# What does this PR do?

Adds an opt-in, rank-local determinism tracer and offline comparator for locating the first semantic divergence between distributed training runs.

The implementation follows the progressive workflow discussed in the determinism roadmap:

1. record low-cost lifecycle and tensor metadata on selected ranks/iterations;
2. narrow the first mismatching boundary with summary or deterministic sampled digests;
3. use full-tensor SHA-256 only around the localized boundary.

The tracer writes one append-only JSONL file per global rank and never introduces a distributed collective. It is disabled by default.

## Issue tracking

Linked issue: Relates to #5785

Design discussion: https://github.com/NVIDIA/Megatron-LM/issues/5785#issuecomment-5323286193

## Implementation
- Adds training flags for output directory, rank/iteration selectors, evidence mode, sampling, flushing, and explicit append behavior.
- Keeps the reusable tracing recorder and schema under megatron/core/determinism, with megatron/training limited to lifecycle and metric integration.
- Records iteration lifecycle, scalar losses, gradient norm, and zero-gradient count from the training loop.
- Supports metadata, summary, sampled, and full evidence modes.
- Uses create-only output by default; append mode validates the existing stream and resumes sequence/occurrence counters.
- Adds an offline comparator that reports the earliest divergence independently per rank in execution order, without implying a global cross-rank ordering.
- Rejects malformed rank trace filenames and invalid trace records fail-closed.
- Adds CUDA coverage for non-default streams, observer validity, and CUDA graph restrictions.
- Keeps backend/model-specific boundary sites and the deferred device-digest backend out of this PR for follow-up work.

## Semantics and safety

- No distributed collectives are called by the tracer.
- Metadata mode does not read tensor values.
- Value-bearing modes snapshot tensors at the call site and materialize them at flush time.
- Sampled and summary matches are diagnostic only.
- A `full_tensor_certificate` means every captured tensor record hashed every logical tensor byte; it does not claim the uncaptured program state was equal.
- Existing trace files are never overwritten unless append continuation is explicitly requested.
- Pending records are flushed at iteration boundaries, graceful shutdown, and training exception handling. SIGKILL remains inherently unrecoverable.

Context: I recently ran an independent multi-rank seed-divergence validation for #7782
(rank-local fingerprint gathering over NCCL + offline first-divergence comparison), so
I've been through many of the same observer-design questions this PR addresses. I read
the full diff at 7e2b645. Overall: strong foundation — I verified the four alignment
points from @Connor-XY's comment are all correctly implemented in this revision
(including the comparator now walking per-rank execution sequence via zip_longest).

Things I'd specifically want to keep during follow-up work:
- `_capture_tensor` recording a CUDA event on the caller's stream and `flush()`
  synchronizing only that event before host materialization — correct, and keeps
  flush stream-agnostic without a device-wide sync.
- The sampled-mode advanced-indexing gather that avoids materializing full copies of
  non-contiguous inputs.
- Binding dtype/shape/mode/sample_indices into the SHA-256 header, so digests can't
  accidentally compare equal across layouts.
- The fail-closed read path: recomputed evenly-spaced sample indices, duplicate JSON
  field rejection via `object_pairs_hook`, strictly increasing sequence, per-file
  semantic-key uniqueness.

Findings (none of them block the foundation for me):

1. `trace.py` `_new_record`: records with `iteration=None` bypass `iteration_spec`
   entirely (selection is only applied when `iteration is not None`). A direct API
   user instrumenting a boundary without passing `iteration` will take full-mode
   snapshots on every iteration even under `--determinism-trace-iterations 20-40`.
   Either document the bypass in the selector section, or require `iteration` for
   value-bearing captures.
2. `trace.py` SUMMARY branch: for complex tensors the summary is computed over
   `abs()` magnitudes, but neither the record nor the user guide says so. A doc line
   (or a `summary_basis: "magnitude"` field) would prevent summary-mode comparisons
   from being misread.
3. `trace.py` `record_scalar`: the exact-type check `type(value) not in (bool, int,
   float)` rejects numpy scalars — even `np.float64`, which subclasses `float`. Loss
   values from external paths commonly arrive as numpy scalars. Consider
   `numbers.Real`/`numbers.Integral` or an explicit numpy conversion.
4. `tools/determinism/compare_traces.py`: `from trace_comparison import ...` relies
   on the script directory being `sys.path[0]`; `python -m`-style invocation breaks.
   A try/relative-import fallback (or a package) would harden it.
5. Minor, atexit path: if a process dies during CUDA graph capture with pending
   value-bearing records, the atexit flush raises
   "flush ... not CUDA-graph-capture safe" during interpreter shutdown, which can
   bury the original traceback in the logs. Consider catching that in the atexit
   path and emitting a short "trace incomplete" note instead.
6. Nit, `_parse_range_spec`: a spec like `"4-"` fails with a bare `int("")`
   ValueError rather than the labeled error message.
7. Diff hygiene, `megatron/training/training.py`: this PR also re-splits several
   pre-existing import lines (opentelemetry / nemo.lens) unrelated to the feature.
   If that's isort-hook-enforced, fine — otherwise reverting keeps the diff in this
   5k-line file easier to read.

One more thing: I noticed the 14 CUDA tests in
`test_determinism_trace_cuda.py` are currently skipped ("I don't have GPU access").

invocation and report the results here — happy to do that this week if it helps.

Thanks for implementing this and for keeping the initial scope generic. We reviewed the direction in the context of #5785 and would like to treat #6610 as a candidate common foundation, rather than build a separate public tracing system.

The rank-local schema, selectors, append behavior, evidence-strength distinctions, documentation, and fail-closed comparator are all useful. We can contribute complementary work from the ongoing hierarchical-tracing effort: a preallocated device-digest backend with deferred host materialization, targeted FSDP/optimizer boundaries, and GPU-scale validation.

Before detailed line-by-line review, we would like to align on four points:

1. **Layering:** please keep the reusable recorder/digest API in a Megatron-Core-safe module, with only lifecycle and metric wiring under `megatron/training`. Future Core boundary sites should not need to import a training-layer module.
2. **First-divergence semantics:** the comparator currently validates `sequence`, but selects content mismatches using semantic-key sorting. Within an iteration this can report the lexicographically first boundary rather than the first one executed. “First” should mean earliest per-rank execution sequence. Across ranks, the report should expose the earliest candidate for each rank rather than imply a synchronized global order.
3. **Observer strength:** `summary`, `sampled`, and `full` add device work, allocation, and host synchronization even though they add no collectives. That is acceptable for progressive narrowing, but the behavior and intended dose should remain explicit. We propose adding a deferred device-digest mode in a follow-up for low-perturbation scale localization, while retaining full SHA-256 for narrow confirmation.
4. **Validation:** CPU contract tests are a good start. Before treating value-bearing captures as scale-safe, we should add GPU tests for non-default streams and an observer-validity/performance check. We can help run those tests on the target stack.

We suggest keeping backend/model-specific call sites out of this PR. Once the common API and comparison semantics are settled, we can submit FSDP, collective, Transformer Engine, and optimizer boundaries as smaller follow-ups.

There is no need to close or restart this work. If this division sounds reasonable, we can share the overlapping implementation and GPU findings, agree on the recorder/backend interface, and collaborate on the changes directly in or following #6610.

When loading a trace directory, any file matching `rank_*.jsonl` but not the expected `rank_<digits>.jsonl` pattern is silently accepted with `expected_rank=None`, which disables filename-rank validation and duplicate-rank detection for that file. This can mask malformed traces (e.g., `rank_backup.jsonl` containing rank 0 records) and produce confusing comparison results.

Consider failing closed for directory loads by requiring every matched filename to conform to `rank_<int>.jsonl`.
