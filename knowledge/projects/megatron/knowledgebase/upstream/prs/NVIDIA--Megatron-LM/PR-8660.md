# refactor(training): make cfg.data authoritative inside the training loop

**Superseded by #8978**, opened against `main` with the rebased and validated implementation at `436688a90`. Continue review there.

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Make `cfg.data` authoritative for the GPT-family data path inside the training loop. Loaders read their type, workers, sharding, pinning and persistence from `cfg.data.dataloader`. Batch construction, SFT loss reporting and distillation read the dataset's computed flags; training, evaluation, packed forward metadata and telemetry read the dataset's sample length.

`--no-pin-memory` and `--no-persistent-workers` expose the existing config fields. Defaults preserve current CLI behavior. The container adds the corresponding data/model validation checks for Python and YAML configurations, without mutating model settings or removing legacy CLI validation.

Part of #3554; follows the merged data-section PR #8341.

## Compatibility and remaining scope

- Keep sample length, model position capacity and packing budget distinct. Loader-only sections retain the legacy sequence-length fallback; containers without a model section retain model-argument fallbacks.
- Keep SFT's default collate separate from varlen's identity collate, and preserve the current batch/distillation `cu_seqlens` formula.
- Preserve public signatures and serialization shape. No Megatron Core production change.
- Estimator/JIT internals await #8234's explicit-input APIs. Phase-transition scheduling, SFT loss-log mode, decoder/encoder lengths and distillation blend/cache identity remain with their current owners.
- Provider registry, loader-module extraction, `drop_last` behavior and Bridge convergence remain separate work.
