# What does this PR do?
TECudaGraphHelper.create_cudagraphs now calls
torch.autograd.graph.set_override_stale_capture_stream(True) before make_graphed_callables(). It uses the same hasattr guard as the local per-layer path and full-iteration capture, which already enable the override.

Eager steps and TE's side-stream warmup can leave AccumulateGrad nodes alive that reference a stream outside the capture. Virtual-expert runtime weights get their weight gradients out of band: TE accumulates them into main_grad and returns None to autograd. Autograd therefore cannot move their nodes onto the capturing stream. Its end-of-backward sync with the stale stream would cross the capture boundary, so the backward capture fails with "autograd tried to synchronize streams across the capture boundary". As a result, the TE implementation could not capture whole-layer MoE graphs (cuda_graph_modules=[moe]), the only MoE scope that virtual experts support.

With the override, autograd skips that sync. Work on a non-capturing stream is not part of the graph, so skipping the sync does not change the graph. As in the other capture paths, the process-global setting stays enabled. VisionTECudaGraphHelper inherits create_cudagraphs, so vision-encoder capture enables it too.

Add test_virtual_expert_te_cuda_graph_training_parity. It builds DDP on a side stream, as megatron/training does, and captures whole-layer MoE graphs of a virtual-expert HybridModel through TECudaGraphHelper while the last eager step's autograd graph is still alive. It then checks that replayed training steps match eager ones. Without this change, the capture fails with the error above.
