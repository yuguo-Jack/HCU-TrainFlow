# [Dev] fix: make repeated TransformerConfig.__post_init__ idempotent for linear CP fields

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8423) · state: closed · merged: False

## Original PR description

## What

Make `TransformerConfig.__post_init__` idempotent for `linear_cp_mode` / `linear_cp_layout` on `dev`.

## Why

`__post_init__` fills an unset `linear_cp_mode` / `linear_cp_layout` with defaults (`chunkwise` / `zigzag` for GDN, KDA and hybrid models) and records whether the caller set them (`_linear_cp_mode_was_default`, `_linear_cp_layout_explicit`). Running it a second time on the same object cannot tell those defaults from user input:

- It raises `linear_cp_mode='chunkwise' requires linear_cp_layout='contiguous'`.
- It flips `_linear_cp_layout_explicit` from `False` to `True`. `hybrid_block`, `mamba_layer_config` and `multi_token_prediction` read that flag later to choose the CP layout, so configs that do not raise still silently change behavior.

Callers that edit fields and finalize a config again hit this. Megatron Bridge's deferred `finalize()` is one: GDN recipes (for example the Qwen3.5 dynamic-CP recipe) fail at setup on `dev`. Bridge has a workaround in https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6608; this PR is the proper fix at the source.

`main` does not carry the derived-flag logic (it has a plain `linear_cp_layout` field), so it is not affected; this is `dev` only.

## How

In `_normalize_sync_compatibility_fields`:

1. Before normalizing, restore the linear-CP fields that a previous pass derived back to `None`, unless the caller changed them since.
2. After the existing derivation, record what this pass derived (`_linear_cp_derived_defaults`).

A repeated `__post_init__` then sees the same inputs as the first. Explicit values, edits made between passes, and rejection of explicit invalid combinations are unchanged. `from_config` deep-copies the instance `__dict__`, so the record is carried over like the existing flags.

## Testing

Six regression tests are added to `tests/unit_tests/transformer/test_transformer_config.py`: derived defaults stay derived across repeated passes (GDN, GDN2), explicit values stay explicit, edits to either field between passes are honored, and an explicit chunkwise/non-contiguous combination is still rejected.

- With this change: `test_transformer_config.py` passes (83 tests), and `test_transformer_config_dynamic_cp.py` passes (129 tests).
- Without it (unmodified `dev`), 3 of the 6 new tests fail and 3 pass:
  - Fail: `test_repeated_post_init_keeps_derived_linear_cp_fields`, `test_repeated_post_init_keeps_gdn2_headwise_default`, `test_repeated_post_init_honors_linear_cp_mode_set_between_passes`.
  - Pass (no-regression guards for behavior that already worked): `test_repeated_post_init_preserves_explicit_linear_cp_fields`, `test_repeated_post_init_honors_linear_cp_layout_set_between_passes`, `test_explicit_chunkwise_with_non_contiguous_layout_is_still_rejected`.
- End to end with Megatron Bridge: finalizing the Qwen3.5 dynamic-CP recipe's GDN model config three times succeeds with unmodified Bridge `main` on this change, and fails on the second call without it.
- black (repo-pinned version and flags), isort and ruff are clean on the changed files.

Not run: the full GPU functional suites.
