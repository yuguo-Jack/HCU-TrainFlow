# What does this PR do?

Generalizes fixed-address persistent storage for GTP backward operations captured by local CUDA graphs. It also enables NCCL symmetric-memory one-shot reduce-scatter for GTP + local CUDA graphs.

  ### Problem

  Local CUDA graph replay requires every graph-owned communication buffer to retain a stable address. The existing specialized wgrad-ring mechanism has several limitations:

  - it only manages padded wgrad reduce-scatter inputs;
  - it requires an explicitly configured ring size;
  - it does not cover asynchronous reduce-scatter outputs or FP32-accumulation scratch;
  - it cannot naturally allocate graph-owned wgrad inputs from the exact registered symmetric-memory domain required by dense GTP or expert GTP one-shot reduce-scatter;
  - repeated parameter usage, including MTP, can require multiple distinct buffers within one graph.

  Consequently, adding another graph-owned GTP tensor requires another specialized lifetime mechanism, while symmetric one-shot RS cannot safely reuse ordinary graph storage.

  ### Solution

  This PR replaces the specialized wgrad ring with an automatically sized persistent-buffer plan:

  1. Eager backward discovers each CUDA graph runner’s aligned storage requirements, grouped by allocation domain and dtype.
  2. Before capture, the plan allocates a bounded number of alternating fixed-address arenas outside the CUDA graph memory pool.
  3. Capture bump-allocates stable tensor views from the runner’s assigned arena.
  4. Replay-time CUDA events prevent an arena generation from being reused while earlier graph work is still in flight.
  5. Capture validates that it consumes exactly the capacity discovered during eager execution.

  Symmetric reduce-scatter inputs are allocated from the registered memory pool for their exact GTP or expert-GTP process group. Dense and expert GTP therefore cannot alias storage registered for a different communicator, allowing NCCL one-shot RS to work with local CUDA graphs.

  ### Persistent storage coverage

  The plan now manages:

  - padded wgrad reduce-scatter inputs;
  - graph-owned asynchronous reduce-scatter outputs;
  - FP32 reduce-scatter all-to-all scratch;
  - FP32 accumulation output scratch;
  - repeated GTP parameter usage, including MTP.

  Ungraphed execution continues to use the existing eager buffer pools and cache paths.

  The centralized discovery, allocation, and replay-fencing API can also support additional graph-owned GTP storage in the future. This PR does not add CUDA graph offloading support.
