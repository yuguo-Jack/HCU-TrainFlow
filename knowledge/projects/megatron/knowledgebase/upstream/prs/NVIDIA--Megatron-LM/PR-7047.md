# What does this PR do?

This is **DCP V2 3/4**. It moves dynamic CP onto the standard train/evaluation path, including PP, VPP, and MTP data ownership, and removes the obsolete dedicated Hybrid-CP path.

The change:

- promotes `dynamic_context_parallel` as the public name while retaining a deprecated Hybrid-CP CLI/config alias;
- deletes `hybrid_cp_schedule.py`, `HybridCPDataLoaderWrapper`, `HybridCPMegatronPretrainingSampler`, their schedule hook, and obsolete schedule tests;
- selects per-microbatch singleton, power-of-two, and full non-power-of-two runtime CP groups with the packing-aware `default_dynamic_cp` scheduler;
- carries runtime CP and TP×CP metadata through normal TP/PP broadcast and standard train/eval forward schedules;
- keeps PP/VPP iterators independent, supplies MTP stages correctly, and preserves rerun-iterator ownership;
- reroutes text samples with CP-lane-local DP all-gather; and
- materializes the required contiguous/zigzag layouts and padding masks for every pipeline stage.

Original change authored by @zhongbozhu in [zhongbozhu/Megatron-LM@a708518](https://github.com/zhongbozhu/Megatron-LM/commit/a7085181a31e9000c268e6b4f8c211c179b8e67d). Refreshed onto main and completed for standard schedule integration and removal of the dead Hybrid-CP implementation.

## October 9 review follow-up

Rebased onto main at `8949def81`, preserving the existing integration and subsequent process-group fixes. The PR remains ready for review, with maintainer edits enabled.

Addresses the six review findings against `3b77433d4`:

1. **PP + CP field ownership:** slice only `tokens/position_ids` on embedding stages, `labels/loss_mask` on loss stages, and both on MTP stages. Padding metadata remains available everywhere.
2. **Static Hybrid packing:** use the resolved CP group's size for TP×CP layout setup; static packing no longer dereferences `local_cp_size=None`.
3. **Mixed layouts + SP:** shard each layout's CP-local padding mask across TP before passing it to Hybrid layers. Preserve the original CP-only batch views, including layouts with different padded lengths.
4. **Non-power-of-two VPP:** expand only through actual supported CP sizes, with a capacity-checked full-domain fallback. Alignment makes progress or reports an explicit error instead of looping.
5. **Full-domain VPP batches:** split packed sample IDs within a full-domain group when multiple sequences are available; do not reject an otherwise splittable batch.
6. **Padding-aware capacity:** account for per-sequence zigzag padding during static/dynamic packing, CP-size selection, expansion, fallback, and VPP alignment. Keep final CP-local alignment within the configured budget.
