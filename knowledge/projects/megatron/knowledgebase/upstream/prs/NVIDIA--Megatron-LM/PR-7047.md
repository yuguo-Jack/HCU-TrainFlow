# What does this PR do?

This is **DCP V2 3/4**. Dynamic context parallelism now uses the standard train/evaluation schedules and caller-owned process groups, including packed data on PP, VPP, and MTP stages. The obsolete dedicated Hybrid-CP schedule and data-loader wrapper are removed.

The implementation:

- exposes `dynamic_context_parallel`, retaining a deprecated Hybrid-CP CLI/config alias;
- packs text samples into supported runtime CP groups, including singleton and full non-power-of-two groups, and carries runtime CP and TP×CP groups in `ProcessGroupCollection`;
- reroutes samples through CP-lane-local DP all-gather and supplies independent PP/VPP iterators with the fields each stage owns;
- returns contiguous/zigzag batch views, packed metadata, and layout-specific padding masks; each Hybrid mask is SP-sharded before reaching its layer;
- bounds packing, CP expansion, fallback, and VPP alignment by the actual per-sequence padding cost, and reports unsplittable VPP batches without looping;
- supports static Hybrid packing and the default zigzag layout with the cumulative-length shape expected by Transformer Engine; and
- ends finite packed evaluation without closing an unopened fault-tolerance step.

For example, a PP first stage no longer tries to CP-slice removed `labels`; static packing no longer dereferences a missing runtime CP size; and twelve 1024-token rows at CP6/capacity2048/alignment32 are split into batches that fit after padding.

Original change authored by @zhongbozhu in [zhongbozhu/Megatron-LM@a708518](https://github.com/zhongbozhu/Megatron-LM/commit/a7085181a31e9000c268e6b4f8c211c179b8e67d).
