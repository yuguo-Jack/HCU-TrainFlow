# ci: select unit tests natively in CPU containers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8932) · state: closed · merged: False

## Original PR description

Run native pytest/Testmon selection on CPU runners inside the same CUDA CI image before allocating a GPU job. A successful empty selection skips the GPU job immediately; a nonempty selection executes its exact native node IDs on the existing GPU runner. Failed collection or invalid/missing selection evidence retains native GPU selection and full-bucket fallback.

Reuse the existing selector, recipe rank counts, production/experimental filters, mandatory mappings, baseline compatibility checks, and runner routing. CPU containers use the ordinary Docker runtime without GPU requests. H100 uses the existing AWS/GCP x86 CPU runners; GB200 uses the existing ARM64 CPU runner. Keep the gzip cache version compatible with the current GPU-produced baselines.

The handoff helper only serializes and validates native results and their baseline snapshot, bound to the source SHA, bucket, platform, recipe rank count, and immutable image ID. It does not implement dependency selection or read dependency fingerprints. The native `testmon_selector.py` engine is unchanged. Empty selections export an empty coverage database so the current coverage gate remains effective. Merge-group/full-test policies and baseline production remain unchanged.

This enables CPU-driven skipping directly, without a comparison mode or rollout controls. Hardware-dependent collection can differ on CPU despite using the same image; collection errors fall back to GPU testing, while successful CPU selections are used as requested.

Validation: 342 targeted regression tests passed, covering native collection, empty GPU skipping, CPU failures, artifact identity and completeness, recipe topology, immutable image execution, GPU fallback, coverage, and cache compression. Formatting, Ruff, pylint, targeted typing, Bash syntax, and reusable-workflow Actionlint checks passed. The main workflow retains its existing unrelated missing-required-script diagnostics. A local CUDA-base-container probe confirmed CUDA libraries are present with zero visible GPUs; actual H100/GB200 CPU collection and GPU execution are pending CI.

### [P2] Install Testmon before preparing the GPU handoff

A valid nonempty CPU selection cannot bypass GPU collection when the fresh GPU container lacks `pytest-testmon`. In [run_enforced_tests](https://github.com/NVIDIA/Megatron-LM/blob/9f4b49096735a486b589a67e6cd1fe029928a8f9/tests/unit_tests/run_ci_test.sh#L375-L386), `preselected` calls `prepare --check-runtime` before reaching the plugin installation in [run_testmon_phase](https://github.com/NVIDIA/Megatron-LM/blob/9f4b49096735a486b589a67e6cd1fe029928a8f9/tests/unit_tests/run_ci_test.sh#L232-L248). Preparation validates the runtime, and [runtime_identity](https://github.com/NVIDIA/Megatron-LM/blob/9f4b49096735a486b589a67e6cd1fe029928a8f9/tests/unit_tests/testmon_cache.py#L54-L64) rejects the missing package. The image dependency sync doesn't request the separate [Testmon dependency group](https://github.com/NVIDIA/Megatron-LM/blob/9f4b49096735a486b589a67e6cd1fe029928a8f9/pyproject.toml#L149-L168), so this is a supported starting state. The GPU then repeats native selection instead of executing the CPU-selected IDs directly.

**Correction:** Install the pinned plugin before preparation. The invariant is that a valid handoff can bypass GPU selection without depending on an earlier collection process to install its validation prerequisite. Replace the opening condition and success branch at [lines 375–376](https://github.com/NVIDIA/Megatron-LM/blob/9f4b49096735a486b589a67e6cd1fe029928a8f9/tests/unit_tests/run_ci_test.sh#L375-L376) with the following, keeping the existing `else` branch:

```bash
    if [[ "$mode" == "preselected" ]] \
        && uv pip install --python /opt/venv/bin/python --no-deps "pytest-testmon==2.2.0" \
        && native_selection_transport prepare; then
        UNIT_TESTMON_INSTALLED=true
        echo "Using the validated native CPU selection."
```

This limits the added installation to `preselected`. Preserve installation during native `enforce` and `select-only` collection, invalid-handoff → native-GPU → full-bucket fallback, phase markers, repeat counts, and executed-test failure propagation. Full and baseline behavior should remain unchanged. Verify this suggested code before adopting it.

**Proposed acceptance checks:** Start a GPU run without Testmon and supply a valid nonempty artifact from the same image and runtime. Assert that installation precedes real preparation, no native selector runs, and the artifact's exact targets execute with the existing phase markers and configured repeat count. Retain cases where an invalid artifact invokes native collection, failed native collection invokes the full bucket, and an executed test failure fails the run. The current [preselected regression test](https://github.com/NVIDIA/Megatron-LM/blob/9f4b49096735a486b589a67e6cd1fe029928a8f9/tests/test_utils/test_unit_testmon.py#L726-L767) stubs the transport helper, so it doesn't exercise this prerequisite.

I completed the light source review across the changed files and their directly affected paths. I didn't execute tests or validate the runner behavior.
