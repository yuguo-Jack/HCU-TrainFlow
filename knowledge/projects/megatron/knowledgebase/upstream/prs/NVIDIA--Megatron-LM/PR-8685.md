# Add refit tests that run the refitted model

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8685) · state: open · merged: False

## Original PR description

## What does this PR do?

This PR adds a unit-test foundation for weight refit (resharding). Most tests refit a real model and then run it, instead of only checking transferred tensors. It changes no production code, and every test passes on unmodified `main`. Its only non-test change documents existing refit failure behavior.

The foundation adds:

- `test_model_swap.py`: refit-then-run tests across topologies, backends and precisions, checked against a freshly built model that holds the same weights;
- `test_mimo_model_swap.py`: after each repeated MIMO-to-LLaVA refit, the refitted LLaVA model runs on a fixed image-and-text input;
- `test_mxfp8_refit.py`: the FlashInfer refresh test's routed case now uses a production-supported shape (8 experts, 2 local);
- `test_batch_invariant_mamba_prefix_caching.py`: a real-refit harness, exercised by RECOMPUTE suspend → refit → resume rows;
- `test_execution.py`: a test that a failed transfer batch raises and leaves earlier batches applied; refit is not transactional;
- documentation of that failure contract: a "Failure recovery" section in `megatron/core/resharding/README.md` and docstrings for `execute_reshard_plan` and `swap_model_weights`, copied from the refit monolith;
- test-harness changes, described under Scope.

## How was the test matrix determined?

An audit of the existing refit tests found three gaps:

1. They mostly compared transferred tensors, so a refit that copied correct bytes into storage the model never reads would still pass.
2. Few covered repeated refits, cached plans, or backends other than NCCL.
3. None refit a model while the inference engine held live requests.

The matrix therefore has two layers:

1. **Refit-then-run.** Each topology, backend or architecture refits a target and runs it. The result is compared with a fresh model built from the same weights.
2. **Engine lifecycle.** A real engine suspends, refits and resumes with requests in flight.

This is differential coverage against a fresh-model oracle, not every combination of refit options. Cases that need a production fix are excluded here and live with their fixes.

## How are results checked?

**Refit-then-run tests**
- The refitted target's logits must match the fresh model's:
  - the same argmax;
  - `allclose` within 5e-4, or 2e-3 when source and target topologies differ;
  - transferred parameters equal exactly.
- Target parameter storage addresses must not change across refits.
- Repeated refits must reuse the cached plan.

**MIMO test**
- Outputs must differ after each weight change.
- Outputs must return exactly to the first ones when the original weights come back.

**Engine lifecycle rows**
- A request is in flight across the suspend, refit and resume.
- After the epoch change, both requests carry the new epoch.
- Under RECOMPUTE, the resident request's hash salt changes.
- CUDA graphs are recaptured once.
- At least one post-refit step runs a CUDA graph.
- Post-refit output differs from pre-refit output (real refits only).

**Failure test**
- The first batch's writes are visible and the second batch's are not.
- No barrier or cache refresh runs.

## Scope

This PR makes no production-code, functional-test or configuration change. Its only non-test change is the failure-contract documentation, which documents the existing non-transactional failure behavior that `test_transport_failure_is_propagated_and_not_transactional` pins; behavior does not change. The whole refit series adds 2,047 net unit-test lines, within the 2,060 the user approved.

**Harness changes**
- `test_gpt_model_batch_invariant.py` imports `megatron.rl` lazily. Other inference tests import its tokenizer and feature flags, and should not need the RL extras.
- `test_utilities.py` restored backend flags under `torch.backends.__allow_nonbracketed_mutation()`, because determinism tests freeze direct flag assignment. Main #7575 now makes the same fix, so this PR no longer changes the file.
- `test_batch_invariant_mamba_prefix_caching.py` skips the speculative refit rows on SM90 when only FA4 is available. They leave batch-invariant mode, so production lets FA4 choose a KV split count, and that FA4 cannot split KV on SM90. Main's chunked-prefill pairwise tests skip such rows the same way.

**Changes to existing upstream tests**
- `test_cache_matches_uncached_eager` keeps `main`'s checks. Only its call sites change: it now passes `exercise_real_refit=False` to the shared harness and sets its environment through `_set_env`.
- On H100 with FlashAttention 3, `test_cache_matches_uncached_eager` fails on `main` too, because of the paged KV-cache tail bug that lmcafee-nvidia/Megatron-LM#120 fixes. On GB200 it passes.
- `test_mimo_to_llava_repeated_refit` used to add 1 to every weight on each update. It now applies a different patterned change on updates 1 and 2, and adds a fourth update that restores the original weights. It runs the refitted LLaVA model after each update.
- `test_flashinfer_moe_buffers_refresh_in_place` used to call `finalize_recv` directly. Both its cases now run a real `ReshardPlan` through `execute_reshard_plan`, with a loopback copy service in one process, and its routed case checks the routed kernel's output before and after refit.

**Where the other rows live**
- The PERSIST rows need the epoch PR's drain, and the OFFLOAD rows need both the drain and the graph-live-state fix. They live in the epoch PR and in the refit tests PR.
- The harness's sampling-backend and seed options are added by the epoch PR, which is the first to use them.
