# Build ModelOpt models with the stock GPT/Hybrid builders

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8340) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
Removes the parallel ModelOpt model-construction path (`megatron/post_training/model_builder.py`: `ModelOptGPTModelBuilder`, `ModelOptHybridModelBuilder`, `ModelOpt*ModelConfig`, `modelopt_gpt_hybrid_builder`). ModelOpt models are now built by the stock `GPTModelBuilder` / `HybridModelBuilder` from a regular, serializable `GPTModelConfig` / `HybridModelConfig`.

## Design
- **Config, not builder subclasses.** Entry points build the stock config as on the plain path, then `megatron.post_training.model_config.apply_modelopt_model_config()` adds the ModelOpt settings in place (choosing GPT vs. Hybrid by `isinstance`): the layer-spec options from the `--export-*` flags and the offline speculative-decoding tweak (`num_layers=0`). The stock builders resolve the ModelOpt layer spec from those options while keeping MTP on the standard decoder spec, as the old builder did, so no layer-spec callables need to be attached to the config. (`ModelConfig` serialization also encodes module-level callables/partials, and `_Keys.BUILDER` is accepted by `instantiate()` so serialized model configs load in `STRICT` mode.)
- **Declarative setup.** A new `ModelConfig.transformations: ModelTransformConfig` field holds the layer-spec options (`default_te_spec`, `force_local_attention`, `real_quant_cfg`, `moe_grouped_gemm`), the QAD train target, the LSQ scale LR (passed by the LSQ hook to the optimizer override, so it follows the model being built), and the offline speculative-decoding layer count (`original_num_layers`). It serializes with the model config, so a reloaded config rebuilds the same model.
- **Distillation is a run-level setting.** It lives in `PretrainConfigContainer.distillation: DistillationConfig`, next to the student's `checkpoint`, not in the student's model config. It holds:
  - the teacher checkpoint (path and format);
  - the resolved `teacher_model` config, read once at CLI translation from the teacher args (`--export-kd-teacher-model-config` overrides). `teacher_model_config` exists only to carry that CLI flag; YAML run configs should give the teacher directly as its own `ModelConfig` in `teacher_model`;
  - the KD loss settings, `loss`: the contents of the `--export-kd-cfg` YAML, passed through unchanged as keyword arguments of ModelOpt's `DistillationConfig`, which validates them at conversion.

  `loss` does not mirror ModelOpt's fields, so it follows the installed ModelOpt version (e.g. 0.48 replaces `skip_lm_loss`/`kd_loss_scale` with `kd_loss_alpha`), and `modelopt` stays out of the training config's imports. Inference containers have no distillation section.
- **Hooks rebuilt from config.** On each build, `ModelBuilder.pre_wrap_hook()` composes the hooks in `megatron.post_training.model_hooks`, before `Float16Module`/DDP wrapping (and under `torch.device("meta")` when `init_model_with_meta_device` is enabled), in this order:
  1. Restore `modelopt_state`, from the run container's `checkpoint.load` and `checkpoint.ckpt_format`.
  2. QAD freeze.
  3. LSQ.
  4. Layernorm checkpoint-key check (see below) and TE load hook.
  5. User `pre_wrap_hooks`, including the training freezes.
  6. KD conversion, from the run container's `distillation`.

  The ordering holds by construction.
- **Teacher.** The teacher config is built with `gpt_config_from_args` / `hybrid_config_from_args` on the teacher args, and inherits the student's transformations without QAD/LSQ. It is built by the same builder class as the student. Its weights are still loaded after mixed-precision wrapping (`load_kd_teacher_checkpoint`), never inside the hook.
- **Validation.** `ModelConfig.validate` checks the transformations (`qad_train_target`, `real_quant_cfg`) and rejects them combined with `transformer_impl="inference_optimized"`. `DistillationConfig.validate` checks the distillation config itself. `PretrainConfigContainer.validate` then runs the cross-config checks, after every section has validated (so an unresolved teacher fails with a clear error), via `validate_distillation_student`:
  - VPP
  - `tp_comm_overlap`
  - TE cross-entropy
  - matching student/teacher TP/PP/CP/`pipeline_dtype`, and EP when the teacher is MoE
  - `manual_gc`

  `ModelBuilder.pre_wrap_hook` runs the same checks for builds without a run container, before any model is allocated.
- **Building.** Training calls `build_distributed_models(...)` directly, as on main, and passes the run's `checkpoint` and `distillation`. Post-training and inference scripts translate CLI args via `modelopt_inference_config_from_args(args)` and call `build_inference_models(cfg, device=..., mixed_precision=...)`, which builds on the MPU process groups without DDP and passes `cfg.checkpoint` (with `build_modelopt_models(args)` bridging legacy inference callers that initialize a run container without a model). The distributed builder accepts an explicit `device=` (e.g. CPU export). `MimoModelBuilder` accepts the new kwargs.
- **When ModelOpt is used.** `should_use_modelopt_config(args)` selects the ModelOpt config for a checkpoint with `modelopt_state`, a distillation teacher (`--export-kd-teacher-load`), or `--modelopt-enabled`, without writing back to args. Other ModelOpt options do not select it on their own.
- **Architecture flags in core.** `qk_l2_norm` and `moe_apply_probs_on_input` come from the core `--qk-l2-norm` / `--moe-apply-probs-on-input`. The GPT-OSS YaRN settings come from the core YaRN flags (`--enable-gpt-oss` is removed).
- **Model type.** It comes from the config class instead of `--export-model-type`. `pretrain_gpt.py`, `pretrain_hybrid.py` and flextron build their stock config and apply ModelOpt to it. The post-training scripts (`modelopt_model_config_from_args`) treat a model as hybrid iff `--hybrid-layer-pattern` is set.
- **`restore_modelopt_state`** still selects the ModelOpt spec in the GPT/Hybrid builders as on main; `transformations` takes precedence when set, and Hybrid's `wide_residual` check guards both paths. The Hybrid branch now also uses the fused TE layernorm keys, like the GPT branch and Megatron-Bridge's own builders.

## Behavior changes / deprecations
- The KD teacher is now built with the student's layer-spec flags; before, it ignored some of them. GPT/Hybrid model fields outside `TransformerConfig` (e.g. untied embeddings, `rotary_base`) now come from the teacher config instead of the student.
- `--freeze-all-layers` / `--freeze-base-model-for-mtp` freezes now always run before the KD conversion.
- `--export-model-type` is **deprecated** (default `None`). It is still honored, e.g. for a hybrid model without a layer pattern. It warns, and it raises if it contradicts the config type. A GPT config with `--hybrid-layer-pattern` raises. Before this change, a hybrid ModelOpt run that omitted it silently built a GPT config. GPT ModelOpt configs now honor `--yaml-cfg`, like plain runs.
- The `model_config_cls=` parameter of `gpt_config_from_args` / `hybrid_config_from_args` is removed. So is the private `_freeze_base_for_mtp` alias; `--freeze-base-for-mtp` still works.
- `--modelopt-enabled` is now only an input to model selection; it is not written back to args. The distillation loss and pipeline shape adjustment are selected from the built model (`is_distillation_model`).
- `has_modelopt_state(checkpoint_path, ckpt_format)` now takes `ckpt_format` explicitly instead of reading `get_args()`, and `load_modelopt_state` accepts `ckpt_format=` and loads non-sharded `torch` checkpoints from `load_dir` rather than `args.load`.
- `--enable-gpt-oss` is **removed**. The ModelOpt GPT-OSS conf scripts pass the YaRN flags explicitly (`--position-embedding-type yarn --rotary-scaling-factor 32.0 --yarn-original-max-position-embeddings 4096 --yarn-beta-fast 32.0 --yarn-beta-slow 1.0 --no-yarn-correction-range-round-to-int`); `examples/gptoss/02_train.sh` keeps RoPE, as on main. `yarn_original_max_position_embeddings` changed from the old preset's 131072 to 4096, matching the Hugging Face config and Megatron-Bridge, which changes RoPE frequencies for ModelOpt GPT-OSS runs.
- The ModelOpt-local spec now **always** loads and saves layernorms under the fused Transformer Engine checkpoint keys (e.g. `linear_qkv.layer_norm_weight`) and registers the TE load hook on the student and KD teacher, unless `--export-default-te-spec` is set. `--export-te-mcore-model` is **deprecated** and ignored; every shipped workflow already passed it, and Megatron-Bridge already hard-codes the remapping. Distributed checkpoints saved from the ModelOpt spec *without* that flag (layernorms under their module names) no longer load: the student and KD teacher loads detect them from the checkpoint metadata and fail with an error explaining how to re-save them, instead of failing on missing keys or, with a non-strict `--dist-ckpt-strictness`, loading with default layernorm weights. The Hybrid `restore_modelopt_state` branch changes the same way.
- `--export-legacy-megatron` (unused) is removed.
- `--export-qk-l2-norm` and `--export-moe-apply-probs-on-input` are **deprecated** aliases of `--qk-l2-norm` and `--moe-apply-probs-on-input`.
- `get_model_for_inference(pg_collection=...)` (disaggregated serving) now raises for any ModelOpt checkpoint, including one detected from its `modelopt_state`, instead of silently building it with the plain builder.
- `--export-kd-cfg` YAML keys are no longer checked against a fixed list; ModelOpt validates them.
- A dense KD teacher no longer needs the student's expert parallelism; only an MoE teacher must match it.
- ModelOpt transformations with `--transformer-impl inference_optimized` now raise instead of silently using the ModelOpt spec.
- `load_kd_teacher_checkpoint` loads the teacher only from the run's `distillation` config (no `--export-kd-teacher-load` fallback), and also clears `ckpt_step`, `pretrained_checkpoint` and `non_persistent_ckpt_type` while loading it. The Flextron loss detects KD from the built model, and the KD loss mask takes its TP split from the TP group instead of args.
- `examples/post_training/modelopt/finetune.py` follows the model config for offline speculative-decoding mode (`transformations.original_num_layers`) instead of reading `--export-offline-model` in its callbacks, and `--offline-distillation-data` is bound to the dataset provider when the CLI is translated.
- Fixed: `modelopt_state` from torch-format checkpoints was never restored, because `_load_base_checkpoint` was called without `args` and unpacked into 3 values (an error swallowed by `except Exception`; the same bug exists on main).
- The serialized `_builder_` key is accepted for compatibility but ignored. The `_target_` class determines the builder.
- The per-layer parameter-count print in the old hybrid builder is dropped.
- The QAD and flextron hybrid functional-test configs no longer pass `--export-model-type`, and the ModelOpt distill-resume and hybrid QAD functional-test configs no longer pass `--export-te-mcore-model`.
- `examples/post_training/modelopt/mmlu.py` no longer calls `to_empty()` after the builder has materialized the model; the unused `megatron.post_training.utils.to_empty_if_meta` is removed.
- `examples/post_training/modelopt/offline_feature_extract.py` now imports `parse_and_validate_args`; it failed with a NameError before.

## Not in this PR
- Distillation redesign (`TeacherSource`, `LossSpec`, moving the KD engine into MCore).
- Removing the `args.finetune` teacher-load workaround.
- Making `load_checkpoint` read `CheckpointConfig` instead of args.
- Config-owned settings for offline KD (cached teacher logits: `logits_save_*`/`logits_load_*`, `LogitsSaverHooks`, `compute_dataset_hash`). Offline KD is still in development, and how to represent it in the config is undecided.
- `train_rl.py` and other legacy `model_provider` callers no longer switch to ModelOpt for a ModelOpt checkpoint (the `training.py` fallback is gone); they should build from a run config like `pretrain_gpt.py`.

### [P2] Preserve the optional-ModelOpt guard in Flextron

**Failure:** In an environment with Megatron's ordinary Hybrid dependencies installed but without `nvidia-modelopt`, the [new guarded import](https://github.com/NVIDIA/Megatron-LM/blob/539c92a430dbc71e9d3fa664f592316c4b1c8564/megatron/elastification/pretrain_hybrid_flex.py#L62-L74) succeeds: the configuration adapter no longer imports ModelOpt. Consequently, `has_nvidia_modelopt` becomes `True` even though the package is absent. A previously valid non-ModelOpt Flextron invocation with a stock `--spec` now enters [_build_modelopt_stage](https://github.com/NVIDIA/Megatron-LM/blob/539c92a430dbc71e9d3fa664f592316c4b1c8564/megatron/elastification/pretrain_hybrid_flex.py#L91-L100) and fails with `ModelOpt integration does not support custom args.spec`. Without a custom spec, it instead reaches the unconditional ModelOpt imports in the pre-wrap hooks. The expected behavior is to retain the existing non-ModelOpt construction branch. The [previous guarded module](https://github.com/NVIDIA/Megatron-LM/blob/d2c430ab485c6947701447e5d551d3aafaa39161/megatron/post_training/model_builder.py#L11-L12) actually checked dependency availability.

**Correction:** Make this availability guard probe the dependency, not merely its dependency-free configuration adapter. A small patch at the existing `try` block is:

```diff
 # modelopt distillation
 try:
+    import modelopt.torch.distill.plugins.megatron as _modelopt_megatron  # noqa: F401
+
     from megatron.elastification.loss_func import loss_func as loss_func_modelopt
```

**Preservation and acceptance:** Add a proposed regression test that makes the ModelOpt plugin import raise `ModuleNotFoundError`: importing this entry point must leave `has_nvidia_modelopt=False`, and `model_provider` must use the ordinary Hybrid branch with a supplied stock spec, without invoking `_build_modelopt_stage`. In an installed-ModelOpt case, retain `has_nvidia_modelopt=True` and the new stock-builder/hook path, including checkpoint restoration before Flextron setup. Neither branch should be selected merely because the configuration adapter imports successfully.

### [P2] Default ModelOpt-only options for checkpoint-detected inference callers

**Failure:** The new [checkpoint-detection branch](https://github.com/NVIDIA/Megatron-LM/blob/539c92a430dbc71e9d3fa664f592316c4b1c8564/megatron/inference/utils.py#L178-L192) can call `build_modelopt_models(args)` for callers that never registered `add_modelopt_args`. For example, [the inference performance tool](https://github.com/NVIDIA/Megatron-LM/blob/539c92a430dbc71e9d3fa664f592316c4b1c8564/tools/run_inference_performance_test.py#L48-L63) registers only the inference arguments and [initializes a container without a model](https://github.com/NVIDIA/Megatron-LM/blob/539c92a430dbc71e9d3fa664f592316c4b1c8564/tools/run_inference_performance_test.py#L155-L169). **Preservation and acceptance:** Add proposed GPT and Hybrid regression cases using valid core/inference arguments without `add_modelopt_args`, a container with `model=None`, and mocked positive checkpoint-state detection. Leave translation real and mock only final model construction: both must reach the stock builder with default transformations, without `AttributeError` or namespace mutation. Retain explicit local-attention/real-quant/default-TE options and the existing freeze-alias conflict rejection.
