# What does this PR do?

Adds the core building blocks that dynamic context parallelism needs at runtime: TP × runtime-CP process groups, resolution of the runtime CP group a scheduled batch records, and CP sharding of padding masks. Nothing here changes how training is configured or scheduled.

This is part 1 of 7 of a split of #7047, made so that each PR needs at most three CODEOWNERS reviewer groups. Original changes by @xiaoyao0115 in #7047, building on @zhongbozhu's zhongbozhu/Megatron-LM@a708518.

**Changes**

- `parallel_state`: builds the TP × runtime-DPxCP group for every runtime CP size (`get_dynamic_tensor_data_context_parallel_group`). Converting CP layouts after sequence-parallel scattering communicates over this group. With TP1 it is the dynamic DPxCP group itself. These communicators are created only when dynamic CP is enabled with TP>1; their first in-tree user arrives in part 4.
- `core/utils.py`: `_resolve_dynamic_cp_group_for_batch` resolves the runtime CP group from a batch's `local_cp_size` (or a group it already carries) and checks the sizes match. `get_batch_on_this_cp_rank` now resolves that group for every dynamic-CP batch, including the real singleton group when CP is off for a microbatch, and shards with per-sequence balancing. Per-document balancing also works on pipeline stages that carry only labels or padding masks.
- `context_parallel/utils.py`: padding masks are sharded with the batch in every CP layout (padded slots stay masked), and `get_batches_on_this_cp_rank` resolves the dynamic group once before building layout views.
