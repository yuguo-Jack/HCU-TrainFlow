# Make DSv4 attention and indexer backward deterministic

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7708) · state: open · merged: False

## Original PR description

With `config.deterministic_mode=True`, DSv4 CSA uses deterministic sparse-attention backward, stable Top-K selection (ties choose the smallest key ID), and fixed-order sparse-indexer gradients. Learned-indexer no-grad and training forwards now visit those keys in the same compressed-first order, so changing grad mode does not change FlashMLA's reduction order. Default-mode ordering is preserved.

This PR targets `main` and covers SBHD/non-CP attention. Packed THD/context-parallel integration is in #7921; this PR does not depend on #7469 or #7705.

## Original work and dev dependencies

- Stable Top-K and the forward-ordering approach come from **Bo Li (@bobboli), #7169**, merged into `dev`. This main-based port explicitly gates the ordering change on deterministic mode. The port commit includes Bo's co-author credit.
- Deterministic sparse-attention/indexer backward is adapted from **Haochen Yuan (@HaochenYuan), #7441**. Our #7706 corrects sample-local key addressing and the clipped-log KL derivative, including targets that do not sum to one.
- The related dev fixes for the complete CSA teacher denominator and zero-loss gradient connectivity already have equivalents in this implementation. Dev compact/MXFP8 indexer, dynamic/balanced CP and JIT/cache features are separate work, not prerequisites for this fix.

`torch.use_deterministic_algorithms` alone preserves the existing external-kernel dispatch. Explicit deterministic mode rejects dense indexer backward and unsupported sparse-attention backward runtimes: it requires SM10x, padded query heads in {16, 32, 64, 96, 128}, and cudnn-frontend >= 1.29. cuDNN scratch is allocated per call from the caching allocator.

## Validation

Runtime: four GB300 ranks, cuDNN Frontend 1.29.0 / cuDNN 9.23.2, BF16 attention, `NCCL_ALGO=Ring`, at most one NCCL channel, NVLS disabled, and isolated compiler caches per rank.

- Final head `cc6e84092a6ba30df7661c1f749290d17e1b0593`: complete indexer/replay file **44 passed per rank**, no skips (job **1103346**, `COMPLETED 0:0`). Both new real parity cases fail at the intended key-order assertion on prior production `915d73c`, with candidate tests overlaid: **2 expected failures per rank**, reported separately from candidate passes.
- The unchanged fused-attention file **27 passed per rank** and manifest **245 passed per rank** on predecessor `3989b7736` (job **1102699**). Production, those files and runtime are byte-identical to the final head. That earlier job failed because the new positive-loss fixture used unsupported Top-K 64; the final-head rerun above uses 128. Its unrelated fixture failure is not counted as a successful regression control.
- Changed-test formatting, lint, copyright, syntax and determinism-manifest coverage checks passed. All GPU runs retain normal repository conftest, per-rank outcomes and before/after source guards.

The new real learned-indexer regression uses BF16, B=2, S=128, compression ratio 4, 64x512 attention heads, a 64x128 indexer, and Top-K 128. It checks actual key IDs/lengths, sample addressing, causal validity, finite outputs and byte-identical outputs across repeated no-grad/training forwards, with zero and positive sparse KL loss. Four mocked dispatch cases separately protect default behavior.

Existing backward tests compare output/dQ/dKV/sink gradients against FP64 autograd and require byte-identical replay. The native reference uses FP32 gradient leaves to avoid BF16 reference accumulation error; the 64-head dKV check combines a BF16-epsilon/RMS-scaled absolute allowance, <1% relative-L2 error and an independent exact-replay assertion.

## Scope and performance

These are focused attention/indexer checks, not whole-recipe or cross-configuration determinism certification. No performance comparison is claimed. Known costs are stable full sorting, fixed-order indexer recomputation with a 1 GiB intermediate budget per chunk, and cuDNN deterministic-backward scratch. mHC, optimizer, grouped-MLP and Bridge changes remain separate. Tracking: #5176, #5785.
