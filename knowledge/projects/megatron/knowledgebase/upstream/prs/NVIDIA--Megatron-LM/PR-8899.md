# Pass MoE process groups through shared experts, unpermute and SequentialMLP

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8899) · state: open · merged: False

## Original PR description

Three MoE modules read the global parallel state where they should use the process groups of their own module or collection: the fused shared expert, the batch-invariant unpermute and the `SequentialMLP` experts. This unit makes each of them use the groups of its module or collection, so a MoE model built on its own grid gets the right TP, EP and expert GTP groups. On the standard grid the groups are the same and results do not change. The unit is part of #6307. It consolidates 3 draft PRs unchanged, one commit per member, so review it commit by commit. It depends on no other unit or PR. The branch stacks on the units that land before it only to keep one linear landing order.

## Members

- #8024: Use the shared expert's TP group in the fused SwiGLU path. `FusedSharedExpertMLP` now passes `self.tp_group` to its 4 tensor-parallel collectives, as the unfused and overlapped paths already do, so a fused shared expert on its own grid no longer reduces over the global TP group and returns wrong values.
- #8053: Take the batch-invariant MoE EP size from the token dispatcher. `moe_utils.unpermute` and `batch_invariant.unpermute` take an optional `ep_size`, which `MoEAlltoAllTokenDispatcher.combine_postprocess` sets from its own EP group; callers that pass nothing keep the global EP size.
- #8724: Give SequentialMLP experts the expert groups of their collection. `SequentialMLP` passes its `pg_collection` to each expert `MLP`, so `fc1` and `fc2` shard over the collection's `expt_gtp_remat` and stamp `expt_dp` as the replica group, matching `TEGroupedMLP`.

## Behavior changes for callers

- `moe_utils.unpermute` and `batch_invariant.unpermute` have a new optional `ep_size` argument.
- `SequentialMLP` experts on a collection with `expt_gtp_remat=None`, such as the one `build_inference_pg_collection` builds, now stay unsharded, as `TEGroupedMLP` experts do. Before, they took the global `expt_gtp_remat`.
- Out-of-tree linear builders now receive `SequentialMLP`'s collection instead of `None`. A builder that takes its TP group from `pg_collection.tp` would switch the experts from expert TP to dense TP.
