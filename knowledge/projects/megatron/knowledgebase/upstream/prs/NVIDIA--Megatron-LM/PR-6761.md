# Layer sharded Muon scope change to allow hybrid TP mode on expert and dense matrices

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/6761) · state: open · merged: False

## Original PR description

# What does this PR do?

Adds `--muon-expert-tp-mode` (`OptimizerConfig.muon_expert_tp_mode`, default `None`): a Newton-Schulz mode selector for expert-parallel weights that defaults to following `--muon-tp-mode`. Setting it enables hybrid modes, e.g.

```
--optimizer muon --use-distributed-optimizer \
  --muon-tp-mode auto --muon-expert-tp-mode layer_sharded --muon-ns-batch-size 32
```

runs #6664's per-weight duplicated/distributed selection on dense weights while layer-sharding the MoE expert weights (#6683) — where the layer-sharded win concentrates (many identically shaped matrices per NS home). Unset, behavior is unchanged: plain `--muon-tp-mode layer_sharded` still shards everything.

Before this patch the two were mutually exclusive: layer sharding replaced `TensorParallelMuon` for all weights, so `auto` could not apply to dense weights, and #6664 hard-codes expert weights to `duplicated`.

## Measured performance (Nemotron-4 problem sizes)

NS-step microbenchmarks at N4 matrix sizes (16 NS steps, polar_express, modelled world 12288, tp1/gtp64/ep64/etp1/egtp4; step cost = slowest rank; `auto` column drives the real `_select_tp_mode` per weight). Step cost in ms:

| axis | duplicated | distributed | lsh_batched | auto |
|---|---|---|---|---|
| dense (GTP), syrk off | 121.8 | 223.7 | 129.2 | **106.4** |
| dense (GTP), syrk on | 99.1 | 187.1 | 99.8 | **85.4** |
| expert (EGTP), syrk off | 142.1 | 1901.2 | **47.3** | — |
| expert (EGTP), syrk on | 131.2 | 1745.9 | **41.6** | — |
