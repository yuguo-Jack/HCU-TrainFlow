# Add option to disable ShortCutMoE for MTP

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8526) · state: open · merged: False

## Original PR description

## Summary

Adds `moe_shortcut_disable_mtp` (`--moe-shortcut-disable-mtp`), which turns off shortcut MoE in the hybrid MTP stacks while keeping it in the main decoder.

MTP stacks share the decoder's `TransformerConfig`, and their per-layer configs are copied from it. When the option is set, `HybridStack.__init__` builds MTP stacks from shallow copies of the stack config and of each per-layer config with `moe_shortcut_connection`, `moe_shortcut_parallel` and `moe_shortcut_post_norm` cleared. Each MTP depth then runs its compute and MoE layers sequentially through the ordinary MoE normalization and routing path, without shortcut-specific norms or communication overlap. The decoder config and its layer configs are left unchanged. The option also applies to a shared, repeated MTP layer.

The default is `False`, so existing models are unaffected. Changing the setting for an existing run requires converting the MTP state when resuming from a checkpoint, since the MTP layers then hold different modules.

The CLI flag comes from the `TransformerConfig` field through the existing argument factory, so `megatron/training/arguments.py` needs no change.

## Testing

- `tests/unit_tests/models/test_shortcut_block.py`: with the option on or off, MTP stacks drop shortcut connections only when it is set, and the decoder stack config and layer configs always keep them.
- `tests/unit_tests/transformer/test_multi_token_prediction.py`:
  - with the option set, both MTP depths route the normalized attention output and backpropagate through the norm, for separate and repeated MTP layers, with an ordinary and a wide-residual decoder;
  - leaving the option unset keeps shortcut MTP enabled.
- `tests/unit_tests/models/test_hybrid_moe_model.py`: adds the new field's default to the expected config.
