# Pad the scale buffers before calling TE's quantize

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8247) · state: closed · merged: True

## Original PR description

## What does this PR do?

Fixes an out-of-bounds write in `QuantizedDBuffer.quantize_` (MFSDP v2, MXFP8; TE side issue: NVIDIA/TransformerEngine#3689).

**Symptom.** Using MFSDP v2 + MXFP8 `fully_shard` initialization can cause `CUDA error: an illegal memory access` from TE's `quantize_mxfp8` kernel (`FsdpParameterGroup.sync_model_weight_from_main_weight` -> `QuantizedDBuffer.quantize_`). Some devices ran with silently corrupted neighbouring scales.

**Root cause.** TE's MXFP8 quantize kernel assumes `scale_inv` has the padded physical shape from `get_scale_shape()` and stores a scale for every row of its 64-row chunk, including rows beyond the tensor (NVIDIA/TransformerEngine#3689). `quantize_` passed it the compact per-parameter scale views of the local planes, so whenever a rank's shard is not a multiple of 64 rows (32 rows per rank for the output layer at DP 128) the kernel wrote beyond the view: into the next rank's chunk of the replicated plane, or beyond the end of the local buffer. This is the producer-side counterpart of NVIDIA/TransformerEngine#3518, which `get_tensor()` already works around for GEMM; that issue's 64x64 example stays in bounds, which is why `quantize_` appeared to accept compact scales.

**Fix.** Quantize into the padded scale tensors that `get_tensor()` already builds for the GEMM path and copy the compact region back into the plane views. Data planes are exact and stay views. The extra allocation and copy happen only for parameters whose local shard needs padding and are freed on return; they go away once TE handles compact scales on both paths.

**Test.** `test_quantized_dbuffer_quantize_writes_only_the_local_shard`: a replicated `QuantizedDBuffer` filled with a canary, viewed as `BlockAtomic(32)` (what `FsdpParameterGroup` does) and quantized; asserts the other ranks' chunks of every plane are untouched and the local shard matches TE's reference quantizer. Fails on every rank before this change (`rowwise_scale chunk of rank N+1 was written`), passes after. The existing `test_quantized_dbuffer_quantization_matches_te` cannot catch this because in-order quantization overwrites the corrupted neighbour and the last tensor's out-of-bounds write lands in allocator slack.
