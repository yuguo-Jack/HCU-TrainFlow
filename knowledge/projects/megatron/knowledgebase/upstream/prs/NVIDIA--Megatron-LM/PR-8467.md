# Run FLA's l2norm outside the compiled GDN input preparation

# What does this PR do?

**Makes the training forward of GDN / GDN2 bitwise equal to the no-grad log-prob forward of the same input, by running FLA's `l2norm` outside the compiled `_prepare_input_for_gated_delta_rule`.**

### Problem

`_prepare_input_for_gated_delta_rule` is compiled by `torch.compile` (through `jit_fuser`) and calls FLA's `l2norm` inside the graph. FLA's `l2norm` launches its Triton kernels with a row-count bucket, `NB = cdiv(rows, 65536)`, as a `tl.constexpr`, so Dynamo turns every `NB` value into a guard, and variable-length inputs need one compiled variant per bucket and per grad mode. Once these variants exceed Dynamo's recompile limit (8 by default), every call that needs a new variant runs eagerly, and eager rounding differs from the compiled graph.

### Impact

- **Training forward ≠ log-prob forward in RL.** RL computes log-probs without grad and then trains on the same tokens. The no-grad passes use up the variants, the grad-enabled calls fall back to eager, and the training log-probs no longer match the log-probs they are compared with, even before any weight update. We saw it as a non-zero KL at step 0.
- **Silent.** The only sign is Dynamo's one-line recompile-limit warning.
- **Scope.** GDN and GDN2 with the default `gdn_pre_gated_delta_rule_fusion=False`, whenever `jit_fuser` is `torch.compile` and the row count of the inputs spans several 65536-row buckets (packed variable-length batches).

### Changes

- `common.py`: wrap FLA's `l2norm` once, at import, with `torch.compiler.disable`, and call the wrapper in the non-deterministic branch. The FLA kernels are the same and the rest of the helper stays compiled; deterministic mode's `torch_l2norm` is unchanged.
- `test_ssm_kernels.py`: the new test `test_gdn_compiled_input_preparation_matches_across_grad_modes` runs one length in each of six `NB` buckets, no grad then grad, and requires bitwise-equal outputs.

### Results

Micro-batches (of 36) whose training forward differs from the no-grad forward:

| per-rank key / value heads | lengths | `main` | this branch |
|:---|:---|---:|---:|
| 16 / 48 (TP1) | up to 16K | 36 | **0** |
| 4 / 12 (TP4) | up to 32K | 8 | **0** |
| 4 / 12 (TP4) | up to 64K | 33 | **0** |

- **New test:** fails on `main`, passes on this branch.
- **Compiled variants:** `main` hits the recompile limit in every row above; this branch stays at 6 graphs and compiles nothing new in a second step with new lengths.
- **No regressions:** on 8 ranks, `test_ssm_kernels.py`, `test_gated_norm.py` and the six `test_gated_delta_net*.py` files give the same result for every other test on both sides.
- **Cost per call:** no-grad calls are 1.1–2.1× faster; training calls are 0.15–0.2 ms slower on the two smaller shapes and 0.6 ms faster on the two larger ones (table below).

## Testing

- **Setup:** one node with 8 × H20, torch 2.13, FLA 0.5.1; `main` at 9314b01 against this branch. The results table drives the compiled helper through one RL-like step with the per-rank GDN shapes of a 27B model: 36 micro-batches of 2K tokens up to the length shown, two no-grad passes, then a grad pass with backward.
- **Environment:** the node runs Python 3.10, so `typing.override`, `typing.Self` and the generic `NamedTuple` were backfilled from `typing_extensions`, and the unit-test data download was skipped.
- **Lint:** `tools/autoformat.sh` with `CHECK_ONLY=true` and `tools/check_kernel_determinism_coverage.py` pass.
