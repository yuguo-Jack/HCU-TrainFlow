# Add grouped-query and multi-query cross-attention

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7190) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Enable grouped-query and multi-query attention in `CrossAttention`. Previously, setting `num_query_groups < num_attention_heads` raised an error, preventing encoder-decoder and multimodal models from using fewer KV heads for cross-attention.

Queries retain `num_attention_heads / TP` heads per rank, while K/V are reshaped by query group. When KV groups are fewer than TP ranks, gather the KV projection and select each rank's shared group. The gather's reduce-scatter backward accumulates contributions from every query rank sharing that group. Pass the explicit process group to both projections and preserve the existing MHA parameter layout.

Related to #1814, following the implementation invitation in https://github.com/NVIDIA/Megatron-LM/issues/1814#issuecomment-3705618711.

## Validation

On four RTX 3090 GPUs, using Python 3.12.13 and PyTorch 2.13.0+cu130, all **24 tests passed on each rank** against base `9ca681caf1f6bf604400a5937c021367a65d85b7`:

- Independent dense-reference output, query/context input gradients, and all six parameter gradients.
- FP32 TP=1/2/4 with 8 query heads and 8/4/2/1 KV groups, covering MHA, GQA and MQA, including multiple shared KV groups.
- BF16 MHA controls, MQA/GQA, selective core-attention recomputation, sequence parallelism, and their combinations.
- Unequal query/context lengths, padding masks and nonzero projection biases.

The final GQA test fails on the unmodified baseline with the existing unsupported-GQA exception. Existing FP32 MHA controls also pass on that baseline.

BF16 uses separate output and gradient tolerances for dense-versus-sharded rounding. The shared KV weight gradient additionally requires relative L2 error at most 2%, so the absolute allowance cannot hide missing gradient contributions. FP32 comparisons remain at rtol=2e-5, atol=2e-6.

Scoped Black, isort, Ruff, Python 3.12 AST parsing and `git diff --check` pass. These are host-environment results, not canonical-container or upstream CI results. TransformerEngine, FP8/FP4, packed/CP attention, CUDA graphs and end-to-end T5 inference have not been validated. Existing static KV-cache scheduling is outside this change.
