# What does this PR do?

Bound fine-grained activation offload storage with an optional reusable pinned buffer.

Variable MoE activation shapes can grow the pinned host allocator's cache, and power-of-two rounding can substantially exceed the requested capacity. This adds `--fine-grained-offloading-buffer-size-gib` to pack backups into one fixed buffer per rank, with CUDA events protecting reuse after H2D reads. The default remains disabled.

The buffer uses `cudaHostAlloc` directly, avoiding PyTorch's power-of-two rounding: for example, a 152 GiB budget no longer requires a 256 GiB allocation. Capacity must be a positive multiple of 256 bytes; CUDA may round to whole pages. The buffer never grows and raises a clear error when exhausted. Views retain the backing allocation; captured graphs require the buffer owner to remain alive.

**Keep captured backups reserved during eager offloads.**

**Failure:** Capture a forward graph containing `handler.offload(source)` and a separate backward graph containing `handler.reload(state)`, using the same fixed pool. Backward capture calls `release()`, leaving `_live` empty. Then replay forward with value 17, eagerly offload another same-sized tensor containing 29, and replay backward. This branch resets the eager allocation to offset zero, so the eager copy overwrites the captured backup and backward reloads 29 instead of 17. Graph replay executes neither the Python allocation nor release bookkeeping.

This affects the supported mixed path: captured attention offloads followed by eager expert offloads. [Attention capture/replay](https://github.com/NVIDIA/Megatron-LM/blob/ec2acd019e8c19e34999c97df3de35a09ee2d3a2/megatron/core/transformer/transformer_layer.py#L1831-L1891) and [eager MoE execution after replay](https://github.com/NVIDIA/Megatron-LM/blob/ec2acd019e8c19e34999c97df3de35a09ee2d3a2/megatron/core/transformer/transformer_layer.py#L1943-L2021) share this pool. The existing CUDA-graph integration cases include `core_attn`, `attn_proj`, and `expert_fc1`, but [their builder leaves the buffer disabled](https://github.com/NVIDIA/Megatron-LM/blob/ec2acd019e8c19e34999c97df3de35a09ee2d3a2/tests/unit_tests/pipeline_parallel/test_fine_grained_activation_offloading.py#L987-L1034).

**Correction:** Make `PinnedActivationBuffer.allocate()` and the capture branch of `release()` distinguish graph-lifetime reservations from eager live backups. Captured addresses must remain reserved while their graphs can replay; eager epochs must use disjoint space within the same capacity and still raise on exhaustion. Backward *capture* must not make those addresses available to eager writers. The exact reservation/lifecycle implementation is not unambiguous from the current API, so I am not suggesting a one-line bookkeeping patch.

**Preservation and acceptance — proposed checks, not executed:**
- Add the split-graph sequence above: captured reload must return 17; reloading the eager state must return 29; capacity must remain unchanged.
- Enable a nonzero budget in the existing mixed attention/expert CUDA-graph integration case, with delayed offloading both enabled and disabled. Preserve its logits and gradient comparisons against the baseline (`rtol=atol=1e-2`).
- Retain graph-only replay’s `output == value` and `output2 == value`, and eager multi-reader reuse’s old values 17/29 and new value 43 in [the buffer tests](https://github.com/NVIDIA/Megatron-LM/blob/ec2acd019e8c19e34999c97df3de35a09ee2d3a2/tests/unit_tests/pipeline_parallel/test_pinned_activation_buffer.py#L53-L122). Eager-only epochs must still reclaim storage after all readers retire; graph-owned slots require the longer lifetime.
- Keep the disabled-buffer routing unchanged: variable MoE groups bypass the shape cache, while `core_attn` uses it, as asserted by [the routing test](https://github.com/NVIDIA/Megatron-LM/blob/ec2acd019e8c19e34999c97df3de35a09ee2d3a2/tests/unit_tests/pipeline_parallel/test_pinned_activation_buffer.py#L192-L207).
