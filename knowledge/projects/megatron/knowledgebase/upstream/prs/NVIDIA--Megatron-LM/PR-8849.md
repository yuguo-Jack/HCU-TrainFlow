## Summary

Update the development base image on `main` to `nvcr.io/nvidian/nemo:fw-base-26.12.rc0`. Keep the GitHub pin, Dockerfile default, and GitLab amd64/arm64 dev rows aligned; LTS pins are unchanged.

Authenticate GitHub builds to NGC using `NGC_API_USER` and `NGC_API_KEY`, following [Export-Deploy's workflow](https://github.com/NVIDIA-NeMo/Export-Deploy/blob/b0688b2a064a75604b0df8b7553ae052fefe05f4/.github/workflows/cicd-main.yml). Pass only those secrets through both shared-build callers.

The image introduces PyTorch 2.15 and Triton 3.9. Compatibility changes address observed CI failures while retaining those versions and the image's CUDA stack:

- Remove FLA 0.5.1's stale `BT` autotune key; validate the CP kernel import during the build.
- Install a guarded block-pointer lowering adapted from [SGLang #45470](https://github.com/sgl-project/sglang/pull/45470), with Apache-2.0 attribution in the vendored file. It reconstructs block-pointer loads/stores using ordinary pointer operations on Triton versions that removed the API; native implementations are left untouched. This supports the pinned FLA and existing GDP kernels without a Triton downgrade.
- Backport [FlashAttention #2787](https://github.com/Dao-AILab/flash-attention/pull/2787) in the dev image for its bundled CuTe code to use `cute.arch.sub_packed_f32x2` with the existing Quack 0.6.5 pin. Add a dedicated GB200 GDP numerical unit bucket.
- Set `TORCH_DIST_USE_NCCL2=0` in the dev image to retain the previous lazy process-group behavior. The previous CI run hit eager-communicator memory exhaustion and NCCL split errors matching [PyTorch's upstream investigation](https://github.com/pytorch/test-infra/issues/9006).
- Scope the existing TE pickle opt-in to the two routing-replay tests that load the same CI-managed DeepSeek checkpoint as their already opted-in sibling tests.
- Propagate non-strict model-load exceptions while preserving the existing strict-to-non-strict TE compatibility fallback. A strict control exposed a swallowed legacy-extra-state rejection in the inference-optimized SwiGLU fixture; enable the same fixture-scoped opt-in used by its trusted siblings. Its existing numerical reference is unchanged. Two regression cases cover error propagation.
- Restore the conditional CTA barriers around release/acquire signaling from [upstream Kraken](https://github.com/meta-pytorch/kraken/blob/819d403b439c7fcb2ca15319dfb3ca9b63f5baee/kraken/_ptx_utils/symm_mem_barrier.py). The omitted barriers let only the participating lanes order memory while the rest of the CTA could advance. Focused validation completes all 99 warmups on GB200 and GB300 and passes all 12 existing NVFP4 MoE tests. Add two 64-token NVLS graph replay/refresh variants. The preceding a08 GB200 inference bucket passes all 14 NVFP4 MoE cases, including both new NVLS variants. These cases require Blackwell; H100 coverage is inapplicable.
- Correct MFSDP profiler attribution to group all runtime correlations under their enclosing collective operation and ignore uncorrelated asynchronous annotations. Preserve correlated zero-kernel groups and collective-count assertions.
- Isolate the FSDP buffer-peak test from version-dependent GEMM scratch while retaining its original three/four-full-buffer bounds. Correct ZeRO-1 accounting for the full persistent Partial gradient and its sharded optimizer view, take the baseline after clearing process-global cuBLAS caches, and derive the first-step peak from backward and Adam buffer lifetimes. The 1 MiB accounting slack is unchanged.
- Give the four marked GB200 CP/pipeline CUDA-graph replay cases their own process to bound accumulated communicator state. The catch-all excludes that file automatically; all tests, numerical assertions and existing timeouts remain enabled.
- Run the 19-minute KDA matrix in its own H100 bucket to keep the progressing broad SSM suite within its existing job budget. Preserve current/legacy coverage and timeouts.
- Add compiler coverage (including ordinary-pointer passthrough) and exact GPU replay checks for strided/negative offsets, advance loops, 2-D/3-D boundary masks, transposed layouts, and FP8 padding, plus CPU profiler regression tests.
