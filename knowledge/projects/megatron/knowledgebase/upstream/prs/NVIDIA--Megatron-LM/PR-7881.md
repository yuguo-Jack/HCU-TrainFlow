# What does this PR do?

Reuse packed chunkwise CP metadata across GDN and KDA layers in eager THD training.

For CP > 1, each layer validates packed offsets on the host and requests an FLA CP context. Cache a CPU offset snapshot and the metadata-only context on the current `PackedSeqParams`, then use the snapshot for length, divisibility, and Q/KV checks.

Entries retain the source tensor and refresh when its PyTorch version changes. Context keys also include the actual CP group, convolution width, and builder. The caches are bounded; tensors without version counters fall back to rebuilding. This covers tracked PyTorch mutations in eager execution. Packed chunkwise CP CUDA graph capture remains unsupported.

Related to #6796, which handles CP=1 packed metadata and CUDA graph support. This change covers eager packed chunkwise CP.

## Validation

On clean final head `17fb41e73`, all 18 CPU tests pass in Linux with PyTorch 2.11.0+cu130 and normal Core imports. They cover context reuse, tracked view/in-place mutations, same-shaped replacements, fresh microbatches, padded offsets, CP-group/convolution-width keys, bounded caches, and inference tensors without version counters.

Unchanged production code from dev `f80139c3e`, with the same updated tests and new helper, fails both outer-forward controls at the expected assertion: GDN and KDA request three contexts rather than one. Source hashes, import paths, and the clean final checkout were verified. CUDA remains uninitialized.

The forward-routing tests call the actual GDN/KDA outer methods with computation, layout conversion, and the FLA context builder stubbed. They verify metadata lifetime and routing, not recurrence numerics or real CP communication. GPU parity, throughput, and full repository CI are pending; no speedup is claimed.

`tools/autoformat.sh` passes Black, isort, pylint, and Ruff. Its non-blocking mypy stage reports missing dependencies and existing diagnostics; type checking is not clean.
