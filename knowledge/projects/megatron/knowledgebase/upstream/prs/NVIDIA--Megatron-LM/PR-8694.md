# Fix static text generation server crashes and GTP assert flag names

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8694) · state: open · merged: False

## Original PR description

Fixes three bugs on `main`, one commit each.

1. `tools/run_text_generation_server.py` and the static-engine path of `tools/run_inference_performance_test.py` read `args.inference_max_sequence_length`. `--inference-max-seq-length` is registered with `dest='inference_max_seq_length'`, so both tools crash at startup:

   ```
   AttributeError: 'Namespace' object has no attribute 'inference_max_sequence_length'
   ```

2. `run_mcore_engine()` builds the response tokens as `x.prompt_tokens + x.generated_tokens.tolist()`. That expects list prompt tokens and tensor generated tokens, which only the legacy static engine returns. The default static engine runs on the dynamic engine and returns the reverse, so every `PUT /api` returns HTTP 500. The first error is `'list' object has no attribute 'tolist'`. Patch that and you get `unsupported operand type(s) for +: 'Tensor' and 'list'`. A small helper now turns each token and log-prob field into a plain Python list before the prompt and generated parts are joined. Both engines fill the log probs with lists today, but `InferenceRequest` declares them as tensors, so they get the same treatment.

3. When GTP is requested without a GTP-capable TransformerEngine, the assert told users to set `--gtp_remat-weight-remat-size` and `--expert-generalized-tensor-parallel-remat-size` to 1. Neither flag exists. GTP is controlled by `--tensor-parallel-num-weight-shards` and `--expert-tensor-parallel-num-weight-shards`. Those must be at least the matching TP size, so "set to 1" was wrong too for TP > 1. The message now says to leave them unset or set them equal to `--tensor-model-parallel-size` / `--expert-tensor-parallel-size`.

## Testing

New unit tests (no GPU needed):

- `tests/unit_tests/inference/test_static_inference_tools.py` parses the real inference arguments and checks what both tools pass to `StaticInferenceContext`.
- `tests/unit_tests/inference/test_run_mcore_engine.py` runs `run_mcore_engine()` against stubbed engine results for each engine's tensor/list mix. It checks the joined tokens and log probs, and that the response serializes to JSON.

With this branch all 5 cases pass. On `main`, 4 fail with the errors quoted above. The legacy-engine case passes there because `main` already handles that type mix.

End-to-end on 4 GPUs: `tools/run_text_generation_server.py` with a randomly initialized TP2 × PP2 GPT, a WordPiece tokenizer and `--inference-max-seq-length 512`, then one greedy `PUT /api` (`top_k=1`, 8 tokens).

- `main`: the server crashes at startup with the `AttributeError` from (1).
- Commit 1 only: the server starts, and the request returns HTTP 500 with `'list' object has no attribute 'tolist'`.
- This branch: HTTP 200 with the prompt and generated tokens.

A request with `"logprobs": true` still fails, for an unrelated reason. `StaticInferenceEngine` builds its dynamic context with `materialize_only_last_token_logits` on, and the server always asks for prompt log probs, so the request hits the assertion in `DynamicInferenceEngine.add_request`. Fixing that means either materializing all logits or dropping prompt log probs from the response, so it belongs in a separate PR.
