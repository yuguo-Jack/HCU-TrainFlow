# Deprecate the parallel_state accessors of the global grid

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8765) · state: closed · merged: False

## Original PR description

Depends on #7029, #8026, #8730, #8733, #8747, #8745, #8746, #8758, #8759, #8760, #8761 and #8762. Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/54e85c322f...yx/pstate-a1-accessor-deprecation).
- The code needs #8747's registry, which stays silent and which the MIMO example and the finetuning data loader read. It wraps #6293's `warn_global_process_group_fallback`, which #8733 brings, and makes #8733's fallback helper re-entrant. The memory-buffer aliases point to the `megatron.core.utils` buffer of #8026 and #8730.
- The classification test lists `register_model_parallel_teardown`, which #7029 defines.
- The new guard test scans the code outside Megatron Core, so it needs the PRs that move that code off the accessors: #8758, #8759, #8760, #8761, #8762, #8745, #8746 and #8730, and what they contain (#8740, #8741, #8742, #8743, #8744, #8757, #8753, #8754, #8737, #8738 and #8726). Without them it fails.
- The merges resolve textual conflicts between these branches in `parallel_state.py`, `initialize.py`, `module.py`, `pretrain_hybrid_flex.py`, `pretrain_vlm.py` and three example scripts, and regenerate the process-group allowlist where it conflicted. Each merge commit lists its resolutions.

Land this after #8034. The warning of `get_amax_reduction_group()` names #8034's `amax_reduction_group` as its replacement, which does not exist without it.

#8766 stacks on this PR.

**Why.** The `parallel_state` accessors read one global grid, which belongs to a single model. Megatron Core takes its groups from its callers now, and its remaining global reads are warned fallbacks that the process-group usage check counts. Code outside Megatron Core still gets no notice that the accessors are going away.

**What.**
- Every group, rank and size accessor, stage predicate, virtual-pipeline getter and setter, rank and size override setter, and memory-buffer alias in `parallel_state` now emits `ParallelStateDeprecationWarning`, a `FutureWarning`.
  - It fires once per call site, says the function is deprecated in 0.21 and removed in 0.23, and names the replacement: a `ProcessGroupCollection` field, or a helper such as `amax_reduction_group` or `get_pp_first_rank`.
  - The warnings of `get_pipeline_model_parallel_next_rank()` and `get_pipeline_model_parallel_prev_rank()` say that `get_pp_next_rank()` and `get_pp_prev_rank()` do not wrap around: they return `None` on the last and the first stage. Code that relies on the wrap-around takes the peer from `torch.distributed.get_process_group_ranks(pg_collection.pp)`.
  - Bootstrap, teardown and the registry do not warn: `initialize_model_parallel`, `destroy_model_parallel`, `is_initialized`, `model_parallel_is_initialized`, `register_process_groups`, `get_registered_process_groups` and `build_process_group_collection`.
  - Under `torch.compile` the wrapper calls the undecorated function. A compiled region traces the accessor as before, without a graph break, so `fullgraph=True` still works. The traced call does not warn.
  - A warning hook (`showwarning`, `logging.captureWarnings`) that calls an accessor, or reads the grid in a fallback block, warns once instead of recursing: each thread skips the warnings it is already showing. The helper behind every `ProcessGroupFallbackWarning` gets the same guard.
  - A call site is recorded only after its warning has been shown, so under an error filter every call raises, in every thread.
- Calls from `megatron/core` do not warn, so a core fallback still emits exactly one `ProcessGroupFallbackWarning`. `tools/check_process_group_usage.py` counts core calls of the group, rank and size accessors. It does not count the stage predicates, the overrides, the virtual-pipeline state, `get_all_ranks()`, the dynamic context-parallel group maps or the memory-buffer aliases, so a core call of those neither warns nor fails the check. #8766 closes that gap.
- New `global_process_group_fallback()` for fallbacks outside Megatron Core. It emits the `ProcessGroupFallbackWarning` and returns a block in which the accessors do not warn.
- Training, post-training, elastification and the examples made 64 accessor calls, nearly all in fallbacks for callers that omit their groups. They now read the grid only inside such blocks. Each fallback warns once, as before, and keeps the accessors' semantics, including the rank and size overrides.
  - With `--lazy-mpu-init`, `initialize_megatron()` sets the tensor-parallel overrides because no grid exists yet. That is bootstrap, so it ignores the setters' warning.
  - The BERT and T5 example dataset providers take the run's `pg_collection`, as `pretrain_gpt`'s does. The MIMO example checks the registry instead of each global group.
  - `build_data_loader()` in `tasks/finetune_utils.py` samples over the registered collection's `dp_gtp_remat` group, or `dp` in a collection without that field, as `build_pretraining_data_loader()` does. `finetune()` runs on the grid that `initialize_megatron()` registered, and no caller passes it groups, so a warned fallback there would warn about an argument nobody can pass.
  - `RLSetupCallback` in `megatron/rl/training_setup.py`, where main now reinitializes the GRPO microbatch calculator, takes the size of the model's data-parallel group (`dp_gtp_remat`, else `dp`) instead of `get_data_parallel_world_size()`. The two differ only when the data-parallel world-size override is set.
  - `tasks/eval_utils.py` is not changed. It imports `megatron.schedules`, removed in 2023, so it cannot be imported.
- `pyproject.toml` ignores the warning in tests, which set up the grid on purpose. The filter imports `megatron.core.parallel_state` when pytest reads its config. Where `megatron` cannot be imported, pytest 9.1.1 only emits `PytestConfigWarning: Failed to import filter module` and the run goes on.
- `docs/api-backwards-compatibility-check.md` gets the deprecation schedule, and the testing skill notes the filter.

**Tests.**
- New `tests/unit_tests/test_parallel_state_deprecation.py`:
  - every deprecated function warns once per call site, before it runs, and names its replacement, including the peer-rank caveat;
  - bootstrap and the registry stay silent, and a fallback block reports one fallback warning;
  - a core fallback raises no accessor warning. On the standard grid, `test_core_fallbacks_warn_once_without_accessor_warnings` counts only the fallback warning of `resolve_process_groups`: the TP helper's own fallback warning comes with #8060, which this PR's base does not have;
  - strict mode leaves the accessor warning a warning;
  - the training fallbacks give the same names and groups as the model's collection and honor the overrides;
  - `torch.compile(..., backend="eager", fullgraph=True)` traces an accessor;
  - warning hooks do not recurse, and under an error filter a call raises even while another thread's warning for the same site is raising;
  - the finetuning data loader samples over the registered data-parallel group.
- New stdlib-only `tests/unit_tests/test_parallel_state_accessor_uses.py`. It scans `megatron/` outside core, `examples/`, `tools/`, `tasks/` and the root scripts, and fails on a deprecated call outside a fallback block or the bootstrap exemption. It skips `tasks/eval_utils.py`, and a test fails once that file can be imported again.

On 4 GPUs against its base, this PR's test files show no failures and no regressions:
- `test_parallel_state_deprecation.py`: 102 new tests pass, including the standard-grid tests. `test_core_fallbacks_warn_once_without_accessor_warnings` failed on GPUs before the sync merge narrowed it.
- `test_parallel_state_accessor_uses.py`: 5 new tests pass, with 13 subtests.
- The other files pass the same number of tests on both sides: `rl/test_rl_utils.py` 176, `data/test_get_batch.py` 170 (205 skipped on both sides), `training/test_dataset_providers.py` 103, `data/test_dataset_provider_process_groups.py` 79, `training/test_dataset_ownership.py` 45, `data/test_data_path_process_groups.py` 44, `elastification/test_elastification_process_groups.py` 35, `training/test_training_fallback_warnings.py` 26 and `data/test_packed_pretrain_process_groups.py` 8.

In the integration run (main 77391e71cc with all #6307 PRs and the main-based gap fixes merged, the full unit-test suite on 4 GPUs and on 8 GPUs over two nodes), `test_parallel_state_deprecation.py`, `test_parallel_state_accessor_uses.py` and `rl/test_rl_utils.py`, the test files this PR changes, show no regressions against main.

Before the sync, the branch ran both new files on 4 CPU ranks with Gloo: 103 passed, the same per test as on the stacked version, and the 3 standard-grid tests need GPUs. The `torch.compile` test hangs with the CPU environment's default Triton stub and passes with a fixed one. The stdlib run of the guard passes. On that code the process-group checker reported 152 core reads, 9 of them guarded, before and after this PR.

Earlier GPU runs used the stacked version of this PR. A version before the review fixes passed the new tests on 4 GPUs, including the standard-grid tests, with no regressions in the rest of the unit tests. A 10-iteration TP2×PP2 GPT run of it with `--strict-process-group-fallbacks` logged neither warning. Before the sync, with the other process-group changes from #6307 applied, 4-GPU training smokes under strict mode recorded no deprecation or fallback warning on any rank. A control script that calls an accessor from outside Megatron Core recorded the warning on every rank, so the smokes did see warnings off rank 0.

**Compatibility.**
- Nothing changes on the standard grid except the new warnings.
- Code outside Megatron Core that calls an accessor, such as Megatron-Bridge, sees one `FutureWarning` per call site. A test suite that turns `FutureWarning` into errors needs a filter for `megatron.core.parallel_state.ParallelStateDeprecationWarning`.
- The `DeprecationWarning`s of `set_virtual_pipeline_model_parallel_rank` and `get_hybrid_data_context_parallel_groups` become this warning.
- The new warning is not a `ProcessGroupFallbackWarning`, so `--strict-process-group-fallbacks` leaves it a warning.
- The API compatibility check skips functions whose decorator name contains "deprecated", as it does for `@deprecated`.
- Two questions for maintainers under #6307:
  - A compiled caller never sees the warning. The `torch.compile` short-circuit is there on purpose, so that compiled regions trace as before. Is that acceptable, together with the per-call cost below?
  - The guard skips `tasks/eval_utils.py`, which cannot be imported. Should this PR delete the file instead?
- Needs `determinism-exempt`. `megatron/training/utils/common_utils.py` is a registered kernel file, and it changes only in how the fallback reads the grid.
- Each accessor call costs more. Stock training reaches the accessors only in fallbacks or about once per iteration. Code that calls an accessor every microbatch pays about 0.5 µs per call.

One call of `get_tensor_model_parallel_world_size()` with the size override set (CPU, Python 3.12, torch 2.8; best of 7 runs of 1M calls, loop included; range over 4 runs):

| Caller | ns per call |
|---|---|
| Undecorated function (main) | 32-35 |
| From `megatron/core` | 440-475 |
| From outside core, after the site's first warning | 490-550 |

The `torch.compile` check is 40-55 ns of that. The re-entrancy guard runs only on a site's first call.
