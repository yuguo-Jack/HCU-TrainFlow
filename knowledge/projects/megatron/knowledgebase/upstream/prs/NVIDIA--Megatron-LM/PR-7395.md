## Summary

  With TP > 1, duplicated TE projections can retain `partition_dim=0`
  even though their weights are replicated. Muon then gathers complete
  replicas as if they were shards and computes its update using the
  wrong logical matrix shape.

  - **[P1][correctness]** Restore canonical replicated metadata
    (`tensor_model_parallel=False`, `partition_dim=-1`,
    `partition_stride=1`) in `TELinear` and
    `TERMSNormDuplicatedLinear`. Cover actual TP2 Muon updates against
    an unsharded reference for tall and wide matrices.
  - **[P2][correctness]** Correct `--muon-fp32-matmul-prec` choices to
    `medium`, `high`, and `highest`. The default remains `medium`.

  The fixes are separate commits, with a developer note explaining
  the metadata contract and precision settings.

  ## Validation

  - Four targeted cases passed on each of four GPU ranks, with no skips.
  - CLI checks verified valid values, rejected values, and the default.
  - Black, isort, pylint, ruff, copyright, and diff checks passed.

  GPU validation used a GB300 development container with PyTorch
  2.12.0a0, Transformer Engine 2.20.0.dev0+0a2ebe94, and Emerging
  Optimizers 0.3.0. Upstream CI validation is still required.
  Local mypy did not pass due to missing dependencies and type diagnostics.

### Add regression coverage for the precision CLI fix

The corrected choices in [arguments.py](https://github.com/NVIDIA/Megatron-LM/blob/2598e3d67fd14757d76c3465da5a4cefe05bd79d/megatron/training/arguments.py#L3608-L3615) are right, but the added tests don't exercise argument parsing. Restoring the old list would again reject `--muon-fp32-matmul-prec highest` and accept `low` without those tests detecting it.

Add parser regression tests alongside the existing Muon CLI-to-config test in [test_argument_utils.py](https://github.com/NVIDIA/Megatron-LM/blob/2598e3d67fd14757d76c3465da5a4cefe05bd79d/tests/unit_tests/test_argument_utils.py#L79-L88). Its existing imports support this proposed addition:

```python
@pytest.mark.parametrize("value", [None, "medium", "high", "highest"])
def test_muon_fp32_matmul_precision_cli_reaches_config(value):
    parser = add_megatron_arguments(ArgumentParser())
    flags = [] if value is None else ["--muon-fp32-matmul-prec", value]
    args = parser.parse_args(flags)
    expected = "medium" if value is None else value

    assert args.muon_fp32_matmul_prec == expected
    kwargs = _default_config_from_args(OptimizerConfig, args, return_instance=False)
    assert kwargs["muon_fp32_matmul_prec"] == expected


@pytest.mark.parametrize("value", ["low", "invalid"])
def test_muon_fp32_matmul_precision_cli_rejects_invalid_values(value):
    parser = add_megatron_arguments(ArgumentParser())
    with pytest.raises(SystemExit) as exc:
        parser.parse_args(["--muon-fp32-matmul-prec", value])
    assert exc.value.code == 2
```

These checks preserve acceptance and config forwarding for `medium` and `high`, cover the newly accepted `highest`, retain the omitted-flag default of `medium`, and reject both `low` and an unrelated invalid value. As a regression-sensitivity check, restoring the base choice list should fail the `highest` and `low` cases. This is proposed code, not an executed result; verify it before adopting it.

### Use double quotes in the changed CLI strings

The new choice and help strings in [arguments.py](https://github.com/NVIDIA/Megatron-LM/blob/2598e3d67fd14757d76c3465da5a4cefe05bd79d/megatron/training/arguments.py#L3612-L3614) use single quotes, while the protected [style guide](https://github.com/NVIDIA/Megatron-LM/blob/a0ef64615cc3d2574ffbaac70f324ee365f5ed34/style-guide.md#L9-L10) requires double quotes. Black preserves quote style, so formatting won't correct this.

Replace those three lines with:

```python
        choices=["medium", "high", "highest"],
        help="PyTorch FP32 matmul precision for Newton-Schulz iteration. "
        "Use highest to retain full FP32 arithmetic.",
```

Keep the choice values, order, help text, and existing default unchanged. Acceptance is a static check that the changed literals use double quotes; the parser checks above should retain exactly the same outcomes. This replacement is also unexecuted.
