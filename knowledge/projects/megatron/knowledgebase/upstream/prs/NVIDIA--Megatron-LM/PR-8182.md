# [dev] mla(perf): Latent CP for Kimi-K3 MLA

## Original PR description

# What does this PR do?
<!-- Add a one line overview of what this PR aims to accomplish. -->

Adds `MLAWithLatentCP`, an experimental MLA self-attention variant whose context parallelism exchanges the **compressed KV latent** (`kv_lora_rank + qk_pos_emb_head_dim` channels, 576 for Kimi-K3) between CP ranks instead of the up-projected K/V. Each ring step re-runs the inherited `linear_kv_up_proj` on the received latent, attends, and merges the partial outputs in fp32; backward re-circulates `(latent, dlatent)` pairs and recomputes the up-projection per step, so no full K/V is ever saved. Core attention calls the public Transformer Engine `fused_attn_fwd/bwd` (cuDNN) or FlashAttention-4 directly, selected by the existing `attention_backend` flag. The existing MLA path is untouched; no TE private function is used.

Enabled by `TransformerConfig.mla_latent_cp=True` (GPT decoder specs and the hybrid stack, MTP included). Supports THD packed/padded input in the zigzag CP layout, causal MLA with RoPE as in `MLASelfAttention` and with the output gate, TP with sequence parallelism, CP=1, dynamic CP (p2p mode), `cp_comm_type` `p2p` / `a2a` / `a2a+p2p` (Ulysses stage over the hierarchical a2a group with the up-projection sliced to the rank's heads), fused weight-gradient accumulation, MXFP8 including quantized parameters. Unsupported combinations are rejected in `TransformerConfig.__post_init__`. Contiguous CP input for MLA depends on #7545 (MLA input-layout conversion); `dev` already rejects `cp_partition_mode=contiguous` with MLA.

## Why

For long-context MLA training the CP ring moves full K/V (≈ 0.5 GB per hop at 512K tokens / CP16) and TE's wrapper keeps all P receive buffers alive through the forward. Exchanging the latent cuts the payload 13× and lets each step's buffers die immediately; attention backends can be called directly (FlashAttention-4 is not reachable through TE's CP ring). The latent approach has a structural cost — K/V must be rebuilt per ring step — which the optimizations below pay back.

## Optimizations (in the order they were added; effects measured on the proxy below)

1. **Latent payload, per-step up-projection recompute**: ring payload 503 MB → 38 MB per hop; peak reserved memory −6.4 GB; structural cost ≈ +1 s recompute and ≈ +2.4 s K/V assembly per step at 16 ring steps.
2. **Direct core-attention calls** (cuDNN via TE's public API, or FA4): TE's private THD correction kernels gone (−0.85 s); FA4's backward is 9–11% faster per launch than cuDNN at these shapes (qk 192 / v 128) → −2.9 s/step vs the cuDNN latent ring. FA4 is only available under CP through this path.
3. **fp32 online-softmax merge** as one fused in-place kernel per step; the final merged output/LSE is reused for every backward step (no per-step correction).
4. **One TP all-gather of the latent before the ring, one reduce-scatter after** instead of per-step SP collectives inside the TE linear: −1.5 s of compute-stream NCCL kernel time.
5. **K/V assembly as one autograd Function** with strided copies in both directions (avoids `cat` with a stride-0 operand and the unvectorised split-backward cat): ≈ −2.3 s of kernel time.
6. **Up-projection parameters as Function inputs**: one `AccumulateGrad` / DDP hook per parameter per microbatch, which dynamic CP and DDP bucket readiness require.
7. **`a2a+p2p` and `a2a`**: latent all-gathered over the a2a group, queries/outputs exchanged tokens↔heads, gathered chunks permuted into the zigzag of the p2p group; the ring runs unchanged with P/A steps on H/A heads. All per-step costs shrink with the step count and the attention kernels work on A× larger problems: 70.5 → 67.6 s ([4,4]).
8. **Head-sliced up-projection in a2a modes**: the TE module projects only the rank's H/A heads through a row slab of its weight (zero-copy view, swapped in by a per-call pre-hook after DDP's parameter all-gather completes); gradients map back to the full weight: −0.9 s at [4,4]; **66.1 s at [8,2]**.
9. **Two-stream forward ring** (TE's `cp_stream` pattern) kept behind `mla_latent_cp_two_stream` (default off): measured neutral at 64K–512K on GB300.

## Results

Kimi-K3 9-layer proxy, packed THD 512K tokens, 64 × GB300 (TP4 + sequence parallel, CP16, EP64, MXFP8, Muon, MTP1, selective recompute + fine-grained offload); step time = mean of 7 iterations after one warm-up iteration, one run per configuration; the old path is the existing `MLASelfAttention` → TE context-parallel attention (cuDNN; TE's ring has no FA4 branch). Per-iteration times of the new path are below the old path's corresponding iterations in every FA4 configuration.

| configuration | step (s) | vs old p2p | TFLOP/s/GPU | peak allocated / reserved (GB) |
|---|---|---|---|---|
| old path, `p2p` (cuDNN) | 71.01 | — | 833 | 69.0 / 83.5 |
| old path, `a2a+p2p` [4,4] (cuDNN) | 68.36 | −3.7% | 865 | 69.2 / 79.4 |
| old path, `a2a+p2p` [8,2] (cuDNN) | 67.38 | −5.1% | 878 | 69.2 / 78.6 |
| latent CP, `p2p`, cuDNN | 73.43 | +3.4% | 805 | 69.0 / 78.2 |
| latent CP, `p2p`, FA4 | 70.51 | −0.7% | 839 | 69.0 / 77.1 |
| latent CP, `a2a+p2p` [4,4], FA4 | 66.66 | −6.1% | 887 | 69.0 / 77.2 |
| **latent CP, `a2a+p2p` [8,2], FA4** | **66.10** | **−6.9%** | **895** | **69.0 / 77.1** |

`[A, P/A]` = `hierarchical_context_parallel_sizes`. TE's own hierarchical scheme also prefers [8,2]; against that best old configuration the new path is 1.3 s (−1.9%) faster, with 1.5 GB less reserved memory, and faster in every iteration (by 0.6–1.8 s). Peak allocated is reached outside MLA and is unchanged; the reserved and device-used savings (−6.4 GB / −5.4 GB vs the old p2p path, −1.5 GB / −1.7 GB vs old [8,2]) come from freeing ring buffers per step. Pure `a2a` needs heads-per-TP-rank divisible by the CP size (not possible at CP16 with 24 heads); at 64K/CP4 it is the fastest mode (20.64 s vs 20.89 s old).

**Full model.** With the feature squashed onto the Kimi-K3 preview stack and re-measured with same-commit pairs (same container, mock data, GBS 32, MTP1), the gain carries over to the full model:

| model | parallel layout | old path: TE `p2p`, cuDNN | latent CP `a2a+p2p` [8,2], FA4 | Δ step | TFLOP/s/GPU |
|---|---|---|---|---|---|
| **Kimi-K3 full model (93 decoder blocks)**, THD 512K | TP4 PP4 EP64 CP16, 256 × GB300 | 169.2 s | **157.9 s** | **−6.7%** | 715 → **766** |
| 9-layer proxy, THD 512K | TP4 PP1 EP64 CP16, 64 × GB300 | 69.93 ± 0.23 s | **65.50 ± 0.30 s** | **−6.3%** (faster in every paired step) | 846 → **903** |

Peak allocated memory is unchanged on both (164 GB on the full model's first pipeline stage), reserved memory −4.8 GB (full) / −6.4 GB (proxy), and the mock-data loss trajectories are identical to MXFP8 rerun noise. At 64K with CP2 the pure `a2a` mode replaces the ring entirely: 18.8 → 18.5 s/step on real data with parity 2.69e-4.

![Step time and throughput, old TE p2p ring vs latent CP a2a+p2p [8,2] + FA4, 9-layer proxy and full model](37_latent_cp_speedup.png)

**Numerics.** Real-data resume parity (THD 64K, 32 steps, same checkpoint and data) against the old path: max |Δ lm loss| 1.4–1.9e-4 across the modes (`p2p` cuDNN 1.42e-4, `p2p` FA4 1.91e-4, `a2a+p2p` 1.63e-4, `a2a` 1.89e-4), run-to-run floor ≈ 1e-4, no NaN/skipped steps; on the integrated stack `a2a+p2p` [2,2] 2.32e-4 and pure `a2a` (CP2) 2.69e-4, at the proxy's own rerun floor.

**Profile audit (nsys, one step).** Kernels present only in the new path are its own ring ops (fused fp32 merge, padding-row mask, second-chunk index ops, strided K/V copies, fp32 accumulates, a2a split/cat and permutation index ops) and the FA4 kernels; TE's private `thd_*` correction/half-read/reorder kernels and the cuDNN fusion helpers disappear; ≈ 280–290 of ≈ 320–330 shared kernels have identical launch counts, the rest being the per-ring-step up-projection group and NCCL op counts. GPU idle and exposed communication are unchanged across configurations. Host time of the ring per layer-microbatch: 5 / 9 ms (fwd / bwd) at [8,2] vs 24 / 25 ms for the TE wrapper.

Also explored and not included: a latent **all-gather** CP scheme (no ring, two prefix-attention calls per rank). It reaches 69.3 s at 512K but raises peak allocated memory by 24 GB, because every rank rebuilds K/V for the whole sequence and all heads; the code is kept on a side branch.

## Tests

`tests/unit_tests/transformer/experimental_attention_variant/test_mla_latent_cp.py` compares the old and new paths on identical weights, inputs and upstream gradients (outputs and all parameter gradients): TP × CP layouts up to 8 GPUs, packed and padded THD, CP=1, dynamic CP, separate KV norm, MXFP8 with bf16 and quantized parameters (including the head-slab path), fused weight-gradient accumulation, `a2a`/`a2a+p2p` including odd head counts, two-stream mode, FA4-vs-cuDNN; it also exercises the zero-copy half-KV ring step and the a2a permutation directly (CPU) and covers the config/construction/spec guards. On GB300 (TE 2.20 container): 54 passed / 9 skipped on one 4-GPU node (skips are 8-GPU cases), 9 passed on 2 nodes; the MLA/attention/GPT/hybrid regression groups are identical on `dev` with and without this branch.

## Notes for reviewers

- Only `megatron/core/transformer/experimental_attention_variant/mla_latent_cp.py` (new) plus small gated edits: `TransformerConfig.mla_latent_cp` / `mla_latent_cp_two_stream` (+ validation), the spec swap in `get_gpt_decoder_layer_specs` and `HybridStack.__init__`, and a one-line reset of the hierarchical CP groups in `parallel_state.destroy_model_parallel`.
- FA4 is driven through `flash_attn.cute.interface._flash_attn_fwd/_bwd` (FA4 has no public split API), pinned to `flash_attn_4==4.0.0b11` and SM100+; cuDNN remains the default (`attention_backend=fused`/`auto`).
- Dynamic CP is supported for `p2p`; the `a2a` modes reject it (MCore has no hierarchical variant of the per-microbatch CP groups).
- The measured results come from an internal proxy setup that depends on a preview branch and is not reproducible on `dev` as is; the unit tests are the validation that runs here.
