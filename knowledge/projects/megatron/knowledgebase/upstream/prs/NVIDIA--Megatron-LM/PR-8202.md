# refactor(training): separate RNG finalization from config validation

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8202) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Separate RNG configuration finalization from container validation.

- Remove the RNG finalization call from `ConfigContainerBase.validate()`, so validating a recipe no longer changes RNG policy or the model's derived tracker fields.
- Explicitly finalize those settings in shared `initialize_megatron()` startup, after validation and before RNG/model initialization. This covers training, inference, and lazy/skip-MPU initialization.
- Preserve the existing finalization logic, legacy args/YAML model-factory behavior, and custom-model handling. No new lifecycle framework or copyright-year changes.

This is the focused RNG follow-up discussed in #6925, related to training-loop consolidation #3554. It does not depend on #7778 or #8149.
