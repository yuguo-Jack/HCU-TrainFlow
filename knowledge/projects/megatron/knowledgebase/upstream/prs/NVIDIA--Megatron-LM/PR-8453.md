# What does this PR do?

Adds optional sequence chunking for the MTP vocabulary projection and cross entropy so long-context training does not materialize a full-sequence logits/softmax tensor for an MTP head.

`TransformerConfig.mtp_loss_chunk_size` controls the local sequence rows processed per chunk. The default is `None`, which preserves the existing dense path and behavior. When enabled, each chunk is checkpointed with non-reentrant activation checkpointing and recomputed during backward.

This complements #7478: early backward limits how many MTP heads are simultaneously live, while this change limits the peak vocabulary-sized activation within each head.

The chunked path preserves tensor-parallel and sequence-parallel label layout, optional logit scaling, acceptance metrics, argmax-returning losses, tensor observation, and `mtp_loss_early_backward`.

### Long-context memory benchmark

Latest `main`, BF16, TP=2 + sequence parallelism, hidden size 5120, vocabulary size 248320, sequence length 131000, using `ColumnParallelLinear` and `vocab_parallel_cross_entropy`:

| Mode | Time / rank | Peak allocated / rank | Peak reserved / rank | MTP loss |
|---|---:|---:|---:|---:|
| Dense | 1.695 s | 95.207 GiB | 124.904 GiB | 13.45149231 |
| Chunk 512 | 2.188 s | 6.332 GiB | 8.057 GiB | 13.45149231 |
| Chunk 256 | 2.582 s | 6.202 GiB | 7.930 GiB | 13.45149231 |

At sequence length 8192, dense versus chunked BF16 comparison produced identical loss and hidden-state gradients. The vocabulary weight gradient had relative L2 error `2.02e-3` and max absolute error `9.54e-7`, consistent with changing BF16 GEMM accumulation order.

The latest-main core MTP path above was tested directly at the target 131k sequence length.
