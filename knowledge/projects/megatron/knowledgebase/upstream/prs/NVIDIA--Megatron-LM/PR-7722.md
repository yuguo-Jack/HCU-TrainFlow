# What does this PR do?

A required CODEOWNERS team remains in `pending_expert_teams` or `pending_final_teams` when its member lookup fails or returns no members. Expanding that team to reviewers produces an empty set, however, and only the reviewer set reaches the label state machine. An unreviewed PR can consequently receive or retain `Approved` after a GitHub membership error.

Preserve unsatisfied teams explicitly in the pending sets passed to the state machine. This keeps Expert Review and Final Review pending and revokes stale Approved labels until the required approval is known.

The tests drive the production tracker with real PyGithub imported and mocked API boundaries; no GitHub mutations occur. They cover failed/empty lookups in all three stages for expert/final teams, plus known-team approval and pending-review controls.
