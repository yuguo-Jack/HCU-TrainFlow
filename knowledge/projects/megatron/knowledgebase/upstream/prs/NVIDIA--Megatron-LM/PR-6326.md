# Add per-head Muon QKV orthogonalization and fix TP>num_query_groups with Muon. Generalize to MLA and GQA

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/6326) · state: open · merged: False

## Original PR description

## Summary

- add opt-in `--muon-split-qkv-per-head` support so Muon orthogonalizes each physical Q, gate, K, and V head independently
- derive layouts from the owning attention layer for MHA, GQA, gated attention, heterogeneous layers, and MLA
- keep QKV parameters on the split path when TP fragments query-group blocks, including `TP > num_query_groups`
- reconstruct fragmented layouts across TP and GTP-remat, remove alignment padding before Newton-Schulz, and restore each rank's physical shard afterward
- preserve the old TP-aware path only for projection-level splits with complete local query groups and no GTP
- route per-head, GTP, and fragmented layouts through duplicated/non-TP Newton-Schulz; an explicit `muon_tp_mode=distributed` request warns once
- support `muon_tp_mode=auto` by explicitly selecting duplicated execution for reconstructed QKV layouts instead of forwarding `auto` to Emerging-Optimizers
- expose the behavior through Muon and AdaptiveMuon and add focused TP/GTP/MLA coverage

This branch is rebased onto current `main` at `c9e7ea765`.

## Root cause and behavior

The old projection-split path decided from each rank-local QKV row shard. When TP or GTP cut through a query-group block, the parameter could stop being tagged for QKV splitting, so the same logical weight received different Muon update rules under different parallel layouts.

Tagging now uses the owning layer's global QKV layout and accounts for TP, GTP-remat, and alignment padding. If a split cannot be performed locally, the optimizer reconstructs the logical rows before applying projection-level or per-head Newton-Schulz and then restores the TP/GTP shard.

Uniform per-head layouts use Emerging-Optimizers' batched 3D Newton-Schulz path. The `v0.3.0` dependency already pinned on current `main` provides that contract, so this PR no longer changes the dependency pin.

A genuine layer-layout mismatch still falls back to whole-matrix Muon rather than aborting. This primarily protects custom or heterogeneous modules whose parameter metadata does not describe the physical weight.

## MLA + Muon behavior change

MLA Q and KV up-projection weights now carry logical `qkv_layout` metadata. Because `muon_split_qkv=True` by default, existing MLA + Muon runs now orthogonalize those weights by logical projection slices rather than as one whole matrix. This intentionally changes Muon update geometry and training numerics by default.

Use `--muon-no-split-qkv` to retain the previous whole-matrix MLA behavior. There is currently no MLA + Muon functional golden test in the repository; future functional coverage will need golden values for the split-projection behavior.

## PR #7117 integration

This branch cherry-picks all three commits from [PR #7117](https://github.com/NVIDIA/Megatron-LM/pull/7117) in order and preserves Shiqing Fan's authorship:

- gathered QKV row accounting excludes GTP padding and is independent of rank-local shard divisibility
- tagging and execution both resolve the same GTP-remat process group, including partial process-group collections
- fallback diagnostics include the first parameter debug name
- the `tp_mode=auto` commit is now substantive: reconstructed per-head/global paths explicitly request duplicated execution and have a 4/8-GPU parity regression
- imported GTP tests exercise the public `TensorParallelMuon.orthogonalize()` path

Light review. Three things worth addressing before this leaves draft.

**1) The graceful skip was replaced by a hard failure** (`megatron/core/optimizer/__init__.py:793-847`)

Previously a QKV param whose row count did not match `sum(qkv_split_shapes)` was logged at DEBUG and left with `is_qkv=False`, so Muon fell back to whole-matrix orthogonalization. Now `param.is_qkv = True` is set unconditionally and a mismatch raises `RuntimeError`.

`qkv_split_shapes` is computed once per model chunk from `model_chunk.config` and reused for every `linear_qkv.weight`. For heterogeneous models (`heterogeneous_block_specs`, nemotron-nas), `HeterogeneousTransformerConfig.get_config_for_layer` overrides `num_query_groups` per block (`megatron/core/transformer/heterogeneous/heterogeneous_config.py:246-250`), so layers whose `num_query_groups` differs from the top-level config will now abort optimizer construction instead of degrading gracefully.

Suggest keeping the fallback for the shapes-do-not-match case and reserving `RuntimeError` for layouts that *should* have matched:

```python
                if expected_global_rows != sum(global_split_shapes):
                    log_single_rank(
                        logger,
                        logging.DEBUG,
                        f"Emerging optimizer QKV split skipped for {name}: "
                        f"global_rows={sum(global_split_shapes)}, local_rows={param.shape[0]}, "
                        f"tp_size={tp_size}, gtp_remat_size={gtp_size}",
                    )
                    param.is_qkv = False
                    continue
```

Alternatively, compute `qkv_split_shapes` per parameter rather than caching one value for the whole chunk.

**2) The uniform per-head path cannot run against the pinned dependency**

`pyproject.toml:239` and `uv.lock:1136` pin `emerging_optimizers` to `v0.2.0`, but `_require_batched_newton_schulz_support()` requires `>= 0.3.0`. Uniform head sizes — i.e. every real model, since all splits are `kv_channels` — hit `len(set(split_shapes)) == 1` at `emerging_optimizers.py:411`, so `--muon-split-qkv-per-head` raises `RuntimeError` in the CI container and in any env built from the lockfile.

Every new test that reaches the batched branch monkeypatches `EMERGING_OPTIMIZERS_VERSION` to `Version("0.3.0")`, so `orthogonalize_fn(grad.view(len(split_shapes), head_rows, -1))` is only ever exercised against a stubbed `center_rows`, never against the real `newton_schulz_tp`. The 3D-input contract with upstream is therefore unvalidated. Either bump the pin in this PR, or state the version requirement in the `--muon-split-qkv-per-head` help text so users see the constraint before the traceback.

**3) No coverage for the parameter-tagging logic**

The 76 new lines in `_get_megatron_emerging_optimizer` are the highest-risk part of this change — TP/GTP offset math, `local_start`, `qkv_gtp_pad_length` derivation, and two new `RuntimeError` paths — and nothing tests them. All new tests hand-set `qkv_split_shapes_global` / `qkv_split_heads_are_complete` / `qkv_split_groups_are_complete` on bare `torch.nn.Parameter` objects, so the code that *derives* those attributes never runs. Notably, the headline fix (keeping QKV params on the Muon split path when TP fragments query-group blocks, including `TP > num_query_groups`) has no test that goes through the tagging path at all.

A test that builds a small GPT model with `tensor_model_parallel_size > num_query_groups`, calls `get_megatron_optimizer` with `muon_split_qkv=True`, and asserts on the resulting `linear_qkv.weight` attributes would cover the regression this PR fixes. Per the mcore-testing skill that needs `torch.distributed.run --nproc-per-node N`; `tests/unit_tests/test_emerging_optimizers.py` already initializes model parallel via `Utils.initialize_model_parallel`, so it fits there.

Light review — logic looks sound (I traced the GTP-pad-strip → TP-gather → orthogonalize → restore ordering and the `local_start` offset math for both the fragmented-projection and per-head paths, and unit coverage is genuinely thorough). Two things:

### 1. The documented version fallback does not exist in the code

`megatron/core/optimizer/optimizer_config.py:266-269` and the matching `--muon-split-qkv-per-head` help text in `megatron/training/arguments.py` both claim:

> Batched execution requires Emerging-Optimizers 0.3.0 or newer; older versions process heads individually.

There is no version gate anywhere in `emerging_optimizers.py`. `_orthogonalize_split_qkv` unconditionally hands a 3D tensor to `orthogonalize_fn` whenever the per-head splits are uniform:

```python
if len(set(split_shapes)) == 1:
    # A 3D input selects Emerging-Optimizers' batched Newton-Schulz path.
    head_rows = split_shapes[0]
    return orthogonalize_fn(grad.view(len(split_shapes), head_rows, -1)).view_as(grad)
```

On an older `emerging_optimizers` this fails or silently misbehaves — it does not "process heads individually." The pin is also now a bare commit resolving to `0.5.0a0`, not `0.3.0`, so the stated floor is doubly misleading. Suggest dropping the fallback claim and stating the hard requirement instead:

```python
    muon_split_qkv_per_head: bool = False
    """Whether to orthogonalize each Q, gate, K, and V head independently. Requires
    ``muon_split_qkv``. Uniform head sizes take Emerging-Optimizers' batched
    Newton-Schulz path, which requires the ``emerging_optimizers`` revision pinned in
    ``pyproject.toml``. By default, Muon orthogonalizes the Q, gate, K, and V
    projection matrices separately."""
```

…and the same trim in the `arguments.py` help string. Alternatively, add a real version check if a graceful fallback is actually wanted.

### 2. MLA + Muon numerics change by default, with no opt-in

Before this PR the tagging condition was `'linear_qkv.weight' in name`, which never matched MLA (`linear_q_proj` / `linear_q_up_proj` / `linear_kv_up_proj`) — hence the `# TODO(deyuf): support MLA`. Now those weights carry `qkv_layout`, so with `muon_split_qkv` defaulting to `True` every existing MLA + Muon run silently switches from whole-matrix orthogonalization to split-projection orthogonalization. `--muon-split-qkv-per-head` is opt-in, but the MLA generalization is not.

That looks intentional given the PR title, so no change requested — just flagging that any MLA Muon functional test will need refreshed golden values (see `skills/update-golden-values`), and it's worth calling out in the PR body as a default-behavior change rather than only a new feature.

## Strict review: Muon per-head / TP>num_query_groups / MLA QKV splitting (head `da25331`)

**Findings: CRITICAL 0 · IMPORTANT 2 · SUGGESTION 1.** I reviewed all 16 changed files. I did not run the multi-GPU tests; everything below comes from reading the source.

### Findings
1. **[IMPORTANT Compatibility] Per-head + `--muon-use-syrk` breaks on emerging_optimizers 0.4.x.** When all heads have the same size, the per-head path always passes a 3-D tensor to Newton-Schulz ([emerging_optimizers.py L536-539](https://github.com/NVIDIA/Megatron-LM/blob/da25331752b227e7aa68fde3d30ca886fc06f55d/megatron/core/optimizer/emerging_optimizers.py#L536-L539)). `TensorParallelMuon` accepts `use_syrk` from EO `0.4.0.dev0`, but the repo's own gate in [layer_sharded_muon.py L65-71](https://github.com/NVIDIA/Megatron-LM/blob/da25331752b227e7aa68fde3d30ca886fc06f55d/megatron/core/optimizer/layer_sharded_muon.py#L65-L71) says 3-D input with SYRK needs `>= 0.5.0a0`. On 0.4.x the first optimizer step raises a TypeError. FDecaYed raised this flag combination in an earlier review; it is still unhandled and has no test.
2. **[IMPORTANT Compatibility] An explicit `--muon-tp-mode blockwise` is overridden without any log message.** GTP-rematerialized, TP-fragmented and row-sharded per-head QKV weights are now all-gathered and get non-TP Newton-Schulz. Before this PR, GTP+blockwise warned and kept shard-local NS, and a test covered that; the test was deleted. Now only `distributed` warns ([L430-444](https://github.com/NVIDIA/Megatron-LM/blob/da25331752b227e7aa68fde3d30ca886fc06f55d/megatron/core/optimizer/emerging_optimizers.py#L430-L444)), and the docs and help text mention only `distributed`.
3. **[SUGGESTION Simplification] Dead code and stale docstring.** `scaled_orthogonalize_fn_with_gtp_remat` still has its `qkv_split_shapes` split/fallback code and the `_warned_qkv_split_disabled` flag, but no caller passes `qkv_split_shapes` any more. Its docstring describes a fallback that `orthogonalize` no longer takes.

### What I traced and found sound
- **Tagging.** `_get_megatron_emerging_optimizer` reads the `qkv_layout` that each layer sets on its own weight: `SelfAttention.linear_qkv`, the MLA / FusedMLA / AbsorbedMLA Q and KV up-projections, and heterogeneous per-layer configs. It accounts for TP, GTP-remat and GTP padding, and a layout that does not match falls back to whole-matrix Muon.
- **Collectives are entered consistently.** `qkv_split_groups_are_complete` is the same on every rank: when `local_rows % W == 0`, every `tp_rank * local_rows` offset is aligned too. The per-head path now gathers whenever rows are sharded. So the decision to all-gather can no longer differ across a TP or GTP group.
- **Reconstruction order.** `_gather_qkv_grad` / `_restore_local_qkv_grad` gather GTP shards and strip their padding before the TP gather, then restore in reverse. This matches how GTP pads each TP slice.
- **Equivalence with the old path.** Newton-Schulz commutes with row permutations. So for GTP+TP in duplicated mode, gathering the full QKV and then splitting gives the same math as base's per-projection TP-aware duplicated NS.
- **Muon scale factor.** It is computed from the per-head (3-D batched) or reconstructed-global shape, as intended.
