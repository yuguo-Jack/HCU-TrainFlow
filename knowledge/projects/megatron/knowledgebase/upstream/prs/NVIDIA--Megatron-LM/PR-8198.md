# fix(gdn2): AUT-2519 require TP×CP head divisibility for GDN2 context parallelism

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8198) · state: closed · merged: True

## Original PR description

## Background

FDecaYed's review 5501312260 on #8112 found that dev's config check lets invalid GDN2 context-parallel layouts through. GDN2 (from main) always splits heads across CP ranks. Dev only counted CP in the head-divisibility check when `linear_cp_mode="headwise"`, and dev's default is `"chunkwise"`. So TP1/CP2 with 1 key head and 2 value heads passed validation and then failed at the Q/K split. This was found by reading the source; it was not reproduced on GPU.

## What changed

- `TransformerConfig`: when CP>1, GDN2 key and value head counts must be multiples of TP×CP in both `linear_cp_mode` settings.
- Under CP, GDN2 now raises a clear `ValueError` for `cp_partition_mode="contiguous"` and for `dynamic_context_parallel=True`. This matches the existing headwise-CP limits.
- GDN and KDA behave as before.
- The head-divisibility assert messages now also print `experimental_attention_variant`.
- Docs: added a GDN2 note to the `linear_cp_mode` docstring and to `docs/user-guide/features/context_parallel.md`.
- Tests: added `test_gdn2_head_divisibility_uses_tp_times_cp` (6 CP2 layouts), `test_gdn2_cp_support`, and a `gdn2-contiguous` case.

## Details

- This is dev-only. Main (`fb65908d`) already checks GDN heads against TP×CP for every variant, and main's `TransformerConfig` has no `cp_partition_mode` or `dynamic_context_parallel`.
- The GDN2 GPU tests use 4 key and 8 value heads with at most TP×CP=4, so their layouts are still valid.

**What I verified against source**

- **GDN2 always splits heads over CP.** [`GatedDeltaNet2.forward`](https://github.com/NVIDIA/Megatron-LM/blob/e4487716b4fa2da3e53a6ecd0ef1f9900b4da209/megatron/core/ssm/gated_delta_net/gdn2.py#L219-L234) calls `a2a_cp_to_hp(..., self.cp_size, self.pg_collection.cp, ...)` without checking `linear_cp_mode`. It then splits using `feat_dim_split`, which divides the TP-local sections by `self.cp_size` ([L85-L91](https://github.com/NVIDIA/Megatron-LM/blob/e4487716b4fa2da3e53a6ecd0ef1f9900b4da209/megatron/core/ssm/gated_delta_net/gdn2.py#L85-L91)).
  - The per-TP head check in [`_GDNBase.__init__`](https://github.com/NVIDIA/Megatron-LM/blob/e4487716b4fa2da3e53a6ecd0ef1f9900b4da209/megatron/core/ssm/gated_delta_net/common.py#L216-L229) only runs when `linear_cp_mode == "headwise"`. So under the default `"chunkwise"`, TP1/CP2 with 1 key head and 2 value heads used to pass and then failed inside the layer.
  - The new condition in [`TransformerConfig.__post_init__`](https://github.com/NVIDIA/Megatron-LM/blob/e4487716b4fa2da3e53a6ecd0ef1f9900b4da209/megatron/core/transformer/transformer_config.py#L2056-L2059) closes that gap. Requiring `heads % (TP×CP) == 0` is the same as requiring `(heads/TP) % CP == 0`, which is what GDN2's head split needs. The key-to-value head ratio (`repeat_factor`) stays the same after the split.
- **Rejecting Dynamic CP is correct.** GDN ([gdn.py](https://github.com/NVIDIA/Megatron-LM/blob/e4487716b4fa2da3e53a6ecd0ef1f9900b4da209/megatron/core/ssm/gated_delta_net/gdn.py#L18)) gets its CP group per microbatch through `resolve_cp_group`. GDN2 only uses the static `pg_collection.cp` and `self.cp_size`.
  - With `dynamic_context_parallel=True` and `context_parallel_size=1`, GDN2 would skip the all-to-all while the scheduler still shards the data. That gives wrong results without any error, so rejecting it at config time is the right behavior.
- **Rejecting `contiguous` is correct.** GDN uses `convert_module_input_tensors_cp_partition_mode`; GDN2 has no equivalent. GDN2's all-to-all assumes the zigzag layout. The new check at [L1871-L1876](https://github.com/NVIDIA/Megatron-LM/blob/e4487716b4fa2da3e53a6ecd0ef1f9900b4da209/megatron/core/transformer/transformer_config.py#L1871-L1876) comes after the existing GDN-family headwise check, so an explicit `headwise` setting still gets the older message. Its position inside `has_context_parallelism` also covers configured CP1 with Dynamic CP.
- **GDN and KDA behave as before.** The extra multiplier only applies to `experimental_attention_variant == "gdn2"`. The hybrid `'G'` path uses the same config variant, so it is covered too.
- **Existing GPU tests are not affected.** `_test_parallel_attention_correctness` sets `context_parallel_size` and `cp_partition_mode` on the config after it is built ([test_attention.py L818-L821](https://github.com/NVIDIA/Megatron-LM/blob/e4487716b4fa2da3e53a6ecd0ef1f9900b4da209/tests/unit_tests/transformer/test_attention.py#L818-L821)), so `__post_init__` does not run again. Its GDN2 layouts (4 key / 8 value heads, TP×CP ≤ 4) also pass the new rule.
- **The new tests check the right things (static reasoning only; I did not run them):**
  - `gdn2-contiguous` gets the new contiguous error under both CP fixtures.
  - `test_gdn2_cp_support` passes for static CP2 in both modes and raises the Dynamic CP `ValueError` for `dynamic-cp1`.
  - `test_gdn2_head_divisibility_uses_tp_times_cp` rejects GDN2 1/2 heads in both modes and accepts 2/4. GDN/KDA chunkwise 1/2 and 1/1 still pass, and GDN headwise 1/2 still fails. The default `cp_partition_mode` is `"zigzag"` ([L352](https://github.com/NVIDIA/Megatron-LM/blob/e4487716b4fa2da3e53a6ecd0ef1f9900b4da209/megatron/core/transformer/transformer_config.py#L352)), so these cases never reach the contiguous branch.
- **The docs are accurate.** The `linear_cp_mode` docstring and [context_parallel.md](https://github.com/NVIDIA/Megatron-LM/blob/e4487716b4fa2da3e53a6ecd0ef1f9900b4da209/docs/user-guide/features/context_parallel.md#L57-L60) match the runtime behavior above.

**Other checks.** The PR adds no new fields, arguments or locals, so there are no unused identifiers. There are no changes to checkpoints, defaults or APIs. The only backward-compatibility change is that GDN2 configs that could not run correctly (bad head layouts, contiguous, Dynamic CP) now fail at config time instead of at runtime.
