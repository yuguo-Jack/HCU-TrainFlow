# Fix aux-loss token-count tensor creation under CUDA graph capture

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8217) · state: closed · merged: True

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## Problem
\`TopKRouter.attach_and_log_load_balancing_loss\` builds the per-token-loss scale with \`torch.tensor(python_int, device=cuda)\`. That is a pageable host-to-device copy, which CUDA graph capture rejects when the \`moe_router\` scope is captured together with \`calculate_per_token_loss\`:

\`\`\`
RuntimeError: Cannot copy between CPU and CUDA tensors during CUDA graph capture unless the CPU tensor is pinned.
  router.py: routing -> _apply_seq_aux_loss -> attach_and_log_load_balancing_loss -> torch.tensor(...)
\`\`\`

## Fix
Use \`torch.full((), n, dtype=torch.int64, device=cuda)\`: a device-side fill, same 0-dim int64 value as before, so the \`all_reduce\` and the \`aux_loss * scale\` multiply are unchanged.

## Verification
- Before: nemotron3 Super release recipe (64 GB200 nodes, TE CUDA graphs \`attn mamba moe_router moe_preprocess\`, \`--calculate-per-token-loss\`, \`seq_aux_loss\`) crashed on every rank at graph capture (job 1239887).
- After: the same recipe trained 20 iterations with no tracebacks (job 1241517, W&B https://wandb.ai/adlr/mbridge-dev-zhiyul/runs/dycx4m4p).
