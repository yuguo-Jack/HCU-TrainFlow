# Use and validate the inference process groups instead of the global grid

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8054) · state: open · merged: False

## Original PR description

**Why.** Inference takes its process groups from `InferenceConfig.pg_collection`, but three places misbehave when it is partial or differs from the global grid:

- An unset field reads as `None`, which `torch.distributed` treats as the world group. On 4 GPUs, a TP=2 collection without `tp` gave the wrapper `tp_size=4`. Without `dp`, ranks offset their sampling seed by their global rank, so TP peers seeded differently (42 and 43) and could sample different tokens.
- `run_mcore_engine` built the response where the global grid reported the first pipeline stage, and asserted when no global grid was initialized.
- `MegatronLLM(use_coordinator=False)` checked the global EP size, so it asserted for models on their own groups and misjudged other grids.

**What.**
- The inference wrapper raises `ValueError` for a collection without `tp` or `pp`, and the controller for one without `dp` when the seed offset needs it. Both then use the groups directly; the controller reuses the wrapper's PP group.
- `run_mcore_engine` uses `is_pp_first_stage(engine.controller.pp_group)`, which tests the physical stage as before.
- The direct-mode EP check reads the inference config's collection, else the unwrapped model's. A model without a collection keeps the global fallback.

**Tests.** The new `test_inference_process_groups.py` and the updated `high_level_api/test_apis.py` patch global-grid reads to raise. 17 of their 44 tests fail on main; all pass with this PR on 4 GPUs. Existing wrapper, controller, engine, server and MTP inference tests match main.

**Compatibility.** Collections from `initialize_model_parallel`, `build_inference_pg_collection` and Megatron Bridge set these fields, so their behavior is unchanged. Partial collections, which silently used world groups, now raise.
