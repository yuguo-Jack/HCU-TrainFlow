# Warn before resolve_gtp_remat_group reads the global grid

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8769) · state: closed · merged: False

## Original PR description

Depends on #8734 (which contains #8017, #8031, #8042 and #8049), #8057, #8060 and #8073. Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/2e2bf0c623...yx/pstate-d5-gtp-remat-warn).
- #8734 makes `resolve_gtp_remat_group` warn and gives each of its callers an `owner`. This PR moves that warning ahead of the read.
- The updated tests come from #8057, #8060 and #8073.
- The merges regenerate the process-group allowlist where it conflicted. #8060 and #8734 each remove one use of `get_tensor_model_parallel_rank` in `tensor_parallel/layers.py`, so the merge of #8734 drops that import. Each merge commit lists its resolutions.

Land this after #8722, #8748, #8760, #8761 and #8022. They pass the owner's collection where layers were built without one:
- #8022 for BERT;
- #8748 for the linears that attention, cross-attention, MLA, GDN, DSA, CSA, RADIO, the LLaVA projector and the MoE latent projections build;
- #8722 for duplicated-mode linears;
- #8760 for the Flextron router;
- #8761 for InternViT.

Without them, this PR makes BERT, T5, MLA, GDN, DSA, CSA, VLM, Flextron and NVLM runs warn, and raise under `--strict-process-group-fallbacks`.

The `SequentialMLP` hunk in this PR is identical to #8724's, so either PR can land first and the other merges cleanly.

**Why.** `resolve_gtp_remat_group` falls back to the global grid when its caller passes no collection, or one without the `gtp_remat` or `expt_gtp_remat` field. It read the grid first and warned afterwards, and only when the global group spanned more than one rank. An error filter on `ProcessGroupFallbackWarning` could not stop the read, and the read was silent when GTP was off or the grid was not initialized.

**What.**
- When the caller names an `owner`, the fallback warns before it reads the grid, once per owner and argument like every other fallback. An error filter installed before that warning raises before each read.
- A layer built without a collection, or with one that lacks the field, still takes its GTP axis from the grid when GTP is off, so it now warns in that case too.
- A collection that sets both fields, to `None` when an axis is off, never reaches the fallback. The collection built from the global groups and the inference shard collections set both.
- `owner=None` stays silent. Its callers, `param_is_not_gtp_duplicate` and `model_parallel_cuda_manual_seed`, warn under their own names before the call.
- A `MultiModuleProcessGroupCollection` is still unwrapped first, and a rank outside its language model still gets `None` without reading the grid.
- `SequentialMLP` passes its `pg_collection` to each expert MLP, so the expert linears read their groups from the collection. 4 tests in `test_moe_process_groups.py` expect this and fail without it.
- Tests from #8057, #8060 and #8073 built layers without the GTP fields and expected no warning. They now expect it.

**Tests.** New cases in `TestGlobalFallbackWarnings` (`tests/unit_tests/test_process_groups_config.py`):
- the warning comes before the read under strict mode, with no collection, a partial one and a multi-module one;
- GTP off, and an uninitialized grid;
- no warning when the collection carries the field;
- the MIMO non-language rank;
- `owner=None`.

Before the 2026-11-01 sync, the branch ran the 4 edited test files on 4 CPU ranks with Gloo: 61 passed, and all 18 new test cases passed. No test changed outcome against the stacked version of this PR. The only difference was two tests that #8754 adds to `test_transformer_process_groups.py`, which this base does not have. 35 tests failed: 31 need CUDA, and 2 MoE fallback tests and 2 `Float16Module` cases also failed on the stacked base without this PR.

On 4 GPUs against its base:
- `test_process_groups_config.py`: 42 passed here vs 27 on the base. The 18 new test cases pass. Five of them replace 3 base cases that this PR renames or parametrizes.
- `test_moe_process_groups.py` (23), `test_transformer_process_groups.py` (24), `test_tp_group_fallbacks.py` (13) and `test_tensor_parallel_group_fallbacks.py` (21) pass the same tests on both sides.
- `test_random.py`: 20 passed on both sides. `test_model_parallel_cuda_manual_seed` fails on both sides because it needs 8 ranks; the integration run passes it on 8 GPUs (two nodes).

No test regresses against the base. In the integration run, this PR's 4 edited test files pass all 104 of their tests and show no regressions against main. With all #6307 PRs merged onto main, 22 training smokes on 4 GPUs, including MoE, hybrid and LLaVA, give bit-identical losses to main and record no process-group fallback warning. GTP-on paths did not run on GPUs: GTP needs Transformer Engine 2.19 or later, and no available container has it.

**Compatibility.**
- The groups are the same as before. Only warnings change.
- Code that builds `ColumnParallelLinear`, `RowParallelLinear`, `VocabParallelEmbedding`, the Transformer Engine linears or `InferenceLinear` without `pg_collection`, or with a collection that lacks the GTP fields, now gets a `FutureWarning` even with GTP off, and raises under strict mode. The fix is to pass the owner's collection, with `gtp_remat` and `expt_gtp_remat` set to `None` when those axes are off.
- Stock runs are unaffected once the PRs in the landing note land. The collections of `initialize_model_parallel()`, `build_process_group_collection()`, the full `use_mpu_process_groups()`, the inference shard builder, the MIMO per-module grids and the checkpoint converter all carry both fields.
- Fallbacks that already warned and build a partial collection (Attention, MTP and MoE's default collection) can now add a second, field-level warning from their child layers. It is accurate but noisy. #8772 gives those collections the GTP fields, so that one omission gives one warning.
- This PR needs `determinism-exempt`. Its own diff touches `megatron/core/transformer/moe/experts.py`, a registered kernel file, through the `SequentialMLP` hunk. CI also diffs against main, and the base contains registered kernel files until the PRs below this one land.
