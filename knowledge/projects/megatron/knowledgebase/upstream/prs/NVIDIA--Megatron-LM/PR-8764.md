# Warn on global-grid fallbacks in the GTP, DDP and optimizer helpers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8764) · state: closed · merged: False

## Original PR description

Depends on #8750 (which builds on #8734, #8049, #6293, #8042, #8060, #7029, #8017, #8031 and #8730), #8752 (which builds on #8734, #6259, #8017, #8043 and #8045), #8738 (which builds on #8055, #6259 and #8037), #8035 (which contains #8034) and #8039. Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/a35708016...yx/pstate-f6a-silent-helpers). #8039 here includes its merge of #6259, which puts the intra Gloo groups in the collection that `build_process_group_collection()` returns. The base merges resolve the existing conflicts of #8035 as #8755 does: the Transformer Engine and CUDA-graph imports, `t5_model.py` and `multi_token_prediction.py`. The merge with #8039 takes its builder in `initialize_model_parallel()`, without the memory-buffer creation that #8026 removes. The merges regenerate the process-group allowlist where it conflicted. Each merge commit lists its resolutions.

The base is this large for two reasons. With #8738, which includes #8037, and #8752, stock training passes its collection to `DistributedDataParallel` and `get_megatron_optimizer`, so it reaches none of the new warnings. #8750, #8734 with #8042, and #8035 add or change calls to `resolve_gtp_remat_group`, and this PR gives each of them an `owner`.

**Why.** Three helpers in `megatron/core/process_groups_config.py` read the global `parallel_state` grid without a warning. The process-group checker exempts that file, so these reads were not counted either:
- `resolve_gtp_remat_group`, when its caller passes no collection, or one without the `gtp_remat` or `expt_gtp_remat` field;
- `setup_process_groups_for_ddp`, when `DistributedDataParallel` is built without `pg_collection`;
- `ProcessGroupCollection.setup_process_groups_for_optimizer`, a public static method that reads about fourteen groups when it is called without a collection.

A caller on its own grid got the global groups with no signal, so these fallbacks could not be removed on the published schedule.

**What.** Each fallback now emits a `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23), once per owner and argument, and returns the same groups as before.
- `setup_process_groups_for_ddp(None, ...)` warns as `DistributedDataParallel` before its first read.
- `setup_process_groups_for_optimizer(None, ...)` warns under its own name before its first read, so an error filter stops it before the grid is touched. It names itself rather than a caller because it is public. Its two in-repo callers, the adam/sgd and the emerging-optimizer paths of `get_megatron_optimizer`, pass the collection that `get_megatron_optimizer` resolved, with a warning of its own when it got none. So only direct callers that omit the collection reach this warning.
- `resolve_gtp_remat_group` takes a keyword-only `owner` and warns under it when the global group it falls back to shards weights, that is, spans more than one rank. A missing or single-rank group means GTP is off, which is what an absent field will mean once the fallback is removed, so that case stays silent. The warning names `pg_collection`, or the missing `pg_collection.gtp_remat` or `pg_collection.expt_gtp_remat` field.
- Callers of `resolve_gtp_remat_group` name themselves: the Transformer Engine linears, `ColumnParallelLinear`, `RowParallelLinear`, `VocabParallelEmbedding`, `InferenceLinear`, `MoELayer` for its latent projection, `TensorParallelMuon`, `get_megatron_optimizer` for its duplicate filters, and `setup_model_and_optimizer` for the GTP NCCL user-buffer pools. `param_is_not_gtp_duplicate` and `model_parallel_cuda_manual_seed` already warn about their own fallback, so they pass `owner=None`. Without an `owner`, the warning names `resolve_gtp_remat_group`.
- The docstrings of `DistributedDataParallel` and both setup helpers say that the fallback is deprecated.

The checker's counts do not change (146 reads): `process_groups_config.py` is exempt, and no counted read changes.

**Tests.** New `TestGlobalFallbackWarnings` in `tests/unit_tests/test_process_groups_config.py`, 10 CPU tests:
- `resolve_gtp_remat_group` warns and names its owner when the global group shards weights, names the field a collection lacks, stays silent when the global grid has no GTP, and stays silent with `owner=None`;
- building the DDP groups without a collection warns;
- the optimizer helper without a collection warns once and names itself, raises under an error filter before any accessor is called, and stays silent with a collection.

`optimizer/test_optimizer_fallback_warnings.py` now expects `owner=None` from the GTP duplicate filter.

On 4 GPUs, the GTP and DDP commit on an earlier #8049 head showed no regressions, and its new tests pass. The optimizer-helper commit had only CPU tests before it joined the combined tree. With the other process-group changes from #6307 applied, the full unit test suite shows no regressions against main on 4 GPUs. On that tree, end-to-end training smokes run with fallback warnings turned into errors, record no warning on any rank and match main's loss at every iteration. This branch itself ran the two edited test files on 4 CPU ranks with Gloo: 40 passed, against 30 on the base, and the same 2 tests fail on both trees because they need CUDA.

**Compatibility.** The groups are the same as before. The change adds warnings only.
- Code that builds `DistributedDataParallel` without `pg_collection`, calls `setup_process_groups_for_optimizer` without a collection, or builds a GTP-sharded layer without a collection that sets the GTP fields now warns once, and raises under an error filter.
- `resolve_gtp_remat_group` gains a keyword-only `owner`. Existing calls keep working and warn under the helper's name.
- Not covered here: `resolve_gtp_remat_group` reads the grid before it decides whether to warn, so an error filter cannot stop that read, and the fallback stays silent when GTP is off. #8769 stacks on this PR and moves the warning ahead of the read.
- Needs `determinism-exempt`. `transformer_engine.py`, `optimizer/optimizer.py`, `inference_layers.py`, `tensor_parallel/layers.py`, `tensor_parallel/random.py` and `moe_layer.py` are registered kernel files. Each changes only by an `owner=` keyword.
