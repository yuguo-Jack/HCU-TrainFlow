# Warn when checkpoint helpers fall back to the global process groups

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8753) · state: closed · merged: False

## Original PR description

Depends on #8017 (which contains #6259), #8023, #8044 and #8049 (which contains #6293). Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/7577c442db...yx/pstate-c6-ckpt-helper-fallbacks).
- The fallbacks use `resolve_process_groups` and `ProcessGroupFallbackWarning` from #8049, and `warn_global_process_group_fallback` from #6293.
- #8044 adds the `dp_cp_group` argument of `ensure_metadata_has_dp_cp_group`. This PR rewrites the fallbacks that #8044 added in `module.py`, `transformer/utils.py` and `core/utils.py`.
- #8023 adds the `FusedMLASelfAttention` metadata call that this PR changes.
- The new tests use #8017's `forbid_global_process_groups` and `new_group_with_same_ranks`.
- Before the sync with main, only the process-group allowlist conflicted in the merges, and the last of those merges regenerated it.

#8057 changes the `process_groups_config` import of `module.py`, and #8035 adds a `pg_collection` argument next to this PR's `gtp_replica_group` in the TE linears. Whichever lands second keeps both sides.

Land this after #8748. Until then MLA, absorbed MLA and GDN build their Transformer Engine linears with only their TP group, so stock training with GTP weight remat would warn once per TE class while the model is built.

**Why.** The checkpoint helpers filled in the global TP and DP×CP groups whenever the caller omitted them, with no warning:
- `make_tp_sharded_tensor_for_checkpoint`, `make_sharded_tensor_for_checkpoint` and `make_sharded_tensors_for_checkpoint`;
- `make_sharded_object_for_checkpoint` without `replica_id`;
- `ensure_metadata_has_dp_cp_group` without a group in the metadata or its argument;
- `MegatronModule.sharded_state_dict` and Mamba's `ExtendedRMSNorm`, for a module without `tp_group`.

Several owners also left out groups they hold. Transformer Engine layers with GTP weight remat left the replica group of their shards to a global lookup at save time. On a model built on its own grid, replica ids then span another grid's ranks, so several ranks or none write a shard.

**What.**
- Each helper fallback emits a `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23) and selects the same groups as before: the TP group and the GTP-inclusive DP×CP group, through `resolve_process_groups`. The replica-id fallback keeps the rank accessors, so ranks set with `set_tensor_model_parallel_rank()` and `set_data_parallel_rank()` still apply. The metadata warning names the function that called the helper.
- `MegatronModule.sharded_state_dict` takes its collection's `tp` when it has no `tp_group`. A module with no state of its own, such as a data-parallel wrapper, reads no TP group.
- Owners pass their groups:
  - `BertLMHead` takes a `tp_group`, which `BertModel` passes;
  - both mHC layers give their `HyperConnectionModule`s the layer's TP group;
  - the ViT, Qwen VL and Kimi vision encoders keep their decoder's TP group for the weights outside the decoder;
  - `FusedMLASelfAttention` fills missing metadata with its collection's DP×CP group;
  - the InternViT example passes the groups explicitly.
- `TELayerNormColumnParallelLinear`, `TEColumnParallelLinear`, `TERowParallelLinear` and `TEGroupedLinear` read the replica group of their GTP shards (`dp_cp`, or `expt_dp` for experts) from their collection with `vars()`, also through a `MultiModuleProcessGroupCollection`. A layer with GTP shards and no such group warns while it is built and keeps the existing fallback in `gtp_replica_rank`. Nothing reads the global grid at construction.
- The `ValueError` for a `tp_group` passed without its `dp_cp_group` asks for the missing group.
- The allowlist goes from 172 counted reads to 170: eight accessor reads become six guarded ones.

**Tests.** New `tests/unit_tests/transformer/test_checkpoint_helper_group_fallbacks.py` runs at TP=2 and skips on an odd number of ranks.
- Passed groups are communicators with the global groups' ranks but distinct from them, and every global accessor and the collection shim raise. No fallback warning may appear. This covers the helpers, `MegatronModule` with a collection and as a stateless container, `ExtendedRMSNorm` and the owners above.
- Omitted groups emit one warning that names the owner and argument, and give the same groups, ranks and shard ids as passing the global groups.
- `_gtp_replica_group` uses the collection's field, also through a multi-module collection. A missing field, an explicit `None` or a missing collection warns and returns `None` without a global read. A layer without GTP needs no group.
- `test_sharded_state_dict_dp_cp_group.py` forbids the global DP×CP group where the fallback reads it.

The new file imports `_gtp_replica_group` at module level, so on main it fails at import instead of showing each test's own failure.

On 4 GPUs against its base, `test_checkpoint_helper_group_fallbacks.py` passes all 19 of its tests, which are new because the base has no such file. `test_sharded_state_dict_dp_cp_group.py` passes 6 tests here and 6 on the base. In the integration run, which merges all #6307 PRs onto main, this PR's test files show no regressions against main: they pass 19 and 6 tests, and main has neither file. With the same changes, end-to-end training smokes on 4 GPUs give bit-identical losses to main and record no process-group fallback warning.

Before the sync with main, the branch ran on 4 CPU gloo ranks with no regressions. The 3 new `_gtp_replica_group` tests pass there, and the other 9 new tests need CUDA.

**Compatibility.**
- On the standard grid the fallbacks select the same groups, so replica ids and checkpoints do not change.
- Changes beyond the warnings:
  - An explicit `dp_cp=None` or `expt_dp=None` on a TE layer with GTP shards now warns. It used to reach the silent fallback at save time.
  - A `MultiModuleProcessGroupCollection`'s language-model group is now stamped on all four TE layers. Such a layer used to get no group and fall back at save time.
  - With `parallel_state` uninitialized, the TP fallback of `MegatronModule` and `ExtendedRMSNorm` gets `None` from the collection shim. It then uses TP=1 replica ids with a warning, where main asserted, and `ExtendedRMSNorm` caches that `None`.
  - InternViT's q/k norm, called directly without metadata, warns and uses the global DP×CP group.
- GTP unit tests that build TE GTP layers from partial collections, such as `required_pgs=['tp', 'cp', 'gtp_remat']`, emit at most one construction warning per TE class. Adding `dp_cp` or `expt_dp` to those collections would silence them without changing behavior.
- Still warn at `torch_dist` save, because their owners hold no groups for them: `FlextronRouter` and the MIMO Hugging Face encoder wrappers.
- Not covered: `InferenceLinear` passes `gtp_remat_group` to `TELinear` without a replica group, so its GTP shards still take the silent fallback in `gtp_replica_rank`. `BertLMHead`'s docstring says an omitted `tp_group` defaults to the global group without saying that this is deprecated.
- Needs `determinism-exempt`: the kernel coverage check flags `transformer_engine.py`, `mamba_mixer.py`, `multi_latent_attention.py` and `transformer/utils.py`. Only process-group plumbing and warnings change.
