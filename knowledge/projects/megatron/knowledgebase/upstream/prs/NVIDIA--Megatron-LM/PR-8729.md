# Use the module's groups in SelfAttention consistency check

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8729) · state: closed · merged: False

## Original PR description

Depends on #6293. Please review the diff from the merge of #6293 into main: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/4030e3b81f...yx/pstate-g8-realtime-tests-groups).

**Why.** `SelfAttention.run_realtime_tests` runs under `config.test_mode` with `qk_layernorm`. It checks that every tensor- and data-parallel replica holds the same Q/K layernorm parameters. #6293 moved the check onto the module's `pg_collection`, but it compares over `pg_collection.dp`, the replicate group without GTP-remat peers. The layernorm parameters are replicated across those peers too, and the global `get_data_parallel_group()` that the check read before includes them. So with GTP remat on, the check skips ranks it used to cover. It also never checked the TP group, and a `None` group reaches `torch.distributed` as WORLD.

**What.**
- `run_realtime_tests` compares over `pg_collection.dp_gtp_remat` and the module's TP group. If either is unset or `None`, it raises `ValueError` before any collective runs.
- The warned default collection that `Attention` builds without a `pg_collection` also resolves `dp_gtp_remat` when `test_mode` and `qk_layernorm` are both set. Outside `test_mode` it still resolves no data-parallel group.
- `build_inference_pg_collection` sets `dp_gtp_remat=dp` and `dp_cp_gtp_remat=dp_cp`. That collection turns GTP remat off, so its GTP-remat-inclusive groups are the replicate groups. Without this, the RL inference model (built with `get_model(pg_collection=inference_pg_collection)`) and the disaggregated inference shards would raise on the first forward pass under `--test-mode --qk-layernorm`.
- A comment in `test_process_group_fallback.py` that this change made inaccurate is reworded.

**Tests.** New `tests/unit_tests/transformer/test_attention_explicit_groups.py`:
- CPU, with stand-in groups and a recording `all_gather`:
  - the check gathers over `dp_gtp_remat` and then TP, never over `dp`, with the global accessors patched to raise;
  - an unset or `None` `dp_gtp_remat`, and a `None` TP group, raise before any collective;
  - the default collection requests `dp_gtp_remat` only for `test_mode` with `qk_layernorm`.
- 4 or more GPUs, with the module on a TP=2 grid over a TP=1 global grid:
  - no global reads, and a TP mismatch is reported as a TP discrepancy;
  - the default collection's `dp_gtp_remat` is `get_data_parallel_group()`, and building it warns;
  - the output gate is sliced at the module's TP rank.

`test_inference_shards.py::test_inference_collection_sets_the_gtp_remat_data_parallel_groups` covers the `shards.py` change.

On CPU, 4 of the new attention tests fail against #6293 and pass here. The inference-collection test fails with the `shards.py` change reverted. Before the 2026-11-01 sync, on 4 GPUs against an earlier head of #6293 with the new test file added: no regressions, 8 tests fail there and pass here, and the new TP-`None` and inference-collection tests pass. The 4 failures on both trees are `TestSelfAttention::test_self_attention_{mpu,independent_pg_smoke}`, which need 8 GPUs. Also before the sync, the branch ran on 4 CPU gloo ranks: no regressions, and the 9 new CPU tests pass.

In the integration run (main 77391e71cc with all #6307 PRs and gap fixes merged, against main), on 4 GPUs: `test_attention_explicit_groups.py` has 12 passed, all new. `test_inference_shards.py` has 26 passed vs 25 on main; the extra one is the new inference-collection test. `test_process_group_fallback.py` has 34 passed; main does not have this file. None of the three files has a regression against main. In CI, the `gpt3_mcore_te_tp4_pp1_resume_torch_dist_qk_layernorm_test_mode` functional test runs this check on the standard grid.

**Compatibility.**
- Without GTP remat, `dp` and `dp_gtp_remat` are the same group, so every collective uses the same ranks as before. With GTP remat, the check covers the same ranks as main's `get_data_parallel_group()`.
- Stock training builds the model with the full collection, which includes `dp_gtp_remat`. The check runs as before and no new warning fires.
- Behavior change that needs maintainer sign-off: an explicit collection without `dp_gtp_remat` (or `tp`), used with `test_mode` and `qk_layernorm`, now raises `ValueError` where main used the global DP group. #6293 already raises for a missing `dp`. This departs from the rule of warning wherever main worked. Should it warn and fall back instead? Should the check move to `SelfAttention.__init__`, so it fails at construction instead of on the first forward pass?
- `MultiTokenPredictionBlock` built without a collection resolves `cp`, `hcp`, `tp` and `pp` (plus `dp` with `mtp_hsm`) but no `dp_gtp_remat`, so its `SelfAttention` raises under `--test-mode --qk-layernorm`. `T5Model` resolves the full collection on #6293 and is not affected.
- The `test_mode` default collection still resolves `dp`, although nothing in `Attention` reads it any more. #6293's `test_process_group_fallback.py` asserts it, so a follow-up can drop both together.
- Public signatures are unchanged. Needs `determinism-exempt`: `attention.py` is a registered kernel file, and the change is group plumbing in a test-mode-only check.
