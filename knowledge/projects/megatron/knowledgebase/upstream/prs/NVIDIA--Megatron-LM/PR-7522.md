# What does this PR do?

Add KPool (pooled-key) DSA indexer support, NoPE support for the DSA indexer and absorbed MLA, and opt-in precision controls for matching serving-time precision under FP8 training.

This PR uses the following configuration flags:

- `dsa_indexer_qk_proj_disable_quantization`
- `dsa_indexer_kpool_use_quantization`
- `mla_proj_disable_quantization`

The DSA weights projection remains on its generic path. Its precision is controlled separately by the weights-projection options introduced by #6842; this PR does not force it to FP32 or unconditionally disable its quantization.

## Changes

- `dsa_indexer_kpool > 1`: compress keys in groups of `kpool` tokens using a BF16 per-token compression gate and an FP32 per-slot positional bias. Pool selection is performed over compressed keys and expanded back to token indices. `dsa_indexer_kpool_always_select_tail` appends each query's incomplete causal pool. Packed THD inputs restart pooling at document boundaries. The fused cuDNN DSA path is bypassed for KPool.

- `dsa_indexer_kpool_use_quantization`: optionally emulate the serving indexer's quantized KPool scoring inputs. When disabled, KPool scoring uses the unquantized configured dtype.

- `dsa_indexer_qk_proj_disable_quantization`: optionally keeps the DSA indexer's query/key projection initialization and GEMMs unquantized, typically in BF16. This flag does not control the weights projection.

- NoPE support: `qk_pos_emb_head_dim == 0` is supported by `DSAIndexer` and `AbsorbedMLA` without constructing or applying rotary embeddings.

- `mla_proj_disable_quantization`: optionally keeps absorbed-MLA projections (`q_down`, `q_up`, `kv_down`, and output projection) unquantized. Core-attention precision is unchanged.

## Motivation

The actor and rollout implementations must use matching precision for modules whose outputs affect discrete DSA top-k selection or MLA attention scores. These flags allow model bridges to explicitly reproduce the serving precision split while leaving unrelated projections and the rest of the model on their normal quantization path.

## Review summary (strict, broad scope)

I inspected all 9 changed files. The KPool selection helpers, NoPE handling in `DSAIndexer` and `AbsorbedMLA`, the opt-in precision contexts, the config validation, and the KPool paths through DSAttention's CP gather, fused bypass and top-k all line up with each other. Two real problems remain: a new unit test that fails at this head, and a numerical regression in the FP32 k_norm path.

**Findings: 0 CRITICAL, 2 IMPORTANT, 4 SUGGESTION**

1. **[IMPORTANT Testing]** `test_kpool_projection_precision_and_backward` patches `dsa_indexer_weights_proj_output_dtype`, which does not exist at this head (it comes from #6842). The patch raises `AttributeError`, so the test fails for both `seqlen` values. It also expects FP32 `weights`, but `linear_weights_proj` returns BF16 here.
2. **[IMPORTANT Correctness]** The new FP32 `k_norm` path calls `F.layer_norm` with the raw TE weight and ignores `layernorm_zero_centered_gamma`. With both flags on, the indexer keys collapse to the bias, which is roughly zero. The base code handled this case correctly.
3. **[SUGGESTION Documentation]** The `dsa_indexer_kpool_always_select_tail` docstring contradicts its `True` default.
4. **[SUGGESTION Simplification]** The weights cast in `run_fused_qk_topk_with_loss` is unreachable for KPool, and its comment describes behaviour that does not exist at this head.
5. **[SUGGESTION Performance]** `_kpool_gate_score` stays attached to every layer after selection, so it is held through the whole backward pass.
6. **[SUGGESTION Compatibility]** Freezing indexer parameters whenever the indexer loss is disabled affects every DSA model, not just KPool, and the PR description does not mention it.

**Earlier human-review items, checked against this head and fixed:**
- `rotate_activation_enabled` is passed at both KPool call sites (dsa.py L1967 and L2830).
- The APE parameter is `mark_keep_in_fp32` and non-trainable.
- Explicit 2D and 3D masks are reduced to pool validity, and the tail uses mask-derived global bounds (the CP-position example is covered by `test_kpool_explicit_mask_tail_uses_global_query_positions`).
- Packed compression uses fixed-size tensors with no host sync.
- topk/kpool divisibility and the kpool-plus-indexer-loss combination are rejected both in config and at runtime.
- `linear_wq_b` is called once, under the shared precision context.

**PR description is out of date.** It still names `dsa_indexer_kpool_fp8` and `mla_disable_attention_fp8`. It also says the head-weight projection runs in FP32 and that `linear_weights_proj` is built under the FP8-disabled context. The code instead uses opt-in `dsa_indexer_qk_proj_disable_quantization`, `mla_proj_disable_quantization` and `dsa_indexer_kpool_use_quantization`, and leaves `linear_weights_proj` on the generic path. Please update the description so reviewers and model bridges set the right flags.

**Overall risk: moderate.** The default (non-KPool, non-NoPE) paths keep their base behaviour, apart from the indexer freeze in finding 6. The failing unit test blocks CI. The k_norm regression is limited to one flag combination but silently breaks top-k selection when hit. None of the suggested tests or patches were executed in this review; they come from reading the source.
