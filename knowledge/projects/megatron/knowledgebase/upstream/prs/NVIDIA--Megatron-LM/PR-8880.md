# [Inference] Launch one block per token in the fused TP reduce-scatter + RMSNorm + all-gather

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8880) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

`fused_multimem_rs_add_norm_ag`, the fused TP communication kernel of `--inference-fuse-tp-communication`, now launches one block per token. Before, at decode sizes with H < 8192, each block ran 2-4 tokens in series with most of its threads idle. The output is unchanged bit for bit.

**Problem (performance).**
- **What the kernel does:** it runs each token's multimem reduce-scatter, residual add, RMSNorm and multimem all-gather. Every block processes its tokens one per loop iteration, and each iteration is a dependent chain: `multimem.ld_reduce`, residual add and store, block-wide sum of squares, rsqrt, reload, `multimem.st`.
- **Old geometry:** the launcher sized `BLOCK_SIZE` and the grid from the whole per-rank shard, `cdiv(T * H / 8, world_size)` threads, capped at 1024 threads and 128 blocks. One row only needs `H / 8` threads.
- **Effect below H = 8192:** a block covers several tokens and runs them in series while the extra threads are masked:

  | Shape | Blocks | Tokens per block | Lanes active |
  |---|---|---|---|
  | TP8, H = 4096, T = 64 | 4 | 2 | 50% |
  | TP8, H = 2048, T = 64 | 2 | 4 | 25% |
  | TP2, H = 2048, T = 16 | 2 | 4 | 25% |

  The kernel runs twice per layer. Models with H >= 8192 were not affected, and batch-invariant mode never uses this kernel.

## Fix

The launcher sizes blocks per token, as the variable-count collectives (`multimem_reduce_scatter_v` etc.) already do:
- `BLOCK_SIZE = min(next_pow2(H / 8), 1024)`;
- one block per token on this rank, capped at `max_num_blocks`;
- `num_warps = max(1, BLOCK_SIZE // 32)`, which also removes the old `num_warps = 0` corner for shards under 32 threads.

Both values depend only on values that are equal on every rank, as `kernel_config.py` requires. The kernel body is unchanged apart from one comment.

**Why the bits do not change.** For the same row, a block now has the same number of threads as before or fewer.
- **Rows longer than 1024 chunks (H > 8192):** both geometries use 1024 threads, so the per-window loop is the same.
- **Shorter rows:** the old block's extra threads only added masked +0.0 to the block-wide sum of squares. Triton reduces within warps and then folds warp partials with an xor butterfly, so the zero warps fold onto the same tree. The sum of squares is >= +0, so adding +0.0 is exact.
- **Rest of the computation:** elementwise per token.

## Timing

Recorded, not asserted, and preliminary. H100, 2 ranks only, per-call CUDA-event time of the real kernel from the step-3 repro run. The old and new geometries always ran in the same order, never interleaved:

| H | T = 16 | T = 64 | T = 256 |
|---|---|---|---|
| 2048 | 38.5 → 22.5 µs | 32.8 → 25.3 µs | 33.6 → 26.7 µs |
| 4096 | 30.5 → 22.4 µs | 30.5 → 24.3 µs | 36.0 → 32.4 µs |
| 8192 (same geometry) | 27.7 → 23.0 µs | 30.7 → 27.0 µs | 50.4 → 45.3 µs |

At H = 8192 both geometries are identical, so the 3.7-5.1 µs gap there is measurement-order bias, to be subtracted from the H <= 4096 gains at the same T. The H = 2048 rows and H = 4096 at T <= 64 clear that bias by 2-11 µs. At H = 4096, T = 256 the raw gain (3.6 µs) is below the bias at T = 256 (5.1 µs), so that point shows no measured gain. The GPU verification run below checked correctness only and did not time the kernel. Interleaved old and new launches, TP8 and a full decode step are still not timed, so the acceptance bar (a gain of at least 1% per decode step) is not yet checked.

The same run logged only the normalized output's maximum absolute difference, which was 0. It did not compare the residual or the gathered outputs bit for bit. The bit-identity claim rests on the argument above and on `test_replays_and_matches_shard_sized_launch` below, which compares both outputs bitwise against the old launch and passes on H100 at TP2 and TP8.

## Tests

`tests/unit_tests/determinism/kernels/test_nvls_fused_collectives.py`:
- `test_launch_runs_one_token_per_block` (no GPU): calls the real launcher with the kernel replaced by a recorder, for TP 2-8, H 2048-16384 and T 16-4096. Every block covers one row, and each token on the rank gets its own block up to `max_num_blocks`. Fails on `main` for every shape except the H = 8192 control.
- `test_replays_and_matches_shard_sized_launch` (2+ H100 with NVLink multicast; skips without): random partials, residuals and norm weights, for H in {2048, 3584, 4096, 16384} and 8, 64 and 256 tokens per rank. 256 tokens per rank means 2 tokens per block. The residual output and the normalized all-gathered output must replay bit-exactly and equal the old shard-sized launch of the same kernel.

On H100 in the CI image (`mcore_ci_dev:main`, 2026-11-02), at 2 and at 8 ranks, `test_nvls_fused_collectives.py` passes (12 cases: 8 geometry cases and 4 replays). On `main`, 7 of the 8 geometry cases fail at both world sizes (the H = 8192 control passes); the 4 replays also pass there, since on `main` the launch under test is the old one. The neighbor tests (`test_manifest.py` and `test_dynamic_engine_parallel_and_chunked_prefill.py::TestDynamicInferenceEngineParallel::test_mtp_kv_cache_inference_optimized_sequence_parallel`) pass (303 cases).

The kernel manifest moves `fused_collectives.py` out of the exempt `inference_nvls_symmetric_memory_collectives` entry into its own tested entry, `inference_nvls_fused_rs_add_norm_ag`. The determinism gate then requires this test to change with the kernel; it passes.

**Related PRs.** #8709 (n12, inference all-gather barriers) changes only the docstring of `fused_multimem_rs_add_norm_ag`; the barrier contract is unchanged. The two PRs merge cleanly and compose. If this PR lands first, `fused_collectives.py` is in a tested manifest entry, so #8709 must touch `test_nvls_fused_collectives.py` or carry `determinism-exempt`. #8709 already needs that label for its other files, so the label covers this file too. #8561 (d1), #8704 (n8) and #8712 (n16) call this launcher unchanged and merge cleanly.
