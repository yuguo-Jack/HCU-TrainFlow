# Pass process groups explicitly in the standalone examples and tools

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8746) · state: closed · merged: False

## Original PR description

**Why.** The standalone examples and the inference tools build or load a model on a process-group collection, then read the global grid again:
- `examples/run_simple_mcore_train_loop.py` passed no collection to DDP, the schedule lookup, the schedule or `finalize_model_grads`, so each fell back to the global groups without a warning.
- The examples seeded their RNG through `model_parallel_cuda_manual_seed`, which read the TP, EP, expert-TP and GTP ranks from the global grid.
- The MIMO AVLM inference example gathered its logits over the global TP group.
- `tools/run_text_generation_server.py` picked the HTTP-serving rank from the global PP, TP and EP ranks.
- `tools/run_inference_performance_test.py` set the static wrapper's pipeline flag from the global stage predicates.
- The BERT embedder split its blocks over `parallel_state.get_data_parallel_group()`.

On a grid that is not the global one, these reads can pick other ranks than the model runs on.

**What.**
- The simple training loop, both TRT-LLM export examples and the MIMO AVLM inference example collect their groups once, right after `initialize_model_parallel`. They pass that collection to the model, the RNG seeding (as explicit ranks), DDP, `get_forward_backward_func` (as `pp_size`), the schedule, `finalize_model_grads` and the logits gather. The export README shows the same flow.
- `run_text_generation_server.py` picks the serving rank from the model's collection.
- `run_inference_performance_test.py` stops reading the stage predicates and uses the wrapper's `pp_group`, as `prep_model_for_inference` does.
- The BERT embedder passes its model's `dp_gtp_remat` group, the group `get_data_parallel_group()` returns by default. `get_blocks_by_rank` takes it as a required keyword argument.

**Tests.** New `tests/unit_tests/tools/test_tool_process_groups.py` gives the static wrapper a pipeline group unlike the global grid and the embedder a data-parallel group of its own, with the global accessors patched to raise. The tests mock the wrapper, controller and engine, so they check the wiring, not inference. The embedder test calls `pytest.importorskip("h5py")`, and h5py is not a declared dependency, so it probably skips in CI.

On 4 GPUs against main, `test_tool_process_groups.py` has 2 passed and 1 skipped here. Main does not have the file, so the 2 passing static-wrapper cases are new tests. The embedder test is the one that skips. The examples, including the simple training loop, were not run. The export examples need TRT-LLM and the AVLM example downloads Hugging Face models. In the integration run (main 77391e71cc with all #6307 PRs and the main-based gap fixes merged, on the full unit-test suite), this PR's test file shows no regressions against main. On that tree, 22 end-to-end smokes on 4 GPUs, the text generation server among them, match main. Earlier smokes with the #6307 changes applied found three bugs already on main, which #8694 fixes. On 4 GPUs, an earlier version of this PR stacked on an earlier #6303 head showed the two static-wrapper cases failing on its base and passing with the change. Before the sync, this branch ran the new file on 4 CPU ranks with Gloo: 2 passed, and the embedder test skipped.

**Compatibility.** On the standard grid the groups and ranks are unchanged, so the examples and tools behave as before.
- `get_blocks_by_rank` (tools only) now requires `process_group=` as a keyword argument. Its only caller in the repository, the embedder, passes it.
- The examples' `model_provider` functions take the collection as an argument.
- For the static engine, core still resolves the wrapper's `pp_group` from the global grid (`StaticInferenceContext` builds a default `InferenceConfig`). There the performance tool stops reading the predicates itself, but its behavior does not change.
- `megatron/core/QuickStart.md` walks through the simple training loop and falls further behind it here. #7991 updates it.

Not covered here:
- The ModelOpt, multimodal and MIMO training examples move in #8761.
- The examples still build their collection with `use_mpu_process_groups()` right after initialization. #8767 takes the collection that `initialize_model_parallel()` returns instead.
- #8775 builds the BERT embedder's model on the run's groups.

Landing:
- #6303 adds a `ProcessGroupCollection` import and a `pg_collection=ProcessGroupCollection.use_mpu_process_groups()` argument to `GPTModel(...)` in `run_simple_mcore_train_loop.py` and both TRT-LLM export examples. It conflicts with this PR there. Whichever lands second keeps one import and passes `pg_collection=pg_collection`.
- #8694 conflicts with this PR in `tools/run_inference_performance_test.py`, next to the `pp_group` lines. Whichever lands second keeps #8694's fixes and this PR's `pp_group` lines.
- #8059 passes the model's collection to the TRT-LLM distributed converter from the same export example. Its edit to `gpt_distributed_gpu_export.py` merges cleanly with this one.
- #8819 (based on main) moves the simple training loop's body into `train_step()`, builds the optimizer with `get_optimizer()` and adds `tests/unit_tests/test_run_simple_mcore_train_loop.py`. It conflicts with this PR in the `__main__` loop. Whichever lands second also passes `pg_collection` through `get_optimizer()` and `train_step()`, whose hunks merge without a conflict, and updates the new test to pass the collection. #8819's description lists the edits.
