## Pull request overview

This PR adds packed `thd` (sequence packing) input support to the Megatron Core `BertModel`, enabling packed-sequence execution paths (no explicit attention mask, packed-aware position ids, and packed-aware RoPE length/params). It also adds a unit test to validate that packed inputs bypass attention-mask expansion and use packed position ids / RoPE invocation.

**Changes:**
- Add `packed_seq_params` plumbing to `BertModel.forward()` and route packed runs to skip extended attention mask creation.
- Generate packed position ids from `cu_seqlens_q` when `packed_seq_params` is provided.
- Add a unit test that asserts packed forward uses packed position ids and does not build an extended attention mask.

Nice change — the packed `thd` position-id logic and validation are correct, and the new tests cover the validation paths well.

One non-blocking edge case: in `BertModel.forward`, the `return_embeddings` post-process branch computes:

```python
masks = torch.sum(attention_mask, dim=1)
```

When `packed_seq_params` is provided, `attention_mask` is `None`, so this would raise a `TypeError` if a caller ever combined packed input with `return_embeddings=True` and `post_process=True`. It's an unusual flag combination (and the added tests use `post_process=False`), so it may be out of scope — but worth a guard or an explicit 'unsupported' error to fail clearly rather than deep in the sum.

`bert_position_ids()` uses `assert` for user/input validation and assumes `cu_seqlens_q` is well-formed and matches `token_ids.size(1)`. - guihong-nv · comment · 2026-07-23T20:57:21Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/5540#discussion_r3641345355)

File: `megatron/core/models/bert/bert_model.py` · line None

The position-ID construction assumes `cu_seqlens_q` indexes the local physical token buffer. That is not true for two supported THD layouts: when `cu_seqlens_q_padded` is present, the physical buffer ends at its final value, and under context parallelism tokens are sharded while cumulative lengths remain global. In either case this check rejects valid inputs before attention. Please build position IDs from the physical padded boundaries and partition them consistently with the tokens, or accept precomputed position IDs. A test should cover alignment padding and context parallelism greater than one.

- guihong-nv · comment · 2026-10-02T16:26:25Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/5540#discussion_r4167682518)

File: `megatron/core/models/bert/bert_model.py` · line 304

I think the position ids here can go out of range for the position embedding table. Positions are counted from the start of each padded segment, and that includes the trailing padding at the end of the buffer. BERT defaults to learned_absolute, so the table only has max_sequence_length rows. Say the buffer is 4096 tokens, the last sequence ends at 3000, and max_sequence_length is 512. The trailing padding then gets positions 0 to 1095, and the embedding lookup fails on GPU with an index error. The same thing can happen if alignment padding makes a padded sequence longer than max_sequence_length.

Since padding tokens are masked out anyway, the easiest fix is probably to just clamp them, something like `positions.clamp_(max=self.max_sequence_length - 1)` before the unsqueeze. Setting padding positions to 0 based on the cu_seqlens_q lengths would work too.

Could you also make the gap in `test_packed_forward_handles_trailing_buffer_padding` bigger than max_sequence_length? Right now it's just one token, so the test can't catch this.
