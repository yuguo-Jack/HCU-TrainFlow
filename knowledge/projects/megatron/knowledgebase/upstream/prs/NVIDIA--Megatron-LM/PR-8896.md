# Use the model's process groups in inference, its entry points and tools

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8896) · state: open · merged: False

## Original PR description

This PR makes inference, the inference entry points and the standalone examples and tools use the process groups of the model or inference config instead of the global grid. Callers that run inference on their own grid get correct padding, seeds and ranks. Callers that pass a partial collection get an error instead of silent world groups. It consolidates 4 draft PRs unchanged, one commit per member, so please review commit by commit. A final commit regenerates `tools/process_group_usage_allowlist.json`. It depends on no other unit or open PR. It conflicts with three open PRs: #6303 in the simple training loop and both TRT-LLM export examples, #8694 in `tools/run_inference_performance_test.py`, and #8819 in the simple training loop. Whichever PR lands second resolves the conflict, and #8746 lists the edits.

Part of #6307.

## Members

- #8029: Inference contexts: pad to the context's TP size and accept a collection. `DynamicInferenceContext` pads steps and sizes MoE buffers with its own TP size instead of the global one, and `StaticInferenceContext` takes an optional keyword-only `pg_collection` that `StaticInferenceEngine` passes to its internal dynamic context.
- #8054: Use and validate the inference process groups instead of the global grid. The inference wrapper and controller use the groups of `InferenceConfig.pg_collection` and raise `ValueError` when `tp`, `pp` or (for the seed offset) `dp` is missing; `run_mcore_engine` and the direct-mode EP check in `MegatronLLM` stop reading the global grid.
- #8728: Bind args to the ModelOpt builder in the inference entry points. With `--modelopt-enabled`, `get_model_for_inference()` and `tools/run_text_generation_server.py` failed with a `TypeError` since #5169; both now bind `args` to the builder with `functools.partial`.
- #8746: Pass process groups explicitly in the standalone examples and tools. The simple training loop, the TRT-LLM export examples, the MIMO AVLM inference example, the text generation server, the inference performance test and the BERT embedder take their groups from the model's collection instead of the global grid.

## Behavior changes for callers

- On the standard grid, groups, ranks and padding are unchanged.
- A collection without `tp` or `pp` passed to the inference wrapper raises `ValueError`. So does one without `dp` passed to the controller when the seed offset needs it. Before, these fields fell back to the world group.
- `StaticInferenceContext` accepts a new keyword-only argument, `pg_collection`.
- `get_blocks_by_rank` in `tools/bert_embedding/embed.py` requires `process_group=` as a keyword argument. Its only caller in the repository passes it.
- The examples' `model_provider` functions take the collection as an argument.
- ModelOpt inference through `get_model_for_inference()` and the text generation server works again with `--modelopt-enabled`.
