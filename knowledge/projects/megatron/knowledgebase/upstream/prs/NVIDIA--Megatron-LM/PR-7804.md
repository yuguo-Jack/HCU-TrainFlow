# test(optimizer): cover mixed-dtype checkpoint state and FP32 mHC

# What does this PR do?

Add distributed optimizer regression coverage for mixed FP32/BF16 parameter groups, including real mHC parameters retained in FP32 through `mark_keep_in_fp32`.

The production index correction is already on main through #7336. This PR adds only unit tests that exercise the real DDP and distributed optimizer construction paths, ordinary and precision-aware Adam, serialized DP-zero checkpoint restore, and the next optimizer update.

### Regression covered

For a group encountered in BF16-first buffer order, the actual optimizer stores native FP32 shards before BF16-derived shards. Before the correction, looking up a BF16 parameter could return the FP32 parameter's tensors. Different sizes expose a shape mismatch; equal sizes can associate the wrong parameter and Adam state. These tests first compare each lookup directly with its model shard, independently of the checkpoint round trip.

### Coverage

- Both mixed-dtype registration orders and homogeneous controls, in ordinary and precision-aware Adam modes: eight cases.
- A real small mHC `HybridModel` with production FP32 markers, `Float16Module`, DDP, and both Adam modes: two cases.
- Explicit dtype, BF16-first buffer-order, and mixed-group checks in the mHC cases.
- Controlled gradients, with no mocks, model forward/backward, or training loop.
- Exact checkpoint restore and next-update comparisons.
- `launch_on_gb200` on both functions, selecting all ten cases in the existing GB200 unit-test suite.

## Validation

- All ten cases pass on both local RTX 6000 Ada GPU ranks against main `b597bd1faf`, using `nvcr.io/nvidian/nemo:26.08.rc9`.
- The unchanged tests also passed against #7336 before it merged. Historical before-fix runs failed both mHC cases on both ranks with wrong-shard shapes.
- Current GB200 execution remains for CI; no local GB200 result is claimed.
