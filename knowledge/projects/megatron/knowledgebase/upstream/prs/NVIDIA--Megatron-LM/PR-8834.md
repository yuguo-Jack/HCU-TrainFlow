# Avoid owner reference cycles in hybrid optimizer hooks

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8834) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Release obsolete `HybridDeviceOptimizer` instances, CPU parameter copies and GPU master copies without waiting for cyclic GC by making sub-optimizer copy-back hooks hold a weak reference to their owner.

## Issue tracking

Related to #7232 and #7233. This fixes a separate lifetime problem and does not duplicate #7233's deferred sub-optimizer initialization.

## Details

The existing hooks capture `self`, creating an ownership cycle:

```text
HybridDeviceOptimizer -> sub-optimizer -> step post-hook -> HybridDeviceOptimizer
```

When an optimizer is replaced or discarded, its CPU copies and GPU FP32 masters remain reachable through that cycle until cyclic GC runs. This also occurs outside the temporary optimizer created by `DistributedOptimizer`.

Both copy-back hooks now resolve a weak owner reference at invocation time. While the owner is alive, the same copies and stream/event ordering run. If a caller retains a child optimizer after discarding its owner, the callback returns without copying into the model.

There is no global `gc.collect()` call or change to optimizer initialization/partitioning.

### Measured lifetime behavior

A bounded H200 reproducer creates an HDO with a 256 MiB CPU FP32 parameter copy, disables cyclic GC, and drops the HDO reference:

| Observation after dropping HDO, GC disabled | Upstream baseline | This change |
| --- | --- | --- |
| HDO weak reference still resolves | yes | no |
| CPU-copy weak reference still resolves | yes | no |

Explicit GC releases the baseline objects. Host RSS stays roughly constant in both cases, consistent with the pinned-memory allocator caching released blocks. This PR claims timely object/storage lifetime release, not memory returned to the OS or a measured RSS reduction.

The complementary #7233 avoids the first unsharded HDO materialization in the distributed optimizer. This PR removes cycles for each HDO instance, including ordinary teardown and GPU master copies. The extended factory regression checks stale instances only when they are actually materialized; it does not require two initializations.

## Validation

Python 3.12, PyTorch 2.14.1+cu132, Transformer Engine 2.20.2+6ea2a74, 2 H200 GPUs:

```bash
CUDA_VISIBLE_DEVICES=0,1 python -m torch.distributed.run \
  --master-addr=127.0.0.1 --master-port=29803 --nproc-per-node=2 \
  -m pytest -q tests/unit_tests/test_optimizer_cpu_offloading.py
# 84 passed per rank
```

- Existing full-file optimizer math/offload regressions passed.
- New lifetime tests perform actual Adam steps and check offload fractions 0, 0.5 and 1 with overlap enabled/disabled and cyclic GC disabled.
- Existing distributed optimizer regression also checks any discarded HDO instances and CPU copies are gone before the live optimizer performs an update.
- Retaining a CPU or GPU child optimizer after owner release does not retain the parent or copy into its model.
- Running the new regression assertions against pristine upstream production code gives 9 expected failures per rank, demonstrating they detect the original cycle.
- `tools/autoformat.sh` black/isort/pylint/ruff gates passed. Advisory mypy reports missing import stubs in the isolated lint environment; a clean type-check result is not claimed.

No full-model, 32-node, or checkpoint-resume run was performed on this upstream revision.
