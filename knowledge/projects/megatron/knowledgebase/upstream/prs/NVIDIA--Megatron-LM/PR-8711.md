# What does this PR do?

Integrates first-class HybridModel config lists with standard training, checkpoint handling, runtime metrics, and the Puzzle example. Core support from #7555 is now merged into `main`.

## Umbrella scope: PRs 3–6

The branch incorporates upstream `main` at `1ac85e91a`, including the #7555 merge (`bc9a10e90`). The merged core parser, `HybridLayerEntry` API, cloning, MTP, rotary, pipeline, and validation behavior are preserved. Core support is already in `main`; this umbrella retains all remaining training, metrics, checkpoint, and example changes.

This replaces #7153 as the umbrella for **all remaining unmerged work (planned PRs 3, 4, 5, and 6)**. #7153 was closed by copy-pr-bot when its `pull-request/7555` base was deleted after #7555 merged. This replacement targets **`main` directly** and must remain the complete umbrella while the smaller PRs are reviewed and merged.

The fork branch is `philip/hybrid-config-lists-umbrella`, originally created from `42eeb4b4cf531c16f44a07d45633f6dff0197e84`. It now also includes the shared config-list metadata follow-up from PR 3 (#8715). #7153 and its branch remain unchanged.

The remaining changes are:

- **PR 3 — Training integration:** model configuration/builder forwarding, inferred MTP runtime state, family detection, VPP handling, and config-list run-config metadata serialization.
- **PR 4 — Runtime metrics:** heterogeneous FLOPs and list-aware MoE reporting.
- **PR 5 — Checkpoint compatibility:** family checks and list-defined resume using the supplied Python definition.
- **PR 6 — Puzzle example:** the Python architecture, README, launcher, and Slurm script.

Included implementation:

- Training/configuration-builder support that forwards the original config list and synchronizes inferred MTP depth.
- Model-owned heterogeneous FLOP reporting and list-derived MoE metadata, preserving current hash-router and scheduled-microbatch reporting conventions.
- Scalar checkpoint-family detection and compatibility checks. Architecture objects stay off argparse; the ordered config list, layer fields, and split markers are saved as run-config metadata. Resume still uses the supplied Python definition.
- The full-size Puzzle example under `examples/hybrid/puzzle`, updated for the current run-config initialization lifecycle.
- Focused builder regressions cover unchanged list forwarding, inferred MTP depth, and preserving config-list metadata through dict/YAML saving and checkpoint metadata reading.

There is no Puzzle functional-test recipe, optimizer workaround, or dependency upgrade in this PR.

## Puzzle pretrained-weight smoke test

At commit [`cc0e970ffa8f7979e3c830335472293b467bd8aa`](https://github.com/NVIDIA/Megatron-LM/commit/cc0e970ffa8f7979e3c830335472293b467bd8aa), a separate validation harness loaded the local `NVIDIA-Nemotron-Labs-3-Puzzle-75B-A9B-BF16` Hugging Face checkpoint and completed **20 optimizer steps plus one evaluation batch on all 16 ranks**. SLURM job `7205385` completed with exit `0:0` in 18m36s. This result is specific to the tested commit.

- **Environment:** four GB200 nodes with four B200 GPUs each, verified within one NVLink domain; ARM64 image `gitlab-master.nvidia.com/adlr/megatron-lm/mcore_ci_dev:main`. The runtime used this tag; its manifest digest was not independently verified.
- **Configuration:** full decoder and MTP head; TP1/PP1/CP1/EP16/ETP1; sequence length 2048; microbatch 1; global batch 32; BF16; HybridEP; full uniform recomputation; precision-aware Adam; deterministic mock data (seed 1234), checkpoint tokenizer, and fresh optimizer state.
- **Weight loading:** the validation-only post-wrap importer required complete source/target coverage, matching shapes, and exact copied values. It covered all 42,683 source tensors and preserved all 41 FP32 router biases per rank. The PR's tracked files were unchanged.
- **Checks:** 20 focused importer tests and the existing tiny Puzzle forward/backward test passed. Every rank completed training and evaluation with finite LM/MTP losses and gradients, zero skipped optimizer iterations, and verified changes in sampled embedding and MTP projection parameters.

**Qualification:** the large-gradient check detected one finite local bucket norm of 620.0 on rank 13. The step replay produced 16.125, and training continued through the optimizer update without a skipped iteration. The cause remains unresolved. The accumulated MTP metric for that replayed step includes both passes; the first/final loss values above are unaffected.

This smoke test validates pretrained-weight loading and training execution. Convergence, checkpoint save/resume, and full Hugging Face numerical equivalence were outside its scope; the separate checkpoint-resume validation above remains applicable to its stated commit.
