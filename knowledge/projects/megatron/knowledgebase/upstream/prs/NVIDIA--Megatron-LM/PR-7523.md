# Guard blockwise FP8 backward (E5M2) wgrad against all-zero gradient blocks

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7523) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
Guard the blockwise FP8 recipe's backward (E5M2) weight-gradient quantization against all-zero gradient blocks, where `amax = 0` gives an infinite scale and NaN gradients.

Split out of #7054 as discussed there: a small `fp8_utils.py` fix that is independent of the GLM-5.3-Flash model work. Sibling PRs: #7521 (mHC precision controls) and #7522 (KPool DSA indexer); #7054 now carries only the KDA layers.

## Changes

`Float8BlockScaling` is now constructed with an explicit `fp8_quant_bwd_grad=QParams(power_2_scale=<recipe default>, amax_epsilon=1e-12)`. `amax_epsilon` floors the per-block amax, so a gradient block that is entirely zero gets a finite scale instead of `inf`; blocks with a non-zero amax are unaffected, and the forward quantization parameters are unchanged. `power_2_scale` is read from the recipe class default so the guard follows Transformer Engine's setting.

## Motivation

With `fp8_recipe=blockwise`, a weight-gradient block that is entirely zero has `amax = 0`, so its E5M2 scale becomes `inf` and the quantized gradient turns into NaN, which then poisons the whole weight gradient. This came up in the GLM-5.3-Flash FP8 work in #7054 but is not specific to it.

## Testing

No unit test added: the change is a recipe parameter and only affects blocks whose gradient amax is exactly zero (previously NaN).
