# Handle unset eval-interval when sizing validation data

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8629) · state: closed · merged: True

# What does this PR do?

Fix the `TypeError` raised before the first training iteration when `--eval-interval` is not set, by treating an unset `eval_interval` as "no evaluation during training" when sizing validation data.

Since `core_v0.16.0`, `ValidationConfig.eval_interval` defaults to `None`. The training loop already handles that (`if cfg.validation.eval_interval and ...`), but two places still divided by it:

- `get_train_valid_test_num_samples()`: without `--full-validation` or `--skip-train`, it computed `train_iters // eval_interval + 1`. With an unset `eval_interval`, validation only runs once, after training, so this now uses a single eval point. With `--eval-iters 0` this yields 0 validation samples, so train-only setups work again.
- `build_train_valid_test_data_loaders()`: when resuming iteration-based training, it estimated `consumed_valid_samples` from `iteration // eval_interval`. With an unset `eval_interval` no validation runs during training, so the estimate is skipped and stays 0.

Behavior with `eval_interval` set is unchanged.
