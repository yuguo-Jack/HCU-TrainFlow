# Move portable unit-test coverage to four-GPU GB200 runners

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8791) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Move audited portable unit tests from the congested H100 pool to existing four-GPU GB200 runners. For the latest dev suite, remove 11 complete H100 buckets before runner allocation and route selected cases from mixed buckets exclusively to GB200. Retain eight-rank, fixed-golden, and hardware-specific coverage on H100.

Add 18 GB200 buckets to preserve parallel execution, including two-process coordinator launches inside four-GPU allocations. Keep existing GB200 MoE tests in their blocking-NCCL catchall; only top-level transformer tests use the nonblocking-NCCL workaround needed by context-parallel graph tests. Six FP32 mHC cases and seven grouped-tensor NCCL-EP cases remain on H100. Existing assertions and tolerances are unchanged.

Preserve H100 fallback when GB200 placement is disabled, LTS/legacy and GitLab schedules, functional-test gates, and native Testmon placement/cache compatibility. Load host-side placement metadata without importing the GPU-test package.

Drain outstanding GTP communication before resetting graph-test fixture streams, with an unconsumed-prefetch capture regression. Preserve retained tensor-subclass handling around upstream's schedule-input lifetime fix: generic `record_stream` dispatch can materialize unrelated storage or reject nonuniform grouped tensors. The upstream merge retains both new dense-input cross-stream backward regression cases.

## Timing evidence

The 11 complete migrated buckets account for approximately 100 historical H100 runner-minutes per merge across six sampled successful merge-group runs. Mixed-bucket call times are not runner-savings estimates.

The current run occupied **452.7 H100 and 383.7 GB200 runner-minutes**, including runner setup, tests, and teardown, and excluding allocation wait. The 18 additional GB200 buckets account for 275.2 of those GB200 minutes; the 11 complete migrations account for 130.8.

All unit results were ready **19h 34m 06s after workflow creation**. From the first unit-job start to the last unit-job completion, the span was **5h 26m 20s**, including allocation gaps. The elapsed time includes substantial admission and H100-runner waits.

These measurements are not a matched before/after comparison: the earlier AWS H100 run included a failed engine execution and retry, while this run used GCP H100 runners. They do not establish the proposed 305-minute reduction.
