# Add TE BatchedLinear for DSv4 grouped output projection

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7971) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Main-targeted counterpart of #5722 (dev). Use TE's `transformer_engine.pytorch.ops.BatchedLinear` for `DSv4HybridAttention.linear_o_group_proj`, which
1. supports MXFP8 and BF16, and
2. removes the `.contiguous()` copy after the grouped output projection.

Related to #5795.

### Changes

- `DSv4HybridSelfAttentionSubmodules` gains `linear_o_group_proj`. When it is set, the projection is built as TE `BatchedLinear` (`input_batch_dim=-2`, no bias, fused main-grad accumulation, original-input saving). When TE does not provide `BatchedLinear`, the spec leaves it `None` and the layer falls back to the previous `torch.einsum` path with a warning.
- Checkpoint compatibility: the TE weight is 3D (`[groups, lora_rank, in]`), but plain and distributed checkpoints keep the legacy 2D `linear_o_group_proj` key and layout through a state-dict hook, `_load_from_state_dict`, and a `ShardedTensorFactory` in `sharded_state_dict`.
- `get_dsv4_o_group_proj_spec()` is shared by the GPT DSv4 spec (`get_dsv4_hybrid_module_spec_for_backend`) and HybridModel's static `hybrid_stack_spec` (`csa_layer` and `csa_qk_layernorm_layer`), so GPTModel and HybridModel select the same op.
- Replaces this PR's earlier local `DSv4BatchedLinear` wrapper (flattened 2D parameter) and its determinism-manifest entry. TE's op is now used directly.

### Differences from #5722

Only those required by main:
- uses main's `output_projection_groups` / `output_projection_lora_rank` / `output_projection_local_groups` names;
- main's `hybrid_dsv4_stack_spec` is an alias of the static stack spec, so #5722's change to dev's config-aware factory has no counterpart here;
- test files that exist only on dev (`test_csa_builder_contract_cpu.py`, `test_attention_delay_wgrad.py`, `test_dsv4_hybrid_native_parity.py`) are not touched.

## Dependency and validation

Requires TE with `te.ops.BatchedLinear` (NVIDIA/TransformerEngine#3160, now merged into TE main). Without it, the einsum fallback is used.

Validated on GB200 with TE main `b0219803` (2.22.0.dev0):
- `tests/unit_tests/transformer/experimental_attention_variant/test_dsv4_hybrid_attention.py`: 55 passed (4 GPUs)
- `tests/unit_tests/models/test_experimental_attention_variant_module_specs.py`: 49 passed
- `tests/unit_tests/determinism/kernels/test_manifest.py`: 299 passed

On the dev version (#5722), GPTModel and HybridModel DSv4 MXFP8 training ran cleanly. On a 4×GB200 DSv4 proxy (EP4, SL 4K), `BatchedLinear` was about 4% faster per iteration than the einsum fallback. Those end-to-end runs were not repeated on this main port.

Non-blocking follow-ups for this PR:

- With the default Muon/adaptive-Muon routing on main, the new 3D weight goes to the scalar optimizer (Adam by default), whereas the previous 2D weight uses Muon. Keeping checkpoints 2D doesn't preserve the update algorithm. Please track the intended optimizer behavior and cover it with an actual optimizer-step comparison.
- With primary MXFP8 weights, the TE op doesn't retain the requested high-precision initializer/accessors, so the FP32 master can be initialized from the already-quantized weight. Please track that initialization contract too.

The earlier TE API and output-RoPE test-stub issues are resolved. I found no P0 blocker. The reported GB200 tests don't yet demonstrate Muon routing, fused main-grad lifecycle or optimizer resume; the dev performance result also remains separate from main validation.
