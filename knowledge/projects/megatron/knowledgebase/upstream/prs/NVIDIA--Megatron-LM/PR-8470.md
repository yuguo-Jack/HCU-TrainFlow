# Add extra_layer_kwargs to TransformerBlock forward

# What does this PR do?

Adds an optional `extra_layer_kwargs` argument to `TransformerBlock.forward()` so callers can pass extra Tensor inputs (e.g. a DiT/AdaLN conditioning embedding) to every layer. This is the first slice discussed in #5620.

## Issue tracking

Linked issue: Related to #5620

## Changes

- `TransformerBlock.forward()` takes a keyword-only `extra_layer_kwargs: Optional[Dict[str, Optional[Tensor]]] = None` and forwards it to every layer call.
- The existing local dict that carried `mhc_recompute_manager` is renamed to `mhc_kwargs` so it no longer shadows the new argument. Its behavior is unchanged.
- `checkpointed_forward()` (full activation recompute) passes the extra Tensors as positional checkpoint inputs in a fixed (sorted) key order and rebuilds the kwargs inside the checkpointed function, so their gradients are returned by the checkpoint backward.
- `validate_extra_layer_kwargs()` in `transformer/utils.py` checks that the argument is a dict with `str` keys and `Tensor`/`None` values.

## Contract

- `extra_layer_kwargs=None` (default) keeps the existing behavior.
- Values must be `torch.Tensor` or `None`. Non-Tensor metadata should stay in the config or module attributes.
- The key set should be stable for a given model forward path. Tensor values may change per microbatch.
- Keys must not reuse names of kwargs the block already passes to layers; Python raises `TypeError` on a collision.
- Keys are forwarded to every layer as-is, with no filtering. A layer whose `forward` does not accept a key fails with Python's usual `TypeError`, so a key is never dropped silently. The tests pin this behavior.

Out of scope for this PR (follow-ups): CUDA graph signature/cache-key handling, PP transport of the extra Tensors, and `HybridStack` support.

## Testing

New file `tests/unit_tests/transformer/test_transformer_block_extra_layer_kwargs.py` (16 cases):
- `None` keeps behavior; the Tensor reaches every layer.
- Under full recompute (`uniform` and `block`), outputs and gradients (input, conditioning Tensor and parameters) match the non-recompute run, with both a custom layer and a `TransformerLayer` subclass.
- Key collisions and layers that do not accept the key raise `TypeError`.
- Input validation.
