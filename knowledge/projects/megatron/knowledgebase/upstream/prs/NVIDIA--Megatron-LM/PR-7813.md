# What does this PR do?
@humansand

Expose `--dsa-indexer-topk-tie-break {none,small,large}` for ordinary cuDNN DSA and replace the CPU epsilon tie bias with native cuDNN selection. Omission preserves the existing smaller-index CPU preference and arbitrary CUDA ties.

- **Interface:** `dsa_indexer_topk_tie_break: Optional[Literal["none", "small", "large"]] = None` uses the existing automatic CLI/config plumbing. Explicit `none` permits arbitrary ties, `small` prefers smaller logical key indices, and `large` prefers larger logical key indices. This controls the selected set, not output-slot ordering. Omitted Python `None` is distinct from explicit CLI `none`.
- **Default:** retain the original activation predicate: smaller-index ties only when `topk_k < score_width` and scores are on CPU; arbitrary ties otherwise. No default change to larger-index selection.
- **Implementation:** resolve names to internal kernel modes once in config initialization. Forward the scalar through no-loss, sparse-loss, full fused attention/indexer, score chunks, packed sequences and CP helpers; both autograd backward tuples include the non-differentiable argument. Pass the resolved scalar only to the cuDNN backend. No tensor operation, tensor allocation, host synchronization, device transfer or extra score pass is added by the wiring.
- **Supported scope:** explicit policies require ordinary DSA + `dsa_kernel_backend=cudnn` with fused kernels enabled and `dsa_indexer_kpool=1`. KPool uses a separate selector and rejects explicit policies at configuration time; its unset default is unchanged. Reject unsupported config combinations at initialization, and fail clearly if a runtime layout/loss route reaches reference top-k that cannot honor the policy. Unset configs keep existing fallback behavior. Unfused scoring inside the cuDNN adapter remains supported when selection still uses cuDNN. Standalone reference indexer helpers, TileLang, CSA/MXFP8 and DSv4 selectors are unchanged.
- **Values/layout:** remove epsilon addition/subtraction and preserve original selected scores. Nearby distinct scores are ranked without perturbation. FE radix ordering still distinguishes positive/negative zero; NaN ordering remains unspecified. Existing logical KV ordering, packed offsets, CP communication, attention-slot sorting and indexer precision are unchanged.
- **Dependency / draft gate:** [cuDNN Frontend 1.31.0](https://github.com/NVIDIA/cudnn-frontend/releases/tag/v1.31.0) is the first stable release containing [FE#1332](https://github.com/NVIDIA/cudnn-frontend/pull/1332). Target `dev` at `ff20ed54650dd47ba21989767dfc0068d8c6f73e` pins FE **1.29.0** in both `pyproject.toml` and `uv.lock`. **Keep draft until Megatron advances its consuming dependency to a release containing this API.** The C3 image already contains FE 1.31.0; that validates this patch but does not satisfy the upstream dependency gate. No version checks, compatibility fallback, or dependency-pin change is added.

```bash
--experimental-attention-variant dsa \
--dsa-kernel-backend cudnn \
--dsa-indexer-topk-tie-break large
```

The FE selector benchmark measures tie-scan overhead, not Megatron training performance; omitted/`none` on CUDA retains the no-tie-scan specialization.
