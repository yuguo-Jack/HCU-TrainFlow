# What does this PR do?
@humansand

Expose `--dsa-indexer-topk-tie-break {none,small,large}` for ordinary cuDNN DSA and replace the CPU epsilon tie bias with native cuDNN selection. Omission preserves the existing smaller-index CPU preference and arbitrary CUDA ties.

- **Interface:** `dsa_indexer_topk_tie_break: Optional[Literal["none", "small", "large"]] = None` uses the existing automatic CLI/config plumbing. Explicit `none` permits arbitrary ties, `small` prefers smaller logical key indices, and `large` prefers larger logical key indices. This controls the selected set, not output-slot ordering. Omitted Python `None` is distinct from explicit CLI `none`.
- **Default:** retain the original activation predicate: smaller-index ties only when `topk_k < score_width` and scores are on CPU; arbitrary ties otherwise. No default change to larger-index selection.
- **Implementation:** resolve names to internal kernel modes once in config initialization. Forward the scalar through no-loss, sparse-loss, full fused attention/indexer, score chunks, packed sequences and CP helpers; both autograd backward tuples include the non-differentiable argument. Reuse the existing dispatch kwargs dictionary. No tensor operation, allocation, host synchronization, device transfer or extra score pass is added by the wiring.
- **Supported scope:** explicit policies require ordinary DSA + `dsa_kernel_backend=cudnn` with fused kernels enabled. Reject unsupported config combinations at initialization, and fail clearly if a runtime layout/loss route reaches reference top-k that cannot honor the policy. Unset configs keep existing fallback behavior. Unfused scoring inside the cuDNN adapter remains supported when selection still uses cuDNN. Standalone reference indexer helpers, TileLang, CSA/MXFP8 and DSv4 selectors are unchanged.
- **Values/layout:** remove epsilon addition/subtraction and preserve original selected scores. Nearby distinct scores are ranked without perturbation. FE radix ordering still distinguishes positive/negative zero; NaN ordering remains unspecified. Existing logical KV ordering, packed offsets, CP communication, attention-slot sorting and indexer precision are unchanged.
- **Dependency/performance:** [cuDNN Frontend 1.31.0](https://github.com/NVIDIA/cudnn-frontend/releases/tag/v1.31.0) includes [NVIDIA/cudnn-frontend#1332](https://github.com/NVIDIA/cudnn-frontend/pull/1332). **Keep draft:** Megatron `dev` still locks Frontend 1.28.0 at `b15181d82170c172f2023521638367cc4c01047b`, which lacks this API. Merge only after that consuming dependency advances to a release containing the change. No version checks, compatibility fallback or package-pin change. The FE selector benchmark measures tie-scan overhead, not Megatron training performance; CUDA omitted/`none` retains the no-tie-scan specialization.

```bash
--experimental-attention-variant dsa \
--dsa-kernel-backend cudnn \
--dsa-indexer-topk-tie-break large
```
