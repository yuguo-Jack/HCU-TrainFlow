# Fill SharedExpertMLP checkpoint metadata when the caller passes none

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8818) · state: closed · merged: False

## Original PR description

**Why.** `SharedExpertMLP.sharded_state_dict(metadata=None)` raises `TypeError: 'NoneType' object is not subscriptable` when the shared-expert gate is on.
- The method passes `metadata` to `MLP.sharded_state_dict`. When it is None, MLP fills `dp_cp_group` into a new dict of its own. The caller's variable stays None.
- The `gate_weight` entry then reads `metadata['dp_cp_group']` (line 228) and fails.
- `FusedSharedExpertMLP` inherits the method and fails the same way.
- Callers that hit it: code that calls `sharded_state_dict` on the shared-expert module itself without metadata, such as a unit test. No code in the repo does that today. `MegatronModule.sharded_state_dict` fills the dict before it passes it to its children, so the model's own save path and training checkpoints are not affected.

**What.**
- `megatron/core/transformer/moe/shared_experts.py`: call `ensure_metadata_has_dp_cp_group(metadata)` before `super()`, and use the filled dict for both the MLP children and `gate_weight`.
- The group is the one `MLP.sharded_state_dict` already falls back to for `linear_fc1` and `linear_fc2`. `gate_weight` now gets the same replica id as the rest of the module.
- The fallback read of the global grid moves from `super()` into this method. No read is added.
- No barrier or collective is added. The method only reads the local rank in existing groups.
- Passing the owner's DP x CP group instead needs the two-argument form of the helper from #8044. That can follow once it lands.

**Tests.**
- New `TestSharedExperts::test_sharded_state_dict_without_metadata` in `tests/unit_tests/transformer/moe/test_shared_experts.py`. It builds a gated `SharedExpertMLP` with local linears at TP2 and calls `sharded_state_dict(metadata=None)`. It checks that `gate_weight` is a `ShardedTensor` with replica id `(0, tp_rank, dp_cp_rank)`. It also checks that every entry matches a call that passes the DP x CP group explicitly.
- On 4 CPU ranks with Gloo, the file gives 19 passed and 9 skipped on this branch. Main with only the new test added gives 18 passed, 1 failed (the new test, with the `TypeError` at `shared_experts.py:228`) and the same 9 skipped. The new test also passes on 1 rank.
- GPU runs with NCCL:
  - On 4 GPUs the file gives 25 passed, 2 skipped and 1 failed on this branch, and 24 passed, 2 skipped and 1 failed on main. The extra pass is the new test. The failure on both is `test_shared_expert_forward_backward[2-4-alltoall]`, which needs 8 GPUs.
  - On 8 GPUs (two nodes), with this change merged into the rest of #6307, the whole file passes, `[2-4-alltoall]` and the new test included.
  - `test_modelopt_module_spec.py::TestModelOptMLAMoE::test_sharded_state_dict_restore` and `TestModelOptLlama4MoE::test_sharded_state_dict_restore` pass on 4 GPUs there and on main.
- `tools/check_process_group_usage.py` reports the same 3 pre-existing entries before and after.
- `tools/check_kernel_determinism_coverage.py` passes. `shared_experts.py` is registered with an `exempt_reason`.

**Compatibility.**
- Callers that pass a dict see no change. A dict without `dp_cp_group` gets the same group as before, filled in place.
- Callers that pass `metadata=None` get a state dict instead of a `TypeError`. Without the gate, they get the same state dict as before.
