# Run tools/checkpoint on registered process groups without rank overrides

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8762) · state: closed · merged: False

## Original PR description

Depends on #8740, #8744 (which contains #6303 and #8033) and #8747 (which contains #8039). Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/a287d0d54d...yx/pstate-f4-checkpoint-tools).
- This PR rewrites the converter code that #8744 puts on its own process groups. #8033 adds `initialize_checkpoint_converter_distributed()` and the pipeline-stage test file.
- #8747 adds `parallel_state.register_process_groups()`, and #8039 the `StandardGridExtras` it takes.
- #8740 adds the `pg_collection` arguments of `load_checkpoint()`, `save_checkpoint()` and `get_checkpoint_name()`.
- The merge of #8744 resolves its conflict with #8740 in `tools/checkpoint/loader_base.py` by keeping #8744's per-stage loop, which covers #8740's rank setting. The base merges the three PRs after their update to main in one commit, which also updates the process-group allowlist.

**Why.** After #8744, `tools/checkpoint` still wrote `parallel_state` directly so that code reading the global grid saw the converter's fake groups:
- `install_checkpoint_converter_process_groups()` wrote 17 private `parallel_state` module variables;
- the loader and the saver overrode the global pipeline rank with `set_pipeline_model_parallel_rank()` for every stage;
- `loader_mixtral_hf.py` made seven `_MPU_*` size and rank setter calls and built its model without a collection. It never initialized `torch.distributed`, so `get_pg_size()` and `get_pg_rank()` ignored the fake groups.

#8740 lets `load_checkpoint()` and `save_checkpoint()` take the model's collection, and #8747 adds the public `parallel_state.register_process_groups()`, so none of these writes is needed. Three conversion paths were also broken:
- `convert.py --loader core --model-type GPT` raised `TypeError: model_provider() missing 1 required positional argument: 'model_builder'`;
- a checkpoint with a virtual pipeline failed in `get_transformer_layer_offset()`, because the loader built every chunk with `vp_stage=None`;
- the saver started `torch.distributed` through a TCP store on port 12356, so it failed with `EADDRINUSE` when the port was taken, for example by the saver of another conversion on the same host.

The first and the third also happen on main.

**What.**
- The core loader returns the provider bound to the GPT builder.
- The loader builds each virtual-pipeline chunk with its `vp_stage`. As in training's `get_model()`, only the first chunk of the first stage pre-processes, and only the last chunk of the last stage post-processes. Without a virtual pipeline it builds one model per stage with `vp_stage=None`, as before.
- The saver starts `torch.distributed` with `initialize_checkpoint_converter_distributed()`, as the loader already does. That is Gloo over an in-process `HashStore`, which needs no port.
- `register_checkpoint_converter_process_groups()` replaces the mirror and registers the collection with `parallel_state.register_process_groups()`. Fake groups cannot name their global ranks, so the grid's rank lists stay unset. The GTP-spanning partial data-parallel groups keep the values the mirror gave them.
- `set_checkpoint_converter_model_ranks()` replaces `set_checkpoint_converter_pipeline_rank()`. It sets a model's pipeline, tensor, expert-tensor and expert ranks on the collection only. The global pipeline-rank override is gone.
- The loader and the saver pass the collection to `load_checkpoint()` and `save_checkpoint()` instead of five (loader) or seven (saver) of its groups. Legacy checkpoint files are still named after the selected ranks.
- The saver selects a model's ranks before it builds the model. Before, every model was built with tensor- and expert-parallel rank 0, so with EP=2 the model of expert rank 1 reported holding experts 0 and 1. The legacy format keys experts by their local index, so the saved files do not change.
- The Mixtral HF loader starts `torch.distributed`, builds and registers the collection, and passes it to its model provider through a new optional `pg_collection` argument of `load_checkpoint_to_model()`. Its seven setter calls go.

`tools/checkpoint` now changes `parallel_state` only through `register_process_groups()`. Before this PR it wrote `parallel_state` in 25 places.

**Tests.**
- New `test_checkpoint_converter_initialization.py`: in a fresh process, the saver starts `torch.distributed` while `MASTER_PORT` is taken, and the loader registers the collection it passes to its models.
- New `test_loader_core.py`: the provider that the core loader builds its models with is bound to the GPT builder.
- `test_checkpoint_converter_pipeline_stages.py`: each virtual-pipeline chunk holds its own layers and gets the right pre- and post-processing flags. Every stage test now fails if the converter overrides a global rank or size.
- `test_checkpoint_converter_process_groups.py`: the registered groups form `use_mpu_process_groups()`, the model ranks select one model, and a second registration raises.
- `test_loader_mixtral_hf.py`: the loader builds its model on a collection it registers, with no global grid and no rank overrides.

Each new test fails without its commit's fix. On the stacked version of this PR, a CPU round trip through the real save and load (TP2 PP2, and TP2 PP2 with two virtual stages) restored every parameter exactly, with `FutureWarning`, the class of the fallback warnings, turned into an error. With TP1 PP2 EP2, the saver's models of expert rank 1 now hold experts 2 and 3. Without this PR they held experts 0 and 1.

On 4 GPUs against its base, the five test files pass every test: `test_checkpoint_converter_pipeline_stages.py` 9 here vs 8 on the base, `test_checkpoint_converter_process_groups.py` 7 vs 6, `test_loader_mixtral_hf.py` 14 vs 12, and the new `test_checkpoint_converter_initialization.py` 2 and `test_loader_core.py` 1. That is 33 passed vs 26, with 9 new tests passing and no regressions. In the integration run, this PR's test files show no regressions against main. Before the sync, on the stacked version with all the other process-group changes from #6307 applied, the converter's functional test module passed all 7 GPT conversions at 8 ranks (TP and PP reshards, TE and local specs) with no deprecation or fallback warning.

Before the sync, the branch ran the five test files on 4 CPU ranks with Gloo and `psutil` stubbed: 19 passed, the same per test as on the stacked version, where the base passed 14. The Mixtral test needs `transformers`, which that environment lacks.

**Compatibility.** Saved checkpoints and their file names are unchanged. No `megatron/core` file changes.
- This needs maintainer sign-off: the pipeline-rank override is removed. In a converter process, `parallel_state.get_pipeline_model_parallel_rank()` now raises `ValueError`, because `torch.distributed` cannot report a rank in a fake group. No in-repo code on the conversion path calls it, since every in-repo builder takes the stage from `pp_rank` or `pg_collection.pp`. A model provider or `--loader` plugin outside the repository that reads the global pipeline rank, or calls a core helper without `pp_rank`, gets a fallback warning and then that `ValueError`. Should `set_checkpoint_converter_model_ranks()` keep calling `set_pipeline_model_parallel_rank()` until 0.23 instead?
- Model providers used with `MegatronCheckpointLoaderBase` now receive `vp_stage=`, including `vp_stage=None` without a virtual pipeline. The in-repo GPT, BERT and LLaVA providers accept it. Training's `get_model()` passes it only with a virtual pipeline, so a provider outside the repository that works for training without one can raise `TypeError` here.
- `initialize_checkpoint_converter_fake_process_groups()` keeps its signature and still returns the collection. It now raises `RuntimeError` when process groups are already registered, where main overwrote them silently. No in-repo caller registers twice.
- Needs `determinism-exempt` only while the PRs below this one are unlanded. CI diffs against main, and the base carries registered kernel files. This PR's own diff passes the coverage check.

Related: #8773 runs the converter's functional test on the registered groups.
