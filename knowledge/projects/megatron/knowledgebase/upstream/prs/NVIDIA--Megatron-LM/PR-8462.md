# build: declare optional inference and NVSHMEM dependencies

## What does this PR do?

MCore imports optional backends without publishing their requirements, so downstream projects maintain duplicate dependency lists. Declare the five packages without version constraints: `flash-attn`, `flash-attn-4[cu13]`, and `tilelang` in `inference`; `nvshmem4py-cu13` and `cupy-cuda13x` in a new `nvshmem` extra. Retain Linux markers and regenerate `uv.lock` without changing existing locked package versions.

The dev Dockerfile skips installing FA2 and FA4 so it retains the base image's prebuilt packages. The local uv configuration enables FA4 beta resolution using the existing runtime minimum (`>=4.0.0b20`) and disables isolated FA2 builds because its setup imports PyTorch. The lock also matches the existing dev Dockerfile NVSHMEM runtime (3.7.1), avoiding PyPI Torch's 3.4.5 requirement, which MCore documents as affected by initialization failures. These uv settings are not published dependency constraints. NVSHMEM4Py already brings in the native NVSHMEM runtime transitively.

This PR only publishes dependencies. It does not add backend fixes or test coverage, and the new `nvshmem` extra is not enabled in CI. Downstream projects still own their environment constraints and prerelease policy; the extras do not inherit the NGC image or MCore's lockfile. Fresh FA2/FA4 co-installation remains a separate packaging concern.

Related to #7184. This narrowed PR does not include its FA4 environment fixes.
