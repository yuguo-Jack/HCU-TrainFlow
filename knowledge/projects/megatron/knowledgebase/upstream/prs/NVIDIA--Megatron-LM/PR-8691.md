# What does this PR do?
Fixes silent truncation from the bound being enabled by the local `context.is_decode_only()`. The NVLS dispatcher never syncs decode state across EP ranks so a rank which was decoding while an EP peer was prefilling still bounded its rows.

File: `megatron/core/inference/text_generation_controllers/text_generation_controller.py` · line 941

Add regression coverage for the heterogeneous-EP case this fixes. The existing [active-row policy test](https://github.com/NVIDIA/Megatron-LM/blob/2e35813a38f0f08348184f379205fd1b5a46bcec/tests/unit_tests/inference/test_flashinfer_mxfp8.py#L50-L65) supplies `use_bounded_rows` directly, while the [mixed-EP graph test](https://github.com/NVIDIA/Megatron-LM/blob/2e35813a38f0f08348184f379205fd1b5a46bcec/tests/unit_tests/inference/test_batch_dimension_utils.py#L528-L546) uses token-count synchronization. Neither exercises the capacity-enabled NVLS context-to-controller decision, so reverting this predicate to local decode would leave those assertions unchanged.

Add focused context/controller tests using EP=2, `max_requests=8`, no speculative tokens, capacity 16, eight decode tokens on one rank, and a 32-token prefill on its peer. After `initialize_attention_state()`, assert `is_ep_decode_only()` is false on both ranks, the decoding rank rejects its decode graph, and `_dynamic_step_forward_logits()` disables bounded rows. The gathered real tokens exceed capacity, so the expected behavior is full-row processing—not the truncated prefix that motivated this fix.

Also check the transition back to both ranks decoding: EP decode state and bounded rows should become true, and decode graphs should remain eligible. Preserve prefill/mixed graph eligibility where enabled. Parameterize the controller check for speculative tokens, absent capacity, and capacity below `max_requests * (num_speculative_tokens + 1) * EP`; the latter two must keep bounded rows disabled. Retain the existing row-policy assertions that bounded capacity 1024 selects 1024 of 65536 rows, while unbounded mode selects all 65536.

These are proposed checks, not executed results.
