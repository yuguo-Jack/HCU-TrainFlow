# Support gated shared experts in MOK for Qwen3.5

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7391) · state: closed · merged: True

## Original PR description

## Summary

Enable MCore's MOK backend to support the shared-expert output gate used by Qwen3.5, controlled by the existing `moe_shared_expert_gate` option.

Supports BF16 or MXFP8 routed experts, with BF16 shared experts and output-gate weights.

## Changes

- Reuse the native shared-expert gate parameter without creating duplicate weights or checkpoint entries.
- Pass the gate weight and its main-grad buffer through the MOK autograd bridge.
- Support FP32 and BF16 gate main-grad accumulation while preserving the existing DDP gradient-accumulation hooks.

This PR changes the MCore integration only; gate computation is implemented in MOK.

## Validation

- After merging the latest `dev`, all 47 adapter/config tests passed on each of 4 OCI AGA GB300 ranks, with no failures or skips.
- Earlier validation covered 20 training iterations per configuration on a 35B-shape proxy, across BF16/MXFP8 routed experts and FP32/BF16 main gradients. These E2E runs preceded the latest dev sync.
- Existing dev tests are retained, with 9 additional feature cases.

## Notes

- Gated execution requires a matching MOK version with shared-output-gate support.
- MCore's native shared-expert overlap mode remains unsupported by the MOK backend.
- This change does not modify routed-expert numerical semantics or claim bitwise parity with the Native backend.
