# [dev][kimi-k3] Fix: Align THD and SBHD padding masks and token statistics

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8943) · state: open · merged: False

## Original PR description

Exclude padded rows from the Quantile Balancing histogram updates so the fused and the unfused routing paths see the same statistics: TopKRouter derives qb_valid_mask from the padding mask instead of rejecting padding masks, and accumulate_qb_histogram in moe_utils applies the mask to the fused-path histogram recompute and to the unfused path alike.

Feed the SBHD dataset padding mask into the token statistics as well: pretrain_hybrid.py calls update_seqlen_stats_from_padding_mask on the CP-unsliced [micro_batch_size, seq_length] mask of the first virtual stage, so SBHD validation throughput reporting accounts for real tokens and per-document attention work the same way the packed THD path does.

Tests: test_quantile_balancing.py covers the masked histogram updates on both routing paths; test_num_floating_point_operations.py covers the token statistics derived from the padding mask.

### Keep evaluation samples out of the next training iteration's FLOPs

With `--use-varlen-dataset --varlen-sbhd-validation` and periodic evaluation, this new update also runs during [evaluate's forward steps](https://github.com/NVIDIA/Megatron-LM/blob/3b997d395e680887d027fb6b828c627be042e659/megatron/training/training.py#L7286-L7333). Evaluation never consumes or resets this accumulator. The [next training iteration consumes it](https://github.com/NVIDIA/Megatron-LM/blob/3b997d395e680887d027fb6b828c627be042e659/megatron/training/training.py#L6926-L6953), incorrectly adding evaluation tokens and attention work to training TFLOP/s and cumulative training FLOPs. One evaluation microbatch with real lengths `[5, 3]`, followed by one training microbatch with the same lengths, produces `(16, 68)` instead of `(8, 34)`. SBHD did not populate this accumulator before this change.

**Correction:** Isolate the sequence-statistics state across `evaluate()`, including its early returns and optional non-loss forwards, so evaluation updates cannot reach training's consumer. If evaluation reporting needs these statistics, consume them through an evaluation-specific lifecycle. The exact patch depends on that reporting choice; simply gating on `torch.is_grad_enabled()` is insufficient because frozen reference runs intentionally train under no-grad.

**Preserve and check:** Add a proposed integration regression that runs evaluation, then one training microbatch with lengths `[5, 3]`; training consumption must return `(8, 34)`. Repeat with multiple evaluation steps and an early return. Retain ordinary and frozen-reference training accounting, the CP-unsliced mask, first-virtual-stage counting, the existing `None` no-op, and full-length/packed-sequence cases. I did not execute these checks.

### Reactivate sequence statistics on every full-iteration graph replay

This delegates to a helper that sets `_seqlen_stats_active = True` in Python. Under `--cuda-graph-impl full_iteration`, the new SBHD producer runs inside the captured forward/backward call. [Subsequent iterations replay CUDA work without calling Python](https://github.com/NVIDIA/Megatron-LM/blob/3b997d395e680887d027fb6b828c627be042e659/megatron/core/full_cuda_graph.py#L364-L377), while [consume resets the Python flag to False](https://github.com/NVIDIA/Megatron-LM/blob/3b997d395e680887d027fb6b828c627be042e659/megatron/training/training.py#L866-L891). After the first captured iteration is consumed, later replays update the tensor but consumption returns `(None, None)`. FLOPs then revert to counting the padded allocation, and the tensor is no longer drained. For two length-eight samples with real lengths `[5, 3]`, each iteration should report `(8, 34)`, not fall back to `(16, 128)`.

**Correction:** Integrate this producer with the eager per-iteration lifecycle in `FullCudaGraphWrapper.__call__` and the statistics API: every replay that writes SBHD statistics must activate their consumer before it runs, and consumption must drain that replay exactly once. Alternatively, collect the unsliced mask statistics outside capture. The storage/capture ownership choice needs an explicit implementation; setting the flag once during capture cannot work.

**Preserve and check:** Add a proposed GPU regression with one warmup iteration, capture, and at least two later replays using the same padded mask. Require `(8, 34)` after every iteration and zero accumulator contents after consumption. Retain eager accounting, changing mask values between iterations, the first-virtual-stage gate, and the no-mask path's `(None, None)` result without an extra collective. No tests were executed.

### Discard statistics from superseded training attempts

The first-virtual-stage gate prevents duplicate counting across model chunks, but not across retries. [train_step reruns the whole forward/backward body](https://github.com/NVIDIA/Megatron-LM/blob/3b997d395e680887d027fb6b828c627be042e659/megatron/training/training.py#L4718-L4875), so every attempt executes this additive update again. The [rerun callbacks save and restore only RNG tracker state](https://github.com/NVIDIA/Megatron-LM/blob/3b997d395e680887d027fb6b828c627be042e659/megatron/training/initialize.py#L124-L142), not sequence statistics. A nonfatal spiky-loss retry that continues training therefore counts the same SBHD batch twice. A single microbatch with real lengths `[5, 3]`, executed twice for one logical iteration, leaves `(16, 68)` instead of `(8, 34)`.

**Correction:** Make SBHD sequence statistics attempt-scoped in `train_step`: reset or restore the accumulator before each forward/backward attempt so a retry replaces, rather than adds to, the superseded attempt. Reset at the attempt boundary, not inside this per-microbatch update. Coordinate this with the graph-replay activation fix; an eager reset must not leave captured producers inactive. The exact placement depends on the chosen accumulator lifecycle.

**Preserve and check:** Add a proposed regression with two attempts for one logical iteration and expect `(8, 34)` at the training consumer. In a separate case, execute two distinct microbatches in one successful attempt and retain `(16, 68)`. Preserve ordinary one-attempt runs, frozen-reference runs, packed-statistics seeding, CP-unsliced lengths and virtual-stage deduplication. These checks are based on source reasoning and were not executed.
