# Pass the owner's collection to FP8/FP4 quantization contexts

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8035) · state: closed · merged: False

## Original PR description

**Depends on #8034**, which adds `amax_reduction_group` and the `pg_collection` keyword. Until it merges, please review the four commits after #8034's, one per owner, in [the comparison with #8034's branch](https://github.com/NVIDIA/Megatron-LM/compare/Connor-XY:yx/pstate-b2-amax-group...Connor-XY:yx/pstate-b2-amax-callers). Both branches merged main, so that comparison's file view also shows #8034's changes.

**Why.** These components hold their model's collection, but their FP8/FP4 autocasts still reduce amaxes over the global group, or over WORLD when there is no global grid:
- transformer blocks and layers, MTP, recompute;
- HybridStack;
- CUDA graph runners;
- the multimodal projector and the TE wrappers.

On 4 GPUs, a layer whose own TP×DP×CP ranks are [0, 2] reduces over [0, 1] on main.

**What.** Each owner passes `pg_collection=`:
- TE wrappers, the LM head and the projector. `TELinear` gains an optional `pg_collection`.
- Block, layer, recompute and MTP. `MultiTokenPredictionBlock` and `T5Model` add `tp_cp` and `tp_dp_cp` to their default collections.
- HybridStack. `MambaLayer` keeps its collection.
- The CUDA graph runner. `TECudaGraphHelper` uses `amax_reduction_group`, which removes a dead branch that read a nonexistent `tp_dp` field.

**Tests.**
- Per-owner tests record the group of each autocast, with the global accessor patched to raise. They fail on main.
- In the integration run (all #6307 PRs merged onto main 77391e71cc, against main), the four new per-owner test files pass on 4 GPUs: `test_te_amax_reduction_group.py` (7 tests), `test_quantization_context_amax_group.py` (12), `test_hybrid_stack_amax_group.py` (3) and `test_cuda_graph_amax_group.py` (2). #8034's `test_amax_reduction_group.py`, which this branch carries, passes 23 tests there, one of them added by another #6307 PR.
- In the integration run, this PR's test files show no regressions against main. The touched existing files pass 14 tests vs 5 on main (`test_schedule_quantization_context.py`), 5 vs 4 (`test_multimodal_projector.py`) and 67 vs 67 (`test_hybrid_block.py`) on 4 GPUs, and 31 vs 13 (`test_t5_model.py`) on 8 GPUs (two nodes). The extra passes include other #6307 PRs' new tests.
- Before the 2026-11-01 sync, FP8/FP4 training (delayed, tensorwise, MXFP8, NVFP4, TE CUDA graphs) gave the same results as main.
- Before the sync, the FP8, hybrid and TE regression sets gave the same results as main.

**Compatibility.** On the standard grid the collection holds the same group objects, so numerics are unchanged. A caller-built collection without `tp_dp_cp` (or without `tp_cp` when `tp_only_amax_red` is set) now raises `ValueError` under FP8/FP4. Needs `determinism-exempt`.

Synced with main 77391e71cc on 2026-11-01 by a merge commit, so existing commits and review links stay valid. The merge had no conflicts; its message lists the test and allowlist updates main required.
