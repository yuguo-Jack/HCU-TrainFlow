# Read only the caller's process groups in finalize_model_grads

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8027) · state: closed · merged: False

## Original PR description

**Why.** With an explicit `pg_collection`, `finalize_model_grads` still falls back to the global grid or to WORLD:
- `assert hasattr(...)` never fails, because an unset collection field reads as `None`. The `None` then reaches a global lookup or a `group=None` collective.
- `embd=None` (a rank outside the embedding group) looks up the global embedding group, and the conditional-embedder and router reductions use the global PP group.
- Without a DP×CP group, `num_tokens` and the micro-batch quantile-balancing bias are reduced over WORLD. On TP=2 × PP=2 every per-token-loss gradient comes out 4× too small; with several grids in one job the collective hangs. Global-batch quantile balancing with GTP-remat skips the data-parallel histogram reduction instead, so DP replicas update their router biases differently.

**What.**
- With a collection, only its groups are used:
  - `tp` and `pp` are required;
  - `embd` is required when PP > 1 (`None` on ranks outside the embedding group);
  - `dp_cp_gtp_remat` or `dp_cp` is required for `num_tokens`, micro-batch quantile balancing, and global-batch quantile balancing with GTP-remat;
  - `tp_dp_cp` is required for the expert bias and for global-batch quantile balancing without GTP-remat.
- A missing group raises `ValueError` before any communication.
- The private helpers take their groups as required arguments.
- Delete the `_ParamAndGradBuffer` fallback, which called the nonexistent `parallel_state.get_data_and_context_parallel_group`.

**Tests.** In `test_finalize_model_grads.py` on 4 GPUs: global accessors and WORLD collectives forbidden, a global grid with a different PP layout, each missing group (including both global-batch quantile-balancing cases), `num_tokens` without a DP×CP group, global-batch quantile balancing pooled over the collection's `tp_dp_cp`, and the omitted-collection path. The new tests fail on main and pass here; the DDP and buffer tests are unchanged. In the integration run (main 77391e71cc with all #6307 PRs merged, against main), `test_finalize_model_grads.py` passes 30 tests on 4 GPUs vs 12 on main and fails none, so this PR's test file shows no regressions against main.

**Compatibility.** Without a collection, behavior is unchanged. Collections from `use_mpu_process_groups()`, the schedules, Megatron-Bridge and the MIMO example already set these fields. A missing `tp_dp_cp` now raises `ValueError` instead of `AssertionError`. Needs `determinism-exempt`: no numeric change.
