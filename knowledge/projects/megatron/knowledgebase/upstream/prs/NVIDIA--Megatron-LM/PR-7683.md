# build: update Transformer Engine to release 2.20 tip

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7683) · state: closed · merged: True

## Original PR description

## What does this PR do?

Pin Transformer Engine to [`131157b5750b8578cb8efb78554f6fe6a671cc53`](https://github.com/NVIDIA/TransformerEngine/commit/131157b5750b8578cb8efb78554f6fe6a671cc53), the tip of `release_v2.20` as of September 28, 2026, with dependency metadata `2.20.0+131157b5`.

Raise the cuDNN Frontend dev/build requirement to 1.29.0 and regenerate `uv.lock` in the CI dev container, including the CUTLASS DSL package family at 4.8.0. Constrain Quack to >=0.6.5 and lock 0.6.5: the previous 0.4.1 release imports `cute.core.ThrMma`, which CUTLASS removed in 4.6. The corrected version passes imports and retains the helpers used by pinned Mamba.

Refresh numerical references for 25 configurations. The original 23 reproduce exactly at full precision across independent GPU executions and pass focused GPU reruns. Two additional GB200 one-node GPT cases update only loss and gradient-zero references from GitHub run `36544862435`: three independent executions per case match exactly, existing approximate checks pass, and unchanged exact-comparator replay passes all six executions. Both cases now pass all five fresh GPU repetitions at the current head, with no skipped or NaN iterations. Their timing/memory values, recipes, and tolerances are unchanged. The FSDP case updates loss only. The file-wide precision validator also requires regenerating 48 legacy timing/memory objects across 16 edited files from the same actual artifacts; those recipes assert loss and zero counts only. Dedicated performance-test references are unchanged.

Preserve NCCL EP expert token order in deterministic mode. TE 2.20 enables a count-exchange path that assigns expert slots using atomic counters, changing expert weight-gradient reduction order between reference and overlap schedules. Set the supported `NCCL_EP_HT_EM_AG_SCAN_MODE=1` before group creation through the existing training determinism policy and A2A test context. Normal non-deterministic execution is unchanged; assertions, tolerances, and test selection are preserved.

## Metrics: before and after

**Numerical results are nearly unchanged; a controlled GB200 GPT comparison shows a slowdown.**

| Metric | Before → after | Assessment |
| --- | --- | --- |
| Loss | Absolute mean relative changes below **0.0005%** for 24/25 configurations; T5 loss **0.0247% lower** | Tiny differences in short CI runs; no demonstrated model-quality improvement |
| Gradient-zero counts | Mixed changes, up to **1.40%** | Diagnostic counts, not inherently better or worse |
| Memory | Mean changes below **0.5%**, mixed directions | Small differences versus stored golden references, not a controlled memory benchmark |
| GB200 GPT iteration time | **493.9 → 509.1 ms**, **3.07% slower** | Worse in this workload's warmed, interleaved comparison |

The [controlled timing experiment](https://gitlab-master.nvidia.com/dl/jet/ci/-/pipelines/70644060) used ten measured repetitions per stack after predeclared warmups within one exclusive two-node allocation. Its paired bootstrap 95% interval is **0.14–6.11% slower**, conditional on this allocation and workload, so it cannot rule out a regression above 5%. Earlier comparisons showed larger slowdowns of roughly **8–11.3%**; their results, including first-run spikes, remain recorded in the detailed timing audit below.

These measurements compare the complete dependency environments: TE, cuDNN Frontend, CUTLASS, and Quack changed together. The slowdown's cause remains unresolved; passing correctness tests does not establish performance equivalence. No dedicated performance golden or tolerance was changed.
