# What does this PR do ?
### Summary

Adds `--cuda-graph-impl transformer_engine --cuda-graph-granularity chunk` to capture each PP/VPP decoder block as one forward/backward graph pair. For THD training, the post-process (MTP, LM head and loss) is captured as a separate callable.

Applies to GQA/MHA, MLA, DSA, DSv4 CSA/HCA/SWA, and GDN/KDA through the shared block-capture infrastructure.

### Why chunk granularity

- Captures work across layer boundaries, including activation recompute and MoE dispatch/combine with static token shapes, reducing CPU and kernel-launch overhead.
- Supports changing packed microbatch counts within the capture bound. For PP/VPP, the source global batch size must reach its configured maximum before capture.
- Integrates full/selective recompute, FP8, MTP, paged stash and fine-grained activation offloading. Optional optimizer graphs share the decoder/post-process graph memory pool.
- Includes capture-safety fixes, shared compact-indexer workspaces, and FP8/FP4 checkpoint-routing fixes that also apply to eager execution.

### Validation

- Eager/chunk comparisons on DeepSeek-V3 MLA, DSA, DeepSeek-V4 and Qwen-shaped GDN/KDA proxies, covering BF16/FP8 and selected recompute, parallelism, MTP, paged-stash and offload configurations.
- Regression tests cover real THD capture/replay with loss and gradient comparisons, TP2/SP with MTP on/off, checkpoint preservation, FP8 contexts, packed CP rolls and gradient-clipping precision.
- Core unit tests, functional tests and lint pass on the latest commit.

**PP P2P still exchanges shapes for packed THD graphs**

- Packing sets `variable_seq_lengths=True` (`transformer_config.py:4513`), and `pipeline_p2p_fixed_shape` defaults to False. So every `_communicate` first runs `_communicate_shapes` (`p2p_communication.py:322-328`), which does a small `batch_isend_irecv`, `req.wait()`, `torch.cuda.synchronize()` and `.tolist()` (`:256-271`).
- The host therefore waits for the graph replay that produced the activation before it posts the payload. In steady-state 1F1B, that happens roughly twice per microbatch per stage. Without VPP, the `batch_p2p_sync` after the payload (`:419-423`) also synchronizes. With overlapped interleaved P2P, that later sync is skipped, so the handshake is the only host sync.
- THD CUDA graphs already require `pad_packed_seq_alignment` to be `'max'` or `max_seqlen_per_dp_cp_rank` (`transformer_config.py:4465-4480`). That is the precondition of `pipeline_p2p_fixed_shape` from #7000/#7483 (`model_parallel_config.py:595-635`), so the shape never changes and the exchange is redundant. The CPU run accepts `chunk_wise` + packing + `pipeline_p2p_fixed_shape=True` at this head.
- This applies to any THD graph with PP, not only `chunk_wise`. But `chunk_wise` is the mode where the remaining host overhead matters most.

With pad-to-max packing the inter-stage shape is static, so the per-P2P shape exchange can be skipped:

```suggestion
--pad-packed-seq-alignment max --thd-max-packed-sequences <N> --cuda-graph-dynamic-microbatches \
# packed sequences with PP > 1: the padded inter-stage shape is static, skip the P2P shape exchange
--pipeline-p2p-fixed-shape \
```

Maybe also warn in the `chunk_wise` block of `TransformerConfig.__post_init__` when it is off:

```python
if (
    self.sequence_packing_scheduler is not None
    and self.pipeline_model_parallel_size > 1
    and not self.pipeline_p2p_fixed_shape
    and not self.mtp_standalone
):
    warnings.warn(
        "cuda_graph_impl='chunk_wise' with packed sequences pads every microbatch to "
        "max_seqlen_per_dp_cp_rank, so the pipeline P2P shape is static; set "
        "pipeline_p2p_fixed_shape=True to skip the per-call shape exchange."
    )
```

`pipeline_p2p_fixed_shape` is rejected with dynamic CP (`model_parallel_config.py:598-601`), which point 1 rules out anyway. It has no effect with `mtp_standalone`. We haven't measured the gain, so this is low priority but cheap.

- In P's backward capture every MTP group start runs `bulk_reload` (`fine_grained_activation_offload.py:1450-1455`), which prefetches `_groups_to_reload[-1]`; only the cross-chunk branch (`1456`) checks `_block_capture`. - D's backward capture then finds that group in `_reloading_group` and waits on its event with no capture guard (`1513-1515`). A capture may not wait on an event recorded in another capture, so `make_graphed_callables` fails at D's backward capture (I'd expect `cudaErrorStreamCaptureIsolation`). **[CRITICAL Correctness]** `attn_norm` offload frees TE's static block input during capture (non-mHC layers)

- In a plain `TransformerLayer` with a standalone input norm, the `attn_norm` commit force-releases `residual` (`transformer_layer.py:1101-1104`), which is the group-start view of the layer input (`transformer_layer.py:1029-1033`). In the block's first layer, that input shares storage with TE's static `hidden_states` sample arg. Both `backward_record(args[0])` (`chunk_cuda_graph.py:306-313`) and `make_viewless_tensor` (`transformer_block.py:511`) keep the storage, and nothing clones it.
- Here, `_block_capture_release` runs `resize_(0)` on that storage inside the forward capture, leaving `static_input_surface[0]` with 0 bytes. TE's warm-ups run with offload disabled (`cuda_graphs.py:3743-3745`), so with PP=1 (one slot) capture completes. The first replay then fails when TE's `Graphed.forward` refreshes the static input (`data_ptr()`/`copy_`, `graph.py:842-848` in TE 2.18.0.dev0). With PP>1, a later slot that reuses this sample arg (`cuda_graphs.py:3209-3223`) can already fail during capture.
- Affected: `chunk_wise` + `attn_norm` offload on non-mHC layers with a separate `TENorm` input norm and the default `fp32_residual_connection=False`. Examples are MLA without `mla_down_proj_fusion` (`gpt_layer_specs.py:292`) and DSA (`experimental_attention_variant_module_specs.py:274-278`). mHC layers never release the block input (`transformer_layer.py:3706`, `hybrid_hyper_connection.py:800-804`), so the DSv4 proxy runs are unaffected.
- New with `chunk_wise`: the per-layer path disables `attn_norm` offload for the `attn` scope (`transformer_layer.py:2543-2550`), and whole-layer `transformer_engine` capture with offloading is warned as unsupported (`transformer_config.py:4754-4770`). `chunk_wise` always has an empty scope (`transformer_config.py:5083-5088`) and gets neither.
