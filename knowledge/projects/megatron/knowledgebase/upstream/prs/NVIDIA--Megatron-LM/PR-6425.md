# What does this PR do?
Add Muon support for M-FSDPv2 based on an experimental optimized M-FSDPv1 prototype.  
No integration into MCore yet.

This version uses all-`Flat` placements and uses an owner-based design:
- Non-matrix parameters are simply computed like usual.
- Unsharded, fully locally available matrix parameters are computed fully locally.
- For each sharded matrix parameter, one owner (that owns at least one shard of that parameter) is picked, on which
  1. the full orthogonalization input is reconstructed,
  2. orthogonalization performed, and
  3. the updates are scattered back to the original destinations.

Pseudocode:
```
**** Fwd
for each FSDP unit:
    1. COMM: all-gather weight shards, each rank has full weights
    2. execute fwd, each rank has activations over local data

**** Bwd
for each FSDP unit:
    1. COMM: all-gather weight shards, each rank has full weights
    2. execute bwd, each rank has full gradients over local data
    3. COMM: reduce-scatter full gradients, each rank has gradient
       shards over global data for local weight shards

**** Opt step
for each FSDP unit:
    1. update local optimizer state shards using local gradient shards
       and local optimizer state shards
    2. produce local orthogonalization input shards using local
       optimizer state shards and (optionally, with Nesterov) local
       gradient shards
    3. COMM: on owner, gather orthogonalization input shards, each
       owner has full local orthogonalization inputs

       owner is heuristically picked depending on orthogonalization
       compute cost
    4. on owner, compute orthogonalization outputs (the full updates)
    5. COMM: owner scatters full updates, each rank has local update
       shards
    6. update local weight shards using local update shards
```

Internal design doc with more details: https://docs.google.com/document/d/11FGBYk-hdvGBGh_s-1tGBv2JYLicRPXIHApILtD6Mzw/edit?tab=t.vd156zcgkxyj
