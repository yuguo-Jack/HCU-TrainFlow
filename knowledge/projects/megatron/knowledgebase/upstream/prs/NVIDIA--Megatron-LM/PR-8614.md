# ci: fall back to full unit tests on non-main branches

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8614) · state: closed · merged: True

## Original PR description

PRs targeting branches other than `main` can enter selective unit-test CI and fail with `ValueError: Testmon selection requires main` before GPU tests are dispatched (for example, #7902).

Skip CPU selection for unsupported or empty target branches and dispatch the original bucket matrix in full mode. Keep `main` selection, empty-plan handling, and the existing missing/incompatible-cache fallback unchanged.

Only `.github/workflows/_unit-tests.yml` is changed; test-file changes were excluded as requested.

Validation: the workflow change passed 92 targeted tests with the accompanying regression-test updates before those test updates were removed. `git diff --check` passed. The unchanged repository tests were not rerun after removal; their previous exact-expression assertions will need updating separately. GitHub CI has not yet validated the final revision.

### Update the workflow regression test alongside these conditions

The new [selection condition](https://github.com/NVIDIA/Megatron-LM/blob/c993715750e707fd8e9eaf8efd343ad1b57f02d4/.github/workflows/_unit-tests.yml#L43) breaks both `empty` and `selected` parameterizations of `test_cpu_selection_controls_gpu_execution_and_coverage`. Its [assertion at line 809](https://github.com/NVIDIA/Megatron-LM/blob/c993715750e707fd8e9eaf8efd343ad1b57f02d4/tests/test_utils/test_testmon_workflow.py#L805-L809) still requires the old condition. Updating that assertion alone is insufficient: the [test context](https://github.com/NVIDIA/Megatron-LM/blob/c993715750e707fd8e9eaf8efd343ad1b57f02d4/tests/test_utils/test_testmon_workflow.py#L829-L836) lacks `unit_testmon_target_branch`, so evaluating the new GPU-dispatch condition then raises `AttributeError`. The regression test should pass against the final workflow and cover the fallback being introduced.

**Correction:** retain the workflow fix and update this test in the same change. Replace its select-condition assertion and `inputs` initialization with:

```python
assert workflow["jobs"]["select"]["if"] == (
    "inputs.unit_testmon_mode == 'enforce' && "
    "inputs.unit_testmon_target_branch == 'main'"
)

inputs = SimpleNamespace(
    unit_testmon_mode="enforce", unit_testmon_target_branch="main"
)
```

Also add regression cases using the actual workflow expressions for targets `dev` and `""`: enforce mode must skip selection, allow dispatch when selection is skipped, and retain the original bucket matrix with effective mode `full` when selection outputs are absent. Do not remove or disable the existing assertions to accommodate the change.

**Preservation and acceptance:**
- Retain both existing parameterizations: main/enforce dispatches only after successful selection with tests; empty selection, failed selection, and skipped selection suppress dispatch. Explicit full mode still bypasses selection.
- Add cancellation cases expecting no dispatch for both main and unsupported targets.
- Retain the [grouped-selector assertions](https://github.com/NVIDIA/Megatron-LM/blob/c993715750e707fd8e9eaf8efd343ad1b57f02d4/tests/test_utils/test_testmon_workflow.py#L1031-L1059): cache-error entries use `full`, empty buckets disappear from the matrix, and selected entries retain their plan artifact.
- With pytest, PyYAML, and jq available, `python -m pytest tests/test_utils/test_testmon_workflow.py -k test_cpu_selection_controls_gpu_execution_and_coverage` should pass both existing parameterizations and the added branch/status cases.

This finding is based on static source inspection, not executed tests; the suggested code must be verified before adoption. The branch-gating and downstream full-bucket contracts otherwise match the intended change.
