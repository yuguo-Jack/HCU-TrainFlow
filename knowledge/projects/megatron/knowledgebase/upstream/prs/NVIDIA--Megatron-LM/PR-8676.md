# Support heterogeneous expert counts in router expert-bias updates

# What does this PR do?

Fix a global-batch finalization failure when auxiliary-loss-free MoE routers have different numbers of experts: stacking the token-count and bias vectors from, for example, 4-expert and 8-expert layers raises a size mismatch.

Bucket compatible token-count/bias tensors by shape, dtype, and device, then update buckets in sorted order. Preserve int64 token counts, per-layer in-place bias updates, and the existing eval/frozen/no-bias skips. Homogeneous layers still share one collective. Ranks retain the existing requirement to agree on active layers and logical layer order within each bucket.

This change is limited to auxiliary-loss-free expert-bias updates. It does not change quantile balancing or the heterogeneous-model configuration/training entry point.

- Nine additional real-Core-MoELayer configurations pass: FP32/BF16, single GPU, DP=2, TP=2, allgather/alltoall dispatch, and homogeneous 4/4-expert regression. The two-layer workload uses hidden=512, FFN=1024, top-k=2, micro batch=1, sequence length 256/512, four accumulation microbatches, and three SGD steps. Token counts, bias, outputs, gradients, parameters, and subsequent routes exactly match an independent model using per-layer bias updates.

- An independent code review found no actionable defects.
