# Reduce peak memory in unfused absorbed DSA

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8304) · state: closed · merged: False

## What does this PR do?

Reduce peak memory in unfused absorbed DSA while preserving sequence lengths and selected tokens. The original fallback creates score copies, retains redundant softmax intermediates, and broadcasts shared MQA K/V across query heads. Its mask-construction temporaries can also overlap the full attention scores.

- Fold query heads into query rows and use `bmm` against shared K/V, avoiding per-head K/V copies and gradients.
- Complete mask construction before allocating scores. Without an external additive mask, retain only boolean validity and release the float mask before QK. External additive biases and their gradients are preserved.
- Reshape the owned contiguous score buffer by changing its metadata in place, then reuse it for scaling, masking, and softmax. This avoids both a scaling copy and the `CopySlices` gradients caused by writing through a separate view.
- Outside autocast, combine softmax and the value matmul in one autograd function. Save the FP32 probabilities without retaining a second BF16 cast; reuse the matmul's freshly computed probability gradient for softmax backward. Caller gradients and saved probabilities are not modified during backward. Returning the probability intermediate preserves higher-order derivatives and repeated backward.
- Under autocast, retain the existing separate softmax/value autograd path and its dtype conversions. The shared `masked_softmax` helper also avoids redundant probability/mask storage and preserves the existing `eps > 1` behavior.

The unfused path still has quadratic attention-score storage. This change introduces no sequence-length or top-k limits and no new kernel dependency.

## Measured peak allocation

RTX A1000 Laptop GPU (4 GiB), PyTorch 2.12.1+cu130, **autocast disabled**. Complete absorbed fallback: batch 1, 32 heads, 128 query rows, **16,384 keys**, Q/K/V dimensions 512, top-k 2048, packed-varlen bounds. The FP32 score tensor is 256 MiB throughout. Inputs and upstream gradients are preallocated before resetting `torch.cuda.max_memory_allocated`; values below are peaks above those inputs, excluding an optimizer step.

| Peak allocation | Unmodified upstream | Preceding draft | Current PR |
| --- | ---: | ---: | ---: |
| FP32, no-grad forward | 1098.14 MiB | 278.13 MiB | 266.13 MiB |
| FP32, grad-enabled forward | 1738.21 MiB | 516.13 MiB | 266.13 MiB |
| FP32, forward + backward | 2248.07 MiB | 810.02 MiB | **554.02 MiB** |
| BF16, no-grad forward | 1098.14 MiB | 390.13 MiB | 390.13 MiB |
| BF16, grad-enabled forward | 1778.21 MiB | 556.13 MiB | 430.13 MiB |
| BF16, forward + backward | 1980.07 MiB | 830.02 MiB | **702.00 MiB** |

The latest change lowers complete forward/backward peaks by another 31.6% (FP32) and 15.4% (BF16), while also lowering grad-enabled forward peaks. Relative to unmodified upstream, complete peaks are lower by 75.4% and 64.5% respectively. These reductions are measured outside autocast; autocast retains separate softmax/value backward.

Additional complete forward/backward measurements, with the same dimensions/top-k and autocast disabled:

| Configuration | FP32 preceding → current | BF16 preceding → current |
| --- | ---: | ---: |
| Batch 2, 32 heads, 64 query rows, 16K keys | 850.02 → 602.02 MiB | 878.02 → 754.00 MiB |
| Batch 1, 32 heads, 32 query rows, 64K keys | 900.00 → 644.00 MiB | 965.00 → 837.00 MiB |
| Batch 1, 2 heads, 4096 query rows, 16K keys | 1648.04 → 1136.04 MiB | 1672.04 → 1416.00 MiB |

For the 4096-query FP32 case, grad-enabled forward alone falls from 1216.13 to 704.13 MiB after separating mask construction from score allocation. These are operator measurements, not whole-model or reserved-memory estimates. Query-row sizes describe benchmark tensors, not training limits.

Baselines: upstream `36731acc3` and preceding draft `0a3f8483a`. The PR is based on `4ab3af12d`, whose DSA implementation is unchanged from the upstream baseline.
