# [Dev] Fix FLOPs accounting for detached MTP heads

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7604) · state: closed · merged: True

## Original PR description

## Summary

- count the final LM output projection as forward, dgrad, and wgrad
- count detached MTP draft heads as forward and dgrad only
- share the corrected formula between standard and hybrid FLOPs accounting
- preserve the legacy three-pass count when `mtp_detach_heads` is absent

Main counterpart: https://github.com/NVIDIA/Megatron-LM/pull/7663

## Strict review: no significant issues found, LGTM

**Findings:** 0 critical, 0 important, 0 suggestions.

**Risk:** low. The change only affects how training FLOPs are counted, and only when `mtp_detach_heads=True`. With the flag absent or `False`, the attached MTP count gives the same number as before on both the standard and hybrid paths.

### What I checked

**1. The attached case still gives the same count.**
- The new helper [`_logit_flops_per_token`](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/training/training.py#L460-L481) returns `2·h·V·(3 + 3·mtp)` when the heads are attached.
- Standard path: this equals the old term `forward_backward_expansion_factor(3) · fma(2) · h · V · (mtp + 1)`, using the local factors at [L1595-L1599](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/training/training.py#L1595-L1599).
- Hybrid path: the logit term moved out of `flops_fwd`, which was multiplied by 3. It is now added once, already multiplied by 3, at [L1526-L1539](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/training/training.py#L1526-L1539). That is algebraically the same.
- The existing standard-vs-hybrid DSv4 equivalence test (`_make_dsv4_pair`, `mtp=1`) and the KDA absolute-formula test still apply to these paths.

**2. Detached heads do skip only wgrad, matching the model.**
- [`process_mtp_loss`](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/core/transformer/multi_token_prediction.py#L1899-L1903) passes `output_weight.detach()` to the draft-head projections.
- A detached weight sends the linear layer down [`linear_with_frozen_weight`](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/core/tensor_parallel/layers.py#L403-L419), which computes no weight gradient.
- The draft hidden states still need dgrad:
  - The MTP input is detached but explicitly set back to `requires_grad_(True)` ([L2293-L2302](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/core/transformer/multi_token_prediction.py#L2293-L2302) and [L3100-L3101](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/core/transformer/multi_token_prediction.py#L3100-L3101)).
  - So the GEMM counts for the eh-projection and the MTP layers are unchanged, and only the 2·h·V wgrad per draft head goes away.
- The main LM head is not touched by the flag.

**3. The E2E-TV target projection is unchanged.** It is computed under `torch.no_grad()` on `hidden_states.detach()` ([L1728-L1733](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/core/transformer/multi_token_prediction.py#L1728-L1733)), so it stays a single forward-only pass whether or not the heads are detached. That matches the unchanged `e2e_tv` term on both paths.

**4. New arguments are all used.**
- `mtp_detach_heads` is passed into `hybrid_flops` ([L2089](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/training/training.py#L2089)) and into the standard-path helper call ([L1963-L1968](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/training/training.py#L1963-L1968)).
- `getattr(..., False)` keeps old argument namespaces working, matching the `TransformerConfig.mtp_detach_heads` default of `False`.
- The `reorder_inner_param_groups` hunk only adds blank lines (formatting).

**5. The new tests can pass exactly, though I did not run them.**
- [`TestMTPLogitFlops`](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/tests/unit_tests/test_num_floating_point_operations.py#L624-L699) covers the standard and hybrid paths with cross-entropy and e2e_tv, with no MTP, and with the flag missing.
- With the helper dimensions (`kv_channels·heads/h = 1.0`, `g/n = 1.0`), every float term is an exact integer well below 2^53. So the `==` difference checks are exact.

### Pre-existing behaviour, not caused by this PR and not a finding
The Blackwell fused linear-cross-entropy backward always computes `d_weight` ([entry.py L448-L454](https://github.com/NVIDIA/Megatron-LM/blob/a61ec4b35dbddf1380df79dabf26b0543d26760e/megatron/core/fusions/linear_cross_entropy/blackwell/entry.py#L448-L454)). With `cross_entropy_fusion_impl="linear"` and detached heads, that GEMM still runs, and autograd throws the result away.

This counter counts model FLOPs: a fixed 3× forward+backward factor, with no recompute work added. So leaving out the discarded wgrad is consistent with that convention. The wasted kernel work is a separate optimisation opportunity in the fused kernel.
