# Keep the loaded metadata when the fully parallel load group has one rank

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8521) · state: open · merged: False

## Original PR description

FullyParallelLoadStrategyWrapper kept its own copy of the base strategy's cached_global_metadata and refreshed it only at the end of the parallel load path. When its parallelization group had a single rank, load returned the base strategy's result early and the copy stayed None. The save strategy reads that attribute from the load strategy to reuse the loaded checkpoint's global metadata, so with --ckpt-assume-constant-structure the first save after such a load always gathered every rank's plan instead.

This hits, for example, --ckpt-fully-parallel-load-process-group ep_dp when the expert data parallel group has one rank.

Make cached_global_metadata a property that reads the base strategy's, so it cannot fall out of sync on any return path.
