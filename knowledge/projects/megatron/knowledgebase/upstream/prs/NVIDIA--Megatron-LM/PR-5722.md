### Assessment

This is a well-scoped, well-tested change that swaps the grouped output projection (`DSv4HybridAttention.linear_o_group_proj`) to `transformer_engine.pytorch.BatchedLinear` (enabling MXFP8/BF16 and removing the post-projection `.contiguous()`), while keeping the legacy einsum path as a fallback when TE `BatchedLinear` is unavailable.

I traced the areas most likely to hide bugs and found them handled correctly:

- **Checkpoint backward compatibility** — the `_linear_o_group_proj_state_dict_hook` re-flattens the runtime 3D weight (`linear_o_group_proj.weight`) back to the legacy 2D `linear_o_group_proj` key, and `_load_from_state_dict` accepts both 2D legacy and 3D runtime layouts. `_extra_state` is popped on save and `setdefault(..., None)` on load, so TE-produced state stays out of the canonical checkpoint. Verified against the new `test_o_group_proj_legacy_checkpoint_compatibility` (BF16 + quantized).
- **Distributed checkpointing** — `sharded_state_dict` wraps the weight in a `ShardedTensorFactory` that rewrites `local/global` shapes and offsets from the 3D `(groups, rank, in_features)` layout to the flattened 2D `(groups*rank, in_features)` layout, with an assert that sharding only happens along group/in-feature dims (rank axis must be un-sharded, offset 0, fragmentation 1). This mirrors the established `apply_swiglu_sharded_factory` / `apply_head_wise_attn_gate_sharded_factory` pattern and flows correctly through `make_sharded_optimizer_tensor` for the distributed optimizer (verified via `get_param_id_to_sharded_param_map` in the test).
- **Numerics / gradients** — the new `test_o_group_proj_numerics_and_gradients` checks forward + input/weight grads against the einsum reference for BF16 and MXFP8 with appropriate tolerances.
- **TE availability guarding** — `getattr(te, "pytorch", None)` / `getattr(te_pytorch, "BatchedLinear", None)` degrade gracefully to the einsum path; native-parity test updated to accept both parameter names.

### Most impactful note

One minor **[SUGGESTION Simplification]** (inline): the einsum-fallback `_apply_linear_o_group_proj` does a no-op `.reshape(...)` of an already-3D weight on every forward — safe to drop.

**Risk level: Low.** No correctness, performance, or backward-compatibility concerns. The change is confined to an experimental attention variant, preserves checkpoint format across both implementations, and is covered by targeted unit tests.

Strict Review Summary — PR #5722: Add batched gemm for DSv4HybridAttention

Findings by severity — CRITICAL: 1, IMPORTANT: 0, SUGGESTION: 0

This is a carefully engineered PR. Swapping the raw grouped nn.Parameter + torch.einsum for te.pytorch.BatchedLinear (with a clean einsum fallback + warning when TE is too old) is sound, the MXFP8/BF16 numerics + gradient tests are thorough, and the substantial state-dict shim work correctly preserves the legacy 2D checkpoint layout across state_dict/load_state_dict/sharded_state_dict. The forward-path change (_apply_linear_o_group_proj) is behavior-preserving, and the einsum equation is unchanged. No backward-compat issue for existing checkpoints in the plain state_dict path, and no new direct parallel_state.get_*_group() reads.

Most impactful finding:

[CRITICAL Correctness] The sharded_state_dict build_fn unconditionally reshapes to the full 2D checkpoint_local_shape. Under the DEFAULT distributed-optimizer sharding (fully_sharded_model_space), the optimizer wraps this factory around flat, partial DP-shard state with flattened_range set — a full-shape reshape either raises a numel-mismatch RuntimeError (weight straddling a DP-shard boundary) or produces 2D data with a stale non-None flattened_range. The established precedent (ssm/mamba_mixer.py::_split_tensor_factory) handles this by narrowing/keeping data flat and passing flattened_range through. Suggested fix: skip the reshape when flattened_range is not None (the two leading axes merge contiguously, so flat element order is identical), and add a distopt save/load test — the current test only exercises factory.build() with full-shape data.

Risk assessment: Medium. The core BatchedLinear integration and non-distributed checkpoint paths are well-tested and low-risk. The risk concentrates in the one distributed-optimizer save path above, which is the default distopt sharding type and is not covered by the added tests. Recommend resolving the CRITICAL finding (and adding distopt coverage) before merge.

File: `megatron/core/transformer/experimental_attention_variant/deepseek_v4_hybrid_attention.py` · line None

**[CRITICAL Correctness]** `build_fn` unconditionally reshapes to the full 2D `checkpoint_local_shape`, which breaks distributed-optimizer checkpoint save under the **default** sharding type (`fully_sharded_model_space` → `sharded_param_state_fs_model_space`; see `distrib_optimizer.py` line 1503 default and 1563).

In that path the optimizer wraps this factory around **flat, partial** state via `replace(sharded_metadata, data=state_ten, flattened_range=item_slice)` (`distrib_optimizer.py` lines 2026–2035), where `state_ten` is a 1D DP-shard slice whose numel is `param_range.end - param_range.start` — i.e. only the portion of this parameter residing on the local DP rank. When the grouped-proj weight straddles a DP-shard boundary, `tensor.reshape(checkpoint_local_shape)` raises a `RuntimeError` (numel mismatch); even when it doesn't straddle, you end up with 2D-shaped `data` carrying a non-None `flattened_range`, which is inconsistent for the save machinery.

Contrast:
- `sharded_param_state_fully_reshardable` reshapes to the full shape *before* wrapping and asserts `flattened_range is None` (lines 1770, 1805), so a full-shape reshape is valid there.
- The established reshape/split factory in `ssm/mamba_mixer.py` (`_split_tensor_factory`) handles the flat case by using `ShardedTensor.narrow` and passing `flattened_range` through — it never reshapes flat partial data to the full multi-dim shape.

The previous plain-`nn.Parameter` implementation produced a normal `ShardedTensor` that the optimizer handled natively, so this is a regression on the default distopt save path for DSv4HybridAttention.

**Fix:** the (groups, rank, in)→(groups*rank, in) reshape merges the two leading axes contiguously, so the flat element order is identical. When `flattened_range is not None`, skip the reshape and keep `tensor` flat, building the checkpoint `ShardedTensor` with `local_shape=checkpoint_local_shape` and the passed-through `flattened_range` (mirror the mamba/narrow pattern). Only reshape in the non-flattened case. Please also add a distributed-optimizer save/load test (the current `sharded_state_dict` test only exercises `factory.build()` with full-shape weight data, not the flat optimizer-shard path).

> The previous implementation did assume full-shaped factory data, so it would fail if invoked with a flat partial optimizer state.
>
> After tracing the checkpoint entry point, I changed the fix slightly instead of adding DSv4-specific support for `fully_sharded_model_space`:
>
> - `fully_sharded_model_space` is only the fallback when `DistributedOptimizer.sharded_state_dict()` is called without checkpoint metadata.
> - The normal checkpoint path sets `dp_reshardable` by default, or `fully_reshardable` when requested. `dp_reshardable` does not invoke this parameter factory, while `fully_reshardable` passes full-shaped state with `flattened_range=None`.
> - `fully_sharded_model_space` is deprecated and is already incompatible globally because `ShardedTensor.validate_metadata_integrity()` rejects every non-`None` `flattened_range`. Supporting it only for this DSv4 parameter would therefore not make a complete optimizer checkpoint valid.
>
> I simplified the implementation accordingly:
>
> - The fallback path now retains the original 2D `Parameter`, so it uses the existing state-dict and distributed-checkpoint behavior directly.
> - Only the TE `BatchedLinear` path installs the 3D-to-2D compatibility factory.
> - The factory supports the active non-flat checkpoint formats, preserves PP/FSDP group-axis metadata, and explicitly rejects the deprecated flat format.
>
> I also added coverage for the fallback 2D `ShardedTensor` path and pipeline-offset metadata. The full test file passes on GB200 with two ranks (`35 passed` on each rank), including BF16, MXFP8, quantized model initialization, legacy checkpoint loading, and the einsum fallback.
>
> If `fully_sharded_model_space` needs to be restored, I think it should be addressed globally in the distributed-checkpoint/optimizer implementation rather than with a DSv4-specific irregular-shard conversion.
