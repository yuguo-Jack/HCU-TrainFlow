# Support fsdp_dtensor checkpoints and exact resume for MFSDP v2 Muon

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8547) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Save and resume the `FsdpMuon` + Adam optimizer state from #8548 with the `fsdp_dtensor` checkpoint format, including fused SwiGLU, GDN and MLA parameters.

Stacked on #8548: until it lands, the GitHub diff also shows its commit.

## Implementation

- `ChainedOptimizer` merges the states of chained `FullyShardedOptimizer`s into one mapping keyed by globally unique parameter names, and each optimizer selects its own parameters on load. Other chains are unchanged.
- `FullyShardedOptimizer.load_state_dict` always filters the loaded state by the parameters it owns, because a chain shares one checkpoint mapping.
- The SwiGLU, GDN and MLA conversions in `fsdp_dtensor_checkpoint.py` also handle Muon's `momentum_buffer`, split MFSDP v2 DTensor parameters (v1 keeps its flat-slice path), and strip wrapper prefixes when resolving parameter names.
- Muon momentum needs no special handling: the existing `init_optimizer_state` dummy step creates it.

## Validation

New tests: BF16 checkpoint round trips for Adam/Muon × GELU/SwiGLU × EP=1/2/4. Each saves, restores into a fresh model, continues training, and requires losses to match uninterrupted training exactly (`rtol=0`, `atol=0`).

On 8 H100 (CW) with Transformer Engine 2.18.0, there are no failures in the MFSDP v2 unit tests (99 cases per rank), the `fsdp_dtensor` checkpoint unit tests (142), the MFSDP v1 fused-MLA checkpoint test (4) and, with the same optimizer code, the optimizer unit tests (247).
