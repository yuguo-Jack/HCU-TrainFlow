# Finalize gradient windows by declared multiplicity

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7581) · state: closed · merged: True

## Original PR description

## Summary

Allow an experimental MFSDP unit to declare the total number of parameter-gradient callbacks expected in one reduction window. This is the prerequisite runtime change for #7582.

Combined 1F1B can run separate autograd `GraphTask`s for schedule nodes that consume the same weight. Counting one callback per trainable parameter can therefore reshard and reduce gradients before every contribution arrives.

## Implementation

- Extend `FsdpModule.register_post_backward_hook` with optional `grad_accumulation_count`, defaulting to one callback per owned trainable parameter.
- Use the existing unit-level countdown to invoke post-backward reduction after the declared total arrives, then automatically re-arm for the next window.
- Use post-accumulate hooks for ordinary parameters and Transformer Engine's wgrad callback for parameters with delayed weight-gradient computation.
- Keep the full-backward-hook fallback for parameter-free modules. Reject incompatible callback declarations and tied delayed-wgrad parameters that Transformer Engine cannot accumulate.
- Expose the read-only `Countdown.is_complete` property. #7582 checks that state and reports partially completed windows inline at the adapter's per-step synchronization boundary.

This is total-count accounting, not per-parameter readiness tracking: it cannot identify a missing parameter or detect extra callbacks that complete another whole countdown cycle. Correct declarations remain the scheduler's responsibility.

## Tests

`tests/unit_tests/distributed/mfsdp_v2/test_grad_multiplicity.py` contains **5 cases**:

- Losses, public parameter gradients, and SGD updates match a dense baseline across one, two, and three GraphTasks, plus unequal parameter multiplicities (4 cases).
- A parameter-free unit rejects a nonzero callback declaration (1 case).

The numerical test uses default `zero_grad()` behavior and repeats steps and gradient windows. It has no `set_to_none` parameterization, callback spies, or parameter-group assertions.
