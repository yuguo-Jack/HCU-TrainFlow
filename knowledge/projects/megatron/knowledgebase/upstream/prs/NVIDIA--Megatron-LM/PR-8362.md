# [optimizer] fix: shard experts when dense DP is singleton

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8362) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Fix LayerWise expert ownership when dense data parallelism has size one but expert data parallelism has multiple ranks.

For example, four ranks with TP4 / EP1 / ETP2 have dense DP1 and expert DP2. `shard_params()` currently returns after checking only dense DP, so every expert replica retains the parameter in its optimizer and the expert synchronization list is discarded. On unmodified `main` at `74c9420e35cc3c1226e53421f5ff718653aa8399`, a four-element logical expert weight with all-one gradients has two owners per expert-DP group and reports a norm of `2.8284270763` instead of `2.0`.

The early return now requires both groups to be singletons. Both the DDP-layout and legacy ping-pong paths assign expert owners normally; the singleton dense group still skips synchronization. The reference `broadcast_params()` path also proceeds to expert synchronization when the dense list is absent.

The regression uses real NCCL groups and DDP buffers. It covers dense/expert DP sizes `(1, 2)`, `(1, 1)`, `(2, 2)` and `(2, 1)` with both parameter layouts, verifies one owner per replica group, and compares three clipped updates and synchronized BF16 weights against independent unsharded Adam references.

## Issue tracking

Related to #6099, which propagates the expert TP group for gradient filtering. This fixes the separate ownership early return. The open related LayerWise PRs were checked; no open PR addressing this specific early return was found.
