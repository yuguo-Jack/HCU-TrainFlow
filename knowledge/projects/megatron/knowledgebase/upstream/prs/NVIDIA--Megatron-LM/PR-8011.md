# fix(vision): keep RADIO packed sequence maxima as integers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8011) · state: closed · merged: False

## Original PR description

RADIO temporal grouping constructs scalar-tensor `max_seqlen_q` and `max_seqlen_kv` values even though `PackedSeqParams` declares integer maxima. With FlashAttention 4.0.0b34 and CUTLASS 4.8, these values fail in `cute.ceil_div` with `ValueError: Expected IntTuple, whose leaves are integers`.

Keep the maximum as the Python integer already computed from frame geometry. This preserves cumulative sequence boundaries and their dtype/device, and avoids the unnecessary scalar allocation without adding a device-to-host synchronization.

The issue affects five image/video tests in [Megatron Bridge #6258](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6258), including [the two RADIO video forwards](https://github.com/NVIDIA-NeMo/Megatron-Bridge/actions/runs/37924987528/job/113823958424). Add six CPU regression cases covering uniform videos, ragged videos, mixed images/odd-frame videos, and both embedder paths; also enforce integer maxima in the existing GPU metadata cases.
