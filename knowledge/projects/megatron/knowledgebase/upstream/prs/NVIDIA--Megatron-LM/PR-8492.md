# Preserve coroutine runtime errors

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8492) · state: open · merged: False

## Original PR description

## What does this PR do?

`DynamicInferenceEngine._run_coroutine_sync` runs a coroutine synchronously. When an event loop is already running in the calling thread, it executes the coroutine in a helper thread. The `try` that detects a running loop also wrapped that execution, so a `RuntimeError` raised by the coroutine itself was treated as "no running loop". The bridge then retried on the engine's loop, and the caller saw "This event loop is already running" instead of the real error.

This PR guards only the loop check, so errors raised by the coroutine reach the caller unchanged.

## Example failure scenario(s)

**Scenario (engine step fails inside a running loop)**

- Caller A calls `engine.step_modern()` from code that already runs an event loop.
- The bridge runs the step coroutine in a helper thread, and the step raises `RuntimeError("original engine failure")`.
- The old exception handler catches that error and tries `run_until_complete` on the engine's loop.
- Caller A receives "This event loop is already running", which hides the real failure.
- With this fix, caller A receives `RuntimeError("original engine failure")`.

## How was this bug discovered?

A unit test raises `RuntimeError("original engine failure")` from a coroutine while a loop is running and expects that exact error. On `main` the test receives "This event loop is already running", which exposes the overly broad exception handler.

## Dependency and scope

This PR is independent and based on `main`. The only production change is in `DynamicInferenceEngine._run_coroutine_sync`. The regression is `test_run_coroutine_sync_preserves_runtime_error_from_running_loop` in `test_dynamic_engine.py`.
