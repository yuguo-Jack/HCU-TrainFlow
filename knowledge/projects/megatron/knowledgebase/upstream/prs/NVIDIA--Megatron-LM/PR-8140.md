# What does this PR do?

Right now, the engine loop has to wait for `RequestPayloadStager.stage()` inside its bookkeeping. If this wait is long, it blocks the engine loop, and the GPU goes idle.

This matters for NeMo RL's token-level rollout checkpointing. While a checkpoint is being taken, the framework forbids the stager from writing finished requests into its store: the checkpoint records which requests were still in flight, and a terminal write in the meantime would invalidate that record. This blocks the entire engine loop because `RequestPayloadStager.stage()` stops responding.

This PR lets `stage()` return `RequestPayloadStageDeferred` instead. The engine then holds the finished request's reply, neither indexing nor sending it, and offers it to the stager again on every bookkeeping pass; `flush_deferred_stages()` lets the stager trigger a retry from any thread as soon as it may write again. `reset()` refuses while deferred replies are outstanding.

Failed replies are unaffected.
