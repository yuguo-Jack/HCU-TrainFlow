# Load the MLA query RoPE dims contiguously in the forward kernel

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8141) · state: closed · merged: True

## Original PR description

The in-place query RoPE forward (_mla_rope_fwd_inplace_kernel) read the emb_dim RoPE elements of every head with two stride-2 loads, one for the even and one for the odd elements, and with remove_interleaving it wrote them back with two stride-2 stores. It now loads them with one contiguous load and splits the even and odd elements in registers, and writes the remove_interleaving output with one contiguous store. For DeepSeek-V3's query, [4096, 1, 128, 192] in bf16, the kernel takes 11.3 us instead of 18.7 us on VR200.

With the new load the compiler paired the products into FMAs differently, and its pairing also changed with BLOCK_H. The FMAs are now formed explicitly, with the pairings the two-load kernel compiled to, so the output is bit-identical to before at every BLOCK_H the autotuner can choose and no longer depends on BLOCK_H or num_warps. The exception is fp32 q with bf16 cos/sin and inverse=True, where the previous output itself changed with BLOCK_H; it now equals the previous small-BLOCK_H output.

The query replay test now also covers remove_interleaving=True.
