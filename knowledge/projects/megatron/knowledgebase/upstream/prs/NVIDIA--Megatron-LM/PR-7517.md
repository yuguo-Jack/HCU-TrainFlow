# Fix NaNs in QK clipping with mixed-sign logits

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7517) · state: open · merged: False

## Original PR description

## Why

QK clipping scales Q and K when an attention head exceeds the configured positive logit threshold. A different head can have a negative maximum logit in the same step. Computing `threshold / maximum` and clamping only its upper bound leaves a negative scale for that head; applying the fractional clipping powers then puts NaNs into Q and K weights and their full FP32 master weights.

This is the numerical case identified in #7382, whose broader hybrid-layer and distributed-optimizer changes were retained downstream. The same denominator defect is present in both standard attention and MLA.

## What changed

- Compute the scale as `threshold / maximum.clamp_min(threshold)` in both attention implementations. Every head at or below the threshold receives scale one; an over-threshold head keeps the existing ratio.
- Preserve standard attention's query-group reduction and Q/K scaling, and MLA's separate non-RoPE and RoPE scaling. V weights remain unchanged.
- Extend the existing mixed-logit regressions across MHA, GQA, direct-Q MLA, and Q-LoRA MLA. The cases include negative maxima, signed zero, the threshold boundary, and full FP32 master weights.

The production change remains within the two clipping implementations and adds no allocation, configuration option, or alternate clipping path.

## Verification

Historical validation on one H100 80GB used PyTorch `2.8.0a0+5228986c39.nv25.06` and Transformer Engine `2.19.0`. The 12 cases against actual attention modules reproduced NaN weights on the baseline and passed with the denominator change. MLA coverage included RoPE and YaRN, and the comparisons included full FP32 master weights. Scoped Black, isort, and Ruff checks passed for that revision.

Merged main at `159b443c3e1a23ff68321973b936fef810bb3c61`; the current PR head is `29fd15df642d0148abbc15f3f4f360d101b9d8c8`. A fresh CPU behavior replay on macOS arm64, Python 3.12.14, and PyTorch 2.14.1 executed the current production clipping methods extracted from source. All eight combinations of MHA, GQA, direct-Q MLA, and Q-LoRA MLA with negative maxima and positive/negative zero failed on current main and passed on this head, including full FP32 master weights and unchanged V weights. This isolates the clipping methods with constructed module state.

The existing numerical regression can be rerun with:

```bash
uv run python -m torch.distributed.run --standalone --nproc-per-node 1 \
  -m pytest -q \
  tests/unit_tests/transformer/test_attention.py::TestClipQK \
  tests/unit_tests/transformer/test_multi_latent_attention.py \
  -k clip_qk
```

The H100 evidence predates this merge, and the current head has CPU validation; full multi-rank optimizer-shard clipping and hybrid-layer traversal remain outside this patch. The file-level determinism gate also selects unrelated kernels sharing these source files, so its coverage requirement needs a maintainer decision alongside the focused numerical checks.
