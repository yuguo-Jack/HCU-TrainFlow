# Support blockwise FP8 NCCL EP dispatch

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8917) · state: open · merged: False

## Original PR description

## Summary

Add a minimal `fp8_blockwise` path for NCCL EP dispatch in Megatron Core, and let the overlapped shared-expert path produce one rowwise blockwise-FP8 input that is reused by both shared-expert FC1 and NCCL EP dispatch.

This PR is the MCore counterpart of the NCCL EP block128 work in:
- RFC: NVIDIA/Megatron-LM#8675
- NCCL EP ABI / kernel PR: NVIDIA/nccl-extensions#34

## What changes

- Adds `moe_dispatch_fwd_dtype='fp8_blockwise'` and maps it to `Float8BlockScaling(E4M3, x_block_scaling_dim=1)`.
- Exposes an MCore wrapper for TE's blockwise dual-scale quantization producer.
- Allows `nccl_ep_dispatch` to consume an optional pre-quantized rowwise carrier instead of re-quantizing inside dispatch.
- Lets `MoEFlexTokenDispatcher` share the shared-expert pre-forward quantized input with NCCL EP dispatch when the shared-expert overlap path is eligible.
- Keeps the fallback path unchanged when sharing is not eligible.
- Updates the NCCL EP static-capacity guard so `fp8_blockwise` and BF16 wire can run on SM90; only MXFP8/FP4 dispatch keeps the Blackwell+ requirement.
- Adds a config smoke test for the new wire dtype.

## Current overlap strategy

This PR intentionally does **not** implement the future columnwise-requant overlap work. The current scheduling is conservative and functional:

1. Shared-expert pre-forward communication runs on the shared-expert stream.
2. The same stream produces the blockwise-FP8 rowwise quantized tensor.
3. The main/dispatch stream performs a device-side `wait_event` before NCCL EP dispatch.
4. NCCL EP dispatch consumes that rowwise payload.
5. The routed expert GroupedTensor remains the consumer path for routed experts; no async columnwise requant scheduling is included here.

## Validation

- `python3 -m py_compile` over the changed Python files.
- `git diff --check` passes.
- A focused config smoke test covers `moe_dispatch_fwd_dtype='fp8_blockwise'`.
- H200 qwen30b 8k correctness passed for the FP8 wire + FP8 GEMM development path with the linked TE work: `finite_output_and_gradients_checked=True`, no NaN/Inf.
- Performance note from the same validation setup: async-requant development builds were not a performance win over BF16 on this single-node configuration; the PR keeps the non-overlap functional baseline.

## Code provenance

This code was implemented independently in Megatron Core against the RFC/TE interfaces under review. It does not copy implementation code from other repositories.

## Known limitations / future work

- `moe_combine_bwd_dtype='fp8_blockwise'` is not implemented yet.
- Columnwise requant and combine communication overlap is future work and intentionally excluded from this PR.
- Direct dispatch of columnwise data is future work and intentionally excluded from this PR.
- The commit is signed off (`Signed-off-by`) but not GPG-signed in this environment because no local GPG secret key is available.
