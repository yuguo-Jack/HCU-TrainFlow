# fix(core): mark learnable softmax_offset as tensor parallel for clip norm

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7530) · state: open · merged: False

# What does this PR do?

Fixes Finding 8 of #7452 only: mark learnable attention-sink `softmax_offset` as tensor-model-parallel so clip-norm includes every TP rank's head-sharded sink grads.

@ezyang @wujingyue finding 8 fix ready for review; verified with the in-issue cpu/gloo repro.

## Issue tracking

Linked issue: Fixes Finding 8 of #7452 (does not claim to fix the whole issue)

## Root cause

With `softmax_type="learnable"`, `softmax_offset` is sized per local TP heads and `sharded_state_dict` already shards dim 0, but the parameter was never marked `tensor_model_parallel`. `param_is_not_tensor_parallel_duplicate` then keeps sink grads only on TP rank 0 for clip-norm, undercounting ‖g‖₂. Same symptom family as merged #5916 (expert grad undercount).

## Approach

1. `DotProductAttention`: after creating the learnable `softmax_offset`, call `tensor_parallel.set_tensor_model_parallel_attributes(self.softmax_offset, True, 0, 1)`.
2. `TEDotProductAttention`: after `super().__init__`, if TE created a learnable `softmax_offset` without TP attributes, set the same attributes (set-if-missing).
3. Unit test asserts the TP attributes on a mocked TP=2 `DotProductAttention`.

## Verification

Post-fix CPU/Gloo repro (adapted from the Finding 8 script in #7452):

```bash
PYTHONPATH=. torchrun --standalone --nproc-per-node=2 verify_08_attention_sink_grad_norm.py
```

Result (DotProductAttention path; TE not installed locally):

- observed: 5.0
- reference: 5.0
- `VERIFIED attention_sink_grad_norm_fixed`

Before the fix the same setup selected only rank-0's contribution and reported observed 3.0 vs reference 5.0.

Also ran a focused attribute check: `softmax_offset.tensor_model_parallel is True`, `partition_dim == 0`, `partition_stride == 1`.
