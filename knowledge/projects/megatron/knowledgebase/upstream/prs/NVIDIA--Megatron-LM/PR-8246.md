# Add configurable weight decay for RMSNorm gamma

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8246) · state: open · merged: False

## Original PR description

RMSNorm gamma currently inherits the generic weight-decay exemption for one-dimensional parameters. Add `OptimizerConfig.rmsnorm_weight_decay_mult` and `--rmsnorm-weight-decay-mult` to apply a configurable multiple of scheduled global weight decay specifically to gamma.

For example, `--weight-decay 0.1 --rmsnorm-weight-decay-mult 0.5` applies weight decay of `0.05` to RMSNorm gamma. Leaving the multiplier unset preserves current behavior; `1.0` applies full decay and `0.0` explicitly disables it. Explicit values take precedence over `apply_wd_to_qk_layernorm` for RMSNorm gamma only.

Mark gamma in PyTorch, Transformer Engine (including `TELayerNormColumnParallelLinear.layer_norm_weight` and fused residual norms), ModelOpt, and gated Mamba/GDP norm constructors. The existing `wd_mult` scheduler mechanism keeps the multiplier tied to global scheduled decay. Other parameters retain their current policies. Document custom norm tagging and stored-parameter semantics for zero-centered gamma.

Validation: `tools/autoformat.sh` passed Black, isort, Pylint, and Ruff. The new CLI argument block also passes Black. The script's non-blocking mypy step reported type errors and missing GPU dependency stubs in the touched modules; type checking is not claimed clean. Added unit coverage for selection, Q/K precedence, validation, CLI parsing, scheduled AdamW updates, and standalone/fused TE gamma tagging. Registered determinism tests cover PyTorch and TE norm gamma tagging, gated Mamba/GDP norm replay, and fused Adam parameters/moments with unset, zero, half, and full RMSNorm decay. The kernel determinism coverage gate passes locally without an exemption label. Runtime/CUDA tests were not run locally.
