# fix(inference): AUT-2539 handle string prompts and rejections in KV hand

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8258) · state: closed · merged: False

## Original PR description

## Background

Decode engines in disaggregated serving admit prefilled requests through `add_request_with_kv_handoff()`. The inference review found two gaps:
- `InferenceClient.add_request_with_kv_handoff()` accepts a string or a token list and forwards a string unchanged. The decode side called `torch.tensor()` on the prompt, so a string prompt raised inside the engine loop.
- Unlike `SUBMIT_REQUEST`, the `SUBMIT_REQUEST_WITH_KV` handler in `schedule_requests()` had no `try/except`. That error, or any other handoff validation error, escaped the loop and the client never got a reply.

## What changed

- `inference_state_handoff.py`: `prompt` is typed `str | list[int]`. A string prompt is tokenized once with `controller.tokenize_prompt(tokenizer, prompt, sampling_params.add_BOS)` before block hashing. The deferred and pending import records and the finalizer's `add_request()` then all carry the same token IDs.
- `dynamic_engine.py`: the `SUBMIT_REQUEST_WITH_KV` handler wraps `add_request_with_kv_handoff()` and sends any exception to `_fail_submission()`. That registers the same FAILED placeholder the plain submit path already uses. The `_fail_submission` docstring now mentions this caller.
- New tests: `test_schedule_requests_fails_a_rejected_kv_handoff_and_continues` in `test_dynamic_engine.py` and `test_string_handoff_prompt_is_tokenized_once_before_import` in `test_disagg_handoff_lifecycle.py`.

## Details

Every MP rank processes the same broadcast message, so the failure path keeps request state mirrored across ranks. One behavior change: a non-disaggregated engine that receives `SUBMIT_REQUEST_WITH_KV` now fails that one request with a reply instead of raising out of the loop. This was split out of the inference review. It is independent of #8255, which handles replying to a failed KV import.
