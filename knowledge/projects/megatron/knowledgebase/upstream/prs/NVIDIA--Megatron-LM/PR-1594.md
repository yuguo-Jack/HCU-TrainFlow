- claude[bot] · comment · 2026-04-10T16:44:14Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/1594#discussion_r3065597407)

File: `megatron/core/tensor_parallel/cross_entropy.py` · line 28

This fix is correct — `.float()` on an already-float32 tensor is a no-op, so the downstream in-place ops (`-=` on line 48, `torch.exp(..., out=...)` on line 68) would mutate the original input and break autograd.

Consider adding a regression test that exercises the backward pass with a float32 input to prevent this from regressing. For example, something like:

```python
def test_vocab_parallel_cross_entropy_backward_float32():
    """Regression: ensure backward works when input is already float32."""
    Utils.initialize_model_parallel(4, 2)
    vocab_parallel_logits = torch.range(0, 7).repeat(16, 4).cuda().requires_grad_(True)
    target = torch.arange(0, 32, 2).cuda()
    loss = vocab_parallel_cross_entropy(vocab_parallel_logits, target)
    # This would fail before the fix due to in-place modification of a leaf tensor
    loss.sum().backward()
    assert vocab_parallel_logits.grad is not None
    Utils.destroy_model_parallel()
```
