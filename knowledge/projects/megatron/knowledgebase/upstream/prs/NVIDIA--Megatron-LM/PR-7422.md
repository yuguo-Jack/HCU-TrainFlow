# fix: use dynamic device_type in torch.amp.custom_fwd/custom_bwd

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7422) · state: open · merged: False

## Original PR description

## Problem

In `megatron/core/tensor_parallel/layers.py`, `torch.amp.custom_fwd/custom_bwd` is created with a hardcoded `device_type="cuda"`:

```python
custom_fwd = partial(torch.amp.custom_fwd, device_type="cuda")
custom_bwd = partial(torch.amp.custom_bwd, device_type="cuda")
```

On non-CUDA accelerators (e.g. Ascend NPU), autocast uses a different `device_type` (e.g. `"npu"`). The hardcoded `"cuda"` means the custom forward/backward decorators never match the autocast context, and the AMP cast guard is effectively disabled on those backends.

## Fix

Dynamically resolve the device type from `torch.accelerator.current_accelerator()`:

```python
_CUSTOM_FWD_DEVICE_TYPE = getattr(torch.accelerator.current_accelerator(), "type", "cuda")
custom_fwd = partial(torch.amp.custom_fwd, device_type=_CUSTOM_FWD_DEVICE_TYPE)
custom_bwd = partial(torch.amp.custom_bwd, device_type=_CUSTOM_FWD_DEVICE_TYPE)
```

This follows the same pattern already used elsewhere in the codebase: `get_compute_units()` in `batch_invariant_kernels.py` already resolves the accelerator type via `getattr(torch.accelerator.current_accelerator(), "type", "cpu")`.

## Verification

- Verified on Ascend NPU that `getattr(torch.accelerator.current_accelerator(), "type", "cuda")` correctly returns `"npu"`
- The fix mirrors the approach used in the existing `batch_invariant_kernels.py`
- Not tested: full end-to-end Megatron-LM training on NPU (this changes only the import-time definition of `custom_fwd`/`custom_bwd`; the fallback paths via `torch.cuda.amp.custom_fwd` for pre-2.4.0 are unchanged)

## Related

- The project already uses `torch.accelerator.current_accelerator()` in `batch_invariant_kernels.py:206` and `:1792`
