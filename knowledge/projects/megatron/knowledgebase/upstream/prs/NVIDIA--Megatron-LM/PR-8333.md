# [fsdp, tensor_parallel, moe] fix: preserve fused weight gradient accumulation

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Fix fused local `ColumnParallelLinear` / `RowParallelLinear` weight-gradient accumulation under Megatron-FSDP v1. Two microbatches contributing 8 and 96 per weight must produce 104; the existing local backward overwrites the first contribution and produces 96.

The local backward now reads FSDP's per-parameter `overwrite_main_grad` policy through an explicit `accumulate` variable. FSDP initializes that policy immediately after buffer creation, covering pure `no_shard` without FSDP units; its existing unshard-time refresh is retained.

`TEGroupedMLP._ensure_main_grad` also preserves the policy while exposing fused-op buffers. Previously it forced the flag to `True`, undoing the initialization on paths without an unshard hook. Existing `False`/`True` values and an absent attribute are preserved.

- XFDG · comment · 2026-10-20T03:51:13Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8333#discussion_r4321288010)

One case to check before dropping it: `TEGroupedMLP._ensure_main_grad` (`megatron/core/transformer/moe/experts.py`, from #5209) sets `overwrite_main_grad = True` on the expert weights in the op-fuser pre-forward hook whenever `fuse_wgrad_accumulation` is on and the attribute exists. When the unshard hooks run, for example with `optim` and FSDP units, the pre-backward gather resets the attribute to `_reduces_grad_every_backward(param)` before the fused wgrad reads it. Without the hook-time assignment, those expert wgrads would overwrite `main_grad` instead of accumulating across microbatches.

With this PR, the same thing can already happen under pure `no_shard`. The attribute now exists from construction, `_ensure_main_grad` flips it to `True`, and no hook resets it. Keeping the per-parameter policy in `_ensure_main_grad` instead of forcing `True` would cover both cases and make the hook-time assignment redundant. `test_make_fused_impl_pre_forward_hook_exposes_fsdp_main_grad_for_fused_wgrad` currently asserts the forced value.

I found this by reading the code; I haven't run the op-fuser grouped-MLP path.
