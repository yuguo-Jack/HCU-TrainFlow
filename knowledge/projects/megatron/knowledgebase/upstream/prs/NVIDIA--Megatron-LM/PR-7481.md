# Fix masked-routing local token count before the distributed reduction

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7481) · state: closed · merged: False

## Original PR description

**Incremental review:** [Files changed](https://github.com/NVIDIA/Megatron-LM/pull/7481/files) against `main`.

`get_tokens_per_expert_and_token_count(..., with_padding_mask=True)` returns a
`local_num_tokens` that is not local.

## Why the input alias causes a local/global mix-up

```python
local_tokens_per_expert = routing_map.sum(dim=0)          # contiguous
global_tokens_per_expert = reduce_from_tensor_model_parallel_region(
    local_tokens_per_expert, reduce_group
)
if with_padding_mask:
    local_num_tokens = local_tokens_per_expert.sum() // topk   # reads the aliased buffer
```

`reduce_from_tensor_model_parallel_region` reaches `_reduce()` in
`megatron/core/tensor_parallel/mappings.py`, which does

```python
input_ = input_.contiguous()
torch.distributed.all_reduce(input_, group=group)
```

For a contiguous input this mutates the caller's storage in place, so by the time the masked
branch reads `local_tokens_per_expert` that buffer already holds the group sum.

The value is consumed by `Router.attach_and_log_load_balancing_loss()` as the pre-multiplier
on the aux loss when `calculate_per_token_loss` is enabled, so on any run where ranks hold
different numbers of valid tokens the aux-loss gradient is scaled by a group-global factor.

## Minimal reproduction (real NCCL, 2 ranks, EP=2, topk=2)

Rank 0 has 3 valid rows, rank 1 has 1:

| | rank 0 local | rank 1 local | group global |
|---|---|---|---|
| before this fix | **4** | **4** | 4 |
| after this fix | 3 | 1 | 4 |

Reproduced for topk = 1, 2 and 4. The group histogram and the `with_padding_mask=False` branch
are correct in both cases. The same aliasing is visible directly: an `all_reduce` performed on
the buffer that `routing_map.sum(dim=0)` returned changes it in place.

## The fix

Take the rank-local scalar before the collective runs, into its own storage, and reuse it in
the non-masked branch. The divide operator is preserved exactly as found (`//` on current
main): this changes which tensor is read, not the division. The `// topk` floor that landed via
#7183 (int64 for the fused aux loss) is a separate change and is deliberately left alone.

* no new collective, and collective count/order/group/op are unchanged;
* no `.item()` / `.cpu()` added to the training path and no host synchronization;
* `_reduce()` is not modified globally, so unrelated callers are unaffected;
* the histogram is not cloned; the local scalar owns its storage;
* the `with_padding_mask=False` expressions are unchanged.

## Evidence

Base: `d564dd01de4549a4884be26b1d74e169798fd877` (the alias defect is present on this commit).

Real-NCCL tests, 2 ranks, run with the file's own junit report per rank:

| test file | base | with this PR |
|---|---|---|
| `test_token_count_preservation.py` + `test_local_count_router_gradient.py` | **5 failed**, 6 passed, 3 skipped | **11 passed**, 0 failed, 3 skipped |

Every base failure is the target assertion, not a missing dependency or an invalid config:

```
AssertionError: local token count is not rank-local on rank 0: got 4, expected 3 (group-global would be 4)
AssertionError: rank 0: helper returned 10.0 for tp_cp_group, expected the rank-local valid count 7
AssertionError: rank 0: router used valid_token_count=[10.0], none of which is this rank's valid count 7
```

The skips are the zero-load-rank cases that a 2-rank plan does not contain; they are reported
as skips, not passes.

### What the added tests cover

* helper contract on a real NCCL group: uneven per-rank counts, a zero-valid-row rank, the
  unmasked branch, an all-padding input, and a storage-independence check so the local scalar
  cannot silently alias the histogram;
* the helper called the way the router calls it (`Router.tp_cp_group`) in a real TP domain;
* `Router.forward` handing the rank-local count to `attach_and_log_load_balancing_loss`;
* the aux gradient consequence, isolated: with the routing map, scores, aux formula and
  process group held identical and only the reported count changed, the aux gradient scales
  exactly linearly with it. Measured 1.428571x and 3.333333x for local/total of 7/10 and 3/10,
  which is the `group_global/local` factor this bug introduces;
* a real `MoELayer` forward + backward + optimizer step staying finite with the masked path
  active.

Comparison is exact (integer counts), not tolerance-based.

The `conftest.py` change adds a session-scoped NCCL fixture. Both new modules need a real
distributed group, and per-module init/destroy pairs race when the modules share one `torchrun`
session, killing it with `ncclRemoteError: ... remote process exited prematurely`. Owning the
group once at session scope removes that; the existing session-scoped `cleanup` fixture remains
the single owner of `destroy_process_group`.

## Performance

No speedup is claimed. The change adds one reduction over a `[num_experts]` tensor per call and
removes nothing, so about 1.0 is the expected ratio, and peak allocated/reserved memory are
unchanged. Measured as separate baseline/patch processes in balanced `A-P-P-A` / `P-A-A-P`
blocks on L20, the effect is inside the run-to-run noise of the node used (an A/A control on
identical code showed a 3-6% mean, up to 15% per block), so it is reported as
inconclusive-below-noise rather than as a result.

## Not covered

A single-process full-loss equivalence proof (which would need `finalize_model_grads`
normalization reproduced), a real CP>1 domain, and TP x CP combinations. Global/sequence
aux-loss normalization and the unmasked branch are not modified by this change.
