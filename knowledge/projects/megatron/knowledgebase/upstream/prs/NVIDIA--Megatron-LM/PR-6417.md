# Preserve greedy temperature in RL inference

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

This PR preserves an explicit `temperature=0.0` when an RL request passes through `MegatronLocal`, while retaining `1.0` as the default when temperature is unspecified. The old truth-value fallback treated both `None` and floating-point zero as missing; the fix uses an explicit `None` check so only an omitted value receives the default.

## Example failure scenario(s)

**Scenario (explicit zero temperature)**

- Request A sets `temperature=0.0` for greedy output.
- The old code treats `0.0` as missing and sends `1.0`.
- The model can sample instead of choosing the most likely token.
- The fix preserves `0.0` and keeps the request greedy.

## How was this bug discovered?

While making RL inference comparisons deterministic, the setup requested `temperature=0.0` and inspected the keyword arguments forwarded by `MegatronLocal`. It observed `1.0`, although an explicit zero should have been forwarded unchanged. The detection oracle is the mocked client's exact received temperature for both relevant cases: an omitted temperature must become `1.0`, while an explicit `0.0` must remain `0.0`.
