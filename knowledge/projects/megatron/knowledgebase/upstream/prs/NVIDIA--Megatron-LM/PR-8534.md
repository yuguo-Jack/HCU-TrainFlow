# [Dev] fix(dsa): adapt cuDNN DSA call sites to cuDNN frontend >= 1.26 defaults

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8534) · state: open · merged: False

## Original PR description

## Summary

cuDNN frontend 1.26 (NVIDIA/cudnn-frontend#316) changed two defaults that the DSA cuDNN call sites rely on. `dev` pins FE 1.29.0, so both issues are live on `dev`. Both are silent: no error, just wrong gradients or a wrong top-k selection.

### 1. Sparse indexer backward: top-k ids are treated as per-batch local

Since FE 1.26, `indexer_backward_wrapper` treats top-k ids as local to each batch unless `topk_indices_global=True`. The MCore sparse-indexer-loss path has always passed global ids (`b * S_k + local`). With BSHD and more than one sequence per micro-batch, every batch after the first lost (FE 1.29) or misplaced (FE 1.26–1.28) its sparse indexer gradient. Packed THD (one sequence per batch) is unaffected.

The wrapper is now called through `_call_sparse_indexer_backward`. It sets `topk_indices_global=True` whenever the installed wrapper accepts that parameter (or takes `**kwargs`), and keeps the old call otherwise.

### 2. Dense causal offsets: the default alignment moved from bottom-right to top-left

The dense indexer forward, dense attention-score recompute and dense indexer backward kernels gained `q_causal_offsets`. When it is not given, FE <= 1.25 aligns the causal mask bottom-right (`seqlen_k * ratio - seqlen_q`), and FE >= 1.26 aligns it top-left (offset 0).

MCore's BSHD call sites pass no offsets and were written against the bottom-right contract. The affected caller is the single-sequence packed THD segment scorer (`IndexerScoringPlan.PACKED_SINGLE_SEGMENTS`). It crops each query chunk's key prefix so that bottom-right masking gives each row its absolute causal length. This happens for the CP > 1 zigzag segments and for row-chunked scoring. On a top-left frontend the same call masks columns that are inside the row's causal length, so top-k silently selects from fewer keys. The general packed THD path (`PACKED_THD_GENERAL`) already passes explicit offsets and is unaffected.

When the installed frontend is 1.26 or newer and the offset is non-zero, the bottom-right offset is now passed explicitly. Older frontends and square (zero-offset) calls keep their exact call and kernel compile key. A top-left frontend whose wrapper lacks `q_causal_offsets` fails closed.

### Tests

- `dsa_cudnn_fe_fakes.py` adds CPU fakes of both frontend generations: `BottomRightDefaultDSA` for FE <= 1.25 and `Fe131DSA`.
- `test_dsa_cudnn_fe_compat.py` (18 tests) covers:
  - frontend version parsing;
  - the 1.25/1.26 offset gate;
  - the fail-closed case;
  - the cropped segment scorer selecting identical top-k under either default.
- In `test_dsa_native_parity.py`, the fake `indexer_backward_wrapper` used by the five sparse-loss tests now requires `topk_indices_global` and asserts it is `True`, so these tests fail without the fix. The batched-KV test is the BSHD micro-batch > 1 case.
- While a fake namespace is installed, the native parity fakes report frontend 1.21, so the offset gate does not treat them as a top-left frontend. The real namespace still reports the installed version, so the real-kernel tests still exercise the top-left path.

  - **Sparse indexer backward, BSHD micro-batch 2.** `_run_sparse_indexer_backward` gets global ids. The reference is the same rows run as two b=1 calls with local ids, scaled by 1/b for the row-mean loss.
    - `dev`: batch 0 matches, but batch 1 gets all-zero dQ/dW/dK (relative error 1.0).
    - This branch: both batches match (dQ/dW exact; dK relative error ≤ 2e-5).
  - **Single-sequence packed segment scorer** (`_indexer_topk_single_packed_cp_segments`, 512 local rows, top-k 128). It is compared against an fp32 torch top-k over each row's absolute causal keys.

    | Layout | `dev` recall of reference top-k (mean / min) | This branch |

    | CP=2, rank 1 | 0.331 / 0.141 | 1.000 / 1.000 |

    On `dev`, the CP=2 rows still get a full set of causal keys, but tens of thousands of the selected keys score below the reference k-th score: top-k ran over a top-left-masked key range. CP=1 has a zero offset and is unaffected, as expected.
