# Fix ShortcutMoEBlock registration order for MFSDP prefetch

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8505) · state: open · merged: False

## Original PR description

## What does this PR do?

Fix `ShortcutMoEBlock`'s module registration order for callers that wrap normalization modules separately with MFSDP v2. Static prefetch follows registration order, but the shortcut path executes these modules in a different order:

| | Order |
| --- | --- |
| Current registration | MoE norm → routed experts → shortcut norm → post norm |
| Actual execution | Shortcut norm → routed experts → MoE norm → post norm |

The mismatch can prefetch weights again after their module has finished backward, leaving an unused gathered copy alive across the optimizer update.

Register the shortcut norm before the compute/MoE branches, and re-register the MoE pre-MLP norm after its MLP subtree. That latter norm feeds shared experts after routed experts have executed. Module names, parameter ownership, and forward computation are unchanged.

Keep this registration fix separate from #8312. This replaces closed #7809, whose deleted `pull-request/7952` base prevents GitHub from reopening it. It is based directly on upstream `main` at `ed9c2c8c1cf4a5438922ae8d215181e7c8b9e0fe`, with no dependency on #8312 or the older split-residual PR stack. The regression explicitly selects the shortcut block and norms, so it does not require changes to the adapter's default wrapping.

## Validation

On two RTX A6000 GPUs, **25 tests passed on each rank**, with no skips or failures:

- Six EP=2 training cases, each comparing five optimizer steps against an EP=1 reference at the existing tolerances: ordinary MoE, shortcut blocks, separate norm wrappers, overlap, norm recomputation, and their combination.
- Every training case checks that backward leaves no unused gathered weights.
- All 19 existing shortcut-block tests, including overlap output/gradient comparisons, inference, and wide-residual behavior. The fake MoE in the overlap test now exposes the pre-MLP norm present on real MoE layers.
- With the same regression test on unchanged `main`, the separate-norm case fails the unused-gathered-weights assertion on both ranks. With this fix it passes.

Black, isort, Pylint, and Ruff pass on the final three-file diff. Advisory Mypy reports the same three findings as the upstream control: two existing optional-value diagnostics and a missing Transformer Engine typing stub.

No new full-model numerical-equivalence or latency result is claimed. This fixes the norm/expert ordering tested here; it does not establish that arbitrary module selections match execution order.
