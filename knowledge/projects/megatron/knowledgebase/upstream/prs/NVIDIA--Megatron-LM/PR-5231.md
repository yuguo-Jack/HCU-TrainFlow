- claude[bot] · comment · 2026-06-11T18:02:16Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/5231#discussion_r3398064652)

File: `megatron/core/models/common/language_module/language_module.py` · line 103

Bug: Replacing `vocab_parallel_cross_entropy` with standard `torch.nn.functional.cross_entropy` breaks tensor-parallel correctness. When TP > 1 and `cross_entropy_loss_fusion` is False, the vocabulary is sharded across TP ranks — `vocab_parallel_cross_entropy` handles the cross-rank reduction needed for correct loss computation, while `F.cross_entropy` assumes each rank holds the full vocabulary dimension.

- claude[bot] · comment · 2026-06-11T18:02:20Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/5231#discussion_r3398065089)

File: `megatron/core/transformer/moe/moe_utils.py` · line 914

Bug: This hardcodes `bfloat16` and ignores the `router_dtype` parameter. The backward path still uses `ctx.router_dtype`, creating a forward/backward dtype mismatch. This should use `router_dtype` to stay consistent:

File: `megatron/core/transformer/moe/moe_utils.py` · line 413

Bug: This assumes every token is routed to the same number of experts by reading only `[0]`. If any token is dropped or routes to fewer experts, `topk` will be wrong and the subsequent `reshape(num_tokens, topk)` will fail or produce incorrect results.
