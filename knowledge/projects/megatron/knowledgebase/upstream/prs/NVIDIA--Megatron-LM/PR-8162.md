# Keep prompt log-probs raw under processed_logprobs

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8162) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Prompt log-probs are now computed from the raw distribution in both `logprobs_mode`s. Under `processed_logprobs`, temperature and top-k/top-p apply only to engine-sampled rows.

**Why:** `processed_logprobs` (#5419) exists so RL can recover the behavior policy's probability of each sampled token, for importance-sampling and mismatch corrections. Prompt tokens were never sampled from that distribution. The prefill path still sent every prompt row through the request's sampling transform, which caused two problems:
- prompt scores depended on the request's sampling settings, so they had no stable meaning for scoring workloads like lm-eval loglikelihood;
- any prompt token outside the request's top-k/top-p nucleus got `-inf`. The code already noted this ("prompt rows may keep -inf").

Multi-turn RL doesn't need processed prompt rows either. NeMo RL stitches together each turn's *generated* logprobs and always sets `skip_prompt_log_probs=True`. A later turn's prompt rows would be scored under the current weights, not the ones that sampled those tokens.

**Changes**
- `DynamicInferenceContext.calculate_log_probs_tensors`, prefill branch:
  - `log_softmax` for all rows;
  - processed log-probs only at each request's final (sampled) row;
  - the `-inf` → tempered fallback is applied only to those rows.
  - A partial prefill chunk's final row scores its next prompt token, so it stays raw too.
- Top-N log-probs reuse the same tensor, so prompt top-N is raw as well.
- Decode and only-last-token rows are all sampled rows and are unchanged. Processed mode still rejects speculative decoding.
- Updated docs, the `InferenceConfig.logprobs_mode` docstring, and the CLI help.

**Behavior change:** only for `logprobs_mode='processed_logprobs'` with `skip_prompt_log_probs=False`. Raw mode is unchanged.

**Tests**
- `test_calculate_and_store_log_probs[processed_logprobs]` now expects raw prompt rows and processed sampled rows.
- New `test_processed_log_probs_keep_partial_chunk_row_raw` covers the partial-chunk row.
- These are GPU tests and have not been run yet. A CPU stub check of the new prefill branch passes.

```bash
uv run python -m torch.distributed.run --nproc-per-node 1 -m pytest -q \
  tests/unit_tests/inference/contexts/test_dynamic_context.py \
  -k "calculate_and_store_log_probs or keep_partial_chunk_row_raw"
```
