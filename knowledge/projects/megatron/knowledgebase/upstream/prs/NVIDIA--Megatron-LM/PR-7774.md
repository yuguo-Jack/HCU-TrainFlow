# What does this PR do?
Allow NaN/Inf and other result checks with full-iteration CUDA graphs.

Host-side validation cannot run during CUDA graph capture. Record CUDA tensor snapshots at each validation site, then run the checks after replay and before the training loop decides whether to rerun or update parameters. Clone the replayed snapshots so subsequent replays cannot overwrite results retained for fault attribution.

Remove the requirement to disable loss/gradient checks and update the full-iteration graph documentation. The regression tests are kept in one file.

IMO I think validation_calls should not leak into full CG? full CG should only orchestrate the deferral of the validation calls through the rerun_state_machine object.

What if we were to do:
```
@contextmanager
def capture_deferred_validations(self, key: str): ...   # sets capture mode, allocates self._deferred[key]
def run_deferred_validations(self, key: str): ...       # clones each snapshot and runs the normal path
def clear_deferred_validations(self, key: str): ...
```

and full CG could call like:
```
with torch.cuda.graph(...), rsm.capture_deferred_validations(training_str):
    result = self.forward_backward_func(*args, **kwargs)
...
cuda_graph.replay()
rsm.run_deferred_validations(training_str)
...
# reset():
rsm.clear_deferred_validations(stage)
```

that way full CG doesnt touch resum_state_machine internals and keeps the code cleaner
