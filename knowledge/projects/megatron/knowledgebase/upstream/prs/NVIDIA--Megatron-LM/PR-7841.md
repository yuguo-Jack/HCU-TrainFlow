# What does this PR do?
Fuses two standalone inference-only kernels on the GDP/MoE decode path into previous kernels, removing launches per decode step while maintaining byte-equivalence.

**GDP decode** (`megatron/core/ssm/ops/gdp/fused_recurrent.py`): currently padding requests (`state_indices == -1`) are zeroed by an `o.masked_fill_` after the recurrent kernel, this `masked_fill_` op creates a separate kernel. 
<img width="1857" height="121" alt="image" src="https://github.com/user-attachments/assets/53ab8b4d-cd3e-4f0d-82ef-4108163a622b" />
After the change, the previous kernel directly stores 0.0 for those rows, using a select rather than a multiply so stale NaN/Inf in padded inputs still produce zeros. The separate `masked_fill_` is removed.

**vLLM MoE** (`megatron/core/inference/moe/vllm_fused_moe.py`, `megatron/core/inference/moe/permute.py`): currently `_moe_align_block_size_cuda_graphable` allocates the local-expert counters with `torch.zeros`, this call also creates a separate fill kernel. 
<img width="1935" height="156" alt="image" src="https://github.com/user-attachments/assets/e4c47c74-ff1d-4eb7-8818-ec25aad0880f" />

After the change, `_init_sorted_ids_kernel` zeroes the counters together with `sorted_token_ids` and `expert_ids`, and `compute_local_tokens_per_expert` accepts that buffer through a new optional `zeroed_counts` argument. Its default behavior is unchanged.

**Testing**
- Unit tests, added to the existing test files:
  - `test_gdp_dynamic_inference.py`: padding rows store +0.0 bytes even with NaN/Inf inputs (fp32/fp16/bf16, head-wise and vector beta); real rows match an unpadded batch byte for byte; the padding select follows slot updates across CUDA graph replays; varlen slot indexing is still rejected.
  - `test_moe_permute.py`: a caller-zeroed counter buffer is filled in place, and invalid buffers are rejected.
  - `test_vllm_fused_moe.py`: every CUDA graph replay of the alignment starts counting from zero.
  - The related unit test classes pass on GB200 (806 tests).
- End-to-end inference: N4 Nano checkpoint on 4x GB200 (EP=4, async scheduling, decode CUDA graphs, vLLM MoE backend). In a same-process A/B against the base implementations (base -> branch -> branch -> base, CUDA graphs recaptured per variant), raw logits at all 129 forward steps, generated tokens, and prompt and generated logprobs are byte-identical on all ranks. Median request time is 1.032 s (base) vs 0.998 s (this PR) for one 128-token request, about 3.4% faster for this workload.
