# Fix compiled packed sequence boundary lookup

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7705) · state: closed · merged: False

## Original PR description

[Scoped diff of this PR's own changes](https://github.com/NVIDIA/Megatron-LM/compare/FDecaYed:codex/dsv4-cp-main-20260917...Connor-XY:codex/fix-compiled-packed-boundaries). The full diff also shows #7469's commits until it merges.

Depends on #7469 by @FDecaYed; please review #7469 first. The updated parent's aligned SBHD reference coverage is retained.

Compiled packed-boundary lookup can assign compression rows to the wrong document. Under `torch.compile`, PyTorch `2.13.0a0+8145d630e8.nv26.06` ignores the storage offset of a sliced boundaries tensor in `torch.bucketize`. As a result, `bucketize(rows, prefix[1:], right=True)` is computed against `prefix[0:]` and every row lands one document to the right. With cumulative lengths `[0,128,256]` at ratio 4, first-document group IDs started at -32 instead of 0, whether torch deterministic algorithms were on or off. These invalid document positions can reach RoPE indexing.

The three compiled call sites in `packed_layout.py` now bucketize the complete cumulative prefix and subtract one. The eager `build_seq_lens` uses the same form for consistency. Every prefix starts at zero and query rows are nonnegative, so this keeps `right=True` semantics, including repeated boundaries for empty documents. Existing clamping and validity masks are unchanged. The code comment describes the failure and names the affected build, so the workaround can be revisited.

Tests: twelve eager-versus-compiled metadata regressions. They cover ratios 4 and 128, empty and crossing document boundaries, both CP local starts, and torch deterministic algorithms off and on. An independent integer oracle checks group IDs, positions and gathered rows. The compiler is reset for each case so these layouts do not use up Dynamo's recompile limit for later tests. The tests live in the GB200-marked packed-attention module; moving them to a generic CUDA lane is a separate follow-up.

Validation on GB300 (four ranks, normal repository conftest, PyTorch 2.13.0a0+8145d630e8.nv26.06):
- `test_dsv4_packed_cp.py`: 22 passed on each rank (12 metadata cases and 10 CP2/CP4 parity configurations).
- Control: with #7469's unpatched `packed_layout.py`, all six original metadata cases fail.
- A standalone probe reproduces the compiler behavior. Compiled `bucketize(rows, cu[1:], right=True)` differs from eager whether `cu` is a graph input, a `.contiguous()` slice or an in-graph cumsum, with deterministic algorithms on or off. `bucketize(rows, cu, right=True) - 1` matches eager in every case.
- The boundary correction was also part of an earlier 64-GPU GB300 packed-CP2 fresh/restart integration run.
- Black, isort, pylint, ruff and the kernel determinism coverage gate pass.
