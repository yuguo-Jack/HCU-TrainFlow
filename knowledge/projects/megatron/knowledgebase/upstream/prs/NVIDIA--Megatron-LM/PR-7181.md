# What does this PR do?
This is the fourth of four stacked PRs that introduces a simplified version of DSA. These stacked PRs split PR #[6869](https://github.com/NVIDIA/Megatron-LM/pull/6869).

This PR wires the simplified DSA indexer into the main training loop. There are four main features included:

**Freezing:** `dsa_train_indexer_only` and `dsa_train_main_only` freeze either the non-indexer model parameters or the indexer model parameters. This is necessary for each stage of long-context training with DSA.

**Resetting.** A checkpoint trained without an indexer, or with a different one, needs the indexer reinitialized while the backbone continues from where it stopped. Two initializations are available. Random draws from a seed derived to be tensor-parallel-invariant and data-parallel-aware, so every TP rank of a shard agrees and different DP replicas do not diverge; the reset then broadcasts indexer parameters only. The alternative seeds the indexer from the main Q projection, gathering the fused QKV across TP, with optional rescaling.

**Optimizer state after a reset.**  Clears the indexer's moments *and* resets only its parameter groups' clocks, leaving the backbone's moments and step count untouched. This resets just the indexer rather than the whole run.

**Indexer logging.** Indexer and backbone gradients differ enough in scale that one combined grad-norm hides what either is doing. `calc_dsa_split_grad_norms` and `calc_dsa_split_grad_num_zeros` report them separately, and the LR logging distinguishes the two parameter groups.

### Code review

Found 4 issues:

1. `validate_args()` accesses `args.use_legacy_models`, but the standard parser no longer defines that argument. Any launch with `--overlap-param-gather` reaches this line and raises `AttributeError` before validation finishes. (historical git context)

https://github.com/NVIDIA/Megatron-LM/blob/227a1de8ecd8deb7878ad8ae107afb7bb73f4f66/megatron/training/arguments.py#L1048-L1057

2. A dense checkpoint records `experimental_attention_variant=None`, while a DSA reset run sets it to `"dsa"`. This unconditional compatibility check asserts that the two values match before `_reset_dsa_indexer_after_load()` runs. As a result, `--dsa-reset-indexer-on-load` cannot perform the intended dense-to-DSA conversion. `--no-load-optim` does not skip this check. (bug)

https://github.com/NVIDIA/Megatron-LM/blob/227a1de8ecd8deb7878ad8ae107afb7bb73f4f66/megatron/training/checkpointing.py#L203-L218
https://github.com/NVIDIA/Megatron-LM/blob/227a1de8ecd8deb7878ad8ae107afb7bb73f4f66/megatron/training/training.py#L3569-L3576

3. `training_log()` already runs at line 5743, then runs again for the same iteration at line 5806. The first call updates and clears loss counters and resets interval timers. The second call double-counts the iteration and losses, then repeats collective and parameter-norm work using reset state. Should the second block be removed? (bug)

https://github.com/NVIDIA/Megatron-LM/blob/227a1de8ecd8deb7878ad8ae107afb7bb73f4f66/megatron/training/training.py#L5773-L5825

4. The first logging path calculates DSA-only split gradient statistics for every model. On a normal non-DSA run, the default gradient clipping produces `grad_norm` and the default logging interval is one, so every step scans all gradients and launches extra distributed reductions. I think this should be gated on the presence of a DSA indexer parameter group? (bug)

https://github.com/NVIDIA/Megatron-LM/blob/227a1de8ecd8deb7878ad8ae107afb7bb73f4f66/megatron/training/training.py#L5715-L5733
