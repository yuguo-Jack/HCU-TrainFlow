# Admit SM103 to the batch-invariant TE device-metadata grouped GEMM

# What does this PR do?

Admits SM103 (B300) to the batch-invariant TE device-metadata grouped GEMM, with the same exact cuBLASLt 13.5.1 requirement as SM100.

`te_supports_batch_invariant_grouped_gemm` accepted only `capability == (10, 0)` with cuBLASLt 13.5.1, so `moe_use_grouped_tensor=True` raised on B300 even with the same cuBLASLt. The gate now checks a tuple of validated `(SM capability, cuBLASLt version)` pairs, in the style of `_SYRK_VALIDATED_SMS`, and adds `((10, 3), 130501)`. The cuBLASLt version stays an exact match, and other versions are still rejected. The `RuntimeError` text, both skip messages and the two sentences in `docs/mcore-inference-user-guide.md` now say SM100 or SM103. A new unit test checks the gate on six (SM, cuBLASLt) combinations.

## Testing

B300 (SM103), cuBLASLt 13.5.1 loaded by TE (pip `nvidia-cublas` 13.5.1.27), Transformer Engine 2.20.2+44f31bbe, PyTorch 2.14.1+cu130, Triton 3.8.0:

| | main | this PR |
|---|---|---|
| `test_device_metadata_batch_invariant_training` (bf16 and MXFP8, 5 shapes) | 10 skipped (gate closed) | 10 passed |
| new `test_te_device_metadata_gemm_requires_validated_pair` | – | 6 passed |
| `test_te_native_device_metadata_workspace`, `test_enable_disable_roundtrip`, `test_config_batch_invariant_device_metadata_gemm` | – | 5 passed |

As an extra check outside the test suite, I also tested co-batch invariance on B300. A target expert carried M ∈ {1, 7, 64, 256, 1024, 4096} rows; the other three experts carried four different loads, and each batch was replayed twice. Its output rows, input-gradient rows and weight gradient were bit-identical in every case:
- bf16: 24/24 (k, n ∈ {(2048, 1536), (2688, 1856)}, splits aligned to 32 rows and unaligned)
- MXFP8: 12/12 (groups padded to 128 rows, which TE's grouped MXFP8 quantization requires)

Not covered:
- `test_batch_invariant_moe_matches_training` needs expert parallelism (2+ GPUs); this was a single-GPU run.
- Only cuBLASLt 13.5.1 was tested on SM103. The cuBLASLt 13.6 that ships with the CUDA 13.3 toolkit stays rejected.

black 26.3.0 and isort 5.13.2 report no changes; pylint and ruff were not run.
