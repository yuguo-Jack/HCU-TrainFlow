# What does this PR do?
Support THD and sequence packing for NCCL EP by
- Find the max per-EP rank token through either config (THD) or read during runtime (BSHD)
- Mark the masked/padded token's destination to -1 and zero their probs so NCCL EP will not route them

NCCL EP natually support uneven num tokens across EP rank so there is no need to allreduce and pad to max.

## Strict review: [NCCL EP] Support THD and sequence packing for NCCL EP

The PR has the NCCL EP manager size its buffers from a config bound for packed (THD) input: `max_seqlen_per_dp_cp_rank`, or the new `ModelParallelConfig.seq_length`. It also routes padded rows to `-1` with zero weight, and threads `packed_seq_params` down to the flex dispatcher.

The main eager path works as intended. One supported schedule never receives `packed_seq_params`, and the bound can still differ between ranks. Both affect correctness across EP ranks.

**Findings: CRITICAL 1, IMPORTANT 1, SUGGESTION 1.** Each inline comment has the full failure case, the fix, what must keep working, and acceptance checks.

1. **[CRITICAL Correctness]** `packed_seq_params` never reaches `preprocess` on the EP A2A-overlap path ([moe_layer.py#L545](https://github.com/NVIDIA/Megatron-LM/blob/d7494d69008302f7f2cab0d3592c20d11efa0856/megatron/core/transformer/moe/moe_layer.py#L545)).
   - **Where:** the eager `overlap_moe_expert_parallel_comm` path in [gpt/fine_grained_callables.py#L138-L140](https://github.com/NVIDIA/Megatron-LM/blob/d7494d69008302f7f2cab0d3592c20d11efa0856/megatron/core/models/gpt/fine_grained_callables.py#L138-L140) still calls `preprocess` with four positional arguments. The PR updated both CUDA-graph replay overlap branches in `transformer_layer.py`, but not this one.
   - **Effect:** with ncclep and THD on this path, `_is_thd` stays `False`. The bound comes from each rank's own first microbatch, so EP ranks bootstrap with different arguments. Larger microbatches later raise a `RuntimeError` telling the user to raise `seq_length`, which has no effect on this path.
2. **[IMPORTANT Correctness]** `_dispatch_token_bound` mixes in a per-rank value ([token_dispatcher.py#L2000](https://github.com/NVIDIA/Megatron-LM/blob/d7494d69008302f7f2cab0d3592c20d11efa0856/megatron/core/transformer/moe/token_dispatcher.py#L2000)).
   - **What:** `max(bound, self.num_local_tokens)` uses this rank's own count. `ensure_nccl_ep_bootstrapped` requires identical arguments on every EP rank ([fused_a2a.py#L901-L903](https://github.com/NVIDIA/Megatron-LM/blob/d7494d69008302f7f2cab0d3592c20d11efa0856/megatron/core/transformer/moe/fused_a2a.py#L901-L903)).
   - **Effect:** if the configured bound is too small on only some ranks, those ranks bootstrap with different values instead of all failing with one clear error.
3. **[SUGGESTION Other]** The new over-bound `RuntimeError` gives a fix that only applies to THD ([token_dispatcher.py#L2089-L2094](https://github.com/NVIDIA/Megatron-LM/blob/d7494d69008302f7f2cab0d3592c20d11efa0856/megatron/core/transformer/moe/token_dispatcher.py#L2089-L2094)). For BSHD input, and on the overlap path in finding 1, raising `seq_length` changes nothing.
