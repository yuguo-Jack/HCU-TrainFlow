# Warn when layer placement and MTP fall back to the global pipeline state

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8754) · state: closed · merged: False

## Original PR description

Depends on #6303 (which contains #6293), #8017 (which contains #6259), #8028, #8033, #8057 (which contains #8049) and #8726. Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/cc82ea6264...yx/pstate-c7-layout-vpp-fallbacks).
- The new warnings use #6293's `warn_global_process_group_fallback`. The tests use #8049's `ProcessGroupFallbackWarning` and #8017's `forbid_global_process_groups`.
- This PR edits test files that others add: `test_pipeline_parallel_layer_layout.py` (#8033), `test_combined_1f1b_process_groups.py` (#8028), `test_transformer_process_groups.py` (#8057) and `test_modelopt_spec_pipeline_stage.py` (#8726).
- In four test files the `GPTModel` calls replace the `use_mpu_process_groups()` argument that #6303 adds, and two of these files use #6303's module-level `ProcessGroupCollection` import.
- The merges of #8033 and #8057 regenerate the process-group allowlist, whose total conflicted.

Land this after #8742, which passes the virtual-pipeline size from `get_batch` in `pretrain_gpt.py` and `pretrain_hybrid.py`. Until then, training an MTP model without a custom layout warns from `get_batch`.

**Why.** `get_num_layers_to_build`, `get_transformer_layer_offset` and the `PipelineParallelLayerLayout` methods `get_num_layers_to_build` and `get_layer_offset` decide which layers a pipeline stage builds. A caller that omitted `pp_rank` silently got the rank from `parallel_state`. `mtp_on_this_rank` read the global virtual pipeline size when it got no `vp_size`. `GPTModel` and `HybridModel` passed `config.virtual_pipeline_model_parallel_size`, which is `None` without a virtual pipeline, so every MTP model built without one read `parallel_state`. A model on its own pipeline grid could build or place another stage's layers with no sign of it.

**What.**
- With pipeline parallelism, an omitted `pp_rank` emits a `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23). The rank still comes from `parallel_state.get_pipeline_model_parallel_rank`. A rank forced with `set_pipeline_model_parallel_rank`, or a fake-initialized grid, therefore selects the same stage as before.
- `get_num_layers_to_build` resolves the rank once, before it consults a custom layout, so the warning names the function the caller called.
- With a single pipeline stage every rank is stage 0, so these functions use rank 0 and read nothing.
- `mtp_on_this_rank` warns when it falls back to the global virtual pipeline size: no `vp_size`, no layout, and `ignore_virtual=False`.
- These callers now pass `config.virtual_pipeline_model_parallel_size or 1`, where 1 means no virtual pipeline: `GPTModel`, `HybridModel`, `is_dataset_built_on_rank` in `megatron/training/datasets/providers.py`, which `pretrain_gpt.py` and `pretrain_hybrid.py` share, and `get_batch` in `megatron/elastification/pretrain_hybrid_flex.py`. #8742 does the same for `get_batch` in the GPT and hybrid scripts.
- `is_dataset_built_on_rank_explicit` takes an optional `vp_size` and forwards it to `mtp_on_this_rank`. Omitting it keeps the global fallback, with the warning.
- Tests that hold the pipeline rank or a collection pass the rank instead of forcing it with `set_pipeline_model_parallel_rank`. This also stops two tests from leaving a forced rank in the global state.
- The four `pp_rank` reads still count as accessor reads in the process-group checker, so the allowlist does not change. They cannot go through `resolve_process_groups`, which would ignore forced ranks and the fake grids that the checkpoint converter uses.

**Tests.**
- `test_pipeline_parallel_layer_layout.py`:
  - an omitted rank warns and selects the same stage, with a mocked rank and on a real PP=2 grid;
  - a single stage reads no global state;
  - an explicit rank selects its stage with global reads forbidden.
- `test_transformer_process_groups.py`: `mtp_on_this_rank` without `vp_size` warns and matches the global size at PP=2, VPP=2. `GPTModel` places MTP by its config's virtual pipeline size without a global read.
- `test_modelopt_spec_pipeline_stage.py` expects the warning for an omitted rank. `test_hybrid_model.py` expects a virtual pipeline size of 1 for a model without a virtual pipeline.
- `test_dataset_providers.py` and `test_get_batch.py` give their mocked configs a virtual pipeline size. `test_dataset_providers.py` expects the shared dataset predicate to forward it, with 1 for no virtual pipeline.

On 4 GPUs against its base, the 15 test files this PR touches show no regressions. `test_pipeline_parallel_layer_layout.py` passes 15 tests here vs 8 on the base, 9 of them new or renamed. `test_transformer_process_groups.py` passes 26 vs 24, and its 2 new tests pass. `test_dataset_providers.py` passes 103 on both sides. `test_combined_1f1b_process_groups.py`, `test_get_batch.py`, `test_dynamic_context.py`, `test_dsa_gpt_mamba_equivalence.py`, `test_hybrid_model.py`, `test_pipeline_layout.py` and `test_modelopt_spec_pipeline_stage.py` pass the same 2, 170, 166, 14, 84, 8 and 13 tests on both sides. In `test_gpt_hybrid_interop.py`, `test_layer_wise_optimizer.py`, `test_optimizer.py`, `test_transformer_block.py` and `test_transformer_layer.py`, 134 tests fail on both sides because they need 8 ranks. In the integration run, which merges all #6307 PRs onto main, this PR's test files show no regressions against main. There, these five files have no failures on 8 GPUs (two nodes). The edited test in `test_get_batch.py` needs 8 GPUs, and both runs ran that file on 4, so it was skipped. End-to-end training smokes on the same merge, MTP included, give bit-identical losses to main on 4 GPUs.

Before the sync, the branch ran on 4 CPU gloo ranks, one file at a time, with no regressions. `test_pipeline_parallel_layer_layout.py` went from 8 passing tests to 15, and one of the two new MTP tests needs CUDA. The edited `dist_checkpointing` and DSA test bodies fail on CUDA there before they reach the changed lines, so only the GPU runs cover them.

**Compatibility.**
- On a grid initialized from the model config, stage selection, layer offsets and MTP placement are unchanged. Checkpoints are unaffected.
- A single-stage config or layout now uses rank 0 without reading the global rank. Results differ only on an inconsistent setup: config PP=1 on a global grid with PP>1, together with `account_for_embedding_in_pipeline_split` or `account_for_loss_in_pipeline_split`.
- An explicit `vp_size=None` still means "use the global size", now with a warning, so external callers keep working. That is why the call sites pass `... or 1`. A sentinel default would let them pass the raw config value instead.
- Callers that omit `pp_rank` under PP>1 and hold no collection now warn. These include the checkpoint converter's spec builders, which already warn through `GPTModel`'s fallback, and the deprecated `TransformerLayer._get_layer_offset(config)`.
- Public spec builders that forward `pp_rank` do not document the deprecation yet: `get_gpt_modelopt_spec`, `get_gpt_decoder_block_spec`, `get_gpt_heterogeneous_layer_spec` and `get_transformer_block_with_experimental_attention_variant_spec`. A caller that omits it gets up to four warnings, which name the inner helpers. Each warning points at the caller's file and line.
- `test_explicit_pp_rank_selects_the_stage` installs its own accessor stub before `forbid_global_process_groups`, which then rebinds by that stub's identity. A failure there could name the wrong accessor, but the test still catches every read.
- #8772 builds on this PR and edits `mtp_on_this_rank` next to the new warning.
- Needs `determinism-exempt` only while the PRs below this one are unlanded. CI diffs against main, and the base carries registered kernel files. This PR's own diff passes the coverage check.
