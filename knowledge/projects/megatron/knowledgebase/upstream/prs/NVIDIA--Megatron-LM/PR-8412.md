### [P2] Wait for coordinator cleanup on the normal shutdown path

Making the coordinator a daemon in [dynamic_engine.py](https://github.com/NVIDIA/Megatron-LM/blob/b868fa9116e99ce0049bc40ff3c82d864af849c9/megatron/core/inference/engines/dynamic_engine.py#L1374-L1407) introduces a race with normal interpreter exit. The coordinator example sends `SHUTDOWN`, closes its client, and returns without joining the coordinator ([teardown](https://github.com/NVIDIA/Megatron-LM/blob/b868fa9116e99ce0049bc40ff3c82d864af849c9/examples/inference/advanced/gpt_dynamic_inference_with_coordinator.py#L211-L224)). Python can now terminate that daemon before its cleanup finishes. Previously, normal interpreter exit waited for the non-daemon child.

A concrete affected case is running that example with `--coordinator-schedule-output-path` and at least one request: scheduling records are written only in [DataParallelInferenceCoordinator.stop()](https://github.com/NVIDIA/Megatron-LM/blob/b868fa9116e99ce0049bc40ff3c82d864af849c9/megatron/core/inference/data_parallel_inference_coordinator/coordinator.py#L769-L791). If the parent exits while this write is pending or underway, the requested JSON can be missing or truncated despite successful inference.

**Correction:** retain daemon mode as the abandoned-process fallback, but wait for coordinator completion on this explicit graceful-shutdown path. In the example's rank-zero teardown, immediately after `client.stop()`, add a bounded join and report unsuccessful cleanup rather than silently returning success:

```python
        coordinator = getattr(engine, "inference_coordinator_process", None)
        if coordinator is not None:
            await asyncio.to_thread(coordinator.join, 10.0)
            if coordinator.is_alive():
                raise RuntimeError("Timed out waiting for inference coordinator shutdown")
            if coordinator.exitcode != 0:
                raise RuntimeError(
                    f"Inference coordinator exited with code {coordinator.exitcode}"
                )
```

This belongs after the coordinator shutdown signal, not in `DynamicInferenceEngine.shutdown()`: the caller sends that signal only after the engine reaches `STOPPED`.

**Preservation and acceptance — proposed, not executed:** use a spawned test coordinator with deliberately delayed `stop()` cleanup and a nonempty schedule. After normal teardown, assert that the child exited with code zero and the complete JSON contains the recorded request. Also check that an unresponsive coordinator produces a bounded shutdown failure, an externally managed coordinator with no local process handle is not joined, and a parent abandoning inference can still exit without indefinitely waiting for its daemon child. The suggested code requires author verification.

### Regression coverage: protect the returning RL shutdown contract

No tests accompany removal of the hard exit from [rl_inference_interface_shutdown()](https://github.com/NVIDIA/Megatron-LM/blob/b868fa9116e99ce0049bc40ff3c82d864af849c9/megatron/rl/rl_utils.py#L3306-L3323). The inspected RL tests do not exercise this helper. The existing coordinator lifecycle tests also use an independently spawned coordinator with `launch_inference_coordinator=False` ([example](https://github.com/NVIDIA/Megatron-LM/blob/b868fa9116e99ce0049bc40ff3c82d864af849c9/tests/unit_tests/inference/test_data_parallel_inference_coordinator.py#L836-L847)), so they do not protect the new process-lifetime behavior.

**Correction:** add a regression in [test_rl_utils.py](https://github.com/NVIDIA/Megatron-LM/blob/b868fa9116e99ce0049bc40ff3c82d864af849c9/tests/unit_tests/rl/test_rl_utils.py) asserting that teardown returns, closes rollout generation before killing the interface, clears all three globals, and remains safe when called again. A small proposed test using its existing imports is:

```python
def test_rl_shutdown_returns_and_clears_resources(monkeypatch):
    events = []

    async def close_rollouts():
        events.append("close")

    async def kill_interface():
        events.append("kill")

    loop = asyncio.new_event_loop()
    monkeypatch.setattr(rl_utils, "get_asyncio_loop", lambda: loop)
    monkeypatch.setattr(
        rl_utils, "_ROLLOUT_GENERATOR", SimpleNamespace(aclose=close_rollouts)
    )
    monkeypatch.setattr(rl_utils, "_ROLLOUT_PIPELINE", object())
    monkeypatch.setattr(
        rl_utils, "_INFERENCE_INTERFACE", SimpleNamespace(kill=kill_interface)
    )
    monkeypatch.setattr(
        rl_utils.os, "_exit", lambda code: pytest.fail("shutdown must return")
    )
    try:
        assert rl_utils.rl_inference_interface_shutdown() is None
        assert rl_utils._ROLLOUT_GENERATOR is None
        assert rl_utils._ROLLOUT_PIPELINE is None
        assert rl_utils._INFERENCE_INTERFACE is None
        assert rl_utils.rl_inference_interface_shutdown() is None
        assert events == ["close", "kill"]
    finally:
        loop.close()
```

**Acceptance:** this test should pass on the proposed implementation and fail if the removed `os._exit(0)` is restored. The second call must neither terminate the caller nor close either resource again. Pair it with the subprocess-lifetime regression above; a mocked helper test alone cannot establish that interpreter shutdown completes.
