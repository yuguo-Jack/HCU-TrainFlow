# Check parameter hashes across the model's own data-parallel groups

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8047) · state: open · merged: False

## Original PR description

**Why.** `check_param_hashes_across_dp_replicas` always all-gathers over the global data-parallel groups. A model on its own grid then compares its hashes with ranks that hold other shards or another model: `--check-weight-hash-across-dp-replicas-interval` reports a mismatch for replicas that agree, or hangs when those ranks hold different numbers of parameters.

**What.**
- `check_param_hashes_across_dp_replicas(..., *, dp_group=None, expt_dp_group=None)` takes the model's replicate groups, `pg_collection.dp` and `pg_collection.expt_dp`. If either is passed, no global group is read. A rank with non-expert parameters and no `dp_group`, or with expert parameters and no `expt_dp_group`, raises `ValueError` before any collective, so a dense model may pass `dp_group` alone. If neither is passed, the global groups are used as before.
- The training loop passes the groups of the model's collection, resolved as in `train_step`, at startup and at each check interval.

**Tests.** New tests on 4 GPUs use groups laid out unlike the global grid, with every `parallel_state` group and rank accessor patched to raise: agreeing replicas pass, a mismatch is detected with and without `cross_check`, and missing groups raise. They fail on main. Unit tests cover the training-side group resolution. Existing `test_utils.py` results match main. `pretrain_gpt.py` with the check every 2 iterations (DP=4 with the distributed optimizer, PP=2 x VPP=2, MoE with EP=2) gives losses bit-identical to main.

**Compatibility.** Callers that pass no groups keep the global groups. No change to numerics, checkpoints or the process-group allowlist.
