# Add Flash Attention Perfect Precision (PP) attention for training

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8405) · state: open · merged: False

## Original PR description

## Summary

Adds Flash Attention Perfect Precision (PP) as a training attention backend: `--attention-backend pp` (`AttnBackend.pp`). PP's forward gives the same output bytes for a token in the training forward, prefill, chunked prefill, decode and speculative verify. This PR is the training half; the inference half (paged prefill, decode, verify in the dynamic engine) is stacked on top of it in https://github.com/NVIDIA/Megatron-LM/pull/8406.

Contract (see `docs/developer/determinism/pp_attention.md`):
- Keys are visited in 128-token tiles at absolute positions, grouped into super-blocks of `G` tiles (`pp_attention_super_block_tiles`, default 8).
- Each super-block makes one FP32 partial `(m, l, O)`; partials are folded left to right with one fixed formula, rounded to BF16 once.
- So the bytes do not depend on batch composition, chunking, or decode splits. `G` is part of the bytes; training and serving must use the same `G`.

What is in it:
- `megatron/core/transformer/pp/`: the CuTe DSL forward kernel (head dim 128 and 256, BF16, causal, GQA), the fold, the autograd function and `PPDotProductAttention`. `Attention.__init__` builds `PPDotProductAttention` in place of the TE core attention when `attention_backend == pp`; no layer specs change.
- Backward: the FlashAttention-4 backward (`_flash_attn_bwd`) fed with the PP forward's output and LSE, with `deterministic=True` at head dim 128. Gradients are bitwise run to run.
- Packed THD (`cu_seqlens`) and context parallelism:
  - `all_gather`: zigzag segments run as varlen sequences with a bottom-right causal mask. Output, LSE and `dQ` equal the single-GPU bytes; `dK`/`dV` are sums of two BF16 segment partials.
  - `a2a`: full sequences per head shard, so all bytes equal the single-GPU run.
  - `p2p` and `a2a+p2p` are rejected: ring merges happen at chunk boundaries, not super-block boundaries.
- Rejected at config time: FP8 attention, sliding window, softcap, sinks, bias, dropout, non-causal masks, other head dims.
- Docs: methodology page with the fold diagram, a total-time (training + serving) figure and a TFLOP/s figure for hd128/hd256, measured against FA4 (default and deterministic backward), TE cuDNN and trtllm-gen. Registered in the determinism kernel manifest and op catalog.

```python
config = TransformerConfig(..., attention_backend=AttnBackend.pp, pp_attention_super_block_tiles=8)
```

Testing: `tests/unit_tests/transformer/test_pp_attention_training.py` (forward bytes vs. prefill, gradients vs. an FP64 reference, run-to-run bitwise gradients, THD, CP all_gather/a2a) passes on an SM100 GPU with cutlass-dsl 4.8.0 and 4.6.2. black, isort and pylint are clean.

Commits are DCO-signed (not GPG-signed).
