# What does this PR do?

Sequential partitioning currently counts lines using plain `open()` despite supporting gzip during the subsequent read. Its last-enumerated-line counter also remains undefined or stale for empty shards. Count with the same gzip-aware UTF-8 reader and `sum(1 for _ in fin)` so the partition size reflects actual documents.

This is an AI-assisted draft. Human author review and NVIDIA GPU/CI validation are pending.
