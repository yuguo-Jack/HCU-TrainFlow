# fix(optimizer): skip redundant state reload in DistributedOptimizer.load_state_dict

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8315) · state: open · merged: False

## Original PR description

Fixes #8046.

## What

`DistributedOptimizer.load_state_dict` enters a populated-state branch when
`dist_checkpointing.load` has already filled the inner optimizer state in place
(via sharded-state-dict wrappers around the live state tensors). The previous
implementation passed the optimizer's own current state back through
`self.optimizer.load_state_dict`, which

- cleared `self.state` (PyTorch's `Optimizer.load_state_dict` does
  `self.state = defaultdict(dict)` unconditionally), and
- cast every state tensor to the param dtype, and (for TE `FusedAdam`)
  allocated fresh FP32 state copies.

The originals stay referenced through `state_dict["param_state"]` until the
call returns, so peak GPU memory is roughly doubled during checkpoint restore.
On large MoE runs with expert data-parallel size 1, this OOMs in
`FusedAdam._initialize_state` even though training and saving fit.

## Fix

`dist_checkpointing.load` already populates the live state tensors in place,
so the populated branch only needs to sync the param-group hyperparameters.
The fix replaces the self-`load_state_dict` call with a direct `param_groups`
update that leaves `self.optimizer.state` untouched.

The empty-state branch (the cold restore path, where state has never been
allocated) is unchanged.

## Tests

New unit tests in `tests/unit_tests/optimizer/test_distrib_optimizer_load_state_dict.py`
pin:

- `self.optimizer.load_state_dict` is **not** called in the populated branch
  (load-tracking `AdamW` subclass counts calls),
- `self.optimizer.state` and `self.optimizer.state[param]` keep their identity,
- the state tensors' `data_ptr()` is preserved,
- param-group hyperparameters (`lr`, `weight_decay`) still sync from the
  saved state,
- the native-PyTorch `step` counter is updated in place on the live state.
