# Preserve Transformer Engine's delayed-wgrad marker on MFSDP v2 parameters

# What does this PR do?
  With `delay_wgrad_compute=True`, Transformer Engine marks weights with `skip_backward_post_hook`. MFSDP v2 relies on this marker to reduce them after `backward_dw()`. When MFSDP v2 materializes or shards parameters, it copies only the attributes in `_PARAMETER_ATTRIBUTES_TO_PRESERVE`, so the marker was lost for  modules built on the meta device. Gradients were then reduced before `backward_dw()` ran.

 This PR adds `skip_backward_post_hook` to that list.


  ## Testing
 ` test_mcore_dense.py::test_delayed_wgrad_matches_immediate[meta]` builds a delayed-wgrad `te.Linear` on the meta device, wraps it in FullyShardedDataParallel v2, and requires bitwise-equal losses against immediate wgrad over 5 steps of 3 accumulated microbatches. It fails on main with Missing gradient for FSDP parameter ('weight',) and passes with this fix.
