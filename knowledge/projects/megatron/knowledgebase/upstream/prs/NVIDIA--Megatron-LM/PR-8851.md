# What does this PR do?

Migrate C16 fault-tolerance and autoresume settings to `cfg.fault_tolerance`.

**Stacked on #8558**, pinned at `547c0ffa05a564d88302323ec344f50c51d4f942`. The base is `pull-request/8558`, so this diff contains only C16. Retarget this PR before the parent branch is deleted; merge only after #8558 is integrated.

- Add a separate `FaultToleranceConfig` for `adlr_autoresume`, `adlr_autoresume_interval`, `enable_ft_package`, `calc_ft_timeouts`, and `ft_num_warmup_iters`. Preserve CLI names/defaults through the argument factory.
- Compose an optional `FaultInjectorConfig` at `cfg.fault_tolerance.fault_injector`. Construct it at the CLI boundary, not inside `train()`. Injection remains disabled by default and independent of FT monitoring; rank selection and delayed activation are unchanged.
- Read configuration in FT setup and autoresume setup/cadence, including the legacy finetuning loop. FT setup no longer reparses the command line, so native configs work without global args.
- Move the existing enabled-FT/save-directory check into container validation. No new validation rules or finalization mutation. Preserve the finalized checkpoint policy supplied by #8558.
- Use existing generic run-config serialization, with no section-specific snapshots or additional checkpoint restoration. These remain current-run settings; learned timeouts still load from `ft_state.json` as before.
