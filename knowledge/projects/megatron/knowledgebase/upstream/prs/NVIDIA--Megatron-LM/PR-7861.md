# What does this PR do?
Propagate rank-zero integrity-manifest read and decode failures to every rank before returning from distributed verification.

With `verify_integrity=True`, a truncated `integrity.json` raises `JSONDecodeError` on rank zero before the error broadcast. Peers remain in the collective until timeout or teardown, rather than receiving the checkpoint error. Manifest open failures and invalid UTF-8 follow the same path.

Catch ordinary exceptions at the existing rank-zero verification boundary and reuse the existing error broadcast and `CheckpointingException` wrapper. Add two-process Gloo tests for these failures, existing integrity failures, valid manifests, identical per-rank messages, and successful verification after repair. Single-process behavior, successful verification, checkpoint format, and fallback policy are unchanged. One trailing comma in the touched module is required by the configured Black formatter.

## Risks and limits

The distributed error boundary now wraps ordinary read/decode exceptions in the established `CheckpointingException` contract. It does not catch `BaseException`, recover a dead process or communicator, make manifest writes atomic, or select a fallback checkpoint.

Validation used an isolated CPU environment, not the required upstream container or upstream CI. CUDA/NCCL, multi-node execution, MSC remote storage, asynchronous saves, and full training recovery remain unverified. No benchmark or performance improvement is claimed.
