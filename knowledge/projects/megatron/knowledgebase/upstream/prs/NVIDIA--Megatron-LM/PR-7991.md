# docs: document the process-group CI check and building a ProcessGroupCollection

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7991) · state: closed · merged: False

## Original PR description

Depends on #6257, which this branch is stacked on. The pages describe code from #6259, #6293, #8026, #8031, #8765, #8747, #8733, #8766, #8767, #8734, #8763, #8746, #8770 and #8768, so this PR lands after them. The PR's own diff on top of #6257, synced with `main`, is the [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/bafb4def71...yx/pstate-docs-followup).

**Why.** #6257 documents what is deprecated in `parallel_state` and how to migrate a call. It does not cover:

- the CI check that #6258 added: what it counts, what it skips, and what to do when it reports a read. A moved read needs care, because `--update` cannot handle it.
- code that builds its own grid (Megatron Bridge, RL frameworks, models with independent grids). There is no documented way to build a `ProcessGroupCollection` without the globals.
- the end state of `initialize_model_parallel` and the `get_*()` accessors.

The accessors and Megatron Core's fallbacks now warn, and the warnings point at the deprecation guide. The guide was written before they did. It described tiers of accessors of which only some were deprecated, a checker that skipped predicates and virtual-pipeline state, and a removal with no release. The Core QuickStart, the tracing guide and the fallback examples taught calls that now warn. The example the QuickStart points to, `examples/run_simple_mcore_train_loop.py`, never trains: it steps `torch.optim.Adam` over a DDP-wrapped model. DDP moves each gradient into its buffer and sets `param.grad` to `None`, so no weight moves.

**What.** Docs, docstrings in `parallel_state.py` and `process_groups_config.py`, and the process-group allowlist.

- `docs/developer/parallel-state-deprecation.md`, rewritten for the code after the PRs above:
  - what emits a `ParallelStateDeprecationWarning`, when it stays silent, and what replaces each deprecated function. `get_pp_next_rank()` and `get_pp_prev_rank()` do not wrap around like the accessors they replace, so the page shows how to take the peers from the group's ranks, as `P2PCommunicator` does.
  - `ProcessGroupFallbackWarning`, with `resolve_process_groups()` inside Megatron Core and `global_process_group_fallback()` outside it.
  - the registry (`register_process_groups()`, `get_registered_process_groups()`), and `copy.copy()` before adding fields.
  - strict mode. It leaves `ParallelStateDeprecationWarning` a warning by design, and the page shows how to make that an error too.
  - a migration checklist for frameworks such as Megatron-Bridge and NeMo-RL, with snippets for the `initialize_model_parallel()` path and for a registered `HyperCommGrid` collection.
  - the CI check: what the ratchet over `megatron/core` and the guard over the code outside it count and skip, the `:warned` allowlist entries, and the commands to run them locally. A new read in new code means passing the group through. A moved read needs a reviewed manual allowlist entry. After removing reads, `--update` refreshes the allowlist. Both checks are report-only in CI. The job fails on the checker's own tests and on the removal-version test.
  - the removal schedule (deprecated in 0.21, removed in 0.23) and what `parallel_state` keeps afterwards. Status stays in #6307.
- `docs/developer/process-group-collection.md` (new): `HyperCommGrid` in brief, a dense TP × PP × DP example, which fields to set and why an unused axis must be set to `None` explicitly, and how to pass the collection to `GPTModel`, `DistributedDataParallel`, `get_megatron_optimizer`, the RNG seed and the schedules. The example also sets the GTP-inclusive and per-optimizer-instance data-parallel fields, so a registered copy serves code that still reads `parallel_state`. The page covers the Gloo fields and the process-wide memory buffer.
- `docs/developer/process-group-failure-patterns.md` (new): 11 patterns that make a component use the wrong process groups on a grid other than the global one. Each says what goes wrong and what to write instead. The page ends with how to test a component on a grid of its own.
- `megatron/core/QuickStart.md`: passes the process groups explicitly, based on `examples/run_simple_mcore_train_loop.py`.
  - It wraps the model in `DistributedDataParallel` and calls `finalize_model_grads`, as the example does.
  - It trains with `get_megatron_optimizer` and zeroes the gradient buffer each iteration.
  - It creates the checkpoint directory before saving.
  - It uses the installation guide's container and `PIP_CONSTRAINT` override, because Megatron Core needs Python 3.12.
  - It builds the mock dataset's tokenizer with `MegatronTokenizer` instead of the removed `_NullTokenizer`, and says it needs Megatron Core 0.21.
- `docs/user-guide/observability/pipeline-parallel.md`: reads the pipeline size from the model's collection instead of a deprecated accessor. It also marks the integration as planned, since neither part is wired in.
- Docstrings: the `parallel_state` module docstring deprecates the accessors, not the module, and lists the functions that stay. The Gloo and dynamic context-parallel accessors name their collection fields. The next and prev pipeline-rank accessors note the wrap-around. `use_mpu_process_groups()` is kept to bootstrap code.
- `docs/developer/contribute.md` points to the CI check. `docs/index.md` adds both new pages to the Developer Guide toctree.
- `tools/process_group_usage_allowlist.json`, from the merge with `main`: it records the 3 reads `main` added since this PR was written and drops 1 entry whose read `main` removed.

**Tests.** Docs, docstrings and the allowlist only, so there are no new tests. The docstring changes do not change what the process-group checker reports. With the allowlist from the merge it reports no new reads; on the base it reports the 3 reads `main` added, which the base's allowlist does not record.

On this branch, the 24 relative links and heading anchors in the changed pages resolve, and the 42 Python snippets parse. The rest was checked before the sync with `main`, on a tree that combines this PR with the PRs it depends on:

- The snippets' Megatron imports, attributes and keyword arguments exist.
- QuickStart code blocks, 2 CPU ranks (gloo), fallbacks and the accessor warning as errors: 5 iterations, the loss falls, the weights move by about the learning rate per step, and the checkpoint saves and loads. With `torch.optim.Adam` in its place, as in the example, no weight moved.
- `HyperCommGrid` example, 4 gloo ranks (TP2·DP2), strict mode. Registered, it gives `use_mpu_process_groups()` the ranks of `initialize_model_parallel()`, apart from the Gloo and GTP groups. With both Gloo fields it trains. With only `intra_dp_cp_gloo`, `get_megatron_optimizer` raises `ValueError`, as the page says.
- The wrap-around snippet gives the accessors' peers on every stage (8 gloo ranks, TP2·PP4). The tensor-parallel mappings emit one `ProcessGroupFallbackWarning` per mapping on each rank, as failure pattern 3 says.

The first version of the example, before it set the GTP-inclusive fields and seeded from the collection, was checked as follows:

- Group layout, CPU, gloo, 8 ranks, for TP × PP × DP = 2×2×2, 2×1×4, 1×2×4, 4×2×1, 1×4×2, 1×1×8 and 8×1×1. On every rank, every field the example set matched the group from `initialize_model_parallel` with the same sizes: the same ranks in the same order.
- Training, 4 GPUs, NCCL, `main` at a07014bbd, without `initialize_model_parallel`. A 4-layer `GPTModel` with the Transformer Engine spec ran 3 steps with `DistributedDataParallel`, the distributed optimizer and the schedules, on TP2·DP2, PP2·DP2, TP2·PP2 and PP4. The local spec trained too once the global memory buffer existed (TP2·PP2, TP2·DP2). #8026 creates that buffer on first use.
- Sphinx with `SKIP_AUTODOC=true` gave the same single warning before and after. It was not re-run for this update.

This PR touches no unit-test files. The integration run merges all 93 #6307 PRs and the 6 gap fixes onto `main` 77391e71cc, this PR included, and runs the full unit-test suite on 4 GPUs and 8 GPUs (two nodes) against `main`. No test that passes on `main` fails there, apart from one fused-MHC kernel check that has failed the same way on `main`. The QuickStart has not been run on GPUs.

**Compatibility.** No runtime change. The pages describe the code after the PRs listed at the top, so until those land they name helpers and warnings that `main` does not have. `examples/run_simple_mcore_train_loop.py` still steps `torch.optim.Adam` under DDP, the no-op the QuickStart avoids. It needs its own fix.
