## What this PR does

GRPO and multi-completion PPO produce several completions per prompt. A
conventional packed forward recomputes that prompt once per completion. With
this PR, `HybridModel.forward` accepts a `shared_prefix_layout` and runs the
model with each prompt stored once and every completion run against it.

Without `shared_prefix_layout`, `HybridModel.forward` takes the existing code
path, and importing `HybridModel` does not load the shared-prefix adapter.

Terms:

- **Star**: one prompt followed by its G completions,
  `[prompt, completion_1, ..., completion_G]`.
- **Forest**: several independent stars packed into one forward.
- **Dense rows**: the G separate sequences `[prompt, completion_g]` that a star
  replaces.

## Changes

`megatron/core/models/hybrid/shared_prefix.py` holds only the generic
orchestration. The layer-specific execution lives with each layer (#8153,
#8155, #8156 and #8157).

- **Validation.** `HybridModel.forward` validates the stack configuration
  once, before the embedding.
  - Unsupported stack configurations therefore fail before any partial
    forward.
  - Each self-attention layer goes through
    `validate_shared_prefix_attention(attention, tp_size=..., cp_size=...)`
    from #8156. Its last step binds flash-attn, so a missing flash-attn or one
    older than 2.7.0 raises `ImportError` before any layer runs.
  - The MTP layout and loss-mask checks run when MTP executes, after the
    backbone.
  - Non-fp16/bf16 hidden states are rejected when the layer stack starts,
    before its first layer runs.
- **Layer loop.** `forward_hybrid_stack_shared_prefix` runs each layer on the
  layout. Each layer receives its shared-prefix input as a keyword argument of
  its own call. No module attribute is set.
  - Self-attention layers receive the layout as `shared_prefix_forest`, next
    to `rotary_pos_emb`, and run the forest attention of #8156 in place of core
    attention. A single star is passed as a forest with one root.
  - Mamba layers receive a `shared_prefix_call` request through
    `forward_mamba_layer_shared_prefix` and fork their prefix state (#8157).
  - With expert bias enabled, MoE layers receive
    `shared_prefix_token_multiplicities`. Their routers count logical token
    multiplicities inside the fixed-row router scope (#8153).
  - Every layer runs through its module call, so module hooks fire as on the
    dense path.

  The loop also handles full uniform activation recomputation. The arguments
  are captured in the checkpointed callable, so the backward replay calls each
  layer with the same arguments as its forward call.
- **MTP.** The MTP heads run on the dense rows rebuilt from the star; the MTP
  prefix is not shared. `loss_group_lengths` (#8155) keeps each forest root's
  normalization. Each rank sums its prompt copies' gradients in a fixed FP32
  order; at CP>1 the per-rank partials are combined by the CP reduce-scatter.
  Shared MTP gradients are therefore reproducible for a fixed topology. The MTP
  MoE routers follow the backbone's expert-bias padding convention: when
  padding is excluded, the dense branches receive their per-sequence padding as
  `padding_mask`, as a dense forward with the padding mask does.
- **Capability tokens** at the end of `shared_prefix.py` name the implemented
  code paths for integrations. They are contract identifiers, not evidence
  that a topology has been qualified at full-model scale.
- **Docs.** `docs/developer/shared_prefix.md` describes the feature, including
  the arguments each layer call receives. It is linked from the Advanced
  Features toctree.

## How to enable

```python
from megatron.core.shared_prefix_layout import SharedPrefixLayout

# TP1 with CP1 or CP2. A 3-token prompt with completions of 3 and 1 tokens; the first
# completion carries 2 rows of padding so each branch is a multiple of 4: 9 tokens
# stored, padded to 12.
layout = SharedPrefixLayout(3, (5, 1), logical_completion_lens=(3, 1), padding_multiple=4)
logits = model(
    input_ids=packed_ids,  # [1, 12 / CP], the CP-local zigzag shard
    position_ids=None,
    attention_mask=None,
    shared_prefix_layout=layout,
    loss_mask=loss_mask,  # required when MTP runs in training
)
```

With `labels=None` the forward returns logits of shape
`[1, physical_len/CP, padded_vocab/TP]`, in the input shard's zigzag token
order. It gathers neither across CP nor across TP; the caller computes the
loss.

`padding_multiple` must be a multiple of the topology quantum:

- 1 at TP1/CP1;
- 2·CP at TP1 with CP greater than one;
- 2·TP·CP when TP is greater than one.

`SharedPrefixForestLayout` packs several stars. `megatron.rl` (#8152) builds
layouts and tensors from row metadata.

Optional controls:

- `shared_prefix_exclude_sequence_padding_from_expert_bias` on
  `HybridModel.forward`: whether per-branch padding counts toward expert bias.
  - `True` excludes it, as a dense forward with the packed-sequence padding
    mask does.
  - `False` counts it, as a dense forward with `padding_mask=None` does.
  - Unset, padding is excluded with the flex dispatcher's `hybridep` backend
    and counted otherwise.
- `compute_mtp_loss=False`: skip MTP and its input checks.
- `NRL_SP_MAMBA_IMPL`: the Mamba backend (#8157). The default needs no setting.

## Scope and guards

Supported:

- PP1 hybrid models built from `hybrid_layer_pattern`, in fp16/bf16 with zero
  dropout;
- RoPE or no positional embedding, and self-attention with dot-product core
  attention and vanilla softmax;
- `MambaMixer` with gated RMSNorm, and MLP or MoE layers;
- TP with sequence parallelism, and CP with zigzag ownership;
- full uniform activation recomputation, and MTP in training.

`HybridModel.forward` rejects, with an explicit error:

- models built from `hybrid_layer_config_list`;
- hash routing, quantization recipes, fp8/fp4, wide residual streams, mHC and
  batch-invariant mode;
- multi-latent attention, core attention other than `DotProductAttention` or
  `TEDotProductAttention` (for example DeepSeek Sparse Attention over
  grouped-query attention), logit softcapping, QK-clip statistics,
  sliding-window attention, selective core-attention recomputation, and an
  external attention mask;
- fine-grained activation offloading and CUDA graphs;
- `linear_cp_layout='contiguous'` at CP greater than one;
- MoE:
  - load balancing that replaces top-k routing (such as sinkhorn);
  - nonzero auxiliary-loss or z-loss coefficients, and input jitter;
  - randomized forced routing;
  - expert-capacity and per-rank-capacity token dropping;
  - the flex dispatcher's `ncclep` backend;
  - routing replay, and training MLP chunking;
- a missing flash-attn or one older than 2.7.0 (`ImportError`), and the Mamba
  backend checks of #8157;
- inference contexts, `cp_batch`, `packed_seq_params`, `padding_mask`,
  `output_processor` and `labels` (the caller computes the next-token loss),
  and PP>1;
- at TP>1, logits that are not TP-sharded parallel output;
- MoE expert-bias accounting with a layout that lacks explicit
  `padding_multiple` and `logical_completion_lens`.

MTP has its own restrictions. Pass `compute_mtp_loss=False` to skip MTP.

- The predictor must not contain a Mamba layer and must not use the local
  attention backend (it needs THD packing). It is meant to be attention/MLP or
  attention/MoE; other layer types are not rejected but are not tested.
- Training MTP needs `loss_mask` and a layout with explicit
  `padding_multiple` and `logical_completion_lens`.
- Forests need `calculate_per_token_loss`.
- `decoder_input` and `mtp_input_mask` are rejected.

Without a layout, none of these checks run.

## Validation

**Acceptance method.**

- **FP32.** Shared and dense differ only in summation order. Layer tests use
  PyTorch linear layers with TF32 disabled and bound the difference at 1e-5
  (MoE) and 5e-5 (Mamba) relative L2.
- **BF16.** Shared and dense are two equally valid roundings. Both are compared
  with an FP32 dense reference of the same BF16-representable weights, with MoE
  top-k choices replayed from a fixed table. Shared must be within 1.25 times
  the dense error.
- **TP/CP.** No FP32 reference exists there. The shared-versus-dense gap at the
  target topology must stay within 1.5 times the same model's TP1/CP1 gap.
- **Exact checks.** Expert-bias counts must match exactly. The default path
  with an explicit `None` layout must be bit-identical to omitting it.

**Gradient difference between shared and dense BF16 runs.** Earlier revisions
reported a backbone-gradient difference against a repeated dense run as
unresolved. A review study on one GB200 explains it. The study used TP1/CP1
and random-init hybrid MoE models of up to 28 layers.

- In IEEE FP32, every shared component matches dense to about 1e-7.
- With MoE routing replayed, shared and dense BF16 are equally far from a
  high-precision reference: 1.96% each, as whole-gradient relative L2.
- Their mutual gap (2.34%) is close to the gap between two dense runs with
  different packings (2.05%). It shrinks 8x in FP16, which matches the ratio of
  the two formats' rounding steps.
- With natural routing, BF16 rounding flips MoE top-k choices, which inflates
  every comparison.

A repeated dense run therefore measures only nondeterminism and is the wrong
null.

## Known limitations

- No whole-model gradient comparison has been run at a large training
  topology, such as TP2/CP4 with SP and MTP and routing replayed. The
  distributed tests use small models at TP2/SP/CP2 and TP1/CP4.
- RL training quality is not established by these tests; the integrating
  framework owns that.
- Shared-prefix MTP materializes the full global star on every TP and CP rank
  before rebuilding the dense branches. Long prompts with many completions can
  make MTP memory-heavy.
- `megatron.rl` and `megatron.core` define separate layout classes; the
  conversion between them lives in the caller.
- Models built from `hybrid_layer_config_list` (main #7555) are rejected. Their
  layers carry their own configurations, while the shared-prefix guards read
  only the model-level configuration and `hybrid_layer_pattern`.
- The flex dispatcher's `ncclep` backend is rejected. When the input is not
  THD-packed, it sizes its NCCL EP buffers once, from the first microbatch.
  Since main #8458, a later microbatch with more tokens per rank raises an
  error. Shared-prefix microbatches are not THD-packed, and their length
  changes from one microbatch to the next.
- Shared-prefix training under Megatron FSDP has not been qualified.

Done, by running it through the layer's normal call. This line still calls forward_mamba_layer_shared_prefix(layer, ...), but in #8157 that function no longer touches the layer's internals: it attaches a per-call request to layer.mixer and calls layer(hidden_states=..., attention_mask=None). That goes through MambaLayer.__call__ and MambaLayer.forward (pre-norm, residual, bias-dropout-add as on the dense path), which calls the mixer through MambaMixer.__call__. MambaMixer.forward then hands the request to the star scan (in_proj, scan, gated norm, out_proj). So every module hook on MambaLayer and MambaMixer fires, including Megatron FSDP's unshard/prefetch/reshard and its per-module parameter gathers, and the second of two consecutive Mamba layers is unsharded by its own pre-forward hook.

Outputs, input gradients and all parameter gradients are bit-identical before and after for every NRL_SP_MAMBA_IMPL backend (661/661 tensors). A forward that ignores the request raises instead of silently running dense Mamba, and nested requests are rejected. This PR adds a test that two consecutive Mamba layers in the shared-prefix stack fire their layer and mixer hooks in order.

We have not run shared prefix under Megatron FSDP itself yet, so the docs say it is not qualified. If you would rather have a fail-closed FSDP guard until it is, I can add one.
