# test: use IEEE FP32 GEMMs in mHC PP parity test

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8501) · state: closed · merged: True

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Stabilizes the FP32 (CP1) cases of `test_mhc_schedule_matches_pp1` by running them with PyTorch matmul and cuDNN TF32 disabled, so the PP1 reference and the PP/VPP schedules use IEEE PyTorch GEMMs. Tolerances are unchanged, and the BF16 CP>1 cases are unchanged.

## Why

On main, the CP1 cases of this parity test fail intermittently: embedding-gradient differences land just above the 1e-5 tolerance, and the test passes on retry. The test compares FP32 runs whose PyTorch GEMMs can use TF32 and can pick different kernels for different PP partitions.

## Change

- `test_mhc_schedule_matches_pp1` takes `monkeypatch`. For `cp_size == 1` it sets `torch.backends.cuda.matmul.allow_tf32` and `torch.backends.cudnn.allow_tf32` to `False`. pytest restores both after the test.
- Extracted from 1d34d30ac703a3761cf6a21d3229cf50cb27f15b in #8223. The single-pass mHC changes in #8223 and the other DSv4.1 PRs are not included. The only adaptation is the code comment, which now says what the flags do and don't control (below).

## Scope and limits

- The dev CI image (`nvcr.io/nvidia/pytorch:26.09-py3`) sets `TORCH_ALLOW_TF32_CUBLAS_OVERRIDE=1`. In that image's PyTorch (2.14.0a0), the variable only sets the initial matmul precision (`Context.h`). Setting `allow_tf32 = False` switches the CUDA matmul precision to IEEE, and the cuBLAS handle math mode follows it (`CublasHandlePool.cpp`). We checked this on CPU in the same image; pytest's undo restores the defaults.
- Transformer Engine 2.20.2 (the pinned revision) always uses `CUBLAS_COMPUTE_32F_FAST_TF32` for pure FP32 GEMMs (`cublaslt_gemm.cu`). The TE linear layers in this test (QKV, projection, FC1, FC2) therefore keep TF32 compute. The change covers the PyTorch-native GEMMs: unfused attention (`torch.baddbmm`/`torch.bmm`), the mHC mixing and mapping, and the output layer.
