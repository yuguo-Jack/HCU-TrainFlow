# [lite] DeepSeek-V4.1 BF16 training

# What does this PR do?

Add DeepSeek-V4.1 BF16 training to the experimental lite runtime using existing Megatron-Core components, with no changes to `megatron/core` and no vLLM dependency.

Supports release-native FP4/FP8 loading, BF16 execution, host Engram, KV/index reuse, candidate selection, EP/PP/CP, recomputation, Adam DistOpt and DCP. Ratios 0/2 use Core CSA; ratio 1 composes Core sparse attention and CP. Assembly adds compressed YaRN, shifted hyper-connections and Q without per-head RMS. Zero-loss index-selection parameters are frozen.

Engram retains pinned host FP8 E4M3/E8M0 row shards; only requested rows move to GPU and decode to BF16. Bounded payload/row prefetch overlaps construction. Strict loading rejects unread local keys and unloaded state.

Shared fixes preserve checkpoint buffers/row offsets and lazy-import RNG, synchronize parameters before saves/exports, and align pipeline payloads in both directions while retaining FP32 signed zero.

## Usage

Launch a script with `torchrun --standalone --nproc-per-node=4 train_ds41.py`, using the release safetensors/index/configuration and its matching compressed token map:

```python
from megatron.lite.runtime import create_runtime
from megatron.lite.runtime.backends.mlite.config import MegatronLiteConfig
from megatron.lite.runtime.contracts import ParallelConfig, RuntimeConfig

backend = MegatronLiteConfig(
    model_name="deepseek_v41", impl="lite", hf_path="<release-directory>",
    parallel=ParallelConfig(ep=4),
    impl_cfg={"token_map": compressed_token_map, "optimizer": "adam"},
)
runtime = create_runtime(RuntimeConfig(backend="mlite", backend_cfg=backend))
handle = runtime.build_model()
```

Export with `runtime.export_weights(handle, target="bf16")` (default `"hf"`) or `target="release"` for native FP8/MXFP4. The protocol's `save_hf_weights` writes HF shards; all EP/PP ranks participate. Frozen Engram stays FP8/E8M0 and streams bounded `TensorRowChunk` payloads. Online consumers may set `include_frozen=False`.

See `experimental/lite/examples/deepseek_v41` and `experimental/lite/tests/unit/deepseek_v41`. No preconverted BF16 checkpoint is required.

## Reproducibility and limits

- Defaults do **not** promise determinism. For reproducibility, set `CUBLAS_WORKSPACE_CONFIG=:4096:8` before CUDA initialization, call `torch.use_deterministic_algorithms(True, warn_only=True)` and set `impl_cfg["deterministic_mode"] = True`. These settings were tested jointly, not individually. In a four-layer EP8 repeat, default atomic MoE accumulation was amplified by later routing: LP max/p99 differences were 0.686017/0.500688 nat. With the joint profile, eight ranks and two forwards matched at all 75 observed boundaries and all 16 response LP bitstrings. This is not a statistical noise bound.
- Ratio-2 CP selects the same KV set in a different order; FlashMLA can differ by a BF16 ulp, so this comparison is report-only. CP attention backward values are also reports because reduction order changes; finite/nonzero gradients remain required. Whole-model CP2/CP1 is report-only: measured max/p99 0.08237/0.06221 nat.
- Ratio-1 CP replicates full window/main KV per rank; packs with fewer local rows than the attention window are rejected. TP/ETP/VPP are one; pipeline cuts are contiguous. Default 43-layer prediction-inclusive topology is rejected.
- HF export covers owned text weights, not unowned MTP/vision-only parameters. Reuse the matching config/token map; use DCP to resume optimizer state. Trainable Engram, quantized execution/W4A8 and non-Adam optimizers are unsupported. Cross-stage readers require transported source-cache entries. The continuation test restores scheduler state from a control snapshot rather than independently proving its DCP round trip.
- Core upgrades require revalidation. No full-release training-quality, rollout-parity or RL claim is made.

### Ragged Engram lookup

Frozen-table lookup pads only the leading row dimension of 3D IDs. A two-rank CPU/Gloo regression covers unequal row counts, either rank empty, and both ranks empty; output shape, dtype and BF16 raw bits match full-table lookup. The affected CPU suite passes 9 tests, including the existing exporter contracts; all exporter assertions are retained. A separate eight-rank component regression covers 16 ragged/empty cases with identical output bytes, and two old-code controls fail as expected.


Parameter readiness: native forward publishes Core parameter buckets before functional reads, including mHC. A 40-layer EP8 check with two consecutive updates and no export verified identical log-probability bits and loss across all ranks, matching read-time mHC fingerprints and all 967 replicated dense-parameter fingerprints after the updates. The original 24-step small SFT and EP2 checkpoint/resume tests pass on this fix.
