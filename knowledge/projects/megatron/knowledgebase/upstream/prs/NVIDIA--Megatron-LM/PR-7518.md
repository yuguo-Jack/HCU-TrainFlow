# Keep attention logit statistics valid across CUDA Graph replay

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7518) · state: open · merged: False

## Original PR description

## Why

CUDA Graph replay executes captured device operations without repeating Python assignments. Replacing `current_max_attn_logits` after each forward therefore fails to maintain a cross-microbatch accumulator across graph replays and optimizer steps. Clipping and log-only consumers need a stable accumulator that they can reset without replacing the captured storage.

Fixes #7475. This change addresses the reproduced accumulation failure; the separate freed-buffer hypothesis in the issue has not been established.

## What changed

- Register one nonpersistent FP32 accumulator per attention module, sized for the local tensor-parallel heads and initialized to negative infinity. Preserve its FP32 dtype through `Float16Module` using the existing `mark_keep_in_fp32` contract.
- Accumulate detached per-forward maxima with `torch.maximum(..., out=...)`, retaining the same storage through capture, replay, consumption, and reset.
- Reset the accumulator in place after standard-attention clipping, MLA clipping, and log-only consumption. Treat an untouched all-negative-infinity buffer as having no collected statistics.
- Clear capture and warmup statistics from the same buffers during TE capture cleanup.
- Extend existing coverage with consecutive optimizer-step comparisons between eager execution and captured forward/backward, including gradients, clipping, parameter updates, buffer reuse, and TE attention replay with logging enabled and disabled.

Runtime context-parallel group selection and restoration retain the current main implementation. The accumulator is runtime state and is omitted from checkpoints.
