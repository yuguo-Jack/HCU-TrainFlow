# [CI][Attention][MoE] Bump Transformer Engine to 2.21.0 so its FlashAttention-4 backend stops zeroing causal attention

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8954) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Moves the pinned Transformer Engine from git rev `44f31bbe` (2.20.2) to the v2.21.0 release, `7457e47d26d9d02dfb783007335dfbe75e1b90a8` (annotated tag `v2.21.0`, object `ae1bc86c`), and regenerates `uv.lock`. It also fixes the places where Megatron's handling of TE 2.21 goes wrong. The bump is the long-term fix for P4-N6: with flash-attn-4 4.0.0b30 or later, TE 2.20's FlashAttention-4 backend returns zeros for causal attention. #8860 works around this by capping flash-attn-4 below b30.

**Stacked on #8865** (`fix/bi-te-gemm-accumulate`), merged in with a signed merge commit. TE 2.21 hands the batch-invariant GEMM nD operands, and #8865 flattens them to 2D as TE does. Without it, batch-invariant training on the deepgemm and triton backends crashes on TE 2.21 (see **Fix**). Please land #8865 first.

**Bug (P4-N6).** TE before 2.21 passes FA4 the window `(-1, 0)` for every causal mask, where -1 means unbounded. In flash-attn-4 4.0.0b30, `_resolve_causal_local_window` changed to drop the window only when both bounds are negative. So b30 and later read `(-1, 0)` as a window from i+1 to i, which is empty, and every causal row comes out zero.

TE runs FA4 by default (`NVTE_FLASH_ATTN_V4=1`) on SM90 and newer, so this hits:
- every run with `--attention-backend flash`, including batch-invariant mode;
- auto-backend calls that cuDNN cannot take.

In the GB200 batch-invariant RL test, TE `DotProductAttention` on FA4 b37 differed from fp32 by rel 1, while Megatron's own FA4 calls, which pass `(-1, -1)`, matched (rel ~0.002). Batch-invariance tests miss it because all-zero outputs are batch-invariant.

**Root cause.** The TE that Megatron pins predates TE #3532, which shipped through #3540. That change wraps TE's four FA4 entry points in `_fa4_with_none_window_sentinel` (`attention/dot_product_attention/backends.py:227`, applied at `:288-293`). The wrapper translates -1 to `None` and keeps other negative offsets.

TE v2.21.0 contains this fix. The tag is 119 commits ahead of `44f31bbe` and 25 behind it. All 25 commits it lacks are release-branch cherry-picks of commits that v2.21.0 already has, including #3635 (deterministic dprob for the GLU fused grouped MLP), which the current pin carries.

**Fix.**
- `pyproject.toml`:
  - `[tool.uv.sources]` pins TE to `7457e47d26d9d02dfb783007335dfbe75e1b90a8`.
  - `[[tool.uv.dependency-metadata]]` declares `2.21.0+7457e47d`, the version TE v2.21.0 reports: `build_tools/VERSION.txt` is `2.21.0`, and `te_version()` appends `+$(git rev-parse --short HEAD)`.
  - TE's install requirements are the same at both revs (`build_tools/pytorch.py`, `setup.py`), including `nvidia-cudnn-frontend>=1.29.0`, so `requires-dist` is unchanged.
  - The rev stays a full sha, so the dev Dockerfile's `TE_SHORT_REV="${TE_REV:0:8}"` lookup of the NCCL-EP JIT headers still works. It finds `.../git-v0/checkouts/<repo>/7457e47d/3rdparty/*/build/include/nccl_ep`.
    - uv names the checkout by `git rev-parse --short`. TE's history at either rev has 30-38k objects, so git abbreviates to 8 characters, and no other reachable object shares the prefix `7457e47d`.
    - The bumped nccl-extensions submodule (`a9f207c` to `998d922`) still writes `build/include/nccl_ep/device/ht_ep.cuh` and `build/include/nccl_ep.h`.
- `megatron/core/transformer/moe/experts.py`: `_te_grouped_tensor_supports_sharded_weights` probed `_GroupedLinear._forward_grouped_tensor` for an `is_dist_weight` parameter, which TE #3517 added.
  - TE 2.21 ships #3517, but its GroupedLinear refactor (#3606) replaced the method's keyword arguments with one argument bag, `_forward_grouped_tensor(ctx, fwd_args)` (`module/grouped_linear.py:1520`). The probe therefore reads False on the first TE that has the support.
  - As a result, GTP-sharded experts silently fall back to the split-quantize path, and `moe_paged_stash` with them raises.
  - The gate is now `is_te_min_version("2.21.0")`, as the probe's TODO asked. A 2.21.0.dev build answers False, which is safe: those builds fall back. The `lru_cache` is dropped because the version is already cached.
- `megatron/core/extensions/transformer_engine.py`: TE 2.21 (#3734) stopped validating QB bin bounds and made `mark_qb_bin_bounds_validated` a deprecated no-op that issues a `DeprecationWarning` on every call (`router.py:47`).
  - The quantile-balancing finalizer called it for every router on every step.
  - Megatron now imports it only for TE before 2.21. Those versions validate bounds with a host sync unless they are marked, and refuse unmarked bounds under CUDA graph capture. On 2.21 it stays `None`, which the finalizer already skips.
  - The gate is a version check. TE main nightlies that report `2.22.0.dev0` from 2026-10-14 until #3734 (2026-10-27) still validate bounds; those dev builds are not supported.
- Batch-invariant training on TE 2.21's nD layer inputs. TE 2.21 (#3523) stops flattening layer inputs and gradients to 2D in Linear, LayerNormLinear, LayerNormMLP and `grad_output_preprocess`, and Megatron's batch-invariant patches assumed 2D:
  - The deepgemm and triton GEMM (`BatchInvariantTEGemmFn`) transposed a 3D gradient in the weight-gradient GEMM and failed with "mat1 and mat2 shapes cannot be multiplied". #8865, merged into this branch, flattens A and B to 2D before the layout's transposes and gives the output TE's shape (`getGemmOutputShape`).
  - The batch-invariant `apply_normalization` patch (`batch_invariant_kernels.py`, RMSNorm in LayerNormLinear and LayerNormMLP) returned rsigma as `rsigma.squeeze(-1)`. That is `[s, b]` for TE 2.21's nD input, and TE's `rmsnorm_bwd` takes `[rows]` (`rmsnorm_api.cpp:141`), so it raised "RSigma has invalid shape". It now returns `rsigma.reshape(-1)`, which is `[rows]` for TE 2.20's 2D input and TE 2.21's nD input alike, as TE's own forward returns it. (Both versions check `rsigma.shape == {rows}`; TE 2.20 also requires a 2D `x`.) LayerNorm and quantized outputs fall back to TE's own kernel, and te_native keeps TE's native norm, so neither is affected.
- `megatron/core/transformer/transformer_config.py`: batch-invariant mode now rejects `use_grouped_gemm_for_dense_mlp` and `use_grouped_gemm_for_shared_expert` for every backend, with a message naming both flags.
  - These fused grouped MLPs always quantize. `TEFusedMLPWithGroupedLinear` uses MXFP8 (or NVFP4 via `FP4_RECIPE`) whatever `fp8` says, and the fused shared expert requires MXFP8 or NVFP4. Both pass 32-wide GLU interleave and 256-row split alignment.
  - So on Blackwell, TE 2.21 runs them as cuDNN CuTeDSL grouped GEMMs (#3584), as older TE did with `NVTE_CUTEDSL_FUSED_GROUPED_MLP=1`.
  - No batch-invariant backend controls those kernels. te_native's workspace limit is cuBLAS-only, and deepgemm and triton replace only TE's `general_gemm` and grouped-GEMM calls.
  - Both features are Blackwell-only in practice, since they need MXFP8 or NVFP4.
  - MoE experts on the op fuser are already rejected under te_native batch-invariant training. MXFP8 inference-optimized experts refuse training forwards, and NVFP4 is rejected in batch-invariant mode.

**Behavior changes that can move golden values.**
- **CuTeDSL fused grouped MLP on SM100 (#3584).**
  - TE 2.21 no longer gates the fusion on `NVTE_CUTEDSL_FUSED_GROUPED_MLP`. It fuses when both GroupedLinears have `split_alignment % 256 == 0` (`ops/fused/grouped_mlp.py:1107`) and the GLU is interleaved 32-wide (`validate_grouped_mlp_dims`).
  - Megatron passes 256 wherever TE accepts `split_alignment`: `TEGroupedMLP` with the op fuser, `TEFusedMLPWithGroupedLinear`, and the fused shared expert (`use_grouped_gemm_for_shared_expert`, which does not go through the op-fuser flag).
  - So MXFP8 and NVFP4 runs of those paths with interleaved GLU on GB200 now run the cuDNN CuTeDSL kernels without the variable, MoE included. Hopper is unaffected.
  - Functional tests that already set the variable (`gpt3_mcore_te_tp1_pp1_te_4experts_groupedGEMM_op_fuser`, `deepseek_proxy_mfsdp_v2_ep2_bf16_cg_optim_1node`) see no kernel change, only a DeprecationWarning.
- **EGTP-sharded experts.** With `expert_gtp_remat_size > 1` and the grouped tensor, these experts now stay on TE's grouped-tensor path instead of the split-quantize fallback. This comes from this PR's gate together with TE #3517.
- **Fused router (#3637).** With sigmoid scores and an expert bias, the fused router takes the selected scores from the unbiased intermediate, so tiny probabilities are no longer rounded away. MoE goldens with `moe_router_fusion` and an expert bias may move.
- **Attention selection (#3313, #3205).**
  - THD training with attention dropout on SM100 and SM103 prefers FA2 over FusedAttention.
  - FA3 and FA4 with `pad_between_seqs` zero the padding rows and their gradients.
  - With the FA4 that Megatron locks today (b24 on main, b29 with #8860), TE's FA4 results are unchanged.
- **Quantization kernels.**
  - RMSNorm with MXFP8 quantize is fully fused by default (#3657). TE's tests show it bit-exact against the unfused path.
  - Grouped MXFP8 quantization fixes (#3599, #3656) and a TMA synchronization fix (#3417).
  - The NVFP4 scale path was refactored (#3325, #3454, #3467). It is expected unchanged for E4M3 scales.
- **Other.**
  - Bias gradients sum over all token dimensions (#3523).
  - LayerNormLinear's Userbuffers all-gather overlap now also runs under `no_grad` (#3546).
  - `moe_single_grouped_weight=True` is now honored without `NVTE_GROUPED_LINEAR_SINGLE_PARAM`. The default is False, so goldens are unaffected.

**Batch invariance.** The CuTeDSL path now reaches two batch-invariant configurations: the dense `TEFusedMLPWithGroupedLinear` and the MoE fused shared expert. This PR closes that gap: `TransformerConfig` rejects both under batch-invariant mode (see **Fix**). It covered dense and MoE alike, and the gap also existed on older TE whenever the variable was set.

- replaces `/opt/nccl-ep/include`;
