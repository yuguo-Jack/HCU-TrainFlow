# [Inference][MTP] Drop the LEGACY accepted-draft refill and test that admitted requests never emit a previous row's drafts

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8565) · state: open · merged: False

# What does this PR do?

Follow-up to #8426, which fixed the MTP bug this PR was opened for. Under the default ASYNC schedule, a request admitted into a reused batch row could start its output with drafts accepted by the row's previous occupant. #8426 makes both prepare-next-forward-pass implementations clear prefill rows, so after merging main this PR no longer changes those kernels. It removes the workaround that is now redundant and adds regression tests that reproduce the original bug end to end.

**Background.** `accepted_tokens_per_request` and `accepted_token_counts_per_request` are indexed by active-batch row and persist across steps. Before #8426 the kernel wrote them only for decode rows, so a prefill row kept the drafts of the decode request that last used it. LEGACY hid this with a per-step refill. ASYNC did not, and `DynamicInferenceEngine._process_request_outputs` prepended the stale drafts to the new request's first token: measured on H100 with every draft accepted, request C generated `[42, 43, 71, …]` instead of `[71, …]`.

**Changes.**
- Remove the LEGACY per-step `fill_(-1)` / `fill_(0)` of both buffers. The kernel now sets every active row on both schedules, so the refill only costs two launches per LEGACY step and would hide a kernel regression from LEGACY.
- Rows past the active ones are no longer reset, so the LEGACY step result, its finalize callback and its prefill-only assertion read `[:active_request_count]`, as the ASYNC path already does.

**Tests.**
- `tests/unit_tests/inference/text_generation_controllers/test_mtp_utils.py` is the determinism test registered for `mtp_utils_triton.py`.
  - New `test_prefill_row_drops_previous_occupant_drafts[pytorch|triton]`. Two steps: a row holds a decode request's accepted drafts, then verifies a prefill. The prefill row must report `[-1, -1]` and a count of 0. Main's `test_mixed_async_prefill_row_clears_false_termination_match` covers only the PyTorch reference.
  - `test_basic` starts from random stale buffers and checks every active row bit-exactly against the reference. It keeps one spare row past the active ones, which must stay untouched, and adds `num_speculative_tokens=3`. With 3 drafts the store block is wider than a row, so dropping the store mask makes the last prefill row write into the spare row; the new case catches that.
- `tests/unit_tests/inference/engines/test_dynamic_engine.py::TestDynamicInferenceEngine::test_speculative_admission_ignores_previous_row_drafts` is end-to-end, with a greedy +1 counter model: the real forward and MTP step run, then their logits are overwritten.
  - It covers both schedules, 1 or 2 speculative tokens, and admission into a reused row or a fresh row. Each request's output must equal its own greedy sequence.
  - The test records the row layout of each verify, so it checks that the intended scenario was reached and cannot pass vacuously.

**H100 results, CI image** (`mcore_ci_dev:main`, torch 2.14, TE 2.20.2):
- At this head, with main `581248531` merged, the regression tests pass 78/78. They also pass on main, which now contains #8426's fix.
- Before #8426 they failed on main in 4 cases: `test_prefill_row_drops_previous_occupant_drafts[pytorch]` and `[triton]`, and `test_speculative_admission_ignores_previous_row_drafts[reused_row-1-async]` (C generated `[42, 71, 72, …]`) and `[reused_row-2-async]`.
- Neighbor tests that pass with this PR: `TestTextGenerationController::test_speculative_verify_tokens` (2 GPUs), `test_speculative_mixed_prefill_decode_heterogeneous_acceptance` and `TestAsyncSchedulePairwise::test_async_matches_legacy_for_owned_pair[mtp-graph-heterogeneous-logprobs]`.
