# Name the MFSDP v2 optimizer's experts by the model's EP layout

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8731) · state: closed · merged: False

## Original PR description

Depends on #8045. Please review the diff from the merge of #8045 into main: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/2038339309...yx/pstate-g17-fsdp2-expert-names).

**Why.** `FullyShardedOptimizer` keys its fsdp_dtensor optimizer state by `get_global_unique_param_name`, which offsets local experts by the global expert-parallel rank and size. A model with its own EP layout then saves and loads its Megatron-FSDP v2 optimizer state under other experts' names. #8045 moves the fsdp_dtensor model state, the distributed optimizer's parameter names and the param-group dump off the global layout, so on a custom EP grid the MFSDP v2 optimizer is the one path whose expert names still disagree with the model's.

**What.** When the model has experts, `FullyShardedOptimizer` passes the EP rank and size from #8045's `get_model_ep_rank_and_size`, which walks the wrapper chain to the model's collection. The MFSDP v2 wrapper holds no collection, so the lookup reaches the wrapped model's. Dense models skip the lookup.

**Tests.**
- New `tests/unit_tests/optimizer/test_fully_sharded_optimizer_param_name.py` builds the optimizer behind a wrapper without a collection. It covers an EP grid unlike the global one, with the global EP reads patched to raise, the standard grid, and a dense model.
- `tests/unit_tests/distributed/mfsdp_v2/test_mcore_moe.py` gains `test_optimizer_names_experts_by_the_model_expert_layout`, which used to sit in #8749. It records the keyword arguments the optimizer passes to `get_global_unique_param_name` and checks that every call carries the rank and size of the collection's EP group. Like the other tests in that file, it needs CUDA and an even world size of at least two.

On 4 GPUs against its base (main with #8045 merged): `test_fully_sharded_optimizer_param_name.py` passes its 3 new tests; the file does not exist on the base. `test_mcore_moe.py`: 5 passed here vs 4 on the base, and the 1 new test passes. `test_fsdp_dtensor_expert_offsets.py`: 8 passed on both sides. No test regresses and no test fails on either side. Before the sync, the 3 param-name tests run against #8045's head failed the custom-grid case and passed the other two. Before the sync, on 4 CPU gloo ranks the param-name tests stopped on CUDA, and the mfsdp_v2 tests could not be collected, here and on #8045 alike. In the integration run, this PR's test files show no regressions against main: `test_mcore_moe.py` passes 5 tests vs 4 on main, and the 3 param-name tests pass.

**Compatibility.** Names on the standard grid are unchanged, so checkpoints saved on the standard grid load unchanged. A checkpoint saved on a custom EP grid before this change used global-layout names and will not match. When no wrapper level has a `pg_collection`, `get_model_ep_rank_and_size` returns `(None, None)` and the names keep the global-layout fallback. The `determinism-exempt` label is needed only because #8045's change to `megatron/core/optimizer/__init__.py` is in this branch's base.
