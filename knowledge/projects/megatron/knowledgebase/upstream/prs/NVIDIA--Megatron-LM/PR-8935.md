# feat(attention): Batch-invariant all-to-all context parallelism

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8935) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

**Batch-invariant mode now supports context parallelism (CP > 1) in training, with the training forward bitwise equal to the CP=1 forward.** RL can train long contexts with CP while generation keeps running at CP=1, and a token's training log-prob still equals its generation log-prob.

Before this PR, `batch_invariant_mode` rejected `context_parallel_size > 1`: TE's context-parallel attention runs its own FlashAttention-2 kernels, which batch-invariant mode cannot pin to FlashAttention 3 or 4 with a fixed `num_splits`. The target is Nemotron-3-Nano (Mamba + FA4) at CP=4.

No new config option: the existing `cp_comm_type='a2a'` selects the path.

**Validated end to end:** in a Nemotron-3-Nano MXFP8 RL run training at TP2×CP4 with generation at CP=1, the training log-probs equal the generation log-probs exactly (zero log-prob difference).

## How it works

Under `batch_invariant_mode` with CP > 1, `TEDotProductAttention` does the CP exchange itself and calls TE as if CP were 1:
1. Each CP rank trades its load-balanced sequence shard of every head for the full sequence of 1/CP of the heads (all-to-all), and restores the original token order.
2. TE's CP=1 attention runs on that, built with `num_attention_heads / CP` heads and no CP group. Each head sees the same FA4 call, on the same full sequence, as without CP, and a head's output does not depend on how many other heads are in the call.
3. The output goes back through the reverse exchange to the rank's original sequence shard.

K/V heads:
- **Split** like the query heads when the K/V groups per TP rank divide by CP.
- **Gathered** otherwise (CP divisible by the groups per TP rank): each rank all-gathers the full sequence of K/V and keeps the one K/V head its contiguous query heads share. Nano at TP1×CP4 (2 K/V groups) and at TP2 (1 K/V group per TP rank) take this path.

The sequence/head exchange and the load-balancing reorder reuse the helpers from `MambaContextParallel`, which already does the same exchange for Mamba heads. MoE is per-token and needs no change.

## What is changed

- `TEDotProductAttention`:
  - `__init__`: under batch-invariant CP, builds TE with this rank's share of the heads, sets `num_gqa_groups` for the split or gathered K/V layout, and skips TE's CP setup. Asserts that the heads per TP rank divide by CP, that the K/V groups per TP rank divide or are divided by CP, `softmax_type='vanilla'`, and no `qk_clip` / `log_max_attention_logit`.
  - `forward` hands off to the new `_a2a_cp_forward` for the exchange above. It supports `sbhd` and packed `thd`, and rejects `attention_bias` and dynamic CP.
- `TransformerConfig`: batch-invariant mode with CP > 1 now requires every `cp_comm_type` to be `'a2a'` and no `hierarchical_context_parallel_sizes`, replacing the blanket CP=1 assertion.
- Generation is unchanged: it runs at CP=1 and never enters the new path.

## What is tested

`tests/unit_tests/transformer/test_batch_invariant_a2a_context_parallel.py`, a 3-layer `HybridModel` (Mamba, attention, then MLP or MoE) under `batch_invariant_mode` with the `te_native` backend, FA4 and pinned kernel configs. The CP model loads the weights of a CP=1 model at the same TP size, and each rank runs its load-balanced shard. With TP > 1, sequence parallelism is on, as in training.
1. **Forward bitwise equal to CP=1**, in `sbhd` and packed `thd`:
   - Small model (8 heads) at TP1: 8, 2 and 1 K/V groups at CP=2 and CP=4, covering both the split and gathered K/V paths.
   - Nano-shaped model at TP1×CP4: 32 query heads, 2 K/V groups, head dim 128; Mamba 64 heads of dim 64 in 8 groups; a squared-ReLU MoE layer (8 experts, top-6, FFN 1856); vocab 131072.
   - TP2×CP2 against TP2×CP1: the small model with 8 K/V groups (4 per TP rank, split) and with 2 (1 per TP rank, gathered), and the Nano-shaped model (1 K/V head and 32 Mamba heads per TP rank).
   - On a mismatch, the test names the first decoder stage (layer, final norm or output layer) that diverges.
2. **Gradients match CP=1** for the Nano-shaped model at TP1×CP4 and TP2×CP2, in `sbhd` and `thd`: parameter gradients summed over CP (and, for weights replicated across TP, over TP in both models) are within 1% relative error of the CP=1 gradients for every parameter. The backward reduces in a different order under CP, so this is not bitwise.
3. **Config:** non-`a2a` CP is rejected.

## Performance

A Nano-shaped slice of one Mamba, one attention and one MoE layer (hidden 2688; 32 query heads, 2 K/V groups; 64 Mamba heads; 128 experts, top-6, shared expert 3712; all-to-all dispatcher), GB300 × 4, eager, median of 5 iterations. One sample of the given length is split across the CP group, so with 4 GPUs CP=1 runs 4 samples in parallel and CP=4 runs 1. Time is per sample; peak is the memory allocated during the step on top of the weights. Both modes pin the Mamba kernel configs, so they differ in attention and the GEMMs.
- **This PR:** `batch_invariant_mode`, FA4, `te_native` backend, `cp_comm_type='a2a'`.
- **Default:** no batch invariance, TE's own attention backend selection and TE's own CP: `a2a` at CP=2. At CP=4, TE's `a2a` rejects Nano's 2 K/V heads (it needs the K/V heads to divide by CP), so the default runs TE's ring (`p2p`) there.

- **Log-prob:** 1–8% slower than the default, from FA4's fixed `num_splits=1` and the starved GEMM workspace that batch invariance needs.
- **CP scaling:** at 256k, CP=4 runs one sample 3.6× faster than CP=1, at about 10% lower throughput per GPU.

## Limitations

- `cp_comm_type='a2a'` only; p2p, all-gather and hierarchical CP are rejected.
- The gathered K/V path all-gathers every K/V group per TP rank and keeps one, e.g. 2× the needed K/V traffic for Nano at TP1×CP4 (none at TP2, with one group per TP rank).
- Verified for Mamba, standard attention, MLP and MoE layers; not for GDN, KDA, DSA or MLA.

### [P2] Restore packed K/V using their own sequence boundaries

**Failure.** Both K/V exchange branches in [`_a2a_cp_forward`](https://github.com/NVIDIA/Megatron-LM/blob/696c8b0ffc6e1f71c983142fda7232eabb333dfe/megatron/core/extensions/transformer_engine.py#L2750-L2797) reuse Q's packing metadata. The reused [reordering helper](https://github.com/NVIDIA/Megatron-LM/blob/696c8b0ffc6e1f71c983142fda7232eabb333dfe/megatron/core/ssm/mamba_context_parallel.py#L382-L394) reads only `cu_seqlens_q_padded`, falling back to `cu_seqlens_q`. That works for self-attention, but the wrapper also accepts cross-attention and forwards independent Q and K/V boundaries to TE.

For example, use TP1×CP2, four Q and K/V heads, packed `thd`, Q boundaries `[0, 4, 16]`, and K/V boundaries `[0, 8, 16]`, with padded boundaries equal to those arrays. Every sequence length divides by `2 * CP`. K/V sharded using their own boundaries should reconstruct token order `[0, ..., 15]`; the Q-based permutation instead reconstructs `[0, 2, 3, 1, 6, 7, 8, 4, 5, 10, 11, 12, 13, 9, 14, 15]`. TE therefore receives incorrect K/V sequence membership and produces incorrect attention. This follows from the inspected permutations; it wasn't executed.

**Correction.** Restore each tensor with the boundaries used to partition it. Keep Q metadata for Q and output redistribution, but use K/V metadata in both K/V branches. A suggested structural patch to `_a2a_cp_forward` is below. The lightweight metadata object is sufficient because the inspected helper reads only those two fields; `_forward` must still receive the original complete metadata. Verify this patch before adopting it.

[P2] Fail the gradient check when the error is non-finite

If either compared parameter gradient contains NaN, the [relative-error calculation](https://github.com/NVIDIA/Megatron-LM/blob/696c8b0ffc6e1f71c983142fda7232eabb333dfe/tests/unit_tests/transformer/test_batch_invariant_a2a_context_parallel.py#L423-L431) produces NaN. `NaN > 1e-2` is false, so the parameter isn't added to `mismatched` and this gradient test can pass invalid gradients. Reject non-finite errors as well as finite errors above the tolerance:

```suggestion

```

This preserves the per-parameter 1% criterion and the denominator clamp that lets two zero gradients pass. Verify the suggestion before adopting it.

Acceptance checks (proposed, not executed): NaN or infinity in either gradient must fail; equal finite gradients and two zero gradients must pass; finite relative errors of 0.005 and 0.02 must respectively pass and fail. Retain gradient-key equality and both TP/CP configurations.
