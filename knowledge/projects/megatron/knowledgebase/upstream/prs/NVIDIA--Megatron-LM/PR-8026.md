# Create the global memory buffer on first use

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8026) · state: closed · merged: False

## Original PR description

## Why

The global memory buffer is per-process scratch memory for the sequence-parallel all-gather, local attention and the MoE allgather dispatcher. It uses no process group, but only `initialize_model_parallel()` created it, so a model built on its own `ProcessGroupCollection` failed in its first sequence-parallel linear or local-attention forward with "global memory buffer is not initialized".

## What

- `megatron/core/utils.py` owns the buffer: `get_global_memory_buffer()` creates it on first use and `destroy_global_memory_buffer()` drops it.
- `parallel_state` re-exports both, so call sites are unchanged. `destroy_model_parallel()` still resets the buffer; `initialize_model_parallel()` no longer creates it.
- `_set_global_memory_buffer()` stays for external callers and no longer asserts that the buffer is new.

## Tests

New `tests/unit_tests/test_global_memory_buffer.py`, run after `destroy_model_parallel()`: sequence-parallel Column/RowParallelLinear forward and backward on their own TP group (TP 2 and 4, exact against a dense reference), the global-buffer all-gather, local `DotProductAttention`, creation and reset, keeping a buffer sized before `initialize_model_parallel()`, and calling `_set_global_memory_buffer()` twice. Before the 2026-11-01 sync, 7/7 passed on 4 GPUs and failed on main. Before the sync, existing parallel_state, utils, tensor_parallel and core-attention tests gave the same results as on main, and the sequence-parallel MTP CUDA-graph inference tests passed. In the integration run (main 77391e71cc with all #6307 PRs merged, against main), `test_global_memory_buffer.py` passes 7/7 on 4 GPUs (main has no such file).

## Compatibility

There is still one buffer per process, so the dynamic engine's pre-sizing before CUDA-graph capture is unchanged. The private `parallel_state._GLOBAL_MEMORY_BUFFER` is removed: Megatron-Bridge reads it with a `None` default and keeps working, but one Bridge unit test monkeypatches it and needs a one-line update.

The branch was synced with main 77391e71cc on 2026-11-01 by a merge commit with no conflicts, so existing commits and review links stay valid. The merge also updates the process-group allowlist with the reads main added since this PR was written.
