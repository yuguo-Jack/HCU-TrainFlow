# What does this PR do?

Gives MoE layers of an inference-optimized MLA model their pre-MLP norm.

**Bug.** #3496 added MoE support to `get_gpt_layer_with_inference_submodules`, with a pre-MLP norm (`backend.layer_norm()`) when `num_experts` is set. Only the standard-attention branch got it. The MLA branch still sets `pre_mlp_layernorm=IdentityOp`.

A dense MLP normalizes its input inside its layer-norm-fused `linear_fc1`, so `IdentityOp` is right there. MoE experts have no fused norm. So with `transformer_impl=inference_optimized`, every MoE layer of an MLA model (e.g. DeepSeek-V3-style) runs its router and experts on the unnormalized residual stream. No error is raised. The Transformer Engine MLA spec, which these models are trained with, has the norm.

**Fix.** The inference spec now chooses the pre-MLP norm once, before it branches on the attention type, so the MLA and standard-attention layers share one rule and cannot drift apart again. The norm is declared with `has_residual=True`, like the MLA input norm and the Transformer Engine spec. That changes no module today, since the inference backend ignores `has_residual`.

**Checkpoints.** Each MLA MoE layer built from this spec now has a `pre_mlp_layernorm` module, so its state dict gains `pre_mlp_layernorm.weight` (e.g. `decoder.layers.N.pre_mlp_layernorm.weight`, plus `.bias` with LayerNorm). Checkpoints trained with the Transformer Engine MLA spec already carry this key and need no change. A checkpoint saved from an inference-optimized MLA MoE model before this PR, or a converter that emits keys from the old inference spec, lacks it, and strict dist-ckpt loading reports it as missing. Such a checkpoint never held the trained norm weights; re-export it from the training checkpoint.

**Tests.** `tests/unit_tests/models/test_gpt_layer_specs.py`:
- `test_moe_layers_normalize_the_mlp_input` checks that MoE layers get the same pre-MLP norm with and without MLA, and that dense layers get none.
- `test_norm_slots_match_the_transformer_engine_spec` checks, slot by slot, that every norm slot of the inference layer spec and of its self-attention holds a norm exactly where the Transformer Engine spec does, for MLA and standard attention, dense and MoE layers, with and without `qk_layernorm`. This guards against the inference spec diverging from the spec checkpoints are trained with.

Both are spec-only (no kernel runs) and skip without Transformer Engine. On `main`, the MLA MoE cases fail (3 of 10); with this PR all pass.

On H100 in the CI image, `test_moe_layers_normalize_the_mlp_input` fails on `main` (1 case, MLA) and passes with this PR (2 cases); the neighbor test `tests/unit_tests/models/test_moe_module_specs.py` passes (4 cases). With the review changes (dfw 21004395), `test_gpt_layer_specs.py` passes 10 cases with this PR and fails 3 on `main`, exactly the MLA MoE cases; the neighbor test passes (4 cases). The 57-task inference-vs-training matrix passes on integration trees of current `main` with every open fix (dfw 21004395, 21007036).
