# Enable `unshard_all_planes_in_backward` in MFSDPv2's adaptor when necessary

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8839) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

  Follow-up to #8432: the MFSDP v2 MCore adapter enables `SchedulePolicy.unshard_all_planes_in_backward` for the FSDP units whose MXFP8 weights are used by activation recomputation that does not call the unit's forward hooks. Without it, MXFP8 training fails in backward with `Requested row-wise usage, but MXFP8Tensor is missing
  row-scaled FP8 data`.

  A unit is opted in when a module it owns (excluding nested units) reruns a checkpointed part that contains parameters:
  - **Selective recompute**: checked through the flags layers set at construction (`_SELECTIVE_RECOMPUTE_FLAGS`): `recompute_mlp`, `moe_layer_recompute`, `shared_experts_recompute`, `recompute_up_proj`, `recompute_gdn`, `recompute_in_proj`.
  - **Full recompute**: GPT MTP layers checkpoint `eh_proj` inside their own forward, so the unit owning the MTP layer (the root by default) is opted in. Hybrid MTP layers are not, since their inner layers are units.

  Expert units and units whose recompute reruns only parameter-free modules (e.g. `core_attn`, `moe_act`, an `IdentityOp` MLP) are not opted in.

  Note: the selection reads each layer's recompute flags, so a new in-layer checkpoint that uses the layer's weights must be added to `_SELECTIVE_RECOMPUTE_FLAGS`. If one is missed, MXFP8 training fails with the error above rather than producing wrong results.

  ## Tests

  - `test_unshard_all_planes_in_backward_follows_recompute` (dense/MLA/hybrid) and `test_unshard_all_planes_in_backward_follows_moe_recompute` (MoE, EP=2) check the
  opted-in units for each recompute mode.
  - `test_mxfp8_recompute_matches_no_recompute` (Blackwell) checks that MXFP8 recompute gives bit-exact loss and gradients versus no recompute for dense `mlp`/`full` and
  MoE `shared_experts`/`moe`. On main these fail with the row-scaled error.

I found two gaps in recomputation-unit selection that leave supported MXFP8 configurations on the missing-row-plane failure path. I inspected all four changed files and their directly affected checkpoint/FSDP paths. I didn't execute tests; the patches and acceptance checks below need verification.

### 1. Honor each layer's recomputation configuration

The granularity guards in [recomputed_submodules](https://github.com/NVIDIA/Megatron-LM/blob/35d25879e218d24ec98ab3b3fe5987dc351472b9/megatron/core/distributed/fsdp/mcore_adapter_v2.py#L156-L176) use the root adapter config. However, HybridModel supports independent configurations through `hybrid_layer_config_list`, and [HybridStack constructs each layer with its own config](https://github.com/NVIDIA/Megatron-LM/blob/35d25879e218d24ec98ab3b3fe5987dc351472b9/megatron/core/models/hybrid/hybrid_block.py#L312-L321).

**Failure:** Give a one-layer HybridModel a root config with `recompute_granularity=None` and an `MLPLayerConfig` with selective `mlp` recomputation. The layer sets `recompute_mlp=True` and [checkpoints its MLP](https://github.com/NVIDIA/Megatron-LM/blob/35d25879e218d24ec98ab3b3fe5987dc351472b9/megatron/core/transformer/transformer_layer.py#L1476-L1484), but this helper returns before inspecting that flag. With MXFP8 parameter gather, the layer's backward unshard therefore omits rowwise planes required by replay.

**Correction:** Make both granularity guards follow the configuration that created the module's checkpoint behavior. Proposed changes inside `recomputed_submodules`:

```diff
     def recomputed_submodules(module: nn.Module) -> list[nn.Module]:
-        if config.recompute_granularity == "full":
+        module_config = getattr(module, "config", config)
+        if module_config.recompute_granularity == "full":
@@
-        if config.recompute_granularity != "selective":
+        if module_config.recompute_granularity != "selective":
```

Changing only the selective guard would still miss selective layers beneath a full-recompute root. Keep the existing flag checks, nested-unit ownership boundary, parameter-free exclusion, and GPT-versus-hybrid MTP distinction.

**Acceptance:** Add a HybridModel case with a non-recomputing root and one selectively recomputed MLP layer; assert `recompute_mlp is True` and that `decoder.layers.0` is the sole opted-in unit. Repeat classification with a full-recompute root and selective layer. Conversely, a non-recomputing layer under a selective root must remain excluded. On at least two Blackwell ranks with MXFP8 parameter gather, the first configuration should complete backward and match a no-recompute reference's loss and local gradient shards bit-exactly. Retain the [existing selective-MLP expected-unit assertion](https://github.com/NVIDIA/Megatron-LM/blob/35d25879e218d24ec98ab3b3fe5987dc351472b9/tests/unit_tests/distributed/mfsdp_v2/test_mcore_dense.py#L195-L201) and the [MoE `moe_act` empty-set assertion](https://github.com/NVIDIA/Megatron-LM/blob/35d25879e218d24ec98ab3b3fe5987dc351472b9/tests/unit_tests/distributed/mfsdp_v2/test_mcore_moe.py#L286-L295).

### 2. Recognize full-recompute stacks with custom unit boundaries

The [full-recompute branch](https://github.com/NVIDIA/Megatron-LM/blob/35d25879e218d24ec98ab3b3fe5987dc351472b9/megatron/core/distributed/fsdp/mcore_adapter_v2.py#L157-L162) recognizes only GPT MTP. Explicit unit lists replacing the defaults are part of the [adapter's supported contract](https://github.com/NVIDIA/Megatron-LM/blob/35d25879e218d24ec98ab3b3fe5987dc351472b9/megatron/core/distributed/fsdp/mcore_adapter_v2.py#L219-L224).

**Failure:** Build an MXFP8 GPT model without MTP, enable full uniform recomputation, and pass `fsdp_unit_modules=[]` or `[TransformerBlock]`. No unit opts in. Yet [checkpoint replay calls the individual layers](https://github.com/NVIDIA/Megatron-LM/blob/35d25879e218d24ec98ab3b3fe5987dc351472b9/megatron/core/recompute.py#L80-L134), bypassing the owning root/block's forward hooks. Backward still gathers only columnwise weights, so replay encounters the row-scaled-data error this PR fixes for default boundaries.

**Correction:** Recognize the layer subtrees replayed by TransformerBlock and HybridStack, then retain the existing intersection with owned modules. Add lazy imports for those classes beside the MTP import. Within the full-recompute branch, using the stack's own config, add before the MTP case:

```python
if isinstance(module, (TransformerBlock, HybridStack)):
    if module.config.recompute_method == "block" and not module.config.recompute_num_layers:
        return []
    return list(module.layers)
```

For nonzero block recomputation, inspecting all layers is conservative: [FP8 can shift the checkpoint window at runtime](https://github.com/NVIDIA/Megatron-LM/blob/35d25879e218d24ec98ab3b3fe5987dc351472b9/megatron/core/recompute.py#L226-L240). The invariant is that replayed weights whose owning unit isn't re-entered have both planes available; nested layer units must remain excluded by ownership.

**Acceptance:** Add full-uniform cases without MTP for `[]` and `[TransformerBlock]`. Expect the root and `decoder`, respectively, to opt in, and MXFP8 backward loss/local gradient shards to match no recomputation bit-exactly on at least two Blackwell ranks. Preserve empty selection with default layer units, GPT MTP projection-owner selection, default Hybrid MTP exclusion, no-recompute behavior, and zero-layer block recomputation.
