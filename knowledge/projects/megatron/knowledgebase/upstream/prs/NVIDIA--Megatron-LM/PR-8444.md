# What does this PR do?

Migrate VLM model settings and shared training consumers to their config owners, while preserving application-local data and packing arguments.

**Stacked on #8234.** Base: `pull-request/8234`. The training `model_type` API cleanup is separate in #8797; the two PRs are siblings and do not depend on each other. Retarget this PR before merging/deleting the parent branch.

- LLaVA owns image geometry, class-token dropping, and component freezing; MIMO owns the corresponding vision geometry. Data preprocessing and online evaluation consume those same model settings. Workers retain only scalar preprocessing inputs, not the runtime config.
- `cfg.train.vision_pretraining_type=None` means disabled, replacing the redundant enable/type pair. Existing CLI flags and defaults are unchanged.
- Decoder overlap uses `cfg.model.transformer.tp_comm_overlap`, without another overlap config field. The mock-VLM CLI adapter resolves the existing text-plus-image padding formula before user-buffer initialization, preserving the distinction between the legacy CLI switches when determining length.
- **All sequence-length arguments will be migrated in a separate PR**, including `seq_length`, `decoder_seq_length`, and `dataloader_seq_length`. This PR does not migrate their ownership. Application callbacks retain their existing argument reads and signatures; `set_vlm_sequence_lengths()` temporarily preserves the startup ordering needed for user-buffer sizing. No competing dataset schema is introduced ahead of #8341.
- The shared inference caller of the mock model provider is adapted; broader inference/conversion argument migration is not included.

One intentional startup correction: decoder-only TP overlap now initializes the required user buffers, rather than potentially skipping initialization because only the older global overlap flag was checked.
