**Depends on #6326; merge #6326 first.** This follows the [maintainer's requested sequence](https://github.com/NVIDIA/Megatron-LM/pull/8004#issuecomment-6182858386). The review base is `pull-request/6326`, at `02237350dd9d743129b6a4769273546a36be2f0b`.

**Retarget this PR to `main` before merging #6326 or deleting its bot mirror. Merge this PR only after #6326 lands. Do not merge into the bot mirror branch.**

This PR adds semantic optimizer routing on top of #6326's per-head QKV/MLA support. It reuses the owning-layer `QKVLayout`, existing optimizer tagging, TP/GTP gather/restore helpers, and the shared split executor. Standard all-Muon QKV and MLA up projections retain the dependency's path. No separate QKV splitting implementation is introduced.

```bash
--optimizer muon --muon-split-qkv-per-head --use-distributed-optimizer
```

The per-head flag remains opt-in. Without it, the dependency's default behavior is preserved, including its default MLA up-projection splitting. `--muon-no-split-qkv` retains whole-matrix MLA updates. With the flag, attention output gates use AdamW instead of the dependency's per-head gate Muon.

## Incremental functionality

| Projection | Muon updates | AdamW updates |
| --- | --- | --- |
| Attention with an output gate | Q/K/V heads, using shared QKV boundaries | Output gate |
| GDN1 | Independent Q/K/V heads | z, beta, alpha |
| GDN2 | Independent Q/K/V heads, from the variant's actual sections | z, f, b, w |
| Dense SwiGLU FC1 | Separate gate/up matrices | None |
| MLA down projections | Separate latent/RoPE matrices; fused Q/KV blocks restored to physical TP order | None |

GDN1/2 support and its regressions remain in this PR. The model retains fused parameters, forward GEMMs and checkpoint names. Equal-shaped matrices use independent batched NS; control rows never enter NS. Raw gradients, configured Adam betas/epsilon, scheduled group LR and decoupled decay drive the AdamW slices. Global gradient clipping is unchanged.

The documented Muon CLI selects whole-parameter `LayerWiseDistributedOptimizer` ownership. FP32 masters preserve layouts. The previous review fixes are retained: flattened semantic parameters and per-head + Kitchen fail explicitly; public Kitchen configuration tests do not claim to validate the unavailable backend.

## Compatibility and remaining validation

- Mixed AdamW routing supports plain Muon with decoupled decay. Mixed AdaptiveMuon/coupled-L2, per-head `layer_sharded`, Kitchen and grouped MoE FC1 layouts are outside the supported combination.
- Parameter-shaped Adam moments increase optimizer-state memory. Incompatible all-Muon/older semantic checkpoints need a fresh optimizer (`--no-load-optim`). Per-parameter update counters are retained, including absent gradients.
- Ordinary optimizer state-dict resume and sharded-state conversion are tested. Full training, official GPU CI, native distributed on-disk checkpoint save/load/resume and topology-changing resume are not claimed. Distributed checkpoint conversion requires equal parameter step counters.
- No universal loss or speed improvement is claimed. See [the design and compatibility notes](https://github.com/Hollyming/Megatron-LM/blob/feat/per-head-muon/docs/per_head_muon.md).

File: `megatron/core/optimizer/emerging_optimizers.py` · line 474

This semantic path assumes that every optimizer parameter remains a 2-D row-sharded projection, but `DistributedOptimizer` replaces each model parameter in the inner optimizer's `param_groups` with a flattened 1-D data-parallel shard (see `distrib_optimizer.py:509-511` and `:593-603`). On the first step, `_semantic_plan` therefore uses `p.shape[0]` as a row count and later accesses `grad.shape[1]`, so `--use-distributed-optimizer` will either reject a valid projection layout or fail on the flattened gradient instead of applying per-head updates. Preserve the original 2-D shape and shard offsets for semantic parameters, or explicitly reject this mode before constructing the distributed optimizer.

This issue also appears on line 495 of the same file.
