# What does this PR do?

Build the dataset on TP rank 0 of every pipeline stage when a sequence-packing scheduler is enabled, fixing a crash on middle pipeline stages with PP >= 3.

:warning: For major changes (either in lines of code or in its impact), please make sure to first share a design doc with the team. If you're unsure what's the best way to do so, contact `@NVIDIA/mcore-oncall`.

#8378 limited `is_dataset_built_on_rank` to the first and last pipeline stages when a sequence-packing scheduler is enabled. At that time, `BasePackingScheduler.run()` packed on those stages and broadcast the packing metadata to the middle stages.

#7047, merged after #8378, removed that broadcast. TP rank 0 of every stage now reads its own batches and runs the same schedule locally ("Every PP stage owns the packed dataset on TP rank zero"), but `is_dataset_built_on_rank` was not updated. With PP >= 3 and either `dp_balanced` or `default_dynamic_cp`, the middle stages therefore have no data iterator. `run()` takes its `data_iterator is None` branch and fails on the first iteration at `int(num_micro_batches)`, or, with TP > 1, when it builds the broadcast tensor from `None`. Existing coverage uses PP = 2, which has no middle stage.

Changes:

- `pretrain_gpt.py`, `pretrain_hybrid.py`: when a packing scheduler is enabled, build the dataset on TP rank 0 of every pipeline stage, as the packed-sequence path already does without a scheduler. This also covers a scheduler used with a dataset for which `is_packed_sequence` is `False`.
- `tests/unit_tests/data/test_get_batch.py`: update `test_packed_sequence_dataset_built_on_rank` to the new rule and add the scheduler case with `is_packed_sequence=False`.

Not run locally; the updated unit test needs 8 GPUs (TP2 x PP4).

#8341 moves this predicate to `megatron/training/datasets/providers.py` and carries the old rule over, so whichever of the two PRs lands second needs to include this change.
