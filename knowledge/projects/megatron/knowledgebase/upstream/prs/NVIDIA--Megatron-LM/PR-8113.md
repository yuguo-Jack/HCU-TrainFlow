# fix: Defer frozen MFSDP cleanup without input gradients

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8113) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

An MFSDP unit owning only frozen weights can still contain a separately sharded trainable child. If the unit's inputs do not require gradients, PyTorch fires its full backward hook when output gradients arrive. Resharding there frees frozen weights before internal backward consumes them to compute the child's gradients.

For ordinary backward, defer that unit's completion callback until the final autograd callback. Weight cleanup runs after every microbatch; automatic gradient synchronization runs only on the last microbatch, using the existing `microbatch(context, is_last=False)` scope to skip intermediate waits. An ordinary standalone backward still synchronizes automatically.

The combined 1F1B scheduler bypasses the root's autograd completion callback, so it calls `context.post_backward()` after each microbatch's full backward schedule completes. `finish_grad_sync()` only waits for submitted gradient reductions; MCore retains its explicit final synchronization after all backward work, including delayed weight gradients.

Fixes #7823. Trainable units retain their existing parameter-countdown completion timing.

## Validation

- The frozen-weight regression reuses #7822's two-layer setup. Saved-tensor hooks detect premature storage release before CUDA reads it. It checks frozen-weight release after each of two microbatches and the accumulated trainable-weight gradient. The original regression fails on unchanged `main` (`3140ce462`) and passes with the fix on all four ranks (NSC-LHR job 150819).
- The existing sibling-roots test verifies no automatic `finish_grad_sync()` call after a non-final microbatch and exactly one after the final microbatch. It fails before the synchronization change on all four ranks (job 185452).
- The full MFSDP v2 suite passes on four NSC-LHR GB300 GPUs: **257–263 passed, 2–8 skipped per rank**, with no failures (job 185791, commit `5cacf6ee6`, based on `main` at `8c815a4c9`). The existing separate-stream ZeRO-2 overlap test observes **7 of 8** reduce-scatters overlapping compute, up from **6 of 8** before skipping intermediate waits.
- A two-microbatch combined 1F1B smoke check with MFSDP v2, expert parallelism, and delayed weight gradients confirms two context cleanup calls, no automatic gradient wait, one explicit final wait, and finite gradients on all four ranks (job 185791).
- Context and parameter tests pass after simplifying coverage: **23 passed on each of four NSC-LHR GB300 GPUs** (job 185876, commit `10de87f07`).
- Black, isort, pylint, Ruff, and `git diff --check` pass. Mypy is unavailable in the CI container.

> Are you delaying the weight reshard until the entire model's backward pass is complete (from how I read post_backward and the 1F1B schedule)?

Post-backward is delayed only when none of the input activations require grads. This normally happens only for the first layer (therefore the last of the backward). So I believe in practice post-backward is only delayed slightly. 

```
            def grad_checking_post_backward_hook(module, grad_input, _grad_output):
                if all(grad is None for grad in grad_input):
                    # With no input gradients, this hook runs before internal backward.
                    module.context._delayed_post_backward_callbacks.append(
                        (module, post_backward_hook)
                    )
                else:
                    post_backward_hook(module)
```
