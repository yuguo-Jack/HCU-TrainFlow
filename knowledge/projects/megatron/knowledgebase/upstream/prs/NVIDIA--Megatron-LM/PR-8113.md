# fix: Defer frozen MFSDP cleanup without input gradients

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8113) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

An MFSDP unit owning only frozen weights can still contain a separately sharded trainable child. If the unit's inputs do not require gradients, PyTorch fires its full backward hook when output gradients arrive. Resharding there frees frozen weights before internal backward consumes them to compute the child's gradients.

Defer that unit's completion callback until the final autograd callback. The combined 1F1B scheduler registers the final callback from its backward pre-hook because it calls `unshard()` directly and bypasses `pre_backward()`. Caller-managed gradient synchronization remains explicit; the final callback still performs deferred weight cleanup.

Fixes #7823. Extracted from #7902 as an independent fix against `main`. Trainable units retain their existing parameter-countdown completion timing; this PR does not introduce separate `post_backward` and `post_accumulate_grad` callbacks.

## Validation

- The single regression reuses #7822's two-layer setup. Saved-tensor hooks detect premature storage release before CUDA reads it; the test checks successful backward, the trainable weight gradient, and eventual frozen-weight release.
- On four NSC-LHR GB300 GPUs, the simplified test fails on unchanged `main` (`3140ce462`) because frozen weight storage is released too early, and passes with the fix on every rank (job 150819).
- Before this test-only simplification, the full MFSDP v2 suite passed on four NSC-LHR GB300 GPUs: **259–260 passed, 1–2 skipped per rank** (job 149752).
- Black, isort, pylint, Ruff, and `git diff --check` pass. Mypy is unavailable in the CI container.
