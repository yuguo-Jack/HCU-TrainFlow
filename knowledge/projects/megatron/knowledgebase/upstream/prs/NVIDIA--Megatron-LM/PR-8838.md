# What does this PR do?

Adds the central "configuration errors" troubleshooting page requested in #5766, plus the CPU-only
tests that verify every example in it.

`TransformerConfig.__post_init__` validates the interactions between tensor, pipeline, context,
expert and sequence parallelism, and the resulting error names the offending attribute but not the
invariant behind it. The new page covers seven failures that come up often, and for each one shows:

- the minimal invalid configuration,
- the exact error text,
- the invariant being enforced, and
- a corrected configuration.

The seven cases:

| Attribute | Error |
|---|---|
| `num_attention_heads` | must be a multiple of `tensor_model_parallel_size` |
| `num_query_groups` | must be a divisor of `num_attention_heads` |
| `sequence_parallel` | requires tensor parallelism |
| `pipeline_dtype` | required when `pipeline_model_parallel_size > 1` |
| `attn_logit_softcapping` | must be a positive finite value |
| `pipeline_model_parallel_layout` | excludes the other pipeline layout arguments |
| `virtual_pipeline_model_parallel_size` | must match the layout |

The page ends with a short section on how to locate an invariant for a failure that is not listed,
pointing at `__post_init__` and noting that constructing the config is enough to reproduce a
validation failure.

## Two content decisions worth reviewing

**`hidden_size` is intentionally absent.** It looks like it should be an invariant next to
`num_attention_heads`, but it is derived from the head configuration and does not raise on its own
(`hidden_size=500, num_attention_heads=4, tensor_model_parallel_size=4` constructs fine). Listing it
would have documented a check that does not exist.

**The last two sections use a small layout string on purpose.** The parallelism guide uses
`Et*3|(tt|)*29,m|L`, which encodes 61 decoder layers. On a `num_layers=4` example that string fails
for an unrelated reason, so the snippets here use `E|tt|tt|L` with
`pipeline_model_parallel_size=2` and can be pasted and run as-is.

## Scope

Documentation only; no behaviour change. The acceptance criteria asked for 5-8 failures verified by
a CPU-only config-construction test or an existing unit test, and all seven are covered by the new
test module.
