# [dev] feat(mla): Fuse the elementwise MLA output gate in Triton

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8939) · state: closed · merged: False

## Original PR description

Add megatron/core/fusions/fused_attention_output_gate.py: one Triton kernel for the forward of core_attn_out * sigmoid(gate.float()).to(core_attn_out.dtype) and one for its backward (both input gradients), replacing the eager four- and six-kernel compositions of the elementwise MLA output gate. The kernels replay the eager operations with the same intermediate roundings (libdevice expf and an explicit non-FTZ div.rn.f32 for the FP32 sigmoid, because Triton builds libdevice with flush-to-zero and would drop the subnormal sigmoid outputs of gate logits near -88; the scale rounded to the activation dtype before the multiply; the MulBackward / cast / SigmoidBackward order in backward), so outputs and gradients are bit-identical to the eager gate, and only the two inputs are saved for backward. The eager composition keeps the FP32 sigmoid output and the cast scale alive until backward: +2.25 GiB per pipeline stage and in-flight microbatch at 32K tokens x 3072 local channels, the device-memory regression that the eager gate (#8006) brought in.

The fusion is opt-in through TransformerConfig.attention_output_gate_fusion (--attention-output-gate-fusion). It requires attention_output_gate with gated_attention_proj_granularity='elementwise', multi_latent_attention and Triton >= 3.0; the headwise gate and regular attention keep their existing paths. The new helper apply_elementwise_attention_output_gate_before_cast dispatches between the eager composition and the Triton kernels; both MultiLatentAttention and AbsorbedMLASelfAttention pass the config switch. Contiguous CUDA tensors run the kernels; non-contiguous views and CPU tensors use the eager composition; unsupported dtypes raise.

On a 9-layer Kimi-K3 proxy at 512K packed tokens (TP4, CP16) the fusion removes 960 kernels per step and 0.8 % of the step time at identical peak memory; a checkpointed 64K parity run matches the eager gate within 1.85e-4.

Tests: tests/unit_tests/fusions/test_fused_attention_output_gate.py checks bitwise parity of outputs and both gradients against the eager gate for BF16 / FP16 / FP32 activations and gates (random inputs with a masked tail block, and an extreme-value grid with the subnormal-sigmoid band, BF16 saturation, signed zeros, infinities and FP16/FP32 overflow), the saved tensors, partial gradients, empty tensors, the helper's dispatch and view fallback, and the config validation; the MLA elementwise gate regression in test_attention_output_gate.py covers ordinary and absorbed MLA with the eager and the fused gate. The kernels are registered in the kernel-determinism manifest (mla_attention_output_gate_fusion) with a bit-exact replay test in tests/unit_tests/determinism/kernels/test_attention_output_gate_fusion.py.
