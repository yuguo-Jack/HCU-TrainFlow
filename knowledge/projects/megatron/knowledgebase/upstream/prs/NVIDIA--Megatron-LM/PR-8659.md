# feat(ckpt): save checkpoints with nvrx_checkpointing

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8659) · state: open · merged: False

## Original PR description

Checkpoint saves in the torch_dist, torch_dcp and fsdp_dtensor formats go through the nvrx_checkpointing engine, with
megatron/training/ckpt/native.py ported from
nvrx_checkpointing.megatron.save: registering a state sets up its storage in the node-local checkpoint daemons, and later saves refresh the registered values. A run that resumes its optimizer state registers the state of its next save once its model and optimizer are set up, so the daemons set up that storage while training starts. A state that its registration cannot hold, because its structure changed or an object outgrew its slot, is registered anew. Megatron sharded state dicts are written in the torch_dist layout and DTensor state dicts (Megatron-FSDP, Torch-FSDP2) in the plain torch.distributed.checkpoint layout that their loaders read, so loading is unchanged. --ckpt-format only selects the state dict that the layers prepare; the legacy torch format keeps its own save and load path, which writes per-rank files.

The state dicts saved through the engine keep quantized parameters packed in the formats that the engine reads: E4M3 FP8 with one scale, E4M3 MXFP8 with compact scales, and NVFP4.
megatron.core.dist_checkpointing.quantized_tensors slices rows of MXFP8 and NVFP4 parameters as views of their packed storage, for ShardedTensor.narrow and the SwiGLU split, and GTP native FP8 parameters in these formats are not dequantized. The engine dequantizes them on the host while it writes, so checkpoints are unchanged, and saves no longer copy these parameters to high precision on the GPU, which made a garbage collection after FP8 saves necessary. Quantized parameters in other formats, like FP8 with block scales, are dequantized before the engine reads them, as the save planner did.

This removes the save strategies' use in training, the NVRx local non-persistent checkpoints and NVRx's async worker: asynchronous saves wait for durability on a background thread and are finalized once they are durable on every rank. The daemons run without an idle shutdown and stop when training terminates; unit tests stop them after every test.

Until nvrx_checkpointing publishes portable wheels, the CI image builds its wheel from the public repository in a separate stage, with the toolchain and flags of the project's own CI wheel jobs, and installs it after the expensive dependency builds, so a new pin does not rebuild them.
