# [SSM][KDA] Build two-stage KDA's output norm as the gated RMSNorm it runs, and form its zero-centered gain in FP32

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8882) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Makes the contract of two-stage KDA's output norm explicit. It is Kimi Linear's gated RMSNorm, whatever `normalization` says, and `out_norm` is now built as that weight-only RMSNorm. The PR also adds the zero-centered gain's 1 in FP32.

**Bug.** With `kda_two_stage_gates=True`, `KimiDeltaAttention._apply_gated_norm` runs the output norm and the sigmoid gate as FLA's fused `rms_norm_gated`: `RMSNorm(x) · weight · sigmoid(gate)`, with no bias. That is Kimi Linear's architecture: FLA's `KimiDeltaAttention` uses `o_norm = FusedRMSNormGated(..., activation='sigmoid')`. Every two-stage checkpoint trained and serves that math, and training and inference run the same function. Two things were wrong around it:

- **The contract was hidden.** `out_norm` was built from `normalization`. Under `normalization="LayerNorm"`, the `TransformerConfig` default, it was a `te.LayerNorm` whose bias looked live but was never read, and nothing said that `normalization` did not apply to this norm. The single-stage path calls `out_norm` itself and honors `normalization`.
- **`layernorm_zero_centered_gamma=True`**: the gain `out_norm.weight + 1` was formed in the parameter dtype. In BF16 that keeps 7 fraction bits, so learned gains in (−2⁻⁹, 2⁻⁸) became exactly 1, and every other gain was rounded to a multiple of 2⁻⁷. TE's norms and GDN's fused gated norm add the 1 in FP32. External implementations of the same checkpoint (HF or vLLM exports) do too.

Opt-in configs only: two-stage gates, with zero-centered gamma for the second item.

**Fix.**
- Two-stage gates build `out_norm` as a weight-only RMSNorm whatever `normalization` says, from a copy of the config with `normalization="RMSNorm"`, through a new `_GDNBase._out_norm_config` hook that `KimiDeltaAttention` overrides. Direct gates keep following `normalization`, and so does every other norm in the model. The `kda_two_stage_gates` docstring and the `KimiDeltaAttention` docstring state the contract.
- Supporting `LayerNorm` here was the other option. FLA's `layer_norm_gated` would do it, but it would silently change every existing two-stage checkpoint trained under `LayerNorm`: those checkpoints carry `out_norm.bias`, so a strict load would not catch the change. Rejecting the config, the earlier revision of this PR, broke those valid models. Both are worse than stating the contract they were trained with.
- **Old checkpoints load with identical math.** A two-stage checkpoint saved under `LayerNorm` has `out_norm.weight`, which is the same gain, and an `out_norm.bias` that the forward never read.
  - Plain `load_state_dict`: a load-state-dict pre-hook on two-stage `KimiDeltaAttention` drops `out_norm.bias` whatever its value, so a strict load succeeds and computes what the model trained with.
  - Distributed checkpoints load only the keys the model's sharded state dict asks for. A checkpoint key the model does not request counts as "missing" in `dist_checkpointing` terms. The default `--dist-ckpt-strictness assume_ok_unexpected`, and every `*_unexpected` mode, ignore it. Only `log_all` and `return_all` report it, and `raise_all` refuses the load. Owners who load with `raise_all` should load such a checkpoint once with the default strictness and save it again.
  - TE's LayerNorm and RMSNorm keep the same `_extra_state`, so `out_norm.bias` is the only key that differs.
  - Optimizer state saved for the old bias is not requested either. Resuming training from such a checkpoint is not covered by a test here.
- Under `LayerNorm` with `rmsnorm_weight_decay_mult` set (opt-in), the two-stage `out_norm` weight now takes that multiplier, since it is marked as an RMSNorm gain.
- The two-stage path hands the kernel `out_norm.weight.float() + 1` when zero-centered. The kernel already loads the weight as FP32, and its weight gradient flows back through the cast. Existing zero-centered two-stage checkpoints shift by at most 2⁻⁸ per channel.
- The two-stage gated norm runs outside `torch.compile`; `jit_fuser` now covers only the single-stage norm and gate. The split is line for line the one in #8883, so the two PRs merge cleanly.

**Tests.** `tests/unit_tests/ssm/test_kda_gate_precision.py`:
- `test_two_stage_gates_accept_any_normalization` (CPU): a two-stage `LayerNorm` config builds and validates.
- `test_out_norm_bias_pre_hook_drops_only_that_key` (CPU): the hook drops this module's `out_norm.bias` and nothing else.
- `test_two_stage_out_norm_is_a_weight_only_rmsnorm[LayerNorm|RMSNorm]` (1 H100): `out_norm` has only a weight, marked as an RMSNorm gain. The output is bit-identical to main's two-stage math, `rms_norm_gated(x, gate, out_norm.weight, None, sigmoid)`. On `main` the `LayerNorm` case has a bias.
- `test_two_stage_loads_a_state_dict_with_the_old_out_norm_bias[layer|in_parent]` (1 H100): a state dict in main's two-stage `LayerNorm` layout, with a random `out_norm.bias`, loads strictly into the layer and into a parent module. The loaded parameters equal the saved ones, and the layer's forward is bit-identical to the saved layer's.
- `test_two_stage_zero_centered_gain_is_added_in_fp32` (1 H100), over 2¹⁷ rows of a 128-wide head, against `rms(x)·(w + 1)·σ(g)` in FP32 with the module's own weight. At w = 0.0035 the mean of `actual/expected − 1` must stay below 5e-4. On `main` it is −3.48e-3 (H100, in the step 3 GPU repro). At w = 0.25, exact in BF16, it passes on both.
- `test_single_stage_honors_layernorm_out_norm` (1 H100): the single-stage path keeps a `LayerNorm` output norm with its bias, and honors a bias of 0.5.

`tests/unit_tests/determinism/kernels/test_gated_norm.py::test_kda_two_stage_output_norm_replays` replays the two-stage gated norm bit-exactly, forward and backward, with and without zero-centered gamma. `tools/check_kernel_determinism_coverage.py --base-ref origin/main` passes.

On H100 in the CI image (`mcore_ci_dev:main`, 2026-11-02), the regression tests (`test_kda_gate_precision.py` and the replay) pass (14 cases) and fail on `main` (6 of 14 cases). On `main`, the hook test fails at its import of `_drop_unused_out_norm_bias`, which this PR adds. The two weight-only-norm cases, the two state-dict cases and the w = 0.0035 gain case fail by assertion. The other cases, including w = 0.25 and the replay, pass on `main`. The neighbor tests (`ssm/test_kda.py`, `determinism/kernels/test_gated_norm.py`) pass (62 cases, 12 skipped).
