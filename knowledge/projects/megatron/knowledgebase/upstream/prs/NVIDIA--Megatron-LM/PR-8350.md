# What does this PR do?

Cherry-pick of #8201 into `core_r0.20.0`: runs the Nemotron 3.5 Lightning and Nemotron 3 Super GB200 functional tests in `--deterministic-mode`, so CI compares them bit for bit, and refreshes the Lightning nightly goldens.

Original PR: #8201

## What is included

Six commits from #8201, applied cleanly on `core_r0.20.0` (9051cb7be). The diff is identical to #8201 (7 files, +312/-295).

| Area | Change |
|---|---|
| `model_config.yaml` of `nemotron3_5_lightning_nightly_..._ep8_dgx_gb200`, `..._ep4_dgx_gb200_1N4G`, `nemotron3_super_release_gb200`, `nemotron3_super_release_gb200_sm` | Deterministic env values (`NVTE_ALLOW_NONDETERMINISTIC_ALGO: 0`, `NCCL_ALGO: Ring`, `CUBLAS_WORKSPACE_CONFIG: :4096:8`), `--deterministic-mode: true`; drop `--cross-entropy-loss-fusion` and `--cross-entropy-fusion-impl`, which deterministic mode rejects; `TRITON_CACHE_AUTOTUNING: 1` |
| `_run_training.sh` | Default `TRITON_CACHE_DIR` to `$OUTPUT_PATH/triton_cache` when `TRITON_CACHE_AUTOTUNING` is 1 (deterministic mode needs a shared cache dir) |
| Lightning nightly goldens (GB200, GB300) | Regenerated from CI runs. GB200: loss, num-zeros and memory metrics identical across repeats; iteration-time taken from the slowest repeat (steady-window median 25.72 s) |

## Dependencies on `core_r0.20.0`

- The Super release recipes need the router CUDA-graph-capture fix from #8217 (`torch.full` instead of `torch.tensor` in `attach_and_log_load_balancing_loss`). `core_r0.20.0` already has it as #8291.
- `--deterministic-mode` is already supported on this branch.

## Testing

- The goldens were recorded on main-branch CI runs, not on `core_r0.20.0`. Validate them with a CI run on this PR (label `Run functional tests`) before merging.
- The Super release cases (`nemotron3_super_release_gb200`, `..._gb200_sm`) have no refreshed goldens in this PR. They are release/weekly cases that run from the convergence-tests recipes, and their goldens are not part of this change.
- The 1N4G case was not refreshed. Its golden predates deterministic mode and needs the frozen checkpoint staged on the runner, so it only runs in GitHub CI.
