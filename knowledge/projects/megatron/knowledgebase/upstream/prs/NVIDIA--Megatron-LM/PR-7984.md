# What does this PR do?

Precompute microbatch release offsets for interleaved pipeline input selection, replacing O(V²) cumulative prefix counting with O(V) construction and O(1) lookups, where V is the number of virtual microbatches.

The existing implementation slices and counts an increasingly long chunk-ID tuple prefix at each forward position. The new helper maintains per-chunk release counts and records the exclusive count needed at each position. It preserves the forward-only release rule, reversed backward chunk IDs, warmup delay, and `microbatch_id - offset` activation index. Schedule construction, forward/backward execution order, communication calls, and warmup calculation are unchanged. The additional storage is O(V + model chunks).

## CPU benchmark

Apple M4 Pro, macOS 26.5.1, Python 3.12.11, PyTorch 2.7.1. Valid PP=4, rank-0 layouts; MoE communication overlap disabled. M is the microbatch count, C the model-chunk count, and G the contiguous microbatch group size; V = M × C.

Times are in microseconds. Each value is the median of 51 measurements with alternating before/after order. The benchmark asserts exact result equality before timing. Common schedule-table construction is excluded; the optimized timing includes precomputation and all lookups.

| V | M / C / G | Training warmup | Training before → after (µs) | Forward-only before → after (µs) |
|---:|:---:|---:|---:|---:|
| 32 | 16 / 2 / 4 | 10 | 3.084 → 3.291 | 4.584 → 2.958 |
| 64 | 16 / 4 / 4 | 18 | 10.625 → 6.292 | 16.959 → 5.458 |
| 128 | 32 / 4 / 4 | 18 | 49.000 → 13.541 | 62.000 → 10.917 |
| 256 | 64 / 4 / 8 | 30 | 188.291 → 26.208 | 232.500 → 21.083 |
| 512 | 64 / 8 / 8 | 62 | 696.291 → 56.208 | 924.250 → 45.542 |

At V=512, release bookkeeping is 12.39× faster in training and 20.29× faster in forward-only mode. At V=32, the training median increases by 0.207 µs; the small-schedule overhead is included above. These measurements establish CPU bookkeeping costs, not end-to-end training speedups or GPU performance.

Benchmarks were collected before the rebase. Both changed files were verified byte-identical afterward; the scheduling source on the old and new upstream bases is also unchanged.
