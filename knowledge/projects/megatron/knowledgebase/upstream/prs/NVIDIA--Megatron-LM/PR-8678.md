# Add a Nemotron VL content-rendering mode to the chat endpoint

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8678) · state: open · merged: False

## Original PR description

## What

Adds `MultimodalPromptConfig.content_rendering`, with values `"join"` (the default, unchanged behaviour) and `"nemotron_vl"`. In `nemotron_vl` mode, the chat endpoint flattens a message's content parts the way the Nemotron 3.5 Super VL HF chat template does:

- parts keep their original order, so this mode ignores `content_part_order`;
- a newline goes before a media item only when it follows text that doesn't already end with `\n`, so there is no newline after a leading image;
- when a message has more than one image, each image is labeled `<image N>`; videos are never labeled.

## Why

With the current `media_first` + `"\n"`-join rendering, Megatron's prompts for Super VL differ from what HF and vLLM produce for the same request. The differences are an extra newline after a leading image, missing `<image N>` labels and reordered parts. In a paired Megatron-vs-vLLM accuracy comparison, this produced small but significant gaps: OCRBench v2 −0.57 and MMMU-Pro −0.80. With `nemotron_vl` rendering, prompt token counts match vLLM exactly on CharXiv (all 1000 tasks), BabyVision (all 388) and MMMU-Pro (1719 checked), and the CharXiv and BabyVision differences are within noise.

The `NemotronOmniInferenceWrapper` default stays the same. Nemotron 3 Nano Omni's chat template puts all media first, which is what `media_first` reproduces. Super VL servers opt in instead:

```python
InferenceConfig(
    multimodal_prompt_config=dataclasses.replace(
        NemotronOmniInferenceWrapper.multimodal_prompt_config, content_rendering="nemotron_vl"
    ),
    ...
)
```

## Tests

- `test_nemotron_vl_rendering_matches_hf_chat_template` renders the content loop of the HF chat template with jinja2. It runs eight message shapes through `_extract_multimodal_from_messages` + `_sanitize_messages_for_template` and checks the output matches the template: leading or trailing image, text ending in a newline, empty text, two leading images, interleaved images, text-video-text, and two videos.
- `test_endpoint_renders_images_like_the_nemotron_vl_template` checks the end-to-end prompt tokens for an interleaved multi-image message.
- Config validation and `from_dict` plumbing for the new field.
