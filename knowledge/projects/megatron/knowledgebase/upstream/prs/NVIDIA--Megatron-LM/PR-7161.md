# fix(gtp): checkpoint fused projections in logical layout

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7161) · state: open · merged: False

## Original PR description

## What does this PR do?

- Add GTP distributed-checkpoint support for GDN `in_proj`.
- Unify the GTP + DCP checkpoint interface for GDN, GDP, and Mamba.
- Fix logical checkpoint splitting for dense gated-MLP `fc1`.

While enabling GTP for Qwen3.5-VL on `dev` ([#6608](https://github.com/NVIDIA/Megatron-LM/pull/6608)), we identified checkpoint issues and split the fixes into three PRs for `main`: this PR covers model-weight layout, [#7162](https://github.com/NVIDIA/Megatron-LM/pull/7162) covers optimizer-state mapping, and [#7168](https://github.com/NVIDIA/Megatron-LM/pull/7168) adds padding and grouped-expert support.

## Implementation details

GDN `in_proj` is now checkpointed in its logical section layout. GTP row shards can cross section boundaries, so splitting each shard independently can assign rows to the wrong checkpoint keys. Same-topology round trips may hide this error.

GDN, GDP, and Mamba share an `in_proj` checkpoint factory that gathers the TP-local logical weight before applying each module's section split, then restores rank-local contiguous rows after loading. Existing section keys are preserved, and replica IDs include the GTP rank to prevent duplicate checkpoint writers. Checkpoint state-dict construction performs one GTP-group all-gather per affected weight and holds a temporary TP-local full-weight buffer, including during loading.

Dense gated MLP `fc1` uses the same gather/slice helpers around its `[gate | up]` split. Gathering before splitting preserves the gate/up boundary in the checkpoint; loading restores the contiguous row layout already consumed by the runtime all-gather, without adding a permutation to the training path.

## Qwen3.5-VL validation

These experiments evaluate [#7161](https://github.com/NVIDIA/Megatron-LM/pull/7161) + [#7162](https://github.com/NVIDIA/Megatron-LM/pull/7162) + [#7168](https://github.com/NVIDIA/Megatron-LM/pull/7168) together with native activation-recompute and gradient-precision fixes, as part of the Qwen3.5-VL integration tracked in [#6608](https://github.com/NVIDIA/Megatron-LM/pull/6608).

[W&B project](https://wandb.ai/megatron-core-moe-dev/xuwenc-gtp-qwen3.5-vl) — run prefixes: `ckpt conversion`, `correctness`, `convergence`.

Full Qwen3.5-VL 35B-A3B with MTP enabled, on 16 × GB200, using the Nemotron Image CLEVR1 and CLEVR2 datasets. Maximum sequence length 4096, MBS1/GBS128, BF16 weights with FP32 gradient accumulation and reduction, and HybridEP. Deterministic mode is enabled for checkpoint conversion and correctness, and disabled for convergence. Complete parallel configurations are included in the W&B run names.

### 1. Checkpoint conversion

Saved after 20 updates and restored model and optimizer across non-GTP/GTP, different GTP/EGTP degrees, and TP/PP layouts. All tested checkpoint save/load paths completed successfully, with model weights and optimizer states restored exactly. Each resumed run completed 50 additional updates without skipped steps.

### 2. Correctness

Compared non-GTP, GTP4, and GTP4 + EGTP2 over 50 updates from the same model/optimizer checkpoint and matching inputs. The non-GTP baseline and its repeat matched on all recorded comparisons. Across parallel configurations, peak relative differences in mean LM loss over 50 updates were approximately 0.9% for GTP4 and 1.3% for GTP4 + EGTP2. Detailed runs are available in W&B.

### 3. Convergence

Each run starts from fresh random initialization without loading a shared checkpoint. Evaluation runs every 100 updates for 10 iterations.

All three runs completed 1000 updates with finite recorded values and no skipped updates. Training losses average the last 100 updates; validation losses use the final evaluation at iteration 1000.
