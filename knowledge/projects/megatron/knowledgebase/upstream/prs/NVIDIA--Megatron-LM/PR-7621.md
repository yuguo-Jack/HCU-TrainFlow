# [Dev] lite: Add MiniMax-M3 support (MSA primitive, MagiAttention MSA backend, HybridEP dispatcher)

# What does this PR do?

Adds **MiniMax-M3** (`MiniMaxAI/MiniMax-M3`, HF `minimax_m3_vl` text stack) as a native Megatron Lite model, together with the primitives it needs: a model-agnostic **MiniMax Sparse Attention (MSA)** primitive with a two backend: pure-torch `flex` backend and an efficient **MagiAttention MSA** backend. **HybridEP** backend for the Lite `TokenDispatcher`. The whole change lives under `experimental/lite/`; `megatron/core` is untouched.

## Design

MiniMax-M3: 60 layers, hidden 6144, 64 q / 4 kv heads × 128, Gemma QK-norm, partial RoPE (64 dims), vocab 200064. Layers 0–2 dense; layers 3–59 MoE (128 experts top-4, sigmoid router with bias, shared expert) + MSA (block 128, top-16 blocks per query token, 4 index heads). Activation is clamped `swigluoai`.

- **`model/minimax_m3/`** — config mapping from HF `config.json`, model composed from Lite primitives, bidirectional HF ↔ Lite checkpoint mapping (disk and HF-module names), runtime protocol with `ImplConfig.msa_backend` / `moe_dispatcher` / `deterministic`. Registered for `minimax_m3_vl`, `minimax_m3_vl_text`, `minimax_m3`.
- **MSA primitive** (`attention/msa.py`, `kernels/msa_kernels.py`) — `MSAIndexer` (fp32 scores, chunk-wise block max-pool, per-token top-k, own block forced, frozen) + `MSAttention` reusing `GQAttention` projections/QK-norm/RoPE/TP sharding.
  - `flex`: `flex_attention` with a per-token `mask_mod`; `BlockMask` built from the block-level selection union. TP/SP and all-gather CP on zigzag shards.
  - `magi` (`kernels/magi_msa.py`, lazy import): builds on the MagiAttention backend from #6478. Magi owns CP dispatch, index-K communication and the `msa_v1` kernels; Lite owns projections, norms, RoPE by dispatched position and the output linear. Supports packed documents; `deterministic=True` gives a bitwise-reproducible MSA backward.
- **HybridEP dispatcher** (`modules/dispatcher.py`) — `dispatch_backend ∈ {alltoall, deepep, hybridep}`; `use_deepep` still works, so other Lite models are unchanged. Wraps `HybridEPBuffer.dispatch_with_permute / combine_with_unpermute` with the same autograd contract as Core's `_HybridEPManager`, handles unequal per-rank token counts, caches one buffer per group, exposes `num_sms` / fused-permute knobs.

## Other changes

- `experts.py`: `swiglu_with_probs` routes `swigluoai` (α = 1.702) through Core's fused `weighted_bias_quick_geglu_impl`; α = 1 path unchanged.
- `rotary.py`: `get_emb_for_positions` for arbitrary per-token positions (Magi layout).
- `hf_weights.py`: `split_qkv` handles `tp > num_kv_heads`; `_gather_dense` under PP merges fused qkv/gate_up shards correctly.
- `gqa.py`: deferred Magi import to break a circular import.
- Docs: new `skills/primitive/module/msa.md`; `moe.md` and `tests/README.md` updated.

## Testing

- **Unit (CPU):** M3 static/config/checkpoint contracts; MSA indexer and flex kernel semantics; HybridEP dispatcher with a fake buffer; branch contracts.
- **Smoke (GPU, run on B200):** `flex` and `magi` parallel layouts (TP/SP/CP/EP, packed, deterministic); HF bf16 parity gated on cosine; 50-step train-curve agreement across backends/dispatchers; 2-GPU HybridEP bitwise vs Core.
- Magi suites need Blackwell (`msa_v1`, FA4) and HF-parity suites need a `transformers` with `minimax_m3_vl`; both are marked `optional`.

## Known limitations

- Text-only; MRoPE and attention output gate not supported.
- `flex` rejects THD/packed sequences; `magi` requires attention TP = 1 and the fixed 64/4/4-head shape of the `msa_v1` kernels.
- Validation used the first 6 layers of the real checkpoint; the full 60-layer model has not been trained end to end yet.
