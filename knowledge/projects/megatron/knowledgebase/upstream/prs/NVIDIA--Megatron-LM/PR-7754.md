# What does this PR do?

[KDA team](https://github.com/NVlabs/kda) optimizes GDP decode and inference on GB300 by reducing redundant kernel work, tensor copies, CUDA graph replay validation overhead, and greedy sampling overhead.

Changes:
- Load GDP query and decay inputs only at the Householder steps that consume them.
- Prefetch recurrent inputs for multi-token decode and store the final Householder output directly in a compact, contiguous layout.
- Preserve speculative decode output layout and token padding, and avoid copying transposed projection weights in the Triton batch-invariant GEMM path.
- Add a faster argument check for cached inference CUDA graph replay and a direct argmax path for uniform top-k=1 sampling.

## Performance

Pre-rebase measurements used one GB300, 32 requests, bf16 activations, fp32 inference caches, and local CUDA graphs with the GDP 800M hybrid recipe. Complete inference steps were timed using synchronized wall time. Each comparison used six processes per arm in paired ABBA runs.

| Case | Measurement | Baseline p50 | Optimized p50 | Speedup |
| --- | --- | --- | --- | --- |
| B=32, S=1 | Decode step | 3549.096 µs | 1496.369 µs |  1.261× | 
| B=32, S=1 | GDP mixer | 49.496 µs | 41.768 µs | 1.185× |
| B=32, S=4 | Decode step | 6303.184 µs | 5048.128 µs | 1.249× |
| B=32, S=4 | GDP mixer | 102.275 µs | 102.257 µs | 1.000× |

S=1 compares against pinned main; S=4 compares against the preserved optimized baseline because pinned main fails speculative full-step execution.

Decode step measures synchronized wall time; GDP mixer measures the complete GatedDeltaProductMixer.forward using CUDA events. Results were collected on GB300 before rebasing.

- Waterpine · comment · 2026-10-02T18:39:15Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7754#discussion_r4168708736)

File: `megatron/core/ssm/ssm_inference.py` · line 283

These checks were removed because token-only padding is determined independently of the SSM batch-invariant flag.

The existing CUDA graph bucket builder checks the global batch-invariant kernel switch and rounds token_count up to a multiple of 64, while leaving the request counts unchanged. For example, at TP=1 with no speculative tokens, a decode bucket can contain 64 token rows but only 40 decode request slots. The remaining 24 rows have no corresponding request or SSM state slot.

This can also occur when context.batch_invariant_mode is false. GDP already rejects config.batch_invariant_mode=True in the existing mixer code (https://github.com/NVIDIA/Megatron-LM/blob/main/megatron/core/ssm/gated_delta_product.py#L560-L566). The comment above the assertion explicitly allows GDP to use batch-invariant attention/GEMM kernels without enabling batch-invariant SSM execution. Therefore, the context flag cannot determine whether token-only graph padding is present; trimming and restoring those rows must be handled independently.

Therefore, the first change always slices the decode partition to decode_req_count * (1 + num_speculative_tokens) before entering the recurrent kernels. The second restores any missing rows with zeros before the output projection, using the actual input projection row count.

For Mamba with batch_invariant_mode=True, this preserves the previous trim-and-pad behavior. Without extra padding, no rows are removed and no zero-padding allocation is needed. I verified both revisions on 4×GB300: all 43 selected Mamba regression tests passed, and the targeted Mamba batch-invariant comparisons preserved outputs and state buffers bit for bit.

- Waterpine · comment · 2026-10-02T18:52:55Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7754#discussion_r4168822991)

File: `megatron/core/ssm/ops/gdp/fused_recurrent.py` · line 327

The padding contract is unchanged; the zeroing has been moved into the recurrent kernel’s existing output stores, in both the regular and prefetched loops:

```
tl.store(
    p_o,
    tl.where(i_s >= 0, b_o, 0).to(p_o.dtype.element_ty),
    mask=mask_v,
)
```

A negative state index now explicitly stores zero at that request’s output address, even if its recurrence produces NaN/Inf. The store is still performed for padding rows, so it overwrites any stale output-buffer contents. Persistent-state reads/writes and intermediate snapshot writes remain guarded by i_s >= 0.

The outer masked_fill_ is therefore redundant. Removing it avoids the separate mask construction and masking kernel launch, while preserving the output semantics for valid requests.

Regression tests poison padding inputs with NaNs and verify zero outputs and unchanged unused state/snapshot slots, covering single-token and speculative decode, as well as compact output.

This change is confined to the GDP recurrent kernel. Mamba uses separate SSM kernels and does not call this function.
