# Add test helpers to forbid global grid reads and build collections

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8017) · state: closed · merged: False

## Original PR description

Depends on #6259. Please review the diff from #6259's head: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/7a951c3dfd...yx/pstate-s12-test-helpers).

#6259 adds the Gloo fields `intra_dp_cp_gloo` and `intra_expt_dp_gloo` to `ProcessGroupCollection`, so `build_test_pg_collection` has to set them too. The commit "Set the Gloo fields of build_test_pg_collection to None" sets both to `None`, as in a job built without Gloo groups. Without it, the field-set check in `test_build_test_pg_collection_matches_initialize_model_parallel` fails once both PRs are merged. Before the 2026-11-01 sync, on 4 CPU ranks with Gloo, the helper tests gave the same results with the merge and this commit as before: 15 passed, and the 3 that need CUDA failed.

**Why.** Tests for components that take an explicit `ProcessGroupCollection` have no shared way to prove the component ignores the global parallel grid. Each test hand-rolls a patch of a few `parallel_state` accessors. That misses names a module imported directly (`tensor_parallel/cross_entropy.py` imports `get_tensor_model_parallel_group` by name), or builds a collection whose groups equal the global ones, so a stray global read still passes.

**What** (test-only):
- `forbid_global_process_groups()` in `tests/unit_tests/test_utilities.py`: every accessor that `tools/check_process_group_usage.py` counts raises `AssertionError` naming it, on `parallel_state` and in each imported `megatron` module that bound it by name. `use_mpu_process_groups()` and the pipeline-stage predicates are forbidden by default (opt-out flags and `allow=`). Calls made by `parallel_state` itself keep working, so `initialize_model_parallel` and `destroy_model_parallel` still work inside the block. Everything is restored on exit.
- `new_group_with_same_ranks(group)`: a distinct communicator over the same ranks, created collectively, so identity checks catch a component that used the global group.
- `build_test_pg_collection(tp=, pp=, cp=, ep=, expt_tp=, order=)` / `destroy_test_pg_collection()`: the collection of a standard grid built on `HyperCommGrid`, with the same ranks as `initialize_model_parallel` and no global state. Fields it does not build, the two Gloo fields included, are explicitly `None`. The dynamic context-parallel maps that #7047 added (`dynamic_cp`, `dynamic_tp_cp`) are empty, as `initialize_model_parallel` leaves them for a grid without dynamic context parallelism.
- A `grid_pg_collection` fixture in `tests/unit_tests/conftest.py`.

**Tests.** New `tests/unit_tests/test_process_group_test_helpers.py`: 18 tests pass on 4 GPUs. They include rank parity with `initialize_model_parallel` for eight grid shapes, built inside the forbid block, and the by-name `cross_entropy` read being caught. Existing suites that import the edited files give the same results as on main. In the integration run (main 77391e71cc with all #6307 PRs merged, against main), this PR's test files show no regressions against main. There, `test_process_group_test_helpers.py` passes all 18 tests on 4 GPUs; the file is new, so main has no results for it.

**Compatibility.** Test-only; no production code or existing test changes.

The branch was synced with main 77391e71cc on 2026-11-01 by a merge commit that brings in #6259 after its own update to main. That merge had no conflicts, so existing commits and review links stay valid.
