# Resolve the remaining inference process-group fallbacks with warnings

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8751) · state: closed · merged: False

## Original PR description

Depends on #8017, #8029, #8049 (which contains #6293), #8054 and #8058. Please review the diff from the merge of their heads: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/bd9a7e796b...yx/pstate-c4-inference-fallbacks). The merges resolve the existing conflicts between #8058 and #8054 in `text_generation_controller.py` and between #8058 and #8029 in `dynamic_context.py`, and regenerate the process-group allowlist. #8029 stores the dynamic context's `tp_size` and passes it at every internal rounding call; without it, every dynamic inference step would take the new warned rounder fallback. #8058 gives `InferenceConfig.resolve_pg_collection` the model argument that the direct-mode EP check passes.

**Why.** Several inference helpers still read the global parallel grid when a caller omits their groups:
- The pipeline helpers in `communication_utils.py` warned, but then read the global pipeline group, its last, previous and next ranks, and the stage predicates directly.
- `broadcast_tensor` and `broadcast_list` with `data_parallel=True` read the global model-parallel group and its source rank without a warning. `tokenize_prompts` in both text-generation servers read the global data-parallel source rank the same way.
- `build_inference_pg_collection` filled each omitted size from the global grid without a warning. RL training leaves the `rl_inference_*` sizes unset by default, so its inference grid copied the global grid even when `pretrain()` ran on a collection of its own.
- `DynamicInferenceContext.round_up_tokens` and `round_up_requests` padded to the global TP size when called without `tp_size`, again without a warning.
- In direct mode, the high-level API's EP check read the global expert-parallel size for a model without a collection, while the engine built right after it resolved its groups through `InferenceConfig`.

A caller whose model runs on its own grid could not pass several of these groups.

**What.**
- The communication helpers take their group from the caller, or from `_resolve_group`, which falls back through `resolve_process_groups` (#8049). It warns once per helper with a `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23). When the global grid has no such group, it raises `ValueError` instead of passing `None`, which `torch.distributed` reads as WORLD. The pipeline helpers derive the stage, the last rank and the neighbors from the resolved group, as they already did for a group the caller passed.
- `broadcast_tensor`, `broadcast_list`, `broadcast_int_list` and `broadcast_float_list` take an optional `mp_group`. `tokenize_prompts` takes an optional `pg_collection`.
- `build_inference_pg_collection` takes `training_pg_collection` for omitted sizes. Main's #4264 moved the RL inference-model build to `megatron/rl/training_setup.py`. There, `RLSetupCallback` passes the trained model's collection as `training_pg_collection` to `build_rl_inference_model`, which forwards it. Without one it falls back through `resolve_process_groups`, which warns.
- The dynamic-context rounders warn once per method when called without `tp_size`. Without a global grid they still pad to 1.
- For a model without a collection, the direct-mode EP check uses `InferenceConfig.resolve_pg_collection`, so it checks the EP group the engine runs on. `_llm_base` no longer reads `parallel_state`.
- In-repo callers pass their groups, so stock runs emit no new warning. The refit benchmark example and the model-swap tests pass the sizes they used to inherit from the global grid.

The process-group checker goes from 167 reads to 156, and from 1 guarded read to 6. Sixteen accessor reads, 12 of them silent, become five guarded `resolve_process_groups` calls. Two of them are in new scopes, `_resolve_group` and `DynamicInferenceContext._global_tp_size`, which is why the allowlist has two new guarded entries.

**Tests.** New `tests/unit_tests/inference/test_inference_helper_fallbacks.py`: with groups passed, the helpers read nothing global. Without them, each helper warns once, gets the same groups, and reads the global grid only through the resolver. `test_apis.py`, `test_model_swap.py` and `test_rl_utils.py` are updated. The `test_apis.py` stub gives the global grid every inference group, so it also passes with the validation that #8736 adds. The stub grid of the inference-config fallback test sets `tp_ep`, because #8058's sync with main made the fallback require it. `test_setup_callback` in `test_rl_utils.py` expects the new `training_pg_collection` keyword. The tests also pass with #8733's strict-mode changes to `resolve_process_groups`.

On 4 GPUs against its base: `test_inference_helper_fallbacks.py` passes its 13 tests, all new. `test_apis.py` passes 29 here vs 29 on the base, and its 2 new tests pass: the renamed inference-config fallback test at global EP sizes 1 and 4. `test_model_swap.py` passes 88 and skips 82 on both sides. There are no regressions. In the integration run (main with all the #6307 PRs merged), this PR's test files show no regressions against main on 4 GPUs: `test_apis.py` passes 29 vs 25 on main, the new file 13, `test_model_swap.py` 88 on both sides and `test_rl_utils.py` 176 vs 173. With all the process-group changes from #6307 applied, end-to-end training smokes match main's loss at every iteration. Before the sync, this branch also ran on 4 CPU ranks with Gloo, on the new file, `test_apis.py`, `test_model_swap.py` and the checker tests. There were no regressions. The cases that need CUDA, 7 of the new ones among them, fail on CPU.

**Compatibility.** New keyword arguments default to `None`. On the standard grid, groups, ranks and sizes are unchanged: the rank lists that `initialize_model_parallel` builds are ascending, like the ranks of a `torch.distributed` group.
- The pipeline fallbacks no longer honor the `_MPU_*` pipeline rank and size overrides. Only fake grids set those, and no in-repo caller reaches these helpers with one.
- With no global grid, the communication fallbacks raise `ValueError` instead of `AssertionError`.
- `build_inference_pg_collection` with an omitted size, no training collection and no global grid builds a size-1 axis with a warning, where main raised `AssertionError`.
- A `MultiModuleProcessGroupCollection` as `training_pg_collection` raises `TypeError`, so RL with MIMO is not supported.
- Both servers warn under the same owner, `tokenize_prompts`, so a process that falls back in both sees one warning.
- `DynamicInferenceContext._global_tp_size` warns even when `parallel_state` is not initialized, and then returns 1.
- Needs `determinism-exempt` only while the PRs it depends on are unlanded. CI diffs against main, and the base carries registered kernel files; this PR's own diff passes the coverage check.
