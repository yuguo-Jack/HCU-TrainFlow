# Add async scheduling pairwise unit coverage

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/6430) · state: closed · merged: False

## Original PR description

## What does this PR do?

This PR adds a runtime-backed unit-test foundation for asynchronous dynamic inference scheduling. It compares the same real-engine workload under the legacy scheduler and the asynchronous scheduler across 27 selected companion configurations covering admission pressure, caching, CUDA graphs, sampling, request behavior, model implementations, attention modes, and distributed topologies.

Every matrix row runs the companion configuration twice:

- baseline: `async_sched_mode=LEGACY`
- treatment: `async_sched_mode=ASYNC`

All other flags, requests, seeds, and model settings stay the same. For example, the prefix-cache row first serves a shared-prefix workload with legacy scheduling and then serves the identical workload with async scheduling; both runs have prefix caching enabled. The test checks that changing only the scheduler preserves the required results while runtime counters prove that both prefix reuse and the async scheduling phases actually executed.

This is a targeted pairwise matrix, not a universal Boolean 2x2 over every flag. A row tests the scheduler choice against one deliberately active companion configuration; it does not normally repeat a companion-disabled cell.

## How was the test matrix determined?

The matrix starts from the supported inference settings whose execution, request-local state, cache ownership, batch shape, or distributed communication can interact with scheduling. The selected surface includes:

- engine behavior: request/token capacity, chunked prefill, prefix caching, KV residency, CUDA graphs, and token events;
- request behavior: sampling filters, logprob modes, output-length controls, BOS insertion, termination IDs, stop sequences, and speculative decoding;
- model and kernel behavior: dense GPT, hybrid Mamba, Transformer Engine, inference-optimized layers, BF16/FP8, sliding-window attention, and softmax sinks;
- parallel behavior: tensor, pipeline, sequence, data, and expert parallelism plus NCCL expert dispatch.

A configuration counts only when the unit test can force the production path to run, record a feature-owned runtime witness, and compare scheduler behavior or a precise invariant. Merely setting a flag, inspecting a configured object, or observing generic model execution does not count. Related settings are grouped into one diagnostic owner row when they naturally execute together; configurations requiring special GPU topology have separate rows.

The companion-disabled cells are omitted because every row already has a legacy-scheduler control with the same companion active. Repeating each row with the companion disabled would test the scheduler alone again without proving an additional interaction.

Focused regressions that depend on production fixes remain in their dependent PRs: fused RoPE is in fork #45, and raw-prompt top-N plus heterogeneous MTP/logprob coverage is in fork #46. Direct pending-logit lifecycle and metadata-compaction invariants are in fork #43 and fork #44. GPTOSS SSE remains the separately approved end-to-end exception in NVIDIA/Megatron-LM#6428.

## How are results checked?

The common workload contains seven requests with prompt lengths `(9, 5, 12, 7, 10, 6, 11)` and output lengths `(10, 5, 9, 7, 11, 6, 8)`. They arrive in three waves, `(0,1,2)`, `(3,4)`, and `(5,6)`, with capacity for only four active requests. This forces waiting, arrival during decoding, completion of a middle request while others survive, metadata compaction, both async phase shapes (overlap and no-overlap), and a complete engine drain. The dense eager/PERSIST row also performs an actual `suspend()`/`resume()` cycle and verifies that valid pending async logits and the static KV-memory pointer are both retained across it.

For deterministic rows, the async result must match the legacy result in completion status, output length, exact generated tokens, finite logprobs within the configured tolerance, and top-N content where requested. Event rows also compare event sequences. For stochastic sampling and FP8 rows, cross-scheduler checks require valid completion, shapes, lengths, token ranges, and finite values; a second ASYNC run must then reproduce the first ASYNC run exactly.

Every row also checks the shared async runtime contract and its own feature-specific witness. Examples include nonzero prefix hits and skipped prefill tokens, executed CUDA-graph dimensions, FlashInfer sampling calls, Mamba metadata compaction, SWA and sink kernels, FP8 forwards, TP/SP collectives, pipeline logits broadcasts, or matched NCCL expert dispatch/combine calls. A configured feature that never reaches its owning production boundary fails the test instead of receiving coverage credit.

Four negative guards verify that unsupported routing replay, mismatched MTP depth, processed logprobs with speculative decoding, and skipped async bookkeeping are rejected explicitly. They document unsupported boundaries and are not counted among the 27 positive pairwise rows.
