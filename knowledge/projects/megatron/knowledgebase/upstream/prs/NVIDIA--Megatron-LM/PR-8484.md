# What does this PR do?

Documentation only: brings `megatron/core/resharding/README.md` in line with the current refit code, mainly the NCCL M2N backend.

- **NCCL M2N section rewritten.** The README described an older design (one packed `[source, destination, bytes]` tensor per batch, a per-pair layout-digest exchange, and padding to the largest pair payload). The current `NCCLM2NCopyService` instead consumes the planner's per-parameter `TensorReshardSpec`s, issues one `m2n.reshard` per parameter component with `Shard(dim)`/`Replicate()` placements on 1-D meshes, uses one NCCL4Py communicator and CUDA stream per (source mesh, destination mesh) pair, and groups complete parameters into `m2n.group()` submissions bounded by `max_group_bytes`. Also documents receiver-side MXFP8 staging, the one-time role/limit all-gather and topology check, and that a failed submission poisons the service.
- **M2N restrictions listed explicitly**, as enforced by `_build_tensor_reshard_specs`: GTP shards, strided TP layouts (`partition_stride != 1`, i.e. gated-MLP `fc1`), fused expert tensors, and source/destination dtype mismatches are rejected before communication.
- **Lockstep batching.** The README said generic backends submit the whole model in one batch when no byte limit is set. `nccl`, `gloo`, and `nvshmem` now cap batches at 32 logical parameters by default (`MEGATRON_REFIT_MAX_PARAMS_PER_BATCH`) to avoid the NCCL kernel-plan split deadlock (pytorch#174288).
- **Defaults.** The backend table called `nccl` the "default choice"; `swap_model_weights()` has no default backend and the RL loop's `--refit-method` defaults to `gloo`. Also notes that NIXL supports a single destination pool.

**Clarify that this is not an aggregate per-rank staging bound.** A destination rank can receive parameters from multiple source meshes—for example, parameter A on pair `((0,), (2,))` and parameter B on `((1,), (2,))`. Each can consume the configured group budget in BF16. The service gives these pairs [independent streams](https://github.com/NVIDIA/Megatron-LM/blob/e830b467bcf37fcd521e2492839d9ee9ca5a9410/megatron/core/resharding/copy_services/nccl_m2n_copy_service.py#L353-L378), applies the budget separately, and [joins streams only after submitting all pairs](https://github.com/NVIDIA/Megatron-LM/blob/e830b467bcf37fcd521e2492839d9ee9ca5a9410/megatron/core/resharding/copy_services/nccl_m2n_copy_service.py#L584-L610). Their staging can therefore overlap on rank 2, exceeding the limit this sentence appears to promise.

Replace the MXFP8 sentences at lines 264–267 with wording that distinguishes submission size from total staging:

```text
With an MXFP8 destination, each parameter is received as one full BF16
buffer and quantized once on the same stream. The group budget applies
separately to each source/destination mesh pair, not to aggregate per-rank
staging: buffers for concurrent pairs can overlap, and a single parameter
may exceed the soft limit. Only receiver-side MXFP8 conversion is supported.
```

No implementation change is needed. Preserve the neighboring guarantees that complete packed parameters stay together and persistent model storage is not replaced.

**Acceptance (static checks; not executed):** confirm the two-pair example is no longer described as fitting within one rank-wide budget, while single-pair submissions and oversized parameters remain accurately described. Retain the existing [packed-MXFP8 test](https://github.com/NVIDIA/Megatron-LM/blob/e830b467bcf37fcd521e2492839d9ee9ca5a9410/tests/unit_tests/resharding/test_nccl_m2n_copy_service.py#L637-L673) assertions for zero active buffers after conversion, a maximum of one active full-parameter buffer in its single-pair setup, and matching output data and scales.
