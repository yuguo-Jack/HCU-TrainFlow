# Select the NCCL symmetric-memory backend before every MFSDP v2 test

# What does this PR do?

Fixes an order-dependent setup error in the MFSDP v2 unit tests: `RuntimeError: Backend can not be changed after use.` in the `distributed_setup` fixture.

It happens when pull-request CI runs a test that builds an MFSDP v2 model without `distributed_setup` before any test that uses the fixture. On #8274, all 16 `test_expert_parallel.py::test_ep_fsdp_matches_fullbatch_reference` cases errored this way.

## Root cause

- `distributed_setup` selects NCCL with `symm_mem.set_backend("NCCL")`.
- `DBuffer.is_symmetric_memory` calls `symm_mem.is_symm_mem_tensor()`. That marks the current backend as in use, even for ordinary tensors, and the backend can't change after that.
  - Checked on PyTorch 2.13 (NGC 26.06): `set_backend("NCCL")` raises once the default CUDA backend is in use. Setting NCCL again once NCCL is in use is fine.
- A test that builds an MFSDP v2 model without `distributed_setup` never selects NCCL. If it is the first test in the process, it locks in the default CUDA backend, and every later `distributed_setup` raises.
- **Why full runs pass:** the first file in the directory, `test_annotation.py`, uses the fixture, so NCCL is already selected. This is why merge-queue runs of the bucket pass.
- **Why PR runs fail:** PR CI runs only the tests selected for the change (`testmon_selector.py`). For #8274 it selected `test_checkpoint.py::test_ep_fsdp_checkpoint_roundtrip`, which #8230 added without the fixture, ahead of `test_expert_parallel.py`. Any PR whose selection puts these two together fails the same way.
- **Other exposed tests:** 14 more tests build MFSDP v2 models without the fixture, 11 in `test_mcore_adapter.py` and 3 in `test_optimizer_checkpoint.py`.

## Fix

Move the `set_backend("NCCL")` call from `distributed_setup` into an autouse fixture in the same `conftest.py`. NCCL is then selected before every test in the directory, whichever test runs first.

- `set_backend()` doesn't initialize CUDA, so calling it before `distributed_setup` sets the device is safe.
- **LTS (PyTorch 2.9, NGC 25.09):** `set_backend("NCCL")` works there, and `is_symm_mem_tensor` doesn't exist, so the lock-in can't happen.
- **GB200:** only `test_quantized_dbuffer.py` from this directory runs there, in the shared catch-all process. It already requests `distributed_setup`, so nothing changes.
