# What does this PR do?

Preserve the original exception from a module constructor and add the module name as a traceback note.

`build_module` currently recreates exceptions with `type(e)(message)`. A constructor that calls `b"\xff".decode("utf-8")` therefore raises a new `TypeError` instead of its `UnicodeDecodeError`. A failed file read still raises `FileNotFoundError`, but loses `errno` and `filename`. Recreating exceptions also drops explicit causes and existing notes from the caught instance.

Use `add_note()` and a bare `raise` instead. This retains the original exception, its arguments, structured fields, cause and traceback; nested factories append their module names in order. Python >=3.12 is already required. Module context now appears in exception notes rather than being appended to `str(e)`; the existing BERT diagnostic assertion is updated accordingly.

## Issue tracking

Small bug fix; no linked issue. Regression cases use actual Python decoding and file operations, plus a nested constructor with an explicit cause.
