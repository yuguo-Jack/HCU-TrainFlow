# Batch duplicated Muon expert orthogonalization

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8439) · state: open · merged: False

## Original PR description

## What does this PR do?

Allow `--muon-ns-batch-size` to batch compatible expert matrices in duplicated Muon, extending the option already available for layer-sharded Muon:

```bash
--optimizer muon --muon-tp-mode duplicated --muon-ns-batch-size 32
```

This ports the optimizer batching change from [nv-mistralai-megatron commit ce96803](https://github.com/NVIDIA-NeMo/nv-mistralai-megatron/commit/ce96803ccbb4da686017b43cf48e401fb3594f50). The source commit's sweep-generation and LR-schedule changes are outside this PR.

## Behavior

- Group compatible two-dimensional expert updates by optimizer group, shape, dtype, and device; cap each Newton–Schulz call at the configured batch size.
- Retain the existing per-parameter path for dense weights, QKV splits, TP/GTP-sharded matrices, and singleton tails. GTP eligibility uses the same group resolver as orthogonalization, including partial process-group collections.
- Preserve momentum, coupled/decoupled weight decay, update scaling, and pre/post weight-update hooks. Keep per-parameter checkpoint state unchanged so the batch limit can change on reload.
- Batch size one delegates to the inherited Emerging Optimizers step unchanged. Keep AdaptiveMuon constructor dispatch and layer-sharded non-duplicated/SYRK fallback behavior intact.
- Reject unsupported optimizer/mode combinations. Duplicated batching requires Emerging Optimizers >= 0.3.0 and does not support SYRK; main already pins v0.3.0, so no dependency update is needed.

Batched and separate GEMMs can round differently. This PR enables fewer NS calls but does not claim measured end-to-end throughput or training-quality improvements.
