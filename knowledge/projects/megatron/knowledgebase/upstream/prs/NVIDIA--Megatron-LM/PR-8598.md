# fix(inference): align completion log probabilities with generated tokens

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8598) · state: open · merged: False

## Original PR description

## What does this PR do?

For a non-streaming `/v1/completions` request with `logprobs` and `echo=false`, the response put `None` in front of `token_logprobs` and `top_logprobs`. Each list therefore had one more entry than `tokens`, and every score was shifted one position away from its token.

This PR returns exactly one entry per generated token.

## Example failure scenario(s)

**Scenario (shifted completion log probabilities)**

- Client A requests two generated tokens with `logprobs=1` and `echo=false`.
- The engine returns log probabilities -0.5 and -9999.0 for those two tokens.
- Before this fix, `token_logprobs` was `[None, -0.5, -9999.0]` for two tokens, so the first token appeared to have no score.
- With this fix, `token_logprobs` is `[-0.5, -9999.0]` and lines up with `tokens`.

## How was this bug discovered?

The `logprobs` case of `test_completions_response_format` formats a two-token completion and expects one log probability and one top-N entry per token. On `main` both lists have three entries, starting with `None`.

## Dependency and scope

This PR is independent and based on `main`. The change is limited to the `echo=false` log-probability formatting in `completions.py`. The streaming path and `echo=true` responses are unchanged. The regression updates the expected values of the existing `logprobs` case.
