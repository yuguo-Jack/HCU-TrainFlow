# [dev] misc fixes while bring-up chunk-wise cuda graph

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8105) · state: closed · merged: True

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
Independent fixes collected while developing chunk-wise CUDA graphs (#5258); none depends on that feature.

- **Padding mask under SP + MTP** (`gpt_model.py`, `hybrid_model.py`): the decoder gets the sequence-parallel-scattered padding mask, the post-process keeps the caller's full-length mask (MTP rolls it with `input_ids`/`position_ids`; MoE layers re-align it themselves). Fixes PP1 + SP + MTP + packed sequences: `_roll_tensors_packed_seq: All packed CP1 tensors must have the same sequence length`.
- **KDA under CUDA graph capture** (`kda.py`): skip the `torch.equal(cu_seqlens_q, cu_seqlens_kv)` host sync while a stream is capturing, as GDN already does; the boundaries were validated in the eager warm-up.
- **Batch dict aliasing** (`data_schedule.py`): work on a shallow copy of the iterator's batch. The per-rank slicing rebinds entries in place, and replay paths (`RerunDataIterator`, the PagedStashRunner dropless retry) serve the same dict objects again expecting the pre-slice tensors.
- **CUDA context on the recompute thread** (`utils.with_current_cuda_device`, used by `tensor_parallel.checkpoint` and `te_checkpoint`): the recompute runs on the autograd worker thread; kernels launched through the CUDA driver directly (cuTile in the fused mHC kernels) need a current context there, which torch only creates lazily (`Failed to launch cuTile kernel: invalid device context`).
- **HybridModel + `--cross-entropy-fusion-impl linear`**: output layer is `LinearCrossEntropyModule`, same fused linear + CE branch as GPTModel.
- **Fine-grained offload NUMA hint** (`training.py`): a failing `set_ideal_affinity_for_current_gpu` warns per rank instead of aborting (fails when the job's cgroup holds no CPU of the GPU's socket).
- `fp8_utils._get_custom_recipe`: error message as plain string literals (black 26 rewraps the triple-quoted string with trailing blanks in any PR touching the file).

Validation: GB200, 4 ranks. `test_gpt_model.py`, `test_hybrid_model.py`, `test_kda.py`, `test_sequence_packing.py`, `test_random.py`, `test_fp8_utils.py` give the same results as pristine dev (remaining failures are missing MambaSSM and 8-rank-only cases). The PP1+SP+MTP fix was exercised end to end on a DSv3-shaped GPT proxy (TP2 PP1 EP2 SP, THD packing, MTP) in #5258.

**[IMPORTANT Correctness]** The fused linear-CE branch silently drops muP output scaling on HybridModel.

**Failure.** HybridModel supports muP: see the `init_method` choice at L402-406 and `scale_logits_fn=self._scale_logits if self.config.use_mup else None` at L754.

With `--use-mup` and `mup_base_hidden_size != hidden_size`, `TransformerConfig.__post_init__` sets `mup_output_mult = 1 / width_mult` ([transformer_config.py#L3266-L3269](https://github.com/NVIDIA/Megatron-LM/blob/5d65aad46dd168681976f828afe175e729e7ba0e/megatron/core/transformer/transformer_config.py#L3266-L3269)).

Adding `--cross-entropy-loss-fusion --cross-entropy-fusion-impl linear` now takes this branch:
- It returns the loss straight from `output_layer` and never applies `_scale_logits` ([language_module.py#L309-L326](https://github.com/NVIDIA/Megatron-LM/blob/5d65aad46dd168681976f828afe175e729e7ba0e/megatron/core/models/common/language_module/language_module.py#L309-L326)).
- The MTP fused branch also ignores `scale_logits_fn` ([multi_token_prediction.py#L1801-L1820](https://github.com/NVIDIA/Megatron-LM/blob/5d65aad46dd168681976f828afe175e729e7ba0e/megatron/core/transformer/multi_token_prediction.py#L1801-L1820)).

Example: hidden 4096 with base 1024 gives width_mult 4. Loss and gradients are then computed on logits 4× larger than the muP model defines. Training runs without error, but transferred hyperparameters no longer hold.

Before this PR, the combination failed loudly on HybridModel: `ColumnParallelLinear` has no `output_cross_entropy_loss`, and `compute_language_model_loss` has no `linear` branch. I found no guard in `TransformerConfig` or `arguments.py`. Expected behavior: either apply the scaling or reject the combination.

**Correction.** The smallest complete fix is to reject the combination in `HybridModel.__init__`, right after the `output_layer` construction (after L413). Neither the main-loss nor the MTP fused path can apply the scaling as written.
```python
        if (
            config.use_mup
            and config.mup_output_mult != 1.0
            and config.cross_entropy_loss_fusion
            and config.cross_entropy_fusion_impl == "linear"
        ):
            raise ValueError(
                "cross_entropy_fusion_impl='linear' does not apply muP output scaling "
                f"(mup_output_mult={config.mup_output_mult}); use 'native' or 'te' with use_mup."
            )
```
Also update the comment at L787-789.

Invariant: when `use_mup` is set and `mup_output_mult != 1.0`, the loss must be computed on `logits * mup_output_mult`.

An exact alternative is to feed `hidden_states * mup_output_mult` to the fused call, both here and in `process_mtp_loss`. Because `bias=False`, this gives the same logits and gradients. It requires passing the multiplier into `process_mtp_loss`.

GPTModel has the same gap, which predates this PR. Putting the check in `TransformerConfig.__post_init__` would cover both models, but it changes GPT behavior and is optional here.

**Preservation.** These cases must keep working:
- muP with the `native`/`te` impl, or with no fusion: L798-801 and `scale_logits_fn` in MTP still scale.
- Linear fusion without muP, or with `mup_output_mult == 1.0` (width_mult 1): must still take the fused branch.
- Inference and `labels is None` paths: unchanged.

**Acceptance.** These are proposed tests; I have not run them. Add them to `tests/unit_tests/models/test_hybrid_model.py`.
1. Build a HybridModel with `use_mup=True, mup_base_hidden_size=hidden_size // 2, cross_entropy_loss_fusion=True, cross_entropy_fusion_impl="linear"`. Expect `ValueError`.
2. Build the same model with `use_mup=False`. Construction should succeed. `forward(..., labels=labels)` should return a loss with the same shape as the `native`-impl loss for identical weights, and close to it. Run this on hardware that supports the linear CE kernel.
3. Existing muP Hybrid tests that use the default impl should pass unchanged.
