# What does this PR do?

## What does this PR do?

Two related changes to `megatron/core/context_parallel_layout` and `MultiLatentAttention`:

1. **Fused TP x CP THD layout conversion.** With sequence parallelism, converting a packed (THD) tensor between the `zigzag` and `contiguous` CP layouts used a TP all-gather, the CP-only all-to-all-v and a TP scatter (the `TODO(yuzhongw)` fallback in `conversion.py`). Every token crossed the TP group twice and all TP ranks ran the same CP permutation. The conversion now runs as a single all-to-all-v over the TP x CP group:
   - `routes.py` builds the fused route (a plain `ThdCpRoute`: send order and split sizes for both layouts, ordered by the TP x CP group's rank order) for every `(cp_rank, tp_rank)` sequence-parallel shard from the same host copy of `cu_seqlens` as the CP-only route. Per-rank layout segments are restricted to the shard's SP window, peers are addressed through a logical `cp_rank * tp_size + tp_rank` -> TP x CP group-rank mapping derived from `torch.distributed.get_process_group_ranks` and validated as a Cartesian product (the SBHD redistribution now shares these helpers), and rows exchanged with a peer are ordered by global token position on both sides. The geometry (group sizes, ranks, rank mapping) is taken from the process groups at conversion time and not stored on the route.
   - `prebuild_thd_cp_partition_routes` / `finalize_packed_seq_params` prebuild exactly one route per microbatch: the fused TP x CP route on `PackedSeqParams.tp_cp_partition_route` under sequence parallelism with fusable groups, otherwise the CP-only route on `cp_partition_route` (both filtered out of the TE attention kwargs like the other MCore-only fields). A microbatch converts either CP-local sequences or sequence-parallel shards, never both, and prebuild raises if a metadata object ends up carrying both routes.
   - `convert_cp_partition_mode` dispatches sequence-parallel THD tensors to the fused path. The composed TP gather -> CP all-to-all -> TP scatter path is kept only for process groups that cannot be fused (no matching `tp_cp_group`) and still emits its RuntimeWarning.
   - Backward is the inverse all-to-all-v through the existing differentiable `index_select` / `all_to_all` / `index_copy_` chain.

2. **MLA converts its input CP layout to zigzag internally.** `MultiLatentAttention.forward` used to raise when a THD input's `cp_partition_mode` was not `zigzag`. It now mirrors `Attention.forward`: `convert_module_input_tensors_cp_partition_mode(..., target_partition_mode="zigzag")` on the way in (after the dynamic-CP group swap), the output gate reads the converted hidden states, and `back_to_input_converter` restores the caller's layout after `linear_proj`. The config check that forbade `cp_partition_mode="contiguous"` with `multi_latent_attention` outside `dsv4_hybrid` is dropped accordingly.

Three follow-up commits round this off:

3. **Route construction proportional to the number of layout segments.** `_build_thd_layout_side_route` collected one Python list entry per local row (O(local tokens) host work per microbatch). It now collects `(first_row, length)` runs, merges runs that continue each other, detects the identity order from the runs, and expands the index tensor vectorized on the host. Bit-identical routes; a randomized CPU test compares the run-based builder (CP-only and TP x CP routes) against the per-row implementation kept in the test.
4. **The fused route is prebuilt only under sequence parallelism.** `finalize_packed_seq_params(..., sequence_parallel=...)` receives the flag from `prepare_packed_seq_params` (`config.sequence_parallel`); without SP the CP-local THD tensors are not SP shards and the route is never needed. The lazy build from the cached host `cu_seqlens` remains the safety net.
5. **Dynamic context parallelism is fused as well.** `parallel_state` creates TP x (dynamic DP x CP sub-group) process groups next to the dynamic DP x CP groups (`get_dynamic_tensor_and_data_context_parallel_groups`; one group per distinct rank set, created in the same order on all ranks, coinciding with the dynamic DP x CP groups for TP = 1). `finalize_packed_seq_params` stores the matching group on `PackedSeqParams.tp_cp_group` under dynamic CP, `resolve_tp_cp_group` hands it to Attention, MultiLatentAttention, GatedDeltaNet and KimiDeltaAttention, and the Cartesian check of the fused route passes for the sub-group. The composed fallback now only serves groups that genuinely cannot be fused.

6. **MTP under sequence parallelism receives the caller's CP-local padding mask.** With SP, `GPTModel`/`HybridModel` scattered the MoE padding mask to the TP rank's sequence shard for the decoder and then handed that shard-length mask to multi-token prediction, whose rolls work in the caller's CP-local layout: contiguous packed CP (and packed CP1) rejected the length mismatch — the temporary config guard against MTP + TP > 1 + SP + contiguous hid exactly this — and the zigzag roll sliced the short mask silently. MTP now gets the caller's mask while the decoder keeps its scattered copy (the MoE layers align a full-length mask to sequence-parallel hidden states themselves); the guard is removed. Covered by a TP2 + SP packed-sequence MTP test and by running MTP in every case of the mixed GDN/GQA model test.

## Performance and numerics on a hybrid model

Measured on a fork branch that carries this PR on top of the Kimi-K3 example model (KDA : MLA = 3 : 1 hybrid layers with MoE and MTP 1), nine-layer proxy, 64 GB300 GPUs (16 nodes x 4), TP4 + sequence parallel, PP1, CP16, EP64, packed THD with 524288-token samples (`max_seqlen_per_dp_cp_rank` 32768), GBS 32, MXFP8, Muon, HybridEP dispatcher with forced balanced routing, same container and cluster for all rows. 20 iterations each; step time and throughput are means over iterations 2-20, memory is the largest `max allocated` reported by any rank.

| Code | `cp_partition_mode` | s / iteration | TFLOP/s / GPU | peak allocated | vs. baseline |
| --- | --- | ---: | ---: | ---: | ---: |
| before this PR | zigzag (the only layout MLA accepted) | 71.80 | 823.6 | 75.0 GiB | 1.000 |
| this PR | zigzag | 70.28 | 841.4 | 69.7 GiB | 0.979 |
| this PR | contiguous | 69.72 | 848.2 | 70.1 GiB | 0.971 |

- Row 2 isolates item 1: under zigzag every KDA layer converts zigzag -> contiguous -> zigzag around itself (chunkwise linear attention wants contiguous slices), and the fused TP x CP all-to-all replaces the TP all-gather + CP all-to-all-v + TP scatter composition. The 5 GiB drop in peak memory is the gathered full-sequence TP buffer of the composed path that no longer exists.
- Row 3 adds item 2: with MLA converting its own input to zigzag internally the model can run the contiguous layout, so only the MLA layers (one in four) convert instead of every KDA layer.

Numerics of the layout switch were checked on real data (LongAlign-10k, 64K packed samples, TP4 + SP, CP4, EP64, GBS 256), resuming a checkpoint of the same proxy with `--finetune`, router load balancing `none`, no forced balancing, 32 steps: contiguous on this PR vs. zigzag on the pre-PR code agrees step for step with max |Δ lm loss| 2.3e-4 (mean 7.5e-5), max |Δ MTP loss| 1.7e-4, max |Δ grad norm| 0.006; zigzag on this PR vs. zigzag before differs by 3e-6 at step 1 and at most 2.2e-4 over the 32 steps.

- `tests/unit_tests/test_context_parallel_layout.py` (follow-ups): randomized run-based vs per-row route comparison; `finalize_packed_seq_params` prebuild gating and dynamic TP x CP group resolution on CPU; a GPU test that converts sequence-parallel shards over a dynamic sub-group (TP2, static CP1, sub-group of size 2 at 8 ranks) fused vs composed, bit for bit, and checks the metadata path picks the TP x sub-group.
- `tests/unit_tests/test_parallel_state.py`: `test_dynamic_tp_dp_cp_groups` checks the rank sets of the new groups for TP2 and TP1 at 8 ranks and that the full size maps to the tp-dp-cp group.
- `tests/unit_tests/transformer/test_thd_correctness.py`: `test_mixed_gdn_gqa_model_cp_correctness` gains TP2 + sequence-parallel configurations; static and dynamic CP both have to take the fused route (no fallback warning), and a model-level fused-vs-composed comparison runs for both.
- `tests/unit_tests/data/test_get_batch.py`, `tests/unit_tests/training/test_packed_seq_utils.py`: assert the `sequence_parallel` flag is forwarded to `finalize_packed_seq_params`.
- `tests/unit_tests/transformer/test_multi_latent_attention.py`: new `TestContextParallelMLAAttentionLayoutConversion` feeds contiguous shards to an MLA module configured for the contiguous layout and checks bit-identical outputs and matching gradients against an identical module fed zigzag shards, for CP2, TP2xCP2, TP2xCP4 and TP4xCP2 with sequence parallelism, packed and padded THD, rope and yarn with and without rope fusion. The padded cases skip when TransformerEngine has no attention backend for padded THD MLA attention (head_dim 192, bf16) on the local TE/cuDNN build, which is also what makes the pre-existing `TestParallelMLAAttention::test_gpu_forward_thd_padded` fail there.
- `tests/unit_tests/transformer/test_transformer_config_dynamic_cp.py`: updated for the removed MLA-specific guard.

Validation: the touched test files were run with the CI marker scheme (default bucket and `--experimental` bucket) on GB300 with 4 and 8 ranks (2 x 4-GPU nodes, TransformerEngine 2.20.0.dev0, PyTorch 2.12/CUDA 13.2 container). `test_context_parallel_layout.py` and `test_transformer_config_dynamic_cp.py`: 235 passed (8 ranks), 217 passed / 18 skipped (4 ranks). `test_thd_correctness.py`: 23 passed (8 ranks), including the dynamic CP + SP configurations on the fused route. `test_parallel_state.py`: same result as the base commit plus the new dynamic TP x CP group test (8 ranks). `test_get_batch.py` + `test_packed_seq_utils.py`: 161 passed. The new MLA class: all packed cases pass bit-exactly (12 on 8 ranks, 6 on 4 ranks), padded cases skip on that TE/cuDNN build. The pre-existing tests in `test_multi_latent_attention.py` and `test_attention.py` give the same pass/fail set as the base commit on that environment.
