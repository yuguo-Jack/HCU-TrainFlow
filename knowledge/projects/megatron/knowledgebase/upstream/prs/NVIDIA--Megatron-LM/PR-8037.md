# Pass one process-group collection through the pretrain loop

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8037) · state: closed · merged: False

## Original PR description

## Why

`pretrain()` builds the model on a `ProcessGroupCollection`, but the rest of the loop used the global grid: standard DDP and Torch FSDP2 got no collection, `get_megatron_optimizer` read the globals, the schedule was chosen from the global PP/VP sizes and ran on a default collection and communicator built from `parallel_state`, and the parameter norm got `None`. A collection passed to `pretrain()` reached only the model, and `--create-all-gather-group` did nothing under `pretrain()`.

## What

- Build the collection once after `initialize_megatron` and pass it to every DDP wrapper (Torch FSDP2 gets its DP x CP group), the optimizer when Gloo groups are off, schedule selection and the schedules (with a `P2PCommunicator` over its PP group), and the parameter norm.
- Add the all-gather groups to that collection; reject them if their ranks differ from the data-parallel groups.

## Tests

- New `tests/unit_tests/training/test_training_pg_collection.py` (8 cases, all fail on `main`).
- Integration run (main 77391e71cc with all #6307 PRs and the main-based gap fixes merged, against `main`), 4 GPUs: `test_training_pg_collection.py` passes all 11 cases it holds there: 6 of this PR's 8, plus 5 added by later #6307 PRs, one of which replaces the two all-gather rank-mismatch cases. `main` has no such file. In the integration run, this PR's test file shows no regressions against main.
- Before the sync with main 77391e71cc, on 4 GPUs, mock data, `--deterministic-mode`: loss, grad norm, params norm and evaluation loss are bit-identical to `main` over 12 iterations for TP2 PP2 SP, PP2 VPP2, MoE EP2 PP2, distributed optimizer (PP2; 2 instances), Megatron-FSDP with `--create-all-gather-group` (dense, MoE) and Torch FSDP2, via both the model-builder and `model_provider` paths. The schedules' default builder is no longer reached.
- Before the sync, with GTP-remat 2, every group the schedules and `finalize_model_grads` read is unchanged.

## Compatibility

No API change; `train()`/`evaluate()` without a collection behave as before. With Gloo groups (default), the optimizer still builds its groups from `parallel_state` until the collection carries them.
