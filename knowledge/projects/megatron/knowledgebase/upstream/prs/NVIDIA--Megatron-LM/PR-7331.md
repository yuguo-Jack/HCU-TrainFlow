# What does this PR do?

Adds `--moe-ep-chunk-overlap` (default **off**): a token-chunked, two-stream schedule that overlaps the MoE expert-parallel all-to-alls with the expert GEMMs, replacing the routed-expert region (dispatch → FC1/act/FC2 → combine) rather than wrapping the existing token dispatcher.

:warning: This is a sizeable addition (**+1452 / −9** over 9 files). Happy to open a design issue first if @NVIDIA/mcore-oncall would prefer that — flagging it proactively per the note above.

## Design

The flag is off by default and gated behind a narrow support envelope. When on, `MoELayer` routes the routed-expert region through `MoEEPChunkOverlapRuntime` instead of the flex token dispatcher:

```
forward  (ascending)   FC1(c) → FC2(c)   ||   Dispatch(c+1) or Combine(c−1)
backward (descending)  dgrad(c)          ||   Dispatch(c−1) or Combine(c+1)
                       wgrad(c)          ||   Combine(c)
```

Compute stays on the caller's ambient stream; a single comm stream carries both collectives. Every cross-stream edge is an explicit `torch.cuda.Event`. Weight gradients park in TE's per-op `WeightGradStore` (`delay_wgrad_compute=True`) and are drained inside the loop, so each chunk's wgrad runs under its own chunk's combine.

### New surface

| flag | default | meaning |
|---|---|---|
| `--moe-ep-chunk-overlap` | `False` | enable the path |
| `--moe-ep-chunk-overlap-num-chunks` | `4` | source-token chunks per microbatch |
| `--moe-ep-chunk-overlap-num-comm-sms` | `32` | SM budget for the comm stream |

Transport is selected from the **existing** `moe_flex_dispatcher_backend` (`hybridep` / `ncclep`) rather than a new flag. Public API is one name, `MoEEPChunkOverlapRuntime`.

### Files

| file | change |
|---|---|
| `moe/moe_ep_chunk_overlap/` (5 new files) | the runtime, the transport ABC, and the HybridEP / NCCL-EP transports |
| `moe/fused_a2a.py` | **+122 / −0** — purely additive: `make_hybrid_ep_buffer` and two shape-named stateless legs `hybrid_ep_dispatch_leg` / `hybrid_ep_combine_leg`. No existing trunk body is modified; the flex dispatcher's call sites are untouched. |

### Support envelope (refused, loudly, at construction or per-forward)

`expert_tensor_parallel_size=1`, `context_parallel_size=1`, `moe_router_dtype=fp32`, `add_bias_linear=False`, `moe_apply_probs_on_input=False`, MXFP8 (`fp8_recipe=mxfp8`, `first_last_layers_bf16=False`), activation ∈ {gated silu/quick_gelu, ungated squared_relu}, `moe_paged_stash=False`, `overlap_moe_expert_parallel_comm=False`, `padding_mask=None`. `recompute_granularity='full'` and `'moe' in recompute_modules` are refused because TE's `WeightGradStore` is a FIFO with no chunk identity and a re-run forward reorders it silently. `'moe_act'` **is** supported. Expert GTP weight remat is supported at ≥ 2 local experts.

## Testing — what was actually measured

All on 8× B300 (sm_103), torch 2.11.0+cu130, TE 2.18/2.20, HybridEP, MXFP8, world 2–4, against this branch rebased onto `main` @ `79097b457`.

| check | result |
|---|---|
| routed-expert branch live (real `GPTModel`, fwd+bwd) | **PASS** — 482/3072 routing probs nonzero, **8/8 expert wgrads alive**, `max\|main_grad\| 1.39e-04` |
| same probe with a seeded fault | **FAIL** as required — 0/3072, 0/8 — so the check demonstrably detects |
| selective recompute (`moe_act`, ungated squared_relu) | **PASS**, 4/4 chunks, 8/8 wgrads alive |
| fine-grained activation offloading (`fused_group_mlp`) | **PASS**, 4/4 chunks, 8/8 wgrads alive |
| full-iteration CUDA graphs, no EGTP, vs eager | **96/96 bitwise** (4 ranks × 3 series × 8 iters) |
| partial CUDA graphs, ± EGTP, vs eager | **96/96 bitwise** each |

The liveness check is an **absolute magnitude** assertion, not a differential, deliberately: an earlier defect on this path zeroed every routing probability and the loss curve was indistinguishable from healthy (`6.968` vs `6.975`). A loss gate would not have caught it.
