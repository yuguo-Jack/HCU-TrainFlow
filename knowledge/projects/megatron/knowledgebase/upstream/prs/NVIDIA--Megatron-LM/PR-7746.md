# What does this PR do?

Align the Torch sampler's top-p support with the ascending low-probability-tail cutoff used by NeMo-RL policy recomputation. For 16 equal logits and top_p=0.5, the old descending/shifted cutoff retained 9 tokens while training retained 8; sorting in opposite directions can also select different tied token IDs. A token sampled outside the recomputed support receives a -inf training logprob.

Remove the ascending tail whose cumulative probability is <= 1-top_p, always keeping the highest-logit token. This intentionally changes Torch sampling at exact boundaries and ties, so old seeded outputs can change. It does not promise equal support for numerically different training/inference logits or change the FlashInfer backend.
