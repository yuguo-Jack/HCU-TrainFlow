## Original PR description

## Summary

<img width="1687" height="645" alt="image" src="https://github.com/user-attachments/assets/91c02649-d491-4f46-ac13-226305530a0b" />


Add `register_prefetch_chain(name, weights)` so model integrations can assign already GTP-sharded weights to independent prefetch chains without relying on parameter-name conventions.

- Preserve default classification for unregistered weights.
- Keep each grouped projection’s local-expert weights together.
- Preserve warmup-discovered ordering, CUDA-graph boundaries and shared communication streams.
- Isolate gathered-buffer ownership across independent chains.
- Reject conflicting assignments and registration after initialization; allow empty optional selections.

Registration controls scheduling membership—not which parameters are sharded.

### Update the documented default grouped-chain IDs

The [grouped-expert Design paragraph](https://github.com/NVIDIA/Megatron-LM/blob/c9434b4e36273ce604c0a779c27f351c240b6863/docs/api-guide/core/generalized_tensor_parallel.md#L777) still presents `GTP_remat_grouped_fc1_{graphed,ungraphed}` and `GTP_remat_grouped_fc2_{graphed,ungraphed}` as the runtime chain IDs. These matched the [previous initialization path](https://github.com/NVIDIA/Megatron-LM/blob/0201ccf0eb96d86e3b5439c00cd17031542a4053/megatron/core/tensor_parallel/generalized_tensor_parallelism.py#L701-L721). With the new [automatic registration](https://github.com/NVIDIA/Megatron-LM/blob/c9434b4e36273ce604c0a779c27f351c240b6863/megatron/core/tensor_parallel/generalized_tensor_parallelism.py#L701-L740), ordinary MoE initialization instead produces `GTP_registered_default_expert_fc1_ungraphed` and `GTP_registered_default_expert_fc2_ungraphed`, or their `_graphed` counterparts. Readers inspecting the logged chains will not find the documented defaults.

Replace that paragraph's parenthetical examples with:

```text
(`GTP_registered_default_expert_fc1_{graphed,ungraphed}` /
`GTP_registered_default_expert_fc2_{graphed,ungraphed}` under standard initialization;
explicit registrations or default-name collisions can change the logical-name component)
```

Preserve the explanation that FC1/FC2 are separate, same-role chains across consecutive blocks and share communication streams. The old IDs remain valid for the low-level unregistered classifier; do not describe them as universally invalid.

**Proposed acceptance checks, not executed:** trace a standard-name grouped FC1/FC2 pair through `classify_gtp_remat_chains` in eager and full-iteration modes and confirm the documented IDs match the resolver. Retain the [registration assertions](https://github.com/NVIDIA/Megatron-LM/blob/c9434b4e36273ce604c0a779c27f351c240b6863/tests/unit_tests/generalized_tensor_parallel/test_gtp_prefetch_registration.py#L123-L136) that FC1/FC2 have distinct chain IDs but the same stream key. This replacement is source-reasoned and requires author verification.

This is the [documented synchronous fallback](https://github.com/NVIDIA/Megatron-LM/blob/c9434b4e36273ce604c0a779c27f351c240b6863/docs/api-guide/core/generalized_tensor_parallel.md#L714). The [previous entrypoint](https://github.com/NVIDIA/Megatron-LM/blob/0201ccf0eb96d86e3b5439c00cd17031542a4053/megatron/core/tensor_parallel/generalized_tensor_parallelism.py#L701-L721) accepted it: its eager classification matched the initial `GTP_ungraphed` identity, and warmup skipped linking. The new default-registration pass includes it and raises `RuntimeError` at the [late-registration guard](https://github.com/NVIDIA/Megatron-LM/blob/c9434b4e36273ce604c0a779c27f351c240b6863/megatron/core/tensor_parallel/generalized_tensor_parallelism.py#L207-L212), preventing model setup.

In `_register_default_prefetch_chains`, skip these already opted-out weights when collecting defaults:

```suggestion
        if hasattr(weight, "_gtp_prefetch_chain_name") or weight.prefetch_initialized:
```

Keep the public `register_prefetch_chain` late-registration rejection unchanged. The invariant is that automatic defaults must not convert an existing chain-free opt-out into a registration request. Fresh dense weights must still register; explicit overrides must remain untouched; fresh grouped projections must still register all local-expert members together.

**Proposed regression check, not executed:** using `_weight` and `_model` from the [registration tests](https://github.com/NVIDIA/Megatron-LM/blob/c9434b4e36273ce604c0a779c27f351c240b6863/tests/unit_tests/generalized_tensor_parallel/test_gtp_prefetch_registration.py#L26-L35), create two dense weights, set both opt-out flags on the first, and classify with CUDA graphs disabled. Expect no exception, no `_gtp_prefetch_chain_name` on the first, its chain ID still `GTP_ungraphed`, and `default_dense` membership on the fresh peer. Inspect that the [warmup linking guard](https://github.com/NVIDIA/Megatron-LM/blob/c9434b4e36273ce604c0a779c27f351c240b6863/megatron/core/tensor_parallel/generalized_tensor_parallelism.py#L2084-L2092) still excludes the opted-out weight. Retain the existing [late-registration rejection](https://github.com/NVIDIA/Megatron-LM/blob/c9434b4e36273ce604c0a779c27f351c240b6863/tests/unit_tests/generalized_tensor_parallel/test_gtp_prefetch_registration.py#L66-L73) and [initialization assertions](https://github.com/NVIDIA/Megatron-LM/blob/c9434b4e36273ce604c0a779c27f351c240b6863/tests/unit_tests/generalized_tensor_parallel/test_gtp_prefetch_registration.py#L233-L243): custom membership survives, replicated weights stay unregistered, Mamba projections share a dense chain, and FC1/FC2 each retain their complete projection.
