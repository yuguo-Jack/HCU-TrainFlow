# Add TensorAtomic support in MFSDPv2

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7396) · state: closed · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
   Add a `TensorAtomic` shard placement to MFSDP v2, so that every logical tensor in a
  `DBuffer` is assigned as a whole to one data-parallel rank instead of being split
  row-wise across ranks. This is the building block for owner-based (non-uniform)
  parameter sharding in MFSDP v2.

## Design
  `GlobalLayout` now records the per-rank split explicitly and every buffer in a
  parameter group is planned against one shared layout.

  - **`placement.py`**: add `TensorAtomic()`, a parameter-less dim-0 `Shard`. The owner
    assignment is not carried by the placement.
  - **`layout.py`**: `GlobalLayout` gains `rank_segment_offsets` (`dp_size + 1` boundaries
    of each rank's contiguous segment). `build(..., reference=, tensor_owners=)` fills it
    with a uniform split for `Flat` / `BlockAtomic`, or by packing tensors in owner order
    for `TensorAtomic` (no padding, `tensor_owners` must be non-decreasing).
    `get_local_range` reads the table for the innermost Shard axis and splits outer Shard
    axes evenly, so multi-axis `Flat` behavior is unchanged. `is_uniform` and
    `rank_segments` are derived from the table.
  - **`dbuffer.py`**: `allgather` / `reduce_scatter` keep `*_into_tensor` when
    `layout.is_uniform`, otherwise use the list variants over `layout.rank_segments`.
    `empty` / `distribute_tensors` accept `tensor_owners=`.
  - **`fully_shard.py` / `module.py`**: `fully_shard(..., param_to_owner=)` takes the
    owner map from the caller. Each dtype group is stable-sorted by owner rank before
    `FsdpParameterGroup` is built, so tensors of one rank form a contiguous segment and
    the map never travels below this layer.
  - **`parameter_group.py`**: receives only `tensor_owners`, resolves one layout reference
    (`TensorAtomic`, or `BlockAtomic` with the LCM of block sizes, or `Flat`), and builds
    the single shared `GlobalLayout`. `TensorAtomic` requires a 1-D mesh, cannot mix with
    `Flat` / `BlockAtomic`, and is rejected with `use_symmetric_memory=True`.
  - **`quantized_dbuffer.py`**: scale layouts carry `rank_segment_offsets`; no behavior
    change.


## Limitations

  - `TensorAtomic` currently supports **only 1-D device meshes**.
  - `TensorAtomic` is not supported together with symmetric-memory collectives.
  - Only the `DBuffer` / `GlobalLayout` / `fully_shard` plumbing is included. The owner
    planner that produces `param_to_owner`, plus optimizer, checkpointing and end-to-end
    integration, are left to follow-up PRs.

## Testing

  - 30 new unit tests in `tests/unit_tests/distributed/mfsdp_v2/test_dbuffer.py`
    covering layout construction, invalid assignments, reference/placement
    compatibility checks, `cast`, `view`, `from_local`, `distribute_tensors`,
    storage release/reallocate, and `allgather` / `allreduce` / `reduce_scatter`
    round trips with `TensorAtomic`.
  - Full `tests/unit_tests/distributed/mfsdp_v2` passes on 1 node x 8 H100.
