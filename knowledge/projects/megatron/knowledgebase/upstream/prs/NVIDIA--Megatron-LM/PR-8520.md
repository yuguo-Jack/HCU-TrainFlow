# fix(MoE): keep global aux loss counters in int64 under Float16Module

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8520) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Register `TopKRouter`'s `global_tokens_per_expert` and `ga_steps` buffers as int64, so `Float16Module` no longer casts the global aux loss counters to bf16/fp16. In bf16, `ga_steps` stops at 256 and the per-expert counts lose precision; in fp16 they overflow.

### What's wrong

`TopKRouter` registers `global_tokens_per_expert` and `ga_steps` as float32 buffers. `Float16Module` casts every floating-point buffer to the model dtype, so in a `--bf16` or `--fp16` run both are bf16/fp16. `_apply_global_aux_loss` adds to them on every micro-batch and divides one by the other:

- bf16: `ga_steps += 1` stops at 256 (256 + 1 rounds to 256), and the running per-expert counts lose precision as they grow (8 significant bits).
- fp16: the running counts overflow to `inf` once an expert passes 65504.

The per-micro-batch counts are reduced over `tp_dp_cp_group` in int64 before they are added, so the reduction is not affected; the accumulation is. `local_tokens_per_expert` had the same problem and was moved to int64 in #7081. These two buffers were left as float32.

### Reproduction

```python
# torchrun --nproc-per-node 1 repro_short.py   (from a Megatron-LM checkout, one GPU)
import torch

from megatron.core.transformer.module import Float16Module
from megatron.core.transformer.moe.moe_utils import get_default_pg_collection
from megatron.core.transformer.moe.router import TopKRouter
from megatron.core.transformer.transformer_config import TransformerConfig
from tests.unit_tests.test_utilities import Utils

Utils.initialize_model_parallel(1, 1)
config = TransformerConfig(
    num_layers=1, hidden_size=128, num_attention_heads=8, num_moe_experts=64,
    moe_router_topk=8, moe_router_load_balancing_type="global_aux_loss",
    moe_aux_loss_coeff=1e-3, bf16=True, params_dtype=torch.bfloat16, add_bias_linear=False,
)
router = TopKRouter(config, pg_collection=get_default_pg_collection())
router.set_layer_number(1)
router = Float16Module(config, router.cuda()).module
print(router.global_tokens_per_expert.dtype, router.ga_steps.dtype)
for _ in range(300):  # 300 micro-batches in one global batch
    router(torch.randn(4096, 2, 128, device="cuda", dtype=torch.bfloat16))
print("ga_steps:", router.ga_steps.item())
```

On main (2052769) this prints `torch.bfloat16 torch.bfloat16` and `ga_steps: 256.0`. With this PR it prints `torch.int64 torch.int64` and `ga_steps: 300`.

A longer script runs the same setup with fresh inputs each micro-batch (about 1024 assignments per expert per micro-batch). It records the counts and loss inputs the router actually uses and compares them with an exact int64 running sum fed to the same `switch_load_balancing_loss_func` with the same probs:

| micro-batches | `ga_steps` (bf16) | max per-expert count error | global aux loss error |
|---:|---:|---:|---:|
| 32 | 32 | 1.9% | 0.2% |
| 128 | 128 | 7.8% | 1.0% |
| 256 | 256 | 15.4% | 0.2% |
| 300 | 256 | 32.7% | 20.1% |
| 512 | 256 | 99.1% | 58.7% |

With 4x larger counts per micro-batch the numbers are nearly identical: the error depends on the number of micro-batches. In fp16 the loss is `inf` from about 64 micro-batches. With this PR every row shows 0.00%.

### Impact

- Affected: `moe_router_load_balancing_type="global_aux_loss"`, or a list that contains it, with bf16 or fp16. It is not the default (`aux_loss`), and `aux_loss`/`seq_aux_loss` do not use these buffers. Megatron-Bridge's Qwen3-Next, Qwen3.5, Qwen3.5-VL and EXAONE-MoE providers select `global_aux_loss`.
- The tracker is reset once per global batch (`reset_model_temporary_tensors`), so the error grows with micro-batches per global batch, GBS / (MBS x DP). Count errors start at 2% by 32 micro-batches and reach 15% at 256. Beyond 256 the average is badly wrong.
- The gradient of the aux loss with respect to expert i's probabilities is proportional to that expert's count, so the per-expert error goes straight into the balancing gradient. The logged loss hides part of this, because the errors partly cancel in the sum.
- fp16: an `inf` aux loss gives `inf` router gradients, which should make the loss scaler skip the step. I have not run a full fp16 training loop to confirm this.

### Fix

Register both buffers as `torch.int64`, as #7081 did for `local_tokens_per_expert`; `Float16Module` leaves integer buffers alone. `global_tokens_per_expert / ga_steps` then gives a float32 average. That is the dtype the loss gets today when the router is not cast. TE's `fused_moe_aux_loss` accepts it: TE documents int32/int64/fp32/bf16. Both buffers are `persistent=False`, so checkpoints are unchanged.

#7214 (open) edits the same lines for an unrelated normalization issue. It adds an int64 `global_num_tokens` counter, which is consistent with this change; whichever lands second needs a trivial rebase.

The functional tests `gpt3_moe_mcore_te_tp4_ep2_etp2_pp2_scoped_cudagraph{,_1node}` use `global_aux_loss` with bf16: 16 micro-batches and about 512 counts per expert per micro-batch, already above bf16's exact range. Their golden values may move slightly. I could not run them.

### Tests

- New `TestRouterAuxLoss::test_global_aux_loss_with_float16_module`: it wraps the router in `Float16Module` and feeds the same micro-batch 300 times. It checks that `ga_steps == 300`, that the counts equal 300x the first micro-batch's counts, and that the last global aux loss equals the first. On main it fails (`ga_steps` is 256; with the loss assert first, 1.1995 vs 1.0003). With the fix it passes.
- `test_aux_loss.py` + `test_routers.py`, run on 1 GPU (RTX 5070 Ti, torch 2.14.1+cu130, no TE):
  - before: 102 passed, 71 failed, 15 errors, 36 skipped
  - after: 103 passed, 70 failed, 15 errors, 36 skipped

  The remaining failures and errors are the same set before and after. All of them are `world_size (1) is not divisible by N` (8-GPU parametrizations), and the skips are TE-only tests. I have not run the multi-GPU `global_aux_loss` tests or the TE fused path.

```python
def test_global_aux_loss_float16_replays(self, monkeypatch):
    from megatron.core.transformer.module import Float16Module

    self._init()
    seeded()
    config = _moe_config(
        hidden_size=16,
        num_attention_heads=4,
        num_moe_experts=32,
        moe_router_topk=8,
        moe_router_load_balancing_type="global_aux_loss",
        moe_aux_loss_coeff=1.0,
        moe_router_dtype=None,
        moe_router_fusion=False,
        moe_router_aux_loss_fusion=False,
    )
    router = TopKRouter(
        config, pg_collection=ProcessGroupCollection.use_mpu_process_groups()
    ).cuda()
    router.set_layer_number(1)
    router = Float16Module(config, router).module
    assert router.global_tokens_per_expert.dtype == torch.int64
    assert router.ga_steps.dtype == torch.int64
    monkeypatch.setattr(
        moe_utils.MoEAuxLossAutoScaler,
        "main_loss_backward_scale",
        torch.ones((), device="cuda"),
    )
    hidden = torch.randn(
        256, 2, 16, device="cuda", dtype=torch.bfloat16, requires_grad=True
    )
    tracker = moe_utils.get_moe_metrics_tracker()

    def replay(hidden):
        router.reset_global_aux_loss_tracker()
        tracker.clear()
        router.weight.grad = None
        for step in range(300):
            probs, routing = router(hidden)
            if step == 0:
                first_counts = router.global_tokens_per_expert.clone()
        assert router.ga_steps.item() == 300
        assert torch.equal(router.global_tokens_per_expert, first_counts * 300)
        probs.backward(torch.zeros_like(probs))
        return (
            probs,
            routing,
            router.global_tokens_per_expert.clone(),
            router.ga_steps.clone(),
            router.weight.grad.clone(),
            hidden.grad.clone(),
        )

    try:
        with deterministic_algorithms(True):
            assert_replays_bit_exact(
                replay, (hidden,), backward=False, replays=3,
                contention=True, what="global aux loss under Float16Module",
            )
    finally:
        tracker.clear()
```
