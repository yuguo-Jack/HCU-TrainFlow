# What does this PR do?

Makes `tools/checkpoint/hybrid_conversion.py` work again on current hybrid (Mamba / Nemotron-H) checkpoints. `examples/mamba/README.md` points users to this script to change the TP/PP size of a hybrid checkpoint, but today it fails before converting anything.

It fails in three ways, and this PR fixes each one:

1. **Loading fails.** `torch.load` uses `weights_only=True` by default since PyTorch 2.6, and every Megatron checkpoint pickles an `argparse.Namespace`. The script now calls `megatron.core.safe_globals.register_safe_globals()` before loading.
2. **`Unknown tensor name decoder.layers.0.mixer.in_proj.layer_norm_weight`.** This is the error reported in #1336. The fused input norm of the Mamba mixer (from `TELayerNormColumnParallelLinear`) had no entry in `tp_split_dim`. It is now marked `-1` (replicated on every TP rank), like the other layer-norm weights.
3. **`combine_tp_tensors()` read `args.mamba_d_state`** from the module-level global instead of its `params` argument, so it only worked when run as a script. It now uses `params.mamba_d_state`.

### Testing

New `tests/unit_tests/tools/checkpoint/test_hybrid_conversion.py`: builds a tiny `M*-` hybrid checkpoint (Mamba, attention and MLP layers with TE fused norms), converts TP1 → TP2 → TP1, and checks that the fused norm is replicated on both TP2 ranks and that every tensor round-trips exactly.

```
PYTHONPATH=. python -m pytest -q tests/unit_tests/tools/checkpoint/test_hybrid_conversion.py
```

- Without the fix: fails with `Exception: Unknown tensor name decoder.layers.0.mixer.in_proj.layer_norm_weight`.
- With the fix: passes.
- `tests/unit_tests/tools/checkpoint/`: the same 23 tests fail on `main` and on this branch in my CPU-only environment (all in `test_weighted_merge.py`, unrelated to this change); everything else passes.
- black (`--skip-magic-trailing-comma --skip-string-normalization`), isort and ruff are clean.

I tested on CPU only, with PyTorch 2.14.1.
