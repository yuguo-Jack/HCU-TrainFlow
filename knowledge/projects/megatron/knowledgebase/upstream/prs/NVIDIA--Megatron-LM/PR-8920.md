# [Dev] Converge the LayerWise / DistOpt / Muon optimizer area with main

# What does this PR do?

Replaces dev's own implementations of the layer-wise distributed optimizer (Muon), its sibling `DistributedOptimizer` and Muon's QKV handling with the converged code of the companion main PR (https://github.com/NVIDIA/Megatron-LM/pull/8919), keeping dev-only features. If both PRs merge, main and dev carry one implementation of this area; the remaining dev-only part is chunked optimizer-state offload.

Production code: +1467 / −1810 across 24 files (tests: +1548 / −1397).

## Changes

| Commit | Change |
| --- | --- |
| Optimizer: converge the LayerWise / DistOpt / Muon area with main | The LayerWise layout strategy (`--layer-wise-param-layout {padded,compact}`), the compact layout with an expert-DP sibling `DistributedOptimizer`, whole-param FP8 gathers (BF16 staged from the FP32 masters, requantized on every rank), QKV layout metadata with opt-in per-head and MLA splits, the checkpoint fixes, the device-side grad-norm combination, Q(bf16(master)) FP8 copies, QK-clip for HybridModel/MTP and buffers without CPU backup. Replaces `decouple_ddp_layout`, `merge_layerwise_fp8_grads` and dev's split-QKV variants. Chunked optimizer-state offload is rewired onto the converged layout API, and its DistOpt param-buffer staging now resets only its own bucket groups. |
| LayerWise: drop the legacy layout and the boolean layout flags | Removes `--no-use-layer-wise-param-layout` and `--use-layer-wise-param-layout`; `--layer-wise-param-layout` is the only switch. |
| DDP: partition bucket groups by owner and DDP config | With the compact layout and `reduce_scatter_with_fp32_accumulation`, LayerWise and DistOpt buckets could get each other's collectives; buffers are now partitioned by optimizer ownership and DDP config first. |
| Optimizer: build the layer-wise optimizer for fully frozen stages | A pipeline stage whose params are all frozen is no longer rejected. |
| LayerWise: reject FP8 params the padded layout cannot publish | dev's `validate_args` guard (padded FP8 param gather only for MXFP8 with the reused grad buffer) now lives in the shared LayerWise code. |

## Behavior changes for dev users

- The default layout becomes `padded`, as on main. Pass `--layer-wise-param-layout compact` to keep the previous default.
- `--no-use-layer-wise-param-layout` and `--use-layer-wise-param-layout` are removed and fail to parse.
- The TP > num_query_groups split and the GTP blockwise/distributed split variants follow main (skip / whole-matrix fallback).
- `merge_layerwise_fp8_grads` is removed, so FP8 and BF16 Muon gradients no longer share buckets.
- The compact layout no longer requires `--reuse-grad-buf-for-mxfp8-param-ag` for MXFP8.
- `--ckpt-format torch` is rejected for the layer-wise optimizer. It did not save the sibling `DistributedOptimizer` state.
- Fixed: with chunked offload, compact + MXFP8 + `--reuse-grad-buf-for-mxfp8-param-ag` + overlap diverged from the third step, because the DistOpt staging made already-published LayerWise groups gather again from offloaded masters.

Kept dev-only: Megatron-FSDP options, the FSDP model-to-main no-op, ungated FP8 shard quantization, the `--offload-optimizer-states` alias, nonuniform TP, frozen expert bias, DSv4 / head-wise gate annotations, chunked optimizer-state offload.

## Testing

- 8×H100 and 8×B300 under `--deterministic-mode`, comparing loss and grad norm at every step:
  - with `--layer-wise-param-layout compact`, dense, MoE and B300 MXFP8 with overlap are bitwise identical to dev;
  - offload on and off are bitwise identical (Adam, Muon compact, overlap, MoE, three offload managers, B300 MXFP8), including `torch_dist` resume;
  - the dev and main PRs are bitwise identical on their shared configurations;
  - `torch_dist` checkpoints written by dev (compact and padded) resume bitwise.
- Unit tests: the converged suites plus dev's offload, decoupled-FP8 and argument tests, updated for the removed layout and flags.
- Functional tests: `gpt3_moe_mcore_te_ep8_resume_torch_dist_dist_muon` and its `_1node` variant pin `--layer-wise-param-layout compact`, the layout they already ran with, so their golden values stay valid under the new padded default.
