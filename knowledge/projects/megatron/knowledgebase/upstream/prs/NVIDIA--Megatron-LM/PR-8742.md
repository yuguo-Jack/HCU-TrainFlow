# Use the model's process groups in get_batch and the pretraining loaders

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8742) · state: closed · merged: False

## Original PR description

**Why.** `forward_step` passes the model's collection to `get_batch` in `pretrain_gpt.py` and `pretrain_hybrid.py`, but only the sequence-packing path used it. The default path read the global grid on every micro-batch: the TP rank, the broadcast source rank and group, the first and last stage checks, the MTP pipeline group and the CP group that shards the batch. `pretrain_vlm.py` took its stages from the global pipeline grid and broadcast batches over the global TP group. The data loaders that `pretrain()` builds took their DP rank and size, the TP-rank-0 check and the full-validation iteration count from the global grid too. A model built on other groups got batches read, broadcast and sharded over the wrong ranks.

**What.**
- `get_batch` in `pretrain_gpt.py`, `pretrain_hybrid.py` and `pretrain_vlm.py` reads every group from the model's collection. It raises `ValueError` when the collection lacks a group it needs, instead of passing `None` (WORLD) to `torch.distributed`.
- The VLM `model_provider` takes `pre_process`, `post_process` and `add_encoder` from the collection's pipeline group.
- `is_first_or_last_pipeline_stage` takes optional `pp_group` and `vp_size`. Without a group it reads the global state as before.
- `build_train_valid_test_data_iterators`, `build_train_valid_test_data_loaders` and `build_pretraining_data_loader` take `pg_collection`, and `pretrain()` passes its own:
  - the samplers shard over `dp_gtp_remat`, or over `dp` for a collection without the GTP fields;
  - the data pipeline is built on the first rank of the collection's TP group;
  - full validation agrees on the number of evaluation iterations over `dp_cp_gtp_remat`.
- A MIMO run keeps the global defaults, because its providers build their own loaders.

**Tests.** New `tests/unit_tests/data/test_data_path_process_groups.py` patches the global accessors to fail. On TP and DP grids unlike the global one it checks:
- GPT and hybrid `get_batch`: the broadcast, the CP sharding and the stages without data;
- VLM `get_batch` and `forward_step`;
- the pretraining, random and full-validation samplers;
- the data iterators that `pretrain()` builds.

It also checks that a collection without a needed group is rejected, and compares the stage check with the global grid's. The existing `get_batch`, sampler and training tests cover the standard grid. The VLM `model_provider` change has no unit test, because building LLaVA is too heavy for one. The LLaVA training smoke runs it.

On 4 GPUs against main, the new file's 44 tests pass. `tests/unit_tests/data/test_data_samplers.py`, `tests/unit_tests/test_training.py` and `tests/unit_tests/training/test_initialization_lifecycle.py` pass 1, 32 and 112 tests, the same counts as on main. No test fails on either side. In the integration run (main with every #6307 PR merged), this PR's test files show no regressions against main, and the `pretrain_gpt.py`, `pretrain_hybrid.py` and `pretrain_vlm.py` (LLaVA) training smokes give bit-identical losses to main. Before the sync with main, this branch ran the new file on 4 CPU ranks with Gloo: 41 passed, and 3 need CUDA.

**Compatibility.** New arguments default to `None`, which keeps the global groups. On the standard grid the collection holds the global groups, so batches, samplers and reductions are unchanged.
- On main, `pretrain()` has a collection to pass to the loaders only when its caller gives it one. Stock runs keep the global defaults there until #8037 makes `pretrain()` build a collection for every run. `get_batch` uses the collection `get_model()` built the model on.
- GPT and hybrid `get_batch` raise `ValueError` for a collection with `cp=None`, where main used the global CP group. `pretrain()` always sets `cp`.
- `build_train_valid_test_data_loaders` does not check that `tp` is set, and the VLM `model_provider` does not check `pp`. Without them, every rank builds the data pipeline, and every stage gets `pre_process` and `post_process`. `pretrain()`'s collection always has both.
- The VLM `model_provider` reads `pg_collection.pp` directly. On main nothing turns a `None` collection into one there (#6293 does), so a direct call with `pg_collection=None` raises `AttributeError`. In-repo callers go through `get_model()`, which always passes one.
- The new `pg_collection=None` fallbacks are silent. #8759 makes them warn.
- Needs `determinism-exempt`: `megatron/training/utils/common_utils.py` is a registered kernel file, though only its stage predicate changes.

Not covered here: datasets are still built on global TP rank 0 and on the global stages, through the `is_dataset_built_on_rank` that `pretrain_gpt.py` and `pretrain_hybrid.py` import from `megatron/training/datasets/providers.py`, and through the `pretrain_vlm.py` dataset provider. So this PR alone does not make a run with a different TP layout work end to end: a rank that is TP rank 0 in the collection but not globally gets no dataset. #8759 moves the dataset build onto the run's groups. The reads in `dummy_train_step` move in #8741.

Landing:
- #6293, #6303 and every open PR that contains #6293 (#8049, #8055, #8057, #8058, #8059, #8060 and #8073) conflict with this PR in `pretrain_gpt.py` and `pretrain_hybrid.py`, on the `pp_group` line of the MTP call in `get_batch`, and in the `pretrain_vlm.py` imports. Whichever lands second keeps this PR's `get_batch` lines and one `ProcessGroupCollection` import.
- #8741 adds a stricter DP×CP helper to `training.py` than this PR's `_data_parallel_group_with_cp`, which also accepts `dp_cp`. #8757 replaces both with one helper.
