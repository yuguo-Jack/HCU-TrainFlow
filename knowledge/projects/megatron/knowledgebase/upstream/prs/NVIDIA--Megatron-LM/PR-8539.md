# fix(dsa): adapt cuDNN DSA call sites to cuDNN frontend >= 1.26 defaults

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8539) · state: open · merged: False

## Original PR description

## Summary

Main counterpart of #8534.

cuDNN frontend 1.26 (NVIDIA/cudnn-frontend#316) changed two defaults that the DSA cuDNN call sites rely on. `main` pins FE 1.29.1, so both issues are live on `main`. Both are silent: no error, just wrong gradients or a wrong top-k selection.

### 1. Sparse indexer backward: top-k ids are treated as per-batch local

Since FE 1.26, `indexer_backward_wrapper` treats top-k ids as local to each batch unless `topk_indices_global=True`. The sparse-indexer-loss path passes global ids (`b * S_k + local`). With BSHD and more than one sequence per micro-batch, every batch after the first loses its sparse indexer gradient on FE 1.29.

The wrapper is now called through `_call_sparse_indexer_backward`. It sets `topk_indices_global=True` whenever the installed wrapper accepts that parameter (or takes `**kwargs`), and keeps the old call otherwise.

### 2. Causal offsets: the default alignment moved from bottom-right to top-left

When `q_causal_offsets` is not given, FE <= 1.25 aligns the causal mask bottom-right (`seqlen_k * ratio - seqlen_q`), and FE >= 1.26 aligns it top-left (offset 0). On `main`, three callers relied on the old default:

- **The single-sequence packed CP segment scorer** (`_indexer_topk_single_packed_cp_segments`). It crops each query chunk's key prefix so that bottom-right masking gives each row its absolute causal length.
- **The multi-sequence packed CP THD scorer** (`_indexer_topk_multi_packed_cp_thd`). Its varlen call gives each query segment a longer key prefix and passed no offsets. On `dev`, #6206 already passes these offsets; `main` does not have #6206.
- **The BSHD dense score recompute and dense indexer backward.**

With FE 1.26 or newer, the bottom-right offsets are now passed explicitly: a uniform offset for BSHD calls, and per-segment offsets (`segment_k_lengths - segment_q_lengths`) for the THD call. Older frontends and zero-offset calls keep their exact call and kernel compile key. A top-left frontend whose wrapper lacks `q_causal_offsets` fails closed.

### Differences from the dev PR

- `main` has no `utils.filter_kwargs_for_callable`, so the wrapper signature is probed locally (`_wrapper_accepts_kwarg`).
- The THD call site above (item 2, second bullet) is fixed here; on `dev` it is already correct.
- The tests call `main`'s `_indexer_topk_single_packed_cp_segments` signature.

- [x] CPU tests in `test_dsa_cudnn_fe_compat.py`, 23 passed. They use fakes of both frontend generations (`dsa_cudnn_fe_fakes.py`) and cover:
  - version parsing and the 1.25/1.26 gate;
  - fail-closed behavior;
  - the cropped segment scorer and the multi-sequence packed CP THD scorer selecting identical top-k under either default;
  - a negative control for each scorer: with the offsets removed on FE 1.31, the selection changes.
