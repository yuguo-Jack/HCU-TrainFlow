# Synchronize Sinkhorn backward scratch in the fused mHC kernel

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7704) · state: open · merged: False

## Original PR description

The Triton Sinkhorn backward could return NaN input gradients for HC8. The kernel recomputes the forward iterations into global scratch and then reads that scratch back in the reverse pass. After a layout conversion, a warp can read scratch that another warp has not stored yet. With deterministic empty-memory filling, all 192 HC8 input-gradient elements came out NaN at two, four and eight warps, even though the forward output and the scratch were finite once the kernel finished.

This adds a CTA barrier (`tl.debug_barrier()`) between the scratch stores and the reverse-pass reads. It runs in every mode.

Earlier revisions of this PR also made the mHC Triton kernels bypass their autotuners in deterministic mode. Main's autotune policy (#6076) now pins those autotuners from its per-architecture table, and the bypass would have skipped that table and the policy's cross-rank check. That part is dropped, so this PR only fixes the race.

Tests:
- `test_fused_mhc_kernels.py::TestTritonSinkhorn::test_bwd_reads_scratch_after_all_warps_store` runs the Triton Sinkhorn forward and backward with NaN-filled scratch for HC4 and HC8 at one, two, four and eight warps. Outputs and input gradients must be finite, byte-identical across two runs, and match a CPU float64 reference.
- The kernel manifest registers `test_fused_mhc_kernels.py` for the mHC entry, so the coverage gate tracks it.

Validation:
- Focused GB300 runs of 40 direct HC8 diagnostic cases: 8 had nonfinite gradients before the barrier, and all 40 were finite with it. Maximum FP32 reference errors were 3.41e-8 for outputs and 2.61e-9 for input gradients; BF16 maxima were 9.16e-4 and 4.61e-5.
- The reworked test and the merge with current main (`8518b40`) are covered by CI only. Black, isort and Ruff pass.

Related to #7441.
