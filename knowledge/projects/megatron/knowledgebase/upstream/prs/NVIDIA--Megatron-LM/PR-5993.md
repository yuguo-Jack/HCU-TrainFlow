# fix(data): count real tokens in packed-schedule FLOPs statistics

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/5993) · state: open · merged: False

## Original PR description

## Summary

Count real tokens, rather than padding, in packed-schedule FLOPs and TFLOP/s statistics. Each sample is reduced once across DP, without a CP multiplier. Padded execution buffers, and pre-packed samples without real-length metadata, keep their existing behavior.

Rebased after #8592 and removed the dataset-placement fix it already covers. Added DP>1 global-statistics assertions and CPU regression coverage for per-stage scheduling.

Merged main at e1afbb93. Since #8341 moved the dataset-placement predicate into `megatron/training/datasets/providers.py`, the CPU test patches the modules that predicate reads.

  - An 8-process gloo harness passed all 10 layouts through `wrap_data_iterator` and the `training.py` stats hand-off, with and without the CUDA-graph THD document bound.

### Assert global statistics when DP > 1

The [new regression](https://github.com/NVIDIA/Megatron-LM/blob/ca94eed167ccf4fd4faee84708e65c1c92474b45/tests/unit_tests/data/test_packed_schedule_regressions.py#L667-L680) always supplies a size-one DP group, bypassing the new [statistics reduction](https://github.com/NVIDIA/Megatron-LM/blob/ca94eed167ccf4fd4faee84708e65c1c92474b45/megatron/core/datasets/data_schedule_utils.py#L643-L650). Existing distributed coverage either discards the statistics or [checks only their types](https://github.com/NVIDIA/Megatron-LM/blob/ca94eed167ccf4fd4faee84708e65c1c92474b45/tests/unit_tests/test_sequence_packing.py#L760-L781). Removing the new reduction would therefore leave the value assertions passing while DP > 1 returns local, rather than global, totals.

**Correction:** extend `test_wrap_dataloader` to assert both global values. Its pre-packed fixture rounds each input length to 16 and carries no original-length metadata, so its expected statistics must retain that fallback—not use the unrounded `nums`. A small proposed addition immediately after its type assertions is:

```python
expected_lengths = [((length + 15) // 16) * 16 for length in nums]
assert num_total_tokens_this_global_batch == float(sum(expected_lengths))
assert sequence_square_sum_this_global_batch == float(
    sum(length * length for length in expected_lengths)
)
```

Also add this case to that test's [parallelism parameter table](https://github.com/NVIDIA/Megatron-LM/blob/ca94eed167ccf4fd4faee84708e65c1c92474b45/tests/unit_tests/test_sequence_packing.py#L650-L659), giving the eight-rank suite DP=4 and CP=2 for the inherited dynamic-scheduler path:

```python
(1, 1, 2, None, "default_dynamic_cp"),
```

**Preservation and acceptance:** retain the new unpacked-sample assertions that exclude padding, along with their PP/VPP/MTP field-ownership checks. The distributed pre-packed cases above should equal the rounded-length sums exactly, without a CP multiplier. The existing DP>1 static case and the proposed dynamic case should fail the value assertions if the statistics reduction is removed. These are proposed changes and negative-control checks, not executed results.
