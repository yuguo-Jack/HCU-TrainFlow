# DistributedOptimizer: detach quantized params before building fp32 main-param shards

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8245) · state: open · merged: False

## Original PR description

## Problem

In `DistributedOptimizer._build_model_and_main_param_groups`, the fp32 main-param shard for a **quantized** model parameter that has no `get_high_precision_init_val()` is built as

```python
shard_main_param = model_param.float().view(-1)[param_range.start : param_range.end]
```

`model_param` requires grad, so `.float()` records a grad_fn and the shard (and its slice) is a **non-leaf** tensor. The default optimizer path assigns `param_groups` directly and never validates this, but `HybridDeviceOptimizer` (`--optimizer-cpu-offload`) rebuilds its sub-optimizers through `torch.optim.Optimizer.__init__`, whose `add_param_group` rejects it:

```text
File ".../megatron/core/optimizer/cpu_offloading/hybrid_optimizer.py", line 57, in __init__
    super(HybridDeviceOptimizer, self).__init__(
File ".../torch/optim/optimizer.py", line 408, in __init__
    self.add_param_group(cast(dict, param_group))
ValueError: can't optimize a non-leaf Tensor
```

#6212 / #6982 fixed the same pattern for native fp32 params (`model_param.view(-1)[...]` → `model_param.detach().view(-1)[...]`). The quantized branch a few lines below still lacks the `detach()`; this PR applies the identical change there. The master copy never needs autograd history (grads are copied into it manually), and for a quantized tensor `.float()` already materializes a new fp32 tensor, so detaching changes nothing else.

## How it was hit

verl GRPO on **DeepSeek-V4-Flash** (FP8 attention + MXFP4 routed experts loaded through Megatron-Bridge, bf16 training, `optimizer_cpu_offload=True`, non-precision-aware optimizer) failed at optimizer construction on every rank with the trace above (Megatron-LM `fd1121b8`, July 2026). Wrapping `_build_model_and_main_param_groups` in `torch.no_grad()` from the training script was the workaround we have been carrying since; the same shim is in our DeepSeek-V4-Pro GRPO recipe on H100 (64 nodes). With `--use-precision-aware-optimizer` the branch is skipped, which is why precision-aware runs do not see it.

## Change

One statement in `megatron/core/optimizer/distrib_optimizer.py`: `model_param.detach().float().view(-1)[...]` in the quantized `else` branch, plus a comment. No behavior change for the `get_high_precision_init_val()` path or the non-quantized path.

## Testing

- `python -m py_compile` on the file.
- The non-leaf failure reproduces with any quantized param + `optimizer_cpu_offload=True` without `use_precision_aware_optimizer`; with the `no_grad` workaround (functionally equivalent to this detach) the DeepSeek-V4 GRPO runs train normally (log-prob Pearson 0.994–0.995 between rollout and actor over 5+ steps).
