# Fix fused TEGroupedMLP under Megatron-FSDP v2 with combined 1F1B

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8626) · state: open · merged: False

## Original PR description

# What does this PR do?
With `use_transformer_engine_op_fuser=True`, `TEGroupedMLP` runs fc1, the activation, and fc2 as fused TE ops and bypasses `linear_fc1`/`linear_fc2`. With `overlap_moe_expert_parallel_comm=True`, Megatron-FSDP v2 turns off its module level hooks and unshards through hooks on every parameterized submodule  (`register_combined_1f1b_hooks`), including `linear_fc1`/`linear_fc2`. Unsharding also swaps those submodules' Parameter objects. Because the fused path bypasses the submodules, three things broke. Each is fixed in its own commit:

  1. **Forward pre-hooks were replayed with the wrong signature.**
     - Problem: the fused path replays the submodules' forward pre-hooks itself, as `hook(submodule, None)`. MFSDP v2's unshard hooks are registered with `with_kwargs=True` and take `(module, args, kwargs)`, so the first forward raised `TypeError`.
     - Fix: each hook is now dispatched as PyTorch does. Hooks in `_forward_pre_hooks_with_kwargs` get `(module, (), {})`; the others get `(module, ())`.
  2. **The fused ops kept stale parameters.**
     - Problem: the fused ops register the `GroupedLinear` Parameter objects when they are built. After an unshard swaps in the unsharded parameters, the fused ops still read the sharded ones, whose storage has been released (CUDA illegal memory access).
     - Fix: after replaying the forward pre-hooks, the fused ops re-register any parameter whose object changed.
  3. **Backward pre-hooks never ran.**
     - Problem: the fused backward also bypasses fc1/fc2, so their backward pre-hooks (`register_full_backward_pre_hook`) never fire. MFSDP v2 relies on them to unshard the MXFP8 columnwise weights released after forward (CUDA illegal memory access).
     - Fix: the fused output is now wrapped in `IdentityWithBackwardCallback`, a new identity autograd function in `moe_utils.py`. As the last forward op, its backward runs before any fused backward step and replays the submodules' backward pre-hooks. The wrapper is applied only when the output requires grad and some submodule has a backward pre-hook. As in the forward replay, a hook that modifies the gradient raises an error.

  ## Testing
  New `tests/unit_tests/distributed/mfsdp_v2/test_mcore_moe.py::test_fused_grouped_mlp_ep_overlap_training`, with a new helper `run_combined_1f1b_on_microbatches` in `mcore_training_utils.py`. The test needs Blackwell and TE >= 2.14 and is skipped otherwise.
  - Setup: a two-layer GPT MoE model (standard attention, fused grouped MLP, MXFP8 parameters, `fp8_param_gather`, EP=2) wrapped with Megatron-FSDP v2. It trains for 3 steps of 2 microbatches with the `overlap_moe_expert_parallel_comm` 1F1B schedule. With two layers and two microbatches, the schedule reshards a
  layer between a microbatch's forward and its backward.
  - Check: per-step losses and final parameters match the same model trained with the standard loop.
  - Without each fix, the test fails (4x GB300):

  | Code | Result |
  | --- | --- |
  | main | `TypeError: ... missing 1 required positional argument: '_kwargs'` |
  | + commit 1 | CUDA illegal memory access (stale sharded parameters in forward) |
  | + commits 1-2 | CUDA illegal memory access (released MXFP8 columnwise weights in backward) |
  | + commits 1-3 | passes; all of `test_mcore_moe.py` passes |

  Supersedes #8630 and #8682, which carried fixes 2 and 3 separately.
