# Pass the checkpoint converter's process groups to its models

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8744) · state: closed · merged: False

## Original PR description

Depends on #6303 (which includes #6293) and #8033. Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/d3ff6891e4...yx/pstate-t5-checkpoint-tools). The merge takes #6303's process-group allowlist.

**Why.** `tools/checkpoint` built every model on the global `parallel_state` grid. It wrote fake groups into private `parallel_state` globals, set the `_MPU_*` rank and world-size overrides, and called the model provider without a collection. Each model then resolved its groups through the deprecated global fallback. The loader and the saver also picked stages through `mpu.get_*_group().set_rank()` and `mpu.is_pipeline_first_stage()`/`is_pipeline_last_stage()`.

**What.**
- `build_checkpoint_converter_process_groups()` returns the fake groups as a `ProcessGroupCollection` that sets every field, with `None` for the groups conversion does not create. The loader and the saver pass it as `pg_collection` to every model they build. They also pass its groups to `load_checkpoint()` and `save_checkpoint()`, as training does.
- The loader sets each model's TP and PP rank on the collection and derives `pre_process`/`post_process` from the stage it loads. The saver picks its stages on the collection too.
- `megatron.training.checkpointing` still names legacy checkpoint files after the global ranks, and model builders that take no collection still read the global pipeline rank. For those reads, `install_checkpoint_converter_process_groups()` mirrors the same group objects into `parallel_state`. `set_checkpoint_converter_pipeline_rank()` keeps one override, the pipeline rank, because `get_pipeline_model_parallel_rank()` asks `torch.distributed` for the rank and a fake group cannot answer.
- The other `_MPU_*` overrides go, along with the virtual-pipeline writes that nothing on this path reads. Direct `parallel_state` calls drop from 12 to 0 in `loader_base.py`, from 10 to 0 in `saver_base.py` and from 1 to 0 in `loader_llava.py`. The loader and the saver still drive the mirror's 17 private writes and the pipeline-rank override through the two helpers above.
- `initialize_checkpoint_converter_fake_process_groups()` behaves as before and now returns the collection it mirrors.

**Tests.**
- New: with no global groups present, the loader and the saver build each model on their own collection and pass its groups to load and save.
- New: the loader reads each legacy checkpoint file by its (TP, PP) rank.
- New: the collection sets every field, the mirrored groups form `use_mpu_process_groups()`, and the global ranks follow the collection.
- Updated: the existing stage tests require the collection.

The unit tests set `pg_collection` on the loader and the saver directly. Building the collection and installing the mirror in `initialize_megatron_env` are covered only by end-to-end conversion.

In the integration run on 4 GPUs (every #6307 PR merged onto main 77391e71cc), `test_checkpoint_converter_process_groups.py` passes 7 tests vs 1 on main, and `test_checkpoint_converter_pipeline_stages.py`, which main does not have, passes all 9. In the integration run, this PR's test files show no regressions against main. Before the sync, with the other process-group changes from #6307 applied, the converter's functional test module passed all 7 GPT conversions at 8 ranks (TP and PP reshards, TE and local specs). The pre-sync branch also ran both converter test files on 4 CPU ranks with Gloo, with `psutil` stubbed because the CPU environment lacks it: 14 passed, none failed.

**Compatibility.** On the converter's own grid every rank, size and group is the same as before. No `megatron/core` file changes.
- Model providers used with `MegatronCheckpointLoaderBase` and `MegatronCheckpointSaverBase` now receive `pg_collection=`. The in-repo GPT and LLaVA providers accept it. Providers outside the repository must accept it too.
- `load_model_shards`, `save_local_models_to_checkpoint` and `receive_lm` need the `self.pg_collection` that `initialize_megatron_env` sets. A subclass that skips that step fails with an `AttributeError` on `None`.
- Needs `determinism-exempt` only while #6293 is unlanded. This PR changes no kernel file, but this branch's base carries #6293's `dot_product_attention.py` and `dsa.py` changes.
- Known nit: the docstring of `test_fake_groups_satisfy_language_module` still says the saver builds its models without a collection.

Not covered here: `tools/checkpoint/loader_mixtral_hf.py` still makes 7 `_MPU_*` setter calls and uses the mirror. #8762 converts it, replaces the mirror with `parallel_state.register_process_groups()` from #8747, and removes the pipeline-rank override.

Landing: #8033 and #8740 each add a `set_rank` call to the loader's per-stage loop, which this PR rewrites. #8033 is already in this branch. #8740 conflicts in `tools/checkpoint/loader_base.py`, and whichever lands second keeps this PR's loop, which covers that call.

Synced with main 77391e71cc on 2026-11-01 by merging the updated base, so existing commits and review links stay valid. The only conflict was in the process-group allowlist, which now also records the reads main added since this PR was written.
