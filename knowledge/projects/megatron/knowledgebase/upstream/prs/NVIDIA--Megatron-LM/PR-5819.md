- FDecaYed · comment · 2026-10-26T13:42:37Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/5819#issuecomment-6417491042)

Thanks for this. It addresses a failure we traced on current main.

With `--cuda-graph-impl full_iteration` and PP > 1, `StaticBufferLoader` returns the cached batch dict itself ([full_cuda_graph.py#L233](https://github.com/NVIDIA/Megatron-LM/blob/ed9c2c8c1cf4a5438922ae8d215181e7c8b9e0fe/megatron/core/full_cuda_graph.py#L233)). On the first and last stages, `get_batch_on_this_tp_rank` sets the fields that stage doesn't use to `None` in place ([utils.py#L2402-L2418](https://github.com/NVIDIA/Megatron-LM/blob/ed9c2c8c1cf4a5438922ae8d215181e7c8b9e0fe/megatron/core/utils.py#L2402-L2418)). The next refresh then fails with `AttributeError: 'NoneType' object has no attribute 'copy_'`. Copying the container shells while keeping the tensor objects, as this PR does, fixes that root cause.

We replayed main's loader together with the GPT `get_batch` path on CPU, and it failed on the second iteration. Returning a shallow copy of the cached dict, which is what `copy_container_shell` does for flat dicts, avoided the failure without reallocating the cached tensors. We haven't run this PR itself or done any GPU validation.

Could you add a regression test? For example, apply first-stage and last-stage tailoring after each of at least three refreshes, then check that nothing raises, the cached tensors keep their identity, and the consumed fields pick up the new values.

We're closing #5931 in favor of this PR. Its nested refresh changes have no consumer on main today, so there's no need to extend nested refresh here.
