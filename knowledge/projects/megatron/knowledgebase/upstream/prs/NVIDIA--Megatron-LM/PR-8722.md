# Pass the owner's TP group to duplicated-mode linears

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8722) · state: closed · merged: False

## Original PR description

**Why.** In `"duplicated"` mode, `TELinear` asserted that no `tp_group` was given and then took the global TP group as `_tp_group`. That group only sets the weight's checkpoint replica id. MLA, absorbed MLA, the DSA, simplified DSA and CSA indexers, the DSv4 query down projection and the MoE latent projections all ended up with the global group this way. When a model's TP layout differs from the global grid, or no global grid exists, several ranks claim the main replica of the same weight and dist-checkpoint validation rejects the save. `MoELayer` worked around it by overwriting `_tp_group` after construction, which still read the global group first and skipped `InferenceLinear`.

**What.**
- Duplicated `TELinear` accepts `tp_group`. Transformer Engine still runs the layer with no group and `tp_size=1`; the group only becomes `_tp_group`.
- Every in-repo owner passes its collection's TP group. `MoELayer` passes it to `TELinear` and `InferenceLinear` instead of patching `_tp_group`. The KDA two-stage gates `f_a_proj` and `g_a_proj` from #7054, which main builds without a group, pass it too.
- The ModelOpt `Linear`, which the ModelOpt DSA spec builds in duplicated mode, keeps the group instead of rejecting it.
- Passing no group still falls back to the global TP group.

**Tests.** New `tests/unit_tests/transformer/test_duplicated_linear_tp_group.py` (even world size of at least 4). The global grid has TP=2 over adjacent ranks, the owner grid pairs ranks the global grid keeps apart, and the global TP accessors raise. It checks the replica id, that exactly one rank holds the main replica, the standard-grid default, all seven owners and the ModelOpt DSA indexer, in 10 tests. The seventh owner is the KDA two-stage gates (`f_a_proj`, `g_a_proj`). The latent-MoE and ModelOpt `Linear` unit tests are updated. Before the 2026-11-01 sync with main, on 4 GPUs against main, the 9 tests the file then had failed on main and passed here, and nothing that passed on main failed here. The integration run merges all #6307 PRs onto main 77391e71cc and compares against main. On 4 GPUs there, the new file passes 10 tests, `test_latent_moe_layer.py` passes 15 (15 on main) and `test_modelopt_module_spec.py` passes 16 (15 on main). In the integration run, this PR's test files show no regressions against main.

**Compatibility.**
- Keys and shapes are unchanged. On the standard grid the owners' groups are the global ones, so `TELinear` replica ids and checkpoints are unchanged.
- The ModelOpt duplicated `Linear` at TP>1 is the exception. Its replica id is now `(0, tp_rank, dp_rank)` instead of `(0, 0, dp_rank)`, on the standard grid too. On main every TP peer claimed the main replica, so this is a fix, but it changes what ModelOpt checkpoints record. Post-training owners, is that change OK?
- The DSA, simplified DSA and CSA indexers and the CSA compressor now pass `tp_group=` to whatever duplicated linear class the spec supplies. `TELinear`, `InferenceLinear` and the ModelOpt `Linear` accept it. A custom spec class without a `tp_group` argument would raise `TypeError`.
- A duplicated `TELinear` built with `tp_group=None` still uses the global TP group, for external callers such as Megatron-Bridge. Should that fallback become an error later? After this change, #8060's warning on `get_tensor_model_parallel_group_if_none` fires only for those callers. Please land this before #8060. Otherwise stock MLA, DSA, CSA and latent-MoE runs warn in between.
- Gradient sync of duplicated weights in `finalize_model_grads` is unchanged and out of scope.
- Needs `determinism-exempt`: the kernel coverage check flags the touched attention, MoE and TE files, but only process groups change.
- Merges cleanly with #8023, #8035, #8038, #8060 and #8073.

Synced with main 77391e71cc on 2026-11-01 by a merge commit (no conflicts; its message records the KDA adaptation), so existing commits and review links stay valid.
