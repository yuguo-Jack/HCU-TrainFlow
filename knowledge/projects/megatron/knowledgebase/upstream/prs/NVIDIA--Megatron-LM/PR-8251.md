# fix(dist-checkpointing): AUT-2539 key the PG distribution cache by the full proce

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8251) · state: closed · merged: True

## Original PR description

## Background

`--ckpt-pg-tensors-cache-path` stores each process group's save/load shard distribution in a file named after the group's minimum global rank (`pg_dist_<min rank>.pkl`). Different groups can share a minimum rank, for example a data-parallel group over ranks 0-3 and an expert-data-parallel group over ranks 0 and 2. One group could then read or overwrite the other's distribution. `validate_args` blocks this only for training runs that mix the save and load groups. Direct callers of the core API are not protected.

## What changed

- In `exchange_utils.py`, `_pg_dist_cache_file_path` names the file after a SHA-256 digest of the group's ordered global ranks. The in-process memo uses the same key. The minimum-rank member still writes the file.
- In `arguments.py`, only the comment and the assert message change. The assert itself is kept.
- A new test, `test_groups_sharing_min_rank_use_distinct_cache_entries`, is added to `test_pg_distribution_cache.py`:
  - It creates caches for a 4-rank group and its subgroups [0,2] and [1,3].
  - It checks that three cache files exist and that cached reads equal the uncached distribution.
  - It is skipped with fewer than 4 ranks.

## Details

This changes the cache file names. Caches written under the old `pg_dist_<min rank>.pkl` names are no longer read, so they must be regenerated with `--ckpt-pg-tensors-cache-create`.

- svcnemo-autobot · comment · 2026-10-15T16:28:28Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8251#issuecomment-6197016915)

Thanks @cspades. Short answer: it doesn't need to be, and I'd rather not use a readable part as the key.

- The cache file is now `pg_dist_<sha256 of the group's ordered global ranks>.pkl` (`_pg_dist_cache_file_path` in `exchange_utils.py`). It holds that group's save/load shard distribution.
- The old name, `pg_dist_<min rank>.pkl`, was readable but collided. For example, DP over ranks `[0,1,2,3]` and EDP over `[0,2]` both mapped to `pg_dist_0.pkl`, so one group could read or overwrite the other's distribution.
- Each rank computes the digest locally from its group's ranks, with no extra collective. Each distinct group gets exactly one file, and the in-process memo uses the same key.
- Lookups always go from a group to its file, so readability only helps when someone inspects the cache directory by hand.

If that helps with debugging, I can add a readable prefix and keep the digest as the unique part, for example `pg_dist_r<min rank>_n<group size>_<digest>.pkl`. I've left the code unchanged for now. Let me know if you'd like the prefix.
