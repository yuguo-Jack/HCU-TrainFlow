### Add regression tests for the new CLI polarity and compatibility behavior

The functional recipe migrations exercise ordinary launches, but do not explicitly assert the new destination/inversion or the precedence of the deprecated flag. The existing [determinism argument tests](https://github.com/NVIDIA/Megatron-LM/blob/f24fc209b539fc6711771f5d5011a5b3f2fe8fb3/tests/unit_tests/training/test_determinism_args.py#L33-L69) call the helper directly, while [the initialization test](https://github.com/NVIDIA/Megatron-LM/blob/f24fc209b539fc6711771f5d5011a5b3f2fe8fb3/tests/unit_tests/tuning/test_autotune_config.py#L128-L141) only checks the legacy positive flag. Neither pins down the new opt-out contract.

Add this focused parser-to-config regression beside the existing [adapter tests](https://github.com/NVIDIA/Megatron-LM/blob/f24fc209b539fc6711771f5d5011a5b3f2fe8fb3/tests/unit_tests/test_argument_utils.py#L84-L99), using their existing imports and capturing config:

```python
@pytest.mark.parametrize(
    "flags, expected",
    [
        ([], True),
        (["--deterministic-mode"], True),
        (["--disable-deterministic-mode"], False),
        (["--deterministic-mode", "--disable-deterministic-mode"], False),
        (["--disable-deterministic-mode", "--deterministic-mode"], False),
    ],
)
def test_cli_determinism_reaches_transformer_config(flags, expected):
    parser = add_megatron_arguments(ArgumentParser())
    args = parser.parse_args(flags)
    args.params_dtype = torch.float32
    config = core_transformer_config_from_args(
        args, config_class=CapturingTransformerConfig
    )
    assert args.disable_deterministic_mode == (not expected)
    assert config.deterministic_mode is expected
```

Required companion checks: parameterize the existing initialization test with the same cases and assert `tuning.install(..., deterministic=expected)`; with minimal valid training arguments and a mocked determinism helper, assert that `validate_args` calls it only when `expected` is true. This preserves default-on CLI behavior, opt-out precedence in either flag order, and the legacy flag warning without making it an opt-in again. Also retain the separate library contract: directly constructing `TransformerConfig(num_layers=1, hidden_size=128, num_attention_heads=4)` must still yield `deterministic_mode=False`. These are proposed checks, not executed results.

### Update the deterministic-training guide for the default change

The affected [user guide](https://github.com/NVIDIA/Megatron-LM/blob/f24fc209b539fc6711771f5d5011a5b3f2fe8fb3/docs/user-guide/deterministic-training.md#L14-L22) still instructs users to opt in with `--deterministic-mode` and never documents the opt-out. After this PR, merely omitting that old flag does not disable determinism—for example, a training launch with `--tp-comm-overlap` still reaches the deterministic guard.

Replace the opening opt-in instructions/example with text such as:

> Deterministic mode is enabled by default for Megatron's argparse CLI. Pass `--disable-deterministic-mode` to opt out. The legacy `--deterministic-mode` flag is deprecated and ignored; it does not override the opt-out. Directly constructed Python configuration dataclasses retain their `deterministic_mode=False` default.

Update the flag-labeled explanations in the configuration table and Triton section to describe the enabled mode rather than imply opt-in. Preserve the documented environment restrictions, incompatible-option checks, and kernel-selection behavior; those still apply when determinism is enabled. Static acceptance: the guide must explicitly distinguish CLI and dataclass defaults, document the opt-out and legacy precedence, and no longer present the deprecated flag as necessary to enable determinism.

        $([ "$DETERMINISM_PERF_MODE" = nondet ] && echo --disable-deterministic-mode) \
