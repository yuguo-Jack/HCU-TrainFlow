# What does this PR do?

MFSDP v2 currently rejects per-token loss normalization. Enable it by summing dense and expert gradients across their respective meshes, then dividing the accumulated gradients by the global valid-token count before clipping and the optimizer update. Ordinary rank-averaged losses retain their existing behavior.

The adapter implements `scale_gradients()` for final token-count normalization. MFSDP v2 uses a `grad_scale` multiplier after mesh averaging: dense-DP and expert-DP mesh sizes for per-token loss, or 1 and 1/EP for ordinary rank-averaged loss. Clipping uses the existing upstream implementation. Initial support covers TP=PP=1, context/expert parallelism, and one optimizer instance.

The functional regression extends the existing DeepSeek proxy recipe with `--calculate-per-token-loss` and `--eod-mask-loss`. Masking end-of-document positions produces unequal valid-token counts across ranks and microbatches. The case runs `pretrain_gpt.py` through the standard functional harness with EP=2 on one GB200 node (four GPUs), four accumulated microbatches, and its own full-precision GB200 golden values. The global batch size stays 512 and the microbatch size stays 32. The case is registered in the GB200 MoE recipe for `mr` and `mr-github`, replacing its H100 registration.
