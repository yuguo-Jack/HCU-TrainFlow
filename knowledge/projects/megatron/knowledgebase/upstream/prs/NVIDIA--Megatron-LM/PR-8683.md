# Join the reduction stream to CUDA-graph capture in MFSDP v2 combined 1F1B

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8683) · state: open · merged: False

## Original PR description

# What does this PR do?
With `overlap_moe_expert_parallel_comm=True`, MFSDP v2's combined 1F1B scheduler bypasses `FsdpModule.pre_backward`. That hook is what makes the gradient-reduction stream wait on the current stream. Without that dependency, capturing a full-iteration CUDA graph fails: the first gradient reduction runs on a stream outside the capture and raises `cudaErrorStreamCaptureIsolation`.

` _module_post_backward_hook` now makes `inner_reduction_stream` wait on the current stream before reducing gradients.

## Test

`test_mcore_moe.py::test_ep_overlap_full_iteration_cuda_graph_matches_default_schedule` builds a 2-layer MoE GPTModel (EP=2, drop-padding alltoall) wrapped in FullyShardedDataParallel v2. It captures a full-iteration CUDA graph with and without `overlap_moe_expert_parallel_comm`, then requires bitwise-equal losses and parameters.
  - Fails on main with cudaErrorStreamCaptureIsolation.
  - Passes with this fix.

[P2] Preserve gradient bindings across graph replays

On iterations three and four, `optimizer.zero_grad()` clears the optimizer-facing `.grad` attributes to `None`. [Graph replay runs GPU work without rerunning the Python schedule](https://github.com/NVIDIA/Megatron-LM/blob/81ad176f478171c4660dc59c01d60de9c78059ec/megatron/core/full_cuda_graph.py#L340-L353), so it doesn't repeat [`_install_sharded_grads`](https://github.com/NVIDIA/Megatron-LM/blob/81ad176f478171c4660dc59c01d60de9c78059ec/megatron/core/distributed/fsdp/src/megatron_fsdp/experimental/parameter_group.py#L723-L726). SGD therefore skips every parameter even though captured kernels still write the persistent gradient buffers. Both schedule variants freeze identically, allowing their final parameter comparisons to pass without checking continued training. [FullyShardedOptimizer already handles this exact contract](https://github.com/NVIDIA/Megatron-LM/blob/81ad176f478171c4660dc59c01d60de9c78059ec/megatron/core/optimizer/fully_sharded_optimizer.py#L372-L388), but this test uses raw SGD.

Replace this line with:
```suggestion
            optimizer.zero_grad(set_to_none=False)
```
This preserves the gradient views installed during warmup and zeros their persistent storage before capture and each replay. Retain the eager warmup, both schedule variants, successful-capture assertion, and bitwise loss/parameter comparisons.

Proposed acceptance checks: assert optimizer-facing gradients are non-None immediately before every `optimizer.step()`, including both replay-only iterations; snapshot local parameter shards and verify at least one nonempty shard changes on each replay-only update. Keep the existing `rtol=0, atol=0` comparisons. Removing the production stream fix should still make the overlap variant fail during capture. These checks are proposed; I haven't executed them.

[P3] Use double quotes in the new reset helper

All four new reset assignments use single-quoted keys, contrary to the protected [style guide's explicit double-quote requirement](https://github.com/NVIDIA/Megatron-LM/blob/01fa4164c8b539958500c2314ad52eacfdd80774/style-guide.md#L6-L10). This is a review-only convention: [Black preserves string quotes](https://github.com/NVIDIA/Megatron-LM/blob/81ad176f478171c4660dc59c01d60de9c78059ec/pyproject.toml#L280-L283), so formatting won't correct it.

Replace the four assignments in this helper with:
```python
    FullCudaGraphWrapper.curr_iteration = {"training": 0, "validation": 0}
    FullCudaGraphWrapper.cuda_graph = {"training": None, "validation": None}
    FullCudaGraphWrapper.result = {"training": None, "validation": None}
    StaticBufferLoader.static_buffers = {"training": [], "validation": []}
```
Preserve both stage keys, their values and the assignment order. Acceptance is static inspection: all eight key literals use double quotes, with reset behavior unchanged.
