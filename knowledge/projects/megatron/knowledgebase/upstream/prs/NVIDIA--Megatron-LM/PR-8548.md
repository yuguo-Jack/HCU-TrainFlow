# Integrate MFSDP v2 Muon with the MCore optimizer factory

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8548) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Enable `optimizer="muon"` with Megatron-FSDP v2: `FsdpMuon` updates the 2-D matrices and Adam updates the rest, each wrapped in a `FullyShardedOptimizer` and combined by a `ChainedOptimizer` with joint DTensor-aware gradient statistics and clipping.

## Implementation

- The emerging-optimizer factory dispatches MFSDP v2 models to `_get_megatron_fsdp_emerging_optimizer`. Every rank builds one Muon and one Adam optimizer, because a per-rank number of chained optimizers deadlocks `ChainedOptimizer.get_grad_norm` under pipeline parallelism.
- `assign_owner_work` plans each mesh independently instead of rejecting mixed meshes, so dense and expert parameters share one `FsdpMuon`.
- `FsdpMuon` no longer refreshes the FSDP model weights. `FullyShardedOptimizer` (or `fully_shard_optimizer(..., precision_aware=True)`) does it once per step.
- `ChainedOptimizer` computes DTensor-aware gradient statistics per member and uses `_uses_decoupled_grad` in `step`, which knows MFSDP v2 reduces into `.grad`.
- Muon is accepted with Megatron-FSDP v2, which requires `--muon-no-split-qkv`.

## Validation

On 4 GB200 (OCI-HSG) with Transformer Engine 2.18.0, at commit `aed891b0f`, there are no failures in:
- the MFSDP v2 unit tests (89 cases per rank), including new Muon/Adam loss and gradient-clipping parity with unsharded training (FP32, BF16), Muon/Adam MoE with EP=2 against an EP=1 reference, and per-mesh owner planning;
- `test_optimizer.py` (74 cases per rank);
- pipeline-parallel layouts with different parameter classes per stage (a throwaway script, not in this PR).

Known: at the default medium Newton-Schulz precision, an earlier revision showed a ~0.12% cross-EP gradient-norm deviation. The MoE test uses `muon_fp32_matmul_prec="highest"`.
