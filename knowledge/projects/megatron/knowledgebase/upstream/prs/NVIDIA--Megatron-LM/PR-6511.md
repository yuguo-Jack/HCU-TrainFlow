## Original PR description

# Internal GDN Backend

## Summary

- Adds an in-tree SM100 CuTe DSL backend for MCore Gated Delta Net.
- Provides fused local GDR forward and backward kernels plus forward and backward CP boundary preprocessing.
- Enables the optimized path from Megatron with `gdn_gdr_backend="internal"`.
- Keeps the high-level API compatible with the MCore-supported FLA GDN call contract.
- Uses FLA fallback only in `MCORE_GDN_INTERNAL_BACKEND=auto` mode for unsupported kernel shapes and layouts.

The supported packed-THD CP optimized path is:

```text
CuTe DSL CP forward preprocessing -> fused GDR forward -> CuTe DSL CP backward preprocessing -> fused GDR backward
```

## How To Use In Megatron

Set the GDN backend to internal:

```yaml
gdn_gdr_backend: internal
```

The runtime dispatch mode is controlled by `MCORE_GDN_INTERNAL_BACKEND`:

| Mode | Behavior |
| --- | --- |
| `auto` | Use CuTe DSL when supported; otherwise fall back to FLA for unsupported shapes/layouts. |
| `cute` | Require the CuTe DSL path; unsupported inputs raise an error. |
| `fla` | Bypass the CuTe DSL path and call FLA. |

Semantic options outside the current internal contract, including `use_beta_sigmoid_in_kernel=True` and `allow_neg_eigval=True`, raise immediately instead of falling back.

For packed THD + CP training, use the normal MCore packed-sequence and CP layout flow.

The internal backend handles:

- Runtime dispatch to CuTe DSL kernels.
- FLA fallback in `auto` mode for unsupported shapes/layouts.
- Forward side-output materialization for training.
- Fused backward orchestration.
- CP forward/backward boundary preprocessing.

## API Layers

Use the highest layer that fits your use case:

- Megatron training: set `gdn_gdr_backend="internal"`.
- MCore/module integration: call `chunk_gated_delta_rule(...)`.
- Kernel benchmarking/debugging: call the standalone forward/backward/CP wrappers.

## MCore GDN Adapter

Import:

```python
from megatron.core.ssm.gated_delta_net.internal_gdn_backend import chunk_gated_delta_rule
```

FLA scope: replaces the MCore GDN module's call to FLA `chunk_gated_delta_rule` for the supported MCore GDN call contract, including local GDR forward/backward and CP preprocessing when supported.

Call:

```python
output, final_state = chunk_gated_delta_rule(
    q,
    k,
    v,
    g,
    beta,
    scale=None,
    cu_seqlens=None,
    cp_context=None,
    recompute_h=False,
)
```

Inputs:

- `q`, `k`, `v`: contiguous BTHD tensors.
- `g`, `beta`: BTH tensors.
- `cu_seqlens`: optional packed-sequence offsets.
- `cp_context`: optional FLA CP context.
- `recompute_h`: recompute saved state instead of storing it for backward.

Returns:

- `output`: GDN output, same logical layout as `q`.
- `final_state`: currently `None` for the optimized training path.

This adapter is the recommended entry point outside normal Megatron config usage. It is not an unconditional drop-in replacement for every FLA option.

## Standalone Forward Kernel

Import:

```python
from megatron.core.ssm.gated_delta_net.internal_gdn_backend.kernels.fused_gdr_fwd_cute import (
    chunk_gated_delta_rule_prefill_cute,
)
```

FLA scope: replaces the forward hot path inside `chunk_gated_delta_rule`, including `chunk_local_cumsum`, intra/WY preparation, `chunk_gated_delta_rule_fwd_h`, and `chunk_fwd_o`.

Call:

```python
output = chunk_gated_delta_rule_prefill_cute(
    q,
    k,
    v,
    g=g,
    beta=beta,
    scale=scale,
    initial_state=initial_state,
    cu_seqlens=cu_seqlens,
    output=output,
    output_A=output_A,
    output_g=output_g,
    output_h=output_h,
    checkpoint_every_n_tokens=64,
    checkpoint_cu_starts=checkpoint_cu_starts,
    assume_valid_cu_seqlens=True,
    gate_is_log_decay=True,
)
```

Inputs:

- `q`, `k`, `v`: THD tensors.
- `g`: raw log-decay when `gate_is_log_decay=True`.
- `beta`: update gate.
- `cu_seqlens`: int32 CUDA offsets.
- `initial_state`: optional `[num_seqs, H, 128, 128]` state.

Optional outputs:

- `output`: preallocated forward output.
- `output_A`: saved WY/A tensor for backward.
- `output_g`: transformed cumulative gate for backward.
- `output_h`: saved chunk state for fused backward.

Notes:

- SM100 + CUDA 13 + CuTe DSL runtime are required.
- Head dimension must be 128.
- Chunk size is 64.
- `output_h` requires `checkpoint_every_n_tokens=64`.
- The standalone wrapper supports a non-empty `initial_state`; the high-level MCore adapter does not dispatch that case to the CuTe optimized path today.

## Standalone Backward Kernel

Import:

```python
from megatron.core.ssm.gated_delta_net.internal_gdn_backend.kernels.fused_gdr_bwd_cute import (
    fused_gdr_bwd,
)
```

FLA scope: replaces the backward hot path inside `chunk_gated_delta_rule`, including optional state recompute, `chunk_bwd_dv_local`, `chunk_gated_delta_rule_bwd_dhu`, `chunk_bwd_dqkwg`, WY-gradient preparation, and reverse gate cumsum.

Call:

```python
dq, dk, dv, dg, dbeta, dh0 = fused_gdr_bwd(
    q,
    k,
    v,
    a,
    g,
    beta,
    do,
    dht,
    h,
    scale=scale,
    cu_seqlens=cu_seqlens,
    chunk_offsets=chunk_offsets,
    chunk_size=64,
    trusted_chunk_offsets=True,
)
```

Strict physical layout:

| Tensor | Shape | Dtype |
| --- | --- | --- |
| `q`, `k`, `v`, `do` | `[1, total_tokens, 64, 128]` | BF16 |
| `a` | `[1, total_tokens, 64, 64]` | BF16 |
| `g`, `beta` | `[1, total_tokens, 64]` | FP32 |
| `h` | `[1, num_chunks, 64, 128, 128]` | BF16 |
| `dht` | `[num_sequences, 64, 128, 128]` | FP32 |
| `cu_seqlens`, `chunk_offsets` | `[num_sequences + 1]` | int32 |

Returns:

- `dq`, `dk`, `dv`, `dg`, `dbeta`, `dh0`.

`trusted_chunk_offsets=True` may only be used when the caller has already validated the associated packed metadata on the host side. This wrapper assumes the caller provides forward side outputs with the exact layout and dtype shown above.

## CP Forward Preprocessing Kernel

Import:

```python
from megatron.core.ssm.gated_delta_net.internal_gdn_backend.kernels.fused_gdr_cp_cute import (
    try_chunk_gated_delta_rule_fwd_h_pre_process_cutedsl,
)
```

FLA scope: replaces `fla.ops.cp.chunk_delta_h.chunk_gated_delta_rule_fwd_h_pre_process`, namely the CP all-gather plus local boundary-state merge before the main forward kernel.

Call:

```python
initial_state = try_chunk_gated_delta_rule_fwd_h_pre_process_cutedsl(
    k=k,
    w=w,
    u=u,
    g=g,
    gk=None,
    bg=None,
    v=None,
    chunk_size=64,
    state_v_first=False,
    cu_seqlens=cu_seqlens,
    context=cp_context,
)
```

Dispatcher outcomes:

- `fused`: launches the CuTe DSL CP communication/merge kernel and returns `initial_state`.
- `noop`: no request crosses the rank boundary, so no CP communication kernel or collective is needed; returns `initial_state`.
- fallback: returns `None`, and the caller should execute the FLA CP preprocessing path.

This kernel replaces the CP all-gather + local merge sequence for supported GDN chain layouts.

## Current Kernel Contract

- Device: SM100.
- CUDA: 13 or newer.
- Runtime: CuTe DSL and CUDA Python bindings installed.
- Main forward: bf16/fp16 inputs, head dim 128, chunk size 64.
- Main backward: bf16 training path, 64 heads, head dim 128, chunk size 64.
- CP preprocessing: scalar-gate GDN path, supported CP chain layouts only.
- Dense SBHD chunkwise CP with `B > 1` is not supported by the production `GatedDeltaNet` optimized path.
- FLA fallback for unsupported shapes/layouts happens only in `MCORE_GDN_INTERNAL_BACKEND=auto` mode.

Temporary alignment restriction:

- The production path still contains `[REMOVE BEFORE MERGE]` alignment workarounds.
- Fused backward supports per-sequence partial chunks.
- CuTe DSL CP preprocessing supports non-64-aligned local boundary windows.
- Fused forward still requires every logical sequence to be positive and 64-token aligned.
- The integrated optimized CP path uses fused forward and therefore remains aligned-only until fused forward tail support is enabled.

## Kernel Performance Snapshot

This section reports kernel-scope timing for the GDN/GDR problem exercised by the packed-THD CP benchmark.

Problem size:

- Layout: packed THD.
- Sequence length: 64k global tokens per logical sequence.
- Context parallelism: CP4.
- Chunkwise CP rows use a 16k-token local window per CP rank.
- GDN shape: 64 heads, head dimension 128.
- GDR chunk size: 64 tokens.

Settings:
- Tested on GB200
- Timing unit: milliseconds.
- Speedup: `fla + chunkwise fwd+bwd time / candidate fwd+bwd time`; values below 1.00x are slower than baseline.

GDR-scope timing:

| Backend | CP mode | GDR fwd (ms) | GDR bwd (ms) | GDR fwd+bwd (ms) | Fwd+bwd speedup |
| --- | --- | ---: | ---: | ---: | ---: |
| fla | chunkwise | 2.3935 | 7.6830 | 10.0765 | n/a |
| ours | chunkwise | 1.8370 | 2.7800 | 4.6170 | 2.18x |

cuDNN + headwise is intentionally omitted from the GDR-scope table because headwise CP communication is outside the GDR NVTX scope, so isolating only the GDR scope would not be a fair comparison with chunkwise CP.

GDN-scope timing:

| Backend | CP mode | GDN fwd (ms) | GDN bwd (ms) | GDN fwd+bwd (ms) | Fwd+bwd speedup |
| --- | --- | ---: | ---: | ---: | ---: |
| fla | chunkwise | 6.9840 | 15.2305 | 22.2145 | n/a |
| ours | chunkwise | 6.9215 | 10.6620 | 17.5835 | 1.26x |
| cudnn | headwise | 8.6505 | 21.6905 | 30.3410 | 0.73x |
