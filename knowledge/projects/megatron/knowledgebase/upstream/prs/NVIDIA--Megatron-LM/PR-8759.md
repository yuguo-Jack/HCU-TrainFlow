# Build datasets on the run's groups and warn on data-path fallbacks

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8759) · state: closed · merged: False

## Original PR description

Depends on #8757 and #8754. Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/b5063d8a78...yx/pstate-f1c-data-providers).
- #8757 carries #8742, which puts `get_batch` and the data loaders on the run's groups. Its `_get_data_parallel_group` serves the full-validation reduction.
- #8754 takes the MTP virtual-pipeline size from the model config, also in the `is_dataset_built_on_rank` that this PR changes. It brings #6303, #8017, #8028, #8033, #8057 and #8726.
- The merge of #8757 keeps the `default_layer_spec` signature that takes `pp_rank` and `pg_collection`, and regenerates the process-group allowlist.

Land this together with #8760. This PR makes `is_first_or_last_pipeline_stage()` warn without a `pp_group`, and Flextron's `get_batch` calls it that way until #8760. #8760's dataset provider gets the run's collection only after this PR. #8761's example providers also get it from this PR.

**Why.** `pretrain()` builds the data loaders on the run's collection. The dataset providers of `pretrain_gpt.py`, `pretrain_hybrid.py` and `pretrain_vlm.py` still chose the ranks that build datasets from the global grid: the TP rank, the pipeline stage and the MTP pipeline group. A run whose collection differs from the global grid built datasets on ranks that do not read them, and skipped ranks that do. The data path's remaining `None` fallbacks also read the global grid with no notice.

**What.**
- `build_train_valid_test_datasets` takes `pg_collection` and passes it to a provider whose signature has a `pg_collection` parameter. This is the check training already does for `vp_stage`, and it works through the `vp_stage` partial. Other providers, including ones that only take `**kwargs`, are called with the sizes alone. `build_train_valid_test_data_loaders` forwards its collection.
- The GPT, hybrid and VLM providers take `pg_collection`. `is_dataset_built_on_rank` reads three things from it:
  - the TP rank;
  - the first and last stage, with the config's virtual-pipeline size, as `get_batch` does;
  - the MTP placement.

  A collection without `tp` or `pp` raises `ValueError`. On main, the GPT and hybrid rule lives in `megatron/training/datasets/providers.py`, so the change is in `is_dataset_built_on_rank` and `is_dataset_built_on_rank_explicit` there. The two providers bind `pg_collection` into the predicate they pass to `build_gpt_datasets`.
- These fallbacks now emit `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23) and keep their global reads:
  - `get_batch` in the three scripts;
  - the VLM model provider;
  - `is_dataset_built_on_rank`;
  - `build_pretraining_data_loader`. An external-type loader reads no groups and does not warn;
  - `is_first_or_last_pipeline_stage` without `pp_group`.
- The loader and iterator builders' docstrings mark an omitted collection as deprecated. Their fallbacks already warn through #8757.

**Tests.**
- New `tests/unit_tests/data/test_dataset_provider_process_groups.py`:
  - forwarding to a plain provider, a `vp_stage` partial and a `**kwargs` provider;
  - the GPT, hybrid and VLM rank checks on groups unlike the global grid, with every global accessor patched to fail;
  - main's rule that a sequence-packing scheduler builds on every pipeline stage, through the shared GPT and hybrid predicate;
  - each fallback's warning, including the full-validation group through `_get_data_parallel_group`;
  - on 4 GPUs: the loaders on a strided TP group, and the rank check matching the global grid with and without groups, at TP2×PP2 with and without a virtual pipeline.
- `test_get_batch.py`: the packed-sequence rank test passes the collection. It needs 8 GPUs.
- `test_dataset_providers.py`: main's test of the shared provider body expects the `pg_collection` parameter and the predicate bound to it.

On 4 GPUs against its base:
- `test_dataset_provider_process_groups.py` is new, and its 79 tests pass.
- `test_get_batch.py`: 170 passed and 205 skipped here and on the base. The skipped tests include the packed-sequence rank test, which needs 8 GPUs.
- `test_dataset_providers.py`: 103 passed here and on the base.
- `test_data_path_process_groups.py`, `test_training.py` and `test_training_pg_collection.py`: 44, 34 and 12 passed, the same as on the base.

No test fails on either side. In the integration run (all #6307 PRs merged onto main 77391e71cc), this PR's test files show no regressions against main. End-to-end training smokes on the same merge match main's losses bit for bit on 22 configurations on 4 GPUs, including GPT, hybrid and LLaVA, and record no process-group fallback warning.

Before the sync, the branch ran `test_dataset_provider_process_groups.py` and `test_get_batch.py` on 4 CPU ranks with Gloo: 120 passed, the same per test as with all the other process-group changes from #6307 applied, and 75 of them were new. The 3 failures needed CUDA. On an earlier version of these commits, a 4-process Gloo check compared `is_dataset_built_on_rank` with the collection, without groups, and on the base. It covered six TP, PP and virtual-pipeline layouts, with and without packing, MTP and the scheduler, and all three agreed on every rank.

**Compatibility.**
- New arguments default to the old behavior, which now warns. On the standard grid the same ranks build datasets and read batches.
- Stock GPT, hybrid and VLM training pass their groups everywhere, so their data path does not warn, also under `--strict-process-group-fallbacks`.
- `is_dataset_built_on_rank` without groups builds them through `use_mpu_process_groups(["tp", "pp"])`. It no longer honors the `_MPU_TENSOR_MODEL_PARALLEL_RANK` override, which only `tools/checkpoint` sets. On an initialized `torch.distributed` without a model-parallel grid it raises a `ValueError` that asks for `pg_collection.tp`, where main raised an `AssertionError` about the uninitialized TP group.
- `build_train_valid_test_datasets` now always inspects the provider's signature. A provider that `inspect.signature` cannot read would raise where main worked. No in-repo provider is affected.
- Needs `determinism-exempt`: `utils/common_utils.py`, a registered kernel file, gains a warning. Numerics are unchanged.

The branch was synced with main 77391e71cc on 2026-11-01 by a merge commit that lists each conflict and its resolution, so existing commits and review links stay valid.
