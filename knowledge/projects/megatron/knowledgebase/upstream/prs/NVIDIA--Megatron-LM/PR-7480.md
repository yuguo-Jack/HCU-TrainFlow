# What does this PR do?

Fixes two precision-boundary problems exposed when a language model uses FP32 residual accumulation:

1. Makes mixed-dtype tensor-parallel output logits safe for cross entropy's in-place workspace reuse.
2. Keeps MIMO modality towers and bridge communication in parameter dtype, promoting activations only when they enter the FP32 language embedding stream.

## FP32 output logits

Previously, the Transformer Engine GEMM returned a two-dimensional custom-autograd output that `_linear_forward` reshaped into the final logit tensor. The reshaped result was a view, which could not safely be modified in place by cross entropy.

The new path allocates the final-shaped output first, gives TE a two-dimensional view through its `out` argument, and returns the owning tensor. This does not introduce a clone.

## MIMO precision flow

`fp32_residual_connection` promotes the language pipeline dtype to FP32. Modality configs copied from that language config must not inherit this language-only policy: the pretrained modality tower and projector remain in parameter dtype.

`MultiModulePipelineCommunicator` (in `megatron/core/pipeline_parallel/multimodule_communicator.py`) now accepts an optional `bridge_comm_dtypes` mapping keyed by source module. The Nemotron MIMO provider configures the RADIO encoder bridge with:

```python
bridge_comm_dtypes={
    RADIO_ENCODER_MODULE_NAME: language_config.params_dtype,
}
```

(See `examples/mimo/model_providers/nemotron_moe_vlm.py`.)

With all of this, now the precision flow looks like:

```text
Forward

Modality tower/projector
         BF16
           |
           | BF16 bridge
           | sender dtype validated
           v
MIMO embedding merge
     BF16 -> FP32
           |
           v
Language embedding/residual stream
         FP32
```

```text
Backward

FP32 merge gradient
         |
         | autograd through the local cast
         v
BF16 bridge gradient
         |
         v
BF16 modality source
```

This avoids widening modality communication to FP32 while preserving the FP32 language residual stream.

## Summary of what's implemented in this PR

- Preallocate the final-shaped tensor-parallel linear output and return its owning tensor.
- Add optional per-source `bridge_comm_dtypes` to `MultiModulePipelineCommunicator`.
- Validate all bridge send paths against the receive dtype before entering NCCL. (See `megatron/core/pipeline_parallel/bridge_communicator.py`.)
- Cast modality embeddings to the destination language embedding dtype at the local MIMO merge.
- Keep copied RADIO tower/projector configs in parameter dtype.
- Propagate `--logit-dtype` into the Nemotron MoE VLM language model spec.
- Configure the RADIO bridge from the source parameter dtype.
