# What does this PR do?
Sums GatedDeltaNet's `out_norm` gradients across TP ranks when sequence parallelism is off (finding 11 of #7452).

**Bug.** `out_norm` applies one weight (plus a bias, for LayerNorm) to every value head, but TP splits the heads across ranks, so each rank's gradient for these parameters is a partial sum over its local heads. `_allreduce_non_tensor_model_parallel_grads` only summed them across TP ranks when sequence parallelism was on (via the `sequence_parallel` attribute TENorm sets). With TP>1 and SP off, each rank stepped its replica with a different partial gradient and the replicas silently diverged.

**Fix.**
- `_GDNBase` tags every `out_norm` parameter with `sum_gradients_across_tp_domain=True`. This covers GDN and GDN2, and both RMSNorm and LayerNorm.
- `_allreduce_non_tensor_model_parallel_grads` adds tagged parameters to the existing SUM bucket. The check joins the existing `elif`, so a parameter that is also SP-tagged is still reduced exactly once.

**Tests.**
- `TestSumGradientsAcrossTPDomain` (`test_finalize_model_grads.py`): TP=2 with rank-dependent gradients, so "left alone", "averaged", "summed once" and "summed twice" all give different values. Asserts tagged grads are summed exactly once with SP off and with SP on (parameter carries both tags), and untagged grads are left alone.
- `TestGatedDeltaNet::test_out_norm_params_marked_for_tp_grad_sum`: every `out_norm` parameter carries the tag, for RMSNorm (the fixture) and LayerNorm (asserting the bias exists).
- Both fail on the base commit and pass with the fix. Run locally on 2 GPUs (NGC PyTorch 26.05): 2/2 and 8/8 (all variants with TP×CP ≤ 2; the TP=2, CP=2 variants need 4 GPUs).

**Reproduction** (`11_gdn_out_norm_missing_tp_sum.py` from #7452, 2 Gloo ranks):
- Base `6a3660905a2736b5670baed1ca5954372937918b`: `REPRODUCED`. Per-rank gradients after the finalizer are `[0.3703, 0.9794]` and `[2.4909, 3.8243]`; the reference is their sum, `[2.8613, 4.8037]`. Next-step output error 0.676 (SP off) vs 2.4e-7 (SP on control).
- With this PR: both ranks hold the reference gradient after the finalizer. The script's assertion that the finalizer leaves the gradient unchanged now fails, as expected.

**Note:** #7453 moves the GDN files into `megatron/core/ops`. This PR edits `_GDNBase.__init__` in `common.py`, so whichever lands second needs a small rebase.

- 12kimih · comment · 2026-10-18T21:55:38Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7613#issuecomment-6255627070)

Independent confirmation, from an equivalent change I had opened as #8319 (closed now as a duplicate of this PR):

- Real model: Qwen3.5-4B-Base, first 8 layers, one packed batch of 8k text tokens, bf16. Without this change, TP=2 with SP off gives a GDN `out_norm` weight gradient with relative L2 error 0.72 against a float64 reference (cosine 0.695), and TP=4 gives 0.81. The bf16 noise floor is 4.5e-3. TP=1 is at 3.7e-3. With the `out_norm` gradients summed across TP after `finalize_model_grads` (which is what this PR does), TP=2 and TP=4 are back within the floor and match TP=1. After 3 Adam steps the replicated copies had already drifted apart on the TP ranks without the fix.
- Unit level, on 8x B200 (torch 2.14.1, TE 2.18.0, FLA 0.5.1): one GDN/GDN2 layer, megatron-core DDP, forward/backward, then `finalize_model_grads`. On main, the finalized `out_norm` `main_grad` differs between TP ranks for TP 2/4 with SP off (it passes with SP on). With the same marker-and-sum change, it is bitwise identical across TP ranks and equals the sum of the per-rank partial gradients, for both variants, TP 2/4 and SP off/on.

Downstream, the Qwen3.5-VL recipes in Megatron-Bridge use TP>1 with SP off and rely on this fix (NVIDIA-NeMo/Megatron-Bridge#6533; the recipe-side workaround NVIDIA-NeMo/Megatron-Bridge#6541 was closed in favour of this PR).
