# [MFSDP] Fuse local gradient scaling and accumulation

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8393) · state: open · merged: False

## Original PR description

## What does this PR do?

For later microbatches, local gradient accumulation can cast, scale, and add each gradient in separate operations. Fuse those operations into `destination.add_(grad, alpha=scale)` when the scale is a positive power of two and the gradient converts losslessly to the accumulation dtype.

The eligibility check uses `main_grad.dtype`, following #8949's local-accumulation semantics. `grad_comm_dtype` does not control this path. Other scales and lossy conversions retain the separate conversion, scaling, and addition; the first contribution keeps its existing copy-and-scale path.

Power-of-two scaling avoids intermediate rounding away from underflow/overflow boundaries. This is not a bitwise-equivalence guarantee at those boundaries. At scale 1, #8949 already uses a direct add.

## Dependencies and scope

**Stacked on #8949**, with GitHub base `pull-request/8949`. The diff contains only the fusion and its gradient-accumulation tests. It does not depend on #8828's model-weight optimization.

Retarget this PR to `main` before merging #8949; then rebase it onto the merged #8949 commit before merging this PR into `main`.

## Validation

Agent-run validation of this rebased branch in the development CI Docker image on two RTX A6000 GPUs:

- Expanded training-parity test: **18 passed per rank**, covering `grad_scale` values 1, 1/2, and 1/3 across replicated DP, singleton-inner HSDP/HFSDP, and both `zero_grad` modes. FSDP applies `grad_scale`; the reference scales its backward loss while recorded losses remain unchanged.
- Before this parametrization, the gradient accumulation and CUDA-graph tests passed **23 tests per rank**, with three MXFP8 cases skipped and one symmetric-memory case excluded.
- The numerical test checks BF16 gradients accumulated in FP32 against separate FP32 scaling/addition, bit for bit, for scales 1, 1/2, 1/64, 4, and 1/3, with both default and BF16 communication dtype settings. The 1/3 case exercises the fallback.
- Black, isort, Pylint, and Ruff passed against the #8949 base; optional mypy was unavailable.

No new performance measurement was made for this revision. Earlier GB200 validation and throughput reports predate this rebase.

- wujingyue · comment · 2026-11-02T05:57:12Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8393#issuecomment-6570212309)

My coding agent reproduced two correctness regressions on two Ampere GPUs, comparing this head (`19a6269`) with its parent (`bfab98f`), using `fully_shard`:

1. **The local-path condition can skip a required reduction.** With `parameter=[Replicate()]`, `gradient=[Replicate()]`, and `optimizer=[Replicate()]` on two ranks, `main_grad.holds_full_tensors` is true. The new path skips inner reduction, and outer reduction also returns immediately because its input and output are the same buffer. Rank-local gradients of 1 and 2 therefore remain 1 and 2; the parent correctly averages them to 1.5 on both ranks. The condition should account for the source-to-destination placement transition and mesh sizes.

2. **Scaling the first contribution loses precision with FP32 main gradients.** For HSDP with `(outer=2, inner=1)`, BF16 compute gradients, FP32 main gradients, default communication dtype, and `grad_scale=1/3`, `torch.mul(grad, scale, out=fp32_buffer)` rounds in BF16 before writing FP32. The resulting gradient is `0.5009765625`; the parent produces `0.5` because it converts to FP32 before scaling.

The agent verified both cases with one and two accumulated microbatches. Could we add focused regression tests for these cases? The current diff has no test changes, although the description says coverage was added.

- wujingyue · comment · 2026-11-02T05:58:49Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8393#issuecomment-6570234174)

My coding agent is also trying an alternative locally:

- Handle singleton-axis transitions in `DBuffer`: skip collectives and return a storage-sharing view when no output buffer is supplied; honor an explicit output buffer.
- Keep one explicit `accumulate_local_gradients()` path in `ParameterGroup`, separate from packing and reducing. Select it from the transition from unreduced `Partial("avg")` gradients to the accumulation placements, together with mesh sizes. A replicated destination on a multi-rank axis still requires reduction.
- Preserve the existing compute/reduction stream dependencies and last-microbatch outer reduction.

This would remove the `None` protocol spanning allocation, copying, and reduction. Buffer-level no-ops alone would still leave gradient packing on every backward, so the separate local-accumulation path is needed to eliminate that intermediate buffer.

The prototype is local and uncommitted; validation is still in progress.
