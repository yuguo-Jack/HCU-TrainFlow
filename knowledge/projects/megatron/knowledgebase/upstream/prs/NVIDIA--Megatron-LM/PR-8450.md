# What does this PR do?
### Description

This PR fixes several numerical semantics in the multi-head HyperConnection (mHC) module to align with the reference implementation of DeepSeek-V4 (Ref: [DeepSeek-V4-Flash-0731/inference](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731/tree/main/inference)), while keeping the existing BF16 storage/compute strategy for activations.

**Changes:**
1. **Residual mixing orientation**: Removed the manual `comb.transpose(-1, -2)` since the fused kernel already applies `comb.T` internally.
2. **RMS normalization formula**: Fixed from `1 / (norm / sqrt(n) + eps)` to `torch.rsqrt(mean(square) + eps)`, adjusting the epsilon placement.
3. **Sinkhorn pre-epsilon**: Added `eps` to the `pre` output in `split_sinkhorn` to match the reference.
4. **Unit Tests**: Updated related unit tests with independent references and gradient checks.

### Why this is needed

Before this fix, the mismatch in the residual mixing orientation (`transpose`) and epsilon placements led to significant performance degradation and training instability, especially when loading official checkpoints or running RL/SFT tasks.

**1. RL Training Improvements**
In our RL rollout vs. training evaluation, the Log PPL difference dropped dramatically after the fix. As shown below, the bug caused a severe mismatch (~0.10 diff), whereas the aligned implementation maintains near-zero difference (~0.0004 diff).

**2. SFT Training & Evaluation Mismatch**
During SFT training, the buggy implementation forced the model to compensate for the incorrect routing, resulting in an initially bloated loss (2.29 vs 1.29) and a massive gap in evaluation Log PPL when deployed on a correct vLLM instance. After the fix, the training loss and the vLLM evaluation Log PPL align perfectly from the start.
