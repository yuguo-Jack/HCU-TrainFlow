# fix(moe): reduce peak memory during paged-stash warmup

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8507) · state: closed · merged: True

## Original PR description

## Summary

<img width="712" height="360" alt="image" src="https://github.com/user-attachments/assets/047555e2-c24d-428d-9d89-ccb5a1c37913" />


Reduce warmup peak memory by releasing unused eager allocator cache **before the initial paged-stash allocation**.

The first iteration records activation sizes using temporary tensors. Their unused allocator cache can remain reserved when the next iteration allocates persistent stash buffers, inflating device-memory usage.

This fix synchronizes and releases that cache once at the transition. It skips cleanup during CUDA-graph capture and leaves subsequent iterations, stash capacity, and numerical operations unchanged.

This complements #8503, which removes retained gradient buffers but does not reduce this warmup peak.

## Results


<img width="461" height="408" alt="image" src="https://github.com/user-attachments/assets/4adbfa72-5452-4118-95ed-8a30ada5e6ff" />


DSV3 30-layer proxy + MTP1 on 256 GB300 GPUs: MXFP8, GTP64/EGTP4/EP64, 4K sequence length, MBS2/GBS512, full-iteration CUDA graphs.

| Metric | Before | After |
|---|---:|---:|
| Maximum sampled device memory (GiB) | 183.72 | 165.97 |
| Tokens/s/GPU | 8,460.54 | 8,458.75 |

**17.75 GiB lower memory (−9.7%), with effectively unchanged throughput**

Both runs completed 60 updates without CUDA or allocator profiling. Memory was sampled every 100 ms across all 256 GPUs; throughput averages updates 21–60 after dropping the three slowest.

## Validation

- Three regression tests pass per rank on four GPUs, covering cleanup ordering, capture safety, and reserved-memory reduction without modifying live tensors.
- Unpatched main fails the cleanup-order and memory-regression tests.
- Four-GPU reference, repeated-reference, and candidate runs produce bitwise-identical final FP32 optimizer parameters after 22 updates.
