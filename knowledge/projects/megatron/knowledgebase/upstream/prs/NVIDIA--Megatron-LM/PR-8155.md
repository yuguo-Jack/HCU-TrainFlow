## Original PR description

# feat(transformer): normalize MTP loss per packed loss group

## What this PR does

`process_mtp_loss` normalizes the MTP loss by token counts over the whole
packed sequence. When a caller combines several forwards into one (for
example several shared-prefix groups), each original forward had its own
counts. The new `loss_group_lengths` argument restores them.

## Changes

- `process_mtp_loss(..., loss_group_lengths=None)`: CP-local lengths that
  partition the packed sequence into independent loss groups. Each group's
  MTP gradient then equals the gradient of a separate call for that group,
  including the original/rolled token-count correction.
- Precondition: each group must consist of whole packed sequences. Its
  CP-local boundaries must be the physical sequence boundaries
  (`cu_seqlens_q_padded`, or `cu_seqlens_q` when unpadded) divided by the CP
  size. The docstring states this; the code does not check it.
- At CP>1 the argument requires the zigzag CP layout and is rejected with the
  contiguous one. With the contiguous layout, a rank's share of a group depends
  on the rest of the pack, so the per-rank counts would differ from a separate
  call.
- The argument requires `calculate_per_token_loss=True`. Lengths that do not
  partition the CP-local sequence are rejected.
- Without the argument the loss is unchanged.

## Tests

```bash
python -m pytest tests/unit_tests/transformer/test_multi_token_prediction_loss_groups.py
```

`tests/unit_tests/transformer/test_multi_token_prediction_loss_groups.py`
runs on CPU or GPU:

- one grouped call against one call per group, with and without an MTP input
  mask, to 1e-12 in FP64;
- the per-token weights against their analytic values, on a pack built so that
  every group's correction differs;
- the rejection of the contiguous CP layout.

Result on one GB200 node (torch 2.11, Transformer Engine 2.15, mamba-ssm 2.3.2.post1, causal-conv1d 1.6.2.post1, flash-attn 2.8.1): 4 passed. This branch alone on top of main also ran the surrounding regression suites (routers, attention, MTP, Mamba, training, RL) on one and four GPUs. Every failure in those runs also occurs on main in the same container: tests that need more ranks than the run had, and missing APEX extensions.
