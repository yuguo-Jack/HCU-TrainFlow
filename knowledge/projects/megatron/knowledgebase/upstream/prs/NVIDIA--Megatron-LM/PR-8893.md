# Use the owner's process groups for FP8 amax, CUDA graphs and 1F1B loss

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8893) · state: open · merged: False

## Original PR description

This PR makes FP8/FP4 amax reductions, CUDA graph reuse, TE fused MLPs, context-parallel attention and the combined 1F1B loss step use the process groups of the model that owns them instead of the global `parallel_state` grid. On the standard grid the groups are the same objects, so results do not change. A model built on its own `ProcessGroupCollection` now reduces, reuses graphs and computes the loss on its own ranks. It consolidates five draft PRs from #6307 without changes. Each member is one commit, followed by one commit that regenerates `tools/process_group_usage_allowlist.json`, so please review commit by commit. The unit has no code dependency on other units or open PRs. It lands after the earlier PRs and units in the chain, including #6293, #6303 and the core process-group API, training I/O and attention and layer units. They edit some of the same files, such as `process_groups_config.py`, `transformer_engine.py`, `training.py` and the T5 model tests.

## Members

- #8028: Pass the CP size and last stage to the combined 1F1B loss step. The EP-overlap schedules pass the collection's CP size and the pipeline group's last-stage flag to `forward_step_calc_loss`, which now requires both and no longer reads the global grid.
- #8032: Decide CUDA graph reuse from the graphed module's pipeline group. `CudaGraphManager` resolves the PP group on first call from its own argument, then the module's collection, then the global grid, and `train()` passes the model's collection to `TECudaGraphHelper`.
- #8034: Take the FP8/FP4 amax reduction group from a process-group collection. Adds `amax_reduction_group(pg_collection, tp_only_amax_red)` and an optional keyword-only `pg_collection` on `get_fp8_context`, `get_fp4_context` and the per-module TE autocast; callers that pass no collection are unchanged.
- #8035: Pass the owner's collection to FP8/FP4 quantization contexts. It builds on #8034. Transformer blocks and layers, MTP, recompute, HybridStack, CUDA graph runners, the multimodal projector and the TE wrappers pass their collection, so amaxes reduce over the owner's TP×DP×CP ranks.
- #8038: Use the MLP's TP group in TE fused MLPs and require a CP group for CP attention. `TEFusedMLP` and `TEFusedMLPWithGroupedLinear` use the MLP's `tp_group` (5 global reads removed), and `TEDotProductAttention` rejects context parallelism without a CP group.

## Behavior changes for callers

- `forward_step_calc_loss` and the combined-1F1B helpers require `cp_group_size` and `is_last_stage` (#8028).
- `CudaGraphManager.reuse_cudagraphs` is `None` until the first call (#8032).
- Under FP8/FP4, a caller-built collection without `tp_dp_cp`, or without `tp_cp` when `tp_only_amax_red` is set, raises `ValueError` (#8034, #8035).
- `TEDotProductAttention` with `context_parallel_size > 1` and no CP group raises `ValueError` instead of running without context parallelism (#8038).

The members touch registered kernel files but only select process groups, so this PR needs the `determinism-exempt` label.
