# Expose rank and tensor ranges in GlobalLayout

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7963) · state: closed · merged: True

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

Expose `GlobalLayout.get_rank_range(mesh, placements, rank)` for querying any global process rank, with `get_local_range` delegating to it. Add `get_tensor_range` for full tensor bounds and a separate `intersect_ranges` helper, which `DBuffer` uses to derive its local tensor views. Rank queries preserve the existing equal and uneven segment layouts. `get_local_range` now rejects ranks outside the mesh for all placements, including replicated layouts.

All range APIs use an immutable `Range(start, numel)` with a computed `end` property. `Range` and `intersect_ranges` live in `range.py`. Layout validation uses the same type, replacing the local `TensorRange` class while retaining tensor IDs in overlap diagnostics. The single added test covers `get_tensor_range`. It lives in `test_layout.py` alongside seven existing layout tests moved from `test_dbuffer.py`. The padding/alignment tests call the layout builder directly, and existing range assertions use `Range`.

Related to #5533.

Validation:
- The reorganized layout tests and a DBuffer construction check passed across four CPU/Gloo ranks: 16 passed per rank. Earlier local owner-compute compatibility checks also passed.
- `tools/autoformat.sh` completed; Black, isort, pylint, and Ruff passed. Its nonblocking mypy step reported missing dependencies in the isolated lint environment and existing iterable typing errors.
- Earlier broader DBuffer checks passed except for the existing uneven TensorAtomic all-gather test, which fails on Gloo both before and after the range refactor. CUDA/NCCL validation was unavailable locally.
