# What does this PR do?

Add deployment-aligned DeepSeek-V4.1 training to experimental lite, pairing quantized forward execution with [vLLM #62365](https://github.com/vllm-project/vllm/pull/62365) at `da8922bf0ff1e07e252f9e73fc7741ce6ae37208`. No changes to `megatron/core` are included.

The `impl="vllm"` model reuses native-lite release loading/export, frozen host FP8 Engram, parallel groups, recomputation, Adam DistributedOptimizer and training checkpoints. Deployment operators supply fused quantized expert forward, grouped expert gradients, packed-document indexer operations and paged FlashMLA attention. Inverse RoPE precedes FP8 `wo_a`. Expert-weight packing and all-query indexer scoring use bounded workspace; all query positions retain the full KV context. vLLM imports are deferred to the deployment implementation.

`attention_core="flashmla"` and `head_dtype="float32"` are defaults. `head_dtype="bfloat16"` rounds logits before FP32 log-softmax. The optional `"mega"` attention core has separate forward/operator validation, with the limitations below. The rollout must use the matching attention and head settings.

## Usage and reproducibility

Use the public vLLM revision above with its matching DeepGEMM/FlashMLA dependencies and release-native safetensors, configuration and tokenizer. The validated deployment kernels target SM100. In a distributed training script:

```python
import torch
from megatron.lite.runtime import create_runtime
from megatron.lite.runtime.backends.mlite.config import MegatronLiteConfig
from megatron.lite.runtime.contracts import ParallelConfig, RuntimeConfig

torch.use_deterministic_algorithms(True, warn_only=True)
backend = MegatronLiteConfig(
    model_name="deepseek_v41", impl="vllm", hf_path="<release-directory>",
    parallel=ParallelConfig(ep=8, cp=1, pp=1),
    impl_cfg={"optimizer": "adam", "deterministic_mode": True,
              "attention_core": "flashmla", "head_dtype": "float32"},
)
handle = create_runtime(
    RuntimeConfig(backend="mlite", backend_cfg=backend)
).build_model()
```

Set `CUBLAS_WORKSPACE_CONFIG=:4096:8` before CUDA initialization and launch with `torchrun`. Reproducible forward comparisons require all three settings: this environment variable, the PyTorch flag and `impl_cfg.deterministic_mode=True`. Default atomic accumulation can be amplified by discrete routing/top-k choices. Forward reproducibility does not imply bitwise-identical gradients.

## Known limitations

- Current-head CPU/4L/40L comparisons above are separate from the earlier RL results. No full 40L/384-expert training or convergence claim is made.
- Mega attention has reference-aligned 4L forward/CP2 and operator-gradient checks, but no teacher-forced training-path, RL or PP integration validation.
- Native-lite ratio-2 CP attention uses differing KV index orders; its bitwise CP comparison remains report-only. Whole-model CP bit equality is not a universal claim.
- `attention_deterministic_backward=True` preserves the default dispatch. Long-context recipes may explicitly set it to `False` for atomic cuDNN dKV: forward criteria are unchanged, but dKV backward is nondeterministic.
- Pipeline/source reuse, arbitrary dtype/export overrides and recovery after failed layerwise reload need broader integration coverage. Core streaming-checkpoint patches are excluded.
