# Fix ShortcutMoEBlock registration order for MFSDP prefetch

# What does this PR do?

Fix `ShortcutMoEBlock`'s module registration order so MFSDP v2 can prefetch its norm and expert units in execution order.

With the norms sharded separately, the registered units and their actual forward calls currently disagree:

```text
Registered: MoE norm -> routed experts -> shortcut norm -> post norm
Executed:   shortcut norm -> routed experts -> MoE norm -> post norm
```

MFSDP builds its static prefetch schedule from this hierarchy. In backward, the mismatch can gather a unit again after it has finished and resharded. That unused full-weight copy survives the optimizer update, so the next forward reads stale weights and the loss curve diverges.

Register the shortcut norm before the paired attention/MoE layers, and re-register the MoE layer's pre-MLP norm after its MLP subtree. On the shortcut path, that norm feeds the shared experts; routed experts run earlier using the shortcut norm. Parameter names, ownership, and forward computations are preserved.

The regression uses a real `HybridModel` with EP=2 and keeps prefetch enabled. It compares five Adam steps against an EP=1 full-batch reference and checks that backward leaves no unused gathered weights. Cases cover ordinary MoE, shortcut blocks, separately sharded norms, A2A overlap, and selective norm recomputation. This PR is stacked on #7952. Explicit FSDP boundaries isolate registration-order coverage; #7781 follows with automatic shortcut wrapping.

This aligns the norm/expert boundaries used by this workload. It does not establish that arbitrary finer-grained wrapping follows module-tree order.
