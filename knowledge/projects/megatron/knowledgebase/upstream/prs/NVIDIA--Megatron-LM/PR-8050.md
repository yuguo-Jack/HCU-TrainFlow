# Avoid a second optimizer-state copy when loading into allocated DistributedOptimizer state

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8050) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

`DistributedOptimizer.load_state_dict` no longer passes the inner optimizer's already allocated, already loaded state back through `self.optimizer.load_state_dict`. That call copies the state onto itself (torch casts it, then TE `FusedAdam` reallocates it in FP32 while the old tensors are still referenced), which roughly doubles optimizer memory during checkpoint load and can OOM large models. In that branch only the param-group hyperparameters are loaded now.

## Issue tracking

Linked issue: Fixes #8046

## Details

When the inner state is already allocated, `load_state_dict` uses `state_dict_state = inner_state_dict["state"]`, which is the optimizer's own state. `dist_checkpointing.load` has already filled it in place, and `load_parameter_state_from_*` copies into it afterwards anyway. Re-loading it only creates copies.

The change:
- Records whether the existing state was reused.
- In that case, with Apex/TE optimizers and not `HybridDeviceOptimizer`, loads the param groups through a new `_load_inner_optimizer_param_groups`. It applies the same group-count and group-size validation as `torch.optim.Optimizer.load_state_dict` and keeps the state tensors as they are.
- Leaves unchanged the first, allocating call, `HybridDeviceOptimizer`, the non-Apex/TE path (which adds `step` to the state) and Megatron-FSDP.

## Testing

- New `TestDistributedOptimizer::test_load_state_dict_keeps_allocated_optimizer_state[dp_reshardable|fully_reshardable]`. It loads a checkpoint into allocated state and asserts:
  - the state tensors are not reallocated (same `data_ptr()`)
  - the param-group `lr` comes from the checkpoint
  - the loaded state equals the source (`get_param_state_dp_zero`)
- On 8 GPUs: the new test fails on `main` (state reallocated) and passes with this change. `test_nonreshardable_optimizer_save_load` (5 cases) passes on both.
- With an equivalent patch on a recent Megatron-LM dev branch, restoring optimizer state for a large MoE model (expert data-parallel size 1, precision-aware optimizer) went from CUDA OOM to loading and training normally. On a smaller dense model the extra load-time peak went from several GiB to 0, and the optimizer state, master weights and gradients after restore are bit-identical.
