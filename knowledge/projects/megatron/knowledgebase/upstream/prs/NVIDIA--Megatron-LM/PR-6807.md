# What does this PR do?

A checkpoint resume needs to restore the training progress that was saved. With `restore_training_state=True`, this change loads the Bridge-compatible `train_state.pt` sidecar into the active Megatron-LM `TrainState`, including iteration, consumed and skipped samples, validation samples, accumulated FLOPs, and train/valid/test flags. Inference loading does not adopt training progress.

For example, if the sidecar records iteration 321 while the legacy checkpoint records iteration 123, resume uses 321. Without a sidecar, it reconstructs the active state from the legacy checkpoint fields. The restored values are also copied to `args` while the training-loop migration continues. Legacy distributed-optimizer loading uses the original checkpoint directory without overwriting the restored training iteration.

The save path uses the sidecar writer already on `main`. It snapshots progress before async finalization, and the iteration sidecar and `latest_train_state.pt` tracker receive the same values. Rank zero decides whether the sidecar exists and broadcasts the state or the legacy-fallback decision, so ranks enter the same collective path. FLOP counts retain the upstream `float64` representation, including values above the `int64` limit.
