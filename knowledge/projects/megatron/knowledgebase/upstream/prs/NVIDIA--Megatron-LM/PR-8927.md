# Add an option to empty the CUDA cache before and after `evaluate`

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8927) · state: open · merged: False

## Original PR description

## Summary

Adds `--eval-empty-cuda-cache` (`ValidationConfig.eval_empty_cuda_cache`, off by default), which calls `torch.cuda.empty_cache()` before and after `evaluate()`.

Validation can route tokens very unevenly across experts, so its allocations do not fit the training-shaped caching-allocator pool and can grow reserved memory to the device limit. The caching allocator recovers from its own failed allocations by freeing its cache, but NCCL allocates from the driver directly, so the checkpoint save that follows validation can fail to allocate collective buffers. Releasing the cache on both sides of validation returns that memory to the driver, at the cost of re-mapping training's pool afterwards.

Off by default because the re-mapping after each validation is not free, so it is only worth enabling when validation actually runs the device out of memory.

I found two correctness issues and a runtime test-coverage gap. Tests weren't executed; the checks below are proposed regressions based on source inspection.

### 1. Clear the cache when evaluation reaches the duration limit

With `eval_empty_cuda_cache=True`, `empty_unused_memory_level=0`, and a duration limit reached during validation, the [early return](https://github.com/NVIDIA/Megatron-LM/blob/1396050ae677764449d8d657d0ad1cc54c42e203/megatron/training/training.py#L5844-L5854) bypasses the [new trailing cache clear](https://github.com/NVIDIA/Megatron-LM/blob/1396050ae677764449d8d657d0ad1cc54c42e203/megatron/training/training.py#L5878-L5882). Only the entry-side clear runs, so evaluation's unused allocations remain reserved.

This is still a checkpoint path: [the evaluation wrapper returns on timeout](https://github.com/NVIDIA/Megatron-LM/blob/1396050ae677764449d8d657d0ad1cc54c42e203/megatron/training/training.py#L5979-L5995), the [training loop continues to checkpoint handling](https://github.com/NVIDIA/Megatron-LM/blob/1396050ae677764449d8d657d0ad1cc54c42e203/megatron/training/training.py#L5525-L5578), and [duration-based exit saves a checkpoint](https://github.com/NVIDIA/Megatron-LM/blob/1396050ae677764449d8d657d0ad1cc54c42e203/megatron/training/training.py#L4688-L4714). The option therefore misses its intended release immediately before that save.

**Correction:** In `evaluate()`'s `if done:` branch, insert the same conditional clear immediately before the return:

```python
if cfg.validation.eval_empty_cuda_cache:
    torch.cuda.empty_cache()
return None, None, True
```

Keep the existing rerun-mode restoration and timeout message before this code. This restores the invariant that both normal and duration-limited returns perform the requested trailing clear, without changing default-off behavior or the independent per-iteration memory-clearing option.

**Acceptance:** With a mocked schedule, cache clear, CPU-backed duration tensor, and duration collective, force timeout after one step. Assert `empty_cache → forward → empty_cache`, `(None, None, True)`, and restoration of the previous rerun mode. Normal two-step completion must retain `empty_cache → forward → forward → empty_cache` and `timelimit=False`. With the flag off and memory level zero, assert no clears; with memory level one, retain its per-step clears independently.

### 2. Update the packed-iterator regression fixture for the new field

The [existing packed-iterator test](https://github.com/NVIDIA/Megatron-LM/blob/1396050ae677764449d8d657d0ad1cc54c42e203/tests/unit_tests/training/test_evaluate_packed_iterator.py#L33-L87) supplies a `SimpleNamespace` validation config without `eval_empty_cuda_cache`. The [new attribute read](https://github.com/NVIDIA/Megatron-LM/blob/1396050ae677764449d8d657d0ad1cc54c42e203/megatron/training/training.py#L5697-L5701) therefore raises `AttributeError` before the scheduling loop in all three `completed_steps` cases. The production dataclass default doesn't apply to this mocked config.

**Correction:** Update that test's validation namespace to include the default-off field; production config access doesn't need a fallback:

```python
validation=SimpleNamespace(
    eval_global_batch_size=1,
    eval_micro_batch_size=1,
    eval_iters=completed_steps + 2,
    eval_empty_cuda_cache=False,
),
```

**Acceptance and preservation:** All `completed_steps=[0, 1, 2]` cases must reach their existing assertions: no timeout, exactly `completed_steps` forward calls, no open FT sections, `max(completed_steps - 1, 0)` closed sections, the correct FT iteration index, and restored timers. This retains the previously covered exhaustion-before-first-step and exhaustion-after-completed-steps behavior.

The [new tests](https://github.com/NVIDIA/Megatron-LM/blob/1396050ae677764449d8d657d0ad1cc54c42e203/tests/unit_tests/training/test_eval_empty_cuda_cache.py#L9-L18) only check config and parsing. By inspection, both assertions would remain unchanged if either runtime clear were removed or made unconditional. Add a runtime assertion for the feature's normal-path contract, separately from the timeout regression above.

The [token-weighted evaluation test](https://github.com/NVIDIA/Megatron-LM/blob/1396050ae677764449d8d657d0ad1cc54c42e203/tests/unit_tests/training/test_evaluate_token_weighted_loss.py#L15-L97) already provides a real `run_config` and the necessary runtime mocks. A small extension is to parameterize `eval_empty_cuda_cache` over `[False, True]`, pass it into the test, and set:

```python
run_config.validation.eval_empty_cuda_cache = eval_empty_cuda_cache
run_config.train.empty_unused_memory_level = 0
```

After creating `forward_backward` and `model`, attach their calls to one recorder:

```python
lifecycle = mock.Mock()
lifecycle.attach_mock(forward_backward, "forward")
```

Add `mock.patch.object(torch.cuda, "empty_cache") as empty_cache` to the existing patch context, attach it with `lifecycle.attach_mock(empty_cache, "empty_cache")` before invoking `evaluate()`, and assert afterward:

```python
expected = ["eval", "forward", "forward", "train"]

assert [call[0] for call in lifecycle.mock_calls] == expected
```

This proposed extension checks both call count and boundary ordering without allocating CUDA memory. Retain every existing parameter combination and assertion: loss `5.0` or `0.0` for empty input, two reductions, scheduled microbatch counts, eight consumed validation samples, successful completion, and model-mode restoration. Retain the new CLI/default assertions too.
