# fix(inference): AUT-2539 skip prefill token limit for imported decode pr

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8259) · state: closed · merged: False

## Original PR description

## Background

In disaggregated serving, `_finalize_kv_handoff_import()` admits an imported decode request through `add_request()`. Unless chunked prefill was enabled, `_add_request()` failed any prompt longer than `context.max_tokens` with `TokenOverflowError`. That limit bounds how much prefill work one step does. An imported prompt's KV cache already exists and the request goes straight to decode, so a long disaggregated prompt failed on the decode engine.

## What changed

- `dynamic_engine.py`: `add_request()` and `_add_request()` take a keyword-only `prompt_is_prefilled: bool = False`. `add_request()` forwards it from both of its `_add_request()` call sites (text and VLM). When the flag is set, only the `max_tokens` check is skipped. The max sequence length and KV-pool checks still apply.
- `inference_state_handoff.py`: the import finalizer passes `prompt_is_prefilled=True`.
- Tests:
  - `test_add_request_forwards_prompt_is_prefilled` in `test_dynamic_engine.py`.
  - Parametrized finalizer and limit tests in `test_disagg_handoff_lifecycle.py`.
  - The refit test's `_add_request` double now accepts the new keyword.

## Details

The default is `False`, so every other caller behaves as before. No subclass overrides `_add_request`. This was split out of the inference review and is independent of #8258.
