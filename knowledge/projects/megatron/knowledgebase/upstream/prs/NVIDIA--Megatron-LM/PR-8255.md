# fix(inference): AUT-2539 reply to a KV handoff import that fails before admission

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8255) · state: closed · merged: False

## Original PR description

## Background

A review of recent inference changes on `main` found a hang in disaggregated decode. The decode side imports a request's KV cache before it admits the request. An import can fail before `_finalize_kv_handoff_import()` runs, either because a peer failed or because the local transfer raised. The request then never reaches `add_request()`.

`_admit_pending_kv_imports()` releases or quarantines the blocks and fails the import future, but the engine dispatch drops that future. So no `ENGINE_REPLY` is ever sent. The coordinator frees a request's routing entry and pending count only on `ENGINE_REPLY`, so the client request hangs forever.

## What changed

- `inference_state_handoff.py`: in the `except` branch, an import that is not in `self.requests` now calls `_fail_submission()`. This is the same FAILED-placeholder path already used for rejected submissions. Every MP rank applies the same broadcast completion decision to mirrored state, so all ranks register the same placeholder. Only the MP coordinator sends the reply.
- `dynamic_engine.py`: the `_fail_submission` docstring now names this caller.
- `test_disagg_handoff_lifecycle.py`:
  - The peer-failure quarantine test now asserts exactly one failed submission.
  - The submission-failure test now runs the engine's real `_fail_submission`, `_handle_failed_request` and `_complete_request`, with only the coordinator socket mocked. It asserts exactly one FAILED reply for the request.

## Details

Release-once and quarantine behavior are unchanged. A failure after `add_request()` still goes through the existing request path. There are no dependency or lock changes.

The branch was based on `main` at `a54dd737` and now merges `main` at `ee6baa2e`. CI on the previous head (which merged `main` at `3914483f`, run 38816895124) timed out in an NCCL barrier in `test_checkpointing.py::test_checkpoint_load_without_microbatch_calculator` (`torch_dist` cases). `ee6baa2e` is #8263, "test(checkpointing): seed CPU initialization in checkpoint load test". Against `main` at `ee6baa2e`, this branch still changes only the three files above.
