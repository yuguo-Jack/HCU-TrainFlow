## Implementation details

- **Gather unfused CSA KV rows in FP32.** `unfused_compressed_sparse_attn` gathered BF16 KV rows and cast them to FP32 afterwards, so the gather's backward scatter-added each row's gradient in BF16, once per query that selected it. With a 128-token sliding window the KV gradient is about 6% off an FP32 reference, while the fused FlashMLA/cuDNN gradient is within 0.14% of it. That is why `test_real_fused_sbhd_forward_backward_matches_native_reference` fails where the fused kernels are available: the native reference, not the fused kernel, was the inaccurate side. The gathered tensor was already copied to FP32 for the einsum, so peak memory is about the same.
- **Clamp `-1` slots before the cuDNN backward when `topk_length` is supplied.** With `topk_length`, the cuDNN DSA backward treats every slot as a non-negative address, including the ignored suffix; the fused Path-B backward already clamps for that reason. `CSASparseAttnFunc` now clamps a copy only in that case. Without `topk_length` the `-1` sentinels are the only invalid-slot marker and are kept, since turning them into 0 would make the backward read KV row 0 for them.

## Testing

H20, 2 ranks: `test_csa_fused_sparse_attention.py`, `test_attention_variant_csa.py`.

- `test_real_fused_sbhd_forward_backward_matches_native_reference[1]` and `[2]` fail on `main` and pass here.
- New `test_sparse_attention_backward_clamps_sentinels_only_with_topk_length` checks both cases and that the saved indices are not modified.
- No test fails here that passes on `main`.
