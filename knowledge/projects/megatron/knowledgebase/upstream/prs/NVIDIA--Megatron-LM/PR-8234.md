# refactor(training): migrate model configuration and shared consumers

# What does this PR do?

Make `cfg.model` and `cfg.model.transformer` authoritative for shared model construction and training-loop consumers (C10 of the training-loop consolidation).

- Preserve GPT/Hybrid builders and BERT/T5/VLM/MIMO provider callbacks. Callback paths get a typed model-provider config centrally; position capacity stays distinct from actual data sequence length.
- Read model precision, topology, attention/MoE, recomputation, graph and freeze settings from config in startup, model setup, training/evaluation, warmup, FLOPs and memory estimates. Derive optimizer precision and runtime batch topology centrally. GPT/Hybrid embedding groups, batch layouts and sampler/collation selection use the same model owner.
- Restore model settings from existing checkpoint config metadata, retaining legacy checkpoint fallback and existing CLI override rules. Preserve nested Hybrid/MTP specs and activation settings through serialization.
- Keep TP user-buffer overrides on the existing model owners, with explicit actual sequence length and microbatch inputs. No new overlap config.
- Pass model-owned TP/divisibility inputs explicitly to tokenizer padding during training bootstrap; preserve explicit padded-vocabulary overrides and existing inference defaults. Tokenizer selection and policy remain separate.

Upcycling policy/native-builder changes remain a follow-up; existing callback upcycling is preserved. `modelopt_enabled` remains with the distillation integration (C17). Tokenizer, optimizer and scheduler ownership migrations are separate.

This is an independent draft on main. Integration with #7778, #8149, #8205 and #8202 must retain their distributed/training/DDP owners and centralized finalization contracts; this PR does not replace those migrations.

## Why keep this migration in one PR?

We considered splitting this PR, but the model-config ownership switch needs to be atomic: initialization, model construction, training consumers, and checkpoint handling must agree on the source of truth. Splitting those would leave some paths reading `args` and others reading `cfg.model`, or require temporary compatibility code.

The current 102-file diff includes 51 test files, 23 of which change by at most 12 lines. Serialization could be extracted independently, but that would only reduce this PR to roughly 95 files. Keeping these changes together lets reviewers verify the complete ownership change and its tests in one place.

Compared #8234 at `ea54f674` with #8341 at `f8807e82c`. I'd favor #8341's `GTPParallelLayout` calculation combined with this PR's model-world-size resolution.

For valid inputs and the same world size, both calculate:

```python
configured_cp = transformer.context_parallel_size // sequence_shards
dp = world_size // (tp * pp * configured_cp * weight_size)
```

Both correctly divide out the GTP sequence shards already included in the transformer's resolved CP. `GTPParallelLayout` centralizes the arithmetic and validation and also exposes `batch_parallel_size`, which this PR calculates separately. Constructing it only validates integers; it does not initialize process groups or enumerate ranks.

The implementations differ on invalid inputs: the layout checks that sequence shards divide the weight-remat size, whereas this PR's method does not. Conversely, #8341's `getattr(..., 1) or 1` silently converts zero shard/weight sizes to one; I would avoid that normalization for fields that should already be valid.

For world-size handling, the explicit argument in #8341 makes the calculation deterministic and convenient for tests or hypothetical launch sizes. This PR's no-argument API is convenient for runtime callers, but `get_model_world_size()` also provides an important semantic distinction: MIMO's model world size can be smaller than the global launch. It selects `mimo_llm_world_size` when configured and checks that it fits within the launch. #8341 currently passes `safe_get_world_size()` directly, without that model-subset handling.

My preference would be a shared layout-construction method taking an explicit **model world size**, with runtime callers obtaining that value through `get_model_world_size()`. A no-argument convenience method can wrap those steps. This keeps environment discovery at the runtime boundary while centralizing topology calculations and retaining MIMO handling.

def get_data_parallel_size(self) -> int:
