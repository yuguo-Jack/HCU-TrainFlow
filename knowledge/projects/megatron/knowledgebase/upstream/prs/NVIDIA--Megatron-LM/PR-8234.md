# refactor(training): migrate model configuration and shared consumers

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Make `cfg.model` and `cfg.model.transformer` authoritative for shared model construction and training-loop consumers (C10 of the training-loop consolidation).

- Preserve GPT/Hybrid builders and BERT/T5/VLM/MIMO provider callbacks. Callback paths get a typed model-provider config centrally; position capacity stays distinct from actual data sequence length.
- Read model precision, topology, attention/MoE, recomputation, graph and freeze settings from config in startup, model setup, training/evaluation, warmup, FLOPs and memory estimates. Derive optimizer precision and runtime batch topology centrally. GPT/Hybrid embedding groups, batch layouts and sampler/collation selection use the same model owner.
- Restore model settings from existing checkpoint config metadata, retaining legacy checkpoint fallback and existing CLI override rules. Preserve nested Hybrid/MTP specs and activation settings through serialization.
- Keep TP user-buffer overrides on the existing model owners, with explicit actual sequence length and microbatch inputs. No new overlap config.
- Pass model-owned TP/divisibility inputs explicitly to tokenizer padding during training bootstrap; preserve explicit padded-vocabulary overrides and existing inference defaults. Tokenizer selection and policy remain separate.

Upcycling policy/native-builder changes remain a follow-up; existing callback upcycling is preserved. `modelopt_enabled` remains with the distillation integration (C17). Tokenizer, optimizer and scheduler ownership migrations are separate.

This is an independent draft on main. Integration with #7778, #8149, #8205 and #8202 must retain their distributed/training/DDP owners and centralized finalization contracts; this PR does not replace those migrations.
