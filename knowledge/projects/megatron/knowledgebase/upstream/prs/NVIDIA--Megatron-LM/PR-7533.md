## Strict review summary

Findings: **CRITICAL: 0, IMPORTANT: 4, SUGGESTION: 0**.

The mode-specific RS routing is consistent, but the new integration breaks unwrapped GTP model setup and makes AG-input placement decisions before the final storage location is known. This can leave inputs unregistered or retain unnecessary weight-sized allocations. Overall risk is **medium**, concentrated in setup and memory management.

All nine changed files were inspected, with targeted tracing through model placement, freezing, DDP remapping, quantized storage, and shutdown. Tests were not executed; the acceptance checks below are proposed regressions.

### Suggested correction for finding 1

Replace `_ddp_buffers` in [gtp_symmetric_memory.py](https://github.com/NVIDIA/Megatron-LM/blob/9d2a19978320dd4111329b3a2923a49e7c842aa6/megatron/core/tensor_parallel/gtp_symmetric_memory.py#L289-L293) with:

```python
def _ddp_buffers(ddp_module: torch.nn.Module) -> list:
    """Return DDP communication buffers, or none for an unwrapped module."""
    buffers = getattr(ddp_module, "buffers", ())
    if callable(buffers):
        return []
    return list(buffers) + list(getattr(ddp_module, "expert_parallel_buffers", ()))
```

This distinguishes the inherited `nn.Module.buffers()` method from DDP's communication-buffer list without invoking the method or confusing ordinary tensor buffers with `_ParamAndGradBuffer` objects. The author should verify the suggested code before adopting it.

**[IMPORTANT Compatibility] Handle unwrapped modules without iterating `Module.buffers`

**Failure:** Run GTP with `--skip-train` and no RL optimizer—even with both GTP NCCL-UB flags off. [Setup deliberately skips DDP](https://github.com/NVIDIA/Megatron-LM/blob/9d2a19978320dd4111329b3a2923a49e7c842aa6/megatron/training/training.py#L2857-L2862), but [the new registration call still runs for every GTP model chunk](https://github.com/NVIDIA/Megatron-LM/blob/9d2a19978320dd4111329b3a2923a49e7c842aa6/megatron/training/training.py#L2939-L2954). An unwrapped model/`Float16Module` inherits the callable `nn.Module.buffers`; `list(bound_method)` raises `TypeError` instead of making registration a no-op. The new shutdown helper has the same problem.

**Correction:** Make `_ddp_buffers` distinguish DDP's communication-buffer list from the inherited callable and return `[]` for the latter. Do not call `buffers()`: its results are ordinary tensor buffers, not objects with this registration protocol. A small replacement is provided in the review body.

**Preservation / proposed acceptance:** Calling both registration and deregistration on `torch.nn.Linear(4, 4)` must return without CUDA/NCCL calls or exceptions. A GTP `--skip-train` setup must reach evaluation with flags off and with `ag` enabled. For a DDP-shaped object containing one dense and one expert communication buffer, both lists must still be visited; retain the registered-buffer collective round trip and an empty-DDP-list no-op. These checks have not been executed.

File: `megatron/core/tensor_parallel/generalized_tensor_parallelism.py` · line 772

**[IMPORTANT Performance] Avoid pooling BF16 storage that DDP immediately replaces

**Failure:** With CUDA-initialized BF16 TE weights, `--use-distributed-optimizer --gtp-remat-nccl-ub ag` moves every pre-sharded weight into the GTP pool during construction. [DDP subsequently replaces those same BF16 allocations with views into its separately allocated param buffer](https://github.com/NVIDIA/Megatron-LM/blob/9d2a19978320dd4111329b3a2923a49e7c842aa6/megatron/core/distributed/param_and_grad_buffer.py#L1366-L1384). The GTP pool remains alive in `_pools`, retaining the discarded shard allocations as cached memory in addition to DDP backing, except where later AG allocations can reuse it. This introduces model-shard-sized memory pressure that the adjacent slice path explicitly avoids.

**Correction:** In `attach_gtp_to_presharded_module`, avoid this intermediate symmetric allocation for plain weights that will actually be remapped into DDP. Resolve ownership after freeze/wrapping decisions if necessary; the invariant is that discarded BF16 construction storage is not allocated from the persistent GTP pool.

**Preservation:** Do not blanket-skip quantized weights when distributed optimization is enabled: MXFP8 retains its own storage, and NVFP4 remaps only rowwise bytes while retaining scales/columnwise storage. BF16 weights outside DDP—including frozen weights—still need registered input storage. RS-only mode must not move weights.

**Proposed acceptance:** Build several BF16 TE layers with real DDP and AG registration; verify their final inputs alias the registered DDP pool and no discarded per-weight BF16 blocks remain in the GTP pool before cache warmup. Retain no-distopt BF16 value preservation and bias exclusion, and check MXFP8/NVFP4 retained buffers remain pooled. A safe exact patch depends on exposing final per-parameter ownership; simply adding a global distopt guard would break those preservation cases. Not executed.

**[IMPORTANT Performance] Apply symmetric allocation after CPU weights reach CUDA

**Failure:** Use BF16 CPU initialization, no distributed optimizer, and `--gtp-remat-nccl-ub ag`. [TE constructs these weights on CPU](https://github.com/NVIDIA/Megatron-LM/blob/9d2a19978320dd4111329b3a2923a49e7c842aa6/megatron/core/extensions/transformer_engine.py#L470-L480), so `torch.empty_like(param)` here is still a CPU allocation: entering a CUDA memory-pool context does not change its device. [The later `.cuda()` transfer occurs outside that context](https://github.com/NVIDIA/Megatron-LM/blob/9d2a19978320dd4111329b3a2923a49e7c842aa6/megatron/training/training.py#L2615-L2623). The slice-path `shard.clone()` has the same issue. DDP without distributed optimization supplies no replacement param storage, leaving the actual AG input unregistered while the output is pooled; the advertised symmetric AG path is therefore unavailable.

**Correction:** Route persistent inputs into the registered pool when their final CUDA storage is materialized, rather than treating a CPU clone/empty allocation inside `gtp_symm_pool_ctx` as sufficient. Cover both `_move_presharded_weight_to_symm_pool` and `_gtp_slice_one_param`; do not change CPU seed/master-weight initialization merely to obtain a CUDA allocation.

**Preservation / proposed acceptance:** Extend the CPU-initialization regression to enable AG registration, finish GPU placement, and assert the live BF16 AG-input pointer belongs to the group pool before forward. Retain bitwise equality of reconstructed initial weights at GTP degrees 1/2/4 and the quantized high-precision initializer assertions in [the CPU-init tests](https://github.com/NVIDIA/Megatron-LM/blob/9d2a19978320dd4111329b3a2923a49e7c842aa6/tests/unit_tests/generalized_tensor_parallel/test_gtp_cpu_init.py#L186-L253). Keep CUDA-initialized weight values intact, biases outside the pool, and RS-only allocation unchanged. The exact placement hook needs coordination with the model-build lifecycle; no speculative patch is supplied. Not executed.

**[IMPORTANT Performance] Do not infer every slice parameter's residence from the optimizer flag

**Failure:** With `--use-distributed-optimizer --freeze-base-model-for-mtp --gtp-remat-nccl-ub ag`, a frozen slice-path weight such as the backbone embedding skips the symmetric clone because `param_storage_in_ddp_buffer=True`. However, [freezing happens before DDP wrapping](https://github.com/NVIDIA/Megatron-LM/blob/9d2a19978320dd4111329b3a2923a49e7c842aa6/megatron/training/training.py#L2585-L2589), and [DDP excludes every non-trainable parameter](https://github.com/NVIDIA/Megatron-LM/blob/9d2a19978320dd4111329b3a2923a49e7c842aa6/megatron/core/distributed/distributed_data_parallel.py#L181-L195). That embedding never enters a DDP param buffer, so its AG input remains ordinary memory for the run. `--freeze-all-layers` reaches the same mismatch. The optimizer flag is not a per-parameter storage fact.

**Correction:** Base the skip on actual buffer ownership after freezing/wrapping, and pool live slice-path weights that were excluded from DDP. Update the placement/configuration contract so `param_storage_in_ddp_buffer` cannot stand in for ownership of every parameter.

**Preservation:** Trainable BF16 parameters genuinely remapped into DDP must continue avoiding a redundant pooled clone; no-distopt slice weights must remain pooled. Retain native quantized storage handling rather than assuming every weight type aliases `param_data`.

**Proposed acceptance:** Build a small MTP model with a frozen backbone embedding and trainable MTP parameters. After DDP wrapping, assert the embedding is absent from `buf.params` but its live input belongs to the GTP pool; assert trainable remapped inputs belong to the registered DDP pool. Run the analogous all-frozen setup and retain the existing no-distopt slice-pool assertion. Verify `rs`-only mode does not introduce AG allocations. These checks are proposed, not executed; the exact implementation depends on making final ownership available.
