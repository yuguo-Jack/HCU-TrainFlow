# perf(gdn): gather by the inverse permutation in CP all-to-all backward

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8161) · state: open · merged: False

## Original PR description

## What
`a2a_cp_to_hp` / `a2a_hp_to_cp` reorder tensors with `index_select` in three places:
- the head-dim pre-permutation,
- the THD sequence permutation,
- its inverse on the way back.

Autograd's `index_select` backward is an atomic `index_add_`, because it can't assume unique indices. All three indices are permutations, so the gradient is just a gather by the inverse permutation. That's much faster and deterministic.

This adds `_PermuteAlongDim`, whose forward is `index_select` by the permutation and whose backward is `index_select` by its inverse, and uses it at the three sites:
- **Head permutation:** the inverse comes from a new cached `_build_head_perm_and_inverse_for_split_sections`. `_build_head_perm_for_split_sections` is unchanged, since tests call it directly.
- **THD sequence permutation:** `_build_thd_cp_a2a_perm` already returns its inverse.
- **`a2a_hp_to_cp`:** rebuilds the forward index from the inverse with one O(n) scatter, so callers' signatures don't change.

## Correctness
For a permutation, the old backward adds each element exactly once into zeros and the new one copies it, so gradients are bit-identical.
- **New test** `tests/unit_tests/ssm/test_gdn_permute_along_dim.py`: asserts exact equality of outputs and gradients against `index_select`, for the head permutation and both directions of the THD permutation, in fp32 and bf16.
- **Existing tests:** `test_gated_delta_net.py` and `test_gated_delta_net_parallel.py` under `torchrun --nproc_per_node 4` (GB300) gave 151 passed / 72 skipped / 0 failed on every rank. On a second box, the full suite hits an NCCL watchdog timeout in `test_parallel_gated_delta_net2_correctness`. The base commit hits the same timeout there without this change, and with this change that test passes on its own (6/6 per rank).

## Performance
Measured on a downstream fork, on a model whose KDA layers use these helpers. 262k tokens on 8x GB300, CP4:
- Forward/backward step: 34.1 s → 28.9 s.
- The profiled `index_add_` cost was 5.5 s per step.
- Peak memory is unchanged.
