# Reduce DSv4 output RoPE activation memory

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8399) · state: closed · merged: True

## Original PR description

Port the output-activation memory optimization from dev #7036 onto main. Fused CSA stores its inverse-rotated output and reconstructs the raw attention output during backward, avoiding a second output activation retained from forward. Related to #5795; credits to @ghadiaravi13 for the original dev implementation.

- Cover SBHD and packed THD/CP attention, including the fused indexer-loss paths. Native/unfused attention keeps its existing rotation.
- Preserve main's existing RoPE kernels, including #8141. The output-reconstruction kernel lives under `megatron/core/ops/attention/csa` and copies the non-rotary prefix in the same launch.
- Preserve both saved-output aliases and incoming gradient storage during backward. No new configuration flag or dependency on the other pending performance PRs.

Validation on four GB200 GPUs: 96 tests passed per rank, including output/gradient reconstruction and bit-exact replay, shared/expanded-gradient protection, and the existing native SBHD → fused SBHD → THD → CP2/CP4 comparisons (sparse/dense indexer loss and selective recompute). The two pre-existing, flaky-marked small-head SBHD tests also fail on unmodified main with comparable BF16 KV-gradient differences; no tolerances or skip markers were changed. Formatting/lint, Python syntax, and kernel determinism coverage checks passed.

Reconstructing a saved BF16 output introduces an additional rounding step; this is short numerical/integration validation, not a long-run convergence claim.

### Handle padded-head outputs before reconstruction

**Failure:** Supported head counts requiring FlashMLA padding now fail during backward with output RoPE enabled. The [shared adapter](https://github.com/NVIDIA/Megatron-LM/blob/b133adb7dcf4af86cb84cfa714a39e693f9033a8/megatron/core/transformer/experimental_attention_variant/csa_utils/fused_sparse_attention.py#L119-L149) slices the padded output without making it dense. For example, a contiguous `(4, 64, 512)` backend output sliced to two heads has strides `(32768, 512, 1)`. This `empty_like` allocation compacts that non-dense view to `(1024, 512, 1)`, so reconstruction raises the [matching-metadata error](https://github.com/NVIDIA/Megatron-LM/blob/b133adb7dcf4af86cb84cfa714a39e693f9033a8/megatron/core/ops/attention/csa/output_rope.py#L204-L205). SBHD, packed, and fused-indexer Functions all share this path; backward should instead reconstruct O and dO successfully.

**Correction:** The smallest shared correction is to replace the output-slicing line in `_csa_fwd_flash_mla` with:
```python
out = out[:, :actual_num_heads, :].contiguous()
```
This makes the saved real-head output dense before rotation, restoring the source/destination stride invariant. Do not merely remove the metadata check: the reconstruction kernel uses the input strides for both pointers. Please verify this suggested replacement before adoption.

**Preservation:** Keep real-head output values, LSE/indexer-LSE slicing, and the unpadded full-head path unchanged. Continue reconstructing into private storage so saved-output aliases and shared/expanded upstream gradients remain untouched; no-RoPE backward must remain unchanged.

**Acceptance — proposed, not executed:** Extend [the existing small-head adapter test](https://github.com/NVIDIA/Megatron-LM/blob/b133adb7dcf4af86cb84cfa714a39e693f9033a8/tests/unit_tests/transformer/experimental_attention_variant/test_csa_fused_sparse_attention.py#L230-L267) with `assert out.is_contiguous()`, retaining its exact output/LSE/indexer-LSE value assertions. Add SBHD and THD backward cases with two actual heads, a mocked contiguous 64-head backend output, and real `OutputRopeParams`; require no exception, reconstructed O within the existing dtype tolerance, reference-matching dO, and unchanged saved output/upstream storage. Retain an unpadded 64-head case and no-RoPE backward.
