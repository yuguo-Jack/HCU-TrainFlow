# Unify VocabParallelEmbedding lookup under deterministic_mode

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7126) · state: open · merged: False

## Original PR description

## Summary

Addresses the `VocabParallelEmbedding` bullet of #6547 (`layers.py`: `F.embedding` vs `weight[masked_input]`). Does not touch `moe_utils.py`.

`deterministic_mode` keeps `weight[masked_input]` on PyTorch builds that do not include [pytorch/pytorch#199569](https://github.com/pytorch/pytorch/pull/199569). That fix landed on main on 2026-10-05 and is not in any release through 2.15, including 2.9. `embedding_backward_feature_kernel` can drop or double-count a row's gradient for 2017..3072 CUDA indices under GPU contention, even with `torch.use_deterministic_algorithms(True)`.

`F.embedding` is used otherwise: the non-deterministic path, and `deterministic_mode` once `torch >= 2.16.0`. Nightlies still report a version below 2.16.0 (`2.16.0a0`, `2.16.0.dev*`), so they keep the index gather too.

This layer never passes `padding_idx`, `scale_grad_by_freq`, or `sparse`, so both ops gather the same rows. GTP remat wrapping and the inference reduce-scatter are unchanged.

## Test plan

- [x] CPU: `F.embedding` matches advanced indexing in forward and backward (repeated indices)
- [x] GPU unit test calls `model_parallel_cuda_manual_seed` before constructing the embedding, then checks forward against `F.embedding` for `deterministic_mode={False, True}`
- [x] Determinism replay covers 32,768 indices (sort kernel) and 2,048 indices (feature kernel)
- [ ] CI unit-test bucket, after `/ok to test` on `d637f4f89`

File: `megatron/core/tensor_parallel/layers.py` · line None

Can we keep the deterministic lookup for PyTorch builds that don't have the embedding backward fix yet? Supported versions such as PyTorch 2.9 still have a race with 2,017 to 3,072 CUDA indices that can drop or double-count gradient contributions under GPU contention, even with torch.use_deterministic_algorithms(True). Switching to F.embedding here exposes deterministic runs to that race. The upstream fix only landed on October 5: https://github.com/pytorch/pytorch/pull/199569
