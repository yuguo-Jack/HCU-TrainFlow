# ci: Reduce retry memory by streaming archived failure logs

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8621) · state: open · merged: False

## Original PR description

# What does this PR do?

Reduce archived-log text allocations when deciding whether to retry a failed workload.

## Motivation

The retry path reads all candidate rank and harness logs into a list, then joins the complete corpus. Large failed runs therefore require several full-size text allocations before the retry decision. It also scans archived files when the monitor or tee already found a retry signature.

This adds time and memory to failure recovery. Successful workloads return before this path.

## Change

Read archived logs in chunks of 1,048,576 decoded characters with a 4,096-character overlap for split signatures. This is roughly 1 MiB per chunk for ASCII logs. Reuse monitor or tee evidence before opening archived files. The original `is_flaky_failure` classifier and retry budget are unchanged.

The change removes full archived-log corpus allocations. It does not bound the existing streamed-output buffer or the set of discovered paths. The current retry signatures are short, newline-free literal strings; the overlap preserves matches across chunk boundaries.

Only the launcher and its focused tests change. Review the archived-log scanner and its call site.

## Results

A local 128 MiB nonmatching log corpus produced these medians across three interleaved runs per version:

| Metric | Before | After |
| --- | --- | --- |
| Scan time | 0.811 seconds | 0.424 seconds, about 48% less time. |
| Peak process RSS | 882,012 KiB | 626,648 KiB, about 249 MiB less. |

RSS includes the shared import/runtime footprint. These measurements cover failed-attempt log scanning, not full-job or successful-run speedups. A preexisting monitor or tee match now avoids the archive scan entirely.

A second host shows how the scan scales with corpus size. These are medians across three interleaved runs per version on nonmatching logs:

| Corpus | Scan time before | Scan time after | Peak RSS before | Peak RSS after |
| --- | --- | --- | --- | --- |
| 128 MiB | 1.26 seconds | 0.98 seconds | 945 MiB | 606 MiB |
| 2 GiB | 22.4 seconds | 15.3 seconds | 6,109 MiB | 603 MiB |

## Validation

The baseline and changed scanner agreed on the captured 55.4 MiB CI log corpus. Focused tests passed with the real NeMo-Run imports, covering chunk boundaries, end-of-file matches, nested logs, deduplication, malformed text, read errors, and streamed-evidence short circuits.

Canonical Black, isort, Pylint, and Ruff checks passed. Optional mypy was unavailable. Supplemental stdlib-only probes of the exact scanner and classifier passed for every current signature at chunk boundaries, Unicode text, cross-file splits, and randomized multi-file corpora. These probes isolate scanner semantics and do not replace real NeMo-Run imports or full workflow validation, which remains for maintainer CI.

### Downside

The scanner returns on the first matching signature, so later unreadable logs may no longer emit warnings. Archived logs remain available.
