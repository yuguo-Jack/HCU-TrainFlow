## Implementation details

- `SharedExpertMLP` runs the full, unpadded token set through per-token TE linears. THD packing adds no padding and the token dispatcher only aligns the routed experts, so a token count such as 639 fails with `FP8 execution requires the product of all dimensions except the last to be divisible by 8 ... dims=[639, 1, 5120]`.
- Pad the sequence dimension to `get_align_size_for_quantization` (16 for blockwise or hybrid FP8, 32 for MXFP8) and slice the output back, in `forward` and in the overlapped `pre_forward_comm` / `linear_fc1_forward_and_act` / `linear_fc2_forward` path. The overlapped path unpads in `linear_fc2_forward`, before `post_forward_comm`, so the TP communication and the gate keep the original token count. The added rows are zeros and are dropped.
- Without FP8 or FP4 the alignment is 1 and nothing is padded, so BF16 is unchanged.
- `FusedSharedExpertMLP` feeds TE grouped linears, which accept any token count, and is unchanged.
