# Skip unfused DSA parity cases that do not fit in GPU memory

# What does this PR do?

`test_unfused_absorbed_mla_dsa_matches_native` materializes the full attention scores, so its memory need grows with `seqlen**2`. I measured the smallest per-process limit (`torch.cuda.set_per_process_memory_fraction`) under which each case passes on B300:

| seqlen | fails at | passes at | peak allocated / reserved without a limit |
|---|---|---|---|
| 1024 | 8 GiB | 9 GiB | 7.3 / 12.5 GiB |
| 2048 | 24 GiB | 26 GiB | 22.6 / 25.0 GiB |
| 4096 | 93 GiB | 94 GiB | 81.7 / 93.1 GiB |

The 4096-token cases therefore cannot run on an 80 GB GPU. When all cases run in one process, a failed case also keeps its memory alive until the next case starts, so cases that would fit on their own fail too.

This PR checks free GPU memory before each case, after releasing cached blocks. It skips the case when free memory is below the measured need.

## Testing

All 12 cases in one pytest process on B300. A live allocation held back most of the GPU so that `mem_get_info` reported the free memory of a smaller GPU:

| Free memory | main | this PR |
|---|---|---|
| 79 GiB (80 GB GPU) | 6 failed, 6 passed: the four 4096-token cases OOM, then `dense_loss-True-2048` and `sparse_loss-False-1024` OOM on the memory those failures still hold | 8 passed, 4 skipped (the 4096-token cases) |
| 94.5 GiB (96 GB GPU) | not run | 8 passed, 4 skipped |

On a 96 GB GPU the 4096-token cases are at the edge. On a GH200 earlier they passed when run alone but went OOM after the smaller cases had run in the same process, so skipping them there as well is deliberate.

The test is marked `flaky` / `flaky_in_dev` with a comment about a CUDA error in CI. The comment mentions real cuDNN/flash_mla kernels, which this unfused test does not use. If CI runs on 80 GB GPUs, the OOMs above may be that CUDA error, and with this check the remaining cases might be stable enough to re-enable. I have left the markers alone because I cannot see the CI failure.

black 26.3.0 and isort 5.13.2 report no changes.
