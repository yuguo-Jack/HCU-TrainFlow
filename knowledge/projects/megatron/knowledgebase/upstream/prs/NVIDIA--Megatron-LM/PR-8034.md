# Take the FP8/FP4 amax reduction group from a process-group collection

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8034) · state: open · merged: False

## Original PR description

**Why.** `get_fp8_context`, `get_fp4_context` and the Transformer Engine per-module quantization autocast read the amax reduction group from `parallel_state`, and pass no group when the global grid is not initialized. With delayed scaling, Transformer Engine all-reduces amaxes over that group, and `None` means the default (WORLD) group. A model built on its own `ProcessGroupCollection` therefore reduces over another grid's TP×DP×CP ranks, or over WORLD.

**What.**
- `amax_reduction_group(pg_collection, tp_only_amax_red)` returns `tp_cp` or `tp_dp_cp`. `tp_dp_cp` spans gtp_remat, like the global group. The helper raises `ValueError` if the field is unset or `None`.
- `get_fp8_context`, `get_fp4_context` and the per-module autocast take an optional keyword-only `pg_collection`. The per-module path uses each recipe's own `tp_only_amax_red`.
- Callers that pass no collection are unchanged. The group is resolved only for autocasts.

**Tests.** The new tests check that the autocast receives the collection's group. They use a distinct communicator over the same ranks, with the global accessor patched to raise. They also cover:
- a custom grid that differs from the global one;
- missing fields;
- identity with `get_amax_reduction_group` on TP2, CP2 and TP2+GTP2.

On 4 GPUs all pass; on main, 20 of the 22 new tests fail.

**Compatibility.** Additive keyword-only argument; existing callers see no change. Needs `determinism-exempt`: these files register kernels, and the change only selects process groups.

Part of #6307.
