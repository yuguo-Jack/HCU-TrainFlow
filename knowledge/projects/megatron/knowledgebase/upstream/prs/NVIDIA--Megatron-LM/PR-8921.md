# [dev](perf): Pack-level zigzag CP layout for DSv4 hybrid attention

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8921) · state: open · merged: False

## Original PR description

Add `dsa_cp_pack_zigzag` (`--dsa-cp-pack-zigzag`), a pack-level zigzag context-parallel layout for the DSv4 hybrid attention stack (experimental_attention_variant='dsv4_hybrid').

Under the contiguous THD split two kernels cost in proportion to the query's causal prefix: the ratio-4 indexer score + top-k (C layers) and the attend-to-all-compressed attention of the ratio-128 layers (H layers). With CP ranks the last rank does 2*CP-1 times the prefix-proportional work of the first one, and every other rank waits for it at each EP collective. With this layout rank r holds pack chunks r and 2*CP-1-r (two contiguous segments of l/2 rows), so head + tail work is the same on every rank. The data split, MTP, LM head and loss stay contiguous.

Compared with `dsa_cp_balance_indexer`, which re-routes only the indexer scoring per call (2 A2A per call, H layers stay imbalanced), this is a layout change: one P2P redistribution per microbatch at decoder entry / exit, static geometry (CUDA-graph friendly), and both the indexer and the H-layer attention are balanced. The two flags are mutually exclusive; under pack-zigzag the indexer reuses the balanced indexer's synthetic-layout scoring per segment.

Per DSv4 attention layer on CP rank r:
- two halo exchanges (one per segment) instead of one
- explicit per-segment global rows for q / kv RoPE positions
- compressor layout built twice in a virtual 2*CP world; the compressed K / KV all-gathers are unchanged and carry 2*c_cap(l/2) rows per rank
- indexer score + top-k: one fused call per segment, no A2A
- kv_full_thd = [halo0 | seg0 | halo1 | seg1 | compressed]
- attention index build per block with index_base = b*(d_window + l/2) (the only kernel-level change); the sparse attention kernel is unchanged
- backward: two halo P2P pairs, inverse permutation at entry / exit

Validated in TransformerConfig.__post_init__: dsv4_hybrid variant, contiguous data split (attention_cp_layout / cp_partition_mode), context_parallel_size > 1, no dynamic CP, no full-iteration CUDA graph, fused DSA kernel backend, sparse indexer loss when a ratio-4 layer exists, not combined with dsa_cp_balance_indexer, no Mamba / GDN / KDA layers in the hybrid pattern, even per-rank row count with l/2 >= max(csa_window_size, d_comp) (checked up front from max_seqlen_per_dp_cp_rank and per microbatch by PackZigzagGeometry). A per-layer CP layout manager raises NotImplementedError; MTP layers always run the contiguous path.

Measured on 256K-token RL rollouts, 64 GPUs, PP2 x EP32 x CP16, chunk-wise CUDA graphs + MoE megakernel: 20.57 -> 19.53 s/iter (-5.1%), vs -2.8% for the balanced indexer on the same setup. 128K is within noise; 512K fixed-length (CP32) gave -17.5% on the prototype tree. Eager mode does not benefit (host-bound step).

Tests:
- tests/unit_tests/transformer/test_cp_pack_zigzag.py (CPU): redistribution plan round trip and P2P views for CP 2..16, PackZigzagGeometry invariants, two-block compressor row map vs a brute-force replay, per-segment position ids, config contract
- tests/unit_tests/transformer/test_pack_zigzag_config.py (CPU): CLI flag generation and the startup rejections
- test_csa_builder_contract_cpu.py / test_csa_cp_utils.py updated for the pack_zigzag_geom kwarg and the always-passed position_ids
