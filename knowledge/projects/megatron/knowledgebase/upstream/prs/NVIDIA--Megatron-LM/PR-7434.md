# What does this PR do?

Supersedes #6910, which GitHub automatically closed after its temporary base
branch was deleted. Main counterpart: #6939.

This change builds on the DSA pre-attention infrastructure merged in #6206 and
is directly based on `dev`.

Keep ordinary DSA sparse-attention backward shapes static when top-k contains
empty query rows, removing its dynamic `nonzero`/compact/gather/scatter path.

The generic path promotes each empty row to a safe one-tile cuDNN invocation:
its first index is zero and its effective top-k length is one. FlashMLA's
supported empty-row contract produces `O=0` and `LSE=+inf`; before backward,
the wrapper masks `dO` to zero and sets `LSE` to `+inf`, making
`P = exp(S - LSE) = 0`. The returned `dQ` is explicitly zeroed for those rows,
so the safe tile contributes neither query nor KV gradients. A conservative
host-side certificate retains the allocation-free fast path when all top-k
rows are provably nonempty.

This covers both the combined fused path and the split path used by IndexShare
and MTP sharing. It does not change CSA, THD/CP layout, MTP sharing semantics,
configuration, or the full-iteration CUDA Graph validator.

### How I checked the correctness argument
- **[`_run_sparse_attention_backward`](https://github.com/NVIDIA/Megatron-LM/blob/b11e566902fa37f4db2ea5827c74272c51374487/megatron/core/transformer/experimental_attention_variant/dsa_cudnn_kernels.py#L2398-L2481)**
  - Each empty row is turned into one safe tile: `topk_length` becomes 1, `dO` becomes 0 and `LSE` becomes +inf.
  - That gives `P = exp(S·scale − inf) = 0`. With `dP = 0` and `D = rowsum(dO∘O) = 0`, `dS = 0`. With `attn_sink = −inf`, `exp(−inf − inf) = 0`. No step produces `inf − inf`, so dKV gets no contribution, and dQ is zeroed explicitly afterwards.
  - Without head padding, the buffers are masked out of place, so `grad_output`, the saved LSE and `ctx.topk_length` are not changed. With head padding, the buffers are private, so in-place masking is safe. The repeated-backward check in `test_cudnn_attention_backward_keeps_fixed_rows` covers this.
- **Forward `global_idxs[:, 0].masked_fill_` ([full](https://github.com/NVIDIA/Megatron-LM/blob/b11e566902fa37f4db2ea5827c74272c51374487/megatron/core/transformer/experimental_attention_variant/dsa_cudnn_kernels.py#L2604-L2607), [split](https://github.com/NVIDIA/Megatron-LM/blob/b11e566902fa37f4db2ea5827c74272c51374487/megatron/core/transformer/experimental_attention_variant/dsa_cudnn_kernels.py#L2954-L2957))**
  - In the split path and in full fusion with loss, it writes into a fresh `clamp_min(0)` copy. So the caller's tensor (or the IndexShare holder's) stays unchanged, as the new test asserts.
  - In full fusion without loss, the tensor may alias `topk_indices_cmp`, but the existing `clamp_min_` already changed that tensor in place and nothing reads it afterwards.
  - Index 0 is always in range because empty KV is now rejected in both `run_fused_dsa_attention` and `run_fused_absorbed_sparse_attention`.
- **[`can_prove_all_topk_rows_nonempty`](https://github.com/NVIDIA/Megatron-LM/blob/b11e566902fa37f4db2ea5827c74272c51374487/megatron/core/transformer/experimental_attention_variant/dsa_masking.py#L37-L74)**
  - **Plain causal:** bounds are `[0, min(i+1, skv))` ([L555-L557](https://github.com/NVIDIA/Megatron-LM/blob/b11e566902fa37f4db2ea5827c74272c51374487/megatron/core/transformer/experimental_attention_variant/dsa_masking.py#L555-L557)), so every row has at least one key.
  - **Packed local varlen:** `generate_varlen_mask_params_for_positions` always gives `start ≤ p < p+1 = end`.
  - **Full fusion:** `normalized_plain_causal` is only reachable when CP=1, `packed_seq_params is None` and `sq == skv` ([L310-L319](https://github.com/NVIDIA/Megatron-LM/blob/b11e566902fa37f4db2ea5827c74272c51374487/megatron/core/transformer/experimental_attention_variant/dsa_cudnn_kernels.py#L310-L319)).
  - **No regression from base:** the base fast-path condition is a subset of the new one, and the split path previously always used compaction.

Every new argument and local has a runtime use.

**[IMPORTANT Verification]** Empty rows with `LSE=+inf` are now fed to the real cuDNN `sparse_attention_backward_wrapper`. Before this PR those rows were compacted out, so the production kernel never saw an infinite LSE.

Whether the CuTe kernel computes `exp(S - LSE)` cleanly (→ 0) or hits an `inf - inf` / `inf * 0` NaN depends on its internal formulation (log2-scaled LSE, max-logit tricks, masked slots at `-inf`, etc.). Every new test in this PR stubs the kernel with `FakeDSA`, and the real-kernel tests in this file are disabled in CI, so this runtime assumption is currently untested. A NaN here would poison dKV for the whole batch through the shared safe tile at global row 0.

**Suggestion:** add a real-kernel check (behind the existing cuDNN/FlashMLA skip conditions) that runs a mixed-empty-row BF16 case through the true wrapper and asserts `torch.isfinite` on dQ/dKV plus zero dKV contribution from the empty rows, or state in the Verification notes that this was validated on hardware. It would also be good to confirm with the cuDNN owners that `+inf` LSE is within the wrapper's documented input contract.
