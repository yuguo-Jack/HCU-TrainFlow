# test: Prevent peer overwrites during planner replay checks

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8620) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Prevent a planner rank from launching its next input while a peer is still inspecting the previous CUDA-graph replay result.

## Motivation

The planner's symmetric window can be written by peer ranks. A fast rank can launch the next input while another rank is still checking the previous histogram. That makes the determinism test vulnerable to inspecting overwritten data and producing a false CI failure.

## Change

Add a closing EP-group barrier after inspection so every rank finishes checking the current result before any rank advances. The diff is three added lines in one existing test. The eager reference helper already uses this closing barrier.

## Results

| Evidence | Before | After |
| --- | --- | --- |
| Cross-rank ordering | A rank can advance while a peer is still inspecting the previous result. | The next launch waits for every rank to finish inspection. |
| Multi-rank CI reliability | An unchanged commit failed, then passed on retry. | CI has not run on this change. |
| Repeated replay test on an eight-GPU B200 node, interleaved with the base | The mismatch appeared in 12 of 20 runs. | The mismatch appeared in 0 of 20 runs. |
| Test time for the same runs | Median of 38 seconds. | Median of 38 seconds. |

The [failed CI job](https://github.com/NVIDIA/Megatron-LM/actions/runs/40437779234/job/122437658256) passed on an unchanged-head retry. A CPU reconstruction in which a peer publishes the next balanced histogram reproduces the failure fingerprint: 7/16 elements differ, with a maximum absolute difference of 14 at `(1, 3)`. The B200 runs also fit the ordering hypothesis. Every mismatch was in the histogram at `replay=2`, the last replay before ranks launch a different input, and none occurred at EP1, where a rank has no peers. This does not prove that this race caused the recorded CI failure.

## Validation

The existing EP1 CUDA graph-replay cases passed for int32 and int64. Canonical Black, isort, Pylint, and Ruff checks passed. Optional mypy was unavailable.

The CPU reconstruction is not a multi-GPU runtime reproduction. The B200 runs covered EP1, EP2, EP4, and EP8 for int32 and int64, with this branch merged into main. That environment used PyTorch 2.13.0+cu130 and the pinned Transformer Engine revision. It was not the CI image. The determinism kernel directory had the same failures on this branch and on main. The H100 CI bucket was not run. Each replay gains one synchronization barrier.
