# fix(core): compare major version in experimental EOL check

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8309) · state: open · merged: False

## Original PR description

`experimental_fn` / `experimental_cls` decide whether an experimental API has reached its end of life by comparing only the *minor* component of the version:

```python
PkgVersion(introduced_with_version).minor + max_lifetime < PkgVersion(mcore_version).minor
```

Once mcore crosses a major boundary and the minor version resets to 0, this comparison can never fire again, so expired experimental APIs silently stop being flagged. For example an API introduced at `0.19.0` with a lifetime of 1 minor version is no longer reported once the package version becomes `1.0.0` (`19 + 1 < 0` is false forever).

This PR compares the `(major, minor)` pair instead, which keeps the check working across major bumps, and adds regression tests for the major-boundary case.

Local results: `pytest tests/unit_tests/test_utils.py -k "eol or experimental"` — the new tests fail on current main (no exception raised for the major-bump case) and pass with the fix; the rest of `test_utils.py` is unaffected.

Note: I drafted this change with AI assistance; I reviewed and tested it myself.
