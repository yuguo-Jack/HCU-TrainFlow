# What does this PR do?

Add an opt-in prepared-BinIdx Energon data provider to heterogeneous MIMO
pretraining. `examples/mimo/pretrain_mimo.py` currently accepts only mock data;
`--dataset-provider energon` connects prepared text/image records to its language
and encoder grids while retaining the mock default and existing supervised
entrypoints.

The shared data layer interprets prepared token IDs and lazy image auxiliaries,
and delegates source sampling, streaming packing and replay to Energon. The MIMO
adapter expands structural image slots, preserves existing shifted text labels
and loss masks, forms packed-attention metadata, and aligns each encoder rank
with its ordered language-data lanes. Language lanes own loader checkpoints;
encoder lanes restore the corresponding language states. Mock and real batches
reuse one encoder-input collation helper.

The initial target is RADIO dynamic resolution, patch16, pixel shuffle, no
emitted class tokens, micro-batch size1 and language TP/PP/CP1. Image decoding
occurs on encoder ranks. This path does not render conversations or tokenize
text on the fly.

## Scope and dependency

This main-target draft includes three review units: the encoder geometry
prerequisite from #8717, a provisional shared prepared-data layer, and the
six-file MIMO bridge. The full current diff is 21 files; it is not limited to
the bridge commit. The geometry prerequisite can be dropped from this diff
after #8717 merges.

The shared-data snapshot currently includes optional mask, raw-JSONL and resize
machinery beyond the minimal BinIdx bridge. It needs narrowing and dependency
cleanup before merge. No new model architecture, loss function or checkpoint
engine is introduced by the bridge itself.

## Open integration work

This draft is for code and scope review. The complete provider is not yet
qualified against a compatible public dependency/runtime.

- Resolve the shared layer's unconditional imports of a token-mask module not
  provided by the target native Energon API. Keep optional BinIdx mask support
  with its consumer and settle a reproducible public dependency. The current
  lock selects Energon 7.4.1 and does not establish compatibility with the
  required streaming APIs.
- Reject encoder DDP overlap for this initial data mode: valid image-free packs
  can omit encoder backward participation and leave reductions unissued.
  Language-model overlap remains separate.
- Stop fixed-configuration loading from implicitly enabling stricter DP-resize
  validation. For example, two language lanes, two workers per lane and GBS2
  currently fail the extra divisibility check. Adapt or exclude the stale
  resize helper outside this fixed-configuration scope.
- Update the shared documentation to included consumers, files and actual
  tests. Make the per-source packing contract explicit when custom packing
  groups are configured.
- Qualify both-role prepared-data loading and real checkpoint replay with
  positive workers. Image-boundary supervision refinements and expanded
  encoder/parallel configurations remain separate follow-up work.
