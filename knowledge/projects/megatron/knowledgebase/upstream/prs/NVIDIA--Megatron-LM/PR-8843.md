# What does this PR do?

Computes `MultimodalRotaryEmbedding`'s RoPE angles with an elementwise product instead of a K = 1 matmul, so they stay exact when TF32 is allowed for fp32 matmuls. Details in the issue #8842.

```python
# before
inv_freq_expanded = self.inv_freq[None, None, :, None].expand(3, seq.shape[1], -1, 1)
seq_expanded = seq[:, :, None, :].float()
freqs = (inv_freq_expanded @ seq_expanded).transpose(2, 3)
# after
freqs = seq[..., None].float() * self.inv_freq
```

Elementwise computation in the latter means we reach torch kernels, and not cublas. Output is bit identical to the current code with TF32 off. It is also faster (not the aim of this PR): one forward on B300 takes 42.4 µs instead of 52.6 µs at 32,768 positions, and 92.1 µs instead of 182.9 µs at 131,072.

New test `test_angles_exact_when_tf32_allowed`: it runs the module with TF32 allowed and not allowed, compares with an fp64 reference, and requires both outputs to be identical.

Test results:
| `TORCH_ALLOW_TF32_CUBLAS_OVERRIDE` | this PR | current `main` |
|---|---|---|
| 1 (container default) | 13 passed | new test fails at 4,096 / 16,384 / 21,845; the other 10 pass |
| 0 | 13 passed | same 3 failures |

Only measured on B300. On GPUs where cuBLAS picks the exact kernel for these shapes, the new test also passes on current `main`.
