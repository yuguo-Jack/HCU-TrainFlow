# ci: Skip empty experimental unit-test launches

# What does this PR do?

Skip the experimental test launch when a full-mode bucket has no experimental tests.

## Motivation

The full-mode runner starts eight new pytest workers for the experimental phase even when every test is deselected. Those jobs spend runner time on startup and collection without executing a test.

In the sampled [ops](https://github.com/NVIDIA/Megatron-LM/actions/runs/40615303300/job/122578206721), [resharding](https://github.com/NVIDIA/Megatron-LM/actions/runs/40615303300/job/122578207032), and [post-training](https://github.com/NVIDIA/Megatron-LM/actions/runs/40615303300/job/122578207303) jobs, that empty phase took 46 to 47 seconds from launch to the final deselection summary.

## Change

Reuse the actual production collection and skip the second launch only when every expected rank explicitly reports no experimental items. Missing, invalid, or positive reports retain the launch. Each repeat uses fresh reports.

Review `run_full_tests` first, then `experimental_collection.py`. The remaining changes register the hooks and cover the skip and fallback paths.

## Results

| Evidence | Before | After |
| --- | --- | --- |
| Runner behavior for a confirmed-empty phase, covered by focused checks | Start eight experimental pytest workers. | Skip that launch. |
| H100 elapsed time for the empty phase | 46 to 47 seconds in the linked baseline jobs, with a median of 46.7 seconds. | Not yet measured on H100. |
| `run_ci_test.sh` on a small bucket with an empty experimental phase, eight B200 GPUs, median of three interleaved runs | 68 seconds. | 38 seconds. |

The verified improvement is removal of the redundant launch, which saved about 30 seconds per bucket run on B200. The H100 baseline timing shows the work this targets there, but it is not a measured H100 saving or a full-pipeline speedup.

## Validation

Behavioral tests passed for inherited and late markers, rank union, invalid reports, failed collection or writes, and repeat isolation. Actual `torchrun --collect-only` checks through the unit conftest distinguished empty and nonempty experimental phases. Canonical Black, isort, Pylint, and Ruff checks passed. Optional mypy was unavailable.

The focused CPU suite was also rerun with Python 3.12 and the repository-pinned `pytest==9.1.1`. It exercises real pytest subprocesses and the real shell runner with a CPU substitute for torchrun.

The real runner also ran on eight B200 GPUs, with this branch merged into main. A bucket with no experimental tests skipped the second launch, and a bucket with experimental tests kept it. That environment used PyTorch 2.13.0+cu130 and the pinned Transformer Engine revision. It was not the CI image. H100 and GB200 CI were not run. This relies on the current contract that `--experimental` changes the runtime fixture rather than which items are collected.
