# Use the model's amax group in the combined 1F1B delayed FP8 context

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8739) · state: closed · merged: False

## Original PR description

Depends on #8028 and #8035 (which contains #8034 up to its last, test-only commit). Please review the diff from the merge of their heads: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/23af324e07...yx/pstate-g19-combined-1f1b-fp8-group). In that merge, the process-group allowlist drops the `forward_step_calc_loss` read that #8028 removes, and its total of 195 matches its entries.

**Why.** With delayed scaling, `combined_forward_backward_step`, the EP-overlap 1F1B schedule, wraps each combined forward/backward chunk in one FP8 autocast, and the layers open no context of their own. That autocast came from `get_fp8_context(config)`, which reduces amaxes over the global `parallel_state` amax group (TP x DP x CP, or TP x CP with `tp_only_amax_red`), or over no group without a global grid. A model built on its own collection therefore reduced its amaxes over the global grid's ranks under this schedule, while its layers use the model's group under every other recipe and schedule. #8035 moved the other FP8 and FP4 owners to their collections, and this outer context was the one left.

**What.** `combined_forward_backward_step` passes `get_fp8_context` the `pg_collection` of the forward model chunk, or of the backward chunk in a backward-only step. It finds the collection through the DDP and `Float16Module` wrappers with `get_attr_wrapped_model`.

**Tests.** `tests/unit_tests/a2a_overlap/test_schedule_quantization_context.py` adds:
- mock tests: the outer context gets the forward chunk's collection, bare and wrapped, and the backward chunk's collection in a backward-only step; per-layer recipes open no outer context;
- distributed tests with the real `get_fp8_context`: with the global amax accessor patched to raise and same-rank copies of the groups, the recorded group is the model's; on a custom grid it spans the model's TP x DP x CP ranks.

The test helper passes `cp_group_size` and `is_last_stage`, which #8028 makes required.

In the integration run (main 77391e71cc with all #6307 PRs and the main-based gap fixes merged, against main), `test_schedule_quantization_context.py` passes 14 tests on 4 GPUs vs 5 on main. The 9 tests this PR adds pass, and no test in the file fails on either side, so this PR's test file shows no regressions against main. Across the full unit-test suite in that run, on 4 and 8 GPUs, no test that passes on main fails, apart from one fused-MHC kernel check (`test_fused_mhc_kernels.py`) that failed on one rank and has failed the same way on main. Before the sync, the branch also ran on 4 CPU gloo ranks with no regressions: the 4 new mock tests pass, and the distributed tests skip without Transformer Engine. No test runs a real `GPTModel` with delayed FP8 through the combined 1F1B schedule. The changed line runs only with stand-in model chunks.

**Compatibility.**
- On the standard grid the model's collection holds the same group objects, so the reduction and the numerics are unchanged.
- Only delayed FP8 with the combined 1F1B schedule is affected. If no wrapper level of a chunk has a `pg_collection`, `get_attr_wrapped_model` raises `RuntimeError`. In this repository only `GPTModel` builds schedule plans, and it always sets one. A collection without `tp_dp_cp` (or `tp_cp` with `tp_only_amax_red`) raises `ValueError`, as `TransformerBlock` and the per-layer contexts already do with #8034 and #8035.
- If interleaved chunks held different collections, the forward chunk's group would be used. In standard training all chunks share one collection.
- #5761, already on main, also edits `combined_forward_backward_step`. This PR applies on top of it.
- Needs `determinism-exempt` only because the base contains the kernel-file changes of #8034 and #8035. This PR's own diff touches no kernel file.
