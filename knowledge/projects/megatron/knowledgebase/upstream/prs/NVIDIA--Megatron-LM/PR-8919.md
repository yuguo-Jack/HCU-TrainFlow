# What does this PR do?

Converges the layer-wise distributed optimizer (Muon), its sibling `DistributedOptimizer` and Muon's QKV handling with the dev branch, so that main and dev carry one implementation of this area. The companion PR against dev applies the same code there: https://github.com/NVIDIA/Megatron-LM/pull/8920.

Production code: +1386 / −603 across 24 files (tests: +1531 / −234).

## Changes

| Commit | Change |
| --- | --- |
| LayerWise: explicit param layout strategy with a compact layout | `DistributedDataParallelConfig.layer_wise_param_layout` / `--layer-wise-param-layout {padded,compact}`. `padded` stays the default with unchanged numerics. `compact` (from dev) keeps the Muon matrices in unpadded, unsharded buffers, all-reduces their gradients and has one owner per matrix gather it whole, which avoids the `dp_size × max(shard)` padding. Expert non-Muon params get an expert-DP sibling `DistributedOptimizer`. Also fixes experts without an owner when dp_cp = 1 and expt_dp > 1, and a crash when rank 0 owns no parameter. |
| LayerWise: whole-param FP8 gathers and gather publication | Compact layout: MXFP8 and blockwise FP8 params are gathered as BF16 staged from the owners' FP32 masters and requantized on every rank. `force_sync` and `free_overlap_buffers` publish in-flight uneven gathers. |
| Muon: QKV layout metadata with opt-in per-head and MLA splits | `QKVLayout` metadata on the fused projections; `--muon-split-qkv-per-head` and `--muon-split-mla-qkv`, both off by default. |
| Optimizer checkpoint fixes for the layer-wise chain | Reject `--ckpt-format torch` for the layer-wise optimizer: the torch format does not save the sibling `DistributedOptimizer` (main raised at the first save). Keep the `HybridDeviceOptimizer` step across a DP-reshardable resume. Fix an undefined name in `split_state_dict_if_needed` and a call to a missing `parallel_state` helper. |
| ChainedOptimizer: combine grad norms on the device | float64 on the device; bitwise identical to the previous host-side combination. |
| LayerWise: write whole-param FP8 params as Q(bf16(master)) once | Owners no longer quantize params that the gather requantizes; params outside any gather take the same Q(bf16(master)). |
| QK-clip: find attention modules of HybridModel and MTP stacks | Main raised `AttributeError: 'MambaLayer' object has no attribute 'self_attention'`. |
| DDP: optional torch_memory_saver buffers without CPU backup | `--disable-grad-buffers-cpu-backup` / `--disable-param-buffers-cpu-backup` (from dev). |
| LayerWise: drop the legacy layout and the boolean layout flags | Removes the legacy layout (`--no-use-layer-wise-param-layout`) and the boolean `use_layer_wise_param_layout` spelling. The layer-wise optimizer always chains a sibling `DistributedOptimizer` and rejects chunks wrapped without a LayerWise layout. Docs in `docs/user-guide/features/dist_optimizer.md`. |
| DDP: partition bucket groups by owner and DDP config | `partition_buckets()` built every fp8 bucket group with the config of the last buffer it had looped over, so with the compact layout and `reduce_scatter_with_fp32_accumulation` LayerWise and DistOpt buckets could get each other's collectives. Buffers are now partitioned by optimizer ownership and DDP config first. Models without the layer-wise optimizer keep the same bucket groups. |

## Behavior changes for main users

- The legacy layout (`--no-use-layer-wise-param-layout`) is removed. On H100 it was neither faster nor smaller than padded/compact; its largest rank holds the whole embedding and output-layer Adam state. Optimizer state saved with it, and LayerWise checkpoints written before the sibling `DistributedOptimizer` was added (May 2026), cannot be loaded: start from such checkpoints with `--no-load-optim`.
- `--ckpt-format torch` is rejected for the layer-wise optimizer; use `torch_dist`.
- With `--fp8-param-gather`, the padded layout accepts only MXFP8 with `--reuse-grad-buf-for-mxfp8-param-ag`. Use `--layer-wise-param-layout compact` for blockwise FP8 params.
- Default (padded) training is numerically unchanged.

## Testing

- 8×H100 and 8×B300 under `--deterministic-mode`, comparing loss and grad norm at every step:
  - padded, padded with overlap, MoE, MoE with bias, Lion and PP2 with tied embeddings are bitwise identical to the main baseline;
  - the legacy removal, bucket-group partition and frozen-stage commits are bitwise neutral on padded and compact (dense, overlap, MoE, MoE with bias, B300 MXFP8 with and without overlap); the last commit only adds a check when the optimizer is built;
  - `torch_dist` checkpoints written by the main baseline resume bitwise, and padded and compact checkpoints load across layouts.
- Unit tests: layout resolution and compact ownership (CPU), compact layout end to end with a bit-exact replay registered in the determinism manifest, whole-param FP8 requantize replay, QKV / MLA splits, bucket-group partition regression, fully frozen stage, padded FP8 check; existing LayerWise, distributed checkpointing, DDP, emerging-optimizer and FP8 suites updated for the removed layout.
- Functional tests: `gpt3_moe_mcore_te_ep8_resume_torch_dist_dist_muon` and its `_1node` variant ran the removed legacy layout and now pin `--layer-wise-param-layout compact`. Their golden values were recorded with the legacy layout and need a refresh. GitHub CI does not run these cases: the H100 recipe is marked broken, the GB200 and GB300 cases run in the internal `mr` scope and the `_1node` case is temporarily disabled.
