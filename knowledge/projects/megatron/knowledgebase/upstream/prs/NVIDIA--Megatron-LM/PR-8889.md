# Pass the model's process groups to optimizer grad-norm, clip_qk and expert naming

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8889) · state: open · merged: False

## Original PR description

This PR moves the optimizer and its helpers off the global parallel state. Gradient-norm filtering, `clip_qk` and expert parameter naming now use the process groups of the model being optimized, so a model on its own grid gets the same result as on the standard grid. Callers of the optimizer builders and the FSDP-DTensor checkpoint helpers can pass that layout; optimizer maintainers get one place where these groups are set. It consolidates four drafts unchanged. Each member is one commit, so review commit by commit. It depends on no other unit or open PR. It is the first unit in the stack, directly above #7487, #6259 and #6293. Part of #6307.

## Members

- #8042: Filter optimizer grad-norm duplicates by the collection's TP and GTP groups. A new `set_duplicate_filter_groups(optimizer, pg_collection)` sets the TP, expert-TP and GTP groups for the grad-norm and zero-count duplicate filters, and those filters stop falling back to the global rank when a group is `None`. This fixes an under-counted gradient norm, and so too-weak clipping, when the model's collection turns TP or GTP off next to a global grid that has them on.
- #8043: Let clip_qk reduce over the model's data-parallel group. `clip_qk` takes a keyword-only `dp_cp_group`, and `train_step` passes the model's `dp_cp_gtp_remat` group, or `dp_cp` when that is unset. Without a group, `clip_qk` keeps the global GTP-inclusive DP x CP default.
- #8045: Name FSDP-DTensor experts by the model's expert-parallel layout. The FSDP-DTensor checkpoint helpers and `get_global_unique_param_name` take keyword-only integer `ep_rank` and `ep_size`, read from the model's collection by `get_ep_rank_and_size`. The distributed optimizer's parameter names, the param-group dump and the training loop's FSDP-DTensor preprocessing pass the model's layout.
- #8731: Name the MFSDP v2 optimizer's experts by the model's EP layout. `FullyShardedOptimizer` passes the EP rank and size from the model's collection, found by #8045's `get_model_ep_rank_and_size` walking the wrapper chain, when the model has experts. Dense models skip the lookup.

## Behavior changes for callers

- A collection passed to the optimizer builders must set `tp` (`None` when TP is off). Otherwise `set_duplicate_filter_groups` raises `ValueError`.
- In that collection, `tp`, `expt_tp`, `gtp_remat` or `expt_gtp_remat` set to `None` now means the axis is off for the duplicate filters, not "use the global group". An unset `expt_tp` defaults to `tp`.
- An unset `gtp_remat` or `expt_gtp_remat` resolves through `resolve_gtp_remat_group`, as the model's layers resolve it, instead of `getattr(..., "gtp_remat", None)`. When the field is unset, these two can return different groups.
- Passing only one of `ep_rank` and `ep_size` to the FSDP-DTensor helpers raises `ValueError`. Passing neither keeps the global fallback.
- Expert names on the standard grid do not change, so checkpoints from the standard grid load unchanged. Optimizer state saved on a custom EP grid before this change uses global-layout names and will not match.
