# [Inference][MLA] Support fused TP communication in MLA models, fusing where the next input norm allows

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8704) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Lets GPT models with MLA layers build and run with `inference_fuse_tp_communication=True`. Until now they raised `AttributeError` during construction at every TP size. The fused kernel now runs at each MLA layer's attention output. At the MLA attention input, the layer applies its own norm, and the previous `linear_fc2` only reduce-scatters and adds the residual.

**Depends on #8561, which must merge first.** This branch is stacked on it, so the diff includes #8561's commits until #8561 merges. This PR relies on #8561's change that makes `InferenceRowParallelLinear` add the residual on every path. Without it, the row-parallel layer adds the residual only inside the fused NVLS kernel. This PR would then turn today's build-time crash into silently dropped residuals: on the TP=1, NCCL and batch-invariant paths, and on the NVLS path before every MLA layer, where `linear_fc2` now takes the plain reduce-scatter.

## The bug

A `GPTModel` with MLA attention (inference layer spec, `transformer_impl="inference_optimized"`) and `inference_fuse_tp_communication=True` fails in `TransformerBlock.__init__`, including at TP=1:

```
transformer_block.py: _setup_fused_tp_communication
transformer_layer.py: get_qkv_layer_norm_weights
    return self.self_attention.linear_qkv.layer_norm_weight.data
AttributeError: 'MLASelfAttention' object has no attribute 'linear_qkv'
```

`configure_fused_tp_inference` fails the same way when it wires `linear_qkv`. `TransformerConfig` validation rejects fused TP communication for MoE but accepts it for MLA. A configuration matrix on H100 hit this on three MLA rows: one TP=2 and two TP=1.

## Root cause and fix

The fused reduce-scatter + add + rms-norm + all-gather in a row-parallel layer applies the input norm of the column-parallel layer that follows it, and leaves the normalized, all-gathered result in symmetric memory. `TransformerBlock` assumes that every layer's attention input is such a layer: a `linear_qkv` that applies the input norm itself. In the inference MLA spec it is not. `input_layernorm` is a separate `TENorm`, and the duplicated down projections take the normalized *sequence-parallel shard*. With `q_lora_rank` set, MLA then all-gathers only the low-rank query and KV latents, which nothing upstream can produce.

Rejecting MLA at config time is not necessary. Inside an MLA layer, `linear_proj` feeds the MLP's `linear_fc1` (an `InferenceLayerNormColumnParallelLinear`), exactly as in a GPT layer, so that boundary fuses. Only the boundary into the next MLA layer cannot. So (`transformer_layer.py`):

- **An explicit fusion contract.** `_get_fusable_linear_qkv()` returns the attention's `linear_qkv` only if it is an `InferenceLayerNormColumnParallelLinear`, otherwise `None`. That class, in inference, applies the same RMSNorm as the fused kernel (`layer_norm_weight`, `layernorm_epsilon`), and reads its input from symmetric memory when its `fused_tp_handoff` (#8561) says the kernel ran. Any other attention input applies its own norm: MLA, which has no `linear_qkv`, or a `TELayerNormColumnParallelLinear` in a custom spec.
- `get_qkv_layer_norm_weights()` returns `None` for such layers, and `configure_fused_tp_inference()` sets the handoff only on a fusable `linear_qkv`.
- **No placeholder norm.** A `linear_fc2` that gets no norm weights now gets `None`. This is the case before an MLA layer and in the last layer. On the NVLS path, `linear_fc2` then runs the plain NVLS reduce-scatter and adds the residual (#8561's path). Before, it ran the fused kernel with uninitialized `torch.empty_like` norm weights, and nothing read the all-gathered result. The reduce-scatter and residual add are unchanged. The unused rms-norm and hidden-size multicast all-gather are gone, once per MLA layer and once at the last layer of every fused-TP model. In the dynamic-batching MLA path, the query up-projection's all-gather now follows a reduce-scatter rather than an unread all-gather.

`TransformerBlock` is unchanged. GPT layers are wired as before, except for the last layer's `linear_fc2`. No configuration is newly rejected. No kernel changed.

**MLA without `q_lora_rank`.** With `q_lora_rank=None` and without `qk_layernorm`, `linear_q_proj` is an `InferenceColumnParallelLinear`. It all-gathers the normalized hidden state, which is the tensor the fused kernel leaves in symmetric memory. This PR does not fuse that case: the fusion would not be clean.
- The KV down projection still needs the normalized local shard, so `input_layernorm` would still run, and the query path would get the same norm from a different kernel.
- The fused kernel's norm would have to match `input_layernorm`, a `TENorm` whose type and zero-centered gamma come from the config.
- `InferenceColumnParallelLinear` would need its own handoff, read in each of MLA's query paths.
- The only saving is one all-gather per layer. With `qk_layernorm`, `linear_q_proj` is an `InferenceLayerNormColumnParallelLinear` that applies its own query norm before the all-gather, so the fused output cannot serve it.

The new tests cover this case on the unfused path.

## Tests

`tests/unit_tests/transformer/test_mla_fused_tp_communication.py` builds small inference-optimized blocks with the flag on and off and identical weights. Norm gains are perturbed away from 1, and there is no final norm. It covers four stacks:
- DeepSeek-V3-style MLA (`q_lora_rank`, `qk_layernorm=True`);
- MLA without `q_lora_rank` or `qk_layernorm`;
- GPT only;
- mixed GPT/MLA/GPT.

- `test_block_wiring[stack-tp1|tp2]`: the block builds.
  - Each `linear_proj` is wired to its own layer's `linear_fc1`.
  - Each GPT `linear_qkv` takes the previous `linear_fc2`'s handoff, and each MLA layer reports no QKV norm.
  - A `linear_fc2` gets norm weights only if a GPT layer follows; otherwise it gets `None`.
- `test_fused_matches_unfused[stack-tp1|tp2_nccl|tp2_nvls]`: the flag-on output matches flag-off (atol/rtol 2e-2), on every path of the row-parallel layer.
  - With NVLS (2 GPUs with multicast; skips otherwise), the fused kernel runs in every `linear_proj` and in each `linear_fc2` that a GPT layer follows. Exactly the consumers it feeds skip their own norm.
  - Without #8561, the TP=1 and NCCL cases would drop the residual, so they also pin the dependency.
- The NVLS cases still send MLA's two up-projection all-gathers through NCCL. Without latent caching they write the shared symmetric buffer back to back without `barrier_before`, which `multimem_all_gather` requires for consecutive all-gathers. That race affects MLA at TP>1 with or without this flag. [#8709](https://github.com/NVIDIA/Megatron-LM/pull/8709) (n12) fixes it by making inference all-gathers barrier by default. Once that lands, the override can go, and the test will also cover the NVLS up-projection all-gathers next to the fused kernel.
- `tests/unit_tests/tensor_parallel/test_inference_layers.py` (#8561) now expects the last layer's `linear_fc2` not to run the fused kernel.

**Dynamic engine.** This PR adds no dynamic-engine test.
- Dynamic-batching MLA needs the latent cache, which crashes on `main` at TP>1 with sequence parallelism, in `get_query_key_value_tensors` (`torch.cat` of `[s/TP]` latents with `[s]` RoPE keys). The fix for that is separate (the MLA latent-cache sequence-parallel fix). Inference-optimized layers require sequence parallelism at TP>1, and at TP=1 the fused kernel never runs, so a dynamic test of the fused kernel in MLA has to wait for that fix.
- A configuration matrix on H100 ran MLA with fused TP at TP=1 through the dynamic engine with CUDA graphs, on a tree with this PR's first commit, #8561 and the other open fixes (two rows, both pass).
- With this PR, the NVLS path of a dynamic MLA layer no longer runs a placeholder-weight fused kernel, and its query all-gather follows a reduce-scatter.

On H100 in the CI image (dfw 20990094 and 20992100), the first commit's three tests failed on `main` with the `AttributeError` above and passed with this PR. `test_fused_matches_unfused` ran with NVLS multicast and did not skip. Neighbor tests pass:
- `tests/unit_tests/transformer/test_transformer_block.py::TestParallelTransformerBlock`: 11 tests.
- `tests/unit_tests/transformer/test_transformer_layer.py::TestParallelTransformerLayer`: 20 tests on 8 GPUs. Launched with one process in the first run, its 6 tests that need 8 GPUs failed, on `main` as well.

With the review changes (dfw 21004395): all 20 cases pass with this PR and 18 fail on `main`; the neighbors pass (17, 11 and 20 cases). The 57-task inference-vs-training matrix passes on integration trees of current `main` with every open fix (dfw 21004395, 21007036). On CPU: formatting, lint, the kernel determinism coverage check, test collection, #8561's block-wiring test, and a fake-layer wiring check of GPT, MLA, mixed and `TELayerNormColumnParallelLinear` stacks.
