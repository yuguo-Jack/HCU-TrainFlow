# What does this PR do?
<!-- Add a one line overview of what this PR aims to accomplish. -->

Supersedes PR #6840 (jingqiny-99's AttnRes PR against dev, head 64fbfe3c2), opened as a fresh PR on dev 7b66fcc08 because dev changed too much under the original branch to rebase it. The code is the version validated on the Kimi-K3 development branch (yuzhongw/kimi_k3_dev_dev), which bundles the follow-ups that lived there as separate commits: fine-grained activation offloading for AttnRes (jingqiny-99#2), attention residuals with variable sequence lengths under non-interleaved PP, and the output RMSNorm fusion into the FLA aggregation with 'attn_res' selective recompute.

Port (2026-10-21, dev ff4fbc9f3): re-implemented on dev after the main-to-dev sync (#7960) rather than rebased, because dev rewrote HybridStack (per-layer configs, mHC / shortcut blocks, layers/ split) and restructured the TransformerLayer hooks.

Adaptations to dev:
- AttnResHybridLayer lives in megatron/core/models/hybrid/layers/ hybrid_attention_residual.py (re-exported from hybrid_block) and is applied at construction next to dev's mHC wrapper with the per-layer config copy; HybridStack regains vp_stage, the AttnRes branch sits inside dev's layer loop between prepare_layer/finalize_layer and honours the once-per-microbatch validation gate; AttnRes rejects mHC, wide residuals, shortcut MoE blocks and an active per-layer CP layout manager.
- TransformerLayer: the delta path is rebuilt on dev's _run_input_layernorm / _pre_mlp_layernorm_and_residual / _apply_mlp_bda_step hooks (input_is_normalized, _return_layer_delta and mlp_norm_input are keyword-only extras); AttnResTransformerLayer follows the (output, norm manager, residual) triple and resets attn_norm_manager like dev's BDA step.
- MTP: attn_res_sources is a field of MultiTokenPredictionInputs, threaded through prepare_cp_layout and the nested stack; the per-source layout conversion mirrors mhc_multistream and is dormant until AttnRes allows the per-layer CP layout manager. The depth-source tuple is threaded into _proj_and_transformer_layer only when attention residuals are enabled, so dev's test that monkeypatches that helper with the pre-AttnRes signature (test_forward_propagates_rolled_padding_mask) keeps passing.
- schedules: attn_res_source_cache_reset now runs at every schedule entry (it was nested under the paged-stash branch on the old stack), next to dev's _get_pipeline_hidden_size.
- The KDA SiLU override of the original commit is redundant on dev (_GDNBase pins SiLU) and is dropped.
- Tests build HybridStack through layer_config_list; the padding-mask / SBHD plumbing of the original lives in dev already.

Rebase (2026-11-03, dev 7b66fcc08): hybrid_block.py keeps dev's single #7054 KDA dispatch branch (is_mtp_layer= already there); multi_token_prediction.py keeps dev's mhc_learned_output_contract-gated hc_head parameters (#7521) and adds the AttnRes final head after them, and dispatches the hybrid MTP inner stack on dev's is_hybrid_mtp flag (#7555); transformer_config.py: the recompute_modules choices are the union of dev's dsa_* entries and attn_res, and _validate_attention_residuals() runs right after dev's pinned offload buffer validation (#7961); transformer_layer.py adds only AttnResTransformerLayer (dev's #8424 moved HyperConnectionTransformerLayer out of this file); arguments.py adds only the "hybrid_layer_pattern" exclude entry; test_fine_grained_activation_offloading.py merges dev's buffer_size_gib parametrization (#7961) with the AttnRes rows and iterates dev's _offload_summary_groups(); training/models/gpt.py and hybrid.py mirror own-dataclass fields into the embedded transformer config when it declares the same attribute, so dev's test_rotary_fields_reach_an_mla_transformer_config (#8458) passes next to test_own_field_not_shadowed_by_transformer_field.

Standalone (2026-11-03): this PR depends on no other Kimi-K3 PR. Relative to the development branch it leaves out the strict_runtime_validation pass-through of the AttnRes wrapper and AttnResTransformerLayer (needs PR #7202; follows once both are in) and two NoPE-MLA hunks that belong to PR #6877's use_rope path (functionally identical to that PR's code).
