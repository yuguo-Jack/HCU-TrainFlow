# [Inference][Hybrid] Support fused TP communication in hybrid models

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8965) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Lets hybrid models (`HybridStack`, `HybridModel`) run with `inference_fuse_tp_communication=True`. Until now a `HybridStack` built with the flag raised `AttributeError` at its first inference forward, at every TP size. Each layer now hands its residual add only to an output projection that can add it. The stack links its layers for the fused reduce-scatter + add + rms-norm + all-gather as `TransformerBlock` does. The two entry points that rejected the flag for `HybridModel` now accept it.

**Depends on #8561 and #8704, which must merge first.** This branch is stacked on #8704 (itself stacked on #8561), so the diff includes their commits until they merge. Both change the functions this PR generalizes (`configure_fused_tp_inference`, the QKV/FC2 wiring helpers, `_using_fused_tp_inference`). This PR relies on #8561's `InferenceRowParallelLinear`, which adds a handed-over residual on every path and records in a `FusedTPHandoff` whether the fused kernel ran. Without it, a hybrid layer whose output projection does not fuse (the last layer, TP=1, NCCL) would drop its residual instead of crashing.

## The bug

A `HybridStack` built from `hybrid_inference_stack_spec` with the flag on, e.g. pattern `*-*-`, fails in the first attention layer under `InferenceMode` (H100, TP=1 and TP=2):

```
transformer_layer.py: _run_mlp
transformer_layer.py: _set_fc2_residual
    self.mlp.linear_fc2._set_residual(residual)
AttributeError: 'IdentityOp' object has no attribute 'linear_fc2'
```

Hybrid attention-only layers have `mlp = IdentityOp`, and MLP-only layers (`MLPLayer`) have `self_attention = IdentityOp`. `TransformerLayer` still handed the residual to `self_attention.linear_proj` and `mlp.linear_fc2` whenever the flag was on. A GDN layer, whose attention projects through `out_proj`, fails the same way on `linear_proj`; KDA has the same layout. `HybridStack` also never set up fused TP between its layers.

Reach: `TransformerConfig` accepts the flag for these models, but `megatron/training/argument_utils.py` (`hybrid_config_from_args`, used by `pretrain_hybrid.py` and `megatron/inference/utils.py`) and the repo-root `hybrid_builders.py` (`pretrain_hybrid.py`, `train_rl.py`) reject it for `HybridModel`. So today only direct Core API construction of a `HybridStack` or `HybridModel` reaches the crash.

## Root cause and fix

The fused-TP path assumed that every `TransformerLayer` has both sublayers, with `linear_qkv`/`linear_proj` and `linear_fc1`/`linear_fc2`. Fused TP does not need that assumption. Each residual sublayer either has or lacks two things: an input linear that applies its norm and all-gather (`InferenceLayerNormColumnParallelLinear`), and an output projection that can add the residual (`InferenceRowParallelLinear`). The layers now decide per sublayer, within the API of main, #8561 and #8704 (`transformer_layer.py`):

- **Per-sublayer linears.** `_get_fused_tp_linears()` returns `(input linear or None, output projection or None)` for self-attention and the MLP, in order, and skips an `IdentityOp` sublayer. It generalizes #8704's `_get_fusable_linear_qkv` to all four linears.
- **Residual hand-over.** A sublayer hands over its residual add only if it has such an output projection (`_using_fused_tp_inference(sublayer)`, from a set computed at construction, so the hot path is a set lookup). Otherwise it keeps its bias-dropout-add. This covers `IdentityOp` sublayers and GDN/KDA attention.
- **Same API, generalized.** `configure_fused_tp_inference(qkv_fused_tp_handoff, fc2_next_layer_norm_weights)` chains the sublayers that are present:
  - The previous layer's handoff goes to the layer's first input linear: `linear_qkv`, or `linear_fc1` in an MLP-only layer.
  - Attention's `linear_proj` fuses the MLP's norm.
  - The last output projection fuses the next layer's norm: `linear_fc2`, or `linear_proj` in an attention-only layer.
  - A sublayer without an output projection breaks the chain.

  `get_qkv_layer_norm_weights()` and `get_fc2_fused_tp_handoff()` keep their names and give the stack the first input linear's norm and the last output projection's handoff. `get_qkv_layer_norm_weights()` and `get_mlp_layer_norm_weights()` return `None` instead of raising for a layer without such a linear. They remain the only places that read `layer_norm_weight.data`, so #8712 (which replaces those reads with module references) covers the hybrid links too.
- **One wiring loop.** The block's wiring loop moves into `configure_fused_tp_inference_for_layers(layers)`, which `TransformerBlock._setup_fused_tp_communication` and now `HybridStack` call. It keeps #8561's rule: two layers are linked only if both are graphed alike. It links only layers that implement `configure_fused_tp_inference`. A `MambaLayer` doesn't, because it applies its own input norm and adds its own residual, so no fusion crosses it. A layer kind can join later by implementing the three methods.
- **Context parallelism.** `HybridStack` links each run of layers that share a context-parallel layout. A layout conversion between two layers would leave a fused all-gather's output in the old layout.
- **Entry points.** The `HybridModel` rejections in `megatron/training/argument_utils.py` and `hybrid_builders.py` are removed.

GPT and MLA blocks are wired exactly as with #8704. No configuration is newly rejected, and no kernel changed. Mamba, GDN, KDA and MLA/DSA inputs keep the unfused path. It is correct, but not maximal, for Mamba-heavy patterns. A stack cannot mix `*` with MLA layers, so the new cross-layer MLA link is MLA's `linear_proj` into the next MLP layer's `linear_fc1`.

## Tests

`tests/unit_tests/ssm/test_hybrid_fused_tp_communication.py` (1 and 2 GPUs; H100):
- `TestHybridFusedTPCommunication` builds small inference-optimized `HybridStack`s for `*-*-`, `**--`, `M*-M*-` (Mamba), `G*-G-` (GDN) and `+-+-` (MLA):
  - `test_stack_wiring[pattern-tp1|tp2]`: every output projection that can fuse is linked to the next layer's input linear, and only there. Mamba and GDN `in_proj`/`out_proj`, MLA inputs and the last output are not linked.
  - `test_fused_matches_unfused[pattern-tp1|tp2_nccl|tp2_nvls]` (every pattern but GDN, which runs under `InferenceMode` only with a dynamic inference context): flag-on output equals flag-off output with identical weights and perturbed norm gains (atol/rtol 2e-2). With NVLS (2 GPUs with multicast; skips otherwise), the fused kernel runs exactly at the links, and exactly the input linears it feeds skip their own norm.
  - `test_stack_wiring_stops_at_cp_layout_conversions` (CP=2, 2 GPUs): `*--*` with zigzag attention and contiguous MLP layouts links only the two MLP layers.
- `TestHybridModelFusedTPEngine::test_engine_matches_unfused[mamba|gdn-layer_graphs|block_graphs]` (TP=2, 2 GPUs with NVLS): a `HybridModel` (`M*-M*-`, or `G*-G*-` with GDN in dynamic inference as served, with SiLU, the only activation GDN's convolution supports there) runs the same staggered requests through `DynamicInferenceEngine`, with decode steps replayed from layer- or block-scope CUDA graphs and prefill steps eager. It does this with the flag on and off and compares the generated tokens and every real token's decoder output (atol/rtol 5e-2). The embeddings are tied and scaled, so each request decodes its last prompt token again by a wide logit margin. Both engines then decode the same tokens, while the sub-layers still visibly move the decoder outputs.

On #8704, the stack forward tests and the engine tests fail with the `AttributeError` above (the GDN engine case with `'GatedDeltaNet' object has no attribute 'linear_proj'`, expected), and the wiring tests find no wiring. They pass with this PR. #8561's and #8704's tests are unchanged.

GPU (H100): the first commit passed its tests, and its 2-GPU wiring tests failed on the base. The first review follow-up passed everything but the static GDN forwards, including the Mamba engine test at both graph scopes, which failed on the base. Those GDN forwards now run in the engine test; there, the second follow-up passed everything but the GDN engine cases, whose GELU test config GDN's convolution rejects. With SiLU in the engine test, everything passes, including the Mamba and GDN engine cases at both graph scopes, and every case fails on #8704.

## Review follow-up

- The fused-TP API of main, #8561 and #8704 is kept; the first commit had renamed it.
- Layers are linked by capability, not by class.
- The getters no longer raise on hybrid layers.
- Mamba, GDN and MLA patterns, a CP=2 wiring test and `HybridModel` engine tests (Mamba and GDN) with CUDA graphs are added. GDN forwards are compared in the engine, since GDN runs under `InferenceMode` only with a dynamic inference context.
- The two `HybridModel` rejections are lifted.
- Context-parallel runs are linked per layout.

Merge order: after #8561 and #8704. Conflicts:
- #8709: keep-both conflicts in `HybridStack.__init__` and `TransformerLayer.__init__`.
- #8712: conflicts in the same wiring, as it already does with #8561/#8704. Its `fc2_next_layer_norm_linear`/`get_qkv_layer_norm_linear` would take the same generalized meaning.
