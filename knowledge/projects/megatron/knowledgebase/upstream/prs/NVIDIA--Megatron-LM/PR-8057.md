# Require pipeline groups and warn on global fallbacks in transformer code

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8057) · state: closed · merged: False

## Original PR description

Depends on #8049 (and #6293). Please review the diff from #8049's head: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/d89eccea46...yx/pstate-b10-transformer-defaults).

**Why.** `TransformerBlock` read `pg_collection.pp` behind `hasattr`, which is always true because an unset field reads as `None`. A collection without `pp` gave every stage pipeline rank 0, so with PP=2 stage 1 silently built stage 0's layers with stage 0's layer numbers. `TransformerLayer` and `Float16Module` had the same gap, and the block and layer defaults read the global grid without a warning.

**What.**
- Under pipeline parallelism, `TransformerBlock`, `TransformerLayer` and `Float16Module` require `pp` and reject `None`; without pipeline parallelism `pp` may stay unset. The block and layer also require `tp`.
- An omitted collection goes through `resolve_process_groups`: one `ProcessGroupFallbackWarning` per owner (removed in 0.23), building only the 16 fields the layers' modules read, each the same global group as before.
- `Float16Module` takes `pg_collection`, and warns when neither it nor the wrapped module has one.
- MTP: `MultiTokenPredictionLayer` requires `tp`, `cp` and `pp` in its collection. The `pp_rank` fallbacks of the layer offset and count, and the `metric_avg_group` fallback of `process_mtp_loss`, warn. The acceptance-count guard reads no globals: in training with `tensor_model_parallel_size > 1` in the config, `process_mtp_loss` needs `tp_group` for the vocab-sharded logits.

**Tests.** New `test_transformer_process_groups.py` has 24 cases. The default path is checked for one warning, identical groups, layers and bitwise-equal outputs (TP=2, PP=2). Before the 2026-11-01 sync, 20 of the 24 cases failed on #8049's head, and the block, layer, GPT, BERT, hybrid, MoE, GTP, vision, MTP and dist-checkpointing suites matched the base on 4 GPUs. In the integration run, this PR's test files show no regressions against main: on 4 GPUs, `test_transformer_process_groups.py` passes all 26 of its cases (this PR's 24 plus 2 that a later #6307 PR adds), and `test_wide_residual_connection.py` passes 61 tests, as on main.

**Compatibility.** Groups on the standard grid are unchanged. Megatron Bridge sets `pp` in every collection it builds; modules built without a collection, and MTP spec builders called without `pp_rank`, now warn. An MTP layer given a collection without `tp`, `cp` or `pp` now raises `ValueError`. Land after #8022, or BERT warns.

Synced with main 77391e71cc on 2026-11-01 by merging the updated base, so existing commits and review links stay valid. The only conflict was in the process-group allowlist, which now also records the reads main added since this PR was written.
