# Fix Mixtral HF checkpoint loading with Transformers 5

# What does this PR do?

Fix Mixtral HF-to-mcore checkpoint conversion with Transformers 5. The loader
currently rejects versions such as 5.8.1, then fails on the renamed MoE block
if the version check alone is relaxed.

Use `packaging.version.Version` to enforce Transformers >=4.36.0, including
valid release-candidate and development version strings. Copy router and expert
weights from either the Transformers 4 `block_sparse_moe` / per-expert
`w1,w2,w3` layout or the Transformers 5 `mlp` / fused
`gate_up_proj,down_proj` layout, preserving gate-before-up ordering. Reject
transposed fused expert weights explicitly.

## Issue tracking

Fixes #7934: [Mixtral HF loader fails with Transformers 5](https://github.com/NVIDIA/Megatron-LM/issues/7934).

Related to [#3117](https://github.com/NVIDIA/Megatron-LM/pull/3117), which
changes the version check but does not handle the Transformers 5 expert layout.

## Validation

- A smoke check with a real tiny `MixtralForCausalLM` under
  Transformers 5.17.0 copied every router and expert weight exactly.
- End-to-end validation reported in #7934 tested the same version
  comparison and fused-weight mapping under Transformers 5.8.1 on 2 nodes ×
  4 GB200 GPUs (TP4/PP2/EP1). It converted all 32 layers and produced losses
  identical to the Transformers 4.49.0 baseline: 1.97968 hybrid-FP8 and
  1.952644 BF16.

Focused test command (bypasses the suite's unrelated global GPU/data fixtures):

```bash
python -m torch.distributed.run --nproc-per-node=1 \
  --master-addr=127.0.0.1 --master-port=38764 -m pytest \
  --confcutdir=tests/unit_tests/tools/checkpoint --rootdir=. -q \
  tests/unit_tests/tools/checkpoint/test_loader_mixtral_hf.py
```
