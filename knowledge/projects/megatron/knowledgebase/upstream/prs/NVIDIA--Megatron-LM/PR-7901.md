# fix(post_training): keep GPT-OSS on YaRN without a learned position table

# What does this PR do?

Keep `--enable-gpt-oss` on YaRN for both the rotary module and the embedding constructor, so the published GPT-OSS recipe does not also add a learned absolute position table. Apply the same position type and GPT-OSS YaRN factors to a distillation teacher rebuilt from checkpoint args that still say `learned_absolute`.

## What changed

`modelopt_gpt_hybrid_builder` set `config.position_embedding_type = "yarn"` and still passed `args.position_embedding_type` into `GPTModel` and `HybridModel`. `examples/post_training/modelopt/conf/openai/gpt-oss-20b.sh` never sets `--position-embedding-type`, so that argument stays at the CLI default, `learned_absolute`.

`GPTModel` uses the config attribute for `YarnRotaryEmbedding` and the constructor argument for `LanguageModelEmbedding`. The embedding allocates `position_embeddings` only for `learned_absolute` and adds it in forward. The recipe's table is 40960 × 2880 (about 236 MB in bf16), with no GPT-OSS weights to load into it. `HybridModel` uses only the constructor argument, so the same flag never enabled YaRN on a hybrid export.

The builder now passes `yarn` into both constructors when `--enable-gpt-oss` is set. The CLI argument itself is left unchanged. The published GPT-OSS YaRN factors stay on the config: scale 32, original max position 131072, beta fast/slow 32/1, mscale 1, mscale-all-dim 0, and correction-range rounding off.

With `--export-kd-teacher-load`, the same `model_kwargs` are passed to the teacher, but `teacher_config` is rebuilt from checkpoint args that still say `learned_absolute`. Those args never carry the `yarn_*` fields, so `YarnRotaryEmbedding` raised on `yarn_rotary_scaling_factor`. The teacher config now gets the same position type and GPT-OSS factors. If only the teacher has `--enable-gpt-oss`, its constructor argument is set to `yarn` as well, without changing the student kwargs.

## Tests

`tests/unit_tests/post_training/test_gpt_oss_position_embedding.py` builds through `modelopt_gpt_hybrid_builder` with the recipe's position type:

- GPT export: rotary type is `yarn`, and `embedding.position_embeddings` is absent.
- Hybrid export: constructor type is `yarn`, and the learned table is absent.
- `--enable-gpt-oss` off with `learned_absolute` still allocates the table.
- `--enable-gpt-oss` with `--export-kd-teacher-load` and a teacher yaml that says `learned_absolute`: both student and teacher get YaRN and the GPT-OSS factors, and the loaded teacher args stay `learned_absolute`.
- The same teacher path with no `model_config.yaml`.
- Hybrid distillation teacher.
- Teacher-only `--enable-gpt-oss` does not put YaRN on the student.
- Distillation with both sides on `learned_absolute` still allocates both tables.

`test_gpt_oss_distillation_teacher_builds_real_gpt_model` constructs real `GPTModel` student and teacher objects, checks `YarnRotaryEmbedding` (scale 32, original max 131072, correction rounding off), and runs a CUDA forward and backward.

On a Colab A100-SXM4-40GB (torch 2.11.0+cu130, Transformer Engine 2.20.0) `pytest tests/unit_tests/post_training/test_gpt_oss_position_embedding.py --noconftest` was 9 passed in 25.20s.

`BASE_REF=main CHECK_ONLY=true bash tools/autoformat.sh` reports the new test as already black and isort clean. `model_builder.py` is outside that script's `megatron/core` and `tests/` paths. Local pylint 3.3.5 stops on `.pylintrc` option `bad-builtins` before it scores the file.
