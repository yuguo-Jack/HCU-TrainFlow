# Pass the training collection to the optimizer with Gloo groups on

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8738) · state: closed · merged: False

## Original PR description

Depends on #6259, #8037 and #8055 (which contains #8049 and #6293). Please review the diff from the merge of their heads: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/5d585502d1...yx/pstate-g14-optimizer-always-collection). #8055 is in the base only for the last commit, which updates one of #8037's tests for #8055's schedule warning. The #8055 merge regenerates the process-group allowlist, whose total conflicted.

**Why.** `setup_model_and_optimizer()` passed its process-group collection to `get_megatron_optimizer()` only with `--disable-gloo-process-groups`. With Gloo groups on, the default, it passed `None`, and the optimizer rebuilt every group from the global parallel state through the `ProcessGroupCollection.use_mpu_process_groups()` shim. A collection given to `pretrain()` reached the model and the training loop but not the optimizer, which sharded its state and reduced its gradient statistics over the global grid.

**What.**
- Pass the collection unconditionally. With #6259 the collection carries the Gloo mirrors of the groups the distributed optimizer shards over (`intra_dp_cp_gloo`, `intra_expt_dp_gloo`), and `get_megatron_optimizer()` checks their ranks before using them.
- Document that the collection `pretrain()` builds carries these Gloo groups.
- #8037's `test_schedule_follows_the_collection_pipeline_group` calls the schedule's global fallback on purpose. With #8055 that fallback warns, and under an `error` filter the warning failed the test. The test now asserts the warning, with the once-per-site registry emptied so that it shows even when an earlier test triggered it.

**Tests.** `tests/unit_tests/training/test_training_pg_collection.py`:
- `test_setup_builds_the_optimizer_on_the_collection` (Gloo on and off) runs `setup_model_and_optimizer()` through the real optimizer build, with every `parallel_state` group accessor and the shim made to raise during that build. It checks that the dense and expert distributed optimizers hold the collection's own Gloo communicators.
- `test_collection_carries_the_grid_gloo_groups` (Gloo on and off) guards the property this change relies on. It passes without the change too.

In the integration run (all #6307 PRs merged onto main), this file passes 11 of 11 on 4 GPUs; main does not have the file. The existing tests that now take the collection path with Gloo on show no regressions against main: `test_fp8_param.py`, the Megatron-FSDP v1 tests, `test_multi_token_prediction.py` and `test_upcycling.py`. The new cases sit in an existing test file and no run of the base included them, so the Gloo-on case has not been observed failing without this change.

Before the sync:
- on 4 GPUs, on #6259 merged with #8037, three test groups showed no regressions;
- the branch ran on 4 CPU gloo ranks with no regressions (the setup cases need CUDA);
- with the other process-group changes from #6307 applied, this file passed 11 of 11 at 8 ranks, with and without `-W error::megatron.core.process_groups_config.ProcessGroupFallbackWarning`.

**Compatibility.**
- On the standard grid the collection holds the same group objects the shim returned, so training is unchanged. `--disable-gloo-process-groups` behaves as before.
- With Gloo groups on, a collection passed to `pretrain()` was ignored by the optimizer. It now has to meet the whole `get_megatron_optimizer()` contract that `--disable-gloo-process-groups` already required: `dp`, `expt_dp`, `mp` and `tp_ep_pp`, `intra_dist_opt` with the distributed optimizer, the `intra_*` groups with more than one optimizer instance, and Gloo mirrors whose ranks match. A collection without the Gloo fields raises `ValueError`. No in-repo caller is affected, and Megatron-Bridge and NeMo-RL use their own setup.
- MiMo's optimizer ignores the argument, as before.
- Callers that pass no collection to `setup_model_and_optimizer()` are unchanged: `tasks/finetune_utils.py`, `tools/bert_embedding/embed.py` and many unit tests. `get_model()` builds its own collection there while the optimizer uses the shim, which gives the same groups on the standard grid. #8757 builds a setup's model and optimizer on one collection.
- The new test uses the process-group checker's private `_is_deprecated_accessor` to choose which accessors to patch. It can switch to #8017's `forbid_global_process_groups` once #8017 lands.
- Needs `determinism-exempt` only because #6259's `megatron/core/optimizer/__init__.py` is in the base. This PR touches no kernel file.
