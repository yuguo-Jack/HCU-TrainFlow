### [P2] Recognize config-list checkpoints when classifying the saved model family

**Failure:** Build a config-list HybridModel, save a `torch_dist` checkpoint, then reload it using the same Python definition. The builder sets `args.is_hybrid_model=True` while leaving the pattern unset, and [checkpoint saving preserves that namespace](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/training/checkpointing.py#L1669-L1674). However, [the load-time classifier](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/training/checkpointing.py#L2558-L2581) recognizes only saved pattern fields. It misclassifies this checkpoint as GPT and raises `Loading a GPT checkpoint into a hybrid model requires --hybrid-layer-pattern`. The [same classifier runs for `fsdp_dtensor`](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/training/checkpointing.py#L2751-L2756).

**Correction:** In `_maybe_setup_gpt_to_hybrid_load`, after computing `ckpt_pattern`, replace the family-equality check with:

```python
ckpt_is_hybrid = bool(getattr(ckpt_args, "is_hybrid_model", False) or ckpt_pattern)
if runtime_is_hybrid == ckpt_is_hybrid:
    return None, False
```

The saved checkpoint's marker—not the current runtime's marker—must establish its provenance. Retain actual-model runtime detection, the metadata-less early return, legacy pattern recognition, GPT translation validation, and reverse-family rejection.

**Proposed acceptance checks:** A HybridModel shell plus checkpoint args `is_hybrid_model=True, hybrid_layer_pattern=None` must return `(None, False)`; the same checkpoint with a non-Hybrid runtime must raise the reverse-family error. Legacy pattern/override checkpoints must still load normally. Preserve the existing [metadata-less checkpoint assertion](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/tests/unit_tests/dist_checkpointing/models/test_gpt_hybrid_interop.py#L65-L72), and verify unmarked GPT checkpoints still take compatible pattern translation. Save/reload a small config-list checkpoint and assert weights and resumed iteration are restored.

### [P2] Pass the resolved root configuration into distributed preparation

**Failure:** Use an `AttentionLayerConfig` root with `num_layers=1, bf16=True` and `layers=[root, MTPSplit, root]`. [Core deliberately clones an aliased root](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/core/models/hybrid/hybrid_model.py#L195-L204) and infers MTP depth on that clone. The [new assignment retains it](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/training/models/hybrid.py#L257-L259), but `build_distributed_models` has already captured the original root. [Distributed preparation receives that stale reference](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/training/models/dist_utils.py#L120-L133), so [Float16Module.config](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/core/transformer/module.py#L522-L528) still has `mtp_num_layers=None`. Schedules read the outer config and [skip MTP auxiliary-loss scaling](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/core/pipeline_parallel/schedules.py#L379-L383), rather than applying the microbatch/loss scale.

**Correction:** Immediately before `unimodal_build_distributed_models` calls `prepare_existing_model_chunks_for_distributed_training`, obtain the constructed model's root:

```python
transformer_config = get_model_config(model_list[0])
```

The helper already imports `get_model_config`. Its pre-wrap hook contract returns the model list, so preparation should follow that list's resolved configuration. Keep caller-owned layer entries unchanged; copying inferred fields back into the original root would violate Core's ownership guarantee.

**Proposed acceptance checks:** Build the root-alias example with `wrap_with_ddp=False` and a recording mixed-precision wrapper. Assert the wrapper receives `model.config`, its MTP depth is 1, and the source root still has `mtp_num_layers is None`. Through loss-scale setup, two microbatches with unit loss scale must publish `0.5`. Retain no-alias and no-MTP cases, the existing [wrapper-call assertions](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/tests/unit_tests/training/models/test_dist_utils.py#L282-L304) when stages own the supplied root, and the new forwarding test's source-identity/nonmutation assertions.

### [P2] Make default embedding/output ownership virtual-stage-aware

**Failure:** The [newly supported config-list VPP path](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/training/models/hybrid.py#L186-L187) permits `build_model(pg, vp_stage=i)` without explicit ownership flags. With PP=2, VPP=2 and four PipelineSplit-delimited segments, [the fallback checks physical rank only](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/training/models/hybrid.py#L231-L235). Rank 0's second virtual stage therefore builds an embedding and [uses token embeddings instead of incoming hidden states](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/megatron/core/models/hybrid/hybrid_model.py#L734-L740); the last physical rank's first virtual stage incorrectly owns output processing. The distributed helper supplies correct explicit flags, but the public single-stage method does not.

**Correction:** Import `is_vp_first_stage` and `is_vp_last_stage` from pipeline utilities and replace the fallback block with the same logic already used by GPTModelBuilder:

```python
vp_size = self._model_config.transformer.virtual_pipeline_model_parallel_size
if pre_process is None:
    pre_process = is_vp_first_stage(
        vp_stage=vp_stage, vp_size=vp_size
    ) and is_pp_first_stage(pg_collection.pp)
if post_process is None:
    post_process = is_vp_last_stage(
        vp_stage=vp_stage, vp_size=vp_size
    ) and is_pp_last_stage(pg_collection.pp)
```

Only the first PP/VP pair may infer embedding ownership, and only the final pair may infer output ownership. Explicit flags must remain authoritative.

**Proposed acceptance checks:** Mock Core construction and check `(pp_rank, vp_stage)` pairs `(0,0)`, `(1,0)`, `(0,1)`, `(1,1)` produce flags `(True,False)`, `(False,False)`, `(False,False)`, `(False,True)`. Preserve explicit overrides, distributed-helper ownership, and existing [non-VPP inference assertions](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/tests/unit_tests/training/models/test_hybrid_builder.py#L370-L392).

### [P3] Update the migration guide's blanket builder-VPP prohibition

The [migration guide](https://github.com/NVIDIA/Megatron-LM/blob/ed5ca6a9a2c4204554b7708b3d02ef50a49fdb31/docs/user-guide/hybrid-model-migration.md#L369-L372) still says declarative HybridModelBuilder rejects VPP and custom-builder users must avoid it. That contradicts this PR's explicit config-list support and directs users away from a supported configuration.

Replace that paragraph with a qualified description, for example:

Declarative HybridModelBuilder config-list architectures support virtual pipeline

The pretrain_hybrid.py CLI path continues to derive virtual stages from pattern segments.

Retain the preceding CLI pattern-layout instructions. Static acceptance: the guide must distinguish explicit config-list topology from pattern-derived CLI VPP and no longer prohibit all builder VPP.
