# What does this PR do?

The in-loop `report_memory()` calls only fire once an iteration completes, so a run that dies during startup, for example an OOM while loading a checkpoint into a grid that fits from scratch, leaves no memory trace. This adds reports in `megatron/training/training.py`:

- `(after model and optimizer build)` and `(after checkpoint load, iteration N)` in `setup_model_and_optimizer`. Their difference is what loading the checkpoint cost; on a fresh start, iteration is 0 and it is the baseline.
- `(before first iteration)` at the end of setup in `train()`, once weights, optimizer state, any loaded checkpoint and the symmetric-memory pools are resident.

It also calls `torch.cuda.empty_cache()` after `load_checkpoint` returns, with a third report after it. On a large MoE resume, one rank went from 27.7 GB allocated / 36.3 GB reserved after the build to 29.9 GB allocated but 218.3 GB reserved after the load: the load's buffers were freed only after `load_checkpoint`'s own `empty_cache` had run, so the allocator kept them cached.

`_get_memory_report_dp_group` resolves the group that gates each report's print, unwrapping a MIMO `MultiModuleProcessGroupCollection` to the language model's collection the same way the cross-entropy warmup in `pretrain()` does.

This does not reduce the transient peak inside the load; that comes from the fully parallel load's broadcast exchange and needs a separate fix.

## Notes on the port

Resolved onto current `main`: the iteration in the post-load reports comes from `train_state.iteration` instead of `args.iteration`, and the `(before first iteration)` report sits after `_start_otel_train_span()`.

### Add regression coverage for startup memory reporting and cleanup

The new [setup reports and outer cache release](https://github.com/NVIDIA/Megatron-LM/blob/3005a7841deb07dbec88c563cd2e2f12c8fcb9da/megatron/training/training.py#L3062-L3184) fix a checkpoint-allocation lifetime issue, but this PR adds no corresponding tests. The existing [checkpoint-conversion test](https://github.com/NVIDIA/Megatron-LM/blob/3005a7841deb07dbec88c563cd2e2f12c8fcb9da/tests/unit_tests/test_training.py#L181-L230) verifies load/save dispatch, not report/cleanup ordering. Moving cleanup back inside the loader, or moving the build report after loading, would violate the new contract without violating those assertions.

**Correction and preservation:** Add focused tests alongside the existing training tests; no production rewrite is needed. Preserve both resumed and scratch startup, reporting before a failed load, and local-group selection for plain, colocated MIMO, and encoder-only models. Keep the existing [missing/`None` wrapper fallback and wrapped-model assertions](https://github.com/NVIDIA/Megatron-LM/blob/3005a7841deb07dbec88c563cd2e2f12c8fcb9da/tests/unit_tests/training/test_train_step_schedule_plumbing.py#L170-L187).

**Proposed acceptance checks:**
- Mock a loader returning iteration 7 and record events: build report → loader return → checkpoint report containing `iteration 7` → outer `empty_cache` → post-cleanup report. Assert all reports receive the resolved DP group.
- Make the loader raise; assert the build report already occurred.
- With neither checkpoint path configured, assert the loader is not called, both post-setup reports contain `iteration 0`, and cleanup still occurs between them.
- Assert the [before-first-iteration report](https://github.com/NVIDIA/Megatron-LM/blob/3005a7841deb07dbec88c563cd2e2f12c8fcb9da/megatron/training/training.py#L5154-L5159) occurs before the first training step.

For the unambiguous resolver portion, this proposed test can be added to a new training test module:

```python
from megatron.core.process_groups_config import (
    MultiModuleProcessGroupCollection,
    ProcessGroupCollection,
)
from megatron.training.training import _get_memory_report_dp_group


def test_memory_report_dp_group_selection():
    encoder_dp, llm_dp = object(), object()
    encoder = ProcessGroupCollection(dp=encoder_dp)
    llm = ProcessGroupCollection(dp=llm_dp)
    colocated = MultiModuleProcessGroupCollection(
        module_pgs={"encoder": encoder, "llm": llm},
        language_model_module_name="llm",
    )
    encoder_only = MultiModuleProcessGroupCollection(
        module_pgs={"encoder": encoder}
    )

    assert _get_memory_report_dp_group(None) is None
    assert _get_memory_report_dp_group(llm) is llm_dp
    assert _get_memory_report_dp_group(colocated) is llm_dp
    assert _get_memory_report_dp_group(encoder_only) is encoder_dp
```

These are proposed tests, not execution results. The encoder-first colocated case specifically ensures the resolver selects the language model rather than blindly selecting the first collection.
