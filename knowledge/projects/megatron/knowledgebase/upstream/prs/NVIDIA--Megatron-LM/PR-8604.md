# test(inference): add multimodal dynamic inference coverage foundation

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8604) · state: open · merged: False

## Original PR description

## What does this PR do?

This PR adds a unit-test foundation for dynamic multimodal inference. It runs small real LLaVA models through the dynamic engine and checks that media is encoded once, cached, reused, and placed in the right prompt positions. It also checks that sampling, scheduling and parallel layouts do not change the result. It changes no production code, and every test passes on unmodified `main`.

The foundation adds:

- `tests/unit_tests/inference/test_multimodal_gpu.py`: 43 cases that run real vision encoders, projections and language models through `DynamicInferenceEngine`, covering media caching, prompt placement, chunked prefill, prefix caching, async scheduling, hybrid language mixers, MoE, parallel layouts, CUDA graphs, MTP drafts and sampling;
- a sink case for the dynamic flash-attention replay in `test_runtime_cp_attention.py`, next to the existing no-sink case, which is unchanged;
- a witness in the static VLM controller test that the vision projection actually runs on the 577 image positions.

## How was the test matrix determined?

Existing multimodal inference tests mostly exercised the static path or mocked the encoder. None of them checked, with real models in the dynamic engine, that an image or video is encoded once, cached under a key that identifies it, and placed into the right prompt rows when the same media comes back. They also did not check that these properties survive the engine features that move tokens around: chunked prefill, prefix caching, async scheduling, recompute, CUDA graphs and MTP drafts.

The matrix therefore has three layers:

1. **Media identity and placement.** Each supported vision family and media shape is encoded, reused from the cache, and compared with distinct media.
2. **Engine features with media.** Media requests run through each engine feature that can split, reorder or replay their tokens.
3. **Model and parallel layouts.** The same media request runs on hybrid language models, an MoE model, and tensor-, data- and expert-parallel layouts.

This is differential coverage, not every combination. Each feature runs with media present and is compared with an equivalent uncached, unchunked or eager run. Cases that need any of the eight multimodal fixes live with those fixes. Context and sequence parallelism are not covered here; context parallelism is rejected for dynamic VLM inference by a separate fix PR.

## What combinations are tested?

All cases use small BF16 models and default to two-way tensor parallelism, capped at two ranks so every model divides its heads evenly. Remaining ranks are data-parallel replicas, so the file runs at any launch size, including CI's default 8-GPU launch.

## How are results checked?

- **Media cases:** the same media encodes once and reuses its exact embeddings, mask rows and logits from the cache. Distinct media gives different embeddings and logits, and the prompt token IDs and mask positions stay exact.
- **Engine-feature cases:** results are compared with an equivalent plain run. Chunked against unchunked and graph against eager must match exactly, and async must preserve which request owns each media row.
- **Layout cases:** check that the intended path actually ran, for example router calls, optimized linear layers, or distinct per-rank media under data parallelism. Logits must be finite and greedy tokens must match the logits.
- **Sampling cases:** check seeded top-p and log-probability consistency against the computed distribution.
- **Sink replay:** replays bit for bit, and changing the softmax scale must change its output.

## Scope

This PR is test-only and makes no production, functional-test, configuration or golden change.

This PR first carried a test-harness fix in `test_utilities.py`: determinism tests freeze bare cuDNN flag assignment, so teardown could fail to restore the flags. Main now has the same fix (NVIDIA/Megatron-LM#7575), so this PR takes main's version and no longer changes that file.

Main also now admits dynamic-resolution image requests without encoding them and encodes the waiting requests' images together just before prefill (NVIDIA/Megatron-LM#8408). The tests' request helper runs that encode (`DynamicInferenceEngine._encode_waiting_images`) right after admission, so the embeddings it records are the ones prefill uses.

The static VLM controller test now also checks that the vision projection ran with the expected shape.

The eight multimodal fixes, each with its own regression, are separate PRs based on this one:

- media cache keys (lmcafee-nvidia/Megatron-LM#127);
- static tile tags (lmcafee-nvidia/Megatron-LM#128);
- mRoPE rejection (lmcafee-nvidia/Megatron-LM#129);
- context-parallelism rejection (lmcafee-nvidia/Megatron-LM#134);
- FlashAttention 4 sinks (lmcafee-nvidia/Megatron-LM#130);
- the device and mode of a split MLA projection (lmcafee-nvidia/Megatron-LM#131);
- an already-unfused MLA projection (lmcafee-nvidia/Megatron-LM#132);
- FP8 input rank (lmcafee-nvidia/Megatron-LM#133).

Main now carries its own fix for FA4 sinks, so lmcafee-nvidia/Megatron-LM#130 is now the series' tests PR: it keeps the FA4 sink regressions and points them at main's correction.
