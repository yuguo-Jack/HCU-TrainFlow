# Enable contiguous context-parallel attention for softmax attention la…

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7834) · state: open · merged: False

## Original PR description

### Background
Hybrid models currently use contiguous CP for linear attention and zigzag CP for softmax attention, requiring padding and redistribution between layouts. Allowing both to use contiguous ownership removes that requirement, at the cost of causal attention load imbalance.

### Summary
- Enable `attention_cp_layout="contiguous"` through TE’s `NO_LOAD_BALANCE` all-gather path, supporting packed THD inputs and adapting dense SBHD inputs.
- Make MTP and HSM rolls respect contiguous ownership.
- Simplify packed rolls in MTP and share the codes HSM.

File: `megatron/core/transformer/transformer_config.py` · line 1639

**[CRITICAL Correctness]** Without the CP>1 guard, MLA can run contiguous CP while still applying zigzag RoPE positions.

**What fails**
- Base rejected `attention_cp_layout="contiguous"` with `context_parallel_size > 1` unless the variant was `dsv4_hybrid` ([base L1634-L1641](https://github.com/NVIDIA/Megatron-LM/blob/ee6baa2e31671c3c23eca482d8728be1d4e33d35/megatron/core/transformer/transformer_config.py#L1634-L1641)).
- The RoPE check that replaces it exists only in [`Attention.forward_pre_attn_and_core_attn`](https://github.com/NVIDIA/Megatron-LM/blob/4f04d789db0224c0df1c3b708d8e8b656409ec76/megatron/core/transformer/attention.py#L1398-L1407).
- `MLASelfAttention` overrides `forward` ([L453-L519](https://github.com/NVIDIA/Megatron-LM/blob/4f04d789db0224c0df1c3b708d8e8b656409ec76/megatron/core/transformer/multi_latent_attention.py#L453-L519)) and never calls that method. It builds RoPE itself in `get_query_key_value_tensors` ([L876-L901](https://github.com/NVIDIA/Megatron-LM/blob/4f04d789db0224c0df1c3b708d8e8b656409ec76/multi_latent_attention.py#L876-L901)).
- For SBHD input, `RotaryEmbedding.forward` slices positions with the zigzag helper `get_pos_emb_on_this_cp_rank` ([rotary_pos_embedding.py L205-L208](https://github.com/NVIDIA/Megatron-LM/blob/4f04d789db0224c0df1c3b708d8e8b656409ec76/megatron/core/models/common/embeddings/rotary_pos_embedding.py#L205-L208)). The THD and fused MLA RoPE paths also take `cp_rank`/`cp_size` and assume zigzag.
- MLA's core attention is `TEDotProductAttention`, which this PR switches to contiguous `NO_LOAD_BALANCE`.

**Example:** MLA with `context_parallel_size=2`, `cp_comm_type="all_gather"`, `attention_cp_layout="contiguous"`, dense S=8.
- Rank 0 holds tokens 0-3 but rotates them with positions {0,1,6,7}.
- Rank 1 holds tokens 4-7 but rotates them with positions {2,3,4,5}.
- Actual: the config validates and training runs with scrambled Q/K positions and no error.
- Expected: a `ValueError` at config time, as on base.

**Fix.** Add this to `_validate_cp_layouts` after the dynamic-CP check:

```python
        if (
            self.context_parallel_size > 1
            and self.attention_cp_layout == "contiguous"
            and self.multi_latent_attention
            and self.experimental_attention_variant != "dsv4_hybrid"
        ):
            raise ValueError(
                "Contiguous attention CP does not yet support multi-latent attention; "
                "MLA applies RoPE with zigzag CP positions."
            )
```

The rule to restore: any softmax-attention module that applies RoPE outside `forward_pre_attn_and_core_attn` is either rejected under contiguous CP>1 or slices positions contiguously. DSA goes through MLA, so this check also covers it, as base did.

**Must keep working**
- DSv4 (`dsv4_hybrid`) with contiguous CP stays exempt, as on base, because it has its own contiguous RoPE.
- Non-MLA TE attention with contiguous CP still validates. The runtime check still rejects it when RoPE is present, and NoPE layers still pass.
- MLA with the zigzag layout, and MLA at CP=1 with either layout, still construct.

**Acceptance (proposed tests, not run)**
- A minimal `MLATransformerConfig(num_layers=2, hidden_size=128, num_attention_heads=4, context_parallel_size=2, cp_comm_type="all_gather", attention_cp_layout="contiguous")` raises `ValueError` matching `"multi-latent"`.
- The same config with `attention_cp_layout="zigzag"`, or with `context_parallel_size=1`, constructs.
- Existing `dsv4_hybrid` contiguous-CP configs still construct.
- `test_contiguous_cp_forward_backward` (non-MLA) is unchanged.

**[IMPORTANT Compatibility]** The dynamic-CP check also rejects CP=1 runs that use the sequence-packing scheduler.

**What fails:** `TransformerConfig(num_layers=2, hidden_size=64, num_attention_heads=4, attention_cp_layout="contiguous", sequence_packing_scheduler="dp_balanced", max_seqlen_per_dp_cp_rank=128)` at CP=1 constructs on base. On head it raises `ValueError("Contiguous attention CP does not support dynamic CP.")`.

With `hybrid_context_parallel=False` and CP=1 there is no CP at all, so the rejection is wrong:
- The `dp_balanced` path builds static `PackedSeqParams` with no `local_cp_size` ([data_schedule.py L914-L922](https://github.com/NVIDIA/Megatron-LM/blob/4f04d789db0224c0df1c3b708d8e8b656409ec76/megatron/core/datasets/data_schedule.py#L914-L922)).
- At CP=1, `roll_tensor` uses `roll_contiguous` for either layout ([L263-L265](https://github.com/NVIDIA/Megatron-LM/blob/4f04d789db0224c0df1c3b708d8e8b656409ec76/megatron/core/transformer/multi_token_prediction.py#L263-L265)).
- TE skips its contiguous branch when the CP group has size 1.

So the layout value has no effect at CP=1. Base applied this restriction only when `context_parallel_size > 1` ([base L1634-L1641](https://github.com/NVIDIA/Megatron-LM/blob/ee6baa2e31671c3c23eca482d8728be1d4e33d35/megatron/core/transformer/transformer_config.py#L1634-L1641)), and so does the scheduler check right below it (L1644-L1651).

**Fix.** Apply the CP>1 condition only to the scheduler clause. Keep hybrid CP rejected at every CP size, because it forms dynamic groups from DP×CP ranks:

```python
        if self.attention_cp_layout == "contiguous" and (
            self.hybrid_context_parallel
            or (self.sequence_packing_scheduler is not None and self.context_parallel_size > 1)
        ):
            raise ValueError("Contiguous attention CP does not support dynamic CP.")
```

**Must keep working**
- `hybrid_context_parallel=True` with contiguous layout still raises at every CP size.
- `dp_balanced` with contiguous layout at CP=2 still raises.
- Zigzag with the scheduler is unaffected.

**Acceptance (proposed test, not run).** Parametrize one config test:
- contiguous + `dp_balanced` at CP=1 → constructs.
- the same at CP=2 → `ValueError`.
- `hybrid_context_parallel=True` (with its required fields) + contiguous → `ValueError`.

**[IMPORTANT Compatibility]** The sum returned by `roll_tensor_precomputed_embeddings` now means different things on different paths.

**What fails**
- Base, with SP>1 at CP=1 (default `cp_layout="zigzag"`), gathered the SP shards and returned the sum over the whole CP-local sequence ([base L527-L542](https://github.com/NVIDIA/Megatron-LM/blob/ee6baa2e31671c3c23eca482d8728be1d4e33d35/megatron/core/transformer/multi_token_prediction.py#L527-L542)).
- Head returns `rolled.sum()` over this rank's SP shard only (L325-L327).
- The zigzag CP>1, SP>1 path ([L340-L355](https://github.com/NVIDIA/Megatron-LM/blob/4f04d789db0224c0df1c3b708d8e8b656409ec76/megatron/core/transformer/multi_token_prediction.py#L340-L355)) still returns the sum over all SP shards.

So the same return value covers the whole sequence on one path and only the local shard on the others. A caller passing `return_sum=True` at CP=1 now gets roughly 1/tp of the old value, with no error. The in-tree MTP block passes `return_sum=False` ([L2522-L2544](https://github.com/NVIDIA/Megatron-LM/blob/4f04d789db0224c0df1c3b708d8e8b656409ec76/megatron/core/transformer/multi_token_prediction.py#L2522-L2544)) and is unaffected, but this is a public `megatron/core` helper.

**Fix.** Choose one meaning, state it in the docstring, and return it on every path.
- **Smaller change:** keep the local-shard meaning the new test already asserts. On the zigzag SP path, call the inner `roll_tensor(..., return_sum=False)` and end with `return local_tensor, local_tensor.sum() if return_sum else None`.
- **Alternative:** restore the base meaning on the new path by reducing the sum over `sp_group`. That also requires deciding how the reduced sum should behave under autograd; base's gathered sum carried no gradient to `tensor`. I am not proposing a patch for this option.

**Must keep working**
- The differentiable CP=1/contiguous path, including the gradient equality checked in `test_contiguous_precomputed_embeddings_backward`.
- `return_sum=False` returns `None` on every path.

**Acceptance (proposed test, not run).** Add a zigzag CP=2 × TP=2 case asserting `total == output.sum()`, the same meaning the CP=1 cases already check. The existing `return_sum` parametrization must keep passing.
