# Fix MFSDP local embedding-gradient synchronization for MTP with pipeline parallelism

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7978) · state: closed · merged: False

## Original PR description

## Summary

Extract the MFSDP embedding-gradient compatibility fix from #7582 into an independently reviewable PR. This PR contains only `finalize_model_grads.py` and its four-rank regression test; it does not change combined-1F1B callback counting or scheduler hooks.

## Problem

MFSDP's local-Tensor runtime installs optimizer-layout gradient shards as ordinary Tensors. With MTP and pipeline parallelism, the embedding is used on multiple stages even when input/output weights are untied. Existing cross-stage embedding synchronization assumes a DTensor and raises `TypeError: Input must be a DTensor, got Tensor.`

Directly all-reducing local shards is not sufficient: stages can place the same logical embedding at different offsets in their packed MFSDP buffers.

## Fix

- Retain the existing DTensor gather/all-reduce/copy-back path.
- For local Tensor gradients, recover the owning parameter group and gather its finalized optimizer-layout gradient buffer to replicated placements.
- All-reduce the full logical embedding across the supplied embedding process group, then copy the stage's owned slice back into the original gradient view.
- Handle absent frozen gradients before entering the MFSDP path.

The regression covers different stage-local packing offsets, replicated and sharded storage, preserved gradient identity, and unchanged neighboring gradients.

## Validation

The same production fix and regression test were validated in the integrated develop branch on GB200:

- Four-rank layout regression: both cases passed, SLURM 7805172.
- Subsequent four-rank regression gate including this test: 36 tests passed per rank, SLURM 7808711.
- Combined 1F1B + MXFP8 + PP2/VPP2 + MTP1: 10-step smoke and 110-step full workload passed, no NaNs/skipped steps.
- Integrated MFSDP MTP1 and MTP0 workloads each completed 1,000 steps. These validate the integrated stack, not this standalone branch in isolation.
- Standalone extraction: isort, Black check, and git diff whitespace check passed. Production file matches the previously tested fix exactly. Upstream CI on this standalone head remains pending.

## Scope and dependencies

Based on current upstream main. No dependency on #7581/#7582 countdown symbols; the existing DTensor runtime remains supported. Remove the corresponding production/test changes from #7582 through a follow-up commit, without rewriting its history.

The local-Tensor path currently gathers the entire owning gradient buffer, so temporary memory/communication cost may warrant a separate optimization. This PR preserves the validated fix rather than introducing an untested per-parameter collective implementation.
