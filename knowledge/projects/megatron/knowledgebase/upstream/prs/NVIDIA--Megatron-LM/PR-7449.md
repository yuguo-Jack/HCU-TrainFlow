# Fix hybrid optimizer gradients and checkpoint resume

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7449) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

Fix hybrid CPU/GPU Adam gradient routing and checkpoint continuation. Missing gradients could reuse stale child buffers; native FP32 GPU parameters could miss decoupled gradients; restored CPU master copies or GPU counters could be stale. With transfer overlap, a BF16-to-FP32 GPU gradient cast also ran on the D2H stream and could race its consumer.

## Changes

- Route and clear gradients through the actual inner-parameter map. Perform GPU-owned gradient conversion on the consuming stream and reserve D2H work for CPU-owned copies.
- Preserve GPU group counters and refresh both child optimizers after checkpoint restore, including dp-reshardable, fully-reshardable, dp-zero and historical legacy conversion paths. Restore the full-precision owner before refreshing children; nonzero ranks do not read rank-zero-only legacy state.
- Retain per-format restore hooks because chained callers can directly invoke the dp-zero loader. Handle separately restored scalar counters and canonical FP32 master representations.
- Add BF16-gradient overlap regressions, native gradient/serialization checks, real MCore DDP continuation across four checkpoint formats, and a registered bit-exact optimizer replay. Historical conversion also has CPU contracts for FP32/BF16 and rank-zero/nonzero behavior.
- The legacy Torch test trusts only its self-created fixture through a scoped environment override; production checkpoint-loading policy is unchanged.

Replay alone passed on the baseline, showing why correctness/continuation checks are separate. Those results retain their original revision and narrower format matrix.
