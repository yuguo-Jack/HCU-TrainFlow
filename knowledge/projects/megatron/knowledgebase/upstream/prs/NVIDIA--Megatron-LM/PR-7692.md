# fix(mrope): skip CP freq slice for packed THD sequences

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7692) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Skip the early context-parallel frequency slice in `MultimodalRotaryEmbedding` for packed THD input so `_apply_rotary_pos_emb_thd` can index full-sequence positions. Matches the existing `RotaryEmbedding` `packed_seq` gate.

@sbhavani @NVIDIA/transformer @NVIDIA/gpt @NVIDIA/mcore-oncall @NVIDIA/core-adlr @NVIDIA/core-nemo packed THD mRoPE + CP fix ready for review (Fixes #7679).

## Issue tracking

Linked issue: Fixes #7679

## Root cause

`MultimodalRotaryEmbedding.forward` always CP-slices the frequency table when `cp_group.size() > 1`. For packed THD, `_apply_rotary_pos_emb_thd` later builds `freq_pos` in the *full* sequence and indexes that table (with clamping). After an early slice, those indices select the wrong frequencies.

Regular `RotaryEmbedding.forward` already skips the slice when `packed_seq=True`. `gpt_model.py` already passes `packed_seq=(qkv_format == 'thd')` into rope/yarn, but not into the mrope branch.

## Approach

Mirror approach B from #7679 / the THUDM/slime production patch:

1. Add `packed_seq: bool = False` to `MultimodalRotaryEmbedding.forward`.
2. Change the CP slice gate to `cp_group is not None and cp_group.size() > 1 and not packed_seq` (same predicate name and condition as `RotaryEmbedding`).
3. In the `gpt_model.py` mrope branch, pass `packed_seq=(packed_seq_params is not None and packed_seq_params.qkv_format == 'thd')` exactly like rope/yarn.
4. Do **not** change non-packed CP behavior (`packed_seq` defaults False; non-THD callers keep the early slice).

Slime reference: https://github.com/THUDM/slime/blob/main/docker/patch/latest/megatron.patch (MultimodalRotaryEmbedding + gpt_model mrope call site).

## Call reachability (new guard)

- `packed_seq=True` (THD from gpt_model): skip slice; THD apply owns CP position mapping.
- `packed_seq=False` (default / non-packed / non-thd): keep intentional early CP slice.
- Only `gpt_model.py` mrope call site constructs `MultimodalRotaryEmbedding` freqs today; default keeps external callers on prior CP behavior.

## Verification

No multi-GPU / CUDA on the box used for this PR. Verified locally:

1. `py_compile` on the three touched files.
2. Focused CPU tensor checks (construct `MultimodalRotaryEmbedding` on CPU, fake CP group):
   - packed_seq=True, CP=1 vs CP=2: identical full-seq freqs (shape `[8,1,1,64]`).
   - packed_seq=False, CP=2: still calls `get_pos_emb_on_this_cp_rank`.
   - packed_seq=True, CP=2: does **not** call `get_pos_emb_on_this_cp_rank`.
3. Unit tests added under `TestMultimodalRotaryEmbeddingPackedSeqCP` in `tests/unit_tests/transformer/test_rope.py` (CPU-safe; no CUDA required for the new cases).

Did **not** run multi-GPU packed THD apply with `apply_rope_fusion=False`. Please treat end-to-end CP=1 vs CP=2 numerical parity on GPU as remaining CI / reviewer validation.
