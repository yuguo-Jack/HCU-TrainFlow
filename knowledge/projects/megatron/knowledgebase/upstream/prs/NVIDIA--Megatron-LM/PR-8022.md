# Use the model's process groups in BERT and in GPT's padding-mask scatter

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8022) · state: open · merged: False

## Original PR description

**Why.** `BertModel(pg_collection=...)` stored the collection but built its embedding, encoder, output layer, pooler and rotary embedding without it. It also picked the first pipeline stage with the global `is_pipeline_first_stage()`. A BERT on its own grid was sharded and communicated over the global groups, or failed when no global grid existed. In GPT, the sequence-parallel scatter of the MoE padding mask used the global TP group while the decoder input used `self.pg_collection.tp`, so on a custom grid the mask no longer lined up with the tokens.

**What.**
- BERT passes its collection, or its TP/CP group, to every submodule and uses `is_pp_first_stage(self.pp_group)`. The global predicate ignored virtual stages, so this is equivalent for any `vp_stage`.
- `Pooler` takes an optional `tp_group` for its sequence-parallel gather.
- GPT scatters the padding mask over `self.pg_collection.tp`.

**Tests.** Both tests fail on main and pass here on 4 GPUs; the existing BERT and GPT model tests give the same results as on main.
- BERT, with SP on and off and learned and RoPE positions, is built on new communicators that use the global TP=2 layout. The global TP/PP/CP accessors, the stage predicates and the collection shim are set to raise. Its outputs match the model built on the global grid.
- A TP=2 GPT runs on a TP=1 global grid, and its first layer receives the mask chunk that matches its hidden states.

**Compatibility.** Without a collection, BERT builds one from the global grid as before, so every submodule gets the same groups. `Pooler`'s new argument is optional.
