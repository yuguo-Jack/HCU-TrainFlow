- claude[bot] · comment · 2026-08-25T21:44:55Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/6861#issuecomment-5417229720)

Light review — the contiguous rolling logic looks correct to me. I traced `_roll_tensor_contiguous_cp` (boundary exchange, last-rank zero fill), the packed masking in `_roll_tensor_packed_seq_contiguous` (`searchsorted(physical_ends, ..., right=True)` handles both exact boundaries and zero-length documents), and the window arithmetic in the new `cp_layout == 'contiguous'` branch of `_packed_seq_params_for_local_hsm_roll` (`shard_rank = cp_rank * tp_size + tp_rank` matches how `_get_batch_on_this_cp_rank_contiguous` shards, followed by the SP scatter). Two smaller items.

**1. Coverage gap: packed contiguous CP without sequence parallelism**

`test_hsm_roll_supports_contiguous_cp` parametrizes `[(False, False, False), (True, False, True), (True, True, True)]`, so every packed case runs with `sequence_parallel=True`. Under SP, `use_local_packed_roll` is True, so `roll_tensor` is called with `cp_group=None` and the roll never exercises the cross-rank exchange inside `_roll_tensor_packed_seq_contiguous`.

The packed + non-SP combination is precisely the one this PR newly enables end-to-end: with `linear_cp_layout == 'contiguous'` the added `and self.config.linear_cp_layout == 'zigzag'` guard keeps `use_local_packed_roll` at False even when `genuinely_padded`, so the real `cp_group` reaches `_roll_tensor_packed_seq_contiguous`. That combination of P2P exchange plus document/padding masking is only covered by the standalone `test_roll_tensor_with_contiguous_cp_packed_sequences`, not through the HSM block. Adding `(True, False, False)` and `(True, True, False)` to the parametrization covers it at 4 ranks (`tp=1, cp=2`), since packed-without-SP keeps `use_local_packed_roll` False and routes the roll through `_roll_tensor_packed_seq_contiguous` with a real `cp_group`.

`_sentinel_mask` already tolerates rather than requires zeros at shard ends (`tolerated = sentinel & (entry == 0)`), so exchanged tokens still assert exactly. `(False, False, True)` — dense under SP, where the roll degenerates to zeroing the shard seam — would round out the matrix too.

**2. Stale doc line**

`docs/user-guide/features/multi_token_prediction.md:58` still reads:

> Context Parallel (CP), arbitrary `AttnMaskType`, and learned absolute position embeddings are not supported with MTP.

That was already inaccurate for zigzag CP, and this PR removes the last MTP/CP layout restriction from `_validate_cp_layouts`, so it is worth correcting while touching this area — something like: CP is supported with MTP (both `zigzag` and `contiguous` `linear_cp_layout`); arbitrary `AttnMaskType` and learned absolute position embeddings are not.
