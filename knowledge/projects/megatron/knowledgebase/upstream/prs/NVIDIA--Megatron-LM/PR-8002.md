# What does this PR do?
This PR does two things:
1.) First, it fixes a masking bug which causes a block to leak into another block's token, causing duplicate communication. Currently, the channel-masking code only handles the case when `BLOCK_SIZE > numel_per_token` due to power-of-2 padding. However, in the specific case that `numel_per_token` is not a multiple of BLOCK_SIZE and `numel_per_token > BLOCK_SIZE`, in the final window we have a thread array with IDs `[channel_offset, channel_offset + BLOCK_SIZE)`, where `channel_offset + BLOCK_SIZE` is greater than `numel_per_token`. This causes the current block to launch collectives on the channel's of the next token-row, which is already handled by another block, so there is duplicate communication. This special case only arises when `BLOCK_SIZE` is maxed out at 1024 and when the model's hidden size is > 8192 for BF16 values.
2.) Second, it removes the `token_mask` which is actually just redundant since the outer-loop already enforces the range of the `token_offset` counter to be `[pid, local_tokens)`, so we will never cross the boundary of the rank's input buffer. Also I removed `local_numel` since that is no longer used after these changes.
