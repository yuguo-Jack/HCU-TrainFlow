# Warn when finalize_model_grads or the DSGQA indexer reads global groups

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8735) · state: closed · merged: False

## Original PR description

Depends on #8027 and #8049 (which contains #6293). Please review the diff from the merge of their heads: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/9871544a98...yx/pstate-g10-upstream-new-reads). The two PRs conflict only in the process-group usage allowlist, which the merge commit regenerates.

**Why.** Two owners fall back to the global process groups without a warning:
- `finalize_model_grads` without a collection reads seven groups from `parallel_state` up front. It reads the TP x DP x CP group twice more, for the router expert bias and for global-batch quantile balancing, behind their own `pg_collection is None` checks.
- `SimplifiedDSGQAIndexer` without a collection builds `tp` and `cp` with `use_mpu_process_groups()`.

A caller on another grid silently reduces over the global groups, and these fallbacks have no removal date. On main, `tools/check_process_group_usage.py` reports three of these reads (the two TP x DP x CP reads and the indexer's) as new.

**What.**
- `finalize_model_grads`: the no-collection branch builds its groups with one `resolve_process_groups` call. It warns (`ProcessGroupFallbackWarning`, deprecated in 0.21, removed in 0.23) before it reads `parallel_state`. It requests the groups the accessors returned before: `tp`, `pp`, `embd`, `pos_embd`, the GTP-inclusive `dp_cp_gtp_remat`, `tp_dp_cp` and the two GTP groups. The expert-bias and quantile-balancing paths use the resolved `tp_dp_cp`, so the function reads `parallel_state` in one place. The collection path and its validation are unchanged.
- `SimplifiedDSGQAIndexer` resolves `tp` and `cp` through the same resolver. Like `DSAIndexer`, it now warns when the collection is missing. A collection without `tp` or `cp` raises `ValueError`. Its owner, `DSGQACoreAttention`, already passes the attention layer's collection.
- The allowlist goes from 167 to 159 reads, 2 of them guarded.

**Tests.**
- `test_finalize_model_grads.py`:
  - without a collection it warns once, at the caller, and gives the same results on a global PP=4 grid (plain, expert bias, global-batch quantile balancing);
  - it reads the grid only through the resolver, with every accessor patched to raise, and only after it warns;
  - in strict mode it raises before any read.
- `test_attention_variant_dsa_gqa.py`: the indexer warns and resolves `tp` and `cp`, rejects a collection without `cp`, and `DSGQACoreAttention` hands its collection to the indexer.

The ordering test marks the grid as initialized, so it also holds with #8733's no-grid fallback, which reads before it warns.

Before the sync with main, the branch ran on 4 CPU gloo ranks with no regressions: the 3 new indexer tests pass, the new `finalize_model_grads` cases skip without CUDA, and `test_check_process_group_usage.py` passes 35 of 35. In the integration run (main 77391e71cc with all 93 #6307 PRs and the 6 main-based gap fixes merged, against main itself) on 4 GPUs, `test_finalize_model_grads.py` passes 30 tests vs 12 on main, and `test_attention_variant_dsa_gqa.py` passes 51 vs 48. No test in either file fails or skips on either side. The extra passing tests are new tests from #6307 PRs, this PR's among them. They sit in existing test files and do not exist on main, so they have not been observed failing without this change. In the integration run, this PR's test files show no regressions against main.

**Compatibility.**
- Callers that omit the collection get a `FutureWarning` subclass and the same groups as before.
- An explicit indexer collection that lacks `tp` or `cp` now raises `ValueError`. `cp=None` is still accepted, as the existing tests use it. With RoPE on, that `None` reaches `rope_utils.apply_rotary_pos_emb`, which still reads the global CP group silently. That read is out of scope here.
- `examples/mimo/training/grad_sync.py` can pass a `None` collection to `finalize_model_grads` and now warns. Strict mode (#8733) would fail it.
- The explicit 0.21/0.23 versions equal #6293's defaults, so the DSA modules share one deprecation schedule.
- Needs `determinism-exempt` while #6293 and #8027 are unmerged: the kernel coverage check diffs against main and flags their `param_and_grad_buffer.py`, `dot_product_attention.py` and `dsa.py`. This PR's own files do not need it.
