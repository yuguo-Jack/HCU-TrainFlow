# What does this PR do?

Adds an opt-in preflight check that reports, for a configurable set of process groups, each group's ranks, its hosts, and whether it spans nodes, and can warn or fail fast when a group that should stay on one node (tp by default) does not.

## Issue tracking

Linked issue: related to #7627 (first step, topology only; psutil / pynvml resource checks are left for follow-ups)

cc @cspades, this follows your suggestion to cover dp as well and make the groups configurable.

## Design

- after `initialize_model_parallel`, each rank sends `(hostname, {name: group ranks})` through a single `all_gather_object` on the world group, so every rank has the same view and reaches the same decision
- group names map to `parallel_state` getters: `tp, pp, cp, dp, dp_cp, dp_replica, mp, tp_cp, tp_dp, tp_dp_cp, gtp_remat, ep, etp, tp_ep, ep_dp, embd, pos_embd, intra_dist_opt, inter_dist_opt`. groups that are not initialized are reported as skipped
- rank 0 prints one compact summary, e.g.

```
parallel topology check: world_size=16, nodes=2
  tp: 2 group(s) of size 8, 0 span nodes
  dp: 8 group(s) of size 2, 8 span nodes
    ranks [0, 8] on hosts ['node0', 'node1']
    ...
```

- flags (all in `DistributedInitConfig`):
  - `--preflight-check-parallel-topology {off,warn,error}` (default `off`, so existing runs are unchanged)
  - `--preflight-check-process-groups` groups to report (default `tp cp ep dp pp`, comma or space separated)
  - `--preflight-intra-node-process-groups` groups expected to stay within a node (default `tp`); with `warn` a spanning group logs a warning, with `error` every rank raises before training starts
