# Add a dedicated fallback warning and process-group collection helpers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8049) · state: closed · merged: False

## Original PR description

Depends on #6293. Please review the diff from #6293's head: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/4030e3b81f...yx/pstate-b0-fallback-helpers).

**Why.** Every global process-group fallback says "deprecated since 0.21, removed in 0.23" (the defaults in #6293), so fallbacks that start to warn in a later release cannot follow the N+2 policy. The helper warns once per owner, even when one owner has several fallback arguments, and a plain `FutureWarning` cannot be made fatal on its own: torch emits unrelated ones at import. `ProcessGroupCollection` returns `None` for a field that was never set, so a component cannot tell a missing field from an axis that is off.

**What.**
- `ProcessGroupFallbackWarning(FutureWarning)`. `warn_global_process_group_fallback` emits it, takes per-call `deprecated_in`/`removed_in`, and warns once per (owner, argument). Under an `error` filter every fallback raises.
- `require_process_groups(pg_collection, names, owner=...)` returns the groups in order. An absent field or `NON_GROUP_MEMBER` raises `ValueError` naming the owner and fields; an explicit `None` is allowed. A `MultiModuleProcessGroupCollection` raises `TypeError`.
- `resolve_process_groups(pg_collection, owner=..., required=...)` is the one sanctioned fallback: warn, build only `required` from `parallel_state`, validate.
- The process-group checker counts these calls as `guarded` reads. Replacing a read in the same function swaps the allowlist entry through `--update`; any other new guarded call fails. `--stats` lists guarded reads separately.

No call site changes, and read counts are unchanged.

**Tests.** New unit tests cover the warning, versions, deduplication, strict mode, `require`, `resolve` (including four pipeline stages, where the middle stages have `embd=None`) and the checker. They fail on #6293's head. In the integration run on 4 GPUs (main with all #6307 PRs merged), this PR's test files have no failures and no regressions against main: `tests/unit_tests/test_check_process_group_usage.py` has 70 passed vs 29 on main, `tests/unit_tests/test_process_group_fallback.py` has 34 passed (the file is not on main), and `tests/unit_tests/test_process_groups_config.py` has 42 passed vs 11 on main.

**Compatibility.** Additive; `FutureWarning` filters still match and existing messages are unchanged. For strict mode use `warnings.simplefilter("error", ProcessGroupFallbackWarning)` or pytest's `-W`; `python -W` and `PYTHONWARNINGS` cannot resolve the class at startup.
