## What does this PR do?

This PR does two things:

1. **Refines the residual contract:** each connection owns the complete state passed from read to write and explicitly defines its replay policy. WideResidual is adapted to this contract.
2. **Reorganizes implementation files:** groups WideResidual parameters, math, and policy in one module; consolidates shared replay planning and dispatch; and gives WR and mHC separate Transformer adapter files. Checkpoint keys are preserved.


### Refining residual contracts

Let each residual connection select the complete state carried from its read to the matching write. The shared path validates `(carried_residual, *algorithm_state)` and passes it through unchanged, preserving tensor aliases and gradients through additional state.

Read and write replay now require explicit implementation policies. Wide Residual supplies those policies, while common replay code handles context, planning, and dispatch. WR parameter ownership, checkpoint keys, arithmetic, and replay ordering are preserved.

### File organization blueprint

Shared contract and replay infrastructure stay separate from algorithm implementations. Each algorithm keeps its parameters, math, and state/replay policy together, with separate Transformer and Mamba adapters.

```text
megatron/core/transformer/
├── residual_connection.py                 # Shared read/write contract
├── residual_recompute.py                  # Shared replay planning, context, and dispatch
├── wide_residual.py                       # WR parameters, math, and state/replay policy
├── wide_residual_transformer_layer.py      # WR Transformer adapter
├── hyper_connection.py                    # mHC parameters/math; policy integration follows
└── hyper_connection_transformer_layer.py   # mHC Transformer adapter
```

Mamba adapters remain under `megatron/core/ssm/`. `wide_residual_layer.py` and `residual_recompute_plan.py` are removed; callers import from the canonical modules above.

This PR establishes the WR layout and moves the existing mHC Transformer adapter to `hyper_connection_transformer_layer.py`. Future mHC connection, context, and policy definitions belong in `hyper_connection.py`, with parameter ownership kept separate from the policy classes. mHC consumer integration remains follow-up work.


## File layout and movement

Paths below are relative to `megatron/core/transformer/`.

| Previous location | New location | Contents |
|---|---|---|
| `wide_residual_layer.py`  | => `wide_residual.py` | WR parameters, maps, readout, stream expansion, connection, and legacy state loading. |
| `residual_recompute.py` | => `wide_residual.py` | WR read/write replay and enable predicate, adapted to explicit policy hooks. |
| `residual_recompute_plan.py`  | => `residual_recompute.py` | Shared block planning, manager allocation, and finalization. |
| `wide_residual_layer.py`  | => `wide_residual_transformer_layer.py` | WR Transformer adapter with registered readers and writers. |
| `transformer_layer.py` | => `hyper_connection_transformer_layer.py` | Existing HyperConnection Transformer layer, moved unchanged. |

`residual_connection.py` retains the shared contract and validation. Shared Transformer execution stays in `transformer_layer.py`. Repository mHC layer imports target `hyper_connection_transformer_layer.py` directly. A lazy export in `transformer_layer.py` preserves ordinary imports of `HyperConnectionTransformerLayer` from its old location.
