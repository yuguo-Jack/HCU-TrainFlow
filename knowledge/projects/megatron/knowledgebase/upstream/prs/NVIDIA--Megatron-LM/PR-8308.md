# Support GDN2 and TE CUDA graphs for recurrence offloading

# What does this PR do?

Extend opt-in `gdn_core_attn` activation offloading to BF16/FLA GDN2 training and Transformer Engine CUDA graphs for GDN and GDN2. The existing recurrence scope, backward prefetch anchor, transfer streams and pinned-memory pool are reused. TE layer-graph replay stays on the caller's autograd stream so shared graph pools remain ordered.

GDN2 keeps sigmoid gate outputs resident when gate backward retains the same storage: the differentiable write gate and the differentiable erase gate without head expansion. This avoids transfers that cannot release the original GPU storage.

Attention and whole-layer TE graphs, `gdn_norm_out` recomputation and delayed offload are supported. Graph offload requires PyTorch >= 2.9, TE >= 2.14 and positive graph warmup; set `NVTE_CPU_OFFLOAD_V1=1` before launch. GDN2 requires `fla.ops.gdn2`. FP8/FP4, full recomputation and local/full-iteration graphs are outside this PR; low precision is proposed in #8543. See [configuration and usage](https://github.com/Pinoeer-kingxi/Megatron-LM/blob/03b5ef353a1e657a89247f1ae0f67d05d619166f/docs/developer/gdn_activation_offloading.md).

## Memory and runtime

At earlier head `c5264b66197040f4309edfdb22dc9bbaf62189b1`, BF16 whole-layer graph training on one RTX PRO 6000 used sequence 2048, four microbatches, fraction 1, the default threshold and no norm recomputation. Each fresh-process arm uses three warmup steps and ten measured optimizer steps; capture is timed separately. Peaks are medians of the per-arm peaks, and step changes are paired medians and ranges.

| Model | Allocated peak off → on (MiB) | Reserved peak off → on (MiB) | Retained pinned memory on (MiB) | Step-time change, median [range] |
| --- | --- | --- | --- | --- |
| Qwen3.5-0.8B language model | 16137.82 → 16137.82 | 22576 → 22122 | 504 | +24.75% [+12.71%, +26.55%] |
| GDN2, eight blocks | 3236.12 → 3237.12 | 5212 → 4964 | 432 | +97.83% [+96.40%, +98.97%] |

The Qwen row uses five pairs because of timing variation; GDN2 uses three. These runs reduce reserved memory but not the measured allocated peak. No other compute process was observed on the measured GPU, but other GPUs were shared; host and PCIe isolation are not established. [Commands, rank logs, samples, telemetry and audit](https://github.com/Pinoeer-kingxi/Megatron-LM/tree/02890e97b1273d9a8695f76aaa208730054fe415/gdn-open-issues-20261027).

A separate allocator snapshot at the same head and Qwen configuration locates the measured peak during output projection and cross-entropy: 970 MiB of logits and a 1940 MiB FP32 conversion are live together. In the snapshot after that step, the graph pool reserves 4132 → 3690 MiB, while its allocated count is 46 MiB in both arms. In the GDN2 snapshot, graph-pool reserve also decreases, while the total allocated peak increases by 1 MiB. These observations apply to the measured configurations.

As an exploratory follow-up, smaller offload fractions and the existing delayed-offload option did not reduce allocated peak in this configuration. The delayed-offload arm matches losses, gradients, weights and complete optimizer states for six steps; the timing samples are not sufficient to establish a performance improvement. [Snapshot traces, commands, comparison data and audit](https://github.com/Pinoeer-kingxi/Megatron-LM/tree/8d797dac14e007c1c77954b90c40ad8861566184/gdn-graph-memory-20261027).

Earlier A6000 measurements and a gate-selection experiment used different revisions and are retained in the [historical graph-training evidence](https://github.com/Pinoeer-kingxi/Megatron-LM/tree/6ec7df0dc5adcd9f704077636398999ebdfea027/gdn-graph-training-20261017) and [profile](https://github.com/Pinoeer-kingxi/Megatron-LM/tree/95ba13de41c85950511bfdb7bb481df2235d1d57/gdn-graph-profile-20261017). The historical Qwen graph run omitted mRoPE and is not a valid correct-training performance result.

The option remains disabled by default.
