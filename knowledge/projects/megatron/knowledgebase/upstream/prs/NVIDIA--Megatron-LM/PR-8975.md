# [Test][Inference] Independent oracles for SSM inference

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8975) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Adds independent oracle tests for the SSM inference kernels: the Mamba-2 decode kernel, the static-batching Mamba decode dispatch, the Mamba-2 varlen prefill scan, and the KDA (Kimi Delta Attention) core around FLA's `chunk_kda`. Each test checks its kernel against a reference written from the model math, not from the kernel's code. The files are in `tests/unit_tests/inference/oracles/ssm/`.

No production code changes.

**Stacked on the oracle harness PR #8966 (`test/inference-oracle-harness`)**, which adds the shared helpers these tests use. Retarget to `main` once it merges.

## Why

Before this PR, no test checked the outputs of these paths against an independent reference:
- **Mamba decode.** Nothing compares `selective_state_update`, Mamba's decode kernel with speculative snapshots, against a reference. Two tests touch it: one checks that inputs stay unchanged, the other that a run replays.
- **Static-batching decode.** `MambaMixer._static_decode` has only a shape smoke test, at batch size 2.
- **Prefill scan.** The only independent check of the prefill output `y` (`_chunk_scan_fwd_kernel`) covers:
  - one sequence;
  - no initial state, although every chunked-prefill continuation and every prefix-cache hit starts from one;
  - and it is skipped unless `MAMBA_DETERMINISTIC=1`.
- **KDA.** The KDA tests compare the kernel with itself, packed against unpacked or TP against TP 1. No test compares the layer with the KDA recurrence.

## The oracles

Each module's docstring holds its contract, written from the model math, the call sites and the kernels' documented APIs before the kernels were read. The tolerances follow the harness policy:
- the kernel's max-abs and rms errors against an fp64 reference must be at most 2× those of a trusted implementation, plus one ulp;
- no hand-picked atol;
- copies, padding and untouched memory are checked exactly.

1. **`_selective_scan_update_kernel`** (`test_selective_state_update.py`).
   - **Reference:** the Mamba-2 decode recurrence in fp64, token by token, per request:
     `dt' = softplus(dt + dt_bias)`; `h = exp(A dt') h + dt' x B`; `y = C·h + D x`, gated by `z σ(z)`.
     It produces the output, the snapshot after each token and the final state.
   - **Trusted:** the same recurrence in torch fp32 on the GPU.
   - **Exact checks:**
     - rows with slot `-1` give zero output;
     - slots no row maps to stay untouched, including the last slot;
     - unwritten snapshots stay NaN, and inputs are unchanged;
     - the `mamba_state_selective_copy` rollback is an exact copy of the accepted snapshot.
2. **`MambaMixer._static_decode → ssm_decode`** (`test_mamba_static_decode.py`).
   - **Reference:** an fp64 mixer-level decode step per request: conv shift, SiLU conv, SSM step, gated group RMSNorm. It is fed the captured `in_proj` output and each request's own cache slots.
   - **Trusted:** the same step in fp32, rounding where the module rounds.
   - **Checks:**
     - `out_proj`'s input, bounded per request;
     - the new SSM state, bounded;
     - the new conv state, exact.
3. **`_chunk_scan_fwd_kernel`** (`test_chunk_scan_varlen.py`), called through `mamba_chunk_scan_combined_varlen`.
   - **Inputs:** chunk metadata comes from the production `MambaMetadata.compute_cpu_metadata`, with padding.
   - **Reference:** an fp64 token-by-token recurrence per request from its initial state, with no chunking. It covers the output, the final states and the chunk-exit states that the prefix cache stores.
   - **Trusted:** pip `mamba_chunk_scan_combined`, the training scan. It runs the same chunked algorithm, so it has the same bf16 and TF32 tensor-core rounding. It runs per request with `initial_states`, and on prefixes for the exit states.
   - **Composition:**
     - chunked prefill at `p = 1, c−1, c, c+1`;
     - prefix-cache restore from chunk-exit states at `c` and `2c`;
     - each must continue the fp64 recurrence of the whole request.
4. **The KDA core** (`test_kda_chunk.py`).
   - **Reference:** a `KimiDeltaAttention` forward at TP 1 against an fp64 token-by-token gated delta rule, with explicit conv, gates, L2 norm, β and gated norm, fed the module's own weights. FLA's `naive.py` is not used.
   - **Checks:** the `chunk_kda` output, the gated norm and the module output.
   - **Exact checks:** the call-site arguments, and that the kernel inputs, which sit in NaN guard buffers, are read-only.

Memory safety:
- **Guard bands:** on the state, snapshot and output buffers, and on KDA's kernel inputs.
- **NaN poisoning** of every input that must not be read:
  - unmapped slots and `-1` rows;
  - padded prefill requests' initial states;
  - padded tail tokens, whose output rows must stay poisoned.
- **`sanitizer` marker** on one small case per kernel.

## What it covers

- **Decode kernel.**
  - **Tile classes:** every `(BLOCK_SIZE_M, num_warps)` class. On GB200, the cc ≥ 10 `(32, 8)` tile for `dstate > 64` (`launch_on_gb200`).
  - **dstate:** 1, 15/16/17, 31/32/33, 63/64/65, 127/128/129 and 256.
  - **Head dim:** BLOCK_SIZE_M−1, BLOCK_SIZE_M and BLOCK_SIZE_M+1, and 64.
  - **Shapes:** S = 1, 2 and 4. Head/group layouts (1,1), (8,1), (8,2) and (8,8).
  - **Layouts:** the production TIE_HDIM stride-0 layout, its materialized copy, and a general A/dt.
  - **Options and indices:** z, D per head or per channel, no dt_bias, no softplus; int64, int32 or no indices.
  - **Launcher:** its reshapes.
  - **Special values:** the softplus threshold (dt + dt_bias = 19.5/20/20.5), A from −1e-3 to −16, and a NaN in one request.
  - **int32 offsets:** slot offsets at 2³¹ elements (`large`).
- **Static decode.**
  - b = 1, 2, 3 and 8, including one head;
  - rmsnorm on and off, D_has_hdim;
  - three chained steps;
  - a static prefill of 3/4/5 tokens (around d_conv) and 127/128/129 (around the chunk), then decode. The conv cache after the prefill is checked exactly.
  - **Production layers** from the in-tree Nemotron-H configs, two chained steps each, at b = 1 and at a full static batch:
    - Nemotron-H 8B: hidden 4096, 128 heads of 64, 8 groups, dstate 128, b = 64;
    - Nemotron Nano 9B v2: hidden 4480, 128 heads of 80, b = 64. Head dim 80 is 2.5 Blackwell tiles;
    - Nemotron-H 56B: hidden 8192, 256 heads of 64, dstate 256, b = 32.
  - **Memory:** two steps on static caches placed in guard bands (the file's sanitizer case).
  - On H100 and on GB200, where the decode kernel uses another tile for dstate > 64.
- **Prefill scan.**
  - **Autotune configs:** every one of the 11 that the GPU can launch, pinned in turn, on the one-dot (dstate 128) and K-loop (dstate 256) branches. A config beyond the device's shared memory (on H100, M128 N256 K64 at dstate 128) is dropped only after checking that error; the test then checks that the pinned policy's cheapest fallback and the config timed autotuning picks both launch.
  - **Chunk sizes:** 64, 128 and 256.
  - **Request lengths:** 1, c−1, c, c+1, 2c, 2c+3 and 3c+5, plus zero-length padded requests and padded tail tokens.
  - **dstate:** 64, 128, 129 and 256.
  - **Other inputs:**
    - initial states random, zero or absent;
    - z, and D per head or per channel;
    - bf16 or fp32 activations, and fp32 or bf16 states.
- **KDA.**
  - T = 1, 2, W−1, W, W+1, 63/64/65 and 127/128/129;
  - THD packs with boundaries at chunk offsets 0, 1 and 63;
  - K = 32, 64, 128 and 96; H = 1 and 4;
  - direct and two-stage gates;
  - softplus and both lower-bound gate forms;
  - deterministic mode on and off;
  - RMSNorm, LayerNorm and zero-centered gamma.
  - **Production:** a Kimi Linear layer (hidden 2304, 32 heads, K = V = 128) at TP 1, on H100 and GB200 (FLA autotunes over different tile lists there):
    - its two-stage gates on a 4096-token pack of six sequences, with boundaries at chunk offsets 0, 1 and 63;
    - direct gates and the safe gate on 4 × 1024 tokens.

## Tests

| File | Cases | Hardware |
|---|---|---|
| `test_selective_state_update.py` | 118 H100-only (+2 `large`), 117 GB200-only, 9 on both, 1 CPU | 1 H100, 1 GB200 |
| `test_mamba_static_decode.py` | 33 (7 also on GB200), +1 CPU | 1 H100, 1 GB200 (TE, mamba_ssm) |
| `test_chunk_scan_varlen.py` | 28, +1 CPU | 1 H100 (mamba_ssm as the trusted implementation) |
| `test_kda_chunk.py` | 67 (2 also on GB200) | 1 H100, 1 GB200 (TE, FLA) |

On H100 (first run, before the follow-up commit): 183 passed, 2 failed, 2 `large` skipped; the sanitizer pass (9) and the `large` cases (2) pass. On GB200: 65 passed, 1 failed. Every expected failure below failed on both. The three regression failures are addressed: the fp32-state rollback case is O7-N1 and moved to its expected-fail set; the H100 tile failure was the test forcing a config the kernel cannot select there.

Checked on CPU with the Triton interpreter, on `main`: Two interpreter artifacts were shimmed in the scratch runner, not in the PR: bf16 `tl.dot` on raw bits, and truncating fp32→bf16 casts.
- **Decode kernel**, under both architectures' tile tables: 213 of 245 pass.
  - The 32 failures are the fp32 cases of finding O7-N1 below.
  - With the kernel's softplus formulation in the trusted implementation, all 245 pass.
- **Prefill scan**, at reduced sizes (chunk 16/32, dstate 16/129): 45 of 45 pass. This covers all 11 tile configs, the compositions and padding. pip `mamba_ssm` is not installed there, so the factor-2 bound itself was not checked.
- **Static decode.** The real `_static_decode`/`ssm_decode` and Triton kernels ran on a stand-in module, through the test's own checker:
  - batch 1 passes on `main`;
  - batch 3 fails on `main` and passes with #8568's transposes;
  - D_has_hdim fails on `main` and passes with #8569's layout.
- **KDA.** The reference was cross-checked against a second fp64 formulation. Real `chunk_kda` did not run on CPU.

Expected to fail on `main` (the manifest runs these as expected-fail tasks):
- **`test_mamba_static_decode.py`, every case with b > 1** (20 cases, including the three production layers at a full batch on H100 and GB200). `_static_decode` passes the sequence-first `(1, b, proj)` projection to `ssm_decode`. `ssm_decode` reads it as one request with b tokens:
  - requests 1..b−1 are decoded on slot 0's state;
  - their own slots never advance.

  **#8568 (d6)** fixes this.
- **`test_mamba_static_decode.py`, the D_has_hdim cases** (6, all at b = 1). The kernel reads `D[head]` for every channel. **#8569 (s10)** fixes this.
- **`test_kda_chunk.py::test_kda_matches_fp64_reference[two_stage-zero_centered]`.** The zero-centered gain `w + 1` is formed in bf16, so `w = 0.0038` becomes exactly 1.0 (R01-F1). **#8882** fixes this.
- **Finding O7-N1** (new, low severity, confirmed on H100 and GB200): `test_decode_step_fp32_outputs_match_fp64` and its Blackwell twin fail on some cases, and `test_production_shapes[fp32_state]` and `test_speculative_rollback_restores_accepted_prefix[fp32_state]` fail.
  - **Cause:** the decode kernel computes softplus as `log(exp(x) + 1)` in fp32 (`mamba_ssm.py:34-36`). That has an absolute error of about 2⁻²⁴.
  - **Size:** at production arguments (dt' ≈ 1e-3) it is a relative error of up to 5.5e-5, against 3.6e-8 for `log1p`. `exp(A dt')`, with |A| up to 16, carries it into the fp32 state.
  - **Measured:** on the production shape with an fp32 state, the state's rms error is 3.3× torch fp32's (2× allowed).
  - bf16 states and outputs are rounding-dominated and pass.
  - **Fix direction:** a `log1p`-based softplus.

## Notes for reviewers

- **CI buckets.** `test_chunk_scan_varlen.py` (909 s) and `test_kda_chunk.py` (1048 s) step fp64 references token by token, so each gets its own H100 unit-test bucket next to the oracle directory's. On GB200 the family stays in the directory bucket (226 s).

- **The KDA kernel and module outputs use factor 4** (`CHUNKED_FACTOR`). FLA keeps its intra-chunk matrices, WY factors and chunk states in bf16, which costs a correct kernel about 2–3× the error of the fp32 reference. This is reasoned from FLA's source; the first H100 run must confirm it. The gated norm, where R01-F1 lives, keeps factor 2.
- **The prefill scan's trusted implementation is pip `mamba_chunk_scan_combined`.** The fork rounds the incoming state and `C·B` blocks to bf16 for tensor-core dots, as the training scan does. An fp32 recurrence would be about 100× more accurate, so it cannot be the yardstick. On a GPU without `mamba_ssm` the test fails rather than skips.
- **The decode sweep is split by output precision.** One part has bf16 outputs and states; the other has an fp32 output or state, where the kernel's own fp32 error meets the bound. Each part is generated pairwise and covers every tile class, so the O7-N1 cases can be deselected without losing coverage.
- **The static-decode cases isolate each PR.** D_has_hdim runs only at b = 1, so each failing case points at one PR.
- **Not covered:**
  - TP 2;
  - the batch-invariant tile fallback (target-rows mode);
  - `dt_limit` other than `(0, inf)`;
  - a non-unit dstate stride of the initial states (no caller passes one);
  - the static decode path at 2³¹ state elements (an i32 product, at an unrealistic batch);
  - KDA under TP/SP/CP, FP8, the inference-optimized spec and #8710's `fused_recurrent_kda` path.
- **Production cases run as their own tasks on H100.** The H100 regression run of these files takes about 1700 s of the runner's 1800 s, so the production static-decode and KDA cases have their own tasks there. On GB200 they run with the regression set. They have not run on a GPU yet; with the Triton interpreter, the production static-decode layers pass at b = 1 on `main` under both tile tables, and with #8568's transposes at b > 1.
- **The KDA factor 4 is measured only up to T = 193.** At the production pack's 2048-token sequence, FLA keeps its chunk-to-chunk state in fp32 and rounds only the per-chunk copies that feed the output to bf16. The relative error should therefore not grow with T, but this is reasoned, not measured.
- **Determinism.** No kernel or dispatch changes, so there is no determinism test or manifest entry.
