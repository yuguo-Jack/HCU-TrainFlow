# Fix MFSDP v2 child checkpoint replay by gathering parent weights

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7836) · state: open · merged: False

## Original PR description

# What does this PR do?

Gather an FSDP unit's weights before checkpoint recomputation calls one of its regular children directly. This allows a checkpointed norm to stay inside its parent FSDP unit.

`CheckpointWithoutOutputManager` can replay earlier layers from a hook on the final output. A call such as `unit.norm(x)` then runs before `unit`'s backward-pre hook. Without a gather, the norm reads sharded DTensor weights and fails with a mixed Tensor/DTensor error.

The fix registers forward-pre hooks on descendants whose parameters belong to the current FSDP unit. During backward replay, the hook calls the owner's `pre_backward()` before the child executes. Only the child is recomputed; its owner continues to handle gradient reduction and weight release. Normal forward calls do not trigger this extra backward preparation.

## Issue tracking

Fixes #7777.

**Depends on #7757** and targets `pull-request/7757`. Its idempotent backward-entry guard handles the later parent backward hook and multiple replayed children. Retarget to `main` after #7757 merges.

This is an alternative to #7819, which makes replayed norms/residual helpers separate FSDP units. That workaround is not merged, so this upstream diff adds the parent-gather hook without an adapter change.

## Validation

The test uses the actual `CheckpointWithoutOutputManager` across two units. Each unit checkpoints its norm, and one shared hook replays the norms from the final output. It compares five SGD updates against an unsharded baseline with explicit DP gradient averaging, for both parent-only sharding and separately sharded norms.

- Before: parent-only sharding fails on both GPUs with `aten.native_layer_norm.default got mixed torch.Tensor and DTensor`; separately sharded norms pass.
- After: the new tests plus the complete `test_fully_shard.py` pass on two GPUs: **35 passed, 6 skipped per rank**. The six skipped cases require at least four ranks. This includes shared MTP and reentrant/non-reentrant checkpoint tests.
- `tools/autoformat.sh` completed, and `git diff --check` passed. The local tools report an existing `.pylintrc` option warning and the pre-existing, non-blocking mypy error at `module.py:247` (`register_load_state_dict_pre_hook` on the mixin).

```bash
python -m torch.distributed.run --standalone --nproc-per-node=2 -m pytest -q \
  --confcutdir=tests/unit_tests/distributed/mfsdp_v2 \
  tests/unit_tests/distributed/mfsdp_v2/test_activation_recompute.py \
  tests/unit_tests/distributed/mfsdp_v2/test_fully_shard.py
```

An equivalent hook was also tested in the NT4 Nano SFT fork on the same **64 GB300 GPUs**, with 512K context, BF16 compute, AdamW, random initial weights and real text data. Both variants include #7612, keep default prefetch enabled, and disable training/optimizer CUDA graphs and profiling. Each gets 24 cache-warming steps followed by a fresh 24-step measured run. Times use steps 6–20; memory is the maximum per GPU across all ranks in that window.

| Replay implementation | FSDP units | Mean step | Peak active | Peak reserved |
| --- | ---: | ---: | ---: | ---: |
| Separate child units (#7819 workaround) | 263 | 4.4152 s | 125.1948 GiB | 150.7559 GiB |
| Gather parent before child replay | 105 | 4.0226 s | 122.3138 GiB | 146.4648 GiB |

All 24 steps have finite losses/gradient norms and matching sample counts, valid-token counts and learning rates. Maximum relative loss difference is 0.02224%; no OOMs or allocator retries occurred. These workload numbers are from the fork implementation, not a full upstream functional test. Both variants used BF16 gradient communication. Broader correctness coverage remains part of draft review.
