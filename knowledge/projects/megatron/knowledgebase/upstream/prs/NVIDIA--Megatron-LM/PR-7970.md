# Fuse the residual and bias adds into their neighbours: proj bias in the MXFP8 GEMM epilogue (with BGRAD in the dgrad epi

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7970) · state: open · merged: False

## Original PR description

Proj bias moved into the GEMM epilogue, residual adds fused into the MoE combine and the norm backward.

Numerics: not bit-identical to the unfused baseline: the proj bias is added in fp32 in the GEMM epilogue before the bf16 rounding and its gradient comes from the GEMM's bgrad; the MoE combine seeds the fp32 accumulator with the residual and rounds once.

Tests: black/isort/pylint clean; CPU tests for the HybridEP combine-with-residual and the Triton kernel under TRITON_INTERPRET=1 pass; GPU tests test_fused_unpermute_add and test_gpu_forward_row_parallel_bias_gemm_fusion written, not run

---
Addendum (2026-10-12): two more default-off knobs in the same residual-stream family. `fused_residual_rmsnorm_quantize_grad`: a TE `Quantize(forward=False, backward=True)` op at the head of the fused residual RMSNorm, so the attention projection receives its MXFP8 grad output from the fused backward instead of a separate cast (bias gradient summed by torch, last-bit different from TE's `bgrad_quantize`). `moe_router_grad_fusion`: the router's input gradient is added inside the dispatch backward's unpermute (one bf16 rounding instead of two). The quantized hand-off relies on TE keeping the high-precision values on MXFP8 tensors (TE branch `gap-norm-bwd-fused-pass` @ 1c7dadb5, carried as a patch in the submission image).
