# test: quarantine auxiliary-loss tests that reinitialize process groups

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8238) · state: closed · merged: True

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Temporarily exclude five auxiliary-loss test functions (30 parameterized cases) from development CI using function-level `flaky_in_dev` markers:

| Function | Cases |
| --- | ---: |
| `test_force_balanced_aux_loss` | 5 |
| `test_seq_aux_loss` | 5 |
| `test_seq_aux_loss_mbs_invariant_per_token_loss` | 10 |
| `test_global_aux_loss` | 5 |
| `test_combined_aux_loss` | 5 |

All five functions reinitialize model parallel after `TestRouterAuxLoss.setup_method` has initialized it, exposing the shared process-group teardown/reinitialization race tracked in #7745. LTS eligibility, parameter values, assertions, and test bodies are preserved.

The confirmed recurring failure is in `test_force_balanced_aux_loss`: after #8206 quarantined `[8-1-1]`, [merge-queue job 116102125211](https://github.com/NVIDIA/Megatron-LM/actions/runs/38630673719/job/116102125211) reported a 1,800,000 ms store timeout in `[4-2-1]`. Its source includes the earlier quarantine. The four additional functions are precautionary containment of the shared initialization pattern, not claims of independently observed flakes. This expands the previous one-case exclusion to 30 cases, adding 29 development exclusions in total.

## Issue tracking

Related to #7745; extends #8206 while the initialization fix in #8164 is validated. This quarantine does not fix the race. Keep the issue open and restore coverage after repeated distributed validation.
