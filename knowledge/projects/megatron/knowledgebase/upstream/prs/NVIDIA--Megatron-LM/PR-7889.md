# fix(gtp): preserve FP32 reduce-scatter outputs until gradient accumulation

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7889) · state: closed · merged: True

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

When GTP uses FP32-accumulating reduce-scatter with BF16 gradients, the FP32 shard sum is currently rounded into a BF16 output before being added to `main_grad`. Keep both the synchronous output and asynchronous cache buffers in FP32 so a BF16 `main_grad` rounds the sum only during accumulation. For example, a shard sum of 1001 added to an initial gradient of 2 now produces 1004 instead of the double-rounded 1000.

Extracted from #7450 following [the GTP review request](https://github.com/NVIDIA/Megatron-LM/pull/7450#discussion_r4170037275). This fix applies without MoonEP and is independently mergeable into main. It retains the existing opt-in flag and bypasses for groups of two ranks or fewer and symmetric-memory groups.

### Validation

- Four-GPU torchrun: the standalone synchronous and asynchronous regressions both passed on every rank.
- The asynchronous regression checks the FP32 output and cache dtype and the exact shard sum; both cases check the final BF16 gradient exactly.
- Black, isort, whitespace checks, and the kernel determinism coverage check passed. GTP collectives retain their existing registry exemption.
