# build(security): patch wandb and pynvvideocodec vulnerabilities

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6605) · state: closed · merged: True

## Original PR description

## Background / motivation

- The October 21 scan of `nvcr.io/nvidian/nemo:26.10.rc7` reports SSH connection deadlocks in `golang.org/x/crypto v0.55.0`, gRPC denial of service issues in `google.golang.org/grpc v1.83.0`, and the FFmpeg 8.1.1 MagicYUV out-of-bounds write on amd64 and arm64.
- These libraries are embedded in the image's two `wandb-core` binaries and the base image's PyNvVideoCodec installation.

## What changed

- Rebuild the virtual-environment `wandb-core` with `golang.org/x/crypto v0.56.0`; explicitly preserve the system source's newer `v0.57.0` dependency.
- Raise the system copy's gRPC pin to `v1.83.2`, matching the virtual-environment rebuild and covering both reported gRPC fixes.
- Upgrade the system PyNvVideoCodec installation from `2.0.4` to `2.0.5` in the existing image package installation layer.

## Details

- Keep each W&B rebuild tied to the Python package version from its owning interpreter.
- [PyNvVideoCodec 2.0.5](https://pypi.org/project/pynvvideocodec/2.0.5/) bundles FFmpeg 8.1.2 on both architectures. Both wheels omit `libavcodec`; upgrading also removes the old installation's vulnerable `libavcodec.so`.
- Changes are confined to `docker/Dockerfile.fw_final`.

## Tested

- Container: `gitlab-master.nvidia.com:5005/dl/joc/nemo-ci/r26.10/fw-final:pipe.75385261`, using Docker's `runc` runtime.
- `uv run --no-sync pre-commit run --all-files` and `git diff --check`: passed.
- `uv pip install --python /usr/bin/python3 --system --no-deps 'pynvvideocodec==2.0.5'` with `UV_BREAK_SYSTEM_PACKAGES=1`: upgraded `2.0.4` to `2.0.5`; `libavutil.av_version_info()` returned `8.1.2`; the installed package contains no stale `libavcodec*` files.
- Inspected the official CPython 3.12 amd64 and arm64 PyNvVideoCodec wheels: both include `ffmpeg-8.1.2.tar.xz`, report the `8.1.2` library version, and omit `libavcodec`.
- Executed both Dockerfile W&B rebuild commands for W&B `0.29.0` (virtual environment) and `0.30.0` (system installation). Also ran `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags="-s -w"` for each source tree.
- `go version -m` on all four resulting binaries: `golang.org/x/crypto v0.56.0` for the virtual-environment copy, `v0.57.0` for the system copy, `google.golang.org/grpc v1.83.2` throughout, and the expected `GOARCH`. The system rebuild preserves `golang.org/x/net v0.59.0`.
- Offline `wandb.init`, `run.log`, and run completion passed with both rebuilt amd64 binaries.
- [nemo-ci pipeline 75623555](https://gitlab-master.nvidia.com/dl/JoC/nemo-ci/-/pipelines/75623555) on `main-mirror`, with `MEGATRON_BRIDGE_REF=bf43860f507e58eba6b9d88fe25fcecbb1cb6164`: passed. The full fw-base → Megatron-Bridge → fw-final chain built on amd64 and arm64; all three image import checks passed. Model tests and NVCR publication were disabled for this build.
- Published image: `gitlab-master.nvidia.com/dl/joc/nemo-ci/main-mirror/fw-final:pipe.75623555`; multi-architecture digest `sha256:ab7c94b105460fd588cbf7edce4ab1cfe27425bce92e84bf05383b63dfa510d0`.
- Inspected the published image layers on both architectures: both `wandb-core` binaries contain the expected patched modules; the FFmpeg library hashes match the official PyNvVideoCodec 2.0.5 wheels; layer removal markers delete the old `libavcodec` files. The combined manifest points to these verified architecture digests.
- `docker pull --platform linux/amd64 gitlab-master.nvidia.com/dl/joc/nemo-ci/main-mirror/fw-final:pipe.75623555`: passed, resolving to the digest above. Started the pulled image with Docker's `runc` runtime and checked the exact reported paths. `/opt/venv/lib/python3.12/site-packages/wandb/bin/wandb-core` contains x/crypto `v0.56.0` and gRPC `v1.83.2`; `/usr/local/lib/python3.12/dist-packages/wandb/bin/wandb-core` contains x/crypto `v0.57.0` and gRPC `v1.83.2`. The installed PyNvVideoCodec version is `2.0.5`, `av_version_info()` returns `8.1.2`, and `/usr/local/lib/python3.12/dist-packages/PyNvVideoCodec/` contains no `libavcodec*` files.
- GPU runtime validation and full vulnerability scans remain pending.
