# fix(model): install the Step-3.5 shared-expert MLP for partial MoE specs

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6752) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Makes the shared experts of **Step-3.5-Flash** and **Step-3.7-Flash** clamp their SwiGLU with their own `swiglu_limits_shared`, as Hugging Face does. Today they use the routed experts' clamp (`swiglu_limits`) instead, which is the largest Megatron-vs-Hugging Face logit difference for both models.

# Changelog

Step-3.x clamps the SwiGLU of the routed experts and of the shared expert separately, per layer. Both published configs clamp the routed experts of layers 43 and 44 at 7. Step-3.7 clamps their shared experts at 16; Step-3.5 clamps only layer 44's (16). Hugging Face leaves a shared expert without a limit unclamped. Bridge applies the shared-expert value with `Step35SharedExpertMLP`, which `build_step35_layer_spec` installs by replacing the MoE spec's `shared_experts` builder.

- **Install the shared-expert MLP** (`step35_bridge.py`): `build_step35_layer_spec` looked for the builder in `spec.submodules.mlp.submodules`. Megatron Core builds a MoE layer as `functools.partial(MoELayer, submodules=MoESubmodules(...))`, which has no `submodules` attribute, so the replacement was skipped silently and the shared experts were plain `SharedExpertMLP`s. Every Megatron Core version Bridge has pinned since the replacement was added builds MoE layers this way (be2b2cd70, 5de526f2, today's 902feb8ee, `.dev.commit` 4a4de865, dev c4220af3a), so the lookup now reads the partial's keywords only. Dense and MTP layers have no shared expert and are unchanged.
- **No fallback to the routed clamp** (`Step35SharedExpertMLP`): a layer without a shared-expert limit (Step-3.5's layer 43) fell back to the routed experts' clamp; its shared expert now runs unclamped, as in Hugging Face.
- **Tests**:
  - The layer-spec tests mocked the MLP spec with a `submodules` attribute, which is why the bug went unnoticed; they now use the `partial` form.
  - New tests build the specs with Megatron Core's own `get_gpt_decoder_block_spec`, for the builder-backed model config and the deprecated provider: MoE layers build `Step35SharedExpertMLP` with Megatron Core's original arguments; dense and MTP layers are unchanged.
  - Per MoE layer, the shared expert built from the spec clamps at its own `swiglu_limits_shared` (unclamped for 0) while the routed experts keep `swiglu_limits`, modeled on Step-3.5's layers 43 and 44.
  - The shared-expert forward tests now expect no clamp when no shared limit is set.

# Behavior notes

- Step-3.5/3.7 forward passes change on their clamped layers (43, 44): logits, losses and generations move toward Hugging Face. Checkpoints and conversion are unaffected (no parameter changes).
- `Step35SharedExpertMLP` applies the clamp in `forward()`. `moe_shared_expert_overlap=True` drives the shared expert through other methods and would bypass it; the Step-3.5 and Step-3.7 recipes keep overlap off.
