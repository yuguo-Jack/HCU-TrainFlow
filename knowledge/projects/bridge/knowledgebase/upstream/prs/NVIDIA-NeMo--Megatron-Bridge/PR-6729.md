# feat(recipes): add 64-GPU Llama 405B MXFP8 pretraining

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6729) · state: closed · merged: True

## Original PR description

## What does this PR do?

Add `llama31_405b_pretrain_64gpu_gb200_fp8mx_config()` for full Llama 3.1 405B pretraining on 64 GB200 GPUs at 8K. The recipe uses TP8/PP8/VPP8/CP1, MXFP8 with FP8 parameter gather and gradient-buffer reuse, BF16 gradients, no recompute, and CUDA graphs off. Tensor-parallel communication overlap remains enabled.

## Changelog

- Export the recipe through the Llama and top-level recipe packages for `run_recipe.py`.
- Retain global batch 1536, microbatch 1, FP32 Adam/master states, training schedule, checkpoint defaults and numerical checks.
- Add finalized-configuration/default-preservation tests and document topology, data setup and measured results.

## Validation

The equivalent configuration completed 10 real WikiText-103 updates in NeMo 26.10.rc10 on 64 GB200 GPUs within one NVLink domain. All 64 ranks exited 0 with finite losses/gradients and no skipped updates. Loss decreased from 15.0329 to 12.8288. Median updates 4–10: 288.85 seconds, approximately 1718 model TFLOP/s/GPU. Maximum allocated/reserved memory across ranks: 154.59/157.14 GiB.

CUDA graphs exceeded memory in the tested TP8 configuration; both tested TP4/PP16 variants also exceeded memory with graphs off. This recipe selects the validated TP8/PP8 no-recompute configuration. These are short capacity/stability results; long-term convergence and MXFP8 checkpoint save/resume are not verified.

All 33 targeted recipe tests passed in RC10. The packaged recipe’s finalized model/precision/parallelism/communication settings match the successful training run; normal checkpoint/data/logging defaults are retained. All-files pre-commit and `git diff --check` pass. Independent diff review completed. Strict mypy on the workstation could not resolve the uninstalled runtime dependencies.
