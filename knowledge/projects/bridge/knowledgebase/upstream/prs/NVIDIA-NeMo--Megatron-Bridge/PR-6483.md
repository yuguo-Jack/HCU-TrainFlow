# feat(model): add Muse-Spark-Open-816B-A42B support with GB200 recipes and HybridEP

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6483) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Adds Muse-Spark-Open-816B-A42B (`meta-models/Muse-Spark-Open-816B-A42B`), a sparse MoE vision-and-audio-language model with 816B total and 42B active parameters: HF ↔ Megatron conversion, inference, and GB200 pretraining, SFT, long-context SFT, and LoRA recipes.

# Changelog

- **Model** (`src/megatron/bridge/models/muse_spark_open/`): native Megatron-Core HybridModel decoder (62 alternating attention and latent-MoE blocks, 256 experts, top-8 routing) with the Hugging Face vision and audio encoders invoked directly; HF ↔ Megatron conversion; text-only import and HF export. Class names follow the Hugging Face architecture (`MuseSpark*`).
- **Data**: `MuseSparkProcessor` batches use the Muse Glimmer collator (same chat markers and THW-grid image inputs).
- **Recipes** (`src/megatron/bridge/recipes/muse_spark_open/`): nine GB200 recipes — pretraining (192 and 256 GPUs), full SFT (one epoch of 100K Tulu 3 conversations at 4K/GBS 128, and the cross-model 8K/GBS 8 contract), long-context SFT at 32K/CP2 and 64K/CP4, LoRA, and image-text SFT and LoRA. The 48-node pretraining and SFT recipes and the 16-node LoRA recipe dispatch MoE tokens with HybridEP, so each expert-parallel group must sit inside one NVL72 NVLink domain. These are early recipes: functional, not yet performance-optimized.
- **Tests**: unit tests for the model, collator, recipes, and recipe metadata; an L0 functional test that round-trips a toy checkpoint at TP2, PP2, and EP2 on 2 GPUs (skipped until the installed Transformers includes `transformers.models.muse_spark`).
- **Docs**: `examples/models/muse_spark_open/README.md`, the `muse-spark-open-816b-a42b` verification card with the regenerated catalog and model pages, a README Supported Models row, and a README News entry.
