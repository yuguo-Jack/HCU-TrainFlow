# perf(ckpt): build remaining split indices on the input device

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6347) · state: open · merged: False

## Original PR description

# What does this PR do ?

Follow-up to #6236: the Mamba and GDN mappings still build their shard indices on CPU, so indexing a CUDA weight copies them to the GPU and syncs the stream.

# Changelog

- `MambaInProjMapping.hf_to_megatron` / `megatron_to_hf`: `device=<weights>.device` on every `torch.arange`.
- `ChunkedMapping.get_shard_idx` (`GDNConv1dMapping`, `MambaConv1dMapping`): new optional `device` arg, passed from both directions. It defaults to `None` so the old call form still works; both in-tree overrides are updated.
- Test: `TestSSMMappings` round-trips each mapping and checks every `torch.arange` gets the input's device. `pytest tests/unit_tests/models/test_param_mapping.py` on CPU: 61 passed, 3 skipped, 1 failed (`TestReplicatedMapping::test_hf_to_megatron_broadcast` needs an accelerator, fails the same on main). The 4 new cases fail on main.

# Additional Information

- Related to #6229
- `get_shard_idx` gains an optional `device` argument, which `models/conversion/` AGENTS.md flags as a signature change. Happy to drop that half and keep only the `MambaInProjMapping` change if you prefer.
