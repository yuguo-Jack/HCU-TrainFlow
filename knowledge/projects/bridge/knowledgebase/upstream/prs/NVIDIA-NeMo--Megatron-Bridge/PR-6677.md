# fix(training): preserve pretraining document masking boundaries

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6677) · state: open · merged: False

## Original PR description

# What does this PR do ?

Fixes `dataset.inter_document_masking=True` for pretraining with Core `GPTDataset`. The document boundaries never reached attention, so documents packed in the same row could still attend to each other.

# Changelog

- Core pads `cu_seqlens` by repeating the last offset (`[0, 3, 8, 8, ...]`), and the legacy converter cuts at `argmin`, which leaves no boundaries. Drop the repeats and pass them as `cu_seqlens_q`/`cu_seqlens_kv`. Applied in the GPT step and in `deepseek_v4_step.py`, which reuses it.
- Load the batch on middle pipeline stages when masking is on, so they get the boundaries too.
- With masking on, `ConfigContainer.validate()` requires micro batch size 1 and context parallel size 1, for training and evaluation.
- Add unit tests for the first, middle and last pipeline stages and for the config checks, plus a short docs note.

The new code only runs when `inter_document_masking=True`, so SFT packing is unaffected. Tested on H100: the related unit tests pass, and a 3-step GPT run (PP2, real masked `GPTDataset`) got the exact document boundaries on both stages, with finite loss.
