# build: update r0.7.0 MCore release and validation

## Original PR description

## What does this PR do?

Update Bridge `r0.7.0` to MCore's official `core_r0.20.0` revision `5038673171e463b1486aca4e85dc36fcf6ffc712` and allow CI to validate stable-release commits. This combines the dependency update from closed PR #6523 with the release-branch validation fix from #6534, resolving the [baseline revision rejection](https://github.com/NVIDIA-NeMo/Megatron-Bridge/actions/runs/39056340489/job/117465756222) before the Docker build.

## Changelog

- Update `.main.commit` and the MCore gitlink from `e0c5e18673bf4d4fd89cf87c4f1afbe521fe297f` to `5038673171e463b1486aca4e85dc36fcf6ffc712`.
- Carry the matching TransformerEngine metadata and lock update: `2.20.2+6ea2a74a` → `2.20.2+44f31bbe`. Other lock changes are the dependency-marker normalization already present in #6523; no other package versions change.
- Recognize official `core_r<major>.<minor>.<patch>` branches and verify commit ancestry, retaining the official-repository restriction and existing PR/merge-queue approval rules.
- Extend the existing local Git fixtures for release-only tips/ancestors and rejected release-looking refs.

The four dependency files match #6523, and the validator/test files match #6534. Existing `r0.7.0` tests and `.dev.commit` are unchanged.

## Validation

- `uv lock --check` passed with CI's uv 0.7.2 and the selected MCore release checkout in a CPU container (345 packages).
- `bash .github/scripts/test_docker_dependency_layers.sh` passed.
- Shell syntax, matching pin/gitlink, diff checks, and all-file pre-commit passed.
- Independent review found no issues.
- No container build or GPU training run was performed; runtime validation remains for CI.

Release counterpart of #6534; replaces #6523 with the validator fix included.
