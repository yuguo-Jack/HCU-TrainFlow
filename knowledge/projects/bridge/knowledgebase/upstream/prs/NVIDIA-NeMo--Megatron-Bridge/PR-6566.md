## Original PR description

## Background

Nightly Megatron-Core main bump. The MCore main pin moves from `ce852bfb` to `ebab48fc` (`ebab48fc40c2b6f0a8768f765b9364656a2dccb9`). `.dev.commit` (`4a4de865`) is unchanged.

## What changed

- `.main.commit` and the `3rdparty/Megatron-LM` gitlink now point to `ebab48fc`.
- `uv.lock` was regenerated with `uv lock --upgrade`, which moves transformers from 5.20.1 to 5.20.2.
- `training/state.py`: `TrainState.load_state_dict` now treats `do_train`, `do_valid` and `do_test` as optional, because MCore (NVIDIA/Megatron-LM#8197) no longer saves them in train-state checkpoints. When a flag is missing, the current value is kept. A unit test covers this.
- `nemotron_omni`: transformers 5.20.2 is added to `_PROCESSOR_ADAPTER_RELEASES` and the Super-VL adapter docstring, the minimax_m3 transformers compatibility allowlist, and the Super-VL model docs (md and fern).

## Details

- Commit 1 (`fce591ab`) contains only the pin and lock changes. Commit 2 (`0c364064`) contains the compatibility fixes.
- The branch is based on the current `main` tip `c36bd9a0`.
- The validation image was built from `docker/Dockerfile.ci` with `INSTALL_DIFFUSION_DEPS=true` for validation only: `agent-sandbox@sha256:155613c5…`.

## Tested

Local runs on H100 used the managed Megatron-Bridge profile against this exact tree.
- 21 of 21 impact-selected rows passed: 4 unit rows and 17 functional rows. 0 were skipped as `skipped_upstream` and 0 as `skipped_platform`.
- After the fixes, these rows were rerun on the final tree:
  - unit Core shards 0/3, 1/3 and 2/3: 4281, 4266 and 4234 passed
  - `mlm_to_mbridge` qwen3_4b and llama32_1b: 4/4 each
- The other 16 rows are kept from the earlier run. They don't exercise the changed code paths, and their test inputs (image, lock, selectors, data) are identical.
- `uv lock --check` passed.
- GitHub CI is pending.
