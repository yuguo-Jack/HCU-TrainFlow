# fix(model): match Gemma 4 dense VL image masks to Hugging Face

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6712) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes Gemma 4 31B (dense) image-prompt logits: dense layers now apply Hugging Face's per-layer image masks, so image tokens see their whole image in sliding-window layers and stay causal in global layers.

# Changelog

- Add `Gemma4DotProductAttention` and use it as the core attention of the dense Gemma 4 layer spec (`get_gemma4_layer_spec`, used by both the provider and the builder).
- With `use_bidirectional_attention="vision"` (31B), sliding layers apply the left window to the VL model's image mask themselves (softmax window off, `AttnMaskType.arbitrary` so the fused kernel honors the mask), and global layers OR in the causal mask. Other dense models (E2B, E4B, text-only) keep Megatron Core's behavior.
- Unit tests for the new attention, including Megatron Core's real softmax on CPU and a check that the VL mask, as each dense layer applies it, equals Hugging Face's `create_masks_for_vision_model` result.

Root cause. Hugging Face lets image tokens attend to their whole image only in sliding layers: sliding = window AND (causal OR same image block), full attention = causal. `Gemma4VLModel` passes one mask (causal OR image block) to every layer. The MoE path (`Gemma4TEDotProductAttention`) already turns it into per-layer masks; the dense path used Megatron Core's `DotProductAttention`, where:

- sliding layers: `FusedScaleMaskSoftmax` ORs its causal sliding-window mask into the caller's mask, which closes every image block;
- global layers: the image block stays open whenever the fused softmax kernel's shape checks fail (for example, a sequence length that is not a multiple of 4); when the kernel runs, its causal upper-triangular path ignores the mask.

Measured on H100 (NeMo 26.10 rc9, Megatron Core a2965235, transformers 5.17.0), `google/gemma-4-31B-it`, TP2, one image + "Describe this image." (295 tokens, 276 image tokens), cosine against Hugging Face bf16 logits:

| | image positions | other positions | worst image position | argmax agreement (image / other) |
|---|---|---|---|---|
| main | 0.9615 | 0.9842 | -0.27 | 0.43 / 0.84 |
| this PR | 0.9944 | 0.9931 | 0.88 | 0.78 / 1.00 |
| Hugging Face bf16 vs fp32 | 0.9939 | 0.9915 | 0.65 | 0.76 / 0.90 |

The first difference was at layer 0, the first sliding layer, at image positions only. Per-layer softmax instrumentation on main showed zero attention from image tokens to later image tokens in all 50 sliding layers; with this PR it matches Hugging Face's masks with both the fused and the PyTorch softmax. E2B and E4B (image and text prompts) and the 31B text prompt give bitwise-identical hidden states and logits before and after. 26B-A4B already matched (its image-position gap is at the bf16 noise floor).
