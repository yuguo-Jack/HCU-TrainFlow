# feat(qwen3.5-vl): support independent vision sequence parallelism

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6684) · state: open · merged: False

## Original PR description

Qwen3.5-VL currently forces vision sequence parallelism off. Manually enabling it makes QKV gather an already replicated sequence and produces a RoPE length mismatch. This adds `vision_sequence_parallel=False` independently of language `sequence_parallel`, scatters vision transformer inputs, and restores full patch groups before final/deepstack mergers. Padding has separate attention boundaries and is cropped from merged outputs.

The combined-model provider installs a Bridge-specific `finalize_model_grads_func`. Core still synchronizes DP gradients, handles embeddings and normalizes by token count once. A parameter-filtering view gives Bridge explicit ownership of vision SP sums, preventing both the missing reduction with language SP off and duplicate reduction if Core's global gate changes. The callback also corrects the existing GDN shared output-norm gradient sum when language SP is off. No Core source or submodule-pin change is required.

Training setup preserves the selected callback, rebinds process groups and composes PEFT synchronization without repeating finalization. Defaults and checkpoint parameter names/shapes are preserved. Related to #6662.

Validation:
- Focused units: 341 passed, 1 expected skip in the final single-GPU run (an existing FP8 device-migration test requires two GPUs and passed in the earlier two-GPU run).
- Two H100 ranks, unchanged pinned Core: 16 distributed cases passed per rank. Dense all-four-SP combinations and valid MoE combinations at TP1/TP2; outputs, all parameter gradients, SGD deltas and actual sequence sharding checked. Includes ordinary DDP and overlapped reduction with distributed-optimizer buffers and per-token normalization.
- Against Core PR8538's changed global gate: all 8 full-model matrix cases also passed per rank, checking against duplicate reductions.
- All-files pre-commit passes. A lightweight strict mypy check is incomplete because the workstation lacks PyTorch type information. Fresh independent review completed; bound callback arguments identified during review are preserved and covered by regressions.

Supported added reductions use Megatron DDP with a shared modality TP group. FSDP/DTensor gradients, GTP weight rematerialization and vision SP with CUDA graphs are explicitly rejected where applicable. This does not extend MIMO's separate finalization path. MoE retains Core's existing requirement for language SP when language TP is greater than one.

Checks use tiny random models, mixed image/video frames, odd vision lengths, deepstack and recomputation. They do not establish full-size training, performance/memory gains, distributed MIMO correctness, language packing, or an end-to-end optimizer step; update comparisons use SGD arithmetic on the resulting gradients.
