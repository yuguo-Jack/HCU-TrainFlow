# fix(model): keep YaRN and reject unsupported llama3 RoPE in Llama bridge

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6597) · state: closed · merged: False

## Original PR description

# What does this PR do ?

Fix two RoPE config gaps in `LlamaBridge`. YaRN-scaled Llama checkpoints lost YaRN on the builder path. llama3 RoPE values that Megatron Core cannot apply were dropped without an error.

# Changelog

- **YaRN:** `hf_config_to_model_config_kwargs()` now sets `position_embedding_type` with `setdefault("rope")`, like the other builder-backed bridges.
  - Before, `update()` overwrote the `"yarn"` that the shared mapping selects. `get_model_config()` and `get_model()` then built plain RoPE and ignored the `yarn_*` fields.
  - The mapped config keeps the Hugging Face YaRN defaults (`beta_fast` 32, `beta_slow` 1, `truncate` True), and `megatron_to_hf_config()` exports YaRN back.
  - The legacy provider path already kept YaRN, because `provider_bridge()` derives it from the HF config again.
- **llama3:** Megatron Core's `RotaryEmbedding` applies llama3 scaling with fixed `low_freq_factor=1.0`, `high_freq_factor=4.0` and `original_max_position_embeddings=8192`; only the factor is configurable.
  - The bridge now raises a `ValueError` that names the unsupported values, on both the builder and the provider path. Before, it dropped them, and export wrote the fixed values back.
  - Export uses the same constant.
  - The official Llama 3.1, 3.2 and 3.3 checkpoints use exactly these values, so they are unaffected.
- **Unit tests:**
  - a `yarn` case in the builder/provider parity test
  - a YaRN test that checks the mapping, the export and a round trip
  - a test that each non-default llama3 value raises on both paths

# Testing (local, CPU)

- `tests/unit_tests/models/llama`: 49 passed. The 5 new cases fail on `main`.
- Real HF configs: the mapped kwargs and both exports are identical to `main`.
  - Llama 2 7B, CodeLlama 7B, Llama 3 8B/70B, 3.1 8B/70B, 3.2 1B/3B, 3.3 70B
- Tiny random YaRN Llama through `import_ckpt`, reload and logits:
  - The builder path's max abs logit diff vs HF drops from 4.3e-5 on `main` to 1.8e-7.
  - Its logits are bitwise equal to the provider path's.
  - Exports are bit-exact.
- `pre-commit run --all-files` passes.

# GPU check

Setup: H100, TE 2.20.2, bf16, TP1. Model: `NousResearch/Yarn-Llama-2-7b-64k` (YaRN ×16 over 4096 positions). Compared against Hugging Face logits on 6-token and 6144-token prompts, with transformers 5.17 and 5.20.2.

| | main | this PR |
|---|---|---|
| Provider path | pass (cosine ≥ 0.9997) | pass, bitwise identical to main |
| Builder path (`get_model_config()` / `get_model()`) | **fail at 6144 tokens:** wrong next token, cosine 0.67–0.73 | pass, bitwise identical to the provider path |

The checkpoint's custom-code `auto_map` was removed from the local config copy, because `AutoBridge` otherwise refuses it; that's tracked separately. None of 24 public Llama-architecture checkpoints is rejected by the new llama3 check.
