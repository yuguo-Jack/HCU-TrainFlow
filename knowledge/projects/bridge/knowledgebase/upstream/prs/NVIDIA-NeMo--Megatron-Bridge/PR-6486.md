# fix(model): disable cuBLAS TF32 in the DiffusionGemma FP32 parity scripts

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6486) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Makes the DiffusionGemma FP32 parity examples actually run in FP32. They turned TF32 off only through PyTorch's backend flags, but Transformer Engine runs FP32 GEMMs through cuBLASLt with TF32 compute regardless of those flags, so `toy_parity.py`, `toy_training_parity.py` and `real_fp32_parity.py` compared against a TF32 result and failed their FP32 thresholds on H100 and GB200 in the NeMo container, while reporting `tf32_disabled: true`.

## Summary

- Symptom (`nvcr.io/nvidian/nemo:26.10.rc5`, default env): `toy_parity.py` fails `Encoder parity failed` (encoder max abs diff 0.0107 on H100 / 0.0111 on GB200 vs atol 3e-4); `toy_training_parity.py` fails at TP1, TP2 and EP2; `real_fp32_parity.py` (GB200) fails the image-encoder diagnostic (relative L2 0.02005 > 0.02, min token cosine 0.968 < 0.98). All pass with `NVIDIA_TF32_OVERRIDE=0`.
- Root cause: in the same container, with `torch.backends.cuda.matmul.allow_tf32 = False`, `torch.matmul` / `F.linear` / SDPA stay true FP32 (relative error ~1.5e-6 vs FP64), but `transformer_engine.pytorch.Linear` in FP32 has relative error ~3e-4 — TE's cuBLASLt FP32 GEMM uses TF32 compute independent of PyTorch's flags. `NVIDIA_TF32_OVERRIDE=0` (honoured by cuBLAS when set before the first GEMM) brings TE back to ~1.4e-6.

# Changelog

- `examples/models/diffusion_gemma/fp32_precision.py`: new `disable_tf32()` (sets `NVIDIA_TF32_OVERRIDE=0` plus the PyTorch matmul/cuDNN flags) and `tf32_disabled()` (effective state).
- `toy_parity.py`, `toy_training_parity.py`, `real_encoder_parity.py`, `real_fp32_parity.py`: call `disable_tf32()` instead of setting only the PyTorch flags; reports use `tf32_disabled()`.
- `tests/unit_tests/examples/test_diffusion_gemma_fp32_precision.py`: helper disables cuBLAS TF32 too, PyTorch flags alone do not count as disabled, and every parity script uses the helper.
