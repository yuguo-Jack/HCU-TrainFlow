# docs(model): re-verify GLM-5 and GLM-5.2 GB200 items at public revisions

## Original PR description

# What does this PR do ?

Re-verifies the GLM-5 and GLM-5.2 GB200 card items whose `bridge_commit` pins are not in the public repository by re-running the unchanged card commands at public main, and adds a check that verified GB200 training items pin a reachable revision.

# Changelog

- `examples/model_verification_cards/glm5/card.yaml`, `glm5-2/card.yaml`: `sft`, `peft` and `sft_export_inference` (GB200) re-verified on the card base container `nvcr.io/nvidia/nemo:26.08.rc3` at `e2f2496cb`; new `bridge_commit`, `last_verified`, measured metrics, and an `expected_result` stating only what the run measured.
- `docs/_static/model-verification/catalog-v1.json`, `docs/models/glm/glm5*.md`, `docs/fern/.../glm5*.mdx`: regenerated.
- `tests/unit_tests/doc_consistency/test_verification_card_recipe_revisions.py`: `test_glm5_verified_items_pin_reachable_revisions`; items not yet re-verified are listed in `GLM5_PENDING`.

# Additional Information

- Still pinned to commits outside the public repository (excluded via `GLM5_PENDING`):
  - glm5 `pretrain` (`0b59ee513f`): passes at public main, but the validator requires the same commit as `checkpoint_resume`.
  - glm5 `checkpoint_resume` (`0b59ee513f`): **fails at public main** (device OOM in the first resumed step's reduce-scatter); the card still records it as verified.
  - glm5 / glm5-2 `sft_long_context` (`49c103c714`): the 128K dataset has no published generator.
  - glm5-2 `pretrain` / `checkpoint_resume` (`d592bef3fd`): need an MTP-keeping Megatron import that no published command produces.
- The card-level `verification_environment.bridge_commit` (`fc668edc8`) and glm5-2 `manual_forward_pass` (`6887e0393b`) are fetchable but not on main; the test checks only training-item pins.
- Test fails on main's cards and passes on this branch; it needs full git history, so a shallow CI checkout skips it.
