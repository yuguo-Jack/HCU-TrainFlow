# build: bump r0.7.0 to MCore release 50386731

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6523) · state: closed · merged: False

## Original PR description

Bump Bridge `r0.7.0` to MCore **`core_r0.20.0`** at `5038673171e463b1486aca4e85dc36fcf6ffc712`, from `e0c5e18673bf4d4fd89cf87c4f1afbe521fe297f` ([18-commit comparison](https://github.com/NVIDIA/Megatron-LM/compare/e0c5e18673bf4d4fd89cf87c4f1afbe521fe297f...5038673171e463b1486aca4e85dc36fcf6ffc712)). Both `.main.commit` and the submodule gitlink match the release tip; `.dev.commit` is unchanged. The filename `.main.commit` is retained because existing Bridge CI uses it, but the selected commit is from the MCore release branch.

This brings in the upstream mixed-FP32/BF16 optimizer checkpoint fix from [MLM #7336](https://github.com/NVIDIA/Megatron-LM/pull/7336), addressing #6497's DeepSeek-V4 checkpoint-save failure on [H100](https://github.com/NVIDIA-NeMo/Megatron-Bridge/actions/runs/38929440133/job/117117199682) and [GB200](https://github.com/NVIDIA-NeMo/Megatron-Bridge/actions/runs/38929440133/job/117117198957). Cause: **1. Megatron LM bug** — the old pin indexed optimizer state in buffer order instead of final FP32-first shard order. Replaces #6514's release-only Bridge workaround; no Bridge optimizer workaround is included.

The release also includes MCore's [TE revision update #8036](https://github.com/NVIDIA/Megatron-LM/pull/8036). Carry the corresponding one-line TE metadata update from Bridge main [#6414](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6414) and regenerate the lockfile. `pyproject.toml` and `uv.lock` are byte-identical to that landed main commit (`9dfd9f53693f49c19303b2ab5cfce57eb9ce4933`). The only package version/source delta is TE `2.20.2+6ea2a74a` → `2.20.2+44f31bbe`; remaining lock changes normalize dependency markers with CI's uv 0.7.2.

The branch incorporates current `r0.7.0`, including the DeepSeek-V4 SFT smoke-test correction from [#6515](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6515). The test matches main exactly: run the SFT recipe through `pretrain()` from toy initialization, retaining the toy architecture and validating override attributes. There is no test-file diff against the release base.

Validation:
- After merging current release base: **9 DeepSeek recipe tests passed**, all **3 SFT cases collected**; all-file pre-commit and diff checks passed. GPU training was not run locally.
- Linux/CUDA container: `uv lock` and `uv lock --check` passed (345 packages).
- Against the new release MCore, without the Bridge workaround: **69 passed, 6 GPU-only skips**, combining existing optimizer tests with mixed-dtype checkpoint identity checks. The latter exercise real MCore index construction and get/set methods; precision-aware state storage uses a CPU test double.
- All-file pre-commit, diff checks, matching pin/gitlink and unchanged dev pin passed; independent review completed.
- GPU training/checkpoint validation remains for CI. Existing default L0 DeepSeek launchers on H100 and GB200 cover the observed failure. No tests were disabled or moved.

Other upstream changes include mHC PP/VPP, inference sampling/stops, GTP owner/layout utilities, upstream CI updates, and the release cherry-pick fixing aux-loss token-count tensor creation under CUDA graph capture (#8291 / #8217). These remain subject to release CI and review; local CPU checks do not establish full hardware validation.

Current CI blocker: initial NeMo run [38977050875](https://github.com/NVIDIA-NeMo/Megatron-Bridge/actions/runs/38977050875) rejected the release pin before building either container: `Baseline MCore revision is not approved`. The revision validator accepts main/dev ancestry and selected PR/queue refs, but does not include MCore release branches. The same validator exists on Bridge main; release-branch validation support needs a separate main-first correction. The conflict resolution does not alter that validation policy.
