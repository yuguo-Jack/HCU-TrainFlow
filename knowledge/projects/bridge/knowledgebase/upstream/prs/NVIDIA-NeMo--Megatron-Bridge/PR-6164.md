# fix(deepseek): preserve main and dev conversion compatibility

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6164) · state: closed · merged: False

## Original PR description

DeepSeek V4 FLOP accounting reads the dev-only projection field names, so the existing main pin silently substitutes defaults and undercounts the projection work. Read the actual main or dev field names and verify both schemas against the same hand-calculated result.

Also make the MTP router-bias mapping accept the same missing HF bias as the decoder mapping, and let round-trip verification recreate bridge-synthesized HF weights instead of raising `KeyError` when those weights are absent from the original checkpoint.

These are existing Bridge defects extracted from #6160; this PR leaves both MCore pins unchanged.

Validation: 202 focused tests passed against the exact current main pin (`f6c33bde`) and another 202 passed against the unchanged dev pin (`4a4de865`), using isolated source exports in the task container. This covers FLOP arithmetic, DeepSeek V4 mappings, and the conversion launcher. All-file pre-commit and independent review passed. Full distributed round-trip execution and PR CI remain pending.

[Standard CI](https://github.com/NVIDIA-NeMo/Megatron-Bridge/actions/runs/35489788794) passed, including all 39 L0 jobs. Installation validation remains in progress. The separate Claude preflight check reproduces the existing artifact-download failure addressed by #5844; it is not repaired in this PR.
