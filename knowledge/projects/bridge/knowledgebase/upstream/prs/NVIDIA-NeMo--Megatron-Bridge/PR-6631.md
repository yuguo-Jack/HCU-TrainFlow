## Original PR description

## Background

Nightly Megatron-Core `main` bump (AUT-2615). This PR moves the MCore main pin from `ede2c586` to `3630e44a8046c175f3b6f399204755892b84369a`. The dev lane is paused, so `.dev.commit` is unchanged.

## What changed

- `.main.commit` and the `3rdparty/Megatron-LM` gitlink point to `3630e44a`.
- `uv.lock` was regenerated with `uv lock --upgrade` in the Bridge CI image (uv 0.7.2). `uv lock --check` passes.
- `main` (`c8fb26a5`) is merged in to resolve the conflict. The only conflicting file was `tests/unit_tests/training/test_checkpointing.py`. It now uses the `main` version, which already sets `verify_integrity=False`, so the earlier test fix in this PR is no longer needed. The lock also carries the gitpython override from `main` (`>=3.2.1,<4`).

## Details

- Compared with `main`, this PR changes only `.main.commit`, the gitlink and `uv.lock`.
- The validation image was built from this pin and lock with the `megatron-bridge` profile, with diffusion deps enabled for validation only. It was reused for the merged tree: the image input and the tested head both pin `3630e44a`.
- The merge touched shared training, config, conversion and perf code. So all 28 impact-selected rows ran again on the merged tree, and no earlier pass was reused.

## Tested

Local H100 validation on this exact tree (`ce5563af`):
- **28 of 28 selected rows passed:** 4 unit rows (Core shards 0/3, 1/3, 2/3 and Diffusion) and 24 functional L0/L1/L2 rows.
- `skipped_upstream`: 0. `skipped_platform`: 0.
- Native test skips inside passing rows (not counted as passes):
  - Core shards: 14, 19 and 13;
  - `recipes_deepseek`, `gtp_checkpoint_conversion`: 1 each (MXFP8 needs Blackwell);
  - `decentralized_pg`: 1 (needs 4 GPUs);
  - `pretrain`: 1 (DistTrain needs 8 GPUs).
- `uv lock --check`, `ruff check` and `ruff format --check` pass.
- CI on this head is pending.
