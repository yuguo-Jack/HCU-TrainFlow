File: `tests/unit_tests/recipes/nemotronh/test_nemotron_3_ultra.py` · line 282

**Non-blocking — cover the changed MXFP8 module lists too**

The updated assertions exercise only NVFP4. The PR independently changes the [GB200 MXFP8 factory](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/58f73b02f5eac3104bbcd31f919f0f6ebe43a248/src/megatron/bridge/perf_recipes/nemotronh/gb200/nemotronh.py#L250-L253) and [GB300 MXFP8 builder](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/58f73b02f5eac3104bbcd31f919f0f6ebe43a248/src/megatron/bridge/perf_recipes/nemotronh/gb300/nemotronh.py#L261-L264), which also supplies VRNVL72. As a concrete coverage counterexample, reverting either MXFP8 list to `["attn", "mamba"]` would not be detected by these new assertions; the [existing VRNVL72 MXFP8 test](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/58f73b02f5eac3104bbcd31f919f0f6ebe43a248/tests/unit_tests/recipes/nemotronh/test_nemotron_3_ultra.py#L191-L213) checks the implementation but not the module list. This is source reasoning, not an executed mutation test.

**Correction:** add the two GB200/GB300 MXFP8 factories to this file's existing imports and add the following configuration regression test below the NVFP4 tests. It uses the existing offline fixture and compatibility accessor:

```python
@pytest.mark.unit
@pytest.mark.parametrize(
    "recipe_factory",
    [
        nemotron_3_ultra_pretrain_256gpu_gb200_fp8mx_config,
        nemotron_3_ultra_pretrain_256gpu_gb300_fp8mx_config,
        nemotron_3_ultra_pretrain_256gpu_vrnvl72_fp8mx_config,
    ],
    ids=["gb200", "gb300", "vrnvl72"],
)
def test_mxfp8_perf_recipes_keep_moe_cuda_graph_modules(recipe_factory) -> None:
    cfg = recipe_factory()
    assert cfg.model.cuda_graph_impl == "local"
    assert cuda_graph_module_names(cfg.model) == [
        "attn", "mamba", "moe_preprocess", "moe_router"
    ]
    assert cfg.model.use_te_rng_tracker is True
    assert cfg.rng.te_rng_tracker is True
```

**Preservation and acceptance:** keep the existing NVFP4 tests unchanged, including their FP4 precision, GTP sharding, NCCL EP, attention/Mamba modules, and RNG assertions. The three proposed MXFP8 cases should pass with the current lists and fail if either newly enabled MoE module is removed from their respective builder. This closes the independent-branch coverage gap without changing training behavior. Suggested code is unexecuted and should be verified before adoption.
