# feat(deepseek-v4): let inference.sh launch across nodes

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6163) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Let `examples/models/deepseek_v4/inference.sh` launch its `PP * EP` ranks across several nodes. The script always ran `torch.distributed.run --nproc_per_node=$((PP * EP))`, i.e. everything on one node; with the DeepSeek-V4-Pro defaults (`PP=4`, `EP=8`) that is 32 processes on a single node, which a 4-GPU GB200 NVL72 node cannot run although the header says the defaults are for GB200. The README documents multi-node launches for training but not for inference.

# Changelog

- `examples/models/deepseek_v4/inference.sh`: new `NNODES` / `NODE_RANK` / `MASTER_ADDR` / `MASTER_PORT` / `GPUS_PER_NODE` variables (defaults 1 / 0 / 127.0.0.1 / 29500 / `PP*EP/NNODES`). When `NNODES > 1` the launcher adds `--nnodes --node_rank --master_addr --master_port`; `PP*EP % NNODES != 0` fails fast. With the variables unset the command line is unchanged. Header comment shows the Slurm form (one task per node).
- `examples/models/deepseek_v4/README.md`: one bullet in *Known Limitations* with the multi-node invocation.

# GitHub Actions CI

External contributor without CI trigger permissions. Validation: `bash -n` clean; the same launcher shape (one Slurm task per node, `--nnodes=8 --nproc_per_node=4 --node_rank=$SLURM_NODEID`) was used to run `hf_to_megatron_generate_text.py --legacy-full-prefix` for DeepSeek-V4-Pro on 8 × GB200 (TP1/PP4/EP8) from an imported Megatron checkpoint in the nemo:26.08 container: coherent generation, 12 min 49 s including the 3 TB load.

[P2] Run the documented Slurm command from the repository root

**Failure:** Copying this command at the repository root fails because `./inference.sh` does not exist there. Running it from the model-example directory, where that file exists, also fails: [both inference launches](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/5cdd2d3bafcc2e081313282836afbc880ac25ea9/examples/models/deepseek_v4/inference.sh#L78-L98) resolve `examples/conversion/hf_to_megatron_generate_text.py` relative to the working directory. The documented command should locate both entrypoints without users having to repair its paths.

**Correction:** State that this command runs from the repository root, and replace `./inference.sh` here and in the [matching header example](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/5cdd2d3bafcc2e081313282836afbc880ac25ea9/examples/models/deepseek_v4/inference.sh#L27-L29) with the root-relative script path:

```bash
srun --ntasks-per-node=1 bash -c 'NNODES=$SLURM_JOB_NUM_NODES NODE_RANK=$SLURM_NODEID MASTER_ADDR=$(scontrol show hostnames "$SLURM_JOB_NODELIST" | head -n1) examples/models/deepseek_v4/inference.sh'
```

This suggestion is source-reasoned, not executed; verify it before adopting it.

**Preservation:** Keep one Slurm task per node and the per-task expansion inside the single-quoted payload, so each node retains its own `NODE_RANK` and the same master address. Do not fix this by changing only into the script directory: the Python entrypoint requires the repository-root working directory. Retain both loading branches and their full-prefix generation flags.

**Acceptance (proposed):** From the repository root, use temporary `srun`/`scontrol`/`uv` stubs that execute the payload, return `node0`, and record arguments. With `MODEL_VARIANT=DeepSeek-V4-Pro`, `SLURM_JOB_NUM_NODES=8`, and `SLURM_NODEID=3`, expect the script to be found, the recorded Python entrypoint to exist, and arguments `--nproc_per_node=4`, `--nnodes=8`, `--node_rank=3`, and `--master_addr=node0`. Create the optional checkpoint directory under a temporary `WORKSPACE` and assert both invocations receive those same launch arguments and `--legacy-full-prefix`.
