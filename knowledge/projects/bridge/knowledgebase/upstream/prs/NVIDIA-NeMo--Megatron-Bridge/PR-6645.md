# fix(checkpoint): preserve builder config when loading models

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6645) · state: closed · merged: True

## Original PR description

## What does this PR do?

Fixes `load_megatron_model(...)` followed by `save_megatron_model(...)` for builder-backed checkpoints. Loading reconstructs the outer `ModelConfig`, but previously returned models carrying only their inner `TransformerConfig`; saving then raised a reconstructability `TypeError`.

## Minimal save/load example

Starting with `models` returned by `AutoBridge.get_model(...)` for a builder-backed model, run the following while its single-rank distributed/model-parallel context remains active (TP=PP=EP=1). Use fresh output directories.

```python
from megatron.bridge.training.model_load_save import (
    load_megatron_model,
    save_megatron_model,
)

save_megatron_model(models, "./original_checkpoint")
loaded = load_megatron_model("./original_checkpoint", skip_temp_dist_context=True)
save_megatron_model(loaded, "./resaved_checkpoint")
reloaded = load_megatron_model("./resaved_checkpoint", skip_temp_dist_context=True)
```

Expected: all four calls complete without error. Before this fix, saving `loaded` raises a `TypeError` because its outer builder config was not retained. The final reload checks that the second checkpoint is reconstructable. This illustrates the intended API workflow; a full distributed checkpoint roundtrip was not run locally.

## Changes

- Retain the loaded outer config on every returned builder model chunk, including wrapped models, matching `AutoBridge.get_model()`.
- Preserve the runtime transformer config and existing provider/state-dict behavior.
- Add four unit cases using `BridgeGPTModelConfig`, covering wrapped/unwrapped models and one/two chunks. They also verify the attention-backend enum survives reload. They exercise load→save and real config serialization/reconstruction, with model construction and distributed tensor I/O mocked.

This is a shared fix for builder checkpoints, independent of individual family migrations. It composes cleanly with #6594's CPU→GPU loading fix. No public API signature or checkpoint schema changes.

## Validation

- Two additional bounded serializer probes reproduce the old fixture failure and verify the Bridge-config path restores the enum. These use production config serialization methods with a small transformer stand-in; fresh full CI is required.

The plain `gpt_builder.GPTModelConfig` uses MCore's base `from_dict`, which treats the serialized `AttnBackend` enum as a nested dataclass.
