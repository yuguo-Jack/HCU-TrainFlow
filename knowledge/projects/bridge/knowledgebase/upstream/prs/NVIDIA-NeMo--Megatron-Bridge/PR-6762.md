# chore(deps): AUT-2710 bump Megatron-Core main to e0a4bfed

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6762) · state: closed · merged: True

## Original PR description

## Background

This is the nightly Megatron-Core `main` bump (AUT-2710). It pins MCore `main` to `e0a4bfed` (previously `ba495158`). `.dev.commit` is unchanged at `4a4de865`, because the dev lane is disabled for this run.

## What changed

- `.main.commit` and the `3rdparty/Megatron-LM` gitlink now point to `e0a4bfed7f1e233b857187ceff0104645858d7d1`. I regenerated `uv.lock` with `uv lock --upgrade`, and `uv lock --check` passes.
- `uv.lock` now also lists the `cuda-tile` 1.8.0rc8 aarch64 and win_arm64 wheels. The upgrade locked rc8 before pypi.nvidia.com had published those wheels, which broke the arm64 container build. Package versions and x86_64 artifacts are unchanged.
- Bridge is adapted to MCore config API changes. `OptimizerConfig` and `BlendedMegatronDatasetConfig` no longer run `__post_init__`, and `dataset.mock` and `token_dtype_code` are now read-only derived properties.
  - `training/config.py` finalizes these configs through `validate()`/`finalize_optimizer_config()` and `validate_without_tokenizer()`.
  - `training/setup.py` and `perf_recipes/llama/common.py` no longer assign the read-only properties.
  - `scripts/translate_mlm_to_bridge.py` and the docs skip `--mock-data`. Synthetic data is used when no data path or blend is set.
  - In the tests, the functional recipe helpers and finetune tests pass `split` to `MockGPTDatasetConfig` as a string. I also updated the unit expectations for split handling and for the `overlap_param_gather` fixture.

## Details

No test is disabled, skipped or weakened. There's no dev-lane change in this PR.

## Tested

I ran these locally on H100 using a validation image built at the MCore pin, with diffusion test dependencies enabled only for that image.
- 83 rows were selected based on what this change affects, and all 83 passed: 4 `main-unit` and 79 `main-functional`. There were 0 failures, 0 `skipped_upstream` and 0 `skipped_platform`.
- 34 rows ran before the recipe-helper test fix. Their passes carry forward because none of them runs the changed helpers.
- All passes carry forward across the `cuda-tile` lock fix, because every package keeps the same version and x86_64 wheel hash. The H100 environment is unchanged.
- Some tests skip natively inside passing rows, so that coverage wasn't validated: `test_gtp_native_fp8_conversion.py:70` needs Blackwell, and `test_qwen3_omni_smoke.py:177,196` needs local smoke assets that aren't available.
- pre-commit lint passes. GitHub CI on this head hasn't reported yet.
