# perf(recipe): enable cuDNN normalization for DeepSeek-V3 E2E benchmarks

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6661) · state: closed · merged: True

## Original PR description

## What does this PR do?

Enable cuDNN forward and backward normalization in the four DeepSeek-V3 performance recipes by setting `NVTE_NORM_FWD_USE_CUDNN=1` and `NVTE_NORM_BWD_USE_CUDNN=1` in each recipe's `cfg.env_vars`.

The first version of this PR set the flags in 20 recipes. E2E perf runs showed that cuDNN's norm kernels only help DeepSeek-V3, so the Qwen3-235B-A22B, Qwen3.5-VL and Nemotron-3 recipes keep TransformerEngine's native norm kernels.

## Changelog

- DeepSeek V3, 256 GPUs, GB200/GB300: BF16 and NVFP4 (four recipe functions, eight lines in two files).

## Results

E2E perf runs of all 20 originally targeted benchmarks with the flags, each compared with a run of the same benchmark from the same day without them. Norm-kernel time is the GPU time spent in TE or cuDNN normalization kernels per training iteration on rank 0, from per-kernel GPU profiles. "From norm kernels alone" is the change in norm time that doesn't overlap other GPU work, divided by the baseline iteration time.

| Model | Benchmarks | Step time vs same-day run | From norm kernels alone | Norm-kernel GPU time | In this PR |
|---|---|---|---|---|---|
| DeepSeek-V3 | 4 | 2.3–4.6% faster | 2.2–4.4% faster | 52–54% less | Flags kept |
| Qwen3-235B-A22B | 6 | 0.8–4.2% slower | 1.7–5.1% slower | 2.6–3.3× more | Flags removed |
| Qwen3.5-VL | 4 | 1.4–4.4% slower | 1.1–2.5% slower | 2.6–3.1× more | Flags removed |
| Nemotron-3 Super, Ultra | 6 | −1.9% to +0.8% (see note) | within ±0.3% | +3.5 to +48.5 ms per iteration | Flags removed |

Nemotron-3: the measured range covers five benchmarks. Ultra GB300 measured +14.2%, which came from bursts of slow steps with the extra time in communication; its fastest steps matched the baseline and its norm kernels changed by 3.5 ms per iteration.

- The flags replace TE's `rmsnorm_*` kernels one for one with cuDNN's `ln_tma_fwd_kernel`, `ln_fwd_kernel`, `ln_tma_bwd_kernel` and `ln_bwd_finalize_kernel`, with identical launch counts per iteration.
- On DeepSeek-V3, cuDNN's forward kernels are 2.8–3.5× faster and its backward kernel about 3× faster. Only the dgamma finalize is slower, so total norm time roughly halves.
- On Qwen3-235B-A22B and Qwen3.5-VL, cuDNN's backward is 2.3–2.9× slower and its dgamma finalize 3.2–11× slower. The largest share is the per-head QK-norm RMSNorm, which normalizes rows of 128 channels on Qwen3 and 256 on Qwen3.5.
- On Nemotron-3, norm kernels take about 1–2% of an iteration, so the extra norm time does not measurably change step time.
- Against the 8–14 comparable runs without the flags per benchmark from 21 Oct to 1 Nov, the DeepSeek-V3 runs with the flags were faster than all of them. The Qwen runs were slower than all of them, apart from one outlier run on each Qwen3-235B GB300 benchmark.

Caveats: there is one run with the flags per benchmark. The baselines ran Megatron-Bridge main or r0.7.0 with Megatron-LM main or core_r0.20.0, so they are not same-stack A/B runs. Training configs and TransformerEngine Python sources were identical within each pair. Qwen3-235B loss matched the baselines within 0.02%. DeepSeek-V3 loss curves differ from the baselines, and these runs cannot separate that from the Megatron-LM changes.
