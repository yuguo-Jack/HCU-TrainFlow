# fix(recipe)!: run Nemotron 3 Ultra H100 SFT on the documented 48-node layout

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6376) · state: open · merged: False

## Original PR description

# What does this PR do ?

Make the Nemotron 3 Ultra H100 full-SFT recipe use the 48-node layout that the Ultra README and `slurm_sft.sh` document as the H100 starting point (384 GPUs, TP2/PP12/EP16), rename it to match its GPU count, split its decoder layers unevenly across the 12 pipeline stages so the last stage fits in memory, and avoid a Transformer Engine failure in the first backward pass.

# Changelog

- **Breaking:** rename `nemotron_3_ultra_sft_192gpu_h100_bf16_openmathinstruct2_packed_config` to `nemotron_3_ultra_sft_384gpu_h100_bf16_openmathinstruct2_packed_config`; the old name is removed. The generic alias `nemotron_3_ultra_sft_openmathinstruct2_packed_config` (used by `slurm_sft.sh` and `pack_data_job.sh`) now points to the new recipe.
- Parallelism: PP 6 → 12 and EP 32 → 16 (TP2 with sequence parallelism unchanged), giving dense DP 16 and expert DP 2 on 384 GPUs.
- Pipeline split: stage separators in `hybrid_layer_pattern` place 9 decoder layers on each of stages 0–7, 10 on stages 8 and 9, 11 on stage 10, and 5 on the last stage, which also holds the output layer and the two-depth MTP block. `_split_hybrid_layer_pattern` raises unless the stage sizes exactly cover a pattern that has no separators yet. Because the split is part of the pattern, a `PP` override must also override `model.hybrid_layer_pattern`; the README's H100 SFT notes say so (see the caveat under Additional Information).
- Recompute stays selective, on `moe`, `core_attn`, and `moe_act`; `layernorm` is no longer recomputed (see Why).
- Recipe environment: `NVTE_NORM_FWD_USE_CUDNN=1` and `NVTE_NORM_BWD_USE_CUDNN=1` (cuDNN normalization kernels, as several perf recipes already use), and `CUDA_DEVICE_MAX_CONNECTIONS=1`.
- `dist.distributed_timeout_minutes`: 10 → 90, the value `slurm_sft.sh` already passes; the first step's one-time startup work runs stage by stage through twelve pipeline stages.
- Unchanged: HybridEP, data and packing, GBS 128 / MBS 1 at sequence length 4096, optimizer, LR schedule, seed, and precision. Unit tests pin these, the new layout and stage split, DP/expert-DP, recompute, environment, timeout, and names.
- `slurm_sft.sh` no longer forces full uniform recompute by default; recompute overrides are passed only when set. The README's H100 SFT starting point now matches the recipe, and both SFT rows describe the recipe's recompute modules.
- Tests: the shared offline test provider in `tests/unit_tests/recipes/recipe_test_utils.py` now returns Nemotron 3 Ultra's 108-layer pattern, so `test_all_recipe_factories.py` can build the split recipe; the two Ultra recipe test files reuse that pattern.
- Verification card: the H100 SFT command uses `--nodes 48` and the new recipe name; the generated model guides and catalog are regenerated.

# Why

NVBug 6674155: the 192-GPU recipe fails in its first training step on H100.

- **It was never verified.** The card's H100 SFT entry has been unverified since the card was created, and the PR that added the recipe (#4224) shipped `slurm_sft.sh` and the README with 48-node TP2/PP12/EP16 overrides instead of the recipe defaults.
- **Memory.** At TP2/PP6/EP32 on 192 GPUs, expert data parallelism is 1, so each GPU keeps unsharded expert parameters, fp32 gradients, and Adam state (about 45 GiB of expert state per GPU). Reproductions of that layout ran out of GPU memory in the first step. On 384 GPUs, expert DP 2 shards the expert optimizer state. With the default even split of 9 decoder layers per stage, a 48-node run peaked at 65.2 GiB allocated on the last stage after step 1 (the other stages peaked at 32–50 GiB) and ran out of memory there in step 2. The uneven split moves four decoder layers to stages 8–10, which hold the fewest in-flight microbatches under 1F1B.
- **Timeout.** The first step's per-stage startup work (HybridEP setup, kernel compilation) is serialized through the pipeline, and stage 0's first backward can arrive after the default 10-minute NCCL timeout.
- **Transformer Engine first-backward failure.** On TE 2.18 and later, normalization kernels are compiled with NVRTC and configured per thread. The first configuration on PyTorch's GPU-0 autograd thread queries kernel occupancy without making sure a CUDA context is current, and fails with `invalid device context` when a TE norm is the first CUDA work in a pipeline stage's backward. With selective `layernorm` recompute this happens on every non-last stage that ends with an MoE layer (most of them); full-layer recompute triggers it on every non-last stage. Not recomputing the norms avoids the trigger, and cuDNN normalization kernels avoid TE's NVRTC norm path entirely.

This PR replaces its earlier, timeout-only change for the 192-GPU layout.

# Additional Information

- Related to NVBug 6674155.
- Breaking change: callers of the old recipe name must switch to the new name or the generic alias.
- Caveat for `PP` overrides: Bridge does not check the number of `|` segments in `hybrid_layer_pattern` against PP×VPP. With VPP unset, Megatron-Core builds one segment per pipeline rank, so a `PP` that divides 12 builds only `PP` of the 12 segments without an error, and the default `assume_ok_unexpected` checkpoint strictness ignores the missing layers. For example, the README's GB200 SFT row (`PP=3`) would train 27 of the 108 decoder layers unless `model.hybrid_layer_pattern` is overridden as well. Muse Glimmer recipes split their patterns the same way. A provider-level check is tracked separately.
- Launching through `scripts/training/run_recipe.py` without exporting `PYTORCH_CUDA_ALLOC_CONF` leaves the allocator without expandable segments: Transformer Engine initializes CUDA during import, before the recipe environment is applied. `slurm_sft.sh` exports it. The 48-node run above used the unexported path, so reserved memory reached about 73 GiB on some ranks; fixing the launcher is separate from this PR.
