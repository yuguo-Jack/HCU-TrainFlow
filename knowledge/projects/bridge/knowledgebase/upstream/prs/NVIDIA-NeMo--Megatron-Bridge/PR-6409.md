# [sync][training] fix: honor per-rank checkpoint object loading

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6409) · state: closed · merged: True

## Original PR description

# What does this PR do?

Honor `CheckpointConfig.ckpt_fully_parallel_load_per_rank_objects` when constructing the fully parallel checkpoint loader. With `fully_parallel_load=True` and this option enabled, Bridge currently constructs Core's strategy with `per_rank_object_load=False`, silently retaining the global object-exchange policy.

# Changelog

- Forward the inherited option to `FullyParallelLoadStrategyWrapper` in the native distributed checkpoint loader.
- Cover both option values with the real Core wrapper constructor, preserving the existing process group and cached strategy.

Supported trigger: Bridge pretraining/resume using `torch_dist` checkpoints and fully parallel loading. The path runs through setup, the checkpoint manager, `_load_checkpoint_from_path`, `_load_base_checkpoint`, and `_load_global_dist_base_checkpoint`.

Core already implements per-rank object reads in NVIDIA/Megatron-LM#5551. Its MLM entrypoint forwards this option; Bridge's separate caller omitted it. The default remains `False`. Existing config documentation is inherited from Core; no API or checkpoint format changes are introduced.
