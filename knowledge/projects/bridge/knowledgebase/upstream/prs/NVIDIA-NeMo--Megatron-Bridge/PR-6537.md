## Original PR description

## Background

Nightly Megatron-Core bump for the `main` lane: MCore `8442db19` → `db3a6cd8a03eb550e9fa4532a0db96778bb56fc5` (9 commits). `.dev.commit` is unchanged.

## What changed

- `.main.commit` and the `3rdparty/Megatron-LM` gitlink now point to `db3a6cd8`.
- `uv.lock` was regenerated with `uv lock --upgrade` (uv pinned by `docker/Dockerfile.ci`). `pyproject.toml` is unchanged; the TE, flash-mla and fast-hadamard-transform dependency metadata already matches MCore at `db3a6cd8`.
- Two Qwen3.5 long-context recipe unit tests now call `mixed_precision.finalize()`/`setup()` before `validate()`, the same order `runtime_config_update` uses. MCore 65ac8216e (#7606) rejects GLU interleave with fp32 params, so the fp8 variants failed when they were validated before mixed-precision setup.

## Details

Lock changes vs `main`: openai 3.35.1, paramiko 5.1.0, platformdirs 4.13.4, virtualenv 21.14.10.

## Tested

Ran on H100 in a validation image built from the bump head `cca79933` (same MCore pin and lock as this branch). The source tested is this exact tree.
- Unit: 4/4 rows passed (Core shards 0–2 and Diffusion). Before the test fix, Core shard 1 failed 2 fp8 GLU-interleave cases.
- Functional: 74/75 rows passed. `L1_Launch_recipes_glm_vl` was skipped because the GLM-4.5V HF config is not available offline; main CI skips the same tests for the same reason (run 39103294373).
- `L1_Launch_gtp_checkpoint_conversion` skips its MXFP8 case because it needs Blackwell, as on main CI.

CI on this PR is pending.
