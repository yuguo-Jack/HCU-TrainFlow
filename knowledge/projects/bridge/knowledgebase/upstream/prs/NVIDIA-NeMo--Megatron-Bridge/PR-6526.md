# test(model): drop phantom llama3 RoPE fields from the EXAONE 4.0 provider test

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6526) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes `L2_Launch_models_exaone` on H100 and GB200, which has failed on `main` since #6401 (first failing nightly: [run 38987004275](https://github.com/NVIDIA-NeMo/Megatron-Bridge/actions/runs/38987004275) on 20dd692f1).

```
AssertionError: Converted provider for exaone4-config-only is missing attributes: {'rope_scaling_original_max_position_embeddings', 'rope_scaling_low_freq_factor', 'rope_scaling_high_freq_factor'}
```

**Cause:** #6401 stopped setting `rope_scaling_low_freq_factor`, `rope_scaling_high_freq_factor` and `rope_scaling_original_max_position_embeddings` on the EXAONE 4.0 provider. They are not `TransformerConfig` fields, and Megatron Core's llama3 RoPE scaling hardcodes them to 1.0, 4.0 and 8192. The bridge now warns when an HF config asks for other values. `test_exaone4_provider.py` still set all three on its expected provider, and `compare_provider_configs` requires both providers to have the same attribute names. #6401 had no `full-test-suite` label, so this L2 test did not run on that PR.

# Changelog

- Remove the three attributes from `make_expected_exaone4_1p2b_provider()`. The test still checks `rope_scaling=True` and `rope_scaling_factor=16.0`, the only llama3 RoPE values Megatron Core reads. Setting attributes that don't exist on the config is the phantom-field pattern AGENTS.md rules out for tests.

# Verification

- Bisected locally on CPU (Megatron Core 6e7e6ed4, Transformers 5.20, Transformer Engine stubbed; the test only builds and compares configs). The test passes at fc9b814a6^ and fails at fc9b814a6 and 20dd692f1 with the CI error. With this change it passes on current `main` (b35f75578).
- `pre-commit run --all-files` passes.
- Labeled `full-test-suite` so this PR runs L2. The launcher stops at the first failure (`-x`), so the failing nightly did not run the four EXAONE 4.5 and EXAONE MoE conversion tests in the same group. This PR's L2 run covers them.
