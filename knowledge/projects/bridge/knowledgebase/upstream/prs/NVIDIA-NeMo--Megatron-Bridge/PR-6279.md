# feat(recipe): support DSv4 Pro and proxy benchmarks on MCore dev

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6279) · state: open · merged: False

## Original PR description

## What does this PR do?

Align the GB300 DeepSeek V4 Pro performance recipe with the supplied full-model MCore run, and add 64-GPU GB300 and Rubin proxies matching the measured 16-block runs. The recipes support the development MCore APIs and require compatible native kernels; they are not qualified on Bridge's default MCore pin. The current validation target is public `dev` plus NVIDIA/Megatron-LM#5722, with the October 16 NeMo nightly image. Earlier completed GPU results below used the private `dsv4` pin `d211e50e888fcb8640ddc9923e98940800afcfd3`.

| Recipe | GPUs | Main logical blocks + MTP | TP / CP / EP | PP / VPP | Sequence | GBS / MBS |
|---|---:|---|---|---|---:|---|
| Full Pro | 256 | 61 + 1 | 1 / 16 / 64 | 4 / 4 | 65,536 | 256 / 1 |
| Proxy (GB300 / Rubin) | 64 | 16 + 1 | 1 / 16 / 64 | 1 / none | 65,536 | 256 / 1 |

The proxy keeps the full widths, expert geometry, attention/MoE kernels, and optimizer. It reduces GPU cost per iteration; it does not exercise PP/VPP or establish faster wall-clock steps.

## Changelog

- Restore the Rubin Pro proxy under the current `vrnvl72` recipe name, including the export and DSv4 step selector. It retains the GB300 proxy settings and the earlier Rubin run's MoK communication allocation of 40 SMs forward/backward. Legacy `vr200` launch input resolves through the existing alias.
- Initialize public MCore's DSA metric tracker before forward/graph capture, clear its storage in place between attempts, and reduce/report it on all participating ranks using the owning model's process groups. Preserve older runtimes without this lifecycle API.
- Set `is_hybrid_model=True` as native MCore does for hybrid patterns. This corrects initialization scaling and layer accounting; earlier Bridge runs inherited `False`, so the updated recipes do not reproduce their exact initial weights.
- Forward strict tokenizer-save error handling through the checkpoint compatibility wrapper instead of rejecting its keyword argument.
- Match the logged Pro architecture and `[3] + [4] * 14 + [2]` logical-block pipeline split; retain MTP in both recipes.
- Use layer-wise Muon, MXFP8 parameter gathering, FP32 gradient reduction, MoK/HybridEP, attention-only TE graphs, and selective MLA/mHC recompute with group size two. Disable activation offloading and paged stash.
- Add a fixed synthetic THD dataset with the logged pack shape, static boundary capacity, padding mask, and contiguous CP slicing. Preserve the dataset in the performance launcher and select the DSv4 forward step in both launch paths.
- Prepare development-MCore CP routes before the forward pass, and forward the layer-wise optimizer flag into DDP buffer construction while preserving the separate optimizer/DDP settings.
- Support the development MCore's legacy FSDP names and fixed rank-zero logging. Defer newer checkpoint APIs and reject unsupported GTP/tokenizer-asset requests explicitly; add focused compatibility tests. The first real container build exposed these missing imports.
- Add recipe/data/forward-step/optimizer regression tests and launch documentation. Require declared development-MCore capabilities instead of silently assigning unsupported fields.

Primary area: `area:recipe`. Related background: NVIDIA/Megatron-LM#5795.

Proxy throughput accounting: Bridge reported about 850 model TFLOP/s/GPU at approximately the same 26.8-second step time as the supplied MCore proxy reporting about 1035. The pinned private MCore uses `o_lora_rank`/`o_groups`, while Bridge's FLOP estimator reads the newer output-projection field names. Consequently, the Bridge counter omits grouped output projections that the model actually executes. Normalizing both to the reference FLOP formula reconciles the figures; this is not evidence of a 20% runtime slowdown. Logged representative-rank peak reserved memory is 206.44 GB versus 206.60 GB in the reference after converting its MiB units. These are not maxima established across all 64 ranks.

The source audit also found an extra 1/64 scaling of the displayed MTP metric and missing indexer metric reporting in Bridge; shared MCore training computation/scaling is present. Input tokens differ (reference ascending, Bridge seeded random), and the external reference CPU-binding wrapper remains unaudited. No performance configuration changes or reporting-code fixes have been applied for this comparison.
