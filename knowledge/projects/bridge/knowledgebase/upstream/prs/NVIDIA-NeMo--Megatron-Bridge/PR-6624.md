# build(security): remediate bundled ffmpeg vulnerabilities

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6624) · state: closed · merged: True

## Original PR description

## Background / motivation

- The `nvcr.io/nvidian/nemo:26.10.rc8` scan reports [CVE-2026-65703](https://nvd.nist.gov/vuln/detail/CVE-2026-65703), [CVE-2026-64835](https://nvd.nist.gov/vuln/detail/CVE-2026-64835), and [CVE-2026-64834](https://nvd.nist.gov/vuln/detail/CVE-2026-64834) in bundled FFmpeg libraries on amd64 and arm64.
- PyNvVideoCodec 2.0.5 still bundles FFmpeg 8.1.2. The existing system `pip uninstall` also leaves OpenCV headless and its FFmpeg 5.1.6 libraries installed under `/opt/venv`.

## What changed

- Upgrade the system PyNvVideoCodec installation to 2.2.3, which bundles FFmpeg 9.0.1.
- Explicitly uninstall `opencv-python-headless` from both Python environments, completing the image's existing optional-codec removal policy.
- Update the container documentation to describe both cleanup targets.

## Details

- Use `uv pip` with explicit interpreter paths for the cleanup and PyNvVideoCodec upgrade. `--no-deps` preserves the framework dependency set.
- Retain the existing system DALI cleanup.
- Both official CPython 3.12 PyNvVideoCodec 2.2.3 Linux wheels include the same FFmpeg 9.0.1 source archive. Verified the reference-frame unref in `tdsc.c`, channel-state synchronization in `adxdec.c`, and minimum ASF object-size validation in `rtpdec_asf.c` against the upstream fixes: [TDSC](https://github.com/FFmpeg/FFmpeg/commit/fd3ee52fab34d98a95b787d0b5ff45685766200c), [ADX](https://github.com/FFmpeg/FFmpeg/commit/1836ef96846937a6cc2443698a693104f5c0b21e), [RTP/ASF](https://github.com/FFmpeg/FFmpeg/commit/11d5f475be95d22d5f0692220cc772b116abc632).

## Tested

- `uv run --no-sync pre-commit run --all-files` inside the framework container: passed. `git diff --check`: passed.
- Executed the changed package-management commands in an amd64 container based on `gitlab-master.nvidia.com/dl/joc/nemo-ci/main-mirror/fw-final:pipe.75623555`, using Docker's `runc` runtime:
  ```bash
  uv pip uninstall --python /opt/venv/bin/python opencv-python-headless
  uv pip uninstall --python /usr/bin/python3 --system --break-system-packages \
      opencv-python-headless nvidia-dali-cuda130
  uv pip install --python /usr/bin/python3 --system --break-system-packages --no-deps \
      'pynvvideocodec==2.2.3'
  ```
- Observed OpenCV headless 4.11.0.86 removed from `/opt/venv`; no package metadata or `opencv_python_headless.libs` directory remains in either environment. Repeating both uninstall commands also succeeds.
- Under both interpreters, PyNvVideoCodec reports 2.2.3, `av_version_info()` returns `9.0.1`, and `avformat_version()` returns `63.1.101`. Verified that the package contains only the new FFmpeg libraries, with no stale FFmpeg 8.1.2 files.
- Opened and closed a generated PCM WAV through the upgraded `libavformat` under both interpreters. `import megatron.bridge` passed in `/opt/venv` after the cleanup.
- Inspected the official amd64 and arm64 wheels and confirmed all three fixes in their bundled source archive (`ffmpeg-9.0.1.tar.xz`, SHA-256 `cf38e0e28c7e5605942c4a77755349b0145804a397af37eb1fb4c77cb237f635`).
- [nemo-ci pipeline 75919920](https://gitlab-master.nvidia.com/dl/JoC/nemo-ci/-/pipelines/75919920) is running on `main-mirror`, pinned to `MEGATRON_BRIDGE_REF=4b971057244c51002afa315bdfff64942de40c0d`. Builds fw-base → Megatron-Bridge → fw-final for amd64 and arm64, followed by image import checks. Model tests and NVCR publication are disabled.
- Full image rebuild/rescan, arm64 execution, and GPU video decoding remain pending. GPU validation on this host is unavailable: `nvidia-smi` reports a driver/library version mismatch.
