# fix(models): default the HF config file lock to HF_HOME instead of ~/.cache/huggingface

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6162) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Make `safe_load_config_with_retry()` create its file lock under `HF_HOME` (via `huggingface_hub.constants.HF_HOME`) instead of `Path.home()/.cache/huggingface`, and name the `MEGATRON_CONFIG_LOCK_DIR` override in the retries-exhausted error when the last failure was a lock timeout.

Why: the lock protects the Hugging Face config cache, but its default location ignored `HF_HOME`, so on containerised clusters it landed in `/root/.cache/huggingface` on the ephemeral container layer. On an 8-node × 4-GPU HF→Megatron import of DeepSeek-V4-Pro (nemo:26.08, pyxis/enroot, `HF_HOME` on a shared filesystem) every rank timed out 4 × 60 s:

```text
filelock._error.Timeout: The file lock '/root/.cache/huggingface/.megatron_config_lock_fe96e83596e6dfb94d32c391d3b8772e.lock' could not be acquired.
ValueError: Failed to load configuration from deepseek-ai/DeepSeek-V4-Pro after 4 attempts. This might be due to network issues or concurrent access conflicts. Last error: ...
```

Setting `MEGATRON_CONFIG_LOCK_DIR` to a shared directory fixed it, but the override was only documented in the docstring and not mentioned by the error. With this change the default follows `HF_HOME` (identical behaviour when `HF_HOME` is unset; `MEGATRON_CONFIG_LOCK_DIR` still takes precedence) and the error tells the user what to do.
