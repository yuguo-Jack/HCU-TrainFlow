# fix(model): accept is_mtp_layer in Kimi K3 attention

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6362) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes every Kimi K3 model build failing with `TypeError: ... unexpected keyword argument 'is_mtp_layer'` by accepting the flag MCore now passes to self-attention.

# Changelog

- `src/megatron/bridge/models/kimi/kimi_k3_layers.py`: `KimiK3Attention.__init__` accepts and discards `is_mtp_layer: bool = False`.
- `tests/unit_tests/models/kimi/test_kimi_k3_bridge.py`: 2 tests building `KimiK3Attention` (KDA and MLA layer) through a real MCore `TransformerLayer`.

# Additional Information

- **Root cause:** MCore `TransformerLayer` (current pin `159b443c`, L416) always passes `is_mtp_layer` to self-attention; `KimiK3Attention` had a closed signature. K3 has no MTP layers. The other kwargs MCore passes (`cp_comm_type`, `pg_collection`, `pp_layer_offset`, `name`) are already accepted.
- **Regression?** Yes, since MCore bump #6052 (`1e1b58f7`), which patched the DiT attention classes only. Still present on main `d3fcda9f`. Blocks all K3 import/export/generation.
- **Verification (commit `15021cc7`, base `d3fcda9f`, `nemo:26.10.rc4`, MCore `159b443c`):** RED (EOS job 6209597): both new tests raise the TypeError on unpatched main. GREEN (EOS job 6209247): `tests/unit_tests/models/kimi/` 14 passed. Earlier E2E on the real Kimi-K3 4-layer cut at TP8/EP8 (10-06, previous base): import, MXFP4 export and generation pass.
- **Not included:** o_norm FP32->BF16 and MXFP4 byte drift on export (documented on the model card).
- **NVBug:** 6863113.
