# docs(nemotron): document IITC LoRA training with Bridge CLI

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6338) · state: closed · merged: True

## Original PR description

## What does this PR do?

Add an IITC LoRA tutorial using the existing Bridge recipe CLI, native checkpoint conversion, and `examples/peft/merge_lora.py`. It prepares an illustrative 10,000-example training subset and 210-example validation subset, then evaluates original and merged HF checkpoints on the full 658-example IITC-8K test split.

## Changes

- Put the guide in `tutorials/recipes/nemotron/iitc-lora.md` and link it from the Super VL README.
- Keep only data preparation and evaluation helpers under the model example. No custom training launcher, export helper, or verification scripts are included.
- Remove `selection.csv`. Describe the historical selection briefly and generate a fresh seeded subset with disjoint source papers, question deduplication, and native token-length filtering.
- Replace full activation recompute with selective `layernorm` and `moe` recompute.
- Use the existing import and LoRA merge scripts, retaining the training parallelism during conversion and merge.
- Preserve historical results as historical results; the newly sampled rows do not reproduce the old selection exactly.

## Validation

- Native Bridge recipe/CLI smoke test on 16 H100 GPUs: three optimizer updates completed with selective `layernorm` + `moe` recompute, no skipped updates or NaNs. Disabling recompute and using only `moe_act` each ran out of memory in the first update.
- Data checks passed: deterministic sampling on the published sources, paper-disjoint training/validation, native collator length filtering, and Energon packaging/indexing of a small real-image sample.
- Standard HF-to-native import and LoRA merge/export completed on 16 GPUs at the training TP/PP/EP of 4/2/8. Four sampled tensors (two frozen vision tensors and two adapted language projections) match the historical export byte-for-byte. The resulting standalone HF model passed strict loading with no missing/mismatched tensors or runtime adapters and generated one held-out response (64-token smoke). The original checkpoint passed the same check.
- Pre-commit checks, Markdown relative links, and shell syntax passed.

These are targeted runtime checks, not a repeat of the full 625-step training run or 658-example evaluation. The historical metrics are unchanged. Full HF/Megatron forward-logit parity has not been measured.

A TP2 merge loaded and generated successfully but differed from the historical export in a sampled Mamba input projection. Keeping the training TP4 layout eliminated that sampled mismatch. The tutorial therefore retains the training parallelism; changed-TP adapter resharding is not validated here.

## Validation fixture

The import/merge test uses a canonical view of the historical source weights, excluding aliases and a buffer previously added by experiment preparation; no learned tensors are changed. The original inference check uses the supplied historical checkpoint. Bridge's existing exporter adds the deterministic vision buffer to the merged HF output. No checkpoint-layout helper is introduced in this PR.

## Base branch

Stacked against `huvu/super_35_vl_tutorial_base`, the verified training snapshot, because the required recipe is not available on this PR's original main-branch baseline. Retarget after the prerequisites land and compatibility is revalidated.

Repository CI has not been triggered manually; the validation above is local.
