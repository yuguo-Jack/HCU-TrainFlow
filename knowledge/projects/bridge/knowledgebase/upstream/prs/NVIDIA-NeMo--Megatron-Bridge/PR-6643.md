# fix(ckpt): copy source artifacts from the local HF cache when the Hub is offline

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6643) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes offline (`HF_HUB_OFFLINE=1`) exports dropping the files `_copy_custom_modeling_files` copies from a Hub source, which makes the nemotron-3-nano-4b GPU export fail with `GenerationConfig is invalid ... top_p`.

# Changelog

- `src/megatron/bridge/models/hf_pretrained/base.py`: when `list_repo_files()` fails (for example with `HF_HUB_OFFLINE=1`), `_copy_custom_modeling_files` copies the matching files from the cached snapshot of the requested revision instead, per pattern via `snapshot_download(..., local_files_only=True, allow_patterns=[pattern])`, by repository-relative path, and logs the fallback. Behavior is unchanged when the listing succeeds; a revision that is not cached still copies nothing.
- `tests/unit_tests/models/hf_pretrained/test_base.py`: offline fallback for a commit revision and the default branch, an incomplete cached snapshot handled per pattern, `save_artifacts` keeping the source `generation_config.json` offline, and still raising when the revision is not cached.

# Additional Information

- **Root cause:** #4994 made `save_artifacts` keep the source `generation_config.json` verbatim when Transformers refuses to re-save it under strict validation. For a Hub model ID that copy goes through `_copy_custom_modeling_files`, which starts with `list_repo_files()`. Offline, that call raises `OfflineModeIsEnabled`, the helper silently copies nothing, and the original `ValueError` is re-raised. nvidia/NVIDIA-Nemotron-3-Nano-4B-BF16 sets `top_p` without `do_sample`. The same gap silently drops bridge-specific additional files such as `nano_v3_reasoning_parser.py` from offline exports.
- **Other affected models:** zai-org/GLM-5, zai-org/GLM-5.2 and LGAI-EXAONE/K-EXAONE-2.0-750B-A37B ship the same generation config pattern (`top_p` without `do_sample`; checked by re-saving each card's pinned `generation_config.json` with Transformers 5.17.0), and their verification-card exports pass a Hub ID as `--hf-model`, so they fail offline the same way without this change.
- **Relation to [#6625](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6625):** #6625 fixes `convert.sh`/`infer.sh --executor slurm` resolving relative `work/` paths in the NeMo-Run job directory. With it, the nemotron-3-nano-4b card's export gets past the path error and then hits this failure in offline runs, so the card commands need both.
- **Verification** (26.10 release-candidate container, 1x H100, the nemotron-3-nano-4b card's `convert.sh`/`infer.sh --executor slurm` commands, `HF_HUB_OFFLINE=1`):
  - r0.7.0: export fails with `FileNotFoundError` (the path bug).
  - r0.7.0 + #6625: export fails with `ValueError: GenerationConfig is invalid ... top_p`; the same export passes online.
  - r0.7.0 + #6625 + this PR: export passes; all 263 tensors are bitwise equal to the pinned source, `generation_config.json` is byte-identical, and the output matches the online export of #6625 alone. `infer.sh --task hf-inference` reloads it strictly and continues "The capital of France is" with " Paris.".
  - Unit tests: the new tests fail on main and pass here; the `hf_pretrained`, nemotron_omni conversion, flux and wan tests that use this helper pass (148).
- **Release:** needs the r0.7.0 cherry-pick together with #6625.

[P2] Honor the source loader's explicit cache directory

**Failure — source reasoning, not executed:** `PreTrainedCausalLM.from_pretrained("org/model", cache_dir=custom_cache)` loads generation metadata from that cache because the [loader forwards `self.init_kwargs`](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/905e9ce350029799e2dd67b1f453004c85e16027/src/megatron/bridge/models/hf_pretrained/causal_lm.py#L249-L257). This snapshot lookup instead always uses the default cache. Offline, if `custom_cache` contains the loaded main revision with `{"top_p": 0.95}` while the default cache contains an older main with `{"top_p": 0.8}`, a rejected generation-config save copies the older file and incorrectly succeeds. With an explicit commit cached only in `custom_cache`, the helper returns no files and [the save re-raises](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/905e9ce350029799e2dd67b1f453004c85e16027/src/megatron/bridge/models/hf_pretrained/base.py#L298-L305) despite the source file being available. Expected behavior is to preserve the artifact from the cache used to load the source.

**Correction:** thread `self.init_kwargs.get("cache_dir")` through `_copy_custom_modeling_files` into `_copy_cached_hub_files` and `snapshot_download`. The invariant is that the fallback resolves both the cache directory and revision consistently with the source loader. Suggested small patch at the [helper](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/905e9ce350029799e2dd67b1f453004c85e16027/src/megatron/bridge/models/hf_pretrained/base.py#L87-L126) and [fallback call](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/905e9ce350029799e2dd67b1f453004c85e16027/src/megatron/bridge/models/hf_pretrained/base.py#L219-L223), to verify before adopting:

```diff
@@ _copy_cached_hub_files keyword parameters

+        cache_dir: str | Path | None = None,
@@ snapshot_download call
-                        repo_id=repo_id, local_files_only=True, allow_patterns=[file_spec], **revision_kwargs
+                        repo_id=repo_id,
+                        cache_dir=cache_dir,

+                        allow_patterns=[file_spec],

@@ _copy_custom_modeling_files fallback
```
