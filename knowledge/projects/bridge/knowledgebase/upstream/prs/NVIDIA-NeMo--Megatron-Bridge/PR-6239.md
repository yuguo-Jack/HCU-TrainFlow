# fix(training): guard eval loss reduction and surface zero-token steps

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6239) · state: closed · merged: True

## Original PR description

Follow-up to #6210: evaluation now uses the same finite-zero guard as standard and MIMO training when the reduced token count is zero. Training also reports zero-token iterations so substituted zeros remain distinguishable from measured losses.

## Behavior

- Preserve token-weighted loss reduction and legacy scalar averaging. Evaluation returns finite zero for an empty evaluation set and warns from the global last rank used by evaluation reporting, including ordinary pipeline-parallel runs.
- Accumulate a device-resident zero-token flag once per training step, after DP×CP reduction. Emit the interval count only when nonzero, preserving healthy-run log text.
- Forward MIMO's flag together with its selected loss through the existing broadcast when the language loss owner differs from the global logging rank. Count once on the receiver; preserve source-local counting and the scalar-loss path.
- Reset the counter at logging boundaries and discard it, including its device buffer, during in-process restart so interrupted attempts do not contaminate the resumed interval.

## Validation

- **361 focused tests passed** in the NeMo 26.08.rc9 container against this PR's unchanged MCore pin `d113016bb2850c4b7d804f24ba72c055d7d4f861`: `test_eval.py`, `test_state.py`, `test_train.py`, `utils/test_train_utils.py`, and `megatron_mimo/test_megatron_mimo_step.py`.
- Regression coverage exercises real warning rank filtering with PP>1, remote tokens preventing false empty-batch warnings, MIMO source/receiver flags with no double counting, healthy and scalar-loss cases, and fresh counter allocation after restart. The inherited loss-reduction test now supplies an iterable optimizer-child list compatible with the current copy helper.
- All-file pre-commit and `git diff --check` passed. Independent follow-up source review found no new actionable issues.
- These are focused unit tests with mocked distributed collectives; no full distributed training validation was performed. Strict mypy was attempted and reports missing dependency stubs and typing errors; it is not a passing check.

## Deferred concerns

- The existing MIMO branch that omits the reduction when `llm_pg.dp_cp` is absent remains unchanged. In that branch both loss and diagnostic reflect local tokens. The standard MIMO provider supplies `dp_cp`; resolving alternate process-group wiring remains separate.
- MIMO evaluation does not forward evaluation results when the global last rank belongs solely to an encoder. That existing layout-specific result-routing limitation also applies to the evaluation warning and is outside this change.
- Zero-token training steps continue to contribute zero to the existing interval loss average; this change exposes their count without changing optimizer or averaging semantics.

File: `src/megatron/bridge/training/utils/train_utils.py` · line 1265

Non-blocking: this count only reaches stdout. The loss for these same steps is still written as 0.0 to TensorBoard, W&B, MLflow and Comet ([L1005-L1015](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/77b9c915f74227d4ad0904bd2b49f43ed7aa42aa/src/megatron/bridge/training/utils/train_utils.py#L1005-L1015)), so on a dashboard it looks like an ordinary data point. Skipped/NaN counts are console-only too, so this matches what's there, but the point of this change is that a substituted 0.0 looks like a real loss, so it would help to see the count where the loss is plotted.

This block already writes iteration time and throughput to all four sinks, and the writers only exist on the logging rank, so it could be:

```python
if writer:
    writer.add_scalar("zero-token-iterations", zero_token_iters, iteration)
if wandb_writer:
    wandb_writer.log({"zero-token-iterations": zero_token_iters}, iteration)
if mlflow_logger:
    mlflow_logger.log_metrics({"zero-token-iterations": zero_token_iters}, step=iteration)
if comet_logger:
    comet_logger.log_metrics({"zero-token-iterations": zero_token_iters}, step=iteration)
```

The console field can stay conditional so healthy-run output is unchanged.
