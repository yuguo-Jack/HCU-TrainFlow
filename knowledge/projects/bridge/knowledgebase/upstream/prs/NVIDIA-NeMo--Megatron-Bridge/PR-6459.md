# feat(training): export OpenTelemetry spans and metrics through nemo-lens

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6459) · state: open · merged: False

## Original PR description

# What does this PR do ?

Adds opt-in OpenTelemetry spans and metrics to Megatron Bridge training through [nemo-lens](https://github.com/NVIDIA-NeMo/Lens), so every rank reports where a job spends its time (startup, iterations, checkpoints, evaluation, conversion) to an OTLP collector.

# Changelog

- **Build:** add an `otel` extra (nemo-lens, the OpenTelemetry SDK, and the OTLP gRPC and HTTP exporters). Override nemo-lens to v0.3.0 (`7bcc03c`) in place of the v0.2.0 pin (`b85578fc`) that megatron-core brings in; Bridge needs the `SpanRegistry` API, which v0.2.0 predates. `uv.lock` is regenerated with uv 0.7.2, the version in `docker/Dockerfile.ci`. On Linux x86_64 and aarch64, the installed packages change only by nemo-lens and `opentelemetry-exporter-otlp-proto-grpc`.
- **New `megatron.bridge.telemetry`:** call-site helpers (`span`, `traced`, `enabled`, `set_span_attributes`) and span groups registered under the `megatron_bridge` namespace. It also registers megatron-core's `microbatch`, `layer`, `communication` and `activation_offload` groups, so megatron-core's own spans can be turned on. When nemo-lens is missing or a group is off, a site creates no span.
- **New `megatron.bridge.telemetry.lifecycle`:** when telemetry is enabled and no other library owns the OpenTelemetry providers, `pretrain()` installs them on every rank; so do `finetune()` and `distill()`, which call it. It flushes them when `pretrain()` returns, at exit, and on SIGTERM. Library functions that NeMo-RL calls never install providers; their spans record under the host's providers.
- **Configuration:** no new fields. Bridge uses the `logger.otel_enabled`, `logger.otel_span_groups` and `logger.otel_service_name` fields that `LoggerConfig` inherits from Megatron-LM, and the same `MEGATRON_OTEL_*` environment variables, falling back to `NEMO_LENS_*`. Telemetry is off by default.
- **Spans:** startup, data iterator setup, model build, first iteration, and each iteration with its forward-backward and optimizer phases. Also evaluation, checkpoint save (state dict, I/O, async schedule and finalize, Hugging Face export), checkpoint load, and the `AutoBridge` conversion methods. Spans carry `dl.iteration`, numbered as in the training log.
- **Metrics:** megatron-core's `megatron.training.step_duration_ms`, `throughput_tflops`, `memory_allocated_gb` and `skipped_iters`, recorded at every log interval. Loss and learning rate stay with the experiment trackers.
- **Fix (ckpt):** the async finalize span records how many calls it finalized (`megatron.checkpoint.finalize.count`), because NVRx 0.7.0 reports call index 0 for every finalized call.
- **Style:** `ruff format` of `training/setup.py`: three statements reached `main` unformatted. No behavior change.
- **Tests:** unit tests for the helpers, the lifecycle (including SIGTERM in a subprocess) and the call sites, plus two `training_log` tests. A 2-GPU functional test, added to `L0_Launch_training_pretrain.sh`, trains, resumes, and checks the spans and metrics of each rank.
- **Docs:** new `docs/training/observability.md` guide and its Fern copy. It covers installation, enabling telemetry, collectors, configuration, span groups and spans, metrics, resource attributes, distributed runs, use inside another application, limitations and overhead. The logging guide, the training README, the Sphinx toctree and the nightly Fern navigation link to it.

**Known issue: Megatron-LM's training scripts.** Megatron-LM's `_set_telemetry` (`megatron/training/global_vars.py`) still calls `NemoLensConfig.from_env(span_group_cls=...)`, an argument that nemo-lens removed after v0.2.0. Under this PR's override, Megatron-LM's `pretrain_gpt.py` fails at startup in Bridge's environment with a `TypeError`, whether telemetry is enabled or not. Bridge's training loop doesn't call `_set_telemetry`, but these run `pretrain_gpt.py`:

- `L2_Launch_ckpts_mlm_to_mbridge_{llama32_1b,qwen3_4b}.sh` and `L2_Launch_ckpts_mbridge_to_mlm_{llama32_1b,qwen3_4b}.sh`
- the `nemo-mbridge-mlm-bridge-training` skill, and the Megatron-LM path of `nemo-mbridge-multi-node-slurm`

The fix belongs in Megatron-LM: port `_set_telemetry` and `MegatronSpanGroup` to `SpanRegistry`. Once megatron-core pins nemo-lens v0.3.0 or later, the override can go.

**Dependency change.** CONTRIBUTING asks for dependency changes in a separate PR first. The whole change is the first commit (`build: add otel extra and move nemo-lens to v0.3.0`), so it can go in its own PR if you prefer.
