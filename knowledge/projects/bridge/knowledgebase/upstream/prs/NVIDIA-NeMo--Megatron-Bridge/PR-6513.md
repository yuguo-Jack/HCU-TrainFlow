# fix(peft): sum multi-LoRA gradients across tensor-parallel ranks

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6513) · state: open · merged: False

## Original PR description

# What does this PR do ?

Fixes partial gradients in `MultiLoRALinear` under tensor parallelism: `lora_A` and the adapter's input gradient were missing the other TP ranks' contributions, so multi-LoRA training at TP > 1 silently trained on wrong gradients.

## Problem

For a TP-sharded (non-replicated) adapter, `MultiLoRALinear.forward` computes the rank-`r` intermediate `mid = A·x`, gathers it (column-parallel base) or all-reduces it (row-parallel base) so every rank holds the full `mid`, and then multiplies it by the rank's own shard of `lora_B`.

The forward is correct. In backward, the true gradient of `mid` is a sum over ranks, `Σ_r B_rᵀ · dy_r`, but each rank only computes its own term. `gather_from_tensor_model_parallel_region` splits in backward and `reduce_from_tensor_model_parallel_region` is the identity in backward, so nothing sums it. As a result:

- `lora_A` gradients are wrong at any TP > 1, for both column- and row-parallel bases.
- The gradient flowing into the layer input through the adapter is wrong as well: for a row-parallel base because it is computed from the partial `d mid`, and for a column-parallel base without sequence parallelism because `Aᵀ · d mid` is also rank-sharded and is never summed.
- `lora_B` gradients and the forward output are correct, which is why this does not show up in forward-only checks or at step 0 with zero-initialized B.

The single-LoRA path (`ParallelLinearAdapter`) does not have this problem, because its `linear_out` is a `ColumnParallelLinear` whose input goes through `copy_to_tensor_model_parallel_region` (identity forward, all-reduce backward), and its column-parallel `linear_in` all-reduces its input gradient unless sequence parallelism is on. The fused multi-LoRA path skipped both.

We hit this with multi-LoRA training in Miles at TP 2.

## Fix

Mirror `ColumnParallelLinear` in the fused path:

- After the gather/reduce of `mid`, apply `copy_to_tensor_model_parallel_region(mid)` so its gradient is all-reduced.
- For a column-parallel base without sequence parallelism, apply `copy_to_tensor_model_parallel_region(x)` to the adapter input. Under sequence parallelism the existing sequence gather's reduce-scatter already sums it, and a base with suppressed TP communication (shared experts under `moe_shared_expert_overlap`) leaves the reduction to its caller, so neither case changes.

Replicated adapters are unchanged. The cost is one all-reduce of `[tokens, rank]` in backward per adapted linear, plus one of `[tokens, hidden]` for column-parallel bases without SP, which is the same communication the single-LoRA adapter already does.

# Changelog

- `peft/multi_lora_layers.py`: all-reduce the gradient of the rank-`r` intermediate for TP-sharded adapters, and the adapter input's gradient for column-parallel bases without sequence parallelism.
- `tests/unit_tests/peft/test_multi_lora_tp_distributed.py` (new): two-rank test that wraps a `ColumnParallelLinear` and a `RowParallelLinear` base in `MultiLoRALinear` (two slots, uneven token spans) and checks the output, the input gradient and every rank's `lora_A`/`lora_B` gradient shard against an unsharded reference.
- `L0_Launch_peft_replicated_adapters.sh`: run the new test next to the existing two-rank PEFT test.
- `test_multi_lora_layers.py`: the CPU grouped-MM fallback test, which already stubs the TP gather, now also stubs `copy_to_tensor_model_parallel_region`, since its backward needs a process group.

2×H100, fp32 with TF32 disabled, relative error `‖actual − reference‖ / ‖reference‖`, max over both ranks:

| Base | Quantity | Before | After |
| --- | --- | --- | --- |
| column-parallel | `lora_A` grad (slot 0 / slot 1) | 0.863 / 0.900 | < 1e-6 |
| column-parallel | input grad | 0.828 | < 1e-6 |
| row-parallel | `lora_A` grad (slot 0 / slot 1) | 0.743 / 0.591 | < 1e-6 |
| row-parallel | input grad | 0.683 | < 1e-6 |
| both | output, `lora_B` grad | < 1e-6 | < 1e-6 |

- The new test fails on `main` (both parametrizations) and passes with the fix.
- With the fix: `test_multi_lora_layers.py`, `test_multi_lora.py`, `test_multi_lora_moe.py` (93 passed); `test_replicated_peft_distributed.py` + the new test, `test_multi_lora_seeded_slot_distributed.py` and `test_shared_expert_lora_distributed.py` all pass on two ranks.
- Separately, in a TP 2 vs TP 1 comparison of a `TELayerNormColumnParallelLinear` → `TERowParallelLinear` MLP with multi-LoRA on both linears (TE 2.17), `lora_A` gradients were 72–84% off before the fix and matched TP 1 to fp32 noise after.
