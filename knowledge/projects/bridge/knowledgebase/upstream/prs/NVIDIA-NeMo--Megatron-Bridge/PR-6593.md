# refactor(model): build Mistral from a builder-backed model config

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6593) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Moves the **Mistral** bridge (`MistralForCausalLM`; Ministral and Mistral-NeMo checkpoints after #6370) onto the builder-backed `ModelConfig` / `ModelBuilder` path for checkpoint conversion. As a side effect, it fixes Mistral YaRN checkpoints, which fail on `main` (#5627).

# Changelog

- **`MistralBridge`**:
  - The hand-built `provider_bridge()` is replaced by `hf_config_to_model_config_kwargs()`. It starts from the shared `CONFIG_MAPPING` and sets the Mistral settings explicitly: RMSNorm, SiLU, gated MLP, no linear bias, zero dropout, rotary base, `head_dim`, and sliding window with `cp_comm_type="a2a"`.
  - The provider path reuses the same kwargs and still builds a `MistralModelProvider` (`provider=MistralModelProvider` on the registration), which Ministral3 also extends.
  - Opts in with `MODEL_CONFIG_CLASS = BridgeGPTModelConfig` and converts through the builder (`USE_MODEL_CONFIG_FOR_CONVERSION = True`).
- **YaRN (#5627)**: on `main`, a YaRN `rope_scaling` makes the bridge pass a nonexistent `scale_factor` argument, and provider construction raises `TypeError`. The shared mapping now sets `position_embedding_type="yarn"` and the `yarn_*` fields on both paths. #6319 (@deximple) proposed the provider-only fix; its test case is carried over here.
- **Tests**: new `tests/unit_tests/models/mistral/`; Mistral had no bridge unit tests. It covers the builder mapping, provider/builder parity (Ministral-like with sliding window, NeMo-like with `head_dim` ≠ hidden/heads, tied fp16, YaRN), YaRN fields on both paths, and `sliding_window` export from a builder config.

# Verification

Tiny random-weight Mistral checkpoints on a single GB200 node in the NeMo 26.10 container against `main` (Megatron Core ebab48fc4):
- **Ministral-like:** sliding window.
- **NeMo-like:** `head_dim` ≠ hidden/heads.

**Conversion paths:**
- `scripts/conversion` GPU import at TP2 and export.
- `AutoBridge.import_ckpt` / `export_ckpt`.
- Load + forward as in `compare.py`.
- `roundtrip_checkpoint`.

Each was run on this branch and on `main`.

| Check | Ministral-like | NeMo-like |
|---|---|---|
| Provider fields, `main` vs this branch (also an fp16 source) | identical | identical |
| `get_model_config()` vs provider (also fp16 and YaRN) | 0 diffs | 0 diffs |
| Export vs source HF weights (GPU TP2, CPU, and from a `main`-imported checkpoint) | exact, 39 tensors | exact, 39 tensors |
| Logits: this branch vs `main`, and this branch on a `main`-imported checkpoint | bitwise-identical | bitwise-identical |
| Logits vs HF | cosine 1.000000 | cosine 0.999986 |
| `roundtrip_checkpoint` TP2 | pass | pass |

**YaRN:** on `main`, building the provider for a YaRN config raises `TypeError: MistralModelProvider.__init__() got an unexpected keyword argument 'scale_factor'`. On this branch, both paths produce `position_embedding_type="yarn"` with the HF factor and original context length, and the two configs match field for field.

**Unit tests** (rerun after rebasing onto `main` with Megatron Core 89b28875): 358 passed, 1 skipped across `models/mistral`, `models/ministral3`, `test_retired_model_removal.py`, `test_autobridge_registration_matrix.py`, `test_gpt_model_config.py`, `test_auto_bridge.py` and `test_model_bridge.py`. One failure, `test_model_bridge.py::test_modelopt_plan_keeps_tasks_after_a_sparse_slot`, is a modelopt `ImportError` in this container and fails the same way on `main`.

**Lint:** `ruff check` and `ruff format --check` are clean (ruff 0.16.7; `pre-commit` itself not run).
