# fix(model): compute the text-only Super VL forward reference in-process

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6601) · state: closed · merged: True

## Original PR description

# What does this PR do ?

The text-only Super VL card's `manual_forward_pass` failed when run as published, because it read `--hf-logits-path hf-reference.pt` and nothing produces that file. It now computes the HF reference in-process with `--hf-device cpu`.

# Changelog

- `examples/model_verification_cards/nemotron-3.5-super-vl-120b-a12b-text-only/card.yaml`: `--hf-logits-path` is replaced by `--hf-device cpu`, and the result, date and evidence are re-recorded.
- `docs/_static/model-verification/catalog-v1.json`: regenerated.

# Additional Information

- **Root cause:** with `--hf-logits-path`, compare.py loads a saved reference instead of running HF. No card item, README or script writes that file, and the validator allows only one `command` for `manual_forward_pass`.
- **Verification:** 4x GB200, nemo:26.08.01, card pin 5e63b9d9. Import and export were re-run at 3a5b4f61. Compare: token 16489 matches, cosine 0.999996. Card/catalog doc-consistency tests pass and the catalog `--check` is clean.
- **Not fixed (other 7 cards, still open under NVBug 6965563):** `--hf-device cpu` hit the 10-minute NCCL timeout for super-vl (1474-token prompt) and gpt-oss-120b (MXFP4 load). beam, glm5, glm5-2 and muse-spark do not fit in a GB200 node's host RAM. k-exaone-2 needs `swiglu_limits`, which HF does not apply. These need a published producer step, which the card schema has no place for yet.
- **Regression?** No. The reference was produced outside the repo from the start.
- **NVBug:** 6965563.
