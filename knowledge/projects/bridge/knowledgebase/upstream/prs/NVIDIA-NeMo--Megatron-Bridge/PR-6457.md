## Original PR description

## Background

Nightly Megatron-Core bump, main lane. Pins MCore `main` to `de003e9932ce777e5bdcf41ed178c04c8839ec7f` (from `a98aed55`, 12 commits). `.dev.commit` is unchanged.

## What changed

- `.main.commit` and the `3rdparty/Megatron-LM` gitlink now point to `de003e99`.
- `uv.lock` regenerated with `uv lock --upgrade` (uv 0.7.2); `pyproject.toml` unchanged. Seven non-GPU packages moved: markdown, mlflow, mlflow-skinny, mlflow-tracing, openai, starlette, wrapt.
- Gemma4 fix: MCore #7709 removed the `te_checkpoint` re-export from `moe_layer`. `Gemma4MoELayer` recompute now goes through `precision_aware_checkpoint`, matching upstream `MoELayer`. The unit test now monkeypatches `megatron.core.extensions.transformer_engine.te_checkpoint`.

## Details

- Locally, `L0_Launch_megatron_fsdp` and Core unit shard 1/3 failed when TE auto-selected FlashAttention 4. Both failures reproduce on the old pin and image. Both pass with CI's FlashAttention policy (`NVTE_FLASH_ATTN_V2=1`, V3/V4=0, from `test-template/action.yml`), so they are not caused by this bump.
- `L0_Launch_recipes_deepseek` skips every case on H100, as in CI: five cases need the DSv4 toy model, which is not in TestData, and one is MXFP8, which needs Blackwell. It is not counted as passed. The MCore delta does not touch DSv4 modules.

## Tested

Local H100 runs on the merge of this head with `main` `535a57a2` (tree `390db483`), using the validation image with diffusion deps:
- Unit: Core shards 0/3, 1/3 and 2/3, plus Diffusion — passed.
- Functional: 39 impact-selected L0/L1/L2 rows passed, covering converter, megatron_fsdp, DeepSeek/Qwen3/Gemma4-VL/Nemotron-Omni models, training (pretrain/finetune/resiliency/checkpointing), GTP conversion, and MLM↔MBridge checkpoints. 33 model-family L1/L2 rows judged unaffected were left to CI.
- `uv lock --check`, `ruff check`, `ruff format --check`: pass.
- Required CI: pending.

Re: review 5518307907, which could not check the checkpoint call because the submodule was not visible.

- **Pinned helper:** at MCore `de003e9932ce777e5bdcf41ed178c04c8839ec7f`, `megatron/core/transformer/utils.py:607` defines `precision_aware_checkpoint(function, config, tp_group, /, *args, distribute_saved_activations=False, **kwargs)`.
  - When `config.fp8 or config.fp4` is set, it lazily imports `megatron.core.extensions.transformer_engine.te_checkpoint` and calls `te_checkpoint(function, False, tensor_parallel.random.get_cuda_rng_tracker, tp_group, *args)`.
  - Otherwise it calls `tensor_parallel.checkpoint(function, False, *args)`.
  - These are the same calls the removed `Gemma4MoELayer` branch made.
- **Unit test:** the test now monkeypatches `te_checkpoint` at that lazy-import location. Its BF16, FP8 and FP4 assertions are unchanged.
- **Local H100 runs on this tree:**
  - `test_moe_layer_recompute_uses_expected_checkpoint_for_training[fp8]` and `[fp4]` passed in Core unit shard 0/3 (4050 passed).
  - `[bf16]` passed in Core unit shard 1/3 (4024 passed).
