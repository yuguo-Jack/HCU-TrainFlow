# docs(model): publish a two-node H100 geometry for Super VL conversion

## Original PR description

# What does this PR do ?

Fixes the full Super VL card's H100 GPU import/export and SFT export running out of memory on 4x H100 80GB, by publishing a verified 2x4 geometry.

# Changelog

- `examples/model_verification_cards/nemotron-3.5-super-vl-120b-a12b/card.yaml`: `hf_to_megatron_gpu`, `megatron_to_hf_gpu` and the `sft_export_inference.H100` export use `--nodes 2 --gpus-per-node 4 --tp 1 --pp 2 --ep 4 --etp 1`; `last_verified` 2026-10-21. The GB200 SFT leaf keeps its 1x4 command.
- `docs/_static/model-verification/catalog-v1.json`, `docs/models/nemotron/nemotron3.5-super-vl.md`, `docs/fern/.../nemotron3.5-super-vl.mdx`: regenerated from the card.

# Additional Information

- **Root cause:** at 1x4 TP1/PP2/EP2, PP rank 1 OOMs while it builds the output layer (62.67 GiB allocated, 14.90 GiB reserved but unallocated, on a 79 GiB device). Cards may not publish an allocator env var, so the fix is the geometry.
- **Regression?** No. The 1x4 command never reproduced on H100; GB200 at 1x4 still passes.
- **Verification:** ran the real `convert.sh`/`infer.sh --executor slurm` commands on `nemo:26.08.01`. Import and export at pin 3a5b4f610 pass on H100 and GB200 (2x4). The export matches the source exactly in keys, shapes, dtypes and values: all 43,079 tensors, vision tower and projector included. The H100 SFT export at fb082ba94 plus HF reload at e2cf6cbb3 pass (1453 modules, 7 tokens, "Losses of the two models").
- **Not re-run:** `manual_forward_pass` and the GB200 SFT leaf (both unchanged). No unit test (data-only change); the existing card and catalog tests pass.
- Same fix as #6600 (text-only card); this branch is independent of it.
- **NVBug:** 6969502.
