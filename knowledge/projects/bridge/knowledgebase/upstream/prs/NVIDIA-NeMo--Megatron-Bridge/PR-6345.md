# build: upgrade W&B to 0.30.0 and use bundled core binaries

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6345) · state: open · merged: False

## Original PR description

# What does this PR do?

Upgrade W&B to 0.30.0 in the Bridge package and Framework image, including the separate system installation inherited from the base image. This replaces the older bundled Go components in both `wandb-core` copies.

# Changelog

- Raise the Bridge dependency and UV override to `wandb>=0.30.0`, and pin the Framework environment to `wandb==0.30.0`.
- Regenerate `uv.lock` with `uv lock --upgrade-package wandb==0.30.0` inside the Bridge CI container.
- Replace both custom `wandb-core` source rebuilds with the packaged binaries. The existing rebuilds retained older Go/gRPC pins; the 0.30.0 Linux wheels contain Go 1.27.1, `golang.org/x/crypto` 0.57.0, gRPC 1.83.2, and go-git 5.19.2.
- Explicitly upgrade W&B using `/usr/bin/python3` for the system copy; the Framework UV sync upgrades `/opt/venv`. The system install permits modification of the container's externally managed interpreter.

# Lockfile delta

```text
Updated wandb 0.29.0 -> 0.30.0
Added googleapis-common-protos 1.75.5
Added opentelemetry-exporter-otlp-proto-common 1.44.0
Added opentelemetry-exporter-otlp-proto-http 1.44.0
```

These additions satisfy W&B 0.30.0's new OTLP exporter dependencies. Other locked package versions and the MCore submodule are unchanged.

# Validation

- [x] `uv lock --check` in the Bridge CI container.
- [x] `uv run pre-commit run --all-files` in the Bridge CI container.
- [x] Executed the new Dockerfile system-install command in a disposable Framework container after upgrading the venv copy.
- [x] Both Python interpreters report W&B 0.30.0 and pass offline `init` / `log` / `finish`, producing an offline run artifact.
- [x] Both installed amd64 `wandb-core` files byte-match the audited official 0.30.0 wheel. Official amd64 and arm64 wheel build metadata contains the fixed component versions listed above.
