# refactor(model): build ERNIE 4.5 from a builder-backed model config

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6552) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Moves **ERNIE 4.5 (text MoE)** onto the builder-backed `ModelConfig` / `ModelBuilder` path for checkpoint conversion, following Muse Glimmer and the families already migrated (#6365, #6379, #6383, #6392, #6401, #6551). ERNIE 4.5 has no library recipes.

# Changelog

- **`Ernie45Bridge`**:
  - `provider_bridge()` is replaced by `hf_config_to_model_config_kwargs()`, and the provider path reuses the same kwargs.
  - The ERNIE specifics carry over unchanged:
    - hardcoded `rotary_base` with interleaved RoPE;
    - sigmoid routing with expert bias and shared experts;
    - MTP disabled, because the checkpoints ship no MTP weights;
    - `moe_layer_freq` derived from either `mlp_layer_types` or `moe_layer_start_index`.
  - The builder config leaves `transformer_layer_spec` unset: Megatron Core's builder default for MoE models is already `get_gpt_decoder_block_spec`, which honors the dense-first `moe_layer_freq`. The deprecated provider path keeps `_ernie45_decoder_block_spec` in `hf_config_to_provider_kwargs()`.
  - Fields whose builder-config default differs from the provider's (`masked_softmax_fusion`, `rope_scaling_factor`) are set explicitly.
  - Opts in with `MODEL_CONFIG_CLASS = BridgeGPTModelConfig` and converts through the builder (`USE_MODEL_CONFIG_FOR_CONVERSION = True`).
- **`instantiate_utils`**: allows the private `_ernie45_decoder_block_spec` target when loading run configs, so checkpoints imported through the provider path can be reloaded (see Verification).
- **Tests**: builder mapping, provider/builder parity for both HF config formats (integer and list MoE fields), `megatron_to_hf_config()` from a builder config, and resolution of the legacy spec target.

# Verification

Tiny random-weight ERNIE 4.5 MoE checkpoints (dense first layer, shared experts), untied and tied, on a single GB200 node in the NeMo 26.10 container against `main` (Megatron Core ce852bfb9).

**Conversion paths:**
- `scripts/conversion` GPU import at TP2 and export.
- `AutoBridge.import_ckpt` / `export_ckpt`.
- Load + forward as in `compare.py`.
- `roundtrip_checkpoint`.

Each was run on this branch and on `main`.

| Check | Untied | Tied |
|---|---|---|
| Provider fields, `main` vs this branch (also an fp16 source) | identical | identical |
| `get_model_config()` vs provider | 0 diffs | 0 diffs |
| Export vs source HF weights (GPU TP2, CPU, and from a `main`-imported checkpoint) | exact, 81 tensors* | exact, 80 tensors* |
| Logits: this branch vs `main`, and this branch on a `main`-imported checkpoint | bitwise-identical | bitwise-identical |
| Logits vs HF | cosine 0.99998 | cosine 0.99998 |
| `roundtrip_checkpoint` TP2 | pass | pass |

\* The router expert bias (`moe_statics.e_score_correction_bias`) of a bf16 source is exported as fp32, because Megatron keeps it in fp32. The values are identical after a cast.

**Checkpoints imported on `main` could not be reloaded.** On `main`, the provider path serializes `_ernie45_decoder_block_spec` into `run_config.yaml`, and the deserialization allowlist rejects private targets, so `load_megatron_model` fails on any ERNIE 4.5 checkpoint imported with `main`. That blocks export, for example. Checkpoints imported with this PR serialize `transformer_layer_spec: null` and are unaffected. The added allowlist entry keeps existing checkpoints loadable, mirroring the legacy Gemma 4 entry. Because unmodified `main` cannot reload its own checkpoint, the `main` logits above were produced with `main` plus only this allowlist line.

**Unit tests:** 439 passed, 1 skipped across `models/ernie`, `utils/test_instantiate_utils.py`, `test_gpt_model_config.py`, `test_auto_bridge.py` and `test_model_bridge.py`.

**Lint:** `ruff check` and `ruff format --check` are clean (ruff 0.16.7; `pre-commit` itself not run).
