# [training] fix: validate terminal MegatronMIMO weights

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6079) · state: open · merged: False

## Original PR description

## What

MegatronMIMO training now validates terminal weights when natural completion falls between configured validation intervals.

Supported trigger: a MIMO run reaches `train_iters` with validation data and `eval_iters > 0`, while the terminal iteration is not divisible by `validation.eval_interval`. Previously the loop returned directly to teardown, silently omitting the final validation pass.

## Root cause and fix

`train_megatron_mimo` owns interval validation, but `pretrain_megatron_mimo` lacked the standard pretraining lifecycle’s post-training validation boundary. The fix evaluates only at natural target completion, only when validation is enabled and was not already performed at that iteration, and forwards the existing MIMO communicator and process-group collection. Early exits before the target remain unchanged.

## Scope

This does not add new configuration or change interval validation. It only restores the terminal validation pass for supported natural MIMO completion and avoids duplicate evaluation on interval-aligned completion.

**Light review — LGTM**

The change adds a terminal validation pass at natural MIMO training completion, mirroring the standard `pretrain.py` VALIDATION block, and correctly avoids double-evaluating when the final iteration already coincided with an interval eval (`iteration % eval_interval != 0`). The `eval_interval` fallback (`cfg.validation.eval_interval` → `cfg.train.eval_interval`) matches the training-loop resolution at `train_megatron_mimo.py:241-243`, and the `evaluate_and_print_results(config=cfg, ...)` call is consistent with the existing interval eval. Coverage is good: the unit test asserts the `train → evaluate → finish` ordering, and the functional test now uses `eval_interval=2` so it exercises the terminal path specifically rather than the interval path.

Minor (non-blocking): the unit test patches `evaluate_and_print_results` with `create=True`; since the symbol is now imported at module scope, `create=True` is unnecessary and could mask a future rename/removal of that import. Consider dropping it.

**Suggested test cases**
- `test_pretrain_megatron_mimo_evaluates_terminal_weights_after_natural_completion` (unit)
- `test_megatron_mimo_interval_validation` (functional)

No perf tests impacted.
