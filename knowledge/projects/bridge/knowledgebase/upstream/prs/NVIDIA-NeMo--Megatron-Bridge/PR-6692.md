# chore: CheckpointConfig.finalize() runs the inherited checkpoint validation

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6692) · state: open · merged: False

## Original PR description

# What does this PR do ?

Prepares `CheckpointConfig` for the Megatron-LM commit that makes `cfg.checkpoint` authoritative (NVIDIA/Megatron-LM#8558): Bridge's `finalize()` keeps the Bridge-only checks and ends with `super().validate()`, the single set of checkpoint rules shared by both frameworks.

**Depends on NVIDIA/Megatron-LM#8558.** The `3rdparty/Megatron-LM` pin will be moved to the commit that lands it in the same PR before it leaves draft; against the current pin `super().validate()` does not exist yet, so CI is expected to fail until then.

# Changelog

- `CheckpointConfig.finalize()`: the checks on the Bridge-only fields (`pretrained_checkpoint` exists, `stage_precision_aware_optimizer_state_on_cpu`, `async_save` requires `save` and the persistent worker, `also_save_hf_checkpoint`, `ckpt_step` requires `load`) run first, then `super().validate()`.
- Removed Bridge's own copies of the rules the base class holds: the retention rules (`save_retain_interval` positive, divisible by a positive `save_interval`, not combined with `most_recent_k`) and `load_main_params_from_ckpt` requiring `load_optim=False`. Their messages are unchanged; they are raised as assertions by the base class now, and the retention tests expect that.
- Megatron-LM's `CheckpointConfig` no longer checks anything at construction (its `__post_init__` is gone): the three former construction checks (`async_strategy`, the nvidia-resiliency-ext requirement for an asynchronous `torch_dcp`/`fsdp_dtensor` save, `verify_integrity` with `torch_dist`) reach Bridge through `super().validate()`.
- A save directory without a periodic interval (`save_interval` `None` or `0`) stays valid; Megatron-LM accepts it too since #8558, so the inherited `validate()` accepts everything Bridge accepts today.
- Tests: `test_save_without_a_periodic_interval_is_valid` and `test_shared_checkpoint_rules_are_inherited` added in `tests/unit_tests/training/test_config.py`.
