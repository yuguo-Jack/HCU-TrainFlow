# [sync][training] fix: preserve runtime rerun mode on idle resume

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6588) · state: closed · merged: True

## Original PR description

Resuming an ordinary `torch_dist` checkpoint saved with `rerun_mode="validate_results"` currently replaces an explicitly configured `rerun_mode="report_determinism_stats"` with the saved mode, even when the saved rerun state is `NOT_RUNNING_YET`.

Bridge already requests the idle rerun shard for strict checkpoint loading, but unconditionally restores its runtime state. Use Core's `validate_state_dict()` to decide whether to restore that state, while continuing to request the shard. Active checkpoint reruns retain their saved mode, and a disabled runtime mode remains disabled. This follows the request-versus-restore separation in [NVIDIA/Megatron-LM#7222](https://github.com/NVIDIA/Megatron-LM/pull/7222).

The supported path is `RerunStateMachineConfig` → `initialize.init_rerun_state()` → checkpoint resume in `load_checkpoint()`. The regression test uses the pinned Core's actual rerun serializer and consumer within the existing mocked checkpoint-I/O test, covering idle/active state, all runtime modes, both checkpoint versions, and optimizer-load failure cleanup.
