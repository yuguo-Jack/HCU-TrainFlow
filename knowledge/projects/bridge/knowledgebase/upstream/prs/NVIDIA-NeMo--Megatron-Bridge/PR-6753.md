# docs(model): verify Qwen3.8 27B SFT on H100

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6753) · state: open · merged: False

## Original PR description

# What does this PR do ?

Records the verified H100 SFT item of the Qwen3.8 27B verification card: 100 MedPix SFT steps of the `qwen35_vl_27b_sft_16gpu_h100_bf16_config` library recipe on 2x8 H100 through `scripts/training/train.sh`, with the data, schedule and batch of the card's GB200 SFT item.

# Changelog

- `examples/model_verification_cards/qwen3.8-27b/card.yaml`: new verified `sft.H100` leaf with its `train.sh` command, metrics, expected result and a leaf `bridge_commit` for the commit the run used (`58382ddf9`, with its pinned Megatron-Core, on a NeMo 26.10 release-candidate container). `verification_index` now lists H100 training (`sft` verified, the other five items unverified), and the summary names the new leaf.
- The command declares sequence parallelism and one-layer full-uniform activation recompute. The recipe's own layout (no sequence parallelism, no recompute) does not fit on 80 GB H100: with sequence parallelism but without recompute, the same workload runs out of memory in its first iteration. I'll propose making these settings the recipe's defaults in a separate PR.
- The run is not deterministic, because deterministic mode requires the torch reference Gated DeltaNet backend. The processor is pinned to the card's revision through `dataset.hf_processor_kwargs`. Checkpoint saves are off, since export is not in scope for this leaf.
- Regenerated catalog docs: `docs/_static/model-verification/catalog-v1.json`, the Qwen3.8 27B model guide and its Fern mirror, and both model READMEs.
- `tests/unit_tests/skills/create_model_verification_card/test_validate_card.py`: adds the leaf's throughput inputs to `TRAINING_THROUGHPUT_INPUTS`.

# Validation

- The run: 100 steps on 16 H100 GPUs, LM loss 2.120037 to 1.428843 (the GB200 item: 2.116404 to 1.429567) with every step finite and none skipped; over the last 10 steps, 6,213 ms per step and 221.4 model TFLOP/s per GPU; peak memory 49.6 / 51.2 GiB allocated / reserved.
- Layout check on the same 16 GPUs (15 steps per layout at TP4/PP4, MBS 4, GBS 32): sequence parallelism with full recompute took 6,210 ms per step with 54.4 GB peak allocated; adding virtual pipeline 2 took 6,308 ms; full recompute without sequence parallelism took 6,328 ms with 62.5 GB reserved; sequence parallelism without recompute ran out of memory in iteration 1.
- `skills/create-model-verification-card/scripts/validate_card.py`: valid.
- `scripts/docs/generate_model_verification_catalog.py --check`: the generated docs are current.
- `tests/unit_tests/doc_consistency/test_model_verification_catalog.py` and `tests/unit_tests/skills/create_model_verification_card/test_validate_card.py`: 66 passed.
- pre-commit on all files: passed.
