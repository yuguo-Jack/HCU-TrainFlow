# fix(model): default MODEL_CONFIG_CLASS to None and opt in per family

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6305) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Makes the builder-backed config path opt-in per model family. Builder calls for families that have not migrated now raise instead of returning a wrong config, and the provider path no longer tells those families to switch.

Every bridge used to inherit MODEL_CONFIG_CLASS = BridgeGPTModelConfig, but only the migrated families map their HF config into it. For the rest, get_model_config() returned generic defaults and to_megatron_provider() warned users toward it.

# Changelog

- MegatronModelBridge.MODEL_CONFIG_CLASS now defaults to None. Migrated families opt in explicitly: LlamaBridge and Qwen3Bridge set BridgeGPTModelConfig; MuseGlimmerBridge already sets MuseGlimmerModelConfig. Subclasses of a migrated bridge inherit the opt-in.
- hf_config_to_model_config() rejects unmigrated families through the existing MODEL_CONFIG_CLASS is None branch. The error names the bridge and points to AutoBridge.to_megatron_provider().
- provider_bridge() emits the deprecation FutureWarning only when MODEL_CONFIG_CLASS is set. The provider path itself is unchanged.
- Removed the _has_model_config_mapping() hook-override guard from the first revision.
- Removed the explicit MODEL_CONFIG_CLASS = None on GLM5Bridge and BagelBridge, which is now the default.
- Updated the class comment, docstrings and docs/bridge-guide.md to describe the opt-in default.
- Tests: test_bridge_can_explicitly_disable_model_config is parametrized over every registered bridge (64). Unmigrated bridges must reject the builder path and have no config mapping; opted-in bridges must provide one; a subclass that sets None is rejected. Added an inheritance test and a provider test on Qwen2 (unmigrated) that asserts no FutureWarning. The Qwen3-based tests are gone since Qwen3 is migrated.

# Testing
