# fix(data): allow spawn DataLoader workers to avoid cross-node NCCL hang after fork

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6620) · state: open · merged: False

## Original PR description

# What does this PR do ?

Multi-node training can hang on the first cross-node NCCL collective once the DataLoader forks its
persistent workers; #5984 (release inherited GPU descriptors in workers) does not prevent it, while starting the
workers with `spawn` does. Spawn is currently impossible for `DirectSFTDataset` because its collate is a closure.
This PR makes that collate picklable and adds an opt-in `DataloaderConfig.multiprocessing_context`
(default `None`, behaviour unchanged).

## Problem

Data loader workers are always started with PyTorch's default start method (`fork` on Linux), and
`DirectSFTDataset` binds its collate as a local closure (`_bound_collate`), so even a user-level switch to `spawn`
fails with `AttributeError: Can't get local object 'DirectSFTDataset.__init__.<locals>._bound_collate'`.

We hit a hard hang that only `spawn` avoids: on a 4-node A800 cluster (kernel 5.4.250, driver 535 + CUDA 13 compat,
NCCL 2.30, IB/RoCE), the first cross-node NCCL collective after the DataLoader forks its persistent workers never
completes (GPUs at 100% util / ~100 W, no progress until the NCCL timeout). Minimal reproducer (no Megatron): one
cross-node all-to-all to register IB memory, `fork` a child that stays alive, then all-to-all again:

| child | result |
|---|---|
| fork, child stays alive | hangs |
| fork, child stays alive, parent writes no heap | hangs |
| fork, child exits before the collective | OK |
| fork, child closes inherited `/dev/nvidia*` fds at start (= #5984 worker init), stays alive | hangs |
| spawn | OK |

`RDMAV_FORK_SAFE=1`, disabling GDR, `NCCL_CUMEM_ENABLE`, `NCCL_RUNTIME_CONNECT=0`, `CUDA_MODULE_LOADING=EAGER`
did not help. #5984 (close inherited `/dev/nvidia*` descriptors in workers) does **not** avoid this hang either:
on 2 nodes x 8 A800 the `fork_closefd` mode hung exactly like plain `fork` (no post-fork all-to-all completed within
240 s), while `spawn` completed all iterations immediately. Closing the fd
does not undo the mappings the child inherited, which fits the fork/COW-of-pinned-pages explanation on pre-5.9 kernels.

# Changelog

1. `DataloaderConfig.multiprocessing_context` (default `None` = unchanged behaviour), plumbed through
   `build_train_valid_test_data_loaders` → `build_pretraining_data_loader` → `DataLoader`, mirroring `prefetch_factor`
   (only passed when `num_workers > 0`, since PyTorch rejects it otherwise).
2. `DirectSFTDataset.collate_fn` becomes `functools.partial(_apply_collate, collate_impl, processor, collate_kwargs)`
   with a module-level `_apply_collate` — same call as the closure (`_processor` is only assigned in `__init__`), but
   picklable. Collate implementations returned by `select_direct_hf_sft_collate` / the model-collate registry are
   module-level functions or partials of them, so the whole thing pickles.

# Tests

- `test_direct_sft_collate_fn_is_picklable_for_spawned_workers`: pickle round-trip gives identical output.
- `test_multiprocessing_context_applies_only_to_worker_loaders`: context reaches worker-backed loaders, ignored at
  `num_workers=0`.

Validated outside the repo test env (the image's Megatron-Core lacks `mark_keep_in_fp32`, so the package does not
import there): the two changed modules loaded standalone; `spawn` / `forkserver` / default loaders each fetch batches
from a worker process with a DirectSFTDataset collate; the original closure fails under `spawn` as above. The same
partial-based collate applied on top of Bridge 0.6.1, ran a 60-step, 32-GPU distillation job with spawn workers.

The two new unit tests have not been run locally in an environment matching `main`'s dependencies; relying on CI for them.

# Additional Information

- Related to #5984 (that change does not prevent this hang; see table above).
- Compatible with the lazy direct-HF SFT rows from #6590: the lazy dataset's adapter and `partial(normalize_sft_example, ...)` transform are picklable.

Standalone reproducer (no Megatron; one rank per node is enough). With 2 nodes x 1 A800, `fork` and `fork_closefd` hang on the post-fork `all_to_all` until the NCCL timeout, `spawn` returns in ~2 s.

```
torchrun --nnodes 2 --nproc_per_node 1 --node_rank <r> --master_addr <a> --master_port 29500 \
    fork_nccl_repro_minimal.py --mode fork   # fork | fork_closefd | spawn
```

```python
"""Minimal standalone repro: a forked child that stays alive hangs the next cross-node NCCL collective.

Run on 2+ nodes (one rank per node is enough), e.g.
    torchrun --nnodes 2 --nproc_per_node 1 --node_rank <r> --master_addr <a> --master_port 29500 \
        fork_nccl_repro_minimal.py --mode fork          # fork | fork_closefd | spawn
"""

import argparse
import datetime
import multiprocessing as mp
import os
import time

import torch
import torch.distributed as dist


def close_nvidia_fds_then_sleep(seconds):
    # What Megatron-Bridge #5984 does in DataLoader workers: release inherited /dev/nvidia* descriptors.
    for fd in os.listdir("/proc/self/fd"):
        try:
            if os.readlink(f"/proc/self/fd/{fd}").startswith("/dev/nvidia"):
                os.close(int(fd))
        except OSError:
            pass
    time.sleep(seconds)


if __name__ == "__main__":
    ap = argparse.ArgumentParser()
    ap.add_argument("--mode", choices=["fork", "fork_closefd", "spawn"], required=True)
    ap.add_argument("--timeout_s", type=int, default=120)
    args = ap.parse_args()

    torch.cuda.set_device(int(os.environ["LOCAL_RANK"]))
    dist.init_process_group("nccl", timeout=datetime.timedelta(seconds=args.timeout_s))
    x = torch.ones(1 << 20, device="cuda")
    dist.all_to_all_single(torch.empty_like(x), x)  # connect and register IB memory
    torch.cuda.synchronize()

    # A persistent child, like a DataLoader worker with persistent_workers=True.
    ctx = mp.get_context("spawn" if args.mode == "spawn" else "fork")
    target = close_nvidia_fds_then_sleep if args.mode == "fork_closefd" else time.sleep
    child = ctx.Process(target=target, args=(600,), daemon=True)
    child.start()
    junk = [bytearray(64 << 20) for _ in range(8)]  # parent keeps writing its heap, as training does

    t0 = time.time()
    dist.all_to_all_single(torch.empty_like(x), x)  # hangs with fork / fork_closefd, returns with spawn
    torch.cuda.synchronize()
    if dist.get_rank() == 0:
        print(f"[{args.mode}] post-fork all_to_all OK in {time.time() - t0:.2f}s", flush=True)
    child.terminate()
    dist.destroy_process_group()
```
