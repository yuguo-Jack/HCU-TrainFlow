# docs(model): re-verify Nemotron 3.5 Lightning training at a recipe-containing revision

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6425) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes two problems in the Nemotron 3.5 Lightning verification card's training items.

1. The training leaves were pinned to bridge_commits that predate the recipe rename in #5303, so the recipes named in the published commands did not exist at the recorded revision. The card's default bridge_commit moves to bcd2d134c (#5303). Conversion and inference stay at 619a2df1d with explicit pins, and the per-leaf training pins are dropped. Every verified training leaf is re-run in nvcr.io/nvidia/nemo:26.08 at bcd2d134c (2x8 H100, 2x4 GB200), and its metrics and expected result are replaced with the measured values.
2. The published two-node H100 `sft_long_context` command runs out of memory in iteration 2 on H100 80GB. The leaf now runs on four eight-GPU nodes. Recipe GBS/MBS, sequence length, TP/CP/EP, recompute and precision are unchanged. It was re-verified on 4x8 H100 at bcd2d134c (100/100 steps, LM loss 0.4268879 -> 0.2653436), and the audited token-slot fixture is updated to 32 GPUs.

Catalog, nightly MDX and model guide are regenerated from the card.

# Changelog

- `examples/model_verification_cards/nemotron-3.5-lightning/card.yaml`: default `bridge_commit` -> `bcd2d134c`; QA-measured metrics, `last_verified` and expected results for every training leaf on H100 and GB200; H100 `sft_long_context` on 4 nodes; summary updated.
- `docs/_static/model-verification/catalog-v1.json`, `docs/models/nemotron/nemotron3.5-lightning.md`, `docs/fern/.../nemotron3.5-lightning.mdx`: regenerated.
- `tests/unit_tests/doc_consistency/test_verification_card_recipe_revisions.py` (new): each verified Lightning leaf's recipe is defined under `src/` at its effective bridge_commit, and its `last_verified` is no earlier than that commit's date.
- `tests/unit_tests/skills/create_model_verification_card/test_validate_card.py`: H100 `sft_long_context` audited GPU count 16 -> 32.

# Additional Information

- **QA runs:** `nvcr.io/nvidia/nemo:26.08`, Bridge `bcd2d134c`, MCore `6513e3e2`; H100 on EOS (jobs 6223620-6223626, 6223752, 6239236), GB200 on 2x4 nodes (jobs 3289307-3289313, 3289316, 3289411, 3289412, 3290217, 3318807). All leaves 0 skipped / 0 NaN, checkpoints complete.
- **Metrics:** card skill definitions, parsed from complete optimizer-step rows; last-10-step means.
- **This new test skips in CI.** It needs the recorded commits in git history, and CI's depth-1 checkout does not have them; it skips only in a shallow checkout, and a missing commit fails in a full clone. Run it locally with full history. It fails on the current main card and passes here.
- `peak_*_memory_gib` values are as reported by Megatron, which uses GB (1e9 bytes) despite the field name; left unchanged here.
- **Checks:** `validate_card.py` valid; `generate_model_verification_catalog.py --check` clean; `tests/unit_tests/doc_consistency` + `test_validate_card.py` pass; pre-commit clean.

- **NVBug:** 6626551, 6900116.
