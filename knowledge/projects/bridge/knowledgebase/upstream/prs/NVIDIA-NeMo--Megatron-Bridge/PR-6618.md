## Original PR description

# What does this PR do ?

Fixes the data tutorials' launcher commands. They still pass `run_recipe.py` flags that no longer exist, so the commands fail with an argument error when copied as written.

# Changelog

- `tutorials/data/text-only-sft/README.md`: `--dataset llm-finetune-preloaded` → `--dataset local-jsonl` (same `dataset_root` and `input`/`output` columns).
- `tutorials/data/hf-multimodal/README.md`: local JSON example `--dataset vlm-hf` → `--dataset local-vlm`; MedPix example `--dataset vlm-hf` → `--dataset medpix`; `--peft_scheme lora` → `--mode lora` in both commands.
- Same file: the explanation and the "Migrate from `vlm-preloaded`" section now name the current selectors (`local-vlm`, named HF presets, `energon`).
- `CONTRIBUTING.md`: fix the code-style link (`skills/code-style/` was renamed to `skills/linting-and-formatting/`).
- `tests/unit_tests/tutorials/`: update `test_multimodal_tutorials_document_runnable_qwen_paths` to require the current selectors (`local-vlm`, `medpix`, `--mode lora`) instead of the removed `--dataset vlm-hf`, and add `test_text_only_sft_tutorial_uses_current_dataset_selector` to check that the text-only SFT tutorial uses `--dataset local-jsonl`.

**[P2] Set a batch size that fits the generated tutorial data**

**Failure:** Prepare the tutorial data, supply a valid pretrained checkpoint, and run this command. The selector now passes argument parsing, but the [preparation script creates only four training rows](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/62e50f4af56880e11a75e4b174031dbf425077b3/tutorials/data/text-only-sft/prepare_example_data.py#L22-L35), whereas the [selected recipe sets `train.global_batch_size=8`](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/62e50f4af56880e11a75e4b174031dbf425077b3/src/megatron/bridge/recipes/llama/h100/llama3.py#L1359-L1364). The local preset builds a finite dataset without oversampling, so the [loader guard](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/62e50f4af56880e11a75e4b174031dbf425077b3/src/megatron/bridge/data/loaders.py#L359-L369) raises `Not enough train samples for a single global batch` (4 < 8) before iteration 1 instead of starting SFT.

**Correction:** Add the following override to this example, restoring `len(train_ds) >= train.global_batch_size`. Keep shared recipe/preset defaults unchanged for larger datasets.

```suggestion
    --dataset local-jsonl \
    train.global_batch_size=4 \
```

**Preservation:** Retain `local-jsonl`, the `input`/`output` preprocessing, sequence length 4096, micro-batch size 1, and the generated validation/test files.

**Acceptance — proposed, not executed:** Extend `test_text_only_sft_tutorial_uses_current_dataset_selector` to check that the documented effective global batch is 4 for the four generated training rows, retaining both current/removed-selector assertions. With DP=1, the resulting batch sampler should yield one four-sample training batch; the two-row validation and one-row test splits should remain enabled and build successfully. With a valid checkpoint, the corrected launch should reach iteration 1 with finite loss. Verify the suggestion before adopting it.
