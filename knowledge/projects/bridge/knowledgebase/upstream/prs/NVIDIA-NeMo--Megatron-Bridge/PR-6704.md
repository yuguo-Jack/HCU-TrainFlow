# perf(data): bound index workers by input count

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6704) · state: open · merged: False

## Original PR description

# What does this PR do ?

The data functional job repeatedly starts 96 index workers for a single input file, spending around six seconds on a tiny index build. Those idle workers consume process and memory resources without increasing file-level parallelism.

Bound the worker count by the input count: one file starts one worker, and empty input starts none. The implementation is two added production-code lines, a docstring update, and a focused regression test.

**Before/after evidence**

| Metric | Before | After | Evidence |
| --- | --- | --- | --- |
| Child processes for one item with `workers=96` | 96 | 1 | The regression test fails on main with `assert 96 == 1` |
| `safe_map` time for one item with `workers=96` | 1,613 ms | 44 ms | Best of three calls on one machine |
| `L0_Launch_data.sh` time | 204 seconds | 165 seconds | One complete run each on B200 |
| `L0_Launch_data.sh` time without `test_chat_template.py` on `270264f20` | 172, 192, and 197 seconds | 137, 147, and 137 seconds | Three runs each on B200, with the order alternated after the first pair |

The validation machine started 80 workers before this change (`os.cpu_count() // 2`), and CI logs show 96. Other work used other GPUs and CPU cores during some of these runs, so these times are approximate. CI time was not measured.

# Changelog

- Cap `safe_map` workers at the number of tasks, including zero for empty input.
- Report the effective worker count when building memmap indices.
- Document that `workers` is now an upper limit.
- Add a focused resource-bound regression that also verifies mapping results for a single item and empty input.
- Keep work in child processes and preserve result ordering, exception handling, and crash isolation.

See the [CI section](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/main/CONTRIBUTING.md#-running-github-ci) in the Contributing doc for how to trigger the CI. A Nvidia developer will need to approve and trigger the CI for external contributors.

Validation ran on NVIDIA B200 GPUs on x86-64, with this PR merged onto main at `00e3730dd`, which includes Megatron-Core `ba495158`. Each launcher used two GPUs, 40 pinned CPU cores to match the CI `--cpus=40` limit, `HF_HUB_OFFLINE=1`, and an environment built from `uv.lock`. Only the GPU indices in the launchers changed. This environment is not the CI container image.

The unit test module ran with the normal project imports and conftest. The functional `test_utils.py` module covers results, ordering, exceptions, empty input, and an abrupt worker exit, and it behaved the same on main and on this PR. `L0_Launch_data.sh` completed on main and on this PR with the same tests, and the `using 80 workers` log lines are gone. `test_chat_template.py` ran with a public copy of the Llama 3.1 tokenizer at the CI path, because the gated original was not available. The test sets its own chat template. The launcher also completed with #6702, #6703, and #6705 merged.

Not validated: H100 and GB200 runners, and the CI container image. Upstream CI remains pending.
