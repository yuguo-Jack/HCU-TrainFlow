# feat(data): add prefetch_factor to the dataloader config

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6511) · state: closed · merged: True

## Original PR description

DataloaderConfig exposes num_workers, pin_memory and persistent_workers but not the DataLoader's prefetch_factor, so recipes that need workers to buffer more than PyTorch's default of two batches each had to patch torch.utils.data.DataLoader. With a full-iteration CUDA graph, every microbatch of a step must be loaded before the graph replays, so the workers need to hold a whole step's worth of samples.

Add prefetch_factor (default None, which keeps PyTorch's default) and pass it through build_pretraining_data_loader to the train, validation and test loaders. It is only passed when num_workers > 0, since PyTorch rejects it otherwise. The benchmark runner keeps it when it swaps in the mock dataset, as it does the other loader fields.
