# fix(ckpt): cache loaded metadata so the first save after resume reuses it

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6653) · state: open · merged: False

## Original PR description

# What does this PR do ?

Pass `cache_metadata` to the resume-path load strategy so the first save after resume reuses the loaded checkpoint metadata.

```python
# src/megatron/bridge/training/checkpointing.py, _load_global_dist_base_checkpoint
- load_strategy = TorchDistLoadShardedStrategy()
+ load_strategy = TorchDistLoadShardedStrategy(cache_metadata=ckpt_cfg.ckpt_assume_constant_structure)
```

## Why

`save_checkpoint` already reuses metadata from the load strategy when it is available:

```python
# save_checkpoint
if ckpt_cfg.ckpt_assume_constant_structure and ckpt_cfg.ckpt_format == "torch_dist":
    cached_global_metadata = getattr(checkpointing_context["load_strategy"], "cached_global_metadata", None)
    if cached_global_metadata is not None:
        save_strategy.cached_global_metadata = cached_global_metadata
    else:
        logger.debug("Failed to plug in the read metadata from the load strategy...")
```

Megatron-Core fills `cached_global_metadata` only when `cache_metadata=True`:

```python
# megatron/core/dist_checkpointing/strategies/torch.py, TorchDistLoadShardedStrategy.load
if self.cache_metadata:
    self.cached_global_metadata = fsr.read_metadata()
```

The load side used the default `cache_metadata=False`, so the metadata was not kept. The first save after a resume then ran the full plan gather, even with `ckpt_assume_constant_structure=True`.

Megatron-LM passes the flag at the same call site:

```python
# megatron/training/checkpointing.py
load_strategy = TorchDistLoadShardedStrategy(cache_metadata=args.ckpt_assume_constant_structure, ...)
```

## How to reproduce

1. Train with `ckpt_format="torch_dist"` and `ckpt_assume_constant_structure=True`. Save once.
2. Restart and resume from that checkpoint with debug logging on.
3. Watch the first save:

```text
# main
DEBUG Failed to plug in the read metadata from the load strategy...

# this PR
DEBUG Plugging in the read metadata from the load strategy...
```

Two unit tests cover the same path on one CPU rank:

```python
# real torch_dist save, then load through _load_global_dist_base_checkpoint
assert "weight" in checkpointing_context["load_strategy"].cached_global_metadata.state_dict_metadata

# save_checkpoint with that context
assert checkpointing_context["save_strategy"].cached_global_metadata is loaded_metadata
```

# Changelog

- `_load_global_dist_base_checkpoint`: pass `cache_metadata=ckpt_cfg.ckpt_assume_constant_structure`.
- `save_checkpoint`: fall back to `load_strategy.base_strategy.cached_global_metadata`. `FullyParallelLoadStrategyWrapper` does not forward it on a single-rank DP x CP group.
- Add `TestLoadSaveCachedMetadataHandoff`: flag propagation, real load keeps metadata, first save picks it up.
- Update `test_load_global_dist_base_checkpoint_with_path_override` for the new argument.
