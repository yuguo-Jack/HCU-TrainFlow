# docs(model): match DeepSeek V4 Flash GB200 pretrain recipe to its pinned commit

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6585) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes the DeepSeek V4 Flash card's `pretrain.GB200` and `checkpoint_resume.GB200` commands failing with `Recipe ... not found` at their pinned `bridge_commit`, by restoring the recipe name that commit defines.

# Changelog

- `examples/model_verification_cards/deepseek-v4-flash/card.yaml`: `--recipe` in both items `..._64gpu_gb200_fp8mx_library_config` -> `..._128gpu_gb200_fp8mx_library_config`.
- `docs/_static/model-verification/catalog-v1.json`, `docs/models/deepseek/deepseek-v4.md`, `docs/fern/versions/nightly/pages/models/deepseek/deepseek-v4.mdx`: regenerated.

# Additional Information

- **Root cause:** both items were verified on 2026-08-27 (098656c42, c0adc7079) with the `128gpu` name at `dff6445009eb`; c6d73b7a3 later renamed the recipe (and changed its config) and updated the card command but not the pin.
- **Regression?** No. The card on main has never published a command that resolves at its own pin.
- **Verification:** GB200 container at `dff6445009eb` + pinned MCore dev: `load_recipe` raises AttributeError for `64gpu` and builds the `128gpu` config (TP1/PP4/VPP4/EP16) with the card overrides. The full 64-GPU run was not repeated.
- **Not included:** re-verifying at a main commit (moving to `64gpu` with a new pin). That needs a fresh 64-GB200 run. No unit test: the pin is not in main's history, so a revision test would fail in a full clone.
- **NVBug:** 6964574.
