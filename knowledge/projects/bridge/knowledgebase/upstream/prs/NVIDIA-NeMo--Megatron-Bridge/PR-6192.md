# [sync][training] fix: honor checkpoint integrity verification

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6192) · state: closed · merged: True

## Original PR description

Enabling `checkpoint.verify_integrity=True` currently leaves native checkpoint hashing and verification disabled. Bridge inherits the public setting from MCore, but its `torch_dist` save and load calls omit the keyword, so MCore uses its `False` default. A readable checkpoint with modified metadata is therefore accepted despite the requested integrity check.

This forwards the existing setting to both MCore calls and adds save/load regression cases for `True` and `False`. The default behavior and public API are unchanged. MCore implemented the capability and its training glue in [#4305](https://github.com/NVIDIA/Megatron-LM/pull/4305); Bridge owns these separate callers.

Validation bases:

- Bridge: `bb04cd47805d1c56c70ee1f15aa10336a1249b8c`
- Pinned MCore: `c343bb6d337eae14e195835262854361680bcab8`
- Upstream MCore main observed: `6a3660905a2736b5670baed1ca5954372937918b`

With only the regression tests applied to the unmodified Bridge base, this command exited 1 with six missing-`verify_integrity` failures and four passing controls. The identical command after the fix exited 0: **10 passed**.

```bash
uv run python -m pytest tests/unit_tests/training/test_checkpointing.py::TestSaveCheckpoint::test_save_checkpoint_global tests/unit_tests/training/test_checkpointing.py::TestCheckpointPathOverride -q --tb=short
```

A separate one-GPU, one-rank NCCL checkpoint check passed a healthy tensor round trip, then appended a byte to otherwise readable checkpoint metadata. Before the fix, Bridge accepted it despite `verify_integrity=True` (expected regression failure, exit 1). After the fix, Bridge raised the expected checkpoint integrity exception (check passed, exit 0). This does not claim multi-rank error-broadcast coverage.

`uv run pre-commit run --all-files` passed, with no unstaged hook changes. Independent read-only review found no blocking code findings. All-state duplicate searches found no active Bridge fix for this native checkpoint setting. Existing configuration documentation remains applicable; no new option or dependency is introduced.
