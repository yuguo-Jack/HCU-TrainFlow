# fix(conversion): keep gathered adapter weights on rank 0 only in save_hf_adapter

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6596) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Stops `AutoBridge.save_hf_adapter` from materialising the complete adapter on every rank. The export generator is collective (gathering the TP/PP/EP shards), so every rank must drive it, but only rank 0 converts and writes; keeping the gathered host copies on all ranks made the host memory of an export `ranks_per_node x adapter_size`. With 8 ranks per node, a per-expert MoE adapter of 150 GB (Beam-1.0-501B-A23B, rank 256) needs 1.2 TB of host RAM and the export is OOM-killed.

# Changelog

- `save_hf_adapter` iterates the export generator on every rank, counts the exported tensors, and appends `HFWeightTuple(name, weight.clone())` on rank 0 only; the other ranks drop each tensor as soon as it is produced.
- The empty-export `RuntimeError` is raised from the count, so it still fires on every rank.
- `convert_adapter_weights_to_peft_state` and `infer_rank_pattern_from_adapter_weights` run on rank 0 only, right before writing; the gathered list is released after conversion.
- The written `adapter_config.json` and `adapter_model.safetensors` are unchanged.
- Tests (`tests/unit_tests/models/test_adapter_export.py::TestSaveHfAdapter`): a non-zero rank consumes the whole generator, does not convert, does not write and still hits both barriers (fails on `main`); rank 0 of a process group writes the same files as the single-process path; an empty export raises on every rank.
