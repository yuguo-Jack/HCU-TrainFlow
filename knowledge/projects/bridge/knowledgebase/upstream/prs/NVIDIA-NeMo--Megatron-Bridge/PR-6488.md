# fix(nemotron-omni): recover video embedder in image-SFT exports

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6488) · state: open · merged: False

## Original PR description

## What does this PR do?

This PR prevents an HF export of Nemotron Omni model's issue. That is when running finetuning image-embedder only (no video-embedder), the export silently drops the pretrained video-embedder weights. Hence, the exported checkpoint only has randomly inited video-embedder weights.

**Cause:**
The original model has separate image and video embedders. The CORD-v2 image-only fine-tuning recipes set `temporal_patch_dim=1`. With this setting, RADIO does not construct the video-embedder, so its pretrained weight has nowhere to load and is absent from the saved fine-tuned checkpoint. Image and text inputs do not use that layer, so training can proceed without revealing the problem.

On export, Bridge previously omitted the missing `video_embedder.weight` but retained the reference HF configuration that expects it. Hence, HF reload initializes the missing weight randomly. The resulting model therefore has a randomly inited video-embedder weight.

**Fix:**
The fix handles this during export:
- If the Megatron export already contains a video weight, then just use it.
- Otherwise (as in the image-embedder only finetuning), recover the pretrained video weight from the original reference HF checkpoint.
- If the configuration requires that weight and recovery is impossible, fail with an explicit error, even with `--not-strict`.

This also repairs exports of existing image-SFT checkpoints, provided the original `--hf-model` and `--hf-revision` are supplied. It prevents random initialization of the video embedder; other shared weights changed during image fine-tuning can still affect video quality.

## Changelog

- Recover an absent video embedder weight from the reference HF checkpoint while preserving any video weight already emitted from Megatron.
- Fail explicitly when a required video weight cannot be recovered, including with `--not-strict`.
- Respect pipeline-stage ownership, export dtype/device, and source-only weight provenance.
- Document the image recipes' inherited video settings and the requirement to export against the original HF checkpoint and revision.
- Add regression tests for recovery, trained-weight precedence, missing/unreadable references, and export options.

## Validation

- The regression test failed before the fix: permissive export wrote a checkpoint without `video_embedder.weight`.
- A reduced real-RADIO run on H100 reproduced the missing parameter at temporal size 1, its omission after checkpoint save, and different synthesized values when reloading at temporal size 2.
- With the fix, the reduced export recovered the full `(1280, 1536)` source video tensor exactly; source standard deviation was `0.02528413`.
- `uv run --no-project python -m pytest tests/unit_tests/models/nemotron_omni/test_nemotron_omni_conversion.py -q`: **75 passed** (after removing redundant test combinations).
- Ruff checks passed.
- `uv run pre-commit run --all-files`: passed.

The full 30B CORD-v2 SFT/card workflow and full HF reload have not been rerun. Validation used Transformers 5.17.0 with newer nightly Bridge/MCore revisions than the original report. This change repairs export; it does not add the unused video parameter to image-SFT checkpoints or guarantee unchanged video quality after shared weights are fine-tuned.

**Blocking: recover video only in the route that owns its mapping.**

`video_exported` describes this invocation's stream, not the complete model. [MIMO export](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b3caafd2a18549bbc33baccca72a55ceb2635acf/src/megatron/bridge/models/megatron_mimo/conversion/orchestrator.py#L892-L931) invokes this override separately for each route with a filtered registry. The [Omni route order](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b3caafd2a18549bbc33baccca72a55ceb2635acf/src/megatron/bridge/models/nemotron_omni/nemotron_omni_bridge.py#L702-L713) is language, images, projector. Consequently, the language invocation has `video_exported=False` and emits the reference video tensor before the images invocation emits its trained tensor. The writer's [first-occurrence deduplication](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b3caafd2a18549bbc33baccca72a55ceb2635acf/src/megatron/bridge/models/megatron_mimo/conversion/orchestrator.py#L1075-L1089) then discards the trained value. For example, reference video values of 1 and trained values of 3 produce an exported video tensor of 1. A successful export must retain 3.

**Correction:** gate recovery and its missing-weight validation on this invocation's registry containing the video mapping. [Route-local registries](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b3caafd2a18549bbc33baccca72a55ceb2635acf/src/megatron/bridge/models/megatron_mimo/conversion/orchestrator.py#L285-L298) preserve HF names, and the ordinary image-SFT registry retains the video mapping even when RADIO has no corresponding parameter. Suggested replacement for line 390, unexecuted:

```python
video_in_registry = any(
    mapping.hf_param == self._HF_VIDEO_EMBEDDER_KEY
    for mapping in self.mapping_registry().mappings
)
recover_video = video_in_registry and not video_exported and not video_owned_elsewhere
```

This keeps recovery in the images route, avoids premature validation in language/projector routes, and leaves the existing immutable-buffer passthrough unchanged. Do not instead change global deduplication to last-wins: that would let the projector route's later fallback overwrite the trained tensor again.

**Acceptance — proposed regressions:** exercise the rank-0 MIMO stream with language followed by images and projector, a reference `(4, 6)` video tensor filled with 1, and a mapped image-route tensor filled with 3. Assert exactly one video key with values 3. Repeat with no image-route video parameter: assert exactly one recovered tensor equal to 1. With neither source available and video required, assert failure in the images route, not the language route. Retain the existing direct-export precedence/provenance assertions, both image-SFT recovery cases, dtype/device assertions, and remote-PP-owner suppression in the [conversion tests](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b3caafd2a18549bbc33baccca72a55ceb2635acf/tests/unit_tests/models/nemotron_omni/test_nemotron_omni_conversion.py#L785-L881).

**Blocking: use the Super-VL schema when deciding whether video is required.**

This streamer is also inherited by `Nemotron35SuperVLBridge`, whose [provider contract](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b3caafd2a18549bbc33baccca72a55ceb2635acf/src/megatron/bridge/models/nemotron_omni/nemotron_omni_bridge.py#L555-L575) determines video capability from the **top-level** `video_temporal_patch_size > 1`, not `vision_config.separate_video_embedder`. The [existing Super-VL fixture](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b3caafd2a18549bbc33baccca72a55ceb2635acf/tests/unit_tests/models/nemotron_omni/test_nemotron_omni_conversion.py#L161-L177) explicitly removes the nested flag and sets the top-level size to 2.

Static trace: with that schema, no Megatron video tensor, and an accessible reference checkpoint containing only unrelated weights, `video_required` becomes false. The stream finishes without video instead of raising; permissive writing can therefore still create an incomplete checkpoint. Expected behavior is the same explicit failure provided for Nano Omni when its configuration requires video and recovery is impossible.

**Correction:** make the requirement predicate model-specific. Replace lines 392–398 with `video_required = recover_video and self._hf_requires_video_embedder(config)`, and add these methods to the respective classes (suggested, unexecuted):

```python
# NemotronOmniBridge
@staticmethod
def _hf_requires_video_embedder(config) -> bool:
    vision = getattr(config, "vision_config", None)
    separate = (
        vision.get("separate_video_embedder", False)
        if isinstance(vision, dict)
        else getattr(vision, "separate_video_embedder", False)
    )
    return separate is True

# Nemotron35SuperVLBridge
@staticmethod
def _hf_requires_video_embedder(config) -> bool:
    return int(getattr(config, "video_temporal_patch_size", 1) or 1) > 1
```

The invariant is agreement with each bridge's provider contract. Do not simply OR both schemas together: Super-VL's provider overrides the nested setting, so a top-level temporal size of 1 must not become video-required because of a stale nested flag. Recovery when a reference tensor exists should remain unchanged, as should trained-tensor precedence and PP/route ownership guards.

**Acceptance — proposed regressions:** parameterize Super-VL top-level size 2 with no nested flag over missing path, missing key, and unreadable reference; with no mapped video, each must raise a `ValueError` mentioning `video_embedder.weight`, including through permissive writing. A size-2 source containing the key must recover it exactly. Top-level size 1 with no video source must not acquire the required-video error, even with a nested flag set to true. Retain Nano Omni's nested dict/object true cases, nested false behavior, and the existing trained-weight precedence assertions in the [conversion tests](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/b3caafd2a18549bbc33baccca72a55ceb2635acf/tests/unit_tests/models/nemotron_omni/test_nemotron_omni_conversion.py#L785-L881).
