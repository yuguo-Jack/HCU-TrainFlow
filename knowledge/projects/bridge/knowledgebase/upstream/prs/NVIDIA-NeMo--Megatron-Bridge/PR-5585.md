# fix(ckpt): reject unowned export metadata at every PP size

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/5585) · state: closed · merged: True

## Original PR description

## What does this PR do?

Reject missing export metadata with the mapped parameter name at every pipeline-parallel size. An invalid all-ranks-unowned AutoMapping task now raises instead of silently returning an empty export at PP1; PP2 retains its error and identifies the parameter. Both normal and quantized export entry points use the same check.

The original NemotronH failure no longer reproduces on main after #5262 and #6343. This revision replaces the original `allow_missing` proposal, which would have hidden an invalid PP2 task. Mapping validation is not a universal ownership guarantee: cached parameter names and caller-supplied tasks still make a clear error useful.

## Changelog

- Enforce the existing object-broadcast ownership requirement at PP1 and include the parameter name in the PP2 error.
- Remove the empty-export guards and misleading dense-layer/MoE comment.
- Test missing ownership, valid remote ownership and repeated export, both export entry points, valid `False`/`0` metadata, and missing expert-count metadata.

## Validation

- 454 focused and adjacent unit tests passed; two MXFP8 tests require newer GPU hardware and were skipped.
- Current-main and candidate NemotronH PP1/PP2 round trips and separate cold exports: complete 29-key output including embedding, correct shapes/dtypes, finite tensors, exact round-trip values, rank agreement, repeat equality, strict HF reload and identical finite/nonconstant HF logits.
- Real distributed controls: valid parameters arrive from either owning rank; deliberately invalid all-unowned tasks fail with the parameter name at PP1 and PP2 in the candidate. The original proposal returned empty output for the invalid PP2 case.
- Full repository pre-commit checks and diff checks pass. Strict local typing retains the same existing errors as main; it is not claimed clean.

The semantic fixture is a deterministic tiny random HF NemotronH checkpoint, not pretrained full-model weights. The forward comparison is HF before/after conversion, not Megatron forward parity. Quantized-entry ownership checks do not qualify quantized payload numerics.

Related: NVBug6612509.

LGTM - clean, well-tested fix.

The asymmetric `allow_missing` usage in `megatron_to_hf` (owner passes it implicitly False, non-owners pass True) is safe: `all_gather_object` gives every rank the same ownership list, so the `allow_missing` branch is only reached when *no* rank owns the object - in which case all ranks are non-owners and all pass `allow_missing=True`. When any rank owns it, `src_rank` is found everywhere and the broadcast runs symmetrically. No collective divergence. The change correctly turns the old `ValueError` into a graceful `{}` export for Megatron params with no HF counterpart on any PP rank (e.g. MoE modules on dense layers via `moe_layer_freq`).

**Suggested test cases** (all present in this PR):
- `test_megatron_to_hf_skips_param_no_pp_rank_owns` - unowned param exports as `{}` and nothing is broadcast
- `test_megatron_to_hf_uses_type_broadcast_by_owning_pp_rank` - non-owning rank still receives the parallelism type from the owner
- `test_broadcast_obj_from_pp_rank_raises_when_unowned_by_default` - default (`allow_missing=False`) still raises when no rank owns the object

No perf tests impacted.
