# test(quant): cover the priority models in the ModelOpt HF export test

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6770) · state: open · merged: False

## Original PR description

# What does this PR do ?

Focuses the ModelOpt quantized HF export functional test (`test_modelopt_hf_export.py`) on the models we care most about, and fixes a silent-corruption case it found. Stacked on #6767; review that first.

| Model | Format | Compared with the 1-GPU export | What it covers |
|---|---|---|---|
| Qwen3 | FP8 | TP2 | Dense baseline, FP8 packing |
| Qwen3.5-VL MoE | Mixed (NVFP4 MLP, FP8 attention) | PP2, EP2 | GatedDeltaNet, routed + shared experts, VLM wrapper with the vision tower unquantized |
| Nemotron-H | NVFP4 | TP2, PP2, EP2 | Mamba `in_proj`, MoE, parity with ModelOpt's `export_mcore_gpt_to_hf` |
| GLM-5.3-Flash | NVFP4 | EP2 | KDA fused `in_proj` (traced rows), DSA/MLA, hyper-connections |
| DeepSeek-V4 Flash | NVFP4 | PP2 | Window/compressed attention, hash-routed MoE, PP layout (its attention supports TP=1 only) |
| Kimi K3 | NVFP4 | TP2 | KDA and MLA, latent MoE, attention residuals, remote-code config |

15 exports, down from 16 today. The Qwen3-MoE, text-only Qwen3.5 and #6767's Bailing / Qwen3-Next / Step-3.5 cases are removed; their mappings stay covered by unit tests.

# Changelog

- `modelopt_utils`: a quantized weight whose HF output is not a `<module>.weight` tensor now fails the export plan. Before, e.g. DeepSeek-V4's hyper-connection mixer (`nn.Linear` in Megatron, bare `hc_attn_fn` parameter in HF) was written packed with no entry in `quantization_config`.
- Toy checkpoints move to `tests/functional_tests/test_groups/quantization/modelopt_export_toys.py` and are built only when a test needs them. Kimi K3 is not in `transformers` (5.17 / 5.20.2), so its toy is a raw state dict with a 7-line config class loaded with `trust_remote_code`. DeepSeek-V4 reuses the released-layout conversion from its conversion test.
- Export driver (`modelopt_hf_export.py`):
  - keeps vision towers, DSA indexers, DeepSeek-V4 compressors, hyper-connection mixers and Kimi K3's attention residuals unquantized, as deployments do;
  - finalizes with `apply_overrides_and_finalize`, which sets DeepSeek-V4's PP layout;
  - ties the weight ranges of projections deployments fuse (MLA q/kv down-projections, Kimi K3's KDA q/k/v and `q_a_proj` / `kv_a_proj_with_mqa`). ModelOpt 0.49 does this for `linear_q_down_proj` / `linear_kv_down_proj` during calibration; Kimi K3's HF-style module names are tracked in OMNIML-6311;
  - skips ModelOpt's amax sync without TP/ETP. With TP=1 every rank holds whole weights, and ModelOpt 0.48 syncs Megatron-Core `TELinear` ranges over all ranks, which hangs under PP (fixed in NVIDIA/Model-Optimizer#3199, tracked in OMNIML-6311).

# Tests

- `test_modelopt_hf_export.py`: every case passes locally on 2× RTX 6000 Ada in `nvcr.io/nvidian/nemo:26.10.rc9` (nvidia-modelopt 0.48.0rc1, pinned Megatron-LM). I ran a superset of this matrix (20 exports, all 6 models; 7 passed in 50 min) and then GLM-5.3-Flash at EP2 on its own, the one case not in that superset. Every parallelism writes the single-GPU checkpoint bit for bit, and each model's `quantization_config.ignore` is checked exactly.
- `tests/unit_tests/models/test_modelopt_utils.py`: 124 passed, including the new `test_quantized_weight_must_map_to_hf_weight_tensor`.
- Locally each export takes ~150 s under coverage on shared GPUs; in CI the current 16 exports take ~16 min, so the 15 here should stay well inside the 30 min job.
