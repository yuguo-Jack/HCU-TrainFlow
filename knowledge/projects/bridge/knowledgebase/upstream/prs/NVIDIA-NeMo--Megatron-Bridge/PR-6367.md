# fix(model): apply Hugging Face YaRN defaults for omitted rope_scaling keys

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6367) · state: open · merged: False

## Original PR description

# What does this PR do ?

Applies the Hugging Face YaRN defaults (`beta_fast=32`, `beta_slow=1`, `truncate=True`) in the shared HF → Megatron config mapping when a YaRN `rope_scaling` omits them, so GPT-family checkpoints with YaRN no longer crash at model construction.

**The bug:** the shared mapping only copies YaRN keys that are present. A config such as `{"rope_type": "yarn", "factor": 4.0, "original_max_position_embeddings": 32768}` is the standard form for Qwen2.5 / Qwen3 long context. With it, `yarn_beta_fast` / `yarn_beta_slow` stay `None`. Megatron Core's `GPTModel` passes these fields to `YarnRotaryEmbedding` explicitly, which overrides its defaults, so model construction fails:

```
TypeError: unsupported operand type(s) for *: 'NoneType' and 'int'   (yarn_rotary_pos_embedding.py:244)
```

# Changelog

- `MegatronModelBridge.YARN_HF_DEFAULTS`: the defaults transformers' `_compute_yarn_parameters` uses for omitted keys.
- The GPT YaRN branch of the shared mapping fills those defaults with `setdefault`. Values the checkpoint sets explicitly always win.
- Unit tests: defaults are filled for omitted keys, explicit keys are preserved, and non-YaRN configs are unaffected.
- `Qwen3Bridge`: drops its local copy of the same three defaults, added by #6365, now that the shared mapping fills them. Qwen3's existing YaRN tests, which assert 32 / 1 / `True` for omitted keys and keep explicit values, now cover the shared path.

# Scope and behaviour change

- **Affected:** generic GPT bridges whose YaRN config goes through the shared mapping (for example Qwen2/2.5, Qwen3, Qwen3-MoE).
- **Not affected:**
  - MLA models (separate `MLA_ROPE_SCALING_MAPPING` branch).
  - Mistral and Ministral3, which build their providers by hand.
  - GPT-OSS, which sets every YaRN field explicitly after the mapping.
- **Behaviour change for configs that already worked:** a YaRN config that sets the betas but omits `truncate` previously got `yarn_correction_range_round_to_int=None` (no rounding). It now gets `True`, matching Hugging Face's default. Agreement with HF logits improves (table below).
