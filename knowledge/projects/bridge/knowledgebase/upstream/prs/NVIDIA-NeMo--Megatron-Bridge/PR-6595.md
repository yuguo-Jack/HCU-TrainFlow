# fix(peft): resolve grouped-expert LoRA init from the full per-expert fans

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6595) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Makes the initialization of per-expert LoRA adapters (`GroupedExpertLinearAdapter`, `share_expert_adapters=False`) and of the shared side of `SharedOuterGroupedExpertAdapter` independent of the expert-parallel, expert-tensor-parallel and tensor-parallel sizes, by resolving the fan-dependent init methods (`xavier`, `kaiming`) from the full per-expert matrix dims instead of the stacked 3-D tensor or the local shard. This is the grouped-expert follow-up that #5843 left open.

Background: `GroupedExpertLinearAdapter` stores its weights as `(num_local_experts, dim, in_features)` and `(num_local_experts, out_features, dim)` and initialised them with `nn.init.xavier_normal_` on the 3-D tensor. torch reads `fan_in = dim * in_features` and `fan_out = num_local_experts * in_features` off that tensor, so every expert's `linear_in` started with std `sqrt(2 / ((dim + E_local) * in_features))` instead of `sqrt(2 / (in_features + dim))`, about `sqrt(dim + E_local)` too small (8.4x at rank 64 with 8 local experts, 11x at rank 128 with 8 local experts), and shrinking further with fewer EP ranks. With `lora_B` zero-initialised, the adapter's effective learning rate scales with `||A||`, so per-expert adapters trained from this init barely move while the dense adapters of the same run train normally.

# Changelog

- `GroupedExpertLinearAdapter.__init__` passes `fan_in=in_features, fan_out=dim` (linear_in) and `fan_in=dim, fan_out=out_features` (linear_out) to `_get_init_fn`, so xavier resolves to a fixed-std normal and kaiming to a fixed-bound uniform computed from the per-expert matrix; the init no longer depends on `num_local_experts` or on the expert-TP shard. For one unsharded expert matrix the draws are bit-identical to before.
- `SharedOuterGroupedExpertAdapter.__init__` passes the same full fans for the init handed to its TP-sharded `ColumnParallelLinear` / `RowParallelLinear` and to `PackedPerExpertLinear` (which already initialised one expert matrix at a time, so only the shared side changes).
- Tests (CPU, `tests/unit_tests/peft/test_utils.py`, `test_canonical_lora.py`): per-expert xavier scale for 1/4/8 local experts, independence from the expert-TP shard (ETP 1/2/4), per-expert kaiming bound, the shared-outer init resolved from the full fans, and the `CanonicalLoRA` transform producing per-expert adapters at the per-matrix scale. All fail on `main` and pass with the fix.
- `MultiLoRA` init paths are untouched (own geometry, as in #5843).
