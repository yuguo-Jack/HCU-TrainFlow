# fix(recipe): fit the Qwen3.5-VL 27B SFT recipe on 16 H100

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6755) · state: closed · merged: False

## Original PR description

# What does this PR do ?

`qwen35_vl_27b_sft_16gpu_h100_bf16_config` runs out of memory on its own hardware: at its MBS 4, the first pipeline stage exceeds 80 GB H100 memory in the first iteration. This makes the recipe fit on 16 H100s by turning on sequence parallelism and selective recompute of `core_attn`, `gdn_norm_out` and `mlp`.

# Changelog

- `src/megatron/bridge/recipes/qwen_vl/h100/qwen35_vl.py`: the 27B SFT recipe sets `sequence_parallel=True` and selective recompute of `core_attn`, `gdn_norm_out` and `mlp` (previously no sequence parallelism and no recompute). Its layout (TP4/PP4), batch (MBS 4, GBS 32), schedule and precision are unchanged.
- `tests/unit_tests/recipes/qwen_vl/test_qwen35_vl_recipes.py`: a defaults test for the 27B SFT recipe.
- `tests/functional_tests/test_groups/recipes/test_qwen35_vl_recipes_finetune.py` (L1): the recompute scenario now runs the recipe's own selective default instead of full recompute, and the freeze and `qwen3_vl_step` scenarios run without recompute, so recompute stays covered by one scenario.

# Validation

MedPix SFT of Qwen3.8-27B (the Qwen3.5-27B architecture) on 2x8 H100 80GB at TP4/PP4, MBS 4, GBS 32, sequence length 4096 with padding to the maximum length, BF16, not deterministic. Each layout ran 15 steps, timed over steps 6-15:

| Sequence parallel | Recompute | Result |
|---|---|---|
| on | none | out of memory in iteration 1 (first stage) |
| on | selective `core_attn`, `gdn_norm_out` | out of memory in iteration 1 (first stage) |
| on | selective `core_attn`, `gdn_norm_out`, `mlp` (this PR) | 5,660 ms per step, 243.1 model TFLOP/s per GPU; first stage peaks at 75.9 GB allocated, 78.0 GB (72.6 GiB) reserved of 79.1 GiB |
| on | full, uniform, 1 layer | 6,210 ms per step, 221.6 TFLOP/s per GPU; 54.4 GB allocated, 56.6 GB reserved |
| off | full, uniform, 1 layer | 6,328 ms per step, 217.4 TFLOP/s per GPU; 55.8 GB allocated, 62.5 GB reserved |

- Losses of the fitting layouts agree within 0.84% at every shared step; no skipped or NaN iterations.
- The selective default leaves about 6.5 GiB free on the first stage. These runs disabled validation and checkpoint saves, which the recipe enables every 500 steps. One-layer full-uniform recompute is the fallback with more headroom (about 26 GiB free, 9% slower); the Qwen3.8 card's H100 SFT item (#6753) uses it as a declared override.
- `tests/unit_tests/recipes/qwen_vl/`: 272 passed. The functional test file collects its 5 tests; its GPU run is in L1.
- pre-commit on all files: passed.
