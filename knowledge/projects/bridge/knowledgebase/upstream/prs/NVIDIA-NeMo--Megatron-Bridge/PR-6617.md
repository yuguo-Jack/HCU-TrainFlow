# feat(recipe): add deterministic Nemotron 3 Ultra GB200 MXFP8 perf recipe

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6617) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Add a deterministic variant of the Nemotron 3 Ultra 256-GPU GB200 MXFP8 perf recipe. It keeps the NCCL EP dispatcher, so the only delta vs the base recipe is determinism overhead.

# Changelog

- Add `nemotron_3_ultra_pretrain_256gpu_gb200_fp8mx_deterministic_config` in `perf_recipes/nemotronh/gb200/nemotronh.py`: wraps `nemotron_3_ultra_pretrain_256gpu_gb200_fp8mx_config` and applies `apply_determinism_overrides` (deterministic mode, unfused CE and router aux loss, determinism env vars including `NCCL_EP_HT_EM_AG_SCAN_MODE=1`, and the Mamba/causal-conv1d flags).
- Unlike `deepseek_v3_pretrain_256gpu_gb300_fp8mx_deterministic_config`, this recipe does **not** switch to HybridEP and does not change `moe_use_grouped_tensor`. All perf settings (GTP, CUDA graphs, offload, recompute) are inherited unchanged.
- Declare the recipe's `cfg.env_vars` inline (`**COMMON_PERF_ENV_VARS`, `**DETERMINISM_ENV_VARS`, plus the base recipe's settings), as required for flat perf recipes and matching the DeepSeek V3 deterministic recipe. The resulting environment equals the base environment plus `DETERMINISM_ENV_VARS`.
- Export it from `megatron.bridge.perf_recipes.nemotronh`.
- Add a unit test: the dispatcher stays NCCL EP, every base env var is preserved, and all determinism env vars are set.

# Validation

256× GB200 (64 nodes), 50 steps, NeMo 26.10 rc7 image, MCore at the Bridge pin. Two deterministic runs (A1, A2) and one non-deterministic baseline (B, the existing fp8mx recipe). Forced load balancing is on, as in all perf recipes.

**Determinism.** A1 and A2 are identical at all 50 steps for lm loss, MTP-1/2 loss and grad norm, at log precision.

**Overhead, steps 20–48 mean.** B hit its 1 h time limit after step 48 because of a slow first-step kernel compile.

| Run | Det | ms/step | MODEL TFLOP/s/GPU |
|---|---|---|---|
| A1 | on | 4,885 | 603.3 |
| A2 | on | 6,532* | 505.0* |
| B | off | 4,566 | 646.4 |

| Comparison | Step time | TFLOP/s/GPU |
|---|---|---|
| A1 vs B | **+7.0%** | **−6.7%** |
| A2 vs B | +43.1%* | −21.9%* |

A1 vs B is the representative overhead: about **+7% step time** and **−7% TFLOPs**.

\*A2 is an outlier. It ran a burst of slow steps (step 36: 8.1 s, 37: 12.6 s, 38: 17.2 s, 39: 15.5 s, 40: 7.3 s, 41: 6.3 s, 47: 7.0 s). A1 never exceeded 5.6 s and B never exceeded 5.9 s in the same window, and A1/A2 have identical configs and bitwise-identical numerics, so this is most likely a node or fabric issue on A2's allocation, not determinism cost. By median, the gap is about +10% (A1) and +20% (A2).
