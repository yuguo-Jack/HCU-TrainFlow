# feat(quant): save ModelOpt-quantized models as quantized HF checkpoints

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6657) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Adds `AutoBridge.save_hf_pretrained_modelopt`, which saves a ModelOpt-quantized Megatron model as a quantized Hugging Face checkpoint (packed weights, scales and the inline `quantization_config` that vLLM, SGLang and TensorRT-LLM read) at any TP / PP / EP / ETP. It is the offline counterpart of `export_hf_weights_modelopt` (#5812), and `examples/quantization/export.py` now uses it instead of ModelOpt's TP=1-only Megatron exporter.

Part of #4804 (PR 3 of its plan, "quantized export core"); tracked as OMNIML-5976.

```python
bridge.save_hf_pretrained_modelopt(megatron_model, "./llama3_2_1b_nvfp4_hf")
```

# Changelog

- `AutoBridge.save_hf_pretrained_modelopt(model, path, *, export_plan=None, show_progress=True, source_path=None, max_shard_size=5 GiB)`:
  - streams the tensors of `export_hf_weights_modelopt` into safetensors shards (the source checkpoint's layout can't hold the new scale tensors) and writes the plan's `quantization_config` into `config.json`, replacing any source quantization config; no `hf_quant_config.json`;
  - fails, on every rank, for enabled quantizers it cannot carry yet (KV-cache `k/v_bmm_quantizer`, output quantizers) instead of dropping them, and for projections that deployments fuse into one GEMM (q/k/v, gate/up, MLA q_a/kv_a) whose `weight_scale_2` / `input_scale` differ;
  - rejects bridges that post-process exported weights.
  - It is a separate API for now, so `save_hf_pretrained`'s fake-quant sidecar export (#6565) is unchanged; a TODO notes unifying the two by quantizer state.
- `build_modelopt_export_plan`: the `quantization_config` `ignore` list names only unquantized matrices (embedding, LM head, routers, ...), no longer norms and other vectors.
- `examples/quantization/export.py`: uses the new API at any parallelism. Models it does not cover yet (e.g. KV-cache quantization, Mamba layers) and `--export-extra-modules` (EAGLE / Medusa) fall back to ModelOpt's exporter.
- `save_hf_pretrained`'s artifact saving moved into `_save_hf_artifacts`, shared by both saves (no behavior change).
- Docs (`docs/modelopt/quantization.md`, `examples/quantization/README.md`), unit tests, and an L0 functional test (H100 + GB200, 2 GPUs).
- The PTQ examples and docs use `Qwen/Qwen3-0.6B` instead of the dated Llama-3.2-1B.

# Testing

- Unit: `tests/unit_tests/models/test_modelopt_utils.py` 70 passed (new: shard writer, sibling-scale check, quantizer guard, norms not ignored).
- Functional (new L0 `test_modelopt_hf_export.py`, 3 passed): toy Qwen3 NVFP4 at TP2 / PP2, FP8 at TP2, and Qwen3-MoE mixed NVFP4-MLP / FP8-attention at EP2 / ETP2 / PP2 each write the single-GPU checkpoint bit for bit, with identical `config.json`.
- Also locally: 21 exports (Qwen3 / Qwen3-MoE × NVFP4 / FP8 / mixed × TP1 / TP2 / PP2 / EP2 / ETP2) all bitwise equal to TP1.
- Examples end to end on a tiny Qwen3: `quantize.py --export-quant-cfg nvfp4` (calibrated, saved at TP1), then `export.py` at TP2 equals `export.py` at TP1, and equals ModelOpt's `export_mcore_gpt_to_hf` of the same checkpoint: every tensor bitwise (per-tensor scales are 0-d instead of 1-d) and the same `config.json` including `quantization_config`. Only the shard layout differs and `hf_quant_config.json` is no longer written.
- `Qwen/Qwen3-0.6B` with the updated example commands: `quantize.py` (FP8 and NVFP4, TP2, 32 calibration samples; post-quantization generation coherent) then `export.py` at TP2: `quant_algo` FP8 / NVFP4, `ignore` = `lm_head`, `model.embed_tokens`.
- Not run: larger models, vLLM serving.

Notes:
- Parity tests against ModelOpt's exporter and KV-cache export are a follow-up once the ModelOpt pin reaches 0.49.0rc0 (FP8 rounding fix NVIDIA/Model-Optimizer#3005, KV-cache export NVIDIA/Model-Optimizer#2981); a TODO in the functional test tracks it. With 0.48.0rc1, FP8 exports are self-consistent across parallelism but round some weights differently from ModelOpt's exporter and fake quantization.
