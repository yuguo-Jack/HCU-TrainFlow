# docs(model): re-verify the Nemotron 3.5 Lightning GB200 long-context SFT leaf at ae0a1b026

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6777) · state: open · merged: False

## Original PR description

## What

Re-verifies `items.sft_long_context.GB200` of the Nemotron 3.5 Lightning verification card at Megatron Bridge
`ae0a1b026f52517c55cf19416510f7f895a24c0c` in `nvcr.io/nvidia/nemo:26.08`, with the leaf's command unchanged. The
leaf now records that commit as its own `bridge_commit`; every other leaf keeps the card's default commit, and the
summary says so. The catalog JSON and the Lightning model guide (and its Fern page) are regenerated from the card.

## Result

2 GB200 nodes x 4 GPUs, 100 steps of 32K packed OpenMathInstruct-2 SFT:

| Metric | Value |
| --- | --- |
| LM loss, step 1 -> 100 | 0.4268937 -> 0.2648855 |
| MTP-1 loss, step 1 -> 100 | 0.5128821 -> 0.3132023 |
| Step time, steps 91-100 | 31,725.330 ms |
| Model throughput, steps 91-100 | 440.660 TFLOP/s/GPU |
| Token throughput, steps 91-100 | 16,525.849 tokens/s/GPU |

All 100 steps have finite LM/MTP losses and no skipped or NaN iterations. The step-100 checkpoint is complete:
12 files (distributed metadata, eight shards, `metadata.json`, `run_config.yaml`, `train_state.pt`) and a latest
marker of 100. Its saved run configuration matches the command (32K packs aligned to 4, CP2 a2a, EP8 HybridEP,
selective recompute, GBS 128 / MBS 1, LR 5e-6 -> 0 over 100 steps with 10 warmup steps).

The MTP-1 values are lower than the ones this leaf recorded before because MTP loss now applies the SFT loss mask
(#6175). The expected result therefore notes that this leaf is not convergence-comparable with the H100
long-context leaf, which still records the card's older default commit.

## How it was run

The leaf's command at `ae0a1b026` in the 26.08 container, reading the Hugging Face tokenizer and dataset offline from
a cache filled at the pinned revisions. The OpenMathInstruct-2 packs were written before the GPU job by the same
configuration's dataset builder, so the run read them instead of packing in the job.
