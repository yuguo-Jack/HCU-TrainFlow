# docs(model): publish a two-node H100 geometry for Super VL text-only conversion

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6600) · state: closed · merged: True

## Original PR description

> Stacked on #6599 (NVBug 6965336): both change the text-only card's H100 `sft_export_inference` export line. Merge #6599 first; this PR then retargets to `main`.

# What does this PR do ?

Fixes the Super VL text-only card H100 GPU import/export and SFT export OOMing on 4x H100 80GB by publishing a verified 2x4 geometry.

# Changelog

- `examples/model_verification_cards/nemotron-3.5-super-vl-120b-a12b-text-only/card.yaml`: `hf_to_megatron_gpu`, `megatron_to_hf_gpu` and `sft_export_inference.H100` export use `--nodes 2 --gpus-per-node 4 --tp 1 --pp 2 --ep 4 --etp 1`; `last_verified` 2026-10-20.
- `docs/_static/model-verification/catalog-v1.json`, `docs/models/nemotron/nemotron3.5-super-vl-text-only.md`, `docs/fern/.../nemotron3.5-super-vl-text-only.mdx`: regenerated from the card.

# Additional Information

- **Root cause:** at 1x4 TP1/PP2/EP2 each H100 holds ~62 GiB of weights and the output-layer allocation OOMs (14.90 GiB reserved-unallocated). It passes only with an allocator env, which cards may not publish.
- **Regression?** No. The 4-GPU H100 claim never reproduced from the published command; GB200 at 4 GPUs still passes.
- **Verification:** real `convert.sh`/`infer.sh --executor slurm` on `nemo:26.08.01`. Import and export at pin 3a5b4f610 pass on H100 and GB200 (2x4); the export matches the source `language_model.*` keys, shapes, dtypes and values exactly (42,683 tensors). The H100 SFT export plus HF reload at 5e63b9d9 pass (862 modules, "Two plus two equals four.").
- **Not re-run:** the six-position SFT forward fixture. No unit test (data-only change), but the existing card and catalog tests pass.
- **NVBug:** 6965333.
