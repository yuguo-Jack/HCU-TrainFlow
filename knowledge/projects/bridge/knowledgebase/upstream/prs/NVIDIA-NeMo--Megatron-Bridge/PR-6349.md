# fix(model): build Sarvam MLA without a query norm when there is no query LoRA

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6349) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Builds Sarvam 105B's MLA layers without the query norm that its Hugging Face architecture does not define, reusing the DeepSeek fix from #5262.

Sarvam 105B has `q_lora_rank: null` and needs `qk_layernorm=True` for `kv_a_layernorm`. With that combination MCore fuses an RMSNorm into `linear_q_proj` (`QKNormConfigResolver._resolve_mla_qk_layernorm`), the same problem #5261 describes for DeepSeek: the parameter has no Hugging Face counterpart, so importing a Sarvam checkpoint fails and exports drop a trained weight.

# Changelog

- `SarvamMLAModelProvider` builds its decoder block with `get_deepseek_decoder_block_spec` instead of `get_gpt_decoder_block_spec`. Models with a query LoRA are unchanged; Sarvam has no MTP layers, so no MTP transform is needed.
- `test_sarvam_mla_provider_defaults` checks the provider uses that spec builder.

Testing, on this branch with the pinned Megatron-LM: `tests/unit_tests/models/sarvam` and `tests/unit_tests/models/deepseek/test_deepseek_attention.py` pass (69 tests). A small randomly initialized Sarvam MLA model in the production Hugging Face layout (norm weights randomized) imports with no `linear_q_proj.layer_norm_weight`, and its logits match the Hugging Face model (relative L2 difference 5e-4 in FP32).

Sarvam MLA checkpoints already trained with Bridge on MCore 0.19 or later contain `linear_q_proj.layer_norm_weight`. The corrected model has no such parameter, so those checkpoints load without it and behave differently; this is the same trade-off as #5262.
