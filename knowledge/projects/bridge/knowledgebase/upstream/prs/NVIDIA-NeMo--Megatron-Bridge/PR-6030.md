**Review — DeepSeek V3 B200 perf recipe retune**

The change retunes the 256xB200 DeepSeek V3 recipes: BF16/FP8-CS drop PP 16->8; FP8-MX drops EP 32->8, keeps VPP=2, removes DeepEP dispatcher + MoE EP-comm overlap + delay-wgrad and keeps only mla_up_proj recompute; NVFP4 switches EP 32->8 and dispatcher DeepEP->HybridEP with overlap/delay-wgrad off; all gain the HybridEP topology env block (NUM_OF_HYBRID_EP_RANKS_PER_NVLINK_DOMAIN, NUM_OF_TOKENS_PER_CHUNK_COMBINE_API, NVLINK_DOMAIN_SIZE=8, USE_MNNVL=0).

**Findings**

- [High] CI-breaking test mismatch. tests/unit_tests/recipes/test_perf_recipe_environment.py::test_explicit_environment_invariants_across_all_flat_recipes still lists deepseek_v3_pretrain_256gpu_b200_fp8mx_config and deepseek_v3_pretrain_256gpu_b200_nvfp4_config in _DEEPSEEK_WITHOUT_HYBRID_EP_RECIPES and asserts they carry no HybridEP env vars. This PR adds those vars to both, so the (assert not hybrid_ep_names) check fails. That set must be updated in this PR. See inline comment.
- [Low] Formatting. A blank line between nvfp4_config and fp8mx_large_scale_config was removed (only one blank line now); ruff format expects two. See inline comment.
- [Question] Inert env in fp8mx_config. It gains the HybridEP topology vars but keeps the default alltoall dispatcher (moe_flex_dispatcher_backend is not set to hybridep), so those vars have no effect. Only nvfp4_config actually selects hybridep. Confirm this is intended.
