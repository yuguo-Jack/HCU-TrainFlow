# fix(model): start text-only Super VL H100 SFT card leaf from the import

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6599) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Makes the Nemotron 3.5 Super VL text-only card's H100 `sft` leaf runnable from the card: it resumed a step-250 `h100-sft` checkpoint that no card command writes, so it now trains from the imported checkpoint, as the GB200 leaf does.

# Changelog

- `examples/model_verification_cards/nemotron-3.5-super-vl-120b-a12b-text-only/card.yaml`: `sft.H100` starts from `--pretrained_checkpoint .../megatron/iter_0000000` and saves to `h100-sft`; `sft_export_inference.H100` exports `h100-sft/iter_0000500`; H100 metrics, dates and results now come from the re-run.
- `docs/models/nemotron/nemotron3.5-super-vl-text-only.md`, its Fern mirror, `docs/_static/model-verification/catalog-v1.json`: regenerated.
- `tests/unit_tests/doc_consistency/test_verification_card_published_commands.py`: new check that every published `--load_dir` reads a path written by a command in the same card, plus regression cases.

# Additional Information

- **Root cause:** the leaf was a recovery continuation of an unpublished reference run. No card item writes `h100-sft`, so the command failed with a missing input.
- **Regression?** No. The leaf has been like this since the card landed in #6220.
- **Verification:** ran the fixed command on 8x8 H100 (nemo:26.08.01, Bridge `5e63b9d9`, the card pin): 500/500 steps, 0 skipped/NaN, with a complete `iter_0000500`. The export plus HF reload/greedy completion reproduced the card's result. The new test fails on the old card and passes on the fixed one.
- **Not included:** the removed "matched numerical fixture" claims were not re-run. The H100 export needs `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`, which is a separate NVBug (6965333). #6586 adds the matching check for the `checkpoint.load=` form.
- **NVBug:** 6965336.

- svcnvidia-nemo-ci · comment · 2026-10-21T16:57:46Z · [source](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6599#discussion_r4339573284)

File: `tests/unit_tests/doc_consistency/test_verification_card_published_commands.py` · line 237

[P2] Count only the effective checkpoint save path

**Failure:** Using the existing reduced-argv fixture pattern, give `_published_commands` two entries from the same card:

```text
train.sh --save_dir work/unwritten checkpoint.save=work/actual
train.sh --load_dir work/unwritten
```

This check passes because both producer tokens enter `produced`. However, [the training runner applies convenience arguments before trailing ConfigContainer overrides](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/0df0d7bcab2bff3950096006d1225b458f1d0e15/scripts/training/run_recipe.py#L506-L511): the first command saves only to `work/actual`. With otherwise valid training arguments and an empty workspace, the second command therefore still loads an unpublished checkpoint root—the failure this guard is meant to reject. Reversing the two producer tokens does not change their precedence.

**Correction:** In this function, resolve recognized outputs per command before adding them to the card-wide set. A trailing `checkpoint.save` must replace, not supplement, `--save_dir`. This small suggested patch preserves the other currently recognized producers:

```diff
         output_flag = conversion_outputs.get(tokens[1]) if is_conversion else None
+        outputs: dict[str, str] = {}
         for index, token in enumerate(tokens):
             name, _, value = token.partition("=")
             if not value and index + 1 < len(tokens):
                 value = tokens[index + 1]
             if name in producers or name == output_flag:
-                produced.setdefault(card, set()).add(value.rstrip("/"))
+                outputs[name] = value.rstrip("/")
             if name == "--load_dir":
                 loads.append((leaf, card, value.rstrip("/")))
+        if "checkpoint.save" in outputs:
+            outputs.pop("--save_dir", None)
+        produced.setdefault(card, set()).update(outputs.values())
```

Keep this resolution **per command**: another independent command genuinely saving `work/unwritten` must still make that root eligible. The patch is a source-based suggestion, not executed code; verify it before adoption.

**Acceptance/preservation:** Add a proposed regression asserting that loading `work/unwritten` raises for both producer-token orders, while loading `work/actual` or `work/actual/iter_0000250` passes. Also assert that an independent producer of `work/unwritten` makes that load pass. Retain the existing same-card root/iteration acceptance cases and unproduced-root rejection cases. Standalone `--save_dir`, standalone `checkpoint.save`, conversion-output recognition, trailing-slash handling, and separation between cards must remain unchanged.
