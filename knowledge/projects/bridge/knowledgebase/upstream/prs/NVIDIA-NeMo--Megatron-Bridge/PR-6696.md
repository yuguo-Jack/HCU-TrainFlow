# perf(recipe): give the MoE dispatcher 32 SMs and fuse the router in the Nemotron 3.5 Lightning VRNVL72 recipes

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6696) · state: closed · merged: True

## Original PR description

## Summary
This PR changes two settings in both Nemotron 3.5 Lightning VRNVL72 recipes (`nemotron_3_5_lightning_pretrain_8gpu_vrnvl72_fp8mx_config` and `nemotron_3_5_lightning_pretrain_8gpu_vrnvl72_bf16_config`):

1. **`moe_hybridep_num_sms` 16 → 32.** This field is an alias for `moe_flex_dispatcher_num_sms`, which the NCCL EP dispatcher from #6373 also reads. Both recipes inherit 16 from the GB300 builders.
2. **`moe_router_fusion` False → True.** The base Lightning config leaves top-k/score routing unfused.

## Measurement
Both settings were first measured with HybridEP. They were measured again on top of #6373 (NCCL EP) in nemo-ci on Hecate, with the PR and plain main run in the same configuration. With the change, the mean step time is shorter in both precisions. Results are available internally on request.

On HybridEP:
- On MXFP8, 48 and 64 SMs were not meaningfully faster than 32.
- On BF16, 24 SMs was not meaningfully faster than 16.

The matching nemo-ci goldens update is ready to merge after this PR.

## Scope
- The GB300 recipes are unchanged because they weren't measured there.
- `test_vrnvl72_perf_recipes_match_gb300_configs` keeps its NCCL EP checks. It now lists both settings as allowed differences between VRNVL72 and GB300 in both precisions.

## Testing
- `ruff check` and `ruff format` pass.
- Recipe changes were exercised end-to-end by the nemo-ci perf tests described above.
