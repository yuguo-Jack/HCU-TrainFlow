# build(mok): include Rubin in nightly GPU targets

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6687) · state: open · merged: False

## Original PR description

Regular nightly images currently contain MoK kernels for Blackwell SM100/SM103, so the same image cannot run MoK on Rubin. Build SM100a, SM103a, and SM107a kernels into each native ARM/x86 wheel by default, using the existing PyTorch 26.09 / CUDA 13.4 base.

Pin MoK to the Rubin-support change in [QiZhangNV/mixture-of-kittens#10](https://github.com/QiZhangNV/mixture-of-kittens/pull/10), based on the current integration branch. That change selects ThunderKittens device instructions separately for each GPU target. Remove Bridge's local MoK patch because its multi-target and namespace fixes already exist in the selected source; MoK owns its TK preparation patches.

The installer compiles a small kernel for every requested NVCC target before fetching/building and verifies all requested cubins in the installed wheel. `MOK_ARCH=ALL` remains the Dockerfile default; individual SM100/SM103/SM107 builds remain available. No architecture pipeline variable is needed: [nemo-ci !3018](https://gitlab-master.nvidia.com/dl/JoC/nemo-ci/-/merge_requests/3018) now exposes only an optional source-commit override.

Validation:
- Nine focused installer tests and three single-architecture subtests pass in a Linux CPU container. These exercise compiler rejection and missing-cubin detection with mocked build tools.
- Shell syntax and changed-source whitespace checks pass.
- `uv run pre-commit run --all-files` passes in the Linux container (all five Python hooks; Markdown-name hook has no matches).
- Native ARM/x86 CUDA 13.4 wheel builds pass in [pipeline 76993332](https://gitlab-master.nvidia.com/dl/JoC/nemo-ci/-/pipelines/76993332). Both installed extensions contain SM100a, SM103a, and SM107a cubins.
- Same-image GPU correctness passed on [GB300](https://gitlab-master.nvidia.com/dl/JoC/nemo-ci/-/jobs/512055599) and [Rubin](https://gitlab-master.nvidia.com/dl/JoC/nemo-ci/-/jobs/512055600): 16 tests passed on each of four ranks, including BF16/MXFP8 forward/all-gradient comparisons at widths 256/640 and the existing eager-dispatch cases. CI and Slurm completed successfully.
- Both GPU jobs loaded the identical ARM image digest and identical MoK extension SHA256. The intermediate `mok-wheel` image used an offline pytest-only overlay; the installed MoK package was unchanged.
- **Draft, dependent on MoK #10.** SM100 was compiled but not GPU-tested. These bounded kernel tests do not establish full-model correctness or performance parity; no published nightly tag was replaced.
