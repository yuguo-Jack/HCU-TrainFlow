# fix(training): exclude dropped anchor blocks from the DSpark loss and metrics

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/5242) · state: closed · merged: True

## Original PR description

> Stacked on #5233 and #5234: this fixes the DSpark core introduced there, so until those merge this PR also lists their commits. Only the last commit is new here; I will rebase once the base PRs land.

## What

`block_keep_mask` was consumed only by the `tau` diagnostic. The loss weight was built from `eval_mask` alone, so a dropped anchor block (keep = 0) whose eval prefix was still set received full CE/TV/confidence gradient, and its positions were averaged into `accept_rate`, biasing both the objective and the diagnostics.

## Fix

Define the supervised-position mask once in `dspark_loss` (`supervised = eval_mask * block_keep_mask.unsqueeze(-1)`), derive the decayed loss weight from it, and pass it into `_acceptance_metrics` (now keyword-only per the repo style rule on same-type parameters). One mask drives the loss weight, `accept_rate`, and the `tau` block validity, so the three sites cannot drift.

## Tests

Two new unit tests: dropped blocks produce exactly zero gradient and the loss equals the eval-mask-zeroed equivalent; `accept_rate`/`tau` ignore a dropped block that deliberately mismatches the teacher. Both fail on the parent commit and pass here. All 18 dspark unit tests pass; ruff is clean.

## Merge note

the masked-input-robustness fix PR (same stack) sanitizes padded inputs keyed on `eval_mask` alone. Whichever of the two branches merges into the DSpark core branch (#5234) second should rebase that sanitization onto the combined `supervised` mask (one-line change: build `supervised` first and use `supervised.bool()` as the scrub mask), so that positions of dropped anchors are scrubbed as well as zero-weighted.
