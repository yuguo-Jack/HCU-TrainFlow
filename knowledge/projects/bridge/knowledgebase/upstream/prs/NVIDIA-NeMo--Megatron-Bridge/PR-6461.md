# docs(recipe): clarify recompute and performance readiness

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6461) · state: closed · merged: True

## Original PR description

## What does this PR do?

Define performance readiness for new base pretraining library recipes and separate diagnostic full recompute from final recipe recommendations. No recompute and cheap selective recompute are equally valid starting choices. Full recompute requires measured capacity need or better end-to-end throughput in matched runs, including any larger MBS or lower TP it enables.

## Changelog

- Apply approximate BF16 targets of 200 model TFLOP/s/GPU on H100 and 400 on GB200 to new pretraining recipes under `src/megatron/bridge/recipes/`. Exclude SFT, PEFT, and long-context SFT. A `perf_recipes` benchmark cannot satisfy this library-recipe requirement. Other precisions/hardware need workload-matched measured targets.
- Withhold severely underperforming library recipes or explicitly mark them early, unoptimized in the recipe, public docs/card, and PR, with measured results and limitations. Include the label in the affected card item's `expected_result` so generated pages display it.
- Update the VLM workflow, examples, GDN caveat, and all four recompute guides. Compare viable layouts at fixed workload, hardware, precision, GBS, and convergence settings; record memory and steady-state performance.
- Identify the VLM card configurations as historical measurements rather than defaults, preserving their values, and align the recipe recommender's fit-then-fill evaluation.
