# fix(build): install pinned cuDNN Frontend Git ref in fw-final

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6447) · state: closed · merged: True

## Original PR description

The `fw-final` image built in [nemo-ci job 485560402](https://gitlab-master.nvidia.com/dl/JoC/nemo-ci/-/jobs/485560402) contains the registry `nvidia-cudnn-frontend==1.29.0` wheel despite requesting the pinned `feat/1.29.0-megatron` Git commit. `uv pip install` runs from `/opt/NeMo-FW`, where `override-dependencies` replaces the explicit Git requirement with the registry version.

When `CUDNN_FRONTEND_GIT_REF` is set, skip cuDNN Frontend during the preceding `uv sync`, install it from Git with `--no-config`, and fail the build unless the installed distribution records the requested commit. An empty ref continues to use the registry wheel, and `MBRIDGE_PRESERVE_BASE_RUNTIME=True` continues to preserve the base runtime.

Validation:
- In the published `fw-final` image, `uv pip install --dry-run --no-config` selected Git commit `8924d4b41fd678ba1b98cd7f98bb78b222637573` instead of the registry wheel.
- `uv run python -m pytest -q tests/unit_tests/docker/test_preserve_base_runtime.py`: 16 passed; the Dockerfile shell-syntax cases passed again after the final edit.
- `uv run pre-commit run --all-files`: passed in the published image with environment syncing disabled.

A full `fw-final` image rebuild has not been run locally.
