# feat(model): support Qwen3.5-VL MTP in MegatronMIMO training

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6781) · state: open · merged: False

## Original PR description

# What does this PR do ?

Adds Multi-Token Prediction (MTP) training for Qwen3.5-VL in MegatronMIMO, as requested in GitHub issue #6663. Until now MegatronMIMO dropped the MTP layer. It now builds it on the last language pipeline stage, trains it, logs its loss and keeps its weights through HF conversion. MTP stays off unless `--enable-mtp` is passed.

# Changelog

- **MTP spec per pipeline stage.** MegatronMIMO builds the language spec before the MPU globals exist. `mtp_block_spec()` and the Qwen3.5-VL spec builders therefore take an explicit `pp_rank`, which wins over the rank of the provider's own process groups. The Qwen3.5-VL MegatronMIMO language spec now wires `mtp_block_spec` (it was `None`), so only the stage that owns MTP builds it.
- **Opt-in per provider.** `Qwen35VLModelProvider` and `Qwen35VLMoEModelProvider` set `mimo_supports_mtp = True`. Providers without it still get `mtp_num_layers=None`, and MegatronMIMO now also turns `mtp_num_layers=0` into `None`.
- **Conversion.** With MTP kept, HF ↔ MegatronMIMO conversion imports and exports the `mtp.*` weights through the existing `Qwen35VLBridge` mappings. Checkpoints converted before this change have no MTP weights and must be converted again to train MTP.
- **Data flow.** `megatron_mimo_step.forward_step` keeps `input_ids` on the language stage that runs MTP, which re-embeds shifted tokens. Before, only the first stage kept them.
- **Logging.** `train_megatron_mimo` reduces the MTP loss tracker on the language last stage and adds `mtp_1 loss` to `loss_dict`, so it reaches the logging rank next to `lm loss`.
- **Example.** `finetune_qwen35_vl.py` gains `--enable-mtp`. It is off by default, raises if the HF config has no MTP layers, and makes the last language stage read `input_ids`. `slurm_sft.sh` exposes it as `ENABLE_MTP=1`. The example README and the non-colocated SFT tutorial document MTP training.
- **Parity check.** New `examples/megatron_mimo/qwen35_vl/verify_mtp_parity.py` (`standard`, `mimo` and `compare` steps):
  - Loads one HF checkpoint into the standard Qwen3.5-VL model (1 GPU) and into MegatronMIMO (language and vision on separate GPUs).
  - Runs one forward and backward pass on the same synthetic image-text batch.
  - Compares the weights, LM loss, MTP loss and every gradient. `compare` exits 1 on any mismatch.
- **Functional tests (2 GPUs).**
  - `megatron_mimo/test_qwen35_vl_mtp.py`, picked up by the L0 MegatronMIMO launcher: trains with MTP, and round-trips the `mtp.*` weights through HF export.
  - `models/qwen_vl/test_qwen35_vl_mimo_mtp_parity.py`: runs the parity script. It is added to the H100 and GB200 `L1_Launch_models_qwen35_vl.sh`.
- **Unit tests** cover:
  - MTP spec building at pipeline sizes 1 and 2 without the MPU globals
  - the provider gate
  - `input_ids` routing
  - MTP loss collection
  - the example's flags and batch spec
  - the parity comparison

# Difference from the standard path

MegatronMIMO's `MimoModel` passes an `mtp_input_mask` that excludes image-placeholder tokens from MTP conditioning and from the MTP loss. The standard `Qwen3VLModel` has no such mask. `mtp_1 loss` can therefore differ slightly between the two paths when image tokens contribute to the loss. The parity check applies the same mask on the standard side and also reports the unmasked standard MTP loss.

# Testing

GPU, 2× H100, at 8f2c73685 (before the main merge; Megatron-Core ed9c2c8c), on a 4-layer toy Qwen3.5-VL checkpoint with one MTP layer:

| Test | Branch | `main` (control) |
|---|---|---|
| `test_qwen35_vl_mtp.py` (MTP training, `mtp.*` round trip) | 2/2 pass | Training test fails: only `lm loss` is reported |
| `test_qwen35_vl_mimo_mtp_parity.py` | Passes in 4.3 min | Fails at the `mimo` step: MegatronMIMO builds no MTP layer |
| All of `test_groups/megatron_mimo` | 12/12 pass | n/a |

Parity results:
- Weights are bitwise equal: 53 language tensors, including 12 MTP, and 21 vision tensors.
- LM loss is 7.698769 and MTP loss 7.778442 on both paths.
- All 53 language and 21 vision gradients are bitwise equal.
- Without the image-token mask, the standard path's MTP loss is 7.795.
