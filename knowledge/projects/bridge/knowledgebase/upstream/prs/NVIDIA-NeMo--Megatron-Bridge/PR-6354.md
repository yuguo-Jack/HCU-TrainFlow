# [models] feat: add Qwen4-Exp hybrid builders and VLM conversion

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6354) · state: open · merged: False

## Original PR description

Qwen4-Exp can be built through `AutoBridge.get_model_config()` / `get_model()` as a Core HybridModel and converted with its vision tower. `text_only=True` selects the standalone language namespace, including the LM head, without loading vision tensors. LM and VLM share decoder construction and language modules.

This takes over Yuchen Wang's #6315, preserving every original commit and merge and adding the migration on top. Yuchen's Bridge-local QSA, gated residual, PLE and GDN/MoE implementation remains the basis. Casper Hansen's #6123 is the original conversion/model reference; this implementation does not depend on its unmerged Core changes. Neither original PR is modified or closed.

- Preserve complete attention/MLP blocks, layer indices, gated residual connections, PLE raw-token inputs and the learned final output mixer inside HybridModel/HybridStack.
- Use nested transformer/model configs and builders; remove unused legacy providers and redundant builder overrides.
- Convert the vision patch embedding, positional embedding, transformer and merger; use multimodal positions for attention and QSA pooled keys. Support sharded and native Transformers unsplit PLE tables, text-only selection and authoritative embedding tying.
- Skip the QSA indexer when the physical sequence length proves that all causal blocks fit the selection budget, retaining its checkpoint parameters and using the same dense attention backend. At the measured 2K length, the FLOPs estimate excludes skipped indexer projections.
- Provide a registered image-SFT recipe through standard `run_recipe.py` / `train.sh`, HF checkpoint loading and the shared Qwen VL forward step. The subset preparer lives under `scripts/data/`; there is no bespoke training driver.

The [image-SFT recipe](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/0759e54d8023df0842e366625eed4927ddbb43b8/src/megatron/bridge/recipes/qwen_vl/qwen38_flash_next.py) now defaults to the fastest combination in the completed comparison: **64 GB200, TP4/SP, EP64/ETP1, PP1/CP1, BF16, sequence 2048, MBS1/GBS16**, using **HybridEP**, fused permutation (including HybridEP permutation), router, bias/activation and gradient accumulation. Recompute, shared-expert overlap and CUDA graphs remain disabled. Routing remains natural; no forced load balancing was used. HybridEP requires its runtime backend and suitable NVLink placement.

**Early performance tuning; numerical equivalence remains unresolved.** The complete VL checkpoint `Qwen/Qwen3.8-Flash-Next` at revision `de4b8e4d43b917e7706784d8bb445c9af86a3540` was loaded in NeMo **26.10 RC4 (non-public release candidate)** with Transformers **5.16.1**, from runtime source `62f79249661338ea921f00d927d704bde10833cb`. The native Energon run completed **100 updates / 1,600 samples** from the prepared 8,192-sample Nemotron-Image-Training-v3 ECD subset. All 64 ranks completed with finite loss/gradient norms, no skipped updates, and actual 64-participant HybridEP domain checks.

| Native-loader TP4 result | Measured value |

| Initial / final loss | 0.350771964 / 0.167497709 |

The [verification card](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/0759e54d8023df0842e366625eed4927ddbb43b8/examples/model_verification_cards/qwen3.8-flash-next/card.yaml) and [recipe instructions](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/0759e54d8023df0842e366625eed4927ddbb43b8/examples/models/qwen/qwen4_exp/README.md) record this execution result. SFT verification denotes successful training execution, **not HF/backward/parallelism parity**. There is no input-matched native-loader baseline for a native throughput speedup claim.

Separate 40-update comparisons used identical authenticated predecoded samples, GBS16 and fresh full-checkpoint initialization:

| Configuration | Final-ten mean ms/update |
| --- | ---: |
| Original TP8 | 6,025.37 |
| QSA bypass, TP8 | 6,241.40 |
| QSA + HybridEP/fusions, TP8 | 5,191.28 |
| QSA + HybridEP/fusions, TP4 | 2,564.53 |

TP4 was **2.35× faster in this single sequential replay experiment**, with no recompute or OOM fallback. Timing varied substantially, so this is not a repeated steady-state benchmark. QSA alone showed no speedup. **Maximum loss difference versus baseline was 0.008722812 and maximum preclip gradient-norm difference was 28.2429**, exceeding the accepted `1e-5` threshold. Differences start at the first update, including QSA-only; their cause is not yet established. Profiled baseline intervals contain substantial collective activity, but this does not identify a specific module's critical-path cost.

The earlier TP8/GBS8 registered-recipe run remains historical evidence: 100 updates, loss **0.3097828 → 0.2084261**, **7.75 analytical TFLOP/s/GPU**. The original **5,349-step** VL run and its [loss curve/settings](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6354#issuecomment-6160448312) also remain valid: 8,192 prepared image conversations reused cyclically, initial/final loss **0.31087 / 0.01342**, no recorded skipped/nonfinite updates. Gradient spikes remain unexplained. None of these runs establishes held-out generalization, checkpoint reload/export or resume.

Other verification remains scoped:

- **Conversion:** full in-memory language checkpoint import and full VL checkpoint loading passed; persisted checkpoint reload remains unverified.
- **Loaded-weight text pretraining:** ten steps passed on 32 GB200, TP8/EP32, with nonzero sampled optimizer-master changes and no skipped updates.
- **HF/Bridge/native-vLLM forward correlation:** all three pairs pass on the tested 64-token prompt; the 128-token EOS prompt remains below the standard 0.99 cosine gate (last-row cosines **0.986387 / 0.985372 / 0.985446**). Private HF-layer substitutions are diagnostic controls, not production parity fixes.
- The optimization allocation passed all eight exact CLI/finalized configuration variants and focused native model/config/data checks before loading weights. QSA's isolated forward/backward checks passed exactly; this does not resolve the full-model differences.

Current model limits remain **PP=CP=1**, no cached inference/padding masks, activation recomputation, CUDA graphs, FP8 or MTP. The unused selective-recompute extension is excluded from the final change. For a replacement VLM source with `text_only=True`, construct a fresh AutoBridge rather than passing the builder's replacement `hf_path` argument.

Shared supporting fixes include correct MoE counting for hybrid blocks; outer-config sequence length and dictionary vision FLOPs accounting; gated-residual/PLE matrix FLOPs; a reusable `train.sh --setup-script` hook; sanitized non-public RC provenance in verification cards; and offline pinned-tokenizer resolution. Analytical TFLOPS excludes norms, activations, lookups, PLE depthwise convolution, communication and duplicated parallel work; it is not hardware-counter throughput or MFU.

Publication checks: all-files pre-commit, 61 card tests, 59 standalone validator tests, and 21 documentation tests passed. Recipe metadata checks passed 41 cases with one unchanged, previously confirmed Nemotron registry-collision failure. Independent review checked model-source equivalence, recipe settings against the measured configuration, and verification claims. The updated recipe roundtrip test was not rerun in RC4; the card identifies the actual measured source and its override-based execution.
