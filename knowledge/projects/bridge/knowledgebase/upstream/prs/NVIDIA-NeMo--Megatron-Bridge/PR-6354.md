# [models] feat: add Qwen4-Exp hybrid builders and VLM conversion

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6354) · state: open · merged: False

## Original PR description

Qwen4-Exp can now be built through `AutoBridge.get_model_config()` / `get_model()` as a Core HybridModel and converted with its vision tower. `text_only=True` projects a VLM checkpoint into the standalone language namespace, including the LM head, without loading vision tensors.

This takes over Yuchen Wang's #6315 by retaining every original commit and merge exactly and adding the migration on top. Yuchen's Bridge-local QSA, gated residual, PLE and GDN/MoE implementation remains the basis. Casper Hansen's #6123 is credited as the original conversion/model reference; this implementation does not depend on its unmerged Core changes. Neither original PR is modified or closed by this PR.

- Preserve complete attention/MLP blocks, layer indices, both gated residual connections, PLE raw-token inputs and the learned final output mixer inside HybridModel/HybridStack.
- Use declarative nested transformer/model configs and builders. LM/VLM share decoder construction and all language modules; unused legacy aliases/providers and redundant builder overrides are removed.
- Convert the Qwen vision patch embedding, positional embedding, transformer and merger; use multimodal token positions for attention and QSA pooled keys.
- Preserve sharded PLE import/export while accepting native Transformers unsplit PLE tables. Persist text-only selection and propagate authoritative embedding tying to conversion.
- Count the MoE layers inside complete hybrid blocks correctly so standard training metric logging works.

Full language-checkpoint import and ten loaded-weight pretraining steps passed on **32 GB200 GPUs** with `Qwen/Qwen3.8-Flash-Next` in NeMo `26.10.rc4`, using `text_only=True`, real WikiText, and loaded HF language/PLE weights.

| Verification | Status | Evidence |
| --- | --- | --- |
| Conversion / checkpoint loading | Passed: in-memory language import | HF revision `de4b8e4d43b917e7706784d8bb445c9af86a3540`, 48 layers, 2,427 mappings; persisted checkpoint reload remains unverified |
| Forward correlation | Unverified: EOS prompt fails the standard gate | Full-checkpoint HF/Bridge/native-vLLM comparison captured all 48 layers and full-vocabulary logits. All three pairs pass on 64 tokens; on the 128-token EOS prompt, last-row cosines are **0.986387 / 0.985372 / 0.985446** (HF–Bridge / HF–vLLM / Bridge–vLLM), below 0.99 despite matching final argmax |
| Pretraining with loaded weights | Passed: ten steps, clean exit | Pre-clipping gradient norm **16.2381–26.3589**, zero skipped updates, nonzero sampled FP32 optimizer-master changes at every step |

Layerwise private controls with HF GDN, routing, gated residuals, shared experts and matching routed-expert backends reproduce embedding and layers 0–2 exactly for both tested prompts; the first remaining difference is layer 3, the first native QSA attention layer. These diagnostic substitutions are outside this PR and do not constitute a production parity fix.

Verification [card](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/228077d7b63b13d8b3b7f276c78f53c8110c57ac/examples/model_verification_cards/qwen3.8-flash-next/card.yaml). The diagnostic runner is kept outside this PR.

Training configuration: TP8/EP32/expert-TP1/PP1/CP1, sequence length 512, microbatch 1, global batch 4, BF16 parameters/gradient buffers, distributed Adam with FP32 masters and moments, LR `1e-6`, weight decay 0, gradient clipping 1.0. These results support numerical training health; they do not establish convergence, HF forward/backward parity, image-conditioned execution, or performance.

The verification uses `moe_token_dispatcher_type="allgather"`, `moe_permute_fusion=False`, and `moe_shared_expert_overlap=False`. Earlier nonfinite outputs were isolated to the RC4 SPCX variable-split all-to-all transport path: an exact-split raw replay failed with SPCX and passed bitwise with internal IB, consistent with [#5462](https://github.com/NVIDIA-NeMo/Megatron-Bridge/issues/5462). Full-model internal-IB training is not claimed; production dispatcher defaults are unchanged.

All 86 focused model/conversion unit tests and 22 MoE-count/API tests passed in RC4. All-files pre-commit and the final CPU configuration/cache/scheduler checks passed on the publication source. Strict mypy remains non-clean due to untyped Bridge/Core interfaces and training/test annotations. Independent review covered the complete proposed diff and audited the full-checkpoint step records and verification claims.

Existing limits remain PP=CP=1, no cached inference/padding masks, activation recomputation, CUDA graphs, FP8 or MTP. For a replacement VLM source with `text_only=True`, construct a fresh AutoBridge instead of passing the builder's replacement `hf_path` argument.
