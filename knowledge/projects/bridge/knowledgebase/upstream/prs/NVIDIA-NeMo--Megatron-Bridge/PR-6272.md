## Original PR description

# What does this PR do ?

Add `deepseek_v3_pretrain_256gpu_gb300_fp8mx_deterministic_config`: the existing DSv3 256-GPU GB300 MXFP8 perf recipe with the `--deterministic` overrides applied.

> **Stacked on #6271** (base branch `zhiyul/det-reuse-mcore-setup`). This PR's diff is only the recipe commit; it relies on #6271's `apply_determinism_overrides` (Megatron-Core env defaults, aux-loss fusion off). Merge #6271 first; this PR is then retargeted to `main`.

# Changelog

- `perf_recipes/deepseek/gb300/deepseek_v3.py`: new recipe wrapping `deepseek_v3_pretrain_256gpu_gb300_fp8mx_config` and calling `apply_determinism_overrides`. Until the NCCL EP path is deterministic it switches to HybridEP (`TODO: revert back to NCCL EP once the NCCL EP issue is fixed`):
  - `moe_flex_dispatcher_backend = "hybridep"`
  - `moe_use_grouped_tensor = False` (legacy grouped MLP; HybridEP with grouped tensors is untested)
  - HybridEP topology env (`NUM_OF_HYBRID_EP_RANKS_PER_NVLINK_DOMAIN=32`, `NUM_OF_TOKENS_PER_CHUNK_COMBINE_API=128`, `NVLINK_DOMAIN_SIZE=72`, `USE_MNNVL=1`); drops the unused `NCCL_EP_HT_EM_PULL_PUSH`.
  - These match the GB300 recipe before #6171 switched it to NCCL EP and grouped tensors.
- `perf_recipes/deepseek/__init__.py`: export.
- `tests/unit_tests/recipes/test_gb300_ncclep_perf_recipes.py`: the recipe equals the base plus the determinism overrides and the HybridEP settings.

**Verification:** with this configuration, two independent 50-step runs on 256 GB300 GPUs matched on all 550 logged metric values (lm loss, grad norm, MTP loss, …) compared as raw floats. That result also needed two fixes outside this repo, being reported to their owners: a deterministic `dprob` reduction in the cuDNN grouped-GEMM dGLU backward, and a stream-ordering fix for HybridEP non-blocking dispatch/combine. Without them this recipe is configured deterministically but is not yet bitwise reproducible.
