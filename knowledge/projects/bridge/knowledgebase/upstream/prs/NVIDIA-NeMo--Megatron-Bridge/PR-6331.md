# docs(model): save a BERT tokenizer in the megatron-bert README checkpoint step

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6331) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes the published BERT fill-mask example (`inference.sh`) failing with `The tokenizer does not define a mask_token`, by saving a `BertTokenizerFast` in the README's checkpoint step instead of `AutoTokenizer`.

# Changelog

- `examples/models/bert/megatron-bert/README.md`: the checkpoint-normalize step imports and loads `BertTokenizerFast` instead of `AutoTokenizer`.
- `tests/unit_tests/doc_consistency/test_readme_consistency.py`: add `test_megatron_bert_readme_saves_a_bert_tokenizer` (every tokenizer load of `nvidia/megatron-bert-uncased-345m` in the README must use a BERT tokenizer class).

# Additional Information

- Root cause: the Hub repo `nvidia/megatron-bert-uncased-345m` has no `config.json` and its `tokenizer_config.json` sets no `tokenizer_class`, so `AutoTokenizer` returns a tokenizer without `[MASK]`, which the README then saved into the checkpoint.
- Regression: no — broken since BERT support merged (efb58880).
- Verification: new test fails on main, passes with the fix; on H100 `inference.sh` failed before and now prints top-1 `capital` for "Paris is the [MASK] of France.", matching transformers' `MegatronBertForMaskedLM`.
- Pre-existing, unrelated: `test_readme_supported_models_table_lists_every_shipped_model_family` already fails on main.
- QA: NVBug 6882925.
