# perf(recipe): run the VRNVL72 DeepSeek V3 MXFP8 recipes with MLPerf execution settings

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6723) · state: open · merged: False

## Original PR description

# What does this PR do ?

Switches the 256-GPU VR NVL72 DeepSeek-V3 MXFP8 perf recipe and its 64-GPU proxy to the MLPerf DeepSeek-V3 execution settings, keeping the Megatron Bridge benchmark training setup, so the two stacks can be compared on throughput through the existing nemo-ci tests.

# Changelog

- `deepseek_v3_pretrain_256gpu_vrnvl72_fp8mx_config` keeps the training setup of the shared GB300 MXFP8 base: mock data, NullTokenizer, GBS 4096, the LR schedule, forced load balancing, the FP32 router and the auxiliary-loss coefficient. It takes these execution settings from the MLPerf config `config_VR200_64x4x240xtp1pp4ep32cp1_mxfp8_full_cg.sh`:
  - **MoE dispatch:** NCCL EP with GroupedTensor experts (as on `main` since #6373), `moe_flex_dispatcher_num_sms=64`, MLPerf's per-phase `NCCL_EP_*` SM counts, receive capacity factor 4, paged-stash CUDA factor 1.5, router padding for quantization.
  - **Parallelism:** PP=4 × VP=4 over the same `Et*4|(t*4|)*14tmL` layout (was PP=2 × VP=8).
  - **Fusions:** `fused_residual_rmsnorm`, `mla_down_proj_fusion`, `use_fused_mla_kv_rope_quant`, shared expert as grouped GEMM, cuDNN LayerNorm fused with MXFP8 quantization, per-tile swizzle.
  - **Runtime:** optimizer CUDA graph, CUDA graph warmup 2, gloo process groups off, manual GC every 500 steps, no dataloader attention mask.
  - **Environment:** LayerNorm SM margin 0, `NVTE_EXT_MARGIN_SM=16`, `TORCH_NCCL_AVOID_RECORD_STREAMS=1`, `TORCH_DIST_USE_NCCL2=0`, nondeterministic TE kernels allowed.
- `deepseek_v3_pretrain_64gpu_vrnvl72_fp8mx_proxy_config` inherits all of this. It keeps 13 decoder layers, PP=1, EP=32 and GBS 4096, and its environment is identical to the parent's. It does not reproduce the parent's PP=4 × VP=4 schedule: EP=32 with PP=4 would need 128 GPUs.
- Keep the other MXFP8 proxies on `main`'s NCCL EP settings, without the MLPerf-only knobs:
  - `deepseek_v3_pretrain_4gpu_vrnvl72_fp8mx_proxy_config` now builds from the shared MXFP8 base with NCCL EP and grouped tensors, so it still differs from the NVFP4 4-GPU proxy only in quantization.
  - `deepseek_v3_pretrain_64gpu_gb300_fp8mx_proxy_config` still shrinks its NCCL EP GB300 parent. It no longer has to equal the VRNVL72 proxy.
- Not mirrored:
  - MXFP8 token dispatch and combine need NVIDIA/Megatron-LM#7992 to run with 1F1B EP overlap and paged stashing.
  - Megatron Bridge doesn't expose the DataLoader prefetch factor.
- Tests:
  - Add a test that the 256-GPU recipe keeps the GB300 MXFP8 training setup and carries the MLPerf settings.
  - In the proxy tests, the 64-GPU MXFP8 proxy now follows its PP=4 × VP=4 parent, the GB300 proxy no longer has to equal the VRNVL72 proxy, and the 4-GPU MXFP8 proxy resizes the 256-GPU GB300 MXFP8 recipe.
  - Exempt the two recipes from the DeepSeek env invariants for LayerNorm SM margin 20 and deterministic TE kernels.

# Notes

- The nemo-ci tests `deepseek_v3_256gpu_vrnvl72_fp8_mx_v2_perf` and `deepseek_v3_64gpu_vrnvl72_fp8_mx_proxy_perf` will launch these settings unchanged. Their golden values and golden configs need a refresh after the first run.
- With `scripts/performance` and `--data mock`, the launcher rebuilds the dataset config, so `create_attention_mask=False` does not carry over. The GPT-OSS recipes behave the same way.
- `use_fused_mla_kv_rope_quant` needs a Megatron-LM with NVIDIA/Megatron-LM#8144, which the pinned submodule has.
