## Original PR description

## Background

Nightly Megatron-Core main bump (AUT-2633). This pins Bridge `main` to MCore `main` at `ed9c2c8c`, which was selected once for this run. The previous pin was `20527695`. The dev lane is paused, and `.dev.commit` (`4a4de865`) is unchanged.

## What changed

- `.main.commit` and the `3rdparty/Megatron-LM` gitlink move from `20527695` to `ed9c2c8c`. This is a fast-forward of 2 MCore commits: #7047 (dynamic CP integration) and #7780 (GTP scratch lifetime fix).
- `uv.lock` is regenerated with `uv lock --upgrade` (uv 0.7.2). The lock revision stays at 3, and `uv lock --check` passes. Upgrades: cachetools 7.2.5, grpcio/grpcio-tools 1.85.0, hydra-core 1.3.8, multidict 7.2.1, starlette 1.10.0, wcwidth 0.9.4.
- No Bridge source or test changes.

## Details

MCore changes no dependency files between the two pins. Tests were selected from the MCore change (dynamic CP renames, data_schedule, ModelParallelConfig, GTP): Core unit shards 0-2/3, Diffusion unit, L0 pretrain/finetune/qwen3_vl_cp_contract/decentralized_pg/megatron_mimo, L1 nemotronh/gtp_checkpoint_conversion, and L2 llama_cuda_graphs. They ran in a validation image built from this commit with diffusion deps (`sha256:d9af48da`).

## Tested

Local runs on this exact commit, 2x H100 per row:
- 11 passed, 0 skipped_upstream, 1 skipped_platform.
- skipped_platform is Core unit shard 1/3: 4742 passed, 2 failed. The 2 failures are `test_qwen35_vl_122b_h100_pipeline_layout[qwen35_vl_122b_a10b_pretrain_128gpu_h100_{bf16,fp8cs}_config-8-2]`. The test pods are offline: the HF config `Qwen/Qwen3.5-122B-A10B` is not in the test cache, and huggingface.co cannot be reached. A probe in the same image, checkout and mount confirmed both facts. Upstream main CI at `afcc7eee` passed these tests with live HF access. **These 2 tests were not validated locally.**
- Main required CI on this PR: pending.
