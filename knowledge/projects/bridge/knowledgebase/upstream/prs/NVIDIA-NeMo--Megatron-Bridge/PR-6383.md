# refactor(model): build OLMoE and GLM-4.5 from builder-backed model configs

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6383) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Moves **OLMoE** and **GLM-4.5** onto the builder-backed `ModelConfig` / `ModelBuilder` path, for recipes and checkpoint conversion, following Muse Glimmer.

# Changelog

- **Opt-in after #6305**: `MODEL_CONFIG_CLASS` now defaults to `None`, so each migrated bridge sets `MODEL_CONFIG_CLASS = BridgeGPTModelConfig` next to `USE_MODEL_CONFIG_FOR_CONVERSION = True` (as Qwen3 and Llama do), and its tests assert it.
- **`OlMoEBridge`**: `provider_bridge()` is replaced by `hf_config_to_model_config_kwargs()`, and the provider path reuses the same kwargs. The builder config carries the OLMoE layer spec (`transformer_layer_spec=olmoe_layer_spec`), so both paths build `OLMoESelfAttention` with QK layernorm. `USE_MODEL_CONFIG_FOR_CONVERSION = True`.
- **`olmoe_layer_spec`** now also accepts a builder-backed GPT model config, using the builder-side TE layer helper that reads `config.transformer`. Previously it called the provider's `default_layer_spec`, which reads provider-only fields (`use_transformer_engine_full_layer_spec`, `dense_grouped_gemm`) and fails on a builder config. The provider path is unchanged.
- **`GLM45Bridge`**: same kwargs migration. The builder config leaves `transformer_layer_spec` unset because MCore's builder default for MoE models is already `get_gpt_decoder_block_spec`, which honors the dense-first `moe_layer_freq`. The deprecated provider path keeps its explicit decoder block spec in `hf_config_to_provider_kwargs()`. `USE_MODEL_CONFIG_FOR_CONVERSION = True`.
- **Recipes**: all six GLM-4.5 H100 recipes use `get_model_config()`. OLMoE recipes construct `OlMoEModelProvider` directly and are unchanged.
- **Tests**:
  - Builder mapping, provider/builder parity, and an OLMoE layer-spec equivalence check between provider and builder config.
  - GLM-4.5 recipe fakes provide `get_model_config()`.
  - A strict recipe test runs every GLM-4.5 recipe against a real `BridgeGPTModelConfig` at the real model depth (46/92 layers).
