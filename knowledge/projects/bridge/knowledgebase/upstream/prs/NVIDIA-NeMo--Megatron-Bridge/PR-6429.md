# feat(kimi): add early Kimi K3 pretraining recipe

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6429) · state: open · merged: False

## Original PR description

Kimi K3 has native model and checkpoint-conversion support but no library pretraining recipe. Add `kimi_k3_pretrain_config`, documented as **early, perf not optimized**, and export it for the standard `scripts/training/run_recipe.py` entry point.

**Unsupported parallelism:** Context parallelism (CP > 1) and virtual pipeline parallelism (VPP) are not supported by the current Kimi K3 implementation. Keep `context_parallel_size=1` and `virtual_pipeline_model_parallel_size=None`; the model rejects CP > 1 and any non-`None` VPP setting.

The recipe uses 512 GB200 GPUs with TP4/PP4/EP128, a 24/23/23/23 pipeline split, BF16, full activation recomputation, distributed Adam, 8K sequences, and global batch 128. Real K3-tokenized indexed RP2 and HF checkpoint initialization are supplied through standard runner overrides. The learning-rate schedule retains its full warmup/decay horizon when the trial is shortened.

The recipe includes the explicit K3 tokenizer vocabulary path and previously checked transport/FLA forward controls. These controls preserve kernel arithmetic; they do not claim to repair underlying runtime libraries or optimize performance. Tokenizer initialization now preserves explicit options when training validation reruns its initialization method; absent deprecated kwargs previously reset `trust_remote_code=True` to false. Regression tests cover validation reentry and direct/legacy option precedence. The README provides the standard launch command and measured validation limits.

Validation:

- All repository pre-commit hooks passed. Six focused recipe/tokenizer tests passed in the cluster runtime.
- **8K:** the standard runner completed a ten-step real-RP2 trial with all 512 ranks successful and finite loss/gradients. A later longer 8K full-recompute run completed 241 finite iterations before a backward CUDA OOM. The 8K default is not qualified for sustained training.
- **4K full recompute:** TP4/PP4/EP128, full/uniform/1, GBS128/MBS1 completed 929 consecutive iterations in 3h14m31s. All 512 ranks exited successfully. Loss averaged 1.576 over the first 20 steps and 0.491 over the final 20. Mean throughput after five startup steps was 54.8 model TFLOP/s/GPU; maximum PyTorch peak allocation/reservation across ranks was 150.6/154.8 GiB.
- **4K selective recompute:** TP8/PP8/EP64, selective `[moe]`, GBS128/MBS1 completed 626 consecutive iterations in 3h14m57s. All 512 ranks exited successfully. Loss averaged 1.576 over the first 20 steps and 0.802 over the final 20. Mean throughput after five startup steps was 36.4 model TFLOP/s/GPU; maximum PyTorch peak allocation/reservation across ranks was 140.6/144.7 GiB.
- Both long 4K runs used 512 GB200 GPUs, CP1, no VPP and no MTP. All steps had finite positive loss/gradient norms, zero skipped/NaN iterations, and all rank memory records reported zero CUDA OOMs. The saved configurations, clean duration exits, all-rank records, and eight NVLink blocks of 16 nodes were checked. PyTorch memory figures exclude allocations outside its allocator.
- Selective validation used runner overrides for sequence length 4096, TP8/PP8/EP64, first pipeline stage 9 layers and the remaining seven stages 12 layers each, selective `[moe]` with recompute method/layer count unset, and disabled MoE permutation fusion. Initial distributed timeout was 30 minutes, restored to 600 seconds after the first iteration. Both 4K launches used expandable CUDA allocator segments. The recipe defaults remain 8K/TP4/PP4/EP128/full recomputation.
- Independent code and saved-result reviews passed for the original short trial. Earlier faithful tiny training and full-model frozen-forward checks also passed. The new selective result passed the saved launcher verifier and a local replay against the collected artifacts.

These results qualify finite training through the tested durations. The prepared RP2 corpus repeats; loss reduction does not establish generalization or independent full-model loss agreement. Checkpoint saving was disabled, so save/resume correctness remains unqualified. The selective configuration uses less peak PyTorch memory but has lower measured throughput than the tested full-recompute configuration; TP/PP/EP also differ. Keep the recipe labeled **early, perf not optimized**.
