## Original PR description

# What does this PR do ?

Re-verifies the K-EXAONE-2 card's `manual_forward_pass` item at a public Bridge revision. The item recorded `bridge_commit` 68d7e875d3, which is not in the public repository (`git fetch` → "not our ref"), so its 2026-07-31 result could not be reproduced from the card. Adds a check that verified K-EXAONE-2 items record a reachable revision.

## Why the HF reference applies `swiglu_limits`

- The model config sets `swiglu_limits` = 7.0 on decoder layers 62-77.
- Bridge maps it to `activation_func_clamp_value` (`exaone_moe_provider.py` `_layer_specific_config`).
- Megatron Core clamps SwiGLU on those layers' routed and shared experts (`clamped_swiglu`: gate ≤ L, up ∈ [-L, L]; complete on all expert paths since NVIDIA/Megatron-LM#5940, 2026-08-13).
- transformers' `ExaoneMoe` (5.17) does not read `swiglu_limits`, so an unclamped HF forward diverges on those layers.
- Evidence, same import and Bridge:
  - **Unclamped HF reference:** HF predicts 392 (`"?"`) vs Megatron 2879, so the token does not match (cos 0.998974, max/mean |Δ| 19.5 / 12.46).
  - **Megatron clamp disabled** (diagnostic only): the token matches 392 (cos 0.999996).
  - **HF reference with the same clamp as Megatron Core** (applied to the routed and shared experts of layers 62-77): HF predicts 2879. **That reference is the one this PR's result uses.** It's produced by a memory-bounded HF forward of all 78 layers with the clamp applied; the script is kept with the evidence.
- @cuichenx: please confirm a clamp-aware HF reference is the right baseline for this card. Until transformers supports `swiglu_limits`, an unmodified HF forward cannot match Megatron on this model.

**Blocking: Publish a reproducible producer for the new clamped HF reference**

**Failure:** Starting from the recorded Bridge/HF pins and completing the published GPU import still does not let a reader reproduce this refreshed result. The [card command](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/4fc8a13532f5b5d6059d2974a24f4c6bf708093b/examples/model_verification_cards/k-exaone-2/card.yaml#L113-L133) consumes a pre-existing `hf_logits_korean.pt`, but neither the card nor this changeset supplies its producer or a public generation invocation. The [comparison branch](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/4fc8a13532f5b5d6059d2974a24f4c6bf708093b/examples/conversion/compare_hf_and_megatron/compare.py#L977-L987) skips HF model loading when that argument is supplied, and [_load_hf_reference_logits](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/4fc8a13532f5b5d6059d2974a24f4c6bf708093b/examples/conversion/compare_hf_and_megatron/compare.py#L734-L756) only calls `torch.load`: without the verifier's private artifact, this reaches `FileNotFoundError`. Removing the argument is not equivalent—the new result explicitly depends on a modified, clamp-aware HF forward. A public Bridge pin therefore does not make the refreshed comparison reconstructible.

**Correction:** Publish a sanitized, maintained reference producer and document its exact portable invocation as a prerequisite of `manual_forward_pass`. It must use the recorded immutable HF revision, Korean prompt, BF16 workload, and all 78 decoder layers, then write the `input_ids` and final-position `logits` consumed by the existing loader. Keep private execution wiring and evidence blobs out of the card. The producer's implementation is unavailable here, so I cannot safely supply its replacement code. If it cannot be made publicly reconstructible, leave this refreshed item unverified, remove its verified-only commit override/date, and synchronize the index, summary, and generated catalog rather than presenting the command as reproducible verification.

**Preservation:** Preserve an independent HF-weight-derived reference—not Megatron-derived logits. Apply the stated clamp to both routed and shared experts in layers 62–77: gate has only an upper bound of 7, while up is bounded on both sides. Earlier/unlimited layers and unrelated dense/MTP paths must remain unchanged. This agrees with the [provider's config-driven layer selection](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/4fc8a13532f5b5d6059d2974a24f4c6bf708093b/src/megatron/bridge/models/exaone/exaone_moe/exaone_moe_provider.py#L69-L90); do not blanket-clamp every HF MLP or disable Megatron's configured clamp to match stock Transformers.

**Acceptance — proposed, not executed:** From an empty reference-output directory, the documented producer must create an artifact accepted by the existing loader for exactly the published prompt IDs. Add a tiny expert fixture checking routed and shared experts at layers 62 and 77: gate/up values `[-8, 8]` must yield `silu([-8, 7]) * [-7, 7]`; layer 61 and unlimited dense/MTP paths must retain their original output. Retain the existing loader test's assertion that different IDs raise `ValueError`. Finally, regenerate the full-model reference and rerun the recorded comparison: next token 2879 must match and cosine similarity must be at least 0.99; record max/mean differences as diagnostics, not pass/fail thresholds. The author must verify the producer and these checks before adopting the correction.
