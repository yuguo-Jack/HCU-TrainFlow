# fix(training): preserve independent MFSDP v2 sharding policies

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6200) · state: closed · merged: False

## Original PR description

# What does this PR do?

Preserve explicitly configured MFSDP v2 sharding policies instead of overwriting non-expert inner sharding with `optim_grads_params`. For example, DeepSeek V3 MLPerf requests non-expert inner `optim_grads`, expert inner `optim_grads_params`, and `optim` on both outer axes; validation now keeps that combination intact.

# Changelog

- Remove the forced non-expert ZeRO-3 override; retain the dedicated v2 optimizer settings and existing unsupported-feature guards.
- Add configuration tests for independent expert/non-expert policies and inheritance of unset expert policies.
- Document the 256-GPU/EP64 layout: non-expert `(outer=4, inner=64)` and expert `(outer=4, inner=1)` meshes.

# Dependency

Requires the companion MCore adapter fix https://github.com/NVIDIA/Megatron-LM/pull/7728, which depends on DBuffer support in https://github.com/NVIDIA/Megatron-LM/pull/7633. The adapter PR removes the v2 ZeRO-3-only guard; the DBuffer PR gathers replicated model weights from optimizer shards across both axes. This PR does not change the MCore submodule pin.

# Validation

- 15 FSDP configuration tests passed in `tests/unit_tests/training/test_config.py`.
- Both v1 and v2 full BF16 MLPerf configuration dry runs preserved all four requested sharding policies with the patched MCore sources.
- `uv run pre-commit run --all-files`: passed.
- Before the MCore split, with combined MCore #7633 and cleanup #7662, the 0.3B DeepSeek V3 MLA/MoE proxy completed 20 steps on eight EOS H100s for both dense `(2,4)` / expert `(2,2)` and dense `(4,2)` / expert `(4,1)` meshes. Both runs preserved all four requested policies, used BF16 with training/optimizer CUDA graphs, and had no skipped or NaN iterations. Loss fell from `10.58813` to `5.40518` / `5.405465`. Runtime: PyTorch `2.14.0a0+4fdf77b940.nv26.08`, Transformer Engine `2.19.0+5e52befd`.

The companion MCore change passed the eight-GPU DBuffer suite, FP32/BF16 optimizer reconstruction checks, and all 39 adapter tests per rank. Full 256-GPU training remains unverified. FP8 and checkpointing remain unsupported by this Bridge v2 path.
