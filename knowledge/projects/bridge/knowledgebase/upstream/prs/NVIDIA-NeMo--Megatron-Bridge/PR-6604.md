[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6604) · state: closed · merged: True

## Original PR description

# What does this PR do?

Port the final GB300/VRNVL72 MXFP8 proxy changes from #6603 to `r0.7.0`, based on release commit `21232e023a7d1a78972da5235ddb532fd0241da2`. This contains the combined scope of source commits `f74e957458dc0876e660d0276a1b759ab3fbbc40` and `2ee89c62a3e416cccb7e68d10c7a7bca29e30046`, not a merge of `main`.

# Changelog

- Export `deepseek_v3_pretrain_64gpu_gb300_fp8mx_proxy_config`, selectable with `--gpu gb300 --compute_dtype fp8_mx --num_gpus 64 --config_variant proxy`.
- Match the existing 64-GPU VRNVL72 MXFP8 proxy: 3 dense + 10 MoE decoder layers, 1 additional MTP layer, PP=1 with no VPP or interleaved layout, TP=CP=ETP=1, EP=32, GBS=4096 and MBS=1. Dense DP=64, expert DP=2, and 64 microbatches per iteration.
- Use the shared HybridEP base, full-iteration CUDA graphs, cuTeDSL and combined-1F1B MoE overlap, without the production GB300 recipe's NCCL EP/grouped-tensor overrides.
- Match HybridEP runtime settings: 32 ranks per NVLink domain, 128-token combine chunks, NVLink domain size 72 and MNNVL enabled.
- Set `NVTE_ALLOW_NONDETERMINISTIC_ALGO=1` in both 64-GPU MXFP8 proxies to allow the fused SwiGLU scale-gradient atomic reduction. The existing VRNVL72 proxy changes from zero to one; its baseline must be rerun for matched comparisons.
- Include configuration/environment parity, overlap and selector tests, environment invariants, and usage documentation. Adapt test parameterization to the release branch, which does not have the main-only 4-GPU proxies.

# Validation

- Passed: `uv run pre-commit run --all-files` and `git diff --check`.
- Passed: source-level checks that both changed recipe functions match #6603 exactly and every other existing GB300/VRNVL72 recipe function is unchanged from the release base.
- Passed: dependency-isolated execution of the actual proxy bodies, pipeline-layout helper and new parity test with a stubbed shared base; the actual environment-invariant test for both changed builders; export check. These checks do not validate full recipe construction or GPU runtime behavior.
- Blocked locally: `uv run python -m pytest tests/unit_tests/recipes/test_deepseek_v3_proxy_recipes.py tests/unit_tests/recipes/test_perf_recipe_environment.py -q` fails during conftest import with `ModuleNotFoundError: No module named 'torch'`.
- No GPU jobs were launched. Memory fit, capture/replay and steady-state performance remain unverified on the release runtime. This reduced-depth proxy does not establish at-scale throughput or convergence.

# Release scope and approval

- Blast radius: one new opt-in GB300 proxy, one kernel-policy change to the existing 64-GPU VRNVL72 MXFP8 proxy, package export, tests and documentation. Existing 256-GPU recipes and NVFP4 proxies remain unchanged. No dependency pins, CI workflows or nemo-ci definitions change.
- No existing public signature or default production recipe changes. The VRNVL72 proxy no longer requests bit-exact TE kernels, so numerical reproducibility and performance can change for callers of that specific proxy.
- This adds an opt-in recipe under package source; it is not presented as a fixes-only exception. Any release-freeze exception/cherrypick approval required by the release policy must come from the automation team. No waiver, QA recommendation or completed release validation is claimed here.
- Before merge: run focused tests in the supported environment, validate both proxies on the intended release containers, rerun the VRNVL72 baseline, and obtain required release approval and golden-value updates. No performance results or golden values have been invented or updated in this PR.
