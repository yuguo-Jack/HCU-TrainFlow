# test(model): fix Sarvam MoE and LLaDA-1.5 load tests after builder config retention

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6732) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes the 8 unit tests that fail on `main` because #6645 and #6642 merged four minutes apart and their CI never ran together. This changes only the tests.

# Root cause

- #6645 (`4236d1447`, merged 20:40Z) makes `build_and_load_model()` keep the outer builder `ModelConfig` on every built chunk (`model_chunk.model_config = model_cfg`). That lets a later `save_megatron_model()` rebuild the checkpoint config, and it matches what `AutoBridge.get_model()` already does.
- #6642 (`28d6dcf89`, merged 20:44Z) added `test_load_builds_on_requested_device` for Sarvam MoE and LLaDA-1.5, with 4 parametrizations each. The test stubs the builder's `build_distributed_models()` and returns `[object()]` as the model.
- A bare `object()` cannot take attributes, so on `main` the new assignment raises `AttributeError: 'object' object has no attribute 'model_config'` (`model_load_save.py:446`).
- #6642's last CI ran on 2705e323e (10-26), before #6645 was on `main`. #6645's CI never saw the new tests.

The production code is correct, because real model chunks are `torch.nn.Module`s. The tests' stand-in was too thin.

Each failure needs both commits:

# Changelog

- `tests/unit_tests/models/sarvam/test_sarvam_config.py` and `tests/unit_tests/diffusion/model/llada15/conversion/test_llada15_bridge.py`: the stubbed build returns `[torch.nn.Module()]`, and the test also asserts `result[0].model_config is loaded`. Both families now cover #6645's config retention too. With #6645's hunk reverted, that assertion fails in all 8 cases.
