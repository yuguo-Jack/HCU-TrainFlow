# refactor(model): build Qwen2 and MiMo from builder-backed model configs

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6379) · state: open · merged: False

## Original PR description

# What does this PR do ?

Moves **Qwen2/Qwen2.5** and **MiMo** onto the builder-backed `ModelConfig` / `ModelBuilder` path, for recipes and checkpoint conversion, following Muse Glimmer and #6365 (Qwen3).

**Builds on #6365 (merged).** It reuses #6365's `TransformerConfig` YaRN fields, without which Qwen2.5 YaRN checkpoints could not convert through the builder. Rebased onto `main` after #6365's squash-merge, so the PR now contains only the Qwen2 and MiMo commits.

# Changelog

- **`Qwen2Bridge`**: `provider_bridge()` is replaced by `hf_config_to_model_config_kwargs()`, and the provider path reuses the same kwargs (`hf_config_to_provider_kwargs`). Provider-implied defaults are explicit (`masked_softmax_fusion`, `rope_scaling=False`, `rope_scaling_factor=1.0`, `position_embedding_type` via `setdefault("rope")` so YaRN is preserved). `USE_MODEL_CONFIG_FOR_CONVERSION = True`.
- **`MimoBridge`** (subclasses `Qwen2Bridge`): extends the Qwen2 kwargs with `qk_layernorm=False`, `add_qkv_bias=True`, and MTP depth (`mtp_num_layers`, `mtp_loss_scaling_factor=0.1`) instead of overriding `provider_bridge()`. It inherits the conversion flag.
- **Recipes**: all 30 Qwen2/2.5 H100 recipes use `get_model_config()`.
- **Tests**:
  - New `test_qwen2_bridge.py`; Qwen2 had no bridge unit tests. It covers the direct builder mapping, provider/builder parity (tied, fp16, YaRN), and the YaRN transformer fields plus HF export.
  - A strict recipe test runs every Qwen2/2.5 recipe against a real `BridgeGPTModelConfig`.
  - MiMo tests cover the builder MTP mapping and provider parity.
