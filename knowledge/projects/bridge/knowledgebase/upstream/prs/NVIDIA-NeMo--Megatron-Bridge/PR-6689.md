# fix(ckpt): make DeepSeek-V4 convert.sh export and PP > 1 conversion work

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6689) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes two DeepSeek-V4 failures in the conversion launcher (`scripts/conversion/convert.sh`, `gpu_backend.py`) that
reproduce on `main`, and makes export restore pipeline layouts from builder-backed checkpoints.

1. **`convert.sh export` failed in finalize** with `AssertionError: v_head_dim must be greater than
   qk_pos_emb_head_dim`. Export rebuilds the Hugging Face config from the checkpoint
   (`AutoBridge.from_auto_config`). The generic mapping exported `partial_rotary_factor` from `rotary_percent`, which
   the DeepSeek-V4 import pins to 1.0. Native Transformers `DeepseekV4Config` derives
   `qk_rope_head_dim = head_dim * partial_rotary_factor` (and ignores a `qk_rope_head_dim` argument), so the rebuilt
   config had `qk_rope_head_dim = 512`, and the re-import set `qk_pos_emb_head_dim = v_head_dim = 512`.
   (`head_dim` itself round-tripped: `kv_channels` is 512 in the saved config.)
2. **`convert.sh import` with PP > 1 failed** with `Number of decoder layers 4 must match num_layers 8`. The launcher
   used `DeepSeekV4Bridge.generate_pipeline_layout`, a GPT-style layout with one decoder entry per logical layer, but
   the hybrid model has an attention and a MoE layer per logical layer, and MCore's `HybridModel` takes its stage
   boundaries from the `|` segments of `hybrid_layer_pattern`. MCore also requires every hash-routed MoE layer on the
   embedding stage, so an even split is not always valid either (the four-layer truncated Flash model has three hash
   layers: PP=2 needs `3|1`, not `2|2`).
3. **Builder-backed checkpoints** save `pipeline_model_parallel_layout`, `pipeline_model_parallel_size` and
   `mtp_num_layers` under `model.transformer` in `run_config.yaml`, but export read them only from the top level of
   `model`, so it never restored or rebalanced their saved layout. Exports at the saved PP still worked, but an
   export at another PP that does not divide the layer count failed in MCore's divisibility assertion.

# Changelog

- `DeepSeekV4Bridge.megatron_to_hf_config`: export `head_dim` from `v_head_dim` and the `partial_rotary_factor` that
  reproduces `qk_pos_emb_head_dim`. Leave `max_position_embeddings`, the router aux-loss coefficient and `rope_theta`
  to the reference config (import replaces the first two with training settings, and the export keeps the reference
  RoPE parameters), as GLM-5 already does for `max_position_embeddings` (#5996). The rebuilt config now serializes
  exactly like the source config.
- `DeepSeekV4Bridge.configure_pipeline_layout` replaces the GPT-style `generate_pipeline_layout`; it applies
  `set_deepseek_v4_pipeline_model_parallel_layout`, the segmentation the recipes use. `scripts/conversion/utils.py`
  prefers this in-place hook when a bridge has it (import, export and round trip; GPU and CPU backends).
- `set_deepseek_v4_pipeline_model_parallel_layout`: the default split grows the embedding stage when an even split
  would leave hash-routed MoE layers behind. It is unchanged whenever the even split is already valid (all current
  recipe topologies), and explicit `logical_layers_per_stage` is untouched.
- `gpu_backend.export_checkpoint`: `load_megatron_model` strips the checkpoint's `|` segments, so export passes the
  segments that match its pipeline layout; restoring a checkpoint's saved layout also restores the segments saved with
  it.
- `gpu_backend._maybe_restore_pipeline_layout`: read the pipeline fields nested under `model.transformer` for
  builder-backed checkpoints.

# Validation

  config cut to four layers plus MTP (legacy key names, native `DeepseekV4Config`) rebuilds a config whose JSON equals
  the reference's, and re-importing it gives `v_head_dim=512`, `qk_pos_emb_head_dim=64`. This runs on the provider path,
  and also on the builder path once DeepSeek-V4 has a model config (it ran there on the merged migration tree).
- `tests/unit_tests/recipes/test_deepseek_v4_pipeline_layout.py`: default splits checked against MCore's own
  hash-MoE placement check (`_validate_hash_moe_pipeline_placement`), including four layers at PP=2 (`3|1`) and 43

# Notes

- `DeepSeekV4Bridge.generate_pipeline_layout` is removed. Since the bridge builds the native `HybridModel` (#5860),
  its GPT-style layout fails MCore's validation for every PP > 1, and the conversion launcher was its only caller.
- DeepSeek-V4 conversion moves to `DeepSeekV4ModelConfig` (builder) in a pending migration. This branch merges
  cleanly with it, and the unit and GPU checks above also ran on that merged tree (builder path).
- #6248 (open) adds a training-runner layout hook for the DeepSeek-V4 provider that reuses
  `set_deepseek_v4_pipeline_model_parallel_layout`; it does not touch the conversion launcher.
- #5360 (stale draft) also edits `DeepSeekV4Bridge.megatron_to_hf_config`: it drops `partial_rotary_factor` so the
  reference supplies it, and recomputes `max_position_embeddings` from `rope_scaling`, which the generic export does
  not fill for MLA providers, so the value would stay at `seq_length`. This PR derives the factor from the checkpoint's
  MLA dimensions and leaves `max_position_embeddings` to the reference. The rest of #5360 (model card, MTP and indexer
  export mappings, recipes) is independent of this change.
