# [model] fix: forward provider pipeline rank to MTP specs

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6406) · state: open · merged: False

## Original PR description

With a `GPTModelProvider`, `mtp_num_layers > 0`, and `dist.use_decentralized_pg=True`, model construction reaches MCore's global pipeline-rank fallback even though Bridge has already supplied the provider's process-group collection. The global MPU pipeline group is unset in that mode, so MTP spec construction fails before training starts.

Forward the rank from the provider's pipeline group to the final `get_gpt_mtp_block_spec` call. This completes the Bridge caller migration started in #5752: its decoder callable receives `pp_rank`, but the final MTP helper still omitted it. Calls without a provider process-group collection retain their existing fallback. There are no public signature, dependency, or submodule changes.

The supported path is Bridge pretrain/setup → decentralized initialization → `ModelProviderMixin.get_model` → `GPTModelProvider.provide` → `mtp_block_spec`. This change is scoped to that provider path; it does not claim validation of all decentralized distributed training combinations.

Validation uses Bridge base `9166429859ed9a29860ca2e1f3fc317173df8c0e` and its exact MCore pin `8949def81eb744b9219e2d794c80265928c40a5b`. MCore discovery base was `b86e75c184483a54689d17b1a9eb6c5bcc999425`; a later default-branch recheck observed `6a6c8aa6e9ee258db08bed381e882c0f754d14bc`, which does not change the pinned test dependency.

The test calls the real pinned MCore spec builder; it covers PP=1 and both PP=2 ranks.
