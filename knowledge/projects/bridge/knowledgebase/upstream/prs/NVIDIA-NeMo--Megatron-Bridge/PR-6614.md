# perf(recipe): add Nemotron 3.5 Super VL 64-GPU GB300 MXFP8 pretrain recipe

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6614) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Add nemotron_35_super_vl_pretrain_64gpu_gb300_fp8mx_config. It starts from the 64-GPU GB200 BF16 recipe and changes the execution and the arithmetic precision to the fastest of eight configurations measured on 16 GB300 nodes (64 GPUs, one NVL72 domain):

- tensor parallelism 1, sequence parallelism off (expert parallelism only)
- MXFP8 (bf16_with_mxfp8_mixed) with router padding for quantization
- Transformer Engine op fuser with the CuTe DSL fused grouped MLP
- NCCL EP (eager, dropless) instead of HybridEP, with MXFP8 on the dispatch-forward and combine-backward wire
- environment: NVTE_CUTEDSL_FUSED_GROUPED_MLP=1, NCCL_EP_HT_EM_PULL_PUSH=1 (eager NCCL EP at EP64 is not expected to fit without it) and NVTE_FLASH_ATTN_V4=0; the four HybridEP variables are dropped because the NCCL EP backend does not read them

Data, objective, optimizer, schedule, batch shape (sequence 8192, micro batch 1, global batch 512), natural routing, scoped CUDA graphs, FP32 optimizer state and FP32 gradient reduction are inherited unchanged.

Measured with text-only mock data (steps 21-60, median): 946.2 TFLOP/s per GPU (5,868 ms/step), against 611.0 TFLOP/s per GPU (9,088 ms/step) for the GB200 BF16 recipe on the same mock data in an earlier allocation. MXFP8 compute and the quantized wire change the numerics; there is no convergence evidence on real data, and throughput and memory were not measured with image or padded data.

Register the gb300 package in the nemotron_omni compatibility aliases and add unit tests that pin the recipe as the GB200 BF16 recipe plus exactly these overrides.
