# [ckpt] fix: accept iteration-zero legacy checkpoint trackers

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6629) · state: open · merged: False

## Original PR description

A native Megatron checkpoint root whose `latest_checkpointed_iteration.txt` contains `0` fails during pretrained initialization with `AssertionError: error parsing metadata file`. Bridge's fallback reader requires a positive iteration even though Core accepts iteration zero and Bridge's resolver treats nonnegative iterations as valid.

Allow zero in the legacy metadata reader. Add resolver-level tests with real tracker files for zero, positive, release, negative and malformed values. Release behavior and invalid-input rejection stay intact. This affects legacy roots without `latest_train_state.pt`; passing a direct iteration directory already bypasses the reader.

Supported path: `checkpoint.pretrained_checkpoint` → `load_checkpoint` / PEFT setup → `_load_checkpoint_from_path` → `_load_base_checkpoint` → `_resolve_checkpoint_iteration` → `read_metadata`. See [checkpoint initialization documentation](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/7e825224f9a955aa11230e42aef115422cea05e7/docs/training/checkpointing.md#L114-L120).

Upstream context: [Core #2199](https://github.com/NVIDIA/Megatron-LM/pull/2199) and [#2351](https://github.com/NVIDIA/Megatron-LM/pull/2351). Related merged Bridge [#2624](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/2624) adds direct-directory loading; [#5803](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/5803) handles release retention. Neither fixes this legacy-root assertion. Refreshed all-state searches found no exact open Bridge fix.
