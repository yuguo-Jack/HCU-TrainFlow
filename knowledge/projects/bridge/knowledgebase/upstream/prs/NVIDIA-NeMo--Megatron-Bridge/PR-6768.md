# feat(quant): export quantized QKVGMapping weights through ModelOpt

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6768) · state: closed · merged: False

## Original PR description

# What does this PR do ?

`save_hf_pretrained_modelopt` can now export quantized weights that a bridge maps with `QKVGMapping`, which fuses Q, K, V and a per-head scalar gate (`g_proj`) into Megatron's `linear_qkv`. Step 3.5 and Step 3.7 use it for every attention layer. Until now any quantized weight under this mapping failed at every parallelism:

```
ModelOpt export metadata capture failed: NotImplementedError: ModelOpt real-quant export does not support QKVGMapping topology
```

**Stacked on #6767** (the base branch of this PR): both change the QKV branch of `_transform_source_state`. This PR's own change is the last commit.

# Changelog

- `QKVGMapping` reuses `QKVMapping`'s attention layout and tensor-parallel type. The rows of the gathered ModelOpt state for `q_proj`, `k_proj`, `v_proj` and `g_proj` are selected with the same `split_qkvg_weights` the mapping applies to the weight, in both of its layouts:
  - gate rows after the interleaved QKV block (Megatron-Core with native head-wise gates);
  - `attention_output_gate`, where each head's gate row is repeated across the head dimension; the gate takes one row per head, as the weight conversion does. This is the layout Step 3.5 uses with the pinned Megatron-Core.
- A `QKVGMapping` subclass that overrides `megatron_to_hf`, such as Beam's `BeamQKVGateMapping` (full-width gate), is rejected, as custom `QKVMapping` / `ConcatenatedQKVMapping` row layouts are.

# Tests

- `tests/unit_tests/models/test_modelopt_utils.py`: 112 passed, 13 of them new.
  - FP8 with per-row scales and NVFP4, at TP 1 and 2, in both gate layouts: each exported `q` / `k` / `v` / `g` weight and its scales are bit-identical to ModelOpt's packing of the same Hugging Face weight.
  - Custom row layouts are rejected for `ConcatenatedQKVMapping` and `QKVGMapping`, including `BeamQKVGateMapping`.
  - 10 of the 13 fail without this change.
- `tests/functional_tests/test_groups/quantization/test_modelopt_hf_export.py`: new toy dense Step 3.5 case (NVFP4, `attention_output_gate` layout): the TP=2 export is bit-identical to the single-GPU export, with `g_proj` packed as NVFP4. It fails without this change. All 7 cases passed.
- Dequantizing the toy's exported NVFP4 `g_proj`, `q_proj` and `k_proj` gives the source weights to within NVFP4 error (cosine similarity 0.995).
- Ran on 2× RTX 6000 Ada in `nvcr.io/nvidian/nemo:26.10.rc9` with `nvidia-modelopt==0.48.0rc1` and the pinned Megatron-LM.

ModelOpt's own Megatron exporter does not support Step 3.5, so there is no reference checkpoint to compare with. vLLM builds Step 3.5's `g_proj` as a `ColumnParallelLinear` with the model's `quant_config`, so it takes a quantized gate; no vLLM run yet.
