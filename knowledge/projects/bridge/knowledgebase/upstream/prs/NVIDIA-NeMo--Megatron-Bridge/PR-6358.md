# fix(data): reject structured conversations in selected chat-named columns

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6358) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes prompt-completion SFT silently training the canonical `prompt`/`completion` pair when the selected chat-named prompt column (e.g. `messages`) holds a structured conversation, by excluding a selected column from chat-key inference only when it holds paired text.

# Changelog

- `src/megatron/bridge/data/sft_processing.py`: `normalize_sft_example` excludes a selected prompt/completion column from chat-key inference only when its value is a `str`.
- `tests/unit_tests/data/test_sft_processing.py`: 2 tests for a structured conversation in a selected chat-named column, with and without a canonical pair.

# Additional Information

- **Root cause:** `sft_processing.py:198` (#5713) dropped the selected columns from `conversation_keys` whatever their value. As a result, a structured `messages` skipped the "exactly one schema" guard and fell through to the canonical-pair fallback.
- **Contract:** #5713 states "genuine structured conversations remain rejected by prompt/completion preprocessing". This restores that, and string chat-named columns still train.
- **Regression?** Yes, introduced by 51fde10c (#5713). Before it, the same row raised "SFT rows must select exactly one schema".
- **Verification:** red-green in `nvcr.io/nvidian/nemo:26.10.rc4` on main 1b26bcb7. RED: 2 failed (DID NOT RAISE; wrong error). GREEN: 2 passed, and `tests/unit_tests/data/` passed 965.
- **Not included:** the native HF adapter drops a second populated chat key (`conversations`) when `messages` is set. That is pre-existing adapter behaviour and is left to dev.
- NVBug 6648569.
