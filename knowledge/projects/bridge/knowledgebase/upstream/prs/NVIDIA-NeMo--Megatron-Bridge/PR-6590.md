# feat(data): load direct-HF SFT rows lazily from the memory-mapped dataset

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6590) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Adds `DirectHFSFTDatasetConfig.lazy_examples`. It keeps a direct-HF SFT split as its memory-mapped Hugging Face dataset and adapts and normalizes each row when the dataset reads it, instead of holding every row as Python objects in every rank.

## Why

`DirectSFTDataset` stores the adapted, normalized rows as a `list[dict]`, built separately in each rank. For large chat-SFT jsonl files this dominates host memory:
- On a Qwen3.6-35B-A3B QAD run (4 ranks per node), a 4 GB chat jsonl peaked at **152 GB RSS per rank**.
- The 2.2M-row (40 GB) GLM-5.3-Flash set could not be loaded at all.
- Both runs had to write a per-job slice of the rows before each job (an out-of-tree "window" script that reproduces the `idx % len` wrap).

The loaded (non-streaming) HF dataset that the rows come from is already memory-mapped Arrow. Its pages sit in the page cache, which every rank on a node shares.

# Changelog

- **`LazyAdaptedHFDataset`** (`sources/hf_adapters.py`): a `Sequence` over a loaded HF dataset.
  - At construction it makes one pass, keeping an `array('q')` of the row indices the schema adapter keeps.
  - The pass also raises on a malformed row at load time, as the eager path does.
  - `__getitem__` re-runs the adapter and an optional transform on `dataset[index]`.
- **`load_and_adapt_hf_dataset_lazily`** (`sources/hf.py`): the lazy counterpart of `load_and_adapt_hf_dataset`. It requires an indexable `datasets.Dataset`, not a streaming one.
- **`lazy_examples: bool = False`** on `DirectHFSFTDatasetConfig`:
  - Applies to the training split and the validation/test splits through `load_direct_hf_sft_examples_lazily` (normalization via `normalize_sft_example`).
  - Rejected for blended training sources (several sources or `source_weights`); blending still materializes rows.
- **`DirectSFTDataset`** accepts any non-empty `Sequence`, not only a `list`.

The default is unchanged: eager loading, same API. Collate selection works unchanged; it iterates the sequence, which costs one more pass at build time.

## Measurement

200,000 chat rows (1.56 GB jsonl), loaded through `load_direct_hf_sft_examples(_lazily)`, private memory (RSS minus file-backed pages) over the import baseline:

| | private memory | RSS |
| --- | --- | --- |
| eager | +1.87 GB | 3.39 GB |
| lazy | +0.00 GB (indices only) | 3.06 GB (mostly shared Arrow pages) |

Eager memory grows with the number of rows and their Python string overhead; lazy keeps 8 bytes per row.

## Testing

`nvcr.io/nvidian/nemo:26.10.rc3`, `PYTHONPATH=src`:
- `pytest tests/unit_tests/data`: 1093 passed, 1 skipped.
- New tests:
  - lazy vs eager builder output for the same rows, including `idx % len` wrap-around and collation;
  - adapter-dropped rows are skipped with indices matching `adapt_hf_dataset`;
  - slice and negative indexing;
  - empty sources raise;
  - lazy with a blend is rejected.

Not run: a multi-rank training job with `lazy_examples=True`.

## Usage

```python
DirectHFSFTDatasetConfig(
    seq_length=32768,
    source=HFDatasetSourceConfig(path_or_dataset="json", split="train", load_kwargs={"data_files": "train.jsonl"}),
    enable_in_batch_packing=True,
    dataloader_type="single",
    lazy_examples=True,
)
```
