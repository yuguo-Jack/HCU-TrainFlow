# perf(recipe): default GB200 MoE perf recipes to NCCL EP and grouped tensors

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6373) · state: open · merged: False

## Original PR description

# What does this PR do ?

This PR moves selected GB200 MoE perf recipes to the NCCL EP flex dispatcher, with `moe_use_grouped_tensor=True`. It follows #6171 (GB300) and #6261 (GPT-OSS 120B GB200 MXFP8).

# Changelog

- The following 18 GB200 recipes now call `_enable_ncclep` and set `moe_use_grouped_tensor=True`. Their inline environment sets `NCCL_EP_HT_EM_PULL_PUSH=1` and drops the HybridEP topology names. Parallelism, precision, recompute, CUDA graph mode and comm overlap are unchanged.

  | Family | Recipes | Previous dispatcher |
  |---|---|---|
  | DeepSeek V3, 256 GPUs | BF16, MXFP8, NVFP4, MXFP8 large-scale | HybridEP |
  | DeepSeek V4 Flash, 128 GPUs | MXFP8 | HybridEP |
  | GPT-OSS 120B, 64 GPUs | BF16 | **alltoall** |
  | Nemotron 3 Super, 64 GPUs | BF16, MXFP8, NVFP4 | HybridEP |
  | Nemotron 3 Ultra, 256 GPUs | MXFP8 | HybridEP |
  | Nemotron 3.5 Lightning, 8 GPUs | BF16, MXFP8 | HybridEP |
  | Qwen3 30B-A3B, 8 GPUs | BF16, MXFP8 | HybridEP |
  | Qwen3 235B-A22B, 256 GPUs | BF16, MXFP8, NVFP4, MXFP8 large-scale | HybridEP |

- Each switched recipe applies the NCCL EP overlay itself; none inherits it from a HybridEP sibling. Where a switched recipe and a HybridEP recipe derive from the same parent:
  - DeepSeek V3 NVFP4 builds on a new shared HybridEP base, `_build_deepseek_v3_gb200_bf16`.
  - DeepSeek V4 Flash: the GB300 recipe now builds on the new HybridEP base `_build_deepseek_v4_flash_gb200_fp8mx` instead of the GB200 recipe. GB300, and the VR200 and B300 recipes derived from it, keep HybridEP unchanged.
  - Qwen3 30B-A3B 8-GPU and 32-GPU BF16 share a new HybridEP base, `_build_qwen3_30b_a3b_gb200_bf16`, so only the 8-GPU recipe switches.
  - Nemotron 3.5 Lightning BF16 still derives from the Nemotron 3 Nano BF16 recipe, which stays on HybridEP, and switches explicitly.
  - The MXFP8 large-scale proxies inherit the switch from their 256-GPU MXFP8 recipes; only their environment changes.
- Nemotron 3 Ultra MXFP8 drops a HybridEP rank variable that is no longer used, and its docstring is updated.
- The new `test_gb200_ncclep_perf_recipes.py` checks two things:
  - The full NCCL EP stack on all 19 GB200 NCCL EP recipes, including GPT-OSS MXFP8 from #6261.
  - That 15 GB200 recipes kept on HybridEP don't pick it up. Most of these share a base or parent recipe with a switched one.
- Existing tests that hardcoded HybridEP for the switched recipes are updated:
  - Two tests compare a perf recipe with its GB200 library training recipe: Nemotron 3 Super BF16 and Qwen3 30B MXFP8. The library recipes stay on HybridEP, so these tests now treat NCCL EP as a benchmark-only difference.
  - The Lightning-vs-Nano policy test now allows for the dispatcher environment differing between the two.
  - The DeepSeek V4 Flash GB300 test now also asserts that GB300 stays on HybridEP.

# Scope

- **Switched:** 18 GB200 MoE recipes, all with nemo-ci benchmarks. 16 match GB300 recipes that already run NCCL EP after #6171.
- **Switched without GB300 precedent:**
  - **GPT-OSS 120B BF16** moves from `alltoall`, not HybridEP. Its GB300 counterpart still runs `alltoall`.
    - The recipe keeps EP A2A overlap and `delay_wgrad_compute`, which TE's grouped-tensor `GroupedLinear` supports, and has no op fuser.
    - GPT-OSS experts have biases, so the expert dbias goes through TE's atomic grouped-dbias kernel. That kernel only raises under `NVTE_ALLOW_NONDETERMINISTIC_ALGO=0`, which this recipe does not set.
    - The nemo-ci llmb jobs at 64–512 GPUs all scale this recipe.
  - **DeepSeek V4 Flash MXFP8**: #6171 removed the GB300 switch as unverified, so there is no NCCL EP measurement for DSV4 on either GPU.
    - Its stack is the same one NCCL EP already runs for DeepSeek V3 MXFP8 on GB300: full-iteration CUDA graph, paged stash, capacity factor 1.5 and op fuser.
    - It keeps `moe_flex_dispatcher_num_sms=32`, which now caps the NCCL EP SMs.
- **Intentionally kept on HybridEP in this PR, although their GB300 counterparts switched:**
  - Kimi K2 MXFP8
  - Nemotron 3 Nano BF16/MXFP8
  - Qwen3 30B-A3B 32-GPU BF16
- **Still on HybridEP, matching GB300:** Nemotron 3 Ultra NVFP4.
- **Not touched: GB200 recipes with no nemo-ci benchmark.** These include FP8-CS variants, Qwen3 235B 64-GPU, Qwen3-Next, Qwen3-VL/Qwen3.5-VL, GLM-5, Kimi BF16/FP8-CS, GPT-OSS 20B and the `*_dev` recipes.
- **Deliberately kept on HybridEP:** `deepseek_v3_pretrain_256gpu_gb200_fp8mx_partial_cg_dev_config`. It offloads `expert_fc1` with EP overlap, and MCore rejects that combination under `ncclep`.
- **`NVTE_ALLOW_NONDETERMINISTIC_ALGO=0` stays on the DeepSeek V3 and V4 GB200 recipes.** #6171 removed it on GB300 DeepSeek V3 because TE's op-fuser fused grouped MLP raises under deterministic mode.
  - The GB200 DeepSeek MXFP8/NVFP4 recipes already run that op-fuser path with `=0` today. With the op fuser on, grouped tensors are already enabled, so NCCL EP leaves that path unchanged.
  - DeepSeek V3 BF16 gains `moe_use_grouped_tensor` without the op fuser. TE `GroupedLinear` only uses the atomic `compute_grouped_dbias` kernel when the experts have a bias, and DeepSeek experts have none.
  - Keeping `=0` keeps the A/B down to the dispatcher. If GPU runs do hit the TE determinism error, drop the setting as #6171 did.

# Validation

- `pre-commit run --all-files` passes.
- Local CPU unit tests were run with CPU torch and Megatron-Core at the pinned `441a9874`, using import-only stubs for Triton and TE so recipe construction runs on macOS.
  - Up to the second commit, the changed and new recipe tests plus related recipe test files gave 453 passed.
    - 35 failed for environmental reasons. These tests build configs without the offline fixture, and the sandbox blocks fetching the HF model configs.
    - The failing cases include GB300, B200/B300 and VR200 recipes that this PR does not touch.
  - For the third commit, the affected files pass: 94 tests across the GB200 NCCL EP test, the DeepSeek V4 Flash tests, the environment invariants and the GB300 NCCL EP test.
- MCore `TransformerConfig.finalize()` accepts the NCCL EP DeepSeek V4 Flash GB200 config.
  - The real GPT-OSS 120B provider needs the HF config, which could not be fetched locally. Its NCCL EP, A2A-overlap and grouped-tensor requirements were checked against MCore's validation statically.
- The functional test `test_perf_config_integration.py` was updated but not run.
- **No GPU validation yet.** There are no GB200 step-time, memory or loss numbers for these recipes on NCCL EP.
