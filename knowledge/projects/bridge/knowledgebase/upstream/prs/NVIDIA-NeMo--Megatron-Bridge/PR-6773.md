# fix(recipe): disable HybridEP permute fusion in Qwen3.5-VL GB200 functional recipes

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6773) · state: open · merged: False

## Original PR description

# What does this PR do ?

Fixes Qwen3.5/3.6-VL 35B-A3B GB200 SFT failing in the first MoE forward (`Fuse mode requires identical chunk sizes: dispatch=64, combine=128, preprocessing=64`) by turning off HybridEP permute fusion in the GB200 functional defaults.

# Changelog

- `src/megatron/bridge/recipes/qwen_vl/gb200/qwen35_vl.py`: GB200 functional defaults set `moe_permute_fusion_into_hybridep = False`.
- `tests/unit_tests/recipes/qwen_vl/test_qwen35_vl_recipes.py`: assert the flag is off for GB200 SFT and PEFT.

# Additional Information

- **Root cause:** GB200 SFT inherits the flag from the 16-H100 execution config (`h100/qwen35_vl.py:85`); GB200 `env_vars` set only a 128 combine chunk and never reset it.
- **Fix choice:** matches GB200 PEFT (flag never set) and GB300 MXFP8 with the same 128/64/64 layout (`gb300/qwen35_vl.py:379`).
- **Blast radius:** GB200 SFT functional recipe only.
- **Regression?** Yes — introduced by c94c5b9bb (2026-08-05) H100 exec-config tuning, inherited by the GB200 functional defaults.
- **Verification:** red-green in `nemo:nightly` (EOS 6437013): RED 2 failed, GREEN 2 passed (file 173 passed). E2E: Qwen3.6 card GB200 SFT, 2x4 GB200 (Lyris 3590126) `HEALTH OK` 100/100 iters, lm loss 2.21 -> 1.03; pre-fix job 3590038 failed.
- **NVBug:** 7041007.
