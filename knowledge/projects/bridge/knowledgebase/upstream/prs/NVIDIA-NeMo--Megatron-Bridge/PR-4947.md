# [recipe] fix: export GPT-3 compatibility alias

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/4947) · state: open · merged: False

## Original PR description

## Summary

- restore the documented `gpt3_175b_pretrain_config` compatibility alias at the GPT family package boundary
- add a focused contract test covering discovery through the current lazy recipe loader

## User impact and root cause

Both supported selections below derive or request the legacy name:

```bash
scripts/training/run_recipe.py --recipe gpt3_175b_pretrain_config
scripts/training/run_recipe.py --model gpt3_175b --mode pretrain
```

The compatibility wrapper exists, but `megatron.bridge.recipes.gpt` exports only the vanilla GPT alias. The umbrella recipes package therefore never receives `gpt3_175b_pretrain_config`, while the H100 fallback exposes only the canonical hardware-specific name. The shared loader returns no callable and raises `AttributeError` before configuration or training setup.

The fix imports the existing wrapper from the GPT family package and adds it to `__all__`. No recipe defaults, model configuration, runner API, or canonical H100 export changes.

## Regression evidence

The unchanged focused test was run against current `main` with unmodified production code and after the fix:

```bash

```

- before: `1 failed`; `find_library_recipe("gpt3_175b_pretrain_config")` returned `None`
- after: `1 passed`

## Scope

This is package-export and loader-discovery coverage only. It does not change or claim validation of GPT-3 model construction, GPU execution, throughput, convergence, or recipe defaults.
