# refactor(model): add Qwen3 builder-backed model config with YaRN support

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6365) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Moves dense Qwen3 onto the builder-backed `ModelConfig` / `ModelBuilder` path for recipes **and checkpoint conversion** (following Muse Glimmer, #5479), and adds YaRN support to that path.

**Why:** every GPT bridge inherits `MODEL_CONFIG_CLASS = BridgeGPTModelConfig`, so `AutoBridge.get_model_config()` already returns a config for Qwen3, but it ignores everything Qwen3's `provider_bridge()` set. On `main`, that config uses `learned_absolute` position embeddings, LayerNorm, no gated MLP, no QK layernorm, and linear biases. The provider path's deprecation warning points users to this path.

# Changelog

- **`Qwen3Bridge`**: model settings move from `provider_bridge()` into `hf_config_to_model_config_kwargs()`, and `hf_config_to_provider_kwargs()` reuses them, so the deprecated provider path is unchanged (same pattern as `LlamaBridge`). It also states the provider-implied defaults explicitly (`masked_softmax_fusion`, `rope_scaling=False`, `rope_scaling_factor=1.0`, and `position_embedding_type` via `setdefault("rope")`, which keeps `"yarn"` for YaRN checkpoints).
- **YaRN on the builder path**: the seven `yarn_*` fields move from `GPTModelProvider` to Bridge's `TransformerConfig`. Megatron Core's `GPTModel` reads them from the transformer config, which the builder path passes as `model_config.transformer`. The MCore concentration-factor patch moves with them, because MCore's `hasattr()` check otherwise treats a `None`-valued field as YaRN. `GPTModelProvider` inherits the fields, so provider configs are unchanged.
- **Qwen3 YaRN defaults**: when a Qwen3 YaRN config omits `beta_fast` / `beta_slow` / `truncate`, Bridge fills in Hugging Face's defaults (32 / 1 / `True`). On `main` these reach MCore as `None`, and model construction fails with a `TypeError` on **both** paths for standard Qwen3 YaRN checkpoints. The YaRN recipe only works because it sets them by hand. Values the checkpoint sets explicitly are preserved. A shared fix for all GPT families is in #6367; whichever PR merges second should drop the Qwen3-local copy.
- **Recipes**: all 22 Qwen3 H100 recipes, including the YaRN 128K SFT recipe, now use `get_model_config()`.
- **Conversion**: `Qwen3Bridge.USE_MODEL_CONFIG_FOR_CONVERSION = True`, as in `MuseGlimmerBridge`. `AutoBridge.import_ckpt`, `scripts/conversion` (GPU import/export/round-trip) and `compare_hf_and_megatron/compare.py` now build Qwen3 from `get_model_config()`. New checkpoints record `BridgeGPTModelConfig` + `GPTModelBuilder` in `run_config.yaml`; provider-era Qwen3 checkpoints still load and export.
- **Docs**: the builder-backed section of `docs/bridge-guide.md` describes the path generically (no per-model list) and names the family `ModelBuilder` (`GPTModelBuilder` / `HybridModelBuilder`).
- **Tests**: the shared `_FakeBridge` in `tests/unit_tests/recipes/test_qwen_recipes.py` stubs `get_model_config()` for the migrated recipes.

**Impact on other models:** configs not derived from `GPTModelProvider` (hybrid, T5, BERT, MLA, diffusion, vision sub-configs) now carry `yarn_*` fields set to `None`. Every reader handles that:

- The MCore concentration-factor helper is patched to return 1.0 for `None`. This matches the previous behaviour, where those fields didn't exist and `hasattr()` was False.
- `GPTModel` / `HybridModel` read the fields only when `position_embedding_type == "yarn"`.
- HF export uses `getattr(..., None)`.
- The one Bridge `hasattr` check (nemotron-labs diffusion) only receives `Ministral3ModelProvider`-derived configs, which already declared these fields.

Checkpoints with the new keys load on older Bridge versions: unknown provider kwargs are dropped with a warning, and builder configs filter to declared fields.
