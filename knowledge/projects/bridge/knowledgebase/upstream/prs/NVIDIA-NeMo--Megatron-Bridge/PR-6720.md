# fix(build): preserve inherited FlashInfer pair in Framework overlay

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6720) · state: closed · merged: False

## Original PR description

## What does this PR do?

Preserve the matched FlashInfer Python/cubin pair installed by Bridge when the Framework overlay runs `uv sync --inexact`. A Python-only overlay pin can replace one half of an inherited pair and cause FlashInfer's runtime version check to fail, especially with older Bridge base images.

## Changelog

- Defer `flashinfer-python` to the Bridge environment using the same preservation override as other Bridge-owned dependencies.
- Add an offline regression test that installs metadata-only wheel pairs, runs real `uv sync --inexact` with the overlay's FlashInfer override, and checks both installed versions. Cover `0.6.18.post1`, `0.7.2`, and `0.7.2.post1`; assert the FW-final sync retains `--inexact`.
- Merge current main, keeping its newer matched `0.7.2.post1` pins and lockfile. Those pins are already upstream; this PR's remaining diff is the overlay fix and regression test.

## Validation

- Three parameterized regression cases passed in the NeMo Framework container with uv 0.7.2.
- Negative control: restoring the old `0.6.18.post1` Python-only pin makes both newer-pair cases fail with a Python/cubin mismatch.
- The full Framework overlay resolved 342 packages with `uv lock`, using the Export-Deploy, Evaluator, and Run checkouts in the available Framework image. This validates that image's source snapshot, not all moving upstream refs.
- `uv run --no-sync pre-commit run --all-files` and `git diff --check` passed.
- Full image build and GPU imports were not run; the host has an NVIDIA driver/library mismatch. The offline tests verify package preservation, not GPU kernel compatibility.

[P2] Update the Framework override alongside the FlashInfer pair

**Failure:** [the Framework override](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/e9eb87fa5cee0e6a90620cf0f068a173fcb34275/docker/common/fw_pyproject.toml#L71-L75) still selects `flashinfer-python==0.6.18.post1`, explicitly to match Bridge's cubin. [FW-final reuses Bridge's environment and runs `uv sync --inexact`](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/e9eb87fa5cee0e6a90620cf0f068a173fcb34275/docker/Dockerfile.fw_final#L60-L79). Whenever that solve includes FlashInfer Python, the override selects the old Python package while the inherited cubin is now 0.7.2, violating the version-match contract documented immediately below this change. The corresponding pair matched before this PR.

Minimal proposed reproduction: start with Bridge's matched 0.7.2 pair, then sync a minimal project sharing that environment, depending on unpinned `flashinfer-python`, and using the Framework overrides plus `--inexact`. Source reasoning predicts Python 0.6.18.post1 versus cubin 0.7.2, rather than a retained matched pair. External Framework metadata is unavailable here, so I cannot establish whether today's complete FW solve reaches this edge.

**Correction:** preserve the Bridge-owned Python package through the Framework overlay, as that overlay already does for other Bridge-owned dependencies. Replace line 74 of the linked Framework configuration with:

```toml
"flashinfer-python; sys_platform == 'never'", # Installed with matching cubin by MBridge
```

With the existing `--inexact`, suppressing this dependency edge retains the inherited installation. This suggested change has not been executed; verify it before adopting it.

**Preservation:** retain the new matched 0.7.2 pair and supported older bases containing the matched 0.6.18.post1 pair. Merely changing the overlay's Python-only pin to 0.7.2 would create the reverse mismatch on those older bases. Keep Bridge's new pins and its normal/MCore-triggered sync branches unchanged.

**Proposed acceptance checks:** add `test_fw_overlay_preserves_flashinfer_pair`, parameterized with inherited pairs `0.7.2/0.7.2` and `0.6.18.post1/0.6.18.post1`. For the minimal overlay setup above, run its inexact sync and assert both distribution versions remain equal to the inherited version. On a compatible GPU host, `import flashinfer` must pass its version check for each pair. Also verify the actual FW image solve and add a static assertion that the preservation override remains paired with FW-final's `--inexact`. These checks were not run.
