## Original PR description

## Background

Nightly Megatron-Core `main` bump for Bridge `main`: `5de526f2` → `902feb8e`. `.dev.commit` is unchanged (`4a4de865`).

## What changed

- `.main.commit` and the `3rdparty/Megatron-LM` gitlink now point to `902feb8eea1839d60b312cb7b6ec3b2b0724cc6d`.
- `uv.lock` regenerated with `uv lock --upgrade` (uv 0.7.2): huggingface-hub 2.3.0→2.4.0, wrapt 2.5.2rc1→2.6.0.dev1, and patch updates for cuda-pathfinder, nodeenv and opentelemetry. `uv lock --check` passes.
- `MuseSparkMoE.preprocess` accepts `packed_seq_params` and forwards it to the flex dispatcher. This matches `MoELayer.preprocess` in MCore main.
- The branch merges `main` at `ef86aebb` to resolve a conflict. The Sarvam and LLaDA-1.5 test fixes now come from `main` (#6732).

## Details

The `[[tool.uv.dependency-metadata]]` entries already match MCore at `902feb8e` (TransformerEngine 44f31bbe, flash-mla, fast-hadamard-transform), so no metadata edit was needed.

## Tested

Local H100 runs with a validation image built from the bump commit. Rows were selected from the MCore, lock and Bridge diff: 43 functional and 4 unit rows. Rows outside that selection were not run locally.
- The 4 unit rows were run again on this head `15e0f8df`: Diffusion passed (596 tests), Core 0/3 passed (5259 tests) and Core 2/3 passed (5150 tests).
- The 43 functional rows passed on an earlier candidate. Their results are kept, because no functional test uses the code merged from `main`.
- skipped_platform: 1 row, unit Core 1/3. In that row, 5238 tests passed and 2 failed: `test_qwen35_vl_122b_h100_pipeline_layout` [bf16, fp8cs]. The test pod has no HuggingFace network access, and the `Qwen/Qwen3.5-122B-A10B` config is not in the staged cache. **These 2 cases were not validated locally.**
- Totals: passed 46, skipped_upstream 0, skipped_platform 1. Native pytest skips are not counted as passes.

GitHub CI on this head is pending.
