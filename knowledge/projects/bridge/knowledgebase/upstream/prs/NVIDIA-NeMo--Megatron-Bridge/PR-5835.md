## Original PR description

## What does this PR do?

Adds corpus checks for published verification-card commands and removes a remaining duplicate `--ep` flag from the DeepSeek V4 Flash manual-forward command. NVBug 6674249 originally reported an invalid conversion topology and a conversion-only `--executor` flag forwarded to an inference task. Current `main` already contains those command corrections; this PR preserves them and the newer verification records.

The tests check GPU conversion divisibility separately for TP×PP and ETP×EP×PP, conversion-only flags on inference commands, and repeated non-append flags. They follow the shared argument helpers used by current text generation. Negative controls cover the originally rejected topology, the forwarded `--executor`, and duplicate `--ep`; a helper test checks aliases, append flags, and unused helpers. The generated model catalog is updated with the card.

**Light review**

The change fixes two broken published commands in the DeepSeek-V4-Flash card and adds a stdlib-only regression test that scans all cards against the launchers that own the flags. I verified the fixes and the test logic against the source.

Card fixes (both correct):
- megatron_to_hf_gpu: dropping --pp 4 is right. World size = 2x4 = 8; with --pp 4 --ep 8, setup_conversion.py computes ETP*EP*PP = 32, and 8 mod 32 != 0 raises ValueError (scripts/conversion/setup_conversion.py:129-131). With --ep 8 alone it passes.
- manual_forward_pass: dropping --executor slurm is right. infer.sh / setup_inference.py never declares --executor (a conversion-only flag), so it would be rejected. The retained --pp 1 --ep 4 are declared by the model-comparison task script compare.py:1076-1079.

Test logic verified: the three tests mirror the launcher divisibility formula, resolve the selected --task to its entry-point argparse before flagging cross-namespace flags (conservative, given parse_known_args in setup_inference.py:249), and honor action=append flags. Correct.

Minor (non-blocking):
- The new test has no pytest.mark.unit / module-level pytestmark; the testing skill asks unit tests to be marked (passes today under --strict-markers, but it is the convention).
- tests/unit_tests/doc_consistency/ lacks an __init__.py, unlike every sibling unit-test package. Worth adding for collection consistency.

No logic bugs, typos, or stale docs found.
