# fix(training): name the MCore dev pin in dynamic CP field errors

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6578) · state: closed · merged: False

## Original PR description

# What does this PR do ?

On Megatron-Core pins without dynamic context parallelism, report the dev-pin requirement instead of a bare unknown-field error when `model.dynamic_context_parallel` is set.

# Changelog

- **`ModelConfigOverrideMixin.__setattr__`:** on pins that don't declare `dynamic_context_parallel` or `min_dynamic_context_parallel_size` (the `main` pin today), assigning either field now appends the dev-pin hint.
  - Before: `AttributeError: Neither BridgeGPTModelConfig nor TransformerConfig declares a field named 'dynamic_context_parallel'.`
  - After: the same message, followed by ` Dynamic context parallelism needs the Megatron-Core dev pin: ./scripts/switch_mcore.sh dev && uv sync.`
  - Previously, `BridgeGPTModelConfig` recipes failed at assignment before `ConfigContainer.validate` could report the requirement, which provider configs already got.
- **`training/global_batch_packing.py`:** imports the same hint constant, so the field guard and validation stay in sync.
- **Docs:** `docs/training/dynamic-context-parallel.md` and its Fern copy now say where the error is reported: at assignment for configs that reject undeclared fields (such as `BridgeGPTModelConfig`), and in `ConfigContainer.validate` for other configs. The old text said validation always reports it.
- **New unit test:** `test_dynamic_cp_fields_name_the_dev_pin_on_pins_without_them`. It is skipped on pins that declare the fields; on those pins the assignment routes to the transformer config and the hint never fires.

This PR leaves `.dev.commit` alone, since `main` gets the regular pin updates. The 26.10 dev-pin fix goes directly to the release branch in #6579, which also carries this change. For that reason this PR does not need the `r0.7.0` cherry-pick label.

# Testing

Local runs after rebasing onto `main` at `e97a67acb`, in an NGC PyTorch 26.06 container (TransformerEngine 2.20.2), switching the Megatron-LM tree on `PYTHONPATH`:

- **Repro on the `main` pin** (MCore `89b28875`, from #6591; `cfg.model.dynamic_context_parallel = True` on `qwen3_600m_sft_1gpu_h100_bf16_config`): the bare `AttributeError` before this PR, the hinted one after. On the MCore `dev` head (`ff4fbc9f3`), the assignment routes to `transformer.dynamic_context_parallel`.
- **Unit tests** in `test_gpt_model_config`, `test_model_base`, `test_global_batch_packing`, `test_config`, `test_mcore_commit`, `data/packing/test_global_batch` and `test_qwen35_dynamic_cp_recipe`:
  - `main` pin: 446 passed. The new test passes, and it fails on `main` without this change.
  - MCore `dev` head: 449 passed, with the new test skipped.
  - The only two failures are environment-only and also fail without this PR. The `[flex]` energon case needs a GPU, and `test_main_commit_matches_submodule` needs git metadata in the container.
- **Import order:** importing `megatron.bridge.training.global_batch_packing` before anything else in the package works on both pins (no import cycle).
- **Lint:** ruff 0.9 `check` and `format --check` are clean.

# Known limitation

The `run_recipe.py` command-line path (`model.dynamic_context_parallel=true`) is rejected by Hydra's struct-mode override parser before the field guard runs, so it still doesn't show the hint. YAML and `+` overrides of unknown keys are skipped with a warning. That behavior is generic across fields and predates this PR.
