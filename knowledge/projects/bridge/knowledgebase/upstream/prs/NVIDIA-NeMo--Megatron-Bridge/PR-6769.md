# fix(model): route ERNIE 4.5 MoE with softmax like the HF and Paddle models

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6769) · state: open · merged: False

## Original PR description

# What does this PR do ?

The ERNIE 4.5 text and VL bridges configure the MoE router as `moe_router_score_function="sigmoid"` with an expert bias ("Same as DeepSeek V3"), but ERNIE 4.5 routes with **softmax**: it picks the top-k experts from the softmax probabilities plus `e_score_correction_bias` and then renormalizes the probabilities of the selected experts (HF `Ernie4_5_MoeTopKRouter`; Paddle ERNIE `moe_gate_act="softmax"`, which the released `baidu/ERNIE-4.5-21B-A3B-PT` config does not override). So a converted model routes differently from the original.

Megatron-Core's softmax path ignores `expert_bias`, so the bridge cannot just switch the score function. This PR adds `Ernie45TopKRouter`, whose gating returns the log-odds of the softmax probabilities; since `sigmoid(log-odds) = p`, Megatron-Core's existing sigmoid + expert-bias + renormalize path then reproduces ERNIE's routing exactly, and the fused router, expert-bias updates and aux loss keep working.

# Changelog

- `models/ernie/ernie_router.py`: new `Ernie45TopKRouter` and the ERNIE decoder block spec that uses it.
- `models/ernie/ernie_45_bridge.py`: use the new spec on both the builder and the provider paths; the old private spec name stays as an alias for checkpoints saved through the provider path. Comments corrected.
- `models/ernie_vl/...`: swap the router into both VL expert pools.
- `docs/models/ernie/ernie45.md`: the text example named `ERNIE-4.5-0.3B-PT`, a dense model this bridge does not handle; it now uses `ERNIE-4.5-21B-A3B-PT`.
- `tests/unit_tests/models/ernie/test_ernie45_bridge.py`: assertions updated, and two new tests for the router and the spec.

Note: a Megatron checkpoint that was already fine-tuned with the sigmoid routing will route differently after this change.

# Testing

**Routing on real activations.** `baidu/ERNIE-4.5-21B-A3B-PT` in Hugging Face Transformers 5.22.1 on one B300, three short texts (English prose, Python, Chinese). I recorded the input of every MoE router and compared HF's routing with the bridge's current sigmoid routing and with this PR's log-odds router:

| | token×layer pairs with a different expert set (27 layers, 7155 pairs) | mean routing-weight L1 |
|---|---|---|
| current bridge (sigmoid + bias) | 28.3% (15–23% per layer) | 0.59 |
| this PR (log-odds) | 0 | 0 (max 2.2e-7) |

**End to end**, replacing the HF router with each variant and rerunning the model:

| text | sigmoid: top-1 agreement with HF | sigmoid: perplexity (HF → sigmoid) | log-odds |
|---|---|---|---|
| English prose | 0.704 | 3.15 → 4.86 | identical |
| Python | 0.966 | 1.54 → 1.55 | identical |
| Chinese | 0.755 | 13.0 → 10.1 | identical |

This exercises the routing math inside the HF model, not a converted Megatron model; I did not run a full HF↔Megatron logit comparison or the VL models.

**Unit tests** (`tests/unit_tests/models/ernie/test_ernie45_bridge.py`, CPU, Megatron-Core at the pinned `ba495158`, Transformer Engine 2.20.2): 40 passed on `main` (6d32b58), 42 passed with this PR; the new tests fail on `main` (the router module does not exist). `ruff check` and `ruff format --check` (0.9.9) are clean.
