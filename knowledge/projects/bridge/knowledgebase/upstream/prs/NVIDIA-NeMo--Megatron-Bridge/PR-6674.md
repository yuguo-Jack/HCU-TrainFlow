# docs(model): re-pin Super VL GPU conversion entries to include the launcher fix

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6674) · state: closed · merged: True

## Original PR description

The two-node GPU import and export entries in both Super VL cards (from #6606 and #6599/#6600) are pinned to 3a5b4f61, which predates #6625. At that commit, `convert.sh --executor slurm --nodes 2` starts its tasks outside the repository checkout, so the published commands cannot run as written (NVBugs 6969502 and 6965333).

This PR pins those four entries to 0d907c7ee, which is 3a5b4f61 plus a cherry-pick of #6625 (launcher code and its tests only; conversion code is unchanged). The tag `card-pins/nemotron-3.5-super-vl/0d907c7e` keeps that commit reachable.

Re-verification at 0d907c7ee, with the card commands run verbatim on the cards' base container (nemo:26.08.01), 2 nodes x 4 H100:
- Full card: import and export completed, and all 43,079 tensors match exactly (keys, shapes, dtypes, values; 248,906,833,960 bytes). The exported package reloads strictly in Transformers and generates a coherent 32-token image description.
- Text-only card: import and export completed, and all 42,683 language tensors match exactly, including 1,040 MTP tensors, with no media tensors (247,222,108,160 bytes).

The expected results now say which checks ran at the new commit. GB200 and the text-only tokenizer, config and dispatch checks ran at 3a5b4f61, which has identical conversion code. The SFT-export entries are unchanged.

Checks:
- The model verification catalog is regenerated and `--check` is clean.
- The card and catalog doc-consistency tests and the card-validator tests pass (96).
- `pre-commit run --all-files` passed.
- `validate_card.py` reports the same two errors on both cards as on main (empty `hf_revision`, addressed by #6616).

The `r0.7.0` cherry-pick applies cleanly only after #6669 and the `r0.7.0` cherry-pick of #6599 are in.
