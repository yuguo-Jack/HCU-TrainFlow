[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6531) · state: closed · merged: True

## Original PR description

## Background

Nightly Megatron-Core bump, main lane only. This PR moves `.main.commit` and the `3rdparty/Megatron-LM` gitlink to MCore `main` 8442db193ced81584c2e94faa352ec7307d18d83 (was 6e7e6ed4). `.dev.commit` is unchanged.

## What changed

- `.main.commit` and the gitlink now point to 8442db19.
- `uv.lock` was regenerated with `uv lock --upgrade` (uv 0.7.2). Notable upgrades: transformers 5.20.1, pillow 13, wandb 0.31.0, protobuf 7.37.0rc1, numba 0.68.1rc2.
- `training/config.py`: Bridge's `DistributedInitConfig` now declares `use_megatron_fsdp` itself. MCore #7778 removed the field, but Bridge validation, recipes and tests still use `cfg.dist.use_megatron_fsdp`.
- nemotron_omni: the Super-VL processor adapter's version guard, its docstring and the model docs now cover transformers 5.20.1. The minimax_m3 unit test's version expectations include 5.20.1.

## Details

- Local runs used the FlashAttention env from Bridge CI (`NVTE_FLASH_ATTN_V2=1 V3=0 V4=0`, `.github/actions/test-template/action.yml:184`). Without it, the FA4 backward pass hangs on H100. The same hang happens with the baseline main CI image, so the bump did not cause it. Passes from rows that ran without this env count only where their logs show no FA4 use. The other rows were rerun with the CI env.
- `L1_Launch_recipes_glm_vl` is excluded from the local gate at the requester's decision. Both of its tests skip because the GLM-4.5V config is missing from the offline HF cache. Baseline main CI run 39041856905 shows the same two skips.

## Tested

- Local H100 runs on the exact committed tree, using the validation image built from f09ffd3e: 4/4 unit selectors and 74/75 functional launchers passed. The remaining launcher (glm_vl) is excluded.
- `ruff check`, isort and `ruff format --check` pass on the changed files.
- `uv lock --check` passes.
- Required CI: pending.
