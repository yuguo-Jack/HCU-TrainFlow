# docs(model): verify Beam GB200 training leaves at public pins

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6615) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Adds GB200 coverage for all six Beam training items, verified at a public Bridge commit and the public HF revision, and moves the card's default Bridge commit to one on main. The published H200 leaves are kept as they are.

# Changelog

- `examples/model_verification_cards/beam/card.yaml`: default `bridge_commit` -> 21af081c (model-level items no longer repeat it); GB200 pretrain/sft save checkpoints; new GB200 `sft_export_inference`, `sft_long_context`, `checkpoint_resume` leaves; GB200 leaves warm-start from the card's own GPU import. H200 leaves unchanged; the four that inherited the old default now pin dd861860 explicitly.
- `docs/_static/model-verification/catalog-v1.json`, `docs/models/README.md`, `docs/models/beam/beam.md`, Fern mirrors: regenerated.
- `tests/unit_tests/skills/create_model_verification_card/test_validate_card.py`: throughput inputs for the new GB200 `sft_long_context` and `checkpoint_resume` leaves.

# Additional Information

- **Verification:** all six GB200 items passed at aedba7f3 with revision 06641076. Resume losses equal the reference at all 50 steps. The SFT export reloads strictly with `--tp-plan auto` on 2 x 4 GB200.
- **Execution change:** the GB200 pretrain and checkpoint_resume commands add `+env_vars.NCCL_MAX_P2P_NCHANNELS=1` and keep the recipe's CUDA graphs and selective recompute. Without it, rank 0 runs out of memory at step 51 after the step-50 save: the torch_dist save coordinates on rank 0 over the default NCCL group, and NCCL's default 32 point-to-point channels per peer leave about 23.7 GiB of buffers on rank 0 (root cause in MCore, NVBug 6972253). With the variable, the commands run at full speed (last-10 mean 7.90 s/step versus 14.78 s/step with the previous CUDA-graphs-off workaround), and all 100 pretrain losses and all 50 resumed losses equal the reference.
- **Scope:** the existing GB200 pretrain/SFT/LoRA commands change (checkpoint saves, warm-start path, the pretrain NCCL setting). H200 leaves are not rerun (no H200 hardware) and keep their published commits and revision.
- **Risk:** aedba7f3 (GB200 pin) is reachable on GitHub but not on main.
- **NVBug:** 6964571.

[P2] Resolve the new artifact chain from the mounted checkout

**Failure:** With the default Pyxis launcher, a checkout mounted at `/opt/Megatron-Bridge`, and artifacts under its `work/` directory, this export does not find the preceding SFT checkpoint. The [training runner](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/fe7599dc8a48f52a5d6675c2f8931a120fd8b5b4/scripts/training/run_recipe.py#L516-L521) explicitly changes to the checkout because NeMo-Run workers start in `/nemo_run/code`. The [conversion worker](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/fe7599dc8a48f52a5d6675c2f8931a120fd8b5b4/scripts/conversion/run_conversion.py#L160-L173) does not do that, and [GPU export](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/fe7599dc8a48f52a5d6675c2f8931a120fd8b5b4/scripts/conversion/gpu_backend.py#L359-L365) checks this relative path directly, raising `FileNotFoundError`. The following HF-inference command likewise passes its relative export directory directly to Transformers. Thus matching path strings do not establish the advertised producer/consumer chain.

**Correction/preservation:** Establish the mounted checkout as the working directory for Slurm conversion and HF-inference workers, or otherwise resolve their portable artifact aliases consistently with training. Target the Slurm task/executor construction in [setup_conversion.py](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/fe7599dc8a48f52a5d6675c2f8931a120fd8b5b4/scripts/conversion/setup_conversion.py#L171-L255) and [setup_inference.py](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/fe7599dc8a48f52a5d6675c2f8931a120fd8b5b4/scripts/inference/setup_inference.py#L224-L270). This also keeps the GPU import at the location the newly warm-started training leaves read. Preserve absolute paths, Hub model IDs, caller-relative direct/local helper use, and the existing Enroot working-directory behavior. I cannot verify the installed NeMo-Run working-directory API here, so an exact executor-property patch would be speculative. Record and reverify any changed verification commit, then regenerate dependent documentation.

**Acceptance (proposed, not executed):** Start mocked Slurm workers in a temporary directory outside the checkout; place the SFT checkpoint only under checkout-relative `work/`. Assert export reads that checkpoint and HF inference reads its resulting checkout-relative export. Also check that Slurm GPU import writes the path training consumes, while absolute inputs and direct/local relative-path resolution remain unchanged.
