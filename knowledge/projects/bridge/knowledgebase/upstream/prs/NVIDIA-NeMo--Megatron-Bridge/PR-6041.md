# feat(peft): fuse expert LoRA output merge

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6041) · state: closed · merged: True

## Original PR description

## Summary

- Add a LoRA-scoped `use_transformer_engine_op_fuser` switch so PEFT can opt into Transformer Engine fusion without changing the model-wide fusion setting.
- Preserve the original expert linear forward and fuse the LoRA output projection into its output, avoiding a second base-weight GEMM for supported non-grouped expert linears at TP1.
- Keep grouped expert adapters and TP>1 on the existing fallback path, with dispatch and forward/backward parity coverage.

## B300 before / after

Benchmark-only capacity screen on Nemotron Lightning: one B300 node, exact 131,041-token packed sequence, TP1/DP4, recompute r2, one logical forward request across four ranks.

| Candidate | Terminal point | Terminal allocation | Completed calls |
| --- | --- | --- | --- |
| Main-qualified baseline, XID 1052895 | First shared-expert FC1 base GEMM | 928 MiB requested, about 215 MiB free | 0 forward / 0 backward / 0 optimizer |
| Tuned candidate, XID 1052959 | Passed MoE; failed later in attention projection | 672 MiB requested, 114.81 MiB free | 0 forward / 0 backward / 0 optimizer |

The tuned candidate also used 32-way MLP chunking, so this is end-to-end progress evidence rather than an isolated kernel speedup. Neither run completed a forward pass, so throughput and speedup are not claimed. The live image used the equivalent expert-merge implementation from Bridge commit `9379a8492f9cdfcf808a7f56fc3004565381a74b`; this PR rebases the focused change onto current `main`.
