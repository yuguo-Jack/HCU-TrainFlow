# feat(conversion): add a failure exit mode to HF/Megatron comparison

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6312) · state: open · merged: False

## Original PR description

# What does this PR do?

Add `--fail-on-mismatch` to the HF/Megatron forward comparison. Today a different next token or cosine similarity below 0.99 is printed, but the command still exits successfully. The new flag makes those cases fail the command, so a validation job can use its exit status.

# Changelog

- Keep the existing diagnostic behavior when the flag is omitted.
- Require matching next tokens within the HF vocabulary and cosine similarity >= 0.99. Absolute logit differences remain diagnostic metrics.
- Reduce the verdict across all ranks before raising, including non-last pipeline stages, and destroy the process group on failure.
- Document the flag and cover mismatched tokens, low cosine similarity, NaN logits, padded vocabulary entries, and failure propagation from either rank.

# Validation

- 38 targeted CPU tests passed on macOS, Python 3.12.13 and PyTorch 2.14.1. Model loads/forwards are mocked in the CPU tests; verdict propagation uses a real two-process Gloo group.
- Unpatched main fails the three regression cases that expect an error for token mismatch, low correlation, or NaN logits.
- All repository pre-commit hooks passed.
- Strict mypy reports the same 39 existing diagnostics on main and this patch, with no new diagnostic.
- CUDA/NCCL and full-model inference were not run for this patch.

Local test command (isolates the CPU test file from GPU-dependent conftest imports):

```bash
uv run --no-project --python 3.12 --with torch --with pytest --with rich --with pre-commit --with mypy \
  python -m pytest --noconftest tests/unit_tests/test_compare_mask_handling.py -q
```
