# feat(quant): support LSQ scale learning for ModelOpt-quantized models

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6699) · state: open · merged: False

## Original PR description

# What does this PR do ?

Adds training support for ModelOpt LSQ scale learning (learnable NVFP4 per-block weight scales, `_amax_pre` / `_amax_post`) in `training/post_training/`: correct reduction groups for expert scales, an optimizer parameter group for the scales, and a pre-wrap hook for scale-only learning.

# Changelog

- **Expert scales get the expert reduction group.** `restore_sharded_modelopt_state` now calls `propagate_expert_allreduce_to_lsq_params`, which copies each weight's `allreduce` flag onto its scales. Before, Megatron-Core treated expert scales as dense parameters and reduced them over the data-parallel group. On Qwen3-30B-A3B with EP=4, after 10 iterations every one of the 12,288 expert scale tensors was identical to the matching expert's on the other EP ranks, and grad norm jumped from 2.61 to 19.7 at iteration 2. With the flag, no expert shares scales with another.
- **`LSQOptimizerConfigOverrideProvider`** puts the scales in their own optimizer parameter group (peak/minimum learning rate, weight-decay multiplier) on the base schedule. It only overrides settings that differ from the base config: Megatron-Core matches parameter groups by these fields when loading optimizer state, so a scale group identical to the base group would be conflated with it.
- **`freeze_all_but_lsq_scales`** is a pre-wrap hook for scale-only learning. It freezes every other parameter, so the weights take no gradient buffer or optimizer state, unlike freezing them through `optimizer.lr = 0`, and stops MoE router expert-bias updates (`frozen_expert_bias`), as Bridge's MTP freeze does. It can run before or after the ModelOpt restore hook; scales the restore creates stay trainable. With activation recompute, it makes the input of recomputed transformer blocks require grad once the embedding is frozen, the same fix as PEFT's `maybe_enable_recompute_inputs_grad`.
- **Docs:** "Scale Learning (LSQ)" section in `docs/modelopt/quantization.md` and its fern copy.

Memory per GPU, scale-only, `optimizer.lr = 0` vs the freeze hook (GB300, mock data, with ModelOpt's `examples/megatron_bridge/distill.py`):

| Model, parallelism | `lr = 0`: at rest / peak | freeze hook: at rest / peak |
|---|---|---|
| Qwen3-1.7B, DP=4 | 19.83 / 57.05 GB | 7.79 / 45.01 GB |
| Qwen3-30B-A3B, EP=4, full recompute | 172.96 / 181.53 GB | 46.19 / 54.76 GB |

Usage:

```python
from megatron.bridge.training.post_training.lsq import (
    LSQOptimizerConfigOverrideProvider,
    freeze_all_but_lsq_scales,
)

cfg.checkpoint.pretrained_checkpoint = "/path/to/lsq-quantized-checkpoint"
cfg.model.restore_modelopt_state = True
cfg.model.register_pre_wrap_hook(freeze_all_but_lsq_scales)  # scale-only; omit to train the weights too
# (ModelConfig: cfg.model.pre_wrap_hooks.append(freeze_all_but_lsq_scales))
cfg.optimizer_config_override_provider = LSQOptimizerConfigOverrideProvider(
    scale_lr=3e-5, scale_min_lr=None, scale_wd_mult=0.0
)
```

# Additional Information

- **Testing** (GB300, `nemo:26.08`):
  - On this branch rebased onto `main` (Megatron-Core `ba49515`): `tests/unit_tests/training/post_training`, with the checkpoint, resume and optimizer unit tests, 907 passed, 1 skipped; and ModelOpt's `test_qad_lsq_scale_only` (LSQ PTQ, scale-only training, stop and resume) with the ModelOpt PR.
  - On the earlier base (`0652ea797`, Megatron-Core `ed9c2c8`), with the ModelOpt PR, mock data, 4 iterations: Qwen3-1.7B through ModelOpt `distill.py` at CP=1/2/4, with and without full recompute, and resumed from iteration 2; Qwen3-1.7B through Bridge's own `restore_modelopt_state` path with the hook registered before the restore, at CP=1/2; Qwen3-30B-A3B at EP=4 and EP=2 × CP=2. In every run the scales train and all other tensors stay byte-identical to the PTQ checkpoint.
- **Depends on** ModelOpt PR https://github.com/NVIDIA/Model-Optimizer/pull/3069 for scale gradients through Transformer Engine `LayerNormLinear` layers and frozen weights. With an older ModelOpt, `freeze_all_but_lsq_scales` and `LSQOptimizerConfigOverrideProvider` (on a model with scales) raise a `RuntimeError` instead of training with some scales unchanged.
- **Resuming** a scale-only run needs https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6698.
- Static-block NVFP4, and so LSQ, requires `tensor_model_parallel_size=1` in ModelOpt today.
