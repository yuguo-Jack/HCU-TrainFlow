# feat(training): let distill() take training callbacks

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6686) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Adds a `callbacks` argument to `distill()` and passes it to `pretrain()`, as `finetune()` already does.

## Why

Without it, a distillation run that needs a training callback has to call `pretrain(config, forward_step_modelopt, callbacks=...)` itself and skip `distill()`'s checks (the `DistillationProvider` assert and the mrope context-parallel guard).

The first user is ModelOpt's QAD example (NVIDIA/Model-Optimizer#3034). Its `--fake_quant_weight_cache` flag uses `on_train_step_start` / `on_train_step_end` to fake-quantize each student weight once per training step instead of once per micro-batch and activation recomputation.

# Changelog

- `distill(config, forward_step_func=forward_step_modelopt, callbacks=None)`: `callbacks` takes a list of `Callback` instances, a `CallbackManager`, or `None`, and is passed to `pretrain()`. The default is unchanged.

## Testing

`nvcr.io/nvidia/nemo:26.08` with this branch on `PYTHONPATH` (`src` + its Megatron-LM submodule):
- `pytest tests/unit_tests/training/test_distill.py tests/unit_tests/training/test_distill_cp_guard.py`: 6 passed.
- New `test_distill_passes_callbacks_to_pretrain` fails without the change.
- ModelOpt's `test_qad` runs `distill(config, callbacks=...)` end to end through this commit (see NVIDIA/Model-Optimizer#3034).

## Usage

```python
from megatron.bridge.training.distill import distill

distill(config, callbacks=[MyCallback()])
```
