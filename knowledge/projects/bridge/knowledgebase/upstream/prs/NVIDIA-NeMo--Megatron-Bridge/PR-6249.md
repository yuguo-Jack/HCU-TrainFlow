# fix(training): align native DeepSeek V4 packed CP layouts

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6249) · state: open · merged: False

## Original PR description

Depends on NVIDIA/Megatron-LM#7469 at runtime for native DSv4 packed-CP training; this Bridge change can be reviewed and merged on its own (see "Dependency and scope").

## What does this PR do?

Native DeepSeek V4 attention selects contiguous context parallelism with `attention_cp_layout`, but `dsv4_step` still reads the former dev-only `cp_partition_mode`. A packed batch can therefore take the zigzag partitioner even when the model requires contiguous token ownership.

Set both native `attention_cp_layout` and `linear_cp_layout` to `contiguous` in the packed SFT/PEFT recipes (including their GB200 derivatives). The step requires both settings because it supplies contiguous tokens at the HybridModel boundary without a `cp_batch` layout-conversion plan. Partition token/label/loss-mask/position tensors with the explicit CP process group's rank and retain global packed sequence boundaries on every pipeline stage. Exclude scalar metadata from token slicing, carry `pad_between_seqs`, and reject missing packed metadata or a noncontiguous layout before entering the wrong path. The shared packed-parameter utility already ignores the obsolete dev-only field on main; this PR removes it from the DSv4 step's forwarding contract.

At CP>1 this deliberately removes the old non-packed zigzag fallback: non-packed batches and either noncontiguous native layout now fail with an explicit error. CP1 behavior is unchanged. Middle pipeline stages also read non-packed batches so they fail consistently rather than proceeding with missing data.

Token slicing is limited to `tokens`, `labels`, `loss_mask`, `position_ids`, and `padding_mask`, each with global shape `[1, tokens]`. Attention masks and recognized sequence metadata remain unchanged; unexpected populated fields are rejected. Only the total packed length must be divisible by CP size for this partitioner. The recipe keeps its existing offline-packer padding default, but no longer presents `2*CP` per-document padding as a contiguous-CP requirement.

The model guide, Fern mirror, generated catalog, and verification card now use both native layout fields. Only the migrated long-context card entry is marked unverified: its historical dev-API metrics do not verify the new main command. Its old result remains in git history. The command also drops the dev-API explicit pipeline layout, which counted logical blocks rather than the native attention/MoE layers; the recipe's own PP4 segments apply, so this PR does not depend on #6248.

## Dependency and scope

DSv4 packed THD/context-parallel training requires NVIDIA/Megatron-LM#7469 (or its eventual equivalent on main). This Bridge adaptation can be reviewed independently; it does not add those kernels or declare CP training supported without them. MCore remains responsible for topology support and validation. This targets the native main API: configurations supplying only the old dev `cp_partition_mode` must migrate to both native layout fields; backward compatibility with that dev API is not claimed.

The original local experiment additionally restricted its launch to static CP2/TP1 and used an explicitly named packed-mock fixture. Those qualification restrictions, the fixture, and replay harness are excluded from this PR. No full-model fresh/restart qualification is claimed.

On the current Bridge MCore pin, CP>1 with these layouts fails MCore's config validation ("attention_cp_layout='contiguous' is not yet supported with context parallelism") until #7469 lands, so no CP>1 run silently takes another path. CP=1, the recipe default, validates.

The DSv4 step slices `padding_mask` with the tokens but, as before this change, does not pass it to the model, so MoE router statistics still count alignment padding (the generic GPT step forwards it). Forwarding it would make the GB200 packed PEFT recipe's router-scoped CUDA graphs fail the existing padding-mask check, so it is a separate follow-up; the step's docstring states the gap.

Global cumulative sequence boundaries remain global; this is not an end-to-end global `total_tokens` guarantee. The shared loader does not carry that scalar, and the shared Hybrid forward path derives it from local token length. Tests only require a supplied scalar to survive the standalone partition helper unchanged.
