## Original PR description

# What does this PR do?

Check same-repository branch links against the PR's resulting Git tree before checking external links online. This catches links to files deleted by the PR, including references in unchanged historical documentation, and permits links to files added by the same PR before they exist on `main`.

Follow-up to #6370 and #6416. The original workflow already checked out GitHub's synthetic merge commit, but HTTP requests to `blob/main` and `tree/main` still resolved live `main`. That let the six historical links broken by #6370 pass before merge; #6416 subsequently pinned them to `v0.4.2`.

# Changelog

- Explicitly check out and log the immutable event SHA/tree plus PR base/head SHAs. PRs, including forks, use the synthetic merge commit; schedule/dispatch use their event commit. Checkout credentials are not persisted and permissions remain `contents: read`.
- Use pinned Lychee 0.24.2 to extract the same full Markdown/MDX input set without exclusions, then validate same-repository target-branch GitHub blob/tree and raw-content URLs against `git ls-tree`. This needs neither network access nor history beyond the shallow checkout's tree.
- Send external URLs and explicit tags/SHAs/other branches to the existing online checker. Remove the temporary Kimi exclusions: new files are now validated locally.
- Preserve GitHub's file/directory route redirects, decode URL paths once, and preserve encoded ref boundaries. Fail missing objects and empty extraction; untracked files cannot conceal missing committed targets.
- Add regression coverage for additions, deletions with unchanged referers, version pins, directories/raw URLs, URL encoding, missing revisions, shallow clones and fork remotes.

# Review questions for Andrew Chen (@chenopis) and the CI team

This PR implements the verified repository-URL gap. The broader investigation identified separate contracts that are deliberately left for follow-up review:

- **Relative Fern routes and fragments:** this still checks HTTP(S) targets, with local file/directory existence only. Enabling strict Fern body-link validation produced 1,142 baseline errors involving `.md`/`.mdx` and generated API routes. A version-aware route/heading inventory needs its own audited change; this PR does not claim to catch new broken relative links.
- **Generated outputs and navigation:** existing catalog freshness tests and Fern configuration checks remain responsible for these. Should generator `--check` also become a lightweight required docs step? This PR does not change generation or repair files before validation.
- **Preview:** the trusted-main/PR-content preview overlay remains distinct from the candidate-tree check. Any preview navigation change needs to preserve the credential boundary; this PR does not change publishing.
- **Version and branch policy:** URLs to the PR target branch resolve locally; other branches, release tags and SHAs retain online semantics. Please confirm this also matches the intended policy for PRs targeting release branches and manual dispatches on non-default branches.
- **HTTP status policy:** existing acceptance of 401/403/429 and non-Kimi exclusions is preserved. Those statuses are not proof of target existence; narrowing them should be a separate policy decision. Local candidate failures cannot be masked by those exceptions.
- The new checker has local fork/shallow tests, but actual hosted fork-event execution remains a CI validation point. It does not follow submodule contents beyond the superproject's recorded objects.
