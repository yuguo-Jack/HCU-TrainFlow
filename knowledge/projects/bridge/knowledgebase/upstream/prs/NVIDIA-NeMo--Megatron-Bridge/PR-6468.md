**Blocking — Carry the NCCL EP environment into the VRNVL72 NVFP4 alias**

Calling `nemotron_3_ultra_pretrain_256gpu_vrnvl72_nvfp4_config()` now inherits `moe_flex_dispatcher_backend="ncclep"` here, but its [environment replacement](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/117bf89a01a7726342860a610e09fe9f4397e8af/src/megatron/bridge/perf_recipes/nemotronh/vrnvl72/nemotronh.py#L259-L295) discards `NCCL_EP_HT_EM_PULL_PUSH` and reinstates the four HybridEP settings. Those settings are [inert on NCCL EP](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/117bf89a01a7726342860a610e09fe9f4397e8af/src/megatron/bridge/perf_recipes/environment.py#L28-L38). Consequently, the advertised VRNVL72 recipe does not configure the explicit NCCL EP mode used by GB300 and required by the [_enable_ncclep caller contract](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/117bf89a01a7726342860a610e09fe9f4397e8af/src/megatron/bridge/perf_recipes/_common.py#L98-L106). This is a configuration mismatch; a runtime crash or throughput regression has not been established.

**Correction:** In the VRNVL72 Ultra **NVFP4** factory only, replace lines 278–282 with:
```python
        # NCCL EP dispatcher mode.
        "NCCL_EP_HT_EM_PULL_PUSH": 1,
```
The invariant is that the inherited NCCL EP backend and its recipe-owned environment describe the same dispatch stack. Do not replace HybridEP environments across all VRNVL72 factories: the Super and Nano aliases deliberately retain that backend.

**Preservation:** Keep Ultra's GTP64/EP64 layout, local attention/Mamba graphs, grouped tensors, NVFP4 precision, cuDNN normalization overrides, activation-offload settings, and fast-math flag. The existing Ultra MXFP8 alias should retain its matching NCCL EP flag; the Super NVFP4 alias should remain HybridEP with its four topology settings and without that flag.

**Acceptance, proposed and not executed:** Construct the GB300 and VRNVL72 Ultra NVFP4 configs offline and assert both have backend `ncclep`, `moe_use_grouped_tensor=True`, `NCCL_EP_HT_EM_PULL_PUSH == 1`, and no names from `HYBRID_EP_ENV_NAMES`. For VRNVL72, also retain both cuDNN flags, `NVTE_CPU_OFFLOAD_V1`, `NVTE_CUTEDSL_FUSED_GROUPED_MLP`, and `NVTE_USE_FAST_MATH`, all equal to 1. Retain the Super NVFP4 case of [test_vrnvl72_aliases_do_not_inherit_nccl_ep](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/117bf89a01a7726342860a610e09fe9f4397e8af/tests/unit_tests/recipes/test_gb300_ncclep_perf_recipes.py#L130-L142): backend remains HybridEP and its complete HybridEP environment remains present. Verify the suggested edit before adoption.

**Non-blocking — Update the NVFP4 recipe descriptions after removing HSDP**

The public [GB200 docstring](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/117bf89a01a7726342860a610e09fe9f4397e8af/src/megatron/bridge/perf_recipes/nemotronh/gb200/nemotronh.py#L294-L303) and [GB300 docstring](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/117bf89a01a7726342860a610e09fe9f4397e8af/src/megatron/bridge/perf_recipes/nemotronh/gb300/nemotronh.py#L321-L330) still advertise Megatron-FSDP/HSDP, HybridEP, and `num_gpus` sizing HSDP instances. After this change, both disable FSDP, select NCCL EP and partial local graphs, and use a fixed single optimizer instance; `num_gpus` is no longer consumed by either body. Reading help for these factories therefore describes a different execution configuration than the returned one.

**Correction:** Make these narrow docstring substitutions in both factories:
```diff
- NVFP4, Megatron-FSDP (HSDP).
+ NVFP4, GTP.
- precision, HybridEP flex dispatcher,
+ precision, NCCL EP flex dispatcher with local attention/Mamba CUDA graphs,
- num_gpus: Launch GPU count used to size HSDP optimizer instances.
+ num_gpus: Retained for compatibility; sharding is rack-local and the
+     distributed-optimizer instance count is fixed at one.
```
Additionally describe dense GTP32 for GB200's TP2 layout and dense GTP64 for GB300's TP1 layout. These counts follow the [64 total weight shards configured by the helper](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/117bf89a01a7726342860a610e09fe9f4397e8af/src/megatron/bridge/perf_recipes/nemotronh/common.py#L205-L223), not 64 additional shards on both systems. Update the same obsolete `num_gpus` explanation in the directly affected [VRNVL72 NVFP4 alias](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/117bf89a01a7726342860a610e09fe9f4397e8af/src/megatron/bridge/perf_recipes/nemotronh/vrnvl72/nemotronh.py#L259-L266).

**Preservation:** Retain the public signatures/default allocation and the descriptions of TP/SP differences, EP64, batch and sequence sizes, mixed NVFP4 precision, selective MoE activation recomputation, activation offload, and MTP=2. This is documentation correction only, not removal of the compatibility argument.

**Acceptance, static-only:** Inspect each docstring against its returned config: no HSDP sizing or HybridEP claim remains for these NVFP4 factories; dense GTP counts distinguish GB200 from GB300/VRNVL72; signatures and configuration assignments are unchanged. Verify the suggested substitutions in their full docstring context before adoption.
