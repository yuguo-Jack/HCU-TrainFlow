# perf(recipe): update VRNVL72 Qwen3.5-VL 35B/397B MXFP8 recipes

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6450) · state: closed · merged: True

## Original PR description

# What does this PR do ?

The 35B and 397B Qwen3.5-VL MXFP8 perf recipes for VRNVL72 were GB300 aliases that only replaced the process environment and reset GatedDeltaNet to FLA. Apply the settings of the measured VRNVL72 runs instead. Both keep forced load balancing.

35B-A3B (8 GPUs): EP 4 as in the measured runs, GBS 1024, cuDNN GDN, the grouped-GEMM shared expert, HybridEP preprocessing SMs 16 and the dispatch/wgrad overlap, the vision-encoder CUDA graph (cap 3136), 8 data workers, LayerNorm SM margin 0, cuDNN normalization and the allocator settings. It also restores the NVTE_CUTEDSL_FUSED_GROUPED_MLP=1 gate that the recipe's environment dropped.

397B-A17B (64 GPUs): the CuTe DSL fused grouped MLP (op fuser, GLU interleave 32 and its gate), cuDNN GDN, gdn_norm_out recompute, 128-token HybridEP dispatch and preprocessing chunks, the vision-encoder CUDA graph (cap 784) and LayerNorm SM margin 16.

Measured recipe against recipe on VRNVL72 (MXFP8, mock data, forced load balancing): +31.8% at 35B; the 397B A/B is pending. The 397B recipes need a Megatron-Core fix for CUDA graph capture of the router with per-token loss (a regression from NVIDIA/Megatron-LM#7046).

The BF16 and FP8-CS VRNVL72 aliases change only in comments.
