# cp: `perf(recipe): default GB200 and VRNVL72 MoE perf recipes to NCCL EP and grouped tensors (6373)` into `r0.7.0`

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6747) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Cherry-pick of #6373 into `r0.7.0`.

#6373 moves the GB200 and VRNVL72 MoE perf recipes from HybridEP to NCCL EP with `moe_use_grouped_tensor=True`. It also builds the GB300 DeepSeek V3 64-GPU MXFP8 proxy on its NCCL EP parent. See #6373 for the full recipe list and the benchmark results.

On `r0.7.0` this switches 10 GB200 recipes, 25 VRNVL72 recipes and the GB300 proxy. The two 4-GPU VRNVL72 DeepSeek V3 proxies that #6373 also switched are not on this branch (see below).

# Conflict resolution

Four files conflicted. All other files applied cleanly.

- `perf_recipes/deepseek/vrnvl72/deepseek_v3.py`, `test_gb300_ncclep_perf_recipes.py`, `test_moe_full_iteration_recipes.py`: the 4-GPU VRNVL72 DeepSeek V3 proxies come from #6441, which is not on `r0.7.0`. Their NCCL EP switch and test entries are dropped. The rest of each file takes the #6373 change.
- `test_nemotronh_recipes.py`: `r0.7.0` has a different import block. It is kept, plus the `HYBRID_EP_ENV_NAMES` import that the #6373 test change uses.

For each touched file, the diff between this branch and post-#6373 `main` matches the diff between `r0.7.0` and pre-#6373 `main`. The only exception is inside the dropped 4-GPU proxy code.

# Validation

- `pre-commit run --all-files` passes.
- Every recipe that the changed tests reference exists on `r0.7.0`. The Nemotron 3 Ultra GB200 recipes already use NCCL EP here, as the new `test_gb200_ncclep_perf_recipes.py` expects.
- Unit tests were not run locally (no torch environment). CI runs them.
