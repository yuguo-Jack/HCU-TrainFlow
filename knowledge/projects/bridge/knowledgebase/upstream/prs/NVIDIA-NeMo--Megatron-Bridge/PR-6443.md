# fix(training): align Muon distributed setup and checkpointing

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6443) · state: open · merged: False

## Original PR description

## What does this PR do?

Fix distributed Muon setup, parameter synchronization, and checkpoint save/resume. Changing an Adam recipe to `optimizer="muon"` can currently retain incompatible distributed settings and silently produce incorrect updates. Explicit layer-wise configurations also miss overlap and checkpoint paths that check only `use_distributed_optimizer`.

## Changelog

- Normalize emerging optimizers to layer-wise distribution when distributed training is requested, including legacy `dist_*` aliases, and pass the required parameter layout through provider, builder, and component model setup.
- Support both full shard-aligned and compact LayerWise parameter layouts through `use_layer_wise_param_layout`; compact mode retains LayerWise's variable-size synchronization path instead of enabling ordinary DDP distributed-optimizer bucketing.
- Recognize both distributed optimizer implementations when configuring overlap, synchronizing parameters for evaluation/hash checks/checkpoints, and selecting checkpoint metadata, including nested mixed optimizer trees.
- Support parameter synchronization through delegating model wrappers. Disable encoder overlap when empty-input ranks can skip the hooks needed to issue collectives, preserve overlap for the language model, and warn when encoder overlap is overridden.
- Reject unsupported FSDP, optimizer-step overlap, multiple optimizer instances, and component gradient-buffer reuse combinations early.
- Preserve the existing Kimi recipes on compact LayerWise buffers with parameter-gather overlap disabled until their MoE/pipeline topology is validated with the new layout.
- Document distributed Muon configuration and add focused unit coverage plus two-GPU training/checkpoint regressions, including data-parallel resize.

## Validation

- Existing targeted unit validation: **1,008 passed, 7 skipped**.
- Additional focused unit validation for compact layout propagation, MIMO DDP behavior, nested checkpoint metadata, setup, model construction, and config overrides: **475 passed, 1 skipped**.
- Kimi recipe follow-up: **119 passed**, including 54 recipe cases that verify legacy-alias normalization, compact-layout retention, and resolved overlap settings.
- Two-GPU BF16 GPT, 531,968 parameters: 14 fresh-process cases covering explicit/inherited/legacy Muon settings, provider and builder paths, parameter overlap on/off, replica hashes, two checkpoint sharding formats, and Adam controls. Six updates per uninterrupted run, evaluation at steps 3/6, saves at 2/4/6, and fresh resumes from step 2. Losses, gradient norms, and final tensors match exactly across the intended pairs.
- Data-parallel resize regression: a two-rank run saves at step 2 and continues through step 3; a one-rank run resumes from that checkpoint. Final synchronized model tensors and gradient norm match exactly, with the scalar loss matching within `1e-6` to account for reduction ordering.
- Four-GPU BF16 GPT + CLIP: six Adam/Muon overlap and resume cases with alternating empty encoder ranks. Losses, gradient norms, completed gradient reductions, synchronized checkpoint hashes, and scheduler records match exactly. Resume checks also compare restored model and optimizer tensors before continuing.
- Two-GPU BF16 MIMO component regression: compact Muon, shard-aligned Muon, and distributed Adam with overlap off/on. Checks parameter identity and ownership, raw-autograd gradient norms, every model tensor against replicated optimizers, and exact same-topology checkpoint continuation including FP32 masters and optimizer moments. Encoder overlap uses the existing synchronous override; component forwards isolate optimizer behavior from pipeline scheduling.
- Negative controls: unchanged main silently produces different updates for inherited Muon settings and fails the replica-hash case. Restoring only the old save-time gate causes the checkpoint synchronization assertion to fail at the first save.
- All-file pre-commit checks pass. Strict mypy is not clean: the checked training files and installed dependencies report existing typing errors and missing typed-package markers.

These are short correctness runs; they do not establish long-run convergence or performance.

- svcnvidia-nemo-ci · comment · 2026-10-16T18:32:42Z · [source](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6443#discussion_r4298029650)

File: `src/megatron/bridge/training/config.py` · line 2265

[P2] Apply communication overrides before validating optimizer-step overlap

**Failure:** Start with `vanilla_gpt_pretrain_config()` and set:
```python
cfg.optimizer.optimizer = "muon"
cfg.optimizer.overlap_param_gather_with_optimizer_step = True
cfg.comm_overlap = CommOverlapConfig(
    tp_comm_overlap=False,
    overlap_param_gather_with_optimizer_step=False,
)
runtime_config_update(cfg)
```
The inherited distributed flag makes this call select layer-wise distribution, then [normalize_optimizer_config](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/ee73562a10e6ee42c2a3ef714ab7c4c40fdd6b45/src/megatron/bridge/training/utils/optimizer_utils.py#L43-L48) raises immediately. However, [CommOverlapConfig applies explicit user overrides](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/ee73562a10e6ee42c2a3ef714ab7c4c40fdd6b45/src/megatron/bridge/training/comm_overlap.py#L563-L601), so the effective optimizer-step-overlap setting should be `False` and this configuration should proceed.

**Correction:** Remove this pre-overlap synchronization call; retain the call at the start of [ConfigContainer.validate](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/ee73562a10e6ee42c2a3ef714ab7c4c40fdd6b45/src/megatron/bridge/training/config.py#L1399-L1409), which runs after overlap setup. The updated [CommOverlapConfig.setup gate](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/ee73562a10e6ee42c2a3ef714ab7c4c40fdd6b45/src/megatron/bridge/training/comm_overlap.py#L636-L644) already recognizes optimizer-side flags and legacy aliases without this early normalization. Suggested patch at this location, for author verification:
```diff
-    # Resolve optimizer mode before selecting communication overlap capabilities.
-    _validate_and_sync_distributed_optimizer_settings(cfg)
-
```
The invariant is to validate effective settings after communication overrides, while still normalizing distribution before model construction.

**Preservation and acceptance — proposed checks, not executed:** Add `test_runtime_config_update_applies_overlap_override_before_layerwise_validation` using the setup above, parameterized with `muon` and `dist_muon`. Expect successful runtime update, normalized name `muon`, layer-wise distribution enabled, ordinary optimizer distribution disabled, DDP distribution enabled, and optimizer-step overlap disabled. With no override, or an explicit `True` override, expect the existing `ValueError`. Retain the existing normalization test's idempotent explicit/inherited/alias results, replicated Muon's all-distribution-flags-false result, and Adam/SGD's ordinary-distribution result in [the distribution tests](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/ee73562a10e6ee42c2a3ef714ab7c4c40fdd6b45/tests/unit_tests/training/test_optimizer_distribution.py#L28-L78).
