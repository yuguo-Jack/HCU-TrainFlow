# fix(recipe): use partial CUDA graphs for Qwen3 GB200 MXFP8

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6364) · state: closed · merged: False

## Original PR description

## What does this PR do?

The Qwen3-30B-A3B GB200 MXFP8 performance preset runs out of memory in the first optimizer step after full-iteration CUDA-graph capture on newer framework stacks, as reported in [#6307](https://github.com/NVIDIA-NeMo/Megatron-Bridge/issues/6307). Switch `qwen3_30b_a3b_pretrain_8gpu_gb200_fp8mx_config` to Transformer Engine graphs scoped to `attn`, `moe_router`, and `moe_preprocess`.

Keep the existing benchmark helper so that HybridEP, expert communication overlap, delayed weight-gradient computation, paged stash, expert padding, capacity, and allocator settings match the successful diagnostic. The only runtime changes are `cuda_graph_impl` and `cuda_graph_scope`. Update the existing recipe regression test to check the new graph settings while retaining its checks for precision, topology, batches, environment, and benchmark behavior.

This mitigates the preset failure. The underlying full-iteration memory regression and the hang after an OOM remain tracked by #6307. The related [#5356](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/5356) changed the B200 preset; this change applies to GB200.

## Validation

Completed GPU experiments:

| Experiment | Result |
| --- | --- |
| Graph settings only | All eight ranks completed 30 iterations with graph replay, finite losses, and zero skipped/NaN steps. Graph pool: 33.684 GiB; post-capture peak allocated: 138.083 GiB; peak reserved: about 174.1 GiB. Mean step time over iterations 16–30: 8,450.6 ms. |
| Partial graphs plus companion settings | Also completed 30 iterations. Changing allocator/record-stream settings and disabling paged stash/expert padding provided no memory-headroom benefit; mean step time was 8,819 ms. Those changes are excluded. |

The graph-only experiment used 8 GB200 GPUs across two nodes, MBS 4, GBS 512, sequence length 4096, EP8, HybridEP, and MXFP8.

## Performance and remaining validation

The diagnostic still reached approximately 184.29 of 184.31 GiB device memory and emitted allocator OOM-retry warnings before capture, so the successful 30-step run does not establish comfortable memory headroom or long-run stability.

The model verification card's historical full-iteration result is about 6.50 seconds per step, versus 8.45 seconds for this partial-graph diagnostic. These measurements use different stacks and timing windows; they are not a matched estimate of the graph-mode performance cost. The card remains an explicitly pinned historical result. 

Related to #6307.
