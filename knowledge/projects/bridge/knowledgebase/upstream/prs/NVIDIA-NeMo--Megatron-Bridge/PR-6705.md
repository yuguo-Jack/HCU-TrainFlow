# test: isolate fake shell commands from BASH_ENV

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6705) · state: open · merged: False

## Original PR description

# What does this PR do ?

The fake-host fixture inherits `BASH_ENV`. Its wrapper and Bash-based `stat` and `enroot` doubles therefore repeat the container's shell initialization even though they only simulate local commands.

Clear `BASH_ENV` in that fixture with one added line.

**Before/after evidence**

| Metric | Before | After | Evidence |
| --- | --- | --- | --- |
| Times Bash sourced `BASH_ENV` in the focused module | 227 | 0 | A counting probe set as `BASH_ENV` |
| Focused module time with a 0.1-second `BASH_ENV` probe | 26.00 seconds | 2.66 seconds | One run each on one machine |
| Focused module time with `BASH_ENV` unset | 2.80 seconds | 3.19 seconds | One run each on one machine, so this difference is noise |
| Focused module time in a local container with `BASH_ENV=/etc/bash.bashrc` | 23.48 seconds | 2.89 seconds | One recorded local comparison |

The saving depends on how slow `BASH_ENV` is on the runner. The CI test template already exports `BASH_ENV=/dev/null` on GCP runners, so this change only helps where the image value stays set. The end-to-end CI benefit has not been measured.

# Changelog

- Clear `BASH_ENV` with `monkeypatch` in `fake_host`, restoring the original environment after each test.
