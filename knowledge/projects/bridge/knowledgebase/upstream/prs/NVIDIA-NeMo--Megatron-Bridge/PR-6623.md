# fix(model): pass --bagel-repo through the conversion launcher for BAGEL import

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6623) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes the BAGEL card's `hf_to_megatron_gpu` command failing as published with `ImportError: Could not import official BAGEL module modeling.bagel` unless PYTHONPATH is set by hand, by adding a `--bagel-repo` option to the conversion launcher.

# Changelog

- `scripts/conversion/arguments.py`: new import-only `--bagel-repo` option, forwarded to the worker.
- `scripts/conversion/run_conversion.py`: `_run_import` exposes the checkout via `configure_official_bagel_repo` before backend dispatch.
- `tests/unit_tests/conversion/launcher/test_arguments.py`, `test_run_conversion.py`: 3 tests (forwarding, sys.path before backend, invalid checkout).
- `examples/model_verification_cards/bagel/card.yaml`: `hf_to_megatron_gpu` passes `--bagel-repo work/dependencies/Bagel`; leaf repinned and re-dated.
- `docs/...bagel.md`, `bagel.mdx`, `catalog-v1.json`: regenerated.

# Additional Information

- **Root cause:** `BagelModelProvider._official_config` (`provider.py:192-196`) imports `modeling.bagel` and only adds the checkout to `sys.path` when `bagel_repo` is set. Nothing on the convert.sh path set it.
- **Regression?** No. The option has been missing since BAGEL conversion landed (#5605). Earlier passing runs exported PYTHONPATH outside the card command.
- **Verification:** NeMo 26.10 release container. Unit tests: RED on main (3 failed), GREEN on this branch (30 passed). E2E with PYTHONPATH empty: the old command failed with the ImportError. The new card command passed (`Loaded native BAGEL state: source=1223 target=943`), and the checkpoint reloaded with 0 missing keys and 1223/1223 EMA tensors exactly equal.
- **Card pin:** BAGEL does not run on current `main` with either MCore pin, so the e2e ran on this fix cherry-picked onto the card's `fd8ab826`. The leaf pins that commit, `6d319871f`.
- **Conflict:** #6613 edits the same leaf (`bridge_commit`, `last_verified`, `expected_result`) and the generated docs. If #6613 merges first, keep `--bagel-repo` and this leaf's `bridge_commit`, then regenerate. Merge order is the dev's call.
- **Related:** BAGEL on current main is blocked separately by NVBug 6848442 (MCore pin).
- **NVBug:** 6972273.

- svcnvidia-nemo-ci · comment · 2026-10-22T18:07:08Z · [source](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6623#discussion_r4351825004)

File: `scripts/conversion/arguments.py` · line 414

[P2] Include the checkout in the local-GPU shell-safety guard

**Failure:** A local GPU import with `--bagel-repo '/tmp/Bagel checkout'` now passes launcher validation and forwards that value to the unquoted local Torchrun task. The existing [validation contract](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/e4af4229d7a3a6ceaaadd6047254b9d65e960896/scripts/conversion/setup_conversion.py#L136-L146) explicitly rejects whitespace/metacharacters because NeMo Run 0.10 cannot preserve them on this path, but its `worker_values` list omits this new argument. Consequently, this checkout can be split into multiple worker arguments instead of reaching the dependency helper intact. [Task construction](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/e4af4229d7a3a6ceaaadd6047254b9d65e960896/scripts/conversion/setup_conversion.py#L227-L254) confirms that only Slurm arguments receive explicit shell quoting. This is source reasoning, not an executed reproduction.

**Correction:** In the linked `setup_conversion.py::_validate_args`, immediately before the existing `shlex.quote` check, add:
```python
            if args.command == "import" and args.bagel_repo is not None:
                worker_values.append(args.bagel_repo)
```
This restores the invariant that every newly supported checkout path subject to the local-GPU quoting limitation is rejected before submission. Please verify the suggestion before adopting it.

**Preservation:** Keep shell-safe local checkout paths accepted and forwarded unchanged, and retain default omission when the flag is absent. Do not reject these characters globally: Slurm already quotes its task arguments, and direct worker/CPU dispatch should remain unchanged. Existing model/output-path guards for import, export, and roundtrip must also remain intact.

**Acceptance:** Add proposed `test_local_gpu_validates_bagel_repo_shell_safety` in the [launcher tests](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/e4af4229d7a3a6ceaaadd6047254b9d65e960896/tests/unit_tests/conversion/launcher/test_setup_conversion.py#L394-L414): parse local GPU import arguments with one GPU and checkout `/tmp/Bagel checkout` or `/tmp/Bagel;checkout`; `_validate_args` must raise the existing shell-safety ValueError. `/tmp/Bagel` and an omitted checkout must pass. A Slurm import with the spaced checkout and required executor settings must still pass validation and produce one quoted checkout argument. Retain the existing three worker-value rejection cases and the new worker tests' assertions that a valid checkout is visible before dispatch and an invalid checkout invokes no backend.
