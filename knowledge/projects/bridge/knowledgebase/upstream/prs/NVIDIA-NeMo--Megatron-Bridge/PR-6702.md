# test: prepare functional release data on demand

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6702) · state: open · merged: False

## Original PR description

# What does this PR do ?

Synthetic-data recipe and model tests currently prepare unused Megatron-LM release archives. Without the staged CI cache, an unrelated test can trigger GitHub release discovery and downloads before it runs.

Remove `autouse=True` so only tests that request `ensure_test_data` pay that setup cost. This is a one-line change.

**Before/after evidence**

| Scenario | Before | After | Evidence |
| --- | --- | --- | --- |
| Archive extractions in `L1_Launch_recipes_qwen_vl.sh`, summed over sessions and ranks | 10 | 0 | Logs from matched launcher runs |
| Preparation for the explicit fixture consumers in `L0_Launch_data.sh` | 1 | 1 | Logs from matched launcher runs |
| `L1_Launch_recipes_qwen_vl.sh` time with staged archives | 1,017 seconds | 1,040 seconds | One matched run each on `270264f20` |
| `L0_Launch_data.sh` time with staged archives | 204 seconds | 207 seconds | One run each |

The verified improvement is eliminating unused preparation and its possible GitHub dependency. Staged extraction is already fast, and the matched launcher times show no measurable speedup, so this PR does not claim one.

# Changelog

- Remove `autouse=True` from the session data fixture. Explicit consumers keep the same fixture, temporary directory, and downloader.
- Avoid release discovery, downloads, and extraction for synthetic-data recipe and model tests that do not consume those assets.

# GitHub Actions CI

See the [CI section](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/main/CONTRIBUTING.md#-running-github-ci) in the Contributing doc for how to trigger the CI. A Nvidia developer will need to approve and trigger the CI for external contributors.

Validation ran on NVIDIA B200 GPUs on x86-64, with this PR merged onto main at `00e3730dd`, which includes Megatron-Core `ba495158`. Each launcher used two GPUs, 40 pinned CPU cores to match the CI `--cpus=40` limit, `HF_HUB_OFFLINE=1`, and an environment built from `uv.lock`. Only the GPU indices in the launchers changed. This environment is not the CI container image.

A collection-time audit of `tests/functional_tests` on main and on this PR shows that the tests that resolve to this fixture after the change are exactly the tests that request it by name, and that this set did not change. Other tests cannot reach the prepared data, because the fixture writes it to a pytest temporary directory and only exposes the path as its value.

`L0_Launch_data.sh` completed with this PR and with the same tests as main. It also completed with no staged archives, which exercised the real GitHub discovery and download path for the explicit consumers. `test_chat_template.py` ran with a public copy of the Llama 3.1 tokenizer at the CI path, because the gated original was not available. The test sets its own chat template. `L1_Launch_recipes_qwen_vl.sh` completed with this PR alone on `270264f20`. On `00e3730dd`, it completed with this PR merged with #6703, #6704, and #6705, and the log showed no archive extraction. `L0_Launch_data.sh` also completed with those four PRs merged.

The no-op `ensure_test_data` overrides that opted out of the old autouse behavior are now redundant. They stay in place to keep this change small.

Not validated: H100 and GB200 runners, and the CI container image. Other functional launchers did not run, so the collection audit is the only evidence for them. Upstream functional CI remains pending.
