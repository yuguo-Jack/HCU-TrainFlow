# docs: use absolute links for example files in README news

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6504) · state: closed · merged: True

## Original PR description

## What
Switch four links in the 10/15 README news entries from repo-relative paths to absolute GitHub URLs:
- the Nemotron 3.5 Super VL verification card;
- the Muse-Spark-Open-816B-A42B examples README (two links);
- the Muse-Spark-Open-816B-A42B verification card.

## Why
`docs/index.md` includes `README.md` with `:relative-docs: docs/`, so the Sphinx build rewrites only links under `docs/`. The `examples/...` links added in #6483 and #6493 stay relative, and MyST can't resolve them. The docs build runs `sphinx-build --fail-on-warning`, so the four `myst.xref_missing` warnings fail the release workflow's "Build docs" job, and `release-summary` with it, on every PR based on current `main`. #6489, #6490, #6498 and #6499 all hit it.

The README's other example links already use absolute `https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/main/...` URLs. All three link targets exist on `main`.

## Validation
- Local `sphinx-build --fail-on-warning --builder html . _build/html` in `docs/`, with the docs dependencies locked in `uv.lock` (Sphinx 9.1.0, MyST-Parser 5.1.0): the four README warnings are gone. The one remaining warning is local-only: the build ran on an exported copy without the `3rdparty/Megatron-LM` submodule, which `docs/training/multi-token-prediction.md` links into. CI checks out the submodule, so that link resolves there, and the failing CI runs report only the four README warnings.
- `pre-commit run --all-files` passes.
