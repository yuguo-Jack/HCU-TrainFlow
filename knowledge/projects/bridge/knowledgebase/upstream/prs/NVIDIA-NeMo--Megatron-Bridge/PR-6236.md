# perf(ckpt): build QKV/KV split indices on the input device

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6236) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Creates the index tensors in the QKV/KV split helpers on the input tensor's device, so splitting a CUDA tensor no longer copies CPU indices to the GPU and blocks on the stream.

# Changelog

- `param_mapping.py`: pass `device=<input>.device` to every `torch.arange` in `split_qkv_biases`, `split_qkv_weights`, `split_qkv_weights_scale`, `split_qkvg_weights`, `split_kv_biases` and `split_kv_weights`. The issue names `split_qkv_weights`; the other five build their indices the same way.
- Test: `TestHelperFunctions::test_split_helpers_index_on_input_device` (CUDA only, with and without `attention_output_gate`) runs each helper on a CUDA tensor under `torch.cuda.set_sync_debug_mode("error")` and checks that the outputs stay on the input device and equal the CPU results.

The Mamba and GDN mapping classes build indices with `torch.arange` too. I left them out to keep this PR to the helpers in the issue.

# Validation

Single RTX 3080 Ti, PyTorch 2.14.0+cu126, Megatron-Core at the pinned submodule commit `c035a426`. Transformer Engine was not installed. The package imports it at module level, so I ran with a local import stub for it. None of the six helpers call into TE.

- Profiler (the script from the issue, extended to all six helpers): on `upstream/main` each call issued 2–4 `Memcpy HtoD (Pageable -> Device)` and the same number of `cudaStreamSynchronize` (one per index tensor). With this change: 0 and 0 for every helper.
- New test: 2 passed with the change, 2 failed on `upstream/main` (`RuntimeError: called a synchronizing CUDA operation`). Reverting the change in one helper at a time makes the test fail for each of the six.
- Unit test files that call these helpers (`test_param_mapping.py`, `test_fp8_param_export.py`, `test_model_bridge_lora.py`, `test_canonical_lora.py`, `test_gemma4_modeling.py`, `test_step35_bridge.py`, `test_muse_glimmer.py`): 419 passed, 1 skipped. The remaining 4 failures (`test_muse_glimmer.py`) and 2 errors (`test_canonical_lora.py`) fail the same way on `upstream/main` in this environment and trace back to the TE stub (MagicMock inputs, missing TE norm weights, no `reset` on stubbed TE base classes). `test_flux_attention.py` needs `modelopt` and was not run.
- The timing check from the issue (an `8192 x 8192` BF16 matmul queued right before `split_qkv_weights`, 7 samples): median host return time 15.314 ms on `upstream/main`, 0.247 ms with this change.
- `ruff check` and `ruff format --check` (ruff 0.9.9) pass on both changed files.
