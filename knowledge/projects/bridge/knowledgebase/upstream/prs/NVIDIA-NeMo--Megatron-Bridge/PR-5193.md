# [ckpt, build] fix: support pip-installed conversion on Megatron-Core 0.18.x

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/5193) · state: open · merged: False

## Original PR description

## What

Makes a pip-installed Megatron Bridge work against the released Megatron-Core **0.18.x** line, not just the exact source pin. This is a concrete step toward #5148.

Current main pins Megatron-Core commit `24bad8e677` (`0.20.0`), while the [public PyPI index](https://pypi.org/simple/megatron-core/) currently ends at `0.18.2`: there is no public `0.19.x` or `0.20.x` package to install. The supported pip range is therefore declared explicitly as `>=0.18.0,<0.21` and tested against both the current source pin and the actual public 0.18.x line.

On 0.18.x, `megatron.training.models.gpt` does not exist. Without this change, that missing module breaks `megatron.bridge.training` and every checkpoint import/export path that depends on it.

## How

- `megatron.bridge.compat.mcore_version` declares the public compatibility floor (`0.18.0`), current source pin (`0.20.0`), and exclusive next-minor ceiling (`0.21`). Tests keep the source gitlink, code declaration, and package metadata aligned.
- `megatron.bridge.compat.mcore_gpt` is the stable facade for GPT builder/config symbols and serialized targets. It prefers the upstream implementation when present and uses the vendored fallback only when the whole upstream module is absent; unrelated transitive import errors still propagate.
- The fallback is refreshed from the current 0.20 GPT implementation. Its model-builder call projects the current arguments onto the callable exposed by older MCore releases, including omitting the new layerwise optimizer/layout arguments on 0.18.x.
- All current-main consumers, including the newer GPT model-config path, import through the facade. Legacy upstream serialized targets are normalized when loading existing run configs.
- Package metadata and user documentation now state `megatron-core[dev,mlm]>=0.18.0,<0.21`.

No file under `3rdparty/Megatron-LM` is modified, no dependency is added, and no public conversion API signature changes.
