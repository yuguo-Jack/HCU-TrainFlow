# feat(recipe): add validated Beam GB200 library recipes

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6528) · state: closed · merged: True

## Original PR description

# What does this PR do?

Add GB200 BF16 library recipes for Beam pretraining and full SFT on 64 GPUs, and LoRA on 32 GPUs, with related runtime fixes needed to train the released checkpoint.

# Changelog

- Use HybridEP within one NVLink domain: TP4/EP64 for 4K pretraining, TP8/EP64 for 8K packed SFT, and TP4/EP32 for 8K packed LoRA. Preserve natural routing and FP32 gradients, master parameters and Adam moments.
- Pretraining captures attention/router CUDA graphs and selectively recomputes expert activations to retain memory headroom. Packed finetuning stays eager without recompute. All three use periodic garbage collection; TP and fine-grained expert communication overlap remain disabled.
- Preserve FP32/FP64 router GEMMs under model autocast, execute gate bias through its parameter-owning module, include captured sandwich norms in parameter-gather ownership, and skip update collectives for fixed expert biases. Remove the obsolete distributed-optimizer constructor modification now covered by the pinned Megatron-Core.
- Use native Beam support from Transformers 5.20.1 and remove the local configuration fallback and registration. The lockfile upgrade and related compatibility fixes landed in #6531. Keep the package-wide `>=5.15,<5.21` requirement; only the five native Beam HF integration cases skip below 5.20.1, while mapping, modeling and recipe coverage remains active.
- Add recipe exports, focused regressions, a two-GPU graph/gather regression, usage examples and measured training results. H200 training settings are preserved; their checkpoint revision is updated to the publicly resolvable release. Extend the verification card and generated catalog with the three completed GB200 training runs at their tested Bridge commit. GB200 export/inference, long-context SFT and checkpoint resume remain unverified; refresh the commit and evidence after post-merge retesting.

# Validation

Retested after merging main `01d1c29ad769668dcadaae52896319afce56feb5` at PR head `aedba7f32e8f6bb43105e8710167ed08668ce4c8`. All three recipes completed a fresh 100-step full-model run using NeMo 26.10 RC5, native Beam support from Transformers 5.20.1, Megatron-Core `8442db193ced81584c2e94faa352ec7307d18d83`, and public Beam revision `06641076793dad51b8907f7eb2a14f4e08fd3ec8`. Transformers was installed as a no-dependency wheel overlay; Bridge and MCore used the pinned source, while the remaining image packages were retained. This does not claim a full installation of main's lockfile.

Each run starts from the same imported public checkpoint and retains the previously tested inputs, schedules, precision, natural routing and performance settings. Actual placement, effective configuration, optimizer state, model partitions and graph/recompute execution were checked on every rank. Checkpoint writes and evaluation are disabled.

| Recipe | GPUs | Steps | Seconds/update | Physical tokens/s/GPU | Model TFLOP/s/GPU | Minimum observed free memory |

| Full SFT | 64 | 100 | 1.6841 | 605.61 | 83.18 | 9.28 GiB |

Throughput uses updates 51–100 and the slowest rank's synchronized elapsed time, including five periodic garbage collections and intervening logging. Token counts include padding. Model FLOPs are architecture-based estimates, not measured hardware FLOPs. The LoRA FLOP estimate uses the full-training formula; it is neither actual adapter compute nor MFU. All three runs passed 100 finite updates with zero skipped/NaN updates and at least 4 GiB observed memory headroom. First/last ten-update mean losses are 1.1828/1.0398 for pretraining, 1.0766/0.7390 for SFT, and 1.0778/0.8389 for LoRA. Full-checkpoint save/export/resume and adapter export are not established by these training runs.

The recipe guide reports the synchronized steps-51–100 measurements from these Transformers 5.20.1 runs, matching the verification card. One run per stack on different valid single-domain allocations does not establish a repeatable speedup. The earlier matched tuning screens remain the basis for configuration selection: router graphs without selective recompute failed the memory-margin check; TP2/PP2/EP32, activation fusion and TP overlap were rejected after their respective memory or numerical failures. SM16 and SM32 were effectively tied in the selected pretraining configuration; retained SM32 is not claimed to be superior.
