# fix(hf_pretrained): cache small tensors and reuse safe_open handles in SafeTensorsStateSource

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6456) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Make `SafeTensorsStateSource.load_tensors` cache small tensors (quantization scales) per instance and reuse `safe_open` handles, so repeated single-key lookups during HF export do not re-open the shard files.

# Changelog

- `hf_pretrained/state.py`, `SafeTensorsStateSource.__init__`: per-instance `_small_tensor_cache` (tensors with ≤ 16M elements) and `_open_handles`; both switchable via `MBRIDGE_STATE_CACHE_SMALL_TENSORS=0` / `MBRIDGE_STATE_REUSE_HANDLES=0`, threshold via `MBRIDGE_STATE_SMALL_TENSOR_NUMEL`.
- `SafeTensorsStateSource.load_tensors`: serve cached keys first; in the index-mapped path use the reused handle and cache small tensors after reading them. The glob fallback path, the `key_prefix` strictness and the returned tensors are unchanged.

Why: `export_hf_weights()` re-quantizes every FP8/MXFP4 weight against its original HF `*scale` tensor and fetches each scale through `hf_state_dict[key]` → `load_tensors([key])` → one `safe_open` of the shard per tensor. For DeepSeek-V4-Pro that is ≈150k shard opens of an 806 GB checkpoint per export. In an RL loop (verl: Megatron actor → vLLM weight refit every step) the export was 657–698 s of a 962 s step at 61 layers.

Measured on GB200 (verl, DeepSeek-V4-Pro, Bridge 0.6.2 with the same change; this PR is the port to `main`):

| model | export (`update_weights`) before | after | RL step |
|---|---|---|---|
| 4-layer truncated, 8 nodes | 31–35 s | 9–12 s | – |
| 61-layer, 64 nodes | 657–698 s | 238–254 s | 962 s → 535 s |

rollout/actor log-prob agreement unchanged (Pearson 0.9994 / 0.9950 before and after). Memory: the cached scales of the full Pro checkpoint are a few hundred MB per rank.

[P2] Keep caller mutations out of the cached checkpoint tensors

**Failure:** With an indexed shard containing `w.scale = torch.tensor([1.0])`, the default configuration now makes this sequence return zero:
```python
source = SafeTensorsStateSource(checkpoint_dir)
source.load_tensors(["w.scale"])["w.scale"].zero_()
value = source.load_tensors(["w.scale"])["w.scale"].item()
```
The cache stores the returned tensor itself, and the [cache-hit branch](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/5f926954b002b3ddd4dc6a2485fd4d7ca7ee3cab/src/megatron/bridge/models/hf_pretrained/state.py#L680-L687) exposes that same mutable object again. Consequently, in-place preprocessing changes subsequent reads from this disk-backed checkpoint without changing the checkpoint file. Previously, [each mapped read opened a fresh shard handle](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/535a57a215d330d1cd1e71ad00c92017c54bc9c5/src/megatron/bridge/models/hf_pretrained/state.py#L673-L681).

**Correction:** Keep cache-owned storage private on both insertion and retrieval. Suggested replacements, not executed:
```python
# SafeTensorsStateSource._maybe_cache, inside the existing condition:
self._small_tensor_cache[key] = tensor.clone()

# SafeTensorsStateSource.load_tensors, cache-hit assignment:
loaded_tensors[key] = cached.clone()
```
Both changes are necessary: cloning only hits leaves the first returned tensor able to poison the cache; cloning only insertion leaves later hits writable. The invariant is that changing any returned cached tensor cannot change the cache's checkpoint value.

**Preservation / acceptance:** Add a CPU regression using the one-element shard above. Mutate the first result, then mutate a cache-hit result; the following read must still equal `[1.0]` each time, with unchanged shape/dtype and no additional `safe_open` calls. Check both handle-reuse settings. Retain the existing size gate and cache-disabled behavior, and retain the separate text/vision values asserted by [test_prefix_views_do_not_modify_shared_index_or_default_source](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/5f926954b002b3ddd4dc6a2485fd4d7ca7ee3cab/tests/unit_tests/models/hf_pretrained/test_text_only.py#L130-L147).

[P2] Invalidate an incomplete shard handle before retrying

**Failure:** Every retry calls `_get_handle(file_path)`, but with reuse enabled that returns the same object and therefore the same parsed header. For example, let an index advertise `text.weight` in a shard initially containing only `text.other`. If that shard is atomically replaced with a complete shard during the first retry delay, `SafeTensorsStateSource(path, key_prefix="text.").load_tensors(["weight"])` still checks the old header on all three attempts and raises `KeyError`. The [selected-subtree guard](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/5f926954b002b3ddd4dc6a2485fd4d7ca7ee3cab/src/megatron/bridge/models/hf_pretrained/state.py#L691-L696) correctly prevents a fallback scan, so it cannot rescue this case. The [previous retry loop](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/535a57a215d330d1cd1e71ad00c92017c54bc9c5/src/megatron/bridge/models/hf_pretrained/state.py#L673-L690) reopened the shard on each attempt.

**Correction:** Retain handles after successful reads, but evict a handle when its requested keys are missing. Insert immediately after computing `still_missing`:
```python
if still_missing and self._reuse_handles:
    self._open_handles.pop(str(file_path), None)
```
This suggested change makes the next attempt construct a fresh handle; it also avoids retaining the incomplete handle after the final failed attempt. Successful repeated reads must continue reusing their handle.

**Preservation / acceptance:** Proposed CPU regression: create the indexed prefixed shard described above, disable tensor caching, and replace it with a shard containing `text.weight = ones(1)` inside a patched first `time.sleep`. Loading must return `ones(1)` after two opens; a subsequent successful read must not open again. Make glob scanning fail if invoked. An unchanged incomplete shard must still raise `KeyError`, retaining the no-unrelated-scan assertion in [test_selected_source_does_not_scan_other_shards_for_missing_tensor](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/5f926954b002b3ddd4dc6a2485fd4d7ca7ee3cab/tests/unit_tests/models/hf_pretrained/test_text_only.py#L150-L158). Preserve the ordinary unprefixed fallback branch.
