# fix(ckpt): support MFSDP v2 MoE checkpoint resume

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6469) · state: open · merged: False

## Original PR description

# What does this PR do?

Enable MFSDP v2 MoE checkpoint save/resume in Bridge and verify that resumed training matches uninterrupted training. Bridge currently rejects these checkpoints during config validation. After allowing them, loading into the unwrapped model bypasses the MFSDP adapter's BF16 compute-weight refresh, causing the first resumed loss to differ.

**Depends on [NVIDIA/Megatron-LM#8230](https://github.com/NVIDIA/Megatron-LM/pull/8230).** That fix must be available in Bridge's Core dependency before this PR merges. This PR does not change the Core submodule pin.

# Changelog

- Allow MFSDP v2 checkpoint save/load with `fsdp_dtensor`.
- Restore model state through the original wrapper, matching Core's loader, so the MFSDP v2 adapter refreshes BF16 compute weights from the restored main weights.
- Add an EP=2 regression to the existing two-GPU MFSDP functional suite. Reuse its small MoE model and training helpers; save after steps 1–2, rebuild and load, then compare resumed steps 3–4 exactly against uninterrupted training. Check the executed step numbers and require the checkpoint to exist.
