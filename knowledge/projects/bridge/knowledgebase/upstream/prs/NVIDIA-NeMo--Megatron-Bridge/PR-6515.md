# test(recipe): run DeepSeek V4 SFT smoke test from toy init

## Original PR description

# What does this PR do ?

Fixes the DeepSeek V4 SFT functional test, which fails `L0_Launch_recipes_deepseek` on H100 and GB200 on `main` (first failing `main` run at 30efd7989) and on every PR that merges current `main`.

```
AssertionError: Finetuning requires a loading from a pretrained checkpoint or resuming from a checkpoint
```

**How it started:** the test sets `checkpoint.pretrained_checkpoint = None` and `checkpoint.load = None` and calls `finetune()`, which has required one of them since #4667. Until 2026-10-16 the DeepSeek V4 toy model (`/home/TestData/megatron_bridge/models/deepseek_v4_toy`) was missing from CI test data, so every DeepSeek recipe test skipped. No PR added the toy model. It was put directly on the runners' test-data volume that day, between 10:31 UTC (#6501's H100 job still skipped) and 11:40 UTC (#6502's GB200 job found it), on both the H100 and GB200 runners. Since then the pretrain tests run and pass, and this test fails.

# Changelog

- Run the SFT recipes through `pretrain()` instead of `finetune()`. The smoke test starts from the toy model's initialization and swaps in a mock dataset. `finetune()` only adds the checkpoint requirement on top of `pretrain()`, so the SFT recipe configs get the same coverage.
- Drop the `num_layers`, `num_moe_experts`, `moe_router_topk`, `moe_layer_freq` and `csa_compress_ratios` overrides. Since #5860, HybridModel derives these from the toy HF config, and #5860 removed them from the pretrain test for that reason. The SFT test kept them because it was skipping in CI. The remaining overrides are the pretrain test's set plus single-rank parallelism.
- Use the pretrain test's Megatron Core guard, which also requires `hybrid_dsv4_stack_spec`, so older cores skip instead of failing.
- Check `hasattr` before applying each model override (AGENTS.md testing rule).

# Verification

- `ruff check` and `ruff format --check` pass (ruff 0.9.9, the pre-commit pin).
- Not run locally: the test needs GPUs and the CI toy model. This PR's L0 run is the check. The launcher stops at the first failure (`-x`), so the `no_mtp_sft` and `sft_openmath_thinking_packed` cases have not run in CI before.
