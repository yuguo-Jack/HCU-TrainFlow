# chore(docker): AUT-2347 update Nsight Systems to 2026.5.1

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6114) · state: open · merged: False

## Original PR description

## Background

Nsight Systems in the MB framework-base image is selected at build time via `ARG NSYS_VERSION` (passed by the CI build caller); the repo intentionally keeps no in-repo default. The only in-repo version strings were the stale `2026.1.0.1085` examples in the README and install script. This PR targets the release branch `r0.6.0` to move those references to **2026.5.1**. It deliberately adds **no** repo-side default: selecting the executable nsys apt package remains the build caller's approved decision.

## What changed

- `docker/README.md`: NSYS_VERSION example `2026.1.0.1085` → `2026.5.1`.
- `docker/common/install_nsys.sh`: comment example updated to `2026.5.1` → package `nsight-systems-2026.5`.

No change to `docker/Dockerfile.fw_base` (a prior revision added an `ARG NSYS_VERSION=2026.5.1` default; that was reverted after commit-approval review because a repo default would pick the executable package version for all builds).

## Details

`install_nsys.sh` derives the apt package as `nsight-systems-<year.major>` and installs `=${NSYS_VERSION}-1`. For 2026.5.1 this resolves to `nsight-systems-2026.5=2026.5.1-1`, installed from the NVIDIA CUDA apt repo only when the build caller sets `REINSTALL_NSYS=True` and passes `NSYS_VERSION=2026.5.1`.

## Tested

- `bash -n docker/common/install_nsys.sh` — syntax OK.
- Verified year.major extraction: `2026.5.1` → `nsight-systems-2026.5`.
- Confirmed no remaining `2026.1.0.1085` / `nsight-systems-2026.1` references under `docker/`.
- Docs/comments only; no executable-dependency change, so no build-behavior delta.
