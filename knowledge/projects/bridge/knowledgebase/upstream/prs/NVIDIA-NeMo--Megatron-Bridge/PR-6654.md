## Background

This is the nightly MCore `main` bump for Megatron-Bridge (AUT-2625). Only the main lane is in scope. The dev lane is paused.

## What changed

- `.main.commit` and the `3rdparty/Megatron-LM` submodule move from `3630e44a` to `20527695` (MCore `main`).
- `uv.lock` is regenerated with `uv lock --upgrade`. The notable updates are:
  - huggingface-hub 1.33.0 → 2.3.0
  - fla-core / flash-linear-attention 0.5.2 → 0.6.0
  - diffusers 0.41 → 0.42
  - multidict 6.9.1 → 7.2.0
  - cuda-tile 1.7.0 → 1.8.0rc4
- `.dev.commit` (`4a4de865`) and `pyproject.toml` are unchanged.

## Details

- The TransformerEngine dependency metadata in Bridge matches MCore at `20527695`, so no metadata edits were needed.
- The huggingface-hub major-version change affects model, tokenizer and dataset loading in most tests. For that reason, the full main lane (unit and functional) was run, not a narrower selection.

## Tested

All runs were local H100 runs on this exact head `17d83710` (tree `10f45016`), with the validation image `agent-sandbox@sha256:59a24a1a…` and the `megatron-bridge` profile v16.

- Selected rows: 80 (4 unit, 76 functional).
- **Passed: 79. Skipped upstream: 0. Skipped platform: 1.**
- Platform skip: unit Core shard 1/3. The model `Qwen/Qwen3.5-122B-A10B` is not in the test data Hugging Face cache, so the 2 `test_qwen35_vl_122b_h100_pipeline_layout` cases were **not validated**.
- Some cases inside passing rows are skipped by the tests themselves because they need Blackwell GPUs, so H100 did not run them:
  - the DeepSeek-V4 MXFP8 recipe case;
  - `test_gtp_native_fp8_conversion.py:70` in `L1_Launch_gtp_checkpoint_conversion`.
- `L0_Launch_training_distributed_save` deselects 2 cases with its own `-m "not pleasefixme"` filter.
- GitHub CI on this head: pending.
