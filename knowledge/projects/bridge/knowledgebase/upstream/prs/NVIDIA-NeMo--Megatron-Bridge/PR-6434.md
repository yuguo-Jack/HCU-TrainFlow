# [sync][training] fix: honor checkpoint sharding validation policy

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6434) · state: closed · merged: True

## Original PR description

Setting `CheckpointConfig.ckpt_load_validate_sharding_integrity=False` currently still sends `validate_access_integrity=True` to Core's global checkpoint loader and save path. The fully-parallel save wrapper also retains its default validation policy. This leaves the inherited checkpoint configuration ineffective in supported recipe training.

Forward the policy to the global loader and to both save layers when the installed Core wrapper supports the save-side option. Preserve the development pin's load-only semantics, cached constant-structure behavior, and existing MIMO exceptions. Constructor capability is checked once at import.

Bases: Bridge `b1bb0a97ec5aad323eb2dd666e3f69aaebc1daff`; upstream Core main `a98aed553e25b4e86c59f50be54ac0ea4227b442`. Bridge's pinned Core: `e30d863a6d82a3c45f2d71355dc73fbf5610967b`. Development pin: `4a4de865795f123eda422ebf0a4c13d2418cf3cb`.

Source changes: https://github.com/NVIDIA/Megatron-LM/pull/4422 and https://github.com/NVIDIA/Megatron-LM/pull/5554. Related Bridge PR 6192 handles content-hash verification, a separate contract.
