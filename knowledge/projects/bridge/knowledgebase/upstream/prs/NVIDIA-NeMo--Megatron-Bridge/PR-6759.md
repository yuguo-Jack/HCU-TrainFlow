## Original PR description

Update MCore dev to `7b66fcc088e6e60b87c350e0e185721e0373d0ab` and validate it in ordinary PR CI. **Stage 1: `.dev.commit` and the submodule both point to dev; `.main.commit` stays unchanged. L0 only, without L1/L2 labels.**

After dev CICD NeMo passes, post the passing run link and tested SHAs, update this branch from Bridge main, restore the submodule and lockfile to the main pin while retaining `.dev.commit` and the compatibility fixes, then rerun L0 CI. The temporary dev submodule change must not merge.

**Known blocker reproduced on latest dev:** six BF16 Nemotron recipe-finalization tests still reject NCCL-EP grouped tensors without TE op-fuser. This is category **1 — Megatron-LM bug**: [MLM #7195](https://github.com/NVIDIA/Megatron-LM/pull/7195) fixed main, but dev retains the check after [#8813](https://github.com/NVIDIA/Megatron-LM/pull/8813). The focused local run had 29 passing and 6 failing cases. The correction is [MLM #8925](https://github.com/NVIDIA/Megatron-LM/pull/8925), targeting dev: all 35 Bridge recipe cases and 10 focused MCore config checks pass with it. Supported-hardware numerical CI and upstream review/merge remain pending. No recipe settings or assertions were weakened.

The updated dev lock adds only the dev dependency `nvtx`; other resolved package versions are unchanged from the merged Bridge main baseline. MCore metadata now matches dev (FlashInfer, cuDNN frontend, FLA extra, and Pillow requirements). Existing Bridge overrides remain in force. Lock check and all-file pre-commit passed in the Linux/CUDA container. Stage-1 [L0 CI](https://github.com/NVIDIA-NeMo/Megatron-Bridge/actions/runs/41685379706) is queued for Bridge head `8851c8ae6027b9fb7997246e3fc29143a1e0063e`.

Each change is tied to an upstream change below. Categories: **1 — Megatron-LM bug; 2 — no bug on either side, interface incompatibility; 3 — Bridge bug.**

Existing assertions remain. | 2 |

Earlier validation at `5821631877c0ff498c255e85737f2a437429c6f1` with dev `c4220af3` (not evidence for the refreshed head):

- Local dev unit run: **16,442 passed, 109 skipped, 59 failed** initially. After fixes and environment corrections, rerunning all 59 failures gave **48 passed and 11 failed**. This was not a fresh, fully passing suite.
- The remaining 11 are the **six upstream NCCL-EP cases**, **one Beam BF16 tolerance failure** also seen with main on local Ada GPUs, and **four cloud-plugin cases** that need Kubernetes configuration and also fail locally with main.
- **Four two-GPU functional tests passed:** pretraining/checkpointing, full-iteration graphs, TE attention graphs, and full-iteration graphs with optimizer capture. Each ran 10 updates with finite loss and no skipped or NaN updates; graph tests exercised capture and replay.
- **300 focused tests passed with MCore main.** Their dev counterparts and seven new context-parallel config regression cases also passed. Independent review, pre-commit, and main/dev dependency-lock checks passed. No assertions or numerical tolerances were weakened.
- [Full dev CI](https://github.com/NVIDIA-NeMo/Megatron-Bridge/actions/runs/41504798815) **failed before pytest started in all three core unit-test shards**: Docker reported the test container unavailable. These were infrastructure launch failures, separate from the locally reproduced NCCL-EP config bug. That earlier normal PR CI tested MCore main; the new stage-1 PR run tests the dev submodule.

Local GPU tests used two RTX 6000 Ada GPUs. The exact four-GB300 DeepSeek-V4 graph capture/replay test from the handoff has **not** been rerun for this PR.
