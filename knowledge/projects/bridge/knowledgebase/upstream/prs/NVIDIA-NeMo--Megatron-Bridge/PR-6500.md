# ci: stop norecursedirs from hiding 52 unit test files

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6500) · state: open · merged: False

## Original PR description

## What does this PR do?

`norecursedirs` in `pyproject.toml` lists `scripts`, `examples`, `tools` and `tutorials` to keep pytest out of the repo's top-level script directories. pytest matches those names against directory basenames at any depth, so they also hide `tests/unit_tests/scripts/`, `examples/`, `tools/` and `tutorials/`. The unit job (`pytest tests/unit_tests`) has never collected those 52 files (about 960 tests). They pass when a file is passed to pytest explicitly, because explicit paths bypass the filter. For example, the Muse Spark Open cases in `tests/unit_tests/scripts/training/test_recipe_metadata.py` pass locally but have never run in CI.

This PR ignores the top-level directories by path instead. A root `conftest.py` sets `collect_ignore`, which pytest resolves relative to that file, and `norecursedirs` keeps only the generic patterns (`.*`, `build`, `dist`, ...). The list also covers `3rdparty`: Megatron-LM has test files under same-named directories (`tools/run_inference_performance_test.py`), and `pytest .` from the repo root previously walked into the submodule's own `tests/` as well.

## Tests that went stale while CI skipped them

- `scripts/training/test_recipe_metadata.py`: #5062 added a library recipe named `nemotron_3_super_pretrain_64gpu_gb200_bf16_config`, the same name as an existing benchmark recipe, without listing the collision. I added it to `BENCHMARK_RECIPE_PRECEDENCE_COLLISIONS`. Bare lookup already resolves to the benchmark recipe, and the card's verified GB200 `pretrain_performance` item (mock data, forced routing) relies on that, so the only runtime change is the existing "exported by both packages" warning. For the recipe owner: the library GB200 recipe has no other name, so `train.sh --recipe` cannot reach it. That is already the case on `main`.
- `scripts/performance/test_recipe_environment.py`: expect `NCCL_EP_HT_EM_AG_SCAN_MODE`, which #6440 added to `DETERMINISM_ENV_VARS`.
- `examples/conversion/test_hf_to_megatron_generate_text_cli.py`: the fake provider implements `apply_overrides_and_finalize` (#5985).
- `examples/test_hf_to_megatron_generate_text_loading.py`: the `common_utils` stub provides `maybe_initialize_distributed` (#5995).
- `examples/conversion/test_hf_to_megatron_generate_vlm_cli.py`: expect the revision to be forwarded to `GenerationConfig.from_pretrained` (#5246).
- `scripts/test_performance_offline_mode.py`: the `nemo_run` stub provides `Script` (#4630).
- `scripts/training/test_run_recipe.py`: two benchmark dry-run tests now clear `WORLD_SIZE` and `SLURM_NTASKS`, like the neighbouring dry-run test. In a full shard, the `models/qwen_vl/modelling_qwen3_vl` test classes leave `WORLD_SIZE=1` behind (set in `setup_class`, never unset), and these tests then weak-scaled from DP 16 to DP 1.

## Skipped until nemo-run is bumped

`scripts/performance/utils/executors.py` uses `nemo_run.KubeflowExecutor` at import time, and the locked `nemo-run==0.4.0` does not have it. `test_executors.py` and the performance `test_setup_experiment.py` therefore fail at collection, which aborts the whole unit session. Both now skip with that reason. In `test_run_script_entrypoint.py`, only the one test that imports `setup_experiment` skips. Running them needs a newer nemo-run in `uv.lock`; 0.4.0 also lacks `SlurmExecutor(container_env=...)` and `Script(metadata=...)`. That bump should be its own dependency PR. `test_csp_plugins.py` already skips for the same reason.

The performance `test_setup_experiment.py` is renamed to `test_performance_setup_experiment.py`. These test directories have no `__init__.py`, so it would clash with `scripts/training/test_setup_experiment.py` ("import file mismatch") as soon as both import.

## Verification

Run on macOS with the locked package versions (CPU torch, Transformer Engine stubbed), so GPU paths are not covered here.

- `pytest --collect-only tests/unit_tests`: test files visited go from 512 to 562 and test items from 12,973 to 13,936. The only test files without items are the two module-level skips above and one `importorskip`.
- Throwaway test files in top-level `scripts/`, `examples/`, `tools/`, `tutorials/`, `docs/`, `src/` and `3rdparty/` are not collected by `pytest .`, while one in `tests/unit_tests/scripts/` is. Explicit paths into the top-level directories still work.
- The 52 files pass or skip, except 27 `test_container_runtime.py` cases that need bash 4.4 or later and fail with macOS's bash 3.2. That file passes on Linux with bash 5.1.
- `Launch_Unit_Tests_Core.sh` equivalent, all three shards, `main` against this branch on the same machine: none of the 12,396 tests that run on both changes outcome. The newly collected tests add 930 passes, 10 skips and the 27 bash 3.2 failures above.
- `pre-commit run --all-files` passes.
