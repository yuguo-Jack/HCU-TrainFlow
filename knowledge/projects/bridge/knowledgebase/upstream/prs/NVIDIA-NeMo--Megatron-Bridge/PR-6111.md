# fix(tokenizer): respect offline mode and local_files_only in _resolve_hf_tokenizer_revision

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6111) · state: open · merged: False

## Original PR description

# What does this PR do ?

Respects `HF_HUB_OFFLINE` / `local_files_only` and provides fallback to local cache when resolving revision-pinned Hugging Face tokenizers in `_resolve_hf_tokenizer_revision()`.

# Changelog

- In `src/megatron/bridge/training/tokenizers/tokenizer.py`, determine `local_files_only` from `hf_tokenizer_kwargs` or `HF_HUB_OFFLINE` from `huggingface_hub.constants`.
- Pass `local_files_only` to `snapshot_download()` and fallback to `local_files_only=True` if network error occurs.
- Add unit tests in `tests/unit_tests/training/test_tokenizer.py` covering offline resolution, retry fallback, and explicit `local_files_only` override.

Thank you for the thorough validation, and for catching the escaped exception. Confirmed the gap before fixing: httpx.ConnectError walks ConnectError -> NetworkError -> TransportError -> RequestError -> HTTPError -> Exception, never touching builtin ConnectionError, so the online-with-refused-connection case had no handler.

7da8ed0 adds httpx.TransportError to the caught tuple, imported behind a guard with a placeholder class that never matches when httpx is absent, so environments on older huggingface_hub (requests-based, builtin ConnectionError) are unaffected. The new regression test drives exactly your scenario: HF_HUB_OFFLINE=0, no local_files_only, first snapshot_download raises httpx.ConnectError, and the test asserts the second call resolves from the cache with local_files_only=True. It fails on 9f54739 with the escaping ConnectError and passes on 7da8ed0; the full tokenizer suite is 19 tests green locally (the one external model-download test excluded as in your run).

Also happy to have NVIDIA CI vet the updated head whenever a maintainer can approve it.
