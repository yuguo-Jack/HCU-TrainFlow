# fix(misc): fail sync inference when a prompt returns no result

## Original PR description



# What does this PR do ?

Fixes the sync inference CLI exiting 0 with an empty `GENERATED TEXT OUTPUT` banner when every prompt is rejected at engine admission, by failing when the engine returns fewer results than prompts.

# Changelog

- `scripts/inference/text_generation.py`: raise `RuntimeError` when `len(outputs) != len(prompts)`, before `_print_results`.
- `tests/unit_tests/inference/test_text_generation_entrypoint_results.py`: 2 tests covering both branches of the new check.

# Additional Information

- **Root cause:** #5748's guard filters the records `llm.generate()` returns. `DynamicInferenceEngine.generate()` (mcore `2a75ac12`) harvests records only from steps it runs, and `has_unfinished_requests()` ignores `failed_request_ids`, so an all-rejected batch returns `[]` and the filter has nothing to inspect.
- **Blast radius:** sync dynamic CLI only; the legacy static path and the async CLI (which delivers failed records over ZMQ) are unchanged.
- **Regression?** No — pre-existing. #5748 improved the mixed-batch case and did not introduce this.
- **Verification:** real `examples/inference/run_text_generation.sh` on EOS in `nvcr.io/nvidian/nemo:nightly` — pre-fix `exit 0` + empty banner; post-fix `exit 1`, no banner, `Inference failed: engine returned 0 result(s) for 1 prompt(s)`. Unit tests red-green verified (RED: DID NOT RAISE, exit 1; GREEN: 21 passed).
- **Not fixed here:** naming the failed request id requires mcore to return admission-rejected records (`3rdparty/Megatron-LM` is not modified from this repo). Separately, `norecursedirs` contains `scripts`, so `tests/unit_tests/scripts/` is never collected (0 of 10,015 ids) — hence the new test lives under `tests/unit_tests/inference/`.
- Related to # 5748

**Light review - LGTM**

The added guard correctly closes the gap where requests rejected at admission are never returned by the dynamic engine, so a partial result set no longer prints a misleading banner as if generation succeeded. The RuntimeError message is clear, the copyright year is correct (2026), and both the failure path and a regression (all-prompts-returned) path are covered by unit tests.

Minor observation (pre-existing, not introduced here): _print_results pairs outputs[idx] with prompts[idx] by position. The new count check makes this safe when counts match, but it relies on the engine returning results in prompt order. If ordering is ever not guaranteed, pairing by request_id would be more robust. Not blocking.

**Suggested test cases**
- test_dynamic_generation_rejects_missing_inference_results (added - verifies the mismatch raises and no banner prints)
- test_dynamic_generation_prints_results_when_every_prompt_returns (added - regression, full result set still prints)
- No perf tests impacted.
