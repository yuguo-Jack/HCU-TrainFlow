# fix(ckpt): make MIMO conversion timeout configurable

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6487) · state: open · merged: False

## Original PR description

# What does this PR do?

Fix a timeout issue during large MegatronMIMO checkpoint exports. 

**Cause:** 
Due to the speed difference in saving weights time for the language and vision components. Particularly, since the language component is much larger than the vision component, the vision ranks are done writing weights first, and have to wait for language ranks to finish. If writing takes more than NCCL's default 10 minutes, those image ranks time out and abort the export.

**Fix:** 
Raise the CLI timeout to **120 minutes** and make it configurable with `--distributed-timeout-minutes` or `DISTRIBUTED_TIMEOUT_MINUTES` in the Nemotron Omni example. Weight conversion is unchanged; the timeout must still be long enough for checkpoint I/O.

# Validation

- Exact 120B checkpoint from the QA report, eight H100s, original parallel layout: normal export completed in **4m50s**, with **43,079/43,079 tensors byte-identical**.
- A second real-model export included an **11-minute writer pause**. Image ranks waited **833 seconds** in the gather, exceeding the old 600-second limit, and export completed with **43,079/43,079 tensors byte-identical**. Both runs used the new default.
- Used `expandable_segments:True` to resolve a separate allocator-fragmentation OOM during import.
- 24 focused unit tests and all pre-commit checks passed. A scaled NCCL test also reproduced the original timeout/abort.

Addresses QA issue 6917686.
