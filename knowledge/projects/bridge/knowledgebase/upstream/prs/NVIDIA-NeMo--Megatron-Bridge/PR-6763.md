# [models] feat: shard frozen Qwen PLE tables across EP

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6763) · state: open · merged: False

## Original PR description

The Qwen3.8-Flash-Next PLE table is currently sharded with attention TP, so lowering TP substantially increases its per-GPU memory. This adds opt-in EP row sharding for **frozen** n-gram tables, while retaining the existing logical weight/key and shared text/VL decoder. At EP32, the approximately 95 GiB BF16 table occupies approximately 3 GiB per rank.

**Draft, stacked on #6354.** The default TP path is preserved. Select `ple_embedding_sharding="ep"`, `ple_freeze_ngram_embeddings=True`, and `expert_tensor_parallel_size=1`. Dense PLE projections, norms and convolution remain trainable. Trainable EP tables, CP, graph capture and scheduler changes are outside this PR.

### Attribution

The owner-routed request/return all-to-all and forked shard initialization are adapted from **@BestJuly's NVIDIA/Megatron-LM#7553**, specifically [`distributed_embedding.py` at `1ce7e86a073c18bcb6ea2ca5542c91e270d06a12`](https://github.com/BestJuly/Megatron-LM/blob/1ce7e86a073c18bcb6ea2ca5542c91e270d06a12/megatron/core/models/engram/distributed_embedding.py). Bridge preserves its single padded table instead of adopting the upstream multi-table representation. Attribution is also retained in the implementation and model documentation.

### Implementation

- Route only this rank's requested rows to their EP owners; support duplicate and empty requests. Hash complete sequences before SP slicing.
- Mark frozen shards as expert-DP replicas so ordinary dense-DP parameter broadcasts cannot overwrite distinct EP rows.
- Resolve HF import/export ownership from the destination module, preserving lazy shard reads and streamed default-dtype export. EP export broadcasts owner rows directly to preserve signed-zero and NaN payload bits.
- Describe the existing logical checkpoint weight using EP row offsets and expert-DP replica metadata.

### Validation

- Native NeMo 26.10.rc4 CPU preflight passed **70 tests**, including direct production imports, real four-process Gloo routing, all 17 new integration cases, existing Bridge/PLE tests, and private verification-harness checks.
- **TP1/EP32 passed on all 32 GB200 ranks** with the full checkpoint: exact local-row import, duplicate/empty/boundary lookup, streamed HF shard export, 4K hashed lookup, dense PLE forward/backward and update checks, and unchanged frozen-table hashes. A separate small native TP checkpoint was saved for the checkpoint-format resharding test.
- **TP2/SP also passed on all 32 ranks**, including full-table conversion/lookup and the separate native TP-to-EP checkpoint loading test. Full-model 4K TP1/EP32 Muon training completed one update on all ranks (loss1.9322, gradient norm11.6959), then exhausted GPU memory on the next forward. This is not a steady-state performance result.
- All pre-commit hooks passed; independent source review completed. Production source remains unchanged across the GPU attempts.

No 300 TFLOP/s result is claimed. The upstream 384–430 number uses an 8-layer, 32K-token GB300 proxy and additional kernel/graph optimizations; this PR initially ports the table distribution only. The following performance observation uses the full checkpoint rather than that proxy.

### Full-model performance observation

Job 8565127 completed 15 updates on 32 GB200 GPUs with sequence length 4096, TP2/SP, EP32, ETP1, CP=PP1, MBS1/GBS32, frozen PLE and Muon. No recompute, CUDA graphs or forced router balancing. After excluding the first 10 updates, the producer reports **4.214 s/update**, **31,103 tokens/s**, **40.88 estimated model TFLOP/s/GPU**, and **113.68 GiB peak allocated memory**. Loss moved from 1.93221 to 1.70620; retained gradient norms were finite (1.19370–11.33106).

Training exited successfully, but an output quota failure interrupted evidence publication. Independent review verified all 15 surviving final rank audits, including frozen-table invariance and Muon update checks; 17 final audits are missing. Aggregate performance remains provisional. This does not invalidate the earlier complete 32-rank correctness gates. The FLOP estimate uses the existing dense QSA surrogate, includes GR/PLE projection matrices, and excludes optimizer work and communication; tokens/s and update time are the primary performance measures. Parallelism and batch differ from the earlier baseline, so this is not an isolated EP-sharding speedup measurement.
