# fix(recipe): give Moonlight-16B 8-chunk pipeline layouts 27 decoder layers

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6359) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Fixes Moonlight-16B training at PP=8/VP=1 and PP=4/VP=2 failing at config finalization, because both recipe pipeline layouts listed 31 decoder layers for a 27-layer model.

# Changelog

- `src/megatron/bridge/recipes/moonlight/h100/moonlight_16b.py`: re-split the (8, 1) and (4, 2) layouts as front-loaded [4, 4, 4, 3, 3, 3, 3, 3] (27 decoders).
- `tests/unit_tests/recipes/test_moonlight_recipes.py`: 1 test that runs every supported Moonlight layout through Megatron-Core `PipelineParallelLayerLayout.validate_layer_layout` at the model depth.

# Additional Information

- **Root cause:** `_get_moonlight_pipeline_layout` (8, 1) and (4, 2) entries were `4 + 4*6 + 3 = 31` decoders; Moonlight-16B-A3B has `num_hidden_layers=27` and no MTP.
- **Blast radius:** only those two topologies, which never passed MCore validation; reachable from public PP overrides since #5708.
- **Regression?** No — the entries are unchanged since the recipe was added in #1133.
- **Verification:** unit test in `nvcr.io/nvidian/nemo:nightly` — RED `Number of decoder layers 31must match num_layers 27`; GREEN 1 passed; full module 17 passed.
- Related to #5708
