# refactor(model): build Qwen3 MoE from a builder-backed model config

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6592) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Moves **Qwen3 MoE** (Qwen3-30B-A3B, Qwen3-235B-A22B) onto the builder-backed `ModelConfig` / `ModelBuilder` path, for recipes and checkpoint conversion, following Qwen3 dense (#6365) and the other migrated families.

# Changelog

- **`Qwen3MoEBridge`**:
  - `provider_bridge()` is replaced by `hf_config_to_model_config_kwargs()`, and the provider path reuses the same kwargs.
  - The settings are unchanged: RMSNorm, QK layernorm, no QKV/linear bias, `moe_router_pre_softmax` derived from `norm_topk_prob`, aux-loss load balancing, alltoall dispatcher.
  - Fields whose builder-config default differs from the provider's (`masked_softmax_fusion`, `rope_scaling_factor`, `position_embedding_type`) are set explicitly. YaRN checkpoints keep `"yarn"` from the shared mapping.
  - Opts in with `MODEL_CONFIG_CLASS = BridgeGPTModelConfig` and converts through the builder (`USE_MODEL_CONFIG_FOR_CONVERSION = True`).
- **Recipes**:
  - The H100 Qwen3 MoE recipes use `get_model_config()` (7 call sites). The Qwen3 MoE perf recipes build on these.
  - Removed `cfg.model.moe_a2a_overlap = ...` from the library recipes and the H100/B200/B300 perf recipes. No model config declares the field and nothing reads it: A2A overlap is controlled by `comm_overlap.overlap_moe_expert_parallel_comm`, which is also what `scripts/performance` reads. The builder config rejects undeclared fields, so these lines would raise `AttributeError`.
- **Tests**:
  - Bridge: builder mapping, provider/builder parity (default, `norm_topk_prob=False`, tied fp16, YaRN), and `megatron_to_hf_config()` from a builder config.
  - New `recipes/qwen/test_qwen3_moe_recipes.py`: builds every Qwen3 MoE library and perf recipe against a real `BridgeGPTModelConfig`, so a field the builder config does not declare fails the test. The shared offline recipe fixture accepts any attribute.
  - `test_qwen_recipes.py`: the MoE fake bridge also overrides `get_model_config()`, and two assertions on the removed `moe_a2a_overlap` field are dropped.

# Verification

Tiny random-weight Qwen3 MoE checkpoints (4 experts), with `norm_topk_prob=True` and `False`, on a single GB200 node in the NeMo 26.10 container against `main` (Megatron Core ebab48fc4).

**Conversion paths:**
- `scripts/conversion` GPU import at TP2 and export.
- `AutoBridge.import_ckpt` / `export_ckpt`.
- Load + forward as in `compare.py`.
- `roundtrip_checkpoint`.

Each was run on this branch and on `main`.

| Check | `norm_topk_prob=True` | `norm_topk_prob=False` |
|---|---|---|
| Provider fields, `main` vs this branch (also an fp16 source and a YaRN config) | identical | identical |
| `get_model_config()` vs provider (also fp16 and YaRN) | 0 diffs | 0 diffs |
| Export vs source HF weights (GPU TP2, CPU, and from a `main`-imported checkpoint) | exact, 135 tensors | exact, 135 tensors |
| Logits: this branch vs `main`, and this branch on a `main`-imported checkpoint | bitwise-identical | bitwise-identical |
| Logits vs HF | cosine 0.999985 | cosine 0.999985 |
| `roundtrip_checkpoint` TP2 | pass | pass |

**Training (NeMo-CI L0 job `qwen3_30b_a3b_16gpu_h100`, run outside NeMo-CI):** NeMo-CI only tests `main`, so its L0 Qwen3-30B-A3B job was run on 2 H100 nodes for this branch (88e783dfa) and for its `main` base (4aa119666). Both used Megatron Core 89b28875 in the NeMo 26.10 container.

- **Setup.** Each run used NeMo-CI's in-container entry point and arguments: `scripts/performance/bootstrap.py --use_recipes -m qwen -mr qwen3_30b_a3b --task pretrain`. This builds `qwen3_30b_a3b_pretrain_16gpu_h100_bf16_config` (EP16 with HybridEP), run for 50 steps with GBS 64, MBS 1 and sequence length 4096.
- **Differences from NeMo-CI.** Mock data with a 32k `NullTokenizer` replaced RedPajama2, and no checkpoint was saved at step 50.

| Runs | Result |
|---|---|
| `main` vs this branch, `--deterministic` (`GPTModelProvider` vs `BridgeGPTModelConfig`) | Bitwise-identical at all 50 steps for lm loss, grad norm, load-balancing loss and learning rate (TensorBoard float32). Loss 10.785 → 1.438. |
| `main` vs `main`, `--deterministic` (control) | Bitwise-identical at all 50 steps |
| `main` vs this branch, NeMo-CI settings (non-deterministic fused kernels) | Identical at steps 1–2, about 1e-4 apart at step 3, then diverging as non-deterministic runs do. Final loss is 1.33 (`main`) and 1.04 (this branch). |

- **Stability.** No run had skipped or NaN iterations. Every run, including the deterministic `main` runs, had grad-norm spikes (up to 102) at peak learning rate on mock data, between steps 26 and 34.
- **Speed.** Median step time was 2.3–2.5 s in every run.

**Unit tests** (rerun after rebasing onto `main` with Megatron Core 89b28875): 803 passed, 1 skipped across `models/qwen`, `recipes/qwen`, `test_qwen_recipes.py`, `test_qwen_perf_recipes.py`, the MoE/perf recipe suites (`test_flex_dispatcher_recipes.py`, `test_gb300_ncclep_perf_recipes.py`, `test_moe_full_iteration_recipes.py`, `test_e2e_perf_recipe_recompute.py`, `test_perf_recipe_environment.py`, `test_bseries_nvfp4_full_iteration_recipes.py`, `test_r050_perf_recipe_ports.py`), `test_gpt_model_config.py` and `test_auto_bridge.py`.
