# fix(recipes): default library optimizers to FP32 state

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6683) · state: open · merged: False

## Original PR description

# What does this PR do?

Restore standard FP32 optimizer state in library recipes, with **DeepSeek-V3 as the only documented exception**.

The [DeepSeek-V3 technical report, section 3.3.3](https://arxiv.org/html/2412.19437v2#S3.SS3.SSS3) reports no observable degradation from BF16 Adam moments compared with FP32, while retaining FP32 master weights and accumulated gradients. Keep that combination in both V3 pretraining recipes. This is an author-reported comparison; it does not establish convergence of this Bridge implementation or justify reduced state for DeepSeek-V4 and other models.

For every other affected model, retain the FP32-state changes in this PR. No qualifying matched optimizer-state convergence comparison was found in the original/migration PRs or original-model sources reviewed for those models.

# Changelog

- Disable precision-aware Adam and use FP32 main parameters, main gradients and Adam moments in the other affected library recipes; retain their model compute and gradient communication precision.
- For DeepSeek-V3 only, retain precision-aware Adam with BF16 moments and FP32 master weights/main gradients. Enable FP32 gradient accumulation/reduction in both mixed-precision and DDP settings to match the paper's stated precision policy. Setting only `main_grads_dtype` does not change the accumulation buffer.
- Document the V3 exception and test its exact dtype combination. The two Qwen3 PA-only changes retain their already-FP32 state dtypes.
- Align Ultra FSDP gradient delivery and remove PA-only checkpoint staging settings.
- Make inherited benchmark optimizer settings explicit so `perf_recipes` keeps its existing behavior.
- Check effective defaults across public library factories and cover affected benchmark inheritance. Document increased memory requirements.

# GitHub Actions CI

- Before the V3 exception update, native RC5 CPU validation: **1,342 tests passed** across the two factory matrices and 12 affected family test files, using offline fixtures and a cached public Super config; no model weights required.
- All-files pre-commit passes. Independent review covered the initial FP32-state changes. V3 exception update in RC5: **838 passed**, including both factory matrices and the V3 checks. One additional, unchanged V4 PEFT construction test failed because its public HF config was absent from the offline cache. Corrected before/after comparison covered all 783 factories: only the two V3 library variants changed; all 451 benchmark optimizer, checkpoint-staging and gradient-precision snapshots remained identical. The one intentionally unsupported Qwen3-Next PEFT factory retained its expected error.
