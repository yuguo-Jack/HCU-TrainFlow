# fix(model): honor explicit meta-device disable

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/5952) · state: open · merged: False

## Original PR description

## Why

`init_model_with_meta_device` is an optional override with three meanings: `True` enables meta initialization, `False` disables it, and omission or `None` preserves the provider setting. The construction path currently checks the override's truthiness. That ignores explicit `False` and chooses the construction device directly from the override. The provider configuration and the actual construction context can therefore disagree.

The distinction is used by model construction and checkpoint/export consumers that request real CPU or GPU tensors. This follows the CPU-initialization override contract already merged in #5925.

## What changed

- Update the provider only when `init_model_with_meta_device is not None`.
- Select the construction context from the resulting provider value. Enable `torch.device("meta")` when that value is true and retain the caller's context otherwise.
- Apply the same behavior through direct `get_model` calls and `provide_distributed_model`, whose existing forwarding remains the single path into construction.
- Document the tri-state contract on both public entry points and `GetModelKwargs`.
- Cover omission, explicit `None`, and both boolean overrides using the existing model-instantiation regression, including restoration of the surrounding device context.

The provider value remains the authoritative configuration for later allocation and wrapping stages. ModelProviderMixin's existing deprecation and its replacement API are unchanged.
