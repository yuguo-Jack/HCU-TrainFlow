# fix(build): cap PyNvVideoCodec RTSP redirects

[Upstream PR](https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6656) · state: closed · merged: False

## Original PR description

## Summary

Backport FFmpeg's RTSP redirect limit (upstream commit f5d4fd186c68913240c4f6e9cda98443e1518b34) to the FFmpeg 9.0.1 library bundled in PyNvVideoCodec 2.2.3. This addresses CVE-2026-107696 without removing PyNvVideoCodec or changing its library ABI.

The final-image build uses the source archive included in the pinned wheel, verifies its SHA-256, applies the upstream patch, and rebuilds `libavformat.so` with the wheel's configuration. It checks that the rebuilt library exports the same symbols before replacing all three installed aliases. The build fails if the wheel or ABI changes unexpectedly.

## Validation

- Rebuilt the x86_64 wheel's FFmpeg library in the NVIDIA PyTorch 26.09 base container; the rebuilt library loaded successfully.
- Compared all 2,326 exported symbols with the original wheel: identical.
- A local RTSP server returning repeated 302 responses produced a bounded error after nine responses (`Too many RTSP redirects`).
- Confirmed that the x86_64 and aarch64 wheels contain the same FFmpeg source archive hash and configuration flags. An arm64 smoke build under QEMU rebuilt the patched library and loaded it successfully; the full NeMo image build remains to be validated in CI.
- `bash -n` and repository pre-commit hooks passed.

## Scan note

This is a source patch backport to FFmpeg 9.0.1. Version-based scanners may continue to report CVE-2026-107696 until PyNvVideoCodec publishes a wheel with a patched FFmpeg release or the scanner accepts evidence of this backport.

[P2] Add a behavioral regression check for the installed library

The redirect bound has no checked-in regression test. The [export comparison](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/5f90026956484e8eeed62d404653649d08592d68/docker/common/patch_pynvvideocodec_ffmpeg.sh#L47-L52) cannot distinguish the intended limit from, for example, changing this threshold from 8 to 80: both export the same symbols. The inspected [CI image build](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/5f90026956484e8eeed62d404653649d08592d68/.github/workflows/cicd-main.yml#L533-L554) also builds `Dockerfile.ci`, not the final-image stage applying this backport. The reported manual test is useful, but the repository checks do not enforce the security fix's behavior.

Add a CPU-only localhost RTSP smoke test and invoke it after the [installed-library replacement](https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/5f90026956484e8eeed62d404653649d08592d68/docker/common/patch_pynvvideocodec_ffmpeg.sh#L54-L57), or in final-image validation. Exercise the installed PyNvVideoCodec `libavformat`, not a separate system `ffmpeg` executable. Keep the production guard unchanged: the invariant is at most eight followed redirects per connection, while valid bounded chains remain usable. Exact test implementation depends on the wheel/API details unavailable in this snapshot, so no implementation patch is supplied.

Proposed acceptance checks: an always-302 fixture returns an error with `Too many RTSP redirects` after the ninth redirect response, before a safety timeout; zero-, one-, and eight-redirect chains ending in a valid session still open; two independent bounded connections each succeed with a fresh budget. Run against both amd64 and arm64 replacements. Confirm that the loop assertion fails against the original unpatched wheel and against a threshold-of-80 mutation. These are proposed checks, not executed results.
