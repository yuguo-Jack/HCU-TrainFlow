## Background

Nightly Megatron-Core `main` bump for Megatron-Bridge `main`. The dev lane is out of scope for this run: `.dev.commit` is unchanged (`4a4de865`).

## What changed

- `.main.commit` and the `3rdparty/Megatron-LM` gitlink now point to MCore `3e95097b4a9ab6ea6b2a39eb2b2b24e4a6dfa54a`. The previous pin was `9131593673d0`.
- `uv.lock` regenerated with `uv lock --upgrade` using uv 0.7.2 (lock revision 2 kept). Runtime-relevant upgrades are `cuda-bindings` 13.4.3→13.4.4 and `cuda-python` 13.4.1→13.4.4. `uv lock --check` passes.

## Details

MCore delta (4 commits):
- #7758: context parallelism in MIMO.
- #7772: inference CUDA graphs with Shortcut MoE / wide residual.
- #7774: validation for full-iteration CUDA-graph replay.
- One copy-pr-bot commit.

Tests were selected from this delta and the lock changes. Functional launchers that don't touch the changed paths were recorded as excluded, not as passed.

## Tested

Run locally on H100 (2 GPUs) at this exact head, using a validation image built from this commit with `docker/Dockerfile.ci`:
- Unit: Core shards 0/3, 1/3, 2/3 (12,276 passed in total) and Diffusion (573 passed).
- Functional: `L0_Launch_megatron_fsdp`, `L0_Launch_models_nemotron_omni`, `L0_Launch_training_megatron_mimo`, `L1_Launch_recipes_nemotron_omni`, `L2_Launch_recipes_llama_cuda_graphs`. All passed.

Note: `L0_Launch_megatron_fsdp` and Core shard 1/3 first failed inside FlashAttention-4 backward kernels. This predates the bump: the image's cutlass-dsl 4.8.0 does not match what flash-attn-4 4.0.0b24 needs (4.6.0.dev0). Both rows passed when rerun with the CI test-template attention policy (`NVTE_FLASH_ATTN_V2=1 NVTE_FLASH_ATTN_V3=0 NVTE_FLASH_ATTN_V4=0`).
