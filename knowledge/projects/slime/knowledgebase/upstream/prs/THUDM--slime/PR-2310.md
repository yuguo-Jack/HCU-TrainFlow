# fix(megatron): compact actor logits before projection

[Upstream PR](https://github.com/THUDM/slime/pull/2310) · state: open · merged: False

## Original PR description

## Summary

Long masked prompts still produce full `[T, V]` vocabulary logits before Slime selects trainable tokens, causing the projection and fp32 conversion peaks in #2253. Add opt-in `--compact-actor-logits` to project only the `N` loss-masked rows for eligible built-in actor policy/SFT paths.

A Slime-owned `CompactLogitsGPTModel` is selected only for eligible actor post-process chunks. Log-probability/entropy computation accepts `[N, V]`, builds compact top-p masks, and scatters scalar results back to the existing response/CP layout. Empty masks retain zero-gradient connections.

Critics, custom providers/hooks/losses, MTP, TIS/mismatch metrics, debug capture, rollout log-probs, PPO reward-KL, score centering, MuP scaling, and custom Megatron output processors preserve the full-logit path. The optimization is disabled by default and can be enabled with `--compact-actor-logits` for eligible built-in paths.

Normal forward and combined 1F1B both resolve the model's `_postprocess` method dynamically. The context covers the pipeline schedule call. Model state-dict keys and checkpoint ownership are unchanged.

Fixes #2253.
