# feat(ray): add --disable-retain-serving

[Upstream PR](https://github.com/THUDM/slime/pull/2508) · state: closed · merged: False

## Original PR description

## Background

Retained serving was introduced on October 7, 2026, in commit 4a7a50909ac310b7b23caf851ef05a2af26baa74 ("Support manual Megatron restarts with retained serving", #2444).

It preserves internal serving resources after training failures or `ray job stop` for reuse by a later job. For runs that do not need this capability, retained actors and GPU allocations require separate cleanup.

## Changes

Add `--disable-retain-serving` to make `ServingCluster` and `RolloutManager` follow the Ray job lifetime instead of using named, detached actors. When this flag is set, startup or training failures dispose both owners through the existing cleanup mechanism.

Serving retention remains enabled by default, and external-serving ownership is unchanged. Existing detached sessions are not automatically cleaned up by this flag.

The lifecycle setting is excluded from recovery configuration comparisons to preserve session identity and journal compatibility. The PR includes targeted tests and English and Chinese documentation.

## Validation

- 162 tests passed across argument validation, placement group, and training recovery tests.
- `git diff --check` passed.
- Manually verified that adding `--disable-retain-serving` to the launch script successfully starts end-to-end post-training and that resources are released after `ray job stop`.
- Training recovery with the default retained-serving mode (without `--disable-retain-serving`) was not tested end to end.
