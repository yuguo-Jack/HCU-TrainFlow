# fix(data): give uniform reward groups exactly zero advantage

[Upstream PR](https://github.com/THUDM/slime/pull/2494) · state: open · merged: False

## Original PR description

## What does this PR do?

When every rollout in a prompt group gets the same fractional reward, there is no preference between them, so every advantage in the group should be exactly zero. In `_post_process_rewards` the group is centered in float32, and for identical rewards that can leave a residue of about an ulp instead of zero. With std normalization on, the residue is then divided by its own std, which turns it into a small nonzero advantage shared by the whole group.

Small reproduction on current main (a group of 16 rollouts that all scored 0.3, `grpo` with `grpo_std_normalization`):

- centered reward for each rollout: `+2.98e-08` instead of `0`
- advantage after std division: about `+0.0298` for every rollout in the group (0.6 gives about `+0.0596`, 0.9 about `-0.0596`)

So a group where all samples earned the same partial credit still pushes the policy, always in the same direction for the whole group. I ran into the same class of problem in the Miles fork's copy of this code (RadixArk/miles#4019, fixed there); this repo's version has the same arithmetic, so I am sending the fix here as well.

## The change

`slime/data/batch_builder.py`, inside `_post_process_rewards`: if a group's rewards are all finite and all equal, write exact zeros for that group and skip the centering for it. Everything else is unchanged. Groups with a NaN or an infinite reward are deliberately left alone, so a bad reward keeps propagating as NaN instead of being quietly turned into zero.

This covers `grpo`, `gspo`, `cispo` and `reinforce_plus_plus_baseline`, since they all share this normalization block.

## Tests

New cases in `tests/test_grouped_rewards.py`:

- `test_uniform_fractional_rewards_have_exactly_zero_advantage`: rewards 0.3, 0.1 + 0.2 and 0.9, 16 rollouts in one group, for all four estimators, with std normalization on and off. All advantages exactly 0. (On main, the 24 cases with std normalization or the centering residue fail.)
- `test_uniform_group_next_to_mixed_group`: a uniform group batched with a mixed [1, 0, 0, 0] group. Only the uniform group is zeroed.
- `test_uniform_nonfinite_rewards_stay_nonfinite`: uniform NaN and infinite groups stay NaN.
