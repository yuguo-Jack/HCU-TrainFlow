## Original PR description

# [ROCm] Support ROCm 7.15 on MI300/MI325

## Summary
- The previous images and `amd_tutorial` docs no longer support proper model training; they have been updated to better align with the ROCm ecosystem.
- Rebuild the ROCm image on `rocm/primus:v26.5` so MI300/MI325 (gfx942) tracks the CUDA image's SGLang v0.5.21 and Megatron-LM `core_v0.19.2` stack. slime is cloned from THUDM/slime main at build time.
- Align both language tutorials with the existing Qwen3-4B AMD recipe (`Qwen3-4B-Instruct-2507`), and clear the Primus attention-backend overrides that conflict with `--attention-backend`.

## Changes

- Replace `docker/Dockerfile.rocm`. The image starts from `rocm/primus:v26.5` and keeps that image's torch, triton, aiter, flash-attn, and Transformer Engine. It clones THUDM/slime main, installs SGLang v0.5.21 (`e00930c`) with the `docker/patch/v0.5.21` patch stack from that clone, builds `sgl-kernel` through `setup_rocm.py`, builds `torch_memory_saver` for HIP, and installs Megatron-LM `core_v0.19.2` (`4b4acac9`). The default GPU target is gfx942.
- Pin runtime library and device settings in the image: `LD_LIBRARY_PATH` follows the copies torch and Transformer Engine load, `GPU_ARCHS` is the build target, and `RAY_EXPERIMENTAL_NOSET_HIP_VISIBLE_DEVICES=1`. An entrypoint unsets `NVTE_FLASH_ATTN`, `NVTE_FUSED_ATTN`, and `NVTE_UNFUSED_ATTN` so every `docker run` process drops the Primus presets. Transformer Engine reads these with `int(os.getenv(...))`, so the variables have to be absent.
- In `scripts/run-qwen3-4B-amd.sh`, unset the same three `NVTE_*` variables before launch. The recipe uses `--rm-type dapo` with `--reward-key score`, 8192-token rollout and eval responses, `--num-rollout 100`, `--eval-interval 10`, and `--skip-eval-before-train`. The checkpoint stays `Qwen3-4B-Instruct-2507`.
- Rewrite `docs/en/platform_support/amd_tutorial.md` and `docs/zh/platform_support/amd_tutorial.md` to build or pull `amdagi/slime:rocm7.15_torch2.12_py3.12`, download `Qwen3-4B-Instruct-2507`, and run the same conversion and training commands. Conversion still passes `--use-cpu-initialization`. The `NVTE_*` unset is not in the conversion snippet; the image entrypoint clears those variables.
