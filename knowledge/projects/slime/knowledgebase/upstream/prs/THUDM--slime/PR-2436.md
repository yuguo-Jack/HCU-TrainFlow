# fix(data): address optional Straw and trusted top-p validation regressions

[Upstream PR](https://github.com/THUDM/slime/pull/2436) · state: open · merged: False

## Original PR description

## Summary

Fix two independent CPU regressions present on `main`: an optional Straw import on the object-store path and incomplete validation of new sampled-token metadata against previously validated top-p support. They are separate commits. Both fixes are included here because the full PR CPU suite runs both affected tests, so either fix alone leaves the other job red.

| Path | Problem on `main` | Change |
| --- | --- | --- |
| Object-store rollout without a queue lease | `group_lease()` imports `straw.protocol.Lease` before it checks whether the group has a lease. The no-lease path can fail with `ModuleNotFoundError` even though it does not use Straw. | Return `None` for a no-lease group before importing Straw. Lease-backed groups still construct the same `Lease` after authorization checks. |
| Validated top-p support plus new sampled-token metadata | `TensorRef.validated` proves the stored support was validated earlier, but the fast path also skips comparing a *new* `tokens`/`sampled_logps` pair with that support. | Keep the no-payload-read fast path when no new tokens are supplied. When new tokens are supplied, run the existing bounded support scan and check membership and recorded log-probabilities. |

The original failures are visible in the [base-branch CPU workflow](https://github.com/THUDM/slime/actions/runs/36706056601). They also reproduce on the current `main` used for this update.

## Regression coverage

- Extend `test_optional_straw.py` to call `group_lease()` on an object-store group in a subprocess that blocks Straw imports. This directly covers the no-lease path. The existing dynamic-filter regression also runs in the CI environment without Straw.
- Update the top-p transport regression to use 4,097 rows, crossing the implementation's 4,096-row chunk boundary. It checks continuous, bounded and matching ID/log-probability reads, then rejects a changed sampled token.
- Preserve the metadata-only republication check for validated references when no new sampled tokens are supplied.

The changes do not alter sampling probabilities, queue authorization, or the reference-policy replay fix in #2434.
