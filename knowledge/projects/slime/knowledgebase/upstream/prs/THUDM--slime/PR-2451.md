# fix(qwen3.5): average TP-replicated linear-attention gradients across TP

[Upstream PR](https://github.com/THUDM/slime/pull/2451) · state: open · merged: False

## Original PR description

## Summary

In the Qwen3.5 spec, `slime_plugins/models/qwen3_5.py` adds the linear-attention layers (`linear_attn` = `Qwen3_5GatedDeltaNet`, plus `input_layernorm`) as a `HuggingfaceAttention`. These parameters are **replicated** on every tensor-parallel rank, not sharded, but nothing synchronizes their gradients across TP.

`hf_attention.py` gathers the sequence-parallel input before these modules, so in exact arithmetic every TP rank computes the same full gradient. In practice the kernels are not bitwise deterministic across ranks. The replicas drift apart a little more every step, so TP ranks end up training slightly different weights, and a distributed checkpoint keeps only one of the copies.

This PR marks these parameters with `average_gradients_across_tp_domain = True`. Megatron's `finalize_model_grads` (`_allreduce_non_tensor_model_parallel_grads`) then averages their gradients across the TP group, so the replicas stay identical. With TP=1 it is a no-op: that path returns early when the TP group size is 1.

## Evidence

A/B on Qwen3.5-9B SFT, 2 nodes × 8 B200, TP=2 / PP=2, 30 training steps, same data and seed. The only difference is the gradient flag. A test-only probe compared each replicated parameter across the 2 TP ranks after every step (all-reduce MAX − MIN):

| step | without this change | with this change |
| --- | --- | --- |
| 0 (after init) | 0 / 120 params differ | 0 / 120 |
| 2 | 74 / 120 differ, max abs diff 3.1e-5 | 0 / 120 |
| 5 | 82 / 120, max abs 1.2e-4 | 0 / 120 |
| 30 | 85 / 120, max abs 2.4e-4 (max rel 0.19%) | 0 / 120 |

We first saw this in a strict save/restore check that compares per-rank tensor fingerprints (Qwen3.5-35B, TP2). At save time, the source TP ranks already held different values for these replicated weights. The checkpoint stores a single copy, so the restored TP1 no longer matched the source TP1. In a 122B A/B, the extra all-reduce cost +0.24% step time.

These runs used a slime 0.3.0-based build. On `main`, the `Attention` class touched here differs only by a new `name` argument, and the sequence-parallel gather/scatter in `hf_attention.py` is the same. I haven't rerun the A/B on `main`.

## Notes

- `qwen3_next.py` builds its linear attention the same way and may need the same change. I haven't measured it, so it's not included here.
- No new test: reproducing the drift needs a multi-GPU TP run. Happy to add a test if there's a preferred harness for this.
