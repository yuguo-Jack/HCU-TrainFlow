# fix(qwen3.5-vl): skip the CP index mapping when there is no context parallelism

[Upstream PR](https://github.com/THUDM/slime/pull/2376) · state: open · merged: False

## Original PR description

## Summary

With `--context-parallel-size 1`, the Megatron Qwen3.5-VL path cannot complete a
training step: any packed sequence with an odd token count is rejected before
the first optimizer step. `examples/geo3k_vlm/run_geo3k_qwen35.sh` sets CP 1, so
the example ships in that state.

This PR makes `_inject_vision_embeddings()` skip the CP→packed index mapping
when there is no CP group, which is the same condition `gather_packed_input_ids()`
already short-circuits on. One file, no behaviour change for `cp_size > 1`.

## The bug

```
File "slime_plugins/models/qwen3_5_vl.py", line 163, in _inject_vision_embeddings
    local_indices = get_packed_cp_local_indices(
File "slime_plugins/models/qwen3_5_vl_utils.py", line 22, in get_packed_cp_local_indices
    raise ValueError(f"Packed sequence length {sequence_length} must be divisible by 2 * CP size {cp_size}")
ValueError: Packed sequence length 4551 must be divisible by 2 * CP size 1
```

`get_packed_cp_local_indices()` maps a CP rank's local tokens back to the packed
stream through Megatron's two-chunk zigzag layout, which splits every sequence
into `2 * cp_size` chunks — hence the divisibility requirement. The check is
correct for that layout, but `_inject_vision_embeddings()` calls the helper
unconditionally, passing `cp_size=1` when no CP group exists. At `cp_size=1` the
requirement degenerates into "every packed sequence must have an even length".

Packed lengths are whatever the micro-batch happens to pack, so about half of
them are odd. A run therefore survives until the first odd pack and then dies
inside `train_one_step`.

## Reproduction

* Model `Qwen/Qwen3.5-35B-A3B`, `examples/geo3k_vlm` (GEO3K), Megatron training
  backend, `--colocate`, `TP2 / PP1 / CP1`.
* Observed on 1 node × 8 GPUs at EP8 and on 2 nodes × 16 GPUs at EP16 alike —
  the failure does not depend on the parallel layout, only on CP being 1.
* Rollout 0 generates normally; the job fails ~140 s into the first
  `train_one_step`, at whichever micro-batch first packs to an odd length.

Any VL run with `--context-parallel-size 1` and packed sequences reproduces it;
no images or dataset specifics are required beyond taking the vision-injection
path.

## The fix

```python
if cp_group is None or cp_group.size() == 1:
    local_indices = None
else:
    local_indices = get_packed_cp_local_indices(
        cu_seqlens, cp_group.size(), cp_group.rank(), input_ids.device
    )
local_feature_indices = feature_indices if local_indices is None else feature_indices[local_indices]
...


Why this is the identity case, not a suppressed check:

* `forward()` builds `full_input_ids` with `gather_packed_input_ids()`, which
  returns `input_ids` unchanged when the CP group is `None` or of size 1. So at
  CP 1 the full packed stream and the local stream are the same tensor.
* `feature_indices` is built over `full_input_ids`, i.e. already in local order,
  and `feature_indices[arange(n)] == feature_indices`.
* Where the helper previously succeeded at `cp_size=1` (even lengths), it
  returned exactly that identity range — first half of each sequence followed by
  its second half. No output that used to be produced changes.

The token-layout assertion right below the change is kept and still runs: at
CP 1 both sides have the same length, so it remains a meaningful check.

## Why the call site rather than the helper

`get_packed_cp_local_indices()` and its divisibility check are left untouched.
The check describes a real constraint of the two-chunk layout that function
implements; what is wrong is asking it for a mapping when no CP split exists.
Fixing the caller keeps the helper's contract intact and matches the
short-circuit `gather_packed_input_ids()` already performs for the same
condition.

## Scope and risk

* `slime_plugins/models/qwen3_5_vl.py` only, +18 / −7.
* `cp_size > 1` takes exactly the same path as before.
* `tests/test_qwen3_5_vl_native.py::test_thd_cp_indices_select_two_chunks_per_packed_sequence`
  covers the helper at `cp_size=2` and is unaffected.

## Testing

* Existing unit tests are untouched and still describe the `cp_size > 1` layout.
* Verified end to end by rerunning the GEO3K configuration above, which
  previously stopped at the `ValueError` in the first training step.
* No unit test is added for the CP-1 path: it lives in
  `_inject_vision_embeddings()`, which needs a constructed `Qwen3_5VLModel`
  (Megatron parallel state, a vision tower and an embedding layer), which the
  current pure-`torch` test module cannot build. Happy to add one if you would
  prefer the fix inside `get_packed_cp_local_indices()` instead, where it is
  directly unit-testable.

I hit the same error with Qwen3.5-0.8B at slime 41014d1, on 2 GPUs with TP 1 and CP 1:

```
ValueError: Packed sequence length 1109 must be divisible by 2 * CP size 1
```

It failed in the first training step. The failing sample was text-only, so a micro-batch with no image fails too. About half of the samples have an odd length: 5198 of 10240 in my 40-step 0.8B run.

CPU reproduction on main `05e3b017`. It needs only `torch` and slime:

```bash
python -c "import torch; from slime_plugins.models.qwen3_5_vl_utils import get_packed_cp_local_indices as f; f([0, 1109], 1, 0, torch.device('cpu'))"
```

I used the helper-side variant that the description offers at the end. It returns `torch.arange(boundaries[0], boundaries[-1], device=device)` when `cp_size == 1`. Results:

- With it, 40 training steps ran on Qwen3.5-0.8B and on Qwen3.5-2B, both with TP 1 and CP 1.
- On CPU, the output is the same as on main for even lengths at CP 1 (500 random cases), and for all ranks at CP 2, 4 and 8 (1400 cases). Bad lengths still raise at CP > 1.
- `tests/test_qwen3_5_vl_native.py`: 8 passed on main `05e3b017` with the change.

With the helper-side variant, this pure-`torch` test covers CP 1. It fails on main and passes with the change:

```python
@pytest.mark.unit
def test_thd_cp_indices_are_identity_without_cp():
    indices = get_packed_cp_local_indices([0, 3, 4, 7], cp_size=1, cp_rank=0, device=torch.device("cpu"))
    assert indices.tolist() == list(range(7))
```

I did not run the call-site version in this PR. It covers the same case. `examples/geo3k_vlm/run_geo3k_qwen35.sh` uses CP 1, so merging either version would let the example train.
