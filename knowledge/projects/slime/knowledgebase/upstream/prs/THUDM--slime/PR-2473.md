# fix(coding_agent_rl): snapshot fails when repo .gitignore ignores .harness

[Upstream PR](https://github.com/THUDM/slime/pull/2473) · state: closed · merged: False

## Original PR description

## Summary

`examples/coding_agent_rl/swe.py::_repository_tree` excludes the harness metadata directory with a pathspec:

```
git add -A -- . ':(exclude)PROBLEM_STATEMENT.md' ':(exclude).harness/'
```

When the task repo's own `.gitignore` already ignores `.harness` (for example a `.*` rule), `git add` treats the pathspec as naming an ignored path and exits 1:

```
The following paths are ignored by one of your .gitignore files:
.harness
hint: Use -f if you really want to add them.
```

`sb.exec(..., check=True)` then raises, `git_diff` fails, and `generate` aborts the rollout (`exception:RuntimeError`) before grading. Every rollout on such a repo is lost, regardless of the model.

This PR keeps `.harness/` out of the snapshot through a temporary `core.excludesFile` instead of a pathspec.

## How we hit it

Running MiMo-V2.6-RL-oss `format-code-task-002561` (sfcc-ci) with the Claude Code harness, all 4 rollouts aborted. The image ships sfcc-ci's upstream `.gitignore`, which contains `.*` / `!.github` (unchanged since 2019 in SalesforceCommerceCloud/sfcc-ci). On a fresh sandbox, calling `swe._repository_tree` directly:

| state | result |
| --- | --- |
| repo as shipped, no `.harness/` | ok |
| after the harness creates `.harness/` (as `slime/agent/harness/common.py` always does) | fails with the error above |
| `.harness/` present, `.*` removed from `.gitignore` | ok |

Reproduced with git 2.39.5 (in the image) and git 2.50.1.

## Fix

```sh
harness_excludes=$(mktemp)    # removed by the existing EXIT trap
echo .harness/ > "$harness_excludes"
git -c core.excludesFile="$harness_excludes" add -A -- . ':(exclude)PROBLEM_STATEMENT.md'
```

The snapshot content is unchanged:

- `.harness/` stays out whether or not the repo ignores it;
- the repo's own ignore rules still apply;
- `PROBLEM_STATEMENT.md` is still excluded by pathspec (it is not ignored, so that pathspec is safe).

Simply dropping `':(exclude).harness/'` would not be correct: on repos that do not ignore dot directories, `.harness/` would then end up in the patch.

`git_diff`'s `git diff ... ':(exclude).harness/'` is left as is: `git diff` between two trees does not reject pathspecs that match ignored paths.

## Test

Adds `test_patch_when_repo_gitignore_ignores_dot_directories` to `tests/test_agent/test_swe_workspace_diff.py` (already part of the CPU `agent-test` CI job). It uses the existing `LocalShell` / real git setup.

- Without the fix: the new test fails with the error above; the 3 existing tests pass.
- With the fix: 4 passed.
- `pre-commit run` on the changed files: all hooks pass.
