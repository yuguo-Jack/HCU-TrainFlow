# Keep a router's existing registration when an engine registers again

[Upstream PR](https://github.com/THUDM/slime/pull/2483) · state: open · merged: False

## Original PR description

## Problem

With external engines (`--rollout-external-engine-addrs`), slime registers each engine with the router on every run (`_init_external` → `_register_to_router`). `shutdown()` returns before `unregister_worker`, because the external cluster owns those processes. So the engines stay registered after the run, which is intended: they outlive it. A run that ends uncleanly leaves its launched engines registered the same way.

The next run POSTs the same URLs again. `sglang_router` 0.3.2 answers a repeat with 202, so this goes unnoticed with the default router. A router whose `POST /workers` is create-only answers `409 WORKER_ALREADY_EXISTS`, and `raise_for_status()` aborts the run before its first rollout. One such router is [SMG](https://github.com/smg-project/smg), whose `POST /workers` stays create-only (smg-project/smg#3976 was declined).

Reproduced with two engines served outside slime, SMG as the router, and two short runs back to back:

```
run 1: 3 steps
run 2: 0 steps
ray.exceptions.RayTaskError(HTTPError): ray::SGLangEngine.init() ...
requests.exceptions.HTTPError: 409 Client Error: Conflict for url: http://127.0.0.1:30100/workers
```

## Fix

Registration goes through a new `server_control.register_worker()`, next to `unregister_worker()`.
- On `409` with `code: WORKER_ALREADY_EXISTS`, it reads `GET /workers`. If the router lists the URL with the same payload slime would post (`url`, `worker_type`, and `bootstrap_port` for a prefill engine), it keeps that registration and logs it.
- Any other refusal raises as before: a registration that differs, another 409 code such as `WORKER_CREATE_IN_PROGRESS`, or another status.

Routers that answer 2xx, including `sglang_router`, see no change.

## Tests

`tests/test_server_control.py`, CPU-only, with a fake router:
- `test_register_worker_posts_the_payload`: 200 and 202;
- `test_register_worker_keeps_the_registration_an_earlier_run_left`: a matching prefill registration with its `bootstrap_port`;
- `test_register_worker_refuses_a_registration_that_differs`: another worker type, another or missing `bootstrap_port`;
- `test_register_worker_raises_any_other_refusal`: another 409 code, a 409 without a code, a 500.

```
$ python -m pytest -q tests/test_server_control.py tests/test_external_sglang_engines.py
26 passed
```

End to end on 4x H100: two engines served outside slime (`--rollout-external-engine-addrs`), Qwen3-0.6B, SMG as the router, and two 3-step runs back to back against the same router. The patch was cherry-picked onto `5bec7a10`; `slime/backends/sglang_utils/` is unchanged between that commit and `main`.

```
slime 5bec7a10:              run 1: 3 steps   run 2: POST /workers -> 409, 0 steps
slime 5bec7a10 + this PR:    run 1: 3 steps   run 2: POST /workers -> 409, registration kept, 3 steps
```
