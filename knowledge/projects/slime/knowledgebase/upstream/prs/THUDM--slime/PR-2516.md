# Add flattened bucket broadcasting for weight updates

[Upstream PR](https://github.com/THUDM/slime/pull/2516) · state: open · merged: False

## Original PR description



<p><span>This PR adds </span><code dir="ltr">--update-weight-broadcast-mode</code><span> to control how full weights are broadcast to rollout engines:</span></p><ul><li><code dir="ltr">per-param</code><span> (default): broadcasts each parameter separately.</span></li><li><code dir="ltr">flattened-bucket</code><span>: packs each update bucket into a single byte tensor and broadcasts it once, reducing collective calls.</span></li></ul><p><span>The flattened mode preserves mixed tensor dtypes and passes </span><code dir="ltr">load_format="flattened_bucket"</code><span> to SGLang for reconstruction and loading. The configuration is also forwarded through the tensor updater’s distributed path.</span></p><p><span>Flattened broadcasting requires </span><code dir="ltr">--update-weight-mode=full</code><span>, </span><code dir="ltr">--update-weight-transport=nccl</code><span>, and an SGLang implementation with multi-dtype </span><code dir="ltr">FlattenedTensorBucket</code><span> support.</span></p><h3><span>Experimental results</span></h3><p><span>We benchmarked weight updates for Qwen3-30B-A3B on Moore Threads S5000 GPUs in a disaggregated training and inference setup, with one node dedicated to training and one node dedicated to inference.</span></p><div><div><div>

Broadcast mode | Average weight update time
-- | --
per-param | 22.108 s
flattened-bucket | 25.642 s

</div></div></div><p><span>In this configuration, flattened broadcasting increased average weight update time by </span><strong><span>3.534 s (15.99%)</span></strong><span>. 
</span></p><p><span>Larger deployments and models may benefit more from fewer collective calls if communication overhead becomes dominant. However, this remains a hypothesis: additional benchmarks are needed to determine whether those savings outweigh packing and memory-copy costs as deployment size increases.</span></p><h3><span>Validation</span></h3><ul><li><span>Added unit tests for argument parsing and rejection of incompatible update modes.</span></li><li><span>Python syntax and diff whitespace checks passed.</span></li><li><span>Measured weight update performance in the two-node S5000 configuration described above.</span></li></ul>
