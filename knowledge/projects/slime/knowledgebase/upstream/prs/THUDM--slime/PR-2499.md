# perf(codec): 4.6x faster SampleCodec.prepare token-list encoding

[Upstream PR](https://github.com/THUDM/slime/pull/2499) · state: open · merged: False

## Original PR description

## TL;DR
Speed up the nested `visit` encoder in `SampleCodec.prepare` (`slime/data/codec.py`). The change moves the transport import out of the per-value call, returns exact `None`/`str`/`bool`/`int` values before the type-dispatch chain, and copies flat primitive lists/tuples in a single pass.
Optimized workload: encoding rollout groups whose samples carry ~8192-element token lists, as in `tests/test_distributed_rollout.py::test_buffer_checkpoint_reuses_durable_groups_and_protects_them_from_gc[True]`.
Metric: wall time of `SampleCodec.prepare` over 32 groups x 2 samples, using 9 interleaved baseline/candidate pairs per run, with the median taken across 3 runs.
Before -> after: **173.78 ms -> 37.74 ms per batch (4.6x faster; median paired ratio 0.2185)**.
Tested: the codec, distributed-rollout, straw-transport, trajectory-branching and score-centering test files pass (commands below). ruff, black and isort pass.

## Problem
`visit` recurses once per element of every list. On each call it runs a function-local `from slime.data.transport import ...` and checks `DiskPayloadRef` before it reaches the primitive check. For samples with thousands of token ids, almost all of the encode time goes to this per-element overhead.

## Change
- Import `DiskPayloadRef`, `RawRolloutRef`, `RolloutGroupRef` and `TrainBatchRef` once per `prepare` call, not once per visited value. The import stays local to `prepare`.
- Return exact `int`/`str`/`bool`/`NoneType` values first. These exact types can never be refs, tensors or containers, so the output is unchanged.
- For lists/tuples, copy the items with `list(value)` when every element has an exact primitive type. Otherwise primitive items are inlined and only non-primitive items recurse. Dict keys/values get the same inlining.
- Tags, field order, special-float handling, numpy/torch handling, cycle detection and error messages are unchanged. Encoded lists are still fresh copies.

## Benchmark
Baseline: `540ea919e45b8b929198abce008a103be9cfc779`, Python 3.12.13.

The workload mirrors the test above: 32 rollout groups x 2 samples, each with ~8192 tokens. The samples also carry rewards with NaN, metadata containing tuples, bytes, `np.int64`, `np.ndarray` and torch tensors, loss masks, and log-probs with `-inf`. Each group goes through `SampleCodec.prepare` on the straw rollout store with online GC enabled. One unsupported value is included so the raised exception is compared too. Each run uses 9 interleaved (ABAB/BABA) baseline/candidate pairs on an isolated core, with a fresh seed per pair, and runs after a warmup. An independent process on the unmodified tree checks that encoded payload bytes, records, dependencies and the exception match exactly.

| Run | Baseline median | Candidate median | Median paired ratio |
| --- | ---: | ---: | ---: |
| 1 | 173.78 ms | 37.72 ms | 0.2185 |
| 2 | 169.11 ms | 37.74 ms | 0.2241 |
| 3 | 174.05 ms | 37.89 ms | 0.2178 |

Relative IQRs were 2.3%, 1.8% and 1.5%. A baseline-vs-baseline control gives 0.998.
