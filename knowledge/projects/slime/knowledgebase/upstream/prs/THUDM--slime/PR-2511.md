# fix(rollout): release timestamps for consumed buffer groups

[Upstream PR](https://github.com/THUDM/slime/pull/2511) · state: open · merged: False

## Original PR description

`BufferQueue.get()` removes consumed groups from `data` but leaves their `group_timestamps` entries behind. Repeated write/read cycles therefore retain every consumed instance ID and timestamp.

Remove the matching timestamp after the existing successful data removal. Incomplete groups and a group whose transformation raises retain their data and timestamp.

The regression tests exercise the real FastAPI write/read routes, incomplete groups, reused IDs and transformation errors. The new test is registered in the CPU workflow matrix, with FastAPI/uvicorn installed only for that test; the generated workflow is included.

Validation on macOS / Python 3.13:
- The same regression tests: base **3 failed, 1 passed**; this change **4 passed**.
- Independent CPU/ASGI review checks, including a concurrent same-ID write: **5 passed**.
- Ruff and `git diff --check` passed; generated workflow matches its template.

These checks cover this CPU queue/ASGI path. Distributed Ray/GPU training and the upstream Python 3.10 CI lane have not been run locally.
