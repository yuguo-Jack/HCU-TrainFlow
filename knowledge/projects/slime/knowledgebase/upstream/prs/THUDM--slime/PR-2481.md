# feat: add local training performance benchmarks

[Upstream PR](https://github.com/THUDM/slime/pull/2481) · state: open · merged: False

## Original PR description

A local training baseline is needed to compare training-service overhead against slime while keeping the model, token data, optimizer, and effective batch fixed. Add a train-only Megatron benchmark that loads pre-tokenized debug rollouts, skips SGLang, and writes the invocation, configuration, logs, and measured performance summaries.

- Expose GPU/TP layout, optimizer settings, static micro-batches, and gradient accumulation. Record optimizer updates per rollout and pass sequence length explicitly to Megatron.
- Generate rollout samples from JSONL token sequences using next-token supervision. Reject duplicate or insufficient sequences rather than recycling data.
- Compare micro-batch sizes at a fixed global batch and collect training time, step time, and throughput in `comparison.json`.
- Exclude warmup rollouts, reject missing performance records, and require fresh output directories to avoid stale results.

Validation:
- Bash syntax and Python compilation checks.
- Dry-run sweeps for micro-batches 1/2/4, verifying accumulation 4/2/1, optimizer flags, sequence length, and execution from outside the repository.
- Rollout generation, duplicate-sequence rejection, and stale-output rejection.
- Simulated Ray submission and performance parsing, including warmup exclusion and missing-metric failure.

Real GPU training has not been run. Slime performance times are per rollout; the default configuration performs one optimizer update per rollout.
