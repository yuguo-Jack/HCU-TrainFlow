# fix: put the critic value head on a VLM's language_model

[Upstream PR](https://github.com/THUDM/slime/pull/2450) · state: closed · merged: True

## Original PR description

VLM wrappers like `Qwen3_5VLModel` delegate `forward()` to an inner `language_model` that owns the LM head. The critic's `LinearForLastLayer` was assigned to the wrapper, so it was never called: the critic returned vocab-sized logits and the first value step failed the `logits.size(-1) == 1` assertion in `loss.py`. This attaches the value head to `language_model` when the model has one (custom-provider and spec-provider paths) and looks it up there in `_iter_critic_output_layers`, so post-load reinitialization still finds it. Plain GPT models are unchanged, and the HF loader already skips the 1-output head.

Added a CPU test that builds a critic through the spec-provider path for a VLM-style wrapper and a plain model; the wrapper case fails without the fix. We hit this on Qwen3-VL through Megatron-Bridge in an older slime and fixed it there with the same change (run on 2×H200, PPO with a critic, 3 steps); I haven't run `Qwen3_5VLModel` with a critic on GPU.
