# fix: add rotary_percent to Megatron TransformerConfig patch so MiniMax-M2 hf->torch_dist conversion works

[Upstream PR](https://github.com/THUDM/slime/pull/2190) · state: closed · merged: False

## Original PR description

## Summary

Converting a MiniMax-M2 HF checkpoint to `torch_dist` format no longer crashes with `TransformerConfig got an unexpected keyword argument 'rotary_percent'`; the bundled Megatron config patch now declares the field.

## Why this matters

Issue #2129 reports the crash when running the hf -> torch_dist conversion for MiniMax-M2. The conversion passes `rotary_percent` to Megatron's `TransformerConfig`, but that field is not present in the pinned Megatron-LM. slime already carries missing `TransformerConfig` fields in its `docker/patch/*/megatron.patch` files, so the field belongs there:

```python
rotary_percent: Optional[float] = None
"""Percent of rotary dimension to use for rotary position embeddings."""
```

## Changes

- Add `rotary_percent: Optional[float] = None` to the `TransformerConfig` block in every versioned `megatron.patch` (`latest`, `v0.5.12.post1`, `v0.5.9`, `v0.5.7`, `v0.5.6`, `v0.5.5.post1`, `v0.5.0rc0-cu126`) so the patch stays consistent across the image tags.

The default `None` preserves existing behavior for models that do not set it.

## Testing

Each patch file is a unified diff applied during the Docker image build. Confirmed each modified hunk's header line counts stay consistent after the insertion so the patch still applies cleanly.

Fixes #2129

- mvanhorn · comment · 2026-10-31T11:46:44Z · [source](https://github.com/THUDM/slime/pull/2190#issuecomment-6542952800)

I went to resolve the conflict here and I don't think this change is needed on main anymore.

The crash in #2129 came from mbridge's `_build_base_config` passing `rotary_percent` straight into `TransformerConfig(**base_config)`. #2251 removed mbridge, including `slime_plugins/mbridge/minimax_m2.py`, and `tools/convert_hf_to_torch_dist.py` no longer goes through `AutoBridge`. The config now comes from `core_transformer_config_from_args` in `model_provider.py`. At the pinned Megatron commit (4b4acac) that helper only copies fields `TransformerConfig` declares, so an unexpected keyword can't reach it. `rotary_percent` goes to `GPTModel` as a constructor argument instead, so the `--rotary-percent 0.5` in `scripts/models/minimax-m2.sh` still takes effect.

The patches moved on too. `docker/patch/latest` and `v0.5.21` no longer touch `transformer_config.py`, so the hunk has nowhere to land, and the older version directories aren't what the default `PATCH_VERSION` builds.

I checked this by reading main at 540ea91, I didn't run a MiniMax-M2 conversion. Anyone still seeing this error on an older checkout should be fixed by updating slime and the image.
