# test: prevent Git maintenance race in SWE workspace fixture

[Upstream PR](https://github.com/THUDM/slime/pull/2459) · state: open · merged: False

## Original PR description

The SWE workspace-diff fixture commits a temporary repository and immediately copies its live `.git` directory. Automatic Git maintenance can remove `.git/objects/maintenance.lock` after `copytree` enumerates it, causing an unrelated CPU test failure before any workspace-diff assertions run.

Observed upstream evidence: [CPU job log](https://github.com/THUDM/slime/actions/runs/38084962578/job/114309457332) reports `shutil.Error` / missing `maintenance.lock` at the copytree call, with unstaged failing and staged/committed passing. [The report on #2451](https://github.com/THUDM/slime/pull/2451#issuecomment-6102325157) identifies it as unrelated to that PR's Qwen3.5 change.

Set repository-local `maintenance.auto=false` immediately after fixture initialization, before its first commit. The two-line, test-only change prevents this fixture from launching automatic maintenance while its object directory is copied. It changes no global Git configuration. All assertions remain intact: unstaged/staged/committed edits, image baseline exclusion, binary patch application, preserved index/HEAD, and resulting file contents. The existing CPU registration and `NUM_GPUS = 0` entry point remain unchanged.

Validation on Linux, Python 3.12.14, pytest 8.3.5 and Git 2.52.0, against main `58b0878679de339ec7844b45d884a87955a134be`:

```bash
export CUDA_VISIBLE_DEVICES='' SLIME_ACCELERATOR=cpu
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 PYTHONDONTWRITEBYTECODE=1
export PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTEST_ADDOPTS='-p no:cacheprovider'
python tests/test_agent/test_swe_workspace_diff.py
python -m pytest tests/test_agent/test_swe_workspace_diff.py
pre-commit run --files tests/test_agent/test_swe_workspace_diff.py
```

- Direct CPU entry point and pytest: each 3 passed, exit 0.
- Controlled local reproduction used a real temporary Git repository and real automatic maintenance process. A low GC threshold triggered maintenance; a pre-auto-gc hook held it while copying. When copytree reached the lock, releasing the hook let Git remove its own lock, reproducing the same ENOENT. With repository-local `maintenance.auto=false` before the commit, commit and copytree passed without a maintenance hook or lock. The reproduction driver exited 0 after verifying both outcomes.
- Independent read-only review confirmed the exact two-line patch, the real-Git reproduction and preserved assertion coverage. All applicable configured pre-commit hooks and `git diff --check` passed; hooks did not change the validated patch.

The local reproduction deliberately controls timing; it is not a claim of naturally reproducing the upstream intermittent failure. This setting prevents the fixture's automatic maintenance trigger, not externally launched explicit maintenance. Remote CI remains to run. No GPU, training, broad build or paid service was used.
