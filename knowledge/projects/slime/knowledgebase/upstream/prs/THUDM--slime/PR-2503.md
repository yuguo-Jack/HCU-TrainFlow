# ci: batch CPU tests to reuse dependency setup

[Upstream PR](https://github.com/THUDM/slime/pull/2503) · state: open · merged: False

## Original PR description

## Summary

Batch the always-on CPU and agent test files into small shards to share dependency setup. Each file still runs in its own Python process.

### Motivation

The current workflow installs dependencies separately for every registered file. The baseline run spends 4,549 summed seconds installing dependencies across 101 CPU and agent jobs. Sharing setup within a shard reduces that repeated runner work while preserving process isolation between files.

### Before and after

| Measurement, CPU and agent jobs only | [Base `540ea919` run](https://github.com/THUDM/slime/actions/runs/40445960764) | [This PR](https://github.com/THUDM/slime/actions/runs/40635022484) | Observed reduction |
| --- | ---: | ---: | ---: |
| Dependency setup jobs | 101 | 17 | 84 fewer, 83.2% |
| Summed dependency installation time | 4,549s | 708s | 3,841s, 84.4% |
| Summed job elapsed time | 7,165s | 2,119s | 5,046s, 70.4% |

The compared runs used about **64 fewer runner-minutes for dependency installation** and **84 fewer runner-minutes for total CPU and agent jobs**. These are sums across jobs, not workflow wall-clock latency. This is one hosted run per version, and runner and cache variation apply. The timings do not establish how much faster the entire workflow finishes.

## Changes

- Run files in shards of at most seven, with per-file log groups, timings, and failure summaries. Continue after a failed file and fail the shard if any file fails.
- Preserve argument splitting and reject GPU entries in the CPU runner.
- Keep tests with Straw separate from tests that verify behavior without Straw. Balance the slower Straw suites and automatically include future ungrouped entries.
- Retain the complete existing catalogs and GPU jobs. Regenerate the workflow from its template and document the execution model.

For review, start with the template, `build_cpu_test_shards`, and `run_tests`, then inspect the behavioral tests. The large YAML diff is generated output. This PR can land independently of the score-centering and metrics optimizations.

Per-file check names become named shard checks. Maintainers should confirm that required-check policies accept those names before landing.

## Testing

- The registered runner tests pass with Python 3.10. Real child scripts verify process isolation, arguments, continuation after failure, aggregate exit status, GPU rejection, and complete shard partitioning.
- Workflow generation is repeatable. Parsed catalog comparison preserves every existing entry exactly once, keeps dependency profiles separate, and leaves non-CPU jobs unchanged.
- Black 24.3.0, isort 5.13.2, Ruff 0.14.7, and `git diff --check` pass.
- Actionlint 1.7.7 reports no added diagnostics against the base workflow. Existing optional-field errors in unchanged GPU matrices remain.
- Hosted CPU and workflow checks passed at `3d8ac3a3`. Label-gated GPU jobs were skipped.

Commands: `python tests/ci/test_run_cpu_tests.py` and `python .github/workflows/generate_github_workflows.py`.
