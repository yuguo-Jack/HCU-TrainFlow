# fix(launcher): quote Ray runtime environment JSON

[Upstream PR](https://github.com/THUDM/slime/pull/2512) · state: open · merged: False

## Original PR description

`execute_train` inserts serialized runtime environment JSON inside literal single quotes. An environment value such as `{"RUN_NOTE": "owner's run"}` makes Bash reject the command before Ray starts; paired apostrophes can instead be silently removed from the value.

Use `shlex.quote` when passing `--runtime-env-json`. Add regressions that run the actual launcher through Bash with an argument-recording stand-in for the Ray CLI, covering both the `extra_env_vars` mapping and `ExecuteTrainConfig.extra_env_vars` JSON input. Register the tests in CPU CI and explicitly install the launcher's existing Typer dependency there.

Related: #2346 fixes equals signs in the space-separated input parser. This change covers the later shell serialization of the runtime environment.

Validation on macOS arm64, Python 3.12.13:

- Same 10 regression cases: **8 failed / 2 passed before**, **10 passed after**.
- `python -m pytest tests/utils/test_runtime_env_quoting.py -q` and direct script execution both passed.
- Repository-pinned pre-commit hooks on all four changed files and `git diff --check` passed; generated workflow matches its template.
- Tests check the exact CLI arguments and decoded environment values. Ray cluster startup, GPU work, and model training are not exercised.

Prepared with Codex assistance; validation results above were observed on the before/after implementations.
