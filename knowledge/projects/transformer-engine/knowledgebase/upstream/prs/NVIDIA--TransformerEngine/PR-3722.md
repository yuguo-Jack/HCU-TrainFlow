# [PyTorch] FP8BS grouped GEMM test reference fix

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3722) · state: closed · merged: True

## Original PR description

# Description

FP8BS grouped GEMM tests were being compared against a reference with FP32 accumulation. FP8BS on Blackwell via MXFP8 emulation passed these tests because MXFP8 grouped GEMM on Blackwell accumulates at a higher precision than native FP8BS grouped GEMM on Hopper.

This PR changes the reference in the test to the unfused split-grouped GEMM — consistent with how native MXFP8 grouped GEMM is tested.

<a href="#"><img alt="P2" src="https://greptile-static-assets.s3.amazonaws.com/badges/p2.svg?v=9" align="top"></a> **Scale differences are no longer stressed**

Replacing the tile-scaled operands with plain `torch.randn` removes deliberate differences between FP8 block scales. This matters especially for `weight_block_dim=2`, where large blocks of normally distributed values have similar maxima. A bug that reads another block's scale could then be harder to catch.

Keep the per-tile power-of-two factors while using the new split-GEMM reference. The reference no longer needs exactly representable operands.

Note: If this suggestion doesn't match your team's coding style, reply to this and let me know. I'll remember it for next time!
