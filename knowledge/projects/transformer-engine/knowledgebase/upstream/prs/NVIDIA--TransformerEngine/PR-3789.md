# [PyTorch] Avoid materializing per-view gradients for packed QKV/KV inputs

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3789) · state: closed · merged: True

## Original PR description

# Description

#3200 derives q/k/v from a packed `qkv_layer`/`kv_layer` with `Tensor.select`. In eager mode, autograd builds the gradient of each `select` view as a zero-filled tensor of the full packed shape, copies the view's gradient into it, and then sums those tensors. For a self-attention layer with packed QKV, that adds 3 fills, 3 copies and 2 additions of the packed-QKV size to every backward pass. This happens even when the attention backend already wrote dQ/dK/dV into a single packed buffer, which FusedAttention does for the `3hd`/`h3d`/`2hd`/`h2d` layout groups.

`MultiheadAttention` now passes `qkv_layer` whenever `num_gqa_groups == num_heads` and RoPE, Q/K norm, KV caching and CPU offloading are off. So this affects the default `MultiheadAttention`/`TransformerLayer` self-attention configuration, and cross-attention through `kv_layer`. Before #3200, these modules split QKV with `SplitAlongDim`, whose backward returns the packed gradient buffer without copying when the view gradients alias it, and concatenates them otherwise.

This PR uses `SplitAlongDim` again in `_unpack_packed_qkv` and squeezes the split dimension outside the autograd function. `select` stays in place under `torch.compile`, because `SplitAlongDim.backward` inspects data pointers, and for quantized packed inputs. The compiled path is therefore unchanged.

## Changes

- `_unpack_packed_qkv` derives the packed q/k/v (or k/v) views with `SplitAlongDim` in eager mode, and with `select` under `torch.compile` or for `QuantizedTensorStorage` inputs.

`SplitAlongDim`'s own `squeeze=True` option isn't used here. With it, the squeezed outputs come back without a `grad_fn`, so gradients would be dropped silently. Its current callers only use it on FP8 dequantization paths.

## Performance

Setup: 1x A100-SXM4-80GB (SM80), driver 570.172.08, torch 2.11.0+cu128, CUDA 12.8, cuDNN 9.19.0, TE built with `NVTE_CUDA_ARCHS=80`. FusedAttention (cuDNN arbitrary-seqlen backend) was selected.

Workload: 4 stacked `te.TransformerLayer`s in BF16, hidden 4096, 32 heads (no GQA), FFN 16384, LayerNorm and GeLU, no bias or dropout, causal, `fuse_qkv_params=True`, `sbhd`, sequence 4096, batch 1. Each iteration is a forward and a backward with gradients set to `None` beforehand. The time is the mean of 10 iterations after 3 warmup iterations, with CUDA synchronized; the GPU was idle less than 0.3% of the time.

| | Time per iteration | Kernel launches per iteration | bf16 fill / copy / add kernels |
|---|---|---|---|
| Before #3200 (`720ec27e`) | 89.8 ms | 128 | 0 / 0 / 16 |
| main (`35a8e2f9`) | 92.3 ms | 160 | 12 / 12 / 24 |
| This PR | 89.5 ms | 128 | 0 / 0 / 16 |

Per layer, the removed work was about 0.15 ms of fills, 0.22 ms of copies and 0.34 ms of additions, roughly 3% of the step time on A100. On GPUs with faster GEMMs, these memory-bound kernels make up a larger share of the step.

## Testing

- Outputs, input gradients and all parameter gradients are bitwise identical to main. I checked 104 tensors from `te.TransformerLayer` with MHA and GQA (16/16 and 16/4 heads), `qkv_weight_interleaved` on and off, LayerNorm/GeLU and RMSNorm/SwiGLU, and bias on, with `NVTE_ALLOW_NONDETERMINISTIC_ALGO=0`. I ran this on both FusedAttention and FlashAttention 2.8.4 (`NVTE_FUSED_ATTN=0`). FlashAttention returns separate dQ/dK/dV, so it exercises `SplitAlongDim`'s concatenation fallback.
- `tests/pytorch/attention/test_attention.py`, run as in `qa/L0_pytorch_unittest`:

  | | default | `NVTE_ALLOW_NONDETERMINISTIC_ALGO=0` |
  |---|---|---|
  | without flash-attn | 294 passed, 4965 skipped | 282 passed, 4977 skipped |
  | with flash-attn 2.8.4 | 349 passed, 4910 skipped | 337 passed, 4922 skipped |

  There were no failures. Most skips need FP8 (SM89+), SM90+ or FlashAttention 3.
- The declarative packed-input tests (`-k declarative`): 12 passed. To check that they would catch a broken split, I detached the views in a local experiment, and all 12 failed.
- `tests/pytorch/test_numerics.py -k "gpt or mha or dpa or transformer_layer or kv_cache or sanity"`, both with `NVTE_FUSED_ATTN=0` (as in `L0_pytorch_unittest`) and without it: 48 passed, 80 skipped.
- `tests/pytorch/test_torch_compile.py` was skipped because torch 2.11 lacks the opaque-object API. As a substitute, I compiled `_unpack_packed_qkv` with `fullgraph=True` for both `qkv_layer` (`sb3hd`) and `kv_layer` (`sbhd_sbh2d`). There were no graph breaks, and the forward and backward results matched eager mode.
- black (24.4.2, repository options) and pylint 3.3.1 are clean on the changed file.
