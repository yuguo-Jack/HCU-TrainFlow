# [PyTorch] Fix NVFP4 weight views of the single-group fused grouped MLP

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3662) · state: closed · merged: True

## Original PR description

With one group, the fused grouped MLP passes the weights to cuDNN as stacked tensors instead of per-group pointers, and two of its NVFP4 views of them were wrong:

- Forward: the FC1 weight scale view divided the logical K by the scale-atom divisor, which counts packed bytes for NVFP4 (two values per byte). The view asked for twice the scales and raised error.
- Backward: the FC2 dgrad viewed the column-wise NVFP4 data as (out_features, in_features / 2), but it is the transposed weight, (in_features, out_features / 2), and swapped the scale atom axes, which cuDNN rejects. Build these operands with _convert_to_cudnn_grouped_gemm_tensor_format, as the FC1 dgrad does.

Run the single-group test for every grouped MLP recipe, not only MXFP8.
