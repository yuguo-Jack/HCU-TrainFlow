# Optimize context parallel attention layouts and gradient accumulation

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3683) · state: open · merged: False

## Original PR description

# Description
Optimize context parallel attention with eligible dense cuDNN descriptors for equal-length BF16 THD inputs, bounded initialization removal, vectorized A2A layout copies, reuse of the first AllGather backward gradient contribution, and bounded native head partitioning to reduce workspace.

This is an opt-in experimental draft. All new switches are disabled by default. It keeps the existing communication flow and preserves the externally packed Stats layout through explicit stream-ordered conversions.

## Type of change
- [x] New feature (non-breaking change which adds functionality)

## Changes
- Add uniform THD forward/backward descriptor paths for D128/D256.
- Check the promised sequence lengths and physical offsets on device on each execution; an invalid opt-in promise reports a CUDA device error.
- Preserve physical pitches and sequence origins in the bounded AllGather backward experiment and its graph cache.
- Skip redundant output/gradient zeroing only for the checked BF16 D128, separate-Q/K/V, GQA4 subset.
- Add a bounded, opt-in SM100 BF16 A2A pack/unpack fast path inside the existing swap API, used by both attention backends.
- Add focused PyTorch and C++ copy regressions and fix test-helper dtype dispatch with older CUDA headers.
- Reuse the first dK/dV contribution as the accumulator for opt-in BF16 THD CP4 or CP8/D256 AllGather, preserving the second addition, stream events and communication.
- Add sixteen repository regressions covering both backends, unequal padded THD at CP4/CP8 and CP2/SBHD fallbacks.
- Add default-off native H16/H8/H4 partitioning for qualified AllGather backward shapes; preserve physical strides and reuse workspace.
- Add a C++ address-contract regression and sixteen fresh-worker CP activation/fallback cases.
- Document the seven experimental controls and their limitations in docs/envvars.rst.

## CP8 first-gradient accumulator reuse

Extend the existing default-off `NVTE_CP_EXPERIMENTAL_AG_FIRST_DKV` eligibility from CP4 to CP4 or CP8 for BF16 THD D256 AllGather. The first contribution already contains the accumulator's initial value; reusing it avoids a separate zero-filled allocation and the first add into zero. The accumulation algorithm, later addition, stream events, reorder and collective calls are unchanged. This is a three-file Python/test/documentation extension; no backend or FROST kernel changes.

The exact candidate passes **16/16 repository tests, zero skips**, across 72 fresh rank workers on B200 with cuDNN 9.27 and FA4. Coverage includes OFF/ON, unequal padded THD CP4/CP8, GQA8 and CP2/SBHD fallback controls. Full outputs and gradients are checked. Loaded Python paths and native binaries are verified for every worker. All 318 common/Torch-native/build inputs match the existing build byte-for-byte; the corresponding binaries are reused. Changed-file hooks and the license check pass. Whole-repository PyTorch lint retains the same four diagnostic lines as the isolated unmodified parent, all in byte-identical untouched files; this is not a clean global lint pass. Full GPU L0/JAX coverage remains outstanding.
