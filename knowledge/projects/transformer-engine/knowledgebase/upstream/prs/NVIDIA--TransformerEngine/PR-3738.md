# [PyTorch/JAX] Add NVTE_CUDNN_ATTN as an alias of NVTE_FUSED_ATTN

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3738) · state: open · merged: False

## Original PR description

# Description

TE's `FusedAttention` backend is cuDNN's flash-algorithm attention (online softmax). The docs already say so: `attention.ipynb` calls it "cuDNN attention (`FusedAttention`)". But the env var, Megatron's `--attention-backend fused` and the backend-selection logs only ever say "fused". Users keep asking whether "fused" is cuDNN, and whether it uses the flash algorithm.

This PR adds a **non-breaking alias** and names cuDNN in the logs. Nothing existing is renamed.

| Kept as-is | Added |
|---|---|
| `NVTE_FUSED_ATTN` | `NVTE_CUDNN_ATTN` (alias; setting both to different values raises `ValueError`) |
| `FusedAttention` class, `use_fused_attention`, `NVTE_Fused_Attn_Backend`, JAX `fused_attn()` | n/a |
| Checkpoint key `core_attention.fused_attention._extra_state` | n/a |
| n/a | Log: `Running with cuDNN attention backend (FusedAttention, sub-backend 1)` |

Companion Megatron-LM PR: `AttnBackend.cudnn`, an enum alias of `fused`, so `--attention-backend cudnn` works: NVIDIA/Megatron-LM#8488.

## Changes

- `transformer_engine/common/utils.py`: `cudnn_attention_enabled()` is the single reader of both variables. PyTorch and JAX both call it.
- `pytorch/.../utils.py` and `jax/flax/transformer.py`: replace the direct `NVTE_FUSED_ATTN` reads.
- `pytorch/.../dot_product_attention.py`: add `NVTE_CUDNN_ATTN` to `_THD_POLICY_BACKEND_ENV_VARS`. Without it, the THD policy backend cache would not invalidate when only the alias changes.
- Log, docstring and `docs/envvars.rst` updates. The recorded outputs in `docs/examples/attention/attention.ipynb` still show the old log text. They are left untouched to keep this diff small.
- Tests in `tests/pytorch/attention/test_attention_backend_selection.py` cover alias resolution, the conflict error and cache-key membership. The autouse fixture now also clears `NVTE_CUDNN_ATTN`.

## Testing

- `cudnn_attention_enabled()` was run standalone over all 9 combinations of unset/0/1 × unset/0/1. Results: the default is 1, either variable works alone, agreeing values pass, and conflicting values raise.
- All edited files compile. black 24.4.2 was run with the repo's pre-commit args.
- **Not run locally:** the full `test_attention_backend_selection.py` (no TE build matching `main` was available), the JAX tests, and GPU runs. CI needs to cover these.

This is a breaking change. The name `NVTE_CUDNN_ATTN` is more informative but I think the correct way to do this would be to fully deprecate `NVTE_FUSED_ATTN` and remove it in TE 3.0 if we really want to do this. CC @cyanguwa 

External repositories (such as Megatron) set `NVTE_FUSED_ATTN` depending on requested backend. If a user then set a conflicting value of `NVTE_CUDNN_ATTN`, then it will cause a crash due to no fault of the user.
