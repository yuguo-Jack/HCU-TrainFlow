# Add cuDNN OSS forward dispatch for context parallel attention

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3705) · state: open · merged: False

## Original PR description

# Description

Add an opt-in cuDNN OSS (FROST) forward provider for context-parallel attention. Supported D128 BF16 compact-THD causal training calls execute the complete compiled FROST forward chain through TE's common C++ dispatcher and return the packed FP32 Stats consumed by backward.

This draft is stacked on [#3699](https://github.com/NVIDIA/TransformerEngine/pull/3699) at `a7e91a56`. The current forward head is `a708a5a8`: [incremental diff](https://github.com/YangXu1990uiuc/TransformerEngine/compare/a7e91a561021374493671690009566af38a957d6...a708a5a83598053d49afd86e505413025f086007). It includes compatibility with the known FE prepared host signatures described below. The backward branch is unchanged. The combined GitHub diff includes that dependency until it lands.

## Execution and supported scope

- Python participates in cold preparation: construct the normal FE graph, select its supported forward engine, and retain the complete compiled host entry and immutable arguments. Steady-state C++ binds the current pointers, workspace and stream and calls TVM-FFI directly. The compiled entry includes metadata/remap, descriptor setup and the main SDPA kernel.
- Support SM100, D128, BF16 training, separate Q/K/V, compact THD, top-left causal padding, and no dropout, bias, sinks, paging or sliding window. Stats remain packed token-major FP32 natural logarithms.
- Compactness is an explicit promise checked on the GPU every execution, including graph replay: physical origins must equal zero-based cumulative lengths, with valid bounds and nonempty KV for live Q. Unequal sequence lengths are supported; there is no dense conversion. Physical storage holes, AllGather forward subcalls with those holes, D256 forward and noncausal forward are outside this initial scope.
- Cache plans per declaration/device without holding a C++ cache lock across Python. Validate current operand/workspace alignment, capacity and overlap. Retain immutable FFI values in the cache without adding FFI array-type registration dependencies to the common library.
- Add default-off, fallback and strict modes, documentation, seventeen directed forward tests and 25 CPU contract tests. The dedicated FROST QA target requires all 104 tests and all twelve isolated metadata-guard children.
- Accept only the known 27-, 31- and 37-slot FE host signatures. Extra score, bias and KV-mask slots must contain their exact disabled defaults. Unknown signatures and enabled unsupported features are rejected. C++ uses bounded stack storage and passes the actual argument count, retaining native steady-state execution.

The integration selects existing FE kernels; it does not change their arithmetic or communication implementation. The separate private backward exp2 experiment is not part of this PR.

## Use and dependencies

Build TE with CuTeDSL support and install compatible FE source, `nvidia-cutlass-dsl[cu13]>=4.8.0`, and `apache-tvm-ffi`. This draft validates and consumes FE's private prepared forward metadata. A stable FE export contract and compatible dependency packaging remain prerequisites for graduating the integration.

Current-FE directed requalification used develop `7701e232` plus [FE #1690](https://github.com/NVIDIA/cudnn-frontend/pull/1690), the terminal dQ-credit synchronization repair in [FE #1698](https://github.com/NVIDIA/cudnn-frontend/pull/1698), and an isolated FP32 padding-helper correction. This is a composed qualification package, not unmodified develop or the unmodified published FE heads. Ordinary numerical tests do not detect the unrepaired D128 dense/THD barrier-phase violation. The current package passes the directed TE suite and unfiltered terminal-credit synccheck; the FE performance holds remain in force. The current-head 2K and 8K CP comparisons below use this package and explicitly exclude #1696 and #1702. Older comparisons retain their earlier frozen dependency versions.

```bash
export NVTE_ENABLE_CUTEDSL_BACKEND=1
export CUDNN_FRONTEND_ENABLE_FROST_ENGINES=1
export NVTE_FUSED_ATTN=1
export NVTE_FLASH_ATTN=0
export NVTE_FUSED_ATTN_FROST_FWD=2          # strict; 1 permits backend fallback
export NVTE_FUSED_ATTN_FROST_FWD_COMPACT=1  # only for the documented layout
export NVTE_FUSED_ATTN_FROST=2             # optional: pair with OSS backward
```

Warm up each declaration before CUDA Graph capture. Leave the compactness promise disabled for physical holes or unsupported declarations. `NVTE_FUSED_ATTN_FROST_FWD=0` retains the existing forward route.

The historical CP measurements below used FE develop `2bcdd1bb` plus [#1696](https://github.com/NVIDIA/cudnn-frontend/pull/1696) for the forward lookup optimization and the complete [#1690](https://github.com/NVIDIA/cudnn-frontend/pull/1690) patch for the existing D256 pitched-backward regressions. The D256 pitch dependency is not required by the D128 forward implementation itself.

## Current compatibility validation

- **25 CPU contract tests pass:** legacy/current signatures, neutral optional slots, malformed or unknown signatures, and retained feature guards.
- **79/79 original TE GPU tests pass, zero failures/errors/skips**, on an exclusive production B200 (148 SM, 1000 W) with cuDNN 9.27.0.42, CUDA 13.2 and the dependency package above. This includes all twelve isolated metadata guards, independent CPU-FP64 O/Stats/gradient comparisons, rebinding, streams, changed-length replay and cached execution with Python preparation callbacks disabled. The native forward plans use the current 37-slot host signature.
- **Eight terminal-credit FE regressions pass ordinarily and all eight pass under unfiltered synccheck with zero reported errors.** No unexpected GPU process was observed. This is directed synchronization coverage, not a complete sanitizer matrix.
- Recompiled the changed common CUDA unit with the existing CUDA 13.2 configuration, linked with 113 hash-verified unchanged parent objects, and loaded that library through the normal current-head TE/PyTorch path. The submitted native code matches the tested code; Python preparation differs only by an AST-equivalent trailing-comma formatting fix.
- Changed-file pre-commit, Pylint 3.3.1, C++ lint and diff checks pass. The QA launcher now includes the 25 contract tests; the reported CPU and GPU suites were run separately.

The current-head complete-CP comparison below exposes a forward-path slowdown. Isolated host-submission and device-runtime attribution for this combination remains pending. The PR remains a draft pending that investigation, current-head review/CI, remaining integration qualification and the dependency holds.

## Follow-up causal THD forward kernel optimization

[cuDNN Frontend #1702](https://github.com/NVIDIA/cudnn-frontend/pull/1702), head `41be3b14`, builds on #1696 and moves one quarter of softmax exp2 work on eligible SM100 BF16 D128-flavor causal THD **interior** tiles to the existing FMA implementation. Masked/diagonal tiles retain MUFU; paged, split-KV, sliding-window and FP16 causal paths are excluded. This is a separate FROST kernel change; the TE dispatch code and this PR's head are unchanged.

At **B32/S16384/Hq32/Hkv8/D128, BF16 causal THD, 524288 tokens, CP4/A2A**, two independent B200 nodes show **1.46–1.72% lower complete-CP latency** against the repaired FROST forward+backward baseline. Timing includes forward, backward, helpers and communication, with identical TE binaries and communication, four balanced orders, 256 full output/gradient checks and 48 telemetry/stability windows per node. Baseline/candidate/FA4 medians are **74.617/73.342/70.940 ms** on one node and **74.517/73.367/70.716 ms** on the other. Paired ratios are analyzed separately per node; the optimized path still takes **3.34–3.78% longer than FA4**.

The published forward source independently passes **22 numerical/replay cases plus one public-layout rejection** on B200, with **two cases under each of memcheck, racecheck and synccheck**, zero errors/hazards. Tests include both packed Stats layouts, changed-length replay and smaller/asymmetric D128-envelope widths. The original complete-CP measurements retain their frozen experimental-package attribution; they do not remeasure the entire new public FE package or add an original-grid win rate. Existing TE integration/export/packaging requirements remain unchanged.
