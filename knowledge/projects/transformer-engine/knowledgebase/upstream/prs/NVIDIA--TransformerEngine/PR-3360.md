# [PyTorch] Restore FlashAttention 2 head dim support on sm103

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3360) · state: closed · merged: False

## Original PR description

# Description

Restore the FlashAttention 2 head-dimension behavior from #2836. #2629 preserved the new padded Q/V head-dimension handling but accidentally reintroduced the exact compute-capability allowlist that #2836 removed.

On B300 (sm103), that allowlist rejects a padded head dimension of 256 and falls back to quadratic unfused attention.

## Changes

- Preserve the padded Q/V head-dimension validation introduced by #2629.
- Remove the stale architecture allowlist for FlashAttention 2 head dimensions above 192.
- Update the backend-selection diagnostic to match.

## Testing

### Status quo

- Layout: one 8xB300 node with four B300s assigned to the Megatron trainer (`TP=4`) and four to rollout inference. Qwen3.6-27B used BF16 THD attention, head dim 256, Transformer Engine 2.11.0, and FlashAttention 2.8.3.
- Our production workload requested FlashAttention, but TE's exact compute-capability allowlist omitted B300 (`sm103`) and silently selected `UnfusedDotProductAttention` instead.
- XID 1043331 replayed an unsliced 65,332-token datum with a 65,536-token microbatch budget. The quadratic unfused softmax tried to allocate 202.75 GiB and raised `torch.OutOfMemoryError` during forward.

### After the fix

- Used the same image, package versions, TP4 trainer layout, model, BF16 THD configuration, head dim, 65,536-token budget, and exact 65,332-token datum. Only this selector gate was patched.
- The full 64k training update completed without OOM: `forward_backward` took 413.2s, the Adam optimizer step took 9.6s, and grad norm was finite at 1776.48. This validates FlashAttention 2 and 64k context on the four-B300 trainer configuration.
- Python compilation and diff checks pass.

- 0z5a · comment · 2026-10-19T17:54:24Z · [source](https://github.com/NVIDIA/TransformerEngine/pull/3360#issuecomment-6273670420)

@kalectory @cyanguwa This regression is still on `main` (`eb3c860a`). `utils.py:1045` still allows FA2 for a padded head_dim > 192 only on `((8, 0), (9, 0), (10, 0), (12, 0))`, so sm103 (B300 / GB300) still falls back to fused or unfused attention for head dims in (192, 256]. This PR was approved but closed without merging. Was that intentional, or could it be reopened?

One thing to consider before dropping the clause entirely. flash-attn's hdim256 backward picks its kernel by opt-in shared memory per block (`run_mha_bwd_hdim256` in `csrc/flash_attn/src/flash_bwd_launch_template.h`). Below 144 KB, in the branch commented "sm86 and sm89, max smem is 99 KB. Only works without dropout", it launches no kernel at all when dropout is enabled. The `mha_bwd` check that used to reject "head dim > 192 with dropout" on those GPUs was removed in Dao-AILab/flash-attention@bbb21d6, and neither v2.8.3 nor main has a replacement. Removing TE's allowlist would therefore send sm86/sm89 training with dropout down that path. This comes from reading the source; I have not run it on an sm86/sm89 GPU.

A narrower fix is to add `(10, 3)` to the tuple. sm103 has the same 227 KB of opt-in shared memory per block as sm90 and sm100, so it takes the same backward kernel as sm100. I have that change plus a regression test in `tests/pytorch/attention/test_attention_backend_selection.py`. The test mocks the compute capability, so it needs no GPU:
- sm103 with padded head dims 224 and 256, and MLA 192/256, select FA2;
- the 192, 264 and 252 boundaries;
- an sm100 control.

The three sm103 cases above 192 fail on current `main` and pass with the change. I'm happy to open it as a PR, or to leave it to you if you'd rather reopen this one.
