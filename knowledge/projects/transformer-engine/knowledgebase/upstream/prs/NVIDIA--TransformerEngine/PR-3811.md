## Original PR description

# Description

Currently `nvte_cublas_gemm_v2` requires C and D tensors to be the same, even though cublas has support for them to be different. This would allow us to fuse add to GEMM, required to fix #3741. Without this, the unfused add in PyTorch is a not performant.

- timmoon10 · comment · 2026-11-04T08:45:58Z · [source](https://github.com/NVIDIA/TransformerEngine/pull/3811#discussion_r4465473825)

File: `transformer_engine/common/gemm/cublaslt_gemm.cu` · line 461

None of these checks for `C` are necessary if `beta` is zero. In that case we can blindly set `C` to match `D`, similar to the old logic for FP8 output.

Unfortunately, this opens up some problems.
1. We can only check `beta` if it is on CPU.
2. We do have a config option `kNVTEMatmulConfigAlphaBetaOnDevice`. However, `alpha` must be on device for NVFP4 tensor scaling. We might want separate options to control whether `alpha` is on GPU and `beta` is on GPU.

Fixing this is more a matter of convenience than correctness. If someone is calling a GEMM with `beta=0`, it might be nice for them to pass the same tensor into `C` and `D` even if accumulation isn't supported. However, for now, the only case where `C` and `D` don't match is when `D` is FP8, in which case we can hackily workaround by passing in a dummy BF16 tensor for `C`.
