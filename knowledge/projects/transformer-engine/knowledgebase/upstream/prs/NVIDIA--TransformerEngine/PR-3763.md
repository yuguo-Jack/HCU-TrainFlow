# [PyTorch] Add bounded-memory CPU optimizer state export

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3763) · state: open · merged: False

## Original PR description

# description

add opt-in `state_dict_cpu_offload=False` to `FusedAdam`, allowing checkpoint callers that use the no-argument `state_dict()` API to move each converted state to CPU before exporting the next one. this addresses the GPU expansion peak reported in [Automodel #4209](https://github.com/NVIDIA-NeMo/Automodel/issues/4209), where checkpoint CPU offload runs after the complete optimizer dictionary has already been materialized.

Fixes #3668.

## type of change

- [x] new feature, with existing behavior retained by default
- [x] fix for the bounded-memory checkpoint export path

## changes

keep the existing state conversion and DTensor wrapping, then copy each export state to CPU when the option is enabled. placing the copy after wrapping avoids CUDA meshes moving a CPU local tensor back to the GPU. exported values, dtypes, keys and distributed metadata remain unchanged, while live optimizer state and parameter-group metadata retain their existing ownership and placement.

add a standalone lifecycle scenario to the existing L0 runner, covering repeated exports, restoration and continued updates, including sharded DCP with the `flatten_optimizer_state_dict=True` configuration used by Automodel. the option is a constructor setting so the existing optimizer factory can forward it without changing DCP's call signature.

- 14 ordinary-tensor lifecycle combinations pass, covering FP32/FP16/BF16/FP8 moments, FP32/FP16 master weights, int16 remainders and capturable settings, with unchanged live-state values, devices and storage pointers after export.
- two-rank CUDA-mesh DTensor export, restore and continued native optimizer updates pass for FP32, FP16 and BF16 moments, including uneven shards.
- two-rank sharded DCP passes all four `flatten=False/True × sync/async` combinations. full-state DCP also passes default/CPU export with synchronous and asynchronous saves, followed by load and continued updates.
- a two-rank checkpoint also loads into one rank and produces bitwise-equal parameters after the next native Adam update.
- that native package passed `27` selected FusedAdam regressions with `12 deselected`, using `-k "TestFusedAdam and not MXFP8 and not Float8Block"`. the earlier main/candidate Python comparison passed the same selection for both arms.

the GPU allocation increments measured in that earlier native run were:

| parameters | default export peak | CPU export peak |
| --- | ---: | ---: |
| 1 × 1,048,576 elements | 8 MiB | 4 MiB |
| 8 × 1,048,576 elements | 64 MiB | 4 MiB |
| 32 × 1,048,576 elements | 256 MiB | 4 MiB |
| 8 × 4,194,304 elements | 256 MiB | 16 MiB |

these measurements use two BF16 moments and report temporary PyTorch allocated memory above the pre-export level. comparing with a baseline that subsequently copies the complete dictionary to CPU gives the same peak differences and the same final CPU payload, with zero additional GPU export allocation retained at the common endpoint. total process memory and checkpoint storage are separate quantities.

a full-state gather can move exported states back to the mesh device, as documented. the complete L0 matrix, minimum supported PyTorch version, larger cross-world-size configurations and original 64-GB200 recipe remain unrun. the FP8 scenarios emit the release's `Float8Tensor` `_to_copy` warning and still pass their value and continued-update checks. please run the project's full build and distributed optimizer matrix before merging.
