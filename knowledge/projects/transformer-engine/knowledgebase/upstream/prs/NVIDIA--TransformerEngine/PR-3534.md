# [PyTorch] [torch.compile] torch.compile support for LayerNormLinear and LayerNormMLP

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3534) · state: open · merged: False

## Original PR description

## Description

Add full-graph `torch.compile` support for `LayerNormLinear` and `LayerNormMLP`, including backward, dynamic batch dimensions and normalization outputs.

The single late fallback check relies on the Dynamo fix in [pggPL/pytorch#4](https://github.com/pggPL/pytorch/pull/4), related to [pytorch/pytorch#144820](https://github.com/pytorch/pytorch/issues/144820). Without that fix, a graph break inside forward's try/finally can disable compilation for subsequent supported instances of the same module class.

Targets `main`. This branch includes the NVFP4 packed-buffer, TensorSpec and Bias correctness fixes from [NVIDIA/TransformerEngine#3628](https://github.com/NVIDIA/TransformerEngine/pull/3628). It also includes the GEMM scale-layout fix prepared separately in [pggPL/TransformerEngine#72](https://github.com/pggPL/TransformerEngine/pull/72), so fake outputs can follow quantizer metadata without querying native kernel layout rules.

## Changes

- Describe forward outputs, saved tensors, aliases and backward gradients for both LayerNorm modules; retain eager fallbacks for unsupported configurations.
- Decide fallback eligibility once after preparing quantizers in Linear, LayerNormLinear and LayerNormMLP; reuse the prepared eager path and preserve end_forward cleanup.
- Share output-gradient setup and quantizer validation with Linear. Adapt the newly inherited fused-attention backward container to the same gradient setup contract, preserving its existing first-output gradient assignment.
- Support compiled FP8 weight caching in both LayerNorm modules, following Linear: replace the cache on the first microbatch and reuse it on subsequent microbatches, including both MLP weights. GPU-controlled cache updates and fused wgrad accumulation retain eager fallbacks.
- Share the cache regression across Linear, LayerNormLinear and LayerNormMLP, checking independent eager outputs/gradients, cache refresh/reuse, optimizer updates, immediate/deferred backward and CUDA Graph replay.
- Describe normalization statistics and activation outputs directly from quantizer metadata, including gathered LayerNormMLP output shapes. Remove layout-query bindings and backend-specific layout prediction from fake implementations.
- Parameterize module compile tests across recipes, shapes and modes, with LayerNorm-specific outputs, gradients and eager fallbacks. Retain the non-matrix Linear regressions and expanded cold CUDA Graph recipe coverage inherited from #3628.

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **RMSNorm gradients read wrong scales**

With `NVTE_NORM_FWD_USE_CUDNN=1`, a `CustomRecipe` can choose `MXFP8Quantizer(with_2d_quantization=True)` for normalization.
