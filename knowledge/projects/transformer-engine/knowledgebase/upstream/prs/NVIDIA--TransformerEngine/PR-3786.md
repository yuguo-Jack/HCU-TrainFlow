# [Common] MXFP8 partial amax and cast kernels launch only the row tiles of the shard

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3786) · state: open · merged: False

## Original PR description

# Description

`mxfp8_scaling_compute_partial_amax` and `mxfp8_scaling_partial_cast` launched one block per 32×128 tile of the whole rows x cols weight, even though each call handles only a 1D shard of it, and every thread then skipped the elements outside the shard. They now launch only the row tiles that hold the shard. With 64-way sharding this is 3-23x faster for the amax kernel and 2.3-20x for the cast kernel; the largest weights gain the most.

## Changes

Please list the changes introduced in this PR:

- **`partial_row_tiles(rows, cols, start_offset, len)`** returns the first and past-the-end rows of the 32-row tiles that contain elements `[start_offset, start_offset + len)`, or an empty range when `len == 0`. Both launchers already require `rows % 32 == 0`, so the clamp to `rows` always lands on a tile boundary.
- **Both kernels take a `row_offset`**, and the tile row is `row_offset / 32 + blockIdx.y` in place of `blockIdx.y`. The per-element shard guard is unchanged, so partial first and last tiles behave exactly as before.
- **The grid's y dimension** covers only `[row_begin, row_end)`. An empty shard launches nothing.
- **The amax kernel's output contract is unchanged.** The full-grid kernel wrote amax 0 for every tile outside the shard. The launcher now writes those zeros with `cudaMemset2DAsync`, over exactly the columns the old kernel wrote: `blocks_x * 4` rowwise and `blocks_x * 128` columnwise, for the rows before `row_begin` and from `row_end` on. Callers that do not zero-initialise the amax buffers therefore see identical results. Padding rows beyond `rows` are not touched, as before.
- **The cast kernel** writes only elements inside the shard, so no fill is needed.
- **`NVTE_CHECK_CUDA(cudaGetLastError())`** is added after both launches.

<a href="#"><img alt="P2" src="https://greptile-static-assets.s3.amazonaws.com/badges/p2.svg?v=9" align="top"></a> **Neighboring writes escape this test**

The test promises to check that cast outputs outside the shard stay untouched, but `out_row` and `out_col` contain only the shard. Their sentinel values are all overwritten, so the checks cannot catch writes before or after the output slice. Real callers pass views into larger weight buffers.

Allocate larger sentinel-filled buffers, pass shard views to the cast, and check both surrounding regions afterward. Include the empty shard with a nonempty backing buffer.
