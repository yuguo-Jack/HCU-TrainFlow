# [PyTorch] Remove multi-layer TransformerLayer cases from comm+GEMM overlap tests

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3692) · state: closed · merged: True

## Original PR description

# Description

Comm+GEMM overlap separates the GEMM work into smaller chunks such that compute for one chunk can overlap with the communication for the previous or next chunk. This chunking results in cuBlasLt picking different heuristics for the chunked GEMM than the reference non-chunked GEMM.

On Blackwell, these different GEMM kernels produce bitwise identical results. On VR200, the chunked heuristic has a 1ULP BF16 difference in a single element of the QKV FPROP GEMM output. The diverging result lands on an FP8 boundary and causes 8 elements in the FP8 quantization to leap an entire step, which then cascades into a 9-12% divergence in 23+ million elements in the attention output.

A single-layer of the TransformerLayer module manages to stay within our 12.5% test tolerance, but the error accumulation grows to ~19% in the multi-layer case, causing the test to fail on VR200 only.

The failure on VR200 disappears and the outputs and gradients become bitwise identical against non-overlapped reference when chunked and non-chunked GEMMs are manually forced to select the same heuristic.

In further discussion with @ptrendx, we concluded that a 1ULP BF16 difference is not unexpected or indicative of a bug, but it is going to keep causing failures in the the multi-layer TransformerLayer test moving forward regardless. Since the multi-layer test does not exercise any code paths that are not already covered by the single-layer test, we decided to remove the multi-layer tests entirely.
