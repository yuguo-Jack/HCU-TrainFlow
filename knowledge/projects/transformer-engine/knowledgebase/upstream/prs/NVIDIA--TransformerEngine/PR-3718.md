# [PyTorch] Check saved tensors against comm+GEMM overlap buffers

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3718) · state: closed · merged: True

## Original PR description

# Description

Userbuffers and the cuBLASMp buffers for comm+GEMM overlap are shared by every layer, so a tensor saved for backward that aliases one is overwritten by the next layer's forward pass. A single layer cannot observe this numerically. The layer runner now checks every tensor saved during the test model's forward and backward passes and fails if its storage overlaps the buffer returned by `get_buffer()`. With the cuBLASMp backend, the check runs with cuBLASMp 0.11.0 or newer, where `get_buffer()` views the gathered input in its workspace (cuBLASMp buffer was not exposed via API in older versions).

The multi-layer TransformerLayer cases removed in #3692 were added in #1554 to catch this, but relied on numerical tolerances to detect it. This new test checks the root cause instead of relying on numerical failures.
