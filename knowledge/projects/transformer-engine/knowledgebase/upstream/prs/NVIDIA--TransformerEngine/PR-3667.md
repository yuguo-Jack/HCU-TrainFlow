# [PyTorch] Interpolate the class name in six op error messages

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3667) · state: closed · merged: True

## Original PR description

# Description

Six `RuntimeError` messages in the fusible-op API build one string from four fragments and leave the `f` off the first one, so the brace expression that names the offending subclass goes out verbatim:

```
{self.__class__.__name__} operation has 1 extra tensor inputs and 0 extra tensor outputs.
It should override `fuser_forward` instead of `op_forward`.
```

The two fragments after it are f-strings and do interpolate, so the counts are right and only the class name is lost, which is the one part a caller cannot work out for themselves. These are the guards that fire when a subclass declares extra tensor inputs or outputs and implements `op_forward` / `op_backward` instead of `fuser_forward` / `fuser_backward`, so the message exists to say which operation got it wrong.

The same four-fragment message appears six more times in the same tree with the `f` in place, in `basic/swiglu.py:499`, `:507`, `basic/activation.py:383`, `:391`, `basic/grouped_linear.py:852` and `:860`. These six were the ones that were missed.

Demonstrated standalone, since it is a property of the language rather than of TE:

```python
class Demo:
    num_extra_inputs = 1
    num_extra_outputs = 0

    def msg(self):
        return (
            "{self.__class__.__name__} operation has "
            f"{self.num_extra_inputs} extra tensor inputs "
            f"and {self.num_extra_outputs} extra tensor outputs. "
            "It should override `fuser_forward` instead of `op_forward`."
        )


print(Demo().msg())
```

```
{self.__class__.__name__} operation has 1 extra tensor inputs and 0 extra tensor outputs. It should override `fuser_forward` instead of `op_forward`.
```
