# Support learnable softmax (attention sink) with cp_comm_type="p2p"

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3551) · state: open · merged: False

## Original PR description

**Incremental review:** [Files changed](https://github.com/NVIDIA/TransformerEngine/pull/3551/files) against `main`.

Addresses #2541.

## What was broken

`softmax_type="learnable"` (the learnable attention sink) with `cp_comm_type="p2p"` was rejected by an assertion. Behind that assertion, the p2p fused-attention helpers never passed `softmax_type` to `fused_attn_fwd` / `fused_attn_bwd`, so the kernels fell back to `"vanilla"` and ignored `softmax_offset`.

## What changed

* `cp_p2p_fwd_fused_attn` / `cp_p2p_bwd_fused_attn` take `softmax_type` and `softmax_offset`. The offset joins the auxiliary tensor pack in the order the forward returns it (`[stats, rng, (bias), (offset)]`). The previously unconditional `attn_bias = rest[0]` is now guarded by whether a bias was passed, because with a sink the pack would otherwise return the offset as the bias.
* **The sink enters each query row's softmax exactly once.** cuDNN counts the sink as one more softmax column, so the softmax stats of a tile include `e^offset`. The p2p forward merges the tiles' stats, so passing the offset to every tile would add the sink once per tile that a row visits. Only step 0 gets the sink: it is the local KV tile, and it covers every local query row (the diagonal tile under a causal mask, the full tile without one). The other tiles run a plain softmax. In the backward, only the mirror tile passes the sink and returns its gradient. The other tiles' dq/dk/dv use the merged stats, which already include the sink.
* **Sink gradient reduction.** Each rank's sink gradient covers only its own query rows. It is all-reduced over the CP group, so every rank returns the full-sequence gradient. This matches the a2a path, which all-gathers the per-head gradients, and it is what `run_attention_with_cp.py` compares against.
* `utils.py` and `attn_forward_func_with_cp`: fused attention is no longer disabled for non-vanilla softmax with p2p. With a sink, the FP8 per-tile forward returns the offset as a third aux tensor, and the FP8 unpacking now accepts it. The existing gate for FP8 with a sink on sm < 100 or cuDNN < 9.21 still applies.
* Tests:
  * `test_attention_with_cp.py` now runs the non-vanilla softmax cases (`cp_4_1` off-by-one, `cp_4_2` learnable) for p2p as well as a2a.
  * `run_attention_with_cp.py` kept the reference sink gradient as an alias of `softmax_offset.grad`, then zeroed it before the CP run accumulated into the same tensor. The sink-gradient check therefore compared the CP result with itself, for a2a as well. It now clones the reference.
  * The learnable offsets are drawn as `randn * 5` from a fixed CPU generator. With the default zero offset, the sink is almost invisible next to thousands of keys.

An earlier version of this PR passed the sink to every tile and did not reduce the gradient. Both errors cancel without a mask at cp=2: every row was counted twice, and each rank held half the rows. Under a causal mask they don't cancel: the sum of the per-rank sink gradients was off by up to 0.84 (reference max 6.36). The CP test skipped non-vanilla softmax for p2p, and its sink-gradient check compared against an alias, so neither caught it.

### B300 (sm_103), cp=2 and cp=4

The B300 run used TE main `fac8d4a9` built for `103a` with CUDA 13.3, with this PR's Python files on top, cuDNN 9.27.0 and torch 2.14.1+cu130.

The essential run includes p2p with thd (cuDNN ≥ 9.26), and a2a with the new non-zero offsets for sbhd and thd, `cp_4_3` (sliding window) and FP8. The FP8 p2p cases are the FP8 change in this PR.

An FP64 emulation of the p2p tile schedule shows the same pattern. With the sink on every tile, the ratio of the CP sum to the reference ranges from 0.5× to 2× per head at cp=2, and from 0.25× to 4× at cp=4. With the sink on step 0 only, it matches to 1e-15 at both sizes.

## Not covered

* The flash-attention backend.
* FP8 with a sink on sm_90, where the existing FP8 + sink gate on sm < 100 keeps FusedAttention off.
* `cp_size > 4`, and the a2a runs at cp=4 beyond `cp_4_2` bshd.
* `cp_comm_type="a2a+p2p"`, which is still rejected for non-vanilla softmax.

## Question for reviewers

Both a2a and p2p now return the full-sequence sink gradient on every CP rank. Other parameters get only their own tokens' gradient on each CP rank. Megatron-LM scales the loss by the CP size and scales dense gradients by `1 / dp_cp_group.size()` before the DP×CP reduction. As far as I can tell, it treats `softmax_offset` like any other parameter. In that setup, the sink gradient would come out `cp_size` times larger than the weights' gradients. Is the full gradient on every rank the intended contract, or should both paths return the per-rank partial sum? I kept the existing a2a contract here so that the two paths agree.

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Sink Is Counted Per Tile**

`softmax_offset` is passed unchanged to every fused P2P tile, and each fused call installs it as its own sink token. For `cp_size = N`, the generic LSE merge therefore includes `N * exp(offset)`, while the learnable-softmax contract appends only one global sink. Every `cp_size > 1` run consequently computes incorrect probabilities and accumulates the gradient of an N-sink operation instead of the intended single sink.

With `post_scale_bias` and learnable softmax, P2P reconstructs the backward auxiliary pack as `[stats, rng, bias, offset]`.
