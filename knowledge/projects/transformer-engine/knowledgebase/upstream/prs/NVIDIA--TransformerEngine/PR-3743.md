# Don't rely on cuda.core for compute capability check

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3743) · state: open · merged: False

## Original PR description

# Description

Cutedsl kernels rely on cuda.core to check compute capability, but this is not a TE dependency.

This will make CI able to run using CuTeDSL kernels instead of falling back to CUDA kernels. It also fixes how a all NaN 32 element block is handed so now the scale will be NaN instead of 0 when all elements are NaN, and it's consistent across different configurations for both CUDA and CuTeDSL so the CI tests can pass.

Fixes #3793

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Backends disagree on NaN scales**

Full all-NaN blocks now get scale `0xFF` in the generic CUDA kernel, but CuTeDSL still turns their amax into zero. An all-NaN FP32 input therefore gets different scale bytes from the same quantizer depending on the selected backend. This breaks the bit-exact scale contract checked by the backend comparison tests.

Keep the NaN behavior consistent across both backends and add an all-NaN comparison case.
