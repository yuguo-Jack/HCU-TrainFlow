### reviews

- sudhakarsingh27 · COMMENTED · 2026-10-29T23:49:47Z · [source](https://github.com/NVIDIA/TransformerEngine/pull/3712#pullrequestreview-5706173999)

The overall structure follows existing TE/JAX conventions. A few small consistency improvements:

1. **Document the public API contracts.** Include shapes, dtypes, index coordinates, and scaling. In particular, distinguish the equal-length batched interfaces (BSHD inputs provided by MaxText?) from the raw packed/flat APIs (cuDNN can accept THD inputs): the compressor and sparse-attention APIs accept packed/flat inputs, while the indexer binding still requires dense batches. Also clarify global KV-row indices versus batch-local indices, and that `softmax_scale=1.0` applies no additional scaling.

2. **Use the existing array annotations instead of `Any`.** Public tensor arguments and returns could use `jnp.ndarray`, as the LayerNorm and activation APIs do. This improves readability without changing behavior; internal helpers can remain lightly annotated.

3. **Reuse each forward rule from its decorated primal.** The primal and forward rule currently repeat the kernel invocation. LayerNorm and fused attention have the primal call the forward rule and return its output, avoiding drift between the two paths:

   ```python
   out, _ = _dsa_indexer_fwd(q, k, weights, ratio, sm_scale)
   return out
   ```

The first point is a usability improvement; the other two are optional cleanup. No broader restructuring is needed.
