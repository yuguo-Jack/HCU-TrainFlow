- Packs MXFP8 payload and scale bytes into payload-shaped plain tensors.
- Adds `mxfp8_carrier_to_grouped` for reconstructing grouped quantized views.
- Updates distributed tests for caller-owned and automatically allocated carriers.
- Adds guarded reconstruction paths to fused grouped MLP forward and backward execution.

<h3>Confidence Score: 4/5</h3>

The PR does not appear safe to merge because fused grouped MLP execution still processes MXFP8 carriers without activating the required reconstruction branches.

The carrier-producing EP paths now return plain tensors whose bytes are not valid BF16 values, while both grouped-MLP reconstruction branches default to disabled attributes that are never assigned; the ordinary fallback therefore re-quantizes packed payload and scale bytes as if they were high-precision activations or gradients.

File: `transformer_engine/pytorch/ops/fused/grouped_mlp.py` · line 1279

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Carrier reconstruction flags are unset**

When an MXFP8 EP dispatch carrier reaches the fused grouped MLP, reconstruction requires `ep_mxfp8_carrier_input` to be true, but that attribute is never assigned in the repository. The forward path therefore interprets packed E4M3 data and E8M0 scales as ordinary BF16 values, producing incorrect expert activations; the corresponding unset `ep_mxfp8_carrier_grad` guard causes the same corruption for gradients.
