# [JAX] Return EP FFI errors instead of throwing through XLA

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3792) · state: open · merged: False

## Original PR description

# Description

An exception thrown by an `nvte_ep_*` call inside a JAX EP FFI handler (e.g., `handle_mem buffer is too small`) propagates through XLA, which is not exception-safe. On GB200 CI this segfaults the process (`test_primitive_prepare_rejects_undersized_handle`) instead of surfacing a Python error. The handlers now catch the exception and return an XLA FFI internal error, as `EpInstantiate` and the borrowed-comm bootstrap already do.

## Changes

- Add an `ffi_guard` helper in `ffi.h` that runs a callable, returns `ffi_internal_error(...)` if it throws, and otherwise returns `ffi_with_cuda_error_check()`.
- Use it around the `nvte_ep_*` calls in `EpPrepareFFI`, `EpDispatchFFI`, `EpPrepareAndDispatchFFI`, `EpCombineFFI`, `EpDispatchBwdFFI` and `EpCombineBwdFFI`.
