# [PyTorch] Test FusedAdam with an empty param in the last launch slot

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3802) · state: open · merged: False

## Original PR description

# Description

#3212 fixed FusedAdam's handling of empty tensors: `MultiTensorApply` now drops
zero-numel tensors before launch, and `multi_tensor_apply` rejects them. Its
regression test, `test_empty_param_at_end_of_group`, puts the empty tensor in
slot 2 of a 2-tensor launch. That does not cover the case reported in #3202,
where the empty tensor falls in the last `TensorListMetadata` slot and more
tensors follow. Before #3212, that case wrote past the end of the metadata
arrays.

This adds a test for that exact boundary. It puts the empty tensor in slot 36
(depth-4 Adam) or slot 30 (depth-5 Adam with master weights), follows it with
20 more tensors, and compares against `torch.optim.Adam` over 7 steps. It runs
with and without `capturable`.

Fixes #3202

## Testing

1x NVIDIA L40 (sm89), driver 570.195.03, CUDA 12.8, PyTorch 2.11.0+cu128,
built in `nvcr.io/nvidia/cuda:12.8.0-devel-ubuntu22.04` with
`NVTE_FRAMEWORK=pytorch NVTE_CUDA_ARCHS=89`.

On this branch, `python -m pytest -v tests/pytorch/test_fused_optimizer.py -k TestFusedAdam`:
31 passed, 4 skipped (MXFP8 and FP8 block-scaling tests that need a newer GPU),
including all four new cases.

On 68493d2d, the commit before #3212, the same check (run as a standalone copy
of the test, because the in-suite version does not apply there) fails in all
four cases:

- `master_weights=False`: parameters come back NaN (silent corruption).
- `master_weights=True`: `CUDA error: an illegal memory access was encountered`.

This matches the two symptoms described in #3202.

<a href="#"><img alt="P2" src="https://greptile-static-assets.s3.amazonaws.com/badges/p2.svg?v=9" align="top"></a> **FP32 checks compare shared values**

When `master_weights=False`, `p` is already FP32, so `p.detach().float()` shares its storage instead of copying it. Both optimizers update the same values, and the final comparison checks shared storage against itself. Wrong finite updates or skipped updates can therefore pass in both `capturable` cases. Use `p.detach().clone().float()` to give the reference independent values.

```suggestion
        ref_params = [torch.nn.Parameter(p.detach().clone().float()) for p in tst_params]
```
