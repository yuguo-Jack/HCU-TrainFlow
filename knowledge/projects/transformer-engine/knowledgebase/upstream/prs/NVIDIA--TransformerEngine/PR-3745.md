# [PyTorch]Validate grouped split alignment on device

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3745) · state: closed · merged: True

## Original PR description

# Description

Validate grouped split sizes inside the existing device-side multi-output offset scan. GroupedLinear requests 128-row alignment; the generic grouped MLP offset path requests 256-row alignment. The check runs on every CUDA graph replay without a host read or an added kernel launch.

`nvte_splits_to_offsets_multi_v2(split_sizes, split_alignment, outputs, ...)` exposes the check. The original C API symbol remains and forwards with alignment 1. The PyTorch private binding accepts an optional `split_alignment`. 


## Type of change

- [x] Bug fix (non-breaking change which fixes an issue)
- [x] New feature (non-breaking change which adds functionality)

## Changes

- Validate every device-resident split in the prefix-sum kernel, including later 256-element scan chunks. `NVTE_DEVICE_ERROR` prints and asserts; `__trap()` keeps the failure effective in Release builds where `NDEBUG` removes the assert. `NVTE_BUILD_DEBUG=1` enables the assert when building, not at runtime.
- Use a bitmask for power-of-two alignments and run the existing scan with 128 threads for up to 128 splits, retaining 256 threads for larger inputs.
- Pass alignment from GroupedLinear and grouped MLP into the multi-output scan.
- Keep the device-trap failure case out of the automated tests because it invalidates the test process's CUDA context. Existing grouped tensor tests pass; this PR has no negative alignment regression test.
- Document the device-side alignment contract.

### Offset-scan GPU time on GB200

Measured the one- and four-output scan with 8 and 16 experts, 256 rows per expert, and `split_alignment=128` on the PR. The four-output call uses strides `[1,1,7168,4096]`, matching a grouped linear FC1 shape. Inputs are CUDA int64 splits; the first output is int32 and the remaining outputs are int64. Four-output calls use bulk allocation.

| Experts | Outputs | Base µs/call | PR µs/call | PR − Base µs |

GPU times are medians of seven samples, each timing 40 replays of a CUDA graph containing 64 scan calls. Baseline `e32e1238` and PR `06228625` used the same GB200 and container, with their respective built extensions.

This is fine, but bitmasking seems overkill for a kernel that's unlikely to be compute-bound. The following is a little simpler. 
```suggestion
    // Load input from global memory into shared memory
    if (idx < args.num_splits) {
      block_scan[tid] = load_split_size(args.split_sizes, args.split_sizes_dtype, idx);
    } else {
      block_scan[tid] = 0;
    }

    if (args.split_alignment > 1) {
      // Check that splits have required alignment
      if (__syncthreads_or(block_scan[tid] % args.split_alignment)) {
        if (tid == 0) {
          NVTE_DEVICE_ERROR("Grouped split size is not divisible by split_alignment.");
          __trap();  // NVTE_DEVICE_ERROR's assert is compiled out of release builds.
        }
        return;
      }
    } else {
      __syncthreads();
    }
```
