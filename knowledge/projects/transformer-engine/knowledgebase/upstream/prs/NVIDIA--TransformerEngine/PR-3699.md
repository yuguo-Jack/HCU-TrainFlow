# Add cuDNN OSS backward dispatch for context parallel attention

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3699) · state: open · merged: False

## Original PR description

# Description

Add an opt-in cuDNN OSS (FROST) backward provider to TE's fused-attention path so context-parallel attention can execute the open-source D128 and D256 kernels through the common C++ dispatcher.

The first call prepares a cuDNN Python graph and registers its compiled TVM-FFI backward chain. Subsequent calls bind current pointers, stream and caller-owned workspace directly in C++. Forward and context-parallel communication retain their existing implementations.

## Type of change

- [x] New feature (non-breaking change which adds functionality)

## Implementation and supported scope

- Reuse TE's optional CuTeDSL/TVM-FFI registration infrastructure. Cache immutable plans per declaration and device, including mask alignment; validate binding alignment, workspace capacity and overlap before dispatch.
- Support SM100 BF16, separate Q/K/V, D128/D256, nondeterministic backward, no dropout/bias/sinks, and unmasked or top-left causal attention. D256 also supports rectangular bottom-right causal attention when Q length is no greater than KV length; Q-longer-than-KV uniform THD falls back in mode 1 and declines in mode 2. Existing forward rejects that orientation for dense BSHD. D128 bottom-right remains unsupported. Dense BSHD lengths are multiples of 128.
- D128 uses native packed THD, including unequal sequence lengths. D256 THD requires an explicit uniform-layout promise, checked on the GPU on every execution, and converts packed FP32 Stats on the caller's stream.
- A separate default-off flag admits causal THD AllGather for CP2/4/8. It preserves physical batch pitches, selects the current Q half by pointer origin, and retains existing gradient initialization for unused rows. No new Q/K/V repack kernel is added.
- Add a default-off D128 output-initialization policy for strict FROST, BF16 GQA and square compact equal-length THD. The PyTorch binding and common dispatcher share the eligibility predicate; an every-execution GPU check validates lengths/origins before the complete backward chain overwrites dQ/dK/dV. Native/fallback, unequal and rectangular cases retain their fills.
- Retain the complete backward helper chain, scratch initialization and grouped-gradient reductions. Add off, fallback and strict-routing modes, plus tests for changed inputs/addresses, nondefault streams, mask-cache separation and CUDA Graph replay. Replay removes the Python preparation callback after warmup to verify native dispatch.

This PR adds the execution path; it does not change FROST kernel algorithms. [TE #3683](https://github.com/NVIDIA/TransformerEngine/pull/3683) separately optimizes layouts and CP copies.

```bash

export CUDNN_FRONTEND_ENABLE_FROST_ENGINES=1
export NVTE_FUSED_ATTN_FROST=2  # strict OSS backward; 1 permits backend fallback
# Optional: omit fully overwritten output fills for compact D128 GQA THD:
export NVTE_FUSED_ATTN_FROST_D128_NOZERO=1
# For equal-length D256 THD:
export NVTE_FUSED_ATTN_FROST_UNIFORM=1
# Additionally enable the qualified causal THD AllGather layout:
export NVTE_FUSED_ATTN_FROST_ALLGATHER=1
python -m pytest -v tests/pytorch/attention/test_frost_attn.py
```

Warm up each declaration before CUDA Graph capture. Leave the uniform-layout promise disabled for unequal THD and gapped layouts outside the explicit AllGather contract. `NVTE_FUSED_ATTN_FROST=0` retains the existing route.
