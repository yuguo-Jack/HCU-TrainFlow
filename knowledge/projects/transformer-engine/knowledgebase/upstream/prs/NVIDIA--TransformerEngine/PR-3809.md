# CuTeDSL NVFP4 1D quantize kernels

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3809) · state: open · merged: False

## Original PR description

# Description

Adds register-resident (g2r) NVFP4 1D quantize kernels to the CuTeDSL NVFP4 backend: the CuTeDSL counterparts of the CUDA register kernel in the companion CUDA PR (`teddy/nvfp4-register-quantize-1d`). The backend is organized like the MXFP8 one after #3642: a common module with the config, a kernel base class (`supports()` / `eligible_to_dispatch()`), the `NVFP4QuantizeEntry` dispatcher and compilation, plus one module per kernel.

**Depends on #3223.** The first commit brings that PR's NVFP4 backend onto current main, whose CuTeDSL infrastructure has changed since it branched; it stays authored by its original author. This PR will be rebased onto #3223 once that lands, so the first commit is expected to shrink or disappear. Opened as a draft for visibility until then.

## Changes

- Port the #3223 CuTeDSL NVFP4 backend to the current CuTeDSL plumbing (`NVTE_WITH_CUTEDSL`, `NVTE_ENABLE_CUTEDSL_BACKEND`, `TVMFFIConfigCache`), with CUDA fallback (and a reason under `NVTE_WARN_IF_CUTEDSL_BACKEND_NOT_CHOSEN`) for configs the compiled ABI cannot take. Also fixes the transposed-output shape for rank > 2 inputs and a ptxas rejection of an immediate operand to `max.xorsign.abs.bf16x2`.
- Split the backend into `quantize_nvfp4_common.py` and per-kernel modules; the TMA-staged tuned-1D kernel becomes `NVFP4QuantizeGeneralG2SKernel`, the fallback for every config.
- Add `NVFP4QuantizeRowwiseG2RKernel` (rowwise only) and `NVFP4QuantizeBidimensionalG2RKernel` (rowwise + columnwise), dispatched for BF16 input without fast math or row-scaled NVFP4 when their alignment and grid checks pass; exactly one kernel launches per call. Round-to-nearest output is byte-identical to the CUDA kernels.
- Stochastic rounding in the g2r kernels draws Philox once per output block, keyed by the block's coordinates and direction (`philox_rng.py`); each draw is plain Philox4x32 (as curanddx computes it) with `NVTE_BUILD_NUM_PHILOX_ROUNDS` rounds. Its random bits for a given seed differ from the general kernel's.
- Tests (`test_nvfp4_cutedsl_backend.py`, laid out like the MXFP8 one): CUDA vs CuTeDSL byte equality over shapes, directions, fast math, row scaling, zero blocks and the noop flag; inputs the g2r kernels must hand to g2s (16-byte-aligned pointer, grid.y overflow); stochastic rounding checked statistically and for determinism; the per-block draw against plain Philox4x32.

## Results (GB200, ncu kernel time, BF16 randn, E4M3 scales, cold L2)

Speedup over TE main (`quantize_transpose_tuned_1D`), shapes 1024x1024 to 32768x16384:

| Mode | CuTeDSL g2r vs main | CuTeDSL g2r vs CUDA register kernel |
|---|---|---|
| Rowwise, round-to-nearest | 1.04-1.48x | 0.99-1.04x |
| Rowwise, stochastic rounding | 1.12-1.49x | 0.97-1.08x |
| Rowwise + columnwise, round-to-nearest | 1.12-1.41x | 1.00-1.04x |
| Rowwise + columnwise, stochastic rounding | 1.21-1.63x | 1.00-1.13x |

Per-shape numbers and the diff: https://claude.ai/artifact/3eqb1p2shCLjyyD68SuQ3f?sk=R5I3hkJLPOMfmm88DJYRUA
