## Original PR description

# Description

Performance optimization of the NVFP4 RHT cast-fusion kernels on SM100 (dense, grouped, and graph-safe grouped quantization). Output numerics are unchanged.

## Changes

- Remove register spills in the RHT cast-fusion kernels (column-quant epilogue processed in chunks; per-group tensors rebuilt per tile).
- Use packed `mul.rn.f32x2` (FMUL2) for scale computation and data scaling.
- 256-bit row-quant store layout.
- Graph-safe grouped kernel: stage group metadata in shared memory and cache the current tensor range instead of re-reading global memory per tile.
- Cheaper tile-scheduler index math.

I tested this PR on a B300 (sm_103). TE was built for `103a` from main `63451d6b`, once as-is and once with this PR (`5e7536a1`) applied, CUDA 13.3.

**Numerics.** For each path I dumped every output buffer of the NVFP4 quantization with RHT, rowwise + columnwise, from the same inputs and seeds. Each build gives byte-identical buffers on repeated runs.

| path | shapes | without stochastic rounding | with stochastic rounding |
|---|---|---|---|
| dense (`NVFP4Quantizer(x)`) | (128, 128) to (8192, 7168), 6 shapes | identical | identical |
| grouped (`tex.split_quantize`) | 4 split configurations, including an empty split | identical | rowwise data differs in the 3 configurations with 128-row-aligned splits, columnwise data identical |
| graph-safe grouped (`tex.group_quantize`) | 3 configurations with 128-row-aligned splits | identical | rowwise data differs, columnwise data identical |

The fourth grouped configuration (8 × 320 rows) is not 128-row aligned. It runs `group_rht_gemm_device`, which this PR doesn't change, so it serves as a control rather than as coverage. Its data matches; the rowwise scales differ only in the padding rows past row 320.

The amax of the empty split differs because neither build writes it. That predates this PR.

So with stochastic rounding, the grouped and graph-safe grouped kernels produce different rowwise bytes than main. The aggregate error statistics I measured are the same in both builds: rowwise dequantization rms error / rms x 0.1373–0.1374, and mean bias / |x| within ±1.3e-4, the same range as without stochastic rounding. I did not check that the random bits stay independent per element. Without stochastic rounding, every output is bit-identical.

`tests/pytorch/nvfp4/` with this PR (the RHT exact, grouped, graph-safe grouped, SR and RHT swizzle-fusion files): 1555 passed, 0 failed, 274 skipped.

**Kernel time** (Nsight Compute `gpu__time_duration`, median of 3 launches, µs; cases matched to kernels by launch order):

| case | main | this PR |
|---|---|---|
| dense 4096×2048 | 16.9 | 16.3 |
| dense 8192×7168 | 45.0 | 39.2 |
| dense 2560×2048 | 16.0 | 14.8 |
| grouped, 8 × 1024 rows, N=4096 | 31.7 | 27.8 |
| grouped, 6 splits (256/0/768/1280/512/128), N=7168 | 29.3 | 25.1 |
| graph-safe grouped, 8 × 1024 rows, N=4096 | 39.3 | 27.4 |
| graph-safe grouped, same 6 splits, N=7168 | 37.1 | 26.8 |
| `group_rht_gemm_device` (not changed by this PR), 8 × 320 rows | 17.2 | 17.2 |

Registers per thread go from 128 to 96 in the three changed kernels.

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Equal-shaped rowwise quantization fails**

The new staging loop reads `first_dims` even when only rowwise output is requested. For equal-shaped groups, `GroupedTensor` uses an empty `first_dims`, so this pointer is null. The old row-only path never read it; the new path hits an invalid device-memory read before quantization starts.

Load `group_first_dims` only when columnwise output needs it, and derive equal-group dimensions from the logical shape instead of reading the optional array.
