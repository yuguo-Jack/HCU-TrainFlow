# [PyTorch][CP] Make THD CP helper kernels to be shared memory size aware

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3698) · state: closed · merged: True

## Original PR description

# Description

Large packed-document counts could make `cu_seqlens` exceed the per-block shared-memory allowance, causing THD context-parallel kernel launch failures.

## Changes

Boundary storage was selected using device-reported limits: default shared memory when the table fits, otherwise the original global table. Opt-in shared memory was removed to avoid staging large boundary tables per block.

Existing shared-memory pre-scaling was retained. For example, partition/reorder with `world_size = 2` stages `[0, 8, 24]` as `[0, 4, 12]`. Shared reads use divisor `1`; global reads use the original table and divisor `2`.

Compile-time `use_shared` specializations were retained to preserve shared-path optimization. The boundary view was replaced with ordinary pointer and explicit `read_divisor` arguments in the kernels and other boundary-reading helpers (e.g. `binary_search` and `thd_partition_src_index`). No global scratch allocation was introduced.

The following seven THD utility kernels were updated:

- `thd_partition_indices_kernel`
- `thd_reorder_between_sequence_and_cp_rank_order_kernel`
- `thd_copy_valid_tokens_from_per_split_to_rank_local_kernel`
- `thd_read_half_tensor_kernel`
- `thd_lse_kernel` — second-half LSE reads and correction
- `thd_out_correction_kernel`
- `thd_grad_correction_kernel`

Regression tests cover default-shared and global-memory boundaries, including the two-table copy case.
