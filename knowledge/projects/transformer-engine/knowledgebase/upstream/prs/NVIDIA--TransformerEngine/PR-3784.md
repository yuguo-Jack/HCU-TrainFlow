# [JAX] Disable TE C API CuTeDSL backend at import time

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3784) · state: closed · merged: True

## Original PR description

# Description

When XLA + TE/JAX's stream capture dry-run warmup + TE core CuTeDSL backend are all put together, we see `CUDA_ERROR_STREAM_CAPTURE_UNSUPPORTED` on some tests. Long-term, I am investigating further to make this compatible. But short-term, I will be disabling the TE core CuTeDSL backend in TE/JAX until we are compatible with this backend.

<a href="#"><img alt="P2" src="https://greptile-static-assets.s3.amazonaws.com/badges/p2.svg?v=9" align="top"></a> **PyTorch loses CuTeDSL**

If a PyTorch-only user has JAX installed but not the TE JAX extension, this assignment still disables their requested CuTeDSL backend. The parent package eagerly imports `transformer_engine.jax`. This code changes the environment before `load_framework_extension("jax")` fails, and the parent catches that failure without restoring the setting. PyTorch's first MXFP8 call then caches the disabled setting and falls back to regular CUDA kernels despite `NVTE_ENABLE_CUTEDSL_BACKEND=1`.

Only disable the backend after confirming that the TE JAX extension is available.

**Knowledge Base Used:** [CuTeDSL kernel backend](https://app.greptile.com/nvidia-public-github/-/custom-context/knowledge-base/nvidia/transformerengine/-/docs/native-cutedsl.md)
