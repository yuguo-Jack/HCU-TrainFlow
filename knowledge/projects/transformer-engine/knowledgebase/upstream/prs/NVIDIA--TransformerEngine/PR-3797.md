# [CI] Disable TF32 for the L0 PyTorch numerics tests

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3797) · state: open · merged: False

## Original PR description

# Description

Make the L0 PyTorch numerics tests give the same result outside the CI image.

Transformer Engine selects TF32 for pure FP32 GEMM, and the PyTorch references in these tests do not use it. Where cuBLAS takes the TF32 path, FP32 cases in `test_numerics.py` and `tests/pytorch/debug/test_numerics.py` fail on correct code, because the differences exceed the FP32 tolerances. The launchers already set `NVIDIA_TF32_OVERRIDE=0` for `test_mhc.py` for the same reason.

## Changes

- Set `NVIDIA_TF32_OVERRIDE=0` for the numerics tests in `qa/L0_pytorch_unittest/test.sh` and `qa/L0_pytorch_debug_unittest/test.sh`.

## Validation

Both launcher versions ran on NVIDIA B200 with CUDA 13.2, PyTorch 2.15.0+cu132, and no override in the environment. Without this change, FP32 cases fail in the `test_numerics.py` command, and the debug launcher exits with an error. With this change, the `test_numerics.py` command finds no failures, and the debug launcher exits successfully. `test_numerics.py` shows the same failures on the same cases with PyTorch 2.11 and 2.13, and the override removes them.

The environment of the CI image was not visible, so the reason that these tests pass there without this variable is not known. If the image already disables TF32, this change has no effect in CI. A100 and H100 were not tested.
