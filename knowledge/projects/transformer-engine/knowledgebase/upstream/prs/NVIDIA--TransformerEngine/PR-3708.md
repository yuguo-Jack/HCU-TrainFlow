# [Common] Use .shared::cta for 2D TMA loads on sm_12x

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3708) · state: open · merged: False

## Original PR description

# Description

On sm_120 and sm_121 (RTX 50 series, RTX PRO Blackwell, GB10), the first launch of a TE cast kernel that loads
through `ptx::cp_async_bulk_tensor_2d_global_to_shared` raises the CUDA context's per-thread stack limit from
1,024 B to 14,624 B. That covers every NVFP4, MXFP8 and FP8 TMA cast kernel and the Hadamard amax kernels. The
driver then keeps local memory for that stack resident for the life of the context. On an RTX 5080 Laptop GPU
(60 SMs), the first NVFP4 quantization takes **1,196 MiB of device memory** (400 MiB on a 20-SM RTX 5050), none of
it visible to PyTorch's allocator (`torch.cuda.memory_reserved()` does not grow). The model does not need that
memory: it is reserved for a driver syscall that TE never calls.

This PR makes the helper use the `.shared::cta` destination on sm_12x. The stack limit then stays at 1,024 B, that
memory stays free, and outputs are bitwise identical.

Related: #2255 (NVFP4 on RTX 50 series), #3300 (NVFP4 RHT for SM120/SM121, whose sm_12x path loads through this
helper and is also covered).

## Root cause

`cp_async_bulk_tensor_2d_global_to_shared` (`transformer_engine/common/util/ptx.cuh`) issues

```
cp.async.bulk.tensor.2d.shared::cluster.global.tile.mbarrier::complete_tx::bytes [dst], [tensorMap, {x, y}], [mbar];
```

On sm_12x, ptxas lowers the `.shared::cluster` destination into a run-time branch. A destination in the executing CTA
gets a native `UTMALDG`; any other destination calls (`CALL.ABS.NOINC`) the driver-provided
`__cuda_syscall_cp_async_bulk_tensor_2d_tile_unicast`, which the kernel records as an `EIATTR_EXTERNS` entry. TE
never takes the remote branch, because its destinations are always CTA-local. Still, any kernel that contains the
call is launched with the syscall's stack requirement. At that first launch the driver raises the context-wide stack
limit and reserves local memory for it: roughly SMs × max resident threads per SM × stack size, here
60 × 1,536 × 14,624 B. Both last for the lifetime of the context.

The lowering reproduces without TE (`tma_forms.cu`, attached: one kernel per destination form; nvcc 13.4.92, `-O3`):

| target | `.shared::cta` | `.shared::cluster` |
|---|---|---|
| sm_90a | 56 SASS instructions, `UTMALDG`, no call, REG 10, STACK 0 | identical SASS |
| sm_100a | 56 SASS instructions, `UTMALDG`, no call, REG 10, STACK 0 | identical SASS |
| sm_120, sm_120a, sm_120f, sm_121a | 56 SASS instructions, `UTMALDG`, no call, REG 10, STACK 0 | 80 SASS instructions: CTA-rank check, `UTMALDG` **and** `CALL.ABS.NOINC` → `__cuda_syscall_cp_async_bulk_tensor_2d_tile_unicast`; REG 24, STACK 8 |

Runtime of the same pair (`tma_stack_repro.cu`, NVIDIA GeForce RTX 5050, 20 SMs, CUDA 13.4): `.shared::cta` keeps the stack limit at 1024 → 1024 B with 0.0 MiB taken; `.shared::cluster` raises it 1024 → 14624 B and the device loses 400.0 MiB. Both copies are verified correct, and `cudaFuncGetAttributes().localSizeBytes` reports only 8 B for the cluster kernel.

## Fix

`dst_shmem` and `mbar` always come from `__cvta_generic_to_shared`, which yields `.shared::cta` window addresses. A
`.shared::cta` address used in the `.shared::cluster` form already refers to the executing CTA's own shared memory.
So on sm_12x the helper can issue the `.shared::cta` form of the same copy: same bytes, same mbarrier transaction
count, no remote path. TE already uses that form in `cp_async_bulk_tensor_2d_global_to_shared_cta` (FP8
block-scaling grouped quantize), and the 1D bulk-copy helper `cp_async_bulk_tensor_1d_global_to_shared` uses the
`.shared::cta` destination on every arch ≥ sm_100. The `.shared::cta` destination needs PTX ISA 8.6 (CUDA 12.8),
which every sm_12x build already requires.

The change is confined by the preprocessor to `__CUDA_ARCH__ >= 1200`, so sm_90/100/103/107/110 code compiles exactly
as before. In the minimal test, sm_90a and sm_100a produce identical SASS for both forms. Switching the helper to
`.shared::cta` unconditionally, like the 1D helper, would therefore be equally valid if maintainers prefer a single
form. I kept the narrow version so that datacenter targets need no re-validation.

## How to reproduce

```bash
# sm_120/sm_121 GPU; TE built for sm_120 (the default arch list includes it)
python repro_stack_limit.py
#   without: stack limit (bytes/thread): 1024 -> 14624
#            device memory outside the caching allocator: +1196.0 MiB   (RTX 5080 Laptop GPU)
#   with:    stack limit (bytes/thread): 1024 -> 1024
#            device memory outside the caching allocator: +0.0 MiB
#   (NVIDIA GeForce RTX 5050, 20 SMs, main: without → +400.0 MiB; with → +0.0 MiB)
```

`repro_stack_limit.py` (attached) quantizes one 1024×2048 BF16 tensor with `te.NVFP4Quantizer`. Before and after the
cast, it prints `cuCtxGetLimit(CU_LIMIT_STACK_SIZE)` and `total − free − memory_reserved()`. `tma_stack_repro.cu`
(attached) reproduces the effect without TE: `nvcc -std=c++17 -O3 -arch=sm_120a tma_stack_repro.cu -lcuda`, then run
it with `cta` and with `cluster`.

## Tests

`tests/pytorch/nvfp4/test_sm12x_tma_stack_limit.py` (new; L0 runs `tests/pytorch/nvfp4` as a directory). On sm_12x,
it runs the first NVFP4 cast (1D and 2D block scaling) in a fresh process, because the limit is per context and
never shrinks. It asserts that `CU_LIMIT_STACK_SIZE` is unchanged, and skips on other GPUs. On `main` @ eb3c860
(NVIDIA GeForce RTX 5050): **2 failed in 5.86s** without the fix (`The first 1d NVFP4 cast raised the per-thread stack limit from 1024 to 14624 bytes`), **2 passed in 5.97s** with it.

## Out of scope (same lowering, separate concerns)

- `fused_attn/flash_attn.cu` has a file-local `cp_async_bulk_tensor_4d_global_to_shared` that uses the
  `.shared::cluster` form too. On sm_12x, its 22 `multi_tensor_transpose_to_bhsd::transpose_to_bhsd_kernel<…>`
  instantiations still reference `__cuda_syscall_cp_async_bulk_tensor_4d_tile_unicast`. The TMA path of
  `multi_tensor_transpose_to_bhsd` is taken for `sm_arch >= 100`, which includes sm_12x, so the same change most
  likely applies there. It deserves its own PR with attention-path validation.
- `gemm/cutlass_grouped_gemm.cu`: 6 CUTLASS SM90 grouped-GEMM kernels (cluster shape 1×2×1), built for the sm_120
  arch-specific target, reference `__cuda_syscall_cp_async_bulk_tensor_2d_tile_multicast`. That is genuine multicast,
  which `.shared::cta` cannot express.

## References (outside TE)

- kekzl/imp#2640 (merged 2026-10-08) reports the same lowering on an RTX 5090: `cudaLimitStackSize` 1024 → 14448 B
  and ~3.5 GB of local memory, both cleared by moving bulk copies to `.shared::cta`.
- NVlabs/cuda-oxide#1337 tabulates the TMA global→shared forms on sm_120a vs sm_100a: only `.shared::cta` avoids the
  syscall path on SM12x. SM12x does support peer destinations through the emulated path, so a by-target switch is
  sound only where every destination is CTA-local, as it is for this helper.
