# [Common] Make CI fail if CuTeDSL kernels with supported configs are not used

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3746) · state: open · merged: False

## Original PR description

# Description

We need fail cases where we expect CuTeDSL kernels are used to avoid silent fallbacks like #3743 catches. This also introduces a breaking change that `NVTE_WARN_IF_CUTEDSL_BACKEND_NOT_CHOSEN` is changed to `NVTE_REPORT_IF_CUTEDSL_BACKEND_NOT_CHOSEN` which can warn or fail the test.

## Changes

Please list the changes introduced in this PR:

- Report CuTeDSL kernels falling back with a warn or fail option based on the env var
- 2D quantization is currently unsupported so for this it won't trigger warn or fail and I added a TODO to remind me of adding this kernel later
- Add cuda-bindings in setup.py since it's used by quantize_mxfp8.py and fused_mla_q_uproj
- Make CI scripts fail if falling back to CUDA

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Backend comparison tests fail**

With CuTeDSL built and enabled, this global setting breaks the existing CUDA-versus-CuTeDSL tests. `tests/pytorch/mxfp8/test_mxfp8_cutedsl_backend.py` calls `set_cutedsl_backend(False)` to compute its CUDA reference. That call now throws “the CuTeDSL backend is disabled” before the comparison can run. The JAX tests do the same and inherit the same setting from `qa/L0_jax_unittest/test.sh`.

Allow intentional CUDA reference calls while keeping strict checks for the CuTeDSL calls. The reporting level is read once, so changing the environment after the first native call will not fix this.
