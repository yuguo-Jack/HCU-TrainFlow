# Run minimum-versions build on pushes to main to warm sccache

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3721) · state: closed · merged: True

## Original PR description

# Description

`minimum_versions.yml` only runs on `pull_request`. sccache's GitHub Actions cache backend therefore stores every compiled object in a PR-scoped cache (`refs/pull/<N>/merge`), which no other PR can read. When we checked, the repo had 0 cache entries on `main` and ~24.6k PR-scoped ones. As a result every new PR's first run compiles TE from scratch: ~2.6% sccache hit rate and ~60 min median wall time, versus ~10 min per job once that PR's own cache is warm.

Running the workflow on pushes to `main` fills the base-branch cache scope, which PR runs can restore.

## Measurement

Measured on a fork (agarg21/TransformerEngine), 3 fresh PRs per arm, all green:

| | First run of a new PR (median) | Job-minutes per run | sccache hit rate |
|---|---|---|---|
| Before (no main scope) | 63.9 min | 116 | 2.6% |
| After (main warmed by one push run) | 14.7 min | 24 | 96.4% |

Fork run IDs: before 39471922855, 39471924582, 39471927842; after 39496253340, 39496257361, 39496261774; warm-up push run 39482052619.

Caveats:
- Only each PR's first run benefits; later pushes to the same PR already hit that PR's own cache. That is roughly 88 of ~986 PR runs/month.
- Cost: one extra build per merge to `main` on GitHub-hosted runners, mostly warm after the first.
- Revert: remove the 3 lines.
