# [Common] Fuse RMSNorm forward with MXFP8 quantization

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3657) · state: closed · merged: True

## Original PR description

RMSNorm forward with MXFP8 output used cuDNN's fused kernel or, in PyTorch without NVTE_NORM_FWD_USE_CUDNN, a BF16 normalization followed by a separate quantization of the rounded values. cuDNN's kernel runs 128 CTAs for 4096 rows and cannot write GEMM-swizzled scaling factors, so a swizzle kernel follows before the GEMM.

Add a fused kernel. A pre-pass computes rsigma per row, then one CTA per 32x128 tile normalizes in FP32, quantizes row- and/or column-wise, and writes the scaling factors in compact or GEMM-swizzled layout. The output is the MXFP8 quantizer applied to the FP32 normalized values, as cuDNN computes it; the two can differ only through the rounding of rsigma.

Use the kernel for RMSNorm with MXFP8 output whenever both dimensions are multiples of 128, and let the PyTorch binding request swizzled scaling factors in that case. NVTE_NORM_FWD_MXFP8_USE_CUDNN=1, or nvte_enable_cudnn_norm_fwd_mxfp8(true), restores the previous paths.

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Requested scales are ignored**

With both dimensions divisible by 128 and cuDNN disabled, `MXFP8Quantizer(with_2d_quantization=True)` now skips `MXFP8Quantizer::quantize`. The fused kernel chooses separate scales for each row or column instead of the requested 32×32 blocks. This silently changes the scales and FP8 values. Previously, the unfused path forwarded the setting to `nvte_quantize_v2`.

Keep these quantizers on the unfused path until the fused kernel supports this option.

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **cuDNN override breaks forward**

The binding reads `NVTE_NORM_FWD_MXFP8_USE_CUDNN` directly, but the common API reads a cached flag changed by `nvte_enable_cudnn_norm_fwd_mxfp8`. If the environment variable is unset and a caller invokes that setter with `true`, the binding still selects the TE path. With `optimize_for_gemm=True`, it allocates swizzled scales. The common API then selects cuDNN and rejects those scales, so forward throws instead of restoring the previous path.

Use the same backend state when choosing the output layout and launching the operation.

<a href="#"><img alt="P2" src="https://greptile-static-assets.s3.amazonaws.com/badges/p2.svg?v=9" align="top"></a> **Reserved SMs are ignored**

This early return drops `multiprocessorCount`, so both new kernels ignore the caller's `sm_margin`. On the default fused path, `NVTE_FWD_LAYERNORM_SM_MARGIN` and `NVTE_INF_LAYERNORM_SM_MARGIN` no longer reduce the work launched at once. Large inputs can use the SMs users intended to leave for communication, hurting overlap.

Pass the limit through and use it when sizing the launches, or retain the previous path when a margin is requested.

  - RMSNorm+quant+swizzle: 2 bytes read, 2+2/32 bytes write

That quantizer leaves `z->data.shape` at `{0}`, but `nvte_rmsnorm_fwd` requires it to match the input shape before reaching the new kernel. Keep column-only quantizers on `UNFUSED`, or update the common API to check the logical output shape.
