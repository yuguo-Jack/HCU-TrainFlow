# [PyTorch] Fix unlimited attention window handling for FlashAttention 4

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3570) · state: closed · merged: False

## Original PR description

## Summary

FlashAttention 4 changed its window handling in [`4.0.0b30`](https://github.com/Dao-AILab/flash-attention/commit/17498dad3497abd3800f32da56c6fe4fe78d9556): `(-1, 0)` is now treated as an effectively empty local window rather than an unlimited causal window. Transformer Engine still uses `-1` as its unlimited-window sentinel.

| FA4 version / TE behavior | Value passed to FA4 | Interpretation |
| --- | --- | --- |
| FA4 < `4.0.0b30` | `(-1, 0)` | Unlimited causal attention |
| FA4 >= `4.0.0b30` without this PR | `(-1, 0)` | Effectively empty local window |
| FA4 >= `4.0.0b30` with this PR | `(None, 0)` | Unlimited causal attention |

This PR converts TE's `-1` sentinel to FA4's `None` convention in standard and context-parallel forward and backward paths.

## Tests

- Added a unit test for the sentinel conversion, including `None` and finite windows.
- Added a BSHD/THD causal forward and backward comparison against PyTorch SDPA while forcing FA4.
- AGA 905211 passed the helper unit test against the matching internal TE extension.
- AGA 906233 passed head-256 causal BSHD and THD FA4 b32 forward/backward comparisons with PyTorch SDPA using the cherry-picked TE commit in a full NGC-base image.
