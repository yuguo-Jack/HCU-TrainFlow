# fix(fp8): floor tiny amax so scale_inv stays at least FLT_MIN

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3764) · state: open · merged: False

## Original PR description

# Description

`compute_scale_from_amax` returned scale 1 only for a zero, infinite, or NaN amax. A positive amax below `max_fp8 * FLT_MIN` missed that check, so `scale = max_fp8 / amax` overflowed and `scale_inv` was stored as an FP32 subnormal.

`max_fp8 * FLT_MIN` is exact in binary32. This change floors a positive amax at that value before the division. `scale` is then at most `2^126` and `scale_inv` is at least `FLT_MIN`. An amax of `7.7e-37` is amplified to about 65 and kept as a non-zero FP8 code instead of flushing the tile to zero. Zero, inf, and NaN still return scale 1. An amax at or above the threshold, including ordinary training magnitudes, stays bitwise identical.

The E4M3 threshold is `448 * FLT_MIN` (`0x04e00000`). The E5M2 threshold is `57344 * FLT_MIN` (`0x08600000`).

No linked issue.

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Shape mismatch fails the test**

`_scale_inv` has shape `(1,)`, but `flt_min` is a scalar with shape `()`. `torch.testing.assert_close` requires matching shapes; it does not broadcast them. The new test therefore fails on FP8-capable GPUs even when the quantizer returns the correct value, causing the PyTorch CI job to fail.

Create the expected value with `torch.full_like(x_te._scale_inv, torch.finfo(torch.float32).tiny)`.

```suggestion
        flt_min = torch.full_like(x_te._scale_inv, torch.finfo(torch.float32).tiny)
```
