# [PyTorch] Allow ZeroTensor dummy weight gradients

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3670) · state: closed · merged: True

## Original PR description

With fuse_wgrad_accumulation, the modules accumulate the weight gradient into main_grad and return a dummy weight gradient. When one backward pass uses a weight twice, autograd adds the two dummies; for an LM head shared by the main and MTP heads in Megatron-LM that is a [vocab, hidden] add whose result is discarded (0.44 ms for 129280 x 7168 on VR200).

A parameter with zero_tensor_dummy_wgrad set now gets a ZeroTensor dummy, which has no storage and costs nothing to add. zero_out_wgrad keeps precedence and its zero-filled dummy; other parameters get the dummy they get today.

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Backward gets the wrong GPU**

`LayerNormMLP` now gets its ordinary dummy gradients from a cache keyed only by shape and dtype. If a process runs a backward pass on one GPU, then runs a same-shaped module on another GPU, the second backward returns the first GPU's cached tensor. Autograd rejects that gradient because it is on the wrong device. Both weights are affected, including when `zero_out_wgrad=True`.

Include the device in the cache key, or keep fresh allocations for these branches.
