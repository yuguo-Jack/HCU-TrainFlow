<h3>Summary</h3>

This PR reduces Python work in `GroupedLinear` while keeping quantizers and saved tensors ready for backward.
- GroupedLinear uses shared quantizers when it can run one grouped GEMM.
- Quantized weights keep enabled layouts when grouped operations change their needs.
- Bias gradients arrive during the main backward even when weight gradients wait.
- Saved-tensor restoration tracks consumed tensors with a cursor.

- greptile-apps[bot] · comment · 2026-10-16T09:25:28Z · [source](https://github.com/NVIDIA/TransformerEngine/pull/3613#discussion_r4292995320)

File: `transformer_engine/pytorch/ops/basic/grouped_linear.py` · line 983

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **FP8 backward fails on Hopper**

On Hopper, a discrete FP8 weight created under `torch.no_grad()` has no transpose buffer. Removing `w.update_usage(...)` means `_get_discrete_weights_for_gemm` now changes only quantizer flags when training later needs input gradients. Those flags do not build the missing buffer. Forward succeeds, but backward calls grouped GEMM with `layout="NN"` and fails because the weight has no columnwise data.

Keep the call that builds required layouts for existing quantized weights.
