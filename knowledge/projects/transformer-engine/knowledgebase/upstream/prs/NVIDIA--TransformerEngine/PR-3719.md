# [Common] Use FP8 fast accumulation in the cuBLASMp comm+GEMM overlap

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3719) · state: open · merged: False

## Original PR description

The cuBLASMp comm+GEMM backend ignored use_split_accumulator: nvte_all_gather_gemm, nvte_gemm_reduce_scatter and nvte_gemm_all_reduce had no parameter for it, and cuBLASMp had no attribute for it. FP8 forward GEMMs therefore ran with split accumulation on Hopper, while the cuBLASLt and Userbuffers paths use fast accumulation there. cuBLASMp 0.12.0 adds CUBLASMP_MATMUL_DESCRIPTOR_ATTRIBUTE_FAST_ACCUM.

Add use_split_accumulator to the three functions, after accumulate as in nvte_cublas_gemm, and pass the value that the comm+GEMM overlap already receives. When A and B are FP8 and split accumulation is not requested, the GEMM sets the attribute, as cublaslt_gemm.cu does with cuBLASLt. With cuBLASMp older than 0.12.0, at build time or at run time (nvte_cublasmp_version()), the GEMMs keep split accumulation.

The C++ comm GEMM test passes the setting to the overlapped GEMM and runs one FP8 case per collective with fast accumulation. Its cuBLASLt reference keeps split accumulation, so these cases check the accuracy as well.
