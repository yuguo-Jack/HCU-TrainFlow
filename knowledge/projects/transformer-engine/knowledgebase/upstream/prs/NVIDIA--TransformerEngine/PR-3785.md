# [PyTorch] Fix grouped split validation for GroupedLinear/GroupedMLP ops

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3785) · state: closed · merged: True

## Original PR description

## Summary
- Set `GroupedLinear` split alignment from the active recipe: 1 for BF16/FP16 and Blackwell FP8 current scaling, 16 for Hopper FP8 current scaling, and 128 for MXFP8/NVFP4/FP8 block scaling. An explicit value applies unless the deprecated environment override forces 256.
- Reject negative splits at every alignment and check 16-byte uniform and discrete-A GEMM leading dimensions, with or without bias.

## Cause
PR #3745 passed the default `split_alignment=128` into the device-side scan for every grouped-tensor path. Unquantized BF16 accepts 32-row groups, so `TestFuser.test_deferred_param_init` trapped at the forward call. Passing alignment 1 alone also bypassed the scan's negative-size guard; this PR makes that guard unconditional.

Making the contract different for quantized and unquantized compute is hacky and unintuitive. If the user has promised a certain alignment, we should expect them to provide it.

2. Relax the alignment check when the user-promised alignment is stricter than necessary (https://github.com/NVIDIA/TransformerEngine/pull/3785/changes#r4427584832).

1 is more logical, but it might increase the scope of this PR.

File: `transformer_engine/pytorch/ops/basic/grouped_linear.py` · line None

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **FP8 backward accepts unsupported splits**

`_default_split_alignment` now allows any split size for FP8 current scaling, but Hopper still needs splits divisible by 16 when computing weight gradients. For example, splits `[1, 127]` with 128-wide features pass forward checks. In backward, `layout="NT"` selects physically transposed columnwise data, so each split becomes the FP8 leading dimension. The new feature-width check does not check that dimension, so backward sends unsupported dimensions to cuBLAS and can fail.

Keep a 16-element split requirement for this path, or pad the columnwise data and its layouts.
