# [PyT] Guard for buggy quack version

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3762) · state: closed · merged: True

## Original PR description

## Description

Fail fast when a known Quack/CUTLASS DSL incompatibility would cause FA4 backward to hang on Hopper. The error reports the installed versions and directs users to a compatible Quack release containing the fix from [Quack PR \#181](<https://github.com/Dao-AILab/quack/pull/181>).

The guard applies when FA4 is selected, gradients are required, and all of these conditions hold:

- GPU compute capability is SM90.
- Quack is `>=0.6.0,<0.6.4`.
- CUTLASS DSL is `>=4.6.2`.

Related upstream issue: [Dao-AILab/flash-attention\#3078](<https://github.com/Dao-AILab/flash-attention/issues/3078>).

## Changes

- Cache Quack and CUTLASS DSL versions during FA4 initialization.
- Reject the affected combination before dispatching FA4, including when backend selection is cached.
- Provide an actionable RuntimeError with detected versions and the upstream fix link.

## Validation

Local H100 validation: **134 checks passed, two hardware-specific skips**. Validation tests remain local.

Confirmed early failure with affected Quack and successful backward with Quack 0.6.4. Covered train/eval, individual Q/K/V gradients, inference, cached selection, `torch.compile` with the eager backend, activation checkpointing, and mixed THD dispatch. Formatting checks passed.
