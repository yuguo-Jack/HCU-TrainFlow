# Fix CPU QuantizedTensor dequantize RecursionError

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3812) · state: open · merged: False

## Original PR description

`_FromNVFP4Func.forward()` and `_FromMXFP8Func.forward()` call `tensor.to(device=cuda)` on the full `QuantizedTensor` when dequantizing a CPU-resident quantized tensor. This triggers `__torch_dispatch__`, which calls `maybe_unwrap` -> `dequantize()` -> `forward()` -> `tensor.to()` -> `__torch_dispatch__` in an infinite loop, producing a `RecursionError`.

**Fix:** move the raw inner data tensors to CUDA individually via `get_metadata()` and construct a plain `TensorStorage` for the `tex.dequantize` call. Plain `torch.Tensor.to()` on the inner buffers does not enter `__torch_dispatch__`, breaking the cycle.

**Testing:** added `tests/pytorch/test_cpu_quantized_tensor_dequantize.py` covering both NVFP4 and MXFP8 quantizers: explicit `dequantize()`, arithmetic (`xq_cpu + 0`), roundtrip value fidelity, and `.float()` cast.

Fixes #3294

<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Tests fail on older GPUs**

The CUDA-only skip lets these tests run on GPUs that cannot quantize NVFP4, such as H100. NVFP4 needs compute capability 10.0 or higher; its kernel raises a device error on older GPUs. Check `is_nvfp4_available()` and `is_mxfp8_available()` in the matching fixture branches and skip unsupported cases.

If no CUDA device is available, these checks raise while pytest imports this file. Both helpers reach `torch.cuda.current_device()` before `pytestmark` can skip the tests, so collection fails instead of reporting skipped tests. Move the checks into the fixture, or guard them with `torch.cuda.is_available()`.

```suggestion
if torch.cuda.is_available():
    nvfp4_available, reason_for_no_nvfp4 = te.is_nvfp4_available(return_reason=True)
    mxfp8_available, reason_for_no_mxfp8 = te.is_mxfp8_available(return_reason=True)
```
