# Fix ONNX custom-op metadata and LayerNorm execution

[Upstream PR](https://github.com/NVIDIA/TransformerEngine/pull/3659) · state: closed · merged: True

## Original PR description

## Summary

Return a scalar inverse scale from the fake implementation of
`tex::fp8_cs_quantize`, matching eager execution. The previous one-element
vector metadata can fail Inductor's output checks and gives ONNX an incorrect
output shape.

Also repair the registered `tex::layernorm` operator: use
`torch.nn.functional.layer_norm` instead of the nonexistent extension
`LayerNorm` class, and make its fake return a fresh contiguous tensor instead
of aliasing the input. Current module exports use the separate
`onnx_layernorm` helper; this fixes direct use of the registered operator.

Keep the focused opcheck regressions in the existing `test_onnx_export.py`
suite, including contiguous/transposed LayerNorm inputs in FP32/FP16/BF16.

Related issue: #3636.

## Validation

- RTX Ada: 7 opcheck cases passed. The LayerNorm cases fail on the old eager
  implementation and also fail if only eager is fixed, detecting fake aliasing.
- Direct LayerNorm eager/Inductor checks passed for 9 dtype/rank combinations;
  ONNX export and ONNX Runtime output comparisons passed for 2D and 3D inputs.
- Repository pre-commit, Python lint, license and diff checks passed.

Runtime checks used prebuilt TE libraries with the updated Python exporter.
The full ONNX suite was not rerun.
