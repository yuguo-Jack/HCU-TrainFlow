# fix(sampler): save slice order as plain values and use 8 Feistel rounds

[Upstream PR](https://github.com/NVIDIA/Megatron-Energon/pull/304) · state: closed · merged: True

## Original PR description

Follow-up fixes for #280

## Changes

### Save the pending slice order as seed and offset

`DatasetSampler` used to keep `SliceIndex` in `_savable_fields`. Since it isn't `Savable`, `SavableDataset.save_state` raised a `UserWarning` on every mid-epoch checkpoint, and checkpoints were tied to the import paths and slot layouts of `SliceIndex` and `FeistelPermutation`.

The pending slice order can be rebuilt from two builtin values, which now replace `_pending_slice_index` in `_savable_fields`:

- `_pending_slices_seed`: seed of the epoch's `FeistelPermutation`, `None` if the slices are not permuted.
- `_pending_slices_offset`: number of slices of the epoch that have already been opened, `None` if no epoch is in progress.

The order is `range(num_slices)` without shuffling and `FeistelPermutation(num_slices * shuffle_over_epochs, seed)` with shuffling. With `shuffle_over_epochs == -1`, the initial slices are now drawn directly with `randbelow` like all later ones, so nothing is pending. The RNG calls are the same as before, so the order doesn't change.

This removes `SliceIndex` and the unused `WorkerRng.permutation`.

### Use 8 Feistel rounds by default

With 4 rounds, the permutation is measurably biased for small slice counts. Measured over 20,000 random seeds:

| size | rounds | max. deviation of P(position, value) | adjacent inputs stay adjacent (uniform) |
| ---: | ---: | ---: | ---: |
| 5 | 4 | 25% | 0.474 (0.400) |
| 5 | 8 | 7% | 0.422 (0.400) |
| 10 | 4 | 23% | 0.226 (0.200) |
| 10 | 8 | 5% | 0.203 (0.200) |
| 100 | 4 | within noise | 0.0271 (0.0200) |
| 100 | 8 | within noise | 0.0202 (0.0200) |

With 4 rounds and size 6, only 688 of the 720 permutations ever appear. Adjacent slices often come from the same shard, so this weakens shuffling.

### Tests and docs

- `test_max_samples_per_sequence_one_uses_compact_indexes`: both loaders are now closed via `with` (addresses the Copilot comment), and the expected order is updated for 8 rounds.
- `compatibility.md`: notes that checkpoints only store the permutation seed, so changing the Feistel permutation also breaks restoring an epoch in progress.

## Compatibility

- `CHECKPOINT BREAKING CHANGE`: `DatasetSampler` saves `_pending_slices_seed` and `_pending_slices_offset` instead of `_pending_slices_offset` and `_pending_slice_indexes`, checkpoints from before cannot be restored.
- `ITERATION ORDER BREAKING CHANGE`: the shuffled slice order changes again bc of the number of Feistel rounds.
