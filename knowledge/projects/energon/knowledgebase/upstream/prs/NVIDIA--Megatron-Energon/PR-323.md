## What does this PR do?

Fixes for #288 (streaming packing).

- Prepend streaming pushback to the carryover buffer instead of appending it. Before this fix, when a selector left older carryover unconsumed (for example a pushed-back lookahead sample), the remainder of a split sample was queued behind that carryover. The slices of that sample then came out of source order. New `SavableSampleBuffer.prepend` keeps the restore keys in sync, so save/restore keeps the order too.
- Discard pushback returned with an empty pack, as the docs already state. Before this fix, a selector that pushed back an incomplete tail at the end of the data got the same samples back on every call. It failed with `RuntimeError` once the failure tolerance was reached, or looped forever with tolerance 0. The `select_next_pack` docstring now mentions this.
- Docs: the `select_next_pack` example in `packing.md` crashed on the pushed-back `PartialSample` (`sample.tokens`). It now handles full and partial inputs and returns the incomplete last pack at the end of the data. Also removed the nonexistent `group=None` argument from the `_build_packing_postencode` call in `custom_blending.md`.
