# feat(worker): add logical workers with physical-worker fanout

[Upstream PR](https://github.com/NVIDIA/Megatron-Energon/pull/290) · state: open · merged: False

## Original PR description

## Summary

Decouples the *logical* data streams (sharding, RNG, saved state) from the number of physical
DataLoader workers executing them. With `WorkerConfig(logical_workers=L)` a run can use more
physical workers while keeping the same logical streams.

## Changes

- `WorkerConfig.logical_workers`, `LogicalWorkerAssignment`, logical/physical worker id helpers;
  sharding, worker seeds and restore keys use the logical worker id.
- `StrideDataset`: each physical worker advances its logical stream and keeps every n-th output.
- Skip mode: `@skip_safe` (or `@stateless(skip_safe=True)`) marks pure task-encoder functions
  that may be elided for outputs a physical worker discards; supported through cooking, map,
  batch, packing and streaming packing. Errors in skip-safe functions are fatal.
- Docs: *Logical Workers and Fanout* in Parallelism, skip-safe section in Task Encoder, new
  internals page.

## Compatibility

- Without `logical_workers` the logical and physical workers are identical, so existing setups
  should keep their streams. `WorkerConfig.config()` gains the `logical_workers` key.

## Review notes

- In the original branch this landed before the core refactoring; here it is re-expressed on
  top of it (e.g. `Sharder` now returns per-physical-worker ranges, including the compact
  `max_samples_per_sequence=1` path).

Found a checkpoint correctness issue in the fanout path, reproduced against head `c371e4e8248d9f38348dfb5d9d047da9a3a1fb40`. The inline comment describes the cause.

With a fixed topology (`world_size=2`, `num_workers=0`, `logical_workers=1`), rank 0 emits `0`, rank 1 emits `1`, and rank 0's uninterrupted next output is `2`. Saving rank 0 immediately after its first output and restoring into a fresh loader instead yields `1`, repeating rank 1's already-consumed output. No topology or fanout change is needed.

```text
Consumed: rank 0 = 0, rank 1 = 1
Rank 0 next: uninterrupted = 2, restored = 1
AssertionError: Fanout restore resumed at 1, expected 2; rank 1 already consumed 1.
```

Also reproduced with the PR's real packed WebDataset fixture (`world_size=4`, `num_workers=0`, `logical_workers=2`): rank 0's first restored batch equals rank 1's already-consumed first batch. The standalone repro below uses the real `SavableDataLoader` and `StrideDataset` with a deterministic counter dataset. Validation was on CPU/Python 3.12; this establishes the zero-subprocess path, rather than qualifying all multiprocessing/distributed paths.

```python
"""Reproduce PR #290's fanout checkpoint bug with the real Energon loader.

Run with Energon 8 PR #290 (c371e4e8248d) on PYTHONPATH:
    PYTHONPATH=/path/to/energon/src python repro_energon8_stride_restore.py

No files, subprocess workers, or distributed process group are required.
The topology stays fixed: two physical ranks share one logical stream.
Before the fix, rank 0 restores output 1 instead of output 2, repeating
the output already consumed by rank 1. The final assertion fails.
"""

from megatron.energon import WorkerConfig, get_savable_loader
from megatron.energon.flavors.base_dataset import SavableDataset
from megatron.energon.wrappers.stride_dataset import StrideDataset


class Numbers(SavableDataset):
    """Finite deterministic stream with its next position checkpointed."""

    _savable_fields = ("position",)

    def __init__(self, worker_config):
        super().__init__(worker_config)
        self.reset_state_own()

    def __iter__(self):
        while self.position < 20:
            value = self.position
            self.position += 1
            yield value

    def reset_state_own(self):
        self.position = 0

    def len_worker(self, worker_idx=None):
        return 20

    def worker_has_samples(self):
        return self.position < 20

    def set_skip_mode(self, active):
        pass  # Advancing this counter is equally cheap in either mode.

    def config(self):
        return {"type": type(self).__name__}


def make_loader(rank):
    config = WorkerConfig(
        rank=rank, world_size=2, num_workers=0, logical_workers=1
    )
    return get_savable_loader(
        StrideDataset(Numbers(config), worker_config=config)
    )


def main():
    # These independent rank instances model the two stride offsets. No
    # collectives are used by save_state_rank() / restore_state_rank().
    with make_loader(0) as rank0, make_loader(1) as rank1:
        iterator = iter(rank0)
        first0 = next(iterator)
        checkpoint = rank0.save_state_rank()
        first1 = next(iter(rank1))
        expected = next(iterator)

        with make_loader(0) as restored:
            restored.restore_state_rank(checkpoint)
            actual = next(iter(restored))

    print(f"Consumed: rank 0 = {first0}, rank 1 = {first1}")
    print(f"Rank 0 next: uninterrupted = {expected}, restored = {actual}")
    assert (first0, first1, expected) == (0, 1, 2)
    assert actual == expected, (
        f"Fanout restore resumed at {actual}, expected {expected}; "
        f"rank 1 already consumed {first1}."
    )


if __name__ == "__main__":
    main()
```

File: `src/megatron/energon/wrappers/stride_dataset.py` · line 82

[P1] Preserve the pending stride phase across checkpoint restoration

The inner stream has advanced through the retained output when this yield suspends, but the suffix skip on line 85 has not run yet. Since `_savable_fields` is empty, saving at this boundary retains only the inner cursor. A fresh iterator starts again with `stride_offset`, losing the pending suffix skip. For stride 2/offset 0, saving immediately after yielding 0 and restoring produces 1 instead of the uninterrupted next output 2; offset 1 has already consumed 1, so this repeats data across physical ranks. I reproduced this through `get_savable_loader` with `num_workers=0`, both on a deterministic counter and on the PR's packed WebDataset fixture, without changing topology. Please checkpoint the pending stride phase (or otherwise make the saved cursor encode equivalent continuation) and add save/fresh-loader-restore coverage for each stride offset. The review body includes a standalone repro.
