# perf(sampler): use Feistel-network permutations for slice shuffling

[Upstream PR](https://github.com/NVIDIA/Megatron-Energon/pull/280) · state: closed · merged: True

## Original PR description

## Summary

Replaces materialized index permutations in `DatasetSampler` with memory-constant,
RNG-backed permutations based on a Feistel network (`rng.FeistelPermutation`, cycle-walking for
non-power-of-two ranges). This keeps memory usage flat for very large datasets.

## Changes

- `rng.py`: `FeistelPermutation` and helpers.
- `DatasetSampler`: uses the RNG permutation for all slice modes.
- `Sharder`: compact range-based slice offsets for `max_samples_per_sequence=1`.
- `compatibility.md`: documents the permutation as part of the iteration-order surface.

## Compatibility

- `ITERATION ORDER BREAKING CHANGE`: shuffled slice order changes for a fixed seed.

## Tests

- New `test_dataset.TestDataset.test_max_samples_per_sequence_one_uses_compact_indexes`;
  expected orders in existing tests updated.

## Validation

- Full unit test suite on this layer: 141 tests passed (CPU).
- `ruff check`, `ruff format --check`, license headers: clean.
- Sphinx docs build (`-E -a`): no warnings.

- Copilot · comment · 2026-10-13T09:47:01Z · [source](https://github.com/NVIDIA/Megatron-Energon/pull/280#discussion_r4257120357)

File: `src/megatron/energon/flavors/common/dataset_sampler.py` · line None

Saving a mid-epoch state now passes a non-`Savable`, non-builtin `SliceIndex` through `SavableDataset.save_state`, so every checkpoint emits the `UserWarning` from `base_dataset.py:323-330`. Since multi-worker loaders checkpoint repeatedly, this can continuously pollute logs. Please serialize the index data as builtin state or add explicit `SliceIndex` save/restore handling (including the `None` initial state).

- Copilot · comment · 2026-10-13T09:47:01Z · [source](https://github.com/NVIDIA/Megatron-Energon/pull/280#discussion_r4257120419)

File: `tests/test_dataset.py` · line None

This test creates a persistent two-worker loader, and the restored loader below, without closing either one. The iterators are also left suspended immediately after their last requested batch, so cleanup relies on GC and can leave worker processes and `GcDataset` cleanup active when an assertion fails. Use context managers or a `finally` block to close both loaders deterministically.

- Copilot · comment · 2026-10-13T13:24:45Z · [source](https://github.com/NVIDIA/Megatron-Energon/pull/280#discussion_r4259189794)

File: `docs/source/internals/compatibility.md` · line 58

The compatibility impact is broader than the documented in-progress permutation concern: this PR replaces the saved `_pending_slice_indexes` field with `_pending_slices_seed`, while `SavableDataset.restore_state` requires every current `_savable_fields` key (`base_dataset.py:349-350`). Thus every checkpoint produced before this change fails restoration, including epoch-boundary checkpoints. The PR currently declares only an iteration-order break; either add an old-state migration/test or explicitly declare and explain the checkpoint-breaking change as required by this document's compatibility policy.
