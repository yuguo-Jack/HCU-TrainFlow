# refactor!: rename subflavors to tags

[Upstream PR](https://github.com/NVIDIA/Megatron-Energon/pull/281) · state: closed · merged: True

## Original PR description

## Summary

Renames *subflavors* to *tags* everywhere: samples (`__tags__`), cookers (`has_tags`),
dataset factories, recipe references and the task encoder.

## Changes

- New `megatron.energon.tags` module with the alias machinery (`SampleTagsAlias`,
  `HasTagsAlias`, `TagsAlias`, `resolve_tags`, `canonicalize_tag_kwargs`).
- Old names keep working: `__subflavors__`/`subflavors=`/`has_subflavors=` and the recipe key
  `subflavors:` are accepted as deprecated aliases; setting both old and new name raises.
- `typed_converter.py`: support for the field aliases when loading YAML configs.
- Docs and the data-flow image updated to the new term.

## Compatibility

- `RECIPE CONFIG BREAKING CHANGE` (soft): `subflavors` → `tags`, alias kept.
- `API BREAKING CHANGE` (soft): `__subflavors__` → `__tags__`, alias kept.

## Tests

- `test_dataset.TestDataset.test_tags_backward_compatibility`,
  `test_recipe.TestDataset.test_subflavors_recipe_alias`.

## Validation

- Full unit test suite on this layer: 143 tests passed (CPU).
- `ruff check`, `ruff format --check`, license headers: clean.
- Sphinx docs build (`-E -a`): no warnings.

File: `src/megatron/energon/recipe/loader_interface.py` · line 112

Changing this public override contract makes existing `DatasetLoaderInterface` implementations with `get_datasets(..., subflavors=...)` fail when the updated recipe code invokes them with `tags=`. The object-property alias machinery does not translate method keywords, so this is a hard extension-point break despite the PR describing the rename as soft. Add a compatibility dispatch/shim or retain the legacy method keyword at this boundary.

- Copilot · comment · 2026-10-14T09:58:46Z · [source](https://github.com/NVIDIA/Megatron-Energon/pull/281#discussion_r4269343741)

File: `src/megatron/energon/tags.py` · line None

The unconditional rewrite breaks legacy constructors on subclasses of public alias-enabled bases. For example, an existing `BaseCoreDatasetFactory` subclass whose `__init__` still explicitly accepts `subflavors` now receives `tags` instead and raises `TypeError`; the same happens even when directly called with the promised legacy keyword. Preserve the legacy keyword when the concrete initializer accepts only that spelling (and apply the same rule in the typed converter) so this remains a soft compatibility break.
