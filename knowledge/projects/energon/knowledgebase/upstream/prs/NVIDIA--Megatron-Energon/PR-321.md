## What does this PR do?

- **Remove redundant `post_initialize` overrides** (review comments): `AuxFilesystemReference` and
  `AuxByteRangeStoreReference` repeated the `AuxFileStoreReference` base implementation.
- **Reject unknown wrapped aux protocols:** a `name+backend://` aux reference with an unregistered
  `name` (a typo, or a registration module that was not imported) silently became a prepared-dataset
  reference to a bogus local path. Loading then failed with a misleading "not prepared" error, and
  `traverse_recipe` returned the wrong path. It now raises a `ValueError` naming the protocol.
- **Keep aux references given as YAML mappings working:** adding the non-dataclass
  `AuxFileStoreReference` base to the `AuxReference` union made the config parser accept any
  mapping unchanged, so e.g. `media: {fs_path: media}` was no longer converted to
  `AuxFilesystemReference` and failed later with a `TypeError`. The concrete dataclasses are now
  listed before the base class, and non-string references are rejected explicitly.
- **`ByteRangeStore`: fail on missing files for zero-length ranges:** a zero-length range returned
  `b""` without opening the file, so a wrong path went unnoticed. The file is now always opened.
