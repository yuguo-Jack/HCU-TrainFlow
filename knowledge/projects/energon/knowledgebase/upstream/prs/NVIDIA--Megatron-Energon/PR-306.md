# fix(tags): restore backward compatibility for the subflavors API

[Upstream PR](https://github.com/NVIDIA/Megatron-Energon/pull/306) · state: closed · merged: True

## Original PR description

## Summary

Restores backward compatibility for the `subflavors` → `tags` rename from #281, limited to
recipe/dataset configs and the API exported directly from `megatron.energon`.

## Changes

- All legacy names (`subflavors`, `__subflavors__`, `has_subflavors`) emit the standard
  `FutureWarning` (as required by the compatibility guidelines).
- The legacy-to-canonical alias handling is shared between the constructor metaclass and
  `typed_converter`. This also fixes the caller's `default_kwargs` being mutated while merging
  them with the config values.
- Crude samples passed to cookers also contain the legacy `"__subflavors__"` key.
- `basic_sample_keys` returns a dict that aliases `"__subflavors__"` to `"__tags__"`, so cookers
  that read or update `basic_sample_keys(...)["__subflavors__"]` before constructing the sample
  keep working. Unpacking it (`**sample_keys`) only yields the canonical keys. Previously, these
  cookers lost the tags and then failed with `Cannot set both '__tags__' and '__subflavors__'`.
- The docs only describe `tags`, not the legacy aliases.
