## What does this PR do?

Parquet random access has to decode a whole row group to return one row. Reading row by row
through `reader[i]`, as the other formats do, decoded each row group once for every row in it.
This PR makes Parquet shuffle at row-group granularity and stream rows sequentially within a
slice. It also makes the Parquet file store thread-safe and validates the columns that are read.

### Row-group shuffling
- When training, every row group is a slice. Row groups are spread across ranks and workers and
  visited in random order; the rows within a row group are read sequentially.
- With a filter index (or `serial` read order), slices are whole files.
- New `parquet_read_order` option on recipes, dataset loaders and the Parquet factories:
  - `row_group_shuffled` (default)
  - `serial`: dataset order, no shuffling, a single stream, for data that is already shuffled
- `max_samples_per_sequence` does not split Parquet slices further, because starting a slice in
  the middle of a row group would decode the rows before it.
- Warnings when training with shuffling and the slices shuffle poorly: a user-set
  `max_samples_per_sequence` has no effect, or there are fewer row groups than
  `parallel_shard_iters`.

### Streaming slices
- New optional `SequentialSampleReader` protocol with `iter_slice(start, stop)`.
- `DatasetSampler` keeps one stream per active slice next to its `SliceState` and samples between
  them as before. Streams are opened lazily at the slice's current position, so a restored
  checkpoint or restarted epoch streams the remaining rows instead of falling back to random
  access. Streams are not part of the saved state; the checkpoint format is unchanged.
- `DatasetSampler.close()` closes open streams before the reader. A retained iterator reopens its
  streams on the next read.
- Readers without `iter_slice` (tar, jsonl, binidx) are unaffected.
- `TranslatedIndexReader.iter_slice` streams the underlying range and skips filtered-out rows.

### Parquet reader and file store
- `iter_slice` reads with `iter_batches` (256 rows per batch, no threads), so rows are decoded
  incrementally and once per epoch. Memory per active slice is bounded by the batch. Each stream
  owns its file handle.
- Random access (`reader[i]`) decodes only the row's row group, located by bisection.
- `ParquetFileEntry.row_group_rows` is collected from the footers and is now required.
- `ParquetFileStore` opens a fresh Parquet file per read (`disable_cache`), like
  `WebdatasetFileStore`. The cache pool reads from file stores in a thread pool, and sharing
  cached handles across threads raised errors or crashed in pyarrow.
- Reading `"<idx>.<column>"` raises `KeyError` for a column that is not read, instead of reading
  columns excluded by the part filter.
- Building with a part filter that excludes all columns (e.g. of a cooker) raises `ValueError`
  instead of yielding samples without data.
