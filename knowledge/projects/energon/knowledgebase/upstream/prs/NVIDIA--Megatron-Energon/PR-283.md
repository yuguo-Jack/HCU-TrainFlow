# feat(flavors): add prepared filter indexes and EPath mapped arrays

[Upstream PR](https://github.com/NVIDIA/Megatron-Energon/pull/283) · state: open · merged: False

## Original PR description

## Summary

Adds *filter indexes*: precomputed sidecar files that restrict a random-access dataset to a
selected set of samples without rewriting the data. Selection is done once (offline), loading
just reads the translation table.

## Changes

- `flavors/common/filter_index.py`: `FilterIndex`, `FilterIndexWriter`, `TranslatedIndexReader`
  and the builders `build_filter_index`, `build_filter_index_from_shard_indexes`,
  `build_filter_index_from_global_indexes`. Sidecars are `filter_<name>.json/.idx` for manifest
  datasets and `<file>.<name>.json/.idx` for single-file datasets.
- `BaseIndexedDatasetFactory` applies a configured filter (`filter_name`) by translating shard
  counts and ordinals; all factories and `get_dataset_from_config` accept `filter_name`.
- Recipe references accept `filter: <name>`.
- `EPath.map(dtype=..., shape=..., offset=...)` / `epathlib/mapped_array.py`: typed 1-D arrays
  over EPath files, using `np.memmap` for local paths and seek/read for remote ones.
- Docs: new *Filter Indexes* page; internals updated.

## Tests

- New `tests/test_filter_index.py`; mapped-array tests in `tests/test_epathlib.py`.

- Copilot · comment · 2026-10-15T11:58:23Z · [source](https://github.com/NVIDIA/Megatron-Energon/pull/283#discussion_r4282658813)

File: `src/megatron/energon/flavors/base_indexed_dataset.py` · line 167

The sidecar stores dataset-wide ordinals in manifest order, but the WebDataset reader uses only `self.shards`, in selected split order. Passing the full translation table directly can read the wrong samples or raise `IndexError` for splits that omit, exclude, or reorder shards. For example, with five-sample shards A/B and only B's local index 3 retained, the table stores 8; a B-only split then passes 8 to a five-sample reader. Project the filtered table positions onto the selected shard order and rebase original ordinals into the inner reader's address space. Cover both split selection and reordered shards in regression tests.

- Copilot · comment · 2026-10-15T11:58:23Z · [source](https://github.com/NVIDIA/Megatron-Energon/pull/283#discussion_r4282658885)

File: `src/megatron/energon/flavors/base_indexed_dataset.py` · line 137

Factory length includes retained samples from every split instead of only `self.shards`. An empty `FilterIndex` is also falsy, so an all-reject filter reports the unfiltered length. These values feed worker rotation offsets and repetition-based blend weights in `task_encoder/base.py`. Check explicitly for `None` and sum the selected shards' filtered counts; test both an empty filter and a filter spanning multiple splits.

- Copilot · comment · 2026-10-15T11:58:24Z · [source](https://github.com/NVIDIA/Megatron-Energon/pull/283#discussion_r4282658936)

File: `src/megatron/energon/flavors/common/filter_index.py` · line 259

Global appends fail when no samples are retained from a leading or intermediate shard, including a leading empty shard. With shard counts `a=5, b=4`, selecting `[5]` raises `expected 'a', got 'b'`: the global lookup advances to B, but `_ensure_active_shard` still expects A. Activate skipped shards with zero filtered counts before appending the selected sample. Add regression tests for leading and intermediate gaps.
