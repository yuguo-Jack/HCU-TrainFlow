# sglang-explainer-video: read line-sense 行 as háng; poly_probe for polyphones

[Upstream PR](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/pull/112) · state: closed · merged: True

## Original PR description

## Problem

The voice sometimes reads 一行 (one line) as yì **xíng**, as in 一行人. `pron_check` can't catch it, because Whisper writes 行 for either reading.

## Measurement: new `scripts/poly_probe.py`

Each take of a line is compared (DTW over log-mel frames) with the same line where the polyphone is swapped for unambiguous homophones of each reading (航/杭 = háng, 型/形 = xíng). It judged 11/11 control words right (银行, 行业, 进行, 行为, 运行, 一行人, 统一行动, 可行 …).

- **Edge picks the reading per request.** The same sentence can flip between takes, so a single listen proves nothing; the tool synthesizes several takes and reports the misread rate.
- In 13 past videos, 31 of 74 「一行」 lines were read xíng. 「每行」 4/28, 「整行」 2/3, 「长行」 1/1.
- Five real lines × 6 takes: **13/30 wrong as written → 0/30 after this rule.** 「退回一个 CTA 一行」 was 6/6 wrong.

## Fix (`pronunciation.json` patterns; captions keep 行)

| Written | Spoken |
| --- | --- |
| 一行 / 这一行 / 每一行 / 一行的上下文 | 一航 (except after 唯一 / 统一 / 万一) |
| 一行行 | 一航航 (so 航行 never forms) |
| 每行 / 整行 / 几行 / 两行 / 多行 / 长行 / 短行 / 逐行 / 按行 / 六行 / 七万…十行 / 第 3 行 | …航 |

These keep xíng: 行为, 行动, 行驶, 行人, 行李, 行星, 行政, 行得通 / 行不通, …. 使 / 进 / 程 only block the rule when they don't start 使用 / 进行 / 程序, so 每行使用, 每行进行 and 一行程序 still get 航. `tests/test_explainer_pronounce.py` pins both lists and the caption map-back.

Left alone on purpose, because both readings are common: 这行 / 那行 (那行吧 = xíng), 此行, 同行, 单行, 上行 / 下行. The docs say to write 这一行 / 同一行 instead.
