# sglang-explainer-video: no length cap — explain every algorithm and code change

[Upstream PR](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/pull/103) · state: closed · merged: True

## Original PR description

## Why

A PR / article explainer video should make a viewer **understand every algorithm and every meaningful code change**. The skill's fixed budget (1–3 min, ≤ 3 min per film, 40–70 s for a focused PR), and pr-to-video's own story-design limits (~3 min film target, "feature 2–4 diff hunks", "implementation is the footnote") push the script toward trimming exactly the details that matter. Length should follow the material: a complex PR or a long article gets a longer film.

## What

- **`SKILL.md`**
  - New **Core principle** section:
    - **No target length.** Never cut a mechanism, code path, edge case, number or caveat to shorten the film; add frames instead. Per-frame pacing stays at one idea, ≲ 60 汉字 (~11 s).
    - **Understand before scripting.** Write `capture/understanding.md` first; it is the coverage checklist, and every item maps to at least one frame.
    - **Code is the spine.** Feature every hunk that carries logic, split long hunks, explain *why*. This explicitly overrides pr-to-video `story-design.md`'s length and hunk limits.
  - Step 2: read everything. For PRs: the full `diff.patch` (the extracted brief is budget-truncated), touched functions in full at the PR head via `gh api …?ref=<headRefOid>`, and review comments that changed the design. For articles: the whole article and the sources it depends on.
  - Step 3: check the storyboard against `understanding.md`; long films get section kickers.
  - Step 4: split a long frame rather than trimming it (the `EDGE_TTS_RATE` shortcut is removed).
  - Step 8: long films dispatch frame workers in waves (≤ 5 packets each, ≤ 3 workers at a time).
- **`references/house-style.md`**: "Completeness over brevity" replaces the per-film budget. The brief's `length` becomes an informational estimate.
- **`references/troubleshooting.md`**: the assembly warning that a film runs over the brief's expectation is expected for long material. Update `length:` instead of trimming.
- README row updated; plugin version 0.9.1 → 0.9.2.

Docs-only change. No script behaviour changes; pre-commit passes on the changed files.
