# feat(embodied): support comma-separated multi-dataset training for FastWAM

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/269) · state: open · merged: False

## Original PR description

## Change Summary

- **What changed?**
  - `--dataset-path` now accepts a **comma-separated list** of LeRobotV2 (v2.0/v2.1) dataset directories. A single path keeps the previous behaviour; multiple paths are concatenated.
  - Added `MultiLeRobotV2Dataset` (`loongforge/embodied/data/datasets/lerobot_dataset.py`): concatenates N `LeRobotV2Dataset`s, each keeping its own `task_index -> text` map. `__len__` is the total frame count, so a uniform sampler yields **frame-count-weighted sampling** across suites.
  - `build_fastwam_lerobot_dataset` (`.../fastwam/fastwam_dataset.py`) splits `--dataset-path` on commas and returns either the single dataset (unchanged path) or the multi-dataset wrapper.
  - The wrapper propagates the dataloader-injected `_transform` to every sub-dataset and aggregates per-suite `stats` via `aggregate_stats` for normalization.
- **Which issue or requirement does this address?**
  - Reproduces the official FastWAM LIBERO "4 suites joint" training setup (spatial + object + goal + 10, frame-count-weighted). Previously impossible: the comma string was treated as one directory, raising `FileNotFoundError` on `<whole-string>/meta/episodes.jsonl`.
- **Which modules are affected?**
  - `data`, `vla` (embodied data path only).

## Reviewer Notes

- **Already exercised in a real FastWAM SFT run:** the comma-separated multi-suite path has been used for actual 4-suite joint SFT training (spatial + object + goal + 10), i.e. the data/training integration is validated in practice, not just by unit-level checks.
- **Local checks done (CPU, real data):** 4 LIBERO suites load with one `LeRobotV2Dataset: root=...` log line each; `len(dataset) == 277,713 ==` sum of sub-lengths; `__getitem__` bisection returns bitwise-identical samples to the corresponding sub-dataset (incl. boundary indices); `_transform` propagates to all sub-datasets; `stats`/`meta.stats` aggregate and are non-empty; single-path / comma-path / whitespace-and-trailing-comma inputs all dispatch correctly. `ruff check` clean.
- **Backward compatibility:** the change is additive. `LeRobotV2Dataset`/`LeRobotV3Dataset` are untouched; `build_fastwam_lerobot_dataset` is only used by the `fastwam` dataset strategy, and its single-path branch calls `_build_lerobot_dataset` with the same arguments as before. Other models that use the lerobot datasets (groot, pi05, xvla, ...) are unaffected.
- **Scope / risks:**
  - Covers LeRobotV2 (v2.0/v2.1) only; v3.0 is out of scope (upstream's `MultiLeRobotV3Dataset` is separate).
  - Uses `episodes=None` (full dataset); per-root episode filtering is not supported yet.
  - Assumes sub-datasets share the same `fps` / `chunks_size` semantics (holds for the LIBERO suites).
- **Follow-up:** an optional unit test with a synthetic fixture (no real data dependency) was not added in this change.
