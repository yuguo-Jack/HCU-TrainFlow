`math.isclose(float(den), 0.0)` uses the default tolerances (`rel_tol=1e-9, abs_tol=0.0`), which reduce to `abs(den) <= 1e-9 * abs(den))`, i.e. `1 <= 1e-9` — **false for every nonzero `den`**, no matter how small (`math.isclose(1e-8, 0.0)` → `False`, even `math.isclose(1e-12, 0.0)` → `False`). This guard only ever fires on bitwise-exact `den == 0.0`.

For near-identity quaternions (`quat[3]` close to ±1 — common for small end-effector rotations in LIBERO), `den = sqrt(1 - w²)` can be small-but-nonzero (e.g. 1e-6 to 1e-8). The guard then fails to trigger and `quat[:3] * 2*acos(w) / den` divides by a near-zero denominator, amplifying floating-point error into a large/garbage axis-angle vector instead of the intended safe near-zero fallback.

Suggested fix: use an absolute tolerance, e.g. `math.isclose(float(den), 0.0, abs_tol=1e-6)` or simply `den < 1e-6`.

```suggestion
    if math.isclose(float(den), 0.0, abs_tol=1e-6):
```
