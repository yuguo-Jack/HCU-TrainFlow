# [tools] fix: keep shard filename zero-padding when loading HF safetensors

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/326) · state: closed · merged: True

## Original PR description

## Change Summary

- `_detect_shard_pattern` in `tools/mcore_checkpoint_convert/utils/ckpt_util.py` recognized shard files with any number of digits but always returned a `{:05d}-of-{:05d}` format string. As a result, `load_huggingface_checkpoint` / `merge_transformers_sharded_states` built the wrong file names for shards that are not padded to exactly 5 digits (for example `model-00001-of-000163.safetensors`) and raised `FileNotFoundError`.
- The fix uses one regex to match both supported prefixes and builds the format string from the zero-padding widths in the matched filename. Behavior for the existing 5-digit layouts does not change.
- Fixes #325
- Affected module: `tools/mcore_checkpoint_convert` (used by the adapter / vision_patch / adapter_internvl / merge_huggingface conversion scripts).

Before the fix, the 6-digit case fails with `FileNotFoundError`. After the fix, all three cases pass, and so does `tests/llm_vlm/unit/test_convert_checkpoint_config_utils.py`.
