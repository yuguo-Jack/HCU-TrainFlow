# [ci] fix: harden release publication and mask runner startup metadata

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/291) · state: closed · merged: True

## Original PR description

## Summary

Move the CI helper scripts under `.github/scripts/`, harden Docker Hub promotion verification, and protect private runner startup metadata from public GitHub Actions logs.

## Changes

### CI layout

- Move the root `ci/` helpers to `.github/scripts/` and update workflow, pre-commit, runner, hook, skill and test references.
- Keep document-link repository-root resolution working after the move.
- Share the CI test module loader used by the test suite.

### Docker Hub promotion

- Verify the published Docker Hub tag through authenticated Registry API requests instead of relying on the publisher's Docker CLI `manifest inspect` command.
- Compare the tag manifest hash with the push digest and verify the image configuration against the source image ID.
- Retry transient authentication and manifest failures up to four times with bounded timeouts. Authentication failures and digest/content mismatches remain blocking.
- Keep registry credentials in the promotion's private temporary Docker configuration. Logs omit credentials and raw registry response bodies.
- Extract the verifier to `.github/scripts/self_runner/verify_dockerhub_manifest.py`; it is streamed to the publisher over SSH stdin.
- Debug cleanup behavior is unchanged: promotion removes only the newly created destination tag and temporary credentials.

### Runner startup masking

- Add repository-level `RUNNER_PRIVATE_LOG_MASKS` references to self-hosted release and GPU regression jobs.
- Register the secret value and each of its lines before `Set up job`, so the private proxy endpoint is masked at runner initialization rather than by a later workflow step.
- Add preflight checks for release and GPU regression so a missing Secret fails before self-hosted execution starts.
- Add a sensitive-scan rule for the exact runner startup proxy message, with redacted findings and masked/loopback exceptions.
- The fork repository must configure the same Secret before its self-hosted jobs can run.
- Existing public logs retain their original content; this change does not remove historical logs.
