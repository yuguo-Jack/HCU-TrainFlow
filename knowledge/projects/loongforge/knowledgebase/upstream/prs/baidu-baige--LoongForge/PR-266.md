# [vlm, train] fix: filter MLA recompute from non-MLA components

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/266) · state: closed · merged: True

## Original PR description

## Summary

- prevent the global `mla_up_proj` selective-recompute setting from being inherited by non-MLA VLM components
- preserve `mla_up_proj` on MLA foundation models
- emit the compatibility warning through `warn_rank_0` to avoid duplicate messages from every rank

## Problem

VLM parsing copies global training arguments to the foundation model, image encoder, and image projector. When an MLA foundation enables `mla_up_proj`, non-MLA vision components inherit the same entry and fail `TransformerConfig` validation with:

```text
mla_up_proj in recompute_modules is only supported with multi_latent_attention.
```

LoongForge already filters component-incompatible `a2a_*` recompute entries in this validation path. This change follows the same inline filtering pattern for the MLA-only entry without modifying the foundation configuration.

## Validation

- `ruff==0.9.10` passed for the changed Python file
- Python 3.12 syntax checks passed
- the equivalent fix was validated in a successful multi-node 32B VLM selective-recompute training run
