# [ci,docs] ci: add PyTorch compatibility and release readiness

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/272) · state: open · merged: False

## Original PR description

## Problem

The PyTorch Ecosystem review requirements ask for governance and release documentation, demonstrable validation against recent PyTorch releases, and a pip-installable package. LoongForge previously lacked the governance documents, had no automated latest-PyTorch compatibility check, documented no PyPI installation path, and had a release version mismatch: tag `v0.2.1` was `0.2.1` while `pyproject.toml` still said `0.1.0`.

## Changes

- Adds a Linux Foundation-based `CODE_OF_CONDUCT.md`.
- Adds `GOVERNANCE.md` with maintainer ownership, decision process, release responsibilities, and a 12-month support commitment.
- Adds `.github/CODEOWNERS` pointing to the maintainer team.
- Adds release methodology, cadence, criteria, and compatibility notes to the README.
- Adds `pytorch-compatibility.yml`, which resolves the latest patch release in each of the two newest stable PyTorch series from PyPI and tests the built wheel against both versions.
- Adds version-sensitive PyTorch tests using modules with only PyTorch runtime dependencies.
- Adds English and Chinese PyPI installation guidance, including the distinction between the source wheel and the complete Docker runtime.
- Bumps the package version to `0.2.2` so the next immutable tag can be `v0.2.2`.
- Replaces the nonexistent local `CHANGELOG.md` metadata URL with the GitHub Releases page.
- Links the conduct and governance documents from the contribution and README sections.

## Validation

- `python -m pytest -q tests/test_pytorch_compatibility.py`
- `python -m ruff check tests/test_pytorch_compatibility.py`
- `actionlint .github/workflows/pytorch-compatibility.yml`
- `python -m build --sdist --wheel` followed by `python -m twine check dist/*`
- `git diff --check`
- The PR's GitHub Static Checks workflow passes.

## Follow-ups outside this PR

- Create the `baidu-baige/loongforge-maintainers` GitHub team and enable code-owner review.
- Create the `pypi-release` GitHub environment and configure the PyPI trusted publisher for `baidu-baige/LoongForge`, workflow `release.yml`.
- After merge, tag the matching immutable `v0.2.2` release and push it to trigger PyPI and Docker publishing.
- The weekly PyTorch compatibility workflow will run after the workflow is available on the default branch.
