# [vla] fix: rename VLDA checkpoint manifest from vlda_config.json to config.json

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/324) · state: closed · merged: True

## Original PR description

## Summary
- Rename the VLDA checkpoint manifest filename from `vlda_config.json` to `config.json` in `VLDAFinetuneTrainer._save_checkpoint`, `VLDAFinetuneTrainer._handle_resume`, and `VLDAModelFactory.build` so Hugging Face Hub can properly track model downloads.
- Update the LIBERO evaluation config (`cookbook/loongforge-vlda/eval/configs/libero/libero.yaml`) comment to reference `config.json`.
- Keep the manifest JSON schema, fields, and validation behavior unchanged.

## Test Plan
- Verified zero remaining references to `vlda_config.json` across the repository (`rg vlda_config`).
- Runtime verified inside the LoongForge Docker container (`loongforge:ubuntu24.04-cu12.9-torch2.8.0-py312_v0.2.0_release`):
  - `VLDAFinetuneTrainer._save_checkpoint` writes `config.json` with the full manifest schema (`model`, `data`, `resume_contract`, `dataset_fingerprint`, `norm_stats_sha256`) and does not generate `vlda_config.json`.
  - `VLDAFinetuneTrainer._handle_resume` loads `config.json`, validates `norm_stats_sha256` and `resume_contract`, and rejects checkpoints that only contain legacy `vlda_config.json`.
  - `VLDAModelFactory.build` loads `config.json`, applies `VLDADataConfig`, and preserves 11-field `VLDAModelConfig` mismatch validation.
  - `VLDAModelFactory.build` and real `VLDAPolicy` (`model.safetensors`) weight loading succeed both when `vlda_config.json` is deleted (with `config.json` present) and when no JSON config file is present at all (falling back cleanly to default `VLDADataConfig`).
