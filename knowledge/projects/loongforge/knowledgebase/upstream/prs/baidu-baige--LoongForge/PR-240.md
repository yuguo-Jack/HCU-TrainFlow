# [vla, data] fix: populate image_is_pad and sync FastWAM defaults

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/240) · state: closed · merged: True

## Original PR description

## Summary
Populate a real `image_is_pad` mask for FastWAM and sync LoongForge's FastWAM defaults with the official FastWAM recipe:

1. **`image_is_pad` (data fix):** the FastWAM pipeline never produced a real `image_is_pad` mask; the collator always emitted all-False, so episode-boundary samples (~27% at `num_frames=33`) trained the video loss on duplicated, clamped frames.
2. **Action scheduler shift (model fix):** `FastWAMModelConfig` defaulted the action flow-match scheduler to `shift=5.0`, copying the video scheduler. Official FastWAM (`configs/model/fastwam.yaml`) uses `1.0` for actions and `5.0` for video only.
3. **FastWAM-style normalization (opt-in):** `data.norm_stats_path` normalizes action/proprio with FastWAM's `LinearNormalizer` formula over its `*_dataset_stats.json` — the same file FastWAM eval uses (`data.fastwam_norm_mode`, default `min/max`, clamped to [-5, 5]). Delta action dims are zeroed on padded steps first (`data.delta_action_dim_mask`). With `norm_stats_path` unset, the default q99 path is unchanged.
4. **FastWAM LR schedule (opt-in):** `--lr-decay-style linear_warmup_cosine_annealing` reproduces FastWAM's `LinearLR` warmup (1/W -> 1) followed by `CosineAnnealingLR` to `--min-lr`. None of the existing styles match it per step, because the HF warmup schedules start from lr = 0.
5. **Config:** FastWAM eval already unnormalizes with min/max over the checkpoint's `*_dataset_stats.json`, but training defaulted to q99 over recomputed stats. `configs/models/embodied/fastwam.yaml` now documents `data.norm_stats_path` (default `null`, so behaviour and CI baselines are unchanged), and sets the LIBERO defaults for `fastwam_norm_mode` / `delta_action_dim_mask`. Enable it per run with `data.norm_stats_path=...`.

## Changes
- `data/datasets/lerobot_dataset.py`, `fastwam/transforms/fastwam_collator.py`: emit a per-sample `image_is_pad` in the multi-frame branch and stack it in the collator, falling back to all-False.
- `model/fastwam/modeling_configuration_fastwam.py`: the action scheduler now defaults to `train_shift = infer_shift = 1.0`.
- `fastwam/transforms/fastwam_transform.py`, `data_configuration_fastwam.py`: add `FastWAMLinearNormalizeTransform` and its config fields.
- `optimizer/lr_scheduler.py`, `train/training_args.py`: add the `linear_warmup_cosine_annealing` style.
- `configs/models/embodied/fastwam.yaml`: add `norm_stats_path` (null), `fastwam_norm_mode` and `delta_action_dim_mask`.
- `tests/embodied/unit/test_fastwam_parity.py`: unit tests for the normalizer, the scheduler defaults and the LR schedule.

## Test Plan
- **Unit tests:** `pytest tests/embodied/unit/test_fastwam_parity.py`: 7 passed. `ruff check` on the changed files is clean.
- **`image_is_pad` mask:** bit-identical to FastWAM's native LeRobot pad mask, with 0 mismatches over 80 samples (48 of them boundary samples) on `libero_spatial_no_noops_lerobot`.
- **End-to-end:** compared against official FastWAM (DeepSpeed ZeRO-1) on 8x A800, micro-batch 16, `libero_spatial`, 300 steps, from the same base checkpoint. With this PR (FastWAM recipe: warmup = 5% of steps, min_lr = 1% of lr) plus alignment-only settings that are kept out of this PR (deterministic numerics, DeepSpeed-order gradient reduction, per-step noise seeding, no shuffle), every rank's loss matches FastWAM bit-for-bit at every step.

## Notes
- Changing the action-shift default changes training and inference for FastWAM configs that relied on the old default. To reproduce the previous behaviour, set `model.action_scheduler.train_shift` and `model.action_scheduler.infer_shift` to `5.0` explicitly.
