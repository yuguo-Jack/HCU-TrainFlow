# fix(glm5_next): avoid dataclass default_factory fields under transformers>=5.6

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/265) · state: closed · merged: True

## Original PR description

Under transformers>=5.6 PretrainedConfig is itself a dataclass, and a subclass field declared with field(default_factory=...) is mishandled: it raises "non-default argument follows default argument" at class-definition time, and even past that the transformers constructor reports it as a missing required field. This made importing loongforge.models.foundation (which eagerly imports glm5_next) fail on the pinned transformers 5.12.1 stack.

Default vision_config and moe_layer_freq to None and materialize them in __post_init__ instead of using default_factory. Behavior is preserved: vision_config still becomes a fresh Glm5NextVisionConfig() per instance (and the dict path is kept), and moe_layer_freq is unconditionally derived from mlp_layer_types later in __post_init__ regardless of its initial value.
