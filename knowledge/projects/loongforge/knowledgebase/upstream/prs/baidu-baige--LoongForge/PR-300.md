# [vla] fix: Add Groot-N1.7 for training and evaluation on LIBERO and SimplerEnv

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/300) · state: closed · merged: True

## Original PR description

## Change Summary

What changed?

- Align GR00T-N1.7 eval with official Isaac-GR00T:
    - The Qwen3-VL backbone now always takes the last decoder layer's pre-final-RMSNorm output as `backbone_features`, on both transformers 4.x and 5.x. Before this, the extra RMSNorm corrupted the actions the policy predicted.
    - The eval image pipeline now reads `letter_box_transform` from the checkpoint's processor config instead of hard-coding it.
  - Checkpoints now save a `processor_config.json` (training `data_cfg`) next to the weights, so eval can recover the data spec from the checkpoint alone.
  - SimplerEnv: split eval into Bridge and Fractal configs and scripts. Add the Fractal (Google Robot) task configs.
  - Docs: update the LIBERO tutorial. Add a SimplerEnv training/eval README with SFT scripts, modality/stats files, and result figures.

Which issue or requirement does this address?

  - GR00T-N1.7 eval accuracy on LIBERO and SimplerEnv (Bridge & Fractal) did not match the official results.

 Which modules are affected?

  - `loongforge/embodied/model/groot_n1_7`, `loongforge/embodied/eval` (adapters, orchestrator, runners, payload builder, factory), `loongforge/embodied/distributed/checkpoint.py`, `loongforge/embodied/data/.../groot_n1_7`, `configs/.../simplerenv`, `examples/embodied/groot_n1_7`
