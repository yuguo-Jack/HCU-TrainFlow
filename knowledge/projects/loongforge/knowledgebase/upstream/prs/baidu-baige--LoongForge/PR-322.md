# [docs] fix: resolve Sphinx warnings that break the Read the Docs build

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/322) · state: closed · merged: True

## Original PR description

## Problem

The docs on loongforge.readthedocs.io have stopped updating and no longer match the repository. For example, the live
[Quick Start](https://loongforge.readthedocs.io/en/latest/embodied_tutorial/quick_start_index.html)
page still links to `quick_start_groot_n1_6.html`, but the repository renamed that file to `quick_start_gr00t_n1_6.md` some time ago.

The cause is that the RTD build keeps failing. Both `.readthedocs/en/.readthedocs.yaml` and
`.readthedocs/zh/.readthedocs.yaml` set `fail_on_warning: true`, so a single Sphinx warning fails the build and the
site stays on the last successful version. Reproducing the RTD setup locally (install `docs/requirements-docs.txt`,
then run `sphinx-build -W`) gives 9 warnings for English and 11 for Chinese. All of them are `myst.xref_missing`, from three causes:

1. The in-page TOC links at the top of `quick_start_gr00t_n1_7.md` and `quick_start_lingbot_va.md`
   (e.g. `[1. Training Setup](#1-training-setup)`) have no target, because MyST does not generate heading anchors
   by default. This affects both languages.
2. In the English `quick_start_fastwam.md`, the relative path to the LIBERO benchmark page goes up one level too many (`../eval_docs/...`).
3. The Chinese `quick_start_fastwam.md` and `quick_start_lingbot_va.md` link to the English eval docs through
   `../../source/...`. The Chinese build is rooted at `docs/source_zh` and cannot resolve files outside it,
   and `source_zh` has no `eval_docs`.

## Solution

- `docs/source/conf.py`, `docs/source_zh/conf.py`: add `myst_heading_anchors = 3` so headings at levels 1–3 get anchors and the in-page TOC links resolve.
- `docs/source/embodied_tutorial/quick_start_fastwam.md`: change the path to `eval_docs/benchmarks/libero.md`,
  matching `quick_start_lingbot_va.md` and `eval_overview.md` in the same directory.
- `docs/source_zh/embodied_tutorial/quick_start_fastwam.md`, `quick_start_lingbot_va.md`: replace the 3 cross-tree links
  with absolute GitHub URLs to the English eval docs
  (`https://github.com/baidu-baige/LoongForge/blob/master/docs/source/embodied_tutorial/eval_docs/benchmarks/{libero,robotwin}.md`),
  matching the existing GitHub links in the Chinese docs.

This only changes doc config and links. No page content changes. 5 files, +6/-4 lines.

## Result

- Running `sphinx-build -W --keep-going -E` locally with the RTD config: all 9 English and 11 Chinese warnings are gone, and both builds succeed (exit 0).
- Checked in a local preview: the in-page TOC links on the GR00T-N1.7 and LingBot-VA pages jump to the right sections; the LIBERO
  link on the English FastWAM page is now an internal link to `eval_docs/benchmarks/libero.html`; the 3 eval links on the
  Chinese pages point to the matching files on GitHub.
- Once merged, the RTD build works again and the live docs catch up with the repository, including every doc change
  that never went live, such as the `quick_start_gr00t_n1_6` rename.
