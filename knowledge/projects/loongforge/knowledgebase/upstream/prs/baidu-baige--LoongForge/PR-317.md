# [vla] fix: save aliased modules and tied tensors once in checkpoints

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/317) · state: closed · merged: True

## Original PR description

# fix(embodied): Deduplicate aliased/tied weights in checkpoints (issue [#314](https://github.com/baidu-baige/LoongForge/issues/314))

## Problem

LoongForge embodied models write the same weights multiple times under different
state-dict keys when saving DCP and safetensors checkpoints.

The root cause is that `nn.Module.state_dict()` recurses through module
registration paths without deduplicating by object identity. Embodied models
commonly register the same module or parameter under multiple names, for example:

- **PI05**: `self.model = PI05Pytorch(...)` and then `self.pi05 = self.model`
- **FastWAM**: `mot` / `dit` / `video_expert` / `action_expert` register the same components repeatedly
- **GR00T-N1.7**: `lm_head.weight == embed_tokens.weight` (tied weight)

DCP writes every key to disk. The safetensors path additionally `.clone()`s every
tensor before saving, breaking the shared-storage relationship and physically
duplicating the aliased data (`save_file` rejects tensors that share storage, so
the current code papers over this with clones).

As a result, a single save writes a large amount of duplicate data.

## Solution

Instead of modifying model structure, this PR establishes a canonical-only
serialization view at the checkpoint layer:

- **On save**: a `state_dict` post-hook drops alias keys, keeping only the
  first-registered (canonical) path.
- **On load**: a `load_state_dict` pre-hook re-adds alias keys from their
  canonical values so `strict=True` continues to hold.
- **Automatic alias discovery**: `build_alias_map()` identifies aliases by module
  identity (prefix mapping) and Parameter/buffer object identity, resolving
  chained aliases (e.g. FastWAM's `dit.mixtures.video -> mot.mixtures.video ->
  video_expert`). It merges only identical objects and never merges distinct
  views that merely share storage.
- **Backward compatible**: when resuming an old duplicated checkpoint, the extra
  alias keys are simply not requested and the pre-hook restores them. New
  canonical-only checkpoints cannot be resumed by old code — this is a schema
  upgrade, marked via `model_state_schema` in `resume_meta.json`.

The change is contained in `loongforge/embodied/distributed/checkpoint.py`:

- New `build_alias_map()` / `canonical_state_dict()` (context manager) / `MODEL_STATE_SCHEMA`
- `save_checkpoint()` installs the dedup view before saving, covering DCP / safetensors / pt
- `_resume_dcp()` builds the load template from the deduplicated key set and loads strictly

## Results

Compared baseline (before) vs new (after) on 8×A800 with local weights and data.
`model tensor bytes` is the logical tensor size; `checkpoint dir` is actual
on-disk usage (including optimizer state).

| Model | Method | Duplicate source | model keys | model tensor bytes (before → after) | safetensors file | DCP dir | pt file |
|---|---:|---|---:|---:|---:|---:|---:|
| PI05 | with weights | whole-module alias `model ↔ pi05` | 1626 → 813 | 18.71 → 9.35 GB | 18.71 → 9.35 GB (−50%) | 33.85 → 24.49 GB (−27.64%) | unchanged |
| FastWAM | with weights | `mot/dit/expert` chained alias | 6794 → 1847 | 49.57 → 13.45 GB | 49.58 → 13.45 GB (−72.87%) | 73.68 → 37.55 GB (−49.04%) | unchanged |
| GR00T-N1.7 | with weights | tied `lm_head ↔ embed_tokens` | 1031 → 1030 | 13.82 → 12.58 GB | — (non-contiguous, uses pt) | 26.79 → 25.55 GB (−4.65%) | unchanged |
| Wall-OSS-0.5 | with weights | tied `lm_head ↔ embed_tokens` | 839 → 838 | 17.94 → 16.67 GB (−7.11%) | — | — | — |
| xvla | random init | tied weight (1) | 904 → 903 | 3.73 → 3.52 GB (−5.6%) | — | — | — |
| vlda | random init | none | 1998 (0 dup) | 18.26 GB (none) | — | — | — |
| dreamzero | random init | none | 1828 (0 dup) | 50.50 GB (none) | — | — | — |
| lingbot_va | random init | none | 959 (0 dup) | 20.36 GB (none) | — | — | — |
| cosmos3 | meta init | none | 809 (0 dup) | 60.69 GB (none) | — | — | — |

Key validations:

| Check | Result |
|---|---|
| Retained canonical weights are bit-identical to before | `shared_value_mismatches = 0` for the three models |
| Optimizer state duplication | none; key count unchanged |
| New code resumes new checkpoint | passed |
| New code resumes old duplicated checkpoint | passed |
| Weight correctness for all three formats (dcp / safetensors / pt) | passed |

Note: the first three models were validated with full checkpoint writes (the
safetensors / DCP / pt columns have measured values); the remaining models were
scanned at the state-dict level (with weights / random init / meta init), so those
three columns are `—`. Alias detection depends only on model structure and
parameter/buffer object identity, not weight values, so the random-init results
are equally reliable.

Conclusion: of the 9 constructible embodied models, PI05, FastWAM, GR00T-N1.7,
Wall-OSS-0.5 and xvla have alias/tied weights (covered by this PR); vlda,
dreamzero, lingbot_va and cosmos3 have no duplication. `gr00t_n1_6` was not
scanned because the local Eagle config is missing.

Regarding `.pt`: `torch.save` already deduplicates by shared storage, so `.pt`
never physically duplicated data and its file size is essentially unchanged (this
change's value for `.pt` is a unified key schema consistent with
DCP/safetensors). The duplication in issue #314 actually occurs in **safetensors**
(clone breaks sharing) and **DCP** (writes per key).

## Testing

- New `tests/embodied/unit/test_checkpoint_alias.py`: whole-module alias, tied
  parameters, chained aliases, distinct-view exclusion, canonical state dict,
  `strict=True` load, and save/load round-trips for DCP/safetensors/pt.
- 12 unit tests pass in total (including the existing async-checkpoint cases).

## Compatibility

- Old checkpoint → new loader: compatible (backward compatible).
- New checkpoint → old loader: incompatible (schema upgrade); `resume_meta.json`
  records `model_state_schema`, and this should be called out in the release notes.
