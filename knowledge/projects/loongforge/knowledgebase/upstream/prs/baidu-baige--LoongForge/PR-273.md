# [llm] feat: support variable-length chunks in ChunkPipe

[Upstream PR](https://github.com/baidu-baige/LoongForge/pull/273) · state: closed · merged: True

## Original PR description

ChunkPipe previously assumed every chunk of a sequence had the same width: all addressing was `idx * config.chunksize`. That forces seq_length to be an exact multiple of chunksize and prevents splitting a sequence into uneven chunks (e.g. [1536, 512]), which is needed to balance the growing per-chunk attention cost across chunk-microbatches.

Chunk geometry now comes from two config fields (derived in Megatron's arguments.py): `chunk_sizes`, the per-chunk widths, and `cu_chunks`, their prefix sum. Every `idx * chunksize` start-offset becomes `cu_chunks[idx]` and every chunk-width becomes `chunk_sizes[idx]`:

- dsa_fused / multi_latent_attention: the indexer-key, kv_compressed and key_pos_emb caches keep a constant-stride slot layout (slot k starts at k * max_chunk_size) but write/read only the chunk's actual length, so a variable chunk table still maps onto fixed-size storage.
- RoPE and sparse-MLA kv offsets use the prefix sum instead of a product.
- base_gpt_model: MTP label/loss_mask truncation uses this chunk's width rather than the max width, and the pretrain normalizer uses cu_chunks[-1] (== seq_length) instead of chunksize * chunk_num_per_seq.
- The DSA indexer KL is normalized by the full sequence length so the N chunk-microbatches still sum to a sequence-level mean when chunks differ in size.
- training_utils: the P2P/activation shape hint is the largest chunk, and the microbatch inflation factor is chunk_num_per_seq instead of the seq_length / chunksize division.

Uniform mode is bit-identical: chunk_sizes[k] == chunksize and cu_chunks[k] == k * chunksize, so all rewritten expressions reduce to the previous ones.

Note: variable-length chunks require --calculate-per-token-loss. Without it, schedules.py divides each chunk's loss by that chunk's own token count, which over-weights tokens in short chunks (a [1536, 512] split inflates the gradient norm by ~15%).

Also makes BaseModelConfig.__post_init__ tolerate transformers <= 4.x, which still runs PretrainedConfig setup in __init__ rather than __post_init__.
