# feat(platforms): Add Intel GPU (XPU) support for single-GPU training

[Upstream PR](https://github.com/areal-project/AReaL/pull/1832) · state: closed · merged: True

## Original PR description

## Description

AReaL currently does not recognize Intel GPUs. It falls back to the CPU platform, logs "No supported accelerator detected", and training fails with `NotImplementedError`.

This PR adds an XPU platform using the existing platform abstraction:

- Add `XpuPlatform` with the `xpu` device type, `xccl` communication backend, and `ZE_AFFINITY_MASK` for device visibility.
- Detect XPU after CUDA, ROCm, and NPU, before falling back to CPU.
- Route device calls (e.g. `set_device`) to `torch.xpu` through the existing `Platform` fallback, and implement `synchronize` and `clear_memory`.
- Add `Platform.device_of(local_rank)` to construct devices with an explicit type, such as `xpu:0`. This avoids relying on how PyTorch resolves a bare device index.
- Add tests for platform selection, device construction, device visibility, and delegation to the correct PyTorch backend.

The existing accelerator selection priority is unchanged. This PR adds platform support; it does not modify the training algorithms.

## Additional Context

Tested on one Intel Arc Pro B70 with torch 2.13.0+xpu and transformers 5.17.0:

- Platform tests (`tests/infra/test_platforms.py`): 17 passed, 1 skipped because `torch_npu` was unavailable.
- GSM8K SFT (`examples/math/gsm8k_sft.py`) with Qwen3-0.6B completed 20 steps; loss decreased from 1.43 to 0.62.

Multi-GPU XPU execution was not validated. next PR updates existing FSDP tests that still contain CUDA-specific assumptions.
