# feat(infra): balance v1 rollout sessions across inference backends

[Upstream PR](https://github.com/areal-project/AReaL/pull/1847) · state: open · merged: False

## Original PR description

## Description

Add opt-in backend load balancing to the v1 SGLang rollout path. New sessions select the healthy backend with the lowest outstanding execution count normalized by capacity; subsequent requests keep the same backend for cache locality. DataProxy ownership is unchanged, and generation traffic goes directly to the selected backend.

Enable with `rollout.backend_routing.enabled: true` in v1 single-controller mode. The controller owns the shared router lifecycle, including train/eval sender fencing, draining, and weight-version publication. Metadata retries are idempotent; ambiguous generation failures fail the pool instead of replaying an uncertain execution. Pauses do not consume the backend-health timeout budget, and stale health responses cannot override a resumed pool.

## Performance observation

An asynchronous SWE multimodal comparison used 64 task IDs, 16 TP=4 inference replicas, fixed model weights (`lr=0`), and nine updates per arm:

| Metric | Routing off | Routing on |
| --- | ---: | ---: |
| Sum of rollout durations | 21,727.7 s | 20,400.7 s |
| Generated output tokens | 62.2066 M | 62.2109 M |
| Per-backend output-token coefficient of variation | 0.1918 | 0.0657 |

**Observed asynchronous rollout duration decreased by 6.1%.** This is one sequential OFF/ON comparison, not a guaranteed speedup: asynchronous sample consumption, trajectories, uncached prompt work, and environment latency differ. The first eight updates improved by 2.3%; the ninth contributes most of the aggregate saving. Training-time reductions are excluded from this claim.

**Synchronous rollout:** no reliable numerical estimate is claimed. A synchronous batch waits for its slowest trajectory, so the asynchronous 6.1% is not a synchronous estimate or an upper bound. The earlier synchronous run was dominated by environment timeouts and cannot establish a comparable scheduling benefit.

Experimental scheduling policies, training-engine fixes, private launch recipes, and diagnostic instrumentation are excluded.
