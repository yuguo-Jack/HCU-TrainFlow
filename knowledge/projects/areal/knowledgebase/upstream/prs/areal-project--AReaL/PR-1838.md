# fix(trainer): make on-policy distillation follow the teacher

[Upstream PR](https://github.com/areal-project/AReaL/pull/1838) · state: open · merged: False

## Original PR description

## Description

Fixes two bugs in the legacy single-teacher on-policy distillation loss (`teacher:`
config, both `engine_type: rollout` and `engine_type: train`) in `grpo_loss_fn`. The
MOPD path (`mopd:` config) is unchanged.

### 1. Joint KD+RL (`rl_loss_weight > 0`) does not use the teacher

- **Problem:** the joint branch backpropagates `log pi_theta - log pi_T`. With the
  teacher detached, the gradient is `grad log pi_theta` for every sampled token, the
  same for any teacher, and zero in expectation on student samples. This is the
  default (`rl_loss_weight: 1.0`) and is what both shipped distillation examples run.
- **Change:** `actor.py` uses the k2 estimate `0.5 * (log pi_theta - log pi_T)^2`,
  whose gradient `(log pi_theta - log pi_T) * grad log pi_theta` is the reverse-KL
  gradient on student samples. The docs (en/zh) no longer claim that the k1 term is
  gradient-equivalent to the reverse KL.
- **Effect:** tokens the teacher prefers are pushed up and the others down, in
  proportion to the log-prob gap. `rkl_loss` still logs `log pi_theta - log pi_T`.
  Runs without a teacher are unchanged.

### 2. Pure KD (`rl_loss_weight == 0`) applies an unclipped importance ratio

- **Problem:** the pure branch replaces the whole policy loss with
  `exp(log pi_theta - log pi_old) * (log pi_T - log pi_theta)`. Under decoupled PPO,
  `pi_old` is the rollout behavior policy, so staleness and inference/training
  mismatch scale the gradient without bound (a ratio of e^6 gives a ~400x push), and
  `eps_clip`, `c_clip`, `rejection_sampling` and `loss_aggregation` are ignored.
- **Change:** `actor.py` uses the per-token reward `log pi_T - log pi_theta` as the
  advantage of the existing PPO/SAPO/CISPO loss and scales it by
  `distill_loss_weight`, the same structure as the MOPD loss and verl's policy-gradient
  distillation.
- **Effect:** pure KD gets the same ratio clipping, rejection sampling and loss
  aggregation as RL. When the ratio is 1 (strictly on-policy, token mean) the gradient
  is identical to before.

## Additional Context

- Tests: the new `tests/test_distillation_loss.py` (CPU only) covers the joint gradient,
  masking, the on-policy pure-KD gradient, equivalence with the policy loss under
  `token_mean` / `seq_mean` / `prompt_mean`, ratio clipping and rejection sampling.
  `test_single_teacher_m2_filtering_preserves_loss_and_gradient_across_microbatches`
  pinned the old gradients and is updated: joint mode expects the k2 gradient, and pure
  KD now shares the RL rejection mask and PPO clipping instead of keeping stale tokens.
  Its M2-mask and cross-microbatch denominator checks are unchanged.
  On a CPU-only container (torch 2.10, Python 3.12) the new tests and the related loss
  tests (`test_mopd_loss.py`, `test_ppo_stats.py`, `test_prompt_mean_loss.py`,
  `test_functional.py`; 157 tests) pass. On `main` the new tests fail (7/8), as does the
  updated M2 test.
- Pre-commit: `ruff check`, `ruff format --check` (v0.14.9) and the SPDX header check
  pass on the changed Python files; the full hook set was not run locally. The doc
  edits are in `docs/*/algorithms/`, which mdformat excludes; the docs were not
  rebuilt.
- After this change `distill_loss_weight` takes effect in joint mode for the first
  time, so earlier joint KD+RL runs were effectively GRPO and their weight may need
  re-tuning.
- With `importance_sampling_level: sequence` (GSPO), pure KD now averages the
  distillation reward per sequence, as GSPO does for task advantages.
- Not covered: the rollout-engine teacher position alignment in #1728 / #1729.

### Reproduction on `main` (CPU)

```python
from unittest.mock import MagicMock, patch

import torch

from areal.trainer.ppo.actor import grpo_loss_fn


def grad_for(teacher, rl_loss_weight=1.0, old=None):
    logp = torch.tensor([[-2.0, -1.0]], dtype=torch.float64, requires_grad=True)
    old = logp.detach().clone() if old is None else torch.tensor([old], dtype=torch.float64)
    data = {
        "logprobs": old,
        "prox_logp": old.clone(),
        "advantages": torch.zeros_like(logp),
        "loss_mask": torch.ones_like(logp, dtype=torch.bool),
        "teacher_logp": torch.tensor([teacher], dtype=torch.float64),
        "rl_loss_weight": rl_loss_weight,
        "distill_loss_weight": 1.0,
    }
    with patch("areal.trainer.ppo.actor.stats_tracker", MagicMock()):
        loss = grpo_loss_fn(logprobs=logp, entropy=torch.zeros_like(logp),
                            input_data=data, eps_clip=0.2, eps_clip_higher=None, c_clip=None)
    loss.backward()
    return logp.grad


# Bug 1: two very different teachers give the same joint-mode gradient (0.5 per token).
print(grad_for([-0.5, -2.0]), grad_for([-9.0, -0.1]))
# Bug 2: pure KD, token 0 was sampled at log-prob -8 and is now -2 (ratio e^6):
# its gradient is about -302 instead of being clipped.
print(grad_for([-0.5, -2.0], rl_loss_weight=0.0, old=[-8.0, -1.0]))
```
