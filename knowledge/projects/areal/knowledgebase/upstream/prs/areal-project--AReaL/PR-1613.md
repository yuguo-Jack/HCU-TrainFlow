# feat(engine): add CPU-staged Megatron AdamW

[Upstream PR](https://github.com/areal-project/AReaL/pull/1613) · state: closed · merged: True

## Original PR description

## Description

Keep authoritative FP32 AdamW master parameters and moments in pinned CPU memory and stream updates through bounded reusable CUDA buffers. The staged optimizer integrates with Megatron checkpointing and AWEX colocation while preserving ordinary optimizer residency behavior.

- Select precision-aware distributed AdamW automatically when CPU staging is enabled.
- Reuse bounded CUDA slots for H2D, optimizer computation, and D2H state updates.
- Keep managed optimizer slabs CPU-resident across AWEX phase transitions and checkpoint them synchronously.
- Rebuild staged CPU masters and moments after model-only HF weight reloads.
- Preserve optimizer-chain handling for dense/expert parameter groups and mixed managed/ordinary optimizers.

Muon support is split into stacked #1743, based on this branch. Activation-storage tracking is split into independent #1779; ordinary Megatron training no longer installs its patches or mutates activation storage in this PR.

## Examples

`examples/cpu_staged_offload/` contains DAPO-Math configurations for Qwen3-30B-A3B-Base and Qwen3.5-35B-A3B-Base, sharing one training entry point. The Qwen3.5 configuration defaults to three training steps on eight GPUs with attention TP2/DP4, MoE EP8, and four TP2 rollout servers.

```bash
export AREAL_PROXY_ADMIN_API_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
# Set QWEN3_5_35B_A3B_BASE_MODEL_PATH and DAPO_MATH_17K_PATH to local directories.
python examples/cpu_staged_offload/dapo-math_rl_cpu_staged.py \
  --config examples/cpu_staged_offload/dapo-math_grpo_qwen3_5_cpu_staged.yaml \
  trial_name=staged
```

Repeat with `trial_name=baseline actor.megatron.cpu_staged_offload.enabled=false` for the baseline. Precision-aware mode stays enabled in both runs.
