# feat(trainer): add optional trajectory capture and offline replay

[Upstream PR](https://github.com/areal-project/AReaL/pull/1842) · state: open · merged: False

## Original PR description

## Description

Add opt-in training-batch capture and offline replay for single-controller SGLang RL with both AReaL v1 and v2. `trajectory_debug.mode` defaults to `off`; `dump` saves the batch consumed by training, and `replay` performs training updates without creating rollout, evaluation, proxy, or inference weight-transfer services.

`rollout` snapshots precede auxiliary scoring, while `full` snapshots retain its results before advantage computation. Versioned manifests and CPU tensors preserve logical groups and processed multimodal inputs. The same change restores training policy versions during recovery without inference and keeps replay lifecycle logging consistent with actual execution.

Usage and reproducible minimal/three-step GPU scripts are in `examples/trajectory_replay/`; the configuration and debugging guides are updated in English and Chinese.

## Additional Context

The new debug mode is disabled by default. Training-only recovery now restores the training policy version, including existing SFT/DPO/reward-model recovery callers; the inference-backed recovery path is unchanged.

Replay is a debugging tool for saved batches. Snapshots do not include model, optimizer, or RNG state and do not make stale responses equivalent to fresh on-policy RL. Replay requires matching controller version, model, training topology, batch settings, and scope, and it reads only trusted snapshots using restricted deserialization.

Validated combinations are GRPO without critic/teacher and the reference-scoring paths above. Critic/teacher integration has no dedicated GPU acceptance; v2 native checkpoint recovery, other controller modes, online agents, and inference evaluation during replay remain unsupported. Snapshot IO and CPU memory have a cost; three-step results do not establish leak freedom or long-term training quality.
