# fix: configure multimodal limits and count rejected Arena failures

[Upstream PR](https://github.com/areal-project/AReaL/pull/1874) · state: open · merged: False

## Original PR description

## Description

Arena failures rejected before trajectory export currently bypass Harness outcome metrics, understating failure rates. SGLang multimodal request limits also cannot be configured through the typed training YAML.

- Add `sglang.limit_mm_data_per_request` with validation and JSON CLI serialization. The default preserves SGLang defaults; include a commented configuration example in the Qwen3.8-27B YAML.
- Record Arena call and terminal outcomes once, before export and filtering, including rejected tasks. Zero-reward recovery does not count a failure twice.
- Publish terminal-status breakdowns and explicit call/result denominators. Keep local cancellation without a remote terminal outcome separate from Harness failures.
- Preserve reward statistics over valid exported trajectories and document the different denominators.

`harness_error` continues to mean `HARNESS_FAILED`; `task_error` covers all failed terminal statuses, including evaluation and collection failures. Both use `task_result_count`. Historical Harness rates may increase because previously omitted failures are now included.
