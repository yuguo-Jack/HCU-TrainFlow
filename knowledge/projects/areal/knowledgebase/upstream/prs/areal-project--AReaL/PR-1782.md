# feat(engine): support independently normalized named losses

[Upstream PR](https://github.com/areal-project/AReaL/pull/1782) · state: closed · merged: True

## Original PR description

## Description

Training engines currently accept one scalar loss and one normalization weight. Add a fixed-schema mapping of summed loss numerators and per-term masses, allowing objectives with different masks or units to retain independent normalization across microbatches and ranks.

Preserve the existing scalar API and reductions. Adapt FSDP, Archon, and Megatron, including native token normalization, fractional/empty masses, and transport-only ranks that must not invoke objective callbacks. Static term names allow dummy ranks to contribute the complete zero-mass schema. This PR provides the engine contract; actor loss plugins and turn/token efficiency are separate follow-ups.

Also fix Megatron evaluation metrics sharing storage with MCore callback tensors. Evaluation now uses one scalar callback in both native/manual modes and clones the normalized metric before MCore scales its callback tensor in-place. Normalizer values are validated at construction/reduction boundaries, avoiding repeated checks in the combination helper.

Risk areas: per-term DP/CP/PP scaling, Megatron native token denominators and auxiliary losses, and transport-only batches. The tests cover the existing main prompt-mean reduction bridge without changing its response scheduling.

The four supplemental tests fail before their assertions because Triton is unavailable in the test environment. They are not counted as passes.

Current-fix GPU training differential tests passed for FSDP DP2 (FP32/BF16), Archon DP2/PP2, and Megatron DP2/CP2/PP2 (native/manual). Maximum gradient/parameter-update relative L2 errors were 8.50e-7, 1.10e-6, and 0 respectively.

Actual Megatron evaluation checks cover scalar/named objectives, independent denominators, globally empty terms, different microbatch counts, CP1/CP2, and two-node dense/MoE runs with TP2/PP2/DP2 and MoE EP4. Supported eval cases match an independent full-logprob oracle (maximum absolute error 7.63e-6); native/manual metrics match exactly. Evaluation preserves parameters and does not finalize gradients; training immediately afterward updates parameters successfully. Dense transport-only ranks are also covered. The strengthened CPU regression fails on the previous eval implementation (18 cases) and passes with this fix.

The earlier two-step scalar GRPO end-to-end smoke completed with nonzero gradients, parameter changes, and weight synchronization. That full rollout smoke was not rerun for this follow-up; the current fix was validated with actual engine eval and training regressions.

### Coverage limits

- The end-to-end smoke exercises the existing scalar actor. Named losses are covered by separate engine differential tests.
- MoE bitwise comparisons require deterministic execution. Arbitrary BF16 algebraic rewrites and manual/native cross-mode calculations are not guaranteed bitwise equal; original failing comparisons were not reclassified as passes.
- MoE transport-only batches remain rejected by the existing engine guard, including evaluation. The initial validation attempt retained this failure; the follow-up explicitly verifies identical rejection on all ranks rather than claiming numerical support.
- CP2 eval passes using the default TransformerEngine FusedAttention backend. A strict deterministic attempt selected a FlashAttention path with an installed dependency API mismatch before reaching the loss callback; that path remains unverified. Oracle tolerances were not relaxed. Real MoE checks retain strict deterministic execution.
- MTP, long-run convergence, performance, and exhaustive GPU eval/critic/tree combinations remain unverified.
