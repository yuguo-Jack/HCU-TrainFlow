# fix(utils): share the Saver frequency decision across models in a step

[Upstream PR](https://github.com/areal-project/AReaL/pull/1802) · state: closed · merged: True

## Original PR description

## Description

`PPOTrainer._save_hf` calls `Saver.save` for the actor and then for the critic in the same training step. Each call ran the shared `EpochStepTimeFreqCtl.check`, so the step and epoch counters advanced twice per step, and the time window was reset by the first call. As a result, when a critic is used:

- `saver.freq_steps=2` (or `freq_epochs=2`): the critic is saved every step (or epoch) and the actor is never saved.
- `saver.freq_secs=N`: the first call resets the window, so the actor is saved and the critic is not.

This PR makes the frequency decision once per global step in `Saver` and reuses it for the other models saved in that step. Trainers that save a single model behave exactly as before, and the saved `freq_ctl` state format is unchanged.

Reproduction (`freq_steps=2`, actor + critic saved each step, 6 steps):

```
before: actor saves at steps: []               critic saves at steps: ['0', '1', '2', '3', '4', '5']
after:  actor saves at steps: ['1', '3', '5']  critic saves at steps: ['1', '3', '5']
```
