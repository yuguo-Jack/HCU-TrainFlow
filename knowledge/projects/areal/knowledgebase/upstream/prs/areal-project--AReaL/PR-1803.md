# fix(infra): keep commas and equals in local scheduler env var values

[Upstream PR](https://github.com/areal-project/AReaL/pull/1803) · state: closed · merged: True

## Original PR description

## Description

`get_env_vars()` parsed its `additional_env_vars` string with `dict(item.split("=") for item in s.split(","))`, and the local scheduler builds that string by joining `scheduling.env_vars` as `k=v,k=v`. Any value containing `,` or `=` therefore raised `ValueError` when creating local workers. Examples: `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True,max_split_size_mb:128`, or `X=a=b`.

- `get_env_vars` now also accepts a mapping, whose values are used verbatim.
- The string form splits each item on the first `=` only (backward compatible).
- `LocalScheduler` passes `scheduling.env_vars` directly instead of round-tripping through a string.
- The slurm and ray schedulers call `get_env_vars()` without arguments and are unaffected.
