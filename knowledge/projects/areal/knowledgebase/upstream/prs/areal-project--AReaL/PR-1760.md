# fix(reward): score LaTeX Geometry3K answers as whole expressions

[Upstream PR](https://github.com/areal-project/AReaL/pull/1760) · state: closed · merged: True

## Original PR description

## Description

`geometry3k_reward_fn` in `areal/reward/geometry3k.py` ran `extract_answer` on the gold answer with its last-number fallback on. About one in ten Geometry3K answers are LaTeX (in the first 100 test rows: `5 \sqrt { 3 }`, `4 \frac { 4 } { 11 }`, `\sqrt { 21 }`, `6 \sqrt { 6 }`, ...), so the gold answer became its last number (`3`, `11`, `21`). Passing the bare LaTeX to math-verify had the same effect, because its expression extractor also picks the last number.

Before (gold `5 \sqrt { 3 }`):
- `The answer is [5\sqrt{3}].` -> 0.0
- `The answer is [3].` -> 1.0

After:
- `The answer is [5\sqrt{3}].` -> 1.0
- `The answer is [3].` -> 0.0

Numeric gold answers (`48`, `7.85`) score the same as before.

This PR:
- takes only a bracketed value from the gold answer (`use_last_number=False`) and otherwise keeps the raw string;
- wraps both sides in `$...$` before `MathVerifyWorker.verify` so they are parsed as one LaTeX expression;
- adds `test_geometry3k_latex_ground_truth` to `tests/test_math_verify_reward.py`.

Note: `examples/vlm/geometry3k_grpo.py` scores with the `\boxed{}` reward in `areal/workflow/openai/geometry3k_agent.py`, so the example itself is not affected; this fixes the public `areal.reward.geometry3k_reward_fn`.
