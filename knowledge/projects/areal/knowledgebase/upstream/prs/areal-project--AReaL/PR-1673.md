# fix(trainer): prevent reward and advantage explosion on remainder group normalization

[Upstream PR](https://github.com/areal-project/AReaL/pull/1673) · state: open · merged: False

## Original PR description

## Description

In GRPO, PPO, and RLOO training with group-level reward or advantage normalization (`mean_level='group'` or `std_level='group'`), batches can have a size `bs` that is not an exact multiple of `group_size` (e.g., dynamic batching, filtered rollouts, or uneven test batches).

Previously, when `group_sizes` was `None`, `Normalization._build_group_slices` computed:
```python
return [
    slice(i * self.group_size, (i + 1) * self.group_size)
    for i in range(bs // self.group_size)
]
```
This caused two critical failure modes:
1. **Advantage / Reward Explosion on Remainder Tails**:
   Any remainder items (`rem = bs % group_size > 0`) were completely omitted from `group_slices`. As a result, `mean` and `std` remained `0.0` for those tail sequences. During normalization `x_centered / (std + eps)`, their values were divided by `eps` (e.g. `1e-5` or `1e-8`), exploding by a factor of \(10^5 \sim 10^8\) (e.g. normalizing `[1.0, 2.0, 3.0]` with `group_size=2` produced `[-1.0, 1.0, 300000.0]`), destabilizing policy updates and causing gradient explosion or NaN loss.
2. **Small Batches (`bs < group_size`)**:
   `range(bs // group_size)` evaluated to `[]`, leaving all items in the batch unnormalized and dividing the entire batch by `eps`.

This PR fixes these issues:
1. **Remainder Group Slicing**: Slices the remainder tail as `slice(bs - rem, bs)` so remainder groups are normalized within their own group.
2. **Singleton Group Stability**: For singleton groups (`group_sz == 1`), sets `group_std = 1.0` and centers to `0.0`, guaranteeing zero output without dividing by zero or exploding.
3. **Small Batch Handling**: Safely normalizes batches with `bs < group_size` instead of returning an empty slice list.
