# feat: add score centering for SGLang FSDP training

[Upstream PR](https://github.com/areal-project/AReaL/pull/1817) · state: closed · merged: True

## Original PR description

## Description

Add opt-in head/tail score centering for native SGLang rollouts and ordinary FSDP training. With sampler/trainer mismatch, uncorrected REINFORCE can collapse; this feature subtracts the estimated sampler-expected score using the sampler's top-k probabilities and a trainer-shaped tail.

The implementation computes score centering using PyTorch log-softmax/gather with checkpointed chunks. Full input logits remain live. It uses existing dependencies and SGLang’s standard response metadata.

- Collect sampler token IDs/log-probabilities through SGLang's standard top-logprob response, including interrupted generations.
- Preserve `[batch, sequence, head]` metadata through padding, batching, and next-token alignment.
- Select explicit unweighted REINFORCE plus the detached head/tail SC correction when `actor.use_score_centering=true`. SC is disabled by default; existing PPO paths remain unchanged.
- Provide a native RLVR example and fail explicitly for unsupported combinations: sampling transformations, non-FSDP backends, TP/SP greater than one, tree training, OpenAI-client transport, distillation, and incompatible policy surrogates/rejection rules.

Supported sampling is temperature 1, without top-k/top-p truncation or penalties. The sampler head size is configurable; the experiment below uses 128.

## Related Issue

Related: #1797 (existing score-centering proposal). This PR targets the native **SGLang + FSDP** path and includes numerical and learning validation. Feedback on aligning the two proposals is welcome; no issue is claimed fixed.

## Paper-style reproduction

We repeated the fixed-weight-noise Countdown setup from [Score Centering Stabilizes Off-policy Reinforcement Learning](https://arxiv.org/abs/2609.20807), using the [authors' pinned task/prompt/reward code and experiment configuration](https://github.com/martin-marek/score-centering/tree/64842967077ea105470ca73fc5d714366d3f7bdb).

**Setup:** Qwen3-0.6B, 64 prompts × 8 responses per update, 512 total tokens, temperature 1 with untruncated sampling, top-128 sampler metadata, ±1 rewards with within-prompt mean subtraction, SGD at constant LR 0.01, and 300 updates. We sample `delta = 0.02 * initial_weights * Normal(0,1)` once and reuse it: training generation uses `current_weights + delta`, while held-out evaluation uses clean current weights. Evaluation uses 64 held-out prompts × 8 responses every 20 updates.

The comparison is **REINFORCE without score centering** versus **REINFORCE + score centering**. Both use the same base policy-gradient objective. In the existing W&B run names and plot legend, `pg` means REINFORCE without score centering, and `reference` means REINFORCE + score centering. These are historical run labels; the original graph is preserved.

### Training behavior (the supplied plot)

The supplied W&B plot shows **`train_accuracy`, noise 0.02, seed 0**: the fraction correct in each training batch of 64 prompts × 8 responses, generated with the **noisy sampler weights**. It is a per-update curve, not held-out evaluation and not an average across seeds.

![Countdown training accuracy: REINFORCE without score centering versus score centering, noise 0.02, seed 0](https://raw.githubusercontent.com/ActuallyEdward/AReaL/edward/sglang-reference-score-centering/examples/math/score_centering_countdown_noise002.png)

### Separate held-out evaluation (not a summary of the plot)

The table below reports **`eval_accuracy` on 64 held-out prompts × 8 responses using clean current model weights, without injected sampler noise**. Each entry averages the three evaluations at updates **260, 280, and 300**. These numbers are not read from the training plot and are not expected to equal its final values.

For example, seed 0's SC evaluation accuracies are 59.57%, 61.13%, and 62.50%, giving a mean of **61.07%**. The REINFORCE without score centering entry of **0.00%** means zero correct responses in those three held-out evaluations; it does not claim that every training batch in the plot had exactly zero accuracy. Seed 1 and the zero-noise control are separate runs, not curves shown in the supplied image.

| Training noise scale | Seed | REINFORCE without score centering: mean held-out accuracy | REINFORCE + score centering: mean held-out accuracy |
|---|---|---|---|
| 0.02 | 0 | 0.00% | 61.07% |
| 0.02 | 1 | 0.00% | 67.71% |
| 0, control | 0 | 60.55% | 62.37% |


Together, the training curve and the separate held-out measurements support the paper’s **qualitative stability finding at noise 0.02 in two completed seeds**. They do not establish universal stability or reproduce every result in the paper. Additional seeds/noise conditions were still running at collection time. The learning runs used our integration on AReaL v2.1.0; this PR ports the same score-centering calculation to current main, with regression testing after the port. The 300-step experiments were not rerun on the rebased source.

Differences from the paper: PyTorch/FSDP and SGLang rather than JAX; Torch noise RNG; BF16 serving; independently sampled online trajectories affected by dynamic batching. A fully detached constant from the paper's surrogate is omitted, preserving gradients but changing scalar loss values. This does not reproduce its quantization, staleness, or larger-model experiments.
