# feat(engine): add distributed Muon optimizer offload

[Upstream PR](https://github.com/areal-project/AReaL/pull/1743) · state: open · merged: False

## Original PR description

## Description

Add `optimizer.type=dist_muon` on Megatron-Core 0.19.0, with native GPU state or CPU-staged state. This builds on the AdamW offload infrastructure merged in #1613 and now targets `main`.

- Use MCore's layer-wise Muon ownership and classification, with AdamW for scalar/non-matrix parameters. Pin `emerging-optimizers==0.3.0`.
- Stage FP32 master weights and momentum in pinned CPU slabs through bounded CUDA buffers. Cover dense, expert, scalar-only, all-expert and empty-owner paths.
- Support synchronous staged distributed checkpoints with DP ownership resharding at fixed model-parallel topology. Native Muon checkpointing requires fixed DP topology.
- Accept AWEX release/resume that changes allocation addresses while preserving Parameter/Storage identity, layout and size; continue rejecting replaced parameters or storage.

Merged current `main` and removed inherited AWEX/runtime changes already handled there. CI installs the new Muon dependency into an isolated directory used by both installation validation and tests; it does not resync AWEX.

## Validation

- Muon numerical/state/checkpoint unit tests, optimizer configuration, and checkpoint-manager tests: **68 passed, 2 skipped**. The two skips are existing async metric cases.
- AdamW offload/AWEX and merge regressions for R3, named losses and chunked forward: **96 passed**.
- Single-node 2/4-GPU DP/TP tests: **4 passed**. Includes native and staged Muon checkpoint save/load plus an identical next update, changed-address storage release/resume, and rejection of parameter/storage replacement.
- `pre-commit run --all-files`: passed.

Multi-node tests were not run because this machine is a single node. A staged DCP topology-change restore was not exercised in this validation run.
