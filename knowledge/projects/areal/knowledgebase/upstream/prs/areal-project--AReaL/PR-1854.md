# fix(v2): publish the weight version before resuming generation

[Upstream PR](https://github.com/areal-project/AReaL/pull/1854) · state: open · merged: False

## Original PR description

## Description

`GatewayTrainController.update_weights()` resumed generation as soon as the
weight exchange finished, while the new version only reached the data proxies
later, from `RLTrainer._update_weights_and_publish_version()`. Requests aborted
by `pause_generation()` resubmit the moment `continue_generation()` clears the
pause state, so those segments are served by the new weights but stamped with
the pre-update version by `InfBridge.agenerate()` (`inf_bridge.py:227`).

Per-token versions select the behavior policy used to interpolate the proximal
log-probabilities (`compute_prox_logp_approximations`, `actor.py:1261`), so
mislabeled segments get the wrong off-policy correction. This is the same failure
mode #1791 addressed for responses in flight across a version bump.

## Additional Context

`set_version()` broadcasts to every data proxy synchronously (`run_async_task`
awaits the gather), so all proxies see the new version before any request can
leave the pause loop. `continue_generation()` sits in a `finally` so a failed
broadcast cannot leave inference paused forever.

`RLTrainer` still calls `rollout.set_version()` afterwards: that call is still
needed by the v1 controller, whose `update_weights()` neither pauses nor resumes
generation, and is a no-op for v2.
