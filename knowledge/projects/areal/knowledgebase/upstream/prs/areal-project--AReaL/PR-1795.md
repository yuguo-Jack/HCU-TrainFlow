# fix(infra): correct multi-node vLLM DP launches in Ray scheduler

[Upstream PR](https://github.com/areal-project/AReaL/pull/1795) · state: closed · merged: True

## Original PR description

## Description

Fix multi-node vLLM rollout launches in the Ray scheduler. When DP replicas fit entirely within individual nodes, assign each node its local DP size and a disjoint starting rank through a shared DP rendezvous. Only the head node serves HTTP; secondary nodes remain headless.

Previously, these launches always passed the global node count through `nnodes`. Dense vLLM EngineCores reset their DP state during startup but retain `nnodes`, causing node-local TP/PP replicas to be incorrectly partitioned across nodes. This can fail executor initialization or incorrectly reduce the local world size.

Preserve the existing `nnodes` and `node_rank` launch path when model-parallel replicas span nodes or the allocation does not match the node-local DP layout. Single-node and SGLang launch behavior remains unchanged.

Add regression coverage for node-local DP, cross-node TP/PP, allocation guards, and single-node/SGLang compatibility. Use real vLLM configuration parsing to cover dense DP reset behavior and MoE configurations with wide EP and attention DP.
