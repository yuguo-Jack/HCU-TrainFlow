# fix(infra): drop rollout results the controller stopped waiting for

[Upstream PR](https://github.com/areal-project/AReaL/pull/1864) · state: open · merged: False

## Original PR description

## Description

When a rollout exceeds `request_timeout`, `RolloutController` pops its future,
counts a rejection and returns — but the worker is not told. The worker keeps
running the workflow, and when the rollout finishes
`BatchTaskDispatcher._fetch_loop` stores the result in `_pending_results` and
fires a callback that now resolves nothing. The entry is never removed, because
the only consumer (`get_rollout_result`) is never called for that task again. The
whole trajectory stays in the worker process until it exits.

This change tells the worker to abandon the task on timeout and on failure:

- `BatchTaskDispatcher.abandon_task(task_id)` marks the task as abandoned. The
  fetch loop drops the result when it arrives, or immediately when it is already
  pending, and runs the same shard cleanup as the rejected-trajectory path
  (`WorkflowExecutor._clear_rejected_trajectory`).
- `RemoteInfEngine.abandon_rollout_task` exposes that over the engine RPC.
- `RolloutController._create_submit_callback` calls it after dropping the future
  in both failure branches. A failed abandon RPC is logged and does not mask the
  original timeout.

`abandon_task` returns `False` for ids the dispatcher no longer tracks, so an
abandon that races a task that never started does not grow the abandoned set.

## Additional Context

Scope: this is the v1 multi-worker controller path. `RolloutControllerV2`
consumes results through `WorkflowExecutor.wait()` in-process and has no
abandoned-result path.

Tests: `tests/test_abandoned_rollout.py` covers abandoning before and after the
result arrives, the unknown-id no-op, the normal (non-abandoned) path, and the
controller RPC contract. The dispatcher tests fail without the change.

```
pytest tests/test_workflow_executor_filtering.py tests/test_staleness_manager.py \
  tests/test_async_task_runner.py tests/test_abandoned_rollout.py -q
74 passed
```

`tests/test_rollout_controller.py` cannot run in this environment (it starts a
Werkzeug callback server and binding fails with "Can't assign requested
address"); the same tests fail on unmodified `main` here.
