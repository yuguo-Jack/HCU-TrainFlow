# feat(trainer): support DTA tree training on Ascend NPU

[Upstream PR](https://github.com/areal-project/AReaL/pull/1767) · state: open · merged: False

## Original PR description

## Description

Ports the Dynamic Tree Attention (DTA) feature from `feat/dta` to the `ascend` branch, enabling DTA-based tree training on Ascend NPU hardware. DTA organizes rollout sequences that share a common prefix into a prefix tree and traverses it with DFS, so shared prefixes are computed once instead of per sequence — significantly cutting training compute and memory.

- Add DTA engine (`areal/experimental/dta/`): `DTAEngine`, token trie, tree time model, trie, DP wrapper, and data-parallel layer
- Add NPU backend for varlen attention via `torch_npu` (`npu_fusion_attention`), complementing the existing CUDA Flash Attention path
- Replace the boolean `enable_tree_training` flag with `tree_training_mode` ("sparse" | "dta" | "disabled"); the old flag is deprecated but still accepted for backward compatibility
- Integrate DTA into the RL trainer (`rl_trainer.py`) and distributed rollout (`dist_rollout.py`) with DTA-specific packing algorithm
- Add Archon engine changes (`archon_engine.py`, `archon_zero1.py`) to support DTA training flow
- Add TAU2 DTA example configs for both GPU and NPU
- Add unit tests for DTA engine, token trie, and DP layer; add Archon training test infrastructure
- Add DTA slides and test documentation

## Additional Context

`enable_tree_training` is deprecated but still supported — existing configs keep working. It maps to `tree_training_mode` internally and will be removed later.
Migration:
- `enable_tree_training: true` -> `tree_training_mode: "sparse"`
- `enable_tree_training: false` -> `tree_training_mode: "disabled"`

The new `tree_training_mode: "dta"` option is added for Dynamic Tree Attention (DTA) training.
