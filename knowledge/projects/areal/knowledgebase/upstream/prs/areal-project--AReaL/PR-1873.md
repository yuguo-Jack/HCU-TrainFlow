# fix: stabilize Arena sessions and AWEX rollout handover

[Upstream PR](https://github.com/areal-project/AReaL/pull/1873) · state: open · merged: False

## Original PR description

## Description

Qwen3.5 Arena training could lose usable timeout trajectories or fail while switching between rollout and training. Recover only model-attributed failures supported by an original Harness receipt, keep proxy session lifecycle safe under retries, and support SGLang's relocated multimodal embedding cache during AWEX cache invalidation.

The handover failure reproduced in the actual rollout image: native KV release and flush succeeded, then AReaL accessed the removed `mm_utils.embedding_cache` attribute and terminated the scheduler. Support both the legacy location and `mm_schedule.embedding_cache`, retaining image invalidation for trainable visual weights and the initial frozen checkpoint synchronization.

This branch includes the pending GDN startup fix from #1837 and is synchronized with current main. The integration preserves both default GDN protection and the independently selected CPU multimodal processor; #1837 overlaps with that bootstrap change. Companion model-specific launchers: areal-project/AReaL-RSI#59.

## Changes

- Accept native Core/runner deadlines as zero only after validating task-attempt-pinned, original structured receipts. A redacted public schema can trigger verification but cannot itself establish attribution. Retry pinned artifact 404 responses with a bounded lookup; missing/conflicting receipts and infrastructure failures remain rejected.
- Make proxy session creation idempotent under existing retries and discard failed sessions during workflow cleanup. Preserve trajectory/export checks before admitting recovered zero rewards.
- Respect `log_requests=false` in the AWEX launch path and deduplicate repeated proxy warnings.
- Clear the actual multimodal embedding cache on both supported SGLang layouts instead of crashing on the removed attribute.
