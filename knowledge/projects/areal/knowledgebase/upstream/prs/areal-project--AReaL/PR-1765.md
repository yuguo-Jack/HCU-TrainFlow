# feat(engine): add HARTS tree execution for Qwen3.5 GDN

[Upstream PR](https://github.com/areal-project/AReaL/pull/1765) · state: open · merged: False

## Original PR description

## Description

Add a Qwen3.5-35B-A3B-Base adaptation of HARTS tree execution on the Megatron Bridge path:

- Plan compact trie execution for Gated DeltaNet with differentiable boundary states and bounded replay; use ancestor-aware causal convolution and tree masks in full-attention layers.
- Map semantic labels and advantages back to compact logits while retaining the chunked LM-head loss (`enable_chunked_logits=true`, `lm_head_loss_chunk_size=1024`). Shared compact rows accumulate gradients from distinct fork labels.
- Preserve MoE auxiliary-loss and expert-bias token multiplicities, add a runnable DAPO Math config, and assign distinct AWEX transfer ranks to four TP2 SGLang servers.
- Schedule compact tree microbatches across DP replicas and synchronized slots, exchanging CPU trajectory rows while keeping PPO masks, log probabilities, and chunked-loss labels aligned.

Milestone commits keep planning, chunked loss, model integration, AWEX rank repair, nested-state correction, and benchmark documentation separately reviewable.

## Additional Context

The baseline and the new globally scheduled HARTS run each completed three steps on one eight-L20X node with Qwen3.5-35B-A3B-Base, DAPO Math, DP4/TP2/EP8, four TP2 SGLang servers, two samples per prompt, 128 maximum generated tokens, and chunked LM-head loss enabled. CPU staged offload was disabled in both arms because the installed Megatron-Core 0.17.0 does not meet this branch's staged optimizer compatibility guard.

| Metric | Baseline | HARTS |
| --- | ---: | ---: |
| Mean actor training step, post-compilation steps 2–3 | 7.81 s | 4.44 s |
| Actor input tokens per actor training second, steps 2–3 | 611 | 996 |
| End-to-end training time, three steps | 883.18 s | 899.21 s |
| AWEX weight-update time, three steps | 708.67 s | 800.57 s |
| Highest GPU-used reading at PPO-update checkpoints | 100.51 GB | 97.20 GB |

Training steps are 1.76× faster and actor input-token throughput is 1.63× higher on the two post-compilation steps. End-to-end time is 1.8% higher, while AWEX weight exchange took 91.90 seconds longer. A previous HARTS run before global scheduling measured 3.76 seconds per actor step and 936.20 seconds end to end; these separate short runs have varying rollout samples and AWEX times. Generated rewards differed, so this is an execution/performance smoke test, not a convergence claim. The memory readings are checkpoints, not all-phase peaks.

W&B: [baseline](http://8.150.1.98:8080/sct-test/wht_tree_training/runs/wht_tree_training_baseline-qwen35-20260929_train) and [HARTS with global scheduling](http://8.150.1.98:8080/sct-test/wht_tree_training/runs/wht_tree_training_harts-qwen35-global-dp-20260930_train).

Validation: 15 HARTS core/planner/mapping/convolution tests, 12 chunked/semantic LM-head tests, 3 AWEX controller tests, 46 sequence-packing tests, 3 targeted Megatron VLM tests, direct CUDA FLA gradient checks, 200 randomized trie forward/gradient checks, and a real one-step AWEX smoke, followed by both three-step runs. `mdformat --check` and Ruff passed. PR pre-commit CI passed. Local `pre-commit run --all-files` was run; its `uv-lock` hook rewrote both existing lockfiles under local uv 0.11.8 without dependency changes, so those unrelated rewrites were restored. Multi-node integration was not run because no multi-node allocation was available.

The new global scheduler passed a two-rank Gloo row-exchange check and 70 targeted CUDA tests. Its three-step GPU benchmark completed and synced to W&B. Public FLA only exports per-sequence final states, so nested forks may pack an additional state-only prefix into the same call. This preserves minimum call depth but can repeat linear-attention core work beyond the paper's selective-state kernel bound. The tested path is text-only Qwen3.5 without context parallelism.


### Long-output 20-step comparison

Both Qwen3.5-35B-A3B-Base DAPO Math runs completed 20 PPO/AWEX updates on eight L20X GPUs. Each step trained on 32 prompts x 16 samples, with rollout concurrency 32, queue 512, input limit 2048, generation limit 20480, and request limit 32767. Both retained chunked LM-head loss. SGLang was capped at 32 running requests per TP2 server to avoid the OOM seen in an uncapped attempt.

| Measure | Baseline | HARTS |
| --- | ---: | ---: |
| Mean actor step | 156.94 s | 470.92 s |
| Actor tokens/s, steps 2-20 | 30,876 | 10,263 |
| Total training time | 17,011.21 s | 23,511.31 s |
| Mean generated tokens | 9,258 | 9,240 |
| Max PPO-update checkpoint GPU memory | 123.65 GB | 133.33 GB |
| Mean compact/original tree token ratio | - | 0.989 |
| Rollout-controller timeout events | 0 | 6 |

HARTS was 38.2% slower end to end on these long outputs. Each completed update still contained 512 trajectories. HARTS requires `pad_to_maximum=true`, while the baseline used `false`, so this run does not isolate padding cost from tree execution. Both runs exited successfully and synced to W&B. The targeted CUDA test for shared-row chunked LM-head gradients passed. The [example README](https://github.com/areal-project/AReaL/blob/feature/harts-tree-training/examples/cpu_staged_offload/README.md) records the full setup and limitations.

### Follow-up: tree performance and τ³ airline stress

Three additional commits reduce HARTS tree overhead, keep proxy control RPCs responsive during large rollouts, and add a non-solo τ³-Bench airline workflow with smoke and 10-step pressure configurations. The fixed-input actor benchmark keeps the 1,024-token chunked LM-head loss enabled in both modes. Its three steady-state updates on eight L20X GPUs measured median actor steps of 8.855 s baseline and 4.579 s HARTS (1.93×); this excludes rollout and AWEX.

The separate 10-step airline runs used 32 prompts × 16 samples per step, rollout concurrency 32, queue 512, and input/generation/request caps of 2,048/20,480/32,767 tokens. From the native StatsLogger tables, excluding compilation step 1:

| Steps 2–10 | Baseline | HARTS |
| --- | ---: | ---: |
| Original actor tokens | 268.072M | 268.139M |
| Accumulated actor time | 8,127.52 s | 6,869.15 s |
| Original actor throughput | 32,983 token/s | 39,035 token/s |
| Weighted compact/original token ratio | — | 0.4351 |

HARTS throughput was 1.1835× baseline. Both runs completed 10 updates with chunked LM-head loss enabled; their native logs record 14 and 15 resampled trajectory timeouts, respectively. These were separate live rollouts and used 32,768 versus 65,536 compact-token microbatch caps, so this is an actor-throughput comparison, not a paired replay or end-to-end speedup. W&B [baseline](http://8.150.1.98:8080/sct-test/wht_tree_training/runs/tau3base20261003r3) and [HARTS](http://8.150.1.98:8080/sct-test/wht_tree_training/runs/tau3harts20261006r8) contain historical replay of numeric native-log metrics, not live logging.

Validation for these commits: 81 focused non-slow tests passed (one optional τ³ test skipped without its checkout), the three τ³ adapter tests passed with the v1.0.1 checkout on `PYTHONPATH`, and the compiled CUDA tree-convolution output/gradient test passed. Full pre-commit was run; local uv 0.11.8 regenerated both lockfiles despite no dependency change, so the unrelated lock changes were restored. All other all-file hooks and each commit's installed hooks passed. Multi-node integration remains untested because no multi-node allocation was available.
