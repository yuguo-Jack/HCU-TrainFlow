# feat(v2): add recipe-based data engineering and TIR example

[Upstream PR](https://github.com/areal-project/AReaL/pull/1780) · state: closed · merged: True

## Original PR description

## Summary

Add recipe-based data engineering to AReaL, allowing research controllers and users to generate, clean, calibrate, and select task datasets through a reusable Python execution interface.

- Define `DataRecipe` and `Calibrator` protocols with task, reference, response, and selection contracts.
- Execute bounded data jobs with validation, deduplication, exclusions, progress tracking, and provenance.
- Publish content-verified dataset snapshots and export training views to HuggingFace datasets compatible with existing AReaL loaders.
- Provide a TIR example under `examples/data_engineering/tir/` and documentation in English and Chinese.

## Design

Recipes define task-specific generation, cleaning, scoring, selection, and training-data projection. AReaL manages execution and dataset publication.

Calibration is optional and uses a Python interface. Calibrators receive public tasks and return responses or execution failures; the recipe scores responses using private references.

The TIR example generates exact-answer math tasks across eight families. Its optional calibration adapter consumes existing model/Harness evaluation reports and selects candidates based on repeated answer outcomes.

## Usage

```bash
python3 -m areal.v2.data_engineering \
  --config examples/data_engineering/tir/data_generation.yaml \
  --output /tmp/tir-data-job \
  --export-hf /tmp/tir-training-data
```

Python callers can use `await run_data_job(config, output)` directly.

This initial version runs foreground jobs. Parallel processing, checkpoint recovery, and online TIR inference integration are outside this PR.
