# fix(engine): automatically protect FlashInfer GDN decode padding

[Upstream PR](https://github.com/areal-project/AReaL/pull/1837) · state: open · merged: False

## Original PR description

## Description

SM90 FlashInfer GDN decode can let CUDA graph padding indices (`-1`) alias the last recurrent-state pool slot. Install the validated padding backport automatically when a supported Qwen GDN model actually selects FlashInfer decode.

Honor SGLang's backend precedence: `linear_attn_decode_backend` overrides `linear_attn_backend`, which defaults to **Triton** in the pinned SGLang and supported SM90 runtimes. Unset decode and explicit Triton no longer trigger the FlashInfer >=0.6.17 guard. A general FlashInfer selection still applies the patch, while a decode-specific Triton/CuteDSL selection overrides it. Unsupported `auto` values are left to native argument validation rather than interpreted as FlashInfer.

Preserve source hash guards, atomic installation, write-free repeated startup and independent opt-in CPU multimodal preprocessing. Integrate latest main and resolve the startup/test conflicts without dropping either path.

- sitabulaixizawaluduo · comment · 2026-10-30T03:09:52Z · [source](https://github.com/areal-project/AReaL/pull/1837#discussion_r4420084149)

File: `areal/engine/sglang_model_patches.py` · line None

When `--linear-attn-decode-backend` is omitted, this condition treats `None` as requiring the FlashInfer patch. However, the pinned SGLang `0.5.10.post1` defaults `linear_attn_backend` to `triton` and resolves the decode backend as `linear_attn_decode_backend or linear_attn_backend` ([defaults](https://github.com/sgl-project/sglang/blob/v0.5.10.post1/python/sglang/srt/server_args.py#L553), [resolution](https://github.com/sgl-project/sglang/blob/v0.5.10.post1/python/sglang/srt/layers/attention/linear/utils.py#L38)).

Consequently, a Qwen3.5/Qwen3-Next launch using the repository's pinned FlashInfer `0.6.7.post3` now raises `RuntimeError: FlashInfer >= 0.6.17 is required for this patch` before starting SGLang, even though its Triton decode path never invokes the affected FlashInfer kernel. Explicit `--linear-attn-backend triton` also triggers this failure because that argument is not parsed here. The base commit returns without this check for these models, so this breaks previously valid startup configurations independently of the SM90 padding bug.
