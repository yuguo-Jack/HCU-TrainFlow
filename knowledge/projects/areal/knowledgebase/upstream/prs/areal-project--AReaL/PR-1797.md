# feat: add Score Centering off-policy drift correction

[Upstream PR](https://github.com/areal-project/AReaL/pull/1797) · state: open · merged: False

## Original PR description

Add an additive drift correction for off-policy RL based on "Score Centering Stabilizes Off-policy Reinforcement Learning" (arXiv:2609.20807). The sampler's top-k head is exact; its tail is modeled as the trainer's tail rescaled to the sampler's tail mass, so the correction only needs the k head log-probs of the trainer and stays a low-variance, additive term. On-policy (p=q) the correction is exactly zero in both value and gradient.

Trainer log-probs are gathered with a chunked fp32 autograd function that bounds the log-softmax workspace to (chunk_size, vocab), so large vocabularies no longer materialize the full (N, V) softmax. The IS weight function is shared by head and tail: "none" (pure SC), "tis" (upper-clamped), and "mis" (IcePop band-mask).

Key changes:
- Add areal/utils/score_centering.py with the VeRL/Slime rho+alpha tail model, the chunked autograd gather, and the weight_fn construction.
- Thread sampler top-k log-probs end to end: request them from vLLM, parse (ids, logps), accumulate across interrupted generations, and assemble [seq, k] tensors on the trajectory.
- Split 3D [bs, seq, k] tensors during micro-batch assembly, pad log-prob keys with -inf, and cap k at sc_top_k so vLLM v1's 1+N entries cannot inflate q_mass.
- Inject trainer logits in the FSDP engine (truncated inside the pad_length guard) and add the masked correction to grpo_loss_fn.
- Validate the SC config, fail fast under Ulysses SP and concat multi-turn, and regenerate the CLI reference.

## Description

Adds Score Centering (SC), an additive drift correction for off-policy RL
([arXiv:2609.20807](https://arxiv.org/abs/2609.20807)). The sampler's top-k head
is exact; its tail is modeled as the trainer's tail rescaled to the sampler's
tail mass, so the correction only needs the k head log-probs of the trainer. On
policy (`p == q`) it is an exact no-op — value and gradient are zero; off policy
it is a low-variance additive term.

The implementation follows the VeRL/Slime reference (`rho`/`alpha` tail model)
and is ported onto `ascend`'s native `/inference/v1/generate` vLLM backend.
Trainer log-probs are gathered with a chunked fp32 autograd function that bounds
the log-softmax workspace to `(chunk_size, vocab)` instead of `(N, vocab)`.
`sc_mode` selects the IS weights: `none` (pure SC), `tis` (clamped), and `mis`
(IcePop band-mask).

Key changes:

- New `areal/utils/score_centering.py` with the rho+alpha model, chunked
  autograd gather, shared `weight_fn`, and `-inf` top-k padding helpers.
- Sampler top-k log-probs threaded end to end: config → vLLM request/parse →
  remote-inference accumulation → OpenAI proxy client/types → `[bs, seq, k]`
  micro-batch assembly → FSDP logits injection → masked correction in
  `grpo_loss_fn`.
- Fix `q_mass` inflation: pad log-prob keys with `-inf`, and cap `k` at
  `sc_top_k` so vLLM v1's `1+N` entries cannot inflate it to `2.0`.
- Truncate logits inside the `pad_length` guard (fixes `logits[:-0]`) and inject
  them only when SC is enabled.
- Regenerate the CLI reference.

### Validation

Environment: Python 3.11.15 | torch 2.10.0+cpu | torch_npu 2.10.0.post2 |
vLLM 0.23.0 / vllm-ascend 0.23.0rc2.dev107+geaefc536d | transformers 5.5.4 |
Ascend910 ×3 | branch `feature/score-centering` @ `eaaa3634`.

```text
python -m pytest tests/test_score_centering.py \
  tests/test_rlvr_topk_assembly.py \
  tests/test_vllm_generation_request.py               -> 60 passed
python -m pytest tests/test_functional.py tests/test_mopd_loss.py \
  tests/test_ppo_stats.py tests/test_ppo_actor_controller.py \
  tests/test_rlvr_reward_logging.py                   -> 54 passed
```

Unit tests cover the numerics: on-policy correction and gradient are exactly
`0.0`; `q_mass = 1.0` for `k == vocab`; `tis` matches an independent
rho+alpha+clamp reference element-wise (`atol=1e-12`); `mis`, `-inf` padding,
the `sc_top_k` cap, and the Ulysses-SP guard all pass.

End-to-end GRPO smoke, Ascend910 ×3, `sc_top_k=128`, `sc_mode=none`, 2 steps:

| Step | `sc_correction/avg` | `sc_q_mass/avg` | `sc_s_bar/avg` | `rollout/reward` |
|------|---------------------|-----------------|----------------|------------------|
| 1 | 1.0748e+04 | 9.9490e-01 | -8.9794e+00 | 7.1667e-01 |
| 2 | 1.5578e+04 | 9.9560e-01 | -8.7987e+00 | 6.9167e-01 |

SC stats are present and finite, `sc_q_mass/avg ≈ 0.995`, no shape/gather errors,
run completes. Baseline (`use_score_centering=false`, `sc_top_k=0`) produces no
SC metrics and comparable reward.

Not tested: CUDA path and multi-node runs; SC under Ulysses SP (`sp_size > 1`)
and `concat` multi-turn are rejected by design.
