# feat: support recovery across v2 trainers

[Upstream PR](https://github.com/areal-project/AReaL/pull/1783) · state: open · merged: False

## Original PR description

## Description

Add checkpoint recovery for AReaL v2 PPO (actor and critic), SFT, DPO, and reward-model trainers, following the v1 single-controller lifecycle. Restore training state from the latest published checkpoint when the driver is invoked again. Synchronize recovered actor weights and versions with inference workers before generation resumes, and support colocated AWEX recovery. Add focused unit tests and update the English and Chinese checkpointing documentation.

- pyq623 · comment · 2026-10-16T03:56:03Z · [source](https://github.com/areal-project/AReaL/pull/1783#discussion_r4290774936)

File: `docs/en/reference/checkpointing.md` · line None

Could we clarify how the V2 driver is restarted after a recovery failure?

From tracing the standard entry points, examples/math/gsm8k_rl.py constructs the trainer once, and areal train run calls the driver once (training/commands/run.py:54). A recovery exception propagates after cleanup, while the existing recover.retries loops belong to the legacy SPMD launchers. I also checked current main (b2f2f56f),  where these entry points likewise do not include a driver restart loop.

Would it make sense to consider one of the following options?

1. Document that automatic restart requires an external supervisor, and clarify the corresponding comment in recover.py.
2. Provide a V2-compatible restart entry point, with a test covering an initial recovery failure followed by a successful retry.

If there is an existing V2 restart mechanism that I missed, could you point me to it?

- sitabulaixizawaluduo · comment · 2026-10-16T06:27:41Z · [source](https://github.com/areal-project/AReaL/pull/1783#discussion_r4291556686)

The description here is ambiguous, and I will modify it in the subsequent commit. In fact, the recovery in v2 cannot rely on `recover.retries` for retries; this aligns with v1's single controller. I believe this capability can be developed as an independent feature.
