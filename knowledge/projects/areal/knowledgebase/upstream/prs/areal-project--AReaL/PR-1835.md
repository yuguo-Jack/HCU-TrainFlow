# fix(engine): make trainer-rollout colocation work end to end

[Upstream PR](https://github.com/areal-project/AReaL/pull/1835) · state: open · merged: False

## Original PR description

> **Merge after PR1** (`fix(engine): restore aiter MoE weight layout after online weight updates`).
> Both PRs edit `VLLMWorkerExtension.areal_update_weights`; once PR1 is in `main` I will rebase this
> PR (see "Merge order" below).

## Description

Colocation runs the trainer and the rollout engine on the same GPUs and offloads one while the
other works. It failed in five places, on FSDP and Megatron, with both SGLang and vLLM rollouts.
This PR fixes all five. Separation mode, where trainer and rollout use different GPUs, is not
affected.

| Component | Failure | Fix |
|---|---|---|
| FSDP, Megatron | Colocated trainers offload before rollout init and again in the initial offload policy. The second `torch_memory_saver` pause calls `exit(1)`. | `offload()` and `onload()` return early when already in that state. |
| FSDP | RPC payloads are broadcast into device memory, but paused memory cannot back new allocations while the engine is offloaded. | Broadcast over a gloo mirror of the model-parallel group while offloaded. |
| vLLM | The rollout controller adds `base_gpu_id`, `nccl_port` and `_awex_gpus_per_server` for every colocated backend. vLLM rejects them and exits 2 with `unrecognized arguments`. | Drop them before building the server command; apply the placement through `VLLM_PORT` and device visibility. |
| vLLM | A disk weight update runs while the rollout sleeps. Writing into the unmapped weight pool raises `CUDA error: invalid argument`. | Wake only the weight pool, load, then offload it again. The KV cache stays released. |
| SGLang | A disk weight update writes into released weights, and non-AWEX colocation resumes the weights pool without a CPU backup, so rollouts sample from uninitialized memory. | Onload the weights around the disk update, and enable `enable_weights_cpu_backup` for non-AWEX colocation. |

### Why not just use AWEX colocation

AReaL has two colocation paths, side by side in `rl_trainer.py`:

| | Generic colocation (this PR) | v1 AWEX colocation |
|---|---|---|
| Enabled by | rollout `scheduling_strategy: {type: colocation, target: actor}` (or the reverse) | `weight_update_mode: awex` |
| GPU switch | `_should_offload_rollout`: torch_memory_saver offload/onload of each side | the AWEX adapter, by tag |
| Weight update | disk or xccl | AWEX writes device memory directly |
| Engines | any rollout/train backend | SGLang + Megatron |
| Examples / tests | none | `examples/math/gsm8k_grpo_awex_colocate.yaml` and the AWEX tests |

Both are public configuration, and AWEX mode explicitly turns the generic path off rather than
replacing it. So FSDP users and vLLM users who want colocation can only use the generic path.
That path has no example and no end-to-end test, and parts of it assume SGLang: for example,
`RolloutController` passes `nccl_port` to every colocated backend under a comment saying "SGLang
needs a separately reserved third port", and vLLM exits on that argument. The other `type:
colocation` entries in `examples/` and `tests/grpo/config.yaml` are under `ref:`, so they colocate
the reference model with the actor and do not exercise rollout offload.

### Merge order

This PR and PR1 both edit `areal_update_weights` in `areal/engine/vllm_ext/vllm_worker_extension.py`.
PR1 uses `model_runner.reload_weights(...)` when a MoE layer runs the aiter backend and keeps
`model_loader.load_weights(...)` otherwise. This PR wraps that body in a wake, try and re-offload
block. The two changes are independent, so the resolution keeps this PR's outer block and PR1's
gated body inside it:

```python
resleep = restore_offloaded_weights(self)
try:
    try:
        if self._areal_needs_layerwise_reload():
            with (
                torch.device(self.model_runner.device),
                set_current_vllm_config(self.model_runner.vllm_config),
            ):
                self.model_runner.reload_weights(weights_path=model_path)
        else:
            self.model_runner.model_config.model = model_path
            model_loader = get_model_loader(self.model_runner.vllm_config.load_config)
            logger.info("Reloading weights inplace...")
            with set_current_vllm_config(self.model_runner.vllm_config):
                model_loader.load_weights(
                    self.model_runner.model,
                    model_config=self.model_runner.model_config,
                )
        self.sync()
        return True, "Success"
    except Exception as e:
        ...
finally:
    if resleep:
        offload_weights_tag(self)
```

PR1's `reload_weights` also copies its result back into the original storage, so it needs the
weight pool mapped exactly as the old loader did. The FADA runs below used the earlier ungated PR1,
whose aiter branch is the same code as the `reload_weights` branch above.

## Additional Context

### Validation

Two rounds on 8 × MI308X (gfx942), ROCm 7.15, base image `rocm/primus:v26.5`, built from
`Dockerfile.rocm` (PR2). Both rounds used weight-update mode `disk` for the colocation cases.

- **Round 1**: `main` + PR1 + PR2, without this PR.
- **Round 2**: `main` + PR1 + PR2 + PR3 + PR4.

The smoke cases run 3 steps at lr=0. They check that the rollout's weights after the sync are
bit-identical to the trainer's, and that a checkpoint save, load and resume really happened. The
accuracy cases train Qwen2.5-Math-7B for 20 steps. Their gate is the mean train-vs-rollout logprob
difference on the same weights, which must stay below 0.2.

| Case (colocation) | Round 1, without this PR | Round 2, with this PR |
|---|---|---|
| vLLM + FSDP2, smoke | fails: all 8 vLLM servers exit 2 on `--base-gpu-id ---awex-gpus-per-server --nccl-port`; 0 of 3 steps | passes: 3/3 steps, bit-exact sync, resume verified, logprob diff 0.021 |
| SGLang + Megatron, smoke | fails: all 8 Megatron workers exit at the second `torch_memory_saver` pause; 0 of 3 steps | passes: 3/3 steps, bit-exact sync, resume verified, logprob diff 0.055 |
| vLLM + FSDP2, accuracy | not run (smoke failed) | passes: 20/20 steps, logprob diff 0.0096 |
| SGLang + Megatron, accuracy | not run (smoke failed) | passes: 20/20 steps, logprob diff 0.019 |

The four separation-mode cases and the 30B stability case behave the same in both rounds.

**What the comparison does and does not show.** Round 1 stops each case at its first failure, so it
directly demonstrates two of the five bugs: the vLLM argument exit and the double pause. The other
three sit behind them. Logs from round 2 show the disk-update wake running on both backends: vLLM's
weight pool wake and re-offload, and SGLang's `tags=['weights']` onload and offload. They carry no
direct trace of the gloo broadcast or of `enable_weights_cpu_backup`. Both were diagnosed in an
earlier porting run on AReaL `3b936798`:

- without the gloo mirror, every FSDP rank failed in `broadcast_object_list` with
  `CUDA error: invalid argument` right after the actor offload. A CPU probe validated the mirror;
- without the CPU backup, SGLang resumed a wiped weight pool after the first release. The
  train-vs-rollout logprob difference was about 2.7 and entropy about 8.9, while the weight-sync
  digest still matched. A release/resume probe gave garbage without the backup and identical output
  with it. Round 2
also included PR4, so this PR was not isolated from it; none of these colocation cases uses an FSDP
MoE model, which is the only place PR4 changes behaviour.

### What this does and does not cover

- Not covered yet: CUDA. The failures sit in platform-independent code, so they are expected on
  CUDA too, but only ROCm was tested:
  - the vLLM `unrecognized arguments` exit is pure command-line building;
  - the double `torch_memory_saver` pause, the write into vLLM's slept weight pool and SGLang's
    missing CPU backup follow from how those libraries behave on every platform;
  - the RPC broadcast into paused memory raised a HIP error, and I have not checked whether CUDA
    fails the same way.
- AWEX colocation is out of scope; it keeps its own paths.
