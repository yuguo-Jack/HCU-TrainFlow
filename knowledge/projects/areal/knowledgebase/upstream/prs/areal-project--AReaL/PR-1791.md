# fix(v2): pin generation versions before awaiting responses

[Upstream PR](https://github.com/areal-project/AReaL/pull/1791) · state: closed · merged: True

## Original PR description

## Description

`InfBridge.agenerate` reads the current weight version after awaiting the backend response. If `set_version()` runs while that request is in flight, its tokens are labelled with the updated version instead of the version at dispatch.

Capture the version before each HTTP request and use it for that segment's `output_versions`. An aborted request keeps its original version, while its resubmission captures the updated version. This applies the same approach already used by `RemoteInfEngine` in #1569 to the v2 bridge.

The regression covers both SGLang and vLLM, with and without abort/resubmit. On the original code, the interrupted case reports `[11, 11, 12]` instead of `[10, 10, 11]`; it passes with this change.
