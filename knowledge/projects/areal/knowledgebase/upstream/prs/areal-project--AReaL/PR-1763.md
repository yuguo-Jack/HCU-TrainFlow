# fix(dataset): keep Geometry3K SFT image_grid_thw two-dimensional

[Upstream PR](https://github.com/areal-project/AReaL/pull/1763) · state: closed · merged: True

## Original PR description

## Description

`get_geometry3k_sft_dataset` stores `processed_input["image_grid_thw"].squeeze(0)`, which turns the processor's `[num_images, 3]` grid into a flat `[3]` vector. Every consumer expects one row per image: `FSDPEngine` and the Megatron `extract_vision_from_multi_modal` `torch.cat` the per-sample grids along dim 0, and the Qwen-VL vision tower indexes `grid_thw[:, i]`. With the squeezed grid, Geometry3K SFT on a Qwen-VL model fails in the vision forward (and a batch of several samples would be concatenated into one flat vector). The CLEVR SFT loader and `VisionRLVRWorkflow` already store the grid unchanged.

Reproduction with a tiny randomly initialized `Qwen2VisionTransformerPretrainedModel` (no download):
- `grid_thw=[[1, 2, 2]]` (as the CLEVR loader stores it): OK, output `(4, 16)`
- `grid_thw=[1, 2, 2]` (as the Geometry3K loader stores it): `TypeError: iteration over a 0-d tensor`

This stores the grid as the processor returns it.
