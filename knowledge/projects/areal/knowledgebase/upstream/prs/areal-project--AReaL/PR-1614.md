# feat(v2): support AWEX colocation and async checkpoint recovery

[Upstream PR](https://github.com/areal-project/AReaL/pull/1614) · state: open · merged: False

## Original PR description

## Description

Enable v2 Megatron/SGLang AWEX colocation on the shared adapters introduced in #1684. Actor and rollout workers can share GPUs while retaining separate training and inference parallel layouts.

The controller coordinates rollout pause/drain, inference memory release, auxiliary-model scoring, training, checkpointing, and weight publication. Rollout memory is released before reference-model scoring, and generation resumes only after the updated weights and policy version are committed. CUDA IPC exports remain alive until receiver acknowledgement.

Support synchronous and asynchronous DCP recovery through the existing checkpoint generation and `LATEST` protocol. Asynchronous saves publish `LATEST` only after finalization. Before shutdown, v2 controllers drain pending saves on every training rank before destroying workers or their parent rollout guards. Drain failures propagate instead of proceeding with cleanup. This lifecycle applies to both colocated and separated v2 Megatron training.

## Related Issue

Builds on #1684 (shared AWEX adapters and converters).

## Additional Context

Validation:

- CPU regression suite after test consolidation: **489 passed, 45 skipped**, including **10 `LATEST` pointer tests**.
- Real-CUDA IPC lifetime tests: **6 passed**, covering acknowledgements, failures, timeouts, repeated publication, and teardown protection.
- **Colocated, two GPUs:** Qwen3-0.6B, actor DP2, rollout TP2, reference scoring, KL=0.01. Both synchronous and asynchronous DCP runs completed 20 training steps, restarted through `LATEST`, and completed steps 21–22.
- **Separated, four GPUs:** Qwen3-0.6B, actor on one GPU, reference model on one GPU, rollout TP2 on the other two. With KL=0.01 and asynchronous DCP enabled, the run completed the same 20-step/restart/2-step sequence.
- Each async run finalized four checkpoints. The final save was still pending at training completion and was drained before worker cleanup. Restart restored model, optimizer, LR scheduler, and RNG state. Both async jobs exited successfully; all 22 steps reported successful optimizer steps and finite, nonzero gradient norms. Learning rate was zero on the first warmup step and nonzero thereafter.
- Tested with PyTorch 2.9.1+cu129, SGLang 0.5.10.post1, Megatron-Core 0.19.0, the Megatron-Bridge 0.6.0 wheel pinned in `uv.lock`, AWEX 0.9.0, and torch-memory-saver 0.0.9.
- Full pre-commit checks and English/Chinese documentation builds passed.

Scope and validation limits:

- AWEX colocation supports full-weight Megatron training and SGLang inference. Ray v2 guard colocation, LoRA colocation, and other training/inference backends are outside this PR's supported scope.
- GPU end-to-end tests used a single node and the local scheduler. Slurm guard placement has CPU regression coverage; no new multi-node GPU run was performed. Auxiliary guard colocation onto a partial-node actor allocation remains restricted; the four-GPU test used a dedicated reference GPU.
- Pointer tests cover atomic selection, ignoring unpublished generations, invalid-pointer rejection, and publication failure propagation. The GPU runs exercised normal shutdown and restart, **not mid-write SIGKILL or ENOSPC fault injection**.
- The subsequent LoRA preflight, incomplete drain-probe, and concurrent session-initialization, and initialization/teardown lifecycle fixes passed CPU regression tests; the GPU end-to-end runs preceded these boundary fixes.
- Both v1 and v2 reject incompatible rollout allocator settings without rewriting them. Configure `expandable_segments:False` (or omit the option) in both allocator environment names for rollout; actor settings remain independent. Startup rejection and example configuration parsing passed CPU checks; no new GPU run was performed for this policy change.
- These short-generation GSM8K runs validate the execution and recovery lifecycle, not learning quality or performance improvements.
- Based on main commit `3b93679888e9f4929f6f155f13c6a286a62dfd72`, verified as the upstream tip when publishing.
