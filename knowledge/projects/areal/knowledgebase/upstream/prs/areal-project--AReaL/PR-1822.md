# fix(engine): correct FSDP TP forward layout and Qwen3 norm gradients

[Upstream PR](https://github.com/areal-project/AReaL/pull/1822) · state: closed · merged: True

## Original PR description

## Description

Fix two tensor-parallel correctness problems in the FSDP model parallelization plan:

1. **Forward pass:** Hugging Face causal-LM wrappers slice hidden states between the final normalization and `lm_head`. A sequence-sharded DTensor can fail at that boundary with `aten.alias.default` on the tested Torch/Transformers stack. Gather the sequence and return a local tensor at the final normalization output, then configure the vocabulary-sharded output head to accept replicated inputs. Normalization still computes on sequence shards.
2. **Qwen3 Q/K gradients:** Query/key normalization receives `[batch, sequence, local_heads, head_dim]`. Its previous replicated-input declaration loses contributions to shared normalization-weight gradients. Use `SequenceParallel(sequence_dim=2, use_local_output=True)` to describe the head partition correctly.

No dependencies or configuration options are added. The changes are independent of score centering.

## Related work

PR #1365 previously proposed a fix for the same final-normalization/LM-head dispatch problem reported in #1366. This PR explicitly overlaps with that proposal: both gather and localize the normalization output before wrapper slicing. Here the transition is expressed through the existing `ReplicateParallel` style instead of an extra forward hook, and is submitted together with the distinct Q/K gradient fix and regression tests. It does not depend on #1365 being merged.

The Q/K correction also follows up on the normalization wrapping introduced in #335. This PR leaves critic `score` handling unchanged; #1365 additionally adjusts that path.

## Validation

```bash
python -m pytest tests/test_fsdp_tp.py -q
pre-commit run --all-files
```

Three CPU/Gloo TP=2 regression cases compare against unsharded models:

- A small normalization/projection model selects global token positions before the output head and checks outputs and all parameter gradients.
- A randomly initialized Qwen3 model runs through its backbone and projection directly, isolating Q/K gradient reduction from wrapper slicing.
- The same Qwen3 model runs through the full causal-LM wrapper, exercising both fixes together.

Both Qwen3 cases check vocabulary-sharded outputs, every parameter gradient, and every parameter after an Adam update. All three fail on unmodified upstream `main` at `f31bd36` and pass with the combined patch. The full pre-commit suite passes.

Validation uses Torch 2.9.1 and Transformers 5.3, CPU/Gloo, eager attention, and an untied small Qwen3 model without model downloads. The boundary change applies to models with an `lm_head` in this parallelization path; real-model test coverage is Qwen3. These tests do not establish GPU/BF16, combined FSDP sharding, CP, multi-node, or other-model coverage. There are no learning-curve or performance claims.
