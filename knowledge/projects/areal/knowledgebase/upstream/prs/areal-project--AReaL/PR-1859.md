# fix(engine): preserve NPU graph storage during weight updates

[Upstream PR](https://github.com/areal-project/AReaL/pull/1859) · state: closed · merged: True

## Original PR description

## Description

Fix Ascend MoE XCCL weight updates that could replace storage referenced by captured NPU graphs or allow data-parallel dummy forwards through partially reloaded weights. Keep generation paused across all buckets, use native layerwise reload for the target and MTP draft, and finalize once before resuming generation. Preserve shared weights and runtime-only routing tensors, rebuild derived weights, and reject changes to captured tensor storage or repeated finalization after failure.

### Captured graph storage

Ascend MoE checkpoint weights and inference weights use different layouts. The previous XCCL path manually reversed the MoE layout and ran whole-model postprocessing for each bucket. An assignment such as `parameter.data = parameter.data.transpose(1, 2).contiguous()` can allocate new storage. Updating the Python parameter does not retarget memory addresses already captured by an NPU graph.

```text
Before update:       Python weight -> address A, value 1
                     Captured graph -> address A, value 1
Unsafe replacement:  Python weight -> address B, value 2
                     Captured graph -> address A, stale or invalid contents
Required result:     Python weight -> address A, value 2
                     Captured graph -> address A, value 2
```

Use vLLM's native layerwise reload machinery for the supported Ascend MoE path, retain references to the original runtime storage, and validate each tracked parameter and buffer after finalization. Address, shape, stride, dtype, and device must remain unchanged. A mismatch raises before generation resumes. The example illustrates the storage hazard; it is not a claim that every replacement necessarily produces NaNs.

### One transaction across all buckets

A bucket boundary is not a complete model update. For example, bucket 1 may contain a layer's gate/up projection while bucket 2 contains its down projection. Previously, each bucket endpoint paused and resumed generation and postprocessed the model. Internal data-parallel dummy forwards triggered by repeated pauses can encounter unfinished reload state, including temporary meta tensors when using native reload.

```text
Pause once
  -> load gate/up projection bucket
  -> load down projection bucket
  -> load all remaining buckets
  -> finalize native reload once
  -> verify captured storage and synchronize
Resume generation
```

The continue-generation endpoint now invokes worker finalization before resuming. If finalization raises, generation stays paused. A transaction whose finalization has started cannot retry finalization because that operation mutates native loader state.

### Coordinated target and MTP loading

The target model and MTP draft use their own checkpoint loaders within the same native reload transaction. For example, if both models share an output head, an incoming head weight handled by the target loader is skipped for that same shared tensor in the draft loader, avoiding duplicate loading and processing. A checkpoint alias handled only by the draft loader is still loaded.

- When the actor exports MTP-specific weights, those weights update the draft.
- When it exports no MTP-specific weights, the frozen MTP-specific layers retain their values; shared target/draft weights still follow target updates.
- Runtime-only Ascend routing tensors remain live, while derived tensors such as the packed convolution weight are rebuilt through native reload processing.
- Independent speculative draft models retain their own checkpoint and are not included as MTP drafts.
