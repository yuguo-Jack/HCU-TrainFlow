# feat(engine): add isolated MTP training with checkpoint preservation

[Upstream PR](https://github.com/areal-project/AReaL/pull/1870) · state: closed · merged: True

## Original PR description

## Description

This PR backports the MTP training work from upstream [7823be6d70abd7347d8affd52b88cc7ef698baef](https://github.com/areal-project/AReaL/commit/7823be6d70abd7347d8affd52b88cc7ef698baef) to the `ascend` branch, adapted for the NPU Megatron-Bridge and xccl paths.

Enable Megatron MTP training with an independent auxiliary objective while preserving complete HF checkpoints when MTP training is disabled. Frozen MTP tensors are captured from the checkpoint actually loaded, so saving after a resume preserves that checkpoint's head.

- Add `megatron.enable_mtp_training` and `mtp_loss_scaling_factor` (default `0.1`) with packed-sequence and context-parallel normalization, VPP metadata propagation, and `mtp_loss` reporting.
- Isolate auxiliary gradients from policy parameters while retaining the existing shared global gradient clipping.
- Preserve frozen MTP weights and configuration during HF export, rebuild shard metadata from safetensors headers, and propagate rank-zero checkpoint errors to peers.
- Require Megatron-Bridge and one prediction layer for MTP training; reject LoRA, critic, tree-attention, and AWEX training combinations. Trained-MTP xccl updates require `use_bridge_for_update_weights: true`.
- Update example configs and English/Chinese CLI references, and add MTP loss and vLLM drafter-loader coverage to Ascend CI.

This change targets the Ascend/NPU Megatron path. MTP and policy gradients share global clipping, so the auxiliary loss can still affect the policy's clipping scale.
