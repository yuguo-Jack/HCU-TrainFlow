# feat(tools): add reproducible FSDP train-step benchmark

[Upstream PR](https://github.com/areal-project/AReaL/pull/1824) · state: closed · merged: True

## Original PR description

## Description

Add a standalone, reproducible benchmark for AReaL's actual FSDP training step. The tool keeps a fixed synthetic SFT workload and model revision, then runs each `max_tokens_per_mb` / gradient-checkpointing candidate in a fresh `torchrun` process. It reports valid-token throughput, loss-token throughput, latency samples, per-rank memory, prepared versus executed microbatch counts, provenance, and failures in JSON and Markdown.

The worker calls `FSDPEngine.train_batch()` with AReaL's packed SFT loss, so the measured interval includes microbatch preparation, packing, forward/backward, gradient clipping, and optimizer update. Inputs are staged before timing; data construction, model loading, checkpoint I/O, and stats export are excluded. Non-finite gradient updates fail the trial instead of being counted as successful steps. A Linux subreaper isolates torchrun workers, including detached worker sessions, during timeout and signal cleanup.

The contribution is a measurement foundation for the future Autopilot roadmap. It does not automatically mutate user configs or claim a universal optimum. The first version is deliberately limited to single-node Linux CUDA, dense Qwen2/Qwen3/Llama text models, FSDP data parallelism, and packed FlashAttention 2.

- CUDA integration suite: **2 passed** (single GPU: four combinations; two GPUs: one smoke configuration), using `NCCL_P2P_DISABLE=1 NCCL_IB_DISABLE=1` for this host. - CPU process tests exercise real `torchrun` timeout cleanup for detached workers and SIGINT/SIGTERM interruption reporting while preserving unrelated processes.

## Scope and limitations

- The implementation does not benchmark multi-node, TP/CP/PP/EP, MoE, VLM, CPU, or rollout/inference backends.
- GPU results were collected on shared A100 devices and demonstrate functionality; they should not be treated as a stable performance ranking.
- Output directories nested inside a local model directory are explicitly rejected so generated artifacts cannot change the checkpoint manifest.

## Additional Context

The four real-checkpoint trials use `Qwen/Qwen2.5-0.5B` revision `060db6499f32faf8b98477b0a26969ef7d8b9987`, a global batch of four 256-token sequences (1,024 input / 1,020 loss tokens per step), BF16 compute, FP32 master parameters/AdamW state, token budgets 256/512, and gradient checkpointing off/on. All 20 measured updates completed successfully. This is functional validation on shared GPUs, not a claim of stable speedups or RL convergence.

Reproduce the integration checks with:

```bash
python -m pytest tests/test_fsdp_benchmark.py -q
# Host-specific NCCL transport overrides were used for the two-GPU validation.
CUDA_VISIBLE_DEVICES=0,1 NCCL_P2P_DISABLE=1 NCCL_IB_DISABLE=1 \
  OMP_NUM_THREADS=1 TOKENIZERS_PARALLELISM=false \
  python -m pytest tests/test_fsdp_benchmark_cuda.py -q
```
