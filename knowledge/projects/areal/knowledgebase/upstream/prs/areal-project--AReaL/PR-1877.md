# fix(reward): preserve Geometry3K units and validate completions

[Upstream PR](https://github.com/areal-project/AReaL/pull/1877) · state: open · merged: False

## Original PR description

## Description

Preserve correct Geometry3K answers with ordinary unit suffixes and prevent structured completion objects from receiving credit through their Python representation.

The full-expression verification merged in #1868 turns plain unit letters into LaTeX variables: `\boxed{5 centimeters}`, `\boxed{5 in}`, and `[90 cm^2]` receive zero against gold `5`, `5`, and `90`. Separately, `str(completions)` escapes backslashes in container representations; a dict or tuple containing `\boxed{2\sqrt{3}}` can then incorrectly match gold `3` through the legacy number fallback.

- Remove only recognized, separated trailing geometry-unit annotations, with a quantity boundary so an algebraic operand such as the `in` in `5 + in` is retained. Keep full-expression verification; no unrestricted raw-text retry or unit conversion is introduced.
- Document that completions are decoded strings and return zero for non-string inputs. Built-in RLVR, vision RLVR, and multi-turn callers decode to strings; the async reward wrapper preserves arguments.
- Clarify that the gold scanner validates empty/unfinished boxes without selecting their contents. Valid gold boxes remain for grouping-preserving normalization. Returning the extracted box would incorrectly turn gold `5 + \boxed{2}` into `2`.
- Add explicit regressions for the review examples and document test-module responsibilities. The existing delimiter behavior is retained and tested, including `[$\sqrt{4}$]` and display-math forms.

Only `areal/reward/geometry3k.py` and four reward test files change. The shared verifier and other dataset/example scorers are unchanged.

## Validation and scope

```bash
python -m pytest tests/test_geometry3k_reward.py tests/test_geometry3k_reward_extended.py tests/test_geometry3k_reward_units.py tests/test_math_verify_reward.py -q
```

- **579 tests pass on both draft branches** with `math-verify==0.8.0`: the original 274 cases, 278 unit cases, and 27 additional review regressions.
- The new review cases cover complete boxed gold, boxes inside gold sums/fractions, dollar/display delimiters on both sides, literal escaped backslashes, and list/dict/tuple completions. Before the input guard, the dict and tuple cases incorrectly earned full credit for gold `3` when containing `\boxed{2\sqrt{3}}`; the new guard rejects them. Boxed-gold and delimiter cases passed before the clarification and remain covered.
- Unit coverage includes the three reported false negatives, 26 spellings/formats on integers, fractions, radicals, powers and pi expressions, and controls against partial-number matches or removing algebraic operands. This is bounded format coverage, not an exhaustive guarantee for model outputs.
- The preceding dataset sweep passed all 3,002 extraction checks and 18,010/18,012 reward probes on both branches. The two existing external-verifier failures concern changed angle labels in congruence statements. The latest update only rejects non-string completions and clarifies existing string behavior; the full 579-test suite was rerun.
- All changed-file hooks pass. Full-tree pre-commit still fails in unrelated environment-dependent hooks (missing `tomllib`/`mdformat` in their interpreters and inaccessible lockfile cache); project consistency passes separately under a supported interpreter.
- Reward tests ran on CPU. NPU training and distributed integration were not run.

The public library reward is the affected API. The documented Ascend VLM training example and Geometry3K E2E select `examples.vlm.geometry3k_grpo.geometry3k_reward_fn`, which uses a separate `mathruler` scorer and is unchanged. That separate implementation can still differ in answer extraction.

Test responsibilities are now stated in module docstrings: focused extraction/grading/input contracts, generated/equivalence/malformed cases, unit compatibility, and legacy shared-verifier integration. Ascend's existing CPU test selector discovers all four modules automatically; no CI workflow change is needed.
