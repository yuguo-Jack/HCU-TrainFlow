# fix: enable Qwen3.5 VLM chunked loss and prefill graph control

[Upstream PR](https://github.com/areal-project/AReaL/pull/1821) · state: closed · merged: True

## Original PR description

## Description

Allow Qwen3.5 image batches on the Megatron Bridge model-owned THD path to use the existing chunked LM Head loss. The wrapper retains visual fusion, mRoPE and CP packing before returning hidden states, so rejecting all vision inputs prevented a supported path from running.

Also expose optional `SGLangConfig.disable_prefill_cuda_graph`. This lets callers keep decode CUDA graphs and memory saver enabled while disabling incompatible breakable prefill graphs. The default is `None`, preserving command generation for older SGLang runtimes.

Add regression coverage for admission, the installed Bridge wrapper's visual gradients and CP layout, and phase-specific CLI flags. Regenerate English and Chinese CLI references. No loss kernels or scheduler behavior change.

## Related Issue

No linked issue; fixes configurations encountered while validating the Qwen3.5 Arena launcher.

## Additional Context

Megatron expert review found no correctness issue in the guard change. The wrapper/head tests cover image fusion and local CP1/CP4 token ordering with tiny float32 modules; they do not cover video, BF16, full attention/GDN, or DP/EP collectives. The production loss implementation is unchanged. Other multimodal paths keep their existing admission checks. The new SGLang flag requires a runtime supporting `--disable-prefill-cuda-graph` only when explicitly enabled.
