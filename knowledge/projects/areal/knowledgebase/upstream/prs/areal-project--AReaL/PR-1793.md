# fix(infra): quote Slurm container environment values

[Upstream PR](https://github.com/areal-project/AReaL/pull/1793) · state: closed · merged: True

## Original PR description

## Description

Quote each `SchedulingSpec.env_vars` assignment with `shlex.quote()` when generating Slurm Apptainer commands. This keeps the complete `KEY=VALUE` in one `--env` argument when the batch script is parsed by the outer shell.

### Affected scenarios

- JSON configuration containing spaces, quotes, and commas.
- Paths containing spaces, such as `/models/model cache`.
- Text containing single/double quotes, newlines, or literal shell metacharacters.
- Empty values.

Previously, these values could be split into multiple arguments or lose quote characters. Real Apptainer tests reproduce whitespace/JSON values being misinterpreted as the image path, failing before container execution. Ordinary numeric/plain-text values retain their behavior.

### Compatibility boundary

- Only Slurm's `container_type="apptainer"` command-generation path changes.
- No HTTP/OSS implementation, configuration fields, or dependencies are included.
- Native Slurm, Ray, and LocalScheduler are unchanged.
- Callers should provide raw, resolved values rather than prequoted shell fragments. Configurations relying on implicit outer-shell variable expansion, command substitution, globbing, or tilde expansion should resolve those expressions before constructing `env_vars`.
- Apptainer's own environment evaluation is unchanged. This does not add `--no-eval` or guarantee literal preservation of arbitrary expressions inside the container.

## Related Issue

No linked issue; independently reproduced with generated shell commands and a real Apptainer container.
