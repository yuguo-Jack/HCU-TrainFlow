# fix(engine): align Qwen VLM image preprocessing across engines

[Upstream PR](https://github.com/areal-project/AReaL/pull/1825) · state: closed · merged: True

## Original PR description

## Description

Text-only packed Qwen microbatches can carry modality token types without visual grids or deepstack embeddings. Keep both pre-pack and CP-local visual masks absent in this case, while preserving masks for real images and videos. This prevents text-only requests from failing during deepstack/CP/SP processing.

Native SGLang image resizing can diverge from the image inputs reconstructed for Megatron training. Align both paths with the native resize and processor rules, preserve visual text token types, and compact multimodal tensors before transport. When selected on the SGLang server, the AReaL processor integration and CPU image decoding fix can be installed without a separately patched SGLang distribution.

For supported Qwen VLMs, `AREAL_VLM_ALIGN_SGLANG` defaults to `true`: the OpenAI proxy follows SGLang image preprocessing for training inputs while forwarding the original image bytes. `SGLANG_VLM_QWEN_LIMIT_PIXEL` independently defaults to `true` and reduces the eligible maximum pixel budget by 16; set it to `false` for the full budget, with the same value in the SGLang server and proxy environments. Set `AREAL_VLM_ALIGN_SGLANG=false` only to use the proxy's original HF preprocessing; it does not change SGLang. Separately, `SGLANG_EXTERNAL_MM_PROCESSOR_PACKAGE=areal.engine.sglang_processors` opts the SGLang server into the validated AReaL processor and CPU/PIL path. Without this server opt-in, startup leaves SGLang's Qwen3-VL/Qwen3.5 sources and any third-party processor unchanged. The docs describe the validated SGLang runtime and how to prepatch a read-only image.
