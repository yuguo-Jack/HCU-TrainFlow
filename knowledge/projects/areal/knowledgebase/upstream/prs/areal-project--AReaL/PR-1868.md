# fix(reward): preserve boxed Geometry3K answer expressions

[Upstream PR](https://github.com/areal-project/AReaL/pull/1868) · state: closed · merged: True

## Original PR description

## Description

Geometry3K prompts require a final answer in `\boxed{...}`, but the library reward function previously selected the last square-bracketed value or numeric token. This truncated correct expressions and could give full credit to an incorrect answer whose last number matched the gold.

| Completion | Gold | Before | After |
| --- | --- | --- | --- |
| `\boxed{5\sqrt{3}}` | `5\sqrt{3}` | 0 | 1 |
| `\boxed{2\sqrt{3}}` | `3` | 1 | 0 |
| `\boxed{\frac{1}{11}}` | `11` | 1 | 0 |

The change is confined to `areal/reward/geometry3k.py` and regression tests:

- Scan balanced braces to select the last outer boxed answer, preserving nested fractions, roots, powers, and escaped braces. Earlier reasoning, bracketed references, and trailing numbers cannot override it.
- Return an empty extraction for an empty or unfinished final box, including one containing a completed inner box. Preserve the existing bracket/number fallback when no box is present.
- Preserve complete gold expressions while removing only outer answer/math wrappers. A cube-root index such as `[3]` is no longer mistaken for the gold answer.
- Remove remaining nested `\boxed` formatting while retaining its grouping braces before verification, so the verifier compares the whole selected expression rather than an inner box.

These rules operate on delimiters and expression boundaries rather than special-casing the three reported values. This addresses the same truncation failure for brace-balanced fractions, radicals, powers, sums, and their nested combinations. The shared verifier, its configuration, and other dataset/example scorers are unchanged.

python -m pytest tests/test_geometry3k_reward.py tests/test_geometry3k_reward_extended.py tests/test_math_verify_reward.py -q

- 274 tests passed on current upstream `main`, including 225 Geometry3K cases. Coverage includes 1,000 generated expression trees in four contexts, with both complete and truncated boxes (8,000 extraction assertions), plus brace depths up to 1,024.
