# fix(v2): forward frequency_penalty and stop in vLLM bridge requests

[Upstream PR](https://github.com/areal-project/AReaL/pull/1762) · state: closed · merged: True

## Original PR description

## Description

`VLLMBridgeBackend.build_generation_request` (v2 inference service) builds its vLLM payload without `gconfig.frequency_penalty` and `gconfig.stop`. The sibling `SGLangBridgeBackend` and the v1 `VLLMBackend` both forward them (the v1 backend was fixed for the same omission in #1429), and vLLM's `/v1/completions` and `/v1/chat/completions` endpoints accept both fields. So with the v2 inference service on vLLM, a configured repetition penalty and stop strings are silently ignored, and the same config samples differently depending on the backend.

This adds `frequency_penalty` to the payload, and `stop` when it is set, matching the v1 vLLM backend.
