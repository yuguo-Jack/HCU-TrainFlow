# fix(engine): keep text packing kwargs out of Qwen-VL vision tower

[Upstream PR](https://github.com/areal-project/AReaL/pull/1851) · state: open · merged: False

## Original PR description

## Description

**Bug:** Packed training of Qwen-VL models fails on transformers >= 5.16. Newer transformers pass the model's extra arguments on to the vision encoder, so the text sequence-packing settings reach it as well and clash with its own (`got multiple values for keyword argument 'max_length_q'`). Separately, `test_vlm_consistency` has been broken since <old PR that merged prev 1206>, because its mock data lacks `mm_token_type_ids`.

**Fix:**

- Strip the text packing settings before they reach the Qwen-VL vision encoder, which computes its own. No effect on transformers versions that don't pass them on (e.g. 5.3).
- Update the test: add `mm_token_type_ids`, use a realistic `[prompt][images][answer]` layout, and compare answer-token log-probs instead of raw logits. The raw-logit check fails on bf16 rounding even when packing is correct, and passed before only with a hand-picked seed. The new check still catches real packing bugs:

| Case | mean \|Δlogp\| |
| --- | --- |
| Correct packing | <= 0.06 |
| Bug: one packed sample attends to the previous one | 0.50-0.63 |
| Bug: 1D instead of 3D positions for images | 0.16-0.20 |
