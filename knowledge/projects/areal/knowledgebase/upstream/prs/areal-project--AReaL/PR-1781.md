# feat(trainer): add logical trajectory mean loss aggregation

[Upstream PR](https://github.com/areal-project/AReaL/pull/1781) · state: open · merged: False

## Original PR description

## Description

A logical rollout can export several training rows, for example after context compaction. Averaging per-row losses gives that rollout extra weight. Add `actor.loss_aggregation=traj_mean` to average token means over logical rollouts, pooling the original valid tokens across all rows belonging to each rollout.

Use existing `RolloutGroup.row_counts` metadata for membership and share the prepared unit reduction with `prompt_mean`. The collector already annotates a single rollout exported as several rows; unannotated rows each count as one rollout. Custom workflows exporting several logical rollouts in one result must provide their boundaries.

This preserves response-level optimizer scheduling, packing, and engine interfaces. With `R` globally active rollouts and `K` actual optimizer steps, each step uses the fixed denominator `R/K`. At fixed parameters and masks, the mean of step losses and gradients recovers the full-batch trajectory mean. Later loss filtering changes the numerator while retaining each rollout's original token denominator. Empty rollouts are excluded; globally empty updates are rejected on all ranks. With one row per rollout and one optimizer step, this matches `seq_mean`; multiple steps retain full-update weights rather than independently renormalizing each step.

PPO, SAPO, and CISPO use the same reduction. The default remains `token_mean`, and the existing restrictions on non-token aggregation with tree training and distillation apply.

## Attribution

The trajectory-mean idea and reciprocal full-rollout token coefficients are inspired by Lindsey Xing (@lxing532) in [HwVanICI/AReaL, commit 3daf1524](https://github.com/HwVanICI/AReaL/commit/3daf152462d8b6427278884a55d2d0d16b02fb6e), which builds on #1546. Thank you for the implementation and motivating this addition.

This implements that objective through upstream's existing prepared loss abstraction and canonical logical-rollout metadata. It uses response-level scheduling with coefficients spanning optimizer steps; the fork's marker-based membership and atomic trajectory scheduling are not copied. The source is also credited in the preparation docstring, both language docs, and the commit message.
