# fix(engine): restore FSDP learning-rate scheduler state

[Upstream PR](https://github.com/areal-project/AReaL/pull/1801) · state: closed · merged: True

## Original PR description

## Description

FSDP checkpoint recovery restores the optimizer's learning rate but leaves the scheduler at step zero. The first resumed update can match uninterrupted training, while subsequent updates restart warmup or decay. For example, saving after 80 scheduler steps and loading into a fresh engine restores `last_epoch` as 0.

Save `lr_scheduler.pt` with optimizer-bearing checkpoints and restore it after the optimizer for both DCP and HF formats. Rank 0 writes the metadata before the existing synchronous checkpoint operation, so no additional barrier or DCP schema change is needed. Model-only operations leave the scheduler untouched.

Older checkpoints without the metadata remain loadable with an explicit warning; their missing scheduler progress cannot be recovered exactly. A present but corrupt file raises an error. English and Chinese documentation explain this compatibility boundary and the requirement to retain the scheduler configuration and total training steps.
