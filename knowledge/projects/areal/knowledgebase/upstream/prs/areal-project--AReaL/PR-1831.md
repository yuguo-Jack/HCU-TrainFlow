# feat(trainer): support actor-sourced rollout initialization on Ascend

[Upstream PR](https://github.com/areal-project/AReaL/pull/1831) · state: closed · merged: True

## Original PR description

## Description

Currently, the actor and rollout engines independently load their initial weights from checkpoint, reading the model weights twice during startup. The rollout engine already receives subsequent weights through the actor's weight-update path, but cannot use that path for initialization.

This PR adds optional actor-sourced rollout initialization for Ascend. With this option enabled, only the actor loads the initial checkpoint weights; vLLM starts with dummy weights and receives the actor's weights through the existing weight-update path before the first rollout. This avoids the rollout engine's separate checkpoint weight read while preserving the current behavior by default.

### Configuration

Add `rollout.initial_weight_source` with two choices:

- `checkpoint` (default): actor and rollout load independently, without an initial actor-to-rollout synchronization.
- `actor`: start rollout with dummy weights and synchronize from the actor before the first rollout.

For example:

```yaml
rollout:
  initial_weight_source: actor

actor:
  weight_update_mode: xccl
```

Actor-sourced initialization requires a non-disk weight-update mode and rejects LoRA, since adapter-only updates cannot initialize the dummy base model. The initial synchronization preserves the actor's weight version and is skipped when recovering an existing run.

This change targets full-model vLLM initialization with the v1 single-controller path.
