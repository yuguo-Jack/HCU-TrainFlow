# feat: distinguish consumed rollout and retained training metrics

[Upstream PR](https://github.com/areal-project/AReaL/pull/1796) · state: open · merged: False

## Original PR description

## Description

Asynchronous rollout metrics can include unused prefetch, while turn statistics derived only from retained training rows omit rejected episodes. Align quality metrics with task consumption and expose two distinct turn populations:

- `rollout/num_turns/{avg,min,max}` and `_count`: one observation per consumed logical episode before filtering, including rejected episodes and discarded groups. Count generated responses from raw session history, including retry branches later discarded by export. Report unavailable counts separately as `rollout/num_turns_missing_count`.
- `train/num_turns/{avg,min,max}` and `_count`: original generation history of each retained training row after selection/filtering. Preserve row metadata through serialization, slicing, and token cropping. Individual exports may retain multiple rows per episode.
- Keep scalar capture generic, with the executor explicitly selecting task-local observations. Controller and SPMD consumers share tracker reductions, with independent local export and existing DP reduction boundaries. Turn distributions use compact summaries to avoid rescanning previously consumed tasks.
- Carry reward and acceptance observations with task results until dequeue. Expose reward-observation and task-attempt counts; complete groups contribute zero to incomplete-group metrics.
- Support classic proxy, v2 session export, and native remote inference. Observe failed v2 sessions before cleanup, distinguish unknown Harness status, and preserve observation-weighted DP aggregation. Remove duplicate turn logging from built-in multi-turn workflows.

For example, consuming 2-turn and 8-turn episodes and filtering the latter yields rollout mean 5/count 2 and training mean 2/count 1 when the retained episode exports one row. Evaluation uses separate `eval-rollout` episode and `eval-train` row scopes. English and Chinese documentation describes the denominators and custom-workflow integration.

## Validation

- Latest compact turn-statistics update: **109 passed**, including real two-process Gloo aggregation with unequal observation counts and an empty rank. A deterministic regression verifies that consuming more tasks does not inspect previous observations; it fails against the prior implementation.
- Local CPU benchmark (median of three runs, four turn observations per task): consuming 8,000 tasks took **10.72 s before / 0.28 s after**. Recording no longer scans historical tensors; export and retained per-call summaries remain linear in the number of records. Timing is illustrative, not a CI threshold.
- The broader and GPU results below were completed on `c947aae2f`, before this focused CPU aggregation optimization. GPU training was not repeated for the compact update.

- Broad metrics, executor, grouping, classic proxy, failure/retry, v2 controller/export, RTensor, gateway, and PRM regression suite: **514 passed**; four callback cases excluded locally due to IPv6 binding passed remotely.
- Remote controller and metrics suite: **247 passed**, including two-process Gloo aggregation with unequal observation counts and an empty rank. The separate controller GPU integration case was excluded from this run; the real training smoke exercises its generation/transport path.
- Two-step Qwen3-0.6B/GSM8K GRPO with SGLang DP2, Megatron DP2, XCCL synchronization, and intentional group filtering passed on four GPUs. Each step consumed **12 groups / 48 rollout episodes**, rejected **4 groups**, and retained **32 training rows**. Assertions verified rollout count 48, training count 32, zero missing turn counts, acceptance/rejection fractions, nonzero finite gradients, and weight versions 1 and 2. This uses the standard RLVR workflow and native metric collection, without a synthetic turn-metadata wrapper.
- Full `pre-commit run --all-files` and canonical `./docs/build_all.sh` passed.

Focused coverage includes `pytest tests/test_scalar_capture.py tests/test_rollout_stats.py tests/test_episode_turns.py tests/test_rollout_metrics.py tests/test_rollout_metrics_distributed.py tests/experimental/openai/test_rollout_metrics.py tests/v2/inference_service/test_rollout_turn_metadata.py`. Coverage also checks nested/async/thread capture, replay without recapture, independent reset windows, and requests omitting optional metadata. Additional regressions cover failed classic sessions, v2 excluded members and discarded groups, offline ready-plus-active history, online trajectory boundaries, and empty/missing counts during worker aggregation.

Risk areas are dequeue accounting and session/row metadata transport. Unknown turn counts are excluded rather than filled with zero. Custom workflows should use `set_episode_turns` instead of additionally logging `scalar(num_turns=...)`. This does not provide exactly-once accounting across network retries. Multi-node training, all-backend GPU combinations, proxy/Harness GPU end-to-end training, long-run convergence, and MTP were not validated.
