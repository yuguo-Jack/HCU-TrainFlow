# feat: distinguish consumed rollout and retained training metrics

[Upstream PR](https://github.com/areal-project/AReaL/pull/1796) · state: open · merged: False

## Original PR description

## Description

Asynchronous rollout metrics can include unused prefetch, while turn statistics derived only from retained training rows omit rejected episodes. Align quality metrics with task consumption and expose two distinct turn populations:

- `rollout/num_turns/{avg,min,max}` and `_count`: one observation per consumed logical episode before filtering, including rejected episodes and discarded groups. Count generated responses from raw session history, including retry branches later discarded by export. Report unavailable counts separately as `rollout/num_turns_missing_count`.
- `train/num_turns/{avg,min,max}` and `_count`: original generation history of each retained training row after selection/filtering. Preserve row metadata through serialization, slicing, and token cropping. Individual exports may retain multiple rows per episode.
- Keep scalar capture generic, with the executor explicitly selecting task-local observations. Controller and SPMD consumers share tracker reductions, with independent local export and existing DP reduction boundaries. Turn distributions use compact summaries to avoid rescanning previously consumed tasks.
- Keep the metrics recorder independent of workflow acceptance. A shared executor adapter records observations at consumption and normalizes rejected results; terminal failures remain visible to the dispatcher.
- Allow retained-row turn counts without Harness classification. Missing classification contributes only to the overall distribution; episode and row metadata share one classification function.
- Centralize remote statistics export in the inference engine. Backend facades delegate and access executor metrics through its export interface.
- Carry reward and acceptance observations with task results until dequeue. Expose reward-observation and task-attempt counts; complete groups contribute zero to incomplete-group metrics.
- Support classic proxy, v2 session export, and native remote inference. Observe failed v2 sessions before cleanup, distinguish unknown Harness status, and preserve observation-weighted DP aggregation. Remove duplicate turn logging from built-in multi-turn workflows.

For example, consuming 2-turn and 8-turn episodes and filtering the latter yields rollout mean 5/count 2 and training mean 2/count 1 when the retained episode exports one row. Evaluation uses separate `eval-rollout` episode and `eval-train` row scopes. English and Chinese documentation describes the denominators and custom-workflow integration.

Compact turn recording has a regression that rejects historical list rescanning. A previously recorded local benchmark of 8,000 tasks measured 10.72 s before and 0.28 s after compact aggregation (median of three runs). Export and stored per-call summaries remain linear in the number of records; timing is not a CI threshold.

Risk areas are dequeue accounting and session/row metadata transport. Unknown turn counts are excluded rather than filled with zero. Unknown Harness classification is excluded from both Harness subgroups. Custom workflows should use `set_episode_turns` instead of additionally logging `scalar(num_turns=...)`. This does not provide exactly-once accounting across network retries. Multi-node training, all-backend GPU combinations, proxy/Harness GPU end-to-end training, long-run convergence, and MTP were not validated.
