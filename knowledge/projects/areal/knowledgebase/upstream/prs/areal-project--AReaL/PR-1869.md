# fix(reward): backport Geometry3K expression parsing to ascend

[Upstream PR](https://github.com/areal-project/AReaL/pull/1869) · state: open · merged: False

## Original PR description

## Description

Backport Geometry3K library answer parsing to `ascend`, which lacks both #1760's gold-LaTeX handling and #1868's boxed extraction. Its old implementation takes the last bracketed value or number from both prediction and gold, allowing `\boxed{2\sqrt{3}}` to match gold `3` and `\boxed{3}` to match gold `5\sqrt{3}`.

- Select the last outer boxed completion with balanced braces, preserving nested expressions and escaped braces. Empty or unfinished final boxes receive zero. Keep the legacy bracket/number fallback when no box is present.
- Preserve complete gold expressions and normalize nested boxes as grouping before math-delimited verification. The gold scanner is deliberately only a validity check: selecting the inner box in `5 + \boxed{2}` would change the gold answer to `2`.
- Include the pending main follow-up #1877: normalize recognized trailing geometry units and reject non-string completions rather than grading escaped Python representations. This fixes both the reported unit false negatives and the structured-input false positives without enabling raw-number verification retries.
- Add regression coverage and module docstrings describing the scope of each test file.

The change is limited to `areal/reward/geometry3k.py` and four reward test files. The shared verifier, dependencies, and separate VLM training scorer are unchanged.

File: `areal/reward/geometry3k.py` · line 127


Wrapping every extracted answer in `$...$` regresses previously accepted answers with ordinary unit suffixes. With `math-verify==0.8.0`, these cases return `1.0` on the PR base but `0.0` with proposed changes:

| Completion | Gold |
| --- | --- |
| `\boxed{5 centimeters}` | `5` |
| `\boxed{5 in}` | `5` |
| `[90 cm^2]` | `90` |

The forced LaTeX parsing treats unit letters as variables: `$5 in$` becomes `5*i*n`, and `$90 cm^2$` becomes `90*c*m**2`. Correct geometry answers therefore lose credit.

Thanks for the detailed review. I’ve addressed the points in the latest update:

- Gold boxes: Removed the unused boxed variable and clarified that the scanner only validates gold boxes. We deliberately preserve the full gold expression: returning the extracted value would incorrectly reduce 5 + \boxed{2} to 2. Added regressions for standalone boxes and boxes inside sums/fractions.
- Completion types: The built-in RLVR, vision RLVR, and multi-turn workflows pass decoded strings. However, direct dict/tuple inputs did reproduce the false positive you described. Non-string completions now return zero instead of being stringified. The doubled-backslash example cited is a GSM8K test; Geometry3K now also has explicit escape-handling coverage.
- Math delimiters: The existing behavior is retained, with new tests covering $...$ and $$...$$ inside bracketed/boxed predictions and wrappers on the gold side.
- Test organization: Added module docstrings explaining each file’s responsibilities.

The suite now passes 579 tests on both branches. I also confirmed automatic CPU-test discovery and clarified that the documented Ascend training example and E2E use the separate mathruler scorer.

One qualification on main parity: the reward module and all four test files are identical between this PR and #1877, but the diff against merged main is not yet empty. #1877 contains the unit-suffix correction and these review follow-ups. My preference is to merge that main follow-up first, then recheck parity before merging this backport.

Agreed that the two scorer implementations deserve a separate convergence discussion; this PR leaves the training-example scorer unchanged.
