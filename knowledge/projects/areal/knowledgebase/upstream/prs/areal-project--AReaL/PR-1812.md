# fix(utils): split multimodal payloads by trajectory rows

[Upstream PR](https://github.com/areal-project/AReaL/pull/1812) · state: closed · merged: True

## Original PR description

## Description

Fix the inverse of multimodal list concatenation when splitting a batch back into trajectory groups.

Previously, `split_and_unpad_tensor` deep-copied the entire `multi_modal_input*` list into every trajectory. This inflated both image-row lists and tensor storage and broke per-trajectory ownership. The real `PPOActor.compute_advantages` path uses this split through `batched_call`.

- Slice only list-valued `multi_modal_input*` fields by trajectory group size, then deep-copy each group's slice.
- Reject multimodal row counts inconsistent with the tensor batch.
- Preserve existing deep-copy behavior for ordinary metadata and non-list values.
- Add CPU regression tests for variable/empty groups, no-image rows, multimodal key variants, copy isolation, within-group aliases, linear unique-storage growth, and the real PPO advantage path followed by selection/reordering and microbatch preparation.

## Additional Context

### Minimal reproduction on the base revision

```python
import torch

from areal.utils.data import batched_call

trajectories = [
    {
        "input_ids": torch.full((1, 3), image_id, dtype=torch.long),
        "attention_mask": torch.ones(1, 3, dtype=torch.bool),
        "multi_modal_input": [
            {"pixel_values": torch.full((4, 3), float(image_id))}
        ],
    }
    for image_id in (1, 2)
]
outputs = batched_call(lambda batch: batch, trajectories)
print([len(output["multi_modal_input"]) for output in outputs])
print([
    [row["pixel_values"][0, 0].item() for row in output["multi_modal_input"]]
    for output in outputs
])
```

The base prints `[2, 2]` and `[[1.0, 2.0], [1.0, 2.0]]`.
The fix prints `[1, 1]` and `[[1.0], [2.0]]`.

### Small CPU storage probe

Four rows share one 128 KiB image tensor within each trajectory group. Counted unique retained tensor storages by `untyped_storage().data_ptr()`, summing their `nbytes()`:

| Trajectory groups | Baseline output storages / bytes | Fixed output storages / bytes |
| --- | --- | --- |
| 1 | 1 / 128 KiB | 1 / 128 KiB |
| 2 | 4 / 512 KiB | 2 / 256 KiB |
| 8 | 64 / 8 MiB | 8 / 1 MiB |
| 16 | 256 / 32 MiB | 16 / 2 MiB |

These are CPU tensor-storage observations, not process-RSS, GPU-OOM, or throughput benchmarks. End-to-end GPU training was not run.

### Scope and risk

Only list-valued keys matching the existing `is_multi_modal_key` contract are sliced. Ordinary metadata lists are deliberately not interpreted as row-aligned, even when their length matches the batch. Image dimensions are not sequence-unpadded.

The Megatron controller already strips/restores multimodal fields around its advantage RPC; this fix addresses the generic split utility and PPO actor path rather than claiming that workaround is missing. An unchanged-order downstream batch can mask image alignment errors; the regression deliberately selects and reorders returned trajectories to check their ownership contract.
