# fix(engine): align Megatron loss scaling with upstream

[Upstream PR](https://github.com/areal-project/AReaL/pull/1790) · state: closed · merged: True

## Original PR description

## Description

In mean-loss mode, AReaL manually scaled the main loss while Megatron Core seeded auxiliary gradients separately. Configure the optimizer loss-scale hook during initialization for all model chunks and both normalization modes, then remove manual scaling from the engine and FP8 gradient-capture helper. This keeps main and auxiliary gradients on the same scale through optimizer unscaling.

Align per-token loss construction with main's helper: distribute integer token counts using quotient and remainder, and use each rank's assigned weight for both its numerator and count. This is mathematically equivalent to the previous CP bookkeeping for reconstructed full-sequence losses. Retain the positive global batch-weight guard and the existing NPU auxiliary-setting propagation.

Extend CPU regression coverage for non-divisible and zero token counts, shared model configurations, dynamic loss scales, optimizer-free engines, and independently injected auxiliary gradients. Keep the FP8 comparison helper consistent with the engine's DP/CP and microbatch normalization.

## Upstream Provenance and Local Adaptations

This is a selective backport/adaptation of normalization and scaler changes from two upstream commits, with local compatibility work and regression tests. It is not a wholesale cherry-pick of #1672.

The scaler helper already existed in the parent of `c74b343c`, which is why it is absent from that commit's diff. Both helper bodies match their respective upstream implementations apart from docstrings. The existing positive global-weight guard and NPU auxiliary-setting forwarding are retained from #1788; they are not new changes in this PR. The broader MTP/speculative-decoding functionality from #1659 and VLM routing/version-guard changes from #1672 are outside this PR's scope.
