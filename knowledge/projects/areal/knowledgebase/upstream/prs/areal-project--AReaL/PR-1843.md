# feat(trainer): support two-stage rollout correction on Ascend

[Upstream PR](https://github.com/areal-project/AReaL/pull/1843) · state: closed · merged: True

## Original PR description

## Description

Currently, `actor.rejection_sampling` uses a single configuration for both sample filtering and importance weighting. With sequence-level ratio filtering, surviving tokens receive their sequence's geometric-mean weight. A sequence can therefore pass the rejection gate while an individual token has a large probability ratio, without a separate token-level weight cap.

This PR adds optional two-stage rollout correction for Ascend, allowing sequence-level rejection and token-level importance weighting to be configured independently. This enables combinations such as geometric-mean sequence rejection sampling (Geo-RS) with token-level truncated importance sampling (Token-TIS).

### Configuration

Add optional `actor.importance_sampling`, reusing `RejectionSamplingConfig`:

- `rejection_sampling` supplies the filtering mask.
- `importance_sampling` supplies the `pi_proximal/pi_behave` correction weight.
- Leaving `importance_sampling` unset preserves the existing single-stage behavior, where `rejection_sampling` supplies both.

For example:

```yaml
actor:
  use_decoupled_loss: true
  rejection_sampling:
    level: sequence
    action: mask
    metric: ratio
    agg: mean
    lower: 0.98
    upper: 1.02
  importance_sampling:
    level: token
    action: clamp
    metric: ratio
    upper: 2.0
```

Both stages evaluate the original incoming mask, and their resulting masks are intersected. Filtering keeps the original loss-aggregation denominator. Each stage reports its own fraction through `rs_filtered_fraction` and `is_filtered_fraction`.

Configuring `importance_sampling` without `rejection_sampling` raises an error; single-stage correction should continue to use `rejection_sampling`.
