# fix(infra): reap detached Slurm worker descendants

[Upstream PR](https://github.com/areal-project/AReaL/pull/1771) · state: closed · merged: True

## Original PR description

## Description

Fix Slurm worker descendants surviving task shutdown on clusters using
`proctrack/linuxproc`. Detached worker/proxy processes from terminal historical
jobs were observed still holding substantial host memory. Cleanup based only on
the original RPC process tree can lose double-forked descendants.

- Run each task under a lightweight Linux subreaper. Orphaned descendants remain
  attached to the supervisor even after an intermediate parent or worker dies.
- On worker exit or TERM/INT/HUP, discover descendants repeatedly, send TERM,
  escalate to KILL, and reap them. Cleanup stays within that task's descendants;
  it does not select processes by username, job-name pattern, or environment.
- Give the supervisor its full shutdown budget before scheduler-wide escalation.
- Preserve worker interpreter, shell variable expansion, leading `env` wrappers,
  environment setup, output, and worker exit status. The bootstrap avoids importing
  AReaL/PyTorch in an extra supervisor process for every rank.
- Enable `pipefail` so streaming logs cannot hide an unsuccessful worker step.

Linux subreaper semantics: [PR_SET_CHILD_SUBREAPER manual](https://man7.org/linux/man-pages/man2/PR_SET_CHILD_SUBREAPER.2const.html).

## Risks and limits

The supervisor needs Linux `prctl` support. It cannot execute cleanup if it is
itself killed with SIGKILL, including an OOM that kills the entire task/container;
Slurm cgroup process tracking is required to cover that case. Scheduler escalation
now waits for the normal supervision shutdown budget before sending SIGKILL.

GPU and full distributed training suites were not rerun: this change concerns
per-task process lifetime and shell command construction, which the CPU tests
exercise directly. The currently running recovery experiment was kept running.
