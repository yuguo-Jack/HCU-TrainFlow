# feat(docker): add Dockerfile.rocm for AMD ROCm images

[Upstream PR](https://github.com/areal-project/AReaL/pull/1820) · state: closed · merged: True

## Original PR description

**Merge after #<PR1>** (`fix(engine): restore aiter MoE weight layout after online weight updates`).
The sglang variant runs that PR's `areal.engine.sglang_aiter_moe_layout` at build time. On this
branch alone, `VARIANT=vllm` builds, while `VARIANT=sglang` stops with
`No module named areal.engine.sglang_aiter_moe_layout`.

### Key changes

- `FROM rocm/primus:v26.5` (ROCm 7.15, torch 2.12, Transformer Engine, aiter, flash-attn). The base
  image's ROCm torch is never replaced, and the last build step fails if `torch.version.hip` is unset.
- The engine pins match `Dockerfile`: SGLang `v0.5.10.post1` and vLLM `v0.19.1`, both built from
  source for ROCm. `torch_memory_saver` (`118b09b`, whose HIP VMM fix is not in a tag yet),
  Megatron-LM `core_v0.19.0` and mbridge are also built from source.
- vLLM cherry-picks vllm#41802 (`6881c754e1`, released in v0.21.0). It fixes `call to atomicAdd is
  ambiguous` in the GPTQ kernels on ROCm >= 7.13. Drop it once AReaL pins vLLM >= 0.21.0.
- `requirements-rocm.txt` pins the shared Python dependencies. They are installed `--no-deps` because
  `pyproject.toml` requires `torch<2.11`, so resolving it would replace the ROCm torch. That is also
  why this file cannot use `uv.lock`.
- Engine source trees are removed after installation, as in the CUDA image.
- Runtime overrides of values baked into the base image (each one is commented in the file):
  - `GPU_ARCHS=gfx942`: aiter cannot resolve the base's `native` and would JIT for gfx906.
  - `LD_LIBRARY_PATH` replaced rather than appended: the base ships two libLLVM copies, and loading
    both aborts torch_memory_saver and Transformer Engine.
  - `NVTE_FLASH_ATTN=1 NVTE_FUSED_ATTN=1`: megatron-core's `attention_backend=auto` needs both.
  - `VLLM_SERVER_DEV_MODE=1`: vLLM 0.19.1 serves `/sleep` and `/wake_up`, used by colocation, only in
    dev mode. Dev mode exposes unauthenticated debug endpoints, so do not publish the vLLM port.
  - `SHELL ["/bin/bash", "-o", "pipefail", "-c"]`.

## Additional Context

### What was tested

All runs used AMD MI308X (gfx942).

**1. Images built from exactly this Dockerfile (with #<PR1> applied)**

- `VARIANT=sglang` and `VARIANT=vllm` both build. The import check prints
  `OK 2.12.0+rocm7.15.0a20260720 0.5.10.post1` and `OK 2.12.0+rocm7.15.0a20260720 0.19.1`.
- At runtime both images report `GPU_ARCHS=gfx942`, `PYTORCH_ROCM_ARCH=gfx942` and
  `VLLM_SERVER_DEV_MODE=1`, and both engines import with `/sglang` and `/vllm` removed.
- In the sglang image, 5 of 5 `torch_memory_saver` VMM probes pass. They cover allocation, the
  `LD_PRELOAD` hook with and without a region, `TMS_INIT_ENABLE=1`, and pause/resume with CPU backup
  followed by `.item()`.

**2. End-to-end RL training on an image from this Dockerfile (`VARIANT=vllm`)**

The run used Qwen3-30B-A3B with FSDP2, vLLM 0.19.1, aiter MoE, CUDA graphs and real xccl weight
updates. It completed 4 of 4 steps with exit code 0, finite loss and live gradients. The mean
train-vs-rollout logprob difference was 0.030, and 0.16% of tokens were beyond ln 2. 

**3. RL training cases (8 × MI308X)**

Based on this PR [fix(engine): restore aiter MoE weight layout after online weight updates](https://github.com/areal-project/AReaL/pull/1834): FSDP and Megatron colocation offload, vLLM colocation server
arguments, vLLM disk-update wake-up, SGLang colocation weights, and an MoE expert-name fix. These
results show that the stack trains.

| Case | Model | Result |
|---|---|---|
| smoke: SGLang + FSDP2, separation | Qwen2.5-0.5B | pass |
| smoke: vLLM + FSDP2, colocation | Qwen2.5-0.5B | pass |
| smoke: SGLang + Megatron, colocation | Qwen2.5-0.5B | pass |
| smoke: vLLM + Megatron, separation | Qwen2.5-0.5B | pass |
| accuracy: SGLang + FSDP2, separation | Qwen2.5-Math-7B | pass, logprob diff 0.0188 |
| accuracy: vLLM + FSDP2, colocation | Qwen2.5-Math-7B | pass, logprob diff 0.0094 |
| accuracy: SGLang + Megatron, colocation | Qwen2.5-Math-7B | pass, logprob diff 0.0186 |
| accuracy: vLLM + Megatron, separation | Qwen2.5-Math-7B | pass, logprob diff 0.0095 |
| stability: SGLang + FSDP2, separation | Qwen3-30B-A3B | 120/120 steps, no OOM, hang or RCCL timeout; leak verdict inconclusive |

- **Smoke**: 3 steps at learning rate 0. It checks that the rollout weights are bit-identical to the
  trainer's after a sync (with a poisoned-weights negative control), and that a checkpoint saved
  after step 2 is loaded and training resumes at step 3.
- **Accuracy**: 20 steps, gated on the mean train-vs-rollout logprob difference (limit 0.2, at most 1%
  of tokens beyond ln 2). It does not prove convergence.
- **Stability**: no OOM, hang or RCCL timeout. 

### Not covered

- GPUs other than MI308X (gfx942). Other architectures need `--build-arg GPU_ARCH=...` and were not built.
- Other base images or ROCm versions, and upstream AMD CI (AReaL has no AMD runners).
- `requirements-rocm.txt` and the per-variant pins are maintained by hand and must follow `uv.lock`.
