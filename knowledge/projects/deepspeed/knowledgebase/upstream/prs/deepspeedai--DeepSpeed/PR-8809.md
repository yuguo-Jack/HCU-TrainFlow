# [checkpoint] Execute affine transfer plans with bounded peer staging

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8809) · state: open · merged: False

## Original PR description

The merged #8623 planner describes affine shard copies. This PR executes those plans directly into existing frozen target shards with bounded peer staging, without reconstructing the full logical tensor.

Refs #8230, #8252 and 0z5a/DeepSpeed#1. This is the executor portion of that work; #8800 supplies live AutoEP metadata separately. The diff is limited to **3 files, 972 added lines**: executor, contract tests and API documentation. Historical benchmark drivers and evidence remain in the fork and are linked below.

`execute_transfer` / `execute_transfers` accept explicit source and target rank bindings, preserve strided regions and storage offsets, and collectively reject invalid buffers, aliases or request-order disagreement before writes. Shared plans reuse their schedule within a call. CUDA handles drain every 32 rounds and before return; other work handles retain immediate waits.

Review fixes: CUDA tests check accelerator type and visible device count before worker launch; valid scalar plans now execute; the unrelated `new_group(timeout=...)` changes are removed, preserving the existing CCL interface.

On the same two H100s, restoring the original scalar predicate causes all four scalar regressions (single/batched, local/cross-process) to fail with the dimension-rejection defect. The fixed full file passes, including FP32/FP16/BF16 transfer, mixed storage windows, collective refusal, request ordering and a shared-plan batch spanning 48 rounds. The final pytest and Slurm step exit zero and the assigned GPU contexts are gone. Startup/resource failures are retained separately.

[Historical eight-H100 non-scalar correctness evidence](https://github.com/0z5a/DeepSpeed/blob/3cdc69ae1c4de9ebed8bfe57d02c2640785a5af2/tests/distributed/checkpoint/evidence/affine_handoff_gpu8_wait32_20261011.json) records 304 BF16/FP32 checks plus mixed-layout and shared-plan checks. [Historical paired performance](https://github.com/0z5a/DeepSpeed/blob/3cdc69ae1c4de9ebed8bfe57d02c2640785a5af2/tests/distributed/checkpoint/evidence/affine_handoff_gpu8_wait32_performance_20261012.json) reports 1.289x geometric speedup, 95% CI [1.2703, 1.3080], for a 1-GiB synthetic frozen-weight handoff. These are prior non-scalar runs, not a new eight-GPU qualification of this rebased and reduced branch or a full-model performance claim.

Scope: scale-1 plans and frozen packed weights. No optimizer migration, live AutoEP swap, CPU/NVMe offload integration, training convergence/resumption, serving or non-CUDA vendor qualification. The staging budget applies per peer direction; a payload-time transport failure may partially modify targets. Maintenance contact: @0z5a.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Accept scalar segments produced by the planner**

When source and target maps describe a 0-D scalar (for example `replicated_map((), 1)`), `plan_transfer` legitimately emits a one-element `TransferSegment` whose shape is `()`, but this truthiness check rejects it before either a local or P2P copy. Consequently the generic executor cannot execute valid planner output for scalar parameters; validate dimensionality with `len(segment.shape) != ndim` without treating a zero-dimensional shape as an empty segment.
