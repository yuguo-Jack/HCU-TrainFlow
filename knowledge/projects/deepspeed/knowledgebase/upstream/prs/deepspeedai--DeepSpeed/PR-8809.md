# [checkpoint] Execute affine transfer plans with bounded peer staging

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8809) · state: open · merged: False

## Original PR description

The merged #8623 planner produces affine copy descriptors, but executing a topology handoff still needs a transport path. This PR executes those scale-1 plans directly into existing target shards, with bounded peer staging and collective rejection before any write, without reconstructing the full logical tensor.

Refs #8230 and #8252. This carries forward the executor already described in 0z5a/DeepSpeed#1. It is separate from #8800's live AutoEP metadata producer and the replica-policy/phase-integration work discussed in #8252; duplicate-work searches found no open upstream executor PR.

### Implementation

- Opt-in `execute_transfer` / `execute_transfers` APIs, explicit source/target endpoint bindings, N-D strided tiling, storage-offset/alias checks and a per-peer/per-direction staging budget.
- Contiguous regions use existing shard views; mixed or strided messages use bounded staging. Requests sharing one plan reuse its schedule only within that call.
- Caller-stream ordering protects reuse and final target readiness. CUDA transport handles drain every 32 rounds and before return; unsupported stream-blocking backends retain immediate waits.
- An AutoEP adapter consumes persisted placement metadata from frozen, packed expert Parameters. It preserves Parameter identity; no implicit live-layer swap or optimizer migration is added.
- Unit and external torchrun correctness drivers, synthetic benchmarks, source-bound validation records and API documentation. New upstream code is retained, including CPU shared-memory ISA fallback.

### Performance and compatibility

The preceding schedule-reuse revision used 1 GiB of BF16 expert weights, 32 parameters,
8 MiB per peer and five alternating paired windows, each at least 60 seconds.

| Metric | Rebuild/extract | Direct transfer |
|---|---:|---:|
| Median of window P50 latency | 21.304 ms | 21.262 ms |
| Maximum per-rank peak allocated | 3.500 GiB | 2.500 GiB |
| Maximum per-rank peak reserved | 3.627 GiB | 3.627 GiB |

The paired geometric speedup is **0.9989x, 95% CI [0.9847,1.0132]**: the interval
includes parity, so this PR makes **no established speedup claim**. Those timings
belong to the preceding revision, not the new 32-round drain; its paired performance
has not been rerun. Earlier regressions and failed attempts remain in the evidence records.

Validated: scale-1 frozen packed weights, CPU contracts and BF16/FP32 H100 CUDA,
disjoint/resized endpoint sets, collective refusal, strided layouts, offsets, and
immediate AutoEP consumer forward checks. Not validated here: full-model serving,
training convergence/resumption, optimizer state, unnormalized ZeRO/EDP fragments,
CPU/NVMe offload integration, live concurrent updates, DeepEP or other GPU vendors.
A failure after payload begins can leave partial target data; there is no rollback contract.
The staging limit bounds each peer direction, not the model or total device memory.

When source and target maps describe a 0-D scalar (for example `replicated_map((), 1)`), `plan_transfer` legitimately emits a one-element `TransferSegment` whose shape is `()`, but this truthiness check rejects it before either a local or P2P copy.
