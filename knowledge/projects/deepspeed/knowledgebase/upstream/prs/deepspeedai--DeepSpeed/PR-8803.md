# Use C++20 for XPU op builders on torch 2.12+

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8803) · state: open · merged: False

## Original PR description

On PyTorch 2.12+, `torch.utils.cpp_extension` compiles extensions with `-std=c++20`, and PyTorch's headers need it (`torch/all.h` errors below C++20 since 2.12, and `ATen.h` requires it on main). The XPU op builders append `-std=c++17` after torch's own flag. That later flag wins, so every XPU JIT build fails (for example `FusedAdamBuilder`).

This PR makes the XPU `SYCLOpBuilder.cxx_args` and `AsyncIOBuilder.cxx_args` use C++20 on torch >= 2.12 and keep C++17 otherwise. It applies the same rule #8238 added for the CUDA/CPU builders (see #8235).

Scope: XPU only. The NPU and SUPA builders and ROCm hipcc still hardcode `-std=c++17` and may need the same change. They are left out because I can't test them here.

### Testing
On 8x Intel Arc Pro B70 with torch `2.14.0.dev20260804+xpu`, using a fresh `TORCH_EXTENSIONS_DIR`:
- Before: the XPU `fused_adam` JIT build fails with errors that the PyTorch headers require C++20.
- After: `fused_adam` builds with icpx. Its updates match `torch.optim.AdamW` to within about 1e-6. AutoSP tests that use FusedAdam (for example `EngineBackward`) now pass.
- `AsyncIOBuilder` reports itself incompatible on this machine (no libaio), so that build was not exercised.

On a torch 2.0 XPU installation (the project still declares `torch>=2.0.0`), this helper returns `-std=c++14`, and `SYCLOpBuilder.cxx_args()` now uses that value for every SYCL op. Before this change the SYCL builder always passed C++17, and `csrc/xpu/adam/multi_tensor_apply.dp.hpp` already uses `if constexpr`, so `FusedAdamBuilder` is now compiled in a language mode below what its source requires.
