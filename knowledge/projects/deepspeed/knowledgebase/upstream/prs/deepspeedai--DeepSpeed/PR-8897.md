# Cover ZeRO-3 DP-resize rejection before serial checkpoint loading

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8897) · state: open · merged: False

## Original PR description

Add regression coverage for ZeRO-3 rejecting legacy checkpoints with a different data-parallel size before serial checkpoint synchronization. The production preflight is already in merged #8891; this follow-up retains that upstream engine implementation and makes this PR test-only against master `9148ab22`.

The regression saves real optimizer state at DP=1 and loads at DP=2 with both `load_optimizer_states` flags, serial loading enabled/disabled, and FP32/FP16/BF16. Every rank must raise the existing topology error and reach a barrier. The valid serial round trip now covers full-state and module-only loading with torch Adam.

Local validation on 2026-10-30: Apple M3, macOS 15.1 ARM64, Python 3.12.13, torch 2.14.1, CPU/Gloo:

```sh
DS_ACCELERATOR=cpu CUDA_VISIBLE_DEVICES=0,1,2,3 LOCAL_SIZE=4 GLOO_SOCKET_IFNAME=lo0 OMP_NUM_THREADS=1 PYTHONPATH=.:tests python -m pytest --forked tests/unit/checkpoint/test_zero_optimizer.py::TestZeRO3CheckpointDPChange tests/unit/checkpoint/test_zero_optimizer.py::TestZeROCheckpoint::test_pipeline_checkpoint_loading --torch_ver=2.14.1 -q
```

Result: **10 passed, 4 skipped** (FP16 unsupported). Changed-file pre-commit passes. No training arithmetic, checkpoint format, or runtime code changes relative to current master. #8898 separately fixes token handoff for successful serial loads. Historical GPU results in the previous description apply to the original implementation, not this test-only integration; no new CUDA/NCCL, offload or multi-node validation is claimed.

Negative control: restricting the current preflight to `load_optimizer_states=True` leaves the serial masters-only case hung until the external 180-second deadline (exit 124). This is a timeout observation, not a normal pytest assertion failure. The original engine was restored in `finally`; that exact selected case then passes again. The final engine is byte-for-byte current master.

AI assistance (OpenAI Codex) was used to prepare and execute this follow-up. Published follow-up: `ae939211` integrates upstream master `9148ab22` in the existing PR branch. The submitting human confirmed reviewing the final diff and running the relevant tests, and authorized DCO sign-off and publication.
