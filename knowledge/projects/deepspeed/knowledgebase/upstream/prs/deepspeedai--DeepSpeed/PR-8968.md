# Skip redundant Stage-0 gradient reduction at DP=1

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8968) · state: open · merged: False

## Original PR description

## Summary

This adds the optional Stage-0 performance follow-up noted in [#8814](https://github.com/deepspeedai/DeepSpeed/issues/8814). The shared `pg_utils.is_parallel()` migration was completed separately in #8815; this PR only avoids the dense gradient bucket reduction when it is provably an identity. The prior tracking issue #8965 is closed, and no open duplicate PR was found.

The fast path requires a singleton data-parallel group, an effective DP size of 1, matching gradient and communication dtypes, and identity gradient scaling. It avoids bucket splitting for the common dense-only case. If dtype conversion or scaling would change the result, the existing reduction path remains in use. Sparse gradients keep their existing handling; expert-gradient and ZeRO-1/2 paths are unchanged. No public API or configuration changes.

## Compatibility scope

Validated: Stage-0 DP=1 on L20 with FP32 gradients and FP32/BF16 communication dtype; DP=2 reduction behavior for ZeRO stages 0/1/2 on CPU/Gloo; singleton subgroup and sequence-adjusted group-size guards on CPU/Gloo.

Not validated end to end: pipeline parallelism, MoE, offload, full TP/SP training topologies, and ZeRO-1/2 on L20. Those paths are not changed by this PR.
