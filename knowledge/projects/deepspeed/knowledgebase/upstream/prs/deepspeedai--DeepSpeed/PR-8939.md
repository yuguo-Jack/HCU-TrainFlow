# feat(rollout): non-greedy sampling on hybrid engine graph decode path

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8939) · state: open · merged: False

## Original PR description

Closes #8934.

## Summary

`HybridEngineRollout` decodes greedily on its fast paths. Graph capture applies only when `temperature <= 0`, and sampling silently falls back to Hugging Face `generate()`. Continuous batching (#8368), with or without its CUDA graph (#8732), rejects `temperature > 0` outright. RL rollouts sample at temperature 1, so they get neither path.

Only the decode forward is captured; the next token is picked on the host from the output logits. So sampling needs no change to any captured graph. This PR changes token selection and dispatch only:

- **One token selector**, `HybridEngineRollout._token_selector(sampling)`, picks the first token and every decoded token on all three paths: graph decode, continuous batching, and continuous batching with graphs.
  - At `temperature <= 0` it takes the argmax, as before.
  - Otherwise it applies Hugging Face's `TemperatureLogitsWarper`, `TopKLogitsWarper` and `TopPLogitsWarper`, in `generate()`'s order on float32 logits, then calls `torch.multinomial`. So every path samples from the same distribution as `generate()`.
- **Graph dispatch:** sampled requests go to the graph path; `generate()` no longer checks `is_greedy` for it.
- **Continuous batching:**
  - The greedy-only check is removed.
  - The model's repetition penalty is applied before the selector, which is `generate()`'s order.
- **`_hf_sampling_kwargs(sampling)`:** the `generate()` sampling arguments, now shared by the main `generate()` call and the continuous-batching prefill of models without cache-class support. That prefill previously hard-coded `do_sample=False`.
- **Docs:** `inference-engine.rst` now describes sampling on the graph decode path, and "greedy decoding" is dropped from the continuous batching requirements.

## Known issues outside this PR

On master, two cache and mask gaps stop some paths from running on a Hugging Face model with SDPA attention, greedy included. This PR doesn't touch either; #8602 fixes both.
- **Plain graph path (`_generate_graph`), Transformers 4.57.x:** capture fails with "operation not permitted when stream is capturing". The decode step's 2-D attention mask makes Transformers call `padding_mask.all()` on the host (reported by 0z5a on #8197). #8602 passes a pre-built 4-D decode mask.
- **Plain graph path and continuous batching without graphs, Transformers 5.x:** `DeepSpeedStaticCache` has no `get_query_offset` (also #8852). #8602 adds it.

Until #8602 lands, the end-to-end GPU tests of these paths fail with those errors (results below).

## Tests

The tests cover correct dispatch and correct sampling.

`tests/unit/runtime/rollout/test_hybrid_engine_rollout.py` (CPU):
- The graph dispatch test also runs at temperature 0.7 and checks that `generate()` is not called.
- `test_token_selector_samples_the_configured_distribution`: 20,000 draws from fixed logits for temperature, top-k, top-p and their combination. They are compared against a reference distribution computed independently of the rollout. No token outside the top-k / top-p support may appear, and every token's frequency must lie within 4 standard errors.
- `test_token_selector_is_argmax_without_temperature`.
- `test_continuous_generation_samples_when_temperature_is_set`:
  - setup: continuous batching on a fake model whose logits tie tokens 7 and 8, with top-k 2;
  - check: the output must contain both tokens and nothing else (greedy would always pick 7);
  - this replaces the assertion that continuous batching rejects `temperature > 0`.
- `test_continuous_sampling_applies_repetition_penalty_before_warpers`: with penalty 1.5 and top-k 1, the token the penalty favors must win.

`tests/unit/v1/test_hybrid_engine_rollout_v1.py` (CUDA): `test_decode_sampling_matches_hf_generate` samples end to end on a tiny random Llama, with a scaled output head so next-token distributions are peaked.
- Paths: graph decode, continuous batching, and continuous batching with graphs.
- Settings: (temperature 1), (temperature 0.7, top-k 5) and (temperature 1, top-p 0.8).
- Check: under the same seed, the generated tokens must equal Hugging Face `generate()`'s exactly. Every prompt gets its own continuous batching slot, so each path draws all rows' tokens in one call per step, as `generate()` does, and both consume the same random numbers.

Results on this branch (master `322283b25` + this PR), 1× NVIDIA A40 (driver 595.71.05), torch 2.14.1+cu130:

| 5.19.0 | 88 passed, 6 failed, 1 skipped | the 3 plain graph-path and 3 continuous-batching-without-graphs cases: no `get_query_offset` |

All failures are the master issues above, which #8602 fixes. Every CPU test passes on both versions, and so does continuous batching with graphs end to end. The skipped test is the optional pretrained-model test
(`DEEPSPEED_PRETRAINED_ROLLOUT_MODEL`).

Read at `aa82e726`.

The shared token selector is a nice consolidation: one place applies temperature, top-k and top-p in `generate()`'s order on float32 logits. On CPU, `test_hybrid_engine_rollout.py` and `test_hybrid_engine_rollout_v1.py` pass (57; the rest need CUDA or a pretrained model), including the 20,000-draw distribution test.

One point I think needs settling before this lands, inline below. With `use_graph_capture=True`, sampled requests used to fall back to `module.generate()` and now always take `_generate_graph`. That changes two things for configurations that work today:
- Until #8602 lands, `_generate_graph` fails on Transformers 4.57.x with SDPA (the host-side `padding_mask.all()` during capture that I reported on #8197) and on 5.x (`get_query_offset`), as the description and the merge-queue failure show. So sampled rollouts with graph capture that currently run through `generate()` would start raising.
- `_generate_graph` (the plain graph decode, not the continuous-batching one) never reads `generation_config`, while `generate()` applies its processors. For example, Qwen2.5-7B-Instruct ships `repetition_penalty: 1.05`, so its sampled rollouts would silently move to an unpenalized distribution. Greedy graph decoding already had this gap; this PR extends it to sampled requests.

Landing after #8602 would cover the first point. For the second, keeping the `generate()` fallback for sampled requests whose `generation_config` has a non-default repetition penalty, or rejecting them, would keep "the same distribution as `generate()`" true.

The two Codex notes on the continuous path also still apply at this head:
- The prefill token is selected from unpenalized logits (`_continuous_prefill_cache`), unlike the decode steps.
- The penalty runs on bf16/fp16 logits before the selector casts to float32.

On fp16/bf16 continuous-batching models with a non-default repetition penalty, `clone()` preserves the low-precision dtype, so the multiply/divide at lines 1122-1124 rounds before `_token_selector` later casts to float32. Hugging Face `generate()` casts next-token logits to float32 before running logits processors; near a top-k/top-p boundary this ordering can change the retained support and sampled probabilities, so convert the logits to float before applying the penalty.
