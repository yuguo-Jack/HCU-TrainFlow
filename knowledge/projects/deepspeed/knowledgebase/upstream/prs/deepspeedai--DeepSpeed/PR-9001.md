# ZeRO-1/2: expose original parameter layout on flat optimizer partitions

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/9001) · state: open · merged: False

## Original PR description

## Summary

ZeRO-1/2 replace each optimizer parameter group with one flat local FP32 partition. Custom optimizers therefore see a single 1-D tensor and cannot recover the original parameter shapes, boundaries, or global offsets. This is a common source of shape-dependent failures in custom optimizers (see #8812).

This change keeps the flat layout untouched and attaches metadata to each flat partition:

- `ZeROFlatParamMetadata` and `ZeROFlatPartitionMetadata` describe the original parameter index, shape, numel, flat offset, padding, local partition overlap, and DP group/world size.
- `get_zero_flat_partition_metadata(param)` returns the metadata for a partition, or `None` for non-ZeRO tensors.
- The metadata is exposed from the public `deepspeed.runtime.zero.flat_param_metadata` module and attached by both the standard ZeRO-1/2 optimizer and the BF16 optimizer wrapper (`bf16` + `data_types.grad_accum_dtype: fp32`, stage 1, no optimizer offload).
- `original_index` uses the parameter's original position in the optimizer group, so it remains correct when `round_robin_gradients` reorders the flat group.
- The untested-optimizer warning now points custom optimizer authors at the new API.
- The API, field semantics, padding/ordering rules, supported wrapper paths, and local-partition overlap are documented in `docs/_tutorials/zero.md`.

No optimizer behavior changes; this is opt-in introspection.

## Testing

- `tests/unit/runtime/zero/test_zero1_custom_optimizer_metadata.py` covers the single-rank layout, a two-rank partition-overlap check, BF16 wrapper metadata, and a five-parameter round-robin reordering regression.
- Manually validated with `torchrun --nproc_per_node=2`, including `round_robin_gradients=True`.
- `pre-commit` passes (flake8 run separately under Python 3.12).

Fixes #8812

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Invert the round-robin metadata index map**

When `zero_optimization.round_robin_gradients` is enabled and the group permutation is not self-inverse, `_round_robin_reorder` maps original indices to flat indices, but this lookup treats each flat index as an original-index key. For five parameters over two ranks, the flat order `[0,2,4,1,3]` is labeled `[0,3,1,4,2]`, so a custom optimizer that uses `original_index` associates shapes or state with the wrong parameters and can silently corrupt updates; invert the mapping or use `param.param_idx_in_group`.
