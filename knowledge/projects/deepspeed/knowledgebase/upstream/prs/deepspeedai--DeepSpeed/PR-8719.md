# Add ReFlow asynchronous CPU-offloaded optimizers for ZeRO-3

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8719) · state: open · merged: False

## Original PR description

Implements #8697.

This PR adds **ReFlow**, an asynchronous CPU-offloaded optimizer path for DeepSpeed ZeRO-3. The motivation and detailed design are described in #8697.

ReFlow reduces the cost of the CPU-offloaded optimizer path and overlaps the remaining host-side work with GPU backward computation.

The ReFlow design and evaluation have been **accepted to ASPLOS 2027** as *“ReFlow: Exposing Parallelism in CPU-Offloaded LLM Training via Register-Resident SIMD Fusion and Decoupled Update Scheduling.”*

Once the paper is publicly available, I will update this PR and #8697 with the paper link and publish a technical blog covering ReFlow's design, usage, and evaluation.

### What this PR adds

- ReFlow integration for ZeRO-3 CPU-offloaded training.
- ReFlow CPU Adam/AdamW and Lion optimizers.
- Fused AVX/SIMD optimizer kernels with BF16 gradient input and point-of-use FP32 promotion inside SIMD registers.
- CPU-resident gradient accumulation for intermediate micro-steps, avoiding repeated blocking H2D gradient retrievals.
- Final GPU-side accumulation and gradient-norm computation only at the terminal micro-step.
- Asynchronous bucket-wise CPU optimizer execution overlapping GPU backward.
- Ready/Persist scheduling that separates GPU-critical low-precision parameter generation from persistent FP32 optimizer-state updates.
- Gradient clipping and overflow handling without FP32 optimizer-state rollback.
- `zero_optimization.reflow` configuration.
- Unit/training tests, CI coverage, configuration documentation, and tutorial.

### Validation

ReFlow has been tested on:

- NVIDIA B200
- NVIDIA A100
- NVIDIA RTX 5080
- NVIDIA RTX A5000
- NVIDIA RTX PRO 6000
- AMD EPYC CPUs
- Intel Xeon CPUs

Correctness testing covers Adam/AdamW and Lion, gradient accumulation, gradient clipping, overflow handling, checkpointing, learning-rate scheduling, high-precision optimizer-state access, and single-/multi-GPU execution.

Under deterministic GPU execution, ReFlow produces **bit-identical training results** to the baseline.

Representative performance results:

| Workload | ZeRO-Infinity | ReFlow | Improvement |
| --- | ---: | ---: | ---: |
| OPT-30B, 1× B200 | 166.41 TFLOPS/GPU | 671.29 TFLOPS/GPU | 4.0× |
| OPT-30B, 4× B200 | 366.40 TFLOPS/GPU | 681.18 TFLOPS/GPU | 1.86× |

On a single A100 at 15B, ReFlow also achieves **1.7× higher throughput** than ZeRO-Infinity.

In the standard AdamW evaluation, separate from the clipping-heavy experiment, ReFlow reduces the exposed optimizer update tail by **more than 96.8%** across the evaluated gradient-accumulation configurations and reduces total iteration time by up to **74.3%**.

Under a separate clipping OPT-30B AdamW workload, ReFlow reduces the critical-path host update time from **2440 ms to 850 ms (65.2%)**, while requiring no FP32 optimizer-state rollback.

ReFlow is also optimizer-agnostic: with Lion, it achieves **1.6×–4.4× higher throughput** than ZeRO-Infinity-Lion across 8 to 1 GPUs.

All modified files pass the DeepSpeed pre-commit checks.

- Copilot · comment · 2026-10-01T17:32:51Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8719#discussion_r4158462090)

File: `deepspeed/runtime/reflow/reflow_stage3.py` · line 1701

`_wait_for_pending_state_updates()` catches worker exceptions and only records them for a later training-step check. Consequently, `state_dict()` continues after a failed/partial FP32 state commit and can write a corrupted checkpoint, contradicting the guarantee that checkpoint APIs observe a fully applied step. Propagate the pending worker failure before serialization, with rank-safe coordination where needed.
