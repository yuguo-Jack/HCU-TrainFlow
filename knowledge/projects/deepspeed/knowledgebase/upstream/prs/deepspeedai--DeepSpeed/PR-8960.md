# Divide SequenceTiledCompute's incoming gradient out of place

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8960) · state: open · merged: False

## Original PR description

`sequence_tiled_compute(..., output_reduction="mean")` rescales the gradient of any other term added to the same loss.

**Cause:** `SequenceTiledCompute.backward` ran `incoming_grad /= shards` on the gradient autograd passes in. For `tiled + other`, both branches receive that same tensor, so the other term's gradient was divided by `shards`.

**Fix:** divide out of place. `TiledMLP` never mutates its incoming gradient, and `TiledFusedLogitsLoss` divides its own tensor, so neither has this defect.

**Not a duplicate:** no open or closed PR or issue mentions `SequenceTiledCompute`, `sequence_tiled_compute` or `incoming_grad`.

**Test:** `DS_ACCELERATOR=cpu pytest tests/unit/ulysses_alst/test_tiled_compute.py -k "not Distributed and not TestTiledFusedLogitsLoss and not TestTiledMLP and not test_tiled_mlp" -q` on CPU only (Apple M2 Pro, torch 2.11.0). The new test sums the tiled result with `x.sum()` in both orders: it fails before (max diff 0.75) and 26 pass after. Not covered: GPU, the `DistributedTest` cases, ZeRO stages, multi-rank sequence parallelism.
