# Honor explicit dtype in ZeRO tensor constructors

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8959) · state: open · merged: False

## Original PR description

## Summary

Fixes #8948.

Honor an explicit tensor-constructor `dtype` inside `deepspeed.zero.Init`, instead of unconditionally converting floating-point results to the context's dtype.

The unconditional conversion can round an explicitly fp32 `torch.arange` to bf16 before a model computes RoPE inverse frequencies. Converting the resulting buffer back to fp32 cannot recover the lost precision.

## Changes

- Preserve a non-`None` explicit `dtype` in both the wrapped torch factory functions and the `torch.Tensor.__new__` hook.
- Keep the existing context-dtype conversion when `dtype` is omitted or `None`. Device override and parameter-partitioning behavior are unchanged.
- Document constructor dtype precedence in the `zero.Init` docstring.
- Add a regression test comparing RoPE-style frequencies against a plain PyTorch fp32 reference. It also checks explicit fp32 `torch.Tensor` construction and the existing implicit bf16 behavior for `torch.Tensor` and `torch.zeros`.

This intentionally changes dtype precedence for explicitly typed constructor calls. Such tensors may use more initialization memory than before when their requested dtype is wider than the context dtype. This is not a change to the engine's subsequent model/buffer conversion policy.
