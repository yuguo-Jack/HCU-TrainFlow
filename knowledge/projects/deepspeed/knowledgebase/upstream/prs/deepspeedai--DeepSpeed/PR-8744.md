# Add a pr-checklist agent skill and an AI contribution policy

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8744) · state: closed · merged: True

## Original PR description

## Summary

Adds a `pr-checklist` skill that agents and human reviewers can work through before opening or reviewing a PR, plus a mandatory contribution policy for AI-assisted changes. Referenced from vLLM's pr-checklist skill and AI contribution policy, and adapted to DeepSpeed's architecture and existing rules.

## Motivation

PR Review effort on this repo exceeds the bandwidth of code maintainers given AI-assisted coding becomes a norm in many scenarios, and many of the efforts are repeatedly spent on trivial PRs and bug fixes (e.g. changes that break a vendor accelerator, config or checkpoint compatibility breaks, tests that pass without exercising the new path, PRs with performance claims and no reproduction detail, and diffs carrying unrelated reformatting). Here we want to formulate the pr-checklist skill and AI contribution policy to ensure the good code quality, and make sure that code maintainers time can be spent on highly valuable PRs. 

## What's added

**`.agents/skills/pr-checklist/SKILL.md`** — four sections (design fit, testing and validation, code quality, PR contents), with the content grounded in DeepSpeed repo:

- **Core components** are taken from the path filters already encoded in `hpu-gaudi2.yml` and `xpu-max1100.yml`, which enumerate the files where a change can break a vendor accelerator.

- **Accelerator portability** covers `check-torchcuda` / `check-torchdist`,`get_accelerator()`, the "new `abstract_accelerator` method needs every subclass" trap, per-accelerator `op_builder/` entries, and the torch-free import constraint that `no-torch` enforces.

- **Compatibility** is framed as the matrix contributors actually have to reason about (ZeRO stage x offload x precision x parallelism), plus the three contracts whose breakage is silent for users: config JSON keys (deprecate via
  `DeepSpeedConfigModel`, do not rename), checkpoint load/convert paths, and the public API that downstream frameworks depend on.
- **Distributed hazards** covers peak memory as a first-class cost, host synchronization in the step, stream/event ordering on offload paths, and collective symmetry (a collective behind a rank-local condition is a hang).
- **Testing** points at `DistributedTest`, `world_size` selection that can actually observe a sharding bug, `torch_assert_close` tolerances by dtype, `reuse_dist_env` cross-test pollution, and the requirement that a test fail with the change reverted.
- **CI** documents which of the 34 workflows actually gates a given PR — vendor workflows are path-filtered or nightly, and `modal-torch-latest` runs its GPU tests in the merge queue rather than on PR push — plus `ci/tests_fetcher.py --explain` and the `DYNAMIC_EDGES` gap for monkey-patched, JIT-built, and injection-time code paths.

**Contribution policy in `AGENTS.md`** (`CLAUDE.md` is removed since Claude Code reads `AGENTS.md` directly, leaving one instruction file) — duplicate-work checks (including checking sibling implementations for a shared defect before fixing one), the proposal-first requirement for new features that `CONTRIBUTING.md` already specifies, accountability requirements for AI-assisted PRs, and fail-closed behavior.

## Design decisions

- **Canonical file under `.agents/`, with `.claude/skills/pr-checklist` as a symlink to it.** The skill is plain Markdown and useful to any agent tool or human reader; the symlink gives slash-command discovery without a second copy to keep in sync. The `AGENTS.md` pointer is what makes it discoverable to tooling that reads only the repo-root instruction file.

- **Exclude`.agents/` added to the `check-torchcuda` and `check-torchdist`.** The checklist names both banned strings in prose while documenting the hooks that ban them, which fails those hooks. This follows the existing precedent of excluding `docs/` and `docs/_tutorials/accelerator-abstraction-interface.md` for the same reason.
- **No enforcement consequences are stated.** vLLM's version warns that breaches can result in banning; that is a project governance decision, so the policy here states requirements only.

## Validation

Documentation and configuration only — no runtime code is touched, so no accelerator testing applies.

- `pre-commit run --files` passes on all five changed paths, including `check-symlinks` and `destroyed-symlinks` for the new symlink, and `check-useless-excludes` for the two modified hook excludes. Both hooks were confirmed to fail before the exclude change and pass after.
- Every repo path, workflow name, and helper symbol referenced in the checklist was verified to exist, as were the three relative links and both`CONTRIBUTING.md` anchors.
- The symlink resolves (`.claude/skills/pr-checklist/SKILL.md` is readable through it) and is stored with mode `120000`.

Note for Windows checkouts without symlink support: git may materialize `.claude/skills/pr-checklist` as a text file containing the link target. That is harmless — the `AGENTS.md` pointer and the real path under `.agents/` both still
work.
