# Use the sign bit, not -1.0f, to take sign() in the CPU Lion AVX path

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8711) · state: closed · merged: False

## Original PR description

The CPU Lion AVX path computes `sign(c) * -lr` by ANDing `c` with the bits of `-1.0f` and XORing in `-lr`. But `-1.0f` also carries exponent bits, so for `|c| < 2` the result is a value around 1e-36 instead of `+/-lr`. On AVX2/AVX512 builds, `DeepSpeedCPULion` (`"Lion"` with `offload_optimizer: cpu`) only applies weight decay, except on the scalar tail.

The fix masks with `-0.0f`, which is just the sign bit.

Test: `test_cpu_lion_matches_reference` checks each step against Lion's Algorithm 2. The existing test only compares parameter norms at 1% tolerance, so a no-op update passes it. On an AVX2 build, master fails all 6 cases (16 of 22 elements wrong, 100% at 64 and 1M). With the fix, all 6 pass.
