# Release process-group caches before CPU/Gloo worker shutdown

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8846) · state: closed · merged: True

## Original PR description

## Problem

After successful distributed teardown, DeepSpeed could retain references to destroyed process groups in its group caches. Reinitialization could then reuse a stale TP group. In the CPU/Gloo AutoEP test path, completed engines could also remain in hook cycles until interpreter finalization; native Linux reproduced a SIGABRT while a Gloo worker released Python tensor state during finalization.

This shutdown-lifetime issue is a suspected cause of the CPU/Gloo SIGABRT observed in [[this CI run](https://github.com/deepspeedai/DeepSpeed/actions/runs/38838610946/job/116773374488)](https://github.com/deepspeedai/DeepSpeed/actions/runs/38838610946/job/116773374488), which motivated this investigation. We later reproduced the same abort signature on native Linux, but without a core dump from the original run, we cannot confirm that both failures share the same root cause.

## Approach

Release DeepSpeed-owned group aliases and metadata only after backend teardown succeeds. WORLD teardown clears all owned group state, while explicit subgroup teardown removes only identity-matching entries. Note that backend failures preserve the caches, and NON_GROUP_MEMBER remains a no-op.
The CPU/Gloo test helper runs cyclic collection after a successful callback and global teardown; production teardown does not force garbage collection.

File: `deepspeed/utils/groups.py` · line 151

After a mesh subgroup is destroyed, `get_group()` raises an error while resolving its unregistered name rather than returning the destroyed group. DeviceMesh also caches group names, so this differs from the retained ProcessGroup references addressed here.
`WORLD` teardown already clears mesh_device. Simply setting `mesh_device = None` would let the helpers fall back to `WORLD` and could silently change the communication topology. I suggest handling partial DeviceMesh teardown separately.
