# Fix legacy MoE dispatch capacity agreement across expert-parallel ranks

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8940) · state: open · merged: False

## Original PR description

When expert-parallel ranks receive unequal token counts, legacy token-dropping gates can allocate different dispatch capacities before equal-split all-to-all. Dropless top-1 can also shrink the already-agreed capacity back to its local token count. This can hang both training forward and backward.

Fixes https://github.com/deepspeedai/DeepSpeed/issues/6809.

## Change

- Agree the final capacity with MAX inside the explicit EP group for top-1, top-2, and top-k, in both token-drop modes. Dropping uses the maximum configured capacity; dropless dispatch uses the maximum expert occupancy.
- Keep communication capacity separate from the existing bounded local top-k row selection. Remove the dropless top-1 local capacity clamp.
- Round capacity to the non-expert TP size because the dispatcher splits this dimension before expert execution. None/singleton EP groups continue to avoid collectives.

Routing-weight normalization, auxiliary-loss formulas, public signatures, and checkpoint/config formats are unchanged. Smaller input ranks can retain more tokens and send additional padding. Token-dropping EP adds one scalar MAX collective per MoE forward; the dropless branch still performs one MAX.

## Validation

Hardware: same-node **2 x RTX 4090 24GB**, driver **580.76.05**, torch **2.12.1+cu130**, CUDA **13.0**, NCCL **2.29.7**, Python **3.12.3**. Base: **f818504999bdd57c3e771368aefc301290020d9a**.

Before the fix, with 128/257 tokens, four experts, hidden=32, k=1, capacity_factor=1, drop_tokens=True, the actual all-to-all inputs are `(4,32,32)` / `(4,65,32)`. The training reproducer hangs and exits 124 under a 50-second timeout. After the fix, both ranks send `(4,65,32)` and complete forward, backward, and SGD update.

Before/after regression evidence:

- Capacity-contract tests: baseline **10 failed / 6 passed**; fixed **16 passed**. Covers dense/sparse outputs, both token-drop modes, k=1/2/4, and probability/position top-k selection.
- Training reference: **24 passed**. EP=2 outputs, auxiliary loss, input/gate/expert gradients, and SGD-updated parameters match a full EP=1 model using the same agreed capacity, for 128/257 and 129/129 tokens in FP32/BF16.
- TP split/gather forward and backward: baseline **8 failed / 4 passed**; fixed **12 passed**, combining the expert-TP enabled and disabled runs at EP=1, TP=2, three tokens. The failures pin odd capacity and the top-1 local clamp.

Additional DeepSpeed engine validation uses the two-layer `SimpleMoEModel` (hidden=32, four experts, SGD, ZeRO-0, no offload). It covers 24 equal-token and 24 uneven-token combinations of FP32/BF16, both drop modes, k=1/2/4, and gradient accumulation=1/4, with eight optimizer updates per combination. All updates and losses remain finite. Equal-token losses match the baseline exactly; maximum parameter differences are 1.49e-8 (FP32) and 9.77e-4 (BF16), within precision-specific tolerances. An unmodified-baseline repeat itself differs by 1.49e-8 in FP32, so no bitwise-state equivalence is claimed.

Existing MoE regression: **34 passed, 28 skipped** (four-rank cases and unavailable Tutel), including FP16 SimpleMoE at ZeRO 0/1/2, FP32 expert-gradient comparison at ZeRO 0/1/2, dense/sparse dispatch and tracing capacity tests. Changed-file pre-commit passes.

A separate two-layer **legacy MoE + SGD training microbenchmark** uses hidden=1024, FFN=4096, 16 experts, EP=2, TP=1, drop_tokens=True; 129/129 or 128/257 tokens, three warmup updates and 16 measured updates. Times are wall-clock, synchronized, using the slowest rank per step; memory is maximum PyTorch allocated memory per GPU during measured steps. This is a single run per configuration. Equal-input loss traces match baseline. The added agreement has a measured latency cost (equal-input median approximately 35–40 ms after the fix versus 31–37 ms before); it does not change equal-input peak allocated memory.

## Scope and overlap

Duplicate checks included #6809 in PR bodies and capacity/agreement/uneven/all-to-all keywords. No same-scope implementation was found. Merged #8155 bounds local top-k selection; it does not establish EP capacity agreement. #8769 changes optional route normalization; this patch leaves those formulas untouched.

The dense gate and sparse legacy MOELayer paths share this fix. Legacy inference-v1 imports TopKGate; AutoEP and inference-v2 use separate dispatch implementations and are unchanged. Tutel consumes the agreed capacity but was not installed for device testing.

EP=4, simultaneous EP=2 + TP=2, non-CUDA accelerators, Tutel, and full-model quality convergence are not validated here. The available machine has two GPUs; four-rank combinations need additional hardware.

AI assistance was used for implementation, test construction, device execution, and these notes. The human operator explicitly authorized submission and DCO sign-off using their configured Git identity.
