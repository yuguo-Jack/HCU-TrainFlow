# Size HybridEngine rollout KV caches from local prefill shapes under AutoTP

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/9008) · state: open · merged: False

## Original PR description

## Summary

Size HybridEngine rollout KV caches from each rank's own prefill KV tensors, not from the global model config. Under AutoTP, each rank holds only its share of the KV heads. Today the cache is allocated for the full model's KV-head count, so TP>1 rollout fails on all three decode paths:

| Path | TP>1 failure today | Change |
| --- | --- | --- |
| Plain graph (`_generate_graph`) | Passing batch size, device and dtype makes `DeepSpeedStaticCache` initialize from `module.config` up front, so the lazy per-layer setup never runs. The prefill copy then fails with `4 vs 2` heads, or broadcasts silently when the rank has 1 local head. | Drop those up-front arguments, so the existing lazy setup sizes each layer from the prefill tensors before capture. |
| Continuous eager (`_generate_continuous`) | The same up-front setup from config fails on the first prefill copy (`4 vs 2`, `2 vs 8`). | Create the cache lazily. `_continuous_cache_layer` initializes each layer from the prefill tensors, sized to the slot count. The slot count is the decode batch capacity, not the prefill batch. |
| Continuous graph | The graph state cache is initialized from config, and capture happens before any prefill. | Create the cache lazily and run one decode forward on the current stream before warmup, so every layer is initialized with local shapes. Without this, those tensors would be allocated on the warmup side stream. |

`lazy_initialization` gains an optional `max_batch_size`, which the continuous path uses because its capacity is the slot count. `cache_memory_bytes` is now computed after decode, once the layers exist. No model config is changed and no TP/world group is consulted, so TP×DP layouts work with no extra logic.

## Related work / scope

- #9000 / #9004 fix attention-mask construction during capture, not KV shape allocation. This PR is independent of them. For real Hugging Face model validation, #9004's runtime hunk was applied to **both** the baseline and the fixed tree.
- #8602 divides cache heads by the global world size, which breaks TP×DP (for example TP2×DP4). This fix reads the tensors directly instead of inferring the TP group.
- On Transformers 5.17, continuous eager also needs #8852 (`get_query_offset`), which is still open, so the continuous eager HF runs below apply #8852 to both baseline and fixed trees. The new unit tests use a local model and do not depend on #8852.
- **Known limitation, not changed here:** a persistent continuous graph (#8732) that contains NCCL ops makes `torch.distributed.destroy_process_group()` hang in `ProcessGroupNCCL.shutdown()` at exit. Releasing the rollout (`del` + `gc.collect()` + `synchronize()`) before destroying avoids it. Before this PR, TP>1 continuous graph could not run, so the hang was not reachable. A release/close API is left for a follow-up.

Added in 766d560: `TestAutoTPContinuousRollout` (`world_size = 2`) in `tests/unit/v1/test_hybrid_engine_rollout_v1.py`. It runs real AutoTP through `deepspeed.initialize` with `tensor_parallel.autotp_size=2` on a tiny Llama (4 KV heads, so each rank holds 2), and checks that the `k_proj` shards are actually split. It then runs continuous rollout with 3 requests on 2 slots, so a refill lands in an already allocated cache row. The tokens must equal `generate()` on the same sharded model, for both eager and graph capture.

Results on 2× NVIDIA H20, torch 2.9.0a0+50eac811a6.nv25.09, Transformers 4.57.6, Python 3.12.3:

| Tree | eager | graph |
| --- | --- | --- |
| this PR | pass | pass |
| rollout + static cache reverted to d8241a9 | `size of tensor a (4) must match ... b (2)` | `value tensor of shape [2, 2, 16] cannot be broadcast to ... [2, 4, 16]` |

Plain graph is not in this test, because real HF models need the mask fix in #9004 for that path; the TP2/TP2×DP4 plain-graph runs with #9004 are reported in the description. On Transformers versions whose `Cache` defines `get_query_offset` (5.x), the eager case skips until #8852 lands. The graph case still runs there. The test releases the rollout before process-group teardown because of the known NCCL graph teardown hang noted in the description.
