# ZeRO-3: honor stage3_max_reuse_distance for forward-gathered parameters

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/9003) · state: open · merged: False

## Original PR description

## Summary

Forward-gathered parameters were not released when `stage3_max_reuse_distance` was set to a small value. The prefetcher skips parameters that are already available and records the step at which they will be needed next; the release path then retained those parameters until that step regardless of the configured reuse distance. Because the prefetcher can scan far enough ahead to see the backward reuse of parameters gathered in the forward pass, the parameters stayed resident until backward and accumulated across layers (see #7670).

The reuse-distance scan already keeps parameters that are reused within the configured window and releases the rest, so the extra prefetch-skip retention is removed in favor of that scan for non-offloaded parameters. `stage3_max_reuse_distance: 0` now releases parameters as soon as each module's forward completes and re-gathers them during backward, trading communication for lower forward memory. The trace scan also uses each future module's own leaf-module flag when collecting its parameters.

The prefetch-skip retention is deliberately kept for NVMe-offloaded parameters: releasing one also returns its swap-in buffer, and a later on-demand fetch can then fail with no available buffer. This preserves the previous NVMe queue/buffer ordering while keeping aggressive release for parameters that stay on the accelerator.

The default (`1e9`) behavior is unchanged: parameters are still kept resident through backward.

## Testing

- New `tests/unit/runtime/zero/test_zero3_forward_parameter_release.py` covers aggressive release with prefetch enabled (fails before this change), default retention, release with prefetch disabled, and an NVMe-offload training regression test (skipped when async-io is unavailable).
- Existing ZeRO-3 tests such as `test_zero_leaf_module.py`, `test_zero_allreduce_fetch_params.py`, `test_zero_context.py`, and `test_zeropp.py` pass on CPU.
- Manually validated with `torchrun --nproc_per_node=2`.
- `pre-commit` passes (flake8 run separately under Python 3.12).

Fixes #7670

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Preserve NVMe prefetch order when releasing skipped parameters**

With ZeRO-3 NVMe parameter offload and a reuse distance shorter than the prefetch lookahead, an AVAILABLE parameter's later trace entry can already have been popped when this code releases it. Releasing also returns its swap-in buffer; an intervening parameterless backward hook can prefetch later queue entries into that buffer, so the parameter's on-demand fetch reaches `AsyncPartitionedParameterSwapper.swap_in()` with no buffer and hits its "Not enough buffers" assertion. The deleted guard explicitly prevented this queue/buffer-order divergence, so retain it for NVMe parameters or reinsert skipped entries before allowing release; none of the added tests enables parameter offload.
