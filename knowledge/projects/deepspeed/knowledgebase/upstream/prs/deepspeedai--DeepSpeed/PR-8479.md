# Recognize a norm by its shape, not by whether its class name was listed

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8479) · state: open · merged: False

## Original PR description

Fixes #8447.

## The gate

`Loading.is_load_module` decides whether AutoTP loads a module's weights from the checkpoint:

```python
def is_load_module(module):
    load_layers = [nn.Linear, nn.Embedding, nn.LayerNorm]
    load_layer_names = ["LPLayerNorm", "SharedEmbedding", ..., "MoEGate"]   # 26 names
    return module.__class__ in load_layers or module._get_name() in load_layer_names
```

A norm whose class is not on that list returns `False`, `_replace_module` skips it, and on the meta-device path its weight is never materialized. It stays on meta, and nothing is logged.

transformers defines one norm class per architecture, so a list of names can only ever cover a fraction of them. Measured by scanning every `modeling_*.py` in transformers 5.12.1 for norm classes and asking the gate about each — using **one shared RMSNorm body so only the class name differs**, which is the whole point:

| | `master` | this branch |
| --- | ---: | ---: |
| norm class names found | 336 | 336 |
| recognized | **14** | **336** |
| silently skipped | **322** | **0** |

The skipped set includes every Gemma generation, every GLM, Granite, Olmo, MiniMax, Nemotron and Zamba.

## The change

Recognize a norm by shape rather than by name: a **leaf module whose only parameter is a 1-D `weight`** (plus an optional bias) is elementwise-affine, which is exactly what `Loading.load` already knows how to copy. A bias has to be a parameter of the weight's shape: `Loading.load` copies into it as one, so a buffer or a differently shaped tensor named `bias` is refused.

The name list is left in place, so nothing that matched before stops matching.

## It admits norms and nothing else

This is the half that needed checking, and it is identical on both sides:

| | `master` | this branch |
| --- | --- | --- |
| `nn.Linear` | True | True |
| `nn.Embedding` | True | True |
| `nn.LayerNorm` | True | True |
| `nn.Conv1d` | False | False |
| `nn.MultiheadAttention` | False | False |
| `nn.Sequential` (container) | False | False |
| leaf with a 2-D `weight` | False | False |

`nn.Linear` and `nn.Embedding` carry 2-D weights and are matched by class above, so they cannot start matching by shape; a container owns no parameters of its own; and a leaf carrying anything besides `weight`/`bias` is not a plain norm.

## A sharded checkpoint

`_replace_module` gets one checkpoint file at a time, so an admitted norm's prefix can be missing from the shard in hand. BatchNorm is admitted by shape now, and its running stats are persistent buffers that still have to leave meta, so the absent-module branch calls `Loading.load_buffer(..., persistent_only=True)`. That skips non-persistent buffers (a rotary `inv_freq` is in no shard; materializing it would leave uninitialized memory where a meta tensor fails loudly on first use) and buffers registered as `None` (BatchNorm without running stats), which used to raise `AttributeError` in `load_buffer`. Callers that pass no flag behave as before, apart from the `None` case.

## Testing

`tests/unit/v1/autotp/test_autotp_custom_patterns.py`, 8 new cases, all runnable without an accelerator:

- the gate accepts a norm it has never heard of, and refuses what it refused before (2-D leaf, `Conv1d`, `MultiheadAttention`, a container, an extra parameter, a bias that is a buffer or the wrong shape);
- running `_replace_module` on a meta model with an unlisted norm, plain and biased, leaves real tensors holding the checkpoint's values, rather than only checking the gate;
- for a module absent from the shard: BatchNorm's running stats leave meta, a `None` buffer does not raise, a persistent buffer leaves meta next to a non-persistent one that stays on it.

The earlier table (336 norm class names recognized, up from 14) was measured on transformers 5.12.1 with the original revision and still holds, since the name list is untouched.

I ran the gate against `404f8172` in a clean container (torch 2.14.0+cpu, `auto_tp.py` imported from the PR tree). I wanted to check the "admits norms and nothing else" half by enumerating `torch.nn` rather than sampling it, and for weights the claim holds. Of 42 constructible classes, the ones whose verdict changes between the merge base and this branch are `BatchNorm1d/2d/3d`, `SyncBatchNorm`, `GroupNorm`, `PReLU` and torch's own `RMSNorm`. All of them are affine along dim 0, so `mp_replace.copy` replicates them, which is what you want.

The BatchNorm family is worth a second look, because it is the only newly admitted set that keeps state in buffers. When a module is admitted and its prefix is absent from the state_dict, `replace_module.py:695` and `auto_tp.py:766` take the `else: continue`, and that skips the `Loading.load_buffer` call two lines below it. That call is the only thing that moves a buffer off meta.

```
meta-init model with a BatchNorm1d child, state_dict carrying no 'norm.' key
                          running_mean.is_meta   running_var.is_meta
bb7ad0d82 (merge base)    False                  False
404f8172  (this branch)   True                   True
```

A state_dict that does not carry a prefix is ordinary once a checkpoint is sharded, since `replace_module()` loads one file into `sd` and hands that to `_replace_module`. I drove `_replace_module` directly rather than a real sharded model, so I am reporting the path and the measurement and not a user report.

The hole is the caller's, not yours. On the merge base a named rotary entry already reaches it, and `inv_freq` stays on meta at both SHAs. What your change decides is how many modules get there.

One edit keeps it in scope, and it is safe because `_is_elementwise_affine_leaf` already requires a leaf, so nothing else below the `continue` applies:

```python
    else:
        if len(child._buffers) != 0:
            Loading.load_buffer(child, state_dict, checking_key)
        continue
```

The optional-bias constraint described here is not enforced: checking only parameter names accepts a leaf whose `bias` is a buffer/tensor or a differently shaped parameter. `Loading.load` then treats that attribute as a parameter and may replace a registered buffer or copy incompatible state. Validate that a non-`None` bias is a `Parameter` with the same shape as `weight`.

File: `deepspeed/module_inject/auto_tp.py` · line None

This predicate does not constrain what `load_buffer` processes. If a module has one persistent buffer plus a non-persistent cache, the condition passes and `load_buffer` materializes both; if any registered buffer is `None`, it dereferences `None.data` and crashes. Filter individual buffers inside `load_buffer` (including skipping `None`) and make this absent-shard call process persistent buffers only.
