# Release GIL while destroying AIO handles

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8832) · state: closed · merged: True

## Original PR description

## Problem

DeepSpeed's native AIO tests can hang due to a deadlock during AIO handle destruction.

The Python thread holds the GIL while waiting for the AIO worker threads to exit. A worker may need that same GIL to release its last PyTorch tensor reference, leaving both threads waiting indefinitely.

#7727 and #8196 addressed related problems by releasing the GIL in `aio_handle.wait()` and blocking read/write calls. However, those fixes do not cover handle destruction, where the same GIL-related deadlock remains possible.

These are examples of CI workflow runs that seemed to get stuck because of this issue:
- https://github.com/deepspeedai/DeepSpeed/actions/runs/38673265097/job/116221122826
- https://github.com/deepspeedai/DeepSpeed/actions/runs/38683066926/job/116251793809

## Approach

Release the GIL around the shared AIO/GDS base handle's worker shutdown and join sequence when destruction entered with it held. Preserve the existing path when destruction already runs without the GIL.
Add a native regression test that verifies another Python thread can make progress while an AIO handle is destroyed.

This PR will mitigate the flakiness of the CI tests.
