# Fix lost TP all-reduce results for non-contiguous tensors

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8837) · state: open · merged: False

## Original PR description

## Problem
`dist.all_reduce` reduces its argument in place. Three tensor-parallel autograd functions in `deepspeed/module_inject/layers.py` call `dist.all_reduce(x.contiguous(), ...)` and then return `x`. When `x` is not contiguous, `.contiguous()` returns a copy. The reduction lands in that copy and is discarded, so the TP sum is silently skipped:

- `RowParallel.forward` (training path): the forward output is not reduced.
- `ColumnParallel.backward`: the input gradient is not reduced, e.g. when the output is transposed before the loss.
- `AsyncColumnParallel.backward`: `grad_input` comes from `matmul` and is normally contiguous, but it uses the same pattern, so it is fixed the same way.

In-tree AutoTP layers only hand these functions `matmul` / embedding outputs and their gradients, which are contiguous, so the bug is latent there today. It is hit by any caller that passes a non-contiguous tensor, such as a custom TP layer. A training-loop test through `LinearLayer` passes with or without this fix, so the regression tests target the autograd functions directly.

## Fix
Assign the contiguous tensor first, reduce it, and return it.

## Tests
`tests/unit/module_inject/test_tp_noncontiguous_reduce.py` (2 ranks) feeds a transposed input to `RowParallel` and a transposed gradient to `ColumnParallel`, and checks that the result is the sum over ranks (1 + 2 = 3).
- Before the fix: both tests fail; each rank keeps only its own value.
- After the fix: passes, together with `test_tp_shard.py` (17 passed).

Run on 2× Intel Arc Pro B70 (XPU, XCCL), torch 2.14.0.dev20260804+xpu.

Thanks. I tried this, but an AutoTP-level test cannot reach the bug, so it would not guard the fix.

In-tree, these primitives only receive freshly computed tensors: `LinearLayer` / `SubParamLinearLayer` wrap their input in `ColumnParallel`, whose backward gradient comes from `matmul`'s backward, and `LinearAllreduce` / `VocabParallelEmbedding` / `SubParamLinearAllreduce` feed `RowParallel` a `matmul` / embedding output. Those are contiguous whatever the caller does with the layer's input or output. I checked that transposed, expanded and permuted inputs and a transposed loss all still deliver a contiguous gradient to `ColumnParallel.backward`.

To confirm, I ran the suggested test (a `LinearLayer` -> `LinearAllreduce` stack over a 2-rank TP group, output transposed before the loss, input gradient compared with an unsharded reference) against the code **before** this fix:
- integration test: **passes** (cannot detect the bug)
- `test_tp_noncontiguous_reduce.py`: both tests **fail** (each rank keeps only its own value)

So the bug is latent for AutoTP layers today. It is reachable whenever these autograd functions get a non-contiguous tensor, e.g. a custom TP layer or a future caller, which is exactly the contract the primitive tests pin down. I kept the regression tests at that level, since a training-loop test would pass with or without the fix.
