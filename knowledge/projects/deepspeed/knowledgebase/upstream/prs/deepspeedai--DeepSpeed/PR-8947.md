# Sum the OPSD JSD loss in float32 for bf16 and fp16 logits

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8947) · state: open · merged: False

## Original PR description

`generalized_jsd_loss` miscounts valid tokens and mis-sizes the loss for bf16 and fp16 logits.

**Cause:** the response mask was cast to the logits dtype before `.sum()`. bf16 rounds counts above 256 (97992 becomes 97792), and fp16 overflows past 65504 (count becomes int64 max, loss goes to 0).

**Fix:** count the mask in int64 and sum the per-token JSD in at least float32. fp32 and fp64 behave as before.

**Not a duplicate:** no open or closed PR or issue touches `opsd.py` besides #8677, which introduced it. The other cross-entropy helpers already reduce in fp32.

**Test:** `pytest tests/unit/runtime/rollout/test_rollout_interface.py -q` on CPU only (Apple M2 Pro, torch 2.11.0). The new bf16/fp16 case fails before (`97792 == 97992`, `int64 max == 97992`) and 22 pass after. Not covered: GPU, ZeRO stages and offload, multi-rank aggregation.
