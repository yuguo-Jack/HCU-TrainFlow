# Keep fp32 CPU optimizer states in fp32 when loading a state_dict

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8974) · state: open · merged: False

## Original PR description

## Summary

`DeepSpeedCPUAdam`, `DeepSpeedCPULion` and `DeepSpeedCPUAdagrad` keep fp32 states for bf16/fp16 params when
`fp32_optimizer_states` is set (the default), but the `load_state_dict` they inherit from torch casts the states to
the param dtype. A resume with `bf16_master_weights_and_grads` and `offload_optimizer` (ZeRO-1/2/3, and SuperOffload
with #8972) therefore continues without an error on rounded bf16 moments and the bf16-state kernel. This PR overrides
`load_state_dict` to take these states from the saved tensors in fp32 again. Nothing changes for fp32 params or with
`fp32_optimizer_states` off.
<img width="1841" height="504" alt="image" src="https://github.com/user-attachments/assets/07ee75ae-52aa-4d81-9f15-a7a62a6d8fe7" />

## Before → after

- Right after `load_checkpoint`, all but 3 of the 131,584 elements of each moment were rounded, by up to 0.39% → the
  saved fp32 values.
- A resume against the uninterrupted run (ZeRO-1, 2 and 3, betas of 0.5): up to 1.0e-2 off → bit-identical.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Run state restoration before load-state post-hooks**

When a caller registers PyTorch's public optimizer `register_load_state_dict_post_hook`, `super().load_state_dict(...)` invokes that hook before these lines restore the moments, so the hook observes rounded bf16/fp16 state rather than the state this method ultimately installs. Likewise, if a pre-hook returns a replacement state dict, the restoration still reads the original argument and can overwrite the hook's transformed values. This affects all three new optimizer overrides, so the restoration should use the effective state dict and complete before user post-hooks run.
