# Merge final_linear shards when loading a Megatron checkpoint on fewer TP ranks

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8946) · state: open · merged: False

## Original PR description

## Problem

`MegatronSDLoader.split_state_dict` splits the vocab-parallel `final_linear.weight` (GPT-NeoX output layer) along dim 0 when a checkpoint is loaded on more TP ranks than it was saved with. `merge_state_dict` has no matching branch, so when a checkpoint is loaded on *fewer* TP ranks the key falls through to `else: new_client_sd[key] = value_list[0]` and only the first shard is kept.

Example: `final_linear.weight` of shape `[32, 8]` split to TP=2 gives two `[16, 8]` shards (correct); merging them back to TP=1 returns `[16, 8]` instead of `[32, 8]`, so the model's `load_state_dict` fails with a size mismatch. The asymmetry dates back to #1899, which added `final_linear` to the split side only.

## Fix

Add `final_linear.weight` to the dim-0 concatenation branch of `merge_state_dict`, mirroring the split side.

## Tests

New `tests/unit/checkpoint/test_state_dict_factory.py`: builds a Megatron-style checkpoint, splits it to TP=2 with `SDLoaderFactory`, merges the shards back to TP=1, and asserts every key equals the original tensor.

```
DS_BUILD_OPS=0 pytest tests/unit/checkpoint/test_state_dict_factory.py
```

- `main`: fails with `AssertionError: final_linear.weight`
- this PR: passes

Ran on macOS (Apple Silicon) CPU only, no accelerator, torch 2.15.0, Python 3.13. pre-commit passes on the changed files.

## Scope / validation

- Pure state-dict manipulation; no numerics, performance or memory impact.
- Covers whole-model `mp_rank_*` checkpoints. The PipelineModule per-layer path is not changed (there, `sanity_check(ckpt_list[0])` already rejects a layer file that only holds `final_linear`, a separate issue).
- Not validated on GPU, or with ZeRO / offload / quantized (`quantize=True`) loading. The quantize path is unaffected, since the quantizer only applies to `mlp.dense_h_to_4h.weight` in this branch.

## Duplicate check

Searched open PRs and issues for `final_linear`, `state_dict_factory`, `MegatronSDLoader`, `merge_state_dict`: no existing work. No open PR touches `state_dict_factory.py`.

AI assistance was used to prepare this change; I reviewed the diff and ran the tests above.
