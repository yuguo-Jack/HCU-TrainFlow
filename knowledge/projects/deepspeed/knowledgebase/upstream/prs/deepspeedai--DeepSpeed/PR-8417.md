# Log the skipped optimizer step on gradient overflow

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8417) · state: closed · merged: True

## Original PR description

ZeRO returns early from `step()` on non-finite gradients. `DynamicLossScaler` reports that from inside `update_scale`, but `CreateLossScaler` only returns it for `fp16 + dynamic_scaling` — bf16 and fp32 always get the static `LossScaler`, whose `update_scale` is an inherited no-op.

The skip is counted in `engine.skipped_steps`, but that is only surfaced by `_report_progress`, gated on `steps_per_print`, and `STEPS_PER_PRINT_DEFAULT` is `None`. So on a default bf16 config the loop advances, the LR scheduler steps and metrics are emitted while no weights are updated, with no output at all.

Fixes #8415

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Emit the overflow warning only from rank zero**

In any multi-rank ZeRO-1/2 run, overflow is all-reduced before this block, so every process enters it and `logger.warning()` emits one warning per rank for every skipped step. This can multiply repetitive output by the world size and overwhelm logs during sustained non-finite gradients; use the same rank-zero guard as `DynamicLossScaler` (or `log_dist(..., ranks=[0])`).
