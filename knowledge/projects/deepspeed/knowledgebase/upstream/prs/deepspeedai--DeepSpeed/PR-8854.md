# Scale ZeRO-3 __avg_scatter_grads by sequence_parallel_size

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8854) · state: open · merged: False

## Original PR description

## Summary

Fixes #8692.

In `DeepSpeedZeroOptimizer_Stage3`, `__avg_scatter_contiguous_grads` (`stage3.py:1877`) and `allreduce_bucket` (`stage3.py:2278`) both divide the gradient averaging world size by `float(self.sequence_parallel_size)`, matching ZeRO-0 (`engine.py:3884`) and ZeRO-1/2 (`stage_1_and_2.py:1505, 1687, 2379`).

However, `__avg_scatter_grads` (`stage3.py:1936-1940`) delegates to `reduce_scatter_coalesced` (which divides by `partition_world_size`) and only rescales when `averaging_world_size != partition_world_size` without accounting for `self.sequence_parallel_size`:

```python
partition_world_size = dist.get_world_size(group=process_group)
averaging_world_size = self._gradient_averaging_world_size(
    params_to_reduce, partition_world_size) / float(self.sequence_parallel_size)
if averaging_world_size != partition_world_size:
    scale = partition_world_size / float(averaging_world_size)
    grad_partitions_for_rank = [g.mul(scale) for g in grad_partitions_for_rank]
```

Without this division by `float(self.sequence_parallel_size)`:
1. Under `sequence_parallel_size > 1`, ZeRO-3 with `reduce_scatter=True` or `contiguous_gradients=False` produces gradients smaller by a factor of `sequence_parallel_size` than `reduce_scatter=False, contiguous_gradients=True` or ZeRO-1/2.
2. Even within a single ZeRO-3 model using `reduce_scatter=False, contiguous_gradients=True`, parameters whose size exceeds `reduce_bucket_size` fall back to `__avg_scatter_grads` (`stage3.py:1686`), while smaller parameters use `__avg_scatter_contiguous_grads` (`stage3.py:1683`), causing different layers of the same model to receive gradients scaled by `1 / sp_size` vs `1.0` in the same backward step.
