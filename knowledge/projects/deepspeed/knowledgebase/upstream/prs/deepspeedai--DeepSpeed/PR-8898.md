# Complete ZeRO-3 serial checkpoint handoff for universal loads and rank boundaries

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8898) · state: open · merged: False

## Original PR description

Fix ZeRO-3 serial checkpoint token handoff for valid Universal Checkpoint loads and non-default DP groups. Universal loading currently receives a token without forwarding it; legacy loading can use a DP-group rank as a global destination and can cross a local launcher boundary.

Use the shared handoff helper for legacy and universal loaders, forward to the next global rank, and stop at the launcher-local boundary. Legacy temporary checkpoint state is released before the send. No public signature, checkpoint format, or training arithmetic changes.

This is independent of #8897's rejection regression. Merged #8891 supplies DP-size preflight; this PR retains that implementation and fixes successful loads. #8892's neighboring restoration changes remain separate.

Published follow-up on 2026-10-30 (`36246fed`), integrating master `9148ab22` in the existing PR branch:

- Capture accelerator device count before deleting launcher metadata in the fallback test, avoiding a CPU runner changing its inferred local size during the load.
- Add a four-rank legacy checkpoint round trip using DP groups `[0,2]` / `[1,3]` and model groups `[0,1]` / `[2,3]`. It verifies exact model weights, FP32 masters, Adam moments/counters and engine step after restore, then compares the next loss and actual parameter update against uninterrupted training.
- The four-process MPU topology exercises checkpoint group/rank addressing with SimpleModel; it is not a tensor-parallel model-training or multi-node validation claim.

Validation: Apple M3, macOS 15.1 ARM64, Python 3.12.13, torch 2.14.1, CPU/Gloo:

```sh
DS_ACCELERATOR=cpu CUDA_VISIBLE_DEVICES=0,1,2,3 LOCAL_SIZE=4 GLOO_SOCKET_IFNAME=lo0 OMP_NUM_THREADS=1 PYTHONPATH=.:tests python -m pytest --forked tests/unit/checkpoint/test_universal_checkpoint.py::TestZeRO3SerialUniversalCheckpoint tests/unit/checkpoint/test_zero_optimizer.py::TestZeROCheckpoint::test_serial_checkpoint_with_launcher_topology tests/unit/checkpoint/test_zero_optimizer.py::TestZeROCheckpoint::test_serial_checkpoint_with_nondefault_dp_groups --torch_ver=2.14.1 -q
```

**9 passed**: four Universal Checkpoint cases, four launcher/fallback cases, and the four-rank non-default-DP round trip. All applicable changed-file pre-commit hooks pass.

Negative control: reverting only the helper's token-destination rank to the DP-group rank makes the four-process regression hang. The pytest timeout plugin reports a timeout/internal error at 25 seconds, and the external process-group deadline terminates the run at 75 seconds (exit 124). This is a timeout observation, not an ordinary assertion failure. The production helper was restored in `finally`; the exact four-process test then passes again.

Historical validation on the original revision: 2×RTX 3090 24 GiB, driver 580.105.08, Python 3.12.3, torch 2.12.1+cu130, CUDA 13.0, NCCL 2.29.7; nine targeted cases passed, and the unchanged baseline reproduced Universal serial timeout and invalid global destination. A separate four-rank CPU reproducer exposed the legacy self-send. Those GPU results predate #8891 and do not validate this local integration/follow-up.

Real CUDA/NCCL reruns of the updated tests, actual multi-node, four-GPU TP/DP, MoE, NVMe and vendor accelerators remain unvalidated. No throughput, convergence or peak-memory improvement is claimed. Arbitrary I/O/rank failures and recovery protocols are outside this patch.

AI assistance (OpenAI Codex) was used for investigation, implementation and validation. The submitting human confirmed reviewing the final diff and running the relevant tests, and authorized DCO sign-off and publication of `36246fed`.
