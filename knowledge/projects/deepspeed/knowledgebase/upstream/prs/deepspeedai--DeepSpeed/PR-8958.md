# [VocabTP] Add vocabulary-parallel generalized JSD with Triton kernels

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8958) · state: open · merged: False

## Original PR description

## Motivation

Teacher-student training compares the models' next-token distributions, not
just the probability of a single ground-truth token. DeepSpeed already offers
vocabulary-parallel forward/reverse KL, but does not support the interior
`0 < beta < 1` generalized Jensen-Shannon divergence used by GKD-style
distillation. Applying a local softmax independently on each vocabulary shard
does not compute the intended full-vocabulary objective.

TRL currently has two relevant implementations on its main branch:
`experimental.GKDTrainer` computes generalized JSD from materialized logits;
`DistillationTrainer` uses completion filtering and tiled LM-head projection
to compute KL/JSD without materializing full logits. Those implementations do
not call DeepSpeed's vocabulary-parallel divergence ops. In particular,
support for DeepSpeed/ZeRO or FSDP parameter sharding is not itself support
for a vocabulary-parallel softmax and divergence.

This PR supplies the missing Core logits-based primitive, as a building block
for teacher-student workloads and a possible subsequent TRL integration. It
does not claim to integrate TRL or replace its memory-efficient tiled loss.
Refs #8790.

## Changes

- Add `vocab_parallel_jsd(student_logits, teacher_logits, beta=0.5,
  tp_group=None)`, returning FP32 per-token divergence replicated on TP ranks.
- Add fused Triton paired softmax statistics, divergence and backward kernels.
  Reuse global normalization and reduce the two KL-to-mixture expectations
  together. Recompute probabilities in registers during backward rather than
  retaining full FP32 probability tensors; keep bounded eager chunks as fallback.
- Enable JSD on an active Intel Triton backend without changing XPU's global
  Triton capability flag or existing-op dispatch.
- Support gradients to both inputs, detached teachers, uneven vocabulary
  shards, empty local shards, and non-contiguous causal-shift views.
- Preserve the existing Core convention: beta=0 selects forward KL and beta=1
  selects reverse KL. These are explicit endpoint branches, not continuous
  limits of the weighted interior JSD.
- Leave temperature, optional T-squared scaling, masking and normalization to
  the caller, following the existing vocabulary-parallel per-token ops.

## Not a duplicate

- #8791 / #8838 implement logprobs, entropy and forward/reverse KL, not
  interior-beta generalized JSD. The new API reuses their KL endpoints.
- #8947 fixes counting and accumulation in the existing dense rollout loss.
  This PR does not edit `runtime/rollout/opsd.py` or its tests.
- DeepSpeedExamples#1019 integrates vocabulary-parallel KL into OPSD. This PR
  does not change Examples, cache handling, rollout or trainer integration.
- #8945 connects fused-linear CE to HF forward. This PR is independent of it:
  no LM-head projection changes or loss-function hooks.

## Scope and limitations

This is a new opt-in logits-based API; existing ops and training defaults are
unchanged. Unlike the existing single-pass KL forward, JSD needs global
normalization before evaluating the nonlinear mixture: statistics and
divergence are two input passes. It still consumes materialized local logits.
Top-k restriction, pointwise
clipping, differing student/teacher shard layouts, fused-linear divergence,
DeepCompile support and automatic TRL integration are not included.

Every TP rank must supply identically ordered student/teacher vocabulary
shards and backpropagate the same replicated per-token loss.

## Validation

Hardware: up to 4 Intel Arc Pro B70 GPUs, XCCL, driver 1.15.39122+11,
torch 2.14.0.dev20260804+xpu, Intel Triton 3.8.0. Final validation: **67 CPU
regressions passed, 11 fused XPU cases passed, and 4 distributed cases passed
at each of TP1/2/4**. Existing entropy/KL Triton-only tests still skip on XPU
because their accelerator-wide flag remains disabled; JSD uses its own checked
Intel backend dispatch. The final TP cases cover FP32/BF16 interior JSD versus
an FP64 oracle, empty shards/disjoint support, and head SGD update parity.

On NVIDIA L20, driver 580.173.02, torch 2.14.1+cu130 (CUDA 13.0),
Triton 3.8.0, NCCL: the **full test file passed, 113 passed with no skips**.
This includes all JSD TP1/2/4 cases and FP32/FP16/BF16 single-device kernels.
The existing `ds` conda environment was used without dependency changes;
tested source hashes match the local implementation and tests.

Scoped pre-commit hooks and diff checks pass. Numerical checks use an
independent FP64 dense PyTorch reference, nonuniform vocabulary partitions,
FP32/BF16, both-input gradients and frozen inputs. Additional cases cover
disjoint support, undefined masked rows, empty local shards, empty token
batches, causal-shift views, independent large logit shifts and row chunking.
Three SGD updates of a sharded head match the dense reference at TP1/2/4.
This head-only training test does not exercise a DeepSpeed Engine or ZeRO.

Exploratory logits-only forward+backward A/B on B70, N=1024,
V=151936, BF16, beta=0.3, frozen teacher:

|---|---|---:|---:|
| 2 | Gather both logits, dense PyTorch JSD | 6.671 | 112.17 |
| 2 | Vocabulary-parallel eager JSD | 1.057 | 58.38 |
| 2 | Vocabulary-parallel Triton JSD | 0.435 | 3.08 |
| 2 | Existing Triton reverse KL | 0.435 | 3.29 |
| 4 | Vocabulary-parallel eager JSD | 0.841 | 31.14 |
| 4 | Vocabulary-parallel Triton JSD | 0.217 | 3.41 |
| 4 | Existing Triton reverse KL | 0.217 | 3.16 |

Five warmups and ten measured trials, synchronized wall time; per-trial MAX
over TP ranks, independently for time and memory. Resident input allocations
are included in peak. Student gradients are included. All arms start with sharded logits, and the dense arm includes
their gather; it is not TRL's existing chunked-projection implementation.
Losses and local student gradients match before timing. Clocks were not
pinned. This benchmark excludes head projection, backbone, optimizer and
rollout; it demonstrates only an op-level comparison, not full-training or
TRL speedup. Reproduction script and raw JSON/logs are retained locally and
should be attached to the PR when submitted. KL's Triton kernels are enabled
only in the XPU benchmark for comparison; their production dispatch is unchanged.
