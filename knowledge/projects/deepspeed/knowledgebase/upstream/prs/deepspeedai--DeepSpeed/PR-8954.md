# Retire stale checkpoint artifacts after replacing a ZeRO export

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8954) · state: open · merged: False

## Original PR description

Fixes #8952.

Repeated conversion into one output directory can leave a stale index that selects the previous checkpoint, even when the newly written single file contains the correct weights. This fix keeps the directory consistent with the successful latest export.

## Change

After all new shards and the optional index have been written, remove obsolete standard converter output names: the PyTorch/safetensors single files, indexes and exactly numbered shard filenames. Preserve the files in the new export, unrelated configuration/tokenizer/backup files, and directories.

Both serialization formats are considered: retaining old safetensors while writing new PyTorch weights (or vice versa) can let format preference select stale weights. No general prefix deletion or directory clearing is used.

The existing converter and tutorial document replacement behavior. Users retaining multiple variants should use separate output directories.

This does not make export transactional: a failed write may already have overwritten same-name files. Cleanup does not begin until serialization/index writing succeeds; concurrent export/loading is outside the supported scenario. No checkpoint input format, dtype conversion, reconstruction algorithm or public signature changes.

## Sibling paths and duplicate check

The legacy FP32 API and dtype-selectable API/CLI share this output writer. ZeRO-1/2 use one reconstruction path and ZeRO-3 another before converging here. Both output formats are covered. In-memory recovery APIs are unchanged.

No matching open replacement fix was found in live issue/PR searches. #8376 covers tied safetensors, #8378 frozen dtype, #8530 debug behavior, #8681 BF16 stage 0, #8901 legacy serialization, and #6655 reconstruction parallelism. #8501 concerns source-tag selection, while this bug is stale output selection; #8502 concerns loading full training state. None of those changes is included here.
