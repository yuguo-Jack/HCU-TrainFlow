# Build CPU optimizer ops without CUDA and fix the CPU Lion SIMD update

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8813) · state: closed · merged: True

## Original PR description

`cpu_adam`, `cpu_adagrad` and `cpu_lion` have had no CUDA code since #5409, but on CUDA systems they were still built through `TorchCPUOpBuilder`, which links CUDA libraries and checks the installed CUDA toolkit version. This caused CPU Adam build failures such as `cannot find -lcurand` (#5677). As suggested, this PR builds them as plain CPU (C++) extensions without CUDA dependency.

Fixes #5677. Related: #4768 (its "cuda is missing" warning came from `get_cuda_compile_flag()`, removed here).

## Changes
- CPU Adam/Adagrad/Lion now use the `CPUOpBuilder` builders in `op_builder/cpu` on CUDA systems as well. `TorchCPUOpBuilder` and its top-level builders are removed; `async_io` and `dc` now derive from `CUDAOpBuilder`. CPU Lion is also registered for the CPU accelerator.
- Fix CPU Lion on AVX2/AVX-512: the sign mask was `-1.0f` instead of `-0.0f`, so vectorized elements got an almost-zero update instead of ±lr. Add a reference test covering every SIMD path.
- If a CPU optimizer op fails to build/load, raise one `RuntimeError` naming the op, with the build error as its cause. `DeepSpeedCPUAdagrad`/`DeepSpeedCPULion` no longer add a misleading `AttributeError` from `__del__`.
- Skip `TestCPULionGPUError` on the CPU accelerator.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Preserve C++20 flags for CPU optimizer builds**

When running with PyTorch 2.12 or newer, routing these three builders through `op_builder.cpu` drops the `-std=c++20` selection inherited from the former `TorchCPUOpBuilder`; `CPUOpBuilder.cxx_args()` supplies no language-standard flag, while the repository’s CUDA and MPS builders explicitly select C++20 for these PyTorch versions. Consequently, JIT or precompiled CPU Adam, Adagrad, and Lion extensions on CUDA installations can be compiled under the extension toolchain’s older/default standard and fail against PyTorch 2.12 headers. Add the same version-dependent C++ standard selection to `CPUOpBuilder` before redirecting these builders.

- hwchen2017 · comment · 2026-10-13T06:49:43Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8813#discussion_r4255561263)

File: `accelerator/cuda_accelerator.py` · line 385


`CPUOpBuilder` intentionally passes no `-std` flag, so PyTorch supplies the standard it requires:

- **JIT** (`torch.utils.cpp_extension.load`): the base flags include `-std=c++20` on PyTorch 2.12+.
- **Prebuilt** (`BuildExtension`): `-std=c++20` is appended when the extension passes no `-std` flag.

The CUDA and MPS builders need a version switch only because they hardcode `-std=c++17`, which overrides PyTorch's default (the failure in #8235). Hardcoding a standard in `CPUOpBuilder` would duplicate PyTorch's choice and need updating whenever PyTorch raises it.
