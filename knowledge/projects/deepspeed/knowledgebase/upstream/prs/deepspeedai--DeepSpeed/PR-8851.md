# [AutoTP] Support frozen AutoTP models and manage AutoTP mode per model

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8851) · state: open · merged: False

## Original PR description

## Summary

Two bugs show up when a frozen teacher runs next to an AutoTP student in one process, as in on-policy distillation (deepspeedai/DeepSpeedExamples#1019, #8850).

**1. Frozen replicated parameters break `deepspeed.initialize`.**
`register_replicated_grad_hooks` registers a gradient all-reduce hook on every replicated (non-TP) parameter. PyTorch refuses hooks on tensors with `requires_grad=False`, so a fully or partially frozen model fails during `initialize`.
- Frozen params are now skipped. They get no gradient, so their TP replicas cannot diverge.
- To keep that guarantee, the engine remembers which replicated params were frozen at `initialize`. If any of them becomes trainable later, the next backward raises a clear error instead of letting TP replicas drift apart silently.

**2. The AutoTP training mode leaks into `init_inference`.**
`deepspeed.initialize` with AutoTP sets a process-global training-mode flag. A teacher passed to `deepspeed.init_inference` afterwards still sees training mode. As a result:
- it is sharded with the student's TP group instead of its own `tp_size`;
- its LM head is not handled as for inference;
- its parameters are left trainable.

The fix makes the mode per model instead of process-wide:
- `AutoTPMeta`, which AutoTP already passes to every layer it builds, gains a `training` field. AutoTP fills it from its `training_mode` argument, which `deepspeed.initialize` sets to `True` and `init_inference` to `False`.
- Each `TensorParallel_Layer` takes its mode from `tp_meta`, so the forward path (`RowParallel`, `add_bias`) follows how that model was sharded. The student keeps training-mode behavior after the teacher is built, and vice versa.
- `AutoTP.set_tensor_parallel_config` and `replace_transformer_layer` (kernel injection, `set_lm_head`, MP checkpoint saving) use the explicit `training_mode` instead of the global flag.
- Backward compatibility: `AutoTP(training_mode=None)` (the new default) and layers built without `tp_meta` still follow `set_autotp_mode`, so existing direct callers behave as before.

## Related work

I searched open and closed PRs and issues for `register_replicated_grad_hooks`, `AUTOTP_MODE` and frozen AutoTP models, and found no existing fix. Reported while integrating #1019.

Sibling paths checked:
- Every `is_autotp_training_mode()` reader in `deepspeed/`: `auto_tp.py` (`set_tensor_parallel_config`) and `replace_module.py` (kernel injection, `set_lm_head`, MP checkpoint saving) now use the explicit mode; the remaining reads are the fallbacks for callers that pass no mode.
- All `AutoTP(...)` call sites in `deepspeed/` (engine, `TpTrainingManager`, `InferenceEngine`) already pass `training_mode` explicitly. No code in `deepspeed/` builds TP layers outside AutoTP.
