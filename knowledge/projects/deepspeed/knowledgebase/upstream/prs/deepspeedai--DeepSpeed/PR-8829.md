# AutoEP + AutoTP folding: allow CPU optimizer offload under ZeRO-3

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8829) · state: open · merged: False

## Original PR description

### Summary

#8670 left optimizer and parameter offload rejected for AutoEP + AutoTP folding ("not validated yet ...
run a follow-up proof for per-family replica groups"). This PR provides that proof for ZeRO-3 with the
optimizer offloaded to the CPU, and accepts that configuration:

```json
{
  "zero_optimization": {"stage": 3, "offload_optimizer": {"device": "cpu"}},
  "tensor_parallel": {"autotp_size": 2},
  "expert_parallel": {"enabled": true, "autoep_size": 2}
}
```

Everything else stays rejected, now with a message that names the unsupported part: optimizer offload
with ZeRO stages 1 and 2, NVMe optimizer offload, parameter offload, and Muon with optimizer offload.
An explicit `"device": "none"` is treated as no offload (it was rejected before).

### Why ZeRO-3 + CPU optimizer offload is already correct

- ZeRO-3 applies the folded per-family gradient correction (`_apply_autoep_folding_tp_correction`:
  AVERAGE for TP-replicated parameters, `/tp_size` for routed experts, SKIP for TP-sharded ones) in
  `reduce_independent_p_g_buckets_and_remove_grads`, before every reduce-scatter. That path is the same
  with and without offload; offload only changes where the reduced partitions are stored.
- The offloaded norm (`complete_grad_norm_calculation_for_cpu_offload`) uses the same folding-aware
  counting as the device norm (`_grad_norm_counts_every_rank` plus the expert-parallel all-reduce), from
  per-partition norms recorded at the accumulation boundary.

The test below checks the claim end to end instead of relying on this reading.

### Changes

- `validate_folding_global` / `validate_autoep_config`: take the offload **devices** instead of
  "offload configured" booleans (`offload_optimizer_device`, `offload_param_device`); accept stage 3 +
  `"cpu"`; reject the rest as above. Internal helpers; the two in-repo callers are updated.
- `DeepSpeedEngine`: passes the configured devices.
- ZeRO-3: rejects Muon with optimizer offload under folding. The offloaded Muon update gathers full
  gradients on its own path, which this PR does not validate (and which overlaps ongoing Muon offload work).
- Docs: the AutoEP folding constraint in `autoep.rst`.

### Tests

- `test_autoep_autotp_folding_config.py`: accepted and rejected offload combinations (replaces the
  blanket-rejection test; the duplicate in `test_autoep_autotp_grad_parity.py` is removed).
- `test_autoep_autotp_sharded_attention.py`, new `TestFoldedZero3ClippedUpdate`: reuses #8670's
  per-gradient comparison against an unfolded ZeRO-0 reference and adds one clipped SGD step. For each
  of 4 folding shapes (world 4; TP x EP = 2x2, 2x4, 4x2, 4x4), `zero.Init` on/off, and offload on/off,
  it compares losses, every gradient, the global norm, and every parameter's update. Clipping (clip
  1e-2, lr 1/clip) makes the update depend on the norm the optimizer computed, so a wrong offloaded norm
  fails the test; the comparison allows one fp32 ulp of the parameter for recovering an update as
  `after - before`, and asserts that a 0.1% error in the update is still detected.

### Compatibility matrix

Validated: ZeRO-3 x optimizer offload {none, cpu} x `zero.Init` {off, on} x fp32 x folding TP {2, 4}
x EP {2, 4} (world 4), torch SGD on the offloaded CPU fp32 partitions.

Not validated (and either rejected or left unchanged): DeepSpeedCPUAdam's offloaded step (the tests run
torch SGD on the CPU fp32 partitions with `zero_force_ds_cpu_optimizer: false`; DeepSpeedCPUAdam steps
the same partitions but through its own kernel), bf16/fp16 with offload, 8-rank shapes, NVMe offload
(rejected), parameter offload (rejected), ZeRO-1/2 optimizer offload (rejected; its offloaded norm path is
being changed by #8823), Muon with offload (rejected).

### Not a duplicate

No open or merged PR enables offload with AutoEP + AutoTP folding (searched "folding offload",
"AutoEP offload", "AutoTP offload"). #8823 fixes ZeRO-1/2 routed-expert clipping under folding and does not
touch ZeRO-3 or offload; ZeRO-1/2 offload is left rejected so the two do not interact. Tracked in the
Q4 roadmap #8672 (AutoEP + AutoTP folding milestone).
