# Fix comms logger IndexError when the tensor is passed by keyword

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8998) · state: open · merged: False

## Original PR description

## Summary

With the comms logger enabled, profiling a collective whose input tensor is passed by keyword after other positional args raises `IndexError`:

```python
dist.all_gather_into_tensor(output, tensor=input)  # IndexError: tuple index out of range
```

`get_msg_size_from_args` (`deepspeed/comm/utils.py`) reads `args[get_tensor_position(func)]` whenever any positional arg is present. For `all_gather_into_tensor(output_tensor, tensor, ...)` the tensor's position is 1, but only one positional arg was passed. `reduce_scatter_tensor` has the same signature shape.

The fix reads the positional slot only when it exists. Otherwise the existing kwargs lookup (`get_tensor_kwarg`) finds the tensor, so the message size is recorded correctly. Calls that already worked behave the same.

## Test

New test `test_profiled_op_accepts_tensor_passed_by_keyword` in `tests/unit/comm/test_comms_logger.py`. It calls `comm.all_gather_into_tensor(output, tensor=input)` with profiling on and the backend replaced by a mock, following the existing tests in that file. It checks that the recorded size is the input tensor's size (16 bytes), not the output's.

```
$ cd tests && pytest unit/comm/test_comms_logger.py -k "not Latency"
# without the fix (new test only)
FAILED unit/comm/test_comms_logger.py::test_profiled_op_accepts_tensor_passed_by_keyword - IndexError: tuple index out of range
# with the fix
56 passed, 1 deselected
```

`TestCommsLoggerLatency` was deselected because it needs 2 devices. `pre-commit run --files deepspeed/comm/utils.py tests/unit/comm/test_comms_logger.py` passes.

Hardware: CPU only (ARM Neoverse-N1, 4 cores, no accelerator), Python 3.10, torch 2.14.1+cpu.

## Scope and compatibility

- Only the comms logger's message-size lookup changes, and it only runs when comms profiling is enabled. It is independent of ZeRO stage, offload, precision and parallelism. No training or collective runs were done; none of those matrix cells were exercised.
- Sibling paths: `get_msg_size_from_args` is the only caller of `get_tensor_position`/`get_tensor_kwarg`, and its only caller is `timed_op` in `deepspeed/comm/comm.py`, so there is no other copy of this logic to fix.

## Duplicate check

- `gh pr list --state all --search get_msg_size_from_args` returns nothing.
- No open PR touches `deepspeed/comm/utils.py`. Open comms-logger PRs change `comms_logging.py`, `timer.py` or `comm.py`, not this lookup.
- No issue reports this error.

AI assistance was used to help find the issue and draft the change. I reviewed every changed line and ran the tests above.
