# Fix BF16 full-gradient updates to use the accumulation buffer

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8856) · state: open · merged: False

## Original PR description

`safe_set_full_grad()` currently writes BF16's staging `param.grad`, but `BF16_Optimizer` steps from its separate accumulation buffer. Gradient masking between backward and step is silently ignored. With immediate accumulation enabled, a parameter spanning optimizer partitions instead raises a shape error.

I changed the setter to write the existing full accumulation buffer, matching the getter's BF16 detection. The ordinary-gradient and ZeRO partitioned-gradient branches are unchanged. The regression runs two real data-parallel ranks, both accumulation modes, BF16 ZeRO-1 and the ZeRO-2 sibling path, matrix and bias parameters, two accumulated microbatches, and zero/nonzero replacement gradients. It checks the public getter and SGD parameter updates.

### Reproduce on CPU without compiling DeepSpeed ops

Save this as `repro.py` and run from the checkout:

```python
import argparse
import os

import torch
import deepspeed
import deepspeed.comm as dist
from deepspeed.utils import safe_get_full_grad, safe_set_full_grad, safe_get_full_fp32_param

parser = argparse.ArgumentParser()
parser.add_argument('--immediate', action='store_true')
args = parser.parse_args()
# Use PyTorch/Gloo instead of building DeepSpeed's optional CPU communication op.
deepspeed.ops.__compatible_ops__ = {'deepspeed_shm_comm': False}
if 'RANK' not in os.environ:
    os.environ.update(RANK='0', LOCAL_RANK='0', WORLD_SIZE='1', MASTER_ADDR='127.0.0.1', MASTER_PORT='29643')
deepspeed.init_distributed(dist_backend='gloo')

class Model(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.weight = torch.nn.Parameter(torch.ones(4))

    def forward(self, x):
        return (self.weight * x).float().sum()

config = {
    'train_micro_batch_size_per_gpu': 1,
    'zero_optimization': {'stage': 1},
    'bf16': {'enabled': True, 'immediate_grad_update': args.immediate},
    'data_types': {'grad_accum_dtype': 'fp32'},
    'optimizer': {'type': 'SGD', 'params': {'lr': 0.1}},
    'zero_allow_untested_optimizer': True,
}
engine, _, _, _ = deepspeed.initialize(model=Model(), config=config)
engine.backward(engine(torch.arange(1, 5, dtype=torch.bfloat16)))
param = engine.module.weight
try:
    safe_set_full_grad(param, torch.zeros(4, dtype=torch.float32))
    replacement = safe_get_full_grad(param).tolist()
    engine.step()
    weights = safe_get_full_fp32_param(param).tolist()
    if dist.get_rank() == 0:
        print('OPTIMIZER', type(engine.optimizer).__name__)
        print('GRAD_AFTER_SET', replacement)
        print('WEIGHT_AFTER_STEP', [round(x, 6) for x in weights])
except Exception as exc:
    print(f'RANK {dist.get_rank()} ERROR {type(exc).__name__}: {exc}')
finally:
    engine.destroy()
    dist.destroy_process_group()
```

```bash
OMP_NUM_THREADS=2 DS_BUILD_OPS=0 DS_ACCELERATOR=cpu PYTHONPATH="$PWD" python repro.py
OMP_NUM_THREADS=2 DS_BUILD_OPS=0 DS_ACCELERATOR=cpu PYTHONPATH="$PWD" python -m torch.distributed.run --standalone --nproc_per_node=2 repro.py --immediate
```

| Observed result | Before | After |
| --- | --- | --- |
| One rank, gradient after setting zeros | `[1.0, 2.0, 3.0, 4.0]` | `[0.0, 0.0, 0.0, 0.0]` |
| One rank, master weights after SGD | `[0.981743, 0.963485, 0.945228, 0.92697]` | `[1.0, 1.0, 1.0, 1.0]` |
| Two ranks, immediate accumulation | `RuntimeError: shape '[4]' is invalid for input of size 2` | Zero gradient; weights remain `[1.0, 1.0, 1.0, 1.0]` |

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Route vectorized BF16 updates through the accumulation buffer**

When `BF16_Optimizer` uses the default `immediate_grad_update=False`, callers of the exported `safe_update_full_grad_vectorized()` do not get this new precedence: its loop at `deepspeed/utils/tensor_fragment.py:357-358` still sees the non-`None` BF16 staging `p.grad` and copies only there, while the optimizer steps from `_hp_grad`. Vectorized masks or edits therefore remain silently ignored under the same configuration fixed here; route that helper through the accumulation buffer as well and cover this public sibling API.

Fixed in the follow-up commit: `safe_update_full_grad_vectorized()` now gives `_hp_grad` the same precedence as `safe_set_full_grad()`. The callback gets the full gradient from `safe_get_full_grad()` and the result goes into `_hp_grad`. I parametrized the existing two-rank test over the setter and the vectorized API (ZeRO-1/2, both `immediate_grad_update` modes); it checks the callback input, the getter after the update and the SGD step. The two BF16 vectorized cases fail without the change, and the reconstruction class plus the CPU tensor-fragment cases pass (20 passed, 3 FP16 skipped). I also noted in zero3.rst that the parameter order must match on every rank.
