# [AutoSP] Align cross entropy targets after an in-model causal label shift

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8811) · state: open · merged: False

## Original PR description

> **Stacked on #8457.** Only the last commit (`6f7c57b9a`) belongs to this PR; please review that commit. I will rebase once #8457 is merged.

Addresses https://github.com/deepspeedai/DeepSpeed/pull/8457#discussion_r4243588078 (in-model causal label shift under AutoSP).

### Problem
AutoSP shards the labels the same way as `input_ids`. A causal LM that shifts its labels inside the model (Hugging Face `ForCausalLMLoss` pads and shifts, `labels = F.pad(labels, (0, 1), value=-100)[..., 1:]`; Megatron-style code slices `logits[..., :-1, :]` / `labels[..., 1:]`) then shifts each shard on its own. Each rank pairs the last token of its shard with the wrong target, and the loss is silently wrong. #8457 documents pre-shifted labels as the workaround; this PR makes the in-model shift itself correct.

### Approach
- Labels are no longer sharded. Any shift the model applies to them runs on the full sequence, so the label subgraph computes exactly what it does without SP.
- For each `F.cross_entropy` whose target derives from the labels:
  1. Walk from the CE input back to the sequence-sharded logits. Static sequence slices on the way (e.g. `logits[..., :-1, :]`) are removed, because each rank must keep its whole shard of logits. Their offsets give the window `[start, S + stop)` of global positions the CE input covered.
  2. Pad the full target with `ignore_index` back to the global positions of that window, then hand the CE this rank's shard `[r*S/sp, (r+1)*S/sp)`. This needs no communication because the labels are replicated.
  3. The loss and gradient aggregation from #8457 is unchanged.
- A static check makes sure the target lines up position by position with the logits window: the symbolic length of the target's sequence dimension must equal `S + stop - start`.
- Anything outside this pattern raises instead of silently misaligning:
  - Only casts, `contiguous`, `view`/`reshape`/`flatten` (after any slices) and static sequence slices are allowed between the logits and the CE.
  - The labels may only flow into CE targets. They cannot be combined with sharded tensors such as `input_ids`, or returned from the module.
- Padding uses `narrow` + `full_like` + `cat` instead of `F.pad`/`constant_pad_nd`, which specialize the symbolic sequence length during fake-tensor propagation.

### Validation (8× Intel Arc Pro B70, torch 2.14.0.dev+xpu)
- `TestAutoSPCausalLoss` compares the loss and the parameters after two optimizer steps against single-device training on the full sequence, over 4 ranks (sp=2, dp=2). New cases:
  - `slice` (`logits[..., :-1, :]` / `labels[..., 1:]`)
  - `pad` (HF style)
  - each combined with ZeRO-1, `sum`/`mean`, an explicit mesh, and an empty shard
- `test_rejects_labels_it_cannot_align` covers a strided logits slice and labels masked by `input_ids`.
- `test_compile_autosp.py`: 45 sequential and 20 non-sequential tests pass. `TestAutoSPCompile` and `TestAutoSPEngineBackward` were excluded because they fail on this machine for environmental reasons (dynamo tracing of `synchronize()`; the XPU C++20 op build, fixed in #8803), identically on the base branch.
- Tiny HF `LlamaForCausalLM` (transformers 5.17), unshifted `labels`, sp=2, also checked with `dynamic=True` + `attention_mask`:

  | | loss |
  |---|---|
  | single device | 4.840665 |
  | #8457 alone | 4.845766 (wrong) |
  | this PR | 4.840665 |

### Notes
- Pre-shifted labels (`shift_labels`) remain supported and are still the simplest path.
