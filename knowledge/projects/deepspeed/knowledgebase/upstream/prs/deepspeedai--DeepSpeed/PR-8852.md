# Support Transformers 5.20 cache query offsets in DeepSpeedStaticCache

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8852) · state: open · merged: False

## Original PR description

### Background

Native Llama continuous rollout on Transformers 5.20.1 failed because `DeepSpeedStaticCache` lacked `get_query_offset(layer_idx)`. The query offset must exclude the current write; using `get_seq_length()` would be off by one.

### Changes

**Implemented and validated** on `fix/static-cache-query-offset`:

- Added layer and cache query-offset methods: zero when unset, the scalar write position otherwise, or the maximum per-row position with row validity handled by attention masks.
- Preserved cache-length and KV-write behavior without capture-time host synchronization.
- Added independent masking and CUDA replay regressions, plus native Llama generation comparisons covering eager / SDPA attention, padding, slot refill, and graph reuse.

### Validation

RTX A4500 (20 GiB), PyTorch 2.9.1+cu128 / CUDA 12.8, FP16:

| Transformers | Results |
| --- | --- |
| 5.20.1 | 76 passed, 1 skipped |
| 4.57.6 | 73 passed, 4 skipped |

Actual CUDA capture/replay passed. Randomly initialized tiny Llama rollouts matched native `generate()` tokens, attention masks, and response offsets. Both versions skipped the optional pretrained-model test; 4.57.6 also skipped three tests requiring the newer masking API. Modified-file pre-commit checks passed.

Run in each Transformers environment:

```bash
python -m pytest \
    tests/unit/utils/test_static_cache.py \
    tests/unit/runtime/rollout/test_hybrid_engine_rollout.py \
    tests/unit/runtime/rollout/test_continuous_batching.py \
    tests/unit/v1/test_hybrid_engine_rollout_v1.py -q
```

### Scope and dependencies

Depends on the cache code from deepspeedai/DeepSpeed#8732, not the benchmark. Changes are limited to compatibility, tests, and documentation; this does not claim full Transformers 5.20 cache API support. Issue 1 depends on this fix in the tested 5.20.1 environment.
