# Report skipped optimizer steps from the non-ZeRO optimizer wrappers

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8869) · state: open · merged: False

## Original PR description

## Summary

#8417 made the static `LossScaler.update_scale` warn when a non-finite gradient skips the optimizer step. That covers `DeepSpeedZeroOptimizer` and ZeRO-3, which route the skip through a loss scaler. Three sibling wrappers skip the step on their own and still report nothing at the default WARNING level:

- `FP16_Optimizer` and `FP16_UnfusedOptimizer` (ZeRO stage 0): with bf16, `use_grad_scaling` is false and `_update_scale` is never reached; with a static fp16 scale, the skip is only logged at INFO.
- `BF16_Optimizer` (ZeRO stage 1 with `grad_accum_dtype: fp32`, bf16 pipeline parallelism): `step()` returns after `clear_hp_grads()` without any message.

In all three the training loop advances, `engine.skipped_steps` is incremented, the LR scheduler stays put and the weights are unchanged, with no output on a default config.

## Change

- `report_skipped_step()` in `loss_scaler.py` holds the #8417 warning; `LossScaler.update_scale` and the three wrappers above call it.
- `docs/_pages/config-json.md` documents `bf16.check_grad_overflow`, including which paths ignore it (ZeRO-0, ZeRO-3 and `BF16_Optimizer` always skip a step whose gradient norm is not finite).
- No code paths were added for the dynamic fp16 scaler, which already reports.

Sibling paths checked: ZeRO-1/2 (`stage_1_and_2.py`, covered by #8417 through `LossScaler`), ZeRO-3 (`_overflow_check_and_loss_scale_update` → loss scaler, covered), ZenFlow (inherits the ZeRO-1/2 path), the three wrappers above (this PR).

Not a duplicate: #8426 adds a second warning inside `DeepSpeedZeroOptimizer.step()` (already covered by #8417); #8588 changes the reported norm in `FP16_UnfusedOptimizer`. Neither touches the paths here.

## Tests

`TestFixedScaleSkippedStepIsReported` in `tests/unit/runtime/half_precision/test_static_loss_scale_overflow.py` builds an engine with each wrapper, runs one finite and one `inf`-scaled step, and asserts that the skip count, the unchanged parameters and the number of WARNING records agree. Five cells: bf16 × {FP16_UnfusedOptimizer, FP16_Optimizer, BF16_Optimizer}, static fp16 × {FP16_UnfusedOptimizer, FP16_Optimizer}.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Skip BF16 rows when the accelerator lacks BF16**

On an accelerator for which `is_bf16_supported()` is false (for example a pre-Ampere CUDA GPU or a vendor device without BF16), the three `bf16` rows still run because only FP16 is capability-gated. They then initialize a BF16 engine and execute a BF16 `Linear`, so a cross-accelerator suite can fail in unsupported kernels rather than skip; add the analogous BF16 capability check before initialization.
