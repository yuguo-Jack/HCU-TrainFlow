# Add klxpu (KUNLUNXIN XPU) self-hosted CI for the v1 unit suite

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8923) · state: closed · merged: True

## Original PR description

Run the tests/unit/v1 suite on a self-hosted KUNLUNXIN XPU runner inside the vendor container, one test file per subprocess (torch_xmlir inits CUDA at import, so pytest --forked is unusable). A blocklist keeps new tests running by default:
  - ignore.txt   whole files/dirs that hang or wholly fail
  - deselect.txt individual node ids that fail

Environment handling, all per-machine via Actions variables so the same workflow works on hosts with different networks and storage:
  - proxy (KLXPU_HTTP_PROXY/KLXPU_HTTPS_PROXY): unset means direct access.
  - Hugging Face (KLXPU_HF_ENDPOINT + HF_HUB_DISABLE_XET): route model downloads through a reachable mirror and force plain-HTTPS LFS, since the Xet CDN is unreachable behind a mirror and otherwise stalls.

Ignored files cover known KLX-stack limitations: BKCL/XCCL single-communicator hangs (autotp/moe/muon/zero/ulysses), Triton unsupported, torch.compile intercepted by torch_xmlir, and GDS unavailable.

Whenever this script runs, pytest finds `tests/pytest.ini`, whose `addopts` supplies `-m "not sequential ..."`; `pytest --help` describes `-m` as “Only run tests matching given mark expression.” Since this is the only pytest invocation, cases such as `tests/unit/v1/zero/test_zero_user_backward.py:845` and `tests/unit/v1/nvme/test_aio.py:222` are always deselected, and an all-sequential file returns 5 and is reported as `PASS` below. Add a companion sequential pass (as the other accelerator workflows do) or override this marker filter so the advertised v1 suite actually covers these tests.
