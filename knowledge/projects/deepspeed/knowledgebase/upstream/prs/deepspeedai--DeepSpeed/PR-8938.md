# [ops] Warn when DeepSpeedCPUAdam is limited to one OpenMP thread

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8938) · state: open · merged: False

## Original PR description

torchrun sets `OMP_NUM_THREADS=1` for every process when `--nproc_per_node` is larger than 1, unless the variable is already set. `DeepSpeedCPUAdam` then steps on a single OpenMP thread, and nothing in the log says so. The deepspeed launcher sets the thread count only with `--bind_cores_to_rank`, which is the path the ZeRO-Offload tutorial documents. Users who launch with torchrun or accelerate get no hint.

**Measured effect**

Setup: ZeRO-1 with `offload_optimizer: cpu`, Qwen3-4B in bf16, fp32 gradient accumulation. The time is for `engine.step()` (CPU Adam plus the copies around it), median over the measured steps.

| Hardware | Launch | `OMP_NUM_THREADS=1` | threads set per rank | Speed-up |
|---|---|---|---|---|
| one GH200, 72-core host | 1 process, variable set to 1 by hand to match the torchrun default | 5.6 s | 0.8 s (36 threads) | 7× |
| B300 | `torchrun --nproc_per_node 2`, real default | 3.92 s | 1.76 s (32 threads, half a NUMA node per rank) | 2.2× |

On B300, each rank steps half of the optimizer state, so the single-thread cost is already split over two processes. In a 2-GPU torchrun job on L40S at the default, the same step took 6.2 s.

The B300 run with threads set also changed the attention path for packed micro-batches. That doesn't touch `engine.step()`, so the optimizer column only reflects the thread count.

**Change**
- `single_thread_warning()` in `deepspeed/ops/adam/cpu_adam.py` returns a message when `OMP_NUM_THREADS` is `"1"` and the rank has at least two cores (CPU affinity divided by `LOCAL_WORLD_SIZE`).
- `DeepSpeedCPUAdam.__init__` logs it once per process, for the first optimizer instance.
- The CPU Adam tuning section of the ZeRO-Offload tutorial gets a note for torchrun users.

It only warns and does not change the thread count:
- an explicit `OMP_NUM_THREADS=1` may be intentional;
- the OpenMP runtime may already have read the variable by the time the optimizer is built.

**Tests**

`tests/unit/ops/adam/test_cpu_adam_threads.py` is CPU only and does not build the op. It checks four cases:
- warns at the torchrun default when the rank has spare cores;
- silent when the variable is unset or larger than 1;
- silent when the rank has a single core;
- a single process counts all its cores.

yapf, flake8, codespell and the license check pass.
