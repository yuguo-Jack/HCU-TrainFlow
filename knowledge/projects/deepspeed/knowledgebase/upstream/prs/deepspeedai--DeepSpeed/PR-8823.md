# Fix routed-expert gradient clipping for AutoEP + AutoTP folding

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8823) · state: open · merged: False

## Original PR description

AutoEP + AutoTP folding gives TP peers different routed experts. ZeRO-1/2 currently filters non-TP expert parameters to TP rank zero when computing the clipping norm, then applies the ordinary expert-norm averaging path. This can omit expert owners and produce an incorrect clipping coefficient even when reconstructed logical gradients are correct.

Compute folded expert norms over the actual expert-DP partition group and EP owner group, without another TP sum or expert-norm average. Only groups tagged with the AutoEP expert placement family use this path. Dense groups and native MoE groups retain their existing reductions and native expert-norm averaging, including when native ETP and AutoEP groups coexist. ZeRO-3 is unchanged and is checked as a sibling reference. The existing folding contract rejects optimizer/parameter offload.

Refs #8672 and #8670. The live duplicate check found no open PR fixing this ZeRO-1/2 folding path. #8476, #8478 and #8691 address FP32/ZeRO-0 clipping in `runtime/utils.py`; they do not change the partitioned optimizer reductions fixed here. #8739 implements DeepEP weight-gradient overlap and does not change these norm reductions.

### Final change

This PR contains three files:

- `deepspeed/runtime/zero/stage_1_and_2.py`: correct the folded expert clipping reductions.
- `tests/unit/v1/moe/test_autoep_autotp_sharded_attention.py`: reconstruct full logical gradients and FP32 master parameters, then compare an actual SGD update against an unsharded ZeRO-0 reference across all 45 parameter families. Thresholds of 0.5 and 2.0 times the reference norm cover active clipping and an inactive control. Snapshots are cloned before in-place updates; distributed diagnostics finish before assertions.
- `docs/code-docs/source/autoep.rst`: document expert ownership and the reduction contract.

The sharded-attention regression supports 4- and 8-rank TP2/EP4 configurations, ZeRO-1/2/3 and ZeRO-3 `zero.Init`. An additional two-rank analytic SGD regression covers native ETP alone and mixed native ETP/folded AutoEP groups at ZeRO-1/2.

### Incremental review and corrections

Reviewed the original PR head `352ee55cd14f77f30e5170939c7e60c4d4bd7754`. This review concerns the ZeRO-1/2 change in this PR and agrees with [the existing native-ETP review finding](https://github.com/deepspeedai/DeepSpeed/pull/8823#discussion_r4274002921).

**Finding addressed:** A global folding spec previously routed every MoE optimizer group through the folded EDP+EP norm path. A native MoE group using expert tensor parallelism still needs its model-parallel reduction; replacing that reduction can leave each TP lane with a partial norm and a different clipping coefficient.

The correction selects the folded path only for groups whose parameters all carry `ds_zero_placement_family="autoep_expert"`. Native groups keep their existing model-parallel reduction and expert-norm averaging, including when folded and native groups coexist. Dense behavior and ZeRO-3 are unchanged.

The new two-rank regression uses actual ZeRO optimizers, collectives, backward and SGD updates. Native ETP gradients with shard norms 3 and 4 must produce norm 5. Adding a folded expert with norm 12 on TP rank one must produce norm 13 on both ranks, followed by the analytically expected clipped parameter update. Both ZeRO-1 and ZeRO-2 are covered, with native-only controls.

Corrected in [fb5d0e5](https://github.com/deepspeedai/DeepSpeed/commit/fb5d0e5efa6d9aec89b26cd022e50d4862478945). [Review only this increment](https://github.com/deepspeedai/DeepSpeed/compare/352ee55cd14f77f30e5170939c7e60c4d4bd7754...fb5d0e5efa6d9aec89b26cd022e50d4862478945).
