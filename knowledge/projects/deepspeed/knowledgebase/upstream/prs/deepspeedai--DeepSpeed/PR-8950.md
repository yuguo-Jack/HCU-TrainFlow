## Summary
- Run the workflow Python on 3.12 so transformers main can be installed. The Modal image was already 3.12; the runners and the AWS capacity fallback were still preparing 3.10.

- 0z5a · COMMENTED · 2026-11-01T16:45:55Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8950#pullrequestreview-5729182590)

I only looked at the Gloo subgroup change in `deepspeed/comm/torch.py`, not the rest of this PR.

The fix works, and the problem isn't limited to PyTorch 2.7–2.10. On torch 2.15 (CPU, gloo), `init_process_group("gloo", device_id=torch.device("cpu:0"))` followed by `new_group([0])` on two ranks raises `'ProcessGroupGloo' object has no attribute 'perform_nocolor_split'` on the non-member rank. With `_ensure_gloo_subgroup_split()` applied, three ranks build `[0, 1]` and `[1, 2]`, all-reduce on each and on the world in between, and get 2 / 3 / 2. Without it, the non-member raises (seen with two ranks), and the three-rank run hangs.

Two suggestions:
- The docstring says "PyTorch 2.7 through 2.10"; 2.15 is affected too, so the range could be dropped.
- No unit test targets it directly, and the CPU job never binds a device, so CPU CI doesn't exercise it. Binding `device_id=torch.device("cpu:0")` reproduces the failure on CPU, so a small three-rank gloo test like the one above could cover it in the CPU job.

Optional: `init_process_group` passes `device_id` on the CUDA accelerator regardless of backend. Passing it only when CUDA tensors use NCCL would keep DeepSpeed-initialized gloo worlds off the split path entirely, leaving this patch as the fallback for externally initialized ones.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Handle nonempty tensors smaller than one quantization group**

When a quantized parameter has fewer elements than `group_size`—for example, a small `QuantizedLinear` with the default group size of 512—`num_groups` is zero and this returns an empty quantized buffer. `QuantizedParameter._ensure_quantized()` then installs that empty buffer, while the matching dequantization early-return leaves the original-shaped output uninitialized, producing silently incorrect model outputs. Limit this shortcut to truly empty inputs, reject undersized nonempty inputs, or implement a partial group.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Select CPU staging from the requested process group**

For a CUDA collective using a non-default process group, this checks only the default group's backend. If the default group is Gloo but the supplied `group` is NCCL, every decorated collective copies the CUDA tensor to CPU and then passes it to NCCL, breaking a configuration that previously worked; conversely, a Gloo subgroup under a default NCCL group is not staged and still faults. The staging decision needs to use the backend of the actual `group` argument bound by the wrapper.
