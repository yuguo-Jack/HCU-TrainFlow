# Vectorize `partition_balanced` dynamic programming inner loop

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8893) · state: open · merged: False

## Original PR description

## Summary
`partition_balanced(weights, num_parts)` in `deepspeed/runtime/utils.py` (invoked by `PipelineModule._partition_layers` for `partition_method="parameters"` and `"type:..."`) solves the 1D linear partition problem using dynamic programming over `(i, j, k)`.

Currently, the innermost transition loop (`for k in range(i):`) executes in interpreted Python with scalar `np.ndarray` indexing (`dp_max[k, j - 1]`, `dp_min[k, j - 1]`, `prefix_sum[i] - prefix_sum[k]`), performing $O(N^2 \cdot M)$ scalar NumPy lookups during pipeline initialization.

## Changes
- Hoist `part_sum = prefix_sum[i] - prefix_sum[:i]` out of the `j` loop so suffix sums are computed once per prefix length `i`.
- Replace the inner `for k in range(i):` loop with vectorized NumPy array operations (`np.maximum(dp_max[:i, j - 1], part_sum)`, `np.minimum(dp_min[:i, j - 1], part_sum)`).
- Select `k = i - 1 - int(np.argmin(cost[::-1]))` to preserve the exact last-minimizer (`dp_cost[i, j] >= cost`) tie-breaking semantics of the original loop while maintaining $O(N \cdot M)$ memory complexity.
- Add tie-breaking verification cases in `tests/unit/utils/test_partition_balanced.py`.

## Micro-benchmark (`partition_balanced(weights, num_parts)`)
| Layers ($N$) | Pipeline Stages ($M$) | Before (`master`) | After (this PR) | Speedup |
|---:|---:|---:|---:|---:|
| 300 | 8 | 0.5890 s | 0.0205 s | **28.8x** |
| 600 | 8 | 2.3619 s | 0.0462 s | **51.1x** |
| 1,000 | 16 | 13.6686 s | 0.1735 s | **78.8x** |

## Testing
- Verified exact output equivalence across 200+ randomized weight and stage configurations (including zero weights and tie-breaking cases).
- `pytest tests/unit/utils/test_partition_balanced.py tests/unit/runtime/utils/test_partition.py` (all unit tests pass).
