# Clear stale offload scratch before restoring low-precision gradients

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8728) · state: open · merged: False

## Original PR description

## Problem

With unmanaged gradient accumulation, ZeRO-2 CPU offload and BF16/FP16 master weights, a genuinely overflowing step can cause the next entirely finite step to be skipped.

`_restore_cpu_offload_grad_to_gpu` copies only the locally owned fragment into a shared scratch tensor for low-precision masters. The norm and optimizer-buffer consumers read that fragment, but the overflow tracker reads the entire restored gradient. NaNs left in the unowned region by another parameter group can therefore set `local_overflow` for a finite window.

## Change

Clear the destination view before the partial copy. The FP32-master full-copy path is unchanged.

The regression uses the public Engine training loop with two parameter groups (12 and 8 elements) and DP=2. It first produces a real NaN step, then requires two finite steps to update both parameters. All parameters participate in every step; the test does not fabricate optimizer state or poison scratch storage directly. It covers BF16/FP16 with both low-precision and FP32 masters.

## Validation

- Historical device-validation base: `c687df79653459d08c0c6fada6d124971d966662`. The device results below belong to that original revision, not the new merge head.
- Two NVIDIA B300 GPUs; Python 3.12.13, Torch 2.11.0+cu130, CUDA 13.0; actual CPUAdam extension.
- On unmodified master, the added BF16 and FP16 low-precision-master cases fail at `finite step did not update large`; both FP32-master controls pass.
- With this change, all four registered distributed regression cases pass.
- Official `pre-commit run --files` passes with the unchanged repository configuration and pinned hooks on Linux/Python 3.12.
- The original module's two CPU-accumulator cases pass. Its other eight cases require the no-offload GPU FusedAdam comparison and could not run successfully in this environment: extension compilation fails on missing `cusparse.h`. They are not claimed as passing.

This is a correctness fix, not a performance or convergence claim.
