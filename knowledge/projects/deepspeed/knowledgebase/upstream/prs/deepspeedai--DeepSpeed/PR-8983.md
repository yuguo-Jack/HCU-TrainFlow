# Fix DynamicLossScaler never lowering the scale when fp16 hysteresis is 0 or less

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8983) · state: open · merged: False

## Original PR description

`DeepSpeedFP16Config` accepts `fp16.hysteresis` of 0 or a negative number. `DynamicLossScaler.update_scale`, which ZeRO stages 1, 2 and 3 use through `CreateLossScaler`, only lowers the scale when `delayed_shift == 1 or cur_hysteresis == 1`. With a start value of 0 or below, `cur_hysteresis` only counts further down, so the scale is never lowered and every overflowing step is skipped for the rest of the run. The stage 0 fp16 optimizers already treat these values as no delay (they back off unless `cur_hysteresis > 1`), so the two paths disagreed.

The change uses `<= 1` in both comparisons, so 0 or below behaves like 1 and backs off on every overflow. Values of 1 and above behave as before. I did not add config validation, to avoid rejecting configs that load today.

Fixes #8982

## Duplicate check

The related ones are #8647, which added hysteresis handling to the stage 0 optimizers with a `> 1` check but left `DynamicLossScaler` unchanged, and the open #7856, which would reject `hysteresis` below 1 at config parse time. This change takes the other approach and accepts 0 or less as no delay, the same as the stage 0 optimizers, so either can land. Sibling paths: `fused_optimizer.py` and `unfused_optimizer.py` (stage 0) already use `cur_hysteresis > 1`, and bf16 has no loss scaler. The change touches only `DynamicLossScaler`.

## Tests

Added `TestZeroScalerHysteresis::test_no_delay_lowers_the_scale` in `tests/unit/runtime/half_precision/test_dynamic_loss_scale.py`. For hysteresis 1, 0 and -1 it sends three overflows and checks the scale goes from 2**8 to 2**5.

Run in Docker on CPU only (no GPU; x86_64 Linux, Python 3.13, torch 2.9.0+cpu, `DS_ACCELERATOR=cpu`, `DS_BUILD_OPS=0`):

- `pytest tests/unit/runtime/half_precision/test_dynamic_loss_scale.py -k TestZeroScalerHysteresis`: 2 failed and 1 passed on main, 3 passed with the fix.
- Standalone script from the issue on main: hysteresis 0 and -1 keep scale 65536 after 20 overflows (exit 1). With the fix the scale reaches the minimum (exit 0).

Not run: the rest of that test file (it needs an fp16-capable accelerator), pre-commit, ZeRO end-to-end runs.

## Compatibility matrix

Only the scaler class was exercised, which is the code ZeRO 1, 2 and 3 share with fp16. Not validated: ZeRO end-to-end runs, offload, parallelism, GPUs. There is no change to numerics, throughput or memory for hysteresis of 1 or more.
