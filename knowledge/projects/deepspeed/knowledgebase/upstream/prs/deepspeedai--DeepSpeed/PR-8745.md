# AutoEP: opt-in skip of the recomputed DeepEP combine

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8745) · state: open · merged: False

## Original PR description

## Summary

Add opt-in `expert_parallel.skip_recompute_combine` for AutoEP's DeepEP route. In supported Hugging Face per-decoder-layer **reentrant** checkpointing, the recomputed MoE output is used only by the residual add and is discarded by the checkpoint. The route records post-expert row weighting and combine backward without executing those forward operations; dispatch, expert compute and all required backward transfers still run. Default behavior is unchanged.

This is the existing skip-combine PR, not a duplicate implementation. It remains distinct from the non-reentrant layout replay merged in deepspeedai/DeepSpeed#8731. The branch is rebased onto current master and preserves that replay, the fused gate+up defaults from deepspeedai/DeepSpeed#8733, and the independent exact-size buffer checks from deepspeedai/DeepSpeed#8747. AI assistance was used for finalization, with author review before submission.

## Supported contract

- `comm_backend="deepep"`, `autoep_size > 1`, BF16 dispatch; eager and fused row weighting, at their unchanged `score_apply` boundary.
- Supported decoder presets: `deepseek_v2`, `deepseek_v3`, `minimax_m3`, `mixtral`, `qwen3_5_moe`, `qwen3_moe`, checked against Transformers 5.12.0 modeling code.
- The recompute guard checks the attached decoder layer's checkpoint configuration: `gradient_checkpointing=True` and the standard Torch checkpoint partial with `use_reentrant=True`. Transformers 5 defaults to non-reentrant, so explicitly use `gradient_checkpointing_kwargs={"use_reentrant": True}`.
- Other checkpoint APIs, non-reentrant checkpointing with this flag, unsupported presets and custom patterns are outside the supported contract. Without recomputation, the ordinary path runs.
- The skip requires that the MoE output has no value-dependent consumer in the recompute. The combined sentinel is NaN; an invalid consumer can produce non-finite values or gradients, but the sentinel is **not** a general runtime proof that arbitrary wrappers, hooks or patched decoder graphs are safe.

## Finalization

Resolved the upstream conflicts without dropping replay or buffer behavior. Both normal and recorded combines now share their backward-context setup, including transferring the pending dispatch entry from the exchange to the consuming autograd node. Otherwise the recorded path could retain a stale entry and attempt to replay the previous step's routing in a later reentrant backward.

The CPU reproducer fails before the context fix with `activation checkpointing recomputed a different routing`. The new regression performs three successive steps with changing routes and compares outputs, input/router/expert gradients and required transfers for both pre/post score application.

The single CUDA weighting test now runs in a fresh `DistributedTest` worker, retaining its actual fused/recorded-backward comparison rather than allocating CUDA from an ordinary forked unittest. The existing real-DeepEP skip parity cases run two steps per model. The one-step test helper's defaults and original tolerances remain unchanged.

## Existing performance evidence

Qwen3-30B-A3B, **8 H100s**, EP8, micro-batch **4**, gradient accumulation **16**, sequence **4096**, DeepEP **28 SMs**, reentrant activation checkpointing; **30 steps with 10 warmup**. The equivalent benchmark prototype records the same weighting/combine backward but returns uninitialized output where the product fills NaN. Both arms inherit concatenated gate+up and backward weight-gradient overlap; this is the **incremental skip effect**, not their combined benefit.

One allocation, order normal / skip / skip / normal:

| Recompute | Run medians | Mean |
|---|---|---:|
| Normal | 20,575.1 / 20,574.2 ms | 20,574.7 ms |
| Combine + post-weighting forward skipped | 19,945.7 / 19,928.2 ms | **19,936.9 ms (-3.10%)** |

Peak allocated memory stayed at **58.69 GB**; peak reserved memory was **0.25 GB lower**. Loss differences over these 30 steps were within same-arm repeat noise (maximum **9.4e-4**). The 8-GPU residual-block gate had numerical equality under `torch.equal` for output/input/router gradients and expert-gradient differences around **5e-5 relative L2**, within two normal recomputes' variation. `torch.equal` is not a claim about signed-zero bit patterns.

The measurements are historical prototype evidence, **not** a retiming of the rebased product or a universal benefit across models/hardware. Skipping the forward combine removes that recompute transfer; it does not add overlap or remove the cached dispatch and weight-gradient communication required by backward.

Thank you for this awesome optimization!

One small issue I found is that `skip_recompute_combine` still accepts
a custom `moe_layer_pattern` together with a supported preset. The pattern
override changes the decoder parent while the preset name remains supported,
so the later whitelist does not prove that the custom parent only performs the
validated residual add. A value-dependent wrapper can consume the recorded
combine's NaNs during recomputation and corrupt gradients.

The minimal fix could be to reject a non-null `moe_layer_pattern` whenever `skip_recompute_combine` is enabled and add a supported-preset-plus-custom-pattern regression. See this [commit](https://github.com/tohtana/DeepSpeed/commit/2ea5e9015a271d34de04e71eb8b21998bd0dff04).

`skip_recompute_combine` still accepts a custom `moe_layer_pattern`. `resolve_preset_candidates()` applies that override while retaining the selected or auto-detected preset name (`auto_ep_presets/registry.py:121-175`), so the preset whitelist later passes even when the replacement's parent is not a validated decoder layer.
