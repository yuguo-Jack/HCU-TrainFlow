# Forward the inputs DSUNet._forward accepts to the UNet

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8408) · state: open · merged: False

## Original PR description

### What is wrong

`DSUNet._forward` accepts `timestep_cond` and `added_cond_kwargs` and forwards neither, and it passes `return_dict` positionally:

```python
return self.unet(sample, timestamp, encoder_hidden_states, return_dict)
```

`UNet2DConditionModel.forward`'s fourth positional parameter is **`class_labels`**, not `return_dict`:

```python
def forward(self, sample, timestep, encoder_hidden_states,
            class_labels=None, timestep_cond=None, attention_mask=None,
            cross_attention_kwargs=None, added_cond_kwargs=None, ..., return_dict=True)
```

Driving the wrapper with a stub that mirrors that signature, with `enable_cuda_graph=False` so no accelerator is needed:

| caller passes | UNet receives on master | UNet receives with this PR |
|---|---|---|
| `return_dict=False` | `class_labels=False`, `return_dict=True` | `class_labels=None`, `return_dict=False` |
| `timestep_cond=<tensor>` | `None` | the tensor |
| `added_cond_kwargs={...}` | `None` | the dict |

SDXL's UNet requires `added_cond_kwargs` (`addition_embed_type == "text_time"`), and `timestep_cond` is what a guidance-distilled model reads, so both are dropped exactly where they matter.

### What changed

Pass everything after `encoder_hidden_states` by keyword. The `if cross_attention_kwargs:` branch goes with it: `cross_attention_kwargs=None` is what omitting the argument already meant, and both of its arms carried the same positional mistake.

### Test

`test_ds_unet_forwards_the_inputs_it_accepts` in `tests/unit/inference/test_stable_diffusion.py`, a plain function alongside the existing `TestStableDiffusion` class. It drives `DSUNet` with a recording stub, needs no accelerator and downloads no model.

```
$ pytest tests/unit/inference/test_stable_diffusion.py -k ds_unet -q
master      1 failed    assert True is False   (return_dict never reached the UNet)
this PR     1 passed
```

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Refresh nested added conditioning before graph replay**

With `enable_cuda_graph=True` (the default), SDXL passes `added_cond_kwargs` as a dictionary containing tensors such as `text_embeds` and `time_ids`. `_graph_replay` only copies top-level tensor kwargs, so the captured dictionary from the first invocation is never refreshed; a later pipeline call with a different prompt replays using the first call's added conditioning and produces silently incorrect images. Flatten or explicitly copy the dictionary's tensor values into static buffers before replay; the new test disables CUDA graphs and therefore does not cover this path.

Useful? React with 👍 / 👎.

Real, and split out into #8488.

You are right that forwarding `added_cond_kwargs` is what makes the staleness reachable: before this PR it was dropped entirely, so there was nothing to go stale. `_graph_replay` matches on `torch.is_tensor`, so a dict of tensors is skipped and the capture-time conditioning is replayed for every later prompt.

It is not specific to this file. The same six lines sit in `DSVAE` (three times), `DSClipEncoder` and `InferenceEngine`, all with the same gap. #8488 adds one `refresh_static_tensors()` helper next to `CUDAGraph` and uses it at all six sites, with a CPU test that fails on master.

Keeping it out of this PR so this one stays about the argument list.

File: `deepspeed/model_implementations/diffusers/unet.py` · line 81

With CUDA graphs enabled (the `UNetPolicy.apply` default), this newly forwarded dictionary becomes stale after the first capture. `_graph_replay` only copies kwargs whose top-level value is a tensor (`unet.py:30-32`), so a later call with new SDXL `text_embeds`/`time_ids` keeps replaying the tensors captured in the original `added_cond_kwargs`. Please teach graph replay to update tensors nested in this mapping (and cover a second replay with different conditioning); otherwise repeated inference can use the previous request's conditioning.
