## Original PR description

# Add an opt-in deterministic execution policy

Draft contribution related to #8915, prepared following the submitter's offline
discussion with DeepSpeed developers. Maintainer design review is requested.

## Changes

- Add boolean `deterministic_mode`, default false, with small config/engine wiring
  and a 31-line runtime helper.
- On CUDA, select strict PyTorch deterministic algorithms, disable TF32/cuDNN
  benchmarking and enable deterministic cuDNN. Validate cuBLAS workspace
  environment; do not attempt to install it after CUDA use.
- Preserve communication precision, NCCL algorithm, GAS, TP/EP and overlap
  settings. Do not prohibit configurations merely because they are untested.
- Forward PyTorch's deterministic state to FPDT FlashAttention backward across
  GPU/offload and supported version branches.
- Reject legacy `stochastic_mode=True` during construction/forward/backward
  when deterministic algorithms are enabled.
- Bypass Triton grouped GEMM timing autotuning with an existing fixed
  configuration for forward/dx/dw, without mutating shared autotune caches.
- Add configuration, runtime and custom-path tests, config docs and tutorial.
