# Accept warmup_num_steps=0 in the warmup LR schedulers again

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8804) · state: open · merged: False

## Original PR description

`WarmupLR`, `WarmupDecayLR` and `WarmupCosineLR` raise `ValueError: warmup_num_steps must be a positive integer, got 0` since 0.19.3. HF Trainer writes 0 into `"warmup_num_steps": "auto"` when no warmup is set, so those runs fail at startup on transformers before 5.18 (5.18 works around it with `max(1, ...)` in huggingface/transformers#48640). HodeTech/ForgeLM#502 hit this.

**Cause:** #8126 added a `<= 0` check. Before it, 0 was valid and `max(2, warmup_num_steps)` clamped it to 2, the same as 1.

**Fix:** Reject only negative values in both checks, so 0 behaves as before. `None` and negative values still raise.

**Test:** New `test_warmup_schedulers_accept_zero_warmup_num_steps` checks that 0 gives the same LRs as 2 for all three schedulers. It fails on master with that ValueError and passes after. `test_lr_schedulers.py` passes (91 tests, CPU). yapf and flake8 are clean.
