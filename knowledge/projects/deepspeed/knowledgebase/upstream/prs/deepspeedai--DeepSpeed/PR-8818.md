# Respect BF16 overflow-check opt-out in ZeRO-1/2

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8818) · state: closed · merged: True

## Original PR description

Fixes #8805.

### Why

The post-norm overflow guard ignored the explicit BF16 `check_grad_overflow=false` setting. Gating it on that flag alone also disabled ordinary FP32 invalid-norm rejection, because the engine sets the flag to false in FP32 mode.

### Scope

- Honor the opt-out only when the optimizer dtype is BF16; preserve FP32/FP16 invalid-norm rejection.
- Apply the same rule in ordinary ZeRO-1/2 and the ZenFlow overlap step override.
- Cover clipped/unclipped BF16 gradients, native distributed FP32 rejection, and ZenFlow overlap admission.

The follow-up `d89a883` addresses both P1 findings on the original submitted head.

### Testing

All runs used isolated GPFS environments, Python 3.12 and PyTorch 2.11.0+cu130.

| Focused validation | Negative control | Follow-up result |
| --- | --- | --- |
| New regression file | 17 passed / 3 failed against the original overlap guard | 20 passed: four native distributed FP32 cases and 16 overlap admission unit cases |
| FP32 native CPU engine, two ranks | Published `74e4d5d`: 4 passed / 8 failed step checks per rank, with nonfinite parameters | 12/12 step checks per rank; Inf/NaN skip and parameters remain finite |
| ZenFlow native CPU optimizer process, two ranks | Original overlap guard: 16 passed / 8 failed step checks per rank | 24/24 step checks per rank across eight configurations |
| Two H200s, NCCL | Original pre-fix source: 8/12 configurations and 28/36 step checks passed per rank | 12/12 configurations and 36/36 step checks per rank |
| Existing FP16/BF16 overflow suite | Previously tested on the initial patch | Fresh rerun: 36 passed |
| Scoped pre-commit | New regression registered in Git before the tracked-file license hook | Passed |

The CPU and H200 engine matrices cover ZeRO-1/2, clipping 0/1 and finite/Inf/NaN gradients. The H200 matrix includes FP32, BF16 default checking and explicit BF16 opt-out; finite updates match an independent FP32 Torch SGD reference converted to the target dtype exactly (`rtol=0, atol=0`).

ZenFlow integration uses actual CPU offload and its native optimizer process with both BF16 check settings. It covers the full-update warmup path (`full_warm_up_rounds=100`), not the selective/top-k phase. The overlap unit cases mock dispatch/cleanup and are not presented as native-worker validation.

Not claimed: GPU ZenFlow/offload, ZeRO-3, other accelerator vendors, full convergence, performance or full CI. Keep-alive was restored and verified on all four H200s after device tests.

AI assistance: OpenAI Codex assisted with implementation and validation. The submitting human has reviewed and approved the original changes and this follow-up line by line; the reported validation was run with Codex assistance.
