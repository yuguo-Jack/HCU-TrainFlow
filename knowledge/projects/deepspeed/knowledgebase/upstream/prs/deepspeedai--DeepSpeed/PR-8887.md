# XPU: register pinned host memory via Level Zero ext_memmap

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8887) · state: closed · merged: True

## Original PR description

## Motivation

DeepSpeed's native pin-memory path (`DS_PIN_MEMORY_BACKEND=native`) currently has no device registration on XPU — `register_host_memory()` returns `False`, so pinned host buffers are mlock-only and device access to them does not go through device page-table mappings. This PR implements the L0 equivalent of `cudaHostRegister` on the XPU accelerator.

## Implementation

- `XPU_Accelerator.register_host_memory()`: map existing host memory into the device's page tables via Level Zero's external host-memory mapping (`zeMemAllocHost` with the `ZE_extension_external_memmap_sysmem` descriptor chain), created in our own L0 context — device page tables are shared across the driver's contexts, so buffers registered here are accessible from torch's runtime as well.
- `unregister_host_memory()` releases the mapping.
- Graceful degradation: returns `False` when the L0 loader or the extension is unavailable.

## Tests

Three monkeypatched unit tests in `tests/unit/v1/pin_memory/test_pin_memory.py` (same pattern as the existing CUDA/CPU/NPU tests — no XPU hardware needed in CI):
- registration calls Level Zero with the correct descriptor chain (host desc -> `pNext` -> external memmap desc), address and size passthrough
- a mapping that comes back at a different address is treated as a failed registration
- failure paths return `False` rather than raising

## Operational notes

- On multi-NUMA hosts, binding the process to the GPU's NUMA node (`numactl --cpunodebind=N --membind=N`) is recommended when registering large ranges.
- `ulimit -l unlimited` (or an equivalent memlock limit) is required for large registrations; the DeepSpeed pin-memory path already checks and reports this.

```c
// Register page-locked host memory with ZE_extension_external_memmap_sysmem, then copy it on device K.
// usage: l0_repro K REG_CTX COPY_CTX     REG_CTX: all|one   COPY_CTX: same|other
#include <level_zero/ze_api.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#define CHECK(x) do { ze_result_t r_ = (x); if (r_) { printf("%s -> 0x%x\n", #x, r_); return 1; } } while (0)

int main(int argc, char **argv) {
    int k = atoi(argv[1]);
    int reg_one = !strcmp(argv[2], "one"), copy_same = !strcmp(argv[3], "same");
    CHECK(zeInit(ZE_INIT_FLAG_GPU_ONLY));
    uint32_t n = 1; ze_driver_handle_t drv; CHECK(zeDriverGet(&n, &drv));
    uint32_t nd = 0; CHECK(zeDeviceGet(drv, &nd, NULL));
    ze_device_handle_t devs[64]; CHECK(zeDeviceGet(drv, &nd, devs));
    if (k >= (int)nd) { printf("only %u devices\n", nd); return 1; }
    ze_context_desc_t cd = {ZE_STRUCTURE_TYPE_CONTEXT_DESC, NULL, 0};
    ze_context_handle_t reg_ctx, copy_ctx;
    if (reg_one) CHECK(zeContextCreateEx(drv, &cd, 1, &devs[k], &reg_ctx));
    else CHECK(zeContextCreate(drv, &cd, &reg_ctx));
    if (copy_same) copy_ctx = reg_ctx; else CHECK(zeContextCreate(drv, &cd, &copy_ctx));

    size_t bytes = 64 << 20;
    int *host = mmap(NULL, bytes, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    mlock(host, bytes);
    for (size_t i = 0; i < bytes / 4; i++) host[i] = (int)i;
    ze_external_memmap_sysmem_ext_desc_t mm = {ZE_STRUCTURE_TYPE_EXTERNAL_MEMMAP_SYSMEM_EXT_DESC, NULL, host, bytes};
    ze_host_mem_alloc_desc_t hd = {ZE_STRUCTURE_TYPE_HOST_MEM_ALLOC_DESC, &mm, 0};
    void *mapped = NULL;
    CHECK(zeMemAllocHost(reg_ctx, &hd, bytes, 0, &mapped));
    printf("registered: identity=%d\n", mapped == (void *)host);

    ze_device_mem_alloc_desc_t dd = {ZE_STRUCTURE_TYPE_DEVICE_MEM_ALLOC_DESC, NULL, 0, 0};
    void *dbuf; CHECK(zeMemAllocDevice(copy_ctx, &dd, bytes, 64, devs[k], &dbuf));
    ze_command_queue_desc_t qd = {ZE_STRUCTURE_TYPE_COMMAND_QUEUE_DESC, NULL, 0, 0, 0,
                                  ZE_COMMAND_QUEUE_MODE_SYNCHRONOUS, ZE_COMMAND_QUEUE_PRIORITY_NORMAL};
    ze_command_list_handle_t cl; CHECK(zeCommandListCreateImmediate(copy_ctx, devs[k], &qd, &cl));
    printf("copy H2D on device %d ...\n", k); fflush(stdout);
    CHECK(zeCommandListAppendMemoryCopy(cl, dbuf, host, bytes, NULL, 0, NULL));
    memset(host, 0, bytes);
    printf("copy D2H on device %d ...\n", k); fflush(stdout);
    CHECK(zeCommandListAppendMemoryCopy(cl, host, dbuf, bytes, NULL, 0, NULL));
    size_t bad = 0; for (size_t i = 0; i < bytes / 4; i++) bad += host[i] != (int)i;
    printf("device %d reg_ctx=%s copy_ctx=%s: mismatches=%zu\n", k, argv[2], argv[3], bad);
    CHECK(zeMemFree(reg_ctx, host));
    return bad != 0;
}
```
Build: `gcc -O2 -o l0_repro l0_repro.c -lze_loader`; run `./l0_repro 3 all same` (fails) vs `./l0_repro 3 one same` (ok).
</details>

Suggestion: cache one context per device, keyed by the torch device index at registration time, and pick the L0 device by matching `torch.xpu.get_device_properties(k).uuid` with `zeDeviceGetProperties(...).uuid` rather than assuming the `zeDeviceGet` order. `unregister_host_memory` would then need to free in the same context, so it should look up the context recorded at registration instead of the current device.

Minor:
- XPU does not override `pin_memory_alignment()` (default 1). The native allocator returns page-aligned buffers today, so this works, but declaring 4096 would protect against a future allocator change if the extension requires page alignment.
- The added tests are mocks only. A short hardware test (register, `copy_(non_blocking=True)`, check values, on a non-zero device) would have caught the crash above; it could live with the other XPU-only tests if the v1 pin_memory suite is not run on XPU CI.
