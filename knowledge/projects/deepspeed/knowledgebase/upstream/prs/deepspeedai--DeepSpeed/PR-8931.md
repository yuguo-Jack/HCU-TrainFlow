# [Fix] Reject duplicate block ids in BlockedAllocator.free to prevent KV-cache double allocation

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8931) · state: open · merged: False

## Original PR description

### Motivation

`BlockedAllocator.free()` validates every block for validity *before* mutating the free list, but the "already free" check cannot detect duplicates **within a single call**: marking happens in the second (mutation) loop, so both passes see the stale `-1` marker for a repeated id.

Repro (pure CPU, no model or GPU needed):

```python
allocator = BlockedAllocator(4)
a = allocator.allocate(3)      # blocks [0, 1, 2]
allocator.free([0, 0, 1])      # passes validation
# free_blocks is now 4 (should be 2): block 0 is in the free list twice
b = allocator.allocate(2)      # returns [1, 0]
# block 0 is handed out while sequence 1 still owns it -> two sequences
# share one KV block and silently overwrite each other's cache state
```

The same call path is reachable from production code: `DSStateManager.flush_sequence()` passes `seq.all_block_ids()` (a Tensor) into `BlockedKVCache.free()` -> `BlockedAllocator.free()`. Iterating that Tensor yields 0-dim tensors, which hash by identity -- so even a set-based duplicate check would be defeated without normalizing to `int`.

### Changes

1. In the validation pass, reject ids that appear more than once in the same `free()` call (`Block X provided multiple times to free`).
2. Normalize each element with `int(block)` before checking, so Tensor inputs go through the same code path.

No behavior change for valid inputs: the free-list mutation loop is untouched.

### Tests

Added `test_free_duplicate_block_rejected` in `tests/unit/inference/v2/ragged/test_blocked_allocator.py`:

- duplicate `free()` raises `ValueError`
- allocator state is unchanged by the failed call (`free_blocks` stays consistent)
- the blocks can still be freed exactly once afterwards, and a full allocate/free cycle yields no duplicate ids

### Test commands / results

- Pre-fix repro on CPU (pin_memory shim): `free([0, 0, 1])` succeeded and a subsequent `allocate(2)` returned `[1, 0]` -- block 0 allocated twice.
- Post-fix: the duplicate call raises `ValueError: Block 0 provided multiple times to free`; `free_blocks` stays consistent.
- `flake8` on changed files: clean.
- No GPU was required for this change: the allocator is host-side pure-Python logic; the added test runs under the existing `inference_v2` marker and only needs `BlockedAllocator` construction (CPU with pinned-memory shim locally; will exercise natively on the GPU CI runners).

### Duplicate check

Searched issues and PRs for `BlockedAllocator`, "already free", "allocated twice", "duplicate block" (both deepspeedai/DeepSpeed and legacy microsoft/DeepSpeed) -- no existing report. PR #8503 (fixing #5407) touches only `engine_v2.py` and does not include this fix.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Use normalized block IDs in the mutation pass**

When block 1 is allocated and a caller passes `free(True)` (or a 0-D bool tensor), the conversion validates ID 1, but the mutation loop still uses the original `True`. PyTorch treats that as a boolean mask, so `self._blocks[True] = ...` overwrites the whole free-list tensor while only incrementing `_free_blocks` once, corrupting allocator state; materialize the normalized IDs and use them in both passes (or reject booleans).
