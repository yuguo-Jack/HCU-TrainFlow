# AutoTP: shard an untied input embedding along the vocabulary (`vocab_…

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8859) · state: open · merged: False

## Original PR description

**Part of:** #8672 (Q4 2026 roadmap), "Enable training of large scale models".

## Summary

`vocab_parallel_lm_head` (#8309) shards an input embedding only when it is tied to the output layer. An untied input
embedding stays replicated on every tensor-parallel rank: on Qwen2.5-72B at TP 8 it is 1.25B of each GPU's 10.18B
parameters (12%), with its gradient, master copy and Adam states, and its gradient is the last one produced in
backward. This PR adds `tensor_parallel.vocab_parallel_embedding` (default `false`): AutoTP replaces the model's
untied `nn.Embedding` by the existing `VocabParallelEmbedding` (1/tp of the rows per rank, masked lookup, sum over
the TP group).

```json
"tensor_parallel": {
    "autotp_size": 8,
    "vocab_parallel_embedding": true
}
```

## Results

Qwen2.5-72B, 4 nodes x 8 H200 (EFA), AutoTP 8 x ZeRO-1 over 4, micro-batch 2, 64 x 8,192 tokens per step, bf16 with
fp32 master weights and Adam states, no recompute, Liger kernels for RMSNorm, rotary embedding and SwiGLU (applied by
our benchmark script); the two runs in one allocation, with this code in our study tree (together with the AutoTP
sequence-sharding changes, which are separate PRs):

| | Without | With |
|---|---|---|
| Step time | 15.88 s | 15.77 s |
| Peak memory (rank 0) | 114.1 GiB | 107.0 GiB |
| Embedding parameters per GPU | 1.25B | 0.16B |
| Gradient reduce after the last backward (`wall_clock_breakdown`) | 89 ms | 44 ms |

- `test_matches_single_device_training` (ZeRO 0 and 1): the input embedding becomes a `VocabParallelEmbedding` with

- jinyouzhi · comment · 2026-10-20T10:00:43Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8859#issuecomment-6288397240)

Thanks for picking this up. This fills the untied half of the tied/untied unification in RFC #8173 (#8582 handled tied + vocab-parallel head), so it fits well. A few points from tracing the paths on master:

1. **Tied + row-parallel head gives a misleading error.** With a tied model and a ROW `lm_head` spec (#8538), the embedding is already a `HiddenParallelEmbedding`, so `shard_untied_input_embedding` raises `needs ... nn.Embedding, got HiddenParallelEmbedding`. Could any embedding already replaced by a TP layer (e.g. `isinstance(embedding, TensorParallel_Layer)`) be treated like the `VocabParallelEmbedding` case (return `None`), or get an explicit message?

2. **Double partitioning with `partition_config`.** If a user spec matches the embedding (non-SKIP), `_slice_embedding` has already returned a new `nn.Embedding` sliced on the hidden dim (`[V, H/tp]`, `requires_grad=False`). That passes the `nn.Embedding` check and is then sharded on the vocab dim as well. Suggest raising when the weight already carries `DS_AUTOTP_UC_META` (or otherwise detecting a prior slice) and the user also set `vocab_parallel_embedding`.

3. **DeepCompile `autotp`.** The HF `tp_plan` path explicitly keeps embeddings replicated when the DeepCompile autotp pass is on ("does not support vocabulary-parallel embeddings"), but `finalize_autotp` shards unconditionally here. A guard (error or warning + skip) would keep the two consistent.

4. **HF `embedding_rowwise` for untied models.** HF transformers adds `embed_tokens: embedding_rowwise` whenever a model has a `_tp_plan`, and torchtitan / Megatron also shard the input embedding along vocab by default. Today that request is honoured only for tied heads (auto-enabling `vocab_parallel_lm_head`); for untied models it is converted to SKIP. Would you consider making the flag tri-state like `vocab_parallel_lm_head` (`None` = follow the HF plan), either here or as a follow-up?

5. **Tests.** The Llama test model probably goes through the HF `tp_plan` branch, so the heuristic and `partition_config` branches of `finalize_autotp` are not exercised. Cases that would be useful:
   - tied + `vocab_parallel_lm_head: true` + `vocab_parallel_embedding: true` -> no-op path (`return None`), still matches the reference;
   - untied + `vocab_parallel_lm_head: true` (both head and embedding sharded);
   - one of the non-HF branches (e.g. `partition_config`).
