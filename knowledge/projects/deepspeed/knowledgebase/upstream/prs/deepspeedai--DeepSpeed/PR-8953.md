# Initialize OneCycle momentum at the upper bound

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8953) · state: open · merged: False

## Original PR description

Fixes #8951.

A fresh `OneCycle` starts at minimum LR but previously applied minimum momentum to the optimizer, even though its computed schedule starts at maximum momentum. The first Adam moment update was wrong and subsequent parameter updates diverged from the inverse-cycle schedule.

## Change

- Initialize beta1 from `max_moms` for `last_batch_iteration == -1`.
- Preserve resumed optimizer settings and the `cycle_momentum=False` path.
- Correct the contradictory minimum-momentum docstring and clarify the first-update behavior in the existing tutorial.
- Exercise applied optimizer momentum rather than only computed scheduler values. Add real-engine Adam/reference comparisons for scalar and per-group bounds, cycling enabled/disabled, and the resume-constructor guard. Remove the old assertion that pinned the incorrect initial minimum.

No public API, configuration key, checkpoint format, beta2, post-cycle decay, or LR-step indexing change. First-update numerics deliberately change to match the documented inverse cycle.
