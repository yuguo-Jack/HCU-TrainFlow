# [fix] NPU: RoPE correctness, inverse-frequency caching, and KV cache preallocation in the inference op

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8776) · state: closed · merged: True

## Original PR description

## Summary

Fixes **two silent RoPE correctness bugs** on the NPU inference path (decode tokens were always rotated with the position-0 angle; prompt tokens were rotated with the wrong element pairing) and adds the missing **HF-style split-half rotary branch** (`rotate_half`, aligning the CUDA `launch_apply_rotary_pos_emb` kernel). Rotary angles now derive from a **cached inverse-frequency vector** (v2 inference pattern) instead of a per-forward float64 recompute chain. The KV cache moves from a per-token `torch.cat` (O(n²) per sequence) to a **preallocated buffer** with O(1) single-row decode writes, plus a GQA reshape fix. End-to-end on a real Qwen3-4B checkpoint, 32 generated tokens are **identical to the Hugging Face reference**; decode at n=32k is **2.4×** faster (KV path alone **10.6×**).

## Problem

`op_builder/npu/inference.py`

### RoPE

1. **Decode rotary position was always 0.** `seq_offset` was accepted but never used; every decode token was rotated with the position-0 angle. Evidence: same input with `seq_offset=0` and `100` produced identical outputs, matching the position-0 reference but not the position-100 one.
2. **Prompt rotary was wrong the whole time.** `npu_rotary_mul` was called without `rotary_mode`, so it used the default half-pairing while the cos/sin table is interleaved (`repeat_interleave(2)`); element pairing was scrambled during prompt processing.
3. **`advance_tokens()` was missing.** The CUDA csrc increments the token count after the last layer (`pt_binding.cpp:548`); the NPU version never did.
4. **`rotate_half=True` had no implementation.** The CUDA side applies HF-style split-half rotary through a dedicated kernel (`launch_apply_rotary_pos_emb`); the NPU op only had the every-two path, so HF Llama/GPT-NeoX/InternLM-class models silently lost RoPE entirely on NPU.
5. **Angles were recomputed every forward.** The full float64 `pow` chain (plus per-call H2D copies) ran on every call with no caching.

### KV cache

1. **The cache was rebuilt every decode step.** `torch.cat([k_cache, k], dim=2)` reallocates and copies the whole cache per token (O(n²) per sequence), followed by a second full copy for the contiguous BSH layout.
2. **GQA reshape used the wrong head count.** `k_cache/v_cache` were reshaped with `heads`; with GQA (`num_kv < heads`) element counts can happen to divide, silently reshuffling head dimensions instead of failing.

## Fix

- Rotary angles are now derived from a cached, position-independent `inv_freq` vector (keyed by `(rotary_dim, rope_theta, device)`, fp32), following the v2 inference pattern (`exaone4_5/model.py` registers `_rope_inv_freqs` at model init); per-forward derivation is `arange + seq_offset → outer → sin/cos`.
- `seq_offset` now drives the decode token's absolute rotation position; the decode position comes from the KV buffer row count (`kv_len`), keeping one source of truth.
- `npu_rotary_mul(..., 'interleave')` matches the interleaved table layout; a new `rotate_half` branch implements the HF split-half convention (pairing `j` with `j + rotary_dim/2`, side-by-side duplicated cos/sin, `npu_rotary_mul` default half mode), sharing the same cached `inv_freq`.
- `advance_tokens()` after the last layer, aligned with the CUDA csrc, and the v2 signature parameters (`is_prompt`/`token_idx`/`position_ids`) are accepted for interface alignment.
- KV is written into a preallocated buffer stored directly in the layout `npu_fusion_attention` consumes (`[bsz, cap, num_kv_heads * head_dim]`): a decode step writes one row (O(1)) and attention reads a zero-copy `[:, :kv_len]` view; the caller receives `[bsz, heads, len, head_dim]` transpose views (same semantics as the CUDA workspace tensors).
- Buffer capacity grows geometrically (2×) with prompt headroom `min(2P, P+2048)`, and is reused for fixed-length workloads (e.g. diffusers prompt-length forwards). Reuse validates shape/dtype/device, not just length.
- `k_cache/v_cache` are reshaped with `num_kv` instead of `heads` (validated end-to-end by the Qwen3-4B GQA run).

### Design notes

- **Capacity strategy**: the CUDA op allocates a full `max_out_tokens` workspace at construction. The NPU op has no access to the config at construction (static functions), and paying max-context memory up front is expensive on NPU for long contexts; geometric grow-on-demand was chosen instead. The growth copy is amortized O(1) per token.

## Results (all measured on 2*Ascend 910B4)

### Table 1 — RoPE transform, whole-function A/B (prompt seq=1024 / decode seq=1, fp16)

| Phase | Old (float64 recompute per forward) | New (cached inv_freq, fp32 chain) | Speedup |
| --- | --- | --- | --- |
| prompt | 1.163 ms | 0.896 ms | **1.3×** |
| decode | 1.095 ms | 0.819 ms | **1.3×** |
