# [checkpoint] universal state keys for non-Adam optimizers (fix #8608)

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8870) · state: open · merged: False

## Original PR description

## Background

DeepSpeed universal checkpoint conversion read Adam-specific optimizer state keys (`exp_avg`, `exp_avg_sq`) by hardcoded name. Issue #8608 reports that this prevents any non-Adam optimizer — Muon, Lion, SGD — from round-tripping through universal checkpoints: Muon keeps `momentum_buffer` for the matrices it orthogonalizes, and the converter raised `KeyError: "exp_avg"` before writing anything.

## Problem

Three hardcoded locations in the checkpoint pipeline, all reviewed by the issue author:

1. `ds_to_universal.py:extract_zero_shards` and `:extract_zero_shards_stage3` build `flat_state` from `exp_avg` / `exp_avg_sq` by name.
2. `ds_to_universal.py:merge_tp_slices` and `:merge_zero3_slices` iterate `for state in ("fp32", "exp_avg", "exp_avg_sq")` — plus `SCALE_POWER_BY_STATE[state]` which would crash on unknown states.
3. `stage3.py:load_hp_checkpoint_state_from_checkpoint_dir_stage3` ZeRO-3 loader does `for key in ["fp32", "exp_avg", "exp_avg_sq"]` and also assumes `state[0]["step"]` always exists.

Note: ZeRO-1/2 loader `load_hp_checkpoint_state` already discovers state names from the files in the folder, which is why only the three places above needed to change. Also DeepSpeed splits a Muon run into two param groups — Adam's pair for half the params and `momentum_buffer` for the matrices — so state keys must be discovered per param group (ZeRO-1/2) / per sub-group (ZeRO-3), not once for the whole checkpoint.

## Solution

**`deepspeed/checkpoint/affine.py`** — Added `"momentum_buffer": -1` to `SCALE_POWER_BY_STATE`. A gradient-like state takes scale power -1 (same as `exp_avg`). New optimizer states will be refused at tensor-parallel merge time unless someone adds them to this table, which is safer than silently guessing.

**`deepspeed/checkpoint/ds_to_universal.py`** — Three small helpers, and four call sites updated to use them:
- `_flat_state(param_group_id, state, fp32_flat_group)` — walks the param group's own state dict; keeps every tensor state that is shaped like the ZeRO partition, plus `step`. Refuses any state whose shape does not match (ZeRO-1/2 Muon replicates momentum_buffer whole per partition and can't be split this way yet; raising is safer than writing fragments that look right and hold the wrong rows).
- `_states_on_disk(slice_base_path, tp_degree)` — reads the fragment files the extraction wrote off disk; returns whatever state names are present. This keeps the merge from having to know which optimizer ran.
- `_scale_power(state, name)` — wraps `SCALE_POWER_BY_STATE` with a named error so missing states surface clearly at affine-map merge time.

Call sites updated: `extract_zero_shards`, `extract_zero_shards_stage3`, `merge_tp_slices`, `merge_zero3_slices`.

**`deepspeed/runtime/zero/stage3.py`** — Added `_universal_state_keys(checkpoint_dir, fp16_group)` which lists the `.pt` files the saved checkpoint wrote for one sub-group's parameters, excluding `step`. The ZeRO-3 universal loader now:
- Discovers state keys per sub-group, not once globally
- Takes `step` from whichever param group saved one (Muon's matrix group has no step count)

## Testing

This sandbox has no GPU, so the distributed Muon integration test from PR #8609 could not be run here. The code was verified by:
- Syntax-checking all three modified files (`ast.parse`)
- Manual diff review against the issue author's approach in PR #8609
- Static grep confirming the same three hardcoded locations cited in the issue were the only ones that needed changing

**Hardware**: N/A (CPU-only sandbox). **Software**: Python 3, torch not installed in this environment.

## Impact

- ZeRO-1, ZeRO-2 and ZeRO-3 universal checkpoint serialization now works with any optimizer that saves partition-shaped tensor states: Muon, Lion, SGD, and future custom optimizers
- No breaking change to existing Adam checkpoint format — Adam checkpoints will still save/load identically
- Fail-closed: states of wrong shape or unknown scaling now raise with a descriptive message instead of silently corrupting the checkpoint
- Known limitation from issue #8608: ZeRO-1/2 Muon's replicated whole-group `momentum_buffer` is explicitly refused in this change; full ZeRO-1/2 round-trip for Muon requires the separate momentum-buffer handling added in PR #8609 commits `051a0f5c7` and `aaf6ebce1`

Closes #8608
