# Add deepspeed.comm.pg_utils.is_parallel for optional parallel groups

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8815) · state: closed · merged: True

## Original PR description

Part of #8814, following @delock's suggestion in #8791 and the review discussion on where the helper should live.

## Change
- Add `deepspeed/comm/pg_utils.py` with `is_parallel(group)`: `group` is not `None` and spans more than one rank.
  - `comm.py` keeps the plain collectives, where `group=None` means the world group. In `pg_utils`, `group=None` means the parallel dimension is absent.
  - `pg_utils` is **not** star-exported from `deepspeed.comm`; callers write `from deepspeed.comm import pg_utils`, so the two meanings of `None` stay apart.
  - It is a predicate rather than a per-collective wrapper (an earlier revision had `all_reduce_if_parallel`), so one helper guards every primitive: sync or async all-reduce, all-gather, inference all-reduce, ...:
    ```python
    if pg_utils.is_parallel(group):
        dist.all_reduce(tensor, group=group)
    ```
- Replace the hand-written `group is not None and dist.get_world_size(group) > 1` guards, and variants that only check `None`:

| Area | Sites |
|---|---|
| sequence | `vocab_parallel_ops.py` (5; local `_tp_active`/`_all_reduce` removed), `cross_entropy.py` (4, `_global_sp_sum`, empty-shard check) |
| MoE | `sharded_moe.py` capacity MAX reductions (3) |
| inference v1 | `ds_mlp.py`, `triton/mlp.py`, `ds_attention.py`, `triton/attention.py`, `moe_inference.py` (async all-reduce, expert-MP all-gather and split) |
| ZeRO | `stage_1_and_2.py` / `stage3.py` `_model_parallel_all_reduce`, `stage3.py` AutoEP norm reductions (3) |
| AutoTP | `module_inject/layers.py`: `RowParallel` forward, `ScatterToTensorParallelRegion` / `ColumnParallel` backward, `LmHeadLinearAllreduce` forward; `TensorParallel_Layer` caches `is_tp_parallel = is_parallel(mp_group)` once at construction, used by the 6 `mp_group is None or tp_world_size == 1` guards in `LinearAllreduce` / `LinearLayer` / `SubParam*` / fused-QKV layers (no per-call cost) |
| other | `runtime/utils.py` MoE EP norm reductions (2) |

Behavior is unchanged. Sites that only checked `None` now also skip single-rank groups, where every guarded collective is a no-op.

Not migrated:
- Guards on a separately supplied size (`len(partition_sizes)`, a `tp_world_size` argument) in gather helpers: the size is not derived from a group.
- Sites where `None` means the world group: `kv_cache` warm-up, `moe_inference._alltoall`.
- AutoEP folding correction: its guard covers more than a collective.
- Engine/ZeRO DP buckets.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Skip process groups that exclude this rank**

When a caller passes a process group that excludes the current rank, `get_world_size(group)` returns `-1` per this module's contract, so this equality check falls through even though there is no local work. This regresses the replaced `> 1` guards and is not harmless on the custom CCL backend: `CCLBackend.get_all_ranks_from_group` derives an empty rank list and calls `_new_group`, which indexes `ranks[0]`; reduce only when the reported size is greater than one so non-members skip the collective.
