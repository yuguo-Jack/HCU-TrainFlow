# Fix FP16 optimizer init: suppress weight decay and reset step counter

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8987) · state: open · merged: False

## Original PR description

## Summary

`initialize_optimizer_states()` runs a synthetic `optimizer.step()` with zero gradients to eagerly allocate internal state tensors (exp_avg, exp_avg_sq, etc.). With AdamW this has two side effects:

1. **Weight decay modifies master weights** before any real training (e.g. 0.5 becomes ~0.4995 with weight_decay=0.1)
2. **Step counter advances to 1**, skewing bias correction on the first real update

This PR fixes both `FP16_FusedOptimizer` and `FP16_UnfusedOptimizer` by:
- Temporarily zeroing `weight_decay` in all param groups during the synthetic step
- Resetting the step counter to 0 afterward

This preserves the eager state allocation (important for memory planning and checkpoint compatibility) while eliminating the numerical side effects.

Fixes #8910

## Test plan

- Added `TestFP16InitNoSideEffects` with two cases:
  - `test_adamw_master_weights_unchanged`: verifies FP32 master weights match the original FP16 parameters after init
  - `test_adamw_step_counter_zero`: verifies optimizer step counter is 0 after init

pytest tests/unit/runtime/half_precision/test_fp16.py::TestFP16InitNoSideEffects -v

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Restore NAdam's auxiliary state when rewinding its step**

For stage-0 FP16 with `torch.optim.NAdam`, which the engine accepts through its generic torch-optimizer path, the synthetic zero-gradient step also advances `state['mu_product']` to approximately 0.45. Resetting only `step` leaves that cumulative momentum product advanced while rewinding the variance bias correction. Consequently, even with zero weight decay, the first real unit-gradient update at default settings becomes approximately `0.739 * lr` instead of a fresh NAdam optimizer's `1.056 * lr`, introducing a substantial numerical regression. Restore the auxiliary step-dependent state as well, or restrict this rewind to optimizers whose remaining state is unaffected by the synthetic step.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Read the AdamW master weights through the unfused wrapper**

On FP16-capable devices, the supplied `torch.optim.AdamW` selects `FP16_UnfusedOptimizer` in `DeepSpeedEngine._configure_fp16_optimizer`. That wrapper exposes nested `fp32_groups`, not `fp32_groups_flat`, so this test raises `AttributeError` before checking any weights and fails the new regression suite. Read the master parameters through the public `opt.param_groups` interface and compare corresponding parameters rather than assuming the fused wrapper's flattened layout.
