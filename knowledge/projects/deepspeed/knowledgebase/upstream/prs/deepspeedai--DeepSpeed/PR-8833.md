# Fix TestLionConfigs on the CPU accelerator and run it on every runner

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8833) · state: closed · merged: True

## Original PR description

#8813 registered CPU Lion for the CPU accelerator. `TestLionConfigs` (`tests/unit/ops/lion/test_lion.py`) gated both of its cases on `CPULionBuilder` only, so on the CPU accelerator the non-offload case now runs and builds `FusedLion`, which has no CPU implementation:
```
ValueError: This op had not been implemented on CPU backend.
```

#8813's CI did not catch it because `test_lion.py` was skipped at module level unless the accelerator supports fp16. On the CPU accelerator that needs native fp16 support (AVX512-FP16), which few GitHub-hosted runners have (4 of 37 recent `cpu-torch-latest` runs). All six CPU runs of #8813 landed on runners without it.

## Changes
- Gate each config on the op it builds: the `FusedLion` case on `FusedLionBuilder` and the `DeepSpeedCPULion` case on `CPULionBuilder`, instead of one `CPULionBuilder` check for both. 
- Run the test in fp32 and remove the module-level fp16 skip. The test only checks which optimizer `deepspeed.initialize` builds, and that depends on optimizer offload, not precision (`_configure_basic_optimizer` in `engine.py`). The test now runs on every runner instead of only on fp16-capable CPUs. The Lion ops are still tested in fp16 by `TestCPULion` in `test_cpu_lion.py`.
