# Restore fp32 masters for ZeRO-3 and the ZeRO-1 BF16 optimizer

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8892) · state: open · merged: False

## Original PR description

## Summary
- Stacked on #8891. This branch now includes that pull request through `894a2b72`. The new delta is ZeRO-3 and the dedicated ZeRO-1 BF16 optimizer.
- `load_checkpoint` still always restores saved fp32 masters. `load_optimizer_states=False` keeps those masters and starts Adam with fresh moments. `load_module_only=True` rebuilds the dedicated BF16 optimizer from the loaded bf16 weights. ZeRO-3 still reads its fp32 partition on a module-only load, because the model checkpoint does not hold the partitioned weights.
- `ZeRO-3` and `BF16_Optimizer.load_state_dict(..., load_from_fp32_weights=False)` now rebuild the masters from the bit16 weights, matching ZeRO stage 1 and 2. `DeepSpeedEngine.load_checkpoint` passes true, so a normal resume keeps the saved masters. `zero_optimization.load_from_fp32_weights` stays deprecated and ignored.

AI assistance was used to implement and test this change. This does not duplicate an open DeepSpeed PR.

## Test plan
- [x] `tests/unit/checkpoint/test_fp32_master_stage3_bf16.py` with torch 2.9.1+cu130, Python 3.12.12, gloo, world size 1, commit `b190a3f7`: 2 passed. The dedicated BF16 optimizer keeps the saved masters when optimizer state is skipped and rebuilds them for `load_module_only=True`. ZeRO-3 keeps the saved masters for both of those loads. Adam moments stay fresh.
- [ ] Not run on the 4×H200 node. The #8891 suite there does not cover these two optimizers.

Validated cells: dedicated ZeRO-1 BF16 optimizer and ZeRO-3, same data-parallel size, legacy checkpoint, bf16, no offload. Open cells: fp16, MoE, NVMe offload, and a data-parallel size change.

When `load_optimizer_states=False` and FP32 masters are requested (the new default path), this operand now sends a normal legacy load through `_load_zero_checkpoint`. When ZeRO-3 optimizer offload uses NVMe (`swap_optimizer=True`), the following branch skips `_load_zero_checkpoint`, while the later NVMe block unconditionally copies all saved swap files and `reset_swap_buffers()` swaps the saved FP32 parameters back into the bit16 partitions.
