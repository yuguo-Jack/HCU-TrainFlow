# [ROCm] Fix the ROCm build of inference_core_ops

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8937) · state: open · merged: False

## Original PR description

The following changes are made to enable `inference_core_ops ` extension on `ROCm`:

- Compile the ROCm HIP kernels as `C++20` when PyTorch is 2.12 or newer. 

- Under` hipBLAS v2`, use `hipDataType` for the GEMM datatype. hipify was turning `cublasDataType_t ` into `hipblasDatatype_t`, which this hipBLAS no longer defines.

- On AMD, pass a 64-bit mask to `__shfl_sync `in the FP6 dequant kernel. 0xffffffff is a 32-bit unsigned int, and this HIP build rejects it.

- Pass `QUANT_GEMM_Kernel ` to `cudaFuncSetAttribute` through a concrete function pointer. After hipify, `hipFuncSetAttribute` only accepts `const void*`, and the `__global__` template did not convert. On CUDA, `cudaFuncSetAttribute` still sets `cudaFuncAttributeMaxDynamicSharedMemorySize` on the same kernel.

- PyTorch's hipify keeps the `.cpp` extension and appends _hip to the stem, so `bias_activation.cpp` becomes `bias_activation_hip.cpp`. The CUDA source `bias_activation_cuda.cu` becomes `bias_activation_hip.hip`, which has the same stem. Both compile to `bias_activation_hip.o`, and that duplicate object caused the link error. Renaming the host file to `bias_activation_host.cpp` gives `bias_activation_host_hip.cpp` and avoids the clash. Thee same changes are made to `gated_activation_kernels.cpp` file too.
  - deepspeed/inference/v2/kernels/core_ops/bias_activations/bias_activation.cpp → bias_activation_host.cpp
   - deepspeed/inference/v2/kernels/core_ops/gated_activations/gated_activation_kernels.cpp → gated_activation_kernels_host.cpp

## Test
JIT Build
```
import deepspeed.ops.op_builder as op_builder
op_builder.InferenceCoreBuilder().load()           # inference_core_ops
```

non-JIT Build
```
cd DeepSpeed
DS_BUILD_OPS=0 DS_BUILD_INFERENCE_CORE_OPS=1 python3 setup.py build_ext --inplace
```
