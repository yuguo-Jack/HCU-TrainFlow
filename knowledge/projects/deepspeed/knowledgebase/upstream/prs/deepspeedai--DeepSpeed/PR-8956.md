# Fix ZeRO-1/2 lazy optimizer-state linking for all parameter groups

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8956) · state: open · merged: False

## Original PR description

## Summary

ZeRO stages 1 and 2 update optimizer parameter groups one at a time and call
`_lazy_init_hp_params_optimizer_state()` after each group. That method linked
whatever optimizer state existed at that moment and then unconditionally set
`_hp_optimizer_states_linked = True`. Groups that had not been stepped yet
therefore never linked their Adam moments after their own update, and
`safe_get_full_optimizer_state()` raised:

```
ValueError: exp_avg not found in optimizer state fragment
```

for every group after the first.

This change:

- makes `lazy_init_hp_params_optimizer_state()` report whether a group's
  optimizer state exists yet, and set the fragments for that group;
- passes the just-stepped group index from `_optimizer_step()` so only that
  group is inspected, and tracks linked groups individually. A group that still
  has no state is retried on its next update, so the work per group update is
  bounded by one group rather than a rescan of all of them;
- keeps `_hp_optimizer_states_linked` false until every group has been linked;
- adds a two-rank regression test with separate `weight` and `bias` parameter
  groups for ZeRO stages 1 and 2, asserting both moments after the first step;
- adds a unit test pinning that linking after a group update inspects only that
  group.

`BF16_Optimizer` shares the helper but is not affected: it calls `step()` once
for all parameter groups before linking, so every group already has its state.
That wrapper is unchanged.

Fixes #8911.

- YidaWeng · comment · 2026-10-30T13:23:18Z · [source](https://github.com/deepspeedai/DeepSpeed/pull/8956#discussion_r4424070642)

File: `deepspeed/utils/mixed_precision_linkage.py` · line None

Good catch — that is a real regression, and it is fixed in 8b1f41e.

The hook is no longer a rescan. `_optimizer_step()` now passes the group it just updated, `_lazy_init_hp_params_optimizer_state(group_no)` inspects only that group, and linked groups are tracked in a set, so an already-linked group returns immediately. A group whose state appears later is retried on its own next update.

For a stateless optimizer the helper still returns `False` every time, but the cost per group update is now one `optimizer.state.get()` and a no-op fragment set for that single group, instead of walking all N groups and rebuilding the mappings of the stateful ones. The global flag stays false in that case, which is harmless because it is only used as the fast path inside this method.

I did not mark a stateless group complete from state-dict truthiness, because a stateful optimizer can legitimately leave a group without state (for example a group whose params have no gradients yet), and that group still has to link once its state appears. The per-group retry handles both cases without the quadratic scan.

I also reverted the `BF16_Optimizer` change: that wrapper calls `step()` once for all groups before linking, so every group already has state there and it never had the ordering defect.

Added `test_lazy_init_only_inspects_the_group_that_stepped`, which fails against the previous scan-all implementation and passes now.
