# ZeRO-3 NVMe offload: restore the optimizer state on resume

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8984) · state: open · merged: False

## Original PR description

## Summary

With NVMe optimizer offload, `load_checkpoint` has skipped the ZeRO optimizer checkpoint since #7613, which avoided a crash on load (#7549). A resumed run therefore loses the Adam state, the lr, the fp16 loss scale, and the weights of the sub-groups too small to swap.

Cause of the crash: the optimizer states of swapped sub-groups are saved as empty tensors. The swapper only swaps tensors above a minimum size, so it did not read them back, and CPU Adam stepped on empty tensors.

This PR loads the ZeRO checkpoint again, after the swap files are copied. Before the swap-in, each empty state gets the size of its sub-group, without allocating memory, so the swapper reads it from the swap files. Muon momentum kept in memory (`save_muon_momentum_buffer_in_memory`) is loaded into its existing buffer.
