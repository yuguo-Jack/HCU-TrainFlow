# Preserve explicit dtype in zero.Init tensor constructor wrappers

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/9006) · state: closed · merged: False

## Original PR description

`zero_wrapper_for_fp_tensor_constructor` unconditionally casts every floating-point result to `target_fp_dtype` (e.g. bfloat16), even when the caller passed an explicit `dtype=torch.float`. This silently corrupts RoPE `inv_freq` in transformers models under ZeRO-3: the `torch.arange(..., dtype=torch.float)` inside rotary embedding init is computed in bfloat16, producing angle errors of ~118 rad at position 65536.

**Fix:** skip the cast when the caller passed a non-None `dtype` kwarg. The same guard is added to `get_new_tensor_fn_for_dtype` for consistency.

**Testing:** added `tests/unit/runtime/zero/test_zero_init_preserve_dtype.py` covering explicit float32/float64, no-dtype, `dtype=None`, integer dtypes, and multiple creation functions (`empty`, `zeros`, `ones`, `randn`).

Fixes #8948
