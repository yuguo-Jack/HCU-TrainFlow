# fix(rollout): pass a pre-built 4-D mask to the static graph decode forward

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/9004) · state: open · merged: False

## Original PR description

Closes #9000.

## Problem

With `use_graph_capture=True` and no `continuous_batch_size`, `_generate_graph` gives the captured decode forward a 2-D attention mask, so Transformers builds the causal mask during capture. That fails on the supported versions:

- **4.57.x with SDPA:** `padding_mask.all()` runs on the host and breaks capture with "operation not permitted when stream is capturing" (reported by @0z5a on #8197).
- **5.x:** Transformers calls `get_query_offset`, which `DeepSpeedStaticCache` doesn't have.

## Fix

The captured forward now gets a pre-built 4-D additive mask. The mask is refreshed before each replay, and prefill is unchanged. The fix is cherry-picked from @0z5a's commit.

`_generate_graph` also raises a `ValueError` for `flash_attention_2`, as the continuous graph path does, because it can't use a 4-D mask.

#8602 includes the same mask change, but it's a much larger PR that will take a while to merge. #8852 is still needed for continuous batching without graphs on 5.x.

## Compatibility

- **Validated:** CUDA on an A40; fp32, fp16 and bf16; eager and SDPA attention; Transformers 4.57.6, 5.19.0 and 5.22.1.
- **Not validated:**
  - accelerators other than CUDA
  - hybrid models
  - the `flash_attention_2` rejection on a real FlashAttention model

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Preserve sliding-window constraints in the 4-D decode mask**

When graph capture is used with a sliding-window causal model such as Mistral and the context exceeds `config.sliding_window`, this mask only encodes padding and therefore leaves every older cache column visible. Transformers treats a supplied 4-D mask as already prepared, so it no longer adds the model's sliding-window exclusion as it did for the previous 2-D mask; the captured path can consequently produce silently different tokens from `model.generate()`. Build the precomputed mask with the model's local-attention rules, or reject such configurations explicitly.
