# Fix uint8 parameter broadcast for 0-dim parameters

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8866) · state: closed · merged: False

## Original PR description

#8416 changed the parameter broadcasts in _broadcast_model and ZeRO-3 to send p.data.view(torch.uint8), so that narrow dtypes the comm backend doesn't support (FP8 / MX / NVFP4) are sent as raw bytes. However, a dtype view to a type with a different element size needs a last dimension to reinterpret, so it fails on 0-dim parameters:
`RuntimeError: self.dim() cannot be 0 to view BFloat16 as Byte (different element sizes)`
Fix:
Add `as_byte_view(tensor)` to deepspeed/runtime/utils.py. It views 0-dim tensors as 1-dim (view(1)) before the uint8 view. The result still shares storage with the original tensor, so the broadcast remains in-place. pls help review, thx! @delock @sfc-gh-abkulkarni
