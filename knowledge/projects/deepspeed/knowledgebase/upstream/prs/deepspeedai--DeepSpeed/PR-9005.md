# Fix duplicate CSV monitor headers after restart

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/9005) · state: open · merged: False

## Original PR description

Restarting a CSV monitor with the same `output_path` and `job_name` currently appends another header in the middle of the existing metric data. Check whether the opened append-mode file is empty before writing the header, instead of tracking filenames per monitor instance. Existing rows and appended values are preserved.

The regression tests use real files and single-rank Gloo to cover new/empty files, repeated writes, and a second monitor instance appending to the same file. The monitoring tutorial documents the append behavior.

Validation :
- Before the fix: the restart case fails with a second header; new/empty-file cases pass. After the fix: all 3 cases pass.
- Two independent processes using `MonitorMaster` append to the same file: one header and both records retained.
- Changed-file pre-commit checks and `git diff --check` pass. Source distribution and wheel build with `DS_BUILD_OPS=0`.

```bash
DS_ACCELERATOR=cpu LOCAL_SIZE=1 CUDA_VISIBLE_DEVICES=0 \
  uv run --no-project --python /tmp/deepspeed-csv-test-env/bin/python \
  pytest tests/unit/monitor/test_monitor.py -k TestCSVMonitorFiles --torch_ver=2.9.1 --color=no
```


Duplicate check: searched open PRs and all-state issue/PR results for `csv`, `csv_monitor`, `csvMonitor` and `duplicate header`; found no same-scope fix. #8971 concerns emitting training loss, #8401 concerns configuration metrics, and #8065 adds Trackio. TensorBoard, WandB and Comet delegate to their own backends and do not share this header logic.
