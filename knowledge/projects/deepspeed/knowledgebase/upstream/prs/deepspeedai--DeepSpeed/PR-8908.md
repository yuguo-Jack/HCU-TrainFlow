# Fix ZeRO-3 NVMe module-only checkpoint weight refresh

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8908) · state: open · merged: False

## Original PR description

## Summary

ZeRO-3 module-only loading with NVMe optimizer offload tries to refresh an empty FP32 swap placeholder before its weights have been restored. The original baseline also took the ordinary `zero_to_fp32` reconstruction path for explicit `load_optimizer_states=False`, which could not reconstruct the empty swapped partitions; #8891 has since replaced that engine flow. This change restores only FP32 weights from the NVMe files and resident ZeRO shards, materializes the low-precision model, and then refreshes the masters through the swapper. Live optimizer moments are retained.

Refs #8890 (the NVMe module-only subsection only). #8891 and #8892 change neighboring master-only restore paths and explicitly leave the NVMe follow-up open. #8897 tracks the separate DP-size rejection regression; #8898 fixes successful serial handoff.

Restoration requires identical DP size, ordered parameter/subgroup layout, master dtype, and swap storage layout. Those conditions are checked before subgroup writes. `custom_load_fn` is rejected for this combination instead of silently overwriting callback-supplied weights. Other checkpoint branches retain their existing flow.
