# Link every param group's optimizer state in ZeRO-1/2

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8643) · state: open · merged: False

## Original PR description

With more than one param group, ZeRO-1/2 can't read or write the optimizer state of any group after the first:

```python
# two groups, e.g. weight decay on/off
safe_get_full_optimizer_state(bias, "exp_avg")
# ValueError: exp_avg not found in optimizer state fragment
```

With two ranks only the rank holding the param raises, and the other one hangs when it reads the result.

The cause is the lazy linking from #5104. `_optimizer_step` steps the groups one at a time, but all of them get linked right after the first group's step, when the rest have no state yet, and it never runs again. It worked before #5104, and ZeRO-3 is fine.

This links each group after its own step instead.

The fragment tests only ever used one group, so I added `TestTensorFragmentOptimizerStatePerGroup` with two groups, which compares `exp_avg` and `exp_avg_sq` against plain PyTorch AdamW. It fails on master and passes here. Fragment and checkpoint tests pass on 2×H20 (174 passed).


## Environment

NVIDIA H20-3e, driver 580.105.08, Python 3.11.15, torch 2.9.1+cu128; the runs above used 2 GPUs.
