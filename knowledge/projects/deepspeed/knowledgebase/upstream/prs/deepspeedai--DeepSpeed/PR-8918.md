# Keep empty gradient-norm ranks in collective reductions

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8918) · state: open · merged: False

## Original PR description

Fixes #8912.

`get_global_norm_of_tensors` fails when a rank has no local norm inputs, leaving peers in a collective. Materialize iterable inputs once and use a device-local FP32 zero for empty positive p-norm and infinity-norm contributions. Keep the existing model/expert/pipeline group choices and collective order. Nonempty results retain their input-device placement.

Validation: 2 x NVIDIA GeForce RTX3090 24GB, driver580.105.08, torch2.12.1+cu130, CUDA13.0, NCCL2.29.7, Python3.12.3. On upstream bf222a2a, a two-rank NCCL reproduction fails with `stack expects a non-empty TensorList` on the empty rank; a nonempty generator regression fails for the same reason. With the fix:

```
python -m pytest --forked tests/unit/runtime/test_runtime_utils.py --torch_ver=2.12.1+cu130 --cuda_ver=13.0 -q
27 passed
```

Coverage includes L1/L2/L3/infinity, one/all/no empty ranks, real model/expert groups, generators, output dtype/device, and a public-engine BF16 ZeRO1 TP2/DP1 clipped-SGD update with an empty norm rank. Changed-file pre-commit checks pass. The committed-diff CI selector identifies 87 impacted v1 test files; those broader tests have not all been run locally.

Duplicate check: no open PR found for #8912 or this empty-input fix. Existing #8478/#8635 address norm accounting rather than empty collective participants. Sibling flattened/ZeRO norm helpers were inspected and are unchanged. No production convergence or throughput claim; other accelerators, full folded-MoE models, offload, and combined pipeline/expert topologies are unvalidated.

## One remaining edge case

An iterable containing a zero-element tensor is still not covered:

```python
get_global_norm_of_tensors([torch.empty(0)], norm_type=2)          # 0.0, OK
get_global_norm_of_tensors([torch.empty(0)], norm_type=float("inf"))
# RuntimeError: max(): Expected reduction dim to be specified for input.numel() == 0.
```

Zero-size tensors are reachable (zero-size parameters / sharded grads), and `_get_local_norm_contribution` currently only handles an empty iterable, not an empty tensor inside a non-empty iterable.

Suggested change:

```diff
 def _get_local_norm_contribution(input_tensors, norm_type, device):
     """Compute the FP32 input to the global MAX or SUM reduction."""
-    if not input_tensors and norm_type > 0:
-        return torch.zeros((), dtype=torch.float32, device=device)
-
     all_norms = []
     for tensor in input_tensors:
         if norm_type == inf:
+            if tensor.numel() == 0:
+                continue
             tensor_norm = tensor.detach().abs().max().float()
         else:
             tensor_norm = tensor.detach().float().norm(norm_type)
         all_norms.append(tensor_norm.to(device))
 
+    if not all_norms and norm_type > 0:
+        return torch.zeros((), dtype=torch.float32, device=device)
+
     local_norms = torch.stack(all_norms)
```

Regression case to add next to `TestGlobalNormEmptyInput`:

```python
@pytest.mark.parametrize("norm_type", [2, float("inf")])
def test_zero_element_tensor(norm_type):
    norm = ds_utils.get_global_norm_of_tensors([torch.empty(0)], norm_type=norm_type)
    assert norm.item() == 0.0
```

With that applied locally, all of the above pass, including mixed inputs: `[torch.empty(0), torch.tensor([3., 4.])]` → inf 4.0 and p=2 5.0.

I can't push to your branch, so please take the diff as-is if useful. The only other thing I'd flag is that the CUDA/NCCL path has not been rerun since the refactor because CI is blocked; a green CUDA run would be good before merge.
