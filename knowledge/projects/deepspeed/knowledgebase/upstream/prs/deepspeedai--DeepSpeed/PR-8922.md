# Check where column-split pieces write in a shard

[Upstream PR](https://github.com/deepspeedai/DeepSpeed/pull/8922) · state: closed · merged: True

## Original PR description

`ParamAffineMap.validate()` checks where a piece writes in its shard only when the piece's destination is one dense interval. That check came from #8624. A column split has no such interval: each piece writes a few columns of every shard row. So for fused QKV split along columns, Yuan's o_proj, or any `sub_param_map` / `segmented_map` / `block_gather_map` with `partition_dim=1`, two pieces can write the same shard columns and pass every check.

Reproduction on `master` (fused QKV `(4, 12)` split along columns at TP 2):
1. Move rank 0's value piece onto its key columns.
2. `validate()` and `validate_coverage()` both pass.
3. `rebuild(extract(F))` differs from `F` in 8 of 48 elements.
4. Two columns of rank 0's shard are never written by `extract`, so they hold uninitialised memory.

## Changes

- **`validate()`** now also checks strided pieces, still from metadata only, without walking elements.
  - Bounds: each strided piece's lowest and highest shard address must lie inside the shard.
  - Overlap: a column-split piece is a box in its shard's row-major grid, so overlap between such pieces follows from their corners. A strided view that wraps past the end of a shard row is valid but is not a box; the full check below covers it.
  - The box pass runs only on ranks that hold a strided piece. Ranks with only dense pieces cost the same as before.
- **`validate_coverage()`**, the full O(n) check, now walks every shard address and requires each one to be written exactly once. Together with the element-count check, that makes "every shard address is written by exactly one element" a complete check, for any stride, including strided pieces that are not boxes.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Keep wrapped strided views valid**

When a legitimate strided destination starts near the end of a shard row but all of its storage addresses remain in bounds, this branch rejects it. For example, in a `(3, 3)` shard, an `AffinePiece` with shape `(2, 2)`, `dest_offset=2`, and `dest_strides=(3, 1)` visits flat addresses `2, 3, 5, 6`, but `_dest_box` computes a column stop of 4, `_dest_interval` returns `None`, and `validate()` now raises. Because destinations are arbitrary `torch.as_strided` views over `_flat_buffer`, serialized or custom maps using such wrapped views can no longer rebuild; bounds should be checked against the actual flat address range while box coordinates are used only when the view fits the shard grid.
