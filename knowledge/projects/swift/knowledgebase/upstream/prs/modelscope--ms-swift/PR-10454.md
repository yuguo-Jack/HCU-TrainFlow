# PR information

Related issue: none.

`CheckpointEngineManager` currently waits for each rollout replica to finish sleeping or waking before starting the next. With many replicas, these independent operations add substantial latency to every training/generation handoff.

This change submits sleep/wake requests to every server across all replicas, then waits once for completion. Phase barriers, sleep settings and partial-wake behavior are preserved. Sleeping state is updated only after all requests succeed. Regression tests and English/Chinese documentation are included.

Prepared with Codex assistance.

## Experiment results

Controlled lifecycle-only A/B on one node with 8 H200 GPUs, using the same live vLLM actors and generated two-layer Llama model (hidden size 128, vocabulary 128). The benchmark alternates the unchanged upstream and candidate managers. Ray zero-copy tensor transport is disabled for both. Each mode has two warm-up cycles and six measured cycles at 1, 2, 4 and 8 replicas. One GPU per replica, TP=1, sleep level 1, eager execution.

Mean driver wall times with **8 replicas**:

| Phase | Sequential | Concurrent | Speedup |
|---|---:|---:|---:|
| Sleep | 2.6934 s | 0.4719 s | 5.7× |
| Wake weights | 0.0404 s | 0.0218 s | 1.9× |
| Wake KV cache | 2.5527 s | 0.4207 s | 6.1× |

The single-replica control is essentially unchanged. Greedy outputs match after every cycle in both modes. These measurements isolate lifecycle scheduling for this tiny-model setup; they do not establish a full-training speedup or the exact gain for 32 replicas. Runtime: Ray 2.59.0, PyTorch 2.13.0+cu130, vLLM 0.32.0.

Validation of this upstream implementation:

- `python -m pytest tests/megatron/test_ray_rollout_lifecycle.py -q`: **9 passed** locally and with the GPU training runtime's dependencies. Unchanged upstream fails the 3 concurrency cases. Tests cover secondary servers, submission-before-wait ordering, partial wakes, repeated calls and failure propagation.
- `pre-commit run --all-files`: **passed**.
- Two-H200 smoke test with two native vLLM replicas and a generated tiny Llama: repeated sleep, partial/full wake and shutdown while asleep passed, with identical greedy outputs after waking. This was a single-host TP=1 test.
