# PR information

Before NPU training, users need to collect environment information from Python packages, Ascend installation directories, and `npu-smi` separately. This makes troubleshooting and providing reproducible environment details in issues more cumbersome.

This PR adds a standalone script, `examples/ascend/check_env.py`, that users can run manually in their training Python environment. It presents component versions, installation locations, and NPU management information in grouped tables.

Changes:

- Organize the report into four sections: basic environment, software components, Ascend installation information, and NPU status. The Note column displays available locations, with automatic wrapping for long paths.
- Query Python package information through the standard-library `importlib.metadata` API, without importing ms-swift or training frameworks or adding third-party dependencies.
- Extract version fields from driver/CANN version files instead of printing their full contents.
- Apply a five-second timeout to `npu-smi info` and continue collecting other information when a component is missing or an individual probe fails.
- Add Chinese and English documentation and nine unit tests.

### Usage

Run from the repository root using the Python environment used for training:

```bash
python examples/ascend/check_env.py
```

To save the report:

```bash
python examples/ascend/check_env.py > env_report.txt
```

### Supported inspection scope

The following table defines the complete inspection scope of this PR. The script does not automatically diagnose every training dependency.

| Section | Component/item | Information collected |
| --- | --- | --- |
| Basic environment | OS | System name, kernel/system version, and architecture |
| Basic environment | Python | Current interpreter version and executable path |
| Software components | PyTorch (`torch`) | Distribution version and installation location in the current Python environment |
| Software components | torch-npu (`torch-npu`) | Distribution version and installation location |
| Software components | ms-swift (`ms-swift`) | Distribution version and installation location |
| Software components | Megatron Core (`megatron-core`) | Distribution version and installation location; MISSING when distribution metadata is absent |
| Software components | MindSpeed (`mindspeed`) | Distribution version and installation location; MISSING when distribution metadata is absent |
| Software components | mcore-bridge (`mcore-bridge`) | Distribution version and installation location; MISSING when distribution metadata is absent |
| Ascend installation information | Ascend driver | Version from `/usr/local/Ascend/driver/version.info` and its containing directory |
| Ascend installation information | CANN | Version from files in configured/common installation paths and the containing directory |
| NPU status | `npu-smi info` | Tool path, query status, and raw output, including device model, health, and utilization information provided by the tool |

### Constraints and limitations

- **Information collection only.** FOUND means information was obtained; it does not confirm that a component can be imported, executed, or used compatibly with other components, or that the environment is ready for training.
- **Package detection relies on distribution metadata for the current interpreter.** Source trees added through `PYTHONPATH` without distribution metadata may be reported as MISSING even when the source exists. Note shows the distribution location, which may differ from the module actually loaded or an editable source directory.
- **Megatron Core, MindSpeed, and mcore-bridge are optional depending on the training backend.** Their absence is reported individually and does not imply an unusable basic training environment.
- **Driver/CANN detection targets common Ascend Linux installation layouts.** CANN checks roots configured through `ASCEND_HOME_PATH` / `ASCEND_TOOLKIT_HOME` first. When neither is set, it checks `/usr/local/Ascend/ascend-toolkit/latest` and `~/Ascend/ascend-toolkit/latest`. It looks only for `version.cfg`, `version.info`, `ascend_toolkit_install.info`, and `cann_install.info` in these roots and their `aarch64-linux` / `x86_64-linux` subdirectories. Nonstandard paths or unrecognized version formats may produce UNKNOWN.
- **Version files do not identify the dynamic libraries loaded at runtime.** The script reports the first recognized version and does not audit multiple CANN installations or library-loading precedence.
- **The report is local and read-only.** It does not source environment scripts, install or repair components, inspect all nodes, execute NPU tensor operations, test HCCL communication, or initialize Megatron. The `npu-smi` output does not validate device visibility for the training process.
- **Dependencies outside the listed scope are not inspected.** DeepSpeed, Transformers, vLLM, firmware versions, and topology tests are outside this PR. The existing NPU tensor availability check remains documented as a separate runtime verification step.

Status definitions:

| Status | Meaning |
| --- | --- |
| FOUND | Component or tool information was obtained successfully |
| MISSING | Package distribution metadata or the `npu-smi` executable was not found |
| UNKNOWN | No recognizable version/device information was obtained, for example because a version file could not be read or `npu-smi` returned empty output |
| UNAVAILABLE | A query failed, timed out, or raised an exception during an individual probe |

## Experiment results

### Hardware run

The contributor-provided `check_env_output.txt` shows the following results:

- Linux x86_64 and Python 3.11.16.
- PyTorch 2.10.0+cpu, torch-npu 2.10.0.post4, and ms-swift 4.6.0.dev0.
- Ascend driver 25.7.rc1 and CANN 9.1.0.
- `npu-smi` returned information for eight Ascend950PR devices, all with Health reported as OK.
- Distribution metadata for Megatron Core, MindSpeed, and mcore-bridge was not detected, and the script still completed the remaining probes.

These observations validate information collection in this environment; they do not establish compatibility for the version combination or all device generations.
