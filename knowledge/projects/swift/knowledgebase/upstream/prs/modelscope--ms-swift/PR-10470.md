# PR information

Related issue: none.

Ray Megatron completion logging formats the same prompt separately for every response. With 32 prompts and 16 responses each, that encodes and decodes prompts 512 times.

Reuse formatted JSON-compatible prompts within one logging call, reducing that example to 32 formatter calls. Keep the dictionary local to the loop; preserve response order, rewards, generation-step fields and prompt IDs. Unsupported inputs and JSON coercions use the original formatter, including its fallback rendering. Add discoverable unittest coverage, paired Ray docs and an offline benchmark.

AI assistance (Codex) was used to prepare the implementation, tests and description.

## Experiment results

Base: `modelscope/ms-swift@d907e329cf27391cd21ae19a7cb0b3c07dc46173`.

```bash
python tests/run.py --pattern test_ray_prompt_logging.py
git show d907e329cf27391cd21ae19a7cb0b3c07dc46173:swift/ray/megatron/base_trainer.py > /tmp/ray-prompt-logging-baseline.py
python scripts/benchmark/ray_prompt_logging.py --baseline /tmp/ray-prompt-logging-baseline.py
python scripts/benchmark/ray_prompt_logging.py --baseline /tmp/ray-prompt-logging-baseline.py --generations 1
pre-commit run --all-files
```

**14 tests pass**, locally through the repository's unittest launcher and in the Linux training runtime. Coverage includes native formatting/fallback, full message identity, unsupported/circular inputs, JSON coercions, row order and rewards, disabled logging, per-call lifetime, formatting/writer failures and real JSONL output. All pre-commit hooks pass.

The public replay uses synthetic text/responses, Swift's real `qwen2_5` template and a locally constructed byte-level tokenizer. It downloads no model or dataset. Each variant has one warmup call, followed by six timed pairs with alternating execution order. Timings measure CPU log-row construction with an in-memory writer; disk I/O is excluded. A separate real-writer check verifies byte-identical JSONL.

| CPU / fixture | Original median | Candidate median |
| --- | ---: | ---: |
| Apple M4 Pro, 32 prompts × 16 responses | 0.605 s | 0.0416 s |
| Xeon Platinum 8558, 32 prompts × 16 responses | 1.172 s | 0.0833 s |
| Xeon Platinum 8558, 512 unique prompts × 1 response | 1.161 s | 1.176 s |

The repeated-prompt replay is about **14× faster**, with formatter calls reduced from 512 to 32. The unique-prompt control retains 512 calls and has a roughly 1.3% higher median on the Xeon run; key construction has a cost when there is no reuse. Every replay preserves all rows and exact JSONL bytes.

Linux runtime: Python 3.12.14, PyTorch 2.13.0, Ray 2.59.0, Transformers 5.19.0 and tokenizers 0.23.3. This is a synthetic text logging microbenchmark, without trained tokenizer merges, image processing or model execution. No end-to-end GRPO throughput or VRAM improvement is claimed.
