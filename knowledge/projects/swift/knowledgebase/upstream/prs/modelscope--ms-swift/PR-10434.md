# Make colocate trainer offload optional and independent

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10434) · state: closed · merged: True

## Original PR description

## Summary

v5 colocate 把 `--offload_model` / `--offload_optimizer` 当成说明文字：两个开关无论怎么设，每步都会把模型和优化器一起卸到 CPU。native FSDP 则直接拒绝 offload。和 verl 对比时，swift 无法选择“留在 GPU 上”，FSDP 也走不了和 DDP 一样的 offload 路径。vLLM 的 sleep/wake 本身是有的，问题出在 trainer 这一侧。

这次改动：

- `--offload_model` 和 `--offload_optimizer` 各自生效。默认都是 false，权重和优化器留在 GPU。要卸到 CPU 时显式打开。这改变了 v5 colocate 的旧行为：以前不写这两个参数也会 offload。
- GRPO / PPO / RFT / distill 的 colocate 循环把开关传给 twinkle。vLLM sleep/wake 不动。
- `reload_to_gpu` 只把这次真正移走的部分搬回来。
- 非 colocate 的 sampler 仍然忽略这两个开关和 `sleep_level`。
- `resource_mode=adaptive` 还是要借 trainer 的卡，两个开关都为 false 时直接拒绝。
- 生成式 eval 的 `ColocateHandover` 没有 RolloutConfig，默认两个都 offload，eval 时 trainer 仍会让出 GPU。

依赖同名的 twinkle PR：DDP 和 native FSDP 才能按这两个开关搬家。

## Test plan

- [x] colocate 下只关 `offload_model` 不再打出 “atomic / ignoring” 警告
- [x] `resource_mode=adaptive` 且两个开关都是 false 时 `validate_rollout_config` 拒绝启动
- [x] 单卡脚本覆盖 DDP 与 native FSDP 的四种组合（都卸、只卸模型、只卸优化器、都不卸），reload 后数值还原；没有实现 offload 的 strategy 抛 `NotImplementedError`
- [x] Qwen3.5-0.8B、8 卡、colocate、`--offload_model true --offload_optimizer true` 的 GRPO 跑过多个 step，`grad_norm` 非 0

- qychen2001 · comment · 2026-10-27T02:32:02Z · [source](https://github.com/modelscope/ms-swift/pull/10434#issuecomment-6432288589)

看到一个还没在这个分支上改的问题，先记在这里。

v5 colocate（GRPO / PPO / RFT / distill）实际调用是 `sampler.sleep(level=rollout_config.sleep_level or 1)`。`RolloutConfig.sleep_level` 默认是 0，但 `0 or 1` 会变成 1，所以默认值和显式 `--sleep_level 0` 都会睡到 level 1，没办法选择不 sleep。`--sleep_level 2` 可以原样传下去。`resource_mode=adaptive` 更严：校验只接受 0 和 1，然后同样把 0 改成 1，2 直接拒绝，这条路径实际只有 1。

对照：

- swift v4（`swift/rlhf_trainers`）的 0、1、2 都生效。colocate 是 `sleep_level > 0` 才调用 `engine.sleep(level=args.sleep_level)`，0 是真的不睡。
- verl 没有「不睡」这一档。同步 colocate 用 `VLLM_SLEEP_LEVEL`：vLLM >= 0.18 是 2，更低版本或 NPU 是 1；`layered_summon` 会改回 1。异步路径在 MTP / LoRA adapter / NPU 时用 1，否则用 2。

另外，`ColocateHandover` 的注释写 level 1 只卸 KV、权重留在 GPU。装上的 vLLM 0.19 里，level 0 只暂停调度，level 1 是权重卸到 CPU 并丢掉 KV，level 2 连权重一起丢。注释和运行时不一致。

这次先不改，后续在这个分支上把 0/1/2 做成和 v4 一样可选。
