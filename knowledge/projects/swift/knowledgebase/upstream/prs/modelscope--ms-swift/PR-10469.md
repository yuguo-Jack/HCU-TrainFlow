# PR information

Related issue: none.

Ray GRPO can reject valid training microbatches because batch validation applies the microbatch divisor to prompt counts, while Ray workers batch generated completions.

For example, `generation_batch_size=512`, `num_generations=16`, DP size 32 and `micro_batch_size=2` give one prompt and 16 completions per rank. The completions form eight full training microbatches, but the current check rejects the single prompt as indivisible by 2.

Use completion divisibility by `dp_size * micro_batch_size` for Ray. Pass the existing Ray mode through both driver preflight and worker argument initialization. Preserve the non-Ray prompt rule, prompt/DP alignment and minimum per-GPU allocation checks. Update the English and Chinese Ray documentation. No new user configuration is introduced.

AI assistance (Codex) was used to prepare the implementation, tests and description.

```bash
python -m unittest discover -s tests/megatron -p test_ray_batch_alignment.py -v
pre-commit run --all-files
```

- The repository's unittest launcher discovers and passes all **12 tests** locally. The cases cover both validation entry points, TP/PP/CP-derived DP sizes, invalid completion/prompt counts, the GPU-count guard and non-Ray behavior.
- Native Ray collation, using a lightweight collation stub, produces 32 shards of eight full microbatches of size 2, preserving all 512 sample IDs, their order and batch-object identity.
- In a Linux training runtime, loading the exact unchanged upstream argument and pipeline modules rejects the valid example at both entry points. The exact candidate modules pass the same suite: **12 tests pass** with complete real-module imports, and **12 pass** in the portable unittest suite. Runtime: Python 3.12.14, PyTorch 2.13.0, Megatron Core 0.19.2, mcore-bridge 1.6.5 and Ray 2.59.0. Installed Swift and the training checkout are not patched.
- All pre-commit hooks pass.

These are validation and batch-construction checks. No model-training, throughput or VRAM result is claimed, and this change is not a recommendation to increase microbatch size.
