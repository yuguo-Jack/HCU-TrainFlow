# PR information

`MeanMetric.compute()` writes globally reduced totals back into its per-rank accumulators. Further calls re-reduce those totals, so appending new observations after reading a metric overweights the earlier observations.

For example, two ranks first add `1` and `3`, read the mean twice, then add `5` and `7`. The mean should be `4.0`, but currently becomes `2.8`.

Reduce local copies and calculate the result without modifying `self.state` or `self.count`. Keep the existing float32 collective dtype and process-group selection.

## Experiment results

macOS arm64, Python 3.11.15, PyTorch 2.4.1, real CPU/Gloo processes:

- Before: `python -m pytest tests/utils/test_mean_metric.py -q` — **1 failed, 2 passed**. The distributed test measured `2.8` instead of `4.0` after updating an already-computed metric.
- After: `python -m pytest tests/utils/test_mean_metric.py tests/utils/test_reranker_metrics.py tests/utils/test_acc_metrics.py -q` — **13 passed**.
- `pre-commit run --all-files` — all ten hooks passed.

New tests exercise repeated reads, later updates, an empty rank receiving data, reset/custom empty values, and both default and explicitly supplied process groups with two real processes. Existing four-process reranker tests also pass. NCCL/HCCL training was not run.

Prepared and tested with Codex assistance.
