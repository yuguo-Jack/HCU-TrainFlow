# PR information

Fixes #10351

When I enable Megatron-FSDP v1 together with `use_precision_aware_optimizer=True`, Swift's same-name argument copying leaves `megatron_fsdp_use_decoupled_grad` at its default. The FSDP gradient path then disagrees with the precision-aware optimizer's `decoupled_grad` reader, allowing parameters with missing gradients to be skipped.

I extracted the DDP configuration construction into `_build_ddp_config` and aligned the decoupled-gradient flag with `use_precision_aware_optimizer` on the v1 path, matching Megatron-LM. The fix preserves configuration outside that path and raises a clear compatibility error when an older MCore configuration class does not expose the required field.

I added eight CPU regression tests, one optional test against the real Swift/MCore configuration class, and a compatibility note in both Chinese and English parameter documentation. No dependency upgrade is included. Current Swift has no `megatron_fsdp_version` CLI argument; a missing attribute defaults to v1. The explicit version=2 regression case only checks the guard's configuration behavior.

AI assistance: I used OpenAI Codex to help prepare the implementation and tests.

## Experiment results

In my original MCore 0.19.x reproduction, gradient norms remained zero for 300 training steps. After correcting the mapping, they became nonzero; the first-step norm was 411.231 versus the baseline's 411.157, and training loss decreased normally. These are results from the original reproduction, separate from this Mac's local checks.
