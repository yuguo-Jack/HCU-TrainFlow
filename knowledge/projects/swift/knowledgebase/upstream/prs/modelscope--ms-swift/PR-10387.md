# PR information

Related issue: none.

SFT accuracy currently copies predictions and labels to the CPU and builds Python correctness lists on every micro-batch, even when `logging_steps` is large. Accumulate device-side correct/valid counts instead, and transfer the reduced counters when metrics are logged. This preserves token weighting across variable-length batches and excludes sequences with no supervised labels.

Use one tensor implementation for accuracy, with the existing list return format as the default. Packed sequence accuracy uses prefix sums to avoid reading individual GPU boundaries in Python. Add a small `MeanMetric.update_counts()` entry point so counters bypass the scalar `.item()` in `update()`. Sequence-parallel prediction/label gathering is unchanged.

Production changes total +46/-35 lines. The existing sequence-parallel test double is adapted to accept counts; no new test cases or benchmark files are included.

AI assistance: implementation, local validation, and this description were prepared with OpenAI Codex. Human review checklist items remain unchecked in this draft.

## Experiment results

On an RTX A1000 Laptop GPU with PyTorch 2.12.1+cu130, BF16 logits and vocabulary size 32,000, the actual accuracy hook was measured including argmax and a logging flush every 100 micro-batches. Timings are medians of three warmed-up runs against main at `80e55df90`.

| Accuracy / input | Before | After | D2H copies over 3 micro-batches, excluding logging |
| --- | ---: | ---: | ---: |
| Token, batch 1, length 8,192 | 3.116 ms | 3.084 ms | 6 → 0 |
| Sequence, batch 1, length 8,192, 64 packed sequences | 5.425 ms | 3.114 ms | 1,158 → 0 |

These are accuracy-hook timings, not end-to-end training speedups. Accuracy values matched exactly. A small native GPT-2 through `Seq2SeqTrainer.compute_loss` also produced identical loss, parameter gradients, and accuracy logs for token/sequence accuracy with logging intervals of 1 and 100.
