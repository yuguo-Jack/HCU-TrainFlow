# fix(train): honor prefetch factor for SP map-style datasets

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10329) · state: open · merged: False

## Original PR description

When sequence parallelism uses a map-style dataset, `get_sp_dataloader()` omits `dataloader_prefetch_factor` when constructing `DataLoaderShard`. An explicit value such as `--dataloader_prefetch_factor 16` is therefore silently ignored and PyTorch uses its default of 2. The iterable SP and ordinary training paths already forward this option.

Forward the existing argument in the map-style SP path, covering both training and evaluation callers. Add a CPU regression test with a mocked distributed sampler and a real DataLoader, checking explicit prefetch, default prefetch, zero workers, and unchanged batch contents.

Validation:
- Reproduced on installed ms-swift 4.5.2: requesting 16 produced `loader.prefetch_factor == 2`.
- Executed the exact modified methods from this branch with the same installed dependencies: all three CPU cases passed. This is method-level validation, not a full upstream training run.
- Flake8, isort, YAPF formatting check for the regression test, and `git diff --check` passed.

No training throughput improvement is claimed by this PR.
