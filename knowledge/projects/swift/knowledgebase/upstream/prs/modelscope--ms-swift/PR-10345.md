# fix(template): composite transparent images onto white in load_image

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10345) · state: closed · merged: True

## Original PR description

Fixes #10343.

## Problem

`load_image` ends with `image.convert('RGB')` for every non-RGB image. For transparent images (RGBA, LA, and palette PNGs with a transparent colour) this drops the alpha channel without filling in a background, so transparent areas turn black. Black lines and text on a transparent background become invisible. Every template that loads images goes through `load_image`, so the image reaches the model already black in training and in vllm/lmdeploy inference.

## Fix

Composite images with transparency onto a white background before the RGB conversion:

- detection: `image.mode in ('RGBA', 'LA', 'PA') or 'transparency' in image.info` — the same check vllm uses (`_has_transparency` in `vllm/multimodal/image.py`);
- `convert('RGBA')` then `paste` onto a white `RGB` canvas using the alpha channel as mask;
- images without transparency (RGB, L, JPEG, CMYK, palette without transparency, fully opaque RGBA) are converted exactly as before — pixel-identical for opaque inputs.

This mirrors how the same defect was fixed in lmms-eval (EvolvingLMMs-Lab/lmms-eval#1573, which blacked out MathVista/MMMU test images).

## Verification

The repro from #10343 now prints `background=255 line=0` (white background, visible black line) for all three input modes, instead of `0/0`.

Added `tests/general/test_load_image_transparency.py` (5 tests, no network/GPU/model needed):
- RGBA / LA / P-with-transparency PNG bytes → white background, black outline preserved;
- fully opaque RGBA → pixel-identical to the old behaviour;
- semi-transparent pixels blend with the white background;
- RGB / L / P-without-transparency → unchanged (pixel-equal to direct `convert('RGB')`);
- `Image.Image` objects composited as well.

All 5 tests pass locally via a standalone harness that loads the patched module directly (the full pytest suite needs the heavy `swift` import chain, exercised in CI). flake8 / isort / yapf are clean with the repo configs.
