# Fix naive colocated weight export and avoid redundant offload/reload

# PR information

Related issue: none.

Naive colocated weight synchronization offloads the training model immediately before exporting its weights. Megatron DDP offloading releases the GPU storage behind trainable parameters, so dense and adapter-only LoRA exports can fail when the exporter or IPC sender reads them.

Remove the offload/reload pair around export. Weights stay resident until transfer completes, while generation-phase offloading remains unchanged. Preserve LoRA merge/unmerge cleanup and update the initial-sync state only after success. Add focused regression tests and matching English/Chinese documentation.

The original path already reloads the full training state after export. Keeping it resident overlaps that state with export temporaries, so configurations still need GPU headroom for those temporaries.

AI assistance (Codex) was used to prepare the change, tests and measurements.

## Experiment results

GPU experiments used `modelscope/ms-swift@a013ae639060ba3439a60dd7cb07ff9561d06be6`. The PR is rebased onto `eed35f1a67ec9e72eeb93a9ac442cf89a4447daf`; the affected manager code is identical between these bases. Regression tests and lint were rerun after rebasing.

- `python -m pytest tests/megatron/test_ray_weight_export.py -q`: **18 passed**. The unchanged manager fails 10 cases and passes 8. Coverage includes full/adapter-only and initial/repeated syncs, colocated/separate operation, export failures, LoRA cleanup and success-state handling.
- `pre-commit run --all-files`: **all hooks passed**.
- Native TP=2 bridge checks compare dense and LoRA exports exactly against a resident-model control, including adapter-only updates, subsequent offload/reload and injected export-failure cleanup.
- A real **9.408B vision-language model on eight H200s** completed 12 GRPO updates: ten fixed-weight updates for timing, followed by two nonzero-learning-rate updates with model and optimizer offloading enabled. All eight ranks had finite nonzero gradients; timing weights stayed unchanged; the live updates changed weights consistently across all eight replicas.

Paired sync timing used the same initialized actors and weights, two warmup pairs and eight alternating measured pairs. The existing model-residency flag fix was active for both versions, with offloading disabled during timing; all other runtime changes were held fixed. This measures the incremental effect of these four removed lines in that working stack.

| Sync implementation | Median time |
| --- | ---: |
| Previous logic | 1.711 s |
| Resident export | 1.219 s |

This saves **0.49 s per sync (28.8% less time)** in this configuration. Warm-iteration sampled whole-device peaks were **136.7 GiB for both versions**. During the paired syncs, both left at least **27.6 GiB free**.

GRPO steps were around 35 seconds. Generated-token hashes differed between repeats despite fixed sampling seeds, so no causal whole-step throughput gain is claimed. These are bounded workload checks, not maximum-context or long-run convergence qualification.
