# PR information

Related issue: none.

Fix collective mismatches in HF GRPO rollout logging by gathering and caching complete per-sample records. Prompts, completions, and optional metadata now travel together in one object-gather call. Table columns are constructed only when exporting the retained records.

## What goes wrong

`GRPOTrainer._log_rollout()` gathers prompts and completions separately, then decides which optional columns to gather using local checks. Each locally selected column triggers another object gather.

Those checks do not establish that other ranks selected the same columns:

| Rank | Local optional fields | Log gathers |
| --- | --- | --- |
| 0 | `solution` | prompt, completion, solution |
| 1 | none | prompt, completion |

Rank 0 enters another object gather while rank 1 leaves logging and proceeds toward subsequent work. The ranks can enter incompatible collectives, resulting in a collective mismatch error or timeout.

Equal call counts can also produce incorrect logs. If rank 0 gathers `solution="answer-0"` while rank 1 gathers `num_turns=2`, both execute a third gather, but each interprets `["answer-0", 2]` as a different column.

The trigger is inconsistent field presence, not an empty field value. A `solution` key whose value is `None` still satisfies the original presence check.

This happens in the shared rollout path after rewards and advantages have been calculated. `log_completions=False` does not bypass collection; it controls the later export. The mismatch does not require asynchronous generation, sequence parallelism, or parameter sharding.

## Gather and retain records

Each local sample produces a record containing its prompt messages, decoded completion, `solution`, and `num_turns`. Missing optional values are represented by `None`. Every rank submits its list of records through the same single object-gather call, including when its list is empty.

After gathering, prompt messages are rendered through the existing template method. Complete records are retained in one bounded `_rollout_logs` deque, using the existing `generation_batch_size` limit. Eviction therefore removes a sample and its metadata together, rather than advancing independent prompt, completion, and optional-field buffers.

For example, ranks that supply different fields now retain two separate records:

| prompt | completion | solution | num_turns |
| --- | --- | --- | --- |
| prompt-0 | completion-0 | answer-0 | null |
| prompt-1 | completion-1 | null | 2 |

Field availability affects record contents only. It cannot change communication count, order, or field identity. Logging now uses one object-gather call instead of the previous two to four calls.

## Build columns at export

`log()` selects the retained records using the existing entropy-based row limit, then expands them into the table used by JSONL, W&B, and SwanLab.

Optional columns are discovered from the selected records. A missing entry becomes `None`; a column is omitted only when every displayed entry is `None`. Empty strings and zero turn counts remain valid values. Fields that disappear in later rollouts cannot leave values attached to newer samples, and fields introduced later receive placeholders for older retained rows.

This keeps field selection in presentation code, after communication has completed. Adding an optional field to a record does not require adding a gather or maintaining another deque.

Rewards, advantages, and entropy retain their existing accumulation paths. Completion decoding, prompt rendering, sample ordering, and the bounded retention size are preserved. The change is limited to GRPO log collection, its cache initialization, and table construction in `grpo_trainer.py`.
