# PR information

Related bug report — none. Refs #9641, which introduced this path. Found through code analysis and reproduced with constructed CPU training runs.

Teacher setup enables dynamic self-distillation capability even for ordinary reward-only batches. Using `_has_teacher` in the loss compatibility guard consequently rejects REAL, FIPO and off-policy sequence masking when the batch has no teacher log-probabilities.

Check the batch's teacher log-probabilities in both HF and Megatron. HF checks the original batch before dynamic loss chunking so teacher-active batches remain rejected even when chunk metadata is incomplete. Add regression coverage and paired documentation.

## Experiment results

- `.venv/bin/python -m pytest -q tests/train/test_grpo_inactive_teacher.py tests/train/test_grpo_reward_metrics.py tests/test_align/test_grpo_loss.py` passed all 57 tests. The 28 new cases produce 12 expected failures and 16 passes with the original production code.
- `.venv/bin/python -m pre_commit run --all-files` passed all 10 hooks. `git diff --check` and `.venv/bin/python -m pip check` passed.
- A standalone CPU experiment used the full SwiftRLHF pipeline with a randomly initialized tiny Qwen2, local prompts and constructed rewards. With `kl_in_reward=false` and `beta=0.04`, REAL, FIPO and off-policy masking each failed at the original guard and completed three optimizer steps after this change. The normal GRPO control produced identical losses, gradient norms and parameter-update magnitude before and after the change.
- Adding `teacher_prompt` produced real teacher log-probabilities and kept all three unsupported combinations rejected. The repository regression tests additionally cover train/eval and chunked/non-chunked batches using native tiny Qwen3 forwards and backward passes.
- An independent CPU Megatron loss-component check passed 19 configurations. It executed the actual setup/loss/FIPO/masking methods with single-rank communication fixtures. Full Megatron GPU training remains unverified.

AI assistance was used for code analysis, implementation and validation.
