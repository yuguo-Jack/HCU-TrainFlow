# PR information

Related issue: #10129. This preserves the separate-gradient-buffer fix from #10130; it does not reopen that correctness issue.

Custom SFT loss currently casts every retained logit row to FP32 and computes CE before ignoring unsupervised tokens. Multi-sample `logits_to_keep` suffix cropping can leave unsupervised holes. Separately, sequence-parallel chunked CE rebuilds a CE graph and calls `autograd.grad` for each backward chunk.

This change:

- Selects supervised rows after autoregressive label alignment, before the FP32 cast and CE, then scatters losses back to the existing per-token shape. It retains dense CE when the ignored-row count is no larger than the batch size, avoiding a near-full gather after existing token compaction
- Computes chunked backward directly as `g * softmax(logits) - g * one_hot(labels)`, with zero upstream weights for ignored labels. It retains a separate gradient buffer and respects the forward CE compute dtype under autocast

DFT probabilities remain detached. External token weights, normalization, and channel-loss logging keep their existing semantics. The backbone context and output-head projection are unchanged. This does not add fused-linear-CE integration; chunked CE remains specific to `CELOSS_PARALLEL_SIZE > 0`.

Only the two production files are included; validation scripts are kept outside the repository.

AI assistance: OpenAI Codex was used for implementation, code review, local validation, and PR preparation.

## Experiment results

NVIDIA RTX A1000 Laptop GPU, PyTorch 2.12.1+cu130. Timings cover loss forward and weighted backward on preallocated logits, with four warmups and the median of five groups of 15 steps, synchronized on CUDA.

| Case | Before | After |
| --- | ---: | ---: |
| BF16 sparse-supervision CE | 1.441 ms | 0.596 ms |
| BF16 sparse-supervision DFT | 1.409 ms | 0.640 ms |
| FP32 chunked CE, 1024 x 2048, chunk 64 | 2.105 ms | 1.425 ms |
| FP32 chunked CE, 2048 x 8192, chunk 128 | 3.751 ms | 2.398 ms |

The sparse case uses two length-1024 samples with four assistant spans each. Existing suffix cropping retains 1922 rows, of which 256 are supervised, with vocabulary size 4096. CE-saved vocabulary-sized FP32 storage, deduplicated by underlying storage, decreases from **30.03125 MiB to 4 MiB**. For ordinary CE, loss and output-head parameter gradients match exactly in this example; the DFT control also matches exactly.

For chunk size 64, CE and log-softmax calls each decrease from 32 to 16; NLL/log-softmax backward calls decrease from 16 to zero, replaced by 16 softmax calls.

The dense control (1920 supervised rows out of 1922) is approximately **3.1% slower**, from 1.400 to 1.443 ms, due to valid-index detection, which includes CUDA synchronization. These are loss-phase measurements, not end-to-end training speed or memory claims. Analytical backward may round differently from log-softmax backward in FP16/BF16; AMP comparisons also used a same-logit FP64 gradient reference. No NPU/MPS/XPU validation was performed.
