## Summary

This PR vectorizes `get_half_index` for packed multi-document sequence-parallel ring attention.

The previous implementation created a CPU boolean mask and iterated over every document boundary in Python. This caused repeated host-side scalar reads when `cu_seqlens` was on NPU.

This change:

- Keeps the existing `slice` fast path for a single document.
- Builds a device-resident `torch.long` gather index for multiple documents.
- Preserves odd-length document behavior.
- Preserves the existing `ctx.is_half_index_tensor` contract.
- Removes per-document host synchronization.

| 2 | 918.5 / 939.1 | 897.1 / 922.6 | 1.02x |
| 4 | 1467.8 / 1520.9 | 892.4 / 922.3 | 1.64x |
| 8 | 2496.1 / 3004.0 | 890.9 / 925.8 | 2.80x |
| 32 | 8734.3 / 8827.5 | 899.0 / 923.6 | 9.72x |
| 128 | 33478.1 / 34246.6 | 923.8 / 944.8 | 36.24x |
| 512 | 132836.8 / 141790.6 | 1006.3 / 1022.6 | 132.00x |
| 1024 | 252684.0 / 257457.1 | 1136.3 / 1169.7 | 222.36x |

The benchmark follows the repository NPU benchmark convention: 10 warmup iterations, 30 synchronized measurement iterations, and median/p95 reporting.

The small-document regression is below the 10% threshold, so no additional scalar fallback was added.

Training smoke test on 8 Ascend 910B3 NPUs:

- `sequence_parallel_size=8`
- `sp_world_size=2`
- `rp_world_size=4`
- `padding_free=true`
- Qwen2.5-0.5B-Instruct with LoRA

Results:

```text
baseline runtime:   22.49s
optimized runtime:  19.26s
```

The optimized implementation was exercised by the real ring-attention training path. Outputs, gradients, and training loss matched the baseline.
