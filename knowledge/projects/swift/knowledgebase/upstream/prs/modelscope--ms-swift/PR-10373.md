# PR information
1、HCCL permission verification
Add HMAC authentication. This signature verification occurs before `pickle.loads()`; without the secret key, an attacker cannot forge a valid signature, ensuring that malicious pickle payloads are never deserialized.
(1) Upon startup, the main process generates a 256-bit random key and distributes it to authorized workers via `HCCLMasterMetadata`.
(2) `_send_pyobj`: Instead of using `send_pyobj()`, the data is first serialized via `pickle.dumps()`. An HMAC-SHA256 signature is then calculated, and the combined data—consisting of the 32-byte signature followed by the payload—is sent.
(3) `_recv_pyobj`: Instead of using `recv_pyobj()`, the system uses `recv()` to retrieve the raw bytes. It extracts the first 32 bytes (the signature) and verifies them using `hmac.compare_digest`. Only if the verification succeeds is `pickle.loads(payload)` called; otherwise, the data is rejected.
