# fix(checkpoint): use unique tmp name for last-checkpoint symlink

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10384) · state: closed · merged: False

## Original PR description

## Problem

`update_last_checkpoint_symlink()` in `swift/utils/io_utils.py` uses a fixed staging path (`last-checkpoint.tmp`) for every update. Concurrent checkpoint-save callbacks can interfere with each other's temporary symlinks, so one caller can report success while publishing another caller's checkpoint target.

## Fix

Give each update a unique temporary name (`<link>.<uuid4>.tmp`) before the atomic `os.replace`, so concurrent writers no longer share a staging path.

## Test

Added `test_last_checkpoint_symlink_under_concurrency` to `tests/utils/test_io_utils.py`, exercising concurrent updates and asserting no leftover `.tmp` files.

Fixes #10336
