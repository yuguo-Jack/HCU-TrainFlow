# Record v5 colocate sleep_level bugs

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10442) · state: closed · merged: True

## Original PR description

这条 draft 用来记 v5 上修过的 bug。每修一处，在下面加一条，链接指向云端 commit。

## 已修复

### colocate 的 `sleep_level` 0 被改成 1

https://github.com/modelscope/ms-swift/commit/481b7dd584ef772b675b7d598b8b55778e0daa87

GRPO / PPO / RFT / distill 的 colocate 循环写的是 `sampler.sleep(level=sleep_level or 1)`。配置默认值是 0，`0 or 1` 得到 1，所以默认和显式 `--sleep_level 0` 都会睡到 level 1，关不掉。`--sleep_level 2` 本来就能传下去。

这个 commit 改成和 swift v4 一致：0 不调用 `sleep`，引擎留在 GPU 上；1 把 vLLM 权重卸到 CPU 并丢掉 KV；2 把权重和 KV 一起丢掉。adaptive 的 0 也不再被改成 1。生成式 eval 没有 RolloutConfig，交接仍固定 level 1。

### vLLM engine 把 level 1 注释反了，level 0 会真正进入 sleep

https://github.com/modelscope/twinkle/commit/ad90541d9b7d99221e016bd060d9a913400efff7

twinkle 的 `VLLMEngine.sleep` 注释写成 level 1 只卸 KV、level 2 连权重一起卸。装上的 vLLM 0.19 相反：level 1 是权重卸到 CPU 并丢掉 KV，level 2 是权重和 KV 都丢掉。level 0 在 vLLM 里会暂停调度。这个 commit 让 level 0 在进 vLLM 之前直接返回，1 和 2 原样转发，并改掉那句注释。

### 两个 offload 都关时，trainer 的缓存分配器不释放，下一轮 KV 映射 OOM

https://github.com/modelscope/twinkle/commit/68baa1ad5978026678157b6829bc42960fe5e899

https://github.com/modelscope/ms-swift/commit/7fa622b982a04742db2076555e384faf74daf902

`--offload_model false --offload_optimizer false` 时，`TrainableModel.offload_to_cpu` 以及 DDP / FSDP2 / Megatron 的同一道提前返回只记「什么都没搬」就 return。真正搬走参数之后的 `empty_cache()` 走不到。权重和 Adam 状态留在 GPU 上是对的，但 backward 的激活峰值还留在 PyTorch caching allocator 里。vLLM 是另一个进程，用 CuMem 映射 KV 时只能看到这块仍被占用。Qwen3.5-4B、8 卡、sleep level 2、显存比例 0.5 的 colocate GRPO 第 1 步能训完，第 2 步 `wake_up(kv_cache)` 在 `create_and_map` 里 OOM。当时 sleep 之后卡上仍占约 41 GiB。

verl 的 hybrid 在 `param_offload=false` 时仍会在映射 KV 之前 `empty_cache()`。这里对齐的是这一步，不是把参数卸到 CPU。两个开关都关时仍 `gc.collect()` 并 `empty_cache()`，`reload_to_gpu` 继续是空操作。swift 侧的 commit 只改了 `offload_for_rollout` 的说明。

修完后同一配置训了 3 步，进程退出码 0。第 2、3 步的 KV 都能唤醒，sleep 之后卡上剩余约 14–20 GiB。三步 `grad_norm` 为 0.2188、0.3460、0.7406。

twinkle 的 commit 里还包含这五个文件的 ruff 格式化。hook 会整文件格式化，不改格式无法通过检查。

## 还没修

- adaptive 不能用 sleep level 2。不发布新权重的借卡只做 `wake_up(tags=['weights'])`，没有 `sync_weights`。level 1 卸到 CPU 的权重能被这次 wake 请回来；level 2 已经把权重丢掉，wake 只会得到一块空参数。
- adaptive 要求 `sampler_mode=disaggregated`。显式打开 `--offload_model` 时，校验仍警告 offload 被忽略。借卡时 trainer 其实会 offload。
