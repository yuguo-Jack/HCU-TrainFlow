# PR information

No linked issue. Found through code inspection and reproduced with constructed CPU experiments using the real Swift trainer APIs.

`Trainer`, `RerankerTrainer`, and `ScoringTrainer` can divide evaluation loss by the training gradient accumulation window. Evaluation also passes `num_items_in_batch` in recent Transformers versions, so that argument does not identify a training call. With fixed BERT weights and validation data on Transformers 5.17, setting accumulation to 8 changes classification loss from 0.693147 to 0.086643. When evaluation follows full and partial training windows, the changing divisor can also select the worse checkpoint.

Apply the existing accumulation scaling only when the passed model is in training mode. Preserve the training formula and fallback divisor, extend the existing regression suite to cover evaluation and decision training, and document the behavior in both languages.

AI assistance was used for investigation, implementation, and validation.

## Experiment results

- `OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python -m pytest -q tests/train/test_trainer_partial_accumulation.py tests/train/test_decision_loss.py`: **36 passed**. The same suite against the original trainers has **9 expected evaluation failures and 27 passes**. Coverage includes accumulation windows 1/2/4 and a model that does not accept loss kwargs.
- Independent CPU experiments with native tiny BERT classification/reranking models exercise the complete Swift trainer constructor, `train()`, automatic evaluation, checkpoint saving, and `load_best_model_at_end`. Five microbatches with accumulation 4 produce windows of 4 and 1. Classification CE improves from 2.859033 to 2.671674, but the original trainer reports 0.714758 then 2.671674 and reloads checkpoint-1. The fix reports the unscaled losses and reloads checkpoint-2; reranking and decision experiments also select checkpoint-2. Gradients and parameters after each BERT optimizer update are bitwise identical before and after the fix.
- Native tiny Qwen3 classification/reranking models also return the reference CE/BCE across all eight configured/current-window evaluation cases.
- `.venv/bin/python -m pre_commit run --all-files`: all hooks passed. `git diff --check` and `.venv/bin/python -m pip check` passed.

Runtime: Python 3.13, PyTorch 2.14, Transformers 5.17. These are constructed CPU regressions using randomly initialized small models, not pretrained-model quality benchmarks or production incidents.
