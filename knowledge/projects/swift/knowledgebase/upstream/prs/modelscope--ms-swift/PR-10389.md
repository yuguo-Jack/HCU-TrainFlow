# PR information

Refs #10388

Adds `examples/train/grpo/plugin/text2sql/`:
- `text2sql_plugin.py`: `text2sql_exec` (execution-match reward) and `text2sql_format`.
  The database comes from a `db_path` column or `db_id` + `TEXT2SQL_DB_ROOT`. Reference results are
  cached per (db, sql) so the 8 rollouts of a prompt run the reference once; rollouts are scored in a
  thread pool.
- Guards: read-only connection + SQLite authorizer (no writes, ATTACH, PRAGMA, extensions), one
  statement per query, timeout inside SQLite, row cap. A failing reference returns `None` (NaN, no
  reward) instead of 0; `TEXT2SQL_SKIP_EMPTY_GOLD=1` does the same for empty references.
- `prepare_bird.py`: BIRD JSON/JSONL -> `messages` + `solution` + `db_id` rows.
- `text2sql.sh`: GRPO script (Qwen3-4B, colocate vLLM).
- Docs: "Example: Execution Reward for Text-to-SQL" in `reward_function.md` (EN and ZH), including
  the constant-answer caveat (16/500 BIRD Mini-Dev references return `1`).

## Experiment results

Unit-level checks (ms-swift stubbed): equivalent query = 1.0; superset, multi-statement with DROP,
DELETE, ATTACH, runaway recursive CTE, prose without SQL = 0.0 and the database is unchanged;
failing reference -> None; empty reference skipped with the flag; `prepare_bird.py` output format.
All 500 BIRD Mini-Dev reference queries run identically inside the sandbox and with plain sqlite3
(except two references that take >100 s even without it).
I have not run a full GRPO training job yet (no GPU on hand).
