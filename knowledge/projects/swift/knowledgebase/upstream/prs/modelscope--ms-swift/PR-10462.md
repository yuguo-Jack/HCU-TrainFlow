# PR information

Fixes #10461

`get_toolcall` in `hy_v3`, `hy_v3_preview`, `minimax_m2`, and `minimax_m3` decoded every XML parameter with `json.loads` (and `ast.literal_eval` through `_parse_json` for Hunyuan and MiniMax-M2) and never read the tool schema. These formats write strings raw, so a parameter declared as `string` changed type whenever the text looked like a literal: `"12345"` became `12345`, `"true"` became `true`, `"'hi'"` became `hi`, `"1_000"` became `1000`, and `"[1, 2]"` became a list. `swift infer` / `swift deploy` and GRPO rollouts go through `InferEngine._get_toolcall`, which forwards `tools` only when `supports_tool_schema` is set. #10281 and #10300 already did this for `xing4_0` and `minicpm5`.

On `hy_v3` and `minimax_m2`, `parsed if parsed is not None else v` also treated a successful JSON `null` as a parse failure, so a real null came back as the string `"null"`.

The four templates now set `supports_tool_schema = True`. When the schema type includes `string` (a bare type or a union, in any order), the raw text is kept. A bare `null` on a nullable string (`["string", "null"]`) is still JSON null, same rule as `minicpm5` / `xing4_0`. Integers, booleans, objects, and arrays still use the existing decoder. With no schema that decoder is unchanged, except a literal `null` is `None` instead of `"null"`.

## Experiment results

CPU only, no model download.

`tests/general/test_xml_agent_string_args.py` on main, before the fix:

```
139 failed, 5 passed
```

Failures are `get_toolcall()` rejecting `tools`, string round-trips (`"12345"`, `"true"`, `"'hi'"`, `"1_000"`, `"[1, 2]"`, `"null"`), and a real null coming back as `"null"` on hy_v3 and minimax_m2. The 5 passes are no-schema cases that were already correct.

After the fix:

```
python3 -m pytest tests/general/test_xml_agent_string_args.py tests/general/test_agent_template_tool_arg_types.py tests/general/test_glm4_5_agent_template.py tests/general/test_qwen3_coder_agent_template.py tests/general/test_xing4_0_template.py tests/utils/test_gemma4_toolcall.py tests/utils/test_kimi_k25_tool_call_id.py -q
209 passed, 136 subtests passed
```

The issue repro prints `OK` for `hy_v3_preview`, `hy_v3`, `minimax_m2`, `minimax_m3`, and `minicpm5`.

`pre-commit run --all-files` passed (flake8, isort, yapf, and the other configured hooks).
