# PR information

Related issue: none.

Ray checkpoint weight synchronization can stall when a receiver's ZMQ subscription reaches the publisher after initialization returns. The NCCL initialization broadcast synchronizes the tensor channel, but does not establish readiness of the separate PUB/SUB metadata channel. The existing 100 ms sleep only reduces the likelihood of losing the first metadata message. A receiver missing that message waits in `recv_string()` and never joins the corresponding tensor broadcast.

Replace the fixed sleep with publisher-side subscription confirmation. Use XPUB and have each receiver subscribe to a distinct rank marker after subscribing to the shared metadata topic on the same connection. Initialization waits for every expected marker, with the existing store timeout as its deadline. Per-rank markers avoid treating duplicate common-topic subscriptions as distinct receivers. Bucket serialization, authentication, and tensor broadcasts remain unchanged.

The production change is 17 insertions and 5 deletions in `nccl.py`.

## Experiment results

Local reproduction and validation used independent processes, real TCP ZMQ sockets, and CPU Gloo collectives. The harness loaded the checkpoint classes and functions unchanged from source with CPU/runtime dependencies supplied by the harness; it did not start Ray actors or a GPU NCCL group. An XPUB/XSUB proxy delayed only subscription forwarding, without explicitly dropping data messages.

- On the unchanged implementation, the no-delay case passes. Both delayed cases (one receiver, and two receivers with only the last delayed) stall after the 500 ms subscription delay ends. After another 4 seconds, the workers remain alive; captured stacks show the sender waiting in the tensor broadcast and receivers waiting for metadata. The test watchdog then cleans up the workers.
- With the fix, the normal and delayed cases complete with exact tensor equality across multiple buckets and two consecutive weight synchronizations. A separate test verifies that a missing rank marker produces a bounded initialization error rather than accepting only the common subscription.

Validation performed before removing the local regression test file from the PR:

```text
python -m pytest tests/megatron/test_nccl_metadata_readiness.py -q
4 passed in 12.13s

pre-commit run --all-files
All hooks passed
```

The regression test file is not included in the final PR diff; only `nccl.py` is changed. No multi-GPU NCCL end-to-end result is claimed. Production NCCL may eventually fail through its watchdog; this change prevents the initial metadata-loss race rather than providing general recovery from later disconnects or receiver failures.
