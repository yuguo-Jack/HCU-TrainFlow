# PR information

Fixes #10506

`GLM5NextTemplate` (GLM-5.3-Flash) inherits `GLM5_2Template`, whose `reasoning_effort_needs_thinking = True` renders the `Reasoning Effort: ...` system line only when thinking is on. Thinking is off by default for this template, so by default every training row was encoded without the line. The GLM-5.3-Flash release `chat_template.jinja` writes it on every conversation (default Max), as GLM-5.3 does; `GLM5_3Template` already sets the flag to `False`. This PR sets the same flag on `GLM5NextTemplate`.

## Experiment results

Token comparison of ms-swift's encoding (training mode, `swift.dataset.load_dataset` + `get_template`) against the release template rendered by transformers' `apply_chat_template` from the `zai-org/GLM-5.3-Flash` files, on 384 GSM8K rows (main `680df5c6`, transformers 5.18.0, CPU):

| setting | before | after |
|---|---|---|
| default (no env, no template kwargs) | 384 / 384 rows differ | 0 differ |
| `REASONING_EFFORT=low` | 384 / 384 rows differ | 0 differ |
| `REASONING_EFFORT=low`, `enable_thinking=True` | 0 differ | 0 differ |

"0 differ" means ms-swift's input ids equal the release rendering followed by the next `<|user|>` (the stop token ms-swift appends after the last assistant turn). The minimal example in the issue prints the same string as the release template after this change.
