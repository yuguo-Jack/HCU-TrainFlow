# PR information

Fixes #10455

**Problem.** Gemma-4 writes tool-call string values between `<|"|>` delimiters and does not escape their content (this is also how `Gemma4AgentTemplate._format_argument` renders them). `get_toolcall` -> `_parse_arguments` -> `_gemma_to_json` replaced every `<|"|>` with a bare `"` and ran the bare-key quoting regex over the whole body. Any value containing `"`, a newline, a tab, a backslash, or a `,key:` sequence therefore became invalid JSON (or a corrupted object), the `JSONDecodeError` was swallowed, and the tool call was returned with `arguments == "{}"`. All infer engines (`vllm`, `sglang`, `lmdeploy`, `transformers`, GRPO vLLM engine) use `agent_template.get_toolcall` via `InferEngine._get_toolcall`, so `swift deploy`/`infer` with `--agent_template gemma4` silently dropped the arguments of, e.g., file-writing or shell tool calls.

Repro on main (a013ae639):

```python
import json
from swift.agent_template.gemma4 import Gemma4AgentTemplate
t = Gemma4AgentTemplate()
resp = '<|tool_call>call:write{content:<|"|>print("hi")\n<|"|>,path:<|"|>a.py<|"|>}<tool_call|>'
print(t.get_toolcall(resp)[0].arguments)
# before: {}
# after:  {"content": "print(\"hi\")\n", "path": "a.py"}
```

Other values that came back as `{}` before: `{'cmd': 'ls\ncd /tmp'}`, `{'text': 'a\tb\\c'}`, `{'q': 'a,b:c'}`.

**Fix.** `_gemma_to_json` now splits the body on `<|"|>`: odd segments (string contents) are re-encoded with `json.dumps(..., ensure_ascii=False)`, and the existing bare-key quoting regex is applied only to the segments outside string values. Output for inputs that parsed correctly before is unchanged.
