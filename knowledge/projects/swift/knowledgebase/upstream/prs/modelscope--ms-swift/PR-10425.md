# PR information

Refs #8355

GPTQModel can convert symmetric GPTQ v2 weights to GPTQ v1 inside Optimum's `save()`. Optimum updates the quantizer's format, but the model configuration still contains the pre-save format. This leaves `config.json` describing v2 weights while `quantize_config.json` and the saved tensors use v1, which can corrupt generation after reloading.

Refresh and save the model's quantization configuration from the quantizer after saving its weights, retaining the existing omission of the calibration dataset. This follows the backend's final format without saving the weights a second time. Regression tests cover both GPTQ export modes, converted/unchanged formats, and both serialized format-key conventions.

AI assistance was used for investigation, implementation, regression tests and experiment preparation.

## Experiment results

Investigated the report using the public `Qwen/Qwen3.5-4B` checkpoint and public `AI-ModelScope/alpaca-gpt4-data-zh` calibration data. This does not reproduce the reporter's private LoRA checkpoint or its exact exclamation-mark output.

Pinned GPU stack: A800 80 GB, torch 2.8.0+cu128, Transformers 5.4.0, Optimum 1.27.0 and GPTQModel 6.0.0 with the Triton backend; 128 calibration examples, maximum length 2048, group size 128 and seed 42.

| Checkpoint | Four fixed prompts | Mean token NLL on three diagnostic answers |
| --- | --- | --- |
| Unquantized public checkpoint | Normal responses, 4/4 | 0.9559904 |
| Original export and independent reload | Same two-character cycle repeated 96 times, 4/4 | 13.5925973 |
| Same quantized tensor files, only model configuration corrected to the saved format | Normal responses, 4/4 | 0.9451559 |
| Production save fix, followed by a fresh-process reload | Normal responses, 4/4 | 0.9451559 |

The metadata-only control preserves all 248 quantized modules and changes no tensor values. These probes isolate the loading-format defect; the three-answer NLL set is not a general quality benchmark.

`PYTHONPATH=. python -m pytest -q tests/export/test_gptq_save.py`: 8 passed locally; the unmodified export path gives 4 failures specifically in the conversion cases. The tests execute `QuantEngine.quantize`, Optimum's real save/to_dict methods and actual Transformers configuration/weight serialization, while replacing calibration and backend conversion. Changed-file flake8/isort/yapf and `git diff --check` pass.

The 8 regression cases also pass on the supported pinned GPU stack (Transformers 5.4.0 / Optimum 1.27.0). Full repository `pre-commit run --all-files` passes. The production-save experiment reused already-calibrated 4B weights, verified all 248 modules were in the expected internal format, executed the real `QuantEngine.quantize()` save branch, and reloaded the result in a new process. Calibration was not repeated; saving, format conversion, configuration serialization and reload were not mocked. Both saved configuration files now describe the actual GPTQ v1 format, and the calibration dataset remains excluded from the model configuration.
