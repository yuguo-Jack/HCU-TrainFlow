# PR information

Add unit tests for the `swift/metrics/` package, mirroring the metric test suite that already exists in
`twinkle` (`tests/metric/test_metrics.py`). All new files live under `swift/dev/tests/component/metrics/`:

| File | Covers |
|---|---|
| `test_utils.py` | `Metric` base contract (`add_state` / `reset`), `MeanMetric`, `InferStats`, `eval_metrics_map` |
| `test_acc.py` | `compute_acc` (token/seq strategy, causal shift, `-100` padding, padding-free `cu_seqlens`) and `AccMetrics` |
| `test_reranker.py` | `RerankerMetrics` MRR/NDCG query grouping |
| `test_embedding.py` | `InfonceMetrics`, `PairedMetrics`, `EmbedddingMetricMixin` |
| `test_nlg.py` | `compute_rouge_bleu`, `NlgMetrics` |

Each assertion pins a behavior that is easy to get wrong and that a refactor would silently change: the
causal-LM shift (position `i` predicts token `i+1`, while an encoder-decoder model must NOT be shifted),
`-100` labels being dropped from the accuracy denominator, query boundaries in the reranker/infonce metrics
being recovered from the label vector, and `INFONCE_USE_BATCH` deciding whether the other queries' positives
count as negatives.

Conventions followed: function-based tests (no classes) with plain `assert`, matching the rest of
`swift/dev/tests/component/`; no markers are needed (pure CPU, nothing downloaded), so they run in the PR
tier `pytest -m "not slow"`. `ruff check` passes.
