# PR information

Related issue: none linked.
Companion implementation: https://github.com/modelscope/mcore-bridge/pull/251

Add DeepSeek-V4.1 Ascend LoRA examples for single-host reduced-model validation and two-host full-depth training. Update Qwen3.8-Flash-Next examples and paired Chinese/English documentation to use the shared `NGRAM_EMBEDDING_CPU_OFFLOAD` environment variable.

- `megatron_lora.sh`: single host with 8 NPUs, TP1/PP1/EP8 and 2K packing.
- `megatron_lora_multinode.sh`: based on the previously successful two-host / 16-NPU full 40-layer text-model configuration, with TP1/PP4/EP4, sequence length 256, packing/padding-free disabled and unfused attention.
- Put setup, launch instructions, resource requirements and validation scope in Chinese/English READMEs next to the scripts.
- Replace `PLE_CPU_OFFLOAD` in the Qwen examples and explain compatibility: the legacy variable remains a fallback when the new variable is unset; an explicit new value of `0` takes precedence.

This PR changes examples and documentation only. The companion mcore-bridge change is required for the shared switch and DeepSeek Engram CPU offload. CPU-resident tables stay frozen.

AI assistance was used to prepare, review and validate these changes and write this description.

## Experiment results

Checks passed:

```bash
pre-commit run --all-files
bash -n examples/ascend/train/deepseek_v41/megatron_lora.sh \
    examples/ascend/train/deepseek_v41/megatron_lora_multinode.sh \
    examples/models/qwen4_exp/megatron_sft.sh \
    examples/models/qwen4_exp/megatron_grpo.sh
```

- **Current implementation, single host:** completed 10 BF16 LoRA steps on 8 Ascend 950DT devices with a four-layer text checkpoint, EP8 and 2K packing. Loss changed from 13.33709621 to 12.74300385, gradient norms were finite and nonzero, and adapter checkpoints were saved at steps 5 and 10. All 8 workers used the current checkouts; 80 audited packed batches contained 2025–2048 tokens. The checkpoint retained the original hidden size/expert count and one Engram table; this is reduced-model validation.
- **Historical full-depth run:** completed 10 steps on two hosts / 16 Ascend 950DT devices with the full 40-layer text checkpoint, TP1/PP4/EP4, length 256 and short sample data. Step 5 and step 10 each saved 16 checkpoint shards; 120 LoRA B tensors were finite, nonzero and updated between saves. This run used the earlier offload argument and a host-specific NUMA launcher. The new two-host example uses the shared environment variable and has not been rerun on two hosts with the final code.
- The companion bridge regression suite passed all 27 tests. Existing Qwen GPU examples were not rerun.
- These results do not validate full-parameter training, vision, long-sequence full-model training or full HF export.
