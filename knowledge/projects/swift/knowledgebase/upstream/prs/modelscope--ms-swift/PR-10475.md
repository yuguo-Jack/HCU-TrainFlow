# PR information

Related issue: none.

Ray's default PyTorch serializer copies CPU tensors when workers receive training batches. Enable Ray's native zero-copy tensor serializer for the Ray Megatron CLI, before its first Ray import, and propagate the setting through job, training-worker and rollout-actor environments. Preserve an explicit `RAY_ENABLE_ZERO_COPY_TORCH_TENSORS=0` opt-out and the existing Python API default.

Received CPU tensor storage must be treated as read-only. Native consumers move inputs to the accelerator or stack results into owned tensors before mutation. Custom CPU consumers must copy before in-place changes or disable the setting. Add bootstrap/propagation regressions, a public round-trip and ownership replay, and matching English/Chinese docs. No custom serializer or dependency is added. [Ray documents the native feature and its ownership contract](https://docs.ray.io/en/latest/ray-core/objects/serialization.html).

AI assistance (Codex) was used to prepare the implementation, tests and description.

## Experiment results

Base: `modelscope/ms-swift@b02a4f7ad0704d4b20a4ac94621c5ac442284b5f`.

```bash
python tests/run.py --pattern test_ray_tensor_transport.py
for mode in 0 1 1 0; do
  RAY_ENABLE_ZERO_COPY_TORCH_TENSORS=$mode python scripts/benchmark/ray_tensor_transport.py --payload-mib 64 --rounds 6
done
# CUDA/Megatron runtime; use an available GPU:
for mode in 0 1; do
  CUDA_VISIBLE_DEVICES=0 RAY_ENABLE_ZERO_COPY_TORCH_TENSORS=$mode python scripts/benchmark/ray_tensor_transport.py --payload-mib 4 --rounds 2 --gpu
done
pre-commit run --all-files
```

**7 tests pass on Linux**, including real actors with both settings. Four startup/propagation test groups fail against the original source. Locally on macOS, 6 pass and the Linux actor test skips; both standalone CPU replays also pass. All pre-commit hooks pass.

CPU replay: Xeon Platinum 8558, Ray 2.59.0, PyTorch 2.13.0+cu130, one Torch thread per process. Four fresh processes run in disabled/enabled/enabled/disabled order, each with one warmup and six timed rounds: 12 samples per setting, with no samples excluded. The synthetic payload contains a 64 MiB BF16 tensor plus small conformance tensors. Startup is outside the timed region; the actor receives and sums the entire main tensor. No model or dataset download is required.

| Median per round | Copying | Zero-copy |
| --- | ---: | ---: |
| `ray.put` | 88.73 ms | 2.25 ms |
| Actor receive + full read | 142.83 ms | 65.37 ms |
| Put + actor receive/read | 231.37 ms | 68.36 ms |

The combined replay median is **3.38× faster**. Each phase and the per-round combined time are summarized independently.

The replay verifies values, ten dtypes including BF16, non-contiguous/scalar/empty inputs, aliases, read-only reuse and owned CPU copies. Both settings also pass a one-H200 replay through native batch preparation and GRPO/GKD carrier transfers: GPU-side changes leave the original CPU tensors intact, including a second actor's view. All GPUs are released afterward. The tested native consumer functions match upstream source.

These are synthetic single-host transport and ownership checks. No full GRPO update, convergence, multi-node throughput or VRAM improvement is claimed.
