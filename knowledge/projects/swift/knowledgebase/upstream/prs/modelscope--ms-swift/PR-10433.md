## Summary

`GRPOTrainer._compute_loss_and_metrics` builds the per-token importance ratio as
`exp(per_token_logps - old_per_token_logps)` and only applies `completion_mask` when reducing the
PPO loss afterwards. If the log-ratio at an excluded completion token overflows, the later
`inf * 0` produces `NaN` for the loss and for the excluded-token gradient.

This change masks the per-token log-ratio to zero for excluded completion tokens **before**
exponentiation. Valid-token math and all importance-sampling levels are unchanged (`sequence` /
`sequence_token` already mask the same positions when reducing, and `real` / FIPO likewise apply
`completion_mask` afterwards).

This is a defensive numerical fix for the state described in the issue. The issue's CPU example
reproduces the same expressions, and I reproduced the failure directly through
`_compute_loss_and_metrics` with controlled per-token log-probs (instead of a full production run).
I am therefore not claiming an observed production training failure; the included regression test
locks down the trainer path for the masked-token overflow state.

## Reproduction and results

Before the fix, using the trainer loss path with `completion_mask = [[False, True]]`,
`old_per_token_logps = [[-1001., -1.]]`, and `per_token_logps = [[-1., -1.]]`:

```text
loss: nan
grad: tensor([[nan, -1.]])
```

After the fix:

```text
loss: -1.0
grad: tensor([[0., -1.]])
```

## GPU validation

Ran the same loss-path reproduction on the available NVIDIA RTX A5000 24GB (SM86) with all tensors
on CUDA. It returned `loss: -1.0`, `grad: tensor([[0., -1.]])`, and the process released the GPU
afterwards (peak observed allocation for the process: ~215 MiB).

Also ran a 2-step end-to-end GRPO smoke run on the A5000 with `Qwen/Qwen2-0.5B` (LoRA, no vLLM,
`max_completion_length=64`, batch 2, 2 generations). It completed training, evaluation, and
checkpoint saving with ~1.36 GiB peak process memory:

```text
{'loss': '0', ..., 'global_step/max_steps': '1/2', 'memory(GiB)': '1.35'}
{'loss': '0', ..., 'global_step/max_steps': '2/2', 'memory(GiB)': '1.36'}
[INFO:swift] last_model_checkpoint: /tmp/.../checkpoint-2
```

The smoke run used the full trainer/GPU path but did not naturally produce the overflow state;
the controlled CUDA reproduction above is the direct before/after check for the fix.
