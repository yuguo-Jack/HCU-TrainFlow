# PR information

Multimodal preprocessing repeatedly copies expanded token sequences and intermediate pixel buffers. This PR reduces those shared CPU and allocation costs while preserving encoding, sampling and pixel values:

- Build media-token expansions in order, copying each unchanged span once. A shared helper aligns labels, fractional loss scales and multimodal masks.
- Use one capture group for escaped literal markers, enabling shared-prefix regex optimization. Custom regex expressions retain their original grouping and backreference behavior.
- Normalize the newly created InternVL image tensor in place, avoiding a full clone without changing the caller's image.
- Convert selected LLaVA video frames to RGB arrays as they are decoded, release native frame buffers earlier, and close the container before stacking.
- Skip MiniCPM/mPLUG's intermediate dtype-conversion copy when decoded frames are already uint8.

Related to #10312. The media changes from #10320 are consolidated here; that PR is superseded. This targets shared preprocessing costs and does not establish the bottleneck in the reporter's unspecified dataset. Searches for `10312 in:body`, `extend_tokens`, `dataset preprocessing performance`, `split_str_parts_by`, `template regex`, `vision_utils`, `load_video_llava`, `video decoding`, `video performance`, `image performance` and `normalize inplace` found no other overlapping optimization. Related packing, audio-path and tool-turn PRs address different behavior.

The diff contains only three production files. No models, tests or benchmark artifacts are added. Increasing placeholder order, missing-media IndexError handling, optional/empty fields, masking, delimiter semantics, frame selection and input ownership are preserved. AI assistance was used for implementation and validation.

## Encoding and cache measurements

Validated against main `410a5d18930725d1d3cfe3acdd611eb9795c403b`, on an i7-12800HX pinned to one CPU, Python 3.12.13, PyTorch 2.13.0, Transformers 5.14.1 and datasets 5.0.1. No model was downloaded.

The synthetic cache benchmark executes the real `Template.encode` → `AddLengthPreprocessor` → `Dataset.save_to_disk` path with an in-memory byte BPE tokenizer and a small template subclass that expands media placeholders. Each placeholder becomes 256 tokens; 128 rows per run, serial mapping, cache reuse disabled, nine interleaved repetitions. Values are median milliseconds (min–max):

| Placeholders/row | Before | After | Speedup |
| --- | --- | --- | --- |
| 0 | 72.11 (71.42–81.83) | 64.04 (62.85–66.07) | 1.13× |
| 1 | 85.36 (85.05–86.48) | 75.87 (74.60–76.98) | 1.13× |
| 8 | 192.41 (191.68–194.65) | 132.13 (130.80–133.14) | 1.46× |
| 32 | 965.27 (954.25–987.83) | 317.35 (308.79–319.10) | 3.04× |

The final implementation also preserves the earlier optimized version's pipeline performance: paired medians differ by less than 1% across all four workloads. The shared expansion helper adds 0.8 µs in the isolated single-placeholder check (23.50 → 24.31 µs); the corresponding complete pipeline remains 75.87 ms for 128 rows. All encoded outputs and cached-content hashes match exactly. These measurements exclude image/video decoding and image processors; they are not a claim about full production multimodal throughput.

## Image and video measurements

Compared with main `410a5d18930725d1d3cfe3acdd611eb9795c403b` on an i7-12800HX pinned to one CPU, Python 3.12.13, PyTorch 2.13.0, torchvision 0.27.1, Pillow 12.3.0, PyAV 19.0.1 and decord 0.6.0. Inputs were generated locally; no model or external media was downloaded.

Image timings cover the complete `transform_image` function, including resizing, cropping, tensor conversion, normalization and stacking. Video timings cover complete loader calls on local H.264 files, including reading, decoding, sampling and output conversion. Values are median milliseconds (min–max); image measurements use 15 interleaved repetitions of 5 calls, video measurements use 9 interleaved repetitions.

| Workload | Before | After |

| MiniCPM video, 1080p, 2 sampled frames | 109.989 (107.535–111.440) | 100.824 (100.007–102.655) |

Peak RSS increase above the imported-process baseline was measured separately, with 1 ms sampling and three fresh processes per variant. Median increases in MiB:

| Workload | Before | After |
| --- | --- | --- |
| LLaVA 720p | 114.68 | 90.41 |
| LLaVA 1080p | 249.73 | 203.17 |
| MiniCPM 1080p | 179.55 | 172.34 |

These are preprocessing measurements, not training or full dataset-cache throughput. Large images are dominated by resizing, so their speed gain is smaller. On a three-frame 240p clip, the 1–3 ms loader timings differ by less than 3% in either direction. Qwen-VL delegates video decoding to an external package; no Qwen-VL speedup is claimed here. Batch-decoding all InternVL frames was also evaluated and omitted because it increased peak memory and slowed some HD workloads.

<summary>Standalone reproduction of pixel equality and loader timings</summary>

Run from the checkout with its dependencies and PyAV installed. This creates a synthetic video locally and compares the original and changed loader; no model is needed.

```python
import gc
import os
import random
import statistics
import subprocess
import tempfile
import time

import av
import numpy as np
import torch
from PIL import Image
from swift.template import vision_utils

os.sched_setaffinity(0, {min(os.sched_getaffinity(0))})
torch.set_num_threads(1)
source = subprocess.check_output([
    'git', 'show', '410a5d18930725d1d3cfe3acdd611eb9795c403b:swift/template/vision_utils.py'
], text=True)
baseline = {}
exec(compile(source, '<baseline>', 'exec'), baseline)
rng = random.Random(10312)
image = Image.fromarray(np.random.default_rng(10312).integers(
    0, 256, (448, 448, 3), dtype=np.uint8))
assert torch.equal(baseline['transform_image'](image), vision_utils.transform_image(image))

with tempfile.TemporaryDirectory() as directory:
    path = os.path.join(directory, 'video.mp4')
    with av.open(path, 'w') as container:
        stream = container.add_stream('libx264', rate=24)
        stream.width, stream.height = 1280, 720
        stream.pix_fmt = 'yuv420p'
        stream.options = {'preset': 'ultrafast', 'crf': '20'}
        stream.codec_context.thread_count = 1
        yy, xx = np.indices((720, 1280), dtype=np.int32)
        for i in range(96):
            pixels = np.stack(((xx + i * 17) % 256, (yy * 3 + i * 29) % 256,
                               (xx // 7 + yy // 5 + i * 11) % 256), axis=-1).astype(np.uint8)
            for packet in stream.encode(av.VideoFrame.from_ndarray(pixels, format='rgb24')):
                container.mux(packet)
        for packet in stream.encode():
            container.mux(packet)
    os.environ['NUM_FRAMES'] = '16'
    before = baseline['load_video_llava']
    after = vision_utils.load_video_llava
    assert np.array_equal(before(path), after(path))
    samples = {'before': [], 'after': []}
    functions = {'before': before, 'after': after}
    for _ in range(9):
        order = list(functions)
        rng.shuffle(order)
        for name in order:
            gc.collect()
            start = time.perf_counter()
            result = functions[name](path)
            samples[name].append(time.perf_counter() - start)
            del result
    print({name: statistics.median(values) * 1000 for name, values in samples.items()})
```
