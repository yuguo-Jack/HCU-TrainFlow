# PR information

Related: #10076 (the earlier native Megatron token-normalization issue). This fixes the remaining Ray path; the DP scaling error is reproducible even when every response has the same number of valid tokens.

GKD arguments force `calculate_per_token_loss=True`, but Ray's `GKDLoss.loss_func` still returns `(loss_mean, metrics)`. MCore disables its ordinary DP gradient averaging in per-token mode. Its two-value loss branch leaves the token count at zero, so final gradient normalization is skipped as well. With a fixed global batch and equal response lengths, moving from DP=1 to DP=2 therefore doubles the gradient. Detached logging metrics are averaged separately, which hides the error in the reported loss.

Align this callback with the existing native Megatron GKD contract:

- Return the local JSD loss sum, local valid-token count, and metrics. MCore then divides the accumulated DP/CP gradient sum by the global valid-token count.
- Remove the earlier CP mean and final CP divisor, since normalization now belongs to MCore.
- Accumulate optional SFT as a sum using the same denominator as native GKD. Keep its existing dataset/student gating and vocabulary-parallel model loss call.
- Report detached `[sum, count]` metrics with a DP×CP SUM reduction so the existing logger computes a token-weighted mean across microbatches.

The production diff is limited to `swift/ray/megatron/loss/gkd.py` (+16/-24). It uses the existing scheduler and logger interfaces and adds no configuration option.

Developed with AI assistance; I discussed the normalization issue and kept the fix scoped to this loss callback.

## Experiment results

Local regression scripts are retained outside this production-only diff. The CPU/Gloo harness executes the actual Ray loss method and vocabulary-parallel helpers, and imports MCore 0.16.0's real loss-dispatch and gradient-finalization functions. A small dense model synchronizes gradients with SUM, matching MCore's per-token DDP setting. Ray orchestration and MCore's DDP bucket implementation are not exercised.

With the same fixed global batch, the original DP=1/2 gradient norms are `0.01856419805` / `0.03712839610`. After the change, both are `0.01856419805`; the logged loss remains `0.04532633038`.

Validation commands and results:


Coverage includes equal/unequal response lengths, full-vocabulary/top-k losses, forward/reverse KL and JSD, SFT and its on-policy exclusion, empty ranks, all-empty batches, uncovered teacher tokens without SFT, and metric sum/count aggregation. Maximum gradient error against an independent full-batch reference is `3.29e-10`.

The SFT shared denominator follows native Megatron GKD; separate JSD/SFT normalization for partial teacher coverage is outside this change. A full Ray/NCCL training run remains outstanding, so this PR is a draft.
