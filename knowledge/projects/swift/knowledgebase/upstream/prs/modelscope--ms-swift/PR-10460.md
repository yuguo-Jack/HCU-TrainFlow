# PR information

Related issue: none.

Ray Megatron can put several per-node resource-pool slices on the same node. `STRICT_PACK` keeps the bundles within one placement group together; it does not separate different placement groups.

For example, two 4-GPU nodes can accommodate `nnodes=2`, `train.gpus=2` and `rollout.gpus=6` as one training GPU and three rollout GPUs per node. If both training slices land on one node, a rollout slice can wait indefinitely despite that feasible layout.

Create each slice on a node not already used by its pool, using Ray's built-in node-label selectors. Place larger slices first, keep per-node counts aligned when sorting placements for rank assignment, and release partial reservations if pool creation fails. Separate pools can still use different node sets; colocated roles still share one pool.

Require Ray 2.54 or later for the upstream [STRICT_PACK label-selector fix](https://github.com/ray-project/ray/pull/60170). Multi-node pools fail before reserving resources on older Ray. Update the English and Chinese Ray documentation.

AI assistance (Codex) was used to prepare the implementation, tests and description.

- Regression coverage includes GPU/NPU reservations, shared and separate pools, uneven counts, rank ordering, failure cleanup and the old-Ray guard. macOS: 23 pass, the Linux-only cluster test is skipped.
- Additional real-Ray checks reproduce the asymmetric allocation stall above with the original source. The candidate completes that allocation, preserves uneven slice counts, and releases reservations after an injected failure.
- All pre-commit hooks pass.

These placement checks use multiple logical Ray nodes on one physical host and perform no CUDA work. No physical multi-host training or throughput gain is claimed.
