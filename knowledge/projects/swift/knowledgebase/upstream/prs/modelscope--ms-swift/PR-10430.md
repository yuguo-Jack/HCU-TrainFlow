# PR information

Refs #10429

While investigating the prefix mismatch reported in #10429, code analysis exposed a separate server-side path: `MultiTurnScheduler.run()` normalizes the engine response, but `setdefault` lets raw token IDs and masks returned by `step()` bypass that normalization. This drops the response prefix from both the stored training trajectory and the history used for the next inference turn. Returning only IDs can instead fail the ID/mask length assertion.

Normalize these overrides through `get_response_token_data`, retaining the completed turn's template settings before `step()` can change them. This preserves explicitly masked prefixes, sampled prefix repetitions, masked observations, and same-message continuations. Update the English and Chinese custom-scheduler documentation.

The change is limited to the default server `run()` handling `step()` overrides. It does not claim to resolve the report's colocate path or arbitrary custom `run()` implementations.

AI assistance: OpenAI Codex assisted with investigation, implementation, and validation.

## Experiment results

- `python -m unittest discover -s tests/rollout -p test_server_step_overrides.py`: 7 tests passed. The same regression cases against the original `run()` produce 6 reported failures, including the IDs-only assertion and missing-prefix checks.
- `python -m pytest -q tests/rollout/test_exact_token_io.py tests/rollout/test_server_exact_token_io.py tests/rollout/test_server_step_overrides.py -k "not multimodal_chunk_rebuild and not ray_driver_scheduler"`: 38 passed, 4 deselected, 6 subtests passed. The full three-file pytest run yields 39 passed, 2 failed, 1 error; the unchanged baseline reproduces those same failures/errors. They come from the existing `ExactTokenTemplate` missing `_get_response_prefix` (collected twice) and a top-level helper with no `trainer_name` fixture. No unrelated test fixes are included.
- `pre-commit run --all-files` and `git diff --check`: passed, including the new test file.
- CPU integration check with the real Qwen3.5-9B tokenizer/processor, `qwen3_5` non-thinking template, server scheduler and `encode_sample`: with fixed A/B engine outputs, baseline IDs+mask omit the first prefix and IDs-only raise an assertion. After the fix both turns retain the prefix with loss mask 0, and the first sampled token's training context matches its rollout prompt. This uses fixed engine outputs, not model inference or a quality benchmark.
