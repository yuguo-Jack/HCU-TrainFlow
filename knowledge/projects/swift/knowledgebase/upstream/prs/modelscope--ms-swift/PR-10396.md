# PR information

Fixes #10395

When `split_list(ori_list, num_shards, contiguous=True)` was called with `num_shards > len(ori_list)`, it relied on `np.linspace(0, len(ori_list), num_shards + 1, dtype=np.int64)` for slice indexing.
Because float truncation occurs when casting to `int64`, for `split_list([1, 2], 4, contiguous=True)`, the index list evaluates to `[0, 0, 1, 1, 2]`. This produced `[[], [1], [], [2]]`, causing Rank 0 (shard 0, typically master worker in distributed processing) to receive an empty list `[]` while items were scattered across subsequent ranks.

This PR replaces the linspace slicing in the contiguous path with standard balanced chunking using pure Python integer division (`divmod(len(ori_list), num_shards)`). This ensures:
1. Extra remainder items are evenly distributed into the leading shards, matching `torch.chunk`, `np.array_split`, and `contiguous=False`.
2. When `num_shards > len(ori_list)`, items are placed into shards `0` through `len(ori_list) - 1`, and trailing shards are empty `[]`.
3. Added validation `if num_shards <= 0: raise ValueError(...)`.
4. Avoids floating-point precision truncation artifacts on large lists and removes unnecessary numpy reliance in this basic list utility.
