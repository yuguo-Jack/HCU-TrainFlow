# PR information

Refs #10079

Add an opt-in top-k MOPD loss to the HF GKD path, following Eq. 5 in [the MOPD paper](https://arxiv.org/html/2606.30406). Enable it with `--gkd_loss_type mopd --gkd_logits_topk K`. The default remains `jsd`.

For each teacher-selected token, the loss is `p_student * (log p_student - log p_teacher) - p_student + p_teacher`. Both probabilities come from the full vocabulary at temperature 1; the selected top-k support is **not renormalized**. This preserves the probability mass outside the selected support.

The implementation reuses the existing teacher representation, response masking, and token-count reduction. Local teacher logits are normalized only on the MOPD path, teacher targets are detached, missing API top-k entries are ignored, and student normalization is computed in chunks. FP16/BF16 inputs use FP32 loss arithmetic, while FP64 is preserved for numerical checks.

The new option is carried through RLHF arguments and GKDConfig. Invalid top-k settings, Liger, and sequence parallelism are rejected for MOPD. Both English and Chinese documentation are updated. This change is limited to HF GKD and assumes shared student/teacher token-ID semantics; it does not add a Megatron path or vocabulary alignment.

### Tiny-model training through the real HF GKD pipeline

CPU FP32, single thread, random two-layer Qwen2 model (24,928 parameters; hidden size 32, intermediate size 64, 2 attention heads, 2 KV heads, vocabulary 64, no dropout), an offline WordLevel/ChatML tokenizer, and a teacher initialized from the same student plus deterministic parameter noise. The fixture uses 32 synthetic training samples and 8 fixed evaluation samples. These runs call `rlhf_main`, use the normal trainer/loss, and do not mock the loss or backward pass.

Core training arguments were:

```text
--rlhf_type gkd --gkd_loss_type mopd --gkd_logits_topk 8
--model <tiny-student> --model_type qwen2 --template chatml
--teacher_model <tiny-teacher> --teacher_model_type qwen2
--dataset <train.jsonl> --val_dataset <eval.jsonl> --split_dataset_ratio 0
--tuner_type full --torch_dtype float32 --attn_impl eager --use_cpu true
--use_vllm false --gradient_checkpointing false --padding_free false
--max_length 64 --max_completion_length 8 --temperature 1 --beta 1
--lmbda 0 --sft_alpha 0 --per_device_train_batch_size 2
--per_device_eval_batch_size 2 --gradient_accumulation_steps 1
--learning_rate 0.001 --lr_scheduler_type constant --max_steps 24
--eval_strategy steps --eval_steps 6 --logging_steps 1
--save_strategy steps --save_steps 12 --save_total_limit 2
--dataloader_num_workers 0 --dataset_num_proc 1 --report_to none
--seed 10079 --data_seed 10079 --load_from_cache_file false
```

| Run | Optimizer steps | Result |
| --- | ---: | --- |
| Unmodified main, default JSD | 24 | Preserved regression baseline |
| Patched default JSD | 24 | Every loss/gradient-norm entry and final weights exactly match unmodified main |
| MOPD, offline | 24 | Training loss 0.00639202 -> 0.000270284; fixed evaluation loss at step 6/24: 0.00177399 -> 0.000291457 |
| MOPD, same-seed repeat | 24 | Every loss/gradient-norm entry and final weights exactly match the first MOPD run |
| MOPD, on-policy | 6 | `lmbda=1`, gradient accumulation=2; finite nonzero student gradients and successful checkpoint save/reload |
| MOPD, resume from step 12 | 12 additional | Final weights and complete recorded loss/gradient-norm history exactly match uninterrupted training |

All six runs verified finite nonzero student gradients, actual student weight updates, no teacher gradients or teacher weight changes, identical logits after save/reload (maximum absolute error 0), and stable repeated greedy generation.

An additional response-only evaluation used 8 unseen prompts (40 response tokens) with the same MOPD objective: initial student **0.00647370**, JSD baseline/patched JSD **0.00534294**, and MOPD/repeat/resume **0.000562544**. This is integration/correctness evidence from a random tiny model, not a task-quality comparison.

Environment: Python 3.14.3, PyTorch 2.11.0+cpu, Transformers 5.7.0, TRL 0.29.0, PEFT 0.20.0, Datasets 4.8.4, Accelerate 1.15.0, editable ms-swift 4.6.0.dev0. On Windows, the validation runner bypassed only the optional last-checkpoint symlink update because symlink creation lacked the required privilege; checkpoint serialization, reload, and training math used repository code unchanged.

GPU/NPU, teacher-server end-to-end, pretrained task quality, performance, and the full repository test suite were not validated.
