# PR information

Adds training and inference support for **THX-02** (`--model_type thx02`, `--task_type decision`), a typed-decision model ([ModelScope](https://modelscope.ai/models/HAL-X/THX-02), [Hugging Face](https://huggingface.co/doofz/THX-02)) that answers several choice / yes-no / score questions about one input (text and images) in a single forward pass.

- `Thx02ModelLoader` (`swift/model/models/decision.py`): reads the backbone config from THX-02's own `config.json`, loads the Qwen3.5 hybrid backbone (vision + gated-deltanet / full attention), switches the full-attention layers to noncausal attention and attaches the inline readout as `scoring_head`.
- `Thx02ReadoutHead` (`swift/model/decision_head.py`): a linear readout over the answer codes at each question marker, divided by the calibrated temperature.
- `Thx02Template` (`swift/template/templates/decision.py`): renders the joint prompt with the checkpoint's own chat template and processor (text and images) and passes the marker positions as meta.
- `Thx02Preprocessor` (`swift/dataset/preprocessor/decision.py`): Decisions-API schema, gold answers or soft targets, option order preserved.
- Example script `examples/train/decision/thx02.sh` with a local mini dataset (no download needed), docs in en/zh (`BestPractices/Decision.md`, supported models table).
- Alignment test `tests/test_align/test_decision_thx02_align.py` against the reference implementation shipped in the model repo.

It reuses the existing decision pipeline (`ScoringTrainer`, `distill_rps` loss); packing / padding_free is not supported for this model, since records would attend to each other.

## Experiment results

```
THX02_MODEL_DIR=/path/to/THX-02 pytest -q tests/test_align/test_decision_thx02_align.py
6 passed   # 1x RTX 4090; full forward matches the reference implementation's probabilities
```

Without `THX02_MODEL_DIR` (and no hub access) the two checkpoint stages skip and the rest pass (4 passed, 2 skipped).

- z0o0ey · comment · 2026-10-20T08:56:27Z · [source](https://github.com/modelscope/ms-swift/pull/10398#issuecomment-6287293299)

Hello, thank you for the code. I have personally tested several aspects—loading weights without prefixes, using hooks for non-causal attention, template encoding/marker localization, flattening via the collator, LoRA training (successfully executed using SWIFT SFT, including joint training and saving of the head), and inference with adapters—and I have identified a few points that may warrant attention. Additionally, we have updated the temperature regulation mechanism within the 'decision' task in our 'main' branch; please check whether it is necessary to incorporate this functionality into your own code[pr-10399](https://github.com/modelscope/ms-swift/pull/10399)：
1. Silent misalignment under truncation strategy (Medium): In `Thx02Template._encode`, `readout_positions` are calculated before truncation occurs; however, `_encode_truncated` fails to update these positions when truncating `input_ids`. While this is not an issue with the default `truncation_strategy='raise'` (as sequences exceeding the limit trigger an immediate error), setting `--truncation_strategy` to `left` or `right` causes marker positions to go out of bounds or point to incorrect hidden states. Unlike the `Clef` template (see `swift/template/templates/decision.py:215`), which explicitly truncates the state and recalculates span offsets, the `THX-02` template lacks equivalent safeguards. It is recommended to either raise an error in `_encode` when `length > max_length` or validate the positions after truncation.

2. Late and misclassified rejection of `--packing` (Minor): Although the documentation states that `--packing` / `--padding_free` are not supported, the `NotImplementedError` is only raised during the encoding of the first batch—long after the model has been loaded and training has commenced. Furthermore, the requirement for `flash_attn` when using `--packing` is enforced within `sft_args._check_padding_free`, resulting in a poor user experience regarding error reporting. It is recommended to raise a clear `ValueError` during the `__post_init__` phase, consistent with how other decision parameters are validated.

3. Residual randomly-initialized `lm_head` (Minor; relevant to full fine-tuning): The `_thx02_forward` method bypasses the `lm_head`. Nevertheless, this randomly-initialized `lm_head` still consumes VRAM and is included in checkpoints during full fine-tuning. Moreover, in multi-GPU DDP full fine-tuning, it is treated as a "parameter with no gradients," which triggers an error when the default setting `find_unused_parameters=False` is used. (As the documentation primarily highlights the LoRA workflow, this is a potential pitfall rather than a hard blocker.)

4. Gaps in CI coverage (Minor): In the alignment tests, "Stage A" (encoding alignment) and "Stage C" (full forward-pass alignment) are automatically skipped if no actual checkpoint is present—meaning they are never executed within the CI pipeline. In other words, the critical path involving the non-causal mask and template rendering has zero coverage in the CI; it has only been tested on the author’s local machine (using an RTX 4090 and `transformers` 5.17.0). My local end-to-end experiment has filled this validation gap, but I recommend adding an integration test—perhaps using a random backbone—to the PR.

5. Minor issues: `get_processor` unconditionally overwrites `image_processor.size`, meaning any `--max_pixels` argument provided by the user is ignored (this aligns with the reference implementation, but it is worth noting in the documentation). If a key is missing in `decision_config.json`, the code raises a raw `KeyError`. In `Thx02Preprocessor`, the error message for `_resolve_gold` refers to "Clef gold." Furthermore, the `config.thx02` dictionary attached within `get_config` is never actually read by any part of the codebase. Additionally, the specified minimum version of `transformers>=5.2.0` has not been verified; while I have confirmed that the mask dictionary mechanism exists in version 5.20.1, it is unclear whether the same `layer_types` dispatch logic is present in 5.2.0. I suggest either verifying this or raising the minimum version requirement. 

- doofzoff · comment · 2026-10-20T12:20:46Z · [source](https://github.com/modelscope/ms-swift/pull/10398#issuecomment-6290705207)

Thanks for the detailed review! I rebased onto main (including #10399) and pushed a follow-up commit.

**Temperature calibration (#10399).** THX-02 now works with `TemperatureCalibrationCallback`. The head has the same `head_temperature` and per-kind `temperatures` buffers as JEV, applied on top of THX-02's own temperature. They default to 1.0, so without an eval set the probabilities match the released model. They are saved to `scoring_head.json` and restored on reload. Verified on the real checkpoint.

1. **Truncation.** A THX-02 record longer than `max_length` now raises `MaxLengthError` under every `truncation_strategy`. It is never truncated, since cutting tokens would drop questions and shift the readout positions.
2. **Packing.** `--packing` and `--padding_free` are rejected during argument parsing, before the model loads (about 5 s from the CLI).
3. **lm_head.** I checked this one: THX-02 has `tie_word_embeddings=True`, so `lm_head` shares storage with `embed_tokens` (same `data_ptr`). It is not random, uses no extra memory and has no DDP issue. I added a guard that freezes it if a config ever unties it.
4. **CI.** Added stage E, which builds a tiny random THX-02 with the real file layout and runs in about 20 s. It covers loading, the noncausal mask, padding invariance, template rendering, no truncation, `max_pixels` bounds, packing rejection, calibration round trip and a short `swift sft` with reload.
5. **Minor.**
   - `--max_pixels` can lower the resolution down to 65536 px but not raise it above the trained bound from `decision_config.json`. Documented and tested.
   - Missing `decision_config.json` keys now give a clear `ValueError`.
   - The gold error names the right model.
   - `config.thx02` removed.
   - You were right about transformers: 5.2.0 lacks `create_recurrent_attention_mask`, which first appears in 5.13.0. I raised the requirement to `transformers>=5.13.0`. All 15 tests pass on 5.13.0 and 5.17.0.

One note on the callback: when training resumes from an already calibrated checkpoint, the new fit replaces the old `head_temperature` instead of composing with it. Not an issue for a first calibration, just mentioning it.
