# PR information
1. Automatic Temperature Calibration Callback: Automatically enabled when `task_type=decision`; requires no additional parameters. After training, the model performs a forward pass on the validation set to collect logits, calculates the optimal temperature $T$, and saves it to the prediction head. This temperature scales the logits without altering the predicted answers; it ensures that when the model expresses an "80% confidence level," this corresponds to an actual 80% accuracy rate.
2. Two-Tier Temperature Mechanism: Combines a global temperature (reflecting the model's overall overconfidence or underconfidence) with a relative temperature specific to each question type, allowing for more granular calibration than a single scalar value.
3. Calibration Validation: Logs automatically report ECE (Expected Calibration Error), Brier score, and NLL (Negative Log-Likelihood) both before and after calibration. These metrics are derived via 2-fold cross-validation to ensure an "honest" assessment (avoiding the bias of evaluating the model on the same data used for calibration). In tests on the JEV model, ECE decreased from 0.165 to 0.121, the Brier score improved by 9.5%, and accuracy remained unchanged.
4. Persistence and Auto-loading: The calibrated temperature is saved to `scoring_head.json` and automatically reloaded when restoring a checkpoint or running inference via `swift infer`. Consequently, the probabilities output during deployment are already calibrated, requiring zero additional effort for deployment.
5. Multi-GPU Safety: In a Distributed Data Parallel (DDP) setup, validation set shards from all GPUs are aggregated before calculating the temperature. File writing and logging are restricted to the main process (resolving issues where multiple processes would otherwise attempt to write to the same file, with only the final write being preserved).
6. Comprehensive documentation (including best practices for "Decision" tasks) and updated README information.
