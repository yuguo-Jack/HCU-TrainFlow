# PR information

GRPO 使用 twinkle.perf 的公共记录器保存整轮耗时、有效 token、吞吐和内存指标。Swift 只标记训练边界、上报实际样本访问和更新数，不再维护独立的 performance.py。

- performance.jsonl 按完成的 rollout batch 记录，明确区分 RL iteration 和 optimizer update。
- optimizer_metrics.jsonl 保存逐更新原始指标，带 run_id 和时间戳；保留 WebUI metrics.jsonl 的平铺格式和频率。
- 计时等待真实远程完成，辅助 forward 并发提交；从逻辑时间扣除报告开销，同时保存完整墙钟。
- 使用 StreamingDriver 的公开快照；最后的清理统计单独保存为 summary。
- 训练继续使用完整 optimizer batch 和 Twinkle 内部微批接口。

依赖 https://github.com/modelscope/twinkle/pull/368 ，建议先合入 Twinkle。重新整理为一个代码和测试提交，没有新增文档。
