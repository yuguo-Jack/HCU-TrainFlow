# PR information

Honor `overlong_filter` in the Liger GRPO loss path.

The ordinary loss path excludes truncated completions when `overlong_filter=True`, but `compute_liger_loss()` currently passes the original completion mask to Liger. Truncated responses therefore still contribute to the loss and gradients when `use_liger_kernel=True`.

This two-line change filters the local completion mask before rollout importance-sampling correction, sequence-advantage reduction, and the fused loss call. The original `GRPOBatch.completion_mask` is not modified, and disabling the filter retains the existing behavior.

No existing issue specifically tracking this discrepancy was identified.

## Experiment results

For a two-response batch with one truncated response and identical input log probabilities, the truncated response's log-probability gradients are:

| Path | Before | After |
| --- | --- | --- |
| Ordinary GRPO | `[0, 0]` | `[0, 0]` |
| Liger GRPO | `[-0.25, -0.25]` | `[0, 0]` |

The paths also agree when filtering is disabled or no response is truncated.

**127 CPU checks passed**: 102 local regression/compatibility cases plus 25 existing tests in `tests/test_align/test_grpo_loss.py`. The local checks call the actual trainer loss methods and `LigerFusedLinearGRPOLoss(compiled=False)`, comparing loss and all model-parameter gradients across mixed/all/no truncation, enabled/disabled filtering, KL regularization, and supported token/sequence importance-sampling cases. All-filtered cases also produce finite zero loss and gradients.

Validated with PyTorch 2.12.1, Transformers 5.5.0, TRL 0.29.1, and Liger Kernel 0.8.1. Full distributed training has not been run.
