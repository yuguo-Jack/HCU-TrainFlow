# PR information

With `--optimizer muonclip --optim_args nesterov=true`, MuonClip currently orthogonalizes the momentum buffer and then adds the raw gradient. That raw-gradient contribution bypasses Newton–Schulz orthogonalization and RMS scaling, making the matrix update strongly dependent on gradient magnitude.

Build the Nesterov direction `grad + momentum * buffer` before orthogonalization, following [Moonlight's update order](https://github.com/MoonshotAI/Moonlight/blob/c2ad5b20c605086526a179d36901bfc41b52b44b/examples/toy_train.py#L183-L198). The stored momentum buffer remains the ordinary momentum recurrence; the Nesterov combination does not mutate it or `param.grad`.

Local CPU regression checks cover three consecutive updates of tall and wide matrices, both Nesterov settings, gradient rescaling, and the vector/explicitly non-Muon fallback against `torch.optim.SGD`. The regression script is kept locally and is not included in this PR.

Related issue: none; this fixes a reproduced problem in the existing `nesterov=true` configuration.

## Experiment results

PyTorch 2.12.1, CPU, seed 42, FP32 `(8, 4)` gradients, `momentum=0.95`, with weight decay and QK clipping disabled. Scale the gradient by 100 and compare the update norms:

| Setting | Before | After |
| --- | ---: | ---: |
| `nesterov=true` | 86.400980x | 0.993196x |
| `nesterov=false` | 0.991704x | 0.991704x |

Ratios near 1 retain the rounding variation of the existing BF16 Newton–Schulz kernel. The local scale check allows 3% tolerance. Before the fix, the Nesterov scale test and both rectangular reference cases fail; the non-Nesterov and SGD controls pass.

A separate `MuonClipOptimizerCallback` smoke check with `optim_args='nesterov=true,qk_clip_enabled=false'`, an `nn.Linear` layer and MSE backpropagation also changes the matrix-update ratio from 48.001848x to 0.997439x when the loss is scaled by 100.
