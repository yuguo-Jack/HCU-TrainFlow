# [v5] Fix RL colocate, precision, completion logs and prompt ordering

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10451) · state: closed · merged: True

## Original PR description

## Problem and changes

修复 v5 RL 的 colocate 推理设备分组、逐样本日志、计算精度和 prompt 读取顺序，目标分支为 `dev-swift-v5`。

- Colocate 训练与推理支持不同切分：sampler 使用独立的 sampler group/DP mesh，TP/PP 通过 engine_args 传入。两组仍共享物理卡；vLLM 内部 DP 固定为 1，避免重复创建外层 actor 副本。SGLang 内外 DP 尚未完成处理或实机验证。
- RL-10：共置训练遵循 log_completions，评分后写入对应 output_dir 的 completions.jsonl。
- RL-04：FP32 参数加载覆盖与计算精度独立；BF16/FP16 配置保留对应 mixed_precision，显式 FP32 配置保持 no。覆盖 GRPO/PPO/在线蒸馏的公共 builder。
- RL-14：GRPO/PPO/在线蒸馏 prompt dataloader 消费 train_dataloader_shuffle，默认 True；False 保留输入 prompts 顺序。源文件顺序还依赖关闭上游 dataset_shuffle。

配套 Twinkle PR：https://github.com/modelscope/twinkle/pull/348 （checkpoint 单 writer、完整回复日志及 FSDP worker 精度日志）。

## Scope and compatibility

按用户要求，已通过 revert 撤回 GA 更新边界、完整窗口步数预算、指标编号及相关测试修改。保留原有 v5/main 计数约定；本 PR 不再声明修复 RL-01。旧指标的零基编号及双 RPC 事务语义需要独立讨论。

## Validation

- sampler placement CPU 回归覆盖 colocate/分离 TP、PP、DP 组合和外层副本布局；原有实机实验确认 Qwen3.5-4B、8 PPU、训练 8 rank、推理 TP2×DP4 的 colocate 启动和训练，以及 completion 日志与 checkpoint 保存。
- 精度/shuffle CPU 回归通过：BF16/FP16/FP32、有/无 FP32 加载覆盖、真实 FSDP MixedPrecisionPolicy，以及真实 DataLoader 的顺序、seed/epoch 复现和尾批保留。模型下载/远程构造使用替身。
- 回退涉及文件逐一核对，与 GA 修改前一致；回退后重新运行精度/shuffle 回归。
- 此前 96 completions、cur_step=12、更新边界 4/8/12 的实机结果来自现已撤回的 GA 修改，不是当前分支的验收结果。
- 早期实机配置虽写 BF16，实际发生在 RL-04 修复前，mixed_precision=no；新增精度/shuffle 修复及本次回退后未重跑多卡训练。没有 SGLang、异构/异步、Megatron 或 checkpoint 续训的完整实机验收。
