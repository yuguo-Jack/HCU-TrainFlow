# Micro batch 切分下沉到twinke( dev swift v5)

## Original PR description

# PR type

- [x] Bug Fix
- [x] New Feature

# PR information

将 `swift/dev` 各 recipe 的微批划分统一交给 Twinkle。Swift 准备一次优化器更新所需的数据，Twinkle 在后端内部调度微批前后向与梯度累积，Swift 再执行优化器更新。

完整更新窗口仍遵循：

```text
global_batch_size
    = per_device_train_batch_size × DP × gradient_accumulation_steps
```

主要变更：

- **统一训练提交方式**：覆盖 SFT/PT、Embedding、SeqCls、Reranker、离线偏好训练，以及 GRPO、PPO、RFT 和蒸馏。按更新窗口提交数据，显式传入后端 `micro_batch_size`，跨调用的 `gradient_accumulation_steps` 设为 `1`。PPO 分别更新 policy 和 critic。
- **接入 GRPO 动态分批**：新增 `dynamic_batching`、`max_tokens_per_micro_batch` 和 `packing_algorithm`，支持 `ffd`、`kk`。更新窗口大小仍由原有批大小与 GA 决定，窗口内部的实际微批由 Twinkle 调度。目前仅开放 GRPO 的 HF/Unsloth 路径。
- **适配算法输入**：DPO/RM 将原始记录的微批大小 `B` 换算为展开后的 `2B` 条序列；偏好训练与评估的辅助前向使用对应调用的微批大小。CHORD 每个窗口分别提交 RL、SFT 两次前后向，累计后执行一次优化器更新。
- **明确重复训练与尾批边界**：GRPO/PPO 在同一批 rollout 的重复训练遍历之间连续组批，丢弃该批最终不足完整更新窗口的部分；RFT 丢弃每轮筛选结果中不足窗口的尾部。离线监督训练保留每个 epoch 末尾不足 GA 个 dataloader batch 时的更新，不跨 epoch 拼接。
- **调整蒸馏取数**：轮次路径按每次优化器更新选择 on-policy/off-policy 来源，并准备一个完整 GBS。on-policy 按所需数据量生成回答；off-policy 使用独立的数据游标，仅在选择该来源时推进。
- **合并离线公共流程**：抽取 `run_supervised()`、`fit_supervised()` 和评估状态管理，共用训练、评估、最佳模型跟踪、保存及恢复流程；各 recipe 通过 `micro_step_fn` 准备输入和辅助参数。
- **调整预算与计数**：更新优化器步数预算以匹配各路径的提交与尾批规则。`global_step` 按优化器更新计数，`micro_step` 保留名义微批统计，不依赖 DBS 实际划分出的物理微批数。
