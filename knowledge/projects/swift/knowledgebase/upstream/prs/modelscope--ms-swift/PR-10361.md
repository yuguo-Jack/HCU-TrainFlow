# fix(loss): stop clamping the decision masked cross-entropy

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10361) · state: closed · merged: False

## Original PR description

Fixes #10354.

## Problem

`ScoringLoss._masked_soft_ce` in `swift/loss/decision.py` computes

```python
probs = masked_softmax(logits, option_mask)
log_probs = torch.log(probs.clamp_min(1e-9))
return -(target * log_probs * option_mask).sum(dim=-1)
```

For a one-hot target on a confidently-wrong class, `probs[target]` falls below `1e-9` long before the optimiser can recover, and the clamp caps the loss at `-log(1e-9) ≈ 20.72` while zeroing the gradient on the target class. Training therefore stops receiving any corrective signal — the reporter saw the gradient norms collapse to zero in `distill_rps` Qwen3-0.6B decision training, with the loss pinned at `10.36 ≈ 0.5 * -log(1e-9)` (half the samples capped). Reproducible in both FP32 and BF16.

## Fix

Replace `log(softmax + clamp)` with `log_softmax`: the loss stays finite for arbitrarily small probabilities, the gradient on the target class is always non-zero, and the result is bit-identical to the old path on inputs that have not yet entered the clamped regime. `masked_softmax` already maps pad slots to 0, so `log_softmax` on the same masked logits maps them to `-inf`; `masked_log_softmax` mirrors the contract by `masked_fill(0.0)` on the pad slots.

```python
log_probs = masked_log_softmax(logits, option_mask)
return -(target * log_probs * option_mask).sum(dim=-1)
```

## Verification

New `tests/general/test_decision_ce_gradient.py` (5 tests, no model/GPU needed):

- `test_correct_class_with_tiny_probability_still_gets_gradient`: with target on a class 50 nats below the rest, the new CE produces a non-zero gradient on the target class and the pre-fix CE does not.
- `test_correct_class_loss_is_finite_under_extreme_logits`: logit = -1e3 → loss `> 20.72` and finite.
- `test_pad_slots_contribute_zero`: `masked_log_softmax` keeps the pad slots at 0 (same contract as `masked_softmax`).
- `test_one_hot_target_matches_softmax_cross_entropy`: on un-clamped inputs the new loss matches the old loss to 1e-6.
- `test_scoring_loss_subclass_uses_unclamped_path`: smoke test that `ScoringLoss._masked_soft_ce` calls into the fixed path.

All 5 pass via a standalone verifier (the full pytest suite needs the heavy `swift` import chain, exercised in CI). flake8 / isort / yapf are clean with the repo pins.

Reported reproducer (FP32 and BF16):

| dtype | old loss | old grad class 0 | new loss | new grad class 0 |
|---|---|---|---|---|
| float32 | 20.7233 | 0.0 | 51.0986 | -1.0 |
| bfloat16 | 20.7233 | 0.0 | 51.0986 | -1.0 |
