# PR information

Related issue: none.

This is a performance optimization of entropy computation and autograd storage. The GRPO objective and entropy-filtering rule are unchanged.

With padding-free GRPO and entropy logging or filtering enabled, the local forward passes packed `[total_nnz, vocab_size]` logits to an entropy helper whose default chunk size is one along dimension 0. This invokes log-softmax once per token. Because the training logits require gradients, entropy also retains intermediate tensors for backward, even though this GRPO path uses it only for metrics and a boolean quantile mask.

This change touches two production files:

- Compute entropy in token-row chunks and restore all leading dimensions. The default chunk size accounts for vocabulary width and dtype, targeting 16 MiB across the log-probability, probability and product buffers, with a minimum of one row. An explicit token chunk size remains supported.
- Handle empty inputs and noncontiguous slices without copying the full logits tensor just to flatten it.
- Use the local helper consistently instead of conditionally importing TRL's implementation.
- Disable gradient recording only for entropy statistics/filtering in the local and sequence-parallel GRPO forward paths. The model forward and sampled-token logprobs remain differentiable; the shared entropy helper itself remains differentiable for other callers.

No new classes, dependencies, configuration flags or committed test artifacts.

## Experiment results

A local validation harness loaded the production entropy helpers and `_get_logps_via_local_forward` directly from source, comparing the change against base commit `2286b0351`.

For FP32 logits of shape `[1024, 2048]`, on both CPU and CUDA:

| Measurement | Previous helper | New default | Explicit 128-token chunks |
| --- | ---: | ---: | ---: |
| `aten._log_softmax` calls | 1024 | 2 | 8 |
| Unique underlying storage saved by entropy autograd | 16 MiB | 0 | 0 |

Zero saved storage means no retained entropy backward intermediates; temporary computation buffers still exist. This is an operator/storage comparison, not an end-to-end throughput benchmark.

Maximum entropy difference was 0 on CPU and `9.54e-7` on CUDA. GPU batching can change rounding, so entropy is not claimed to be bitwise identical on CUDA.

A trainable embedding/Linear policy exercised positive and negative advantages, valid-token masking, top-20% entropy filtering, backward and one SGD step. Across **24 cases** (CPU/CUDA × FP32/FP64 × three seeds × padded/packed), the selected masks, loss, all parameter gradients and updated parameters were exactly equal. Sampled-token logprobs retained gradients, while GRPO entropy outputs did not.

Additional checks covered shape restoration, empty dimensions, noncontiguous inputs without a full flattening copy, standalone helper gradients and the entropy-disabled path.
