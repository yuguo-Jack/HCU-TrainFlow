# fix(dataset): invalidate metadata cache on registration

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10160) · state: closed · merged: True

## Original PR description

After the first dataset lookup, `DatasetSyntax` keeps an ID/path-to-metadata cache. A later `register_dataset()` call updates `DATASET_MAPPING` but leaves that cache unchanged, so newly registered datasets fall back to default preprocessing and `exist_ok=True` replacements continue using the previous configuration. This affects repeated Python/notebook use, including `register_dataset_info()` followed by `load_dataset()`.

Invalidate the lookup cache after a successful registration so the next lookup rebuilds all aliases. Rejected duplicate registrations leave the existing metadata intact.

Validation: the three new regression tests fail on main and pass with this change. They cover HF/ModelScope IDs, replacement of aliases, and loading a local JSONL file before and after changing its registered preprocessor. The new tests plus existing dataset source/routing tests pass (7 tests); changed-file pre-commit checks pass. Whole-repository lint currently has an unrelated formatting failure in `tests/megatron/test_infonce_ddp_e2e.py` on the base revision.
