# PR information

`swift.utils.time_synchronize()` falls through to `torch.cuda.synchronize()` when CUDA, NPU and MUSA are unavailable. On this Mac, both the CPU call and synchronization after real MPS tensor operations raise `AssertionError: Torch not compiled with CUDA enabled`.

Make CPU synchronization a no-op and use `torch.mps.synchronize()` for MPS. Honor explicitly requested CPU/MPS devices. Keep device forwarding for CUDA/NPU/MUSA, MUSA's precedence over patched CUDA, and errors for explicitly requested unavailable CUDA devices.

## Experiment results

macOS arm64, Python 3.11.15, PyTorch 2.4.1:

- Before: `python -m pytest tests/utils/test_synchronize.py -q` — **7 failed, 4 passed**.
- After: `python -m pytest tests/utils/test_synchronize.py tests/utils/test_musa.py::TestMusaDeviceHelpers tests/utils/test_max_reserved_memory.py -q` — **22 passed**.
- `pre-commit run --all-files` — all ten hooks passed.

The CPU and MPS tests ran on real devices; CUDA/NPU/MUSA routing was tested with mocks. No full model training was run.
