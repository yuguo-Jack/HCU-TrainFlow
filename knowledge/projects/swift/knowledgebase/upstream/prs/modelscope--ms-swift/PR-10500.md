# PR information

Fixes #10498

Replaces #10499.

Saturate the two length rewards once the total generated-token count exceeds their configured maximum. CosineReward keeps the configured maximum-length value for correct or incorrect answers. SoftOverlong keeps the documented DAPO penalty of -1.

The length can exceed the reward threshold when it is configured below the generation limit or when a rollout contains multiple turns. The current cosine oscillates beyond that threshold, and the soft-overlong penalty grows without a lower bound. Extend the existing length-reward tests and document the saturation behavior in English and Chinese.

The evidence comes from the public report and constructed CPU reproductions. Duplicate checks covered all 164 open PR titles and file lists, the issue timeline, and related historical PRs. #10149 added multi-turn token counting. Open #10266 changes MathORM and does not address these length rewards.

## Experiment results

Tested against main `ef4953a4dc65ded0f9fd33776ee76f4d96880663`, using Python 3.13, PyTorch 2.14.0, Transformers 5.17.0 and TRL 0.29.1 on CPU.

```bash
.venv/bin/python -m pytest tests/utils/test_multiturn_length_rewards.py tests/utils/test_reward_metrics.py tests/utils/test_rewards.py tests/utils/test_async_rewards.py tests/train/test_grpo_reward_metrics.py -q
.venv/bin/python -m pre_commit run --all-files
.venv/bin/python -m pip check
git diff --check
```

- Original implementation with the expanded length-reward suite fails 25 subcases. These include flat and multi-turn overlong inputs, configurable cosine endpoints, and RolloutOutput → GRPOSample → score_completions.
- Fixed related suite passes 42 tests and 78 subcases, with no skips. All configured pre-commit hooks, dependency checks and diff checks pass.
- A constructed one-step SwiftRLHF run uses a local randomly initialized one-layer Qwen2, real generation, both built-in rewards, and the normal forward/backward path. Both versions generate identical 3-token and 8-token responses. With reward maxima of 2 and soft_cache_length=1, the original cosine rewards are -0.25/-0.5 and soft-overlong rewards are -2/-7. After the fix they are 0/0 and -1/-1.
- With both reward maxima set to 8, the same experiment produces identical tokens, rewards and gradient norms before and after the fix. Multi-turn token partitioning is covered through the real reward dispatch in the tests. The model experiment is single-turn and validates the training path on CPU.

AI assistance was used for investigation, implementation and validation.
