# PR information

Refs #10307

This PR replaces the AutoAWQ export path with GPTQModel while preserving the existing `--quant_method awq` interface.

It also:

- Adds `ms-swift[awq]` as an optional dependency.
- Supports image calibration for Qwen2-VL.
- Preserves the `--quant_batch_size -1` behavior.
- Documents known dependency conflicts and current export limitations.

Issue #10307 concerns dependency conflicts during AWQ model fine-tuning. This PR is related to that issue but does not claim to resolve the fine-tuning problem.

## Current limitations

This implementation is not yet a drop-in replacement for every previous AWQ use case:

- Explicit `--device_map` and some custom model-loading options are not supported.
- Multimodal AWQ calibration currently supports Qwen2-VL images only.
- Qwen2-VL was tested with a randomly initialized small model, not a pretrained model or an accuracy benchmark.
- The optional dependency does not resolve the declared conflicts between GPTQModel, SwanLab, and ms-opencompass.

## Experiment results

Tests were performed on an NVIDIA GeForce RTX 4090 D with Python 3.12, PyTorch 2.11.0+cu130, Transformers 5.14.1, GPTQModel 7.3.2, and vLLM 0.25.1.

- Qwen3-0.6B AWQ, GPTQ, and GPTQ v2 GPU exports completed. vLLM loaded each exported model and generated text.
- The tested GPTQ v2 export was converted to GPTQ v1 during saving; the exported configuration recorded the actual format.
- A nonzero LoRA adapter was merged before AWQ export.
- A synthetic small Qwen2-VL model completed image calibration, AWQ export, reload, and generation with image inputs.
- `--quant_batch_size -1` completed an AWQ GPU export.
- The opt-in GPU integration suite passed for AWQ, GPTQ, and GPTQ v2:

  ```bash
  SWIFT_TEST_QUANT_MODEL=/path/to/Qwen3-0.6B \
  SWIFT_TEST_QUANT_DATASET=/path/to/c4_demo.jsonl \
  python -m pytest -q tests/export/test_quant_gpu_integration.py
  ```

- AWQ unit tests, GPTQ saved-format tests, the optional-dependency metadata test, and `pre-commit run --all-files` passed.

The diagnostic image still had dependency conflicts: GPTQModel 7.3.2 requires protobuf >=7.34 and NumPy 2.2.6 on Python 3.12, while SwanLab 0.9.2 requires protobuf <7 and ms-opencompass 0.1.6 requires NumPy <2. Therefore, `pip check` did not pass for the complete diagnostic image.

AI assistance was used to develop and test this change.
