# PR information

Fixes #10498

`CosineReward.cosfn` computes `cos(t * pi / T)`, where `t` is the summed completion length and `T` is `cosine_max_len`. Cosine is periodic, so once `t > T` the reward wraps around. A correct two-turn answer of 2048 tokens (with `T = 1024`) gets +1.0, the same as an empty answer. `SoftOverlong` keeps going below -1 for long completions, while DAPO bounds the penalty to [-1, 0].

The change clamps `t` to `T` in `cosfn` and the `SoftOverlong` reward to -1.0. Completions at or below the limits score as before.

## Experiment results

Run in a Linux container (CPU only).

- Script from the issue: on main, the correct 2048-token answer scores +1.0 and `SoftOverlong` gives -5.0 at 2048 tokens and -9.0 at 3072 (exit 1). With the fix the correct answer scores +0.5, the same as at 1024 tokens, and `SoftOverlong` stays at -1.0 (exit 0).
- A sweep over lengths 0 to 3T for T in {8, 64, 512, 1024, 4096}: on main, every step past T breaks the documented monotonic ordering. With the fix, none do.
- 6,300 generated inputs checked against the documented behaviour of both rewards, with no mismatches.
