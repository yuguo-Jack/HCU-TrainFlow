# PR information

Alpha-divergence DPO can produce NaN/Inf even when the loss and gradients are representable. With FP16 sequence log-probabilities of -44 for both policy responses and -20 for both reference responses, alpha=0.5 and beta=0.1, the loss becomes NaN instead of log(2). The exponent cap itself overflows while rounding in FP16. Separately, dividing the exponential difference by alpha before multiplying by beta can overflow an otherwise finite scaled margin, including in FP32.

This patch:

- Computes the exponent cap with Python math, outside the input tensor's low precision.
- Promotes FP16/BF16 sequence log-probabilities to FP32 before the alpha-divergence calculation, preserving FP64 inputs.
- Applies beta/alpha together for losses using the scaled margin; retains the unscaled margin required by IPO.

Only sequence-level tensors are promoted. This PR contains one production file; the additional numerical regression tests remain local at the submitter's request. It addresses these two overflow paths, not general cancellation near alpha=0 or every possible extreme input.

Related: #10313 fixes DiscoPOP's modulated exponential, a different loss branch. Searches for open PRs referencing #10313, `_get_exp_cap`, or `alpha_divergence` found no duplicate alpha-divergence fix.

AI assistance: OpenAI Codex implemented the patch and ran the validation below. Human review/attestation items remain unchecked.
