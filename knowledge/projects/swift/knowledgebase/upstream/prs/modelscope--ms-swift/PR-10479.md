# PR information
1. Integration of new models.

2. Patch-chain fix: Resolved an issue where the scoring head wrapper would bypass the original `forward` method when `forward` had already been patched (e.g., in `device_map` scenarios). This fix also benefits other decision-based models.

3. Deduplication of "gold" lookups: Added an `_lookup_gold` method to the `ScoringPreprocessor` base class. This replaces a redundant 5-line block of code—previously duplicated across the `Clef`, `OmniJev`, `Kev`, and `Laya` preprocessors—that handled the fallback mapping from "question-level gold" to "answers."

4. Stricter error handling for `Kev`: Previously, if a `question` in `parse_record` was not a dictionary, it would be silently converted into `{'question': str(q)}` (which inevitably led to subsequent errors or invalid output rows). This has been updated to explicitly raise a `ValueError`.
