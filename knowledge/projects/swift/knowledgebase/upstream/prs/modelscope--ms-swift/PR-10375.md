# PR information

Fixes #10374 

When lazy encoding fails before and after a checkpoint, recreating `LazyLLMDataset` resets its shared fallback cursor. Resuming at the correct sampler position can therefore return different replacement rows than uninterrupted training.

Derive bounded, non-repeating fallback candidates from a dataset seed and the requested index, only after the first encoding failure. This removes access-history-dependent selection without changing checkpoint code. Keep strict mode, the total attempt limit, valid-row access and exclusion of the initial failed row. Document the deterministic candidate behavior and add resume/access-order regression tests.

The same failing index uses the same candidate order across epochs. Different failing indices may still share a replacement. Determinism assumes unchanged dataset order, seed and encoding outcomes; the old replacement sequence is intentionally not preserved.

## Experiment results

- Checkout validation: `python -m pytest tests/general/test_lazy_dataset_retries.py -q` — 8 passed, 9 subtests passed; `pre-commit run --all-files` — passed.
- The same class was applied directly to installed Swift 4.4.2 and its tests passed there as well.
- GPU integration reproduction uses Magnus/Megatron Bridge with Qwen3-0.6B-Base, 2×B200, BF16, 8 steps, global batch 4, seed 42, lazy tokenization, no packing/streaming/shuffle, and zero DataLoader workers. Rows 2 and 20 exceed max_length=256. Compare uninterrupted training with an independent run stopped after the synchronous step-4 checkpoint and resumed in a fresh process.
- Before (archived 2026-10-14 run): first post-resume fallback changes the step-6 batch; maximum loss difference `0.0024992227554321289`.
- After (final `2**30` seed-range implementation): all 32 batch pairs and all 16 per-rank scalar-loss byte comparisons match exactly; maximum logged loss difference is 0 across steps 1–8. Both ranks resume at step 4 / consumed_samples 16. No tolerance or fallback-state restoration is used.
- This is an integration reproduction through Magnus, not a full native Swift CLI or multi-worker validation. Each plot compares uninterrupted/resumed runs within one implementation.
