# PR information

Related issue: none.

When `loss_type=fipo`, both the HF and Megatron GRPO trainers compute discounted Future-KL using 128-position blocks of a decay matrix. Blocking limits temporary memory, but still constructs T² decay elements and performs O(BT²) accumulation for a batch of B sequences of length T.

Replace that accumulation with a discounted suffix scan:

```text
F[t] = sum(gamma ** (j - t) * d[j], j=t..T-1)
     = d[t] + gamma * F[t+1]
```

The implementation doubles the covered suffix length each iteration, taking O(BT log T) work and O(BT) storage. At T=1024, it replaces eight accumulation matrix multiplies with ten scan stages and constructs no decay matrix.

The change is limited to the two existing `_compute_fipo_influence` methods: **14 insertions, 22 deletions**, with no new classes, dependencies or configuration options.

- Preserve token positions, including holes in the completion mask. Zeroed tokens still occupy their original discount distance.
- Keep dual-clip participation, the final completion mask, influence clipping and the safety mask.
- Compute each stage's coefficient from the original dtype-matched `gamma.pow(offset)`, avoiding additional rounding from repeated squaring.
- Add `@torch.no_grad()` to the influence calculation. Influence weights were already detached before use in the policy loss; model/logprob gradients remain outside this method.

Ordinary GRPO does not call this method and receives no performance benefit from this change.

## Experiment results

Compared the actual production methods in both files against base commit `2286b0351`, extracting them from source without requiring a full distributed trainer initialization.

**Numerical and gradient validation:** 288 cases across HF/Megatron × CPU/CUDA × FP32/FP64 × three seeds × four discounts (0, the default, 0.999, 1) × three clipping profiles. A trainable Linear policy exercised positive/negative advantages, masked holes and tails, fully masked sequences, backward and one SGD step. All comparisons passed.

Maximum absolute differences under the default FIPO settings, across CPU/CUDA and both implementations:

| Quantity | FP32 maximum absolute difference |
| --- | ---: |
| Future-KL | 2.98e-7 |
| Influence weight | 2.38e-7 |
| Parameter gradient | 7.45e-9 |
| Parameter after SGD | 2.33e-10 |

The broader checks used FP32 `rtol=2e-6`, with `atol=1e-6` for Future-KL/weights and `atol=2e-8` for loss/gradients/updated parameters. Clipped weights used the absolute tolerance alone. FP64 used `rtol=atol=2e-12`.

These are comparison tolerances, not universal absolute-error guarantees. Near-unit discounts with influence clipping disabled can amplify differences through `exp`: the largest observed absolute weight difference was 1.95e-3, while still passing the relative check.

Also passed 72 boundary cases (empty/single-token/non-power-of-two lengths, noncontiguous inputs, masks, gamma=0/1) and 24 length-4096 comparisons. The latter's maximum Future-KL difference was 3.87e-7. New influence outputs and metrics have no autograd graph.

**Function microbenchmark:** NVIDIA RTX A1000 Laptop GPU, PyTorch 2.12.1+cu130, FP32, batch=2, default FIPO settings. HF results, averaged over 15 calls after warmup with CUDA synchronization:

| Sequence length | Matrix implementation | Suffix scan |
| --- | ---: | ---: |
| 128 | 0.148 ms | 0.195 ms |
| 1024 | 0.477 ms | 0.232 ms |
| 4096 | 6.086 ms | 0.266 ms |

Short sequences can be slower due to scan launch overhead. These are local function timings, not end-to-end training speedups.

At length 1024, measured accumulation matrix-multiply calls decreased from 8 to 0, and unique storage retained by this method for autograd decreased from 4,206,592 bytes to 0. Temporary computation buffers still exist.
