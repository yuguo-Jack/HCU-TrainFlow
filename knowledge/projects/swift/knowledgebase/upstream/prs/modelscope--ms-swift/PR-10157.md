# PR information

Activation offload deduplicates saved tensors by their storage address and dtype.
A tensor and its transpose therefore share a CPU copy even though their values
have different layouts. Reloading only reshapes that copy: a square transpose
silently uses the wrong activations in backward, while a smaller slice can fail
to reshape.

Include the device, shape and strides in the key, and use `data_ptr()` for the
starting address. Identical views still share a copy. The offload schedule and
transfer implementation are unchanged.

## Experiment results

```bash
python -m unittest discover -s tests -p test_activation_offload_views.py -v
```

All four tests pass on one CUDA device, including actual transfer/reload and
FP32/BF16 backward comparisons. The original code fails the view checks and
produces wrong gradients for both dtypes. With CUDA hidden, two tests pass and
the two transfer tests are skipped.

A separate single-GPU FSDP2 check wraps three small linear/nonlinear blocks and
enables the public activation-offloading helper. The original code disagrees
with the eager reference on the first backward; the fix matches all gradients
and parameters across three SGD updates. This is a small correctness check,
not a throughput benchmark; multi-GPU FSDP and NPU were not tested.

Changed-file pre-commit checks pass. The all-files run also encounters the
existing isort/YAPF formatting issue in `tests/megatron/test_infonce_ddp_e2e.py`
from #10150, which is outside this patch.
