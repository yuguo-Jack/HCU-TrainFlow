# fix(utils): give each checkpoint save its own staging symlink name

[Upstream PR](https://github.com/modelscope/ms-swift/pull/10344) · state: open · merged: False

## Original PR description

## Problem

Concurrent checkpoint-save callbacks interfere through the shared `last-checkpoint.tmp` staging symlink: one caller may report success while publishing another caller's checkpoint target, and the other can lose its staging path entirely (#10336, with a deterministic reproduction).

## Root cause

`update_last_checkpoint_symlink` staged the swap through a fixed `{link}.tmp` name and removed any existing file there before re-creating it. The destination replacement is atomic, but the staging name is shared between writers, so the remove/replace window interleaves.

## Fix

Name the staging link after the writing process: `{link}.{pid}.tmp`. Each writer only ever removes and replaces its own staging link; the destination replacement stays atomic and the link target stays relative.

## Testing

Added `test_last_checkpoint_symlink_concurrent_writers`: a second writer's staging link exists while another update runs, and the update neither consumes nor republishes it; when the second writer publishes, its own target lands. All 7 tests in `tests/utils/test_io_utils.py` pass (verified on Linux, where symlink creation is unprivileged). The pre-existing test's no-leftover assertion was updated for the pid-suffixed staging name.
