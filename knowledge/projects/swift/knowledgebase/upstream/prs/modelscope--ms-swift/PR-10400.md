# PR information

Add unit tests for the loss implementations that live in this repo. New files under
`swift/dev/tests/component/loss/`:

| File | Covers |
|---|---|
| `test_base.py` | `BaseLoss` contract, `loss_map` registry |
| `test_causal_lm.py` | `CustomCrossEntropyLoss`: denominator, `num_items_in_batch`, label roll |
| `test_embedding.py` | pair / multi-negative parsers, cosine / contrastive / online-contrastive / infonce (full switch matrix) |
| `test_reranker.py` | pointwise and listwise reranker (grouping, min group size, temperature) |
| `test_dpo_loss.py` | `DPOTrainer.dpo_loss`: all 14 variants, both f-divergences, `reference_free`, label smoothing, rewards |
| `test_gkd_loss.py` | `jsd_loss` (β = 0 / 1 / mixture, chunking) and `gkd_loss` (full-vocab + top-k, dropped empty positions, vocab alignment) |

Conventions: function-based tests, plain `assert`, no markers (pure CPU, no downloads), so they run in
the PR tier `pytest -m "not slow"`.

One test is marked `xfail`: the legacy `InfonceLoss` gathers across DP ranks with a 2-D local tensor
mixed into a list of 3-D per-rank tensors, so `torch.cat` raises for `world_size > 1` on the plain
(non-Megatron, non-sequence-parallel) path. The defect is recorded, not changed; it will flip to
XPASS once fixed.

- kevssim · comment · 2026-11-03T03:06:50Z · [source](https://github.com/modelscope/ms-swift/pull/10400#discussion_r4450512151)

File: `swift/dev/tests/component/loss/test_embedding.py` · line 325

这个 xfail 记录的崩溃来自 mock，不是 `InfonceLoss` 的问题。真实的 `accelerate.utils.gather_object` 会把结果展平一层（`[x for y in outputs for x in y]`），所以每个 rank 返回的是 2 维张量，第 168 行的 `torch.cat` 不会报错。生产代码先 `unsqueeze(0)` 再 gather，就是为了配合这次展平。

建议让 mock 按同样方式展平：
```python
lambda obj: [*obj, *other.unsqueeze(0)] if obj.dim() == 3 else [*obj, *other_labels]
```
然后去掉 xfail，PR 描述里关于这个缺陷的说明也一起删掉。我本地按这个改法试过，不报错，loss 和单进程算整个 batch 的结果一致（都是 1.1275）。

- kevssim · comment · 2026-11-03T03:06:50Z · [source](https://github.com/modelscope/ms-swift/pull/10400#discussion_r4450512159)

File: `swift/dev/tests/component/loss/test_embedding.py` · line 329

两个问题：
1. `gathered` 是在 monkeypatch 生效之后算的，同样走了 `world_size > 1` 加 mock 的分支，起不到参考值的作用。请把它移到 `monkeypatch.setattr` 之前。
2. 每个 rank 只有 3 行数据（anchor、positive、negative），labels 应该是 `[1, 0]`，不是 `[1, 0, 0]`（参考第 231 行的约定）。

- kevssim · comment · 2026-11-03T03:06:50Z · [source](https://github.com/modelscope/ms-swift/pull/10400#discussion_r4450512167)

File: `swift/dev/tests/component/loss/test_gkd_loss.py` · line 54

student `[1, 0]` 和 teacher `[0, 1]` 互为镜像，正向 KL 和反向 KL 的值相同（都是 0.4621）。即使 β = 0 和 β = 1 的分支写反了，这两个测试也照样通过；β = 0.5 的测试同理。建议换成不对称的输入，比如 `[2, 0, -1]` / `[0, 1, 0.5]`，并断言两个方向的结果不相等。
