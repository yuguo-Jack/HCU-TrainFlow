# feat(inkling): add Inkling (Small and Large) text backbone to the Megatron backend

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1256) · state: closed · merged: True

## Original PR description

## Summary

Adds the text backbone of Thinking Machines' **Inkling** (`thinkingmachines/Inkling-Small`, 263.7B total / 12.0B active parameters, and `Inkling`, the Large model, 947.0B / 41.1B) to the Megatron backend as `model_type: inkling`. The numerical reference is the official transformers `models/inkling` code (commit `263c5eb9`); Miles is the design reference. Multi-token prediction, vision and audio are not included.

- **Correctness, one GPU:** a tiny fp32 model matches transformers' logits, loss and every gradient to 1e-5, on both attention backends. The released Inkling-Small layers 0–5 (one full sliding/global period, dense and MoE layers) imported through the converter match the reference to 1.5e-6.
- **Correctness, 8 GPUs:** under DP 8, EP 8, PP 2 / 4 / 8 and interleaved PP, one training step matches the reference run in fp64. The loss agrees to 7 digits, and every tensor gradient is within 3.3e-6, the same as the reference's own fp32 error.
- **Training:** 50-step runs on one MI355X node with the 12-layer Small proxy and the 6-layer Large proxy (released widths), with AdamW, Muon and distributed Muon. No NaN or skipped steps.
- **Convergence:** a 1.5B Inkling trained for 500 steps on FineWeb-Edu from the same weights and samples as the transformers reference ends within 0.03 (0.6%) of it in loss, about the size of seed-to-seed variation. Muon and distributed Muon end 0.38 below AdamW and agree with each other to 0.002.

Draft: the gaps that block real pretraining are listed at the end.

## What's in this PR

**Model** (`primus/backends/megatron/core/models/inkling/`, `core/transformer/inkling/`)
- `InklingModel`: embedding RMSNorm, untied LM head scaled by the muP width multiplier, and masking for the padded vocabulary.
- `InklingTransformerConfig`: per-layer geometry. Sliding layers (512-token window) and global layers have different head and KV-group counts in Large (16 vs 8 KV groups).
- Attention with the learned relative-position bias, in two backends. `eager` builds a dense bias and serves as the reference. `flex` adds the bias in a FlexAttention `score_mod` with a cached block mask, so no `[s, s]` tensor is stored. Global layers also apply log scaling. `r` has its own projection (`linear_rel`), so `linear_qkv` keeps Megatron's grouped q/k/v layout.
- ShortConv: four causal depthwise convolutions per layer, in fp32.
- MoE: a sigmoid router with the shared-expert sink and expert-score correction bias (no auxiliary loss), plus `global_scale`, with TE grouped experts. Layers 0–1 use a dense SwiGLU MLP.
- `inkling_hf_mapping.py`: the release ↔ Megatron weight mapping, used by the converter and the tests.

**Muon** (`patches/inkling_muon_qkv_patches.py`): Megatron's Muon splits `linear_qkv` into q, k and v using one shape for the whole model. In Large, sliding and global layers have different KV-group counts, so the split crashed (`shape '[9, 1280, -1]' is invalid`). The patch gives each `linear_qkv` weight its own layer's split shape, including on the fp32 master copies. It is enabled only for `model_type: inkling` with a Muon optimizer.

**Wiring**: `import_utils.get_model_provider` and `megatron_pretrain_trainer.py`, which reuses `pretrain_gpt`'s forward step and datasets.

**Configs, tools, docs**
- Presets: `inkling_small`, `inkling_large`, the proxies `inkling_small_12L` and `inkling_large_6L`, and `inkling_small_tiny` for tests.
- `examples/megatron/configs/MI355X/inkling_small_12L-BF16-pretrain.yaml` and `inkling_large_6L-BF16-pretrain.yaml` (same recipe, different model).
- `tools/checkpoint_conversion/convert_inkling_hf_megatron.py`, which converts a Hugging Face checkpoint to a single-rank Megatron `torch` checkpoint and has a header-only `--dry-run`. Both modes need one visible GPU, because Transformer Engine layers will not build without one, but they allocate no GPU memory; without a GPU the converter exits at once with that message.
- `tools/convergence_test/prepare_dataset.py --eod-token`: names the end-of-document token for tokenizers with no eos token. Inkling's tokenizer defines none, so the script refused it; with `--eod-token '<|endoftext|>'` every document ends in 199999, and the tokenizer copy saved with the data has that token as its `eos_token`, so training that loads it reports the same id.
- `README.md` (usage, and the recipe for training on real data) in `core/models/inkling/`.

## Changes since the first draft

Fixes for the review comments, plus a merge of `main`:
- **Converter vocabulary:** the embedding and LM head are now trimmed or zero-padded to the vocabulary training builds. That is `unpadded_vocab_size` rounded up to `--make-vocab-size-divisible-by` × `--tensor-model-parallel-size`, giving 200,064 with the defaults. Before, the converter kept the release's 201,024 rows, and the converted checkpoint failed to load with the documented recipe.
- **Fully masked attention rows:** eager attention now gives a query with no allowed key an all-zero output, matching flex, instead of a uniform average over every key.
- **ShortConv and document boundaries:** the builder rejects `reset_attention_mask`, because the ShortConvs would mix tokens across document boundaries that attention hides. Padded rows are documented as unsupported.
- **8-GPU check:** a NaN gradient error or a non-finite loss now fails.
- **Docs and lint:** fixed the file endings the lint check flagged; the test READMEs now include the Emerging-Optimizers setup the Muon tests need.

Added since:
- **Real data:** `prepare_dataset.py --eod-token`, and the recipe for real-data training in the Inkling README.
- **Convergence:** the 500-step comparison against the transformers reference, with plots (`core/models/inkling/assets/`).
- **Selective recompute:** `recompute_granularity: selective` with `core_attn` (Megatron's default module list) used to be silently ignored, because Inkling's attention `forward` called the core directly. It now runs the core under `tensor_parallel.checkpoint`, with `rel_states` and `rel_proj` as inputs. A new test, `test_selective_core_attention_recompute`, runs on the eager and flex backends; it checks that the checkpoint runs once per attention layer and that the fp32 loss and gradients are unchanged. A 50-step Small AdamW run with recompute on gave a loss of 5.7610 (5.7620 with it off), 1.75 GB less memory per GPU and 2% slower steps; the saving is small because flex attention stores no sequence × sequence tensors. The `layernorm` and `mlp` modules were ignored too, because the layer override calls both norms and the MLP directly; they now follow `TransformerLayer` (the norm outputs are dropped after use and rebuilt during backward, and dense MLPs run under a checkpoint, using `te_checkpoint` with fp8/fp4). The test is now `test_selective_recompute`, covering `core_attn`, `layernorm`, `mlp` and all three on both backends; it also checks that every dropped norm output is rebuilt. A 50-step Small AdamW run with all three gave a loss of 5.7618 (5.7617 with recompute off), 3.6 GB less memory per GPU and 2% slower steps.
- **Deferred LM-head weight gradient:** with `defer_embedding_wgrad_compute: true`, the LM head now gets the activation and gradient buffers Megatron's pipeline schedule expects, as in `GPTModel`; before, the first forward crashed. `test_deferred_lm_head_wgrad_matches_immediate` builds a last pipeline stage, runs two microbatches through the schedule's buffer clear and drain, and checks that the drained gradient equals the immediate one. A 20-step Small run at PP 2 / EP 4 trained the same with the option on and off (loss 7.1133 vs 7.1106 at step 20) and was 3.4% faster, using 22 GB more memory per GPU for the buffered microbatches.
- **Converter without a GPU:** the converter's docstring said `--dry-run` works on a login node, but Transformer Engine, Megatron's router and the `mamba_ssm` import all need a GPU. The docstring and README now say one visible GPU is needed, and the converter checks for it before importing Megatron.
- **Large recipe:** `inkling_large_6L-BF16-pretrain.yaml`, a separate example config for the Large proxy. It was previously run through the Small config with `PRIMUS_MODEL=inkling_large_6L`. A 10-step run with it on Oct 21 gave the same losses as the Oct 19 Large AdamW run through step 7; after that the shorter learning-rate schedule takes over.

### 8 GPUs: parallel layouts against the reference, 14 of 14 passed

```bash
PYTHONPATH=/tmp/inkling_ref/site torchrun --nproc-per-node 8 \
    tests/unit_tests/backends/megatron/inkling/parallel_reference_check.py
```

The check runs one training step of an 8-layer fp32 Inkling (dense layer 0, MoE layers 1–7, global attention on layers 3 and 7) through Megatron's pipeline schedules. The batch is a fixed 16 × 256 tokens. Each rank loads its slice of the reference weights. The global loss and every gradient (summed over data-parallel ranks) are compared with the reference run in fp64 on the full batch.

| Layout | PP × virtual stages | EP | DP | Microbatches | Worst tensor grad error (eager / flex) | Worst `global_scale` error (eager / flex) |
| --- | --- | --- | --- | --- | --- | --- |
| `dp8` | 1 | 1 | 8 | 2 | 2.8e-6 / 2.8e-6 | 1.1e-5 / 2.8e-6 |
| `ep8` | 1 | 8 | 8 | 2 | 3.3e-6 / 3.1e-6 | 3.2e-6 / 2.6e-6 |
| `pp2_ep4` | 2 | 4 | 4 | 4 | 2.4e-6 / 2.7e-6 | 2.9e-6 / 3.5e-6 |
| `pp4_ep2` | 4 | 2 | 2 | 8 | 2.5e-6 / 2.6e-6 | 1.4e-5 / 1.4e-5 |
| `pp8` | 8 | 1 | 1 | 16 | 2.8e-6 / 2.8e-6 | 1.1e-5 / 3.3e-6 |
| `pp2_vpp2_ep4` | 2 × 2 | 4 | 4 | 4 | 2.4e-6 / 2.7e-6 | 2.9e-6 / 3.7e-6 |
| `pp4_vpp2_ep2` | 4 × 2 | 2 | 2 | 8 | 2.5e-6 / 2.6e-6 | 1.4e-5 / 1.5e-5 |

- Errors are max |diff| relative to each tensor's largest value. The limit is 1e-5 for tensors and 1e-4 for the one-element `global_scale` gradients.
- Each `global_scale` gradient sums thousands of cancelling terms, so its fp32 rounding depends on the data and on the number of microbatches. The reference's own fp32 run is off by 1e-6 to 4e-5 on them.
- In every layout the loss is 6.2149262, equal to fp64.

### Convergence: 500 steps against the transformers reference, real data

Megatron Inkling and transformers' `InklingForCausalLM` (`263c5eb9`) trained the same model from the same weights on the same samples, in the same order. Runs on Oct 20–21 (jobs 227510 and 229734), with the code of `dea24bd5`. The harness (weight creation, the reference trainer and the comparison) was a set of scratch scripts and is not part of this PR.

**Model:** a 1.512B-parameter Inkling-Small at reduced width, small enough for the reference to train with plain DDP. Everything not listed is Inkling-Small's value.

| | Convergence model | Inkling-Small |
| --- | --- | --- |
| Layers | 12: dense MLP on 0–1, MoE on 2–11; global attention on 5 and 11, sliding on the rest | 42 |
| Hidden size | 1024 | 4096 |
| Attention heads, head dim | 8, 128 | 32, 128 |
| KV groups, global / sliding | 2 / 4 | 8 / 8 |
| Routed experts, top-k, shared | 64, top-6, 2 shared | 256, top-6, 2 shared |
| Expert FFN / dense FFN | 512 / 4096 | 2048 / 16384 |
| muP width multiplier | 4.0 | 16.0 |
| Unchanged | window 512, relative extent 1024, `d_rel` 16, ShortConv kernel 4, sigmoid router with route scale 8, vocabulary 200,058 (padded to 200,064) | |

Sliding layers have more KV groups than global ones, as in Inkling-Large, so the run covers per-layer attention shapes.

**Data:** shard `sample/10BT/000_00000.parquet` of FineWeb-Edu, tokenized by `prepare_dataset.py --eod-token '<|endoftext|>'`: 201,728 documents, 200.2M tokens, each document ending in 199999. Megatron trains with `HuggingFaceTokenizer` loaded from the tokenizer copy saved with the data (end-of-document 199999). The reference rebuilds Megatron's `GPTDataset` from the same cached index (`dataloader_type: single`), so both read identical samples.

**Recipe:** 500 steps of 64 × 4096 tokens (131M tokens). AdamW, lr 6e-4 with 50 warmup steps from 0, then cosine to 6e-5. Weight decay 0.1, none on 1-D parameters and biases. Betas 0.9 / 0.95, eps 1e-8, gradient clipping 1.0, bf16.
- Megatron: TE FusedAdam with the distributed optimizer and fp32 master weights, EP 1 × DP 8, flex attention, no Primus-Turbo, expert-bias update rate 0.
- Reference: torch fused AdamW with DDP, fp32 parameters under bf16 autocast, eager attention, experts through `grouped_mm`.

**Initial weights:** transformers' own initialisation for each seed, rounded to bf16, then converted to Megatron with `convert_inkling_hf_megatron.py`. In fp32 the two models' logits agree to 1.8e-6 relative to the largest logit, and the top token agrees everywhere. The same 29,708 parameter values are excluded from weight decay on both sides.

**AdamW results:** final loss is the mean of the last 10 steps; the gap is averaged over the last 100.

| Initial weights | Megatron | Reference | Megatron − reference |
| --- | --- | --- | --- |
| Seed 0 | 5.0432 | 5.0149 | +0.029 (0.57%) |
| Seed 1 | 5.0179 | 5.0000 | +0.018 (0.35%) |

- The first-step losses agree to 1e-4, and steps 1–50 to within 0.017. The gap opens between steps 60 and 150, then stays flat.
- The gap is about the size of run-to-run variation: the two reference seeds end 0.015 apart and the two Megatron seeds 0.025 apart.
- An earlier run on a different 200M-token sample of the same shard, built by a separate script, ended with Megatron 0.032 *below* the reference (5.0003 against 5.0318). The gap's sign depends on the data, so there's no sign of a systematic difference.
- Gradient norms agree: the Megatron/reference ratio is 0.997 over steps 1–10 and 0.97–1.00 (median) over the last 100.

## Not done yet

- **Checkpointing:** no `sharded_state_dict` yet, so distributed save and restore are untested.
- **Real data:** has run only on the 1.5B convergence model. The released tokenizer still has no end-of-document token, so data must be prepared with `--eod-token` and training pointed at the saved tokenizer copy; nothing stops a run that loads the tokenizer straight from the Hub, which trains with no end-of-document id.
- **Parallelism:** TP has not been run, and PP has not been used for a training run. Sequence and context parallelism are rejected, because the output ShortConvs would need a halo exchange.
- **Convergence:** checked at 1.5B for 500 steps (above); not yet at the released widths or for longer runs.
- **Reporting:** no Inkling FLOPs formula, so the logged TFLOP/s use the GPT formula.
- **Expert balance:** no per-expert load logging yet.
- **Muon recipe:**
  - The router weights and `rel_proj` go to Muon; the plan keeps them on Adam.
  - Weight decay is not coupled to lr².
  - `dist_muon` with `overlap_param_gather` fails when expert DP = 1. This is a Megatron layer-wise optimizer bug, not patched here.
- **Performance:** FlexAttention global layers are about 10× slower than causal attention without a bias.
