## fix(megatron): use the real model vocab under mock data (Llama 2 memory/throughput on v26.8)

### Problem
Llama 2 7B/70B on MI355X regressed after v26.2 (memory up, 7B FP8 MBS13 OOM; 70B throughput down on the v26.8 RC / ROCm 10.1 image).

### Root causes
1. **Memory.** #654 forces `NullTokenizer` with `vocab_size=131072` whenever `mock_data` is on. Llama 2's vocab is 32000, so the embedding, output layer, their grads and optimizer state, and the logits are all ~4x too big. The same default silently mis-sizes every mock-data config whose real vocab isn't ~131k (237 of 243 MI355X/MI300X/MI325X example configs).
2. **70B throughput.** `base_env.sh` defaults to `GPU_MAX_HW_QUEUES=2` with `TORCH_NCCL_HIGH_PRIORITY=1`. On ROCm 10.1, FSDP2 compute stalls behind all-gathers when the host runs ahead. Kernel work is *not* slower: under the profiler, or with per-microbatch device syncs, v26.8 matches v26.2.

### Changes
- `mock_data_patches.py`: when `vocab_size` is unset, read it from the `tokenizer_model` HF config (local dir or Hub `config.json`, including `text_config`), minus the EOD token NullTokenizer appends. It falls back to 131072 with a warning when the config can't be read. An explicit `vocab_size` is still preserved.
- `primus/configs/models/megatron/*.yaml` (61 files): set `vocab_size` to the real HF config vocab on every model config that names a tokenizer, so no Hub lookup (and no `HF_TOKEN` for gated `meta-llama/*`) is needed. Configs whose tokenizer is a stand-in (gpt-oss, Grok, GLM-4.7/5) use the target model's vocab.
- `llama2_70B-BF16-pretrain.yaml`: add `env: GPU_MAX_HW_QUEUES: "4"`. This is scoped to the config because 7B is no faster at 4 queues.
- `gpt_oss_20B-BF16-pretrain.yaml`: with the real 201088 vocab, Megatron's native fused cross-entropy runs out of memory under `overlap_moe_expert_parallel_comm` (24.6 GiB fp32 logits allocation). Use `cross_entropy_fusion_impl: "te"`, as the MI355X FP8 and MI325X BF16 configs already do, and `env: PYTORCH_CUDA_ALLOC_CONF: "expandable_segments:True"` to keep peak HBM near 92% instead of 98.6%.
- Unit tests for the vocab resolution.

- Copilot · comment · 2026-10-14T08:09:14Z · [source](https://github.com/AMD-AGI/Primus/pull/1249#discussion_r4268292683)

File: `primus/backends/megatron/patches/args/mock_data_patches.py` · line 32

A parsed config with an unexpected schema bypasses the fallback: this expression is outside the `try`, so a JSON array or `"text_config": null` raises `AttributeError`, and a string/zero vocabulary reaches `model_vocab_size - 1` and can raise or create an invalid size. Validate and extract the value inside the guarded block so the documented fallback applies to unreadable or invalid configs.

- Copilot · comment · 2026-10-14T08:09:15Z · [source](https://github.com/AMD-AGI/Primus/pull/1249#discussion_r4268292764)

File: `primus/configs/models/megatron/llama3.1_8B.yaml` · line 6

This explicit HF vocabulary size bypasses the new `model_vocab_size - 1` adjustment. `NullTokenizer` therefore exposes 128257 entries and Megatron pads this model to 128384, whereas auto-resolution exposes the intended 128256 and needs no extra padding block. The same inconsistency applies to the other newly added explicit model vocabularies: encode the NullTokenizer constructor value (`HF vocab_size - 1`) in those configs, or introduce a separate model-vocabulary field while preserving the public `vocab_size` override semantics.

- Copilot · comment · 2026-10-14T09:09:35Z · [source](https://github.com/AMD-AGI/Primus/pull/1249#discussion_r4268851536)

File: `primus/backends/megatron/patches/args/mock_data_patches.py` · line 68

The newly added model presets set `vocab_size` to the full HF value, so they all bypass this resolution branch. The preserved value is then passed to the legacy `NullTokenizer`, which appends EOD; for Llama 2, `32000` therefore becomes tokenizer size `32001` and pads to `32128` instead of `32000`. This leaves every shipped preset one token too large (and often allocates another `128 * TP` block), contradicting the real-vocab goal. Store the NullTokenizer pre-EOD value (`HF vocab_size - 1`) in those presets, or introduce a separate model-vocab field that this patch converts while retaining `vocab_size`'s existing explicit-override semantics.
