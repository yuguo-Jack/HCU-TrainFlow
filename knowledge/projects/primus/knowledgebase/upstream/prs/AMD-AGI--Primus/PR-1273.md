# fix(megatron): stop sys.modules scans from building unused apex ops

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1273) · state: closed · merged: True

## Original PR description

## Summary

The `fused_pad_routing_map` patch and `rebind_everywhere()` look for stale references with `getattr(module, name, None)` on every `sys.modules` entry. A miss runs the entry's `__getattr__`:

- In images that ship apex in JIT mode (`rocm/primus:v26.8` = `rocm/primus:latest`, `amdprimus/amdprimus:tas-20261019`), `amp_C`, `syncbn` and `fused_weight_gradient_mlp_cuda` are proxies whose `__getattr__` builds the extension. Every training launch built or loaded all three, even when the run uses none of them: ~17 s each with a cold extension cache (every `primus-cli container` launch), 4–20 s in total with a warm one. Ranks waiting on the build lock log every 0.05 s `filelock` poll at DEBUG.
- transformers' lazy modules print an `Accessing ... Returning ... instead` alias warning per probe.

## Changes

- `_rebind.py`: `rebind_everywhere()` searches only real modules (`issubclass(type(obj), ModuleType)`) and reads their namespace through `ModuleType`'s C-level `__dict__` slot, where `from x import name` binds it, so no `__getattr__`, `LazyLoader` load or `__dict__` property (apipkg) runs. Non-module entries (apex op proxies, cffi `Lib`) are skipped. A `None` old value skips the scan (it matched every module lacking the name); a holder that refuses `setattr` gets a warning.
- `fused_pad_routing_map_patches.py`: delegates to `rebind_everywhere()`; warns and skips if Megatron no longer defines the symbol.
- `logger.py`: `quiet_filelock_logger()` raises the `filelock` logger to INFO, so a genuine multi-rank JIT build does not flood the logs either, without lowering a stricter level (MLPerf quiet mode sets ERROR). `PRIMUS_VERBOSE_FILELOCK=1` keeps the DEBUG lines (documented in `environment-variables.md`). Raising `stderr_sink_level` instead would hide Megatron's iteration lines, which are DEBUG.

Trade-off: a wrapper that forwards attribute access to a module outside `sys.modules` (the `torch.backends` pattern), or a non-module object in `sys.modules`, is no longer rebound. None of them holds a symbol Primus patches, and the old and new scans find the same holders (see Test); `test_minimax_m3_config.py`'s stand-in importer is now a real module.

## Results

On every setup below the patch step drops from ~50 s (cold cache) or 4–20 s (warm) to < 1 s, the noise lines disappear, and loss and step time are unchanged. An op a run really uses is still built, on first use (e.g. `fused_weight_gradient_mlp_cuda` with `gradient_accumulation_fusion: true`). The saving is a fixed cost per launch per node, independent of model size, so it matters most for short, frequent jobs such as benchmarks, CI and tuning.

**MI355X**: 8 GPUs, `rocm/primus:v26.8`, a fresh `docker run --rm` container per run, `main` f32d9711 and this PR 277cdc05 interleaved, n = 3, 10 iterations. llama3.1-8B: MI355X BF16 config, GBS 64. DeepSeek-V3 proxy: MI355X BF16 config cut to 4 MoE layers, 64 experts, EP8, GBS 32.

| Model | main | this PR | Saved | Launch to iteration 1 | Time in the patch |
| --- | --- | --- | --- | --- | --- |
| llama3.1-8B | 158.5 ± 1.2 s | 114.1 ± 0.1 s | 44.4 s (28%) | 121.6 → 76.9 s | 51.3 s → < 1 s |
| DeepSeek-V3 proxy | 154.2 ± 0.8 s | 122.7 ± 0.5 s | 31.5 s (20%) | 143.3 → 111.3 s | 50.8 s → < 1 s |

The training segment takes the same time on both (llama ~30.3 s, DeepSeek-V3 ~4.0 s), final loss is within run-to-run variation (~7.3946, ~5.4340), and both rebind the same module, `token_dispatcher`. DeepSeek-V3 saves less because it sets `gradient_accumulation_fusion: true` and so still builds `fused_weight_gradient_mlp_cuda`. Logs: rank 0 console ~5,000 → ~2,800 lines, 199 alias warnings → 0, and each of ranks 1–7 loses ~1,900 `filelock` lines from `debug.log` (~450 KB → 16–28 KB).

**MI455X**: `amdprimus/amdprimus:tas-20261019`, MI455X example defaults from #1272, one run each in a fresh container, 10 iterations. "After" is 01929a1c; the final head reran the 1-GPU case with the same result.

Every Megatron training is faster; net of #5860's cold container, the PR saves about 4 min per CI run even with warm caches, since loading the already-built apex ops still cost 4–20 s per launch. The 12.5 min drop in the unit-test step is #5860's cold container, not this PR ([#5854](https://github.com/AMD-AGI/Primus/actions/runs/39561868348), `main` with warm caches, took 11m21s vs 11m03s here). The noise lines were `filelock` 7,158, transformers alias 4,179, hipify 1,096 and extension build output 122; the 24 left are `qwen3_30B_A3B` building fused wgrad on first use.

## Test

- New unit tests in `test_rebind.py`, `test_fused_pad_routing_map_patches.py` and `test_logger_filelock.py`, 18 passed, each failing against the code it guards (`main` or an earlier commit here): proxies (`__getattr__`, `LazyLoader`, `__dict__` property) are not probed; hooked non-module entries, including one that reports `ModuleType` as its `__class__`, are not touched; a `None` placeholder is not spread; a refused `setattr` warns; a missing Megatron symbol is skipped; the filelock level is raised but never lowered, honors the opt-out, and is applied by `setup_logger()`.
- Same holders: with the full Megatron/Primus stack imported (7,749 `sys.modules` entries), the old and new scans find the same holders for all three rebound symbols (`fused_pad_routing_map` → `token_dispatcher`; `core_transformer_config_from_args` → `gpt_builders`, `pretrain_gpt`; `get_gpt_decoder_layer_specs` → `gpt_builders`); only the three apex proxies are no longer probed.
- Merged with `main` f32d9711 on a MI455X GPU container: 1015 passed, 4 failed; `main` alone: 1003 passed and the same 4 failed (`test_minimax_m3_msa.py` ×3, `test_fla_kda_autotune_patches.py` ×1).
- Primus CI #5870 passed; pre-commit.
