# perf(configs): tune MI355X FLUX.1-dev (JAX) and Mixtral 8x7B / DeepSeek-V2-Lite BF16 (Megatron); add FP8 MoE models to the perf catalog

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1348) · state: closed · merged: True

## Original PR description

## Summary

Config-only changes for `release/v26.9`:

1. **MI355X `maxdiffusion/flux_dev-pretrain`:** `reuse_example_batch: True`. This is the same fix #1338 made for MI300X, where it took FLUX.1-dev from 5.21 to 6.00 images/s/device.
2. **MI355X `megatron/mixtral_8x7B_v0.1-BF16-pretrain`:** Turbo grouped GEMM with the fused activation-with-probs, and `turbo_deepep_num_cu: 64 → 160`. Mixtral BF16 regressed ~5% on MI355X with `utd/ci:primus_ci_59003fd_20261028`.
3. **MI355X `megatron/deepseek_v2_lite-BF16-pretrain`:** `turbo_deepep_num_cu: 64 → 160`.
4. **`tools/perf/configs.yaml`:** adds `deepseek_v2_lite-FP8` and `mixtral_8x7B_v0.1-FP8` to the MI300X, MI325X and MI355X Megatron catalogs.

| Change | Measured on | Result |
|---|---|---|
| FLUX.1-dev `reuse_example_batch` | MI300X (#1338) | +15% (5.21 → 6.00 images/s/device) |
| Mixtral 8x7B BF16 | MI300X proxy | +2.4% tokens/s/GPU |
| DeepSeek-V2-Lite BF16 | MI300X proxy | +2.1–2.4% tokens/s/GPU |

## Changes

### MI355X `flux_dev-pretrain.yaml`

- **`reuse_example_batch: True`**, with batch size unchanged at 14.
  - MaxDiffusion's synthetic iterator builds each batch on GPU 0 and round-trips it through the host (~950 MB at batch 14).
  - `FluxTrainer` fetches each batch synchronously between steps, so all GPUs sit idle while that happens.
  - On MI300X this gap was 239 ms per step, while the train step's GPU work (1.33 s) was identical with and without reuse. The data is random either way.
  - This is the setting MaxText's benchmarking guide recommends for synthetic runs. `WanTrainer` already hides the same cost behind a prefetch thread.
  - Note: FLUX numbers are not directly comparable with older results, which included the gap.

### MI355X `mixtral_8x7B_v0.1-BF16-pretrain.yaml`

- **`use_turbo_grouped_gemm: true` + `use_turbo_fused_act_with_probs: true`.** The fused op replaces the separate Triton SiLU/probs kernels around the expert GEMMs, which took ~4.6% of GPU time in a profile. Turbo grouped GEMM alone is flat (+0.4%), but the fused activation requires it. Together: +2.2% (two runs).
- **`turbo_deepep_num_cu: 64 → 160`:** +0.2–0.3% on Mixtral, about +1 GB peak memory.

### MI355X `deepseek_v2_lite-BF16-pretrain.yaml`

- **`turbo_deepep_num_cu: 64 → 160`**, about +1 GB peak memory on MI355X (89.3% HBM before). DeepEP throughput keeps rising up to ~60% of the GPU's CUs and flattens beyond. 160 is that fraction of MI355X's 256 CUs, and it's what the MI355X `deepseek_v2_lite-FP8` and `gpt_oss_20B-BF16` recipes already use.

### `tools/perf/configs.yaml`

- Adds `deepseek_v2_lite-FP8-pretrain.yaml` and `mixtral_8x7B_v0.1-FP8-pretrain.yaml` to the Megatron lists for MI300X, MI325X and MI355X. All six paths exist.

**1. 🟠 Should fix: Mixtral 8x7B BF16 on MI355X logs an expandable-segments warning: this PR enabled Turbo grouped GEMM without allocator env**

Mixtral 8x7B BF16 (MI355X) now enables `use_turbo_grouped_gemm` without an `expandable_segments:True` allocator env. `warn_turbo_grouped_gemm_without_expandable_segments` will therefore log an advisory warning at startup. Most MI355X Turbo grouped-GEMM configs omit this env too; only `gpt_oss_20B-FP8-pretrain.yaml` sets it. With 8 experts at EP8, each rank stacks a single expert per layer, so higher reserved memory is possible but no OOM is shown. Consider adding `PYTORCH_HIP_ALLOC_CONF: "expandable_segments:True"` to the `env:` block for consistency.

**Who is affected:** Users launching the MI355X Mixtral 8x7B BF16 example config without exporting an allocator conf.
