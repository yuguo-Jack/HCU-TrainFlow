# feat(examples): MI455X DeepSeek-V3 and Llama-3.1-8B launchers use tuned hipBLASLt kernels

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1295) · state: closed · merged: True

## Original PR description

## Summary

- Adds hipBLASLt tuning files for the MI455X DeepSeek-V3 proxy and Llama-3.1-8B examples
  (`examples/megatron/models/*/hipblaslt_tuning/`). Each launcher sets `HIPBLASLT_TUNING_OVERRIDE_FILE` to
  its file by default; set it empty for hipBLASLt's own choice.
- The files were made with a `hipblaslt-bench` built from rocm-libraries e1e7fdcab9 (the image has none), run
  in the default image `tas-20261019`, whose hipBLASLt is built from the same commit. A row is kept only if it
  is at least 3% faster on replay: 17 of 27 GEMM shapes (DeepSeek-V3, 4-GPU run) and 11 of 15 (Llama) get a
  faster kernel.
- Launchers: no default file with `PRIMUS_HIPBLASLT_TUNING=1`, so stage 3 of Primus's own tuning flow uses its
  stage-2 result. A file of the user's own may be relative to the caller's directory, must be readable, and is
  mounted read-only into the container. An empty value is unset before Primus starts (hipBLASLt takes a set
  but empty variable as an override file named "").
- READMEs: a short hipBLASLt tuning note, and Reference tables for 1 and 4 GPUs that go from the baseline to
  FlyDSL to the hipBLASLt tuning. The profile breakdowns are dropped. Only `examples/` changes.

The Llama example needs a Primus-Turbo with PR #574 as `TURBO_DIR` (`dev/mi455x_v2` 85e85e70, measured below).

## Results

This branch on one node of 4x MI455X, started from the host (1 GPU: GPU 3; 4 GPUs: the launchers' defaults).
ms/iter is the average of iterations 3-10; peak memory is the largest `hip mem usage` in Primus's log (last
rank). The rows with FlyDSL, with and without the tuning file, are the mean of 2 runs that alternated between
them; the baseline rows (without the tuning file) are the mean of 3 runs from an earlier set, and the speedup
is against them.

DeepSeek-V3 proxy, 1 GPU (4 layers, 32 experts, GBS 16):

| Variant | ms/iter | Speedup | Tokens/s/GPU | TFLOP/s/GPU | Peak mem/GPU | loss @ iter 10 |
| --- | --- | --- | --- | --- | --- | --- |
| Baseline: TE unfused attention, Triton grouped GEMM | 1967 | 1.00x | 33,300 | 719 | 174.15 GiB | 5.49455 |
| + FlyDSL attention and grouped GEMM | 1010 | 1.95x | 64,900 | 1400 | 130.52 GiB | 5.49483 |
| **+ hipBLASLt tuning (default)** | **960** | **2.05x** | **68,200** | **1473** | 130.53 GiB | 5.49473 |

DeepSeek-V3 proxy, 4 GPUs (EP4, 128 experts, GBS 64):

| Variant | ms/iter | Speedup | Tokens/s/GPU | TFLOP/s/GPU | Peak mem/GPU | loss @ iter 10 |
| --- | --- | --- | --- | --- | --- | --- |
| Baseline: TE unfused attention, Triton grouped GEMM | 2139 | 1.00x | 30,600 | 661 | 215.21 GiB | 5.56290-5.56295 |
| + FlyDSL attention and grouped GEMM | 1200 | 1.78x | 54,600 | 1179 | 170.71 GiB | 5.56274 |
| **+ hipBLASLt tuning (default)** | **1132** | **1.89x** | **57,900** | **1249** | 170.71 GiB | 5.56307 |

Llama-3.1-8B, 1 GPU (MBS 4, GBS 4, seq 8192):

| Variant | ms/iter | Speedup | Tokens/s/GPU | TFLOP/s/GPU | Peak mem/GPU | loss @ iter 10 |
| --- | --- | --- | --- | --- | --- | --- |
| Baseline: Primus-Turbo Triton attention | 1938 | 1.00x | 16,900 | 870 | 345.02 GiB | 10.1909 |
| + FlyDSL attention | 1080 | 1.79x | 30,300 | 1562 | 344.74 GiB | 10.1904 |
| **+ hipBLASLt tuning (default)** | **983** | **1.97x** | **33,300** | **1716** | 344.69 GiB | 10.1902-10.1903 |

Llama-3.1-8B, 4 GPUs (DP4, GBS 16):

| Variant | ms/iter | Speedup | Tokens/s/GPU | TFLOP/s/GPU | Peak mem/GPU | loss @ iter 10 |
| --- | --- | --- | --- | --- | --- | --- |
| Baseline: Primus-Turbo Triton attention | 1943 | 1.00x | 16,900 | 868 | 276.18 GiB | 8.9728 |
| + FlyDSL attention | 1117 | 1.74x | 29,300 | 1509 | 276.08 GiB | 8.9683-8.9709 |
| **+ hipBLASLt tuning (default)** | **1023** | **1.90x** | **32,000** | **1649** | 276.03 GiB | 8.9698-8.9745 |

- The tuning file alone: DeepSeek-V3 1010 -> 960 ms/iter (1.05x) on 1 GPU and 1200 -> 1132 ms/iter (1.06x)
  on 4 GPUs; Llama 1080 -> 983 ms/iter (1.10x) and 1117 -> 1023 ms/iter (1.09x).
- Repeatability: the 2 runs of each row are within 0.7% of each other. In the earlier set the FlyDSL rows
  with and without the tuning file were up to 4% off (DeepSeek-V3 1005 / 956 and 1157 / 1100 ms/iter,
  Llama 1116 / 1024 and 1138 / 1047 ms/iter on 1 / 4 GPUs: Llama slower, DeepSeek-V3 on 4 GPUs faster),
  with the speedup from the tuning file within 1% of the new one. The new runs agree within 1% with the
  earlier measurements on this node: Llama FlyDSL 1084 / 1113 ms/iter in #1288, DeepSeek-V3 FlyDSL
  1195 ms/iter on 4 GPUs in the previous README.
- The rows without the tuning file ran before the launcher unset an empty `HIPBLASLT_TUNING_OVERRIDE_FILE`,
  so hipBLASLt looked for a file named "" on each heuristic query.
- Numerics: on 1 GPU, DeepSeek-V3's loss at iteration 10 and its grad norms are the same as in the earlier
  set; on 4 GPUs the loss differs from it by up to 0.0004 and the grad norms by up to 0.004 (both new runs of
  a row gave the same values). Llama's loss varies in the last digits because the fused FlyDSL backward adds
  dQ with atomics.
- hipBLASLt logs of runs through the launchers show the tuned kernels picked: all 11 Llama rows, 16 of the
  17 DeepSeek-V3 rows on 1 GPU, and all 17 in the 4-GPU run logged when the file was made (the 17th, the
  router with 128 experts, occurs only on 4 GPUs).
- Little is left for further tuning. TE's in-situ search over every candidate of hipBLASLt's heuristic (up to
  465 per shape) finds no faster set for Llama on 1 GPU (0.3% slower than the tuning file in the same set);
  for DeepSeek-V3 it finds 1.2%, almost all of it (-10.7 of -11.1 ms/iter) in the 1-GPU variant's router
  shape (32 experts), which the 4-GPU file does not cover. FlyDSL's BF16 GEMM takes 1.01-1.44x the tuned
  kernels' time on the Llama shapes and on DeepSeek-V3's kv_down; it is faster only on the MoE router GEMM
  (32 or 128 experts), a small part of the iteration.
