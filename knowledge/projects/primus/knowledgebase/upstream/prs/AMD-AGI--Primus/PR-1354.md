# perf(megatron): tune MI325X GPT-OSS-20B and ZAYA1-8B pretrain configs

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1354) · state: closed · merged: True

## Original PR description

- GPT-OSS-20B BF16/FP8: align with the tuned MI300X configs (#1329): Primus-Turbo grouped GEMM (hipBLASLt backend), Turbo RMSNorm and norm+TE linear, DeepEP, sync-free MoE stage 2, gradient accumulation fusion, fp32 router, micro batch size 8 -> 4.
- ZAYA1-8B BF16: micro batch size 216 -> 184 and global batch size 1728 -> 1472 (one micro batch per GPU per step at DP=8) to prevent OOM

Both MI325X GPT-OSS-20B configs (BF16 and FP8) drop `use_sink_attention: true`, so the default `use_sink_attention: false` from `primus_turbo.yaml:41` applies. With it, `PrimusTurboAttention` creates no learned `sinks` and runs plain attention. The MI325X sliding window was already `0`, so only the learned sinks are lost. The PR copies the MI300X block, which also has no sink settings; MI325X now matches MI300X but differs from its own previous config (#616, #783) and from the MI355X/MI455X siblings. Re-add `use_sink_attention: true`, or state in the config that the change is intentional.

**Who is affected:** Users running the MI325X GPT-OSS-20B BF16/FP8 example pretrain configs.

**2. 🟠 Should fix: MI325X GPT-OSS FP8 re-enables delayed-scaling patches that caused a memory fault: this PR dropped `disable_delayed_scaling_patches`**

The PR replaces this file with the MI300X version and drops `fp8_recipe: delayed` and `disable_delayed_scaling_patches: true`. #900 (27a162d) added that guard because the `delayed_fp8_scaling` stream patches crashed this MI325X config with a GPU memory fault (`sum_and_scatter`) at about iter 6. With `fp8: hybrid`, `fp8_recipe` still inherits `delayed` from `trainer_base.yaml`, and `disable_delayed_scaling_patches` falls back to False. `_needs_delayed_scaling` is therefore True, so `megatron.fp8.delayed_scaling_update` and `megatron.grad_zero_and_data_prefetch` are installed again. The other MI325X FP8 configs still keep the flag; either keep it here, switch to `fp8_recipe: tensorwise`, or document why the new Turbo/DeepEP setup no longer faults.

**Who is affected:** Users running the MI325X GPT-OSS-20B FP8 pretrain example as shipped.

_Checked against the code by an independent pass._
