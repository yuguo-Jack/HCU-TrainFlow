# perf(automodel): compile-friendly FP8 linears and deferred train-loop host syncs

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1350) · state: open · merged: False

## Original PR description

Builds on the AutoModel backend series (#1314, #1322) and the Primus-Turbo FP8 linear swap from #1323. Everything is opt-in and off by default, set in the `primus_turbo:` and `primus_train:` sections; no new environment variables. No open issue covers this work.

**What changes**
- `primus_turbo.fp8_linear_traceable`: `TraceableFloat8Linear` keeps the FP8 GEMMs inside compiled graphs. Primus-Turbo's `gemm_fp8` builds `QuantizedTensor` subclasses and is dynamo-disabled, so every swapped linear was a graph break. Forward and all three gradients are bit-identical to `Float8Linear`.
- On top of it:
  - `fp8_linear_delayed_scaling`: reuse each operand's scale between refreshes (`fp8_linear_amax_warmup_steps: 2`, `fp8_linear_amax_refresh_interval: 16`).
  - `fp8_linear_inductor_cast`: scaled casts as plain ops, which Inductor fuses into the kernel that produces the activation.
  - `fp8_linear_shared_input_scales`: one cast for an input several linears read (76 groups covering 266 of FLUX's 421 FP8 linears).
  - `fp8_linear_gemm_backend`: Primus-Turbo's default backend for these GEMMs. `flydsl` keeps FLUX's FP8 GEMMs off hipBLASLt except where K ≤ 128.

  When the FP8 swap runs, a dependent setting without what it depends on stops the run; left on without the swap, these settings only log a warning.
- `primus_train.defer_host_sync`: the train loop's loss and grad-norm host syncs happen on logging steps only, and FLUX's latent position ids are built on the GPU.
- `flux_1_schnell-sq256-fp8.yaml`: 256×256, mbs 64 / gbs 512, AC off, per-block compile and all of the above, with the preset's fp32 storage and bf16 compute.

**Results** (8× MI355X, `rocm/primus:v26.8`, FLUX.1-schnell, COCO 256×256 cache, same seed, 500 steps)

| | img/s/GPU (sustained) | loss, steps 402–498 | peak memory |
|---|---|---|---|
| main, stock FP8 swap (bf16 storage) | 56.9 | 0.7473 | 225.9 GB |
| this PR (bf16 storage) | 71.4 | 0.7473 | 206.4 GB |
| this PR, the example (fp32 storage) | 71.1 | 0.6890 | 214.7 GB |

With the settings on and off, the per-step loss differs by at most 0.0009 over the 500 steps. No NaN in 10 60-step runs of the example or in the three 500-step runs. Measured before the review fixes, which change eval-mode forwards (these runs made none) and sum the logged loss in float64.

**Notes**
- From Primus-Turbo 0.4, `quantize_fp8_tensorwise` pads K to a multiple of 128 unless told otherwise. The path asks for the unpadded layout `Float8Linear` uses; without it FLUX's `x_embedder` (K = 64) gets an input gradient of the wrong shape. Works with Primus-Turbo 0.3 to 0.5.
- The delayed-scaling schedule advances once per training forward of the transformer, so with gradient accumulation it counts micro-batches. Eval-mode (validation) forwards quantize dynamically, as `Float8Linear` does, and leave the scales alone. Scales are not checkpointed; a resumed run re-warms.
- Delayed scaling assumes at most one pending backward per swapped linear, one swapped transformer per process and, with shared input scales, no `.to()` or cast of the model after its first forward. The module docstring explains each; the FLUX.1-schnell example meets all three.
- gfx942 and granularities other than tensorwise keep `Float8Linear`, with a warning.

**Breaking:** none.

**How to review:** `quantization/_fp8_traceable.py` (module docstring first), the `fp8_linear.py` diff, `training/deferred_host_sync.py`, then the example.

**Test plan**

Covers bit-identity with `Float8Linear`, the Inductor cast against the extension cast (eager and compiled), fullgraph compile, the K = 64 case, the refresh schedule, shared-input discovery, settings validation, and the train-loop rewrite's anchors against the pinned AutoModel.
- After the review fixes, the affected files (`test_fp8_traceable.py`, `test_deferred_host_sync.py`, the new `test_source_patch.py`, `test_quantization.py`, `test_diffusion_profiler.py`, `test_automodel_patches.py`): 217 passed on MI355X. The new tests cover eval-mode forwards leaving the delayed scales alone, a compiled refresh writing the same scales as an eager one with one graph per kind of forward, Primus-Turbo 0.3 and 0.4+ backend APIs, the warning for settings left on without the swap, bit-identical logged losses, and the source-patch helper's anchor checks, zero-argument `super()` and `__future__` flags. **9. Logged `train_avg_loss` and checkpoint loss drift ~1e-6 from upstream: this PR sums `epoch_loss` in fp32** (`primus/backends/automodel/training/deferred_host_sync.py:47-58`)

With `defer_host_sync`, `epoch_loss` is summed as a float32 0-d tensor between logging steps instead of a Python float (fp64). So `train_avg_loss`, the checkpoint `train_loss` and the epoch `avg_loss` differ from upstream at the fp32-rounding level (about 1.5e-6 relative over 5000 steps logged every 10). The difference also depends on the log cadence. The docstring and README claim 'Logged values are unchanged' should be qualified, or the sum kept in `.double()`.

**Who is affected:** Runs that enable `primus_train.defer_host_sync` see averaged-loss values that differ from upstream in roughly the 6th-7th significant digit.

**10. Rewritten upstream methods compile with PEP 563 annotations: `exec` inherits `_source_patch`'s future import** (`primus/backends/automodel/_source_patch.py:67`)

`exec` without `compile(..., dont_inherit=True)` applies `_source_patch`'s future import, so every rewritten upstream method is compiled with PEP 563 string annotations and different flags from the original. **4. 🟠 Should fix: Backward crashes with an inplace-modification error on refresh steps when a linear has two pending backwards**

`_TraceableFP8GemmNTDelayed` saves `scale_g` with `save_for_backward`, and on refresh steps its backward overwrites that buffer in place through `_stash_scale`. If one `TraceableFloat8Linear` has two backwards pending in a refresh step, the second fails autograd's version check ('modified by an inplace operation'). That happens when the linear is called twice in one forward, or when two forwards run before their backwards. **Who is affected:** Users of `fp8_linear_traceable` + `fp8_linear_delayed_scaling` on a model that reuses a swapped linear within one forward, or that runs several forwards before backward.
