# feat(kimi_k3): Kimi K3.1 Pro preset, 4-layer proxy and MI455X BF16 recipe

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1363) · state: open · merged: False

## Original PR description

## Why
Kimi K3.1 Pro (released 2026-10-23; weights and config.json announced for 2026-11-04) has no
Primus preset, and the K3 family has no MI455X recipe. Moonshot describes K3.1 Pro as "a
post-trained version of Kimi K3" (https://www.kimi.ai/blog/kimi-k3-1-pro), so the K3
architecture applies as is.

The existing proxy, `kimi_k3_8L_official` (8 layers at the released widths, EP 8 on MI355X),
does not fit one 4 x MI455X node: at EP 4 the expert-DP size is 1, so each GPU holds the full
optimizer state of its 224 experts per MoE layer, and the estimated static memory is ~621 GiB
per GPU at 8 layers against 432 GiB of HBM.

This PR is the baseline only: the preset, the proxy and a recipe that runs as committed with the
image's Primus-Turbo. No performance changes.

## What
Three new files, in the same layout as Kimi K3
(`kimi_k3` -> `kimi_k3_8L_official` -> `MI355X/kimi_k3-BF16-8L-official`). No existing file
changes.

- `primus/configs/models/megatron/kimi_k3.1_pro.yaml`: the K3.1 Pro preset. It extends
  `kimi_k3.yaml` without overrides until the K3.1 Pro config.json is public; then only the keys
  that differ from moonshotai/Kimi-K3 get overridden here, and the presets and recipes built on
  it stay as they are.
- `primus/configs/models/megatron/kimi_k3.1_pro_4L.yaml`: a 4-layer proxy at the released
  widths. Only the depth shrinks; the layer pattern is the first four layers of the release
  (KDA, KDA, KDA, NoPE MLA; layer 0 dense MLP, layers 1-3 MoE). Four layers is the depth that
  leaves room for activations (~277 GiB static per GPU; 5 layers ~363 GiB). `num_layers` and
  the two per-layer patterns live in the preset because both patterns are length-checked
  against `num_layers` and have to change together.
- `examples/megatron/configs/MI455X/kimi_k3.1_pro_4L-BF16-pretrain.yaml`: a one-node
  4 x MI455X BF16 recipe, from `MI355X/kimi_k3-BF16-8L-official.yaml`:
  - `model` -> `kimi_k3.1_pro_4L`, `expert_model_parallel_size` 8 -> 4, `recompute_num_layers`
    8 -> 4 (still full recompute over all layers), experiment / wandb names.
  - The batch is sized like the other one-node MI455X proxies instead of copying the MI355X
    4-node run: sequence 7168 -> 4096, global batch 128 -> 64, micro-batch 2, so each rank runs
    8 micro-batches per step. The MI355X batch gave each GPU 3.5x the tokens per step of this one.
  - Hyperparameters, the memory recipe (distributed + precision-aware optimizer, bf16 grads and
    moments) and the backends are the MI355X ones. fla's Triton kernels need Triton's expert
    scheduling off on gfx1250 (`TRITON_HIP_USE_EXPERT_SCHEDULING=0`); the recipe comment says so.

## Results (4 x MI455X, 1 node, 12 iterations, mock data, recipe as committed, image Primus-Turbo)

| | |
| --- | --- |
| Model | 4-layer K3.1 Pro proxy, 93.84 B parameters (27.4 B per GPU) |
| Parallelism | TP 1, PP 1, EP 4, DP 4 (expert-DP 1) |
| Batch | seq 4096, micro-batch 2, global batch 64 (8 micro-batches per rank per step) |
| Precision / recompute | BF16, full recompute over all 4 layers |
| **Throughput** | **13,371 tokens/s/GPU** (median of 3 runs; 13,305-13,544) |
| Step time | 4.78-4.95 s |
| Model TFLOP/s per GPU | 458-470 at iteration 12 |
| Memory per GPU | 340.6-340.8 GB (78.8-78.9%) |
| Loss at iteration 12 | 4.687-4.688, no NaN or skipped iterations |

| run | node | tokens/s/GPU | s/iter (iterations 4-12) | memory |
| --- | --- | ---: | ---: | ---: |
| 1 | A | 13,370.6 | 4.88-4.92 | 340.6 GB |
| 2 | B | 13,305.4 | 4.90-4.95 | 340.8 GB |
| 3 | B | 13,544.3 | 4.77-4.88 | 340.6 GB |

- Throughput is the harmonic mean over iterations 4-12. Iterations 1-2 include JIT compilation
  (20.2 s and 13.0 s with a warm kernel cache; 80.6 s and 43.3 s on a cold one). Memory is the
  value logged at the last iteration.
- Noise: the three runs, on two nodes of the same type, span 1.8%.

## Reproduce
Image `amdprimus/amdprimus:tas-20261019`; on that image Triton's
`is_expert_scheduling_enabled()` also had to be patched to return False for gfx1250.

```bash
./primus-cli direct --env PRIMUS_GPU_MODEL=MI455X --env NNODES=1 --env GPUS_PER_NODE=4 \
  --env TRITON_HIP_USE_EXPERT_SCHEDULING=0 -- \
  train pretrain --config examples/megatron/configs/MI455X/kimi_k3.1_pro_4L-BF16-pretrain.yaml \
  --train_iters 12
```

## Not in this PR
- MI455X optimizations (Turbo FlyDSL kernels for MLA attention, KDA, SiTU and attention
  residuals, no dataloader attention mask, less recompute, deduplicated alltoall, tuned
  hipBLASLt, ...): follow-up PRs on top of this baseline.
- The K3.1 Pro config.json diff: once it is published, a follow-up diffs it against
  moonshotai/Kimi-K3 and overrides only the keys that differ.
