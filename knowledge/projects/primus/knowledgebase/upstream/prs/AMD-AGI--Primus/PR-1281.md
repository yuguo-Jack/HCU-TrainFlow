# fix(megatron): record_stream prefetched batches on the consumer stream

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1281) · state: closed · merged: True

## Original PR description

## Summary

`CudaPrefetchIterator` allocates each batch on its own HtoD stream and hands it
to the compute stream after `wait_stream()`, but never calls `record_stream()`
on the tensors. `wait_stream()` only orders execution. It does not tell the
caching allocator that the compute stream uses the memory. So when the compute
stream drops the last reference to a batch, the block goes straight back to the
prefetch stream's pool while kernels that read it are still queued, and the
next prefetch's HtoD copy can overwrite it.

On gpt-oss-120B FP8 the overwritten block held the token ids read by the
embedding backward. `sum_and_scatter` uses them as row offsets into the
gradient buffer, so it wrote out of bounds and the run failed in the first
backward pass with `HSA_STATUS_ERROR_MEMORY_APERTURE_VIOLATION`, then hung.
The prefetcher is installed only by `patch_grad_zero_and_data_prefetch`, whose
condition is `_needs_delayed_scaling`. That is why only `fp8_recipe: delayed`
(the default) faulted, while BF16 and `fp8_recipe: tensorwise` ran clean, and
why the dependence on micro-batch size was erratic rather than tracking memory
use.

`__next__` now `record_stream()`s every CUDA tensor in the returned batch on
the consumer stream. The docstring claimed `record_stream()` was not needed
because references are held through forward/backward. That claim is removed:
holding references keeps memory alive only until Python drops them, and kernels
already queued on another stream can still read it after that.

## Testing

- New `tests/unit_tests/backends/megatron/test_cuda_prefetch.py` (GPU). It
  queues a consumer read behind `torch.cuda._sleep`, frees the batch, and checks
  that the next prefetch does not get the same block. In `rocm/primus:v26.8` on
  MI355X: without the fix it fails, because the next prefetch gets the exact
  freed pointer. With the fix, `2 passed`.
- End to end, 1 node x 8 MI355X, `rocm/primus:v26.8`, gpt-oss-120B FP8 delayed
  recipe shrunk to one node (36 layers, 32 experts, EP 8, mbs 8, gbs 1024, full
  recompute), mock data, 3 iterations:
  - Unfixed: aperture violation and hang, reproduced on 3 different nodes.
  - Fixed: 3/3 iterations, exit 0, in 2 of 2 runs, at 563-583 TFLOP/s/GPU on the
    one steady-state iteration of each run.
- `pre-commit run` on the changed files passes.
