# fix(flydsl): port Primus FlyDSL kernels to the 0.3.x API

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1275) · state: closed · merged: True

## Original PR description

## Summary
- FlyDSL 0.3 dropped `flydsl.expr.buffer_ops` and `flydsl.expr.vector`. Without a port, Primus's own FlyDSL kernels fail to import under FlyDSL 0.3.4.1 (e.g. the CI image from #1271).
- **`buffer_ops`:** import from Primus-Turbo's vendored 0.2.4 module (`primus_turbo.flydsl.utils.buffer_ops`), same as Mega MoE.
- **`vector`:** vendor the FlyDSL 0.2.4 helpers under `primus/.../flydsl_compat/vector.py` (Apache-2.0; full text in `LICENSE-APACHE`).
- Covers MiniMax-M3 MSA / indexer, DeepSeek-V4 `flydsl_v1`, Kimi-K3 `_flydsl_v1`, and the deprecated V4 FlyDSL kernels' import lines.

## Test plan
- [x] Under FlyDSL 0.3.4.1 (`tasimage/primus:pr-1271`), import succeeds for:
  - MiniMax MSA / indexer flydsl modules
  - DeepSeek-V4 `_flydsl_v1` DSA fwd/bwd
  - Kimi-K3 KDA + attn-residual `_flydsl_v1` kernels
- [ ] `pytest tests/unit_tests/backends/megatron/test_minimax_m3_flydsl_{indexer,fwd,bwd,attention}.py` on gfx950
- [ ] Single-node MiniMax-M3 pretrain with default `msa_backend: flydsl`
- [ ] DeepSeek-V4 with `use_v4_attention_backend=flydsl_v1` (smoke)
