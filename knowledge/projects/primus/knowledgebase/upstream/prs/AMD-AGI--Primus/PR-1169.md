# fix(megatron): stop the tp_group deprecation warning from breaking compiled graphs

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1169) · state: open · merged: False

## Original PR description

## Summary

`torch.compile` takes a hard graph break inside every `RowParallelLinear`
forward, caused by a deprecation warning about an argument that is never used.
This patch skips that warning while Dynamo is tracing, which removes the break
without changing eager behaviour or any numerics.

## Root cause

Line numbers are for Megatron-core 0.19.2, which `main` pins.

`RowParallelLinear.forward` passes the tensor-parallel group as a literal
`None` (`megatron/core/tensor_parallel/layers.py:1466`), unlike
`ColumnParallelLinear.forward`, which passes `tp_group=self.tp_group`
(line 1183). The `None` reaches the deprecation shim
`get_tensor_model_parallel_group_if_none` (`megatron/core/utils.py:573`), whose
`tp_group is None` branch calls `warnings.warn` on rank 0.

`warnings.warn` is the C builtin `_warnings.warn`, which Dynamo cannot trace:
it reports *"Dynamo does not know how to trace the Python builtin
`_warnings.warn`"* and breaks the graph. Because Dynamo must split every frame
between the break and the root of the compiled region, the cost grows with
model depth rather than staying constant: a transformer block typically holds
several row-parallel linears, and activation recomputation replays each
forward.

The argument is dead on that path in every configuration. The functional API
only uses `tp_group` for a collective when `allreduce_dgrad` or
`sequence_parallel` is set, and `RowParallelLinear.forward` hardcodes both to
`False` (lines 1448 and 1465); the row-parallel output all-reduce that does
need a group uses `self.tp_group` separately afterwards. Python's warning
registry also dedupes the warning after its first emission, while the graph
split is paid on every step.

This is not about tensor parallelism: the branch tests the `None` sentinel, not
the TP world size, so it fires identically at TP=1.

## The fix

The shim is left alone. The `warnings` module global in `megatron.core.utils`
is replaced with `_WarningsSilentWhileTracing`, a stand-in whose `warn` is a
plain Python function:

- **While Dynamo traces**, it returns early. Dynamo inlines a plain Python
  function instead of breaking on it, and `torch.compiler.is_compiling()` is
  constant-folded to `True`, so nothing of the warning survives into the graph.
- **In eager**, it forwards to the real `warnings.warn` with the caller's
  arguments, adjusting only `stacklevel` for its own frame, so the notice is
  emitted verbatim and still points at the caller. That notice is a real
  upstream signal (the shim is marked `# TODO(zijiey): remove this function
  later.`) and should keep reaching anyone running eager.

Implementation notes:

- **Why the module global.** The shim resolves `warnings` through
  `megatron.core.utils`'s globals at call time, so one swap covers every
  caller: `layers.py:262`, `:508`, `:830`, `:955`, `:1320` and the four call
  sites in `extensions/transformer_engine.py`. It needs no edit to the
  Megatron-LM submodule, and upstream's group resolution stays authoritative.
- **Other warnings in that module.** `megatron/core/utils.py` has two more
  `warnings.warn` call sites, both deprecation notices (the `deprecated`
  decorator and `deprecate_inference_params`). They are also skipped while
  tracing, where they would break the graph the same way, and still warn in
  eager.
- **Applies only while the defect exists.** Before installing, the patch reads
  the shim's source and installs only if it still has the `warnings.warn`
  branch. It reads the bytecode's names if no source is available. So it turns
  itself off once upstream fixes or removes the shim, on any Megatron-LM
  version. A version gate would not work here: Megatron-LM is a submodule
  pinned by commit, so `importlib.metadata.version("megatron-core")` raises,
  and `megatron.core.__version__` does not move when the shim changes.
- **Safe to leave installed.** The swap is installed once at `before_train`
  and never restored. The stand-in holds no state beyond the module it
  delegates to, and installing twice is a no-op. A missing shim, a renamed
  global and an already-installed patch are all treated as "nothing to do".

## Scope

Not specific to a model or to a distributed wrapper. Any model built on
Megatron's row-parallel linear hits this under `torch.compile`, and the
behaviour is the same under Megatron-FSDP, torch FSDP2 and DDP. It was found on
the diffusion backbones (Wan and Flux), where per-block compilation makes the
split frames easy to see, but nothing about it is diffusion-specific.

## Default-on, with an escape hatch

Enabled by default, unlike most of Primus's environment escape hatches: the
patch only skips a deprecation warning about an unused argument while
tracing, so it cannot change results, and eager still warns. Set
`PRIMUS_TP_GROUP_TRACE_FIX=0` to restore the unpatched shim, which is useful
for A/B measurement of the graph breaks themselves.

## Validation

**Real Megatron, before and after.** Rebased on `main` (Megatron-core 0.19.2),
in `rocm/primus:v26.8` with torch 2.14, one GPU, with a process group and
Megatron's parallel state initialized. The model is Megatron's own `MLP`
(`ColumnParallelLinear` then `RowParallelLinear`), counted with
`torch._dynamo.explain`:

| | graphs | graph breaks | `fullgraph=True` | eager `tp_group` warning |
|---|---|---|---|---|
| unpatched | 3 | 2 | fails | emitted |
| patched | 1 | 0 | compiles, output matches eager | emitted |

The unpatched break is at `megatron/core/utils.py:585`, the `warnings.warn`
call: *"Dynamo does not know how to trace the Python builtin
`_warnings.warn`"*.

**Training.** On the Wan and Flux backbones under Megatron-FSDP, torch FSDP2
and DDP, with per-block `torch.compile` (on the previous Megatron pin):

- The row-parallel graph breaks are gone on every wrapper.
- Loss and grad norm match the unfixed runs at every logged iteration.
- With `PRIMUS_TP_GROUP_TRACE_FIX=0` the breaks come back.

## Tests

`tests/unit_tests/megatron/patches/test_tp_group_trace_warning_patch.py`, 25
tests. They run on CPU with stub Megatron modules, so they need no GPU, process
group or Megatron-LM checkout:

- the warning is skipped while tracing and still emitted in eager;
- the builtin's calling conventions, including the reported line under keyword
  and positional `stacklevel`;
- defect detection from source and from bytecode, and the env override;
- install idempotence and the fail-soft paths;
- the reproducer: `torch._dynamo.explain` counts one break through the real
  `warnings` module and none through the stand-in, and `fullgraph=True` raises
  `Unsupported("_warnings.warn")` unpatched and compiles patched.

## Follow-up

The hardcoded `None` at `megatron/core/tensor_parallel/layers.py:1466` is still
a defect worth fixing at the source: a one-line `tp_group=self.tp_group`,
behaviour-preserving at TP=1 and more correct above it. This patch does not
stand in for that upstream change; it removes the break for all callers in the
meantime.

## Architecture Concerns

_These findings come from architecture principles distilled from the repo's PR lineage — patterns that caused PRs to be rejected or significantly reworked._

### gate-workaround-removal-on-runtime-version-detection
_When a downstream patch/monkey-patch exists to work around a bug in an external dependency (compiler, runtime, driver, ISA), and that bug is fixed in a specific upstream version, the removal of the workaround must be gated on a runtime detection of the dependency's version — not removed unconditionally nor left permanently in place. This preserves correctness on both old and new versions of the dependency within the same codebase._

**Findings:**
- Add a runtime version/capability gate for the Megatron-LM dependency instead of relying solely on `PRIMUS_TP_GROUP_TRACE_FIX`: query the installed version at runtime (e.g. `importlib.metadata.version("megatron-core")` or `megatron.core.__version__`) in `_needs_patch`, and only apply the monkey-patch on versions where `get_tensor_model_parallel_group_if_none` still contains the `warnings.warn` branch. The env var should remain a user override, not the sole applicability signal — an env var is not version detection.
- The docstring cites the upstream shim as deprecated (`# TODO(zijiey): remove this function later.`) at fixed source locations (`megatron/core/utils.py:520`, `layers.py:1265`, `:1247/:1264`). Thread that upstream-fix expectation into the patch condition: record the first Megatron-LM version in which the shim is removed or the warning branch fixed, and short-circuit the patch at/above that threshold so users on the fixed dependency pay no shim-wrapping overhead and no behavioral divergence.
- Make `patch_tp_group_trace_warning` fail-soft against dependency drift instead of assuming the symbol exists: replace `original = getattr(mcore_utils, _FUNC_NAME)` with a guarded lookup (`getattr(..., None)`) that logs and returns cleanly when the upstream shim has been removed, rather than raising `AttributeError` on a newer Megatron-LM where the bug no longer exists.
- Do not hardcode assumptions about upstream internals (the reimplemented resolution order: `torch.distributed.is_initialized()` → `parallel_state.is_initialized()` → expert/tp group) without a version bound. Either verify the upstream body matches the expected version at patch time (e.g. signature/source check) or restrict application to an explicit inclusive version range, so a future upstream refactor cannot silently change group resolution semantics under compile.
