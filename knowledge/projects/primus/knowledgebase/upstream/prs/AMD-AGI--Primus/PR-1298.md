# fix(megatron_bridge): use gpt_step for text-only models in posttrain

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1298) · state: closed · merged: True

## Original PR description

Fixes #1194

## Summary

`MegatronBridgePosttrainTrainer.train()` used `vlm_step.forward_step` for every model. At the pinned Megatron-Bridge commit (9577b12), `vlm_step.get_batch()` pads tokens to a multiple of 128 without updating `cu_seqlens`, so packed SFT with `pad_to_max_length=False` fails on the first step:

```
RuntimeError: split_with_sizes expects split_sizes to sum exactly to 2048 (input tensor's size at dimension 0),
but got split_sizes=[174, 193, 310, 247, 153, 132, 203, 251, 220, 140, 9]
```

Changes:

1. Text-only models use `gpt_step.forward_step`, as the pretrain trainer does; VLMs keep `vlm_step`. A provider counts as a VLM if it has a non-`None` `vision_config` or a `freeze_vision_model` field. Ministral3 and Nemotron-VL only have the latter, and no text-only provider in the pinned Megatron-Bridge has either.
   - `gpt_step.get_batch` indexes `batch["attention_mask"]`, while `vlm_step` used `.get()`. The chat SFT collate (with the default `get_attention_mask_from_fusion=True`) and the MLPerf synthetic warmup batches omit that key, so the text-only step fills in `attention_mask=None`.
   - `gpt_step` does not pad to a multiple of 128 like `vlm_step` did; the SFT collates already pad to a multiple of 16, and with PP the finetune loop takes the sequence length from the batch.
2. A `before_train` patch keeps `cu_seqlens` in sync with the `vlm_step` padding by registering the padded tail as an extra segment (`loss_mask` is 0 there), so VLMs on packed data no longer crash either. It is only registered while `vlm_step.get_batch` still pads; upstream removed that padding in NVIDIA-NeMo/Megatron-Bridge#4315.
3. The MLPerf Llama2-70B synthetic warmup, which runs by default (`SYNTH_WARMUP_STEPS=5`), now restores the Adam param-group `step`. It was left at the warmup step count, which shrank the first bias-corrected updates and raised the early training loss.

## Testing

- `test_posttrain_forward_step.py` covers VLM detection, step selection, the `attention_mask` default and the step that `train()` passes to `finetune()`. `test_vlm_step_cu_seqlens_patch.py` checks that the patched `cu_seqlens` sum to the padded length, padded positions are masked, the extension is idempotent, and CP / unpadded batches are left alone; two of its cases run the vendored `vlm_step.get_batch` and need a GPU and `nvidia-modelopt`. `pytest tests/unit_tests/backends/megatron_bridge/`: 51 passed, 2 skipped in `rocm/primus:v26.8`; the 2 skipped cases pass in a GPU container with `nvidia-modelopt`.
- Qwen3-0.6B LoRA, packed, `pad_to_max_length=False`, 8x MI300X, 20 iterations: main crashes at iteration 1. With this PR, `gpt_step` trains normally (loss 6.011 → 0.563), and `vlm_step` forced on with the patch matches it (6.012 → 0.561).
- MLPerf Llama2-70B LoRA, main (`vlm_step`) vs this PR (`gpt_step`), same seed and node. The recipe hard-codes MXFP4, which needs gfx95x, so this is a BF16 equivalence run on 8x MI300X (TP2, DP4, gbs 4, 80 iterations, warmup off), not an MLPerf reproduction:

**2. argmin fallback corrupts cu_seqlens when no -1 sentinel is present** (`primus/backends/megatron_bridge/patches/vlm_step_cu_seqlens_patches.py:57`)

When `cu_seqlens_argmin` is None, `extend_cu_seqlens_to` falls back to `torch.argmin(cu_seqlens[0])`, which returns 0 if the row has no `-1` sentinel. It then overwrites `cu_seqlens[0,0]` with `padded_len` instead of appending a segment; for example, `extend_cu_seqlens_to(IntTensor([[0,1000,2032]]), None, None, 2032, 2048)` returns `[[2048,1000,2032]]`. No current producer reaches this branch: the only `cu_seqlens` producer (Megatron-Bridge `sft.py` collate) always supplies `cu_seqlens_argmin` and `-1`-pads every row. Treating a missing sentinel as all entries valid (`num_valid = size(1)`), or requiring `cu_seqlens_argmin`, would make the helper robust.

**Origin:** latent

**Who is affected:** Only a future dataset or collate that emits `cu_seqlens` without `cu_seqlens_argmin` and without a `-1` sentinel, fed through the patched `vlm_step.get_batch`.

_Checked against the code by an independent pass._

**3. Patch gated on helper name in source; extension is not idempotent** (`primus/backends/megatron_bridge/patches/vlm_step_cu_seqlens_patches.py:33`)

The patch is gated on the text check `"_ceil_to_mult" in inspect.getsource(get_batch)` rather than on the actual bug. If an upstream fix (Megatron-Bridge#4315) updates `cu_seqlens` but keeps the helper name, the wrapper still applies. Because `extend_cu_seqlens_to` does not check whether `cu_seqlens` already ends at `padded_len`, it would then add a zero-length segment: two passes give `[[0,1000,2032,2048,2048]]` with argmin 5. If upstream renames the helper, the patch is silently disabled. The pinned bridge still has the bug, so the patch is correct today; making the extension idempotent (skip when the last valid entry already equals `padded_len`) would make it robust.

**Origin:** latent

**Who is affected:** Only VLM post-training users, and only after the Megatron-Bridge submodule is bumped to a version that fixes cu_seqlens but keeps `_ceil_to_mult` in `get_batch`.

_Checked against the code by an independent pass._

**4. Patch silently no-ops for mbs>1, 1-D, CP>1 and truncation cases** (`primus/backends/megatron_bridge/patches/vlm_step_cu_seqlens_patches.py:99`)

`wrap_vlm_get_batch` returns early without changing anything when context parallelism is on (CP>1). Upstream `vlm_step.get_batch` still slices tokens per CP rank and then pads them, while `cu_seqlens` stays global, so the patch does not fix the THD mismatch there. The skip is intentional and commented, but nothing is logged, so a warning would help. The other cases listed are not reachable: packed finetuning with `micro_batch_size>1` is rejected by Megatron-Bridge config validation, and packed `cu_seqlens` is always 2-D `[1, N]`. Truncation (`padded <= packed`) only happens if `packed_sequence_size` is set above `seq_length`.

**Who is affected:** Users fine-tuning a VLM provider (one with `vision_config` or `freeze_vision_model`) on a packed SFT dataset with `context_parallel_size > 1`.

_Checked against the code by an independent pass._

**5. Only real-vlm_step test silently skips on any import exception** (`tests/unit_tests/backends/megatron_bridge/test_vlm_step_cu_seqlens_patch.py:150`)

`TestUpstreamVlmStep` is the only test that runs the real vendored `vlm_step.get_batch` and the `_ceil_to_mult` source-string condition. Its `upstream_vlm_step` fixture catches any `Exception` and calls `pytest.skip`, so a Bridge import regression or an image dependency mismatch shows up as a skip rather than a failure. In this environment it skips even with the pinned Megatron-LM/Bridge sources present, because of `torch.onnx._type_utils` and `modelopt.torch` import errors. Consider narrowing the skip (e.g. only when `third_party/Megatron-Bridge` is empty). Consider also adding cases for PP padding to `seq_length` and for mbs>1 / `tokens=None` passthrough.

**Who is affected:** Maintainers relying on CI to catch drift between the patch and the vendored Megatron-Bridge `vlm_step`; users are unaffected.

_Checked against the code by an independent pass._

**6. Switching to `gpt_step` drops padding to 128 and to `seq_length` under PP** (`primus/backends/megatron_bridge/megatron_bridge_posttrain_trainer.py:121`)

Switching text-only posttrain from `vlm_step` to `gpt_step` drops `vlm_step`'s padding: round-up to a multiple of 128, or pad/truncate to `cfg.model.seq_length` under PP>1. In the default fine-tuning path this is harmless. With `dataloader_type='batch'`, `train.py` takes the P2P `seq_length` from the batch's own `tokens` width, and `GPTSFTDataset` already pads to `pad_seq_length_to_mult` (16). It only matters for unusual setups: PP>1 with a non-`batch` dataloader and `pad_to_max_length=False`, or alignment needs above 16. Upstream's text fine-tune script uses `gpt_step` too; a short note in the PR would be enough.

**Who is affected:** Only text-only posttrain runs with PP>1 that override `dataloader_type` away from `batch` while dynamically padding, or that need sequence alignment above 16; no shipped config does this.

_Checked against the code by an independent pass._

**7. Routing tests use stubs and miss real providers and batch contracts** (`tests/unit_tests/backends/megatron_bridge/test_posttrain_forward_step.py:33`)

The routing tests in `test_posttrain_forward_step.py` use `SimpleNamespace` configs and stub both `gpt_step` and `vlm_step`, so `_is_vlm_model` is never checked against the real Megatron-Bridge provider classes. No test runs a batch through the real `gpt_step.get_batch`, which indexes `batch["attention_mask"]` directly. So the `"attention_mask": None` entry this PR adds to `_SyntheticSFTDataIterator` is not guarded against regression. `test_vision_config_provider` sets both `vision_config` and `freeze_vision_model`, so it does not isolate the `vision_config` branch.

**Who is affected:** Maintainers relying on the tests to catch regressions in the text-only/VLM routing or the synthetic SFT warmup batch format; no runtime impact.

_Checked against the code by an independent pass._

**1. 🟠 Should fix: `gpt_step.get_batch` raises KeyError on batches without `attention_mask`**

Text-only post-training now uses `gpt_step.forward_step`, whose `get_batch` reads `batch['attention_mask']` directly. `vlm_step.get_batch` used `batch.get('attention_mask')` and also fell back to `input_ids`. `get_batch_from_iterator` copies only the keys the batch has. `GPTSFTChatDataset.collate_fn` (`chat=True` in `dataset_kwargs`) adds `attention_mask` only when `get_attention_mask_from_fusion=False`, and that flag defaults to True, so such runs now fail with `KeyError: 'attention_mask'` on the first step. Packed and plain SFT collates always set the key and are not affected; consider wrapping the iterator with `setdefault('attention_mask', None)` rather than patching only the synthetic warmup iterator.

**Who is affected:** Users fine-tuning a text-only model through `MegatronBridgePosttrainTrainer` with a chat-format SFT dataset (`dataset_kwargs={'chat': True}`), or with a custom iterator that omits `attention_mask`.

_Checked against the code by an independent pass._
