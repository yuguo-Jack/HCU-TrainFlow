# feat(diffusion): Add AMDB FLUX.1-dev benchmark support

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1341) · state: closed · merged: True

## Original PR description

## Summary

Add **FLUX.1-dev** support for the AMDiffusionBenchmark (AMDB), reusing the existing Primus diffusion backend and native FLUX implementation.

This PR introduces the shared AMDB benchmark infrastructure and integrates FLUX.1-dev without duplicating existing model code.

## Changes

### Shared AMDB infrastructure
- Add `AMDBBenchmarkTrainer`, extending the existing `FSDP2Trainer`.
- Add shared benchmark dataset loading and checkpoint download support.
- Reuse the existing training step loop, even-size batch handling, and gradient-norm short-circuit in `trainers/base.py`.
- Integrate with the existing model registry, argument builder, logging, and checkpoint preparation paths.

### FLUX.1-dev integration
- Reuse the native FLUX implementation under `models/flux/` and `models/registrations/flux.py`.
- Add opt-in AMDB-specific behavior:
  - BFL QK-norm epsilon (`1e-6`).
  - Logit-normal timestep sampling.
  - Pre-encoded latent support.
  - Triton RoPE implementation (`models/flux/rope_triton.py`).
- Reuse the existing `data/flux_precomputed.py` image loader.
- Keep the existing `flux.1-dev` and `flux.1-schnell` execution paths unchanged unless the new benchmark options are explicitly enabled.

## Reused Components

- `models/flux/layers.py`
- `models/flux/model.py`
- `models/flux/adapter.py`
- `models/flux/train_pipeline.py`
- `models/flux/autoencoder.py`

**12. Short tail step reports inflated FPS/TFLOPS: latent caching drops the even-batch sampler** (`primus/backends/diffusion/trainers/benchmark.py:88`)

`_cache_encoded_batches` (on by default) rebuilds the loader with a plain `DistributedSampler`/`DataLoader(drop_last=False)`, discarding `EvenSizeBatchSampler`. 5 samples at batch 4 give batch sizes `[4, 1]`, while FPS still uses the configured batch size and TFLOPS reuses the first step's FLOPs, so the short tail step reports inflated numbers. This also makes `dataloader_even_batches` dead; keep the even-batch sampler on the cached path.

_An independent check of the code found this probably does not apply: `_cache_encoded_batches` iterates `self.dataloader`, which for flux-dev is the `EvenSizeBatchSampler` loader (`BENCHMARK_TRAINER` sets `dataloader_even_batches: True`), so the cached list is already padded to a multiple of the batch size. Running the real sampler on head: 5 samples at batch 4 cache 8 samples and the rebuilt loader yields [4, 4]; 7 at batch 3 yields [3, 3, 3]._

**13. Fused RoPE cache keeps GPU tensors pinned and may return stale values; inputs under-validated** (`primus/backends/diffusion/models/flux/rope_triton.py:87`)

`_shared_cos_sin` keeps a process-global cache keyed by identity and shape but not device or dtype. It is never cleared, so `pe` and fp32 cos/sin copies stay pinned on the GPU, and it returns stale values if `pe` is modified in place. `fused_rope_supported` checks only `xq`, not the `freqs_cis` device or the `xk` layout, which risks out-of-bounds reads.

_An independent check of the code found this probably does not apply: `_shared_cos_sin` caches a single entry keyed by `is freqs_cis` while holding a reference, and `pe` is rebuilt by `pe_embedder(ids)` each forward and never written in place. `apply_rope` only takes the fused path when `xq.shape == xk.shape`, `_launch` makes inputs contiguous, and `fused_rope_supported` checks `freqs_cis` dims 0/1/3 against `x`, so no out-of-bounds or stale read is reachable._

Existing caches are bypassed, so FLUX.1-dev (~24GB) and T5-XXL are re-downloaded. Use `~/.cache/huggingface` and respect explicit `HF_HOME`; update the README and test that lock in the current path.

_An independent check of the code found this probably does not apply: The `~/cache/huggingface` root and skipping the runner's automatic `$DATA_PATH/huggingface` `HF_HOME` are stated in the download.py docstring, the backend README and the unit test. **19. Host RAM grows with dataset size under default `cache_latents`: this PR caches all encodings on CPU** (`primus/backends/diffusion/trainers/benchmark.py:66`)

This is deliberate, to match AMDiffusionBenchmark's cached-latent runs, and can be disabled with `cache_latents: false`.
