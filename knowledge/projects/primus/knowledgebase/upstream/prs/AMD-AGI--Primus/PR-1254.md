# fix(glm5_next): accept text-only HF checkpoint names in the GLM-5.3 loader

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1254) · state: closed · merged: True

## Original PR description

## Summary

The GLM-5.3 (`glm5_next`) HF loader hard-coded the `model.language_model.` weight prefix used by the released checkpoint. Text-only HF exports, such as Miles' Megatron -> HF export used in RL, write `model.layers.N...` instead, so the trainer could not reload its own exported checkpoints. SGLang strips `language_model.` either way and serves both.

`_HFReader` now picks the prefix (`model.language_model.` first, then `model.`) by looking up `embed_tokens.weight` in `model.safetensors.index.json`, and raises a `KeyError` naming the tried prefixes if neither is present. The embedding, final norm and per-layer lookups use the detected prefix. `lm_head.weight` has no prefix in either layout and is unchanged.

## Testing

- New `tests/unit_tests/backends/megatron/glm5_next/test_glm5_next_hf_loader.py` (CPU only): detects both prefixes on a tiny safetensors checkpoint and rejects an unknown one. `3 passed` in `rocm/sgl-dev:miles-rocm10-mi30x-20261001` on MI300X.
