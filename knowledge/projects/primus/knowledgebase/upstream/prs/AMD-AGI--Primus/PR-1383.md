# fix(gpt-oss): run the MLPerf recipes on PyTorch 2.14 and Megatron core_v0.19.2

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1383) · state: open · merged: False

## Original PR description

On the current main stack (v26.8 image with PyTorch 2.14, Megatron-LM `core_v0.19.2` since #1321), the GPT-OSS-20B MLPerf recipes cannot train. This PR fixes the three issues that the 200-step MLPerf short test hits in order.

## 1. Conflicting MoE SM-count knobs abort startup

`core_v0.19.2` merges `moe_deepep_num_sms` and `moe_hybridep_num_sms` into `moe_flex_dispatcher_num_sms` and rejects differing values:

```
RuntimeError: Training execution failed: Conflicting deprecated SM-count knobs {'moe_deepep_num_sms': 20, 'moe_hybridep_num_sms': 16}; set a single moe_flex_dispatcher_num_sms instead.
```

The three GPT-OSS MLPerf recipes drop both keys. The resulting files are byte-identical to #1370's, so the two PRs merge cleanly. These recipes use the `alltoall` dispatcher with DeepEP disabled, so the run is unchanged.

## 2. RCCL-SDMA parameter buffers: `KeyError: 'params'`

`_ParamAndGradBuffer.__init__` now takes `params_with_names` (`(param, name)` pairs) instead of `params`, so the direct parameter-gather wrapper failed while DDP wrapped the model:

```
File ".../rccl_sdma_param_all_gather_patches.py", line 129, in wrapped
KeyError: 'params'
```

The wrapper now reads `params_with_names` when present and keeps the old argument as a fallback. A unit test covers the 0.19 signature.

## 3. Fused Adam-clip patch is silently skipped

- The JIT extension was built with `-std=c++17`, but PyTorch 2.14 headers require C++20.
- The patch also wraps `MegatronOptimizer.get_main_grads_for_grad_norm`, which 0.19 renamed to `get_grads_for_grad_norm`.

The patch runner logs both failures and continues, so training falls back to the unfused optimizer step even with `PRIMUS_FUSED_ADAM_CLIP=1`:

```
[Patch] ✗ Patch 'megatron.optimizer.te_fused_adam_clip' failed: type object 'MegatronOptimizer' has no attribute 'get_main_grads_for_grad_norm'
```

The patch file and its tests are taken unchanged from #1364 (same base blob as main):

- Use `get_grads_for_grad_norm` when present.
- Let torch choose the C++ standard.
- Accept the `group=` argument of `reduce_max_stat_across_model_parallel_group`.
- Reject separate grad-norm groups and `grad_norm_skip_threshold`, which a single on-device norm cannot honor.

## Validation

In progress as part of the GPT-OSS-20B MLPerf TTT validation on main (Jira AIMA-337). The short-test gate fails on any `[Patch] ✗` line and requires both training and evaluation loss to decrease.
