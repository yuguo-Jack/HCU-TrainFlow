# Make training and the projection benchmark both take the fused FP8 grouped-MLP path plus remove calibration constants

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1346) · state: open · merged: False

## Original PR description

## Changes

**Pipeline schedule**
- VPP is resolved the way Megatron's `validate_args` does it. A bare `virtual_pipeline_model_parallel_size`, with no `num_virtual_stages_per_pipeline_rank`, `num_layers_per_virtual_pipeline_stage` or layout, is reset to `None`, so Megatron runs the non-interleaved 1F1B schedule. The projection had been simulating the interleaved schedule for these configs. This applies to the Megatron backend only; the JAX and TorchTitan adapters keep their own semantics. A warning is printed when it happens. `--vpp` now also sets `num_virtual_stages_per_pipeline_rank`, so it actually takes effect.
- Each pipeline stage-to-stage send is charged in the simulator (latency + bytes / bandwidth).

**Attention**
- With `sink_window_even_layers_only`, sink attention applies its sliding window to odd layers only. The benchmark model has one layer, so both the windowed and the full variant are timed and weighted by the full model's layer pattern. In real traces, full-attention layers cost ~0.85 ms more in forward and ~2.6 ms more in backward than windowed ones, and the benchmark reproduces both.

**Gradient sync and optimizer**
- The Megatron DDP bucket model:
  - bucket size = params // `ddp_num_buckets`;
  - parameters in reverse order, never split;
  - separate dense and expert buffers;
  - no bucketing for `pp_rank > 0` or model chunks after the first;
  - a per-rank serial reduce queue during the last micro-batch's backward;
  - the `overlap_param_gather` all-gather prefetch chain.
- `finish_grad_sync()` and `start_param_sync()` are timed on the real buffers on the benchmark node. That measured bus bandwidth is used for intra-node groups.
- Gradient bytes follow `grad_reduce_in_bf16`. Attention parameters are counted from heads, `kv_channels` and query groups. The shared expert and untied vocab parameters are included. Only non-expert gradients are synced when experts are sharded.

**Other**
- The loss is benchmarked on the rank that owns it, and vocab padding matches Megatron's.

**7. 🟠 Should fix: Projected optimizer step inflated by factor `cp` with CP>1: target expert-DP omits context parallelism**

The target optimizer scaling uses `max(1, dp_target // ep)` as expert-DP, where `dp_target = world/(tp*pp*cp)`. Megatron's expert-DP is `world/(etp*ep*pp)`, i.e. `dp*cp/ep`, which is what the benchmark side records via `get_expert_data_parallel_world_size()` and what `_exposed_overlapped_grad_sync_ms` uses. With CP>1 the target per-rank expert shard is overestimated by a factor of `cp`, inflating the projected optimizer step. Minor: `_fixed_ms` is clamped at 0, which hides a negative residual (per-element overestimate) instead of warning.

**Who is affected:** Performance projection of MoE models with context parallelism > 1 and the distributed optimizer, in benchmark mode.
