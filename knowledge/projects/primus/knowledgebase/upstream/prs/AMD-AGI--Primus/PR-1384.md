# ci(docker): build fork PR images without pushing and keep the Docker Hub token off the runner

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1384) · state: open · merged: False

## Original PR description

## Problem

Fork and Dependabot PRs get no repository secrets, so build-docker fails at `docker login -u tasimage -p` with exit code 125 (e.g. #1351).

## Changes

**CI workflow**
- **Pushing:** on `pull_request` runs without a Docker Hub token, the image is built but not pushed. Any other event without a token fails, so `latest`/`weekly` never silently go stale.
- **Login:** Docker Hub logins use `--password-stdin` under a per-run `DOCKER_CONFIG` that is deleted on exit. The token is no longer left on the runner for later jobs to read.
- **Getting the image:** build-docker exposes the built image id and tag. run-unittest-torch uses that image id from the local Docker daemon when it runs on the build host; otherwise it pulls the tag and checks it still has that id. A re-run or a retag therefore cannot swap the image.
  - Fork PRs are tested against their own image, including Dockerfile and pin changes.
  - A fork PR's image exists only on the build host, so its GPU tests fail with a clear error on any other host.
  - The duplicated `IMAGE_TAG` step is removed.
- **Fork container:** fork PRs get their own UT container (`primus_ut_torch_fork`), reused across fork PRs. Fork code never runs in the container that internal PRs, main and scheduled runs reuse and pass `HF_TOKEN` into.
- **Pre-checkout cleanup:** the chown helper runs `BASE_IMAGE` instead of whichever local `tasimage/primus` image comes first, which may be a fork PR's build.
- **Concurrency:** PR groups key on the PR number, so fork PRs from same-named branches (e.g. `main`) don't cancel each other.
- **Docs:** `contributing.md` and `testing.md` describe the no-push case and that run-unittest-torch depends on build-docker.

**TorchTitan prepare hook**
- `HF_TOKEN` is only required when `tokenizer.json` is not already cached. Fork PRs no longer fail TorchTitan E2E when the assets are under `DATA_PATH/torchtitan`.
- Every node still fails fast when the tokenizer is missing and no token is set.

## Testing

- pre-commit passes. actionlint reports no new findings.
- The push block and the test job's image lookup were simulated with a stubbed `docker`. The four lookup cases (same host; other host without token; pull matching the id; tag rebuilt) all behave as expected, and no auth dir is left behind. The per-run `DOCKER_CONFIG` push was also exercised by a real build-docker run of this PR.
- `tests/runner/test_prepare_hooks.py` passes. The new tests fail on main's hook (cached tokenizer) and on a rank-0-only token check (other nodes).

**5. Long-running build's `-ainic` push fails unauthenticated: this PR's mtime-based sweep deletes its auth dir** (`.github/workflows/ci.yaml:218-221`)

The new sweep `find "${HOME}" -maxdepth 1 -name 'docker-push-auth-*' -mmin +60 -exec rm -rf {} +` measures age by directory mtime. That mtime is set by `docker login` and never refreshed by `docker push`. If two `build-docker` runners share the same `$HOME`, a run that logs in can delete the auth dir of another run whose first push has taken over an hour. The in-flight push keeps its credentials, but that run's following `docker push ...-ainic` then fails unauthenticated. The step runs under GitHub's default `bash -e`, so a `find` error (e.g. two sweeps racing on the same dir) also fails the step. Adding `|| true` and keying staleness on something the run refreshes would avoid both.

**Who is affected:** Only hosts running several `build-docker` runners under one user/`$HOME`, with concurrent non-fork runs whose image push exceeds an hour.

In the pruned case the error blames host placement, which misleads. Keep a pull-by-tag fallback when credentials exist, and give a missing image id its own error message.

**Who is affected:** Non-PR runs (main, schedule, release) whose `build-docker` and `run-unittest-torch` runners end up on different hosts, or whose image was pruned out-of-band before a re-run.
