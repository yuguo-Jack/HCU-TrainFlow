# maxtext: bump to release/v26.9, silence TE return_max_logit warnings, default autotune level 3 (#1289)

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1316) · state: closed · merged: True

## Original PR description

## Summary

Moves MaxText to `release/v26.9` and fixes two problems that show up on the JAX 0.11.1 / ROCm 10.2 images (tested on
`utd/ci:jax_ci_7821e29_20261019`, 8× MI325X):

- TE 2.19 prints a four-line `return_max_logit` warning on every backward attention call: once per layer, per GPU, per step, about 90% of a MaxText training log.
- Primus's default `--xla_gpu_autotune_level=4` intermittently aborts compilation of the train step on GPU 0. Under `primus-cli container`, 7 of 10 runs crashed before step 0.

## Changes

- **Bump `third_party/maxtext` to `release/v26.9`** (`07c240fa` → `8d1d43c0`). `.gitmodules` now tracks `release/v26.9`, and `primus/_thirdparty.lock` is regenerated. v26.9 carries the same 11 ROCm patches as v26.8, rebased onto newer upstream. Upstream drops the `retry_when_tokens_dropped` config key and renames the `cosmos3-*-reasoner` model configs to `weaver-max` / `weaver-mini`; nothing in Primus references them.
- **Silence TE's per-call `return_max_logit` warning** (new `primus/backends/maxtext/patches/te_fused_attn_patches.py`). TE's C++ backward fused-attention FFI handler reads `return_max_logit`, but the Python lowering of `FusedAttnBwdPrimitive` only passes it to the forward call, so the handler warns and falls back to `False`. A MaxText setup patch adds `return_max_logit=False`, the same fallback value, to the backward lowering, so numerics are unchanged. MaxText imports TE lazily and TE's import order matters on this stack, so the patch installs an import hook instead of importing TE. It's a no-op when TE already passes the attribute.
- **Default `XLA_GPU_AUTOTUNE_LEVEL` to 3** (`primus/backends/maxtext/env_spec.py`, plus the two docs that state the default). Level 4 adds the autotuner's correctness checks (redzone checks and candidate result comparison). On this image those checks fail with `redzone_allocator.cc:248 ... Mismatched results with host and device comparison` or `HSA_STATUS_ERROR_MEMORY_APERTURE_VIOLATION` on GPU 0. Level 3 keeps autotuning and drops only the checks. `XLA_GPU_AUTOTUNE_LEVEL=4` restores the old default.

### Why the autotune crash is easy to miss

Running several jobs inside one long-lived container keeps MaxText's JAX compilation cache (`~/jax_cache`) warm, so later runs skip compilation and autotuning entirely and never crash. `primus-cli container` starts a fresh container for every run, so every run compiles from scratch.

## Validation

`primus-cli container` on 8× MI325X (`tus1-p3-g43`), image `unifiedtrainingdockers.azurecr.io/utd/ci:jax_ci_7821e29_20261019`, fresh compile per run, level set with `--env
XLA_GPU_AUTOTUNE_LEVEL=<n>`.

**Autotune level.** llama2_7B BF16; the level-4 row also includes two deepseek_v2_16B BF16 runs.

| Level | Runs passed | Seconds per step |
|---|---|---|
| 4 (old default) | 3 / 10 | 5.68–5.72 |
| 3 (new default) | 5 / 5 | 5.67–5.68 |
| 0 (image default) | 4 / 4 | 5.74–5.76 |

**FP8 at level 3.** 20 steps each, with level 0 as the control, since the old `env_spec.py` comment says level 0 produces NaN losses on FP8 MoE models.

| Config | Level 3 loss, step 0 → 19 | Level 0 loss, step 0 → 19 | Seconds per step, level 3 vs 0 |
|---|---|---|---|
| `deepseek_v2_16B-nanoo_fp8` | 12.034 → 11.511 | 12.034 → 11.511 | 3.97 vs 4.03 |
| `qwen3_30B_A3B-nanoo_fp8` | 12.427 → 12.149 | 12.427 → 12.149 | 4.49 vs 4.59 |

All losses are finite, and level 3 matches level 0 within 0.002 at every step. Level 0 didn't produce NaN either, so this shows level 3 is safe for `nanoo_fp8` on MI325X but doesn't exercise the overflow the old comment describes. The plain `fp8` configs that may hit it exist only for MI355X.

**TE patch.** Every run with the patch logs `Added 'return_max_logit=False' to TE's backward fused-attention FFI lowering.` and has zero `return_max_logit` warnings, against 4,320 in a 20-step deepseek_v2_16B BF16 run without it. On Qwen3-30B-A3B over 12 steps: 4,608 → 0 warnings, step time 3.478 → 3.480 s, loss unchanged (12.197), log 1.8 MB → 220 KB.

**MaxText v26.9 submodule.** The CI image sets
`MAXTEXT_PATH=/workspace/maxtext`, so the `primus-cli container` runs above use the image's MaxText, not the submodule. The submodule itself (`third_party/maxtext` at `8d1d43c0`) passed llama2_7B BF16 for 10 steps in three runs from a manually started container of the same image.

**Unit tests.** `pytest
tests/unit_tests/core/backend/test_env_registry.py`: 18 passed.

_PostImportHook is inserted at sys.meta_path[0] and never removed after it patches the target. It re-implements finder iteration by hand and monkey-patches loader.exec_module on the loader instance returned by another finder, instead of using a wrapping loader or new spec. Wrappers stay attached to shared or cached loaders and stack on every later reload or re-import. This can bypass other finders' expectations (LazyLoader, editable-install finders) and is fragile global import-system state for a log-noise fix.
