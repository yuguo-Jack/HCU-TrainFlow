# feat(tools/perf): run control, provenance, failure reasons, diffusion/DLRM backend and Excel report

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1260) · state: closed · merged: True

## Original PR description

## Summary

This PR makes `tools/perf` usable for unattended publication benchmarking.
Runs are bounded and can be interrupted cleanly. Every result records what
produced it. Failures are classified. Diffusion and DLRM benchmarks join the
batch. The results go into an Excel report that can compare against a
baseline.

### Run control (`run_batch.sh`, `run_batch_multinode.sh`, `lib/`)
- Both runners share their per-run helpers in `lib/run.sh`, `lib/control.sh`
  and `lib/common.sh`. Logs, summaries and snapshots are unchanged by the move.
- Each run gets its own process group and is stopped after
  `MAX_RUN_SECONDS` (default 1 h) or after `MAX_IDLE_SECONDS` (default 20 min)
  without log output.
- Ctrl+C, SIGTERM and SIGHUP stop the run and its labelled containers within
  about a second.
- The footer records why the run ended.
- Pre-run checks:
  - pull a missing image (with an optional `DOCKER_LOGIN_*` login)
  - stop this user's containers left over from earlier batches
  - refuse busy GPUs (`GPU_BUSY_MIB`, `ALLOW_BUSY_GPUS=1`)
  - refuse docker0, bridge or loopback NCCL/Gloo interfaces
  - in multi-node batches, refuse nodes that hold different images under the
    same tag (`PULL_IMAGE=1` pulls the registry copy on every node first)
- `DRY_RUN=1` prints the plan without touching Docker, the GPUs or `HF_TOKEN`.
- Exit codes: 0 ok, 1 a run failed or did not start, 2 refused,
  130 interrupted.
- `NUM_REPS` repetitions and `MAX_ATTEMPTS_PER_CONFIG` retries.
- `EXTRA_ENV` values that look like secrets are masked wherever they are
  shown, and `PERF_*` names are rejected.

### Provenance
- The summary and every run banner record the image ID, the container's ROCm
  and HIP next to the host's ROCm, and the host settings: CPU governor, NUMA
  balancing, THP, IOMMU and the amdgpu driver.
- `batch_host_<stamp>.txt` holds every node's settings.
- The image's `/workspace/.manifest` is copied into `batch_manifest_<stamp>/`.

### Extraction (`extract_results.py`, parser version 4)
- Writes fixed `results.csv` and `results.json` files atomically, refreshed
  at the end of every batch (`EXTRACT=0` skips this).
- Every row gets a `status` (ok, failed, interrupted, incomplete or unknown).
  A row that is not ok also gets a `failure_reason`: timeout, idle, oom,
  gpu_contended, nic_error, nccl_error, segfault, python_error, killed and
  others, together with the log line that shows it. This works on old logs
  too.
- New columns are appended, so readers that index columns by position keep
  working.
- Fixes:
  - MXFP8 configs were labelled FP8.
  - Fractional batch sizes became 0.
  - Failed multi-node attempts looked like good runs.

### Diffusion and DLRM benchmarks (`diffusion_bench/`, `BACKEND=...,diffusion_dlrm`)
- New `diffusion_bench` runner for AMDiffusionBenchmark (FLUX.1-dev, SDXL,
  Mochi, HunyuanVideo, Wan 2.1) and DLRMBenchmark, driven by `config.yaml`.
- The batch runner launches it once per repetition, after the catalog
  configs, in catalog mode only. The multi-node runner refuses this backend.
- The extractor writes one row per diffusion model and per DLRM precision.
- `HF_TOKEN` is never put on a command line and is masked in every results
  file.

### Excel report (`report.py`)
- Writes `report.xlsx` with these sheets:
  - Overview: provenance and run counts per batch
  - Performance: means and CV over each config's successful runs; replicates
    with different step counts share a row, and the Steps column lists them
  - Runs: an Excel table to build PivotTables on, including failure details
  - a TFLOP/s chart
- `--baseline DIR` with `--threshold` adds the baseline's numbers and the
  change. Several result directories can share one report.
- pandas and XlsxWriter are installed on first use into
  `~/.cache/primus-perf/`. The runners only call the report when both are
  already installed and never install mid-batch. `REPORT=0` skips the report.

### Catalogs
- `perf-config.yaml` is renamed to `perf_configs.yaml`. The MI300X MaxText FP8
  entries now point at the `nanoo_fp8` configs.
- `configs.yaml` adds the MI300X Mamba, Zebra-Llama, GDN and KDA models and
  the Megatron-Bridge Qwen3-32B LoRA and SFT post-train configs, plus the
  MI355X Llama3.1-8B MXFP8 and MXFP4 configs.
- `perf_pub.sh` is an example script for the publication perf collection.

## Behaviour changes to note
- Single-node runs now have time limits. Raise `MAX_RUN_SECONDS` or
  `MAX_IDLE_SECONDS` for long configs and for first-time model downloads.
- The output files have fixed names, `results.csv` and `results.json`, and
  are overwritten.
- The runners return non-zero when any run fails.
