# perf(megatron): align persistent DEOSC state views with logical quantization tiles

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1371) · state: open · merged: False

## Original PR description

# Description

With `weight_deosc_state_slabs`, every DEOSC shard gets four views (`prev`, `prev_q`, `dist_w`, `dist_w_qdq`) into two per-device slabs. This change pads each shard so its views start at the same phase modulo 32 as the shard's offset in its parameter (`rng.start % 32`). The fused DEOSC kernels then see whole 32-column MXFP4 tiles at aligned addresses, including shards that start mid-tile. The padding is allocated once, and state shapes and checkpoint contents are unchanged.

This is Su Ann Chong's commit from `suachong/gptoss-deosc-state-alignment-20261011` (8488dc54c, also on `suachong/mpo`). It applies to `main` unchanged. The other commits on this branch add:

- a CPU test for shards that start at offset 0 and mid-tile (offset 45): views stay inside their slab and keep the logical tile phase;
- black formatting of the change.

In the GPT-OSS-20B MLPerf 6.1 tracking deck, this change together with the router-gradient join (#1372) takes the MXFP4 recipe from 56.49 to 56.11 min TTT (67.88 → 68.33 samples/s) on 8× MI355X.
