# feat(zaya1): size MI355X 8B batches to GPU memory

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1276) · state: closed · merged: True

## Original PR description

## Summary

- Size `micro_batch_size` on MI355X to the largest multiple of 8 that completes on one 8-GPU node with `rocm/primus:v26.8`, end-of-training evaluation included: BF16 248 / 1984 and FP8 208 / 1664. They replace the MI300X sizes (BF16 128 / 1024, FP8 120 / 960) that #1270 gave MI355X without an MI355X run. `global_batch_size` stays micro batch × 8, one micro batch per GPU per step.
- Docs: MI355X rows in the ZAYA1 validation note's throughput table, and the support matrix no longer calls MI355X untested.

## Results

One MI355X node on Crusoe: 30 steps, mock data, sequence length 128, data parallel 8, `rocm/primus:v26.8` (PyTorch 2.14.0, TE 2.17.1). Step time is the median over steps 6 to 30, tokens/s/GPU the harmonic mean, and TFLOP/s/GPU the mean. Every run that completed had 0 skipped and 0 NaN iterations.

| Precision | Micro / global batch | Step time | Tokens/s/GPU | TFLOP/s/GPU | Peak memory per GPU | Tokens/s/GPU before (MI300X sizes) | Tokens/s/GPU at micro 1, global 8 |
|---|---|---|---|---|---|---|---|
| BF16 | 248 / 1984 | 1733 ms | 17363 | 209.7 | 282 of 288 GB | 13069 | 168 |
| FP8 | 208 / 1664 | 1890 ms | 12400 | 158.4 | 284 of 288 GB | 7654 | 105 |

Next size up: BF16 256 and FP8 216 (also 224 and 232) run out of memory on the fp32 logits buffer. At FP8 216 the allocator held 30 GiB reserved but unused, so `expandable_segments` would probably fit it, as it fit MI325X FP8 192 in #1270. Not adopted, to match the other recipes.

TFLOP/s/GPU is Megatron's analytic GPT estimate. It models neither CCA nor the alternating attention and MoE stages, so compare it only between ZAYA1 runs.

FP8 at 120 / 960 is slower on MI355X (7654 tokens/s/GPU) than on MI300X (8478), while BF16 at 128 / 1024 is 30% faster than on MI300X. Not profiled here.
