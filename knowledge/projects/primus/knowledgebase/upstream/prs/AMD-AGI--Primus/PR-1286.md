# feat(megatron): reuse the logits buffer in TE fused cross entropy (overwrite_input)

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1286) · state: closed · merged: True

## Original PR description

## Summary

TE 2.19+ changed the fused cross-entropy backward (TE `bdfc75d`, "Minimize the memory usage of the fused cross entropy kernel"). Unless `parallel_cross_entropy` is called with `overwrite_input=True`, it now keeps a BF16 copy of the logits for backward: one extra `b * s * vocab * 2`-byte buffer per in-flight micro-batch. Megatron's `te_parallel_cross_entropy` never passes the flag, so Primus runs on TE 2.19+ images pay that memory. This is what pushed gpt-oss FP8 out of memory on the new UTD CI images (AIMA-298).

This PR adds a `te_ce_overwrite_input` option, **on by default**, which restores the TE ≤ 2.17 memory behavior for every Megatron config:

- **`te_patches/cross_entropy_overwrite_patches.py`:** a `before_train` patch, active only when `te_ce_overwrite_input` is set *and* `cross_entropy_loss_fusion: true` with `cross_entropy_fusion_impl: te`. It replaces `te_parallel_cross_entropy` in both `megatron.core.extensions.transformer_engine` and `language_module` with a wrapper that passes `overwrite_input=True`.
  - It falls back to Megatron's call for non-contiguous logits, which TE rejects with the flag.
  - It logs a message and leaves Megatron's call unchanged when the installed TE has no `overwrite_input` (TE ≤ 2.17).
- **`primus_megatron_module.yaml`:** adds `te_ce_overwrite_input: true`, inherited by every Megatron config (about 215 configs use `cross_entropy_fusion_impl: te`).

**Caveat:** with the flag, the logits buffer holds the gradient after the loss backward. A config that reads the logits afterwards (distillation, reusing RL log-probs, hooks that log logits) must set `te_ce_overwrite_input: false`. I found no such reader in the Primus Megatron backend; the DeepSeek-V4, MiniMax-M3 and GLM-5 "distill" code uses the attention indexer's scores, not the output logits. Megatron-Bridge and posttrain paths were not audited.

**Older TE is unaffected:** on TE without `overwrite_input` (≤ 2.17, and the 2.19.0.dev0 builds before `bdfc75d`) the patch logs a message and changes nothing. TE ≤ 2.17 already reused the logits buffer.

## Results

MI355X, 8 GPUs, `utd/ci:primus_ci_2d288e9_20261020` (TE 2.20.0.dev0+023639b51), gpt-oss FP8 tensorwise:

| Run | Patch | tok/s/GPU | Peak memory |
|---|---|---|---|
| 20B (image config, mbs 12) | off | 41,127 | 285.8 GB |
| 20B | on (this branch) | 44,630 | **268.5 GB** |
| 120B proxy, recompute 12 layers | off | 30,098 | 250.3 GB |
| 120B proxy, recompute 12 layers | on | 31,010 | **238.9 GB** |

- **Memory:** 11–17 GB lower peak.
- **Loss:** unchanged; the gradient is computed the same way in both modes.
- **Throughput:** the 20B patch-off run is from a single run and probably on the slow side, so read the throughput difference as neutral to slightly positive.

## Testing

- **New tests:** `tests/unit_tests/backends/megatron/test_te_cross_entropy_overwrite_patches.py` covers the enable condition, TE signature detection, wrapper arguments, the non-contiguous fallback, and a GPU check that loss and logits gradient are **bit-identical** with and without `overwrite_input` against real TE.
  - TE 2.20 (new UTD image): 8 passed.
  - TE 2.17.1 (`rocm/primus:v26.8`): 7 passed, 1 skipped (TE has no `overwrite_input`).
- **End to end:** 20B FP8 run from this branch with `te_ce_overwrite_input: true`. The patch applies and logs its message, and peak memory is 268.5 GB (row 2 above).
- **Lint:** `pre-commit run` on the changed files passes.

## Follow-ups (not in this PR)

- If a workload that reads logits after backward lands, set `te_ce_overwrite_input: false` in its config.
