# feat(diffusion): Add AMDB HunyuanVideo benchmark support

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1343) · state: closed · merged: False

## Original PR description

## Summary

Add **HunyuanVideo** support for AMDiffusionBenchmark using the existing Primus diffusion training infrastructure.

Since HunyuanVideo does not currently have a native implementation in Primus, this PR introduces the HunyuanVideo transformer architecture and integrates it with the shared AMDB benchmark framework.

## Changes

### HunyuanVideo model implementation
- Add the HunyuanVideo transformer architecture and supporting model components.
- Implement the model using the existing `GenAIModel` interface.
- Reuse `utils/hf_load.py` for Hugging Face checkpoint loading.
- Register the model through the existing Primus configuration and model registration infrastructure.

### AMDB integration
- Integrate with `AMDBBenchmarkTrainer`, extending `FSDP2Trainer`.
- Include shared AMDB dataset and checkpoint download support.
- Reuse existing training step handling, batch management, and gradient-norm logic.
- Use existing Primus logging and parameter counting utilities.

## Reused Components

- `trainers/base.py`
- `models/interface.py`
- `argument_builder.py`
- `registry.py`
- `utils/hf_load.py`
- `utils/log.py`
- `utils/train_utils.py`
- Existing diffusion checkpoint preparation infrastructure.

## Validation

- [x] End-to-end AMDB video benchmark training.

**11. Synthetic or cached denoiser-only runs still download the 13B checkpoint and encoders: staging runs first** (`runner/helpers/hooks/train/pretrain/diffusion/prepare.py:208`)

`_stage_benchmark_downloads` runs before the `synthetic:` and cached `.pt` short-circuits in `_validate_benchmark_model`, and `stage_benchmark_assets` always calls `materialize_pretrained`. Denoiser-only runs therefore snapshot-download the 13B `hunyuanvideo-community/HunyuanVideo` checkpoint, the dataset and the LLaMA/CLIP encoders, and fail offline or on gated repos (probe: `dataset_path='synthetic:1x16'` still calls `_snapshot('hunyuanvideo-community/HunyuanVideo')`). Skip staging for synthetic or cached inputs, and gate the checkpoint on `BENCHMARK_DENOISER_ONLY` too, not just the encoders.

_An independent check of the code found this probably does not apply: `build_hunyuan_model` (models/registrations/hunyuan.py:74) itself calls `materialize_pretrained('hunyuan-video', ...)` unconditionally and loads the weights, so training needs the full checkpoint even for `synthetic:` or denoiser-only runs; prepare only downloads it earlier. `materialize_dataset` returns early for `synthetic:`/`.pt`, and encoder prefetch is skipped exactly when `BENCHMARK_DENOISER_ONLY=1`, which is also when the trainer skips building `HunyuanTextEncoder`._

**12. Existing HF caches are ignored and checkpoints re-downloaded: fallback cache root is `~/cache/huggingface`** (`primus/backends/diffusion/utils/download.py:55`)

`huggingface_home()` falls back to `Path.home()/'cache'/'huggingface'` instead of `~/.cache/huggingface` (probe: `/ws/home/cache/huggingface`), and `configure_huggingface_cache` overwrites `HF_HOME`/`HF_HUB_CACHE` with it. Existing caches are not reused, so multi-GB checkpoints are re-downloaded into a new directory. An explicit `HF_HOME` equal to `$DATA_PATH/huggingface` is also overridden; use the standard default.

_An independent check of the code found this probably does not apply: The `download.py` module docstring, `primus/backends/diffusion/README.md` and `test_benchmark_workloads.py` all document and assert the `~/cache/huggingface` fallback, and the bypass of the runner's automatic `$DATA_PATH/huggingface` (set by `base_env.sh`). An explicit non-automatic `HF_HOME` and `PRIMUS_HF_HOME` are still honoured, so this is a documented design choice, not a bug._

**13. Cached-latent loader drops even-batch padding, inflating FPS on short tail steps and risking hangs** (`primus/backends/diffusion/trainers/benchmark.py:82`)

With the default `cache_latents=True`, the rebuilt `DataLoader(drop_last=False)` with `DistributedSampler` discards `EvenSizeBatchSampler` (7 samples, batch 3 -> sizes `[3,3,1]` instead of `[[0,1,2],[3,4,5],[6,0,1]]`). FPS still divides `per_device_train_batch_size` by step time, so the short tail step inflates FPS. Uneven per-rank shards can give ranks different `len(dataloader)` and hang collectives. Keep the even-batch sampler on the cached path.

_An independent check of the code found this probably does not apply: The cache is built from the `EvenSizeBatchSampler` loader, so each rank stores `ceil(shard/B)*B` samples. A CPU probe of the rebuilt `DataLoader` on those samples gave only full batches, e.g. [3,3,3] for n=7, B=3, and equal lengths on all ranks for W=2 and W=4. `DistributedSampler` pads every shard to the same size, so there is no short tail step to inflate FPS and no per-rank length mismatch to hang collectives; the candidate's probe ran the loader on the raw dataset rather than on the cached s…_

**5. 🟠 Should fix: Same epoch-0 padding samples repeat in every epoch: latent cache stores even-batch padding as data**

`_cache_encoded_batches` iterates `self.dataloader`, whose `EvenSizeBatchSampler` pads the tail batch with samples from the front of the rank's epoch-0 shard. Those padding samples are encoded and stored as ordinary cached samples. The epoch length still matches even batching (`ceil(shard/B)*B` samples, all batches full). However, the same repeated samples, fixed at epoch 0, recur in every later epoch instead of being re-drawn per epoch. To restore per-epoch padding, cache the unique samples only and keep `EvenSizeBatchSampler` on the cached loader.

**Who is affected:** AMDB benchmark runs with the default `cache_latents=True` and `dataloader_even_batches=True` whose per-rank shard is not a multiple of the local batch size.
