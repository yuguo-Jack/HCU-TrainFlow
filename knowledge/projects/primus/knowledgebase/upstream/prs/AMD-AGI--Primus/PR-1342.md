# feat(diffusion): Add AMDB SDXL benchmark support

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1342) · state: closed · merged: False

## Original PR description

## Summary

Add **Stable Diffusion XL (SDXL)** support for AMDiffusionBenchmark using the shared benchmark infrastructure and existing Primus diffusion backend.

Since SDXL does not currently have a native model implementation in Primus, this PR introduces the SDXL UNet and supporting model components.

## Changes

### SDXL model implementation
- Add the SDXL UNet architecture and required model components.
- Integrate SDXL with the existing `GenAIModel` interface.
- Use the existing `primus.backends.diffusion.attention` backend for attention operations.
- Reuse `utils/hf_load.py` for Hugging Face checkpoint loading.

### AMDB integration
- Add SDXL support through `AMDBBenchmarkTrainer`, which extends `FSDP2Trainer`.
- Include the shared AMDB dataset and checkpoint download infrastructure.
- Integrate model configuration with `argument_builder.py` and `registry.py`.
- Reuse existing logging, parameter counting, and training utilities.

## Reused Components

- `trainers/base.py`
- `models/interface.py`
- `primus.backends.diffusion.attention`
- `utils/hf_load.py`
- `utils/log.py`
- `utils/train_utils.py`
- Existing diffusion checkpoint preparation infrastructure.

## Validation

- [x] End-to-end AMDB benchmark training.

**17. Cached-latent runs drop even-batch padding and cache duplicates: this PR rebuilds the loader without the sampler** (`primus/backends/diffusion/trainers/benchmark.py:82-95`)

With `cache_latents=True`, the cache is built from the `EvenSizeBatchSampler` loader, so padded duplicates get encoded into it. The loader is then rebuilt as a plain `DataLoader` with no even-batch sampler, which silently discards `dataloader_even_batches`. Epochs then end in short tail batches that FPS still reports at full size: siheyuan's 156 images at batch 20 give a 16-sample step every 8 steps. Cache unique samples only and keep the even-batch sampler when rebuilding the loader.

_An independent check of the code found this probably does not apply: `_cache_encoded_batches` iterates the `EvenSizeBatchSampler` loader, so each rank caches a multiple of `per_device_train_batch_size` samples. Rebuilding with that batch size and real samplers gave only full batches: (156,20,1) cached 160 and gave [20]; (156,12,1) gave [12]; (37,12,2) gave [12]. Padding duplicates are the deliberate Accelerate `even_batches` parity documented in `argument_builder.py`._
