# feat(automodel): rename backend, AutoModel bump, patch-registered hooks, DDP AC repair, profiler

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1314) · state: closed · merged: True

## Original PR description

First of a series; the following PRs build on the patch framework added here.

**What changes**
- The backend #835 added as `nemo_automodel` is renamed `automodel`, after the project it runs:
  `primus/backends/automodel/`, its configs, examples, prepare hook and tests,
  `AutoModelAdapter` / `AutoModelPretrainTrainer`, and `framework: automodel`. Old configs
  (`framework: nemo_automodel`), `--backend nemo_automodel` and imports of the four modules #835
  published keep working, with a deprecation warning. The upstream package keeps its name,
  `nemo_automodel`.
- `--backend` works. On `main` it never did, under any name: the launch line passes it to the
  prepare hook and to `train pretrain`, neither declared it, and argparse took it as an
  abbreviation of `--backend_path`, so the run looked for a checkout named after the backend. The
  train parsers (`primus/core/launcher/parser.py`) now declare `--backend`, and the AutoModel hook
  no longer accepts abbreviated options. The other backends' hooks still do; that is left for a
  separate change.
- `third_party/Automodel` moves to NVIDIA-NeMo/Automodel main (`bd1ca5a0`). That pin requires
  `transformers==5.15.1` and `diffusers>=0.39.0` in the image.
- The prepare hook enforces the pin. It used to keep any importable AutoModel; now it keeps
  one only if it is the commit `primus/_thirdparty.lock` pins and its installed metadata matches,
  and otherwise installs `third_party/Automodel` over it (ROCm packages held), logging every
  package it added, removed or moved. `AUTOMODEL_REINSTALL=0` keeps any copy unless
  `BACKEND_PATH`/`AUTOMODEL_PATH` names one explicitly, and `PRIMUS_SKIP_PIP=1` installs nothing, as in
  the other backends' hooks. A root container over a host-owned checkout no longer fails the
  install on git's ownership check.
- The same constraints hold diffusers below 0.41, which the pin leaves open: diffusers 0.41.0
  imports `torchao.quantization.FqnToConfig` whenever torchao is installed, the image's torchao
  lacks it, and so no diffusers model would load. An installed copy above the cap counts as
  stale and is reinstalled under it.
- On a ROCm torch the hook removes the CUDA-only `nvidia-cutlass-dsl` wheels the install pulls in
  (through `quack-kernels`). The diffusion path never imports them, but torch 2.14's Inductor
  imports `cutlass` whenever it is installed, and its MLIR bindings collide with FlyDSL's, which
  Primus-Turbo loads, so the first compile aborts. The install removes them before it logs the
  version changes, and the hook checks again on every launch, so containers set up before this
  change are repaired too.
- The backend gets a patch package: every `patches/*_patches.py` registers through
  the existing Primus patch framework (`@register_patch`, `PRIMUS_PATCHES`), as the megatron,
  maxtext and megatron_bridge backends already do. Adding a feature means adding a file. The
  trainer runs the patches before it builds the AutoModel config, and model-specific patches apply
  only to their model.
- Settings are config fields: top-level `primus_*` sections of the module config, removed before
  the config reaches AutoModel. No new environment variables. Each patch module declares the keys
  its feature reads, and the trainer warns about any `primus_*` key no module declared, so a typo
  no longer turns a feature off silently.
- `ddp.activation_checkpointing` now takes effect. AutoModel's parser moves it out of `DDPConfig`,
  which is the only place the DDP path reads it; the repair copies it back and is a no-op once
  upstream forwards it. It applies only when the `ddp:` section asks for checkpointing, so FSDP2
  runs do not log it as applied.
- The Wan preset uses the pinned diffusers' registered `flash` attention backend. Its previous
  `aiter` value raises at startup on this pin; there is no automatic fallback.
- `primus_profiler.enabled: true` runs the diffusion train loop under `torch.profiler`, one trace
  per rank under `diffusion_profile/` in the experiment directory. On ROCm 10.1 images
  (`rocm/primus:v26.8`), GPU tracing of FSDP2 runs can hang in rocprofiler-sdk; until an image
  carries the fix (ROCm/rocm-systems#9984 and ROCm/rocm-systems#8564, in ROCm 10.2), set
  `ROCPROFILER_QUEUE_INTERPOSITION=0` for profiled runs.
- The trainer accepts the keyword arguments `main`'s core runtime passes (`module_name=` and the
  rest); #835's `__init__(self, backend_args)` raised `TypeError` on that path.

**Why the bump.** Typed recipe config and the `optimizer:` schema (NVIDIA-NeMo/Automodel#3122),
diffusion context parallelism (NVIDIA-NeMo/Automodel#3157), and per-model `ModelParallelizer`
sidecars (NVIDIA-NeMo/Automodel#4032), which let a model repair subclass upstream's
parallelization instead of replacing it.

**Breaking config schema** (AutoModel rejects the old keys at startup)
| old | new |
|---|---|
| `optim.learning_rate` | `optimizer.lr` |
| `optim.optimizer.*` | `optimizer.*` |
| `step_scheduler.log_every` | `step_scheduler.log_remote_every_steps` |

The in-tree Wan configs are migrated; out-of-tree configs need the same change.

**How to review.** The rename is mostly moves. The old name is resolved from one table,
`primus/backends/backend_aliases.py`, which the config parser, `prepare_experiment.sh` and the
projection CLI read; `primus/backends/nemo_automodel/` keeps the old import paths and registry
name. GitHub shows the moved adapter, trainer, `argument_builder.py` and
`__init__.py` as new files, since their old paths keep the aliases. To see what changed in them:
`git diff origin/main:primus/backends/nemo_automodel/nemo_automodel_adapter.py HEAD:primus/backends/automodel/automodel_adapter.py`,
and likewise for the others. Then start at `patches/__init__.py`, `options.py` and the trainer's
`init()`, then `distributed/ddp_activation_checkpointing.py`, then the prepare hook. Unlike the
other backends, the hook installs from `prepare.py` rather than an `00_install_requirements.sh`,
as #835's already did: enforcing the pin needs the checks in Python.

**Test plan**
- `pytest tests/unit_tests/backends/automodel` — stubbed tests need no AutoModel; contract
  tests run against the pinned AutoModel when it is importable. The example-config smoke test now
  covers the `automodel` experiments; an old-style `framework: nemo_automodel` experiment, the
  old imports and a registry lookup of the old name resolve to the renamed backend, and
  `train pretrain` takes `--backend` as itself.
  Every setting the backend reads is declared, and the shipped configs set no other. The tests
  pass in any order: `main`'s `tests/unit_tests/core/patches` empty the global patch registry
  without restoring it, so the backend's conftest rebuilds it for each test.
- `pytest tests/runner/test_prepare_hooks.py` (not run by CI): the hook does not read `--backend`
  as `--backend_path`.
- Wan and FLUX.1 short training runs through `primus-cli` on 8× MI355X; the profiler writes one
  trace per rank into the experiment directory; `--backend automodel` and
  `--backend nemo_automodel` launches train, the old name with one deprecation warning, and so
  does an old-name config; an old `optim.` key stops the run at startup with AutoModel's
  migration message.. A misspelled `primus_*` key on the launch line gives one warning naming it; the DDP repair applies on the DDP path and not on FSDP2.
- From the unmodified `rocm/primus:v26.8` image: the first launch installs the pin and trains, and
  with an older AutoModel installed first, the hook replaces it and training passes. With
  diffusers 0.41.0 installed first, the hook brings it under the cap and a diffusers model imports.
