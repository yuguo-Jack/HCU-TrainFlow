#  feat(mega_moe): run GPT-OSS on MegaMoE (Turbo bump, expert biases)

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1285) · state: closed · merged: True

## Original PR description

# Description

GPT-OSS-120B could not train with MegaMoE (`use_turbo_mega_moe: true`). The first forward failed with `RuntimeError: All autotune configs failed`, because GPT-OSS's hidden = moe_intermediate = 2880 is not on the MegaMoE kernels' tile grid. Primus-Turbo [#571](https://github.com/AMD-AGI/Primus-Turbo/pull/571) adds that shape to MegaMoE, along with per-expert fc1 / fc2 biases.

This PR:
- **Bumps the CI Primus-Turbo pin** from `de8fa6ca` to `d04ffd9b`. The new pin includes #571 and the FlyDSL dense GEMM race fixes (#570). AITER stays at v0.1.24.post1.
- **Adds expert biases to MegaMoE** (`mega_moe.py`), which used to reject `add_bias_linear`. When it is set, each expert owns an fc1 bias `[E, 2I]` and an fc2 bias `[E, H]`. They are zero-initialised like Megatron's grouped linears, EP-sharded and checkpointed with the weights, and passed to Turbo's stage2 with TEGroupedMLP semantics: the fc1 bias is added before the activation clamp, and the fc2 bias is scaled by the routing weight. Bias-free configs, including today's GPT-OSS and DeepSeek configs, pass `None`.
- **Adds GPT-OSS parity tests** (`test_mega_moe.py`): GPT-OSS-20B / -120B cases (H = I = 2880, EP8, biased experts, swigluoai) in bf16 and mxfp8, checked against Megatron's `MoELayer`, including the bias gradients.

## Performance

**GPT-OSS-120B, 12-layer single-node proxy of `examples/megatron/configs/MI355X/gpt_oss_120B-BF16-pretrain.yaml`**

| arm | ms / iter | vs DeepEP | tokens/s/GPU | memory | loss @1 / @10 |
| --- | ---: | ---: | ---: | ---: | --- |
| alltoall (recipe default) | 7,650 | 0.86× | 34.3K | 211.9 GB | 12.3052 / 11.7573 |
| DeepEP (baseline) | 6,546 | 1.00× | 40.0K | 196.2 GB | 12.3052 / 11.7573 |
| MegaMoE bf16 | 6,114 | **1.07×** | 42.9K | 193.9 GB | 12.3052 / 11.7573 |
| MegaMoE mxfp8 | 5,839 | **1.12×** | 44.9K | 212.8 GB | 12.3052 / 11.7574 |

- **Hardware:** 1 node, 8× MI355X; TP1 / PP1 / EP8; mock data; balanced routing.
- **Shrunk to one node:** only depth and global batch change: 12 of 36 layers, GBS 2048 → 512 (8 micro-batches per rank, the same as at 64 GPUs), and full recompute over the 12 layers.
- **MoE shape unchanged:** 128 experts (16 per rank), top-4, H = I = 2880, mbs 8, seq 4096.
- **Model:** `gpt_oss_120B.yaml` as is (SwiGLU, no biases, 2880 shared expert).
- **Baseline:** the config's own MoE path, Megatron TEGroupedMLP with the alltoall dispatcher.
- **Measurement:** 10 iterations; step time is the median over iterations 4–10. Memory is the max `hip mem usage` over the logged iterations.
- **Stack:** `tasimage/primus:pr-1275` (torch 2.14, FlyDSL 0.3.4.1, AITER v0.1.24.post1), Primus-Turbo `d04ffd9b`.

The loss curves agree at every step. MegaMoE bf16 matches the baseline to the 6th significant digit, and MegaMoE mxfp8 is within 1e-4.

## Validation (MI355X, 8 GPUs, EP8)

- [x] `test_mega_moe` GPT-OSS-20B / -120B cases, bf16 and mxfp8, with Turbo `d04ffd9b`. Cosine similarity against Megatron's `MoELayer` for fwd, dx, dW1, dW2, db1 and db2 is ≥ 0.9997 for bf16 and ≥ 0.995 for mxfp8.
- [x] The 120B proxy above, which is the 1-node reproducer of the `All autotune configs failed` error, now trains with MegaMoE bf16 and mxfp8.

## Not in this PR

File: `primus/backends/megatron/core/extensions/mega_moe.py` · line 204

CI still pins Primus-Turbo to `de8fa6ca` (`.github/workflows/ci.yaml:48`). At that revision, neither `fused_mega_moe_stage2` nor `fused_mega_moe_fp8_stage2` accepts `fc1_bias` or `fc2_bias`. Both calls now pass these keywords unconditionally, so even existing bias-free configurations raise `TypeError` when reaching stage2. Advance the CI pin to the companion GPT-OSS-capable revision as part of this change. If older Turbo versions must remain supported, also omit these keywords in both precision paths when biases are absent.
