## Original PR description

(cherry picked from commit 5a1f509bc2e822d1bc682bc5b83e462926966530)

- GPT-OSS-20B BF16/FP8: align with the tuned MI300X configs (#1329):
  Primus-Turbo grouped GEMM (hipBLASLt backend), Turbo RMSNorm and
  norm+TE linear, DeepEP, sync-free MoE stage 2, gradient accumulation
  fusion, fp32 router, micro batch size 8 -> 4.
- ZAYA1-8B BF16: micro batch size 216 -> 184 and global batch size
  1728 -> 1472 (one micro batch per GPU per step at DP=8) to prevent OOM.

**1. 🟠 Should fix: MI325X GPT-OSS-20B FP8 re-enables delayed-scaling patches that memory-faulted: this PR dropped the guard**

The MI325X `gpt_oss_20B-FP8-pretrain.yaml` is now a verbatim copy of the MI300X config. It silently drops `disable_delayed_scaling_patches: true` (and the explicit `fp8_recipe: delayed`), a guard #900 added for MI325X because the delayed-scaling stream patches hit a GPU memory fault (`sum_and_scatter`) at about iter 6. With `fp8: hybrid` and the `trainer_base.yaml` default `fp8_recipe: delayed`, `_needs_delayed_scaling` now returns True, so `megatron.fp8.delayed_scaling_update` and the prefetch patch are re-enabled on MI325X. The other MI325X FP8 configs (llama3.1/3.3, qwen3_30B_A3B) keep the guard. Either keep `disable_delayed_scaling_patches: true` (or use `fp8_recipe: tensorwise`), or state in the PR that the fault no longer reproduces.

**Who is affected:** Users running the MI325X GPT-OSS-20B FP8 pretrain example.

_Checked against the code by an independent pass._

**2. 🟠 Should fix: MI325X GPT-OSS-20B trains without learned attention sinks: this PR dropped `use_sink_attention: true`**

Both MI325X GPT-OSS-20B configs (BF16 and FP8) drop `use_sink_attention: true` because they are replaced wholesale by copies of the MI300X configs, which never enabled sinks. With the `primus_turbo.yaml` default `use_sink_attention: false`, these examples now train GPT-OSS without learned attention sinks. That is a model change in a perf-tuning PR, and the MI355X 20B configs still enable sinks (window 128). The old MI325X config already had `sink_sliding_window: 0`, so only the sinks themselves are lost. Restore `use_sink_attention: true`, or state that dropping it is intentional for parity with MI300X.

**Who is affected:** Users and the `tools/perf` jobs running `examples/megatron/configs/MI325X/gpt_oss_20B-{BF16,FP8}-pretrain.yaml`.

_Checked against the code by an independent pass._
