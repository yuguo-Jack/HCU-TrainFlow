# fix(megatron): mix the resume iteration into the Flux per-DP-rank seed

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1361) · state: open · merged: False

## Original PR description

Refs #1258

## Summary

`FluxPretrainTrainer.forward_step` reseeds the CPU and CUDA generators with `seed + 100 * dp_rank` on its first call. That overwrites the RNG state restored from the checkpoint, so a resumed run replays the noise and timestep draws of step 0 instead of continuing.

The seeding moves into a shared helper, `primus/backends/megatron/training/diffusion/rng.py::seed_training_rng_per_dp_rank(seed, dp_rank, iteration)`, and the trainer passes `args.iteration` (the step training resumes from):

- A fresh run (`iteration == 0`) keeps `seed + 100 * dp_rank`, so existing loss curves are unchanged.
- A resumed run adds `1_000_003 * iteration`, which is larger than any `100 * dp_rank` offset, so no two (rank, iteration) pairs share a seed.

The opt-in `per_step_rng_reseed` path already derives its seed from a step counter that is rebuilt on resume, so it is unchanged. The WAN trainer in #1132 has the same first-call reseed (`seed_training_rng_per_dp_rank(seed, dp_rank)`) and can call this helper with `args.iteration`; that part of #1258 stays open until it does.

## Testing

- `tests/unit_tests/backends/megatron/diffusion/training/test_training_rng.py` (CPU): a fresh run keeps the old seed, the same inputs give the same draws, a resumed run does not replay the step-0 draws, and seeds do not collide across 256 ranks and several iterations.
- `test_flux_trainer.py::test_resumed_forward_step_does_not_replay_step0_draws` (GPU): the first `forward_step` draws differ between `iteration=0` and `iteration=500`. It fails against main.
- Both files pass in `rocm/primus:v26.8` on MI300X (15 passed).
- Not run: an end-to-end Flux train / save / resume.
