Primer, an agent that onboards models to Primus, generated this change from run `Muse-Spark-Open-816B-A42B-20261025-212640-683e` and verified it on `main` at `dad0a081af43`. It is a draft for maintainer review.

## Scope

This pull request adds Muse Spark Open's **text decoder** (`text_config`, model type `muse_spark_text`): 62 layers, an 816B-total / ~42B-active mixture of experts, text in and text out. The checkpoint converter maps only the text decoder (`model.language_model.*` and `lm_head`).

Muse Spark Open itself is multimodal (text, image, video and audio in; text out). Its other components are **not part of this pull request** and are planned as follow-ups:

- **Vision tower:** a 50-layer ViT with window attention and 2D RoPE, and a 2×2 merge of image patches (images and video).
- **Vision projector:** the adapter and projection that merge image features into the text embeddings.
- **Audio tower:** a 4-stage causal convolution encoder on the raw waveform.

With this pull request, the text decoder trains on text, and fine-tuning starts from the released checkpoint through Primus's checkpoint hook. **Updated (current port):** the vocabulary is padded to 202,048 at every TP, the released router expert-bias correction is kept, and fine-tuning from the converted checkpoint is verified on a 4-layer cut of the released weights (the hook converts it, Megatron loads it, and the first loss is far below a random model's). The full 816B model has no distributed converter: the hook stops with an error that lists the supported routes (convert on a host with about 3.3 TB of RAM by raising `native_ckpt_max_params`, or point `pretrained_checkpoint` at a `torch_dist` checkpoint made elsewhere); see the hook's README section. Image, video and audio inputs need the follow-up above.

**Verified on the current port:** static checks and lint; per-layer and full-model log-prob parity with the Hugging Face reference; training (end to end, proxy, the parallel layouts the plan requires); the checkpoint save/reload round trip; fine-tuning from the checkpoint (4-layer cut); 10-node training; and data-parallel scale-out of the full configuration to 960 GPUs.

**Open review items being worked on:** the launcher's MASTER_PORT probe (stderr captured with the port; ports set outside `--env` not treated as pinned; and whether that generic launcher change belongs in this PR), `remove_partial_checkpoint` deleting the latest-iteration marker of a complete checkpoint, and a fallback in the FLOPs patch that CI never exercises.

- HuangWei-95 · COMMENTED · 2026-10-27T07:56:33Z · [source](https://github.com/AMD-AGI/Primus/pull/1319#pullrequestreview-5663769078)

The model math lines up with HF and reuses upstream Megatron mechanisms well. The main gap is the checkpoint path: a checkpoint produced by this converter can't be loaded by any experiment in this PR, and `train posttrain` can't reach the converter. Performance work hasn't started. Details are inline; summary below.

I agree with Copilot's threads on the [expert key layout](https://github.com/AMD-AGI/Primus/pull/1319#discussion_r4383122626), [hook registration and the `convert()` signature](https://github.com/AMD-AGI/Primus/pull/1319#discussion_r4383122682), [mock-data vocab padding](https://github.com/AMD-AGI/Primus/pull/1319#discussion_r4383122755) and the two BF16 norm-precision issues ([1](https://github.com/AMD-AGI/Primus/pull/1319#discussion_r4383122798), [2](https://github.com/AMD-AGI/Primus/pull/1319#discussion_r4383122832)), and don't repeat them below.

### Blocking

1. **Converted checkpoints don't load.** The single-rank legacy `torch` save can't feed the EP8 or multi-node layouts, and the forced `padded_vocab_size = 202048` doesn't match the tokenizer-padded 201856 even with the real tokenizer. Saving `torch_dist` fixes file layout, expert keys and vocab rows together (inline on `native_loader_muse_spark.py`).
2. **No test covers loading.** None of the experiments sets `load`, and no rung of the verification ladder reloads a converted checkpoint through the trainer, so CI can't catch the above. A reload test at EP > 1 would.
3. **The full-model experiments default to one node** (TP1 / PP1 / EP8), which can't hold the model (inline).

### Important

- **Performance:** every Turbo path and fusion is off, the norms are eager fp32, and there are no throughput numbers. Folding `qk_scale_factor` into `softmax_scale` also keeps Turbo attention off its FlyDSL kernel (inline).
- **FLOPs aren't corrected for sliding-window layers.** 46 of the 62 layers are SWA. Upstream charges `S / 2` keys per query; with W = 2048 a SWA query sees 1536 keys on average at S = 4096 (upstream counts 2048) and 1984 at S = 32k (upstream counts 16384). Reported TFLOP/s is therefore inflated, more so at long context.
- `MuseSparkMoELayer` doesn't receive `pg_collection` (inline).
- The router's base class depends on import order (inline).
- `gating()` reassigns `.data` in forward, and the `preprocess` override drops the CUDA-graph decorator (inline).

### Minor

- **Naming:** `muse_Spark_Open_816B_A42B` (preset, experiments, test) is mixed-case; the proxy preset in this PR and the repo convention are lowercase snake_case.
- **Tests:** three of the four trainer tests build essentially the same model (inline). The L1 / L2 checks live in Primer rather than the repo, so reviewers and CI can't rerun them; a small committed HF-parity unit test would help.
- **Duplication:**
  - `normalize_layer_pattern` in `muse_spark_layer_patterns_patches.py` re-implements the config's `_layer_pattern`.
  - `_is_muse_spark` is defined in two patch files.
  - `muse_spark_te_gemm_workspace_patches.py` copies `megatron.glm5_next.te_gemm_workspace`; one shared patch with a model list would do.
- **Dead code:**
  - `FP32_SUFFIXES` (`native_loader_muse_spark.py` L46) is unused, and `del offset` (`muse_spark_layer_specs.py` L114) is dead.
  - `native_loader_muse_spark_text.py` isn't referenced anywhere.
  - The patches accept model_type `muse_spark_text`, but `import_utils` doesn't.
- **Gated tokenizer:** the `muse_spark_base` experiment uses `HuggingFaceTokenizer` with `meta-models/Muse-Spark-Open-816B-A42B`, so it needs the gated repo even with mock data. The ungated `amd/Muse-Spark-Open-816B-A42B-Quark-PTPC-FP8` ships byte-identical `tokenizer.json`, `tokenizer_config.json` and `special_tokens_map.json`.
- **Logging:** `stderr_sink_level: DEBUG` in every experiment makes the logs noisy.
- **Duplicate configs:** the MI300X and MI355X experiments are identical apart from the header comment.

### What's good

- **The math matches HF:**
  - gated residuals;
  - the input-scaled and zero-centered norms, including the post-norm eps;
  - o_norm, the weightless QK norm and the embedding norm;
  - the softcap;
  - the scaled sigmoid router;
  - the post-expert norm applied before the routing weight.

  The hyperparameters match too: window 2048 (2047 for TE), a global layer every 4 layers, the scale factors, the vocab and the bias update rate.
