# feat(automodel): context parallelism for Ideogram-4

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1327) · state: closed · merged: True

## Original PR description

Part 4 of 4 of the Ideogram-4 work, stacked on 4c (#1326). The diff here shows only this commit. Once 4a–4d are reviewed, this PR is squash-merged into its base, and Ideogram-4 goes to `main` as 4a (#1324).

**What changes**
- Ulysses context parallelism (`fsdp.cp_size` above 1) for Ideogram-4, by attaching the one thing it was missing: a diffusers context-parallel plan. The mesh, gradient synchronization over the CP axis, the per-rank reseed and the loss correction already exist upstream.
- The model is single-stream, so hidden states, encoder features and the indicator split together at the root. `segment_ids` stay whole, because the root builds the full-length mask from them, and the rotary outputs are split instead of `position_ids`.
- diffusers splits the sequence into equal parts, so once CP is on the adapter left-pads the packed batch to a multiple of the CP degree. The added columns are padding and the image tokens stay at the tail.
- Two configurations are refused, because both would train silently wrong: the var-len processor, which bypasses the dispatch where the all-to-all lives, and a per-token timestep.

The plan is inert until a config asks for a degree above one. The degree must divide both the world size and the head count, and CP is FSDP2-only upstream. If diffusers ships its own plan, that one is kept, with a warning, and the refusals and the padding still apply. The CP degree is kept on each model instance.

**Breaking:** none.

**How to review.** `models/ideogram4/context_parallel.py`; its module docstring goes through the plan entry by entry.

**Test plan**
- Unit tests: the plan's entries, the refusals, the padding, the per-instance degree and hook, and that the forward is never wrapped. The guard and padding tests need no diffusers, so they run in CI.
- On MI355X: CP=2 output matching CP=1, a CP run that trains, training on a ragged batch that needs padding, and CP with var-len refused.

<summary><strong>What changed in this PR</strong></summary>

This PR adds context parallelism (CP) for the Ideogram-4 model. CP splits the token sequence across GPUs (Ulysses style) so longer sequences fit. The model has no CP plan, which is why it cannot use CP today. The change attaches that plan, pads the packed batch so it divides evenly by the CP degree, and refuses two setups that would train wrong without raising an error. With the default CP degree of 1, nothing changes.

**Changes:**
- Attaches a diffusers CP plan to Ideogram-4 that splits the per-token inputs and the rotary outputs, and gathers the result at the final layer.
- Left-pads the packed batch to a multiple of the CP degree, and refuses CP with the variable-length attention path and with per-token timesteps.
- Adds unit tests for the plan, the guards and the padding, plus config comments and README notes on the constraints.
