# feat(automodel): Ideogram-4 training with var-len attention, an encoded cache, ZeRO-1 and context parallelism

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1324) · state: closed · merged: True

## Original PR description

Fourth PR of the series that started with #1314. It adds Ideogram-4 text-to-image pretraining to the AutoModel backend. The work was reviewed in four parts, this PR and #1325–#1327, and the other three have been squash-merged into this one, so Ideogram-4 reaches `main` as a single commit. Each part's review is on its own PR.

**What changes**
- **Training on synthetic data.** Ideogram-4 pretraining on the AutoModel diffusion path, runnable end to end on synthetic features with no gated weights. A synthetic dataset, model and module presets, example experiments, README and support-matrix entries, and `tools/automodel/make_ideogram4_config_dir.py`, which writes a weightless transformer config directory, since pretraining initialises randomly.
- **Var-len attention** (`primus_ideogram4.varlen_attention`, off by default). A var-len flash path that replaces the model's dense block-diagonal mask, which otherwise forces SDPA at the full quadratic cost. The packing is built on the host from the caption lengths, so it needs no device-to-host reads, and its shape is fixed, so it never forces a recompile.
- **Activation checkpointing.** Whole-block checkpointing for Ideogram-4 on the FSDP2 and DDP paths; the default parallelizer wraps only each block's attention and feed-forward. `primus_ideogram4.ac_every: n` checkpoints every nth block.
- **Encoded cache** (#1325). An offline builder that encodes images and captions once, a dataloader that reads the result, and a CLI that runs the builder: `primus-cli direct --single -- data automodel-cache --model ideogram4`. The dataloader emits the same batch contract as the synthetic one, so a config swaps one for the other. Cached captions are never truncated, over-length captions are dropped before encoding and counted in `metadata.json`, and `metadata.json` is written last and atomically, so an interrupted build is never read as complete. Building a cache needs the encoder weights: the text encoder is public, while the autoencoder's repository is gated on Hugging Face. Training reads only the cache.
- **ZeRO-1 on the DDP path** (#1326, `primus_ideogram4.zero1`). A DDP preset with the AdamW state optionally sharded across the data-parallel ranks. Where ZeRO-1 does not apply (parameters already sharded, a single rank) it warns and keeps the plain optimizer; a construction failure raises. The optimizer patch applies only to runs that train Ideogram-4.
- **Context parallelism** (#1327, `fsdp.cp_size` above 1). Ulysses context parallelism, by attaching the one thing Ideogram-4 was missing: a diffusers context-parallel plan. The mesh, gradient synchronization over the CP axis, the per-rank reseed and the loss correction already exist upstream. Once CP is on, the adapter left-pads the packed batch to a multiple of the CP degree, since diffusers splits the sequence into equal parts.

**Known limitations**
- The var-len path is non-deterministic, because a deterministic var-len backward is impractical at these lengths. It raises under `torch.use_deterministic_algorithms(True)` and warns once with `warn_only=True`. It calls its own kernel, so the `primus_turbo` attention settings do not apply to it, and it warns if they are set.
- Caption dropout (`cfg_dropout_prob` above 0) is refused: guidance at inference uses a separate unconditional transformer, so the conditional one is never run without text.
- A ZeRO-1 run cannot save or resume. AutoModel saves the optimizer through `state_dict()`, which `ZeroRedundancyOptimizer` refuses until consolidated, so ZeRO-1 raises unless `checkpoint.enabled` is false; the DDP experiments set it to false. ZeRO-1 is aimed at multi-node runs and is tested on a single node only.
- Context parallelism is FSDP2-only upstream, and its degree must divide both the world size and the head count. It is refused with the var-len processor, which bypasses the dispatch where the all-to-all lives, and with a per-token timestep, since both would train silently wrong.

**Breaking:** none. Everything is new, lives under the AutoModel backend, and applies only to runs that configure Ideogram-4. The existing `diffusion-*` data commands are unchanged; the new one is a sibling.

**How to review.** Under `primus/backends/automodel/models/ideogram4/`: `adapter.py` and `attn_processor.py`, then `cu_seqlens.py` and `packing_buffer.py` (the packing and how it reaches the attention modules), then `parallelize.py`; `data/cache.py` and `data/build.py`, with the registry and CLI in `primus/backends/automodel/data/`; `zero1.py`; and `context_parallel.py`, whose module docstring goes through the plan entry by entry.

**Test plan**
- Unit tests: host-built against mask-derived packing over fixed and randomized shapes, processor path selection, deterministic mode, the shared packing buffer, the velocity sign and publish order, and the settings; the whole-block sidecar against stubs and, when AutoModel is importable, the real parallelizer on CPU; the cache loader's batch contract, the no-truncation refusals, index validation, a full build read back by the loader and a rebuild that leaves no stale index; the ZeRO-1 optimizer patch over a stubbed and the real optimizer-config hierarchy, its warn-versus-raise cases and checkpoint refusal, and a real `ZeroRedundancyOptimizer` on two CPU ranks; the context-parallel plan, its refusals and the padding. Only the numerical comparison of the var-len path against masked SDPA, forward and gradients, needs a GPU.
- On MI355X: the synthetic experiment end to end, with whole-block AC, AC off and a block stride; a small cache built with the default encoders, the cache experiment on it, and a smaller rebuild into the same directory; the DDP experiments with and without ZeRO-1 on synthetic and cached data; CP=2 output matching CP=1, a CP run that trains, and training on a ragged batch that needs padding.
