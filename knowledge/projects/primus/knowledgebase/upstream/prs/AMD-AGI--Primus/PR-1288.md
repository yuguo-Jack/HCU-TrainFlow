# feat(examples): add MI455X Llama-3.1-8B pretraining example (Megatron)

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1288) · state: closed · merged: True

## Original PR description

## Summary
Adds a Llama-3.1-8B pretraining example for MI455X (gfx1250), laid out like the DeepSeek-V3 example:
- `examples/megatron/configs/MI455X/llama3.1_8B-BF16-pretrain.yaml`: full model, seq 8192, BF16, mock
  data, no recompute; Primus-Turbo attention (FlyDSL) and RMSNorm.
- `examples/megatron/models/llama3.1-8b/run_llama3.1_8b_mi455x.sh`: runs from the host (new container,
  the default) or inside a container (`PRIMUS_LAUNCHER=direct`).
  - `TURBO_DIR` points at a Primus-Turbo checkout.
  - The Triton gfx1250 expert-scheduling fix is applied.
  - `PRIMUS_MAX_POSITION_EMBEDDINGS` follows `PRIMUS_SEQ_LENGTH`.
  - With the flydsl backend, the launcher stops before training if the Primus-Turbo in use has no gfx1250
    head-dim-128 kernels.
- `README.md`: how to run, reference numbers, attention backend and determinism notes.

## Dependency
Needs a Primus-Turbo with the gfx1250 head-dim-128 FlyDSL attention: Primus-Turbo PR #574
(`dev/lhz/llama31_8b_opt` -> `dev/mi455x_v2`). The README pins the measured commit 62a3fcca. With the
image's own Primus-Turbo, the launcher stops with a message.

## Results
MI455X, `amdprimus/amdprimus:tas-20261019`, Primus-Turbo 62a3fcca, no hipBLASLt tuning, MBS 4, seq 8192
(32,768 tokens per GPU per iteration), average of iterations 3-10. 4 GPUs: the launcher's defaults (DP4,
GBS 16, distributed optimizer), started from the host. 1 GPU: GBS 4. Peak memory is Primus's
`hip mem usage` (GiB). Speedup is against Primus-Turbo Triton attention at the same GPU count.

| GPUs | Attention | ms/iter | Speedup | Tokens/s/GPU | TFLOP/s/GPU | Peak mem/GPU | loss @ iter 10 |
|---|---|---|---|---|---|---|---|
| 4 | Primus-Turbo Triton (baseline) | 1971 | 1.00x | 16,600 | 856 | 276.08 GiB | 8.973 |
| 4 | **Primus-Turbo FlyDSL (default)** | **1113** | **1.77x** | **29,400** | **1515** | 276.08 GiB | 8.972-8.975 |
| 1 | Primus-Turbo Triton (baseline) | 1924 | 1.00x | 17,000 | 876 | 344.99 GiB | 10.191 |
| 1 | **Primus-Turbo FlyDSL (default)** | **1084** | **1.77x** | **30,200** | **1556** | 344.75 GiB | 10.190-10.191 |

TE's unfused attention (`USE_TURBO_ATTENTION=False`) is slower than Triton: without recompute it runs out
of memory in the first iteration, and with `--recompute_granularity selective` it takes 5037 ms/iter on
4 GPUs (5027 on 1 GPU).

On 4 GPUs an iteration takes 2.7% longer than on 1 GPU (data-parallel communication not fully hidden), and
peak memory per GPU is 69 GiB lower (distributed optimizer sharding). The loss differs from 1 GPU because
the global batch does (16 vs 4).

## Test
- 4 GPUs from the host: FlyDSL twice, Triton, TE with selective recompute, TE without recompute (out of
  memory, as expected).
- 1 GPU from the host: 1083 ms/iter, the same as inside a container.
- 1 GPU with `PRIMUS_SEQ_LENGTH=16384 MBS=2`: trains, 1231 ms/iter.
- Launcher pre-check, in a container without GPUs: it stops when no gfx1250 kernels are available and
  passes with `TURBO_DIR` set, with `triton`, or with `USE_TURBO_ATTENTION=False`.
- No amdgpu dmesg errors in any run.
