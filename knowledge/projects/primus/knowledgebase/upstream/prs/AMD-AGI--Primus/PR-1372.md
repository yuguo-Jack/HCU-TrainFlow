# perf(megatron): join MoE router and expert input gradients

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1372) · state: open · merged: False

## Original PR description

# Description

The MoE input feeds both the FP32 router and the experts. With `moe_router_bwd_bf16` (#1240), autograd runs the router dX GEMM, rounds it to BF16, and adds it to the expert input gradient. The new opt-in `moe_router_grad_merge` defers the router dX GEMM to an identity autograd join on the MoE input. The join then computes `bf16(dY @ W) + expert_grad` in one Triton kernel with the same two roundings, which removes one GEMM output write, one read and the separate add per MoE layer.

- `primus/backends/megatron/core/extensions/router_grad_merge.py`: the kernel, the join, the guards and `install()`.
- `router_bwd_bf16_patches.py`: patch `megatron.moe.router_grad_merge` (priority 60, after the BF16 router backward). It raises if `moe_router_bwd_bf16` is off.
- `fused_residual_rmsnorm.py`: the fused residual/RMSNorm layer forward opens the join around `layer.mlp(...)`. Its normalized activation is consumed by the MLP alone; the residual stream, including the V2 carry, stays outside.
- `language_model.yaml`: `moe_router_grad_merge: false`.

The join applies only in training with grad enabled and an FP32 router with 16/32/64/128 experts. It is skipped for shared experts, recompute or offload of the MLP or its norm, CUDA graphs, chunked MLP, padding masks, input jitter, latent MoE, forced load balancing, replaced `MoELayer`/router methods, and hooks other than DDP's parameter all-gather pre-hook. Every other call runs Megatron's path unchanged. On each rank, the first 48 fused joins are compared bitwise with the unfused GEMM-plus-add; a mismatch logs a warning and disables the join for the run.

This ports Su Ann Chong's `suachong/mpo` commit 472e72253, written against Megatron-LM d3528a21, to `main` (Megatron-LM core_v0.19.2):

- GPT-OSS constants (`(8192, 4, 2880)` input, `(32, 2880)` router weight) are replaced by the model config.
- The sha256 pins of seven upstream source files are replaced by method-identity checks; installation is skipped (with a log line) if another patch already replaced a wrapped method.
- `TransformerLayer._forward_mlp`, whose signature changed in v0.19.2, is no longer wrapped; only the fused residual/RMSNorm forward opens the join.
- DDP pre-hooks are recognized by the marker of the fused QK RMSNorm/RoPE patch (`megatron.turbo.qk_rmsnorm_rope`).
- A kernel mismatch disables the join instead of raising.

In the GPT-OSS-20B MLPerf 6.1 tracking deck, this join together with the DEOSC state alignment (#1371) takes the MXFP4 recipe from 56.49 to 56.11 min TTT (67.88 → 68.33 samples/s) on 8× MI355X.
