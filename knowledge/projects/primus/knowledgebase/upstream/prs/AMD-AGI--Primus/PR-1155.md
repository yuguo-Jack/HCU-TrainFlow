# examples(megatron): add gfx1250 native LoRA SFT recipes

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1155) · state: closed · merged: True

## Original PR description

### Summary
Adds proxy 1-GPU native Megatron SFT + LoRA recipes for MI455X and a gfx1250 runbook. Training goes through `train posttrain` + `sft_trainer.yaml` (native Megatron SFT trainer), not Megatron-Bridge.

These configs exist because `examples/megatron/configs/MI355X` already has native LoRA-SFT recipes (e.g. Llama-3.1-8B) but there was no MI455X / gfx1250 counterpart for B0 enablement.

### Hardware gate
**Required architecture: `gfx1250` (MI455X B0).**

| Item | Value |
|---|---|
| ISA | `gfx1250` (`rocminfo` / `torch.cuda.get_device_properties(0).gcnArchName`) |
| Product | MI455X (B0) |
| GPUs | 1 (`HIP_VISIBLE_DEVICES=0`, `NNODES=1`, `GPUS_PER_NODE=1`) |
| Env | `PRIMUS_GPU_MODEL=MI455X` (or auto-detect via `runner/helpers/envs/primus-env.sh`) |
| Image | `amdprimus/amdprimus:gfx1250-20260831` |
| Attention | `PRIMUS_TURBO_ATTN_BACKEND=triton` (no aiter on this image) |

Do **not** validate or merge on gfx942 / gfx950 / MI300X / MI355X. Default Primus-CI GPU runners are not this arch and are not a substitute.

A passing run must print:

```
Detected GPU model: MI455X
Loading MI455X (gfx1250) specific settings...
```

If ISA is not `gfx1250`, stop. Do not `source runner/helpers/envs/MI455X.sh` by itself (`LOG_INFO_RANK0` lives in `base_env.sh`).

### Change
**Configs** (`examples/megatron/configs/MI455X/`):

| File | What it is | Weights |
|---|---|---|
| `llama3.2_1B-BF16-lora-sft.yaml` | Full Llama-3.2-1B LoRA SFT | Converts gated HF (`meta-llama/Llama-3.2-1B`) |
| `llama2_70B-BF16-lora-sft-1gpu-proxy.yaml` | Llama-2-70B shape, **4 of 80 layers** | Random init, no 70B download |
| `qwen2.5_72B-BF16-lora-sft-1gpu-proxy.yaml` | Qwen2.5-72B shape, **4 of 80 layers** | Random init, no 72B download |
| `qwen3_235B_A22B-BF16-lora-sft-1gpu-proxy.yaml` | Qwen3-235B-A22B MoE shape, **4 of 94 layers** | Random init, no 235B download |

Shared overrides: `TP=PP=CP=EP=1`, `bf16: true`, `gradient_accumulation_fusion: false` (no apex fused MLP in the gfx1250 image), wandb/tensorboard off, LoRA `dim=16` / `alpha=32`.

Qwen3 MoE: `use_turbo_deepep: false`; LoRA is **attention-only** (`linear_qkv` / `linear_proj`). Expert `linear_fc1` / `linear_fc2` are `PrimusTurboColumnParallelGroupedLinear` and cannot be LoRA-wrapped.

- Index / Sphinx links in `docs/README.md`, `docs/04-technical-guides/README.md`, `docs/04-technical-guides/native-sft-lora.md`, `docs/02-user-guide/posttraining.md`, `docs/sphinx/_toc.yml.in`

```bash
  --env HIP_VISIBLE_DEVICES=0 --env NNODES=1 --env GPUS_PER_NODE=1 \
  --env PRIMUS_GPU_MODEL=MI455X \
  --env PRIMUS_TURBO_ATTN_BACKEND=triton \
  -- train posttrain \
  --config examples/megatron/configs/MI455X/<config>.yaml
```

### 🟡 Strong Suggestions

#### `examples/megatron/configs/MI455X/qwen3_235B_A22B-BF16-lora-sft-1gpu-proxy.yaml:44-54` — Define tokenizer and model architecture parameters only in the canonical model-specific config YAML (e.g. primus/configs/models/megatron/Llama3_70B.yaml); keep base model configs generic and do not set these parameters in base YAMLs or example/experiment YAMLs.
> The new example/experiment YAMLs set tokenizer parameters (tokenizer_type/tokenizer_model) and model-architecture parameters (num_layers, num_experts, moe_router_topk, moe_layer_freq) directly in the example overrides instead of in a canonical model-specific config YAML.

**Why this matters:** Base configs are inherited by many model variants and example/experiment YAMLs are meant to compose reusable model configs. Placing tokenizer/model-architecture parameters in the base or example layer leaks model-specific values into generic files, causes silent misconfiguration across derived models, and prevents proper factoring of shared config. Reviewers require these parameters to live in the canonical model-specific YAML so each model has a single authoritative definition.

**Problematic code:**
```
overrides:
     stage: sft

     tokenizer_type: HuggingFaceTokenizer
     tokenizer_model: Qwen/Qwen3-0.6B

     num_layers: 4
     moe_layer_freq: 1
     num_experts: 128
     moe_router_topk: 8
```

**Hint:** Create model-specific YAMLs under primus/configs/models/megatron/ (e.g. a 4-layer proxy variant derived from qwen3_235B_A22B.yaml / llama2_70B.yaml / qwen2.5_72B.yaml / llama3.2_1B.yaml) that define the tokenizer and architecture params, and reference them via `model:` from the example configs.
