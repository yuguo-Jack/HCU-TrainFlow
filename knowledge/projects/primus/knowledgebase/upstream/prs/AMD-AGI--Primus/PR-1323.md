# feat(automodel): Primus-Turbo attention overrides and FP8/MXFP4 linear swaps

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1323) · state: closed · merged: True

## Original PR description

Third PR of the series that started with #1314; it builds on #1322 (now merged), which added the FLUX and Wan training paths.

**What changes** — all opt-in, all off by default, set in the `primus_turbo:` / `primus_te:`
config sections (each patch module declares its keys), no config files:
- `primus_turbo.fp8_attention`: FP8 flash attention through Primus-Turbo.
- `primus_turbo.nondeterministic_attention`: bf16 flash attention with the atomic
  (non-deterministic) backward.
- `primus_turbo.fp8_linear`, `primus_turbo.mxfp4_linear`, `primus_te.mxfp4_linear`: swap
  `nn.Linear` for Primus-Turbo FP8, Primus-Turbo MXFP4 (experimental), or TransformerEngine MXFP4.
  A precedence registry picks one when several are requested and logs which request lost. A swap
  turns on `model.transformer_engine_linear`, the AutoModel setting that performs it. The TransformerEngine MXFP4 swap converts only the Linears inside the transformer blocks, where its autocast is entered; Linears outside them stay in bf16 and are counted in the log.

Each override rebinds the diffusers attention backend or swaps modules before the model is built;
no diffusers or AutoModel source is edited, and any call an override does not handle falls through
to the original kernel. The attention overrides run only behind `model.attention_backend: flash`
or `aiter`; with another backend they warn, and the first call actually served is logged.
FP8 attention pads queries to the kernel multiple but never pads keys, because zero keys would
change softmax; a non-multiple key length falls back, and so does a causal call whose query length is not a multiple, since padding would move the causal diagonal. The FP8 linear swap applies AutoModel's
shape/FLUX predicate and additionally keeps Wan's five `condition_embedder.*` linears in bf16.

**Breaking:** none.

**How to review.** `attention/_backend_registry.py` and `quantization/_common.py` hold the shared
logic; each feature is then one module plus its patch.

**Test plan**
- Unit tests (fake registry and selectors; most need no torch).
- On MI355X: attention numerics against the replaced kernel, and each linear swap on real modules.

File: `primus/backends/automodel/attention/fp8.py` · line None

🔴 Blocking **[PR Pundit]**

flash_attn_fp8_pad64 zero-pads the query sequence to a multiple of 64 and the docstring and test comment call this exact ('each query row is independent'). That is true only for non-causal calls. Padding happens only when Sq % 64 != 0 and Skv % 64 == 0, so Sq != Skv. Primus-Turbo's Triton kernel, like flash-attn, aligns the causal mask bottom-right: query row m may see key j only if m >= j + (Sq - Skv). Padding Sq to Sq_pad moves the diagonal, so every real query row loses its last (Sq_pad - Sq) allowed keys. The output is wrong and there is no warning. unaligned_keys does not screen is_causal. Causal calls with unaligned Sq must fall back (add them to unaligned_keys), or padding should happen only when causal is False, or at the front.

**Evidence (verified by running it):** Ran a CPU simulation (/tmp/causal.py) with Sq=100, Skv=128 and a bottom-right causal mask. Padded queries vs reference: max abs diff 2.46 when causal, 0.0 when non-causal. The kernel forwards causal=is_causal unconditionally.
