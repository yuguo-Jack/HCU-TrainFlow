# fix(megatron_bridge): prefer rope_parameters over default_theta when resolving rope_theta

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1297) · state: closed · merged: True

## Original PR description

Fixes #1193

## Summary

With transformers 5.x, `resolve_rope_theta()` returned `config.default_theta` first. That is the class default (10000 for Qwen3), not the checkpoint value, so `rope_parameters["rope_theta"]` (1e6 for Qwen3) was never read and Megatron-Bridge models were silently built with the wrong RoPE base.

`resolve_rope_theta()` now reads `rope_parameters["rope_theta"]` (dict or object) first and only falls back to `default_theta`. transformers 4.x configs, which expose `rope_theta` directly, are not affected.

## Testing

- New cases in `tests/unit_tests/backends/megatron_bridge/test_rope_config.py` cover `rope_parameters` as an object, `rope_parameters` (dict and object) taking precedence over `default_theta`, the `default_theta` fallback, and `Qwen3Config(...).rope_theta` read through the installed shim. The precedence and shim cases fail against main. `pytest tests/unit_tests/backends/megatron_bridge/`: 35 passed in `rocm/primus:v26.8` (transformers 5.10).
- Qwen3-0.6B LoRA SFT on SQuAD, 8x MI300X, `rocm/primus:v26.8`, 20 iterations: the effective `rotary_base` is `10000` without the fix and `1000000` with it.
- The wrong base barely changes the loss on short SQuAD samples (0.43 at iteration 20 either way), so the ~12.4 loss reported in #1193 was not reproduced. On 4096-token sequences, a HuggingFace reference loss with base 1e6 vs 1e4 is 3.11 vs 3.49 for Qwen3-0.6B and 2.04 vs 2.40 for Qwen3-30B-A3B.

<details><summary>Nits and less certain findings (3)</summary>

**1. Nested per-layer-type `rope_parameters` silently fall back to class default theta** (`primus/backends/megatron_bridge/utils/rope_config.py:23-34`)

`resolve_rope_theta` reads only a flat `rope_parameters['rope_theta']`. Under transformers 5.x, configs with per-layer-type RoPE such as `Gemma3TextConfig` and ModernBERT store nested `rope_parameters` (`{'full_attention': {...}, 'sliding_attention': {...}}`) and a dict `default_theta`. For those configs the function falls through and returns the dict `default_theta` (e.g. `{'global': 1e6, 'local': 1e4}`), not a float. The base code returned the same dict because it checked `default_theta` first, so this PR does not change that case. A follow-up could handle nested dicts (prefer `full_attention`) or raise.

**Origin:** pre-existing

**Who is affected:** Users converting or training Gemma3/ModernBERT-style models through Megatron-Bridge with transformers 5.x, if the bridge reads `hf_config.rope_theta` for them.

_Checked against the code by an independent pass._

**2. Fixed precedence untested through the real `__getattribute__` shim** (`tests/unit_tests/backends/megatron_bridge/test_rope_config.py:61-71`)

The new precedence tests call `resolve_rope_theta` only on `Mock`s. The single end-to-end test of `install_transformers_rope_theta_shim` still sets only `default_theta`. No test reads `cfg.rope_theta` through the shim on a `PretrainedConfig` whose `rope_parameters['rope_theta']` differs from `default_theta`, which is the case this PR fixes. Consider adding one so a regression in the shim path is caught. The behaviour itself is correct today.

**Who is affected:** Maintainers only: a future regression in the shim path for transformers 5.x configs would not be caught by tests; runtime behaviour is correct.

_Checked against the code by an independent pass._

**3. Duplicate dict/SimpleNamespace test cases instead of parametrization** (`tests/unit_tests/backends/megatron_bridge/test_rope_config.py:37`)

`test_rope_parameters_dict_wins_over_default_theta` and `test_rope_parameters_object_wins_over_default_theta` are identical except for whether `rope_parameters` is a dict or a `SimpleNamespace`. They could be one test parametrized over the container type. The new `test_rope_parameters_object` largely mirrors the existing `test_rope_parameters_dict` and could be folded into the same parametrization. Note that `test_rope_parameters_dict` also sets `default_theta = None`, so those two are not exact copies. This is a style point only; the coverage itself is valid.

**Who is affected:** Only maintainers of the unit test file; there is no runtime impact.

_Checked against the code by an independent pass._
