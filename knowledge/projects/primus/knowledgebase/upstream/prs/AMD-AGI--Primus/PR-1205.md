### Strong suggestions

🟡 **Loss curve or convergence check before/after the upcycling conversion (e.g., dense baseline loss vs. hybrid-initialized model loss over a short run)**
> The tool produces the initial weights a training job starts from, so it directly affects training outputs. The diff only documents a 1-iteration mock-data smoke run (train_iters: 1), which proves the checkpoint loads but shows no loss/convergence trajectory demonstrating the upcycled hybrid model starts from a sane state relative to the dense source.
> *Rule: Loss curve or convergence check before/after*
> *Source: repo evidence requirement*

🟡 **Correctness test on a small model run, ideally reproducible/automated (e.g., a tiny Zebra hybrid config converted and trained for a handful of steps, with asserted expectations, or a unit test over the dense→hybrid tensor name/shape mapping)**
> Evidence is limited to a manually-documented one-GPU smoke run described in upcycling-changes.md plus an upcycle_report.json artifact; there is no committed test that exercises the conversion logic (layer-type routing for attention vs. Mamba/GDN/KDA blocks, parameter renaming, shape/dtype handling, sharded/distributed checkpoint handling) so regressions in the mapping would not be caught automatically.
> *Rule: Correctness test on a small model run*
> *Source: repo evidence requirement*

🟡 **Explicit statement of whether upcycled outputs are numerically equivalent to the dense source (i.e., which tensors are copied bit-exactly, which hybrid-only parameters are freshly initialized, and that any divergence is intentional)**
> Upcycling intentionally changes model structure, so reviewers need a clear equivalence/divergence statement: confirmation that carried-over attention/MLP/embedding weights are unchanged (e.g., allclose or checksum on matched tensors) and that unmatched entries in upcycle_report.json are expected new Mamba/GDN/KDA state rather than silent drops.
> *Rule: Statement of whether outputs are numerically equivalent or intentionally changed*
> *Source: repo evidence requirement*

### Advisory

🔵 **Negative/edge-case verification for the conversion tool (unsupported layer pattern, mismatched hybrid layer spec, missing tensors) asserting the tool fails loudly rather than emitting a partially populated checkpoint**
> The report of matched/unmatched tensors is informational only; without a check that unmatched required tensors cause an error, a misconfigured hybrid pattern could yield a randomly-initialized model that trains silently to poor quality.
> *Source: repo evidence requirement*
