# fix(hybrid): read the FLA switches without requiring Megatron-LM args

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1290) · state: closed · merged: True

## Original PR description

Megatron-Bridge builds and trains models without initializing Megatron-LM's global args. Four places in the hybrid model code read FLA switches through `megatron.training.get_args()` without a guard, so `zebra_mamba_1B_hybrid_sft_posttrain.yaml` stopped with `AssertionError: args is not initialized` while building the model: the `FLAFlashAttention` start-up banner, `HybridStack`, `GatedDeltaNet` and `KimiDeltaAttention`.

`get_megatron_arg(name, default)` in `primus/backends/megatron/core/utils.py` returns the default when those args are not set up, and the four call sites use it. `fla_flash_attention.is_enabled()` already guarded its read and now goes through the same helper. Under Megatron-LM nothing changes. Under Bridge the switches keep their defaults: the FLA kernels stay off, and MLA still moves to the direct flash-attn path on its own when the installed flash-attn is newer than Transformer Engine supports. The hybrid-models README says so.

## Validation

8x MI300X, the 2026-10-22 Primus CI image (Primus 4321af16) with this diff applied.

- Unit tests: `test_get_megatron_arg.py` (new), `test_fla_flash_attention.py`, `test_gdn_rocm_gate_patches.py` and `test_fla_kda_autotune_patches.py`: 61 passed.
- Bridge SFT, `zebra_mamba_1B_hybrid_sft_posttrain.yaml`: the model now builds (1,574,787,712 parameters). The run then stops at data setup, for a separate reason: the Zebra finetune recipe loads SQuAD as `squad`, which `huggingface_hub` 1.33 rejects (`Repository id must be 'namespace/name'`), and the `dataset: mock: true` in the Zebra Bridge model configs is not used by the finetune recipe. With `dataset_name: "rajpurkar/squad"`, as the other Bridge model configs set, the run completes all 200 iterations.
- Megatron-LM, same image without and with this diff: `zebra_llama_gdn_300M_BF16` and `zebra_llama_mamba_300M_BF16` still report `reason=args.fla_mla_attn='1'`, with iteration-1 loss 11.96999 vs 11.96996 and 11.96300 vs 11.96298. `zebra_llama_kda_1B_BF16` matches over its 50 iterations (final loss 0.1615068 vs 0.1615033).
