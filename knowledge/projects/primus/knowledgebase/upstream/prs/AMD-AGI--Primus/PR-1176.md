# fix(megatron): QK-Norm on MLA decoupled-RoPE to stop hybrid divergence

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1176) · state: open · merged: False

## Original PR description

## What

Adds a **parameter-free QK-Norm** (unit-RMS `RMSNorm`) on the **decoupled-RoPE** q/k of Multi-Latent Attention, applied before `apply_rotary_pos_emb`.

## Why

In MLA the q/k are split into a **content** part (`qk_head_dim`) and a **decoupled-RoPE** part (`qk_pos_emb_head_dim`). The content part is normalized (`q_layernorm`/`kv_layernorm` on the compressed latents), but the **rotary part is never normalized** — it is projected, split off, and fed straight into `apply_rotary_pos_emb`.

In a KDA/MLA hybrid this is a divergence mechanism: the rotary component's magnitude grows with training until it dominates the per-head attention logits and blows up the deep residual stream. `qk_clip` (MuonClip) does **not** catch it — `qk_clip` rescales the per-head weights (content q/k and the rotary q rows), but the rotary key `k_pos_emb` comes straight out of `linear_kv_down_proj`, is shared by all heads, and is never rescaled or normalized, so the rotary logit term grows through it and the logits climb past any threshold.

Observed in a 3B KDA-RoPE hybrid: with `qk_clip` active and its threshold holding the *clipped* logit, training still diverged; per-layer instrumentation showed the deepest residual layers exploding together while the raw attention logits shot well past the clip threshold — i.e. the runaway came through the rotary path.

## Fix

Normalize `q_pos_emb` and `k_pos_emb` to **unit RMS** over `qk_pos_emb_head_dim` before RoPE. RoPE is a rotation, so this bounds the rotary logit contribution at `qk_pos_emb_head_dim` (`mscale² · qk_pos_emb_head_dim` with YaRN, whose cos/sin carry the `mscale` factor) regardless of projection-weight growth.

- **Parameter-free** (no learnable gain): adds no parameters, so the `state_dict` and distributed-optimizer shard layout are unchanged and **existing checkpoints resume unchanged**.
- **Targeted**: only the rotary (pos) component is normalized; the content path is untouched.

## Implementation

Source-string patch on `MLASelfAttention.get_query_key_value_tensors` (the non-fused path), consistent with the existing `patches/` convention. `PrimusMLASelfAttention` inherits the method unchanged, so patching the base class covers the hybrid.

- **Enable**: `mla_rope_qk_norm` config flag, or `PRIMUS_MLA_ROPE_QK_NORM=1` (no config-schema change required).
- **Scope**: non-fused RoPE path (`apply_rope_fusion: false`, `cache_mla_latents: false`). The patch logs a warning and no-ops when RoPE fusion is in effect (the fused kernel applies rotary internally). It judges the effective value: `before_train` runs before Megatron's `validate_args`, which drops `apply_rope_fusion` unless `position_embedding_type: rope`, so the MLA hybrids' inherited `apply_rope_fusion: true` (with `position_embedding_type: none`) does not skip it. It also no-ops when `cache_mla_latents=True`, and for NoPE MLA (`mla_use_nope`, the Kimi K3 default), whose positional dims are an unrotated pass-through that must stay bit-exact, and when `qk_pos_emb_head_dim` is 0 (nothing to normalize).
- **Fail-fast**: if the patch is enabled but cannot be installed (e.g. upstream source drift breaks the anchor), the run aborts instead of silently training without it.
- **Default off** → no behavior change for existing configs.

## Testing

Enabled on the 3B KDA-RoPE hybrid: the max attention logit dropped from ~5,600 to ~65, and training passed cleanly through the iteration where it previously diverged (grad flat ~0.1, zero grad-norm spikes), with loss at/below the pre-divergence baseline.

Unit tests (`tests/unit_tests/backends/megatron/test_mla_rope_qk_norm_patches.py`, 20 pass in `rocm/primus:v26.5` on MI355X against the pinned Megatron-LM): anchor still matches upstream; rewrite lands on the defining base class even when the module attribute is rebound to a subclass, and is idempotent; enable condition and all four skip guards; the config flag enables the patch on the shipped `zebra_kda_1B_hybrid.yaml` through the runtime's arg build and params merge; install failure aborts; and a numerical test on a tiny real `MLASelfAttention` checks that the patched method feeds unit-RMS q/k into the rotary embedding while the content q/k and the value are bit-identical to the unpatched method.

`before_train` patches run before Megatron's `validate_args` (that is called inside `pretrain()`), and `validate_args` is what forces `apply_rope_fusion` off when `position_embedding_type != "rope"`. Both `mla_rope_qk_norm: true` and `PRIMUS_MLA_ROPE_QK_NORM=1` were no-ops on exactly the configs this targets. (The YAML key itself does reach the patch: the arg builder drops it and the runtime's params merge restores it before `before_train`.)

The guard now checks the effective value (`apply_rope_fusion and position_embedding_type == "rope"`). The new `test_yaml_flag_enables_on_shipped_hybrid_config` loads `zebra_kda_1B_hybrid.yaml`, runs it through `MegatronArgBuilder` and `merge_namespace` as `PrimusRuntime` does, and asserts the patch enables.
