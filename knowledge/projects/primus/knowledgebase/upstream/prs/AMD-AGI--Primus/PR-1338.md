**1. MI300X wan2.1_14b keeps a16 atomics despite same non-aligned 79200-token shape** (`examples/maxdiffusion/configs/MI300X/wan2.1_14b-pretrain.yaml:56`)

Optional follow-up. The new comment in the MI300X `wan2.1_1.3b` config says gfx942 a16 v3 backward kernels have no padded-seqlen variant, so WAN's 79200-token sequence falls back to a slower CK-tile kernel; it switches that config to `NVTE_CK_IS_V3_ATOMIC_FP32: "1"`. The untouched MI300X `wan2.1_14b` config uses the same 720x1280x85 shape and keeps `"0"`, so it may hit the same fallback. Consider benchmarking 14B with `"1"` or noting why it is left as is. This is a possible speed-up for 14B, not a correctness problem.

**Who is affected:** Users running the MI300X `wan2.1_14b` MaxDiffusion pretrain example, who may get slower backward attention than possible.

_Verified by running it._

**2. Saved-name list includes tags never emitted by T2V WAN** (`examples/maxdiffusion/configs/MI300X/wan2.1_1.3b-pretrain.yaml:114`)

`key_proj_text` and `value_proj_text` in `names_which_can_be_saved` are dead in this config. maxdiffusion tags them only on the I2V cross-attention branch (`added_kv_proj_dim is not None`), and `Wan2.1-T2V-1.3B` has `added_kv_proj_dim: null`. `save_and_offload_only_these_names` ignores them silently. They have no effect on memory, because T2V cross-attention is already saved via `key_proj`/`value_proj`. The other names (`hidden_states`, `context`, `attn_output`, `query_proj`, ...) are real tags; consider dropping the two `*_text` entries.

**Who is affected:** Readers and maintainers of the MI300X `wan2.1_1.3b` T2V config; runtime behaviour is unaffected.

_Verified by running it._

**3. Capitalised `True` inconsistent with lowercase booleans in the same block** (`examples/maxdiffusion/configs/MI300X/flux_dev-pretrain.yaml:100`)

`reuse_example_batch: True` uses capitalised `True`, while the same block uses `enable_profiler: false`. It is the only `: True` under examples/maxdiffusion. Use lowercase `true` for consistency.

**Who is affected:** Readers and maintainers of the MI300X flux_dev example config; runtime behaviour is unchanged because YAML parses `True` as a boolean.

**Related past reviews:** [#315](https://github.com/AMD-AGI/Primus/pull/315) on `examples/maxtext/configs/MI300X/grok1-pretrain.yaml`
