# chore(megatron): bump Megatron-LM to core_v0.19.2

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1321) · state: closed · merged: True

## Original PR description

## Summary

Bump `third_party/Megatron-LM` from the current pin `d3528a213` (core 0.16.0rc0) to the **`core_v0.19.2` release tag** (`4b4acac9a`, 1024 commits on the pin's history), with the Primus changes needed to run on it. The same code also runs on the old pin and on Megatron-LM main (`e30d863a6`, core 0.20).

| Commit | What |
|---|---|
| fix(megatron): run Primus on Megatron-core 0.19.2 and Megatron-LM main | All adaptation code and tests |
| perf(megatron): cached fast path for DDP `_post_param_sync` on Megatron-LM main | Main only; skipped on 0.19.2, whose method has no per-parameter walk |
| perf(megatron): MI355X MoE recipes skip the dataloader attention mask | 6 MI355X MoE recipes |
| chore(megatron): bump version to core_v0.19.2 | Submodule + `_thirdparty.lock` |

### Main changes

- **Entry point**: `pretrain()` now takes a `PretrainConfigContainer`. Primus builds the run config itself and leaves its `model` unset, so the Primus `model_provider` is still used. The pretrain and SFT trainers share this.
- **Signatures**: new constructor arguments (`name=`, `ExpertsBuilder`, `TESpecProvider` kwargs, ...) are accepted, and the wrappers around `train_step`, `train`, `evaluate`, `save_checkpoint`, `backward_step` and the FLOPs functions forward the new arguments.
- **Mock data**: the new `NullTokenizer` counts EOD inside `vocab_size`. Primus adds it back, so every Megatron version builds the same ids and embedding. Without this, losses diverge.
- **TE fused CE**: core 0.17–0.19 reject `cross_entropy_fusion_impl='te'` because older TE keeps the input gradient in BF16 (TE PR #3193).
  - The ROCm TE in v26.8 (2.17.1) does not have the fix.
  - The native fusion OOMs on Llama-3.1-70B.
  - So the check is dropped and TE CE is kept, exactly as on the pin, with a warning.
- **Patches that silently stopped applying**: these were found and fixed (the patch runner only logs failures):
  - Turbo FP8/FP4 context under full recompute (Qwen3-30B FP8 −18% on MI355X);
  - stacked `validate_args` rewrites (Llama-3.1-8B MXFP4 failed to start);
  - MTP `mtp_on_this_rank` (MTP was silently off);
  - FLA fused CE, FLA SwiGLU and the GDN ROCm gate.
- **Inkling**: adapted to the 0.19 expert builder, `name=` and MLP build path, and its Muon q/k/v split patch.
- **MI355X MoE recipes** now set `create_attention_mask_in_dataloader: false`.
  - With the mask, DeepSeek-V2-Lite, Qwen3-30B and GPT-OSS-20B BF16 lose 2–3% tokens/s on 0.19.2 on MI355X.
  - These models use causal flash attention, so the `[mbs, 1, S, S]` mask is never read; loss is unchanged.
  - The underlying cause inside 0.19.2 was not pinned down.

- **MI355X MXFP8 / MXFP4**: the quantized paths are active after the upgrade (same MX patches and recipes as before, TFLOP/s well above BF16).
- **Attention mask on MI300X**: toggling it on the four MoE configs does not change the upgrade result (before → after: +0.2% to +2.1% with the mask, +0.2% to +1.0% without).

**Other models**: ZAYA1-8B BF16 runs 10 iterations plus the end-of-run evaluation on 0.19.2; loss matches the pin and step time is +0.2%.

**Unit tests** (CI scope, `tests/unit_tests/` with CI's deselects): the failures are the same as on the pin, all from the v26.8 image:
- 5 × `test_turbo_cross_entropy_patch.py`: the image's Primus-Turbo has no `ops.cross_entropy`;
- `diffusion/test_te_vs_local_spec_attention.py::test_eager_te_vs_local` aborts the process, so the file was excluded.

## Not covered / follow-ups

- **TE with the FP32-gradient fix (TE ≥ 2.18)**: needs a new image and a memory plan for Llama-3.1-70B on MI300X. With the fix, peak memory goes from 189/192 GB to full and training stalls.
- **New-image paths**: `turbo_fp8_permute` and `qk_rmsnorm_rope` need a newer Primus-Turbo than v26.8; they were only checked on `tasimage/primus:latest`.
- **Other MoE recipes**: other recipes that keep `create_attention_mask_in_dataloader` on are worth switching off as well (MI300X gains 0–1.5%).
- **Not rerun on 0.19.2**: DeepSeek-V4, Kimi-K3, Mamba/GDN/Zebra hybrids. They were validated earlier against Megatron-LM main.
