# fix(specforge): install tensorboard with its dependencies

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1315) · state: closed · merged: True

## Original PR description

## Summary
- Install `tensorboard` with its dependencies in the SpecForge image, before the smoke check. `SummaryWriter` imports that dependency tree, and a `--no-deps` install leaves `--report-to tensorboard` broken.
- Drop `tensorboard` from `install-light-deps.sh` so pip does not treat an already-installed `--no-deps` copy as satisfying the requirement.
- The Muse Spark base image and the SGLang spec-capture patch are not part of this change.

## Test plan
- [x] `docker build -f examples/specforge/docker/Dockerfile -t primus-specforge:tensorboard-deps .`
- [x] Confirm the build reaches `from torch.utils.tensorboard import SummaryWriter` and the existing smoke check still passes.

🟠 Should fix **[PR Pundit]** (raised by 4 of 4 reviews)

`python -m pip install "tensorboard>=2.14,<3"` resolves tensorboard's full dependency tree with no constraints file or `--upgrade-strategy` against the base image. The tree includes absl-py, grpcio, markdown, numpy, packaging, pillow, protobuf (>=3.19.6,!=4.24.0; recent releases need protobuf>=6.31.1 and grpcio>=1.74), setuptools, six, tensorboard-data-server and werkzeug. If base versions are absent or do not satisfy tensorboard's ranges, pip silently installs, upgrades or downgrades packages shared with sglang, torch and transformers, such as protobuf, numpy, setuptools and grpcio (sglang's smg-grpc-servicer also uses protobuf and grpcio). This violates the image's documented conflict policy ('do not let pip replace it'). The build still passes, and smoke-check.sh only detects a CUDA torch swap. Fix: pin the base stack with a constraints file (e.g. `pip freeze > /tmp/base-constraints.txt; pip install -c /tmp/base-constraints.txt tensorboard...`), pin a tensorboard version compatible with the base image, or install only the missing pieces.

**Evidence:** Read the diff: plain `python -m pip install` with no `-c`, `--no-deps` or `pip check`. `pip show tensorboard` here (2.20.0) lists Requires: absl-py, grpcio, markdown, numpy, packaging, pillow, protobuf, setuptools, tensorboard-data-server, werkzeug; numpy, protobuf, setuptools and pillow are shared with the torch/sglang stack. smoke-check.sh only checks torch build metadata. Could not build the image (no Docker or network).

🔵 Minor **[PR Pundit]** (raised by 4 of 4 reviews)

The `from torch.utils.tensorboard import SummaryWriter` check is inlined in the Dockerfile instead of being added to smoke-check.sh. That script describes itself as 'Build-time and post-build smoke checks' and is the documented home of the GPU-free checks. Re-running it in a built, derived or updated container will not detect a broken `--report-to tensorboard`, which is the regression this PR fixes. The check also only imports the module and never writes an event file, which is where protobuf and the other deps are actually exercised. Nor does any check verify that the base packages tensorboard can upgrade (protobuf, grpcio) are unchanged. Move the check into smoke-check.sh and make it write a scalar to a temporary directory.

**Evidence (verified by running it):** smoke-check.sh contents (step 2) contain no tensorboard check.
