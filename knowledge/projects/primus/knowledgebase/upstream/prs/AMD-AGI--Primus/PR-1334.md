# feat(diffusion): add AMDiffusionBenchmark post-training to the in-tree backend

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1334) · state: closed · merged: False

## Original PR description

## Summary

- Add Flux.1-dev, SDXL, Mochi-1, HunyuanVideo, and Wan2.1-I2V post-training workloads to Primus, registered under `primus/backends/diffusion/amdb_benchmarks` with MI300X, MI325X, and MI355X configs.
- Time only the denoiser step. Each rank encodes its shard once before the timed loop, matching AMDiffusionBenchmark. Host decode, bf16 frozen encoders, fused Flux RoPE, and MIOpen find mode 5 stay on these benchmark paths and off the existing Flux and Wan trainers.
- Match the AMDB training loss. Wan trains on the raw VAE sample, with only the image-to-video condition normalized. Mochi and Hunyuan use AMDB's flow-matching target. Gradient checkpointing is off for Mochi and Hunyuan on MI300X and MI325X.

## How to run

From a writable directory, on one node:

```bash
cd /workspace/Primus
./primus-cli direct -- train posttrain --config examples/diffusion/configs/MI300X/benchmark_flux_dev-posttrain.yaml
```

Swap the config for `benchmark_sdxl`, `benchmark_mochi_1`, `benchmark_hunyuan_video`, or `benchmark_wan2_1_i2v`. Defaults are 100 steps (SDXL 200), local batch 1, learning rate `1e-5`, and seed 42. `cache_latents: false` restores online VAE and text encoding inside the step.

## MI300X, 8x GPU, steady state after step 5

| Model | AMDB fps | Primus fps | AMDB TFLOPS/s | Primus TFLOPS/s | Loss, last 10 steps, AMDB → Primus |
|---|---:|---:|---:|---:|---|
| FLUX.1-dev | 4.19 | 5.24 | 273.5 | 312.2 | 0.40 → 0.41 |
| SDXL | 12.82 | 14.19 | 229.1 | 253.7 | 0.24 → 0.24 |
| Mochi-1 | 1.04 | 1.20 | 140.9 | 163.5 | 0.53 → 0.61 |
| HunyuanVideo | 0.68 | 0.72 | 176.7 | 187.1 | 0.16 → 0.14 |
| Wan2.1 I2V | 0.33 | 0.40 | 250.9 | 244.7 | 0.19 → 0.15 |

fps is the comparison to use. TFLOPS/s divides a first-step flop count by the step time, and the two counters do not count the same attention work on Flux, SDXL, and Wan. Mochi ends higher because the official denoiser and the Diffusers denoiser do not take the same steps. Wan step 1 is still higher (4.94 against 3.55) because the two VAEs do not draw the same sample. Both end on the same scale.

Fold these into the existing classes as parameters or methods to avoid two diverging copies.

`amdb_benchmarks/wan/{wan_dit,components,adapter}.py` copy `models/wan/*` with the base classes unchanged; `WanRMSNorm` and `WanLayerNorm` are defined in both places. The additions are I2V cross-attention, `MLPProj`, `clip_fea`, a tokenizer field and three adapter methods. Merge these into, or subclass, the existing modules.
