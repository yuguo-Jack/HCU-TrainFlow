# fix(te): recover gfx950 hipBLASLt wgrad failures via workspace retry and torch fallback

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1141) · state: closed · merged: False

## Original PR description


## Summary
Unblocks `mamba_370M` pretrain on MI355X, which dies on the first backward in TE `LayerNormLinear.wgrad_gemm` with `HIPBLASLT Error: 6` (`HIPBLAS_STATUS_INTERNAL_ERROR`). The failing call is fused `in_proj` wgrad (`NT`, `M=1024`, `N=4384`, `K=65536` tokens). Fprop of the same layer succeeds, `hipblaslt-bench` runs the dumped problem, and a standalone TE repro fails at every output width, so this is TE's large-K hipBLASLt path, not a gfx950 fused-width dead zone.

With Primus tuning off, TE takes the first hipBLASLt heuristic algo without re-checking workspace. Wgrad `K` is the token count, so hipBLASLt picks a split-K solution that needs more than the 64 MiB TE allocates for gfx950.

This PR adds a ROCm-only `before_train` patch that wraps `general_gemm` and rebinds every already-imported call site. On a hipBLASLt status failure it grows the TE workspace (64 → 128 MiB) and retries the same GEMM; if that still fails it recomputes with torch and memos the shape. Quantized, gelu, and Userbuffers GEMMs are never rerouted. Either path lets backward continue so training no longer dies on the first step.
