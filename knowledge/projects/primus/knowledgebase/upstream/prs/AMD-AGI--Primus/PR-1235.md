# docs(release): update documentation for v26.8

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1235) · state: closed · merged: True

## Original PR description

## Summary

Updates Primus documentation for `rocm/primus:v26.8` and
`rocm/jax-training:maxtext-v26.8`, with software-stack facts extracted from the
published images.

The image families use different ROCm builds in this release:

- `rocm/primus:v26.8`: ROCm 10.1.0, PyTorch 2.14, with Transformer Engine and
  Flash Attention built from source.
- `rocm/jax-training:maxtext-v26.8`: ROCm 10.2 nightly, JAX 0.11.1,
  Transformer Engine 2.18 (dev), and no bundled Primus checkout.

## What changed

- Added machine-generated image snapshots and rotated the release notes:
  v26.8 is current, v26.7 remains detailed, and v26.5 moves to Earlier releases.
- Updated current image tags, package version, checkout instructions, README
  highlights, backend notes and the model support matrix.
- Added public, inbox-friendly release highlights for v26.7 and v26.8.
- Re-aligned both bare-metal install flows with the v26.8 Dockerfiles:
  - PyTorch: ROCm 10.1 / torch 2.14, source-built Transformer Engine and
    Flash Attention, and updated AITER / Primus-Turbo pins.
  - JAX: ROCm 10.2 nightly / JAX 0.11.1 / TE 2.18, MaxText TensorFlow extras,
    and a checksum-verified LLVM archive for the TensorFlow Bazel build.
- Updated the release-docs workflow for images that do not ship
  `/workspace/Primus`, per-family changelogs, and the public announcement format.
- Documented two v26.8 correctness considerations:
  - `packing=false` still produces a different MaxText loss curve; use
    `NVTE_CK_USES_FWD_V3=0` to reproduce the earlier convergence.
  - Some DeepEP MoE performance recipes set
    `PRIMUS_TURBO_DEEPEP_DISABLE_CHEAP_FENCE=0`; this can affect gradient
    accuracy. Convergence and production runs should set it to `1` or remove it
    from the recipe.

## Validation

Validated on 8× MI325X, Ubuntu 22.04 (glibc 2.35), Python 3.12:

- Clean bare-metal installation of both stacks completed successfully.
- MaxText Llama-2 7B BF16 ran for 20 steps on 8 GPUs at about
  500 TFLOP/s/device; the loss trend matched the v26.8 container.
- Megatron Llama-3.1 8B BF16 ran for 10 iterations on 8 GPUs at about
  608 TFLOP/s/GPU, with zero NaN iterations. Final loss was 6.6537 on bare
  metal and 6.6535 in the v26.8 container.
- Package-manifest comparison found 280 packages in common for PyTorch
  (4 minor version differences) and 266 in common for JAX. Expected differences
  are documented in the installation READMEs.
