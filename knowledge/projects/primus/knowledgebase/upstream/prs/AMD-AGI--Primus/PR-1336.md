# fix(megatron): skip data prefetch when data_iterator is None

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1336) · state: open · merged: False

## Original PR description

Fixes #1335.

With the delayed FP8 recipe, TP=1 and PP>=3, `patch_grad_zero_and_data_prefetch` wraps `data_iterator` in a `CudaPrefetchIterator` on every rank. Middle pipeline stages build no dataset and receive `data_iterator=None`, so the prefetcher's first `next(None)` raises `TypeError: 'NoneType' object is not an iterator` at iteration 1.

This change skips the prefetcher when `data_iterator is None`. `_pf` stays `None`, so `_synced_prefetch_fwd_bwd` passes the original `None` through unchanged, the same way the VPP list case already works. The first and last stages are unaffected.

I found this on v26.8 (TP=1, PP=8, DP=4, 32 x MI355X, `--fp8_recipe delayed`), where middle-stage ranks crashed at iteration 1. The same code is on `main`.

**1. No regression test for skipping prefetch when `data_iterator` is None** (`primus/backends/megatron/patches/delayed_fp8_scaling_patches.py:269`)

No test covers the new `data_iterator is not None` guard in `_patched_train_step`, so reverting the hunk leaves the suite green. Before the fix, `CudaPrefetchIterator(None)` raised `TypeError: 'NoneType' object is not an iterator` on the first step. That happens on pipeline stages that get no data iterator; with TP=1 these are likely the middle stages, since Megatron normally builds data on both the first and last stage. A small test could install the patch with `tp_size=1` and mocked CUDA streams, call the wrapped train_step with `data_iterator=None`, and assert that `_prefetch_state` has no `'iter'`.

**Who is affected:** Future regressions would hit Megatron runs with delayed FP8 scaling, TP=1 and pipeline parallelism, on stages that have no data iterator.
