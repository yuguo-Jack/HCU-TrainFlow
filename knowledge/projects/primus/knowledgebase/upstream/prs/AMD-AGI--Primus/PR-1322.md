# feat(automodel): FLUX and Wan training paths, synthetic data, and schnell guidance

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1322) · state: closed · merged: True

## Original PR description

Second PR of the series that started with #1314, and builds on the patch framework added there.

**What changes**
- **Wan 2.2:** `activation_checkpointing: selective` is honoured (upstream's Wan parallelizer runs
  full AC for it) and `fsdp.reshard_after_forward` reaches the per-layer sharding (upstream drops
  it). Done as a subclass of upstream's `WanModelParallelizer`, filling in only what it drops.
- **FLUX.1:** `activation_checkpointing` covers every block in both block lists. The default
  parallelizer selects only the longer 38-block single-stream list, leaves all 19 dual-stream
  blocks untouched, and wraps only each selected block's attention rather than the whole block.
- **FLUX.1-schnell:** trains. The adapter now honours `use_guidance_embeds`, so a transformer
  without a guidance embedder no longer fails at step 0.
- Synthetic dataloaders for Wan and FLUX, FLUX dev/schnell presets, and example experiments.
- Under tensor parallelism (`tp_size > 1`) both sidecars leave activation checkpointing to upstream and log that they did, so blocks are never wrapped before upstream applies its TP plan.

No new flags: each repair changes only what upstream drops or mis-applies for a setting the
config already asks for. Upstream's sharding, TP plan and mixed precision stay in charge, and an
upstream sidecar for FLUX would become the base automatically.

**Known limitation.** On FLUX, `selective` needs `enable_compile: false`: AutoModel's selective
policy fails under `torch.compile` when Transformer Engine is installed. It therefore runs eager,
and it is slower than the compiled full-AC default. The FLUX module preset says so.

**Breaking:** none.

**How to review.** `distributed/sidecar.py` (how a Primus sidecar is registered over upstream's)
and `distributed/activation_checkpointing.py` first, then `models/wan/` and `models/flux/`.

**Test plan**
- Unit tests, including contract tests that run each sidecar on the real pinned AutoModel on CPU.
- Short runs on 8× MI355X: Wan, FLUX.1-dev and FLUX.1-schnell; multi-GPU runs check from the logs
  that reshard and selective/full AC took effect.

🟠 Should fix **[PR Pundit]**

With share_text_features=True (the config default and the wan_synthetic_pre_trainer.yaml setting), the 'shared' text tensor is drawn lazily from the per-index generator g (seed+idx) of whichever index is fetched first, after the video draw. It is then cached per dataset instance. Each rank and each DataLoader worker builds its own copy. Without persistent_workers, workers are respawned every epoch. Under shuffle or DistributedSampler, each copy hits a different first index. The 'shared' text therefore differs across workers, ranks, epochs and runs, and depends on read order. This contradicts the module docstring ('two runs see identical data') and the comment 'same tensor on every rank and in every run'. FLUX's loader does this correctly with a dedicated Generator().manual_seed(self.seed).

**Evidence (verified by running it):** Script on head: two SyntheticWanDataset instances that fetched index 0 vs index 5 first return different text_embeddings for sample 3 (torch.equal False), while video_latents for sample 3 match.
