# mi455x_v3: MegaMoE by default and tuned grouped GEMM for the MI455X DeepSeek-V3 proxy

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1365) · state: closed · merged: True

## Original PR description

# Description

MI455X v3: the DeepSeek-V3 example now runs its MoE layers as Primus-Turbo's fused MegaMoE layer (`use_turbo_mega_moe: true`, one line in `examples/megatron/configs/MI455X/deepseek_v3-BF16-pretrain.yaml`). `--use_turbo_mega_moe False` on the launcher's command line turns it off; EP 1 or above 8 keeps the default MoE path. Goes with AMD-AGI/Primus-Turbo#597, which brings the v3 grouped-GEMM tuning (AMD-AGI/Primus-Turbo#590) to Primus-Turbo `main`, where MegaMoE (AMD-AGI/Primus-Turbo#582) already is; the example's non-MegaMoE path gets that grouped GEMM too.

It needs a Primus-Turbo with the gfx1250 MegaMoE kernels (`main` since AMD-AGI/Primus-Turbo#582). The default image `tas-20261019` ships Primus-Turbo `21588d59`, which predates them: set `TURBO_DIR`, or use an image with v3.

## Results

DeepSeek-V3 proxy on 4× MI455X, launcher defaults (EP4, 128 experts, top-8, MBS 2, GBS 64, seq 4096, even routing). ms/iter is the mean of iterations 4–20 over 3 alternating runs.

| MoE path | Primus-Turbo | ms/iter | Speedup | TFLOP/s/GPU | Peak memory | lm loss, iter 20 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| all-to-all + grouped GEMM | before v3 (`ff4898e4`) | 1103.4 | 1.000× | 1282 | 162.2 GiB | 1.75401 |
| all-to-all + grouped GEMM | v3 | 1050.2 | 1.051× | 1347 | 162.2 GiB | 1.75396 |
| **MegaMoE (this PR)** | v3 | **1003.5** | **1.100×** | 1410 | 146.4 GiB | 1.75398 |

- Other routings, MegaMoE against the all-to-all path on `ff4898e4`: uniform 1130.0 → 1035.1 ms (1.092×), the router's own (warm FlyDSL cache, median) 1131.7 → 1047.5 ms (1.080×); 24–25 GiB less peak memory.
- First run with the router's own routing on a cold FlyDSL cache (a new machine or image): the all-to-all path recompiles its grouped GEMM for every new token count, so the first 50 iterations take about 1 minute with MegaMoE against 8–9.5 without. By Primus's average TFLOP/s/GPU over those iterations, the measure AMD-AGI/Primus-Turbo#582 quotes as +30%, MegaMoE is 1.33× faster (1.43× against v3's all-to-all path).
- On this commit (10 iterations): the default run patches MegaMoE in (998.5 ms, 146.4 GiB); with `--use_turbo_mega_moe False` it does not (1045.0 ms, 162.2 GiB).
- Loss and grad norms stay within run-to-run noise.

**1. 🟠 Should fix: Grouped-GEMM settings no longer affect experts: this PR enables MegaMoE, which bypasses grouped GEMM**

With `use_turbo_mega_moe: true` at the default `bf16` and `expert_model_parallel_size: ${PRIMUS_EP:4}`, `patch_mega_moe` swaps `MoELayer` for `PrimusTurboMegaMoELayer`. Its experts call `fused_mega_moe_stage1/2` directly, so `PrimusTurboGroupedLinear` is never built. As a result, `use_turbo_grouped_gemm`, `turbo_grouped_gemm_backend: bf16:flydsl` and `moe_permute_fusion` do nothing, and the PR title's 'tuned grouped GEMM' and the header comment (lines 9-11) describe a path the run no longer takes. Fix the title and header, and mark these settings as fallback-only for `--use_turbo_mega_moe False`.

**Who is affected:** Readers of the MI455X DeepSeek-V3 proxy example who expect its grouped-GEMM backend settings to be in effect under the default EP4 run.
