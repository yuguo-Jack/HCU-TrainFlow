# fix(megatron): reduce deferred output-layer wgrads with their grad bucket

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1362) · state: open · merged: False

## Original PR description

Fixes #1330

## Summary

With `defer_embedding_wgrad_compute` the output layer hands DDP a placeholder weight gradient each microbatch, and `finish_embedding_wgrad_compute` runs the real wgrad GEMMs into `main_grad` after the pipeline schedule. With `overlap_grad_reduce` the reduce-scatter for that weight's bucket has already been issued by then, either by `grad_sync_func` (`align_grad_reduce=True`, the default) or by the DDP grad-ready hooks (`align_grad_reduce=False`). The drained gradient is never reduced, so `output_layer.weight` gets a wrong gradient every step. Upstream Megatron-LM, including the core_v0.19.2 pin on main, has the same ordering.

This adds `primus/backends/megatron/patches/defer_embedding_wgrad_patches.py`, a `before_train` patch that only applies when `defer_embedding_wgrad_compute`, `overlap_grad_reduce` and PP > 1 are all set with DDP (not Megatron-FSDP or FSDP2):

- `clear_embedding_activation_buffer` records the last-stage model at the start of each schedule call.
- `_ParamAndGradBucketGroup.start_grad_sync` drains that model's deferred wgrads first when the bucket group holds the output weight. Both sync paths go through it, so this covers `align_grad_reduce` true and false.
- The patch is registered at priority 80, so its `start_grad_sync` wrapper is outside `rccl_sdma_grad_reduce_scatter` (60, which issues the reduce-scatter without calling the inner function) and `grad_buffer_ownership` (70, which inspects `main_grad`). The drain runs before either of them sees the bucket.
- The schedule's later `finish_embedding_wgrad_compute` becomes a no-op once the buffers are empty (draining empty buffers would raise). If it still finds undrained buffers, some `start_grad_sync` override bypassed the patch, and it warns once.
- Both schedule helpers are rebound everywhere they were imported by name, including PrimusPipe.

No shipped config enables `defer_embedding_wgrad_compute`, so default runs are unaffected.

## Testing

- `tests/unit_tests/backends/megatron/test_defer_embedding_wgrad_patch.py` (CPU): the output-weight bucket drains before it syncs, other buckets are left alone, the drain happens once per step, the later drain is skipped, a bypassed drain warns once, untied output layers, non-last stages, and the enabling condition.
- `tests/unit_tests/backends/megatron/test_defer_embedding_wgrad_patch_wiring.py` (GPU): applies the patch to the real `schedules` module and `_ParamAndGradBucketGroup`, checks the rebinds (including PrimusPipe) and idempotency, checks that every other `before_train` patch touching `start_grad_sync` has a lower priority, and pins the upstream helper signatures. The wrapper-order test fails at the default priority 50.
- 17 passed in `rocm/primus:v26.8` on MI300X.

It holds strong references to the model, config and buffers across steps and eval, so a later `start_grad_sync` (e.g. after a forward-only pass) can act on a stale entry. `_pending[:] = [...]` also keeps only the last model, which breaks multiple DDP models in one process or nested schedule calls.

**1. 🟠 Should fix: Output-layer wgrad silently left unreduced with `rccl_sdma` grad backend: this PR's drain is bypassed**

With `MEGATRON_GRAD_REDUCE_BACKEND=rccl_sdma`, the RCCL-SDMA patch (#1186/#1207, priority 60) wraps outside this patch's `start_grad_sync` wrapper (default priority 50). On its eligible path (distributed optimizer, one optimizer, no fp32 RS accumulation, direct symmetric buffers), `make_start_grad_sync` issues the reduce-scatter without calling the original, so the early drain never runs. The late `finish_embedding_wgrad_compute` drain then adds the output-layer gradient after its bucket was reduced, so DP replicas diverge: #1330 is back, with no warning. Register this patch above priority 60 or drain inside the RCCL path. Also warn or raise when `orig()` is reached with non-empty buffers under `overlap_grad_reduce`.

**Who is affected:** Runs with `defer_embedding_wgrad_compute`, `overlap_grad_reduce`, PP>1 and the opt-in `MEGATRON_GRAD_REDUCE_BACKEND=rccl_sdma` grad reduce-scatter backend with distributed optimizer.

_Checked against the code by an independent pass._

**3. 🟠 Should fix: Interleaved pipeline step time rises: this PR runs output-layer wgrad GEMMs synchronously in grad sync**

`start_grad_sync` now runs all N deferred output-layer wgrad GEMMs synchronously before issuing the bucket's reduce-scatter. With `sequence_parallel`, the synchronous TP all-gathers in `drain_embedding_wgrad_compute` run there too. The hook path (`register_grad_ready` during the last microbatch's backward, ahead of `send_backward`) applies only with `--no-align-grad-reduce`. Under the default `align_grad_reduce: true`, the non-interleaved 1F1B schedule drains on the last stage only after its final `send_backward`, so nothing upstream waits. The interleaved schedule calls `grad_sync_func` in `backward_step_helper_postprocess` before the following send, so there the drain lands on the cooldown critical path. This is a throughput cost of moving the drain out of the flush (the point of `defer_embedding_wgrad_compute`), not a correctness bug.

**Who is affected:** Last-pipeline-stage ranks that combine `defer_embedding_wgrad_compute` and `overlap_grad_reduce` with PP>1, and either use virtual pipeline stages or set `--no-align-grad-reduce`.

_Checked against the code by an independent pass._
