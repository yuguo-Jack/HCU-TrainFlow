# feat(examples): DeepSeek-V3 proxy pretraining example for 4x MI455X (gfx1250)

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1250) · state: closed · merged: True

## Original PR description

## Summary

Adds a DeepSeek-V3 MoE proxy pretraining example for one node of 4x MI455X (gfx1250): full DeepSeek-V3 layer shapes (MLA, hidden 7168), 4 MoE layers of 128 experts, EP4, seq 4096, BF16, mock data. All files are new; `examples/README.md` only gains the new directory.

## Changes

- `examples/megatron/configs/MI455X/deepseek_v3-BF16-pretrain.yaml`: MI455X config based on the MI355X one. 4 layers, 128 experts, top-8, EP4, no MTP, no activation recompute. DeepEP is off; experts run on the Primus-Turbo grouped GEMM.
- `examples/megatron/models/deepseek-v3/run_deepseek_v3_proxy_mi455x.sh`: launcher. `PRIMUS_LAUNCHER=container` (default) runs from the host through `primus-cli container`; `PRIMUS_LAUNCHER=direct` runs inside a container. Settings are environment variables, as in `run_deepseek_v4.sh`.
- `examples/megatron/models/deepseek-v3/prepare_mi455x.sh`: optional setup. `TURBO_DIR` builds a Primus-Turbo checkout for the image; `CONTAINER` starts a container for direct runs.
- `runner/helpers/patches/12_fix_triton_expert_scheduling.sh`: `--patch` script that turns off Triton's gfx1250 expert scheduling, which makes Triton kernels fault or return NaN at random. `TRITON_HIP_USE_EXPERT_SCHEDULING=0` alone does not reach the Inductor kernels. The script skips itself when scheduling is already off.
- `examples/megatron/models/deepseek-v3/README.md`: usage, settings, reference numbers, profile and known issues.

## Usage

```bash
# From the host (image amdprimus/amdprimus:tas-20261011 by default)
bash examples/megatron/models/deepseek-v3/run_deepseek_v3_proxy_mi455x.sh

# Inside a container
CONTAINER=dsv3 bash examples/megatron/models/deepseek-v3/prepare_mi455x.sh
docker exec -it dsv3 bash
PRIMUS_LAUNCHER=direct bash examples/megatron/models/deepseek-v3/run_deepseek_v3_proxy_mi455x.sh
```

## Testing

4x MI455X, `amdprimus/amdprimus:tas-20261011`, Primus-Turbo `dev/mi455x_v1` (a1800137) and the image's Primus-Turbo:

| Config | ms/iter | TFLOP/s/GPU | Peak VRAM/GPU | lm loss at iteration 10 |
| --- | --- | --- | --- | --- |
| Default (no recompute) | 2202 | 646 | 197–199 GiB | 5.57984 |
| `PRIMUS_RECOMPUTE_LAYER_IDS=0,3` | 2543 | 558 | 181–191 GiB | 5.57984 |

- Both launchers run 10/10 iterations with no GPU faults in dmesg.
- Loss and grad norms are identical with and without recompute, and with either Primus-Turbo.
- 1-GPU variant (one MI455X, another node): 671 ms/iter, 942 TFLOP/s/GPU.
- pre-commit and `tests/runner/test_docs_cli_examples.py` pass.
