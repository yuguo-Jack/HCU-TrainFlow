# mi455x_v1: add MI455X (gfx1250) DeepSeek-V3 proxy and GPT-OSS examples

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1272) · state: closed · merged: True

## Original PR description

## Summary
Brings `dev/mi455x_v1` to `main`. Only `examples/` changes:
- DeepSeek-V3 proxy pretraining on 4x MI455X: `examples/megatron/models/deepseek-v3/` (launcher, README) and `examples/megatron/configs/MI455X/deepseek_v3-BF16-pretrain.yaml` (#1250, #1267). Attention and the expert grouped GEMMs run on Primus-Turbo's FlyDSL kernels; default image `amdprimus/amdprimus:tas-20261019`.
- GPT-OSS 20B / 120B on 4x MI455X: `examples/megatron/models/gpt-oss/` (#1264) and `examples/megatron/configs/MI455X/gpt_oss_{20B,120B}-BF16-pretrain.yaml`. The MI455X yamls are separate from the MI355X ones, so MI355X tuning such as #1252 no longer changes this example. 20B takes the #1252 settings with Turbo DeepEP off (see Known issues); 120B is the gfx1250 runbook's 8-of-36-layer proxy (MBS 1 / GBS 8, full recompute). Default image `amdprimus/amdprimus:tas-20261019`.
- `examples/README.md` lists both directories.

On top of `dev/mi455x_v1` (merge of `main` 5e8a4abb, no conflicts):

DeepSeek-V3:
- `runner/helpers/patches/12_fix_triton_expert_scheduling.sh` (added by #1250) is removed, so nothing outside `examples/` changes. The DeepSeek-V3 launcher handles Triton like the GPT-OSS one: from the host it re-runs itself in a `docker run` with the options of `primus-cli container`, and inside the container it makes Triton's `is_expert_scheduling_enabled()` return `False` when `PATCH_TRITON_EXPERT_SCHEDULING=1` (default). If it cannot patch Triton (non-root), the DeepSeek-V3 launcher stops with a message saying so.
  - The patch is still needed besides `TRITON_HIP_USE_EXPERT_SCHEDULING=0`. Checked on gfx1250: with the variable alone, 0 of 17 Inductor kernels compile in expert mode, but 17 of 17 come back in expert mode when Inductor loads them from the FX-graph cache of an earlier run without the variable. Editing Triton's default also invalidates that cache.
- `PRIMUS_RECOMPUTE_LAYER_IDS=3` crashed (a single id reaches `recompute_layer_patches` as an int); the launcher passes the ids as a list. A relative `TURBO_DIR` is resolved against the caller's directory; `MASTER_ADDR`/`MASTER_PORT` and the other single-node variables that `primus-cli container` forwarded go into the container.
- README re-measured on `main` (DeepSeek-V3 vocabulary 129280, #1249). The 1-layer 1-GPU variant and the wrong-gradient/NaN and vocabulary notes are removed. A note explains why the example does not set expandable segments despite the #1257 warning: 1–3 GiB less peak VRAM, but 0.6% slower (4% for TE/Triton), same loss.

GPT-OSS (since #1264):
- The launcher runs the new MI455X yamls instead of the MI355X yamls plus command-line overrides. The 120B proxy keeps its effective settings (8 layers, PP 1, MBS 1 / GBS 8, full uniform recompute, no profiler, native CE). The 20B yaml takes the #1252 settings with Turbo DeepEP off. Through the merge of `main`, the 20B example on `dev/mi455x_v1` picks up #1252's `use_turbo_deepep: true` and hangs at the first DeepEP dispatch; this branch fixes that.
- Default image `amdprimus/amdprimus:tas-20261011` → `amdprimus/amdprimus:tas-20261019` (same image as the DeepSeek-V3 example; 20B gives bitwise-identical lm loss and grad norms, 120B lm loss within 1e-4, both within 1% in time).
- README re-measured on `main` (vocabulary 201088, #1249). The GPU-detection note is removed: `primus-env.sh` maps gfx1250 to MI455X.

- 20B at MBS 4 / GBS 64: 766 TFLOP/s/GPU, 7% below MBS 8, so the example keeps MBS 8 like the gfx1250 runbook.
- 20B with Turbo FlyDSL grouped GEMM: 4% faster (855 TFLOP/s/GPU), same peak memory. Not the default; the yaml keeps the #1252 setting.
- 120B proxy at MBS 8 / GBS 64 without recompute, with FlyDSL grouped GEMM, all-to-all overlap and the 20B settings: 889 TFLOP/s/GPU, 77,070 tokens/s/GPU (4.2x), 70% of memory. The README has the command; the yaml keeps the runbook proxy.

## Test
- 4-GPU from the host (container mode): default x3, TE/Triton x2, `PROFILE=True` x1 (trace shows the FlyDSL MLA kernels `mla_fwd_kernel`, `k_dkdv64`, `k_dqg96`, `k_delta_bshd` and the FlyDSL grouped GEMM kernels `kernel_grouped_nt`, `kernel_grouped_variable_k`). 1-GPU inside a container (direct mode): x3. Repeated runs give bitwise-identical loss and grad norms; no NaN, no amdgpu errors.
- Final launcher (after review fixes): TE/Triton and profiled 4-GPU runs from the host, 1-GPU in a container, `PRIMUS_RECOMPUTE_LAYER_IDS=3` and `0,3`. `PATCH_TRITON_EXPERT_SCHEDULING=0` leaves Triton untouched; non-root, already-patched and changed-signature cases checked in a CPU container.
- Expandable segments A/B: 4-GPU x3, TE/Triton x2, 1-GPU x3.
- GPT-OSS from the host: 20B and 120B x2 each with DeepEP off, then x1 each on the MI455X yamls (same lm loss and peak memory); 10/10 iterations, 0 NaN, no amdgpu errors.
- Turbo DeepEP on gfx1250: a 4-rank standalone run at the GPT-OSS 120B MoE shape gets a correct `get_dispatch_layout`, then `dispatch` raises `CPU recv timeout`; a one-block HIP probe shows the 32-bit `__ballot` behind it.
- Reproduction at this head (19217fcc), each README configuration once from a fresh container: DeepSeek-V3 4-GPU default 1197.1 ms, 4-GPU TE/Triton 2154.4 ms, 1-GPU 4 layers 1004.8 ms; GPT-OSS 20B 2222.9 ms, 120B proxy 441.9 ms. lm loss equal to the tables above (DeepSeek-V3 grad norms equal to the README's); no NaN, no amdgpu errors.
- pre-commit; `tests/runner/test_docs_cli_examples.py`.

## Known issues / follow-ups
- GPT-OSS: Turbo DeepEP does not run on gfx1250, so the MI455X yamls turn it off. Turbo DeepEP assumes 64-lane wavefronts (`kWarpSize = 64`). On gfx1250's 32-lane waves `__all_sync(kFullWarpMask, ...)` is never true, so `barrier_block` in `notify_dispatch` never returns and the first dispatch fails with `CPU recv timeout`. A 32-bit mask alone does not fix it: `warp_reduce_sum` also assumes 64 lanes (it returns twice the sum of the first 32 lanes), so DeepEP needs a wave32 port in Turbo. Turbo's test suite does not catch this because on gfx1250 its `conftest.py` runs only a short whitelist of suites, which excludes DeepEP.
- `ci.yaml` Turbo/aiter pin bump with the FlyDSL 0.3.4.1 port of Primus's FlyDSL kernels.

`PRIMUS_WORKSPACE` is forwarded into the container, but a workspace outside the mounted directories is not bind-mounted. For example, `PRIMUS_WORKSPACE=/mnt/experiments` puts logs, profiler traces and experiment outputs in the container filesystem, where `--rm` deletes them after the run. Resolve and create the configured workspace on the host, then mount it at the same path so this documented setting preserves results.

Container mode does not forward an exported `MASTER_PORT`, although direct mode honors it. With host networking, concurrent jobs on different GPUs that request different ports can therefore still collide on the default port (1234). Forward `MASTER_ADDR` and `MASTER_PORT`, as `primus-cli container` does.
