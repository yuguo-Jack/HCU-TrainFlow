# fix(megatron): recommend and verify expandable segments for Turbo grouped GEMM (AIMA-242)

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1257) · state: closed · merged: True

## Original PR description

PrimusTurboGroupedLinear merges each layer's expert weights into one parameter, so the distributed optimizer allocates a few very large fp32 main-grad tensors per step (768/384 MiB per layer for Qwen3-235B). They do not fit the fragmented free pool and force new segments, raising peak reserved memory above the TE grouped GEMM path.

- Warn when use_turbo_grouped_gemm is enabled without expandable_segments:True in the allocator config.
- Add a global runner hook that fails fast when expandable_segments:True is requested but not in effect on the current PyTorch build.

- Copilot · comment · 2026-10-15T09:09:03Z · [source](https://github.com/AMD-AGI/Primus/pull/1257#discussion_r4281119233)

File: `runner/helpers/hooks/05_check_expandable_segments.py` · line 52

Resolve YAML `env:` entries in order, matching `PrimusRuntime._apply_config_env` (`primus/core/runtime/train_runtime.py:371–374`). For example, `ALLOC_OPTS: expandable_segments:True` followed by `PYTORCH_HIP_ALLOC_CONF: $ALLOC_OPTS` enables expandable segments at runtime, but this comprehension ignores `ALLOC_OPTS` and leaves the reference unresolved. The hook then returns success without checking support. Apply preceding entries before expanding allocator values, and add a regression test for this case.

- Copilot · comment · 2026-10-15T09:09:04Z · [source](https://github.com/AMD-AGI/Primus/pull/1257#discussion_r4281119313)

File: `runner/helpers/hooks/05_check_expandable_segments.py` · line 67

The runner executes global hooks before applying `direct.env` and sourcing `--env <file>` (`runner/primus-cli-direct.sh:582, 623–653`). If expandable segments are requested only through either source, this check sees no request and returns success, allowing an unsupported build to launch without verification. Run the allocator validation after the runner's final environment exports, while still applying the experiment YAML overrides before importing PyTorch.

- Copilot · comment · 2026-10-16T02:24:53Z · [source](https://github.com/AMD-AGI/Primus/pull/1257#discussion_r4290246768)

File: `runner/helpers/hooks/05_check_expandable_segments.py` · line 32

The training parser accepts `--exp` as an alias for `--config` (`primus/core/launcher/parser.py:25–30`), but this helper ignores it. When expandable segments are requested only in that experiment's `env:` block, the hook finds no config and silently skips verification. Recognize both aliases, including their `=value` forms.
