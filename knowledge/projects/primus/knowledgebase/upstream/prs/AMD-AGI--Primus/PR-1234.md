# fix(torchtitan): gate the primus_turbo attention converter on use_turbo_attention

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1234) · state: closed · merged: True

## Original PR description

## Summary

29 of 33 TorchTitan model configs (all llama3.x, llama4, deepseek_v3, qwen3) list `converters: [primus_turbo]` unconditionally, and TorchTitan builds converters from `model.converters` regardless of `primus_turbo.enable_primus_turbo`. `PrimusTubroConverter` always replaced the attention wrappers with `TurboAttention`, but the `(q, k, v)` `Attention.forward` that `TurboAttention` expects is only installed by the `torchtitan.primus_turbo.turbo_attention` patch, which requires both `enable_primus_turbo` and `use_turbo_attention`.

With either flag off (e.g. an image without `aiter`, or turning turbo attention off while debugging), the stock TorchTitan `Attention` calls `TurboAttention` with `block_mask` / `enable_gqa` and the first forward fails under `torch.compile` with `TypeError: Unexpected keyword arguments: ['block_mask', 'enable_gqa']`.

## Changes

- `primus_turbo_converter.py`: the converter is enabled only when `enable_primus_turbo and use_turbo_attention`, matching the patch that installs the compatible `Attention`; the Float8 attention config is imported only when it is used. Default configs (both flags on) behave exactly as before.
- `tests/unit_tests/backends/torchtitan/test_primus_turbo_converter.py`: the converter replaces attention only when both flags are on.
- Typo fixes (review feedback): `PrimusTubroConverter` / `PrimusTubroFP8Converter` / `PrimusTubroMXConverter` -> `PrimusTurbo*`, `ModelConvertersContainer.primus_turbo_entension` -> `primus_turbo_extension`, with all references updated. Registry keys are unchanged, so configs are not affected.

## Testing

- `pytest tests/unit_tests/backends/torchtitan/test_primus_turbo_converter.py tests/unit_tests/backends/torchtitan/test_config_utils.py` (CPU): 20 passed; the 4 new tests fail without the fix.
- Found while running TorchTitan Llama 3.1 8B with `use_turbo_attention: false` on MI455X; the run only worked after clearing `model.converters`.
