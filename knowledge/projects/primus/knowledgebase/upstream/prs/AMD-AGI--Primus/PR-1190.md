# feat(megatron): add Triton fused AdamW on the shared kernels, on by default

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1190) · state: closed · merged: True

## Original PR description

## Summary

Adds a Triton AdamW for the Megatron backend, on by default (`use_triton_fused_adam: true`; set `false` to keep TE `FusedAdam`), built on the shared kernels merged in #1233 (architecture-dependent grid for large tensors, batched launches for small ones).

TE builds on the generic `multi_tensor_apply` launcher cap every Adam launch at 320 workgroups. ROCm TE builds that include the custom device-metadata Adam kernel (as in current Primus images) already launch one uncapped kernel per step, so on MI355X large tensors are on par. It is still on by default: it was never slower than TE in the measurements below, is clearly faster on MI455X and on many small tensors, and falls back to TE for every path it does not implement.

## Changes

- `primus/backends/megatron/core/optimizer/triton_fused_adam.py`: `TritonFusedAdam`, a TE `FusedAdam` subclass.
  - Same host-side structure as the TorchTitan optimizer: static per-parameter kernel inputs are cached across steps, batched launches are issued while the host walks the parameters, and only gradients are re-validated each step.
  - Capturable, TE-managed master weights (precision-aware optimizer), decoupled grads, non-FP32 `exp_avg` / `exp_avg_sq`, FP8 / DTensor params, `grad_scaler`, `closure` and groups without bias correction use the TE step. Individual gradients the kernels cannot take are updated by torch's functional Adam in the same step.
  - Being a TE `FusedAdam` subclass keeps the distributed-optimizer `isinstance` check, per-group `step` bookkeeping and the checkpoint state layout unchanged.
- `primus/backends/megatron/patches/triton_fused_adam_patches.py`: when enabled, rebinds `megatron.core.optimizer.Adam`; skips with a warning if TE is not the active optimizer (e.g. `PRIMUS_TORCH_OPTIM=1`) or if the fused Adam + clip patch from #1219 is installed on TE `FusedAdam` (it defers gradient clipping into that step and runs first, priority 39 < 40).
- `trainer_base.yaml`: `use_triton_fused_adam: true` (a config without the flag is also treated as enabled); documented in `megatron-parameters.md`.
- `benchmark/kernel/optimizer/bench_fused_adamw.py`: adds a `megatron` implementation.
- Unit tests against TE `FusedAdam` (and torch AdamW for the per-gradient fallback).

## Testing

- MI355X (gfx950, `rocm/primus:v26.7`, TE 2.17 with the custom Adam kernel), this revision, medians of 3 (default grid 512):
  - Unit tests (`tests/unit_tests/core/kernels`, TorchTitan and Megatron optimizer tests): 38 passed.

    | Shapes | TE `FusedAdam` | Triton (this PR) | Previous revision |
    |---|---|---|---|
    | Llama 3.1 8B, 32 layers (291 tensors) | 39.89 ms | 39.75 ms (1.00x) | 0.97x |
    | 8 layers, `--split 64` (3729 tensors) | 22.80 ms | 17.64 ms (1.29x) | 0.88x |

  - Host preparation on 3729 tensors dropped from ~10 ms to ~6.7 ms and now overlaps the kernels: step time 17.7 ms vs 17.6 ms of GPU kernel time (previous revision 26.4 ms).
  - End-to-end Megatron Llama 3.1 8B (1 GPU, mbs 1, gbs 4, seq 4096, distributed optimizer, 20 iters): `optimizer-inner-step` 41.04 -> 39.21 ms (-4.5%), `optimizer` 71.95 -> 69.94 ms; lm loss identical for the first two steps, max difference 6.7e-3 afterwards (final 10.4645 vs 10.4697). The patch log line is present.
- MI455X (gfx1250, one A0 sample with `REV_ID 0x00`, so absolute times will differ on B0; `amdprimus/amdprimus:gfx1250-20260910`, TE 2.17 with the custom Adam kernel), this revision (default grid 4096):
  - Unit tests: 38 passed.

    | Shapes | TE `FusedAdam` | Triton (this PR) |

  - End-to-end Megatron Llama 3.1 8B (same setup as above), three flag-off/on pairs: `optimizer-inner-step` 22.4-22.6 -> 18.5-18.6 ms (-17.3% to -17.7%), `optimizer` 43.4-43.7 -> 39.6-39.8 ms (-8.7%); lm loss identical for the first two steps, max difference 4.7e-3 afterwards (final 10.46579 vs 10.46583). The patch log line is present.
