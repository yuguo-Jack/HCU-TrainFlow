# fix(runner): keep a preset HIP_VISIBLE_DEVICES instead of overwriting it

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1237) · state: closed · merged: True

## Original PR description

## Summary

`runner/helpers/envs/base_env.sh` unconditionally set `HIP_VISIBLE_DEVICES=$(seq -s, 0 $((GPUS_PER_NODE - 1)))`. A selection made by the user or the scheduler was silently replaced: for example `HIP_VISIBLE_DEVICES=2` with `GPUS_PER_NODE=1`, in a container that sees all 8 GPUs, became `0`, so on a shared node the job ran on another user's GPU. This was hit while running single-GPU benchmarks on a mixed MI355X node; the workaround was pinning with `ROCR_VISIBLE_DEVICES` instead.

## Changes

- `base_env.sh`: keep a preset `HIP_VISIBLE_DEVICES`; warn when it lists a different number of GPUs than `GPUS_PER_NODE`. The default for an unset variable is unchanged (`0..GPUS_PER_NODE-1`).
- `tests/runner/helpers/test_primus_env.sh`: Test 12 covers both cases.

## Behavior change

Jobs that export `HIP_VISIBLE_DEVICES` before the runner now keep it. If a launcher relied on the runner resetting a stale value, it will see the warning above when the count does not match `GPUS_PER_NODE`.

## Testing

- `bash tests/runner/helpers/test_primus_env.sh`: 13/13 passed; the new "preset is kept" check fails without the fix.
- `shellcheck` (v0.10.0.1, as in pre-commit) clean on both files.
