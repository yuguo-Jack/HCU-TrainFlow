# feat(mega_moe): adopt the Mega MoE buffers sized to the dispatched rows (Primus-Turbo #566, #568)

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1271) · state: closed · merged: True

## Original PR description

Summary (DeepSeek-V3 4-layer proxy, 8x MI355X, Mega MoE before -> after the Primus-Turbo change;
numbers from the Primus-Turbo PRs):

| precision | peak memory | TFLOP/s per GPU | loss | source |
|---|---|---|---|---|
| MXFP8 | 162.4 -> 149.3 GB (**-13.1 GB, -8.1%**) | 1118.4 -> 1131.3 (+1.2%) | same curve | [Primus-Turbo #566](https://github.com/AMD-AGI/Primus-Turbo/pull/566) |
| BF16 | 152.9 -> 122.3 GB (**-30.6 GB, -20.0%**) | 962.6 -> 955.5 (-0.7%) | same curve | [Primus-Turbo #568](https://github.com/AMD-AGI/Primus-Turbo/pull/568) |

# Description

Primus-Turbo #566 (MXFP8) and #568 (BF16) stop sizing every per-layer Mega MoE tensor at the
worst-case receive pool. Each layer reads the rows dispatched to this rank back once, after its
routing prologue, and allocates to them. This PR moves Primus onto that Primus-Turbo revision.
Primus's MegaMoE integration is unchanged; the work is in the CI image the new Primus-Turbo needs.

## Changes

- **Primus-Turbo `67b8e093` -> `de8fa6ca`**: #566, #568, the FlyDSL 0.3.4.1 / AITER v0.1.24.post1
  upgrade (#544) and MI455X optimization v1 (#567). AITER moves to v0.1.24.post1 with it.
- **CI base image `rocm/primus:v26.5` -> `v26.8`**, Triton 3.7.0 -> 3.9.0 (`release/3.9.x`). AITER
  installs with `AITER_USE_SYSTEM_TRITON=1`, so the pinned Triton stays the only one.
- **`-ainic` image:** v26.8 already carries the AINIC stack, so `-ainic` is the same image under that
  tag. The `Dockerfile.ainic` build stays in the workflow, commented out: it builds rccl rocm-7.1.0,
  which needs `rocm_smi`, and the ROCm 10.1 SDK in v26.8 no longer ships it.

## Behaviour changes

- **Mega MoE syncs with the host once per layer**, in both precisions, so a layer that contains it
  can no longer be captured in a CUDA graph. `examples/megatron/models/deepseek-v4/run_deepseek_v4.sh`
  still suggests full-layer capture with MegaMoE.
- **FlyDSL 0.3.4.1:** Primus's own FlyDSL kernels still target 0.2.4 and fail to import under it: the
  Kimi-K3 `_flydsl_v1` kernels and the DeepSeek-V4 `flydsl_v1` attention backend. They need a port to
  the 0.3.x API.

## Testing

- CI image build of this branch (`tasimage/primus:pr-1271`).
- On that image, 8x MI355X: the DeepSeek-V3 4-layer proxy trains 15 iterations with bf16 and MXFP8
  Mega MoE.
