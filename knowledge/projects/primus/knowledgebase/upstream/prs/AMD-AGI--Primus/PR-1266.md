# feat(tools/perf): record the platform with every batch; fix TorchTitan and Megatron-Bridge TFLOP/s

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1266) · state: open · merged: False

## Original PR description

## Summary
Every batch now records the platform it ran on, on every node: server and BIOS, CPUs, memory, GPU settings, host GPU driver and NICs. It also states it in one sentence, the form performance results are quoted with:
> Dual AMD EPYC 9575F 64-Core Processor-based Supermicro AS -4126GS-NMR-LCC server with 8x AMD Instinct MI355X (288GB HBM3E 1400W) GPUs, 1 NUMA node per socket, System BIOS 1.7, Ubuntu 22.04.5 LTS, Host GPU driver amdgpu 30.10.1 (ROCm 7.0.1)
It also fixes two throughput numbers the extractor got wrong. TorchTitan TFLOP/s at or above 1,000 were read as 1. Megatron-Bridge's post-training estimate was reported as TFLOP/s.
### Platform (`lib/common.sh`, `run_batch.sh`, `run_batch_multinode.sh`)
- Collected on every node without root, in about 3 s:
  - server, board and BIOS from DMI (vendor placeholders dropped)
  - CPU sockets, cores, threads and NUMA nodes (`lscpu`); frequency driver, boost, max clock, EPP and idle states
  - usable and installed memory and populated channels (EDAC); DIMM model with rated and configured speed (udev's DMI records)
  - per GPU, from the amdgpu sysfs files every Slurm step can read: memory, power cap (and its default when lowered), compute/memory partition, perf level and max sclk, VBIOS, PCIe link
  - host GPU driver release from the `amdgpu-dkms` package (deb or rpm; `…30100100` is 30.10.1), and the ROCm release of the host's repo.radeon.com repository
  - active RDMA ports with driver, rate and firmware; OS, kernel and kernel command line
- `batch_host_<stamp>.txt` has each node's values as `key: value` lines. After them comes the raw data: `lscpu`, `numactl -H`, idle states, DIMMs, per-GPU sysfs, RDMA ports, amdgpu module parameters, driver packages and repositories, Docker and network interfaces.
- The batch summary carries the one-line `System`. Every run banner carries it too, plus the fields behind it: server, BIOS, OS, kernel and command line, CPU topology, frequency and idle states, host memory, GPU VRAM, power cap, partition, clocks, VBIOS and PCIe, host GPU driver and package, RDMA NICs.
- Multi-node: `Host check` says whether every node reported the same platform. If not, the summary warns with the keys that differ, and the end of `batch_host_<stamp>.txt` lists each value with how many nodes had it. When the runner is not one of the nodes (e.g. salloc on a login node), the first node's platform is used.
- The GPU's marketing name and memory type come from amd-smi on the runner. Without it, the sysfs product name is used and the memory type is left out.
### Extraction and report (`extract_results.py` parser versions 5 and 6, `report.py`)
- 19 platform columns: `system_description`, `host_check`, `server`, `bios`, `os`, `kernel`, `kernel_cmdline`, `cpu_*`, `host_memory`, `gpu_*`, `rdma_nics`. They are appended, so readers that index columns by position keep working.
- Overview: the Hardware section shows the system description and every platform field per batch. Runs: a new System column.
### Fixes
- **TorchTitan TFLOP/s at or above 1,000.** TorchTitan prints `tflops: {tflops:,.2f}`. The pattern stopped at the comma, so `1,293.62` became 1. For llama3.1 8B/70B BF16/FP8 on MI355X, the reported value goes from 1.0 to between 1208.9 and 1701.5.
- **Megatron-Bridge post-training.** `MODEL_TFLOP/s/GPU` is an estimate: global batch × `seq_length` × FLOPs per token, divided by step time. Without packed sequences, post-training pads each micro-batch only to its longest sample, a few hundred tokens for SQuAD against a `seq_length` of 8192. So the Qwen3-32B LoRA recipe reported 13,987 TFLOP/s/GPU, about 5.6× MI355X's BF16 peak. For these runs (`post_trainer`, `packed_sequence` resolved to false, Megatron-Bridge's default):
  - the estimate is kept as `hmean_nominal_tflops` ("Nominal TFLOP/s per GPU" in the report), and `hmean_tflops` is empty
  - throughput is samples/s/GPU, from each iteration's global batch size and step time
  - `throughput_note` says why
  Pretraining and packed post-training keep their TFLOP/s.
- The Performance sheet drops its Notes column. "Runs ok / total" and the Runs sheet carry what it said.
## Behaviour changes to note
- Existing result directories: run `extract_results.py <dir>`, then `report.py`, to pick up the two fixes. `report.py` already re-parses a `results.json` from an older parser version, without writing it.
- Megatron-Bridge SFT/LoRA rows without packed sequences no longer have TFLOP/s. Compare them on nominal TFLOP/s or samples/s/GPU, within one config.
- Run banners are about 20 lines longer: 77 lines on MI355X, within the extractor's 200-line banner window.
- The Performance sheet has no Notes column.
