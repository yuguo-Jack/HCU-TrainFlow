# fix(megatron-bridge): load SQuAD by its namespaced id in the Zebra SFT configs

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1291) · state: closed · merged: True

## Original PR description

The Zebra Megatron-Bridge model configs (`primus/configs/models/megatron_bridge/zebra_mamba_{1B,3B,8B}_hybrid.yaml`) set `dataset: mock: true`, but the Zebra finetune recipe always builds its dataset from `default_squad_config(...)`. The setting had no effect, and the SFT runs loaded SQuAD under the id `squad`. `huggingface_hub` 1.x rejects repository ids without a namespace (`Repository id must be 'namespace/name', got 'squad'`), which stopped `zebra_mamba_{1B,3B,8B}_hybrid_sft_posttrain.yaml` at data setup. This PR names the dataset `rajpurkar/squad`, as the other Bridge model configs already do.

The Bridge Zebra configs only reach data setup with #1290, which fixes the `args is not initialized` error during model construction.

## Validation

8x MI300X, the 2026-10-22 Primus CI image (Primus 4321af16, `datasets` 5.0.1, `huggingface_hub` 1.33.0), with #1290 and this diff applied, using the stock example configs:

| Config | Iterations | Final lm loss |
|---|---|---|
| `zebra_mamba_1B_hybrid_sft_posttrain.yaml` | 200/200 | 9.169 |
| `zebra_mamba_3B_hybrid_sft_posttrain.yaml` | 200/200 | 9.049 |
| `zebra_mamba_8B_hybrid_sft_posttrain.yaml` | 200/200 | 10.340 |

These configs load no pretrained checkpoint (`pretrained_checkpoint: null`), so the losses stay high.

## Known problem, not fixed here

Rerunning a config whose checkpoint directory already holds a `torch_dist` checkpoint fails while loading it, with `TypeError: empty() got an unexpected keyword argument 'strides'` in `megatron/core/dist_checkpointing/strategies/torch.py` (`load_tensors_metadata`). Megatron-LM builds meta tensors with `torch.empty(tp.size, **tp.properties.__dict__, device='meta')`. The image's PyTorch (a 2.16 nightly) added a `strides` field to `torch.distributed.checkpoint.metadata.TensorProperties`, and `torch.empty` does not accept it. Runs that start without an existing checkpoint are unaffected.
