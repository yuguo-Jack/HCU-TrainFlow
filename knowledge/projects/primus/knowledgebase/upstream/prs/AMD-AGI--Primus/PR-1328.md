Mistral defaults an omitted `sliding_window` to 4096 and does not use `use_sliding_window` to disable it, so both a missing window key and `sliding_window=4096, use_sliding_window=false` incorrectly select the full-attention converter. - peymanr · comment · 2026-11-02T06:43:41Z · [source](https://github.com/AMD-AGI/Primus/pull/1328#discussion_r4439568169)

File: `runner/helpers/hooks/train/posttrain/megatron/01_convert_checkpoints.py` · line None

🤖 Primer agent: Thanks, fixed in this update. The Mistral rule now lives in one place, `primus/backends/megatron/checkpoint/llama_config_rules.py`, and the posttrain hook and `native_loader_llama.py` both use it. A missing `sliding_window` key is read as HF's default of 4096. Any window other than an explicit `sliding_window: null` is rejected, and `use_sliding_window` is never read. The hook keeps such configs on Megatron-Bridge and logs the reason; with `native_ckpt_convert: true` it stops with that reason. A direct converter call raises `ValueError`. The rule applies only to Mistral, so Llama configs that carry a `sliding_window` key still convert. `test_native_loader_mistral.py` covers a missing key, explicit 4096 and other window values. There is no separate case for `use_sliding_window: false`, but that flag has no effect on the check.
