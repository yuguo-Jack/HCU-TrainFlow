# posttrain: enable megatron patches for megatron-bridge and fix intermittent framework parsing

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/507) · state: closed · merged: True

## Original PR description

## What
This PR focuses on two issues:
1) Enable/ensure Megatron (and Megatron-Bridge) patches are active in the posttrain flow.
2) Fix intermittent failures where posttrain framework detection is corrupted by noisy stdout.

## Why
- Patches are required to keep behavior consistent across environments and apply known fixes automatically.
- Framework parsing could intermittently fail when unrelated stdout (e.g. "Created path: ...") polluted the captured output, leading to a wrong hook directory path.

## Key Changes
- `runner/helpers/hooks/train/posttrain/dispatch_framework.sh`
  - Make `FRAMEWORK` extraction robust by taking **only the last stdout line**.
  - Keep debug logs on stderr.
- (Other commits in this branch) Megatron-Bridge posttrain flow updates and examples/presets that help validate the patch+dispatch behavior.

The stderr redirection `2> >(tee /dev/stderr >&2)` is redundant since it duplicates stderr to itself. This construction doesn't add value and makes the command harder to understand. Consider simplifying to just `2>&1 >&2` if you need stderr visibility, or remove it entirely if the debug output to stderr is already sufficient.
```suggestion
" | tail -n 1 | tr -d '\r' || true)"
```
