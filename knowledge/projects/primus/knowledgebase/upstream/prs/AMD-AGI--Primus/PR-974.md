# Migrate Llama2 MLPerf SFT logging from local mlperf_sft to primus_mllog

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/974) · state: closed · merged: True

## Original PR description

## Summary
- Remove the duplicate `primus/backends/megatron_bridge/mlperf_sft/` package now that SFT MLPerf logging lives in `primus_mllog` (`mlperf-common`).
- Update `llama2_custom.py` to import `MLPerfSFTLogger` from `primus_mllog` instead of the local Megatron-Bridge copy.
- Fail fast when `ENABLE_MLLOG=1` but `primus_mllog` is unavailable, raising `ImportError: PRIMUS_MLLOG IS NOT FOUND`.

## Motivation
The Megatron-Bridge `mlperf_sft` module duplicated logic already provided by `primus_mllog`. Consolidating on `primus_mllog` avoids drift between two implementations and makes missing MLPerf dependencies obvious during MLPerf runs.

| `primus/backends/megatron_bridge/recipes/mlperf_llama2_70b/llama2_custom.py` | Import switched to `primus_mllog`; hard-fail on missing package |

## Test plan
- [ ] Verify `primus_mllog` is on `PYTHONPATH` (e.g. `mlperf-common` installed or mounted)
- [ ] Run Llama2-70B LoRA MLPerf posttrain with `ENABLE_MLLOG=1`:
  ```bash
  source examples/mlperf/llama2_70b/config_MI355X_1x8x1.sh
  bash examples/mlperf/llama2_70b/run_and_time.sh
  ```
- [ ] Confirm `:::MLLOG` init events are emitted (e.g. `opt_base_lr`, `max_steps`, `config_filename`)
- [ ] Confirm training completes without import errors when `primus_mllog` is present
- [ ] Negative test: remove `primus_mllog` from `PYTHONPATH` with `ENABLE_MLLOG=1` and confirm run aborts with:
  ```
  ImportError: PRIMUS_MLLOG IS NOT FOUND
  ```
- [ ] Confirm no remaining references to `primus.backends.megatron_bridge.mlperf_sft`

## Dependencies / notes
- Requires `primus_mllog` from `mlperf-common` to be available in the runtime environment (Docker image, `PYTHONPATH`, or install step).
- If CI fails with SIGTERM under torchrun, the underlying error is usually the missing import on a non-rank-0 worker; rerun with `MLPERF_VERBOSE_LOGS=1 PRIMUS_LOG_SUPPRESSION=0` to see the full traceback.
