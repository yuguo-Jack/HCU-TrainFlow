# Add SDXL, Mochi-1, and HunyuanVideo AMDiffusionBenchmark workloads

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1379) · state: closed · merged: True

## Original PR description


## Summary

Adds three AMDiffusionBenchmark workloads on top of current `main` (`1b077e2f`): SDXL, Mochi-1, and HunyuanVideo. This replaces #1342 (SDXL) and #1343 (HunyuanVideo), and re-lands Mochi-1, which was merged in #1345 and then reverted by #1377.

FLUX.1-dev (#1341) and Wan2.1 I2V (#1344) are already on `main` and are not changed here.

## Changes

- **Workloads**
  - SDXL: fine-tunes the in-tree Stability UNet (`sd_xl_base_1.0.safetensors` plus SDXL VAE).
  - Mochi-1: fine-tunes the Genmo `AsymmDiTJoint` DiT and VAE encoder, with T5-XXL.
  - HunyuanVideo: fine-tunes the Tencent `HYVideoDiffusionTransformer`, with a LLaMA text encoder and CLIP-L. If `PRETRAINED_PATH` is unset, `primus-cli` downloads `hunyuanvideo-community/HunyuanVideo`.
- **Model code**: adds in-tree `models/sdxl`, `models/mochi`, and `models/hunyuan`, each with an adapter and train pipeline.
- **Registration**: `registry.py`, `argument_builder.py`, and `registrations/{sdxl,mochi,hunyuan}.py` register the builders. `stable-diffusion-xl` is accepted as an alias for `sdxl`.
- **Configs**: per-model benchmark YAMLs for MI300X, MI325X, and MI355X, plus model configs under `configs/models/diffusion/`.
- **Shared utilities**
  - `download.py`: per-model companion files, and a shared Disney dataset pin (`Wild-Heart/Disney-VideoGeneration-Dataset` at `316b85f5…`) for Wan, Mochi, and Hunyuan.
  - `checkpoint_io.py`: loads directory checkpoints, refuses mixed formats and key overlap, guards SDXL against missing keys (over 50%), and uses `torch.load(weights_only=True)`.
  - `pixels.py`: a `normalized` flag so frames are normalized once.
  - `sampling.py`: `sample_amdb_sdxl_sigmas` for SDXL.
  - `trainers/benchmark.py`: `cached_sample_loader`.
- **Prepare hook**: `prepare.py` validates per-model encoders and downloads per-model assets. `synthetic:` dataset paths skip downloads.
- **Docs**: `examples/diffusion/README.md` and `primus/backends/diffusion/README.md` cover all five workloads, the dataset pin, the `DATASET_PATH=synthetic:hunyuan` mode, and the default `LOCAL_BATCH_SIZE` table.

We can close #1342 and #1343 once merged. #1345 is already closed.

**21. Mochi copies constant VAE statistics host-to-device every step** (`primus/backends/diffusion/models/mochi/train_pipeline.py:84`)

`MochiTrainPipeline.compute_loss` copies the constant `STATS['mean']` and `STATS['std']` (12 CPU floats each) to the GPU on every step. `SDXLTrainPipeline` caches its constant tables per device (`_alphas_on`, `_sigma_grid_on`). The cost is negligible, because the same function already forces a host sync each step via `sequence_lengths.max().item()`. Caching the two tensors per device would match the SDXL pipeline and remove the redundant copies; this is a consistency/cleanup nit, not a measurable slowdown.

**Who is affected:** Users post-training Mochi-1 with the new benchmark workload; every training step pays two tiny H2D copies.

_Checked against the code by an independent pass._
