# mi455x_v2: add MI455X Llama-3.1-8B example (FlyDSL attention) and hipBLASLt GEMM tuning

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1312) · state: closed · merged: True

## Original PR description

## Summary

Brings `dev/mi455x_v2` to `main`. Only `examples/` changes:

- Llama-3.1-8B pretraining on MI455X (#1288): `examples/megatron/models/llama3.1-8b/` (launcher, README) and
  `examples/megatron/configs/MI455X/llama3.1_8B-BF16-pretrain.yaml`. Attention runs on Primus-Turbo's FlyDSL
  kernels (AMD-AGI/Primus-Turbo#574, below).
- hipBLASLt tuning files for GPT-OSS 20B / 120B (#1296), and for the DeepSeek-V3 proxy and Llama-3.1-8B (#1295).
  Each launcher loads its file by default; `HIPBLASLT_TUNING_OVERRIDE_FILE=` restores hipBLASLt's own choice.

`main` (64fef81e) is merged in without conflicts. Of its changes, only #1286 (`te_ce_overwrite_input`) is on
these examples' path, and it is a no-op with the default image's TE (`parallel_cross_entropy` has no
`overwrite_input`).

## Primus-Turbo

The Primus-Turbo side is its `dev/mi455x_v2` branch (e3c6f03d): `main` ca1fdd67 plus

| PR | Change | Used by |
| --- | --- | --- |
| AMD-AGI/Primus-Turbo#574 | gfx1250 FlyDSL flash attention, head dim 128 | Llama-3.1-8B attention |
| AMD-AGI/Primus-Turbo#560 | gfx1250 FlyDSL sparse-MLA forward / backward (DeepSeek-V4) | none of these examples |

Llama-3.1-8B needs a checkout of it built in place as `TURBO_DIR` (see its README); AMD-AGI/Primus-Turbo#580
brings the branch to Primus-Turbo `main`. The DeepSeek-V3 proxy and GPT-OSS run on the image's Primus-Turbo
(`main` 21588d59).

## Results

This branch (d1144a89) on one node of 4x MI455X, `amdprimus/amdprimus:tas-20261019`, launcher defaults. ms/iter is
the average of iterations 3-10, mean of 3 runs per row that alternated between the rows of a table. DeepSeek-V3
and GPT-OSS on the image's Primus-Turbo, Llama-3.1-8B on Primus-Turbo `dev/mi455x_v2` (e3c6f03d).

| Example | Baseline | + FlyDSL | + hipBLASLt tuning (default) |
| --- | --- | --- | --- |
| DeepSeek-V3 proxy (EP4, 128 experts) | 2143 | 1159 (1.85x) | **1099 (1.95x)** |
| Llama-3.1-8B (DP4) | 1946 | 1137 (1.71x) | **1047 (1.86x)** |

Baseline: TE unfused attention and Triton grouped GEMM (DeepSeek-V3), Primus-Turbo Triton attention (Llama).

GPT-OSS (EP4, MBS 8 / GBS 64):

| Model | hipBLASLt default | + hipBLASLt tuning (default) |
| --- | --- | --- |
| GPT-OSS 20B | 2204 | **2118 (1.04x)** |
| GPT-OSS 120B proxy, 8 of 36 layers | 852 | **821 (1.04x)** |

The 120B row uses the README's "120B tuning" settings. The 120B yaml (MBS 1) is unchanged: there only the
shared-expert GEMMs are tuned, about 0.6 ms of a 447 ms iteration.

lm loss and grad norms match the READMEs, with no NaN. The READMEs were measured on another MI455X node: the
baselines and GPT-OSS rows agree within 0.6%, while the FlyDSL rows differ by up to 3.5% between the two nodes
(DeepSeek-V3 faster on this one, Llama-3.1-8B slower).

- copilot-pull-request-reviewer[bot] · comment · 2026-10-26T09:30:04Z · [source](https://github.com/AMD-AGI/Primus/pull/1312#discussion_r4375729158)

File: `examples/megatron/models/gpt-oss/run_gpt_oss_mi455x.sh` · line 39

Passing the tuning-file variable into Docker does not make the referenced host file available there: this launcher only mounts the repository. For example, `HIPBLASLT_TUNING_OVERRIDE_FILE=/tmp/custom-tuning.txt` reaches the container as a nonexistent path, so the requested tuning cannot be loaded. Resolve nonempty host override paths and add a read-only bind mount before starting Docker, as the other two launchers do.

- copilot-pull-request-reviewer[bot] · comment · 2026-10-26T09:30:05Z · [source](https://github.com/AMD-AGI/Primus/pull/1312#discussion_r4375729216)

File: `examples/megatron/models/gpt-oss/run_gpt_oss_mi455x.sh` · line 65

When running `PRIMUS_LAUNCHER=direct PRIMUS_HIPBLASLT_TUNING=1 PRIMUS_HIPBLASLT_TUNING_STAGE=3`, this unconditional default causes the tuning hook to select the bundled file instead of the result generated by stage 2. `prepare_experiment.sh:251` prefers any nonempty override, so re-tuning a different shape or hipBLASLt build is silently ignored. Suppress the bundled default during automatic tuning, as the DeepSeek and Llama launchers already do.

- copilot-pull-request-reviewer[bot] · comment · 2026-10-26T09:35:37Z · [source](https://github.com/AMD-AGI/Primus/pull/1312#discussion_r4375771041)

File: `examples/megatron/models/llama3.1-8b/run_llama3.1_8b_mi455x.sh` · line 95

The documented `PRIMUS_WORKSPACE` setting is forwarded into the container, but only the repository is mounted for output. Setting it to a host directory outside the checkout, such as `/scratch/primus-output`, writes the logs and profiler traces into the container's private filesystem; `docker run --rm` then deletes them on exit. Please create and bind-mount the resolved workspace so custom output locations persist on the host.
