# [WIP] feat(megatron): opt-in pinned-Triton fusions for DeepSeek-V3 on MI455X

[Upstream PR](https://github.com/AMD-AGI/Primus/pull/1259) · state: open · merged: False

## Original PR description

## Summary

Six opt-in Megatron-backend optimizations for DeepSeek-V3 pretraining on MI455X (gfx1250). Each one has its own
switch in `primus_megatron_module.yaml`, and every switch defaults to `false`, so nothing changes unless a config
turns it on. Every Triton kernel launches with one pinned config: no in-process autotuning, since benchmarking
autotune candidates inside the training process can hang on gfx1250.

| Switch | What it does |
|---|---|
| `use_primus_pinned_triton_configs` | Pins the in-process autotuners of Megatron's MLA YaRN RoPE fusion (`apply_rope_fusion`, BLOCK_H 32) and the MoE permutation fusion (`moe_permute_fusion`, Primus' copy and TE's module, BLOCK_SIZE 1024) to one stock config each. Every requested kernel is resolved before any is pinned; the run aborts at `before_train` if a Primus or Megatron kernel cannot be pinned (TE's module is optional and skipped). |
| `use_primus_fused_lm_cross_entropy` | `compute_language_model_loss` on two Triton kernels, gradient written in place into the logits buffer (the autograd version counter is bumped, so a node that also saved the logits raises). TP=1, contiguous `[s, b, V]` logits; other calls keep Megatron's CE. |
| `use_primus_fused_swiglu` | Prob-weighted and plain SwiGLU fwd/bwd as one Triton kernel per direction (fp32 math, one rounding). Calls with bias, clamp, fp8 store or CPU offload keep the original function. |
| `use_primus_triton_router_gemm` | MoE router gating linear (fp32 logits, no bias) fwd/dgrad/wgrad on three Triton kernels. Exactly 32 experts; other calls keep the original path. Pair it with `moe_router_fusion`. |
| `use_primus_triton_adamw_step` | DistributedOptimizer step: deferred grad clip + AdamW + bf16 model-param write in one pass per parameter, bitwise equal to TE FusedAdam + clip + copy on gfx1250. Not enabled (with a warning) for the precision-aware optimizer, non-fp32 moments, FSDP or fp8 params. Unlike `PRIMUS_FUSED_ADAM_CLIP` (a HIP extension of TE's Adam kernel), it is Triton, keeps Megatron's clip coefficient and also does the bf16 copy; the two are mutually exclusive. |
| `use_primus_global_grad_nan_check` | Checks the global grad norm for NaN/Inf before the update, instead of a norm plus two host syncs per DDP bucket. Needs `check_for_nan_in_loss_and_grad`, `clip_grad > 0` and `rerun_mode: disabled`. Narrower than the bucket check: grads left out of the norm (TP-duplicate params on tp_rank > 0) are not checked. |

Every switch logs once per reason when a call takes the original path, and warns when it is enabled on a GPU other
than gfx1250, where the pinned configs were chosen and validated.

## Scope / caveats

- Validated on gfx1250 (MI455X) only. With all switches off, the patch modules import nothing beyond the patch API
  and the applied-patch lists are unchanged for every model config. The new kernels compile for gfx950 and gfx942
  (compile only; no runtime check there).
- In the MI455X example config, four switches can take effect (pinned configs, CE, SwiGLU, NaN check). Router GEMM
  needs 32 experts (the example has 128) and the fused AdamW step needs fp32 moments (the example uses the
  precision-aware optimizer with bf16 state).
- `turbo_sync_free_moe_stage >= 1` forces `moe_permute_fusion` and the Turbo fused router back on in
  `validate_args`. Use stage 0 to control the permute fusion and to reach `moe_router_fusion`.
- Enable the switches through the config or as extra arguments to `run_deepseek_v3_proxy_mi455x.sh`, e.g.
  `--use_primus_pinned_triton_configs True --apply_rope_fusion True --moe_permute_fusion True --use_primus_fused_lm_cross_entropy True --cross_entropy_loss_fusion False --use_primus_fused_swiglu True --turbo_sync_free_moe_stage 0 --moe_use_fused_router_with_aux_score False --use_primus_triton_router_gemm True --moe_router_fusion True --use_primus_triton_adamw_step True --use_primus_global_grad_nan_check True`

## Results (1x MI455X)

DeepSeek-V3 proxy through `run_deepseek_v3_proxy_mi455x.sh`, one GPU: 4 MoE layers, 32 experts, EP1, top-8,
seq 4096, MBS 2, GBS 16, mock data, Primus-Turbo `dev/mi455x_v1` (e1a967a0), FlyDSL attention and FlyDSL bf16
grouped GEMM, fp32 optimizer state, `torch.compile` off. Median step time over iterations 11-30.

| Switches | Step (ms) | tokens/s/GPU | Max mem (GB) |
|---|---|---|---|
| none | 1459.8 | 44892 | 161.4 |
| all six | 1094.8 | 59864 | 161.3 |

One switch at a time (ms/step vs none): RoPE + permutation pinning -205, SwiGLU -89, CE -48, router GEMM -21,
AdamW step + NaN check -18. The sum (-381) exceeds the combined -365 because the GPU clock drops when the
remaining work is GEMM- and attention-dominated.

## Accuracy

- AdamW step + global NaN check: loss and grad norm identical to the baseline over 30 iterations.
- CE and router GEMM: per-iteration loss within 4e-5 / 6e-5 (mean relative), no systematic sign.
- SwiGLU: the fused kernel is more accurate than the eager bf16 chain it replaces (fp64 reference: output and
  input grad 55.6 dB vs 50-52 dB, prob grad 139.9 dB vs 52.8 dB; the eager chain has a small mean bias), which
  shows as a small consistent loss offset early in training.
- All six over 200 iterations: no drift; mean relative loss difference 2.9e-4 with alternating sign; final loss
  0.032421 vs 0.032416; grad norm identical at the end.

## Tests

- Unit tests under `tests/unit_tests/backends/megatron/` (`test_pinned_triton_configs_patches.py`,
  `test_fused_lm_cross_entropy_patches.py`, `test_fused_swiglu_patches.py`, `test_triton_router_gemm_patches.py`,
  `test_triton_adamw_step_patches.py`, `test_primus_opt_in_patch_gates.py`): gates, fallbacks, eligibility,
  default-off behaviour, and GPU numerics against the reference paths. 84/84 pass on MI455X; on CPU 69 pass and
  the GPU cases skip. The bitwise comparison with TE FusedAdam is asserted on gfx1250 and uses a tight tolerance
  elsewhere; the pinning tests restore the real autotuners.
- The GPU tests have not run on MI355X yet: please run the PR with the `ci:gpu` label before merging.
- pre-commit passes on all changed files.
