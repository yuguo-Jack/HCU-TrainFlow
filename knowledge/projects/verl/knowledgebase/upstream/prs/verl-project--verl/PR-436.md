# Fix a bug for grad norm computation in SFT. Get loss 10% lower after fixing this bug

[Upstream PR](https://github.com/verl-project/verl/pull/436) · state: open · merged: False

## Original PR description

Thanks for your great work on veRL! However, the current implementation in SFT for grad accumulation seems wrong. The loss should be divided first, then do backward. Experiments show that fixing this bug can get loss 10% lower (from 2.7 -> 2.4) on some tasks

Of course yes if the grad norm is divided first. Note that when every micro batch comes in, it only contributes to its fraction in the final batch, both for loss and for grad norm, so I'm very sure to implement correct micro-batching, each micro batch should be forward and backward first (with the loss divided before doing backward), then finally do the norm clip.

- hiyouga · comment · 2025-03-05T06:41:48Z · [source](https://github.com/verl-project/verl/pull/436#discussion_r1980793840)

File: `verl/trainer/fsdp_sft_trainer.py` · line 400

It's ok to perform backprop for each microbatch data, but I think the `clip_grad_norm` operation can be done after computing gradients for all micro-batches.

Suggest change:
```python
        for micro_batch in micro_batches:
            loss = self._compute_loss_and_backward(batch=micro_batch, do_backward=False) / n_micro_batches
            loss.backward()
            step_loss += loss.item()

        grad_norm = self.fsdp_model.clip_grad_norm_(max_norm=self.config.optim.clip_grad)
```
