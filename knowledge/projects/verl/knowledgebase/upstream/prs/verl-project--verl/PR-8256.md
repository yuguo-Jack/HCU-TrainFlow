# [model] fix: support Transformers 5 Qwen3.5 dynamic cache

[Upstream PR](https://github.com/verl-project/verl/pull/8256) · state: open · merged: False

## Original PR description

### What does this PR do?

Fix cached Qwen3.5 forwards with Transformers 5, where convolution and recurrent state are stored in layer-scoped `DynamicCache` entries. The existing code accesses legacy top-level arrays and raises:

```text
AttributeError: 'DynamicCache' object has no attribute 'conv_states'
```

The patch reads and updates both legacy and layer-scoped cache state, including tensor-valued and state-indexed entries. Multi-token continuation retains the previous convolution context and recurrent state; single-token decoding uses the recurrent update path.

### Design & Code Changes

- Add cache access/update helpers and select state index zero for indexed entries.
- Carry cached state through chunked continuation and retain outputs for the new tokens.
- Resolve gated-delta-net kernels from instance attributes or the Transformers module.
- Add CPU regression coverage for prefill, multi-token continuation, single-token decode, and chunk/token equivalence.

Related work: [#7471](https://github.com/verl-project/verl/pull/7471) also changes kernel resolution in `qwen3_5.py` and addresses decoder block-type names. This PR additionally fixes the cache-state API and continuation behavior. The overlapping kernel-resolution changes need coordination before merge.

The cases cover real `DynamicCache` objects, tensor-valued cache entries, state-indexed entries, and selection of the active state flag.

Earlier A3 GRPO smoke validation exercised rollout, reward computation, actor update, and vLLM weight synchronization with a non-zero actor gradient. A separate recorded run stopped in the generic nested-tensor actor indexer with `split_with_sizes` after reaching reward computation. End-to-end training validation remains outstanding.

Experiment records: [cache-only success smoke](https://swanlab.cn/@lzc12138/qwen35_dynamic_cache/runs/1wgahoxs), [comparison run](https://swanlab.cn/@lzc12138/qwen35_dynamic_cache/runs/j5l30vlp).

### API and Usage

Existing Qwen3.5 callers use the compatible cache handling automatically. Legacy cache objects remain supported.
