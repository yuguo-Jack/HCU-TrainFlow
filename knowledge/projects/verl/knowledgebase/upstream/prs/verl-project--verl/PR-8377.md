# [training_utils] fix: keep confident-label logprobs and gradients in the torch logprob path

[Upstream PR](https://github.com/verl-project/verl/pull/8377) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes the torch log-prob path (`logprobs_from_logits_naive` and `logprobs_from_logits_v2`) so a confident label keeps its logprob and gradient. Before this change both rounded to exactly 0 once the label's margin over the other logits passed ~16.6 in fp32 (~5.5 for v2's bf16 branch on CPU), while the other logits kept nonzero gradients. Part of #8376, which has a repro; the Triton fused-kernel half is #8378.

Following Barron et al., "A Fix for Softmax and Cross-Entropy" (arXiv:2610.31642), the label logprob is computed as `logp_t = -softplus(logsumexp_{j != t}(z_j) - z_t)`, with the label left out of the logsumexp.

### API and Usage Example

No API changes. Results match `log_softmax` at ordinary margins, and differ from `main` only where `main` had rounded to 0. bf16 inputs are now computed in fp32 and cast back to bf16.

### Design & Code Changes

- New `_LabelLogprobs` `autograd.Function` in `verl/utils/torch_functional.py`:
  - **Forward:** gathers the label logit, then takes the logsumexp of a copy of the logits with the label set to `-inf`, in at least fp32. It saves the full `logsumexp(z) = logaddexp(logsumexp_{j != t}(z_j), z_t)` for backward. Rebuilding it as `z_t - logp_t` would give NaN for a `-inf` label.
  - **Backward:** recomputes `p_j = exp(z_j - logsumexp(z))` from the saved input. It returns `-p_j` for the other logits and `1 - p_t = -expm1(logp_t)` at the label. Only the input logits and per-label values are saved. Backward is `once_differentiable`: second derivatives through it aren't supported.
- `logprobs_from_logits_naive` calls it on the full logits. `logprobs_from_logits_v2` keeps its row loop and calls it per row, and its separate bf16 `log_softmax` branch is gone.
- Not touched: the flash-attn and NPU cross-entropy dispatch in `logprobs_from_logits`. On CUDA with flash-attn installed, those still serve the default path; see #8376.
