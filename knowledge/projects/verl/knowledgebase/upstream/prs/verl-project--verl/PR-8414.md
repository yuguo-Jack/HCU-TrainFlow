# [model] perf: build Qwen3-VL/Qwen3.5 pos-embed interpolation tensors without Python lists

[Upstream PR](https://github.com/verl-project/verl/pull/8414) · state: open · merged: False

## Original PR description


### What does this PR do?

`fast_pos_embed_interpolate` (patched into Qwen3-VL, Qwen3-VL-MoE, Qwen3.5 and Qwen3.5-MoE vision towers) converts every
bilinear interpolation index and weight to Python lists via `.tolist()` / `.extend()`, then rebuilds tensors from those
lists with `torch.tensor(...)` on every vision forward. For multi-image batches this is tens of thousands of Python
objects per forward.

This PR keeps the per-image tensors, concatenates them, and copies them to the target device once. The CPU arithmetic is
unchanged, so the output is bitwise identical to the previous implementation.

Related: #5572 and #5948 (both open) also touch `fast_pos_embed_interpolate` for device placement / refactoring, but keep the `.tolist()` round trip. This change is independent of them and easy to rebase onto either.

### Test

New CPU test `tests/models/test_qwen_vl_pos_embed_interpolate_on_cpu.py` compares both patched functions
(`qwen3_vl`, `qwen3_5`) against the previous implementation with `torch.equal`, for FP32 and BF16 and for
single/multi-image, `t > 1`, and grids larger than `num_grid_per_side` (16 cases). Passes on transformers 5.5.3
(`verlai/verl:vllm024.dev1`) and 5.8.1 with torch 2.11.

Index/weight construction only (`hidden_size=1`, 8 CPU threads, median of 7):

| grid_thw | before | after |
| --- | ---: | ---: |
| 1 x [1, 32, 32] | 1.1 ms | 0.3 ms |
| 8 x [1, 46, 80] | 25.1 ms | 2.2 ms |
| 32 x [1, 46, 80] | 106.5 ms | 8.8 ms |

On GPU (1x A100-80GB, torch 2.11 + CUDA 13.0, transformers 5.8.1), with a random-weight Qwen3-VL vision tower at
Qwen3-VL-8B sizes (depth 27, hidden 1152, bf16, SDPA, `no_grad`). The output of both patched functions and of the full
vision forward is bitwise identical to the previous implementation on CUDA. Old/new runs interleaved, median:

| grid_thw | `fast_pos_embed_interpolate` before | after | vision tower forward before | after | saved |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 x [1, 32, 32] | 1.3 ms | 0.6 ms | 37.1 ms | 36.3 ms | 0.7 ms (2.0%) |
| 8 x [1, 46, 80] | 24.8 ms | 3.9 ms | 361.4 ms | 347.5 ms | 13.9 ms (3.8%) |
| 32 x [1, 46, 80] | 98.3 ms | 14.1 ms | 1458.3 ms | 1378.6 ms | 79.8 ms (5.5%) |

The interpolation runs on the host before the vision blocks are launched, so the GPU idles while it runs and the
saved host time shows up almost one-to-one in the forward latency.

### API and Usage Example

No API or config change.

### Design & Code Changes

- `verl/models/transformers/qwen3_vl.py`, `verl/models/transformers/qwen3_5.py`: append per-image index/weight tensors
  instead of extending Python lists; build `idx_tensor` / `weight_tensor` with `torch.stack(torch.cat(...))` followed by a
  single `.to(device, dtype)`. Interpolation math, the sequential BF16 summation order, and the merge permutation are
  untouched.
