# fix: run dense fused kernels through the FSDP2 LM head

[Upstream PR](https://github.com/verl-project/verl/pull/8312) · state: open · merged: False

## Original PR description

## What does this PR do?

Fix the generic torch fused forward path for FSDP2-managed LM heads,
including models such as Qwen3.

Previously, the fused forward accessed `lm_head.weight` directly,
bypassing the LM head's FSDP2 hooks and potentially mixing regular
Tensors with DTensors during matrix multiplication.

This change installs a fused LM head forward during backend initialization
and runs fused computation through `self.lm_head(...)`. It preserves
torch/liger backend selection and handles DTensor weights, device placement,
and hidden-state dtype inside the module boundary.

The Triton path is unchanged.
