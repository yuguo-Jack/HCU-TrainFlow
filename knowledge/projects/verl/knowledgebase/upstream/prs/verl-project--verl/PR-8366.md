# [rollout, vllm] fix: keep vLLM compile mode working under full_determinism

[Upstream PR](https://github.com/verl-project/verl/pull/8366) · state: open · merged: False

## Original PR description

### What does this PR do?

`actor_rollout_ref.rollout.full_determinism=true` does not work with the default vLLM compile mode on the pinned stack (vllm 0.29.0, torch 2.13). The vLLM engine fails during startup:

```
torch._inductor.exc.InductorError: RuntimeError: In the deterministic mode of Inductor, we will avoid those
benchmarkings that would cause non-deterministic results. ...
  scheduler.py create_combo_kernel_nodes -> speedup_by_combo_kernel -> benchmark_fused_nodes -> may_ban_benchmarking
RuntimeError: Engine core initialization failed.
```

**Cause:**
1. `enable_full_determinism()` runs in the vLLM server and calls `torch.use_deterministic_algorithms(True)`. That call also sets `torch._inductor.config.deterministic = True`.
2. In this mode Inductor refuses to benchmark kernels.
3. vLLM before v0.32 sets `inductor_compile_config["benchmark_combo_kernel"] = True` unconditionally on torch >= 2.9, so `torch.compile` of the model aborts.

vLLM fixed this upstream in vllm-project/vllm#59074, which turns off combo-kernel benchmarking in deterministic mode. That fix first ships in v0.32.0, so 0.29 (pinned) and 0.30 (#8072) are both affected. The determinism tests in this repo all set `enforce_eager=true`, so CI does not exercise the compile path. The setup in `docs/advance/determinism.md` does not mention `enforce_eager`, so users following it hit the crash.

**Fix:** when `full_determinism` is on, the vLLM server sets `combo_kernels=True, benchmark_combo_kernel=False` in `compilation_config.inductor_compile_config`, the same values vLLM >= 0.32 chooses itself. If the user already set either key through `engine_kwargs.vllm.compilation_config`, it is left alone. Nothing changes when `full_determinism` is off.

**Not a duplicate:** I searched issues and PRs for `full_determinism`, `deterministic mode of Inductor` and `benchmark_combo_kernel`. The open ones (#7667, #8026) cover routing and actor-side batch invariance, not this startup failure.

### Design & Code Changes

- `verl/workers/rollout/vllm_rollout/utils.py`: new `apply_deterministic_inductor_defaults(compilation_config)`.
- `verl/workers/rollout/vllm_rollout/vllm_async_server.py`: call it while building `compilation_config` when `config.full_determinism` is set.

Once verl moves to vLLM >= 0.32, the helper is a no-op in effect, since vLLM picks the same values, and it can be removed.
