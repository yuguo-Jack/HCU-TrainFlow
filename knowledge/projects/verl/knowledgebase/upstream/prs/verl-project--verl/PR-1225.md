- paulinebourigault · comment · 2025-04-25T12:49:59Z · [source](https://github.com/verl-project/verl/pull/1225#issuecomment-2830343182)

Hi @patrik-bartak, thank you that's a valid point to consider, but I think that it is not necessary to change the implementation. 

Here's why:
1. **Current Implementation**: We're adding the token length logging right after we calculate the rewards, inside the training loop. This is exactly when we have access to the reward scores and response tokens needed to calculate positive vs negative token lengths.
2. **Alternative Approach**: Your suggestion to add the token length metrics to the general metrics dictionary at the end of each iteration would then be logged all at once.

The current approach is actually better because:
1. **Data Availability**: Token length calculation depends on specific data that's readily available after reward calculation (responses, rewards, attention masks). Moving it to the end might require keeping unnecessary references to this data.
2. **Immediate Logging**: Logging the token lengths immediately gives you more granular tracking, not dependent on the metrics aggregation.
3. **Separation**: The token length tracking is a specific feature with its own parameters, while metrics at the end typically aggregate training statistics (loss, gradients, etc.).

The current implementation logs token lengths right after reward calculation. It captures the data when it's available and logs it at an appropriate point in the training loop.
