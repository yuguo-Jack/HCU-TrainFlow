# [rollout, vllm] feat: support KV cache FP8

[Upstream PR](https://github.com/verl-project/verl/pull/4435) · state: open · merged: False

## Original PR description

### What does this PR do?

This PR adds support for FP8 KV cache quantization in vLLM rollout, providing significant memory savings during inference. The KV cache quantization can be used independently or combined with weight and activation FP8 quantization https://github.com/volcengine/verl/blob/main/docs/advance/fp8.md. 

**How it works:**
Leverage vllm to dynamically calculate qkv scales for FP8 KV cache quantization(requires vllm 0.11.2).​ vllm only performs the calculation in the first forward. For RL training, the calculation needs to be triggered every training step to adapt to the new model weights. ​After weights update of each training step, reset the `calculate_kv_scales` flag to True for all the attention layers.​ So for FP8 rollout, functionally we can have:

- FP8-linear W8A8
- KV cache FP8 (for storage only)
- FP8-linear W8A8 + KV cache FP8 (for storage and attention calculation)​

As this function requires vllm 0.11.2, the PR also includes some changes for v0.11.2 compatibility

**Experiments and results:** 

- Model: Qwen3-8B-Base
- Configuration​:

  - DAPO recipe. AIME24 online validation.​
  - 1*8*H100. veRL,  FP8 async rollout, vllm+FSDP​
  - Prompt batch size 32​
  - Rollout batch size: 32x3x16​
  - Train_batch_size & ppo_mini_batch_size 32​
  - Max response length 20K​
  - Token-level TIS, C=2​
  - vllm0.11.2+cuda12.9+DeepGEMM+CUDA Graph
 

- Accuracy: 
  - KV cache FP8 aligns well with BF16 on online validation. Full FP8 is also mostly aligned.

<img width="814" height="639" alt="image" src="https://github.com/user-attachments/assets/2f2dc830-0d73-4161-832e-08c9fa964e79" />

- Performance:
  - FP8 linear W8A8 vs BF16:  up to 20% speedup​
  - KV cache FP8 only vs BF16: ~38% rollout speedup.​
  - FP8 linear W8A8 + KV cache FP8 vs BF16 about ~44% speedup ​
