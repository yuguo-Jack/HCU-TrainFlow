# [hardware, doc] feat: run the TPU GRPO smoke test on 2 chips, derive the DP shard size from TP, and fix SFT torchrun

[Upstream PR](https://github.com/verl-project/verl/pull/8288) · state: open · merged: False

## Original PR description

### What does this PR do?

Combines three TPU example PRs into one so they can be reviewed and merged together. It supersedes #8266, #8271 and #8280. Only `examples/tpu/` changes; no library code.

### Changes

**1. 2-chip GRPO smoke test (from #8266)**

- The Qwen3-0.6B GRPO example now needs 2 chips (2x `v6e-1`) instead of 8 (2x `v6e-4`): one trainer chip and one rollout chip.
- `ray-tpu-v6e4-2slice.yaml` is renamed to `ray-tpu-v6e-2slice.yaml` and defaults to two `v6e-1` slices. Comments give the `v6e-4` / `v6e-8` values.
- `run_qwen3_0_6b_torchtitan.sh` defaults to `N_CHIPS_TRAINER=1 N_CHIPS_ROLLOUT=1` and uses the same trainer and rollout settings as `run_qwen3_4b_torchtitan.sh`.
- `examples/tpu/grpo/README.md`: the 2-chip flow is the default. A new section covers Qwen3-4B on 2x `v6e-4` and 2x `v6e-8`.

**2. DP shard size derived from TP (from #8280)**

- In all three TPU scripts, `DATA_PARALLEL_SHARD_SIZE` defaults to `TOTAL_TRAINER_CHIPS / TENSOR_PARALLEL_SIZE`.
- The default is unchanged at `TENSOR_PARALLEL_SIZE=1` (pure FSDP, still the fastest setting). With `TENSOR_PARALLEL_SIZE>1`, `dp_shard * tp == world_size` now holds without a manual override.
- Removed the outdated warning that TP>1 gives non-finite gradients on TPU. TP support lands in the companion plugin PR verl-project/verl-hardware-plugin#62.

**3. SFT `torchrun` fixes (from #8271)**

- `run_qwen3_0_6b_torchtitan.sh` used to abort under `set -u` when `TPU_WORKER_HOSTNAMES` was unset. Now `MASTER_ADDR` falls back to `127.0.0.1` on single-host runs, and multi-host runs exit early with a clear error if no routable master is set.
- `examples/tpu/sft/README.md` is updated for the `torchrun` default. The `ray job submit` examples now pass `SFT_TRAINER_MODE=ray` and the `verl-hardware-plugin` runtime env.

**Review follow-ups (CodeRabbit comments on #8271 / #8280)**

- Multi-host `torchrun` no longer silently falls back to loopback.
- The SFT README commands drop the explicit `DATA_PARALLEL_SHARD_SIZE`, and the README says that any explicit value times `TENSOR_PARALLEL_SIZE` must equal the trainer chip count.

**Validate that `TENSOR_PARALLEL_SIZE` divides `TOTAL_TRAINER_CHIPS`.**

The default `DATA_PARALLEL_SHARD_SIZE` uses integer division. If `TENSOR_PARALLEL_SIZE` is `0`, the script fails with a bash arithmetic error. If it does not divide `TOTAL_TRAINER_CHIPS`, the quotient is truncated. `dp_shard * tp` then differs from the world size, and the failure appears later inside TorchTitan. The same applies to the `DATA_PARALLEL_SHARD_SIZE` line in `run_qwen3_4b_torchtitan.sh`. Add an early check with a clear message.
