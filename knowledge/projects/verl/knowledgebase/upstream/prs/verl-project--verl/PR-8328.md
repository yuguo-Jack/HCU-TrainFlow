# [ci, fsdp] feat: capture Ascend environment and weight transfer diagnostics

[Upstream PR](https://github.com/verl-project/verl/pull/8328) · state: open · merged: False

## Original PR description

### What does this PR do?

Capture evidence for the Ascend nightly-ci Qwen3-VL accuracy regression. Local runs of the failing CI revision have not reproduced the collapse, so the full Qwen3-VL nightly job now saves environment/content fingerprints, bounded per-worker weight-path records, and full training logs as an artifact.

This is diagnostic instrumentation, not a proposed numerical fix. Default metadata mode does not copy tensors, read tensor values, synchronize devices, or introduce collectives. Python/file I/O can still affect timing. An explicitly selected values mode adds synchronization and local-shard SHA256/nonfinite checks for a separate intrusive control.

Duplicate-work check: open PR searches for `8187 in:body`, `Ascend diagnostics`, and `offload logging` found no implementation of this environment plus FSDP2/rollout diagnostic path. Related results address PEFT compatibility, Megatron allocation failures, or FP8 quantization auditing rather than this investigation.

AI assistance was used to implement and test these diagnostics. This draft is for the submitting human to review every changed line, run the relevant Ascend CI, and assess the results before requesting final review or merging.

### API and Usage Example

The `nightly_ci_ascend` workflow now accepts ordinary `pull_request` events targeting main, filtered to relevant source/configuration/workflow/diagnostic paths. Opening, updating, or reopening a matching PR runs `nightlyCI_grpo_qwen3_vl_8b_Instruct_fsdp2_vllm_ascend` using the normal PR merge ref and repository approval process. No label or workflow_dispatch entry is needed.

This is the full nightly job: the original 16-NPU runner, container, 160 GiB shared memory, train batch 32, mini batch 16, launcher default 15 training steps, and baseline download/check remain. It does not depend on the E2E LLM job. The existing one-step E2E workflow is unchanged.

All schedules and all other nightly jobs are unchanged; their existing schedule conditions skip them on PR events. Re-running historical Actions still uses historical code.

For local collection, use `tests/special_npu/env_diagnostics/collect.py` with the same Python/container/model/data. Set `VERL_WEIGHT_DIAGNOSTICS_DIR` to enable worker diagnostics, `VERL_WEIGHT_DIAGNOSTICS_MODE=metadata` by default, and `VERL_WEIGHT_DIAGNOSTICS_LIMIT=2` to bound records per process/stage/model.

Download `ascend-diagnostics-<run id>-<attempt>`: environment/report.json, weights/*.jsonl, weight-summary.json, full training output, original launcher log, and the downloaded baseline/checker. Artifacts are retained for 14 days and upload is attempted even after failure. Host loss/forced termination can still prevent upload.

### Design & Code Changes

- Stdlib environment collector records package origins and source/binary hashes, CANN/driver/firmware information, NPU topology, process/container resource limits, selected redacted environment variables, and complete model/data file hashes. Unknown image digest and incomplete probes remain explicit.
- FSDP2 records checkpoint input, set_model_state_dict completion, buffer broadcast completion, offload/reload boundaries, and actor export; vLLM records the first two incoming buckets and the model after loading. Ray explicitly forwards the three opt-in diagnostic variables.
- Each worker writes a separate JSONL with rank, model identity, local-shard layout/dtype/device/pinning, nonpersistent buffers, module origins, and mapped library paths.
- Values mode records full local tensor hashes and nonfinite counts; the summary compares only compatible same-process/same-model offload or reload pairs. It does not equate checkpoint full weights with FSDP/TP shards, audit every bucket, or prove end-to-end transfer correctness.
- Diagnostics never convert a missing hash or absent report into a numerical pass. Metadata summaries explicitly state that tensor integrity was not checked.
