# [fsdp] fix: optimize model updating in rollout mode in LoRA training with FSDP

[Upstream PR](https://github.com/verl-project/verl/pull/4470) · state: open · merged: False

## Original PR description

### What does this PR do?

Lora training is much slower than full training under the same experiment setup. Just as https://github.com/volcengine/verl/issues/4033, https://github.com/volcengine/verl/issues/4085, https://github.com/volcengine/verl/issues/4055.

From the ray timeline and tensorboard, it seems that the main time discrepancy does not occur during the `generate sequence`, but rather during the switching of `rollout_mode`.

While dived into the code, I found that in version 0.6.1, when the vLLM version is greater than 0.8.5, the default SLEEP_LEVEL is changed to 2, causing the base_model to be reloaded every time rollout_mode is called, which is time-consuming

```Python
elif vs.parse(package_version) >= vs.parse("0.7.0"):
    vllm_version = package_version
    if vs.parse(package_version) >= vs.parse("0.8.5"):
        VLLM_SLEEP_LEVEL = 2
    from vllm import LLM
    from vllm.distributed import parallel_state
```

In `rollout_mode`, when using full training,  `fsdp_module.state_dict()` can be used directly. However, in the LoRA case, the `collect_lora_param` function first summons the parameters and then moves them to the CPU. I think this is time-consuming and unnecessary. 
https://github.com/volcengine/verl/blob/v0.6.1/verl/workers/fsdp_workers.py#L672
https://github.com/volcengine/verl/blob/v0.6.1/verl/utils/fsdp_utils.py#L629

So I modify the lora weight updating schema in this pr.

### Test

Run experiments in both fsdp and fsdp2 with Qwen2.5-7b in gsm8k datasets. The results are as belowed：
- qwen25_7b_lora_fsdp2_async： fsdp2 + lora + fix-code
- qwen25_7b_lora_fsdp_async: fsdp + lora + fix-code
- qwen25_7b_lora_fsdp2_async_old: fsdp2 + lora + current-code
- qwen25_7b_lora_fsdp_async_old: fsdp + lora + current-code
- qwen25_7b_full_fsdp2_async: fsdp2 + full + current-code, for comparsion.

The reward function's curve aligns with expectations, while the training time per step has been significantly reduced.

## Code Review

This pull request introduces a significant performance optimization for LoRA training with FSDP by revamping how LoRA parameters are collected. The changes avoid expensive `FSDP.summon_full_params` calls and unnecessary CPU transfers, which should substantially reduce the overhead when switching to `rollout_mode`. The modifications in `fsdp_utils.py` and `fsdp_workers.py` are central to this optimization. Additionally, the PR includes bug fixes in `ray_trainer.py` to prevent crashes during profiling and in `vllm_rollout.py` to fix a logging error.

My review focuses on the correctness and maintainability of the new implementation. I've identified a potential issue in `verl/utils/fsdp_utils.py` where an internal FSDP attribute is modified without being restored, which could lead to side effects. Please see my detailed comment.

File: `verl/utils/fsdp_utils.py` · line 635

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

Modifying the internal `_is_root` attribute of FSDP submodules in-place can lead to unpredictable behavior in subsequent operations that rely on the FSDP module's original state. This change persists and is not reverted, which could interfere with other parts of the system that expect the FSDP hierarchy to be in its original configuration (e.g., during checkpointing or other state dict operations). To ensure safety and prevent side effects, it is highly recommended to restore the original `_is_root` values after collecting the state dictionary.

A `try...finally` block could be used to ensure the values are restored even if errors occur:
```python
orig_is_root_values = {}
try:
    for name, submodule in module.named_modules():
        if fsdp_version(submodule) > 0 and name.startswith("_fsdp_wrapped_module.base_model"):
            if hasattr(submodule, "_is_root"):
                orig_is_root_values[name] = submodule._is_root
            submodule._is_root = False
    
    # ... existing logic to get state_dict ...

finally:
    # Restore original _is_root values
    for name, submodule in module.named_modules():
        if name in orig_is_root_values:
            submodule._is_root = orig_is_root_values[name]
```
