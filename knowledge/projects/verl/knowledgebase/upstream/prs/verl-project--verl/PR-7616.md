# [vllm, rollout] feat: support Ascend prefill-decode disaggregation

[Upstream PR](https://github.com/verl-project/verl/pull/7616) · state: closed · merged: False

## Original PR description

### What does this PR do?

Add production-oriented vLLM prefill-decode disaggregation support for Ascend RL rollouts.

The change:

- enables Ascend PD through vLLM-Ascend MooncakeConnectorV1;
- supports asymmetric prefill/decode TP and role-specific memory, batching, and sequence limits;
- adds decode routing policies, including round-robin, random, power-of-two, consistent hash, rendezvous hash, and cache-aware routing;
- exposes separate prefill/decode metrics endpoints and labels;
- preserves request affinity across turns and safely drains in-flight PD requests before sleep or KV cache release;
- synchronizes weight updates and cache invalidation across all prefill/decode servers.

### API and Usage Example

```bash
++actor_rollout_ref.rollout.disaggregation.enabled=True \
++actor_rollout_ref.rollout.disaggregation.prefill_replicas=1 \
++actor_rollout_ref.rollout.disaggregation.decode_replicas=3 \
+actor_rollout_ref.rollout.disaggregation.decode_tensor_model_parallel_size=4 \
++actor_rollout_ref.rollout.disaggregation.transfer_backend=mooncake \
+actor_rollout_ref.rollout.disaggregation.decode_policy.type=power_of_two
```

### Design & Code Changes

A vLLMPDReplica owns one prefill engine and multiple decode engines. Requests enter through the prefill endpoint, transfer KV state through the configured connector, and are routed to a decode engine by the selected policy. All P/D engines remain part of the same rollout replica for weight synchronization, cache lifecycle, sleep/wake, and metrics collection.
