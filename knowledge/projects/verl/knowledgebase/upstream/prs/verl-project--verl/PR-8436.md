# [rollout] fix: honor repetition penalty in agent loops

[Upstream PR](https://github.com/verl-project/verl/pull/8436) · state: open · merged: False

## Original PR description

### What does this PR do?

Stops both AgentLoop implementations from overriding the configured rollout `repetition_penalty` with a request-level `1.0`.

`AgentLoopWorker` and the V1 `AgentLoopWorkerTQ` currently include `repetition_penalty=1.0` in every request. The vLLM async server intentionally uses:

```python
sampling_params.setdefault("repetition_penalty", self.config.get("repetition_penalty", 1.0))
```

Because the AgentLoop request already contains the key, a configured value such as `actor_rollout_ref.rollout.repetition_penalty=1.2` can never be applied. Training and validation continue normally, but silently use `1.0`.

This PR removes the two request-level hard-coded values. The server now supplies the rollout configuration value through its existing default path, while callers that explicitly provide a per-request value remain able to override it.
