# [vllm, sglang, model] chore: upgrade vllm==0.32.0 and transformers==5.16.1

[Upstream PR](https://github.com/verl-project/verl/pull/8390) · state: closed · merged: True

## Original PR description

### What does this PR do?

Upgrade the CUDA 13 dependency stack to `vllm==0.32.0` and the project-wide `transformers==5.16.1` pin, then regenerate `uv.lock`.

vLLM 0.32.0 requires `tokenizers>=0.23.2`, while SGLang 0.5.20 still declares `tokenizers==0.22.2`. Add a project-wide `tokenizers==0.23.2` override, following the existing Transformers override pattern, so every resolution fork remains consistent. Also widen the Transformers support window in `setup.py` and `requirements.txt` to `<5.17` so package metadata accepts the pinned version.

Adapt `AsyncLLM.pause_generation()` to the vLLM 0.32 API while retaining vLLM 0.29 compatibility: 0.32 and newer use `mode="abort"`, while older versions keep `wait_for_inflight_requests=False`. Keep the score-centering top-k coverage test valid for both providers: vLLM 0.29 retains cutoff ties, while 0.32 keeps exactly `top_k` entries.

Adapt the Qwen3.5 monkey patches to both Transformers 5.12 and 5.16. Transformers 5.16 renamed decoder `layer_type` to `block_type` and moved causal-convolution and gated-delta callables from instance attributes to module functions.

This is not a duplicate of [#8072](https://github.com/verl-project/verl/pull/8072): that PR targets vLLM 0.30.0 only, whereas this PR targets 0.32.0 and includes the required Transformers 5.16.1, tokenizers 0.23.2, and compatibility changes.

AI assistance was used to update dependency pins, regenerate the lockfile, diagnose CI, implement compatibility handling, run checks, and draft this PR. The submitter reviewed the changed files and confirmed the change.
