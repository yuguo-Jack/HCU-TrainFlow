# [ckpt] fix: normalize PEFT keys in HF save and dump LoRA adapter with live config

[Upstream PR](https://github.com/verl-project/verl/pull/4770) · state: open · merged: False

## Original PR description

### What does this PR do?

Makes the `huggingface/` output of a LoRA/PEFT training run directly loadable, and dumps the LoRA adapter with its real config.

On main, `FSDPCheckpointManager.save_checkpoint` saves the HF model via `get_fsdp_full_state_dict(...)` → `save_pretrained(hf_local_path, state_dict=state_dict)` with no PEFT handling, so for LoRA runs `huggingface/` contains `base_model.model.*` / `*.base_layer.weight` keys plus raw `lora_A/lora_B` tensors — HF/vLLM cannot load it (see @thvasilo's docker repro in the comments). Since the engine refactor removed `fsdp_workers.py`, main also no longer writes any `lora_adapter/` at save time.

This PR, in the `should_save_hf_model` path, when the model has a `peft_config`:

1. writes a single `{local_path}/lora_adapter/` via `peft.get_peft_model_state_dict` + `peft_config.save_pretrained` — so `adapter_config.json` carries the **live** `lora_alpha`/`task_type` (the original version of this PR reconstructed the config from tensor shapes, which produced `lora_alpha=0`; that is gone)
2. normalizes the state dict with the existing `verl.utils.fsdp_utils.normalize_peft_param_name` (already used by rollout weight-sync) before `save_pretrained`, so `huggingface/` holds plain base-model keys

Note for reviewers: **this is effectively a new diff under the old PR number.** Every code site the original January diff touched was removed in the engine refactor; the branch was rebuilt on current main rather than rebased.

### Test

`tests/utils/ckpt/test_lora_hf_save_on_cpu.py` (CPU, runs in `cpu_unit_tests`):
- normalized full state dict of a real `PeftModel` loads into the plain base model with no missing/unexpected keys
- `_save_lora_adapter` writes `adapter_config.json` with the live `lora_alpha` (32, not 0) and the adapter round-trips through `PeftModel.from_pretrained` with identical weights
- no-op (and no directory) for non-PEFT models

Local testing is CPU-only; multi-GPU FSDP validation is left to reviewers/CI with hardware.

## Code Review

This pull request introduces a fix for saving LoRA/PEFT models by normalizing the `state_dict` keys to be compatible with HuggingFace inference engines. A new `_save_lora_adapter` method is added to handle the extraction of LoRA weights and key normalization, and unit tests are provided to verify this new functionality.

The changes are logical and well-tested. I have two main points of feedback:
1. The key normalization logic in `_save_lora_adapter` uses `str.replace()`, which is not robust for prefix/suffix removal and could lead to bugs with unexpectedly formatted keys. I've suggested a more robust implementation using `startswith()` and `endswith()`.
2. The unit tests duplicate the implementation of `_save_lora_adapter`. This creates a maintainability risk. I've recommended converting the method to a `@staticmethod` to allow direct testing without code duplication.

Addressing these points will improve the robustness and maintainability of the code.

- yurekami · comment · 2026-01-03T16:08:07Z · [source](https://github.com/verl-project/verl/pull/4770#issuecomment-3707160978)

Thanks for the review feedback! I've addressed both concerns in commit 3952342b:

### 1. Unsafe String Replacement (Fixed)

Replaced the chained `str.replace()` calls with explicit `startswith()`/`endswith()` checks:

```python
# Before (unsafe - replaces ALL occurrences)
key = name.replace("base_model.model.", "").replace(".base_layer.weight", ".weight")

# After (safe - only handles prefix/suffix)
if key.startswith("base_model.model."):
    key = key[len("base_model.model."):]
if key.endswith(".base_layer.weight"):
    key = key[:-len(".base_layer.weight")] + ".weight"
```

This prevents unintended substitutions if patterns appear in the middle of key names.

### 2. Code Duplication (Fixed)

- Converted `_save_lora_adapter()` to a `@staticmethod`
- Removed the duplicated `_save_lora_adapter_standalone()` from the test file (50 lines deleted)
- Tests now call `FSDPCheckpointManager._save_lora_adapter()` directly

All tests pass ✅

File: `verl/utils/checkpoint/fsdp_checkpoint_manager.py` · line None

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The use of chained `str.replace()` for normalizing state dictionary keys is not robust. The PR description mentions removing a "prefix", but `replace()` will substitute all occurrences of the substring, not just at the beginning or end of the string. This could lead to unexpected behavior and corrupted keys if the substrings (`"base_model.model."`, `".base_layer.weight"`, `".base_layer.bias"`) appear in other parts of a parameter name.

To make this logic more robust and align with the intent of removing prefixes/suffixes, please consider using `startswith()` and `endswith()` checks.

```python
            key = name
            if key.startswith("base_model.model."):
                key = key[len("base_model.model.") :]

            if key.endswith(".base_layer.weight"):
                key = key[: -len(".base_layer.weight")] + ".weight"
            elif key.endswith(".base_layer.bias"):
                key = key[: -len(".base_layer.bias")] + ".bias"
```
