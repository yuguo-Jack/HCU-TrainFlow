# [fsdp] fix: honor fsdp_config.dtype when mixed_precision param_dtype is unset

[Upstream PR](https://github.com/verl-project/verl/pull/8359) · state: open · merged: False

## Original PR description

## What does this PR do?

Fixes #8076.

`FSDPEngineConfig` inherits `dtype: str = "bfloat16"` from `EngineConfig` (`verl/workers/config/engine.py`), documented as `"Mixed precision training param dtype, default 'bfloat16'"`.

However, `FSDPEngine._build_fsdp_module` and the QAT export path in `FSDPEngine.get_per_tensor_param` only consulted `self.engine_config.mixed_precision` and hardcoded `param_dtype = torch.bfloat16` (or `mixed_precision_config.get("param_dtype", "bf16")`) whenever `mixed_precision` was `None` or omitted `param_dtype`. As a result, setting `actor_rollout_ref.actor.fsdp_config.dtype=float16` silently ran FSDP training and autocast in BF16 and skipped creating `ShardedGradScaler`.

This PR updates `FSDPEngine._build_fsdp_module` and `get_per_tensor_param` to resolve `param_dtype` from `self.engine_config.dtype` when `mixed_precision` is `None` or does not specify `param_dtype`, while preserving explicit `mixed_precision["param_dtype"]` overrides.

## Testing

- Added CPU unit tests in `tests/workers/engine/test_fsdp_engine_dtype_on_cpu.py` covering FSDP1 and FSDP2 with `dtype` (`bfloat16`, `float16`, `float32`) and `mixed_precision` (`None`, partial dict without `param_dtype`, and explicit `param_dtype` overrides), verifying `MixedPrecision` / `MixedPrecisionPolicy`, `_autocast_dtype`, and `ShardedGradScaler`.
- Extended `_autocast_dtype_worker` in `tests/models/test_engine.py` with a regression check for `mixed_precision=None, dtype="float16"`.
