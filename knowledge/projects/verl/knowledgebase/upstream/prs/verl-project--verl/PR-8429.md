<blockquote>
<h2>PyTorch 2.14.1 Release</h2>
<p>This release is meant to fix the following regressions and silent correctness issues:</p>
<h2>Silent correctness fixes</h2>
<ul>
<li>Fix incorrect <code>torch.linalg.lstsq</code> solutions on MPS for complex batched underdetermined systems (<a href="https://redirect.github.com/pytorch/pytorch/issues/196113">#196113</a>), fixed by <a href="https://redirect.github.com/pytorch/pytorch/pull/196128">#196128</a></li>
<li>Fix non-orthogonal <code>U</code> and inaccurate small singular values from <code>torch.linalg.svd</code> on MPS for rank-deficient and ill-conditioned inputs (<a href="https://redirect.github.com/pytorch/pytorch/issues/196112">#196112</a>), fixed by <a href="https://redirect.github.com/pytorch/pytorch/pull/196139">#196139</a> and <a href="https://redirect.github.com/pytorch/pytorch/pull/199063">#199063</a></li>
<li>Update the CUDA 13.2 Linux binaries to CUDA 13.2.2 (<a href="https://redirect.github.com/pytorch/pytorch/pull/196351">#196351</a>). This NVIDIA update resolves two critical issues that could produce incorrect results (<a href="https://docs.nvidia.com/cuda/archive/13.2.2/cuda-toolkit-release-notes/index.html#overview">CUDA 13.2.2 release notes</a>):
<ul>
<li>cuBLAS: <code>cublasLtMatmul()</code> could ignore tensor-wide scaling for NVFP4 matrix multiplications (introduced in CUDA 13.2 Update 1)</li>
<li>Compiler: failed thread reconvergence could leave stale or corrupted register values in kernels with nested thread divergence (present since CUDA 12.8)</li>
</ul>
</li>
</ul>
<h2>Regression fixes</h2>
<ul>
<li>Fix <code>torch.linalg.svd</code>, <code>torch.linalg.svdvals</code> and <code>torch.linalg.lstsq</code> failing on MPS with a Metal pipeline-state error for inputs above 8192 elements (<a href="https://redirect.github.com/pytorch/pytorch/issues/195937">#195937</a>), fixed by <a href="https://redirect.github.com/pytorch/pytorch/pull/195949">#195949</a> and <a href="https://redirect.github.com/pytorch/pytorch/pull/195950">#195950</a></li>
<li>Fix internal assert in <code>torch.svd(out=)</code> on MPS for complex inputs (<a href="https://redirect.github.com/pytorch/pytorch/issues/195822">#195822</a>), fixed by <a href="https://redirect.github.com/pytorch/pytorch/pull/195872">#195872</a></li>
</ul>

<h1>Backwards Incompatible Changes</h1>
<h2>torch.nn</h2>
<ul>
<li>
<p><code>torch.nn.LinearCrossEntropyOptions</code> no longer accepts <code>acc_policy=&quot;balanced&quot;</code>; use <code>&quot;compact&quot;</code> instead (<a href="https://redirect.github.com/pytorch/pytorch/issues/188283">#188283</a>)</p>
<p>The <code>&quot;balanced&quot;</code> policy was removed because <code>&quot;compact&quot;</code> provides the same weight-gradient accumulation precision with lower memory use on CUDA, already uses the equivalent scratch layout for mixed-precision inputs on other devices, and was never selected by <code>&quot;auto&quot;</code>. Constructing the options with <code>acc_policy=&quot;balanced&quot;</code> now raises <code>ValueError: invalid acc_policy: 'balanced'; expected one of 'auto', 'accurate', 'compact'</code>.</p>
</li>
</ul>
