# [megatron, model] refactor: modernize Megatron integration - use native output callbacks [2/5]

[Upstream PR](https://github.com/verl-project/verl/pull/8439) · state: open · merged: False

## Original PR description

### What does this PR do?

Roadmap item 2 of [RFC #8324](https://github.com/verl-project/verl/issues/8324), split from [integration preview #25](https://github.com/ISEEKYAN/verl/pull/25), **depends on [upstream #8438](https://github.com/verl-project/verl/pull/8438)**. This upstream draft targets `main`, so its current diff includes step 1. Review step 1 first; this branch will be rebased after it merges to leave only forward execution changes. [Fork preview #27](https://github.com/ISEEKYAN/verl/pull/27) shows the isolated step-2 diff against fork #26. Submitted at the author's request; human line review remains pending.

Replace the copied GPT forward with native output callbacks. Eager and fused paths share THD/BSHD preparation, context labels, CP metadata and output unpacking. Per-forward context is immutable; callbacks use the output layer's explicit TP group and preserve sequence-parallel gradient behavior. Convert Core's sequence-major hidden layout to batch-major token order before the fused kernel.

This is the structural migration from #25, not a competing implementation of #8029 (parameter synchronization), #7826 (MTP fused BSHD), #7499 (legacy missing labels) or #8031 (MTP head gradients). Native readiness is used when available; the helper from #8029 is reused once installed. Old Core with overlapping parameter gather and no readiness helper safely selects eager output. No new DDP bucket synchronization implementation is introduced. MTP/value-model fused exclusions remain unchanged; retained legacy MTP postprocessing (including zero-MTP references) is detected after compatibility setup and also stays eager; MTP/replay migration and recompute cleanup remain later slices.

### Test

- H100, Torch 2.11.0+cu130 / TE 2.15 image, official Core source: **2 passed on 0.19.2 and 2 passed on 0.21**. Actual BF16 Triton fused output agrees with an eager reference for log-probabilities, entropy, hidden gradients and tied/untied output-weight gradients.
- CPU coverage includes real Core `GPTModel.forward` callback execution, THD/BSHD eager-versus-callback value/gradient parity, native forward identity, per-call label context, explicit TP/SP contracts, backend setup, eager fallback, and existing MTP/DCP/replay/packing regressions.
- All-files pre-commit and `git diff --check` pass.

### API and Usage Example

Engine setup calls the shared compatibility boundary and receives whether native fused output is supported. Providers missing `output_processor` / `output_processor_context` keep their original forward and use eager execution. The old `patch_fused_forward` setup name remains an alias for callback configuration and no longer patches a method. Fused BSHD selects the same shared adapter as eager BSHD. Public model inputs and RL objectives are unchanged.

### Design & Code Changes

`model_forward_fused.py` loses the legacy copied forward and separate packing implementation. `model_forward.py` owns layouts and attaches per-forward packed labels to callback context. Core owns wrapper unwrapping, avoiding the old FSDP factory/type mismatch. The compatibility registry retires its legacy fused-forward entry. Existing MTP packed normalization metadata remains in place for the later MTP migration.
