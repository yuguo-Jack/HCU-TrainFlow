# [algo] fix: drop IcePop-rejected tokens from geo_mean loss

[Upstream PR](https://github.com/verl-project/verl/pull/8421) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes #8406.

`compute_policy_loss_geo_mean` folded IcePop-rejected tokens (IS weight 0) into the geometric mean through `log(1e-10)` and left them in the policy ratio: a rejected token kept its gradient and the rest of its sequence was down-scaled (x0.24 at L=16, x0.70 at L=64 in the issue's CPU repro).

The fix applies one rule, mirroring the token-level losses: a rejected token contributes exactly 0 to every geo_mean sum while denominators stay the original token count, so kept tokens keep the gradient they had without the rejection. A fully rejected sequence gets zero weight instead of a loss built from the sequence advantage alone. Diagnostics (`ppo_kl`, clip fractions) still use the original `response_mask` and are unchanged.

- After: `[vanilla] grad -0.00000, ratio 1.000` / `[geo_mean] grad -0.00000, ratio 1.000`

### API and Usage Example

No API change. `compute_policy_loss_geo_mean` keeps its signature; behaviour only changes when `rollout_is_weights` contains zeros (IcePop rejections). With all-positive weights the output is bit-identical to before.

### Design & Code Changes

- `verl/trainer/ppo/core_algos.py` (`compute_policy_loss_geo_mean`): build `loss_mask = response_mask * (rollout_is_weights > 0)` and use it in the ratio and IS-aggregation numerators; denominators stay `response_mask_sum`; zero `pg_losses` where a sequence has no kept tokens.
- `tests/trainer/ppo/test_core_algos_on_cpu.py`: regression test above.
