# [algo] fix: pad nested importance weights for distillation PG

[Upstream PR](https://github.com/verl-project/verl/pull/8210) · state: closed · merged: False

## Original PR description

### What does this PR do?

Fix policy-gradient distillation when rollout importance weights arrive as a NestedTensor.

Before calling the PPO policy loss, `distillation_loss()` converts `log_prob`, `old_log_prob`, advantages and `response_mask` from NestedTensor to padded dense tensors, but passes `rollout_is_weights` through unchanged. On the no-padding path the weights stay jagged and the policy loss fails. In the forward pass it raises `ValueError: NestedTensor where_self(...): expected condition to be a jagged layout NestedTensor`, and in backward it raises `NotImplementedError: aten._nested_sum_backward.default`.

This PR pads nested weights with `0.0` before the policy loss, matching the other dense inputs. Padded positions are already excluded by `response_mask`. Dense or absent weights are unchanged.
