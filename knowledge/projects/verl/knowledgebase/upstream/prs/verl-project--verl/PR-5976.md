# [rollout] feat: trainer-side FP8 weight quantization for colocated and disaggregated modes

[Upstream PR](https://github.com/verl-project/verl/pull/5976) · state: closed · merged: False

## Original PR description

### What does this PR do?

Move FP8 blockwise weight quantization from rollout GPU to trainer GPU in the weight sync path, controlled by a new config flag `trainer_quantize_fp8`. This halves transfer bandwidth in disaggregated mode (1 byte vs 2 bytes per param) and reduces peak memory during bucketed transfer in colocated mode.

Supports:
- SGLang rollout: colocated (async quantization) and disaggregated (NCCL/NIXL/HCCL checkpoint engines)
- vLLM rollout: pre-quantized FP8 weight loading with version-aware scale naming (v0.10–v0.17)
- All 5 checkpoint engines use `ensure_async_iterator` to accept both sync and async weight generators, eliminating the need for a separate sync quantization path

Related: #5836 (Q2 roadmap → Weight refit optimization → "fp8 rollout: quantize weights on trainer side")

The `weight_block_size` is hardcoded to `[128, 128]`. This value must be consistent with the dequantization configuration used in the rollout worker (e.g., SGLang). Hardcoding it in multiple places (here and in `fsdp_workers.py`) is error-prone and makes it difficult to change the quantization parameters. Consider retrieving this from `self.config.rollout` or defining a shared constant.
