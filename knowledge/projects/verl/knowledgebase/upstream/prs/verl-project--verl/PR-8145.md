[Upstream PR](https://github.com/verl-project/verl/pull/8145) · state: closed · merged: False

## Original PR description

### What does this PR do?

`Worker._setup_env_cuda_visible_devices()` pins this rank's accelerator only when a
`RAY_EXPERIMENTAL_NOSET_*_VISIBLE_DEVICES` variable is set. In the default configuration verl
never calls `set_device()` at all, and instead relies on Ray's per-actor visibility mask
relabeling devices so that index 0 is this rank's device.

That assumption holds only where the accelerator runtime honors its own visibility mask. Where
it does not, every rank in the job runs on the same physical device. The collision does not
raise a device error — it surfaces as out-of-memory, or as collectives taking paths intended for
ranks that share a device.

This PR resolves the index to pin from Ray's own assignment, in **both** visibility modes,
through a new `PlatformBase.ray_device_index()`:

* the position of Ray's reported id inside the visible-devices mask when one is set;
* the reported id itself when nothing is masked.

A platform whose runtime ignores its own mask overrides the hook. Behavior on a runtime that
honors the mask is unchanged — a masked actor resolves to index 0, which is what the process
defaulted to before.

Two related fixes come with it:

1. **Physical vs. logical ids under a user mask.** With NOSET set and
   `ASCEND_RT_VISIBLE_DEVICES=4,5,6,7`, Ray reports physical id `5` and the current code calls
   `set_device(5)` against a runtime that sees only logical 0–3. That is
   [#7507](https://github.com/verl-project/verl/pull/7507); the platform hook fixes it for every
   platform at once, without hardcoding vendor environment-variable names in
   `single_controller`.
2. **A NOSET name that no longer exists.** `ray_noset_visible_devices()` hardcodes a list of
   NOSET variables. Ray derives its NOSET name from the variable it masks, and those get renamed
   — [ray-project/ray#64440](https://github.com/ray-project/ray/pull/64440) moved Ray's Intel
   GPU manager from `ONEAPI_DEVICE_SELECTOR` to `ZE_AFFINITY_MASK` and deleted the old NOSET
   name — so the hardcoded entry names a variable Ray no longer reads. Derive it the way Ray
   does and let the platform name any others, as the sglang rollout path already does in
   `async_sglang_server.py` and `sglang_pd_replica.py`.

### Why this belongs in core rather than in a hardware plugin

The hardware-plugin guidance is to default to plugin-side patching and reserve core changes for
hardware-agnostic blockers. This is one, on three counts.

**1. The gate is wrong independently of any single vendor.** `if is_ray_noset_visible_devices:`
conditions *whether verl pins at all* on a flag that only describes *who sets the mask*. Those
are different questions. Three vendors have now hit it from three directions:

| Report | Hardware | Symptom | Current workaround |
| --- | --- | --- | --- |
| [#7507](https://github.com/verl-project/verl/pull/7507) | Ascend 910B4 | `set_device(5)` → `Invalid device ID` with `ASCEND_RT_VISIBLE_DEVICES=4,5,6,7` | mask-index lookup, `ASCEND_`/`CUDA_` names hardcoded in `single_controller` |
| [#8138](https://github.com/verl-project/verl/pull/8138) | Google TPU | Ray's host-level chip id does not index the one-chip visible list | `if device_name == "TPU": local_rank = os.environ["TPU_VISIBLE_CHIPS"]` in `single_controller` |
| this PR | Intel Arc Pro B60 | both ranks land on device 0; run dies out of memory | — |

Three different vendor branches in the same three lines of `worker.py` is the shape of a missing
abstraction, not of three vendor bugs.

**2. The vendor-specific half stays out of core.** Core gains only the policy — *resolve the
index from Ray's assignment* — plus one method. The hardware knowledge stays in the platform
class: `PlatformROCm` inherits the CUDA mask variable, `PlatformNPU` names
`ASCEND_RT_VISIBLE_DEVICES`, and an out-of-tree platform overrides `ray_device_index()` when its
runtime ignores the mask. No vendor branch is added to `single_controller`.

**3. A plugin cannot reach this code path in time.** The only plugin-side route is patching
`Worker._setup_env_cuda_visible_devices`. That method is the **first statement of
`Worker.__init__`**, and a plugin's patches are applied from its platform's `__init__`, which is
itself first triggered by the `get_resource_name()` call *inside that same method*. By the time
the platform object exists, the function that needed patching is already executing. Applying it
earlier means patching at verl import time, before any platform is selected.

That last point is not hypothetical: `PlatformTPU` is a plugin platform, and #8138 still had to
patch core `worker.py` to pin a TPU chip.

### Relationship to #8138, and an offer

`PlatformTPU` in `verl-hardware-plugin` already ships a method for exactly this:

```python
def ray_local_rank_override(self) -> Optional[str]:
    # Ray does not enumerate TPU chips, so the index comes from TPU_VISIBLE_CHIPS, which
    # get_worker_env_vars() sets when the worker is created.
    return os.environ.get("TPU_VISIBLE_CHIPS", "0")
```

`PlatformBase` on `main` has no such hook and `worker.py` calls no `ray_*` platform method, so
that override is currently dead code — which is why #8138 hardcodes the vendor name in core
instead. `ray_device_index()` is the missing hook.

As written here the hook fires only when Ray reports at least one accelerator id for the
resource, which covers CUDA, ROCm, NPU and XPU but not TPU, where Ray reports none (the TPU
plugin patches Ray's lookup to return `[]` rather than raise, because verl assigns chips itself
through `TPU_VISIBLE_CHIPS`). Making the hook return `Optional[int]` and letting it decline would
let it fire on an empty list too, so `PlatformTPU` could own its chip index and #8138's
`if device_name == "TPU"` branch could be dropped. Happy to make that change here, or to adopt
the plugin's existing `ray_local_rank_override` name instead of a new one — whichever maintainers
and the TPU authors prefer. I have no TPU access, so that reading of the TPU path needs their
confirmation.

### Test

**Unit (`tests/plugin/test_platform_abstraction.py`):** `ray_device_index()` for the
mask-set, mask-unset, non-contiguous-mask and non-indexable-mask (UUID) cases, that a subclass
override is honored, and that `ray_noset_visible_devices()` derives the NOSET name from the
platform's visible-devices variable rather than the hardcoded list. Mock-only, no accelerator
required.

**In-process construction:** `Worker` is also built outside Ray — `SFTTrainer._build_engine()`
builds `TrainingWorker` in-process under torchrun, and
`tests/single_controller/test_get_set_dispatch_collect_cpu.py` constructs `Worker()` directly.
Querying Ray there would start a local Ray instance just to answer, since
`ray.get_runtime_context()` initializes Ray when it is not already running. Guarded with
`ray.is_initialized()` and covered by a test asserting `ray.get_runtime_context` is never called
during in-process construction.

**End-to-end on hardware that exposes the collision:** 2× Intel Arc Pro B60, GRPO on both the
legacy and v1 trainers, FSDP1 and FSDP2, Qwen2.5-0.5B-Instruct on GSM8K, vLLM rollout. Before:
both Ray actors report the same physical device UUID and the run dies out of memory. After: two
distinct physical devices at every step including verl's own `create_device_mesh()`, a 6 GB
allocation on rank 0 leaves rank 1's free memory unchanged, world and FSDP-mesh SUM/AVG probes
return correct values, and all four strategy/trainer combinations complete two steps with exit
code 0. The platform involved is out-of-tree, so CI cannot cover this leg.

**No behavior change on in-tree platforms:**

| Mode | Ray reports | Mask read | Resolved index | Before this PR |
| --- | --- | --- | --- | --- |
| Ray masks the actor (default) | physical id, e.g. `3` | `CUDA_VISIBLE_DEVICES=3` | `0` | no pin; process default was `0` — same |
| NOSET, no user mask | `0..N-1` | unset | the id itself | `set_device(id)` — same |
| NOSET + user mask `4,5,6,7` | `5` | `4,5,6,7` | `1` | `set_device(5)` → invalid device — **fixed** (#7507) |
| Mask not indexable (CUDA UUID form) | UUID | UUID list | matched by value | n/a |

ROCm is covered by the CUDA path: `PlatformROCm` subclasses `PlatformCUDA`, Ray's AMD manager
uses `HIP_VISIBLE_DEVICES` or `CUDA_VISIBLE_DEVICES` and rejects `ROCR_VISIBLE_DEVICES` set
without `HIP_VISIBLE_DEVICES`, and `_setup_env_cuda_visible_devices()` normalizes HIP→CUDA with
asserted-equal values before the pin — so the id Ray reports is always a member of the mask being
read.

### API and Usage Example

New platform hook with a default implementation; existing platforms need no change:

```python
class PlatformBase(abc.ABC):
    def ray_device_index(self, accelerator_ids: list[str]) -> int:
        """Map the accelerator ids Ray assigned to this actor to a device index to pin."""
```

Thin accessor in `verl/utils/device.py`, following the existing `get_*` pattern:

```python
from verl.utils.device import get_ray_device_index

local_rank = get_ray_device_index(ray.get_runtime_context().get_accelerator_ids()["GPU"])
```

A platform whose runtime does not honor its own visibility mask overrides the hook:

```python
class PlatformXPU(PlatformBase):
    def ray_device_index(self, accelerator_ids: list[str]) -> int:
        # torch-xpu discards ZE_AFFINITY_MASK once its lazy init runs, so every actor still
        # enumerates all devices and xpu:N is physical device N regardless of the mask. Pin the
        # physical id Ray assigned; a mask-relative index would put every rank on xpu:0.
        return int(accelerator_ids[0])
```

No config, CLI or user-facing API changes.

### Design & Code Changes

`verl/plugin/platform/platform_base.py` — new `ray_device_index()`. Reads
`visible_devices_envvar()`: if a mask is set, return the position of Ray's id in it; if the id is
not in the mask then the mask is not one we can index into (CUDA's UUID form), and a masked actor
only sees what Ray gave it relabeled from 0, so return 0. If nothing is masked, every device on
the node is visible and the id is the index.

`verl/utils/device.py` — `get_ray_device_index()`, delegating to the active platform.

`verl/single_controller/base/worker.py` — drop the `is_ray_noset_visible_devices` gate
and resolve from Ray's assignment in both modes. Return early when `ray.is_initialized()` is
false, so in-process `Worker` construction neither queries Ray nor starts a local Ray instance.
Skip pinning when Ray assigned this actor no accelerator of this resource type — CPU-only actors
and the driver. As before, the first assigned id is used when an actor holds several.

`verl/utils/ray_utils.py` — `ray_noset_visible_devices()` keeps the existing list for
compatibility and additionally derives `RAY_EXPERIMENTAL_NOSET_{visible_devices_envvar}` the way
Ray does, plus any names the platform reports through `ray_noset_envvars()`. The function has no
in-tree callers left after this change — `worker.py` was the last one, and the sglang paths build
the variable name inline — but it is public and out-of-tree platforms call it, so it is fixed
rather than removed. Glad to drop this hunk if maintainers would rather deprecate the helper.

`tests/plugin/test_platform_abstraction.py` — tests described above.
