# [doc] feat: add H20 results with an FP8 KV cache to the FP8 guide

[Upstream PR](https://github.com/verl-project/verl/pull/8484) · state: closed · merged: True

## Original PR description

### What does this PR do?

Adds FP8 E2E results on H20 with and without an FP8 rollout KV cache to `docs/low_precision/fp8.md`, plus a short section on enabling the FP8 KV cache. Depends on #8483: without it, FP8_BLOCK rollout combined with an FP8 KV cache generates garbage.

Results (Qwen3-30B-A3B-Base, DAPO-Math-17k, 2K/20K, 128×16, token-level TIS C=2, 100 steps, 8×H20 per run):

| | BF16 | FP8 E2E | FP8 E2E + FP8 KV cache |
|---|---|---|---|
| AIME24 at step 0 / 50 / 100 | 5.4 / 20.1 / 23.9 | 4.4 / 19.4 / 22.5 | 4.6 / 19.0 / 22.0 |
| `rollout_corr/k3_kl`, last 20 steps | 0.00065 | 0.00131 | 0.00290 |
| Step time (s) | 396 | 376 | 357 |
| Rollout generation (s) | 182 | 164 | 143 |

![Qwen3-30B-A3B on H20, training curves](https://github.com/user-attachments/assets/202130be-49db-47b9-bcc1-ac3a1c5a2745)

![Qwen3-30B-A3B on H20, step time](https://github.com/user-attachments/assets/b97a8ecd-8cb6-47ec-8c00-620493c7e635)

- All three runs are stable; accuracy, reward, entropy and response length overlap.
- The FP8 KV cache (uncalibrated, scales 1.0) doubles the train/rollout mismatch of FP8 E2E, but it does not grow over training.
- It cuts rollout generation by 13% over FP8 E2E, and the whole step by 10% over BF16.

Not a duplicate: no open PR adds FP8 KV cache usage or results to the FP8 docs (queries below). #4435 adds an FP8 KV cache feature on the older FSDP path and does not touch `fp8.md`.

AI assistance: this PR was prepared with AI assistance (Claude Code). I ran the experiments and reviewed every changed line.
