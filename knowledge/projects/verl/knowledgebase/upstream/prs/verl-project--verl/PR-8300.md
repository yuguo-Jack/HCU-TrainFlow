# [fsdp, perf, trainer] feat: shared-prefix packing for the FSDP engine

[Upstream PR](https://github.com/verl-project/verl/pull/8300) · state: open · merged: False

## Original PR description

### What does this PR do?

The `rollout.n` samples of a GRPO prompt share that prompt, but the actor, ref and critic forwards compute it `n` times. With `fsdp_config.use_prefix_packing=True`, we pack adjacent samples with an identical prompt as one trunk plus one branch per sample, so we compute the prompt once:

```
before: [prompt | resp_1] [prompt | resp_2] ... [prompt | resp_n]
after:  [prompt[:-1]] [prompt[-1] | resp_1] ... [prompt[-1] | resp_n]
```

| segment | queries | keys |
|---|---|---|
| trunk | `prompt[:-1]` | `prompt[:-1]` |
| branch i | `prompt[-1] + resp_i` | `prompt[:-1] + prompt[-1] + resp_i` |

We gather keys and values after RoPE, so a branch never sees another branch, and bottom-right causal alignment gives each branch token the full trunk plus its own earlier tokens, as in the unpacked sequence. In backward, the gather sums the branches' gradients on the trunk keys onto the trunk, which is the unpacked gradient. We pass `cu_seqlens` explicitly because branch positions do not restart at 0, so boundaries derived from `position_ids` would merge the branches.

This is one varlen flash-attention call per layer, the same call the rmpad path already makes: no new kernel, mask or dependency. Each branch starts with a copy of the last prompt token, because `no_padding_2_padding` reads the first response log-prob from that row; with it, the rolled labels, fused kernels, entropy, Σπ² and the critic work unchanged. We map outputs back with one `index_select` per tensor, so nothing below the model forward changes. A per-micro-batch counter raises if any attention layer bypasses the packed wrapper, so an unsupported model fails loudly instead of letting branches attend to each other. Off by default; without the flag, users run today's code.

GRPO on Qwen3-4B, `rollout.n=8`, 2x H100: a training step is **2.7x faster** with a 2k-token prompt and 1.18x faster on plain GSM8K (83-token prompts), with reward curves matching within sampling noise. Peak memory is unchanged in those runs; in a single-GPU forward+backward sweep the speedup reaches 3.8x at an 8k prompt and peak memory halves (35.8 → 18.7 GB).

RFC: https://github.com/verl-project/verl/issues/8299. Related: #6401 / #6689 (prefix-tree attention for Megatron with MAGI/Flex; FSDP listed as planned); #4368 (PrefixGrouper: forked the old `dp_actor.py` forward and needed `use_remove_padding=False`, no caller since #6067); #7202 (tried to revive that fork, closed in favour of #6689; this PR sits in the engine on the rmpad path instead); #7561 (Megatron RFC).

### Test

We test packed-equals-unpacked by two independent routes, so the oracle and the production path do not share an attention implementation.

CPU, exact (`cpu_unit_tests.yml` picks up the `_on_cpu.py` files; the two `tests/utils` files run in `gpu_unit_tests.yml`):
```bash
pytest tests/workers/test_prefix_packing_on_cpu.py tests/workers/test_prefix_packing_engine_on_cpu.py \
  tests/utils/test_prepare_micro_batches_with_group_size.py tests/utils/test_seqlen_balancing.py
```
We run a tiny fp32 Qwen2 through SDPA with a hand-built dense tree mask, which we first check against a brute-force per-sample forward, and require packed log-probs, entropy, values and every parameter gradient to match at `atol=1e-5`. We also unit-test pack/unpack round trips, label alignment, group-detection edge cases, tail padding, the nothing-shared fallback, every rejection check, the layer guard (including across FSDP's kwarg copy) and micro-batch grouping.

GPU (added to `model.yml` next to `test_transformer.py`), H100, flash-attn 2.8.3, transformers 5.12.1:
```bash
pytest -s tests/models/test_prefix_packing.py   # 14 passed
```
We compare the production path (bf16, varlen flash-attention, the packed wrapper) against the existing rmpad forward: Qwen2 (with and without sliding window) and Qwen3, fused kernels on/off, gradient checkpointing on/off, plus the critic, plus an sdpa model that must leave the layer counter at zero. Log-probs and entropy match within `atol=1e-2`, gradient cosine > 0.999.

End-to-end GRPO, Qwen3-4B, 2x H100, FSDP + vLLM, `rollout.n=8`, 128 prompts/step, 20 steps, mean of steps 5-20, the flag the only difference:

| | 2k-token prompt: baseline | packed | speedup | GSM8K (83-token prompt): baseline | packed | speedup |
|---|---|---|---|---|---|---|
| `timing_s/old_log_prob` | 44.8 s | 14.3 s | 3.13x | 15.8 s | 13.3 s | 1.19x |
| `timing_s/ref` | 60.5 s | 15.6 s | 3.88x | 17.1 s | 11.1 s | 1.54x |
| `timing_s/update_actor` | 158.4 s | 51.2 s | 3.09x | 69.2 s | 59.3 s | 1.17x |
| `timing_s/step` | 289.5 s | 107.1 s | **2.70x** | 123.0 s | 104.4 s | **1.18x** |
| `prefix_packing_token_ratio` | | 3.65 | | | 1.10 | |

With the long prompt the actor phases reach ~85% of the 3.65x token saving and the ref exceeds it. On GSM8K every phase beats the 1.10x token saving (1.18x on the step), because dynamic batching now budgets by packed length and runs fewer, fuller micro-batches; the token ratio is a floor on the speedup, not an estimate of it. Rewards match within sampling noise (per-step difference mean -0.003, sd 0.009 with the long prompt; +0.010, sd 0.013 on GSM8K; the binomial standard error of a 1024-sample mean is ~0.01). Peak allocated memory is 38.25 GB per GPU in all four runs, so at this batch size a fixed floor sets the peak and packing neither raises nor lowers it.

Single-GPU forward+backward sweep (Qwen3-4B, fused kernels, gradient checkpointing, 8 x 1024 response tokens): speedup 1.06x at a 64-token prompt, 2.18x at 2048, 3.81x at 8192, at least 84% of the token ratio throughout; peak memory never rises and falls from 35.8 to 18.7 GB at 8192, so the same GPU holds roughly twice the response tokens per micro-batch.

### API and Usage Example

```bash
actor_rollout_ref.actor.fsdp_config.use_prefix_packing=True   # ref follows the actor
critic.fsdp.use_prefix_packing=True
```
Off by default; a user who does not set it runs today's code. If the dead `use_prefix_grouper` flag is also set, prefix packing wins (`balance_batch` follows the packing grouping); we remove that flag in a follow-up. We check at model build that `use_remove_padding=True`, `ulysses_sequence_parallel_size=1`, `flash_attention_2`/`3` on CUDA with flash-attn >= 2.1, a text-only model, and not a model that takes `cu_seqlens` directly (linear-attention hybrids), and we reject top-k distillation, score centering, router replay and multi-modal inputs per micro-batch, each with an explicit error.

### Design & Code Changes

- `verl/workers/utils/prefix_packing.py` (new): group detection by prompt token ids (exact by construction, no `uid` needed), the pack/unpack plan, budget helpers, the support checks and the layer counter.
- `verl/workers/engine/fsdp/transformer_impl.py`: pack in `prepare_model_inputs`, unpack in `prepare_model_outputs` (actor and critic); run plain rmpad when a micro-batch shares nothing; raise if any attention layer bypassed the packed path; log `prefix_packing_token_ratio`.
- `verl/models/transformers/monkey_patch.py`, `dense_common.py`: the flash-attention wrapper handles the `prefix_packing` kwarg (gather K/V, explicit `cu_seqlens`, record the layer); the fused-kernel forward passes it on.
- `verl/utils/seqlen_balancing.py`, `verl/workers/engine/utils.py`: dynamic batching keeps same-prompt samples in one micro-batch, budgeted by packed length, and splits a group over budget with its own trunk per part.
- `verl/trainer/ppo/ray_trainer.py`, `v1/trainer_base.py`, `trainer/ppo/utils.py`: with the flag on, `balance_batch` keeps each prompt's samples on one rank.
- `verl/workers/utils/padding.py`: `get_prompt_lens` shared with the packer.
- Config field (`workers/config/engine.py`, yaml), docs (`docs/perf/perf_tuning.rst`, `docs/examples/config.rst`), example toggle in `run_qwen3_4b_fsdp.sh`, CI step in `model.yml`.

Follow-ups, not in this PR: linear-attention hybrids (recurrent-state handoff at the trunk inside the existing `qwen3_5.py` packed-sequence patch), Ulysses SP, sharing beyond the prompt for multi-turn trees, removing the dead PrefixGrouper code.

**Prevent DP micro-batch count failure after prefix grouping.**

With prefix packing enabled, `rearrange_micro_batches` synchronizes the required micro-batch count with `MAX` and the available atomic-group count with an effective `MIN`. It raises when the synchronized count exceeds the smallest rank's group count.

`_balance_batch` equalizes sample counts and balances workload. It does not guarantee equal prefix-group counts. A rank can therefore receive fewer groups while another rank's oversized groups are split by `split_groups_to_budget`, which can make the synchronized micro-batch count larger than the former rank's group count. The exact 1.5× example does not force eight micro-batches because the initial lower bound is `ceil(total_packed_tokens / max_token_len)`, but the failure remains reachable with groups whose split parts require more micro-batches than another rank has groups.

Before calling `rearrange_micro_batches`, synchronize the required count and split groups on ranks with too few atomic groups. Recompute `group_token_lens` with `packed_group_lens` after each split, and repeat until every rank can provide the synchronized count. Add a multi-rank test with unequal prefix-group counts.
