# [perf] fix: chunk rows in logprobs_from_logits_v2 for 2-D bf16/fp16 logits

[Upstream PR](https://github.com/verl-project/verl/pull/8351) · state: closed · merged: False

## Original PR description

### What does this PR do?

`logprobs_from_logits_v2` is the fallback used by `logprobs_from_logits` when the flash-attn cross-entropy kernel is not used (not installed, or `VERL_DISABLE_FLASH_ATTN_CE=1` for bitwise-reproducible log-probs). For 16-bit logits it loops over the first dimension. With remove-padding the logits are 2-D `(num_tokens, vocab)`, so this is one `log_softmax` + one `gather` + one autograd node **per token**: thousands of tiny kernels per micro-batch, in the log-prob pass and in the actor update.

For 2-D 16-bit logits this PR processes rows in chunks whose `log_softmax` output is at most `_LOGPROB_CHUNK_BYTES` = 32 MiB (`32 MiB // (vocab * element_size)` rows, e.g. 110 rows for a 151936 vocab in bf16). `split()` is used so the backward stays a single node. Other ranks and fp32/fp64 are unchanged. A labels/logits shape mismatch raises a clear `ValueError`.

### Test

New tests in `tests/utils/test_torch_functional.py`:
- `test_logprobs_from_logits_v2_2d_bitwise_matches_per_row`: bf16 and fp16, contiguous and non-contiguous (transposed) logits, one chunk / uneven chunks / one row per chunk / 151936 vocab. Outputs and gradients are compared to the per-row reference as raw bits (`view(torch.int16)`), 16 cases.
- `test_logprobs_from_logits_v2_bf16_2d_does_not_loop_over_tokens`: 64 tokens run a single `log_softmax` on the whole `(64, 1000)` block.

On one GB300 GPU (CUDA, torch 2.15 nightly):

```
upstream main + new tests:  17 failed  (64 per-row log_softmax calls instead of 1; chunk budget absent)
this PR:                    17 passed
```

Bitwise equality is verified for these dtypes, layouts and this GPU/torch build; it is not a general PyTorch guarantee for other backends.

Benchmark of `logprobs_from_logits_v2` on one GB300 GPU, bf16, median of 5. "Peak" is the extra allocated memory during the call on top of the logits.

| tokens x vocab | path | no_grad forward | peak (no_grad) | forward + backward | peak (fwd+bwd) |
|---|---|---|---|---|---|
| 4096 x 151936 | per-row (main) | 125.3 ms | +2.3 MiB | 289.2 ms | +2375 MiB |
| | this PR | 1.3 ms | +31.9 MiB | 3.6 ms | +2374 MiB |
| 16384 x 151936 | per-row (main) | 519.6 ms | +8.3 MiB | 1455.0 ms | +9500 MiB |
| | this PR | 5.1 ms | +31.9 MiB | 14.8 ms | +9496 MiB |
| 16384 x 32000 | per-row (main) | 480.7 ms | +8.1 MiB | 1341.8 ms | +2000 MiB |
| | this PR | 1.2 ms | +32.0 MiB | 2.9 ms | +2000 MiB |

The chunked path holds one chunk's `log_softmax` output (bounded by the 32 MiB budget) where the per-row loop held about one row, so the no-grad peak rises by up to ~32 MiB; with gradients the peak is unchanged. Budget sweep for 16384 x 151936 (no_grad / fwd+bwd): 8 MiB 19.5 / 49.6 ms, 32 MiB 5.1 / 14.8 ms, 64 MiB 4.3 / 11.0 ms, 512 MiB 3.3 / 9.1 ms; 32 MiB keeps nearly all of the speedup.

### Design & Code Changes

- `verl/utils/torch_functional.py`: `_LOGPROB_CHUNK_BYTES = 1 << 25`; chunked branch for 2-D logits in the 16-bit path.
