![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The bash parameter expansion for `VERL_EXP_NAME` is missing the `-` character. The current syntax `${VAR:default}` is interpreted as a substring expansion `${parameter:offset}`, which will cause a syntax error because the default value string is not a valid integer offset. It should be `${VERL_EXP_NAME:-...}` to correctly provide a default value when the variable is unset or null. This also aligns with best practices for handling unset variables in shell scripts.

```suggestion
VERL_EXP_NAME=${VERL_EXP_NAME:-function-reward-minimal-fsdp-size${FSDP_SIZE}}
```

File: `tests/special_e2e/run_ppo_trainer_veomni_npu.sh` · line None

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

There is a potential mismatch between the available GPU resources and the rollout parallel configuration. The script defines `NUM_GPUS=8` (line 28) and the actor strategy (`FSDP=2, SP=2, EP=2`) utilizes all 8 GPUs. However, the rollout is configured with `tensor_model_parallel_size=4` and `expert_parallel_size=4`. In vLLM, the total number of GPUs required for a single rollout replica is typically the product of these dimensions (`TP * EP`). If `TP=4` and `EP=4` requires 16 GPUs, the initialization will fail on an 8-GPU node. Even if it fits in 4 GPUs (with `DP=1`), it would create a mismatch with the 8-GPU actor setup in a hybrid engine environment, as rollout workers would not be present on all GPUs. Please verify the intended parallel strategy for the 8-GPU NPU setup.
