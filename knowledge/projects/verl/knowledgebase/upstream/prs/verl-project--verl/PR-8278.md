# [CI] fix: guard actor policy_loss lookup when config lacks the field

[Upstream PR](https://github.com/verl-project/verl/pull/8278) · state: open · merged: False

## Original PR description

## Summary
`main` is red on `cpu_unit_tests`: after #8010 (score centering) and #7945 (Liger TP fused CE) both landed, the megatron liger CPU test builds a lightweight config via a monkeypatched `omega_conf_to_dataclass` that returns a `SimpleNamespace` without `policy_loss`, while `ActorRolloutRefWorker.init_model` reads `actor_config.policy_loss...` unconditionally → `AttributeError`.

- Reproduces on `main` itself: latest main run (4b26c788) job `117718352932`, `1 failed, 1503 passed` —
  `FAILED tests/workers/test_megatron_liger_fused_kernels_on_cpu.py::test_worker_reserves_both_consumers_before_ref_reset - AttributeError: 'types.SimpleNamespace' object has no attribute 'policy_loss'`.
- Guard the lookup with `getattr(..., None)`; absent `policy_loss` selects the default `ppo_loss`, identical to an empty-default `PolicyLossConfig`.

## Test plan
- [x] Verified the guarded conditional returns the same result as the original expression for: missing attribute, empty `policy_loss`, `rollout_correction` present without centering, and centering enabled.
- [ ] `cpu_unit_tests` green on this PR.

### reviews

- rahul05ranjan · COMMENTED · 2026-10-19T12:15:06Z · [source](https://github.com/verl-project/verl/pull/8278#pullrequestreview-5571378254)

Minimal and correct: `getattr(actor_config, "policy_loss", None) or {}` is exactly the right guard for the lightweight configs the CPU unit tests build, where `policy_loss` may be absent and the old `actor_config.policy_loss.get(...)` raised a bare AttributeError the moment #8010's `score_centering` elif was reached. Behavior is unchanged for configs that do define `policy_loss` (and the elif priority — distillation first — is untouched). Nothing else needed for a fix this size; the failing CI run it unblocks is the real test.
