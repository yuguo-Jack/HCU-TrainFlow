# [reward] fix: normalize punctuation around extracted GSM8k answers

[Upstream PR](https://github.com/verl-project/verl/pull/8231) · state: open · merged: False

## Original PR description

### What does this PR do?

The GSM8k reward function (`verl/utils/reward_score/gsm8k.py`, the default scorer for `openai/gsm8k`) compares the raw regex match with the ground truth, so **correct answers surrounded by ordinary formatting get 0 reward**:

| Response | Method | Extracted on `main` | Score on `main` | With this PR |
|---|---|---|---|---|
| `#### 72.` | strict | `72.` | 0 | 1 |
| `#### $300` | strict | `None` (the regex rejects `$`; the existing `.replace("$", "")` was dead code) | 0 | 1 |
| `#### 18.00` | strict | `18.00` | 0 | 1 |
| `Total is 72.` | flexible | `72.` | 0 | 1 |
| `So she earns 1,000 dollars.` | flexible | `1,000` (strict strips commas, flexible did not) | 0 | 1 |
| `The answer is 42, right, ok` | flexible | `,` | format_score | 1 |
| `No numbers here, really.` | flexible | `,` | format_score | 0 |

Fix: normalize every extracted candidate (drop thousands separators, trailing periods and trailing decimal zeros) and only accept candidates that contain a digit. Every GSM8k ground truth is an integer (checked all 8,792 train and test answers), so dropping trailing decimal zeros cannot turn a wrong answer into a correct one. The `####` marker is still required in strict mode.

### How much this matters on real model outputs

I sampled one response per GSM8k test question (n=1319) with the exact prompt from `examples/data_preprocess/gsm8k.py`, temperature 1.0 (rollout default), max 1024 new tokens, using MLX on a MacBook. I then scored the same responses with `main` and with this PR:

| Responses | Method | reward=1 on `main` | reward=1 with this PR | 0→1 | 1→0 |
|---|---|---|---|---|---|
| Qwen2.5-0.5B-Instruct | strict | 11 (0.8%) | 15 (1.1%) | 4 | 0 |
| Qwen2.5-0.5B-Instruct | flexible | 359 (27.2%) | 412 (31.2%) | 53 | 0 |
| Qwen2.5-1.5B-Instruct | strict | 164 (12.4%) | 175 (13.3%) | 11 | 0 |
| Qwen2.5-1.5B-Instruct | flexible | 701 (53.1%) | 835 (63.3%) | 134 | 0 |

- **flexible**: on `main`, 13–16% of the answers that the fixed scorer accepts got 0 (53/412 for 0.5B, 134/835 for 1.5B). Most of these are a trailing period, a thousands separator or `$X.00`. For 61 (0.5B) and 10 (1.5B) responses, a bare `,` or `...` was extracted as the "answer".
- **strict** (the default path): before RL, only 30–36% of responses use the `####` marker, so the absolute effect is smaller. Still, 11 of the 175 answers that 1.5B gets right under the fixed scorer (6%) were scored 0 on `main` (`#### $29.00`, `#### 6.00`, `#### 25.`). These are the formats a policy produces once it learns the marker, and the reward currently treats them like wrong answers.
- **No response that scored 1 on `main` scores 0 with this PR.** I hand-checked a random sample of the 0→1 flips. All were the model's final answer, except one where flexible's existing "last number in the text" rule picked a number from the question that happened to equal the answer. That behavior is unchanged by this PR.
