# [hardware, recipe, rollout, worker] feat: DeepSeek-V4-Flash true on-policy GRPO on ROCm (MI355X)

[Upstream PR](https://github.com/verl-project/verl/pull/8505) · state: open · merged: False

## Original PR description

### What does this PR do?

Adds a ROCm (MI355X, gfx950) recipe and image for DeepSeek-V4-Flash GRPO where the vLLM rollout log-probs and the
trainer log-probs of the same tokens are **bitwise equal** (`rollout_probs_diff_max` = 0.0). It follows the pattern
of #7050 and #8146: a Dockerfile on `vllm/vllm-openai-rocm:v0.26.0` that applies patch files from
`docker/rocm/patches/`, plus a recipe.

- **Image** `docker/rocm/Dockerfile.rocm.deepseek-v4.true-on-policy`: the base (pinned by digest) and the TE / apex /
  libhsa / mbridge / Megatron-Bridge / transformers / TransferQueue pins of `Dockerfile.rocm.deepseek-v4`, then
  - the four existing DeepSeek-V4 vLLM patches, plus 18 vLLM batch-invariance patches (`vllm-bi-*.patch`);
  - Megatron-LM `ISEEKYAN/Megatron-LM` `ds4_vllm_align_preview` (the branch with mLite's vLLM-aligned DeepSeek-V4
    implementation, `impl=vllm`) plus 13 patches (`megatron-dsv4-*.patch`) that run it on ROCm;
  - a build-time `sha256sum -c` of every patched file, and closure checks (import paths, no start-up overlay).
- **Recipe** `examples/grpo_trainer/run_deepseek_v4_flash_true_on_policy_rocm.sh`: `VLLM_BATCH_INVARIANT=1`
  (default) runs the consistent arm (batch-invariant rollout TP1 x DP8 x EP8 per node; mLite `impl=vllm` actor, CP4 x
  EP32, FSDP2); `VLLM_BATCH_INVARIANT=0` runs the Megatron-Core FP8-QAT baseline of
  `run_deepseek_v4_flash_megatron_rocm.sh`. Modelled on #7688.
- **verl fixes** the consistent arm needs:
  - `rollout.full_determinism` gave every request of a replica the same sampling seed, so the n samples of a GRPO
    group were identical and every advantage was 0. The seed is now derived from `(rollout.seed, request_id)`.
  - `enable_full_determinism` no longer fills every `torch.empty` with NaN
    (`torch.utils.deterministic.fill_uninitialized_memory = False`): tens of thousands of fill kernels per
    micro-batch, no effect on kernels that write their whole output.

Each patch header states what it fixes, why batch invariance needs it, and its upstream status. Several are already
on vLLM `main` after v0.26.0 (#49758, #59788, #59941) or covered by #52231; the DeepSeek-V4-specific ROCm kernels are
not yet proposed upstream, because vLLM `main` rewrote that attention path. Moving the rollout to vLLM `main` also
means porting the trainer's mirror of the forward, so this PR pins vLLM 0.26.0.

Related: #7688 (the NVIDIA preview of the same recipe), #8317 (GB200 image for Megatron Lite + batch-invariant
vLLM), #8146 / #7050 (the ROCm DeepSeek-V4 image this one extends).
