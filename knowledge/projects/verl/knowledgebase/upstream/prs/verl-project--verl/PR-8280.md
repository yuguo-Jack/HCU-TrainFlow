# [hardware, doc] fix: auto-compute DATA_PARALLEL_SHARD_SIZE when TENSOR_PARALLEL_SIZE > 1 in TPU TorchTitan scripts

[Upstream PR](https://github.com/verl-project/verl/pull/8280) · state: closed · merged: False

## Original PR description

## Summary

Update the TPU TorchTitan example scripts (`examples/tpu/grpo/run_qwen3_4b_torchtitan.sh`, `examples/tpu/grpo/run_qwen3_0_6b_torchtitan.sh`, and `examples/tpu/sft/run_qwen3_0_6b_torchtitan.sh`) so `DATA_PARALLEL_SHARD_SIZE` defaults to `$((TOTAL_TRAINER_CHIPS / TENSOR_PARALLEL_SIZE))` instead of `${TOTAL_TRAINER_CHIPS}`.

- **Default unchanged (`TENSOR_PARALLEL_SIZE=1`)**: `DATA_PARALLEL_SHARD_SIZE` evaluates to `TOTAL_TRAINER_CHIPS` (pure FSDP across all trainer chips for best throughput).
- **When `TENSOR_PARALLEL_SIZE > 1`**: `DATA_PARALLEL_SHARD_SIZE` automatically divides `TOTAL_TRAINER_CHIPS` by `TENSOR_PARALLEL_SIZE` so `dp_shard * tp == world_size` holds without manual overrides.

Companion `verl-hardware-plugin` PR: https://github.com/verl-project/verl-hardware-plugin/pull/62

## Testing

- TPU CI on `jialei777/verl-upstream` (`main-ci`, commit `aca6d410`, pinned to `dad7bf8f`):
  - [`tpu_unit_tests`](https://github.com/jialei777/verl-upstream/actions/runs/39198766080) ✅
  - [`e2e_sft_llm_tpu`](https://github.com/jialei777/verl-upstream/actions/runs/39198765968) ✅
  - [`e2e_v1_separate_async_tpu`](https://github.com/jialei777/verl-upstream/actions/runs/39198766096) ✅
- 100-step Qwen3-4B GRPO verification on 4x TPU v6e Trainer + 4x TPU v6e Rollout (`TENSOR_PARALLEL_SIZE=2` -> `DATA_PARALLEL_SHARD_SIZE=2` and `TENSOR_PARALLEL_SIZE=1` -> `DATA_PARALLEL_SHARD_SIZE=4`): both completed all 100 steps with 0 `NaN`/`Inf` gradients and reached `93.8%–95.3%` GSM8K validation accuracy.
