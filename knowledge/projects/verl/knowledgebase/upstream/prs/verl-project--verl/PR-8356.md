# [rollout, fully_async] fix: shrink min_tokens with the budget on FullyAsyncLLMServerClient resumes

[Upstream PR](https://github.com/verl-project/verl/pull/8356) · state: open · merged: False

## Original PR description

### What does this PR do?

`FullyAsyncLLMServerClient.generate` shrinks the length budget on every resume: after an abort it sets `max_tokens` (or `max_new_tokens`) to the original value minus the tokens already generated. A caller-set lower bound, `min_tokens` (or `min_new_tokens`), is copied as is into every attempt.

Two problems follow under the fully async trainer:

- Once the generated count passes `original_max - original_min`, the next attempt asks for more tokens than its budget allows. vLLM rejects the request: `VLLMValidationError: min_tokens must be less than or equal to max_tokens=3, got 5.` The rollout fails.
- Before that point, the resumed attempt still forces the full original minimum, so the final response is longer than the caller's `min_tokens` asked for.

This PR captures the original lower bound once, next to `original_max_tokens`, and on every resume sets it to the original minus the tokens already generated, floored at 0 and capped at the shrunk budget. Requests without a lower bound are unchanged.

### Test

New CPU test `tests/workers/rollout/test_llm_server_min_tokens_on_cpu.py`:

- Abort after 3 tokens with `min_tokens=5, max_tokens=6`: the resumed attempt gets `min_tokens=2, max_tokens=3`. The same case runs for `min_new_tokens` / `max_new_tokens`.
- Abort after 3 tokens with `min_tokens=2`: the resumed attempt gets `min_tokens=0`.
- No `min_tokens` in the request: none is added.

```
pytest -q tests/workers/rollout/test_llm_server_min_tokens_on_cpu.py \
  tests/workers/rollout/test_llm_server_routed_experts_on_cpu.py \
  tests/workers/rollout/test_topk_coverage_on_cpu.py \
  tests/workers/rollout/test_llm_server_response_length_cap_on_cpu.py
51 passed
```

Without the change, 3 of the 4 new cases fail (`assert 5 == 2`, `assert 2 == 0`). `ruff check`, `ruff format --check` (v0.12.2) and `check_license.py` pass.
