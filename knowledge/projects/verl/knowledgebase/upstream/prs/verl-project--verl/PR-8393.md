# fix: serialize mlflow sqlite init with a cross-process file lock

[Upstream PR](https://github.com/verl-project/verl/pull/8393) · state: open · merged: False

## Original PR description

## Problem

With `actor_rollout_ref.rollout.trace.backend=mlflow` and the default `sqlite:///tmp/mlruns.db`, every `AgentLoopWorker` calls `RolloutTraceConfig.init` → `mlflow.set_experiment` concurrently. Alembic migrations on the same sqlite file race — worker startup crashes, and a half-migrated db from a crashed run then fails deterministically on every retry.

## Fix

Serialize the mlflow initialization with a cross-process `fcntl` file lock (held via context manager) when the tracking URI is sqlite: the first worker migrates the schema, the rest reuse it. Falls back to unlocked init on non-POSIX platforms.

## Notes

- sqlite remains single-machine only; multi-node setups should point `MLFLOW_TRACKING_URI` at an mlflow server.
- Verified manually: two-process lock serialization test, and 8 concurrent AgentLoopWorkers starting cleanly against one sqlite db.
