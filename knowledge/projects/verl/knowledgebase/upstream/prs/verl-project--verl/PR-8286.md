# [megatron] fix: leave HybridDeviceOptimizer state untouched in optimizer offload (#8237)

[Upstream PR](https://github.com/verl-project/verl/pull/8286) · state: closed · merged: True

## Original PR description

### What does this PR do?

Megatron's `optimizer_cpu_offload=True` turns the optimizer into a **HybridDeviceOptimizer (HDO)**: it permanently splits optimizer state between CPU memory and GPU memory via `optimizer_offload_fraction`. The GPU-side state is owned by a fused CUDA optimizer that can only work with GPU tensors, so it must stay on GPU.

veRL's phase-switch helper (`offload_megatron_optimizer`) moves optimizer state to CPU to free memory. That is correct for a normal optimizer, but for an HDO it also moved the GPU-resident state to CPU — both unnecessary (that state is deliberately GPU-resident) and fatal: the next training step crashes, or the offload itself raises `CUDA error: invalid argument` when the moved tensor points into memory the model offload has already freed (issue #8237).

**Fix**: the offload helper now skips HDO optimizers entirely. Nothing is lost — the HDO's CPU-side state is already on CPU, and the GPU-side state stays where the user asked it to be. Normal optimizers are offloaded exactly as before, and `load_megatron_optimizer` is unchanged.

Adds a regression test (`tests/utils/megatron/test_optimizer_offload_and_load.py`) that builds an HDO (fraction 0.5 and 0.0), steps once, and asserts offload does not move the GPU-side state and load restores it.

### Test

- **Mechanism repro** (standalone, RTX 4090): real HDO + fused GPU optimizer + a state tensor whose backing storage is freed by the model offload, mirroring the reporter's scenario — without the fix it fails with `CUDA error: invalid argument` inside `offload_megatron_optimizer`; with the fix it passes.
- **Unit** (RTX 4090): `pytest tests/utils/megatron/test_optimizer_offload_and_load.py -k "hdo or precision_aware"` → **2 passed**. The existing non-HDO offload test (`-k precision_aware`) passes — no regression. The new HDO regression test (`-k hdo`) passes for fractions 0.5 and 0.0: the GPU sub-optimizer's `exp_avg`/`exp_avg_sq` remain object-identical on cuda across offload and are restored by load.
- **E2E smoke** (RTX 4090): full megatron training (Qwen2.5-0.5B, `optimizer_offload=True` + `optimizer_cpu_offload=True`, fractions 1.0/0.5/0.0) — all three exit 0 (2 update steps each).

Note: building/stepping an HDO on megatron-core 0.16.1 hits a separate `Float16Optimizer` param-groups bug (a Megatron-LM issue, not this PR); the HDO test uses an all-bf16 model (matching verl's real `Float16Module` path) so it does not depend on that megatron fix.

### API and Usage Example

No API change. Existing `optimizer_offload` / `optimizer_cpu_offload` / `optimizer_offload_fraction` semantics are unchanged — the only difference is that HDO state is no longer moved to CPU (which was incorrect).

### Design & Code Changes

- `verl/utils/megatron_utils.py`, `offload_megatron_optimizer`: remove the unconditional HDO sub-optimizer state loop; HDO optimizers are now skipped entirely, and only non-HDO optimizers' `exp_avg/exp_avg_sq/master_param` are offloaded to CPU. `offload_megatron_copy_params` (params / fp32 master shards) is unchanged. `load_megatron_optimizer` is unchanged (it already delegates HDO state placement to `_move_new_state_to_right_device`).
- `tests/utils/megatron/test_optimizer_offload_and_load.py`: add HDO regression test (fractions 0.5/0.0).

File: `verl/utils/megatron_utils.py` · line 698

With `optimizer_offload_fraction < 1`, the HDO has a GPU-resident FusedAdam sub-optimizer whose state must stay on GPU. This line moves it to CPU, so either the next fused step reads CPU tensors (native crash, no traceback) or — when `master_param` is a view into `param_data` freed by the model offload earlier in the same phase switch — the `.to("cpu")` itself reads freed memory and raises `CUDA error: invalid argument` (issue #8237).
