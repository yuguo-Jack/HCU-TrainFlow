# [perf, hardware] fix: flush NPU profiler scopes on exceptions

[Upstream PR](https://github.com/verl-project/verl/pull/8191) · state: open · merged: False

## Original PR description

### What does this PR do?

When an Ascend training stage raises inside `NPUProfiler.annotate()`, the wrapper skips `mark_end_range()`, `step()` and `stop()`. The failure's traceback can retain the running profiler: its framework operation trace has not been flushed when the exception reaches the caller. `marked_timer()` similarly leaves its MSTX range open on failure.

Put scope cleanup in `finally` blocks so failing stages and timers close their markers and discrete profiles flush before returning the exception. If a profiler `step()` raises, still attempt `stop()`; continuous profiling also resets its process-level count after cleanup. Continuous stage annotations keep the outer profile running, as on the success path.

### Test

```bash
python -m pytest -q -s tests/utils/test_mstx_exception_cleanup_on_cpu.py tests/utils/test_special_mstx_profile.py tests/utils/test_mstx_exception_cleanup_on_npu.py
pre-commit run --all-files --show-diff-on-failure
```

- Before the fix: all **7** new exception-path CPU tests fail; the new real-NPU regression also fails against a separate unmodified main checkout because the backend is still running after the stage exception.
- After the fix: **26 passed**, including the 18 existing NPU profiler tests and the new real-NPU trace test. All **14** pre-commit hooks pass.

The CPU tests inject stage, marker and profiler-step failures and check exception identity, single stage execution, range closure, backend shutdown and count reset. The NPU test uses the real `DistProfiler` dispatcher and real NPU profiler, retains the backend to expose premature reliance on garbage collection, and verifies:

1. The original stage exception propagates once, with the backend already stopped.
2. The nonempty framework operation trace exists immediately after failure.
3. Parsing that trace yields a complete `update_actor` MSTX interval (`ph="X"`, positive duration) and the real matrix-multiply operation.
4. A subsequent stage succeeds, stops its profile, and writes a second operation trace.

The NPU test runs in a bounded child process and explicitly cleans up a baseline profiler if its assertions fail. It is collected by the existing NPU unit-test workflow; absent torch-npu/device skips it on other runners. The CPU regression file is collected by the existing CPU workflow.
