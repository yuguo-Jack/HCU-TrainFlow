# [hardware, doc] fix: update the TPU GRPO example for verl-hardware-plugin main (Ray 2.59 image, pip-installed plugin, no NOSET)

[Upstream PR](https://github.com/verl-project/verl/pull/8243) · state: closed · merged: False

## Original PR description

### What does this PR do?

Makes `examples/tpu/grpo` (scripts, README and image) work with `verl-hardware-plugin` `main`, and prepares it for the plugin loading its vLLM patches through an entry point. Only `examples/tpu/grpo/` changes.

1. **Drop `RAY_EXPERIMENTAL_NOSET_TPU_VISIBLE_CHIPS`** from both scripts and the README. verl-project/verl-hardware-plugin#55 removed the plugin's `TPU_VISIBLE_CHIPS` workaround and relies on Ray (>= 2.59) assigning `TPU_VISIBLE_CHIPS` to each actor; with the variable set, Ray assigns none and the trainer fails in `init_process_group` with `RuntimeError: create_process_group(): PjRtClient is not initialized.`
2. **Install the plugin with pip instead of shipping its source in `py_modules`**: `"pip": {"packages": ["verl-hardware-plugin @ git+https://github.com/verl-project/verl-hardware-plugin@main"], "pip_install_options": ["--no-deps"]}`. An installed package registers entry points; a directory on `sys.path` does not. verl-project/verl-hardware-plugin#58 moves the vLLM patches to a `vllm.general_plugins` entry point and fails fast when it is missing. `--no-deps` keeps the image's torch/verl. The README also shows how to install a local checkout as a wheel (`${RAY_RUNTIME_ENV_CREATE_WORKING_DIR}`).

3. **Build the image on Ray 2.59 with torchtitan 0.3.0** (`Dockerfile`): plugin `main` needs Ray >= 2.59 (above) and supports torchtitan 0.3.0, so the base moves from `rayproject/ray:2.56.0-py312` to `2.59.0-py312` and torchtitan is installed from PyPI (`0.3.0`) instead of the google-pytorch fork at `f880cc73` (drops `/torchtitan`, `PYTHONPATH` and the fork-only `typeguard`/`spmd_types` pins). The other pins (torch, torch-tpu, tpu-sync, jax, libtpu, vLLM, vllm-torchtpu, transformers, TransferQueue) are unchanged.
4. **Pass build credentials as BuildKit secrets**: the build pulls the private `vllm-project/vllm-torchtpu` repository and `torch-tpu` from an authenticated index, which the previous `docker buildx build -t <IMAGE> ...` command had no credentials for. The `Dockerfile` now reads `GIT_AUTH_TOKEN.github.com` and `tpu_index_token` secrets (not stored in the image) and the README documents the command.
