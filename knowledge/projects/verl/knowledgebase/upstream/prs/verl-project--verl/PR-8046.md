# [vllm, rollout] fix: keep merged LoRA weights across vLLM sleep

[Upstream PR](https://github.com/verl-project/verl/pull/8046) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes #7904 for **FSDP** merged LoRA (`actor_rollout_ref.model.lora.merge=true`) with `free_cache_engine=true`. Hybrid sleep was level 2, which discards vLLM parameter storage. Wake puts the buffers back empty. The FSDP merged sync then sends a PEFT export through `load_weights`, not a full checkpoint refill, so any parameter that export does not overwrite stays uninitialized. Rollout text turns into token soup and nothing raises. `free_cache_engine=false` never discards those parameters, which is why that run stays clean.

**Megatron is unchanged:** merged LoRA still sleeps at level 2. Megatron’s merge path uses `bridge.export_hf_weights` (full HF export), so a level-2 discard is fine there. Adapter LoRA (`merge=false`) already slept at level 1 on every backend. Full-parameter training still sleeps at level 2.

This does not use `initialize_layerwise_reload` / `finalize_layerwise_reload`. That lifecycle buffers every tensor until the layer is complete and can OOM on large MoE, which #7987 already rejected in favor of in-place MoE staging.

This is not #8032 (opt-in `lora.resync_base` so adapter mode can sleep at level 2) or #7304. https://github.com/verl-project/verl/pulls?q=is%3Apr+7904

- Shr3yash · comment · 2026-09-29T08:18:40Z · [source](https://github.com/verl-project/verl/pull/8046#issuecomment-5886398865)

Yes. Level 1 for merged LoRA is only the FSDP PEFT-export path.

#7904 used the default `ppo_trainer` (FSDP) with `lora.merge=true` and `free_cache_engine=true`. That sync goes through `FSDPEngine._merged_lora_per_tensor_param` (`normalize_peft_param_name(state_dict())`), which does not refill every parameter after sleep level 2. `fsdp`, `fsdp2`, and `fsdp_turbo` share that engine, so those still sleep at level 1 when LoRA is merged.

Megatron stays at level 2 for merged LoRA. `MegatronEngine.get_per_tensor_param` calls `bridge.export_hf_weights` on the merge path, which is a full HF export, and that matches what you see. Adapter LoRA is still level 1 on every backend. Full-parameter training is still level 2.

The HTTP server cannot tell the backend from the LoRA config, since both sides use `lora.merge`. `LLMServerManager` passes `actor_rollout_ref.actor.strategy` into the vLLM replica. An unset strategy also stays at level 2.
