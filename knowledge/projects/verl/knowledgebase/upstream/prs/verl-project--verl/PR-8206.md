# [algo, fsdp, perf] refactor: share support normalization in score centering

[Upstream PR](https://github.com/verl-project/verl/pull/8206) · state: open · merged: False

## Original PR description

### What does this PR do?

When FSDP score centering processes a recorded sampler head, the head-scoring helper and sampled-token CE currently normalize the same vocabulary separately. This follow-up shares head/sample normalization and computes complete-support loss scores directly in the verified support. Unknown/incomplete rows keep the existing recorded-top-k plus full-vocabulary trainer-tail approximation, including its epsilon regularization. Sampling and recording parameters do not change.

Dependency: the automatic alignment and coverage-receipt changes in #8196. This draft is stacked on codex/sc-auto-support-8196, a mirror of the reviewed #8196 feature head; its diff contains only the two performance commits. It will be retargeted/rebased onto main after #8196 merges. This adds a separate full-local-vocabulary FSDP path. #8199 remains the Megatron/TP extension and can continue to use the unchanged general correction-helper APIs. #8020 proposes broader support replay for IS/RS and is outside this optimization.

A separate FP64 score-domain diagnostic on the same fixture construction explains the numerical sensitivity: shared response-logits gradients differed by 0.0263% relative L2 (max absolute 1.49e-8), versus 0.301% for the legacy path. The original FP32 absolute-logsumexp oracle was itself sensitive to cancellation at near-zero log-probs and is retained in the artifacts rather than treated as ground truth. A singleton-support variant correctly produces zero shared/oracle gradients and is not counted as an effective model update.

These results do not establish training quality, distributed FSDP acceptance or end-to-end RL performance.

### API and Usage Example

No new user configuration is required. SC still tries verified support alignment first and otherwise uses the configured head/trainer approximation. The FSDP engine supplies its already rolled/SP-sliced sampled labels to the SC logits processor. Callers without sampled labels retain the old correction-helper route, and hooks without shared sampled scores retain the existing CE fallback.

Manual benchmark (run on an idle CUDA device):

```bash
CUDA_VISIBLE_DEVICES=0 uv run --active --no-sync python benchmarks/benchmark_score_centering.py --output score_centering_benchmark.json
```

### Design & Code Changes

- Share one chunked full-vocabulary forward normalizer across head/sample scoring and detached head-mass diagnostics. Complete rows normalize their loss directly over finite recorded support.
- Avoid full-vocabulary softmax recomputation in backward for complete rows; fallback rows reuse the shared normalizer. CUDA row selection has no GPU-to-host synchronization.
- Accumulate sparse head/sample collisions in FP32 before casting; retain dense vocabulary-sized logits gradients. Keep logits unchanged for entropy/KL and other graph consumers.
- Pass already local prediction labels through FSDP; gather/unpad outputs once in the packed route and preserve the existing dense route.

The full-vocabulary mass diagnostic still requires O(NV) forward work for every row. This change does not turn the model LM head or dense logits-gradient allocation into K-only work. The new helper requires a materialized full local vocabulary and must not be applied directly to an unmaterialized TP shard.
