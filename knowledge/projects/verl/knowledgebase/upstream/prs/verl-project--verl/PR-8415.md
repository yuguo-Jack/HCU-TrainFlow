# [vllm, rollout] fix: reserve wildcard engine ports and close reservations on failure

[Upstream PR](https://github.com/verl-project/verl/pull/8415) · state: closed · merged: False

## Original PR description

### What does this PR do?

Reserve vLLM engine ports on the IPv4/IPv6 wildcard listener scope while retaining the advertised NIC address. Reserving only the advertised interface can leave the wildcard address used by the engine available to another listener.

Reservations remain held during configuration and are released immediately before engine creation. Partial allocation, launch errors and cancellation release owned sockets; cleanup is idempotent.

### Duplicate-work check

Searched open PRs for [wildcard port](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+wildcard+port) and [port reserve](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+port+reserve) on 2026-10-28. #5706 reserves the Ray worker master port in `single_controller/ray/base.py`; this change covers the vLLM engine listener scope and reservation lifecycle in `vllm_async_server.py`.
