<h1>Release v5.19.0</h1>
<h2>New Model additions</h2>
<h3>EmbeddingGemma2</h3>
<!-- raw HTML omitted -->
<p>EmbeddingGemma 2 is a multimodal embedding model from Google built on the Gemma 4 architecture. It encodes text, images, audio, and video, individually or combined in one input, into a shared 768-dimensional vector space for cross-modal retrieval, semantic similarity, clustering, and classification. It uses Matryoshka Representation Learning, so embeddings can be truncated to 512, 256, or 128 dimensions. It also offers configurable visual and video token budgets, and unused vision or audio towers can be disabled at load time to save memory.</p>
<p><strong>Links:</strong> <a href="https://huggingface.co/docs/transformers/main/en/model_doc/embedding_gemma2">Documentation</a></p>
<ul>
<li>Smthn smthn (<a href="https://redirect.github.com/huggingface/transformers/issues/49364">#49364</a>) by <a href="https://github.com/vasqu"><code>@​vasqu</code></a> in <a href="https://redirect.github.com/huggingface/transformers/pull/49364">#49364</a></li>
</ul>
<h2>Breaking changes</h2>
<p>All MoE models whose routers compute logits now return them when <code>output_router_logits=True</code>, following the Qwen3-MoE pattern (a <code>router_logits</code> recorder on the base model, <code>MoeModelOutputWithPast</code> from the backbone, and a MoE causal LM output from the head), so code that relied on the previous outputs or their absence should read the router logits from these output classes.</p>
<ul>
<li>🚨 Return router logits from every MoE model that computes them (<a href="https://redirect.github.com/huggingface/transformers/issues/48920">#48920</a>) by <a href="https://github.com/qgallouedec"><code>@​qgallouedec</code></a></li>
</ul>
<p><code>Owlv2ForObjectDetection.embed_image_query</code> now selects the query box with the highest objectness score, as in the original OWLv2 notebook, instead of the OWL-ViT heuristic, so image-guided query embeddings and detections may differ from earlier releases.</p>
<ul>
<li>🚨 Select the OWLv2 image query by objectness (<a href="https://redirect.github.com/huggingface/transformers/issues/49200">#49200</a>) by <a href="https://github.com/qgallouedec"><code>@​qgallouedec</code></a></li>
</ul>
<p>The <code>&quot;paged|&quot;</code> prefix for SDPA and flash attention implementations is deprecated, so users should set the regular attention implementation (e.g. <code>sdpa</code> or <code>flash_attention_2</code>) for continuous batching instead of <code>paged|sdpa</code> or <code>paged|flash_attention_2</code>.</p>
<ul>
<li>🚨 Attention 🚨 Deprecate &quot;paged|&quot; prefix for SDPA and flash  (<a href="https://redirect.github.com/huggingface/transformers/issues/49112">#49112</a>) by <a href="https://github.com/remi-or"><code>@​remi-or</code></a></li>
</ul>
<p>The regular flash and SDPA attention functions (<code>flash_attention.py</code>, <code>sdpa_attention.py</code>) now support continuous batching directly, and <code>&quot;paged|...&quot;</code> implementations for these are redirected to them, while eager still requires the <code>&quot;paged|eager&quot;</code> prefix.</p>
<ul>
<li>🚨 Attention 🚨 Make regular attention support CB (<a href="https://redirect.github.com/huggingface/transformers/issues/49101">#49101</a>) by <a href="https://github.com/remi-or"><code>@​remi-or</code></a></li>
</ul>
<p>In continuous batching, the cache update for the index-based and block-table paths is now fused into a single call, which slightly changes the cache update function's behavior and affects any custom code that calls the separate update paths.</p>
<ul>
<li>🚨 [CB] 🚨 Fuse update for index and block table path (<a href="https://redirect.github.com/huggingface/transformers/issues/49088">#49088</a>) by <a href="https://github.com/remi-or"><code>@​remi-or</code></a></li>
</ul>
<p>Continuous batching internals changed in preparation for removing <code>&quot;paged&quot;</code>: `max</p>

<li>🚨 [CB] 🚨 Little fixes before removing &quot;paged&quot; (<a href="https://redirect.github.com/huggingface/transformers/issues/49069">#49069</a>) by <a href="https://github.com/remi-or"><code>@​remi-or</code></a></li>
</ul>
<h2>Parallelization</h2>
<p>Expert parallelism gains a token-dispatch implementation, selected via the new <code>ep_dispatch_experts</code> plan rule and now the default for Qwen3 MoE and Mellum, which removes the requirement that EP size equal TP size. The <code>Trainer</code> was also adapted to work with expert parallelism, and the docs now note that PEFT adapters support tensor parallelism. A CI-related fix for pipeline-parallel chart2table inference was also included.</p>
