# [model] fix: fold post-lm_head logit scaling into the fused-kernel temperature and reject lm_head bias

[Upstream PR](https://github.com/verl-project/verl/pull/8441) · state: open · merged: False

## Original PR description

## What does this PR do?

When `use_fused_kernels=True` is enabled, `patch_forward_with_backends` in `verl/models/transformers/monkey_patch.py` routes causal LM architectures through `forward_with_torch_backend` or `forward_with_triton_backend` in `verl/models/transformers/dense_common.py`. Both functions run `forward_base_model` to obtain the pre-`lm_head` hidden states and pass `(hidden_states, self.lm_head.weight, temperature)` directly to the fused linear cross-entropy kernel (`FusedLinearForPPO` or `linear_cross_entropy`), bypassing the model's `CausalLM.forward` method.

Several standard `transformers` causal LM families apply a mandatory post-`lm_head` logit scaling factor or an additive `lm_head.bias` inside `CausalLM.forward`:

1. **Granite / GraniteMoE / GraniteMoEShared / GraniteMoEHybrid / GraniteSWA / GraniteMoESWA** (`granite`, `granitemoe`, `granitemoeshared`, `granitemoehybrid`, `granite_swa`, `granitemoe_swa`): divides logits by `self.config.logits_scaling` (`3.0` on `granite-4.0-h-350m` up to `16.0` on `granite-3.x-8b` and `granite-4.0-h-small`).
2. **Cohere / Cohere2 / Cohere2MoE / CohereCompassText** (`cohere`, `cohere2`, `cohere2_moe`, `cohere_compass_text`): multiplies logits by `self.logit_scale` (`config.logit_scale`, e.g. `0.0625` on Command R / Aya 23 / Aya Expanse 32B, `0.125` on Aya Expanse 8B, `0.25` on Cohere2 R7B / Command A, and `0.8333` on Command R+).
3. **Falcon-H1** (`falcon_h1`): multiplies logits by `self.model.lm_head_multiplier` (`0.0390625` = `1 / 25.6` on `Falcon-H1-0.5B-Instruct`, `0.01953125` = `1 / 51.2` on `Falcon-H1-1.5B-Instruct`, down to `0.0078125` = `1 / 128` on `Falcon-H1-34B-Instruct`).
4. **HyperCLOVA X** (`hyperclovax`): multiplies logits by `self.config.logits_scaling` (`0.125` = `1 / 8` on `HyperCLOVAX-SEED-Think-14B`).
5. **Models with `lm_head.bias is not None`** (e.g. `phi` where `lm_head` always has `bias=True`, `phimoe` with `lm_head_bias=True`, `ernie4_5_moe` with `use_bias=True`, `zaya` with `lm_head_bias=True`): adds `self.lm_head.bias`, which neither fused kernel accepts.

Because the fused path omits these post-`lm_head` operations while the rollout engine (`vLLM` / `SGLang`) and the non-fused `verl` path execute the full model head, the fused path evaluates a distribution `1.2x` (Command R+) to `128x` (Falcon-H1-34B) sharper (or shifted by `-lm_head.bias`) than the true policy. On `Falcon-H1-0.5B-Instruct` with the Triton backend, the Triton epilogue's cross-split max starts at `0` (`kernels.py` L387; open PR `#7439` changes it to `-inf`): when every unscaled logit in a row is strongly negative (e.g. at most `-119.80` on row 60, whereas the scaled max is `-4.68`), the `float32` `exp`-sum underflows to `0`, the forward returns `log p = +inf`, and the backward computes `exp(z - 0) * (1 / 0) = 0 * inf = NaN`, which the `d(lm_head.weight)` matmul spreads to all `33,570,816` `lm_head.weight.grad` entries.

## API and Usage Example

No public API changes; with `apply_monkey_patch(..., use_fused_kernels=True)`, the fused forward now folds post-`lm_head` logit scaling automatically and raises `ValueError` at the first fused forward if `lm_head.bias is not None`:

```python
import torch
from transformers import AutoConfig, AutoModelForCausalLM
from verl.models.transformers.monkey_patch import apply_monkey_patch

torch.manual_seed(0)

cfg = AutoConfig.for_model(
    "granite",
    hidden_size=128,
    intermediate_size=256,
    num_hidden_layers=2,
    num_attention_heads=4,
    num_key_value_heads=2,
    head_dim=32,
    vocab_size=2048,
    logits_scaling=8.0,
)
model = AutoModelForCausalLM.from_config(cfg).float().eval()
with torch.no_grad():
    model.lm_head.weight.mul_(40.0)

x = torch.randint(0, 2000, (1, 16))
y = torch.roll(x, -1, -1)
T = 0.7

with torch.no_grad():
    ref = torch.log_softmax(model(input_ids=x).logits / T, dim=-1)
    ref_lp = ref.gather(-1, y.unsqueeze(-1)).squeeze(-1)

    apply_monkey_patch(model, use_remove_padding=False, use_fused_kernels=True, fused_kernels_backend="torch")
    out = model(input_ids=x, shift_labels=y, temperature=T, return_dict=True)
    print("Max |fused - ref| log_prob:", (out.log_probs - ref_lp).abs().max().item())
    # Before fix: 51.74467468261719
    # After fix:  0.0
```

## Design & Code Changes

1. Added `_logit_scale_factor(self)` in `verl/models/transformers/dense_common.py`:
   - Raises a clear `ValueError` advising `use_fused_kernels=False` when `getattr(self.lm_head, "bias", None) is not None` (behavior change: models with a biased `lm_head` such as `phi`, `phimoe` with `lm_head_bias=True`, `ernie4_5_moe` with `use_bias=True`, and `zaya` with `lm_head_bias=True` now fail fast at the first fused forward instead of silently computing unshifted log-probs).
   - Returns the model's multiplicative logit scale $c$ for `_GRANITE_MODEL_TYPES` (`1.0 / logits_scaling`), `_COHERE_MODEL_TYPES` (`logit_scale`), `falcon_h1` (`model.lm_head_multiplier`), and `hyperclovax` (`logits_scaling`), or `1.0` otherwise.
2. Passed `temperature / _logit_scale_factor(self)` into `FusedLinearForPPO.forward` (`forward_with_torch_backend`) and `linear_cross_entropy` (`forward_with_triton_backend`), since $(W h \cdot c) / T = (W h) / (T / c)$ for $c > 0$.
3. **Out of scope:**
   - `final_logit_softcapping` (handled by `#7991`);
   - Megatron fused kernel path (`verl/models/mcore/model_forward_fused.py`);
   - `inkling_text` (which also slices `logits` to `unpadded_vocab_size`) and VLM wrapper classes routed through `dense_common` whose transform lives on `text_config` (`granite4_vision`, `cohere_compass`, `inkling_mm_model`).

**Handle zero post-`lm_head` scales before the fused division.**

The Cohere lookup uses `or`, so an instance `logit_scale` of `0` selects `config.logit_scale`. When both values are zero, the lookup returns `0.0`. Both fused call sites then evaluate `temperature / _logit_scale_factor(self)` with a zero divisor and raise `ZeroDivisionError`. The native Cohere forward produces zero logits for this case. When only the instance value is zero and the config value is nonzero, the fallback silently changes the scale and the log probabilities.

Falcon-H1 `lm_head_multiplier` and HyperCLOVAX `config.logits_scaling` reach the same division with a zero value. Replace the `or` with a `None` check. Reject zero in all three branches with an actionable `ValueError`.
