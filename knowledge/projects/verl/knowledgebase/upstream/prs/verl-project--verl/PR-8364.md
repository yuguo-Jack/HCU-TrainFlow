# [trainer, algo] fix: pass sum_pi_squared through the V1 trainer for optimal token baseline

[Upstream PR](https://github.com/verl-project/verl/pull/8364) · state: open · merged: False

## Original PR description

### What does this PR do?

Optimal token baseline (`optimal_token_baseline`, `tir_optimal_token_baseline`) does not work on the V1 trainer, which `main_ppo` now uses by default. Step 1 fails with:

```
AssertionError: Step-dependent optimal baseline requires sum_pi_squared from actor. Please set actor.calculate_sum_pi_squared=True in config.
```

This happens even when `actor.calculate_sum_pi_squared=True` is set. #6153 wired `sum_pi_squared` into the engine and the legacy `ray_trainer.py`, but V1's `PPOTrainer` does not pass it through:

- `_compute_old_log_prob` never puts `calculate_sum_pi_squared` into `extra_info`, so the engine never computes it.
- It also never reads `sum_pi_squared` back from TransferQueue.
- `_compute_advantage` does not select it, so `compute_advantage()` never sees it.

The fix forwards the flag. When the flag is set, it reads the actor's `sum_pi_squared`, slices it to the response with `response_from_nested`, and writes it back. This is the same left shift used for `old_log_probs` and `entropy`. `_compute_advantage` then fetches it. With the flag off, nothing changes.

**Not a duplicate:**
- Searched open and closed PRs and issues for `sum_pi_squared`, `optimal token baseline` and `optimal_token_baseline v1`. #6153 and #5615 (both merged) only cover the legacy trainer. #7473 (open) touches `ray_trainer.py` only, and #8026 (open) leaves `sum_pi_squared` alone.

### Test

**CPU unit test:** `tests/trainer/ppo/v1/test_sum_pi_squared_on_cpu.py` uses an in-memory TransferQueue stand-in. It checks three things:
- the flag reaches `extra_info`;
- the stored `sum_pi_squared` is the response-aligned slice (and is left untouched when the flag is off);
- OTB and TIR-OTB produce finite advantages through `_compute_advantage`.

```
pytest -q tests/trainer/ppo/v1/test_sum_pi_squared_on_cpu.py tests/trainer/ppo/v1/test_trainer_base_on_cpu.py
# with this PR: 14 passed
# test_sum_pi_squared_on_cpu.py on main: 4 failed (KeyError: 'calculate_sum_pi_squared' x2, OTB AssertionError x2)
```

**GPU run:** 1x RTX 4090, main @ 3c6d9b4, V1 sync trainer, Qwen3-0.6B, GSM8K, batch 32 × n=4, 3 steps, vLLM rollout, `actor.calculate_sum_pi_squared=True`, `rollout.log_prob_micro_batch_size_per_gpu=4`:

| run | result | `rollout_probs_diff_mean` | `critic/advantages/mean` | `critic/advantages/max` |
|---|---|---|---|---|
| main, `optimal_token_baseline` | AssertionError at step 1 | – | – | – |
| this PR, `optimal_token_baseline` | 3/3 steps | 0.0058 / 0.0059 / 0.0056 | 0.0062 / 0.0030 / -0.0002 | 1.28 / 1.38 / 1.16 |
| this PR, `tir_optimal_token_baseline` | 3/3 steps | 0.0058 / 0.0059 / 0.0056 | 0.0086 / 0.0008 / -0.0019 | 1.50 / 1.00 / 0.99 |

Side note, not changed here: with the default `log_prob_micro_batch_size_per_gpu=16`, step 2 OOMs on a 24 GB card in `calculate_sum_pi_squared_from_logits`. The cause is `logsumexp(2.0 * logits)`, which materializes another full-vocabulary copy, about 5 GB for a packed micro-batch. A chunked version like `entropy_from_logits_with_chunking` would avoid this; I can follow up if that is wanted.

### Design & Code Changes

`verl/trainer/ppo/v1/trainer_base.py`:
- `_compute_old_log_prob`:
  - add `calculate_sum_pi_squared` to `extra_info`;
  - when it is set, select `sum_pi_squared`, slice it to the response, and write it to TransferQueue next to `old_log_probs` / `entropy`.
- `_compute_advantage`: select `sum_pi_squared` when the flag is set.
