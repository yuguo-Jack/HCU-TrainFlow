# [rollout, sglang] fix: reject late submissions to deactivated replicas

[Upstream PR](https://github.com/verl-project/verl/pull/8387) · state: open · merged: False

## Original PR description

### What does this PR do?

A request can acquire a rollout actor handle immediately before that replica is removed from routing. If it reaches SGLang after generation is paused and KV memory is released, it currently waits for that replica to resume instead of retrying an available peer.

V1 already calls `abort_replicas(reject_request=True)` when returning hybrid GPUs to training, but SGLang ignores the flag. Honor it in the public SGLang submission layer: return an aborted `TokenOutput` so the existing async client retries. The legacy controller also requests rejection on deactivation. Temporary weight-sync pauses keep their waiting behavior. Pause/resume control is serialized; failed control leaves admission closed until an explicit resume succeeds.

Related to #8186. This fixes the public V1 path independently of the planned legacy fully-async migration.

### API and Usage Example

The existing contract now works for SGLang:

```python
await checkpoint_manager.abort_replicas(reject_request=True)
await checkpoint_manager.sleep_replicas()
```

The default `reject_request=False` still parks submissions during a temporary pause. No new user configuration.

### Design & Code Changes

- Add a SGLang submission gate and serialize generation-control calls.
- Forward the existing rejection flag through the SGLang replica; enable it in the legacy deactivation controller.
- Add 13 focused regressions and an explicit CI entry.
