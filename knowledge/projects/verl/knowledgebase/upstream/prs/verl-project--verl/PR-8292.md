# [hardware] fix: pin tensordict and install orjson in the TPU GRPO image

[Upstream PR](https://github.com/verl-project/verl/pull/8292) · state: closed · merged: True

## Original PR description

### What does this PR do?

Fixes the TPU GRPO image (`examples/tpu/grpo/Dockerfile`, from #8288): an image built today fails at `import verl` with

```
ModuleNotFoundError: No module named 'orjson'
```

`verl/utils/tracking.py` imports `orjson`, which verl does not list as a dependency. The image used to get it through tensordict, but tensordict 0.15.2 (released 2026-10-19) dropped its `orjson` requirement, and the Dockerfile's unpinned `tensordict>=0.10.0` now resolves to 0.15.2.

### Changes

`examples/tpu/grpo/Dockerfile` only:

- pin `tensordict==0.15.1`, the version the TPU examples were tested with;
- install `orjson` explicitly.

### Test

The TPU CI built the image from this Dockerfile, with no cache, and ran on it with verl-hardware-plugin `c76de674`, the commit `examples/tpu/grpo/README.md` checks out:

| Test | Result |
|---|---|
| [tpu_unit_tests](https://github.com/jialei777/verl-upstream/actions/runs/39361783003) (`import verl` with the plugin, `torch_tpu` ops) | Passed. Without this fix it fails with the `orjson` error above |
| [e2e_sft_llm_tpu](https://github.com/jialei777/verl-upstream/actions/runs/39361782915) (Qwen3-0.6B SFT, `torchrun` and Ray, 1x v6e-4) | Passed: train/loss 1.38 -> 0.55, val/loss 0.72 -> 0.61 |
| [e2e_v1_separate_async_tpu](https://github.com/jialei777/verl-upstream/actions/runs/39361782903) (the README's 2-chip Qwen3-0.6B GRPO, 2x v6e-1) | Passed: 5 steps, val acc 0.25 / 0.375 / 0.125, max rollout-vs-trainer KL 0.0013 |
