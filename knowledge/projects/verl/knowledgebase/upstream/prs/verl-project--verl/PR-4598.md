[Upstream PR](https://github.com/verl-project/verl/pull/4598) · state: open · merged: False

## Original PR description

### What does this PR do?

When the reward within a group is a floating-point number (e.g., 0.2), (scores[i] - id2mean[index[i]]) suffers from numerical computation errors, causing advantages that should be zero to become non-zero.
The PyTorch version is 2.9.

This loop over the batch size is inefficient and can be a performance bottleneck. It's recommended to use a vectorized implementation for better performance.

Additionally, the related function `compute_grpo_vectorized_outcome_advantage` appears to have the same numerical precision issue and would likely benefit from a similar fix.

```suggestion
        means = torch.stack([id2mean[idx] for idx in index])
        stds = torch.stack([id2std[idx] for idx in index])

        if norm_adv_by_std_in_grpo:
            adv = (scores - means) / (stds + epsilon)
        else:
            adv = scores - means

        # Handle numerical precision issues by setting advantage to 0 when score is close to mean
        is_close_mask = torch.isclose(scores, means, atol=epsilon)
        adv[is_close_mask] = 0.0
        scores = adv
```
