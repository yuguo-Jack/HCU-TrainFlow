# [ckpt, fsdp] fix: detect sharded mesh after replicated buffers

[Upstream PR](https://github.com/verl-project/verl/pull/8016) · state: closed · merged: False

## Original PR description

### What does this PR do?

Fix FSDP checkpoint conversion when a replicated buffer sorts before the sharded parameters.

`_extract_device_mesh_info` only inspects the alphabetically first key. If it is a plain tensor, the fallback mesh has shape `(1,)` and the merger loads only rank 0, even when later entries are DTensors sharded across multiple ranks. A two-rank CPU checkpoint with a scalar buffer and a `(4, 2)` sharded weight currently merges to just `(2, 2)`.

Search the state dict for a DTensor and use its actual mesh. The non-DTensor fallback and placement merging are unchanged. Tests cover `fsdp`, VeOmni's `dp_shard`, and `ddp/fsdp` meshes, plus controls where the DTensor sorts first.
