Updates the requirements on [tensordict](https://github.com/pytorch/tensordict) to permit the latest version.
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/pytorch/tensordict/releases">tensordict's releases</a>.</em></p>
<blockquote>
<h2>TensorDict v0.15.1</h2>
<h2>Highlights</h2>
<p>TensorDict 0.15.1 is a patch release with 46 bug fixes. They cover <code>update_</code>, <code>copy_</code> and in-place math on lazy stacks, h5 files and <code>TypedTensorDict</code>, <code>UnbatchedTensor</code> and non-tensor data, NumPy conversion, <code>tensordict.nn</code>, and <code>torch.compile</code>. There are no new features or deprecations. Several fixes change behavior that was previously wrong; see &quot;Behavior changes&quot; below.</p>
<h2>Bug Fixes</h2>
<h3>Construction and conversion</h3>
<ul>
<li><code>td.new_tensor(data)</code> takes a list, tuple, NumPy array or scalar, as <code>torch.Tensor.new_tensor</code> does; before, it raised <code>AttributeError</code> (<a href="https://redirect.github.com/pytorch/tensordict/issues/2748">#2748</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2747">#2747</a>).</li>
<li>A list of tensors of different shapes in <code>TensorDict(...)</code> or <code>set</code> becomes a <code>NonTensorStack</code>, as with <code>from_dict</code>; before, it raised <code>AttributeError</code> (<a href="https://redirect.github.com/pytorch/tensordict/issues/2751">#2751</a>).</li>
<li>NumPy arrays with negative strides, fields of packed structured arrays and big-endian arrays are copied into a tensordict; before, they raised a misleading <code>ValueError</code> (<a href="https://redirect.github.com/pytorch/tensordict/issues/2853">#2853</a>, <a href="https://redirect.github.com/pytorch/tensordict/issues/2855">#2855</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2852">#2852</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2854">#2854</a>).</li>
</ul>
<h3>Keys, get, set and update</h3>
<ul>
<li><code>td.update({&quot;x&quot;: td})</code>, and <code>p[&quot;x&quot;] = p</code> on a <code>TensorDictParams</code>, raise <code>ValueError</code>; before, they left a tensordict that holds itself, or raised <code>RecursionError</code> (<a href="https://redirect.github.com/pytorch/tensordict/issues/2764">#2764</a>).</li>
<li>Gradients flow through <code>update_</code> and <code>copy_</code>; before, <code>backward()</code> through the written leaves raised, and compiled code with these calls failed to compile (<a href="https://redirect.github.com/pytorch/tensordict/issues/2881">#2881</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2863">#2863</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2886">#2886</a>).</li>
<li><code>copy_</code>, <code>update_</code> (also with <code>keys_to_update</code>) and in-place math write the h5 files and lazy stacks that a <code>TensorDict</code> holds; before, these silently kept their values (<a href="https://redirect.github.com/pytorch/tensordict/issues/2777">#2777</a>, <a href="https://redirect.github.com/pytorch/tensordict/issues/2838">#2838</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2775">#2775</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2780">#2780</a>).</li>
<li><code>split_keys(..., reproduce_struct=True)</code> puts each non-tensor entry, and each entry that only some lazy-stack members hold, in one part; before, every part got a copy (<a href="https://redirect.github.com/pytorch/tensordict/issues/2802">#2802</a>, <a href="https://redirect.github.com/pytorch/tensordict/issues/2841">#2841</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2782">#2782</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2803">#2803</a>).</li>
</ul>
<h3>Arithmetic, reductions and torch functions</h3>
<ul>
<li><code>torch.where(mask, 0, td)</code> and <code>torch.where(mask, tensor, td)</code> work on tensordicts and tensorclasses; before, they raised <code>AttributeError</code> and <code>TypeError</code> (<a href="https://redirect.github.com/pytorch/tensordict/issues/2762">#2762</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2743">#2743</a>).</li>
<li><code>named_apply(fn, out=buf)</code> writes into <code>buf</code> and returns it, as <code>apply</code> does; before, it returned a new tensordict and left <code>buf</code> unchanged (<a href="https://redirect.github.com/pytorch/tensordict/issues/2846">#2846</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2845">#2845</a>).</li>
</ul>
<h3>Lazy stacks, stack and cat</h3>
<ul>
<li>Printing a lazy stack or a <code>TypedTensorDict</code> over one stacks no tensors; before, it stacked every entry twice, which can exhaust GPU memory (<a href="https://redirect.github.com/pytorch/tensordict/issues/2799">#2799</a>, <a href="https://redirect.github.com/pytorch/tensordict/issues/2829">#2829</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2783">#2783</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2800">#2800</a>).</li>
<li><code>filter_empty_()</code> and <code>split_keys()</code> work on a lazy stack whose members hold empty sub-tensordicts; before, they raised <code>KeyError</code> (<a href="https://redirect.github.com/pytorch/tensordict/issues/2806">#2806</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2796">#2796</a>).</li>
<li>When one member of a lazy stack rejects its part of <code>update_</code> or <code>copy_</code>, nothing is written; before, the earlier members were already written (<a href="https://redirect.github.com/pytorch/tensordict/issues/2837">#2837</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2776">#2776</a>).</li>
<li><code>update_</code> and <code>copy_</code> broadcast a 0-d or size-1 value into a lazy stack inside a <code>TensorDict</code>; before, the value was silently dropped (<a href="https://redirect.github.com/pytorch/tensordict/issues/2850">#2850</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2834">#2834</a>).</li>
<li><code>empty(recurse=True)</code> drops the tensors of a lazy stack inside a tensordict, as at the root; before, member-only tensors kept their values (<a href="https://redirect.github.com/pytorch/tensordict/issues/2847">#2847</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2840">#2840</a>).</li>
<li><code>flatten_keys()</code> on a lazy stack keeps each member's values and shares their tensors; before, every member got the first member's <code>UnbatchedTensor</code>, and leaves were copies (<a href="https://redirect.github.com/pytorch/tensordict/issues/2890">#2890</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2869">#2869</a>).</li>
</ul>
<h3>Non-tensor data and UnbatchedTensor</h3>
<ul>
<li><code>NonTensorData.update_at_</code> with a NumPy array index raises the <code>RuntimeError</code> that a list or tensor index raises; before, it raised a confusing <code>ValueError</code> (<a href="https://redirect.github.com/pytorch/tensordict/issues/2727">#2727</a>).</li>
<li>Writing non-tensor data at a 0-d <code>True</code> or <code>None</code> index works on a tensordict without batch dims; before, it raised <code>IndexError</code> (<a href="https://redirect.github.com/pytorch/tensordict/issues/2750">#2750</a>).</li>
<li><code>set</code> of an <code>UnbatchedTensor</code> into a lazy stack stores it in every member, and <code>flatten_keys()</code> and <code>unflatten_keys()</code> work on such stacks; before, these raised (<a href="https://redirect.github.com/pytorch/tensordict/issues/2867">#2867</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2864">#2864</a>).</li>
<li><code>update_</code> and <code>copy_</code> of an <code>UnbatchedTensor</code> in a lazy stack work along any stack dim; before, a stack dim other than 0 raised <code>ValueError</code> (<a href="https://redirect.github.com/pytorch/tensordict/issues/2873">#2873</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2868">#2868</a>).</li>
</ul>
<h3>Tensorclasses</h3>
<ul>
<li>A tensorclass's <code>get_at</code> takes <code>default=</code> and passes other keywords, such as <code>as_list=True</code>, to <code>get</code>, as <code>TensorDict.get_at</code> does; before, it raised <code>KeyError: 'default'</code> (<a href="https://redirect.github.com/pytorch/tensordict/issues/2832">#2832</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2830">#2830</a>).</li>
</ul>
<h3>TypedTensorDict</h3>
<ul>
<li>In-place math on a <code>TypedTensorDict</code> over lazy stacks whose members hold different keys works; before, it raised or wrote entries it should not (<a href="https://redirect.github.com/pytorch/tensordict/issues/2760">#2760</a>, <a href="https://redirect.github.com/pytorch/tensordict/issues/2769">#2769</a>, <a href="https://redirect.github.com/pytorch/tensordict/issues/2839">#2839</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2739">#2739</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2759">#2759</a>).</li>
<li><code>dense.copy_(src)</code> and <code>dense.update_(src)</code> write the nested entries of a <code>TypedTensorDict</code> over a lazy stack; before, those entries kept their old values (<a href="https://redirect.github.com/pytorch/tensordict/issues/2770">#2770</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2768">#2768</a>).</li>
<li><code>t + 1</code>, <code>copy_</code> and <code>update_</code> work on a <code>TypedTensorDict</code> over a lazy stack, whatever its members; before, they raised or skipped nested entries (<a href="https://redirect.github.com/pytorch/tensordict/issues/2774">#2774</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2771">#2771</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2772">#2772</a>, fixes <a href="https://redirect.github.com/pytorch/tensordict/issues/2773">#2773</a>).</li>
</ul>
