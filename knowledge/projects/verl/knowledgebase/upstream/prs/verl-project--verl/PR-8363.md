# [sglang, rollout] fix: honour rollout.logprobs_mode on the SGLang rollout

[Upstream PR](https://github.com/verl-project/verl/pull/8363) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes #8362. The SGLang rollout ignores `rollout.logprobs_mode`. It always returns log-probs of the temperature-scaled full-vocabulary distribution, so:
- `raw_logprobs` has no effect on SGLang;
- `processed_logprobs` does not reflect top-k / top-p truncation, whereas vLLM's are normalised over the kept tokens.

With the same config, rollout-correction weights and mismatch metrics therefore differ between the two backends. See the measurements in #8362.

This PR:
- **Sets `SGLANG_RETURN_ORIGINAL_LOGPROB=1` for `logprobs_mode=raw_logprobs`** before the scheduler processes start, so SGLang returns pre-temperature log-probs as vLLM does.
- **Rejects modes SGLang cannot return** (`raw_logits`, `processed_logits`) when `calculate_log_probs=True`.
- **Warns when `processed_logprobs` is combined with `top_p < 1` or `top_k > 0`** on SGLang. SGLang has no way to return log-probs over the kept set, so the difference is made explicit instead of silent.

### Test

GSM8K, GRPO, Qwen3-0.6B, 32 prompts × n=4, 2 steps, one RTX 4090, vllm 0.29.0 / sglang 0.5.20 from `uv.lock`, `rollout_is=token`, temperature 0.7, top_p 1.0. Each cell shows the step-1 / step-2 values.

| backend | `logprobs_mode` | `rollout_corr/rollout_is_mean` | `training/rollout_probs_diff_mean` |
|---|---|---|---|
| vLLM | processed | 0.9997 / 0.9999 | 0.0080 / 0.0080 |
| vLLM | raw | 1.0336 / 1.0326 | 0.0389 / 0.0392 |
| SGLang (main) | processed | 0.9999 / 1.0001 | 0.0080 / 0.0082 |
| SGLang (main) | raw | 1.0006 / 1.0001 | 0.0082 / 0.0080 |
| **SGLang (this PR)** | **raw** | **1.0332 / 1.0343** | **0.0386 / 0.0395** |

With this PR, SGLang `raw_logprobs` matches vLLM `raw_logprobs`; on `main` it is identical to `processed_logprobs`. `SGLANG_RETURN_ORIGINAL_LOGPROB` reaches the scheduler processes, which re-read it at import.

CPU tests in `tests/workers/config/test_rollout_config_on_cpu.py`:
- the unsupported-mode error;
- the truncation warning;
- no warning for untruncated `processed_logprobs` or for `raw_logprobs`.

`pytest tests/workers/config/test_rollout_config_on_cpu.py`: 4 passed. `ruff check` and `ruff format --check` on the changed files: clean.

### API and Usage Example

No API change. `actor_rollout_ref.rollout.logprobs_mode=raw_logprobs` now takes effect on SGLang. Configs that SGLang cannot serve now fail fast (unsupported mode) or warn (truncated `processed_logprobs`).

### Design & Code Changes

- `verl/workers/rollout/sglang_rollout/async_sglang_server.py`: set the env var for `raw_logprobs` next to the existing `SGLANG_BLOCK_NONZERO_RANK_CHILDREN`, before `Engine._launch_subprocesses`.
- `verl/workers/config/rollout.py`: SGLang-specific validation in `RolloutConfig.__post_init__`, next to the existing `topk_log_probs` checks.
- `tests/workers/config/test_rollout_config_on_cpu.py`: three CPU tests.
