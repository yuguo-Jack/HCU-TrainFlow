# [data] fix: keep the first NonTensorData in concat_tensordict with tensordict >= 0.11

[Upstream PR](https://github.com/verl-project/verl/pull/8453) · state: closed · merged: True

## Original PR description

### What does this PR do?

`concat_tensordict` treats `NonTensorData` as per-batch metadata and keeps the first instance. `concat_tensordict_with_none_bsz` documents this ("metadata concatenation simply preserves the first instance"), and `test_concat_tensordict` asserts it (`output["temp"] == 1.0`). `TensorDict.cat` behaved that way up to tensordict 0.10. From tensordict 0.11 it stacks `NonTensorData` values that differ into a `NonTensorStack` with one value per sample. This PR restores the first input's `NonTensorData` after `TensorDict.cat`, in both branches of `concat_tensordict` (regular and nested tensors). With tensordict <= 0.10 nothing changes.

How it shows up: `examples/tpu/grpo/Dockerfile` pins `tensordict==0.15.1` (#8292). There, the per-rank outputs of `TrainingWorker.infer_batch` are concatenated through `BatchData.concat` -> `concat_tensordict`. If their `metrics` differ between data-parallel ranks, they come back as a list, and `sft_trainer_ray` fails in validation:

```
  File "verl/trainer/sft_trainer_ray.py", line 365, in fit
    val_losses.append(metrics["loss"])
TypeError: list indices must be integers or slices, not str
```

The metrics differ, for example, once `perf/max_memory_allocated_gb` reports each TPU rank's real peak memory (verl-project/verl-hardware-plugin#91). Until now it read 0 on every rank. `ray_trainer.py`'s `tu.get(output, "metrics")["mfu"]` after `compute_log_prob` reads the same structure. `train_batch` is not affected, because its outputs have no batch dimension and go through `concat_tensordict_with_none_bsz`.

### Test

- `tests/test_protocol_v2_on_cpu.py -k concat`:

  | | tensordict 0.10.0 (verl's pin) | tensordict 0.15.1 (TPU image) |
  |---|---|---|
  | before | 3 passed | `test_concat_tensordict` fails: `output["temp"]` is `[1.0, 1.0, 2.0, 2.0]` |
  | after | 4 passed | `test_concat_tensordict` and the new `test_concat_tensordict_keeps_the_first_metadata` pass |

  `test_chunk_concat` also fails with tensordict 0.15.1, before and after this PR. It calls `torch.cat` on TensorDicts directly, so it tests tensordict's own behaviour rather than verl's helper.
- New `test_concat_tensordict_keeps_the_first_metadata`: rank outputs with different `metrics`, with regular tensors and with nested tensors.
- TPU CI (Cloud TPU v6e on GKE, `examples/tpu` recipes with this branch's image and tensordict 0.15.1). The runs use verl `2ab35292` plus this commit (`1ffe98bf`), and verl-hardware-plugin with real per-rank TPU memory metrics:

  | Workflow | Without this PR (verl `2ab35292`) | With this PR (`1ffe98bf`) |
  |---|---|---|
  | `e2e_sft_llm_tpu` (Qwen3-0.6B SFT, 4 DP ranks, Ray + torchrun) | [failed](https://github.com/jialei777/verl-upstream/actions/runs/40961393275) with the `TypeError` above | [passed](https://github.com/jialei777/verl-upstream/actions/runs/40965388507): train/loss 1.38 -> 0.55, val/loss 0.72 -> 0.61, with the same losses as before |
  | `tpu_unit_tests` | [passed](https://github.com/jialei777/verl-upstream/actions/runs/40961393319) | [passed](https://github.com/jialei777/verl-upstream/actions/runs/40965490913) |
  | `e2e_v1_separate_async_tpu` (GRPO, 1 trainer rank) | [passed](https://github.com/jialei777/verl-upstream/actions/runs/40961393209) | [passed](https://github.com/jialei777/verl-upstream/actions/runs/40965494960) |

  The crash does not need the new memory metrics. With memory metrics that are 0.0 on every rank, the SFT run still [failed the same way](https://github.com/jialei777/verl-upstream/actions/runs/40964850889) in one run. In that case the only per-rank value left in the metrics is psutil's `perf/cpu_memory_used_gb`, which each rank reads at a slightly different moment.

No API change.

### Design & Code Changes

- `verl/utils/tensordict_utils.py`: `_keep_first_non_tensor_data(output, first)` puts back `first`'s `NonTensorData` values that `TensorDict.cat` turned into something else. `concat_tensordict` applies it after both of its `TensorDict.cat` calls.
- `tests/test_protocol_v2_on_cpu.py`: `test_concat_tensordict_keeps_the_first_metadata`.
