# [trainer] fix: seed SFT dataloader generators so resume keeps the restored CPU RNG

[Upstream PR](https://github.com/verl-project/verl/pull/8434) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes #8433.

`SFTTrainer` built its train/val `StatefulDataLoader`s without a `generator`, so every iterator construction drew a `base_seed` from the global CPU RNG. On resume that draw happens right after the checkpoint manager restores `torch.get_rng_state()`, so the resumed run continued from a different global CPU RNG state than an uninterrupted run. This PR gives each dataloader its own seeded `torch.Generator`, so building iterators no longer touches the global CPU RNG and the restored state is the one training actually continues with.

### Test

New CPU test `tests/trainer/test_sft_dataloader_resume_rng_on_cpu.py` (picked up by `cpu_unit_tests.yml` via the `*_on_cpu.py` pattern). It calls the real `SFTTrainer._build_dataloader` with a stub engine and checks:

1. resume: after saving dataloader state + `torch.get_rng_state()`, rebuilding, restoring both and building the iterator, the next batches **and** subsequent global CPU RNG draws match the uninterrupted run;
2. building train/val iterators does not change `torch.get_rng_state()`;
3. generator seeds are distinct per dp rank and between train and val.

Locally (torch 2.15.0, torchdata 0.11.0):

```
with the fix:    3 passed
without the fix: 3 failed
```

`ruff check`, `ruff format --check`, `check_license.py` and `check_docstrings.py` pass on the touched files.

### API and Usage Example

No API change. The existing (previously unused by the SFT trainer) `trainer.seed` in `sft_trainer_engine.yaml` now seeds the dataloader generators.

### Design & Code Changes

- `verl/trainer/sft_trainer.py`: pass `generator=torch.Generator().manual_seed(seed + dp_rank)` to the train dataloader and `seed + dp_size + dp_rank` to the val dataloader, with `seed = config.trainer.seed`.
  - Per **dp** rank, not global rank: ranks in one dp group restore the same `data_{dp_rank}.pt`, so they must derive the same `base_seed`.
  - Separate train/val streams, so building a val iterator can never shift the train one.
  - Batch order is unchanged: `DistributedSampler` shuffles from its own `seed + epoch`; the generator only feeds the iterator's `base_seed` (worker seeding).
- `tests/special_sanity/check_license.py`: add the `Copyright 2026 Individual Contributor:` header (the 2025 variant already exists; other organizations already have `_26` variants) for the new test file.
