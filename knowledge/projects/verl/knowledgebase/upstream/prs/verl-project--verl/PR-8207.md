# [trainer, cfg] fix: guard rollout correction against truncated sample…

[Upstream PR](https://github.com/verl-project/verl/pull/8207) · state: open · merged: False

## Original PR description

…rs (#8020)

With logprobs_mode=processed_logprobs (default) the rollout engine returns log-probs renormalized over the top_p/top_k/min_p truncated support, while the actor's old_log_probs are full-vocabulary. The correction ratio old_log_prob - rollout_log_prob therefore carries the truncated mass on every token: sequence-level IS weights collapse below lower bounds and k1 rejection bounds (0.999_1.001, 0.5_2.0) reject every sequence, so the Geo-RS / Seq-MIS presets silently produce zero gradient (issue #8020).

- validate_config now raises an actionable error when rollout_is/rollout_rs correction is combined with a truncated sampler and processed log-probs.
- compute_rollout_correction_and_rejection_mask warns (once per process) when a batch ends up fully rejected or fully zero-weighted.
- compute_is_metrics no longer raises ZeroDivisionError on the ESS metric when IcePop zeroes every weight; it reports ESS 0.0 instead.
