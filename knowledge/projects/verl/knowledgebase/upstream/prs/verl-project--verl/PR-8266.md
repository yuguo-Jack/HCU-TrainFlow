# [doc, hardware] feat: run the TPU GRPO Qwen3-0.6B example on 2 chips (2x v6e-1)

[Upstream PR](https://github.com/verl-project/verl/pull/8266) · state: closed · merged: False

## Original PR description

### What does this PR do?

Lowers the hardware you need to try the TPU GRPO example from **8 chips (2x `v6e-4`) to 2 chips (2x `v6e-1`)**. One chip runs the TorchTitan trainer and one runs the vLLM rollout. Users with little TPU quota can now run the Qwen3-0.6B GSM8K example end to end. The Qwen3-4B setup is still documented, with the exact changes needed to scale up.

### Changes

- `examples/tpu/grpo/ray-tpu-v6e4-2slice.yaml` -> `ray-tpu-v6e-2slice.yaml`: defaults to 2 single-host `v6e-1` slices (`google.com/tpu: "1"`, `cpu: "32"`, `memory: 128Gi`, topology `1x1`). Comments next to each field give the `v6e-4` / `v6e-8` values.
- `examples/tpu/grpo/run_qwen3_0_6b_torchtitan.sh`:
  - Defaults to `N_CHIPS_TRAINER=1 N_CHIPS_ROLLOUT=1`. Set `N_CHIPS_TRAINER=4 N_CHIPS_ROLLOUT=4` for 2x `v6e-4`.
  - Uses the same trainer and rollout settings as `run_qwen3_4b_torchtitan.sh`: torch.compile with splash attention, SimpleFSDP, sequence-length bucketing on the actor and the ref, bypass-mode rollout correction (`calculate_log_probs=True`), and a larger vLLM batch (`max_num_seqs=64`, `max_num_batched_tokens=4096`).
  - Sets `data.dataloader_num_workers=0`, as in the 4B script.
- `examples/tpu/grpo/README.md`:
  - The 2-chip Qwen3-0.6B smoke test is now the default flow (steps 1-5, with a `ct6e-standard-1t` node pool).
  - New section 6, "Run Qwen3-4B on 2 `v6e-4` slices": upload the 4B model, create the `v6e-4` node pool, change the YAML, submit the job. Also covers 2x `v6e-8`.

### Test

On GKE with 2x `v6e-1` (`ct6e-standard-1t`), image built from `examples/tpu/grpo/Dockerfile`, and `verl-hardware-plugin` at the commit pinned in the README. Commands copied from the README.

| Run | Result |
|---|---|
| 5-step smoke test (script defaults) | Passed `tests/special_tpu/verify_tpu_e2e_log.py grpo --steps 5`. About 5-6 min from submit to the step-1 metrics (includes XLA compilation). After that, compiled steps take **~2 s**. Max rollout-vs-trainer KL 0.0014. |
| 20 steps (`TOTAL_TRAINING_STEPS=20 TEST_FREQ=5 VAL_BEFORE_TRAIN=True VAL_MAX_SAMPLES=64`) | Passed the same verifier with `--steps 20`. GSM8K val acc (64 samples) went 0.125 (step 0) -> 0.172 (step 10) -> 0.219 (step 20). Max rollout-vs-trainer KL 0.0019. |

These are smoke tests: `train_batch_size=4` and lr `1e-6`, so per-step rewards are noisy. The 4B script and its convergence results are unchanged.
