# [reward] fix: accept markdown-decorated answers in math_dapo Minerva scoring

[Upstream PR](https://github.com/verl-project/verl/pull/8450) · state: open · merged: False

## Original PR description

### What does this PR do?

`verl/utils/reward_score/math_dapo.py` scores the Minerva `Answer: ...` format by extracting the text that follows the `Answer:` label and comparing it with the ground truth. The extracted text kept the markdown emphasis that models put around the answer label or around the answer value, so a correct answer was scored as wrong.

| model output | score before | score after |
| --- | --- | --- |
| `**Answer:** 42` | `-1.0` | `1.0` |
| `Answer: **42**` | `-1.0` | `1.0` |
| `**Answer:**\n\n42` | `-1.0` | `1.0` |
| `` `Answer:`\n\n42 `` | `-1.0` | `1.0` |
| `**Answer**: 42` | `-1.0` | `1.0` |
| `Answer: **_42_**` | `-1.0` | `1.0` |
| `__Answer: 42__` | `-1.0` | `1.0` |
| `Answer: 42` | `1.0` | `1.0` |
| `Answer: x*` (ground truth `x*`) | `-1.0` | `1.0` |
| `Answer: **42**.` | `-1.0` | `1.0` |
| `**Answer:** 42.` | `-1.0` | `1.0` |
| `Answer: 42.` | `-1.0` | `1.0` |
| `The result is \boxed{42}` | `1.0` | `1.0` |

Fixes #8449.

### Trailing sentence period

A model that ends its answer sentence with a period (`Answer: 42.`) produced the prediction `42.` and was scored wrong against the ground truth `42`. The period is punctuation, not part of the answer, and models add it routinely. It is removed before the markdown markers are stripped, so a decorated answer that is followed by a period (`**Answer:** 42.`) still reduces to the bare answer. The ground truth is stripped the same way, so a reference that carries a trailing period still matches. Answers that merely *contain* a period are unaffected: `3.14`, `x_1`, `x*` and `\frac{1}{2}` keep their exact text.

### Design & Code Changes

`verl/utils/reward_score/math_dapo.py`

- New helper `_strip_markdown_emphasis()`: removes the markdown emphasis that surrounds an extracted answer. A wrapper that encloses the whole answer (`**42**`, `__42__`, `*42*`, `` `42` ``) is removed first, then a marker that decorates one side only (`** 42`, `42**`) is removed. Nested wrappers are removed as well, so `**_42_**` becomes `42`.
- Underscore emphasis is only removed when it encloses the whole answer, because `_` is also the LaTeX subscript operator, so answers such as `x_1`, `_1` and `x_` stay untouched.
- A single trailing `*` is kept, because it can be part of the answer itself (`x*`); a single leading `*` is removed, because it opens an emphasis that was never closed.
- A wrapper that spans the label and the answer, e.g. `__Answer: 42__`, is removed as well. The label is not part of the capture, so its closing marker stays in the captured answer; it is dropped when the text in front of the label opens the same marker and the label does not close it itself, e.g. `__Answer__: x__` keeps its `x__`.
- The marker runs are taken without a regex, because overlapping alternatives for the marker lengths backtrack exponentially on a long run of asterisks.
- `is_correct_minerva()` strips the emphasis from the extracted answer. An extraction that contains no answer at all (e.g. a bare `**Answer:**` label) is reported as `[INVALID]` again, so `verify()` falls back to the `\boxed{}` answer instead of comparing against an empty string.
- The default `answer_pattern` skips an optional emphasis or code marker that sits between the label and the answer, so that `**Answer:**\n\n42` and `` `Answer:`\n\n42 `` are parsed as `42`. It also skips a marker between the label and its colon, so that `**Answer**: 42` is parsed as `42`. The marker after the colon is only skipped when it is followed by whitespace or the end of the string, so a legitimate leading `_` in an answer such as `_1` is not consumed.

`tests/utils/reward_score/test_math_dapo_minerva_markdown_on_cpu.py` (new)

- CPU regression tests for the decorated label/value forms, for the unchanged plain form, for a wrong answer, for the answers whose `*` belongs to the answer, for the LaTeX subscript answers that must not be mistaken for emphasis, for the wrappers that span the label and the answer, for the `\boxed{}` fallback, and for a long run of asterisks, which must not make the cleanup stall.

The change is confined to the Minerva extraction. The `\boxed{}` path, the strict-box mode and the answer normalization are untouched.
