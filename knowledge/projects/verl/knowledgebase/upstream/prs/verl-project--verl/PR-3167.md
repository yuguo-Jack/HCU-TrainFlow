## Code Review

This pull request aims to change the loss averaging from being token-based to per-sample-based, which is a good improvement for training stability. However, the current implementation introduces a critical bug. The changes correctly handle the case with sequence parallelism enabled, but they break the standard training path (without sequence parallelism). The loss and loss_mask tensors have incompatible shapes in the standard path, which will lead to a runtime error. This needs to be fixed before merging.

File: `verl/trainer/fsdp_sft_trainer.py` · line 449

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

This new logic for per-sample loss averaging assumes that both `loss` and `loss_mask` are 2D tensors. This holds true for the sequence parallelism path (`use_sp=True`).

However, for the standard path (`use_sp=False`), `loss` is computed as a 1D tensor on lines 380-384. This will cause a runtime error on line 447 (`torch.sum(loss, dim=1)`).

Additionally, the change on line 363, which keeps `loss_mask` as a 2D tensor, breaks line 385 (`loss = loss * loss_mask.to(loss.device)`) in the standard path due to a shape mismatch.

The entire loss calculation for the `use_sp=False` path needs to be updated to work with 2D tensors to be compatible with these changes. For example, by not flattening the logits and labels before the loss function.
