# [trainer, cfg] fix: size TransferQueue storage units from trainer.nnodes

[Upstream PR](https://github.com/verl-project/verl/pull/8340) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes #7398. `transfer_queue.backend.SimpleStorage.num_data_storage_units` defaulted to a fixed 8. Each `SimpleStorageUnit` and the `TransferQueueController` reserve 1 CPU, and `TaskRunnerV1.run` always sets `transfer_queue.enable = True`, so every default PPO run reserves 9 CPUs before the trainer starts. On a node where Ray has fewer than 9 CPUs, one unit stays `PENDING_CREATION` and `tq.init` blocks with no error.

This PR defaults the count to `null` and resolves it to `2 * trainer.nnodes` right before `tq.init`, which matches the recommendation in the config comment. An explicit value is kept as is.

### Test

- New `tests/trainer/test_tq_storage_units_on_cpu.py` composes `ppo_trainer` with Hydra and checks: `nnodes=1` gives 2, `nnodes=4` gives 8, an explicit `num_data_storage_units=3` stays 3. Local run: 3 passed.
- `scripts/generate_trainer_config.sh` regenerated the four `_generated_*.yaml` files and reports clean.
- Behavior before this change, from the repro in #7398 (one local Ray node, TransferQueue 5fe4e49, Ray 2.59.0): 8 CPUs with 8 units leaves one unit `PENDING_CREATION` and `tq.init` blocked for 120 s; 8 CPUs with 2 units returns with 5 CPUs left.

### API and Usage Example

No new option. Users who relied on 8 units on a 1 to 3 node run can set it explicitly:

```bash
transfer_queue.backend.SimpleStorage.num_data_storage_units=8
```

### Design & Code Changes

- `verl/trainer/config/transfer_queue/transfer_queue.yaml`: default `null`, comment states the 1 CPU per unit cost.
- `verl/trainer/main_ppo.py`: `set_default_tq_storage_units(config)` fills the count from `trainer.nnodes` when it is `null`, called before the config is printed and passed to `tq.init`. This is the only place in verl that creates TransferQueue from config; the other `tq.init()` calls attach to the existing controller.
- Regenerated `_generated_ppo_*.yaml`.
