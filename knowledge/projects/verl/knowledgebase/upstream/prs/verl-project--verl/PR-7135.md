# [megatron] feat: support packed cu_seqlens

[Upstream PR](https://github.com/verl-project/verl/pull/7135) · state: closed · merged: False

## Original PR description

### What does this PR do?

Adds explicit packed-sequence `cu_seqlens` support to the Megatron backend so THD/remove-padding forwards can preserve sequence boundaries inside packed nested rows instead of treating each row as one attention segment.

This is not duplicating an existing PR. I searched open PRs for Megatron packing work:
- https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+megatron+cu_seqlens+packing
- https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+megatron+sequence+packing

AI assistance was used to help implement and validate this change; the changes were reviewed before submission.

### Test

- `pre-commit run --all-files --show-diff-on-failure --color=always` — passed.
- End-to-end pod run on `training-platform-agent/jkolehma-verl` using real `openai/gsm8k`, real `Qwen/Qwen3-0.6B`, Megatron TP=2, `ROLLOUT_N=4`, 100 training steps — passed.
  - Final `critic/rewards/mean`: `0.4375`
  - Final `training/rollout_actor_probs_pearson_corr`: `0.999240517616272`
  - Reward average rose from `0.003125` over steps 1–20 to `0.342187` over steps 81–100.

![Qwen3-0.6B Megatron packing reward curve](https://raw.githubusercontent.com/kolehma8/verl/pr-assets-mcore-packing-reward/reward_mean_100step_n4.png)

No-packing ablation on the same setup (`actor/ref megatron.use_remove_padding=False`, 100 steps, `ROLLOUT_N=4`) also passed. Comparing logged `timing_s/step` over steps 2-100:

| Mode | Avg step time | Median step time | Avg step time / 1k tokens | Avg reward (steps 81-100) | Avg Pearson |

| Packing (THD) | 5.531s | 5.501s | 0.520s | 0.3422 | 0.999184 |
| No packing (BSHD) | 5.562s | 5.536s | 0.530s | 0.4109 | 0.999140 |

Packing was ~`1.005x` faster by average step wall time and ~`1.020x` faster normalized per 1k tokens in this small-model smoke benchmark.

### API and Usage Example

```bash
bash examples/grpo_trainer/run_qwen3_0_6b_packing_megatron.sh \
  MODEL_PATH=Qwen/Qwen3-0.6B \
  TP=2 \
  ROLLOUT_N=4
```

For custom packed data, pass `cu_seqlens` in the Megatron batch metadata while keeping the THD path enabled via `actor_rollout_ref.actor.megatron.use_remove_padding=True`.

### Design & Code Changes

- Adds optional packed `cu_seqlens` plumbing from `MegatronEngineWithLMHead.prepare_model_inputs` through fused, non-fused, and value-model Megatron forwards.
- Extends `preprocess_thd_engine` to accept flat or per-row padded packed boundaries, map them onto Verl's aligned THD buffer, and pass those boundaries into `PackedSeqParams`.
- Keeps row-level padded offsets for postprocessing back to nested tensors.
- Rolls labels/positions within packed sequence boundaries so label preparation does not cross document/sample segments.
- Adds regression tests for flat `cu_seqlens`, per-row padded `cu_seqlens`, packed-boundary label rolling, and invalid missing row boundaries.
- Adds a small GRPO Megatron packing example with rollout-vs-actor Pearson logging enabled.

- kolehma8 · comment · 2026-07-24T16:25:12Z · [source](https://github.com/verl-project/verl/pull/7135#issuecomment-5071997482)

> Hi @kolehma8 , why do we need a standalone argument `cu_seqlens` ?

Hi @ISEEKYAN , the `cu_seqlens` argument contains the sample offsets in the packed sequence required for the attention part. HuggingFace computes this internally for some some models, but my understanding is that you need to pass it explicitly in Megatron. There is a discussion in HuggingFace to deprecate the implicit derivation of the packing offsets and also switch to explicit input arguments: https://github.com/huggingface/transformers/issues/46851
