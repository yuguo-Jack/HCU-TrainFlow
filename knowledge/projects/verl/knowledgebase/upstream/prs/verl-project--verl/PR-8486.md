# [Feature]support vllm feature of weight checker

[Upstream PR](https://github.com/verl-project/verl/pull/8486) · state: open · merged: False

## Original PR description

### What does this PR do?

Adds an opt-in, one-time self-check of the trainer→rollout weight sync, run at
initialization before the first training step.

When a sync breaks — name mapping, TP/EP sharding, fused layouts, quantization
rewrites, a truncated transfer — it usually does not raise. The rollout keeps
serving stale weights and RL silently trains off-policy. This PR makes that
failure loud: hash the rollout weights, destroy them, push the trainer's weights
through the real update path, and confirm the digests come back identical.

Only the engine can be the reference here: the trainer works in checkpoint/HF
coordinates while the engine holds fused, sharded and repacked runtime tensors,
so a trainer-side digest is not comparable.

### Test

Unit tests, no GPU required — `tests/checkpoint_engine/test_weight_checker.py`:

- `TestChecksums` — merging keeps ranks apart and rejects duplicate keys; the
  compare matrix covers unchanged, changed, dropped and added keys.
- `TestEngineCompatibility` — the adapter dispatches to the all-DP APIs, to the
  single-DP `collective_rpc` path (covering every TP worker), and to the
  level-1 sleep fallback that preserves weights while keeping KV asleep; DP > 1
  is rejected before anything is reset.
- `TestUpdateLifecycle` — ordering and failure handling: KV stays released until
  the comparison succeeds, a failed check never resumes generation or KV, and
  `delta_sharded` is rejected before the rollout is mutated.

End-to-end: 8 GPUs, Qwen3-4B, vLLM rollout with TP=2 (4 replicas, 2320 shards),
`trainer.total_training_steps=1`. The check passes and training proceeds.

### API and Usage Example

```yaml
actor_rollout_ref:
  rollout:
    checkpoint_engine:
      check_weight_update_equal: true   # default false
```

Requires a vLLM rollout with free_cache_engine=True and full weight sync. Everything else is unchanged: with the key off, no engine call is made.

```Expected output at startup:
Weight update check: snapshotting 4 rollout replica(s)
Weight update check: baseline recorded, 2320 weight shard(s)
Weight update check: weights reset, syncing through the real update path
Weight update check: comparing against the baseline
Weight update check: passed: 4 replica(s), 2320 weight shard(s) matched.
```
### Design & Code Changes
flowing
1.Pause generation.
2.Transfer once to establish resident weights — the engines were slept at init and vLLM level-2 sleep discards weights rather than offloading them.
3.prepare — release only KV memory and keep it released for the rest of the check, so reset/sync temporaries never overlap the KV pool.
4.snapshot — the engine hashes every parameter into rank-qualified digests; the baseline stays in the server actor.
reset — randomize the weights. Without this a transfer that did nothing would compare equal.
5.Second transfer through the same path training uses, with resume_kv_cache=False.
6.compare — re-hash and diff; any mismatch raises before the first step.
f7.inish — restore KV memory and the prefix cache, resume generation.
On failure, KV stays released and generation stays paused: the weights may be corrupt.

Key decisions

1.No new engine route: verl owns the AsyncLLM in-process, so this calls the same engine APIs behind vLLM's dev /weight_checker route.
2.WeightCheckEngineAdapter bridges vLLM versions — all-DP APIs (compute_weight_checksums_all, reset_weights, release_kv_cache_memory) first, single-DP collective_rpc next, and sleep(level=1) + wake_up(tags=["weights"]) when no KV-release API exists. Level 1 is mandatory in that fallback; level 2 would discard the state being snapshotted.
3.Duplicate digest keys are an error (a worker dropped its rank prefix), and every replica must answer — a headless actor is never counted as a pass.

Changed files

1.verl/utils/weight_checksum.py — digest merge/compare + WeightCheckEngineAdapter.
2.verl/checkpoint_engine/base.py — verify_update_path, checking_weights mode on update_weights, coverage enforcement.
3.verl/workers/rollout/vllm_rollout/vllm_async_server.py — the prepare/snapshot/reset/compare/finish actions.
4.verl/workers/rollout/replica.py — action fan-out per replica.
5.verl/workers/engine_workers.py — resume_kv_cache keyword for the naive sync.
6.verl/trainer/ppo/v1/trainer_*.py — hook in on_init_end; skipped on resumed runs.
7.verl/trainer/ppo/ray_trainer.py — same hook for the legacy trainer.
8.verl/workers/config/rollout.py, verl/trainer/config/rollout/rollout.yaml and the four _generated_*.yaml — the config key.
9.tests/checkpoint_engine/test_weight_checker.py — tests.
Limits: vLLM rollout only; full weight sync only (adapter-only LoRA and delta_sharded are rejected); DP > 1 needs the all-DP vLLM APIs; resumed runs only sync, since the two sides no longer start from the same weights; the comparison is byte-exact by design.
