# [megatron] fix memory management in overrided recompute backward

[Upstream PR](https://github.com/verl-project/verl/pull/8338) · state: open · merged: False

## Original PR description

## What does this PR do?

Stops verl's recompute-backward patch from freeing GPU storage that other tensors still use.
Today that makes `recompute_granularity='full'` crash with an illegal memory access whenever a
tensor is fed to more than one checkpointed chunk. The fix keeps the MoE memory reclaim the patch
was written for (same amount, measured below), and replaces the MTP-only special case from #7328
with a fix for that whole class of aliasing.

### The bug

`apply_patch_megatron_recomputation_backward` (`verl/models/mcore/patch.py`) frees every
checkpoint input right after its segment's backward:

```python
t.untyped_storage().resize_(0)        # t = detached recompute leaf
t.grad.untyped_storage().resize_(0)
```

`t` is a `detach()` of the saved input, so it shares that input's storage, and `resize_(0)`
empties the storage for every alias, not just for `t`:

* A tensor passed to several checkpointed chunks is freed after the first chunk's backward, and
  the next chunk's recompute reads freed memory:

  ```
  RuntimeError: CUDA error: an illegal memory access was encountered
  ```

  megatron's own `checkpointed_forward` passes `context` to every chunk this way
  (`megatron/core/recompute.py`), as does any model that feeds a cross-layer tensor to every
  layer.
* A checkpoint input that is a view of storage a later backward still reads is truncated the same
  way. This is the MTP + mHC crash from #7328.

Stock megatron-core does not have this problem: its `CheckpointFunction.backward` never frees
storage, and the saved inputs go away when autograd releases them.

### Why the existing patch does not cover it

#7328 skips the reclaim only when `ctx.run_function`'s closure holds a
`MultiTokenPredictionLayer`. Every other shared or aliased input still crashes, and a name-based
check cannot know about them.

The memory the reclaim is meant to recover is not held through the shared storage at all.
`MoEAlltoAllTokenDispatcher.dispatch_preprocess` keeps the routing `probs`, together with their
autograd graph, on the module and never clears them (megatron-core 0.18.0). The recomputed graph
therefore survives the backward, and its `AccumulateGrad` nodes keep the detached leaves, with
their data and `.grad`, alive until the next forward. That is why only MoE models leak.
NVIDIA/Megatron-LM#6339 clears the leaves' `.grad`, which releases the gradient half only, and it
does not take effect under verl, which replaces the whole backward.

Dropping the leaves' own references is therefore enough; resizing the shared storage is both
unnecessary and unsafe.

## Changes

* `patch_backward`: for every detached leaf that requires grad, drop the leaf's own references
  instead of resizing its storage:

  ```python
  t.grad = None
  t.data = t.new_empty(0)
  ```

  Storage still referenced elsewhere (the saved input, a tensor fed to other chunks, the base of
  a view) stays valid and is freed by its last owner; storage held only through the leaf is
  released. The `.data` assignment is the idiom megatron itself uses in
  `deallocate_output_tensor`.
* Return the input grads directly. The `.clone()` was needed only because the original grad
  storage was resized right after; removing it saves one copy per segment.
* Remove the `record_stream` calls. When `t.data` is replaced, `ctx.saved_tensors` still
  references the storage, so nothing is freed at that point; the actual free happens on
  autograd's normal path, as in stock megatron-core.
* Remove the MTP closure special case from #7328: dropping references cannot truncate an alias.
* Add `tests/models/test_mcore_recompute_reclaim.py` and run it in the `model_engine` job of
  `.github/workflows/model.yml`.

Net change to `patch.py`: −23 lines.

## Not a duplicate

Searched verl issues and PRs for `CheckpointFunction`, `recomputation_backward`, `resize_`,
`reclaim`. Related work, none superseding this:

* #7328 (merged): MTP-only special case for the same bug class; this PR generalizes and replaces it.
* NVIDIA/Megatron-LM#6339 (open): clears `.grad` in megatron's own backward; gradient half only,
  and bypassed under verl.
* NVIDIA/Megatron-LM#3267 (draft): the manual release this patch was ported from.
* #8324 (RFC): plans to retire the backward override; this PR keeps it compatible and smaller
  until then.

## Test

`tests/models/test_mcore_recompute_reclaim.py`: 5 GPU cases, single GPU, no distributed init.
Each case chains `CheckpointFunction` segments the way `checkpointed_forward` does with
`recompute_method=uniform, recompute_num_layers=1`, and compares gradients bitwise against the
same chain without checkpointing:

``` py
pytest tests/models/test_mcore_recompute_reclaim.py -q

# tests/models/test_mcore_recompute_reclaim.py::test_outliving_recompute_graph_does_not_retain_inputs PASSED                                                                                                                                                            [ 20%]
# tests/models/test_mcore_recompute_reclaim.py::test_detached_leaves_released_inputs_intact PASSED                                                                                                                                                                      [ 40%]
# tests/models/test_mcore_recompute_reclaim.py::test_input_shared_across_segments PASSED                                                                                                                                                                                [ 60%]
# tests/models/test_mcore_recompute_reclaim.py::test_context_passed_through_segments PASSED                                                                                                                                                                             [ 80%]
# tests/models/test_mcore_recompute_reclaim.py::test_view_input_whose_base_is_read_by_a_later_backward PASSED                                                                                                                                                           [100%]

# ============================================================================================================================ 5 passed in 32.61s ============================================================================================================================
```

* a recomputed graph kept alive by a module attribute (the MoE leak): inputs and grads are not
  retained
* only the detached leaves are released; the saved inputs keep their data
* one tensor fed to every segment
* a view input whose base is read by a later backward (the #7328 shape)
* `context` passed through the chunks the way `checkpointed_forward` does (each chunk returns
  it and the next one takes it)

All 5 pass locally. Against the previous `resize_(0)` backward, the shared-input, `context` and
view-alias cases crash with an illegal memory access and the release case fails. Against stock
megatron-core, the leak and release cases fail.

Memory A/B on a real `GPTModel` (4 layers, S=4096, H=1024, fp32, full recompute; MoE: 4 experts,
top-2, alltoall dispatcher; megatron-core 0.18.0, torch 2.11, H800). Floor is the memory still
allocated between iterations:

| backward | MoE floor | MoE peak | dense floor | param grads |
|---|---|---|---|---|
| stock megatron-core | 736.56 MiB | 3068.4 MiB | 576.0 MiB | reference |
| previous `resize_(0)` | 608.56 MiB | 2986.9 MiB | 576.0 MiB | bitwise equal |
| this PR | 608.56 MiB | 2986.7 MiB | 576.0 MiB | bitwise equal |

Clearing `dispatcher.probs` by hand on stock megatron-core gives 608.31 MiB. That attributes the
128 MiB leak (activation + grad, × 4 layers) to that reference.

MTP regression: the full `tests/unit_tests/transformer/test_multi_token_prediction.py` from
NVIDIA/Megatron-LM#3457 (48 cases, 8 GPUs) passes with this patch installed.
`CheckpointFunction.backward` is called 36 times on rank 0, including the MTP layers under full
recompute.

Not covered: an end-to-end mHC + MTP run (the #7328 setup), and the Qwen3-30B-A3B configuration
from the original leak report. The view-alias unit test stands in for the former.

AI assistance was used for the investigation and to draft the patch and tests; the diff was
reviewed line by line before submitting.
