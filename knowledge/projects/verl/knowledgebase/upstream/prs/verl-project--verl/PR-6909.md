## Original PR description

# Algo (OPD): On-Policy *Self*-Distillation (OPSD)

## Summary

This PR adds **On-Policy Self-Distillation (OPSD)** ([arXiv:2601.18734](https://arxiv.org/abs/2601.18734)) on top of verl's existing On-Policy Distillation (OPD) / `teacher_loop` infrastructure.

OPD trains a student on its own rollouts while a **separate, larger, frozen teacher** provides dense token-level supervision — but it requires a second model on a dedicated teacher pool. OPSD removes the *external* teacher: the **same architecture/checkpoint** plays both roles, differing only in **conditioning context**. The teacher conditions on the question `x` *plus* privileged information `y*` (the verified reference solution / CoT); the student conditions on `x` only. Gradients flow through the student only.

Two teacher-weight sources are supported via config:
- **`frozen` (default, reproduces the paper §4.1):** teacher = the initial checkpoint `θ₀`, served by the existing OPD teacher pool (point the teacher `model_path` at the student base).
- **`live` (Algorithm-1 variant):** teacher = current student weights served by the rollout engine, no separate teacher GPUs. Config surface + validation are in place; the `frozen` path is fully wired end-to-end in this cut.

The whole thing reuses OPD's loss layer, padding, and engine forward **verbatim** — only (S1) the input sequence and (S2) the output layout differ. See `docs/algo/opsd.md` for the full design.

## What changed

### Core OPSD wiring
- **`verl/experimental/teacher_loop/teacher_manager.py`**
  - `build_privileged_sequence` (S1): rebuild the teacher prompt as a *proper chat turn* from `(problem x, reference y*)` via the chat template (matching the reference impl), truncating `y*` to `max_reference_length`; returns `[teacher_prompt, ŷ]` + prefix length.
  - `remap_privileged_to_student_layout` (S2): remap the privileged teacher tensor back onto the student `[x, ŷ]` layout so `_pad_teacher_outputs` and downstream causal alignment stay byte-for-byte identical to OPD (works for both 1-D and 2-D top-k tensors).
  - `compute_self_distill_logprobs_single`: reuses `compute_teacher_logprobs_single` for the forward, wrapping it with S1/S2.
- **`verl/experimental/agent_loop/agent_loop.py`**: route teacher log-probs through the privileged builder when OPSD is enabled; pass the tokenizer into the teacher manager; `NotImplementedError` guard for `teacher_weights='live'` follow-up.

### Config
- **`verl/workers/config/distillation.py` + `distillation.yaml`**: new `SelfDistillationConfig` (`enabled`, `teacher_weights`, `reference_key`, `problem_key`, `teacher_template`, `teacher_thinking`, `max_reference_length`, `max_bridge_length`). Teacher context sizing extended by `privileged_extra = max_reference_length + max_bridge_length` in `validate_and_prepare_for_distillation` (defaults to `0`, so plain OPD arithmetic is unchanged).

### Loss (reference parity, FSDP `forward_kl_topk`)
- **`verl/trainer/distillation/fsdp/losses.py` + `distillation/losses.py`**:
  - `clip_tau`: per-vocab pointwise KL clipping *before* the vocab sum (distinct from the existing post-sum `loss_max_clamp`).
  - `loss_temperature`: softmax temperature applied to **both** student and teacher logits over the top-k support.
  - `clamp_negative_to_zero` (default `True` = original verl behavior): gate the `clamp_min(0.0)` floor so the reference's negative-allowed per-token loss can be reproduced.
  - **Sampling-temperature undo**: multiply back the engine's rollout-temperature division so distillation targets are built from **raw** logits (avoids dividing the student by temperature twice).
- **Megatron path**: `clip_tau` and `student_logits_temperature` raise `NotImplementedError` (FSDP-only in this cut; the custom backward must zero clipped-entry gradients).

### Engine / training
- **`verl/workers/engine/fsdp/transformer_impl.py`**: pass `student_logits_temperature` into the logits processor (both padded and rmpad paths).
- **`verl/workers/config/optimizer.py`**: allow `lr_scheduler_type='linear'`; FSDP engine wires HF's `get_linear_schedule_with_warmup` for reference parity.
- **`verl/trainer/ppo/ray_trainer.py`**: mirror core metrics into a `train/` wandb section (`train/loss`, `train/learning_rate`, `train/grad_norm`) using HF-Trainer metric names so verl and reference runs overlay directly. Aliases only; original keys untouched.

### Docs
- **`docs/algo/opsd.md`** (~1090 lines): background vs OPD, method/equations, both weight-source modes, config reference, example scripts, and the smoke/test plan.

```bash
  algorithm.adv_estimator=grpo \

  actor_rollout_ref.actor.optim.lr=1e-6 \
  trainer.n_gpus_per_node=8 trainer.nnodes=1 \
  distillation.enabled=True \
  distillation.n_gpus_per_node=2 distillation.nnodes=1 \
  distillation.self_distillation.enabled=True \
  distillation.self_distillation.teacher_weights=frozen \
  distillation.self_distillation.reference_key=reward_model.ground_truth \
  distillation.self_distillation.max_reference_length=2048 \
  distillation.self_distillation.max_bridge_length=64 \
  '+distillation.teacher_models.self_frozen.key=self_frozen' \

  distillation.distillation_loss.loss_max_clamp=10.0 \

  distillation.distillation_loss.clip_tau=5.0
```

## Code Review

This pull request implements On-Policy Self-Distillation (OPSD), introducing a privileged-context builder and a full-layout boundary remapper to support distillation from a frozen copy of the model under a privileged prompt. It also adds several OPSD-specific loss configurations, such as pointwise KL clipping (clip_tau) and distillation temperature scaling, alongside a linear learning rate scheduler. The reviewer identified a critical issue in the FSDP transformer implementation where a shape mismatch on the temperature tensor can cause a runtime crash during in-place division when sequence parallelism is disabled.

- XiangZheng2002 · comment · 2026-07-03T14:34:56Z · [source](https://github.com/verl-project/verl/pull/6909#issuecomment-4877296170)

I wanted to follow up on one issue regarding the "live" and "frozen" modes for the teacher weights.

**On the teacher's weights: frozen vs. live.** The OPSD paper ("Self-Distilled Reasoner", arXiv:2601.18734) is internally inconsistent about *which* weights serve the teacher, and this PR deliberately follows its experiments rather than its main-text definition:

- The **method section (§3, "Teacher and student policies")** defines both policies off the *same, currently-updating* parameters θ — "Both policies share the same parameters θ but differ only in their conditioning context," i.e. `p_T(·|x,y*) ≜ p_θ(·|x,y*)` and `p_S(·|x) ≜ p_θ(·|x)`. This is the "live" teacher, where the teacher tracks the student's current weights.
- The **experiments (§4.1, Implementation details)** instead *freeze* the teacher at the initial checkpoint θ₀: "We fix the teacher policy to be the initial policy, rather than the currently updating learning policy, as we find this helps stabilize training and implicitly acts as regularization to prevent excessive deviation from the initial policy." Every reported number uses this frozen teacher.

This PR implements only the **frozen** teacher (θ₀), which matches the paper's experiments and the reference implementation (`siyan-zhao/OPSD`): reuse the OPD teacher pool with `teacher_models.*.model_path` set to the student's base checkpoint. The **live** teacher (θ served by the rollout engine at current weights) is intentionally out of scope here — it requires additional trainer-level control flow — and will be added in a follow-up PR. Until then, `teacher_weights="live"` fails closed with a `NotImplementedError` so we never silently optimize a different objective.

When `self.use_ulysses_sp` is `False` (e.g., when sequence parallelism is disabled), `temperature_rmpad` remains a 2D tensor of shape `(1, total_nnz)` because the squeezing logic inside the `if self.use_ulysses_sp:` block is skipped. To prevent this crash, please ensure `temperature_rmpad` is flattened/squeezed to a 1D tensor of shape `(total_nnz,)` at the beginning of `prepare_model_outputs` (or inside `prepare_model_inputs`) before any in-place operations are performed.
