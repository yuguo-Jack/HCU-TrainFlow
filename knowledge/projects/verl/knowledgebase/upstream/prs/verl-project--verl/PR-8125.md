# fix: guard against re-conversion of already-nested teacher_logprobs in rmpad preprocessing

[Upstream PR](https://github.com/verl-project/verl/pull/8125) · state: open · merged: False

## Original PR description

### What does this PR do?

Adds the missing `is_nested` guard for `teacher_logprobs`/`teacher_ids` in the rmpad preprocessing (`verl/workers/utils/padding.py`), mirroring the adjacent `routed_experts` handling in the same function.

### Context

Filed alongside #8122 (crash: `split_with_sizes expects split_sizes to sum exactly to 2124, but got split_sizes=[4, 4]` from `index_select_tensor_dict` → nested `teacher_logprobs` unbind).

**Honest status: this guard alone does not eliminate the reported crash** — see the update comment on #8122. With the guard applied, the identical signature reproduced in further configurations. It remains a defensive consistency fix: re-conversion of already-nested tensors produces silently inconsistent jagged metadata, and the adjacent `routed_experts` block already guards against exactly that. The crash trigger correlates with verl's synthetic padding-sample upsampling (`trainer.balance_batch=True`); deeper root-cause investigation is ongoing and will be reported on the issue.
