# [fsdp] fix: sort buffers in fsdp2_load_full_state_dict to prevent NCCL deadlock with heterogeneous buffers

[Upstream PR](https://github.com/verl-project/verl/pull/6405) · state: closed · merged: True

## Original PR description


Models with heterogeneous buffer sizes (e.g., Gemma4 with different rotary embedding dimensions for sliding vs full attention) cause NCCL deadlocks in fsdp2_load_full_state_dict because named_buffers() iteration order is non-deterministic across ranks after FSDP2 wrapping. 

Fix: sort buffers by name before broadcasting to ensure all ranks process them in the same order.

Also relaxes the FSDP wrap policy to skip layer classes not found in the model (e.g., vision/audio layers in text-only mode) instead of crashing.

Fixes #6365

### Design & Code Changes

Fixes NCCL deadlock in `fsdp2_load_full_state_dict` for models with heterogeneous buffer sizes. 

After FSDP2 wrapping, `model.named_buffers()` iteration order is non-deterministic across ranks. For models with buffers of different sizes (e.g., Gemma4 has `full_attention_inv_freq`=256 and `sliding_attention_inv_freq`=128), different ranks broadcast mismatched tensors → NCCL deadlock.

**Fix:** Sort buffers by name before broadcasting to ensure deterministic order across all ranks. Also relaxes the FSDP wrap policy to skip layer classes not found in the model (e.g., multimodal models loaded in text-only mode) instead of crashing

- `verl/utils/fsdp_utils.py`: Sort `named_buffers()` by name before `dist.broadcast
- `verl/utils/fsdp_utils.py`: Warn instead of crash when configured layer classes are missing from model


### Logs

NCCL deadlock: rank0 sends 128 elements, rank1 expects 256

[rank0] Broadcasting buffer model.layers.0.self_attn.rotary_emb.inv_freq (shape: [128])
[rank1] Broadcasting buffer model.layers.0.self_attn.rotary_emb.inv_freq (shape: [128])
All ranks process buffers in same order

Affects: Gemma4, and any future model with heterogeneous buffer sizes under FSDP2
