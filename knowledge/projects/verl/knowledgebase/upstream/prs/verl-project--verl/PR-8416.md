# [vllm, rollout] fix: fold unquantized MoE refits through backend aliases

[Upstream PR](https://github.com/verl-project/verl/pull/8416) · state: closed · merged: False

## Original PR description

### What does this PR do?

Extend unquantized MoE refit folding to the `replace_parameter` aliases used by already-loaded hardware backend modules. Intercepting only the upstream module misses methods whose globals resolve the alias in a backend module, leaving those replacements outside verl's folding path.

An `ExitStack` scopes and restores the backend and upstream aliases, including mixed layers and exceptions. Optional backend packages are not imported just to discover aliases.

### Duplicate-work check

This extends merged #7987's unquantized folding mechanism. Searched open PRs for [replace_parameter](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+replace_parameter) and [refit memory](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+refit+memory) on 2026-10-28. #7483 covers DeepSeek/GLM LoRA serving; #7986/#8129/#8293/#8308 concern quantized staging or backend selection. None of the inspected changes adds this unquantized backend-alias interception.
