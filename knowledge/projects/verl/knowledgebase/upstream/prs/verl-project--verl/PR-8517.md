# [rollout, vllm] feat: bridge full weights to the Ascend HCCL trainer engine

[Upstream PR](https://github.com/verl-project/verl/pull/8517) · state: open · merged: False

## Original PR description

### What does this PR do?

Add a full-weight HCCL adapter for the public `HCCLTrainerWeightTransferEngine.trainer_init(..., client=..., source=...)` and `send_weights()` API. A replica leader sends to the next TP replica so the sender NPU does not also receive in the same HCCL group. This builds on the opt-in dispatch, IPC support and coordinated preflight from the preceding PR.

This is part 2 of a three-PR series. Depends on #8516. The branch targets upstream main and includes the preceding commits; review the incremental change [here](https://github.com/yeyunu/verl/compare/262e93a62860a0852ede39295e9e7b93448c0ecb...6168a527efae1f82ddb79478449ad76d93058bc2). Rebase after the prerequisite merges before merging this PR.

### API and Usage Example

```bash
+actor_rollout_ref.rollout.engine_kwargs.vllm.weight_transfer_config.backend=hccl \
  +actor_rollout_ref.rollout.engine_kwargs.vllm.additional_config.weight_nz_mode=0
```

Use a compatible vLLM/vLLM-Ascend pair exposing the documented native APIs. This first version supports unquantized full weights; LoRA/QAT, a separately synchronized MTP drafter and delta payloads are rejected on the opt-in path. IPC/reload requires same-device colocation. HCCL additionally requires one node, replicated FSDP full-weight streams, at least two TP replicas, DP=PP=1 and no prefill/decode disaggregation. Native communication failures invalidate the adapter; restart workers before retrying. Default unconfigured paths retain their existing behavior.

### Design & Code Changes

- Extend the selector and worker preflight for `hccl`.
- Materialize bounded batches on the actor thread; keep FSDP iterator advancement there, and run the native engine on a dedicated thread with its NPU device selected.
- Adapt synchronous client RPCs to Ray. Start once, defer per-batch finish, and finish once after the full stream. Clone exporter-owned tensors before advancing the source.
- Reuse the trainer engine between rounds. Queue cleanup behind outstanding work on cancellation; do not claim that Python cancellation interrupts an HCCL collective.
- Add HCCL protocol/failure/cancellation tests and topology documentation.

No Step5 model implementation, private checkpoint/data paths, training diagnostics, SGLang changes or NPU worker patches are included.
