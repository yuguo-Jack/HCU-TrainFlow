[Upstream PR](https://github.com/verl-project/verl/pull/8492) · state: open · merged: False

## Original PR description

### What does this PR do?

> **Draft — not intended for merge yet.** This PR adds the detailed design specification for separate_async fault tolerance, as the review surface for a community discussion. It is a design document only: no code is introduced or changed. Tracking RFC: #8380 — the design update and discussion live in that issue.

The spec describes the **v2 recovery-source scheme**: per-step engine-native snapshot → local staging → aggregated FT store, with the trainer side and the rollout side each self-recovering from the store, independently and without disturbing each other.

Key design points:

- **Snapshot data plane**: end-of-step engine-native save (one shape for both FSDP and Megatron) → local staging (keep-2, seconds) → async FT shipper → aggregated store where `seal` is the single atomic commit point; per-step snapshot (K=1) is near-zero cost at 30-minute-step scale (measured 272 MB/s mean bandwidth).
- **Trainer-side recovery**: full-group in-place restart with rank-aligned reads of staging/store shard files; RPO = 0 at K=1.
- **Rollout-side recovery**: engine-process replacement (building on the merged standalone replica lifecycle APIs) + cold start from the store's canonical θ (HF safetensors; TP re-sharding done by the engine itself).
- **Fail-closed everywhere**: any uncertainty falls back to verl's current behavior (crash + checkpoint restart) — FT is never worse than no FT.
- **FT module**: fault sensing / orchestration / recovery primitives with registration points; 5 thin host integration points; trainer kernels untouched; `trainer.ft.enabled=false` means zero behavior change.
