# [fsdp, ckpt]fix: backport FSDP2 CPU offload checkpoint fix to v0.8.0

[Upstream PR](https://github.com/verl-project/verl/pull/7072) · state: closed · merged: False

## Original PR description

### What does this PR do?

>Fix a device mismatch crash during checkpoint saving when using FSDP2 with `CPUOffloadPolicy`. Previously, `save_checkpoint` would unconditionally call `load_fsdp_model_to_gpu()` to manually move the model to GPU before saving, even when FSDP2's native `CPUOffloadPolicy` was already managing parameter placement. This caused a conflict and device mismatch error (especially on non-CUDA devices such as Ascend NPU).

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

`self.experts.gate_up_proj` and `self.experts.down_proj` are `nn.Module` instances (typically linear layers), not PyTorch tensors. Calling `.chunk()` or `.transpose()` directly on them will raise an `AttributeError`. You must access their `.weight` attribute first.

```suggestion
    if hasattr(self.experts, "gate_up_proj") and hasattr(self.experts, "down_proj"):
        gate_proj_weight, up_proj_weight = self.experts.gate_up_proj.weight.chunk(2, dim=1)
        w1 = up_proj_weight.transpose(1, 2).to(input_dtype)
        w2 = gate_proj_weight.transpose(1, 2).to(input_dtype)
        w3 = self.experts.down_proj.weight.transpose(1, 2).to(input_dtype)
```
