# [perf, model] feat: add DeepSeek-V4 MFU / FLOPs estimation

[Upstream PR](https://github.com/verl-project/verl/pull/8506) · state: open · merged: False

## Original PR description

### What does this PR do?

- Add MFU/FLOPs estimation for `deepseek_v4` in `verl/utils/flops_counter.py`, so DSV4 runs no longer log `mfu = 0` after `Only support config type of {...}, but got deepseek_v4`.
- Account for DSV4 hybrid attention: sliding-window layers, CSA layers (2x compressor + lightning indexer) and HCA layers (single-block compressor), driven by the per-layer `compress_ratios` (checkpoint format) or `layer_types` + `compress_rates` (HF transformers format).
- Account for shared-KV MQA (K == V), Q LoRA, grouped low-rank output projection, mHC, DeepSeekMoE (router gate + routed top-k and shared experts) and the LM head. MTP layers are not counted.
- Add a `deepseek_v4` regression case in `tests/utils/test_flops_counter.py` with DeepSeek-V4-Flash dimensions.

### Test

`tests/utils/test_flops_counter.py` calls `get_device_flops()` and needs a GPU, so the estimator was checked on a CPU-only box with that probe stubbed:

```console
$ python3 verify_dsv4.py
model_type: deepseek_v4   registered: True
batch=[512, 1024, 2048]  expected=310.877746   got=310.877746
batch=[4096, 4096, 4096] expected=1095.446349  got=1095.446349
```

The expected values are derived by hand from the DeepSeek-V4-Flash config, with one batch below and one above the sliding-window / compression thresholds so both sides of the clamps are covered. The new case runs in CI through `gpu_unit_tests.yml`; a `ci-request` will follow.

### API and Usage Example

No API change. `FlopsCounter(config)` picks the estimator up as soon as `config.model_type == "deepseek_v4"`:

```python
from verl.utils.flops_counter import FlopsCounter

flops_achieved, flops_promised = FlopsCounter(config).estimate_flops(batch_seqlens, delta_time)
```
