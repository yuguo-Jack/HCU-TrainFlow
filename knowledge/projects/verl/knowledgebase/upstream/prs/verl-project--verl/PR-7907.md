# Lixali/tpu run

[Upstream PR](https://github.com/verl-project/verl/pull/7907) · state: closed · merged: False

## Original PR description

### What does this PR do?

Minimal fixes needed to run Qwen3-0.6B GRPO end-to-end on TPU with the TorchTitan engine and vLLM rollout.

- `vLLMColocateWorkerExtension` imported `verl.utils.vllm.vllm_fp8_utils` unconditionally at module load. That module pulls in GPU-only FP8 dependencies that are unavailable in the TPU vLLM build, so every rollout worker crashed at import even though the model is plain bf16. The FP8 helpers are now imported lazily and only when a quantized model is actually detected or `VERL_VLLM_FP8_QUANT_ENABLED=1` is set.
- `TorchTitanEngine` implicitly enabled FSDP CPU offload for any `forward_only` engine (i.e. the reference policy). On TPU this offload path is not supported and breaks the reference model; the implicit enablement is now skipped for `device_name == "tpu"`. Explicit `offload_policy=True` still works everywhere.
- Add `debugpy` to `examples/tpu/gke/Dockerfile.tpu` so remote debugging of Ray workers is possible in the GKE image.

AI assistance (GitHub Copilot) was used to draft parts of this change; every line has been reviewed by the submitter.
