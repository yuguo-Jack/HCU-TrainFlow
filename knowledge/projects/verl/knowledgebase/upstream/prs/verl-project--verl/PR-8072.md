# [rollout] chore: upgrade vllm==0.30.0

[Upstream PR](https://github.com/verl-project/verl/pull/8072) · state: closed · merged: False

## Original PR description

### What does this PR do?

Upgrade the rollout engine pin to the current release: `vllm==0.29.0` -> `vllm==0.30.0`, and regenerate `uv.lock` so the lock and the pin agree.

This follows the same pattern as #7973 (`[rollout] chore: upgrade vllm==0.29.0/sglang==0.5.20`), which performed the previous bump; this is the next step from 0.29.0.

`vllm 0.30.0`'s PyPI wheel is already a cu130 / torch-2.13 abi3 build, so no source build or wheelhouse routing is required.

### Test

`uv lock` resolves cleanly against PyPI (exit 0), with `vllm` locked at `0.30.0`.

The lock also moves `nvidia-nccl-cu13 -> 2.30.7`, `triton -> 3.8.0`, `nvidia-cutlass-dsl -> 4.7.1`, `nvidia-cudnn-cu13 -> 9.24.0.43` and `quack-kernels -> 0.6.5`. This is not an unrelated refresh: regenerating with `uv lock --upgrade-package vllm` produces the same set, because `vllm 0.30.0` transitively requires those newer versions.

The GPU test jobs run on self-hosted runners that are not exposed to fork PRs (the job queues for 24h and is cancelled), so I have not been able to obtain a CI signal here. Happy to post in the `ci-request` channel, or to run any specific command you want and paste the output.

### API and Usage Example

No API change: this is a dependency pin plus the regenerated lockfile.

### Design & Code Changes

Two files:

- `pyproject.toml`: `vllm==0.29.0` -> `vllm==0.30.0`, plus the adjacent comments that name the version (the flashinfer transitive pin is `==0.6.18.post1` in 0.30; the `transformers` floor comment now refers to 0.30).
- `uv.lock`: regenerated.

I deliberately did **not** touch `setup.py` (`vllm>=0.18.0`, a floor that 0.30 already satisfies), `requirements.txt` (no vllm pin), or `manage_envs.py` (no vllm version) — none of them need changing for this bump.

I also have not ported any rollout code adaptation, because I have no evidence yet that 0.30 requires one: #7973's code changes (`vllm_rollout/weight_update_utils.py`, `models/mcore/patch.py`, `utils/vllm/utils.py`) accompanied the torch 2.11 -> 2.13 bump as well. If you tell me 0.30 needs a specific adaptation, I will add it.
