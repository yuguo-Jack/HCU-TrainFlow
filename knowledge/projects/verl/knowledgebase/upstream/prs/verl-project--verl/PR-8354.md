# [megatron, docker] fix: install DeepEP in uv training environments and restore NVSHMEM

[Upstream PR](https://github.com/verl-project/verl/pull/8354) · state: closed · merged: True

## Original PR description

Megatron MoE training can enable the DeepEP dispatcher while the uv `megatron` extra leaves `deep_ep` uninstalled. The CUDA 13 image also lacked a system NVSHMEM installation at the path embedded in the prebuilt DeepEP wheel.

Install `deep-ep==1.2.1` with the Megatron extra from the matching Torch 2.13 / CUDA 13 wheelhouse for Linux x86_64 and aarch64, and update the lockfile and native DeepEP usage documentation. Install NVSHMEM 3.4.5 in the image with loader configuration, use published CUDA 13.0 NCCL Debian packages for the base layer, and move all 17 uv CI workflows to the rebuilt `uv.cu130.dev5` image.

This PR covers native DeepEP for Megatron training. Inference-engine DeepEP enablement and the internal FlashComm adapter are outside its scope.

Validation:
- `uv lock --check` — passed.
- `uv sync --frozen --dry-run --extra megatron --extra vllm --python-platform x86_64-unknown-linux-gnu` — passed; selects DeepEP 1.2.1.
- The same dry run for `aarch64-unknown-linux-gnu` — passed; selects DeepEP 1.2.1.
- Parsed all 17 changed workflow YAML files and checked their dev5 image references; no dev4 references remain under `.github`.
- `git diff --check upstream/main...HEAD` — passed.
- Inspected the published cp312 x86_64 DeepEP wheel: it links `libnvshmem_host.so.3` and records the system NVSHMEM directory in RUNPATH.

GPU import and native dispatch/combine on the open-source Torch 2.13 stack have **not** been validated. The separate internal Torch 2.11 / FlashComm run is not validation of this path. This draft needs GPU validation and human review before it is ready.

No open PR addressing this same fix was found in searches for `DeepEP uv`, `NVSHMEM image`, and `DeepEP` titles. This contribution was prepared with AI assistance (Codex); the human submitter should review every changed line and validate the GPU path before marking it ready.
