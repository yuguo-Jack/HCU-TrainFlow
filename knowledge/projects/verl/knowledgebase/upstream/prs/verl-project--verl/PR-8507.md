# [vllm, hardware] refactor: support vLLM-Ascend 0.30 in the NPU patch layer

[Upstream PR](https://github.com/verl-project/verl/pull/8507) · state: open · merged: False

## Original PR description

### What does this PR do?

Target **vLLM-Ascend 0.30** instead of 0.23 and shrink the NPU patch layer to what 0.30 still needs.

**1. Drop the shims whose fixes are already upstream in vLLM-Ascend 0.30 / vLLM 0.30**

- DeepSeek V4 hash-routing `__init__` override — 0.30's `DeepseekV4MoE` builds `tid2eid` as `(token_ids + expert_offsets) % n_routed_experts` natively (same table the patch wrote).
- DeepSeek V4 expert `weight_loader` restore in `load_weights` — 0.30's `replace_parameter()` documents that `weight_loader` is always taken from the existing parameter.
- GLM-5.2 SFA `kv_b_proj` keep-alive — 0.30 gates `dispose_layer(self.kv_b_proj)` behind `rl_weight_update_enabled` (#15463).
- GLM-5.2 SFA indexer scale — 0.30 moved the indexer to `vllm_ascend/attention/indexer*.py`; the old `indexer_select_post_process` target no longer exists (the patch would have failed closed).
- vLLM partial wake-up / DP dummy-batch patch and its `run_engine_core` entry point — vLLM 0.30 already skips executor/dummy-batch work while asleep.
- Legacy `FusedMoE` class-level `weight_loader` transpose wrapper — 0.30 only exposes the `FusedMoEFactory` function, and the layout transpose is owned by the Ascend `process_weights_after_loading`.
- `CaMemAllocator.sleep` synchronize wrapper — vllm-ascend 0.30 synchronizes before unmapping tensor memory itself.

**2. Retarget the remaining patches to 0.30** (`13330bfc`)

- Version gate `0.23.0 <= vllm < 0.24.0` → `0.30.0 <= vllm < 0.31.0`; `v023_*` / `vllm013_*` entry points renamed to `v030_*`.
- DeepSeek V4: import `AscendDeepseekV4ForCausalLM` from `vllm_ascend.models.deepseek_v4.model`. 0.30 ships the model as a package with an empty `__init__.py`, and `apply_npu_vllm_patches()` runs at `import verl.utils.vllm`, so the old package-root import raised `ImportError` in every NPU process. The Transformers → Ascend rename is still required: 0.30's `load_weights` resolves names through `params_dict[name]` without a fallback.
- GLM-5.2 RMSNorm: drop the `torch.ops.vllm.maybe_chunk_residual` call (the op is gone in 0.30) and require the bias-aware `npu_add_rms_norm_bias` source shape before patching; stop importing `vllm_ascend.patch.worker.patch_routed_experts_capture`, which 0.30 applies itself from `vllm_ascend.utils.adapt_patch`.
- FIA decode mask: keep the source-level rewrite; both anchor blocks still match the 0.30 `full_graph_fia` / `forward_fused_infer_attention` sources exactly once.
- Rotary embedding: forward `enforce_enable` to `CustomOp.__init__`, which takes it keyword-only in 0.30.

### API and Usage Example

No public API, CLI or config change. `apply_npu_vllm_patches()` keeps its signature and still runs when `verl.utils.vllm` is imported; only the set of patches it applies changes, and those patches are internal to the NPU rollout path.

```python
# unchanged call site: importing verl.utils.vllm applies the NPU patches
from verl.utils.vllm import apply_npu_vllm_patches  # already called at import time
```

### Design & Code Changes

- `verl/utils/vllm/npu_vllm_patch.py` — removes seven 0.23-era shims and their helpers; keeps three patches (DeepSeek V4 name/loader wrapper, FIA decode mask, ARM `sched_yield`) plus the env-gated GLM-5.2 block, now gated on `0.30.0 <= vllm < 0.31.0`.
- `tests/utils/test_npu_vllm_patch_on_cpu.py` — drops the `FusedMoE`-factory cases, retargets the dispatch test to vLLM `0.30.0`, and renames it to `test_apply_npu_vllm_patches_installs_every_patch`; DeepSeek V4 name-mapping / lazy-consumption tests are unchanged.
- Behavioural scope: only the NPU vLLM rollout path is affected. Settings that keep the old behaviour: `VERL_VLLM_ASCEND_GLM52_PATCH` (opt-in) still gates the GLM-5.2 block.
