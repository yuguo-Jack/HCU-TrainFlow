# [doc] fix: clarify GRPO batch sizes and optimizer updates

[Upstream PR](https://github.com/verl-project/verl/pull/8223) · state: open · merged: False

## Original PR description

### What does this PR do?

Closes #1524.

Clarify the units and arithmetic behind GRPO/PPO train, mini and micro batch sizes. The configured actor and critic `ppo_mini_batch_size` values are prompt-equivalent global sizes; the trainers multiply them by `rollout.n` before partitioning trajectories across the corresponding data-parallel ranks.

Add the issue's `1024 / 256 / 80 / n=5` worked example, formulas for fixed-size gradient accumulation and optimizer-update counts, and explicit boundaries for dynamic token-budget batching, forward-only log-probability batches, multi-output rollouts, filtering, padding and asynchronous replay.

The explanation is linked from the PPO guide, configuration reference and batch-size FAQ. This changes documentation only: no runtime behavior, defaults, APIs, dependencies or CI configuration change.

### API and Usage Example

No API or configuration behavior changes. The documentation now explains the existing calculation. For the issue's fixed-size example with eight actor data-parallel ranks:

```text
B=1024, n=5, M=256, d=8, m=80, E=1
rollout trajectories = B*n = 5120
global actor mini-batch = M*n = 1280
local actor mini-batch = M*n/d = 160
micro-batches per optimizer update = M*n/(d*m) = 2
actor optimizer updates = (B/M)*E = 4
```

### Design & Code Changes

- Correct the canonical `actor_rollout_ref.rollout.n` key and explain that configured PPO mini-batches use prompt-equivalent global units.
- Add a symbol table, formulas, divisibility checks and the original worked example to the GRPO guide.
- Distinguish actor data-parallel size from rollout tensor parallelism or total GPU count.
- Explain that dynamic token-budget micro-batching does not have a fixed micro-batch count and that rollout/reference log-probability micro-batches are forward-only.
- Cross-link the shared explanation from PPO, the configuration reference and FAQ.
