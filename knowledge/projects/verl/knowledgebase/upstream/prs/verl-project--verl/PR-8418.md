# [veomni, lora, vllm] feat: support M3.1-Flash expert LoRA rollout export

[Upstream PR](https://github.com/verl-project/verl/pull/8418) · state: closed · merged: False

## Original PR description

### What does this PR do?

Extend the native VeOmni LoRA integration to M3.1-Flash multimodal experts and export temporary merged full weights for vLLM synchronization. Dense, shared-expert and independent-expert merges preserve actor/optimizer parameter storage.

The target checkpoint is **MiniMax-M3.1-Flash**. Its checkpoint config uses `model_type="minimax_m3_vl"` and architecture `MiniMaxM3SparseForConditionalGeneration`; existing `minimax_m3` module/class identifiers are retained for compatibility. They are architecture identifiers, not a claim that a different model version was validated.

Default targets cover text attention and MLP/experts, excluding vision, lm_head and the no_grad sparse indexer. Explicit dense/vision/projector targets remain supported; explicit indexer targets fail. The generic Qwen3 EP1/SP1 restrictions remain unchanged.

**Stacked draft:** current main `2ab35292039a51175a4b3d3b3b2d76e951a0d3e4` has been merged at `7ae23d53769a3b1078b151183cfd2a70b11c8ccc`. The branch includes generic dense-LoRA #8307 at `8f42981f4c3f2d1e8723e78f6842e3d38198b563`, the full-parameter export proposed in #8417, and the companion VeOmni source below. Dependency ancestry is retained for attribution; the overall diff includes inherited scaffolding. The three engine conflicts are resolved by merging adapters in the unquantized HF exporter, keeping checkpoint output separate from the optional rollout quantizer. Current vLLM admission handling is preserved. GitHub reports no merge conflicts against that main revision; dependency selection/locking and native acceptance remain pending.

### Why this is not duplicate work

Searched open [VeOmni LoRA](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+VeOmni+LoRA) and [MiniMax](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+MiniMax) PRs on 2026-10-28. #8307 provides Qwen3 Dense native LoRA and excludes expert adapters; it is a dependency. #8353 is the verl-native FSDP2 text-model route. This draft supplies the VeOmni multimodal expert-LoRA/export path, building on #8417.

The added tests execute the actual engine methods with isolated backend imports, covering M3.1-Flash and Qwen3 LoRA with quantization enabled/disabled and the non-LoRA converter path. The checkpoint callback exports floating weights, while rollout applies the configured quantizer after adapter merging.

### Historical full-model evidence

The experimental LoRA stack used the full **60-layer / 128-expert M3.1-Flash**, rank/alpha 64, training EP4/SP4 and rollout TP32/EP1, with DSpark3 enabled. Two actor updates completed; correct sampled responses were 90/128 and 94/128, with finite gradient norms 0.02171357 and 0.01769571. Greedy accuracy changed from 10/16 to 15/16 on the same 16 examples used for training. Step 3 later stalled and was stopped; no checkpoint was produced.

These are historical overfit/debug results from the experimental stack, not new validation of this extracted branch, a held-out evaluation, long-run stability, or SFT evidence.
