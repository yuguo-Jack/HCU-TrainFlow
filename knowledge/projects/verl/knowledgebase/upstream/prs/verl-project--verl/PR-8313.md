# fix(agent_loop): honor data.truncation policy in _cap_text_prompt_length

[Upstream PR](https://github.com/verl-project/verl/pull/8313) · state: open · merged: False

## Original PR description

## Summary

Fixes #8281. The shared prompt cap `AgentLoopBase._cap_text_prompt_length` unconditionally left-truncates overlong text prompts (keeps only the suffix), ignoring the documented `data.truncation` policy (`error`/`left`/`right`/`middle`). With `error` (the default) configured, an overlong prompt was silently truncated and its leading instructions discarded, instead of failing loudly.

This PR makes the cap honor `data.truncation`:

- `error` (default): raise `ValueError` instead of silently truncating, mirroring the existing multimodal fail-loudly path.
- `left`: keep the suffix (current behavior).
- `right`: keep the prefix.
- `middle`: keep roughly half from each end, discarding the middle (matches the documented "keeps head and tail").

### Boundary fix included: `middle` at cap=1

While reviewing the `middle` branch we found an edge case: `head = (prompt_length + 1) // 2` leaves a tail budget of `0` when `prompt_length == 1`, and Python's `-0 == 0` makes `prompt_ids[-0:]` select the **entire** list — a 10-token prompt would be capped into 11 tokens. The tail slice is now computed forward (`prompt_ids[len(prompt_ids) - tail_length:]`, naturally empty when the budget is 0), preserving the exact same head+tail semantics for every cap >= 2. A regression test covers cap=1.

## Why not reuse PR #4600

[#4600](https://github.com/verl-project/verl/pull/4600) targets the **pre-Continuous-Token** tokenization path and #2069's postprocess tensor-size mismatch. Current main already caps prompts via the shared `_cap_text_prompt_length` in the CT initial-token construction (`ct_build_initial_tokens` → `_cap_text_prompt_length`), which runs **before** #4600's proposed check, so #4600 is both stale (predates the CT refactor) and non-mergeable against current main. The correct fix point is the shared `_cap_text_prompt_length`, which covers `SingleTurnAgentLoop`, `ToolAgentLoop`, and every CT-built loop.

## Tests

Added CPU-only unit tests `tests/experimental/agent_loop/test_cap_text_prompt_length.py` covering all four policies plus the default-`error`, unknown-value, and the cap=1 `middle` regression paths.

**12 passed** in the verl `verl-e2e` environment (4090 GPU node, Python 3.12.15 / ray 2.59.0 / torch 2.11.0+cu128 / transformers 5.8.1). A control check against the pre-fix implementation confirms these tests fail on the old behavior (e.g. `error` returns the suffix instead of raising; `middle` at cap=1 extends the prompt).

Additionally verified on the same node:
- GPU e2e smoke (grpo + ToolAgentLoop + Qwen2.5-0.5B, 2 training steps): normal training path runs clean.
- Negative check: with `max_prompt_length=32` the default `error` policy fails loudly with the expected `ValueError`.
