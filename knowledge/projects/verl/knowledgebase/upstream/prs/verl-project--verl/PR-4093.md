## Code Review

This PR removes a hardcoded `log_level: "info"` to improve performance. While this change is effective, I've identified a related bug in the handling of `engine_kwargs`. Currently, engine parameters from the configuration are not passed to the SGLang engine, preventing flexible configuration of settings like `log_level`. I've left a comment with details on this issue. Fixing this bug would provide a more robust solution, allowing `log_level` and other SGLang engine parameters to be configured externally without code changes.

While removing this hardcoded `log_level` improves performance, a more robust solution would be to make it configurable. It appears there's an attempt to support this via `engine_kwargs` (line 421), but these arguments are not correctly passed to the SGLang engine constructor. Currently, only `attention_backend` is used from `engine_kwargs`, and the rest of the configured parameters are silently ignored. This prevents runtime configuration of important engine parameters like `log_level`.

I recommend fixing the `engine_kwargs` handling by merging them into the `args` dictionary before initializing the engine. This would make the system more flexible and avoid the need for hardcoded values or future code changes to tune engine parameters.
