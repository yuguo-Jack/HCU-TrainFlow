<h2>v1.14.2</h2>
<p>Patch release fixing two cases of silently wrong training and three crashes.</p>
<p>Worth calling out: <strong><a href="https://redirect.github.com/huggingface/trl/issues/7505">#7505</a></strong> affects GRPO, RLOO and Distillation on the default generation path (<code>use_vllm=False</code>). Runs on models whose tokenizer eos is their only end-of-turn id are unchanged.</p>

<h2>v1.14.0</h2>
<h2>Features</h2>
<h3><code>trl.losses</code> is gone: DPO, KTO and GRPO stream their own log-probs</h3>
<blockquote>
<p>[!WARNING]
<code>from trl.losses import FusedLinearDPOLoss</code> (or <code>FusedLinearKTOLoss</code>, <code>FusedLinearGRPOLoss</code>, <code>FusedLinearJSDLoss</code>) no longer works. The module introduced in v1.13 has been removed.</p>
</blockquote>
<p>v1.13 vendored Liger's <code>chunked_loss</code> into <code>trl.losses</code> as a holding action, not a destination (<a href="https://redirect.github.com/huggingface/trl/issues/7063">#7063</a>). The problem it was holding: those classes reimplement each trainer's loss math, so TRL carried two copies of every formula, and copies drift. That drift is where the bugs were. GRPO's <code>grad_norm</code> differed from the default path, KTO ignored the reference model under PEFT, KTO class weights and DPO <code>label_smoothing</code> were silently dropped. Worst of all, under plain DDP the fused path ran the loss on the unwrapped model, so <code>DistributedDataParallel</code>'s reducer was never armed and gradients were never all-reduced: every rank silently kept its own.</p>
<p>The fix is to stop reimplementing. All DPO, KTO and GRPO need from the fused path is per-token log-probs of the selected tokens, and TRL already had <code>_ChunkedLogProbFunction</code> for exactly that: it streams the vocabulary with an online logsumexp and recomputes in the backward pass. Each trainer now runs <code>backbone -&gt; _ChunkedLogProbFunction -&gt; its own existing loss code</code>, unchanged. One implementation of each loss, and the memory win is kept, because full logits are still never materialized.</p>
<p>Thirteen restrictions existed only because the loss had been rewritten in a form that could not express those options. Most are gone: DPO with <code>use_liger_kernel=True</code> now accepts mixed loss types, f-divergences and precomputed reference log-probs, and GRPO gains entropy and off-policy masking. Still refused: <code>use_weighting</code>, <code>compute_metrics</code>, a PEFT adapter on <code>lm_head</code>, prompt-learning PEFT, and the MoE auxiliary loss.</p>
