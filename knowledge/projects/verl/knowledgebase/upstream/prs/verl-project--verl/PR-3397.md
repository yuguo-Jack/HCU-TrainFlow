### What does this PR do?

> Add **concise** overview of what this PR aims to achieve or accomplish. Reference related GitHub issues and PRs that help with the review.

This PR adds the training recipe for [rStar2-Agent: Agentic Reasoning Technical Report](https://arxiv.org/abs/2508.20722)

The main features introduced in this recipe are:
- **resampling**: The original rollout traces can be sampled using specific sampling rules (e.g., rejection sampling, resampling of correct traces) before sending them to update the policy model.
- **code judge tool**: Add a code execution tool that can execute code snippets in parallel across multi-nodes.
- **tool call error handling**: Maintain tool call decode errors as tool responses when tool call parsing fails.
- **reward fusion**: Fuse prime_math and math_verify results to achieve better reward signals.

This function has several issues:
1. The return type hint is `bool`, but it returns `float` values (`1.0`, `0.0`). This should be corrected to `-> float`.
2. The exception handling is inconsistent. The first `try...except` block for `prime_compute_score` swallows any exception and continues, while the second one for `math_verify_compute_score` returns `0.0` immediately upon exception. This makes the logic hard to follow.
3. The variable `prime_score` assigned in the first `except` block is never used.

A refactoring is recommended for clarity, consistency, and correctness.

```suggestion
def compute_score(model_output: str, ground_truth: str) -> float:
    try:
        # prime_compute_score returns a tuple, we need the first element.
        if prime_compute_score(model_output, ground_truth)[0]:
            return 1.0
    except Exception:
        # If prime_compute_score fails, fall back to math_verify_compute_score.
        pass

    try:
        if math_verify_compute_score(model_output, ground_truth):
            return 1.0
    except Exception:
        # If math_verify_compute_score also fails, return 0.0.
        return 0.0

    # If both ran successfully but did not return a positive score.
    return 0.0
```

Using `dict(tools_kwargs)` creates a shallow copy. If `tools_kwargs` contains mutable objects like lists or dictionaries, they will be shared across different tool calls. This can lead to subtle and hard-to-debug issues where one tool call unintentionally modifies the state for another. Using `copy.deepcopy` ensures that each tool call gets a completely independent copy of the arguments. You will need to `import copy` at the top of the file.

```suggestion
                tools_kwargs_copy = copy.deepcopy(tools_kwargs)  # Use deepcopy to avoid sharing mutable state
```
