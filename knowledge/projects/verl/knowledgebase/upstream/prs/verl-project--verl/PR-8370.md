# [veomni] feat: honor optim.override_optimizer_config (fused AdamW under FSDP2 CPU offload) and make checkpoint ingestion configurable

[Upstream PR](https://github.com/verl-project/verl/pull/8370) · state: closed · merged: True

## Original PR description

### What does this PR do?

Two VeOmni-engine settings that the other engines already expose:

1. **`optim.override_optimizer_config` is ignored by the VeOmni engine** (the FSDP, Megatron and Automodel engines honor it), so it always builds VeOmni's default foreach AdamW. With `actor.veomni.enable_fsdp_offload` — on in the DeepSeek-V4 recipe — FSDP2's `CPUOffloadPolicy` keeps the sharded parameters, gradients and Adam states on the host and the step runs on CPU tensors, where foreach AdamW materializes a temporary as large as the local fp32 parameters at every step. With DeepSeek-V4-Flash on two nodes, that temporary pushed the hosts over Ray's memory-usage threshold right after the first optimizer step; fused AdamW does not allocate it. This PR forwards `override_optimizer_config` to VeOmni's `build_optimizer` and defaults `fused` to `true` under `enable_fsdp_offload` (an explicit `fused: false` still wins). As in the FSDP engine's builder, override keys replace the base arguments (`lr`, `betas`, `weight_decay`), and an overridden `lr` is also the scheduler's peak rate.
2. **Checkpoint ingestion is hard-coded** to `broadcast_model_weights_from_rank0=True`: rank 0 reads the checkpoint and broadcasts every tensor, so the whole fp32 model crosses the inter-node network at every launch. `broadcast_model_weights_from_rank0` and `ep_sharded_stream_load` (both `build_parallelize_model` options) are now engine config fields with unchanged defaults.

### Test

`tests/workers/test_veomni_optimizer_overrides_on_cpu.py`: `override_optimizer_config` reaches `build_optimizer`, `fused` defaults to `true` only under `enable_fsdp_offload`, an explicit value wins, and overrides of `lr` / `betas` / `weight_decay` replace the base arguments, including the scheduler's `lr`.

One AdamW step on CPU-resident fp32 parameters (torch 2.13; plain tensors and DTensors behave the same): foreach allocates a temporary as large as the parameters, fused allocates none, and the updated parameters are bitwise identical (first 2^20 elements compared).

End to end: with this change, `run_deepseek_v4_veomni.sh` with its defaults stays within host memory through the optimizer steps on two nodes each of AMD gfx942 and gfx950.

### API and Usage Example

```bash
actor_rollout_ref.actor.optim.override_optimizer_config.fused=false          # opt out of the offload default
actor_rollout_ref.actor.veomni.broadcast_model_weights_from_rank0=false      # every rank reads the checkpoint
actor_rollout_ref.actor.veomni.ep_sharded_stream_load=true                   # ... only its expert-parallel slice
```

### Design & Code Changes

- `VeOmniEngine._build_optimizer`: the base arguments updated with `override_optimizer_config`, `fused` defaulting to `enable_fsdp_offload`; `_build_lr_scheduler` takes an overridden `lr`.
- `VeOmniEngineConfig` / `config/engine/veomni.yaml`: `broadcast_model_weights_from_rank0` (default `true`), `ep_sharded_stream_load` (default `false`), passed to `build_parallelize_model`; `_generated_ppo_veomni_trainer.yaml` regenerated.
- `VeOmniOptimizerConfig` / `config/optim/veomni.yaml`: document `override_optimizer_config`.
