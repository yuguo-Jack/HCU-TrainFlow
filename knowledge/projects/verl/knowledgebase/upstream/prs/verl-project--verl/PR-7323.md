# [model, fsdp] fix: align Qwen3.5 vision calls across ranks

[Upstream PR](https://github.com/verl-project/verl/pull/7323) · state: open · merged: False

## Original PR description

### What does this PR do?

FSDP2 records each wrapped-module forward use with multiplicity for pre-backward parameter unsharding. With dynamic multimodal batching, a rank containing both images and videos enters `model.visual` twice, while an image-only, video-only, or text-only rank enters it once. The resulting rank-local usage mismatch can make later parameter all-gathers execute in different orders.

This PR concatenates image and video patches and their `grid_thw` metadata before one shared visual forward. It then splits the output at the grid-derived image feature boundary before scattering image and video embeddings back to their token positions. Image-only, video-only, and the existing text-only dummy path continue to enter the visual tree exactly once.

Related context: issue #3491 and PRs #3496, #3670, #5881, and #5948. This is not a duplicate of #3496/#3670, which address 0-vs-1 visual usage for text-only ranks, or #5948, which addresses Ulysses/fused-kernel/device handling while retaining separate image and video visual calls.

No public API, CLI, or configuration changes are introduced. Existing Qwen3.5 FSDP2 training uses the aligned visual path automatically.

### Design & Code Changes

- Concatenate image and video pixel tensors and `grid_thw` metadata in image-then-video order.
- Invoke the shared Qwen3.5 visual encoder once per micro-batch.
- Derive the image output boundary from `grid_thw` and `spatial_merge_size`.
- Preserve the existing per-modality token-count validation and text-only dummy visual forward.
- Add CPU numerical and two-rank FSDP2 regression coverage.
