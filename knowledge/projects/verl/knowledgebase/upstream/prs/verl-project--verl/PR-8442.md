# [fsdp, vllm] fix: split packed MoE experts on the correct axis for the NPU grouped-GEMM layout

[Upstream PR](https://github.com/verl-project/verl/pull/8442) · state: open · merged: False

## Original PR description

### What does this PR do?

Fix a weight-sync shape mismatch that makes Qwen3-VL-MoE training unusable on Ascend NPU with vLLM rollout.

`unfuse_moe_params()` always splits packed expert weights on `dim=1`, which is correct for the HF checkpoint layout but wrong for the layout produced by the NPU grouped-GEMM patch. As a result every expert is sliced across `hidden_size`, and the first `update_weights_from_ipc` after training starts fails inside vLLM's fused-MoE loader:

```
RuntimeError: copy_d2d_baseformat_opapi ... call aclnnInplaceCopy failed, error code is 161002
The size of tensor self [96, 1536] must match the size of tensor src [128, 1536]    # TP=8
The size of tensor self [192, 1536] must match the size of tensor src [256, 1536]   # TP=4
```

`src` is `hidden/2/TP = 1024/TP` (what verl sends), `self` is `intermediate/TP = 768/TP` (what vLLM allocates). Both ends are upstream code, so any NPU user with a Qwen-style MoE student + vLLM rollout hits this with no local modification. Reproduced on current `main` (`0938fcb3`, which already includes #8251) as well as on the earlier commit this branch was opened against.

### Test

Regression tests are added to the existing CPU-only test module `tests/workers/rollout/test_vllm_moe_param_converter_on_cpu.py`, which already covers `unfuse_moe_params`. The new cases assert converted **values**, because square expert tensors keep their shape under a wrong transpose:

- NPU grouped-GEMM layout (`[E, hidden, 2*I]` / `[E, I, hidden]`) is normalized before expansion, with `hidden_size` passed in.
- A square `gate_up_proj` (`2*I == hidden`) and a square `down_proj` (`I == hidden`) are resolved by `npu_gmm_layout=True`; the same tensors without provenance keep the previous standard-layout split.
- `gpt_oss` packed experts are still passed through untouched.

The same coverage is also available as a standalone script (no pytest, no NPU) for anyone reproducing this on a cluster:

**1) CPU verification** (no NPU, no vLLM, no training; torch only). Save as `/tmp/test_moe_layout.py` and run `python -m pytest /tmp/test_moe_layout.py -q` (or just `python /tmp/test_moe_layout.py`):

```python
import torch
from verl.workers.engine.fsdp.utils import unfuse_moe_params

E, H, I = 4, 2048, 768          # qwen3_vl_moe-30b-a3b: hidden=2048, intermediate=768

def collect(gu, dp, hidden, npu_gmm=False):
    params = [
        ("m.mlp.experts.gate_up_proj", gu),
        ("m.mlp.experts.down_proj", dp),
    ]
    return dict(unfuse_moe_params(params, "qwen3_vl_moe", hidden_size=hidden, npu_gmm_layout=npu_gmm))

# HF / checkpoint layout (behaviour must not change)
hf_gu = torch.randn(E, 2 * I, H)
hf_dp = torch.randn(E, H, I)
ref = collect(hf_gu, hf_dp, H)

# NPU GMM layout produced by NPUQwen3VLMoeTextExperts, with provenance passed in
npu_gu = hf_gu.transpose(1, 2).contiguous()   # [E, H, 2I]
npu_dp = hf_dp.transpose(1, 2).contiguous()   # [E, I, H]
out = collect(npu_gu, npu_dp, H, npu_gmm=True)

assert out.keys() == ref.keys()
for name, ref_t in ref.items():
    torch.testing.assert_close(out[name], ref_t)          # same shape, same values

# shapes that vLLM's per-expert loader expects
gate_key = "m.mlp.experts.0.gate_proj.weight"
down_key = "m.mlp.experts.0.down_proj.weight"
assert out[gate_key].shape == (I, H)                       # (768, 2048)
assert out[down_key].shape == (H, I)                       # (2048, 768)

# shape heuristic still works when the caller does not pass provenance
heur = collect(npu_gu, npu_dp, H)
for name, ref_t in ref.items():
    torch.testing.assert_close(heur[name], ref_t)

# square / ambiguous case (2 * intermediate == hidden): only provenance can resolve it
I2 = H // 2                                                # 1024
hf_gu2 = torch.randn(E, 2 * I2, H)                         # [E, H, H], square
npu_gu2 = hf_gu2.transpose(1, 2).contiguous()              # same shape, different values
ref2 = dict(unfuse_moe_params([("m.mlp.experts.gate_up_proj", hf_gu2)], "qwen3_vl_moe", hidden_size=H))
got2 = dict(unfuse_moe_params([("m.mlp.experts.gate_up_proj", npu_gu2)], "qwen3_vl_moe",
                              hidden_size=H, npu_gmm_layout=True))
for name, ref_t in ref2.items():
    torch.testing.assert_close(got2[name], ref_t)          # would be silently wrong without provenance

# without provenance and without hidden_size the old (NPU-broken) path is preserved
old = collect(npu_gu, npu_dp, None)
assert old[gate_key].shape == (H // 2, 2 * I)              # (1024, 1536), the pre-fix bug

# gpt_oss must still be passed through untouched
oss = dict(unfuse_moe_params([("x.mlp.experts.gate_up_proj", npu_gu)], "gpt_oss", hidden_size=H))
assert oss["x.mlp.experts.gate_up_proj"].shape == npu_gu.shape

# the call site detects the layout through the MRO, which survives the FSDP2 class swap
class NPUQwen3VLMoeTextExperts(torch.nn.Module):
    pass

fsdp_wrapped = type("FSDPNPUQwen3VLMoeTextExperts", (NPUQwen3VLMoeTextExperts,), {})()
assert not type(fsdp_wrapped).__name__ == "NPUQwen3VLMoeTextExperts"
assert any("NPUQwen3VLMoeTextExperts" in {b.__name__ for b in type(m).__mro__} for m in [fsdp_wrapped])

print("all checks passed")
```

- **Before** (clean `0938fcb3`, no patch): every TP rank of every rollout replica fails on the first `update_weights_from_ipc`, ~1 s before the first training step could start. 87 occurrences in one run:


- The same failure mode at `tensor_model_parallel_size=8` was `[96, 1536]` vs `[128, 1536]`, i.e. the identical bug scaled by TP.

### API and Usage Example

`unfuse_moe_params` gains two keyword-optional arguments; existing callers are unaffected.

```python
# before
def unfuse_moe_params(weights, model_type: str | None = None): ...

# after
def unfuse_moe_params(
    weights,
    model_type: str | None = None,
    hidden_size: int | None = None,
    npu_gmm_layout: bool = False,
): ...
```

`npu_gmm_layout` states the producer layout instead of inferring it from shapes. This is what makes square expert tensors safe: when `hidden_size == 2 * intermediate` (gate/up) or `hidden_size == intermediate` (down), the two layouts are shape-identical, so a shape check alone cannot tell them apart and would export silently wrong weights.

Call site (`verl/workers/engine/fsdp/transformer_impl.py`). The flag is read from the constructed module, not from the config, because the NPU patch is best-effort — `trust_remote_code` models or a patch that failed and only logged a warning keep the standard packed layout. FSDP2 rewrites the class of every sharded module to a derived `FSDP<Name>`, so the check walks the MRO instead of comparing the concrete class name. VL configs keep the text hidden size inside `text_config`:

```python
hf_config = self.model_config.hf_config
text_config = getattr(hf_config, "text_config", hf_config)
# The NPU patch swaps the Transformers experts module for a grouped-GEMM one that
# keeps the experts transposed. Its installation is best-effort, so read the layout
# from the constructed module instead of inferring it from the config. FSDP2 rebuilds
# the class of every sharded module ("FSDP<Name>", still deriving from the original
# one), so search the MRO instead of comparing the concrete class name.
npu_gmm_layout = any(
    "NPUQwen3VLMoeTextExperts" in {base.__name__ for base in type(module).__mro__}
    for module in self.module.modules()
)
per_tensor_param = unfuse_moe_params(
    per_tensor_param,
    hf_config.model_type,
    hidden_size=getattr(text_config, "hidden_size", None),
    npu_gmm_layout=npu_gmm_layout,
)
```

`npu_patch.py:384` is the only place that swaps the experts module — `qwen3_moe` / `qwen3_next` patch `forward` only and keep HF parameter layout, so their module class stays unchanged and the flag stays `False`.

### Design & Code Changes

**Root cause.** Two subsystems disagree on the packed layout:

| producer / consumer | tensor | layout |
| --- | --- | --- |
| `npu_patch.py` `NPUQwen3VLMoeTextExperts` (producer, NPU only) | `gate_up_proj` | `[E, hidden, 2*I]` = `[128, 2048, 1536]` |
| `npu_patch.py` `NPUQwen3VLMoeTextExperts` (producer, NPU only) | `down_proj` | `[E, I, hidden]` = `[128, 768, 2048]` |
| HF checkpoint / `unfuse_moe_params` (consumer) | `gate_up_proj` | `[E, 2*I, hidden]` |
| HF checkpoint / `unfuse_moe_params` (consumer) | `down_proj` | `[E, hidden, I]` |

`chunk(2, dim=1)` on `[128, 2048, 1536]` splits the hidden axis, producing `[1024, 1536]` per expert instead of `[768, 2048]`. vLLM expects the HF layout on the receiving side and converts to GMM itself after loading (post-load `w13_weight.transpose(1, 2)` in vllm-ascend, and `fused_moe/layer.py` deriving shard sizes from the HF orientation), so the exporter must emit HF-oriented tensors.

**Changes.**

1. `verl/workers/engine/fsdp/utils.py` — normalize the layout before streaming, preferring explicit provenance over shape inference:

```python
if name.endswith(".mlp.experts.gate_up_proj") and tensor.dim() == 3:
    # Ambiguous when 2 * intermediate == hidden: fall back to the standard layout
    # instead of guessing, so shapes that used to be correct stay unchanged.
    if npu_gmm_layout or (
        hidden_size is not None and tensor.size(1) == hidden_size and tensor.size(2) != hidden_size
    ):
        # NPU GMM layout: [experts, hidden, 2 * intermediate]
        gate, up = (part.transpose(1, 2) for part in tensor.chunk(2, dim=2))
    else:
        # Standard layout: [experts, 2 * intermediate, hidden]
        gate, up = tensor.chunk(2, dim=1)
    ...

if name.endswith(".mlp.experts.down_proj") and tensor.dim() == 3:
    down_proj = (
        tensor.transpose(1, 2)
        if npu_gmm_layout
        or (hidden_size is not None and tensor.size(2) == hidden_size and tensor.size(1) != hidden_size)
        else tensor
    )
```

2. `verl/workers/engine/fsdp/transformer_impl.py` — compute `npu_gmm_layout` from the same condition that installs the NPU patch, and pass it together with `text_config.hidden_size` (see snippet above).

3. Docstring updated to document both layouts and the `npu_gmm_layout` semantics.

**Why square expert tensors are now handled.** When `H == 2I` the NPU `gate_up_proj` `[E, H, 2I]` and the HF one `[E, 2I, H]` are both `[E, H, H]`. A shape check cannot distinguish them, and splitting on the wrong axis still yields the expected per-expert shape — i.e. silently wrong weights that would previously fail loudly on `down_proj`. Passing `npu_gmm_layout=True` from `get_per_tensor_param` removes the guess entirely, so such configs export correct weights (and the symmetric `H == I` case for `down_proj` behaves the same way).

**Why existing users cannot be affected.**

- With `npu_gmm_layout=False` (default, and always the case off NPU) the code is byte-identical to the previous heuristic, and the heuristic branches are unreachable for the HF layout, not merely unlikely:
  - HF `gate_up_proj` is `[E, 2I, H]`, so `size(2) == H` always holds, while the branch requires `size(2) != H`.
  - HF `down_proj` is `[E, H, I]`; transposing needs `size(2) == H` (i.e. `I == H`) and `size(1) != H` (i.e. `H != H`), which cannot both hold.
- `npu_gmm_layout=True` is only produced when `is_npu_available` and the model is `qwen3_vl_moe` and `use_liger` is off — exactly the condition under which `apply_npu_fsdp_patches()` replaces the experts module.
- Additionally: `hidden_size` defaults to `None`; the only caller is `get_per_tensor_param` (FSDP engine online weight export); `gpt_oss` returns early; non-MoE models never match these tensor names.

`verl/workers/engine/veomni/utils.py` (`default_moe_param_handler`) has the same `chunk(2, dim=1)` assumption, but it is a different engine path and is intentionally left untouched here.
