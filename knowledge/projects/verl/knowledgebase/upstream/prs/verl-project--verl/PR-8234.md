# [rollout, vllm] fix: do not pass data_parallel_start_rank to the DP leader (vLLM >= 0.28 hybrid-LB)

[Upstream PR](https://github.com/verl-project/verl/pull/8234) · state: open · merged: False

## Original PR description

### What does this PR do?

Multi-node vLLM rollout replicas (`data_parallel_size > data_parallel_size_local`) fail at engine start on vLLM ≥ 0.28 with

```
Remote engine 15 must not use --headless in external or hybrid dp lb mode
```

`vLLMHttpServer` starts node 0 as the API server and nodes > 0 with `run_headless`, but passes `data_parallel_start_rank = node_rank * data_parallel_size_local` to **every** node. Since vLLM 0.28, `EngineArgs.create_engine_config` infers hybrid-LB mode when `data_parallel_start_rank is not None and not headless` (still the case on vLLM `main`, `vllm/engine/arg_utils.py`), and in hybrid-LB mode the leader rejects headless remote engines. The node-0 server is the internal-LB leader and must not carry a start rank; its local engines start at rank 0 anyway.

This PR only sets `data_parallel_start_rank` for `node_rank > 0`. #6856 covered the pre-0.28 semantics and was closed by a vLLM-side port fix (vllm-project/vllm#49212); this is the 0.28+ follow-up. gpustack, kserve and vllm-ascend made the same change in Sep–Oct 2026.

### Test

Cannot be covered by CI (needs a replica spanning several nodes). Validated on a GB200 cluster (4 GPUs per node, aarch64), verl `1d367a4f` + vLLM 0.29.0, DeepSeek-V4-Pro with `moe_backend=marlin`:

- without the change: 16 replicas × 16 GPUs (4 nodes each) all fail with the message above within 8 minutes of job start;
- with the change: 8 replicas × 32 GPUs (8 nodes each) load, allocate KV cache, capture CUDA graphs and serve; GRPO runs end to end (rollout/actor log-prob Pearson 0.995), 15+ multi-node runs since, including 128-node runs (16 replicas × 32 GPUs).

Single-node replicas (`data_parallel_size_local == data_parallel_size`) are unaffected: vLLM disables hybrid-LB for that case regardless of the start rank; an 8-node smoke with one replica per node behaves identically before and after.
