# [hardware, doc] feat: update the ROCm Dockerfile for Primus v26.8

[Upstream PR](https://github.com/verl-project/verl/pull/8432) · state: open · merged: False

## Original PR description

### What does this PR do?

Updates [`docker/rocm/Dockerfile.rocm`](docker/rocm/Dockerfile.rocm) for the current Primus ROCm training image and refreshes [`docker/rocm/README.md`](docker/rocm/README.md) so the documented build matches that recipe. This follows the ROCm Dockerfile/README added in #6619.

The image now starts from `rocm/primus:v26.8` (ROCm 7.16, PyTorch 2.14) instead of the previous Primus v26.4 stack. It builds vLLM `v0.29.0` and the pinned SGLang commit, installs Ray `>=2.58.0`, and adds the Qwen3.5 Megatron extras (Gated Delta Net / `flash-linear-attention`, Megatron-Bridge on the nightly path, ISEEKYAN `mbridge` on the release path).

### Test

This area is not covered by CI hardware (AMD GPUs), so validation is a local image build, same as #6619.

Built `docker/rocm/Dockerfile.rocm` and started the image on an 8× MI350X host with `/dev/kfd` and `/dev/dri` mounted. The image Python reports `torch 2.14.0+rocm10.1` and `torch.cuda.device_count() == 8`.

```sh
docker build \
    -f docker/rocm/Dockerfile.rocm \
    -t verl-rocm:local .
```

### API and Usage Example

Build args are overridable. Defaults are the Primus v26.8 / vLLM v0.29.0 recipe.

| Build arg | Default | Purpose |
| --------- | ------- | ------- |
| `PRIMUS_TAG` | `v26.8` | Base image tag. `v26.7` and `v26.8` are supported. |
| `GPU_ARCH` | `gfx942;gfx950` | `PYTORCH_ROCM_ARCH` and `AMDGPU_TARGETS`. |
| `VERL_SOURCE` | `nightly` | `nightly` clones upstream `main` and installs Megatron-Bridge. `release` clones `VERL_REPO` / `VERL_BRANCH` and installs ISEEKYAN `mbridge`. |
| `VLLM_TAG` | `v0.29.0` | vLLM tag built from source. |
| `SGLANG_TAG` | `0801cc05ed202544e2e5c67d6b0a1d454de54fca` | SGLang commit. Re-validate when changing `PRIMUS_TAG` or `VLLM_TAG`. |
| `RAY_SPEC` | `ray[default,serve]>=2.58.0` | Ray install when `RAY_SOURCE=stable`. |
| `MAX_JOBS` | `64` | Parallel jobs for the vLLM build. |

The image runs as the non-root `verl` user and its entrypoint is `/bin/bash`, so `docker run` with no command already opens a shell. Pass the host `video` and `render` group ids so that user can open the ROCm device nodes.

```sh
docker build \
    -f docker/rocm/Dockerfile.rocm \
    --build-arg VERL_SOURCE=release \
    --build-arg GPU_ARCH=gfx942 \
    --build-arg MAX_JOBS=64 \
    -t verl-rocm:mi300 .
```

### Design & Code Changes

- Base image is `rocm/primus:v26.8`. PyTorch, Triton, Transformer Engine, and aiter stay on the Primus builds.
- Install `amdsmi` from the ROCm SDK tree (v26.8 via a `.pth` file, v26.7 via `pip`) and preload `rocm_sdk` with `RTLD_LOCAL`, so Ray's AMD GPU detector does not report 0 GPUs and `torch.cuda.device_count()` stays correct.
- Build vLLM `v0.29.0` from source and link `libz3.so.4.15` for tilelang. Install Ray `>=2.58.0`.
- Install verl with `--no-deps`. `VERL_SOURCE=nightly` uses upstream `main`, Megatron-Bridge `0.6.2`, and `megatron-core==0.19.2`. `VERL_SOURCE=release` uses `AMD-Ecosystem/verl` `release/0.9.0.amd0`, ISEEKYAN `mbridge`, and `megatron-core==0.18.0`.
- Add the Qwen3.5 extras: `flash-linear-attention`, `transformers>=5.12`, `mistral-common`, `mathruler`, `transferqueue`, `model-hosting-container-standards`, CuPy, and `torchao>=0.16.0`.
- Build SGLang beside vLLM (`SGLANG_USE_AITER=0`, Triton attention). On Primus v26.8 the SGLang HIP files are compiled as C++20.
- Apply the OpenSSL and Python package security updates, drop nested Dockerfiles and VCS metadata, and run as `USER verl`.
- Rewrite `docker/rocm/README.md` for this recipe. The previous README described the Primus v26.4 / BuildKit-cache-mount build, which this Dockerfile no longer uses.
