# [rollout, vllm] fix: launch vLLM servers when rollout workers hold no accelerator

[Upstream PR](https://github.com/verl-project/verl/pull/8529) · state: open · merged: False

## Original PR description

### What does this PR do?

`vLLMReplica.launch_servers` takes the first accelerator id of every rollout worker (`get_accelerator_ids()[get_resource_name()][0]`). This raises `IndexError` when a worker holds no accelerator. On TPU, verl's rollout workers get no TPU, because a chip can belong to only one process and the vLLM engine opens the host's chips itself. As a result, out-of-tree platforms have to copy and override the whole `launch_servers` method.

This PR reads the worker's full id list instead and builds each node's visible-devices string with a small helper:
- every worker on the node holds an accelerator: same string as before (first id of each worker, comma-joined);
- no worker on the node holds one: empty string;
- only some do: `ValueError`.

GPU and NPU behavior is unchanged.

- xiaoxlu · comment · 2026-11-04T17:47:17Z · [source](https://github.com/verl-project/verl/pull/8529#issuecomment-6637783689)

> > On TPU, verl's rollout workers get no TPU, because a chip can belong to only one process and the vLLM engine opens the host's chips itself.
> 
> Even through each TPU can belong to only one process, but without worker_accelerator_ids, how can each vllm worker process pick each of their own chip?

On TPU, vLLM picks the chips itself, not verl:
1. verl launches one vLLM server per host without passing any device IDs.
2. Inside that server, vLLM's `mp` executor spawns one worker process per local TPU chip (local rank 0, 1, 2, ...).
3. vllm-torchtpu sets each worker's `LOCAL_RANK`, and torch_tpu maps it to `TPU_VISIBLE_CHIPS`, so each worker opens only its own chip.

GPU/NPU behavior is unchanged; this PR just avoids indexing `[0]` when the worker's device ID list is empty.
