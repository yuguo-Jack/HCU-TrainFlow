# [perf, algo] feat: compute sum_pi_squared in row chunks to cut peak memory

[Upstream PR](https://github.com/verl-project/verl/pull/8365) · state: open · merged: False

## Original PR description

### What does this PR do?

`calculate_sum_pi_squared_from_logits` computes `exp(logsumexp(2 * logits) - 2 * logsumexp(logits))` over the whole packed micro-batch in one pass. It is used by `actor.calculate_sum_pi_squared=True`, which optimal token baseline needs. Both `2 * logits` and the `logsumexp` temporaries are full-vocabulary tensors the size of the logits, so on top of the logits themselves the call needs about two more copies of them. With a 152k vocabulary this is the step that runs out of memory on a 24 GB card at the default `log_prob_micro_batch_size_per_gpu=16`, while the same run without `calculate_sum_pi_squared` fits. I hit this while validating #8364.

This PR processes the rows in chunks (default 2048, the same default as `entropy_from_logits_with_chunking`) and concatenates the per-row results. The values and dtype stay the same, the signature only gains an optional `chunk_size`, and gradients still flow. No config change.

**Not a duplicate:** I searched PRs and issues for `calculate_sum_pi_squared_from_logits`, `sum_pi_squared memory` and `sum_pi_squared OOM`. Only #6153 (which added the function) and #8364 (V1 wiring, independent of this change) came up.

### Test

**Unit tests:** `tests/utils/test_torch_functional.py` gains `test_calculate_sum_pi_squared_from_logits_chunking`. It compares values and gradients against the softmax-squared reference for 2-D, 3-D and empty inputs at `chunk_size` 1, 4 and 2048. The existing tests are unchanged.

```
pytest -q tests/utils/test_torch_functional.py -k sum_pi_squared
# 16 passed
```

**Memory and time:** RTX 4090, vocab 151936. The reported peak is the extra memory allocated during the call, on top of the input logits. Each time is the mean of 3 calls. The outputs are bitwise identical (max |diff| = 0).

| rows × vocab | dtype | main: extra peak | this PR: extra peak | main time | this PR time |
|---|---|---|---|---|---|
| 4096 × 151936 | fp32 | 4.64 GiB | 2.32 GiB | 78 ms | 40 ms |
| 8192 × 151936 | fp32 | 9.27 GiB | 2.32 GiB | 91 ms | 80 ms |
| 8192 × 151936 | bf16 | 4.64 GiB | 1.16 GiB | 40 ms | 41 ms |

**End to end:** V1 trainer with #8364 applied, Qwen3-0.6B, GSM8K, batch 32 × n=4, `optimal_token_baseline`, `calculate_sum_pi_squared=True`, default `log_prob_micro_batch_size_per_gpu=16`:
- without this PR: step 2 fails with `OutOfMemoryError: Tried to allocate 5.29 GiB` inside `calculate_sum_pi_squared_from_logits`;
- with this PR: 3/3 steps complete, `rollout_probs_diff_mean` 0.0057 / 0.0058 / 0.0055.

### Design & Code Changes

`verl/utils/torch_functional.py::calculate_sum_pi_squared_from_logits`:
- flatten the leading dimensions;
- evaluate the same formula per `chunk_size` rows;
- `torch.cat` the results and reshape back;
- return an empty tensor for zero rows.
