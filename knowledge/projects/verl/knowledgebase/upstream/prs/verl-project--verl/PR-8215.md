# [megatron, training_utils] feat: budget BSHD padded tokens in dynamic batching

[Upstream PR](https://github.com/verl-project/verl/pull/8215) · state: closed · merged: False

## Original PR description

### What does this PR do?

With `use_dynamic_bsz=True`, `rearrange_micro_batches` budgets each micro-batch by the sum of its real tokens. On the Megatron BSHD path (`use_remove_padding=False`), however, every micro-batch is stored as `batch_size * aligned_max_seq_len` tokens: it is padded to its longest sequence (or to the mini-batch max with `pad_bshd_to_minibatch_max=True`) and then aligned for TP/CP/FP8. A few short samples next to a long one can therefore exceed `max_token_len_per_gpu` by a large factor.

This PR adds an opt-in `megatron.dynamic_bsz_cost_model=bshd_padded` that budgets the padded storage the BSHD forward actually allocates. The default stays `token`, so behavior is unchanged unless the option is set.

Related: #5338 proposes length-grouped micro-batches for FSDP. This PR differs in three ways: it targets the Megatron BSHD engine, it uses the exact padded length of `preprocess_bshd_engine` (TP/CP/FP8 alignment and `forced_max_seqlen`), and it reuses the existing DP count sync and within-limit loop of `rearrange_micro_batches` (including `min_num_micro_batch` and VPP divisibility) instead of adding a separate code path. It does not include the token hard cap of #6735, and it does not touch the micro-batch construction changed by #7097.

```bash

```

Result: `85 passed, 1 skipped`. The new tests cover:

- `BSHDPadding.num_tokens` equals the tokens allocated by the real `preprocess_bshd_engine` (with stubbed Megatron parallel state) across 36 combinations of TP/CP/FP8, fixed length and sequence length.
- 33+33 tokens with CP=8 cost 96 (aligned), not 66.
- For a mixed short/long batch, the token model packs 16 samples into one micro-batch (16 x 1024 padded tokens), while the padded model isolates the long sample.
- For every micro-batch count from the minimum up to the batch size: the exact count is returned, partitions are non-empty and within budget, and every sample appears exactly once. FP8 padding also stays within budget.
- Budgeting with a fixed length (`pad_bshd_to_minibatch_max`), fail-fast on an oversized single sample, rejection of `force_group_size > 1`, unchanged token-path output vs `main` for a fixed input, and CP scaling through `prepare_micro_batches`.
- A 3-rank Gloo DP group with different batch sizes and length distributions: every rank gets the same micro-batch count (the max of the local counts) and every partition stays within the padded budget. An oversized sample on one rank raises on all ranks without hanging.

`tests/utils/test_seqlen_balancing.py::test_seqlen_balancing_distributed_params` needs CUDA/NCCL. It is not a CPU test and fails the same way on `main` without CUDA.

Example (64 samples: 60 of 200-2000 tokens and 4 of 14k-16k tokens; TP2/CP4; budget 65536):

| | token model | bshd_padded |
|---|---|---|
| per-micro-batch max length | 2 micro-batches, max 502272 padded tokens | 3 micro-batches, max 65472 |
| `pad_bshd_to_minibatch_max=True` | 2 micro-batches, max 502272 | 16 micro-batches, max 62784 |

### API and Usage Example

```bash
actor_rollout_ref.model.use_remove_padding=False \
actor_rollout_ref.actor.use_dynamic_bsz=True \
actor_rollout_ref.actor.ppo_max_token_len_per_gpu=16384 \
actor_rollout_ref.actor.megatron.dynamic_bsz_cost_model=bshd_padded \
actor_rollout_ref.actor.megatron.pad_bshd_to_minibatch_max=False
```

The reference model follows the actor setting. The critic uses `critic.megatron.dynamic_bsz_cost_model`.

```python
from verl.utils.seqlen_balancing import BSHDPadding, rearrange_micro_batches

micro_batches, indices = rearrange_micro_batches(
    batch, max_token_len, dp_group=dp_group, bshd_padding=BSHDPadding(tp_size=2, cp_size=4)
)
```

### Design & Code Changes

- Cost contract: `len(mb) * get_bshd_padded_seq_len(raw_len, len(mb), tp, cp, fp8) <= max_token_len_per_gpu * cp_size`. Here `raw_len` is the micro-batch max, or the mini-batch max when `pad_bshd_to_minibatch_max=True`.
- `verl/utils/seqlen_balancing.py`:
  - `get_bshd_padded_seq_len` computes the TP/CP/FP8 alignment and is now shared with `preprocess_bshd_engine`.
  - `BSHDPadding` describes the padding rule.
  - A new partitioner sorts samples by length, cuts greedy contiguous runs under the budget, and splits the most expensive run until the requested count is reached.
  - `rearrange_micro_batches(..., bshd_padding=None)` uses the partitioner for the initial count and inside the existing within-limit loop (`all_reduce MIN`). DP ranks therefore agree on the count, and every partition is checked against the exact padded cost.
  - A single sample whose padded size exceeds the budget fails fast on all ranks through the existing synchronized constraint check.
- `verl/models/mcore/util.py`: `preprocess_bshd_engine` calls the shared alignment helper; behavior is unchanged.
- `verl/workers/engine/utils.py`: `prepare_micro_batches` forwards `bshd_padding`.
- `verl/workers/engine/megatron/transformer_impl.py`: builds `BSHDPadding` from the TP/CP world sizes, `tf_config.fp8` and the `forced_max_seqlen` of `pad_bshd_to_minibatch_max`, and rejects `use_remove_padding=True`.
- Config and docs: `McoreEngineConfig.dynamic_bsz_cost_model` (validated), `engine/megatron.yaml`, `ref/megatron_ref.yaml` (follows the actor), the regenerated `_generated_ppo_megatron_trainer.yaml`, and `docs/perf/perf_tuning.rst`.
- Explicitly rejected combinations: THD (`use_remove_padding=True`, which also covers dynamic CP) and `force_group_size > 1`.
- Known approximations:
  - With FP8 padding the alignment depends on the micro-batch size, so the count may exceed the minimum; partitions always stay within budget.
  - VLM BSHD inputs are aligned without FP8, so the cost is an upper bound on that path.

#### Open questions for reviewers

1. With the default `pad_bshd_to_minibatch_max=True`, every micro-batch costs the mini-batch max length, so the count can grow a lot (16 in the example). The docs recommend `False`. Should `bshd_padded` turn it off automatically instead?
2. `bshd_padded` with `use_dynamic_bsz=False` is a documented no-op. Should it raise instead?
3. The option lives in `megatron.*` because only the Megatron BSHD engine needs it, and actor training and log-prob computation share one engine config.
