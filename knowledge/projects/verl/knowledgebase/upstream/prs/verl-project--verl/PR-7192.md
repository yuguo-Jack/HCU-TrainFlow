### What does this PR do?

This PR adds native Megatron-Core `HybridModel` MTP support for NVIDIA Nemotron 3.5 Lightning and Nemotron 3.5 Super VL. Lightning has SFT and GRPO examples; Super VL has image/text SFT through its multimodal wrapper. GPU validation of Super VL is pending.

- Uses Megatron-Core's native HybridModel MTP target/loss path instead of verl's legacy GPT MTP patches.
- Preserves response-aware MTP loss masking and supplies packed-sequence metadata required to reset Mamba state across samples.
- Retains current-`main` context-parallel layouts, padding buckets, FP8 padding, and legacy GPT shifted-label behavior.
- Rejects undersized packed labels instead of silently fabricating targets, while trimming ordinary dense right padding.
- Cleans up HybridProvider-only MTP overrides when MTP is disabled.
- Adds Nemotron 3.5 Lightning SFT and replaces the older Super example with Nemotron 3.5 Super VL image/text SFT.
- Recognizes the nested HybridModel decoder and `llm_config` MTP fields in Super VL; preserves its shared MTP block across two prediction depths.
- Packs variable-resolution RADIO image inputs with image sizes and frame counts, supports mixed text/image batches, and rejects unsupported video/audio and CP>1 configurations.
- Adds a Nemotron 3.5 Lightning GRPO launcher whose validated defaults enable R3 router replay and one-token MTP speculation.
- Fails fast when R3 uses an unsupported vLLM version: vLLM >= 0.22 for R3 alone and >= 0.26 for R3 combined with MTP speculation.
- Adds a reproducible NGC-based container recipe installed from the repository's canonical `uv.lock`.

The GRPO defaults reproduce the drift-reduction settings used in validation: raw log probabilities, fixed seeds, temperature 1, CP=1, FP32 routers, disabled prefix caching/dynamic batching/batch balancing, and disabled router/permutation fusion.

This does not duplicate another contribution: earlier [Lightning/HybridModel searches](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+%22HybridModel%22+MTP) returned only this PR; the [Super VL search](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+%22Nemotron%22+%22Super%22+%22VL%22+in%3Atitle%2Cbody) found no overlapping open PR before this update.

### API and Usage Example

Build the Lightning image from a clean checkout of the exact PR head:

```bash
docker build --build-arg VERL_COMMIT="$(git rev-parse HEAD)" \
  -f docker/Dockerfile.nemotron_3_5_lightning \
  -t verl-nemotron-3-5-lightning .
```

Download the exact model and GRPO dataset snapshots:

```bash
hf download nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16 \
  --revision d468880b6ad3c6e0d21377ce7242adaea4cc884d \
  --local-dir "$HOME/models/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16"
hf download BytedTsinghua-SIA/DAPO-Math-17k data/dapo-math-17k.parquet \
  --repo-type dataset --revision 65877096c24ffa7abc4e4fa5edb95cf3413a5674 \
  --local-dir "$HOME/verl/data/DAPO-Math-17k"
hf download BytedTsinghua-SIA/AIME-2024 data/aime-2024.parquet \
  --repo-type dataset --revision aa49075e24ad594b79fdf0bdcefa735c2181be67 \
  --local-dir "$HOME/verl/data/AIME-2024"
```

Current `main` does not expose a Hub revision through `HFModelConfig`; set `MODEL_PATH` to the local snapshot above for exact reproduction.

Prepare message-formatted GSM8K for SFT:

```bash
python examples/data_preprocess/gsm8k_multiturn_sft.py \
  --revision 740312add88f781978c0658806c59bc2815b9866 \
  --local_save_dir "$HOME/data/gsm8k_sft"
```

Run Lightning SFT once per host with the same rendezvous address and a distinct node rank:

```bash
MODEL_PATH="$HOME/models/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16" \
DATASET_DIR="$HOME/data/gsm8k_sft" CHECKPOINT_DIR=/shared/output/sft \
NNODES=2 NGPUS_PER_NODE=8 NODE_RANK=0 \
MASTER_ADDR=node-0.example.internal MASTER_PORT=29500 \
bash examples/sft/gsm8k/run_nemotron_3_5_lightning_megatron.sh
```

Use `NODE_RANK=1` on the second host. For GRPO, form a 2-host Ray cluster and run once on its head:

```bash
MODEL_PATH="$HOME/models/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16" \
DATA_DIR="$HOME/verl" CHECKPOINT_DIR=/shared/output/grpo \
NNODES=2 NGPUS_PER_NODE=8 ROUTER_REPLAY_MODE=R3 MTP_ROLLOUT_SPEC=1 \
bash examples/grpo_trainer/run_nemotron_3_5_lightning_30b_a3b_megatron.sh
```

Use identical image, model, data, and output paths on both hosts. Inject credentials such as `WANDB_API_KEY` only at runtime.

Super VL image/text SFT uses `examples/sft/vlm/run_nemotron_3_5_super_vl_megatron.sh` with the pinned Bridge/Core source pair and Transformers 5.20.1. Follow the setup and checkpoint download commands in [the MTP guide](https://github.com/Phlip79/verl/blob/7f76b9062f1e84cb5e3219a8b8a6a7a51dc4c4b4/docs/advance/mtp.md#7-nemotron-35-super-vl-sft), prepare `examples/data_preprocess/pokemon.py`, and launch once per host. Defaults are 4×8 GPUs, TP2/PP1/EP16/CP1, frozen vision encoder, trainable projector/decoder, and two shared MTP prediction depths. Video/audio, Super VL GRPO/R3/speculative rollout, quantization, and restore are outside the verified scope.

### Design & Code Changes

- Native HybridModels receive unshifted `input_ids` targets and an unshifted response-aware MTP loss mask; legacy GPT models retain their shifted labels/masks.
- `PackedSeqParams.total_tokens` is supplied only for Hybrid/Mamba models so current-main behavior remains unchanged for other models.
- Provider-specific repeated-layer overrides are applied only after identifying a HybridProvider.
- R3 + MTP version validation examines vLLM's effective normalized speculative configuration, including `engine_kwargs` overrides.
- The image starts from `nvcr.io/nvidia/pytorch:26.06-py3` and installs the repository's frozen Megatron + vLLM extras into an isolated project venv; the exact locked stack should receive a fresh GPU smoke/soak before this PR leaves draft.
