# [reward, trainer] fix: keep colocated RM outcomes on generated tokens

[Upstream PR](https://github.com/verl-project/verl/pull/8379) · state: open · merged: False

## Original PR description

### What does this PR do?

Keep colocated reward-model outcome scores on the last generated, non-padding token. A multi-turn response may end in a masked chat-template suffix; GAE, REINFORCE++ and ReMax then drop an outcome placed on that suffix. Forward the original generation mask from TransferQueue in the V1 trainer so the reward manager can apply the same rule there. The scorer continues seeing the complete trajectory.

Related to #8367. This does not duplicate #8368: that PR changes the two agent-loop score paths and explicitly excludes `RewardManagerBase.assemble_rm_scores`. This patch changes reward assembly and V1 colocated-RM input only. No estimator or agent-loop implementation changes.

### API and Usage Example

No new API or configuration. Existing `response_mask` is honored when available. Callers without the field, and rows with no generated tokens, retain the last valid-token placement.

### Design & Code Changes

- Select the greatest response index where both generation and attention masks are nonzero.
- Pass the stored generation mask through V1 colocated reward input, keeping attention derived from sequence lengths so scorer context is unchanged.
- Keep fallback placement and all estimator implementations unchanged.
- Document colocated reward placement in `docs/advance/reward_loop.rst`.

Token rejection sampling that masks tokens after reward assembly remains out of scope.
