# [trainer, reward, rollout] feat: add opt-in turn-level process rewards for v1

[Upstream PR](https://github.com/verl-project/verl/pull/8305) · state: open · merged: False

## Original PR description

### What does this PR do?

Add **opt-in turn-level process feedback** to the v1 TransferQueue trainer. Agents can provide `output.extra_fields["turn_rewards"]` directly, or configure task scorers when that field is absent. Process scores shape actor advantages after the existing outcome estimator; outcome rewards, GRPO normalization, and critic returns remain unchanged.

The default is disabled. This change includes Continuous Token turn-boundary tracking, typed configuration, public documentation, and CPU coverage of both the numerical rules and worker/trainer integration.

### API and Usage Example

```python
# Response coordinates; context/tool tokens are at positions 2 and 3.
output.extra_fields["generated_turn_spans"] = [(0, 2), (4, 6)]
output.extra_fields["turn_rewards"] = [-1.0, 0.5]
# process_scores becomes [-1, -1, 0, 0, 0.5, 0.5].
```

```yaml
trainer:
  use_v1: true
algorithm:
  process_reward:
    enabled: true
    mode: additive
    weight: 0.1
    scorers: []
```

When `turn_rewards` exists, each retained generated turn must have one finite scalar and configured scorer **evaluation** is skipped. Invalid direct feedback raises instead of silently falling back. Configured scorer classes are still instantiated at worker startup; `scorers: []` is sufficient for direct inputs.

Without `turn_rewards`, an optional `BaseProcessScorer.evaluate(output, span, context)` returns a finite scalar or per-token vector. Each scorer specifies a fully qualified class `path`, an optional `weight`, and constructor `kwargs`. Scorer weights combine task signals; the global process weight applies once during advantage shaping.

### Design & Code Changes

- **Scoring:** add `verl/trainer/ppo/process_reward.py` for boundary/input validation, direct turn-score broadcasting, scorer aggregation, and additive / GVPO-style / process-weighted actor-advantage shaping. The GVPO-style branch retains the existing estimator and policy loss; it is not presented as a full algorithm reproduction.
- **Agent contract:** document the reserved `turn_rewards` and optional `generated_turn_spans` fields. Mask fallback remains available for custom loops, but explicit spans distinguish adjacent generations.
- **Continuous Token integration:** ToolAgentLoop tracks spans across assistant/context merges, trims spans when a merge removes suffix tokens, excludes synthetic boundary tokens, and clips spans/rewards with final response truncation.
- **Worker/TQ:** score completed training trajectories only when enabled, retain zero process scores on context/padding, and transport process scores as an independent response-token field. Validation skips this path.
- **Trainer:** shape advantages only after normal estimation/rollout correction; preserve the outcome tensors and estimated returns. Add process-score and GVPO branch metrics, excluding rejected tokens.
- **Configuration/docs/tests:** add `ProcessRewardConfig`, disabled YAML defaults and regenerated reference configurations; add `docs/advance/process_rewards.rst` and link it from the Agent Loop page and documentation index. New tests use the existing `*_on_cpu.py` workflow discovery convention, so no workflow change is needed.

Task scorers own external-service timeout/retry/rate-limit policies and must distinguish action failures from infrastructure failures. The change does not infer success from tool text, ship a pretrained PRM, or automatically convert existing tool-return rewards into process scores.
