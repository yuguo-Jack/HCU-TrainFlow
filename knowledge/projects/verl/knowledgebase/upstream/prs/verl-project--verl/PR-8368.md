# [rollout, reward] fix: put the agent-loop score on the last generated token

[Upstream PR](https://github.com/verl-project/verl/pull/8368) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes #8367.

The agent loop puts the trajectory score on the last response token. A multi-turn trajectory can end with a chat-template suffix that has `response_mask = 0`. The SWE agent recipe does this: its trajectories end with `['```', '<|im_end|>', '\n']`, mask `[1, 1, 0]`. GAE, REINFORCE++, ReMax, OTB and TIR-OTB ignore rewards on mask-0 tokens, so with these estimators the outcome score never reaches the model. GRPO and RLOO sum the rewards without the mask and are not affected.

This PR puts the score on the last `response_mask = 1` token. The scorer still sees the full trajectory. The estimators do not change.

### API and Usage Example

No API change.

### Design & Code Changes

`verl/experimental/agent_loop/agent_loop.py`:

- `AgentLoopOutput.as_dict()`: put the score on the last nonzero position of `response_mask`. If there is none, keep `[-1]`.
- `AgentLoopWorker._postprocess()`: the same rule for the padded batch. If a row has no generated token, keep the last valid token.

Not changed:

- Token-level rejection sampling can set the mask of the final generated token to 0 after the score is placed. It needs a separate decision (see #8367), so this PR does not change it.
- `RewardManagerBase.assemble_rm_scores` (colocated reward model) places the score the same way. On the v1 trainer its input has no `response_mask`, so I left it for a follow-up.
