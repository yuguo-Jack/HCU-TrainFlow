# [reward] fix: copy extra_info per sample in reward loop managers

[Upstream PR](https://github.com/verl-project/verl/pull/8522) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes a race in the experimental reward loop. The rollouts of one prompt share a single `extra_info` dict: `DataProto.repeat` copies the object array by reference, and pickling the chunk for the `RewardLoopWorker` preserves the sharing. `RewardLoopWorker.compute_score_batch` runs `run_single` for all samples concurrently. Before their first `await`, the naive, limited and remote managers write per-rollout values into that dict: `num_turns`, `rollout_reward_scores` and `tool_extra_fields`. Every rollout of a prompt is therefore scored with the last rollout's values, and the writes leak back into the batch.

This affects `compute_rm_score` (the colocated reward-model path, `_compute_reward_colocate`). The agent-loop path pickles each sample separately and is not affected. The managers now copy `extra_info` before writing to it. `gdpo` writes only a run-constant `experiment_name`, so it is left unchanged.

### Test

Added `test_reward_loop_naive_keeps_extra_info_per_rollout` to `tests/workers/reward_manager/test_naive_on_cpu.py`. It repeats one prompt 4 times, round-trips it through pickle, gives rollout *i* `__num_turns__ = i`, and scores all four concurrently with a `compute_score` that returns `num_turns`.

- `main`: `[3.0, 3.0, 3.0, 3.0]` instead of `[0, 1, 2, 3]` (fails)
- this PR: passes; `pytest tests/workers/reward_manager/`: 19 passed

Added `test_extra_info_per_rollout` to `tests/experimental/reward_loop/test_rate_limited_reward_manager_on_cpu.py`. Four rollouts share one `extra_info` dict, and rollout *i* has `tool_extra_fields = {"turn": i}`. They are scored concurrently with an async `compute_score` that returns `extra_info["turn"]`. The test uses a stub tokenizer, so it does not need a model download.

- `main`: `[3.0, 3.0, 3.0, 3.0]` instead of `[0, 1, 2, 3]` (fails)
- this PR: passes, and the shared dict is unchanged

`RemoteRewardManager` gets the same one-line change. It has no test harness in `tests/` yet.

Added in 962ca493: `test_extra_info_per_rollout` in `tests/experimental/reward_loop/test_rate_limited_reward_manager_on_cpu.py`. `RateLimitedRewardManager` does not write `num_turns`.
