# [trainer] fix: rebuild 3D position_ids jagged layout to prevent split_with_sizes crash on equal-length batches

[Upstream PR](https://github.com/verl-project/verl/pull/7901) · state: open · merged: False

## Original PR description

Fixes #7899

### What does this PR do?

Makes 3D (mRoPE) `position_ids` batches layout-correct end to end:

1. **Write sites stop producing malformed layouts.** All sites that build jagged nested tensors from per-sample 2D mRoPE slices switch from `torch.nested.as_nested_tensor(...)` (which mis-takes the component dim as the jagged dim for equal-length inputs, producing ragged@1) to verl's own `nested_tensor_from_tensor_list(..., ragged_idx=2)` / explicit ragged@2 rebuilds. `serialize_tensordict` now records `_ragged_idx`, and `deserialize_tensordict` rebuilds with it instead of re-rolling `as_nested_tensor` (older 2-tuple and strided encodings keep the original `as_nested_tensor` path unchanged).
2. **The blind workaround is replaced by a validating normalize.** `maybe_fix_3d_position_ids()` previously set `_ragged_idx = 2` unconditionally — correct by luck for variable-length batches, but for equal-length (or `batch_size == 1`) batches it turns a malformed-but-self-consistent ragged@1 tensor into an inconsistent one that crashes at the next `unbind()`. It now forwards to a new `normalize_3d_position_ids()` that:
   - passes canonical input through unchanged (zero cost, idempotent);
   - recognizes the two non-canonical states by **layout signature** (values/offsets shape relationships — component-count agnostic, no `C in (3, 4)` hardcode, so mRoPE variants with 5–8 components also work): coordinate-packed equal-length quirk output, and sequence-packed tensors whose ragged metadata was reset by serialization;
   - rebuilds them into canonical ragged@2 and resolves the square corner (`values.shape[0] == values.shape[1]`) with a `_MAX_PLAUSIBLE_COMPONENTS = 8` tie-break;
   - leaves unknown layouts alone — the fail-fast guard below reports them loudly instead of guessing.
3. **Fail-fast instead of cryptic crashes.** `index_select_tensor_dict()` validates `sum(lengths) == values.shape[ragged_idx - 1]` before `unbind()` and reports key name / ragged_idx / sums / offsets step when inconsistent; `concat_nested_tensors()` rejects mixed `_ragged_idx` inputs instead of silently using the first tensor's tag.

No caller changes: `maybe_fix_3d_position_ids()` keeps its name and signature, so `engine/base.py`, `engine_workers.py`, `engine_workers_tinker.py` call sites are untouched.

### Why this is still needed with TransferQueue enabled by default

#7767 (closed) was closed on the rationale that TQ no longer consolidates/pickles TensorDict. That removes only the *serialization* door. The equal-length quirk fires **at the write sites themselves** — `left_right_2_no_padding()` and `restore_dynamic_batch()` build the nested tensor directly in verl code, and TQ faithfully preserves whatever layout it receives — so the malformed ragged@1 layout reaches training unchanged. #6851 (all batch sizes = 1, deterministic trigger, traceback through `transferqueue_utils.py`) is another report of the same crash — multiple users have hit it. This PR closes the write-side doors and makes the consumer side defensive rather than blindly re-tagging.

### Implementation (file by file)

| File | Change |
|---|---|
| `verl/workers/utils/padding.py` | `left_right_2_no_padding()`: rebuild 3D `position_ids` via `nested_tensor_from_tensor_list(..., ragged_idx=2)` (same approach as the SFT collator fix in #5689) |
| `verl/utils/seqlen_balancing.py` | `restore_dynamic_batch()`: rebuild preserving the source tensor's `_ragged_idx` instead of `as_nested_tensor` |
| `verl/protocol.py` | `serialize_tensordict()`: encode `_ragged_idx` alongside layout; `deserialize_tensordict()`: rebuild jagged payloads with the recorded `_ragged_idx`; legacy 2-tuple and strided encodings keep the original `as_nested_tensor` path (exact backward compatibility — they may carry layouts the explicit builder cannot express, e.g. dim-0-varying 2D samples) |
| `verl/utils/tensordict_utils.py` | new `normalize_3d_position_ids()` (+ private signature helpers); `maybe_fix_3d_position_ids()` forwards to it; `index_select_tensor_dict()` calls `assert_nested_layout_consistency()` before `unbind()`; `concat_nested_tensors()` rejects mixed `_ragged_idx` |

### Test plan

- New CPU test file `tests/utils/test_nested_position_ids_layout_on_cpu.py` — **8 red-green cases** (runs anywhere, no accelerators; all eight FAIL on unfixed master, all eight PASS with the fix):
  1. real-scale equal-length quirk end to end (128 × `(4, 34135)`, `maybe_fix` + `index_select`; master crashes with the exact `split_with_sizes` signature);
  2. square corner `values=(32,32)` (master silently returns transposed `(L, C)` chunks — wrong data, no crash);
  3. blind-retagged legacy layout end to end;
  4. `index_select` on an inconsistent layout raises an actionable error (key / ragged_idx / sums) instead of the raw `split_with_sizes` message;
  5. `concat_nested_tensors` rejects mixed `ragged_idx` inputs (master silently rebuilds with the first tensor's tag);
  6. `serialize` → `deserialize` → `maybe_fix` → `index_select` round trip on an equal-length canonical batch (master re-rolls the quirk in `deserialize` and crashes);
  7. component-count-agnostic repair (sequence-packed stale metadata, C=6);
  8. canonical passthrough is idempotent and zero-cost (variable-length and single-sample square).
- No existing test changes: master's CPU suites for protocol / padding / seqlen-balancing stay green with the patch (87 tests run green locally, torch 2.13.0).
- Fix behavior verified on torch 2.13.0 (CPU); the original quirk occurrence was torch 2.9 in training.

Confirming this from an independent reproduction, and +1 for the `normalize_3d_position_ids` direction over the old `data["position_ids"]._ragged_idx = 2` blind flip.

**Setup:** Qwen3.5-4B, GRPO, verl/Agent-R1, PyTorch 2.11.0+cu129, TensorDict 0.10.0, single prompt with `rollout.n=8`.

**Symptom matches #7899 exactly** — crash happens *after* rollout completes, at mini-batch selection inside the actor update:

```
RuntimeError: split_with_sizes expects split_sizes to sum exactly to 16561
(input tensor's size at dimension 1), but got split_sizes=[4, 4, 4, 4, 4, 4, 4, 4]
```

The `4`s are the mRoPE component axis, not the response length — consistent with the root-cause analysis here.

**Two observations that support this PR specifically:**

1. **It is not a group-size problem.** With `rollout.n=4` the same run reproduces with `split_sizes=[4, 4, 4, 4]`. So lowering `n` is not a workaround; the trigger is the equal-length mRoPE `[B, C, L]` batch where the component axis gets picked as the jagged axis after consolidate/pickle.

2. **Idempotency matters, and this PR handles it.** `maybe_fix_3d_position_ids` is called on *both* the full batch and each rebuilt mini-batch (`engine_workers.py` L252 and L290). A first attempt at fixing this only repacked the malformed `[B*C, L]` values and, on the *second* call, mistook the already-correct `[C, sum(L)]` layout for invalid input and raised `Invalid mRoPE position_ids values shape: torch.Size([4, 66184]), batch_num=8`. The canonical-passthrough path + `test_8_canonical_passthrough_idempotent` here is what actually closes that gap — a rebuild-only fix would have shipped a half-working patch.

**CPU-only minimal reproducer** (torch 2.10, no weights) that crashes pre-fix and is stable after the rebuild:

```python
B, C, L = 4, 4, 5
parts = [torch.arange(C * L, dtype=torch.float32).reshape(C, L) + i * 1000 for i in range(B)]
values = torch.stack(parts).reshape(B * C, L)
offsets = torch.arange(0, B * C + 1, C)
nt = torch.nested.nested_tensor_from_jagged(values, offsets=offsets)
nt._ragged_idx = 2          # simulates the post-pickle metadata/value mismatch
list(nt.unbind())           # -> crash; rebuild on the sequence axis fixes it and is idempotent
```

**On-model result:** applying the layout rebuild (same idea as `normalize_3d_position_ids`) let the full `n=8` actor update proceed — training reached `global_step:12` with a non-zero training signal (step 10: reward mean 0.125, actor loss 0.0785, grad_norm 0.131) and `split_with_sizes` errors = 0. This is related to the upstream jagged high-dim `unbind` behavior tracked in pytorch/pytorch#153238.

LGTM from the reproduction side. One small ask if it fits scope: since the source-side write-site fixes here plus `assert_nested_layout_consistency` now cover the malformed-layout path, a note in the deprecated `maybe_fix_3d_position_ids` docstring steering new callers to `normalize_3d_position_ids` (already present) would help avoid reintroducing the blind-flip in downstream forks.
