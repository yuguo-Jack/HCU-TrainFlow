This pull request updates the loss normalization logic to correctly handle gradient accumulation. It introduces a `mini_batch_full_token_count` parameter to normalize the token-level loss by the total number of tokens in a mini-batch, rather than a micro-batch. The changes are logically sound and address an important aspect of distributed training.

My review includes feedback on a type hint correction and a significant performance improvement by avoiding redundant data iteration in `dp_actor.py` and `dp_critic.py`. Addressing these points will improve code quality and efficiency.

The type hint for `mini_batch_full_token_count` is `int` but the default value is `None`. This is incorrect and will be flagged by type checkers. For consistency with the `agg_loss` function and for correctness, it should be `int | None = None`.

```suggestion
    mini_batch_full_token_count: int | None = None,
```

- gemini-code-assist[bot] · comment · 2025-10-22T13:59:34Z · [source](https://github.com/verl-project/verl/pull/3863#discussion_r2452207598)

File: `verl/workers/actor/dp_actor.py` · line 409

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

This loop iterates over `micro_batches` just to calculate `mini_batch_full_token_count`. This is inefficient as it requires an extra pass over the data before the main training loop. You can compute this value more efficiently from the `mini_batch` object before it's split into `micro_batches`. The total token count is simply `mini_batch.batch["response_mask"].sum().item()`. This avoids iterating through all the micro-batches twice. You could calculate it once per mini-batch and remove this loop.
