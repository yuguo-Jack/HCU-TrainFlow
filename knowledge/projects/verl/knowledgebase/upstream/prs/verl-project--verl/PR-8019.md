# [ckpt] feat: configure Hugging Face export dtype

[Upstream PR](https://github.com/verl-project/verl/pull/8019) · state: closed · merged: False

## Original PR description

### What does this PR do?

Evaluation and serving usually need BF16 Hugging Face weights, not FSDP's full FP32 master weights. Today users must save verl checkpoint shards and run the [offline FSDP merger](https://github.com/verl-project/verl/blob/main/verl/model_merger/fsdp_model_merger.py#L53-L83), which consumes verl checkpoint shards rather than an already exported HF safetensors model. This PR adds `hf_export_dtype` (`bf16`, `fp16`, or `fp32`) to cast only the HF export before [`save_pretrained`](https://github.com/huggingface/transformers/blob/main/src/transformers/modeling_utils.py#L3235-L3248); `null` preserves current behavior.

Related to #296. This does not duplicate #7997: that PR forwards Transformers `save_pretrained` kwargs, but Transformers has no save-time dtype conversion argument. Open-PR searches for `hf_export_dtype`, `export checkpoint dtype`, and #296 found no PR implementing export-only dtype conversion.

Fixes one part of https://github.com/verl-project/verl/issues/8027

### API and Usage Example

```bash
# PPO actor with FSDP or VeOmni
actor_rollout_ref.actor.checkpoint.hf_export_dtype=bf16

# SFT with engine=fsdp or engine=veomni
checkpoint.hf_export_dtype=bf16
```

### Test

Six 8-GPU training runs with `Qwen/Qwen3-8B` verified `hf_export_dtype=null` and `hf_export_dtype=bf16` across FSDP actor, SFT, and VeOmni actor. Each run used FP32 model initialization and master parameters, BF16 mixed-precision compute, and one training step. Every export contained the expected `8,190,735,360` parameters and reloaded through Transformers:

| Path | Default | `bf16` | HF reload |
|---|---|---|---|
| FSDP actor | FP32, 1 file | BF16, 1 file | Passed |
| SFT | FP32, 1 file | BF16, 1 file | Passed |
| VeOmni actor | FP32, 1 file | BF16, 1 file | Passed |
