# [ckpt] feat: delta_sharded gather_round_megabytes

[Upstream PR](https://github.com/verl-project/verl/pull/7778) · state: open · merged: False

## Original PR description

### What does this PR do?

The per-rank byte budget of one gather round in the delta_sharded steady sync (sparse_gather max_round_bytes, which bounds what rank 0 receives per round) was hard-wired to bucket_size, the flush size shipped to the rollout. The two pull in opposite directions: the flush bucket wants to be large (fewer update_weights requests), the gather round has to fit rank 0's GPU headroom. With 512 MB buckets on a 480-rank Megatron trainer (PP>1 merges every param over WORLD) a single round could need tens of GB on rank 0.

Add engine kwarg gather_round_megabytes (engine_kwargs.delta_sharded. gather_round_megabytes in the rollout config); None keeps the old coupling.
