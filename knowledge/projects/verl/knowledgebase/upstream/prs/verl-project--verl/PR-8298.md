# [ci] fix: change gsm8k datasets paths in Ascend jobs

[Upstream PR](https://github.com/verl-project/verl/pull/8298) · state: closed · merged: True

## Original PR description

### What does this PR do?

Fix the GSM8K source directory in the three Ascend workflows that failed during dataset preprocessing on #8251. They currently pass `${HOME}/.cache/datasets/openai/gsm8k`, which resolves to `/root/.cache/datasets/openai/gsm8k` and raises `FileNotFoundError`.

Use the proposed runner cache path `/root/.cache/modelscope/dataset/openai/gsm8k` so the existing preprocessing steps can validate it on the NPU runners.

Affected failures:

- [e2e_ascend / LLM RL job](https://github.com/verl-project/verl/actions/runs/39397448201/job/118545925791)
- [e2e_ppo_trainer_megatron_vllm_2_ascend / FSDP vLLM job](https://github.com/verl-project/verl/actions/runs/39397448240/job/118545929465)
- [vllm_ascend](https://github.com/verl-project/verl/actions/runs/39397448294/job/118545936815)

This is a functional fix for three blocked CI jobs. Duplicate checks covered #8251's discussion and open PR searches for `8251 in:body`, `gsm8k ascend`, and `modelscope`; no open PR addressing this dataset-path failure was found. #8251 changes FSDP-Turbo and vLLM model handling and does not fix these workflow paths.

This change was prepared with AI assistance. NPU CI validation is pending.
