# [ckpt] fix: use PyTorch NCCL process group

[Upstream PR](https://github.com/verl-project/verl/pull/8496) · state: closed · merged: False

## Original PR description

### What does this PR do?

Replaces the NCCL checkpoint engine's Ray collective group and CuPy master buffers with a dedicated PyTorch `ProcessGroupNCCL` backed by `TCPStore`. This lets the engine use the NCCL-compatible communication backend exposed through PyTorch on special accelerator devices where CuPy does not expose NCCL, while preserving the existing rank topology, metadata transport, and bucket protocol.

This does not duplicate an existing PR. ### API and Usage Example

No consumer API changes. Existing configurations continue to select `checkpoint_engine.backend=nccl`; the engine now creates and owns its PyTorch NCCL process group internally.

### Design & Code Changes

- Allocate both sender and receiver buckets as CUDA `torch.Tensor` objects.
- Publish a separate `TCPStore` port with the existing ZeroMQ metadata endpoint.
- Construct a dedicated `ProcessGroupNCCL`, bind it to the actor's visible device, and wait for broadcast and barrier work handles.
- Abort and clear the owned process group when `rebuild_group` is enabled.
- Remove this engine from the CuPy dependency rationale; NIXL, delta-sharded, and Megatron still require CuPy.
