# [trainer] fix: align V1 rollout diagnostics with token availability

[Upstream PR](https://github.com/verl-project/verl/pull/8528) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes #8504. With multiple local updates per parameter synchronization, an empty-response batch can contaminate rollout diagnostics with a placeholder NaN, while the final batch's validity flag can hide an earlier available nonfinite measurement.

Exclude unavailable values and their weights from the six guarded diagnostics, reduce availability across the window, and preserve all-unavailable NaNs and available NaN/Inf values. For example, available means .01, .02, and .04 interspersed with an empty batch now aggregate to .0233333 with valid=1. An available NaN followed by an empty batch remains NaN with valid=1.

### API and Usage Example

No new API or configuration. Existing per-update statistics retain their reduction semantics; the change does not calculate pooled token statistics or alter the loss or gradients.

### Design & Code Changes

- Filter the explicitly guarded diagnostics while each update's availability, values, and weights are still paired. Retain emitted keys for an all-unavailable window without retaining unavailable values or weights.
- Reduce the 0/1 availability flag using `max`, and explicitly propagate retained NaNs in the two guarded maxima to avoid Python `max`'s order dependence.
- Preserve sample weighting, zero-total-weight fallback, metric absence, unrelated metrics, mismatch-count summation, and reset behavior.
- Extend existing CPU aggregator and trainer-base suites. Both are selected by `cpu_unit_tests.yml` through the `*_on_cpu.py` naming rule; no workflow change is needed.
- Document all changed functions, including aggregation contracts and the focused integration test's worker boundary.
