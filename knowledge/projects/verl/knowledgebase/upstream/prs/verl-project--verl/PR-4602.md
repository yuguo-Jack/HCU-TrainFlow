## Code Review

This pull request introduces a `checkpoint_engine` to handle weight synchronization in hybrid mode, with changes across FSDP and Megatron workers, as well as vLLM and SGLang rollouts. The implementation adds new configuration flags and logic to conditionally use this new engine.

My review has identified a few critical issues:
1.  A potential bug in `fsdp_workers.py` where incorrect weights might be updated due to a variable mix-up. This is coupled with significant code duplication that should be refactored.
2.  Unsafe access to environment variables in `vllm_rollout.py` which could lead to worker crashes if the environment is not perfectly configured.

I've provided code suggestions to address these critical issues for improved correctness and robustness.

There's a potential critical bug and significant code duplication here.

**1. Potential Bug (Critical):**
On line 747, `update_weighs_by_checkpoint_engine` is called with `per_tensor_param`. However, this block is for updating the base model weights, and the `else` branch correctly uses `per_tensor_base_params`. This will cause the wrong weights to be updated when the checkpoint engine is enabled.

**2. Code Duplication (High):**
The logic for choosing the weight update method is duplicated for the base model update (lines 745-749) and the main parameter update (lines 752-756). This reduces maintainability and makes the code prone to errors like the one mentioned above.

I've provided a suggestion that fixes the critical bug. I also recommend refactoring this logic into a helper function to eliminate the duplication entirely.

```suggestion
            if self.config.rollout.enable_checkpoint_engine:
                req_func = await self.rollout.checkpoint_engine_req_func(self.infer_world_size)
                self.update_weighs_by_checkpoint_engine(per_tensor_base_params, req_func)
            else:
                await self.rollout.update_weights(per_tensor_base_params, base_sync_done=False)
            del base_model_params, per_tensor_base_params
        
        if self.config.rollout.enable_checkpoint_engine:

        else:
            await self.rollout.update_weights(per_tensor_param, peft_config=peft_config, base_sync_done=self.base_sync_done)
```

Accessing environment variables using `os.environ["KEY"]` is unsafe as it will raise a `KeyError` if the variable is not set, causing the worker to crash. It's much safer to use `os.getenv("KEY", default_value)`.

This is a critical issue that can lead to runtime crashes if the environment is not perfectly configured.

```suggestion
        rank = int(os.getenv("RANK", "0"))
        local_world_size = int(os.getenv("RAY_LOCAL_WORLD_SIZE", "1"))
```

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

Calling `int(os.getenv("RANK", None))` will raise a `TypeError` if the `RANK` environment variable is not set, because `os.getenv` will return `None` and `int(None)` is invalid. This will cause the worker to crash.

To make this more robust, please provide a default string value to `os.getenv`.

```suggestion
        rank = int(os.getenv("RANK", "0"))
```
