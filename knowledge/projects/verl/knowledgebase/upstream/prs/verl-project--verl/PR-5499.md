## Original PR description

### What does this PR do?
This PR adds **SDPO (Self-Distillation Policy Optimization)** as a new policy loss mode in verl, enabled via:
- `actor_rollout_ref.actor.policy_loss.loss_mode=sdpo`

Key points:
- Adds `SelfDistillationConfig` under `actor_rollout_ref.actor.self_distillation` (disabled by default unless `loss_mode=sdpo`).
- Trainer constructs SDPO “reprompted teacher context” inputs + masks and passes them through the training batch.
- Actor update computes SDPO self-distillation loss (full-logit or top-k(+tail) distillation, optional IS clipping).
- Adds an example config (`verl/trainer/config/sdpo.yaml`) and SDPO documentation.
- No behavior change for existing algorithms/configs unless `loss_mode=sdpo` is selected.

Reference implementation / upstream: https://github.com/lasgroup/SDPO

The open PR implementing on-policy distillation is vaguely related: https://github.com/verl-project/verl/pull/4897

- gemini-code-assist[bot] · comment · 2026-03-05T10:05:29Z · [source](https://github.com/verl-project/verl/pull/5499#discussion_r2888981746)

File: `verl/trainer/ppo/core_algos.py` · line 1201

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

The implementation of the distillation loss for the non-full-logit case appears to be incorrect for optimizing reverse KL divergence. Using `.detach()` on `log_ratio` prevents gradients from flowing through it, turning it into a constant for the backward pass. The standard score function estimator for reverse KL, `D_KL(student || teacher)`, requires the gradient to be computed with respect to the `(log π_student - log π_teacher)` term as well. This implementation effectively uses a fixed 'advantage' based on the log-ratio at the beginning of the step, which is not standard and likely cripples the gradient signal, potentially leading to incorrect or unstable training. The `.detach()` should be removed to allow for proper gradient flow.

```suggestion
        log_ratio = student_log_probs - teacher_log_probs
        per_token_loss = log_ratio * student_log_probs
```

- gemini-code-assist[bot] · comment · 2026-03-05T10:05:29Z · [source](https://github.com/verl-project/verl/pull/5499#discussion_r2888981753)

File: `verl/trainer/ppo/ray_trainer.py` · line 651

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The manual creation of `teacher_prompt_attention_mask` when `teacher_prompt` is a tensor has a risky fallback for `pad_token_id`. If `self.tokenizer.pad_token_id` is `None`, it defaults to `0`. This can lead to incorrect masking if `0` is a valid token ID in the vocabulary. While `apply_chat_template` with `return_dict=True` should prevent this branch from being taken, this constitutes a latent bug. It would be safer to raise an error if `pad_token_id` is not available, ensuring robust handling of all tokenizer configurations.

```suggestion
            if self.tokenizer.pad_token_id is None:
                raise ValueError("Tokenizer must have a pad_token_id set for manual attention mask creation.")
            pad_token_id = self.tokenizer.pad_token_id
            teacher_prompt_attention_mask = (teacher_prompt_input_ids != pad_token_id).to(dtype=torch.long)
```
