# [reward] fix: read APPS/TACO call-based tests in prime_code

[Upstream PR](https://github.com/verl-project/verl/pull/8175) · state: open · merged: False

## Original PR description

### What does this PR do?

Fixes #8174. Two bugs in `prime_code` made call-based (function-call) tasks score 0 when they shouldn't:

1. **Correct solutions scored 0 on APPS/TACO data** (`testing_util.py`). The call-based path only parsed LiveCodeBench-style tests, where each input is a string of JSON lines. APPS and TACO publish call-based tests with each input as a list of arguments, so every such task raised before running a test. Now a string input is parsed as before, and a list input is used directly as the arguments with the output as given.
2. **Partially correct solutions scored 0 under `continuous=True`** (`__init__.py`, reported in #8182 by @zhongerdeajie). The per-test loop rebuilt each test without `fn_name`, so `run_test` graded call-based tasks as standard input and every per-test run failed. Now `fn_name` is carried into each rebuilt test. This one affects both layouts.

Confirmed — this finding is real, and I checked it against the upstream code: the `isinstance(inputs[0], dict)` normalization (the block whose own comment says "(assuming a singleton list)") replaces the entire argument list with just its first element re-keyed. For a call like `method({"a": 1}, 2)` — a dict first argument followed by more arguments — `method(*inputs)` then raises `TypeError` from the missing argument. The string layout has carried this for a while; the list-layout path in this PR makes it equally reachable, so it's worth fixing while the file is open.

One-line fix that keeps the int-key normalization and preserves the remaining arguments:

```python
if isinstance(inputs[0], dict):
    inputs = [{int(k): v for k, v in inputs[0].items()}] + inputs[1:]
```

Happy to follow up with a small test (a two-argument call whose first argument is a dict) if useful.
