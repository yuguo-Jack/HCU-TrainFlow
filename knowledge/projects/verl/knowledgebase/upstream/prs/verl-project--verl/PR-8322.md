<h1>v0.31.0</h1>
<h2>Highlights</h2>
<p>This release features 717 commits from 307 contributors (96 new)!</p>
<ul>
<li><strong>DeepSeek-V4.1-Flash performance</strong>: FlashMLA mega attention with the V4.1 NVFP4 compressed KV cache is now the SM100 default (<a href="https://redirect.github.com/vllm-project/vllm/issues/56935">#56935</a>); DeepGEMM sparse MQA logits for the indexer (<a href="https://redirect.github.com/vllm-project/vllm/issues/56254">#56254</a>) and Mega-Gate fusing the gate GEMM with expert selection (<a href="https://redirect.github.com/vllm-project/vllm/issues/56266">#56266</a>); decoder boundaries fuse the TP all-reduce, mHC input preparation (<a href="https://redirect.github.com/vllm-project/vllm/issues/57643">#57643</a>) and the MoE finalize (<a href="https://redirect.github.com/vllm-project/vllm/issues/58586">#58586</a>); a fused small-batch WO-A with inverse RoPE and MXFP8 quant on SM100/SM103 (<a href="https://redirect.github.com/vllm-project/vllm/issues/58634">#58634</a>); the MXFP8 <code>wo_b</code> GEMM fused with the sequence-parallel reduce-scatter (<a href="https://redirect.github.com/vllm-project/vllm/issues/57428">#57428</a>); Engram <code>wkv</code> sharded across TP ranks (<a href="https://redirect.github.com/vllm-project/vllm/issues/58678">#58678</a>) and Engram host tables shared across co-located DP replicas by default (<a href="https://redirect.github.com/vllm-project/vllm/issues/57651">#57651</a>); encoder CUDA graphs for the vision tower (<a href="https://redirect.github.com/vllm-project/vllm/issues/56625">#56625</a>); and SWA bounded replay that keeps the sliding-window KV out of prefix caching (<a href="https://redirect.github.com/vllm-project/vllm/issues/56227">#56227</a>).</li>
<li><strong>Fast restart</strong>: the new <code>vllm preload</code> CLI launches the weight-cache daemon that keeps post-quantized weights resident in GPU memory across engine restarts (<a href="https://redirect.github.com/vllm-project/vllm/issues/56680">#56680</a>), now with data parallelism (<a href="https://redirect.github.com/vllm-project/vllm/issues/57386">#57386</a>), MTP draft models (<a href="https://redirect.github.com/vllm-project/vllm/issues/57312">#57312</a>), a <code>/health</code> endpoint (<a href="https://redirect.github.com/vllm-project/vllm/issues/58552">#58552</a>) and a readiness wait (<a href="https://redirect.github.com/vllm-project/vllm/issues/58370">#58370</a>). Experimental initialized-engine snapshots (<code>vllm snapshot create/restore</code>) use CRIU to restore a fully initialized TP1 engine (<a href="https://redirect.github.com/vllm-project/vllm/issues/51360">#51360</a>).</li>
<li><strong>Model Runner V2 and speculative decoding</strong>: draft-model speculative decoding (<a href="https://redirect.github.com/vllm-project/vllm/issues/43091">#43091</a>) and custom logits processors (<a href="https://redirect.github.com/vllm-project/vllm/issues/56497">#56497</a>) on Model Runner V2; the new LiLiCorr drafter (<a href="https://redirect.github.com/vllm-project/vllm/issues/57934">#57934</a>); async scheduling for DFlash (<a href="https://redirect.github.com/vllm-project/vllm/issues/58065">#58065</a>) with the context K/V precompute captured in the draft CUDA graph (<a href="https://redirect.github.com/vllm-project/vllm/issues/57632">#57632</a>); DSpark adaptive verification for Gemma4 (<a href="https://redirect.github.com/vllm-project/vllm/issues/57263">#57263</a>) and variable-length decode for Kimi-K3 (<a href="https://redirect.github.com/vllm-project/vllm/issues/52988">#52988</a>); a DCP target with a non-DCP DSpark draft (<a href="https://redirect.github.com/vllm-project/vllm/issues/56723">#56723</a>); and MoE memory now counted during MRV2 profiling, avoiding OOMs on WideEP deployments (<a href="https://redirect.github.com/vllm-project/vllm/issues/57270">#57270</a>, <a href="https://redirect.github.com/vllm-project/vllm/issues/58411">#58411</a>).</li>
<li><strong>Large scale serving</strong>: MoonEP balanced EP all2all backend via <code>--all2all-backend moonep</code> (<a href="https://redirect.github.com/vllm-project/vllm/issues/52101">#52101</a>), prefill context parallelism with data parallelism (<a href="https://redirect.github.com/vllm-project/vllm/issues/57075">#57075</a>), a low-SM multimem reduce-scatter for SM100/SM103 (<a href="https://redirect.github.com/vllm-project/vllm/issues/55072">#55072</a>), DeepEPv2 with sequence parallelism (<a href="https://redirect.github.com/vllm-project/vllm/issues/57210">#57210</a>) and EPLB with shared-expert overlap (<a href="https://redirect.github.com/vllm-project/vllm/issues/57236">#57236</a>), a sharding-aware NCCL M2N weight-transfer backend for RL (<a href="https://redirect.github.com/vllm-project/vllm/issues/51520">#51520</a>), and KV offloading back-pressure detection (<a href="https://redirect.github.com/vllm-project/vllm/issues/50045">#50045</a>).</li>
<li><strong>Scheduling controls</strong>: <code>--max-num-active-seqs</code> caps RUNNING admission independently of <code>max_num_seqs</code> (<a href="https://redirect.github.com/vllm-project/vllm/issues/56758">#56758</a>), <code>--long-prefill-token-threshold</code> now adapts to the number of waiting prefills instead of chunking a lone request (<a href="https://redirect.github.com/vllm-project/vllm/issues/57951">#57951</a>, <a href="https://redirect.github.com/vllm-project/vllm/issues/58459">#58459</a>), the waiting queue was reworked so requests already holding KV blocks are scheduled first (<a href="https://redirect.github.com/vllm-project/vllm/issues/58947">#58947</a>), and the KV connector + MTP deadlock under KV pressure was fixed (<a href="https://redirect.github.com/vllm-project/vllm/issues/57104">#57104</a>).</li>
<li><strong>HiSparse hardening</strong>: MTP verification rows resolved with a union residency kernel (<a href="https://redirect.github.com/vllm-project/vllm/issues/59235">#59235</a>), MTP acceptance collapse under FULL graphs fixed (<a href="https://redirect.github.com/vllm-project/vllm/issues/59309">#59309</a>), no GPU pages without host backing (<a href="https://redirect.github.com/vllm-project/vllm/issues/59036">#59036</a>), a chunked-prefill preemption livelock fixed (<a href="https://redirect.github.com/vllm-project/vllm/issues/59494">#59494</a>), KV cache sized from the groups HiSparse allocates (<a href="https://redirect.github.com/vllm-project/vllm/issues/59450">#59450</a>), and host prefix publication and GPU prefix adoption fixes (<a href="https://redirect.github.com/vllm-project/vllm/issues/59007">#59007</a>, <a href="https://redirect.github.com/vllm-project/vllm/issues/59282">#59282</a>).</li>
<li><strong>Security</strong>: per-request <code>mm_processor_kwargs</code> and <code>media_io_kwargs</code> are rejected unless <code>--trust-request-mm-kwargs</code> is set (<a href="https://redirect.github.com/vllm-project/vllm/issues/58830">#58830</a>); prefix-cache extra keys are tagged by source so a LoRA name and a <code>cache_salt</code> can no longer collide (<a href="https://redirect.github.com/vllm-project/vllm/issues/51899">#51899</a>), and the LoRA path is part of the block hash (<a href="https://redirect.github.com/vllm-project/vllm/issues/59335">#59335</a>); stale multimodal receiver-cache entries can no longer replace fresh payloads (<a href="https://redirect.github.com/vllm-project/vllm/issues/57833">#57833</a>).</li>
<li><strong>Breaking changes</strong>: per-request multimodal kwargs gated (<a href="https://redirect.github.com/vllm-project/vllm/issues/58830">#58830</a>); <code>tokenizer_mode=&quot;slow&quot;</code> removed (<a href="https://redirect.github.com/vllm-project/vllm/issues/58545">#58545</a>); <code>--enable-mamba-fine-grained-prefix-cache</code> renamed to <code>--enable-mamba-shared-prefix-checkpoint</code> (<a href="https://redirect.github.com/vllm-project/vllm/issues/57382">#57382</a>); online quantization through <code>quantization=&quot;fp8&quot;</code> replaced by the <code>fp8_per_tensor</code> shorthand (<a href="https://redirect.github.com/vllm-project/vllm/issues/53585">#53585</a>) and Quark silent online quantization removed (<a href="https://redirect.github.com/vllm-project/vllm/issues/51800">#51800</a>); the AllSpark INT8 W8A16 backend removed (<a href="https://redirect.github.com/vllm-project/vllm/issues/58001">#58001</a>); <code>--enforce-eager</code> now also disables JIT kernel warmup (<a href="https://redirect.github.com/vllm-project/vllm/issues/58197">#58197</a>); XPU graphs enabled by default with <code>VLLM_XPU_ENABLE_XPU_GRAPH</code> removed (<a href="https://redirect.github.com/vllm-project/vllm/issues/51600">#51600</a>).</li>
</ul>
