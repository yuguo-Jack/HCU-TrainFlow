# Integration Agentbay Cloud Sanbox

[Upstream PR](https://github.com/verl-project/verl/pull/5470) · state: open · merged: False

## Original PR description

## Summary

Add AgentBay as a cloud sandbox backend for code execution during multi-turn RL training.
[AgentBay](https://agentbay.console.aliyun.com) is a secure cloud sandbox service provided
by Alibaba Cloud Wuying, enabling LLMs to execute code in isolated environments during
RL rollouts.

### Changes

- **`verl/tools/agentbay_tool.py`**: `AgentBayTool` implementation extending `BaseTool`,
  with async session management (create/execute/release) backed by `wuying-agentbay-sdk`.
  SDK import is lazy-loaded so it's only required when AgentBay is configured.

- **`examples/sglang_multiturn/config/tool_config/agentbay_tool_config.yaml`**: Tool
  configuration defining the `code_interpreter` function schema for multi-turn rollout.

- **`examples/data_preprocess/gsm8k_agentbay.py`**: GSM8K data preprocessing script
  that formats prompts for code-interpreter style tool use.

- **`examples/sglang_multiturn/run_qwen0.5b_gsm8k_agentbay_1gpu.sh`**: Minimal
  single-GPU training script (Qwen2.5-0.5B + GRPO) for end-to-end pipeline verification.

- **`docs/examples/agentbay_example.rst`**: Documentation covering prerequisites
  (SDK install, API key), configuration, and quick start guide.

## How it works
Prompt → Model generates code → code_interpreter tool call
→ AgentBay cloud sandbox executes code → returns output
→ Model reads result → outputs final answer (#### format)
→ Rule-based reward (GSM8K) → GRPO policy update

## Dependencies

- Optional: `pip install wuying-agentbay-sdk` (only needed when using AgentBay tool)
- API key from [AgentBay Console](https://agentbay.console.aliyun.com/service-management),
  set via `AGENTBAY_API_KEY` environment variable

## Test plan

- [ ] Run data preprocessing: `python examples/data_preprocess/gsm8k_agentbay.py`

- [ ] Verify end-to-end: model generates tool calls → AgentBay executes → rewards computed → training step completes

## Code Review

This pull request integrates `AgentBay` as a cloud sandbox backend, introducing a new `AgentBayTool`, example configurations, a data preprocessing script, a run script, and documentation. While the overall implementation is well-structured, a high-severity command injection vulnerability was identified in the `GSM8K` data preprocessing script. This issue arises from the script's use of a utility function that executes shell commands via string concatenation of unsanitized command-line arguments. It is strongly recommended to sanitize inputs or update the underlying utility to use safer command execution methods, such as `subprocess.run` with argument lists. Furthermore, there are opportunities to improve the robustness of the data preprocessing script and the `AgentBayTool` implementation.

![security-high](https://www.gstatic.com/codereviewagent/security-high-priority.svg) ![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The script uses `makedirs` and `copy` from `verl.utils.hdfs_io` with the `args.hdfs_dir` argument, which is directly sourced from command-line input. The `verl.utils.hdfs_io` module implements these functions using `os.system()` by concatenating the path into a shell command string without any sanitization or escaping. An attacker who can control the `--hdfs_dir` argument can execute arbitrary shell commands on the system. For example, providing `--hdfs_dir "hdfs://path; touch /tmp/pwned"` would result in the execution of `touch /tmp/pwned`.

- gemini-code-assist[bot] · comment · 2026-03-03T09:47:00Z · [source](https://github.com/verl-project/verl/pull/5470#discussion_r2877226664)

File: `examples/data_preprocess/gsm8k_agentbay.py` · line 51

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The `extract_solution` function uses `assert solution is not None`, which will raise an `AssertionError` without a descriptive message if the expected pattern is not found. This can make debugging difficult. Additionally, it uses `solution.group(0)` and string splitting, which is less direct than using `solution.group(1)`.

It's better to handle the case where the pattern is not found by raising a `ValueError` with an informative message and to use `group(1)` for cleaner code. The regex can also be slightly improved for readability.

```suggestion
    solution_match = re.search(r"####\s+(-?[\d.,]+)", solution_str)
    if not solution_match:
        raise ValueError(f"Solution format '#### <number>' not found in: {solution_str}")
    return solution_match.group(1).replace(",", "")
```

- gemini-code-assist[bot] · comment · 2026-03-03T09:47:00Z · [source](https://github.com/verl-project/verl/pull/5470#discussion_r2877226683)

File: `verl/tools/agentbay_tool.py` · line 56

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The code currently does not handle the case where the AgentBay API key is not provided either through the configuration or the environment variable. If `api_key` is `None`, `AsyncAgentBay(api_key=None)` might raise an unhelpful error from the SDK. It's better to explicitly check for the API key and raise a `ValueError` with a clear message on how to fix it.

```suggestion
            api_key = self.config.get("api_key") or os.getenv("AGENTBAY_API_KEY")
            if not api_key:
                raise ValueError(
                    "AgentBay API key not found. Please set it via AGENTBAY_API_KEY "
                    "environment variable or in the tool config."
                )
            self._agent_bay = AsyncAgentBay(api_key=api_key)
```
