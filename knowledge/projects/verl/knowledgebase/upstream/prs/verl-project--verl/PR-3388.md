# [Fix] Apply `convert_nested_value_to_list_recursive` to `tool_calls` attribute in messages, at multiturn_sft_dataset.py

[Upstream PR](https://github.com/verl-project/verl/pull/3388) · state: open · merged: False

## Original PR description

### What does this PR do?

Sometimes, the `tool_calls` value of a Chatml message is of numpy.ndarray type. If so, chat template of LLM may have hard time encoding the messages.

In my case, I got this error while SFTing:
File "<template>", line 85, in top-level template code
ValueError: The truth value of an array with more than one element is ambiguous. Use a.any() or a.all()

The line 85 of my LLM's jinja2 chat template is:
`{%- if msg.tool_calls %}` 

The error is gone after applying `convert_nested_value_to_list_recursive` to `tool_calls`.

## Code Review

This pull request addresses an issue where `tool_calls` in messages can be of type `numpy.ndarray`, causing problems with chat templates. The fix involves converting these values to lists recursively. While the fix is functionally correct, the implementation places the conversion logic inside the `__getitem__` method of the dataset. This is inefficient as it runs for every sample retrieval and can have side effects. I've recommended moving this logic to the dataset's initialization method for better performance and design. Additionally, the pull request is missing a unit test to cover this new logic, which is crucial to prevent future regressions.

Placing this data conversion logic inside `__getitem__` is inefficient and not a recommended practice. This method is called for every data sample, potentially multiple times across epochs. This leads to redundant processing. Furthermore, modifying the dataset's internal state (`self.messages`) within `__getitem__` can lead to unexpected behavior, especially in multi-process data loading scenarios.

This conversion should be performed only once when the data is first loaded. A better place for this logic is within the `_read_files_and_process` method, right after `self.messages` is initialized. This would process the entire dataset at once, improving performance and making the `__getitem__` method stateless and faster.
