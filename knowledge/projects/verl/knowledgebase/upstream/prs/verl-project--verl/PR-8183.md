# [perf] fix: read head_dim from config for Qwen3-VL FLOPS estimation

[Upstream PR](https://github.com/verl-project/verl/pull/8183) · state: closed · merged: False

## Original PR description

### What does this PR do?

Fixes `_estimate_qwen3_vl_flops` in `verl/utils/flops_counter.py` to read `head_dim` from the model config instead of deriving it as `hidden_size // num_attention_heads`, which underestimates the FLOPS (and therefore underreports MFU) for Qwen3-VL models whose `num_attention_heads * head_dim != hidden_size`.

Also adds a regression test case for `qwen3_vl` based on the exact config of `Qwen/Qwen3-VL-4B-Instruct`, a model where the derived value differs from the true `head_dim` (the existing `qwen3_vl` test uses the 8B model, where `hidden_size // num_attention_heads` happens to equal `head_dim`, so this bug was not exposed).

### Test

All existing golden values are unchanged (13 original cases pass), plus one new case:

```text
$ pytest tests/utils/test_flops_counter.py -q
14 passed in 0.24s
```

The new `qwen3_vl_4b` case uses the exact `Qwen/Qwen3-VL-4B-Instruct` config (explicit `head_dim=128`) and covers both batch shapes `[512, 1024, 2048]` and `[4096, 4096, 4096]` with image tokens. With the old derivation, `head_dim` would be computed as `2560 // 32 = 80` instead of `128`, underestimating the total FLOPS by ~9-10%.

### API and Usage Example

No API changes — this only corrects an internal estimation detail.

### Design & Code Changes

`_estimate_qwen3_vl_flops` derived `head_dim = hidden_size // num_attention_heads`, but Qwen3-VL sets an explicit `head_dim` in `text_config`:

| Model | hidden_size | num_attention_heads | head_dim | heads × head_dim |
| --- | --- | --- | --- | --- |
| Qwen3-VL-4B | 2560 | 32 | 128 | 4096 ≠ 2560 |
| Qwen3-VL-32B | 5120 | 64 | 128 | 8192 ≠ 5120 |

This affects two terms:

1. the attention projection FLOPS (`q/k/v/o` linear layers), and
2. the attention score FLOPS `6 * seqlen^2 * num_attn_heads * d_head * num_hidden_layers`.

The fix reads `head_dim` from the config with the same `getattr` fallback pattern already used by `_estimate_qwen3_vl_moe_flops` (and the other estimators):

```python
head_dim = getattr(config.text_config, "head_dim", hidden_size // num_attention_heads)
```

The fallback keeps backward compatibility: `qwen2_vl` and `qwen2_5_vl` share this estimator, do not set `head_dim`, and satisfy `hidden_size == num_attention_heads * head_dim`, so their estimates are unchanged.
