# [fsdp] feat: support R3 router replay

[Upstream PR](https://github.com/verl-project/verl/pull/8194) · state: open · merged: False

## Original PR description

### What does this PR do?

Wires R3 (rollout router replay) into the plain FSDP engine. The megatron and veomni engines already replay the rollout's MoE routing; the FSDP engine dropped `routed_experts`.

With `actor.fsdp_config.router_replay.mode=R3` and `rollout.enable_rollout_routing_replay=True`, `FSDPEngineWithLMHead` passes the rollout's top-k expert indices to the model as the forward argument `routed_experts` in `compute_log_prob` and the actor update. The model applies them.

### Design & Code Changes

- `fsdp.yaml`: add `router_replay.mode` (default `disabled`).
- `engine_workers.py`: read the mode for `fsdp` / `fsdp2`, so the existing `enable_routing_replay` flag is set on the batch.
- `fsdp/transformer_impl.py`: `_pack_routed_experts` flattens `routed_experts` in the packed order of `input_ids` and appends the pad suffix. Shape `(1, total_nnz + pad_size, num_layers, topk)`, int64. Rows without a recorded choice are all zero and the model routes them natively (same convention as the veomni controller).
- `veomni/transformer_impl.py`: one line to keep VeOmni on its own replay hook.

Not supported, and rejected with an error instead of ignored: padded inputs (`use_remove_padding=False`), Ulysses SP, a batch without `routed_experts`, a model whose `forward` has no `routed_experts` parameter. R2 is not implemented.

No in-tree Hugging Face model takes `routed_experts` yet; this PR only adds the engine side.
