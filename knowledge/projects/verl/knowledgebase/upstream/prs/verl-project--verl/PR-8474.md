# [trainer] fix: end v1 fit() through on_train_end() and stop the train dataloader workers

[Upstream PR](https://github.com/verl-project/verl/pull/8474) · state: closed · merged: True

## Original PR description

### What does this PR do?

Fixes two problems at the end of the v1 trainer's `fit()`:

- When training reaches its last step, `fit()` returns from inside the loop. On that path `on_train_end()` never runs, so the hook only fires when the loop ends some other way (the epochs run out first). No class in the repo overrides it yet.
- The train iterator `self.train_dataloader_it` keeps its dataloader workers alive after `fit()`, and `StatefulDataLoader` also holds its last iterator. At process exit the workers are killed with the Ray actor. Every successful run then ends with a traceback after `Final validation metrics`:

  ```
  (TaskRunnerV1 pid=...)   File ".../torch/utils/data/_utils/signal_handling.py", line 73, in handler
  (TaskRunnerV1 pid=...)     _error_if_any_worker_fails()
  (TaskRunnerV1 pid=...) RuntimeError: DataLoader worker (pid ...) is killed by signal: Killed.
  ```

  We saw it at the end of each arm of a three-arm GRPO run (Qwen3-30B-A3B, 4×B300, 10 steps each; the job's exit code was 0 every time).

The last step now `break`s out of the loop, so `on_train_end()` and the dump executor shutdown run on every path. `fit()` then stops the train dataloader's workers through the iterator's `_shutdown_workers()`, the same call the iterator makes when it is garbage collected.

### Test

`tests/trainer/ppo/v1/test_fit_teardown_on_cpu.py` (new, CPU). It runs `fit()` for three steps with a stub `step()` that draws batches through `_fetch_one_gen_batch()` from a real `StatefulDataLoader` with two workers:

- `on_train_end()` runs once after the last step.
- No worker process outlives `fit()`.

Both tests fail without the change: the hook is not called, and the two workers are still alive.

```bash
python -m pytest -q tests/trainer/ppo/v1/ -k on_cpu   # 238 passed
pre-commit run --files <changed files>               # all hooks pass
bash scripts/generate_trainer_config.sh              # All good
```

A minimal Ray actor that keeps such an iterator and returns did not print the traceback at shutdown, so its appearance depends on how Ray tears down a full verl job. I have not rerun a full job with this change; the test covers the cause, the workers that outlive `fit()`.

### Design & Code Changes

- `verl/trainer/ppo/v1/trainer_base.py`:
  - On the last step, `fit()` leaves the loop with `break` instead of `return`, so `on_train_end()` and `_shutdown_dump_executor()` (called once now) run after it.
  - New `_shutdown_train_dataloader()` drops `train_dataloader_it` and stops its workers.
- `tests/trainer/ppo/v1/test_fit_teardown_on_cpu.py`: new CPU test.
