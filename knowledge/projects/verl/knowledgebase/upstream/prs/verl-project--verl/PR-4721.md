## Original PR description

## Summary

Add comprehensive tests to verify gradient accumulation correctness across all supported loss aggregation modes. This addresses the need for testing gradient accumulation with different loss aggregation modes.

### Test Coverage

**Loss Aggregation Modes Tested:**
- `token-mean`
- `seq-mean-token-sum`
- `seq-mean-token-mean`
- `seq-mean-token-sum-norm`

**Test Categories:**
1. **Token-weighted accumulation equivalence** - Verifies that losses with gradient accumulation match full-batch processing
2. **Sequence-based simple accumulation** - Tests seq-mean modes with batch-weighted accumulation
3. **agg_loss consistency** - Tests determinism and mask behavior
4. **Gradient equivalence** - Verifies accumulated gradients match full-batch gradients using actual model
5. **Edge cases** - Single micro-batch, uneven token distribution

### Key Assertions
- Losses on the same mini-batch are equal with/without gradient accumulation
- Proper weighting is applied based on loss aggregation mode (token-weighted for token-mean, batch-weighted for seq-mean)
- Gradients accumulated over micro-batches match full-batch gradients

### Test Results
All 56 tests pass across different batch sizes (8, 16, 32) and micro-batch configurations (2, 4 micro-batches).

The current test suite does not cover the critical edge case where a micro-batch contains zero valid tokens. This can occur in practice, for example, with sparse response masks, and can lead to a division-by-zero error in `agg_loss` for the `"token-mean"` mode, causing a crash.

To ensure the gradient accumulation logic is robust, I recommend adding the following test case to the `TestEdgeCases` class. This test will expose the issue and ensure that it is handled gracefully.

```python
    @pytest.mark.parametrize("loss_agg_mode", LOSS_AGG_MODES)
    def test_zero_tokens_in_micro_batch(self, loss_agg_mode: str):
        """Test gradient accumulation when a micro-batch has zero valid tokens."""
        batch_size = 8
        seq_len = 64
        num_micro_batches = 2

        torch.manual_seed(42)

        # Create a batch where the first micro-batch has tokens, but the second has none.
        response_mask = torch.zeros(batch_size, seq_len, dtype=torch.float32)
        response_mask[: batch_size // num_micro_batches] = 1.0

        batch = {
            "log_prob": torch.randn(batch_size, seq_len),
            "old_log_prob": torch.randn(batch_size, seq_len),
            "advantages": torch.randn(batch_size, seq_len),
            "response_mask": response_mask,
        }

        # This test will fail for "token-mean" due to a division-by-zero in `agg_loss`
        # when a micro-batch has no tokens. The test is here to expose that.
        loss_full = compute_loss_without_accumulation(batch, loss_agg_mode)
        loss_accum = compute_loss_with_token_weighted_accumulation(
            batch, loss_agg_mode, num_micro_batches
        )

        torch.testing.assert_close(
            loss_accum,
            loss_full,
            rtol=1e-5,
            atol=1e-6,
            msg=f"Zero tokens in micro-batch failed for {loss_agg_mode}",
        )
```
