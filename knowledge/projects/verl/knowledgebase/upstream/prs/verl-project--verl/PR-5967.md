# [fully_async] fix: Add Mindspeed Patch for Async Training on Ascend NPUs

[Upstream PR](https://github.com/verl-project/verl/pull/5967) · state: closed · merged: True

## Original PR description

### What does this PR do?

The MindSpeed patch for Megatron was not being applied in the `fully_async` training path, causing `torch_npu`-related errors when training on Ascend NPUs. This PR addressed this issue. We also provide an example script for training Qwen3-VL-30B-megatron in a fully async setting on ascend npus. 

### Fix
Ensured the MindSpeed patch is applied correctly regardless of the training mode, so `fully_async` training now works as expected on Ascend NPUs.

- gemini-code-assist[bot] · comment · 2026-04-11T01:12:01Z · [source](https://github.com/verl-project/verl/pull/5967#discussion_r3067295048)

File: `verl/workers/engine_workers.py` · line None

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The direct access to `self.config.actor.megatron` is unsafe and will cause a runtime crash (e.g., `AttributeError` or `KeyError`) if the training strategy is not Megatron (such as FSDP2), as the `megatron` key may be missing from the configuration. 

Additionally, `repatch` is a global side-effect utility specifically for MindSpeed/Megatron on NPUs. It should only be invoked when the Megatron strategy is active. Since the `MindspeedEngineWithLMHead` already performs this patching during its initialization, this call in `ActorRolloutRefWorker` should be guarded to ensure it only runs when appropriate and doesn't break other training paths.

```suggestion
        if repatch is not None and self.config.actor.get('strategy') == 'megatron':
            megatron_cfg = self.config.actor.get('megatron')
            if megatron_cfg:
                repatch(megatron_cfg.get("override_transformer_config", {}))
```

- HwCARI · comment · 2026-04-14T02:03:55Z · [source](https://github.com/verl-project/verl/pull/5967#discussion_r3076746491)

File: `verl/workers/engine_workers.py` · line None

The issue is that `DetachActorWorker.__init__()` of `separation/engine_workers.py` used in the fully async training calls `_get_strategy_handlers()`, which imports `verl.utils.megatron_utils`. That module has a top-level `from megatron.core import ...`, causing megatron to be loaded into sys.modules before the engine module could import mindspeed first. This results in the related monkey patches not taking effect as expected.
