# [trainer] fix: preserve the token axis when packing position IDs

[Upstream PR](https://github.com/verl-project/verl/pull/8412) · state: closed · merged: False

## Original PR description

### What does this PR do?

Fixes a position-ID layout mismatch encountered during Qwen3.5-4B GRPO training on Ascend 910B.

Actor minibatch selection fails when unbinding a nested tensor. Relevant traceback excerpt, with environment-specific paths removed:

```text
File "verl/utils/tensordict_utils.py", line 495, in index_select_tensor_dict
    tensor_lst = tensor.unbind()

RuntimeError: split_with_sizes expects split_sizes to sum exactly to 1280
(input tensor's size at dimension 1), but got split_sizes=[4, 4, 4, 4, 4, 4, 4, 4]
```

![Sanitized traceback excerpt](https://raw.githubusercontent.com/yue-zeng-yue/verl/06960097236eaae9af87e7fc58b96781c79db0d4/.github/pr-assets/padding-position-ids-error.png)

*Typeset log excerpt, not an original screenshot. The same traceback is included as text above.*

For equal-length batches of multi-component position IDs, `as_nested_tensor()` can infer the component axis as the jagged dimension. Subsequent processing interprets it as the token axis, resulting in inconsistent layout metadata and the split failure.

### Changes

- Construct nested position IDs explicitly along the token axis in `left_right_2_no_padding()`.
- Reuse the existing `cu_seqlens` and specify `jagged_dim=position_ids.dim() - 1`.
- Add regression coverage for ordinary text and multi-component position IDs, including equal-length batches and single-sample inputs.

No configuration or public API changes are required.

### Validation

The following checks passed locally:

```bash
python -m pytest tests/utils/test_padding_on_cpu.py -q --tb=short

pre-commit run --files \
  verl/workers/utils/padding.py \
  tests/utils/test_padding_on_cpu.py \
  --show-diff-on-failure
```

After applying the same fix in our existing Ascend 910B environment, Qwen3.5-4B GRPO training completed all 250 steps without recurrence of the reported `split_with_sizes` error.
