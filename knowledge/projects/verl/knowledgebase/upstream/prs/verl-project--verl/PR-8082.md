# [rollout, vllm] feat: add request hooks to vLLMHttpServer.generate

[Upstream PR](https://github.com/verl-project/verl/pull/8082) · state: closed · merged: True

## Original PR description

### What does this PR do?

Adds two request hooks to `vLLMHttpServer.generate()`, so a server subclass can change a request's sampling parameters and its output without overriding `generate()`. Admission, pause/resume, and weight-sync coordination stay in `generate()`.

This implements the hook option discussed in #7735 ([maintainer comment](https://github.com/verl-project/verl/issues/7735#issuecomment-5884513068)). The motivating user is [verl-project/verl-genrank#4](https://github.com/verl-project/verl-genrank/pull/4), which needs per-request `logprob_token_ids` and the selected-token rows in the output. Today `generate()` keeps only the sampled token's log probability, so verl-genrank overrides the whole method and copies its admission bookkeeping (`_submission_paused`, `_resume_event`, `_admitting`). That copy is already behind main: since `e42d6af6`, the commit verl-genrank pins, `generate()` moved admission into `_park_until_admitted()` and started rejecting late arrivals.

verl-omni also overrides `generate()`. Its pinned verl (`fefb080`) predates the admission gate, so these hooks may help it keep upstream admission when it updates.

### API and Usage Example

```python
class SelectedTokenServer(vLLMHttpServer):
    def _preprocess_sampling_params(self, sampling_params):
        sampling_params["logprob_token_ids"] = sampling_params.pop("selected_token_ids")

    def _postprocess_output(self, output, final_res, sampling_params):
        rows = final_res.outputs[0].logprobs if final_res.outputs else []
        ids = sampling_params.logprob_token_ids
        output.extra_fields["selected_logprobs"] = [[row[t].logprob for t in ids] for row in rows]
        return output
```

The subclass is selected through `vLLMReplica.server_class`, as today.

### Design & Code Changes

Both hooks sit in the existing "Hook methods for subclass overrides" section; their defaults keep the current behavior.

- `_preprocess_sampling_params(sampling_params: dict) -> None`
  - Input: the request's sampling-parameter dict after upstream fills its defaults (`max_tokens` already removed, `logprobs` set to 0 or `None`, `detokenize` defaulted).
  - Order: before `SamplingParams` is built and before `_park_until_admitted()`.
  - Errors: an exception fails the request; it is never admitted, so the admission counter is untouched.
- `_postprocess_output(output, final_res, sampling_params) -> TokenOutput`
  - Input: the `TokenOutput` built by upstream, the engine's `RequestOutput`, and the built `SamplingParams`.
  - Order: after the engine stream ends and the admission counter is released; runs for normal outputs and for requests aborted with empty outputs. Requests rejected at the admission gate return before it.
  - Errors: an exception fails only this request.
  - Hooks should add to `extra_fields` rather than replace it: the PD prefill leg reads `kv_transfer_params` from there.
- With PD disaggregation, each leg calls `generate()` with its own copy of the sampling parameters, so the hooks run once on the prefill server (whose output is discarded) and once on the decode server.
- CI: `test_submitter_gate_on_cpu.py` imports vllm, which the `cpu` extra does not install, so `cpu_unit_tests` skips it and it was not in the vllm workflow's CPU list. This PR adds it to the "Run vllm CPU unit tests" step, which also starts running its 12 existing gate tests.
