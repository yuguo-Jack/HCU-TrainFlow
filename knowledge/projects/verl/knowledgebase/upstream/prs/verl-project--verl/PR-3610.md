- gemini-code-assist[bot] · comment · 2025-09-25T03:43:41Z · [source](https://github.com/verl-project/verl/pull/3610#discussion_r2377621073)

File: `recipe/agent_lightning_like/example/agent_client.py` · line 82

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

Creating a new `aiohttp.ClientSession` for each `chat` call is inefficient. A `ClientSession` is designed to be reused for multiple requests to pool connections. Creating a new one for every request adds overhead and can lead to resource exhaustion (e.g., too many sockets in `TIME_WAIT` state) under high load. The session should be created once and reused. Since the `AgentClient` is instantiated for each sample, consider managing the `ClientSession` at a higher level, such as in the `AgentLoopWorker`, and passing it down.

The background `uvicorn` server process started on line 81 is only killed at the end of the script. If the main python script fails, the `kill` command on line 154 will not be executed, leaving the server process running. To ensure cleanup happens even on script failure, you should use a `trap` to kill the server process on exit.


- gemini-code-assist[bot] · comment · 2025-09-25T03:43:41Z · [source](https://github.com/verl-project/verl/pull/3610#discussion_r2377621078)

File: `recipe/agent_lightning_like/llm_router.py` · line None

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

Using `os._exit(-1)` to terminate a Ray actor is unsafe. It bypasses normal Python exit procedures, including `finally` blocks and `atexit` handlers, and can lead to resource leaks or corruption of Ray's internal state. A better approach is to let the actor exit gracefully, for example by raising an exception or using `ray.actor.exit_actor()`.

```suggestion
            print("LLMRouter shutdown, maybe address already in use, raising SystemExit to exit actor gracefully.")
            raise SystemExit(-1)
```
