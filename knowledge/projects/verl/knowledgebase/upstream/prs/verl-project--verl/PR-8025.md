# [training_utils, trainer, tests] feat: raw log-prob mismatch metrics for rollout vs actor

[Upstream PR](https://github.com/verl-project/verl/pull/8025) · state: closed · merged: True

## Original PR description

### What does this PR do?

Adds three raw log-prob metrics next to the existing `training/rollout_probs_diff_*`:

- `training/rollout_logprobs_mismatch_count`: valid response tokens whose `rollout_log_probs != old_log_probs`
- `training/rollout_logprobs_diff_max` / `_mean`: |Δ| of the raw log-probs

`rollout_probs_diff_*` compares `exp(log_prob)` and cannot see a 1-ULP log-prob difference (float32 `-0.10000000149` vs `-0.10000000894` give the same prob). Exact 0-diff train-rollout work (verl-project/verl#7688, verl-project/verl-omni#637) needs a gate that only passes at zero elements, so the count is exposed directly. In the V1 trainer the count is aggregated by sum, not mean.

Emitted from `calculate_debug_metrics`, so every existing caller (v1 trainer, legacy trainer, separation trainer) gets it under `rollout.calculate_log_probs=True` with no config change.

Useful gate for exact 0-diff train-rollout work: `rollout_probs_diff_*` really can hide 1-ULP log-prob differences, and summing `mismatch_count` in the V1 aggregator is the right aggregation for a zero-element check.

One correctness nits on the inline comment: keep the mismatch count on the same `.float()` path as `rollout_logprobs_diff`, otherwise mixed bf16/fp32 batches can disagree between the count and the abs-diff metrics.

Also:
- `test_all_masked_returns_invalid` only checks `mismatch_count == 0`; please also assert the new `*_diff_max` / `*_diff_mean` stay `nan` on the early-return path.

- SamitHuang · comment · 2026-10-21T03:34:58Z · [source](https://github.com/verl-project/verl/pull/8025#discussion_r4332775642)

File: `verl/utils/debug/metrics.py` · line 125

`!=` compares the native dtypes, while `rollout_logprobs_diff` above casts both sides with `.float()` first. If `old_log_probs` / `rollout_log_probs` ever differ in dtype (bf16 vs fp32 is common), the mismatch count and the abs-diff metrics can disagree. Prefer deriving the count from the already-casted tensor, e.g. `int((rollout_logprobs_diff != 0).sum().item())`, so both metrics share one comparison path.
