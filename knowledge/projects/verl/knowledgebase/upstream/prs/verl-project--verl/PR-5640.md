# [vllm] fix: npu disable flash_attn for RotaryEmbedding

[Upstream PR](https://github.com/verl-project/verl/pull/5640) · state: closed · merged: True

## Original PR description

### Summary
bugfix: Incorrectly imported flash_attn in RotaryEmbed when using vLLM > 0.13 on NPU

### Quenstion

When running on NPU with the vllm_ascend backend, a ModuleNotFoundError: No module named 'flash_attn.ops'; 'flash_attn' is not a package occurs.
This is because the mindspeed and megatron backends introduce flash_attn as a dummy module from mindspeed_dummy.py.However, the vllm_ascend backend does not depend on or use flash_attn, especially the apply_rotary_emb_flash_attn function in the ApplyRotaryEmb class.
This fix skips the invalid flash_attn import path for NPU + vLLM > 0.13 and avoids loading unused flash-attention related code.

### Fix
In the vllm_async_server function, add checks for both VLLM version ≥ 0.13 and NPU availability.When both conditions are satisfied, patch the __init__ method of RotaryEmbed to prevent incorrect import of flash_attn.

## Code Review

This pull request addresses a `ModuleNotFoundError` for `flash_attn` on NPU environments with vLLM versions 0.13.0 and newer by monkey-patching `ApplyRotaryEmb.__init__` to prevent the problematic import. The approach is sound, but the version check for applying the patch is unbounded, which poses a risk for future vLLM updates. I've kept the high-severity comment suggesting scoping the patch to a specific version range to improve maintainability and prevent potential future breakages, as it does not conflict with any provided rules.

Applying this patch is correct for the intended purpose. However, the condition on line 64 (`_VLLM_VERSION >= version.parse("0.13.0")`) that controls this block is too broad. It applies the patch to all future vLLM versions, which is risky because the underlying `ApplyRotaryEmb.__init__` method could change, making this patch incompatible and causing subtle bugs.

To improve forward-compatibility, please consider modifying the condition on line 64 to be more specific, for example: `version.parse("0.13.0") <= _VLLM_VERSION < version.parse("0.14.0")`. This pattern of using bounded version checks is already present elsewhere in the codebase (e.g., in `verl/utils/vllm/vllm_fp8_utils.py`).
