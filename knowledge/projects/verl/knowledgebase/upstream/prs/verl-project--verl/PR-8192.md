# [training_utils, hardware] fix: dispatch log-prob kernels by tensor device

[Upstream PR](https://github.com/verl-project/verl/pull/8192) · state: open · merged: False

## Original PR description

### What does this PR do?

On an Ascend environment with `torch_npu.npu_cross_entropy_loss` installed, `logprobs_from_logits()` dispatches CPU logits to that NPU-only operator and raises `NotImplementedError`. Installing Flash-Attention causes the equivalent problem because its availability takes priority over the input device. This already forced the FSDP distillation CPU regression to replace real log-probs with a dummy tensor.

Select optimized cross-entropy using both kernel availability and `logits.device.type`: Flash-Attention for CUDA tensors, native CE for NPU tensors, and the existing PyTorch fallback elsewhere. The CUDA disable switch and `inplace_backward` argument continue to work. Remove the dummy FSDP log-prob stub and verify real numerical outputs in both padding modes.

Minimal failing example on the unmodified Ascend checkout:

```python
import torch
from verl.utils.torch_functional import logprobs_from_logits

logprobs_from_logits(torch.randn(2, 3, 13), torch.randint(13, (2, 3)))
# NotImplementedError: Could not run 'npu::npu_cross_entropy_loss'
# with arguments from the 'CPU' backend.
```

### Test

Local environment: Ascend 910B2, CANN 8.5.2, torch 2.7.1+cpu with torch-npu 2.7.1.post2, Transformers 5.12.1, Python 3.12.0/aarch64.

```bash
python -m pytest -q -s tests/utils/test_logprobs_device_dispatch_on_cpu.py tests/utils/test_logprobs_device_dispatch_on_npu.py tests/workers/test_distillation_topk_symmetry_on_cpu.py
pre-commit run --all-files --show-diff-on-failure
```

Before the fix, **20 failed / 4 passed**: the 18 CPU combinations reach device-only kernels, and the two real FSDP CPU log-prob paths fail against installed torch-npu after removing the dummy stub. A direct call with the real installed NPU operator also reproduces the `NotImplementedError` above.

After the fix, **44 passed**:

- CPU FP32/FP64/BF16 forward and gradients, 2D/strided 3D logits, and each optional-kernel availability combination.
- **18 real NPU cases**: FP32/FP16/BF16 outputs and gradients, native CE and fallback, including the case where Flash-Attention is reported available. The NPU CE operator is executed normally; a call-through spy checks that native CE is selected when available. Largest FP32 absolute errors: outputs **2.39e-7**, gradients **7.46e-8**; tested FP16/BF16 outputs and gradients match their reference exactly.
- Two CUDA **metadata** cases use FakeTensorMode on CPU to check flattening, output shape/device, `inplace_backward=False`, and the disable switch. CUDA hardware/kernel numerics were not run locally.
- Six FSDP distillation regressions, now using real CPU log-probs and checking their numerical values against log-softmax in both padding modes.

All **14** pre-commit hooks passed. The new CPU and NPU files are collected by existing workflows; the real NPU test skips when torch-npu or an NPU is absent. No full RL training or throughput benchmark was run; this PR claims device-correct dispatch, not a speedup or training-quality change.
