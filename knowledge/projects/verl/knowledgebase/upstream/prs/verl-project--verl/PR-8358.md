# [reward] fix: extract dict['score'] in PrimeRewardManager parallel scoring

[Upstream PR](https://github.com/verl-project/verl/pull/8358) · state: closed · merged: False

## Original PR description

### What does this PR do?

Fixes #8216.

When a reward evaluation function returns a dictionary (such as the built-in `math_dapo.compute_score` or `rlla.compute_score` which return `{"score": ..., "acc": ..., "pred": ...}`), `PrimeRewardManager`'s `parallel_compute_score_async` previously fell through to `else: scores.append(float(result[0]))`, raising `KeyError: 0`. Because `PrimeRewardManager.verify()` wraps `run_reward_scoring` in `except Exception`, that `KeyError: 0` was caught and silently replaced the entire training batch's rewards with `0.0`.

This PR aligns `parallel_compute_score_async` in `verl/workers/reward_manager/prime.py` with `NaiveRewardManager`, `BatchRewardManager`, and `DAPORewardManager` by extracting `float(result["score"])` when `isinstance(result, dict)`.
