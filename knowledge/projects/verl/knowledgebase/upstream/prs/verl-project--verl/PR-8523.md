# [reward] feat: pass truncation to compute_score in the DAPO reward loop manager

[Upstream PR](https://github.com/verl-project/verl/pull/8523) · state: open · merged: False

## Original PR description

### What does this PR do?

The reward loop `DAPORewardManager` now sets `extra_info["truncated"]`. It is `True` when the response reaches the rollout's response limit (`actor_rollout_ref.rollout.response_length`) and its last token is not EOS. DAPO's overlong shaping penalizes length, but a `compute_score` function has no way to tell whether a response was cut off. A truncated response can still contain a correct-looking final answer, and scoring it as complete rewards unfinished reasoning. With this flag, a scoring function can, for example, give truncated responses zero. Functions that ignore the key are unaffected.

The manager copies `extra_info` before writing to it, because the rollouts of a prompt share one dict and are scored concurrently (see the companion fix for the other managers, #8522).

Related: #7063 adds `valid_response_length` and `max_resp_len` to the legacy manager's `reward_extra_info` output for logging. This PR instead passes truncation into `compute_score`, in the reward loop manager.

### Test

Added `test_reward_loop_passes_truncated_to_compute_score` to `tests/workers/reward_manager/test_dapo_on_cpu.py`, parametrized over 6 cases:
- padded batch: full length without EOS → `True`; full length ending in EOS → `False`; shorter than the width → `False`;
- unpadded responses, as the agent loop scores them (width = valid length): shorter than `rollout.response_length` without EOS → `False`; at the limit without EOS → `True`; shorter than `reward_kwargs.max_resp_len` without EOS → `False`.

It also checks that the batch's `extra_info` is not modified. `pytest tests/workers/reward_manager/`: 24 passed. The two short unpadded cases fail with a check against the batch width.

### API and Usage Example

```python
def compute_score(data_source, solution_str, ground_truth, extra_info=None, **kwargs):
    if extra_info.get("truncated"):
        return 0.0
    ...
```

### Design & Code Changes

`verl/experimental/reward_loop/reward_manager/dapo.py`: `__init__` reads the limit from `actor_rollout_ref.rollout.response_length`, falling back to `reward_kwargs.max_resp_len`. `run_single` copies `extra_info`, then sets `truncated`; with no configured limit it compares against the batch width. The agent loop scores each response unpadded, so the batch width alone would mark every short response without EOS (for example, one stopped by a stop string) as truncated. The legacy `verl/workers/reward_manager/dapo.py` is unchanged.
