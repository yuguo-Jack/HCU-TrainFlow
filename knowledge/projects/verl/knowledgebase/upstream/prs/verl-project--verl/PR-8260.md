# [rollout, vllm] fix: reject engine_kwargs that override verl-managed vLLM args

[Upstream PR](https://github.com/verl-project/verl/pull/8260) · state: closed · merged: True

## Original PR description

### What does this PR do?

Some vLLM args are derived from verl's own config (TP, DP, expert parallelism, LoRA, routing replay) but could also be passed through `rollout.engine_kwargs.vllm`. Which source won depended on where verl wrote the derived value, and neither direction was reported: `tensor_parallel_size` from `engine_kwargs` replaced verl's, while `enable_expert_parallel` was always overwritten with `expert_parallel_size > 1`. With the default `expert_parallel_size=1`, an explicit `engine_kwargs.vllm.enable_expert_parallel=True` became `False`; every GPU then held all experts (and their LoRA buffers) and vLLM reported no memory for the KV cache.

This PR keeps verl's config as the only knob for these args. `engine_kwargs` naming one of them now fails at server start with the config to set instead:

| vLLM arg | set instead |
|---|---|
| `tensor_parallel_size` | `rollout.tensor_model_parallel_size` |
| `data_parallel_size` | `rollout.data_parallel_size` |
| `enable_expert_parallel` | `rollout.expert_parallel_size` (= TP × DP) |
| `enable_lora`, `max_lora_rank` | `actor_rollout_ref.model.lora` |
| `enable_return_routed_experts` | `rollout.enable_rollout_routing_replay` |

The check replaces the delta_sharded-only TP/DP override checks. The one in-repo script that set `enable_expert_parallel` next to `expert_parallel_size` drops the redundant line, and the perf doc names the rollout config.
