### Test

Validated HF → MCore → HF round trips for:
- Qwen3-30B-A3B
- Qwen3-VL-30B-A3B-Instruct
- Qwen3.5-35B-A3B
- Qwen3.5-9B
All four models passed the following checks:
1. HF → MCore conversion: Ran scripts/converter_hf_to_mcore.py --pp_size 4 --test with TP1/PP4. After zeroing and reloading the parameters, every parameter exactly matched the HF-loaded reference.
2. v2 checkpoint layout: Verified that weights and HF artifacts were saved under model/dist_ckpt/ and model/huggingface/.
3. Checkpoint resharding: Built models with TP2/PP2 using make_megatron_module and loaded the converted checkpoint through load_mcore_dist_weights, the loading function used by the Megatron engine. Every parameter exactly matched a direct HF load.
4. MCore → HF comparison and export: Ran verl.model_merger test --backend megatron against the original HF checkpoint. Saved the TP2/PP2 model state using save_dist_checkpointing, then exported it through verl.model_merger merge --backend megatron. Both comparison and output validation passed.
5. HF round-trip consistency: Reloaded the exported models with Transformers. There were no missing, unexpected, or shape-mismatched weights. All loaded BF16 state tensors had identical SHA-256 hashes, and tokenizer/processor outputs had identical token IDs.
6. Forward-output consistency: Compared last-token logits before and after conversion using a GSM8K text sample for Qwen3 and a Geo3K image-text sample for the other models. All comparisons passed with atol=rtol=1e-5.
