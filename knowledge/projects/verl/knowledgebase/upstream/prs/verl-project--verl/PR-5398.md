## Code Review

This pull request introduces support for KV cache sharing using LMCache, adding new examples and making necessary code modifications. While the implementation is generally well-structured, the load balancing logic in `AsyncLLMServerManager` contains significant flaws. The new `_release_server` mechanism is vulnerable to `KeyError` crashes due to LRU cache eviction and can lead to corrupted request counts with sticky sessions. Critically, the load balancing is also broken by default when the new feature is not enabled, impacting existing functionality. These issues require attention to ensure system stability and performance.

The `_release_server` method is called unconditionally, but the logic for tracking in-flight requests is only implemented for the case where `kv_transfer_config` is enabled. When `kv_transfer_config` is not set, `_choose_server` does not update the `_inflight` request counter. As a result, `_release_server` incorrectly calculates the new request count as 0 and updates the server's load in the heap to 0. This breaks the load balancing for the non-`kv_transfer_config` case, causing it to always pick the most recently used server.

To fix this, the call to `_release_server` should be made conditional on `kv_transfer_config` being enabled.

```suggestion
        if self.config.actor_rollout_ref.rollout.kv_transfer_config:
            self._release_server(request_id)
```

- gemini-code-assist[bot] · comment · 2026-02-25T09:17:18Z · [source](https://github.com/verl-project/verl/pull/5398#discussion_r2851789932)

File: `verl/experimental/agent_loop/agent_loop.py` · line 118

![security-high](https://www.gstatic.com/codereviewagent/security-high-priority.svg) ![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The `_release_server` method and its usage in `generate` introduce several reliability and performance issues that can lead to a Denial of Service (DoS) and severe load imbalance:

1. **KeyError / Crash**: `_release_server` relies on looking up the server in `self.request_id_to_server` (an `LRUCache`) using the `request_id`. If the `request_id` is evicted from the cache while a request is in flight (possible under high load as the cache size is limited to 10,000), `_release_server` will raise a `KeyError`, crashing the `AgentLoopWorker` actor. Since `AgentLoopWorker` is an async actor handling many concurrent requests, this crash will abort all pending operations.

2. **Corrupted Load Balancing Counts**: For "sticky sessions" (where multiple requests share the same `request_id`), the cache only stores the server assigned to the *latest* request. When any concurrent request in that session finishes, `_release_server` will decrement the count for the *latest* assigned server, regardless of which server actually handled the finished request. This corrupts the in-flight request counts.

3. **Broken Default Load Balancing**: When `kv_transfer_config` is disabled (the default), `_choose_server` increments the heap count but not `self._inflight`. `_release_server` then resets the heap count to 0 (because `self._inflight` is 0), effectively ignoring any other requests still in flight for that server and breaking the least-requests logic.

**Recommendation**: Pass the `server` handle directly from `generate` to `_release_server` instead of looking it up in the cache. Ensure `self._inflight` is updated correctly regardless of the `kv_transfer_config` setting.
