# [rollout, sglang] fix: reduce tensor lifetime overlap during bucketed weight sync

[Upstream PR](https://github.com/verl-project/verl/pull/8435) · state: open · merged: False

## Original PR description

### What does this PR do?

Reduce overlapping tensor lifetimes during SGLang bucketed weight sync. A non-fused view that overflows the current bucket is now compacted after that bucket has been consumed. The generator drops references to flushed entries, and the adapter drops `params_batch` after the awaited update, before pulling another bucket.

This preserves `_compact_for_bucket`'s view-cloning guard and DeepSeek-V4 fusion groups. No tensor is released before the awaited update completes.

This does not duplicate #6738 (skip redundant clones for owned tensors), #7139 (always clone views of reused NCCL receive buffers), or #7369 (keep fused parameters together), all of which are merged. Open-PR searches for `get_named_tensor_buckets`, SGLang bucket/lifetime/clone terms, and the related issue/PR numbers found no PR addressing this emission-order and reference-lifetime change. #2605 concerns flattened transfers; #8327's adapter changes concern quantized delta-sync validation.

AI assistance was used for implementation and validation (OpenAI Codex). The human submitter confirmed reviewing every changed line and personally running the relevant tests before submission.

### Design & Code Changes

- Determine an ordinary tensor's bucket placement before cloning its view. Fused members are still compacted immediately to protect them from upstream buffer reuse, staged until complete, and placed as one indivisible group.
- Replace the `_place`/`flushed` references and leaking entry-loop locals with direct bucket placement and short-lived entry references.
- Delete the adapter's `params_batch` only after `await sgl_update_weights(...)` returns.
- Extend the existing CPU bucketer test file, which is already selected by the CPU CI workflow's `*_on_cpu.py` discovery. The adapter unit test loads the actual method with SGLang imports and the HTTP transport stubbed, so it runs without SGLang or a distributed process group.
