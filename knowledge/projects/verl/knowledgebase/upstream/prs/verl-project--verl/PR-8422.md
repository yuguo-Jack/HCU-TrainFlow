# [algo, doc] fix: use alpha = B/(B-M) in GPG advantage estimator

[Upstream PR](https://github.com/verl-project/verl/pull/8422) · state: open · merged: False

## Original PR description

### What does this PR do?

Fix `compute_gpg_outcome_advantage` to use the group-based correction `alpha = B / (B - M)` from [GPG, Eq. 7](https://arxiv.org/html/2504.02546v4), where `M` counts responses in uniform-reward groups. The current `B / count_nonzero(raw_rewards)` depends on the reward encoding: `[1,0,0,0]` plus `[0,0,0,0]` gives alpha 8 instead of 2; encoding the same outcomes as ±1 gives alpha 1 instead of 2.

Count nonuniform groups using exact reward equality, preserving the current singleton convention (zero baseline; only a nonzero singleton is valid). When there are no valid samples, use alpha 1 to avoid division by zero. Add eight CPU regression cases and document the correction.

This changes GPG's effective update scale in either direction. No API or config changes. Alpha remains calculated over the whole training batch; this does not implement optional resampling.

**Duplicate check (2026-10-28):** searched open GPG / `count_nonzero` PRs and issue #6478. #6803 removes unused GPG parameters/statistics, #6452 handles rollout-rejected rows, and #4677 vectorizes estimators; they retain the existing alpha formula. #8349 corrects uniform-group GRPO rounding rather than GPG alpha. #6803's old-scaling assertion would need updating if both changes land. Happy to rebase.

### API and Usage Example

### Design & Code Changes

- `verl/trainer/ppo/core_algos.py`: accumulate the number of valid responses in the existing group loop and compute `B / num_valid` (or 1 when zero). Exact equality avoids classifying equal fractional rewards as nonuniform due to floating-point standard-deviation residue.
- `tests/trainer/ppo/test_core_algos_on_cpu.py`: eight regression cases, already covered by the CPU workflow.
- `docs/algo/gpg.md`: define the scaling, singleton behavior and batch-level calculation.
