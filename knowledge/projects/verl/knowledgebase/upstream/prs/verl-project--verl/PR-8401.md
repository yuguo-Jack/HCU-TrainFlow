# [hardware, docs] feat: add multi-stage Intel GPU (XPU) Docker image for vLLM 0.32.0

[Upstream PR](https://github.com/verl-project/verl/pull/8401) · state: closed · merged: True

## Original PR description

### What does this PR do?

Add `docker/xpu/Dockerfile.stable.vllm`: a multi-stage Docker image for running verl on Intel GPUs (Arc Pro B-series, XPU), with vLLM 0.32.0+xpu rollout and FSDP/FSDP2 training on torch 2.14.0+xpu. XPU platform support comes from [verl-hardware-plugin](https://github.com/verl-project/verl-hardware-plugin), which the image installs alongside verl.

Related: verl PR 8390 (vLLM 0.32.0 / transformers 5.16.1 for the CUDA stack), whose transformers window this image now follows.

### API and Usage Example

```bash
git clone https://github.com/verl-project/verl.git && cd verl
docker build -f docker/xpu/Dockerfile.stable.vllm -t verl:xpu-vllm032 .
docker run --rm -it --device /dev/dri --ipc=host --privileged verl:xpu-vllm032
```

Pin the checkouts with `--build-arg VERL_REF=<commit> --build-arg PLUGIN_REF=<commit>`. For release builds add `--no-cache` so the system certificates, `pip`, `certifi` and `uv` are fetched fresh instead of served from a stale layer.

### Design & Code Changes

Only `docker/xpu/Dockerfile.stable.vllm` is added. Stages: `drivers` -> `runtime-base` -> `builder` -> `runtime`. Only the finished `/opt/venv` and the verl / verl-hardware-plugin checkouts reach the shipped image; git, curl, uv and the driver `.deb` files stay in earlier stages.
