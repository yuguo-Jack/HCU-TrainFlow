# [megatron, ci] fix: honor module ignore patterns in ModelOpt QAT

[Upstream PR](https://github.com/verl-project/verl/pull/8329) · state: closed · merged: True

## Original PR description

### What does this PR do?

Fix ModelOpt QAT module ignore patterns so that they disable the module's child quantizers. For example, `*self_attention.linear_proj` currently matches neither `...linear_proj.input_quantizer` nor `...linear_proj.weight_quantizer`. Training therefore still applies fake quantization even when rollout explicitly keeps the corresponding `o_proj` in BF16.

Keep the existing direct-quantizer rule and append a `pattern.*` rule. This preserves explicit quantizer selection and Megatron aliases, while respecting the module-name boundary (`in_proj_a` does not disable `in_proj_ab`).

Duplicate check: [open ModelOpt/ignore PRs](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+ModelOpt+ignore), [open ignore_patterns PRs](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+ignore_patterns). The related rollout matching work (#7918) and TE FP8 audit work (#8132) do not fix this ModelOpt module-to-child-quantizer matching path. No equivalent open fix was found. This addresses one concrete mismatch relevant to #8186, not that entire roadmap.

### API and Usage Example

No API change. Existing module patterns now take effect:

```yaml
actor_rollout_ref:
  actor:
    megatron:
      qat:
        enable: true
        mode: fp8
        ignore_patterns: ["lm_head", "*mlp.gate", "*self_attention.linear_proj"]
  rollout:
    quantization:
      linear: FP8_BLOCK
      moe: FP8_BLOCK
      ignore: ['re:.*self_attn\.o_proj$']
```

Actor ModelOpt patterns use globs; rollout patterns shown here use the explicit regex prefix. Backend-specific names still need to correspond to the same layer.

### Design & Code Changes

- Expand module ignores to child quantizers, retaining the original direct pattern.
- Replace the string-only regression assertion with behavioral quantization checks and cover FP8/MXFP8 and BF16 gradient preservation.
- Rename the test file to `test_modelopt_mxfp8_on_gpu.py` so the existing GPU unit-test command discovers it automatically in an environment with ModelOpt/compressed-tensors. No separate workflow step is needed.
