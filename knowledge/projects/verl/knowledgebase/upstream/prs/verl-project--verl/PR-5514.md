## Original PR description

### What does this PR do?

integrates [atropos](https://github.com/NousResearch/atropos) RL environments with verl's GRPO training pipeline. envs handle generation and scoring; this recipe polls scored batches and trains with verl's FSDP actor + internal vLLM.

closes #1782

recipe submodule PR: https://github.com/verl-project/verl-recipe/pull/61 (merged)
upstream atropos fixes: https://github.com/NousResearch/atropos/pull/408 (merged)

### Design & Code Changes

#### core verl changes (3 files)

- **`setup.py`** — `extras_require["atropos"]` with httpx dependency
- **`verl/trainer/ppo/core_algos.py`** + **`ray_trainer.py`** — `token_level_advantages` passthrough for GRPO, as [required by the bounty](https://github.com/verl-project/verl/issues/1782). per-token advantages pass through `compute_advantage()` → `compute_grpo_outcome_advantage()` when provided, standard GRPO otherwise

*note:* also fixed a TOCTOU race in `run_unvicorn()` during development but reverted it after seeing it was independently fixed upstream in #5383.

#### recipe (`recipe/atropos/`)

subclasses `RayPPOTrainer` and overrides `fit()` to replace verl's rollout+reward phase with atropos API polling. everything else (FSDP sharding, actor optimization, checkpoint management, vLLM lifecycle) is inherited.

```
atropos env (any) → generate_proxy.py (CPU, :9004) → verl internal vLLM (HYBRID, GPU)
                                                        ↕ sleep/wake
                                                     FSDP actor (GPU)
env scores → trajectory API (:8000) ← trainer polls
```

- generation and training share GPUs via sleep/wake (HYBRID mode)
- CPU-only proxy translates between atropos and vLLM request formats, round-robins across replicas for multi-GPU
- pause/resume drain prevents CUDA crashes from in-flight generation hitting freed GPU memory during sleep/wake
- env-agnostic: switching envs is `ATROPOS_ENV=<module_name>`, no code changes

full implementation details, file listing, and tests in the recipe submodule PR.

#### upstream atropos fixes

1 bug fix found during integration, details in the [atropos PR](https://github.com/NousResearch/atropos/pull/408).

## Code Review

This pull request introduces support for pre-computed token-level advantages within the GRPO algorithm, facilitating integration with external RL environments like Atropos. The changes are well-scoped and correctly implemented. Specifically, `verl/trainer/ppo/core_algos.py` is modified to accept an optional `token_level_advantages` argument in `compute_grpo_outcome_advantage`, bypassing the standard computation when these are provided. Correspondingly, `verl/trainer/ppo/ray_trainer.py` is updated to pass these advantages from the data batch. The necessary `httpx` dependency for Atropos integration is also added in `setup.py`. The implementation is clean and effectively achieves the stated goal. I have not identified any issues of high or critical severity.
