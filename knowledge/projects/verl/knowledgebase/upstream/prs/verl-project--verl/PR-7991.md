# [model] fix: reject logit softcapping in generic fused forward

[Upstream PR](https://github.com/verl-project/verl/pull/7991) · state: open · merged: False

## Original PR description

### What does this PR do?

Reject the generic fused forward when the model's text configuration enables `final_logit_softcapping`. For example, Gemma4 uses `30 * tanh(logits / 30)`, but `dense_common` bypasses the original LM-head forward and computes log-probabilities and entropy without that transformation. This changes the policy distribution and gradients rather than merely introducing floating-point error.

The error is raised before replacing the model class's forward, with instructions to set `actor_rollout_ref.model.use_fused_kernels=False`. This is a correctness guard, not an implementation of fused softcapping. Model-specific forward adapters are unchanged.
