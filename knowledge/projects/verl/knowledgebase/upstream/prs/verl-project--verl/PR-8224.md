# [rollout] guard delta-loader masked copy to model param/buffer storage (part of #7060 known issue)

[Upstream PR](https://github.com/verl-project/verl/pull/8224) · state: open · merged: False

## Original PR description

Part of the masked-copy guards known issue in #7060 (also relates to the low-precision scope of #5972 / the 26Q4 roadmap #8186).

## What does this PR do?

**Guard (a):** the delta loader's masked-copy context patched `Tensor.copy_` globally — any same-shape floating `copy_` inside the window (temporaries, scratch tensors, other modules' state) was silently NaN-masked. This ports guard (a) from THUDM/slime#1806: masked semantics now apply **only** to destinations whose storage belongs to the model's own `named_parameters()` / `named_buffers()`, tracked as a sorted `data_ptr` interval index (bisect lookup, no per-call allocation); everything else passes through to the original `copy_`.

## Guard (b) — audit result (follow-up, needs sender-side signalling)

From reading SGLang's current `weight_updater.py`: on the custom-loader path, `end_weight_update` runs `post_load_weights` **only when no load ran** (`run_post_load = not self._session.loaded_weights`, P2P/RDMA case). So for the delta loader, derived tensors (fp8 scales, MoE biases, MLA `w_kc`/`w_vc`) are never recomputed after a masked apply — confirming the known issue. A complete fix needs the sender to flag which flushes require a post-load pass (e.g. a `post_load` bit in `__delta_spec__`) so `apply_delta` can call SGLang's `post_load_weights(model)` after leaving the masked context, without paying quant-recompute cost on every flush. I plan to send that as a follow-up PR against the delta checkpoint engine + loader; happy to take direction from maintainers on the wire-format part.

## Tests

New cases in `tests/checkpoint_engine/test_sglang_loader.py` (CPU-only):
- a foreign same-shape floating tensor copied inside the window goes through the original `copy_` (NaNs land), while the model param is masked — fails on the unpatched loader
- registered buffers are treated as model storage (mask applies)

Existing suite for the loader: 8 passed, no regressions. `_FakeModel` gained minimal `parameters()` / `named_buffers()` so the guard can index it.

**🎯 Functional Correctness** | **🟠 Major** | **⚡ Quick win**

**Index storage extent rather than logical tensor size.**

For a strided registered tensor, `numel() * element_size()` can be smaller than the address range used by its elements. For example, a parameter backed by `base[::2]` has elements beyond the calculated end. A copy into a later slice of that parameter bypasses masking and writes NaN placeholders. Build the range from the underlying storage, and retain the overlap handling above. ([docs.pytorch.org](https://docs.pytorch.org/docs/stable/storage?utm_source=openai))

**Merge overlapping model ranges before lookup.**

If a registered tensor occupies a short range inside a longer parameter range, `bisect_right` selects the short range for pointers after its start. A destination beyond that short range, but still inside the longer parameter, then uses ordinary `copy_`. A sparse delta can write its NaN placeholders into model weights. Merge overlapping ranges before building `starts` and `ends`.
