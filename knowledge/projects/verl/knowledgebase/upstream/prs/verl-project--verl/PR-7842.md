# [sglang, rollout] fix: ban sampled vision placeholders and OOV tail

[Upstream PR](https://github.com/verl-project/verl/pull/7842) · state: open · merged: False

## Original PR description

### What does this PR do?

Stops SGLang rollout from sampling `<|image_pad|>` / `<|video_pad|>` when no image or video backs them, and from sampling the out-of-vocabulary tail (ids `>= len(tokenizer)` that still have a logits column).

#7038 already does this for **vLLM**: `monkey_patch_compute_logits` masks `logits[..., len(tokenizer):]` plus the vision placeholder ids with `index_fill_` (also used by #7882). That PR's description says SGLang still needs a follow-up. This is that follow-up, with the same static-mask mechanism:

- Resolve the ids with `get_vision_placeholder_token_ids` (processor only; empty for text-only), as on vLLM.
- Wrap SGLang's `Sampler._preprocess_logits` inside each spawned scheduler process: one `index_fill_` over a device-resident column index built once per (device, logits width), plus `logits[..., len(tokenizer):] = -inf`, then SGLang's original body.
- Install it through `run_scheduler_process_func=functools.partial(run_scheduler_process_with_token_ban, ...)`, a picklable wrapper around `sglang.srt.entrypoints.engine.run_scheduler_process` (SGLang starts schedulers with multiprocessing spawn, including under the DP controller, so a patch in the rollout-server process would not be inherited).
- A missing hook raises instead of silently un-banning.

Prompt placeholders are unchanged: a real image in the prompt still means what it always meant. Prompt logprobs come from SGLang's LogitsProcessor and are not touched.

Related: #7038 (landed, vLLM-only). Closed #7515 attempted this; the first revision was an AgentLoop `get_rope_index` fallback and was closed. The author later reworked the fork to the sampling-layer ban but could not reopen. This PR is the sampling-layer approach, independently ported onto current `main`.

#### Why a static mask instead of a per-request logits processor

The first revision of this PR attached SGLang's `DisallowedTokensLogitsProcessor` to every request (and forced `enable_custom_logit_processor` on). In our internal fork the same per-request processor measured `timing_s/gen` +34..48% versus the ban switched off on a 9B VL distillation workload (ban-on Merlin run `3d94850ceedf10e4`: 449.6 / 435.4 s; ban-off `27516e3b6591561b`: 340.6 / 312.3 s). SGLang's `apply_custom_logit_processor` runs `nonzero()` plus boolean gather/scatter over `[B, vocab]` every decode step, and the host syncs break the overlap scheduler. The static mask has no per-request payload and no host sync; its own cost was **not** separately measured here (expected: one device-side fill per step, the same pattern as the vLLM mask).

- On the real SGLang `Sampler` class: vision ids and the OOV tail get zero probability (asserted on softmax, since `sanitize_nan_logits` may rewrite `-inf`), every other column is bit-identical, argmax cannot pick a banned id.
- The column index is built once and reused across steps; re-installing replaces rather than stacks; a missing `_preprocess_logits` raises.
- The scheduler entry installs the ban before calling SGLang's `run_scheduler_process`, and the bound `functools.partial` pickles (spawn).
- `launch_server` passes that partial with the vision ids and `len(tokenizer)`, and no longer sets `enable_custom_logit_processor`; `generate` sends no `custom_logit_processor` / `custom_params` and leaves prompt placeholders untouched. These two tests fail on the previous revision of this PR.

### API and Usage Example

No new config keys. VL processors that already expose image/video token ids are banned automatically, matching #7038. The OOV tail is masked for every model, as on vLLM. `engine_kwargs.sglang.enable_custom_logit_processor` is no longer touched, so user-supplied custom logit processors keep working.
