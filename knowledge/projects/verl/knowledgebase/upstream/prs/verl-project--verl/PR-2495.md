# [misc] feat: add MPS/CPU fallback support for local debugging

[Upstream PR](https://github.com/verl-project/verl/pull/2495) · state: open · merged: False

## Original PR description

Enable the verl trainer and workers to run on MPS or CPU by:

* Setting `attn_implementation="eager"` when flash-attn is not available
* Skipping FSDP and using `.to(device)` for unsupported devices
* Using `psutil` for memory stats when torch APIs are unavailable
* Updating `ray.init` and distributed init for flexible device support

The `while` loop introduces a busy-wait, which can cause performance degradation. It repeatedly calls `self._read_files_and_tokenize()` if `self.dataframe` is not ready, which can lead to race conditions and redundant I/O operations if multiple dataloader workers enter this loop concurrently. The underlying issue should be addressed directly instead of using a busy-wait with `time.sleep`.

- gemini-code-assist[bot] · comment · 2025-07-12T09:08:32Z · [source](https://github.com/verl-project/verl/pull/2495#discussion_r2202459455)

File: `verl/workers/fsdp_workers.py` · line 714

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

The memory metrics for non-CUDA/NPU devices are incorrect and misleading. `psutil.virtual_memory()` reports system-wide memory, not the memory used by the current process. For process-specific metrics, `psutil.Process(os.getpid()).memory_info()` should be used. `torch.cuda.max_memory_allocated()` returns the *peak* memory usage. The `psutil` implementation here gets the *current* system memory usage, not the peak. This makes comparisons between CUDA and CPU/MPS environments invalid. `max_memory_reserved` is set to `mem.available`, which is the currently available system memory, not a measure of peak reserved memory for the process. These issues result in fundamentally incorrect metrics.

```suggestion
                # For local/dev environments.
                # NOTE: This reports current process memory usage, not peak.
                mem_info = psutil.Process(os.getpid()).memory_info()
                max_memory_allocated = mem_info.rss / (1024**3)
                max_memory_reserved = max_memory_allocated
```

- gemini-code-assist[bot] · comment · 2025-07-12T09:08:32Z · [source](https://github.com/verl-project/verl/pull/2495#discussion_r2202459456)

File: `verl/utils/profiler/performance.py` · line 48

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The memory statistics for non-CUDA/NPU devices are misleading. This implementation uses `psutil.virtual_memory()`, which reports system-wide memory usage, not the memory usage of the current process. This is inconsistent with the CUDA path, which reports process-specific memory, making comparisons between environments unreliable. Additionally, `mem_reserved` is set to `mem_free`, which is conceptually incorrect. Reserved memory should be greater than or equal to allocated memory. For system RAM, `mem_reserved` should likely be equal to `mem_allocated` since there is no caching allocator like in PyTorch for CUDA. To provide accurate and comparable metrics, you should report process-specific memory usage.

```suggestion
        process = psutil.Process(os.getpid())
        mem_info = process.memory_info()
        mem_total = psutil.virtual_memory().total
        mem_free = psutil.virtual_memory().available
        mem_allocated = mem_info.rss
        mem_reserved = mem_info.rss # For CPU/MPS, reserved is same as allocated
```
