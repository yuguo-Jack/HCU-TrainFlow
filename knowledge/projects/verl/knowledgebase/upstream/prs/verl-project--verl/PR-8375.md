# [perf, data] fix: backport fast multimodal special-token check for transformers < 5.15

[Upstream PR](https://github.com/verl-project/verl/pull/8375) · state: closed · merged: False

## Original PR description

### What does this PR do?

Fixes #8261.

With the pinned `transformers==5.12.1`, every processor call runs `ProcessorMixin._check_special_mm_tokens`, which does `list(ids).count(token_id)` on a tensor. That compares one scalar tensor at a time, so a long prompt pays ~0.5 s per call even when it has no image or video. huggingface/transformers#47580 (released in 5.15.0) fixes this by calling `tolist()` first.

Bumping transformers is blocked on the sglang / torch pins (see #8261, #8240), so this PR backports the fix inside `hf_processor`:

- `_check_special_mm_tokens_on_lists` converts `input_ids` to Python lists and then calls the upstream check, so the counting and the error message stay upstream's.
- `hf_processor` binds it to the processor instance only when transformers < 5.15.0 and the processor class does not override the check. With transformers >= 5.15.0 nothing changes.

Unlike the `return_tensors: null` workaround from the issue, this needs no config change and does not change what the processor returns.
