# [ci, vllm] fix: select Triton for L20 FP8 MoE test

[Upstream PR](https://github.com/verl-project/verl/pull/8326) · state: closed · merged: True

## Original PR description

### What does this PR do?

Follow up [#8308](https://github.com/verl-project/verl/pull/8308) by explicitly selecting the vLLM Triton Linear and MoE backends in the L20 FP8 MoE end-to-end test. #8308 made DeepGEMM the default for low-precision rollouts when no engine backend is configured, but L20 is SM89 and does not support that DeepGEMM path. The existing dense L20 smoke test already carries the same override; this change applies it to the Qwen3-30B-A3B MoE workflow as well.

This is not a duplicate: searches for [L20 Triton FP8 MoE](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+L20+Triton+FP8+MoE) and [the affected workflow](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+e2e_ppo_trainer_megatron_vllm_2) found no open PR addressing this test.

AI assistance was used to inspect backend-selection behavior, update the workflow, run checks, and prepare this PR description. The human submitter reviewed the change and is responsible for it.
