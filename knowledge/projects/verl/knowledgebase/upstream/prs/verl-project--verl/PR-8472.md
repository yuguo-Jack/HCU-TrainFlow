**Build the PR checkout of `verl` for every Ascend PR image.**

When a PR changes a Dockerfile and `requirements-npu.txt`, the PR build uses the changed Dockerfile but installs `verl` from a remote branch instead of the checked-out PR source. This can let the check pass while a later build uses the changed requirements and fails.

The main-image Dockerfiles clone the default branch. The v0.9.1 Dockerfiles clone `release/v0.9.1`. None of the A2, A3, or A5 jobs passes a `verl` source ref. Use the checked-out PR source for both main and v0.9.1 PR builds instead of cloning a remote branch.
