# [rollout, vllm, trainer] fix: restore default vLLM compile caching

[Upstream PR](https://github.com/verl-project/verl/pull/8167) · state: closed · merged: True

## Original PR description

### What does this PR do?

Resolve the TODO in `verl/trainer/constants_ppo.py` that disables vLLM's compile cache due to vllm-project/vllm#31199. That concurrent cache-write bug was fixed by vllm-project/vllm#35420, first included in vLLM 0.17.0; Torch 2.10+ also contains the native atomic-write fix from pytorch/pytorch#162432. verl now requires vLLM >=0.18.0, so remove the obsolete workaround and restore upstream defaults.

Explicit `VLLM_DISABLE_COMPILE_CACHE` values are still forwarded to Ray workers for troubleshooting. The checkpoint server-adapter test also uses upstream defaults. On recent Torch versions, removing this override also restores vLLM's default AOT selection.

No open PR addressing this change was found in the duplicate checks below. This PR does not claim to resolve the separate LoRA issue #3149. AI assistance was used to research and implement this change.
