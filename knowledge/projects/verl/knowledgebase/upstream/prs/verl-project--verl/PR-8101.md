# [rollout, reward] fix: align padding for asynchronous reward inputs

[Upstream PR](https://github.com/verl-project/verl/pull/8101) · state: open · merged: False

## Original PR description

### What does this PR do?

Fix asynchronous reward inputs for multi-output trajectories with different prompt lengths. `_compute_score` currently pads concatenated sequences independently from prompts/responses, so the response boundary in `attention_mask` can disagree with `responses`. Default reward managers then decode padding, truncate the final answer, or apply an incorrect DAPO length penalty.

For outputs with `(prompt_len, response_len) = [(3, 5), (9, 2)]`, the final two-token response is treated as length five; with `max_resp_len=7` and a four-token DAPO buffer, this introduces a spurious `-0.5` penalty. This fixes the input contract of the multi-output scoring introduced in #6228. No issue-closing claim is made.

### Design & Code Changes

- In `_compute_score`, reuse `_pad_token_ids` to left-pad prompts and right-pad responses to their respective trajectory maxima before concatenating IDs/masks and computing positions.
- Add CPU regressions and document the padding/length-metadata contract.
- Risk: custom consumers relying on the previous compact concatenated width now receive `max_prompt_len + max_response_len`; extreme length combinations can increase temporary padding. No performance benefit is claimed.
