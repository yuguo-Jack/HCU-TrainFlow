# [rollout] fix: keep the prompt out of an empty tool agent loop response

[Upstream PR](https://github.com/verl-project/verl/pull/8479) · state: closed · merged: False

## Original PR description

### What does this PR do?

Fixes `ToolAgentLoop.run` returning the prompt as the response when the first turn generates no tokens. Fixes #8478.

The final split is `response_ids = agent_data.prompt_ids[-len(agent_data.response_mask):]`. If the first generation is empty, `response_mask` is `[]` and the slice becomes `prompt_ids[-0:]`, which is the whole prompt. The loop does not crash: no tool calls are parsed, the state goes to TERMINATED, and the sample is emitted with `response_ids` equal to the prompt (cut to `response_length`), `response_mask` empty, and `prompt_ids` correct. After `_agent_loop_postprocess` the prompt tokens sit in the response region with `attention_mask=1` and `response_mask=0`, so the response is decoded and scored as prompt text and the prompt is counted in response length metrics.

Empty generations are produced by existing code paths: `vllm_async_server.py` returns `TokenOutput(token_ids=[], stop_reason="aborted")` when a request is aborted before its first token (`pause_generation(abort)`) or rejected at the weight sync gate, and `trtllm_async_server.py` does the same on rejection. #6675 already handled empty token lists in `_pad_token_ids` for this case.

`SingleTurnAgentLoop` already guards the same slice (`... if response_mask else []`, `single_turn_agent_loop.py:91`). This PR applies the same guard to `ToolAgentLoop`.
