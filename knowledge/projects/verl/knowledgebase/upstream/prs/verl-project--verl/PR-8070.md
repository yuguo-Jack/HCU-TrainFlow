# [rollout] feat: expose a server manager replica-size hook

[Upstream PR](https://github.com/verl-project/verl/pull/8070) · state: open · merged: False

## Original PR description

### Summary

Extract the existing footprint calculation into `LLMServerManager._get_rollout_replica_world_size()`. Custom rollout managers can override this method rather than copy `_initialize_llm_servers`, preserving upstream initialization and metrics behavior. The default TP/DP/PP and prefill/decode calculations are unchanged.

Requested during [verl-omni #656 review](https://github.com/verl-project/verl-omni/pull/656#discussion_r4118154957), where sequence-parallel replicas currently require a downstream lifecycle override. Replica implementations remain responsible for matching worker slicing and rank mapping to their footprint.

Searched open PRs for `replica size hook`, `rollout_world_size`, `_initialize_llm_servers`, and `LLMServerManager replica`: [search](https://github.com/verl-project/verl/pulls?q=is%3Apr+is%3Aopen+%22replica%22+%22hook%22).

This PR adds no topology validation and changes no replica/adapter placement logic; it provides only the downstream extension point. No open PR implementing this hook was found.

### Usage

```python
class DiffusionLLMServerManager(LLMServerManager):
    def _get_rollout_replica_world_size(self):
        return super()._get_rollout_replica_world_size() * self.rollout_config.ulysses_degree
```

This example assumes the downstream replica already uses the same SP footprint for slicing and rank mapping.
