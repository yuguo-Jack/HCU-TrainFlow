# [ci] fix: trigger the SFT e2e workflows on the config they actually load

[Upstream PR](https://github.com/verl-project/verl/pull/7925) · state: open · merged: False

## Original PR description

### What does this PR do?

The three SFT e2e workflows list two entrypoint paths that no longer exist:

```yaml
      - "verl/trainer/fsdp_sft_trainer.py"
      - "verl/trainer/config/sft_trainer.yaml"
```

A `paths:` entry naming a missing file still parses and GitHub reports nothing — it simply never matches again.

The trainers these jobs actually run are `verl/trainer/sft_trainer.py` (spmd) and `verl/trainer/sft_trainer_ray.py` (ray), both selected in `tests/special_e2e/sft/run_sft_engine.sh`:

```bash
if [ "$mode" = "spmd" ]; then
  ENTRYPOINT=${ENTRYPOINT:-"-m verl.trainer.sft_trainer"}
else
  ENTRYPOINT=${ENTRYPOINT:-"-m verl.trainer.sft_trainer_ray"}
fi
```

and both load `sft_trainer_engine.yaml`, not `sft_trainer.yaml`:

```python
@hydra.main(config_path="config", config_name="sft_trainer_engine", version_base=None)
```

**Scoping the actual impact, because it's narrower than it first looks.** These blocks start with `**/*.py`, and GitHub applies path filters in order with last-match-wins, so I simulated the ordered list rather than assuming:

| changed file | triggers before | triggers after |
|---|---|---|
| `verl/trainer/sft_trainer.py` | ✅ | ✅ |
| `verl/trainer/sft_trainer_ray.py` | ✅ | ✅ |
| `verl/trainer/config/sft_trainer_engine.yaml` | ❌ | ✅ |

The two `.py` files are already covered by the leading `**/*.py`, and no later negative entry excludes them. So the **real** gap is the config: `sft_trainer_engine.yaml` is 85 lines of live training config (batch sizes, `use_dynamic_bsz`, engine/optim defaults) that these three jobs load on every run, and today it matches no entry at all — editing it runs none of them.

I'd rather state that precisely than oversell it. Repointing the `.py` entries is then mostly about the block saying what it means, instead of naming two deleted files.
