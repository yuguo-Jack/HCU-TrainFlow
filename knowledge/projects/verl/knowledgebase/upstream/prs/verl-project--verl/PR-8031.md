# [megatron] fix: stop MTP loss from updating the LM head

[Upstream PR](https://github.com/verl-project/verl/pull/8031) · state: open · merged: False

## Original PR description

### What does this PR do?

With MTP training enabled on megatron-core versions that provide `process_mtp_loss` (including the pinned `core_v0.18.0`), the MTP loss silently updates the LM head, and also the input embedding when `share_embeddings_and_output_weights=True`. This PR detaches the output-layer weight on that path so the MTP loss only trains the MTP block, matching the legacy branch of the same function.

Origin: #6648 ("MTP compatible with latest mcore") added the `_HAS_PROCESS_MTP_LOSS` branch in `verl/models/mcore/mtp_patch.py` and passes `self.output_layer` / `output_weight` to `process_mtp_loss` as-is, while the legacy branch below it still detaches them ("Detach output-layer params so MTP loss does not update lm_head."). Related: draft #7826 edits the same file but does not touch this path, so this is not a duplicate.

Mechanism: Megatron's `process_mtp_loss` (`megatron/core/transformer/multi_token_prediction.py` in `core_v0.18.0`) computes MTP logits with `output_layer(hidden_states_list[k + 1], weight=output_weight, ...)` and attaches the MTP loss to the main hidden states through `MTPLossAutoScaler`, whose backward injects a gradient for the MTP loss regardless of the main loss. Because neither the module weight (untied) nor the shared weight (tied) is detached, that gradient flows into the LM head. In RL the LM head is part of the policy, so this biases the policy update with an objective unrelated to the reward. The fix wraps the output layer in `detached_output_layer`, which resolves the weight (module weight when `weight=None`, otherwise the shared weight) and passes it detached; `ColumnParallelLinear` then takes its frozen-weight path (`linear_with_frozen_weight`), while gradients still reach the MTP hidden states.

AI assistance (Claude Code) was used to write this change and run the tests below.

### Test

New CPU test `tests/utils/test_megatron_mtp_detach_lm_head_on_cpu.py` drives the real megatron-core `process_mtp_loss` with a CPU output layer whose `forward` signature is asserted equal to `ColumnParallelLinear.forward`, backpropagates only the MTP loss, and checks: a negative control (undetached layer gets a nonzero LM-head grad), no grad on the untied LM head, no grad on a tied shared weight, nonzero grad on the MTP hidden states, and that `_megatron_gptmodel_postprocess` hands `process_mtp_loss` the detached wrapper.
