## Original PR description

# GIFT: Group-relative Implicit Fine-Tuning

GIFT is an **on-policy reinforcement learning framework for aligning large language models (LLMs)**. It unifies key ideas from **GRPO, DPO, and UNA** while avoiding many of their practical limitations. 

You can test it on "examples/gift_trainer/test_qwen_gift_math_3e-6_1.slurm" which utilizes DAPO's data for training and AIME's data for evaluation.

The core idea is simple: instead of directly maximizing rewards with complex RL objectives, GIFT **matches rewards within small sampled groups**, turning alignment into a **stable, regression-like learning problem**.

---

## Why GIFT?

Aligning LLMs with reinforcement learning is powerful but often unstable:

* PPO-style methods require careful clipping and value estimation
* Offline methods (like DPO / UNA) lack exploration
* Reward scaling and normalization are hard to tune

GIFT addresses these issues with a cleaner and more robust objective.

---

## Core Idea (Intuition)

1. **Sample a group of responses on-policy** for the same prompt
2. **Compute two signals** for each response:

   * An *explicit reward* (from a reward model or heuristic)
   * An *implicit reward* derived from how the policy differs from a reference model
3. **Normalize both signals within the group** (center and scale them)
4. **Train the policy to match the two normalized signals using simple regression**

Because everything is done *relative to the group*, problematic global normalization terms disappear automatically.

---

## What This Buys You

* **Stable training** – no PPO clipping, no value function
* **Low-variance gradients** – group-relative normalization
* **Fast convergence** – behaves like supervised learning
* **On-policy exploration** – unlike offline preference methods

In practice, this makes RL alignment **much easier to scale and tune**.

---

## How GIFT Relates to Prior Work

* **GRPO**: keeps on-policy sampling, but removes heavy RL machinery
* **DPO**: shares the idea of implicit rewards, but works on-policy
* **UNA**: aligns implicit and explicit rewards, but with group-relative normalization

GIFT can be seen as a **unifying framework** that combines the strengths of all three.

The current implementation of `compute_gift_outcome_advantage` uses multiple Python loops to iterate over tensors for grouping and normalization. This is highly inefficient and will cause a performance bottleneck, especially when running on GPUs. This logic can be vectorized for significant performance improvement, similar to `compute_grpo_vectorized_outcome_advantage`. You can use `verl.utils.as_torch_index` and `verl.utils.group_mean_std` to achieve this.

```suggestion
    with torch.no_grad():
        g = as_torch_index(index, device=scores.device)
        mean_g, std_g, _ = group_mean_std(scores, g, eps=epsilon)

        # group_mean_std handles singleton groups by returning mean=0, std=1.
        scalars = (scores - mean_g[g]) / (std_g[g] + epsilon)

        scores = scalars.unsqueeze(-1) * response_mask
```

The current implementation of `normalize_gift_kl` uses multiple Python loops to iterate over tensors for grouping and normalization. This is inefficient and will be a performance bottleneck on GPUs, especially inside the training loop. This logic can be vectorized for significant performance improvement. Also, the `id2indices` variable is unused and can be removed.

A vectorized implementation would avoid these loops and be much faster.

```python
    g = as_torch_index(index, device=kl_div_sum.device)

    with torch.no_grad():
        kl_detached = kl_div_sum.detach()
        G = int(torch.max(g).item()) + 1 if g.numel() > 0 else 0

        count_g = torch.zeros(G, device=g.device, dtype=torch.float32).index_add_(0, g, torch.ones_like(kl_detached))

        # Calculate mean and std for multi-element groups
        sum_g = torch.zeros(G, device=g.device, dtype=torch.float32).index_add_(0, g, kl_detached)
        sum_sq_g = torch.zeros(G, device=g.device, dtype=torch.float32).index_add_(0, g, kl_detached.square())

        mean_g = sum_g / count_g.clamp_min(1.0)

        # Sample variance: sum((x - mu)^2) / (n-1)
        var_g_num = sum_sq_g - sum_g.square() / count_g.clamp_min(1.0)
        var_g_den = (count_g - 1).clamp_min(1.0)
        var_g = var_g_num / var_g_den
        std_g = torch.sqrt(var_g.clamp_min(0.0))

        # Get per-item stats
        mean_per_item = mean_g[g]
        std_per_item = std_g[g]

        # Handle single-element groups as in the original implementation
        is_singleton = count_g[g] <= 1
        mean_per_item[is_singleton] = kl_detached[is_singleton]
        std_per_item[is_singleton] = 1.0

    # Debug: print group statistics
    if debug:
        num_groups = len(torch.unique(g))
        group_sizes = torch.bincount(g)
        print(f"[GIFT KL Norm] num_groups={num_groups}, group_sizes={group_sizes.tolist()[:5]}{'...' if len(group_sizes) > 5 else ''}")
        if num_groups > 0:
            first_uid_idx = g[0].item()
            print(f"[GIFT KL Norm] first_group: uid={index[0]}, size={group_sizes[first_uid_idx].item()}, "
                  f"mean={mean_per_item[0].item():.4f}, std={std_per_item[0].item():.4f}")

    # Normalize KL (gradients flow through kl_div_sum, not mean/std)
    kl_div_sum_normalized = (kl_div_sum - mean_per_item) / (std_per_item + epsilon)
```
