# [trainer] fix: configure bypass mode before workers are created

[Upstream PR](https://github.com/verl-project/verl/pull/8348) · state: closed · merged: False

## Original PR description

### What does this PR do?

**Problem.** `algorithm.rollout_correction.bypass_mode=true` skips the old-log-prob forward and uses `old_log_probs = rollout_log_probs`. The actor should then train with `loss_mode=bypass_mode`, but it silently keeps the default vanilla PPO loss, anchored at the rollout policy. Rollout IS / RS settings have no effect.

**Root cause.** Actor workers get their copy of the config when they are created. The legacy trainer switches `actor.policy_loss.loss_mode` to `bypass_mode` inside the training loop (`apply_bypass_mode`), which changes only the trainer's own copy. The v1 trainer does not switch it at all.

**Fix.**
- New `configure_bypass_mode(config)` sets `actor.policy_loss.loss_mode=bypass_mode` and copies `algorithm.rollout_correction` into `actor.policy_loss.rollout_correction`. An explicitly configured non-vanilla loss (e.g. gspo) is kept.
- It is called in the trainer constructors before any worker is created: legacy, v1 (`trainer_base.py`), fully async and one-step-off.
- `apply_bypass_mode(batch)` now only substitutes the log-probs.
- With the bypass loss, rollout-correction metrics are computed per micro-batch in the worker. A micro-batch can contain only padding, and on main that raises `ValueError: response_mask must contain at least one valid token`. The checks are removed: masked max/min return 0.0 and ESS returns 0 when there are no valid tokens.
- The docs no longer ask users to set the actor loss by hand.

Fixes #4912. #4930 also moves the config change out of the training loop, but only into the legacy trainer's `init_workers`. This PR also covers the v1, fully async and one-step-off trainers, and handles padding-only micro-batches.

### Test

- A/B on Qwen3-8B, upstream main vs this PR. Setup: GRPO, FSDP2 + vLLM, v1 `main_ppo`, 1 node × 4 GPUs, 3 steps, `bypass_mode=True loss_type=reinforce rollout_is=token`. Both arms skip the old-log-prob forward (`timing_s/old_log_prob` about 0.04 s, a copy). On main the actor runs vanilla PPO: it logs `actor/pg_clipfrac` and no `rollout_corr/*` metrics, so the IS setting is ignored. With this PR the actor runs the bypass loss: it logs `rollout_corr/rollout_is_mean` = 0.9997 / 1.0002 / 1.0003 and the other `rollout_corr/*` metrics, and no `pg_clipfrac`.
- Existing `tests/trainer/ppo/test_rollout_corr.py`, `test_rollout_corr_integration.py`, `test_core_algos_on_cpu.py`, `test_score_centering_on_cpu.py` and `test_score_centering_metrics_on_cpu.py`: 113 passed on both main and this PR. An all-padding mask passed to `compute_rollout_correction_and_rejection_mask` (token IS, sequence IS with batch normalize, token IS + token_k1 RS) raises `ValueError` on main and returns finite metrics with this PR.
