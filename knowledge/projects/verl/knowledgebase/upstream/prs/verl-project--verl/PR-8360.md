# [reward] fix: support APPS/TACO list-formatted call-based test cases in prime_code

[Upstream PR](https://github.com/verl-project/verl/pull/8360) · state: closed · merged: False

## Original PR description

## What does this PR do?

Fixes #8174.

For `data_source` in `("apps", "taco", "codecontests", "codeforces")` without a `sandbox_fusion_url`, `default_compute_score` falls back to `prime_code`. In `verl/utils/reward_score/prime_code/testing_util.py`, the `CODE_TYPE.call_based` branch of `run_test` assumed LiveCodeBench-style JSON-line string inputs and JSON-encoded string outputs (`inputs.split("\n")` and `json.loads(output)`).

In APPS and TACO datasets, call-based `inputs` are already stored as pre-parsed argument lists (e.g. `[[1, 2], [3, 4]]`) and `outputs` as native values (e.g. `[3, 7]` or native strings). Calling `.split("\n")` on a list raised `AttributeError` before executing any test case, causing `default_compute_score` to return `0.0` even for a correct solution.

This PR checks `isinstance(inputs, str)` per test case so both JSON-line string layouts and pre-parsed list layouts are handled properly, and converts non-string `raw_inputs` / `raw_outputs` before passing them to `truncatefn`.

## Testing

- Added CPU unit tests in `tests/utils/reward_score/test_prime_code_on_cpu.py` verifying `default_compute_score` and `check_correctness` across both APPS/TACO list layouts and JSON-line string layouts, including native string return values and wrong-answer metadata formatting.
