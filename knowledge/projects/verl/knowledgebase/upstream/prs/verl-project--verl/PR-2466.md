# [rollout] feat: implemented the persistable replay buffer feature

[Upstream PR](https://github.com/verl-project/verl/pull/2466) · state: open · merged: False

## Original PR description

## **Implemented the replay buffer to have the following features:**
**1. Large-scale data storage**
Uses an in-memory cache combined with RocksDB, preventing OOM issues when handling large data storage and transfers, such as when storing rollout results.

**2. Customizable sampling strategies**
Supports pluggable samplers, with uniform sampling and p-time sampling already implemented.

**3. Data persistence**
Allows other trials or the same trial after restarting to reuse data in the replay buffer.

## **Performance:**
Achieved QPS comparable to Python dict. During rollout, the performance is similar to the baseline (using a python dict) when most data is in the in-memory cache. However, access times may increase as more data resides in RocksDB.

## **Links for other information:**
User manual: https://github.com/volcengine/verl/issues/2584
RFC: https://github.com/volcengine/verl/issues/2539

Deserializing data with `pickle.loads` from a potentially untrusted source like a database file is a major security vulnerability. - gemini-code-assist[bot] · comment · 2025-07-10T21:58:35Z · [source](https://github.com/verl-project/verl/pull/2466#discussion_r2198834033)

File: `verl/utils/replay_buffer/task_processor.py` · line None

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

This method executes P1 tasks (EVICT, POPULATE) which modify the LRU cache (`self._cache`). However, it does not acquire the `_p0_lock`. The `get()` method in `PersistableReplayBufferClient` acquires this lock before accessing the cache. This creates a race condition where a user thread calling `get()` can access the cache concurrently with the task processor thread modifying it here. This can lead to data corruption or crashes. You should acquire `self._p0_lock` here to ensure exclusive access to the cache, similar to how it's done in `_execute_p0_q`.
