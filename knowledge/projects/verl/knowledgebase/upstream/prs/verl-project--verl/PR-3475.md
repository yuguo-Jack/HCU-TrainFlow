# [trainer] feat: Data buffering to conserve data during filtering

[Upstream PR](https://github.com/verl-project/verl/pull/3475) · state: open · merged: False

## Original PR description

### What does this PR do?

Current DAPO implementation discards all the extra samples during filtering below, wasting lots of samples

```python
traj_bsz = self.config.data.train_batch_size * self.config.actor_rollout_ref.rollout.n
batch = batch[:traj_bsz]
```

This PR wraps a SmartDataloader object around the dataloader, returning unused samples back to the front of the dataloader to be used by the next batch. It also has the option to return the filtered-out samples to the BACK of the dataloader to be used at the end of the epoch, so a supposedly improved model can train on these samples again.

<img width="991" height="635" alt="Screenshot 2025-09-14 at 10 48 33 PM" src="https://github.com/user-attachments/assets/dd1461f9-52af-4291-b2ce-72a41348bcb6" />

### Design

`class DataBuffer` simply holds a list of `DataProto` objects for easy access.
`class SmartDataLoader` controls two buffers, unused_buffer (during `batch = batch[:traj_bsz]`) which will contain samples to be called _immediately_ in the next batch, and an optional filtered_buffer, which will contain samples to be called at the end of the epoch when the dataloader is exhausted.

In other words, the `SmartDataLoader` is a 3-stage data-retrieval process:
1. From unused_buffer
2. From `train_dataloader`
3. From filtered_buffer

- `data_con` in metrics logs the number of samples saved (which is usually a lot)

### Usage Guide

Simply add 
```sh
data.databuffer.enable=true \
data.databuffer.keep_filtered=true \
```
to any run.sh scripts

The `__init__` method has a critical flaw. If `self.config.enable` is `False`, it returns early, leaving `self.unused_buffer` and `self.filtered_buffer` uninitialized. This will cause an `AttributeError` when other methods like `get_stats()` or `return_unused_samples()` are called, as they are not guarded against this case. Additionally, `self.filtered_buffer` is only initialized if `self.config.keep_filtered` is true, which can lead to an `AttributeError` in `get_batch_for_generation` if `keep_filtered` is false. To prevent crashes, these attributes must always be initialized.

```suggestion
    def __init__(self, dataloader, config):
        self.config = config
        self.dataloader = dataloader
        self.dataloader_iter = iter(dataloader)
        self.dataloader_exhausted = False
        self.reached_epoch_end = False         # mark that we hit StopIteration (before refresh)

        # Always initialize buffers to prevent AttributeErrors.
        self.unused_buffer = DataBuffer()
        self.filtered_buffer = DataBuffer() if self.config.keep_filtered else None
        self.data_history = set()  # track seen data UIDs
        self.current_batch_remainder = None

        if self.config.enable:
            print("DEBUG: SmartDataLoader initialized")
```
