# [trainer, rollout, cfg, doc] feat: experimental teacher-generated distillation rollouts

[Upstream PR](https://github.com/verl-project/verl/pull/8335) · state: open · merged: False

## Original PR description

### What does this PR do?

Adds experimental teacher-generated rollouts for distillation. A user function chooses the student or teacher once per training batch; the existing teacher server generates teacher responses and scores the completed sequences. Validation always uses the student. With no selector, training keeps its existing behavior.

Addresses #8334. This stays a draft pending RFC feedback and human review.

### API and Usage Example

```yaml
distillation:
  rollout_source_selector:
    path: pkg://verl.experimental.teacher_rollout
    name: select_source
    kwargs: {teacher_probability: 0.5}
```

Custom selectors receive `batch`, `global_step`, and `seed`, and return `"student"` or `"teacher"`. The built-in selector derives reproducible choices from the seed and step.

Initial support: synchronous V1, vLLM, one teacher model, single-turn text, and supervised `forward_kl_topk`. Use temperature `1.0`, disable policy gradients and task rewards, and set `rollout.calculate_log_probs=False`.

### Design & Code Changes

`verl.experimental.teacher_rollout` owns selection, configuration checks, source assignment, and rollout metrics. The shared trainer and TransferQueue retain small integration hooks. Teacher routing stays in the experimental agent loop; generation and scoring remain separate requests. Docs and tests cover the experimental API.
