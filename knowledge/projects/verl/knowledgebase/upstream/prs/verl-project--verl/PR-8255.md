# [model, fsdp] fix: Qwen3.5 decoder layer forward on transformers >= 5.13

[Upstream PR](https://github.com/verl-project/verl/pull/8255) · state: open · merged: False

## Original PR description

## Motivation
The reason for this PR is to resolve a future or the needs of using non pinned transformers.
from current pinned 5.5.3,!=5.6.0,<5.13

## What is wrong

`qwen3_5_decoder_layer_forward` (the patched `Qwen3_5DecoderLayer.forward`) reads `self.layer_type`.
transformers 5.13.0 renamed that decoder-layer attribute to `block_type`, so on transformers >= 5.13 the first
forward raises:

    AttributeError: 'FSDPQwen3_5DecoderLayer' object has no attribute 'layer_type'

(The `FSDP...` prefix is just FSDP2's dynamic subclass of the layer; the attribute is missing on the layer itself.)

Which transformers versions have which name (checked from the wheels' `modeling_qwen3_5.py`):

| transformers | `Qwen3_5DecoderLayer` attribute |
|---|---|
| 5.10.4, 5.11.0, 5.12.0 | `layer_type` |
| 5.13.0 - 5.17.0 | `block_type` |

## Fix

Read the name that exists: `getattr(self, "layer_type", None) or self.block_type`. Works on both sides of the rename,
so the pin can move later without another change.

## Test

New CPU-only unit test `tests/models/test_qwen3_5_decoder_layer_forward.py` (tiny random full-attention layer).

| transformers | before | after |
|---|---|---|
| 5.12.1 | pass | pass |
| 5.17.0 | FAIL (AttributeError above) | pass |
