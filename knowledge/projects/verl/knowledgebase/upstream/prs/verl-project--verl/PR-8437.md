# [tests, hardware] pytest changes for device-agnostic case 

[Upstream PR](https://github.com/verl-project/verl/pull/8437) · state: closed · merged: True

## Original PR description

## What does this PR do?

Follow-up to the earlier cuda/nccl test device-agnostic cleanup. A second pass over `tests/`
found several files that were still hardcoding `"cuda"` or asserting against `torch.cuda`
directly instead of going through `verl.utils.device`'s platform helpers (`get_device_name()`,
`get_torch_device()`, `is_device_available()`, `get_nccl_backend()`, `get_platform()`). That
breaks these tests on any non-CUDA accelerator even though the product code they're testing
already resolves the device generically.

Scope note: checkpoint-engine backend names such as `"nccl"` are registry keys, not torch
backends, and are left as-is — as are the megatron/NPU/trtllm/sglang-specific tests and the
tests that intentionally mock `torch.cuda`.

CUDA behavior is unchanged: every helper resolves to `cuda` on a CUDA host, so this is a
no-op there and only changes behavior on other accelerators.

## API and Usage Example

## Design & Code Changes

- `test_correctness_on_gpu.py`: assert `get_device_name()` for `kv_buffer_device` instead of `"cuda"`.
- `test_vllm_topk_support.py`: create tensors on `get_device_name()`.
- `test_chunked_topk_log_probs_on_cpu.py`: gate the low-precision GPU case on `is_device_available()` instead of skipping on every non-CUDA accelerator.
- `test_fsdp2_pinned_model_transfer.py`: build the model, mesh, and assertions on the platform device; cuda and xpu run, other devices keep the early exit.
- `test_worker_group_basics.py`: request an accelerator through `get_platform().ray_resource_options()`.
- `test_worker_group_torch.py`: use `get_nccl_backend()`, `get_device_name()`, `get_torch_device()`.
- `test_linear_cross_entropy_on_cpu.py`: build device strings from `get_device_name()`; forbid probing both `torch.cuda` and the platform's device module.
- `test_value_loss_normalization_on_cpu.py`: run the accelerator case on whatever accelerator is present.
- `test_fsdp2_cpu_offload_state_dict.py`: match the platform device in the expected device-mismatch message.
- `test_fsdp2_model_cpu_offload.py`: assert via the platform device.
- `test_special_linear_cross_entropy_tp.py`: use `get_nccl_backend()`, `get_device_name()`, `get_torch_device()`.
- `test_vllm_pd_disaggregation_on_cpu.py`: assert against the product code's own `get_device_name()` report instead of `"cuda"`.

AI assistance was used to review the diff and run/verify the test suite above; the submitter
reviewed every changed line and the test results before submitting.

**Enable CANN logits before comparing entropy on NPU.**

On NPU, `linear_cross_entropy` can dispatch to `CannLinearCrossEntropy`. With `VERL_NPU_LCE_RETURN_LOGITS` unset, the implementation does not request vocab logits. If CANN returns no softmax, it returns a zero entropy placeholder, while the Torch reference computes entropy. The unconditional assertion at line 404 can then fail.

Set `VERL_NPU_LCE_RETURN_LOGITS=1` for this test, or compute entropy through a path that does not depend on the optional CANN softmax output.
