# [data] fix: re-raise ImportError in overlong prompt filter instead of dropping all rows

[Upstream PR](https://github.com/verl-project/verl/pull/8221) · state: open · merged: False

## Original PR description

### What does this PR do?

When an optional dependency is missing (for example `qwen_vl_utils` for multimodal data), `_process_multi_modal_info` raises `ModuleNotFoundError` inside `doc2len` for every sample. The catch-all `except Exception` in `maybe_filter_out_long_prompts`, added in #3814 to drop malformed rows, swallows it and returns `max_prompt_length + 1`, so the filter silently drops the whole dataset. Training then fails much later with an unrelated error:

```
ValueError: num_samples should be a positive integer value, but got num_samples=0
```

A missing package is an environment problem, not malformed data, so this PR re-raises `ImportError` (which covers `ModuleNotFoundError`) in both `doc2len` paths. Malformed rows are still dropped as before.

Related: #6888 moves these two functions to module level (`_filter_prompt_length_with_processor` / `_filter_prompt_length_with_tokenizer`). If it lands first, the same two lines apply there and I'm happy to rebase.

Added `test_maybe_filter_out_long_prompts_reraises_import_error` to `tests/utils/dataset/test_rl_dataset_on_cpu.py`. It patches `_process_multi_modal_info` to raise `ModuleNotFoundError` and asserts the filter raises `ImportError` instead of returning an empty dataset.

- Before the fix: `Failed: DID NOT RAISE ImportError` (captured output shows `filter dataset len: 0`)
- After the fix: passes, and all 11 tests in the file pass locally

Found while running the CPU dataset tests locally without `qwen_vl_utils` installed: `test_image_rl_data` failed with the `num_samples=0` error above.
