# [fsdp] fix: prevent NPU parameter corruption during FSDP2 CPU offload

[Upstream PR](https://github.com/verl-project/verl/pull/8187) · state: open · merged: False

## Original PR description

### What does this PR do?

Prevent parameter corruption when offloading an FSDP2 model from NPU to CPU with uneven parameter shards.

With `model.to("cpu", non_blocking=True)`, the NPU-to-CPU transfer can still be in progress when FSDP2 repads the local shard. This repadding happens inside `FSDPModule._apply`, before `model.to()` returns: it allocates padded CPU storage and copies the transferred values into it. Reading the unfinished transfer can therefore persist incorrect parameter values in the new storage. Synchronizing after `model.to()` returns is too late to repair them.

This PR uses blocking CPU transfers on NPU and applies the same policy to both runtime offloading and `fsdp2_load_full_state_dict`. The CUDA non-blocking transfer path is preserved.

The issue was identified while investigating a multi-node Qwen3-Omni accuracy drop related to [vllm-omni#8039](https://github.com/vllm-project/vllm-omni/issues/8039). A 4304-element vision bias divides evenly across 16 ranks, but requires padding across 32 ranks: the nominal shard size is 135 and the final rank owns 119 elements. The investigation localized parameter corruption to this uneven tail during CPU offloading.

The regression requires no model weights. It checks complete BF16 vectors for 27 uneven/even parameter pairs, covering:

- Initial sharding and full-state loading with CPU offload.

- Repeated offload/reload cycles.

The uneven vectors exercise repadding with two ranks and reproduce the 4304-element, 135/119 shard layout with 32 ranks.

The existing CUDA pinned-transfer regression has not been rerun for this commit. Full pre-commit execution and end-to-end NextQA accuracy validation also remain pending.

### API and Usage Example

No public API or configuration changes are required. Existing callers automatically use blocking NPU-to-CPU transfers through the FSDP2 offload helper.

NPU offloading now waits for transfer completion; its performance impact has not yet been measured.
