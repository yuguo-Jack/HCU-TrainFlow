# [megatron, doc] fix: keep bridge layer specs and the causal mask under QAT

[Upstream PR](https://github.com/verl-project/verl/pull/8361) · state: closed · merged: True

## Original PR description

### What does this PR do?

Fixes two ways Megatron QAT breaks because of the layer spec the engine builds the model from, and corrects the Hopper note in the QAT guide. Both came out of the MXFP4 recipe checks reported in #8186.

**1. Models whose Megatron-Bridge bridge sets its own layer spec fail under QAT.** With QAT enabled, the engine replaced every provider's `transformer_layer_spec` with `modelopt_transformer_layer_spec`. Megatron-Bridge maps the HF weights onto the modules of the spec the bridge chose, and more than twenty bridges set their own (OLMoE, Qwen3-Next, text-only Qwen3.5, DeepSeek-V2/V3/V4, GLM, Kimi, MiniMax, ...). Under the ModelOpt spec those models lose modules. OLMoE fails at load:

```
ValueError: Shape mismatch for megatron param decoder.layers.0.self_attention.k_layernorm.weight
```

By the same code path, Qwen3-Next and text-only Qwen3.5 would lose their linear-attention layers (from reading the bridges; not run). Qwen3.5 checkpoints (`Qwen3_5MoeForConditionalGeneration`) only escape because the Qwen3.5 VL provider builds its language block without reading `transformer_layer_spec`, so their QAT already runs on the TE spec.

The engine now switches to the ModelOpt spec only when the provider uses Bridge's default GPT spec (`default_layer_spec`). Any other spec is kept, and ModelOpt quantizes its Transformer Engine modules in place (`TELayerNormColumnParallelLinear`, `TERowParallelLinear`, the grouped expert linears, ...). Models on the default spec are unchanged.

**2. Packed THD sequences fail at the first forward when context parallelism is 1** (`use_remove_padding=True`, the default):

```
AssertionError: Attention mask type must be padding or padding_causal for qkv_format=thd!
```

When `use_arbitrary_attention_mask` is unset, `modelopt_transformer_layer_spec` turns it on for CP=1; the arbitrary mask is meant for speculative-decoding training. Transformer Engine then rejects verl's THD inputs. This PR defaults the flag to `False` under the ModelOpt spec, which keeps the causal mask that the non-QAT TE spec uses. An explicit `override_transformer_config.use_arbitrary_attention_mask` still wins.

**3. Docs.** `docs/low_precision/qat.md`:
- The `MXFP4` preset has no Marlin fallback: its MXFP4-weight × FP8-activation experts are served only by vLLM's DeepGEMM FP4 MoE kernel (SM100/SM120), so on Hopper the rollout fails at engine start.
- New limitation: the ModelOpt spec's expert module (`SequentialMLP`) rejects tensor and expert parallelism together, so default-spec models need TP=1 or EP=1 under QAT. Models with their own spec keep it.

- wuxibin89 · comment · 2026-10-26T11:28:18Z · [source](https://github.com/verl-project/verl/pull/8361#issuecomment-6414899795)

I think the two paths can be unified by always keeping the layer spec selected by Megatron-Bridge, including for providers using `default_layer_spec`, instead of switching those providers to `modelopt_transformer_layer_spec`.

`apply_qat_to_modules()` subsequently calls `mtq.quantize()` on every model chunk and instruments supported modules in place. Current ModelOpt registers the relevant MCore/TE modules, including `TELayerNormColumnParallelLinear`, `TERowParallelLinear`, `TEColumnParallelLinear`, `TEColumnParallelGroupedLinear`, `TERowParallelGroupedLinear`, and `TEGroupedMLP`. The custom-spec OLMoE result in this PR already demonstrates this in-place path.

Keeping the default TE spec as well could:

- avoid maintaining two QAT model topologies;
- avoid the ModelOpt spec’s `SequentialMLP` TP+EP restriction;
- avoid its arbitrary-attention-mask default for THD inputs;
- keep QAT and non-QAT weight mapping/module structure aligned.

Could we test Qwen3-MoE with its original default TE spec (forward/backward plus export/refit), and if that passes, remove the layer-spec replacement entirely? The main thing to verify would be quantizer coverage and exported expert scales for each supported QAT mode.
