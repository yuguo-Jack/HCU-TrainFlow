# [reward] fix: handle dict-returning score functions in PrimeRewardManager

[Upstream PR](https://github.com/verl-project/verl/pull/8217) · state: open · merged: False

## Original PR description

Fixes #8216

### What does this PR do?

`parallel_compute_score_async` in `PrimeRewardManager` had no branch for dict results, so dict-returning reward functions (math_dapo, rlla, ...) hit `float(result[0])`, raised `KeyError: 0`, and `verify()`'s except-all fallback silently zeroed the whole batch.

This adds the same `isinstance(result, dict) -> result["score"]` handling that `NaiveRewardManager` / `BatchRewardManager` / `DAPORewardManager` already have.

### Tests

New `tests/workers/reward_manager/test_prime_on_cpu.py` (CPU-only):
- dict result -> uses "score" key (failed before this fix)
- float / tuple (prime_math style) results unchanged
- failing task still scores 0.0

Full `tests/workers/reward_manager/` suite: 22 passed.
