# fix(vllm): Python 3.10+ event loop compatibility for sync mode

[Upstream PR](https://github.com/verl-project/verl/pull/4939) · state: open · merged: False

## Original PR description

### What does this PR do?

This PR fixes event loop initialization for Python 3.10+ compatibility when using sync rollout mode (required for PRIME training).

**Problem**: vLLM rollout worker fails on Python 3.10+ with sync mode:
```
RuntimeError: no running event loop
```

**Root Cause**: Current code uses `get_event_loop()` which internally calls deprecated `asyncio.get_event_loop()`. In sync mode (no running event loop), this fails on Python 3.10+.

**Solution**: Replace with `asyncio.get_running_loop()` and fallback:
```python
# Before
loop = get_event_loop()

# After
try:
    loop = asyncio.get_running_loop()
except RuntimeError:
    loop = asyncio.new_event_loop()
    asyncio.set_event_loop(loop)
```

Actually, this is exactly the error we encountered in production:
```
RuntimeError: no running event loop
File "vllm_rollout_spmd.py", line 575, in _init_zeromq
    loop = asyncio.get_running_loop()
```

**Root cause**: When using `mode: sync` for PRIME training, Ray workers don't have an async context by default. The ZeroMQ initialization expects to run inside an async context.

The existing `get_event_loop()` helper didn't handle this case — we got `RuntimeError: no running event loop` until we added the try/except fallback.

Our fix:
```python
try:
    loop = asyncio.get_running_loop()
except RuntimeError:
    loop = asyncio.new_event_loop()
    asyncio.set_event_loop(loop)
```

This creates a new event loop when none exists (sync mode), which resolved the issue.

Tested on Python 3.10+ with PRIME training in sync mode — works correctly now.
