# Fix math_dapo Minerva extraction for markdown-decorated answers

[Upstream PR](https://github.com/verl-project/verl/pull/8485) · state: closed · merged: False

## Original PR description

## Bug

Models commonly wrap the Minerva `Answer:` label in markdown bold/italic (`**Answer:** 42`, `Answer: **42**`, `**Answer:**\n\n42`). The existing regex captures the `*` markers as part of the answer, so correct answers score -1.0.

Fixes #8449

## Root cause

The Minerva answer pattern `(?i)Answer\s*:\s*([^\n]+)` matches the literal "Answer" and captures everything after the colon to end of line. When models decorate with markdown:

| Input | Extracted | After normalize | Score |
|---|---|---|---|
| `**Answer:** 42` | `** 42` | `**42` | -1.0 |
| `Answer: **42**` | `**42**` | `**42**` | -1.0 |
| `**Answer:**\n\n42` | `**` | `**` | -1.0 |

## Fix

Two-step stripping in `is_correct_minerva()`:

1. **Pre-extraction**: strip markdown emphasis around the `Answer:` label so the regex matches and `\s*` can span newlines in the `**Answer:**\n\n42` variant
2. **Post-extraction**: strip leading/trailing `*` from the captured answer value; if nothing remains, mark as `[INVALID]` so the `\boxed{}` fallback fires

LaTeX content is preserved: only leading/trailing `*` characters are removed, not underscores or interior characters (`x_1` subscripts survive unchanged).

## Tests

Added `tests/utils/reward_score/test_math_dapo_on_cpu.py` covering:
- All three markdown decoration patterns from the issue
- Italic variant (`*Answer:*`)
- Plain form (regression)
- LaTeX subscript preservation (`x_1`)
- Bold-only marker falling through to `\boxed{}` fallback
