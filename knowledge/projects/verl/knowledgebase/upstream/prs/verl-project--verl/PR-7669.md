# [doc, ci] feat: add Ascend tutorial doc translation pipeline

[Upstream PR](https://github.com/verl-project/verl/pull/7669) · state: closed · merged: False

## Original PR description

### What does this PR do?

Add an automated Chinese-to-English documentation translation pipeline for
`docs/ascend_tutorial/`, keeping the English docs in sync with the Chinese
sources.

The pipeline:

- Scans `docs/ascend_tutorial/zh/` (Markdown + reStructuredText, excluding
  `index.rst`) and translates them into English documents under
  `docs/ascend_tutorial/en/`, mirroring the directory structure and keeping
  the original file format (`.md` stays `.md`, `.rst` stays `.rst`).
- Runs on a scheduled GitHub Actions workflow (every 3 days) and on manual
  trigger, then opens an auto-translation PR for review.
- Caches per-block translations as `.po` translation memory under
  `docs/ascend_tutorial/locale/`, so incremental runs only translate changed
  blocks and reuse existing translations.

### Key Features

- **Fail-closed translation**: blocks that fail to translate are never
  persisted as fake translations; the affected document is reported as failed
  so no incomplete document is merged.
- **Reliability**: per-block automatic retry with backoff, per-request
  timeout, and a failed-document summary + failed block preview in the logs.
- **Performance**: concurrent block translation (configurable) to keep runtime
  low even on slower models.
- **Model-agnostic**: any OpenAI-compatible LLM can be plugged in by setting
  the endpoint, model name, and API key (defaults: Volcano Engine gateway +
  `glm-5.2`).
- **Quality**: enforces a translation standard (Google Developer
  Documentation Style Guide) via the translation skill document
  (`.agent/skills/translate-ascend/skill.md`), including active voice, simple
  present tense, terminology consistency, and structure preservation.
- **Sphinx-compliant output**: generated RST documents are cleaned up
  (indentation restored, title underlines padded, stray fences removed, line
  endings normalized) so the docs build cleanly with Sphinx.
- **Complete navigation**: all translated English docs are registered in
  `docs/ascend_tutorial/en/index.rst`, so every page is reachable from the
  docs navigation.

### API and Usage Example

The translation engine is configurable via environment variables or CLI:

```bash
# API key (any OpenAI-compatible provider)
TRANSLATION_ASCEND=<key>
# endpoint / model
LLM_API_BASE=https://st8tp3ajl0df3n8b8l8qu.apigateway-cn-beijing.volceapi.com/v1
LLM_MODEL=glm-5.2
# optional tuning
LLM_CONCURRENCY=4
LLM_TIMEOUT=120
LLM_BLOCK_RETRIES=2
```

```bash
# Translate one document locally
python .github/workflows/scripts/translate_md.py \
  --files docs/ascend_tutorial/zh/faq/faq.rst \
  --api-key <key> --api-base <url> --model <model> \
  --output-json /tmp/translation_results.json
```

### Design & Code Changes

- `.github/workflows/schedule_doc_translate_ascend.yaml`: scheduled translation
  workflow that detects changes, translates via the LLM API, and opens an
  auto-translation PR with a compliant title.
- `.github/workflows/scripts/translate_md.py`: the translation engine — block
  splitting, concurrent translation with retry, `.po` translation memory,
  RST/Markdown post-processing, configurable LLM provider.
- `.agent/skills/translate-ascend/skill.md`: the translation standard and
  terminology glossary (English style guide key points + Ascend/verl terms).
- `docs/ascend_tutorial/en/index.rst`: English docs toctree covering all
  translated documents.
- `docs/ascend_tutorial/en/**` + `docs/ascend_tutorial/locale/**`: the
  translated English docs and translation memory.
