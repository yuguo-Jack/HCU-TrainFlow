# [dsv4][perf] Compile the mHC hyper-connections (mhc region)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5195) · state: open · merged: False

## Original PR description

**Depends on:** #5196 (complex_rope), which lands first; this stack is based on its branch. The shared MoE change #5157 (`moe_dispatch_combine`) adds -14.7% at 16k for DeepSeek-V4 (91.7 -> 78.2 ms). Turning it on in `DeepSeekV4Model.Config` is a one-line follow-up after it lands.

**TLDR:** Compile DeepSeek-V4's mHC hyper-connections as the `mhc` region: 16k step 240.1 -> 154.5 ms (-35.7%).

**Problem**
1. **mHC.** DeepSeek-V4 keeps 4 residual streams: `HcPre` mixes them before each attention/MoE, `HcPost` after, `HcHead` before the output.
2. **Eager today.** Their forwards run eager; no region covers them.
3. **Big temporaries.** `HcPost` builds a `[T, 4, 4, D]` fp32 product in memory.
4. **Tiny kernels.** `HcPre`'s Sinkhorn normalization launches about 650 small kernels per step.
5. **Cost.** At 16k, 85.6 ms of the 240 ms step goes away once these run compiled (Results).

**Solution**
1. **One region.** The forwards of `HcPre`, `HcPost`, `HcHead` become the `mhc` region.
2. **Enabled** in `DeepSeekV4Model.Config.local_compile_regions`.
3. **Kept inside:** `HcPre`'s GEMM (N=24, memory-bound, its output feeds only the region).
4. **Unchanged:** the math and the parameters.

```text
before:  HcPre (eager, ~650 kernels) -> attn/MoE -> HcPost (eager, [T,4,4,D] fp32 in memory)
after:   HcPre (mhc region)          -> attn/MoE -> HcPost (mhc region, fused)
```

**Results**
```text
DeepSeek-V4 Flash layers 4+5, fwd+bwd wall, 1x GB300, FA4, median of fresh processes within 1% of best
16k   240.09 -> 154.49 ms  (-35.7%)
4k     80.15 ->  54.73 ms  (-31.7%)
peak memory 16k   71.7 -> 66.3 GB
correctness: compiled vs eager, outputs and all grads within 2e-2 (bf16);
             earlier measurement of the same code: rel L2 1.1e-5 (HcPost), 5.4e-5 (HcPre), same error vs fp64
graphs: HcPre 3, HcPost 3 (training 4k/16k/2k + no_grad 4k/2k, limit 8)
```

NOTE: not yet measured under CUDA graphs. Not tested: loss curve, multi-GPU (FSDP+TP+EP), GraphTrainer, H100.

Rejected:
- head-major q / o-grad for `gather_attn`: -3.8% with Triton attention, neutral to slightly worse with FA4 (78.2 vs 79.9 ms screen)
- passing `o` head-major into the region: Inductor still returns a token-major input grad
- coordinate-descent tuning for the HcPost region: ~0.5 ms of 75 ms (<1%), +11 s compile, slower decode

Compile limits hit:
- Inductor can't generate kernels for complex tensors, so compiled ComplexRoPE runs eager: 480.5 us fwd+bwd at 16k; real arithmetic gets 142.5 us (#5196).
- `complex_rope` enabled alone on DeepSeek-V4 exceeds the graph limit; enabled with the glue regions it uses 3 graphs (#5196 and PR 2).
- Sinkhorn's transposed reads compile to one kernel per normalization step: per-entry tensors fuse it, for +42 s cold compile (PR 4).
- A `functools.cache` filled during a fake-tensor trace hands a FakeTensor to later eager calls (PR 6).

Left at 16k: attention ~11 ms (FA4), grouped GEMMs 23 ms, other GEMMs ~15 ms; every glue item left is under 1%.

Not tested: loss curves, multi-GPU (FSDP/TP/EP), GraphTrainer, H100, SAC (the recipe uses none), CUDA graphs.
