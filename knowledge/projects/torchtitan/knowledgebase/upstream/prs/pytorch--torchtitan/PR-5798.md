# Fix docstring typo in preprocess_data (autoencoer -> autoencoder)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5798) · state: closed · merged: True

## Original PR description

## Summary (human-written)

`preprocess_data`'s docstring lists its parameter as `autoencoer`, which is not a word and not the parameter name — the signature is `autoencoder: AutoEncoder | None`. Anything that reads the docstring (help(), generated API docs, an editor's signature hint) shows the typo, and a script that scrapes parameter names gets a name that does not exist. I checked the surrounding entries to keep the same `name (Type): description` shape and confirmed no other entry in this file is misspelled against its signature.

## Why

On `main` today:

```python
def preprocess_data(..., autoencoder: AutoEncoder | None, ...):
    """
    Args:
        autoencoer(AutoEncoder): autoencoder to use for preprocessing
```

The documented name cannot be passed as a keyword argument, and the missing space before the parenthesis also breaks the block's alignment with the other entries.

## What changed

One line in `torchtitan/models/flux/utils.py`: `autoencoer(AutoEncoder)` → `autoencoder (AutoEncoder)`. No code, no signature, no behaviour change.

## Numerics / performance

Not applicable — docstring text only.

## Testing

- `flake8 torchtitan/models/flux/utils.py` — clean.
- The AST check that found this compares every docstring parameter name against the real signature; it reports 0 for the tree after the fix (it reported this single hit before).
