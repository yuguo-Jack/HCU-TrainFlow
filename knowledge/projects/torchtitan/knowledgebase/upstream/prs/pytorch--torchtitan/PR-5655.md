## Summary

Add the released Qwen3.8-Flash-Next text and vision backbone, following the `add_model` workflow proposed in #5636.

- Add `qwen3_8_flash_next` with the released `125B-A6B` configuration and an eight-layer debug configuration.
- Implement four gated residual streams (GR), per-layer lexical embeddings (PLE), and Qwen Sparse Attention (QSA), including the sparse-stage indexer KL objective.
- Add HF checkpoint conversion, reference parity checks, CPU feature tests, combined distributed training fixtures, and a committed deterministic numerical golden with an independent remote replay.

## Architectural choices

Flash-Next uses 48 decoder layers, dimension 2560, and a 3:1 Gated DeltaNet/QSA layout. It adds four residual streams, a learned block indexer, and a large n-gram lexical lookup table to the existing Qwen architecture. These components need model-specific equations and checkpoint mappings.

The port reuses Qwen3.5's Gated DeltaNet, expert computation and dispatch, vision encoder, multimodal preprocessing, MRoPE, and training lifecycle. The model-specific MoE adapters preserve HF's BF16 router rounding. Shared embedding, normalization, and RoPE options preserve existing defaults and checkpoint layouts.

PLE resets at EOS and packed document boundaries. Original token IDs and document positions survive pipeline boundaries independently of multimodal rotary coordinates. The lexical table uses TP across features, preserving HF row-chunk export without gathering the full table on each rank.

QSA selects complete four-token blocks causally and includes the current partial block. The training target sums detached main-attention probabilities across heads, max-pools complete blocks, and normalizes over selected blocks. TP heads are summed before pooling. The report does not give a loss coefficient; this configuration uses `1.0`, independently of the MoE load-balancing coefficient `0.001`.

Strict deterministic training exposed GDN L2-normalization backward autotuning choosing different FP32 reduction orders across fresh processes. The shared chunk, CP, and recomputed backward paths now disable this autotuning when strict determinism is enabled, matching KDA's existing policy. Normal-mode autotuning is preserved. The reference parity report and nine shared GDN GPU forward/backward tests pass with this change.

## Execution limits

- QSA uses bounded gather/indexer chunks and native SDPA MATH. Dynamic selection shapes currently require disabling CUDA graphs; context parallelism is explicitly rejected.
- MTP training and speculative decoding are outside the port's current scope.
- Full 177B parameter materialization, production-scale convergence, and production throughput have not been validated.
- The pinned nightly has a preexisting CosSinRoPE eager/compile discrepancy on unchanged upstream/main: one BF16 gradient value differs by `9.54e-7`. The pinned CUTLASS DSL 4.6.2 supports the validated fused GDN backend; the optional cuDNN backend requires DSL 4.7.0.

## Draft follow-ups for current upstream/main

The two implementation commits were validated against the source base above. Latest upstream/main (`3f990a8e9` when this draft was prepared) merges without textual conflicts, but has since changed the compile configuration and loss contracts.

**What this PR does.** Adds `qwen3_8_flash_next`, a subclass of Qwen3.5. It adds three things:
- four gated residual streams, carried as one `[T, 4*D]` tensor;
- a hashed n-gram lexical table (PLE) on layer 1, TP-sharded by feature;
- QSA, where each query attends to the top-k 4-token blocks plus its own partial block, and an indexer is distilled from detached main-attention probabilities via `AuxLoss.inject`.

It also changes `common/embedding.py`, `common/norm.py`, `common/rope.py` and `common/attention/{gdn,cp_gdn}.py`, and adds five integration entries with a B200 golden.

**Example.** For a packed document at token 9 with `compress_ratio=4` and `token_budget=4` (one block):
```
complete blocks: [0..3] ends at 3, [4..7] ends at 7 -> visible (end <= 9, same doc)
indexer scores both, picks top-1, e.g. [4..7]
tail: token 8 and 9 (local_count % 4 = 2 -> current partial block)
SDPA over J = [4,5,6,7,8,9]; KL target = max-pool over heads-summed probs of [4..7]
```
Today, gradients of that KL reach `x_TD` and every layer below it. In DeepSeek V4's equivalent, they stop at the indexer.
