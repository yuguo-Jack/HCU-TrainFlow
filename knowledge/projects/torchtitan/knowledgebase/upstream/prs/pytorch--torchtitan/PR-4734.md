# [graph_trainer] Accumulate chunked-loss gradients before SimpleFSDP reduction

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4734) · state: open · merged: False

## Original PR description

## Summary

Reduce redundant parameter-gradient synchronization in GraphTrainer chunked loss by accumulating LM-head gradients locally before returning them through the original SimpleFSDP autograd edges.

For each used FSDP parameter, this changes RS(g0) + ... + RS(gN) into RS(g0 + ... + gN). The reduction structure is established during tracing through modeling and autograd code, without a reduce-scatter coalescing pass.

The accumulation is scoped to each loss invocation. Cross-microbatch synchronization remains the responsibility of the trainer or pipeline schedule. Floating-point accumulation order changes, and additional full-size buffers may increase peak memory.

## Changes

- Add a per-chunk backward extension point to the base loss wrapper.
- Unshard each SimpleFSDP LM-head parameter once per loss invocation and reuse a detached compute leaf across chunks.
- Accumulate chunk gradients in an owned buffer using the reduction dtype.
- Return accumulated hidden-state and parameter gradients through an autograd bridge, supporting both backward() and autograd.grad(), including outer loss scaling.
- Separate all-gather communication dtype from the autograd boundary dtype using PyTorch's internal Redistribute function, preventing FP32 accumulated gradients from being rounded to BF16 before reduction.
- Restore parameter-access state on nested calls and exceptions.
