# chore: drop unused global declarations flagged by flake8 (F824)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5773) · state: open · merged: False

## Original PR description

Running the repo's own lint config over the tree:

```
$ python -m flake8 --config=.flake8 --select=E,F,W --statistics torchtitan
5     E704 multiple statements on one line (def)
9     F824 `global _buffer` is unused: name is never assigned in scope
```

`.flake8` selects `F` and does not ignore F824, so these nine are lint violations that only surface when the file is next touched (pre-commit runs on changed files).

### Fixed here

| file | lines |
|---|---|
| `torchtitan/distributed/deepep/deepep.py` | 164, 235, 266, 303 |
| `torchtitan/distributed/deepep/hybridep.py` | 141, 239, 271, 305 |
| `torchtitan/experiments/graph_trainer/simple_fsdp.py` | 473 |

Reading a module-level name does not need a `global` declaration, so removing these changes no behavior. Eight are standalone statements and are deleted; `deepep.py:266` declares two names and keeps `global _pending_combine_event`, which *is* assigned in that scope.

### Verification

```
$ python -m flake8 --config=.flake8 --select=F824 torchtitan
(no output)
$ python -m py_compile torchtitan/distributed/deepep/deepep.py       torchtitan/distributed/deepep/hybridep.py       torchtitan/experiments/graph_trainer/simple_fsdp.py
(ok)
```

### Not touched

The five remaining E704 hits are all in `experiments/graph_trainer/graph_pp/stage_builder.py`, where four `def` stubs are written as `def f(...) -> T: ...`. That form is what the formatter produces, so expanding them would likely be reverted and fail the ufmt hook — if you want `flake8` quiet about it, adding `E704` to the `ignore` list in `.flake8` looks like the smaller change. Left out of this PR deliberately.

No tests were run: the change is a no-op on module globals, and this environment only has stable torch 2.10 (the suite needs nightly, `torch.compile(..., recompile_limit=...)`).

**Verdict: Approve** -- each removed `global` sits in a function that only reads the name. Dropping it doesn't change behavior and clears the nine F824 hits that `.flake8` (`select = ...F...`) reports whenever these files are touched.

**What this PR does.** It removes `global _buffer` from four functions in `deepep.py` and four in `hybridep.py`, and `global _active_parametrization` from `SimpleFSDP._forward`. In `deepep.py:_combine_op_impl`, it narrows `global _buffer, _pending_combine_event` to `global _pending_combine_event`.

**Example.**
```python
# before (deepep.py:_dispatch_op_impl)
global _buffer
buffer = _buffer          # read only; module lookup works without `global`
# after
buffer = _buffer
```

<details><summary>Details</summary>

I checked every function body at HEAD. The only places that assign these names still keep their `global`:
- `_buffer`: `deepep.py:376/388` and `hybridep.py:411/444` (`get_buffer`)
- `_pending_combine_event`: `deepep.py:264/287` (`_combine_op_impl`, declaration kept) and `deepep.py:335/340` (`sync_combine`)
- `_active_parametrization`: `simple_fsdp.py:50-55` (the context manager)

None of the eight edited functions assigns `_buffer`, and `_forward` doesn't assign `_active_parametrization`. Python looks up names that are only read at module scope anyway, so the declarations did nothing. These ops also have no compile/trace effect.

Leaving E704 in `graph_pp/stage_builder.py` out of this PR is right: it's a separate concern.

</details>

This touches core distributed code (`torchtitan/distributed/deepep/`), so a maintainer still needs to review.
