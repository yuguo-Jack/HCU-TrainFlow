# [rope] Remove the Helion RoPE override and the helion dependency

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5530) · state: open · merged: False

## Original PR description

**TLDR:** Delete `torchtitan_recipes/overrides/helion_rope.py` and the `helion` dependency. No recipe uses the override anymore, and the compiled RoPE is on par with or faster than it for every model up to 128k (the MLA models through the PR below this one).

**Problem**
1. **One user left.** The Muse Spark recipes were the only ones that imported the Helion RoPE override. "[muse_spark][perf] Compile RoPE with the q/k norms; drop the Helion RoPE override" (lower in this stack) moved them to the compiled q/k region.
2. **Leftovers.** Only its own test, one integration test definition, a CI pin (`helion==1.1.0`), a pyrefly ignore entry and a docs example still refer to it.
3. **Cost.** An optional dependency and ~1,030 lines (576 override + 455 test) to maintain for no caller.

**Solution**
1. **Delete** the override and its test.
2. **Keep its coverage.** Its two non-contiguous layouts (a split key with an inserted head dim, a query with transposed head strides) move into `test_rope_compile.py`, against the compiled path.
3. **Clean up** the DeepSeek-V3 MTP integration test (drop the override import and the ROCm skip that existed for it), the CI pin and the pyrefly ignore entry. `OVERRIDE.md` drops the Helion example; `fused_swiglu.py` stays as the worked example.
4. **Unchanged.** Every recipe and model default.

**Results**
```text
Numerics: no recipe changes. The DeepSeek-V3 MTP integration test runs stock ComplexRoPE (since the MLA PR
          below); it has no golden. Fake-PG goldens of DeepSeek-V3, GPT-OSS, Llama 3, Muse Glimmer and Qwen3
          are byte-identical to main (exported locally on GB300).

RoPE alone, GB300, CUDA graphs, us: compiled rope region (Helion).
64k: dynamic T. 128k: Llama 3 and Glimmer are the first (static) compile; the Muse Spark q/k region is dynamic.
model               mode      64k                   128k
Llama 3 8B          train      452.7 ( 462.8)        801.9 ( 888.8)
                    prefill    224.3 ( 231.5)        439.8 ( 436.4)   (dynamic T: 447.0)
Muse Glimmer 30B    train      381.5 ( 373.4)        664.5 ( 721.4)
                    prefill    192.3 ( 194.8)        375.1 ( 364.8)
Muse Spark q/k      train     2071.9 (2240.5)       4123.6 (4378.9)
region              prefill    699.6 ( 766.8)       1390.9 (1484.3)

mla_qk region (_apply_rope_to_q_and_k_pe), GB300, CUDA graphs, us: compiled (Helion)
model               mode      64k                   128k
DeepSeek-V3 671B    train     1926.6 (2673.0)
                    prefill    953.5 (1326.5)       1899.5 (Helion fails: int32 index)
Kimi K2.5           train      989.7 (1360.1)
                    prefill    495.0 ( 668.9)        977.9 (1316.0)
```
(Helion numbers in the mla_qk region come from a standalone bench closure; on that bench the compiled region matched the real module path within 0.3%.)

You may ask: does any model get slower than Helion? Not by more than 3%. DeepSeek-V3 and Kimi are 26-28% faster than Helion in their q/k region, train and prefill. Contiguous q/k models are on par, at most +2.8% (Glimmer prefill 128k, static compile). No recipe uses Helion for these models today.

NOTE:
- `deepseek_v3_mtp_fsdp+ep` loses its ROCm skip (it existed for Helion), so it runs on ROCm for the first time on main or with a `ciflow/rocm` tag; not run on ROCm.
- Changing `.ci/docker/requirements-dev.txt` changes the CI image tag.

**Test plan**
- `pytest tests/unit_tests/gpu/models/qwen3_5/test_rope_compile.py` (incl. the moved layouts).
- `pytest tests/unit_tests/{gpu,cpu}/models/deepseek_v3 tests/unit_tests/cpu/models/common/test_rope.py tests/unit_tests/gpu/models/kimi_k2_7 tests/unit_tests/{gpu,cpu}/models/muse_spark`: 76 passed, 1 failed (CosSinRoPE `test_forward_and_backward_match_eager`, also fails on main on GB300).
- Fake-PG models suite with `--export-numerics`, diffed against main: byte-identical for all 5 models.

Stack: 3 of 3 on top of the RoPE / Muse Spark stack: mla_qk region -> MLA RoPE as int32 pairs -> this PR.
