# Release CUDA cache before the first optimizer update

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5350) · state: closed · merged: True

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.15.0) (oldest at bottom):
* __->__ #5350

Release unused CUDA cache on the first Optim.step call so NCCL can allocate buffers during gradient clipping. Keep the release outside CUDA graph capture and independent of the restored step number. 

The original solution of setting `NCCL_RUNTIME_CONNECT=0` in init_distributed can cause too much memory overhead and even lead to several CI failures (/dev/shm is not enough). 

Forward/backward may leave unused memory in PyTorch's cache. NCCL allocates buffers outside PyTorch's caching allocator and cannot reclaim that memory. This workaround assumes fwd/bwd succeeds and enough unused cache can be released for NCCL's allocations during the first optimizer update. It cannot prevent allocation failures during forward/backward or later steps.

Refs: https://github.com/pytorch/torchtitan/issues/5019
