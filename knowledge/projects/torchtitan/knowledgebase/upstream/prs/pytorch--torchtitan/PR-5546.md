# Handle unavailable FlashAttention backends safely

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5546) · state: closed · merged: True

## Original PR description

Fixes https://github.com/pytorch/torchtitan/issues/5536.

Default Varlen attention currently activates FA3 on Hopper and FA4 on Blackwell without checking whether the corresponding wheel is installed. With a missing wheel, model construction raises `ModuleNotFoundError`, including for models that can use PyTorch's built-in FA2.

This change checks backend availability and uses FA2 with a warning when the architecture's wheel is absent. Outer attention constructors validate the head dimensions through a shared inner-attention interface. DeepSeek-V3 and Kimi K3 MLA configurations with unequal Q/K and V dimensions fail during construction with the detected SM, dimensions, and required module in the error message. Flex attention remains available for these layouts.

Backend activation is shared between training and the vLLM generator. Existing activation is reused, and broken installations retain their original exception as the cause of an actionable error instead of silently falling back. Architecture selection stays within PyTorch's supported families: Hopper uses FA3 and Blackwell uses FA4; a missing FA4 wheel does not select FA3 on Blackwell, and later SM families are not assumed to support FA4.

The change does not alter attention arithmetic, model parameters, or checkpoint keys. The new fallback can change numerical results relative to FA3/FA4, so it emits a warning.

## Numerical evidence

Compared the fallback with explicit PyTorch FA2 on an NVIDIA L4 using PyTorch `2.14.0a0+4fdf77b940.nv26.08`, CUDA 13.4, BF16 inputs, seed 42, and strict deterministic algorithms. The input has two packed sequences of 32 tokens, four heads, and head dimension 64. Backend selection and missing-wheel discovery are simulated for FA3 and FA4; attention forward and backward run on the real CUDA device.

| Missing wheel | Execution | Max output difference | Loss difference | Max Q/K/V gradient difference |
| --- | --- | --- | --- | --- |
| FA3 | Eager | 0 | 0 | 0 |
| FA3 | `torch.compile(fullgraph=True)` | 0 | 0 | 0 |
| FA4 | Eager | 0 | 0 | 0 |
| FA4 | `torch.compile(fullgraph=True)` | 0 | 0 | 0 |

All four comparisons passed with `atol=0, rtol=0`. Each produced attention loss `0.19502778351306915` and combined input-gradient L2 norm `0.012680011801421642`.

Reproduce the comparisons with:

```bash
python -m pytest tests/unit_tests/gpu/models/common/test_varlen_attention.py \
  -k backend_setup_matches_explicit_backend -vv
```

The two installed-FA3/FA4 cases were skipped on L4; actual Hopper/Blackwell backend execution is not covered by these results. The test now runs the missing-wheel comparisons on the default A10 GPU CI runner as well.

Full-training loss and optimizer `grad_norm` comparisons were not run. This patch changes backend setup and constructor validation, while leaving attention forward code unchanged; the focused comparison checks the new fallback's output, loss, and every input gradient against its intended backend. A training convergence rerun would add little evidence for this setup change. Cross-backend bitwise equality is not expected.

### Why it's ~450 LoC

The fix for #5536 needs about 15 lines. The rest of the PR is three other changes plus tests for them.

| Bucket | +LoC | Needed for #5536? |
|---|---|---|
| Tests (`test_tools_utils.py`, two `test_varlen_attention.py`, bitwise parity) | ~320 | Partly. A CPU test that mocks `find_spec` is enough |
| `tools/utils.py`: new `_cuda_flash_attention_backend`, `activate_cuda_flash_attention`, `validate_flash_attention_head_dims` | ~95 | About 15 lines of it |
| New `InnerAttention.validate_head_dims` interface, called from 9 outer-attention constructors in 8 files | ~30 | **No** |
| vLLM generator moved onto the shared helper | net −17 | Optional cleanup |

### What goes beyond the fix

1. **A new `validate_head_dims` contract on `InnerAttention`.** It adds a base-class method and calls it from GQA, DSv3, DSv4, Kimi K3, gpt_oss, qwen3_5, flux (3 sites) and vLLM. Six of those nine calls pass `validate_head_dims(head_dim, v_head_dim=head_dim)`, which can never fail. Only the two MLA models (and vLLM's diff-KV path) have unequal dims.
   - This is a separate feature: "MLA + varlen on FA2 should fail at construction". That was already true on A100/L4 before this PR, so it has nothing to do with a missing wheel.
   - It also conflicts with CLAUDE.md #7 (no speculative defensive checks). Without it, PyTorch's FA2 kernel raises its own error at forward time.
2. **Detecting broken installs.** `get_cuda_flash_attention_impl` parses `ModuleNotFoundError.name` to tell "package missing" from "a dependency of the package is missing". That edge case adds a lot of branching.
3. **Behavior change in architecture selection.** It replaces `has_cuda_capability(10, 0)` with an exact-major lookup `{9: FA3, 10: FA4}`. As a result, SM 11.x/12.x (e.g. consumer Blackwell RTX 50xx) no longer select FA4 even when the wheel is installed. This silently changes behavior for existing users. It is a reasonable change to discuss, but it belongs in its own PR.
4. **Repeated checks.** `torch.cuda.is_available() or torch.version.hip` appears 3 times. `activate_cuda_flash_attention` calls `_cuda_flash_attention_backend()` and then `get_cuda_flash_attention_impl()`, which calls it again.

### What the minimal fix looks like

Return `None` (so the caller stays on FA2) when the wheel isn't importable, and warn once. Both existing callers (`VarlenInnerAttention.__init__` and the vLLM impl) already handle `None`:

```python
def get_cuda_flash_attention_impl() -> str | None:
    if torch.version.hip is not None:
        return None
    if has_cuda_capability(10, 0):
        impl, module = "FA4", "flash_attn.cute"
    elif has_cuda_capability(9, 0):
        impl, module = "FA3", "flash_attn_interface"
    else:
        return None
    try:
        found = importlib.util.find_spec(module) is not None
    except ModuleNotFoundError:  # parent package `flash_attn` missing
        found = False
    if not found:
        warn_once(logger, f"{impl} not installed ('{module}'); falling back to FA2.")
        return None
    return impl
```

Add one CPU unit test that patches `has_cuda_capability`/`find_spec`, and the whole PR comes to roughly 40–60 LoC.

### Recommendation

Cut this PR down to the snippet above plus a small test. If the MLA head-dim error and the SM≥11 FA4 policy are wanted, open each as its own PR so the change in item 3 gets its own review.
