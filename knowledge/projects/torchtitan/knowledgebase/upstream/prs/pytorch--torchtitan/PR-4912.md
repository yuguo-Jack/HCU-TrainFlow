# [typing] Type decoder layer configurations

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4912) · state: open · merged: False

## Original PR description

## Summary

```diff
- TransformerBlock.Config[AttentionConfig]
- Decoder.Config[BlockConfig]
+ TransformerBlock.Config
+   attention: Attention.Config
+ Decoder.Config
+   layers: list[TransformerBlock.Config]
+ model-specific consumers
+   assert isinstance(config, ConcreteConfig)
```

Use the shared base configuration types in the common decoder and narrow only
where model-specific fields are consumed. This removes the extra generic type
parameters and `Config[...]` subscriptions while retaining concrete nested
model configs, mutable layer lists, and the DeepSeek V4 dense-first-layer
checkpoint adapter regression.

Document the base typing contract for model authors in
`torchtitan/models/README.md`.

## Evidence

- **Before:** the PR threaded `AttentionConfigT`, `DecoderLayerConfigT`, and
  `MTPDecoderLayerConfigT` through shared and model-specific configs.
  **After:** the focused decoder configuration regression passes: **3 passed**
  (`tests/unit_tests/cpu/models/common/test_decoder_config_typing.py`).
- Pyrefly on every changed production Python file: **0 errors**, with one
  pre-existing redundant-cast warning in DeepSeek V4.
- Full non-type-checking pre-commit hooks pass. The full Pyrefly hook reaches
  one unrelated existing error in `torchtitan/models/common/dist_moe/runtime.py`.
- The model-authoring documentation checks pass, including codespell and link
  validation. `git diff --check` passes and the worktree is clean.
- A broader CPU model-suite attempt is not claimed to pass: collection on
  macOS stops in the declared Attention Gym CUTE backend because `cutlass` is
  unavailable. No GPU, distributed-training, or loss-parity result is claimed.

**Verdict: Approve -- please address the items below before merging.** The asserts are the expected cost of the base-typed design you asked for, and only generics or `pyrefly: ignore` suppressions would remove them. The must-fix items from the previous review are all still open at HEAD.

**Why the asserts are there.** On `main`, `Decoder.Config.layers` is a bare `list`. Each `layer` is therefore `Any`, and pyrefly accepts any attribute access, e.g. `layer.attention.n_groups`. With `layers: list[TransformerBlock.Config]`, `layer.attention` has type `Attention.Config`, which only has `n_heads` and `inner_attention` (`common/attention/attention.py:108`). Reading a subclass field (`head_dim`, `q_lora_rank`, `n_groups`, `output_gate`, `attention_res_norm`, ...) now requires telling the type checker the concrete type. The PR adds 21 `isinstance` checks for this: 7 in FLOP counters, 8 in state dict adapters, 4 in DSV4 flavors and validation, and 2 in recipes. They all run when configs are built, models are built, checkpoints are mapped, or FLOPs are counted. None of them run in the training step.

**Can we avoid them?** Not without bringing back what you asked to remove:

| Option | Shared code | Per-model cost | Type checking |
|---|---|---|---|
| `isinstance` narrowing (this PR) | none | 21 one-line checks | yes, and also checked at runtime |
| Generics (previous revision) | TypeVars through `TransformerBlock`/`Decoder`/`MTPDecoder`/`MultimodalModel`, plus `Config[...]` everywhere | none | yes |
| Redeclare `layers` and `attention` in each model | none | 2 `# pyrefly: ignore [bad-override]` per model (dataclass fields are mutable, so overrides must be invariant) | unsound; each ignore also hides any other error on that line |
| `cast(...)` | none | same count as the asserts | no runtime check |
| Keep `layers: list` (`main`) | none | none | none: every `layers[i]` is `Any` |

Redeclaring the field only cost nothing on `main` (Muse Spark and DSV4 `attention`) because `layers` was `Any`. With a typed `layers`, it would also need a second suppression on each model's `layers`.

`isinstance` narrowing on layer configs is already the pattern on `main` for models that mix attention types: `qwen3_5/model.py:363`, `kimi_k3/model.py:250`, `rl/generator/vllm/model_wrapper.py:141`. This PR extends it to the remaining models. I recommend keeping the asserts. If ~21 asserts is too high a price for typed layers, the alternative is to keep `layers: list` and drop this PR, not to look for another typing trick.

### Why `AttentionConfigT` exists, and whether it's needed

- [x] Read the PR's `TransformerBlock.Config` / `Decoder.Config` changes (`torchtitan/models/common/decoder.py:40-90`)
- [x] Find which callsites need concrete layer/attention types
- [x] Answer

**Short answer:** yes, the simpler version works: `attention: Attention.Config` on `TransformerBlock.Config` and `layers: list[TransformerBlock.Config]` on `Decoder.Config`. The generics only let the type checker know the concrete type of `layers[i].attention` without a cast. Only a few callsites use that, so I don't think it's worth the extra type parameters.

#### What the generics buy

The base `Attention.Config` only has `n_heads` and `inner_attention`. Three places read fields that only exist on a subclass:

| Callsite | Field | Concrete config |
|---|---|---|
| `deepseek_v3/state_dict_adapter.py:71` | `layers[0].attention.q_lora_rank` | `DeepSeekMLAAttention.Config` |
| `deepseek_v4/model.py:251` | `layer.attention.n_groups` | `DeepSeekV4Attention.Config` |
| `muse_spark/state_dict_adapter.py:270` | `layer.attention.output_gate` | `MuseSparkAttention.Config` |

With the simpler typing, Pyrefly reports these three as missing attributes.

You might expect a subclass to just redeclare the field, e.g. `attention: GQAttention.Config`. Pyrefly flags that as `bad-override` because dataclass fields are mutable. Muse Spark needed `# pyrefly: ignore [bad-override]` for exactly this before the PR. `AttentionConfigT` gets the narrower type without that suppression. The same applies to `Decoder.Config`: a subclass can't redeclare `layers: list[Sub.Config]` without an ignore, because `list` is invariant.

`list` invariance is also why the builders' return types change, e.g. `-> list[Llama3TransformerBlock.Config]` in `llama3/flavors.py`. With a plain `layers: list[TransformerBlock.Config]`, a function returning a list of a subclass can't be passed as `layers=`. So the builders would need to keep returning `list[TransformerBlock.Config]`, as they do on `main` today.

#### Why it isn't worth it

- **It mostly adds noise.** `qwen3_5`, `kimi_k3` and `muse_glimmer` write `TransformerBlock.Config[Attention.Config]`, which narrows nothing because their layers mix attention types. Most other models only need the parameter so the table above type-checks.
- **The 4 removed DeepSeek V3 ignores don't need generics.** They are on `_build_mtp_layers(layers[-1], ...)` (`deepseek_v3/flavors.py:417`). That function only deep-copies `attention`, `feed_forward` and the two norms into `MTPTransformerBlock.Config`, which uses the base `TransformerBlock.Config` fields. Typing its `inner_cfg` parameter as `TransformerBlock.Config` removes them too.
- **The three callsites can narrow locally.** That code is already model-specific, and checking the type there is clearer than threading a type parameter through the shared `Decoder` → `MTPDecoder` → `MultimodalModel` classes:
  ```python
  attention = model_config.layers[0].attention
  assert isinstance(attention, DeepSeekMLAAttention.Config)
  if attention.q_lora_rank != 0:
  ```
  The PR already handles the DeepSeek V4 `feed_forward.router` this way with `isinstance` (`deepseek_v4/state_dict_adapter.py:127-132`).

#### Suggested shape

1. `TransformerBlock.Config.attention: Attention.Config`, with no `Generic`.
2. `Decoder.Config.layers: list[TransformerBlock.Config]`, with no `Generic`. This also answers @acisseJZhong's inline question. Drop `DecoderLayerConfigT`, `MTPDecoderLayerConfigT` and the `Config[...]` subscripts in the 11 model files.
3. Builders keep returning `list[TransformerBlock.Config]`, and `_build_mtp_layers` takes `TransformerBlock.Config`.
4. Add an `isinstance` assert at the three callsites in the table.
5. Keep the DeepSeek V4 dense-first-layer fix in `state_dict_adapter.py` and its test; that bug fix doesn't depend on the generics.
6. Rewrite `tests/unit_tests/cpu/models/common/test_decoder_config_typing.py`. It currently checks that the configs can be subscripted, which would no longer apply.

This closes the `layers: list` TODO with less churn. The cost is three runtime asserts instead of static narrowing.
