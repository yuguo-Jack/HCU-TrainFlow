# [dsv4] Don't cache the Indexer's Hadamard matrix

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5201) · state: open · merged: False

## Original PR description

**TLDR:** `Indexer._rotate_activation` multiplies by a 128x128 Hadamard matrix that `functools.cache` kept. A fake-tensor trace filled the cache with a FakeTensor, and every later eager call broke. The matrix is now built on every call; speed is unchanged.

**Problem**
1. **Cached matrix.** `compressor._hadamard` builds the 128x128 matrix under `functools.cache`, keyed by size, dtype and device.
2. **Fake first.** A fake-tensor trace (make_fx, GraphTrainer) calls it first and caches a FakeTensor.
3. **Breaks eager.** Later eager Indexer calls get that FakeTensor back and fail.
4. **Real first.** In the other order, the trace bakes the cached real tensor in as a constant.
5. **When.** Nothing on main fake-traces DeepSeek-V4 today, so no run hits it yet.

**Solution**
1. Drop the cache: `_hadamard` builds the matrix on every call (7 doublings of a small tensor).
2. Unchanged: the matrix and the Indexer math.

**Results**
Numerics: identical (the same +1/-1 matrix, built each call instead of read from the cache).
```text
DeepSeek-V4 Flash layers 4+5, fwd+bwd wall, 1x GB300, FA4, median of fresh processes
16k   74.93 -> 75.07 ms  (+0.2%, noise)
4k    32.00 -> 32.22 ms
```
Measured on top of the DeepSeek-V4 compile stack; this commit changes no compiled region.

NOTE: not measured under CUDA graphs; GraphTrainer end to end not run.

**Test plan**
`pytest tests/unit_tests/cpu/models/deepseek_v4/test_deepseek_v4_compressor.py -k test_rotate_activation_after_fake_tensor_trace` (fails on main, passes here).
