# [TorchTitan] Make DeepSeek V3's HF save file map match what the save writes

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5065) · state: closed · merged: True

## Original PR description


Summary:
`fqn_to_index_mapping` comes from `hf_assets_path`'s
`model.safetensors.index.json`, and only HF saves read it, to decide which
file each tensor goes into. Consolidation creates an output header entry for
every name in the mapping. A name the save never writes gets
`{"shape": [], "dtype": ""}`, and `safetensors` then refuses to open that
file (`unknown variant ''`). DCP's HF reader opens every file, so loading
the saved checkpoint fails.

The released `deepseek-ai/DeepSeek-V3` index (91,991 entries) lists three
kinds of tensors a TorchTitan HF save did not write:

- 45,808 FP8 `X.weight_scale_inv` scales. Saves are unquantized, so these
  are dropped from the mapping.
- The MTP layer, `model.layers.61.*` (788 entries), when the config has
  `num_mtp_layers=0`. The model has no such layer, so these are dropped too.
- `model.layers.61.embed_tokens.weight` and
  `model.layers.61.shared_head.head.weight` with `num_mtp_layers=1`. The
  checkpoint stores a copy of the shared embedding and output head under the
  MTP layer, while TorchTitan has one `tok_embeddings.weight` and one
  `lm_head.weight`. `to_hf` clones the shared tensors for the MTP names so
  safetensors can serialize both entries into the same file, including CPU
  exports. The saved bytes are duplicated like the released checkpoint.
  `from_hf` skips these copies and restores the main names.

On a load, `to_hf` also allocates temporary MTP copies. DCP reads these
independent buffers as well as the main tensors, adding about 3.7 GB of
reads for the released 671B BF16 embedding/head copies. In the
released checkpoint the copies match the main tensors on every sampled row
(rows 0, 1, 43093, 64640, and 129279 of each). `DeepSeekV4` converts its MTP
layers to its own names and opts out with an empty `_MTP_SHARED_COPIES`.
`KimiK25` inherits the change.

Test Plan:
```
pytest -q -o addopts= --tb=short tests/unit_tests/cpu/models/test_state_dict_adapter.py tests/unit_tests/cpu/components/checkpointer/test_checkpoint.py
pre-commit run --all-files
```
89 tests passed. The MTP regression covers one and two layers, checks
independent storage with identical values, and saves/reloads the main and
MTP embedding/head entries through the HF writer and reader without an
index map. The index-filter tests cover `num_mtp_layers` 0 and 1.

Formatting and lint hooks passed. Full pre-commit's type checker reports
two pre-existing `l2norm(..., autotune=...)` signature errors in the unchanged
KDA module with the local Attention Gym installation.

Earlier validation on the full `671B` config with the released index found
that the mapping and `to_hf` output match exactly: 45,395 names with
`num_mtp_layers=0` and 46,183 with `num_mtp_layers=1`.

This change was written with the help of an AI assistant.
