# [models] Report the missing backend per Attention Gym kernel

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5500) · state: closed · merged: True

## Original PR description

## Summary

Follow up to #5467 (review point 2 there). The facade recorded backend import errors per attn_gym module, but every placeholder raised the first recorded error, so with, say, `attn_gym.sparse` failing on cutlass and the GDN modules importing fine, `GDNKernel.Config().build()` reported cutlass although GDN would have worked.

- Exports of a module whose backend is missing now resolve to a `_MissingKernel` subclass carrying that module's error (one subclass per module, cached, named `_MissingKernel[<attn_gym module>]`). Calling it, `.apply`, or `.from_fragments` raises a fresh `ModuleNotFoundError` with that backend's name and message.
- `is_missing_kernel()` (a `TypeGuard`) replaces the `is not _MissingKernel` identity checks in `kda.py`, `gdn.py`, `linear_attention.py` and `cp_linear_attention.py`, so the subclasses are also kept out of SPMD registration.
- `require_attn_gym(kernel, *kernels)` checks the given exports and each module calls it from `__init__` with every export it uses, so a build error names the backend that module needs: `KDAKernel` (`chunk_kda`, `bound_gate`, `l2norm`), `GDNKernel` (`chunk_gdn`, `recurrent_gdn`, `l2norm`), `InnerKDA` / `InnerGDN` (`causal_conv1d`), `ContextParallelInnerKDA` / `ContextParallelInnerGDN` (`context_parallel_kda` / `context_parallel_gdn`, `context_parallel_conv_history`, `ContextParallelRouting`, and `l2norm` for GDN). The zero argument form from #5467, which raised on any error recorded so far, is gone.
- No change when `attn_gym` is missing (the placeholders are the base class and raise the install hint) or when every backend imports.

Not in this PR: attn_gym resolves `causal_conv1d` and the other `attn_gym.linear.short_conv` exports lazily (`attn_gym.linear._lazy`) and raises a plain `ImportError` at attribute access, which `_load_module` never sees, so on a machine without cutlass `gdn.py` / `kda.py` still fail to import and 18 CPU test modules do not collect. I have that fixed on top of this branch and will open it next, the `causal_conv1d` checks here are what make it fail at build rather than at the first forward.

## Test plan

`tests/unit_tests/cpu/models/common/test_optional_imports.py`:
- new `test_attention_modules_report_their_own_backend_at_build`: a fake attn_gym whose modules all import except the broken ones. With `attn_gym.linear.short_conv` failing on cutlass, `KDAKernel` / `GDNKernel` build and `InnerKDA`, `InnerGDN` and their CP variants fail at build with cutlass, with the three context parallel modules failing on triton, the inner modules build and the CP variants fail with triton. Fails without the `__init__` checks.
- mixed case extended: `…l2norm_fwd` fails on triton and `attn_gym.linear.kda.impl.fused` on cutlass in one process, `_L2Norm()` raises triton, `_ChunkKDA()` / `.apply` raise cutlass, `require_attn_gym(_ChunkKDA)` raises cutlass, `require_attn_gym(real, _L2Norm)` raises triton, `require_attn_gym(real, real)` passes, the placeholder is named after its module.
- broken backend case asserts the placeholders are subclasses and that none reached the SPMD registry.
- existing `[cutlass-*]` build cases now go through `require_attn_gym(kernels)` and still see `error.name == "cutlass"`.

### Review: per-kernel backend errors for the attn_gym facade

The change is correct and fixes the problem it targets: when one attn_gym module fails on a backend, that failure no longer blocks kernels from other modules. Turning placeholders into per-module subclasses, cached in `_BACKEND_KERNELS`, is a small and clean way to do it. Switching to `is_missing_kernel()` everywhere also keeps the subclasses out of SPMD registration. I checked the whole repo outside `tests/` and no `is _MissingKernel` identity checks are left. My comments are below, most important first.

#### 1. The narrower build check lets CP backend failures through until `forward` (worth deciding on purpose)
`ContextParallelInnerKDA` / `ContextParallelInnerGDN` build `KDAKernel` / `GDNKernel` through `InnerKDA` / `InnerGDN`. Those now check only `chunk_kda, bound_gate, l2norm` or `chunk_gdn, recurrent_gdn, l2norm`. Their own kernels are not checked:
- `context_parallel_kda` / `context_parallel_gdn`
- `context_parallel_conv_history` and `ContextParallelRouting` (`attn_gym.linear.context_parallel`)
- the short-conv exports

Before this PR, importing `cp_kda.py` touched `context_parallel_kda` at import time. So a backend failure there was recorded, and the old coarse `require_attn_gym()` raised at **build**. Now the build succeeds and the error only appears at the first `forward`, after model init, sharding and possibly checkpoint load. The error message is still correct; it just shows up later.

Suggestion: have each CP inner module call `require_attn_gym(context_parallel_kda, context_parallel_conv_history, ContextParallelRouting)` in its `__init__` (same for GDN). Then the "fails at build" contract holds for CP too. If late failure on CP is acceptable, add a sentence to the PR description saying so.

[Fix this →](https://claude.ai/code?q=On%20branch%20attn-gym-per-kernel-errors%2C%20add%20require_attn_gym(context_parallel_kda%2C%20context_parallel_conv_history%2C%20ContextParallelRouting)%20to%20ContextParallelInnerKDA.__init__%20in%20torchtitan%2Fmodels%2Fcommon%2Fattention%2Fcp_kda.py%20and%20the%20GDN%20equivalent%20in%20cp_gdn.py%20so%20CP%20backend%20failures%20surface%20at%20build%20time%2C%20and%20extend%20test_optional_imports.py%20accordingly.&repo=pytorch/torchtitan)

#### 2. Kernel lists are copied by hand from `forward`
`attention/kda.py:74` and `attention/gdn.py:223` restate which exports `forward` / `prepare_inputs` / `_recurrent_gdn_fwd` call. If someone adds a kernel call and forgets to update the list, nothing fails; the build check just gets weaker. I don't see an easy way to enforce this mechanically. At minimum, a short comment at each `require_attn_gym(...)` call ("must list every attn_gym export used by forward") would help reviewers catch drift.

#### 3. Calling with zero arguments silently switches to the coarse check
`require_attn_gym(*kernels)` with no arguments means "fail if anything recorded so far failed", which is a different and stricter check. A caller passing an empty, computed tuple would get it without noticing. No production callers use the zero-argument form any more; only the test at `test_optional_imports.py:299/441` does. Per CLAUDE.md's "no speculative" guidance, consider dropping the coarse branch and keeping one meaning. If it stays, the docstring should state the split more directly.

#### 4. `TypeGuard` would remove the `cast` (nit)
```python
from typing import TypeGuard

def is_missing_kernel(kernel: object) -> TypeGuard[type[_MissingKernel]]:
    return isinstance(kernel, type) and issubclass(kernel, _MissingKernel)
```
Then `require_attn_gym` can use `kernel._error` directly, and the `cast` import goes away.

#### 5. Every subclass has the same name (nit)
`type("_MissingKernel", ...)` gives each per-module subclass the same `__name__` / `__qualname__` as the base, so reprs and tracebacks can't tell them apart. Something like `f"_MissingKernel[{module_name}]"`, or a name that includes `error.name`, would make debugging easier. It costs nothing, since identity checks are gone.

#### 6. Small points (fine as they are)
- `_raise_for(None)` falling back to "first recorded backend error" is now only reachable through the zero-argument `require_attn_gym()`. The base `_MissingKernel` is only handed out when `attn_gym` is absent, and in that case `_BACKEND_ERRORS` is empty. If you drop the coarse branch (#3), this fallback can go too.
- `_BACKEND_ERRORS.setdefault` combined with the cached subclass means a second export from the same failed module reuses the first error. That is the correct behaviour.
- The tests are thorough. The mixed triton/cutlass case in a single process covers the original bug directly.
