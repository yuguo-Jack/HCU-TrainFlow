# [rl] abort a generation when its caller gives up

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5493) · state: closed · merged: False

## Original PR description

**TLDR:** When the caller of a `generate` call gives up, e.g. Verifiers cancels an agent's model call at the rollout timeout, the vLLM request now stops instead of decoding to `max_tokens` (16,384 in the Terminal-Bench recipe). On 1 H100, a cancelled 1,000-token request stopped by the first check, 0.5 s later; on main it decoded all 1,000 tokens. This is a waste fix: the end-to-end saving is not measured.

**Problem**
1. **The caller gives up.** Verifiers cancels a rollout's in-flight model call when the rollout ends early, e.g. at the 7,200 s rollout timeout. The cancelled HTTP request drops its connection to `GenerationServer`.
2. **The server keeps going.** `web.AppRunner(app)` uses aiohttp's default `handler_cancellation=False`, so the handler keeps awaiting `generate_fn`.
3. **The cancel stops at the caller.** Monarch's `call_one` sends the message, then returns a local handle for the reply. Cancelling that handle leaves the remote endpoint running, on both hops: controller to router, and router to generator.
4. **vLLM decodes to the end.** Up to 16,384 tokens per turn in the Terminal-Bench recipe, for a reply nobody reads.
5. **How often.** In one earlier overloaded GB300 Terminal-Bench run, 153 of 249 finished rollouts ended at the timeout. Not re-measured; read it as an upper bound, since a timeout during a tool call leaves no model call in flight.

**Solution**
The one place that sees the cancel turns it into an explicit abort; the generator answers the call, and every rank drops the request from vLLM.
```text
                           main                               this PR
GenerationServer handler   keeps awaiting generate_fn         cancelled on disconnect (handler_cancellation=True)
GenerateFn (controller)    the cancel stays local             sends router.abort_generation(request_id), re-raises
InterGeneratorRouter       generate keeps running             sends the abort to every generator
Generator engine loop      decodes to max_tokens              rank 0 answers "abort" and frees the DP rank;
                                                              every rank calls engine.abort_requests, before a load too
```
- The abort reply also ends the router's call, so the router's load count drops as for any finished call.
- With DP > 1, a peer DP rank's completion or rejection that arrives after the abort is skipped.
- A cancelled server handler no longer records `generation_metadata`. Before, a late entry was never popped and stayed until `close()`.
- Calls that aren't cancelled behave as before.
- `GenerationEngine.abort_requests` is a new abstract method: every engine must be able to stop a request. `VLLMEngine` calls vLLM's `abort_request`.

**Results**
```text
1 H100, Qwen3-0.6B, eager vLLM (~23 tok/s), one 1,000-token request cancelled 2 s in; engine polled every 0.5 s
same script, venv and GPU on both commits (main = this PR's base)

GenerateFn cancelled
  main:     decodes all 1,000 tokens, engine idle 40.6 s after the cancel
  this PR:  engine idle at the first poll (0.50 s)
HTTP client cancels its POST
  main:     engine idle 41.6 s after the cancel
  this PR:  engine idle at the first poll (0.51 s)
```
- The 40 s on main comes from this setup's slow eager decode, not from the production cost of one orphan.
- Also checked: a caller still waiting gets `finish_reason="abort"`; aborting a finished or unknown id does nothing, and the next `generate` works.

NOTE:
- Covered by CPU tests only: generator DP > 1 and TP > 1 (the Terminal-Bench 35B recipe runs DP2 x TP2), and an abort in the same decision as a weight load.
- Not covered: the order of a generate and its abort across a multi-host generator mesh, and the agent harness's own HTTP client (the check drives the server with an aiohttp client).
- Landing order: the new `test_verifiers.py` test calls `server.set_generate_fn`, which the "one GenerateFn per rollout group" PR deletes. Whichever lands second switches it to `server.generate_fns[1] = generate_fn`.
- Drain mode (`hot_swap=False`, which no recipe sets): a call waiting in the router for a drain reaches its generator after the abort and decodes to the end, as before. There is a TODO.

**Test plan**
```text

```
