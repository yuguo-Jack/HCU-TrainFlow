# [rl] DPPOLoss: optional symmetric trust region (drop any token with |p - p_gen| > threshold)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5476) · state: open · merged: False

## Original PR description

(Rebased on the "one scoring step and one metrics step for every RL loss" PR. Replaces a separate `IPOLoss` class from an earlier draft.)

**TLDR:** `DPPOLoss.Config(symmetric=True)` also drops tokens that moved past the threshold against their advantage, so no token trains once `|p - p_gen|` exceeds the threshold. With `divergence_threshold=0.3, max_ratio=1e4`, this is the absolute-probability trust region some open-source RL trainers call IPO. The default (False) is unchanged.

**Problem**
1. `DPPOLoss` drops a token when `sign(A) * (p - p_gen) > divergence_threshold`, i.e. only when it moved the way its advantage pushes it.
2. A token that moved past the threshold the other way keeps training, so its gradient pulls it back.
3. To match an external baseline, some runs need the hard bound: drop any token with `|p - p_gen| > threshold`, whichever way it moved.
4. A second loss class for that would copy DPPO, since the gradient (`-A * min(p / p_gen, cap) * grad log p`) and the denominator are the same.

**Solution**
1. New field `DPPOLoss.Config.symmetric: bool = False`.
2. True drops a token when `|p - p_gen| > divergence_threshold`. False keeps the paper's rule.
3. Nothing else changes: `loss/trust_region_dropped_frac` counts the dropped tokens in both modes.

```text
p_gen = 0.5, threshold 0.2        symmetric=False   symmetric=True
p = 0.8, A = 1 (moved +0.3)       dropped           dropped
p = 0.2, A = 1 (moved -0.3)       kept              dropped
```

The matched-baseline config:
```python
DPPOLoss.Config(divergence_threshold=0.3, max_ratio=1e4, symmetric=True, global_vocab_size=...)
```

**Results**
NOTE: not run yet. Fill in before opening.
```text
Numerics: symmetric=False runs the same ops as before (bitwise unchanged).
          symmetric=True: same gradient as the reference implementation in the test below, on every token,
          except ratios p / p_gen below e^-10, which get weight e^-10 (the shared log-ratio clamp) instead of
          their true value. Both are ~0.
```

You may ask:
- Why not a separate `IPOLoss`? It would copy DPPO's gradient, denominator and metrics; only the drop direction and the cap value differ.
- Where did `adv_tau`, `bit_wise/kl_k3/mean` and `bit_wise/logprob_diff_abs/mean` go? `adv_tau` only rescaled the advantage, which the learning rate already does, and nothing set it. The two mismatch metrics describe every loss, so they belong in the shared `policy_metrics`; they come with the router-replay PR, which adds them to DAPO.

NOTE: `loss/mean` reports `-A * w * log p` (DPPO's surrogate), not the reference's `-A * w`. Gradients are the same.
