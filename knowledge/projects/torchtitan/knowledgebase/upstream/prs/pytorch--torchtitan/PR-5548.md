# [kimi] Use the published rms_norm_eps for Kimi K2.x decoder-layer norms

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5548) · state: closed · merged: True

## Original PR description

The Kimi flavors (`moonlight-16B-A3B`, `Kimi-VL-A3B`, `Kimi-K2.5`) build their decoder layers with DeepSeek V3's `build_mla_moe_layers`, which hardcodes `eps=1e-6` for each block's `attention_norm` and `ffn_norm`. The published configs of all three models set `rms_norm_eps=1e-5` (`moonshotai/Moonlight-16B-A3B`, `moonshotai/Kimi-VL-A3B-Instruct`, `moonshotai/Kimi-K2.5`), and the HF modeling code applies it to `input_layernorm` and `post_attention_layernorm`. Only the final norm used the published value.

The difference is not negligible for these checkpoints. On real token-embedding rows from the published weights, the layer-0 normalized input differs between eps 1e-6 and 1e-5 by a median of 1.0% (Moonlight), 1.2% (Kimi-VL) and 4.8% (K2.5), and by up to 34–40% for some tokens.

This adds a `norm_eps` argument to `build_mla_moe_layers` (default `1e-6`, so DeepSeek V3 is unchanged) and passes `1e-5` from the Kimi builder. The MLA q/kv norms keep `1e-6`, as in the HF modeling code.

**Test**
- With the model flavors built on CPU, the Kimi flavors' `attention_norm`/`ffn_norm` eps is 1e-5 and DeepSeek V3's stays 1e-6.
