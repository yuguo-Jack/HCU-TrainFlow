# Keep merges.txt lines that start with # in the BPE fallback loader

## Why
When a tokenizer dir has vocab.json/vocab.txt + merges.txt but no tokenizer.json, the merges loader skips every line starting with "#". Only the `#version` header is a comment though, so real merges like `# #` (which builds "##") get dropped and text with "##" tokenizes differently from the pretrained tokenizer.

**Example.** vocab `{"#": 0, "##": 1, ...}`, merges.txt `#version: 0.2` / `# #`:
- main: `encode("##")` -> `[0, 0]`
- this PR: `[1]`, same as `tokenizers`' own `BPE.from_file`

## What changed
- `torchtitan/components/tokenizer.py`: skip only `#version` lines, same as the `tokenizers` library does.

## Testing
- New `test_bpe_merges_starting_with_hash_are_loaded` in `tests/unit_tests/cpu/components/test_tokenizer.py`: fails on main (`[0, 0] != [1]`), passes with the fix.
- Rest of test_tokenizer.py passes, except `test_hf_backend_renders_generation_tags`, which fails the same way on main here because `transformers` isn't installed.
