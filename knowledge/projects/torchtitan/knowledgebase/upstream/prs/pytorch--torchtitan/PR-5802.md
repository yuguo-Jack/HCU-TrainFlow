## Why
TP collectives are moving out of `ShardingConfig` src -> dst pairs, where
`Module` inserts them implicitly, and into explicit `spmd.redistribute` calls in
model code (as `RowParallelLinear` / `ColumnParallelLinear` and the MoE did,
#4878). The two decoder collectives still inserted implicitly are the token
embedding's reduction and the gather before `lm_head`.

Terms: the *residual layout* (`residual_activation_placement`, already on main)
is the TP layout of the `(tokens, hidden)` stream between blocks: `S(0)` with
sequence parallelism, `I` (Invariant) without.

**Example (TP=2, SP on).**
```
tokens -> Embedding (vocab-sharded weight, each rank returns TP-Partial)
          main: sharding config out_src=P, out_dst=S(0)  -> Module inserts reduce-scatter
          now:  VocabParallelEmbedding.forward calls spmd.redistribute(P -> S(0))
       -> blocks (residual layout S(0))
       -> final norm
          main: sharding config out_dst=R                -> Module inserts all-gather
          now:  Decoder._final_norm_and_gather calls maybe_gather_tp_input(S(0) -> R)
       -> lm_head (vocab-sharded, needs R)
```

Implicit async boundary collectives also hid a real bug, below.

## What changed
**Embedding**
- New `VocabParallelEmbedding(Embedding)` in `models/common/embedding.py`. The
  masked vocab-shard lookup runs in a `spmd.local_map` region returning
  TP-Partial, then the module reduces it in the remat region `<fqn>.tp_reduce`:
  P -> S(0) (reduce-scatter) with SP, P -> I (all-reduce) without.
- `replicate_output=True` selects P -> R, for multimodal models whose vision
  scatter needs the full sequence on every rank (qwen3_5 family, kimi_k3, and
  kimi_k2_7 under SP).
- The base `Embedding` still returns TP-Partial. The Transformers modeling
  backend experiment depends on it and is migrated later in the stack.

**Final norm**
- `lm_head` is vocab-sharded, so it needs the full hidden states on every rank.
  New `Decoder._final_norm_and_gather`: root norm, then `maybe_gather_tp_input`
  (S(0) -> R all-gather with SP; I -> R, forward no-op and backward all-reduce,
  without).
- It gathers after the norm, so under SP the norm only touches the local
  sequence shard. It gathers once rather than inside `lm_head`, which
  `ChunkedLossWrapper` calls once per chunk.
- Called by `Decoder` and every model with its own forward: deepseek_v3 MTP,
  deepseek_v4, kimi_k2_7, kimi_k3, muse_glimmer, muse_spark, qwen3_5. The MTP
  block gathers its `mtp_norm` output the same way.

**Sharding configs:** `token_embedding_sharding_config`,
`multimodal_token_embedding_sharding_config` and
`pre_lm_head_norm_sharding_config` now only declare (and, under typechecking,
assert) boundary layouts.

**Mechanical, skimmable:** every `flavors.py` switches `Embedding.Config` to
`VocabParallelEmbedding.Config`, and each model forward changes one line to call
`_final_norm_and_gather`.

## Bug fixed: Muse Spark embedding gets no gradient under TP
On main, the implicit boundary redistribution runs with `async_op=True` (#5398)
and returns an `AsyncCollectiveTensor`. It flows straight into the compiled
`muse_spark_rmsnorm` region, and torch.compile returns an output with
`requires_grad=False`, silently cutting the graph. `tok_embeddings` never
trains. The explicit reduction is synchronous, like `RowParallelLinear`'s.

| TP2+EP2, step 1, seed 42 | main | this PR | TP1 reference |
| --- | --- | --- | --- |
| `tok_embeddings.embedding.weight` grad norm | `None` | 0.0590 | 0.0564 |
| every other parameter grad | | bitwise identical to main | |

The async + compile interaction is an upstream issue (worth filing separately);
this PR only stops exercising it at these boundaries.

## Alternatives considered
- Gather inside `lm_head` (a `ColumnParallelLinear`): N all-gathers under
  `ChunkedLossWrapper` instead of one.
- Make the base `Embedding` reduce: breaks the Transformers backend experiment,
  which converts `nn.Embedding` in place and owns its reduction.

## User-facing changes
| Before | After |
| --- | --- |
| `Embedding.Config(..., sharding_config=token_embedding_sharding_config(...))` | `VocabParallelEmbedding.Config(...)` (add `replicate_output=True` if the output must be TP-Replicate) |
| Custom forward calls `self.norm(h)` before `lm_head` | Call `self._final_norm_and_gather(h)` |

## Numerics
Bitwise-identical loss and grad_norm over 10 steps vs. base `8e3da8b50` (seed 42,
deterministic, `scripts/loss_compare.py --assert-equal`):

| gpt_oss TP2+EP2 | 4 | identical |
| deepseek_v4 FSDP | 4 | identical |

qwen3_5, kimi_k2_7, kimi_k3 and Muse Glimmer multimodal could not be
loss-compared on the test machine (base-tree env/recipe failures or
nondeterministic kernels). Higher PRs in this stack verify qwen3_5 and
kimi_k2_7 with a full-model fwd+bwd harness.

## Testing

  catches a missing or wrong reduction (output and weight grad vs. an
  unsharded reference, across SP on/off and `replicate_output` on/off).
- `test_fsdp_moe_sharding.py` switched to `VocabParallelEmbedding`.
- CPU unit tests (models, config, quantization): no new failures vs. base.

**What this PR does.** It removes the automatic `ShardingConfig` src -> dst redistributions on the token embedding and the root norm, and runs those collectives explicitly in `forward`. A new `VocabParallelEmbedding` subclass reduces its TP-partial lookup itself: reduce-scatter under SP, all-reduce otherwise, and an all-reduce to `Replicate` when `replicate_output` is set. A new `Decoder._apply_final_norm` gathers the norm output to `Replicate` before `lm_head`. Every flavor and every Decoder subclass's final-norm call site is updated (I checked all of them, including DSv3 MTP). It continues #4878, alongside #5803 and #5805.

**Example** (llama3, TP=2 + SP):
```
main:  tok_embeddings = Embedding + token_embedding_sharding_config
         local_spmd lookup -> P@TP; boundary out_dst reduce-scatters to S(0) (async)
       norm: pre_lm_head_norm_sharding_config out_dst all-gathers S(0) -> R (async)
PR:    tok_embeddings = VocabParallelEmbedding
         local_map lookup -> P; remat.region(spmd.redistribute)(P -> S(0))
       Decoder._apply_final_norm: norm(h) stays S(0) -> maybe_gather_tp_input -> R
```
It runs the same collectives with the same backward `op_dtype`, so loss should be bitwise identical. The only difference is that `async_op=True` is gone, and in both places the consumer uses the result immediately anyway.

This `local_map` region declares only `out_types`. `.claude/rules/distributed.md` requires `local_map` regions to declare their `in_types`, and the code this replaces did: `local_spmd=True` with `in_dst_shardings={"input": token_id_placement()}`. tokens = token_id_placement()
```python
partial = dense_activation_placement(tp=spmd.P, cp=spmd.S(0))
output = spmd.local_map(
    in_types=((tokens.local_type, tokens.partition_spec),),
    out_types=(partial.local_type, partial.partition_spec),

```

- claude[bot] · comment · 2026-11-04T07:12:42Z · [source](https://github.com/pytorch/torchtitan/pull/5802#discussion_r4464704437)

File: `torchtitan/models/common/embedding.py` · line 93

`replicate_output` encodes a second time the layout the flavor already chose with the sharding config (`multimodal_token_embedding_sharding_config()` vs `token_embedding_sharding_config()`). All 13 call sites repeat the same condition twice (e.g. `kimi_k2_7` has `multimodal and enable_sp` both here and in `_token_embedding_sharding`). If the two disagree, only spmd typechecking catches it. Under no-SP, `R` and `I` have identical forward values but different backward semantics, so with typechecking off the mismatch is silent.

Pick one source of truth. Options: derive `dst` from the configured output layout; have a single helper build both; or drop the flag, so the embedding always emits the residual layout and the multimodal decoders gather with `maybe_gather_tp_input` before the vision scatter. The last option means RS + AG instead of one AR: about the same bandwidth, one extra collective latency.

File: `torchtitan/models/common/embedding.py` · line 123

This remat region does nothing. Remat only checkpoints and configures `layers.*` blocks (`torchtitan/distributed/activation_remat.py:129-146`), so `tok_embeddings` never runs inside a checkpoint and no save/recompute pattern is ever applied to it. The region and its `recompute=` flag have no effect, yet the class docstring describes `<fqn>.tp_reduce` as a remat region, which suggests users can control it through `save_regions`. Call `spmd.redistribute` directly and drop the remat wording from the docstring. The same applies to `norm.tp_gather` from `_apply_final_norm`; reusing `maybe_gather_tp_input` there is fine.
