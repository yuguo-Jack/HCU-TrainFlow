# [rl] Verifiers 0.4.0 (1/14)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5456) · state: open · merged: False

## Original PR description

**TLDR:** Bump the Verifiers example to 0.4.0. On 0.4.0, main breaks twice (a renamed method, a removed import) and would train timed-out rollouts with their graded reward; this PR fixes all three.

**Problem**
1. `VerifiersTaskDataset` caps tasks with `Taskset.head`; 0.4.0 renamed it `take`, so any config with `num_tasks` fails.
2. The tests import `OverlongPromptError`, which 0.4.0 removed, so `test_verifiers.py` fails at collection.
3. 0.4.0 marks a timed-out stage (setup, agent, finalize, scoring) with `trace.is_timeout` and can leave `ok=True`.
4. `rollout_status` reads only `ok`, so a timed-out rollout trains like a finished one. On 0.3.1 it had `ok=False` and no reward.

**Solution**
1. `take` instead of `head`.
2. Requirements: verifiers 0.4.0 and mcp 2.0; Terminal-Bench adds harbor 0.24.0 on the host (only it has `resolve_verifier_environment_definition`, which 0.4.0's Harbor taskset calls).
3. `rollout_status` maps `is_timeout` (on the trace or the episode) to the existing `ERROR_TIMEOUT`: logged, no reward.
4. 0.4.0 reports an overlong first prompt as a failed model call ("maximum context length"); the "first prompt does not fit" warning now checks that call.
5. Unchanged: rewards and validation scores for every `error_reward`; the in-sandbox Terminus harness stays at 0.22.0 (a separate install in the container).

**Results**
```text
Verifiers CPU tests (test_verifiers*.py, test_verifiers_terminal_bench*.py, test_model_defaults.py)
main + verifiers 0.3.1, harbor 0.22.0    42 passed
main + verifiers 0.4.0, harbor 0.24.0    collection error (ImportError: OverlongPromptError)
PR   + verifiers 0.4.0, harbor 0.24.0    49 passed (7 new)

3-step math smoke, Qwen3-0.6B, 1 trainer + 1 generator (H100), verifiers 0.4.0, local recipe:
rollout_reward/_mean 0.042, 0.062, 0.050; validation ran before and after
```

You may ask: why 0.4.0, not 0.3.2? PyPI has only 0.3.2.devN pre-releases; 0.4.0 is the first release after 0.3.1.

NOTE:
- On the Terminus harness, 0.4.0 turns a mid-rollout context overflow into an error; 0.3.1 truncated it (~0.3% of rollouts in an agentic SWE run). Verifiers' own chat harnesses end such a rollout cleanly.
- A timed-out rollout now runs finalize and scoring before it returns, so a timed-out Terminal-Bench rollout holds its sandbox through the test run. The reward is unchanged.
- Not run: Terminal-Bench end to end (needs sandboxes). CI's Verifiers step installs only `dapo_math/requirements.txt`, so CI skips the Harbor tests.

**Test plan**
```bash

pytest -rs tests/rl/unit_tests/cpu/test_verifiers.py tests/rl/unit_tests/cpu/test_verifiers_example.py \
  tests/rl/unit_tests/cpu/test_verifiers_terminal_bench.py \
  tests/rl/unit_tests/cpu/test_verifiers_terminal_bench_prepare_tmax.py tests/rl/unit_tests/cpu/test_model_defaults.py
# 49 passed, no skips
pytest -rs tests/rl/unit_tests/cpu   # 540 passed, 3 skipped (none for harbor or Verifiers)
```
- On main with 0.4.0, the new and edited tests fail: the first-prompt warning, two timeout cases, the timed-out rollout and `num_tasks`.
- A CPU end-to-end run (real env server, generation server and rollouter; fake generator) warns on both overflow paths and gives an agent timeout no reward.
- `uv pip compile` resolves both files: `dapo_math` (96 pins) and `terminal_bench` (129 pins, adds harbor==0.24.0), both with verifiers==0.4.0.
