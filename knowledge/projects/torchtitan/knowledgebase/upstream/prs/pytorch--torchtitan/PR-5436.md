# [moe][perf] Argsort expert ids on the narrowest integer type (2/6)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5436) · state: open · merged: False

## Original PR description

**TLDR:** The MoE dispatch sorts expert ids as uint8 (up to 256 experts) or int16 instead of int64, so the radix sort makes 1 pass instead of 8: argsort of 32,768 routes 69 -> 24 us on GB300, same order. Reference path (Dist-MoE and DeepEP have their own dispatch), low priority.

**Stack** (6 PRs, merge bottom-up; this PR is in **bold**)

| # | PR | Independent? | Needs (stack positions) |
|---|---|---|---|
| 1 | AllToAll dispatcher: permute and unpermute with gathers | yes | — |
| **2** | **Argsort expert ids on the narrowest integer type** | **yes** | **—** |
| 3 | EP=1 inference: gather-sum MoE combine region | no | 2 |
| 4 | EP=1 inference: sort-region MoE dispatch | no | 2, 3 |
| 5 | Gather-sum dispatch and combine for training, at any EP | no | 4 |
| 6 | Turn on gather-sum dispatch and combine for DeepSeek-V3 and Kimi | no | 3, 4, 5 |

**Problem**
1. **Sort.** Every dispatch sorts the `T * top_k` routes by expert: `torch.argsort(expert_ids, stable=True)` in `_local_reorder` (EP=1, and EP>1 before the all-to-all; training and inference).
2. **Keys.** The router returns int64 ids, so the radix sort sorts 64-bit keys.
3. **Passes.** CUB's radix sort makes one pass per key byte (plus a memset each): 8 passes, though 256 experts need 1 byte.
4. **Cost.** 32,768 routes (4096 tokens x top-8): 69 us; 262,144 routes (a 32k-token training microbatch): 89 us per MoE layer.

**Solution**
1. `_argsort_expert_ids` casts the ids to uint8 (<= 256 experts) or int16 (<= 32,768) before `torch.argsort(stable=True)`.
2. `num_experts` is a Python int fixed by the model, so the dtype branch is a trace-time constant: no graph break, and the same dtype in training and inference.
3. `_local_reorder` calls it.
4. Unchanged: the order (stable sort on the same keys); more than 32,768 experts keep int64.

**Results**
```text
Numerics: bitwise identical (stable sort on the same keys).

torch.argsort(stable=True) of top-8 expert ids (E=256), GB300, CUDA-graph replay, us
routes      int64   int32   int16   uint8
272          30.2    20.2    16.1    13.4
2,048        31.9    21.6    17.3    13.4
32,768       69.1    44.9    32.5    23.8
262,144      88.8    53.9    36.9    27.6
On main the sort is one eager call per MoE layer, so a layer saves the table's difference
(derived from the table, not measured on a layer): -45 us at 4096 tokens, -61 us at 32k
```

NOTE: expert ids must be in [0, num_experts), as the grouped GEMM already requires.
