# [Paged Stash] Run the stash runner outside the trainer's CUDA graph

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5354) · state: open · merged: False

## Original PR description

[#5023](https://github.com/pytorch/torchtitan/pull/5023) moves CUDA graph capture out of `cuda_graph_pass` and into the client `TrainingEngine`, which captures the whole forward/backward as one graph. Paged stashing composed with the old pass-level capture by sitting outside each captured subgraph; with a whole-step graph it ends up inside one, where `PagedStashRunner`'s host-side work is not capturable—the overflow flag's `event.query()`, the freelist reset, and the Triton warmup, which cannot compile during capture.

### Changes

Invert the nesting. Wrap the eager forward/backward in the CUDA graph first, then run the runner around that: the runner stays on the host and may rerun the step, and the graph holds only the step itself.

An overflow still has to drop the graph before the pages it baked pointers into are released, so `PagedStashRunner` takes a `reset_cuda_graphs` callback rather than calling the module-level function, which after [#5023](https://github.com/pytorch/torchtitan/pull/5023) has no trainer graph to reset. The trainer passes one that tears its graph down and rebuilds the wrapper, and the rebuilt wrapper is looked up on every attempt so a blocking rerun picks it up.

Whole-step capture also lifts the pipeline-parallel restriction in `next_entries`, which returned no entries under capture: a stage-level graph captured at one point in the schedule would replay that point's skip and prefetch decisions for every microbatch. The trainer captures every pipeline action at its own place, so the schedule-dependent answers replay correctly and skipping and prefetching work under GraphPP with graphs on.

### Memory measurements

Measured on 4×GB200, DeepSeek-V3 debugmodel + HybridEP, PP=2 Interleaved1F1B / 4 microbatches, FSDP 2, EP 2, round-robin routing. Peak reserved memory on the worst rank, saved-but-not-paged against paged:

| HybridEP capacity factor | 1.0 | 2.0 | 4.0 | 8.0 |
| --- | ---: | ---: | ---: | ---: |
| Saved, not paged (GiB) | 10.89 | 14.72 | 23.05 | 39.19 |
| Paged (GiB) | 9.68 | 10.00 | 11.22 | 13.82 |

Capture is what makes the un-paged side cost `layers × padded`: it pins every layer's padded buffer in the graph's private pool. The stash pool that replaces them is 2217.56 MiB at capacity factors 1, 2, and 4 and 2219.01 MiB at 8, while the padded residency grows from 2016 to 16138 MiB, so the pool follows live rows and not the padding. Over the sweep, the un-paged slope is 4.06 GiB per capacity-factor unit against 0.61 paged.

### Test coverage

The runtime mechanics are now tested the way they run, with the step captured:

- `test_blocking_mode` drives the whole-step graph and absorbs the separate pass-level CUDA graph case it duplicated.
- `test_deferred_mode` gains a captured step, so the default overflow policy is covered around a graph and not only eagerly.
- `test_reloads_are_prefetched_one_schedule_entry_ahead` captures and replays a prefetched reload, since prefetching is how the stash runs under the trainer's graph.
- `test_paged_activation_lives_until_its_copy_is_joined` captures the release, which is where it bites: an activation held past its join keeps its padding in the graph's private pool for the life of the graph, and that per-layer residency is what paging removes.
- `test_schedule_decides_which_stashes_stay_resident` pins `next_entries` under capture with a pipeline schedule—the one place the lifted restriction needs covering, since skipping and prefetching both read it.
- `test_sizing_keeps_one_pool_of_live_pages` gains the `worst_case + actual` decomposition an earlier consolidation dropped.

What stays eager is what capture cannot reach: the graph-pass and partition tests run at trace time, before there is a stream to capture; the schedule and sizing tests are arithmetic over actions and page counts; and the optimizer-skipping test turns on `optimizers.step()` honoring the flag on device, which runs outside the forward-backward graph.

### Integration validation

Paged stashing had two integration tests, one per concurrency mode, because the modes could not be combined. They can now: `aot_fx_trace_deepseek_v3_graph_pp_hybridep_paged_stash` drops `disable_cuda_graphs` and runs GraphPP, the whole-step CUDA graph, and paged stashing together.

It passes on 4 GPUs with "Recorded CUDA graph" on every rank, GraphPP sizing engaged on every rank, and no token drops.

Agent used: Claude Opus 1M
