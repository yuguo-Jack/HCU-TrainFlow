Parameterize `Decoder.Config` as `Generic[LayerConfigT]` so `layers` is `list[LayerConfigT]`, and specialize per model as `Decoder.Config[<Block>.Config]` (addresses @fegin's review on #5415).

### 2. Lint: new imports are out of order and duplicate an existing import path

`TransformerBlock` is already re-exported from `torchtitan.models.common` (`common/__init__.py:38`). llama3, qwen3, gpt_oss, deepseek_v3 and kimi_k2_7 all import it from that existing `from torchtitan.models.common import (...)` block. - `kimi_k3/flavors.py:24` comes before `from torchtitan.models.common import (`
- `muse_glimmer/flavors.py:26` comes before `from torchtitan.models.common.attention import`

### 3. The `list` casts can be avoided by following the existing pattern

The other models already handle invariance without a cast. Their builders return `list[TransformerBlock.Config]` and append into a list typed as the base class (`llama3/flavors.py:85-89`, `qwen3/flavors.py:116`, `gpt_oss/flavors.py:222`, `deepseek_v3/flavors.py:299`). In qwen3_5, muse_glimmer, deepseek_v4 and kimi_k3 you could do the same:

```python
layers: list[TransformerBlock.Config] = []
...
return layers
```

Adding a `Qwen35TransformerBlock.Config` to a `list[TransformerBlock.Config]` type-checks fine, so the `cast(list[TransformerBlock.Config], layers)` calls and their `from typing import cast` imports can go. That keeps every model on one idiom.

The one exception is DeepSeek V4. `_build_mtp_layers` needs the subclass-typed `layers[-1]` (`deepseek_v4/flavors.py:856/1002/1148`), so the element-level `cast(DeepSeekV4TransformerBlock.Config, layers[-1])` is fine to keep.

### 4. The `getattr(..., default)` calls in state dict adapters can hide errors

This goes against CLAUDE.md principle 7 (no speculative fallbacks).

- **`deepseek_v3/state_dict_adapter.py:71`**: `getattr(model_config.layers[0].attention, "q_lora_rank", 0)`. The PR description says the `0` matches the `Attention.Config` default, but `q_lora_rank` isn't defined on `Attention.Config`. It's only on `DeepSeekMLAAttention.Config` (`deepseek_v3/model.py:53`). If the attention config is ever not MLA, or the field gets renamed, this quietly picks the non-LoRA HF key map, and the only symptom is wrong or missing keys at checkpoint load. That's the kind of loading breakage `.claude/rules/models.md` asks us to protect against.
- **`kimi_k3/state_dict_adapter.py:269`**: `getattr(self.kimi_config.layers[0], "attention_res_norm", None)`. `attention_res_norm` is a required field with no default on `KimiK3TransformerBlock.Config` (`kimi_k3/model.py:240`). The `None` fallback would make the adapter generate placeholder layer-0 attn-res weights for any config that lacks the attribute.

Narrowing the type explicitly would satisfy the type checker and still fail loudly, for example:

```python
attention = model_config.layers[0].attention
assert isinstance(attention, DeepSeekMLAAttention.Config)
if attention.q_lora_rank != 0:
```

and

```python
layer0 = self.kimi_config.layers[0]
assert isinstance(layer0, KimiK3TransformerBlock.Config)
if layer0.attention_res_norm is None:
```

`cast(...)` would also work, though it skips the runtime check.

### 1. Blocker: the new assert in `DeepSeekV3StateDictAdapter.__init__` fails for every DeepSeek V4 config

`torchtitan/models/deepseek_v3/state_dict_adapter.py:72-76`:

```python
from .model import DeepSeekMLAAttention

attention = model_config.layers[0].attention
assert isinstance(attention, DeepSeekMLAAttention.Config)
```

`DeepSeekV4StateDictAdapter` subclasses this adapter and calls `super().__init__(model_config, hf_assets_path)` (`deepseek_v4/state_dict_adapter.py:31`). V4 layers use `DeepSeekV4Attention.Config`, and that class inherits from `Attention.Config`, not from `DeepSeekMLAAttention.Config` (`deepseek_v4/attention.py:273`). So the assert raises `AssertionError` whenever a V4 adapter is constructed. That breaks:
- every V4 HF checkpoint load and save (`from_hf` / `to_hf`)
- `DeepSeekV4StateDictAdapterTest` in `tests/unit_tests/cpu/models/test_state_dict_adapter.py:301` and `:357`, which build `DeepSeekV4StateDictAdapter(config, ...)` directly

Before this PR the code worked by duck typing: both config classes define `q_lora_rank`. V4 then overwrites `self.from_hf_map` completely (`deepseek_v4/state_dict_adapter.py:33`), so the V3 `q_lora_rank` branch never had any effect for V4.

Two ways to fix it:
- **Recommended:** move the V3 map construction, including the `q_lora_rank` branch, into a method such as `_build_from_hf_map(model_config)`. V4 overrides that method rather than calling the V3 map logic and then throwing the result away. The V3 assert is then only reached with V3/Kimi K2.7 configs, which use `DeepSeekMLAAttention.Config` (`deepseek_v3/flavors.py:218`). This also removes the existing `# pyrefly: ignore [bad-argument-type]` workaround's reason for existing.
- **Minimal:** keep the narrowing but don't depend on the concrete class. For example, use `cast(DeepSeekMLAAttention.Config, ...)` with a comment that V4's config also has `q_lora_rank` and V4 replaces the map anyway. Checking against `DeepSeekV4Attention.Config` from V3 code would add a reverse V3 → V4 dependency, so avoid that.

[Fix this →](https://claude.ai/code?q=On%20branch%20cursor%2Fdecoder-layers-typing-ab29%2C%20torchtitan%2Fmodels%2Fdeepseek_v3%2Fstate_dict_adapter.py%20lines%2070-89%20assert%20isinstance(attention%2C%20DeepSeekMLAAttention.Config)%20which%20fails%20for%20DeepSeekV4StateDictAdapter%20(it%20calls%20super().__init__%20and%20V4%20uses%20DeepSeekV4Attention.Config).%20Move%20from_hf_map%20construction%20into%20an%20overridable%20method%20that%20DeepSeekV4StateDictAdapter%20overrides%2C%20then%20run%20pytest%20tests%2Funit_tests%2Fcpu%2Fmodels%2Ftest_state_dict_adapter.py&repo=pytorch/torchtitan)
