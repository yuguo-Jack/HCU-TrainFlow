# Avoid per-edge pipeline P2P with XCCL

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5750) · state: closed · merged: True

## Original PR description

## Summary (human-written)
With pipeline parallelism enabled on XPU, TorchTitan enables pipeline_per_edge_p2p, but XCCL cannot split process groups for directed pipeline edges. This change disables per-edge P2P when the backend is XCCL. We tested the change on an XPU device and confirmed that it works.
## Why

`init_distributed` currently enables `pipeline_per_edge_p2p` whenever the pipeline parallel degree exceeds one. On XPU, the default backend is XCCL, which cannot split process groups for directed pipeline edges.

| Device | Backend | PP degree | Before | After |
| --- | --- | ---: | --- | --- |
| XPU | XCCL | 2 | Per-edge P2P enabled | Disabled |
| CUDA | NCCL | 2 | Per-edge P2P enabled | Enabled |

## What changed

- Check the device's default distributed backend before configuring per-edge P2P.
- Disable the option for XCCL while preserving its behavior for other backends.

## Numerics / performance

No numerical or performance measurements have been collected yet. An XPU pipeline run is needed to validate training behavior.

## Testing

- Python syntax check and `git diff --check` passed before commit.
- Verified on an XPU device internally and it passed the XCCL test.

**What this PR does.** Since #4540, `init_distributed` turns on PyTorch's `dist_config.pipeline_per_edge_p2p` whenever PP > 1. That flag splits a communicator for each directed PP edge. This PR leaves the flag off when the device's default backend is `xccl`, so XPU runs use the shared PP process group for P2P, as they did before #4540.

**Example.**
```
device_type="xpu", PP=2, PyTorch exposes pipeline_per_edge_p2p
  main: pipeline_per_edge_p2p=True  -> per-edge group split on XCCL fails (per PR; error not shown)
  PR:   pipeline_per_edge_p2p=False -> P2P uses the shared PP group
device_type="xpu", PP=2, older PyTorch without the option
  main: RuntimeError("Pipeline parallelism requires a PyTorch version ...")
  PR:   no error (per-edge isn't needed on XCCL)
device_type="cuda" (NCCL): unchanged
```

This works around a gap in PyTorch, not in torchtitan: either `ProcessGroupXCCL` lacks the comm splitting that per-edge P2P relies on, or PyTorch's per-edge path doesn't fall back for backends that can't split. Without a TODO, nobody will know when this vendor-specific `"xccl"` branch can come out of core code (CLAUDE.md principles 3 and 9).

Fix: make the comment a TODO that links an upstream issue (pytorch/pytorch, or intel/torch-xpu-ops if XCCL is the owner), e.g.

```python
# TODO(<upstream issue link>): XCCL cannot split process groups for directed
# PP edges. Remove this gate once per-edge P2P supports XCCL.
```

The proper fix belongs upstream. Per-edge P2P could check the backend's `supports_splitting` and fall back to the shared PP group. Then torchtitan wouldn't need a backend-name check.
