# [rl] Preserve explicit allocator settings across aliases

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5662) · state: open · merged: False

## Original PR description

TitanRL independently defaults both allocator configuration names. Setting only `PYTORCH_ALLOC_CONF=expandable_segments:False` therefore adds `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`, which PyTorch reads first and uses instead of the explicit setting.

Copy an explicit CUDA/unified value into the missing alias before applying defaults. Preserve empty values, both explicitly supplied values, and the existing late-import warning. Defaults are unchanged when neither alias is set.

Validation: eight CPU tests pass; four alias regressions fail on main. Three alternating baseline/candidate comparisons of actual H100 CUDA allocator snapshots confirm the fix with PyTorch 2.9.0+cu130. Applicable pinned file hooks pass; the unavailable global Pyrefly checker excludes both changed paths.

Prepared with AI assistance.
