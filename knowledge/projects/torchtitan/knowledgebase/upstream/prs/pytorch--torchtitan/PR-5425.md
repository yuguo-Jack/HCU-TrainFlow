# [CI Fix][GraphTrainer] Fix CUDA graph pass test fixture after feed-forward migration

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5425) · state: closed · merged: True

## Original PR description

The GraphTrainer A10G workflow fails in `TestDefaultTransformerBlockBuckets.test_compile_time_passes_follow_core_cuda_graph_config` with `AttributeError: 'int' object has no attribute 'feed_forward'` ([main job](https://github.com/pytorch/torchtitan/actions/runs/38732792440/job/116414518598)).

Introduced by #5345 (`d51e4b3c6b`): `compile_time_passes` now reads `layer_cfg.feed_forward`, but this fixture still supplies `layers=[0, 1]`. Give its two dense-layer stubs a `feed_forward=None` field, matching the other fixtures. Production pass behavior is unchanged.

Validation:
- Reproduced the exact exception using the original fixture against current main's pass implementation.
- All 3 tests in `TestDefaultTransformerBlockBuckets` pass after the change.
- CPU validation used isolated `torch==2.16.0.dev20261015+cpu` with the shared environment's incompatible optional CUDA-only `torchcomms` package hidden from import. The shared torch 2.14 environment cannot collect current main's tests because it lacks `analyze_pipeline_activation_liveness`.
- Ran `pre-commit run --all-files`: all hooks except Pyrefly pass; Pyrefly reports 54 existing dependency/type errors outside this change. Restored its unrelated automatic edits. Scoped lint passes with Pyrefly skipped.

Keeping this a draft pending the complete A10G GPU workflow. This fixes the reported fixture failure; it does not establish that every later workflow stage passes.
