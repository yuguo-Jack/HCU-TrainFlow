[CP] Add sliding-window varlen selective gather

## Summary (human-written)
Selective gather -- only gathering the required blocks instead of doing allgather.

Integrate selective gather CP for sliding window VarlenAttn. This PR depends on
https://github.com/meta-pytorch/attention-gym/pull/651.

This version assumes CP is within the same nvlink domain. A cross-nvlink domain version require the next attention-gym PR.

## Why
K/V all-gather copies tokens that sliding-window attention cannot use. Keep local K/V and gather only remote window blocks through attention-gym's copy-engine exchange.

Example: CP8, 128K tokens per rank, window 4096, block size 256:

```
All-gather K/V:         1024K tokens
Compact K/V:       at most 136K tokens
Saved remote K/V:  at most   8K tokens with full remat
```

These are buffer-size bounds. They exclude shared transport buffers and other activations. With full remat, all-gather also releases gathered K/V but fetches it again during backward. Selective gather retains halos to avoid that fetch. Model peak memory must be measured for each policy.

## What changed
- Use attention-gym's public builder for fixed contiguous or head-tail routing. Reuse exchanges across matching layers. Packed document offsets can change during CUDA Graph replay.
- Save remote K/V under full remat. During backward, rebuild compact K/V from local K/V and saved halos without fetching remote K/V again.
- Check compact K/V SPMD types and load-balancer compatibility. Support no balancer and head-tail; reject PTRR. Attention-gym validates actual token-range alignment.
- Keep the generic Muse Glimmer integration on all-gather. The H100 recipe selects selective sliding attention through the same setup, with full remat and real process groups.
- Mechanical: share varlen chunk helpers with all-gather.

## User-facing changes
| Attention | Backend |
| --- | --- |
| Sliding varlen | Opt into `SelectiveGatherKVSlidingWindowVarlenInnerAttention` with contiguous or head-tail CP in one NVLink domain. |
| Full varlen | Keep `AllGatherKVVarlenInnerAttention`. |

## Numerics
Loss and grad_norm match bit-for-bit across all 20 steps, both backends, and both remat policies on job 2276942. Seed 42, deterministic mode, BF16, FA4, and CUDA Graphs. All 64 rank records and TensorBoard files agree.

## Performance
Full 52-layer Muse Glimmer, CP16 on 16 GB300s in one NVLink domain, head-tail sharding, 256K packed tokens across 17 documents capped at 16K, and 2048-token sliding windows. Full layers use all-gather in both variants. The benchmark uses this PR's public-layout code with attention-gym 38cd874 and PyTorch 087ceb5.

| Remat | Sliding backend | Step (ms) | Peak allocated (GiB) | Peak reserved (GiB) |
| --- | --- | ---: | ---: | ---: |
| Full | All-gather | 2866.2 | 43.393 | 57.793 |
| Full | Copy engine | 2701.7 | 43.545 | 57.867 |
| Inner attention | All-gather | 2404.6 | 141.706 | 159.648 |
| Inner attention | Copy engine | 2227.7 | 141.857 | 159.139 |

- Copy engine reduces step time by 5.74% under full remat and 7.36% under inner remat. Peak allocated memory increases by 0.151 GiB in each pair.
- Inner remat uses save_regions=["*"] and recompute_regions=["attention.inner_attention*"]. Projection math runs once; inner attention runs twice. Bare operations outside saved regions can replay.
- One run per case on one allocation. Timing averages the slowest rank at each of 17 graph replays. Memory peaks include build, warmup, capture, and training; symmetric-memory buffers can be outside the allocator.

## Testing
- Pass each rank's `cp_query_ranges` to attention-gym `4bc108c`. All layout and plan fields match the benchmark builder across 12,496 rank-specific cases, including the full CP16 benchmark shape. Copy-engine source is unchanged. GPU checks and performance results use attention-gym `38cd874`.
- 75 TorchTitan CPU tests pass. They cover varlen attention, exchange sharing, fixed-layout rejection, remat regions, and saved K/V lifetime. Two shipped-recipe tests are excluded. Routing tests live upstream; all 39 host plan tests pass.
- The four-H100 numerical suite passes all eight combinations of contiguous/head-tail, remat off/on, and window sizes 1/4. It checks outputs, gradients, shared exchanges, changed documents, and CUDA Graph replay. The one-token window works with zero remote blocks.
- Both Muse Glimmer recipes validate. The H100 recipe was checked in isolation because the full module import fails on the torchvision issue below.
- Production validation, CP attention, and context-parallel helpers pass targeted Pyrefly with one PyTorch source path. All non-typechecking pre-commit hooks pass. Whole-worktree Pyrefly reports 195 dependency and scratch-file errors.

## Known issues
- The attention-gym release pin still lacks block exchange. Testing uses its local checkout.
- Whole-worktree typechecking reports scratch-file and dependency errors. The generic integration file has ten errors in untouched code.
- The full H100 suite cannot import torchvision locally because torchvision::nms is missing. Its existing Qwen3.5 import triggers the failure.
