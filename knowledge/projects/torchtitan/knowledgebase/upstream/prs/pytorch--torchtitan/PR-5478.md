# [rl] rollout_buffer gauges: count the groups the batcher took

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5478) · state: open · merged: False

## Original PR description

**TLDR:** `rollout_buffer/num_groups_finalized` reads 0 on most steps, and on one run 48 of 80 slots showed in no gauge. A new gauge, `rollout_buffer/num_groups_taken`, counts those groups, so the buffer gauges now add up to the slot budget.

**Problem**
1. The buffer has `(target_offpolicy_steps + 1) * num_prompts_per_train_step` slots.
2. A group keeps its slot until the weight pull after its optimizer step.
3. The batcher loop takes each finished group right away. The group leaves the buffer, so no gauge counts it, but it still holds its slot.
4. Qwen3.5-4B chess, 80 slots (wandb `chess_118/v6wbfy42`): `num_groups_finalized` read 0 in all 36 steps from 11 to 46.
5. At step 112, 48 of the 80 slots were in no gauge.

**Solution**
1. `RolloutGroupWorkBuffer.metrics()` logs `num_groups_taken`: groups the batcher took whose slot is not freed yet.
2. It is slots in use minus groups still in the buffer. Both counts already exist in the buffer, so the controller doesn't change.
3. Unchanged: the other gauges and their names.

```text
  num_groups_waiting      admitted, no rollout started
  num_groups_inflight     rollouts running
  num_groups_finalized    rollouts done, not yet taken by the batcher
+ num_groups_taken        taken by the batcher: in the batcher, the batch queue or the trainer
  available_active_slots  free
```

You may ask:
- Why not one gauge each for the batcher, the queue and the trainer? When the trainer logs, it always holds `num_prompts_per_train_step` groups, and the queue holds zero or one batch. The split would need two counters in the controller loops, and it adds little: the trainer's batch-wait ratio near 0 already says a batch was waiting.
- Why not rename `finalized`? It is the buffer's state name, and keeping it keeps old runs comparable.

NOTE: not run on GPU; the numbers above come from a run without this PR. The gauge is one subtraction of two counts the buffer already keeps.

**Test plan**
`pytest tests/rl/unit_tests/cpu/test_async_controller.py -k buffer_gauges`: four slots in four states each land in exactly one gauge, and freeing the taken group's slot moves it to `available_active_slots`.
