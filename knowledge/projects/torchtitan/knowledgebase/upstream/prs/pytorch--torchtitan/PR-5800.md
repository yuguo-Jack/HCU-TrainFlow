## Why
`resample_waveform` computes source positions in float32 (`arange(n, float32) * src / tgt`). Once the index gets large, float32 can't represent the fractional part well, so long clips get interpolated from slightly wrong positions. Every clip whose rate differs from the target goes through this, since the whole clip is resampled before truncation.

**Example.** 44.1 kHz -> 16 kHz, a ramp where each sample's value is its index:
- main: up to 0.125 samples off at 30 s
- this PR: exact

## What changed
- `torchtitan/components/data/multimodal/utils/audio.py`: compute the lower index and the interpolation weight with int64 `//` and `%` instead of float32 positions. Weights are still float32, output is unchanged for short clips.

## Testing
- New `test_resample_waveform_keeps_source_positions_on_long_clips` in `tests/unit_tests/cpu/components/data/test_multimodal_audio_utils.py`: fails on main (max error 0.125), passes with the fix. Rest of the file passes.
