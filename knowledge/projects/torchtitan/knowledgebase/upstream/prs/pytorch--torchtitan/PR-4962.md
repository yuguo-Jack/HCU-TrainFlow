# [distmuon] Unify matrix compute with BlockShard

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4962) · state: open · merged: False

## Original PR description

## Summary

- Define `BlockShard.block_sizes` as contiguous element counts so one matrix block is described uniformly as `R * C`.
- Support `BlockShard(dim=0, block_sizes=(R * C,))` for both a native `[B, R, C]` matrix batch and a single `[R, C]` matrix.
- Use that layout for Kimi K2.7 and Kimi K3 dense/shared FFN `w13` and `w2` parameters, deriving sizes from each layer configuration.
- Migrate existing Kimi per-head BlockShard layouts to element-count units and preserve the 2D Newton-Schulz path for a single 2D matrix.

## Motivation

DistMuon currently needs `Shard(0)` for a native `[2, F, D]` fused FFN weight and `Owned()` for a `[F, D]` weight, even though the optimizer unit in both cases is one contiguous `F * D` matrix. Element-count BlockShard metadata represents both shapes with the same layout and keeps matrix boundaries explicit.

This PR does not change BlockShard ownership or load balancing: blocks are still assigned by block count using the existing contiguous partitioning.
