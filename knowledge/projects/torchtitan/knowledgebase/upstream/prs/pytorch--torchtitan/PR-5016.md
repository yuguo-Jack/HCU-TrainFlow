# [torchft] Make the torchft manager timeout configurable

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5016) · state: closed · merged: True

## Original PR description

In 256-GPU torchtitan + torchft chaos runs with the native nccl2 process group (finding 11 in the report), one local rank per host blocked for 60 s in the reconfigure commRevoke after a shrink. Its peers were already in FSDP collectives that need that rank, and the intra-replica watchdog (`comm.train_timeout_seconds=60`) fired at the same moment the reconfigure timed out (torchft manager timeout, hard-coded default 60 s). The watchdog won on 11 of 29 hosts and SIGABRTed every rank, including rank 0, which hosts the ManagerServer. That turned a recoverable reconfigure failure into replica teardowns (56 aborts in one burst).

Fix: add `fault_tolerance.timeout_ms` (default 60000, unchanged behavior), pass it to `torchft.Manager`, and log a warning when the effective timeout (`TORCHFT_TIMEOUT_SEC` overrides it) is not below `comm.train_timeout_seconds`. The docstring notes that it also bounds checkpoint transfer during recovery.

Test plan:
- `pytest torchtitan/experiments/torchft/tests/test_torchft_manager.py` (new `test_timeout_is_passed_to_manager`)
- pre-commit (pyrefly not installed locally)
