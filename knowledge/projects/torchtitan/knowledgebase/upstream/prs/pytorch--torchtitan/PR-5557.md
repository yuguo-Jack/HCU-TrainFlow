# [CI Fix][ROCm] Refresh DeepSeek V3 CP MI350X golden

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5557) · state: closed · merged: True

## Original PR description

## Summary

- Refresh the MI350X DeepSeek V3 FSDP+CP+PP+EP loss and grad-norm golden.
- Keep the existing strict equality check and ten-step coverage unchanged.

## Why

#4760 switched DeepSeek V3 context parallelism to the compact MLA path and refreshed the A10G golden, but the MI350X golden was not updated. The ROCm workflow only runs after changes reach main, so the stale accelerator-specific file first surfaced there.

The new sequence is bitwise identical across consecutive main runs, including:

- https://github.com/pytorch/torchtitan/actions/runs/39326163793
- https://github.com/pytorch/torchtitan/actions/runs/39359318990
- https://github.com/pytorch/torchtitan/actions/runs/39366623432

The first passing run before #4760 and the first failing run used the same ROCm image digest and PyTorch nightly, isolating the change to TorchTitan source. The same new sequence also persists across later dependency nightlies.

## Test plan

- `SKIP=pyrefly-check pre-commit run --all-files` (pass)
- Full `pre-commit run --all-files`: all other hooks pass; local Pyrefly is blocked because the shared venv has PyTorch 2.14 and older torch_checkpointing APIs while current main targets PyTorch 2.16 nightly APIs.
- MI350X execution is covered by the linked independent main runs; ROCm hardware is not available locally.
