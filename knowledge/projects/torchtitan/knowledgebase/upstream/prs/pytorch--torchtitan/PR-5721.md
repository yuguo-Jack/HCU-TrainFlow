# [vision] Make vision rope_apply overridable through config

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5721) · state: open · merged: False

## Original PR description

## Summary

Add vision `rope_apply` to the config tree so it can be replaced through `@override`, while preserving the default computation.

## Why

Currently, each vision encoder selects the RoPE implementation in `forward` and passes it as a plain callable. It is absent from the config tree and cannot be targeted by `@override`.

Moving it into `VisionAttention.Config.rope_apply` allows the implementation to be replaced through the standard config override mechanism:

```python
@override(target=ComplexVisionRoPEApply.Config, exact=True)
def custom_vision_rope(cfg):
    return derive(cfg, CustomVisionRoPEApply.Config)
```

## What changed

- Wrap complex and cos/sin RoPE implementations using the existing `Function` pattern, without adding model parameters or checkpoint keys.
- Default configurations continue to call the existing rotary functions. `rope_cache` remains a forward argument, preserving its sharding boundary.
- Muse Spark reads the final `use_rope` value when constructing the encoder and uses identity RoPE when disabled, allowing recipes to change the flag after creating the config.
- `VisionAttention` and `VisionTransformerBlock.forward` no longer accept `rope_apply`. Callers that construct attention configs directly must provide the corresponding config.

## Numerics

Small Kimi K2.7, Kimi K3 and Qwen3.5 vision encoders were trained for 10 AdamW steps using identical synthetic inputs and targets, with FP32, a fixed seed and strict deterministic algorithms enabled.

All losses and gradient norms match bit for bit before and after the refactor, with a maximum absolute difference of **0**. Outputs, parameter gradients and final model states also match exactly.
