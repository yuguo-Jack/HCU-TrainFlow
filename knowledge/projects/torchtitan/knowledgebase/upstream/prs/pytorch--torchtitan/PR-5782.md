## Why

TorchTitan cannot build or train the released Flash-Next architecture. Qwen3.5
already supplies its GDN, gated shared experts, multimodal preprocessing,
vision encoder, FSDP and optimizer hooks, but the decoder has different residual,
lexical and sparse-attention computation. This PR adds those differences using
the existing model lifecycle and component configs.

Component reuse needs public Qwen3.5 config factories, ordinary `Linear.Config`
router gates, and a shared structural annotation contract for QSA metadata.
This model supplies the concrete consumer of all three shared API changes.

For a packed document with T tokens and hidden width D, a decoder block carries
four streams instead of one:

```text
[T, 4*D] -> PLE lookup/injection -> gated read [T, D]
          -> GDN or selected QSA -> gated residual write [T, 4*D]
          -> gated read [T, D] -> shared routed MoE -> gated write [T, 4*D]
```

Original token IDs and document positions reach PLE independently of multimodal
rotary coordinates. Masked/padded tokens do not contribute to MoE auxiliary
counts. The optional indexer-teacher objective trains only the indexer.

## What changed

- Expose `make_qwen35_deltanet_config` and `make_qwen35_vision_encoder_config`,
  accept the shared `Linear.Config` router-gate base, and use structural
  attention metadata annotation. Factory-callsite renames are mechanical;
  shared arithmetic and parameter layouts are unchanged.
- Add model-specific gated residual, offset/gated normalization, partial MRoPE,
  n-gram PLE, rounded router scoring and chunked selected-token QSA reference code.
- Reuse Qwen3.5's GDN/vision config factories and training/FSDP lifecycle.
- Export the standard model/flavor/build API and explicit indexer-loss config.
- Add strict HF mappings for all 1,627 released decoder/vision keys, including
  numeric lexical shard ordering; the 31 MTP keys are outside this model.
- Add independent feature/backward tests and the same-weight HF parity harness.

This initial increment supports FSDP. TP/SP and EP follow in `2/n`, the shared
deterministic GDN policy in `3/n`, and PP in `4/n`. CP remains unsupported.

## Alternatives considered

- Reimplement shared GDN/vision or add model-specific flags to common modules:
  rejected because the public Qwen3.5 config factories already supply both.
- Full dense attention with a sparse mask: the selected-token implementation
  expresses the released block/tail semantics directly, but its saved training
  memory is unresolved and requires the revision described above.

Full released-checkpoint materialization, 51.2B-table distributed conversion,
full-size training, inference KV caching and MTP are outside the validated scope.
The SDPA MATH path retains activations across query chunks; full-scale memory
and throughput are unqualified.

**Verdict: Request changes** -- under FSDP the QSA indexer can end up with `None` grads on some ranks, and the QSA training path's saved activations grow with sequence length times the 2,048-token budget. An attention-gym path for the same pattern already exists in `deepseek_v4`.

**What this PR does.** Adds `torchtitan/models/qwen3_8_flash_next/`, built on `Qwen35Model`. The model has a four-stream gated residual, a hashed n-gram PLE in layer 1, and QSA every fourth layer (the other layers are Qwen3.5 GDN). QSA is an indexer that picks top-k complete 4-token blocks, plus selected-token SDPA and an optional indexer KL loss. The PR also makes two Qwen3.5 config factories public, widens the shared router gate type to `Linear.Config`, and turns `AttentionMetadata` into a Protocol. FSDP only; TP, EP, PP and CP raise.

**Example.** `build_model_config("debugmodel", seq_len=64, parallelism=ParallelismConfig())` builds 8 layers, with QSA at `layer_id` 3 and 7 and GDN elsewhere. Activations go `[T, 256] -> repeat -> [T, 1024]`. In each block, a gated read gives `[T, 256]`, then attention or MoE, then a gated write back to `[T, 1024]`. With `token_budget=16`, a QSA query at position 38 of one document attends to the 4 best complete earlier blocks (16 tokens) plus its own incomplete tail of up to 3 tokens. Each attended token is gathered per query, then attended with SDPA MATH.

**Indexer params can get `grad=None` on some ranks, so FSDP2 reduce-scatters may not match.** The KL is the indexer's only gradient path: its input is `x_TD.detach()` (L370) and the selected indices are integers.

When a rank's microbatch has no complete 4-token block (all padding, or every document shorter than 4 valid tokens), `num_blocks == 0`. Then `raw_sum` stays the detached `new_zeros(())`, and `index_qk_proj`, `q_layernorm` and `k_layernorm` get `grad=None` on that rank while other ranks have grads. FSDP2 only reduces params whose `grad is not None`, so the ranks would issue different reduce-scatters. The `all_padding` unit test runs in one process and can't catch this.

Smallest fix: seed the sum from the graph, so the inject always carries a (zero) indexer gradient.
```python
raw_sum = scores_TB.sum() * 0  # keep indexer params in the graph on every rank
```
I haven't reproduced this on multiple GPUs.
