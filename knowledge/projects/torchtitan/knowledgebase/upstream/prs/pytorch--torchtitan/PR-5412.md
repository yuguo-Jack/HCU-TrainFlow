# [NPU] Initialize device backends before SPMD imports

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5412) · state: open · merged: False

## Original PR description

## Summary

Import `torch` at the TorchTitan package entry point, before submodules can import `spmd_types`. This is a deliberately small, backend-neutral initialization-order change: no explicit `torch_npu` import, device-specific branches, or swallowed initialization errors.

## Why

On the tested NPU stack, `import torchtitan.components.loss` enters `spmd_types` before Torch finishes loading its device extensions. NPU backend initialization then imports symbols from the partially initialized SPMD module, causing a circular-import failure involving `register_local_autograd_function`. Initializing Torch first makes that same native import succeed.

This only addresses imports through TorchTitan, not arbitrary third-party code importing `spmd_types` first.

## Validation and draft status

- The native import above fails before and succeeds after the change on Torch 2.14.0 / TorchNPU 2.14.0+git9c3f664 / spmd_types 0.2.3.
- `import torchtitan.models.base.module` succeeds both before and after.
- Formatting, syntax, license, flake8, ufmt, pydoclint, codespell and link checks passed.
- Full pre-commit was previously attempted: Pyrefly failed with dependency/API-resolution errors in the local Torch 2.11 environment, including missing main dependencies. The latest changed-file run also cannot locate Pyrefly on its default PATH. Full lint is **not** claimed passing.
- **Important:** main pins a newer SPMD commit than the tested stack. Reproduce and verify using main's pinned dependencies before requesting review.
- Native main RoPE test collection in the existing NPU environment is blocked by missing `torch_remat`. Full main NPU training, CUDA regression and CI are not claimed passing.
- No v0.3.0 training results are presented as current-main validation.

## Scope

One production file, three added lines. No custom test runners, environment patches, or v0.3.0-only adaptation changes are included. Main already covers some of those historical changes; the old RoPE workaround was also excluded after unmodified main methods passed direct NPU checks.

Please keep this PR as a draft pending validation with the matching main dependency stack.
