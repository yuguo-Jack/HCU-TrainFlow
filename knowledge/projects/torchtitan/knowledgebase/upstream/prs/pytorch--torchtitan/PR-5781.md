## Why

Flash-Next shares Qwen3.5's GDN and vision architecture, but its factory would
have to import private helpers or duplicate those configs. Its router also
uses ordinary `Linear` logits; the shared router's type currently restricts the
gate to `HiMidLoLinear`. Finally, sparse block metadata must participate in the
same SPMD annotation contract without making common attention import a model.

For example, the next PR can now express the checkpoint's rounded router logits
without changing shared router computation:

```python
TokenChoiceTopKRouter.Config(
    num_experts=8,
    gate=Linear.Config(in_features=256, out_features=8, bias=False),
    score_func=Float32Softmax.Config(dim=-1),
)
```

The config now type-checks. Existing `HiMidLoLinear` callers keep their behavior.

## What changed

- Expose `make_qwen35_deltanet_config` and `make_qwen35_vision_encoder_config`;
  rename every Qwen3.5-family caller mechanically.
- Type the router gate as its actual shared `Linear.Config` base class.
- Express non-Flex attention metadata through a structural
  `annotate_spmd_types()` protocol. Existing varlen/linear metadata already
  implement it; common code has no Flash-Next dependency.

This is the first dependency of the Flash-Next stack. The original implementation
PR #5655 and its worktree remain intact.

## User-facing changes

| Before | After |
| --- | --- |
| `_qwen35_deltanet_config` / `_qwen35_vision_encoder_config` are private factories | `make_qwen35_deltanet_config` / `make_qwen35_vision_encoder_config` support reuse by another flavor factory |
| Router gate is annotated as `HiMidLoLinear.Config` | It accepts the existing `Linear.Config` base and its subclasses |
| Closed attention-metadata annotation | Compatible metadata supplies `annotate_spmd_types()` without a common-code dependency on the new model |

## Numerics / performance

`06cd1fb1c4e1b340f5398c5b4ed1459530589d64` using the existing Qwen3.5 MoE
model and its multimodal video dataset on one NVIDIA GB300. Both runs use seed
42, strict deterministic execution, and 10 optimizer steps. Full-precision
TensorBoard loss and gradient norm are bitwise identical at every step;
`scripts/loss_compare.py --metrics loss,grad_norm --assert-equal` passes.
