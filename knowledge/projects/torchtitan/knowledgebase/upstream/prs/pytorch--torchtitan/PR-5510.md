# [rl] Verifiers: release each finished rollout's routing session (2/14)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5510) · state: open · merged: False

## Original PR description

**TLDR:** A Verifiers rollout now releases its routing sessions when Verifiers' `run` returns, as native rollouts already do. It also fixes a bug: one failing Verifiers rollout made the controller release its group while its siblings still generated.

**Problem**
1. **Native rollouts release.** `RolloutWorker` calls `release_session_fn` after a rollout's last turn: the router drops the session's pin and, with `session_kv_holder`, the generator frees its held KV.
2. **Verifiers didn't.** `VerifiersRollouter.run_group_rollouts` dropped `release_session_fn` (a TODO), so a pin stayed until the `max_sessions` LRU (262,144 entries) dropped it, and held KV stayed until the group ended.
3. **Group failure.** The group gathered without `return_exceptions`: one failing rollout raised at once, and the controller released the group while its siblings kept generating.
4. **What that leaks.** The siblings' later calls pin the group's cache salt and hold KV again, and nothing releases them.
5. **Cost today: small.** No recipe turns on `session_kv_holder`, and a stale pin is ~150 B. It matters once a recipe holds session KV.

**Solution**
1. `GenerationServer` now routes each call by Verifiers' `X-Session-ID`, which is the trace id.
2. When `VerifiersEnvClient.run` returns, `_run_single_rollout` releases every trace of the episode.
3. The group gathers with `return_exceptions=True` and raises the first failure after every sibling finished.
4. Unchanged: native rollouts.

```text
Verifiers path                          the rollout's sessions               the group
run returns, ok or not                  released, every trace (new)          released after every sibling (new)
a sibling's run raises                  the others released; it is not       released after every sibling (new)
an attempt Verifiers retried            not released (not in the traces)     released
cancelled mid-rollout (shutdown)        not released                         not released
```

NOTE:
- Releasing an id the router never saw does nothing; a failed release is logged.
- A call Verifiers gave up on can still run after `run` returns and pin its session again. The group's release frees its held KV; the LRU drops its pin.

**Test plan**
- `test_verifiers.py::test_rollout_releases_every_trace_session_even_if_one_release_fails`: two traces released in order; the first release's error is logged.
- `test_verifiers.py::test_a_failing_rollout_fails_its_group_only_after_every_sibling_finished`: fails without `return_exceptions`.
- `pytest tests/rl/unit_tests/cpu` (verifiers 0.4.0, on PR 1): 542 passed, 3 skipped. The fake traces carry `is_timeout`, which 0.4.0 reads.
