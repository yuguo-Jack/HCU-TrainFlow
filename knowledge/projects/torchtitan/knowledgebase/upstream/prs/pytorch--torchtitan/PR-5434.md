# [muse_spark][perf] Compile the attention's per-head norms and output gate

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5434) · state: open · merged: False

## Original PR description

**TLDR:** Muse Spark's per-head attention norms ran ATen `rms_norm` on 64-wide rows, far below bandwidth; two regions compile the q/k norms with the query scale and the output norm with the sigmoid gate: 2 layers -7% in training, -11% at prefill, -1 to -7% at decode.

**Problem**
1. **Per-head norms.** `MuseSparkAttention` normalizes q and k (`[T, 128, 64]`, `[T, 16, 64]`), scales q, and normalizes the attention output before a sigmoid gate.
2. **Tiny rows.** ATen's `rms_norm` kernel is slow on 64-wide rows: 403 us fwd for q + k at 4k, ~21 us ideal.
3. **Separate kernels.** The scale, reshape and gate multiply each add a pass over `[T, 8192]`.
4. **Cost.** q/k glue 794 us and output glue 814 us per layer at 4k, fwd+bwd (ideals 42 and 66 us).

**Solution**
1. **`muse_spark_attention_qk_norm`** compiles `q_norm(q) * scale_query_by` and `k_norm(k)` in `_norm_query_and_key`.
2. **`muse_spark_attention_output`** compiles the output norm, head flatten and sigmoid gate in `_flatten_attention_output`.
3. **Unchanged.** RoPE (Helion override) and attention stay outside; same math.

```text
before:  q -> rms_norm -> *scale       o -> contiguous -> rms_norm -> reshape -> * sigmoid(gate)   (eager)
after:   [q_norm*scale, k_norm]        [rms_norm -> reshape -> * sigmoid(gate)]                      (2 regions)
```

Correctness: not bitwise; the error vs fp64 is smaller than eager's in bf16 and the same in fp32.
```text
max relative error vs fp64, op level, 4k      output    input grads
bf16  q/k norm + scale      main              2.4e-3    2.9e-3
                            this PR           1.7e-3    2.3e-3
      output norm + gate    main              2.8e-3    4.3e-3
                            this PR           1.7e-3    2.3e-3
fp32  both                  main / this PR    ~7e-8     ~8e-8
```
2 layers at 4k: the difference from PR 2 is 1.5x what a 1-ulp change of the input causes; at op level the compiled version is the more accurate one.
Graphs: 4 per region across training (2k, 4k, 16k) and inference (prefill 2k, 16k; decode 1-256) shapes, limit 8.

NOTE: per-head norms are local under TP (heads are sharded). Not tested: multi-GPU, loss curve.
