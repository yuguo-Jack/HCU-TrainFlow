## Why

V4.1's three-block DSpark decoder predicts five draft positions together, conditioned on three backbone residuals and frozen shared embeddings/output weights. The main text-training loss does not train this decoder. Its projections and final heads also need to execute inside the owning FSDP blocks.

**Example.**

```text
three frozen backbone residuals -> main projection -> draft blocks -> logits
frozen noise-token embeddings ---------------------^               ^
teacher-forced previous tokens -> Markov correction ---------------+
pre-final-norm residual -> FP32 confidence
```

`model(tokens, return_draft_context=True)` returns concatenated features; `model.forward_draft(...)` computes the auxiliary predictions. The caller owns the CE/confidence loss, draft schedule, separate optimizer, and the frozen output weight's lifetime through backward. The standard text recipe does not invoke the drafter.

## What changed

- Add blockwise draft attention, main conditioning projection, low-rank Markov correction, and confidence head; map the released `mtp.*` keys.
- Stop gradients into the backbone features, draft embeddings, and shared output projection.
- Execute projections and final heads inside their owning FSDP block forwards.
- Include drafter blocks in the model's rematerialization lifecycle, with flat tensor outputs, distinct KV region names, and explicit Markov-head recompute dependency.
- Register balancing/count reset for the separate drafter optimizer. Restrict visual balancing to backbone layers, because backbone and drafter have different expert counts.

The debug fixture uses eight backbone experts and four drafter experts; released counts are 384 and 128. Coupled projections/heads and unsupported inherited embedding/output config are validated explicitly.

## User-facing changes

| Before | After |
| --- | --- |
| Standard text loss trains the backbone | Standard recipe remains backbone-only; a separate caller can train DSpark with its own objective and optimizer |
| No draft-context/auxiliary forward API | Frozen context collection and five-position draft predictions |
| No `mtp.*` checkpoint mapping | Draft blocks, Markov, and confidence weights map to HF |

The `mtp.*` key translations are mechanical. Frozen dependencies, FSDP ownership, and rematerialization boundaries require correctness review.

## Numerics / performance

| Check | Result |
| --- | --- |
| Native / independent author draft CE+BCE | Both `8.35378646850586` |
| Logical HF drafter parameter gradients | 102 tensors, including six inactive-expert zero gradients |
| Drafter gradient max error / norm ratio | `1.49e-8` / `1.000000000029365` |
| Draft logits / confidence max error | `1.19e-7` / `0` |
| Drafter remat off/on within FSDP2 | All 10 losses, global norms, and all 69 native gradients per step bitwise equal |
| Frozen backbone after 10 auxiliary optimizer steps | Every parameter exactly unchanged |

Changing the reduced drafter's expert count exposed image quantizer boundary sensitivity. A `1.49e-8` pre-quantization attention difference crosses an E4M3 midpoint; raw independently rounded image logits differ by at most `1.594e-3`. The image arithmetic comparison holds quantizer inputs equal, independently verifies all 34 author quantizer outputs bitwise, and retains independently computed selections; controlled logits differ by `3.58e-7`. The raw error is stored explicitly. Text and drafter comparisons retain independent quantization decisions.

## Testing

32 CPU model tests and all-file pre-commit passed. The CPU remat test keeps two distinct outstanding draft contexts and checks exact outputs/loss/all gradients plus frozen backbone ownership. The FSDP2 run checks actual auxiliary optimizer hooks, counter reset and synchronized biases after every step, reconstructed projection/confidence gradients, and exact frozen backbone values.

Hardware: two GB300 GPUs; published, unmodified PyTorch `2.16.0.dev20261030+cu132` ARM wheel.
