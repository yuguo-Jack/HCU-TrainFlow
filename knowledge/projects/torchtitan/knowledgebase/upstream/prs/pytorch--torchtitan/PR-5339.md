# [rl] Verifiers: release each finished rollout's routing session

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5339) · state: closed · merged: False

## Original PR description

**TLDR:** A Verifiers rollout now releases its routing sessions once Verifiers' `run` returns, as `RolloutWorker` rollouts already do. A first commit fixes a bug: one failing Verifiers rollout made the controller release its group while its siblings still generated.

**Problem**
1. **Native rollouts release.** `RolloutWorker` calls `release_session_fn` after a rollout's last turn: the router drops the session's pin, and with `session_kv_holder` the generator frees the session's held KV.
2. **Verifiers didn't.** `VerifiersRollouter.run_group_rollouts` deleted `release_session_fn` (a TODO). A finished session kept its pin until the `max_sessions` LRU (262,144 entries) dropped it, and its held KV until its group ended.
3. **Group failure.** `run_group_rollouts` gathered without `return_exceptions`. One failing rollout raised at once, and the controller called `release_groups` while the siblings kept generating.
4. **What that leaks.** The siblings' later calls pin the group's cache salt and hold KV again, and nothing releases them.
5. **Cost today: small.** No recipe turns on `session_kv_holder`, and a stale pin is ~150 B. It matters once a recipe holds session KV on GPU or offloads it to CPU.

**Solution**
1. `GenerationServer` routes each call by Verifiers' `X-Session-ID`, which is the trace id.
2. Once `VerifiersEnvClient.run` returns, `_run_single_rollout` calls `release_session_fn` for every trace of the episode. Another agent's trace has its own id; releasing an id the router never saw does nothing. A failed release is logged, as in `RolloutWorker`.
3. First commit: the group gathers with `return_exceptions=True` and raises the first failure once every sibling finished.
4. Unchanged: the `RolloutWorker` path.

Release paths after this PR:
```
path                                              the rollout's session             the group
RolloutWorker: done, or env / generator error     released after the last turn      released after the group
Verifiers: run returns, ok or not                 released, every trace (new)       released after every sibling (new)
Verifiers: a sibling's run raises                 the others released; it is not    released after every sibling (new)
Verifiers: an attempt Verifiers retried           not released (not in the traces)  released
cancelled mid-rollout (shutdown)                  not released                      not released
```

NOTE:
- A call Verifiers gave up on can still be running when `run` returns, and pin its session again after the release. The group's release frees its held KV; the LRU drops its pin.

**Test plan**
- `test_verifiers.py::test_rollout_releases_every_trace_session_even_if_one_release_fails`: two traces (another agent's and the policy's); both ids are released in order, and the first release's error is logged.
- `test_verifiers.py::test_a_failing_rollout_fails_its_group_only_after_every_sibling_finished`: fails without the first commit.
- `pytest tests/rl/unit_tests/cpu/test_verifiers*.py` (verifiers 0.3.1): 32 passed.
