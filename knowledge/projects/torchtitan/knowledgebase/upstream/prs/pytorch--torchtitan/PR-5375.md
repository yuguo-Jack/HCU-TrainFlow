# [rl] Enable Muse Glimmer for Verifiers tasks

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5375) · state: closed · merged: True

## Original PR description

## Why

Verifiers rebuilds its renderer in environment-server workers from a serialized `renderers` config. Muse Glimmer is implemented in TorchTitan, so workers could not load its former TorchTitan-only dataclass config without patching the installed `renderers` package.

## What changed

- Upgrade to `renderers` 0.1.12. Muse Glimmer now has one `BaseRendererConfig` subclass, `MuseGlimmerRendererConfig`, which validates the options on both the trainer and environment-server sides. `from_renderers(CustomRendererConfig(import_path=..., ...))` adapts it to TorchTitan recipes; workers import the same renderer by path without a registry patch.
- Allow the Verifiers rollouter to forward any TorchTitan renderer config that exports a worker config. Muse implements the 0.1.12 `Renderer` protocol, including `parse_response(..., prompt_ids=...)`.
- Migrate the Search-R1 Muse recipe to `from_renderers(...)` and add a Muse Glimmer Terminal-Bench recipe using the same path. The Terminal-Bench example caps Muse 30B at 16K context and 8 agent turns; it is not a full 120-turn benchmark recipe.

## Verification

- Focused CPU tests: 163 passed, 1 skipped. They cover config validation and transport, worker reconstruction, trainer/worker token-id parity, ATEM tool-call parsing, and both recipes.
- All pre-commit hooks except repository-wide Pyrefly passed; scoped Pyrefly on the changed production files and Muse renderer tests found no errors. Full-tree Pyrefly fails on unrelated local dependency/PyTorch API mismatches.
- Prior manual internal-model comparison produced the same 193 token IDs on the controller, in a spawned worker, and with the old patched-library path. A live Terminal-Bench training run with this PR has not been performed.

hmm, let me explain again - We don't need `to_renderers()` function. 

We want to enable following torchtitan config: 
``` 
renderer=from_renderers(
              CustomRendererConfig(   # this is a class from prime-rl's repo
                  import_path="torchtitan.models.muse_glimmer.renderer.MuseGlimmerRenderer"
              )

``` 

The from_renders() is needed here because our config tree expect a torchtitan's `RendererConfig` object, so we convert from prime-rl's to ours (RendererConfigAdapter)

However, terminal-bench (via `Verifiers`) rollouter needs torchtitan's `RenderConfig` -> Prime RL's, so each worker_server process can import and read the render class within it's own process. Since the original prime-rl's render is already stored in RendererConfigAdapter.render_config, we don't need `to_renders` function at all, just get_render_config() is enough. Updated the name
