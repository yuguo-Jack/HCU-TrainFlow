# [muse_spark][perf] Enable the Muse Spark regions by default

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5433) · state: open · merged: False

## Original PR description

**TLDR:** The three Muse Spark regions were on only in the Dist-MoE scale recipes. With them in the model's default list, the base, debug and RL recipes get the same fused kernels: on 2 layers, training -7 to -10%, prefill -10%, decode -7 to -11%.

**Problem**
1. **Regions exist.** `model.py` declares `muse_spark_residual`, `muse_spark_input_scaled_rmsnorm` and `muse_spark_logit_postprocess`.
2. **Recipe-only.** Only the Dist-MoE scale recipes add them to `local_compile_regions`. The base, debug and RL recipes keep the default `["loss", "fp32_to_bf16_split"]`.
3. **Eager there.** The residual, the post-FFN norm and the expert-output norm each run as separate eager kernels.
4. **Cost.** At 4k tokens, per layer: residual 724 us, post-FFN norm 381 us, expert-output norm 1335 us. The bandwidth ideals are 95, 47 and 189 us.

**Solution**
1. **Model default.** Add the three regions to `MuseSparkModel.Config.local_compile_regions`.
2. **Recipe.** Delete the scale recipes' now-redundant `extend`.
3. **Unchanged.** The region code. The two LoRA SFT recipes still set `["loss"]`, so they don't get these regions.

NOTE:
- New reach: the base, debug and RL DAPO recipes (trainer and generator). The RL generator compiles these regions under FULL CUDA graphs for the first time.
- `muse_spark_input_scaled_rmsnorm` is not batch invariant: a batch-invariant run must clear the regions, as other models' batch-invariant recipes do.
- The debug model gives each layer its own gain center, which can add a graph per region. Not run yet (see the TODO below).
- Not tested: multi-GPU, loss curve.
