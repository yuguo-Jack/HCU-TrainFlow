# [rl] terminal-bench 9B recipe: use the default FULL cuda graphs

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5491) · state: open · merged: False

## Original PR description

NOTE: measured on H100 only; needs retesting on Blackwell.

**TLDR:** The Qwen3.5-9B Terminal-Bench recipe drops its `FULL_DECODE_ONLY` pin and uses the generator's default `FULL` CUDA graphs. On a Terminal-Bench-shaped replay, generator busy time drops 229.9 -> 195.1 s (-15%, H100).

**Problem**
1. `rl_grpo_qwen35_9b_terminal_bench` pins `cuda_graph=VLLMCudaGraphConfig(mode="FULL_DECODE_ONLY")`.
2. Under that mode only pure-decode steps replay a graph. A step that also carries a prefill runs eager, its decode tokens included.
3. Terminal-Bench turns add ~1.1K tokens each (completion plus terminal output), so many steps mix one session's new turn with other sessions' decode.
4. The pin is left over from a `FULL` bug that was fixed (`b67239bc9`); `FULL` has been the default again since `a6948f508`, and the same 9B model runs it in `rl_grpo_qwen3_5_9b_varlen`.

**Solution**
1. Remove the pin; the recipe inherits `FULL`, which also graphs mixed steps up to `max_num_batched_tokens` (unset here: the engine default, 2,048).
2. Unchanged: the 35B-A3B recipe (its MoE dispatcher can't be captured) and the generator defaults.

**Results**
```text
Numerics: FULL_DECODE_ONLY is bitwise identical to eager. FULL is not, on prefill steps (they run padded inside graphs):
          greedy tokens identical on 158 of 192 prompts; mean |logprob diff| 0.006 before the first divergence, max 0.46.
          Real 9B weights, recipe settings, 192 prompts of 100-8,000 tokens, 32 greedy tokens. No NaN in any mode.

Qwen3.5-9B, 32 layers, random weights, 1x H100, FA3; DP=1, max_num_seqs 192, max_model_len 131072.
64 multi-turn sessions; busy time = sum of engine step times; each cell shows two runs.
workload                                   FULL_DECODE_ONLY      FULL                delta
Terminal-Bench-shaped (12 turns, 585+512)  228.0 / 231.9 s   ->  195.3 / 194.9 s     -15%
small turns (6 turns, 256+512)              58.3 /  57.2 s   ->   45.4 /  46.7 s     -20%
large turns (6 turns, 512+3,072)           134.4 / 136.1 s   ->  125.4 / 131.0 s      -5%
cost: graph capture 3 -> 5 s, graph pool 0.13 -> 0.60 GiB, KV cache -0.7%
```

NOTE: generator busy time from a synthetic replay, not RL step time; the end-to-end effect wasn't measured.
NOTE: the runs weren't counterbalanced, and another job shared the host during the FULL_DECODE_ONLY runs. A separate A/B at `max_num_batched_tokens=8192` gave -14% on Terminal-Bench-shaped turns.

**Test plan**
`pytest tests/rl/unit_tests/cpu/test_verifiers_terminal_bench.py`. The two asserts that pinned the dense recipe's graph mode are deleted: they restated a recipe value.
