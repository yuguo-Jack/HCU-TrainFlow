# [Release CI] Add RL suites to release GPU validation

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5589) · state: closed · merged: False

## Original PR description

## Summary

Add RL to TestPyPI GPU release validation without allowing RL dependencies to replace the selected Torch release wheels.

- A10G: RL unit tests, deterministic loss guard, and integration tests.
- B200: retain the core Dist-MoE CPU/GPU unit coverage, and add the RL Dist-MoE recipe unit test plus the active `rl_b200` integration suite.
- Run copied tests outside the checkout so they exercise the installed TorchTitan candidate.
- Pin the compatible vLLM nightly and resolve its dependencies across PyPI and the PyTorch wheel index.
- Install TorchAO for non-RL suites from the matching nightly CUDA index, consistent with main CI, while keeping release Torch and TorchVision pinned.

## Validation

- `bash -n .github/scripts/validate_release_gpu.sh`
- Scoped pre-commit hooks for the changed shell and workflow files.
- Confirmed the TorchAO nightly CUDA 13.0 index provides current x86_64 and aarch64 wheels.
- The B200 source-wheel dry run completed the active `rl_b200` integration test successfully. Its unit-test command referenced a test added after the release branch cut; that reference has been removed while existing release-branch Dist-MoE unit coverage remains intact.
- Local 8x H100 investigation confirmed that the existing Kimi K3 parity tests are skipped and the only `rl_kda` case is disabled, so this PR does not add a no-op H100 lane.

H100 RL release validation can be added when Kimi K3/MLA coverage is enabled.
