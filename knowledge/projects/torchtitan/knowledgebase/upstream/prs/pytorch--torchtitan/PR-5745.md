[attention] Share varlen metadata with CP variants

## Summary (human-written)
`VarlenAttentionMetadata` is namedtuple because we want to avoid
`pytree.register_dataclass`. However, this design make the typing
harder and confusing. This PR makes `VarlenAttentionMetadata` a
dataclass so that other CP variation can inherits from
it -- you cannot do this with namedtuple.

## Why
All-gather and selective-gather varlen CP share document offsets and window limits, but need different prepared metadata. Their forward signatures should state that requirement. Shared metadata subclasses and generic attention classes preserve the sliding-window inheritance and each variant's input type. The selective-gather PR uses this contract for _SelectiveGatherVarlenMetadata. This checks direct forward calls and overrides; PyTorch module calls remain untyped.

```python
class AllGatherKVVarlenInnerAttention(
    AllGatherKVVarlen,
    VarlenInnerAttention[AllGatherKVVarlenAttentionMetadata],
): ...
```

## What changed
- Use frozen dataclasses for varlen metadata. Copy all base fields into CP metadata without copying tensors. Register both types as PyTrees through torch.export.register_dataclass.
- Make full and sliding-window varlen attention generic in their metadata type. Default to VarlenAttentionMetadata. Share the kernel call through _forward_varlen so CP can pass chunk metadata without widening its public input type.
- Mechanical: update metadata constructors, field access, and dataclasses.replace calls in Flux and existing tests.

## Alternatives considered
- Dataclass inheritance alone cannot narrow an overridden method's input type.
- A separate inner module adds indirection and breaks the sliding-window class relationship.

## User-facing changes
| Before | After |
| --- | --- |
| metadata._replace(...) | dataclasses.replace(metadata, ...) |
| cp_metadata.varlen_metadata.cu_seq_q | cp_metadata.cu_seq_q |

md = replace(VarlenAttentionMetadata(cu_seq_q=cu, cu_seq_k=cu, max_q=8, max_k=8),
             window_size=(3, 0))

cp.cu_seq_q                          # same tensor object as md.cu_seq_q
isinstance(cp, VarlenAttentionMetadata)  # now True

- claude[bot] · comment · 2026-11-02T20:40:48Z · [source](https://github.com/pytorch/torchtitan/pull/5745#discussion_r4447479120)

File: `torchtitan/models/common/attention/attention.py` · line 344

Should consider: the `Generic[_VarlenMetadataT]` parameterization is the larger half of this PR. It brings the `typing_extensions` import (the first in the repo), a `forward` that only asserts and forwards to `_forward_varlen` (plus a 13-line docstring), and `assert isinstance(self, VarlenInnerAttention)` in the CP mixin (`cp_attention.py:370`) so the checker can resolve `self._forward_varlen`. What it buys is narrower static types on overrides and direct `.forward` calls. As the description says, `module(...)` calls stay untyped, and the CP `forward` already raises `ValueError` on the wrong metadata type at runtime.

A smaller version keeps only the dataclass inheritance:
- `VarlenInnerAttention.forward` stays typed `VarlenAttentionMetadata`.
- `AllGatherKVVarlen.forward` takes `VarlenAttentionMetadata` and keeps its existing `isinstance` -> `ValueError` check.
- CP keeps calling `super().forward` with the chunk metadata, so `_forward_varlen` and the self-assert go away.

That's roughly 40 fewer lines, with the same runtime behavior. #5746 would follow the same pattern for `_SelectiveGatherVarlenMetadata`. If you keep the generic for the typing benefit, consider dropping the parameter-restating docstring. The old `forward` had none, and nothing in it is non-obvious.
