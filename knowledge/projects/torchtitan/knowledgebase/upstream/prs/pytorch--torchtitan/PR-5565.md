# [models] Defer backend errors from attn_gym's lazily resolved exports

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5565) · state: closed · merged: True

## Original PR description

## Summary

Follow up to #5467 and #5500. attn_gym resolves its backend backed exports on first attribute access (`attn_gym.linear._lazy`), `causal_conv1d`, `causal_conv1d_decode` and `paged_causal_conv1d` come from `attn_gym.linear.short_conv`, which imports fine, only the `getattr` imports `attn_gym.linear.short_conv.cute` and raises `ImportError("causal_conv1d requires the optional CuTeDSL backend: ...")` chained from `ModuleNotFoundError(name="cutlass")`. #5467 only deferred a `ModuleNotFoundError` raised by the module import itself, so `gdn.py` / `kda.py` still failed to import on a machine without cutlass, and with them everything that imports `torchtitan.models.common`, 18 of the CPU test modules did not collect on macOS.

- `__getattr__` resolves exports through `_load_export`, an `ImportError` whose cause is a backend's `ModuleNotFoundError` is recorded under `"<module>.<export>"` and the export becomes a placeholder carrying that error, exactly like an export of a module that failed to import. A missing attn_gym module, or an `ImportError` that is not a missing module, still raises at import.
- The install hint now names attn gym 0.0.17, the version `.ci/docker/requirements.txt` pins (noted in the #5467 review).
- No change when every backend imports, `getattr` succeeds and nothing is recorded.

On a machine without cutlass the models now import, `causal_conv1d` is a placeholder, so `InnerKDA` / `InnerGDN` (which check it in `__init__` since #5500) fail at build with the cutlass error instead of at the first forward, and `KDAKernel` / `GDNKernel` still build when their own backends import.

Also takes the optional note from the #5500 re review, the build test now breaks one thing per case, so each entry of the `require_attn_gym` lists is load bearing.

## Test plan

`tests/unit_tests/cpu/models/common/test_optional_imports.py`:

- New `test_attention_gym_lazy_exports_with_missing_backend`, a fake `attn_gym.linear.short_conv` resolves `causal_conv1d` lazily and fails on cutlass. `gdn` imports, `gdn.causal_conv1d` is a placeholder (not `_MissingKernel` itself), calling it and `require_attn_gym(causal_conv1d)` raise `ModuleNotFoundError(name="cutlass")`, an `ImportError` chained from a missing attn_gym module, and one that is not a missing module, still raise and leave no placeholder. Fails without the facade change (the `ImportError` escapes at import), passes with it.
- `test_attention_modules_report_their_own_backend_at_build` is reparametrized over 11 cases, each breaking exactly one thing on a backend of its own, the `attn_gym.linear.short_conv` module, or one of the 10 exports the `require_attn_gym` lists name (`causal_conv1d`, `chunk_kda`, `bound_gate`, `l2norm`, `chunk_gdn`, `recurrent_gdn`, `context_parallel_kda`, `context_parallel_gdn`, `context_parallel_conv_history`, `ContextParallelRouting`), broken through the lazy export path. Each case asserts the placeholder is named after what failed and exactly which of `KDAKernel`, `GDNKernel`, `InnerKDA`, `InnerGDN`, `ContextParallelInnerKDA`, `ContextParallelInnerGDN` fail at build. Dropping `ContextParallelRouting` from the `cp_kda.py` list fails only the `[ContextParallelRouting]` case, without the facade change the 10 export cases fail and the module case passes.
- The two install hint asserts updated to 0.0.17.

On macOS 15 (attn-gym 0.0.17, no cutlass/triton), rebased on a4a62b3, `pytest tests/unit_tests/cpu --collect-only` goes from 1371 tests collected / 23 errors to 1640 / 5. The 18 errors fixed were all the `causal_conv1d` `ImportError`, the 5 that remain are `experiments/graph_trainer/paged_stash_memory_policy.py` importing triton at module level (3) and an older `renderers` in my env (2), neither touched here. Of the 18 modules, 16 run standalone, 210 passed, 2 fail for platform reasons (`qwen3_8` builds a model whose inner modules need cutlass and gets the deferred cutlass error at build, `test_lora_forward` runs torch.compile on CPU), the other 2 (`kimi_k3/test_kimi_k3_config.py`, `recipes/test_debug_config_defaults.py`) hit the graph_trainer triton import when run on their own. `test_optional_imports.py` 25 passed, pre commit on both files passes every hook except pyrefly, which reports the same pre existing diagnostics as main.

The root cause is right. #5467 only caught a `ModuleNotFoundError` from `import_module`, but `attn_gym.linear._lazy` raises a wrapping `ImportError` later, from `getattr`. Handling that in `_load_export` is the right layer for the fix. The change is small, `_is_backend_error` now holds the logic both paths share, and the success path is the same as before (`getattr` still returns directly). Below is one UX regression worth fixing, plus a few nits.

I wasn't able to run the tests or pre-commit in this environment because the commands need approval, so everything here comes from reading the code. I did check every entry in `_BUILD_FAILURE_CASES` against the `require_attn_gym(...)` calls in `kda.py`, `gdn.py`, `cp_kda.py` and `cp_gdn.py`, and they all match.

---

#### 1. attn_gym's install hint is dropped from the deferred error (`attn_gym.py:228-233`)

`_load_export` records `cause`, the inner `ModuleNotFoundError("No module named 'cutlass'")`. `_raise_for` then re-raises only `str(cause)` and chains from `cause`. The outer `ImportError` (`"causal_conv1d requires the optional CuTeDSL backend: ..."`) is discarded, and that's the one with the guidance the user can act on. It doesn't appear in the message or anywhere in the traceback chain. So a user building `InnerKDA` on a machine without cutlass gets a bare `No module named 'cutlass'`. The new test even pins this: `assert str(error) == "No module named 'cutlass'"`.

For a module-level failure, the recorded MNFE is the whole story. For a lazy export, attn_gym has deliberately written a better message, and we should keep it. One option, which keeps `_BACKEND_ERRORS: dict[str, ModuleNotFoundError]` and the `name=` contract:

```python
key = f"{module.__name__}.{name}"
recorded = ModuleNotFoundError(str(error), name=cause.name, path=cause.path)
recorded.__cause__ = error
_BACKEND_ERRORS.setdefault(key, recorded)
```

The test assert would then become `"CuTeDSL backend" in str(error)` (or similar), with `error.name == "cutlass"` unchanged.

[Fix this →](https://claude.ai/code?q=In%20torchtitan%2Fmodels%2Fcommon%2Fattn_gym.py%20on%20branch%20attn-gym-lazy-exports%2C%20_load_export%20records%20only%20the%20inner%20ModuleNotFoundError%20cause%2C%20so%20attn_gym%27s%20outer%20ImportError%20message%20(with%20the%20install%20hint)%20is%20lost.%20Record%20a%20ModuleNotFoundError(str(error)%2C%20name%3Dcause.name%2C%20path%3Dcause.path)%20with%20__cause__%20set%20to%20the%20original%20ImportError%20instead%2C%20and%20update%20test_attention_gym_lazy_exports_with_missing_backend%20in%20tests%2Funit_tests%2Fcpu%2Fmodels%2Fcommon%2Ftest_optional_imports.py%20to%20assert%20the%20outer%20message%20is%20preserved.&repo=pytorch/torchtitan)

#### 2. Only explicit chaining is recognized (`attn_gym.py:228`)

`error.__cause__ or error` covers `raise ImportError(...) from mnfe`, which is what attn_gym 0.0.17 does. If a later release uses implicit chaining instead (`raise ImportError(...)` inside an `except`, with no `from`), only `__context__` is set. The error then escapes at import and the 18 collection failures come back. Keeping this narrow is reasonable (CLAUDE.md #7), so I'm not asking for a change. I'd mention in the docstring that this relies on attn_gym using `from`, so the next person to see the failure knows where to look.

#### 3. Nits

- `_raise_for` docstring (`attn_gym.py:134`): "the backend error recorded for the export's module". Since a key can now be `"<module>.<export>"`, this should say "for the export or its module".
- `_missing_backend_kernel(module_name)` (`attn_gym.py:177`): the parameter now also receives `"<module>.<export>"` keys. Renaming it to `key` would match how `_BACKEND_ERRORS` is now described.
- `_is_backend_error` doesn't defer `error.name is None`, same as the old inline check. Good, the behavior hasn't changed.

#### Tests

- Reparametrizing the build test so each case breaks exactly one thing works well. Every `require_attn_gym` entry is now covered by a case that fails if the entry is dropped. The placeholder-name assert (`_MissingKernel[<module>.<export>]` vs `_MissingKernel[<module>]`) also checks which path recorded the error.
- In the module case (`"attn_gym.linear.short_conv"`), the export is found with `next(... if module == broken)`, which depends on `_EXPORTS` dict order (it currently picks `causal_conv1d`). Any export of that module works for the assert, so this is fine. Just flagging the order dependence.
- `test_attention_gym_lazy_exports_with_missing_backend` covers both negative paths (an attn_gym submodule as the cause, and an `ImportError` with no MNFE cause), including the check that no placeholder gets cached (`name not in facade.__dict__`). Monkeypatching `facade.import_module` relies on the facade's local name for it, but it runs in a subprocess, so it can't leak into other tests.
- The version bump to 0.0.17 matches `.ci/docker/requirements.txt:13`, and the sync comment is a useful addition.

#### Summary

The change is correct and well-scoped. Fixing **#1** before merge would give users attn_gym's actionable message instead of a bare `No module named 'cutlass'`. The rest is optional.

#### Fresh pass on the facade

- **Success path:** unchanged. `getattr` returns directly, nothing is recorded, and `__getattr__` caches the value in `globals()` as before.
- **Fallback when `__cause__` is missing:** `cause = error.__cause__ or error` also covers a lazy `getattr` that raises a bare `ModuleNotFoundError`. In that case `recorded` repeats the same message and chains to the original. That's harmless, so no change needed.
- **What still raises at import:** `_is_backend_error` keeps the old rule. A missing `attn_gym.*` module, or an MNFE with `name=None`, raises at import. An `ImportError` that isn't caused by an MNFE also re-raises unchanged. The test covers all of these.
- **`setdefault`:** each export has its own key and is cached in `globals()` after its first access, so `setdefault` never sees a second write in practice. It's still a reasonable guard.

#### Tests

- `expected_message` in the build test (`broken in facade._EXPORTS` → attn_gym's message, otherwise the backend's) checks each of the 11 cases against the error path it should go through. With fix #1 in place, the export cases also check that the outer message is kept.
- `test_attention_gym_lazy_exports_with_missing_backend` checks the recorded message, `recorded.__cause__.__cause__`, and the message raised both by calling the placeholder and by `require_attn_gym`. That covers the whole chain.

#### Nit (optional)

- `assert str(recorded.__cause__.__cause__) == ...` depends on the fake's exact two-level chain. That's fine for a fake, but `error.name == "cutlass"` on the outermost error is the actual contract callers rely on, and that's already asserted.

LGTM. The fixes are minimal, they match the suggestions, and the tests have been updated to cover them.
