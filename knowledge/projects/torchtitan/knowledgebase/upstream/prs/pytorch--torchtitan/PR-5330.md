# [attention] Add recipe-owned dense causal BF16 SDPA

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5330) · state: open · merged: False

## Original PR description

Prepared with AI assistance.

Reuse PyTorch SDPA with cuDNN/Flash preference for one continuous unpadded
context row. Preserve the standard MLA projection/sharding wrapper and replace
only its Q/K/V attention leaf. Compose the existing fused MLA and dense leaf
in one override, avoiding order-dependent parent/child replacements.

Keep continuous-row data policy outside core. The unmasked_text_rows override
selects recipe-owned ContinuousTextCollator/ContinuousTextDataLoader for both
training and validation. Supply continuous valid-token positions before native
collation/MTP counting; preserve source labels, masks and native padding.
Packing stays token-bounded and attention metadata stays context-row-bounded.
Core TextCollator has no toggle and retains its native document-aware behavior.
Already continuous fixed-row sources need only the attention override.

Reject padding, document resets, CP/incomplete sequence layouts and unsupported
attention variants rather than silently changing semantics or dispatch.

**Verdict: request changes.** Don't merge this as one PR. Drop the continuous-row data path (`unmasked_text_rows`, `ContinuousText*`, and the core capacity hook). Merge the dense attention leaf only if a benchmark shows it beats stock varlen on one segment; otherwise keep it in the branch.

### Merge or keep in a branch?

The PR does two separate things, and they deserve different answers.

**1. The data policy (`unmasked_text_rows`, `ContinuousTextCollator`, `ContinuousTextDataLoader`): don't ship it, not even in recipes.** Moving it from `TextCollator` into `torchtitan_recipes/` changes where the code lives, but your concern was about offering the option at all. It is still in-tree, documented in the core data README, and enabled with one flag. The benchmark doesn't need it either. The author's earlier reply says the MLPerf AirStore provider "already supplies aligned full rows with continuous positions", and the README added here says such sources "can use the attention override alone". So for the stated use case this code adds nothing. It is also the only reason for the core hook `_get_attention_document_capacity` (`loader.py:61`, `trainer.py:92,150`, `validator.py:393`). That hook is a private method on the base config, called from trainer and validator, and only the recipe overrides it. Anyone who really wants unmasked packing can write their own source, as you suggested.

**2. The dense attention leaf (`DenseCausalBf16SDPA` plus `dense_causal_fused_mla`): it could be worth merging, but the PR doesn't yet justify it.**
- **For merging:** it's about 150 lines in `torchtitan_recipes/overrides/` and off by default. It also refuses inputs where it would change results: padding, position resets, CP, sliding windows. That keeps the risk to real workloads low. A recipe override with a GPU test is also the cheapest way to keep it reproducible. Code kept in a fork tends to break as core changes the attention metadata and override APIs, so if vendors are meant to reproduce numbers, keeping it in-tree helps.
- **Against:** stock `VarlenInnerAttention` already has `sdpa_backends = [CUDNN_ATTENTION, FLASH_ATTENTION]` with `set_priority=True` (`attention.py:337-345`). The workload this override targets, one causal unpadded row, can already run on stock varlen with `cu_seqlens=[0, T]` and `max_num_documents=1`. The PR has no throughput numbers; the description says "not 671B throughput". For a performance PR, the only reason to merge is a measured win over that baseline.

**Recommendation:** split the PR. Delete the data path and its docs. Then post a benchmark of dense SDPA against stock varlen with `max_num_documents=1` at the real shape (DSv3 MLA, 4K-8K tokens, the target GPU). If the gain is clear, say 3% or more end to end, land the attention override. The only core change it should need is the `_requires_document_capacity` ClassVar. If the gain is noise, keep it in the branch and document how to reproduce with the stock path.

<summary>Detailed review notes</summary>

### Core and scope

- **The data path is still offered** (`torchtitan_recipes/overrides/dense_causal_sdpa.py:63-113`, `:248`, `torchtitan/components/data/README.md`). See point 1 above: remove it.
- **Core hook used by one recipe** (`torchtitan/components/data/loader.py:61`). The base `BaseDataLoader.Config` gains a private `_get_attention_document_capacity`, and core code calls it in four places. Only the recipe overrides it, which conflicts with "Don't leak experiments into core". It goes away once the data path is removed.
- **Unupdated callsite.** `torchtitan/experiments/torchft/trainer.py:176` still passes `config.dataloader.max_num_documents`, so the torchft trainer and the base trainer would disagree about capacity under `ContinuousTextDataLoader`. Also moot once the data path is removed.
- **Recipe policy documented in model docs** (`torchtitan/models/deepseek_v3/MTP.md:72-78`). The model doc describes a recipe-only collator as if MTP relied on it. It should be removed together with the data path.
- **Core test imports a recipe** (`tests/unit_tests/cpu/test_trainer.py`). The core trainer test now imports `torchtitan_recipes.overrides.dense_causal_sdpa`. Recipe tests should stay under recipe test paths.

### Attention leaf

- **`sdpa_backends` is silently ignored** (`dense_causal_sdpa.py:122`). `DenseCausalBf16SDPA.Config` inherits the `sdpa_backends` field, but `_dense_causal_sdpa` hardcodes `[CUDNN, FLASH]`. Either use the inherited field or reject non-default values. As written, a user who sets it gets no effect and no warning.
- **Missing equivalence test against stock varlen.** The GPU test compares against SDPA's MATH backend, not against the path this replaces. Add a test showing that `DenseCausalBf16SDPA` and `VarlenInnerAttention` with one segment produce matching output and gradients. Together with the benchmark, that is what supports merging.
- **No benchmark.** The PR has no perf numbers: no tokens/s and no kernel timings against the stock varlen baseline. Following CLAUDE.md, use at least 10 steps.
- **Async asserts on validation failure** (`build_attention_metadata`). If positions aren't continuous or padding is present, `torch._assert_async` triggers a device-side assert, which kills the CUDA context and gives a vague error. That's acceptable for a benchmark-only override, but say so in the docstring.

### Looks fine

- `dense_causal_fused_mla` reuses `fused_mla` and swaps only the leaf `inner_attention`. That composition is correct, because `derive` returns a new parent config and assigning to it doesn't change the caller's `cfg`.
- GQA works: `enable_gqa` is passed through `kwargs` the same way the stock varlen path does it, and the parametrized test covers `kv_heads=2`.
- Rejecting window sizes, non-plain Varlen configs and `out_transform` matches "fail instead of silently changing semantics".
