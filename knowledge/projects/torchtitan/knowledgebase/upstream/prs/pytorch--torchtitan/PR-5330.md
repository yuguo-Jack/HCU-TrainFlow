# [attention] Add dense causal BF16 SDPA override

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5330) · state: open · merged: False

## Original PR description

## Agent details

Prepared with AI assistance.

Add an opt-in dense causal BF16 SDPA override using strided Q/K/V views and native cuDNN/Flash selection. Keep existing document-aware training unchanged by default.

Packed text also needs an explicit data policy: `TextCollator.Config(mask_document_boundaries=False)` makes positions continuous within each context row before MTP token counting. It applies equally to training and validation; labels and padding remain unchanged. Source-document packing limits are ignored with a warning in this mode, while attention metadata capacity is derived from context rows rather than source documents.

Enable both overrides:

```bash
--override torchtitan_recipes.overrides.dense_causal_sdpa.dense_causal_bf16_sdpa,torchtitan_recipes.overrides.dense_causal_sdpa.unmasked_text_rows
```

For DeepSeek fused MLA, use the combined factory. It composes the existing fused MLA and dense attention implementations without weakening parent/child override conflict checks:

```bash
--override torchtitan_recipes.overrides.dense_causal_sdpa.dense_causal_fused_mla,torchtitan_recipes.overrides.dense_causal_sdpa.unmasked_text_rows
```

Dense attention requires one full, unpadded context row. Unsupported Flex attention, document resets, padding, windows, context parallelism, and incomplete token layouts fail explicitly. Multiple flattened context rows keep their boundaries and require varlen attention. Fixed two-offset dense metadata does not require a document-capacity setting.

Disabling document boundaries changes training semantics, not only performance. Already-continuous frozen sources can use the attention override alone. Pipeline validation CUDA graphs are owned by #5241; this PR does not duplicate that feature.
