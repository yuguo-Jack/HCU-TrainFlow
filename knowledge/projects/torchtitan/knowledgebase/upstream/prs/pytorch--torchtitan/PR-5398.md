# [spmd_types] Overlap module-boundary collectives with compute (async_op)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5398) · state: closed · merged: True

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.15.0) (oldest at bottom):
* __->__ #5398

spmd_types collectives wait on the NCCL result right after issuing it, so
module-boundary redistributes (e.g. the sequence-parallel all-gather before
attention/MLP and the reduce-scatter after) never overlap with compute in
eager mode. The DTensor backend avoided this by calling
`redistribute(..., async_op=True)` at exactly these boundaries.

spmd_types now has the same opt-in (meta-pytorch/spmd_types@fce1acb:
`async_op`, forward only by default; `backward_options={"async_op": True}`
for backward). This bumps the spmd_types pin to that commit and passes
`async_op=True` through `spmd_redistribute_per_axis` from the two
module-boundary call sites in `Module`. Backward collectives still wait.
