# [muse_glimmer] Size the q/k RoPE row permute from the tensor

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5726) · state: closed · merged: True

## Problem

`MuseGlimmerStateDictAdapter` permutes q/k rows between torchtitan's interleaved and HF's split-half RoPE layouts. The k call sites in `to_hf` and `from_hf` pass the projection's `(head_dim * n_kv_heads, dim)` explicitly, so a tensor with the projection's rows but another second dim fails in the `view`. Concrete case: exporting a rank-r LoRA factor `lora_B` of the fused `wqkv` through `to_hf` (as an RL trainer does to serve the adapter) raises

```
RuntimeError: shape '[2, 32, 2, 256]' is invalid for input of size 512
```

on the `debugmodel` flavor with a rank-4 factor. The q path already sized itself from the tensor.

## Change

The permute only reorders rows, so `_permute` and `_reverse_permute` take `(rows, cols)` from the tensor, the `dim1`/`dim2` parameters go away, and the geometry helper returns only the head counts that remain in use. No numerics change for weights: the explicit dims equaled the weight's own shape.

## Testing

- New CPU unit test `TestMuseGlimmerStateDictAdapterRowPermute`: a rank-wide factor exports with the q/k/v row counts and the same row order as the weight. Fails on main with the error above, passes with the change.
- `tests/unit_tests/cpu/models/muse_glimmer/test_muse_glimmer.py`: 6 passed.
- Loading `meta-models/Muse-Glimmer-30B` and exporting it back through `to_hf` is bit-exact against the safetensors (TP=1 and TP=2) before and after.

**Verdict: Approve -- please address the items below before merging.** The fix deletes dead size parameters, so the row permute sizes itself from the tensor. Weights get the same result as before, and the change touches only the muse_glimmer adapter. A maintainer still needs to review.

**What this PR does.** `_permute` / `_reverse_permute` used to accept optional `dim1`/`dim2`. Only the text k-projection call sites passed them, always as `(head_dim * n_kv_heads, dim)`, which for a real `wk` equals `w.shape`. The PR drops those parameters, reads `(rows, cols)` from the tensor, and shrinks `_attn_geometry` to `_attn_heads`, since `dim` and `head_dim` no longer have a consumer.

**Example.** On the `debugmodel` flavor, a rank-4 factor with the fused `wqkv` row count goes through `to_hf`:
```
before: _permute(wk_factor, n_kv_heads, head_dim*n_kv_heads, dim)
        -> view(2, 32, 2, 256) on a (128, 4) tensor -> RuntimeError
after:  _permute(wk_factor, n_kv_heads)
        -> view(2, 32, 2, 4) -> (128, 4), rows in the same order as the weight
real wk (128, 256): identical in both versions (explicit dims == w.shape)
```

- **Prior art.** `muse_spark/state_dict_adapter.py:39` (`_permute_rope_rows`) already sizes its permute from the tensor. That helper is private to muse_spark, so not reusing it here is correct.
