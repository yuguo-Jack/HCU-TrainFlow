# [rl] MoE router replay: train on the experts the generator chose

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5255) · state: open · merged: False

## Original PR description

**TLDR:** The trainer can now route each token to the experts the vLLM generator chose (router replay). On Qwen3-30B-A3B the trainer-generator k3 KL drops ~6x. One flag, off by default.

**Problem**
1. The generator (vLLM) and the trainer run the same MoE weights.
2. bf16 noise near the top-k boundary still sends some tokens to different experts: 12.8% of (token, layer) top-8 sets on Qwen3-30B-A3B, from 0.1% at layer 0 to 19% at layer 36.
3. A token routed differently gets a different logprob, so `p_trainer / q_generator` moves for reasons unrelated to the policy update.
4. Cost: k3 KL 2.8e-4 per token; the worst token per step is off by 2 nats on average.

**Solution**
1. `VLLMGenerator.Config.return_routed_experts = True`.
2. The generator returns each token's experts; the trainer routes the same tokens to them.
3. Gate weights still come from the trainer's scores, so the router keeps its gradient.
4. Without the flag nothing changes.

```text
generator (vLLM)             rollout                                trainer
router --hook--> capture     Completion.routed_expert_ids           model_kwargs["routed_expert_ids"]  [T, L, K]
                             [P+N-1, L, K] uint8                      Decoder: layer i gets [:, i]
                             -> RolloutTurn: a delta, like the prompt router:  ids    = replayed ids
                             -> TrainingSample: [len(tokens)-1, L, K]          weights = scores.gather(ids)
```

**Results**
```text
Qwen3-30B-A3B (48 layers), DAPO math, on-policy, 8xH100; steps 1-3, same seed and prompts
                 replay off            replay on
k3 KL            2.4e-4 - 3.2e-4  ->   4e-5 - 5e-5        ~6x
mean |Δlogp|     0.0071 - 0.0085  ->   0.0030 - 0.0038    2.3x
max |Δlogp|      1.04 - 1.35      ->   0.21 - 0.93

Same model cut to 2 layers, DAPO math, 4 steps, this branch
native rollouter     k3 7.6e-4 - 1.2e-3  ->  9e-5 - 1.0e-4     max |Δlogp| 0.76 - 1.46  ->  0.07 - 0.085
Verifiers rollouter  k3                      9e-5 - 1.0e-4     max |Δlogp|                  0.06 - 0.074
```
- Correctness: replaying a model's own routing is bitwise identical (logits and grads), with FullAC, SelectiveAC and RegionAC, in all 7 MoE families.
- Cost: every trainer rank receives the whole microbatch grid, and the ids grow it 38 -> 422 B/token: +270 ms/step (~1.5%) on the 30B grid. TODO in `controller.py`.

You may ask:
- Why a forward argument and not router state? Activation-checkpoint recompute and CP sharding both see forward arguments; state would be read again later.
- Why not replay the gate weights? The router would get no gradient.
- Where is the routing-mismatch % above from? Router counters plus a measure-only mode, left for a follow-up PR to keep this one small.

NOTE:
- The 30B replay arm ran 3 steps; the matched 100-step pair is not run yet.
- Verifiers gives a continued turn's last token the row of the token before it (TODO in the rollouter).
