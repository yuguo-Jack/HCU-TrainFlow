# [rl] Skip validation data construction when steps=0

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5747) · state: closed · merged: False

## Original PR description

## Why
`ValidationConfig(steps=0)` disables validation; the Muse Spark DAPO recipe uses it for a five-step training run. However, `Controller.setup_async()` still calls `get_validation_samples(0)` to size generator concurrency. The accessor builds the held-out dataset before returning an empty list, so disabled validation still loads data and can fail if that data is unavailable.

For `get_validation_samples(0)`:

| Behavior | Before | After |
| --- | --- | --- |
| Returned samples | `[]` | `[]` |
| # of dataset constructions | 1 | 0 |

## What changed
Return immediately for zero steps in the shared accessor. The existing guard in `Controller.validate()` does not cover startup. Extend the existing data tests to catch unintended dataset construction; retain coverage for positive limits and `-1`.

## Numerics / performance
No model computation changes. End-to-end loss comparison and performance benchmarks were not run.
