## Why
GPU unit tests have failed on main since #5774 (`a3e458c73`). `apply_fsdp_to_multimodal_encoder` and `apply_fsdp_to_decoder` now build the mixed-precision policy from `Module.named_preserve_dtype_params()`. `tests/unit_tests/gpu/distributed/test_fsdp_cpu_offload.py` passes plain `nn.Module` fakes, so all three `TestVisionEncoderCPUOffload` tests fail:

```
AttributeError: '_VisionEncoder' object has no attribute 'named_preserve_dtype_params'
```

The real encoders and decoders are torchtitan `Module`s (the helpers' declared type), so the fix belongs in the test.

## What changed
- `_VisionEncoder`, `_Block` and `_TinyVLM` in the test subclass `torchtitan.models.base.module.Module` instead of `nn.Module`, like other test fakes (`test_aux_loss.py`, `test_remat_all_to_all.py`). Test-only.

## Testing
- `pytest tests/unit_tests/gpu/distributed/test_fsdp_cpu_offload.py` on 2 GPUs: 6 passed (3 failed on main).

**What this PR does.** Since #5774, `mixed_precision_policy()` (`torchtitan/distributed/fsdp.py:250`) calls `module.named_preserve_dtype_params()` on the module passed to `apply_fsdp_to_multimodal_encoder` / `apply_fsdp_to_decoder`. Both helpers are typed to take a torchtitan `Module`, but the test fakes were plain `nn.Module`s, so the call raised `AttributeError`. The PR changes the three fakes to subclass `torchtitan.models.base.module.Module`. That matches the real encoders and decoders, and other GPU test fakes already do the same (`test_activation_checkpoint.py`, `test_remat_all_to_all.py`, `test_deepep_activation_checkpoint.py`).

**Example.**
```python
# before: _VisionEncoder(nn.Module)
apply_fsdp_to_multimodal_encoder(model.vision_encoder, mesh, ...)
# -> AttributeError: '_VisionEncoder' object has no attribute 'named_preserve_dtype_params'

# after: _VisionEncoder(Module)
# -> _preserve_dtype_params == (), so preserved is empty,
#    param_dtype_override_fn is None, and the policy is the same as before #5774
```

- Gate: the problem is real on `main`. `mixed_precision_policy` calls the `Module`-only method with no fallback, and the helpers' declared `encoder: Module` type is correct for every in-repo caller.
