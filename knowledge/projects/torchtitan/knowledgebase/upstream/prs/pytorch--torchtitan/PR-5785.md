## Why

The preceding model increment rejects PP. Flash-Next carries four residual
streams, and PLE needs original token IDs and document positions even when its
layer is on a later stage. The final stream mixer must remain with the language
model head. This PR uses the existing pipeline hooks to preserve those contracts
and supplies combined training and a repeatable numerical regression fixture.

**Example.** Four virtual stages over PP2:

```text
stage 0: token embedding + layer 0 -> [T, 4D]
stage 1: layers 1-3, including PLE -> [T, 4D]
stage 2: layers 4-5                -> [T, 4D]
stage 3: layers 6-7 + stream mixer + language-model head
original token IDs and document positions reach every stage
four microbatches use Interleaved1F1B with full activation remat
```

## What changed

- Enable real PP through the inherited `BaseModel.pipeline` hooks and pin the
  stream mixer with `pipeline_last_stage_module_fqns`. Fake PP raises because
  its static metadata assumes one residual stream.
- Add a packed-document CPU split-model forward/backward check for the original
  ID payload, PLE after a stage boundary, and every stage parameter gradient.
- Register the real eight-GPU FSDP2/TP2/EP4/PP2 recipe in the model and H100 suites:
  four virtual stages, four microbatches, Interleaved1F1B and full remat.
- Register a GB300 TP2/EP2/SP numerical fixture with its exported loss/grad_norm
  golden and public hardware/software/source/data provenance.
- Mechanical: move the existing TP2 recipe beside the new PP recipes and extend
  the existing suite-registration checks.

The shared engine rejects SPMD typechecking under PP. The combined PP recipe
uses that supported contract; the TP2/EP2/SP numerical fixture checks types.
This PR depends on `[qwen3_8_fn] 3/n`.

## Alternatives considered

- A model-specific pipeline engine would duplicate existing stage ownership
  and schedule machinery.
- Putting PLE only on stage 0 would leave its later-stage original-ID contract
  unexercised; the four-stage recipe places it on stage 1.
- A single local numerical capture does not establish independent remote
  repeatability; qualification and export use remote GB300 launches.

Full-size lexical conversion/training, sparse-attention throughput/memory and CP
remain outside the verified scope. No performance improvement is claimed.
