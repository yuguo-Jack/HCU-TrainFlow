[config] Remove the CP import cycle

## Summary (human-written)
config/__init__.py shouldn't import parallelism, this causes a circular
import and this PR remove it.

```
context_parallel -> config/__init__.py -> config/parallelism -> context_parallel
```

## Why
A CP-first import fails on main. CP imports Configurable, but config/__init__.py eagerly imports ParallelismConfig, which reads the unfinished CP module.

```python
from torchtitan.distributed.context_parallel import ContextParallelLoadBalancer
```

## What changed
- Remove the eager parallelism exports from config/__init__.py. Keep the direct load-balancer type annotation.
- Mechanical: update ten test files to import from config.parallelism.
- Add one fresh-process regression test for CP-first imports and runtime type hints.

## User-facing changes
| Before | After |
| --- | --- |
| Import ParallelismConfig or FSDPSymmMemScope from torchtitan.config | Import from torchtitan.config.parallelism |

## Alternatives considered
- A type-only CP import avoids the cycle but breaks get_type_hints(ParallelismConfig).
- A lazy export adds a compatibility layer that the repo does not require.

## Numerics
Imports only. No tensor math or training behavior changes. GPU numerics were not rerun.

**Verdict: Approve** -- the cycle is real, the fix removes it at its source (the eager re-export in `torchtitan/config/__init__.py`), and every in-repo caller is updated. A maintainer still needs to review, since this touches core config.

**What this PR does.** `torchtitan/distributed/context_parallel.py` imports `torchtitan.config.configurable.Configurable`. Importing that submodule runs `torchtitan/config/__init__.py` first, and before this PR that file eagerly imported `.parallelism`, which in turn imports `ContextParallelLoadBalancer` from the half-initialized CP module. The PR removes the `ParallelismConfig` / `FSDPSymmMemScope` re-exports and switches 10 test files to `torchtitan.config.parallelism`. It also adds one fresh-process regression test.

**Example.**
```python
# fresh interpreter
from torchtitan.distributed.context_parallel import ContextParallelLoadBalancer
# before: context_parallel -> config/__init__ -> config/parallelism -> context_parallel
#         -> ImportError (ContextParallelLoadBalancer not yet defined)
# after:  config/__init__ only loads configs/configurable/function/loader/override -> OK
```

### Should consider
- `tests/unit_tests/cpu/config/test_parallelism_config.py:23-27` -- the `get_type_hints` assertion has no in-repo consumer, and the annotation is evaluated eagerly anyway. The two imports alone catch the regression (see inline).

<details><summary>Details</summary>

- **Callsite audit.** No remaining `from torchtitan.config import ParallelismConfig/FSDPSymmMemScope` or `torchtitan.config.ParallelismConfig` attribute access anywhere in `torchtitan/`, `torchtitan_recipes/`, `tests/`, scripts, or `*.md` docs. Recipes and most tests already imported from `torchtitan.config.parallelism`, so this PR also unifies on one import path.
- **Remaining `config/__init__` imports.** `configs`, `configurable` (-> `observability.structured_logger`), `function`, `loader`, and `override` don't import `parallelism` or `distributed.context_parallel`, so this cycle is fully gone.
- **Alternative.** Importing `Configurable` from a different path in `context_parallel.py` wouldn't help, because any `torchtitan.config.*` import runs the package `__init__`. Removing the re-export is the smallest correct fix.
- **Test cost.** One subprocess that imports torch. This guards an import-order invariant that in-process pytest runs can't detect once some other module has already imported `torchtitan.config`, so it earns its place.

</details>
