# [graph_trainer] Save tensors written by forward in-place ops instead of recomputing them

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5622) · state: open · merged: False

## Original PR description

Fixes #4688

SAR recomputes a node by re-running whatever produced it, but doesn't replay in-place writes made into it later. Pass 1b in `tag_sac_policy` saves mutation nodes and their users, which works when make_fx rebinds the tensor to the mutation output. Two cases where that doesn't happen:

1. A mutable op that returns `()`, e.g. clone -> custom in-place kernel -> return clone, as in the issue
2. A write through a view of a recomputable tensor, e.g. `y[:k] = v` or `y.view(-1)[:k].add_(1)`

In both, reads after the write still point at the pre-write node. That node stays recomputable, and backward gets a copy without the write.

This adds `_force_save_forward_mutation_bases`, run right after Pass 1b and after min_cut tagging. For each forward mutation, it marks the base of the written tensor MUST_SAVE if the base is recomputable and read outside the mutation. The read check keeps things like `zeros_like(...).scatter_(...)` in MoE routing recomputable.

Test plan:
- issue repro: grad 4 -> 6
- custom op, view write and slice assignment, traced with `minimal_fx_tracer` under default / full / min_cut: wrong before, bitwise equal to eager after
- 3-layer toy model on GPU with `memory_policy="default"`: max grad error ~963 before, 0 after
- no tag changes on the llama3 and qwen3 MoE debug models; `test_bitwise_deterministic` passes (DSv3 skipped locally, needs FA3)
- two new tests in `TestApplySACPass`, which fail on main and pass here
- `test_passes`, `test_cpu_offload`, `test_remat_metadata`, `test_sac_peak_memory`, `test_numerics`, `test_paged_stash`: 265 passed, 6 skipped (existing skips)

`sac_and_offload` still gives wrong grads for the view case, but that also happens on main without this change, so I'll file it separately.
