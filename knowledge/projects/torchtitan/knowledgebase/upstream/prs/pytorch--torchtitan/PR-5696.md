# [DistMuon] Test that packed chunks compute on the right rows

## Why
Since #5468, a rank can compute several chunks of one parameter, packed into one compute tensor. No test runs `step()` on that path: the CPU schedule test checks plan structure only, and no GPU test packs. A mismatch between the planner's packing order and the offsets DistMuon uses for its Newton-Schulz views would make Newton-Schulz run on the wrong rows, with no error, and still pass every existing test.

## What changed
- Extends the shared-bucket test from the previous PR, renamed `test_shared_bucket_matches_per_parameter_buckets`. It adds a compute-ready (3, 64, 64) parameter that only ranks 0-2 hold, so their fixed work pushes every other parameter's chunks onto rank 3. It also adds a `BlockShard(dim=0, block_sizes=(4, 2))` parameter, so the packed chunks have different shapes.
- The test asserts that `a`, `b`, `c` and `blocks` really pack onto rank 3 before comparing results, so it can't silently stop covering packing if placement changes.

## Testing
- The test passes on this stack (4 GPUs).
- With DistMuon's views assigned in reverse packing order, a stand-in for a packing/view mismatch, it fails on `layers.0.blocks`. With equal-shaped chunks it would not catch that, which is why the blocks alternate 4 and 2 rows.
