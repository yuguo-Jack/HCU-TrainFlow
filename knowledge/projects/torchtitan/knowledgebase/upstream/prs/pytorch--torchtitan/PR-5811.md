# [rl] generator: move the engine-agnostic model build, state dict load and paged attention out of vllm/

## Why
The generator's TorchTitan model build, its initial HF load, the FSDP
per-group model state dict load, and the paged-KV call into the trainer's
varlen FlashAttention live inside `generator/vllm/`, although none of them is
vLLM-specific. The SGLang engine stacked on top of this PR needs the same
code; without this move it would have to copy about 500 lines of FSDP storage
handling.

**Example.**
```python
# before: VLLMModelWrapper owns the build and the load
engine._get_model()._prefetched_model_state_dict
engine._get_model().load_model_state_dict(fetch)

# after: any engine's wrapper builds the same loader
model, parallelism_context = build_inference_model(config, parallelism=..., precision=..., device=...)
load_initial_weights(model, config, checkpointer_config)
loader = ModelStateDictLoader(model, model_state_dict_load_mode=...)
loader.load(fetch)            # engine._get_model().model_state_dict_loader.load(fetch)
```

## What changed
All mechanical: the same calls in the same order.
- `torchtitan/rl/generator/inference_model.py` (new): `build_inference_model`,
  `load_initial_weights`, `ModelStateDictLoader` (the `_fsdp_load_groups`,
  reshard/restore/unshard helpers and `load_model_state_dict` body from
  `vllm/model_wrapper.py`), and `get_attention_dimensions` (from
  `vllm/attention/attention.py`).
- `torchtitan/rl/generator/paged_attention.py` (new): the FA3/FA4 activation and
  the `varlen_attn_out` call (cu_seqlens_k handling, `num_splits=1` for FA2 and
  batch-invariant mode) from the vLLM CUSTOM backend.
- `vllm/model_wrapper.py`, `vllm/attention/attention.py`, `vllm/engine.py`,
  `vllm/registry.py`: call the shared code; the wrapper exposes
  `model_state_dict_loader`.
- Tests: the load tests move from `test_vllm_wrapper.py` to
  `test_inference_model.py` unchanged; other tests follow the renames.

Reviewers can skim the moved bodies; the call sites in `vllm/model_wrapper.py`
are the part to check.

**Verdict: Approve -- please address the items below before merging.** This is a mechanical move. Each step runs in the same order, and the second consumer (#5812, SGLang) already calls every new entry point.

**What this PR does.** It moves three things out of `generator/vllm/` into engine-agnostic modules, because none of them depends on vLLM:
- The TorchTitan model build, the initial HF load, and the per-FSDP-group model state dict load go to `inference_model.py`.
- The FA3/FA4 activation and the paged-KV `varlen_attn_out` call go to `paged_attention.py`.

`VLLMModelWrapper` now calls `build_inference_model` and `load_initial_weights`, and holds a `ModelStateDictLoader`. `VLLMEngine` reaches the load and the pinned buffers through that loader.

**Example.**
```python
# before (vllm/engine.py)
self._get_model().load_model_state_dict(fetch)
self._get_model()._prefetched_model_state_dict
# after
self._get_model().model_state_dict_loader.load(fetch)
self._get_model().model_state_dict_loader.prefetched_model_state_dict
```
The wrapper's `__init__` used to run about 100 lines of build/parallelize/materialize code. Now it runs `build_inference_model -> _initialize_dist_moe_runtime -> load_initial_weights -> _inject_attention_sinks -> _patch_vllm_all_reduce -> maybe_apply_numa_binding -> ModelStateDictLoader(...)`. The loader's constructor groups the parameters by FSDP group, allocates the pinned buffers, and unshards the model, the same as the old inline code did.

### Should consider
- `torchtitan/rl/generator/inference_model.py:227` -- the loader could do the NUMA binding itself, so engines don't need to call it in the right order before building it (inline).
- `torchtitan/rl/generator/inference_model.py:33` -- `get_attention_dimensions` fits better in `paged_attention.py` than in the model build/load module (inline).

<details><summary>Details</summary>

- **Ordering check.** The only step that moved relative to the others is `_fsdp_load_groups` plus the `gpu_fetch` quantized-param check, which now runs after `maybe_apply_numa_binding`. Neither depends on the binding. The vLLM dtype check now runs before the `ParallelismContext` is built, and that has no side effects.
- **Leftover callers.** No in-repo callers remain of `wrapper.load_model_state_dict`, `wrapper._prefetched_model_state_dict`, `_maybe_initial_load_weights`, `_checkpointer_config`, `model_wrapper._fsdp_load_groups` / `_unshard_and_free_sharded_params`, or `attention.get_attention_dimensions`. The `generator._prefetched_model_state_dict` hits are a separate attribute on `Generator`.
- **Imports.** `inference_model.py` imports no vLLM, so `registry.py` can import `get_attention_dimensions` at top level without the old deferred import.
- **Paged attention.** `paged_varlen_attention_out` gets the same arguments as before. `cu_seqlens_k` for FA2 is built on `query[:num_actual_tokens].device`, the same device as before. `num_splits=1` for FA2 / batch-invariant mode, `enable_gqa`, and `return_aux` still apply under the same conditions.
- **Unchanged generic-code calls.** The moved code still calls `torch.cuda.empty_cache()` and `torch.cuda.get_device_capability()` in modules that are now engine-agnostic. I left these alone: changing them would be a drive-by fix in a move-only PR, and FA3/FA4 is CUDA-only anyway.

</details>

- claude[bot] · comment · 2026-11-04T16:31:05Z · [source](https://github.com/pytorch/torchtitan/pull/5811#discussion_r4470270209)

File: `torchtitan/rl/generator/inference_model.py` · line 234

Should consider: the docstring at L199 makes every engine call `maybe_apply_numa_binding` before it builds the loader. The vLLM wrapper (`vllm/model_wrapper.py:359`) and the SGLang wrapper in #5812 both repeat `load_initial_weights -> maybe_apply_numa_binding -> ModelStateDictLoader(...)`. If an engine misses that step, nothing errors: the pinned buffers just land on the wrong NUMA node. The loader is the one allocating them, so it could bind as the first thing in `__init__`, using `torch.accelerator.current_device_index()` / `torch.accelerator.current_accelerator().type` the way #5812 does. vLLM calls it unconditionally today, so binding unconditionally in `__init__` keeps the behavior the same. Then you can delete the bind call from both wrappers and the ordering note from the docstring.

- claude[bot] · comment · 2026-11-04T16:31:07Z · [source](https://github.com/pytorch/torchtitan/pull/5811#discussion_r4470270621)

File: `torchtitan/rl/generator/inference_model.py` · line 33

Should consider (nit): the module docstring says this file covers how the generator *builds, initially loads, and state-dict-loads* the model. `get_attention_dimensions` does none of those. It reads an attention config for the engines' registries and layer replacement. `paged_attention.py` (the engine-agnostic attention helpers) looks like a better home, so `inference_model.py` doesn't turn into a catch-all as more shared pieces arrive (#5812 already adds `compute_logits` here).
