# [CI Fix][GraphTrainer] Install FA3 in H100 tests

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5558) · state: closed · merged: True

## Original PR description

## Summary

- Install the FA3 wheel in the GraphTrainer H100 source-checkout workflow.
- Install FA3 again in the isolated GraphTrainer release-validation environment.
- Use the same PyTorch wheel index already used by the standard H100 integration path.

## Root cause

The current H100 run has nine failures across the Llama 3, DeepSeek V3, and Qwen3 MoE bitwise suites: https://github.com/pytorch/torchtitan/actions/runs/39366623354/job/118444885499

Every failure occurs during model construction with `ModuleNotFoundError: No module named flash_attn_interface`. #5307 made compatible models use Varlen attention by default. On SM90, TorchTitan selects FA3, but the GraphTrainer H100 workflow replaces PyTorch nightly without installing the separate FA3 wheel.

A generic FA2 fallback does not fix the full suite: DeepSeek V3 MLA uses unequal Q/K and V head dimensions and requires FA3. Installing the declared H100 backend is therefore the CI fix.

The release-validation script creates a separate environment for the installed package, so it must install FA3 at that boundary as well; an install in the source-checkout workflow does not carry over.

## Test plan

- `SKIP=pyrefly-check pre-commit run --all-files` (pass)
- Validate the full GraphTrainer H100 source and installed-package suites through `ciflow/h100.8`.

The shared local environment has an older PyTorch/Pyrefly API set than current main, so the Pyrefly hook is left to CI.
