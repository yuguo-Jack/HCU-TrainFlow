# [attention] 7/n Keep linear-attention graph metadata replayable

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5680) · state: open · merged: False

## Original PR description

Part **7/n** of the Kimi K3 / Dist-MoE training stack. Based on `shuhuayu/k3-dm-stack-06`: the review diff contains only this feature.

## Why

Linear-attention metadata must expose tensor inputs to graph copying. An unregistered Ulysses metadata subclass is otherwise treated as one opaque object, and rebuilding it for another batch fails graph input validation.

Routing also needs fixed document and fragment capacities. With CP=2, real PTRR and four padded document slots, changing offsets from `[0,1024,1024,1024,1024]` to `[0,512,1024,1024,1024]` changes the maximum fragment count from three to four. Sizing buffers from that runtime count changes their shapes and prevents replay.

## What changed

- Register base, Ulysses, and routed linear-attention dataclasses so graph input copying can refresh every tensor, including the shared Attention Gym routing object.
- Derive a batch-independent fragment bound from the selected load balancer: one for contiguous sharding, two for head-tail, and query-block count divided by CP degree for valid PTRR.
- Pass that bound through the existing CP metadata-preparation interface to KDA/GDN. Attention Gym receives both `slots=S` and `max_subsequences=padded_documents+S-1`; it rejects insufficient capacity.
- Preserve automatic KDA chunk-kernel selection and all kernel arithmetic. No new kernel-options configuration is added.
- Move existing CPU-only KDA metadata and GDN CP mock checks into common-attention CPU coverage. This portion is mechanical.

## Example

For the two PTRR batches above, use the same static bound `S=8 query blocks/2 CP ranks=4`. Both retain `slots=4`, seven subsequence slots, and eight offsets, regardless of whether three or four fragments are active. Their active routing values still describe their own document boundaries.

## Alternatives considered

A bound equal to local token count would pad state summaries and quadratic predecessor tables excessively. The selected load balancer already knows a much smaller fixed bound, so no user tuning knob or second routing planner is needed.

## Numerics

Fresh GPU-0-only testing matched eager loss, every parameter gradient, and parameter updates exactly across five warmup/capture/replay updates with changing padded document layouts. The existing packed-versus-independent-document check also passed on the default cuDNN KDA path, retaining its original `rtol=2e-2, atol=2e-2` assertions.

**Historical validation:** a real two-rank NCCL CP2 diagnostic matched compact-reference loss and all five input gradients exactly across two warmups and three capture/replay calls with padded routing. It was not rerun during this GPU-0-only review.

These are focused numerical checks, not a full-model training or throughput claim. No kernel arithmetic or model/checkpoint parameter changes are made.
