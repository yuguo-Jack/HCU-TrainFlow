# [rl] Train the MoE router gate in RL, keep the expert bias frozen

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5409) · state: open · merged: False

## Original PR description

**TLDR:** RL recipes stop freezing the MoE router gate. They still freeze the expert bias and drop the aux loss. In our ablation, a trainable gate leaves the trainer-vs-vLLM logprob gap flat (0.0317 -> 0.0312 over 60 steps), while a moving expert bias tripled it in 30 steps.

**Why**
1. `build_rl_model_configs` applies `FreezeMoERoutingTransform` to every RL recipe. It sets `freeze_expert_bias=True`, `router.freeze_gate=True` and `router.aux_loss=None` on every MoE layer.
2. The bias freeze has the evidence: a moving expert bias took the gap from 0.053 to 0.157 in 30 steps (Qwen3-30B-A3B, 8 layers, lr=0).
3. The gate freeze had no ablation. It stops the router from learning during RL.
4. Most of the RL setups we compared train the gate; only the expert bias needs freezing.
5. Our ablation agrees: the gate moves, and the gap does not grow.

```text
trainer-vs-vLLM logprob gap, median of the first 5 -> last 5 steps
Qwen3.5-35B-A3B-Base, first 4 layers, 60 steps
  gate frozen               0.0315 -> 0.0290
  gate frozen, replicate    0.0319 -> 0.0271
  gate trainable            0.0317 -> 0.0312   (gate weights move 1.7e-3 relative)
Qwen3-30B-A3B, first 4 layers, 20 steps
  gate frozen               0.0199 -> 0.0187
  gate trainable            0.0185 -> 0.0190
```
Setup: real checkpoints cut to 4 layers, 2 H100s, trainer FSDP2 + EP2 and one vLLM generator with real weight sync. Each step: 64 samples x 200 tokens, random +-1 advantages, AdamW lr 5e-6, push to the generator. No expert bias, aux loss off. Gap = mean |trainer logprob - vLLM logprob| over completion tokens. The two identical frozen runs differ by ~10%, so smaller changes are noise.

**What changes**
1. `FreezeMoERoutingTransform` gets one knob per field it sets: `freeze_expert_bias=True`, `freeze_gate=False`, `drop_aux_loss=True`. With these defaults the gate trains.
2. A False knob leaves its field as built. The aux loss can be dropped but not rebuilt, so all three knobs work the same way.
3. `build_rl_model_configs(freeze_moe_routing=...)` takes the transform instead of a bool:
```python
build_rl_model_configs(..., freeze_moe_routing=FreezeMoERoutingTransform(freeze_gate=True))  # also freeze the gate
build_rl_model_configs(..., freeze_moe_routing=None)  # MoE as built: the bias moves, aux loss on
```
4. Unchanged: the class name, the frozen bias and dropped aux loss in every RL recipe, and `router.freeze_gate` (default False).

You may ask:
- With no bias updates and no aux loss, does a trainable gate collapse onto a few experts? Not in 60 steps: max/mean expert load goes 18.5 -> 19.0 trainable vs 18.5 -> 19.2 frozen (Qwen3.5 run above).
- Why not a lower gate lr? No evidence it's needed. A recipe can already set one: an `AdamW.Config(pattern=r"router\.gate\.", lr=...)` listed before the `.*` one claims the gate first.
- Why is a transform instance the default argument? The transform is a frozen dataclass, so the shared default can't be mutated, and the signature shows the real default.

NOTE:
- An RL checkpoint saved with the frozen gate can't resume after this PR: it has no optimizer state for the gate, and the checkpoint load expects it. Pass `freeze_moe_routing=FreezeMoERoutingTransform(freeze_gate=True)` to resume one.
- The ablation runs the real trainer and vLLM actors with random advantages, not the full RL loop. Not run: GPU tests.

**Test plan**
```bash
pytest tests/unit_tests/cpu/config/test_freeze_moe_routing.py tests/rl/unit_tests/cpu/test_model_defaults.py  # 49 passed
pytest tests/unit_tests/cpu/config tests/rl/unit_tests/cpu tests/unit_tests/cpu/components/optim  # 780 passed, 5 skipped
```
- `test_freezes_every_moe_family`: one AdamW step per MoE family, for each `freeze_expert_bias` x `freeze_gate`. The expert bias stays only with `freeze_expert_bias`. The gate stays, with no optimizer state, only with `freeze_gate`. Every other parameter trains.
- `test_false_knobs_leave_moe_as_built`: on a model built with a frozen bias and gate and an aux loss, all-False knobs change nothing.
- `test_model_defaults.py`: every RL recipe builds with a trainable gate, a frozen bias and no aux loss. `freeze_moe_routing=None` leaves the MoE as built.
