# [rl] Place roles on the hosts of a Monarch job in torchtitan.rl.train

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5403) · state: open · merged: False

## Original PR description

Part of the RFC pytorch/torchtitan#5401 (GRPO on Intel XPU).

Contains only the multi-host change; merge after #5402.

`torchtitan.rl.train` only spawns on `this_host()`. With `TORCHTITAN_MONARCH_JOB` naming a dumped Monarch job (`SlurmJob`, or `PBSJob` from meta-pytorch/monarch), `train.py` loads it before building the controller (loading sets the transport remote procs dial back on) and passes `spawn_proc_mesh` host meshes: the trainer takes the first `ceil(trainer GPUs / GPUs per node)` hosts, generators the rest, and generators on one node share that node's mesh so they get disjoint GPUs. One host is shared by every role. Device-agnostic.

Tests: `tests/rl/unit_tests/cpu/test_host_meshes.py`. Multi-node GRPO on Aurora up to 16 nodes. Validated on ALCF Aurora (torch 2.14.0+xpu, oneCCL 2022.1.1, vLLM main, Qwen3-0.6B GRPO, full + LoRA): 18/18 regression (2 nodes x 1/2/4/8/12 tiles, 16 nodes x 4/12 tiles, 1- and 8-node 10-step runs). This branch targets current main, which needs torch nightly while vLLM's XPU support pins torch 2.14, so it was checked line by line against the tested torch-2.14 branch.
