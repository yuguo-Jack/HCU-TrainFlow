# [graph_trainer] Split the configured HybridEP capacity budget once

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5540) · state: open · merged: False

## Original PR description

## AI-Generated Details

Prepared with Codex from the author's capacity-factor requirement.

Two eager chunks must share one full-call HybridEP output budget:

```text
B = max_input_tokens * ep_size * min(local_experts, top_k) * capacity_factor
chunk0 = floor(B / 2)
chunk1 = B - floor(B / 2)
```

Apply native alignment to each half and bind that integer while tracing its
chunk. The public factor remains unchanged; replay does not consult a Python
context. Factor 4 therefore gives effective factor 2 per chunk on the original
full-call basis. Do not halve both the token bound and factor. Shared transport
buffers are a separate allocation, not this per-call output capacity.

## Test Plan

The real two-rank MoE test observes grouped-linear dispatch inputs through a
standard pre-hook, without replacing the dispatcher/forward or supplying the
capacity it is meant to verify. Factor 4 gives 3072/3072 rows; factor 0.251 gives
odd raw budget 385, aligned to 192/256. It checks combined allocation bytes against
a full call, finite gradients, unchanged public factor and restored context.

```bash
python -m pytest torchtitan/experiments/graph_trainer/tests/test_numerics.py::TestHybridEPContracts::test_eager_chunk_capacity_uses_full_call_budget -v
```

The patch is unchanged by this update and is only rebased onto the earlier
gradient-identity fix. Later paging coverage extends the same real graph test
with native dispatch/shared-expert and terminal combine/wgrad ordering checks.
Scheduling comparisons retain the same chunks/capacities; they do not promise
bitwise equivalence to an unchunked computation. No host token-count read.

PP does not chunk tokens and retains each microbatch's full capacity budget.
