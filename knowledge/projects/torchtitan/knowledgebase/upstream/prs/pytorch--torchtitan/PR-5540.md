# [graph_trainer] Split the configured HybridEP capacity budget once

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5540) · state: open · merged: False

## Original PR description

## AI-Generated Details

Prepared with Codex from the author's capacity-factor requirement.

Two eager chunks must not each allocate a full-call HybridEP output budget.
Derive one absolute row bound:

```text
B = max_input_tokens * ep_size * min(local_experts, top_k) * capacity_factor
chunk0 = floor(B / 2)
chunk1 = B - floor(B / 2)
```

Apply native alignment to each half, then bind that integer while tracing the
chunk. The public dispatcher factor is unchanged and replay does not consult
the Python context. Factor4 therefore becomes effective factor2 per chunk on
the same full-call basis; do not halve both the token bound and the factor.
Transport buffers are a separate shared allocation, not this output capacity.

## Test Plan

The real native contract family covers allocated bytes, alignment, retained
routing state and deliberate capacity drops. Final-stack traced dispatches
use the expected static row bounds, and deterministic same-chunk training
matched exact loss/norm and full checkpoint state. No host token-size read is
introduced. Those tests ran through the production backend, not a patched
allocation or a synthetic FX graph.

This capacity policy applies to SPMD token chunks. The separate PP feature
does not chunk tokens and preserves each microbatch's full capacity factor.
