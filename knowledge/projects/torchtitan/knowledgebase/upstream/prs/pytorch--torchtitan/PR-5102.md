# Rename activation checkpointing policies to activation checkpoint configs

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5102) · state: closed · merged: True

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.18.0) (oldest at bottom):
* __->__ #5102

The policies are plain configs applied with one function, since the policy
objects held nothing beyond their config. User-facing names say "activation
checkpoint"; torch_remat stays the implementation:

* `ActivationCheckpointConfig` (formerly `RegionAC.Config`) saves regions
  matching `save_regions` except those matching `recompute_regions`.
* `FullActivationCheckpointConfig` (formerly `FullAC.Config`) and
  `DefaultActivationCheckpointConfig` (formerly `SelectiveAC.Config`, the
  trainer default) are fixed presets of it. The default preset's regions may
  change as measurements improve; an explicit `ActivationCheckpointConfig` is
  the way to pin a policy.
* `apply_activation_checkpoint(model, config)` replaces
  `config.build(dump_folder=...).apply(model)`. Per-block saved-tensor hooks,
  previously a `RegionAC.get_saved_tensors_hooks` override, are passed as its
  `saved_tensors_hooks` callable.
* The `ActivationCheckpointingConfig` type alias is removed: it was the union
  of these configs and None, so annotations use
  `ActivationCheckpointConfig | None`. The trainer field keeps its name,
  `activation_checkpoint`.

No behavior change; call sites, recipes, tests and docs are renamed, including
tests that landed after the policies were introduced (`test_aux_loss.py`,
`test_remat.py`'s saved view-output test, and the `alphabet_sort` RL test
recipe).
