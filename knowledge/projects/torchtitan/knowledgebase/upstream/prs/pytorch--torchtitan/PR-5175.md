# [graph_trainer][pp] PP unshard stages overlap with compute

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5175) · state: open · merged: False

## Original PR description

PP prepares schedule:

  unshard(stage_1)
  forward(stage_0)
  forward(stage_1)


But unshard currently includes wait_tensors.

The main idea is to have unshard that is doing unshard_launch(stage_1) starting all_gathers,

book keep waits in the runner,

UNSHARD_WAIT schedule action will do actual wait. In this case we get overlap.

Putting waits on the boundaries adds bookkeeping similar to unshard_params.


The user UNSHARD_WAIT is emitted automatically before the first use of those unsharded params
