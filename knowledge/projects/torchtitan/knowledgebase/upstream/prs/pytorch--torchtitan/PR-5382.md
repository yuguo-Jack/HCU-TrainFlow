# [moe][perf] Gather-sum dispatch and combine for training, at any EP (5/6)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5382) · state: open · merged: False

## Original PR description

**TLDR:** Compiled training uses the gather-sum dispatch and combine, with gather-based backwards, at EP=1 and around the EP>1 all-to-all: one Qwen3.5-35B-A3B MoE layer fwd+bwd at 32k tokens 24.1 -> 10.8 ms, and the trainer's MoE output equals the generator's, bitwise. Reference path (Dist-MoE and DeepEP have their own dispatch and combine), low priority.

**Stack** (6 PRs, merge bottom-up; this PR is in **bold**)

| # | PR | Independent? | Needs (stack positions) |
|---|---|---|---|
| 1 | AllToAll dispatcher: permute and unpermute with gathers | yes | — |
| 2 | Argsort expert ids on the narrowest integer type | yes | — |
| 3 | EP=1 inference: gather-sum MoE combine region | no | 2 |
| 4 | EP=1 inference: sort-region MoE dispatch | no | 2, 3 |
| **5** | **Gather-sum dispatch and combine for training, at any EP** | **no** | **4** |
| 6 | Turn on gather-sum dispatch and combine for DeepSeek-V3 and Kimi | no | 3, 4, 5 |

**Problem**
1. **Training combine.** With grad on, `LocalTokenDispatcher` (EP=1) and `AllToAllTokenDispatcher` (EP>1) keep the scatter-add combine.
2. **Gather backward.** Their token gather's backward is `index_put_(accumulate=True)`.
3. **Mismatch.** With stack position 3, the generator sums a token's routes in fp32 and rounds once; the trainer rounds to bf16 after every route.
4. **Why it matters.** RL compares trainer and generator logprobs of the same tokens.
5. **Cost.** At 32k tokens the layer takes 24.1 ms of kernels per fwd+bwd, with a 9.2 GiB backward peak.

```text
forward:   x -> gather tokens -> expert rows -> experts -> gather-sum per token -> out
backward:  grad_x <- sum each token's top_k rows <- ... <- gather grad_out per route, times score <- grad_out
           (no scatter-add, no index_put accumulate)
```

**Solution**
1. `_sort_routes_for_training` (`moe_dispatch` region): the inference sort without the token gather, which autograd needs.
2. `_DispatchGather`: `x[token_indices]`; its backward sums each token's `top_k` rows in fp32 (`_sum_routes_per_token`).
3. `_CombineGatherSum`: the forward is the generator's `_gather_weighted_sum`; the backward gathers too, and skips the score gradient when the scores need none.
4. **EP>1.** `AllToAllTokenDispatcher` sorts routes with `_sort_and_gather` before the all-to-all, so its combine also calls `_CombineGatherSum` (positions 3-4 at inference).
5. Unchanged: eager training keeps argsort + scatter-add (bitwise); Dist-MoE, DeepEP and HybridEP.

**Results**
```text
Numerics: not bitwise vs the scatter path (rel L2 3.0e-3: fp32 vs bf16 accumulation).
          max rel L2 vs fp64, op level (CPU probe of the same combine, stack position 6):
          eager combine 2.34e-3 | gather-sum 1.66e-3 = bf16 rounding floor
          Trainer MoE output == generator MoE output, bitwise. Backward bitwise deterministic (two runs).
          EP=2, eager or main's regions only: logprobs bitwise, grads within main's run-to-run noise.
          EP=2, all regions: loss diff 7.4e-4, vs 1.06e-3 eager-vs-compiled without the EP>1 step.

one Qwen3.5-35B-A3B MoE layer (ffn_norm + MoE), fwd+bwd, FullAC, bf16, EP=1, GB300, kernel ms
T=4k     5.97 -> 4.04
T=16k   13.56 -> 6.78
T=32k   24.05 -> 10.80   (backward peak 9.2 -> 4.4 GiB)

2 Qwen3.5-35B-A3B layers (GDN + full attention), fwd+bwd, FullAC, kernel time,
positions 3-5 (position 4 as an earlier one-hot counting-sort version) plus the router compile, vs main
4k -27%   16k -42%   32k -43%

4 Qwen3.5-35B-A3B layers (3 GDN + full attention, all MoE), FSDP=2 + EP=2, 2x H100, fwd+bwd, compiled regions,
kernel time without NCCL, rank 0, vs this PR without the EP>1 step
4k tokens/rank   152.4 -> 143.4 ms
16k tokens/rank  378.5 -> 348.6 ms   (-7.5 ms per MoE layer; its grouped GEMMs take ~5.6 ms)
```

You may ask: why custom autograd Functions? Autograd's backward of a gather is `index_put_(accumulate=True)`, the scatter this PR removes.

NOTE:
- The layer numbers come from an earlier version of this stack that also compiled the per-expert token count (~0.4%).
- At EP>1, decode gains little: AllToAll copies its split sizes to the host, so it runs without CUDA graphs.
- Not measured at EP>1: step wall time, EP=4/8.
