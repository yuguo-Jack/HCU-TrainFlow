# [distributed] 1/n Apply initialization timeouts to mesh process groups

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5674) · state: closed · merged: True

## Original PR description

Part **1/n** of the Kimi K3 / Dist-MoE training stack. Based on `main`: the review diff contains only this feature.

human notes:
previously: `distributed/utils.py::init_distributed()` passes `CommConfig.init_timeout_seconds` to `torch.distributed.init_process_group()` so the world group has, say, 30 minutes timeout. now, that remains unchanged. Additionally, `TrainingEngine._initialize_distributed_runtime()` calls `set_pg_timeouts()` after `ParallelismContext.from_config()`,  so the tracked mesh subgroups get the configured timeout before model/FSDP/optimizer initialization. this also covers the RL trainer. without this pr, independently created NCCL subgroups can still use the default 10-minute timeout even though we configured 30 minutes. the existing switch to `train_timeout_seconds` after the first step is unchanged.

## Why

The world process group receives `comm.init_timeout_seconds`, but mesh subgroups created later do not inherit it. They can retain the backend-default startup timeout through model initialization and the first update.

Example: with `CommConfig(init_timeout_seconds=1800)`, the world group uses 1,800 seconds but a later NCCL subgroup can use its 600-second default. This change applies the configured startup budget to the groups tracked by `ParallelismContext` before model/FSDP/optimizer initialization.

## What changed

- Call the existing `set_pg_timeouts()` helper immediately after `ParallelismContext.from_config()` in the shared training engine.
- Apply the same call in the TorchFT runtime override.
- Preserve the unconditional post-first-step switch to `train_timeout_seconds`, including fake backends.
- Add no helper, configuration field, or test. The deleted forwarding-only mock test is not coverage for the current code.

## User-facing changes

| Configuration | Before | After |
| --- | --- | --- |
| `init_timeout_seconds=1800` | World: 1,800 s; tracked NCCL mesh groups may use 600 s during startup. | World and tracked mesh groups: 1,800 s during startup. |
| Default `init_timeout_seconds=300` | World: 300 s; tracked NCCL mesh groups may use 600 s. | World and tracked mesh groups: 300 s during startup. |
| After the first update | Existing switch to `train_timeout_seconds`. | Unchanged. |

Groups created separately outside the context's tracked mesh map, including optimizer-specific communicators, are not covered by this call.

## Numerics

No model math, parameter layout, gradient policy, or checkpoint mapping changes. The existing helper adds one startup barrier/device synchronization; there is no new per-update synchronization.
