# [model] Let recipes choose the state dict adapter

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5322) · state: closed · merged: False

## Original PR description


Summary:
A model's state dict adapter is a class variable on the model class, so every
run of a model uses the same adapter. Some adapters only work with one
checkpointer.

- Add an optional `state_dict_adapter_cls` field to `BaseModel.Config`. `None`
  keeps the model class's `state_dict_adapter_cls`, so existing recipes are
  unchanged.
- Add `resolve_state_dict_adapter_cls`, and use it where training and the RL
  initial load build the adapter.

A recipe now pairs the adapter with its checkpointer explicitly:

```python
config.checkpointer = TorchCheckpointingManager.Config(...)
config.model.state_dict_adapter_cls = SomeOtherAdapter
```

The checkpoint conversion scripts are unchanged: they build model configs from a
model name and flavor rather than a recipe, so the field is never set there.
