# [rl] Pass opaque resume state to the trainer; rename RL data loader and work-buffer state

## Why
Three RL names don't describe what the code does:

1. **Controller resume state.** The controller wraps the rollouter state in a one-key dict, `{DATALOADER_STATE_KEY: ...}`, and hands it to the trainer as `controller_state`. The two key constants live in their own module, `trainer/controller_state.py`. The trainer never reads the payload, so the wrapper, the constants and the module add indirection without a consumer.
2. **`RLDataLoader.acknowledge`.** The controller calls it exactly at the optimizer/checkpoint transaction boundary. After the call, those indices are left out of the next checkpoint. That is a commit.
3. **Work-buffer `INFLIGHT` state.** The only transition into it is `claim_next()`, so the name hides which call moves an entry there.

**Example.**
```python
# before
self._rollouter.acknowledge_training_sample_ids(packed.group_ids)
controller_state = {DATALOADER_STATE_KEY: self._rollouter.state_dict()}
await trainer.optim_step.call(controller_state=controller_state, ...)
# resume
state = await trainer.get_controller_state.call_one()
self._rollouter.load_state_dict(state[DATALOADER_STATE_KEY])

# after
self._rollouter.commit_training_sample_ids(packed.group_ids)
await trainer.optim_step.call(resume_state=self._rollouter.state_dict(), ...)
# resume
self._rollouter.load_state_dict(await trainer.get_resume_state.call_one())
```

## What changed
- **Resume state (logic, small):** the trainer stores an opaque `resume_state` under the checkpoint key `"resume"`: `get_resume_state()` and `optim_step(resume_state=...)`. The trainer doesn't know what's inside it. `MirroredState` moves into `trainer/trainer.py`, its only user, and `trainer/controller_state.py` is deleted.
- **Data loader (mechanical):** `RLDataLoader` / `IterableRLDataLoader` / `MapStyleRLDataLoader` are now `RolloutDataLoader` / `IterableRolloutDataLoader` / `MapStyleRolloutDataLoader`. `acknowledge` becomes `commit`, and `Rollouter.acknowledge_training_sample_ids` becomes `commit_training_sample_ids`. Recipes, the README, the verifiers example and tests are updated.
- **Work buffer (mechanical):** `INFLIGHT = "inflight"` becomes `CLAIMED = "claimed"`. Docstrings and the controller diagram are updated.

Skimmable: `torchtitan_recipes/rl/*`, `tests/rl/*`, `torchtitan/rl/README.md`, `torchtitan/rl/examples/verifiers/rollouter.py`, `torchtitan/rl/rollout/data.py`.

## User-facing changes
| Before | After |
| --- | --- |
| `IterableRLDataLoader.Config(...)` / `MapStyleRLDataLoader.Config(...)` | `IterableRolloutDataLoader.Config(...)` / `MapStyleRolloutDataLoader.Config(...)` |
| `RLDataLoader.acknowledge(indices)` | `RolloutDataLoader.commit(indices)` |
| metric `rollout_buffer/num_groups_inflight` | `rollout_buffer/num_groups_claimed` (matches `num_groups_waiting` / `num_groups_finalized`) |
| trainer checkpoint key `"controller"` holding `{"dataloader": state}` | key `"resume"` holding `state` |

RL checkpoints saved before this change won't restore their data loader state.

## Numerics
No computation path changes: these are renames, plus removing a dict wrapper on the controller-to-trainer resume payload. No loss comparison was run.
