# [muse_spark][perf] Compile the residual-stream RMSNorms (muse_spark_rmsnorm region)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5458) · state: open · merged: False

## Original PR description

**TLDR:** Compile Muse Spark's base RMSNorm (`muse_spark_rmsnorm` region): decode -2 to -5%, training -0.1 to -1.6%, prefill ~0, for a 2-line model change.

**Problem**
1. **Residual-stream norms.** `attention_norm`, `ffn_norm`, `post_attention_norm`, `pre_expert_norm` and the final norm use `MuseSparkRMSNorm.forward`.
2. **Eager.** After PR 1 they run ATen's fused `rms_norm` (fwd 1 kernel, bwd 2) plus a separate weight-add and cast.
3. **Cost.** Small per call, but at decode every kernel launch counts.

**Solution**
1. **Region.** `@local_compile("muse_spark_rmsnorm", batch_invariant=False, recompile_limit=16)` on `MuseSparkRMSNorm.forward`, enabled in the model config.
2. **Graph budget.** One region serves four call shapes (fp32 stream with weight, bf16 without weight, 4096-wide expert norm, final norm) x grad mode x dynamic T: 12 graphs, so the limit is raised to 16.
3. **Unchanged.** The norm math.

**Results**

Correctness: not bitwise; the error vs fp64 is the same as eager's (output 5.1e-8, input grad 5.7e-8, weight grad 1.7e-3 in bf16; weight grad 1.3e-7 vs 2.2e-7 in fp32).
2 layers at 4k: the difference from PR 3 is 0.9x what a 1-ulp change of the input causes.
Graphs: 12 across training and inference shapes, limit 16.
NOTE: graph count measured on text shapes; the multimodal model also calls this region on perception embeddings (`perception_emb_norm`), not counted.
