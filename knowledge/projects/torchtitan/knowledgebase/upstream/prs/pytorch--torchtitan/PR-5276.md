# [Kimi K3] Make the vision encoder CP-invariant

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5276) · state: closed · merged: False

## Original PR description

## Summary

Make the Kimi K3 vision encoder CP-invariant by default, with no configuration flag.

| | Before | After |
|---|---|---|
| Encoder weights / activations on CP | R | I |
| Vision-bank backward | CP-partial gradients | One CP all-reduce before encoder backward |
| Encoder FSDP | dp_shard x cp | dp_shard only; CP-replicated state |
| Decoder FSDP | dp_shard x cp | Unchanged |

The indexed bank can contain repeated indices, so its backward needs an all-reduce, not an all-gather. Add mixed-mesh gradient clipping and keep the encoder separately wrapped under PP.

## Benchmark

4x GB300, 447M-parameter Kimi encoder, BF16, TP=1, 4 images/DP rank (1,024 patches), deterministic seed 42. Two fresh-process trials/mode, 30 measured steps after 5-10 warmup steps; encoder + fusion + backward + AdamW only.

| DP / CP | Median ms, before -> after (trials 1; 2) | Peak GiB, before -> after |
|---|---|---|
| 2 / 2 | 114.1 -> 123.2; 114.9 -> 115.5 | 4.03 -> 5.26 |
| 1 / 4 | 113.0 -> 125.2; 112.2 -> 125.4 | 4.03 -> 8.36 |

Parameter communication decreases, but **no step-time improvement** here; replicated optimizer work/memory increases. No end-to-end speedup is claimed.

## Validation

- 38 CPU tests and 4-GPU gradient/clipping tests pass; FP64 gradients match the unsharded reference at 1e-12. CP=1 loss/gradients/updates remain bitwise identical.
- FP32 encoder (TP=1/2) gradient/update max differences: 3.7e-9 / 9.0e-7. BF16 synthetic loss max difference: 0.0043; full-training convergence is untested.
- Changed-file formatting/lint pass. Full pre-commit is blocked by GitHub access; full typecheck has unrelated dependency errors. Runtime: PyTorch 2.16 nightly/cu130, spmd-types 0.3.0.
