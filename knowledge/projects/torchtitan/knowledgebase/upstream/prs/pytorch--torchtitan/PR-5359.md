# [rl] Terminal-Bench: cap the Terminus-2 harness script below Python 3.15

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5359) · state: closed · merged: True

## Original PR description

## Why
`TerminalBenchTerminusHarness` runs `terminus_harness.py` as a uv (PEP 723) script, and uv picks the newest interpreter that satisfies `requires-python = ">=3.12"`. Python 3.15 is now released, so uv picks 3.15. Harbor 0.22.0 depends on litellm, which pulls fastuuid 0.14.0. fastuuid has no 3.15 wheel, and building it from source fails ("the configured Python interpreter version (3.15) is newer than PyO3's maximum supported version (3.14)"). Every rollout then fails in harness setup with `HarnessError` and 0 turns; with every group untrainable, the controller stops after 10 such batches.

## What
- `requires-python = ">=3.12,<3.15"` in the script header.
- One sentence in the module docstring saying why.
- No other harness or program templates in torchtitan main declare `requires-python`.

## Testing
- `pytest tests/rl/unit_tests/cpu/test_verifiers_terminal_bench.py`: 9 passed, 1 skipped.
- End to end on a GB300 Slurm cluster with a remote sandbox runtime: with `>=3.12`, 83 of 83 rollouts failed in setup with the error above. With the cap, harness setup succeeded and rollouts ran normally.
