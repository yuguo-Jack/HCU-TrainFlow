# Support for MiniMax M3 with MiniMax Sparse Attention (MSA, https://arxiv.org/abs/2606.13392) on FSDP2, TP/SP, EP and PP.
The first five commits are the FSDP2 baseline and the common changes it needs, which open as one PR of their own; the last three add TP/SP, EP and PP.

## Summary
- `torchtitan/models/minimax_m3/`: the model (428B total, 23B activated), MSA on 57 of its 60 layers as a flex inner attention over the blocks an indexer selects, the indexer's KL loss, the vision tower with 3D RoPE, and the HF state dict adapter.
- `scripts/checkpoint_conversion/numerical_tests_minimax_m3.py`: parity against HF `minimax_m3_vl` on a reduced config.
- `torchtitan/models/common/`: `OffsetRMSNorm` moves here from Qwen3.5, `RoPE` applies partial RoPE itself, Qwen3.5's post-vision-scatter block sharding config moves here, and one vision projector sharding config replaces the identical ones of Qwen3.5 and Kimi K2.7, which Kimi K3 also used.
- `torchtitan/models/deepseek_v3/state_dict_adapter.py`: a subclass supplies the HF key map and the RoPE type, so M3 reuses the per-expert conversion.
- CP raises `NotImplementedError`: MSA's mask comes from a per-layer block selection that depends on the activations, which the CP flex path does not cover.

## Design
- TP for MSA:
  - The index query heads shard with their KV groups, and the shared index key head is replicated.
  - An MSA layer gathers its input once for the q/k/v and index projections, so its `wqkv` is a plain `Linear`.
  - The KL loss divides by the global KV group count, and its logged value sums every TP rank's groups.
- EP and PP use titan's MoE expert parallelism and pipeline split unchanged.

## Test plan
- `pytest tests/unit_tests/cpu` (`1972 passed, 18 skipped, 3 xfailed, 1 failed`; the one failure fails the same way on main) and `pytest tests/unit_tests/gpu/models/minimax_m3 -q` (`2 passed`)
- The models-suite cell `minimax_m3_mm_fsdp+tp+sp+ep` (FSDP 2 x TP 2 x EP 2, SPMD typechecking on) (`passed`)
- HF parity on the debug flavor in bf16: last-token KL 2.21e-5, and 4.74e-5 over all positions with HF's block and expert choices imposed.
- The parallelism matrix below, all 29 layouts on 8 x RTX 5060 Ti (`passed`).

## Results
8 x RTX 5060 Ti, debug model reading `c4_test` as text-only 512-token rows, 4096 tokens per step, AdamW, seed 42, deterministic, 100 steps; every cell loads one single-GPU seed checkpoint and runs on a copy of one compile cache that 10 steps of each layout warmed. Layouts are grouped by data stream, since each dp degree reads different samples, and each stream's reference runs twice as its noise floor. Kit, not part of this PR: [chain_4d_5060.sh](https://github.com/QIU023/torchtitan_model_support/blob/c25ade39ad9d/Raising_PRs/RFC_MINIMAX_M3/kit_m3_5060_2026-10-25/rtx5060/chain_4d_5060.sh).

Every layout that differs from its reference only in FSDP or PP, and every EP layout without TP, matches its step-1 loss bitwise; TP layouts differ from step 1, since the row-parallel reductions round differently and that flips some MSA block selections and expert choices.

- Each reference is identical to its rerun on all 100 steps.
- Later steps drift once any bit differs; the HSDP table of the FSDP2 baseline PR shows the size of that drift for a reduction order alone.
- PP layouts differ from the step-1 grad norm on, for two reasons:
  - the reference compiles flex attention for the vision tower first, so dynamo recompiles MSA's call with a dynamic head count, while a stage without the vision tower compiles it with static shapes;
  - with static shapes on both sides, the dense projection weights still differ, since PP adds the micro-batches' bf16 gradients in another order, as it does for unmodified DeepSeek V3.
- EP changes only the routed experts' step-1 gradients (at most 2.4e-3 in relative L2 norm), since their weight gradient becomes one grouped GEMM over the tokens gathered from every EP rank.
- TP: with the reference's selections and choices imposed, the largest step-1 gradient gap falls from 2.8e-2 to 5.4e-3 at tp2 x ep2 and from 3.9e-2 to 5.7e-3 at tp4 x ep4.
