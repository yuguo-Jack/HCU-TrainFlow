## Why

Shared global KV and index state can outlive the stage that produced them. A conventional single-hidden-state pipeline would drop those tensors or their backward routes. Mutable model caches would also mix state from outstanding microbatches under an interleaved schedule.

**Example.**

```text
stage A: producer -> (residual, next_mix, global_KV, index_KV, IDs, scores, candidates)
                              | explicit payload, owned by this microbatch
stage B: consumers -----------+ -> updated payload -> stage C
backward: residual/global_KV/index-score gradients return to their producers
```

## What changed

- Enable existing TP/EP sharding and real pipeline execution.
- Supply static forward/backward metadata for seven boundary tensors through the shared factory included in `1/n`.
- Preserve shared state as explicit per-forward arguments, including interleaved four-stage execution.
- Validate complete, ordered block splits and exactly-once ownership of enabled input/output modules; require a fixed dataloader document bound, keep CP>1 unsupported, and reject fake PP. DSpark requires TP=1; tensor-parallel backbone configs explicitly disable the drafter.
- Register real TP2/EP2 and combined FSDP2/TP2/PP2/EP2 training in the appropriate CI suites. The combined numerical factory uses reference attention; a separate factory selects fused attention-gym kernels.
- Add pipeline gradient/lifetime tests and current architecture/validation documentation.

## User-facing changes

| Before | After |
| --- | --- |
| Backbone supports FSDP with TP=EP=PP=1 | Existing TP/EP and real PP support the backbone |
| No pipeline shared-state contract | Seven explicit tensors with static forward/backward metadata |
| No distributed V4.1 CI selection | Fused two-GPU TP/EP plus combined eight-GPU numerical recipes |

CI catalogue entries and model-index links are mechanical. Boundary state, gradient routes, and split validation require correctness review.

## Testing

69 CPU model/integration-definition tests passed on the current upstream base. Nine pipeline cases cover three splits and no/default/full remat with two outstanding packed forwards, exact logits/loss/every gradient/buffer, and real boundary shape/dtype/stride/gradient metadata. Focused invalid-split cases guard missing/misplaced output, vision, and drafter modules; two config cases reject unsupported drafter TP with and without sequence parallelism. A packed-document regression demonstrates why PP rejects unbounded document metadata. All-file pre-commit passes. The native CPU seed/checkpoint and selected fused TP2/EP2 recipe completed ten training steps with SPMD checking enabled in the complete ARM Python 3.12 environment (published PyTorch `2.16.0.dev20261030+cu132`, `torch_checkpointing 0.1.1`, CUTLASS DSL `4.7.0`); all losses and norms are finite, with loss `7.677572250366211` -> `6.613213539123535`. Each native child verified the source, helpers, dependency versions, and published PyTorch file hashes before computation. The earlier vision/drafter FSDP checks and fresh native V4 FSDP2 regression remain passing.

Full-size convergence, released weight-value loading, H100 execution, CP>1, packed incremental cache allocation, and optimized serving prefill remain outside the validated scope. No throughput improvement is claimed.
