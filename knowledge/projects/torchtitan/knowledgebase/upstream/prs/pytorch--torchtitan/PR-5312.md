# [parallelism] Reject a non-positive pipeline_parallel_layers_per_stage

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5312) · state: closed · merged: True

## Original PR description

## Summary

`parallelism.pipeline_parallel_layers_per_stage` defaults to `None`, which means the pipeline split is inferred. Setting it to `0` reaches `math.ceil(... / layers_per_stage)` in `torchtitan/distributed/pipeline_parallel.py` and raises `ZeroDivisionError`. A negative value gets past that division and then fails with a stage-count `ValueError` that tells the user to adjust the field, without saying the field itself is invalid.

`ParallelismConfig.__post_init__` now rejects a non-positive value with `ValueError`. `None` is unchanged. The check stays on the config object. `pipeline_parallel.py` is left alone because other open PRs edit it.

This is separate from the seed-checkpoint launch check. That one depends on the process-group world size, not on this field.

## Test plan

- [ ] CPU: `tests/unit_tests/cpu/config/test_parallelism_config.py` rejects `0` and `-1`, and still accepts `None` and `2`.
