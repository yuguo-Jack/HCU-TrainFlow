Related, standalone on main: Train the MoE router gate in RL, keep the expert bias frozen.

**TLDR:** Kimi now compiles its MoE router (`moe_router_topk`). EP 4 decode, GB300: 35.9 -> 19.0 µs per layer (Kimi K2.5, T = 64). Expert ids are identical except near-ties (1-4 of 1,048,576 tokens); scores and grads differ by rounding.

**Problem**
1. **Opt-in region.** The router's score / top-k / normalize (`moe_router_topk`) compiles only for models whose `local_compile_regions` list it. Only Qwen3.5's does.
2. **Cost.** Kimi runs it eager: 34-46 µs per layer at EP 4 decode, ~1.0 ms fwd + bwd per router at 16k tokens.

**Solution**
1. `kimi_k2_7.build_model_config` appends `moe_router_topk` to the list Kimi inherits from DeepSeek-V3, for every Kimi flavor. Kimi's routers have no expert groups, so the region compiles the whole top-k.
2. **Who runs it.** Kimi has only test recipes, so this is headroom.
3. **Unchanged.** The router code, and DeepSeek-V3's list (its group-limited router wasn't measured).

NOTE:
- No Kimi recipe is batch-invariant, so the router region's `batch_invariant=False` doesn't raise.
- Kimi's 4-GPU PP + FSDP + EP integration test (`kimi_k2_5_muon_pp+fsdp+ep`, 1 step) passed with the router region on. Not run: the 8-GPU `kimi_k2_5_muon_fsdp+ep`, an RL run.
- Muse Spark gets the same region in a separate follow-up, after the Muse regions stack.

**Test plan**
`pytest tests/unit_tests/cpu/models/common/test_router_compile_regions.py tests/unit_tests/gpu/models/common/test_router_compile.py`: region lists; compiled vs eager fwd + bwd on the Kimi flavor router (grads rel L2 < 1e-3); scores at 1-256 tokens bitwise equal to the 16k batch.
