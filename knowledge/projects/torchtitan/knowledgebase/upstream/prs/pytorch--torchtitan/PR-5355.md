# Install torch_checkpointing from main

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5355) · state: closed · merged: False

## Original PR description


Summary:
Point the `torch_checkpointing` requirement at the `main` branch of
meta-pytorch/torch_checkpointing instead of commit `dcbb3a59`, as #5131 did for
`spmd_types`. TorchTitan's `TorchCheckpointingManager` is developed alongside
torch_checkpointing, so with a commit pin every torch_checkpointing fix needs a
separate TorchTitan bump before CI or `pip install -r requirements.txt` sees it.

`requirements.txt` at the repo root is a symlink to this file and
`pyproject.toml` reads its dependencies from it, so the change applies to pip,
uv and CI alike. Workflows that install the requirements directly resolve
`main` on every run; the Docker image resolves it when the image is rebuilt.

Test Plan:
- The edited requirements file parses with `packaging.requirements.Requirement`;
  the URL is `git+https://github.com/meta-pytorch/torch_checkpointing.git@main`.
- `pre-commit run --files .ci/docker/requirements.txt` passes.
- `pytest tests/unit_tests/cpu/components/checkpointer/` against torch_checkpointing
  `dcbb3a59`, the current `main`: 121 passed.
