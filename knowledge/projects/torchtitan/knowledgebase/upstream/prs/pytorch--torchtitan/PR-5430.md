# Consolidate norm input names

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5430) · state: closed · merged: True

## Original PR description

## Summary

Consolidate norm inputs names on `input` and reuse shared norm sharding configurations.

## Existing problem

Sharding configurations identify inputs by their `forward` argument names. Shared norm configurations use `"input"`, but PyTorch's `RMSNorm` and several custom norms used `"x"`.

This mismatch could silently skip input sharding checks or redistribution when using something like the shared `norm_sharding_config`. It also led to model-specific sharding helpers and a suppressed parameter-name override error in Muse Spark.

## Changes

- Give the common RMSNorm wrapper and custom norms a consistent `forward(input, ...)` signature.
- Update gated norm sharding keys to match.
- Replace Spark's duplicated head-norm sharding helper with the common helper.
- Remove unused `input_name` and `has_weight` arguments from the audio state sharding helper and reuse its wrapper configuration.

Computation order, parameter names, and checkpoint keys are unchanged. The upstream RMSNorm naming difference is handled in one common wrapper.
