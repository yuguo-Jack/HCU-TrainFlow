# [PP] save memory by return_outputs=False to pp_schedule.eval

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5247) · state: closed · merged: True

## Original PR description

## Why

With pipeline parallelism, `Validator.validate` runs each step through `pp_schedule.eval(...)`, which calls the schedule's `step()` with its default `return_outputs=True`. The last stage then keeps every microbatch's output until the end of the step, to merge them into an output the validator never reads: it only uses the per-microbatch `losses`. Training's `pp_schedule.step(...)` in `training_engine.py` already passes `return_outputs=False`.

With plain cross-entropy, the last stage's outputs are the logits, so validation holds `num_pp_microbatches x tokens x vocab` of them at once: about 16 GiB in BF16 for DeepSeek V3's 129,280-token vocabulary with 16 microbatches of 4,096 tokens. With `ChunkedLossWrapper`, the outputs are the final hidden states instead, which are smaller but are also all kept.

## What

- Pass `return_outputs=False` to `pp_schedule.eval`; `eval()` forwards it to `step()`.
- Add a CPU test that checks the validator's pipeline path asks for no outputs.

## Verification

- `pytest tests/unit_tests/cpu/test_validate.py tests/unit_tests/cpu/test_validator_frequency.py`: 14 passed. The new test fails without the change.
- The `validation_tp_cp_pp` integration recipe (`llama3_debugmodel_validation_tp2_cp2_pp2`, 8 GPUs) runs its 10 steps, with validation at steps 5 and 10.
- 8 x H100 with FSDP2: `deepseek_v3_671b(seq_len=4096)` cut to 16 layers (1 dense, 15 MoE) and 16 routed experts (top-8), PP 2 x 8 virtual stages (Interleaved1F1B, one layer per stage), 4-way FSDP, EP 4, 16 microbatches of 4,096 tokens, full activation checkpointing, plain cross-entropy, deterministic with seed 42, and validation at steps 1, 2 and 4 (2 steps each). Validation loss, training loss and grad norm are bitwise equal before and after. Peak memory during validation on the GPU holding the LM head:

| | Before | After |
| --- | --- | --- |
| Active | 54.2 GiB | 48.7-48.9 GiB |
| Reserved | 77.6-77.7 GiB | 64.0-64.3 GiB |
