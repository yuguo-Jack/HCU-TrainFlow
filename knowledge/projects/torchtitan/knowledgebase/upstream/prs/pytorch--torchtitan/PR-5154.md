# [torchft] Load the per-replica dataloader only when the load includes it

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5154) · state: closed · merged: True

## Original PR description

With fault tolerance and `enable_ft_dataloader_checkpoints` on, `TorchFTCheckpointManager._load_checkpoint` restores the per-replica dataloader checkpoint (`_ft_load`) after every load, whatever the load asked for. Its `_states_to_load` override drops `"dataloader"` from the main load, so the information about whether the dataloader was requested is lost before `_load_checkpoint` runs. As a result:

- `exclude_from_loading=["dataloader"]`, the partial-load example in `docs/checkpoint.md` (for changing the number of GPUs, for instance), is ignored: the replica still resumes its old data position.
- A model-only load (`initial_load_path` with `initial_load_model_only`) also runs `_ft_load` with the step parsed from that path (when it ends in `step-N`). If this run's folder already holds per-replica dataloader checkpoints (a restart before the first full checkpoint), the dataloader resumes from them while the train state starts fresh.

### Change

Remove the `_states_to_load` override and make the decision in `_load_checkpoint`: when FT dataloader checkpoints are enabled and `"dataloader"` is among the states this load restores, take it out of the main load and load the per-replica checkpoint afterwards; otherwise skip `_ft_load`. Loads that include the dataloader behave exactly as before, and nothing changes when FT dataloader checkpoints are off.

### Test plan

- New `test_load_skips_ft_checkpoint_when_dataloader_is_excluded` in `torchtitan/experiments/torchft/tests/test_torchft_checkpoint.py`: with `exclude_from_loading=["dataloader"]` and both a main and a per-replica checkpoint at step 5, `load()` loads only the main checkpoint, without the dataloader. It fails on main (2 loads instead of 1). The existing `test_load_restores_ft_checkpoint_after_main_checkpoint` still passes, so the normal resume still restores the per-replica checkpoint.
- `test_torchft_checkpoint.py` and `tests/unit_tests/cpu/test_checkpoint.py` pass locally (CPU). `test_torchft_optimizer.py::TestTorchFTMoELoadBalancing::test_accepted_step_synchronizes_global_moe_load_once` fails in the same environment with and without this change.
- flake8 (with the hook's plugins) and ufmt (black 22.12.0, usort 1.0.5) pass on the changed files; pyrefly was not run locally.
