# Remove shared SDPA and use Varlen attention in Flux

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5295) · state: closed · merged: True

## Original PR description

Superseded by #5296. GitHub automatically marked this PR merged into `optim_ulyssescp` during the stack reorder; it was not merged into `main`. The active stack is `main` -> #5296 -> #4760.

Flux was the remaining production caller of the shared SDPA backend. Make Flux use the existing Varlen backend by folding `(B, L)` into tokens at the attention boundary. Separate cumulative Q/KV sequence lengths preserve bidirectional attention within each sample and prevent attention across samples. The outer blocks retain their batched layout for per-sample conditioning, and CP still gathers K/V before folding, allowing local Q and gathered K/V lengths to differ.

Update all Flux flavors and block defaults to this adapter. Remove the public `ScaledDotProductInnerAttention` implementation and exports, while retaining the unchanged implementation under `experiments/graph_trainer` for graph tests and numerical comparison scripts. Flux reuses common Varlen's BF16 compute; no kernel implementation is added. Model parameter keys remain unchanged.

Validation on the rebased branch:

- 9 targeted CPU/GPU tests and 7 subtests passed: forward/backward against independent attention, sample isolation, unequal Q/KV lengths, fullgraph compilation, and real two-GPU CP with SPMD type checking.
- 12 graph-trainer/Flex/Varlen regression tests passed; two registry-dependent cases were deselected because of the runtime issue below.
- Actual 258M-parameter `flux-debug` model: 10 AdamW steps on synthetic inputs, seed 42, deterministic algorithms enabled, BF16 autocast, and `inplace_wgrad_accum=False` in both runs. Every step's loss and grad_norm matched the SDPA reference exactly. Loss went from `0.985900342464447` to `0.6753833889961243`; verified 40 calls to each backend and strict state-dict loading between the two models.
- All non-Pyrefly pre-commit hooks passed across the repository; scoped Pyrefly for all seven changed core files reported zero errors. The experiment's SDPA class has an identical AST to the parent implementation.

Local validation limitations: the installed PyTorch lacks `torch.distributed.pipelining.analyze_pipeline_activation_liveness`, so normal Flux test collection fails through the unrelated converter registry. The targeted Flux tests and model comparison used a temporary loader that bypasses that registry while executing the real model and attention kernels. Full `pre-commit run --all-files` was run, but global Pyrefly fails on existing errors, including files in the local `titan-rl` environment; its unrelated autofixes were reverted. Representative-data convergence and performance comparisons remain unverified; the 10-step result is a synthetic numerical smoke test.
