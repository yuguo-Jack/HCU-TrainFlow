# [graph_trainer] Schedule eager HybridEP with explicit completion

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5539) · state: open · merged: False

## Original PR description

## AI-Generated Details

Prepared with Codex from the author's eager HybridEP overlap design.

Native dispatch/combine and their backward operations expose distinct completion
requests and graph-visible waits retaining every tensor input. Routing handles
survive through backward; native record-stream ownership protects the same
inputs during eager execution and full CUDA replay.

The eager pass emits source annotations. This PR introduces the shared native
validator, positional ABI and mutation dependencies, and early-launch/late-wait
topological scheduler once. Prefer ready launch ancestors over unrelated compute
so input-gradient exchanges can issue before independent wgrad. Paging and PP
extend this contract without replacing it or inferring roles from shapes/names.

SimpleFSDP getters are primed outside chunk ownership. Shared unshard and gradient
reduction chains are validated before bucketing; retired graph-chunk/count-sync
tags and process-group rewrites are removed. Only capacity-based non-blocking
HybridEP is supported. DeepEP and full-graph Inductor are outside this feature.

Canonicalization must preserve parameter-gradient value identities when removing
aliases, detach, identity views, cancelling transposes and full slices. The
existing marker-removal tuple merge is shared across those replacements; module
and chunk annotations remain attached to their producing operations. Losing
gradient identities made a standalone scheduling test pass while the actual
16B graph lost its wgrad ownership. A production-tracer regression now covers
real autograd gradients and adjacent tied-parameter identity markers.

Native EP uses a high-priority stream. Set `TORCHTITAN_HYBRIDEP_DISPATCH_SMS` and
`TORCHTITAN_HYBRIDEP_COMBINE_SMS` before initialization to select native SM targets
(16 each by default), without restricting compute. Priority does not preempt
running CTAs, so communication still must issue before its overlapping compute.

Acceptance recipes use native varlen Flash/FA4. An optional
`VarlenInnerAttention.Config.sdpa_backend` scopes native `sdpa_kernel` selection:
the default retains automatic priority, explicit Flash cannot fall back to cuDNN,
and flags are restored after each call. Fixed C4 document metadata permits full
forward/backward CUDA capture without full-graph Inductor.

## Verification

The owning commit's 31 focused canonicalization tests passed. Combined-stack tree
`9542fd0f3872179b0f9c4042a8bb85107f56908b` passed 69 native/paging/CPU cases and
all 3 full-CUDA SPMD, combined PP and DualPipeV paging numerical comparisons.
Native 16B graph inspection verifies terminal combine before both expert wgrads
in all 26 MoE layers; paired local loss/norm samples are exact. These are
correctness and graph gates, not a new scale-speedup claim.

Scheduling-only comparisons retain identical chunks, routing and capacities.
Chunked and unchunked execution are not promised bitwise equal. The unrelated
video optional-time-base typing failure remains outside EP scope.
