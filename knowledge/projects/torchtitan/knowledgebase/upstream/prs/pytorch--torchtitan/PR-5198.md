# [dsv4][perf] Run the Compressor and mHC projections as bf16 GEMMs with fp32 output

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5198) · state: open · merged: False

## Original PR description

**TLDR:** Run DeepSeek-V4's fp32 projections as bf16 GEMMs with fp32 accumulation (`HiMidLoLinear`) instead of fp32 SIMT matmuls: 16k step 120.2 -> 91.7 ms (-23.7%).

**Problem**
1. **fp32 projections.** The Compressor's `wkv`/`wgate` run under an fp32 autocast; the mHC `hc_fn` projection upcasts too.
2. **fp32 matmuls.** Both upcast bf16 operands and run fp32 matmuls.
3. **No fast path.** Main's trainer no longer enables BF16x9, so these run as SIMT `sgemm` kernels (no tensor cores).
4. **Cost.** At 16k, 28.5 ms of the 120.2 ms step goes away with bf16 GEMMs (Results).

**Solution**
1. **Compressor:** `wkv`/`wgate` use main's `HiMidLoLinear` (config change); its autocast becomes `enabled=False`.
2. **mHC:** `HcPre`/`HcHead` own a raw `hc_fn` parameter, so they call a new function `hi_mid_lo_linear`.
3. **What it does:** a bf16 GEMM accumulating in fp32, with grad_output split into 2 bf16 pieces in backward.
4. **Unchanged:** parameter names, so checkpoints load as before. fp32 operands (no mixed precision, CPU) still run fp32 matmuls.

```text
before:  x bf16 -> .float() -> fp32 matmul (SIMT sgemm) -> fp32 out
after:   x bf16 -> bf16 GEMM, fp32 accumulate (tensor cores) -> fp32 out
         bwd: grad_output = hi + mid (2 bf16 pieces), each a bf16 GEMM
```

**Results**
```text
DeepSeek-V4 Flash layers 4+5, fwd+bwd wall, 1x GB300, FA4, median of fresh processes within 1% of best
16k   120.23 -> 91.70 ms  (-23.7%)
4k     45.95 -> 38.56 ms  (-16.1%)
peak memory 16k   66.3 -> 63.8 GB
correctness: not bitwise; error vs fp64 unchanged (earlier measurement, same method):
             HcPre 2.54e-3, Compressor CSA 3.01e-3, HCA 3.02e-3
graphs: unchanged (HcPre 3)
```

You may ask: why 2 pieces and not 3? 3 pieces had the same error vs fp64 and were slower.
NOTE: reaches every DeepSeek-V4 config (CSA, HCA and Indexer compressors; all HcPre/HcHead).
NOTE: not yet measured under CUDA graphs. Not tested: loss curve, multi-GPU, H100 (SIMT there too), the SPMD typecheck path.

**Test plan**
DeepSeek-V4 CPU tests and `pytest tests/unit_tests/gpu/test_deepseek_v4_mhc_compile.py`

Stack: 4 of 7. Branch `felipemello1/lcp/dsv4-4-fp32-projections`.
