# [release] Refresh GPU validation coverage and add B200

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5411) · state: closed · merged: True

## Original PR description

The staged-RC GPU workflow omits B200 coverage and H100 DeepEP activation-checkpoint gradient checks.

Add an 8x B200 job using the existing B200 CI runner/container and a clean uv environment. Run the full B200 integration suite plus Dist-MoE CPU/GPU and MXFP8 FSDP unit tests, including the shared GraphTrainer SimpleFSDP cases. Install pytest/expecttest, FlashAttention 4, and Dist-MoE before verifying the pinned package versions and the installed TestPyPI RC. The B200 image recipes use the RC's image dependencies and pinned torchvision.

Add the H100 DeepEP gradient checks after installing the matching dependency, and copy the pytest configuration into the isolated validation directory so strict marker checks recognize `multi_gpu`. Preserve the existing A10G and H100 GraphTrainer release-validation jobs, their numerical tests, and precompile support. Update the release guide for all seven GPU jobs and remaining coverage gaps.

Validation:

- Bash syntax, ShellCheck (excluding SC1091 for the generated venv activation file), and `git diff --check` passed.
- Static suite and mocked-command audits passed: the non-GraphTrainer suites cover 92 integration tests / 104 configuration executions. Both restored GraphTrainer runner functions and the H100 GraphTrainer job match the pre-PR versions exactly. Verified installed-RC test paths, precompile support, H100 dependency ordering, B200 SimpleFSDP inclusion, and failure propagation.
- Pre-commit checks for the three changed files passed. `pre-commit run --all-files` passed every hook except Pyrefly, which reported 52 existing type/dependency errors in unchanged Python files in the local environment. Its unrelated automatic edits were reverted.
- Complete-script dry run: **22 mocked scenarios pass**, covering all seven suites, install retries, version/hardware guards, failure propagation, checkpoint cleanup, and Lighthouse shutdown.
- Built a synthetic RC wheel from this PR and imported the official pinned staging wheels from isolated target directories. The original version/import-location check passes on 8x H100, but **real core and GraphTrainer CLI startup fail** because `torch==2.14.0` lacks `torch.distributed.pipelining.analyze_pipeline_activation_liveness`, imported by the existing Dist-MoE runtime. The current PR source must be reconciled with the intended release's PyTorch version before it can pass release validation.
- The branch still has `assets/version.txt=0.2.2`; the workflow correctly rejects non-RC versions. A matching published RC and actual A10G/H100/B200 runs are still required. Full dependency installation, CUDA kernels, DeepEP compilation, and numerical goldens have not been verified.
