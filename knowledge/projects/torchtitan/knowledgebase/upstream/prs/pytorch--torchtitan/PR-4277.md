# [checkpoint] Load Hugging Face checkpoints natively

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4277) · state: closed · merged: True

## Original PR description


Summary:
Load an initial Hugging Face safetensors checkpoint (`checkpoint.initial_load_in_hf`) through a temporary, model-only `torch_checkpointing` manager.

The model state is converted with the state-dict adapter (`to_hf`), loaded in place, and restored with `from_hf`. The load names the export's format with `metadata_format=HuggingFaceSafetensorsDistributedMetadataFormat`: an export has no native metadata, and `torch_checkpointing` only reads a non-native format the caller names. The model item keeps its `DefaultResharder`, which reshards every safetensors source into the model's DTensors. The temporary manager loads the export as the `model` item, so `torch_checkpointing` reads `model.safetensors.index.json` or `model.safetensors`, and the probe checks those two names, with no directory listing. Exports named after another item, such as diffusers' `diffusion_pytorch_model.safetensors.index.json` for Flux, are left as a TODO for a follow-up. Retention's validity check uses `model`, the name this checkpointer writes its own exports under. The load is `strict`, but only over the weights `to_hf` maps, so parameters an export does not carry, such as new LoRA adapters, keep their initialized values. A native base checkpoint cannot yet initialize a LoRA model, since its strict load requires the adapter parameters; a TODO marks that. Quantized Hugging Face loads are rejected for now.

It also imports `METADATA_FILE_NAME` from `torch_checkpointing.metadata_serialization`, where it now lives.

Every `torch_checkpointing` API it uses, including `metadata_format`, `torch_checkpointing.hf.metadata` and `METADATA_FILE_NAME` in `metadata_serialization`, is on `torch_checkpointing` main. The probe spells the single-file name, `{item_key}.safetensors`, itself.

Test Plan:
Against `torch_checkpointing` main:
```
pytest -q tests/unit_tests/cpu/test_torch_checkpointing.py tests/unit_tests/cpu/test_state_dict_adapter.py
pre-commit run --files torchtitan/components/checkpointer/torch_checkpointing.py tests/unit_tests/cpu/test_torch_checkpointing.py
```
55 passed, 24 subtests passed. `test_hf_load_reads_a_real_safetensors_export` loads a real indexed `model` export into an `nn.Linear` with no mocks, and `test_hf_load_leaves_parameters_the_export_does_not_carry` loads one into a model with an extra LoRA-like parameter, which keeps its value; loading the export by plain path instead fails with "Missing files for checkpoint items ['model']". pre-commit: clean. Repo-wide pyrefly reports no `torch_checkpointing` errors.
