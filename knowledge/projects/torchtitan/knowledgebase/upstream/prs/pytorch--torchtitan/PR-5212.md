# [compile][doc] Blockers/workarounds found when using torch compile

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5212) · state: open · merged: False

## Original PR description

Human note:

I let an agent improve perf in Titan using compile. In the process, i asked the agent to track asks to the compile team based on blockers/workarounds it found.

this is an 100% vibecoded doc from the agent, in case the compile team is curious to take a look.

Read the readme.md

-----------

**TLDR:** 13 torch.compile asks from TorchTitan's regional compile. To improve performance, several rewrites were necessary. Inductor could make them itself.

1. `docs/torch_compile_asks/README.md`: hard failures first, then performance by share of a 16k microbatch on main's default regions, then compile time, then one-line known behaviors.
2. `docs/torch_compile_asks/repros/`: pure-torch repros (`./repros/run_all.sh cpu|gpu`) and raw logs.

**Results**
```text
1x GB300, torch 2.15.0.dev20260926+cu130, triton 3.8.0; repros re-run 2026-10-09; TorchTitan claims checked on main 01b1b69e3
hard failures:  1 graph budgets -> FailOnRecompileLimitHit   2 FX cache serves code from a stale fake
                3 AOTAutograd AttributeError on a parameter view's ._base
largest perf:   opaque deterministic scatter  3.1 ms/MoE layer     ~2.0% of a Kimi K3 16k microbatch
                symbolic strides on views     2.6-3.3 ms/layer     ~1.7-2.1%
                small reductions not unrolled up to 1.2 ms/call    ~1.6%
every repro reproduces within ~1% of the original runs
```

**Test plan**
`./docs/torch_compile_asks/repros/run_all.sh cpu` and `... gpu` (one CUDA GPU).
