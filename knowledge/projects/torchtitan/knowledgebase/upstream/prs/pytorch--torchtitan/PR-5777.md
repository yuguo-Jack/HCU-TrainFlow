# chore: ignore flake8 E704, which the formatter produces on purpose

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5777) · state: open · merged: False

## Original PR description

The repo's own config reports five E704 that cannot be fixed from the source side:

```
$ python -m flake8 --config=.flake8 --select=E,W,F torchtitan
torchtitan/experiments/graph_trainer/graph_pp/stage_builder.py:59:5: E704 multiple statements on one line (def)
...  (5 in that file)
```

All five are ellipsis-only stub bodies written as `def f(...) -> T: ...`. That form is what the project formatter emits:

```
$ ruff format --diff torchtitan/experiments/graph_trainer/graph_pp/stage_builder.py
1 file already formatted
```

And expanding a stub does not survive formatting — writing the body on its own line makes `ruff format` collapse it straight back:

```
-    ) -> list[Any]:
-        ...
+    ) -> list[Any]: ...
1 file would be reformatted
```

So E704 is a linter/formatter conflict, not a code smell. This adds it to the existing `ignore` list with a comment explaining why, and leaves everything else untouched (`B007,B008` etc. are still reported).

```
before:  python -m flake8 --config=.flake8 --select=E704 torchtitan  -> 5
after:   python -m flake8 --config=.flake8 --select=E704 torchtitan  -> 0
```

Alternative if you would rather not widen the global ignore: a `per-file-ignores` entry for `torchtitan/experiments/*`. Happy to switch.
