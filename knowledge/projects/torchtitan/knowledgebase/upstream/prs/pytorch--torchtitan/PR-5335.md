# [Attn] Unify attention metadata

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5335) · state: closed · merged: True

## Original PR description

Build and route metadata by the configured inner-attention type, removing cached metadata keys and redundant config lists. Use `first_full_attention` for shared config consumers. CP load balancing requires full attention; models without it use contiguous sharding and emit a warning.

Unify hybrid Qwen/Kimi blocks under one `attention` config and module, and update checkpoint adapters and Muon parameter matching. Rename DeepSeek MLA to `DeepSeekMLAAttention` and type inner-attention configs explicitly.

HF checkpoints remain compatible. Native Kimi K3 KDA (`delta_attention`) and Qwen3.5/3.6/3.8 (`attn`) decoder paths become `attention`; older native checkpoints require key migration.

### Testing

Rebased onto `3f021a1eb9`. Focused checks using local import compatibility shims: 106 tests passed; three dependency/API failures reproduce on main. Scoped Pyrefly diagnostics are unchanged from before the rebase.

Earlier validation:

- Kimi K3 and Qwen3.5/3.6/3.8 BF16 debug decoders: 10 steps, seed 42, deterministic mode; bitwise-identical outputs, loss, grad_norm, gradients and updated weights after normalizing parameter names.
- Targeted CP, hybrid, Muon and HF checkpoint round-trip checks passed.
- Full pre-commit: other hooks passed; 50 existing local Pyrefly errors remain. Three MRoPE tests reproduce the same compiled-library import failure before the changes.

### 1. Naming of `first_non_linear_attention` (`decoder.py:93`)

You're right that `non_linear` is a bad name, for both reasons you gave. SWA costs `O(L*W)`, so in complexity terms it is linear. And "non-linear" defines the set by what it excludes, so readers have to know that `LinearAttention` is a term of art (GDN/KDA) and not a complexity class.

**`first_key_value_attention` doesn't separate the two groups, though.** GDN and KDA also have K and V: KDA has `q_proj`/`k_proj`/`v_proj`, and the delta rule writes `k^T v` into its state. The real difference is how K/V is consumed:

| | GQA full | GQA SWA | MLA (DSv3/Kimi) | DSv4 | GDN / KDA |
|---|---|---|---|---|---|
| softmax over keys | yes | yes | yes | yes | **no** |
| KV cache grows with context | yes | yes (bounded by W) | yes (latent) | yes | **no** (fixed recurrent state) |
| has K/V projections | yes | yes | yes | yes | **yes** |

The last row is identical across the whole table, so a name based on K/V can't tell the groups apart. The first row can.

**Recommendation: `first_softmax_attention`.**
- It describes what the set *is* rather than what it isn't. "Softmax attention vs. linear attention" is the standard split in the linear-attention literature and in hybrid-model papers.
- SWA, full GQA, MLA and DSv4 are all clearly softmax attention, so the SWA ambiguity goes away.
- It fits every consumer: TP head checks (`validation.py:69`, `decoder.py:165`), vLLM head dims (`vllm_registry.py:71`), the flex/varlen backend check (`rl/generate.py:126`, `rl/generator.py:940`), Muon MLA dims (recipes), and the CP fallback (`decoder.py:340`).

Second choice: `first_kv_cache_attention`. It reads well for the vLLM callers but less well for TP and CP. I'd go with softmax.

If you rename it, also update:
- the docstring at `decoder.py:94` (say "softmax attention, i.e. not GDN/KDA"),
- the error strings "no non-linear attention layer" in `rl/model/vllm_registry.py:74`, `rl/generate.py:128` and `rl/generator.py:943`,
- the comment at `decoder.py:332`,
- the `SimpleNamespace(first_non_linear_attention=...)` mocks in `tests/rl/unit_tests/cpu/test_generator.py:536` and `tests/unit_tests/cpu/models/common/test_cp_attention.py:143`.

[Fix this →](https://claude.ai/code?q=On%20branch%20unify_attn%2C%20rename%20Decoder.Config.first_non_linear_attention%20to%20first_softmax_attention%20in%20torchtitan%2Fmodels%2Fcommon%2Fdecoder.py%20and%20update%20every%20callsite%20(validation.py%2C%20rl%2Fgenerate.py%2C%20rl%2Fgenerator.py%2C%20rl%2Fmodel%2Fvllm_registry.py%2C%20torchtitan_recipes%2Ftests%2Fmodels%2Fkimi_k3.py%2C%20kimi_k2_7.py%2C%20scripts%2Fcheckpoint_conversion%2Fnumerical_tests_kimi_k3.py%2C%20and%20tests).%20Update%20the%20docstring%20and%20%22non-linear%20attention%22%20error%20messages%2Fcomments%20to%20say%20softmax%20attention%20(not%20GDN%2FKDA).&repo=pytorch/torchtitan)

### 2. Inconsistency between `is_full_attention` (inner) and linear-ness (outer), plus `InnerLinearAttention.Config` (`kda.py:145`)

Your two comments point to the same fix. `InnerKDA.Config` and `InnerGDN.Config` already share `conv_kernel_size` and a byte-identical `build_attention_metadata` (`kda.py:155-172` vs. `gdn.py:281-298`). Only `kernel` differs in type, plus KDA's `head_dim`. I agree with adding `InnerLinearAttention(InnerAttention)` in `linear_attention.py`, which already imports from `.attention`, so there's no import cycle. Move `conv_kernel_size` and the metadata builder there.

That would also make the softmax/linear predicate an *inner* property, next to `is_full_attention`. `first_softmax_attention`, `_cp_shard` and `validation.py:202` could then all test `inner_attention` the same way, and the "full on inner, linear on outer" mismatch you flagged would disappear. KDA's `head_dim == 128` check can stay on `InnerKDA` or move to the outer `KDA` as you suggested. Either is fine. This could land in the follow-up PR.

### 3. CP fallback when there is no full attention (`decoder.py:332`)

- **"What if a PP stage is all-linear?"** This case is already safe. `pipeline_parallel.py` deep-copies the whole model and deletes layer *modules*, but `self.config.layers` keeps the full list. Every PP rank calls `model_parts[0].preprocess_inputs` (`training_engine.py:602`), and both `_cp_shard` and `_get_attention_metadata` (`decoder.py:389`) iterate over `self.config.layers`. So every stage picks the same layer and generates the same permutation. Stage-local selection would actually break things, because stages would disagree on the permutation.
- **What if the whole model is all-linear?** `selected_attention_metadata` is `None`. `HeadTailCPLoadBalancer` ignores it, so that works. `PTRRFlexAttentionCPLoadBalancer` raises "PTRR load balancing requires attention metadata, but got None" on the first step (`context_parallel.py:116`). Validation (`validation.py:202`) `continue`s over linear layers, so the config passes validation and only fails at runtime. Rejecting PTRR when the model has no softmax attention in `validation.py` would be a small improvement.
- **"How does the SWA fallback help?"** For load *balance*, you're mostly right. With SWA, per-query cost is `min(pos_in_doc, W)`, so imbalance only exists in the first `W` tokens of each document. The practical effect is that PTRR gets a `BlockMask` and works instead of raising. It also keeps the previous behavior: the old `canonicalize_cp_inner_attention` path had the same full-then-SWA fallback. I'd keep it, since removing it would be a behavior change for SWA-only plus PTRR. If you'd rather drop it, add the validation error above at the same time.

### 4. vLLM: first full vs. first non-linear (`vllm_registry.py:71`)

I'd push back on your comment here and keep the softmax version. It is a superset of "full", so it works for every case "full" handles. It also works for all-SWA models (e.g. Mistral-7B-v0.1-style, every layer windowed), where looking for full attention would raise even without PP. The head counts and dims are the same for SWA and full layers in every current hybrid (gpt-oss, Qwen3.5), and the comment at line 69 already says so.

### 5. Other comments

- **Base norm class (`decoder.py:62`):** agreed it can wait. `Module.Config` loses type safety on `attention_norm`/`ffn_norm`; a TODO pointing at the follow-up would help.
- **`InnerAttention` → `BaseInnerAttention` vs. `BaseAttention` → `Attention`:** the PR went with `Attention`, which is consistent now (`Attention` / `InnerAttention` / `LinearAttention`).
- **`type(cast(...).attention.inner_attention)` in kimi_k2_7, muse_glimmer, qwen3_5, mtp:** the `Decoder.forward` version (`decoder.py:251`) is already clean. Checking that the other models drop the cast the same way is worth one more pass.
- **`simple_fsdp.py:225`:** the reason given holds up. Metadata is now keyed by `type(inner_attention)`, and SimpleFSDP's parametrization swaps a module's class even when it has no parameters, which would break the lookup. It deserves a one-line code comment, since it's otherwise non-obvious.
- **Out of scope (not this PR):** the TP divisibility check at `validation.py:69` and `decoder.py:165` only looks at the first softmax layer. GDN/KDA head counts, which are also TP-sharded, aren't checked. The same check also appears in both places.
