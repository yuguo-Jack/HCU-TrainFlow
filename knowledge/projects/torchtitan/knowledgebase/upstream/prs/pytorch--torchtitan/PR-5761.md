## Agent details

**TLDR:** Silent data corruption (SDC) replay now works when a step has several `forward_backward` calls, as with streamed RL microbatches. Before each re-run, restore puts back the gradients the call started with, instead of zeroing them. The check schedule counts optimizer steps, not calls.

**Numerics:** unchanged. A checked call keeps its last run's results, and they equal an unchecked run bitwise (1-GPU check below).

```python
# before (restore)
_local_tensor(snapshot.original).zero_()
# after (capture clones the entry value; restore puts it back into the same tensor)
_local_tensor(snapshot.original).copy_(snapshot.value)
```

**Problem**
1. SDC replay runs a `forward_backward` call again and compares hashes of the gradients, the loss and the buffers. Before each re-run, it restores the state the call started with.
2. For a parameter that already had a gradient, restore zeroed it. That is right only for a step's first call.
3. A streamed step's second call starts with the first call's gradients. The re-run misses them and reports a false mismatch.
4. So the config rejected SDC replay with streaming or lazy preprocessing, and the engine forced one call per step. Its schedule counted calls, so `num_steps=1` checked only a step's first call.

**Solution**
1. **Restore puts the entry values back.** `_GradientSnapshot.value` holds a copy of each entry gradient. Restore keeps the original tensor, so graph addresses stay valid, and copies the value into it. A parameter that entered without a gradient goes back to `None`.
2. **The schedule counts steps.** `SDCReplayer.checks_current_step` is true for every call of a checked step. `optim_step` calls `step_completed()`.
3. **A checked call preprocesses its groups once, up front.** Lazy preprocessing would run again in every re-run and count the loss tokens twice. GraphTrainer rejects lazy preprocessing at config time, and its body now asserts the flag is off.
4. **Removed:** 2 config checks (streaming + SDC, lazy preprocessing + SDC) and the engine check that forced one call per step.
5. **Unchanged:**
   - With graphs, SDC replay still allows one replay. Lifting that needs its own PR with a green CI run of `llama3_debugmodel_sdc_replay_accelerator_graph` at more replays (TODO at the check).
   - Per-microbatch-group graphs still reject SDC. A capture inside a re-run that starts from `None` gradients would record an assignment instead of an add. The next PR replaces that mode.

**Results**

```text
Numerics: unchanged for unchecked calls. A checked call keeps its last run's results.

1 GB300, the RL trainer with a Qwen3 debugmodel (varlen, DAPO loss, masked prompts), 6 AdamW steps,
SDC on every call, compared with the same run without SDC by torch.equal. Step 5 has no loss tokens.
case                                      before this PR                  this PR
2 calls per step, no graphs, 2 replays    SDCReplayMismatch at step 1,    no mismatch; gradients, loss, metrics,
                                          call 2 (one-call check off)     grad norm, final weights: bitwise
"Before" ran at 705d4d655, "this PR" at c9f9c12f3. The SDC code has not changed since c9f9c12f3.
```

You may ask:
- Why copy the gradients instead of zeroing them and adding them back after the call? A re-run's result must not depend on the order of the adds. A copy restores the exact entry state.
- What does it cost? One copy of this rank's local gradients during a checked call that starts with gradients. By default only the first step after a (re)start is checked.

NOTE:
- Each call is checked on its own. Corruption of the gradient storage between two calls is not caught.

<details><summary>Details</summary>

- Gate: the problem is real on the base branch. Restore zeroed entry gradients, which is only correct for a step's first call, so SDC was banned for streaming. Copying the gradients back is the right fix in the right layer (`sdc_replayer.py`). Its cost is one copy of the local gradients during later calls of a checked step; the PR describes that cost, and its docs describe the copy.
- FSDP/HSDP: deferred reduction and the HSDP all-reduce both finish on each call's last group, so no unsharded accumulation state is left between calls. The snapshot only needs `.grad`, and it covers that. PP finalization happens per call in the same way.
- Lazy preprocessing: forcing up-front preprocessing on checked calls means `local_loss_token_count` and `ntokens_seen` are counted once. With RDMA microbatches, a checked call reads its whole column before it trains (no overlap). That costs speed only, not correctness.
- Callers of `optim_step` (core trainer, RL trainer, torchft, graph_trainer) all go through `TrainingEngine.optim_step`, so they all reach `step_completed`. `SDCReplayMismatchTrainer` returns without calling `optim_step` and asserts `steps_since_reset == 0`, which still holds.
- Under graphs, the kwarg `preprocess_microbatch_groups_lazily=False` flows into `AcceleratorGraphInputSpec` as a constant non-tensor input, which is fine.
</details>
