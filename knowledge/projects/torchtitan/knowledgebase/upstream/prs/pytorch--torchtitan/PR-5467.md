# [models] Let the attn_gym facade defer missing-backend import errors

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5467) · state: closed · merged: True

## Original PR description

## Summary

#5231 made the models importable when `attn_gym` is **absent**. On a machine where `attn_gym` is **installed but one of its kernel backends is not** (cutlass and triton have no macOS wheels, the same happens on any non CUDA box without them), `attn_gym` itself imports fine and its submodules raise `ModuleNotFoundError(name="cutlass")` / `(name="triton")` at import time. The facade's `_load_module` only tolerates `error.name == "attn_gym"`, so the error escapes, `torchtitan.models.common` fails to import, and none of `tests/unit_tests/cpu` can collect.

This keeps the existing contract from #5231 and extends it to that case:

- `_load_module` records a `ModuleNotFoundError` raised from inside an `attn_gym.*` import (keyed by module) and resolves the export to `_MissingKernel`, so the identity checks in `kda.py` / `gdn.py` / `linear_attention.py` / `cp_linear_attention.py` still skip SPMD registration.
- `_raise_missing` re-raises the recorded backend error (same `name` and message) when a placeholder kernel is called, and `require_attn_gym()` raises it when a kernel is built. The existing `test_linear_attention_reports_missing_dependency[cutlass-*]` cases therefore still see `error.name == "cutlass"`.
- No change when `attn_gym` is missing, and no change when every backend imports.
- `require_attn_gym()` is deliberately coarse, any recorded backend failure makes it raise, which matches the previous behaviour where the module import itself failed. Per kernel granularity can come later if a backend mix (e.g. cuDNN present, cutlass absent) turns out to matter.

Related: #5181 (@githubsgi) handles the same symptom for the KDA import in `attention/__init__.py`, this does it once at the facade for every export, including the `linear_attention.py` import that still fails without it.

## Test plan

New `test_common_attention_imports_with_broken_attention_gym_backend[cutlass|triton]` in `tests/unit_tests/cpu/models/common/test_optional_imports.py`: an installed `attn_gym` whose submodules all fail on the backend import, the common package and every model debug config still import/build, `_MissingKernel` is not registered with SPMD, and calling a kernel, `require_attn_gym()`, or building `KDAKernel` / `GDNKernel` raises the backend's own `ModuleNotFoundError`.

On macOS 15 (Apple Silicon, torch 2.16.0.dev20261014+cpu, attn-gym 0.0.17 without cutlass/triton):
- before: `pytest tests/unit_tests/cpu/components/checkpointer` → 2 errors during collection (`No module named 'cutlass'`, then `'triton'`)
- after: `tests/unit_tests/cpu/models/common/test_optional_imports.py` 11 passed; `tests/unit_tests/cpu/components/checkpointer` 120 passed, 2 failed (unrelated: torch_checkpointing uses `os.O_DIRECT`, reported separately); `torchtitan/experiments/torchft/tests` 26 passed
- `pre-commit run --files` on both files: all hooks pass (flake8, µfmt, pydoclint, codespell, pyrefly)

**Summary:** The approach is sound. It fixes the problem once in the facade instead of patching each call site (#5181 does the latter). It keeps the `_MissingKernel` identity checks working, so SPMD registration is still skipped. And `error.name` matches the backend, so the existing `[cutlass-*]` tests keep their meaning. One real concern and a few small ones.

#### 1. The new catch also hides real errors inside attn_gym (main concern)

`attn_gym.py:155`
```python
if name.split(".")[0] != "attn_gym":
    raise
_BACKEND_ERRORS.setdefault(name, error)
return None
```
This checks the *module being imported* (`name`). It doesn't check *what failed* (`error.name`), so every `ModuleNotFoundError` raised under `attn_gym.*` is now deferred. That includes errors that aren't a missing optional backend:

- **Version mismatch / wrong `_EXPORTS` path.** If an attn_gym release moves `attn_gym.linear.gdn.impl.cudnn`, importing it raises `ModuleNotFoundError(name="attn_gym.linear.gdn.impl.cudnn")`. Today that fails loudly when `torchtitan.models.common` is imported. After this PR it quietly becomes `_MissingKernel` on a CUDA box with every backend installed, and only shows up when a kernel is built. The same goes for a typo in `_EXPORTS`.

Narrowing the check to failures *outside* the attn_gym namespace keeps the intended behaviour (cutlass/triton/cudnn missing) and still raises on internal breakage:
```python
except ModuleNotFoundError as error:
    if error.name == "attn_gym":
        return None
    if error.name is None or error.name.split(".")[0] == "attn_gym":
        raise
    # attn_gym is installed but this module needs a backend that is not ...
    _BACKEND_ERRORS.setdefault(name, error)
    return None
```
(`name` always starts with `attn_gym` here, because `_load_module` is only called with `_EXPORTS` values or `"attn_gym"`. The existing check therefore never re-raises anything, so it's effectively dead code.)

[Fix this →](https://claude.ai/code?q=In%20torchtitan%2Fmodels%2Fcommon%2Fattn_gym.py%20_load_module%20on%20branch%20attn-gym-defer-backend-errors%2C%20only%20defer%20ModuleNotFoundError%20whose%20error.name%20is%20outside%20the%20attn_gym%20namespace%20(a%20missing%20backend%20like%20cutlass%2Ftriton).%20Re-raise%20when%20error.name%20is%20None%20or%20starts%20with%20%22attn_gym.%22%20so%20moved%20submodules%20or%20_EXPORTS%20typos%20fail%20loudly.%20Keep%20the%20error.name%20%3D%3D%20%22attn_gym%22%20-%3E%20return%20None%20branch.&repo=pytorch/torchtitan)

#### 2. The error reported depends on which modules failed first, not on the kernel called

`_raise_missing` always raises the *first* recorded error, and `require_attn_gym()` raises if *any* error was recorded. The PR description already calls `require_attn_gym()` coarse on purpose, and that's fine as a first step. Two things to know about it:

- Suppose `attn_gym.sparse` (DSv4 `lightning_indexer` / `gather_attn`) fails on cutlass while the cuDNN-backed GDN/KDA modules import fine. Then `GDNKernel.Config().build()` raises the cutlass error even though GDN would work. This setup was already broken before the PR (the import failed), so it's not a regression. But it makes the error message misleading for that case.
- `_BACKEND_ERRORS` fills in lazily, as exports are first accessed. So `require_attn_gym()`'s result depends on which model modules happen to be imported already. Today `kda.py`/`gdn.py` look up their exports when the module is imported, so it works in practice. Still, that's a hidden ordering dependency.

A cheap improvement is to give `_MissingKernel` placeholders the module they came from, so calling a placeholder re-raises *its own* module's error. That fixes the wrong-message case without making `require_attn_gym()` per-kernel. It's fine as a follow-up; at minimum, a `TODO` next to `require_attn_gym` would be good.

#### 3. Nits

- `attn_gym.py:130`: a `for ...: raise` loop that only ever runs once reads oddly. Clearer:
  ```python
  error = next(iter(_BACKEND_ERRORS.values()), None)
  if error is not None:
      raise ModuleNotFoundError(str(error), name=error.name, path=error.path) from error
  ```
  Building a new exception (rather than `raise error`) is the right call, since it stops tracebacks piling up on one shared exception object. Worth a short comment saying so.
- The module docstring on line 7 still says "placeholders when the package is missing". It should also mention a missing backend.

#### 4. Tests

- The `MetaPathFinder` raises from `find_spec` for *every* `attn_gym.*` module. That means the error comes during module lookup, not partway through running the submodule's own imports (which is what happens on macOS). Both reach the same `except`, so this is fine for checking the facade logic.
- Missing coverage:
  - **Mixed case:** some submodules import and others fail. It would check that the exports that loaded are real objects and still get registered with SPMD.
  - **Negative case for #1:** a `ModuleNotFoundError(name="attn_gym.<something>")` should still raise when imported.
- The model list matches the existing test at line 62 (both leave out `kimi_k2_7`, `qwen3_6`, `qwen3_8`, `flux`), so it's consistent. Adding `kimi_k2_7` to both would cover the other KDA user.

#### Verdict
Looks good once #1 is fixed. That change is small and keeps today's "fail loudly on real breakage" behaviour on the main CUDA path. #2 can be a follow-up.

**#1 in detail** (`attn_gym.py:156-166`): `_load_module` now decides based on `error.name`. In order:
- `"attn_gym"` returns `None`, the same behaviour as #5231.
- `None` or anything under `attn_gym.*` is raised.
- Anything else is recorded and deferred.

So a submodule moved in a new attn_gym release, or a typo in `_EXPORTS`, still fails at import time on a CUDA box with every backend installed. Tracing the negative test: `linear_attention` first looks up `_ConfiguredShortConv`, which reads from `attn_gym.linear.short_conv.cute`. The finder raises with `name="attn_gym.linear"`, and that error propagates. That matches the claim that this test fails against the first revision and passes now.

#### New observations (none blocking)

1. **Only `ModuleNotFoundError` is deferred.** A backend that is installed but can't load raises a different exception type. Examples: triton present but incompatible (`ImportError` from `from triton import X`), or cutlass-dsl failing to find `libcuda` (`OSError`/`RuntimeError`). Those errors stay loud, the same as before this PR. I think that's the right default, since those are broken environments rather than unsupported platforms. Just noting it's out of scope here.

2. **The `error.name is None` case is raised.** Some packages raise `ModuleNotFoundError("...")` by hand without setting `name`. Those will fail at import rather than being deferred. That's the conservative choice and fine, but if a macOS report like that shows up, this is where to look.

3. **The mixed-backend test** (`test_optional_imports.py:301`) monkeypatches `facade.import_module`. That works because `_load_module` looks up the module-level `import_module` each time it's called. It also replaces `spmd.register_local_autograd_function`, which works because `linear_attention.py:33` calls it through the `spmd.` attribute. Both run in a subprocess, so nothing leaks to other tests. One fragile spot: if either module switches to a `from ... import`, the test will start failing for a misleading reason. A one-line comment in the script would help, but it's optional.

4. **Fresh exception in `_raise_missing`** (`attn_gym.py:134-136`). It keeps `name`, the message and `path`, and chains the original error with `from error`. So callers that check `error.name == "cutlass"` (the existing `[cutlass-*]` cases) still pass, and the original traceback is still available. 👍

5. **Not this PR:** the install hint at `attn_gym.py:139` still pins `attn-gym==0.0.16`, while the PR description tested with 0.0.17. If the pin is out of date, fix it in a separate change.

#### Verdict
Approve-ready from my side. The design keeps the "fail loudly on real breakage" behaviour on the main CUDA path and fixes test collection on platforms without cutlass/triton wheels. The per-placeholder error reporting (#2) is a reasonable follow-up PR, since it needs changes at the `_MissingKernel` identity-check call sites in `kda.py`, `gdn.py`, `linear_attention.py` and `cp_linear_attention.py`.
