# Refresh stale A10G GPT-OSS/Qwen3 MoE goldens from #4772

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5368) · state: closed · merged: True

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.12.0) (oldest at bottom):
* __->__ #5368

#4772 exported its A10G goldens on a base that predated #5250 (in-place
bf16 Linear WGRAD accumulation), which itself re-baselined every A10G
golden. The final ghstack rebase onto #5250 kept #4772's stale values, so
the committed real_pg goldens never matched the landed code: step-1
grad_norm already differs (the WGRAD accumulation change), and the
divergence grows from step 2. The PR's real-PG CI only ran the required
subset, which excludes these tests; its fake-PG job failed on both.

These tests intentionally verify the new batch-wise aux-loss policy (the
expert-bias policy is kept only for gpt_oss_pp via
_use_expert_bias_load_balancing), so this refreshes values without
changing configs.

Provenance (torch 2.16.0.dev20261011+cu132, A10G, seed checkpoint per the
test definitions):
- real_pg: bit-identical across two independent main runs -- job
  114675094754 at 8b4a1300e and job 115529499679 at 50474ad60.
- fake_pg: bit-identical across four independent ciflow/fake-pg runs on
  PRs based on post-#4772 main (runs 38459347990, 38460226133,
  38460414111, 38466591432) that do not touch core model code.
