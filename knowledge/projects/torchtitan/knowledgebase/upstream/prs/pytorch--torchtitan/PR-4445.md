TODO: update this description with more details

High-level so far:

- **MXFP8 fwd + BF16 bwd MoE.** The bottleneck for RL is typically in rollouts so we keep the backward in high precision for now for better training stability. We can explore quantizing the backward later if it provides meaningful perf gains. We only quantize MoE for now because initial microbenchmarks did not find significant gains for linears for models like Qwen3-30B-A3B, can add linear quantization later if needed.

- **Weight sync lifecycle owns the quantized weights**. Similar to https://github.com/pytorch/torchtitan/pull/4203, we only maintain 1 copy of mxfp8 weights as the source of truth (but for the generator, since there's no FSDP there). Trainer pre-quantizes weights to mxfp8 before passing them to generator (`quantize_expert_state_dict_to_mxfp8 `). Generator generates rollouts from pre-quantized weights directly (`MXFP8InferenceGroupedExperts`)

- **Adds padding functionality to DeepEP.** DeepEP is needed to enable cudagraphs on the generator to avoid the [unpinned D2H sync issue](https://github.com/pytorch/torchtitan/blob/7a401fbac96e4303bf4ba7c9c4def9a8b157eaa0/torchtitan/experiments/rl/examples/alphabet_sort/config_registry.py#L634). However, TorchTitan's DeepEP dispatcher does not support padding yet, and our activation quantization kernel requires padding to 32 (or 128 for cutedsl), so we need to add that functionality.

- **TorchAO / TorchTitan split.** TorchTitan will maintain all workflows and only import kernels from TorchAO. For example, the autograd function `_MXFP8GroupedMMFwdBF16Bwd` is adapted from `_MXFP8GroupedMM` from TorchAO. TODO: we will likely replace this autograd function with a more FSDP-aware one following the MoE version of https://github.com/pytorch/torchtitan/pull/4203.
