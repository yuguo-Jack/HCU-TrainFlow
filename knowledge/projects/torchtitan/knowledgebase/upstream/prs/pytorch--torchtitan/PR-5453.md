# [rl] Verifiers generation server: no per-request access log (3/14)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5453) · state: open · merged: False

## Original PR description

**TLDR:** The Verifiers generation server logged one INFO line per generate call: 79-87% of the controller's log lines and ~6-9% of the controller thread's samples. `AppRunner(access_log=None)` turns it off.

**Stack** (14 PRs, merge bottom-up; this PR is in **bold**)

**Results**
```text
Terminal-Bench RL runs on GB300, controller log
aiohttp.access lines    79-87% of lines (4 runs)
                        1.7-2.0M lines, 334-386 MB (the two longest runs)

py-spy --gil, controller thread, 120 s, 10-node SWE RL run
access log + logging    ~6-9% of samples
```

You may ask:
- What about errors? Every response loses its access line, errors included. A `GenerateFn` exception still logs with `logger.exception`; other error responses reach the client, and failed rollouts log their reason.
- Where is per-call timing? Each generate call still gets a `generate` span in the controller's structured log.

**Test plan**
```bash
pytest tests/rl/unit_tests/cpu/test_verifiers.py -k generation_server
```
`test_generation_server_does_not_log_each_request` fails on main. It pins the `aiohttp.access` logger at INFO, since aiohttp skips the line above INFO and the inherited level depends on imports.
