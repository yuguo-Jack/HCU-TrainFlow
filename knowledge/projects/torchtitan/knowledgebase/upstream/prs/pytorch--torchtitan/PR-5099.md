# [chunked CE] Add opt-in Liger fused linear CE override

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5099) · state: open · merged: False

## Original PR description

## Summary

Add an opt-in recipe override that replaces TorchTitan's separate LM-head projection and chunked CE with Liger's fused linear-CE kernel. Liger chunks tokens internally, avoiding a full `[T, V]` logits tensor. The default TorchTitan path is unchanged and Liger remains an optional dependency.

## Usage

Install the optional dependency in the local or remote environment:

```bash
pip install -e ".[liger]"
```

Then enable both overrides:

```text
--override torchtitan_recipes.overrides.liger_fused_linear_cross_entropy.liger_fused_linear_cross_entropy_head
--override torchtitan_recipes.overrides.liger_fused_linear_cross_entropy.liger_fused_linear_cross_entropy_loss
```

Current requirements:

- `liger-kernel>=0.8.3` (installed by the `liger` extra)
- `training.disable_cuda_graphs = True`: Liger's current fused-linear-CE implementation is not CUDA Graph compatible
- standard Trainer, TP=1, and the stock dense `Linear` LM head
- the fused loss stays outside `torch.compile`; other local-compile regions may remain enabled

**CUDA Graph limitation:** Liger [`main`](https://github.com/linkedin/Liger-Kernel/blob/main/src/liger_kernel/ops/fused_linear_cross_entropy.py#L130-L143) still calls `.item()` on CUDA tensors in fused-linear-CE forward, which performs host synchronization during capture. A full H100 forward/backward capture fails with `cudaErrorStreamCaptureInvalidated`. This is why the override checks for active capture and requires CUDA graphs to be disabled.

## Why two override classes?

TorchTitan keeps the LM head and loss function as separate components, so the override provides one adapter for each:

- **`LigerFusedLinearCrossEntropyHead`** replaces `model.lm_head`, owns the LM-head weight, and remains the module seen by FSDP. With `target=labels`, it calls Liger; without a target, it behaves like the normal linear head and returns logits.
- **`LigerFusedLinearCrossEntropyLoss`** replaces the chunked loss wrapper. It receives hidden states, labels, and `global_loss_token_counts`, calls the paired head, and normalizes the summed loss. It owns no parameters and implements no CE kernel.

The Loss calls the Head, and the Head makes one Liger fused-linear-CE custom-autograd call. The two adapters do not execute two separate CE kernels.

## Training path

At initialization, the existing Trainer wiring connects the loss adapter to the model-owned head and makes the model return hidden states instead of full logits:

```text
Trainer builds model and loss
  -> loss.set_lm_head(model.lm_head)
  -> model._skip_lm_head = True
```

For each training microbatch:

```text
tokens -> model forward (LM head skipped) -> hidden states [T, H]
labels ------------------------------------------+
global_loss_token_counts ------------------------+
                                                  |
                                                  v
                         LigerFusedLinearCrossEntropyLoss
                         (TorchTitan loss adapter)
                                                  |
                         calls lm_head(hidden, target=labels)
                                                  |
                                                  v
                         LigerFusedLinearCrossEntropyHead
                         (owns W[V, H]; module/FSDP hooks run)
                                                  |
                         one Liger fused-linear-CE call
                                                  |
                         +-> split token rows internally
                         |   for each chunk:
                         |     logits_chunk = hidden_chunk @ W.T
                         |     CE + chunk gradients
                         |     release logits_chunk
                         |
                         +-> sum chunk losses
                         +-> accumulate dHidden and dW
                                                  |
                                                  v
                         loss_sum / global_loss_token_counts
                                                  |
                                                  v
                                             scalar loss
```

TorchTitan's outer `ChunkedLossWrapper.chunk_size` is not used on this path. Liger chooses its internal chunk size from T, H, V, and `chunk_mem_const`; no full `[T, V]` logits tensor is materialized.

## Liger kernel used

This uses the public [`liger_fused_linear_cross_entropy`](https://github.com/linkedin/Liger-Kernel/blob/e2039eb8c78328dbead94eea7c7c9e7f6850f9ff/src/liger_kernel/transformers/functional.py#L83-L127) wrapper, backed by [`LigerFusedLinearCrossEntropyFunction`](https://github.com/linkedin/Liger-Kernel/blob/e2039eb8c78328dbead94eea7c7c9e7f6850f9ff/src/liger_kernel/ops/fused_linear_cross_entropy.py#L51-L415).

That implementation fuses the linear projection with CE and chunks internally. It also accumulates weight gradients into one persistent buffer across chunks. This PR does **not** use the preference-training implementations under Liger's `src/liger_kernel/chunked_loss/` directory.

## Performance

The benchmark uses the same Qwen3-8B model shape as [#5178](https://github.com/pytorch/torchtitan/pull/5178): 8.19B parameters, 36 layers, `H=4096`, and `V=151936`. The end-to-end test uses FSDP8, TP1, PP1, BF16, selective activation checkpointing, `T/device=8192`, and 1024 tokens/chunk on 8xH100 96 GB. Local C4 test data and the test tokenizer supply inputs without changing model or loss shapes.

Both paths use the stock dense `Linear` LM head and disable CUDA graphs because those are requirements of the Liger override. Therefore, this comparison intentionally differs from #5178's `HiMidLoLinear` and CUDA-graph settings. It uses TorchTitan `c38f2a38e`, Liger `e2039eb8c78328dbead94eea7c7c9e7f6850f9ff`, and the same isolated PyTorch build as #5178 (`ccd8044a383a00dc90a696392f0085a56b2b63ee`). The benchmark recipe is local-only and is not included in this PR.

### Loss path

**Liger is 1.134x faster at 8192 tokens/device and 1.091x faster at 16384 tokens/device.** It also reduces incremental peak allocation by 40-44%.

Single H100 96 GB, BF16 Qwen3-8B LM-head shape, two runs per shape, 5 warmup and 20 measured forward/backward steps per run. The table reports the combined median of 40 measurements and incremental peak allocated memory. Each measurement includes LM-head forward, summed CE, valid-token normalization, and backward.

The baseline uses the listed `chunk_size`. Liger uses `chunk_mem_const=4`, which selects the same effective token chunk size for each shape.

| Tokens/device | Tokens/chunk | Path | Speedup | Median time | Memory reduction | Incremental peak |
| ---: | ---: | --- | ---: | ---: | ---: | ---: |
| 8192 | 1024 | chunked + local-compiled CE | 1.000x | 55.92 ms | - | 2.77 GiB |
| | | Liger fused linear CE | **1.134x** | 49.33 ms | **-1.230 GiB (-44.4%)** | 1.54 GiB |
| 16384 | 2048 | chunked + local-compiled CE | 1.000x | 99.48 ms | - | 3.20 GiB |
| | | Liger fused linear CE | **1.091x** | 91.18 ms | **-1.301 GiB (-40.7%)** | 1.90 GiB |

### End-to-end training

Each path ran twice for 50 training steps. The table combines steady-state steps 11-50 from both runs (80 samples/path).

| Path | Speedup | Active vs baseline | Reserved vs baseline | Median TPS/device | Median global TPS | Peak active/device | Peak reserved/device |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| chunked + local-compiled CE | 1.000x | - | - | 7,776 | 62,208 | 43.72 GiB | 50.74 GiB |
| Liger fused linear CE | **1.032x** | **-2.16 GiB (-4.94%)** | **-3.48 GiB (-6.85%)** | 8,022 | 64,177 | 41.56 GiB | 47.27 GiB |

Liger improves the isolated loss path by 13.4% at 8192 tokens/device and 9.1% at 16384 tokens/device. End-to-end throughput improves by 3.17%; the smaller gain is expected because transformer forward/backward, optimizer, and communication are unchanged.

## Numerics

All tests use identical BF16 inputs and initial weights with T=256, H=128, V=2048, seed 42, ignored labels, and 32-token chunks.

### Single forward/backward

| Comparison | Loss | Hidden grad | LM-head grad |
| --- | ---: | ---: | ---: |
| Compiled vs eager | 0 | 0 | 0 |
| Liger vs eager | 3.81e-6 | 1.22e-4 | 1.83e-4 |
| Liger vs compiled | 3.81e-6 | 1.22e-4 | 1.83e-4 |

### 20 AdamW LM-head steps

Loss and gradient values are maximum absolute differences across all 20 steps; final weight is measured after step 20.

| Comparison | Loss | Hidden grad | LM-head grad | Final LM-head weight |
| --- | ---: | ---: | ---: | ---: |
| Compiled vs eager | 3.81e-6 | 0 | 7.45e-9 | 0 |
| Liger vs eager | 1.04e-3 | 1.10e-3 | 7.63e-4 | 6.35e-3 |
| Liger vs compiled | 1.04e-3 | 1.10e-3 | 7.63e-4 | 6.35e-3 |

Relative to the maximum FP64 magnitude, the 20-step Liger-vs-eager differences are 0.0025% for loss, 3.74% for hidden gradients, 2.43% for LM-head gradients, and 0.13% for the final weight. All values pass the FP64 oracle gate (`target error <= 2 * BF16 eager error + BF16 rounding floor`), and an identical Liger rerun is bitwise identical. This checks loss-path parity, not training convergence.
