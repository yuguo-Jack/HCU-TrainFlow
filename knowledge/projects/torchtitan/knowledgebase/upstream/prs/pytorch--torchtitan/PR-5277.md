# Reorganize repo structure, dependencies, docs, and tests

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5277) · state: closed · merged: True

## Original PR description

## Why

The repo had grown organically: dependency lists had drifted (and two
`requirements.txt` files could not be installed), `import torchtitan.rl.<anything>`
pulled in vLLM (12.7 s), tests and docs were hard to navigate, and several
modules lived far from what they belong to. This PR reorganizes the tree so
each piece lives with its owner, without intended changes to training numerics.
It is a single bottom-of-stack PR against `main` so follow-ups (e.g. the
`generator.py` / `controller.py` refactor) can be stacked on top with `gh stack`.

## What changed

**Dependencies and environment**
- `pyproject.toml` reads dependencies and extras (`[dev]`, `[rl]`, `[vlm]`, `[flux]`) from the requirement files; per-folder `requirements.txt` files are symlinks (fixes broken `kimi_k3/` and `qwen3_5/requirements.txt`).
- `torch_checkpointing` is pinned to a git commit; PyPI 0.1.0 predates `default_resharder`.
- New `scripts/install_rl_env.sh` (nightlies, git-main deps, FlashAttention per GPU); the RL README and all RL workflows use it.

**RL**
- `torchtitan/rl/__init__.py` has no side effects: no vLLM import, no env mutation (import 12.7 s -> 29 ms). Entry points apply env defaults before importing torch.
- `generate.py` selects recipes with `--module/--config`, resolves relative `hf_assets_path` (it failed on every RL recipe before), and tears down vLLM's process groups on exit.
- `rl/types.py` removed; each type lives in the module that creates it.
- `rubric.py` and the envs move under `rollout/` (`message_env.py`, `token_env.py`); `distributed/actors/` -> `distributed/monarch_actors/`.
- vLLM linear-attention backend renamed to family-neutral `TorchTitanLinearAttention*`, with shared hybrid-state helpers for GDN/KDA.
- RL checkpoints download to `./assets/hf/` like pretraining.

**Core**
- `protocols/` -> `models/base/` (abstract contracts); `models/common/` keeps concrete components. `models/utils.py` split into `models/common/{moe_state_dict_adapter,flops}.py`.
- `hf_datasets/` merged into `components/data/`; `validate.py` -> `validator.py` (core and Flux).
- Shared GDN/KDA code moves to `attention/linear_attention.py` and `attention/cp_linear_attention.py`; GDN and KDA no longer import each other.
- Muse Glimmer renderer moves to `models/muse_glimmer/`.
- Flux: flattened `model/`, folded `configs.py`, `flux_datasets.py` -> `data.py`; `run_train.sh` gains `ENTRYPOINT=` and replaces `run_infer.sh`; fixed default paths that pointed at the removed `experiments/flux/`.
- The structured logger rejects an empty `output_dir` instead of writing into the launch directory; `ConfigLoader` no longer imports the RL controller.

**Tests**
- Unit tests mirror the source tree; RL and TorchFT tests that lived in the core suite move to their own suites.
- Integration suites keep their configurations next to their test definitions in `tests/integration_tests/`; one runner covers `features`, `models`, `flux`, `h100`, `b200`, `rl`, `rl_kda`, `rl_b200` via per-config entrypoints. CI call sites updated.
- `test_override.py` restores the global override registry (fixed order-dependent failures) and the workarounds other tests had for it are removed.

**Docs and layout**
- README revamp. Convention: `README.md` per package for usage, UPPERCASE design notes next to the code. New `distributed/README.md` and `PIPELINE_PARALLEL.md`; `converging.md`, `extension.md`, `composability.md` folded into `debugging.md`, model READMEs, the config README, and code docstrings.
- `RELEASE.md` at root, `docs/benchmarks/`, `scripts/multinode_trainer.slurm`, RL images under `assets/images/`.
- CODEOWNERS aligned for recipes/tests/scripts; `.claude` rules updated to the current layout.

RL `rl_kda` suite: `bit_wise/logprob_diff/max: 0` at every step.

## Testing

- `pre-commit run --all-files` clean; pyrefly 0 errors.
- CPU unit tests (core + RL + TorchFT): all pass except pre-existing, platform-specific failures (see below).
- GPU unit tests (1 and multi-GPU) and the GDN/KDA GPU tests pass except failures that reproduce on `main`.
- E2E: Llama 3 debug pretraining (1 and 4 GPUs), RL `rl_kda` suite through the unified runner, standalone vLLM generation with real Qwen3-0.6B weights, all suites build with unchanged test counts.

## Known issues (all reproduce on `main`)

- RL runs exit with code 134 at shutdown after all work completes (`torchmonarch` 0.7.0 PyO3 daemon thread + CPython 3.12 finalization).
- aarch64 only: 4 CPU tests fail because Inductor's CPU `flex_attention` lowering is unsupported there.
- GPU: `test_rope_compile`, two MXFP8 compile tests, and `test_fsdp_moe_sharding` fail on `main` too.
