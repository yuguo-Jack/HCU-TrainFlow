# [data] Add checkpoint-safe map-dataset global ordering

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5325) · state: open · merged: False

## Original PR description

## Agent details

Prepared with AI assistance.

Frozen indexed samples need stable global ordering independent of the data-
parallel degree. Reuse the indexed sharding helper and add opt-in strided
ownership after global ordering, repeating before slicing so uneven epochs
remain correct. Contiguous ownership remains the default; streaming sources
retain their existing source-level sharding.

Name the policy map_dataset_dp_sharding and save it with the Grain cursor.
Reject a changed policy before restoring iterator state; historical states
without the field use contiguous ownership. DP-degree-changing checkpoint
resume remains unsupported. Document independently sharded mixture children
and preserve Grain's contiguous-shard epoch behavior.

**Verdict: Approve -- please address the items below before merging.** Every finding from the earlier automated review is fixed at `a99f40b`. What's left is small deletions and the PR description.

**What this PR does.** It adds `GrainDataLoader.Config.map_dataset_dp_sharding = "strided"`. With it, local row `i` on DP rank `r` of a map-style graph (Single or Concat) reads global row `i * W + r`. Repetition happens before the slice, so this still holds across epochs when the dataset length isn't divisible by `W`. The setting is saved in the loader `state_dict`, and resuming with a different setting raises an error.

**Example.** 11 rows, `W = 2`, `repeat=True`, no shuffle. Rank 1's first 4 rows:
```text
contiguous: 6 7 8 9      (its shard is rows 6..10; it starts that shard over after 10)
strided:    1 3 5 7      (row 2*i + 1; the stride carries into epoch 2, where row 11 is row 0)
resume a contiguous checkpoint with strided -> ValueError (before: rank reads different rows, no error)
```

The core logic looks right to me. Strided mode calls `repeat()` before the `[r::W]` slice, so local index `i` on rank `r` maps to global index `i*W + r` across epoch boundaries. Grain's `ShuffleMapDataset` takes the epoch from `index // len`, so later epochs still reshuffle consistently on every rank. Pulling the two copies of the sharding code into `_shard_and_repeat` is a good cleanup. Contiguous stays the default, so existing runs and checkpoints keep their current order. Nothing below is a blocker, but #1 and #2 are worth fixing before merge.

#### 1. Name the field after what it applies to (agrees with @tianyu-l's inline comment)
`torchtitan/components/data/loader.py:78`: the option only affects map-style (indexed) graphs. `SingleDatasetConfig` with a `RandomAccessDataSource` and `DatasetConcatConfig` both go through `_shard_and_repeat`. Streaming sources reject `"strided"`. Possible names: `map_dataset_dp_sharding` or `indexed_dp_sharding`, used the same way in `DatasetIterationPolicy` and the README. The docstring could also say plainly that `"strided"` raises on streaming sources, rather than "streams use source sharding".

#### 2. Switching sharding mode on resume changes the data order without any error
`torchtitan/components/data/loader.py:166-183`: `state_dict()` saves `dp_world_size` and `load_state_dict()` rejects a mismatch, but `data_parallel_sharding` is not saved. If a run resumes with a different mode, `set_state()` still succeeds because the iterator state is just a position. The rank then reads a different set of samples, skipping some and repeating others, and nothing reports it. Since this setting decides which samples a rank owns, I suggest saving it next to `dp_world_size` and raising `ValueError` on mismatch. A missing key could be read as `"contiguous"` so old checkpoints still load.

#### 3. The PR's goal of ordering independent of DP degree doesn't cover resume yet
The motivation is "stable global ordering independent of the data-parallel degree". Strided ownership is what would let a run resume at a different DP degree, since the global position is `sum(local positions)`. However, `load_state_dict` still rejects any change to `dp_world_size`. I'd either add a `TODO(data-dp-resharding)` noting that strided mode is the starting point for that, or make the PR description and README say that only the order is DP-independent, not checkpoint resume.

#### 4. Behavior with `DatasetMixConfig`
- Map children of a mix each get strided sharding separately, and then `MapDataset.mix` combines them per rank. Interleaving the ranks does **not** rebuild a single global mixed stream. The README lists only Single/Concat, which is accurate, but a sentence saying the guarantee doesn't extend to mixes would prevent confusion.
- With `"strided"`, any mix that has a streaming child now raises. That fits "streams own their sharding", but it means the setting can't be used for mixed indexed+streaming graphs. Worth a line in the README.

#### 5. `DatasetIterationPolicy.__post_init__` (`types.py:121-125`)
- The `dp_rank`/`dp_world_size` bounds check is new behavior this feature doesn't need, which is close to the "no speculative defensive checks" guideline in CLAUDE.md. If you keep it, the error should include the actual values, e.g. `f"dp_rank={self.dp_rank} must be within [0, dp_world_size={self.dp_world_size})"`.
- The `data_parallel_sharding` value comes from user config. It would be better to validate it where the user sets it (in `GrainDataLoader.Config` or `GrainDataLoader.__init__`), and the message should include the bad value.

#### 6. A useful comment was dropped
The old `SingleDatasetConfig` code had: *"Grain preserves the epoch through sliced map indices, so the upstream shuffle uses seed + epoch on each repeat."* That's non-obvious and explains why contiguous mode can slice before `repeat()` and still reshuffle each epoch. I'd keep it in `_shard_and_repeat`'s contiguous branch, next to the strided explanation.

#### 7. README (`README.md:527-535`)
The "external indexed provider" paragraph (next-token alignment, padding, override mechanism) covers more than this PR changes, and it describes an integration this PR doesn't exercise. Consider moving it to the PR that adds such a provider, or shortening it to one sentence.

#### 8. Tests
The parametrized test covering reconstruction × shuffle × repeat × concat × DP={1,2,4} with an 11-row (non-divisible) corpus is good. Possible additions:
- A test at the `GrainDataLoader` level, so the path from `Config` to `DatasetIterationPolicy` is covered.
- A checkpoint round-trip in strided mode with `repeat=True` that crosses an epoch boundary, to confirm `get_state`/`set_state` work on the sliced, repeated dataset.
- If #2 is adopted, a test that resuming with a different mode is rejected.
- A test showing that a `DatasetConcatConfig` with a streaming child raises the "requires an indexed source" error. Right now that error fires before concat's own `TypeError`, which is fine, but nothing tests it.

#### Minor
- `_shard_and_repeat` keeps the `len(dataset) < dp_world_size` check for strided+repeat too. Strided+repeat could handle a tiny dataset, but keeping one rule for both modes is fine.

I couldn't run the unit tests or `pre-commit` here because running commands needs approval in this environment, so all of the above comes from reading the code.
