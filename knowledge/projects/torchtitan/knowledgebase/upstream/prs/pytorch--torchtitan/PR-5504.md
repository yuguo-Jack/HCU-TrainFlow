# [docs] Add the torchtitan logo to the README

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5504) · state: closed · merged: True

## Original PR description

## Summary

Replace the plain-text `# torchtitan` title at the top of `README.md` with the new torchtitan logo.

- A `<picture>` element with `prefers-color-scheme` sources (GitHub's documented pattern for theme-specific images) picks the white-"torch" logo for dark mode and the black-"torch" logo for light mode. The `<img>` fallback, used where `<picture>` isn't supported, is the light version with `alt="torchtitan"`.
- The logo sources live in `assets/images/logo/`: rectangle and square versions in both colorways. Only SVGs are checked in. Each is about 7 KB and scales to any size, and PNGs can be rendered from them when needed, so we avoid committing binary images to the git history.

## Known limitations

### The logo may not follow the GitHub theme

GitHub wraps the `<picture>` in a `<themed-picture>` element. Its script chooses the logo based only on the page's `<html data-color-mode>` attribute:

- `light` / `dark`: GitHub forces the matching `<source>`.
- `auto` ("Sync with system"): GitHub does nothing, so the browser's own `prefers-color-scheme` setting decides.

So the logo can mismatch the page in two cases:

- With "Sync with system", the logo follows the browser/OS setting, not the Day/Night themes chosen on GitHub. A dark Day theme with a light OS therefore shows the black logo on a dark page.
- With "Single theme -> Dark", we saw a page report `data-color-mode="light"`, which made the black logo show on a dark page.

This is GitHub-side behavior and affects every README that uses this pattern. The older `#gh-dark-mode-only` / `#gh-light-mode-only` image suffixes are no alternative, because GitHub's CSS for them keys on the same attribute. If this matters, the robust fix is a single logo variant that reads on both light and dark backgrounds.

### PyPI

`pyproject.toml` uses `README.md` as the PyPI long description, and PyPI can't resolve relative image paths. Until we change it, the PyPI page will show the alt text "torchtitan" instead of the logo. After this lands, a follow-up can point the `<img>` / `srcset` URLs at `https://raw.githubusercontent.com/pytorch/torchtitan/main/assets/images/logo/...` so the logo also shows on PyPI.

## Test plan

- `pre-commit run --files README.md assets/images/logo/*` passes, including lychee.
- I loaded the branch README (`/blob/readme-logo/README.md`), the branch landing page (`/tree/readme-logo`) and this PR's "Files changed" rich diff in headless Chromium with the browser set to light. With `<html data-color-mode="dark">`, GitHub's script selected the white logo on all three pages.
