# Propagate peer-result drain failures (#5716)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5716) · state: closed · merged: True

## Original PR description

Summary:

The rank-0 `RequestDispatcher` resolves peer DP results in a background task. If receiving or resolving one of those results raises, the task used to die independently while the engine loop kept running. Outstanding peer generations and later calls could then wait forever because no code observed that failure.

Pass an `on_background_failure` callback into `RequestDispatcher.setup`. On rank 0, the callback atomically closes the engine-loop queue with a `ResultDrainFailureMessage`. Closing the queue wakes an idle engine loop, rejects later endpoint calls, and raises the original drain exception from the main loop. The existing engine-loop crash cleanup then fails outstanding generations, pending loads, and queued calls before releasing resources.

Add a regression test that injects an unknown peer completion to crash the drain task. It verifies that the outstanding generation and `EngineLoop.wait` receive the original `KeyError`, while a later `generate` call is rejected immediately instead of hanging.

**Verdict: Approve** -- this fixes a real hang on `main` (the removed TODO in `_rank0_drain_results` describes it) at the right layer: it reuses the engine loop's existing crash cleanup and adds no new mechanism. A maintainer still needs to review.

**What this PR does.** On rank 0, the peer-result drain task used to die on its own, and nothing watched it. Now, when it raises, it calls a callback that closes the engine-loop queue with a `ResultDrainFailureMessage`. That message wakes `_decide_next_action`, which re-raises the original exception inside `_run`. From there, the existing `except` path fails outstanding generations, pending loads, and queued calls.

**Example.** DP=2, rank 0 has `r0` outstanding on DP rank 1, and the peer reports a finished `"unknown"` id.
```
before: drain task: pop("unknown") -> KeyError, task dies quietly
        r0's generate() and every later peer result wait forever
        wait() never returns
after:  drain task -> queue.close(ResultDrainFailureMessage(KeyError))
        _decide_next_action raises KeyError -> _run except path
        r0 raises KeyError, wait() raises KeyError,
        later generate() raises "generator is closed" immediately
```
Peer ranks stay blocked in the decision broadcast. That is already the case for any rank-0 crash, and `InterGeneratorRouter.wait_engine_loop` handles it by raising as soon as one rank crashes.

### Should consider
- `torchtitan/rl/generator/dispatcher.py:322` -- if `close()` already closed the queue, the drain failure is swallowed without a log line. Log it before calling the callback.
- `tests/rl/unit_tests/cpu/test_engine_loop.py:1270` -- fold this into the parametrized `test_drain_task_resolves_peer_results_on_the_engine_thread` instead of copying its setup.
- `torchtitan/rl/generator/engine_loop.py:402` -- one name for the concept (`on_background_failure` / `_rank0_dispatcher_failed` / `ResultDrainFailureMessage`).

<details><summary>Details</summary>

Ordering and cleanup checks (verified by reading the code):
- `EngineLoopQueue.close` queues the failure message behind any message already put. `_decide_next_action` registers earlier `GenerationMessage`s (or appends loads to `pending_load_messages`) before it reaches the failure message and raises, and the `except` in `_run` fails all of them (`fail_outstanding_generations`, `_fail_loads`). Nothing can be put after the close.
- Skipping `ResultDrainFailureMessage` in `_rank0_close_and_fail_queue` is needed. If the drain fails and then the engine step crashes before the next decision, the failure message is still on the queue and has no `reply`.
- With outstanding generations, the loop drains the queue with `get_nowait` on every decision. When idle, it waits on `queue.get()`. The failure surfaces in both cases.
- After the loop exits, `shutdown()` cancels the drain task. `CancelledError` is a `BaseException`, so the new `except Exception` doesn't catch it and the callback doesn't run.

</details>

- claude[bot] · comment · 2026-10-31T23:23:01Z · [source](https://github.com/pytorch/torchtitan/pull/5716#discussion_r4433670876)

File: `torchtitan/rl/generator/dispatcher.py` · line 325

If the queue is already closed when the drain fails, the failure is lost without a trace. Say `close()` has queued its `CloseMessage` and the drain hits an unknown id before the loop gets to it: `EngineLoopQueue.close` returns early, the loop exits on CLOSE, and `shutdown()` swallows the task's exception (`except (asyncio.CancelledError, Exception): pass`). The outstanding callers get "generator closed before the request finished", and the `KeyError` is never logged. That KeyError points to a real bookkeeping bug (a peer reporting an id rank 0 doesn't track), so it should always show up in the logs. One line fixes it:

```suggestion
        except Exception as exc:
            logger.exception("rank 0 result drain task failed")
            on_background_failure(exc)
            raise
```

(Another option is to log non-cancellation exceptions in `shutdown` instead of passing.)
