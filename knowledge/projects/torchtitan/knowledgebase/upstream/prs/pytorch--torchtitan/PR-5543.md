## Original PR description

# [MoE] Apply router scores before W2 projection

Supersedes #4095: same motivation, reworked so the combine of every dispatcher is one never-replayed remat region and the router scores are absorbed before W2.

## Motivation

Current `RoutedExperts` applies router scores to each routed expert output after the W2 projection in `TokenDispatcher.combine`:

```
routed_output_RD = (
    routed_output_RD.to(torch.float32)
    * metadata.topk_scores_experts_sorted_N.reshape(-1, 1)
).to(routed_output_RD.dtype)
```

This multiplication causes the post-W2 `routed_output_RD` to retain for backward. Because W2 is linear, the router score can be applied earlier to the SwiGLU activation, immediately before W2:

```
routed_output_RD
 = W2(h_RF) * routed_score_R # current impl
 = W2(h_RF * routed_score_R) # our proposal
```


See the diagram below:

<img width="4444" height="5508" alt="image" src="https://github.com/user-attachments/assets/6f4e5155-6cfb-455f-925f-8d9165899666" />

### Expected memory gain in full model:
Combine output: `T * D * 2 = 4096 * 7168 * 2 = 56.0 MiB` per layer, `* 58 layers = 3.17 GiB`

W2 output: `(T * top_k) * D * 2 = 4096 * 8 * 7168 * 2 = 448.0 MiB` per layer, `* 58 layers = 25.4 GiB`

Total per GPU: `25.4 + 3.17 = 28.6 GiB`

### Expected recomputation gain in FullAC

None added: the w2 grouped GEMM still replays exactly once per MoE layer, and the combine is a never-replayed region whose body (score multiply, unpermute, combine communication) runs only on the original forward. Measured on the debug model under FullAC, the replay path also rebuilds fewer saves (15 -> 5 per forward at EP=1), because the absorbed combine is a pure reduction that saves fewer tensors.

## Implementation

The dispatcher returns the per-row router scores in its dispatch metadata, `GroupedLinear.forward(..., routed_scores_R=...)` scales W2's input in float32 before the grouped GEMM, and combine reduces to a plain sum.

Config:

- `make_routed_experts_config(absorb_router_scores: bool | None = None)` forwards the flag to the
  standard `AllToAllTokenDispatcher.Config`. `None` (auto) resolves at build time in
  `RoutedExperts.__init__` to "absorb unless the experts carry an `output_postprocess`".
- DeepEP/HybridEP stay opt-in: `TokenDispatcherTransform(dispatcher=..., kwargs={"absorb_router_scores": True})`;
  their fused combines apply scores themselves, so they default to `False`.
- `swap_token_dispatcher` (quantization) carries the flag across dispatcher swaps.

Dispatcher:

- Standard path: the dispatch remat region exchanges the scores alongside the tokens (same
  all-to-all splits), gathers them expert-major with the same `permuted_indices`, and returns them
  as `routed_scores_R` in the metadata (`None` when not absorbing -- `torch_remat.region` supports
  `None` tuple leaves). TorchAO overrides the gather to zero-fill padded rows.
- `combine` skips the score multiply when the scores were absorbed (`_score_and_scatter_add` takes
  `topk_scores_N: Tensor | None`).
- DeepEP/HybridEP: `dispatch` takes the tracked scores out of the backend state and clears them, so
  the fused combine applies no score; the scores ride `EPDispatchMetadata.routed_scores_R`.

W2:

- `GroupedLinear.forward(..., routed_scores_R=None)` scales the input in float32 and casts back
  before the grouped GEMM; `GptOssGroupedLinear` scales its post-W2 bias rows the same way.
- `RoutedExperts` rejects `output_postprocess` + absorption (post-W2 postprocess must see unscaled
  outputs) and resolves auto at build time.

## Remat

The combine of every dispatcher is one never-replayed `<fqn>.combine` region whose body reads the
w2 output (score multiply where not absorbed, unpermute/scatter-add, combine communication).
Consequences:

- Nothing on the replay path reads the w2 or combine outputs, so no `recompute_needs_tensor`
  marker pins the w2 output anymore. The earlier design durably packed it on the remat tape
  (reported as SAVE_OUTPUT) and re-ran multiply + unpermute on replay; with absorbed scores the
  w2 output is now freed after the forward instead of being retained for backward (the
  scatter-add saves only indices).
- With absorbed scores the combine is a pure reduction: the region saves only the permutation
  indices (plus the scores when not absorbing).
- The standard backends' absorbed scores are an output of the saved dispatch region, so W2's bare
  input scaling marks them with `recompute_needs_tensor`; that marker is a no-op on the
  DeepEP/HybridEP paths and without an active checkpoint.
- Dispatch keeps following the remat policy everywhere; only the combine is always saved.

### HybridEP dispatcher

Same mechanism as DeepEP: dispatch takes the per-row scores the HybridEP backend tracks and
clears them from the dispatch state, so `hybridep.combine_tokens` skips its fused multiply and the
scores ride `EPDispatchMetadata.routed_scores_R`. Opt-in like DeepEP. No separate A/B run: the
HybridEP buffer is GB200/NVLink72-only.

## Tests and verifications

- fp64 parity, standard dispatchers (`tests/unit_tests/gpu/distributed/test_standard_dispatchers_absorb_router_scores.py`,
  GPU, world 2): local, all-to-all at EP=1 (local fallback) and EP=2, TorchAO at EP=1 (padded
  permute, zero-sentinel scores) and EP=2. With rounding gone, the absorbed and post-combine
  paths compute the same function, so a dropped, doubled or misaligned score is an O(1) error;
  loss and every input/parameter gradient are asserted at the float32 scale W2's input scaling
  applies (rtol 1e-5).
- fp64 parity, DeepEP (`tests/unit_tests/cpu/distributed/test_deepep_absorb_router_scores.py`,
  CPU, gloo, world 2): the deep_ep kernels are bf16-only, so the test stubs `ElasticBuffer` with
  a pure-PyTorch implementation (all_gather + local selection, deterministic layout,
  autograd-correct dispatch/combine backward) and runs the dispatcher, the torchtitan deepep
  wrapper, its custom ops and their autograd in float64. Same assertions; verified to fail on
  double-applied and on misaligned (rolled) scores.
- Remat (CPU, `tests/unit_tests/cpu/models/common/test_token_dispatcher.py`): the combine body
  runs exactly once under every policy while the w2 projection's replay still follows the policy;
  with absorbed scores and w2 saved, the w2 output storage is freed after the forward; loss and
  grads match the un-checkpointed run bitwise.
- Remat dumps for the local/all2all/deepep dispatchers: the A/B reports above.

# Verification reports

- [x] Local (CPU, real `torch_remat` + `RegionAC`): absorb vs post-combine scoring are numerically
      equivalent (rel diff ~0.25% = bf16 rounding); gradients flow to the scores in the absorbed path.
- [x] Local fake-EP harness exercises the real AllToAll `dispatch`/`combine` regions: backward clean,
      `w2.grouped_mm` retains nothing with bf16 params, combine retains indices only, backward runs
      exactly one grouped GEMM (the w13 replay).
- [x] GPU debugmodel A/B above: w2 output and combine output rows removed from
      `format_saved_tensors_report`.
- [x] fp64 parity between the absorbed and post-combine versions: the standard dispatchers (GPU) and
      DeepEP through a pure-PyTorch `deep_ep` stub (CPU) agree in loss and all gradients at the
      float32 scale the absorb path applies (~1e-7 relative; asserted at rtol 1e-5). The DeepEP test
      fails on double-applied and on misaligned scores.
- [x] remat dumps for local/all2all/deepep dispatchers.
- [ ] Loss convergence on a representative dataset (e.g. C4) at equal steps, absorbed vs baseline.

## FusedMOE
The fused MoE path is an optional, SM100+-only backend that only activates when explicitly selected, so on every path we actually run (all-to-all / DeepEP / HybridEP) this optimization applies unchanged — and even when selected, it replaces the module wholesale and is unaffected rather than broken.
