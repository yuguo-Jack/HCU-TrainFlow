# [observability] Skip the PP loss-visibility hint when LOG_RANK is unset

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5724) · state: closed · merged: True

## Original PR description

## Summary (human-written)
<!-- Write this yourself, not with an AI tool. 2-5 sentences: the problem, why
     this approach, and what you checked yourself. -->
     
**Problem:** ensure_pp_loss_visible warns on every rank when LOG_RANK is unset (slurm or plain torchrun launches). On those launches nothing filters the console and every rank already prints the loss.
**Approach**: return early when LOG_RANK is unset or empty, and keep the hint for run_train.sh runs.
**What I checked:** the new test fails on main for unset and empty and passes with the fix, and 212 related tests pass.

## Why
`ensure_pp_loss_visible` warns whenever the loss rank is missing from `LOG_RANK`, and that includes the case where `LOG_RANK` is not set at all. `LOG_RANK` only has an effect through `run_train.sh`, which always exports it (default `0`) and passes it to torchrun as `--local-ranks-filter`. Launches that do not set it, such as the repo's own `scripts/multinode_trainer.slurm` or a plain `torchrun`, apply no console filter, so every rank already prints the loss. On those runs every rank still logs a warning that the loss is not visible and points at `run_train.sh`, which the job does not use.

**Example.** 1F1B with `world_size=8`, `pp=2` (loss on rank 4):

| `LOG_RANK` | Before | After |
| --- | --- | --- |
| unset or empty | warns "add rank 4 to LOG_RANK" on every rank | no warning |
| `0` | warns | warns (unchanged) |
| `0,4` | no warning | no warning (unchanged) |

## What changed
- `torchtitan/observability/metrics.py`: `ensure_pp_loss_visible` returns early when `LOG_RANK` is unset or empty. The check for a set `LOG_RANK` and the V-schedule early return are unchanged.
- `tests/unit_tests/cpu/observability/test_metrics_rank.py`: one parametrized test for the hint (unset, empty, `0`, `0,4`).

## Alternatives considered
- Deleting the hint: it is still useful for single-node `run_train.sh` runs, where the default `LOG_RANK=0` hides the loss under PP.
- Also translating the global loss rank to a local rank for multi-node filters: separate concern, and no in-repo launcher sets `LOG_RANK` on more than one node. Happy to follow up if wanted.

## Testing
- `pytest tests/unit_tests/cpu/observability/test_metrics_rank.py`: 8 passed. On `main` the unset and empty cases fail (2 failed, 6 passed) because the warning is logged. The new test catches the hint firing again when no filter is configured, and also pins the existing behavior for a filter that omits or includes the loss rank.
- `pytest tests/unit_tests/cpu/observability tests/unit_tests/cpu/test_trainer.py`: 212 passed, 1 skipped (CPU, torch nightly CPU wheel).
- `pre-commit run` on the changed files: all hooks pass.

**What this PR does.** `ensure_pp_loss_visible` (called from `trainer.py:233` and `experiments/torchft/trainer.py:269` on every rank when PP is on) used to treat an unset `LOG_RANK` as an empty filter, so it warned. The only launchers in the repo that filter console output are `run_train.sh:29,50` and `graph_trainer/run_train_precompile.sh:18,25`, and both always export `LOG_RANK` and pass it as `--local-ranks-filter`. `scripts/multinode_trainer.slurm:63` calls `torchrun` without a filter, so every rank already prints the loss. The PR returns early when `LOG_RANK` is unset or empty.

**Example.** `torchrun --nproc_per_node 8 -m torchtitan.train ...` with `pp=2`, 1F1B (loss computed on rank 4), `LOG_RANK` unset:
```

        (rank 4 is already printing the loss)
after:  no warning
LOG_RANK=0 ./run_train.sh   -> still warns (unchanged)
LOG_RANK=0,4 ./run_train.sh -> no warning (unchanged)
```

Add that it does nothing when `LOG_RANK` is unset (no console filter), so the docstring matches the new early return.
