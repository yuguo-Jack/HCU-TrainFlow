# Run full Terminal-Bench CPU coverage (#5700)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5700) · state: closed · merged: True

## Original PR description

Summary:

## Why this change is needed

The optional Verifiers phase of the RL CPU workflow installs only the DAPO-Math requirements and selects a single test from `test_verifiers_terminal_bench.py`: `test_env_server_workers_skip_the_trainer_imports`. The rest of that module and the entire `test_verifiers_terminal_bench_prepare_tmax.py` module are absent from the selection. Terminal-Bench's Harbor dependency is also missing from this installation step.

This leaves existing CPU checks for the Terminal-Bench recipe, harness configuration, task datasets, and TMax task conversion outside the workflow's intended coverage. Some checks depend on Harbor and can skip when it is unavailable. A successful workflow therefore gives incomplete evidence that changes preserve Terminal-Bench behavior, allowing regressions in these paths to go undetected.

## How the workflow changes

1. Install `torchtitan/rl/examples/verifiers/terminal_bench/requirements.txt` alongside the existing DAPO-Math requirements. This reuses the recipe's pinned `verifiers==0.4.0` and `harbor==0.24.0` dependencies instead of duplicating package versions in the workflow.
2. Apply the existing nightly constraint file to that combined installation. The optional dependencies must remain compatible with the torch, torchvision, and vLLM versions installed earlier by `scripts/install_rl_env.sh`.
3. Run `pytest tests/rl/unit_tests/cpu --strict-markers --durations=20 -vv` after installing the optional dependencies. Pytest discovers every CPU test module, including both Terminal-Bench modules, so new tests are picked up without maintaining a list of filenames. Retain the existing first directory-wide pass to test the base RL environment before Verifiers changes its pinned dependencies; the second pass also checks the base tests with Verifiers and Harbor installed.

## What this adds to CI coverage

- Terminal-Bench harness options and taskset resolution, including resolution in a fresh interpreter.
- Environment workers avoiding trainer imports, separate training and evaluation datasets, and recipe settings for model parallelism, FP32 weights, context bounds, and turn limits.
- TMax parquet-to-task conversion using synthetic input, including filtering, content preservation, repeated conversion behavior, and loading converted tasks through Harbor's parser.

These are existing CPU tests and do not require GPU training or Docker sandbox task execution. The patch changes only the CI workflow. Its operational cost is installing Harbor and repeating the CPU suite with the optional dependencies installed. The first CI pass took about 45 seconds; the complete second-pass runtime still needs to be measured.

## Validation and remaining work

Local YAML parsing, shell syntax validation, lint, and dependency consistency checks passed. The independent Verifiers bridge module and the full TMax converter module passed together: **25 tests, no skips**, including the Harbor parser check.

The complete workflow selection was attempted but could not finish collection because the local TorchStore mirror lacks `RankRole`. CI installs TorchStore from Git main, so the full recipe and harness selection still needs validation in that environment. `pre-commit run --all-files` was also attempted and could not run because it requires a Git checkout; this checkout uses Sapling.

GitHub export completed for the linked PR. Export Status, Meta CLA, Meta Import, and Meta Internal-Only Changes checks passed. The first RL CPU pass failed in an existing alphabet-sort recipe with a `TrainingConfig` constructor error for `disable_cuda_graphs`, before the optional-dependency installation and second test pass. The first pass and relevant recipe/config files match the base revision. Full optional-dependency coverage remains unverified while that failure is unresolved.

This is @tianyu-l's point, and it can be done without listing any files. Every Verifiers module already guards itself with `pytest.importorskip("verifiers")` (and `importorskip("harbor")` / `importorskip("pyarrow.parquet")` where it needs them). `test_model_defaults` also skips the `verifiers_*` recipe params when `verifiers` is missing. So after this install step, a second run of the whole folder picks up all of them, plus any Verifiers test added later.

It's cheap: the full folder took 45s in this PR's CI run (`502 passed, 9 skipped in 45.15s`). Running it again also checks the rest of the suite against the dependencies Verifiers moved, which is the reason this phase runs second. A hand-picked list also lets a new `test_verifiers_*.py` file silently skip forever, and it has already done that once (only one Terminal-Bench test was selected).

```suggestion
        pytest tests/rl/unit_tests/cpu --strict-markers --durations=20 -vv
```

If 45s is too much, use `-k verifiers` instead. It matches the four `test_verifiers*.py` modules and the two `test_rl_recipes_get_model_defaults[...verifiers_*]` params.
