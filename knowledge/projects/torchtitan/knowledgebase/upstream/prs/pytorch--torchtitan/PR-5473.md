# [rl] Print validation reward on the console by default

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5473) · state: open · merged: False

## Original PR description

**TLDR:** By default the validation console line never shows the validation reward, because it looks up `validation/reward/_mean` but the key is `validation_reward/_mean`. This PR renames the two default patterns.

**Problem**
1. `compute_rollout_metrics(prefix="validation")` logs the reward as `validation_reward`, with sub-keys `validation_reward/_mean`, `validation_reward/_max` and so on.
2. `MetricsProcessor.Config.console_log_keys_validation` defaults to `validation/reward/_mean` and `validation/reward/_max`, which match no key.
3. Recipes that keep the default (alphabet_sort, search_r1) print no reward on the validation console line. The recipes that set their own list already use `validation_reward/_mean`.

**Solution**
1. Rename the two default patterns to `validation_reward/_mean` and `validation_reward/_max`.
2. The other defaults (`validation/response_length/mean`, `timing/validate`) already match their keys and don't change.

**Results**
`MetricsProcessor.log(is_validation=True)` on `compute_rollout_metrics` output for 2 rollouts with rewards 1 and 0:
```
before: Validation | Step:  0  timing/validate: 1.50
after:  Validation | Step:  0  validation_reward/_mean: 0.50  validation_reward/_max: 1.0  timing/validate: 1.50
```

**Test plan**
- `pytest tests/rl/unit_tests/cpu/test_metrics.py`: 81 passed.

- `pre-commit run` on the changed file.
