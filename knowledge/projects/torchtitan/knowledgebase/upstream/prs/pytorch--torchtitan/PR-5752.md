# [moe] AllToAll dispatcher: add non_blocking_capacity_factor for fixed-shape dispatch with no host sync

## Why

`AllToAllTokenDispatcher` copies the per-rank token counts to the host before every dispatch all-to-all (`_sync_token_count_exchange`), and the routed-token shapes change on every step. On `main`:

- Accelerator graphs support expert parallelism only with HybridEP and its `non_blocking_capacity_factor` (`torchtitan/config/validation.py`). HybridEP needs DeepEP kernels, so a backend or GPU without them cannot capture EP.
- A backend that compiles one graph for each tensor shape compiles new shapes on every step, and syncs with the host in every MoE layer.

**Example.** DeepSeek-V3 debug model, FSDP 4 + EP 4, 4 AWS Neuron, seed 42: on the first run, most of the dynamic-split step time is compilation of new routed-token shapes, and a step is about 300x slower than with `non_blocking_capacity_factor=1.0`. On a rerun with the same seed and data, every shape is in the compile cache, and the fixed-capacity steps are still about 4x to 5x faster. The fixed-capacity path compiles once.

```python
for _, dispatcher, _, _ in config.model.traverse(AllToAllTokenDispatcher.Config):
    dispatcher.non_blocking_capacity_factor = 1.0
```

## What changed

- `AllToAllTokenDispatcher.Config.non_blocking_capacity_factor: float | None = None`. With `None`, the dispatcher is unchanged. With a factor in (0, 1], each rank sends `C = ceil(T * min(num_local_experts, top_k) * factor)` rows to every EP rank:

  ```text
  send (rank r):  [C slots for EP rank 0][C slots for EP rank 1]...  the kept routes in expert-sorted order, then zero rows
  counts:         kept routes per (EP rank, local expert), all-to-all as device data
  tokens:         all-to-all with equal splits [C] * ep_size
  receive:        sort (source, slot) to (local expert, source) order, zero rows last
  experts:        the grouped GEMM offsets end before the zero rows
  combine:        unsort, equal-split all-to-all back, select out the zero rows, score, scatter-add
  ```

- `ep_size * C` is the receive capacity that HybridEP sizes with the same factor. With 1.0, no route drops. When more than `C` routes go to one EP rank, the routes to its highest local experts drop first. A dropped route skips that expert only: the token keeps its other experts, the shared experts, and the residual.
- A drop sets a sticky device-side flag, `check_all_to_all_over_budget()` (cleared by `reset_all_to_all_over_budget()`), like HybridEP's `check_hybridep_over_budget()`. The graph_trainer paged-stash runner reads it next to the HybridEP flag, so a drop in either dispatcher counts as over budget.
- The mode uses the same remat regions (`<fqn>.dispatch`, `<fqn>.combine`), the same count and token exchanges, and the same `_local_reorder` and `_score_and_scatter_add` as the dynamic path.
- Accelerator-graph validation accepts `AllToAllTokenDispatcher` with the factor set. The `disable_accelerator_graphs` docstring says so.
- `TorchAOTokenDispatcher` has its own padded permute and does not implement this mode, so it raises if the factor is set.

## Alternatives considered

- HybridEP `non_blocking_capacity_factor`: needs DeepEP kernels.
- Round the dynamic splits up to a few bucket sizes: still needs the host sync to pick the bucket.
- A new dispatcher class: the mode shares the exchanges, the remat regions, and the reorder with `AllToAllTokenDispatcher`.
- A capacity for each expert, as in Megatron-LM's `moe_pad_expert_input_to_capacity`: a busy expert drops routes even when its EP rank has free slots.
- Drop the lowest-scoring routes (Megatron-LM's default `moe_token_drop_policy="probs"`) or the routes of the latest tokens (`"position"`): on Neuron eager, the extra small ops in every dispatch make a step about 10% and 5% slower, also when no route drops. The drop flag shows when a run drops routes, so a larger factor can remove the drops instead.

## Numerics

- CPU, 4 gloo ranks, stand-in experts that scale each row by its global expert ID + 1: with factor 1.0, the output, input gradient, and score gradient are bitwise equal to `LocalTokenDispatcher`, in fp32 and bf16. The fixed-capacity path visits the routes in the same order, and the zero rows add exact zeros.
- AWS Neuron, DeepSeek-V3 debug model, FSDP 4 + EP 4, seed 42, 4 steps: the loss with factor 1.0 matches the dynamic splits within 1e-4 relative at every step.

## Performance

Moonlight 16B-A3B (the Kimi K2.7 recipe's text tower), first 4 layers, FSDP 8, 8 AWS Neuron, seed 42, 10 steps:

- EP 8 with factor 0.25 is about 1.6x faster per step than FSDP 8 without EP, and uses about 45% less memory. Factor 0.25 is 2x the mean routes for each destination.
- The loss of EP 8 with factor 0.25 stays within 2e-4 relative of FSDP 8 without EP at every step. The step-1 losses already differ, before any update.
- Factor 1.0 sizes every destination for the worst case, so each rank receives 8x the routed rows. At this size, its all-to-all buffers do not fit.
- The drop flag adds no measurable step time: with and without it, a step takes the same time within 3%.

- `test_full_capacity_matches_local_dispatch`: with factor 1.0, the output, input gradient, and score gradient are bitwise equal to `LocalTokenDispatcher` (fp32 and bf16), and the drop flag stays unset. A source-major receive order fails it, and so does a combine without the zero-row mask.

- `test_only_capacity_dispatch_needs_no_host_sync`: runs dispatch, combine, and backward under `FakeTensorMode` with a fake process group, where a host read raises, with factor 1.0 and 0.25. The dynamic path raises in the same check.
