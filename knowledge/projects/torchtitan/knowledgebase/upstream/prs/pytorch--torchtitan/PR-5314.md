# [scripts] Point helper entry points at real modules and fields

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5314) · state: closed · merged: True

## Original PR description

## Summary

Three documented script entry points fail before they do any work. They are together because each one dies at startup, and none shares a file with an open PR.

- `scripts/checkpoint_conversion/numerical_tests_example.py` is the command in `scripts/checkpoint_conversion/README.md`. It loaded module `llama3`, which is not importable. `llama3_8b` is `torchtitan_recipes.models.llama3.llama3_8b`. The next line called `HuggingFaceTokenizer(config.hf_assets_path)`, but `tokenizer_path` is keyword-only, so that raises `TypeError`.
- `scripts/_checkpoint_test_config.py` is the recipe used by `python scripts/checkpoint_compat_test.py HEAD~1 HEAD`. The save step sets `TORCHTITAN_TEST_LR_TOTAL_STEPS` and the generated recipe assigned `trainer_config.lr_scheduler.total_steps`. `Trainer.Config` has no `lr_scheduler`. The field is `optim.lr_scheduler.total_steps`. The same path is used when the recipe is a `Controller.Config`, because `config.trainer` is a `Trainer.Config`.
- `scripts/rl/loss_compare.py` adds the checkout to `sys.path` so it can import `scripts.loss_compare`. The file is `scripts/rl/loss_compare.py`, so the root is two parents up. Three parents is the directory that contains the checkout, and the import raises `ModuleNotFoundError`.

## Test plan

- [ ] CPU: `tests/unit_tests/cpu/scripts/test_script_entrypoints.py` checks the scheduler assignment, the RL repo root, and the numerical-example module plus tokenizer call.
