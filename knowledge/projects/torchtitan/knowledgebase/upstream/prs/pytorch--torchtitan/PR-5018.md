# [rl] Require FA4 >= 4.0.0b34 for head_dim 256 split-KV decode

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5018) · state: closed · merged: True

## Original PR description

**TLDR:** RL now requires FA4 >= 4.0.0b34, the first release that splits head_dim 256 paged KV during decode. Qwen3.5 single-sequence decode on GB300: 279 -> 50 us per attention call at 32k context.

**Problem**
1. Qwen3.5's softmax-attention layers use head_dim 256, and the generator decodes them over a paged KV cache.
2. With one sequence, a decode call fills only a few SMs unless FA4 splits the KV across SMs (split-KV).
3. FA4 b33 asserts when it splits head_dim 256 paged KV at Qwen3.5's 16-token pages, and at 128-token pages its split is slower at batch 32.
4. b34 runs head_dim 256 on FA4's general forward kernel, which splits at any page size.

**Solution**
1. Bump the FA4 minimum to 4.0.0b34 in `torchtitan/rl/README.md` and the RL B200/H100 workflows.
2. Drop the README's apache-tvm-ffi caveat: b34 accepts vLLM's `apache-tvm-ffi==0.1.11`.
3. No code change: in the cu132 nightlies RL CI uses, torch's `varlen_attn` lets FA4 choose the split count when `num_splits` is unset.

**Results**
GB300, one decode call, 16 q / 4 kv heads, head_dim 256, 128-token pages, CUDA-graph replay, cold L2, us. One split vs FA4's own split count, measured on FA4 main just before b34:
```
bs1  x 8k     78.3 -> 29.2
bs1  x 32k   279.0 -> 50.3
```

**Test plan**
- b34 wheel, `num_splits=-1`, paged head_dim 256 decode: 16-token pages at bs1 x 32k and bs32 x 8k, 24 q heads at bs1 x 32k, and 128-token pages at bs32 x 8k all run and match an fp32 reference (max abs error 0.9-3.3e-4).
- RL B200/H100 CI.
