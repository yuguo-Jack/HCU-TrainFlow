## Human Note

## Agent Notes

The shared `RMSNorm` (used by llama3, qwen3, deepseek, kimi, gpt_oss, flux, ...) had no compile
region, unlike `offset_rmsnorm` (qwen3_5) and `muse_spark_rmsnorm`. Eager `F.rms_norm` runs ATen's
layer-norm kernels: one forward kernel and separate input-grad and weight-grad backward kernels. In
the decision recipe below this PR (Qwen3-1.7B, 32K-token microbatches), those kernels were about 18% of
GPU time in a profiler trace.

This adds `@local_compile("rmsnorm", batch_invariant=False, recompile_limit=16)` to
`RMSNorm.forward`. It is opt-in: no model's default `local_compile_regions` changes, and with the region
off the forward is the same `F.rms_norm(input, normalized_shape, weight, eps)` that `nn.RMSNorm.forward`
calls. Subclasses that override `forward` (muse_spark, muse_glimmer) are unaffected. The limit is 16
like the sibling norm regions, because every norm shape in a model shares the region. The decision
recipe opts in.

Open question: should Qwen3 (or other dense models) enable it by default? That changes numerics
(compiled reduction order), so it is left for a separate change with a loss comparison.

## Performance

Decision recipe, 1 GB300, 80 steps, mean tokens/s over steps 21-80 (higher is better), back-to-back on
the same idle GPU:

| config | tokens/s |
|---|---|
| recipe without the region | 105.5K |
| recipe with `rmsnorm` enabled | 116.2K (+10%) |

No recompiles logged. In the trace, the eager norm kernels (fwd + two bwd, including activation
recompute in that run) were replaced by one fused Triton kernel per direction at about 2% of GPU time.

## Validation

- `tests/unit_tests/gpu/models/common/test_rmsnorm_compile.py`: region vs eager, output and input/weight
  grads, for `[T, 2048]` and `[T, 8, 128]` (per-head) inputs.
- 2-GPU FSDP, CUDA graphs, 600-step decision fine-tune with the region: held-out accuracy 0.872 vs
  0.879 without it (within run-to-run noise; 0.874 in an earlier run with the same compiled norm).
- CPU model/recipe unit tests: same 16 failures (environment, e.g. missing `expecttest`) with and
  without this change.
