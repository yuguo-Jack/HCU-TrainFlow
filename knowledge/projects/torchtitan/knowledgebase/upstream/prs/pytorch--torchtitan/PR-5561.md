# [compile][perf] Compile Muse Spark's SwiGLU and DeepSeek-V4's RoPE by default

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5561) · state: closed · merged: True

## Original PR description

**TLDR:** Two models call an existing compiled region but don't list it, so it runs eager today. This PR lists both:
- DeepSeek-V4's RoPE (`rope`): 2 layers 1.1% faster in training and 1.8% at prefill (16k), RoPE kernels 40% faster, bitwise. Reaches every DeepSeek-V4 recipe.
- Muse Spark's routed-expert SwiGLU (`fused_binary_activation`): 4-layer unit 4.0-5.9% faster in training, 6.3-6.9% at prefill. Headroom: no shipped recipe runs it (they use the `fused_swiglu` override instead).

**Problem**
1. **Regions are opt-in.** A `@local_compile` function runs eager unless the model's `local_compile_regions` lists it.
2. **Muse Spark.** Its routed experts call stock `SwiGLU` (a `BinaryActivationFn`, the `fused_binary_activation` region) on `w13`'s `[rows, 2, 4096]` output, but its 9-region default list lacks it.
3. **DeepSeek-V4.** It calls `ComplexRoPE.forward` (the `rope` region) at 4 sites, but its 3-region default list lacks it.
4. **Eager kernels.** Eager SwiGLU runs silu and the multiply separately, and its backward copies the two grads into one tensor. Eager RoPE runs complex multiplies with casts around them.
5. **Cost.** Enabling the region saves (Results): Muse Spark 2.2 of 36.8 ms per 4-layer fwd+bwd at 2k tokens, 13.9 of 350.3 ms at 16k. DeepSeek-V4: 2.5 of 226.8 ms per 2-layer fwd+bwd at 16k (RoPE kernels 6.24 -> 3.71 ms).

**Solution**
1. **Muse Spark:** add `"fused_binary_activation"` to `MuseSparkModel.Config.local_compile_regions`.
2. **DeepSeek-V4:** add `"rope"` to `DeepSeekV4Model.Config.local_compile_regions`.
3. **Limit 32 on `ComplexRoPE.forward`.** DeepSeek-V4 calls it from 4 sites: q/kv and the inverse rotation of the attention output in attention, compressed kv in the compressor, q in the indexer.
4. **Graph count.** One token count takes 4 graphs in training and 4 more under `no_grad`: 8, Dynamo's default limit. More token counts, and calls without `positions`, took up to 26 in one process in our probes (DeepSeek-V4 has no decode path, so tiny token counts don't occur). With `fullgraph=True`, the graph past the limit raises instead of falling back to eager.
5. **Headroom.** The recipes pack every microbatch to one token count and run no `no_grad` pass, so they use 4. The limit lets a validator, another token count or a caller without `positions` run without crashing.
6. **Unchanged.**
   - Shipped Muse Spark recipes: the `fused_swiglu` override bypasses the region, Dist-MoE runs its own SwiGLU, LoRA SFT keeps `["loss"]`.
   - `CosSinRoPE.forward` (Qwen3, GPT-OSS): its own compile call, so it keeps limit 8.
   - Other ComplexRoPE models (Llama 3, DeepSeek-V3, Kimi K2.x, Muse Glimmer): 4-5 graphs, under 8, so the new limit was never reached in the measured runs.

You may ask: why not drop the `fused_swiglu` override from the Muse Spark recipes? Not measured yet; the override also skips padding rows past `offsets[-1]`.
You may ask: why not `dynamic=True` on the RoPE region instead of a higher limit? DeepSeek-V4 still takes 10 graphs with it (16 when packed and unpacked batches mix; CPU count, debug model), over the default 8. Also, every ComplexRoPE model would then compile its first shape with a dynamic token count.
NOTE: reaches every DeepSeek-V4 recipe (debug, MTP debug, flash, pro; none sets its own region list); DeepSeek-V4 has no golden losses.
NOTE: the DeepSeek-V4 FSDP+TP+EP integration test runs on a real process group, so CI runs it only with the `ciflow/real-pg` label. Passed locally on 4 GB300: TP2, 10 steps, loss 8.25 -> 3.68.
NOTE: more token counts stop adding graphs once T is dynamic, except one that leaves a single compressed entry (128 <= T < 256 packed), which adds 1 per layout and grad mode.
NOTE: DeepSeek-V4 measured at 16k only; train 2k/4k, prefill 2k and decode not run.
NOTE: Muse Spark at EP > 1 not run on GPU: 0 or 1 local rows add SwiGLU graphs; a CPU probe counted 7 graphs (limit 16).
NOTE: open drafts also edit these region lists (MoE router, DeepSeek-V4 glue regions); whoever lands second takes the union.
NOTE: not tested: loss curve, H100.
