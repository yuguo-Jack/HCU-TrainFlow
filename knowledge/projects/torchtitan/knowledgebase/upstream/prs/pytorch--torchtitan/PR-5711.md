## Original PR description

## Summary (human-written)

Merge conflicts from the previous PRs cause CI failing. `disable_cuda_graph`->`disable_accelerator_graphs`

## Why
CPU Unit Test fails on main: https://github.com/pytorch/torchtitan/actions/runs/40973844709/job/123796998693

#5353 renamed `training.disable_cuda_graphs` to `training.disable_accelerator_graphs`. #4920 and #5556 landed after it and still use the old name. `TestShippedCpRecipes::test_every_cp_recipe_passes_the_gate` builds `deepseek_v4_debugmodel_fsdp4_ep4` and fails:

    AttributeError: 'TrainingConfig' object has no attribute 'disable_cuda_graphs'

`rl_grpo_deepseek_v3_debug_varlen` in `alphabet_sort.py` has the same stale keyword. No CPU test builds it, but it raises `TypeError` when run.

## What changed
- Mechanical rename in two places: `tests/integration_tests/models.py` and `torchtitan_recipes/tests/rl/alphabet_sort.py`.

## Testing
- `git grep disable_cuda_graphs` returns nothing.
- Expect the CPU Unit Test job on this PR to pass `test_every_cp_recipe_passes_the_gate`.

**Verdict: Approve** -- a mechanical two-line rename that brings the last two callers in line with `TrainingConfig.disable_accelerator_graphs` (`torchtitan/config/configs.py:73`), which fixes the CPU unit test that is failing on main.

**What this PR does.** #5353 renamed `training.disable_cuda_graphs` to `training.disable_accelerator_graphs`. Two later PRs merged after it and still used the old name. This PR updates those two callers.

**Example.**
```python
# before (main): building the integration test definition raises
config.training.disable_cuda_graphs = True
# AttributeError: 'TrainingConfig' object has no attribute 'disable_cuda_graphs'

# before (main): the RL recipe raises when built
TrainingConfig(disable_cuda_graphs=True, ...)  # TypeError: unexpected keyword

# after: both use the existing field
config.training.disable_accelerator_graphs = True
TrainingConfig(disable_accelerator_graphs=True, ...)
```

<details><summary>Details</summary>

- `git grep disable_cuda_graphs` on HEAD returns nothing, so the rename is complete.
- `alphabet_sort.py` imports `TrainingConfig` from `torchtitan.config` (line 27). That is the same dataclass that defines `disable_accelerator_graphs`, so the keyword is valid.
- Numerics: the flag value is unchanged (`True` in both places). Only the field name is fixed, so behavior matches what the authors of #4920 and #5556 intended.
- Unrelated and harmless: `tests/unit_tests/cpu/components/test_invalid_loss.py:52` still sets `trainer._deferred_cuda_graph_options = None`. No code reads that attribute any more, so the line is dead, but it sets a plain attribute and doesn't fail. If someone wants to clean it up, it belongs in a separate PR.
