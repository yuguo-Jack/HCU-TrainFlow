# [models] Fill aux_loss_denominators in preprocess_inputs

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5405) · state: closed · merged: True

## Original PR description

**TLDR:** Each model with an aux loss now fills its `aux_loss_denominators` kwarg in `preprocess_inputs`, instead of `TrainingEngine` patching it in afterwards. No behavior change. Stacked on the RDMA microbatch PR; the prefetch PR above builds on it to preprocess one group at a time.

**Problem**
1. `TrainingEngine.forward_backward` preprocesses every microbatch group, then loops over them to set `model_kwargs["aux_loss_denominators"] = global_routing_token_counts`.
2. It finds `model_kwargs` from the prepared tuple's length: 3 entries with PP, 4 without.
3. The models already write that key in `preprocess_inputs`, as a `None` placeholder.
4. Preprocessing one group at a time (the next PR) would have to repeat that patch, by tuple shape, for every group.

**Solution**
1. `preprocess_inputs` takes `global_routing_token_counts`, default `None` (the validator calls it without routing counts, as today).
2. The decoder, Qwen3.5, DeepSeek-V3 MTP, Kimi K2.7 and Kimi K3 return it as `aux_loss_denominators`, on the line that wrote `None`. DeepSeek-V4 and gpt-oss inherit the decoder's.
3. `TrainingEngine._preprocess_microbatch_groups` and the graph trainer's override pass it through; the engine's patch loop is gone. The HF backend's `preprocess_inputs` has no `**kwargs` and no aux loss, so it accepts the keyword and drops it.
4. **No behavior change:** the same tensor object, behind the same per-model check, still set after SPMD annotation (so it stays a plain tensor); models without an aux loss are untouched.

NOTE: not tested on GPU with PP or EP.

**Test plan**
- `pytest tests/unit_tests/cpu torchtitan/experiments/transformers_modeling_backend/tests` (repo root, merged with main): 1,653 passed; the only failures fail on main too (offline: 3 tokenizer downloads, `test_download_hf_assets`; `test_quantization.py` needs `torchao`).
- `pytest tests/rl/unit_tests/cpu`: 494 passed, 5 skipped.
- `tests/unit_tests/cpu/components/test_loss.py`: the MTP model returns the per-depth counts as `aux_loss_denominators`.
- `tests/unit_tests/cpu/test_trainer.py`: the engine passes the counts into `preprocess_inputs`; PP and SDC replay still pass.
- `torchtitan/experiments/transformers_modeling_backend/tests/test_hf_build_forward_inputs.py`: the HF backend accepts the keyword.
- GPU, DeepSeek-V3 debug model with MTP (aux loss on), 1 H100, deterministic, seed 42, 10 steps: loss and grad norm equal to main's at every step, as logged (5 and 4 decimals).
