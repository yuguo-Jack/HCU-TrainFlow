# [oncall][CI][B200] Refresh Kimi K3 numerics with FP fusion

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5631) · state: closed · merged: True

## Original PR description

## Human Summary

Fix CI breakage due to Triton default value change. Set the env value explicitly to avoid another breakage.

## AI Summary

- Enable Triton FP fusion explicitly in B200 CI.
- Refresh the Kimi K3 B200 loss and gradient norm reference from full-precision TensorBoard values.
- Run the existing KDA forward and backward accuracy test on B200.
- Keep the strict ten-step training comparison.

## Why

Triton https://github.com/triton-lang/triton/pull/12387 changes the fusion default from disabled to enabled. The Kimi K3 DistMuon test uses Triton kernels without an explicit fusion setting.

Two nightly runs produce identical enabled-fusion loss and gradient norm values:

- https://github.com/pytorch/torchtitan/actions/runs/40148031206
- https://github.com/pytorch/torchtitan/actions/runs/40250914092

The diagnostic run with `TRITON_DEFAULT_FP_FUSION=0` restores all ten values in the disabled-fusion reference exactly: https://github.com/pytorch/torchtitan/actions/runs/40408976642.

The reference uses the enabled-fusion values from the second nightly run. Explicit `TRITON_DEFAULT_FP_FUSION=1` keeps the reference stable across Triton default changes. The KDA accuracy test compares forward outputs and all input gradients against an independent FP32 recurrence before the strict training comparison.
