## Agent details

**TLDR:** W&B drops validation metrics logged at a step where training already logged. With the defaults (`log_freq=10`, validator `freq=10`), that is every validation in core training. `WandBLogger` now collects a step's metrics into one row. A new `commit()` sends the row after the step's last log.

```text
main:     log(train, step=10) -> row 10 sent;   log(validation, step=10) -> dropped
this PR:  log(train, step=10);  log(validation, step=10);  commit() -> row 10 holds both
```

**Problem**
1. `WandBLogger.log` calls `wandb.log(metrics, step=N, commit=True)`. `commit=True` makes W&B finalize row N and send it at once.
2. W&B drops every later log to a finalized step, because steps must increase.
3. Core training logs validation after training, at the same step. So `validation_metrics/*` never reaches W&B.
4. RL logs its post-training validation at the last training step (`Controller.run`). The same rule drops it.

**Solution**
1. `WandBLogger.log` no longer passes `commit=True`. When `step` is set, W&B then collects the log into that step's row.
2. New `BaseLogger.commit()` sends the open row. `Trainer.train` and torchft's `train()` call it after validation.
3. The RL controller calls it at the top of each step, and after post-training validation.
4. `TensorBoardLogger` and `MLFlowLogger` still write at once. Their `commit()` is the base no-op.

**Results**

Numerics for a logging fix: which metrics W&B keeps in each row.

The real `WandBLogger` at this head, CPU, offline, W&B 0.31.0. Steps 1, 3 and 4 log loss and validation; step 2 logs loss only. Step 4 gets no `commit()` before `close()`. Rows read back from the run file:
```text
main:     {1: loss}                    {2: loss}   {3: loss}
this PR:  {1: loss, validation/loss}   {2: loss}   {3: loss, validation/loss}
          {4: loss, validation/loss}   <- sent by close(), which calls wandb.finish()
```

Core training, 1 GPU, llama3 debugmodel, `log_freq=5`, validator `freq=5`, W&B 0.28.1. Run on an earlier version of this change, before its rebase onto main. Losses differ slightly: no fixed seed.
```text
          step 1                  step 5                  step 10
main:     loss 8.08               loss 5.24               loss 4.11
this PR:  loss 8.08, val 7.77     loss 5.22, val 4.69     loss 3.99, val 4.00
```

RL: in the next PR's 2-GPU run, every validation pass landed in its step's row, next to that step's training metrics.

You may ask:
- Why not just drop `commit=True`? Then W&B sends row N only when step N+1 logs. Every row would show up late: up to `log_freq` steps, or one RL step.
- Why not a custom x-axis, `define_metric("*", step_metric="step")`? Then `_step` would stop matching the training step. That breaks panels of older runs, and `WANDB_RESUME_FROM` / `WANDB_FORK_FROM=<run>?_step=N`, which `WandBLogger` passes to `wandb.init`.

NOTE: a step's row reaches W&B when its last log lands. For the last RL step, that is after the post-training validation pass, which can take hours on Terminal-Bench.
- A crash in that pass still sends the row: the RL entry point calls `close()` in a `finally`, and `close()` calls `wandb.finish()`.
- A hard kill (SIGKILL, a scheduler time limit) during that pass may lose the row. Not tested online.

<details><summary>Details</summary>

- **Callsites checked.** `metrics_processor.log` / `logger.log` are called only from `trainer.py`, `components/validator.py`, `models/flux/validator.py` (all inside `Trainer.train` before the new `commit()`), torchft's own `train()`, and the RL controller (`controller.py:927`, `:1225`). Nothing logs to step N after `commit()` in core, so nothing can be dropped there. Test stand-ins: `test_trainer.py:980` and `test_invalid_loss.py` call only `train_step`, not `train()`, so they don't need `commit`.
- **Exit paths.** If `DataloaderExhaustedError` is raised, `train_step` hasn't logged yet and the previous step was already committed. If validation or the RL loop raises, `close()` calls `wandb.finish()`, which flushes the open row. torchft and any other loop that never calls `commit()` falls back to W&B's default: row N is committed when step N+1 is logged.
- **RL ordering.** The first iteration's `commit()` pushes the pre-validation row (`step=start_step`). The commit inside the loop leaves the last step open, so post-validation joins it, and `controller.py:917` pushes it.
- **Latency.** In core, a training row now reaches W&B after checkpoint save and validation for that step, not right after `train_step`. That's negligible.
- The resume case (pre-validation at `start_step`, which an earlier run of the same W&B run already committed) behaves the same as on main.

</details>

How each fixes it:
```text
main:   log(train, step=N, commit=True); log(val, step=N, commit=True)  -> val dropped
#5648:  RL logs {**metrics, "trainer/step": N} with commit=True, and define_metric("*", step_metric="trainer/step")
        -> train and val are two W&B events at trainer/step = N; W&B's _step counts log events
#5227:  log(train, step=N); log(val, step=N); commit()  -> one row N with train + val; _step = N
```

| | #5648 | #5227 (this PR) |
|---|---|---|
| Scope | RL only (`step_metric` set by the RL processor) | core trainer, RL and torchft |
| Core trainer validation at a training step | still dropped | fixed |
| W&B `_step` | counts log events, not optimizer steps | equals the optimizer step |
| Resume or fork by step (`resume_from` / `fork_from=<run>?_step=N`) | `_step` must be mapped from `trainer/step` | works with the step number |
| Rows | train and val at step N are separate events, joined on `trainer/step` | one row per step |
| A log to an already-committed step | never dropped (every log is a new event) | still dropped, e.g. a run extended into the same run id |
| Call sites | none: every log commits | each loop calls `commit()` after its validation (core, RL, torchft); a loop that forgets it logs one step late |
| Last row on a hard kill | committed on each log | may be lost if the process dies before `commit()`; `close()` flushes it on a normal exit |
| Size | small, RL-local | larger: a `commit()` on every logger plus 3 call sites |

Evidence for this PR on its current head: the real `WandBLogger` run offline on W&B 0.31.0 and read back. On main the validation keys are dropped; with this PR they join the training row, and `close()` flushes an uncommitted last row.
