# [moe][perf] Turn on gather-sum dispatch and combine for DeepSeek-V3 and Kimi (6/6)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5518) · state: open · merged: False

## Original PR description

**TLDR:** DeepSeek-V3, Kimi K2.5 and Kimi K3 turn on the `moe_dispatch` and `moe_combine` regions: one MoE layer, training fwd+bwd at 16k tokens per rank, EP 4, DeepSeek-V3 68.3 -> 52.4 ms (-23%), Kimi K2.5 -23%, Kimi K3 -16%. Reference path (Dist-MoE and DeepEP have their own dispatch and combine), low priority.

**Stack** (6 PRs, merge bottom-up; this PR is in **bold**)

| # | PR | Independent? | Needs (stack positions) |
|---|---|---|---|
| 1 | AllToAll dispatcher: permute and unpermute with gathers | yes | — |
| 2 | Argsort expert ids on the narrowest integer type | yes | — |
| 3 | EP=1 inference: gather-sum MoE combine region | no | 2 |
| 4 | EP=1 inference: sort-region MoE dispatch | no | 2, 3 |
| 5 | Gather-sum dispatch and combine for training, at any EP | no | 4 |
| **6** | **Turn on gather-sum dispatch and combine for DeepSeek-V3 and Kimi** | **no** | **3, 4, 5** |

**Problem**
1. **Opt-in.** The gather-sum dispatch and combine run only for models whose `local_compile_regions` list `moe_dispatch` and `moe_combine`.
2. **Who lists them.** Only `Qwen35Model.Config`.
3. **DeepSeek-V3 and Kimi instead.** The eager combine: an fp32 multiply and a scatter-add; the token gather's backward is an accumulating `index_put`.
4. **Cost.** 16 of the 68 ms of a DeepSeek-V3 MoE layer fwd+bwd (Results).

**Solution**
1. Add `"moe_dispatch"` and `"moe_combine"` to `DeepSeekV3Model.Config.local_compile_regions` and `KimiK3Model.Config.local_compile_regions`.
2. Kimi K2.5 gets them through `KimiK25Model.Config`, which subclasses `DeepSeekV3Model.Config`.
3. **Reaches** `deepseek_v3_671b` (EP 2, all-to-all) and the DeepSeek-V3 / Kimi test recipes that don't use the SPMD typechecker.
4. **Not reached:** the three NVFP4 recipes, which set `["loss"]`.
5. Unchanged: eager runs, recipes that set their own region list, and the DeepEP, HybridEP and Dist-MoE dispatchers.

Expert weight grads are bitwise for DeepSeek-V3 and Kimi K2.5 because the combine's output grad is the same in both arms.

You may ask: why one training size per model? The shared code was measured across token counts and in inference on Qwen3.5 in stack positions 3-5; only the per-model flip is new here.

NOTE:
- Needs stack position 5, which registers both names; on main alone `apply_local_compile` raises "Unknown local_compile_regions entries".
- Kimi K3: the combine feeds `routed_norm` and `routed_up`, so expert and router grads change; an RMSNorm backward turns the combine's difference into 7.6e-4 on the per-route grad (CPU probe); the growth to 3.0e-3 is not isolated.
- `deepseek_v3_fsdp+ep` and `deepseek_v3_fsdp+cp+pp+ep` compare exact losses to golden files this PR changes. Before landing, regenerate `real_pg/a10g/deepseek_v3.txt` and `deepseek_v3_cp_pp.txt` (integration workflow, `export_results` dispatch), `fake_pg/a10g/deepseek_v3.txt` (the Fake-PG job, which that dispatch does not run) and the two `real_pg/mi350x/` files (ROCm CI, no export dispatch).
- Not run: a full-size training step or loss curve, EP 8, TP > 1, PP and full-size activation checkpointing (`deepseek_v3_671b` uses both), MXFP8 / NVFP4 (at EP > 1 their dispatcher goes through the same all-to-all combine), H100, inference for these models, the smaller DeepSeek-V3 and Kimi flavors.
