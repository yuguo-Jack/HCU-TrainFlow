# [rl] Generator: chunked copy for vLLM's mamba prefix-cache state blocks

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5385) · state: open · merged: False

## Original PR description

**TLDR:** Replace vLLM's GDN state-block copy with a chunked Triton copy: 1112 -> 27 us for each request that crosses a state block, on Qwen3.5-35B-A3B. Prefill on a 4-layer model: -16% kernel time.

**Problem**
1. **Prefix cache.** With `mamba_cache_mode="align"` (prefix caching for GDN layers), vLLM keeps each request's GDN state per 1152-token block.
2. **Copy.** When a request that already has state crosses into a new block, vLLM's V1 runner copies its state there before the step (`mamba_utils.do_mamba_copy_block`).
3. **When.** Chunked-prefill continuations, prefix-cache hits (every multi-turn turn after the first), and decode once per block. A fresh prompt has no state to copy.
4. **Slow kernel.** It runs one program per state and loops 1 KiB at a time: one 2 MiB fp32 SSM state takes ~1.1 ms.
5. **Cost.** 1112 us per crossing request for the 30 GDN layers of Qwen3.5-35B-A3B (60 copies).

```
vLLM:     state -> [1 KiB][1 KiB] ... 2048 loop iterations          one program per state
this PR:  state -> [64 KiB | 64 KiB | ... 32 chunks]                one program per chunk, all in one launch
```

**Solution**
1. `chunked_mamba_copy_block`: one program per 64 KiB chunk, moving 16-byte words.
2. `TorchTitanGPUModelRunner.load_model` swaps it in for `mamba_utils.do_mamba_copy_block`, once per process.
3. Unchanged: unaligned or overlapping copies (speculative decoding's shift within a block) go to vLLM's kernel. With speculative decoding on, vLLM uses its own fused copy and never calls this one.

**Results**
```
Numerics: bitwise identical (a byte copy).

copy kernel, GB300, one request crossing a block: 30 GDN layers, 60 copies (2 MiB fp32 SSM + 48 KiB conv)
1112 -> 27 us

4-layer Qwen3.5-35B-A3B generator, V1 runner, CUDA graphs, median kernel time over 9 prefill shapes
prefill  -16%
```

You may ask:
- Why not vLLM's V2 runner, which has a fused copy? TorchTitan's generator runs on the V1 runner.
- Why not fix vLLM's `batch_memcpy`? That is the right home; the code has a TODO to send it there and delete this patch.

**Test plan**
```
pytest tests/rl/unit_tests/gpu/test_mamba_state_copy.py
```
