# [rl] Fix default validation console keys so the reward is printed

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4938) · state: open · merged: False

## Original PR description

## Summary

`MetricsProcessor.Config.console_log_keys_validation` defaults to `validation/reward/_mean` and `validation/reward/_max` (`torchtitan/rl/observability/metrics/processor.py`). Those keys are never emitted:

- The validation reward comes from `compute_rollout_metrics(prefix="validation")` (`torchtitan/rl/controller.py:691`) as `m.Metric(f"{prefix}_reward", m.SummaryStats...)`. After reduction the keys are `validation_reward/_mean`, `validation_reward/_max`, and so on.
- `_filter_allow_list` (`torchtitan/rl/observability/metrics/console.py`) runs `re.search` for each pattern, and neither default pattern matches any emitted key.

So the default validation console line has never shown the reward. The metric backends were not affected, because they receive every key.

The train-side default already uses the emitted form (`rollout_reward/_mean`). The math examples override the validation list with `validation_reward/_mean`/`_max`, and `rl/examples/search_r1/README.md` tells users to watch `validation_reward/_mean`. The existing console tests use synthetic `validation/reward/_mean` keys, which is why they never caught the mismatch.

## Changes

- Change the two default patterns to `validation_reward/_mean` and `validation_reward/_max`.
- Add `test_default_validation_allow_list_matches_emitted_reward_keys`. It feeds real `compute_rollout_metrics` output through the default config and asserts that both reward keys are printed.

## Test plan

Run on Linux x86_64 with Python 3.12, torch 2.14.0+cpu, torchmonarch 0.6.0 and torchstore at main. vLLM was installed without its CUDA dependencies.

Two parts of the suite could not run locally:

- `test_verifiers.py` hits a collection error because the optional `verifiers` package is not installed here. It fails the same way on main.
- `test_muse_glimmer_renderer.py` was ignored because its tokenizer fixture downloads from the HF Hub, which this machine cannot reach.

CI covers both.
