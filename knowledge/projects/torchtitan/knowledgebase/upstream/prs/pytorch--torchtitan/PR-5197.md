# [dsv4][perf] Compile the attention's q norm + RoPE glue (q_norm_rope, partial_rope)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5197) · state: open · merged: False

## Original PR description

**TLDR:** Move DeepSeek-V4 attention's q norm, rope split/cat and inverse rope into regions, and enable `complex_rope`: 16k step 154.5 -> 120.2 ms (-22.2%).

**Problem**
1. **Glue around attention.** DeepSeek-V4 attention normalizes each q head (RMS), then splits, rotates and re-cats q/kv.
2. **After attention** it applies the inverse rotation to the output.
3. **Eager today.** All of this runs as eager kernels on `[T, 64, 512]` tensors.
4. **Extra copy.** The output comes back token-major, so the grouped `wo_a` einsum copies it in backward.
5. **Cost.** At 16k, 34.3 ms of the 154.5 ms step goes away once these run compiled (Results).

**Solution**
1. **`_q_norm_rope`** (`q_norm_rope` region): q RMS norm + rope in one region.
2. **`_inverse_partial_rope`** (`partial_rope` region): inverse rotation, cat lowered as per-input copies.
3. **Group-major output.** The inverse rotation writes the layout `wo_a` wants, so it runs a plain bmm with no backward copy.
4. **Enabled:** `complex_rope`, `q_norm_rope`, `partial_rope` in `DeepSeekV4Model.Config`.
5. **Unchanged:** remat markers on main's `wkv`/`wq_b` outputs; the math.

```text
before:  q -> rms (eager) -> split/rotate/cat (eager) -> attn -> inverse rope (eager, token-major) -> wo_a (bwd copy)
after:   q -> [q_norm_rope]                           -> attn -> [partial_rope] (group-major)     -> wo_a (bmm)
```

**Results**
```text
DeepSeek-V4 Flash layers 4+5, fwd+bwd wall, 1x GB300, FA4, median of fresh processes within 1% of best
16k   154.54 -> 120.23 ms  (-22.2%)
4k     54.70 ->  45.95 ms  (-16.0%)
correctness: inverse rope matches eager (assert_close defaults), group-major strides pinned in the test;
             q norm + rope within 2e-2 (compiled RMS keeps fp32 intermediates, eager squares in bf16;
             an earlier measurement of the same code: 3.4e-3)
graphs: q_norm_rope 3, partial_rope 3, complex_rope 3 (training 4k/16k/2k + no_grad 4k/2k)
```

You may ask: why not let the cat use the pointwise-cat option in `q_norm_rope` too? It was slower.
You may ask: why not transpose after the cat? Tried earlier; writing group-major inside the region replaced it.
NOTE: not yet measured under CUDA graphs. Not tested: TP>1 (local head counts were checked bitwise earlier), loss curve, H100.
