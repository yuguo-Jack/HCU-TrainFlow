# [deepseek_v3] recipes: varlen attention on Blackwell (3.6x faster than flex)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5223) · state: closed · merged: False

## Original PR description

Stack:
* #5222
* __->__ #5223
* #5225
* #5226

Stacked on #5222 (review only the last commit).

**TLDR:** on Blackwell, the DeepSeek-V3 671B recipes use `varlen` attention instead of `flex`: 3.6x faster attention at DSv3's head dims, and -29% step time on a 4-layer model with the 671B dims.

**Problem**
1. DSv3's attention has q/k head dim 192 and v head dim 128.
2. At that shape on GB300, compiled flex is 3.6-3.9x slower than `varlen` with FA4.
3. `deepseek_v3_671b` and `deepseek_v3_671b_nvfp4` hard-code `attn_backend="flex"`.

**Solution**
1. `_attn_backend()` in `torchtitan_recipes/models/deepseek_v3.py` returns `"varlen"` when `has_cuda_capability(10, 0)` and `"flex"` elsewhere. Both recipes use it.
2. Other GPUs keep flex: FA2 needs equal q/k and v head dims, and FA3 is untested with these dims.
3. Unchanged: the model flavor default (`flex`), and the dist_moe 671B recipes, which already use `varlen`.

**Results**
One attention layer, fwd+bwd, 128 heads, causal, GB300, through TorchTitan's own `VarlenInnerAttention` / `FlexInnerAttention`, CUDA-graph replay, ms:
```
1 doc x 4096            flex   8.48 -> varlen (FA4)  2.35
1 doc x 16384           flex 118.03 -> varlen (FA4) 30.28
12 docs, 16384 tokens   flex  31.30 -> varlen (FA4)  8.55
```
4-layer DSv3 with the 671B attention and FFN dims, 8 experts (top-2), 16384 tokens per step, 1 GB300, ms/step (2 runs):
```
one 4096-token document per row   flex 345, 427 -> varlen 244, 245   (-29%), 59.9 -> 54.6 GiB
same, with 1 MTP layer            flex 429, 554 -> varlen 302, 361   (-30%), 75.2 -> 66.0 GiB
```
- The step numbers ran varlen on cuDNN, before #5222. With #5222, varlen runs FA4, which is 0.97-1.38x cuDNN's attention time at these dims.
- Numerics vs an fp32 per-document reference, rel L2: flex out 1.9e-3 / dq 2.5e-3, varlen out 2.1e-3 / dq 2.6e-3.

NOTE: the backend is picked from the GPU visible when the config is built, so a config built on a CPU-only host gets `flex`, as the quantization transforms already do.

**Test plan**
- New `test_deepseek_v3_671b_recipe_uses_varlen_on_blackwell` in `tests/unit_tests/cpu/test_config_validation.py`. Not run locally (my torch nightly predates main's pipelining imports); CI runs it.
