# [checkpoint] Load Hugging Face exports named after their index

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5167) · state: open · merged: False

## Original PR description


Summary:
`TorchCheckpointingManager` loads a Hugging Face export as the `model` item, so `torch_checkpointing` reads `model.safetensors.index.json` or `model.safetensors`. Exports named after another item, such as diffusers' `diffusion_pytorch_model.safetensors.index.json` for Flux, did not load.

`BaseStateDictAdapter` gains `hf_index_file`: the index `fqn_to_index_mapping` was read from in `hf_assets_path`, or `None` without one. `StateDictAdapter` records `model.safetensors.index.json` when it finds it, and `FluxStateDictAdapter` records whichever of its two index names it finds. The HF load names its one item with `torch_checkpointing`'s `hf_item_key` applied to that index file, and falls back to `model`, the name this checkpointer writes its own exports under. The probe still checks only the item's index and single-file names, with no directory listing. Exports keep writing under `model`.

This needs `torch_checkpointing.hf.metadata.hf_item_key`, which is not yet in a released `torch_checkpointing`.

Test Plan:
```
pytest -q tests/unit_tests/cpu/test_torch_checkpointing.py tests/unit_tests/cpu/test_state_dict_adapter.py
pre-commit run --files torchtitan/components/checkpointer/torch_checkpointing.py torchtitan/protocols/state_dict_adapter.py torchtitan/models/flux/model/state_dict_adapter.py tests/unit_tests/cpu/test_torch_checkpointing.py tests/unit_tests/cpu/test_state_dict_adapter.py
```
52 passed, with `torch_checkpointing` from source on `PYTHONPATH`. `test_hf_load_reads_a_real_safetensors_export` loads real indexed `model` and `diffusion_pytorch_model` exports into an `nn.Linear` with no mocks. `FluxStateDictAdapterTest` checks `hf_index_file` is the index found for both names. pre-commit: clean apart from pyrefly's missing `torch_checkpointing` imports.
