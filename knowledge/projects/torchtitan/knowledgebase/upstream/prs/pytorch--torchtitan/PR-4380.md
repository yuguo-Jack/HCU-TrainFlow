# [Kimi K3] Add K3 MoonViT Dynamic CP support

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4380) · state: open · merged: False

## Original PR description

## Summary

Adds dynamic context parallelism for the Kimi K3 vision tower (report sec 5.2.3): under CP a large image is split by rows over a sub-CP group that gathers its keys and values, and several large images spread over equal sub-groups.

- `vision_cp/plan.py`: which images split, over which sub-groups, and each rank's rows.
- `vision_cp/attention.py`: `VisionCPAttention`, `VisionAttention` plus the sub-group key and value gather.
- `vision_cp/encoder.py`: `MoonViTCPEncoder`, the base of Kimi K3's encoder.
- `MoonViTCPEncoder.Config.dynamic_cp_min_patches` turns dynamic CP on: `None`, the default, keeps main's path, and the two h100 CP cells set 256.
- `vision_cp/__init__.py`: `install_vision_cp` builds the sub-CP groups from `KimiK3Model.parallelize`.
- `models/common/multimodal.py`: `MultimodalModel._encoder_is_cp_invariant`, true by default, picks each encoder's FSDP mesh.

## Design

- Scope: main's CP path encodes every image on every CP rank, and this PR changes only how that vision bank is computed.
- Which images split:
  - An image with at least `dynamic_cp_min_patches` patches whose height takes whole merge blocks.
  - Every other image stays whole on every rank.
- How an image splits:
  - Bands are whole merge blocks of rows, the same rows in every frame.
  - Trailing ranks pad to the first rank's band.
  - Large images fill equal sub-groups longest first, as many as the largest divisor of the CP size not above their number.
- One tower call per micro-batch:
  - The tower runs once per micro-batch, as on main, so FSDP issues the same collectives on every rank.
  - The packed stream holds the whole images, then this rank's bands.
- Attention:
  - Only bands gather keys and values, over their sub-group.
  - Padding keys match nothing.
  - Padded queries are dropped after the projector.
- Vision bank:
  - One all-gather over the CP group returns the split images' merged tokens, so the bank is main's.
  - With no large image, the tower runs main's path.
- Sub-CP groups:
  - `install_vision_cp` unflattens the CP mesh once per divisor of the CP size.
  - Building is collective, so every rank builds them and reads the switch from the model config, which pipeline stages without the tower also hold.
- Placement:
  - The classes extend only `VisionAttention` and `MoonViTEncoder`, so other MoonViT models can reuse them.
  - Kimi K3 changes in four places: its encoder's base class, its flavors' vision attention, `parallelize` and `_encoder_is_cp_invariant`.
- Gradients under CP:
  - Since #5266 a vision encoder is CP-invariant: FSDP shards it over dp_shard only, and its output boundary all-reduces the gradient over CP.
  - Split images give CP ranks different patches, so with dynamic CP on the tower declares CP as R instead of I and converts `pixel_values` from I to R at its boundary.
  - Its gradients then stay partial per rank, and the new `MultimodalModel._encoder_is_cp_invariant` hook lets Kimi K3 shard the tower over dp_shard x cp, so FSDP sums them.
  - Every other encoder, and Kimi K3 with dynamic CP off, keep the #5266 path.

## Results

Kimi K3 debug model on 2x H100 (torch 2.15.0.dev20260906+cu126), main `e61df55b6` and this PR at `a2a97b88a`, CP=2, dp 1, SPMD typechecking on, the recipe's DistMuon and AdamW, seed 42, deterministic, every run from one seed checkpoint, one compile cache warmed by 10 steps of each configuration, 100 steps. cc12m-test holds 32 samples and each step takes one, so the columns stop at step 20, before any sample repeats. - All-gather and Ulysses are identical for 100 steps, on main and on this PR.
- Main's second run and this PR with dynamic CP off are identical to main for 100 steps.
- With dynamic CP on and no image split, the step-1 gradients match main's bitwise (465 of 465 tensors).
- That run parts from main at step 3 through gradient clipping: `clip_grad_norm_` takes one norm per gradient mesh, and the tower now shares the text's dp_shard x cp mesh, so the bf16 total norm differs by one unit at step 2 (4.5625 against 4.5938).
- With clipping off, the two runs are identical for 20 steps (checked on 2 RTX 5060 Ti).
- Threshold 256 first splits at step 5, the first 256-patch image.
- Threshold 128 splits step 1's 192-patch image, which moves step 1 by 1.3e-4.
- With the whole-image vision bank swapped in, that run matches main's step-1 gradients bitwise and the no-split run for 100 steps.
