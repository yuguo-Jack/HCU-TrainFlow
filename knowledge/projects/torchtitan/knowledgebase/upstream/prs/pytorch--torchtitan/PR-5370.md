# [Paged Stash] Page MoE activations in the eager trainer

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5370) · state: open · merged: False

## Original PR description

A MoE token dispatcher running with a static capacity factor, as a CUDA graph requires, sizes its permuted activations for the worst case while only `sum(tokens_per_expert)` rows hold data. Those activations are held from forward until backward, once per in-flight microbatch under pipeline parallelism, and capture pins every layer's padded buffer in the graph's private pool, so the un-paged cost is `num_layers × padded`.

Paged stashing reclaims the gap: once the forward consumers are done, the live rows are copied into a shared pool of fixed-size pages and the padded tensor is freed; backward pages it back in. The pool is one per `(dtype, hidden_size)`, shared by every layer and sized from measured live rows, which turns `O(layers × worst case)` into `O(worst case + actual usage)`.

GraphTrainer already pages its traced graphs this way. This adds the eager trainer, which captures the whole forward-backward—every microbatch, every pipeline action, P2P included—as one CUDA graph after two eager warmup steps, and whose CUDA graphs with EP > 1 require HybridEP's static `non_blocking_capacity_factor`, so every such run carries exactly the padding this reclaims.

### Activation checkpointing policy

**Paging is an activation checkpointing policy.** `PagedAC(RegionAC)` names the regions it pages with `page_regions` and owns them: `_own_paged_region` stamps the subtree so every region it declares is retained and none is recomputed, stated in RegionAC's own vocabulary rather than forced on another policy from inside a hook.

Outside those regions it is an ordinary `RegionAC`, so `save_regions` and `recompute_regions` choose the policy for the rest of the block. A recompute pattern that falls inside a paged region is dropped, which is what lets a SelectiveAC-style policy compose with paging: its `*routed_experts.w13*` would otherwise recompute the activation paging exists to hold.

### Region and tensor selection

**A region, never marked tensors.** `page_regions` are glob patterns over block-relative module FQNs, read the way `save_regions` is, and a pattern names a region's root, so the default `*routed_experts*` does not also match `routed_experts.w13`.

Within a region, selection is by storage layout: HybridEP's static-capacity dispatch publishes its padded and live row counts to an observer, and a retained tensor whose storage reads as rows of that capacity is paged, so weights and offsets stay resident. Saves of one storage share a stash and each view is rebuilt with `as_strided`. Nothing in the model or the kernels marks anything.

### Runtime and hooks

**One runtime, two frontends.** The kernels, page buffers, stash manager, paged-layer schedule, and overflow runner live in `torchtitan/distributed/deepep/paged_stash/`, next to HybridEP, shared with GraphTrainer's FX frontend; the eager frontend is `paged_stash/eager.py`.

**Megatron's protocol**, driven from module and gradient hooks:

- Stash at the group commit.
- Join at the next group start or at backward start.
- Reload one schedule entry ahead.
- Keep a layer resident when its own backward runs next.
- Measure, then allocate, then page.
- Use device-side overflow flags.

The hooks run on torch_remat. A region pre-hook pushes a `remat.saved_tensors_hooks` pair, which torch_remat delegates to whether or not an enclosing block is checkpointed, and `remat.is_recomputing()` stands them down during a checkpointed block's replay.

Backward reads two `SavedTensorKind`s from an owned region and both are paged:

- `BACKWARD`: autograd's own saves.
- `SAVE_OUTPUT`: a region output held real because a recomputed consumer reads it—which is what covers the capacity-padded dispatch output.

`CHECKPOINT_INPUT` is the enclosing block's own input and is not this region's to page.

`validate_paged_stash` checks only what paging needs from the model: an MoE, `expert_parallel_degree > 1`, and a static-capacity dispatch on every routed-expert token dispatcher. There is no paging-against-checkpointing matrix to validate, because `PagedAC` is the checkpointing policy.

### Memory measurements

Measured on 4×GB200 against `RegionAC(save_regions=["*"])` with paging off—the same tensors crossing into backward, each still holding its capacity-padded buffer.

Over capacity factor 1 → 8, the padded residency grows eightfold while the stash pool does not move:

| Memory | Capacity factor 1 | Capacity factor 8 |
| --- | ---: | ---: |
| Padded residency (MiB) | 1728 | 13824 |
| Stash pool (MiB) | 475.1 | 475.1 |

Over 6 → 18 layers, peak reserved grows 1.110 GiB per layer un-paged against 0.614 paged, saving 1.84 → 7.68 GiB. The pool follows live rows rather than padding, which is the whole point.

### Paging coverage

Two capacity-padded tensors per layer forward reach the pager, both as `SAVE_OUTPUT`, because torch_remat delegates about one tensor per region boundary rather than one per autograd save.

Those are the two that matter: making the activation its own region raises coverage to three and makes peak memory worse, 5.80 → 6.27 GiB at capacity factor 4 over 6 layers, because the third is never resident in padded form, so paging it adds pool without freeing a padded buffer.

Pinning the remaining tensors with `recompute_needs_tensor`, hooking each child module, and entering the hook scope inside the region body all leave the storage counts and pool sizes unchanged.
