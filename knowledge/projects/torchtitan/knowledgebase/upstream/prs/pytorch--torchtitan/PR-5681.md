# [cp] 8/n Apply the Ulysses NCCL safeguard to compact and linear attention

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5681) · state: closed · merged: True

## Original PR description

Part **8/n** of the Kimi K3 / Dist-MoE training stack. Based directly on `main`; this PR can land independently of the remaining stack.

human notes: fix the nccl ulysses safeguard that uses `Ulysses.Config` instead of `UlyssesInnerAttention.Config`. 

## Why

The existing NCCL Ulysses safeguard detects `UlyssesInnerAttention.Config`.
Compact MLA, Ulysses KDA, and Ulysses GDN instead inherit directly from
`Ulysses.Config`, so these models miss the existing protection on affected
NCCL versions.

Example: `UlyssesMLAAttention.Config` does not inherit from
`UlyssesInnerAttention.Config`. On NCCL 2.32.2 the old traversal leaves graph
registration enabled; traversing the common base selects the existing safeguard.
The NCCL fix and version boundary are unchanged:
[NVIDIA/nccl#2362](https://github.com/NVIDIA/nccl/pull/2362).

## What changed

- Match the common `Ulysses.Config` base in the existing safeguard.
- Add one isolated GDN regression for a subclass outside the old hierarchy.
  Full attention uses K/V all-gather in this test, so it cannot accidentally
  trigger the old safeguard.
- Keep the existing version-boundary and unsupported-runtime tests rather than
  repeating them for each backend.

There are only two production-line replacements. Native attention and
communication paths are unchanged; no new option or dependency is introduced.

## User-facing changes

| Before | After |
| --- | --- |
| The safeguard detects only full-attention Ulysses wrappers. | It also detects compact MLA and linear-attention Ulysses wrappers. |
| NCCL >= 2.32.3, non-CUDA, and fake runtimes skip the safeguard. | Unchanged. |

**Verdict: Approve** -- a two-line fix that points the existing NCCL guard at the base class every Ulysses backend actually shares.

**What this PR does.** `configure_nccl_for_ulysses` sets `NCCL_GRAPH_REGISTER=0` on NCCL < 2.32.3 when the model contains Ulysses CP. It looked for `UlyssesInnerAttention.Config`, but `UlyssesMLAAttention`, `UlyssesInnerKDA` and `UlyssesInnerGDN` subclass `Ulysses` directly (`cp_mla.py:83`, `cp_kda.py:42`, `cp_gdn.py:43`). This PR traverses `Ulysses.Config` instead, which covers every current Ulysses backend, plus any future one, with no list to keep up to date.

**Example.**
```
kimi_k3 debugmodel, CP map {MLAAttention: UlyssesMLAAttention, InnerKDA: ContextParallelInnerKDA}
NCCL 2.32.2, device_type="cuda"
before: traverse(UlyssesInnerAttention.Config) -> empty -> NCCL_GRAPH_REGISTER unset
after:  traverse(Ulysses.Config) -> UlyssesMLAAttention.Config -> NCCL_GRAPH_REGISTER=0
```
Both callers (`training_engine.py:328`, `experiments/torchft/trainer.py:83`) pass the model config, so neither needs a change.

- claude[bot] · comment · 2026-11-04T02:50:21Z · [source](https://github.com/pytorch/torchtitan/pull/5681#discussion_r4463014497)

File: `tests/unit_tests/cpu/distributed/test_ulysses_nccl.py` · line None

Consider cutting this down to a single case. The regression it guards is "the traversal matches something narrower than `Ulysses.Config` again", and any one subclass that skips `UlyssesInnerAttention` catches that. Once the guard traverses the base class, `compact_mla`, `kda` and `gdn` all exercise the same `isinstance` check, so the three-way parametrization builds two debug models (kimi_k3 and qwen3_5) and runs the CP transform three times without covering anything extra. The `backend == "compact_mla"` ternaries also make the attention map hard to read.

The version-boundary half (`2.32.3 -> None`) repeats `test_disables_registration_before_fixed_version`. One option: keep only the `gdn` case, which is already a single unambiguous map (`FlexInnerAttention -> AllGatherKV`, `InnerGDN -> UlyssesInnerGDN`), assert `self.configure(model) == "0"`, and drop the parametrization and the version recheck. That leaves about 15 lines. The `ulysses_configs` isinstance assertion that only `UlyssesInnerGDN` is present can stay, since it is what keeps the test from passing on a full-attention Ulysses match.
