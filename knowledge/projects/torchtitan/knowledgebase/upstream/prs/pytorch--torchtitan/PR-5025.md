# Fix FSDP backward finalization in Kimi K3 pipeline stage

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5025) · state: closed · merged: False

## Original PR description

## Summary

- preserve FSDP manual backward finalization in Kimi K3's custom AttnRes pipeline stage
- add a CPU regression test verifying that FSDP-wrapped stages enable manual finalization before forward

## Why

`AttnResPipelineStage` overrides `PipelineStage.forward_one_chunk` to manage rank-local cached residual routing. The override skipped the FSDP lifecycle setup performed by the base implementation, which could let FSDP finalize backward before the pipeline schedule reaches its gradient-reduction boundary.

This is the right fix for the  `AttnResPipelineStage.forward_one_chunk` in #4312:

Followed comment in: https://github.com/pytorch/torchtitan/pull/4312#discussion_r3987651867 to avoid intrusive changes in `pipeline_parallel.py`,

it added the same line, under the same condition, that the base `PipelineStage.forward_one_chunk` gained when pytorch/pytorch#196640 relanded on Sept 29, and the matching reset stays in the base `wait_for_gradient_reduction` / `clear_runtime_states`, which `AttnResPipelineStage` does not override.

The B200 `kimi_k3_fsdp2_tp2_ep2_pp2_vpp4` cell stayed green because the B200 lane installs cu130 nightlies, which jump from `dev20260928` to `dev20261003`, so every run until today (including the `ciflow/b200` run on #4731) had no manual finalization. With `dev20261003`, the cell's recipe on main fails at the first `REDUCE_GRAD` with "FSDP finalize_backward requires manual backward finalization".

The root cause is in #4312: `AttnResPipelineStage.forward_one_chunk` copies the base forward, so it misses whatever the base adds (this line, `register_forward_context`), and it writes the base's private `_forward_chunk_states`, which #4661 had to do the update also.
