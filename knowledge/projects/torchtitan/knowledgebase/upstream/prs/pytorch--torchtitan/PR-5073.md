# Make FlexAttention compiler backend and options configurable

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5073) · state: open · merged: False

## Original PR description

`FlexInnerAttention` currently compiles FlexAttention with the default compiler and Inductor-specific options. Recipes cannot select another compiler backend or supply that backend's own options without replacing the implementation.

Add `compile_backend` and `compile_options` to `FlexInnerAttention.Config` and pass the selected values to `torch.compile(flex_attention, backend=..., options=...)`. The backend accepts a registered name or a callable. An explicit options dict is passed without merging in Inductor settings; other backends receive `None` when options are omitted.

The default configuration (`compile_backend="inductor"`, `compile_options=None`) keeps the original shared callable and compile invocation. Default instances continue observing replacements made by deterministic-mode setup. Configured alternatives share a callable when their backend and options match; options are copied so later recipe mutations do not change existing instances. Tensor layouts, auxiliary outputs, and SPMD annotations are preserved.

This provides configuration-based compiler selection for downstream integrations. Attention-metadata ownership is covered separately by #4897.

- aws-dixuan · comment · 2026-10-16T19:10:35Z · [source](https://github.com/pytorch/torchtitan/pull/5073#discussion_r4298359591)

File: `torchtitan/models/common/attention/attention.py` · line 526

Unifying them means instances would have to hold an index into a shared list instead of the callable, and `set_determinism` plus a few graph_trainer tests would need to rely on the default being the first entry. That's fragile: swapping the list leaves stale indices, and external code that sets `_compiled_flex_attn` would silently stop working. It also wouldn't change behavior, since the default is already looked up at call time. I'd suggest leaving it as is for now.
