Part **9/n** of the Kimi K3 / Dist-MoE training stack. Stacked on
[#5681](https://github.com/pytorch/torchtitan/pull/5681); next:

## Why

MLA key/value assembly and selected-route gathering contain launch-heavy tensor
operations outside the large attention/expert kernels. Named local compilation
can combine those operations without compiling the model. Passing Ulysses'
unwaited shared-key collective into compiled assembly, however, silently loses
the shared-key input gradient. Fusing FP32 route normalization also changes
rounding, so normalization/scaling must retain their native arithmetic.

**Example.**

```python
from torchtitan.distributed.local_compile import LocalCompileConfig

# After the model registers its regions:
local_compile = LocalCompileConfig(regions=["mla_kv", "router_postprocess"])
# MLA assembly and the route gather/map are compiled.
# FP32 route normalization/scaling and expert selection remain native.
# Kimi's model config enables these regions by default.
```

## What changed

- Register the existing compact MLA K/V materialization as `mla_kv`; compiled
  training materializes V so backward produces the complete packed-KV gradient.
  Eager execution and inference keep the split view.
- Return a regular shared-key tensor from Ulysses' all-gather through the
  redistribution autograd boundary. The input/output all-to-alls remain async.
  Calling `AsyncCollectiveTensor.wait()` outside that boundary is not the fix.
- Compile only selected-score gathering and the boolean routing map as
  `router_postprocess`. Keep FP32 normalization/scaling in their original
  forward location, avoiding both rounding changes and an unnecessary wrapper.
- Enable the regions for Kimi and colocate regression tests with common
  attention and MoE components. No new dependency or expert/attention kernel.

## Related work and merge decision

This independent stack candidate overlaps the open
[#5564](https://github.com/pytorch/torchtitan/pull/5564) MLA work and
[#5343](https://github.com/pytorch/torchtitan/pull/5343) router compilation.
The reported Ulysses gradient bug is reproduced and fixed here; the route
boundary is deliberately narrower to preserve exact native normalization.
The full-training stack retains both capabilities until a validated equivalent
lands. Maintainers should converge the implementations, not land duplicate
APIs. This description addresses the split/gradient concerns in
[Felipe's comment](https://github.com/pytorch/torchtitan/pull/5682#issuecomment-6510075732).

## Alternatives considered

- Full-model compilation expands the supported surface beyond these small regions.
- Fused normalization differs from native FP32 rounding even under strict
  deterministic execution; a looser assertion would hide that change.
- Directly unwrapping the async tensor loses autograd ownership. Waiting inside
  redistribution is the small supported boundary; it can reduce overlap of
  this gather with projection, which is not benchmarked separately here.

## User-facing changes

| Before | After |
| --- | --- |
| No named MLA assembly or route gather/map boundary. | Both regions can be enabled independently; Kimi enables them by default. |
| Compiled assembly can receive an unwaited shared-key async tensor. | Ulysses returns the regular tensor with its all-gather gradient intact. |
| Whole postprocessing fusion changes FP32 normalization rounding. | Gather/map are compiled; native normalization/scaling are unchanged. |

## Numerics

Fresh validation used seed 42, strict deterministic algorithms, and unchanged exact assertions:

- One-GPU BF16 MLA assembly matched eager outputs and packed-KV/shared-key gradients bitwise.
- The router check matched weights, selected IDs, routing map, statistics, input gradients and gate gradients bitwise, with native FP32 normalization/scaling retained.

**Historical validation:** real two-rank native NCCL Ulysses forward/loss/every-input-and-parameter-gradient parity and five changed-input/weight CP2 graph updates passed before this rebase. The original async shared-key path failed its gradient check; the revised boundary passed. The original broader fused normalization differed in 699/2,048 route weights (maximum 5.96e-8); the narrowed boundary passed exactly. These multi-rank and negative-control comparisons were not rerun in this GPU-0-only review.

This is component parity, not full-Kimi convergence, FA4/KDA acceptance or an isolated throughput A/B.

- `mla_kv`: #5564 puts the same `@local_compile("mla_kv")` on `materialize_mla_kv`.

One bug to know about either way: with `mla_kv` on, Ulysses CP gives `k_shared` a zero gradient. `cp_mla.py` all-gathers `k_shared` with `async_op=True`, and the unwaited `AsyncCollectiveTensor` loses its autograd link when it enters the compiled region. #5564 will make that all-gather synchronous and add a test through `UlyssesMLAAttention.forward`.

How would you like to split this? One option: #5564 and #5343 land these two regions, and this PR rebases on top for whatever Kimi-specific part is left.
