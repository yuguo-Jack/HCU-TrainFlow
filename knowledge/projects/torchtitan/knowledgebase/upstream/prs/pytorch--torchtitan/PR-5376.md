# [observability] Add profiler.profile_ranks to limit trace export to selected ranks

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5376) · state: open · merged: False

## Original PR description

## Summary

Adds `profiler.profile_ranks: list[int] | None` so a recipe can name the global ranks that save a chrome trace, e.g. `config.profiler.profile_ranks = [0]`. The default `None` keeps today's behaviour of saving a trace on every rank.

## Motivation

Every rank currently exports its own chrome trace, so trace volume and shared-filesystem write pressure scale with world size even though only a handful of ranks are ever inspected. On a 128-node (1024-rank) DeepSeek-V3 run, one profiled iteration produced 1024 trace files totalling 170 GB for the 671B config and 57 GB for the 16B config, with all 1024 ranks writing to the shared filesystem at once.

## Design

Unselected ranks still build the profiler, trace, serialize and gzip their trace exactly like selected ranks, but write the gzip output to `os.devnull` and never create the trace directory. This keeps profiling and export cost balanced across ranks: an earlier version that skipped the profiler entirely on unselected ranks turned the selected ranks into stragglers, which skewed their own traces (collectives looked short because everyone else was waiting on them) and left the other ranks blocked in the next collective for the whole export, which can exceed `comm.train_timeout_seconds` for large traces.

Gzip is done explicitly (JSON to a temp file, then `gzip.open`) rather than relying on `export_chrome_trace`'s `.gz` suffix handling, so the devnull path pays the same compression cost. Selected ranks still produce the same `rank{rank}_trace.json.gz`. The remaining skew is the shared-filesystem write on selected ranks.

## Test plan

- `tests/unit_tests/cpu/observability/test_profiler.py`: 23 passed, including an end-to-end export on a listed rank (readable gzipped trace) and on an unlisted rank (gzip to `os.devnull`, nothing on disk).
- Llama 3 3B, 2 ranks (FSDP) on Intel Data Center GPU Max 1550 (XPU), `profile_freq=50`, 100 steps:
  - `profile_ranks=[0]`: only `rank0_trace.json.gz` written at steps 50 and 100 (valid gzip, ~2 MB each); rank 1 logs that it exports to `os.devnull`; no trace directory or temp files left behind for rank 1. Export time 1.22 s vs 1.24 s per rank.
  - `profile_ranks=None` (default): both ranks write traces at steps 50 and 100, export 1.28 s on both.
  - Baseline with profiling off: 100 steps, loss and throughput unchanged from `main`.
