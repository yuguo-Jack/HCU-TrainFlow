# [graph_trainer] Import the paged stash Triton kernels at launch

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5611) · state: open · merged: False

## Original PR description


### Summary

`paged_stash_memory_policy.py` imported `triton` at module level, and `graph_trainer.trainer` imports it through `graph_pp/pipeline.py -> graph_builder.py -> graph_builder_utils.py`. On a platform without Triton wheels (macOS, CPU only) `GraphTrainer` therefore did not import, and three CPU test modules did not collect: `tests/unit_tests/cpu/test_trainer.py`, `config/test_config_validation.py`, `config/test_cuda_graph_validation_config.py` (noted as the remaining collection errors in #5565, now merged).

- The two Megatron Core kernels (`paged_stash_copy_kernel`, `paged_stash_pop_kernel`) and `GLOBAL_BLOCK_SIZE` move verbatim, with their "copied from Megatron Core 0.19.0, do not clean up" header, into `paged_stash_kernels.py`. Nothing outside `PagedStashBuffer.launch_copy` / `launch_pop` referenced them (they were in `__all__`, which no longer lists them).
- `launch_copy` and `launch_pop` import the kernel module at launch. The policy module imports everywhere, a launch on a machine without Triton raises Python's own `ModuleNotFoundError: No module named 'triton'`, and the kernels can only run on CUDA anyway.
- No change where Triton is installed: the same kernels run from the same launch sites, imported once from `sys.modules` after the first launch.

### Test plan

New `torchtitan/experiments/graph_trainer/tests/test_optional_imports.py`, in a subprocess that blocks `triton` on `sys.meta_path`, `GraphTrainer` and `paged_stash_memory_policy` import with `triton` never loaded, importing `paged_stash_kernels` and calling `PagedStashBuffer.launch_copy` raise `ModuleNotFoundError` with `name == "triton"`. Fails on main (the policy import raises), passes with this change.

On macOS 15 (no Triton), torch 2.16.0.dev20261022 CPU, torch_checkpointing 0.1.1, on main 3ed5aa9 (with #5565 merged):
- `pytest tests/unit_tests/cpu --collect-only`, 3 errors / 1847 tests collected on main (`test_trainer.py`, `config/test_config_validation.py`, `config/test_cuda_graph_validation_config.py`, all the Triton import) -> 0 errors / 1926 tests collected with this change.
- `tests/unit_tests/cpu/test_trainer.py`, `config/test_config_validation.py`, `config/test_cuda_graph_validation_config.py`, 79 passed.
- The new test, 1 passed.
- pre commit on the three files passes every hook except pyrefly, which reports the `import triton` lines of the new module (no Triton locally) and diagnostics that pre date this change in `paged_stash_memory_policy.py`.

The GPU paged stash tests (`torchtitan/experiments/graph_trainer/tests/test_paged_stash.py`) import only the policy module's public names, which are unchanged, I could not run them here (no CUDA).
