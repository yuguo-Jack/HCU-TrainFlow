# [config] Make metric exporters and LR scheduler construction configurable

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5775) · state: closed · merged: True

## Original PR description

## Summary (human-written)
<!-- Write this yourself, not with an AI tool. 2-5 sentences: the problem, why
     this approach, and what you checked yourself. -->

Metrics logger is not object-oriented while it should be -- this PR addresses it.
LR scheduler mostly is, but was using config in the wrong way -- this PR fixes it.

## Why

Metrics processors already use `Configurable`, but their exporters are selected by backend-specific booleans and hardcoded constructors. Adding an exporter requires editing the supervised or RL processor, even though both already share the logger implementations.

LR schedulers have a related construction gap: `LRSchedulersContainer.Config.build()` always returns the base container. A subclass with its own nested config therefore loses its custom behavior unless it also overrides `build()`. The new subclass regression fails on base commit `8289613196e474828ff9e81d55227812f10d1d32` with a base container instead of the requested subclass.

**Example:**

```python
# Exporter selection now composes config objects, in list order.
MetricsProcessor.Config(
    loggers=[WandBLogger.Config(project="experiment"), TensorBoardLogger.Config()],
)

# A scheduler subclass's nested Config now constructs that subclass.
scheduler = CustomLRSchedulersContainer.Config(warmup_steps=2).build(
    optimizers=optimizers, training_steps=10,
)
```

## What changed

- Make TensorBoard, W&B, and MLflow exporters `Configurable` components with nested configs. Both metrics processors consume logger config lists; remove the fixed exporter factory and `LoggerContainer`.
- Preserve MLflow's metrics-rank restriction, including when file exporters save on every rank. Validate its optional dependency at config construction on all ranks.
- Move the RL W&B project onto `WandBLogger.Config.project`. `WANDB_PROJECT` still takes precedence; constructing an RL processor no longer mutates that environment variable. Exporter construction failures now propagate rather than being swallowed by the supervised W&B factory.
- Move LR schedule preparation into the config-taking constructor and use inherited `Configurable.Config.build()`. The schedule formula, host LR handling, metrics, and checkpoint state are unchanged.
- Mechanical: migrate all recipe, integration, script, and test callsites. The cross-commit comparison helper retains the old TensorBoard switch when running in an older checkout.

## Alternatives considered

- Replacing whole metrics processors couples custom export to aggregation and console reporting. The existing shared exporter interface is the smaller extension point.
- Another registry or a configurable LR-curve hierarchy is unnecessary for these consumers.

## User-facing changes

| Before | After |
| --- | --- |
| `enable_tensorboard=True` | `loggers=[TensorBoardLogger.Config()]` |
| `enable_wandb=True` | `loggers=[WandBLogger.Config()]` |
| `enable_mlflow=True` | `loggers=[MLFlowLogger.Config()]` |
| RL `wandb_project="titan_rl"` | `WandBLogger.Config(project="titan_rl")` |
| Disable exporter booleans | `loggers=[]` |
| Custom scheduler config constructs base container | Config constructs its owning subclass |

## Numerics

Loss and gradient norm were read from TensorBoard and checked with `scripts/loss_compare.py --metrics=loss,grad_norm --assert-equal`.
