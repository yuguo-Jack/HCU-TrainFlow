# [graph_trainer][precompile] Handle precompile  process group op in passes

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5210) · state: open · merged: False

## Original PR description

Precompile adds special op to get pg: torch.ops._dtensor.mesh_get_process_group(mesh, dim=0)
And then this extra op becomes an input to comms:
```
  pg = torch.ops._dtensor.mesh_get_process_group(mesh, dim=0)
  gathered = all_gather_into_tensor(
      input=param,
      group_name=pg,
  )
```

Some of our passes, e.g. FSDP comms detection relies on "unary_chain" that ends in comm. That means it follows one input - one output chain to the comm. Precompile addition breaks this assumption and we have to handle it, avoiding "group_name" arg.

1. Ignore group_name arg for unary_chain matching
2. As op torch.ops._dtensor.mesh_get_process_group is added to every collective, it will introduce for the same pgs different nodes. This will break matching of the chains.

Introducing deduplicate_mesh_get_process_groups_pass that will be applied for precompile, to have only one node for pg.
3. torch.ops._dtensor.mesh_get_process_group(mesh, dim=0) needs mesh,
for that we need to pass it to unshard, so extracting mesh too as inputs to unshard.

```
        # Input::
        #
        #     pg = mesh_get_process_group(mesh, dim=0)
        #     unsharded = all_gather(param, group_name=pg)
        #     output = compute(unsharded, x)
        #
        # Output::
        #
        #     def unshard(param, mesh):
        #         pg = mesh_get_process_group(mesh, dim=0)
        #         return all_gather(param, group_name=pg)
```
