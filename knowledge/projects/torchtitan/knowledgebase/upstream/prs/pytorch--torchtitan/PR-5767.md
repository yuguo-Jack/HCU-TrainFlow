## Agent details

Written with Claude Code.

**TLDR:** DeepSeek V4 now trains with pipeline parallelism (PP). Token ids reach every stage, so layers that pick experts by token id (hash-routed layers) can sit on any stage. On main, PP 2 fails at the first step with `KeyError: '2'`.

```text
main, every stage:  tokens -> embed -> 4 copies -> layers 0..3 by index -> hc_head -> norm -> lm_head
this PR, stage 0:   tokens -> embed -> 4 copies -> layers 0, 1 -> send [T, 4, D]
this PR, stage 1:   receive [T, 4, D] -> layers 2, 3 -> hc_head -> norm -> lm_head
both stages:        model kwargs from preprocess_inputs, now with input_ids_T (token ids)
```

**Numerics**

Debug model (4 layers, layers 0-1 hash-routed), 2 GB300 GPUs, seed 42, deterministic, AdamW, 512-token microbatches, same initial weights and data.

- No PP, this PR vs main (1 GPU): bitwise equal, without CUDA graphs (3 steps) and with them (5 steps, 2 of them graph replays).
- PP 2 vs 1 GPU, 1 microbatch per step (GPipe): step-1 loss, grad norm and all 104 grads bitwise equal.
- PP 2 vs 1 GPU, 2 microbatches per step: rounding only. Yardstick: the 1-GPU run without torch.compile regions, which only moves rounding.

```text
                       loss step 1 / 2 / 3              grad norm step 1 / 2 / 3
1 GPU                  8.123888 / 6.358942 / 4.949218   4.447676 / 4.585903 / 3.797573
PP 2, 1F1B             8.123888 / 6.359060 / 4.949241   4.447674 / 4.586136 / 3.796409
PP 2, Interleaved1F1B  8.123888 / 6.359060 / 4.949241   4.447674 / 4.586136 / 3.796409
1 GPU, yardstick       8.124091 / 6.358969 / 4.949053   4.447728 / 4.585631 / 3.795771
```

Interleaved1F1B has 4 virtual stages. With CUDA graphs, it equals 1F1B without CUDA graphs, bitwise, for 5 steps.

Cause: the order in which the 2 microbatches' grads add up. PP 2 and 1 GPU differ in 26 of 104 step-1 grads. On 1 GPU, changing only when FSDP reduces the grads changes the same 26 (earlier revision, same loss and grad norm).

**Problem**
1. DeepSeek V4 keeps 4 copies of each token's hidden state (hyper-connections). Blocks pass `[T, 4, D]`. At the end, `hc_head` mixes them back into `[T, D]`.
2. The forward looks up layers 0..n-1 by index, but a PP stage holds only some of them.
3. So PP fails at the first step: stage 0 holds layers 0-1 and raises `KeyError: '2'`.
4. Later stages get only the previous stage's output, so a hash-routed layer there has no token ids. The default Interleaved1F1B split puts layer 1, which is hash-routed, on stage 1.

**Solution**
1. Loop over the layers this stage holds, as `Decoder.forward` does.
2. Only the stage with `tok_embeddings` embeds tokens and makes the 4 copies. Later stages take `[T, 4, D]` as is.
3. `pipeline_last_stage_module_fqns = ("hc_head",)` pins `hc_head` to the last stage of the default split. Earlier stages return before it. A hand-written split must list `hc_head` in its last part.
4. `preprocess_inputs` adds the token ids to the model kwargs as `input_ids_T`. Each PP rank passes its model kwargs to every stage it holds, so hash routing works on any stage. The idea comes from #4782 (HaoranYu111).
5. `pipeline()` rejects two setups that would fail with unrelated errors. MTP: the split drops the MTP layers. A fake process group (dry runs): its static stage metadata assumes `[T, D]` hidden states (TODO in the code).

NOTE: Not run: more than 2 GPUs per pipeline, V schedules, or PP with data parallelism (PP x FSDP x TP needs 8 GPUs). PP with TP and EP has only the CI smoke run (no numerics comparison).

**Test plan**
- `pytest tests/unit_tests/cpu/models/deepseek_v4/`: 15 passed. New: the default Interleaved1F1B split, with kwargs from the real `preprocess_inputs`, equals the whole model bitwise. The reference reads the ids from the tokens, so all-zero ids in the kwarg fail. Main: `KeyError: '1'`.
- Fake process group, CPU: a fake group raises, a real gloo group passes. The pure-fake dry run stops there.
- GPU: every number above, except the 26-grad diagnosis, comes from this PR's code.
- CI runs both 4-GPU DeepSeek V4 AdamW entries: the unchanged FSDP 2 x TP 2 x EP 2 one and a new TP 2 x PP 2 x EP 2 one with Interleaved1F1B. New entry, `run_tests.py`, 4 GB300s, 10 steps: loss 8.124 -> 3.656, grad norm 4.05 -> 1.88.
