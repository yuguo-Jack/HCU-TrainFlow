# [Kimi K3] Add packed MXFP4 import and MX QAT recipe

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4791) · state: open · merged: False

## Original PR description

## Summary
Adds Kimi K3 MX-QAT training from released packed MXFP4 checkpoints. DCP loads packed weights into BF16 master parameters, while TorchAO applies MXFP4 weight and MXFP8 activation fake quantization to routed experts. Dense BF16 projections remain unchanged.
The general, unquantized vision-QKV checkpoint placement fix is reviewed separately in #4947 and is excluded from this PR. The ongoing DistMuon validation campaign combines both changes at its recorded revision.

## Design principles
- Clear ownership: TorchAO owns numerical operations; TorchTitan owns model selection, configuration, and checkpoint integration.
- Manifest-driven selection: Actual packed/scale pairs determine QAT targets, validated against checkpoint configuration.
- Reuse existing infrastructure: Standard recipes, model transforms, grouped-GEMM hooks, and shared checkpoint readers.
- Preserve training contracts: Keep BF16 parameters and state-dict names; handle padded A_log and distributed dt_bias during loading.
## Design details
- Manifest-driven policy: Validate packed weight/scale pairs against model configuration; use the resulting set for both checkpoint import and QAT selection.
- Direct packed loading: Decode MXFP4 weights into BF16 master parameters through DCP using a shared storage reader.
- Load-time shape normalization: Validate and remove zero padding from A_log; reshape dt_bias while preserving distributed placements.
- Composable QAT: Reuse existing model transforms and grouped GEMM interfaces, with TorchAO owning fake quantization and kernel_preference controlling the backend.
- Standard training flow: Enable QAT through the usual model recipe and checkpoint configuration. Released BF16 dense projections retain their existing behavior.
## Validation
Validated TorchTitan a61b4172 with TorchAO 88b69eab.
- 48 focused tests passed, covering loading, policy, transforms, distributed placement, and gradients.
- Released-checkpoint preflight passed: 249,924 logical tensors, including 247,296 packed pairs. Model construction selected 92 grouped QAT modules and zero dense QAT modules.
- Full released-model smoke test passed on 128 GB200 GPUs across 32 nodes, loading the 1.56 TB checkpoint directly through DCP. Every rank completed two forward/backward/update steps with finite losses and gradients and verified BF16 parameter updates. Model state contained no packed weights or scales.
The smoke test used sequence length 16, synthetic tokens, stateless SGD, and emulated grouped computation. It establishes functional distributed execution, not convergence or native-kernel performance.
