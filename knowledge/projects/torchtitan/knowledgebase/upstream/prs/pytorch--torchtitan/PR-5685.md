## Why

Shared experts do not depend on routed-expert dispatch/computation. Serial
execution cannot overlap them; an unordered side stream can read unfinished
inputs/outputs or recycled storage. This opt-in records input readiness before
routed launches and explicitly joins shared completion before output addition,
without changing model or autograd construction order.

**Example.**

```python
from dataclasses import replace

# CUDA, TP=1, with shared experts; serial remains the default.
moe_config = replace(moe_config, overlap_shared_experts=True)
```

```text
caller: input-ready -> router / routed experts -> wait shared -> add
             |                                      ^
shared:      +-------> shared experts ---------------+
```

## What changed

- Ordinary MoE and Kimi's latent MoE use the same event/stream boundary.
- Protect input/output allocator lifetimes across streams, avoiding allocator
  operations on recompute placeholders.
- Retain serial defaults; reject missing shared experts, CPU inputs, and TP>1.
- Supply an opt-in recipe override and documentation next to the MoE code.

## Alternatives considered

- Launching on an unordered stream risks data races and use-after-recycle.
- Waiting for routed completion before starting shared work removes overlap.
- Reordering Python branches changes autograd construction unnecessarily.
- Unconditional overlap adds activation memory without proving a speedup.

## User-facing changes

| Before | After |
| --- | --- |
| Shared experts execute serially after routed experts. | The opt-in forks after input readiness and joins before addition. |
| No shared-stream policy exists. | Serial remains default; unsupported opt-in modes raise. |

## Landing gates

This is an independent candidate alongside the still-open
[#5554](https://github.com/pytorch/torchtitan/pull/5554). Maintainers should
choose one implementation; duplicate overlap implementations should not land.
The two full-scale recipe ports do not enable this optional policy, so their
historical throughput is not evidence of an overlap gain.

Fresh distributed FSDP/EP overlap and full-scale throughput remain unverified.
Whole-model compilation and GraphTrainer parallel-branch lowering are outside
this policy. Final-tip type checking and maintainer review/CI are still needed.
