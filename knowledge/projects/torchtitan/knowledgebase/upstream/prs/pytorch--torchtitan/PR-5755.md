# [docs] Fix commands and recipe names that do not resolve

## Why

Several docs tell a reader to import, launch, or assign something that does not resolve. Copying them fails before training starts, or sets a timeout two orders of magnitude shorter than the table claims.

**Example.** The Cuspy recipe imports a module that is not in the tree:

```python
# before
from torchtitan.models.llama3.config_registry import llama3_debugmodel
# ImportError: no module named torchtitan.models.llama3.config_registry

# after (same import the memory-snapshot example in that file already uses)
from torchtitan_recipes.tests.models.llama3 import llama3_debugmodel
```

`ConfigLoader` (`torchtitan/config/loader.py`) only accepts `--module`, `--config`, `--override`, `--comm-backend`, `--output-dir`, `--resume-step`, and `--print-config`. The TorchFT page's `--fault_tolerance.no-use_async_quorum` is rejected by argparse. The setting is `config.fault_tolerance.use_async_quorum = False` in the recipe. `TorchFTManager.Config` documents that the field is ignored when `semi_sync_method` is set.

`fault_tolerance.process_group_timeout_ms` is milliseconds (`timedelta(milliseconds=...)`, default `10000` in `torchtitan/experiments/torchft/manager.py`). The table's recommended cell was `60s`. Assigning `60` is 60 ms, not 60 seconds. The cell is now `60000 (60s)`. The code default is unchanged.

`torchtitan_recipes/models/llama3.py` defines `llama3_8b` and `llama3_70b` only. `"405B"` is a flavor in `torchtitan/models/llama3/flavors.py` and has no shipped recipe, so the Llama 3 README no longer says 8B/70B/405B recipes exist or that a 405B recipe expects tokenizer assets. Shipped asset paths are `./assets/hf/Llama-3.1-8B` and `./assets/hf/Llama-3.1-70B` (`hf_assets_path` on those two recipes). `scripts/download_hf_assets.py` writes `repo_id.split("/")[-1]`, so `meta-llama/Llama-3.1-8B` lands at `./assets/hf/Llama-3.1-8B`, not `./assets/hf/Llama3.1-8B`.

`MODULE=torchtitan_recipes.graph_trainer` (and `.rl`, `.decision`) imports a package whose `__init__.py` exports no config callable, so `ConfigLoader._load_config` raises `ValueError` (`Config function ... not found`). The table now lists the modules that define the factories: `graph_trainer.llama3` / `.qwen3` / `.deepseek_v3`, the RL example modules, and `decision.qwen3`.

## What changed

Docs only. No code, config defaults, or tests.

- `torchtitan/observability/README.md`: Cuspy example imports `llama3_debugmodel` from `torchtitan_recipes.tests.models.llama3`. Keeps `CuspyProfilerConfig`.
- `torchtitan/experiments/torchft/README.md`: replace the CLI flag with `config.fault_tolerance.use_async_quorum = False`, including the `semi_sync_method` ignore note. Recommended `process_group_timeout_ms` cell is `60000 (60s)`.
- `torchtitan/models/llama3/README.md`: shipped recipes are 8B and 70B; 405B is a flavor without a recipe; tokenizer paths are the 8B and 70B asset dirs. No 405B launch command.
- `torchtitan_recipes/README.md`: Module column lists loadable modules, not the `graph_trainer`, `rl`, or `decision` packages.
- `torchtitan/components/checkpointer/README.md`: the two `convert_to_hf` / `convert_ema_to_hf` `--hf_assets_path` examples use `./assets/hf/Llama-3.1-8B`.

## Alternatives considered

- Add a `torchtitan.models.llama3.config_registry` shim so the old import works. Rejected: the recipe module already exists, and the memory-snapshot example already uses it.
- Teach `ConfigLoader` the old `--fault_tolerance.*` flags. Rejected: the loader CLI is intentionally those seven flags; the value belongs in the recipe.
- Change the `process_group_timeout_ms` default from `10000` to `60000`. Rejected: the documented unit was wrong, not the default.
- Add a `llama3_405b` recipe. Rejected: out of scope; this only stops claiming one is shipped.
- Re-export config callables from `graph_trainer`, `rl`, and `decision` `__init__.py` so `MODULE=<package>` works. Rejected: the factories live in the submodules, and a package is not a `--module` value.
- Add README string-guard tests. Rejected: maintainers asked not to add those.

| `--fault_tolerance.no-use_async_quorum` | `config.fault_tolerance.use_async_quorum = False` (ignored when `semi_sync_method` is set) |
| recommended `process_group_timeout_ms` of `60s` (reads as assign `60`) | `60000` (60s). Code default stays `10000` |
| Llama 3.1 8B, 70B, and 405B recipes, with 405B tokenizer assets | Shipped recipes are 8B and 70B. 405B is a flavor with no recipe. Assets: `./assets/hf/Llama-3.1-8B` and `./assets/hf/Llama-3.1-70B` |
| `MODULE=torchtitan_recipes.graph_trainer` / `.rl` / `.decision` | `torchtitan_recipes.graph_trainer.llama3` (also `.qwen3`, `.deepseek_v3`); `torchtitan_recipes.rl.alphabet_sort`, `.dapo_math`, `.search_r1`, `.verifiers_dapo_math`, `.verifiers_terminal_bench`; `torchtitan_recipes.decision.qwen3` |

## Testing

Docs only. No new test. README string guards were not added because maintainers asked not to add them. Checked the cited imports and fields against `torchtitan/config/loader.py`, `torchtitan/experiments/torchft/manager.py` (`process_group_timeout_ms: int = 10000`, `use_async_quorum` docstring), `torchtitan/models/llama3/flavors.py` (`"405B"`), `torchtitan_recipes/models/llama3.py` (`llama3_8b`, `llama3_70b`, asset paths), the recipe `def` config functions under `torchtitan_recipes/graph_trainer/`, `torchtitan_recipes/rl/`, and `torchtitan_recipes/decision/qwen3.py`, and `scripts/download_hf_assets.py` (`repo_id.split("/")[-1]`). No training run and no numerics change.
