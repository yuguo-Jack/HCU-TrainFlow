# [rl] Organize torchtitan/rl into role packages; name model state dict transfer consistently

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5316) · state: open · merged: False

## Original PR description

## Why

`torchtitan/rl/` was grouped by technical layer (`components/`, `distributed/`, `model/`, `observability/`, `losses/`) next to flat `controller.py`, `trainer.py` and `generator.py`. Code for one service ended up spread over several of these folders: the generator alone spanned `generator.py`, `distributed/parallelism.py`, `model/vllm_*.py` and `observability/vllm.py`. That left no obvious place for a second inference engine (e.g. SGLang next to vLLM) or potential actor framework.

This PR regroups the package by role, so each service's code sits together and engine- or framework-specific code sits in its own subpackage. It also replaces the informal "weight sync" with the push / pull / load `model_state_dict` terms the RL code already uses elsewhere. No behavior changes.

This prepares for splitting `generator.py` (engine calls vs. request dispatch vs. engine-loop thread) in the next PR of the stack.

## What changed

**Layout** (commit 1: moves plus import and path updates only)

| Package | Contents | Moved from |
| --- | --- | --- |
| `controller/` | `controller.py`, `work_buffer.py`, `model_state_dict_sync.py`, `metrics.py`, design docs | `controller.py`, `components/work_buffer.py`, `distributed/weight_sync.py`, `observability/controller.py` |
| `trainer/` | `trainer.py`, `batcher.py`, `training_sample_builder.py`, `controller_state.py`, `losses/` | `trainer.py`, `components/*`, `components/checkpointer.py`, `losses/` |
| `generator/` | `generator.py`, `parallelism.py` | `generator.py`, `distributed/parallelism.py` |
| `generator/vllm/` | `model_wrapper.py`, `registry.py`, `worker.py`, `stat_logger.py`, attention / GDN / KDA adapters, `batch_invariance.py` | `model/*`, `observability/vllm.py` |
| `rollout/` | adds `data.py`, `recorder.py` | `components/data.py`, `observability/rollout_recorder.py` |
| `routing/` | inter-/intra-generator routing | `distributed/routing/` |
| `actors/monarch/` | Monarch actor wrappers, `torch_elastic.py` | `distributed/monarch_actors/`, `distributed/torch_elastic.py` |
| `_env.py` | process environment defaults | `_runtime.py` |

`components/checkpointer.py` becomes `trainer/controller_state.py` because it only holds the controller state that the trainer checkpoints (`MirroredState`, the state keys). The new package `__init__.py` files re-export nothing, so importing a light module (e.g. `generator.parallelism`) never pulls in vLLM or Monarch.

**Names** (commit 2)

| Before | After |
| --- | --- |
| `WeightSyncManager`, `Controller._weight_sync` | `ModelStateDictSync`, `Controller._model_state_dict_sync` |
| generator `pull_model_state_dict(version)` | `load_model_state_dict(version)` |
| `ModelStateDictPullMessage`, `LoopAction.PULL_MODEL_STATE_DICT`, `LoopDecision.pull_version` | `ModelStateDictLoadMessage`, `LoopAction.LOAD_MODEL_STATE_DICT`, `LoopDecision.load_version` |
| `VLLMGenerator.Config.reset_kv_cache_on_weight_sync` | `reset_kv_cache_on_model_state_dict_load` |
| "weight sync" in docs and comments | "model state dict sync" (the whole handoff) or push / pull / load |

The trainer pushes, the router pulls (prefetch on every generator, then load), and the generator loads. The trainer's `push_model_state_dict`, the router's `pull_model_state_dict` and the generator's `prefetch_model_state_dict` keep their names. Metric keys (`timing/weight_sync/*`) are unchanged so existing dashboards keep working.

## User-facing changes

- RL import paths change, e.g. `torchtitan.rl.controller.Controller` -> `torchtitan.rl.controller.controller.Controller` and `torchtitan.rl.distributed.monarch_actors` -> `torchtitan.rl.actors.monarch`. Every in-repo caller is updated.
- `reset_kv_cache_on_weight_sync` is renamed to `reset_kv_cache_on_model_state_dict_load` (recipes updated).

## Testing

- `pre-commit run --all-files` is clean (pyrefly: 0 errors).
- RL CPU unit tests: 433 passed. The one failure, `test_rollout_worker.py::test_delta_prompts_rebuild_the_full_prompt_samples` (`missing ... 'release_session_fn'`), also fails on main.
- The same tests pass on commit 1 alone, so the stack bisects cleanly.
- Every absolute `torchtitan` import and dotted string reference (e.g. `mock.patch` targets) resolves to an existing module and symbol, checked statically. Every `torchtitan.rl` module imports.
- Every RL recipe in `torchtitan_recipes/rl` and `torchtitan_recipes/tests/rl` builds, except a hardware-gated MXFP8 recipe.

Also included: a separate one-line fix for a malformed call in `tests/unit_tests/cpu/models/test_build_model_config.py`. pre-commit's top-level `exclude: 'build'` is an unanchored regex, so it skips every path containing "build" and never formatted that file.
