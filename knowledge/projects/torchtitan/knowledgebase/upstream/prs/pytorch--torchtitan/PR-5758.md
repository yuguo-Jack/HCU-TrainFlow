## Why

`scripts/checkpoint_conversion/numerical_tests_qwen3_5.py` builds MRoPE ids in `build_inputs` by calling `MultiModalCollator._build_mrope_positions` on a `types.SimpleNamespace(spatial_merge_size=merge_size)` and on `hf_in["input_ids"]`.

The method reads `self.patch_order` first and raises `ValueError` unless it is `"block"`. The stand-in has no `patch_order`, so the call raises `AttributeError` before that check. The real collator default is `"block"`.

The method docstring says `tokens` is `(num_tokens,)`. It does `tokens.unsqueeze(0)` and later returns `mrope_positions.squeeze(0)`, shape `(num_tokens, 3)`. `processor.apply_chat_template(..., return_tensors="pt")` yields `input_ids` of shape `(1, S)`. Unsqueeze makes that `(1, 1, S)`, and `batch_size, seq_len = tokens.shape` raises `ValueError: too many values to unpack (expected 2)`.

`Qwen35Model.forward` does not index `positions` itself. It passes them to each layer. `MRoPE._reshape_cache` uses the 3-axis cache only when `positions.ndim == 2` and the last dimension is 3, i.e. `(num_tokens, 3)`. The collator already returns that rank after `squeeze(0)`, and `preprocess_inputs` forwards the same rank. A stored `(1, S, 3)` tensor would skip MRoPE and fall through to plain RoPE. The old script comment asked for `(1, S, 3)`; that comment does not match the index. The forward comment that still says `(batch, seq, 3)` is the same mismatch and is left alone.

`vision_to_patches` returns `grid_thw` of shape `(3,)`. The collator indexes `grid_thw[image_index]` as one image's `(t, h, w)`, so `grid_thw.unsqueeze(0)` to `(num_images, 3)` stays.

**Example.**

```python
mrope_builder = types.SimpleNamespace(spatial_merge_size=2)
MultiModalCollator._build_mrope_positions(
    mrope_builder,
    torch.zeros(1, 5, dtype=torch.long),  # HF input_ids
    torch.zeros(1, 3),
    None,
    None,
    image_token_id=99,
    video_token_id=98,
)
# AttributeError: 'types.SimpleNamespace' object has no attribute 'patch_order'
```

With `patch_order="block"` but the same `(1, 5)` tokens:

```text
ValueError: too many values to unpack (expected 2)
```

`build_inputs` now squeezes the processor row to `(S,)` before the collator call, so positions come back `(S, 3)`. `tt_inputs` stores that row and `patches` of shape `(N, P)`. `run_tt` reads packed `(T, V)` logits.

## What changed

- `build_inputs` sets `patch_order="block"`, squeezes `hf_in["input_ids"]` to `(S,)`, and calls `MultiModalCollator._build_mrope_positions` inline. The one-off helper is gone.
- Stored tensors match the packed forward: tokens `(S,)`, patches `(N, P)`, `grid_thw` `(num_images, 3)`, positions `(S, 3)`. `patches.unsqueeze(0)` is gone. `grid_thw.unsqueeze(0)` stays.
- `run_tt`'s reference SDPA takes packed `(T, H, K)` the way `FlexInnerAttention` does: `transpose(0, 1).unsqueeze(0)` to `(1, H, T, K)`, then the inverse. `transpose(1, 2)` was the old `(B, L, H, K)` layout.
- Last-token logits are `logits[-1:].unsqueeze(0)`, shape `(1, 1, V)`, matching `run_hf`.
- Deleted `tests/unit_tests/cpu/scripts/test_qwen35_numerical_mrope.py`. It grepped the script and skipped on import.

`mm_collator.py` is unchanged. The `model.half()` / `to_empty` / `init_states` order in `run_tt` is unchanged.

## Alternatives considered

- Keep a helper that accepts both `(S,)` and `(1, S)`. No. `build_inputs` is the only caller and it owns the processor row.
- Leave `run_tt` on batched `(1, S)` tokens and `(1, N, P)` patches. No. The vision encoder checks `pixel_values.shape[0]` against the patch grid, and the text forward is packed `(num_tokens,)`.
- Leave `_SDPA` on `transpose(1, 2)`. No. That swaps heads with `head_dim` once Q/K/V are `(T, H, K)`. GQA then sees different query and key embedding sizes.
- Make `_build_mrope_positions` treat a missing `patch_order` as `"block"`. No. The method already requires `"block"`. #5728 owns `mm_collator.py`.
- Unsqueeze positions to `(1, S, 3)`. No. Rank 3 is not the MRoPE path in `MRoPE._reshape_cache`.
- Construct a real `MultiModalCollator`. No. That needs a dataset context and a tokenizer.

## User-facing changes

| Before | After |
| --- | --- |
| `build_inputs` raises `AttributeError` because the MRoPE stand-in has no `patch_order` | The stand-in sets `patch_order="block"` |
| Processor `input_ids` `(1, S)` make `_build_mrope_positions` raise `ValueError` on the shape unpack | The call gets a 1-D row. Stored positions are `(S, 3)` |
| `run_tt` passes tokens `(1, S)` and patches `(1, N, P)` into a packed forward | tokens `(S,)`, patches `(N, P)` |
| `logits[:, -1:, :]` assumes 3-D logits | `logits[-1:].unsqueeze(0)` matches HF `(1, 1, V)` |
| No config or CLI flag | No config or CLI flag |
