# [profiler] 6/n Preserve active failures during shutdown

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5679) · state: open · merged: False

## Original PR description

Part **6/n** of the Kimi K3 / Dist-MoE training stack. Based on `shuhuayu/k3-dm-stack-05`: the review diff contains only this feature.

## Why

A training OOM is already visible to the profiler's context manager, but
`TrainingEngine.close_profiler()` discards it by passing three `None` values.
Consequently, the existing OOM exit-snapshot branch is never reached when
`Trainer.train()` closes the profiler in its `finally` block.

## What changed

- Pass `sys.exc_info()` from `close_profiler()` into the existing profiler
  context manager. Its API stays unchanged, so every caller closing under an
  active exception gets the same behavior.
- Exercise the real close method and profiler exit path for both a direct OOM
  and the OOM wrapped by a pipeline-stage error. Verify the original exception
  is not swallowed and repeated cleanup does not dump twice.

CUDA-graph stream-lane rendering is intentionally not part of this patch:
upstream [#5526](https://github.com/pytorch/torchtitan/pull/5526) already covers it
for both profiler backends. The duplicate export-capability branch and its
tests were removed during local review.

## Example

```text
train_step raises an OOM (possibly wrapped by a pipeline RuntimeError)
    -> Trainer.train's finally block calls engine.close_profiler()
before: Profiler.__exit__(None, None, None); no OOM exit snapshot
after:  Profiler.__exit__(*sys.exc_info()); the existing OOM branch dumps once
the same training exception still propagates to the caller
```

## Alternatives considered

Adding exception arguments to every close caller is unnecessary:
`sys.exc_info()` preserves the active exception through the nested close call.
Ordinary successful shutdown still supplies three `None` values.

## User-facing changes

| Before | After |
| --- | --- |
| Active training failures are dropped at the engine/profiler boundary. | The existing profiler receives the original failure context. |
| OOM exit snapshots are omitted even when memory profiling is active. | The existing exit-snapshot branch runs once. |

## Numerics

No model kernels, forward/backward, reduction dtype, optimizer arithmetic, or
training-loop scheduling changes. Only shutdown under an active exception
changes.
