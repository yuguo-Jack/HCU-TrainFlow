# [profiler] draw CUDA graph replays on logical lanes

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5526) · state: open · merged: False

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.15.0) (oldest at bottom):
* #5527
* __->__ #5526
* #5136
* #5525

A replayed CUDA graph runs on whatever streams the driver's graph executor
picks, so a profile draws one training step across hundreds of single-kernel
stream lanes. Rank 0 of a Llama3 8B FSDP2 x TP2 GraphTrainer run had 408 GPU
tracks, 370 of them a single NCCL kernel.

Add Profiler.Config.cuda_graph_lanes (on by default), which asks torch to
move graphed work onto logical lanes: one per process group for collectives,
one per mark_stream stream, and one for everything else. It sets
CuspyConfig(graph_lanes="all") for Cuspy and passes graph_lanes="all" to
Kineto's export_chrome_trace. Moved events keep the stream they ran on as
original_stream.

Both need a torch with CuspyConfig.graph_lanes, which landed together with
process group lanes for collectives; on older torch the trace keeps its
replay-stream layout, with a warning when it contains CUDA graph work.

With a prototype of the same lane rule, the same run has 8 GPU tracks on
Cuspy (CUDA graph, mesh_tp, mesh_fsdp, and the eager streams) and 7 on
Kineto. A DeepSeek V3 Dist-MoE FSDP2 x EP2 run has 4.
