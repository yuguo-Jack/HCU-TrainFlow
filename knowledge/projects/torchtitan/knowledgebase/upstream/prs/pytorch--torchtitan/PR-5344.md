# [skills][perf] local_compile_perf: lessons from the Qwen3.5 router

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5344) · state: open · merged: False

## Original PR description

**TLDR:** Lessons from applying `local_compile_perf` to the Qwen3.5 router on current main (which took the MoE layer -3.6% at 16k): look for an ATen fallback before rejecting a region, look for regions a model doesn't enable, and two new limits/negative results.

**What changes** (`.claude/skills/local_compile_perf/`)
1. **measurement.md:** when a region barely helps, look for an ATen fallback inside it before rejecting it. Qwen3.5's router region as written kept ATen `topk` (617 -> 579 us at 16k); argmax rounds reached 437, 301 with the aux-loss sums.
2. **SKILL.md, step 0:** grep for regions the model doesn't enable or a sibling class doesn't call. Qwen3.5's batch-wise aux loss skipped the existing `moe_aux_loss` region (~190 us of `[T, E]` sums per layer).
3. **compile-limits.md:** a layer that adds into `weight.grad` in place (`HiMidLoLinear` with `inplace_wgrad_accum=True`) can't be traced: start the region after it.
4. **negative-results.md:** `triton.decompose_sort_ops=True` is slower than ATen `topk` for top-8 of 256 (747 vs 579 us).
5. **SKILL.md, output:** run the module's tests in the same CI-equivalent venv used for lint.

**Test plan**
Docs only.
