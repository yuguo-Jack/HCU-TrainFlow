# [rl] Terminal-Bench: grade the way harbor run does (1/3)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5237) · state: open · merged: False

## Original PR description

**TLDR:** The Terminus-2 harness stops the agent's tmux server before `tests/test.sh` runs, so every job the agent started with a plain `&` (`python3 server.py &`) is dead when the test checks it. In a Qwen3.5-9B-Base run on TMax, up to 5.6% of rollouts (51 of 904) scored 0 this way. This PR keeps the server alive until scoring, as `harbor run` does, and closes two smaller gaps.

**Problem**
1. `TerminalBenchTerminusHarness.launch()` runs `tmux kill-server` in its `finally`, right after the agent exits.
2. Verifiers runs `tests/test.sh` later, when it scores the rollout.
3. Killing the server hangs up the agent's shell, which kills the jobs it started with a plain `&`.
4. `harbor run` grades in the same container and never stops the session.
5. Cost: up to 51 of 904 rollouts (5.6%), on 11 tasks that scored 0 of 88.

Two smaller gaps, from the same run:
- The agent's `exit` ends the rollout: 19 of 904 (2.1%). Under `harbor run`, when asciinema installs, the default recording nests the agent's shell, so `exit` ends only the recording.
- The program got the task as `--task=...`, so `pkill -f <word in the task>` killed Terminus-2: 12 of 904 (1.3%), counted by replaying the agent's commands.

**Solution**
1. Move the tmux cleanup into `Harness.cleanup`, which Verifiers calls after scoring. It is bounded at 30 s, since nothing above it times out.
2. Write the prompts to a file next to the tmux dir and pass `--prompts=<path>`; `cleanup` removes it.
3. After setup, type `bash` and `clear`; Harbor's recording step types `asciinema rec` and `clear`.
4. Unchanged: the grading path, the Terminus-2 options, the recipe.

**Results**

Local CPU probe (Harbor 0.22.0, tmux 3.7b): the real `launch()` and `terminus_harness.py`, with a scripted model that types `exit` plus more keys, starts `python3 -m http.server &`, then finishes.

```text
program exit code              1 -> 0
service up when tests run      no -> yes     (base: run without the `exit` turn)
processes with task in argv    1 -> 0
`exit`, `C-d`, `exit 1`        session gone -> session alive     (Harbor's own TmuxSession)
```

You may ask:
- Why not grade a rollout whose Terminus-2 crashed? `harbor run` skips the verifier then and counts the trial as 0.
- Why drop the try/except around the cleanup? Verifiers already catches and logs a failing `Harness.cleanup`.
- Why a file and not environment variables? Some sandbox runtimes copy the environment into the command line of a wrapper shell that lives for the whole run, where `pkill -f` matches it. `runtime.write` keeps the bytes off every command line in the sandbox.

NOTE:
- 51 is an upper bound: the run did not log test output, so some of those tests may fail for another reason.
- With the nested shell, cleanup's `tmux kill-server` kills the agent's `&` jobs in only 5 of 12 trials (`harbor run`'s recording: 0 of 12). Verifiers stops the runtime right after `cleanup`, so they don't outlive the rollout.
- The agent's background jobs now run while `tests/test.sh` does. Runs with this change logged a new class of scoring timeouts with busy background loops; under the recipe's 12,000 s scoring budget, one such rollout can hold its group for up to 3.3 h.
- Upstream's Docker runtime runs containers with host networking, so sibling rollouts share ports, and a service now holds its port through its own grading. A sibling's agent can find the port taken, or its tests can reach the other rollout's server. The 51 of 904 came from runs where each rollout had its own VM.
- `pkill -f python` still kills the in-sandbox program.
- Verifiers' stock Terminus-2 harness has the same three gaps; the TODO to delete this copy now waits for them too.
- Not run: an RL job. The rollout counts come from recorded rollouts of an earlier run.

**Test plan**

```
pytest tests/rl/unit_tests/cpu/test_verifiers_terminal_bench.py tests/rl/unit_tests/cpu/test_verifiers.py   # Verifiers 0.3.1, Harbor 0.22.0: 19 passed, 2 failed
pytest tests/rl/unit_tests/cpu   # 511 passed, 8 skipped, same as main (the Verifiers tests skip without verifiers)
```
The 2 failures also fail on main: `test_agent_runs_inside_docker_and_verifier_uses_same_taskset` and `test_training_recipe_uses_separate_datasets` read `Config.train_dataset`, which main renamed when it started checkpointing prompt data. All three new tests fail on main's harness:
- `test_tmux_server_outlives_launch_until_cleanup`
- `test_prompts_reach_terminus2_outside_its_argv`
- `test_agent_shell_runs_inside_the_login_shell`
