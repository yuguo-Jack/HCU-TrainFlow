# [CP] Work around Ulysses graph registration on older NCCL

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5393) · state: closed · merged: True

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.17.0) (oldest at bottom):
* __->__ #5393

NCCL may reuse an incomplete CUDA-graph IPC mapping for another buffer view. This can cause incorrect results or invalid memory access. Set NCCL_GRAPH_REGISTER=0 before process-group initialization for normal Ulysses on NCCL releases before 2.32.3.

The affected NCCL registration code is shared with other collective paths, including all-gather and some out-of-place all-reduce paths. This workaround is scoped to normal Ulysses because that is the confirmed reproduction. We currently couldn't reproduce this issues with other collectives, so we just enable the workaround for Ulysses.

Reproduced the error on a smaller scale, need a larger scale run of Kimi K3 to verify.

Upstream fix: https://github.com/NVIDIA/nccl/pull/2362. The first fixed public release is NCCL 2.32.3.
