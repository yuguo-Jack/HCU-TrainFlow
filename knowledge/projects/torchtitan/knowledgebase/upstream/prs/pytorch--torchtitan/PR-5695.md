## Why
`_compute_redistributed` uses one compute exchange buffer for both directions. For each parameter in a bucket it reads the received fragments, runs Newton-Schulz, and writes the update back into the same buffer before later parameters read their inputs. That is safe only when each update lands exactly on its own already-consumed inputs, which holds for the usual mirrored round trip. Replicated storage on the transport axis breaks it: the inputs come from one holder, but the update goes back to every holder, so the return layout is larger and shifted, and the writes overwrite later parameters' unread inputs. Those parameters then run Newton-Schulz on wrong data every step, with no error. In-tree recipes store parameters as FSDP Shard and are not affected, but Replicate storage is documented as supported.

**Example.** 2 ranks, one bucket `layers.0.*` with three (4, 6, 5) parameters, all `ComputeLayout({"dp_shard": Shard(0)})`, stored as `Shard(1)`, `Replicate()`, `Shard(1)`:

| | `a` | `b` | `c` |
| --- | --- | --- | --- |
| main, after 2 steps vs. per-parameter buckets | equal | off by 0.017 | off by up to 0.027 |
| this PR | equal | equal | equal |

## What changed
- `_build_bucket_plans` records `compute_to_storage_input_offset` on each redistribution bucket plan: 0 when every parameter's return spans equal its receive spans (the update is written in place, as today), otherwise the receive buffer size, so the return input sits after the received inputs.
- The runtime sizes the compute exchange buffer with that offset and writes and sends the return input at it.

## Alternatives considered
- Always give the return trip its own region: also correct, but grows the compute exchange buffer for every bucket, including all in-tree ones.
- Copy every parameter's inputs out before computing: needs a compute buffer per parameter instead of the shared scratch.

## Numerics
Buckets whose return layout mirrors the receive layout, which includes every in-tree recipe, keep offset 0, the same buffer sizes and the same results. Buckets with replicated storage now compute on their own inputs.

## Testing
- New `test_replicated_storage_matches_per_parameter_buckets` (4 GPUs): a shared bucket with `Shard(1)`, `Replicate()`, `Shard(1)` storage must match per-parameter buckets bitwise after two steps. It fails on main (`layers.0.b`, every rank) and passes with this change.
- `pytest tests/unit_tests/gpu/distributed/flex_shard/test_dist_muon.py tests/unit_tests/cpu/distributed/flex_shard`: 20 passed.
- A 2-rank CPU/gloo repro across six storage and compute mixes (Owned, Shard(0), BlockShard compute; with and without Replicate storage): the shared bucket matches per-parameter buckets in all of them.
