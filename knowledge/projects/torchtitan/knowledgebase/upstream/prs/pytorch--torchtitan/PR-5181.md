# Make the KDA attention import optional

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5181) · state: closed · merged: False

## Original PR description

## Summary

`torchtitan/models/common/attention/__init__.py` imports `.kda` unconditionally:

```python
from .kda import KDAAttentionMetadata
```

`kda.py` in turn imports `attn_gym.linear.short_conv`, whose kernels are written in CuTeDSL and live behind the `attn-gym[linear]` extra. That extra resolves to `nvidia-cutlass-dsl[cu13]`, which is CUDA-only by construction:

```
Provides-Extra: linear
Requires-Dist: nvidia-cutlass-dsl[cu13]>=4.6.0; (sys_platform == 'linux') and extra == 'linear'
```

The result is that a CUDA-only dependency sits on the import path of **every** model. On a non-CUDA accelerator, `import torchtitan.models.common` raises, so llama3, qwen3, deepseek_v3, flux, etc. cannot be imported at all -- even though none of them touch KDA.

Repro on XPU, current `main`:

```
  File ".../torchtitan/models/common/attention/__init__.py", line 30, in <module>
    from .kda import KDAAttentionMetadata
  File ".../torchtitan/models/common/attention/kda.py", line 14, in <module>
    from attn_gym.linear._delta_rule.gate import _FusedGate
ModuleNotFoundError: No module named 'attn_gym'
```

Installing base `attn-gym` (pure Python, depends only on `torch`) gets as far as line 21 and then hits the backend guard:

```
  File ".../torchtitan/models/common/attention/kda.py", line 21, in <module>
    from attn_gym.linear.short_conv import causal_conv1d
ImportError: causal_conv1d requires the optional CuTeDSL backend: pip install attn-gym[linear]
```

## Why this looks unintended

The rest of the codebase already treats `attn_gym` as optional:

- [`attention.py`](https://github.com/pytorch/torchtitan/blob/main/torchtitan/models/common/attention/attention.py) guards its own kda import behind `if TYPE_CHECKING:` and uses a string annotation.
- `tests/unit_tests/cpu/test_qwen3_6.py` and `test_qwen3_8.py` call `pytest.importorskip("attn_gym")`.
- `tests/unit_tests/gpu/test_kda_attention.py` guards on `importlib.util.find_spec("attn_gym")`.
- `tests/integration_tests/models.py` carries the comment *"short_conv's CuTe/CUTLASS kernel (attn_gym) is CUDA-only."*

The runtime import in `__init__.py` is the one place that does not. It was introduced in #4639, which moved `kda.py` from `models/kimi_k3/` into the shared `models/common/attention/` package. Before that move the dependency was confined to a leaf module that only Kimi K3 imported, so the blast radius was contained.

## Change

Fall back to an inert placeholder when the import fails. The union alias, `__all__`, and the `models/common/__init__.py` re-export all keep working untouched, because the name stays bound either way -- this is a single hunk in a single file.

Constructing the placeholder re-raises the original `ImportError`, so KDA models fail at *build* time with an actionable message rather than every model failing at *import* time. `isinstance()` checks against it (e.g. `models/kimi_k3/model.py`) still evaluate correctly, to `False`.

One `except ImportError` covers both failure modes, since `ModuleNotFoundError` subclasses `ImportError`.

`cp_kda.py` needs no change -- it is not imported by the package `__init__`, only by tests and two function-local imports in `torchtitan_recipes/tests/suites/h100.py`.

This does not make KDA, DSV4's CSA path, or `torchtitan/rl/model/kda.py` work on non-CUDA accelerators -- those kernels genuinely are CUDA-only. It only stops unrelated models from paying for them.

## Test plan

Verified on Intel XPU (`torch 2.15.0.dev20260907+xpu`), branched off `286578760`:

- **attn_gym absent.** `import torchtitan.models.common` fails on `main` with `ModuleNotFoundError: No module named 'attn_gym'`; succeeds on this branch.
- **attn_gym present, CuTeDSL absent.** Import succeeds. The placeholder captures `ImportError: causal_conv1d requires the optional CuTeDSL backend: pip install attn-gym[linear]`, and constructing it re-raises exactly that error.
- `AttentionMetadata` union still forms, and `isinstance()` against the placeholder returns `False` rather than raising.
- `pre-commit run` passes on the changed file (flake8, ufmt, pydoclint, codespell, license, AST).
- `pyrefly 0.45.1 check` on the changed file: `0 errors`.

No numerics impact: on CUDA with `attn-gym[linear]` installed the `try` branch is taken and behavior is byte-identical to `main`.
