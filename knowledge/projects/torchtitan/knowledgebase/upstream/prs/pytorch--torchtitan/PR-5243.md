# [rl] DAPO-Math grader: score the right side of name = value, degrees against pi (2/2)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5243) · state: closed · merged: False

## Original PR description

**Stacked on** the previous PR ("read thin-space digit groups, compare words as strings"), which sits on the two approved DAPO-Math grader PRs ("score in grader processes with a hard timeout" and "box the gold answer before parsing"), carried on the base branch `felipemello1/dapo-math/trunk`. Once they merge, the stack retargets to main with no other change.

**TLDR:** The DAPO-Math grader scores ten kinds of correct answers 0, such as `\boxed{A_{\min}= \frac12}`, `\boxed{60^\circ}` against gold `\frac{\pi}{3}`, and `\boxed{-c + 2}` against gold `2 - c`. This PR scores them 1. In two INTELLECT-3-RL runs, 149 of 14,119 logged rollouts go 0 -> 1, all correct answers; in MathArena outputs, 29 of 19,974 do. 2 correct answers go 1 -> 0: they had matched only because Math-Verify dropped a variable from both sides.

**Problem**
1. **Named answers.** Models sometimes box the quantity's name: `A_{\min}= \frac12`, `k_{\max}(n)=2^{n-1}-n`, `|P|_{\max} = 2^{999} - 2^{499}`.
2. **Math-Verify.** It reads `x = 5` as 5, but parses `A_{\min}= \frac12` to nothing and `k_{\max}(n)=...` to 2.
3. **Degrees.** `60^\circ` parses as 60 and gold `\frac{\pi}{3}` as 1.047, so the right angle scores 0.
4. **Units.** Math-Verify drops trailing units, including the letters `c`, `m`, `g`, `t`, `h`, `s`, `d`, `l`, `o`, so it reads `2 - c` as `2 -`. In the 131K-context run, `\boxed{-c + 2}` scored 0 and `\boxed{2 - c}` 1 for gold `2 - c`.
5. **Delimiter sizes.** Math-Verify cannot parse `\big`, `\Bigl`, `\biggr` and the rest, so `4\pi\bigl(2-\sqrt3\bigr)` parses to nothing.
6. **Cost in training.** In two Qwen3.5-35B-A3B-Base runs on INTELLECT-3-RL math, 149 logged rollouts were correct answers scored 0 this way. In the first run, in 4 of the 5 degree prompts a sibling wrote `\frac{\pi}{3}` and scored 1, so the group advantage pushed the model away from a correct `60^\circ`.
7. **Cost in eval.** In MathArena's outputs, 29 answers that MathArena marks correct score 0: 22 named, 7 with delimiter sizes.

**Solution**
1. When the box doesn't match, `score_math_response` retries on the text after the box's last `=`.
2. It skips the retry when:
   - that `=` is part of `>=`, `<=` or `!=`, or sits inside braces (`\sum_{k=1}^{n} k`);
   - the box is a list: a comma, a semicolon, or the word `or` or `and`. So `x = 2 \text{ or } x = 3` still scores 0 for gold 3;
   - the gold is itself an equation. Math-Verify drops an equation gold's left side when the answer has none, so `\boxed{y = 3}` would match gold `x = 3`.
3. When only the gold has a `\pi`, `_DEGREES` rewrites the answer's `60^\circ` as `(60\pi/180)`; when only the answer has one, it rewrites the gold's.
4. Six more forms Math-Verify misreads, found in a second run's zeros. Each line is answer, gold, then what the grader does:
```text
p \le 0                                         p\leqq0                 Math-Verify reads `\leqq` as `\le q`: rewrite `\leqq` / `\geqq` as `\le` / `\ge`
-12\%                                           -12                     on a miss, retry with `\%` dropped from both sides
x = \frac{3\pi}{2} + 2\pi k,\ k \in \mathbb{Z}  \frac{3\pi}{2}+2k\pi    read as 2; on a miss, retry without `, k \in \mathbb{Z}`, `\text{ for all } n` or `\forall k`
-1 < x < \sqrt{2}-1                             (-1, \sqrt{2}-1)        Math-Verify's allow_set_relation_comp, for a solved inequality only
120^\circ                                       \gamma = 120^\circ      for an answer without `=`, retry on the gold's right side when its left side has no symbols
\frac{50}{3}                                    16.67                   a gold with 3+ significant digits compares at its own decimals (6 at most)
```
5. Each has a guard, and these stay 0:
```text
2 \forall n \geq 3,\ 1\ (n < 3)                  2                       piecewise: `&` or `\\` rows, or a `,`, `;`, `=`, `\text`, `\quad` or second qualifier after it, keep it whole
2 \forall n \geq 3 \quad 1\ (n < 3)              2                       the same, cases separated by `\quad`
x^2 - 3x + 2 < 0                                 (1, 2)                  unsolved: Math-Verify would solve it, so a copy of the problem would match (3 INTELLECT-3-RL problems)
1 < x < 2                                        1, 2                    a finite-set gold: Math-Verify equates an open interval with any 2-element set
\beta = 120^\circ                                \gamma = 120^\circ      the answer has its own left side
7                                                2x + 1 = 7              the gold's left side has a symbol
\frac{19}{100}                                   0.2                     under 3 significant digits the gold may be exact
27.5\%                                           27.78\%                 a percent gold rounds in percent
```
6. Units. `_matches` also parses each side with units kept. `_drop_units` keeps Math-Verify's unit drop only when the dropped letters are in `\text` or multiply a bare number (`5 cm`), and the other side does not have them:
```text
-c + 2                                           2 - c                   1   `2 -` does not parse, so `2 - c` is read with its `c`
\frac{8h}{5}                                     \frac{8}{5} h           1   the answer has `h`, so the gold keeps it
5 cm, 3 h, 12 \text{ m}                          5, 3, 12                1   units after a number still drop
4                                                n = 4m                  0   `n = 4` still has a symbol: `m` is a variable
70                                               15+55m                  0   `15+55m` is a sum, not a number times a unit
2 - m                                            2 - c                   0   both read as `2 -` before
```
7. Delimiter sizes. `\big`, `\Big`, `\bigg`, `\Bigg` and their `l`/`r`/`m` forms are dropped from both sides (not `\bigcup`); Math-Verify already drops `\left` and `\right`. So `4\pi\bigl(2-\sqrt3\bigr)` matches `4\pi(2-\sqrt{3})`, and `\biggl[0, 1\biggr)` no longer reads as 1.
8. Unchanged: the right-side retry runs only after a miss, and without a `\pi` on the other side degrees stay as written (`336^\circ` still matches `336`).

**Results**
```text
answers scored 1, previous PR -> this PR (math-verify 0.9.0, 5 s grader timeout)
Qwen3.5-35B-A3B-Base, INTELLECT-3-RL, steps 1-51                5,424 rollouts   4,057 -> 4,124   +17 named or degrees, +41 six forms, +3 / -1 units, +7 sizes
Qwen3.5-35B-A3B-Base, INTELLECT-3-RL, 131K context, steps 1-48  8,695 rollouts   5,906 -> 5,986   +11 named or degrees, +58 six forms, +4 / -1 units, +8 sizes
MathArena AIME/HMMT/Apex outputs                               19,974 answers   14,887 -> 14,916  +22 named, +7 sizes, all labeled correct by MathArena
DAPO-Math runs (4B and 30B)                                    12,231 rollouts   4,507 -> 4,507
each distinct gold against itself                               9,789 golds      unchanged
20,000 random pairs of different golds                                           10 -> 10 (pairs of equal golds)
```
Every flip was read by hand. Each 0 -> 1 is a correct answer, the rounded ones at the gold's rounding. The two 1 -> 0 are correct answers that matched only because Math-Verify dropped a variable from both sides: `n = 6k,\ \text{where } k \text{ is a positive integer}` vs gold `n = 6m`, and `f(x) = c \text{ for all } x \in \mathbb{R}, \text{ where } c \in \mathbb{R}` vs gold `f(x) = c` (both read as `f(x) =`). The runs log the highest- and the lowest-reward rollout of each group; only completed ones are counted.

By the rule that scores them (removing it turns the answer back to 0), the 58 in the 131K-context run are: 19 rounded golds, 11 rounded percent golds, 2 one-sided `\%`, 11 qualifiers, 8 golds with a symbol-free left side, 5 inequalities, 2 `\leqq`.

You may ask:
- Why not a Math-Verify option? Its own fallback takes the right side only of a 3+ part chain (`a = b = c`); `NormalizationConfig(equations=True)` is the same rule, and deprecated. latex2sympy can convert degrees, but `parse` hardcodes `convert_degrees=False`.
- Why only after a miss? Run first, a rewrite breaks matches: dropping `\%` turns `12\%` vs gold `0.12` from 1 to 0, and dropping the qualifier turns `F(n)=1\text{ for all }n\in\mathbb N` vs gold `F(x) = 1` from 1 to 0, because Math-Verify reads the whole box as 1 but `F(n)=1` as an equation in another variable.
- Why the last `=`? Chains like `\frac{3}{2\sqrt7} = \frac{3\sqrt7}{14}` end with the simplest form.
- Why skip lists? `a=4,\ b=-1` against gold `-1` would score 1 although the question may ask for `a`.
- Why 3 significant digits for rounding? Rounding at 1 decimal scored `\frac{19}{100}` 1 against gold `0.2` (a phone-dialing probability, exactly 1/5). With 3+ significant digits a gold allows 0.5% at most; it costs `\frac{1}{3}` vs `0.33`, which stays 0.
- Why not turn Math-Verify's units off? 177 matches on these data sets go 1 -> 0, e.g. `60\ \text{km/h}` vs gold 60 and `16\text{ cm}^2` vs gold 16.
- Why not retry with units kept on both sides? Math-Verify's units-kept parse of an annotated answer falls back to odd readings: `F(n)=1 \text{ for all } n \in \mathbb{N}` parses as 1.

NOTE:
- Known leniencies, accepted: `0.5\%` matches gold `0.5`; an exact `12.5` also accepts `12.46`; a point gold `(1, 2)` accepts `1 < x < 2`, since Math-Verify parses `(1, 2)` as an interval; `\boxed{180^\circ}` matches gold `\pi` whatever the question asks; `6` still matches gold `6m` (a number times a letter can be a unit, `3 h`; no rollout hits it).
- 6 of the 88 distinct golds the gold right-side rule applies to accept a wrong answer (`\gcd(m,n) = 1` accepts `1`). A guard would also reject right ones (`e = 3/5`), so those golds go to the data review.
- Still 0, as on the base: an answer with its own left side against an equation gold (`\boxed{n = 1972}` vs gold `x = 1972`).
- Now 0 (were 1), and absent from the data: a bare unit inside a relation (`x = 5 cm` vs `x = 5`); a unit word against a one-letter unit (`1.04 meters` vs `1.04\,\text{m}`).
- Cost: each score parses both sides twice, 0.72 -> 0.80 ms in-process on DAPO golds (1.0-1.4x). A degenerate 100K-character box that hits every retry takes ~50 s instead of ~5 s in-process; the pool's 5 s timeout scores it 0 either way.
- Not run: GPU or end-to-end RL; the change is grader-only.
