## Why

TorchTitan's V4 model cannot represent V4.1's shared global KV, decoder candidate reindexing, single-pass mHC, or Engram phrase memory. The initial port needs a native text model, HF checkpoint loading, reference comparisons, and an FSDP training baseline.

A V4.1 block also returns several tensors with different layouts: a sequence-sharded residual and replicated shared KV/index state. The existing shared components need explicit FP32 expert operands for our reference comparisons, independent tuple layout checks, and per-input FSDP identity type rules. This increment includes those supporting changes with the model they enable.

**Example.**

```python
from torchtitan.config.parallelism import ParallelismConfig
from torchtitan_recipes.tests.models.deepseek_v4_1 import deepseek_v4_1_debugmodel

config = deepseek_v4_1_debugmodel(
    parallelism=ParallelismConfig(data_parallel_shard_degree=2),
)
# The upstream empty-DTensor identity-view checker gap is documented below.
config.debug.spmd_typechecking = False
config.debug.seed = 42
config.debug.deterministic = True
```

```text
Full producer -> shared global KV/index keys -> Reindex/Reuse consumers
hidden-state chain continues through every encoder and decoder block
```

## What changed

- Add the teacher-forced text backbone, CSA2 selection and explicit shared state, two single-pass mHC residual updates per block, and causal 2/3/4-gram Engram.
- Reuse V4's public attention-gym sparse kernels and shared RoPE, norms, grouped MoE, bounded SwiGLU, rematerialization, and FSDP.
- Add released Flash and reduced debug flavors through the public config API. Map HF keys and expose FP8/packed-FP4 weights as logical tensors through public, slice-aware DCP loading.
- Add an explicit expert compute dtype for FP32 reference comparisons; grouped weights follow the input operand dtype. BF16 remains the standard expert configuration. The BF16-only Dist-MoE transform rejects FP32 source configurations.
- Check each declared flat tuple source layout independently, and preserve each input's layout through FSDP identity outputs. The private FSDP autograd type rule has an upstream TODO and issue link: https://github.com/pytorch/pytorch/issues/203261. It adds no collective or tensor computation.
- Expose an optional static `PipelineStage` metadata factory through the shared pipeline constructor, reusing the existing fake-decoder metadata path. The V4.1 pipeline consumer is added in `4/n`; this text baseline has TP=EP=PP=1 and CP=1.
- Add a pinned independent author comparison and focused CPU coverage for model features, loading, expert precision, tuple layouts, and pipeline metadata.

Flavor constants and HF key translations are mechanical. The shared-state forward path, quantized slice reader, and supporting shared-component changes require correctness review.

## Alternatives considered

- Extending the V4 model would mix architectures with different shared-state and checkpoint contracts.
- A separate V4.1 MoE or pipeline constructor would duplicate existing dispatch, rematerialization, and stage construction.

## User-facing changes

| Before | After |
| --- | --- |
| No native V4.1 model/config | Released Flash and debug text flavors with a teacher-forced FSDP baseline |
| No V4.1 shared-KV checkpoint mapping | Native/HF mapping and slice-aware quantized loading |
| Routed expert GEMMs force BF16 | BF16 standard configuration and an explicit FP32 reference option |
| Flat tuple outputs lack independent source-layout checks | Each tuple value is checked against its declared source layout |
| FSDP identity typing merges independent input layouts | Each identity output retains its corresponding input layout |
| Pipeline constructor has only its built-in fake-decoder metadata path | An optional model factory supplies complete public stage metadata |

These reduced ten-step runs validate training execution and numerical behavior; full-size convergence is not established. Optimized serving prefill and packed incremental cache allocation are outside this teacher-forced training implementation.

## Testing

The unchanged source has passing CPU coverage for shared linear/Dist-MoE precision (75 tests and 14 subtests), layouts/base modules (33 tests), pipeline/SPMD integration (56 tests), and text features/loading (15 tests). These suites overlap; the counts are not additive. All-file pre-commit passed.

- Precision tests guard silent operand downcasting and backward drift.
- Tuple/FSDP tests check independent layouts, exact values, independently weighted gradients, and the post-backward callback.
- Pipeline tests check metadata reaches the owned global stage indices under interleaving.
- Model tests cover quantization rounding/STE, mHC formulas, Engram document boundaries, sparse selection, packed/causal outputs and gradients, HF round trips, and unaligned quantized reads across files.

Native FSDP2 training and the V4 regression used two GB300 GPUs with the published, unmodified ARM PyTorch `2.16.0.dev20261030+cu132` wheel.

## Known issues and validation provenance

The optional SPMD checker rejects upstream DTensor identity views of empty cache tensors. The FSDP baseline explicitly disables that checker; the tuple identity rule above does not resolve the separate empty-view limitation. Nested tuple output redistribution is also unsupported and rejected explicitly.

This increment groups the previous supporting commits with the original text baseline. Its complete file tree is identical to the previously validated and pushed commit `121d222c67d5c8bc212b69387f4a394192bcf289`. Existing numerical results remain bound to their original source commits; the regrouping changes commit history rather than model computation.

Stack position: `1/n`; base `main`. Later increments add vision (`2/n`), DSpark (`3/n`), and additional parallelisms/CI (`4/n`). See the model's `README.md` and `VALIDATION.md` for commands and limits.
