# [loss_compare] Log full loss and grad_norm on metric mismatch

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5172) · state: closed · merged: True

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.12.0) (oldest at bottom):
* __->__ #5172

When numerics intentionally change, it's pretty annoying to regenerate new golden loss/grad norm, especially when you don't have the right hardware. This logs both expected / failing loss & norms on all steps when they fail.

Before:

```
[LOSS_COMPARE] Asserting loss values are equal...

[LOSS_COMPARE] loss assertion failed!
[LOSS_COMPARE] Actual baseline loss values (can be used to update the import file if the change is expected):
[LOSS_COMPARE] Note that you should verify the loss curve change is not a regression first!!!
1 8.023916244506836
2 7.69608211517334
...
10 4.052786350250244
```

first, as before):
