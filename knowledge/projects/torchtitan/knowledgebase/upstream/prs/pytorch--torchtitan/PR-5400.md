# Make the FlexAttention causal mask type configurable

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5400) · state: open · merged: False

## Original PR description

## Summary

FlexAttention always builds a block-causal mask, which is causal within each
packed document. This PR adds `FlexInnerAttention.Config.mask_type` so a model
can choose plain `"causal"` instead, matching the transformers backend's
`attn_mask_type`.

- `"block_causal"` is the default and keeps today's behavior.
- `"causal"` doesn't depend on `positions`, so the mask is the same for every
  batch. It's only correct when each sequence holds one document.

A private `Config._causal_mask_mods(positions)` returns the selected mask_mods
and raises `ValueError` on an unknown `mask_type`.
`FlexInnerAttention.Config.build_attention_metadata` and
`SlidingWindowFlexInnerAttention.Config.build_attention_metadata` use it instead
of composing the masks inline; the sliding-window config inherits both the field
and the method from its base. Masks are unchanged for every existing config.

## Test plan

`tests/unit_tests/cpu/models/common/test_flex_attention.py`: 6 passed
(2 existing, 4 new).

- **mask_mods.** On packed and single-document positions, `block_causal` is
  causal ∧ same-document and `causal` is causal. The two agree on
  single-document sequences, and `block_causal` is a strict subset of `causal`
  on packed ones.
- **Mask builders.** For both flex configs, the mask returned with `"causal"`
  differs from the default `block_causal`, and the default is `"block_causal"`.
  That covers both the full and sliding-window masks. It fails if either config
  ignores `mask_type`.
- **Guard.** An unknown `mask_type` raises `ValueError`.
