# [release/0.4][RL] Keep EnvServer workers torch-free

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5615) · state: closed · merged: True

## Original PR description

## Summary

Disable the release-only PyTorch pipeline compatibility shim in fresh Verifiers EnvServer pool workers.

## Why

A Terminal Bench worker imports its local taskset through `torchtitan`. On release/0.4, importing the package applies temporary PyTorch 2.15 pipeline backports and therefore imports Torch, even though EnvServer workers do not construct pipeline schedules. This violates the worker isolation contract and fails `test_env_server_workers_skip_the_trainer_imports`.

The EnvServer process now sets `TORCHTITAN_DISABLE_TORCH_COMPAT=1` before `serve_env` starts its pool. Fresh workers inherit the setting, while trainer processes continue to apply all required PyTorch 2.15 backports. The existing strict assertion remains unchanged.

Failure: https://github.com/pytorch/torchtitan/actions/runs/40066514161/job/120790868785

## Test plan

- `git diff --check`
- Torch 2.15 subprocess probe: importing `torchtitan` loads Torch normally, while `TORCHTITAN_DISABLE_TORCH_COMPAT=1` keeps it unloaded.
- The targeted Terminal Bench test is skipped locally because the optional `verifiers` package is unavailable.
- All available pre-commit hooks pass. Pyrefly could not run because the local environment does not provide the `pyrefly` executable.
