# [rl][observability] Rollout workers write structured logs (5/14)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5461) · state: open · merged: False

## Original PR description

**TLDR:** Rollout worker processes never set up the structured logger, so the spans that run in them (`generate`, `score_group`, `score_single_rollout`) were dropped. Each worker now writes its own JSONL to the controller's folder, only when structured logging is on.

**Problem**
1. The controller's `GenerateFn` and the rubric run inside `RolloutWorkerActor` processes.
2. Those processes never call `init_structured_logger`; the batcher, generator and trainer do.
3. So per-turn generate latency and grading time are missing from the trace, though the worker already sets their step (`RolloutWorkerActor.sync_log_step`).

**Solution**
1. `MonarchActorSystem.spawn_rollout_workers` passes `sl.get_structured_logger_subprocess_init_fn()` to each worker: the controller's init fn, or None when structured logging is off.
2. Each worker calls it with `source="rl_rollout_worker"` and its pool rank, and writes `structured_logs/rl_rollout_worker.global_rank_<i>.<timestamp>-<random>.jsonl`.
3. Unchanged: `Rollouter.setup_async`. The Verifiers rollouter spawns no workers until PR 13 moves its groups into them.

**Results**
```text
H100 CI job rl_grpo_kimi_k3_debug_batch_invariant, 3 steps, 4 rollout workers (measured before `spawn_rollout_workers` moved into `MonarchActorSystem`)
worker  records  bytes   generate_start  score_group_start  steps
0       160      133 KB  16              11                 1, 2, 3
1       164      136 KB  16              13                 1, 2, 3
2       302      251 KB  31              22                 1, 2, 3
3       250      208 KB  27              18                 1, 2, 3
main (same job and base): no rl_rollout_worker file
```

You may ask: why not pass `output_dir` and the on/off flag to `setup_async`? The init fn carries both in one value, as the checkpointer forwards it to its save subprocess.

NOTE: about 0.8 KB per record. Records before the controller's first `sync_log_step` have no step, as in the other processes. The workers also write the env and config `build` spans.

reply from claude:
- **How many:** a handful, 4 by default (`worker_pool_size`). Verifiers spawns none here; from PR 12 on, its groups use the same pool.
- **Sanity pass:** I spawned 4 real worker processes with structured logging on and sent 12 groups.
  - Each worker wrote its own `rl_rollout_worker.global_rank_{0..3}.*.jsonl`.
  - Records carry the right source, rank and step, and spans pair start/end.
  - `choose` spread the 12 groups 7/2/0/3, so short bursts don't land evenly.
- **Rank:** unique among workers: it's the worker's position in its mesh (0..N-1). The file name also has a timestamp and a random suffix.
- **Verifiers:** nothing extra. From PR 12 on, its groups run in these same workers and get the same logger. Verifiers' env-server workers are separate, torch-free processes.
- **Decorators:** none needed now. The controller times each group (`rollout_group`), and the workers already log `score_group`, `score_single_rollout` and, from PR 9, `generate`.
- **The comment in `system.py`:** dropped.
