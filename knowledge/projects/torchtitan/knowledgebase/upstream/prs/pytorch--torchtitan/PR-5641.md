## Original PR description

Enable `fused_mla` with AllGather/Ulysses CP, applying K RoPE and materialization after communication.

### Review: [CP] Support fused MLA kernels with context parallelism

- [x] Gather context / diff
- [x] Review changes
- [x] Post review

The design holds up. Before this PR, `FusedMLAAttention.forward` skipped `MLAAttention.forward` and called the inner Q/K/V backend directly. That is why CP was rejected. Now there is one `materialize_kv` hook, so the CP backend keeps doing the compact communication (all-gather / all-to-all) and the fused kernel only swaps in the K-RoPE + K/V assembly step. CP and non-CP run the same code, and only the position gather depends on CP. The hand-written SPMD layout asserts and the `spmd.local()` block are gone. The fused path also no longer repeats `wkv_b`/view/remat bookkeeping that `project_mla_kv` already does. I found no correctness bugs. Notes below, most important first.

#### Correctness checks (no action needed)
- **Token order.** In both backends the shared key `k_pe` and `positions_T` are gathered with the same rule: `S(0) -> R` over the CP group (AllGather via `cp_all_gather_tensors`, Ulysses via `spmd.redistribute`). So after the gather, row `t` of `k_shared_TR` lines up with `positions_T[t]`. This also holds under HeadTail: each rank's positions are already permuted locally, and the gather puts them in rank order.
- **`q_nope_dim`.** `q_THK.shape[-1] - k_shared_TR.shape[-1]` equals `qk_nope_head_dim` on both paths. Ulysses splits `q_THK` back to its full `K` before calling the materializer.
- **`positions=None` under CP.** `arange(num_tokens)` is local and then gathered, so K positions become `[0..T_local-1]` repeated per rank. The stock path does the same thing: it rotates locally, then gathers. So this matches stock. Flagging it only so nobody assumes the gather fixes `None` positions.
- **Remat.** The old `recompute_needs_tensor(kv)` on the `wkv_b` output is now covered by `MLAAttention.forward`'s `recompute_needs_tensor(kv_THP, k_shared_TR)`. The materializer also still runs outside the `inner_attention` region, as before.

#### Suggestions

1. **A core interface changes for a recipe override** (`mla.py:111-112`, `cp_mla.py:91-92`). CLAUDE.md says "Don't leak experiments into core": `torchtitan_recipes/overrides/` gets a new kwarg on `MLAAttention.forward` and `UlyssesMLAAttention.forward`. The hook is small and generic (not an `if fused:` branch), and I don't see a cleaner option. Maintainers should still sign off on it explicitly. If it stays:
   - Add a type annotation, e.g. `materialize_kv: Callable[[Tensor, Tensor, Tensor], tuple[Tensor, Tensor]] = materialize_mla_kv`.
   - Add one docstring line describing the contract: inputs are post-communication `(q_THK, kv_THP, k_shared_TR)`, and the output is `(k_THK, v_THV)` in the same token order.
   - Optional: `AllGatherKVMLAFlexAttention.forward` passes `materialize_kv` through `**kwargs` without declaring it, while Ulysses declares it. Declaring it in both would make the contract clearer.

2. **The position all-gather runs once per layer, outside any remat region** (`fused_mla.py:1082-1087`). The PR description already says this. Every layer gathers the same `positions` tensor, and full activation rematerialization re-runs it in backward as a bare collective. That tensor is identical across layers, so a follow-up could gather it once per step (for example next to where CP shards the batch) or cache it. For now, a `# TODO:` in the code would keep this from being forgotten.

3. **Gathering untyped `positions` under SPMD type checking.** When `positions is None`, `positions_T` is a fresh `arange` with no SPMD type, and it goes into `spmd.redistribute(src=S(0), dst=R)`. Your CP=2 runs passed with type checking on, but they probably used explicit positions (packed documents). If the `None` + CP + type-checking combination was never run, it's worth one quick check.

4. **The error message got less helpful** (`fused_mla.py:1015-1018`). The old message told users what to do ("Remove the fused_mla override..."). The new one lists the supported backends but doesn't name the one that was configured. Suggested:
   ```python
   f"FusedMLAAttention supports only AllGatherKVMLAFlexAttention and UlyssesMLAAttention "
   f"CP backends, got {type(config.inner_attention).__qualname__}. Remove the fused_mla "
   "override to use this backend."
   ```
   No test covers this rejection anymore. A small test that builds an unsupported CP config would keep it covered.

5. **Typecheck rule** (`fused_mla.py:885`). Using `einsum("bthp,btr,bt->bthp", ...)` to derive the output type is cleaner than the old hard-coded `PartitionSpec`s. One thing to confirm: in the non-CP case, `positions` may be an untyped `arange` from `_resolve_positions`. Check that `spmd.rules.einsum` accepts that operand, or that this path never runs while type checking is active. You said type-checked runs passed, so this is just to confirm coverage.

#### Tests
- The CPU config test now checks the module type, the inner backend type, and that `state_dict` keys match stock for both transform orders. That covers checkpoint compatibility.
- The CP numerical checks (AllGather / HeadTail / Ulysses on 2 GPUs) were run from an external script and are not checked in. CLAUDE.md asks for GPU integration tests when parallelism is involved. Adding even one CP=2 integration test with the `fused_mla` override in `tests/integration_tests/` would protect this path from regressions.
- The C4 loss table (max loss difference ~1.5e-3 over 50 steps, both backends) fits the explanation that K RoPE's backward now runs before CP gradient reduction, which reorders floating-point operations. That counts as convergence evidence for a computation change.

#### Nits
- `fused_mla.py:1100` has a stray blank line before `# The copy below...`.
- The module docstring says "Backward inverse-rotates each rank's contribution before CP gradient reduction." Mentioning there that this is why results aren't bitwise identical to stock would help future readers.

I did not run tests or pre-commit; this was a static review.
