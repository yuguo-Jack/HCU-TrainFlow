# [attention] Deterministic mode: turn off cuDNN attention (its varlen backward is not deterministic)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5480) · state: open · merged: False

## Original PR description

**Needs retesting on Blackwell.** The check below ran on one H100; Blackwell (FA4) was only measured with an earlier version of this PR.

**TLDR:** `--debug.deterministic` is not reproducible with varlen attention: torch's varlen picks cuDNN when it is eligible, and cuDNN's backward is not deterministic (on one H100, `dq` differed from the first run in 2 of 4 reruns). Deterministic mode now turns cuDNN attention off, so varlen runs Flash (FA3 on H100, FA4 on Blackwell), whose backward is deterministic.

**Problem**
1. With no backend priority set, `varlen_attn` tries cuDNN first, then Flash (`torch/nn/attention/varlen.py:53`, nightly 2.16.0.dev20261013).
2. cuDNN varlen is eligible on H100 and Blackwell with cuDNN >= 9.18 (`varlen.py:72`), for GQA too, with head dims <= 128, plus 192/128 backward on Blackwell (`varlen.py:29`).
3. Its backward is not deterministic: gradients differ across 5 runs even with every torchtitan deterministic flag on.
4. Varlen is the default backend, so deterministic runs aren't reproducible for Qwen3 and Llama 3 (head dim 128) on H100 and Blackwell, gpt-oss's full-attention layers (head dim 64), and DeepSeek-V3 (192/128) on Blackwell.
5. Not affected: real Qwen3.5 sizes (head dim 256 has no cuDNN backward), the batch-invariant RL recipes (they pass `num_splits=1`, which cuDNN rejects: `varlen.py:163`), and sliding-window layers.

**Solution**
1. `set_determinism` calls `torch.backends.cuda.enable_cudnn_sdp(False)` next to the other deterministic switches.
2. Flash's backward reads `torch.are_deterministic_algorithms_enabled()` (FA3 and FA4).
3. Unchanged: runs without deterministic mode, and the RL generator (it sets its own deterministic flags).

**Results**
Numerics: deterministic mode only. Varlen runs Flash instead of cuDNN there, so outputs and grads differ from main by rounding (another kernel).
```text
varlen_attn fwd+bwd, run 5 times with the same inputs; outputs and grads compared bitwise to run 1
Qwen3-0.6B attention shape: 16 query / 8 KV heads, head dim 128, 4 packed documents (8192 tokens), causal, bf16
deterministic switches as in set_determinism; torch 2.16.0.dev20261013, cuDNN 9.26, one H100
main:     backend CUDNN_ATTENTION   dq differs from run 1 in runs 4 and 5 (out, dk, dv equal)
this PR:  backend FLASH_ATTENTION   all 5 runs bitwise equal (out, dq, dk, dv)
```
An earlier version (a per-call pin, FA4 only) measured bitwise-equal grads across 5 runs on Blackwell, hd192/128 and hd128, eager and `torch.compile(fullgraph=True)`.

You may ask:
- Why not pin Flash per call in `VarlenInnerAttention` (the earlier version)? torch's varlen reads the same global flag, and one switch next to the other deterministic switches also covers context parallel and any other SDPA call, with no branch in the forward.
- Why not pin Flash in every mode? cuDNN may be faster outside deterministic mode; that needs a speed comparison, not a reproducibility fix.

**Test plan**
- The H100 check above (attention op alone, not a full training step).
- `pytest tests/rl/unit_tests/gpu/test_bitwise_parity.py` (calls `set_determinism` on the trainer side).
