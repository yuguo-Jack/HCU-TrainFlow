# [WIP] Integrate last-words checkpoints with TorchFT training

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5638) · state: open · merged: False

## Original PR description

Integrate completed-boundary emergency checkpoints with experimental TorchFT training. The application binds full model, optimizer, scheduler, optional EMA, counters and per-logical-replica dataloader/RNG state, and rejects partial updates, partial healing and unknown commits.

Periodic restore separates the saving replica's dataloader from the receiver's bound cursor. Restore checks required-state schemas, DCP metadata/storage coverage and independent live schemas before mutation, and rejects required-state exclusions. Retention uses a pure preflight shared with recovery and covers periodic, terminal and elastic-event checkpoints. Workers atomically publish persisted candidates; supervisor validation and restart compatibility checks remain separate acceptance steps.

Validation: focused CPU/DCP probes and complete schema/retention module tests passed. Both wheels, including TorchFT's native extension, have been rebuilt from the paired fixed commits. Installed-package, distributed recovery and NPU numerical acceptance remain in progress; historical v0.3 candidate runs are not evidence for this Main implementation. Deterministic mode is disabled for the authorized NPU functional scope, so no bitwise trajectory claim is made. Performance is deferred.

Keep this PR Draft/WIP pending that acceptance.
