# [gpt_oss][perf] Compile the attention sink rescale as a local region

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5193) · state: open · merged: False

## Original PR description

**TLDR:** Compile GPT-OSS's attention-sink rescale as the `attention_sinks` region: 16k step -3.9%.

**Problem**
1. **Sinks.** GPT-OSS attention rescales its output by `sigmoid(lse - sinks)` (`apply_attention_sink_rescale`, the varlen/flex out_transform).
2. **Eager today.** It runs between the attention kernel and the output projection, outside any region.
3. **Slow kernels.** Eager runs it as non-vectorized broadcast kernels on `[T, H, head_dim]`, plus a separate reduction for the sink grad.
4. **Cost.** ~1.2 ms per 2 layers at 16k, vs ~0.2 ms ideal.

**Solution**
1. **Region.** `apply_attention_sink_rescale` becomes the `attention_sinks` region; rescale and sink-grad reduction fuse.
2. **Enabled** in `GptOssModel.Config`.
3. **Unchanged:** the math and the attention kernel.

```text
before:  attn kernel -> out * sigmoid(lse - sinks) (eager broadcasts) -> wo
after:   attn kernel -> [attention_sinks]                             -> wo
```

**Results**
```text
GPT-OSS 20b layers 0-1, 16k tokens, fwd+bwd wall, GB300, on top of #5160 + PR 1
interleaved in one process (1 foreign job present)   25.23 -> 24.25 ms  (-3.9%)
1 process (indicative)                               25.70 -> 24.69 ms
correctness: CPU fp64 parity vs eager, output and grads of out, lse, sinks
graphs: attention_sinks 3 (static, dynamic, no_grad)
```

NOTE: the RL vLLM wrapper also calls this function (inference, `no_grad`): one more graph per shape there if the generator binds the same regions.
NOTE: not yet measured under CUDA graphs. Not tested: TP-sharded sinks (the recipe runs TP=2), flex backend.

**Test plan**
`pytest tests/unit_tests/cpu/test_gpt_oss_compile.py -k test_compiled_attention_sinks_match_eager`

Stack: 2 of 2. Branch `felipemello1/lcp/gptoss-2-attention-sinks`.
