# [distributed] Add a manual collective-order fault probe

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5658) · state: closed · merged: False

## Original PR description

Superseded by [#5663](https://github.com/pytorch/torchtitan/pull/5663), which combines the FSDP communicator fix with this tested repro and evidence under `tranle-fw`.

Superseded by [zpcore/torchtitan#1](https://github.com/zpcore/torchtitan/pull/1), which targets the branch behind [pytorch/torchtitan#5645](https://github.com/pytorch/torchtitan/pull/5645) and carries the same tested script and sanitized evidence.

- Adds an 82-line manual collective-order reproducer for #5645: matching warmup, then rank 0 submits **A2A→AG** while ranks 1–3 submit **AG→A2A**. `--separate-group` gives AG its own communicator.
- Fresh run of the unchanged script: **shared PG 0 / sequence 3 times out** (rank 0 A2A versus peers AG); **separate communicators pass on all four ranks with exact outputs**, exit 0. Sanitized evidence below.
- This is an intentional host-order fault diagnostic. Separate-group completion is measured here, not a general reversed-order guarantee ([NVIDIA ordering contract](https://docs.nvidia.com/deeplearning/nccl/archives/nccl_2307/user-guide/docs/usage/communicators.html#using-multiple-nccl-communicators-concurrently)). Kept in draft for review.

<summary>Reproduction commands and measured setup</summary>

Exact tested source: [`3803b11c`, fault at line 56](https://github.com/tranle-fw/torchtitan/blob/3803b11c8b822667fab627bd222fe86fced55ff9/scripts/repro_collective_order.py#L56). Both runs used the same four B300 GPUs and PyTorch `2.13.0a0+8145d630e8.nv26.06`, CUDA 13.3, NCCL 2.30.5.

Run each case in a separate process/container with an external deadline. Equivalent local invocations with the recorded communication settings:

```bash
export NCCL_LAUNCH_ORDER_IMPLICIT=1
export NCCL_CUMEM_ENABLE=0 NCCL_CUMEM_HOST_ENABLE=0 NCCL_NVLS_ENABLE=0
export NCCL_SOCKET_IFNAME=lo NCCL_DEBUG=WARN TORCH_NCCL_DUMP_ON_TIMEOUT=0

timeout --signal=KILL 150s torchrun --standalone --nproc-per-node=4 scripts/repro_collective_order.py
timeout --signal=KILL 150s torchrun --standalone --nproc-per-node=4 scripts/repro_collective_order.py --separate-group
```

The measured runs used a container deadline and a CUDA-readiness gate before process-group creation; neither changes the script's fault phase. No GPU delay is injected. Source SHA256: `fb0abc0ec4a74a099a8f89125bf71e270cd9092253191f4c7e62aea79f6e88be`.

Four CUDA ranks; PyTorch 2.13.0a0, CUDA 13.3, NCCL 2.30.5; `NCCL_LAUNCH_ORDER_IMPLICIT=1` in both runs. After matching AG→A2A warmup, rank 0 deliberately submits A2A→AG while peers submit AG→A2A.
