# [profiler] add a minimal always-on kernel timeline

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5527) · state: open · merged: False

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.15.0) (oldest at bottom):
* __->__ #5527
* #5526
* #5136

Profiler.Config.always_on records every training step's GPU kernels with
Cuspy for the whole run, keeps the last num_steps steps in host memory, and
writes them as a Chrome trace every dump_freq steps to
profiling/always_on/iteration_N/rank{R}_trace.json.gz, so any recent step can
be looked at, not only a profiling window chosen up front.

torch's NodeTimerObserver records only each kernel's start, end, stream and
CUDA graph node -- no CPU events. At each step end the boundary is stamped in
CUPTI's record clock and the spans delivered so far are drained with a plain
(non-syncing) CUPTI flush and bucketed into their steps. Kernel names come from
each CUDA graph at instantiation, annotations from torch's CUDA graph
annotations, and lanes from torch's graph lane resolver where torch has one;
eager kernels are written unnamed. A dump skips the newest finished step,
whose kernels may still be running.

Kineto cannot initialize CUPTI while Cuspy holds it, so scheduled profiling
must use profiler.cuspy when always_on is set.

Overhead, steady-state steps 11-30, 5 interleaved runs each, no dumps:
- Llama3 8B FSDP2 x TP2 GraphTrainer on 4 GB300s (~3,900 kernels/step,
  ~0.58 s/step): median tps 14,119 -> 14,016 (-0.7%; -1.8% by mean, which one
  slow run pulls down). The training-thread cost of each step's drain and
  bucketing is ~1.5 ms (~0.3% of a step); the rest is CUPTI collection.
- Llama3 debugmodel on 1 GB300 (~600 kernels/step, ~7 ms/step): no
  difference above run-to-run noise (+-10%); ~0.46 ms per step on the training
  thread.

A dump runs on the training thread: writing 19 kept steps of the 8B run
(~74k kernels, 3.2 MB gzipped per rank) took 1.4 s.

Not included yet: dumps on demand or on failure, pftrace output, per-step
summaries, memcpy/memset spans, and names for eager kernels.
