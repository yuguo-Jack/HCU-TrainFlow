# [RL] Preserve finite entropy for masked full-vocabulary logits

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5351) · state: closed · merged: True

## Original PR description

`compute_logprobs(..., vocab_parallel_group=None, return_entropy=True)` returns NaN entropy for valid distributions with masked vocabulary entries. For logits `[0, 1, -inf]`, the zero-probability term becomes `0 * -inf`, although Shannon entropy should be about 0.5822. A point mass such as `[0, -inf, -inf]` has the same problem. The existing vocabulary-parallel entropy implementation already handles these distributions.

I zero the NaN weighted terms and preserve NaN entropy for invalid distributions. The shared float32 conversion, logprob calculation, no-gradient entropy behavior and original sum operation stay unchanged. The correction also applies after the batch-invariant vocabulary gather. Finite-input controls retain exact outputs and gradients, and the change adds no checkpoint format, configuration option or stored state.

### Validation

- `pytest tests/unit_tests/cpu/components/test_loss.py -q`: 31 passed. The original module has 29 passes on pristine code, and the masked-entropy regression fails against pristine production.
- Two new tests cover masked distributions in float32/float16/bfloat16, point masses, ignored targets and preservation of invalid NaN distributions. Independent CPU/CUDA probes agree with Shannon entropy.
- 48 finite-input CPU/CUDA controls retain exact logprobs, entropy and weighted gradients. Four deterministic 10-step DAPO/GRPO component optimizer controls also retain exact loss, gradient norms, metrics and parameters, including optimizer-state reload.
- A two-rank CPU/Gloo probe verifies the gathered route's entropy, exact logprobs and local-shard gradients, and strict SPMD output types.

Measured CUDA peak allocation matches pristine at three tested shapes. The added metric operations have a latency cost in some cases: the 128x151936 CUDA median was 1.629 ms before and 1.840 ms after. I make no speed claim.

### Correctness (`torchtitan/components/loss.py:440-444`)

I went through each kind of input row:

| Row | `logsumexp` | Weighted terms | Result |
|---|---|---|---|
| Finite logits | finite | none are NaN, so `nan_to_num_` and `masked_fill_` change nothing | **bit-identical to before** ✅ |
| Finite plus some `-inf` (e.g. `[0, 1, -inf]`) | finite | `0 * -inf = NaN` becomes 0 | correct Shannon entropy ✅ |
| Point mass `[0, -inf, -inf]` | `0` | `1*0 = 0` and `0*-inf` becomes 0 | `0` ✅ |
| All `-inf` | `-inf` | everything becomes 0, giving `-inf - 0 = -inf` | `masked_fill_` sets it to NaN ✅ |
| Contains `+inf` or NaN | `inf` / NaN | — | NaN ✅ |

The `masked_fill_` on a non-finite `log_normalizer` is what keeps invalid rows as NaN. When `logsumexp` is finite, no logit can be NaN or `+inf`, so the only NaN that `nan_to_num_` can remove is the `0 * -inf` one. The blanket NaN-to-zero step is therefore sound. Finite inputs give exactly the same result as before, which meets the "identical loss" bar in CLAUDE.md for this metric-only path. Gradients can't change because this runs under `no_grad`.

The batch-invariant vocab-parallel route (gather, then fall through to line 429+) gets the fix too. That route previously disagreed with the non-batch-invariant VP route on masked logits.

### Suggestions

1. **(nit) `nan_to_num_` has a side effect worth knowing about.** By default, `nan_to_num` also replaces `+inf` with the dtype's max and `-inf` with its min. Neither can actually reach the output here: `p * logit` can't be `-inf` because `-inf` logits have `p = 0`, and `+inf` rows are masked afterwards. Still, a reader has to work that out. Two options:
   - Pass `posinf`/`neginf` explicitly, or
   - Mirror the VP implementation for consistency:
     ```python
     weighted_logits = torch.where(torch.isneginf(logits), 0.0, torch.softmax(logits, dim=-1) * logits)
     ```
     This allocates an extra `[T, V]` bool mask plus an output buffer outside of compile. The in-place `nan_to_num_` avoids that, and the PR says it measured matching peak memory. Keeping `nan_to_num_` is fine; a short comment saying why it's equivalent to the VP `isneginf` masking would also work.

2. **(nit) Comment wording.** `# Zero-probability -inf entries contribute zero; invalid rows remain NaN.` is clear. Consider pointing at `_VocabParallelEntropy` so the two implementations are seen as one contract.

3. **Tests (`tests/unit_tests/cpu/components/test_loss.py:65-100`)** look good:
   - They cover fp32, fp16 and bf16, a point mass, an ignored label, `requires_grad=False` on the entropy, and NaN preservation for all-`-inf`, `+inf` and NaN rows.
   - The existing VP test at line ~629 already covers masked logits on the sharded path, so both paths now have regression coverage.
   - Optional: a check that full-vocab entropy matches VP entropy for the same masked logits would lock in their agreement directly. This isn't required.

### Changes since the last review (`torchtitan/components/loss.py:440-446`)

```python
log_normalizer = torch.logsumexp(logits, dim=-1)
# Match _VocabParallelEntropy's zero contribution for masked logits.
weighted_logits = (torch.softmax(logits, dim=-1) * logits).nan_to_num_(
    nan=0.0, posinf=torch.inf, neginf=-torch.inf
)
entropy = log_normalizer - weighted_logits.sum(dim=-1)
entropy.masked_fill_(~torch.isfinite(log_normalizer), torch.nan)
```

- **Nit 1 (implicit `±inf` clamping): fixed.** With `posinf=torch.inf, neginf=-torch.inf`, `nan_to_num_` now only replaces NaN with 0. Readers no longer need to work out why the default clamping can't be reached. It also stays in place, with no extra `[T, V]` bool mask.
- **Nit 2 (link to the VP contract): fixed.** The comment now names `_VocabParallelEntropy`.

### Correctness check, updated for the new version
- **Finite rows:** no NaN terms, so the results are bit-identical to `main`.
- **Masked rows:** for example `[0, 1, -inf]`, or a point mass `[0, -inf, -inf]`. Only `0 * -inf` produces NaN, and it becomes 0. This matches the `torch.where(torch.isneginf(shifted), 0, ...)` branch in the VP path at `loss.py:260-264`.
- **Invalid rows:** all `-inf`, any `+inf`, or any NaN. Here `logsumexp` is not finite, so `masked_fill_` returns NaN. This matches the VP path, where `shifted = -inf - (-inf)` or `inf - inf` is also NaN. The two paths now agree on every kind of row.
- **Gradients:** unaffected, because the code runs under `no_grad`. The logprobs and `cross_entropy` path is untouched.
- **Compile:** an in-place `nan_to_num_` on a fresh temporary inside `@local_compile` is fine.

### Optional, not blocking
- The new comment explains the NaN-to-0 step but not why `posinf`/`neginf` are passed. Something like `# Only replace NaN (0 * -inf); keep +-inf so invalid rows surface.` would make that clear. This is purely cosmetic.
- As noted last time, a test that compares full-vocab entropy with VP entropy on the same masked logits would lock in their agreement. The two separate regression tests already cover each path, so this is fine to skip.

Approving is up to a maintainer. I can't submit a formal approval.
