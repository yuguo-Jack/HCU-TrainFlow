# [fsdp] 2/n Expose backward-prefetch policy

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5675) · state: closed · merged: False

## Original PR description

Part **2/n** of the Kimi K3 / Dist-MoE training stack. Targets `main` after #5674 merged; the review diff contains only this feature.

human notes: 

add an knob to expose backward-prefetch policy when ep is enabled. previously, backward-prefetch is always on when ep is on, after this pr, one can disable it to reduce peak memory. 

## Why

Expert-parallel decoder setup always wires explicit backward prefetch. Memory-constrained pipeline/CUDA-graph recipes cannot opt out of gathering the next parameter unit early. Leaving explicit targets empty does not disable prefetch: FSDP uses its implicit fallback.

Example:

```python
ParallelismConfig(
    expert_parallel_degree=4,
    fsdp_enable_backward_prefetch=False,
)
# Current parameters are still gathered when backward needs them.
# Do not gather the next backward parameter unit early.
# Forward-prefetch and reshard/reduction policies are unchanged.
```

## What changed

- Add default-on `fsdp_enable_backward_prefetch` and propagate `enable_backward_prefetch` through common decoder and MTP FSDP setup.
- Build neighboring source/target pairs when enabled, or self-pairs for every FSDP module when disabled. One shared loop applies the targets with the public FSDP setter.
- A self-pair `(A, A)` becomes `A.set_modules_to_backward_prefetch([A])`. The nonempty target list suppresses implicit prefetch; A's parameters are already prepared by its own pre-backward hook, so the self-prefetch adds no all-gather.
- Extend the existing wiring test to empty, one-layer, and multi-layer stages while retaining its forward-prefetch and decoder/MTP policy checks.

## Alternatives considered

- An empty target list retains FSDP's implicit fallback rather than disabling prefetch.
- Disabling forward prefetch would change a separate overlap policy.
- Calling private FSDP state APIs is unnecessary: self-targets use the existing public setter.

## User-facing changes

| Setting | Behavior |
| --- | --- |
| Default `fsdp_enable_backward_prefetch=True` with EP | Preserve the existing backward-prefetch target order. |
| `fsdp_enable_backward_prefetch=False` with EP | Suppress explicit and implicit backward prefetch, trading overlap for lower peak unsharded-parameter memory. |
| Without EP | This option has no effect. |

The shorter knob name reflects its scope: disabling it suppresses both explicit and implicit backward prefetch, not only explicit targets.

**What this PR does.** It adds `ParallelismConfig.fsdp_enable_backward_prefetch` (default `True`) and passes it to `apply_fsdp_to_decoder` and the MTP wrapper. With EP on and the flag `True`, the existing backward-prefetch chain (lm_head -> last layer -> ... -> first layer -> tok_embeddings) is rebuilt as a list of pairs. I checked the order against `main` for 0, 1 and N layers and it is the same. With the flag `False`, every FSDP module gets itself as its only backward-prefetch target. The list is then nonempty, so FSDP skips its implicit prefetch, and the self-target finds its own parameters already unsharded, so no extra all-gather happens.

**Example.**
```python
# EP=4, 3 layers, fsdp_enable_backward_prefetch=False
# main:  layers.2.pre_backward -> unshard(layers.2), prefetch unshard(layers.1)
#        => two layers' unsharded params live at once
# PR:    layers.2.set_modules_to_backward_prefetch([layers.2])
#        layers.2.pre_backward -> unshard(layers.2); self-target unshard() is a no-op
#        => one layer live; layers.1 is gathered only when its own pre_backward fires
# EP=1 with the same setting: early return at fsdp.py:517 -> implicit prefetch still runs, no error
```

<details><summary>Details</summary>

- **Equivalence of the default path.** `main` sets: `lm_head -> [layers[-1]]` (only when norm and lm_head exist and there is at least one layer), each `layers[i] -> [layers[i-1]]`, and `layers[0] -> [tok_embeddings]` when tok_embeddings exists. The new order list, `[lm_head?] + reversed(layers) + [tok_embeddings?]`, built only when layers is nonempty, produces exactly these pairs. With weight tying, `lm_head`/`norm`/`tok_embeddings` share one FSDP state, as on `main`.
- **Disabled path.** `model.modules()` filtered on `FSDPModule` covers the root, the embedding/norm/head units, every layer (including MTP layers temporarily inserted by `apply_fsdp_to_mtp_decoder`), and nested units added later in the stack (#5676). Under tying, the three modules write the same shared state, which is fine. `tok_embeddings` with `unshard_in_backward=False` stays un-gathered, because `unshard()` returns early in PRE_BACKWARD.
- **Smaller alternative for the EP gap.** Move the `else` branch (self-pairs) above `if ep_degree == 1: return`, and keep the neighbor-pair branch where it is. About the same LoC, and the docstring caveats go away.
- **Test.** It is a cheap CPU mock test. It guards the self-target wiring, which would otherwise regress silently as higher memory. It doesn't check the actual claim (no implicit prefetch and no extra all-gather), because that is upstream behavior. That gap is one more reason for the upstream TODO.

</details>

- claude[bot] · comment · 2026-10-30T22:08:50Z · [source](https://github.com/pytorch/torchtitan/pull/5675#discussion_r4428903744)

File: `torchtitan/distributed/fsdp.py` · line 555

The self-target trick is a workaround for something FSDP2 doesn't provide: there is no public way to turn off implicit backward prefetch. It also leans on two undocumented internals. First, `FSDPState._pre_backward` computes `default_prefetch = len(self._states_to_backward_prefetch) == 0`. Second, `FSDPParamGroup.unshard()` returns early when the group is already unsharded (or when `unshard_in_backward=False`, as on `tok_embeddings`). If either of these changes upstream, this path would silently start all-gathering again, or would gather a unit twice.

Per CLAUDE.md principle 3, please add a `TODO` here that links an upstream pytorch/pytorch issue asking for a public way to disable it, for example making an explicit empty list mean "no prefetch", or a `set_backward_prefetch(False)`. That way the trick can be deleted once upstream supports this.
