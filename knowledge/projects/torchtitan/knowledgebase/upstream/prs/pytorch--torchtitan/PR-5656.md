**Verdict: Approve -- please address the items below before merging.** The design is a small, self-contained logger that follows the same pattern as the W&B and TensorBoard loggers next to it, and the dependency is optional. What's left is tests that never run in CI and a docstring update. A maintainer still needs to review (this touches core `observability/metrics.py`).

**What this PR does.** Adds `MLFlowLogger` next to `WandBLogger` and `TensorBoardLogger`, behind `metrics.enable_mlflow`. `mlflow` is imported on every rank so a missing install fails on every rank the same way (same pattern as DistMoE, per tianyu-l's comment). Only the metrics rank (rank 0, or the first rank of the last PP stage) starts or joins a run, and only it uploads the config JSON and logs metrics. Metric names are rewritten for MLflow only, because MLflow rejects `(`, `)` and `%`. TensorBoard and W&B keys don't change.

**Example.** `enable_mlflow=True`, PP=2 with 1F1B, world_size=8, `save_for_all_ranks=True`:
```
before: no MLflow support
after:  only rank 4 calls mlflow.start_run(); ranks 0-3, 5-7 log nothing to MLflow
        "throughput(tps)"        -> "throughput_tps"
        "mfu(%)"                 -> "mfu_percent"
        "memory/max_active(GiB)" -> "memory/max_active_GiB"
        training exception       -> run ends with status FAILED (sys.exc_info() in close)
```

### Must fix
1. `tests/unit_tests/cpu/observability/test_mlflow_logger.py:154` -- `importorskip("mlflow")` always skips in CI because mlflow isn't a dev requirement. Add `mlflow-skinny` to `requirements-dev.txt`, or delete the test.
2. `tests/unit_tests/cpu/observability/test_mlflow_logger.py:100` -- the file is mostly mock-call checks and duplicates. Keep the rank-selection invariant and the real-store test; drop the rest.
3. `torchtitan/observability/metrics.py:564` -- the author's reply is correct, but the `save_for_all_ranks` docstring should say that MLflow ignores it.

### Should consider
- `torchtitan/observability/metrics.py:248` -- `log_metrics` is synchronous by default and blocks the metrics rank on the tracking server (*unverified*). Use `synchronous=False`, or document `MLFLOW_ENABLE_ASYNC_LOGGING`.
- `torchtitan/observability/metrics.py:390` -- `direction.md` says not to add new `enable_*` booleans. Keeping `enable_mlflow` here matches `enable_wandb` and `enable_tensorboard`, so this is fine for this PR. A follow-up could move all three loggers to `X.Config | None` together.

<details><summary>Details</summary>

- Necessity: the PR description has a concrete user (Datadog) and a reason (self-hostable, OSS; Megatron also supports it). No overlapping open PR. The dependency is optional and imported lazily, so core gets no new required dependency.
- Name normalization is in the right layer. Renaming the source keys instead would change TB/W&B metric keys, which must not change silently. The collision check raises instead of silently dropping a key, which is right.
- `config_dict` comes from `Configurable.Config.to_dict()`, which turns non-JSON values into `repr`, so `log_dict` won't hit a serialization error.
- Failure status: `train.py:59-61` calls `trainer.close()` inside `except Exception`, so `sys.exc_info()` is set there and the run is marked FAILED.

</details>

Not verified: the impact of synchronous MLflow logging on step time against a remote tracking server.
