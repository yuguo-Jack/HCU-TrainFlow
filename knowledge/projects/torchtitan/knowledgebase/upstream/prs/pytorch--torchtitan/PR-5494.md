# [rl] serialize rollouter dataloader access across threads

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5494) · state: open · merged: False

## Original PR description

**TLDR:** A checkpoint saved while the controller reads a training sample can make resume skip that sample. `Rollouter` now holds one lock around its dataloader calls, so state is saved only between reads. With forced thread switches, torn checkpoints in 10 s go from 3738 to 0.

**Problem**
1. `_data_input_loop` reads samples on another thread: `asyncio.to_thread(rollouter.get_training_sample)`.
2. `_trainer_loop` calls `rollouter.state_dict()` at every optimizer step, with nothing ordering it against that read.
3. `IterableRLDataLoader.__next__` first advances the dataset cursor, then records the sample as pending.
4. A `state_dict()` that overlaps a read can save a cursor past sample S while S is not pending yet.
5. Resuming from that checkpoint silently never yields S.
6. **When.** No shipped dataset blocks in `__next__`, so it needs a thread switch mid-read: none seen at Python's default 5 ms switch interval. A dataset that reads disk or network in `__next__` hits it whenever a save overlaps a read.

**Solution**
1. One `threading.Lock` in `Rollouter` guards `get_training_sample`, `acknowledge_training_sample_ids`, `state_dict` and `load_state_dict`.
2. `_trainer_loop` calls `acknowledge_training_sample_ids` and `state_dict` through `asyncio.to_thread`. During a read, the trainer coroutine waits for it to finish, but the event loop keeps running.
3. Dataloaders and public APIs are unchanged.

**Results**
```
# Unit test: state_dict() during a read, then resume (CPU)
before: resumed samples [(0, 1), (1, 2)]   # sample 0 skipped
after:  resumed samples [(0, 0), (1, 1)]

# Stress: DAPO dataset + IterableRLDataLoader, to_thread reads vs the trainer's ack + state_dict(), 10 s, CPU
# torn = the saved cursor is past a sample that is not pending
switch interval 5 ms (default):  torn 0 / 775k -> 0 / 53k
switch interval 1 us:            torn 3738 / 628k -> 0 / 44k

# Event loop during a save that overlaps a 0.5 s read (CPU)
state_dict() on the loop, with the lock:   loop frozen 0.49 s
state_dict() via to_thread (this PR):      loop lag 0.001 s
```

You may ask:
- Why not lock inside each dataloader? Every `RLDataLoader` would repeat it, and `MapStyleRLDataLoader` already asks its caller to serialize these calls.
- Why not an `asyncio.Lock` in the controller? Cancelling the `to_thread` await releases it while the read still runs.
- Why also move ack and `state_dict()` to `to_thread`? On the loop, they would freeze it for a whole read, and deadlock if the dataset's `__next__` waits on the loop.

**Test plan**
```
pytest tests/rl/unit_tests/cpu/test_rollouter_data.py::test_state_dict_waits_for_in_flight_training_sample  # fails before, passes after
pytest tests/rl/unit_tests/cpu  # 517 passed; the 2 failures also fail on main
```
- 2-GPU Qwen3-0.6B RL run, 4 steps with full checkpoints at steps 2 and 4, then resumed from step 2 and trained steps 3-4: both runs finish.

The stress and event-loop numbers come from local scripts that are not in this PR.
