# [refactor] estimate model FLOPs per input batch 

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4819) · state: open · merged: False

## Original PR description

Resolves #4009 

Previously, each models returned a function `get_nparams_and_flops` which returned `num_flops_per_token`, which the trainer used to compute the FLOPs by multiplying the number of text tokens seen to it. 

This does not take into account of FLOPs of multimodal models. The computation becomes more complicated, because vision inputs may have images of different sizes. 

## Change
Each model now returns a function `FlopsEstimator` that takes in a input batch and returns the FLOPs for that input batch. FLOPs is computed and accumulated locally per input batch in the CPU, and it is gathered at the logging step.

Decoder only model FLOPs unchanged.

## Limitations
This PR makes the FLOPs calculation take into account of each images in the batch, but it does not make the calculation aware of the different document lengths present in an input text sequence. 

## Sep 24 Update
- Each model defines `build_flops_estimator` that returns a function `input_dict -> flops`. 
- Each attention module defines `flops_per_token` to handle different flops calculation like quadratic, sliding window, linear, etc. 
- Each decoder model defines `_layer_flops_per_token(layer_config, ...)` that chooses the correct attention module contained in the layer to compute flops, because there is no convention of the name for the attention module inside a transformer block. For example, `Qwen35TransformerBlock.Config` has `attention` or `delta_net`. 
(But they both build to `Qwen35TransformerBlock.attn` so maybe a cleaner change would be to make each model's transformer block to actually inherit from common `TransformerBlock`, but this can mess up the typing of `TransformerBlcok.Config.attention` which is supposed to be `BaseAttention.Config` but not all "attentions" inherit form it). 
- Each vision encoder defines `build_vision_flops_estimator`. 
- Each multimodal models then combine the flops of encoder and decoder.
- Also added `get_parameter_counts` method for `BaseModel` that returns the active param count including embedding. Previously, the reported active param count was using the active param count used for flops calculation, which excluded embedding.

- felipemello1 · comment · 2026-10-16T21:04:36Z · [source](https://github.com/pytorch/torchtitan/pull/4819#issuecomment-6224668316)

message from claude: Hi @jinsooihm, thanks for this. We're opening a small RL-only fix for MFU: RL microbatches are padded to a fixed token count (5-22% padding in our runs), and attention FLOPs assume max_context_length for every token, so in our 131k-context runs RL's mfu_percent reads ~1.8x too high under the non-causal convention.

Our fix uses the fact that under that convention, a document of length L costs L**2 attended tokens. The RL batcher records the sum of squared document lengths at pack time. With positions that restart per document, that sum is also the sum over non-padding tokens of (2 * position + 1).

Happy to move this onto your per-batch estimator once it lands, or to add it there if you'd like.
