# [refactor] estimate model FLOPs per input batch 

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4819) · state: open · merged: False

## Original PR description

Resolves #4009 

Previously, each models returned a function `get_nparams_and_flops` which returned `num_flops_per_token`, which the trainer used to compute the FLOPs by multiplying the number of text tokens seen to it. 

This does not take into account of FLOPs of multimodal models. The computation becomes more complicated, because vision inputs may have images of different sizes. 

## Change
- Each `Model` defines `build_flops_estimator` that takes in input batch and outputs flops for that batch.
- Each `Attention` module defines `flops_per_token`, since now all attentions (except vision attention) actually inherit from `Attention`
- There is a shared function for `Decoder.build_flops_estimator` that sums the `flops_per_token` of its owned attention modules and active params, removing duplicated logic.
- Each encoders also define their own estimator functions.
- There is a default for multimodal models, but the Muse series has additional modules that consumes encoder output before putting into the decoder, so they override.
- Multimodal models override `build_flops_estimator` it by adding the contributions from the encoders.
- Text input flops is still not sensitive to the individual document lengths

## Limitations
This PR makes the FLOPs calculation take into account of each images in the batch, but it does not make the calculation aware of the different document lengths present in an input text sequence.
