# Add blocking periodic validation to async RL training

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5649) · state: open · merged: False

## Original PR description

Summary:
Add ValidationConfig.interval_steps so RL recipes can run held-out evaluation after every N optimizer steps. The default of 0 preserves start/end-only validation; steps=0 still disables evaluation, and negative intervals are rejected.

At a periodic boundary, wait for the current model-state push and generator pull to finish before evaluating. This ensures greedy held-out rollouts use the weights for the logged optimizer step, and blocks the next trainer step until evaluation completes. Keep training rollout workers running in the background. Use absolute step numbers after resume and leave the final step to the existing post-training pass so it is logged only once.

Fix the default validation console filter to match the emitted validation_reward/_mean and validation_reward/_max keys; the old slash-separated patterns hid both rewards. Document how to enable periodic validation, its blocking behavior, and the distinction between the prompt count and interval. Add CPU coverage for ordering, resume, disabled validation, invalid intervals, and visible reward logging.
