# [attention][perf] Compile the attention output gate (Qwen3.5, Muse Glimmer)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5573) · state: closed · merged: False

## Original PR description

**TLDR:** Qwen3.5 and Muse Glimmer scale the attention output by `sigmoid(gate)` in eager: 2 kernels forward (3 when attention returns heads first) and 3 backward. A shared `attention_output_gate` region runs it as 1 + 1. Qwen3.5-35B-A3B 2-layer step at 16k: train -0.86%, prefill -2.0% (CUDA graphs). Muse Glimmer: gate kernel time halved; the 2-layer step time is inside noise.

**Problem**
1. **Gated attention.** Qwen3.5 and Muse Glimmer multiply the attention output `[T, H, V]` by `sigmoid(gate)` before `wo`.
2. **Two gate sources.** Qwen3.5's gate is the second half of each head of its 2x-wide `wq` output; Muse Glimmer's is its own `o_gate` projection.
3. **Eager kernels.** Forward: sigmoid, multiply, plus a head-flatten copy when attention returns heads first. Backward: two multiplies and a sigmoid backward.
4. **Memory-bound.** Each kernel reads and writes the whole `[T, H * V]` tensor. Qwen3.5's sigmoid reads the strided `wq` half with a non-vectorized kernel.
5. **Cost.** At 16k tokens, fwd+bwd kernel time per gated layer, in the training step: Qwen3.5-35B-A3B 391 us, Muse Glimmer 30B about 305 us (bandwidth floor 151 us).

**Solution**
1. **One region for both.** `gate_attention_output(output_THV, gate_THV)` in `models/common/attention/attention.py`, region `attention_output_gate`: contiguous + sigmoid + multiply + flatten in one kernel, the backward in one.
2. **Same eager ops.** The function runs what both models ran (`contiguous`, `out * sigmoid(gate)`, `view(T, -1)`), so with regions off both models compute bit for bit what they did before.
3. **Callers.** Qwen3.5 passes its `wq` gate slice. Muse Glimmer splits `o_gate`'s output into heads with `local_head_split`, as q/k/v are split.
4. **No region options.** Each gate kernel has two autotune configs, and both give bitwise-identical outputs and grads (each forced in turn, GB300): the op has no multiply-add chain to contract.
5. **Enabled** in the default regions of Qwen3.5 (Qwen3.6 and 3.8 build the same config) and Muse Glimmer. Unchanged: Muse Spark's own output region, `wq`, `o_gate`, `wo`.

```text
before:  contiguous(out), sigmoid(gate), mul, view -> wo    fwd 2-3 kernels; bwd mul, mul, sigmoid_backward
after:   gate_attention_output(out, gate)          -> wo    fwd 1 kernel;    bwd 1 kernel
```

You may ask: why not Kimi K3? Same gate on its MLA layers, but about 0.1% end to end, and decode T=1 got 9 us slower under CUDA graphs (+0.7%, every round of 3 runs). It stays eager.
You may ask: why not reuse Muse Spark's region? It is a method of Muse Spark's attention and also applies its per-head output norm.
You may ask: why does Glimmer split its gate into heads instead of the function taking a flat gate? Qwen3.5's gate is a strided half of each head; flattening it would cost an eager copy with regions off.
You may ask: why not round the sigmoid to bf16 as eager does? The only Inductor switch for it (`emulate_precision_casts`) also changes Triton's libdevice for every later kernel in the process. Without it the region is closer to fp64 and keeps the sigmoid in fp32 like `shared_expert_gate`.
NOTE: saturated gates now get gradient. For gate >= ~6.25, eager's bf16 sigmoid rounds to 1.0, so its gate grad is exactly 0; the region's matches fp64 (bf16, output = grad = 1; CPU probe of `gate_attention_output`):
```text
gate      6.0       6.25      7.0       9.0
eager     0.003891  0         0         0
region    0.002472  0.001923  0.000912  0.000123
fp64      0.002467  0.001923  0.000910  0.000123
```
More correct, but a training-dynamics change: loss curves against main can differ by more than ulp noise where gates saturate. How often real Qwen3.5 and Glimmer gates exceed ~6.25 is unmeasured.
NOTE: goldens. The Muse Glimmer golden tests keep the default regions and record `loss` and `grad_norm` per step: grad_norm moves from step 1 (gate grad), and the loss can move from step 1 too (the forward differs by 1 ulp). This PR refreshes fake_pg/a10g, real_pg/a10g and real_pg/mi350x `muse_glimmer.txt` from CI: the fake-PG run, a real-PG export run on this branch and a ciflow/rocm run. Qwen3.5 has no golden.
NOTE: reaches every Qwen3.5/3.6/3.8 and Muse Glimmer config that keeps the default regions, in both trainer and generator: alphabet_sort `rl_grpo_qwen3_5_9b_varlen` and `rl_grpo_qwen3_6_27b_varlen_perf`, terminal-bench `rl_grpo_qwen35_9b_terminal_bench`, `rl_grpo_qwen35_35b_a3b_terminal_bench` and `rl_grpo_muse_glimmer_30b_terminal_bench`, search-r1 `rl_grpo_muse_glimmer_30b_search_r1`. The batch-invariant RL recipe and GraphTrainer clear all regions and are unchanged.
NOTE: TP: an SPMD typecheck of both attentions (2-rank CPU mesh, TP=2 + SP, fwd+bwd, regions off) passes before and after.
NOTE: not tested: train at 2k/4k and decode 8-256 at layer level, multi-GPU runs, loss curve, cold compile time; numerics checked on GB300 only.

**Test plan**
`pytest tests/unit_tests/cpu/models/common/test_attention_output_gate.py`: both gate layouts, tokens-first and heads-first output, bf16; regions off must equal each model's former inline gating bit for bit; regions on within rtol=2e-2, atol=2e-3 (gate grads at saturated gates differ by a few percent: eager's error). Fails before (no such function); also fails if sigmoid becomes silu, if `contiguous` is dropped (heads first) or if the flatten order changes.
`pytest tests/unit_tests/cpu/models/qwen3_5 tests/unit_tests/cpu/models/muse_glimmer tests/unit_tests/gpu/models/qwen3_5`: same failures as main (CPU flex compile in this venv: 3 mrope tests; GPU CosSinRoPE `test_rope_compile` on GB300).
