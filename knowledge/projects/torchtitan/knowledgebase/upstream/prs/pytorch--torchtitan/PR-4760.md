# [CP] Optimize MLA all-gather and Ulysses communication for Kimi K3 and dpskV3 

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4760) · state: open · merged: False

## Original PR description

Stack order: #5445 -> #4760.

Naming and file moves are in #5445; this PR focuses on MLA CP optimization.

**The original optimization idea was inspired by this [MLA Ulysses CP proposal](https://gist.github.com/fegin/bd9bd9e9147ae1b11375dfb68815f78a).**

Shape suffixes: `T` tokens, `H` heads, `L` KV latent, `N` non-positional key, `R` shared key, `V` value; `K=N+R`, `P=N+V`, `F=K+P`. Suffixes describe logical dimensions; collectives change their sharding.

- **K/V all-gather CP**
  - Before: all-gather materialized K and V separately. K repeats `k_shared_TR`
    across attention heads.
  - After: all-gather normalized compressed KV latents and head-shared
    `k_shared_TR`, then apply `wkv_b` and materialize K/V locally. This trades
    repeated projection work for lower communication volume.

  ```python
  # Before: materialize K before communication.
  kv_THP = reshape_per_head(wkv_b(kv_c_normed_TL))
  k_nope_THN, v_THV = unpack(kv_THP)
  k_THK = concat(k_nope_THN, expand_per_head(k_shared_TR))
  k_THK = all_gather(k_THK)
  v_THV = all_gather(v_THV)

  # After: communicate compressed latents before projecting K/V.
  kv_c_normed_TL = all_gather(kv_c_normed_TL)
  k_shared_TR = all_gather(k_shared_TR)
  kv_THP = reshape_per_head(wkv_b(kv_c_normed_TL))
  k_nope_THN, v_THV = unpack(kv_THP)
  k_THK = concat(k_nope_THN, expand_per_head(k_shared_TR))
  ```

- **Ulysses CP**
  - Before: use three all-to-alls for materialized Q, K, and V. K repeats
    `k_shared_TR` across attention heads.
  - Current: all-gather headless `k_shared_TR`, then use one all-to-all
    for `q_THK` + packed `kv_THP`.

  ```python
  # Before: materialize K, then move Q, K, and V from token to head sharding.
  kv_THP = reshape_per_head(wkv_b(kv_c_normed_TL))
  k_nope_THN, v_THV = unpack(kv_THP)
  k_THK = concat(k_nope_THN, expand_per_head(k_shared_TR))
  q_THK = all_to_all_token_to_head(q_THK)
  k_THK = all_to_all_token_to_head(k_THK)
  v_THV = all_to_all_token_to_head(v_THV)
  out_THV = attention(q_THK, k_THK, v_THV)
  out_THV = all_to_all_head_to_token(out_THV)

  # Current: combine q_THK and kv_THP in one all-to-all.
  kv_THP = reshape_per_head(wkv_b(kv_c_normed_TL))
  k_shared_TR = all_gather(k_shared_TR)
  packed_q_kv_THF = all_to_all_token_to_head(
      concat(q_THK, kv_THP)
  )
  q_THK, kv_THP = split(packed_q_kv_THF)
  k_nope_THN, v_THV = unpack(kv_THP)
  k_THK = concat(
      k_nope_THN,
      expand_per_head(k_shared_TR),
  )
  out_THV = attention(q_THK, k_THK, v_THV)
  out_THV = all_to_all_head_to_token(out_THV)

  ```

- **Shared MLA backend and checkpoints**
  - DeepSeek V3, Kimi K2.7, and Kimi K3 share the compact MLA backend.
    `MLAAttention` owns `wkv_b` and delegates to a Q/K/V attention kernel;
    common all-gather communication lives in `distributed/context_parallel.py`.
  - HF adapters map directly to `attention.inner_attention.wkv_b.weight`,
    replacing state-dict renaming hooks. HF keys remain compatible. Native
    checkpoints use the nested key; old `attention.wkv_b.weight` keys are no
    longer automatically remapped.

- **Sharding and backend compatibility**
  - The KV projection explicitly asserts its CP layout: replicated after latent
    all-gather, token-sharded before Ulysses all-to-all. The CP transform copies
    the nested projection config when selecting the backend; the local head
    reshape preserves that layout.
  - `fused_mla` rejects CP backends at model construction because its fused
    forward bypasses the compact MLA communication wrapper. Fused MLA with CP
    is not supported; remove the override to use the configured CP backend.
  - GraphTrainer precompile delegates metadata construction to the Decoder;
    batch-invariant settings traverse Flex configs directly, including those
    nested inside MLA.
  - The TorchTitan vLLM wrapper currently rejects MLA. Kimi K3 MLA inference
    parity and RL integration tests are disabled until support is restored.

### Numerical comparison

[`3e6c5c2b1a`](https://github.com/pytorch/torchtitan/commit/3e6c5c2b1ad501cecd139178bf91b3bffc6b15b3): DeepSeek V3 and text-only Kimi K3 debug models, 2 H100s, CP=2, BF16/Flex, seed 42, deterministic, 256 tokens, 100 steps. Identical initial weights and a fixed synthetic batch; AdamW LR `1e-3`, gradient clipping `1.0`.

Relative differences between the materialized-K/V reference and compact MLA on the same revision. Loss is global mean cross-entropy; grad norm is FP32 L2 before clipping.

| Model | CP backend | Loss Δ, step 10 | Grad norm Δ, step 10 | Loss Δ, step 100 | Grad norm Δ, step 100 |
| --- | --- | ---: | ---: | ---: | ---: |
| DeepSeek V3 | K/V all-gather | 0.067% | 0.371% | 0.541% | 0.116% |
| DeepSeek V3 | Ulysses | 0.103% | 0.218% | 0.056% | 0.128% |
| Kimi K3 | K/V all-gather | 2.321% | 11.125% | 0.462% | 0.628% |
| Kimi K3 | Ulysses | 0.262% | 2.466% | 0.363% | 0.322% |

All runs completed 100 steps with finite loss and gradients. First-step logits and loss are **bitwise identical** in all four comparisons, but gradients are not: first-step relative L2 gradient differences range from **0.1475% to 0.2716%**. Changed BF16 gradient accumulation leads to different subsequent optimizer updates. This fixed-batch comparison does not establish convergence on a training dataset.

#### 1. `cp_attention.py:56`: "If every module that inherits CPAttention also inherits InnerAttention, should CPAttention inherit InnerAttention?"

| CP class | non-CP base | Is it an `InnerAttention`? |

| `KVAllGatherFlexInnerAttention`, `Ulysses*InnerAttention` | `FlexInnerAttention` / `VarlenInnerAttention` | yes |

```python
class CPInnerAttention(
    InnerAttention, ABC, Generic[_GlobalAttentionMetadataT, _LocalAttentionMetadataT]
):
    @dataclass(kw_only=True, slots=True)
    class Config(InnerAttention.Config):
        pass
```

The MRO should still resolve, e.g. `UlyssesMLAAttention -> Ulysses -> CPInnerAttention -> MLAAttention -> InnerAttention -> Module`. That's the same diamond `main` already has for `KVAllGatherFlexInnerAttention(KVAllGatherFlex, FlexInnerAttention)`. Both intermediate `Config`s add no slots, so `slots=True` won't hit a layout conflict. (I couldn't run Python in this job, so please confirm locally.) This also settles the earlier `Mapping[type Inner, type Inner] | Mapping[type MLA, type MLA]` question: `ContextParallelTransform.inner_attention_map` can stay `Mapping[type[InnerAttention], type[InnerAttention]]`, as it already is at `context_parallel.py:33`. fegin's "drop the CP prefix" rename can come in a follow-up.

| Callsite | Why it needs the inner kernel | Removed by the ban? |

```python
# batch_invariance.py
for _, flex_cfg, _, _ in layer_cfg.attention.traverse(FlexInnerAttention.Config):
    flex_cfg.kernel_options.update(BACKEND="TRITON", BLOCK_M=..., BLOCK_N=...)

kernel_types = (VarlenInnerAttention.Config, FlexInnerAttention.Config)
has_supported_kernel = next(attention.traverse(kernel_types), None) is not None
```

`traverse` takes `type[_ConfigT]`, so a tuple might need a small widening or two `traverse` calls.

`model_wrapper.py` then only needs `sharding_config`. With fix 2, the vLLM kernel's sharding can be read from the replaced kernel directly (`backend_cfg.inner_attention.sharding_config` inside the MLA branch, `attention_cfg.inner_attention.sharding_config` otherwise). That's a single local `isinstance`, not a public helper.

After that, `get_attention_kernel_config` can come out of `mla.py` and `__init__.py`. This avoids both the ban and the MLA-aware helper leaking into config transforms and experiments.
