# [rl] add a debugging and performance skill

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5481) · state: open · merged: False

## Original PR description

**TLDR:** Adds `rl_debug_perf`, a Claude skill for debugging a slow or broken TitanRL run. It encodes what we learned from two GB300 runs whose trainers sat idle 79% and 93% of every step, for different reasons.

**Problem**
1. When a TitanRL run is slow or looks broken, an agent starts from zero: which metric to read first, which knob to turn.
2. "The trainer waits for generation" has several causes, and the obvious fix is often the weak one.
3. In a 35B MoE math run, 4 more engines projected -8% step time; raising `target_offpolicy_steps` from 4 to 6 projected -24%.
4. Many "broken run" reports were env or grader bugs, and errored rollouts never show up in the reward curve.

**Solution**
1. `SKILL.md`: inspect errored rollouts first, triage the trainer's wait time to a knob (off-policy steps, batch size, GPU split, length caps), then common bugs by symptom.
2. `references/rollout_inspection.md`: scripts for `rollout_samples.jsonl` and the job log.
3. `references/worked_examples.md`: the two runs with the levers projected, and one run's error taxonomy.
4. `references/metrics.md` and `references/common_bugs.md`: the metric glossary and each bug's details.
5. No code changes.

**Validation**
```text
every snippet that runs on main, on a recorded 2,752-rollout terminal-agent run   runs as written
per-group comparison of two same-seed runs                                     delta +0.028 +- 0.013 (SE), r = 0.889
```

You may ask: Why not fix the bugs the skill describes? Each needs its own code change; the skill gives the symptom and the workaround.

NOTE:
- The perf numbers are projections from `step_time ~= G * W / L` calibrated on each run, not re-measured.
- Metric names follow the per-phase step-time ratios (`perf/trainer/step_time_ratio/wait_for_training_batch`, `/forward_backward`, ...) and the `rollout_buffer/num_groups_taken` gauge, so this lands after the two PRs that add them.
- The branched-rollout snippet was rewritten for main's turn format (`prompt_prefix_len` + `prompt_delta_token_ids`) after the validation run above.
