# [checkpoint] Skip model-only final checkpoints when auto-resuming

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5146) · state: closed · merged: False

## Original PR description


Summary:
Fixes #5054.

With the default `last_save_model_only=True`, the last step writes a model-only checkpoint. It still has the backend's metadata file (`.metadata` for DCP, `metadata.pkl` for torch_checkpointing), so `_find_load_step` treated it as resumable. Rerunning the same job with a larger `training.steps` then auto-selected it, `load()` asked for the full training state (`model_only = step == 0` is False), and the load failed with `Missing key in checkpoint state_dict: dataloader.version.` (DCP; torch_checkpointing fails the same way with `strict=True`).

This is not a regression from the checkpointer consolidation: the pre-split `checkpoint.py` picked any `step-N` with `.metadata` or an HF index and had the same failure. The consolidation's `_is_resumable_checkpoint` already skips final HF exports; this closes the remaining case, the native-format model-only export, whose only marker is the same file a full checkpoint has.

Changes:
- `_find_load_step` gains `require_training_state`. It walks steps newest first and, when set, skips a resumable checkpoint after step 0 that holds no non-model state, logging a warning, so auto-resume falls back to the newest full checkpoint. Only the newest directories pay for the metadata read.
- `load()` sets `require_training_state` only when the load needs more than the model, i.e. something is left in `_states_to_load` besides `model` after `exclude_from_loading`. Recipes that load only the model from the folder (e.g. `flux_debugmodel_inference`, which excludes dataloader/lr_scheduler/optimizer/train_state) keep selecting the newest model-only export instead of silently falling back to older weights.
- Step 0 stays selectable: `load()` restores it as a model-only seed checkpoint.
- New `_holds_training_state` hook per backend:
  - DCP reads `.metadata` (`FileSystemReader`, or `FsspecReader` for remote URIs) and checks for flattened keys under any non-model state name (`optimizer.*`, `train_state.*`, ...).
  - torch_checkpointing reads `metadata.pkl` through the backend `Storage` with `load_distributed_metadata` and checks for any item other than `model`.
- torchft's per-replica dataloader lookup calls `_find_load_step` without the flag, so it is unchanged.
- `docs/checkpoint.md` notes the resume behavior under "SAVE MODEL ONLY".

Test Plan:
New tests:
- `test_checkpoint.py::test_auto_resume_skips_model_only_last_checkpoint`: issue repro (full `step-2`, model-only final `step-3`); auto-resume loads `step-2` with optimizer state and warns about `step-3`. On main it loads `step-3`.
- `test_checkpoint.py::test_auto_resume_uses_model_only_checkpoint_for_model_only_load`: with every non-model state excluded, auto-resume still picks `step-3`.
- `TestFindLoadStepRemote::test_require_training_state_skips_model_only_export` / `..._keeps_model_only_step_zero`: same rule over a `memory://` fsspec folder (covers the `FsspecReader` path).
- `test_torch_checkpointing.py::test_load_latest_skips_model_only_last_checkpoint`: full `step-2`, model-only `step-5`; loads `step-2` with all states. On main it loads `step-5`.

Existing tests that faked a checkpoint with an empty `.metadata` / `metadata.pkl` and auto-loaded past step 0 now write real metadata (DCP `Metadata`, torch_checkpointing `DistributedMetadata`); `fake_save` records the keys it was given, so model-only fake saves look model-only.

`pre-commit run --files <changed files>`: all hooks pass except pyrefly. Against torch_checkpointing@main, `torchtitan/components/checkpointer/torch_checkpointing.py` already fails to import `METADATA_FILE_NAME` from `torch_checkpointing.distributed_metadata` (upstream moved it and `load_distributed_metadata` to `metadata_serialization`), and the new `load_distributed_metadata` import hits the same move. With a torch_checkpointing that still has the old layout on the search path, pyrefly reports no errors in the checkpointer files.
