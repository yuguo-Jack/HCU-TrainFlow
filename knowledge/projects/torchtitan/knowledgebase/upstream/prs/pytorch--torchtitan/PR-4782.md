# Fix DeepSeek V4 forward on pipeline stages

[Upstream PR](https://github.com/pytorch/torchtitan/pull/4782) · state: open · merged: False

## Original PR description

DeepSeek V4 advertises pipeline parallelism, but its forward assumes it owns every decoder layer. After splitting the model, stage 0 still indexes removed layers, later stages expand the HC axis again and derive token IDs from hidden states, and the generic split drops `hc_head`.

Iterate over the layers owned by each stage, expand HC only at the embedding stage, and pass the original token IDs through the existing per-microbatch kwargs for hash routing. A model-specific pipeline wrapper keeps `hc_head` with the final norm and validates explicit splits. This covers the decoder without MTP; MTP pipeline support is unchanged.

Testing:
- 29 related CPU tests pass. The new tests use token-dependent CPU blocks with the real V4 forward and HC head, checking two/four-stage outputs, parameter gradients, checkpoint keys and split validation.
- With seed 42 and deterministic algorithms, the CPU fixture gives bitwise-identical loss and grad_norm before/after this change, both with and without the LM head.
- Two- and four-process Gloo `1F1B` probes pass; maximum gradient difference from the unsplit CPU reference is 2.98e-8.
- Added real-PG integration configurations for FSDP2+PP2 and PP4. These select DeepSeek V4 and construct successfully; GPU training has not been run.

Keeping this as a draft until the target environment checks pass. `pre-commit run --all-files` passes formatting/lint checks but Pyrefly reports 21 errors in unchanged files due to missing dependencies and newer PyTorch APIs. `pytest tests/ -x` stops during collection because torchvision is missing. Local validation used PyTorch 2.12; it does not establish full-model GPU numerical equivalence.
