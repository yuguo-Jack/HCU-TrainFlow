# [BC] Make graph capture backend-agnostic with torch.accelerator

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5353) · state: closed · merged: True

## Original PR description

This PR makes the training step graph wrapper work on any accelerator instead of only on CUDA, so backends such as XPU no longer need a near duplicate module. torchtitan/distributed/cuda_graph.py becomes the accelerator_graph package, which uses torch's device generic torch.accelerator.Graph. CUDA keeps an explicit torch.cuda.graph branch because it does not register with torch.accelerator.Graph, and that branch also keeps the profiler's kernel annotations.

### API changes in this PR (source -> destination)

The diff covers `d681f48..1bbbf76` (the PR's 2 commits). No compatibility aliases are kept, so every old name below is removed. Anything still importing `torchtitan.distributed.cuda_graph` will break.

#### Module
| Source | Destination |
|---|---|
| `torchtitan/distributed/cuda_graph.py` | `torchtitan/distributed/accelerator_graph.py` |
| — | `torchtitan/distributed/cuda_graph_backend.py` (new; registers the CUDA backend when imported) |
| — | `torchtitan/distributed/__init__.py` now does `from torchtitan.distributed import cuda_graph_backend` so the registration always runs |

#### Public names (renamed)
| Kind | Source (`distributed.cuda_graph`) | Destination |
|---|---|---|
| const | `NUM_CUDA_GRAPH_WARMUP_STEPS` | `accelerator_graph.NUM_ACCELERATOR_GRAPH_WARMUP_STEPS` |
| class | `CUDAGraphInputSpec` | `accelerator_graph.AcceleratorGraphInputSpec` |
| class | `CUDAGraphManager` | `accelerator_graph.AcceleratorGraphManager` |
| singleton | `cuda_graph_manager` | `accelerator_graph.accelerator_graph_manager` |
| class | `CUDAGraphWrapper` | `accelerator_graph.AcceleratorGraphWrapper` |
| fn | `cuda_graphs_supported()` | `accelerator_graph.accelerator_graphs_supported()` |
| fn | `wrap_with_cuda_graph()` | `accelerator_graph.wrap_with_accelerator_graph()` |
| fn | `wrap_fwd_bwd_with_cuda_graph()` | `accelerator_graph.wrap_fwd_bwd_with_accelerator_graph()` |
| fn | `cuda_graph_teardown()` | `accelerator_graph.accelerator_graph_teardown()` |
| fn | `get_cuda_graph_annotations()` | `accelerator_graph.get_accelerator_graph_annotations()` |
| fn | `get_cuspy_cuda_graph_annotation_config()` | **moved, name unchanged** -> `cuda_graph_backend.get_cuspy_cuda_graph_annotation_config()` |

#### Private names (renamed)
| Source | Destination |
|---|---|
| `_CUDAGraphGradientState` | `_AcceleratorGraphGradientState` |
| `_ForwardBackwardCUDAGraphWrapper` | `_ForwardBackwardAcceleratorGraphWrapper` |
| `_wrap_with_cuda_graph` | `_wrap_with_accelerator_graph` |
| `_run_eager_on_cuda_graph_stream` | `_run_eager_on_accelerator_graph_stream` |

#### New APIs
| Location | API | Purpose |
|---|---|---|
| `accelerator_graph` | `class GraphBackend` | Default backend built on `torch.accelerator.Graph`. Hooks: `unsupported_reason()`, `new_stream()`, `initialize(stream)`, `capture(fn, args, *, pool, stream, annotation_config)`, `annotations()`, `teardown()` |
| `accelerator_graph` | `register_graph_backend(device_type, backend)` | Sets the backend used for a `device_type` |
| `accelerator_graph` | `AcceleratorGraphManager.capture(fn, args, *, annotation_config)` | Sends capture to the active backend and collects its annotations. Before, the wrapper called `torch.cuda.graph` itself |
| `accelerator_graph` | `_backend()`, `_unsupported_reason()` (private) | Look up the backend; return a reason string, or `None` if capture is supported |
| `cuda_graph_backend` | `class CUDAGraphBackend(GraphBackend)` | Keeps the old CUDA path (`torch.cuda.graph`, dummy-graph pool warmup, `thread_local` capture mode, kernel annotations, ROCm excluded) |

#### Signature and type changes on existing members
| Member | Source | Destination |
|---|---|---|
| `Manager.stream` | `torch.cuda.Stream` | `torch.Stream` |
| `Manager._dummy_graph` | `torch.cuda.CUDAGraph \| None` attribute | removed; moved to `CUDAGraphBackend._dummy_graph` |
| `Manager.graph_pool` | asserted non-`None` | can be `None` (taken from the first graph's `pool()` on non-CUDA backends) |
| `Manager.teardown()` | no sync | calls `torch.accelerator.synchronize()` first, then `backend.teardown()` |
| `Wrapper._graph` | `torch.cuda.CUDAGraph \| None` | `Any` |
| `annotation_config` docstring | "Passed to `torch.cuda.graph`" | "Backend-specific annotation options" |

#### Torch calls replaced inside the wrapper
| Source | Destination |
|---|---|
| `torch.cuda.current_stream()` | `torch.accelerator.current_stream()` |
| `with torch.cuda.stream(s):` | `with s:` |
| `torch.cuda.empty_cache()` | `torch.accelerator.empty_cache()` |
| `torch.cuda.memory_stats()` / `mem_get_info()` | `torch.accelerator.memory_stats()` / `get_memory_info()` |
| `utils.device_type == "cuda" and torch.cuda.is_available() and hip is None` | `current_accelerator(check_available=True).type == utils.device_type`, then `backend.unsupported_reason()` |
| `Optim`: `parameter.device.type == "cuda"` | `parameter.device.type == device_type` |

#### Unchanged (still CUDA-named)
These keep their CUDA names, so the naming is now mixed:
- Config fields: `training.disable_cuda_graphs`, `training.cuda_graph_per_microbatch_group`, `Optim.Config.enable_cuda_graph`, `profiler.maybe_cuda_graph_annotation_config()`
- Helpers: `post_validate_fsdp_for_cuda_graph`, `prepare_pipeline_schedule_for_cuda_graph`
- Internal attributes: `_cuda_graph_enabled`, `_forward_backward_cuda_graph_enabled`, `_cuda_graph_annotation_config`
- Docs and experiments: `distributed/CUDA_GRAPH.md` (the body text is updated), `experiments/graph_trainer/cuda_graph.py` (`cuda_graph_pass`, `reset_cuda_graphs`)
- One user-facing message: `validator.py:~187` still warns "CUDA graph capture is only supported on NVIDIA CUDA". `_wrap_with_accelerator_graph`'s message was changed to `Graph capture is unavailable ({reason})`, so the validator warning is now out of date.
