# [kimi] Fix multimodal TP SPMD boundary type

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5204) · state: closed · merged: True

## Original PR description

## Summary

- Correct the Kimi K3 multimodal decoder-boundary assertion from TP `I` to TP `R`.
- Align the assertion with the existing token-embedding output and layer-0 input sharding contracts.
- Keep computation and communication unchanged; this only fixes SPMD type validation.

## Why

`_set_multimodal_decoder_boundary_sharding` already declares the fused multimodal activation as TP `R` in two places: `tok_embeddings.out_dst_shardings` produces it, and layer 0 accepts it through `in_src_shardings`. Both the real-image fusion path and the text-only dummy-vision path preserve that layout.

The assertion added in #4639 instead required TP `I`. TP was size 1 in that PR's CP coverage, so the mismatch was not exercised. The B200 `kimi_k3_mm` recipe enables FSDP2/TP2/SP/EP2 and exposes the incorrect assertion as `tensor has R, expected I`. The error names `mesh_ep` because TP and EP use the same physical rank groups in this topology.

This is an assertion-contract bug, not a data-dependent activation layout.

**The change is correct. LGTM.** Your three points are all right. The `I` -> `R` transition already exists: it happens at the **output of the vision encoder module itself**, before the fusion step, not inside the scatter/gather.

### Where `I` -> `R` happens

`torchtitan/models/kimi_k2_7/sharding.py:110-119` (`set_moonvit_sharding_config`, which K3 reuses at `kimi_k3/sharding.py:68`):

```python
invariant_activation_placement  = SpmdType({DP: V, CP: R, TP: I})
replicated_activation_placement = SpmdType({DP: V, CP: R, TP: R})

ve_cfg.sharding_config = ShardingConfig(
    state_shardings={"pos_embed": state_placement},
    out_src_shardings=invariant_activation_placement,   # encoder internals: I@TP
    out_dst_shardings=replicated_activation_placement,  # handed to the decoder: R@TP
)
```

`Module._redistribute_outputs` (`torchtitan/protocols/module.py:582-592`) asserts that the encoder output is `out_src` (`I`), then runs `spmd_redistribute_per_axis(I -> R)`. That conversion does nothing in the forward pass. In the backward pass it all-reduces the `P@TP` gradient coming from the decoder, which turns it into the `I@TP` gradient the encoder expects. This is the transition you were looking for.

### Full TP trace for `h_TD`

| Stage | TP type | Where |
|---|---|---|
| `pixel_values` / dummy inputs | `I` | `multimodal_input_sharding()`, `build_dummy_vision_inputs` |
| Encoder blocks, norms, projector | `I` (colwise/rowwise convert to `R`/`S` locally, rowwise returns to `I`) | `common/vision_encoder_sharding.py` |
| **Encoder output** | **`I` -> `R`** | `kimi_k2_7/sharding.py:117-118` |
| `tok_embeddings` output | `P` -> `R` | `kimi_k3/sharding.py:281-282` |
| Fusion (`scatter_vision_embeds` / `gather_vision_embeds` / `add_zero_vision_dependency`) | `R` + `R` -> `R` | `common/multimodal.py`. `gather` and the dummy path call `assert_type_like(out, inputs_TD)`, so the output is checked to match the `R` text embeddings |
| **Assertion this PR fixes** | **`R`** | `kimi_k3/model.py:632` |
| Layer 0 entry | `R` -> `S(0)` with SP, `R` -> `I` without | `kimi_k3/sharding.py:285-296` |

So the fused `h_TD` is `R@TP` on all three paths (real-image scatter, CP gather, text-only dummy). The old `I` assertion contradicted both the `tok_embeddings.out_dst_shardings` above it and the `layers[0].in_src_shardings` below it. #4639 only tested TP=1, which is why the mismatch went unnoticed.

One thing that follows from this: the boundary is `R`, not `I`, because the decoder's gradients come back `P@TP`. The vision encoder's own `I -> R` redistribution performs the all-reduce that is needed before encoder backward. Annotating `h_TD` as `I` would have meant claiming the fused activation already had an invariant gradient, which is not true.
