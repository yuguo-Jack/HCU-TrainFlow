# [HiMidLoLinear] Accumulate LM-head WGRAD into the running fp32 grad in place

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5137) · state: closed · merged: True

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.18.0) (oldest at bottom):
* #5250
* #5249
* __->__ #5137

----

- LM-head (wide) backward adds WGRAD into the running fp32 weight.grad with
  addmm(out=), as MXFP8Linear already does; skips AccumulateGrad's add and a
  [vocab, D] fp32 temporary on ChunkedLossWrapper chunks / microbatches.
- Router (narrow) and fp32-fallback paths unchanged; comments explain why.
- Explicit `inplace_wgrad_accum: bool = True` config on HiMidLoLinear and
  MXFP8Linear (like DistMoeTransform). Raises instead of silently falling
  back when traced (torch.compile, make_fx) or for a non-leaf weight;
  HiMidLoLinear rejects num_linears > 1 with it on. GraphTrainer conversion
  and flavor builders turn it off, and GraphTrainer.Config rejects it on.
- Shared helpers in models/common/inplace_wgrad_accum.py
  (uses_inplace_wgrad_accum, read-only running_grad); each backward clears
  weight.grad itself next to its in-place add.
- Pipeline schedules that split backward into input and weight passes
  (ZBVZeroBubble, DualPipeV, InterleavedZeroBubble) turn the option off: both
  passes run under autograd.grad(), where AccumulateGrad never runs, and
  adding into .grad there dropped the earlier microbatches' gradients (an
  existing MXFP8 bug). 1F1B, Interleaved1F1B and GPipe keep it.
- The in-place add uses the running grad's dtype (fp32 under an FSDP fp32
  reduce dtype, bf16 without FSDP), so it needs no dtype check; keep MXFP8's
  grad_dtype fallback, since FSDP clears grad_dtype during backward.
- Qwen3-8B LM head, chunk-2 backward on H100: 11.98 -> 9.19 ms, peak
  3.54 -> 1.22 GiB; weight.grad bitwise identical.
