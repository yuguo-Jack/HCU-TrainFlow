## Why

The shared GDN wrapper enables Attention Gym's L2-normalization backward
autotuner even when PyTorch deterministic algorithms are enabled. Two
independent Flash-Next TP2/EP2/SP runs with the same source, runtime, seed
checkpoint and input order therefore produce different full-precision
grad_norm at step 5 and loss at step 6.

Operation traces find equal normalization inputs followed by different BF16
gradients. Pinning only the backward launch to the configurations selected by
the two remote jobs reproduces each complete ten-step curve exactly locally.
The cause is the launch policy in the shared wrapper; Attention Gym already
provides a public fixed-configuration option, and the KDA wrapper already uses it.

**Example.** No recipe option is added:

```python
torch.use_deterministic_algorithms(True)
# Packed GDN Q/K: [1, 128, 1, 128].
# Before: backward benchmarks tiles despite deterministic mode.
# After: use Attention Gym's fixed backward launch.
normalized_q = l2norm(
    q, cu_seqlens=cu_seqlens,
    autotune=not torch.are_deterministic_algorithms_enabled(),
)
```

## What changed

- Pass the deterministic launch policy at every shared GDN normalization call:
  chunk execution, recurrent forward, its recomputed chunk backward, and CP.
  Qwen3.5/3.6/3.8 and Flash-Next receive the fix through the shared component.
- Extend the existing GDN GPU tests with packed chunk/recurrent cases. Actual
  backward must bypass the normalization autotuner in deterministic mode and
  retain autotuning when that mode is disabled. Gradients must be finite and
  nonzero. The test fails both deterministic paths on the base commit.
- Mechanical: give the rewritten normalized/output tensors their shape suffixes.
  The public config API, parameter keys and tensor layouts are unchanged.

This PR depends on `[qwen3_8_fn] 2/n`. Pipeline support follows in `4/n`.
PR #5680 changes graph metadata and does not supply this normalization policy.

## Alternatives considered

- A Flash-Next-only launch flag would leave the shared GDN callers inconsistent.
- Disabling autotuning unconditionally would change ordinary training's policy.
- Relaxing equality checks would leave strict deterministic execution unreliable.

## Numerics

The historical normalization-policy checks used the reviewed `ccdb01be` prefix.
The latest upstream additionally changes GDN dtype preservation; Flash-Next
explicitly retains its previous BF16 policy. Current GPU qualification is pending.
The historical full-model/C4/offline/PP captures below use full-stack source
`cb0444dea14eb5a351e978866bf01872022f157f`, including its later pipeline support.
A separate full-stack rebase run at `07d0138e` matches all 20 PP2/full-remat
loss/grad_norm values bitwise on two GB300 GPUs using the same FP32 seed checkpoint.

The forward kernel is already fixed. Changing the backward launch can change
BF16 rounding and subsequent optimizer updates; this is a computation change,
not a claim of bitwise equality to every former autotuned configuration.
The same reference fixtures and gradient bounds are retained.
