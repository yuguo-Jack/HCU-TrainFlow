# [moe][perf] AllToAll dispatcher: permute and unpermute with gathers (1/6)

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5162) · state: open · merged: False

## Original PR description

**TLDR:** The AllToAll dispatcher's eager permute and unpermute become gathers: -5.3 ms per MoE layer at 16k tokens on every EP>1 step, bitwise identical. Reference path (Dist-MoE and DeepEP are the supported ones), low priority.

**Stack** (6 PRs, merge bottom-up; this PR is in **bold**)

| # | PR | Independent? | Needs (stack positions) |
|---|---|---|---|
| **1** | **AllToAll dispatcher: permute and unpermute with gathers** | **yes** | **—** |
| 2 | Argsort expert ids on the narrowest integer type | yes | — |
| 3 | EP=1 inference: gather-sum MoE combine region | no | 2 |
| 4 | EP=1 inference: sort-region MoE dispatch | no | 2, 3 |
| 5 | Gather-sum dispatch and combine for training, at any EP | no | 4 |

**Problem**
1. **Permute.** `AllToAllTokenDispatcher._permute` reorders the received rows with `x[perm]`.
2. **Its backward.** An accumulating `index_put`: a sort plus a zero fill.
3. **Unpermute.** `_unpermute` writes `out[perm] = y`, a non-vectorized scatter.
4. **Where.** Both run eagerly, outside any compile region, on every EP>1 step.
5. **Cost.** 9.36 ms per MoE layer at 16k tokens (DeepSeek-V3, one EP2 rank).

**Solution**
1. A permutation's inverse is a gather, so no accumulation is needed.
2. `_PermuteRows` gathers by the permutation and backpropagates by gathering with its inverse.
3. `_unpermute` gathers by the inverse.
4. Unchanged: TorchAO's padded `_unpermute`.

```text
before:  fwd x[perm]          bwd index_put accumulate (sort + zero fill)
         fwd out[perm] = y    (scatter)
after:   fwd x[perm]          bwd g[inv_perm]
         fwd y[inv_perm]
```

**Results**
```text
Numerics: bitwise identical (pure row moves).

_permute + _unpermute fwd+bwd, DeepSeek-V3 EP2 rank (128 local experts), R = 8T rows x 7168 bf16,
random balanced counts, GPU kernel time in us, median [range] of 3 processes
T     eager                                    compiled
4k    2377 [2376-2466] -> 1077 [1076-1077]     1155 -> 698
16k   9357 [9349-9357] -> 4082 [4080-4083]     4738 -> 2774
per MoE layer: -5.3 ms at 16k, -1.3 ms at 4k
```

You may ask: why not compile the permutes? The eager gathers are close to the compiled version.

NOTE:
- Reaches every recipe with the AllToAll dispatcher at EP>1 (deepseek_v3_671b uses EP=2).
- Under an outer compile, the inverse permutation adds two small scatters.
- Not tested: a real multi-GPU EP run, GraphTrainer with EP, H100.
