# Preserve MXFP8 Dist-MoE weights subclass after EP/TP sharding

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5341) · state: closed · merged: True

## Original PR description

**Problem:**
- MXFP8 Dist-MoE stores w13/w2 as tensor subclasses (`_DistMoeW13ShardedTensor`, `_DistMoeW2ShardedTensor`). On each FSDP unshard they quantize the weight to MXFP8 once and cache it
- EP/TP sharding (spmd_types) returns a plain tensor, so w13/w2 lose their subclass and the cache is never built
- No error: every forward quantizes the bf16 weights again instead, in both training and inference
- `MXFP8Linear` and `NVFP4Linear` already handle this by restoring the subclass in `_parallelize`; Dist-MoE did not

**Fix:**
- Override `MXFP8DistMoeRoutedExperts._parallelize` to restore the w13/w2 subclasses after sharding, same as `MXFP8Linear` / `NVFP4Linear`

**Testing:**
Qwen3-30B-A3B GRPO with MXFP8 Dist-MoE, trainer (FSDP2 x TP2 / EP4) and generator (DP4 / EP4) share 8 B200s, 10 steps:
- Before: w13/w2 reach forward as plain tensors on all ranks, so the weights are quantized on every forward
- After: forward gets the cached MXFP8 weights on all ranks. Per weight sync the generator quantizes 96 times (2 x 48 layers) and the trainer once per FSDP unshard, with 0 quantizations in forward. Reward and trainer/generator logprob agreement unchanged
