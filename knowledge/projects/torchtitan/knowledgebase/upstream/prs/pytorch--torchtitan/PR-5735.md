# [tests] Add per-backend testcase skipping config

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5735) · state: open · merged: False

## Original PR description

## Summary

Replace the per-definition `skip_rocm_test: bool` on integration tests with a
per-backend `skip_cases.toml`:

- one section per backend, matched against `utils.device_type`; `all` applies to
  every backend, and `cuda` / `rocm` are distinguished with
  `torch.version.hip`;
- the loader merges every source into one skip table; the runner filters during
  selection and logs the matched section;
- out-of-tree devices can register their own TOML through an entry point or by
  calling `register_skip_cases()` explicitly, using the same format and parser
  as the in-tree file;
- the default rules migrate the 24 ROCm skips in the core suites; the seven
  graph_trainer skips move to their own TOML, registered by that runner with
  `suites=`;
- add a README, a rule, and unit tests.

## Background

Integration tests currently have no unified skip mechanism: skipping is spread
across per-definition booleans, and some of them, such as skip_rocm_test, are
tightly coupled to specific hardware.

## Design

Skip rules live under `tests/integration_tests/skips/`:

```text
tests/integration_tests/skips/
  __init__.py        # parse, merge, validate, query
  skip_cases.toml    # default rules maintained by titan
  README.md          # format and registration
```

### TOML format

```toml
[rocm]
features = [
  "sdc_replay_accelerator_graph",
  "fsdp_pp_deferred_gradient_reduction",
]
models = [
  "deepseek_v3_fused_mla_swiglu_fsdp+ep",
  "qwen3_5_moe_fsdp+tp+ep",
]
h100 = [
  "dist_gemm",   # symmetric memory is CUDA-only
]
```

- section names are matched against the backend: `npu` / `xpu` and so on compare
  directly with `utils.device_type`; `cuda` and `rocm` are special cases because
  both report `device_type == "cuda"`, and are distinguished with
  `torch.version.hip`; `all` applies to every backend;
- keys are suite names, defaulting to the `_TEST_SUITES` values in
  `tests/integration_tests/run_tests.py`; a registered file can extend them with
  `suites=`;
- values are the `test_name`s of that suite's `IntegrationTestDefinition`
  entries;
- reasons are trailing comments on the entry; a suite or test-name mismatch
  raises `ValueError` before any test starts.

### Registering an out-of-tree device

Beyond the default file, an out-of-tree device can register its own TOML, using
the same schema, in two ways:

1. entry point:

   ```toml
   [project.entry-points."torchtitan.skip_cases"]
   device = "your_package.skips:register"
   ```

   ```python
   # your_package/skips/__init__.py
   def register(): register_skip_cases("path/to/your_toml")
   ```

   Set `TORCHTITAN_SKIP_CASES_AUTOLOAD=0` to disable automatic registration.

2. call `register_skip_cases(path)` directly from the test bootstrap.

In both cases `suites=` can be omitted; the file is then held to titan's own
suite list. Pass it only when the file introduces suites outside `_TEST_SUITES`.

## Migration

- remove `skip_rocm_test` from `IntegrationTestDefinition`;
- move the 24 `skip_rocm_test=True` entries in the core suites into `[rocm]`;
- move the seven graph_trainer `skip_rocm_test=True` entries into
  `torchtitan/experiments/graph_trainer/tests/skips/skip_cases.toml`, registered
  by that runner with `suites=set(_TEST_SUITES_FUNCTION)`;
- add `tests/integration_tests/skips/README.md`, link it from the Test Structure
  in `tests/README.md`, and add a rule to `.claude/rules/tests.md`;
- the test cases themselves are unchanged; out-of-tree callers that still pass
  `skip_rocm_test` are incompatible and need to move to the TOML.

## Validation

Selection over the current main inventory (86 definitions: features 51 /
models 26 / h100 9):

- CUDA: 86 runnable / 0 filtered;
- ROCm: 62 runnable / 24 filtered (features 14 / models 6 / h100 4), matching the
  current `skip_rocm_test=True` count;
- `tests/unit_tests/cpu/test_skip_cases.py`: 5 tests pass, covering
  parse/validation errors, suite declaration, section matching, entry-point
  registration/failure, and the no-`test_suite` runner.
