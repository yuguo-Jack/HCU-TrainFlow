# [MXFP8] Consume directly blocked activation scales

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5334) · state: open · merged: False

## Original PR description

Performnace of this fused cute-dsl quantizer is better than cuda, a single API for dense and grouped mxfp8 linears, no need for scale rearrangements since swizzled layouts are directly output.

AI-assisted implementation details:

> ## Summary
>
> Reuse TorchAO's directly blocked dense activation/gradient API from [#4995](https://github.com/pytorch/ao/pull/4995), with existing single-axis CuTeDSL casts. Keep CUDA as default and CuTeDSL as explicit `activation_quantization_backend` opt-in through the Linear and converter.
>
> Both-axis calls use `offs=None` and compact scales. The synthetic endpoint tensor/cache, separate FakeTensor endpoint branch and column-scale padding trim are removed. Construction checks the required dense API signature and runtime; unsupported BF16 shapes fail explicitly rather than padding to a larger GEMM or silently selecting another backend. Both matrix axes must be 128-aligned.
>
> Every cast explicitly requests RCEIL. Weight quantization, output ownership, FSDP lifetime, backward-save format and in-place gradient accumulation policy are unchanged. This PR depends on one AO PR, #4995; Protonu's #4895 and Aleksandar's #4702 remain credited provenance rather than extra dependencies.
>
> ## Executed local verification
>
> 69 affected CPU tests, 32 Linear GPU tests and 6 real two-rank FSDP lifecycle tests passed against the exact AO candidate. Tests cover actual cast directions, both backward-save formats/accumulation, FakeTensor layout, compiled RAF, retained PP weights and CUDA-graph replay.
>
> Strict README/config documentation rendering passed. All full-repository non-type hooks passed; the known unchanged `video.py:114` Optional-time-base type error remains explicitly deferred, not reported as a clean full type run.
>
> Matched AO cast timing/traces are recorded in #4995. No full-training speedup or owned-output optimization is claimed. External review/CI and upstream merges remain pending.
>
