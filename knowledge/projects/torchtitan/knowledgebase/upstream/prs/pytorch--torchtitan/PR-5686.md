Part **13/n** of the Kimi K3 / Dist-MoE training stack. Stacked on
[#5685](https://github.com/pytorch/torchtitan/pull/5685). A separate 14/n
provides the full-scale MXFP8 recipe consumers.

## Why

The existing remat policy applies each save-region pattern to every transformer
block. Keeping an expensive attention core in one late Kimi layer therefore
requires retaining that core everywhere or changing model code. A block-qualified
save mapping lets a recipe spend a limited activation budget without changing
global expert recomputation or pipeline partitioning.

**Example.**

```python
from torchtitan.distributed.activation_remat import ActivationRematConfig

policy = ActivationRematConfig(
    save_regions=[],
    block_save_regions={"layers.91": ["attention.inner_attention"]},
)
# Only original layer 91 gains this save, including after a PP split.
# Explicit recompute_regions still take precedence.
```

## What changed

- Resolve original block-FQN globs into additive save-region patterns once when
  configuring existing checkpoints.
- Preserve global recompute precedence and saved-tensor-hook ownership; reject
  block overrides on fixed Full/default policies.
- Extend the component's REMAT.md and add numerical/ownership regressions next
  to activation-remat code.

The two forwarding-only recipe wrappers and their wrapper-only tests are
removed. The full-scale consumer constructs this existing policy field directly.

## Alternatives considered

- A global attention save retains the core in every layer and spends more memory.
- Model-specific checkpoint branches duplicate the existing region mechanism.
- Another checkpoint engine or backend arena setting is unnecessary; this only
  selects regions declared by the model.

## User-facing changes

| Before | After |
| --- | --- |
| Save patterns apply uniformly to every block. | Optional block-FQN globs add saves only to matching original blocks. |
| Full/default presets have fixed policies. | They still reject customization; use ActivationRematConfig explicitly. |

The default mapping is empty. Extra retained tensors follow existing pack/unpack
hooks and do not resize Dist-MoE's own activation arena.

## Numerics and testing

Fresh retained-parent checks: **138 CPU tests** and **four GPU-0-only graph
probes** pass.

```bash
CUDA_VISIBLE_DEVICES='' python -m pytest -q -o addopts= --tb=short \
  tests/unit_tests/cpu/distributed/test_activation_remat.py \
  tests/unit_tests/cpu/models/common/test_dist_moe.py \
  tests/unit_tests/cpu/test_trainer.py \
  tests/unit_tests/cpu/recipes/test_shared_expert_overlap.py
```

CPU regressions verify exact loss, input/parameter gradients, original PP layer
IDs, additive glob/global saves, recompute precedence, fixed-preset rejection,
and saved-tensor-hook ownership. GPU probes cover FP32/BF16 with and without an
explicit recompute override: five changing-input captured-graph updates match
the uncheckpointed reference exactly in loss, input/parameter gradients, and
every parameter update. Assertions and deterministic execution remain strict.

All non-type hooks pass. Historical two-GPU PP2/VPP2 checks are separate
evidence, not fresh results from this one-GPU review.
