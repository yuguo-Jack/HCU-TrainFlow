# Test that a saved projection returning a view reaches its bare consumer

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5246) · state: open · merged: False

## Original PR description

Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.18.0) (oldest at bottom):
* __->__ #5246

Human Note
------------
Adding a test for D124426423 that was not caught earlier. That diff has not gone through review yet, when the diff is merged, the test should pass. I will land then.

Agent Notes
------------

The default activation-checkpointing policy saves every linear's local
projection region. MXFP8Linear's projection computes on rows padded to a block
multiple and returns the unpadded slice, a view of a larger buffer. Linear
reshapes that view and FeedForward pins the reshape for the activation, a bare
consumer that recomputation replays. torch_remat persisted a saved output
through a weak reference to the output tensor object, which nothing keeps
alive here (the reshape references the padded buffer), so the pin silently
persisted nothing and recomputation failed:

    RuntimeError: layers.5::feed_forward.w13.linear.out is a placeholder for
    the output of remat.region 'layers.5::feed_forward.w13.linear'
    (recompute=False) ...

This broke llama3_debugmodel_mxfp8 on B200, which only the nightly/ciflow
B200 suite runs. Add a hardware-independent unit test: a column-parallel w13
whose projection mimics MXFP8's padded path, run under the default policy and
compared bitwise against no activation checkpointing.

The test fails with the torch_remat currently pinned and passes with the
torch_remat fix (D124426423); bump the torch_remat pin to that fix's commit
before landing.
