# [qwen3.5, kimi_k3] GDN and KDA: Attention Gym's cuDNN chunk kernels on Blackwell

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5225) · state: closed · merged: True

## Original PR description

**TLDR:** on Blackwell, Gated DeltaNet (Qwen3.5) and KDA (Kimi K3) run Attention Gym's cuDNN chunk kernels instead of the fused ones: Qwen3.5-27B GDN fwd+bwd 2.3-3.9x faster on GB300, generator prefill 2.8x faster.

**Problem**
1. Qwen3.5's Gated DeltaNet layers (3 of every 4) run Attention Gym's chunk kernels in training (`chunk_gdn`) and in generator prefill (`paged_chunk_gdn`); Kimi K3's KDA layers run `chunk_kda`.
2. Attention Gym ships two backends for them: `fused` (any GPU) and `cudnn` (SM100/SM103, packed fp16/bf16).
3. TorchTitan always runs `fused`.
4. **Cost:** on GB300, `fused` is 2.3-3.9x slower than `cudnn` (table below).

**Solution**
1. `chunk_kernel_options(q)` in `torchtitan/models/common/attention/kda.py` returns `{"backend": "cudnn"}` for packed (batch 1) fp16/bf16 CUDA inputs on SM100/SM103, and `{"backend": "fused"}` otherwise.
2. Four calls pass it as `kernel_options`: GDN's `chunk_gdn` (trainer) and `paged_chunk_gdn` (generator prefill), and KDA's `chunk_kda` (trainer) and `paged_chunk_kda` (generator prefill). The generator's state caches are already FP32, which paged cuDNN requires. KDA's cuDNN backend also needs a gate lower bound >= -5.45; `KDAKernel.Config.lower_bound` is validated to `[-5, 0)`.
3. `pyproject.toml` and `requirements.txt` pin `attn-gym[linear,cudnn]==0.0.16`; the RL README says which kernels run where.
4. Unchanged: decode (no backend choice), batch-invariant mode (keeps fused; paged KDA replay requires it), deterministic mode (keeps fused: I haven't checked whether cuDNN's backward is deterministic), and every non-Blackwell GPU.

**Results**
GB300, the four calls above through Attention Gym main (`70fd810`, cutlass-dsl 4.7.1), bf16, 16,384 packed tokens in 5 documents, fused -> cudnn, ms (median of 10):
```
GDN chunk_gdn, fwd+bwd (HK 16, HV 48, D 128)     4.28 -> 1.85   (2.3x)
GDN paged_chunk_gdn, prefill                     1.34 -> 0.42   (3.2x)
KDA chunk_kda, fwd+bwd (H 32, D 128)             3.82 -> 2.31   (1.7x)
KDA paged_chunk_kda, prefill                     1.37 -> 0.59   (2.3x)
```
- cudnn vs fused, relative L2: outputs 4.7-4.9e-3, gradients <= 7.1e-3, updated paged states <= 3.7e-3 (bf16 noise).
- Earlier, Qwen3.5-27B GDN fwd+bwd at 40,960 tokens (attn-gym 0.0.15): 1 x 40960 9281 -> 4018 us, 10 x 4096 8839 -> 2985, 184 x 200 + rest 14409 -> 3690. A 4B generator with cuDNN GDN prefill produced the same greedy text as fused.

You may ask: why no config field to pick the backend? Nothing needs `fused` on Blackwell today, and the outputs match. A field can come with the first case that does.

**Test plan**
- On B200 CI, the existing `test_qwen3_5_deltanet.py` varlen tests (bf16, packed) and the KDA / Kimi K3 GPU tests with packed bf16 inputs now run the cuDNN backend; elsewhere (and batch > 1) they run fused as before.
- The kernel check above ran the four Attention Gym calls directly. TorchTitan's own modules were not run locally on this branch: my torch nightly predates main's imports.
