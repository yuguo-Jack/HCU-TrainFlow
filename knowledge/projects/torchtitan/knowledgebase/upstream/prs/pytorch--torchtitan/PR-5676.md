# [fsdp] 3/n Support layer-scoped CPU offload

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5676) · state: closed · merged: False

## Original PR description

Part **3/n** of the Kimi K3 / Dist-MoE training stack. Based on `main`: the review diff contains only this feature.

## Why

Whole-model CPU offload is too coarse when only a few transformer blocks exceed the memory budget. Selecting layer FQNs must affect both FSDP wrapping and local parameter materialization; otherwise wrapping and initialization disagree. MTP decoder paths also need the same policy.

Example:

```python
ParallelismConfig(
    fsdp_cpu_offload_layer_fqns=("layers.7", "layers.15"),
)
# These block units use CPU offload.
# Other parameter units and model buffers retain their usual placement.
```

## What changed

- Validate selected block FQNs and reject simultaneous selected-layer and whole-model offload.
- Forward the selected policy through common decoder, DeepSeek MTP, and fault-tolerant initialization paths.
- Initialize selected local shards on CPU while keeping model buffers device-resident.
- Add regression coverage for all MTP policy-forwarding call sites.

## Alternatives considered

Moving completed modules to CPU after construction can materialize full parameters first and miss FSDP's offload contract. Offloading the entire model needlessly affects otherwise memory-safe units.

## User-facing changes

| Before | After |
| --- | --- |
| Only whole-model offload is configurable, and model materialization has no selected-layer contract. | Recipes may offload explicit transformer-block FSDP units; empty selection preserves existing behavior. |

## Numerics

Parameter/offload ownership changes, not the layer computation or HF checkpoint mapping. Fresh distributed offload loss/gradient parity remains a landing gate.
