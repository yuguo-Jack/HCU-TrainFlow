# [DistMuon] Send redistributed inputs and directions in BF16

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5279) · state: closed · merged: True

## Original PR description

Part of #5278.

Newton-Schulz casts its input to BF16 before it normalizes, so the prepared input and the direction can be sent in BF16 and the update keeps the same bits.

- The bucket plan carries a `transport_dtype`. The exchange buffers and the scratch buffers are reserved in that dtype (keyed by device and dtype), and the plan hash includes it.
- BlockShard parameters: each block is its own Muon matrix and can have its own lr ratio (`match_rms_adamw` uses sqrt(max(rows, cols))). main multiplies a block's direction by ratio / reference right after Newton-Schulz, in the FP32 compute scratch. In BF16 that multiply would round again, so this PR sends the raw direction and applies ratio / reference after it arrives, in the storage dtype, as a per-row scale (`_direction_row_scale`, rows from `_block_row_spans`). Blocks with the reference ratio get 1.0; when no block differs the multiply is skipped.

Numerics: parameter and momentum digests of every Muon parameter and loss / grad_norm over 40 steps are the same as main (Kimi K2.5 debugmodel on 8 GPUs, Moonlight 27 layers, Kimi K3 debugmodel).

Perf: 8x A100, K2.5 3 layers EP8, slowest rank 251.8 -> 245.9 ms. On a PCIe box (8x 3090) where the exchange is not hidden, 2689 -> 1195 ms. Exchange buffers are half the size.
Test plan: `pytest tests/unit_tests/cpu/distributed/flex_shard`; GPU and CPU flex_shard tests pass on 8x A100 on this PR; K2.5 debugmodel 40 steps on 8x A100 gives the same parameter and momentum digests and loss as the base.
