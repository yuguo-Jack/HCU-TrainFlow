# [_torch_compat] Accept 2.15.0.dev* builds for the pipelining backports

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5801) · state: open · merged: False

## Original PR description

## Why
The gate required an exact "2.15.0" match, so nightly/dev installs
(2.15.0.devYYYYMMDD) silently skipped all pipelining backports
(#199884, #200238, #200199): no error, no log line. Schedules then
behave differently between an RC and a dev build of the same release,
which is costly to diagnose.
## What changed
Relax the gate to startswith("2.15.0") so dev builds load the backports
too. Safety is unchanged:
- each function edit is anchored by before/after sha256 of the target
  source, so a dev build whose source drifted fails explicitly with the
  "revalidate compatibility backport" error instead of being patched
  blindly;
- TORCHTITAN_DISABLE_TORCH_COMPAT=1 still opts out process-wide.
## Testing
On torch 2.15.0.dev20261005: the startup warning confirms the
compatibility backports now apply, and fsdp2_pp2_deferred (4 GPUs),
looped_bfs and interleaved_1f1b (2 GPUs) pass 10 training steps with
expected loss and grad_norm.
