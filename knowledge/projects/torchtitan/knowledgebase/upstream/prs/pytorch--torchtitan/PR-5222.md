# [attention] Pin varlen attention to Flash so FA3/FA4 run instead of cuDNN

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5222) · state: closed · merged: False

## Original PR description

**TLDR:** pin both varlen attention calls to torch's Flash backend, so the FA3 (H100) / FA4 (B200/GB300) that `VarlenInnerAttention` activates actually runs. On current torch nightlies, `varlen_attn` silently runs cuDNN instead whenever cuDNN supports the batch.

**Problem**
1. **TorchTitan picks the kernel.** `VarlenInnerAttention.__init__` activates FA3 on H100 and FA4 on B200/GB300, behind torch's Flash backend.
2. **torch tries cuDNN first.** Since the 2026-08-20 nightly, `varlen_attn` picks cuDNN over Flash for any causal packed batch cuDNN supports (`_select_backend` in `torch/nn/attention/varlen.py`).
3. **Pretraining hits it:** gpt-oss by default; Qwen3, Llama 3 and DeepSeek-V3 with `attn_backend="varlen"`.
4. **RL hides it:** importing vLLM calls `torch.backends.cuda.enable_cudnn_sdp(False)` (`vllm/platforms/cuda.py:53`), so the RL trainer and generator run FA3/FA4 only through that side effect.
5. **Consequences:** a torch update changed the kernel without a TorchTitan change, and cuDNN's varlen backward is not deterministic, so `--debug.deterministic` is not reproducible with varlen on Blackwell.

**Solution**
1. Run `VarlenInnerAttention.forward` (pretraining, RL trainer) and `TorchTitanVarlenInnerAttentionImpl.forward` (RL generator) under `sdpa_kernel(SDPBackend.FLASH_ATTENTION)`.
2. The backward follows: torch's varlen backward reuses the backend the forward picked.
3. Unchanged: other SDPA callers keep their own backend lists; A100, ROCm and batch-invariant mode never reached cuDNN.

**Results**
Cost of the pin, GB300, varlen fwd+bwd, 32 heads, causal, 16k tokens, cuDNN 9.25.1, FA4 4.0.0b34, ms (min of 3 `do_bench`):
```
(qk, v) head dims   packing        cuDNN    FA4    FA4 / cuDNN
(128, 128)          4 x 4096       1.857   1.889   1.02x
(128, 128)          16 x 1024      1.001   1.123   1.12x
(192, 128)          4 x 4096       2.527   2.671   1.06x
(192, 128)          16 x 1024      1.287   1.439   1.12x
```
- DeepSeek-V3's attention through TorchTitan's own `VarlenInnerAttention` (128 heads, (192, 128), 8 shapes, CUDA graphs): FA4 is 0.97-1.38x cuDNN's time.
- In eager, `sdpa_kernel` adds about 7 us of CPU per attention call.

You may ask:
- Why pin if cuDNN is faster on these shapes? So the kernel is the one TorchTitan chose on every torch version and in every process, deterministic mode is reproducible, and the RL trainer matches the generator. A config field can opt into cuDNN later if a model wants the 2-12%.
- Why not `torch.backends.cuda.enable_cudnn_sdp(False)` next to `activate_flash_attention_impl`? It turns cuDNN off for every SDPA call in the process, not only varlen.

NOTE: with the pin, a causal no_grad forward with head dims (192, 192) or (256, 128) on B200/GB300 fails, as it did on torch 2.14: only cuDNN runs them. No TorchTitan model uses them.

**Test plan**
- New `test_varlen_attn_runs_flash_not_cudnn` (fails on main): `pytest tests/unit_tests/cpu/test_varlen_attention.py`.
- Speed check above on GB300; not run on H100.
