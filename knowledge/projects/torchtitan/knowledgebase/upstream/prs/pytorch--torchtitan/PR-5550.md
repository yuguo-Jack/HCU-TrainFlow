# [Dist-MoE] Choose lower-cost PP activation-slot layouts

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5550) · state: open · merged: False

## Original PR description

## Agent details

Prepared with AI assistance.

Compare exactly two static layouts for eager pipeline execution: the existing
uniform-sized shared slot pool and independently colored stage-depth classes
with heterogeneous capacities. Use the existing PyTorch liveness analysis and
Dist-MoE memory planner; choose lower planned saved bytes and prefer uniform on
a tie. Count actual transformed MoE modules, including prediction modules.

Slot capacity is a limit, not owner depth. Pass the actual stage-owner depth
during selection, preserving aggregate local depth for whole-microbatch owners.
Keep one context and shared scratch, immutable assignments, full/weight-backward
release, existing scalar byte/factor controls and scalar reports for uniform
configurations. No allocator, model kwargs, compute kernel or per-step collective
is added. This is not a global memory or throughput optimizer.

Requires a Dist-MoE provider accepting per-slot depth tuples and reporting tuple
MemoryPlan capacities. Missing support fails rather than silently dropping the
feature. GraphTrainer retains uniform layout until its own capture path wires
static owner depth; that integration remains downstream work.
