# [moe][perf] Sort expert ids as int16 in _local_reorder

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5164) · state: open · merged: False

## Original PR description

**TLDR:** `_local_reorder` sorts expert ids as int16 when `num_experts` fits: 2 radix passes instead of 8, same permutation.

**Problem**
1. **Sort today.** `_local_reorder` sorts top-k expert ids as int64.
2. **Radix sort.** CUDA's radix sort runs one pass per 8 key bits: 8 passes for int64.
3. **Cost.** Sort 72.9 us at 4k x 8 ids.

**Solution**
1. **int16 keys** when `num_experts` fits: 2 passes.
2. **Unchanged.** The stable permutation is identical; the guard is on a Python int, so no new graphs.

**Results**
```text
sort, 4k x 8 ids: 72.9 -> 30.4 us   (~40 us per MoE layer; measured on an earlier tree)
DSv3 671B layers 2-3, flex attention, fwd+bwd wall, 1x GB300 (shared), median [range] of 3 fresh processes, no AC
16k   159.76 [159.67-159.78] -> 159.74 [159.39-160.19] ms   (within noise)
correctness: bitwise
```

NOTE:
- Below the 1% bar; kept because it is 4 lines and bitwise.
- Reaches Local, AllToAll and TorchAO dispatchers of every MoE model, eager and compiled.
- Not tested: H100; backward recompute under AC.

**Test plan**
`pytest tests/unit_tests/cpu/test_token_dispatcher_compile.py -k test_local_reorder_matches_int64_expert_sort` (896 experts: ids need > 8 bits)
