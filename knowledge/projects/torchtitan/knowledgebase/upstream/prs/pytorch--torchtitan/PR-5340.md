# Fix Dist-MoE weights when loading from HF

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5340) · state: closed · merged: True

## Original PR description

**Problem:**
- Loading an HF checkpoint into a model with Dist-MoE experts leaves every expert's w13 at random init
- The model then produces garbage (e.g. reward 0 rollouts in RL)
- w13 fusing/splitting is handled correctly for `RoutedExperts` but not for `DistMoeRoutedExperts`
- Similar problem exists when exporting to HF
- Affects any workload that loads from an HF checkpoint instead of relying on random weight initialization, e.g. RL

**Fix:**
- Also traverse `DistMoeRoutedExperts.Config` in both directions. It keeps the same w13/w2 layout, so the conversion is unchanged

**Testing:** Qwen3-30B-A3B on alphabet sort from the HF checkpoint, bf16 Dist-MoE on trainer and generator (8 B200s):
- Before: garbage rollouts, reward 0, trainer entropy ~3.0
- After: reward 0.38-0.62 and entropy ~0.01, matching the stock MoE baseline (reward 0.44-0.64)

Unit-level check (Qwen3 `debugmodel_moe` + `DistMoeTransform`): before, `to_hf` has 0 expert gate/up keys and a strict reload fails with missing `routed_experts.w13.weight`; after, 512/512 keys and the round trip loads cleanly.
