# [docs] Fix README commands that do not resolve

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5311) · state: closed · merged: True

## Original PR description

## Summary

Five README commands name a flag, a file, or a recipe that does not exist. They are in one PR so CI runs once. No README string-guard test is added.

- RL quick start. `ConfigLoader` accepts `--module`, `--config`, `--override`, `--comm-backend`, `--output-dir`, `--resume-step`, and `--print-config`. `--dump-folder` makes argparse exit 2. `--output-dir` sets the output directory, which is what `torchtitan/rl/examples/dapo_math/README.md` already does. The CLI does not override arbitrary registry fields. `--override` applies registered overrides only.
- Terminal-Bench. `--hf_assets_path` is not a CLI flag. `rl_grpo_qwen35_9b_terminal_bench` sets `hf_assets_path` to `./assets/hf/Qwen3.5-9B`, and `rl_grpo_qwen35_35b_a3b_terminal_bench` sets `./assets/hf/Qwen3.5-35B-A3B`, both in `torchtitan_recipes/rl/verifiers_terminal_bench.py`. A different directory is that assignment, not a flag.
- Flux. `requirements-flux.txt` is not at the repo root. The file is `.ci/docker/requirements-flux.txt`, which is also the `flux` extra in `pyproject.toml`. The Qwen3.5 and Kimi K3 READMEs already install from `.ci/docker/`.
- Qwen3. The tokenizer download command was a one-line fence, so the rest of the README was inside the code block. The command itself is unchanged.
- Llama 3 MXFP8. `graph_trainer_llama3_8b_mxfp8` is not defined. Eager MXFP8 is `llama3_8b_mxfp8` in `torchtitan_recipes.tests.models.llama3`. The GraphTrainer recipe is `graph_trainer_llama3_debugmodel_mxfp8` in `torchtitan_recipes.tests.graph_trainer.llama3`.

## Test plan

- [ ] Docs only. No unit test. The flags, requirements path, and recipe names above exist on this branch.
