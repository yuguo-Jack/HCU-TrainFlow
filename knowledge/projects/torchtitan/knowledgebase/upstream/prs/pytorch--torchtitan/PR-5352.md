# [DistMuon] Newton-Schulz can be staged on device of choice

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5352) · state: open · merged: False

## Original PR description

### Why
With FSDP2 CPU offload, DistMuon runs Newton-Schulz on the host, which makes the optimizer step slow. Newton-Schulz is the only heavy compute in the step, so we can copy each compute view to the GPU, run it there, and copy the result back.

In my test, with cpu offloading, allowed the optimizer step to get to ~1s from ~15s per step.

### What
- New `DistMuon(ns_device=None | "cuda" | "cpu")`, also exposed on `DistMuon.Config`. `None` (the default) keeps the current behavior. Otherwise the compute view is copied to `ns_device` for Newton-Schulz and the result copied back. Momentum, parameters and redistribution buffers stay where they are.
- Empty compute views now return early.

### Testing
New test `TestDistMuonCpuOffload`. It checks that:
- Newton-Schulz runs on the CPU with `ns_device=None` and on the rank's GPU with `"cuda"`;
- parameters and optimizer state stay on the host;
- Cuda NS is swapped to an fp32 version so that the absolute tolerance can be tight;
- the results match the host-only run (`atol=1e-5`).

Before this lands:

1. **Rebase onto main.** #5279 landed after this branched, and DistMuon now requires a BF16 compute dtype, so the new test fails on main (details inline).
2. **Lint.** ufmt reformats `_resolve_ns_device`; please run `pre-commit run --all-files`.
3. **`ns_device` values.** Keeping this a DistMuon option next to `ns_steps` and `ns_coefficients` makes sense, but its values hardcode CUDA, `"cpu"` has no use, and the config field needs a docstring saying that only Newton-Schulz moves (inline).

## Inline 1

`torchtitan/distributed/flex_shard/dist_muon.py:188`

```python
        ns_device: Literal["cuda", "cpu"] | None = None,
```

Comment:

Having this on DistMuon next to `ns_steps` and `ns_coefficients` makes sense, and keeping it out of the param group is right: it's a placement choice, not a hyperparameter. The values could be better, though:

- `"cuda"` ties recipes to CUDA (`_resolve_ns_device` uses `torch.cuda.*`).
- `"cpu"` has no use: with offload the default already runs on the host, and without offload it only adds two blocking copies per matrix.

How about:

```python
ns_device: Literal["accelerator"] | None = None
```

`None` keeps the storage device, the same way `None` for `ComputeLayout.compute_dtype` keeps the storage dtype. `"accelerator"` works on any accelerator type and is resolved once at construction:

```python
if ns_device == "accelerator":
    accelerator = torch.accelerator.current_accelerator()
    if accelerator is None:
        raise ValueError("ns_device='accelerator' requires an accelerator")
    self._ns_device = torch.device(
        accelerator.type, torch.accelerator.current_device_index()
    )
```

The torchtitan config can then pass the value straight through. Please also warn when `"accelerator"` is set but the parameters already live on the accelerator, since it does nothing then, and update the class docstring. I tried this on main: the FlexShard tests pass, including the real-FSDP2 test suggested below.

class _TwoLayerModel(nn.Module):
    def __init__(self) -> None:
        super().__init__()
        self.layers = nn.ModuleList(
            (nn.Linear(16, 8, bias=False), nn.Linear(8, 16, bias=False))
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.layers[1](torch.relu(self.layers[0](x)))


@unittest.skipUnless(torch.cuda.device_count() >= 2, "requires two CUDA devices")
class TestDistMuonCpuOffload(DTensorTestBase):
    """FSDP2 CPU offload with Newton-Schulz staged onto the GPU."""

    @property
    def world_size(self):
        return 2

    @property
    def device_type(self):
        return "cuda"

    @property
    def backend(self):
        return "cpu:gloo,cuda:nccl"

    @with_comms
    def test_cuda_ns_device_matches_gpu_resident_run(self):
        mesh = init_device_mesh(
            self.device_type, (self.world_size,), mesh_dim_names=("dp_shard",)
        )
        compute_sharding_by_fqn = {
            # Redistributed to one owner rank.
            "layers.0.weight": ComputeLayout(
                shardings_by_mesh_axis={"dp_shard": Owned()},
                compute_dtype=torch.bfloat16,
            ),
            # Compute-ready: each rank's Shard(0) rows are two complete blocks.
            "layers.1.weight": ComputeLayout(
                shardings_by_mesh_axis={
                    "dp_shard": BlockShard(dim=0, block_sizes=(4,))
                },
                compute_dtype=torch.bfloat16,
            ),
        }
        inputs = torch.randn(
            4, 16, generator=torch.Generator().manual_seed(self.rank)
        ).to(self.device_type)

        def run(*, offload: bool, ns_device: str | None):
            torch.manual_seed(0)
            model = _TwoLayerModel()
            policy = CPUOffloadPolicy() if offload else OffloadPolicy()
            for module in (*model.layers, model):
                fully_shard(module, mesh=mesh, offload_policy=policy)
            names, params = zip(*model.named_parameters())
            optimizer = DistMuon(
                [{"params": list(params), "param_names": list(names)}],
                compute_sharding_by_fqn=compute_sharding_by_fqn,
                bucket_configs=[BucketConfig(patterns=("layers.*",))],
                lr=0.03,
                weight_decay=0.2,
                momentum=0.8,
                ns_steps=2,
                ns_device=ns_device,
            )
            ns_devices: list[torch.device] = []
            original = dist_muon_module._compute_muon_direction

            def record_device(prepared, **kwargs):
                ns_devices.append(prepared.device)
                return original(prepared, **kwargs)

            with mock.patch.object(
                dist_muon_module, "_compute_muon_direction", record_device
            ):
                for _ in range(2):
                    model(inputs).square().sum().backward()
                    optimizer.step()
                    optimizer.zero_grad()
            return params, optimizer, ns_devices

        gpu_params, _, gpu_ns_devices = run(offload=False, ns_device=None)
        host_params, host_optimizer, host_ns_devices = run(
            offload=True, ns_device="accelerator"
        )

        with self.assertWarnsRegex(UserWarning, "has no effect"):
            run(offload=False, ns_device="accelerator")

        rank_device = torch.device(self.device_type, self.rank)
        self.assertTrue(host_ns_devices)
        self.assertTrue(all(d == rank_device for d in host_ns_devices))
        self.assertEqual(host_ns_devices, gpu_ns_devices)
        # Parameters and momentum stay on the host.
        for param in host_params:
            self.assertEqual(param.to_local().device.type, "cpu")
        for state in host_optimizer.state.values():
            self.assertEqual(state["momentum_buffer"].to_local().device.type, "cpu")
        # Both runs use the same GPU kernels, so the offloaded update matches
        # the GPU-resident one exactly. These matrices are too small for host
        # Newton-Schulz to differ, so the device check above is what pins it.
        for host_param, gpu_param in zip(host_params, gpu_params, strict=True):
            torch.testing.assert_close(
                host_param.to_local(), gpu_param.to_local().cpu(), rtol=0, atol=0
            )

Thanks for the thorough review! Here are the updates:

- **Merged `main`.**
- **Renamed `ns_device` to `ns_on_accelerator: bool = False`.** With `"cpu"` removed, the only remaining choices were to keep Newton–Schulz on the storage device or run it on the current accelerator. A boolean expresses this more directly than `Literal["accelerator"] | None`. Device resolution still goes through `torch.accelerator`, so the implementation is not CUDA-specific. It raises a `ValueError` if no accelerator is available.
- **Updated docstrings.** Both `Config.ns_on_accelerator` and the class docstring now explicitly state that only the Newton–Schulz computation moves to the accelerator.
- **Updated the test** to use a real FSDP2 `CPUOffloadPolicy`.

### Numerics

I ran a comparison using the Llama 3 debug model, DistMuon on all layer matrices, FSDP4 across 4×A100 GPUs, and seed 42. Both runs started from the same seed checkpoint. The only difference was whether parameters remained GPU-resident or were CPU-offloaded with `ns_on_accelerator=True`.
