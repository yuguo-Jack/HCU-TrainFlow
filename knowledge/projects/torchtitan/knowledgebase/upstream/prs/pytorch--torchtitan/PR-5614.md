# [release/0.4][CI] Stage test assets for GPU validation

[Upstream PR](https://github.com/pytorch/torchtitan/pull/5614) · state: closed · merged: True

## Original PR description

## Summary

Link the installed test-recipe asset path to the source-test assets staged by GPU release validation.

## Why

The Muse Spark integration recipe is imported from the RC wheel and resolves its synthetic multimodal data below `site-packages/tests/assets`. GPU validation stages that data under its temporary source-test tree but does not connect the installed lookup path to it, so the test fails with `FileNotFoundError` before training starts.

This applies the same asset mapping already used by CPU release validation in #5606. It changes only the validation harness; loss goldens and model code are unchanged. The same setup is needed by the release GPU validation script on main.

Failure: https://github.com/pytorch/torchtitan/actions/runs/40066514161/job/120790868714
