# [Feature][Sampling] Compact target-token-scoring fast path (V1 runner)

[Upstream PR](https://github.com/vllm-project/vllm/pull/56782) · state: open · merged: False

## Original PR description

Releated issue: #56767 
Rerankers and relevance scorers finish prefill and only need the sore for a small fixed set of K candidate tokens(often K=2, yes/no),but the runner still projects the last hidden state through the full-vocab LM Head([B,H] @ [V, H]^T ->[B,V], V≈151k for Qwen2.5) before the sampler gathers the K columns. logprob_token_ids(#43463 ) and generative_scoring are output-side shortcuts -neither avoids that MatMul, which dominates single-step scoring latency.

This adds an eligible-wave fast path: index_select the K candidate weight rows([K,H]) and compute only the compact[B,K] projection, then argmax + remap(column j ->target_token_ids[j]) + target-set log-softmax straight into a SamplerOutput.
ineligible waves fall back to native, unchanged. Two-level opt-in:engine flag --target-token-scoring plus per-request target_token_scoring_normalization="target_set" (default "full_vocab" = existing behavior; logprob_token_ids alone never triggers the compact path, so the flag can't silently change existing logprobs semantics).Dense single-rank unquantized LM Head only;TP-sharded /quantized/spec-decode/structured output fall back to native rather than risk wrong semantics.

Builds on #43463; distinct from #39351 (fuses gather but keeps the full-vocab LM Head — complementary, could stack) and #54335 (distillation, bit-identical full-vocab, targets mrv2).

**Changes:**

- vllm/v1/worker/target_token_scoring/ — new package: admission.py (wave-level gate), projector.py (compact LM Head + CompactLMHeadCache keyed on weight signature incl. _version), compact_sampler.py (argmax+remap+target-set log-softmax for the V1 SamplerOutput), state.py (carrier).
- vllm/v1/worker/gpu_model_runner.py — one guarded branch in execute_model (before compute_logits) and one in sample_tokens (before _sample); ExecuteModelState gains a target_token_scoring field; the cache is a runner attribute.
- vllm/config/model.py, vllm/engine/arg_utils.py — --target-token-scoring flag (mirrors return_sampling_mask).
- vllm/sampling_params.py — target_token_scoring_normalization field.
- tests/v1/worker/test_target_token_scoring.py; examples/target_token_scoring/ (Qwen2.5 reranker equivalence demo, NPU projector benchmark).

The compact [B,K] tensor's column j is target_token_ids[j], not vocab id j;the generic sampler is bypassed precisely so it cannot confuse the two.Correctness invariant: compact[:, j] == full[:, target_token_ids[j]].

**results:**
CPU suite(pytest tests/v1/worker/test_target_token_scoring.py):20 passed.Demo(qwen2_5_reranker_demo.py):OK
Ascend 910B4 device projector (no runner, synchronized median, BF16) vs full-vocab [B,V] projection:
```
batch	K	speedup
16	2	6.04x
16	8	6.34x
64	2	7.24x
64	8	7.00x
```
Candidate columns match exactly (max_abs=0); only irrelevant columns are dropped.
