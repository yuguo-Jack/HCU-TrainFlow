# [Bugfix][KV Offload][P2P] Mark the session dead when its ConnectAck send fails

[Upstream PR](https://github.com/vllm-project/vllm/pull/63664) · state: closed · merged: True

## Original PR description



## Overview

`P2PSession._poll_registration` clears the pending registration before sending `ConnectAckMsg`. If that send raises, the exception escapes `poll()` and the local session remains alive. Route the ack through `_do_send` so a send exception marks the local connection dead and allows the manager to reap its pending work.

Part of #63602 (gap 5).

## Claims

- A raised `ConnectAckMsg` send error marks the local connection dead instead of escaping `poll()`.
- The manager can reap that session and fail its pending local work without waiting for the request deadline, provided polling and cleanup can progress.
- The ack still bypasses the pre-ack queue. Successful sends also refresh the session's activity timestamp.
- This does not guarantee immediate remote notification or bound a blocking transport send.

## Validation

New test `TestConnectHandshake::test_failed_ack_send_marks_connection_dead` (`tests/v1/kv_offload/tiering/p2p/test_sessions.py`): a peer's registration completes, the ack send raises, and the connection must be dead after `poll()`. The existing `test_sessions.py::TestDisconnect::test_send_failure_marks_connection_dead` covers send-error handling. The existing `test_manager.py::TestConnectionDeathMidTransfer::test_dead_connection_with_pending_work_surfaces_failures` covers failure of a dead session's pending load, and separately asserts that an unbound store stays parked for its own timeout. Neither is an end-to-end failed-ack-send test.

Run on CPU in `vllm/vllm-openai@sha256:cb9bc64f0f038c2c2ebf13b31248fb87aca40c356c3d20f363be087cfcff1fcd` with this tree mounted (`uv venv --system-site-packages`, then `pytest --confcutdir=tests/v1/kv_offload/tiering/p2p`):

`test_lookup_expiry_allows_zmq_reconnect` also fails on the unmodified base. Run alone, alternating between the base and this change in one CPU container, it failed 16 of 20 times on each, always in the `poll_until(both_ready)` after the reconnect (`test_manager.py:1341`); no difference was observed in this sample. The failing full-suite run with this change contains no `send of connect_ack failed` warning, so the ack-send exception handler was not observed; successful acks still go through the changed direct-send path. Its cause is unresolved.

Integration check on GPUs of this change together with a rollback patch for gap 4 (not part of this PR; gap 4 is handled in #63628), #63207 and #63498, on nightly `8e2beaa3b`: three single-GPU Qwen3-0.6B engines on one H200 node, mlx5 InfiniBand, NIXL 1.5.0, 1 run per case. A probe seeds a fresh ~2K-token prefix on a source every 200 ms and asks consumer A to pull it. A probe counts as pulled when A submitted the P2P load and the source logged `finalize ... success=True ... send_done=True` for it. Times run from SIGCONT, or from the switch to the replacement pod, to the HTTP request start and finish of the first such probe:

| fault on source B | probes to B or its replacement pulled after recovery | first verified pull after recovery, request start / finish | probes to healthy source C pulled |
|---|---|---|---|
| none | 700/700 | - | 625/625 |
| SIGSTOP 60 s, then SIGCONT | 242/242 (from SIGCONT + 40 s) | 8.7 s / 10.1 s | 616/616 |
| pod force-deleted, replacement | 400/400 (from switch + 10 s) | 0.5 s / 0.8 s | 848/848 |
| pod deleted gracefully, replacement | 400/400 (from switch + 10 s) | 0.3 s / 0.5 s | 839/839 |

Every successful handshake in these runs sent its ack through `_do_send`. The runs do not establish that the ack-send exception handler was exercised; they check that the combined stack does not regress.

No `LLM`/`RemoteOpenAIServer` fault-injection regression is included. The fault is injected at the external transport boundary in the focused tests above. We have not implemented an entry-point fixture for this failure; asking maintainers to accept this test scope.

## Details

`_do_send` is the existing guarded direct-send path. It bypasses the pre-ack queue and marks the local connection dead when a send raises. Other raw-send paths are outside this change.
