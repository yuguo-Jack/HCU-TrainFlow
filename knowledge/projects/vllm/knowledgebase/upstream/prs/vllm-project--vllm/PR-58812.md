# [Model] Add Laya decision pooling

[Upstream PR](https://github.com/vllm-project/vllm/pull/58812) · state: open · merged: False

## Original PR description

## Overview

Support Laya as a pooling model using its ModernBERT encoder and checkpoint decision/action heads.

## Claims

- Keep model definition and registration in vLLM. Preserve checkpoint marker layout, option-count temperatures and FP32 decision-head computation.
- Document the checkpoint serving view and `/classify` output.

## Validation

Six real-checkpoint short/long text cases (choice, predicate and score) were compared against the original CPU FP32 RLAgent. Maximum absolute probability error was 0.0040288568 in Eager and 0.0052211881 in PIECEWISE; both satisfy the predeclared 0.02 bound.

The companion generic Ascend encoder window implementation is required for these NPU results. Local documentation pre-commit checks passed. `tests/models/test_laya.py` covers model-head behavior; the six real-model runs are external device evidence, not an upstream CI result.

Device validation used Ascend 910B4-1, BF16, TP1, the `quay.nju.edu.cn/ascend/vllm-ascend:v0.30.0rc2` base image (digest `sha256:6348403a0ebb19f52bc1b7497de1daeb6df0e4650f9051c169e47a011527a6c3`), and source overlays: [vLLM](https://github.com/Liuchenbing-2026/vllm/commit/d74c7f54aefa0f4be5fafb2362950290886328b5) and [vLLM-Ascend](https://github.com/Liuchenbing-2026/vllm-ascend/commit/cdca8d2c6fec142fbd336ca28a4e9f87f68ca2d8). Torch 2.10.0, torch_npu 2.10.0.post7, CANN 9.2.0 and Transformers 5.19.0 were used. These results are from the combined fixed-source stack, not the unmodified rc2 image or upstream CI.

AI assistance was used; human review remains required.

## Details

Laya is a checkpoint-specific `/classify` model, not an autoregressive model or a newly added System One strategy. The runtime preparation does not modify weights. This updates the existing Laya implementation and is not a duplicate hardware-side model. No leaderboard, multimodal or FULL-graph claim is made.
