# [Bugfix][Multimodal] Fix tensor conversion in audio parsing and hashing

[Upstream PR](https://github.com/vllm-project/vllm/pull/65579) · state: closed · merged: True

## Original PR description

## Overview

Fix tensor-to-NumPy conversion in audio input parsing and shared multimodal hashing.

Following @DarkLight1337's suggestion, I checked the other explicit conversion paths and confirmed the same gradient-related failure in multimodal hashing.

## Claims

- Handle CUDA and gradient-tracking audio tensors by detaching and moving them to CPU before NumPy conversion.
- Detach tensors before hashing, covering image/video tensors and precomputed audio embeddings.
- Add regression coverage and document direct audio Tensor inputs.

## Validation

Before the fixes, the audio model test and the three CPU hashing cases failed with:

```text
RuntimeError: Can't call numpy() on Tensor that requires grad.
```

After the fixes:

| Environment | Validation | Result |
| --- | --- | --- |
| macOS, CPU | Full parser and hasher suites | 57 passed, 4 skipped |
| DGX Spark, CPU/CUDA | New hashing regression for image, video, and audio embeddings | 6 passed |
| DGX Spark | Full parser suite | 34 passed |
| DGX Spark | Whisper Tiny `LLM.generate()` regression | 1 passed |

The hashing tests verify exact hash equality with detached reference tensors.

The Whisper test uses real weights and the `mary_had_lamb` audio sample. It compares gradient-tracking CPU tensors, CUDA tensors, and gradient-tracking CUDA tensors with a NumPy reference using `check_logprobs_close`.

Image/video and embedding coverage exercises parsing and hashing; the real-model test covers raw audio.

## Details

Audio parsing previously called `.numpy()` directly, which fails for CUDA tensors and tensors requiring gradients.

The shared multimodal hasher already moved tensors to CPU, but did not detach them before calling `.numpy()`. Adding `detach()` fixes gradient-tracking inputs while preserving the hashes produced for their detached equivalents.

The DGX validation used this branch's Python source with installed vLLM 0.31.0 native extensions. Startup reported missing Triton kernels and unavailable FlashInfer sampling, but Whisper inference completed. These tests validate input compatibility, not model accuracy.

The earlier search of open PRs found no matching audio conversion fix.
