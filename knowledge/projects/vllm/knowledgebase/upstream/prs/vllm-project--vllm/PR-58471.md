# [Bugfix][KV Connector][NIXL] Shard a GQA draft's KV by head under an MLA target

## Update (2026-10-13)

Adopted @NickLucche's simplification from #60368 (thanks!): the source files now match that branch exactly, carried as a commit authored by him (his three commits squashed, his sign-off kept), followed by one commit of mine adapting the tests. Relative to the earlier revision:
- draft-region identity is computed once at `register_kv_caches` into `_head_sharded_draft_regions` (via `_layer_specs`), replacing the per-region head-count list and the three per-call helpers;
- the push-mode guard lives in `NixlPushConnectorWorker` and rejects only heterogeneous TP, so equal-TP push works; the base class keeps the `tp_ratio < 0` / DCP rejection;
- `tp_mapping.compute_head_offset` carries the rank-offset arithmetic for both the target and the draft mapping.
Tests were adapted to the new structure (see Test Plan); the end-to-end results below predate this revision and were obtained with the earlier implementation of the same behaviour.

## Purpose

Fixes #58470.

NIXL P/D mis-handles a draft model's KV when **all three** hold:

1. **The target is MLA** (e.g. GLM-5.3), so NIXL maps every KV region as replicated: `total_num_kv_heads=1`, `rank_offset_factor=0`.
2. **The draft is not MLA** (e.g. DFlash2, 8 KV heads), so its KV is actually split by head across TP.
3. **Prefill TP ≠ decode TP** (e.g. a DEP8 prefill with attention TP1 feeding a TP8 decoder), so each decode rank needs a different head slice.

Drop any one and it works: an MLA draft (MTP), or equal P/D TP. `_is_region_replicated` already marks the draft regions SPLIT, but three places still use the model-wide MLA answer:

| where | `main` | this PR |
|---|---|---|
| handshake size check (`model_replicated = self.use_mla or …`) | rejects the correct geometry, accepts an unscaled draft block | checks draft regions as SPLIT |
| read offset (`_build_fa_remote`) | every decode rank reads draft head 0 | rank *r* reads head *r* |
| hetero-TP layout guard | skipped when `use_mla` | requires the same block-contiguous layout on P and D |

**Fix.** When the target is MLA and the draft isn't, build a second `TPMapping` from the draft's KV head count (`compute_tp_mapping(..., head_sharded_kv_heads=...)`). The draft's SPLIT regions use it for reads, size checks and the layout guard; MLA regions are unchanged. Prefill TP > decode TP and DCP are rejected with `NotImplementedError` for such drafts. Mamba, CSA-linear and MLA drafts behave as before.

**Not a duplicate.** No open PR touches this. Related:
- #49230 (merged): checks that P and D speculative configs match; they do here.
- #54926: Gemma 4 MTP draft groups are not transferred at all.
- #57309: moves helpers out of `tp_mapping.py`; a refactor only.
