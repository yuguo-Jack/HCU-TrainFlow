# [Test][KV Offload] Update stale partial-tail scheduler expectations

[Upstream PR](https://github.com/vllm-project/vllm/pull/64993) · state: closed · merged: True

## Original PR description



## Overview

Three tests fail on `main`: `test_partial_tail_store_uses_attention_and_recurrent_cow_sources` and both `test_eagle_partial_tail_round_trip_serves_mamba_checkpoint` cases. After #62613 made Mamba events report the checkpoint block size and predecessor hash, the first test still expected placeholder values. After #63249 changed load-job keys to an ordered tuple, the EAGLE tests still compared that tuple with a set. This PR updates those stale expectations.

## Claims

- Assert the Mamba checkpoint event's block size and parent hash as emitted by the event tracker.
- Check loaded offload keys in prefix order, matching the scheduler's tuple contract.

On latest `main` (`5d55ef1590`), the focused run reports `3 failed, 464 deselected`; with these expectation updates it reports `3 passed, 464 deselected`. Ruff, formatting, and `git diff --check` pass.

## Details

The Mamba event tracker emits the checkpoint block size (`4`) and links the checkpoint hash to its predecessor; the scheduler test still expected the older placeholder values. A separate EAGLE round-trip assertion compared the load job's ordered key tuple with a set, although the scheduler preserves prefix order. This PR changes test assertions only; it does not change CI configuration or test markers.

Duplicate-work check: open PR searches found no change for these stale scheduler assertions. Open PR #63550 adds KV event layout coverage in `tests/v1/core/test_kv_cache_events_layouts.py`; it does not modify or cover these offloading scheduler expectations. Open PR #59177 addresses a separate flaky XPU event test.
