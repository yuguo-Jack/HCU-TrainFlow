# [Bugfix] Honor child engine IDs in MultiConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/63353) · state: open · merged: False

## Original PR description

## Overview

Fix MultiConnector initialization when a child connector explicitly sets `engine_id`.

## Claims

- Honor explicit child engine IDs and inherit the parent ID when omitted.
- Preserve the original child configuration dictionaries.

## Validation

- **31 passed, 2 deselected** for the unit-test selection below.
- **1 passed, 32 deselected** for `test_multi_example_connector_consistency`, using the local `DeepSeek-R1-Distill-Qwen-1.5B` checkpoint instead of the gated Llama checkpoint. All test assertions were retained, including matching saved KV contents, first-connector cache reuse, and second-connector fallback after deleting the first store.
- All applicable pre-commit hooks passed for all three changed files.

Before the fix, both the new unit regression and the same local-model integration scenario failed with:

```text
TypeError: vllm.config.kv_transfer.KVTransferConfig() got multiple values for keyword argument 'engine_id'
```

Unit-test command:

```bash
HF_HUB_OFFLINE=1 uv run --no-sync .venv/bin/python -m pytest \
  tests/v1/kv_connector/unit/test_multi_connector.py -q \
  -k "not multi_example_connector_consistency and not mixed_hma_disables_hybrid_kv_cache"
```

The integration test was run on one H800 in eager mode with `VLLM_WORKER_MULTIPROC_METHOD=spawn`. A local pytest collection plugin changed only the test module's `MODEL_NAME` to the local checkpoint. The original gated-model configuration and the mixed-HMA test were not run.

The new regression is marked `cpu_test` so the existing CPU Buildkite lane selects it. Local `-m cpu_test` selection passed (1 passed, 32 deselected). The upstream GPU KV Connector step is currently disabled; upstream CI results for the new head are pending.

## Details

Passing `engine_id` explicitly alongside `**ktc` caused a duplicate-keyword error when the child configuration already contained that key.

Merge the parent default with the child configuration so an explicitly configured child `engine_id` takes precedence, while preserving the original configuration dictionary.
