# [Bugfix][V2 runner] Keep idle-DP dummy requests within max_model_len

[Upstream PR](https://github.com/vllm-project/vllm/pull/64923) · state: open · merged: False

## Original PR description

## Overview

In the V2 model runner, an idle data-parallel rank runs one dummy request padded to the busiest rank's token count. That count can exceed `max_model_len`, but the dummy request's block table only covers `max_model_len` tokens, so its prefill reads past the block table. In #62365 this hung the idle rank of a DeepSeek-V4.1 DP run while its peers timed out in the MegaMoE barrier.

`InputBatch.make_dummy` now splits the dummy batch into `cdiv(num_tokens, max_model_len)` requests when the caller passes `max_model_len`, and the model runner passes it. Nothing changes when `num_tokens <= max_model_len` or when the caller does not pass `max_model_len`.

Split from #62365 by @aoshen02.

## Changes

- `vllm/v1/worker/gpu/input_batch.py`: `make_dummy(..., max_model_len=None)`; when set, `num_reqs = max(num_reqs, cdiv(num_tokens, max_model_len))`. The existing remainder split keeps every request at most `ceil(num_tokens / num_reqs)` tokens.
- `vllm/v1/worker/gpu/model_runner.py`: the dummy-run branch of `execute_model` passes `max_model_len=self.max_model_len`.
- `tests/v1/worker/test_gpu_input_batch_v2.py`: `test_make_dummy_dp_padding_respects_max_model_len` with `max_model_len=1536` and 1536, 1537, 2046 and 8190 tokens. At base the test cannot pass `max_model_len`, so it fails with a `TypeError`.
