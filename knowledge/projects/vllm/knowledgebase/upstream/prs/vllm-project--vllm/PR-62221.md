# [CI][Release] Fix release wheel builds: stop excluding tracked recipes/ from Docker context

[Upstream PR](https://github.com/vllm-project/vllm/pull/62221) · state: closed · merged: True

## Original PR description

## Purpose

Fix the release pipeline, broken since #61302 ([release-v2 #8603](https://buildkite.com/vllm/release-v2/builds/8603)). The CUDA x86_64/aarch64 and ROCm wheel builds fail, which breaks every downstream image and publish step:

```
#58 0.576 Repo is dirty
ERROR: failed to solve: process "/bin/sh -c if [ \"$GIT_REPO_CHECK\" != \"0\" ]; then bash tools/check_repo.sh ; fi" did not complete successfully: exit code: 1
```

**Root cause:** #61302 added `/recipes` to `.dockerignore`. Those 188 files are tracked, and `.git` is bind-mounted into the build, so git sees them as deleted. Two things then break:
- `tools/check_repo.sh` (`git diff --quiet`) fails release builds, which set `GIT_REPO_CHECK=1`.
- setuptools-scm stamps the wheel `...+g<sha>.dYYYYMMDD`, while the Rust frontend build pins `dirty=false`. This fails `test_show_version` in the H200 Rust Frontend OpenAI/Serve-Admin Coverage steps on main.

**Fix:** drop `/recipes` from `.dockerignore`. It's about 1.5 MB of YAML in the build context and isn't installed into the image. A new test, `test_dockerignore_keeps_tracked_root_paths`, fails if a root-anchored `.dockerignore` entry ever excludes tracked files again.

**Not a duplicate:** no open PR touches `.dockerignore`. This supersedes #62214, which only masked the version symptom and would not fix `check_repo.sh`.

## Test Plan

- I extracted the new test's logic and ran it standalone (the repo conftest needs a full env): 188 tracked files excluded on `origin/main`, 0 on this branch.
- Release and Docker builds were not run locally; the release pipeline will confirm.
