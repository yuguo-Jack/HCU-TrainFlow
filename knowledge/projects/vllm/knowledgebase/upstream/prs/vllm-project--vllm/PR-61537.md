# [Bugfix][Spec Decode] Keep DFlash full-attention layers bidirectional for speculators checkpoints

[Upstream PR](https://github.com/vllm-project/vllm/pull/61537) · state: open · merged: False

## Original PR description



## Overview

This fixes speculators-format DFlash/DFlash2 checkpoints that have full-attention layers being served with causal full attention. Fixes vllm-project/speculators#1232. It follows up #47745, which is unchanged for all-sliding checkpoints.

## Claims

- Full-attention draft layers in speculators checkpoints are served bidirectionally, the way Speculators trains them, whatever `sliding_window_non_causal` is set to.
- `z-lab/Qwen3-8B-DFlash-b16` converted with `speculators convert`: mean acceptance length goes from 3.087 to 3.759 (+22%), with per-request metrics identical to the original head on 32/32 requests.
- No change for all-sliding checkpoints (e.g. the RedHatAI DFlash checkpoints, #47745) or for checkpoints without the flag.

## Validation

**Unit:** `pytest tests/transformers_utils/test_speculators_dflash_config.py tests/transformers_utils/test_speculators_dspark_config.py`. The new test resolves served per-layer causality through `SpeculatorsConfig.extract_transformers_pre_trained_config` and `_dflash_layer_causal`. It has 6 cases; on `main`, the 3 cases that have full-attention layers and `sliding_window_non_causal: false` fail (all-full `dflash`, mixed `dflash`, mixed `dflash2`). With the 3 existing DSpark config tests, 9/9 pass on this branch.

**End to end** on 1×H100 (vLLM `624a5ddafd` with precompiled kernels, without and with this patch; its causality and config code is identical to this PR's base; transformers 5.17.0, torch 2.13.0+cu130; converted heads from speculators `e83f9d0`), `Qwen/Qwen3-8B`, `--speculative-config '{"method": "dflash", "model": <draft>, "num_speculative_tokens": 15}' --per-request-spec-decode-metrics detailed --enforce-eager`. Each run is 32 prompts sent one at a time, greedy, `max_tokens=256`. Output text is identical across runs; only acceptance changes.

| draft | vLLM | accepted / drafted | mean acceptance length |
|---|---|---|---|
| `z-lab/Qwen3-8B-DFlash-b16`, original | main | 4889 / 26580 | 3.759 |
| same, converted with `speculators convert --algorithm dflash` (all full, flag `false`) | main | 4508 / 32400 | 3.087 |

## Details

**Root cause.** `update_dflash` sets `dflash_config["causal"] = not sliding_window_non_causal`, and `_dflash_layer_causal` applies an explicit `dflash_config.causal` to every draft layer. In Speculators, that flag only controls sliding-window layers; full-attention layers are always trained bidirectionally (`speculators/models/dflash/attention.py`). The flag's meaning is fixed by how existing checkpoints were trained, and those checkpoints can't be re-trained, so the loader has to match it.

**Fix.** Set `causal=False` only when the flag is true, and otherwise leave it unset. `_dflash_layer_causal` then falls back to "sliding layers causal, full layers bidirectional", which is exactly what Speculators trains:

| layers | `sliding_window_non_causal` | trained | served before | served after |
|---|---|---|---|---|
| all sliding | `false` | causal | causal | causal |
| all sliding | `true` / absent | bidirectional | bidirectional | bidirectional |
| all full | `false` | bidirectional | **causal** | bidirectional |
| full + sliding | `false` | full bidirectional, sliding causal | **all causal** | full bidirectional, sliding causal |

**Compatibility.**
- Every consumer of this config goes through `_dflash_layer_causal` / `dflash_has_any_non_causal`: the DFlash model, `gemma4_dspark`, the MRV1 proposer and the MRV2 speculator.
- I checked with `get_config` that `layer_types` from the speculators `transformer_layer_config` reaches the hf_config, so the fallback sees the real layer types.
- DSpark's loader never sets `causal`, so it isn't affected.
- Mixed full + sliding drafts still need MRV2, as before.

**Affected checkpoints.** No published RedHatAI DFlash checkpoint is affected; they are all-sliding with the flag `false`. Affected: z-lab heads converted with `speculators convert`. The same applies to drafts trained natively in Speculators with full-attention layers (`--full-attention-indices`, or an all-full draft config), since `sliding_window_non_causal` defaults to `false` for DFlash. A converter-side mitigation for the all-full case is vllm-project/speculators#1233. Converted checkpoints that already carry a copied top-level `is_causal` are unaffected by this change (it takes precedence); that Speculators converter fix stops writing it.

This is separate from my other open spec-decode PR (#58656). cc @mgoin (DFlash/DFlash2 in both repos; happy for both to be reviewed together) @eldarkurtic (#47745).

- ra-srivid · comment · 2026-10-14T18:24:19Z · [source](https://github.com/vllm-project/vllm/pull/61537#issuecomment-6175347251)

Thank you for taking a look! At the time of [#47745](https://github.com/vllm-project/vllm/pull/47745), the per-layer `causal` value wasn't used yet. The proposer applied a single `dflash_config.get("causal", False)` to every layer, so your override was needed for causal-SWA heads.
[#47914](https://github.com/vllm-project/vllm/pull/47914) landed the next day and made per-layer causality (sliding → causal, full → bidirectional) actually reach the mask. But an explicit `dflash_config.causal` still overrides every layer, so with `sliding_window_non_causal=False`, full-attention layers are now served causal too.

This PR only sets the override when the flag says every layer is bidirectional (`causal=False`). Everything else is left to the per-layer fallback. Your all-sliding case still resolves causal; that's the first row in the new test. All 6 cases pass on [66d3646](https://github.com/vllm-project/vllm/commit/66d36462346b785603c8027d0e47fda292f1746c).
