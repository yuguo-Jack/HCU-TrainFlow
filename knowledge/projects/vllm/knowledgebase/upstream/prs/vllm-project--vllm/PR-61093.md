All four models fail for the same reason. AITER's FP8 MoE kernel only supports
sizes that are multiples of its tile size: the hidden size must be a multiple of
128, and the intermediate size per GPU a multiple of 256 (128 for SwiGLU). Each
of these models has an intermediate size that isn't:

| Model | Class | TP | Intermediate size per GPU | Padded to |
|---|---|---|---|---|
| RedHatAI/DeepSeek-Coder-V2-Lite-Instruct-FP8 | `Fp8MoEMethod` | 1 | 1408 | 1536 |
| nm-testing/DeepSeek-Coder-V2-Lite-Instruct-FP8 | `CompressedTensorsW8A8Fp8MoEMethod` | 1 | 1408 | 1536 |
| amd/Qwen3-30B-A3B-Thinking-2507-FP8 | `QuarkW8A8Fp8MoEMethod` | 2 | 384 | 512 |
| RedHatAI/diffusiongemma-26B-A4B-it-FP8-dynamic | `CompressedTensorsW8A8Fp8MoEMethod` | 2 | 352 | 512 |

When AITER is used, this PR pads these sizes up to the next supported size and
fills the padding with zeros, so the results don't change. Sizes that already
fit are left alone. The padding is done after the weights are loaded, in
`process_weights_after_loading`, so the weights are loaded at their checkpoint
shapes and model weight loaders don't need to change.

DiffusionGemma also uses the `gelu_tanh` activation, which vLLM did not pass to
AITER even though AITER supports it. This PR passes it through (see Details).

## Claims

- The failing models pass with AITER on, on MI300X and on MI355X with AITER on and AITER off.
- The failing models now work and are added to the tests and produce passing `lm_eval` scores.
- The failing models can now run vllm serve and vllm bench serve  with AITER on and AITER off.
