# [ROCm][Perf] Drop two dead per-step ops from the AITER sparse MLA metadata build

[Upstream PR](https://github.com/vllm-project/vllm/pull/58354) · state: closed · merged: True

## Original PR description

## Purpose

`ROCMAiterMLASparseMetadataBuilder.build()` runs once per KV-cache group per scheduler step and launches two GPU ops whose results are not needed:

1. **Unused `query_lens`.** `build()` computes `query_start_loc[1:] - query_start_loc[:-1]`, but `generate_sparse_seqlen_triton` only reads its size and device; the kernel derives per-request lengths from `cu_query_lens`. The parameter is dropped and `num_seqs` is taken as `cu_query_lens.size(0) - 1`.
2. **Self-aliasing `fill_`.** `paged_kv_indptr[n + 1:].fill_(paged_kv_indptr[n])` passes a view of the tensor being filled, so ATen clones the value first. A broadcast `copy_` from the same element writes the same values without the clone.

| op | aten ops | GPU kernels |
|---|---|---|
| `x[n+1:].fill_(x[n])` | `fill_` → `clone` (`empty_strided` + copy) → `copy_` | 2 |
| `t.copy_(x[n].expand_as(t))` | `copy_` | 1 |
| `qsl[1:] - qsl[:-1]` | `sub` (+ alloc) | 1 |

Each `build()` launches two fewer kernels and makes two fewer device allocations, with no change in output. #57885 removed a similar dead op from the DSA indexer builder.

On ROCm, sparse-MLA layers that do not bring their own backend select `ROCM_AITER_MLA_SPARSE`. Of 18 current checkpoints probed on main (dummy weights, 8 layers, TP=1), three reach this `build()`:

| model | binding | `build()` per decode step |
|---|---|---:|
| GLM-5.3 (`glm_moe_dsa`) | `DeepseekV32MLAAttention` → `ROCMAiterMLASparseBackend` | 2 |
| GLM-5.3-Quark-MXFP4-AttnFP8 (`glm_moe_dsa`) | same | 2 |
| GLM-5.3-Flash (`glm5_next`, DSA every 4th layer) | `MLAAttention` → `ROCMAiterMLASparseBackend` | 1 |

DeepSeek-V4-Flash/Pro and V4.1-Flash use their own builders, and the other 12 have no sparse MLA. CUDA never selects this backend.

## Test Plan

- `pytest tests/kernels/attention/test_rocm_aiter_mla_sparse_metadata_sync.py`. The new `test_build_fills_paged_kv_indptr_tail` poisons the `paged_kv_indptr` tail and checks that it reads as the running total; it fails if the tail copy is removed.
- Output equivalence: every benchmark run hashes the full `paged_kv_indptr` buffer (tail poisoned first), the returned metadata tensors and the AITER work/reduce metadata.
- Micro: the real `build()` on a builder constructed from a real `VllmConfig` (`max_num_batched_tokens=8192`, top-k 2048, decode B ∈ {1, 7, 29, 61, 127}). Both implementations alternate on one builder, order flipped every pair, 300 warmup + 3000 pairs, in 3 processes. *Steady*: contexts > top-k, so the persistent-metadata key hits. *Growing*: the key misses, so `get_mla_metadata_v1` and a stream sync run on every build.
