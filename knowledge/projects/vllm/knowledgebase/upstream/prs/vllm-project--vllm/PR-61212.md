# [Bugfix] Reject beam search in completion render

[Upstream PR](https://github.com/vllm-project/vllm/pull/61212) · state: closed · merged: True

## Original PR description

## Overview

Reject `use_beam_search=true` in `/v1/completions/render`, consistent with the existing behavior of `/v1/chat/completions/render`.

## Claims

Reject unsupported beam search requests with HTTP 400 instead of silently converting them into ordinary sampling requests.

## Validation

Added a service-level regression test covering the error code, message, and rejection before prompt preprocessing. The test fails before the fix because the handler returns a list of `GenerateRequest` objects instead of an error.

After the fix:

- Render tests: **29 passed**.
- All applicable pre-commit checks passed, including Ruff, mypy, and test tethering.

```bash
.venv/bin/python -m pytest \
  tests/entrypoints/scale_out/render/test_render.py \
  -q --tb=short

.venv/bin/pre-commit run --files \
  vllm/entrypoints/scale_out/render/serving.py \
  tests/entrypoints/scale_out/render/test_render.py
```

## Details

Completion render previously converted beam search requests into `SamplingParams` without preserving beam search semantics or `length_penalty`, potentially causing these requests to be executed as ordinary sampling.

This change rejects unsupported beam search requests after model validation and before prompt preprocessing, using the existing chat render error message.

Regular `/v1/completions` beam search support is unaffected.
