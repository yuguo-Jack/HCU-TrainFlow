# [Frontend] Share ChatStreamProcessor between chat streaming and derender

[Upstream PR](https://github.com/vllm-project/vllm/pull/62706) · state: closed · merged: True

## Original PR description

## Overview

Moves the per choice parse steps that chat streaming and parsed streaming derender both repeat into a shared `ChatStreamProcessor`. 

Closes #57572.

## Claims

- `OpenAIServingChat` streaming and `OnlineDerenderer._derender_chat_stream_parsed` now run the same code for `parse_delta`, `tools_streamed`, the `finish_reason` mapping and the parallel tool call filter
- The rule that hides logprobs and token IDs when reasoning is hidden lives in one place (`hide_metadata`)
- No change to what `/v1/chat/completions` streams

## Validation

Existing tests unchanged.

New unit tests in `tests/entrypoints/openai/chat_completion/test_stream_processor.py`

No model eval needed since served output doesn't change.

## Details

The processor handles one choice. It takes a `Parser` instance rather than a class, so the `_make_parser` hook keeps working and the parser cache (#57571, #58417) can hold the processor. Each caller keeps its own extras. Serving keeps usage, logging and the chunked prefill skip. Derender keeps replay, detokenization, tool call ID pinning and `stream_state`.

Small differences:

- Derender: a choice that finishes without generating anything now sends an empty delta without calling the parser, same as serving
- With `parallel_tool_calls=false` the filter runs a bit earlier. Delta logs no longer show tool calls the client never gets and derender only records index 0 in `last_tool_call_ids`. Nothing streamed changes
