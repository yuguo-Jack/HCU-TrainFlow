# [Bugfix][Model] DiffusionGemma: stop sampler recompiles during serving

[Upstream PR](https://github.com/vllm-project/vllm/pull/61669) · state: open · merged: False

## Original PR description



## Overview

DiffusionGemma's sampler helpers use plain `@torch.compile(dynamic=True)` and no startup path runs a decode step, so their graphs compile lazily inside the engine step and stall every request on the replica (about 60 s per graph on MI350X and 1.5–3 min on MI300X). This PR removes the guards that create serving-time variants and compiles the remaining ones during kernel warmup.

## Claims

- After warmup, serving compiles no new graph for `_compiled_sample_step`, `_denoise_temperature`, `_softcap_logits` or `_compute_num_rejected`, for any tile size, request count, canvas width or allowed-set size (including 0 and 1). `sample_row_stats` also no longer compiles a second Triton variant for seeds divisible by 16.
- No behavior change: sampler outputs are bit-identical to `main`, and warmup leaves the RNG state untouched.
- Cost: about 67 s of one-time warmup on MI300X (opt out with `--kernel-config '{"enable_jit_warmup": false}'`) and about 0.1–0.2 ms per denoise step.

## Details

**Root cause.** Each recompile runs synchronously in the engine step. The variants compile lazily, so the stalls recur after every restart and whenever traffic produces a new shape. The profile run's dummy batch takes the prefill path, so nothing at startup reaches the sample step.

**Fix:**
- **Unbacked dims:** mark the tile and request dims unbacked, tied to `num_decode` and `num_reqs` with `torch._check`, and both softcap dims, so any size (including 0 and 1) shares one graph.
- **Duck sizing:** turn it off for `_compiled_sample_step`.
- **Padding:** canvas-dim state buffers get one unused padding column, so a `[:, :W]` view is never contiguous.
- **Draft copy:** runs once after the tile loop instead of inside the step.
- **Seed:** `do_not_specialize=["seed"]` on the Triton kernel. The main sampler gets the same effect by loading seeds from a tensor.
- **Shared tile function:** the tile body moves into `DiffusionSampler._denoise_tile`, shared by serving and a new `DiffusionSampler.warmup()`.

**Warmup.** `warmup()` runs every remaining variant through `_denoise_tile`:
- widths: the canvas length and 1;
- embedding tables: the full table, an 8-id allowed set and a 1-id set (allowed sets only at TP 1, where `diffusion_constrained` is allowed);
- self-conditioning on and off.

That makes 8 step graphs: without self-conditioning the table is unused, so one graph covers all three tables.

It uses a 2-row scratch state and runs under `torch.random.fork_rng`. Dynamo guards on dispatch keys, so persistent buffers are built outside inference mode and per-step tensors inside it, as in serving.

`DiffusionGemmaModelState.warmup_compiled()` calls it and also compiles the constrained step's fp32 softcap; the profile run already compiles the full-vocab one. A new `ModelState.warmup_compiled()` hook, a no-op on the base class, runs it from `kernel_warmup`:
- **Only with JIT warmup enabled:** gated on `enable_jit_warmup`.
- **After the thread count is set:** Dynamo guards on `torch.get_num_threads()`.
- **After the `process_local_only` return:** at TP > 1 the step all-reduces, so a worker added by elastic EP compiles on first use, as before.

<details>
<summary>Guards that created serving-time variants</summary>

| Guard | Trigger | Fix |
|---|---|---|
| 0/1 specialization of tile and request dims | a tile with one request | `mark_unbacked` + `torch._check` ties; without the ties the shape checks become data-dependent guards and break the graph |
| duck sizing | two backed sizes equal at compile time. With the shipped config, warmup's 2 scratch rows equal the stability threshold (2) in `accepted_canvas_history`; without the fix the first real request recompiles on a `history.size()` guard | `torch.fx.experimental._config.patch(use_duck_shape=False)` on the step, the only helper with several backed sizes |
| contiguity of `buf[:, :W]` | a full-width tile is contiguous, a narrower one isn't | padding column (`_canvas_buffer`) |
| `draft_tokens[all_slots, :CL]` inside the step | Dynamo branches on `CL` reaching the buffer width | copy after the tile loop at the widest width |
| softcap shape | 0 rows (prefill-only steps), 1 row, an allowed set of 1 | both dims unbacked |
| softcap dtype | the constrained path softcaps fp32 logits, the full path the head dtype | profile run compiles one, `warmup_compiled` the other |
| width or allowed set of 1 in the step | `diffusion_canvas_length=1`; one `logprob_token_ids` with `diffusion_constrained` | backed (the width also arrives as the int `CL`), so warmed |
| Triton specialization of `seed` | a random seed divisible by 16 | `do_not_specialize=["seed"]` |
</details>

**Trade-offs and limitations:**
- **Startup and per-step cost:** see Claims. The 5 width-1 and single-id graphs cost about 25 s at startup, against 60–160 s per graph if a request hits them during serving.
- **Private API:** `use_duck_shape` is a private PyTorch setting, not used elsewhere in vLLM, and is imported explicitly.
- **Memory:** one extra column per canvas buffer. For `self_conditioning_embeds` that is `max_num_reqs × hidden × 4` bytes.
- **Output stride:** decode `sampled_token_ids` now has a row stride of `CL + 1`. `post_update` passes the stride, and the device-to-host copy makes one contiguous copy.
- **`recompile_limit=64`:** kept, because the step's 8 variants reach Dynamo's default limit.
- **Remaining Triton specializations:** `sample_row_stats` still specializes on its size and stride arguments, which keeps vectorized loads. A narrow or constrained read in a new divisibility class compiles one variant in seconds, unchanged from `main`.
- **Draft copy:** covered by the equivalence harness, not by a unit test.
- **Not validated here:**
  - Serving `main` end to end: this environment has transformers 5.11, while `main` needs 5.16.1 or later, and there is no ROCm build of `main`.
  - TP > 1: the DiffusionGemma GSM8K CI job (`--tensor-parallel-size 2`) runs this warmup.
  - The pinned torch 2.13: this was validated on 2.12.
