# [KV Transfer] Connector-agnostic KV checksums for P/D disaggregation

[Upstream PR](https://github.com/vllm-project/vllm/pull/61488) · state: open · merged: False

## Original PR description



## Overview

> **For review, this series is split into stacked PRs:** #61578 (1/N, framework + NIXL pull), #61579 (2/N, TP replicas and block sizes), #61580 (3/N, NIXL push); Mooncake, Mamba state and the Triton kernel follow. This PR stays as a draft reference implementation of the whole series and holds its end-to-end validation.

Connector-agnostic KV checksums for P/D disaggregation. Some transfers complete without error but deliver the wrong KV: a read after the producer has already reused its blocks, or KV placed at the wrong position because producer and consumer disagree on the layout. With `kv_transfer_config.enable_kv_checksum` on both sides, the consumer verifies every KV load against checksums computed by the producer. Under `kv_checksum_fail_closed`, a mismatched or unverifiable load goes through the existing KV load failure path (`kv_load_failure_policy`: `fail`, or `recompute` locally).

Related, not duplicated: #57912 and RFC #54363 add integrity checks for the filesystem KV offload tier; this PR covers producer-to-consumer transfers. It also references #58860, #59746 / #59747 and RFC #47812 / #48216 (see the commit messages).

## Claims

- Detects KV corruption from a P/D transfer before the request runs, for NIXL pull, NIXL push and Mooncake P2P. It works across TP and PP layouts, block sizes, KV cache layouts, and Mamba state, including TP-split state between producers and consumers with different TP sizes.
- Does not change model outputs. With checksums on vs off in a deterministic setup, 200/200 outputs are identical token for token.
- Adds no CPU<->GPU synchronization to the engine step. The results are copied to the host on a side stream.
- Off by default, so it has no effect unless enabled.

## Details

The series is split by component. Each commit message gives the design, the alternatives that were rejected, known limitations and validation.

1. **Worker computation.** The checksum definition: per (layer, KV head) slice, s = Σ x_j (2j+1) over the 8-byte pieces in token order, weighted by m = 2(layer·H + head) + 1, all mod 2^64. Each worker sums its own slices. Replicated heads count once on the producer and are checked per replica on the consumer. The sums use global coordinates, so they do not depend on the TP/PP split, the block size or the cache layout.
2. **Scheduling and verification.** Selects which blocks to checksum on each side. The comparison reports each group as mismatched or unverified, and fail-closed routes failures through the existing load-failure path. Adds the connector API `kv_checksum_carrier`. NIXL pull carries the checksums in `kv_transfer_params`.
3. **NIXL push.** The checksums ride on the completion notif of the WRITE that delivers the KV. Bumps `NIXL_CONNECTOR_VERSION` (once for the series).
4. **Block sizes.** Producer and consumer may use different block sizes.
5. **Mooncake P2P carrier.**
6. **Triton kernel.** One launch per layer, and each piece is read once. The PyTorch path is kept for CPU. A microbenchmark is added in `benchmarks/kernels/benchmark_kv_checksum.py`.
7. **Mamba state.** Layers declare how TP splits their states (`MambaSpec.state_splits`, for Mamba1, Mamba2 and GDN), so state can be compared across different TP sizes.
8. **NIXL push cleanup.** Drops an unreachable producer-side branch.
9. **MiniMax-M3.** Declares the indexer cache replicated across TP.
10. **Several KV caches per layer.** Supports layers with more than one KV cache.
11. **MLA defaults to replicated.** An MLA spec without `max_tp_shards` is treated as replicated, which matches how NIXL classifies it.
12. **Host-side preparation.** Rows are built with numpy and copied to the GPU in one H2D per step.

Limitations:
- Mooncake is covered by unit tests only; it has not been run end to end on GPU.
- ROCm is untested.
- A Mamba group whose layers do not declare a split is skipped when producer and consumer TP sizes differ.
- When the producer's block size is a multiple of the consumer's (possible with NIXL push and Mooncake P2P), a consumer prefix hit that ends inside a producer block leaves that group unverified, so a fail-closed consumer recomputes the request.
