# [Bugfix][Core] Shut down executor workers when EngineCore init fails

[Upstream PR](https://github.com/vllm-project/vllm/pull/57657) · state: open · merged: False

## Original PR description

## Purpose

Fixes #57650. 

EngineCore.__init__ spawns the executor's worker processes before building the scheduler, so if scheduler construction (or any later step) raises, the `engine_core = EngineCoreProc(...)` assignment in `run_engine_core` never completes and its `finally` cannot call `shutdown()`. The only remaining cleanup is the partially-constructed object's weakref finalizer, which is not deterministic and  since 0.24 hangs on the degraded waitpid path instead of forcing worker exit, leaving
GPU memory unreleased (repro in the issue: scheduler init failure, worker stuck, shm leaks).

Fix: wrap the post-executor init steps in `try/except` and call a best-effort guarded shutdown (`_shutdown_executor_on_init_failure`) before re-raising. Applied in both `EngineCore.__init__` and the `EngineCoreProc.__init__` block that starts fault-tolerance/IO threads and waits for the DP-coordinator READY. `shutdown()` now guards every attribute
it touches with `getattr`, so it is safe on a partial object. Teardown uses the normal `model_executor.shutdown()` path (with configured worker timeouts), so it is deterministic and strictly better than the old finalizer/timeout fallbacks.
