# [Feature][Quantization] Support AWQ/GPTQ Marlin cache restarts

[Upstream PR](https://github.com/vllm-project/vllm/pull/64182) · state: closed · merged: True

## Original PR description

## Overview

Allow the weight-cache daemon to reuse AWQ/GPTQ linear weights already packed for Marlin across engine restarts. Related to #56049; updated against main `8cf1277362aef963a71cf6860c28387acf6ecb90`.

## Claims

- Support AWQ INT4 and symmetric GPTQ INT4/INT8 linear weights with the actual Marlin kernel and FP16/BF16 activations.
- Preserve shared repacked weights, scales, zero points and padded bias without repeating checkpoint conversion or Marlin transformations.
- Continue rejecting other kernels, INT8/FP8 activation overrides and AWQ/GPTQ MoE.

## Validation

November 3 integration update: preserve the GPTQ batch-invariant ordinary-loading path from #60479 and restore the symmetric Marlin runtime zero-point name after #62407. The latter now keeps checkpoint `qzeros` registered and reads a separate empty `w_zp`; an IPC attachment must restore that kernel metadata and mark checkpoint `qzeros` retired. No tensor data is transformed on attachment. The existing tests reproduced 5 failures (GPTQ real-model IPC and four layer cases) before this correction, with 6 passing. Final results: **11 passed, 68 deselected in 244.14s** on B300 (same two pinned real models, ordinary/fallback/IPC/restart with `fallback=False`, plus nine layer/boundary cases). A real CPU/Gloo GPTQ construction check also preserves checkpoint tensors in batch-invariant mode and rejects Marlin IPC without initializing CUDA. Changed-file hooks pass, including mypy and CI tethering. Existing torch/fork deprecation warnings remain; no L4 Buildkite run is claimed.


B300, TP1. The two real-model cases use FP16, eager execution, TRITON_ATTN, explicitly selected Marlin, two prompts × 16 generated tokens, and prompt/sample top-5 logprobs. Each compares ordinary loading → missing-daemon disk fallback → IPC → second IPC; both IPC starts set `fallback=False`. Comparison uses the existing `check_logprobs_close` helper. `VLLM_BATCH_INVARIANT=0` is intentional: AWQ and GPTQ use unpacked implementations when enabled, and Marlin does not guarantee batch invariance.

This is cache-versus-ordinary output equivalence, not quantization accuracy against BF16 or a performance benchmark. Multi-GPU, other hardware and other kernels are not claimed.

## Details

Both methods previously rejected daemon caching even though ordinary Marlin loading worked. Their kernel configuration is constructed before post-load processing. Normal post-load work converts AWQ packing and/or repacks weights, permutes scales/zero points, pads/permutates bias and selects the symmetric GPTQ runtime zero-point name. IPC already supplies transformed tensors; the GPTQ attachment restores the runtime name and retirement metadata. Opt in only the actual `MarlinLinearKernel` with FP16/BF16 activations, and return before those transformations on the pre-processed path. No common loading interface, kernel implementation, scheduler/model-runner change or steady-state synchronization is added.

Reuse the existing daemon, generation and comparison helpers. The L4 Marlin Preload CI step selects the real-model and layer/boundary cases and tracks their source dependencies. Local validation is B300; L4 Buildkite execution is not claimed. The preload guide documents commands, defaults and exclusions, with links from the AWQ/GPTQ guides.

Duplicate checks covered current #56049/comments, issue-linked drafts and open Marlin-preload/AWQ/GPTQ-cache searches. #61908 introduces a different on-disk AWQ-v2 format, while #60479 changes GPTQ batch-invariant execution; neither restores daemon IPC weights. Existing FP8/FP4 cache drafts do not cover this path.
