# [ROCm][DSv4/4.1] Fuse inverse RoPE and MXFP8 quant into the aiter sparse MLA and sparse MLA gating changes

[Upstream PR](https://github.com/vllm-project/vllm/pull/60154) · state: open · merged: False

## Original PR description



## Overview

On ROCm with the aiter sparse MLA backend, DeepSeek-V4/V4.1 ran a separate `rocm_inverse_rope_rows_` pass (and, on V4.1, a separate MXFP8 quantization) after attention. The aiter kernel can now do both in its store, so this passes it the positions / cos-sin cache (and the MXFP8 output buffer) and drops the extra passes.

- DSv4.1: decode and prefill rotate in the store; with an MXFP8 `o_proj` input the store also quantizes into it.
- DSv4: decode and prefill rotate in the store when `wo_a` is BF16. The fp8 `wo_a` path is unchanged (`inverse_rope_group_quant` already rotates there).
- Rows not rotated by a kernel store still go through the standalone pass (none on the aiter path).
- Also, gluon sparse MLA path is disabled for num_heads > 64 + prefill. For those workloads, existing kv gather + OPUS is faster.

Requires the aiter change adding `inv_rope_positions`, `inv_rope_cos_sin_cache` and `out_mxfp8` to `sparse_mla_fwd`, merge after the aiter bump (already done, aiter v0.1.25 has the support for these changes).

Perf. and accuracy runs to be added.
