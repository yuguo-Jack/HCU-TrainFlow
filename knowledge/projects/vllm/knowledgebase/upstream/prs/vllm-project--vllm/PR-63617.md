# [Bugfix][PP] Filter KV-cache tensors to worker-owned layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/63617) · state: open · merged: False

## Original PR description

Fixes #63615.

Emits KV-cache tensors only for layers the worker actually owns, so the `next()` lookup in `allocate_kv_cache` (`worker/utils.py`) always matches under PP. When a pipeline rank owns none of a group's layers, the worker-side projection keeps the group's global `UniformTypeKVCacheSpecs` unfiltered while emptying its `layer_names`; the planner loop then iterates the unfiltered spec and emits tensors naming other ranks' layers, and the consumer-side lookup raises a bare `StopIteration` — surfacing on the *other* rank as an opaque `Worker failed` error (full analysis in the issue).

The diff targets the planner loop in `kv_cache_planning.py`; on the v0.31.0 image the same pair lives at `kv_cache_utils.py:1792` (loop) and `:2666` (projection guard) — the code moved between the two, the bug didn't.

We considered the projection-side alternative (dropping the `worker_layer_names and` guard so an empty rank gets an empty spec) and took the filter instead: no change to `UniformTypeKVCacheSpecs` validation semantics.

**Test** (in `tests/v1/core/test_kv_cache_planning.py`): builds real `KVCacheGroupSpec` objects with a `UniformTypeKVCacheSpecs`, projects them through `_project_kv_cache_groups_to_worker` with a worker spec that omits every layer of that group — producing the actual failing state (empty `layer_names`, unfiltered global spec) — runs the planner, and asserts every emitted tensor's layer names are a subset of the worker's. Reproduced red/green on the v0.31.0 form of the same code: the unpatched planner emits tensors for layers the worker does not own (`[['layer1', 'layer2']]`); the patched one emits none.

Generic PP hygiene, model-independent; verified on a two-rank PP2 hybrid-KV deployment where the crash reproduced deterministically before the fix and never after. Working overlay and receipts: https://github.com/ebfio/deepseek-v41-flash-pp2-pair
