# [KV Connector] Recreate NIXL agents across sleep without UCX overrides

[Upstream PR](https://github.com/vllm-project/vllm/pull/63144) · state: open · merged: False

## Original PR description

## Overview

Follow up on #59635: destroy the NIXL agent on sleep and recreate it on wake, removing the sleep-specific `RCACHE_ENABLE=n,TLS=^cuda_ipc` workaround.

**Draft until the NIXL distribution used by vLLM includes [openucx/ucx#12108](https://github.com/openucx/ucx/pull/12108). Both P/D instances must finish sleeping before reusing their GPU memory.**

## Claims

- Keep CUDA IPC available without sleep-specific UCX environment or backend overrides.
- Reuse the agent configuration and preserve metadata/generation refresh.
- Use the agent lifetime as the sleep state; clean up failed restores before retrying.

## Validation

Final code: `c4c15019ed`. GB300, level-1 sleep, eager execution, real HTTP P/D requests and measured NIXL transfers. No `UCX_TLS`, `UCX_RCACHE_ENABLE`, or `UCX_CUDA_IPC_CACHE` overrides.

Qwen3-0.6B, same-node TP1 + TP1, 2 GiB KV cache per instance. Memory is P / D in MiB:

| UCX build | Before sleep | Both asleep | After first wake and requests |
|---|---:|---:|---:|
| With UCX patch | 5723 / 5979 | 1363 / 1619 | 5167 / 5403 |
| Without UCX patch | 5773 / 5773 | **3407 / 1363** | 5217 / 5197 |

Without the patch, P retains about 2 GiB of KV memory even after both peers sleep, although post-wake output is still correct (10/10).

With the patch: P-first, D-first and concurrent sleep, three cycles each; **90/90 post-wake outputs match**. P-only sleep/wake preserves another **10/10 outputs**, but retains 3407 MiB while D stays awake. Total: **110 transfers, 0 failures**.

DeepSeek-V4.1-Flash (FP8/MXFP4, default Engram CPU offload), two nodes, TP4 + TP4, 16 GiB KV per GPU. Memory range per GPU in GiB:

| Instance | Before sleep | Both asleep | After wake and requests |
|---|---:|---:|---:|
| P | 106.08 | 3.98 | 99.13 |
| D | 106.30–106.39 | 3.85–3.93 | 98.74–98.82 |

All three sleep orders complete with stable asleep/wake memory: **30/30 arithmetic answers correct in the original 32-token responses**, plus **30/30 newline-terminated answer checks**; **400 NIXL transfers, 0 failures**. These cross-node transfers use RDMA; the Qwen test above exercises CUDA IPC.

**Limitation:** full continuations are not reproducible: post-wake matches are 8/10, 5/10 and 5/10; the unchanged baseline (`90aa823cba`) also matches only 6/10 between warmed no-sleep runs and after wake. These tests validate memory reclamation and known answers, not exact generation parity; the initial strict-output check failed (7/10).

Both models: max length 4096, max sequences 16, long-prefix arithmetic prompts, greedy generation, 32 output tokens, prefix caching disabled. Residual memory includes CUDA/kernel state; wake does not recreate all warm-up allocations.

**Checks:** 199 NIXL unit tests pass, including failed restore cleanup and retry; pre-commit and independent code review pass.

## Dependency and lifecycle

Sleep releases handles and registrations, then destroys the agent. Wake recreates it and refreshes metadata; generation checks prevent peers from reusing stale registrations.

**NIXL must use a UCX build containing [openucx/ucx#12108](https://github.com/openucx/ucx/pull/12108)** to release unused CUDA IPC mappings; merging the UCX PR alone is insufficient. Tests used a custom patched build, so build differences may affect residual memory.

AI assistance (Codex) was used for implementation, tests and review.
