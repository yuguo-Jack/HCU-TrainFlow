# [Doc][Recipe] MiniMax-M3.1-Flash: DEP2 + DEP4 PD on GB200/GB300, 7-token FLASHINFER_TS DSpark on NVIDIA

[Upstream PR](https://github.com/vllm-project/vllm/pull/63428) · state: closed · merged: True

## Overview

Update the MiniMax-M3.1-Flash recipe's NVIDIA prefill/decode setup to one DEP2 prefill + one DEP4 decode on GB200 and GB300, and switch the NVIDIA DSpark default to seven speculative tokens on the FlashInfer PrimiTS (`FLASHINFER_TS`) draft backend.

**Draft:** served and evaluated on GB300 with the public image (see Validation); GB200 and the B200/B300 single-node smoke test are still pending.

## Claims

- **Guide:** "Prefill/decode disaggregation (1P1D, DEP2 + DEP4, NVIDIA GB200 / GB300)" replaces the GB200 TP4 + TP4 section. A DEP2 prefill on one tray feeds a DEP4 decode on a second tray. Both roles run DeepGEMM NVFP4 MegaMoE over expert parallelism, the V2 model runner and `--numa-bind`, with NIXL `engine_ttl: 0` and `VLLM_ENGINE_READY_TIMEOUT_S=3600`. The decode adds `--watermark 0.05`, 28 seqs per rank and FULL_DECODE_ONLY graphs up to 224 tokens. Host KV offload on the prefill is documented as an option.
- **Command builder:** `strategy_overrides.pd_cluster` renders the same pools and role flags for `gb200` / `gb300`. `vllm-router` is pinned to `--intra-node-data-parallel-size 1`, because it takes one DP size for both pools.
- **DSpark on NVIDIA (B200, B300, GB200, GB300):** `num_speculative_tokens` 3 → 7 and draft attention `FLASH_ATTN` → `FLASHINFER_TS`, in the feature and in the single-node GB200 guide command. AMD (3 tokens, `TRITON_ATTN`) and Hopper (no DSpark) are unchanged.

## Details

- **Where the layout comes from:** it and the per-role settings were tuned in GB300 AgentX runs on a pre-release build. In those runs, DEP4 decode beat DEP8 per GPU at the same batch per rank. A second DEP2 prefill did not raise throughput, because decode was the bottleneck. That build used features not upstream (a NIXL push transfer mode and a Mooncake-backed prefix pool), plus synthetic acceptance for throughput. The recipe uses NIXL pull, real acceptance (`rejection_sample_method: block`) and the public image instead.
- **Decode sizing:**
  - `--watermark 0.05` makes extra requests wait in the queue instead of preempting running ones.
  - The decode's `--max-num-batched-tokens` stays at 8192, because a preempted request recomputes its context in chunks of that size while every DP rank runs eager steps.
  - NIXL `engine_ttl: 0` turns off idle remote-engine cleanup; with the default one-hour TTL, a decode crashed an hour after its prefill went away.
- **Removed:** the GB200 TP4 + TP4 section (eager prefill, decode `--max-num-batched-tokens 512`, `enforce_handshake_compat: false`). Both roles now share the attention and DSpark configs, which the NIXL compatibility hash covers, so the handshake check can stay on.
- **Tradeoff:** the renderer applies a feature's args per hardware, not per strategy. So the 7-token draft is now the default for every NVIDIA layout, including high-concurrency DEP serving, where a shorter draft can give more throughput. InferenceX's GB200/GB300 DEP4 aggregated lanes use 3 tokens.
- **Known renderer behavior:** for models that fit on one node, the static JSON API co-locates the two PD roles on one node, so `hw/gb{200,300}/strategies/pd_cluster.json` shows the DEP4 decode on `CUDA_VISIBLE_DEVICES=2,3`. The interactive builder uses the recipe's per-role `nodes` (one tray each). The current recipe has the same co-location.
- **Not a duplicate:** #63232 (the `minimax-m31-flash` support branch) adds an earlier version of this file. No other open PR changes it.
