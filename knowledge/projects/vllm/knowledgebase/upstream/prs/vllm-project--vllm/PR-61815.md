# [Quantization] Allow online fp8 weight-only quantization of an unquantized lm_head

[Upstream PR](https://github.com/vllm-project/vllm/pull/61815) · state: open · merged: False

## Original PR description

## Overview

Let `quantization_config.targets` select an unquantized `ParallelLMHead` for online fp8 **weight-only** quantization (per-output-channel fp8 weights, full-precision activations). Quantized checkpoints often ship the lm_head in bf16 (e.g. GPTQ MoE checkpoints with int4 experts), and on small-active-parameter MoE models the head is one of the largest reads per decoded token. Online quantization can already convert a checkpoint's bf16 linears; today `resolve_quant_method` always leaves the lm_head on its checkpoint method.

Related: #58578 (reduced draft vocabulary for MTP drafters that share the target lm_head).

Related: #59973 gives an MTP/EAGLE drafter a private quantized copy of the head while the target keeps BF16 (outputs unchanged); this PR quantizes the target head itself (opt-in, outputs change), which also speeds up target verify and non-speculative decode. #41000 (checkpoint-quantized block-fp8 lm_head via `Fp8Config`) and #52451 (compressed-tensors FP8 metadata for `ParallelLMHead`) cover checkpoints that already quantize the head.

## Claims

- `--quantization-config '{"targets": {"re:.*lm_head$": "fp8_per_channel"}}'` quantizes an unquantized lm_head to fp8 weight-only via `init_wfp8_a16_linear_kernel` (XPU: `XPUW8A16FP8LinearKernel`; CUDA: Humming/Marlin FP8).
- No change without such a target: the `linear` spec never picks up the lm_head; embeddings keep their checkpoint method.
- Only `fp8_per_channel` is accepted for the lm_head (vocab padding rows are never loaded, and per-channel scales keep them out of real rows' scales); an lm_head the checkpoint already quantizes, or one tied to the embeddings, raises a clear `ValueError`.
- One Intel Arc Pro B70, Qwen3.6-35B-A3B GPTQ-Int4: decode +3% without MTP, +11-17% with MTP k=4; gsm8k unchanged within noise; weights -0.47 GiB.

## Validation

`pytest tests/quantization/test_online.py -k "targets or lm_head"`: 9 passed (B70, vLLM nightly `3f1bcfd82` with this branch's files; the touched files are unchanged upstream between that nightly's base and this branch's base `e10c10a64`).

E2E: palmfuture/Qwen3.6-35B-A3B-GPTQ-Int4 (int4 experts, bf16 lm_head 248320 x 2048), `--language-model-only --dtype float16 --kv-cache-dtype fp8`, XPU graphs, 1 request, 512-token code / prose answers, decode tok/s; both arms also use an int4 MoE decode kernel from vllm-project/vllm-xpu-kernels#644, so the lm_head is the only difference:

| | no MTP (4K ctx) | MTP k=4 (2K ctx) | gsm8k, first 100 test questions | weights |
|---|---|---|---|---|
| bf16 lm_head | 86.6 / 87.2 | 157.3 / 118.7 | 97/100 | 20.18 GiB |
| fp8 lm_head (this PR) | **89.4 / 90.2** | **183.7 / 131.9** | 96/100 | 19.71 GiB |

Logs confirm the path: `Quantizing 1 layers of types: language_model.lm_head: 1 (from targets: re:.*lm_head$, fp8_per_channel)`, `Selected XPUW8A16FP8LinearKernel for Fp8PerChannelWeightOnlyOnlineLinearMethod`, and the head's weight is `float8_e4m3fn (2048, 248320)` at runtime. No GPU faults in the kernel log with MTP. Not run: CUDA (the Marlin/Humming W8A16 path is selected by the existing kernel table, untested here).

## Details

- `resolve_quant_method` now accepts `ParallelLMHead`; when an online target matches it, the online method is returned, otherwise the checkpoint method is kept as before.
- `OnlineQuantizationConfig` maps a `ParallelLMHead` matched by `targets` to a lm_head-only table with one entry, `kFp8StaticChannelSym -> Fp8PerChannelWeightOnlyOnlineLinearMethod`; other weight keys get the existing "not supported" error. The existing rejection for other layer types (e.g. `VocabParallelEmbedding`) is unchanged.
- `Fp8PerChannelWeightOnlyOnlineLinearMethod` reuses the PTPC weight quantization and selects a W8A16 kernel; `Fp8PtpcOnlineLinearMethod` now exposes an input quant key only when it quantizes activations.
- `OnlineLinearBase.tie_weights` raises, since a tied head shares the embedding's bf16 weight.
- `LogitsProcessor` already calls `lm_head.quant_method.apply`, and MTP drafters share the target's lm_head module, so verify and draft both use the fp8 head. With MTP the drafter's own `lm_head` is also matched by the pattern and quantized before the proposer replaces it with the shared head ("Quantizing 2 layers"); that copy is discarded. An EAGLE drafter with an identical head no longer compares equal to the fp8 target head and keeps its own copy.
- Docs: one bullet in `docs/features/quantization/online.md`.
