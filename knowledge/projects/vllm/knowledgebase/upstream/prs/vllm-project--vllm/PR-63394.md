# [Doc] MiniMax-M3: use the autotune flag the pinned GB200 nightly accepts, fix golden-AL links

[Upstream PR](https://github.com/vllm-project/vllm/pull/63394) · state: closed · merged: True

## Original PR description

## Overview

Follow-up to #62543 and #61489. The GB200 AgentX lane of [SemiAnalysisAI/InferenceX#4281](https://github.com/SemiAnalysisAI/InferenceX/pull/4281) pins `vllm/vllm-openai:nightly-5555a2d8f7116b2b4877f66516f4128176cf722a` (vLLM commit of 2026-10-13). That image predates #61479, so it does not accept `--disable-flashinfer-autotune`; #61489 switched the GB200 guide command and command-builder override to that spelling. This restores `--no-enable-flashinfer-autotune` for the GB200 lane, which is what the InferenceX recipe and run use. It also fixes the InferenceX golden-AL links, which point at a path that no longer exists.

## Claims

- GB200 guide Worker command and the NVFP4 `gb200` builder override use `--no-enable-flashinfer-autotune`; a sentence in the guide explains why. Other hardware still renders `--disable-flashinfer-autotune`.
- The three `golden_al_distribution/minimaxm3_eagle3_gqa.yaml` links now point at `inferencex-e2e/infx/golden_al_distribution/` (the old path returns 404).

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` passes.
- Rendered every variant x hardware x strategy x feature set x KV-offload option x PD router x pool-node preset x frontend (22,440 renders) before and after: only the 170 GB200 NVFP4 renders change (the autotune flag); none errors.
- Checked at the image's vLLM commit: `arg_utils.py` exposes only `--enable-flashinfer-autotune` (with the argparse `--no-` form), and `EnableDisableAction` (the `--disable-` alias) arrives in #61479, merged after the image's commit. The tested run's `dynamo.vllm` launch lines use `--no-enable-flashinfer-autotune` ([run 39150937290](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/39150937290)).
- Point-by-point check of the guide table (max-num-seqs, capture sizes, SimpleCPUOffload budget) against the PR-head recipe and the logged launch args: no differences.

## Details

Excluded as InferenceX harness or cluster-specific: synthetic acceptance, AIPerf replay settings, Slurm options, `--kv-cache-metrics`, `VLLM_LOG_STATS_INTERVAL`, `ETCD_LEASE_TTL`, RDMA device variables. The B200 section also pins images that predate #61479; not changed here.
