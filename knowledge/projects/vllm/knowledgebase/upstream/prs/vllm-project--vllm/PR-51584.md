# [Bugfix] Account for the NUMA memory policy when sizing available RAM

[Upstream PR](https://github.com/vllm-project/vllm/pull/51584) · state: open · merged: False

## Original PR description

## Purpose

`_get_available_ram_bytes()` in `vllm/model_executor/model_loader/weight_utils.py`
reports host-wide free memory. A process under an `MPOL_BIND` memory policy
cannot use the rest of the machine: **`MPOL_BIND` does not fall back to another
node.** It reclaims within the bound set, and when that is not enough the
allocation fails and the OOM killer takes the process.

So the number can overstate reachable memory by roughly the node count, and two
things that already exist were wrong for a bound process: the
"Checkpoint size … Available RAM …" log line, and the auto-prefetch heuristic
that consumes it. This is a fix to an existing check rather than a new feature.

It also warns when the checkpoint does not fit in the bound nodes. Without that,
the failure mode is a `SIGKILL` with no diagnostic at all, which is very hard to
attribute to a memory policy.

### The measurements this is based on

4-node box (2× Xeon Platinum 8592V, SNC2, ~504 GiB per node), using
`set_mempolicy(MPOL_BIND)` directly:

1. **Does it spill under pressure?** Bound to the node with the least free
   memory (2.3 GiB free, 480 GiB of reclaimable page cache) while a sibling node
   had **39 GiB free and untouched**, allocate and touch 32 GiB:

   ```
   RESULT: touched 32.0 GiB without failing
     node1: 2048 sampled pages (100.0%)   <- the bound node
   ```

   The kernel reclaimed half a terabyte of page cache rather than put a single
   page on the neighbour that had room. No spill by preference.

2. **And when it cannot reclaim?** 529 GiB bound to a 504 GiB node, i.e. above
   its total, with `oom_score_adj = 1000` so we would be the victim:

   ```
   exit code 137        # 128 + 9 = SIGKILL
   ```

3. **The control that closes the argument.** The same 528.5 GiB, same machine,
   minutes later, **with no policy**:

   ```
   RESULT: touched 528.5 GiB without failing
     node0: 0.4%   node1: 11.8%   node2: 46.0%   node3: 41.9%
   ```

   It survives and spreads itself. So what killed case 2 was `MPOL_BIND`, not
   global pressure: the machine had 2 TB, 1.4 TB of reclaimable cache and 433 GB
   free at that moment.

I could not confirm the OOM was `CONSTRAINT_MEMORY_POLICY` specifically — the
kernel log is not readable unprivileged here — so the mechanism is inferred from
the A/B rather than read. The claim being made is only "bound dies, unbound does
not", which is what was measured.

### Implementation notes

- The binding is read with libnuma's `numa_get_membind()` via `ctypes`, **not**
  `/proc/self/status`: `Mems_allowed_list` still reports every node under
  `numactl --membind`, because that is a mempolicy and not a cpuset. Verified:

  ```
  unrestricted           membind nodes: None    Mems_allowed_list: 0-3
  numactl --membind=1    membind nodes: [1]     Mems_allowed_list: 0-3
  numactl --membind=0,1  membind nodes: [0,1]   Mems_allowed_list: 0-3
  numactl --interleave=all  membind nodes: None
  ```

- If libnuma is missing, NUMA is unavailable, or every node is allowed, the
  function returns `None` and behaviour is unchanged.
- `/sys/devices/system/node/nodeN/meminfo` has **no `MemAvailable` line** — that
  one is machine-wide only — so per-node availability is reconstructed as
  `MemFree + FilePages + SReclaimable - Shmem`. Sanity check on this box:
  1995 GiB unrestricted against 1980 GiB in `/proc/meminfo`, 500 GiB for one
  node, 998 GiB for two.
- It is a **warning and not an error** because the loader cannot know whether the
  weights will stay in RAM: on an accelerator they are read transiently and the
  checkpoint may legitimately exceed the bound nodes.

## Test Plan

```bash
pytest tests/model_executor/test_weight_utils.py -k "numa or node_available or warn"
```

Six tests are added:

- `_node_available_bytes` over a synthetic sysfs tree, checking the exact
  arithmetic;
- that an unexpected sysfs layout **disables** the check rather than guessing;
- four parametrised cases of the warning: unbound never warns; bound and it fits,
  no warning; bound and it does not fit, warns; sysfs unreadable, stays quiet.

## Pull request overview

Fixes RAM availability reporting and user diagnostics under NUMA `MPOL_BIND` memory policies so that vLLM doesn’t overestimate reachable memory (which can lead to silent `SIGKILL`/OOM-killer termination) and provides an actionable warning when a checkpoint exceeds memory available on bound nodes.

**Changes:**
- Add NUMA mempolicy detection via libnuma (`numa_get_membind`) and cap “available RAM” to bound-node availability when applicable.
- Reconstruct a per-node “available” estimate from sysfs node meminfo fields and use it for both sizing and warnings.
- Add unit tests covering per-node availability arithmetic and warning emission logic.
