# [Observability] Add tool-calling inference tracing

[Upstream PR](https://github.com/vllm-project/vllm/pull/62109) · state: open · merged: False

## Original PR description



## Overview

Adds tool-calling summaries to Chat Completions and Messages inference spans, with a shared span lifecycle for tool and non-tool requests.

Builds on [the metrics PR](https://github.com/vllm-project/vllm/pull/61571) and aligns vllm.tool_calling.* attributes with [render-server tracing](https://github.com/vllm-project/vllm/pull/61683).

## Claims

- Start inference spans at frontend admission and finish after API response conversion or streaming cleanup.
- Report received tool metadata, emitted-call counts, surfaced parser failures, and interrupted streams.
- Preserve trace context and sampling without adding payload content to spans, tool metadata to headers, or changing metrics.

## Validation

- Focused serving, engine, parser, and tracing tests and changed-file pre-commit checks passed.
- Live Qwen3-0.6B CPU testing covered Chat/Messages JSON/SSE, sampling controls, injected parser failures, and real disconnects. Exported spans matched response counts, statuses, and incoming trace context.
- 3 paired non-tool performance rounds completed 720 measured requests without errors or drops. Paired-median p99 changes ranged from −2.3% to +3.0%. These short, CPU-throttled runs do not establish zero overhead or GPU performance.

## Details

Engine completion precedes final API parsing and Messages conversion. Frontend request-local ownership keeps existing inference spans open through those steps, including streaming failures and cleanup.

This overlaps early span creation in [request-lifecycle tracing](https://github.com/vllm-project/vllm/pull/44402), but adds API-finalization ownership and tool summaries without scheduler-phase spans.

Counts describe server output, not client receipt, tool execution, or upstream field preservation. Errors swallowed internally by parsers remain undetectable.
