# [Bugfix][ROCm][DSv4.1] Enter decoder replay at a PP stage that starts at the cut

[Upstream PR](https://github.com/vllm-project/vllm/pull/64051) · state: open · merged: False

## Original PR description



## Overview

On ROCm, DeepSeek-V4.1-Flash with `--pipeline-parallel-size 2` and decoder SWA bounded replay (the default) crashes on the first prefill that builds a replay batch. PP=2 starts the second stage at layer 20, the last KV source and the replay cut. `_decoder_replay_supported` accepts that split (`start_layer == cut`), but `write_kv` does not handle a stage that has no residual yet. This PR adds the same stage-entry branch that `forward()` already has.

Depends on #63617. Without it, PP>1 on this model fails earlier, in `allocate_kv_cache` (#63615).

## Claims

- Fixes `AttributeError: 'NoneType' object has no attribute 'shape'` (`write_kv` → `mhc_pre_delayed` → `_aiter_mhc_supported`) on the PP stage that starts at the replay cut. With the fix, PP=2 serves with replay on.
- Greedy logprobs with replay on match replay off at PP=2, with real weights, for a prompt longer than the 128-token window (which goes through `write_kv`) and for a short one.
- Adds a `vllm_runner` regression test to the MI355 DeepSeek-V4.1 step.

## Details

**Root cause.** With PP, a stage hands off the settled stream: stage 0 ends with `mhc_post`, and `IntermediateTensors` carry `hidden_states` and `pre_mix` but no residual. `DeepseekV4DecoderLayer.forward` handles this entry (`residual is None` and a 3-D `x` mean the stream is already posted, so it runs a pre-only `mhc_pre_delayed`). `write_kv` is the replay-only path for the first replay layer and lacked that branch, so a stage whose first layer is the cut passed `residual=None` into the seam. `_run_replay_layers` has the same assumption in its `mhc_post` call for the cut's aux hidden state (DSpark). It now uses the posted input directly when there is no residual.

**Scope.**
- Only splits where a stage starts exactly at the cut reach this path. Other splits that keep every layer after the cut on one stage already worked, and splits that don't are rejected by `_decoder_replay_supported`.
- `vllm/models/deepseek_v41/nvidia/` has the same pattern in its `write_kv`. I did not change it because I can't test it.
- `mhc_pre_delayed` treats omitted and `None` post kwargs the same way, so passing `None` keeps the call shape unchanged.

**CI.** The test needs two CDNA4 GPUs and the real checkpoint (~476 GB). Dummy weights give near-uniform logits (top-5 logprobs all ≈ −ln|V|), so greedy tokens are noise and can't be compared. The test is added to `:amd: (MI355) DeepSeek-V4.1 Mono Decode Numerics` (mi355_4, `optional`), whose `source_file_dependencies` already cover `vllm/models/deepseek_v41/amd/`. That step only uses dummy weights today, so please confirm the MI355 agents have the checkpoint cached. If they don't, I'm happy to move the test to a step that does. It loads the model twice (~4.5 min each).

**Not a duplicate.** I found no open PR or issue touching `write_kv` or PP with replay on ROCm. #63106 / #63098 / #63321 work on NVIDIA DSv4.1 PP, and #63617 fixes the separate KV-planner failure this one depends on.
