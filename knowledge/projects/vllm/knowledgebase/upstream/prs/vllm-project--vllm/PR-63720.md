# [Core][Perf] Opt-out for the Mamba prompt-tail prefill stop

[Upstream PR](https://github.com/vllm-project/vllm/pull/63720) · state: open · merged: False

## Original PR description

Draft for early review. No blocking issues.



## Overview

With prefix caching and a `--prefix-match-unit` smaller than the Mamba block size, the scheduler stops every prefill at the prompt's last prefix-match-unit boundary so that state gets cached. When the last chunk starts and ends inside one Mamba block, no internal checkpoint can cover that position, so each such prompt pays an extra forward step. This PR adds `--no-mamba-prompt-tail-checkpoint` to skip that stop. The default is unchanged.

## Claims

- Off: the prompt's last chunk runs to the end, follow-up prompts resume from the last Mamba block boundary, and no cached state is left inconsistent.
- Kimi-K3 agentic disaggregated benchmark on MI355X, flag off on the prefill instance: +0.6% total tok/s/GPU, mean TTFT 3.06 s to 2.82 s, +9% recomputed prefill tokens per request.

## Validation

- New tests in `tests/v1/core/test_mamba_align_chunk_split.py`: the opt-out cases fail without the scheduler change and pass with it.
- `tests/v1/core/test_scheduler.py`, `tests/v1/core/prefix_cache/`, `test_prefix_caching.py`, `test_mamba_align_chunk_split.py`: each file passes on its own. A combined run fails the same 19 `test_scheduler.py` cases on main and on this branch. ruff clean.
- End to end: one run per configuration, below.

<details><summary>End-to-end benchmark</summary>

Kimi-K3, agentic multi-turn trace at concurrency 48, 1 prefill + 1 decode instance on 2 nodes of 8x MI355X, TP8 + DCP8, FP8 KV cache, MoRIIO + `SimpleCPUOffloadConnector`. Prefill: `--prefix-match-unit 128`, Mamba block 1536, attention block 12288, 8192 batched tokens. vLLM ROCm nightly `81198e97` with an earlier form of this patch on the prefill instance, which turned off `mamba_partial_cache_hit` in the scheduler. This PR keeps that flag and skips only the tail stop, so this exact diff has not been benchmarked.

## Details

`_mamba_block_aligned_split` stops at `get_mamba_prefill_checkpoint_position` only when `mamba_prompt_tail_checkpoint` is set and no internal checkpoint covers the tail. The new scheduler attribute is `mamba_partial_cache_hit and cache_config.mamba_prompt_tail_checkpoint`. The checkpoint granularity still keys on `mamba_partial_cache_hit`, and `MambaManager` and the worker checkpoint logic are untouched, so scheduler, manager and worker stay in lockstep. The test stubs that mirror scheduler attributes gain the new one.
