# [Bugfix] Fix biased sampling after a grammar-rejected draft in probablistic spec decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/60690) · state: open · merged: False

## Original PR description

## Overview

Fixes #60451. This bug affects spec decode with structured outputs and `draft_sample_method="probabilistic"`. Spec decode changed the output distribution: after a draft that broke the grammar, that position was sampled from the target distribution p instead of the residual max(p − q, 0). This PR sends the first grammar-rejected draft to verification, on both the async and the sync scheduling paths.

## Claims

- Draft-model spec decode with probabilistic drafts and a grammar now keeps the target model's output distribution. The issue's chi-squared test goes from p = 1.4e-09 (FAIL) to p = 0.78 (PASS).
- Fixed on both scheduling paths: async (MRV2) and sync (MRV1 and MRV2).
- No change for greedy drafts (the default, and every ngram or suffix drafter), for `rejection_sample_method="synthetic"`, or for a grammar that has already terminated. These cases were not biased.
- One metric changes on the sync path. See Details.

## Details

**Root cause.** The scheduler checks each step's drafts against the grammar and cuts them at the first invalid draft. Both paths also removed that first invalid draft from verification:

- Async (MRV2): `get_grammar_bitmask` set `num_acceptable_drafts` to the length of the valid prefix. So `grammar_invalid_drafts` masked the first invalid draft too, and `_resample_kernel` sampled its row from p, as for a bonus token.
- Sync (MRV1 and MRV2): `update_draft_token_ids` stored only the valid prefix in `request.spec_token_ids`. So the invalid draft was never scheduled. When all valid drafts were accepted, its position became the bonus row and was sampled from p.

After a rejected draft, rejection sampling must draw from max(p − q, 0). A draw from p is correct only when reaching that position does not depend on the draft there. Here the position is drawn from p exactly when the drafted token broke the grammar, so it depends on the draft's value. That is the bias.

**Fix.** `StructuredOutputManager.grammar_bitmask` fills row i before it looks at draft i. So the row for the first invalid draft already has the real grammar mask, with p = 0 at that token. If the draft is verified like any other, verification always rejects it and the normal residual draw runs. This PR keeps the first invalid draft for verification and drops or masks only the drafts after it:

- `update_draft_token_ids` (sync) keeps the first invalid draft and sets a new `Request.num_invalid_spec_tokens` (0 or 1). `schedule()` copies it into `SchedulerOutput.num_invalid_spec_tokens`, which before was only set on the async path. It does not copy it when the budget cuts the scheduled drafts short. It drops the entry when the priority policy preempts the request in the same step.
- `get_grammar_bitmask` counts the first invalid draft in `num_acceptable_drafts` (this fixes async, MRV2). It gives the bitmask fill a copy of the drafts with -1 in the invalid slots. So the fill does not advance the grammar through a token it rejected, and it logs no `Unexpected: grammar terminated or rejected draft token` error.
- `_verifies_grammar_rejected_drafts` decides when the draft is kept. It needs `draft_sample_method="probabilistic"`, a rejection method other than `synthetic`, and a grammar that has not terminated. A greedy draft is one-hot, so the old draw from p was already exact, and keeping the draft would only cost a scheduled token. Synthetic acceptance never reads the row, so it would accept the rejected token. A terminated grammar drops drafts whatever their values are, and its rows mask nothing. Without a speculative config nothing changes; diffusion models call `update_draft_token_ids` without one.

The change is in the scheduler only. No model runner code changes, so the sync-path fix also covers MRV1. The spec-decode stats already subtract `num_invalid_spec_tokens` from the drafted count, so the kept draft is not counted as drafted.

**Metric change (sync path, probabilistic drafts, structured outputs).** `vllm:spec_decode_num_drafts` now also counts steps where the grammar rejected the very first draft, because that draft is now scheduled. The async path already counted these steps. The draft-token and accepted-token counts stay the same, but the logged mean acceptance length goes down.

**Known limitation.** When the grammar terminates inside the drafts, for example `[x, EOS, y]`, `y` is kept and verified against a permissive row. If it is accepted, the stats for that step can show one more accepted token than drafted. This happens at most once per request and does not change the output text. To tell this case apart, the grammar backend would need to report why validation stopped. In debug runs of the reproducer with `--sync`, the kept draft was accepted 0 times out of 15,000.

```python
# Speculative decoding + structured outputs: the answer distribution should
# match normal decoding, but with probabilistic drafting it does not.
import collections, math, re, sys
from vllm import LLM, SamplingParams
from vllm.sampling_params import StructuredOutputsParams

N = 4000
PROMPT = "Name a random European capital."
REGEX = r'\{"city": "(Paris|Berlin|Rome|Madrid|Vienna|Lisbon|Prague|Oslo)"\}'
SPEC = {"method": "draft_model", "model": "Qwen/Qwen3-0.6B",
        "num_speculative_tokens": 3, "draft_sample_method": "probabilistic"}
extra = {"async_scheduling": False} if "--sync" in sys.argv else {}
SEED0 = int(sys.argv[sys.argv.index("--seed-base") + 1]) * N if "--seed-base" in sys.argv else 0


def sample(spec):
    llm = LLM("Qwen/Qwen3-1.7B", speculative_config=spec, seed=0, max_model_len=1024,
              gpu_memory_utilization=0.4, enforce_eager=True, **extra)
    sps = [SamplingParams(temperature=1.0, max_tokens=32, seed=SEED0 + i,
                          structured_outputs=StructuredOutputsParams(regex=REGEX))
           for i in range(N)]
    outs = llm.chat([[{"role": "user", "content": PROMPT}]] * N, sps, use_tqdm=False,
                    chat_template_kwargs={"enable_thinking": False})
    texts = [o.outputs[0].text for o in outs]
    assert all(re.fullmatch(REGEX, t) for t in texts), "grammar-invalid output"
    return collections.Counter(re.fullmatch(REGEX, t).group(1) for t in texts)


def chi2_sf(x, k):  # P(chi2_k > x) via the regularized upper incomplete gamma
    a, x = k / 2, x / 2
    if x < a + 1:  # series for P(a, x)
        s = t = 1 / a
        for n in range(1, 500):
            t *= x / (a + n); s += t
        return 1 - s * math.exp(-x + a * math.log(x) - math.lgamma(a))
    b, c, d = x + 1 - a, 1e300, 1 / (x + 1 - a)  # continued fraction for Q(a, x)
    h = d
    for n in range(1, 500):
        an = -n * (n - a); b += 2
        d = 1 / (an * d + b); c = b + an / c; h *= d * c
    return h * math.exp(-x + a * math.log(x) - math.lgamma(a))


ref, spec = sample(None), sample(SPEC)
cats = [c for c in ref | spec if ref[c] + spec[c] >= 20]  # pool rare answers
rows = [[ref[c] for c in cats] + [N - sum(ref[c] for c in cats)],
        [spec[c] for c in cats] + [N - sum(spec[c] for c in cats)]]
stat = sum((rows[r][j] - (rows[0][j] + rows[1][j]) / 2) ** 2 / ((rows[0][j] + rows[1][j]) / 2)
           for r in range(2) for j in range(len(rows[0])) if rows[0][j] + rows[1][j])
p = chi2_sf(stat, len(cats))
print(f"{'city':8s} {'no spec':>8s} {'spec':>8s}")
for c in sorted(cats, key=lambda c: -ref[c]):
    print(f"{c:8s} {ref[c] / N:8.3f} {spec[c] / N:8.3f}")
print(f"chi2 = {stat:.1f}, df = {len(cats)}, p = {p:.2g}")
print("PASS" if p > 1e-3 else "FAIL: spec decode changed the output distribution")
```
