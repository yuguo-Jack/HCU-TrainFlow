# [Bugfix] Fix support_torch_compile positional type check off by one

[Upstream PR](https://github.com/vllm-project/vllm/pull/60214) · state: open · merged: False

## Original PR description

## Overview

Fixes #60202. `@support_torch_compile` checked each positional `__init__` argument against the previous parameter's annotation, so valid positional construction was rejected.

## Claims

- Positional arguments are checked against their own parameter's annotation.
- Arguments taken by `*args` are checked against its annotation, keyword only parameters are never matched to positional arguments.
- Parameters annotated with a `PreTrainedConfig` subclass are not checked. vLLM can pass its own config class, or a remote code config re imported under a different module path, in place of the annotated one (Transformers backend), so an `isinstance` check there rejects valid builds.
- Annotations `isinstance()` cannot evaluate (e.g. `Callable[[T], U]`) are skipped instead of raising.

## Validation

New regression tests in `tests/compile/test_decorator.py` (no GPU needed; `CompilationMode.NONE`). Run on macOS (CPU) from a source checkout:

```
$ VLLM_TARGET_DEVICE=cpu python -m pytest tests/compile/test_decorator.py -k positional_args -v
tests/compile/test_decorator.py::test_positional_args_checked_against_own_parameter PASSED
tests/compile/test_decorator.py::test_positional_args_config_not_checked PASSED
tests/compile/test_decorator.py::test_positional_args_type_mismatch_raises[positional_param] PASSED
tests/compile/test_decorator.py::test_positional_args_type_mismatch_raises[var_positional] PASSED
4 passed, 4 deselected
```

Against `main` without this fix, `test_positional_args_checked_against_own_parameter` fails with the error from #60202:

```
TypeError: 'PositionalArgsModule.__init__' received a positional argument of type 'builtin_function_or_method', but no parameter of that type was found in the method signature. Please either annotate 'PositionalArgsModule.__init__' or pass it as a keyword argument.
```

With only the off by one fix (the previous revision of this PR), `test_positional_args_config_not_checked` fails: a `Qwen2Config` is rejected for a `LlamaConfig` parameter, which is the Transformers backend case described below.

`pre-commit run --files vllm/compilation/decorators.py tests/compile/test_decorator.py` passes (ruff check/format, typos, mypy, SPDX headers, test tethering). The other tests in `test_decorator.py` need CUDA and were not run locally.

## Details

**Root cause:** `old_init` is the unbound `cls.__init__`, so `sig.parameters` starts with `self` while `args` does not; zipping them paired each argument with the preceding parameter's annotation. The fix builds one annotation per positional argument (skipping `self`, expanding `*args`, stopping at keyword only parameters) and keeps the existing check and error message.

**Compatibility:** previously the first positional argument was compared against `self` (unannotated) and never checked, so this enables a check that did not run before. Who it affects:
- Of the 163 `@support_torch_compile` classes in `vllm/` and `tests/`, 18 define an `__init__` that accepts positional arguments (the 5 that inherit `__init__` use keyword only signatures). The only in tree positional construction is Pixtral's `TransformerBlock(args)`, which passes a `VisionEncoderArgs` matching its annotation.
- The Transformers backend decorates HF model classes, which HF builds as `cls(config)`. The config object is not always an instance of the annotated class: vLLM registers its own config classes for some architectures, and remote code configs can be re imported under a different module path. @vadiklyutiy's independent fix (vadiklyutiy/vllm@3785073) showed the stricter check rejecting such builds, and I reproduced it on CPU with a vLLM registered config passed to the matching HF model class. Config typed parameters are therefore excluded from the check (`issubclass(annotation, PreTrainedConfig)`), covered by `test_positional_args_config_not_checked`.

**Not a duplicate:** this is the only PR open for #60202. @vadiklyutiy prepared an alternative on a branch (vadiklyutiy/vllm@3785073, not opened as a PR) covering the same off by one and generic annotation cases, this revision incorporates the config class case it identified.
