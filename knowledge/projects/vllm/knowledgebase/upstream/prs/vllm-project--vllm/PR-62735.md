# [ROCm][CI][Bug] Remove padding from AITER output for quantization/tes…

[Upstream PR](https://github.com/vllm-project/vllm/pull/62735) · state: closed · merged: True

## Original PR description

## Overview

When using VLLM_ROCM_USE_AITER=1 as default, 2 test cases will fail:

quantization/test_online_shared_expert_fusion.py::test_online_shared_expert_loads_bf16_weights_into_mxfp4_slot;
quantization/test_online_shared_expert_fusion.py::test_online_shared_expert_reload_compatibility.
The cause is: previously VLLM_ROCM_USE_AITER=0, so this test used Triton MoE backend, which doesn't have padding in results; now it uses AITER MoE backend, which returns results with padding. We need to remove the padding before we can compare the results.

## Claims

Now this test is able to handle possible padding in the returned results, so no matter VLLM_ROCM_USE_AITER=1 or 0, the test always finishes successfully.
