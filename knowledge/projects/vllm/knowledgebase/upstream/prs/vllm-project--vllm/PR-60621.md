# [Bugfix][Frontend] Treat empty/whitespace arguments as complete JSON in Anthropic streaming

[Upstream PR](https://github.com/vllm-project/vllm/pull/60621) · state: open · merged: False

## Original PR description

### Purpose

Fix an issue where 0-argument tool calls in `/v1/messages` streaming mode are misclassified with `stop_reason: "stop_sequence"` or `"end_turn"` instead of `"tool_use"`.

### Problem

In `vllm/entrypoints/anthropic/serving.py`, `_to_anthropic_stop_reason` determines whether a tool call is complete using:
```python
tool_complete = (tool_used and _is_json("".join(last_tool_args)))
```
When a model invokes a function that takes no parameters (0-argument tool call), the streamed arguments are empty (`""`). Because `json.loads("")` raises `json.JSONDecodeError`, `_is_json("")` returned `False`.

As a result, `tool_complete` evaluated to `False`. When the model matched a stop token (e.g. `</tool_call>`), `_to_anthropic_stop_reason` returned `("stop_sequence", "</tool_call>")` or `"end_turn"` instead of `"tool_use"`. Anthropic API clients (such as Claude Code, Aider, Cursor) require `stop_reason == "tool_use"` to trigger tool execution and would drop or fail the tool call.

### Solution

- In `_is_json`, strip whitespace and treat empty strings as valid complete JSON payloads (`True`).
- Add unit test coverage in `tests/entrypoints/anthropic/test_anthropic_messages_conversion.py` testing `_is_json` with empty/whitespace strings and verifying that 0-arg completed tool calls report `stop_reason="tool_use"`.
