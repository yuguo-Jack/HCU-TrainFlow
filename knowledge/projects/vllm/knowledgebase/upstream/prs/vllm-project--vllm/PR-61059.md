# [Kernel][Perf] Add tuned fused_moe bf16 config

[Upstream PR](https://github.com/vllm-project/vllm/pull/61059) · state: open · merged: False

## Original PR description



## Overview

Add a tuned Triton fused-MoE configuration for **NVIDIA A100-SXM4-40GB** covering the K-EXAONE-236B-A23B MoE shape at tensor parallel size 16 in bfloat16:

- `E=128` experts, `moe_intermediate_size=2048`, so `N=128` per rank at TP=16
- file: `vllm/model_executor/layers/fused_moe/configs/E=128,N=128,device_name=NVIDIA_A100-SXM4-40GB.json`

There is no A100-40GB entry for any shape today (36 A100 files exist, all `A100-SXM4-80GB`), so bf16 K-EXAONE on 16× A100-40GB falls back to the default heuristic config.

## Claims

- Fused-MoE kernel time drops at every batch size M in {1 … 4096}; see the table below.
- End to end (bf16, TP16, MTP, prefix caching, `--max-num-batched-tokens 4096`): output throughput +49% at concurrency 16 and +15% at concurrency 32, with single-stream latency unchanged.
- Configuration-only change: no model code or numerics are touched. gsm8k accuracy and MTP acceptance are unchanged.

## Validation

**Tuning** (16× A100-SXM4-40GB host, vLLM main @ c41b2639e2, Triton 3.7.1, Ray over 8 GPUs):

```bash
python3 benchmarks/kernels/benchmark_moe.py --model LGAI-EXAONE/K-EXAONE-236B-A23B \
  --tp-size 16 --dtype auto --tune --batch-size 1 2 4 8 16 32 64 128 256 512 1024 2048 4096
```

**Kernel time** (`benchmark_moe.py` benchmark mode, one A100-40GB, bf16, TP=16 shape; default = file absent):

| M (tokens) | default (µs) | tuned (µs) | change |
|---:|---:|---:|---:|
| 1 | 71.65 | 62.91 | -12.2% |
| 2 | 98.36 | 93.73 | -4.7% |
| 4 | 146.36 | 128.84 | -12.0% |
| 8 | 226.62 | 210.34 | -7.2% |
| 16 | 348.89 | 311.62 | -10.7% |
| 32 | 468.12 | 413.83 | -11.6% |
| 64 | 492.68 | 462.95 | -6.0% |
| 128 | 526.97 | 485.47 | -7.9% |
| 256 | 568.08 | 516.27 | -9.1% |
| 512 | 615.84 | 599.85 | -2.6% |
| 1024 | 880.61 | 723.03 | -17.9% |
| 2048 | 1255.63 | 1044.73 | -16.8% |
| 4096 | 2026.12 | 1669.79 | -17.6% |

The tuned config wins at all 13 batch sizes; the sum of kernel times drops from 7726 µs to 6723 µs (−13.0%), median change −9.1%.

**End to end** (`vllm serve` bf16 TP=16, `--speculative-config '{"method":"mtp","num_speculative_tokens":1}'`, prefix caching on, `--max-num-batched-tokens 4096`; `vllm bench serve --dataset-name random --random-input-len 1024 --random-output-len 512 --ignore-eos`):

| | default config | tuned config |
|---|---|---|
| conc 1: TPOT | 8.53 ms | 8.61 ms |
| conc 16: output tok/s | 512 | **763** (+49%) |
| conc 32: output tok/s | 1144 | **1310** (+15%) |
| single stream, real prompts (gsm8k, greedy) | 118 tok/s | 120 tok/s |
| gsm8k-200 accuracy / MTP acceptance | 0.92 / 0.917 | 0.92 / 0.895–0.917 (run noise) |

- `jq empty` on the JSON passes; `pre-commit` passes.
- The same procedure for the TP=8 shape (`N=256`) is only relevant to int8 on 40GB (bf16 does not fit at TP=8) and will follow in a separate PR together with `int8_w8a8` support in `benchmark_moe.py`.

## Details

The config was produced with the standard tuning script over the batch sizes above (the small sizes 1/2/4 were tuned in a second pass and merged, since decode steps with MTP run at M ≤ 8 and the first pass had left them on the M=8 entry). Keys follow the existing A100-80GB files.

Duplicate-work check: no open PR touches A100-40GB configs or this shape (searched `E=128,N=128` and `A100-SXM4-40GB` in open PRs).
