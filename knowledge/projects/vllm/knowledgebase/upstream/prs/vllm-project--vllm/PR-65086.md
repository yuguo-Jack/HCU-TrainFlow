## Overview

Resolves the open `# TODO` at line 1002 of `vllm/v1/core/single_type_kv_cache_manager.py` by replacing the $O(N)$ backwards linear block scan with a stride jump search ($O(N/W + W)$). The algorithm is formally verified in Lean 4 to guarantee soundness, bounds safety, and prefix fallback correctness, fixing the block table corruption that stalled prior attempts (e.g. PR #63798).

## Details

### Motivation
In vLLM V1 (`single_type_kv_cache_manager.py`), sliding window attention models requires locating the rightmost contiguous run of at least $W$ (`sliding_window_contiguous_blocks`) cached blocks. 

Currently, upstream executes an $O(N)$ linear loop scanning backwards block by block from `max_num_blocks - 1` down to 0:
```python
# Upstream baseline (lines 1016-1037)
for i in range(max_num_blocks - 1, -1, -1):
    if cached_block := block_pool.get_cached_block(block_hashes[i], ...):
        ...
```
At 128K context (8,192 blocks), this executes 8,192 sequential Python hash lookups per request. When a batch of 64 requests arrives, the single-threaded CPU scheduler spends hundreds of milliseconds running Python dictionary lookups, leaving the GPU idle.

The vLLM maintainers explicitly noted this bottleneck at lines 1002–1006:
> `# TODO: reduce i by sliding_window_contiguous_blocks when cache miss, to optimize the time complexity from O(max_num_blocks) to O(max_num_blocks / sliding_window_contiguous_blocks + sliding_window_contiguous_blocks)`

### Algorithm & Soundness
For a sliding window of length $W$ ending at $e$ (window range $[e - W, e)$):
1. **Anchor Probe**: Probe index $p = e - W$. If block $p$ is a cache miss, any window of length $W$ ending in $[e - W + 1, e]$ must contain index $p$. Because block $p$ is missing, no such window can be valid. Therefore, candidate end $e$ safely jumps to $e \leftarrow e - W$, skipping $W$ checks in a single lookup.
2. **Inner Probe**: If anchor $p$ hits, probe the remaining blocks $k \in [e - 1, \dots, p + 1]$ from right to left. If a miss occurs at index $k$, all candidate windows containing $k$ are invalid, so $e$ safely jumps to $e \leftarrow k$.
3. **Prefix Fallback**: If $e < W$ with no match, scan forward from index 0 to find the contiguous prefix run (at most $W - 1$ lookups). If block 0 misses, terminate in 1 lookup.

This algorithm is formally verified in Lean 4 (`strideSearch_sound`, `strideSearch_boundary_safety`, `prefixFallback_correct`).
