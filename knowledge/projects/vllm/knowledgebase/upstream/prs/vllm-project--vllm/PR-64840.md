# [Bugfix] Size the default GDN recurrent beta by value heads

[Upstream PR](https://github.com/vllm-project/vllm/pull/64840) · state: open · merged: False

## Original PR description



## Overview

`fused_recurrent_gated_delta_rule` builds its default `beta` from `q` (`[B, T, H]`), but the kernel reads `beta` per value head. With grouped value heads (`HV > H`, as in Qwen3.5/Qwen3-Next) and `beta=None`, it reads past the end of the tensor. This builds the default from `v` (`[B, T, HV]`) in the vendored FLA op and in the two GLM-5-Next copies of it. Same fix as upstream fla-org/flash-linear-attention#1610 (Comba, gated Oja, preconditioned GDN, merged) and fla-org/flash-linear-attention#1618 (this GDN op, open).

## Claims

- `beta=None` with `HV > H` now gives the same output and state as an explicit all-ones `beta`. Before, 66% of the output elements and 33% of the state elements differed, depending on whatever memory followed the default tensor.
- No serving path changes: every vLLM caller passes `beta` explicitly today, so this only affects direct callers of the op (and any future caller that relies on the default).

## Validation

H200 NVL, `vllm/vllm-openai:nightly` with this branch's files on `PYTHONPATH`. The branch has since been rebased onto main `17550580e`; the three changed ops and the test file are unchanged upstream in between.

`pytest tests/kernels/fla/test_fused_recurrent_packed_decode.py`:

| | result |
|---|---|
| without the fix | 2 failed (the new test, both copies), 16 passed. `Mismatched elements: 758 / 1152 (65.8%)` for the output, `382 / 1152 (33.2%)` for the state |
| with the fix | 18 passed |

The new test runs one decode step with `H = 2`, `HV = 6` through the serving-style call (state pool + `ssm_state_indices`, `inplace_final_state=True`) twice, with `beta=None` and with `torch.ones(B, T, HV)`, and requires bit-identical outputs and states. It covers `vllm.third_party.flash_linear_attention.ops.fused_recurrent` and the NVIDIA GLM-5-Next copy; the AMD copy has the identical one-line change and is not run here (no ROCm GPU).

## Details

Root cause: the kernel indexes `beta` as `beta + bos * HV + i_hv` (or `(bos * HV + i_hv) * V` when head-wise), so it needs `HV` entries per token. `torch.ones_like(q[..., 0])` has `H`. The upstream FLA function had the same default; FLA fixed the other recurrent ops in fla-org/flash-linear-attention#1610; the GDN one is fla-org/flash-linear-attention#1618.
