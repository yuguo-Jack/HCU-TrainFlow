# [Model] Support Cloudflare/clef-omni on /v1/systemone

[Upstream PR](https://github.com/vllm-project/vllm/pull/61064) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Serve [`Cloudflare/clef-omni`](https://huggingface.co/Cloudflare/clef-omni) on `/v1/systemone`. Clef-Omni is Qwen3-Omni's thinker with a joint schema head that scores every option of every question in one forward pass; vLLM runs it as a pooling model, `ClefOmniForJointSchema`.

```bash
vllm serve Cloudflare/clef-omni
```

## Claims

- `vllm serve Cloudflare/clef-omni` answers `/v1/systemone` with the same answers as the checkpoint's own `joint_schema_model.py`, for text and JSON states and all three question types.
- One request is one forward pass: the prompt is prefilled once for all its questions.
- `images`, `audio` and `videos` (URLs or data URLs) are accepted on `/v1/systemone` for models that take them; other models return 400.

## Validation

**Prompt parity (CPU).** For 5 records (JSON/text/unicode states, choice/noul/score, empty instructions, state truncation), the prompt token ids and every question/option span equal `encode_record`'s. For image, audio, silent video, video with soundtrack, and image+audio+video, the expanded media tokens equal the reference processor's.

**Head parity (CPU, fp32, random weights).** The batched pooler matches a per-question port of the reference head to 7e-7; this is the CI test.

**Answers against the reference (one GB200, bf16).** Reference: the checkpoint's `load_release_model` + `encode_record` on transformers 5.18. 11 requests, sent once sequentially and 4 times concurrently (55 requests): 0 errors, every pick matches, input token counts identical.

| Request | Max prob. gap |
|---|---|
| Invoice JSON, choice + noul | 0.0004 |
| Ticket text, choice + score + noul | 0.009 |
| JSON state, 4 questions | 0.011 |
| French/Japanese, 4-way language choice (0.51/0.42 split) | 0.047 |
| Arithmetic, choice + noul + 10-level score | 0.017 |
| 39k-token log (chunked prefill) | 0.006 |
| Image, 3 questions | 0.001 |
| Audio, 3 questions | 0.003 |
| Silent video, 2 questions | 0.034 |
| Video with soundtrack, 2 questions | 0.049 |
| Image + audio + video, 3 questions | 0.018 |

Sequential and concurrent answers agree to 7e-4. The largest gaps are on split distributions; the reference itself moves by 0.028 on the language question between bf16 and fp32, and an fp32 run of both sides leaves a 0.03 gap, so it is not only bf16 rounding in vLLM.

**Tests.**

```bash
pytest tests/models/multimodal/pooling/test_clef_omni.py \
  tests/entrypoints/generate/structured_decisions \
  tests/models/multimodal/processing/test_qwen3_omni.py \
  "tests/models/test_initialization.py::test_can_initialize_large_subset[ClefOmniForJointSchema]"
```

All pass on GB200 (structured decisions e2e on Qwen/Qwen3-0.6B included). No CI test loads the 30B checkpoint; parity above was run by hand.

## Details

- **Selection.** The checkpoint keeps Qwen3-Omni's `config.json`, so `get_config` switches `Qwen3OmniMoeForConditionalGeneration` to `ClefOmniForJointSchema` when the repo has `joint_head_config.json`. `--hf-overrides` still wins.
- **Model.** The thinker unchanged; the head runs in a `token_classify` pooler on the whole prompt's final hidden states, with `AllPool` for chunked prefill. The schema (question types, question/option spans, option counts) travels in `PoolingParams.extra_kwargs`. Spans count from the end of the prompt, so media expansion before the state does not move them. The head reuses `nn.MultiheadAttention`/`nn.TransformerDecoderLayer` so the checkpoint's weights load as is; `joint_head.safetensors` is outside the shard index and is loaded in `load_weights`. The pooler returns an empty output instead of raising on a missing or malformed schema.
- **Endpoint.** `JointSchemaStrategy` builds the prompt exactly as `encode_record` does (each piece tokenized on its own), sends one pooling request, and maps option probabilities back to request order. `label_mass` is 1 and `usage.input_tokens` counts the prompt once. Read strategies now declare the engine task they run as (`generate`, or `token_classify` for Clef) and `/v1/systemone` is set up once for every server, so a model gets the endpoint exactly when its architecture has a strategy for a task it serves. Strategies may also render the state themselves (Clef uses compact JSON with sorted keys).
- **Media.** Fetched through `MediaConnector` (allowed domains/paths, download cap). Audio and video are decoded as the reference does (PyAV, 16 kHz mono; frames at 2 fps, ≤ 256·32·32 px), with the audio duration/size limits and a 768-frame cap. A video's soundtrack is heard when every video has one.
- **Qwen3-Omni fix.** With `use_audio_in_video`, audio/video tokens were interleaved with `second_per_grid_ts` from the request kwargs (default 2.0) while the processor and the mrope positions used the processed value; with `fps=2` the token order differed from HF. It now uses the processed value. Covered by `test_audio_in_video_follows_requested_fps`.
- **Limitations.** Request-level `instructions` returns 400 (fixed prompt); `chat_template_kwargs` has no effect. Audio clips together with videos that have soundtracks return 400. A choice is capped at 26 options and a score at 10 levels, like other strategies. Validated on MRV2, TP=1.
- **Duplicate check.** Open PR and issue searches for Clef-Omni found nothing.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Convert decoder failures into bad-media errors**

When `/v1/systemone` receives malformed or unsupported audio (including a bad video soundtrack), `av.open` or decoding can raise `av.error.FFmpegError`, which is not a `ValueError`. `_render_media` catches only `ValueError`, and the generic exception handler classifies other exceptions as 500; the standard `AudioMediaIO` explicitly converts this PyAV exception. Convert decoder errors here into a request error so client-controlled bad media receives a 400 instead of an internal-server response.
