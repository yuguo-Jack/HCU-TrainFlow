## Original PR description

## Purpose

Add the owning-repo serving recipe for **autotrust/JEV-27B-VL** at `recipes/models/autotrust/JEV-27B-VL.yaml`.

`recipes/README.md` says model recipes served by vLLM live in this repository under `recipes/models/<hf_org>/<hf_repo>.yaml`, not in the renderer copy. This PR is that owning-repo file. It replaces/supersedes the YAML in [vllm-project/recipes#1193](https://github.com/vllm-project/recipes/pull/1193) (that PR also touches `src/lib/providers.js`, which stays in the recipes renderer repo and is not edited here).

## Recipe

- Hugging Face: https://huggingface.co/autotrust/JEV-27B-VL
- ModelScope: https://modelscope.cn/models/autotrust/JEV-27B-VL
- ModelScope mirror listed on the card: https://www.modelscope.ai/models/AutoTrust-Labs/JEV-27B-VL
- `model.min_vllm_version`: **0.32.0** (`Qwen3_5ForConditionalGeneration` registration). Earlier releases are not supported.
- LoRA module **`jev-decision`** is a base arg (`--enable-lora`, `--max-lora-rank 32`, `--lora-modules jev-decision=JEV-27B-VL/adapter_vllm`), together with `--mamba-cache-mode align`, `--limit-mm-per-prompt '{"image": 8}'`, `--max-num-seqs 8`, `--logprobs-mode processed_logprobs`, and `--trust-request-chat-template`.

## Test Plan

Schema check of the new YAML against the published recipe schema (`https://recipes.vllm.ai/recipe.schema.json`). No model-output or accuracy eval: this change only adds a recipe file.

## Test Result

`ajv-cli` reported the recipe JSON valid. Required flags above are present in `model.base_args`.
