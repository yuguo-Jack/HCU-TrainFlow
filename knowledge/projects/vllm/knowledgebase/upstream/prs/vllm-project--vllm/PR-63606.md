# [Bugfix][Frontend] Use the default template of multi-template processors

[Upstream PR](https://github.com/vllm-project/vllm/pull/63606) · state: open · merged: False

## Original PR description

## Overview

Processors that ship several chat templates (e.g. `Qwen/Qwen3-VL-Reranker-2B`, `ModernVBERT/colmodernvbert-merged`) expose `chat_template` as a `{name: template}` dict. `_try_get_processor_chat_template` returned it as is, so chat rendering fails with `TypeError: unhashable type: 'dict'`. This PR uses the `"default"` entry and carries forward #46801 (@shun-cohere).

## Claims

- Chat-style requests to these models return 200 instead of 400 `unhashable type: 'dict'`. They use the `"default"` template, as `ProcessorMixin.apply_chat_template` does (content format `openai`, not `string`).
- Other processors are unchanged. A dict without `"default"` raises a `TypeError` in the existing `try` (logged at debug level), so resolution falls through to the tokenizer template.

## Details

- Root cause: transformers keeps `processor.chat_template` as a dict when a repo has `additional_chat_templates/*.jinja`. Without tools, `resolve_chat_template` returns it, and the `lru_cache` of `_cached_resolve_chat_template_kwargs` raises.
- On main the servers still start (the warmup only logs the `TypeError`; since #64020 the Anthropic inline-system probe no longer aborts on the dict), but chat-style requests fail. With this PR the probe checks the real template.
- No model eval: only requests that failed on main change; the prompt equals `ProcessorMixin.apply_chat_template`'s output for both models.
- Not a duplicate: PR searches (see logs) find no fix besides #46801 (stale-closed, no review). None of the 9 other open PRs touching `vllm/renderers/hf.py` (updated within 10 days) changes this function.
- AI assistance (Claude) was used; the submitter reviewed every changed line and ran the tests above.

Here is an e2e repro with `vllm serve` and a late-interaction model from the docs. On main, chat-style (`messages`) requests to it fail with a 400.

`ModernVBERT/colmodernvbert-merged` (listed in `docs/models/pooling_models/token_embed.md`, served in `examples/pooling/score/colmodernvbert_rerank_online.py`) ships `additional_chat_templates/sentence_transformers.jinja` next to `chat_template.jinja`, so its processor's `chat_template` is a dict with the keys `['default', 'sentence_transformers']`.

```bash
vllm serve ModernVBERT/colmodernvbert-merged
```

On main, the content format falls back to `'string'` and the chat template warmup fails. Warmup errors are only logged, so the server still starts:

```
INFO [hf.py:647] Detected the chat template content format to be 'string'.
WARNING [base.py:380] Chat template warmup failed
  File "vllm/renderers/hf.py", line 736, in resolve_chat_template_kwargs
    template_vars = _cached_resolve_chat_template_kwargs(chat_template)
TypeError: unhashable type: 'dict'
```

Chat-style Pooling requests then fail. For the Pooling API, `messages` is how the docs send image inputs (ColQwen3 section of `specific_models.md`):

```bash
curl -s localhost:8000/pooling -H 'Content-Type: application/json' -d '{
  "model": "ModernVBERT/colmodernvbert-merged",
  "task": "token_embed",
  "messages": [{"role": "user", "content": [
    {"type": "image_url", "image_url": {"url": "data:image/png;base64,<BASE64>"}},
    {"type": "text", "text": "Describe the image."}]}]
}'
```

| request | main | this PR |
| --- | --- | --- |
| `/pooling` `messages`, image + text | 400 `unhashable type: 'dict'` | 200, 82 token vectors x 128 |
| `/pooling` `messages`, text only | 400 `unhashable type: 'dict'` | 200, 17 token vectors x 128 |
| `/rerank`, plain text | 200 | 200, same scores (6.1145, 3.4882) |

With this PR the warmup succeeds and the content format resolves to `'openai'`.

Other checkpoints from the docs load with the same kind of dict:
- `athrael-soju/colqwen3.5-4.5B-v3`, `vultr/VultronRetrieverPrime-Qwen3.5-8B` and `athrael-soju/ColUltraVBERT`: `['default', 'sentence_transformers']`.
- `Qwen/Qwen3-VL-Reranker-2B` and `-8B`: `['default', 'reranker']`.

On scope: these checkpoints' Sentence Transformers config (`processing_kwargs.chat_template`) selects the `sentence_transformers` template, and vLLM reads that setting only for CrossEncoder scoring. This PR doesn't change that. With it, these requests use the `default` template instead of failing, as `ProcessorMixin.apply_chat_template` does when no template is named.

Setup:
- CPU-only Linux VM, vLLM built from source at fce64bc5c. `_try_get_processor_chat_template` is unchanged on current main.
- transformers 5.20.2.
- Only `vllm/renderers/hf.py` differed between the two runs.
- I added `--skip-mm-profiling` to keep CPU startup short. The chat template is resolved in the API server process, so that flag doesn't affect this path.

If a regression test on this path would be more useful than the render-server one, I can add a `RemoteOpenAIServer` test with `/pooling` `messages` on this model (about 1 GB of weights).
