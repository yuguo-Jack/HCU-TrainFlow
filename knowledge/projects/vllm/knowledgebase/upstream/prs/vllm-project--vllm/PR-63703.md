# [Bugfix][ROCm] Force Triton MXFP4 for the 96-row ASM scale tile

[Upstream PR](https://github.com/vllm-project/vllm/pull/63703) · state: closed · merged: False

## Original PR description

## Overview

Keep the Qwen3.8-27B TP1 GDN `in_proj_ba` MXFP4 projection on Triton. Its 96 scale rows are legal for the ASM swizzle, and ASM is numerically wrong for M<=64. https://github.com/ROCm/aiter/issues/5931

## Claims

- A weight scale with 96 rows no longer takes the AITER ASM FP4 GEMM.
- Other layout-legal shapes, including 128 scale rows, still use ASM when AITER reports them as tuned.

## Validation

- `tests/kernels/quantization/test_rocm_mxfp4.py::test_asm_fp4_scale_swizzle_supported_shape_rules` now expects `(96, 8)` to be rejected. That test is gfx950-only and was not run on this machine.
- The same `{96}` rule is what the measured Qwen3.8-27B MXFP4 TP1 image used.

## Details

`_asm_fp4_scale_swizzle_supported` still requires scale rows divisible by 32 and scale columns divisible by 8. It additionally rejects `_ASM_FP4_FORCE_TRITON_SCALE_ROWS = {96}`.

https://github.com/vllm-project/vllm/pull/58139 is the broader form of this bugfix: it rejects every scale-row count below 160. This pull request keeps the measured 96-row exception only.
