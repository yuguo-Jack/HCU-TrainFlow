# [Attention] Add CuTe DSL backend selection for MLA context prefill

[Upstream PR](https://github.com/vllm-project/vllm/pull/62069) · state: closed · merged: True

## Original PR description

## Overview

Add an opt-in CuTe DSL kernel for MLA attention over cached context. Default dispatch and new-token prefill remain unchanged.

```bash
--attention-config '{"mla_prefill_backend":"TRTLLM_RAGGED","use_prefill_query_quantization":true,"trtllm_ragged_backend":"cute-dsl"}'
```

For Kimi K3, this requires FP8 KV cache.

## Claims

- Enable CuTe context prefill without changing the default TRTLLM path.
- Align packed indptrs on the CPU, avoiding additional GPU copies.
- Reject unsupported dimensions and dtypes before kernel launch.

This is separate from #56784, which adds CuTe decode selection.

## Validation

Validated on GB300 with FlashInfer 0.7.1: **76 passed, 49 skipped** across kernel correctness, chunk metadata, and prefill selector/registry tests.

```bash
.venv/bin/python -m pytest tests/v1/attention/test_mla_backends.py \
  -k test_chunked_context_backend_correctness
.venv/bin/python -m pytest tests/v1/attention/test_mla_context_chunks.py \
  tests/v1/attention/test_mla_prefill_registry.py \
  tests/v1/attention/test_mla_prefill_selector.py
```

CUDA-graph microbenchmarks with Kimi's 12 local heads, FP8 Q/K/V, BF16 output, and packed V:

| Query tokens | Cached-context tokens | TRTLLM µs | CuTe µs | Speedup |
|---:|---:|---:|---:|---:|
| 1,024 | 8,192 | 71.8 | 56.2 | 1.28× |
| 8,192 | 8,192 | 221.0 | 184.8 | 1.20× |
| 16,384 | 8,192 | 467.2 | 369.8 | 1.26× |

Times are medians of three CUDA-graph timing rounds. These measure context attention, not whole-model throughput.

### End-to-end GSM8K

Validated on 8 GB300 GPUs (two 4-GPU nodes)

Kimi K3 MXFP4 target weights, DSpark draft weights, FlashInfer Python/cubin 0.7.1 and JIT-cache 0.7.1+cu130, TokenSpeed MLA 2.0.3, and PyTorch 2.14.0+cu132.

**`max-num-batched-tokens=256` forces chunked prefill for the GSM8K prompts.** A short trace of a cold 775-token GSM8K prompt before evaluation confirmed **72 CuTe context-attention kernel launches on rank 0** (`kernel_cutlass_kernel_cuteblackwellkernelattentionfmhafmhaBlackwellFusedMultiHeadAttentionForward…`). Server configuration (run on each node; `NODE_RANK` is 0 or 1, and rank 1 also passes `--headless`). `TARGET_MODEL` and `DRAFT_MODEL` point to the local target/draft checkpoints:

```bash
export VLLM_USE_V2_MODEL_RUNNER=1
export VLLM_USE_RUST_FRONTEND=0
export VLLM_ALLREDUCE_USE_FLASHINFER=1
export OMP_NUM_THREADS=8

vllm serve "$TARGET_MODEL" \
  --served-model-name moonshotai/Kimi-K3 \
  --host 0.0.0.0 --port 8000 \
  --tensor-parallel-size 8 --decode-context-parallel-size 8 \
  --distributed-executor-backend mp \
  --nnodes 2 --node-rank "$NODE_RANK" \
  --master-addr "$MASTER_ADDR" --master-port 29547 \
  --dcp-comm-backend a2a \
  --trust-remote-code --language-model-only \
  --load-format fastsafetensors --gpu-memory-utilization 0.90 \
  --max-model-len 8192 --max-num-seqs 32 --max-num-batched-tokens 256 \
  --enable-chunked-prefill \
  --max-cudagraph-capture-size 32 --no-enable-flashinfer-autotune \
  --profiler-config "{\"profiler\":\"torch\",\"torch_profiler_dir\":\"$TRACE_DIR\",\"torch_profiler_with_stack\":false}" \
  --enable-prefix-caching --prefix-match-unit 128 \
  --enable-prompt-tokens-details \
  --kv-cache-dtype fp8 --mamba-ssm-cache-dtype bfloat16 \
  --attention-backend TOKENSPEED_MLA \
  --attention-config '{"mla_prefill_backend":"TRTLLM_RAGGED","use_prefill_query_quantization":true,"trtllm_ragged_backend":"cute-dsl"}' \
  --speculative-config "{\"model\":\"$DRAFT_MODEL\",\"attention_backend\":\"TOKENSPEED_MLA\",\"method\":\"dspark\",\"num_speculative_tokens\":4,\"draft_sample_method\":\"greedy\",\"rejection_sample_method\":\"block\"}"
```

No online weight quantization, EP/SP, Mooncake, Dynamo, or synthetic speculative acceptance was enabled. Decode uses TokenSpeed MLA; CuTe is selected only for cached-context prefill. A cached-prefix extension smoke test passed before evaluation.

```bash
lm_eval --model local-completions \

  --tasks gsm8k --num_fewshot 5 --gen_kwargs temperature=0 \
  --seed 42 --log_samples --output_path "$OUTPUT_DIR/gsm8k"
```

## Details

- CuTe requires FP8 queries for head dimension 192 and does not support dimension 256. Runtime validation and test skips share one compatibility helper until FlashInfer exposes a public API.
- CuTe requires packed V. Generic MLA's strided V is copied only when CuTe is selected; already-contiguous V incurs no copy.
- That copy can erase or reverse the speedup on small workloads, so CuTe remains opt-in.
