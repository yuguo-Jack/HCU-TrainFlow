# [Perf][Frontend] Append Responses streaming text in place

[Upstream PR](https://github.com/vllm-project/vllm/pull/65037) · state: open · merged: False

## Original PR description



## Overview

Responses API streaming appends each delta to `SimpleContext._accumulated_text` and `SimpleStreamingState.accumulated_text` with `+=` on an attribute, which CPython cannot do in place, so every token copies the whole text so far. This moves the text into a local for the append, the same fix as #62262 in the detokenizer.

## Claims

- Frontend CPU per streamed token: −49% at 8k and 16k output tokens, −38% for reasoning+content at 8k, −17% at 2k; 256 tokens unchanged.
- Per-token cost no longer grows with output length (~47 ms less event-loop CPU per 8k-token stream, ~95 ms per 16k).
- SSE output and `final_output` are byte-identical.
- Reach: every streaming `/v1/responses` request on non-Harmony models. The Rust frontend has no `/v1/responses` route, so this is the only implementation.

## Validation

CPU-only A/B, 15 alternated rounds, fresh process per run, real `responses_stream_generator` + SSE framing with Qwen3 tokenizer pieces; macOS arm64, Python 3.12.7, load median 2.6:

| output tokens | main µs/token | PR µs/token | delta |
|---|---|---|---|
| 256 (control) | 6.91 | 6.90 | ~ (p=0.70) |
| 2048 | 7.28 | 6.04 | −17.0% |
| 8192 | 11.58 | 5.90 | −49.1% |
| 16384 | 11.66 | 5.89 | −49.5% |
| 8192 reasoning+content | 7.78 | 4.80 | −38.3% |

Byte identity: SSE sha256 (item ids normalized) and `final_output` text match main for content, reasoning+content, custom-tool and function-tool streams at 256 / 2048 / 8192 tokens (12/12).

New `test_failed_text_append_keeps_accumulated_text` fails if the `finally` is removed. Evals: not applicable, output is byte-identical.

Not a duplicate: no open PR touches `accumulated_text` (`--search "responses accumulated_text"`, `"responses streaming quadratic"`, `--state all "accumulated_text"`). #64674 (merged) made custom-tool input decoding incremental and kept the `+=`. Open PRs on `streaming_events.py` (#55371, #52418, #58018, #63238) do not modify these lines.

## Details

The attribute is cleared before the append so the local holds the only reference, which lets CPython resize the string in place; `finally` restores it. The attribute is a plain `str` with the same value after every call, so all readers (`final_output`, done events, per-token custom-tool prefix decoding) are unchanged, and a failed append leaves the streamed text in place as on main. There is no `await` between clearing and restoring. Linux not measured; glibc realloc is cheaper than macOS, so the absolute saving is likely smaller there.

AI assistance (Claude Opus 5.5) was used to find this target while profiling the Responses API, draft the patch, and build the benchmark and identity check. I reviewed every line, re-ran the tests and benchmarks above myself, and can answer for the change.
