# [CI] Select (H200 MIG 35GB) Language Models (Hybrid) and (L4) Granite Compatibility by whole units

[Upstream PR](https://github.com/vllm-project/vllm/pull/58771) · state: open · merged: False

## Original PR description

## What

The `Language Models (Hybrid)` and `Granite Language Model Compatibility` jobs (and their mirrors) stop selecting tests out of `generation/` with `-m hybrid_model` / `-k 'granite-4.0-tiny-preview'`, and run whole coverage units instead. This is filter removal only: same tests, same markers, same replica counts, no sharding change.

## Old

```text
tests/models/language/generation/
├── test_hybrid.py          # Hybrid: -m hybrid_model -k 'not granite-4.0-tiny-preview'
│                           # Granite: -m hybrid_model -k 'granite-4.0-tiny-preview' (1 case of test_models)
└── test_gdn_sleep_wake.py  # Hybrid (via -m hybrid_model)
```

## New

```text
tests/models/language/generation/
├── test_granite_4_hybrid.py   # test_models[granite-4.0-tiny-preview], moved out of test_hybrid.py
└── hybrid/
    ├── __init__.py
    ├── _hybrid_models.py      # test_models body + MAX_NUM_SEQS/ATTN_BACKEND; not collected
    ├── test_hybrid.py         # moved; Granite dropped from HYBRID_MODELS, test_models calls the helper
    └── test_gdn_sleep_wake.py # moved unchanged
```

| Job (key) | Old command target | New command target |
|---|---|---|
| Hybrid Shard %N (`language-models-tests-hybrid`, 2 replicas) + mirror + legacy `test-amd.yaml` | `generation -m hybrid_model -k 'not granite-4.0-tiny-preview'` + shard flags | `generation/hybrid` + shard flags |
| Granite Compatibility (`language-models-tests-granite-l4-compatibility`) + mirror + legacy `test-amd.yaml` | `generation -m hybrid_model -k 'granite-4.0-tiny-preview'` | `generation/test_granite_4_hybrid.py` |

## Notes

- **Coverage-neutral.** Static AST check: all 16 test functions and their decorators are unchanged except `test_models`, whose body moved verbatim into the helper; its 8 cases become 7 in `hybrid/test_hybrid.py` + 1 in `test_granite_4_hybrid.py`. Both files keep `hybrid_model`, so Extended Generation (`-m '(not core_model) and (not hybrid_model)'`), Standard, CPU and 2-GPU commands, which all discover `generation/` recursively, select exactly what they did before. `source_file_dependencies` are untouched; CODEOWNERS follows the move.
- **Hash assignment shifts.** The node IDs gain a `hybrid/` prefix, so `pytest-shard` places cases differently between the two replicas. Predicted from three recent `main` runs below: the heavy side moves from replica 2 to replica 1 with its slowest time within ±2 min.
- **Replaces drafts #56291, #56292, #56293, #56294 and #56313**, which are being closed as stale. Core/extended language filters and the coverage guard follow as their own PRs; sharding the still-slow Hybrid job is a separate Phase 2 PR sized from measured times.
- AI assistance was used (Claude Code). Checks run locally: static equivalence script, `ruff check`/`ruff format --check`, `py_compile`, `yaml.safe_load` on both pipeline files. `pytest --collect-only` and the GPU run come from the scoped validation build.
