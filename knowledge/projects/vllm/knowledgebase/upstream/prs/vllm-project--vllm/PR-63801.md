# [Perf][HiSparse] Prefetch speculative groups with bounded copy workers

[Upstream PR](https://github.com/vllm-project/vllm/pull/63801) · state: closed · merged: True

## Original PR description

## Overview

Extend HiSparse's existing shared-index group prefetch to multi-token speculative verification, including MTP, and bound the CUDA compact-gather launch as verification expands the batch.

Related: #60072. This is separate from the platform-interface PR #62592. It composes with #60103; slot-invalidation fusion, padding-mask fusion and the all-resident resolver optimization remain in that PR and are not duplicated here.

## Claims

- Eligible pure-decode verification batches can stage follower layers' historical KV on the existing group copy stream, with a separate completion event for each layer.
- Prefetch eligibility is separate from the single-token resident-write and host-mirror policy. Mixed/prefill batches keep per-layer staging.
- Compact gather launches at most 64 thread blocks. Additional rows are processed by the existing workers; batches of at most 64 rows retain their column parallelism.
- Add native payload/graph regression cases and a reusable gather benchmark. Scoped H200 serving and profiling results are reported below; no model accuracy or acceptance improvement is claimed.

## Performance results

Measured on 8 x NVIDIA H200 with GLM-5.2-FP8, TP=8, MTP=3 and the V2 model runner. Both arms were rebuilt from frozen main `a1cfd2c1b584c4ac197db9cc9ac84a6d973d39df`; the candidate adds this PR's changes at `bb84fb5e976f941e9e2b8586f79930be64408a74`. Source/native-library pairs were checked. The table uses the original PR implementation.

Runtime: Python 3.12, PyTorch 2.14.0+cu130, CUDA 13.0, driver 595.58.03; EvalScope 1.14.1 for unprofiled serving measurements.

- Workload: 65,536 input tokens, forced 4,096 or 8,192 output tokens, concurrency 32, 32 requests per case; temperature 0, ignore EOS. Frozen GSM8K-derived long prompts are a synthetic performance workload, not a natural long-reasoning accuracy evaluation. Request bodies match between arms and actual input/output lengths were audited.
- Both arms: `kv_cache_dtype=fp8_ds_mla`, 32 GiB GPU KV cache per rank, 128 GiB shared host pool, `max_model_len=73728`, `max_num_batched_tokens=8192`, `max_num_seqs=32`, prefix caching disabled, seed 42; FLASHMLA_SPARSE / DEEPSEEK_V32_INDEXER.
- Each initial process ran a separate C32 64K/128 warmup (excluded), then 4K output, 8K output and an 8K repeat. A separate PR process restart repeated warmup -> 4K -> 8K. The restart rows reuse the original main process's corresponding first measurements; they are not additional independent main restarts.
- TPOT is the mean of per-request `(latency - TTFT) / (output_tokens - 1)`, not inter-chunk latency. TTFT includes queueing.

## Details

Group prefetch already exists for single-token decode. This extends its eligibility without adding a backend support flag, stream, buffer or CPU readback. Current verification KV remains resident and is written by each layer before its attention; only historical host misses are staged early.

The compact gather previously targeted 64 blocks but launched one block per row once the row count exceeded 64. For example, 32 requests with four verification rows produced a 128-block copy grid. Workers now loop over those rows within a 64-block launch. Miss-count clamping, invalid entries, out-of-range source zeroing and padded hot-page strides keep their existing behavior. Tests cover row counts around the boundary, empty plans, payload bytes and replay with updated inputs.

The launch bound may trade dense-copy bandwidth for compute overlap, as illustrated by the diagnostic trace above. A block-count bound does not reserve particular SMs.

An open-PR search found no equivalent speculative-group-prefetch or bounded-gather change. #60103 handles separate existing launch/resolver overhead; #61263 changes residency hash probing.

- MatthewBonanni · comment · 2026-11-02T04:50:35Z · [source](https://github.com/vllm-project/vllm/pull/63801#issuecomment-6569345242)

Following up on the race: it isn't TopK, and it isn't a bug in this PR. The crash is a cluster-barrier race in FlashInfer's MNNVL fused allreduce + residual + RMSNorm kernel, which vLLM's eager `fused_allreduce_rms_norm` uses by default on single-node NVSwitch at TP≥4.

**Root cause.** Since flashinfer-ai/flashinfer#3385 (still on FlashInfer main), `LamportFlags::ctaArrive()` has every thread call `__cluster_barrier_arrive()`, but only warp 0 of cluster rank 0 calls `__cluster_barrier_wait()`. Before that change it was a full `cluster.sync()`. The other CTAs then run the RMSNorm cluster reduction, which writes into peer CTAs' shared memory via `cluster.map_shared_rank`, with no guarantee the peer CTA is resident. If the timing slips, that DSMEM write lands on an absent CTA:
- Xid 13 `Graphics SM Cga Exception: CTA Not Present`
- a sticky `unspecified launch failure`

**Why this PR exposes it.** The PR queues more zero-copy host-memory gathers on the HiSparse copy stream, and now does so on spec-verify batches too. Those gathers run concurrently with the fused AR-norm, and the host reads shift CTA timing enough to hit the window. Main crashes too if you add the same gathers.

**Evidence.** I used a standalone repro with no vLLM code (below). It runs the MNNVL `allreduce_fusion` in a loop while a side stream runs a trivial kernel reading random rows of host memory. TP4, FlashInfer 0.7.2.post1, torch 2.14.0+cu130.

| Config | H200, driver 595.71.05 (VM) | H100, driver 580.126.09 (bare metal) |
|---|---|---|
| MNNVL, side stream on | Xid 13 within seconds | Xid 13 within seconds |
| MNNVL, two-shot / PDL off / pinned memory | Xid 13 | Xid 13 (two-shot) |
| MNNVL, side stream off | no crash | no crash |
| MNNVL, side kernel reads device memory | no crash | — |
| `trtllm` backend | no crash | — |
| **MNNVL + one-line fix (below)** | — | **no crash, one-shot and two-shot** |

`compute-sanitizer --tool racecheck` on the unpatched kernel, with no side stream, reports `Potential invalid __shared__ write ... located in a block that might not have entered yet` in `oneshotAllreduceFusionKernel`. It reports nothing on the patched kernel.

**Fix (FlashInfer).** Make every thread wait after arriving, which restores the pre-#3385 synchronization:

```diff
       __cluster_barrier_arrive();
+      __cluster_barrier_wait();
       if (cluster.block_rank() == 0 && threadIdx.x < 32) {
-        __cluster_barrier_wait();
         arriveCounter(threadIdx.x);
       }
```

https://github.com/flashinfer-ai/flashinfer/pull/7782

Until that lands in FlashInfer, `VLLM_FLASHINFER_ALLREDUCE_BACKEND=trtllm` avoids the kernel; it's clean in the standalone, but I haven't confirmed it at server level. Perf numbers from my earlier runs still stand.

```python
"""vLLM-free repro: FlashInfer MNNVL fused allreduce+residual+RMSNorm on the compute
stream while a side stream runs a trivial zero-copy kernel reading random host rows.

torchrun --nproc-per-node 4 fi_repro.py <seconds> <side:on|off>
Env: BACKEND=mnnvl|trtllm, HOSTMEM=register|pinned, SRC=host|device, ONESHOT=1|0, PDL=1|0
"""

import os
import sys
import time

import flashinfer.comm as fc
from flashinfer.comm.comm_backend import TorchDistBackend
import torch
import torch.distributed as dist
from torch.utils.cpp_extension import load_inline

_SRC = r"""
#include <torch/extension.h>
#include <ATen/cuda/CUDAContext.h>
__global__ void zc_gather(const uint4* __restrict__ host, uint4* __restrict__ dst,
                          const int* __restrict__ rows, int n, int vec_per_row) {
  int warp = (blockIdx.x * blockDim.x + threadIdx.x) / 32, lane = threadIdx.x % 32;
  int nwarps = gridDim.x * blockDim.x / 32;
  for (int i = warp; i < n; i += nwarps) {
    const uint4* src = host + (long long)rows[i] * vec_per_row;
    uint4* d = dst + (long long)i * vec_per_row;
    for (int j = lane; j < vec_per_row; j += 32) __stcg(d + j, __ldcg(src + j));
  }
}
void launch(int64_t host, torch::Tensor dst, torch::Tensor rows, int64_t row_bytes) {
  zc_gather<<<64, 512, 0, at::cuda::getCurrentCUDAStream()>>>(
      (const uint4*)host, (uint4*)dst.data_ptr(), rows.data_ptr<int>(), rows.numel(),
      (int)(row_bytes / 16));
}
"""

secs = float(sys.argv[1]) if len(sys.argv) > 1 else 300
side_on = (sys.argv[2] if len(sys.argv) > 2 else "on") == "on"
rank, world = int(os.environ["LOCAL_RANK"]), int(os.environ["WORLD_SIZE"])
torch.cuda.set_device(rank)
dev = torch.device("cuda", rank)
dist.init_process_group("nccl", device_id=dev)
cpu_group = dist.new_group(backend="gloo")

HIDDEN, MAX_TOK = 6144, 170
ROWS = int(os.environ.get("ROWS", "16"))
oneshot = {"1": True, "0": False}.get(os.environ.get("ONESHOT", ""))
pdl = os.environ.get("PDL", "1") == "1"
ws = fc.create_allreduce_fusion_workspace(
    backend=os.environ.get("BACKEND", "mnnvl"), world_size=world, rank=rank, max_token_num=MAX_TOK,
    hidden_dim=HIDDEN, dtype=torch.bfloat16, comm_backend=TorchDistBackend(group=cpu_group), group=cpu_group,
)
ext = load_inline(
    "pr63801_zc", cpp_sources="void launch(int64_t, torch::Tensor, torch::Tensor, int64_t);",
    cuda_sources=_SRC, functions=["launch"], extra_cuda_cflags=["-gencode=arch=compute_90a,code=sm_90a"],
)

ROW, NREAD = 656, int(os.environ.get("NREAD", "32768"))
host_rows = int(float(os.environ.get("POOL_GIB", "16")) * 2**30) // ROW
if os.environ.get("SRC", "host") == "device":
    pool = torch.empty(host_rows, ROW, dtype=torch.uint8, device=dev)
elif os.environ.get("HOSTMEM", "register") == "pinned":
    pool = torch.empty(host_rows, ROW, dtype=torch.uint8, pin_memory=True)
else:
    pool = torch.empty(host_rows, ROW, dtype=torch.uint8)
    pool.view(-1)[::4096].zero_()
    assert torch.cuda.cudart().cudaHostRegister(pool.data_ptr(), pool.nbytes, 0).value == 0
dst = torch.empty(NREAD, ROW, dtype=torch.uint8, device=dev)
rows = torch.randint(0, host_rows, (NREAD,), dtype=torch.int32, device=dev)

x = torch.randn(ROWS, HIDDEN, device=dev, dtype=torch.bfloat16)
residual = torch.randn(ROWS, HIDDEN, device=dev, dtype=torch.bfloat16)
gamma = torch.ones(HIDDEN, device=dev, dtype=torch.bfloat16)
norm_out = torch.empty_like(x)
res_out = torch.empty_like(x)


def step():
    global residual
    h = x.clone()
    fc.allreduce_fusion(
        input=h, workspace=ws, pattern=fc.AllReduceFusionPattern.kARResidualRMSNorm,
        launch_with_pdl=pdl, residual_out=h, norm_out=torch.empty_like(h), residual_in=residual,
        rms_gamma=gamma, rms_eps=1e-6, use_oneshot=oneshot, fp32_acc=True, layout_code=0, trigger_completion_at_end=False,
    )
    residual = h * 0.5


for _ in range(3):
    step()
ext.launch(pool.data_ptr(), dst, rows, ROW)
torch.cuda.synchronize()
dist.barrier()
if rank == 0:
    print(f"start backend={ws.backend} mc={getattr(ws, 'mc_ptr', None)} oneshot={oneshot} pdl={pdl} side={side_on}", flush=True)
side = torch.cuda.Stream()
t0, n = time.time(), 0
stop = torch.zeros(1, device=dev)
while True:
    if side_on:
        with torch.cuda.stream(side):
            ext.launch(pool.data_ptr(), dst, rows, ROW)
    for _ in range(8):
        step()
    n += 1
    if n % 2000 == 0:
        stop.fill_(float(time.time() - t0 >= secs))
        dist.broadcast(stop, 0)
        if stop.item():
            break
        if rank == 0:
            print(f"iters={n} t={time.time() - t0:.0f}s ok", flush=True)
torch.cuda.synchronize()
if rank == 0:
    print(f"done iters={n} side={side_on}", flush=True)
os._exit(0)
```
