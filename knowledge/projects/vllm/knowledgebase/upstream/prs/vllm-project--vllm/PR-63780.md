## Details

The shared skip-None behavior omitted fields that Python explicitly sets to null. Usage serialization also retained null details on usage-only chunks and always included reasoning details. This follows the Rust frontend's documented Python parity contract. The current OpenAI schema permits nullable finish_reason; the fix does not depend on the issue's older claim that every chunk must contain that field.

Use the existing serde, serde_json, and serde_with dependencies: nested Option values distinguish unset from explicitly null fields, while Serde attributes retain always-present nullable choice fields. A chat-stream usage DTO keeps the continuous and final usage rules separate from shared non-streaming Usage. No new dependency or custom serializer is needed.

- **Design Fit:** Response DTOs own serialization. Reuse existing Serde attributes and usage types; isolate the conditional streaming rules. Engine, parser, and model-runner behavior is unchanged.
