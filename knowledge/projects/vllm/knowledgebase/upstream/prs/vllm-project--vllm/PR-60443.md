# [DeepSeek-V4-P2-02] Stabilize C128 sparse metadata for graph replay

[Upstream PR](https://github.com/vllm-project/vllm/pull/60443) · state: open · merged: False

## Original PR description

## Overview

Stabilize DeepSeek-V4 C128 sparse metadata and compressor graph-capture behavior in batch-invariant mode. This extracts the metadata portion of #54955 from the broader Draft #59883.

## Claims

- Use the preallocated maximum C128 width when batch invariance is enabled, independent of the longest co-batched request.
- Discard the C128 boundary flag for block-size-8 CUDA graph capture, as in the original implementation.
- Retain the adaptive width outside BI mode; graph capture clears the block-size-8 boundary regardless of BI, as in the original PR.

## Validation

- H100: `uv run --no-project python -m pytest --confcutdir=tests/kernels tests/kernels/attention/test_flashmla_sparse.py::test_c128a_batch_invariant_metadata_uses_fixed_width tests/kernels/test_compressor_kv_cache.py::test_compressor_graph_capture_discards_c128_boundary -q` -- 4 passed.
- The composed P2 integration branch passed the full `test_flashmla_sparse.py` suite (34 passed, 9 skipped); end-to-end model evaluation remains pending.

## Details

The adaptive width otherwise depends on the current batch maximum, changing workspace shape during replay. Both production changes are copied from #59883; two focused cases were added to existing test files. The block-size-8 graph-capture change applies independently of the BI flag. This is a non-overlapping slice of that Draft, which should be superseded before submitting the split PRs. AI assistance was used; the human submitter must review the diff and validation.
