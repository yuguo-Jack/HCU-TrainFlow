# [KV Connector][NIXL] Add a ucx_backend_params key for UCX backend init params

[Upstream PR](https://github.com/vllm-project/vllm/pull/62905) · state: closed · merged: True

## Original PR description



## Overview

`NixlConnector` creates NIXL's UCX backend with `num_threads` only, so UCX runs with NIXL's default `ucx_error_handling_mode=peer`. In peer mode UCX wires up only transports that can detect peer failure. On one MI355X node that left tcp: GPU-to-GPU KV reads ran as software emulation over tcp at about 3.4 Gbps, while with `ucx_error_handling_mode=none` UCX picks rocm_ipc zero-copy and a 74 MiB read ran at 483.7 Gbps. `UCX_*` environment variables cannot set this (it is a NIXL backend init parameter), and vLLM has no way to pass one.

## Claims

- New `kv_connector_extra_config.ucx_backend_params` (a dict of strings) passes extra init parameters to the UCX backend. Without the key nothing changes.
- When it is set and UCX is a selected backend, the agent is created with no backends and the worker creates each configured backend itself, in order, with the parameters NIXL would have used; UCX also gets the extra ones. In sleep mode, where the worker already creates UCX itself, the params are added to that call.
- Documented in `docs/features/nixl_connector_usage.md` ("UCX backend parameters").

## Validation

Single MI355X node, an equivalent out-of-tree change, one 74 MiB KV read between two GPUs:

| `ucx_error_handling_mode` | UCX transport | throughput |
|---|---|---|
| peer (NIXL default) | tcp | 3.4 Gbps |
| none (`ucx_backend_params`) | rocm_ipc | 483.7 Gbps |

New `test_ucx_backend_params` in `tests/v1/kv_connector/unit/test_nixl_connector.py`, 4 cases: no key (the agent config creates the backends, as before); UCX only (created explicitly with `num_threads` and the extra params); UCX + LIBFABRIC (both created in order, params on UCX only); LIBFABRIC only (nothing to apply, nothing changes).

## Details

**Flow.** Only worker start-up changes, on both P and D:

1. `NixlBaseConnectorWorker.__init__` reads `ucx_backend_params` from `kv_connector_extra_config`.
2. Without it: `nixl_agent(..., nixl_agent_config(backends=[...]))` creates the backends, as today.
3. With it and UCX selected: `nixl_agent_config(backends=[])`, then `create_backend(name, params)` for each configured backend in order. UCX gets the params NIXL's agent config would have given it (`num_threads` when UCX is the only backend) plus the extra ones.
4. Memory registration, handshake, and the decode-side read are unchanged; UCX simply selects its transports with the requested error-handling mode, e.g. rocm_ipc instead of tcp within a node.

**Trade-off.** With `ucx_error_handling_mode=none` UCX does not detect a failed peer; the docs section says so. The parameter is opt-in and passed through as given.

**Not tested.** Cross-node transfers with mode none, sleep mode with the params (no unit test), and NVIDIA (cuda_ipc), where we expect the same transport-selection effect but did not measure it.
