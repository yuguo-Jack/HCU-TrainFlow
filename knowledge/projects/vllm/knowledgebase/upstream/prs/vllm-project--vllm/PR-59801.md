# [Bugfix][LoRA] Apply PEFT rank_pattern / alpha_pattern scaling per module

[Upstream PR](https://github.com/vllm-project/vllm/pull/59801) · state: open · merged: False

## Original PR description


## Overview

PEFT adapters can set a per-module rank and alpha with `rank_pattern` / `alpha_pattern`. vLLM ignored both and applied the global `lora_alpha / r` everywhere, so those modules were served with the wrong scaling and no warning. This applies PEFT's per-module rank and scaling when loading the adapter.

Part of #59799 (the scaling and `max_lora_rank` parts; the bare `AssertionError` for 3D MoE adapters on non-3D models is left for a follow-up).

## Claims

- Adapters with `rank_pattern` / `alpha_pattern` now match PEFT's outputs (dense and MoE, including PEFT's MoE docs recipe of `rank_pattern = r // num_experts` on the experts).
- MoE packing (`pack_moe`, `pack_moe_stacked`) keeps each projection's scaling instead of copying w1's to w2 and w3.
- `validate_legal` checks the largest rank in `rank_pattern` against `max_lora_rank`. Before, `r=8, rank_pattern={"q_proj": 32}` passed with `max_lora_rank=16` and then killed the engine with a tensor size mismatch.
- No change for adapters without patterns (same code path), or for PEFT `save_as_lora` dynamic-rank adapters (`r=1, lora_alpha=1`, equal per-module `rank_pattern` / `alpha_pattern`), which were already served correctly.

## Details

Root cause: `PEFTHelper` only read `r` and `lora_alpha`, and `LoRALayerWeights.from_config` gave every module `peft_helper.r` and `peft_helper.vllm_lora_scaling_factor`.

- `PEFTHelper` reads `rank_pattern` / `alpha_pattern` and `get_rank_and_scaling(module_name)` resolves them with PEFT's `get_pattern_key` rule (a key matches a suffix of the module name at a `.` boundary; first match in the config's order). For non-overlapping keys this is also what PEFT's planned order-independent matching (huggingface/peft#3818) gives; overlapping keys would need to follow PEFT once that lands.
- Patterns are matched against the checkpoint module name, before the weights mapper renames it (`from_lora_tensors` parses the tensor name once more without the mapper).
- PEFT stores fused MoE expert LoRAs from `target_parameters` as `experts.base_layer` (gate_up_proj) and `experts` (down_proj) and matches patterns against the parameter names, so those two names are mapped back. PEFT nests gate_up_proj as `base_layer` regardless of the order in `target_parameters` (checked), which is also what `_stack_moe_lora_weights` assumes.
- Modules keep their real rank, which also makes the `num_experts = lora_a.shape[0] // rank` fallback in `_stack_moe_lora_weights` correct for adapters with expert rank patterns. `LoRAModel.rank` stays the global `r`; it is only used by `clone()`.

- vadiklyutiy · comment · 2026-10-05T16:57:11Z · [source](https://github.com/vllm-project/vllm/pull/59801#issuecomment-5999119709)

Thanks for the fix! One case still differs from PEFT: a per-expert (2D) MoE LoRA where the experts of one projection in a layer have different scaling, for example `alpha_pattern={"experts.1.down_proj": 64}`.

`_create_merged_loras_inplace` calls `pack_moe` before `lora.optimize()`, and `pack_moe` keeps a single scaling per projection taken from expert 0 (`loras[0]`, `loras[1]`, `loras[2]`). So in the example above, every expert's `down_proj` gets expert 0's `16 / 8 = 2`, and expert 1 loses its `64 / 8 = 8`. Per-expert `rank_pattern` would already fail at `torch.stack`, so only per-expert alpha is affected.

Mean / max |vLLM − reference| prompt logprob with the reproducer below (1x B200; the adapter itself moves logprobs by 0.158 on average):

| | `lora` (with `alpha_pattern`) | `lora_folded` (control) |
|---|---|---|
| main (`18f8f96`) | 0.1082 / 0.513 | 0.0049 / 0.165 |
| this PR (`6439604`) | 0.1082 / 0.513 | 0.0049 / 0.165 |
| this PR + the change below | 0.0049 / 0.165 | 0.0049 / 0.165 |

The 0.165 max is the noise floor of this setup (bf16 vLLM vs fp32 reference); it is the same for the folded control.

Suggested change in `pack_moe`, right after `assert len(loras) % 3 == 0`. It folds the scaling into `lora_b` only when the experts of a projection differ, so adapters without per-expert patterns are unchanged:

```python
        # The packed LoRA has one scaling per projection, so fold it into lora_b
        # where the experts of a projection differ (e.g. from alpha_pattern).
        for proj_loras in (loras[0::3], loras[1::3], loras[2::3]):
            if len({lora.scaling for lora in proj_loras if lora is not None}) > 1:
                for lora in proj_loras:
                    if lora is not None:
                        lora.optimize()
```

With it, the per-projection scaling that the PR reads from `loras[0..2]` stays correct (it becomes 1.0 for folded projections), and the "All experts of one projection share the same scaling" comment can go. A unit test for `tests/lora/test_lora_weights.py` that fails on the current head (96/192 elements mismatch) and passes with the change; all of `test_lora_weights.py` and `test_peft_helper.py` (except the `llama32_lora_files` ones) pass with it:

```python
def test_moe_packing_keeps_per_expert_scaling():
    """Experts of one projection can have different scaling, e.g. from
    alpha_pattern."""
    loras = moe_loras(RSLORA_SCALING) + moe_loras(RSLORA_SCALING)
    loras[4].scaling = 2 * RSLORA_SCALING  # w2 of expert 1
    expected = [lora.lora_b * lora.scaling for lora in loras]
    packed = PackedLoRALayerWeights.pack_moe(loras, "experts").optimize()
    for i, lora_b in enumerate(packed.lora_b):
        torch.testing.assert_close(lora_b, torch.stack(expected[i::3]))
```

<summary>Reproducer</summary>

The script builds a tiny random Qwen3-MoE (4 experts, top-2) and a per-expert LoRA with `r=8`, `lora_alpha=16` and `alpha_pattern={"experts.1.down_proj": 64}`, plus a `lora_folded` control with that scaling folded into `lora_B` and the pattern removed. It does not use PEFT: with transformers 5 the HF experts are fused 3D parameters, so PEFT cannot target per-expert linears (such adapters come from transformers 4 or other tooling). Instead, the reference merges `W += alpha_m / r * B @ A` (PEFT's definition) into the HF expert weights and runs transformers in fp32. Tested with transformers 5.16.1.

```bash
python repro.py
```

```python
"""vLLM vs reference for a per-expert (2D) MoE LoRA whose experts of one layer
have different scaling (alpha_pattern on a single expert).

Reference: the same LoRA merged into the HF weights (W += alpha_m / r * B @ A),
run with transformers in fp32. No PEFT needed.
"""

import json
import os
import tempfile

import torch
from safetensors.torch import save_file
from transformers import AutoModelForCausalLM, Qwen3MoeConfig

import vllm
from vllm import LLM, SamplingParams
from vllm.inputs import TokensPrompt
from vllm.lora.request import LoRARequest

E, R, ALPHA = 4, 8, 16  # every module scaled by 16/8 = 2 ...
ALPHA_PATTERN = {"experts.1.down_proj": 64}  # ... except expert 1 down_proj: 64/8 = 8


def main():
    print("vllm from:", vllm.__file__)
    tmp = tempfile.mkdtemp()
    torch.manual_seed(0)
    cfg = Qwen3MoeConfig(vocab_size=1024, hidden_size=256, intermediate_size=512, moe_intermediate_size=128,
                         num_hidden_layers=2, num_attention_heads=4, num_key_value_heads=2, head_dim=64,
                         num_experts=E, num_experts_per_tok=2, tie_word_embeddings=False)
    model = AutoModelForCausalLM.from_config(cfg, dtype=torch.bfloat16)
    model.save_pretrained(f"{tmp}/base")

    # Per-expert LoRA layout (what PEFT writes for MoE models with nn.Linear experts).
    H, I = cfg.hidden_size, cfg.moe_intermediate_size
    shapes = {"gate_proj": (H, I), "up_proj": (H, I), "down_proj": (I, H)}  # (in, out)
    sd = {}
    for layer in range(cfg.num_hidden_layers):
        for e in range(E):
            for proj, (fin, fout) in shapes.items():
                pre = f"base_model.model.model.layers.{layer}.mlp.experts.{e}.{proj}"
                sd[f"{pre}.lora_A.weight"] = torch.randn(R, fin) * 0.06
                sd[f"{pre}.lora_B.weight"] = torch.randn(fout, R) * 0.06
    ad_cfg = {"peft_type": "LORA", "task_type": "CAUSAL_LM", "base_model_name_or_path": f"{tmp}/base",
              "r": R, "lora_alpha": ALPHA, "target_modules": list(shapes), "bias": "none",
              "use_rslora": False, "use_dora": False, "rank_pattern": {}, "alpha_pattern": ALPHA_PATTERN}
    os.makedirs(f"{tmp}/lora")
    save_file(sd, f"{tmp}/lora/adapter_model.safetensors")
    json.dump(ad_cfg, open(f"{tmp}/lora/adapter_config.json", "w"))

    # Control: expert 1 down_proj scaling folded into lora_B, pattern removed.
    fold = ALPHA_PATTERN["experts.1.down_proj"] / ALPHA
    sd_folded = {k: v * fold if ".experts.1.down_proj.lora_B" in k else v for k, v in sd.items()}
    os.makedirs(f"{tmp}/lora_folded")
    save_file(sd_folded, f"{tmp}/lora_folded/adapter_model.safetensors")
    json.dump({**ad_cfg, "alpha_pattern": {}}, open(f"{tmp}/lora_folded/adapter_config.json", "w"))

    # Reference: merge W += s_m * B @ A into the HF fused expert weights.
    model = model.float().cuda()
    with torch.no_grad():
        for layer in range(cfg.num_hidden_layers):
            experts = model.model.layers[layer].mlp.experts
            for e in range(E):
                delta = {}
                for proj in shapes:
                    pre = f"base_model.model.model.layers.{layer}.mlp.experts.{e}.{proj}"
                    s = (ALPHA_PATTERN.get(f"experts.{e}.{proj}", ALPHA)) / R
                    delta[proj] = (s * sd[f"{pre}.lora_B.weight"] @ sd[f"{pre}.lora_A.weight"]).cuda()
                experts.gate_up_proj[e, :I] += delta["gate_proj"]
                experts.gate_up_proj[e, I:] += delta["up_proj"]
                experts.down_proj[e] += delta["down_proj"]

    prompts = [torch.randint(10, 1024, (48,), generator=torch.Generator().manual_seed(i)).tolist() for i in range(4)]
    with torch.no_grad():
        ref_lp = []
        for ids in prompts:
            x = torch.tensor([ids], device="cuda")
            logp = torch.log_softmax(model(input_ids=x).logits[0, :-1].float(), -1)
            ref_lp.append(logp.gather(-1, x[0, 1:, None])[:, 0].tolist())
    del model
    torch.cuda.empty_cache()

    llm = LLM(f"{tmp}/base", skip_tokenizer_init=True, enable_lora=True, max_lora_rank=R, max_model_len=256,
              gpu_memory_utilization=0.3, enforce_eager=True)
    params = SamplingParams(max_tokens=1, prompt_logprobs=0, detokenize=False)
    for i, name in enumerate(["no_lora", "lora", "lora_folded"]):
        req = None if name == "no_lora" else LoRARequest(name, i, f"{tmp}/{name}")
        outs = llm.generate([TokensPrompt(prompt_token_ids=p) for p in prompts], params, lora_request=req)
        vllm_lp = [[o.prompt_logprobs[j][t].logprob for j, t in enumerate(p) if j > 0] for p, o in zip(prompts, outs)]
        diff = torch.tensor(vllm_lp).sub(torch.tensor(ref_lp)).abs()
        print(f"{name:12s} mean |vLLM - ref| logprob diff: {diff.mean():.4f}  max: {diff.max():.4f}")


if __name__ == "__main__":
    main()
```
