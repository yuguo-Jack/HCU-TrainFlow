# [RL] Release weight-transfer communicators without stopping inference

[Upstream PR](https://github.com/vllm-project/vllm/pull/61060) · state: closed · merged: True

## Original PR description

## Overview

Release the trainer weight-transfer connection without restarting healthy inference workers. Upstream port of [fork #119](https://github.com/aoshen02/vllm/pull/119), rebased onto main `26a488ad93`.

## Claims

- Explicitly destroy NCCL communicators before clearing references, on trainer and worker sides, including dense, sparse and M2N transports.
- Expose `shutdown_weight_transfer_engine` through Python/Rust development HTTP routes, async engine, offline RL mixin and built-in trainer clients.
- Reject shutdown during an active update; repeated inactive shutdown is a no-op. Model weights and KV cache are not offloaded.

## Validation

The following runtime results apply to fork #119 at `f49e6dff710`, based on `43b4aaea`; they are **not** a claim that this new main-based branch has been runtime-tested:

- Python: 69 targeted tests passed; Rust: 3 lifecycle tests plus 1 development-gate test passed and release compiled.
- Eight real NCCL connect/broadcast/shutdown cycles on H200: baseline grew 2.84 GiB/GPU after warmup; candidate growth was zero, releasing approximately 486 MiB per teardown. Cleanup took 0.49–0.53 seconds.
- Installed experimental-image Vime/Ray/NCCL E2E: Python and Rust each passed three update/destroy/reconnect rounds with stable worker PIDs and original/zeroed/restored output assertions. TP1, BF16, MRV2, eager, Qwen2.5-0.5B-Instruct.
- [Detailed commands and evidence](https://github.com/aoshen02/vllm/pull/119#issuecomment-6106742178). Broader Vime CI and CPU counts there are integration coverage, not tests isolated to this patch.

Current main-based branch: `git diff --check` passed. Changed-file pre-commit results are reported in the submission comment. Fresh main-based runtime regression remains pending; this PR is a draft. CPU/XPU hardware, larger TP/PP and all transport backends are not certified by the H200 experiment.

## Details

`PyNcclCommunicator` has no automatic finalizer. Dropping its Python reference alone can leave native communication resources allocated across reconnects. Reuse its existing `destroy()` primitive and the transport shutdown lifecycle rather than introducing a new transport or shutdown of inference.

Follow existing weight-transfer route gates and operation metrics. CPU/XPU inherit worker cleanup. Keep the engine object available for reinitialization. Main moved offline RL methods into `RLOfflineMixin`; the new method follows that location rather than restoring methods to `LLM`.

Duplicate search for `shutdown_weight_transfer_engine` found no open upstream PR. #57854 concerns failed update sessions; #57834 concerns process teardown. This operation retains inference workers. AI assistance was used; human line-by-line review remains required.
