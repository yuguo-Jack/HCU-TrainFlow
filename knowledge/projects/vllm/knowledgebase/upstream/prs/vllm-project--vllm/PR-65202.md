# [ROCm][RDNA] Add gfx1170 and gfx1171 support

[Upstream PR](https://github.com/vllm-project/vllm/pull/65202) · state: open · merged: False

## Original PR description



## Overview

Add ROCm support for gfx1170 and gfx1171: allow both architectures in the build, route them to the RDNA4 custom paged-attention path, and enable the torch `_scaled_mm` FP8 linear kernels on them.

## Claims

- vLLM builds for `PYTORCH_ROCM_ARCH="gfx1170;gfx1171"`. Previously the build stopped at the `HIP_SUPPORTED_ARCHS` gate.
- The ROCm custom paged-attention kernel (`_rocm_C.paged_attention`) compiles for and runs on gfx1170/gfx1171 through the `__GFX12__` (RDNA4) code path.
- FP8 checkpoints and online FP8 quantization load and run on gfx1170/gfx1171 with `PerTensorTorchFP8ScaledMMLinearKernel` / `RowWiseTorchFP8ScaledMMLinearKernel`. Previously kernel selection failed with `Failed to find a kernel`.
- No behavior change for any other architecture: all new checks match gfx1170 and gfx1171 only.

## Validation

Built with `PYTORCH_ROCM_ARCH="gfx1170;gfx1171"`; every GPU extension (`_C`, `_C_stable_libtorch`, `_moe_C_stable_libtorch`, `_rocm_C`) contains code objects for both targets.

**Custom paged-attention kernel:** `pytest tests/kernels/attention/test_attention.py -k "test_paged_attention and not unsupported"` passes all 6 cases the test runs on RDNA (head size 128, block size 16, BF16/FP16, three head layouts). The other configurations are skipped by the test's existing `is_navi()` condition.

**End to end** (`LLM.generate`, greedy, 4 prompts, outputs checked for coherence):

| Model | Setting | Linear / attention kernel selected | Result |
|---|---|---|---|
| Qwen/Qwen2.5-1.5B-Instruct | BF16 | `ROCM_ATTN` with the custom paged-attention decode (no Triton fallback) | ✅ |
| Qwen/Qwen2.5-0.5B-Instruct | BF16 | — | ✅ |
| Qwen/Qwen2.5-0.5B-Instruct | `--quantization fp8` | `PerTensorTorchFP8ScaledMMLinearKernel` | ✅ |
| Qwen/Qwen2.5-0.5B-Instruct | `--kv-cache-dtype fp8` | — | ✅ |
| Qwen/Qwen2.5-0.5B-Instruct | `--quantization fp8 --kv-cache-dtype fp8`, CUDA graphs on | `PerTensorTorchFP8ScaledMMLinearKernel` | ✅ |
| Qwen/Qwen3-0.6B-FP8 | block-wise FP8 checkpoint | `TritonFp8BlockScaledMMKernel` | ✅ |
| RedHatAI/Qwen3-1.7B-FP8-dynamic | per-channel FP8 checkpoint | `RowWiseTorchFP8ScaledMMLinearKernel` | ✅ |
| microsoft/Phi-3.5-mini-instruct | `--quantization fp8` | `PerTensorTorchFP8ScaledMMLinearKernel` | ✅ |

Without the second commit, `RedHatAI/Qwen3-1.7B-FP8-dynamic` fails at load with `Failed to find a kernel`.

## Details

**Build gate.** `CMakeLists.txt` filters `PYTORCH_ROCM_ARCH` against `HIP_SUPPORTED_ARCHS`; gfx1170 and gfx1171 are added next to the other gfx11 entries.

**Paged attention.** gfx1170/gfx1171 predefine `__GFX11__`, so `csrc/rocm/attention_kernels.cuh` picks the RDNA3 branch for them. That branch cannot compile there: the RDNA3 WMMA builtins are rejected, while the RDNA4 `_gfx12` builtins are accepted, the same as on gfx1201:

| Target | Arch macro | `__builtin_amdgcn_wmma_f32_16x16x16_f16_w32` (RDNA3) | `..._w32_gfx12` (RDNA4) |
|---|---|---|---|
| gfx1100 | `__GFX11__` | compiles | needs `wmma-128b-insts` |
| gfx1170 / gfx1171 | `__GFX11__` | needs `wmma-256b-insts` | compiles |
| gfx1201 | `__GFX12__` | needs `wmma-256b-insts` | compiles |

A new `__HIP__GFX117X__` guard (defined only for `__gfx1170__` / `__gfx1171__`) therefore excludes them from the `__GFX11__` branch and adds them to the `__GFX12__` one. The Python-side gate (`use_rocm_custom_paged_attention`, via `_ON_GFX1X`) already covers both, so no runtime change is needed there.

**FP8 linear kernels.** `_rocm_torch_fp8_scaled_mm_supported()` gates the torch `_scaled_mm` kernels by architecture. A new `on_gfx117x()` helper in `vllm/platforms/rocm.py` (explicit match on gfx1170 and gfx1171) is added to that check. hipBLASLt FP8 GEMM with per-tensor and row-wise scales works on these targets.

**Scope and limitations.**
- CI has no gfx1170/gfx1171 runners, so these paths are covered by the validation above rather than by CI.
- No new tests: the existing paged-attention kernel test already covers the RDNA configurations on these targets.
