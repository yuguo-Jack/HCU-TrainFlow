# [Test] Stream bench startup output and add timeout

[Upstream PR](https://github.com/vllm-project/vllm/pull/63502) · state: open · merged: False

## Original PR description

## What this PR does / why we need it

`tests/benchmarks/test_bench_startup.py::test_bench_startup` invokes
`vllm bench startup` via `subprocess.run(..., capture_output=True)`. This has
two issues that make the test hard to run and debug:

1. **No visible progress.** `capture_output=True` buffers all stdout/stderr of
   the child process until it finishes. `vllm bench startup` launches 7 LLM
   instances by default (3 cold + 1 warmup + 3 warm), each involving model
   loading and `torch.compile`, so it can take tens of minutes. During that
   time the terminal shows nothing (the tqdm progress bars are swallowed),
   which looks like a hang. The `print(result.stdout)` / `print(result.stderr)`
   calls only run *after* the process has already exited, so they don't help.

2. **No timeout.** The call has no `timeout`, so if the subprocess ever blocks
   (e.g. a stuck worker, GPU memory not released), the test waits forever
   instead of failing.

This PR streams the child's output directly to the test's stdout/stderr
(`stdout=sys.stdout, stderr=sys.stderr`) so progress is visible in real time
(with `pytest -s`), and adds a generous `timeout=1800` (30 min) so a stuck run
fails instead of hanging indefinitely. The assertion message no longer embeds
`result.stderr` (which is now `None` since output is not captured), using the
exit code instead.

Behavior is otherwise unchanged — the test still asserts `returncode == 0`.
