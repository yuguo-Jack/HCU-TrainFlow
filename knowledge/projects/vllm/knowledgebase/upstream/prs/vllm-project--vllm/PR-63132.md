# [Bugfix][Rust Frontend] Normalize assistant reasoning aliases

[Upstream PR](https://github.com/vllm-project/vllm/pull/63132) · state: open · merged: False

## Original PR description

## Overview

Fix Rust chat requests that reject assistant history containing both `reasoning` and `reasoning_content`. Match Python's canonical non-null precedence independent of JSON key order. Fixes #63130.

## Claims

- Accept both spellings and carry the selected reasoning once through rendering, including tool-call assistant history.
- Preserve empty canonical values, null/absent fallback, canonical serialization, selected-value type errors, and existing `thinking` alias behavior.

## Validation

- Baseline: new decoder and real Axum chat route regressions fail with `duplicate field reasoning` (HTTP 400); malformed controls pass.
- Patched focused: `cargo nextest run --manifest-path rust/Cargo.toml --workspace --all-features --locked --no-fail-fast -E 'test(reasoning_aliases)'`: 3 passed, covering 17 valid route cases and 9 malformed/compatibility controls.
- `cargo nextest run --manifest-path rust/Cargo.toml --workspace --all-features --locked --no-fail-fast`: 2297 passed, 13 existing skips.
- `cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --all-features --locked -- -D warnings`: passed.
- Changed-file pre-commit: passed.

Tests used isolated writable dependency/model-file caches. Local HTTP tests require loopback proxy bypass (`NO_PROXY=localhost,127.0.0.1,::1`); the Python grammar helper requires an HTTP-compatible proxy configuration. 

The HTTP regression uses the production HF/Jinja renderer, fake tokenizer, and existing mock engine, checking exact engine prompt token IDs. No model/GPU serving, model-quality evaluation, or performance claim is included.

## Details

Serde aliases map distinct keys to one field and reject their coexistence. Normalize `reasoning_content` in the existing assistant-message JSON deserializer before derived decoding: discard it when canonical reasoning is non-null; otherwise use the non-null alias. Keep the existing `thinking` collision rules. No global duplicate-key/parser changes or typed thinking-content changes.

Python's current message union accepts some non-string reasoning values; this change retains Rust's existing string-or-null contract for the selected value. A discarded legacy value is ignored before type validation, as in Python.

AI assistance was used (Codex). The human submitter confirmed review of every changed line and successful personal execution of the focused regression tests.

Before this PR was opened, duplicate checks found no existing implementation of this fix. #62765 changes Python prompt-embedding inputs, and #42664/#52513/#41718 cover Python normalization/validation.

Thanks to @world-executed for independently investigating the same issue in #63137 and sharing the alias-normalization approach and `thinking` precedence proposal. We are coordinating to consolidate the overlapping work here; this PR preserves the existing `thinking` alias behavior.
