# [CI] Per-test timeout for Language Models (Extended Pooling)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62279) · state: closed · merged: True

## Original PR description

Shard 3/4 of `language-models-test-extended-pooling` has hung on every full CI run since Oct 16 (builds 95480, 95553, 95634). Shards 1, 2 and 4 take 12-21 minutes; shard 3/4 stalls in `test_colbert.py::TestColbertSharedEngine::test_colbert_token_embed[bert]` right after the `test_bge_m3` API-server tests, and Buildkite cancels it at the 150-minute limit.

A cancelled job also keeps the full run's coverage collect steps from running (`allow_dependency_failure` doesn't cover a cancelled dependency), so the ci-selector's recordings haven't been published since Oct 15.

This adds `--timeout=900 --timeout-method=thread` (`pytest-timeout` is already in `requirements/test/cuda.txt`). A hung test now fails with a stack dump, so whoever owns the ColBERT test gets a trace of where it hangs, and the job ends as failed rather than cancelled. It doesn't fix the hang itself.
