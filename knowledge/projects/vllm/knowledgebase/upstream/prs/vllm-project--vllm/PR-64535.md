# [Bugfix][Parser] Parse closed GLM-4.7 tool arguments once while streaming

[Upstream PR](https://github.com/vllm-project/vllm/pull/64535) · state: closed · merged: True

## Original PR description



## Overview

A GLM tool call that repeats closed argument pairs makes `Glm47MoeParser` re-parse every pair on each streaming conversion, so the API server's cost per token grows with the call until the event loop saturates and liveness fails. This parses each closed pair once. Follow-up to #61253, which covers a single long open value.

## Claims

- Streaming a call with N closed pairs matches the argument regex N times in total. On main every conversion matches all closed pairs again: 1,345,003 matches for N = 401 in the new test.
- Streamed deltas and non-streaming results are unchanged.
- No new config, flag or API. Scope is the `glm47` tool parser; `Ling3Parser` gets the `>` gate only (see Details).

## Details

**Root cause.** `ParserEngine._compute_arg_delta` converts the whole raw argument text whenever the open-value extender from #61253 is inactive: between arguments, and while the open key repeats an earlier key (the extender needs the open value to be the last JSON value). GLM set no `arg_structural_chars`, so every argument chunk event converted, and `_glm47_parse_args` re-ran `_ARG_RE.finditer` over every closed pair plus `_ARG_RE.sub` over the whole text. Merging deltas under load does not bound this, because conversions scale with the events in the merged text.

We hit this serving GLM-5.3 on vLLM 0.32.0, which includes #61253. Decode API servers climbed from 0.3 to 1 core in 3-4 minutes and failed liveness, five times in 24 hours. In three of them the logs show a single request left on the pod, generating at 99-100% MTP draft acceptance (the model repeating itself) while the stats line slipped from 10 s to 15-40 s apart. Stream content was not captured in production; the replay reproduces the same failure through the parser.

**Change.**
- `arg_structural_chars=frozenset(">")`, as DeepSeek V3.2 and V4 use. A delta without `>` cannot close a key or value, so it cannot produce a streamable change: an open last value goes through the extender, and an open repeated key sits mid-JSON where the prefix check withholds it. The next conversion or the final flush converts the full text. The gate alone only delays the kill in the replay (305 s against 215 s, measured on `d6394cf758`), because each conversion still re-scans.
- `_glm47_parse_args` takes an optional `_ClosedArgs` cache, and `Glm47MoeParser` binds one per instance into its converter and extender, the same way DeepSeek V4 and MiniMax M3 replace `_arg_converter` after `super().__init__`. A text that extends the cached text resumes after its last closed pair. Any other text parses from the start, and the cache moves forward whenever a scan closes a new pair. Appending text cannot change a pair that already closed, since each match ends at the first `</arg_value>` after its key, so resuming is exact.

**Cost.** What stays linear in the text per conversion is C-level work: `startswith` against the cached text, the slice when a pair closes, and the join of text outside the pairs for the open-key search. That is the 7% at 1.46M chars above.

**Compatibility and limits.**
- A parser built with a custom `arg_converter` keeps the uncached path (identity check in `__init__`), so tests that wrap the converter still see every call.
- `Ling3Parser` calls `ParserEngine.__init__` directly, so it gets the gate from the shared config and no cache.
- A looping call still generates until `max_tokens`; this keeps the server responsive while it does.
- Unchanged here and the same on main: when a repeated key closes with a different value than before, the final JSON no longer extends what was streamed and the flush withholds it, so the client gets truncated arguments. I can file that separately.

**Not a duplicate.** #61253 (merged) covers one long open value. #58418 (open) edits `_glm47_parse_args` for an unclosed final value; the overlap is textual only. #51141 and #64196 address Inkling and DeepSeek DSML. No open PR covers re-parsing closed GLM pairs.
