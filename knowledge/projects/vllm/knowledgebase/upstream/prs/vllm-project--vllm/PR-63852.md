# [Doc] Kimi-K3: refresh the GB300 AgentX xPyD preset and add the 3P1D DEP16 preset

[Upstream PR](https://github.com/vllm-project/vllm/pull/63852) · state: closed · merged: True

## Original PR description

## Overview

Document the GB300 Kimi-K3 AgentX lanes of [SemiAnalysisAI/InferenceX#4516](https://github.com/SemiAnalysisAI/InferenceX/pull/4516) (head `5a397acc`) in `recipes/models/moonshotai/Kimi-K3.yaml`: the refreshed TP8 + DCP8 xPyD lane (`kimik3-fp4-gb300-dynamo-vllm-agentic-dspark-mooncake-dcp8-disagg`) and a new 3P1D lane with a DEP16 decode pool (`kimik3-fp4-gb300-dynamo-vllm-agentic-dspark-mooncake-dep16-disagg`). Both run on image `vllm/vllm-openai:nightly-e4a5b5537344b103ed10de7764378ef09604ef3d` (vLLM `0.32.1rc1.dev466+ge4a5b5537` in the run logs) with Dynamo `a0de541ea8c861d5ac01d15953ca529bea68637b`.

## Claims

**`gb300_agentx_pd` (AgentX xPyD, default):**

- Image and Dynamo pin moved from `nightly-1b2a6663` / `ffbbaaa6` to the ones above.
- Both roles: `--gpu-memory-utilization 0.95` (was 0.92), `TOKENSPEED_MLA_FP16_PARTIALS=0`; `VLLM_CONNECTOR_PREFETCH_DEPTH` and `VLLM_CONNECTOR_PREFETCH_KV_CAP` removed (the lane no longer sets them).
- Prefill: `--max-num-seqs 32` (was 64), `--max-cudagraph-capture-size 8192` with an explicit `FULL_AND_PIECEWISE` capture list up to 8192, and `DYN_BACKEND_ADMISSION_ENGINE_REQUEST_LIMIT=1024` / `DYN_BACKEND_ADMISSION_ENGINE_REQUEST_WAITING_LIMIT=1024`.
- Runbook: the regular decode adds `--use-replayssm` (the specialized decode does not use it), the Mooncake store connector drops `compact_group_io` and `max_load_batch_keys`, and the frontend runs `--router-session-affinity-ttl-secs 1` (was 900) with `DYN_DISABLE_OPENAI_STRICT_SCHEMA_VALIDATION=1`. The worker table is unchanged (1P2D c56 is no longer run; c48 and c64 remain).

**`gb300_agentx_pd_dep16` (AgentX 3P1D DEP16, new, opt-in):**

- Prefill: TP8 + EP8 across two trays (no DCP), three workers; decode: one DEP16 worker (`--tensor-parallel-size 1 --data-parallel-size 16`, expert parallelism) across four trays. Both roles use MegaMoE, `--enable-ep-weight-filter`, `--max-num-seqs 32`, BF16 KDA state, FP8 KV and FlashInfer autotune.
- Online MXFP8 target quantization through `--quantization-config` `targets`: the KDA `in_proj_qkvgfab`, MLA `fused_qkv_a_g_proj` and latent-MoE `routed_expert_up_proj`/`routed_expert_down_proj` projections on both roles, plus `o_proj` and the shared experts on decode. The DSpark draft is not quantized: the draft is built from its own config (`get_draft_quant_config`), and the run logs show the online quantization pass only while the target loads.
- Decode: `--max-num-batched-tokens 512`, `--max-cudagraph-capture-size 512`, `--use-replayssm`, `tokenspeed_mla_min_split_kv: 8`, `FULL_AND_PIECEWISE` graphs (vLLM's default, replacing the DEP strategy's `FULL_DECODE_ONLY`), no prefix caching, and a Mooncake `kv_consumer` connector with `enable_lookup: false` (runbook).
- Runbook: services, environment (incl. the NVSHMEM MNNVL settings), prefill and decode commands, frontend.
- `meta.date_updated` bumped to 2026-10-26.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` passes (vllm-project/recipes @ `5eec681`).
- Built the full JSON API before and after: only the Kimi-K3 family files change (`moonshotai/Kimi-K3.json`, its `hw/gb300/strategies/pd_cluster.json` and `presets/gb300_agentx_pd.json`, the three promoted Kimi-K3 variants' index and GB300 PD files) and `presets/gb300_agentx_pd_dep16.json` is added. The GB300 PD default render changes only in the image and the flags and env vars listed above.
- Every value was taken from the PR-head recipes and checked against the dumped engine config of every worker in run [40239967341](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/40239967341) (all 8 disaggregated points): 1P3D c16 and 1P2D c24/c32 run the specialized decode (`--max-num-seqs 12`, capture 64, FP32 state, interleave 1, autotune off), 1P2D c48/c64, 2P3D c240 and 3P4D c240 run the regular decode (`--max-num-seqs 128`, `use_replayssm` on), every prefill runs `--max-num-seqs 32` with capture 8192 and `--gpu-memory-utilization 0.95`, and the 3P1D c336 workers match the new preset. The rendered prefill/decode argv of both presets equal the lane's logged launch commands (c32 and c336) apart from the synthetic acceptance settings, `--kv-transfer-config`/`--kv-events-config` (runbook), node addresses, and builder flags that restate the lane's effective values: `--no-disable-hybrid-kv-cache-manager` (no HMA auto-disable in the logs), `--max-num-batched-tokens 16384` on the xPyD pools (the logs show `max_num_batched_tokens=16384`), and the xPyD preset's existing autotune, prefix-cache and hybrid-LB undo flags.

## Details

Excluded as InferenceX-only or cluster-specific: concurrency lists, synthetic acceptance (`rejection_sample_method: synthetic`, `synthetic_acceptance_length`), AIPerf and trace-replay settings, `--served-model-name`/local model path, `--dump-config-to`, Slurm and container options, health checks, `VLLM_SERVER_DEV_MODE`, `TILELANG_CLEANUP_TEMP_FILES`, `WITH_NVIDIA_PEERMEM`, `NCCL_NET_PLUGIN`, the lane's `NVSHMEM_HCA_LIST`/UCX device lists and DP RPC port (site values; the runbook keeps placeholders). The aggregated TP16 c1 point of #4516 is an image-only bump and stays covered by the `gb300_low_latency` preset's `tp16` point.
