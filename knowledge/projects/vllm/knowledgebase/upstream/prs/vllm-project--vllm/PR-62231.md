# [Bugfix] Fix ShardedStateLoader round-trip for attention/KV-cache scale params

[Upstream PR](https://github.com/vllm-project/vllm/pull/62231) · state: open · merged: False

## Original PR description

## Purpose

Fixes #62156.

Every `Attention` layer creates `k_scale`, `v_scale`, `q_scale`, `prob_scale` (and `k_zero_point` / `v_zero_point` in `CompressedTensorsKVCacheMethod`) as `nn.Parameter`s in `create_weights`. During `process_weights_after_loading`, `BaseKVCacheMethod` and `CompressedTensorsKVCacheMethod` copy positive scales into the registered buffers `_k_scale`, `_v_scale`, `_q_scale`, `_prob_scale` (plus `_*_scale_float` and `_*_scale_cpu`) and `delattr` the original `nn.Parameter` attributes.

When `save_sharded_state` saves `model.state_dict()`, the shard files contain the post-processing buffer keys (`...attn._k_scale`, etc.) rather than the parameter keys (`...attn.k_scale`, etc.). Reloading with `load_format="sharded_state"` then fails in `ShardedStateLoader.load_weights` with `ValueError: Missing keys ['...attn.q_scale', '...attn.k_scale', '...attn.v_scale', '...attn.prob_scale']`.

This PR:
1. Wraps `ShardedStateLoader.load_weights` in `set_weights_pre_processed(True)` (matching `RunaiModelStreamerLoader`) and maps any parameter `<prefix>.<attr>` whose post-processed buffer `<prefix>._<attr>` is in the checkpoint to that buffer while removing the consumed parameter (and unused `*_zero_point` parameter).
2. Updates `BaseKVCacheMethod.process_weights_after_loading` and `CompressedTensorsKVCacheMethod.process_weights_after_loading` to sync `_*_scale_float` and `_*_scale_cpu` directly from the loaded `_*_scale` buffers when `is_weights_pre_processed()` is set.

## Test Plan

- Added `test_sharded_state_loader_kv_cache_scales_round_trip` (covering both `BaseKVCacheMethod` tensor scales and `CompressedTensorsKVCacheMethod` per-head `attn_head` scales) in `tests/model_executor/model_loader/test_sharded_state_loader.py`.
