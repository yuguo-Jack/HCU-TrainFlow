# [CI] Keep a per-PR 2-GPU core of the NIXL PD accuracy sweeps

[Upstream PR](https://github.com/vllm-project/vllm/pull/62579) · state: closed · merged: True

## Original PR description

## Overview

#62564 moved the 4-GPU L4 PD-disagg accuracy steps to nightly-only, leaving PRs without NVIDIA-side PD accuracy coverage (the AMD mirrors still run on PRs per #62567). This adds one automatic 2-GPU L4 step that keeps a core set of NIXL PD paths and architectures running on every PR, with prefill and decode sharing GPUs where needed to stay within the 2-GPU budget.

Not a duplicate of #62568, which shards the nightly-only 4-GPU sweeps themselves; this PR restores per-PR coverage at a smaller scale.

## Claims

- A single new automatic step, `(L4) NixlConnector PD accuracy core` (`nixlconnector-pd-accuracy-core-2-gpus`), runs 10 configurations on a 2-GPU L4 pod (~2.5-2.7 GPU-h per PR) covering every model family in the NIXL PD suite that fits a 24 GB L4:

| # | Config | Model | Path / architecture covered | P / D GPUs | Util |
|---|---|---|---|---|---|
| 1 | TP1/TP1 | Qwen3-0.6B | Dense GQA baseline, pull connector | 0 / 1 dedicated | 0.6 |
| 2 | P-TP1 / D-TP2 | Qwen3-0.6B | Hetero-TP, decoder TP>1 | 0 / 1,0 shared | 0.35 |
| 3 | P-TP2 / D-TP1 | Qwen3-0.6B | Hetero-TP, prefiller TP>1 | 0,1 / 0 shared | 0.35 |
| 4 | DP-EP (P-TP1, D-DP2) | deepseek-vl2-tiny | MoE expert parallel + DP-attention decode | 0 / 1,0 shared | 0.4 |
| 5 | Push PP2xTP1 | Qwen3-0.6B | NixlPushConnector, PP prefill layer slicing | 0,1 / 0,1 shared | 0.35 |
| 6 | SLEEP_WAKE TP1/TP1 | Qwen3-0.6B | Sleep/wake round-trip before serving | 0 / 1 dedicated | 0.6 |
| 7 | TP1/TP1 | deepseek-vl2-tiny | MLA KV transfer | 0 / 1 dedicated | 0.8 |
| 8 | TP1/TP1 | granite-4.0-h-tiny | Hybrid SSM Mamba2 conv state (+ small MoE) | 0 / 1 dedicated | 0.8 |
| 9 | TP1/TP1 | Qwen3.5-0.8B | Hybrid SSM GDN conv state | 0 / 1 dedicated | 0.8 |
| 10 | TP1/TP1 | gemma-4-E2B-it | Sliding-window attention + model-native cross-layer KV sharing (`num_kv_shared_layers: 20`) | 0 / 1 dedicated | 0.8 |

- The gemma config was previously unreachable: no CI step ever set `SW_ATTN`, so gemma PD accuracy had no coverage anywhere, including nightly. Sleep/wake previously ran nightly only (inside the 4-GPU step).
- `run_accuracy_test.sh` is unchanged; all engine launch logic is reused. The new sweep script follows the existing `config_sweep_*` pattern.

## Validation

No GPUs were available locally, so validation was static plus the `/ci run` below:

- `pre-commit` hooks pass on the commit (shellcheck with the repo rcfile, Buildkite key check, test tethering).
- Stubbed dry-run of the sweep script executes all 10 configs with the intended env and args (verified by capturing the `run_accuracy_test.sh` invocations).
- GPU-assignment math from `run_accuracy_test.sh` simulated for a 2-GPU pod: shared configs peak at 0.7-0.8 memory fraction per GPU (two engines), dedicated configs at 0.6-0.8. DeepSeek-VL2-Tiny is ~6.5 GB bf16 (3B total / 1B activated), fitting two engines on one 24 GB L4 at 0.4.
- `google/gemma-4-E2B-it` HF config verified to declare `num_kv_shared_layers: 20`, and vLLM consumes that key natively (`add_kv_sharing_layers_to_kv_cache_groups`), so config 10 exercises cross-layer KV sharing without any extra flag.
- First `/ci run nixlconnector-pd-accuracy-core-2-gpus` is the real gate: configs 2-5 (P/D GPU co-location) and 10 (first-ever execution of the gemma PD config) have never run on hardware.

## Details

- Sharing mechanics: `run_accuracy_test.sh` spreads engines modulo the visible GPUs, so on a 2-GPU pod every TP>1 config co-locates prefill and decode ranks. Shared configs cap `--gpu-memory-utilization` at 0.35 (0.4 for vl2-tiny) so two engines fit side by side on 24 GB L4s; Qwen3-0.6B is ~1.2 GB bf16 per TP1 engine.
- Left in the nightly-only 4-GPU sweeps: TP2/TP2, FlashInfer, Mamba1, the wider cross-layer and SW sweeps, MoE DP-EP variants at higher util. Cross-layer layout keeps per-PR coverage via the existing 2-GPU MultiConnector step (normal + BLHNC).
- No AMD mirror on the new step: the MI300/MI355 mirrors of the nightly-only steps are `optional: false` (#62567) and already cover these paths on PRs.
- Known gap left out of scope: the NHD decoder layout (`enable_permute_local_kv`) is not wired to any CI step, nightly included. Worth a separate PR if that path matters.
- Follow-up option: once #62568 lands, this step could enroll in `automatic_shard` to cut wall time across jobs at the same GPU-hour cost.
