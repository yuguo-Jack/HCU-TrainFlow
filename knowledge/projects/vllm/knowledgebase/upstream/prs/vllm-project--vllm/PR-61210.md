# [Bugfix] Inherit target --revision/--code-revision for MTP draft; readable error for n_predict=0

[Upstream PR](https://github.com/vllm-project/vllm/pull/61210) · state: open · merged: False

## Original PR description



## Overview

Fixes #61197: with `method="mtp"` and no explicit draft model, the draft is the target checkpoint itself, but the draft `ModelConfig` was built with the speculative config's own (unset) `revision`/`code_revision`, so config and weights resolved from the repo's default branch instead of the target's `--revision`. This PR inherits both from `target_model_config` (unless explicitly overridden), mirroring the existing `model`/`quantization` inheritance. It also replaces a `ZeroDivisionError` with a readable `ValueError` when a draft checkpoint resolves to `n_predict=0`.

## Claims

- MTP draft config/weights now resolve from the target's `--revision`/`--code-revision` instead of the default branch (regression vs 0.29).
- Explicitly set speculative `revision`/`code_revision` still take precedence over the inherited values.
- Other speculative methods (e.g. `dspark`, separate `draft_model` checkpoints) are unaffected.
- A draft checkpoint with `n_predict=0` (missing `num_nextn_predict_layers`) now raises a readable `ValueError` instead of `ZeroDivisionError`.

Model evaluation is not applicable: this is a config-time-only change that does not affect model outputs, accuracy, or serving behavior.

## Details

**Root cause:** in `SpeculativeConfig.__post_init__`, the `method == "mtp"` branch sets `self.model` from `target_model_config.model_weights or .model` and inherits `quantization`, but leaves `self.revision`/`self.code_revision` as `None`. The draft `ModelConfig(...)` built later passes `revision=self.revision` / `code_revision=self.code_revision`, so the draft resolved config and weights from the default branch rather than the target's pinned revision.

**Design decision:** inheritance is placed next to the existing `model`/`quantization` inheritance and guarded by `is None` checks, so explicit values remain overrides. It intentionally applies only when no explicit draft model is given (i.e. the draft *is* the target checkpoint); a separately provided draft checkpoint is a different repo and keeps its own revision. The `n_predict == 0` guard sits at the top of the existing `elif n_predict is not None:` branch, so `dspark` (separate branch) and valid `n_predict > 0` behavior are unchanged.
