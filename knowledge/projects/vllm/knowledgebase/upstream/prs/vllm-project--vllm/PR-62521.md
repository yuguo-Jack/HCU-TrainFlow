# [Core] Don't apply spec decode async scheduling fallbacks with MRV2

[Upstream PR](https://github.com/vllm-project/vllm/pull/62521) · state: closed · merged: True

## Original PR description

The speculative decoding checks that disable (or reject) async scheduling, for unsupported methods such as CPU ngram and suffix decoding and for disable_padded_drafter_batch=True, are only limitations of the V1 model runner. Model Runner V2 handles these with async scheduling, but they were still forcing it off (or raising when it was explicitly enabled).

This meant that for example async scheduling was being incorrectly disabled by default with "ngram" spec decoding.

Consolidate these together with the existing V1 + pipeline parallelism check into a single V1-only incompatibility that is used both for the default fallback and for the explicit-enable validation.
