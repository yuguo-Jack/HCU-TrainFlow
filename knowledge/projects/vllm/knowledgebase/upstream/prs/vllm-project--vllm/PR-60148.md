# [Metrics][Frontend] Count non-streaming requests that fail during generation

[Upstream PR](https://github.com/vllm-project/vllm/pull/60148) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Counts non-streaming requests that fail after input processing (e.g. in the tool call parser while building the response) under their own stage, `vllm:request_failure_total{stage="non_streaming"}`.

**Stacked on #60147** (which is stacked on #60145) — only the last commit is new. Draft until those merge.

## Claims

- A non-streaming request that fails after generation started is counted with `stage="non_streaming"` and its HTTP status code.
- It is no longer indistinguishable from a request rejected during input processing.

## Validation

```
.venv/bin/python -m pytest tests/entrypoints/serve/middleware/test_request_failure_metrics.py tests/entrypoints/openai/chat_completion/test_chat_error.py tests/entrypoints/serve/exception_handling -q
84 passed
```

- The middleware test checks that a route failing after `mark_generation_started` records one `non_streaming` failure and no `input_processing` failure.
- A chat serving test checks that a non-streaming chat request that fails during generation has the marker set, so the middleware attributes it correctly.

This stage was not triggered against a live server: there is no simple way to make a real parser fail on demand. Validation is unit-level only.

## Details

#60145 added a marker that chat (and Anthropic through it), completions, responses and tokens-in-tokens-out set just before producing a non-streaming response, and excluded marked requests from `input_processing`. This PR counts them as `non_streaming` in the same middleware.

**Limitations.**
- Pooling and speech-to-text endpoints do not set the marker.
- Validation performed inside the engine (`AsyncLLM.add_request`) surfaces after the marker, so a 4xx can appear under this stage; the `code` label distinguishes it.
- The stage counts what the client saw, so engine `finish_reason=error` on a non-streaming request is counted here as well as in `vllm:request_success`.

This PR is small on its own; it can be folded into #60145 if reviewers prefer.

**Not a duplicate.** Searched open PRs for `frontend error metrics`, `request failure counter`; nothing overlapping.
