# [Bugfix] Serialize YAML list items that are mappings as JSON in --config

[Upstream PR](https://github.com/vllm-project/vllm/pull/65616) · state: open · merged: False

## Original PR description



## Overview

`vllm serve --config cfg.yaml` turns a YAML list item that is a mapping into a Python repr (`{'name': ...}`) instead of JSON. As a result, JSON-valued list arguments such as `--lora-modules` cannot be written as YAML mappings and fail with `Invalid JSON format for --lora-modules`. This PR serializes those items with `json.dumps`, the same way top-level mapping values are already handled.

Related: #9655 (closed as not planned; it covered YAML LoRA lists before list support existed). #23528 added support for lists of strings, but mappings inside lists were never handled.

## Claims

- The YAML config below now loads two `LoRAModulePath` entries. Before this change, startup failed with `serve: error: Invalid JSON format for --lora-modules: {'base_model_name': ..., 'name': ..., 'path': ...}`.

  ```yaml
  lora-modules:
    - sql-lora=jeeejeee/llama32-3b-text2sql-spider
    - name: sql-lora-2
      path: jeeejeee/llama32-3b-text2sql-spider
      base_model_name: meta-llama/Llama-3.2-3B-Instruct
  ```
- Scalar list items (`- item`, `name=path`) are unchanged.

## Details

**Root cause:** in `FlexibleArgumentParser.load_config_file`, the `list` branch emitted `str(item)` for each item. The `dict` branch just below already emits `json.dumps(value)` because CLI parsers expect JSON. A mapping inside a list therefore reached `LoRAParserAction` as a single-quoted repr containing commas, so it took the JSON branch and `json.loads` failed.

**Fix:** list items that are `dict` or `list` are now emitted with `json.dumps`. Everything else still uses `str()`.

**Compatibility:**
- `load_config_file` has a single caller, `_pull_args_from_config`.
- A mapping inside a list could never be parsed before, so no working config changes.
- Nested lists of numbers serialize the same either way (`[1, 2]`).
- No argument parses Python-repr list items.

**CI:** the `Entrypoints Unit` step runs `tests/entrypoints/common`. I added `vllm/utils/argparse_utils.py` to its `source_file_dependencies` so that changes to the parser alone also trigger these serve `--config` tests.

**Docs:** `docs/configuration/serve_args.md` now shows that lists become repeated values and nested mappings become JSON, using `--lora-modules` as the example.

**Not a duplicate:** I searched open and closed PRs and issues on vllm-project/vllm for `load_config_file`, `_pull_args_from_config`, `config yaml list of dicts`, `lora-modules yaml`, `config.yaml lora_modules`, `FlexibleArgumentParser list`, and `config list items json`. The open `--config` PRs cover different bugs:
- #49057 and #58102: YAML `false` values are dropped.
- #43548: `--config=<path>` is ignored.
- #51623, #52077, #60319: empty or invalid YAML files.
- #62215, #58096: negative float values on the CLI.
- #60329: JSON-serializes list values in `vllm bench sweep`, which is a different code path.

#54216 (closed, not merged) bundled several `--config` fixes but did not touch list items. No open PR changes the list-item serialization in `load_config_file`.
