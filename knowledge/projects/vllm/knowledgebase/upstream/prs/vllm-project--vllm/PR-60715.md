# [CI][Test] Allow 10% ngram acceptance drop under preemption on CUDA in test_async_scheduling_accuracy

[Upstream PR](https://github.com/vllm-project/vllm/pull/60715) · state: closed · merged: True

## Original PR description

## Purpose

`tests/v1/e2e/general/test_async_scheduling_accuracy.py::test_with_ngram_gpu_spec_decoding` compares each spec-decode config's acceptance against the first (no-preemption) config, allowing a 5% relative drop on CUDA. The **preemption** configs sit right at that floor and flip between passing and failing. That happens on `main` too, not only on torch-bump PRs:

| Build | Lane | Acceptance vs baseline | Drop |
|---|---|---|---|
| [92956](https://buildkite.com/vllm/ci/builds/92956) | `main` (torch 2.13) | 0.0679 vs 0.0727 | 6.6% |
| [93148](https://buildkite.com/vllm/ci/builds/93148) | torch 2.14.1 PR (#52183) | 0.0679 vs 0.0727 | 6.6% |
| [93349](https://buildkite.com/vllm/ci/builds/93349) | torch 2.14.1 PR (#52183) | 0.0705 vs 0.0765 | 7.8% |
| [93464](https://buildkite.com/vllm/ci/builds/93464#01a118e1-24b0-4de4-ae95-0a54dcb719a8) | torch 2.15.0 RC PR (#60324) | 0.0724 vs 0.0765 | 5.3% |

Preemption recomputes requests and loses their n-gram drafts, which is why ROCm already gets a 10% allowance for preemption configs. This applies the same allowance on CUDA. Non-preemption configs keep the 5% floor.

## Test Plan

Test-only change. `ruff check` and `ruff format --check` pass on the file. Every failing data point above is within the new 10% allowance; the non-preemption assertions are unchanged.

## Test Result

The same change has been carried on the torch 2.14.1 (#52183) and 2.15.0 (#60324) bump PRs. Landing it here removes the flake from `main` and lets both PRs drop their copy.

Tracking: pytorch/test-infra#9075.
