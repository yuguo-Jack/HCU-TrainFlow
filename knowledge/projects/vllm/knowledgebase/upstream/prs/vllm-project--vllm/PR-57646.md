# [KV Offload] Expose the processed prefix at request finalization

[Upstream PR](https://github.com/vllm-project/vllm/pull/57646) · state: open · merged: False

## Original PR description

## Purpose

[#51787](https://github.com/vllm-project/vllm/pull/51787) (f12fe10c5c) removed repeated scheduler touch() calls and introduced key positions for request-scoped recency handling. Those positions can include the full prompt before execution completes, so they cannot distinguish the processed prefix from an untouched suffix when a request terminates early.

Expose num_computed_tokens, num_in_flight_tokens, num_prompt_tokens, and num_tokens as read-only ReqContext properties that delegate to Request and stay up to date. These allow offload backends to derive the processed-prefix boundary, excluding in-flight work and the uncommitted final sampled token. Contexts without an associated Request return None. The complete key-position map remains available for outstanding transfers.

Since ReqContext now retains a reference to Request, release completed-batch context references in the async lookup worker before it waits for another batch.

This is separate from [#54979](https://github.com/vllm-project/vllm/pull/54979) and [#43569](https://github.com/vllm-project/vllm/pull/43569), which address GPU cache registration and rollback, and [#52103](https://github.com/vllm-project/vllm/pull/52103), which carries provenance through stored events. This PR exposes metadata; it does not change existing eviction policies.

## Test Plan

- Added a scheduler context test checking that token counts reflect subsequent request updates and return None for contexts without a request.
- Added an async lookup regression test checking that completed request contexts are released while the worker remains idle.
