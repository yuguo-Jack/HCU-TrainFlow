# [RL] Declare weight ownership and layout on ParamMeta

[Upstream PR](https://github.com/vllm-project/vllm/pull/63256) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Implements steps 1–3 of RFC #63215: a `WeightSource` now declares which trainer ranks own each parameter, and how it is laid out across them, on `ParamMeta`. Every engine plans from that declaration instead of a runtime exchange, and a source exposes `iter_full()` and/or `iter_local()` instead of one iterator plus per-backend hooks (`held_names`, `groups`, `M2NWeightSource`).

Step 4 (NCCL broadcast from more than one sender, i.e. pipeline-parallel trainers on NCCL) is left to #62557, which this makes simpler: the per-sender plan can be read straight off `ParamMeta.owners`.

## Claims

- **One ownership declaration for every backend.** `ParamMeta` gains `owners` (global trainer ranks), `mesh_shape` and `placements` (`Replicate` / `Shard`, `torch.chunk` semantics). Metadata is identical on every rank, so engines plan without exchanging it.
- **Two explicit iteration modes.** `iter_full()` yields `(name, full tensor)` and `iter_local()` yields `(name, this rank's piece)`, each only for the names the rank owns, in metadata order. NCCL broadcast, IPC and sharded RDT use `iter_full()`; NCCL M2N uses `iter_local()`. Each engine checks the mode it needs at `trainer_init` (`source.implements_iter_full()` / `implements_iter_local()`).
- **`ModuleSource` covers plain, FSDP2 and DTensor modules for every backend.** It reads owners and placements from each DTensor's mesh, which replaces the M2N-specific `DTensorModuleSource`.
- **Sharded RDT keeps partial ownership** (pipeline stages, expert parallelism, or both), now from `owners` instead of `held_names()`. A rank still gathers and serves only the experts it holds.
- **Engines reject layouts they cannot send at `trainer_init`:**
  - NCCL: every parameter's first owner must be rank 0, its single sender.
  - IPC: every rank must own every parameter.
  - M2N: owners must be all trainer ranks, with at most a 2-D mesh.
  - RDT: owner ranks must exist, and metadata must agree across ranks (digest).
- **`WeightSource.metadata` is a `functools.cached_property`, enforced when the subclass is defined.** Engines read it repeatedly and it must not change.
- **Docs:** `base.md` rewrites the `WeightSource` section, and every engine page gains a Limitations section stating which trainer layouts it accepts. Only sharded RDT takes pipeline-parallel trainers today.

## Details

**Why declare ownership.** Each backend had grown its own way to say which rank holds what: `held_names()` plus an all-gather for sharded RDT, `M2NWeightSource` with per-parameter layouts for M2N, and nothing for NCCL and IPC. Declaring it once on `ParamMeta`, identically on every rank:

- gives every engine the same plan without a runtime exchange;
- lets a backend reject a layout it cannot send up front;
- is what multi-sender NCCL (#62557) and partitioned M2N (#62853) need as input.

**Owned-only iteration.** A rank iterates only what it owns. For Megatron PP=2, that is exactly what each stage can produce without communicating. A framework that broadcasts every weight to every stage can declare `owners=None` and do that broadcast inside `iter_full()`, which keeps NCCL working today. Either mode may run collectives among a parameter's owners, such as an FSDP all-gather per tensor or per layer.

**Per-tensor yields cost nothing when the source gathers in batches.** On main, `iter_groups()` existed because one collective per tensor is slow on a per-expert MoE (~37k tensors). The saving comes from batching the gather, not from yielding a group per generator resume. A source can still gather a layer at a time and yield its tensors one by one (the bench's `DeclaredGatherSource` does). Microbenchmark, 2×GB200, 37,050 tensors in 95 groups, each sharded across 2 ranks and all-gathered, median of 3 after warmup:

| Source | Time per sync |
| --- | --- |
| one all-gather per tensor | 4514 ms |
| one all-gather per group, yielded per tensor and regrouped as `_iter_owned_groups` does (this PR) | 577 ms |
| one all-gather per group, yielded per group (main's `iter_groups` override) | 591 ms |

**Breaking changes to the trainer-side API**, which shipped in recent releases:

- `WeightSource.__iter__`, `held_names()`, `groups()` and `iter_groups()` are removed; implement `iter_full()` and declare `owners`.
- `vllm/distributed/weight_transfer/m2n_source.py` (`M2NWeightSource`, `ManifestM2NWeightSource`, `DTensorModuleSource`) is removed; use `ModuleSource`, or a `WeightSource` with `iter_local()` and declared placements. M2N sources now yield torch tensors only; the raw-pointer / CUDA array interface buffers from #60934 are dropped.
- `metadata` changes from a method to a `cached_property` (`source.metadata`, not `source.metadata()`).
- Sharded RDT now requires `TrainerInitInfo.rank` to equal the default process group rank, and raises at `trainer_init` if it does not. It used to take the rank from `torch.distributed` and ignore `TrainerInitInfo.rank`. Owners are declared in `TrainerInitInfo.rank` numbering, and the producer servers are gathered over the default group, so the two must agree.

**Limitations:**

- NCCL and IPC still reject pipeline-parallel trainers (documented as in progress).
- M2N accepts only sources owned by all trainer ranks (#62853 is the follow-up).
- `ModuleSource` declares DTensors with `Partial` or strided (FSDP+TP) placements as replicated, and gathers them in `iter_local()`.

**Not duplicating existing work.** This implements RFC #63215; no other open PR does. #62557 (NCCL per-update source ranks) and #62853 (partitioned M2N source groups) are follow-ups that would build on `ParamMeta.owners` rather than their own ownership plumbing.
