# [ROCm][Kimi-K3] Support MoRIIO consumers with specialized decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/63031) · state: closed · merged: True

## Original PR description

## Overview

Enable Kimi-K3 specialized decode with MoRIIO READ/WRITE on the decode node, extending #60683 to P/D serving.

## Claims

- Support built-in MoRIIO consumers with the producer on `decode_backend=auto`.
- Reuse existing transfer completion without kernel or protocol changes.

## Validation

```bash
.venv/bin/python -m pytest -q tests/models/kimi_k3/amd_specialized_decode/test_runtime.py
.venv/bin/python -m pytest -q tests/v1/kv_connector/unit/test_moriio_tp_ack.py
```

48 and 40 tests passed. The four READ/WRITE × RDMA/xGMI acceptance cases fail without this change and pass with it.

Two-node MI355X, real Kimi-K3/DSpark weights, TP8/DCP8, K7, FULL decode graphs:

- GSM8K **10/10 in READ and WRITE**, with matching responses (5-shot completions, c1, temperature 0, seed 42, max 1,024 output tokens).
- Each mode transferred 6,354 prompt tokens; traces confirmed `k3_mono_kda_pre_s8` and `k3_mono_k2_s8`.

This is a short functional check. xGMI has configuration coverage only. Two-node serving was tested locally because CI provides one eight-GPU node.

## Details

Specialized layers skip per-layer transfer hooks. MoRIIO READ loads finish before forward (#60808); WRITE receives finish before scheduler admission. This PR enables that consumer path and leaves other connector configurations unchanged.

No overlapping open PR was found.
