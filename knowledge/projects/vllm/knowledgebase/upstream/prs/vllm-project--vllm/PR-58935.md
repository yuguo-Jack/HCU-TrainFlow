# [Bugfix][XPU] Enforce attention backend capability gates via validate_configuration

[Upstream PR](https://github.com/vllm-project/vllm/pull/58935) · state: open · merged: False

## Original PR description

## Purpose

`XPUPlatform.get_attn_backend_cls()` resolved an attention backend without ever calling `validate_configuration()`, while the CUDA and ROCm platforms both do. Because that validation was skipped, every capability gate the attention backends declare (head size, KV-cache dtype, block size, attention sinks, mm_prefix, batch invariance, PCP/DCP, ...) was dead code on XPU: an unsupported configuration was accepted and run, and what broke next depended on the gate it skipped. This is also why several XPU attention problems have surfaced as silent wrongness instead of a clean startup error.

This wires the same validation into the XPU platform:

- every routing point validates the resolved backend before committing to it;
- the auto-selected FlashAttention backend falls back to Triton Attention once when validation fails (the two cover the same non-MLA workloads on XPU), and the fallback is validated as well;
- an explicitly requested backend must be valid, otherwise startup fails with the reasons;
- an explicit FlashAttention request combined with batch invariance or a multimodal prefix now raises with a clear error instead of warning and silently running a backend that cannot honor it.

So the shared gates can run with XPU's missing device capability (`get_device_capability()` returns `None` on XPU), `FlashAttentionBackend.supports_compute_capability()` and the sm90-sink check in `supports_combination()` now treat `None` as "not applicable" instead of raising a `TypeError`.

Fixes #58913

## Test Plan

```bash
pytest tests/platforms/test_xpu_attn_backend_selection.py
```

The new tests cover: validation raising for an unsupported head size, the auto-selection fallback, the loud failures for explicit FlashAttention + batch invariance / mm_prefix, unchanged routing for float32 / batch-invariant / mm-prefix auto-selection, and the capability-free validation path of the shared FlashAttention gates.

## Test Result

```
13 passed in 3.64s (tests/platforms/test_xpu_attn_backend_selection.py)
```

Together with the existing `tests/platforms/test_cpu.py`, the 30-test platforms suite passed 3 consecutive local runs on CPU. The change is control-flow only, so no GPU execution is needed to verify it.
