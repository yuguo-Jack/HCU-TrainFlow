# [CI] Bump Transformers version to 5.20.0

[Upstream PR](https://github.com/vllm-project/vllm/pull/61983) · state: open · merged: False

## Original PR description

## Overview

Bump Transformers to [v5.20.0](https://github.com/huggingface/transformers/releases/tag/v5.20.0). Follows #60381.

## Claims

- `requirements/common.txt` allows `transformers >= 5.16.1, < 5.21.0`.
- Test requirements pin `transformers==5.20.0` (cuda, rocm, xpu, cpu, nightly-torch).
- `min_transformers_version="5.20.0"` on `Kolibri1ForCausalLM` is kept, since 5.16.1 to 5.19.x are still supported. The `transformers-upgrade` skill now says to keep such gates until the floor reaches them, instead of removing them on a pin bump.

## Validation

- `pre-commit run` on the changed files passes. The `pip-compile` hooks for cuda, rocm, xpu and cpu resolve 5.20.0 and leave the hand-edited lock files unchanged.
- `pytest tests/transformers_utils tests/config tests/tokenizers_` on 5.20.0 (macOS, no GPU): 1202 passed, 253 skipped, 2 failed. Neither failure is from this change: `test_ray_runtime_env` needs Ray, and `test_mp_reducer` can't start an engine on this machine (it fails the same way on 5.19.0).
- Checked against the 5.20 breaking changes:
  - Every vendored config that declares `sub_configs` builds and round-trips through `to_dict()` (`SubConfigSpec`, huggingface/transformers#48282).
  - The `embedding_gemma2` imports vLLM uses still resolve (huggingface/transformers#49473).
- Model compatibility with 5.20.0 is being checked by the CI run on this PR.
