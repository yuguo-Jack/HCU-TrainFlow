# [Feature][Whisper] Native word-level timestamps (cross-attention + DTW)

[Upstream PR](https://github.com/vllm-project/vllm/pull/47664) · state: open · merged: False

## Original PR description


Whisper accepts `timestamp_granularities[]=word` today, but `words` always comes
back `null`. This fills it in.

```bash
vllm serve openai/whisper-large-v3-turbo --enable-word-timestamps

curl localhost:8000/v1/audio/transcriptions \
  -F file=@mary_had_lamb.ogg -F model=openai/whisper-large-v3-turbo \
  -F response_format=verbose_json -F 'timestamp_granularities[]=word'
```

**Before**

```json
{
  "text": " The first words I spoke in the original phonograph...",
  "words": null
}
```

**After**

```json
{
  "text": " The first words I spoke in the original phonograph...",
  "words": [
    {"word": "The",   "start": 0.52, "end": 0.88},
    {"word": "first", "start": 0.88, "end": 1.60},
    {"word": "words", "start": 1.60, "end": 2.02},
    {"word": "I",     "start": 2.02, "end": 2.26},
    {"word": "spoke", "start": 2.26, "end": 2.66}
  ]
}
```

Off by default; nothing runs without `--enable-word-timestamps`.

## How

Whisper never emits word boundaries as tokens — they live in the decoder's
cross-attention. Instead of asking a fused backend for its attention
probabilities, this records **Q** (and the encoder **K** at prefill) just before
the fused call, then recomputes `softmax(Q·Kᵀ)` for the `alignment_heads` only,
median-filters it and runs a DTW. Same method as OpenAI Whisper and WhisperX.

No second model, no second forward pass, no attention-backend change, and it
runs with CUDA graphs and `torch.compile` on. The recording is a registered
custom op writing into static buffers, so it stays opaque to Dynamo and safe
under graph replay.

Code lives in `vllm/v1/worker/gpu/word_align.py` and attaches to the V2 model
runner by composition, like `gpu/kv_connector.py`. The runner side is four
lifecycle calls. The V1 runner is untouched.

Each request gets a capture slot from a bounded pool, and a request that finds
the pool full gets no timestamps. Only the layers that actually carry alignment
heads are allocated, and the pool is sized by a 2 GiB budget rather than a fixed
count, so checkpoints with few alignment layers cover a full batch while the
larger ones stay inside the budget:

| model | decoder layers | layers with alignment heads | slots within budget |
| --- | --- | --- | --- |
| `whisper-large-v3-turbo` | 4 | 2 | 215 |
| `whisper-large-v3` | 32 | 10 | 43 |
| `whisper-small` | 12 | 4 | 179 |

The pool is also capped at `max_num_reqs`, so it never allocates for more
requests than the server can run.

## Benchmark

H200, a `large-v3-turbo`-architecture checkpoint, 40 short clips (median ~2 s)
replayed at concurrency 32. `verbose_json` is the baseline because word
timestamps require it — it is ~25% slower than plain `json` on its own, with or
without this feature. Each row is the mean of two passes after a discarded
warm-up pass; runs repeat to within ±2%.

| server | request | KV cache | throughput |
| --- | --- | --- | --- |
| flag off | `verbose_json` | 89,033 tok | 61.6 req/s |
| flag on | `verbose_json` | 85,767 tok | 38.6 req/s |
| flag on | `+ word` | 85,767 tok | 37.4 req/s |

Single-request latency is unchanged within measurement error (~70 ms either
way); the cost only shows up under concurrency.

Two things to note. Asking for words is nearly free once the flag is on (38.6 →
37.4). Turning the flag on costs ~39% throughput even for requests that never
ask for words, because the capture op is compiled into every decode step.
Disabling the copies inside the op does not recover it, so the cost is the op's
presence in the compiled graph rather than the work it does — making the opt-in
per-request instead of per-server is the obvious follow-up.

## Accuracy

- vs the OpenAI/HF `find_alignment` reference: mean |Δstart| **0.019 s** over 399
  words.
- vs an independent forced aligner over ~36k words: median |Δstart| **0.104 s**,
  identical word order. Close to a dedicated aligner, not a replacement for one.
- The change is additive: a new response field, no effect on sampling or on the
  generated text.

## Tests

```bash
pytest tests/models/multimodal/generation/test_whisper_word_align.py            # 15
pytest tests/entrypoints/speech_to_text/transcription/test_transcription_word_timestamps.py  # 4
```

Both pass on the default runner with CUDA graphs and `torch.compile` on. The
unit tests pin the median filter and the DTW **bit-identical** to transformers'
`_median_filter` and `_dynamic_time_warping`, plus the capture op's slot routing
and the slot pool. The e2e tests cover populated and monotonic `words[]` that
reconstruct the transcript, the per-request opt-in, and concurrent clips each
keeping their own timeline. Added to the `Model Runner V2 Core Tests` step so CI
runs them under `VLLM_USE_V2_MODEL_RUNNER=1`.

Also checked on `whisper-large-v3`, where alignment heads span 10 layers instead
of 2: same word count, monotonic, in bounds. Pool exhaustion: 100 concurrent
requests against 64 slots returned 0 errors, 98 with timestamps and 2 without,
none malformed.

> `verbose_json` doesn't support streaming response so it should have been faster?

No because they are not doing the same thing. Three things happen
on `verbose_json` that don't happen on `json`, and none of them are affected by
streaming (line numbers at the base commit, i.e. before this PR):

1. `sampling_params.logprobs = 1` unconditionally (`serving.py:586-587`), read
   only by `avg_logprob`;
2. per-segment `decode` + `zlib.compress` + a per-token `avg_logprob` walk
   (`_get_verbose_segments`, `:356-418`);
3. the decoder prompt is rewritten, `<|notimestamps|>` → `<|0.00|>`
   (`_preprocess_verbose_prompt`, `:319-333`), so **the model is asked to emit
   timestamp tokens** — more decode steps, on a different decode path.

Following up on the `verbose_json` numbers above, since they turned out to matter
for this PR directly.

Word timestamps require `verbose_json`, so until now every word-timestamp request
also paid for the segment machinery.  So a request that only asks for `timestamp_granularities[]=["word"]` can
skip all three. That is now in this PR, gated on a single predicate:

```python
def _needs_segments(self, request) -> bool:
    if request.response_format != "verbose_json":
        return False
    granularities = getattr(request, "timestamp_granularities", None) or []
    if not granularities or "segment" in granularities:
        return True
    # Word-only. Skip segments only if the words will really be produced;
    # otherwise (translation, or a model without word support) fall back
    # rather than answer with nothing at all.
    return not self._wants_word_timestamps(request)
```

One thing I want on the record rather than discovered by a user later. This is
cross-attention DTW is an *approximation* of where a word starts, not a measurement of it. It infers
onsets from where the decoder was attending, so it degrades exactly where the
attention itself is uncertain:

* **poor audio**  noise, low bandwidth, overlapping speakers;
* **gaps a VAD would not resolve**  long pauses, music or breath between words,
  anything where "when did the audio stop being speech" is itself ambiguous;
* **short function words**, which carry few frames of their own and tend to be
  pulled toward their neighbours; the frame-collapse cases above are the extreme
  form of this.

**Suggestion:** When the free-slot pool is exhausted, do not register overflow requests in `slot_of` at all — instead, leave them untracked so their Q/K capture tokens are still routed to the scratch slot (for padding purposes) but `compute_word_align` naturally skips them (since `req_slots.get(req_id)` returns `None` and the existing guard `if slot is None … continue` at whisper.py:1043 kicks in).

1. **Lines 7532-7536** — only assign a slot when the pool is non-empty; otherwise leave `rid` out of `slot_of`:
```python
            if rid not in slot_of:
                # FIFO (pop front) so a just-freed slot isn't reused immediately,
                # giving the async readout time to read it before reallocation.
                if self._wa_free:
                    slot_of[rid] = self._wa_free.pop(0)
                # else: overflow – leave untracked so compute_word_align
                # skips this request (slot will be None), avoiding
                # cross-request buffer aliasing on _wa_scratch.
```

2. **Line 7538** — change `slot_of[req_ids[ri]]` to `slot_of.get(req_ids[ri], self._wa_scratch)` so the `slot_per_ri` array still routes overflow requests' tokens to scratch for the GPU capture (no KeyError), while they remain absent from `slot_of` for the readout:

```python
            count=num_reqs,
        )
```

This way overflow requests simply lose word timestamps for that step (graceful degradation) instead of sharing the scratch buffer. No changes needed in `compute_word_align` — its existing `if slot is None` guard already handles this.

<details>
<summary>💡 Fix Suggestion</summary>

**Suggestion:** The closure returned by `_word_align_snapshot_fn` captures the Python dicts (`slots`, `npos`) but later reads shared GPU buffers (`_WORD_ALIGN_QBUF[slot]`, `_WORD_ALIGN_KBUF[slot]`, `_WORD_ALIGN_NFRAMES[slot]`) without synchronization. Under async scheduling, a freed slot can be reassigned and overwritten by the next step's forward pass before `compute_word_align` reads it, leaking cross-request data.

To fix this, the snapshot function should eagerly clone the GPU buffer slices for all currently-tracked slots at snapshot time (while they are still valid), and pass those cloned tensors into the closure instead of letting `compute_word_align` read from the shared global buffers later. Concretely:

1. In `_word_align_snapshot_fn`, for each `(rid, slot)` in `self._wa_slot_of`, clone `_WORD_ALIGN_QBUF[slot]`, `_WORD_ALIGN_KBUF[slot]`, and `_WORD_ALIGN_NFRAMES[slot]` into a per-request dict (e.g., `buf_snapshots[rid] = (qbuf_clone, kbuf_clone, nframes_val)`).
2. Pass this `buf_snapshots` dict into the closure alongside `slots` and `npos`.
3. Modify `compute_word_align` (or add an alternative entry point) to accept pre-cloned per-request buffer data instead of reading from the global `_WORD_ALIGN_QBUF`/`_WORD_ALIGN_KBUF` by slot index.

Alternatively, you could defer slot freeing: instead of freeing slots in `_word_align_build_indices` at the beginning of step N+1, defer the free until after the previous step's `compute_word_align` closure has executed. This avoids the clone cost but requires plumbing a 'pending free' list.

Either approach ensures the closure reads buffer data that belongs to the correct request, preventing cross-request information leakage.
