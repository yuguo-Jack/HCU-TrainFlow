# [Perf][Rust Frontend] Serialize SSE chunks before building the event

[Upstream PR](https://github.com/vllm-project/vllm/pull/65028) · state: open · merged: False

## Original PR description



## Overview

Build streamed SSE frames with `Event::data(serde_json::to_string(..))` instead of `Event::json_data(..)` in the chat completions, completions and generate routes. Same wire bytes, 1.9–2.7× less time per frame.

## Claims

- Per-frame SSE serialization is 46–62% faster (criterion bench table below).
- Wire output is byte-identical
- Heap operations per frame are not increased (5–7 on both paths)
- Reach: every streaming request on the Rust frontend

## Validation

Criterion, axum 0.8.8, Apple M-series, mimalloc, `critcmp` over one run (both variants in one binary and every case first asserts identical wire bytes through axum's `Sse` response):

| case | `json_data` (old) | `data(to_string)` (new) | speedup |
|---|---|---|---|
| content_token | 504.8 ns | 224.4 ns | 2.25× |
| reasoning_token | 503.7 ns | 223.2 ns | 2.26× |
| first_role | 554.3 ns | 246.6 ns | 2.25× |
| content_escapes | 557.8 ns | 239.3 ns | 2.33× |
| content_120B | 568.0 ns | 305.4 ns | 1.86× |
| finish | 616.0 ns | 254.6 ns | 2.42× |
| tool_args | 693.4 ns | 275.5 ns | 2.52× |
| logprobs_top5_token_ids | 2.13 µs | 799.7 ns | 2.66× |

Intervals were within ±1%, and a repeat run reproduced each variant within ~1%.

End to end, `vllm-rs` + `vllm-mock-engine` + `vllm-bench` (streaming chat, 2048 requests, 3 alternated rounds) showed about −8% server CPU and +6% req/s. That run was on a shared laptop under load, so treat it as directional only. I have no GPU end-to-end number.

Not a duplicate: searched open and closed PRs for `json_data`, `Event::data`, "Rust Frontend SSE" and "SSE serialization". The open PRs that touch these route files (#63926, #63739, #61275, #64573, #63481, #58783) do not edit these lines.

## Details

serde_json writes a chunk as dozens of small fragments; a typical 230-byte chat chunk takes 77 `write` calls, 59 of them 1–2 bytes. `json_data` passes each fragment straight to axum's `EventDataWriter::write_buf`, which repeats a newline/CR scan, a flag check and a `BytesMut` reserve per fragment, and regrows the buffer from capacity 0 as fragments arrive. Serializing into a `Vec` first makes those writes an inlined memcpy, and `data()` does one scan and one copy.

The cost is one extra temporary `String` per frame. The event buffer then grows in fewer steps, so total heap operations stay the same or drop by one. Output is identical because compact serde_json never emits a raw `\n` or `\r`.

AI assistance (Claude) was used to find this target while profiling the Rust frontend against the mock engine, draft the patch, and build the benchmark and identity check. I reviewed every line, traced where the win comes from in axum's and serde_json's source, and re-ran the tests and benchmarks above myself. I can answer for the change.
