# [Bugfix][Quantization] Count only checkpoint elements for padded online-quant MoE weights

[Upstream PR](https://github.com/vllm-project/vllm/pull/62103) · state: open · merged: False

## Original PR description

## Purpose

Online-quant MoE methods can pad the intermediate size (`fp8_per_block` rounds it up to 128, so Qwen3-30B-A3B with MoE TP 4 stores 256 instead of 192), but the online MoE weights did not set `weight_loader_numel` like `UnquantizedFusedMoEMethod` does. Layerwise loading therefore never saw a MoE layer as fully loaded and deferred all of them to `finalize_layerwise_processing`, keeping a bf16 copy of every expert weight on the device. This sets `weight_loader_numel` to the unpadded checkpoint size so each layer is processed as soon as it is loaded.

## Test Plan

New unit test in `tests/model_executor/model_loader/test_reload.py` (fails on main for the padded case). Qwen3-30B-A3B, `quantization="fp8_per_block"`, TP 4 on H200, layerwise reload with weights streamed one layer at a time: peak extra memory per GPU is 54.8 GiB (48 MoE layers pending until finalize) on main and 1.8 GiB with this change. Greedy outputs after reload are unchanged.

AI assistance (Claude) was used; all changes were reviewed by the submitter.
