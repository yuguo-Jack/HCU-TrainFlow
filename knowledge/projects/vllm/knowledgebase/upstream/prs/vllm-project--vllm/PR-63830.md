# [Core][Mamba] Remove mamba_cache_mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/63830) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Removes `mamba_cache_mode`. Since the `"all"` mode was removed (#58997, #60043), it can only be `"align"` (prefix caching on) or `"none"` (off), so Mamba code now reads `cache_config.enable_prefix_caching` directly. The `--mamba-cache-mode` flag was already a deprecated no-op scheduled for removal in v0.33.0; it is removed here too.

## Claims

- **One switch instead of two.** `CacheConfig.mamba_cache_mode`, `MambaSpec.mamba_cache_mode`, `EngineArgs.mamba_cache_mode`, `--mamba-cache-mode` and the `"align"`/`"none"` checks are gone (`vllm/`: 50 files, +199 / −201, including the four new errors and about 30 reworded comments; tests: 43 files, +176 / −302).
- **Behavior is unchanged** for every configuration where prefix caching is not switched off after startup.
- **Configurations that switched prefix caching off after startup now fail fast for Mamba models** instead of silently diverging (Details).

## Details

**Replacing the checks.** `MambaModelConfig` set `mamba_cache_mode` from `enable_prefix_caching`, and every model with Mamba layers runs it, either as a hybrid or as one of the attention-free Mamba architectures. So `mode == "align"` equals `enable_prefix_caching` wherever a `MambaSpec` exists:

- Mamba-only paths (layers, metadata builders, `MambaSpec`, `MambaManager`, Mamba connectors, V2 `mamba_hybrid`, warmup) read `enable_prefix_caching`. `MambaManager` reads its `enable_caching`.
- Paths shared with non-Mamba models must not change for a plain attention model with prefix caching, so they also check for Mamba layers:
  - `validate_block_size`'s chunked-MM check uses `model_config.is_hybrid`;
  - the V1 runner uses a new `mamba_prefix_caching`, set from `kv_cache_config.has_mamba_layers` in `initialize_kv_cache`.
- Helpers that took the mode (`mamba_get_block_table_tensor`, Kimi-K3's `_mamba_get_block_table_tensor`, `_reserved_block_count`) take `enable_prefix_caching: bool`.

**Prefix caching switched off after startup.** The old mode was fixed at startup, so it also covered three places that turn `enable_prefix_caching` off later, sometimes in only one process. Reading `enable_prefix_caching` directly there would let the scheduler and the worker disagree on the Mamba block layout. For models with Mamba layers these now raise and ask for `--no-enable-prefix-caching`:

| Where | Trigger | Process that flips it |
| --- | --- | --- |
| `Attention` / `MLAAttention.__init__` | `VLLM_BATCH_INVARIANT=1` with FLASHINFER or TRITON_MLA | worker only |
| `EngineCore` KV cache setup | non-causal attention layers | engine core only |
| `CpuPlatform.check_and_update_config` | MLA without AMX on CPU | both, after `mamba_block_size` was set for prefix caching |

Models without Mamba layers keep the old warning-and-disable behavior.

**Connectors.** The Mooncake store, offloading and UMBP checks that read the spec's mode now read `vllm_config.cache_config.enable_prefix_caching`. UMBP always builds a caching lookup coordinator for Mamba groups, so Mamba without prefix caching used to trip `MambaManager`'s mode assertion at startup; it now raises an explicit `ValueError`.

**Not covered by tests.** The four new `ValueError`s are guards on rare configurations and have no tests.

**Not a duplicate.** Searched open PRs for `mamba_cache_mode` / `mamba-cache-mode`; none removes it.
