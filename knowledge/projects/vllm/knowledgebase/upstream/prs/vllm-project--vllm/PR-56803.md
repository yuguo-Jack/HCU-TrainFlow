# [Bugfix][Quantization] Keep MXFP4 weight-only checkpoints on W4A16 path (#56770)

[Upstream PR](https://github.com/vllm-project/vllm/pull/56803) · state: open · merged: False

## Original PR description

## purpose

fixes #56770

compressed-tensors mxfp4 checkpoints with `input_activations: null` (llm-compressor `MXFP4A16`) were always built as `CompressedTensorsW4A4Mxfp4()`. on sm100+ that picks `FlashInferMxFp4LinearKernel` and quantizes activations the checkpoint never declared.

`_get_scheme_from_parts` now reads `input_quant` on the mxfp4 branch the same way the nvfp4 branch already does:

- `input_quant is None` builds `CompressedTensorsW4A4Mxfp4(use_a16=True)`, which passes `activation_quant_key=None` to `init_mxfp4_linear_kernel`, so it stays on the w4a16 marlin path
- mxfp4 activations keep the current w4a4 behavior
- any other activation format raises, same as nvfp4

this only covers the dense linear path. the fused moe side is #55232.

## why this is not a duplicate

- #55675 reads the same activation declaration but only logs a warning. it doesn't change which kernel runs.
- #55232 fixes the moe backend selection, not the dense scheme. both are needed, as @jlqibm noted on #56770.
