## Overview

Fix routed-expert output reconstruction when a complete block is still waiting for its hash under EAGLE/MTP lookahead hashing. Include these request-local pending blocks when returning routing rows alongside a cached prefix.

Related: [[#61589 — Lookahead block hashes for EAGLE prefix caching](https://github.com/vllm-project/vllm/pull/61589)](https://github.com/vllm-project/vllm/pull/61589).

## Claims

- Prevent assertion failures when requested routing rows span published blocks, unkeyed full blocks, and an incomplete tail.
- Preserve token order and return owned data that remains valid after buffer reuse.
- Add buffer, worker, and `LLM` regression coverage, and select the EAGLE regression in existing speculative-decoding CI jobs when auxiliary-output connector files change.

## Details
EAGLE/MTP lookahead hashing can delay a full block's hash until subsequent tokens are known. Its routing rows remain in pending_blocks, but the previous read path only consulted the incomplete tail. Reconstructing output after a prefix-cache hit could therefore trigger missing-request or unavailable-range assertions.

Pass the request's pending blocks into RoutedExpertsBuffer.read() and assemble the requested interval from pending blocks and the tail. Preserve complete-range validation and return an independent array so buffer reuse cannot overwrite returned rows. Pending blocks remain available for normal publication when their hashes arrive.
