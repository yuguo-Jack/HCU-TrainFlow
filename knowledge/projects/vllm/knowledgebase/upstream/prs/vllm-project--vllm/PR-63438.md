# [Perf][MRV2] Pickle new requests' block ids as int32 arrays

[Upstream PR](https://github.com/vllm-project/vllm/pull/63438) · state: open · merged: False

## Original PR description

## Overview

With the v2 model runner, send new requests' block ids to the workers as int32 arrays instead of pickled Python ints. The scheduler and its KV connectors keep the lists; the v2 block tables already stage int32 buffers as chunks (#62698).

## Claims

- CPU time to ship two 135K-token requests' block ids (42K ids, 10 KV cache groups) from the scheduler to a v2 worker, main vs this PR (ms):

  | | pickle (scheduler) | unpickle (worker) | staging (worker) | total |
  |---|---:|---:|---:|---:|
  | main | 0.44 | 0.74 | 0.61 | 1.79 |
  | this PR | 0.69 | 0.03 | 0.02 | 0.74 |

  The worker side runs before the DP sync in `execute_model`, where the other DP ranks wait.
- Block-table contents are unchanged. Only `NewRequestData` built for the v2 runner is packed; v1 and out-of-tree runners still receive lists.

## Validation

```bash
pytest tests/v1/core/test_output.py   # 8 passed (CPU), incl. the new pickle round-trip test
```

Array staging through `StagedWriteTensor` and `FusedStagedWriter` is covered by `tests/kernels/core/test_uva.py` on main.

End to end, from the earlier version of this PR (stacked on #59908, before #62698 made list staging cheaper; not re-run on this base): DeepSeek-V4.1-Flash 2P1D on 16x B200, AgentX traces (~130K-token prompts) at 2,048 sessions, MRV2, decode instance only:

| decode workers | without | with |
|---|---|---|
| block-table write > 5 ms | 2.6% of steps | 0% |
| block-table write p99 / max | 5.7 / 35.8 ms | 0.4 / 4.0 ms |
| decode GPU busy | 90.9% | 94.6% |
| per-user tok/s p10 / p50 | 96 / 104 | 99 / 106 |

## Details

- `NewRequestData.__getstate__` converts `block_ids` to `array('i')` when `pack_block_ids` is set; the scheduler sets it only in the v2 branch. The object itself is not modified, so scheduler-side readers (KV connectors' `build_connector_meta`) still see lists.
- The conversion moves ~0.25 ms to the scheduler's pickle and removes ~1.3 ms of unpickling and staging from each worker.
- #59908 (int32 token ids, now closed) is no longer a dependency. #62702 ships prompt token ids as int32 and does not touch block ids.
