# [CI] Enroll Spec Decode AL DSpark and UMBP Connector Integration in automatic sharding

[Upstream PR](https://github.com/vllm-project/vllm/pull/64788) · state: closed · merged: True

## Original PR description



## Overview

Enrolls two more jobs in `automatic_shard`, plus one AMD mirror: the Spec Decode AL DSpark nightly and its AMD mirror, and the standalone AMD UMBP Connector Integration step. No commands change.

## Claims

| Job | Plan |
|---|---|
| `spec-decode-dspark-nightly` | 2 shards (one file split by test) |
| its AMD mirror | 1 shard |
| `amd-umbp-connector-integration-mi355` | 1 shard |

- DSpark's three tests each load a different target and draft model, so splitting them repeats no model load. The extra cost is one job setup, and the slowest shard finishes in well under the step's current wall time.
- One-shard plans run the same tests as on main, as one job, and split by themselves once their tests grow.

## Validation

- Planned each job with ci-infra main's planner against main's timings.
- The sharding harness (each shard's commands run against a mock test tree, as a PR build and as main with the OTel wrapper) shows every DSpark test runs exactly once.
- `split_check.py` finds no step whose jobs each run the whole suite.
- DSpark was left out of #64569 after one build cost more machine time than main. Its logs show the extra time was model loading, which varies from host to host and shows up in main's own nightlies too, not work repeated by sharding.
- `/ci run`, plus a scoped build for the optional and AMD jobs it leaves out, on this head.

## Details

- **UMBP Connector Integration** is new on main and its tests fit in one job today.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job. Fallback-aware timeouts belong in a central timeout setting.
