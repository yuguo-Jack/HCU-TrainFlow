# [Bugfix][Attention] Enable masked NVFP4 XQA on SM120

[Upstream PR](https://github.com/vllm-project/vllm/pull/53543) · state: open · merged: False

## Original PR description

## Overview

Retain masked NVFP4 XQA regression coverage and resolve query dtypes after decode-kernel selection and fallbacks. Rebased onto `main` at `6a95c89c371939997d9ce3b616360b529760f0bc` on 2026-10-30.

## Claims

- Query dtype selection follows the resolved XQA/native route.
- The SM12x-gated GPU regression compares packed-mask NVFP4 XQA with BF16 FA2 over dequantized KV.
- Constructor coverage includes both the native FA2 route now on main and the earlier TRTLLM route, including head-dimension fallback and the native FA2 DCP rejection.

## Validation

RTX 5090 / SM120, Python 3.12, PyTorch 2.13.0+cu130, FlashInfer 0.7.0.post1. Tests used the rebased Python source with precompiled vLLM extensions reused from the previous local test environment.

```bash
.venv/bin/python -m pytest -q tests/v1/attention/test_attention_backends.py \
  -k nvfp4_decode_dtype_after_fallback
# 12 passed, 160 deselected

.venv/bin/python -m pytest -q \
  tests/kernels/attention/test_flashinfer.py::test_flashinfer_xqa_nvfp4_spec_decode_with_baseline
# 1 passed on RTX 5090 / SM120

.venv/bin/python -m pre_commit run --files \
  tests/kernels/attention/test_flashinfer.py \
  tests/kernels/attention/test_flashinfer_trtllm_attention.py \
  tests/kernels/quantization/nvfp4_utils.py \
  tests/v1/attention/test_attention_backends.py \
  vllm/v1/attention/backends/flashinfer.py
# passed, including mypy
```

The 12 constructor cases cover BF16/FP16 × head_dim=256/XQA, head_dim=512/native, and DCP, for both native-FA2 and TRTLLM capability configurations. The native FA2 route uses model-dtype queries and explicitly rejects DCP; the TRTLLM configuration retains the prior FP8 native-fallback expectations. Platform/distributed setup is mocked: these are selection tests, not multi-GPU kernel validation.

The GPU test uses 24 Q heads, 4 KV heads, head_dim=256, q_len=8, batch=3. Hardware validation is local.

A broader check (`-k 'flashinfer and not nvfp4_decode_dtype_after_fallback'` in `test_attention_backends.py`) returned 14 passed, 5 skipped, 20 failed. Repeating it with the **unmodified main backend** produced the identical 20 failing cases and counts. These failures arise from missing local CUDA FlashAttention extensions/model-inspection imports. This is not a passing full backend suite.

**Model evaluation:** no end-to-end model evaluation is claimed for this rebased head. Previous combined-stack backport throughput/canary results do not validate this revision. The prior approval's end-to-end SM120 condition remains unverified locally.

## Details

Main has advanced since the October 2 review: #46963 added native NVFP4 support on SM8x/SM12x and #60452 added SM12x NVFP4 XQA plumbing. This rebase preserves that upstream implementation, including its scale-cache argument, rather than adding a duplicate. The remaining diff is query-dtype ordering/selection plus the masked-XQA regression and shared test-helper relocation. The older statement that all SM12x serving awaits #46329 no longer describes this base; #46329 itself remains open.

The existing six-case regression assumed native fallback always used FP8 queries. It now covers the new FA2 behavior as well, without bypassing its DCP rejection. The isolated-stream implementation and its performance claims remain removed.

AI assistance was used for implementation, review, conflict resolution, testing, and this description. Human review of the rebased diff remains pending.
