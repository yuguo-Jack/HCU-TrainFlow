# [MiniMax-M3.1][PP] m31-pp-opt: NIXL pull from PP prefill stages and the Q8KV4 prefill workspace on SM10x

[Upstream PR](https://github.com/vllm-project/vllm/pull/64733) · state: closed · merged: True

## Original PR description

## Purpose

Brings into `m31-pp-opt` the remaining changes the MiniMax-M3.1 PP prefill benchmark ran with, so the branch reproduces it. Three commits on top of the branch head (`c905d49982`):

1. **Pair KV regions by layer for every transfer**: #63416 as one commit (@Dao007forever, with @NickLucche).
2. **Pull KV from pipeline-parallel prefill stages**: #64397, stacked on #63416. Both stay open against `main` for review; this branch only carries them.
3. **Reserve the Q8KV4 prefill workspace on every SM10x GPU** (new). The Q8KV4 prefill split workspace was reserved only on Rubin (SM107). On B200/B300 the prefill allocated its split partials on every step, about 8 GiB at 32K tokens, outside memory profiling. So PP2 with `--gpu-memory-utilization 0.9` ran out of memory on its first long prefill:
   ```
   torch.OutOfMemoryError: CUDA out of memory. Tried to allocate 8.00 GiB. GPU 1 has a total capacity of 267.68 GiB of which 458.25 MiB is free.
   ```
   This commit reserves the workspace once, for the largest batch, on the whole SM10x family.

## Test Plan

- NIXL unit tests:
  ```bash
  pytest tests/v1/kv_connector/unit/test_nixl_desc_geometry.py \
         tests/v1/kv_connector/unit/test_nixl_connector_hma.py \
         tests/v1/kv_connector/unit/test_nixl_push_connector.py
  ```
- The full PP prefill benchmark, run with this branch on `vllm/vllm-openai:cu134-nightly-335dd77b0`. The setup was one 8-GPU HGX B300 node and MiniMax-M3.1-Flash with the NVFP4 KV cache. TP2, DEP2 and PP2 were each screened, swept and repeated over three seeds, all at `--gpu-memory-utilization 0.9`.

## Test Result

- NIXL: the 12 files of commits 1-2 are byte-identical to #64397's head. On a CPU-only machine, the failure set of the tests above is identical to #64397's head; the failures come from the missing CUDA/NIXL environment.
- Workspace: without commit 3, PP2 with the CuTe DSL MoE ran out of memory on the first long prefill at 0.9. With it, every PP2 config ran screening, sweeps and finals at 0.9 with no out-of-memory error.
- Accuracy: GSM8K (all 1,319 questions) is 0.9613 for PP2's final config, against 0.9568 for the TP2 reference. Every config also matched the reference's first token on 64 long prompts (top-1 agreement 1.0).

AI assistance: commits 1-2 were assembled with Claude Code from the existing PRs; commit 3 and the benchmark runs were done with Claude Code and reviewed by the submitter.
