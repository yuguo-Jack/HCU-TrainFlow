## Overview

Preserve `-1` invalid expert IDs in DeepEP LL round-robin remapping, in the helper shared by dispatch and combine.

**Depends on #64086.** This PR is temporarily stacked on its NIXL fix so it can extend the existing test file instead of duplicating it. The incremental production change is one DeepEP LL mapping line. #64086 itself is unchanged.

## Claims

- Keep invalid routes invalid when a global-to-physical mapping table is present.
- Preserve valid-ID mappings and the no-map path.
- Reuse one parameterized regression for NIXL and DeepEP LL: the same mixed-padding, all-padding and linear-placement cases, setup and dispatch/combine assertions.

## Validation

- Shared CPU adapter regression: **6 passed** (2 backends × 3 cases), PyTorch 2.13.0+cu129.
- Before the DeepEP LL guard was added, the shared cases gave **2 failed, 4 passed**; mixed/all-padding failed because `-1` became expert `7`.
- Ruff check/format and `git diff --check`: passed. The shared test and both source dependencies are selected in CPU CI.
- Earlier single-H200 core validation on `0e60e1ca696f011fb84579ffd60b31ee8c571030`: baseline **2 failed / 1 passed**, fixed **3 passed**, and **6 adapter CUDA Graph replay configurations** passed both dispatch and combine (**12 checks**). The DeepEP LL production file is byte-identical in this revision; the shared-test refactor was subsequently checked with the 6-case CPU suite. [Published data and exact runner](https://github.com/algebra-MCX/vllm/blob/c2170732ab2585970cb1cb38d70ef8da1a5fe13d/benchmarks/moe/deepep_ll_sentinel_h200_20261028/README.md).
- The H200 check uses real CUDA tensors and the real adapter with a recording external transport. Native DeepEP communication, native transport CUDA Graph replay, full `VLLM_GPU_SYNC_CHECK=error`, model evaluation and performance validation remain unestablished.

```bash
CUDA_VISIBLE_DEVICES='' HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  .venv/bin/python -m pytest tests/kernels/moe/test_nixl_prepare_finalize.py -q
```

## Details

The current `mapping[topk_ids]` lookup treats `-1` as a negative index and selects the table’s last valid expert. The one-line guard uses `torch.where(topk_ids >= 0, mapping[topk_ids], -1)`.

The existing test grows from 80 to 93 lines. Only the backend import/constructor selection and low-latency transport aliases differ. Cases and assertions remain shared; no separate DeepEP LL test file or helper module is added.

Triggering the bug requires both a non-None mapping table and incoming invalid IDs. Default linear placement does not use the table; no default model failure or performance gain is claimed.

Duplicate-work checks found no equivalent open DeepEP LL mapping fix. #64086 supplies the NIXL prerequisite; this follow-up adds the DeepEP LL guard.
