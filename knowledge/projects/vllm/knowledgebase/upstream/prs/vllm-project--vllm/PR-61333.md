# [fix] Enable PP routed expert capture for R3

[Upstream PR](https://github.com/vllm-project/vllm/pull/61333) · state: open · merged: False

## Original PR description

## Overview

R3 requires the expert selections from every model layer, but vLLM currently rejects routed-expert capture with pipeline parallelism. Each PP stage captured only its own layers’ expert selections, so the final stage lacked the complete routing data required for R3. This PR enables PP > 1 R3 in MRV2.

## Claims

**Feature support**: Enable PP R3 by preserving expert selections from every PP stage.

## Validation

### Performance benchmark
Setup: `moonlight-16B-A3B-instruct` on B200; ISL/OSL=1024/512. Compare `enable-return-routed-experts` on and off.

| Median TTFT | 1,509.67 | 1,712.91 | +13.5% | 942.09 | 1,003.21 | +6.5% |

Collecting expert routes for replay adds overhead as expected, but the regression was lower for PP than TP.

**Server**
```bash

```

### Training run
See https://github.com/NovaSky-AI/SkyRL/pull/2471 for more details.

## Details

Each PP stage captures its own expert layers. We merge these snapshots and forward them alongside existing hidden-state transfers across PP stages. The final PP stage uses the existing async `AuxOutput` copy/store path.

This PR doesn't add new collectives and leaves TP-only capture unchanged.
