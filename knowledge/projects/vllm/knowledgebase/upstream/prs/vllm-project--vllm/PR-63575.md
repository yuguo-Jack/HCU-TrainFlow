# [Bugfix][Frontend] Preserve nullable MCP tool schemas

[Upstream PR](https://github.com/vllm-project/vllm/pull/63575) · state: open · merged: False

## Original PR description



## Overview

Fix MCP registration failing with `KeyError: 'type'` for valid nullable nested parameters, and preserve enum choices, array item types and nested fields in Harmony tool descriptions.

Related: #43762 addresses ordinary chat/Jinja tool-schema rendering. It does not modify the MCP registration / Harmony conversion path changed here.

## Claims

- MCP tools with parameters such as `filters: SearchFilter | None = None` can be registered.
- Nullable enum, array and object information reaches the rendered Harmony prompt.
- Local references expand independently per branch; recursive/unresolved/external references remain unexpanded. No remote schema retrieval or new dependency is introduced.

## Details

The old conversion kept only each union branch's `type`. A local-reference branch has no `type`; enum/array branches carry relevant information outside that key. Adapt the whole branch, resolve local JSON pointers without network access, and use Harmony's supported `oneOf` representation for multiple alternatives.

This is prompt adaptation, not general-purpose JSON Schema validation. Conflicting constraints are not blindly overwritten; recursive/external references retain the unsupported-reference fallback. Tests verify the final prompt, repeated/escaped references, recursive termination and the real startup path. The Responses API documentation describes the supported behavior. No generation-quality or throughput improvement is claimed.

Duplicate checks on 2026-10-25 found no open PR fixing MCP `trim_schema` / `post_process_tools_description`. #53870 fixed MCP 2.x attribute naming, while #43762 covers the separate chat-template path.
