# [Spec Decode][MRV2] Support heterogeneous-vocab draft models (TLI)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61536) · state: open · merged: False

## Original PR description



## Overview

Draft models with a different vocabulary than the target, `use_heterogeneous_vocab=True` from #38174, now run on Model Runner V2. Since #59541 they fall back to V1. This is the TLI item listed as TBD in #47172.

## Claims

- `method="draft_model"` with `use_heterogeneous_vocab=True` runs on V2, and the V1 fallback is removed.
- On both directions of vocab mismatch, acceptance length on V2 matches V1 and GSM8K accuracy stays within noise of the target alone.
- V2 throughput with TLI is the same as or slightly above V1.

With the 1.5B target at this batch size the draft is extra work, so throughput with drafting is lower than the target alone. That is the same on V1.

Verify computes k+1 rows at once and plain decode computes one, so near-tied logits can flip, see #54506. ## Details

The change keeps the draft vocab inside `StandaloneARSpeculator`. Ids cross between vocabularies at two points only:

1. Target ids become draft ids once per step, in the expanded step-0 input buffer. This is done in place so the draft CUDA graph work in #60989 can keep reading that buffer. The dummy-run path reads the target's own input buffer, so it maps into a new tensor instead.
2. `propose()` maps the drafted ids to target ids, into a preallocated buffer, right before returning them.

`compute_draft_logits` masks logits outside the shared vocab, so the drafter only proposes tokens the target also has. Between draft steps the drafter keeps its own ids. V1 maps back and forth every step, but ids in the shared vocab map one to one, so the drafter sees the same inputs on both runners.

Tokenizers are loaded with each model's own path, mode and revision. The draft config inherits the target's tokenizer mode and revision, which #54780 fixes on the V1 side.

`use_local_argmax_reduction` bypasses `compute_draft_logits`, so the mask would be skipped. #51564 already rejects that combination in the config, so it is not repeated here.

Not in this PR: CUDA graphs for the standalone drafter, which #60989 is adding, and probabilistic drafting with a heterogeneous vocab, which needs the draft distribution mapped into the target vocab and is also unsupported on V1.

Duplicate check: #47172 and the open PRs for TLI and heterogeneous vocab on V2. #54780, #51564 and #59012 fix V1 or `VocabMapping`, and #61152 fixes probabilistic rejection sampling for narrower draft vocabularies. None of them ports TLI to V2.
