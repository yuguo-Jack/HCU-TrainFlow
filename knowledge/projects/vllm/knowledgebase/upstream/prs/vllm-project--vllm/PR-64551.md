# [Bugfix][Rust Frontend] Reject --dataset-path with synthetic vllm-bench datasets

[Upstream PR](https://github.com/vllm-project/vllm/pull/64551) · state: closed · merged: True

## Original PR description



## Overview

Fixes #64538. Rust `vllm-bench` silently ignored `--dataset-path` for the synthetic datasets, so `vllm-bench --dataset-path my_workload.jsonl` without `--dataset-name` benchmarked random prompts instead of the given file. This rejects the combination with the same error as Python `vllm bench serve`.

## Claims

- `--dataset-path` with `random`, `random-mm`, `random-rerank` or `prefix_repetition` (including the default `--dataset-name random`) now fails at startup with Python's error: `Cannot use '<name>' dataset with --dataset-path. Please specify the appropriate --dataset-name (e.g., 'sharegpt', 'custom', 'hf') for your dataset file: <path>`.
- Datasets that read `--dataset-path` (`sharegpt`, `speed-bench`, `hf`, `custom`, `timed_trace`) are unchanged.
- `--dataset-path` help text and the bench README document the restriction.

## Validation

Regression tests in `config.rs`: `test_synthetic_dataset_rejects_dataset_path` and `test_default_dataset_rejects_dataset_path` fail without the fix and pass with it; `test_file_dataset_accepts_dataset_path` passes in both.

```bash
cd rust
cargo test -p vllm-bench                                   # all pass
cargo clippy -p vllm-bench --all-targets -- -D warnings    # clean
cargo fmt -p vllm-bench --check                            # clean
```

End-to-end, release build against a mock OpenAI-compatible server that logs received prompts. `my_workload.jsonl` holds 5 lines of `{"prompt": "MY_REAL_WORKLOAD_PROMPT", "output_tokens": 4}`; common args `--model mock-model --tokenizer gpt2 --base-url http://127.0.0.1:8000 --num-prompts 5`.

| Command | Before | After |
|---|---|---|
| `--dataset-path my_workload.jsonl` | exit 0, "5 random prompts"; `MY_REAL_WORKLOAD_PROMPT` received 0 times | exit 1: `Cannot use 'random' dataset with --dataset-path ...` |
| `--dataset-path /no/such/file.jsonl` | exit 0 | exit 1, same error |
| `--dataset-name random-rerank --backend vllm-rerank --dataset-path my_workload.jsonl` | — | exit 1: `Cannot use 'random-rerank' dataset ...` |
| `--dataset-name custom --dataset-path my_workload.jsonl` | — | exit 0; `MY_REAL_WORKLOAD_PROMPT` received 5/5 times |
| `--dataset-name random` (no path) | — | exit 0 |
| `vllm bench serve` (Python), first row's command | exit 1, same error | unchanged |

The same error is returned with `--multi-turn`, `--sweep-max-concurrency` and `--num-runs`. `mm-processor` has no `--dataset-path` flag and already rejects it as an unexpected argument.

## Details

- **Root cause:** Python checks this combination in `vllm/benchmarks/serve.py`; the Rust port never did, and none of the four synthetic generators read `dataset_path`. Since `--dataset-name` defaults to `random`, a forgotten `--dataset-name` produced plausible-looking results for the wrong workload.
- **Placement:** the check is in `BenchConfig::from_args`, next to the other per-dataset validation. Every serve mode (single run, multi-turn, sweeps, `--num-runs`) builds its config there, so one check covers all of them.
- **Parity:** same dataset list and message as Python. The dataset name in the message comes from the CLI value (`ValueEnum::to_possible_value`), so it matches what the user typed.
- **Not a duplicate:** no open or closed PR or issue covers this; I searched for `64538`, "dataset-path", "vllm-bench dataset-path", and "Cannot use dataset with --dataset-path" before opening #64538 and this PR.
