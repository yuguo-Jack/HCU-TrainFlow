# [Misc] Move FlashInfer MoE helpers into utils package

[Upstream PR](https://github.com/vllm-project/vllm/pull/42378) · state: closed · merged: False

## Original PR description

Fixes #31414.

Moves the FlashInfer MoE-specific helpers out of `vllm.model_executor.layers.quantization.utils.flashinfer_utils` and into the `vllm.utils.flashinfer` namespace as `vllm.utils.flashinfer.moe`.

The existing FlashInfer compatibility wrapper is preserved as the package `vllm.utils.flashinfer` by moving `vllm/utils/flashinfer.py` to `vllm/utils/flashinfer/__init__.py`. The MoE helpers live in a separate `moe.py` submodule instead of being imported from the package top level, which keeps the cleanup behavior-preserving and avoids introducing a top-level dependency on fused-MoE modules.

Validation:
- `git diff --check`
- `python3 -m compileall -q` on the moved package and updated import sites
- `uvx pre-commit run --hook-stage manual --files ...` for all touched files

## Code Review

This pull request refactors FlashInfer MoE utilities by moving them from the quantization layer utilities to a centralized location in vllm.utils.flashinfer.moe. The changes consist of updating import paths across various MoE expert implementations (FP8, NVFP4, and unquantized) and associated test files. Review feedback identifies a layering violation where the new utility module depends on the model executor, which could lead to circular dependencies. Additionally, a bug was noted in the backend auto-detection logic that incorrectly handles SM80 and SM100 devices, potentially causing runtime errors on those platforms.

This import triggers a layering violation because `vllm.utils.flashinfer.moe` depends on `vllm.model_executor.layers.fused_moe.activation` at the top level. Utility packages in `vllm.utils` should remain independent of the model executor to prevent circular dependencies and maintain a clean architecture. Please consider moving the `MoEActivation` enum to a more central location or using lazy imports/string type hints in `moe.py` to break this dependency.

- gemini-code-assist[bot] · comment · 2026-05-12T05:41:59Z · [source](https://github.com/vllm-project/vllm/pull/42378#discussion_r3223976931)

File: `vllm/utils/flashinfer/moe.py` · line 3

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The `get_flashinfer_moe_backend` function (line 100) contains a bug in its auto-detection logic. It currently only falls back to `FlashinferMoeBackend.CUTLASS` for SM90 devices when the `VLLM_FLASHINFER_MOE_BACKEND` environment variable is unset. This will cause a `ValueError` on Blackwell (SM100) and A100 (SM80) devices, even though they are supported by FlashInfer. The logic should be updated to handle these platforms in the fallback block, and the error message should be improved to be more descriptive when auto-detection fails.
