# [Bugfix] Bound EngineCore exit after a startup failure

[Upstream PR](https://github.com/vllm-project/vllm/pull/60141) · state: closed · merged: False

## Original PR description

When EngineCore fails to start, run_engine_core logs the error and lets the process exit normally, and the client in wait_for_engine_startup only notices the failure once the process exits. With spawned processes the exit runs interpreter finalization (atexit handlers, native teardown), and if that hangs the client waits forever. AMD CI hit this in v1/shutdown/test_startup_error.py::test_async_llm_startup_error [forward-2-...]: EngineCore logged "EngineCore failed to start" and "all workers exited gracefully", but never exited, and the test timed out after 2400s.

After a startup failure, set an OS alarm with the default action so the process is terminated if it is still alive after
VLLM_WORKER_SHUTDOWN_TIMEOUT_SECONDS + 30s. Normal cleanup still runs first, and the client then raises "Engine core initialization failed" as usual.

Add a test that hangs EngineCore in an atexit handler after a startup failure. Without the fix it times out; with it the error is raised.
