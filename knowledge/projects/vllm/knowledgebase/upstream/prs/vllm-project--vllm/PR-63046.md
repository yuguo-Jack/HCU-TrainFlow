# [XPU][LoRA] Use active ranks for eager linear dispatch

[Upstream PR](https://github.com/vllm-project/vllm/pull/63046) · state: open · merged: False

## Original PR description



## Overview

Use the active-rank LoRA entry from [kernel #649](https://github.com/vllm-project/vllm-xpu-kernels/pull/649) for eager XPU serving.

## Claims

- Track loaded ranks through packed-slice loading, slot reset and reload; compute at the largest rank needed by the current batch.
- Skip empty eligible batches; retain existing paths for graph/compile, fully sharded LoRA, older kernels, unknown/full ranks and layers exceeding eight slices.

## Validation

```bash
.venv/bin/python -m pytest tests/lora/test_layers.py \
  tests/lora/test_punica_xpu_ops.py tests/lora/test_lora_manager.py -q
.venv/bin/python -m pytest tests/lora/test_layers.py -k xpu_active_rank_slice_limit -q
pre-commit run --all-files
```

151 passed, 72 skipped. Active-rank suites: 20 passed with native kernels and 20 with real legacy kernels; kernel references: 62 passed. Original lifecycle tests-only overlay on main: **4 failed, 12 passed** (expected rank8 dispatch, observed none). Changed-file hooks/mypy passed. All-files checks hit unrelated ROCm lock regeneration and a root-specific entrypoint failure; all 11 entrypoint cases passed as non-root.

Slice-limit regression (FP16/BF16, active rank8/stored32): before the guard, `2 failed, 2 passed` with `RuntimeError: Too many slices (9), max is 8`; afterward, **4 passed**. Both TP2 workers also passed 8/9-slice dispatch, numerical and reset/reload checks.

Qwen3.6-27B FP16/TP2, eager, 128 input / 64 output, stored rank64; ABBA, 2 warmups and 5 samples/case. Max relative MAD: 1.23%. Both arms load the same kernel binary.

All 12,800 generated tokens match in paired arms; maximum selected-token logprob delta 0.02860. Synthetic adapters establish parity, not task quality.

## Details

Validated main base `9d61ade7f6` with kernel #649 at `5cf06f8`, torch 2.13.0+xpu, Triton 3.7.2 and oneAPI 2026.0; torch 2.14 remains untested. Active-path CI needs the kernel release; manual validation used #649. Document automatic selection in `docs/features/lora.md`.

Overlap check: #51613 migrates full-rank multi-slice dispatch; #59572 changes Triton token partitioning. The empty-batch shortcut overlaps #47951; actual-rank XPU dispatch is the main change here.
