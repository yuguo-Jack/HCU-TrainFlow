# [Model][LoRA] Enable LoRA support for BERT cross-encoders

[Upstream PR](https://github.com/vllm-project/vllm/pull/61279) · state: open · merged: False

## Original PR description

## Overview

Enable LoRA for `BertForSequenceClassification` cross-encoders, e.g. `cross-encoder/ms-marco-MiniLM-L6-v2`. That includes PEFT `SEQ_CLS` adapters that save a trained classification head. Follow-up to #61033 (BERT/RoBERTa embedding models); same pattern as #58884.

## Claims

- `--enable-lora` works instead of failing with `... does not support LoRA yet.`
- PEFT adapters with a saved head (`modules_to_save=["classifier"]`) load and match transformers + PEFT. Backbone-only adapters match too.
- Without LoRA, outputs are unchanged.

## Validation

Tesla T4, main @ e0317b28c. Random PEFT adapters (r=8, `init_lora_weights=False`); saved heads are perturbed so they differ from the base head. Each pair is scored with `LLM.score`, vLLM fp16 vs transformers + PEFT (merged) fp32 on CPU, 4 query/document pairs.

| Model | Adapter | Max abs diff, base | Max abs diff, LoRA vs HF+PEFT | LoRA effect (HF) |
|---|---|---|---|---|
| ms-marco-MiniLM-L6-v2 (raw logits) | encoder q/k/v/dense + saved head | 0.0022 | 0.0027 | 13.53 |
| ms-marco-MiniLM-L6-v2 (raw logits) | encoder q/k/v/dense only | 0.0022 | 0.0110 | 7.25 |

- **On main:** the model fails at startup with `... does not support LoRA yet.`
- **With only `SupportsLoRA` added (no classifier change):** the saved-head adapter fails with `ValueError: Cannot load full module 'classifier': the model does not expose a unique ClassificationHeadWithLoRA.`
- **Existing tests,** each passing both before and after the change:
  - `tests/models/language/pooling/test_classification.py::test_bert_model_runner_v2`
  - `tests/models/test_registry.py`
  - `tests/models/test_initialization.py -k BertForSequenceClassification`
  - `tests/lora/test_sequence_classification.py`
  - `tests/models/language/pooling_mteb_test/test_cross_encoder.py`

The comparison script (adapter generation + vLLM vs HF+PEFT check) is ~150 lines; happy to share it or turn it into a `tests/lora` case if useful.

## Details

- **`classifier`: `nn.Linear` → `ReplicatedLinear(..., return_bias=False)`.** With the default `target_modules`, `LoRAModelManager` only wraps `LinearBase` modules (`is_supported_lora_module`). A plain `nn.Linear` classifier therefore never becomes a `ClassificationHeadWithLoRA`, and `_validate_modules_to_save` rejects saved heads. This matches how `as_seq_cls_model` builds `score`, and #60211 makes the same change for RoBERTa's head. BERT's head is a single linear, so this stays within the existing single-layer `modules_to_save` contract. Same weights, bias and `head_dtype`, so non-LoRA outputs are identical. The weight names are unchanged.
- **`packed_modules_mapping`:** `qkv_proj ← query/key/value`. BERT's vLLM module names already match HF, so no `hf_to_vllm_mapper` is needed.
- **`self.config`** is needed by the LoRA manager.
- **Limitation: `bert.pooler.dense` is not LoRA-wrapped,** because `BertPooler.dense` is a plain `nn.Linear`. An adapter that targets it loads and the pooler LoRA is dropped: max abs diff 0.42 vs HF on the pooler-targeting adapter. This is the same class of issue as RoBERTa's `classifier.dense` in #60211. Making it a `ReplicatedLinear` would apply token-indexed LoRA in a per-sequence stage, so I left it. Happy to follow the reviewers' preference: reject such adapters, or let BERT opt `bert.pooler.dense` in if `lora_classifier_modules` from #60211 lands.
- **ModernBERT left out on purpose:** #59206 moves `ModernBertForSequenceClassification` to the Transformers modeling backend and removes the native class, so I didn't touch it. The same change does work there (gte-reranker-modernbert-base on the same T4 setup: max abs diff 0.0002 with a saved head, 0.0014 encoder-only), and I'm happy to send it separately if that's useful before #59206 lands.
- **Scope and fallback:** this does not change `modules_to_save` or any shared LoRA code. It only makes this single-linear classifier eligible for the existing saved-head path. If maintainers prefer not to widen saved-head support for now (see the scope discussion on #60211), the `ReplicatedLinear` change can be dropped. That leaves backbone-only LoRA, as in #58884, which the "encoder only" rows above already validate.
- **No file overlap with #60211** (`vllm/lora/*`, `roberta.py`).
- **CI gap:** no new test. LoRA correctness needs a GPU and adapter checkpoints. Happy to add a `tests/lora` case if wanted.
