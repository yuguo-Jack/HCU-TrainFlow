# [Performance] Enable CUDA BF16 GQA RoPE KV-cache fusion

[Upstream PR](https://github.com/vllm-project/vllm/pull/57271) · state: open · merged: False

## Original PR description

## Purpose
Enable CUDA BF16 GQA RoPE + KV-cache fusion.

Previously, this fusion path was restricted to ROCm/AITER, so CUDA executed RoPE and KV-cache updates separately. This change allows CUDA to run the fusion pass and adds a Triton kernel that applies RoPE and writes the BF16 KV cache in one operation.

The implementation supports:

  - GQA decode
  - CUDA H100
  - BF16 KV cache
  - Neox and GPT-J RoPE layouts
  - Fallback for unsupported cache layouts

## Benchmark Configuration

- **GPU:** 1× H100 80GB
- **Model:** Qwen/Qwen2.5-0.5B-Instruct
- **Input length:** 128 tokens
- **Output length:** 32 tokens
- **Requests:** 100
- **Warmup requests:** 10
- **Runs:** 10 per configuration

## Benchmark Results

| Configuration | Median Output Throughput | Median Total Throughput |
|---|---:|---:|
| Unfused BF16 | 16,105.90 tok/s | 80,529.50 tok/s |
| Fused BF16 | 21,444.51 tok/s | 107,222.53 tok/s |

The fused configuration achieved approximately **33.1% higher median throughput**.
