# [Bugfix][NIXL] Preserve packed-row aliases during region dedup

[Upstream PR](https://github.com/vllm-project/vllm/pull/64661) · state: open · merged: False

## Original PR description

## Overview

Follow-up to [#57662](https://github.com/vllm-project/vllm/pull/57662), addressing the packed DeepSeek-V4.1 alias regression that remained after region deduplication was keyed by `(base_addr, block_len)`. The fix keeps aliases that are genuinely compatible together while preserving separate regions where a fold could truncate data.

Related issue: [#57661](https://github.com/vllm-project/vllm/issues/57661).

## Claims

- Fixes `test_register_packed_dsv4_mla_cache_as_single_region[v41-aliased-groups]`, without introducing failures in the exercised NIXL unit suites.
- Preserves the original exact-length alias behavior used by hybrid MLA and CSA-linear layouts.
- Allows a shorter non-MLA view to reuse a packed whole-row region only when its stride and block count match; wider views and incompatible scratch layouts get their own region.
- Prevents the original failure mode in which a later, narrower view changed the descriptor length for a wider page and truncated the P-to-D transfer.

## Details

### Root cause

`register_kv_caches` builds the region table consumed by both sides of a NIXL transfer:

1. The prefill worker registers each KV-cache view and records its base address, block length, stride, block count, and transfer group.
2. The decode worker registers its corresponding views and uses the resulting region metadata to construct descriptors.
3. Shared transfer groups may read a region owned by another group when the views alias the same physical storage.
4. If a wider page is folded into a region whose block length was set by a narrower, later-registered view, the descriptor sends only the shorter prefix. DeepSeek-V4.1-Flash exposes this when SWA pages and MLA/indexer pages share a row but have different page lengths.

The `(base_addr, block_len)` key added by #57662 correctly prevents that truncation. Treating every alias as incompatible, however, breaks an established packed-MLA whole-row layout: shorter views in the same packed row are intentionally covered by the row region. A universal `(base_addr, block_len, block_stride, num_blocks)` key also splits hybrid MLA and CSA-linear views whose kernel-granularity metadata differs even though their transfer region is intentionally shared.

### Design

The implementation records whether each region came from the packed whole-row path and uses a small compatibility helper at registration time:

- Exact-length aliases continue to use the existing region. MLA aliases still update the canonical block length, stride, and block count as before.
- A shorter non-MLA view may reuse an existing region only when that region is explicitly marked as a packed whole row and its stride and block count match the view.
- A wider view never folds into an existing region, so its full page cannot be truncated.
- Ordinary scratch/CSA pages are not treated as packed-row coverage. A wider ring or PLE page therefore keeps a separate region, while compatible exact-length aliases retain their established identity.
- The packed-row marker is set at the point where the whole-row region is created, instead of inferring intent later from address or geometry alone.

This keeps the special case local to region registration and avoids a growing list of model-specific conditions. The alternative approaches were rejected because base-address-only deduplication reintroduces truncation, a universal geometry key regresses hybrid MLA layouts, and generic shorter-view coverage incorrectly absorbs scratch/CSA pages. Removing the packed whole-row path would avoid the ambiguity by losing the descriptor reduction it provides for packed MLA storage.

### Scope and limitations

This is a metadata/descriptor-registration fix; it does not change the NIXL wire format or add synchronization to the inference path. It is intended to be compatible with the per-group region addressing from #62317. No user-visible API or documentation change is required.

This PR is a follow-up to #57662, not a duplicate of [#61121](https://github.com/vllm-project/vllm/pull/61121). #61121 changes which DeepSeek-V4.1 layouts enter the packed-MLA whole-row path; this PR fixes the compatibility rules for aliases after region deduplication and preserves the behavior of existing hybrid/scratch layouts.
