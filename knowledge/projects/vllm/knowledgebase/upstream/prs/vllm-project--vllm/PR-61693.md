# [Fix] Stop MRV2 prompt logprobs at the end of the prompt

[Upstream PR](https://github.com/vllm-project/vllm/pull/61693) · state: open · merged: False

## Original PR description



## Overview

Clamp MRV2 prompt-logprob output to the remaining valid prompt positions.

## Claims

- Excludes speculative padding from returned prompt logprobs.
- Preserves valid rows across chunked prefill.
- Returns no scored rows for a one-token prompt.
- Added tests: `tests/v1/worker/test_gpu_prompt_logprobs.py`

**Note:** These tests exercise `PromptLogprobsWorker` directly, which has no existing dedicated coverage. The existing logprob suites primarily validate model-level behavior, while the model-runner suite covers broader execution orchestration. A small, parameterized module keeps these worker-level boundary checks together without loading a model checkpoint. The existing Buildkite worker jobs already collect this directory.
If reviewers consider `test_gpu_model_runner_v2.py`is a better place for it, that's also an option.

## Validation

- Added parameterized regression tests for ordinary prefill, a final chunk, and a one-token prompt.
- 60 CPU checks passed across the fix and parent controls, using CPU equivalents for GPU kernels.

GPU: NVIDIA L4 (GCE g2-standard-4), PyTorch 2.14.0+cu130, Triton 3.8.0. Python sources at main 355553ac22 with this PR applied, compiled extensions from the precompiled wheel built at 355553ac22.

On `main` the two cases with draft padding fail: `[8-7-4]` (8-token prompt, 7 tokens computed, 4 drafts) and `[1-0-4]`. Each returns 4 rows for a request with no prompt position left to score. The case without padding passes on both trees.

I deselected 3 tests in `test_logprobs.py` that need gated Llama checkpoints and 4 that do not reach prompt logprobs. `test_logprobs_e2e.py` and `test_async_scheduling.py::test_with_eagle3_spec_decoding` need gated checkpoints and did not run.

End to end, I ran Qwen/Qwen3-0.6B in BF16 with `LLM`, Model Runner V2, ngram speculative decoding with 4 speculative tokens, sync scheduling and prefix caching off. While another request decodes, a one-token prompt arrives with `prompt_logprobs=0` and `max_tokens=1`. The scheduler gives it 5 rows, its token and 4 placeholder drafts. A one-token prompt has no position to score. Its `prompt_logprobs` should be `[None]`, one entry.

| tree | rows scheduled | `prompt_logprobs` entries | expected |
|---|---|---|---|
| `main` | 5 | 5 | 1 |
| this PR | 5 | 1 | 1 |

With the same engine, a batch of 16 requests with 300-token prompts, every other one with `prompt_logprobs=5`, matches `main` exactly. All 2,392 scored positions have the same top-5 ids and logprobs, and all 16 requests generate the same tokens.

## Details

Limit each request’s end index to:
```
min(query_end, query_start + prompt_length - computed_prefill - 1)
```

Apply the limit before accumulating or returning rows. Token gathering and scoring remain unchanged.
