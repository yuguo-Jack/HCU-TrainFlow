## Purpose

- `ibm-granite/granite-3.3-2b-instruct`

Both Instruct sizes were tested. **8B passed all 22 cases; 2B passed 20 and failed two FLASH_ATTN cases**, detailed below. The documentation change adds one model-list entry; the configuration, results, and limitations are recorded in this PR.

This PR contributes model-validation results without duplicating either fix.

## Test Result

| Model | FLASH_ATTN / FA3 | FLEX_ATTENTION | TRITON_ATTN | Total |
| --- | --- | --- | --- | --- |
| Granite 3.3 2B Instruct | 6 passed, 2 failed | 7 passed | 7 passed | **20 passed, 2 failed** |
| Granite 3.3 8B Instruct | 8 passed | 7 passed | 7 passed | **22 passed** |

Both runs executed all 22 cases with **zero skips and zero automatic reruns**. The three invariance-disabled negative controls passed by detecting differences as expected. Decode/prefill equivalence is parameterized only for FLASH_ATTN in this file.

### 2B: FLASH_ATTN chunked-prefill logprob mismatch

`test_logprobs_bitwise_batch_invariance_ragged_chunked_prefill[FLASH_ATTN]` fails with the original test-computed `max_num_batched_tokens=144`. Generated token IDs match, but sampled-token logprobs differ:

```text
prompt 1 (288 tokens): logprobs differ, max|delta|=2.097e-02
prompt 8 (272 tokens): logprobs differ, max|delta|=4.405e-03
```

Independent and eager-mode reruns reproduce both differences. A focused run with the original `0.5` memory budget and `VLLM_USE_BREAKABLE_CUDAGRAPH=0` also fails on the same two requests. Its constructor arguments match the passing 8B case except for the model path, and logs confirm torch.compile is enabled. The failure therefore persists after increasing the memory budget and enabling compilation.

Diagnosis links this to the batch-dependent FA3 kernel selection described in #51902. For 2B's `head_dim=64`, changing the batch maximum query length from 16 to 17 changes the tile from `64x192` to `192x128`. A fixed-input attention probe reproduces differences, and an external diagnostic that fixes this branch makes the original 2B test pass. For 8B's `head_dim=128`, profiling shows `64x128` to `128x128`; the same probe remains equal with either model's softmax scale. These diagnostic results explain the observed shape dependence; they do not establish a general kernel fix or replace the original failures.

### 2B: decode/prefill prefix-construction mismatch

`test_decode_logprobs_match_prefill_logprobs[FLASH_ATTN]` fails at prompt 0, token position 5. Converting the generated prefix to text and tokenizing it again changes two newline tokens `[203, 203]` into `[478]`, so the compared model inputs differ.

A separate diagnostic using the four original prompts, verifying the original generated sequences, and replaying exact token-ID prefixes completes **64/64 token-ID and FP32 logprob-byte comparisons with no differences**. This supports a test-input issue consistent with #53692. The original failure remains in the table above.

Both models use identical tokenizer files. Offline reconstruction of the logged outputs finds exactly one changed prefix for 2B, at the failed position, and none of the 64 positions for 8B. The original 8B tests pass without any prefix replacement or FA3 diagnostic patch.

**2B: `resource_budget.py`**

`GRANITE_MAX_BATCHED_TOKENS` and `GRANITE_ENFORCE_EAGER` were unset for the complete run. Its only constructor override was `gpu_memory_utilization=0.075`.

```python
"""External pytest plugin: change resource budgets, retain upstream assertions."""

import datetime as dt
import json
import os
from pathlib import Path
import subprocess

import pytest

ROOT = Path(__file__).resolve().parent


@pytest.fixture(autouse=True)
def granite_resource_budget(monkeypatch, request):
    from vllm import LLM

    original_init = LLM.__init__
    engines = []

    def limited_init(self, *args, **kwargs):
        original = dict(kwargs)
        budget = float(os.environ.get("GRANITE_GPU_UTIL", "0.075"))
        gpu = os.environ["CUDA_VISIBLE_DEVICES"]
        snapshot = subprocess.check_output(
            [
                "nvidia-smi", "-i", gpu,
                "--query-gpu=memory.total,memory.free", "--format=csv,noheader,nounits",
            ], text=True,
        ).strip()
        total, free = map(int, snapshot.split(","))
        required = total * budget + 1536
        if free < required:
            raise RuntimeError(
                f"Insufficient shared GPU headroom: free={free} MiB; "
                f"budget={total * budget:.0f} MiB + 1536 MiB reserve required"
            )
        kwargs["gpu_memory_utilization"] = budget
        token_budget = os.environ.get("GRANITE_MAX_BATCHED_TOKENS")
        if token_budget and "max_num_batched_tokens" not in kwargs:
            kwargs["max_num_batched_tokens"] = int(token_budget)
        if os.environ.get("GRANITE_ENFORCE_EAGER") == "1":
            kwargs["enforce_eager"] = True
        record = {
            "time": dt.datetime.now(dt.timezone.utc).isoformat(),
            "test": request.node.nodeid,
            "gpu": gpu,
            "free_mib_before_engine": free,
            "original": original,
            "effective": kwargs,
        }
        with (ROOT / "engine-configs.jsonl").open("a") as handle:
            handle.write(json.dumps(record, default=str) + "\n")
        print("[resource_budget] " + json.dumps(record, default=str), flush=True)
        original_init(self, *args, **kwargs)
        engines.append(self)

    monkeypatch.setattr(LLM, "__init__", limited_init)
    yield
    for engine in engines:
        try:
            engine.llm_engine.engine_core.shutdown()
        except Exception as exc:
            print(f"[resource_budget] cleanup: {type(exc).__name__}: {exc}")
```
