# [Perf][MiniMax-M3] Add opt-in FP16 sparse decode tuning

[Upstream PR](https://github.com/vllm-project/vllm/pull/62098) · state: open · merged: False

## Original PR description

## Summary

Add `minimax_m3_msa_decode_fp16_dot`, an opt-in optimization for MiniMax-M3 Triton sparse decode on SM100-family GPUs. It uses FP16 dot operands with FP32 accumulation and selects splits targeting two CTAs per SM. Default BF16 behavior is unchanged.

The option applies to BF16 Q with FP8 KV, absent/scalar scales, and batch-invariant mode off. Operands saturate to the finite FP16 range; the merge masks padded split lanes. Unsupported calls retain the existing path.

```bash
--attention-config '{"minimax_m3_msa_decode_backend":"triton","minimax_m3_msa_decode_fp16_dot":true}'
```

## Validation

Tested `25acf1953b` against `a20280f30e` on **4×GB200, TP4**, using pretrained `nvidia/MiniMax-M3-NVFP4` and FP8 main/index KV. [Results and reproduction](https://github.com/wolfcomos/vllm/tree/9350b094e49e630284472ed799ccb9cc3b8817fd) include pinned model/runtime versions, commands, all observations and historical failed criteria.

- **Four original attention suites:** baseline 213 passed / 51 skipped; candidate 231 passed / 51 skipped; zero failures. All original case outcomes match; all 18 additional cases pass.
- **Full GSM8K:** 1,319 questions, five-shot, nonthinking, greedy, max 1,024 output tokens. Baseline/default: **1,255 correct (95.1478%)**; FP16: **1,254 (95.0720%)**, a **−0.0758 pp** change. Default outputs are token-exact with baseline. FP16 loses 20 and gains 19 correct answers, with one invalid answer and no capped answers; this does not establish quality equivalence.

**Full-model E2E:** synthetic 2,048-token inputs / 2,048-token outputs, chunked prefill, `FULL_DECODE_ONLY` configured with eager prefill; five warmups and seven measurements per shape/engine. Speedup over the candidate's default Triton path (`default time / FP16 time`; higher is better):

| Batch | E2E speedup | Common-tail speedup | Mean-TPOT speedup |
|---|---:|---:|---:|
| 8 | 1.017–1.018× (+1.68–1.85%) | 1.019× (+1.90–1.93%) | 1.018–1.019× (+1.81–1.88%) |
| 40 | 1.018–1.025× (+1.82–2.49%) | 1.034× (+3.38–3.39%) | 1.026–1.029× (+2.57–2.93%) |

Ranges cover all four pairings of two FP16 and two default engines. Drift-adjusted tail and repeatability checks pass; **the previous 3% mean-TPOT reduction target is not met**. Common tail measures latest-first to latest-last token in a draining batch, not serving p99. FP16 output differences may change MoE routing work.

Against the separate native CUTLASS/Triton-fallback reference, FP16's B40 batch completion time is **0.23–0.84% slower**. That single late engine uses different Q preparation and is order-confounded; these results do not show a general win over the default backend.
