# [Bugfix] Fix DeepSeek-VL2 cache identity across cropping modes

[Upstream PR](https://github.com/vllm-project/vllm/pull/63120) · state: closed · merged: True

## Original PR description



## Overview

Fix DeepSeek-VL2 encoder-cache collisions when the same image appears in requests with different cropping modes.

## Claims

- Distinguish raw-image cache identities across cropping modes, including client-provided UUIDs.
- Preserve identities within each cropping mode and for precomputed image embeddings.

## Validation

uv run --no-sync .venv/bin/python -m pytest \
  tests/models/multimodal/processing/test_deepseek_vl2.py \
  tests/models/multimodal/generation/test_deepseek_vl2.py -q

6 passed. Tests cover cropping boundaries, content hashes, client-provided UUIDs, precomputed embeddings, and both single-image → three-image and reverse request sequences. Both generation cases failed before the fix.

Additional validation with real DeepSeek-VL2-tiny weights on an H800:

- Both request orders completed successfully.
- Alternating and repeated requests matched the eight-token outputs of corresponding successful requests on unpatched code. The repeated three-image request was compared against two consecutive three-image requests on unpatched code. Caching remained enabled.
- A subsequent text-only request succeeded.

## Details

DeepSeek-VL2 enables cropping for requests with at most two images and disables it for larger requests. The processor bypasses its preprocessing cache for larger requests, but still assigns the same image identity to different encoder outputs. In the reproducer, these outputs contained 1,023 and 421 embeddings.

Include the cropping mode in raw-image cache identities through _get_mm_hashes(). Precomputed image embeddings retain their existing identities.
