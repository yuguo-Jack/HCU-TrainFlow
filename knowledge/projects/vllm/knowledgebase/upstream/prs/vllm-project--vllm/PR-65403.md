# [Perf][Sparse MLA][GLM-5.3] Index-group workspace savings and opt-in masked-MHA prefill on quantized KV

[Upstream PR](https://github.com/vllm-project/vllm/pull/65403) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Sparse-MLA changes for GLM-5.3 / DSA models on Blackwell: less index-group workspace and an opt-in masked-MHA prefill path for quantized KV caches (aimed at TP8 `nvfp4_ds_mla` serving of the 743B model on B300). It also closes two ways an index-group follower could read top-k rows its leader did not convert in that step. No linked issues or PRs. **Not validated on a GPU** (see Validation).

## Claims

None of the gains below was measured on a GPU: memory rows are allocation sizes from real constructors on CPU, performance rows are FLOP counts.

| Change | Applies to | Gain | Basis |
|---|---|---|---|
| Shared, decode-row-sized index-group workspace | GLM-5.3-Flash; measured with the SM100/SM103 TRT-LLM sparse impl | **Memory:** -1.0 GiB per GPU with MTP5 (1632.8 → 612.4 MiB), -1.37 GiB without speculative decoding (1496.8 → 93.6 MiB) | Measured allocation: real impl constructors at B200/B300 defaults (16384 tokens, 1024 seqs); 11 target layers, plus the MTP layer with MTP5 |
| No index-group workspace for impls that convert top-k inline | FlashInfer SM90, ROCm AITER, SM120 (unless HiSparse is on), Dots3Note; no effect on SM100 | **Memory:** the workspace, side stream and events of each opted-out group are not allocated, about 64 MiB per group at 8K tokens and top-k 2048 | Formula `(rows + 1) x topk_width x 4 B`; zero allocation checked on CPU for the SM90 impl, the others by reading their `forward_mqa` |
| Opt-in masked-MHA prefill for cold batches on quantized KV, default off | SM100 with FA4, GLM-5.x / DeepSeek-V3.2 geometry, fp8 or `nvfp4_ds_mla` KV, TP8 | **Perf:** about 4.0x / 7.5x / 12.6x fewer attention FLOPs for a cold 16K / 8K / 4K prompt (342 → 86, 160 → 21, 68 → 5.4 TFLOP per GPU) | FLOP count, not time; the repo's measured crossover table puts masked MHA ahead of sparse MQA at TP8 up to 112K tokens for unquantized caches |

## Details

- **Index groups.** `SparseMLACommonImpl.uses_index_group` lets impls whose `forward_mqa` converts top-k inline skip registration (HiSparse keeps the group). `SparseMLAIndexGroupBuilder.skip_index_producing_layer()` ends the current group when such a layer produces indices, so a later skip-top-k layer cannot reuse a stale conversion. A layer also starts its own group when its KV cache dtype differs from the group's (`--kv-cache-dtype-skip-layers`): followers read the rows their leader converted, so they must route and convert each batch alike, and a bf16 layer and a quantized one can take different FlashMLA paths or prefill routes. GLM-5.3-Flash now builds one decode-row-sized builder (rows = min(max_num_batched_tokens, max_num_seqs x decode query length)) for its sparse MLA layers, as the DSA models do; the MTP layer builds its own the same way. Trade-off: batches above rows + 1 tokens convert inline in `_convert_once` instead of in the side-stream workspace; unmeasured.
- **Masked MHA on quantized KV.** The existing gate rejects every quantized cache because masked MHA's cached-context gather (`gather_and_maybe_dequant_cache`) cannot decode the packed ds_mla layouts (plain fp8 it can, but that path is unvalidated). A batch without cached context never reads the cache (K/V come from the new tokens' bf16 latents), so the flag admits only those batches, and `_compute_context_mha` asserts on packed layouts. Such a prefill attends to unquantized K/V, as the dense-MHA prefill already does for prompts up to `index_topk` tokens; accuracy and TTFT still need a GPU check, because the routing thresholds were measured on unquantized caches. The 128 MiB top-k mask workspace is reserved only where a masked-MHA route exists for the builder's backend and TP size.
- **Limitations.** Cached-context prefill and decode are unchanged. The source diff is +135/-32 over 11 files and the tests +454/-11 over 7. The workspace tests use real impl constructors and builders; the wiring tests stub the GPU-only pieces (the MLA wrapper, the top-k op and, in the model-level test, the decoder layer), because the CPU platform cannot build sparse attention layers. The changes are independent and could be split. The commit carries no `Signed-off-by`.
- **Not checked for duplicates.** The upstream duplicate-work searches from `AGENTS.md` could not be run from this environment (no `gh`, access limited to this fork); a human must run them before this goes upstream.
