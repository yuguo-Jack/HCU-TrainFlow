### Coverage note

This repro is TP=1 (single GPU), so it exercises the **EngineCore → ZMQ → Frontend** error path end-to-end on real hardware. The **Worker → pipe → Executor** path (which fires with TP≥2) is covered by the unit tests (`test_worker_startup_failure_surfaces_root_cause` spawns a real subprocess and verifies the full message round-trip), but hasn't been verified end-to-end on multi-GPU hardware. CI on a multi-GPU runner would confirm that leg.

The default `__eq__` for this dataclass compares all fields, which can lead to duplicate entries in lists of failed processes if the same process is reported with and without an `exitcode`. This can happen in `multiproc_executor.py:wait_for_ready`. To ensure processes are uniquely identified, it's better to define a custom `__eq__` and `__hash__` based on the process ID (`pid`) when available.

```python
@dataclass
class FailedProcessInfo:
    name: str
    pid: int | None = None
    exitcode: int | None = None

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, FailedProcessInfo):
            return NotImplemented
        # Two processes are the same if they have the same pid, if available.
        # Otherwise, fall back to name.
        if self.pid is not None and other.pid is not None:
            return self.pid == other.pid
        return self.name == other.name

    def __hash__(self) -> int:
        if self.pid is not None:
            return hash(self.pid)
        return hash(self.name)
```

The current order of operations can lead to losing the `exitcode` information for a failed process. If `merge_failed_processes` is called first, it might add a `FailedProcessInfo` with `exitcode=None`. The subsequent check for the `candidate` from `failed_handle` might not add the more detailed information if the process is already considered present. By processing `failed_handle` first, you ensure that the `FailedProcessInfo` with the most complete information is added to the list.

```suggestion
                candidate = FailedProcessInfo(
                    name=failed_handle.proc.name,
                    pid=failed_handle.proc.pid,
                    exitcode=failed_handle.proc.exitcode,
                )
                if candidate not in failed_processes:
                    failed_processes.insert(0, candidate)
                failed_processes = merge_failed_processes(
                    failed_processes,
                    response.error if response is not None else None,
                )
```
