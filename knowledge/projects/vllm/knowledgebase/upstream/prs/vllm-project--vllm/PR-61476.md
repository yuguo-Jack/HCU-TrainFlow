## Overview

Enroll five NVIDIA CI steps in automatic runtime sharding, selecting long jobs from the [duration ranking](https://vllm-ci-dashboard.vercel.app/jobs) over the preceding 12 hours. Batch 4 of five independently based changes.

## Claims

Preserve the test commands and discovery scope while assigning tests using main timing data. Existing AMD fixed shards retain their effective commands and parallelism. Actual wall-time and cost improvements await Buildkite validation.

**KV offload exceeds the overhead threshold:** clean main [94523](https://buildkite.com/vllm/ci/builds/94523) takes 23.93 job-min; two shards take 36.37 (+52%, +6.22 min/shard), with wall time falling to 19.82 min. Both tests pass and plugin/count checks match. Splitting the two DeepSeek connector cases loses warm-cache reuse: engine initialization is 399.90 + 12.32 seconds on main versus 397.13 + 390.94 across shards (+375.85 seconds). TileLang compile-start log entries increase from 115 to 188 across all workers, and the simple connector’s first GSM8K evaluation increases from 61.4 to 268.4 seconds. Total pytest time increases 8.72 min; time outside pytest adds 3.71 min, mostly checkout: 203.8 + 19.7 seconds across shards versus 18.8 seconds on main (+3.41 min). Even excluding all additional time outside pytest, the pytest increase alone is +4.36 min/shard, still above the threshold. Weight loading is slightly faster in the shards, so it does not explain the increase. This is an expensive sharding candidate and remains flagged for review; the wall-time reduction costs substantially more than the guide’s 10–20% target.
