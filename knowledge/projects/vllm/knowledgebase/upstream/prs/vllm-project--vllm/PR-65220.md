# [Feature][Distributed] Default supported shared-memory queues to futex waits

[Upstream PR](https://github.com/vllm-project/vllm/pull/65220) · state: open · merged: False

## Original PR description



## Overview

Default supported local shared-memory `MessageQueue` participants to futex-backed
waits, with `VLLM_SHM_WAIT_BACKEND=stock` as the explicit opt-out. Payload serialization
and remote transport remain unchanged.

## Claims

- Select the optional native control module automatically only on supported
  64-bit Linux x86_64/aarch64, ordinary-GIL CPython. Unsupported automatic
  selection or the exact absent optional module falls back to stock; unrelated
  import, ABI and initialization errors are not hidden.
- Attaching readers follow the writer's exported policy. Remote-only operation
  does not need local native controls.
- Parking avoids continuous polling while waiting for local publication or
  capacity. This is not a universal throughput, latency, CPU or power claim.

## Details

Continuous polling motivated a separate process-shared C11 control block for
the existing payload ring. Waiter registration and a final predicate recheck
prevent missed wakes; aborted writes do not publish, and consumer exceptions
release slots. Existing executor shutdown notification remains required: a
futex is not a peer-death detector. Wake/close must precede unmapping, and mixed
control ABIs are unsupported.

One non-owner attachment helper uses public `SharedMemory(track=False)` on
Python 3.13+, preserving older-Python behavior and creator unlink ownership.
Portable builds, conservative atomics and ordinary-GIL assumptions remain.
There is no free-threaded support, CUDA kernel change or Vera/Rubin-only tuning.

Native ABI/lifetime maintenance and blocking-wake latency are real costs;
roughly 667 added main/build lines warrant design scrutiny and discussion of
the architectural RFC guidance. Related [PR52917](https://github.com/vllm-project/vllm/pull/52917)
proposed adaptive spin/architecture waits and is closed unmerged; this proposal
instead uses timed process-shared futex parking. That status is not evidence of
superiority. The loader mode selector is a separate contribution.
