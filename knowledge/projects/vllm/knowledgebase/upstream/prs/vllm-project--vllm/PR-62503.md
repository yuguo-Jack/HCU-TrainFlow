# [Perf][GDN] Add opt-in parallel inverse with fused zero stores

[Upstream PR](https://github.com/vllm-project/vllm/pull/62503) · state: open · merged: False

## Original PR description

## Overview

Add opt-in parallel diagonal solves and fused zero stores to the existing
non-TMA GDN 64x64 inverse. The default solver remains unchanged.

## Claims

- Batch the four independent 16x16 diagonal recurrences, preserving the existing
  block-merge algorithm and IEEE dot products.
- Initialize unwritten upper blocks and varlen padding in the same launch,
  avoiding the separate zero-fill launch.
- Restrict the opt-in path to FP32 inputs, BF16 outputs, B=1, H=32, BT=64,
  variable lengths and non-TMA execution; other configurations retain the
  original implementation.

## Details

Enable with `FLA_TRIL_PARALLEL_DIAGONALS=1`. No model weights, quantization,
sampling settings, core scheduler or model runner interfaces are changed.
Register/layout effects may vary by accelerator, so the path remains opt-in.

### Duplicate-work check

Refreshed open-PR searches for `solve_tril` and the author's parallel-inverse PRs
found no existing PR implementing this standalone diagonal/zero-store change.

- [#38315](https://github.com/vllm-project/vllm/pull/38315) fuses KKT, inverse
  and WY preparation. This change keeps those interfaces and optimizes the
  existing standalone inverse instead; it does not add another KKT/WY fusion.
- [#61779](https://github.com/vllm-project/vllm/pull/61779) targets GDN prefill
  metadata and grids, rather than the inverse recurrence and initialization.

AI assistance was used for implementation, duplicate-work research, tests,
benchmark automation and this description. The human submitter confirmed review
of the change before publication. The test results above were produced with
AI assistance; no separate human-run test result is asserted here.
