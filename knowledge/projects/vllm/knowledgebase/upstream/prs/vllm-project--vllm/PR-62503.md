# [Perf][GDN] Add opt-in parallel inverse with fused zero stores

[Upstream PR](https://github.com/vllm-project/vllm/pull/62503) · state: open · merged: False

## Original PR description

## Overview

Add an opt-in parallel solve to the non-TMA GDN 64×64 inverse. The four independent 16×16 diagonal recurrences run together, and the same kernel writes upper-block zeros and varlen padding.

## Claims

- Removes the separate zero-fill launch while preserving the existing block merge and IEEE dot products.
- Enabled with `FLA_TRIL_PARALLEL_DIAGONALS=1`, for FP32 input/BF16 output, B=1, H=32, BT=64 and variable lengths. Other configurations use the original solver.

## Validation

Rebased onto `1ca0dfb9` on Oct 29 with the same PR patch. Applicable changed-file pre-commit checks passed. The C550 measurements below are from the earlier checkpoint; GPU and model tests have not been rerun on this head.

On MetaX C550, eager solver-call latency fell by 32–49%:

| Active tokens | Baseline median ms (min–max) | Candidate median ms (min–max) | Reduction |
| ---: | ---: | ---: | ---: |
| 1,072 | 0.111557 (0.111114–0.111721) | 0.075761 (0.073306–0.075960) | 32.09% |
| 3,216 | 0.330168 (0.329480–0.332733) | 0.169592 (0.167841–0.169697) | 48.63% |

Five alternating pairs; each sample times 100 calls with CUDA events after 10 warmups. Other workers were resident. These are solver timings, not whole-model gains.

- 13 kernel/graph checks passed: reference values, upper zeros, padding, fallback and changed-length replay.
- Qwen3.5-35B-A3B W8A8 regression: all 8 greedy token sequences matched; the new path ran 210 times. TP1, eager, no MTP/prefix cache, temperature 0, seed 20261008, max_tokens 128.
- Changed-file pre-commit checks passed, including mypy and CI test tethering.

GPU validation loaded the candidate solver into a pinned MetaX engine: Python 3.10.10, torch 2.10.0+metax3.8.0.7, vendor Triton 3.6.0. Static checks used Python 3.12.15. This does not establish current-main serving compatibility or NVIDIA/ROCm performance. Initial stream-creation and RPC setup failures were resolved before the reported successful runs.

Measured base: `4bd75e952a9f423742223c97c8cc9fc6db362950`; candidate: `be22e9878d7c47459bc860ac771895d4d610d4cf`.

## Details

The path stays opt-in because register/layout effects depend on the accelerator. It keeps the standalone solver interface: #38315 instead fuses KKT/inverse/WY preparation, while #61779 changes prefill metadata and grids.
