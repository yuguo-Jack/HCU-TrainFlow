# [ROCm][DSv4.1] Overlap the Engram WKV chain with the decoder layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/63326) · state: open · merged: False

## Original PR description

## Overview

This PR might be superseded by https://github.com/vllm-project/vllm/pull/63367, as it might reduce or nullify the uplift produced by this PR. TODO: Run sweep with both PRs enabled.

On ROCm with TP > 1, the DeepSeek-V4.1 Engram layer 14 runs its WKV chain (head all-gather, `wkv` GEMM, output all-gather) inline on the default stream on every eager step. The chain's input depends only on the hash ids, which are known before the decoder runs. This PR runs the chain on a side stream behind decoder layers 3 to 12. The gathers are done without collectives: each rank pushes its shard into every peer's IPC buffer with plain stores, and the decoder layers' own TP collectives serve as the cross-rank barrier. The fused post kernel reads the gathered rank-major output directly.

## Claims

- Across a 12 point sweep this PR yields: -1.2% mean TTFT, -2.3% mean TPOT, -1.1% median TPOT,
- The WKV output is bit-identical to the inline path on every rank, so model outputs do not change.
- Graphed steps, CUDA, other ROCm architectures, TP1, sequence parallel, Engram DP sharding, PP, LoRA and ubatching all keep the current path.

- **End-to-end WKV check.** A temporary check compared the pushed WKV output with `self.wkv(self.embed(hash_ids))` at every step of a TP4 serving run with chunks of 1024 to 16384 tokens. ## Details

**Why no collectives on the side stream.** A collective kernel spins until its peers join. Next to the default stream's TP all-reduces, ranks can run the two in different orders and deadlock. A first version with RCCL all-gathers on a private communicator hung at c=640.

**Schedule** (new `amd/engram_ahead.py`, called from `DeepseekV4Model`):

1. After the lookups, the side stream pushes this rank's head rows to every peer.
2. Before layer 3, the default stream waits for that push. Once layer 3's collectives pass, every rank has pushed.
3. Before layer 4, the side stream runs the `wkv` GEMM and pushes its output shard.
4. Before layer 13, the default stream waits for that push, and layer 14 reads the `[tp, T, 6400]` buffer.

A rank only overwrites a peer's buffer after a collective that the peer reaches after reading it, so buffers are never overwritten while being read. With the barrier at layer 3, both waits never stalled from 513 to 16384 tokens, and moving it between layers 2 and 6 changed nothing measurable.

**Other changes.** The push is a persistent Triton kernel with 128 workgroups, which matches RCCL all-gather bandwidth without crowding the default stream. `_fused_engram_post_wkv_kernel` gains a `KV_RANK_COLS` constexpr to read the rank-major layout; existing callers pass 0. No host synchronization is added.

**Gating.** ROCm gfx942/gfx950, TP > 1, Engram DP 1, no SP, PP 1, no LoRA or ubatching, and eager steps of at least 513 tokens. Layer 1 keeps the inline path because no collective runs early enough to act as a barrier for it.

**Limitations.**

- **Memory:** one uncached buffer of about 1 GiB per GPU at 16384 tokens and TP4, allocated at model load, before the KV cache is sized.
- **Platform:** benchmarked only on MI355X at TP4, with this commit on a ROCm development branch.



### Existing PRs

I searched open vllm-project/vllm PRs for "engram prefetch", "engram wkv" and "engram rocm". None overlaps the Engram WKV chain with the decoder.

- [#56989](https://github.com/vllm-project/vllm/pull/56989) (draft) packs FP8 Engram rows through the TP head exchange. It reduces the bytes moved, while this PR hides the exchange, so the two compose.
- [#60938](https://github.com/vllm-project/vllm/pull/60938) (draft) fuses the Engram post update into the delayed mHC input on CUDA Blackwell TP1. It does not touch the WKV chain or ROCm.
- [#62091](https://github.com/vllm-project/vllm/pull/62091) replaces the DP lookup collectives for GPU-resident tables. It does not cover the TP path changed here.
