# [Bugfix][DSv4] Remap Quark MTP layer_quant_config onto draft prefixes

[Upstream PR](https://github.com/vllm-project/vllm/pull/56054) · state: closed · merged: True

## Original PR description

## Purpose

`--speculative-config '{"method":"mtp"}'` fails to load mixed Quark DeepSeek-V4 checkpoints (FP8 attention / shared experts + NVFP4 routed experts). The draft modules are constructed under `model.layers.{num_hidden_layers + i}.*`, but `_make_deepseek_v4_weights_mapper` rewrites Quark `layer_quant_config` keys from `mtp.{i}.*` to `model.mtp.{i}.*`. Per-layer lookups miss, every MTP linear falls back to the global NVFP4 scheme, and `PackedColumnParameter.load_merged_column_weight` then asserts on a packed vs unpacked shape mismatch.

This is independent of the ROCm PDL warmup fix in #56035.

## Changes

- Add `align_mtp_quant_config()` to re-key `model.mtp.{i}.` onto the draft prefixes before MTP construction.
- Give `DeepSeekV4MTP` the same `packed_modules_mapping` as `DeepseekV4ForCausalLM` so fused `gate_up_proj` / `fused_wqa_wkv` unfold to `w1`/`w3` and `wq_a`/`wkv` for per-layer lookup.
- Apply on amd / nvidia / xpu MTP classes (same mapper mismatch exists on all three).

## Test plan

- [x] `vllm serve` DeepSeek-V4-Flash-NVFP4 on 8× gfx950, TP=8, `--speculative-config '{"method":"mtp","num_speculative_tokens":1}'`
- [x] MTP weights load (`MTP draft model loaded: 39 params`)
- [x] Greedy completion and a short chat request succeed
- [x] Speculative acceptance is non-zero (46/51 draft tokens accepted ≈ 90%)


## Test result

ROCm serve reached `Application startup complete`. `/health` 200. Greedy `"The capital of France is"` produced `" Paris."`; chat `"Name three prime numbers greater than 100"` produced `"101, 103, 107"`. Spec decode metrics: 51 draft tokens, 46 accepted.
