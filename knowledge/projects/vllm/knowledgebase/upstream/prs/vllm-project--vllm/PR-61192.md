# [Frontend] systemone: prefill the shared prefix once before the reads on hybrid models

[Upstream PR](https://github.com/vllm-project/vllm/pull/61192) · state: closed · merged: True

## Original PR description

## Overview

`/v1/systemone` on hybrid (Mamba/linear-attention) models prefilled the state once per question, because reads that start together cannot reuse each other's recurrent state. This sends one request for the tokens all questions share before the reads, so each question only prefills its own text. Related: #59299 (endpoint), #60677.

## Claims

- Hybrid model, prefix caching on, 2+ questions: 4 questions 25.3 → 8.1 s, 16 questions 106.5 → 12.0 s, 64 questions 419 → 28.7 s (p50, 2k-token state). Prefix-cache hit rate 0.37 → 0.94.
- Throughput with 8 questions of a 1k-token state per request: 0.027 → 0.17 req/s.
- A single question is unchanged (6.4 s). Answers are unchanged (label accuracy on 120 synthetic tickets identical: 0.90 / 0.67 / 1.00).
- No change on attention-only models or with prefix caching off: the warm-up is skipped.

## Validation

Qwen3.8-27B (Qwen3_5 hybrid, 4-bit, MTP 3) on gfx1151 (Radeon 8060S), nightly `0.31.1rc1.dev273` (`2eb491e18b`), `--enable-prefix-caching --mamba-cache-mode align --prefix-match-unit 32 --logprobs-mode raw_logprobs`. Same seed and prompts in both columns, p50 latency of a `/v1/systemone` call, state of 2048 tokens:

| questions | main | this PR |
|---|---|---|
| 1 | 6.4 s | 6.4 s |
| 4 | 25.3 s | 8.1 s |
| 16 | 106.5 s | 12.0 s |
| 64 | 419.1 s | 28.7 s |

| config | 4 q | 16 q | 64 q |
|---|---|---|---|
| `--enable-mamba-shared-prefix-checkpoint`, main → PR | 14.1 → 8.1 s | 36.4 → 11.9 s | 126.3 → 28.7 s |
| MTP off, `--prefix-match-unit 16`, main → PR | 11.6 → 7.2 s | 42.8 → 10.0 s | n/a → 21.2 s |

The warm-up alone gives the full gain; the checkpoint flag is not needed with it (8.1 / 12.0 / 28.7 s with and without).

Attention-only model (Qwen3-0.6B, prefix caching on), warm-up forced on for the test: 4 questions 0.375 → 0.399 s, 16 questions 0.538 → 0.564 s, since the blocks are already shared within a step there. That is why the warm-up is limited to hybrid models.

Tests:

```bash
pytest tests/entrypoints/generate/structured_decisions/test_strategies.py
```

28 passed on main `56e3b08` (`test_common_prefix_len` and `test_state_is_prefilled_once_before_the_reads` are this PR's). The new test checks the order and content of the engine calls (warm-up request first, with `cache_salt`, then the reads, all starting with the same ids) and the four cases where it is skipped (attention-only, prefix caching off, one question, short state).

Reproduction: a client posting `/v1/systemone` with a fresh synthetic state of 2048 tokens and N filler `choice` questions, after one 2-question warm-up call; p50 over 3 repetitions per N, same seed for both columns; server flags as above.

## Details

- The warm-up is a `max_tokens=1` request on the longest common token prefix of the question prompts (at least 128 tokens), sent with the request's `cache_salt`, priority, LoRA and trace headers. Its prompt-end checkpoint lands where the questions diverge, so each read resumes there and only prefills its question.
- Cost: one extra scheduler round trip when the state is cold. Skipped for one question, a prefix under 128 tokens, prefix caching off, or a non-hybrid model.
- Not covered: Mamba state kept by connectors, and models other than the one above. The change is in `NextTokenStrategy`, so the diffusion strategy inherits it; it was not run.
- Overlaps with the open #61251 (tokenizes the state once per decision and adds a gate for big decisions), which edits the same `read`: if that lands first, the warm-up request should go through its gate; I will rebase on whichever lands first.
