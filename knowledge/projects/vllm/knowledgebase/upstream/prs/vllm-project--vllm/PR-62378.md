# [Kernel][Perf] Bound DSA candidate mask writes to each row's extent

[Upstream PR](https://github.com/vllm-project/vllm/pull/62378) · state: open · merged: False

## Original PR description

## Summary

`_mask_candidates_kernel` (DSA/NSA indexer candidate mask, shared CUDA path) poisoned the **full logits workspace width** with `-inf`, although only each row's `[start, end)` extent is ever read back. The workspace is `max_model_len` wide (CUDA-graph static) while each row's live extent is its own request's block range in the packed column space, so most of those stores hit padding or other requests' column ranges.

This PR bounds the store predicate to the row extent and early-returns from tiles beyond `end`. It aligns the shared kernel with the semantics the ROCm strided variant already relies on (#56628, see also #59668): every consumer of the masked logits is extent-bounded:

- `top_k_per_row_prefill` / `top_k_per_row_decode` read `rowStart`/`rowEnd` from the cu_seqlen tensors (`csrc/sampler.cu`);
- `_block_scores_kernel` loads with `cols < end`;
- `_merge_dcp_topk_global` is a no-op at `dcp_world_size == 1`.

Not a duplicate of #59668: that PR fuses the two ROCm kernels in `rocm_aiter_mla_sparse.py`; this one shrinks the shared kernel's write set.

## Performance (H200 ×8, DeepSeek-V4.1-Flash, TP2×DP4+EP, DSA sparse indexer, saturated decode)

| Metric | Before | After |
|---|---|---|
| `_mask_candidates_kernel` per call (nsys) | 145.1 µs | **54.9 µs (−62%)** |
| Output throughput (rate 1.3 req/s, 10k/5k, 320 prompts) | 4918.8 tok/s | **5096.2 tok/s (+3.6%)** |
| TPOT p99 | 30.59 ms | **27.02 ms (−12%)** |

End-to-end numbers are back-to-back clean runs on the same deployment, same seed/params.

## Correctness

- Greedy outputs over 8 fixed prompts are **byte-identical** before/after (plus a revert control run), so no model-affecting output change is expected.
- New test `tests/kernels/attention/test_candidate_blocks.py` (8 cases; widths 1–262144; packed starts/ends; `row_repeat` groups; −1 padding and clamped/edge candidates) asserts agreement with a full-width poisoned reference within `[0, end)` and that the workspace outside each row's extent is left untouched — the same contract style as the ROCm test.

Thanks for the pointer — agreed that the effect is context-length dependent, so we ran a long-context accuracy A/B on the official MRCR benchmark (openai/mrcr), covering all needle variants.

**Setup.** 103 prompts from all three variants (2/4/8-needle) across three context tiers (~7-10K, ~27-31K, ~64-71K tokens, lengths measured with the model tokenizer), greedy decoding, offline `LLM` inference on H200×8 (TP8), DeepSeek-V4.1-Flash, identical engine config; the **only** difference between arms is this patch (`candidate_blocks.py` before/after). 2 runs per arm on identical prompts. Since the model's tokenizer ships no chat template, the MRCR conversations are rendered to a deterministic plain-text transcript and sent to the completions path — identical on both arms.

**Scoring.** Full-text exact reproduction of a whole needle floors at 0 even unpatched (the needle is a multi-hundred-token poem/diary the model paraphrases), so we score needle identification: the response must start with the required random string and reproduce the located needle's opening — mid-range sensitivity, identical across arms. Note this stack is not call-reproducible end-to-end: the same engine re-queried with the same prompt under greedy sampling flips a large share of these long-form answers between calls (scheduling-dependent batch composition → reduction-order changes), so exact-output A/B equality is unattainable for any change including none — hence statistical equivalence rather than output diffs.

**Result: no accuracy difference.**

| variant / context tier | before | after |
|---|---:|---:|
| 2-needle ~10K | 22/24 | 23/24 |
| 2-needle ~30K | 13/24 | 12/24 |
| 2-needle ~70K | 18/22 | 18/22 |
| 4-needle ~10K | 5/24 | 7/24 |
| 4-needle ~30K | 12/24 | 12/24 |
| 4-needle ~70K | 4/16 | 3/16 |
| 8-needle ~10K | 10/24 | 11/24 |
| 8-needle ~30K | 8/24 | 8/24 |
| 8-needle ~70K | 4/24 | 4/24 |
| **total** | **96/206 (46.6%)** | **98/206 (47.6%)** |

Two-proportion |z| = 0.20 (n.s.); per-sample direction 3 vs 6 with 94/103 equal; responses starting with the required random string: 206/206 on both arms. A supplementary MRCR-style eval (RULER-MRCR task format, 90 prompts, 8K/32K/131K tokens, 3 runs per arm) agrees: 32.6% vs 30.4% pooled (z = 0.56, n.s.).

The kernel-level guarantee remains the tighter one: the added unit test shows the masked logits are bit-identical within `[start, end)`, which is where every consumer reads (top_k_per_row_prefill/decode, `_block_scores`; the DCP merge is a no-op at `dcp_world_size == 1`).

(This eval was run with AI assistance; all numbers above were measured on our H200 cluster and re-checked from the raw per-sample logs.)
