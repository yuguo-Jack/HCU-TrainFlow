# [Pooling] Improve SPLADE throughput 3.6% to 7.8% 

[Upstream PR](https://github.com/vllm-project/vllm/pull/62250) · state: closed · merged: True

## Original PR description

## Purpose

This PR speeds up SPLADE max pooling by batching the `dense/GELU/layer-norm` transform and applying `relu/log1p` after max reduction. Vocabulary projection still runs per sequence, and dense embeddings, classification, sum pooling, and the full MLM-head forward remains as is.

**Accuracy result:** No retrieval-quality regression was observed on SciFact. On both H100 and B300, the branch preserved main’s nDCG@10, Recall@100 and every query’s top-10 result ordering. Scores were comparable to the HF FP32/BF16 references; the raw-vector norm and numerical-error checks are reported below. This conclusion covers the tested checkpoint and SciFact dataset; the later merge from `main` has not been re-evaluated.

nDCG@10 measures how well relevant documents rank in the top 10; Recall@100 measures how many relevant documents appear in the top 100 (higher is better for both). Using raw embeddings without L2 normalization preserves their magnitudes, so normalization cannot hide changes in vector scale.
