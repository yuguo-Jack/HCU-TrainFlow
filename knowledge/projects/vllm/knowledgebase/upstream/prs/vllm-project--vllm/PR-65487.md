# [Bugfix][Distributed] Align packed weight-transfer entries for zero-copy unpack

[Upstream PR](https://github.com/vllm-project/vllm/pull/65487) · state: open · merged: False

## Original PR description



## Overview

Fixes #64936. Packed NCCL/IPC weight transfer now pads each tensor's start offset to a must-agree `packed_alignment`. Workers can then unpack every tensor as a zero-copy view instead of crashing on misaligned slices. This is the padding-based alternative to the receiver-only clone fixes in #65009 and #57665, and it keeps their clone as a fallback for the legacy layout.

## Claims

- **Bug fix:** a packed transfer containing an odd-sized entry (e.g. a 3-byte uint8/FP8 scale) followed by a wider dtype no longer fails with `RuntimeError: self.storage_offset() must be divisible by 8 to view Byte as Long`.
- **Zero-copy with vLLM trainers:** `NCCLTrainerInitInfo` / `IPCTrainerInitInfo` default to `packed_alignment=16`, which covers every dtype's itemsize. Unpacked tensors are views of the receive buffer, with no per-tensor copies.
- **No breakage for trainers outside vLLM:** the worker-side init infos (and the low-level helpers) default to `packed_alignment=1`, which is today's wire format. With alignment 1, `unpack_tensor` copies the misaligned entries instead of failing.
- **A version mismatch fails loudly:** a new trainer sending `packed_alignment` to an old worker is rejected at init. The worker builds its init dataclass with `**init_dict`, so the unknown key raises `ValueError`; it can't corrupt weights or hang. The field is only sent for packed transfers, so unpacked transfers (including sparse NCCL) still work against older workers.

## Details

**Root cause.** `pack_tensors` and `packed_ipc_producer` concatenate raw bytes with no padding. `unpack_tensor` splits the buffer at those sizes and calls `.view(dtype)`, which needs `storage_offset() % itemsize == 0`. A single odd-sized entry shifts every later entry in the pack.

**Why padding instead of only cloning.** Cloning misaligned slices on the receiver (#65009, #57665) works, but it can copy close to a whole pack per in-flight slot (up to ~`num_buffers × buffer_size_bytes` extra memory, held longer under layerwise reload). Padding removes the copy. The overhead is at most `(A - 1) × num_tensors` bytes. A safetensors-header scan from the design analysis (not re-run for this PR) found 0 B for BF16/FP8 models (Qwen3, DeepSeek-V3, gpt-oss) and ~1.07 MB on a 424 GB NVFP4 model.

**Wire format.** Entry *i* starts at `round_up(end_{i-1}, A)`, with the first entry at 0 and no trailing pad. `tensor_sizes` still carries the raw sizes, so no new per-tensor metadata is needed. `A = 1` is exactly today's format. Chunk-close rules are unchanged except that the running size is now the padded end:
- **NCCL:** close right after the tensor whose end exceeds `buffer_size_bytes`.
- **IPC:** close before a tensor whose padded start + size would overflow the buffer.

**Compatibility.**

| Trainer | Worker | Result |
| --- | --- | --- |
| new vLLM | new vLLM | A=16, zero-copy |
| old vLLM / no vLLM (field not sent) | new vLLM | A=1, legacy layout; misaligned entries copied |
| new vLLM, packed | old vLLM | init fails loudly (unknown `packed_alignment` key) |
| new vLLM, unpacked | old vLLM | works (field not sent) |

**Implementation.**
- `packed_offsets()` is the single source of the layout. `_take_chunk()` is the single NCCL chunk-close rule, shared by `pack_tensors` and `packed_nccl_broadcast_consumer`, which replaces the consumer's hand-rolled per-slot accumulator.
- `pack_tensors` still issues one `torch.cat`, with zero pads between entries. Its unused `tensor_list` / `current_size` parameters are removed.
- In the NCCL consumer, unpacking (and any fallback copy) now happens on the slot stream before the ready event is recorded, and the copies are `record_stream`ed like the packed buffer. The ready-event chain and allocator lifetime tracking therefore cover them.
- `packed_ipc_consumer` no longer trims the buffer to `sum(tensor_sizes)`. `unpack_tensor` slices by offset and raises if the layout doesn't fit the buffer. Its existing per-tensor `.clone()` (for buffer reuse) is unchanged.
- The low-level helpers default to `alignment=1`, so out-of-tree callers of `packed_nccl_broadcast_producer` etc. keep the format a default worker expects. Only the trainer init infos/engines opt into 16.
- Docs (`nccl.md`, `ipc.md`) describe the layout and the new field. The `*_no_vllm.py` examples stay on alignment 1 (legacy path), with a comment on how to opt in.

**Open questions for reviewers.**
- Should the fallback copy log a one-time warning when it fires with `A > 1`? That would point at a producer/consumer mismatch.
- How should this sequence with #65009? This PR includes an equivalent fallback. If #65009 lands first, I'll rebase onto it.
