# [Bugfix][Core] Include prompt embedding dtype in prefix cache hashes

[Upstream PR](https://github.com/vllm-project/vllm/pull/59643) · state: closed · merged: False

## Original PR description



## Overview

Include the source dtype in prompt-embedding prefix-cache digests, preventing numerically different FP16/BF16 inputs with identical raw bytes from sharing KV blocks.

## Claims

- Mixed-dtype embeddings no longer reuse each other's cached prefixes.
- Same-dtype cache reuse and the KV-event extra-key structure are preserved.

## Validation

Tested source base: `cfd54ca881`; Python 3.12.13, Torch 2.13.0+cu132, Transformers 5.14.1. Model validation used Qwen2.5-0.5B-Instruct, one NVIDIA A30, TP1, BF16, MRV2, eager, TRITON_ATTN, 65 input rows, greedy generation of four tokens, and prefix caching enabled.

| Full cache utility suite | — | 161 passed |

| Same-dtype BF16 repeat | Reused contaminated entries | Correct BF16 tokens, 64 cached tokens |

Model reproduction: extract 65 input embeddings from the Qwen checkpoint as FP16; reinterpret with `fp16.view(torch.bfloat16)` to retain identical bytes; submit FP16, BF16, isolated BF16 with a different `cache_salt`, and repeat BF16 to the same engine. Compare `num_cached_tokens`, generated token IDs, and logprobs. Both model arms used `VLLM_WORKER_MULTIPROC_METHOD=spawn` and `OMP_NUM_THREADS=1`.

## Details

The existing SHA256 digest reads only tensor bytes. Prefix dtype bytes and a separator to that digest, preserving the per-request digest cache and the `("prompt_embeds", digest)` event-key structure. Existing exact-digest assertions are updated. Cached external entries for these prompts will receive new keys; deployments should use consistent versions across cache producers and consumers.

Duplicate check: searched open PRs for prompt embeddings, dtype/hash, and cache collisions. Inspected #53769's patch: it adds key-partitioning tests without a dtype dimension or a production fix. #53496 changes ExampleConnector storage keys; it does not fix this shared embedding digest.

Local model validation used existing precompiled native extensions and a Humming dependency overlay. Neither is changed by this PR. The editable environment's package version metadata is stale; the tested source SHA above identifies the Python code. An initial missing-extension import failure and a fork/H2D hang were resolved before the reported runs. No throughput gain or general model-quality result is claimed; this is a targeted correctness regression.
