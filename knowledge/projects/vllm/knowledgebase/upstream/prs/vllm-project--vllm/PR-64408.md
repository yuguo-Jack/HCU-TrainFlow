# [Feature][Spec Decode] Add full-attention verify extension ABI

[Upstream PR](https://github.com/vllm-project/vllm/pull/64408) · state: closed · merged: False

## Original PR description

## Overview

Add a fail-closed, data-only full-attention verification extension contract for
plugin-registered non-chain/tree speculators such as EAGLE-4.

The change deliberately does not vendor EAGLE-4 tree policy or kernels. It
creates the host ABI that future FlashAttention and ROCmAttention wiring can
use, mirroring the linear-attention extension introduced by #62962.

## Claims

- Add frozen backend identity, batch metadata, and per-layer row contracts for
  out-of-tree full-attention verification.
- Let a registered speculative method name a lazy extension factory.
- Require the attention backend and extension to explicitly support each other.
- Attach one shared extension instance to every metadata builder in a target
  attention group.
- Reject an unwired or incompatible backend during builder setup instead of
  silently verifying a tree as a causal chain.
- Leave built-in speculative methods and draft attention groups unchanged.

## Details

#62962 adds a `LinearAttnVerifyExtension` for GDN and Mamba2 layers. Full
attention still requires an external method to replace the complete attention
backend, and the current EAGLE-4 plugin's tree backend subclasses the
FlashAttention path. That design does not provide a platform-neutral host
contract for ROCm.

This Draft introduces only the common contract and capability negotiation:

- `FullAttentionVerifyMetadata` contains zero-copy batch metadata.
- `FullAttentionVerifyRows` contains one layer's native query/KV/output views.
- The native KV layout remains identified by the exact backend; the ABI does
  not pretend FlashAttention and ROCmAttention layouts are interchangeable.
- `dispatch_full_attention_verify` has no chain fallback.

Both in-tree FlashAttention and ROCmAttention remain unsupported until their
metadata builders and forward paths explicitly implement the contract.

### Dependencies and non-duplication

This is a stacked Draft:

```text
#62962 registry + linear-attention extension
  -> #62963 prepare/post-accept and sampler hooks
    -> this full-attention extension ABI
```

It does not duplicate:

- #62962's GDN/Mamba2 linear-attention extension;
- #62963's model-runner hooks;
- #63028's EAGLE-4 CUDA integration, CUSTOM backend, docs, or real-weight E2E.

No EAGLE-4 source-available algorithm or Triton kernel is copied into vLLM.
