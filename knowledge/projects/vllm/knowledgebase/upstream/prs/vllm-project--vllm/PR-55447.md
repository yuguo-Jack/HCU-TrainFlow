# [Bugfix][Benchmarks] Validate schema and reference in structured-output correctness

[Upstream PR](https://github.com/vllm-project/vllm/pull/55447) · state: open · merged: False

## Original PR description

## Purpose

Fixes #55441. The structured-output serving benchmark's headline `correct_rate(%)` only checked that a response contained a parseable JSON object: the parsed value was discarded, `expected` was never read, and every space and newline was stripped before parsing, mutating string values. A backend ignoring guided decoding and emitting `{}` per request could score the same 100.0 as a fully conforming one.

The JSON arm now grades on content:

- When the dataset carries a reference completion, the response must match it under semantic JSON equality, including for requests outside the `--structured-output-ratio` share. Key order and whitespace do not matter, while booleans remain distinct from integers at every nesting level.
- When the request actually asked for structured output, schema validation runs before reference comparison, so matching an invalid reference cannot bypass the schema.
- Requests without a reference completion retain parseability semantics when they were not asked for structured output.
- Extraction no longer rewrites the payload, so string values keep their spaces.

## Test Plan

`tests/benchmarks/test_structured_output_eval.py` imports the real benchmark module with irrelevant live-serving imports stubbed and drives the real `evaluate` implementation. Coverage includes schema rejection and acceptance, reference equality and mismatch, ratio-excluded requests, schema-before-reference ordering, boolean versus integer references, unparseable responses, and whitespace inside string values.

The three cases added during review fail against the preceding implementation: a ratio-excluded reference mismatch scores 100, an object equal to its schema-invalid reference scores 100, and `{"ok": 1}` matches `{"ok": true}`. After the fix, the complete file reports 12 passed.

## Finding — unstructured share does NOT actually keep parseability semantics when the dataset carries completions

The PR description and the new unit test both claim: "Requests outside the --structured-output-ratio share keep the old parseability semantics, since they were never asked to follow a schema." But look at the branch order in `_eval_correctness_json`:

```python
if expected is not None:
    try:
        return actual_obj == json.loads(expected)   # runs BEFORE structured/schema gate
    except Exception:
        pass
if structured and schema is not None: ...
return True
```

The reference-completion comparison is NOT gated on `structured`. In a real xgrammar_bench run every row gets a completion (`expected.append(request.completion)` is unconditional at benchmark_serving_structured_output.py:565, and `dataset["completion"][idx]` at :285 always exists), so an unstructured-ratio row (extra_body=None, never asked to follow the schema) that emits valid-but-content-different JSON now scores 0 instead of the claimed parseability pass.

Executed probe (real module, real `evaluate`):
- `structured=False`, `expected={'name':'John Smith','age':34}`, response `{"name": "Completely Different", "age": 99}` → **0.0** (claimed: 100 — parseable, unstructured)
- `structured=False`, response matching the reference → 100.0
- `structured=True`, schema-valid but ≠ reference → 0.0 (intended)
- `structured=True`, `expected=None`, schema-valid → 100.0 (intended)

The unit test `test_unstructured_request_keeps_parseability_semantics` only passes because its fixture sets `expected=None` — which never happens for xgrammar_bench rows, so the test does not cover the real unstructured path.

If the intent is really "parseability for the unstructured share", the reference branch should also require `structured` (e.g. `if structured and expected is not None:`). If the intent is that xgrammar_bench rows are always reference-graded regardless of ratio, then the test should carry a non-None `expected` to reflect reality (and the PR body should drop the parseability claim for reference-carrying datasets). Either way, test and description currently disagree with the code on this path.
