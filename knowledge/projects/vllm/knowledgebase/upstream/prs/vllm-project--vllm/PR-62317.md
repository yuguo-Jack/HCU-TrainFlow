# [KV Connector][NIXL] Read only a group's own regions in hybrid SSM transfers

[Upstream PR](https://github.com/vllm-project/vllm/pull/62317) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

In hybrid MLA+SSM models, the NIXL hybrid descriptor path made every attention group read **all** registered regions. Some regions hold only SSM-layer pages or only scratch (`CircularBufferSpec`) pages, so each MLA block also re-read bytes owned by other groups. On GLM-5.3-Flash, about 38% of the bytes on the wire were duplicates. This PR records, per transfer group, which regions hold its layers and addresses only those.

Related: #57662 (dedup regions by `(base_addr, block_len)`) touches the same registration code. It is complementary, not a duplicate; see the Duplicate check below.

## Claims

- On GLM-5.3-Flash (fp8, TP2→TP2 P/D), this cuts transferred bytes by 38% at 100k ISL (2.18 GB → 1.35 GB per request), with transfer time ~20.5 → ~12.4 ms. Accuracy is unchanged.
- Layouts where every group spans every region produce byte-identical descriptors. This covers pure attention, non-SSM models and FA+GDN hybrids such as Qwen3.5 (verified e2e).
- An SSM group no longer reads SSM slots of regions that hold none of its layers, i.e. a group with fewer layers than the others.

## Validation

**E2E.** Prefill TP2 → decode TP2 on separate GB300 nodes, NixlConnector pull mode, fp8 KV, `--no-enable-prefix-caching`. The KV pool was scrambled, and each point was run twice.

| Model | ISL | Bytes / req (before → after) | Descs | Xfer avg | GSM8K through P/D (before → after) |
|---|---|---|---|---|---|
| GLM-5.3-Flash | 32k | 859,615,744 → 565,391,872 | 950 → 646 | ~8.4 → ~5.2 ms | |
| GLM-5.3-Flash | 100k | 2,177,711,104 → 1,348,099,072 (−38%) | 2150 → 1306 | ~20.5 → ~12.4 ms | 81.8% → 80.6% (run-to-run spread 80.8–82.8%) |
| Qwen3.5-122B-A10B (regression check) | 32k / 100k | identical (977,829,888 / 2,626,191,360) | identical (672 / 1440) | | 40.8% → 41.2% (non-P/D baseline 41.2%) |

Before the fix, a byte-level model of the descriptor layout reproduced all 9 measured points exactly (6 fp8 ISLs + 3 bf16). At 100k it predicts 1,347,815,936 B of useful data out of 2,177,711,104 B on the wire, i.e. ~38% duplicates and ~40% at 262k. After the fix, 283,136 B over the useful amount remain, which equals 2 × (143,616 − 2,048). This comes from the tail region aliasing an indexer region and being read at the indexer's block length. That case is the base-address-only keying that #57662 addresses, so it is intentionally out of scope here.

## Details

**Root cause (P/D flow, pull mode):**
1. P and D each call `register_kv_caches`. Regions are keyed by tensor base address. On GLM-5.3-Flash, each rank registers 40 regions: 11 MLA, 11 indexer, 8 KDA-only (34 KDA layers vs. 11 MLA) and 10 `KPOOL_TAIL`-only.
2. D's scheduler gets the remote block ids per KV group and issues a read in `_read_blocks`.
3. `_compute_desc_ids` takes the hybrid path (`num_ssm_regions > 0`). Each non-scratch attention group used `np.arange(num_regions)` and emitted one desc per block for all 40 regions.
4. The 18 KDA-only and tail-only regions hold no MLA/indexer pages. At an MLA block id they contain another group's (aliased) bytes, which D had already fetched through that group's own descriptors, so every MLA block pulled them a second time.

**Fix:**
- `register_kv_caches` now records the set of transfer groups whose layers live in each region, as `_group_region_indices[group] -> sorted region ids` (`None` if the group registered none).
- Attention groups address exactly those regions. This generalizes the previous special case for `CircularBufferSpec`; `_scratch_region_indices` is removed.
- SSM groups keep the `[FA descs | SSM descs]` layout. They address only the SSM slots (`ssm_regions_per_layer` consecutive descs each) of their own regions. The PLE group and groups with no recorded regions keep the previous behavior.

**Why other layouts are unaffected:**
- Pure attention and non-SSM models return before this code, via the fast path (`region_group_ids` / `uses_region_group_mapping`).
- In FA+SSM hybrids where every group has a layer in every tensor (Qwen3.5, GDN), `_group_region_indices[g] == range(num_regions)`, so descriptors are identical. This was confirmed byte-identical e2e above.
- DSv4 packed rows, heterogeneous TP and block-size ratio operate on the desc list and stride (`num_blocks`, `num_fa_descs`, `logical_blocks`), which are unchanged. Only the selected region subset changes.
- Push mode calls the same `_compute_desc_ids`.

**Duplicate check:** no open PR or issue fixes this. #57662 is adjacent (region identity at registration) and touches the same block of `register_kv_caches`, so a small rebase may be needed depending on merge order. #52408 is a docs issue on the SSM region-count invariant.

### Reviewer notes

Please take a careful look at:
- **(a)** Remote-side descriptor ids are computed with the **local** group→region map. This assumes P and D have identical region layouts, the same assumption the code already made about `num_regions`.
- **(b)** The SSM branch assumes each SSM layer owns `ssm_regions_per_layer` consecutive descriptors, in `_ssm_region_indices` order.
