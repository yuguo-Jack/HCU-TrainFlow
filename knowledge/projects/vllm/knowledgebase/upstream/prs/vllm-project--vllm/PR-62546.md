# [XPU][KV Connector] Fix MooncakeStoreConnector on Intel XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/62546) · state: open · merged: False

## Original PR description

Two CUDA assumptions in the Mooncake store connector break it on XPU:

- ReqMeta annotates `current_event: torch.cuda.Event | None`. In an XPU vLLM worker, torch.cuda.Event is a function, so evaluating the annotation raises `TypeError: unsupported operand type(s) for |: 'function' and 'NoneType'` and the connector module fails to import. Use the device-generic torch.Event for the annotation and for the event recorded in wait_for_save.
- RankLocalStoreLayout.prepare_values computes KV addresses in np.int64. Level Zero USM device pointers are above 2^63, so the first save fails with `OverflowError: Python int too large to convert to C long`. Do the address arithmetic in np.uint64 (the Mooncake bindings take uintptr_t).

Neither change alters behavior on CUDA.

@zhenwei-intel Tested with the following setup on 2x B70

**1. Mooncake config (mooncake.json):**
```{
  "metadata_server": "P2PHANDSHAKE",
  "master_server_address": "127.0.0.1:50061",
  "protocol": "rdma",
  "device_name": "mlx5_0",
  "global_segment_size": "32GB",
  "local_buffer_size": "4GB"
}
```
**2. Master:**
```mooncake_master --rpc_port 50061 --metrics_port 9013 \
  --eviction_high_watermark_ratio 0.9 --default_kv_lease_ttl 60s &
```
**3. vLLM:**
```export MOONCAKE_CONFIG_PATH=$PWD/mooncake.json
export MC_USE_TENT=1 RDMAV_FORK_SAFE=1
export MC_TENT_CONF='{"topology":{"rdma_whitelist":["mlx5_0"]}}'
ZE_AFFINITY_MASK=0,1 vllm serve Qwen/Qwen3-30B-A3B-FP8 \
  --tensor-parallel-size 2 --enable-prefix-caching \
  --kv-transfer-config '{"kv_connector":"MooncakeStoreConnector","kv_role":"kv_both"}'
```
