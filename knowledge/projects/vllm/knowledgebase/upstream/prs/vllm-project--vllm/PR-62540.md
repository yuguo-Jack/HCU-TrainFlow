# [CI] Automatically label Reflection Beam model changes

[Upstream PR](https://github.com/vllm-project/vllm/pull/62540) · state: closed · merged: True

## Original PR description

## Overview

Automatically apply the existing `beam` label to Reflection AI Beam pull requests and issues. Extends the labeling approach in #51459 with Beam-specific paths and title patterns.

## Claims

- Label PRs touching Beam's implementation, configuration, Python/Rust parsers, tests, or recipe.
- Label model-specific PR and issue titles, while avoiding ordinary beam-search titles and paths.
- Keep issue matching title-only so pasted logs and configuration in bodies do not trigger the label.

## Validation

- `.venv/bin/pre-commit run --files .github/mergify.yml .github/workflows/issue_autolabel.yml` — all applicable checks passed; unrelated checks skipped. The human submitter independently ran this command and confirmed the results.
- `.venv/bin/python tools/pre_commit/check_label_rules.py` — passed.
- `git diff --check` — passed.
- Local behavioral checks: 16 PR-title cases and 17 executions of the issue-labeling JavaScript with mocked GitHub calls passed, including body-only and ordinary beam-search negatives. All 26 currently tracked Beam-specific paths match; beam-search paths do not.
- Model evaluation is not applicable: this changes only labeling configuration, with no effect on inference, accuracy, or serving.

## Details

The existing `beam` label (description: "Reflection Beam model support") had no automatic rule. File rules cover the current Beam tree without broadly matching every path containing `beam`.

Title patterns recognize versioned names such as `Beam 1.0` and `Beam-1.0`, `Reflection Beam` / `Reflection AI Beam` / `reflection/Beam`, `BeamForCausalLM`, `BeamConfig`, and `[Beam]`. Bare `beam` is deliberately excluded; ambiguous titles such as "Beam loading fails" require manual labeling.

Duplicate-work checks found no open Beam autolabel or labeling PR. The predecessor #51459 is merged; this adds coverage for Beam rather than duplicating that cleanup. No associated issue was supplied.

AI assistance (OpenAI Codex) was used to inspect the existing configuration, implement the rules, and validate them. The human submitter reviewed the complete diff and independently ran the relevant pre-commit checks.
