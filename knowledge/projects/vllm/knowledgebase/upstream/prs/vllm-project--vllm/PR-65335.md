# [Bugfix][KV Offload] Preserve full specs in scheduler cache projection

[Upstream PR](https://github.com/vllm-project/vllm/pull/65335) · state: open · merged: False

## Original PR description



## Overview

Preserve a Uniform KV group's full per-layer specs when building the scheduler cache config, so native offloading sees the same physical pages and canonical-layout eligibility as workers.

## Claims

- Keep heterogeneous page accounting consistent between scheduler and worker for spec-derived and HiSparse indexer sizing.
- Reject canonical storage when a non-portable sibling is hidden by the scheduler's representative MLA spec.
- Reuse the existing `kv_tp_replicas` protocol from #57652; the replicated-layout gate and default options are unchanged.

## Details

`generate_scheduler_kv_cache_config()` replaces `UniformTypeKVCacheSpecs` with its first layer's spec. The offloading translator could then multiply that page by the layer count, or certify canonical MLA storage without inspecting the other layers. Tensor-backed ordinary sizing already uses allocation sizes; the sizing fix concerns the spec-derived fallback and HiSparse path.

Keep the original Uniform in an optional `KVCacheGroupSpec.full_kv_cache_spec` field while retaining the representative used by scheduler block management. Offloading consults the full layout for page accounting and per-layer certification. Projection remains idempotent and does not mutate worker configs.

Duplicate-work checks on 2026-11-03 covered open PRs for offloading/scheduler, Uniform specs, full_kv_cache_spec, and representative/per-layer accounting. #56953 changes multi-group slot accounting and leaves the single-group case unchanged; #55810 changes GLM hybrid grouping/padding. Neither preserves the scheduler's folded per-layer layout. Closed #56772/#56799 addresses canonical secondary row portability. This change complements the already merged #57652.

Related Ascend metadata fix: [vllm-ascend#20766](https://github.com/vllm-project/vllm-ascend/pull/20766). That fix uses the already-existing replication protocol and does not depend on this scheduler-projection change.
