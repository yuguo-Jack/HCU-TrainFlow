# fix(model_loader): deterministic suffix mapping for Gemma4 MoE quantization

[Upstream PR](https://github.com/vllm-project/vllm/pull/41988) · state: open · merged: False

## Original PR description

### Description

**The Architectural Flaw**
The prior weight loading implementation for ModelOpt-quantized Gemma4 models relied on implicit substring matching to handle Mixture of Experts (MoE) parameters. This approach was brittle, causing namespace collisions with varied quantization suffixes and regressions for standard bare weights.

**The Structural Fix**
This PR replaces loose string manipulation with a deterministic `_MOE_SUFFIX_MAP` contract. 
* **Explicit Boundaries:** Establishes a strict mapping protocol for quantized metadata and standard bare weights.
* **Regression Protection:** Implements base-name matching to ensure non-quantized checkpoints load correctly (addressing `gemini-code-assist` feedback).
* **Performance Hoisting:** Moved suffix mapping out of the inner loop to optimize loading latency.
* **Prefix Preservation:** Guarantees that expert prefixes (`w13`, `w2`) remain immutably bound to their correct dimensional shards.

**Verification & Testing**
* **Expanded Test Suite:** Updated `tests/model_executor/model_loader/test_gemma4_weight_loading.py` to include bare-weight regression tests.
* **DCO & Linting:** All commits signed and formatted via `pre-commit`.
* **CI Deferral:** Logic validated locally; requesting maintainer label for Buildkite integration.

The current implementation introduces a critical regression for standard (non-quantized) checkpoints. 

1. **Bare Weight Regression**: `weight_name` includes a trailing dot (e.g., `experts.0.gate_proj.`). Standard checkpoints often provide keys without a suffix (e.g., `...gate_proj`). The `name.find(weight_name)` check will fail for these keys, causing them to be skipped.
2. **Suffix Normalization**: The logic should handle both bare weights and those with suffixes by stripping the trailing dot from the base name and correctly identifying the suffix (including the empty suffix case).

This fix ensures that both quantized metadata and standard weights are correctly mapped to the model parameters.

```suggestion
                    weight_name_base = weight_name.rstrip(".")
                    idx = name.find(weight_name_base)
                    if idx == -1:
                        continue

                    prefix_part = name[:idx]
                    suffix = name[idx + len(weight_name_base):]
                    if suffix.startswith("."):
                        suffix = suffix[1:]
                    elif suffix != "":
                        continue

                    if suffix not in _MOE_SUFFIX_MAP:
                        continue

                    moe_name = prefix_part + param_name + _MOE_SUFFIX_MAP[suffix]
                    wl_name = weight_name_base + ("." + suffix if suffix else "")
```
