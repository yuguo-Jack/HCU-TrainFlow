# [Bugfix][Scheduler] Drop the drafter shift from the unchunked mm rollback

[Upstream PR](https://github.com/vllm-project/vllm/pull/62782) · state: open · merged: False

## Original PR description

## Overview

With `disable_chunked_mm_input` and a drafter look-ahead `L = num_prefill_lookahead` (1 for EAGLE-family drafters, `num_speculative_tokens` for multi-module MTP), `_try_schedule_encoder_inputs` rolls a chunk that would only partially cover a multimodal item back to `start_pos - L`. #60553 removed the same shift from the full-encoder-cache branch, because both runners now fall back to token embeddings when the drafter reads ahead into an unscheduled input. Its description notes that this rollback "still applies the shift". The shift makes the rollback stall requests or split the items it is meant to keep whole:

- **Stall:** when the token budget fits the item but not the item plus `L`, the first chunk stops at `start_pos - L`. Every later chunk then needs `item + L` tokens, so the request gets 0 tokens on every step, with no error.
- **Split:** when the next item starts fewer than `L` tokens after the previous one ends, the rollback to `start_pos - L` lands inside the previous item.

This rolls back to `start_pos`, capped by the current chunk, matching what #60553 does in the twin branch.

## Claims

- With `disable_chunked_mm_input` and speculative decoding, a prompt whose image fits the token budget no longer hangs.
- Rollback never ends a chunk inside an earlier item.
- No change without a drafter look-ahead (`L = 0`).

## Validation

Real server on `34ac4f96a3`: `Qwen/Qwen3.5-0.8B`, MTP (`num_speculative_tokens=1`, so `L = 1`), `--disable-chunked-mm-input --max-num-batched-tokens 1024 --mm-processor-kwargs '{"max_pixels": 1048576}' --no-enable-prefix-caching --enforce-eager`, RTX 4090. The request is one 1024x1024 image (1024 placeholder tokens, 1047 prompt tokens) plus "What color is this image? One word.", sent to `/v1/chat/completions`.

| Build | Result |
|---|---|
| `main` | no response after 95 s; the request never finishes |
| this PR | HTTP 200 in 1.2 s, "red" |

Output check on this PR with the same server flags and a 1024x1024 image of a red circle and a blue rectangle ("Describe the shapes and colors in this image.", `max_tokens=48`, temperature 0): the MTP run and a run without speculative decoding return identical text. MTP accepted 23 draft tokens.

Tests:

- New `tests/v1/core/test_scheduler.py::test_drafter_lookahead_unchunked_mm_input_progress`, parametrized over `L` in {1, 3} and both cases: the budget equals the image length, and two images with no gap. All 4 cases fail on `main` (a step with 0 tokens, or a chunk ending inside an image) and pass with this PR.
- `pytest tests/v1/core/test_scheduler.py tests/v1/core/test_encoder_cache_manager.py`: 254 passed, 2 failed. - `pre-commit run --files <changed files>`: all hooks pass.

## Details

The shift was added in #34220 to avoid an encoder cache miss when the drafter read one token ahead into an unscheduled item. #60553 added a token-embedding fallback for that read-ahead in both runners (the `start_pos >= computed + scheduled` check) and dropped the shift from the full-cache branch, but kept it here. The `min` keeps the chunk within the budget when an item is reached only through the look-ahead window, as in `test_drafter_lookahead_encoder_cache_cap_respects_token_budget`.

On CUDA, `disable_chunked_mm_input` is forced on for mm-prefix-LM models (Gemma 3, PaliGemma, Molmo2, Bagel, Moondream3, DeepSeek-V4 vision), so those models with EAGLE or MTP are exposed by default. For the stall, the budget only has to fall in `[item, item + L)`. That range includes `max_num_batched_tokens == item`, the smallest budget the encoder cache manager accepts.

Not a duplicate: I found no issue or PR for this (searched "disable_chunked_mm_input lookahead/eagle/MTP/hang", "shift_computed_tokens", "num_prefill_lookahead multimodal"). #60553 fixed the twin branch only. #62030 (for #62031) rejects prefill caps smaller than an item and does not touch the shift.
