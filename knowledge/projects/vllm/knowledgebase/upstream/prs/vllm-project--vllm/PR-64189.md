# [CI][Bugfix] Pin the ColUltraVBERT test checkpoint to the revision vLLM supports

[Upstream PR](https://github.com/vllm-project/vllm/pull/64189) · state: closed · merged: True

## Original PR description

- `registry.py`, `test_colultravbert.py`: pin `athrael-soju/ColUltraVBERT` to revision `509adbab61b7`, the last one that declares `ColUltraVBertForRetrieval`

The checkpoint's owner pushed commit `486d2f2f1c` ("Document native transformers 5.21 support") on 2026-10-27, which changed `config.json` `architectures` from `ColUltraVBertForRetrieval` to `UltraVBertModel`. vLLM does not register that name, so `test_can_initialize_large_subset[ColUltraVBertForRetrieval]` fails with "Model architectures ['UltraVBertModel'] are not supported for now", and the pooling test falls back to the Transformers backend and fails on a `config_class` mismatch. It is red on main (e.g. https://buildkite.com/vllm/ci/builds/97805) and on every PR that runs Basic Models (Extra Initialization) or Multimodal Models (Extended Pooling), on both NVIDIA and AMD. With the pin, `ModelConfig` resolves `ColUltraVBertForRetrieval` again; supporting the new architecture name for users is a separate change.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
