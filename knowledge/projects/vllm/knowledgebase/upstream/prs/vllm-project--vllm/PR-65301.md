# [Bugfix][Rust Frontend] Fail incomplete and errored streams in vllm-bench

[Upstream PR](https://github.com/vllm-project/vllm/pull/65301) · state: open · merged: False

## Original PR description

The `openai` and `openai-chat` backends in the Rust `vllm-bench` count an HTTP 200 stream as successful no matter how it ends:

- `[DONE]` is skipped, so a stream that closes early, even after the usage chunk, still succeeds.
- In-stream error objects (`{"error": {...}}` or a flat `{"object": "error", ...}`) are not detected.

Both backends now count a stream as successful only if it produced a token (#59736), ended with `[DONE]`, and carried no error object. This is the rule #64703 proposes for the Python client, and the Rust `openai-responses` backend already applies the same idea with its terminal event. The rule lives in `finish_stream` and `stream_error` in `backends/mod.rs`, shared by both backends.

## Tests

- Four new tests in `backends/mod.rs` run both backends against a raw-socket SSE server: a complete stream succeeds; a stream without `[DONE]` fails, with and without a usage chunk; nested and flat error objects fail; `[DONE]` with no token fails. On main, the `[DONE]` and error tests fail.
- `cargo test -p vllm-bench`: 240 passed after merging main (including #59736's tests). `cargo fmt --check` and `cargo clippy -p vllm-bench --all-targets -- -D warnings` are clean.
- GPU (RTX 3080, Qwen2.5-1.5B, `vllm-bench --dataset-name random --num-prompts 50`): 50 of 50 successful on both `openai` and `openai-chat`, so vLLM's own streams pass the new rule.

## Duplicate check

No open PR or issue covers `[DONE]` or error handling in the Rust bench client. #64703 (Python, completions/chat) and #57519 (Python, error events) touch only the Python client.
