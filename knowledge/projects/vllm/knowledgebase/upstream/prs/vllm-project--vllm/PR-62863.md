# [ROCm] Only run AITER import-time setup on ROCm

[Upstream PR](https://github.com/vllm-project/vllm/pull/62863) · state: open · merged: False

## Original PR description

## Purpose

`vllm/_aiter_ops.py` ends with two module-level calls:

```python
rocm_aiter_ops.register_ops_once()
_sync_aiter_situv2_moe_env()
```

Shared code imports this module on every platform, e.g. `vllm serve` → `entrypoints/cli/preload.py` → … → `model_executor/layers/linear.py` → `model_executor/layers/utils.py:13`, and the GPU worker via `v1/worker/utils.py:17`. So on CUDA both calls run at import:

- `register_ops_once()` evaluates `is_aiter_found_and_supported() or is_aiter_found_and_supported_on_rdna4()` before its `is_rocm()` early return;
- `_sync_aiter_situv2_moe_env()` sets or clears `AITER_SITUV2_*` environment variables.

Neither does anything useful off ROCm. Running them also means CI's function-level test selection sees every CUDA job executing AITER code, so ROCm-only edits to `register_ops_once` (e.g. #52970) select CUDA jobs such as the NIXL PD tests.

This guards both calls with `current_platform.is_rocm()`. `current_platform` is already imported at the top of the module. `register_ops_once()` has no other caller, and `refresh_env_variables()` still syncs the env on ROCm, so behavior on ROCm is unchanged.

## Test Plan

- `ruff format --check`, file parses.
- CI: ROCm AITER tests (`tests/kernels/moe/test_rocm_aiter_moe.py` is ROCm-only), plus CUDA jobs that import `_aiter_ops`.
