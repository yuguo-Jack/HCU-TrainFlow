# [Rust Frontend] End prefilled Kimi K3 reasoning at the response opener like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/63062) · state: closed · merged: True

## Original PR description

## Overview

In thinking mode the Kimi K3 chat template prefills `<|open|>think<|sep|>`, and the model may skip thinking and open the `response` channel directly. Python then treats the `response` open as the end of the implicit reasoning (vllm-project/vllm#57098, vllm-project/vllm#58372). The Rust Kimi K3 parser keeps the whole output, markers included, as reasoning. This PR ends prefilled reasoning at the `response` open, as Python does.

## Claims

- After a `think` prefill, `<|open|>response<|sep|>answer<|close|>response<|sep|>...` now returns `answer` as `content`, keeps any tool call in the following `tools` channel, and reports no reasoning tokens. Before, everything came back as `reasoning_content`, `content` was empty, and the tool call was lost.
- A `response` open after a generated `<|open|>think<|sep|>` still stays reasoning, matching Python's condition.
- Under an output grammar, the prefilled `think` body now excludes `<|open|>response<|sep|>`, as it already excluded the `think` close, so the grammar and the parser agree on where reasoning ends.

- `kimi_k3_response_open_stays_in_explicitly_opened_reasoning`: after a prefill, a generated `think` open keeps a later `response` open inside reasoning.
- The prefilled-`think` grammar snapshots and the `vllm-chat` `roundtrip_kimi_k3` grammar replay fixtures (`grammar_replay/Kimi-K3.{txt,json}`) show the new exclusion; the XGrammar replay of the recorded Kimi K3 outputs still accepts them.

## Details

A `think` prefill now starts the parser in a new `KimiK3Mode::PrefilledReasoning` (`rust/src/parser/src/unified/kimi_k3.rs`). It ends at a structural `<|open|>response<|sep|>`, matched by special-token identity through the existing `Marker`, and continues into the `response` channel as usual. A generated `<|open|>think<|sep|>` moves it to `KimiK3Mode::Reasoning`, where a `response` open is reasoning text. Streaming, non-streaming and reasoning token usage all consume this state machine, so nothing changes in `vllm-chat` or `vllm-server`. The output grammar (`kimi_k3/grammar.rs`) is built from the same initial mode, so it gets the matching boundary. Under a grammar, the `think` close stays the only way out of a prefilled `think`; letting constrained generation skip `think` is a separate change.

Divergence from Python: Python's non-streaming `extract_reasoning` decides with lookahead over the whole output, and its streaming `extract_reasoning_streaming` does not end at a `response` open at all. The Rust parser streams, so it follows the condition of `count_reasoning_tokens`: text before the `response` open stays reasoning. When the `response` open is the first thing the model emits, the usual case, this matches every Python path except streaming.

Not a duplicate: supersedes the inactive vllm-project/vllm#53274 and vllm-project/vllm#53249, which also end reasoning at a `tools` open and a `response` close, which Python does not do. This PR mirrors only the landed Python condition.
