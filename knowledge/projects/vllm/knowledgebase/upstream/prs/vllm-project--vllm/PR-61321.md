# [BugFix][Spec Decode] Log EAGLE draft RoPE and warn when config omits rope keys

[Upstream PR](https://github.com/vllm-project/vllm/pull/61321) · state: open · merged: False

## Original PR description

## Overview

Log the resolved EAGLE/EAGLE-3 draft RoPE at startup and warn when the draft `config.json` omits rope keys and the default base disagrees with the target. Fixes #61231. Numerics are unchanged.

## Claims

- Operators can see the draft RoPE base and `rope_type` in startup logs for `method=eagle` / `eagle3`.
- When the draft checkpoint's raw `config.json` omits `rope_theta` / `rope_scaling` / `rope_parameters` and the resolved default base differs from the target's, vLLM emits an explicit warning naming both values.
- Drafts that declare rope keys (including an explicit `rope_theta: 10000`) do not get the omission warning.
- Documentation states that EAGLE draft RoPE comes from the draft config only.

## Validation

```bash
.venv/bin/python -m pytest tests/config/test_speculative_draft_rope.py \
  tests/config/test_speculative_draft_max_position_embeddings.py -v
# 16 passed
```

Reproduced the silent default on current `main` with `yuhuili/EAGLE3-LLaMA3.1-Instruct-8B` (no rope keys → base 10000) against `unsloth/Meta-Llama-3.1-8B-Instruct` (base 500000, `llama3` scaling) via the same `get_rope` path the issue describes. After this change, constructing `SpeculativeConfig` for that pair logs the draft RoPE and warns on omission.

No model-output / acceptance-rate change: this PR only adds logging, a warning, and docs.

## Details

**Root cause:** EAGLE draft layers build rotary embeddings from `draft_model_config.hf_config` alone. Missing rope keys are filled by transformers / `get_rope` as base 10000 with no log, so operators cannot tell which base the drafter is using.

**Why not inherit the target's `rope_theta`:** As noted in #61231, some heads are trained at 10000 against a 500000 target; silently moving them would be a regression. This PR follows the issue's requested shape: (1) log, (2) warn on omission when bases differ, (3) document. It does **not** warn when the draft explicitly pins a different base (left for maintainers if desired).

**Implementation:** `_maybe_log_draft_rope` runs next to the existing EAGLE `max_position_embeddings` override. Omission is detected from the raw checkpoint `config.json` via `PreTrainedConfig.get_config_dict` (transformers-filled defaults are ignored). If the raw file cannot be read, the warning is skipped and the info log still runs.

**Not duplicating:** No open PR references #61231. Related but distinct: #58094 (MTP `hf_overrides` rope propagation), #59789 (YaRN draft cache size).

AI assistance was used to draft the change, tests, docs, and this PR description. The human submitter reviewed every changed line and ran the tests above.
