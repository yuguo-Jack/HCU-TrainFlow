# [ROCm][Perf] Add direct FP8 kv_b_proj output for FlyDSL MLA prefill

[Upstream PR](https://github.com/vllm-project/vllm/pull/64288) · state: open · merged: False

## Original PR description

## Overview

Add direct FP8 K/V up-projection to AITER FlyDSL cached-context attention for ROCm MLA. Eligible cached chunks avoid the expanded BF16 K/V buffer and the separate BF16-to-FP8 conversion pass.

## Claims

- Compressed FP8 cache and native per-channel FP8 `kv_b_proj` weights feed AITER's projection kernel, with FP32 accumulation and direct FP8 K/V output for FP8 FMHA.
- Disabled by default. Requires `VLLM_ROCM_USE_AITER_FLYDSL_FP8_PREFILL_ATTN=1` and explicit `kv_b_proj: fp8_per_channel` weight configuration; the attention flag does not quantize model weights.

## Details

Use `ROCM_AITER_MLA` with `--attention-config '{"mla_prefill_backend":"ROCM_AITER_FA"}'`, BF16 activations, E4M3 KV cache and `--quantization-config '{"targets":{"*.self_attn.kv_b_proj":"fp8_per_channel"}}'`. Requires gfx950, DCP >1, MLA dimensions latent/NoPE/RoPE/value = 512/128/64/128 and compatible AITER/FlyDSL APIs. Unsupported configurations fail during weight initialization; batch invariance is unsupported. [Usage and requirements](https://github.com/ajith-sirra-amd/vllm/blob/e2393d702a3736dffdfbfc7eb25abbabe484a1df/docs/configuration/env_vars.md#rocm-flydsl-fp8-mla-prefill).

Eligible cached chunks have maximum query length >=512 and context length >=8192. Within an eligible forward, smaller cached chunks use FP8 projection inputs with BF16 K/V output and the existing attention backend. Calls outside the supported routing/indexing conditions retain the standard path. Prefills without cached context retain ASM prefill and its metadata allocation; speculative draft attention routing is preserved.

The weight adapter views native per-channel FP8 storage and FP32 descales without re-quantizing or repacking. Q uses dynamic per-tensor E4M3 quantization, with reuse restricted to matching pointer/shape/stride within one layer's forward. Cached K/V output descales are estimated from new-token maxima: `2 * max(new_token_amax / 448, 1e-6)`. FMHA returns BF16 output and natural-log LSE for native merging. The two unrelated metadata-copy fixes are isolated on [a separate branch](https://github.com/ajith-sirra-amd/vllm/tree/fix/mla-metadata-async-copy-20261104) and are absent from this PR's diff; separate sync-fix validation is pending.

**Numerical limits:** same-quantized-input arithmetic tests passed. A separate captured-input BF16 diagnostic measured a historical maximum absolute LSE difference of about **0.935**, above the investigation's **0.20** threshold. This was an additional diagnostic, not a prescribed upstream acceptance rule. Cached outliers can saturate the range estimated from new-token values. GSM8K results do not establish BF16 numerical equivalence. A [constructed-outlier diagnostic](https://github.com/ajith-sirra-amd/InferenceMAX_Rocm_Team/actions/runs/41821548931) confirmed saturation with the current 2x new-token estimate. Measuring cached maxima removed clipping and projection reconstruction error in those cases; it used an extra BF16 projection and is not integrated into serving. Two cached-max cases still exceeded the additional output tolerance (0.003803 absolute error); that case is consistent with AITER's internal FP8 softmax-probability rounding. The diagnostic remains failed, and cache-scale handling remains under review. Rotation/scaling experiments that failed this diagnostic are excluded. [Investigation](https://github.com/ajith-sirra-amd/InferenceMAX_Rocm_Team/blob/checks/native-fp8-binary-scale-20261102/docs/kimi/native-lse-correction-2026-11-02.md).

The native runs installed source revision `492080779` with precompiled vLLM binaries from `a1cfd2c1` inside the pinned containers; the container tag is not the tested vLLM source revision. Full commands, image digests, source manifests and execution proofs are in the linked run artifacts. The harness also quantizes other linear layers and sets `TORCH_BLAS_PREFER_HIPBLASLT=0` and `TORCH_BLAS_PREFER_CUBLASLT=0` for an independently reproduced BF16 BLAS issue. This PR does not override the global BLAS backend. [Runtime evidence](https://github.com/ajith-sirra-amd/InferenceMAX_Rocm_Team/blob/perf/kimi-attnfp8-kv-allgather-20261021/docs/kimi/native-runtime-validation-2026-11-02.md).

    tests/kernels/attention/test_rocm_aiter_mla_prefill_fusions.py -k flydsl_fp8
