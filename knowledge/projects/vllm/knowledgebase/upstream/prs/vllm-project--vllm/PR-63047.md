# [Bugfix][DSv4.1] Budget prefill memory the startup profile misses

[Upstream PR](https://github.com/vllm-project/vllm/pull/63047) · state: closed · merged: True

## Original PR description

## Overview

DeepSeek-V4.1 prefill OOMs at `--max-num-batched-tokens 32768`: three allocations that grow with the token budget are missed by the startup memory profile. This PR removes or budgets each of them. Fixes #60450.

OOM on a B200 DEP4 prefill instance (`max_model_len` 1M, `--gpu-memory-utilization 0.95`, 17 min into an AgentX trace; the same flags at 16384 run for hours):

```
torch.OutOfMemoryError: CUDA out of memory. Tried to allocate 2.00 GiB. GPU 2 has a total capacity of
178.35 GiB of which 2.00 GiB is free.
  deepseek_v41/nvidia/model.py:625 forward -> attention.py:967 _wq_b_proj
```

The startup plan left 5.31 GiB free; only 2.00 GiB was left at the OOM.

## Changes

| Gap (32768 tokens, 1M context) | Why the profile misses it | Fix |
|---|---|---|
| Indexer `expanded_block_table_buffer`: 1 GiB per builder, two builders plus a replay copy | Allocated after KV sizing | Rows = `min(max_num_seqs * next_n, max_num_batched_tokens)`, the decode tokens it serves: 12 MiB |
| Engram layers 1 and 14: `previous_post` (1.25 GiB) held through attention and MoE, plus a 1.75 GiB spike in the call | Skipped in the profile run unless the table is DP-sharded | Profile runs look up dead rows (NVIDIA and AMD models); `del previous_post` after the call |
| Indexer prefill logits: SM100's BF16 output plus its FP32 copy, with the previous chunk's still alive: 2.5x the 512 MiB budget | Reserved at 1x | `del logits` per chunk; the prefill term of the #62860 reservation counts the copy (1.5x) |

No kernel, chunking or scheduling change.

## Validation

- `pre-commit`: pass.
- Unit tests: new `test_indexer_expanded_block_table_sized_by_decode_tokens` (fails on main); `test_engram_dp_shard` updated for dead-row lookups. GPU run pending.
- E2E pending: the same config at 32768 / 0.95, startup KV size and profiled peak, main vs PR.

## Notes

- Decode rows never exceed `max_num_seqs * next_n`: the indexer treats wider requests as prefills, and `build()` asserts the bound with host ints (no sync).
- The dead-row branch runs only without attention metadata (with MRV2, only the profile run), where outputs are discarded.
- Not addressed: the 4.11 GiB reserved-but-unallocated at the OOM (allocator fragmentation).
