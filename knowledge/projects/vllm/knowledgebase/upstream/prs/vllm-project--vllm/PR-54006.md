**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Implement the advertised XPU rotation path**

When an MXFP4 checkpoint containing `rotation_config` is loaded on XPU, `current_platform.is_cuda()` is false, so model construction always raises here before reaching the existing XPU MXFP4 kernel. Consequently, the XPU Hadamard-rotation support advertised by this change is unusable; this path needs an XPU-compatible transform rather than rejecting every XPU configuration.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Handle rotations that cross tensor-parallel shards**

For row-parallel layers under tensor parallelism, `x.shape[-1]` is the local input shard rather than the checkpoint's full input width. A valid global rotation—such as the accepted 32768-wide block on a 32768-wide layer with TP=2—therefore encounters a 16384-wide local tensor and raises here, even though the unsharded checkpoint is valid. Either rotations spanning shards must be performed before partitioning/with communication, or this unsupported TP configuration should be rejected before inference.

- jl9876 · comment · 2026-09-08T03:37:55Z · [source](https://github.com/vllm-project/vllm/pull/54006#discussion_r3954090592)

File: `vllm/model_executor/layers/quantization/inc/inc.py` · line None

AutoRound currently supports three rotation backends: `auto`, `inplace`, and `transform`. This PR implements vLLM inference support for checkpoints produced by the `transform` backend. The validation is intended to prevent an `inplace` checkpoint from being loaded through the `transform` inference path, which would apply incompatible rotation semantics and could produce incorrect results.

After checking AutoRound’s backend resolution, I found that requiring the literal value `backend="transform"` is too strict. For MXFP4, `backend="auto"` resolves to `transform`, and older or shorthand configurations may omit the field. I will update the validation to accept `auto`, a missing backend, and `transform`, while continuing to reject `inplace`.
