# [ROCm][Perf][GLM-5.3-Flash] Enable fused shared-expert MoE for TP2 on MI355X

[Upstream PR](https://github.com/vllm-project/vllm/pull/63697) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Allow the GLM-5.3-Flash fused shared-expert path (`VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1`) at TP2 on gfx950. AITER now has tuned fused-MoE configs for the TP2 fused shape: block FP8 in ROCm/aiter#6077 (in AITER v0.1.26) and MXFP4 in ROCm/aiter#6435. Follows #59221. Carried in our GLM-5.3-Flash MI355X builds since 2026-10-14 as amd-sriram/vllm#41.

## Claims

- At TP2 on gfx950, the flag now runs the shared expert inside the AITER fused MoE (289 experts, top-k 9). Before, the gate ignored it with a warning and ran the shared expert as a separate MLP.
- Unchanged: the flag default (off), TP1/TP16, other GPUs, and data, prefill-context or expert parallelism.
- GLM-5.3-Flash MXFP4, 2x MI355X, TP2: +3.6% geomean throughput over a 15-point sweep (8k, 60k and 128k inputs); +5 to +8% at 8k/1k, concurrency 8 to 128. GPQA and NIAH unchanged.

**Serving A/B, 2x MI355X, TP2, `amd/GLM-5.3-Flash-Quark-MXFP4`.**
- Two images built from the same recipe (same vLLM base and AITER commit, which includes ROCm/aiter#6435); the only difference is this change. Flag on in both arms; without this change it is ignored at TP2.
- One server launch per arm, one run per point. Earlier repeat runs on this setup varied by about ±1%.
- Logs: the baseline logs the "flag ignored" warning and runs only the 288-expert / top-k 8 MoE; with this change, no warning and only the 289-expert / top-k 9 MoE. Both shapes use tuned FlyDSL MXFP4 kernels from ROCm/aiter#6435.

**Not measured:** the block-FP8 checkpoint at TP2. **Not in CI:** the serving check needs 2x gfx950.

## Details

- **Why the gate refused TP2.** #59221 allowed fusion only where AITER had tuned configs for the fused shape (TP4/TP8 on gfx950); without them the fused MoE runs default kernels. The per-rank intermediate size at TP2 is 1024. ROCm/aiter#6077 (block FP8, in v0.1.26) and ROCm/aiter#6435 (MXFP4) add rows at that size.
- **Correctness at TP2.** Without EP, the shared expert is split by TP like the routed experts, and the extra top-k column is the same on every rank. Nothing on the fused path depends on TP size.
- **Base stack.** The A/B ran on a nightly from 2026-10-14 with other GLM-5.3-Flash ROCm PRs applied (#50535, #59478, #58064, #61662), the same in both arms. TODO: repeat the A/B on a plain nightly once vLLM's AITER pin includes ROCm/aiter#6435.
- **Scope.** Only the gate in `vllm/models/glm5next/common/model.py` and its test.

**Related work:** #63603 makes the same gate change; #60604 changes the same TP check for gfx942.
