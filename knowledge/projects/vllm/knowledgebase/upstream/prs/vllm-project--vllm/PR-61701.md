# [Spec Decode] Remove Medusa and MLP speculator support

[Upstream PR](https://github.com/vllm-project/vllm/pull/61701) · state: closed · merged: True

## Original PR description



## Overview

Removes Medusa and MLP speculator support and simplifies the code paths, configs, tests, docs, and CI rules that existed only for them. Net −858 lines, no new code.

## Claims

- `method="medusa"` and `method="mlp_speculator"` are removed. They are now rejected by `SpeculativeConfig` validation, which lists the valid methods.
- The MLP speculator was already dead code: its registry entry was commented out ("temporarily disabled") until V1 support, which never landed. Medusa is not supported by Model Runner V2, and EAGLE/MTP/DFlash/DSpark cover its use case.
- Other spec-decode methods are unchanged.

## Validation

- `pre-commit` (ruff, mypy, Buildkite/autolabel rule checks) passes.
- `pytest tests/models/test_registry.py tests/config/test_model_arch_config.py tests/config/test_speculative_draft_hf_overrides.py tests/v1/worker/test_gpu_warmup_blocks.py`: **504 passed, 11 skipped, 2 failed**. The 2 failures (`test_registry_imports[Dots3Note*]`) are unrelated: my local DeepGEMM build is older than the tag bump in #61491 (`cannot import name 'get_block_m_for_nvfp4_mega_moe'`).
- E2E smoke on the V1 model runner (`VLLM_USE_V2_MODEL_RUNNER=0`, Llama-3.1-8B-Instruct, GB200, 16 prompts, greedy, 128 tokens). Results are identical before and after:

| Method | drafts | accepted | mean accept len |
| --- | --- | --- | --- |
| ngram (k=3) | 151 | 192 | 2.27 |
| eagle3 (k=3, yuhuili/EAGLE3-LLaMA3.1-Instruct-8B) | 1480 | 568 | 1.38 |

No model eval is needed: no surviving method's output changes.

## Details

Removed:
- `vllm/model_executor/models/{medusa,mlp_speculator}.py`, `vllm/transformers_utils/configs/{medusa,mlp_speculator}.py`, `vllm/v1/spec_decode/medusa.py`, and their registry and config-map entries.
- In `SpeculativeConfig`:
  - the `medusa`/`mlp_speculator` method literals and their auto-detection;
  - the old-format Medusa checkpoint workarounds (`model_type` hf_override injection and vocab-size patching);
  - the `mlp_speculator` draft-TP=1 override, including the now-unused `draft_hf_config` parameter of `_verify_and_get_draft_tp`;
  - the `hf_config.num_lookahead_tokens` sync (only Medusa/MLP speculator configs defined that attribute).
- The `MedusaProposer` branches in the V1 `gpu_model_runner.py`.
- The `T`/`T_co` generic on `VllmModel`/`VllmModelForTextGeneration`/`VllmModelForPooling`. It existed only for Medusa's `list[torch.Tensor]` hidden states; the default was already `torch.Tensor`, so typing for every other model is unchanged.
- `MedusaModelArchConfigConvertor`, plus the `check_head_size` escape hatch in `tests/config/test_model_arch_config.py`, which only existed for Medusa's zero head size.
- The Medusa e2e acceptance test, MLP docs page, MRV2-unsupported-method entries, Buildkite source deps, mergify/autolabel rules, and docs table rows.

Breaking change: users still passing `method="medusa"` or a Medusa/MLP-speculator draft checkpoint will get a config validation error.

Duplicate check: no open PR removes these. Draft #61357 migrates Medusa to the flat model layout; this PR would make it unnecessary.
