# feat: Add DeepGEMM JIT monitoring and warmup for 5 uncovered entry points

## Original PR description

## Summary

This PR addresses issue #64824 by adding DeepGEMM JIT monitoring and warmup for 5 previously uncovered kernel entry points.

### Changes

**1. JIT Monitoring (`vllm/utils/jit_monitor.py`)**
- Added `_setup_deep_gemm_jit_monitor()` - sets up a background thread that watches `DG_JIT_CACHE_DIR` for new `.so` file compilations
- Added `_deep_gemm_monitor_loop()` - the monitoring loop that detects new kernel compilations
- Integrated into `activate()` to start monitoring alongside Triton/CuTeDSL/TileLang monitors

**2. Kernel Warmup (`vllm/model_executor/warmup/deep_gemm_warmup.py`)**
Added 4 new warmup functions covering 5 entry points:

| Entry Point | Use Case | Warmup Function |
|-------------|----------|-----------------|
| `fp8_einsum` | DSv4 o_proj, MXFP8 | `deepgemm_fp8_einsum_warmup` |
| `fp8_fp4_mqa_logits` / `fp8_fp4_paged_mqa_logits` | Sparse attention indexers | `deepgemm_fp8_fp4_mqa_logits_warmup` |
| `fp8_m_grouped_gemm_nt_masked` | BatchedDeepGemmExperts | `deepgemm_batched_masked_gemm_warmup` |
| `m_grouped_fp8_fp4_gemm_nt_contiguous` | FP4 experts | `deepgemm_fp4_experts_warmup` |

- Updated `_count_warmup_iterations()` to include iterations for all new warmup functions
- Updated `deep_gemm_warmup()` to call all 7 warmup functions with progress bar

### Cache Tracking
Added new cache sets to avoid duplicate warmup:
- `FP8_EINSUM_WARMUP_CACHE`
- `FP8_FP4_MQA_LOGITS_WARMUP_CACHE`
- `BATCHED_DEEP_GEMM_WARMUP_CACHE`
- `FP4_EXPERTS_WARMUP_CACHE`

### Testing
- Code compiles and passes type checks
- All existing warmup functions continue to work
- New warmup functions handle missing kernels gracefully with try/except
