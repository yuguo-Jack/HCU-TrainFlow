## Overview

Let FlashInfer GDN prefill read and write SSM states in the cache pool in place (Qwen3.5/3.8, Qwen3-Next linear attention), removing 4-5 gather/mask/cast/scatter kernels per layer when all prefill rows are fresh or all have cached context. Mixed batches keep the gather path. Includes fixes for two engine-killing crashes found in validation/review: bf16-pool checkpointing and strided state indices with MTP configured. Related: #64419 (FlashInfer prefill output in place).

## Claims

- **Removes the per-layer state gather/mask/cast/scatter kernels entirely** on none/all batches — measured −249 µs of `index_elementwise` plus −118 µs of fill/cast kernels per chunked prefill (18 GDN layers, profile diff below).
- **Forward time −2.7% (8k prefill), −7.6% (chunked prefill), −4.9% (mixed batch)** vs current main; decode unchanged.
- **Side effect: FlashInfer's checkpoint-emitting kernel loses most of its premium** — with `initial_state=None` it runs 358 → 275 µs/layer at 8k (align-mode checkpointed prefill, 48 GDN layers: 17.3 → 13.2 ms per prefill).
- **Fixes an engine-killing crash on Qwen3-Next** (bf16 `mamba_ssm_dtype`): the first checkpointed multi-row batch hits a FlashInfer compile error (`autovec_copy ... BFloat16 and Float32`); checkpointed prefills over a non-fp32 pool now gather into fp32 as before.
- **Fixes the first pool-route prefill crashing with MTP configured**: FlashInfer rejects strided state indices; both metadata-builder paths now materialize contiguous indices.
- **GSM8K unchanged** (A/B below); route-level parity pinned harder: pool ≡ gather (1e-3) and pool ≡ CuteDSL backend as an independent whole-layer reference.
- 5 files, +489/−16 (mostly tests). No new kernels, no new host syncs.

## Details

- **Host-side mode**: computed from `seq_lens_cpu_upper_bound`, exact for prefill rows, so it agrees with the device-side `prefill_has_initial_state` mask; the `_prefill_initial_state_mode` docstring states the invariant and the builder test pins it, spec rows included. Any shape ambiguity falls back to "mixed" = today's gather path, and "mixed" is the default for builders that don't compute it.
- **In-place states**: mode "none" → `initial_state=None` (zero start), final states written to pool rows via `output_state`/`state_indices`; mode "all" → the pool is also the initial-state source. Per prefill row this avoids moving `num_v_heads × head_v_dim × head_k_dim` fp32 twice per layer, and pool states stay in the cache dtype (never cast as a whole pool).
- **bf16-pool fallback (crash fix)**: FlashInfer 0.7.2's regular (non-CP) checkpointing kernel does not compile when it reads/writes a bf16 pool in place while storing fp32 checkpoints; the CP kernel is unaffected but serving batches take the regular one. Checkpointed prefills over a non-fp32 pool force "mixed" (gather into fp32, as before) and warmup skips the uncompilable variants, so graph capture can't hit them either. Found on Qwen3-Next, where the first checkpointed multi-row batch killed the engine.
- **MTP-configured prefill (crash fix)**: mamba block-table rows have `1 + num_spec` state slots. A prefill-only batch takes the non-spec branch, yielding a strided column-0 view as `prefill_state_indices`. FlashInfer's regular route raises `ValueError: Mismatched s_indices.strides[0] ... expected to be 1`; CP raises `RuntimeError: state_indices must be contiguous`. Both `build()` and `update_block_table()` now use `torch.Tensor.contiguous()` (a no-op without spec decode), preventing the first pool-route prefill from killing the engine.

Dispatch cases (all tested):

| case | route |
|---|---|
| fresh rows | pool, `initial_state=None` |
| all-cached rows | pool as initial and final state |
| mixed fresh/cached rows | gather + mask + scatter |
| non-spec decodes + prefills | peeled decodes to `[:num_decodes]`, prefill in place |
| align-mode checkpoints, fp32 pool | checkpointing call with pool route |
| align-mode checkpoints, bf16 pool | gather |
| spec decodes + prefills | pool route, FlashInfer-allocated output, `index_copy_` merge |
| prefill-only, MTP configured | pool route with contiguous state indices |

- Limitations: mixed batches see no state-traffic win. Measured on GB300/B300 (SM103); SM90/SM120 not run (FlashInfer documents the APIs there). TP2 smoke passed (server up, 8k/64 c8 32/32 OK, GSM8K 0.8567); one known pre-existing warmup-coverage gap (`_fused_post_conv_kernel` JIT warning at TP2 only — applies to base too).
- Overlap audit (2026-10-29): #50372 (open) fuses the FlashInfer prefill state I/O with Triton gather/scatter kernels — this PR removes that I/O for none/all batches instead; its fused kernels would still apply to mixed batches and bf16 checkpointed prefills, so the two compose. #41824 (open) is the Triton-backend counterpart (in-place SSM state for the Triton chunk kernel). #60659 (checkpoints for Triton/FLA + FlyDSL) and #55876 (grouped prefill) touch the same files, textual overlap only. #64303 changes which slots prefills read/write; `state_indices` passes that through unchanged. #64419 (merged) is the output-buffer counterpart (FlashInfer prefill output in place).
