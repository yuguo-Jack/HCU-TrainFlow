# [Rust Frontend] Return 501 for /generative_scoring and the opt-in Cohere v2 chat routes

[Upstream PR](https://github.com/vllm-project/vllm/pull/65376) · state: closed · merged: True

## Original PR description

## Overview

Return 501 instead of a bare 404 from the Rust frontend for two Python routes it does not implement: `POST /generative_scoring`, and the opt-in Cohere v2 routes `POST /cohere/v2/chat` and `POST /cohere/v2/chat/render`, under the same gates as Python. A preparatory commit replaces the router builder's positional boolean gates with a small struct.

## Claims

- `POST /generative_scoring` returns 501 with the shared "not supported by the Rust frontend yet" error instead of 404. Python registers the route for every generate model with no flag, so the placeholder has no gate either.
- With `VLLM_ENABLE_COHERE_API=1`, `POST /cohere/v2/chat` returns 501; `POST /cohere/v2/chat/render` returns 501 only when `--enable-scale-out` is also set. Without the opt-in both stay 404, as in Python.
- The `RouteGates` refactor does not change behavior.

Tests in `rust/src/server/src/routes/tests.rs`:

- `unimplemented_python_routes_return_not_implemented` now includes `/generative_scoring`; it fails without the route (404 instead of 501).
- `cohere_routes_follow_the_python_gates` covers all three gate combinations; it fails with the env gate removed (501 instead of 404 when disabled) and with the scale-out gate removed.

## Details

One commit per change:

1. **`POST /generative_scoring`.** Python registers it in `register_generate_api_routers` (`vllm/entrypoints/generate/api_router.py`, router in `vllm/entrypoints/generate/generative_scoring/api_router.py`). The Rust router had no route, so a client got a 404 that reads like a wrong URL rather than a missing feature. It now uses the shared `not_supported` handler, next to the other unimplemented Python routes (`/v1/messages`, `/v1/decisions`, ...).
2. **Route gates as one struct (no behavior change).** `build_router_with_options` took three positional booleans (dev mode, runtime LoRA updating, scale-out), and test-only wrappers forwarded fixed values to it. The gates are now a private `RouteGates` struct resolved once in `build_router`; tests build the router with the gates they need (`..RouteGates::default()`).
3. **Cohere v2 chat routes.** Python's `attach_router` (`vllm/entrypoints/cohere/api_router.py`) registers chat under `VLLM_ENABLE_COHERE_API`, and render only when scale-out (or `--tokens-only`) is also on. On the Rust frontend that opt-in did nothing. A new `RouteGates::cohere_api` gate, read next to its neighbors in `build_router`, registers both routes with `not_supported` under the same conditions. `--tokens-only` fails startup on the Rust frontend, so `--enable-scale-out` is the whole scale-out condition.

**Differences from Python.**

- Python also needs the optional `cohere` SDK and otherwise logs a warning and registers nothing. The Rust frontend has no such dependency, and a 501 tells an operator who asked for the API more than a 404 would.
- The 501 uses the shared error shape rather than Python's Cohere error envelope, like the other placeholders.
- The Cohere test passes the gates directly rather than through `VLLM_ENABLE_COHERE_API`, like the sibling dev-mode and runtime-LoRA gates; the crate has no env-isolated test harness.

Not a duplicate: vllm-project/vllm#46427 implements `/generative_scoring` in Rust but has been inactive since 2026-10-07; this placeholder does not block it. No open PR adds the Cohere routes to the Rust frontend (searched open PRs for Rust frontend generative scoring and Cohere).
