# [Bugfix][MRV2] Skip adaptive verification cost profiling in the CUDA graph memory-profiling pass

[Upstream PR](https://github.com/vllm-project/vllm/pull/63431) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

#47808 put adaptive verification's step-cost profiling inside `capture_model()`. #53306 then made the CUDA graph memory estimate run `capture_model()` on a throwaway KV cache, so startup profiled step costs twice. The first set of curves went into a throwaway manager and was discarded. This PR skips the profiling when `profile_only=True`.

## Validation

1× B300, Qwen3-4B + `deepseek-ai/dspark_qwen3_4b_block7`, adaptive verification, warm caches:

| | Memory-profiling capture | Engine init |
|---|---|---|
| main | 18 s | 57.7 s |
| this PR (n=2) | 12 s, 14 s | 54.3 s, 56.4 s |

The CUDA graph estimate (1.85 GiB), KV cache size, and greedy outputs (32 prompts) are unchanged.

`pytest tests/v1/worker/test_gpu_model_runner_v2.py tests/v1/worker/test_gpu_model_runner_v2_cudagraph_profiling.py tests/v1/spec_decode/test_adaptive_verification.py`: 47 passed. The updated `[profile_only=True]` case fails on main.

Not a duplicate: #62539 and #63410 change the same block for other reasons.
