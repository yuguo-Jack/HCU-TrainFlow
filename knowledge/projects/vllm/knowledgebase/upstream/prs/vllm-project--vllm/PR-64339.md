# [Bugfix] GLM-5.3-Flash: keep kpool top-k rows a valid prefix

[Upstream PR](https://github.com/vllm-project/vllm/pull/64339) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Make GLM-5.3-Flash's kpool indexer list each top-k row's valid entries first, with no `-1` gaps. This is a prerequisite for Flash + HiSparse (#61243): HiSparse's top-k conversion keeps entries in place, so the gaps reach `FLASH_ATTN_MLA_SPARSE`, which crashes with an illegal memory access on Hopper.

## Claims

- With #61243, Flash + HiSparse on `FLASH_ATTN_MLA_SPARSE` (H200, CUDA graphs) now serves instead of failing every request with `CUDA error: an illegal memory access`.
- No change without HiSparse: the generic conversion already moves valid entries to the front, and outputs are bit-identical before and after this PR.
- No performance change: the kernel keeps the same grid, loads and stores, plus one `min` per row.

## Details

The kpool indexer's pooled path anchored the incomplete-pool tail at column `index_topk`. When a row has fewer than `index_topk / index_kpool` complete pools, this leaves `-1` gaps between the selected pools and the tail. The exact-causal shortcut for `max_seq_len <= index_topk` avoids these gaps, but it is a host check. FULL CUDA graphs capture with `max_seq_len = max_model_len`, so decode replay always takes the pooled path.

Without HiSparse the gaps are harmless. `triton_convert_req_index_to_global_index` moves valid entries to the front whenever it returns `valid_counts` (#46076). HiSparse's `hisparse_resolve_residency` keeps entries in place and assumes the indexer's rows have no gaps. With HiSparse, instrumented graph replay showed 288 decode rows per layer with `-1` inside `[0, valid_count)`. FA3 uses those entries as its page table, so it reads row `-1`.

The gappy layout dates to #53906. It only reaches an attention kernel through HiSparse, which #61243 enables for Flash.

The fix anchors the tail at `min(pool_len * kpool, topk)` in the NVIDIA and AMD fused kernels and in the pure-torch reference. Short rows now match the exact-causal fill, and full rows are unchanged. `fit_kpool_indices_to_aiter` stays correct with either layout.

Not a duplicate: no open PR changes the kpool tail layout.
