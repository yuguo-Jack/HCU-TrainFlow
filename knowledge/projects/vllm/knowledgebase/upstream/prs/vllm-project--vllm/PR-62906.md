# [Bugfix] Apply default multimodal LoRA per batch conversation

[Upstream PR](https://github.com/vllm-project/vllm/pull/62906) · state: closed · merged: True

## Original PR description



## Overview

Fix default multimodal LoRA selection in `/v1/chat/completions/batch`. Select the adapter independently for each conversation instead of passing the entire batch to the single-conversation selector.

## Claims

- Apply default multimodal LoRAs to the appropriate conversations in a batch.
- Preserve explicit adapter precedence and text-only behavior.

## Validation

```bash
uv run --no-sync .venv/bin/python -m pytest \
  tests/entrypoints/openai/chat_completion/test_batched_chat_completions.py \
  -m skip_global_cleanup -q
# 6 passed, 5 deselected

uv run --no-sync .venv/bin/python -m pytest \
  tests/entrypoints/serve/lora/test_serving_models.py -q
# 11 passed

uv run --no-sync .venv/bin/python -m pre_commit run --files \
  docs/features/lora.md \
  vllm/entrypoints/openai/chat_completion/batch_serving.py \
  tests/entrypoints/multimodal/openai/chat_completion/test_default_mm_loras.py
# All applicable checks passed
```

Real HTTP validation on an H800 used `ibm-granite/granite-speech-3.3-2b` and its bundled LoRA, with BF16, eager mode, and `max_num_seqs=1`.

- Before the fix, batch audio requests produced different output from single requests using the default adapter.
- After the fix, audio-only and mixed text/audio batches matched the single-request audio output token for token.
- Text-only, single-request, and explicit-adapter results remained unchanged.

HTTP validation preceded the rebase; the affected files are unchanged. The checks above were rerun after rebasing.

The existing Phi-4 integration test covers single and batch endpoints with default and explicit adapters. These cases are included in CI but were not run locally.

## Details

The adapter selector expects one conversation, but the batch endpoint passed a nested list of conversations. No modalities were detected, so default adapters were silently omitted.

Resolve the adapter from each existing `single_request` before submitting it to the engine.
