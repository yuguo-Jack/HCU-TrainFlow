# [CI] Shard (L4) Hybrid SSM NixlConnector PD accuracy into per-model jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/58708) · state: closed · merged: False

## Original PR description

## What
Split `Hybrid SSM NixlConnector PD accuracy` into three named jobs, one per model family (Granite, Qwen3.5, Jamba). Each job keeps its own MI300 mirror. The sweep runs the same 7 configs; only how they are divided between jobs changes.

## Old
```
Hybrid SSM NixlConnector PD accuracy     hybrid-ssm-nixlconnector-pd-accuracy-tests-4-gpus   HYBRID_SSM=1   (7 configs, run one after another)
  mirror.amd (MI300)                     same command
```

## New
```
.../ Granite   hybrid-ssm-nixlconnector-pd-accuracy-granite-4-gpus   HYBRID_SSM=granite  granite-4.0-h-tiny: TP1/1, TP2/2, TP2/1
.../ Qwen3.5   hybrid-ssm-nixlconnector-pd-accuracy-qwen3-5-4-gpus   HYBRID_SSM=qwen3_5  Qwen3.5-0.8B: TP1/1, TP1/2, MTP spec decode
.../ Jamba     hybrid-ssm-nixlconnector-pd-accuracy-jamba-4-gpus     HYBRID_SSM=jamba    AI21-Jamba2-3B: TP1/1
each with mirror.amd -> amd-<key>
```
`config_sweep_accuracy_test.sh`: `hybrid_ssm_configs` is now `hybrid_ssm_{granite,qwen3_5,jamba}_configs`. Any other `HYBRID_SSM` value, such as `1`, still runs all 7 configs in the original order.

## Notes
- The legacy `test-amd.yaml` step (`HYBRID_SSM=1`) is untouched and still runs everything, so this needs no `amd-ci` run.
- No pytest filters were involved: this is a split by config (the script's config list is the manifest), in the same way as #57965.
- Each job keeps the old device, `num_devices: 4` and mirror settings. Timeouts come down from 60 to each family's measured time. Jamba only uses 2 GPUs; lowering its `num_devices` is left for a follow-up.
- Evidence: per-config times from `_bk;t=` log timestamps on main builds 90455, 90771 and 91092 (primary lane and mirror).

## Expected runtime and overhead (predictions, primary lane)
| job | sweep time | running wall | non-sweep overhead | main overhead cause |
|---|---|---|---|---|
| Granite | ~16m | ~17m | ~1.2m | checkout + kv-connector install + NIXL import canary |
| Qwen3.5 | 17–19m | 18–20m | ~1.2m | same |
| Jamba | ~6.5m | ~8m | ~1.2m | same |

Baseline is ~40–43 worker-minutes (one job, very stable across 2 weeks of main); after the split it is ~43–45. That is **~+2.5 extra worker-minutes**, from two more copies of the per-job setup, well under the 20-minute cap. The slowest job is Qwen3.5 at 17–19m of sweep time, down from ~40m, which is under the 20-minute target but close to it. Two jobs would not be enough: any pairing of families adds up to 22m or more.
Mirror: every family also fits on one replica. The extra cost there is dominated by image pull on each new agent, typically a few minutes per job; validation will measure it.
