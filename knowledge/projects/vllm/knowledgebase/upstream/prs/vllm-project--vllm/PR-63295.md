# [Bugfix][Rust Frontend] LoraRequest: drop tensorizer_config_dict to match the Python wire layout

[Upstream PR](https://github.com/vllm-project/vllm/pull/63295) · state: closed · merged: True

## Original PR description

## Overview

The Rust frontend's `LoraRequest` still carries `tensorizer_config_dict`, which #60024 removed from the Python `LoRARequest`. This drops the stale field so the positional wire layouts match again.

## Claims

- Fixes LoRA requests sent through the Rust frontend: the engine currently fails to decode them because a `nil` lands in the `load_inplace` slot.
- Adds a `LoRARequest` fixture to the existing Python msgpack compatibility test. Like the other fixtures there, it uses a copy of the Python struct, so it pins the current six-field layout; it does not track later edits to `vllm/lora/request.py` by itself.

## Validation

`python_msgpack_fixtures_match_rust_encoding` (`vllm-engine-core-client`), on aarch64 with Rust 1.95:

| Tree | Result |
| --- | --- |
| `main` + new test only (the two new test literals also set `tensorizer_config_dict: None` so they compile against the old struct) | FAILED: the Python `load_inplace`/`is_3d_lora_weight` values shift into `tensorizer_config_dict`/`load_inplace` (`left: ... tensorizer_config_dict: Some(Boolean(true)), load_inplace: true, is_3d_lora_weight: false`) |
| this PR | ok |

The old Rust layout decoded by the real `vllm.lora.request.LoRARequest` with msgspec 0.22:

```
msgspec.msgpack.decode(encode(["adapter-a", 3, "/adapters/a", "base-model", None, True, True]), type=LoRARequest)
-> ValidationError: Expected `bool`, got `None` - at `$[4]`
```

Also on this PR: `cargo fmt --all -- --check` clean, `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings` clean, `cargo test -p vllm-engine-core-client -p vllm-server -p vllm-llm lora` all pass (22 server LoRA route/gRPC tests included). The fixture's `LoRARequest` mirror encodes byte-identically to the real Python class for both cases.

```
cargo test --manifest-path rust/Cargo.toml -p vllm-engine-core-client --locked --lib python_msgpack_fixtures_match_rust_encoding
```

## Details

Both sides encode `LoRARequest` as a positional msgpack array (`array_like=True` in Python, `Serialize_tuple` in Rust). #60024 removed `tensorizer_config_dict` (index 4) on the Python side only, so the Rust struct had 7 slots against Python's 6 and every field from `load_inplace` on was off by one. The fix removes the field and its two construction sites; no other code read it.

The new fixture covers both directions: Python bytes decode to the expected Rust struct (with `load_inplace` and `is_3d_lora_weight` set so a shift is visible), and the Rust encoding equals the Python encoding.
