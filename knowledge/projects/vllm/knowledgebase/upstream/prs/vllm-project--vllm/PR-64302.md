# [CI] Exclude nvidia-cuda-cccl from the ROCm test lockfile

[Upstream PR](https://github.com/vllm-project/vllm/pull/64302) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fix `pip-compile-rocm`, which has failed pre-commit on `main` and every PR since torch 2.15.0 was released ([first failing `main` run](https://github.com/vllm-project/vllm/actions/runs/40718175417)).

## Claims

- The ROCm test lockfile resolution has no torch constraint: ROCm CI gets torch from its Docker image, and the hook passes `--no-emit-package torch`. uv still picks a torch to resolve torch's transitive dependencies, and takes the newest on PyPI, even though vLLM pins torch 2.14.0 elsewhere.
- torch 2.15.0 (released 2026-10-28 15:16 UTC) changed those dependencies: it pins `nvidia-nvshmem-cu13==3.7.2`, which requires `nvidia-cuda-cccl`, and no longer pulls in `nvidia-curand` (2.14.1 had `nvidia-nvshmem-cu13==3.4.5` and `cuda-toolkit[...,curand,...]`).
- `nvidia-cuda-cccl` is now excluded like the other CUDA packages, and `nvidia-curand` drops out of the lockfile's excluded-packages list. Neither affects what ROCm CI installs.
- This fixes the symptom. A follow-up should constrain torch in the ROCm resolution to the version vLLM uses, so future torch releases stop changing the lockfile.

## Validation

- `rocm.txt` matches the diffs `pip-compile-rocm` produced in CI on `main` and #64049 ([run 1](https://github.com/vllm-project/vllm/actions/runs/40714798665), [run 2](https://github.com/vllm-project/vllm/actions/runs/40716224375)). I couldn't regenerate it locally because my package mirror resolves older CUDA metadata; this PR's pre-commit run is the check.
