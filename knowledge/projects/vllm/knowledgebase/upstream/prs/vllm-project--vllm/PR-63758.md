# [ROCm][Perf][MRV2] Context-length-bounded decode graphs (RFC #63757)

[Upstream PR](https://github.com/vllm-project/vllm/pull/63758) · state: open · merged: False

## Original PR description

## Overview

Reference implementation for RFC #63757, which covers the design, the alternatives and the interaction with #62749; design feedback is best placed there. This PR stays a draft for the RFC's feedback period.

Model Runner V2 captures FULL decode graphs with `max_seq_len = max_model_len`. This PR adds, per context-length bound a module declares, a copy of each FULL decode graph captured with `max_seq_len = bound`, replayed only when every context in the step fits. GLM-5-Next's sparse indexer is the first user: within `index_topk` (2048 on GLM-5.3-Flash) its top-k is every causal token, so a decode step skips the indexer's q side and scoring.

## Claims

- Model Runner V2, `FULL_DECODE_ONLY` or `FULL_AND_PIECEWISE`: each FULL decode graph gets one copy per declared bound; a decode step replays it only when every request's context is within the bound, otherwise the default graph, as before.
- GLM-5-Next (`Glm5NextForCausalLM`, `Glm5NextForConditionalGeneration`), kpool indexer without rope, CUDA and ROCm: a decode step whose contexts all fit `index_topk` skips `wq_b`, the head-weight projection, q quantization, paged-MQA logits and top-k in the FULL decode graphs captured for that bound. Eager steps and PIECEWISE graphs score as before.
- GLM-5.3-Flash MXFP4, MI355X, TP2, one image per request:
  - `FULL_DECODE_ONLY`: output throughput +2.32 % (SE 0.44 pp) over concurrency 16-64, +4.6 % at concurrency 1, +12.3 % at 4. Text rows that cross or never fit 2048 tokens are within noise. GSM8K unchanged within run-to-run variation; sequential greedy outputs identical.
  - Breakable `FULL_AND_PIECEWISE`: +4.50 % (SE 1.92 pp) over concurrency 16-64; greedy outputs identical.
- Cost: one extra FULL decode graph per capture size and bound; on GLM-5.3-Flash TP2, CUDA graph memory 0.79 → 1.07 GiB per rank with `FULL_DECODE_ONLY` (12.55 → 12.82 GiB with breakable `FULL_AND_PIECEWISE`) and KV cache −0.03 %. Opt-out: `--compilation-config '{"cudagraph_specialize_seq_len": false}'`.
- Unchanged: models that declare no bound; PIECEWISE, mixed FULL and micro-batched (DBO) graphs; prefill and mixed steps; PCP/DCP (feature off); Model Runner V1 graphs.

## Changes

- `vllm/v1/worker/gpu/cudagraph_utils.py`: `BatchExecutionDescriptor.max_seq_len`, matched in `_is_compatible` like `max_query_len`; `_add_seq_len_bounded_graphs` adds the copies, captured after the default graphs and tried before them; `get_cudagraph_seq_len_bounds` collects the declared bounds below `max_model_len`.
- `vllm/v1/worker/gpu/model_runner.py`, `dp_utils.py`: the step's bound, from the CPU arrays `prepare_inputs` uses for the metadata's `max_seq_len` (no device read), passed to dispatch per rank (not part of the DP sync).
- `input_batch.py`, `model_states/default.py`, `model_states/mamba_hybrid.py`: a bounded graph's capture metadata has `max_seq_len = bound`.
- `vllm/config/compilation.py`: `cudagraph_specialize_seq_len` (default on, like `cudagraph_specialize_lora`).
- `vllm/models/glm5next/`: `Indexer` declares `index_topk` when the kpool op has its causal-fill path (`index_kpool > 1`, no indexer rope, CUDA-alike); `forward` computes the k side and gate score first, unchanged, then either calls the op with `q_quant=None, weights=None` or runs the q side. `_skips_scoring()` is True only while a FULL graph is being captured for a batch within the bound. Eager steps, including the warm-up run before each capture, score as before, so each warm-up compiles and autotunes everything its capture runs. The kpool ops accept the `None`s and assert q is present before scoring.
- Second commit: the first commit also skipped scoring in eager decode steps within the bound, which made a cold start under breakable `FULL_AND_PIECEWISE` fail. The warm-up before the 1-token PIECEWISE capture took the skip path, so the scoring path's first call at that size came inside the capture. `torch.compile(dynamic=True)` specializes size 1, so `_fused_indexer_weight_scale` was recompiled there, and inductor's autotune synchronized inside the stream capture (`operation not permitted when stream is capturing`). A warm compile cache hid it. The second commit restricts the skip to FULL captures; the third adds its unit test.
- Memory profiling counts the copies but estimates them low: on GLM-5.3-Flash TP2 the KV budget moved by 0.05 GiB while the copies took 0.28 GiB.

**Unit tests** (`tests/v1/cudagraph/test_cudagraph_manager.py`, CPU, run by the CPU `v1` CI step):

- `test_seq_len_bounded_decode_graph_replays_only_within_its_bound`: the copies have the default graphs' shapes; a decode step up to the bound (inclusive) replays the copy, one token past it or without a bound the default graph; mixed steps stay PIECEWISE.
- `test_full_capture_metadata_max_seq_len_is_the_graph_bound`: capture builds the default graph's metadata with `max_model_len` and the copy's with the bound.
- Both fail on the base (`TypeError`, the arguments do not exist) and pass with this PR; the file's other tests match the base. They also fail when the dispatch boundary moves by one, when copies are appended instead of preferred, when an unbounded step matches a copy, and when the bound is dropped at any of the three capture hand-offs.
- `test_indexer_skips_scoring_only_while_capturing_a_full_graph[eager|capture]` (third commit): a decode batch within the bound scores in an eager step and skips scoring in a FULL graph capture. `[eager]` fails at the first commit (`assert True is False`) and passes at the second; it also fails when the capture check is removed, and `[capture]` fails when the skip is disabled.
- `ruff check`, `ruff format --check`, `typos`: clean at every commit. `mypy` on the changed `vllm/` files: no new errors against the base.
