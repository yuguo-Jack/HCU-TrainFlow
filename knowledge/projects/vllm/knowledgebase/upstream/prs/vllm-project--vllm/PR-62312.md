# [Rust Frontend] Add --reasoning-effort-map to rewrite request reasoning efforts

[Upstream PR](https://github.com/vllm-project/vllm/pull/62312) · state: closed · merged: True

## Original PR description



## Overview

Rust frontend version of #61094: adds `--reasoning-effort-map`, which rewrites the reasoning effort a client sends into one the chat template supports.

## Claims

- `--reasoning-effort-map '{"medium": "high"}'` rewrites listed efforts; unlisted efforts pass through.
- Works for `vllm-rs serve`, the render server, and the Python-launched frontend (`--args-json`), so it follows #61094's flag once that merges.
- `reasoning_effort` in `chat_template_kwargs` is not rewritten (same as #61094).
- Unknown keys fail at startup.
- With the flag unset, behavior is unchanged.

## Validation

End to end with the render server on `deepseek-ai/DeepSeek-V4.1-Flash-1017` (V4.1 rejects `medium`):

| Flag | `reasoning_effort: "medium"` |
|---|---|
| none | 400: `DeepSeek V4.1 reasoning_effort must be low, high, xhigh, max, ...` |
| `{"medium":"high"}` | renders the same tokens as `high` |
| `{"mediun":"high"}` | startup error: ``unknown variant `mediun`, expected one of `none`, ...`` |

Tests:

```bash
cd rust
cargo test -p vllm-server -p vllm-cmd     # 468 + 82 passed
cargo test -p vllm-chat --lib             # 358 passed
cargo clippy -p vllm-chat -p vllm-server -p vllm-cmd --all-targets -- -D warnings
```

New tests: the map rewrites the typed effort but not `chat_template_kwargs`, args-json passes the map through, and an unknown key is rejected. `roundtrip_{qwen3,kimi_k25,mimo_v26}` grammar-replay tests fail locally, and they fail the same way on clean `main`.

## Details

The map is applied in `ChatRequestProcessor` before rendering and before the output processor is built, so chat completions, render and tokenize all use it. CLI keys are parsed as `ReasoningEffort`, which is how unknown efforts get rejected. `Config` and `RenderConfig` keep the keys typed and lower them to strings when building the chat processor.

Not a duplicate: no other open PR adds an effort map to the Rust frontend. AI assistance (Claude) was used.
