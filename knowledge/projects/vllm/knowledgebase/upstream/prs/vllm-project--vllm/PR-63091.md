# [Attention] Refresh FlashInfer decode scales after every weight load

[Upstream PR](https://github.com/vllm-project/vllm/pull/63091) · state: closed · merged: False

## Original PR description

> Stacked on #57678 and #63090. Only the last commit (`[Attention] Refresh FlashInfer decode scales after every weight load`) is new here.

## Problem

FlashInfer folds the layer's q/k/v (and fused output) scales into `bmm1_scale`/`bmm2_scale`, latched as host floats on the first forward. A weight reload with different KV scales kept the old values, and FULL decode CUDA graphs had captured them anyway. With a ModelOpt NVFP4 checkpoint with FP8 KV scales, reload B produced different tokens than a cold B start, while all weights were identical.

Kimi K3 MLA also registered new reciprocal q/k scale buffers on every post-load pass, moving their addresses.

## Fix

- `Attention.process_weights_after_loading` calls `impl.refresh_layer_scales`, which recomputes the scales after every load from the (re)loaded q/k/v/output scales.
- The decode kernels read the scales from a device tensor updated in place, so captured graphs see new values.
- Where FlashInfer only accepts host floats (`o_sf_scale` for NVFP4 output, and the DCP decode path), a FULL decode graph keeps the captured value, so a reload that changes them raises instead of decoding with stale scales.
- Kimi K3: refresh `_q_scale_inv`/`_k_scale_inv` in place.

MLA backends are not changed: no MLA path in vLLM loads static k/v scales today, so their scale floats are always 1.0 and cannot change on reload.

## Test

- Same GB200 reload oracle as #63090 (8 models) passes, including ModelOpt NVFP4 with FP8 KV scales (reload B matches cold B). An earlier revision also passed on H200 with the xqa decode backend.
- Guard trigger: with attention+quant fusion, a checkpoint that halves the `o_proj` input scale raises the host-scalar error.
- `tests/model_executor/model_loader/test_reload_host_scales.py`, `test_kv_scale_reload`: pass.
- GB300 (SM103), same oracle: Qwen3-30B-A3B NVFP4 (incl. FULL graphs), BF16 and online MXFP8, Qwen3.5 FP8, GLM-5.3 BF16/online MXFP8/MXFP4, GLM-5.2 FP8 and NVFP4, Qwen3.8 NVFP4 and MXFP4, DeepSeek-V4.1, Kimi K3: all pass. Without #63090, DeepSeek-V4.1 moves 15 side tensors per reload there.
- H200: Qwen3-30B-A3B BF16 and NVFP4 (incl. xqa decode, eager and graphs), Qwen3.5 FP8, GLM-5.3 BF16, GLM-5.2 FP8: all pass.
