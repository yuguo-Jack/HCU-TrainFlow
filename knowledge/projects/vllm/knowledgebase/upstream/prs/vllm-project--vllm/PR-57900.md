# [ROCm][Bugfix] Make the RoPE + KV-cache fusion reachable by explicit request and through its documented opt-ins

[Upstream PR](https://github.com/vllm-project/vllm/pull/57900) · state: open · merged: False

## Original PR description

## Overview

On ROCm with AITER the RoPE + KV-cache fusion cannot be turned on at all — an explicit `fuse_rope_kvcache=True` is silently reset because the KV-cache update op it rewrites is split out of the graph, and `-O2`/`-O3` never resolve it because the resolver requires the `rotary_embedding` custom op that is only appended once the fusion is on; this PR keeps that op in the graph when a fusion asks for it and turns the custom-op requirement into an opt-out.

**Explicit request.** `set_splitting_ops_for_v1` splits out `vllm::unified_kv_cache_update` to protect Inductor graph reuse (#33267), which only breaks while `layer_name` is a string constant. With hoisted layer names (`_USE_LAYERNAME`) keeping the op costs +0.08 s per compile range on a Llama-3.1-8B cold start; without them it costs 12.8x, so the request is still refused there, now with a warning that says why. `fuse_qk_norm_rope_kvcache` and `fuse_rope_kvcache_cat_mla` are handled the same way, and `_set_compile_ranges()` runs after `set_splitting_ops_for_v1()` so a dropped fusion leaves no endpoint behind.

**Default resolution.** `CompilationConfig.__post_init__` appends `+rotary_embedding` when `fuse_rope_kvcache` is set, before the optimization level resolves that flag, and since #36716 nothing else enables the op on ROCm. Both resolvers now read `-rotary_embedding` as an opt-out, `enable_qk_norm_rope_kvcache` delegates to `enable_rope_kvcache_fusion`, and the append re-runs after splitting ops settle, so the op is requested exactly when a fusion survives.

Both resolvers still return False unless ROCm AITER is enabled, and stock `-O0` to `-O3` resolve as on `main`. This PR supersedes #57349.

## Claims

- With `VLLM_ROCM_USE_AITER=1`, an explicit request for any of the three fusions is honoured when layer names are hoisted, and `-O2` with `use_inductor_graph_partition: true` or `splitting_ops: []` resolves both fusion flags True. `main` resolves all of them False.
- The fused op on MI355X is −62% / −51% / −18% at 1 / 64 / 256 tokens, bit-identical on q, k and both caches; the gain closes toward the existing `rope_kvcache_fusion_max_token_num` (256).
- Llama-3.1-8B serving: median TPOT −2.6% to −3.7%, throughput +3.7%. GSM8K stays within the base-repeat drift.

## Details

The pass matches only dense GQA models with a plain `split → rotary_embedding → unified_kv_cache_update` chain (Llama-3.1, Mixtral, gpt-oss); QK-norm (Qwen3) and MLA-only models match 0. Once a fusion survives, the custom op serves every RoPE call, including above `rope_kvcache_fusion_max_token_num`, where #36716 measured it up to 5% slower than native RoPE. #49142 and #60326 overlap only the MLA hunk.
