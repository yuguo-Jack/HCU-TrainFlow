# [Draft][HiSparse] Evictable resident pages; host pool as an ordinary block pool (on top of #53781)

[Upstream PR](https://github.com/vllm-project/vllm/pull/56109) · state: closed · merged: False

## Original PR description

## Purpose

Design suggestion for #53781 (HiSparse host-resident sparse-MLA decode), **not for merge**. Opened against `main` only so the scheduler- and worker-side integration can be read as one diff. It is the current #53781 head (`2d848329e1`) plus the six commits listed below. Earlier revisions of this PR were based on an older head and carried a separate "KV cache command" transport; that has been dropped and HiSparse traffic stays on the existing KV connector channel.

The goal is to minimise what #53781 changes in `vllm/v1/core`, `vllm/v1/core/sched`, `vllm/v1/worker/gpu` and the KV connector base, on the principle that the generic KV cache manager and coordinator should not know which block pool is on the host, nor that a HiSparse coordinator exists behind three of the managers. The reductions are meant to preserve the observable behaviour of the #53781 head; the intentional differences are listed at the end.

## Commits on top of #53781

1. **Make GPU-resident HiSparse pages evictable pool blocks.** The resident tier is a write-back cache. Once a page's host copy is durable and its owner can read from host, the coordinator releases the page with a generic `BlockPool.unpin_blocks(blocks, on_reuse)`. Removes the synchronous reclaim, host reservations, and spill-then-release machinery.
2. **Give the HiSparse host group a private pool.** The host group carries `KVCacheGroupRole.HISPARSE_SOURCE`; the registry selects `HiSparseSourceManager`, which owns a private host `BlockPool` and defers prefix publication until pages are durable.
3. **Allocate host-resident tensors through `allocate_kv_cache`** via an optional `host_allocator` and `KVCacheSpec.has_layer_views`; the duplicated HiSparse allocator is gone and binding lives in `vllm/v1/hisparse/binding.py`.
4. **Bind the KV cache manager to connectors** with a generic `KVConnectorBase_V1.bind_kv_cache_manager` (default: the existing `bind_gpu_block_pool`), replacing the scheduler's HiSparse connector lookup.
5. **Drive HiSparse through existing connector hooks.** `prefix_completion_group_ids`, `get_num_new_matched_tokens_capped`, `stage_host_mirror_mapping`, `requires_pre_forward_start` and the per-manager `attach` / `complete_external_load` / `has_pending_work` / `has_pending_frees` hooks are gone. The HiSparse connector builds its coordinator from the bound manager, sets `has_sync_kv_loads`, reports pending work through `has_pending_push_work` / `has_pending_block_frees`, and stages row mirrors from the slot mappings it already holds. `pre_forward` extras ride `start_load_kv`'s existing `**kwargs`; block zeroing skips off-device caches inside `KVBlockZeroer`; slot-mapping use is a `KVCacheSpec` property.
6. **Keep the host pool private and complete prefixes through main's flow.** Partial prefix completion (a deep host hit completed by the offloading connector restoring the indexer gap) now uses main's reconciled lookup: a manager may declare that its cached prefix outlives its siblings' (`retains_longer_hit`), the coordinator keeps that group's longer block list, the offloading connector caps its offer so it never covers a range some group cannot, and `allocate_slots` trims the retained list to local + external. `get_computed_blocks_for_connector` and `truncate_computed_blocks` are back to main. Host copy-on-write pairs travel in the HiSparse connector metadata and are released on worker acknowledgement; host cached-block events publish through the device pool's live queue; eviction targets the device pool; pending host imports complete from the source manager's `cache_blocks` on the same success path as before.

## Intentional behaviour differences from the #53781 head

- Eager write-back of resident pages runs regardless of prefix caching, because a page is only evictable once its host copy is durable. #53781 ran it only with prefix caching on.
- The resident tier is evicted through the free queue instead of a synchronous reclaim; a pool fully pinned by a single request that cannot grow falls back to ordinary preemption.
- Connector evictions of device block ids now evict device blocks. #53781's head redirected all connector evictions to the host pool when one existed.
- Host copy-on-write endpoints are released when the worker acknowledges the copy rather than through the scheduler's step fence (never earlier).
- A HiSparse KV cache config without `HiSparseConnector` now fails at bind time instead of silently degrading.
