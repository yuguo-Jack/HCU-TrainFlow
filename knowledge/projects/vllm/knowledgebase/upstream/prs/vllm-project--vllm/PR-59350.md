# [Perf][KV Connector] Drop the redundant index_select in kv_postprocess_layout_on_receive

[Upstream PR](https://github.com/vllm-project/vllm/pull/59350) · state: open · merged: False

## Original PR description

## Purpose

`kv_postprocess_layout_on_receive` rewrites the blocks that were just copied
into the local cache so that their layout matches what the local attention
backend expects. It gathers them, permutes the two inner dimensions and writes
them back:

```python
blocks_to_update = cache.index_select(0, indices)      # line 283
target_shape = list(blocks_to_update.shape)
target_shape[0] = -1
inv_order = [0, 1, 3, 2, 4] if blocks_to_update.ndim == 5 else [0, 2, 1, 3]
src_shape = tuple(target_shape[i] for i in inv_order)
blocks_to_update = cache.index_select(0, indices)      # line 288 - identical
permuted_blocks = blocks_to_update.reshape(src_shape).permute(*inv_order)
cache.index_copy_(0, indices, permuted_blocks)
```

Line 288 repeats line 283 verbatim and immediately overwrites its result with
an identical tensor, so the reshape/permute/copy are unaffected by it. The
first call is needed (`target_shape`/`inv_order` are derived from its shape and
ndim); the second is not.

`index_select` is a full gather of every received block, and this runs on the
decode side for each received block set, so the duplicate doubles a temporary
allocation proportional to the transferred KV. Deleting the statement is
behaviour-preserving; the only observable difference is one fewer gather.

## Test Plan

`tests/v1/kv_connector/unit/test_kv_postprocess_layout_on_receive.py` wraps a
real `torch` cache tensor so the gathers and the write-back are counted, and
runs the helper for both the 4D and the 5D cache layout:

```bash
python -m pytest tests/v1/kv_connector/unit/test_kv_postprocess_layout_on_receive.py -q
```

Besides the call counts it also pins the operation's contract - a layout fix-up
is a permutation, so the received blocks must keep their multiset of values and
untouched blocks must be left alone - which guards against a future change that
"optimises" the remaining gather away or reorders the permutation.
