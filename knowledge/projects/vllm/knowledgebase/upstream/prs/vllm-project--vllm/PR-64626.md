# [Bugfix][Rust Frontend] Don't count content-free chunks as streamed outputs in vllm-bench chat

[Upstream PR](https://github.com/vllm-project/vllm/pull/64626) · state: closed · merged: True

## Original PR description

## Overview

The Rust `vllm-bench` `openai-chat` backend counts any chunk with non-empty `choices` as a streamed output. vLLM's chat stream opens with a role-only chunk, `{"role":"assistant","content":""}`, so TTFT is measured to a chunk with no token and the first real token adds a spurious ITL sample. #62341 fixed the same thing in the Python client; this ports its rule.

## Claims

- On 100 chat requests, `main` recorded one extra ITL sample on every request, a sub-0.1 ms first sample on all 100 (the role chunk arriving just before the first token), and on 22 requests more ITL samples than there are gaps between their tokens. With the fix all three are gone.
- `ChatDelta` now reads `role`, `reasoning`, `reasoning_content`, `tool_calls` and `function_call`, and a chunk counts when it carries content, reasoning or a tool call, or an empty `content` without `role` (a token that decodes to an empty string). Same rule as Python's `_choice_has_streamed_output`.

## Validation

Four new tests in `openai_chat.rs`, on the existing socket SSE server made scriptable: the role chunk, an empty mid-stream delta, an empty-string token, and reasoning plus tool call deltas. All four fail with the old gate. `cargo test -p vllm-bench` passes (217), and `cargo fmt --check` and `cargo clippy -p vllm-bench --all-targets -- -D warnings` are clean.

RTX 3080, `Qwen/Qwen2.5-0.5B-Instruct`, random 256 in / 128 out, 100 prompts, concurrency 16, through a proxy that recorded every streamed chunk:

| | `main` | this branch |
|---|---|---|
| requests with one more ITL sample than token chunks on the wire | 100 | 0 |
| requests with a sub-0.1 ms ITL sample at position 0 | 100 | 0 |
| requests with `len(itl) == output_tokens` | 22 | 0 |

Forced tool calls through `openai-chat` still complete 100 of 100, with ITL counts matching the wire.

## Details

#59736 makes a token-less stream fail. With this change a stream carrying only the role chunk has no token, so the two fit together.

No issue or PR covers this. AI assistance (Claude) was used to write the change and tests. I reviewed every line and ran the tests and GPU comparison.
