# [Bugfix][KV Connector] Backoff last prompt token for sliding window in P/D (#65550)

[Upstream PR](https://github.com/vllm-project/vllm/pull/65584) · state: open · merged: False

## Original PR description

## Motivation
In P/D disaggregated serving, the decoder recomputes the last prompt token ($N - 1$) to sample the first output token. When all $N$ tokens are transferred, the sliding window group is laid out for position $N$, dropping the block holding position 
```math
$N - W  , whenever  (N - W + 1) \equiv 0 \pmod{\text{block\_size}}
``` 
Consequently, FlashAttention's sliding window query at $N - 1$ reads position $N - W$ from `null_block` (#65550).

## Proposed Changes
Scope `_prefill_backoff` to sliding window attention models (`SlidingWindowSpec`) in both NIXL (`nixl/base_scheduler.py`) and Mooncake (`mooncake_connector.py`), following the precedent already established for **Mamba** and **DeepSeek-V4.1 bounded replay**:
1. Prefiller computes $N - 1$ tokens, keeping position $N - W$ within the active sliding window on the sender.
2. Connector transfers $N - 1$ tokens to the decoder.
3. Decoder loads $N - 1$ tokens and natively recomputes token $N - 1$ with its full sliding window intact.
4. Pure full-attention models (Llama, etc.) remain untouched with 0 backoff, avoiding the multimodal boundary splitting and prompt-logprob complexities that stalled #59330.

Fixes #65550.

## Relationship to Prior Work
- **#59330** (@ivanium): Proposed universal backoff across all models, but encountered blockers around multimodal inputs and prompt logprobs. This PR restricts the backoff strictly to `SlidingWindowSpec` (mirroring Mamba and DSV4.1), serving as a clean, low-risk bridge fix.
- **#60545** (@njhill): Proposes transferring hidden states in KV cache padding so decode never recomputes token $N - 1$. Once that architectural PoC lands, this connector-level backoff can be naturally superseded.

## Test Plan

- Verified locally on CPU:
