# [Test Coverage] Add tests for MoE dispatch and Triton qzeros reshape

[Upstream PR](https://github.com/vllm-project/vllm/pull/53643) · state: open · merged: False

## Original PR description

## Purpose

Two dispatch/format-layer gaps in the WNA16 MoE path, plus a one-line diagnostic fix a test exposed.

**1. `CompressedTensorsMoEMethod.get_moe_method` had no direct test coverage.** It is pure routing logic — given a quantization scheme (plus platform/config state on the ROCm branches) it picks one of ~9 backend MoE method classes. The ROCm selection hinges on a 7-term `AND` (native RDNA kernel vs. gfx950 FlyDSL vs. emulation fallback); a single dropped term silently misroutes production traffic. An unreachable-branch bug (dead `CompressedTensorsW4A16FlydslMoEMethod` path, indentation) already shipped this way in #44570 and sat unnoticed for weeks — [#44570 (comment)](https://github.com/vllm-project/vllm/pull/44570#discussion_r3440228634). `test_flydsl_moe.py` exercises the kernel, not the dispatch.

**2. The Triton qzeros reshape in `convert_to_wna16_moe_kernel_format` had no regression coverage.** AutoGPTQ / compressed-tensors checkpoints persist packed weights K-first int32; the `TRITON` branch transposes w13/w2 and scales into the N-first packed-uint8 layout `fused_moe_kernel_gptq_awq` expects. The zero-point transpose was missing until #52112 added it (chasing an unrelated bug, no reference to #44570 or its review thread), and it shipped with no test. A byte/nibble permutation there does not crash — it silently offsets every dequantized weight.

**3. Diagnostic fix (1 line).** While adding an invalid-format case, the `ValueError` in that branch was found to print the *required* format constant instead of the *received* `format` — `f"but got format: {CompressionFormat.pack_quantized.value}"` → `f"but got format: {format}"`. No behavior change: the raise already happened for these configs; only its wording changes. `test_wna16_invalid_bits_or_format_raises[bad-format]` now locks it in.

### Files

| file | contents |
|---|---|
| `tests/kernels/quantization/test_compressed_tensors_moe_dispatch.py` | 28 tests — scheme resolution, simple + weight/input backend routing, NVFP4 routing, and the three ROCm sub-branches of the wNa16 path, including a parametrized check that the gfx950/FlyDSL 7-term `AND` requires every term individually. Every backend class is mocked → asserts routing only (which class, which args), no GPU/model dependency. |
| `tests/kernels/moe/test_wna16_moe_triton_gptq_qzeros.py` | 4 tests — the K-first int32 → N-first uint8 qzeros transform maps each channel's zero-point to the exact byte/nibble `fused_moe_kernel_gptq_awq` reads (`out[e, bn // 2, kg]`), verified against an independently constructed reference; plus the `qzeros=None` (symmetric-checkpoint) path. Parametrized over `AutoGPTQConfig` (sym) and `QuantizationArgs` (asym — where the zero-point values are load-bearing). Pure tensor-shape/value test, no kernel launch. |
| `compressed_tensors_moe.py` | the 1-line message fix above. |

Each test file lives in the tree of the implementation it exercises so it rides that impl's Buildkite `source_file_dependencies` — dispatch (`layers/quantization/compressed_tensors/`) → `kernels-quantization-test`; qzeros (`layers/fused_moe/oracle/int_wna16.py`) → `kernels-moe-test` — per [#53643 review](https://github.com/vllm-project/vllm/pull/53643).

### Not a duplicate

`get_moe_method` has no dispatch-layer tests on `main`; #52112 shipped the qzeros transpose with none; no open PR adds either. This traces to two acknowledged-but-unfixed threads from #44570 ([dispatch coverage](https://github.com/vllm-project/vllm/pull/44570#discussion_r3440228634), [qzeros](https://github.com/vllm-project/vllm/pull/44570)). Related: #52112 (the qzeros fix this covers), RFC #53629 (streaming-time weight conversion, spun out of this work).
