# [Parser] Flush Kimi K3 partial marker text at stream EOF

[Upstream PR](https://github.com/vllm-project/vllm/pull/60642) · state: open · merged: False

## Original PR description

## Overview

Kimi K3 streaming can permanently hold text that looks like the start of an XTML marker when generation ends. Flush the literal unfinished suffix to its reasoning/content channel at EOF, so `value <` is not truncated to `value `.

Rebased onto main `bfa7e5b7afe40ebe48288801a2baf5c1135cd881`. This remains an independent child of closed #58968.

## Claims

```diff
stream ends with an unfinished marker candidate
- buffered suffix is lost
+ emit the generated suffix in its current channel
```

Keep complete framing/tool boundaries and reasoning suppression intact. This parser fix also applies to single-instance serving.

## Details

Use the existing finalization callback and generated text. Reasoning tails stay in reasoning; tool-content flush runs only after reasoning ends. No generic parser interface or generation behavior changes.

Duplicate checks: #50229 broadly migrates K3 to Parser Engine and overlaps these files; this is the smaller fix for the existing implementation, and its regressions should survive that migration. #51400 handles complete message-close markers; #57366/#50291 handle non-streaming truncation; #60565 handles response-only transitions. They do not implement this legacy EOF flush. #58968 was superseded by the split PRs.

**Merge danger:** two-way door; blast radius: K3 streaming text extraction. Normal serving finalizes a choice once; this change does not extend the contract to repeated finalization.

#60655 addresses quoted think markers in non-streaming output. The broader Parser Engine migration in #50229 still overlaps these files; preserve the EOF behavior when composing it.
