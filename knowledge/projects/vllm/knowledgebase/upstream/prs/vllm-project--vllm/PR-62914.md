# [Feature][KV Offload] Enable canonical cross-TP offload for GDN hybrids

[Upstream PR](https://github.com/vllm-project/vllm/pull/62914) · state: open · merged: False

## Original PR description

## Overview

Enable filesystem cache reuse across TP sizes for restricted attention+GDN hybrids in the native `OffloadingConnector`. Implements the [GDN cache-type slice](https://github.com/vllm-project/vllm/issues/61886#issuecomment-6221332738) of #61886; the broader tracking issue remains open.

## Claims

- Reconstruct TP-sharded GDN convolution Q/K/V and recurrent state through the existing canonical mapping and transfer paths.
- Include recurrent-state semantics and storage layout in the cache identity, isolating incompatible and legacy opaque files.
- Preserve the existing format for unsupported profiles and fail closed when a certified profile does not match the live tensor layout.
- Validate real TP1→TP2 and TP2→TP1 filesystem reuse with Qwen3.5-0.8B.

## Validation

Validated on L20 GPUs using native extensions built from upstream `ae8f41238cc7316781ef4359890940749735b209`, with the patched Python source. Model: `Qwen/Qwen3.5-0.8B`, revision `2fc06364715b967f1860aea9cf38778875588b17`, BF16 convolution state and FP32 recurrent state.

Latest targeted validation after cleanup:

| Suite | Result |
| --- | --- |
| Config, canonical mapping, FileMapper, FS and tiering | 324 passed |
| GPU canonical copy/layout and worker registration | 40 passed |
| Independent state oracle and two cross-TP model cases | 10 passed, 10 deselected |

The model cases use fresh producer/consumer processes with `VLLM_GPU_SYNC_CHECK=error`. In each direction, the consumer reused 2,048 prompt tokens, read 62,914,560 bytes through the filesystem tier, and restored five keys across four cache groups.

An independent oracle captures native state before offload and compares the restored consumer state after transfer completion. It checks Q/K/V, recurrent state and attention K/V without deriving expected values from canonical copy offsets. Both directions passed byte-exact checks over 44,703,744 native-state bytes each.

CPU mapping tests cover TP1/TP2/TP4, BF16/FP16 convolution state, padding and incompatible configurations. Applicable pre-commit hooks passed on the validated revision.

No CI configuration changes are included. The dual-GPU model cases were run outside CI on L20; no Buildkite/L4 execution is claimed.

**Numerical limitation:** byte-exact state restoration does not imply equivalence to recomputing the prefix at the consumer's TP. Earlier evaluation on a fixed 200-question GSM8K subset (5-shot, greedy, max_tokens=256) produced:

| Consumer TP | Cold | Same-TP reuse | Cross-TP reuse |
| --- | --- | --- | --- |
| TP1 | 60/200 | 60/200 | 54/200 |
| TP2 | 54/200 | 54/200 | 54/200 |

The final cleanup did not change model computation or the stored format; this evaluation was not rerun for that cleanup. This PR does not claim accuracy neutrality or a performance improvement.

## Details

The existing opaque GDN layout concatenates complete rank-local pages. Cross-TP reuse needs component-major ordering instead: global Q, K, V and recurrent state. This change reuses the existing convolution decomposition and canonical copy machinery, without changing model computation, scheduling or transfer kernels.

Support is intentionally limited to native `TieringOffloadingSpec` with `canonical_layout=true`, Model Runner V1, single-node multiprocessing, PP=PCP=DCP=DP=1, DS convolution layout, align-mode checkpoints and fully TP-sharded GDN state. Attention must be unquantized, head-sharded causal full attention.

Mamba1/Mamba2, replicated state, speculative decoding, ReplaySSM, packed layouts and MRV2 remain outside this first PR. P2P tiers are rejected for the new format, including mixed FS+P2P configurations. The usage documentation includes configuration, compatibility limits and the cross-TP numerical caveat.

Duplicate-work check: reviewed #61886 and open PRs by issue number and area keywords on 2026-10-21. #62160/#62162 cover replicated GQA sizing and chunked-local attention; #62529/#62861 cover PCP and sliding-window mapping tests. This PR addresses native GDN state reconstruction and compatibility, not those slices or the broader storage-tier validation work.
