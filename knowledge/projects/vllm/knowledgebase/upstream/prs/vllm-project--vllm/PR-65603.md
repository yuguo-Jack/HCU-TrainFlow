# [Feature][AuxOutput] Add auxiliary output logprobs support

[Upstream PR](https://github.com/vllm-project/vllm/pull/65603) · state: open · merged: False

## Original PR description

## Overview

Port generated-token logprobs support to the redesigned AuxOutput connector on `rl/aux-output`. Logprobs-only requests use a variable-size artifact store while routed-expert and indexer outputs retain their existing data paths.

## Claims

- Retains generated-token logprobs by KV block and replays them for opted-in requests, including prefix-cache reuse.
- Adds request validation, config and worker tests, a streaming continuation regression test, and usage documentation.
- This adapts the earlier `feat/logprobs_auxoutput` implementation to the redesigned connector; it does not restore the old connector structure.

## Validation

- `.venv/bin/python -m pytest tests/config/test_aux_output_config.py tests/distributed/aux_output_connector/test_store.py -q` — 174 passed.
- `.venv/bin/python -m pytest tests/v1/streaming_input/test_scheduler_streaming.py::TestStreamingScheduler::test_aux_logprobs_are_consumed_before_streaming_parameters_change -q` — 1 passed.
- `.venv/bin/python -m pytest tests/v1/e2e/test_aux_output_logprobs.py -q` — 4 skipped; this environment does not provide a CUDA-like worker.
- `compileall` and `git diff --check` passed. Ruff was unavailable in the environment.
- AI assistance was used; the submitting human should review the changes and validation before submission.

## Details

Requests opt in with `SamplingParams(extra_args={"aux_output_enabled": True})` and must set generated-token `logprobs`. The feature requires Model Runner V2, prefix caching, and `logprobs_mode="raw_logprobs"`. Prompt logprobs, full-vocabulary logprobs, custom logprob token-ID layouts, and online weight updates are not supported by this path.
