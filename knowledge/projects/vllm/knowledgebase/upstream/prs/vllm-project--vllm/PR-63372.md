# [Bugfix][MRV2] Keep routed-expert rows of every DBO microbatch

[Upstream PR](https://github.com/vllm-project/vllm/pull/63372) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

With DBO on, `--enable-return-routed-experts` returns wrong data (MRV2). Every microbatch writes its routing from row 0, so the last one overwrites the others. This PR writes each microbatch at its own token offset.

cc @aoshen02 @specture724 @LucasWilkinson

## Validation

Same 32 requests, routing compared per token with a DBO-off server (DeepSeek-V2-Lite, 2×H200, DP=2, EP, NIXL EP, eager):

| Server | Same routing as DBO off |
| --- | ---: |
| DBO on, main | 0% |
| DBO on, this PR | 89.4% |
| DBO off, rerun (noise) | 88–91% |

New unit test fails on main (8/8 mismatched) and passes here. Existing capture and ubatch tests pass (81 on H200). The routing comparison above was run before the refactor below.

After the refactor, on H200: the 4 DBO capture cases, `test_ubatch_runner_overlaps_and_matches_single_batch`, and `test_capturable_run_replays_as_a_cudagraph` pass.

## Details

- `ubatch_utils.py`: pass each microbatch's `token_slice.start` to `make_ubatch_contexts()` as `token_offsets`, like the V1 path already does.
- `routed_experts_capturer.py`: write at `dbo_current_ubatch_token_offset()` (0 outside DBO, so non-DBO is unchanged).

**Suggestion: Reuse the existing DBO token offset mechanism**

The fix looks correct. However, we already have a generic DBO token offset mechanism in `ubatching.py`, so we could reuse it instead of introducing a routed-experts-specific key in `ForwardContext.additional_kwargs`.

Suggested changes:

1. In `UBatchRunner.begin_capturable_run()`, pass the token offsets to the existing `make_ubatch_contexts()`:

   ```python
   token_offsets=[
       s.token_slice.start for s in ubatch_slices
   ],
   ```

2. In `RoutedExpertsCapturer.capture()`, use the existing `dbo_current_ubatch_token_offset()` helper instead of reading `routed_experts_token_offset` from `ctx.additional_kwargs`.

3. Remove the newly added `additional_kwargs` in `_make_forward_contexts()` and update the corresponding unit test.

This is consistent with the existing implementation in `gpu_ubatch_wrapper.py`, which already passes token offsets through `make_ubatch_contexts()`.

The helper also returns `0` outside DBO, preserving the non-DBO behavior.

This avoids maintaining the same token offset in two different places (`UBatchContext` and `ForwardContext`) and keeps the offset handling centralized in the existing DBO infrastructure.

It would also be useful to verify that CUDA Graph capture/replay preserves the expected offsets.

No changes to the existing DBO synchronization or scheduling logic should be necessary.
