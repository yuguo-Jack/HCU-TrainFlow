# [Online quantization] Extend re-quantization API to MOE (showcase `NVFP4 modelopt/CT/quark` to any online MOE method)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60276) · state: closed · merged: True

## Original PR description

## Overview

Followup to https://github.com/vllm-project/vllm/pull/55684 that implemented the interface for linear layers.

## Claims

This PR implements the RFC https://github.com/vllm-project/vllm/issues/59062 for MOE layers, showcasing:

- compressed-tensors NVFP4 MOE -> any online MOE quant method
- modelopt NVFP4 MOE quant method -> any online MOE quant method
- quark NVFP4 MOE quant method -> any online MOE quant method

We share the re-quantization logic with linear layers (same as https://github.com/vllm-project/vllm/pull/55684), no duplication.

This adds a clean API for features like #51274.

Details & testing to be added later.

Left to do:

- [x] Add modelopt NVFP4 dequantize_weight in this PR
- [x] broaden test
- [x] The generic source/target API ignores the source method's size-rounding contract.
- [x] cleanup

Left to other PRs:

- [ ] Requantization unnecessarily requires a runnable backend for the source format
- [ ] Early fail in case the source method does not implement `dequantize_weight` (for now, this fails during loading)
- [ ] Move from current implementation of **loading all original quant method weights before requantizing, to requantizing on the fly weight by weight**. This will be needed to avoid memory overhead in cases like e.g. `FP8 -> MXFP4`.
- [ ] Requantization to `nvfp4_per_token` (not tested in this PR, needs an other PR for Nvidia GPUs)
- [ ] Adopt this API
    - [ ] https://github.com/vllm-project/vllm/pull/51274 => mxfp4 -> int4 conversion.
