# [CI] Fix stale NVFP4 decode test selector on DGX Spark

[Upstream PR](https://github.com/vllm-project/vllm/pull/64107) · state: closed · merged: True

## Original PR description

## Overview

Fixes #64090. The DGX Spark nightly attention step still selects `test_flashinfer_xqa_nvfp4_decode_correctness`, which #60532 renamed to `test_flashinfer_nvfp4_decode_correctness`. Pytest therefore collects 0 tests and the step fails. This updates the `-k` filter to the substring `nvfp4_decode_correctness`.

## Claims

- The `flashinfer-nvfp4-xqa-dgx-spark` step selects `test_flashinfer_nvfp4_decode_correctness` again.
- Sink-prefill coverage stays out of this fix. #63826 will later widen the same selector to `-k "nvfp4_decode_correctness or nvfp4_sink_prefill"`.

## Validation

- On current `upstream/main` (`d0c20bb840`), `.buildkite/test_areas/attention.yaml` still passed `-k test_flashinfer_xqa_nvfp4_decode_correctness`. The only test whose name contains `nvfp4_decode_correctness` is `tests/v1/attention/test_attention_backends.py::test_flashinfer_nvfp4_decode_correctness`.
- Pytest's `-k` expression matches `nvfp4_decode_correctness` against that name and does not match the old `test_flashinfer_xqa_nvfp4_decode_correctness` token. The new expression does not mention `nvfp4_sink_prefill`.
- No DGX Spark runner was used. The reported failure is `160 deselected / 0 selected`, which this selector change addresses.

## Details

#60532 renamed the test (XQA on SM12x and fa2 on SM8x) and left the Buildkite `-k` filter on the old name. A full-name `-k` match does not match the new function name, so the nightly step exits 1.

This PR changes only that one command in `.buildkite/test_areas/attention.yaml`. It does not change production code and does not include the sink tests from #63826.

This is narrower than the open PRs that also touch the selector:

- #63826 updates the stale name only as part of the fp8/NVFP4 attention-sink feature, and it adds `nvfp4_sink_prefill`.
- #63169 updates the selector together with `head_size=64` cases that #64090 notes are blocked on a newer FlashInfer.
