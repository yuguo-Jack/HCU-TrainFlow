# [Bugfix][Security] Fix catastrophic backtracking in the poolside_v1 and dots tool-call regexes

[Upstream PR](https://github.com/vllm-project/vllm/pull/54678) · state: open · merged: False

## Original PR description

## Overview

Prevent catastrophic backtracking in Poolside v1 and Dots tool-call extraction. This updates the existing PR after upstream drift; it does not introduce another parser or a duplicate fix.

## Claims

- Poolside function names no longer compete with adjacent whitespace quantifiers; names containing internal spaces still parse. Whitespace-only names are intentionally rejected instead of producing an empty function name.
- Dots whitespace runs are possessive while the block capture remains lazy, preserving first-closing-marker and adjacent-block behavior.
- Regex operations use the existing timeout setting, and timeouts take the parser's existing content/no-call fallback.

## Details

Poolside's captured name overlapped with surrounding `\s*` runs. Pinning its first and last characters to non-whitespace removes those ambiguous splits. Dots had overlapping whitespace around a lazy DOTALL capture; making only the whitespace possessive keeps the capture ending at the first marker.

The rebase preserves the current `vllm.renderers.chat_utils` import path, custom tool-choice handling and schema-aware value conversion, including nullable-string handling and its upstream tests. The diff remains four files, 188 additions and 10 deletions. No dependency or core-engine changes.

The `finditer(..., timeout=...)` approach here matches what six other parsers on current `main` already do (`llama`, `pythonic`, `llama4_pythonic`, `lfm2`, `olmo3`, plus this one), so it is not introducing a new convention.

**2. The possessive quantifiers still fix the blowup, and still preserve semantics.** The `dots` block pattern against a start token followed by spaces and no closing tag:

| trailing spaces | `\s*` (main) | `\s*+` (this PR) |
|---|---|---|
| 200 | 33 ms | 0.02 ms |
| 400 | 240 ms | 0.02 ms |
| 800 | 1 832 ms | 0.02 ms |
| 1 600 | **timeout > 5 s** | 0.04 ms |

Cost grows ~8× per doubling, i.e. cubic: under `DOTALL` the dot matches a space too, so the two `\s*` runs overlap with the lazy `.*?` between them and a failing match walks every way of splitting the run.

The semantic risk of making those runs possessive is that a block might stop ending at the *first* closing tag. It does not — `.*?` stays lazy:

```
input   <dots_function_call> a </dots_function_call> mid <dots_function_call> b </dots_function_call>
main    ['a', 'b']
this PR ['a', 'b']
```

and a normal single call extracts byte-identically (`{"name": "f", "arguments": {} }` from both).

Ready for `/ci run`.
