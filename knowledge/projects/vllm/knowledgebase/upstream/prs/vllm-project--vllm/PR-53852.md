# [Bugfix] [Perf] Honor explicit FlashInfer all-reduce size override for ds4-pro-dspark(h200)

[Upstream PR](https://github.com/vllm-project/vllm/pull/53852) · state: open · merged: False

## Original PR description

## Motivation

Standalone FlashInfer all-reduce ignored an explicitly configured cutoff: the
topology-tuned value (or the world-size default) always won, so users could
not raise the routing cutoff on topologies where the default is conservative —
on sm90/TP8 the default standalone cutoff is 0.5 MiB, while FlashInfer MNNVL
outperforms the NCCL path for small decode all-reduces on H200 NVSwitch.

Reviewer feedback on the first version (thanks @GirasoleY) also identified
that reusing the fused-pass `fi_allreduce_fusion_max_size_mb` for standalone
dispatch conflated two settings and could implicitly enable unvalidated
topologies (e.g. TP16 on sm90), and that `get_fi_ar_workspace()` could still
over-allocate the workspace. All three are addressed.

## Changes

- New dedicated pass-config field `fi_allreduce_standalone_max_size_mb`
  (default `None`); standalone all-reduce reads only this field.
  `fi_allreduce_fusion_max_size_mb` keeps its fused-pass meaning.
- One shared cutoff resolution for `FlashInferAllReduce` and
  `get_fi_ar_workspace()`: explicit standalone value → topology-tuned cutoff
  → world-size default. The standalone workspace floor honors the override
  (no over-allocation), while larger caller-provided fused-workspace
  requirements are preserved.
- The explicit override changes the cutoff, never topology support: world
  sizes with neither a tuned standalone cutoff nor a default-table entry
  (e.g. TP16 on sm90) stay disabled and fall back to NCCL.

## End-to-end results (8×H200, DeepSeek-V4-Pro-DSpark, TP8/EP8)

Fixed 1024-in / 2048-out requests, median output tok/s of 3 rounds per
concurrency, identical flags for both arms (same build; only
`VLLM_ALLREDUCE_USE_FLASHINFER` and the override differ):

| Configuration | standalone FI AR off | on, mnnvl + 2 MiB override | Gain |
| --- | ---: | ---: | ---: |
| concurrency 16 | 506.7 | 528.8 | +4.4% |
| concurrency 32 | 514.2 | 529.7 | +3.0% |

Ablation with the default 0.5 MiB sm90 cutoff (override unset): 528.5 / 531.9
— the workload-level gain comes from standalone MNNVL all-reduce itself; the
override matters for decode batch shapes above the conservative default
(hidden 7168 × BF16: 37–146-token batches only route to FlashInfer with the
2 MiB cutoff; the boundary is covered by unit + GPU smoke tests). TPOT
unchanged (29.5–30 ms); all requests completed with exact input/output
lengths, zero failures.

TP16 on sm90 (two-node probe, 16 ranks): all ranks stayed disabled, zero
workspace calls, NCCL fallback all-reduce passed — the override cannot enable
an unsupported topology.

## Tests

- `tests/distributed/test_comm_ops.py`: new focused tests for
  standalone/fused arg independence, override precedence over tuning,
  workspace-floor honoring (including the larger-fused-requirement case),
  the 2 MiB routing boundary, and the TP16-on-sm90 guard.
- Focused run: **29 passed, 19 deselected**; `ruff check` + `ruff format`
  clean.

## Usage

```bash
VLLM_ALLREDUCE_USE_FLASHINFER=1 VLLM_FLASHINFER_ALLREDUCE_BACKEND=mnnvl \
vllm serve <model> --tensor-parallel-size 8 \
  --compilation-config '{"pass_config": {"fi_allreduce_standalone_max_size_mb": 2}}'
```
