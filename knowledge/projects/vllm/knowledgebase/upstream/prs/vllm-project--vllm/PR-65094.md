# [Bugfix][NIXL] Reject P/D pairs whose KV cache groups scale differently

[Upstream PR](https://github.com/vllm-project/vllm/pull/65094) · state: open · merged: False

## Original PR description

## Overview

NIXL pairs every KV cache group's blocks at one P/D block size ratio, which comes from the lcm of the groups' block sizes. If one group's own P/D ratio differs, that group's KV lands at the wrong tokens without an error. This PR adds the groups' block sizes to the handshake metadata and rejects such peers at the handshake.

## Claims

- A P/D pair whose KV cache groups' block sizes don't all change by the same ratio fails the handshake with `NotImplementedError`, in pull and push. Before, Mamba hybrids passed the handshake. The transfer then put that group's KV at the wrong tokens, or, for longer prompts with the finer group on D, failed an assert in `_apply_prefix_caching`.
- Pairs whose groups all scale by the same ratio are unchanged.

## Validation

No new test: no existing parametrization builds two engines whose groups scale differently. One test helper that skips `__init__` now sets the new attribute.

CPU, main `b8c04dd3b4` vs this PR at `726c22fe80`:
- **NIXL unit suites** (`tests/v1/kv_connector/unit/test_nixl_*.py`, `test_tp_mapping.py`, `test_transfer_topology_sharded.py`, `test_bidirectional_kv_transfer.py`, `test_handshake_pp_aggregation.py`): failed sets are identical to main.
- **Local P/D simulation**, not part of this PR. It uses the real planner, `register_kv_caches`, handshake, pull and push paths, with NIXL replayed as memcpy and D checked token by token. Of 496 cases, 20 leave wrong KV on D on main, all of them hybrids whose drafter's groups scale differently from the target's. With this PR, those 20 fail at the handshake, and the 216 cases that transfer correctly on main still do.

GB10 (DGX Spark), main `8530a778f7` (same NIXL code as `b8c04dd3b4`) with and without this PR: Qwen3.5-0.8B, P and D on one GPU over NIXL, P block size 544 and D 1088. Outputs and logprobs are bitwise equal to a 1088/1088 P/D run, and nothing is rejected. The deployments this PR rejects need P at TP8 or a 120B model, so they were checked only in the simulation above.

## Details

`NixlBaseConnectorWorker.__init__` sets `block_size` to the lcm of the transfer groups' block sizes. `block_size_ratio`, the sub-block mapping and `_apply_prefix_caching` then apply that one ratio to every group. A hybrid's groups share one page size per rank, so each group's block size is that page divided by its own per-token bytes. When the per-token bytes of two groups change differently with TP, their block sizes change by different ratios. That happens, for example, with a target and a drafter whose KV heads replicate at different TPs.

Qwen3.8-27B + DFlash2, P TP8 → D TP4, on main:
1. P plans its full-attention groups at 416 tokens per block and D at 832. The drafter's sliding-window group is 832 on both. The NIXL block size, the lcm, is 832 on both sides.
2. The handshake sees a ratio of 1 and skips the per-region size checks for Mamba hybrids, so D accepts P.
3. On a pull, D pairs each group's block list with P's at ratio 1. P's full-attention list is twice as long, and `_apply_prefix_caching` keeps its tail.
4. D's full-attention blocks are read from P's later blocks, and decode runs on that KV.

With this PR, step 2 compares P's group sizes (416 ×4, 832) with D's (832 ×5) and raises.

The check compares the groups' ratios only when both sides have the same cache-group plan; other plans are handled, or rejected, as before.

Supporting per-group ratios instead would need per-group descriptor splits on the KV regions the groups share. With P TP > D TP, D's target page would need a token split across two P blocks, while the drafter page in the same region needs a head split across two P ranks.

Not a duplicate:
- #64067 rejects TP and block size differences only for engines that register dense pages.
- #64812 (draft) plans to advertise specs in the handshake, which would cover `transfer_block_sizes`.
- #59746 pairs blocks at the same single ratio. This PR is independent of it.
