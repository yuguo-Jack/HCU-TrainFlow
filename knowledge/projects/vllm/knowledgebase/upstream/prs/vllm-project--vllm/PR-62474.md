# [Bugfix][ROCm][MoRIIO] Slice WRITE heads by each layer's head count

[Upstream PR](https://github.com/vllm-project/vllm/pull/62474) · state: open · merged: False

## Original PR description


## Overview

Heterogeneous-TP MoRIIO WRITE (#61726) sizes every layer's KV-head slices from the model-wide KV-head count, which is the maximum over layers. Models whose layers have different KV-head counts (Gemma4) then write slices a layer does not have. This PR slices each layer by its own head count.

## Claims

- **Per-layer head counts.** WRITE between different prefill and decode TP sizes builds each attention layer's targets from that layer's KV-head count (`model_arch_config[layer_idx].total_num_kv_heads`). Models whose layers all share one count are unchanged.
- **Failures fixed.** With the Gemma4 shape in vLLM's model-config test (4 KV heads in the sliding layers, 8 in full attention, model-wide 8):
  - prefill TP1 → decode TP2 used to fail with `Head slice ... is outside 4 / 2 heads` on the sliding layers;
  - prefill TP4 → decode TP8 used to write from a producer head that does not exist.

## Validation

- **New fixture:** a `mixed_heads` model in the WRITE byte-exact matrix (`test_moriio_hetero_tp_write.py`), across the existing TP pairs plus TP4 ↔ TP8, HMA on and off, and 3 cache-layout pairs.
  - Before this change: 44 of its 48 cases fail.
  - After: all pass.
- **Full MoRIIO unit suite:** 773 passed. Ruff is clean, and mypy reports no new errors.

## Details

- `_execute_write_task` recomputes an attention layer's target for the same decode rank from the layer's mapping. It skips the layer when another producer writes that copy, which happens when a layer with fewer heads is replicated.
- The request's `write_done` writers (`num_writers`) are unchanged. A layer with fewer heads only ever needs a subset of the model-wide writers, so every writer still writes something and sends `write_done`.
- Mamba state slicing does not depend on KV heads and keeps the request's mapping.
- The same bug in heterogeneous-TP READ is fixed in the READ PR stacked on the READ fan-in fix.
