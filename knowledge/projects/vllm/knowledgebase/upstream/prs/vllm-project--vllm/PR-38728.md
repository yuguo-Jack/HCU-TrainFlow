# [Quantization] Convert NVFP4 weights to FP8 on Hopper for faster inference

[Upstream PR](https://github.com/vllm-project/vllm/pull/38728) · state: open · merged: False

## Original PR description

## Summary

On Hopper GPUs (H100/H200), NVFP4 models fall back to the Marlin kernel which dequantizes FP4→FP16 and uses FP16 tensor cores (989 TFLOPS). This PR converts NVFP4 weights to FP8 block-quantized format at load time and routes compute through existing CUTLASS FP8 kernels (3,958 TFLOPS on Hopper).

- Auto-detected on Hopper when native FP4 is unavailable, controllable via `VLLM_NVFP4_GEMM_BACKEND=fp8-compute`
- Dense linear layers use `padded_cutlass` (CUTLASS block-scaled FP8 GEMM)
- MoE expert layers use `TritonOrDeepGemmExperts` (DeepGEMM FP8 MoE)
- No new CUDA kernels — reuses existing FP8 infrastructure
- 3 files modified, ~240 lines added

## Benchmark

Mistral-Small-4-119B-2603-NVFP4 on 2x H200 NVL, vLLM 0.18.1, 500 prompts (512 in / 128 out), 5 iterations after warmup:

| Metric | Baseline (Marlin) | FP8 Compute | Delta |
|---|---|---|---|
| Output tok/s | 5,435 ± 42 | 8,822 ± 32 | **+62%** |
| Mean ITL | 58.3 ms | 36.6 ms | **-37%** |
| P99 ITL | 229.8 ms | 123.8 ms | **-46%** |
| Mean TTFT | 4,026 ms | 2,307 ms | **-43%** |
| Memory | 131,075 MiB | 132,197 MiB | +0.8% |

## Code Review

This pull request introduces an 'fp8-compute' backend for NVFP4 quantization, which converts weights to FP8 at load time to leverage native FP8 tensor cores on Hopper GPUs, providing significant performance improvements over the existing Marlin FP4-to-FP16 fallback. The implementation includes utility functions for weight conversion, updates to the MoE and linear layer backends, and environment configuration. The review feedback highlights opportunities to improve maintainability by replacing hardcoded block sizes with constants and using existing layer attributes to ensure consistency between activation quantization and GEMM operations.

The `group_size` for activation quantization and the `block_size` for the CUTLASS GEMM are hardcoded. This creates a hidden dependency on the block size set in `convert_to_nvfp4_linear_kernel_format`. To improve maintainability and prevent potential mismatches, you should use the `layer.weight_block_size` attribute that is already set on the layer object.
