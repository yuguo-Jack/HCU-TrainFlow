# [NIXL] Bump NIXL version to 1.5.2

[Upstream PR](https://github.com/vllm-project/vllm/pull/64579) · state: closed · merged: True

## Original PR description

## Overview

Bump the NIXL pin from 1.5.0 to [1.5.2](https://github.com/ai-dynamo/nixl/releases/tag/v1.5.2) for both CUDA 13 (`requirements/kv_connectors.txt`) and CUDA 12 (`requirements/kv_connectors_cu12.txt`) images. This replaces the reverted 1.5.1 bump (#63817, reverted in #64085).

## Claims

- CUDA 12 and CUDA 13 images both install NIXL 1.5.2. The two pins move together.
- No EFA regression: 1.5.2 drops the accidental libfabric 2.7.0 bump that caused the 1.5.1 revert (ai-dynamo/nixl#2528). The LIBFABRIC plugin needs the same libfabric symbol versions as 1.5.0.
- Picks up these LIBFABRIC fixes:
  - Fallback for context-independent CUDA allocations, such as mapped VMM memory (ai-dynamo/nixl#2470).
  - EFA unsolicited write recv is disabled regardless of build headers (ai-dynamo/nixl#2529).
  - All endpoint/CQ/AV calls are serialized with the rail EP lock (ai-dynamo/nixl#2542).
- The UCX path does not change.

## Validation

- **Dependency resolution**, x86_64 and aarch64, both files: `nixl`, `nixl-cu12` and `nixl-cu13` all resolve to 1.5.2.
  ```bash
  uv pip compile --python-version 3.12 --python-platform x86_64-manylinux_2_28 --torch-backend cu129 requirements/kv_connectors.txt
  # repeated for aarch64-manylinux_2_28 and requirements/kv_connectors_cu12.txt
  ```
- `pre-commit run --files requirements/kv_connectors.txt requirements/kv_connectors_cu12.txt`: passed.
- **ELF check** of `libplugin_LIBFABRIC.so` in `nixl_cu13` cp312 x86_64. None of the wheels bundle `libfabric.so`.

  | Version | Required libfabric symbol versions |
  |---|---|
  | 1.5.0 | `FABRIC_1.0`, `1.1`, `1.7` |
  | 1.5.1 (reverted) | `FABRIC_1.0`, `1.1`, `1.10` |
  | 1.5.2 | `FABRIC_1.0`, `1.1`, `1.7` |

- **Not yet run:** GPU P/D serving with `NixlConnector` on CUDA 12 and CUDA 13, LIBFABRIC over EFA, and the aarch64 Rubin NIXL source build. `requirements/kv_connectors.txt` is in the run-all patterns (`.buildkite/ci_config.yaml`), so CI runs the NIXL integration and P/D accuracy tests.

- Tested on 2 x AWS p6-b300.48xlarge, Kimi K3 disagg

## Details

`release/1.5.0...v1.5.2` touches only:

- version strings and attributions
- `src/plugins/libfabric/libfabric_backend.cpp` and `src/utils/libfabric/libfabric_rail.{cpp,h}`
- a comment in `src/utils/libfabric/meson.build`
- `WHL_TORCH_VERSIONS` in `contrib/Dockerfile.manylinux`, which adds NIXL EP extensions for torch 2.15 and 2.16 (ai-dynamo/nixl#2545, ai-dynamo/nixl#2546)

The manylinux build stays on libfabric v1.21.0 and the same pinned UCX commit.

- **Rubin nightly:** with `BUILD_NIXL=true`, `tools/build_nixl_with_torch215_for_rubin.py` reads the `nixl` pin from `requirements/kv_connectors.txt`, so the aarch64 Rubin nightly now builds NIXL v1.5.2 from source.
- **torch extensions:** vLLM pins `torch==2.14.0`, which 1.5.0 already covered. The torch 2.15/2.16 EP extensions only matter for torch-nightly builds.
- **Left unchanged on purpose:** `requirements/rubin-prerelease.txt` (`nixl==1.4.1`) and `requirements/tpu.txt`.

**Not a duplicate:** no open PR bumps NIXL to 1.5.2.
