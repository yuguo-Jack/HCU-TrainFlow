# [Perf][Parser] Avoid O(N^2) arg conversion in Granite streaming parser

[Upstream PR](https://github.com/vllm-project/vllm/pull/62334) · state: open · merged: False

## Original PR description

## Purpose

Avoid quadratic $O(N^2)$ argument conversion and safe-prefix scanning when parsing or streaming Granite 3.0 / 3.1 tool calls (`vllm/parser/granite.py`).

### Root Cause

`granite_config()` configures `tool_call_body_array=True`, `stream_arg_deltas=True`, and `arg_converter=_granite_arg_converter`, without an `arg_value_extender`.

In `tool_call_body_array` mode, `StreamingParserEngine._feed_array_char` feeds array element characters one character at a time through `_feed_args_char(ch)`, which calls `_flush_safe_args()` on **every single character** and emits $N$ separate `EventType.ARG_VALUE_CHUNK` events for an $N$-character tool call (including during non-streaming `extract_tool_calls()`, which delegates through `extract_tool_calls_streaming()`).

Without `arg_value_extender`, `ParserEngine._compute_arg_delta` re-runs `_granite_arg_converter(slot.args, True)` (`extract_json_member_object` + `scan_json_object_end`) and `_safe_arg_prefix(current_json, slot.string_keys)` from byte 0 on every character:

| Tool-Call Payload Size | `main` Latency (Converter Calls) | With `_granite_arg_value_extender` (Converter Calls) | Speedup |
|---|---:|---:|---:|
| **3.3 KB** (50 lines) | 1,486.5 ms (3,369 calls) | **5.55 ms** (63 calls) | **268×** |
| **13.2 KB** (200 lines) | 23,814.5 ms (13,269 calls) | **22.46 ms** (63 calls) | **1,060×** |
| **26.4 KB** (400 lines) | ~95,200 ms (26,469 calls) | **49.54 ms** (63 calls) | **~1,920×** |

### Solution

Add reusable `scan_json_value_extender` and `json_member_value_extender` utilities to `vllm/parser/utils.py` and wire `_granite_arg_value_extender` in `vllm/parser/granite.py` (following the pattern in `#61253`, `#61494`, `#62027`, `#62035`, `#62259`). When `raw_args` ends inside an open JSON string value of the `"arguments"` object, the returned extender validates incoming delta characters in $O(|\text{delta}|)$ time—tracking backslash escapes and returning `delta` directly until an unescaped closing `"` is encountered, at which point it returns `None` to hand back to `_granite_arg_converter`.

## Test Plan

🔴 Granite calls with long strings nested in an object or array argument now stream about 2x slower than on base. These are shapes like `{"edits": [{"text": "<long>"}]}`. In a nested string the factory returns None at line 100, but the engine still calls it after every per-character conversion (parser_engine.py:1115). Each call adds two more full-buffer Python scans per character, on top of the converter and `_safe_arg_prefix`. Fix: also return a pass-through extender for open strings at depth >= 2 of `arguments`. Its output is dropped because `open_value_streams` is False there (parser_engine.py:1084). Keep returning None for open depth-1 keys, where `_safe_arg_prefix` reports a streaming value.

<details>
<summary>Why this was flagged</summary>

Trigger: Granite emits a tool call whose long string sits inside a nested container, e.g. `{"name": "edit", "arguments": {"edits": [{"path": "a", "text": "...13KB..."`. The array splitter feeds it one character at a time (streaming_parser_engine.py:606-612 flushes each in-string char as an ARG_VALUE_CHUNK). Line 1115 then calls `_granite_arg_value_extender(slot.args)` on every char. That re-runs `extract_json_member_object` (another `scan_json_object_end`) and the span loop at granite.py:74-98, then returns None at line 100. Per-char work goes from about 2 to about 4 O(N) Python passes, so the quadratic cost roughly doubles compared with base. For the 13 KB size in the PR's table, base already takes about 24 s, so this adds tens of seconds of CPU on the serving loop. Nothing gates the factory call on `value_streams`.

**Verification:** Granite sets no `arg_structural_chars`, so every character runs `converter(slot.args, True)` at parser_engine.py:1093. New in this PR: line 1113-1115 now also calls `self._arg_value_extender(slot.args)`. For a nested string, `_granite_arg_value_extender` returns None (granite.py ~line 100), so the next character repeats the full path.

</details>
