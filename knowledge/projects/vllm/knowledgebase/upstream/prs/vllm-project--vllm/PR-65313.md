# [CI/Build] Make Python 3.14 the default for images and CI

[Upstream PR](https://github.com/vllm-project/vllm/pull/65313) · state: open · merged: False

## Original PR description



## Overview

Make Python 3.14 the default: every Docker image and the CI that runs in them move from 3.12 to 3.14, the test lock files are resolved for 3.14, and the nightly smoke test that covered 3.14 now covers 3.12. Draft until Mooncake and LMCache publish 3.14 wheels (see Blockers). Follows #34770 (3.14 support) and #60456 (nightly 3.14 smoke test); requested in #41264 (CVE fixes in newer Python).

## Claims

- All images build on Python 3.14: CUDA, CPU, Zen, XPU, ROCm and gfx1250 bases, s390x and ppc64le.
- CI tests run on 3.14 (they run in these images); the Ray compatibility check and the macOS smoke test target 3.14; the nightly `python_only_compile.sh` smoke test now installs into a 3.12 venv.
- In the CUDA, ROCm, XPU and CPU runtime requirements, only the KV connector packages below lack 3.14 wheels (plus TPU's `nixl` pin, see risks).

## Validation

Not yet built or run: no image builds or CI runs on this branch so far (that is what this draft's CI will do). Checked so far:

- **Wheel availability for 3.14** (wheels only, `uv pip compile --no-build`, each requirement separately, x86_64 and aarch64 at glibc 2.35): all of `requirements/common.txt`, `cuda.txt`, `rocm.txt`, `xpu.txt`, `cpu.txt` resolve, including `torch==2.14.0`, `triton`, `flashinfer-python`, `numba`, `xgrammar`, `tilelang`, `nvidia-cutlass-dsl`. Platform indexes: AMD's TheRock index has cp314 for the pinned torch/torchvision/torchaudio/triton; `vllm_xpu_kernels` is `cp38-abi3` and the XPU torch/`auto_round_lib` have cp314; IBM's ppc64le index has cp314 for torch, torchvision, numpy, pyarrow, xgrammar; UBI 9 AppStream ships `python3.14-devel`/`-pip` for s390x and ppc64le.
- **Test lock files** regenerated through the pinned pre-commit `pip-compile` hooks (uv 0.13.6). Changes are only what 3.14 needs: pydantic 2.14 / pydantic-core 2.50, numpy 2.4.6 (ROCm), stdlib backports `audioop-lts` and `standard-*` (XPU), and dropped `greenlet` / `torch-c-dlpack-ext` that only older Pythons pull in. XPU's resolution also moves pandas 3.0.5 -> 2.3.3.
- `pre-commit` passes, including `validate-docker-versions` (`docker/versions.json` regenerated).
- `therock_wheels.py`: `external-links` now takes `cp314` from `Dockerfile.rocm_base` and keeps `py3` wheels (checked directly).

## Details

**Changes.**

- Dockerfiles: `PYTHON_VERSION` default 3.12 -> 3.14 (`docker/versions.json` regenerated). How each gets Python: CUDA build stage from the manylinux image's `/opt/python/cp314-cp314`, runtime from deadsnakes; CPU and XPU via `uv venv --python`; ROCm bases via deadsnakes; s390x/ppc64le from UBI 9 packages.
- ROCm bases: install `python3.X-lib2to3` only below 3.13 (lib2to3 was removed in 3.13).
- s390x: drop the `python3.X-wheel` RPM, which UBI 9 doesn't have for 3.14; `pip install -U pip wheel uv` already installs it in the venv.
- `docker/build_vllm_ppc64le.sh`: takes `PYTHON_VERSION` (default 3.14) instead of hard-coded 3.12.
- `tools/vllm-rocm/therock_wheels.py`: link TheRock wheels for `Dockerfile.rocm_base`'s `PYTHON_VERSION` rather than `cp312`.
- CI: the nightly smoke step becomes `Python 3.12 Smoke` (`python-312-smoke-nightly`); the Mooncake disaggregation test's venv uses the image's `python3` instead of hard-coded 3.12; `check-ray-compatibility.sh` resolves for 3.14; macOS smoke test on 3.14.
- `.pre-commit-config.yaml`: CUDA, ROCm, XPU and CPU test locks compile for 3.14. The docs lock stays on 3.12, matching `.readthedocs.yaml`.
- `requirements/test/xpu.in`: `librosa >= 0.10`. Without it the 3.14 resolve backtracks into librosa 0.6.2, an sdist that imports the removed `imp` module and fails to build; it resolves to librosa 1.0.0 as before.
- Docs: quickstart, ROCm and XPU install pages and `AGENTS.md` recommend 3.14. ROCm's nightly (`rocm100`) wheels become 3.14-only, as they are built in the ROCm image. The XPU page's "Python 3.12 is a MUST" no longer applies: `vllm_xpu_kernels` is abi3.

**Blockers (why this is a draft).** The CUDA images install `requirements/kv_connectors.txt` (`INSTALL_KV_CONNECTORS=true` in the release pipeline), and these have no cp314 wheels on PyPI yet:

- `mooncake-transfer-engine` / `-cuda13` / `-rocm`: 3.14 wheels added in kvcache-ai/Mooncake#4783 and #4949; the `v0.3.14-pre` GitHub pre-releases already ship cp314 (not ROCm). Needs 0.3.14 on PyPI (also unblocks #61204 / #63965).
- `lmcache`: 3.14 support in LMCache/LMCache#5289; `0.5.7rc3` on PyPI has cp314. Needs 0.5.7 final; `kv_connectors_cu12.txt`'s `lmcache == 0.5.6` pin then needs a bump.

**Other risks to watch in CI.**

- ROCm base builds Triton, FlashAttention, AITER and MORI from source; untested on 3.14. Open: #51312 (torchao fix for 3.14 on ROCm). The AITER nightly wheel selection (`select_aiter_nightly_wheel.py`) follows the running Python, so needs cp314 AITER nightlies.
- TPU: `requirements/tpu.txt` pins `nixl==0.3.0`, which has no cp314 wheel (`nixl` 1.5.2 is `py3`).
- Source-only test dependencies (`arctic-inference`, `pytrec-eval-terrier` on aarch64) build from sdist as today; not yet built on 3.14.
- Interpreter performance and `torch.compile` behavior on 3.14 vs 3.12 still need an end-to-end serving comparison.

**Not changed:** tooling that only needs some Python (pre-commit workflow, CI helper workflows, wheel upload/nightly-index scripts, Rust frontend script runner, macOS wheel build), the 33 model recipes with `uv venv --python 3.12` (any supported version works), and example tracebacks in docs.
