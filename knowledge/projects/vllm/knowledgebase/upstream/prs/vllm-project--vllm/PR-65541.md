# [Rust][Benchmark] Align vllm-bench result files and requests with Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/65541) · state: open · merged: False

## Original PR description



## Overview

Align the Rust `vllm-bench` result files and request payloads with Python `vllm bench serve`, and stop sweeps and `--num-runs` from dropping or overwriting results. These are the remaining parity gaps that no open PR covers. With `VLLM_USE_RUST_BENCH=1`, `vllm bench serve` hands the same command line to the Rust client, so these differences reach downstream scripts and comparisons directly.

## Claims

**Result JSON and filenames** (now match `serve.py`):
- `model_id` is the resolved model. Before, it was `""` whenever `--model` was omitted. `tokenizer_id` now falls back to that model, as in Python.
- `date` uses Python's local `%Y%m%d-%H%M%S` instead of UTC ISO 8601, the same string that goes into the filename.
- `latencies` and `queue_times` are always written. The other per-request arrays, including pooling `input_lens`/`errors`, now need `--save-detailed`, as in Python.
- Client-side queue time (waiting for a `--max-concurrency` slot) is now tracked. The `client_queue_time` and `e2el_including_client_queue` percentile metrics are reported. Before, they were accepted but silently ignored.
- The default filename writes the rate the way Python's `str(float)` does: `10.0qps` instead of `10qps`.

**Sweeps and `--num-runs`** (Rust-only modes that lost results):
- `--append-result` is honored. Before, sweeps forced it off and wrote nothing.
- An explicit `--result-filename` gets a per-point suffix (`out-concurrency8.json`, `out-5.0qps.json`). Before, every point overwrote the same file.
- `--num-runs N --save-result` saves each run as `-run<i>`. Before, it saved nothing.

**Requests:**
- Completions send `repetition_penalty: 1.0`, as Python does.
- `openai-embeddings` and `openai-embeddings-chat` send `truncate_prompt_tokens: -1`, as Python does. The existing guard could never be true, so the field was never sent.
- Pooling latency stops after the response body is read, not when the headers arrive.

## Details

- **Behavior changes users may notice:**
  - `date` changes format.
  - Sweeps with `--result-filename` now write one file per point.
  - `openai-embeddings` against a non-vLLM provider now sends `truncate_prompt_tokens`, as the Python client already does. If we'd rather keep the Rust-only omission for third-party providers, it should apply to both clients.
- **Client queue time** is measured from the scheduled arrival (after the arrival-schedule sleep) to the send, matching Python's `start_time - request_arrival_time`. Without `--max-concurrency`, it is just the scheduling overhead (microseconds), as in Python.
- **Conflicts:** this touches the same lines as #64308 (`compute_result_filename`, `run_benchmark` result block) and #65284 (the request task in `run_benchmark`). If those land first, I'll rebase. The conflicts are mechanical.
- **Not a duplicate:** I searched open PRs for the Rust result JSON, `model_id`, `date`, `latencies`/`queue_times`, sweep `--append-result`/`--result-filename`, `--num-runs`, `repetition_penalty`, `truncate_prompt_tokens` and pooling latency. The only hits are Python-only (#58976, #59816, #59032) or #64308, which covers the ramp-up filename and fields only.
- **Out of scope:** the `reasoning_content` chunk rule follows #64937 once it lands; client-side chat templates and the HF dataset registry need a design discussion first.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Preserve the first send time across retries**

When a transient connection failure is retried and a later attempt succeeds, `output.start_time` contains the final attempt's timestamp because it is overwritten on every iteration at lines 1031-1038. Subtracting the original arrival here therefore labels the earlier failed attempts plus the 500/1000/1500 ms retry backoffs as semaphore queueing, and the successful sample then inflates `queue_times` and the aggregate client-queue percentiles; preserve the first send/semaphore-acquisition timestamp separately from the per-attempt timestamp.
