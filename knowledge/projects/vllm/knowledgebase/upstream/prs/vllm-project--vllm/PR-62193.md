# [Spec Decode] Batch invariance: speculative_config.batch_invariant lets the drafter skip batch-invariant MoE kernels

[Upstream PR](https://github.com/vllm-project/vllm/pull/62193) · state: open · merged: False

## Original PR description

## Overview

Under `VLLM_BATCH_INVARIANT=1`, `--speculative-config '{..., "batch_invariant": false}'` lets the speculative drafter select MoE kernels that are not batch invariant. The drafter only proposes tokens; the batch-invariant target verifies them and decides every output token and logprob. This lets speculative decoding use faster drafter kernels while batch invariance is kept for train-inference consistency (e.g. RL rollouts). Leaving the field unset (default `None`) keeps today's behavior; without `VLLM_BATCH_INVARIANT` the field has no effect.

Split out of #62017 by @aoshen02.

## Changes

The switch is a per-drafter config override, following the existing `moe_backend` / `attention_backend` / `kv_cache_dtype` drafter overrides:

- `SpeculativeConfig.batch_invariant: bool | None = None`, added to `_DRAFT_VLLM_CONFIG_OVERRIDES` so `apply_draft_overrides` maps it onto `KernelConfig.batch_invariant` (new, default `True`) of the draft `VllmConfig`.
- `FusedMoE` copies `kernel_config.batch_invariant` into `FusedMoEConfig.batch_invariant` (next to `moe_backend`), and `FusedMoEExperts.is_supported_config` rejects non-batch-invariant experts only when both `VLLM_BATCH_INVARIANT` and `moe_config.batch_invariant` are set. Other BI kernel selections (linear, attention, norms, routing) are unchanged.
- Drafters: EAGLE, MTP and multi-module MTP get the override through `load_eagle_model` -> `apply_draft_overrides`; `StandaloneARSpeculator` (`draft_model`) builds its own draft config and ignores all draft overrides except `kv_cache_dtype` (`moe_backend` and `attention_backend` are already ignored today), so it is left to a follow-up that routes it through `apply_draft_overrides`. The other model runner V2 drafters (DFlash/DFlash2/LiLiCorr, DSpark, Gemma4 MTP, extract-hidden-states) build no MoE layers, so they need nothing. Model runner V1 is not covered, since it is being removed.
- Test: `tests/v1/determinism/test_drafter_batch_invariance.py` drives `SpeculativeConfig.apply_draft_overrides` with the field unset / `True` / `False` and checks which configs may pick a non-batch-invariant experts class; it runs in the H100 batch invariance CI job.
- Documented in the "Speculative Decoding" section of `docs/features/batch_invariance.md`:

```bash
VLLM_BATCH_INVARIANT=1 vllm serve <model> \
    --speculative-config '{"method": "mtp", "num_speculative_tokens": 3, "batch_invariant": false}'
```

Trade-off (also in the docs): target tokens, logprobs and the output distribution are unchanged (lossless rejection sampling). With temperature > 0, which token a seeded request samples and the acceptance rate can depend on batch composition when the drafter is exempt.
