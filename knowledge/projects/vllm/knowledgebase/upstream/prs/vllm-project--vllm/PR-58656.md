# [Frontend][Spec Decode] Populate metrics.speculative_decoding on /v1/responses

[Upstream PR](https://github.com/vllm-project/vllm/pull/58656) · state: open · merged: False

## Overview

Populates `metrics.speculative_decoding` on `/v1/responses`, which `ResponsesResponse` already declares but never filled. Follows #48915 (per-request acceptance stats on chat and completions). Multi-turn responses report acceptance summed across turns.

## Claims

- With `--per-request-spec-decode-metrics summary|detailed`, `/v1/responses` now returns `metrics.speculative_decoding` (it was always `null`), non-streaming and streaming (on `response.completed` only), including gpt-oss (Harmony).
- Multi-turn responses (built-in tools, Harmony tool loops) report counts summed across all generation turns. On live gpt-oss runs they equal the engine's Prometheus counter deltas exactly.
- Shape change: multi-turn responses previously omitted `metrics`; they now return `metrics` with only `speculative_decoding` set. Timing stays omitted for multi-turn.

## Details

**Why summing across turns.** Each turn of a Responses request is a separate engine request with its own acceptance stats. Unlike timing (TTFT/ITL have no single meaning across tool round-trips, which is why timing is omitted for multi-turn), acceptance counts are additive: every verify step counts the same regardless of turn. Derived ratios are recomputed from the totals, consistent with how `usage` already accumulates tokens.

**Changes.**
- `RequestSpecDecodeMetrics.merge()` (`v1/metrics/stats.py`): sums the histogram and draft count, concatenates the per-step arrays, and asserts matching `num_spec_tokens`.
- `ConversationContext` accumulator (`responses/context.py`): `SimpleContext`, `ParsableContext` and `HarmonyContext` fold in the metrics from every turn's finished output. The first turn is copied, so the engine's per-turn object is never mutated.
- `responses_full_generator` (`responses/serving.py`) attaches the total. The streaming generator builds `response.completed` from the same function, so one site covers both.
- Docs: `acceptance_metrics.md` and `per_request_metrics.md` describe the Responses placement and multi-turn summing.

**Not a duplicate.** No other open PR populates spec-decode metrics on `/v1/responses` (searched open PRs for "speculative_decoding responses", "per-request spec decode responses", "responses metrics speculative", and `48915 in:body`). Two open PRs touch neighbouring code:
- #56914 adds per-request reasoning/content token metrics in the same Responses files; different fields, so only a textual conflict is possible.
- #56278 adds `histogram_by_draft_length` to `RequestSpecDecodeMetrics`. Whichever of the two lands second should extend `merge()` to sum it; happy to do that here if #56278 lands first.

Pairs with the AIPerf consume-side PR https://github.com/ai-dynamo/aiperf/pull/1465, which captures this payload on `/v1/responses`.
