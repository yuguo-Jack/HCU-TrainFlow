# [Build][CPU] Publish indexed Triton CPU wheel dependencies

[Upstream PR](https://github.com/vllm-project/vllm/pull/62608) · state: open · merged: False

## Original PR description



## Overview

CPU wheels expose Triton as a GitHub URL dependency, which uv rejects when resolving vLLM from an index and which prevents offline wheelhouse installation. Publish the same CPU Triton build as an indexed dependency and retain its exact version and platform conditions. Fixes #62322.

## Claims

- CPU wheel metadata uses `triton==3.8.0+cpu` with the original Python/architecture markers.
- The x86 CPU upload stages both supported Python wheels after verifying their SHA256 pins. Commit, nightly and release indices include the dependency; download or checksum failures stop publication.
- Installation docs select CPU Triton explicitly with `--find-links` when using `uv --torch-backend cpu`, and provide an offline wheelhouse workflow.

## Validation

```bash
.venv/bin/python -m pytest tests/tools/test_cpu_wheel_distribution.py -q
.venv/bin/python tests/standalone_tests/test_precompiled_wheel.py
.venv/bin/python -m pre_commit run --files setup.py requirements/cpu.txt .buildkite/scripts/stage-cpu-triton-wheels.sh .buildkite/scripts/upload-nightly-wheels.sh .buildkite/scripts/generate-nightly-index.py tests/standalone_tests/test_precompiled_wheel.py tests/tools/test_cpu_wheel_distribution.py .buildkite/test_areas/misc.yaml docs/getting_started/installation/cpu.x86.inc.md
```

11 distribution tests and 11 setup tests passed. All applicable hooks, including pip-compile-cpu, ShellCheck, mypy and Buildkite test tethering, passed. New tests run in the existing CPU suite.

Additional Linux x86_64/Python 3.12 validation used the actual `0.32.0+cpu` release wheel, changing only its Triton Requires-Dist entries to those generated by setup.py and regenerating RECORD. All 3306 other archive members were verified identical. Original wheel: named-index resolution fails on the transitive URL. Changed wheel with the documented options: 152 packages resolve, download and install into a fresh environment using `--offline --no-index --find-links`; `uv pip check` passes. Imports of installed vLLM/LLM/SamplingParams/native extension and real Triton CPU JIT vector addition passed. S3 writes were replayed locally; no production upload was performed.

## Details

Filtering official wheel indices by the vLLM version discards Triton's independent version, so the release filter must preserve CPU Triton just as it preserves the XPU shim. Uploading dependencies before the vLLM wheel prevents a failed download/checksum from exposing a new wheel without its dependency.

`--torch-backend cpu` also restricts Triton to the PyTorch index. Hosting the CPU build alone therefore does not fix the existing uv command; `--find-links` supplies CPU candidates while retaining `first-index` selection for vLLM and the CPU Torch backend. Ordinary `triton==3.8.0` was not substituted for the CPU artifact.

Duplicate checks found no open PR implementing #62322 or the CPU wheel dependency publication fix. This changes packaging and distribution, with no model-output or performance claim. Existing published wheels are not rewritten; the normal release pipeline must publish new wheels and indices after merging.
