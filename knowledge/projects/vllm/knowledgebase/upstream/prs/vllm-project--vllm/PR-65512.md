# [WIP][ROCm][Perf][DeepSeek-V4.1] Mega-attention prefill kernel for gfx942

[Upstream PR](https://github.com/vllm-project/vllm/pull/65512) · state: open · merged: False

## Original PR description

## Overview

Work in progress. Opened so people know this is being worked on.

Follow-up to #65146. It adds a CDNA3 (MI300X / MI325X, gfx942) kernel for the DeepSeek V4.1 fused mega-attention prefill. The #65146 kernel cannot simply be enabled on CDNA3: it stages 128 KiB of LDS (CDNA3 has 64 KiB) and uses gfx950-only instructions (`ds_read_tr16`, the scaled FP8 convert, the 16x16x32 BF16 MFMA). CDNA3 also stores attention as BF16 rather than MXFP8.

This branch is stacked on #65146. Only the last commit is new here.

- New `_rocm_C` op `fused_norm_rope_attn_rope_prefill_bf16`, in the same file as the #65146 kernels. It reuses their paged-cache lookup, top-k + SWA key spans and slot prefetch.
- Each of the four waves owns 128 of the 512 head dims for every key. The partial scores meet in LDS once per 32-key batch, and every wave then runs the same softmax and reuses its own dims for PV. The CTA uses 52 KiB of LDS.
- FP8 dequant uses the CDNA3 FNUZ convert. OCP bytes from the compressed cache are decoded as twice the FNUZ value, after clearing `0x80`.
- The store applies inverse RoPE and writes BF16 rows, so the standalone inverse-RoPE pass is skipped for prefill rows.
- Selection is `get_cdna_version() == 3`, with the same conditions as #65146. The #65146 gfx950 branch now uses `get_cdna_version() == 4`.
- The #65146 kernel body is now compiled for gfx950 only. As written it fails the gfx942 build: local memory 135680 exceeds the 65536 limit.
