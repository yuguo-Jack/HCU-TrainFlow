# [Bugfix][Frontend] Report max_model_len for LoRA adapters in /v1/models

[Upstream PR](https://github.com/vllm-project/vllm/pull/62730) · state: open · merged: False

## Original PR description



## Overview

`/v1/models` returns `max_model_len` for the base model but `null` for every LoRA adapter. An adapter runs on the base model with the same context length, so a client that reads `max_model_len` from the card of the model it calls (to size prompts or `max_tokens`) gets nothing for adapters. This PR sets the adapter cards' `max_model_len` to the base model's value.

## Claims

- Each LoRA card in `/v1/models` now has the same `max_model_len` as the base model card.
- The other card fields are unchanged.

## Validation

- New test `test_show_available_models_lora_card_has_max_model_len` in `tests/entrypoints/serve/lora/test_serving_models.py` registers one adapter at startup (`lora_modules`) and loads one at runtime, then checks `max_model_len` on all three cards. On main both adapter cards have `None`.
- `pytest tests/entrypoints/serve/lora/test_serving_models.py`: 12 passed on this branch; on main the new test fails and the other 11 pass.
- `pre-commit run --files` on the changed files passes.

## Details

`OpenAIModelRegistry.show_available_models()` builds the base cards with `max_model_len=self.model_config.max_model_len`, and `OpenAIServingModels.show_available_models()` then appends the LoRA cards without it. The fix passes the same value to every card built from `lora_requests`, which holds startup, runtime and resolver-loaded adapters alike.
