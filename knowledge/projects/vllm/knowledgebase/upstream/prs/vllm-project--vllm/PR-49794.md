## Original PR description

# Add `/v1/responses/input_tokens` endpoint for preflight token counting

**Resolves:** #49533

## Purpose

This PR introduces support for the OpenAI-compatible endpoint:

`POST /v1/responses/input_tokens`

The endpoint enables clients to perform **preflight token counting** for Responses API requests without executing model inference. This is particularly useful for AI gateways and orchestration frameworks that need to estimate request costs or validate token limits before sending a generation request.

Previously, clients attempting to use this endpoint with vLLM would receive a `405 Method Not Allowed` response. This implementation adds compatibility while avoiding any unnecessary inference overhead.

### Implementation Details

* Added the `/v1/responses/input_tokens` endpoint to the Responses API.
* Introduced `ResponsesCountTokensRequest`, which inherits from `ResponsesRequest`.

  * Clients can reuse the exact same request payload they would send for generation.
  * Inference-related fields (`temperature`, `stream`, `max_output_tokens`, etc.) are accepted without requiring clients to modify their requests.
* Reused the existing request preprocessing pipeline (`_make_request` and `_make_request_with_harmony`) to ensure token counting matches the exact prompt that would be used during inference.
* Supports all existing prompt preprocessing features, including:

  * Chat templates
  * Tool definitions
  * Conversation history via `previous_response_id`
* Bypasses model generation entirely, making the endpoint lightweight and fast.

## Test Plan

### Unit Test

Added:

`tests/entrypoints/openai/responses/test_count_tokens.py`

Run with:

```bash
uv run pytest tests/entrypoints/openai/responses/test_count_tokens.py -v
```

The test mocks the engine client and verifies that the endpoint correctly aggregates the total number of prompt tokens across multiple engine inputs.

### Manual Testing

Start the server and invoke the endpoint:

```bash
curl -X POST http://localhost:8000/v1/responses/input_tokens \
  -H "Content-Type: application/json" \
  -d '{
        "model": "test-model",
        "input": "Hello world, this is a test!"
      }'
```

## Test Results

* ✅ Unit test passes successfully.
* ✅ Endpoint returns `200 OK`.
* ✅ Response contains the expected `input_tokens` count.
* ✅ No generation request is executed and no GPU inference is performed.

Example response:

```json
{
  "input_tokens": 6
}
```
