# [Recipe] Add Qwen recipes with IAXL KVShrink support

[Upstream PR](https://github.com/vllm-project/vllm/pull/65687) · state: open · merged: False

## Original PR description

Add Qwen2.5-72B-Instruct with BF16 and TP=2 defaults, and enable the IAXL KVShrink option. Include the verified IAXL opt-in for Qwen3-8B on Intel Xeon 6.



## Overview

Adds a `Qwen/Qwen2.5-72B-Instruct` recipe and enables the IAXL KVShrink KV Offload option (added in vllm-project/recipes#1191) for it and for `Qwen/Qwen3-8B`.

## Claims

- New Qwen2.5-72B-Instruct recipe: BF16, TP=2, Hermes tool calling; 131K context via opt-in YaRN (not tested).
- `meta.hardware.b200: verified` and `kv_offload_support: { iaxl: verified }` for Qwen2.5-72B-Instruct.
- `kv_offload_support: { iaxl: verified }` for Qwen3-8B on Intel Xeon 6.

## Validation

- **Qwen3-8B, Xeon 6:** vLLM 0.32.0 (CPU wheel, torch 2.13.0+cpu) and intel-accel-for-llm `28f2d3e` (DEVICE=cpu, in-tree QAT, `POLICY=0`). The page's install and serve blocks were run as copied in a fresh Ubuntu 24.04 container. vLLM loads `KVShrinkConnector`, a repeated 1209-token prompt reuses 1152 tokens from the KVShrink store, and the reasoning parser and Hermes tool calling work.
- **Qwen2.5-72B-Instruct, B200:** <N>x B200, TP=2, vLLM <version> (torch <version>), on a <Xeon model> host with <n> QAT devices.
  - Baseline: `/health`, `/v1/models`, a chat completion with `finish_reason: stop`, and a Hermes tool call.
  - IAXL (DEVICE=cuda, `IAXL_DSA_GD_ENABLE=0`): `KVShrinkConnector` loads, a repeated <n>-token prompt reuses <n> tokens, and chat and tool calling work.
- **Recipes PR check:** `node scripts/validate-source.mjs --source vllm --dir <vllm>/recipes` passes against vllm-project/recipes main.

## Details

`kv_offload_support.iaxl` applies to the whole recipe, so IAXL is also offered for Qwen2.5-72B-Instruct on other NVIDIA GPUs with a Xeon host. Grace- and Vera-based nodes are excluded by the taxonomy. IAXL needs at least `TP_SIZE` QAT devices by default. The option's description covers switching to IAA or setting `KVSHRINK_QAT_DEVICES`. CI has no QAT hardware, so validation was run outside CI.
