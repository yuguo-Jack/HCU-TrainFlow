# [Core] Declare EAGLE cache-peek capability for KV cache managers

[Upstream PR](https://github.com/vllm-project/vllm/pull/51351) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Declare which KV cache managers can safely peek past an EAGLE/MTP candidate boundary and then drop back. Resolve eligible groups consistently across core, Mooncake store, and offloading while preserving the current upstream grouping and offloading policies.

Update contribution documentation and the PR template.

Fixes #50630. This updates the existing PR #51351; no second PR is being opened for the same work.

## Claims

- Exclude managers that cannot rewind their cached state from the core and Mooncake fallback; reject unsupported explicit EAGLE annotations when cache-peek selection is active.
- Respect role-specific managers and wrapped uniform specs.
- Preserve `drop_eagle_group_ids`, current proof-margin calculations, and offloading's explicit-draft-group policy.

## Details

The old fallback could grant a peek to every group, although only managers capable of dropping the extra matched cache unit can safely use it. The capability defaults to false; full attention and sliding window opt in, while circular-window and recurrent managers remain excluded. The shared resolver uses the same role-specific manager selection as the callers.

Offloading intentionally disables fallback selection because upstream now relies on explicit draft annotations. Mooncake keeps `StoreSpecGroup` and groups by both spec and manager. No dependencies, GPU synchronization, or public serving options are added.
