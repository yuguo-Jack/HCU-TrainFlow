# [Bugfix] Reserve construction-time scratch across workspace slots

[Upstream PR](https://github.com/vllm-project/vllm/pull/61584) · state: open · merged: False

## Original PR description

## Overview

Reserve construction-time attention scratch in every workspace microbatch/lane slot, so a path first reached after warmup does not try to grow a locked workspace. Addresses the workspace-reservation portion of #61487; HiSparse + DBO state isolation remains separate work.

## Claims

- Construction reservations cover all configured execution slots, including slots not exercised during warmup.
- Runtime requests retain slot-local growth, independent storage, and the existing lock contract.
- Reservations retain no tensor views and use the existing allocation context.

## Validation

Tested on WSL with an RTX 3050 8 GiB, Python 3.12, and an editable precompiled install, based on main at `ec8a372566`.

| Check | Result |
| --- | --- |
| Real FlashInfer/TRTLLM prefill-constructor regressions on unmodified production code | Both fail with the locked-workspace allocation error |
| Workspace, microbatch runner, and prefill registry suites with the patch | 67 passed; ROCm AITER module skipped on NVIDIA |
| All applicable pre-commit checks, including Ruff, mypy, and CI test wiring | Passed |

```bash
.venv/bin/python -m pytest \
  tests/v1/worker/test_workspace.py \
  tests/v1/worker/test_gpu_ubatch_slicing.py \
  tests/v1/attention/test_mla_prefill_registry.py \
  tests/v1/attention/test_rocm_aiter_mla_mtp_split.py -q
```

Coverage includes CPU/CUDA slot isolation, simultaneous-view alignment, locked capacity, peer-storage stability during runtime growth, CUDA graph capture/replay, and real prefill constructor reservations. No full-model multi-GPU serving or ROCm kernel validation was performed; this PR does not claim that the original HiSparse serving repro is fixed.

## Details

Constructors run in microbatch 0, so their previous `get_simultaneous` calls only sized that slot. Other slots could subsequently request the same scratch after locking and fail. `WorkspaceManager.reserve` sizes each slot with the same per-tensor alignment as runtime allocation. Construction call sites use this API; forward calls continue to use `get_simultaneous`, avoiding replacement of storage another microbatch may still be using.

This allocates required scratch for every configured slot before profiling, so memory accounting includes slots that warmup misses. Single-slot configurations retain the same capacity. The API is intended for construction before execution or graph capture, when no slot holds scratch views.

Updated reservations cover FlashMLA sparse, Triton MLA, AITER MLA, TurboQuant, FlashInfer/TRTLLM prefill, B12x, and Dots3Note. HiSparse staging from #60424 is not in this base and should adopt the API when integrated.

Duplicate checks found no open PR implementing construction-time reservations across all slots. Related #60734 addresses shared DSA top-k state; #48179 sizes MoE scratch. Neither implements this fix. The separate HiSparse state-sharing and zero-row-write problems described in #61487 remain unresolved by this PR.
