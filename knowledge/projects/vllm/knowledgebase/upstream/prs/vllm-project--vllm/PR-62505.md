# [Bugfix][Multimodal] Retain OpenCV streams until capture release

[Upstream PR](https://github.com/vllm-project/vllm/pull/62505) · state: open · merged: False

## Original PR description

## Overview

Keep buffered video streams alive until OpenCV releases their captures, and release captures when decoding or metadata extraction raises.

## Claims

- Fix the borrowed `BytesIO` lifetime in `open_video_capture`.
- Release metadata, frame-decoding and demux captures on exceptional exits.

## Validation

Rebased onto `1ca0dfb9` on Oct 29. All five focused CPU regressions passed again, along with applicable changed-file pre-commit checks. The earlier broader run on `14d5931` had 92 passed, 18 skipped and 3 deselected.

Five new cases cover decoded-frame parity, stream survival across `gc.collect()`, metadata/sampling/read exceptions and failed-open cleanup. The command below was used for that earlier broader CPU run:

```bash
VLLM_TARGET_DEVICE=cpu VLLM_PLUGINS='' .venv/bin/python -m pytest \
  tests/multimodal/test_video.py --confcutdir=tests/multimodal -q \
  -k 'not backend_samples_reference_frames and not comparison and not corrupted'
```

Python 3.12.15, CPU torch 2.14.1, OpenCV 5.0.0.93, Linux x86_64. Applicable pre-commit hooks passed, including mypy and CI test tethering. These checks cover decoder lifetime, pixels and metadata; no model or GPU serving test was run.

## Details

OpenCV borrows the Python stream. Previously, `open_video_capture` passed a temporary `BytesIO(data)` and returned the capture without retaining that stream; a minimal probe reproduced a native crash.

The helper is now a context manager, and its callers keep the stream alive through `release()`. A private metadata helper preserves the existing metadata logic. Backend selection, sampling and pixel values are unchanged.

AI-assisted implementation and validation; reviewed by the submitter.
