# [Bugfix][Multimodal] Retain OpenCV streams until capture release

[Upstream PR](https://github.com/vllm-project/vllm/pull/62505) · state: open · merged: False

## Original PR description



## Overview

Keep Python video streams alive until OpenCV has released the associated capture, and release captures when decoding or metadata extraction raises.

## Claims

- Keep the borrowed `BytesIO` alive throughout buffered OpenCV reads and `release()`.
- Close both metadata and frame-decoding captures on successful and exceptional exits; also release demux captures when `grab()` raises.
- Preserve the existing backend selection, sampling, recovery and pixel values. No throughput claim.

## Validation

## Details

`open_video_capture` previously passed an unreferenced `BytesIO(data)` temporary to OpenCV and returned the native capture. OpenCV's Python stream binding borrows that object. The demux path already documented the lifetime requirement, but the regular capture path did not retain the stream. A native crash was observed in a minimal local probe; this patch addresses the dangling stream and deterministic cleanup rather than changing codecs or adding a temporary-file fallback.

The helper is now a context manager; all its in-tree callers keep it open until their work finishes. A private metadata helper keeps the existing metadata algorithm unchanged inside this ownership boundary. The downstream C550 compatibility workaround used a temporary file; this port preserves upstream's buffered stream API instead.

Duplicate search on 2026-10-20: open PRs for `opencv BytesIO`, `opencv stream`, and `opencv fallback`. #47853 concerns interlaced pixel conversion, #57717 sampling-FPS bounds, and #45545 Kimi chunk splitting; none retains buffered streams through capture release.
