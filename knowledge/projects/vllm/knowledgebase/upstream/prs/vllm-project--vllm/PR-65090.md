# [Bugfix][MCP] Keep first server's tools on duplicate server name

[Upstream PR](https://github.com/vllm-project/vllm/pull/65090) · state: open · merged: False

## Original PR description

Fixes #65073

`add_tool_server()` warns about a duplicate server name but still overwrote the advertised tool descriptions with the second server's tools, while requests kept routing to the first server's URL (the `urls` dict is first-wins). The model then advertises tools from server two while calls go to server one.

Check for the duplicate name before writing the description table, so the advertised tools always match the URL that serves them.

**Test plan**: added `test_add_tool_server_duplicate_name_keeps_first_server` in `tests/entrypoints/openai/responses/test_mcp_tools.py`; the whole `TestMCPToolServerUnit` class passes locally (5 passed).
