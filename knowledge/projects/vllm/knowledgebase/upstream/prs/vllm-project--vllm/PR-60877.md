# [Frontend] Score with the chat template declared by Sentence Transformers CrossEncoders

[Upstream PR](https://github.com/vllm-project/vllm/pull/60877) · state: closed · merged: True

## Original PR description



## Overview

Score Sentence Transformers (v5.4+) CrossEncoders with the chat template they declare, so they work without `--chat-template`. 

This closes #60409, follow-up to #31563, and is complementary to #55359 (see Details).

## Claims

- A CrossEncoder whose single `sequence-classification` Transformer module declares the `message` modality in `sentence_bert_config.json` is now scored like in Sentence Transformers: `query`/`document` messages rendered with the saved chat template (the default one, or the named template from `processing_kwargs.chat_template.chat_template`).
- The other `processing_kwargs.chat_template` settings (e.g. `add_generation_prompt`) are passed to the template, like in Sentence Transformers; request `chat_template_kwargs` override them.
- `--chat-template` (or `LLM.score(chat_template=...)`) still takes precedence, and an invalid Sentence Transformers config then doesn't block startup. Checkpoints without this metadata, and models with a built-in score template (`SupportsScoreTemplate`), are unchanged.
- The template is resolved once at startup and logged. A declared template that the checkpoint doesn't have (including an unknown name) fails at startup, instead of silently falling back to pair encoding or to vLLM's fallback templates.

## Validation

- MTEB (NFCorpus, RTX 4080 SUPER): `nvidia/llama-nemotron-rerank-vl-1b-v2` without `--chat-template` scores 0.33922 (bf16) vs 0.33919 for Sentence Transformers 5.7.0 (fp32). Without this change: 0.30173, the test fails.
  `pytest tests/models/language/pooling_mteb_test/test_nemotron.py -k rerank`
- Online, with a tiny random Qwen3 CrossEncoder saved in the Sentence Transformers format: `vllm serve <tiny checkpoint> --runner pooling`, then `/rerank` and `/score` return the same scores as Sentence Transformers (0.51295, 0.519637), and `chat_template_kwargs: {"add_generation_prompt": false}` overrides the saved setting.
- Unit tests: `pytest tests/transformers_utils/test_config.py -k sentence_transformers tests/entrypoints/pooling/scoring/test_io_processor_unit.py tests/entrypoints/pooling/test_io_processor.py`
- `pre-commit run` passes.
- Real-world checkpoint with this layout: `nvidia/llama-nemotron-rerank-vl-1b-v2` (its `chat_template.jinja` was synced with vLLM in its commit "Share reranking chat template across Sentence Transformers and vLLM"). `test_reranker` in `tests/models/multimodal/pooling/test_llama_nemotron_vl.py` now runs without `chat_template` and still matches the HF reference on text and image documents (RTX 4080 SUPER, fp16). Without this change it fails (first text pair: HF 0.3191, vLLM 0.0575).
  `pytest tests/models/multimodal/pooling/test_llama_nemotron_vl.py -k test_reranker`
- On that model, the automatic path produces the same token IDs (BOS included) and scores as `--chat-template examples/pooling/score/template/nemotron-vl-rerank.jinja`.

## Details

- Detection is limited to the exact layout Sentence Transformers uses for sequence-classification CrossEncoders (`model_type: CrossEncoder`, one Transformer module at the root, `transformer_task: sequence-classification`, `message` in `modality_config`). Many rerankers inherit an unrelated chat template from their base LLM, so the tokenizer template is still never used without this explicit declaration, as discussed in #31563.
- The nemotron-rerank-vl reranker test and docs no longer pass `--chat-template` (separate commit).
- Message contents are passed as strings, like with `--chat-template`, so multimodal placeholders keep working.
- The templated prompt is tokenized as with `--chat-template` (default `add_special_tokens`). Plain transformers tokenizers render Sentence Transformers prompts with `add_special_tokens=False`, but custom processors may not: `nvidia/llama-nemotron-rerank-vl-1b-v2`'s processor tokenizes its prompts with the default and adds BOS. Keeping vLLM's existing behavior matches the only checkpoint with this layout I found (verified above); for Qwen3-based rerankers (no BOS) both are identical.
- `restore_suffix` (restoring the template suffix after truncation) is not implemented; the startup log and the docs say to use `max_tokens_per_doc` to truncate documents.
- The config is read in `CrossEncoderIOProcessor` rather than `ModelConfig`, since only scoring uses it and this avoids touching `ModelConfig` and its hash. If #55359 lands first, this can move next to its `sentence_transformers_config`.
- `LLM(chat_template=...)` is still not used by `LLM.score` (unchanged); the saved template applies there, and `LLM.score(chat_template=...)` overrides it.
- Relation to #55359: it handles the modular `Transformer -> Pooling -> Dense` and `Transformer -> LogitScore` layouts and leaves single-module checkpoints unchanged, so the two PRs do not overlap functionally. I kept the same module-type constant and setting names so they can be merged in either order; whichever lands second can reuse the other's helpers (e.g. its `restore_suffix` implementation).
- `nvidia/llama-nemotron-rerank-vl-1b-v2` revisions between its Sentence Transformers integration (April 2026) and b8a9987 (October 2026) declare the `message` modality but only ship the Llama 3 chat template inherited from the base model. Without `--chat-template`, those revisions were already scored without the right prompt; they still need the flag, as the docs now say.
- Motivation: `polaria-tech/zerank-2-reranker-vllm` (zerank-2 converted to `Qwen3ForSequenceClassification`, template added in #60415) can declare its score template this way instead of requiring `--chat-template`.
