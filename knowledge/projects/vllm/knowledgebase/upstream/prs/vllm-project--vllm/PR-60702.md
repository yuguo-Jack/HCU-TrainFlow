# [Bugfix][Benchmark] Support boolean sweep plot filters for equality comparisons (#60629)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60702) · state: closed · merged: False

## Original PR description

### Purpose
Fixes #60629.

### Background & Problem
When using `vllm bench sweep plot --filter-by <col>==true` (e.g. `enable_prefix_caching==true`), `PlotEqualTo` and `PlotNotEqualTo` attempted to cast target values to `float`. For boolean expressions (`"true"`/`"false"`), `float()` raises `ValueError`, leaving the target as a string.

Because loaded DataFrames represent boolean settings with boolean dtypes (`bool` or `boolean`), comparing boolean Series values against string literals (`bool == "true"`) always evaluates to `False`. As a result:
- `==true` drops all rows.
- `!=true` retains both enabled and disabled rows.

### Proposed Changes
1. Added `_resolve_target` helper to `PlotFilterBase`:
   - Checks if the target is boolean-like (`"true"` or `"false"`, case-insensitive).
   - If the column is boolean-valued (`is_bool_dtype` or contains booleans), parses the target as a Python `bool` (`True`/`False`).
   - For string columns with boolean-like text labels, preserves the string type to support literal matches.
   - Retains existing numeric/float/inf conversion and string fallback behaviors.
2. Updated `PlotEqualTo` and `PlotNotEqualTo` to resolve target values before filtering.
3. Added unit tests in `tests/benchmarks/test_plot_filters.py` covering boolean equality, inequality, case variations, nullable boolean Series, and string literal preservation.
