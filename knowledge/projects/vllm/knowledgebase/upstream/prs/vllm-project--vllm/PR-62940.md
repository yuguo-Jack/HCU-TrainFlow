# [Perf] Bypass DispatchPooler grouping for homogeneous tasks

[Upstream PR](https://github.com/vllm-project/vllm/pull/62940) · state: closed · merged: True

## Original PR description




## Overview
When all requests use the same pooling task, `DispatchPooler` still slices metadata and hidden states, calls the sub-pooler, and converts its dense output into individual row tensors. Bypass grouping for homogeneous tasks and return the sub-pooler's output directly, allowing MRv2's existing dense output path to issue one D2H copy for a fully finished batch.


## Claims
- Improve short-query embedding throughput by **3.8% at concurrency 64** and **10.3% at concurrency 128** on the GH200 workload below. The gain comes from doing less CPU work per request on the EngineCore busy loop, which is the bottleneck in this scenario: one batched device-to-host copy per step instead of one copy, one pinned-memory allocation and one pinned free (with their CUDA event bookkeeping) per request.
- Avoid redundant pooling metadata operations and per-row D2H copies when the sub-pooler returns a dense batch. Ragged outputs and the mixed-task fallback remain supported.


## Validation


### Benchmark

Embedding throughput for short text queries on one NVIDIA GH200 (144 GB). Each row is the mean of 2 server starts with 2 runs of 30 s each.

- **Model:** `nvidia/Nemotron-3-Embed-1B-BF16` with online FP8 (`--quantization fp8_per_tensor`).
- **Data:** ViDoRe v3 finance (English) queries (mean length 31 tokens).
- **Server:** `--api-server-count 16 --max-num-batched-tokens 65536`, V2 model runner, `orjson` present.
- **Client:** concurrent `/v1/embeddings` requests from 8 client processes on a separate NUMA node.

| Concurrency | Metric | main | This PR | Change |
|---|---|---|---|---|
| 64 | Throughput (req/s) | 4082 | 4236 | **+3.8%** |
| 64 | Latency p50 (ms) | 15.7 | 15.1 | −3.8% |
| 64 | Latency p99 (ms) | 16.5 | 16.1 | −2.0% |
| 128 | Throughput (req/s) | 6044 | 6665 | **+10.3%** |
| 128 | Latency p50 (ms) | 21.2 | 19.2 | −9.5% |
| 128 | Latency p99 (ms) | 22.6 | 21.6 | −4.3% |

Embeddings match main within its run-to-run variation: the minimum cosine similarity over 512 queries is **0.9996**, the same as the comparison between two main runs.

## Details
The implementation adds a homogeneous-task check before the existing grouping loop. Returning the sub-pooler's output unchanged preserves dense tensors instead of splitting them into Python row objects. Sub-poolers can still return ragged lists, including for requests with different embedding dimensions or token counts. Mixed tasks, empty batches, and unsupported tasks retain the existing fallback behavior.

Frontend pooling multi-task support was deprecated in #37956 and removed in #37861. Instances select one pooling task through `PoolerConfig(task=...)`, making homogeneous batches the normal frontend path even when a model supports multiple selectable tasks.
