# [Frontend] --api-key: authenticate all routes except a liveness allowlist

[Upstream PR](https://github.com/vllm-project/vllm/pull/59892) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`--api-key` guards only `/v1`, `/v2`, `/inference` and `/cohere`; `/invocations`, `/tokenize`, `/metrics` and the docs answer without a key. This PR makes the middleware deny by default: every path needs the key except a liveness allowlist (`/health`, `/ping`, `/load`, `/version`).

Replaces #58028 (closed when my fork was re-created; same commits, rebased). Removes the limitation documented in the `--api-key` help and `usage/security.md`.

## Claims

- With `--api-key`, every route needs the bearer token except `UNGUARDED_PATHS`. Routes added later are guarded by default.
- The allowlist ignores a trailing slash, so a probe on `/health/` still works.
- Only real CORS preflights (`OPTIONS` + `Origin` + `Access-Control-Request-Method`) skip the token check. A bare `OPTIONS /metrics` no longer returns the metrics.

**Breaking change for `--api-key` users:** `/metrics` now needs the key (a scraper without it needs a separate listener), and unauthenticated `/server_info`, `/docs`, `/openapi.json` get 401.

## Validation

`tests/entrypoints/serve/middleware/test_authentication_middleware.py`, on this branch rebased onto `main`: **28 passed**. Added or changed:

- The two route auto-discovery tests now select routes by `UNGUARDED_PATHS`.
- Trailing slash: every allowlisted path with `/` passes without a token; `/v1/models/` stays guarded.
- Preflight, on an app with the server's middleware order and a mount answering any method: bare `OPTIONS` → 401; `OPTIONS` with ACRM but no `Origin` → 401; real preflight → 200 with no mount data. The first two fail without commit 3.

Auth matrix with a real `prometheus_client` ASGI app mounted as vLLM mounts it. "Before" is v0.29.0; `LEAK` = metrics body returned without a key:

| request | before, no key | after, no key | after, key |
|---|---|---|---|
| `GET /health` | 200 | 200 | 200 |
| `GET /v1/models` | 401 | 401 | 200 |
| `POST /tokenize` | 200 | 401 | 200 |
| `GET /metrics` | 200 LEAK | 401 | 200 |
| `OPTIONS /metrics` (bare) | 200 LEAK | 401 | 200 |
| `OPTIONS /metrics` (ACRM, no Origin) | 200 LEAK | 401 | 200 |
| `OPTIONS /metrics` (real preflight) | 200 | 200 | 200 |

`pre-commit` passes.

## Details

Three commits:

1. **Deny by default.** Middleware, `--api-key` help text, and the two auto-discovery tests.
2. **Trailing slash.** The middleware runs before the router, so `/health/` never reaches FastAPI's `redirect_slashes` and would get 401.
3. **CORS preflights only.** The old middleware skipped every `OPTIONS`, which was safe while `/metrics` was open anyway. Under deny-by-default it is not: `/metrics` is a mounted Prometheus ASGI app that returns the exposition for any method. The preflight test is the one Starlette's `CORSMiddleware` uses; both headers are needed because `AuthenticationMiddleware` runs before `CORSMiddleware`, which passes `Origin`-less requests through to the app. Browsers send no credentials on a preflight, so preflights keep working.

**Not done: Rust parity.** `rust/src/server/src/middleware/auth.rs` keeps its own `GUARDED_PREFIXES` and says it mirrors the Python middleware. I cannot build or test the Rust server here; I can add it here or in a follow-up.

**Maintainer decision needed:** whether deny-by-default (and `/metrics` behind the key) is the behavior you want for `--api-key`, versus extending the prefix list.
