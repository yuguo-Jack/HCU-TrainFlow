# [Bugfix][Qwen4Exp] Pin the offloaded PLE table at its exact size

[Upstream PR](https://github.com/vllm-project/vllm/pull/59848) · state: open · merged: False

## Original PR description



## Overview

`pin_memory=True` rounds the offloaded PLE table up to a power of two. Register it at its exact size instead.

## Claims

- 47.7 GiB per-rank table: 65.2 → 47.8 GiB host memory (GB10).
- TP2 Qwen4Exp on 2× DGX Spark now boots at `--gpu-memory-utilization 0.78` (OOM before).
- ROCm/XPU unchanged.

## Validation

- `pytest tests/models/qwen4_exp/test_ple.py` on GB10, rebased on d5e62627a: 113 passed → 115 passed (2 new), 2 skipped on both. The CI step now runs the whole file, so no CI config change. The packed NVFP4 tables from #56273 also go through this path; their tests pass.
- E2E: `Blackfrost-AI/CYBER-FROST-3.8-NVFP4`, TP2 across two GB10s, default `cpu_offload`. Before: OOM in memory profiling. After: serves, KV cache 491k tokens. Greedy outputs vs table-on-device are within run-to-run noise.

## Details

- Anonymous mmap + `cudaHostRegister`, unregistered by a finalizer after the last view. This is the DSv4.1 THP helper's pattern. A failed registration falls back to `pin_memory=True`.
- `pin_tensor` doesn't fit: it never unregisters and can't fall back.
- torch's `pinned_max_round_threshold_mb` is unsafe on 2.13.0 (pytorch/pytorch#192722). `pinned_max_cached_size_mb` disables caching of all large pinned blocks process-wide.
- Not a duplicate: #58185/#56413 fix UVA weight offload, not this table. DSv4.1's tables: #59849. #60909 adds a generic exact-size helper and leaves this table out on purpose; this can switch to it if that lands first.
