# [Bugfix] Keep the HiSparse FlashInfer all-reduce backend on lazy workspace creation

[Upstream PR](https://github.com/vllm-project/vllm/pull/65522) · state: open · merged: False

## Original PR description

## Overview

#65201 forces the `trtllm` FlashInfer all-reduce backend under HiSparse to avoid the MNNVL fused AR+RMSNorm race (#64327). The override was skipped when the shared workspace was created lazily outside the vLLM config context. HiSparse servers then still came up on `mnnvl` and crashed with `CUDA error: unspecified launch failure`. Related: #56699.

## Claims

- HiSparse servers on main now get the `trtllm` all-reduce workspace without needing `VLLM_FLASHINFER_ALLREDUCE_BACKEND`.
- Fixes the `unspecified launch failure` at `state.event.synchronize()` in HiSparse `_finish_mirror_phase` under multi-turn agentic load.

## Validation

Hardware: 4×B200, TP4. `RedHatAI/GLM-5.3-NVFP4` @ `c8917e42`, V2 model runner.

```bash
VLLM_USE_V2_MODEL_RUNNER=1 vllm serve RedHatAI/GLM-5.3-NVFP4 --revision c8917e4258572c405575855ff53effe58c17a38e \
  --trust-remote-code -tp 4 --kv-cache-dtype fp8_ds_mla --block-size 64 \
  --max-model-len 98304 --max-num-batched-tokens 16384 \
  --attention-config '{"hisparse_config":{}}' \
  --kv-transfer-config '{"kv_connector":"HiSparseConnector","kv_role":"kv_both","kv_connector_extra_config":{"host_pool_gib":160}}'

evalscope perf --url http://127.0.0.1:8000/v1/chat/completions --api openai --model <served> \
  --dataset swe_smith --multi-turn --parallel 32 --number 64 \
  --max-tokens 220 --min-tokens 220 --extra-args '{"ignore_eos": true}' --stream --seed 0
```

| tree | workspace backend | result |
|---|---|---|
| main (5 runs) | `mnnvl` | crash every run, ~2.5 min in, at the first pure-decode step (~75% host pool) |
| main + `VLLM_FLASHINFER_ALLREDUCE_BACKEND=trtllm` | `trtllm` | 832/832 turns succeeded, no CUDA errors |
| this PR (2 runs) | `trtllm` | 832/832 turns succeeded in each run, no CUDA errors, host pool peaked at 84% |

Unit test: `pytest tests/distributed/test_flashinfer_all_reduce.py` passes. The new test fails on main.

## Details

`FlashInferAllReduce.__init__` resolves its backend while the config is current, which yields `trtllm` under HiSparse. It then called `_resolve_fi_ar_backend` again when it created the global workspace on the first all-reduce. With the V2 runner, that first all-reduce happens in `_profile_cudagraph_memory` → `capture_model(profile_only=True)`, which runs outside `set_current_vllm_config`. `get_current_vllm_config_or_none()` returns `None` there, so the HiSparse guard is skipped and `mnnvl` is auto-selected. The workspace is a process-wide singleton, so the fused AR+RMSNorm ops reuse the `mnnvl` workspace. Instrumentation confirmed `config is None` at workspace creation, with that stack.

The fix passes the backend resolved at init into `get_fi_ar_workspace`. The fusion pass already resolves within the config context and is unchanged.

The HiSparse guard can be dropped once FlashInfer ships flashinfer-ai/flashinfer#7782; this fix goes with it.
