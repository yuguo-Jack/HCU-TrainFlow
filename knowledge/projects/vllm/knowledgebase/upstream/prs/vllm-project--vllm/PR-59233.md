# [Bugfix] Batch-invariant mode: disable CUDA WNA16 MoE kernel (56887)

[Upstream PR](https://github.com/vllm-project/vllm/pull/59233) · state: open · merged: False

## Original PR description

Supersedes #59199.
Fixes #56887.

## Problem

`VLLM_BATCH_INVARIANT` requests invariant execution, but W4A16 MoE dispatch can still select `moe_wna16_gemm`, whose split-K partial sums are accumulated through FP16/BF16 `atomicAdd`. Because the order of CUDA block completion is not fixed, the reduction can produce different output bits between otherwise identical executions.

## Fix

When `VLLM_BATCH_INVARIANT=True`, `should_moe_wna16_use_cuda()` no longer selects the WNA16 CUDA kernel. Execution falls through to the existing Triton WNA16 path. Default behavior is unchanged when batch-invariant mode is disabled.

## Regression test

The test verifies:
- CUDA WNA16 remains eligible in normal mode.
- CUDA WNA16 is disabled when `VLLM_BATCH_INVARIANT=True`.
- CUDA platform detection is monkeypatched so the dispatch test is machine-independent.

## Scope

This does not modify the CUDA kernel itself and does not change default-mode performance or kernel selection.
