# [PCP] Enable CUDA graphs for DeepSeek-V4.1 with fixed-length DSpark

[Upstream PR](https://github.com/vllm-project/vllm/pull/61555) · state: open · merged: False

## Original PR description

## Overview

Enable `FULL_DECODE_ONLY` and `FULL_AND_PIECEWISE` for DeepSeek-V4.1 PCP with fixed-length DSpark, on top of merged #59857 and #61994. This reuses MRV2's CUDA Graph framework instead of requiring eager execution for this configuration.

In the earlier matched four-H20, cached-64K experiment, enabling graphs reduced decode TPOT from **57.29 to 8.02 ms at C1 (7.14x)** and **57.44 to 17.98 ms at C32 (3.20x)**. These compare eager with graphs on the same patched code, not a fresh benchmark of the latest main. The smaller, subsequent communication optimization is reported separately below.

## Claims

- Preserve attention, compressor/indexer and bounded-replay buffer addresses across graph replays.
- Capture rank-local decode requests and both local prefill segments using the existing graph framework.
- Reuse gathered PCP positions across SWA builders and combine decode hidden-state restoration; retain the mixed-batch path.

## Validation

Four H20 GPUs, TP1/PCP4/EP4, fixed DSpark5, Humming MoE A8 (target attention projections use W8A16), APC and SWA bounded replay. Both benchmark arms include #61554's Engram sharing.

Median of three batches after warmup; DSpark acceptance was about 28% in both arms, with zero preemptions. These measurements predate the communication optimization and latest main sync.

<details>
<summary>Measurement method and limitations</summary>

One public-report excerpt and analysis question was repeated at each concurrency. Client TPOT is `(last-token arrival - first-token arrival) / (output tokens - 1)`, taking the median across requests, then across three batches. Steady throughput uses native token-counter deltas while all requests are decoding. Actual concurrency was verified; client connection pools exceeded concurrency (graph 272, eager 144).

Graph ran first, then eager. Natural EOS was enabled, but all outputs reached the 2K cap, including thinking tokens. This is cached decode performance, not production traffic or completed-answer quality. Cold 64K TTFT was unchanged in a separate run (2.348/2.350 s).

</details>

## Details

Like #62377, this reuses the existing graph framework. V4.1 additionally needs persistent compressor/indexer metadata and replay KV slots/token IDs. Each SWA builder copies shared gathered positions into its capture-time buffer. Hidden-state packing is limited to decode batches with matching dtypes, preserving request order and avoiding extra prefill memory.

#64253 and #62749 explicitly exclude PCP; this PR does not duplicate their metadata kernels or capture mechanism. Engram sharing stays in #61554. Fixed-length DSpark is the scope here; adaptive verification and image-input support are separate work.
