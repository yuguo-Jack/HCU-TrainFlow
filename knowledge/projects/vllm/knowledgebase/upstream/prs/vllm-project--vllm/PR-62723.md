# [Bugfix][Frontend] Pass Cohere v2 response_format to the prompt renderer

[Upstream PR](https://github.com/vllm-project/vllm/pull/62723) · state: open · merged: False

## Original PR description



## Overview

A `/cohere/v2/chat` request with `response_format` constrains decoding to JSON, but the prompt the model sees is the same as for a plain request. Melody has JSON-mode and JSON-schema prompt sections for this, and the `CohereRenderer` docstring says `response_format` is "populated automatically by `CohereServingChatV2`", but the endpoint never forwards it. This PR forwards it and makes the renderer read the schema in the shape v2 sends it.

## Claims

- `response_format: {"type": "json_object"}` now adds melody's JSON-mode instructions to the cmd3 and cmd4 prompts.
- `{"type": "json_object", "json_schema": {...}}`, which is how Cohere v2 sends a schema, now also puts the schema into the prompt.
- `{"type": "text"}` and requests without `response_format` render exactly as before. Constrained decoding is unchanged.

## Validation

- New tests:
  - `test_serving_conversion.py`: the conversion forwards `response_format` into `chat_template_kwargs`.
  - `test_cohere.py`: `_build_render_config` sets `json_schema` for `{"type": "json_object", "json_schema": ...}`.
  - `test_cohere.py`: a request goes through `CohereChatV2Request.model_validate`, the conversion, `_build_render_config` and `cohere_melody.render_cmd3`/`render_cmd4`. `text` renders the same prompt as no `response_format`, `json_object` renders a different one, and `json_object` with a schema renders a third that contains the schema and matches what melody renders for `json_schema` alone.
  - All 4 fail on main.
  - The end-to-end test follows the same chain as the existing `TestRequestCitationsReachRenderedPrompt`. It runs in CI because the test requirements pin `cohere==7.0.8` and `cohere-melody==0.14.0`.
- `pytest tests/renderers/test_cohere.py tests/entrypoints/cohere`: 346 passed on this branch, 342 on main without the new tests. On both, the 9 server tests in `test_chat_v2.py` error in my CPU environment because they need a model download.
- `pre-commit run --files` on the changed files passes, including mypy.
- The script below prints prompt lengths. On main (4964e4482):

```python
"""A /cohere/v2/chat response_format never reaches the melody prompt."""
import cohere_melody as melody
from vllm.entrypoints.cohere.protocol import CohereChatV2Request
from vllm.entrypoints.cohere.serving import CohereServingChatV2
from vllm.renderers.cohere import _build_render_config

schema = {"type": "object", "properties": {"capital": {"type": "string"}}}
conv = [{"role": "user", "content": "hi"}]
for fmt in ("cmd3", "cmd4"):
    prompts = {}
    for name, rf in [("none", None), ("json_object", {"type": "json_object"}),
                     ("json_object+schema", {"type": "json_object", "json_schema": schema})]:
        body = {"model": "m", "messages": conv}
        if rf:
            body["response_format"] = rf
        req = CohereServingChatV2._convert_v2_to_chat_completion(CohereChatV2Request.model_validate(body))
        _, cfg = _build_render_config(conv, dict(req.chat_template_kwargs or {}, cohere_format=fmt))
        prompts[name] = getattr(melody, "render_" + fmt)(cfg)
    print(fmt, {k: len(v) for k, v in prompts.items()},
          "| json_object == none:", prompts["json_object"] == prompts["none"],
          "| schema in prompt:", '"capital"' in prompts["json_object+schema"])
```

## Details

`_apply_cohere_template_kwargs` forwards `documents`, `safety_mode`, `citation_options` and `thinking` into `chat_template_kwargs`, but not `response_format`. The format only sets `ChatCompletionRequest.response_format`, which drives structured outputs. The renderer reads `response_format` only from `chat_template_kwargs`, so it never saw it. This PR forwards the request's `response_format` as a dict, with `setdefault` like the other fields, so a caller's own `chat_template_kwargs` still wins.

The renderer only looked for a schema when the type was `json_schema` or `json`. Cohere v2 has no `json_schema` type and sends the schema next to `type: json_object`, so the schema was dropped even when passed by hand. The renderer now reads it for `json_object` too. Melody renders `json_mode` plus `json_schema` exactly like `json_schema` alone, for both cmd3 and cmd4, and the end-to-end test asserts it.

This does change the prompt for every v2 request that sets `response_format`. That is the documented behavior, and it is the prompt a caller already gets today by passing `response_format` in `chat_template_kwargs` by hand. I did not measure output quality on a model.
