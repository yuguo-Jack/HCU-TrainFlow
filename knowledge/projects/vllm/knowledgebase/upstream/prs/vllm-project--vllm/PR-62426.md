# [Rust Frontend] Inherit presence and frequency penalties from generation_config

[Upstream PR](https://github.com/vllm-project/vllm/pull/62426) · state: open · merged: False

## Original PR description



## Overview

Since vllm-project/vllm#50769, the Python frontend takes `presence_penalty` and `frequency_penalty` from the model's `generation_config.json` as server-side sampling defaults. The Rust frontend still ignores them, so a model that ships `"presence_penalty": 1.5` samples with `0.0` when the request omits the field. This PR makes the Rust frontend inherit both penalties the same way it already inherits the other generation-config defaults.

## Claims

- `generation_config.json` `presence_penalty` and `frequency_penalty` now become defaults for Chat Completions and Completions requests that omit them, matching Python's priority order (request value → server default → OpenAI default `0.0`).
- `--generation-config vllm` still ignores model-provided defaults, including the two penalties.
- Explicit request values still take precedence over the model defaults.

Changed tests in `vllm-text`:

- `lower_sampling_params_uses_generation_defaults_when_user_omits_values` now expects `presence_penalty: 1.5` and `frequency_penalty: 0.5` from the defaults. It fails when the production change in `lower.rs` is reverted.
- `lower_sampling_params_prefers_user_values_over_generation_defaults` checks that request values win over the new defaults.
- The `build_sampling_hints` snapshot covers both the `auto` and `vllm` modes.

## Details

- **Python reference:** `ModelConfig.get_diff_sampling_param` (`vllm/config/model.py`) lists `presence_penalty` and `frequency_penalty` among the generation-config fields it extracts, and `ChatCompletionRequest` / `CompletionRequest` resolve each field in `_DEFAULT_SAMPLING_PARAMS` as request value → server default → OpenAI default.
- **Layering:** these are model-provided sampling defaults, which in the Rust frontend already flow through `GenerationConfig` → `build_sampling_hints` → `SamplingHints` → `lower_sampling_params`. The two fields follow the same path under the same `--generation-config auto`/`vllm` rule, so no new mechanism is added. Most of the diff is the two new `None` fields in existing test fixtures.
- **Not a duplicate:** searching open vLLM PRs for Rust frontend generation-config defaults and penalty defaults finds no PR covering this. vllm-project/vllm#61133 is related in spirit but changes the Python transcription/translation request types only.
