## Overview
Allow native CUTLASS, PyTorch, FlashInfer cuDNN, and FlashInfer B12X NVFP4 linear kernels to consume QuantizedActivation, enabling manual activation+quantization fusion at existing model call sites.

Related to #43501.

## Details
Manual activation+quantization fusion produces a `QuantizedActivation`. A downstream linear kernel must explicitly advertise and consume this format. Adding this support repeats the same preparation logic across NVFP4 backends. `NvFp4LinearKernel.prepare_input()` centralizes that logic and always returns a `QuantizedActivation`. Each consumer can then pass its data and scales directly to the backend’s GEMM implementation.

The quantization call previously lived inside each consumer and supplied a backend-specific string to `scaled_fp4_quant`. Moving that call into the base class requires preserving this configuration. Each subclass now declares an `input_quant_backend_name` attribute, which the helper reads. This names the quantization backend; it can differ from the GEMM wrapper’s name—for example, FlashInfer cuDNN uses flashinfer-cudnn for quantization and cudnn for GEMM.
