# [Bugfix][NIXL] Dedup transfer regions by (base_addr, block_len)

[Upstream PR](https://github.com/vllm-project/vllm/pull/57662) · state: closed · merged: True

## Original PR description

Fixes #57661

- **Root cause**: NIXL region registration deduped transfer regions by `base_addr` alone, and the collapsed branch only refreshed block geometry for MLA regions. In hybrid-attention models, a layer with a different block length aliasing another layer's base address (DeepSeek-V4.1-Flash compressor `state_cache` / indexer `k_cache` overlaid on `swa_cache`) was silently folded and inherited the first region's block length. PD transfers of its state were truncated and misaligned, producing garbled output with no errors.
- **Fix**: dedup key is now `(base_addr, block_len)`. Identical-geometry aliases still fold (`test_overlaid_transfer_groups_share_region_geometry` continues to pass, confirming the lossless path is unchanged).
- **Behavior change (maintainer sanity-check welcome)**: `test_ring_scratch_without_mamba_registers_and_addresses_its_own_regions` now expects `_scratch_region_indices == [2]` instead of `[1]`. That fixture (introduced in #56214) overlays rings on a paged region whose block_len differs from the rings' page size — the old expectation had recorded the benign form of this very bug (the ring inheriting the paged region's geometry). If overlay folding was intentional design, this one assertion is trivially revertible.
- **Tests**: added `test_shared_base_regions_with_distinct_block_lens_stay_separate` (two geometries at one base address — 256B MLA swa page vs 128B compressor ring page — must register as two regions with their own block lens and descriptor geometry). Verified in a container: target test fails on HEAD / passes with the fix; `test_nixl_connector_hma/push_connector/tp_mapping` failure sets are identical before/after. `ruff check` + `ruff format` pass.

**Why this is not a duplicate**: searched open issues/PRs (nixl region dedup, deepseek pd disagg, base_addr, garbled output); #52627 is Mooncake-specific and #54926 is un-transferred draft KV — different root causes.

**Model evals**: 2×8 H200 cluster, NIXL P/D disagg — before: fully garbled output; after: clean English/Chinese generations, 0% garble rate, 6 concurrent streams clean (details in #57661).

**AI assistance disclosure**: root-cause analysis and this fix were produced with ZCode (local agent); cluster diagnosis, the initial mitigation patch, and remote test runs were done with Chaterm (remote agent). The submitter has reviewed every changed line and performed the end-to-end cluster verification above.

Good question — I walked the registration branches before settling on (base_addr, block_len):

num_blocks isn't per-layer geometry: it's logical_num_blocks (mamba) or logical_num_blocks * physical_blocks_per_logical (attention), both worker/group-global, so specs sharing a base and block_len already share num_blocks. Host-resident groups could differ, but those have a different mem_type and the existing fold assert rejects that.

block_stride is pinned to block_len in every branch that can emit a shared base: the mamba branch (stride = page/ratio = len), the flat 1-D view (stride = page = len), virtual transfer pages (len = stride = page), the packed branch (len = stride = registration_len // num_blocks), and the multi-segment branch (len = stride). The remaining block-major branch takes stride from the view, but views at the same data_ptr with the same page size come from the same KVCacheTensor, which fixes one block_stride.

That said, this is an invariant argument, and an invariant argument is exactly what let the base_addr-only key survive until DeepSeek-V4.1-Flash's layout showed up. I'm inclined to keep the key minimal for now: we can't predict which assumption the next hybrid layout breaks, so if we want protection beyond the argument above, an assert in the fold branch (rejecting a fold whose stride/num_blocks disagree) seems more appropriate than widening the key.

## 1. Aliased / folded layers — behavior is identical

The MLA block-major branch emits `(cache.data_ptr(), physical_page_size, block_stride)` ([L1675-1677](https://github.com/vllm-project/vllm/blob/a4b85c2b9541c078b53102b37af9ce4f4c1761fa/vllm/distributed/kv_transfer/kv_connector/v1/nixl/base_worker.py#L1675-L1677)); the mamba branch emits `(cache.data_ptr(), physical_page_size // physical_ratio, block_stride // physical_ratio)` ([L1598-1610](https://github.com/vllm-project/vllm/blob/a4b85c2b9541c078b53102b37af9ce4f4c1761fa/vllm/distributed/kv_transfer/kv_connector/v1/nixl/base_worker.py#L1598-L1610)).

When the views share a storage base, `cache.data_ptr()` coincides with it, and for aliased specs the MLA physical page equals the mamba page divided by `ppl` — so base, block\_len, and stride all agree, the key matches at [L1711-1712](https://github.com/vllm-project/vllm/blob/a4b85c2b9541c078b53102b37af9ce4f4c1761fa/vllm/distributed/kv_transfer/kv_connector/v1/nixl/base_worker.py#L1711-L1712), and the fold is exactly what it was before. No change.

## 2. Split (un-folded) layers — the SSM id layout at L285-303 cannot collide

This is the case you flagged. `register_local_xfer_handler` concatenates

```
[ FA descs (global region order) | mamba descs (_ssm_region_indices order) ]
```

([L2141-2159](https://github.com/vllm-project/vllm/blob/a4b85c2b9541c078b53102b37af9ce4f4c1761fa/vllm/distributed/kv_transfer/kv_connector/v1/nixl/base_worker.py#L2141-L2159)), and the SSM descriptor id is

```
ssm_id = ordinal * logical_blocks + block + num_fa_descs
```

where `ordinal` is the position within `_ssm_region_indices`. A split converts one region into two:

- `num_regions` grows by 1, `num_fa_descs` grows by `num_blocks` (one full FA region of descriptors).
- The mamba layer keeps its ordinal (list position) in `_ssm_region_indices` — only the region index it points at changes, from the folded MLA region to its own new region.
- So `ssm_id = ordinal * logical_blocks + block + num_fa_descs`: the ordinal is unchanged, `num_fa_descs` shifts up by exactly `num_blocks`.

The whole SSM block shifts by exactly the FA section's growth. Ordinals are unchanged and distinct, so no two SSM ids collide; and since `+ num_fa_descs` tracks the FA length exactly, no SSM id lands inside the FA range. **No overlap.**

Where block\_len differs, the pre-PR fold was already mis-addressing the mamba state through the folded MLA region's `block_stride_per_layer[i]` ([L1941-1944](https://github.com/vllm-project/vllm/blob/a4b85c2b9541c078b53102b37af9ce4f4c1761fa/vllm/distributed/kv_transfer/kv_connector/v1/nixl/base_worker.py#L1941-L1944)) — the same silent misalignment this PR fixes for the compressor case. The split does not introduce a new failure mode; it replaces a silent one with a loud assert (see below).

## 3. One caveat: PP > 1 pull layouts

For PP > 1 pull layouts, the `num_regions % num_local_layers` assert at [L1803](https://github.com/vllm-project/vllm/blob/a4b85c2b9541c078b53102b37af9ce4f4c1761fa/vllm/distributed/kv_transfer/kv_connector/v1/nixl/base_worker.py#L1803) would now fire at **startup** for a model whose aliased layers split (previously they folded and were silently mis-transferred). This is a hard stop before any token is processed — no KV data is ever written to the wrong offset. This is a behavior change for that narrow shape; we believe fail-loud at registration is preferable to the previous silent mis-transfer.
