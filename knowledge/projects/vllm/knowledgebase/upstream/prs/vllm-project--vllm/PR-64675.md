# [Bugfix][Parser] Parse closed Qwen3 tool parameters once while streaming

[Upstream PR](https://github.com/vllm-project/vllm/pull/64675) · state: closed · merged: True

## Original PR description



## Overview

A Qwen3 XML tool call that repeats closed parameters makes `_qwen3_arg_converter` re-scan every parameter on each streaming conversion, so the API server's cost per token grows with the call until the event loop saturates and liveness fails. This parses each closed parameter once. It is the Qwen3 counterpart of #64535 (GLM) and covers every parser on the Qwen3 converter: `qwen3_coder`, Nemotron-3, Step-3.5, Step5, Seed-OSS, MiniCPM-V and Granite thinking.

## Claims

- Streaming a call with N closed parameters matches the parameter regex N times in total. On main every conversion matches all closed parameters again and the value extender scans them twice more: 2,051,331 matches for N = 401 in the new test.
- Streamed deltas and non-streaming results are unchanged.
- For a call looping on two parameters, the cost per 4-token engine step at 64K output chars drops from 6.4 ms to 92 us, and a replay at 200 tok/s no longer fails liveness (main: killed at 335 s).
- On a real server (Qwen3-Coder-30B-A3B, one H200), that loop to 256K chars keeps the API server 100% busy on main from 148 s, and `/health` answers no probe within 10 s for the last 150 s of the stream. With this PR the API server is 7% busy and `/health` p99 is 0.9 ms.
- No new config, flag or API. `MiMoParser` keeps its own converter and is unchanged.

## Details

**Root cause.**
- `ParserEngine._compute_arg_delta` converts the whole raw argument text whenever the open-value extender is inactive: between parameters, and while the open parameter repeats an earlier name (the extender needs the open value to be the last JSON value). Qwen3 sets no `arg_structural_chars`, so every argument delta in those states converts.
- `_qwen3_arg_converter` runs `_PARAM_RE.finditer` over every closed parameter, then `_PARAM_RE.sub` over the whole text to find the open one. After each conversion that extends the streamed JSON, `_param_value_extender` runs both again.
- A model looping on closed parameters keeps every delta in those states, so the cost per delta is linear in the call and the total is quadratic. Merging deltas under load does not bound it, because each merged pass converts the whole text again.

**Change.**
- `_qwen3_parse_params` takes an optional `_ClosedParams` cache, and `Qwen3Parser` binds one per instance into its converter and extender after `super().__init__`, as `Glm47MoeParser` does since #64535. A text that starts with the cached text resumes after the last closed parameter. Any other text parses from the start, and the cache moves forward whenever a scan closes a new parameter.
- A Qwen3 value also closes where the next `<parameter=` begins (the lookahead in `_PARAM_RE`), and holds only while that opener follows. So the cached text runs through that opener, and the scan resumes at the end of the value. Appending text cannot change a parameter closed within the cached text, so resuming is exact. `test_value_closed_by_next_parameter_needs_that_parameter` covers a text that shares the prefix but not the opener.
- The extender's repeated-name check uses the closed names from the same parse in place of a second `finditer`.
- A parser built with a custom `arg_converter` keeps the uncached path (identity check in `__init__`), as in #64535.

**Cost.** What stays linear in the text per conversion is C-level work: `startswith` against the cached text, the join of text outside the parameters for the open-parameter search, and the engine's own argument concatenation. That is the 10% busy at 818K chars in the replay.

**Not in this PR.** #64535 also set `arg_structural_chars=frozenset(">")` for GLM, on the argument that a delta without `>` cannot close a key or value. That does not hold for Qwen3, where a value closes at `<parameter=` before any `>`, and the cache alone passes the replay. Measured with the gate added: 39 us per step at 64K chars for the parameter loop, and 385 us against 1247 us for many distinct parameters.

**Unchanged here and the same on main.**
- Many distinct parameters in one call: each conversion still serializes every parameter, so the cost per step grows with their number (1.2 ms at 64K chars, against 6.2 ms on main).
- A long value under a repeated name: `_param_value_extender` refuses any repeated name, so each delta converts the whole value (11.7 ms per step at 64K chars, against 17.6 ms on main). Letting it accept a repeated last name, as GLM's extender does, is a separate change.
- `MiMoParser` keeps its own converter with the full scan.

**Not a duplicate.** #55497 (open) narrows the parameter-name group of `_PARAM_RE` and `_PARTIAL_PARAM_RE`; the cache works with either pattern and the overlap is textual. #59821 (open) edits `Qwen3Parser.__init__` for tool markup in reasoning; whichever lands second rebases. #63277 (open) changes zero-argument calls in the tool adapter. No open PR covers re-parsing closed Qwen3 parameters.
