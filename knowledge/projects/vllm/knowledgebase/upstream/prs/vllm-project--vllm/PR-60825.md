# [Performance] Load HF tokenizers and processors from a local snapshot

[Upstream PR](https://github.com/vllm-project/vllm/pull/60825) · state: open · merged: False

## Original PR description



## Overview

When given a Hub repo ID, `AutoTokenizer.from_pretrained` and `AutoProcessor.from_pretrained` make a Hub request for every candidate file, including a `list_repo_tree` of `additional_chat_templates/` (`transformers.utils.hub.list_repo_templates`). vLLM always passes the repo ID, so each tokenizer and processor load in each process repeats these requests.

This PR resolves the repo ID to a local snapshot of its non-weight files before loading, so Transformers reads from disk. The ModelScope path already does this for tokenizers.

## Claims

- Adds `get_non_weight_snapshot_path` to `repo_utils.py`. It runs `snapshot_download` with weight files ignored, is cached per process and uses the existing `get_lock`. Local paths and ModelScope are untouched, and any download failure falls back to the repo ID, so behaviour matches `main` in that case.
- `resolve_tokenizer_args` uses it when `tokenizer_mode` resolves to `hf`. Mistral and the other custom tokenizer modes are unchanged.
- `get_processor` uses it too.
- Hub requests per load (warm cache): tokenizer 9 → 2, processor 5 → 1. The `additional_chat_templates` listing is gone in both.

## Validation

Requests counted by wrapping `httpx.Client.send`, warm HF cache, same worktree with the diff stashed vs applied:

| Load | Model | `main` | This PR |
|---|---|---|---|
| `get_tokenizer` | `Qwen/Qwen3-0.6B` | 9 | 2 |
| `get_processor` | `Qwen/Qwen2-VL-2B-Instruct` | 5 | 1 |

The 2 remaining tokenizer requests are vLLM's own `list_repo_files` (Mistral detection, before the snapshot) and the snapshot's revision lookup. The first, cold-cache load also downloads small non-weight files Transformers would not have fetched (README, LICENSE, `.gitattributes`).

```bash
.venv/bin/python -m pytest tests/tokenizers_/test_basic.py tests/transformers_utils/test_processor.py -q
# 8 passed. With the registry.py/processor.py changes reverted, both *_loads_from_local_snapshot tests fail.
.venv/bin/python -m pytest tests/transformers_utils/test_processor.py tests/tokenizers_ -q
# 729 passed, 253 skipped (on the first commit, before the test rework)
pre-commit run --files <changed files>
# all passed
```

The download-failure fallback is covered by the existing `test_tokenizer_revision`: with the `except` disabled it fails on the raw Hub 404 instead of the Transformers error.

Not yet validated end-to-end with `vllm serve`.

Points for review:
- `tokenizer.name_or_path` becomes the snapshot path (e.g. `.../models--Qwen--Qwen3-0.6B/snapshots/<sha>`) instead of the repo ID. The path still contains the repo name, so the MiniCPM-V chat template fallback still matches. Logs show the path.
- Remote-code tokenizers or processors that need a file matching the weight ignore patterns (`*.bin`, `*.pt`, ...) would not find it in the snapshot.
- The processor call keys its cache on `revision="main"` and the tokenizer on `None`, so a model whose tokenizer and processor are both loaded does one extra (cheap, fully cached) snapshot lookup.
