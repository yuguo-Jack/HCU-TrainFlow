# [Frontend] Add completion SSE on top of packed top-k logprobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/60918) · state: open · merged: False

## Original PR description

## Overview

Extend RFC #57479's packed top-k format to `/v1/completions`, including SSE deltas, for numeric RL and distillation clients. **Stacked on #60915 at `f66339af0a`**, which includes #60542's NumPy-backed `FlatLogprobs`.

**Direct stacked review: https://github.com/hao-aaron/vllm/pull/2**, targeting `hao-aaron/vllm:rl-frontend/py-top-k-logprobs`. Its Files changed tab contains only the completion SSE/shared-encoder contribution.

This upstream PR remains the publication against `main`: GitHub cannot change an existing PR's target repository, and the dependency branch lives in the author's fork. The existing commit history is preserved. [Incremental comparison](https://github.com/dhruvji/vllm/compare/f66339af0a631966143fc4a36fb28ae97eca3a99...6d92bb7aed5137a541162776624c6f5c87fd1d73).

## Claims

- `return_top_k_logprobs=true`, positive `logprobs`, and `return_tokens_as_token_ids=true` return `logprobs.top_k = {num_positions, k, token_ids, logprobs}` in full completion responses and SSE deltas, including single-token, multi-token and empty terminal deltas.
- Completions and `/inference/v1/generate` share one `PackedTopK` schema and encoder. Both pack engine slots 1..k as base64 little-endian int32/float32 arrays in row-major order. Generate retains its direct byte-fragment rendering.
- Completion packing reads NumPy engine-row views without rebuilding primitive Python lists or candidate `Logprob` objects. Sampled scores, including samples outside top-k, remain in `token_logprobs`; offsets, finish reasons and usage are preserved.

## Details

**Nonduplication:** #60915/#60916 cover `/inference/v1/generate` and reject streaming. This contribution adds `/v1/completions` and completion SSE on the shared format, as welcomed in the PR discussion. The generate endpoint's streaming behavior is unchanged. #60542 supplies the storage and detokenization controls; there are no additional engine, sampling-parameter, scheduler, model-runner or GPU changes above #60915.

The shared encoder preserves candidate order, raw float32 values and negative infinity without sorting or renormalization. Completion sampled scores retain the -9999 lower clamp. Malformed rows and columns widened beyond the packed dtypes are rejected. Echo, beam search, custom candidate IDs and nonpositive/missing `logprobs` remain unsupported. Prompt decoding is retained; existing `stream_interval` controls batching. Usage and NumPy decoding examples are in `docs/serving/packed_logprobs.md`.

Packing still allocates contiguous CPU buffers proportional to positions × k, and base64 adds its usual 4/3 expansion. Dependency #60915 currently also needs conflict resolution against upstream `main`; this update is pinned to its current head rather than modifying unrelated dependency code.
