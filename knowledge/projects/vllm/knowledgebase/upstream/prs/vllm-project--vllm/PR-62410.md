# [Model] Support GLM-5.3 MLA DSpark drafts on CUDA

[Upstream PR](https://github.com/vllm-project/vllm/pull/62410) · state: open · merged: False

## Original PR description



## Overview

Add CUDA serving support for a GLM-5.3 MLA DSpark draft exported in the speculators format, without checkpoint-side Python runtime files or startup monkey patches.

Related: [speculators#1052](https://github.com/vllm-project/speculators/issues/1052), [vllm-ascend#14535](https://github.com/vllm-project/vllm-ascend/pull/14535). The former covers training/export and the latter is an Ascend implementation; this change targets the CUDA model, latent cache, and anchor-relative mixed-window attention. Searches for open GLM/DSpark and `GlmDSparkMLA` PRs found no matching CUDA implementation. This is distinct from K3-specific MLA refactoring and generic draft-context limits.

## Claims

- Register `GlmDSparkMLAForCausalLM` and preserve its architecture and MLA geometry through speculators config conversion.
- Reuse the Qwen3 DSpark scaffold, Markov/confidence heads, MLP, and weight loading, with an MLA decoder and compressed `512 + 64` latent/RoPE cache.
- Resolve layer count, sliding/full layout, window size, and causality from configuration, preserving the tested draft's block-anchor-relative window semantics.
- Keep this PR separate from sampling-RNG changes. Existing model routes remain the defaults.

Both same-node runs completed 300/300 requests with zero errors. ## Details

### Scope and compatibility

The supported MLA geometry is deliberately restricted to Q rank 2048, KV rank 512, NoPE head dimension 192, RoPE dimension 64, and V head dimension 256. Hidden size and head count are read from configuration, subject to compatible tensor-parallel shapes.

The implementation does **not** hardcode five decoder layers or a four-sliding/one-full ordering. It resolves each layer through the existing DFlash attention configuration helper. The measured checkpoint uses four causal sliding layers with a 2048 window and one noncausal full layer; other layouts have not been evaluated. The sliding window starts relative to the draft block's anchor, not each individual query position. Default NeoX-style RoPE was evaluated; this does not claim arbitrary RoPE-scaling compatibility.

This initial path requires BF16 draft weights, eager execution, PP1 and DCP1. Graph support is explicitly disabled. The current paged kernel handles at most 16 query rows per request per call; the evaluated speculative width is 8. Cache insertion currently uses PyTorch indexed assignments; async-performance and graph-capture improvements are not claimed.

The dedicated kernel is retained because the draft's mixed causal/noncausal and anchor-relative window semantics must match training. This is not a claim that every GLM/K3 MLA checkpoint, weight layout, or backend is interchangeable. Future shared-backend work should preserve those semantics.

### Usage

The draft export declares `architectures: ["GlmDSparkMLAForCausalLM"]`; its `transformer_layer_config` declares `model_type: "glm_dspark_mla"` and the MLA dimensions. Matching weights and config are sufficient; no checkpoint-side runtime code is required.

```bash
VLLM_USE_V2_MODEL_RUNNER=1 vllm serve /path/to/target \
  --tensor-parallel-size 4 --enforce-eager \
  --max-model-len 196608 \
  --speculative-config '{"method":"dspark","model":"/path/to/draft","num_speculative_tokens":8}'
```
