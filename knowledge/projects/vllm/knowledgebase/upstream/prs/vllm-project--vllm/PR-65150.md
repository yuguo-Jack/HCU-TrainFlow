# [Bugfix][Rust Frontend] Preserve null DeepSeek tool descriptions

[Upstream PR](https://github.com/vllm-project/vllm/pull/65150) · state: open · merged: False

## Original PR description



## Overview

Fixes #65116. DeepSeek V4 and V4.1 tool schemas now retain `"description": null` when the caller omits the description, matching the Python frontend's rendered prompt.

## Claims

- Preserve absent and explicit-null descriptions as JSON null, while preserving empty and nonempty strings.
- Keep an unset `strict` field omitted and preserve explicit `strict: false` and `strict: true`.
- Check complete V4/V4.1 prompts against Python-generated fixtures, including request-level and developer-message tools.

## Validation

Tested on WSL2 Ubuntu with Rust 1.95.0, using upstream main `5c8ae7c74aaa99d1f7fbeea942fd7282e3413810` as the base. The regression fixtures were generated with the current Python `FunctionDefinition.model_dump()` and DeepSeek encoders. The complete V4.1 prompt also matches the official `deepseek-ai/DeepSeek-V4.1-Flash-1017` reference encoder byte for byte (1,546 UTF-8 bytes).

```bash
cd rust
cargo test -p vllm-chat --lib deepseek --locked
# Main rendering code with the regression fixtures: 76 passed, 3 failed.
# With the fix: 79 passed, 0 failed.

cargo test -p vllm-chat --lib --locked
# 453 passed, 0 failed, using Linux LF fixture bytes.

cargo clippy -p vllm-chat --all-targets --locked -- -D warnings
# Passed.

cargo fmt --all -- --check
# Passed.
```

All applicable pre-commit hooks on the eight changed files and `git diff --check` passed.

The full library suite initially had four unrelated GLM template mismatches because Windows checkout conversion had changed the Jinja fixtures to CRLF. Rerunning with their original Linux LF bytes passed all 453 tests; those temporary checkout adjustments are excluded from the patch. Validation reaches complete rendered prompts, not GPU inference or model-quality evaluation, and no generation or performance claim is made.

## Details

`RenderedToolSchema` uses `skip_serializing_none` at the struct level, which unintentionally removed a missing description as well as the intentionally optional strictness flag. Add `serialize_always` only to `description`; removing the struct-level attribute would also introduce `"strict": null` and widen the behavior change. Existing developer-tool snapshots are corrected, a shared request-tool fixture covers the optional-field cases, and the renderer documentation describes the resulting prompt shape. The regression test is selected by the existing Rust frontend Cargo CI job.

Duplicate-work check: searched issue #65116 and its comments, all-state PRs for `65116` and `RenderedToolSchema`, and related DeepSeek description/null PRs. No PR covering this serializer fix was found. The neighboring continuation and thinking-control work is independent of the tool-schema field serialization.
