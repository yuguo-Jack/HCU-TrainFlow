# [Core] Unbounded streaming-input sessions via RoPE re-anchoring (experimental, default-off)

[Upstream PR](https://github.com/vllm-project/vllm/pull/45833) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Lets a streaming-input session run past `max_model_len` on sliding-window RoPE models, behind `--enable-unbounded-streaming-input`. Experimental, off by default. Builds on #45022 (merged, in v0.32.0).

An earlier Voxtral-only version has run in production at LinTO since June. It ran the live captions of Wikimania 2026 on one L40S at `--max-model-len 8192`, where a session would otherwise stop after 11 min: 6 concurrent streams translated into 5 languages, multi-hour sessions, all week. A throughput bench on the same card, without translation, kept up in real time with 17 streams.

## Claims

- A Voxtral realtime session no longer stops at `max_model_len`. Its KV usage stays constant, since the windows already bound it.
- The shift is model-agnostic: each attention layer is rotated with its own RoPE, read from the model at startup. It works for any streaming-input session on a model where every attention layer uses a sliding window and plain, Llama 3 or YaRN RoPE.
- Unsupported models and configurations are refused at startup.
- With the flag off, the new code does not run.

## Details

### Who needs it today: Voxtral realtime

A Voxtral session stops at `max_model_len`: about 2 h 55 at the default, 11 min at `--max-model-len 8192`. The client has to reconnect and the model loses its context. The vLLM recipe for this model tells users to restart long sessions periodically.

On a sliding-window model the KV of a streaming session is already bounded by the window. What stops the session is the position counter reaching `max_model_len`. The [technical report](https://arxiv.org/abs/2602.11298) says Voxtral's sliding windows support "arbitrarily long streams with bounded memory".

### How it works

RoPE scores only depend on `m - n`, and a query only sees keys in `(m-W, m]`, so shifting every live position down by `d` keeps the scores the same apart from rounding. When a session resumes on a new input chunk close to the cap, the scheduler drops its head (blocks already evicted by the window, mm features, token ids) and the worker re-rotates the cached keys in place by `R(-d)`.

The margin before the cap defaults to half of `max_model_len - W` and can be set with `--unbounded-streaming-input-margin-tokens`. With `d >= W` a key is rotated at most once before it leaves the window, so rounding does not build up.

The position scale of a block-pooled layer comes from its `tokens_per_state`. The only model-side change is in Voxtral: its audio buffer no longer ends the stream at `max_model_len` when the flag is on. `buffer_realtime_audio` gains that keyword, and it is only passed when the flag is on, so models outside this repo are not affected.

Where to look: `vllm/v1/core/sched/reanchor.py` (what a shift does to a session) and `vllm/v1/worker/reanchor_rotary.py` (startup checks and the rotation). The core files only get the hooks. 456 added lines without config, tests and docs, 329 of them in these two new files.

Rounding: cos and sin are computed in fp32 and the keys rounded back to their dtype, so in bf16 the error is per element and not the same for all keys of a frequency. On a shift step each layer does one GPU copy and rotate; steady state does not change. A large `max_model_len` costs CPU, every token resends the session since the last shift.

Why V1 as well as V2: our production still runs on V1. Both runners call the same function, so it costs one hook and the init check.

### Refused at startup

Non-sliding attention, a RoPE other than plain, Llama 3 or YaRN (exact class), a RoPE built for another head size, compressed KV states, quantized KV, KV sharing, prefix caching, KV connectors, KV offloading, encoder cache connectors, speculative decoding, pipeline parallelism, prefill context parallelism, non-CUDA, and a `max_model_len` under the window + the margin + one KV block.

### Limits

- Not detected at startup, needs an override to be used at all: attention that depends on absolute positions outside RoPE (`llama_4_scaling`, Rnj1 chunked attention, Moondream3 `tau_pos`) and RoPE held but unused (Step3p5 NoPE).
- A chunk larger than `max_model_len - W - 1 block` goes past `max_model_len`, as it does on main today (#42502, #51900, #63113 are open).
- If more sessions run than fit in the KV cache, all of them stall (#60137), with or without the flag.
- A turn that generates past the cap is cut there and the next chunk shifts. Voxtral generates 1 token per chunk.
- The API server keeps each session's token ids and text, about 100 MB per session per day (estimated from the code, not measured).
- The docs ask for a text window of 1024 or more: on long read speech a 256 window drops text for minutes, with or without shifts (#47614).

### Not covered: Qwen3-ASR realtime

Qwen3-ASR realtime, the other realtime model in vLLM, is refused at startup: it uses full attention, so nothing ever leaves its KV cache, and M-RoPE. Its sessions grow because earlier segments are carried over. #56218 and #51037 would change that, which may remove the need. If the context stays, three pieces would make it work:

1. Free the old KV blocks of a live session: #53871 (RFC #51948), plus a policy that calls it.
2. Keep the position counter under `max_model_len` without re-prefill: this PR, plus an inverse rotation for M-RoPE (still a constant rotation, the 3 axes move together).
3. Measure quality. The model has no sliding window in its config, and #56218 shows that carried context can hurt it. If the prompt is kept as an attention sink, a shift moves it to a negative position, and shifting only the rest changes its distance to the query ([comment on #51948](https://github.com/vllm-project/vllm/issues/51948#issuecomment-5907011073)). The consolidation in #53876 re-prefills the window from position 0 instead.

Happy to work on this with @nvbfalk.

### Not a duplicate

#53871, #53876 and #43374 free KV of a live session. Here the KV is already bounded and the position counter is what has to move. #42502, #51900 and #63113 end the session or reject the input at the cap; this PR keeps it under the cap.

AI-assisted (Opus 5.5, `Assisted-by` trailers on the commits): most of the migration from the Voxtral-specific code to this model-agnostic version was done that way. Reviewed and validated by me.
