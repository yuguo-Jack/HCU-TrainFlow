# [ROCm] Honor explicit VLLM_ROCM_USE_AITER_UNIFIED_ATTENTION=0 on RDNA

[Upstream PR](https://github.com/vllm-project/vllm/pull/56040) · state: open · merged: False

## Original PR description

## Purpose

On RDNA (gfx12), `VLLM_ROCM_USE_AITER=1` always puts `ROCM_AITER_UNIFIED_ATTN` first, and
`VLLM_ROCM_USE_AITER_UNIFIED_ATTENTION=0` has no effect there. That leaves no way to avoid
this one kernel without turning off aiter entirely (and losing its other Triton paths such as
linear GEMM).

The original LDS-overflow crash from #56021 is fixed on the kernel side by ROCm/aiter#4868
(shipped in aiter v0.1.23), and AMD selects this backend on gfx12 by default on purpose. So
this PR is now deliberately narrow:

- **Default unchanged**: with the variable unset, RDNA still prefers `ROCM_AITER_UNIFIED_ATTN`.
- **Explicit opt-out honored**: `VLLM_ROCM_USE_AITER_UNIFIED_ATTENTION=0` drops only this
  backend on RDNA. This matters while the kernel does not support multimodal inputs and
  silently produces wrong attention output for them (per AMD in #56021).

`is_rdna_unified_attn_enabled()` uses `envs.is_set()` to tell "unset" from "explicitly 0".

Related: #56021

## Not a duplicate

Searched open PRs for `56021 in:body`, `ROCM_AITER_UNIFIED_ATTN RDNA`,
`VLLM_ROCM_USE_AITER_UNIFIED_ATTENTION`, `gfx12 unified attention` and `rdna4 aiter attention`.
None changes how this variable is read on RDNA. #61332 and #42798 also edit
`_get_backend_priorities()`, but for the CDNA ordering of `ROCM_AITER_FA` / `ROCM_ATTN`, and keep
the RDNA branch as is; whichever lands second needs a trivial rebase. ROCm/aiter#4868 fixes the
kernel's LDS budget and does not touch vLLM's backend selection.
