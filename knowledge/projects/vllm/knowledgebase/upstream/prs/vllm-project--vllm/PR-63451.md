# [Bugfix] Release cached cuBLAS workspaces after daemon warmup

[Upstream PR](https://github.com/vllm-project/vllm/pull/63451) · state: closed · merged: True

## Original PR description



## Overview

Release cached cuBLAS/cuBLASLt workspaces after weight-cache daemon warmup, before accepting engine connections.

Follow-up to #62583: communication teardown leaves PyTorch-owned BLAS workspaces resident even though the daemon no longer performs inference.

## Claims

- Release cached BLAS workspaces after daemon warmup while preserving CUDA IPC weights, allowing unused allocator segments to be returned to the GPU driver.

## Validation

### Memory comparison

`nvidia/Qwen3-30B-A3B-NVFP4`, B300, TP=4, `gpu_memory_utilization=0.1`, `max_model_len=8192`, `max_num_batched_tokens=16384`, `max_num_seqs=1024`.

“Before” includes #62583. Memory figures are per GPU / daemon process.

| Metric | Disk load | Daemon before | Daemon after |
| --- | --- | --- | --- |
| Available KV cache | 18.90 GiB / 1,651,280 tokens | 18.92 GiB / 1,653,488 tokens | 18.92 GiB / 1,653,488 tokens |
| Loaded / exported weights | 4,357.92 MiB loaded | 4,340.77 MiB exported | 4,340.77 MiB exported |
| PyTorch allocated memory, cold cache | — | 4,419.98 MiB | **4,387.98 MiB (−32)** |
| PyTorch allocated memory, warm cache | — | 4,419.80 MiB | **4,387.80 MiB (−32)** |
| Daemon NVML memory, cold cache | — | 5,674 MiB | 5,674 MiB |
| Daemon NVML memory, warm cache | — | 5,694 MiB | **5,566 MiB (−128)** |

Workspace allocations decreased by 32 MiB per daemon. NVML savings depend on allocator fragmentation; KV capacity and exported weights remained unchanged.

These development measurements used different B300 GPU sets and base revisions (`c569393ed2` / `404c2b510e`, with unchanged daemon code). Externally disturbed baseline runs were excluded from the KV comparison. Results are individual observations, not repeated-run averages.

### Final implementation validation

`Qwen/Qwen3.5-0.8B`, B300, TP=4, compilation enabled, utilization=0.06, maximum length=8192, batched tokens=2048, maximum sequences=32.

| Metric | Disk load | Cold daemon + IPC | Warm restarted daemon + IPC |
| --- | --- | --- | --- |
| Available KV cache | 13.82 GiB / 1,766,663 tokens | 13.85 GiB / 1,769,706 tokens | 13.85 GiB / 1,769,706 tokens |
| Daemon NVML memory | — | 1,638 MiB | 1,604 MiB |
| Daemon ranks ready | — | 4/4 | 4/4 |
| Generated tokens | Reference | Identical | Identical |

All five runs—cold/warm disk, cold IPC, warm IPC with the existing daemon, and warm IPC after daemon restart—completed successfully with identical 32-token outputs. Exported weight sizes remained unchanged. This is targeted correctness validation, not a broad accuracy evaluation; the disk/IPC KV difference is not attributed to this fix.

## Details

PyTorch caches BLAS workspaces independently of model tensors, so garbage collection and `empty_cache()` cannot release them while those caches retain ownership.

This change clears the caches after communication teardown and before the existing `empty_cache()`. Cleanup is CUDA-only and uses `getattr` to skip gracefully when the private PyTorch API is unavailable. No additional explicit device synchronization is introduced.

Duplicate-work searches found no equivalent open fix. Related #52553 addresses workspace address stability during graph execution; this PR releases caches after daemon warmup has finished.
