# [Rust Frontend] Forward profiler_kwargs from /start_profile

[Upstream PR](https://github.com/vllm-project/vllm/pull/63771) · state: closed · merged: True

## Original PR description

## Overview

vllm-project/vllm#51974 added `profiler_kwargs` to `POST /start_profile`: Python forwards it to the engine's `profile` utility, which merges it into the torch profiler kwargs. The Rust route had no such field, so serde ignored it and the engine profiled with its configured defaults. This PR forwards it.

## Claims

- `POST /start_profile` on the Rust frontend accepts `profiler_kwargs` (a JSON object) and passes it unchanged as the fifth argument of the engine `profile` utility call, `nil` when absent, as Python sends `None`.
- Like Python, the frontend does not interpret the keys.

## Validation

Commands from `.buildkite/scripts/run-rust-frontend-cargo-ci.sh` (`style-clippy` and `test`), run from the repo root:

```

```

- `start_profile_route_forwards_session_overrides` now sends `profiler_kwargs` and asserts that the msgpack `profile` call to the scripted mock engine carries it as the fifth argument; it fails when the route passes `None` instead.
- The no-override tests assert the fifth argument is `nil` (shared `profile_start_without_overrides` helper).

## Details

Python path: the route forwards `StartProfileRequest.model_dump(exclude_none=True)` to `AsyncLLM.start_profile`, which calls the `profile` utility as `(True, profile_prefix, delay_iterations, max_iterations, profiler_kwargs)` (`vllm/v1/engine/core_client.py`); `EngineCore.profile` hands it to the executor, and `vllm/profiler/wrapper.py` merges it.

Rust: `StartProfileRequest` (`rust/src/server/src/routes/profile.rs`) gains the field, and `EngineCoreClient::start_profile` sends it as the fifth argument. The route DTO owns the field and `vllm-engine-core-client` owns the utility's wire arguments, so the value travels along the existing `start_profile` path with one added parameter and no new validation.

Known difference, unchanged here: a wrongly typed override (`"profiler_kwargs": "invalid"`) gets Rust's JSON-body 400 where Python returns 422, as for the other three fields. `tests/entrypoints/serve/test_profile_api_router.py` is in-process and cannot run against the Rust frontend.

Not a duplicate: no open PR touches the Rust `/start_profile` route.
