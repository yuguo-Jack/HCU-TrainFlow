# [CI] Enroll two steps and two AMD mirrors in automatic sharding

[Upstream PR](https://github.com/vllm-project/vllm/pull/64115) · state: closed · merged: True

## Original PR description



## Overview

Enrolls four more CI jobs in automatic sharding (`automatic_shard: true`): two NVIDIA steps and two AMD mirrors, plus the base flag one mirror needs. Each step runs as parallel jobs planned from main's per-file timings. Follows #63907, #62537 and #62120. No test changes.

## Claims

| Step | Command shape | Planned shards |
|---|---|---:|
| `lm-eval-humming-h100-act` | two `pytest` over `evals/gsm8k` config lists | 6 |
| `amd-lm-eval-small-models-distributed-2xb200` | `pytest` over `evals/gsm8k` config lists | 3 |
| `lm-eval-small-models-distributed-2xb200` | one `pytest` | 1 (fits one job; enrolled so its mirror can shard) |
| `kernels-fusedmoe-layer-test-2-b200s` | two plain `pytest` files | 2 |
| `amd-multi-modal-models-standard-2-qwen3-gemma` | three `pytest` with `-m core_model` / `-k` | 2 |

- Every test of every command runs in exactly one shard, with the same environment and filters as today.
- Steps that run as one job today finish sooner; the slowest planned shard of each is under the 20-minute target.

## Validation

- Planned each step and mirror on this branch with ci-infra main's planner (including ci-infra#853) and main's timings; the plans match the table.
- Rendered each step with the pipeline generator and ran every shard's commands against a mock test tree, as a PR build and in main's OTel mode: every test ran in exactly one shard (6/6 NVIDIA cases, the single-job step skipped as expected; 4/4 AMD mirror cases).
- `/ci run` and a build scoped to the AMD Small Models Distributed mirror, which `/ci run` leaves behind the block step: every job passed, and every shard finished within the 22-minute bar. Per-command passed/skipped counts match main's last nightly for each sharded step, and machine time is within 6% of it. The scoped build ran after a rebase onto main; this PR's YAML did not change.

## Details

- **Why these.** They are the long single-job steps left after the earlier batches that the planner can split. Not duplicating an open PR: no open PR touches these keys (#61831, #62077 and #62513 enroll other steps).
- **`kernels-fusedmoe-layer-test-2-b200s`** runs just over the 20-minute target as one job and is planned by file into two uneven shards; included because it runs on most PR builds.
- **`lm-eval-humming-h100-act`** has main timings only since ci-infra#835 (full command labels), so its plan rests on few builds; the PR build checks the shard balance.
- **Timeouts unchanged (human).** `timeout_in_minutes` stays per job. A single-job fallback (no plan, or the `VLLM_CI_RUNTIME_SHARD` rollback switch) would run as before; fallback-aware timeouts belong in a central timeout setting.
- **Left out:** the MI355 Fusion E2E AR-RMS steps select their test by node ID, which the planner keeps whole; `multi-modal-models-extended-generation-1` until it passes on main reliably.
