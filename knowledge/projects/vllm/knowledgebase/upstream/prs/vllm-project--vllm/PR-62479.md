# [Bugfix][KV Cache] Preserve Mamba prefill offload handoffs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62479) · state: open · merged: False

## Original PR description

## Overview

Sparse GPU retention can suppress offload handoffs for valid Mamba prefill states. Offer the exact running-state block at a full, non-final prefill chunk boundary even when that block has no retained hash.

## Claims

- Restore missing prefill boundary offers while preserving GPU prefix-cache retention.
- Reuse the existing handoff contract, including speculative-block offsets; no LMCache changes are included.

349 core tests and 42 connector tests passed. The updated retention test fails in 8/20 cases without the fix and passes in all 20 with it. EAGLE cases allocate three speculative scratch blocks. Pre-commit passed.

Host-side tests used the current Python source and the existing CUDA wheel; CUDA initialization was prohibited. The offline environment includes the OPT-125m configuration at revision `27dcfa74d334bc871f3234de431e71c6eeba5dd6`.

Historical GLM-5.3-Flash validation: H20×8, TP8/MTP3, vLLM `a98247a`, retention=0, 30 GiB GPU KV/rank, 512 GiB CPU cache. Both arms used LMCache `7d7ca47` plus the same local boundary-store fixes; only this vLLM handoff change differed. A complete C8 comparison passed answer checks for 160/160 requests per arm. After natural GPU eviction, eight 48K prefix branches restored 0 → 348,160 aggregate CPU-cached tokens; both arms had zero GPU hits and 8/8 correct answers.

This is historical model evidence, not a model run on the new main baseline. A separate reverse-order baseline run stopped on a response-format error; no stable throughput claim is made here.

## Details

`block_hash is None` currently excludes a state from both GPU lookup and external handoff. A full prefill chunk's running state remains a valid external-cache source. The new path identifies that block after excluding speculative scratch and publishes its exact block ID and token boundary. Internal checkpoints and partial running blocks keep their existing handling.

More accepted handoffs can consume additional external-cache capacity and transfer bandwidth. Consumers remain responsible for pinning and fencing reads.

Duplicate checks found no matching open fix. #55142 addresses preemption of partial tails, #50551 retains finalized decode checkpoints, and #59522 changes Mooncake lookup leases. This change addresses normal full-chunk prefill handoffs under sparse retention.
