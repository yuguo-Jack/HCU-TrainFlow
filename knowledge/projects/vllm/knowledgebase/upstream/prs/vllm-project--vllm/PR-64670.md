# [Bugfix] Move offloaded A_log and dt_bias to the GPU in the Qwen GDN warmup

[Upstream PR](https://github.com/vllm-project/vllm/pull/64670) · state: open · merged: False

## Original PR description



## Overview

Fixes #64669. With CPU weight offloading and no UVA, Qwen GDN models fail to start because the Triton warmup passes the CPU-resident `A_log` and `dt_bias` to the kernels. This moves the two tensors to the cache's device when the warmup config is built.

## Claims

- `--cpu-offload-gb` without UVA (`VLLM_WEIGHT_OFFLOADING_DISABLE_UVA=1`, or WSL2 without `VLLM_WSL2_ENABLE_PIN_MEMORY=1`) starts Qwen GDN models again, with the same greedy output as a run without offloading.
- Nothing changes when the tensors are already on the GPU, resident or a UVA view, since `.to()` then returns the same tensor.

## Validation

vLLM main (this PR's base), RTX 4070 Ti SUPER 16 GB, WSL2, torch 2.14.0+cu130.

The new `test_gdn_weight_offloading_without_uva` offloads only `A_log` and `dt_bias` of Qwen3.5-0.8B without UVA and compares the greedy output with a resident run. It fails on main and passes with the fix:

```
$ cd tests && pytest -q basic_correctness/cpu_offload/test_cpu_offload.py -k gdn_weight_offloading
# main
E       ValueError: Pointer argument cannot be accessed from Triton (cpu tensor?)
FAILED basic_correctness/cpu_offload/test_cpu_offload.py::test_gdn_weight_offloading_without_uva
1 failed, 8 deselected, 22 warnings in 34.53s
# with the fix
1 passed, 8 deselected, 22 warnings in 41.63s
```

The issue's repro, extended to generate 24 greedy tokens for two prompts with `enforce_eager=True`:

| Run | main | this PR |
| --- | --- | --- |
| WSL2 defaults (no pinned memory), `cpu_offload_gb=1` | `ValueError` above | same tokens as without offloading |
| `VLLM_WEIGHT_OFFLOADING_DISABLE_UVA=1`, `cpu_offload_gb=1` | `ValueError` above | same tokens as without offloading |
| `VLLM_WSL2_ENABLE_PIN_MEMORY=1` (UVA), `cpu_offload_gb=1` | not run | same tokens as without offloading |

`vllm-sr/d3-flash` (Qwen3.5-9B backbone, served as a classifier) with `--cpu-offload-gb 6` under WSL2 without pinned memory also starts with the fix (checked on a nightly from 2026-10-23 with the change applied), and its answers on three requests match the checkpoint's own runtime (`trust_remote_code`, CPU) in every pick.

## Details

Without UVA, `UVAOffloader` sets `p.data` to a CPU tensor and wraps the module's forward in `functional_call` with device copies, so a parameter is on the GPU only during that forward. Since #46750, `_qwen_gdn_warmup_config` reads `layer.A_log` and `layer.dt_bias` outside any forward. Moving them in the warmup leaves the offloader alone. Both tensors hold `num_v_heads / tp_size` values, and the copy happens once at startup.

The existing `test_tower_weight_offloading[True]` covers the non-UVA path but offloads only the vision tower, so it did not reach the GDN layers.

This is separate from #60299, which turns CUDA graphs off for offloading without pinned memory. With CUDA graphs off, Qwen GDN models still stop at this warmup.

`kimi_k3_triton_warmup` passes `layer.A_log` and `layer.dt_bias` the same way in its speculative decode and Gluon KDA warmups. I left it out because I can't run Kimi-K3 here, and can add the same change if you'd like.
