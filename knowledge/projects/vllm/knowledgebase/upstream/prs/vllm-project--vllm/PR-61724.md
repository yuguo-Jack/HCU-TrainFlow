# [Perf][Core] Skip the null head of sliding-window block tables

[Upstream PR](https://github.com/vllm-project/vllm/pull/61724) · state: closed · merged: True

## Original PR description

## Purpose

A sliding-window KV group keeps one null block per out-of-window block, so a long request's block table is almost all null (8,183 of 8,192 entries for a 128K-token prompt with a 128-token window and 16-token blocks). `KVCacheBlocks.get_unhashed_block_ids_all_groups` and `SingleTypeKVCacheManager.free` walked every entry in Python. This PR skips that null head.

* `null_head_len()` finds the leading null run by binary search and checks it with one `list.count` of the shared null block. If the null blocks are not one contiguous head, it falls back to a scan.
* `get_unhashed_block_ids_all_groups` and `pop_blocks_for_free` (so both `free` and the deferred-free path) start after the head. `free_blocks` skips any other null blocks; the null block's `ref_cnt` is not maintained (see `BlockPool.__init__`).
* No behavior change: the same block ids are collected, and the same blocks reach the free queue in the same order.

Not a duplicate: I searched open PRs for `null block sliding window free`, `null_block free_blocks`, `sliding window null blocks` and `get_unhashed_block_ids`. vllm-project/vllm#42276 and #55818 change SWA eviction and allocation, not these walks.

## Where it matters

The cost is paid per sliding-window group, on the scheduler's critical path, each time a request is admitted with async KV loads or freed. It shows up when GPU steps are short and requests turn over quickly, as in **DeepSeek V4.1 Flash, WideEP DEP16 decode** (GB300, 64 requests/rank, 169.5K-token prompts):

* A decode step takes ~22 ms on the GPU, and all 16 DP ranks wait for the slowest rank's scheduler.
* Each rank admits and frees ~9 long requests per second.
* Each request has 8 sliding-window groups x 5,298 blocks, 5,292 of them null.

| Scheduler CPU per request | main | PR |
| -- | --: | --: |
| free | 2.0 ms | 0.5 ms |
| async-KV admission (135K prompt) | 0.73 ms | 0.47 ms |

End to end, output throughput went from 8,892 to 9,025 tok/s/GPU **(+1.5%).** 

## Microbenchmark

One request on one sliding-window group (window 128, block size 16): `KVCacheBlocks.get_unhashed_block_ids_all_groups` (collect) and `SlidingWindowManager.free` (free). Median of 300 calls on a Grace CPU, main (`8530aed2b7`) vs this PR, consistent across two runs.

| Prompt tokens | Blocks (null) | Collect, main / PR (us) | Free, main / PR (us) |
