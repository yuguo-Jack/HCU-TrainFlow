# [Bugfix][Rust Frontend] Include null finish_reason in streaming chat choices

[Upstream PR](https://github.com/vllm-project/vllm/pull/63739) · state: open · merged: False

## Original PR description

## Overview

Include `"finish_reason": null` in non-final streaming chat completion choices
from the Rust frontend, matching the Python frontend.

Related to #63656. This PR addresses only the `finish_reason` difference.

## Claims

- Include an explicit null `finish_reason` in non-final choices.
- Preserve the final finish reason and the `[DONE]` stream terminator.
- Extend the existing route regression test and document the behavior.

## Validation

The explicit-null regression assertion failed before the fix:
`left: None`, `right: Some(Null)`. It passes with the fix.

Commands run from `rust/`:

- `cargo test -p vllm-server stream_without_include_usage_keeps_existing_shape -- --nocapture`
  — passed.
- `cargo test -p vllm-server --lib`
  — 509 passed, 0 failed.
- `cargo clippy -p vllm-server --all-targets -- -D warnings`
  — passed.
- `cargo fmt -p vllm-server`
  — completed.

Applicable pre-commit checks on the three changed files and
`git diff --check` also passed.

Validation exercises the HTTP route and SSE serialization using a scripted
engine. No real-model evaluation was performed.

## Details

`#[serde_with::skip_serializing_none]` omits `finish_reason` when its value is
`None`. Adding `#[serialize_always]` to this field preserves it as JSON null,
while retaining the existing omission behavior for other optional fields.

The regression test checks every non-final choice for the presence of
`finish_reason` with an explicit null value. It also checks the final `"stop"`
reason, absence of usage when not requested, and the `[DONE]` terminator.

Other streaming differences described in #63656 remain outside this PR.

Duplicate-work checks found no matching open PR when searching for #63656
and related Rust streaming/null/finish_reason changes. #63061 addressed
non-streaming responses.

I also have a patch for #63656 that includes the same `finish_reason` fix and addresses the remaining reported serialization differences:

- Emit `logprobs: null` when absent.
- Preserve explicit nulls according to chunk type: `token_ids` on content/final choices, and `stop_reason` and `weight_versions` on final choices.
- Include `content: ""` in the initial role delta, plus `prompt_token_ids: null` and `prompt_text: null` when unset.
- Omit unset usage details on the usage-only chunk, including `prompt_tokens_details`.
- Include reasoning-token details when a reasoning parser is configured. Without one, omit them from final usage and emit `completion_tokens_details: null` on continuous-usage chunks.

The patch also adds HTTP/SSE regression coverage for complete chunk JSON, usage serialization, echo with requested token IDs, and reasoning-parser configuration, plus documentation. All 511 `vllm-server` tests passed using the scripted engine. The separate `system_fingerprint` value difference remains outside its scope.
