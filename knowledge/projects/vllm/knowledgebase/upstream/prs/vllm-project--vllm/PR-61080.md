# [Core] Add defer mode for long prefills

[Upstream PR](https://github.com/vllm-project/vllm/pull/61080) · state: open · merged: False

## Original PR description

## Purpose

Adds `--long-prefill-token-threshold-defer`, off by default. Instead of capping each long prefill at `long_prefill_token_threshold`, long prefills take turns:
- one long prefill per step;
- it runs after the waiting requests, with the leftover budget, if that is at least the threshold;
- one that sat out its turn runs first the next step.

**Why:** with context parallelism, each step costs a fixed amount, plus an amount for each request in it that grows with its context. On H200 (GLM-5.3, PCP8×DCP8, 8192 tokens per step) that is about 230 ms fixed, plus about 335 ms for a request at 1M context. Splitting the budget pays these costs more often. Under load the adaptive threshold also splits short cached prompts, which cuts throughput just when the queue is longest.

## Results

Agent X ([Weka trace](https://huggingface.co/datasets/semianalysisai/cc-traces-weka-062126)) with GLM-5.3 at 1M context on 16× H200: PCP8/DCP8 prefill → DP8 decode. This commit on an earlier main, all arms in one run, 20 minutes per point. Adaptive = threshold 2048 + adaptive; defer = threshold 2048 + defer.

| concurrency | arm | requests | TTFT p50 | p95 | p99 |
|---:|---|---:|---:|---:|---:|
| 32 | adaptive | 1186 | 1.3 s | 7.2 s | 105 s |
| 32 | no threshold | 1205 | 1.3 s | 7.7 s | 44 s |
| 32 | defer | 1176 | 1.4 s | 29.9 s | 66 s |
| 48 | adaptive | 464 | 1.7 s | 510 s | 559 s |
| 48 | no threshold | 762 | 2.6 s | 276 s | 326 s |
| 48 | **defer** | 744 | 3.7 s | **198 s** | **264 s** |

- **Under load (concurrency 48):** defer completes 60% more requests than adaptive, matches no threshold on throughput, and has the best tail.
- **Concurrency 32:** within run-to-run noise. A repeat of defer reached 1227 requests with p95 6.5 s, the best of all c32 runs. Variants that ran long prefills oldest-first or one at a time were worse (p95 32–35 s): medium prompts got stuck behind the largest one.
- **Noise:** the same arm varies by up to ±24% in requests between runs at concurrency 48.
- **Accuracy:** gsm8k is the same in all arms (0.728–0.740).
