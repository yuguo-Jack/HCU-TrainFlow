# [ROCm] Enable Gemma 4 image-prefix attention in ROCM_SEGMENTED_ATTN

[Upstream PR](https://github.com/vllm-project/vllm/pull/64424) · state: open · merged: False

## Original PR description

## Overview

Enable Gemma 4 image-prefix attention in the opt-in `ROCM_SEGMENTED_ATTN` backend, including BF16/FP8 KV cache and multiple images.

**Stack dependency: #62666 must merge first.** This branch contains the D=512 parent plus three MM commits. [Review the MM-only diff](https://github.com/big-yellow-duck/vllm/compare/ceaae9657fc6d13c86e329810ba4f641842b0adc...8c620ea4a2577c4bf2d870473d7ecee88e2fd5ea) against parent `ceaae9657f`. Targets `main` and temporarily includes the parent changes; it needs rebasing after #62666 merges.

## Claims

- Apply bidirectional attention within each image range, respecting Gemma's sliding-window clamping and preserving gaps between separate images.
- Widen native KV traversal before split partitioning so reopened past/future image keys reach the kernel; preserve MM masks in the unified fallback.
- Extend the parent's typed `segmented_attention_config.py` with image-aware selection and separately keyed optional startup tuning. Automatic backend selection remains unchanged.

## Details

Image ranges are propagated through backend metadata using the existing shared range utility. Finished image prefixes are filtered using CPU prefill metadata, so causal text/decode can reuse the text path. The main execution path adds no GPU tensor scalar reads; tuning remains a startup operation. Shared Triton helper/fallback fixes are exercised by the numerical fallback and existing segmented cases. No scheduler or model-runner changes remain in the MM-only diff.

The extra host logic is primarily backend-local image-profile selection, cache isolation and bounded tuning reuse. Image span/range count distinguish MM records from causal text records. Static selection works without startup tuning; tuning can increase first-start cost.

Usage is documented in [Attention Backend Feature Support](https://github.com/big-yellow-duck/vllm/blob/edc90a09d0ed182743becd93edc5720237a8c9a4/docs/design/attention_backends.md#rocm-segmented-attention):

```bash
vllm serve RedHatAI/gemma-4-12B-it-FP8-Dynamic \
    --dtype bfloat16 --kv-cache-dtype fp8 \
    --max-model-len 8192 --max-num-batched-tokens 4096 \
    --attention-backend ROCM_SEGMENTED_ATTN
```

Optional tuning: `--kernel-config '{"enable_rocm_segmented_attn_autotune":true}'`. FP8 KV retains the parent's gfx12 restriction. RDNA GPU coverage is local; CI on NVIDIA/MI300 cannot exercise these native RDNA kernels. Existing attention CI selects the host suite, while the RDNA numerical runs above provide hardware-specific validation. Validation reused existing compiled extensions. A clean wheel rebuild and quality coverage beyond single-image ChartQA remain additional validation.

Duplicate-work check: no existing PR from this head or an identical segmented-MM enablement was found. #60317 optimizes unified Triton attention; #63383 adds a separate gfx1151 HIP backend. This extends the existing segmented Triton backend on top of #62666.

AI assistance was used for implementation, validation analysis, documentation and this PR. The human submitter remains responsible for review and validation.
