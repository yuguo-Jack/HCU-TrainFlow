# [Bugfix][Attention] Zero reused FlashInfer MLA KV blocks

[Upstream PR](https://github.com/vllm-project/vllm/pull/58716) · state: open · merged: False

## Original PR description

## Why

FlashInfer MLA kernels can consume values from the unwritten suffix of a KV-cache block. When a recycled block still contains non-finite data from its previous owner, masking is insufficient (`0 * NaN` remains NaN), which can corrupt attention outputs.

vLLM already has a scheduler-to-worker path for zeroing newly allocated KV blocks, but uniform-precision attention models do not currently enable it. This change adds a generic attention-backend capability and opts in only FlashInfer MLA dense/sparse today.

## Summary

- Add a generic `AttentionBackend.requires_kv_cache_zeroing` capability and publish it on the base `AttentionSpec`.
- Preserve the capability across attention-spec merges, uniform-type scheduler projection, and composite backends.
- Enable it for FlashInfer MLA dense and all registered FlashInfer MLA sparse variants, including DeepSeek V4/V4.1 compressed and sliding-window caches.
- Leave FlashMLA dense/sparse and all other attention backends unchanged.

## Reviewer guide

- `vllm/v1/attention/backend.py` and `vllm/v1/kv_cache_interface.py` contain the core logic: the generic backend opt-in, base attention-spec metadata, merge propagation, and zeroing decision.
- `vllm/v1/core/kv_cache_utils.py` preserves the capability when a `UniformTypeKVCacheSpecs` group is collapsed for the scheduler.
- `vllm/v1/attention/backends/composite.py` ORs the requirement from either child backend.
- The FlashInfer backend files only opt the relevant dense/sparse backend classes into the generic capability.
- The tests cover backend scoping and propagation through base/MLA, sliding-window, uniform-type, and composite paths.
- No kernel or block-zeroer implementation changes are needed; this uses the existing newly-allocated-block zeroing pipeline.

## Duplicate check

This is not a duplicate of the closest related work:

- #51749 generalized the existing worker zeroer to all `AttentionSpec` subclasses, but did not enable zeroing for uniform-precision MLA configurations.
- Closed, unmerged #37530 enabled zeroing for every MLA backend; this change is deliberately restricted to FlashInfer MLA dense/sparse.
- #52187 optimizes zeroing by cache group.
- #57158 restores the reserved null block after CUDA graph capture.
- #55085 zeroes unwritten tails after partial Mooncake loads.
