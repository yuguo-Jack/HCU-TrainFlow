# [CI] Run PyTorch Compilation root tests in one pytest, with test_config.py's forked tests spawned

[Upstream PR](https://github.com/vllm-project/vllm/pull/65514) · state: open · merged: False

## Original PR description



## Overview

Alternative to #65476: run the PyTorch Compilation root tests (`tests/compile/test_*.py`) in one plain pytest, make `test_config.py`'s seven `@pytest.mark.forked` tests spawn instead of fork, and restore the default device after each compile test. Enrolls the step and its MI300 mirror in `automatic_shard`. Draft for comparison; only one of the two should merge.

## Claims

- The same 13 root files run, and a new root file is picked up without a YAML edit (`--ignore-glob='compile/*/*'` skips subdirectories, which run in their own steps).
- `test_config.py` no longer fails or hangs when an earlier file in the session has initialized the GPU.

## Validation

- Without the test change, one pytest fails: build [99664](https://buildkite.com/vllm/ci/builds/99664) had 12 `test_config.py` failures with `Cannot re-initialize CUDA in forked subprocess` on NVIDIA, and the MI300 job hung in the same file.
- Pending: `/ci run` on this head; totals and test IDs to compare with main.

## Details

- **Root cause (#28965):** pytest-forked always uses `os.fork`, so `VLLM_WORKER_MULTIPROC_METHOD=spawn` and `create_new_process_for_each_test()` didn't help. `create_new_process_for_each_test("spawn")` runs the same test function in a fresh interpreter, which is already how these helpers run on ROCm.
- **What can differ in the child:** fixture effects that live only in the parent's memory. `use_fresh_inductor_cache` sets the cache directory through the environment, which the child inherits; the env changes the tests make with `monkeypatch` happen inside the child.
- **Default device:** `test_compile_ranges.py`, `test_graph_partition.py` and `test_structured_logging.py` call `torch.set_default_device` without undoing it, which in one process would move later files' implicit-device tensors (for example in `test_wrapper.py`) onto the GPU. An autouse fixture in `tests/compile/conftest.py` restores the default device after each test that changed it.
- **Known limit:** other process-wide state could still leak between files; a pass shows the current order works, not every order.
- **Versus #65476:** that PR keeps one process per file and needs a YAML line per new root file; this one keeps automatic inclusion but changes how seven tests are isolated.
