# [Bugfix][Spec Decode] Warn on near-zero draft acceptance

[Upstream PR](https://github.com/vllm-project/vllm/pull/61084) · state: open · merged: False

## Original PR description

## Overview

Adds a one-shot warning for sustained near-zero speculative draft acceptance, addressing the pairing-diagnostics request in #61072.

## Claims

- Accumulates drafted and accepted token counts across periodic logging intervals.
- At the first scheduler-step boundary where at least 4,096 draft tokens have been observed, evaluates acceptance and warns once if it is below 1%.
- Keeps canary state separate from interval buffers so `reset()` does not reset the early-run window; excludes diffusion because its counters have different semantics.
- Treats near-zero acceptance as a symptom with multiple possible causes, not proof that the pairing is invalid.
- Does not change scheduling, sampling, rejection sampling, or model outputs.

## Details

The scheduler already aggregates accepted and drafted token counts, and periodic metrics report average draft acceptance. This adds a small canary to `SpecDecodingLogging` so that a sustained near-zero rate triggers a one-time warning rather than only appearing in the periodic info log. The canary accumulates across log intervals and evaluates when a scheduler step brings the observed draft-token total to or beyond 4,096.

**Why this is not a duplicate:** I checked the open PRs for #61072 and searched for near-zero/speculative draft-acceptance diagnostics. I found no existing PR that adds this warning. #60365 addresses a separate reduced-vocabulary candidate-to-target-token mapping bug; it does not provide this runtime acceptance warning.

This PR covers only the diagnostics portion of #61072. Draft-embedding dtype/quantization changes and full-vocabulary logits workspace chunking are out of scope.
