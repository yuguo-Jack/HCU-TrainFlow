# [CI][ROCm] Export kernel source maps for CI selection

[Upstream PR](https://github.com/vllm-project/vllm/pull/59100) · state: open · merged: False

## Original PR description

- Add a ROCm kernel-to-source map producer that reads the actual CMake/Ninja objects, including host uses, header dependencies, and embedded GPU architectures.
- Record HIPify provenance for generated sources and copied or renamed headers while leaving the original sources intact.
- Preserve the original vendor header and repository patch as dependencies of generated Torch headers.
- Generate maps in an opt-in stage after native compilation and expose a separate Docker export target.
- Export and upload the map with its build commit after a successful build or image reuse, clearing stale exports; optional map failures leave the image job successful.
- Forward recorder output and job identity from single-node AMD Docker jobs to the agent's artifact directory.
- Run producer, provenance, export, and runner regressions through the existing CMake and Docker metadata test jobs.

NVIDIA image builds already export kernel source maps for the CI selector. ROCm needs the same ownership information, but its native build transforms CUDA sources and headers into HIP inputs. The map uses the retained compilation and dependency records to recover those original paths and refuses incomplete or unsupported builds. This supplies the source half of the companion native SDK recording path, allowing CI to join observed kernel names to repository changes without guessing ownership.

Companion: [ci-infra native recording and selection for both backends](https://github.com/vllm-project/ci-infra/pull/685). Its consumers should be deployed before enabling the new map and recorder producers.

AI assistance was used to implement these changes and run the validation.
