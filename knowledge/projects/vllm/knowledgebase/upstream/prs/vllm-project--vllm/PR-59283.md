# [Core][HiSparse] Keep unpinned blocks last in the free queue

[Upstream PR](https://github.com/vllm-project/vllm/pull/59283) · state: open · merged: False

## Original PR description

## Purpose

**Optional performance improvement, stacked on #59282.** #59282 fixes the crash on its own; this PR only affects how many HiSparse GPU prefix copies survive memory pressure, and so how many prefix pages are read from host instead.

`BlockPool.unpin_blocks` documents unpinned blocks as "last-resort eviction candidates", but it appends them to the free queue like any other block, so blocks freed afterwards are queued behind them. In #59282's scenario, a finished request's cached indexer block is freed after its MLA copies were unpinned, so the resumed request's allocation evicts a copy it was about to adopt while that indexer block survives.

## Changes

- `FreeKVCacheBlockQueue` keeps a last-resort segment at its tail: `append`/`append_n` insert in front of it, the new `append_last_resort_n` appends behind it, and `popleft`/`popleft_n`/`remove` advance its head when they take it.
- `BlockPool.unpin_blocks` uses `append_last_resort_n`, which makes its documented behavior true.

Only the HiSparse coordinator unpins blocks. Without unpinned blocks the segment is empty and the queue orders blocks exactly as before, at the cost of one pointer comparison per popped or removed block.

This does change HiSparse's eviction policy: unpinned blocks, meaning finished requests' copies and pages a running request released but still reads, now outlast every ordinary cached block rather than aging in LRU order. Evicting either kind forces reads from host.

Copies kept in #59282's scenario:

| `free_blocks` | #59282 | this PR |
|---|---|---|
| 7–8 | 0/3 | 0–1/3 |
| 9 | 1/3 | 2/3 |
| 10 | 2/3 | 3/3 |
| 11+ | 3/3 | 3/3 |
