# [Bugfix][ROCm] Fix GPTQ half/half2 atomicAdd on ROCm 7.13 nightlies

[Upstream PR](https://github.com/vllm-project/vllm/pull/57510) · state: open · merged: False

## Original PR description



## Purpose

Fixes #57494.

`gptq/compat.cuh` only defines the `half`/`half2` `atomicAdd` overloads for HIP < 7.13 (#41802). It assumes ROCm 7.13 provides them natively. They were only added partway through the 7.13 nightly series (ROCm/rocm-systems#5194, merged 2026-04-29), so older 7.13 nightlies fail to build `q_gemm.cu` with `no matching function for call to 'atomicAdd'`. Nightlies around the change hit ambiguous overloads instead (ROCm/rocm-systems#6210). A HIP version check can't handle both, because every 7.13 nightly reports the same version.

This PR adds a `gptq_atomic_add` wrapper in `compat.cuh`. On ROCm it always uses the existing CAS-based `atomicAdd_half` / `atomicAdd_half2` helpers, and on CUDA it calls `atomicAdd` as before. All 10 call sites in `q_gemm.cu` use it, and the `atomicAdd` overload guard is now CUDA-only. CUDA behavior is unchanged.

Not a duplicate: no open PR references #57494 or touches the GPTQ `atomicAdd` code.

## Test Plan

Standalone harness that includes the real `compat.cuh` and calls `atomicAdd` (main) / `gptq_atomic_add` (this PR) on `half*` and `half2*`, as `q_gemm.cu` does:

- ROCm compile with TheRock SDK `7.13.0a20260424` (the SDK from #57494):
  `hipcc -x hip --offload-arch={gfx1151,gfx942} -DUSE_ROCM -c test_atomic.cu`
- CUDA 12.6 compile: `nvcc -arch=sm_{60,70,75,80,90} -c test_atomic.cu`
- GPU run on a GTX 1650 (sm_75): 1792 concurrent atomic adds over 7 slots, including odd (2-byte-aligned) `half` addresses, checked for exact sums.
- `pre-commit run --files` on both changed files.
