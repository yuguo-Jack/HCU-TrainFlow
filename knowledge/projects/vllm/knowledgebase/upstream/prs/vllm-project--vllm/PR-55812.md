# [Metrics] Add admission rejection metrics

[Upstream PR](https://github.com/vllm-project/vllm/pull/55812) · state: closed · merged: True

## Original PR description

## Purpose

Follow-up to #49445. Admission limits reject requests with HTTP 503, but operators cannot tell from metrics which queue cap fired (`max_num_queued_reqs` vs `max_num_queued_tokens`), and each rejection logged at INFO.

This adds `vllm:admission_rejections_total` (`reason` label, no `engine` label). The unit is one rejected frontend admission attempt; `n > 1` still increments by one. The counter is incremented in `check_admission` through `StatLoggerManager`, matching the sleep-state side door: this event never appears in `EngineCoreOutputs`.

Per-rejection diagnostic messages move from INFO to DEBUG now that the counter exists (requested on #49445 until metrics landed).

Not duplicating:
- #53936 (atomic `n > 1` admission) remains a separate core change.
- #54746 (shared occupancy) is a different feature.
- No other open PR implements `admission_rejections`.

## Test Plan

```bash
VLLM_TARGET_DEVICE=cpu .venv/bin/python -m pytest -q tests/v1/engine/test_admission_control.py
```

Existing admission tests now also assert Prometheus samples (success stays at 0, each reject reason increments once, request-cap-first, `n > 1` still +1). `vllm:admission_rejections_total` is listed in `EXPECTED_METRICS_V1`.
