# [ROCm] Enable fp8 query for Triton attention

[Upstream PR](https://github.com/vllm-project/vllm/pull/60296) · state: closed · merged: True

## Original PR description



## Overview

1. Enabling fp8 attn for fp8 KV cache for hardware-capable AMD GPUs, a new PR to replace stale #37973.
2. Adding RDNA3 to `rocm.supports_fp8()` API to allow fp8 moe models to work on RDNA(similar to gfx90a now)

## Claims
`TRITON_ATTN` backend is still being used for multimodal models(Gemma3, Gemma4 etc) as both `ROCM_ATTN` and AITER don't have this support.

This flag enablement should be safe; later in attention.py https://github.com/vllm-project/vllm/blob/bb87d227d4b964abb2a966cdf9194f3d376d9bbe/vllm/model_executor/layers/attention/attention.py#L469
`self.kv_cache_dtype.startswith("fp8")` explicitly checks if the quantization is fp8.

## Validation

One thing worth knowing: on gfx11 the linear layers only have a kernel for block-scaled FP8 (TritonFp8BlockScaledMMKernel). Yes, exactly. The Triton compiler does this behind the scene when using `tl.dot()`, for GPUs that doesn't support fp8 MMA. The `supports_fp8()` function is used at model load time, so its closest meaning is "is this fp8 model runnable on this GPU".

Thus, that function shouldn't be used in this case. I made the change and also added gfx11 to `supports_fp8()` to match the desired behaviour. This enables gfx11 to run fp8 MOE models. (TRITON dequantizes on the fly like gfx90a)
