# [Test][UMBP] Cover end-to-end restore while the embedded DRAM pool is evicting

[Upstream PR](https://github.com/vllm-project/vllm/pull/64658) · state: closed · merged: True

## Original PR description

- Let the `umbp_llm` fixture take pool options through indirect parametrization.
- Add `test_restore_under_pool_eviction` on a 64 MiB pool: the newest prompt restores exactly, the oldest is evicted.

The existing end-to-end UMBP tests never fill the pool, so the connector and scheduler path under eviction never runs, and `test_mori_embedded_gpu.py` only overfills it at the runtime level. Prompts run one at a time so MORI's LRU commit order is deterministic, and the pool size assumes Qwen3-0.6B KV on MORI's 64 KiB pages. On MI350X with MORI v1.2.3.post1 built with UMBP, `pytest -v -s -rs v1/kv_connector/umbp_integration/test_mori_token_e2e.py` gave 3 passed and the new test passed 10/10 in a loop. With a 1 GiB pool the same flow restores the oldest prompt in full, so the miss comes from eviction. While probing this we found that equal watermarks, or a high watermark at or below MORI's default low of 0.7, silently disable eviction; that fix is a separate PR. No open UMBP PR covers end-to-end restore under eviction.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
