# [ROCm][Bugfix] Fix Triton paged decode leaving output heads unwritten on gfx942

[Upstream PR](https://github.com/vllm-project/vllm/pull/63268) · state: closed · merged: True

## Original PR description

- `chunked_prefill_paged_decode.py`: offset the output pointer to the token's row as a 64-bit scalar and keep the per-head store offsets 32-bit.
- `test_prefix_prefill.py`: fill the output with NaN, so a row the kernel skips fails every time instead of passing on leftover memory.

`test_qwen3_nonstandard_block_size[True-chunked_prefill_paged_decode-...-8-4-256-1056]`, added with the interleaved V cache in #42755, fails on MI300 intermittently ([build 96693](https://buildkite.com/vllm/ci/builds/96693/list?jid=01a164e7-c489-4e2d-9709-6796df461d5f&tab=output)). Locally it fails 6 of 20 runs on main. The Triton decode kernel only writes 263 of the decode token's 2048 output values, so the result depends on whatever memory the output buffer reuses. The kernel's logic is correct: under `TRITON_INTERPRET=1`, or with `AMDGCN_USE_BUFFER_OPS=0`, every value is written. The LLVM IR computes the 64-bit head offset correctly, but in the gfx942 ISA the `output_stride_1` argument is never read and the head index is multiplied by an unrelated spilled SGPR instead (the block-table row offset, in the variant traced). Rows land at the wrong offsets, so most values are left unwritten and some heads overwrite others. This only happens in variants with hundreds of SGPR spills; computing the per-head offset in 32 bits avoids it, so the change is a workaround for a backend miscompile. The interleaved V path is not the only one affected: the normal layout loses outputs too, on the Triton fallback with 128 and 256 token pages at head size 128 and 256, which hybrid models with large pages can hit. On a decode-only sweep of 60 head-size, GQA, page-size and layout combinations, 18 dropped stores before this change and none after; kernel time changes by -0.4% to +1.4%.

Tests: `pytest kernels/attention/test_prefix_prefill.py` 10/10 (205 passed each; the updated test fails 3/3 without the kernel change), and `pytest v1/attention/test_attention_backends.py v1/attention/test_rocm_attention_backends_selection.py` (201 passed).
