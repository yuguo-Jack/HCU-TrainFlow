# [Bugfix][Model] Nemotron 3.5 Super VL: support the native transformers config

[Upstream PR](https://github.com/vllm-project/vllm/pull/64506) · state: closed · merged: True

## Original PR description



## Overview

Lets `NemotronH_Omni_Reasoning_V3` checkpoints (Nemotron 3.5 Super VL) run without `--trust-remote-code` on transformers ≥ 5.18.

Related to #63470. Alternative to #64030 (see Details).

## Claims

- `nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-*` serves without `--trust-remote-code` when transformers ≥ 5.18 is installed.
- `--trust-remote-code`, older transformers versions, and the existing Nano VL / Nano Omni checkpoints behave as before.
- CI now initializes the model from transformers' built-in `nemotron_h_omni` config.
- `supported_models.md` lists the architecture and the transformers ≥ 5.18 requirement for running without the flag.

## Validation

**Serving:** `vllm serve nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-NVFP4`, with and without `--trust-remote-code`, on transformers 5.18.0. Both load and serve correctly. Without the fix, the run without the flag fails at model init with:

## Details

**Root cause.** Transformers 5.18 added a built-in `nemotron_h_omni` config. The Super VL checkpoints declare `"model_type": "nemotron_h_omni"`, so `AutoConfig` loads that class without remote code. The built-in class renames `vit_hidden_size` to `vision_hidden_size`, but `NemotronH_Nano_VL_V2.__init__` read `config.vit_hidden_size`.

**Fix.** Read `vision_hidden_size`, the name the built-in transformers config uses, and fall back to `vit_hidden_size`, which the remote-code configs use:

| Config | Field |
|---|---|
| Transformers built-in `nemotron_h_omni` (≥ 5.18) | `vision_hidden_size` |
| Checkpoint remote code (`--trust-remote-code`) | `vit_hidden_size` |
| Nano VL / Nano Omni checkpoints | `vit_hidden_size` |

**Test.** The `NemotronH_Omni_Reasoning_V3` registry entry was an offline placeholder. It now points at `nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-BF16` without `trust_remote_code`, gated on transformers ≥ 5.18.0. The built-in `NemotronHConfig` derives `hybrid_override_pattern` from `layers_block_type` and doesn't allow setting it, so the 2-layer override sets `layers_block_type` instead. The "Basic Models (Extra Initialization)" CI step selects this test.

**Why not #64030.** #64030 copies the remote-code config and image processor into vLLM, about 520 lines. Transformers ≥ 5.18 already provides the config, and serving goes through `NanoNemotronVLProcessor` either way, so vLLM only needs this one field read. This matches #60623, which removed configs vLLM had copied once Transformers shipped them.

**Limitations.**
- **Older transformers:** on transformers < 5.18, `--trust-remote-code` is still required.
- **Audio:** the built-in config also renames `sound_config` → `audio_config`, which vLLM doesn't read. The Super VL checkpoints have no audio, but a future checkpoint that loads with the built-in config and includes audio would have audio switched off with no error. Left for a follow-up.
- **Recipe:** the Super VL recipe keeps `--trust-remote-code` until a release includes this fix. Its pinned image (v0.31.0) doesn't have it.
