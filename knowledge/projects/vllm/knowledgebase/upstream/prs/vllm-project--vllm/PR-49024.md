# [Doc] Add stream tracker middleware example for live per-request visibility

[Upstream PR](https://github.com/vllm-project/vllm/pull/49024) · state: open · merged: False

## Original PR description

## Purpose

Two gaps, one example:

1. The `--middleware` flag of the OpenAI-compatible server currently has no
   example and no documentation anywhere in the repo (the only `middleware`
   hit under `examples/` is an unrelated inline logger in the EPD proxy).
2. There is no way to see what individual in-flight requests are doing.
   `/metrics` and `/load` are aggregate by design — per-request metric labels
   are a cardinality anti-pattern (#36189) — and OTel tracing reconstructs
   requests after the fact. When running tens of concurrent streams there is
   no "what is every stream doing *right now*" surface.

This adds `examples/observability/stream_tracker/`: a self-contained,
observe-only ASGI middleware loaded via `--middleware` that answers
`GET /streams` with a live snapshot of active and recently finished
completion requests — id, state (`pending` / `streaming` / `done` /
`error` / `aborted`), age, prompt preview, token count so far, and current
tokens/s.

Demo — a dashboard built on this endpoint, watching 40 concurrent streams
on a DGX Spark: https://x.com/PassingPixels/status/2078242471125868994

Because it ships as an example rather than a server change, it adds no new
flags, routes, or metric series, and creates no API commitment — it is the
same pattern as `examples/observability/opentelemetry/`, applied to the
`--middleware` hook.

Design notes:

- Response bytes are forwarded verbatim; the middleware never buffers or
  rewrites frames, and every tracking step is exception-guarded so an
  internal fault cannot affect the request being served.
- Token counting is SSE-framing-exact: markers are matched as `\ndata:`
  (carry-buffer across frame splits), so a literal `data:` inside generated
  content (code, data URLs) is never miscounted.
- `asyncio.CancelledError` is finalized as `aborted` (client disconnect),
  distinct from `error`, and re-raised untouched.
- Bounded memory: request-body tee capped at 512 KiB, completed ring of 50,
  active-table cap of 256.

## Test Plan

- Unit-style harness driving the middleware against a scripted ASGI app
  (41 assertions): byte-identical forwarding on tracked, untracked, and
  fault-injected paths; exact token counts across pathological SSE frame
  splits (mid-marker, multi-event frames, `data:` inside payload content);
  preview extraction (chat string + content-parts + completions, 512 KiB
  truncation); disconnect/cancellation/error state classification;
  ring-buffer bounds; 8 concurrent streams with a mid-flight snapshot.
- Live: served Qwen3.6-35B-A3B (NVFP4) on a DGX Spark (GB10) with the
  middleware loaded; ran 40 concurrent streaming clients against a
  `--max-num-seqs 30` engine. `/streams` tracked all 40 (30 streaming,
  10 pending), per-stream rates matched the aggregate Prometheus decode
  rate, and completions drained into `recent` with correct end-to-end
  timings. Throughput was indistinguishable from runs without the
  middleware.

## Test Result

All 41 harness assertions pass; live snapshot output is shown in the
example README, and the linked demo above shows the endpoint driving a
live dashboard under 40-stream load.
