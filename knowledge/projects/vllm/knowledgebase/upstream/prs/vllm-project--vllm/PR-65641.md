# [ROCm][CI] Skip the GPU coredump in MonoKernel fault-injection tests

[Upstream PR](https://github.com/vllm-project/vllm/pull/65641) · state: closed · merged: True

## Original PR description

## Overview

Turns off the GPU coredump for the two tests in the `:amd: (MI355) MiniMax M3 MonoKernel` group that inject a rank fault on purpose. They spend most of their time writing a dump nobody reads.

## Claims

- The two tests are 74% of the group's runtime (782.52s of 1058.67s in build 96864).
- No coverage change: same tests, same assertions, same count.
- Scope is those two tests only, because only they are written to crash.

## Details

The group is defined in `.buildkite/test_areas/models_basic.yaml` (key `minimax-m3-monokernel-mi355`, `device: mi355_4`), and mirrored internally as `(MI355) MiniMax M3 Specialized Decode`.

Both tests arm `_arm_late_fault` and assert `EngineDeadError`, so the fault is expected. When a rank faults, `libhsa-runtime64` writes a file-based dump and the worker stays alive while writing. The executor never sees it die, so it waits out the full `VLLM_EXECUTE_MODEL_TIMEOUT_SECONDS` (300). With the dump off the worker dies, its response queue closes, and `mq.dequeue` raises right away.

The same thing is already done on the NVIDIA side, by #61263, for a test that also crashes a kernel on purpose: `test_hisparse_expanded_hash_keeps_union_bound` in `tests/v1/attention/test_sparse_mla_backends.py` passes `CUDA_ENABLE_COREDUMP_ON_EXCEPTION=0`. That one belongs to the `Attention` group's `(B200) V1 Attention` step. There was no ROCm equivalent anywhere in the repo.

The fixture is function-scoped and not `autouse`, so it covers only the two tests written to crash. Everything else in the group keeps the default behaviour.
