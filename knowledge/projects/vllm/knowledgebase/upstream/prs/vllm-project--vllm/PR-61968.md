# [ROCm][DSv4.1][Perf] gfx942 sparse MLA decode: BLOCK_K=16 with 2-stage pipelining

[Upstream PR](https://github.com/vllm-project/vllm/pull/61968) · state: open · merged: False

## Original PR description

On gfx942 the split-K sparse MLA decode kernel was running with the 32-row K tile that was tuned for gfx950, and a single-stage loop

That loop is latency bound, not compute bound. Each iteration loads the slot indices for the tile, gathers that many scattered rows (fp8 nope + bf16 rope) and their scales out of the paged cache, dequantizes them, then does two small dots against a few heads. The dots are tiny, so with `num_stages=1` the MFMAs mostly sit idle waiting on the current tile's gather

The fix is to let Triton pipeline the loop. With `num_stages=2` the next tile's index load and row gather are issued while the current tile is still in the dots. Holding two 32-row tiles in flight is a lot of on-chip storage for MI300X (64 KiB LDS per CU, MI355X has 160 KiB), so the tile drops to 16 rows, where two fit comfortably. Smaller tiles also waste less work on the masked tail of each split

`block_k` also feeds `_decode_num_splits`, so the split count on gfx942 can shift a bit for the same batch. That's expected, the heuristic is already written in terms of `block_k`

gfx950 has its own partial kernel and split heuristic, both tuned around 32-row tiles with a lot more LDS, so it's left alone. Archs that are neither gfx942 nor gfx950 take the generic fallback earlier in the function and don't see this either

Numerics: same math, and the online softmax still accumulates in fp32. Only the order the KV rows are reduced in changes (tile size and split boundaries), so outputs differ from before at bf16 rounding level, not bit for bit

No other open PR changes this tile. #57880 is in the same function but only touches the gfx950 split logic, and it is still open, so there is a small conflict risk if both land close together. #61967 sends big decode steps to the HIP kernel, while this Triton path still handles small steps and builds without the HIP op
