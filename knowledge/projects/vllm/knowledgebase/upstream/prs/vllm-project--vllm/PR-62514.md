# [Perf][Kernel] Single-pass register-resident rms_norm_per_block_quant kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/62514) · state: open · merged: False

## Original PR description

## Purpose

During the performance investigation of fused `RMSNorm + per_block_quant` in #61073 (credit to @daniildiveev's detailed H100 SXM5 microbenchmarking in [Phase 4 of `RESULTS.md`](https://github.com/daniildiveev/llm-inference-perf-notes/blob/845e7c62b79f1d6dcaa7433961b5931dbfca56da/2026-10-15_h100sxm_fusion-remeasure/RESULTS.md)), we identified why the existing fused `rms_norm_per_block_quant_kernel` in `csrc/quantization/fused_kernels/fused_layernorm_dynamic_per_token_quant.cu` underperforms at small token counts and **regresses by 12–40% against the unfused 2-kernel baseline** (`fused_add_rms_norm` + `per_token_group_quant_fp8`) at $T \ge 512$:

1. **Three separate global-memory passes over `input` and `residual`:**
   - **Pass 1 (`vllm::vectorized::compute_rms`):** Reads `input` ($2d$ bytes) and `residual` ($2d$ bytes) from global memory to compute $\text{rms} = (\frac{1}{d}\sum_i x_i^2 + \epsilon)^{-1/2}$, discarding `x` afterward.
   - **Pass 2 (`vllm::vectorized::compute_dynamic_per_token_scales`):** Re-reads `input` ($2d$ bytes), `residual` ($2d$ bytes), and `weight` ($2d$ bytes) from global memory, writes per-thread maxima into a `4096 B` shared memory array (`__shared__ float s_max_vals[1024]`), performs a two-stage shared-memory + warp reduction across two `__syncthreads()` barriers, and writes `scales` to global memory.
   - **Pass 3 (`vllm::vectorized::norm_and_quant`):** Re-reads `input` ($2d$ bytes), `residual` ($2d$ bytes), `weight` ($2d$ bytes), **and re-reads `scales` from global memory**, writes updated `residual` ($2d$ bytes), and quantizes to `output` ($d$ bytes).
   - At $T \ge 512$ ($d = 4096$), the working set exceeds L1 and begins thrashing L2 across concurrent CTAs, turning the 3 passes over `input` and `residual` into redundant HBM/L2 traffic ($25\text{ B/elem}$ vs $9\text{ B/elem}$ minimum with residual).

2. **Shared-memory reduction overhead and non-power-of-2 group mapping:**
   - `compute_dynamic_per_token_scales` allocates `4228 B` of static shared memory per CTA (`s_max_vals[1024]` + `cub::BlockReduce` storage), executes **5 `__syncthreads()` barriers** per token, and computes `threads_per_group = blockDim.x / num_groups`. When `num_groups` does not evenly divide `blockDim.x` (e.g., $d = 5120 \implies 40$ groups with `blockDim.x = 512`, or $d = 7168 \implies 56$ groups), integer division/modulo introduces straggler loop iterations and cross-warp shared-memory gather overhead.

---

## Solution: Single-Pass Register-Resident Kernel with 16-Byte Vector Loads (`VEC_SIZE = 8`) & Sub-Warp Shuffle Reduction

We introduce `vllm::vectorized::rms_norm_per_block_quant_single_pass` (and `rms_norm_per_block_quant_single_pass_kernel`) for `hidden_size <= 8192` (`group_size == 128` or `64`):

```mermaid
flowchart LR
    subgraph Old["Upstream 3-Pass Kernel (5 __syncthreads, 4228 B smem)"]
        direction TB
        O1["Pass 1: Read input + residual -> compute_rms"] --> O2["Pass 2: Re-read input + residual + weight -> s_max_vals[1024] -> write scales to GMEM"]
        O2 --> O3["Pass 3: Re-read input + residual + weight + scales -> write residual & FP8/INT8 out"]
    end

    subgraph New["New Single-Pass Kernel (2 __syncthreads, 132 B smem, 16B Loads)"]
        direction TB
        N1["Phase 1: 16B load input (+ residual -> 16B write residual once), keep x_vals in regs, accumulate ss"] --> N2["CTA RMS Reduction: cub::BlockReduce<float, 1024> -> s_rms (132 B smem)"]
        N2 --> N3["Phase 2: 16B load weight, compute normed in regs, sub-warp __shfl_xor_sync absmax -> write scales & 8B FP8/INT8 out"]
    end
```

- **1 Global Load Pass with 16-Byte Vector Transactions (`VEC_SIZE = 8` for BF16/FP16):** Parameterized over `(VEC_PER_THREAD, VEC_SIZE)` using `vec_n_t<scalar_t, VEC_SIZE>` and `q8_n_t<scalar_out_t, VEC_SIZE>`. For 2-byte `bf16`/`fp16` types (`input_stride % 8 == 0`), each thread issues wide 16-byte (`vec_n_t<scalar_t, 8>`, `LDG.E.128` / `STG.E.128`) loads/stores for `input`, `residual`, and `weight` and 8-byte (`q8_n_t<scalar_out_t, 8>`) vectorized stores for quantized outputs (`VEC_PER_THREAD = 1, VEC_SIZE = 8` for `8` elements/thread; `VEC_PER_THREAD = 2, VEC_SIZE = 8` for `16` elements/thread), falling back to `VEC_SIZE = 4` for `float32` or 4-aligned row strides.
- **Exact Upstream Numerical Parity:** Keeps pre-norm `sum = x + r` in `float32` registers (`x_vals[v][j] = sum`) while writing `static_cast<scalar_t>(sum)` to `residual`, reduces `ss` via `cub::BlockReduce<float, 1024>(reduceStore).Reduce(ss, CubAddOp{}, blockDim.x)` matching `compute_rms`, and computes `static_cast<scalar_t>(x_vals[v][j] * rms) * w_vals[v].val[j]` in `float32` before scaling.
- **Zero Shared Memory for Group Scales:** Because each quantization group (`128` or `64` elements) is owned by a power-of-2 sub-warp of `SUBWARP_SIZE = group_size / (VEC_PER_THREAD * VEC_SIZE)` contiguous lanes (`16` or `8` lanes for `group_size = 128`; `8` or `4` lanes for `group_size = 64`), the per-group `absmax` is reduced entirely in registers via 2–4 steps of `VLLM_SHFL_XOR_SYNC_WIDTH(group_max, offset, SUBWARP_SIZE)`. Lane 0 of each sub-warp writes `scales` to global memory (honoring `outer_scale_stride` for TMA-aligned transposed scales), while all lanes in the sub-warp immediately quantize `normed` using the register-resident `scale`.
- **100% Active Lanes Across Non-Power-of-2 Model Hidden Sizes:** By sizing `blockDim.x` to `ceil_div(num_groups * SUBWARP_SIZE, WARP_SIZE) * WARP_SIZE`, models with non-power-of-2 hidden sizes ($d = 5120 \implies 320$ threads / 10 warps; DeepSeek-V3 $d = 7168 \implies 448$ threads / 14 warps; Llama-3.1-70B $d = 8192 \implies 512$ threads / 16 warps) have **1 group per sub-warp and 100% active lanes** with zero integer division/modulo in the inner loop.
- **Adaptive `(VEC_PER_THREAD, VEC_SIZE)` Dispatch:**
  - `<VEC_PER_THREAD=1, VEC_SIZE=8>` (`8` elems/thread via `1x16B` load, `SUBWARP_SIZE = 16` for `gs=128`) compiles to **31–32 registers/thread** on `sm_90a`, achieving **100% SM register occupancy** (`2,048` threads / `4` CTAs of `512` threads per SM on H100's 65,536-register file). Used whenever `hidden_size <= 4096` and `has_residual || batch_invariant || num_tokens <= 256`.
  - `<VEC_PER_THREAD=2, VEC_SIZE=8>` (`16` elems/thread via `2x16B` loads, `SUBWARP_SIZE = 8` for `gs=128`) halves the CTA thread count (`256` threads at $d=4096$) for large token batches without residual (`num_tokens > 256 && !has_residual`) and covers $4096 < d \le 8192$ in a single pass.

## Benchmark Results on NVIDIA H100 80GB HBM3 (`sm90a`)

### Methodology (Matching `40_microbench.py` from @daniildiveev's Review)
- **Hardware:** NVIDIA H100 80GB HBM3 (`sm90a`, $3.35\text{ TB/s}$ peak HBM3 bandwidth), CUDA 12.8.
- **CUDA Graph Replay with Rotating Output Buffer Rings:** Each graph captures $N$ nodes (`N = 200` for $T \le 1024$, `N = 20` for $T \ge 2048$) rotating across up to $128\text{ MB}$ of distinct output/scale buffer slots to match `torch.empty` allocations inside `vllm`'s `CUDAGraph` capture.
- **Non-Zero Random BF16 Inputs:** All `input`, `residual`, and `weight` tensors are initialized with non-zero normal distributions so H100's HBM3 Lossless Compression (PLC) does not artificially inflate effective bandwidth on zero-filled pages.
- **Unfused Baseline:** Exact vLLM unfused kernels (`vllm::rms_norm_kernel` / `vllm::fused_add_rms_norm_kernel` from `layernorm_kernels.cu` + `per_token_group_quant_fp8_register_colmajor_kernel` from `per_token_group_quant.cu` writing TMA-aligned column-major scales directly).
- **Effective Bytes for `% Peak HBM3 BW`:**
  - With residual: $T \times (2d\text{ [in]} + 2d\text{ [res read]} + 2d\text{ [res write]} + d\text{ [fp8 out]} + 4\frac{d}{128}\text{ [scales]}) + 2d\text{ [weight]} \approx 7.03125 \cdot T \cdot d\text{ bytes}$.
  - Without residual: $T \times (2d\text{ [in]} + d\text{ [fp8 out]} + 4\frac{d}{128}\text{ [scales]}) + 2d\text{ [weight]} \approx 3.03125 \cdot T \cdot d\text{ bytes}$.

## Numerical Correctness & Stability Verification (`1,056` Configurations + `test_fused_quant_layernorm.py` Full Grid)

| Verification Dimension | Coverage | Result vs Upstream 3-Pass & Reference |
| :--- | :--- | :--- |
