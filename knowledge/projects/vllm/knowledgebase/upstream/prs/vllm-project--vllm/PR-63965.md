# [Bugfix][ROCm] Skip Mooncake on Python 3.14 in requirements/rocm.txt

[Upstream PR](https://github.com/vllm-project/vllm/pull/63965) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`mooncake-transfer-engine-rocm` is a hard requirement in `requirements/rocm.txt` but is published only for cp310-cp313, so it cannot be resolved on Python 3.14. This PR adds a `python_version < "3.14"` marker to that requirement. Fixes #61204.

## Claims

- On Python 3.14, the `mooncake-transfer-engine-rocm` requirement no longer fails dependency resolution.
- Behavior on Python 3.12 and 3.13 is unchanged: Mooncake is still installed, including in the ROCm Docker image.

## Validation

Resolving the Mooncake requirement line of `requirements/rocm.txt` with `uv pip compile` for `x86_64-manylinux_2_35` (the platform of the published Mooncake wheel):

| Python | `main` | This PR |
| --- | --- | --- |
| 3.12 | `mooncake-transfer-engine-rocm==0.3.13.post1` | `mooncake-transfer-engine-rocm==0.3.13.post1` |
| 3.13 | `mooncake-transfer-engine-rocm==0.3.13.post1` | `mooncake-transfer-engine-rocm==0.3.13.post1` |
| 3.14 | fails: no cp314 wheel for `mooncake-transfer-engine-rocm` (only cp310-cp313) | skipped by the marker |

Reproduce:

```bash
grep '^mooncake' requirements/rocm.txt | uv pip compile - --python-version 3.14 --python-platform x86_64-manylinux_2_35
```

I did not run vLLM end to end: the change only affects dependency resolution.

## Details

- The marker keeps the requirement in `requirements/rocm.txt`, which is what `docker/Dockerfile.rocm` installs, so images built on Python < 3.14 still ship Mooncake as intended by #55002.
- `tools/vllm-rocm/pin_rocm_dependencies.py` only rewrites the torch/triton/etc. pins and does not touch this line.
- The marker can be dropped once `mooncake-transfer-engine-rocm` publishes cp314 wheels. The Mooncake PR that adds them is kvcache-ai/Mooncake#4949; it is approved and takes effect with the next stable Mooncake release.
- Related: #61244 addresses the same failure by moving the dependency to `requirements/kv_connectors_rocm.txt`. That removes Mooncake from the ROCm image, which `docker/Dockerfile.rocm` builds from `requirements/rocm.txt` only.
