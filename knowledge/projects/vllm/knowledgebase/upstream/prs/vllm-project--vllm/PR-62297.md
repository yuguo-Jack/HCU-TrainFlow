# [Backport][0.32] Preserve Clef Flash context and cold-cache behavior

[Upstream PR](https://github.com/vllm-project/vllm/pull/62297) · state: open · merged: False

## Original PR description

## Overview

Backport Clef-Flash support and the complete-prompt context/cache fix to `releases/v0.32.0` at `5df63a7203cdb9328d824a27b682e77c7b9928be`.

This release-specific backport includes the prerequisite from #61308 (merged as `380638afbb2c5658f22124f6d1d38fcd464ea7d9`, original PR head `feba86ccfe2752bc8bb717ad977ba71d45403684`) and adapts the reviewed fix from #62249, head `67c649854d16e17a5ad679f0bfc3ab13aaa2580d`. The release branch lacks Clef-Flash; #62249 targets `main` and edits the later `openai/decisions` path, which does not exist on this release. No open Clef backport against this release was found. This is not a second mainline fix.

## Claims

- Preserve the original Clef-Flash joint head/pooler, Qwen3.5 wrapper, architecture conversion and registration from #61308. Clef-Omni's existing release implementation supplies the #61064 prerequisite; it is not reapplied.
- Use the engine's resolved `max_model_len` for Flash's complete prompt, including expanded media, state, questions/options and fixed tokens. Exactly-at-limit pooling reads reserve no generation tokens. Oversized requests return the existing HTTP 400 before encoding, instead of silently truncating state. Omni retains its 64,000-token cap and truncation/span semantics.
- Use the existing processor-only media-cache path so an overflowing first request cannot prime the sender for an image the receiver has never seen. No new inference method, CLI option, API route or engine plugin is introduced by the context/cache repair.

Tests ran with existing CPU dependencies (`torch 2.14.0+cpu`, no CUDA build), cached tokenizer files and synthetic inputs; no model weights were fetched. Import-origin checks verify the new release checkout, rather than an older editable checkout. Most pooling outputs are mocked. The cold-cache regression uses the real `HfRenderer`, registered Qwen3.5 processor, CPU pixels, processor-only cache and LRU sender/receiver: first unseen image plus overflow returns 400 without encoding; the same image with a shorter prompt and a repeated accepted request both deliver identical pixels/prompt. The negative control changes only the cache flag and fails with `MultiModalCacheMissError` on the first shorter retry.

An initial run found a test double that lacked the new keyword argument (46 passed / 1 failed); the existing video test double was adapted and the final unchanged source passed all 47 cases. Native feature/model execution from #61308 has not been independently requalified on this release. Larger contexts still need model-specific quality/compatibility validation; this change supplies no quality or latency claim.

## Details

The prerequisite was applied as the original upstream commit. The only feature-backport conflict was the shared-head test import: its renamed head/pooler import is combined with the release's existing `current_platform` import. All six runtime prerequisite postimages matched the exact-context release projection before the context repair; the five non-strategy runtime files remain unchanged by the repair.

The context/cache methods preserve #62249's semantics at the release's existing `generate/structured_decisions/strategies.py` path. Only its focused context/media regressions are ported; later D3 and Decisions API features from mainline are not introduced. This PR does not include the independent UVA change #53981 and does not update downstream pins or deployments.
