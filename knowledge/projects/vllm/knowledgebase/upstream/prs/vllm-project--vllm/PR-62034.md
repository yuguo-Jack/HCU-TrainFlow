# [Bugfix][LoRA] respect attention_k_eq_v=True LoRA layers as `qkk_proj` packed module

[Upstream PR](https://github.com/vllm-project/vllm/pull/62034) · state: open · merged: False

## Original PR description



## Overview



Fix LoRA weight loading on `attention_k_eq_v` full-attention layers (e.g. `google/gemma-4-31b-it`), where the V slice of the packed `qkv_proj` received no LoRA delta even though HF applies the `k_proj` LoRA to V.

This PR is another version of #61267, where using the existing `packed_modules_mapping` mechanism instead of introducing a new "ad-hoc" implicit mapping rule.

## Claims



- On `attention_k_eq_v` full-attention layers, the fused projection is now named `qkk_proj`, and the Gemma 4 models (`Gemma4ForCausalLM`, `Gemma4ForConditionalGeneration`, `DiffusionGemmaForConditionalGeneration`) map it as `"qkk_proj": ["q_proj", "k_proj", "k_proj"]`. Sliding-window layers keep `qkv_proj` → `[q_proj, k_proj, v_proj]`, and KV-shared layers are unchanged.
