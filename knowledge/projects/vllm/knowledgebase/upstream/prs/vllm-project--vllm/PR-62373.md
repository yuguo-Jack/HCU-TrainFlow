# [CI][KV Offload] Signal async lookup results once they can be drained

[Upstream PR](https://github.com/vllm-project/vllm/pull/62373) · state: open · merged: False

## Original PR description

- Set the test helper's `_results_ready` event from the results queue's `put()` instead of inside `batch_lookup()` in `test_async_lookup.py`

`test_found_key_returns_true` fails intermittently with `assert None is True` (https://buildkite.com/vllm/ci/builds/95734 on `main`, and https://buildkite.com/vllm/ci/builds/95743). The helper set the event inside `batch_lookup()`, while `AsyncLookupManager`'s worker only posts the results to `_pending_results` after `batch_lookup()` returns, so a test waking in between drains an empty queue and `lookup()` still returns `None`. Holding that window open with a 1 ms delay before the post fails the original test 200/200; with this change it passes 200/200 at 1, 5 and 20 ms, every test in the file passes 20/20 with a 5 ms delay, and the file passed 10/10 runs (`v1/kv_offload`: 775 passed). This only touches the test; #57474 and #61717 change the same file but keep the event where it was.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
