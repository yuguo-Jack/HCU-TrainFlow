# [Build] Compile DeepGEMM's extension through the compiler launcher

[Upstream PR](https://github.com/vllm-project/vllm/pull/65698) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

DeepGEMM's extension gets built by setuptools, which never sees `CMAKE_CXX_COMPILER_LAUNCHER`. So it's the one file in the build that skips ccache/sccache. This passes the launcher through.

## Claims

- If you build with ccache or sccache, rebuilding `_deep_gemm_C` is a cache hit now instead of a ~60 s compile.
- No launcher, no change.

## Validation

- A test extension built twice with `CC="ccache cc"`: miss, then hit.
- On a B200 box with a warm ccache and a fresh build dir, `_deep_gemm_C` took 65.7 s and was the last job ninja waited on. Will post the after number here, that's why it's a draft.

## Details

`build_deepgemm_C.py` now takes `--launcher` and sticks it in front of `CC`/`CXX`. `deepgemm.cmake` passes `CMAKE_CXX_COMPILER_LAUNCHER` to it.

I did it here instead of moving DeepGEMM to torch's `BuildExtension` so it uses whatever launcher vLLM picked (torch's own wrapper prefers ccache over sccache).
