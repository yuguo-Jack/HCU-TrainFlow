Hi @charxwu, I merged main to resolve the #61939 conflicts and pushed two follow-up commits (4b2fa3b131, 6132eaa85a) addressing the review:

- **Docker:** the gRPC/Protobuf build deps live only in `build_mori`, so the rest of the stack stays cached. `final` gets the runtime libs that `libmori_pybinds.so` links (checked with `ldd`) and fails the build if `UMBPClient` doesn't import. The `rocm_72_base` edits are gone, since #61939 deleted that file.
- **CI:** the integration group is in `test_areas` and needs 1 GPU instead of 4.
- **Tests:**
  - Integration went from 7 cases to 4 and unit from 52 cases to 45.
  - Dropped the TP2/PP2 test (no real TP/PP happens in it), the overlap test that couldn't fail, and tests that only exercised the fake.
  - Gating now uses `pytestmark` instead of import-time asserts.
- **Correctness:**
  - Under `VLLM_BATCH_INVARIANT=1`, a UMBP restore must reproduce the cold run's tokens and logprobs exactly. This covers a batch ending mid-block and a restore that extends a shorter GPU prefix hit, with exact external-hit counts.
  - A new CPU test evicts an object between lookup and load, then checks both `kv_load_failure_policy` values through the real `Scheduler`.
- **Accuracy:** a ROCm-gated UMBP GSM8K row for Gemma-4 that asserts the second pass reloads through UMBP.

On MI350X with MORI built with UMBP, 4b2fa3b131 passed 20/20 for the integration group, the unit group and the GSM8K row (mean accuracy 0.634 before and after the reload). The 20× loop for 6132eaa85a is running and I'll post the counts here when it's done. I broke `embedded.py`, `worker.py` and `connector.py` on purpose to make sure the new tests can fail, and each break was caught.

While checking this I also found that UMBP restores wrong KV under the `BHLNC` cache layout, and fails at init under `LHBNC` (AITER FA with `VLLM_ROCM_SHUFFLE_KV_CACHE_LAYOUT=1`). `register_kv_caches` in `umbp/data.py` treats `stride(0)` as the block stride. That code isn't in this PR, so I'll follow up separately. The new exact-restore tests fail on it with `VLLM_KV_CACHE_LAYOUT=BHLNC`.
