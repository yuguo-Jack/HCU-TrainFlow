# [Perf][DSpark][DSv4.1] Fuse the Markov sampling loop on NVIDIA by inverse CDF

[Upstream PR](https://github.com/vllm-project/vllm/pull/64442) · state: closed · merged: True

## Original PR description



## Overview

Runs DSpark's sequential Markov sampling for DeepSeek-V4.1 on NVIDIA as the existing bias GEMM plus two Triton kernels per draft step, through the draft model's `sample_sequential` hook (as the ROCm model does). Sampled draft tokens are drawn by inverse CDF of the cached draft logits instead of Gumbel-max. Production code changes only under `vllm/models/deepseek_v41/nvidia/` (+223). It is opt-in: `--additional-config '{"dspark_fused_markov": true}'` enables it, and the speculator's loop stays the default.

## Claims

- DSpark Markov sampling (5 draft steps, GB200, CUDA graph): 1.6x at 1 request per rank, 2.7x to 3.9x at 16 to 253 requests per rank.
- DEP4 decode serving with AgentX KV: step time -1.7% at 64 requests x 131K context per rank, -3.2% at 128 x 32K.
- GSM8K and DSpark acceptance length unchanged at DEP4 and TEP4 (TP4 + EP).

## Details

- Per draft step, the loop runs the Markov embedding, the bias GEMM, the logits add, the Gumbel sample (its kernel, a cross-block argmax and a gather) and a copy into `draft_tokens`. Here the bias GEMM (cuBLAS) is kept, `_markov_sample_kernel` adds the base logits as the loop does (fp32 sum rounded once to the cache dtype), writes the draft-logits cache and keeps each vocab block's max and exp-sum, and `_markov_select_kernel` picks the token and writes its `markov_w1` row into the next step's GEMM input.
- Inverse CDF instead of Gumbel-max: one uniform per request, keyed by seed, draft step and position like the loop's noise, picks a block by the prefix sum of the block masses and a token inside it from the same fp32 weights. Tokens follow softmax(cached logits / T), the distribution the rejection sampler verifies; it costs one exp per logit instead of a hash and two logs, which made the Gumbel kernel ALU-bound. The sampled tokens are therefore not those of the loop's Gumbel draw; temperature-0 tokens are.
- The hook is set at model init only when `dspark_fused_markov` is true and the loop would sample from a full draft-logits cache with plain fp32 Gumbel noise: probabilistic drafting, no adaptive verification, no fp64 Gumbel, no watermarking and no batch-sharded sampling (whose sharded cache keeps the loop). Draft top-k is handled by the speculator before the hook.
- Not a duplicate of: #61869 (fuses the loop only with `decode_backend=latency_specialized` on GB300 TP), #64033 (the top-k Markov walk), #62958 (int8 `markov_w2` on Hopper), #63181 / #63891 and the merged #60731 (ROCm).
