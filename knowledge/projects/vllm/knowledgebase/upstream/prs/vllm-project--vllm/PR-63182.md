# [ROCm] Draft-prepare fastpaths: shared-output dedup + parallel pad-tail + KV-only context insert

[Upstream PR](https://github.com/vllm-project/vllm/pull/63182) · state: open · merged: False

## Original PR description

## Overview

Draft-path fastpaths for DSV4.1-Flash serving on gfx950 (MI355X), all three on the DSpark draft prepare step that runs before every draft CUDA-graph replay: shared-output dedup across draft KV cache groups, a parallel pad-tail fix, and a KV-only context insert (dummy-Q removal). All three levers are conditional (kill switches) and engage on ROCm only — every other platform keeps the stock paths, unchanged and silent.

Part of the DSV4.1-Flash MI355X serving fastpath series — four **independent** single-commit PRs, each reviewable and mergeable separately, in any order. Siblings: #63179 (tiny-M quant fusion + lm_head guard), #63180 (fused shared experts), #63181 (fused draft sampling). The four series PRs all register kill switches in `vllm/envs.py` at the same anchor and therefore conflict textually with each other there; the resolution is to keep both sides. This branch is rebased onto current `main` (no textual conflicts; diff unchanged from the original submission).

## Claims

- **Shared-output dedup** (`dflash/speculator.py`): with multiple draft KV cache groups (the DSpark draft model's hybrid KV layout; 3 at the measured TP=4 shape), `prepare_dflash_inputs` runs once per group, but only the per-group outputs differ between calls — every other output is a pure function of the same inputs and is recomputed identically on each call. The dedup computes the shared outputs on the first call only (`SKIP_SHARED` constexpr in the Triton kernel) and skips them on calls 2..N: bit-exact by construction, since the skipped stores would rewrite identical values into the same shared buffers. Kill switch `VLLM_DEBUG_DISABLE_DRAFT_PREPARE_DEDUP`; ROCm-gated.
- **Parallel pad-tail** (same file): the stock kernel pads `[q_pad_start, max_num_tokens)` of each draft group's query slot mapping serially from one CTA, on every per-group call. The fix skips the in-kernel tail (`PAD_TAIL=False`) and pads `[q_pad_start, HWM)` for all draft group rows in one parallel launch, `HWM = min(max_num_reqs * num_query_per_req, max_num_tokens)`; the draft replay only ever reads slot mappings up to `num_tokens_padded` (eager steps and uniform captured graphs alike), so the fix is bit-exact by construction for every read-visible cell. Kill switch `VLLM_DEBUG_DISABLE_DFLASH_PREPARE_PAD_FIX`; ROCm-gated.
- **KV-only context insert** (`dspark.py`): `precompute_and_store_context_kv` used to allocate a zero dummy query and run the fused Q+KV ops with the full q_head_padded, discarding the quantized-Q output. It now calls the existing `fused_deepseek_v4_kv_rope_insert` (#56441) with zero query heads — the same call `nvidia/dspark.py` makes here — so the dummy-Q allocation, its zero-fill and the quantized dummy-Q write disappear on every cache dtype. Kill switch `VLLM_DEBUG_DISABLE_DRAFT_CTXKV_DUMMYQ`.
- **−281 µs decode ITL (−5.0%) on the current base** (`main`@`717cf84342`) — official DSV4.1-Flash serving command at TP=4 on MI355X, complete separation on per-run medians (rebase re-check under Validation). First measured **−5.7% / −15.7%** (−323 / −985 µs, sampled / greedy) on the submission-base nightly ROCm-10 image with fully disjoint per-run ranges; re-checks across bases hold the win at −281 to −290 µs. TTFT flat within noise (draft-path only).

## Validation

## Details

Engagement lines are WARNINGs (the rust-frontend server logs carry no INFO records): the dedup engaged/DISABLED pair, the pad-fix engaged/DISABLED pair (scope=process, one per TP rank), and the ctxkv engaged line (the raw kill var's disabled side is silent — OFF is proven by the engaged line's absence). All of these fire on ROCm only; non-ROCm platforms log nothing and keep the stock paths (pinned by a test).

`q_head_padded=0` (KV-only insert) is covered at op level by `test_fused_deepseek_v4_qnorm_rope_kv_insert.py`; `test_dflash_prepare_inputs.py` pins the prepare contracts described above.

File: `vllm/v1/worker/gpu/spec_decode/dflash/speculator.py` · line 612

This replaces the stock pad tails with one parallel launch. Stock: the prepare kernel pads `[q_pad_start, max_num_tokens)` of every draft group's query slot mapping serially from a single CTA, inside every per-group call. Here the in-kernel tail is skipped (`PAD_TAIL=False`) and all draft-group rows are padded in one parallel Triton launch bounded to `[q_pad_start, HWM)`, where `HWM = min(max_num_reqs * num_query_per_req, max_num_tokens)` bounds every read of the buffer (eager steps and captured-graph pads alike), so the bounded pad is bit-exact for every read-visible cell — the proof now sits inline at the launch. The launch is eager, in `propose()`, so no CUDA-graph capture constraints apply. 

By using HWM limit, the padding avoids redundant work.
