# [MoE] Autotune FlashInfer MegaMoE live-token workspaces at startup

[Upstream PR](https://github.com/vllm-project/vllm/pull/64629) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Autotune FlashInfer CuTeDSL MegaMoE at startup and reuse fixed live-token
workspaces during serving, without requiring an offline tuning cache.

## Claims

- Tune once per geometry/bucket; share knobs across layers and cache across restarts.
- Select workspaces using the EP-wide maximum token count.
- Prepare before CUDA Graph capture and account for retained memory before KV sizing.

## Validation

- Prior profile/cache suite: **88 passed** on `d13d944d6`.
  This logging/helper cleanup passed scoped pre-commit; pytest/GPU runs were not repeated.
  Suite: `uv run --active python -m pytest tests/model_executor/test_flashinfer_autotune_warmup.py -q`.
- GB200 EP4: **96** changed-input graph comparisons passed, including idle/uneven
  ranks and both output ownership modes. Qwen3-30B-A3B-NVFP4, DP4/EP4/TP1,
  D16/P1024: four MRV1/MRV2 startups passed capture and **37/37** requests each;
  GSM8K **89–90.5% on 200 questions**. Cold/restart startup: **450/170 s**,
  knob searches **6/0**. These runs used the feature source with reused native
  extensions; current-head serving was not rerun.

**M3.1 operator perf — 8×GB200, EP8, NVFP4 W4A4.** Actual layer-3 weights,
synthetic activations/routing, H6144/I3072/E128/top4. FlashInfer 0.7.3rc1,
Torch 2.14.0+cu130, CuTeDSL 4.8.

**Experimental:** measured on `1a02c0262ba9` plus M3 wiring and packed-input fixes
**outside this PR**; this does not establish current-PR M3 serving support.

A = fixed workspace; B = buckets with identical knobs; C = buckets + autotune.
B/C decode capacity is 512. A/B use compatible N128 knobs because stock N256
fails compilation for this workload.

At equal capacity, buckets alone are approximately flat; autotune reduces
latency **4.8–6.4% at 8–128 rows** and **2.1% at 256**, with **0.87%/0.19%
regressions at 384/512**. The 16K baseline's larger gain mainly comes from
reducing capacity.

Timings include staging + distributed MoE + reduction: 12 randomized paired
epochs × 50 graph replays, EP-maximum duration, 2,000 bootstrap resamples.
**3,056 correctness checks passed**, with zero full-output A/B/C numerical
difference. Repeated warm-layer timing with fixed routing excludes E2E serving.
The experimental harness is not in this PR.

## Details

Requires the knob/workspace APIs in
[FlashInfer 0.7.3rc1](https://github.com/flashinfer-ai/flashinfer/releases/tag/v0.7.3rc1);
the unchanged 0.7.2.post1 pin falls back to the default path.
Requires EP=WORLD, PCP1, no elastic EP or sleep mode. W4A16 is outside scope.

Related [#62073](https://github.com/vllm-project/vllm/pull/62073) adds Beam/decode
workspace integration; this adds per-bucket knob search, persistent cache and
pre-KV memory accounting. No E2E performance or memory-saving claim; failed
FlashInfer tuning candidates retained allocations until exit in the M3 experiment.
AI assistance was used.
