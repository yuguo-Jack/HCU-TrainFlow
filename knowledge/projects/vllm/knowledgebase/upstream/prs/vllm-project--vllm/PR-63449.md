# [CI][Kimi-K3] Expect no trailing-block drop in DSpark resend tests

[Upstream PR](https://github.com/vllm-project/vllm/pull/63449) · state: closed · merged: True

## Original PR description



## Overview

`test_mooncake_resend_reuses_prompt_checkpoint` in `(4xB200) [Nightly] Kimi K3 Prefix Cache Shard 1/4` has failed since #54163 ([nightly 96830](https://buildkite.com/vllm/ci/builds/96830#01a1675c-cf11-4cdd-af5a-33204d20a817)):

```
AssertionError: prompt_len=7449: actual=7424, expected=7296
```

#54163 stopped DFlash/DSpark from dropping the trailing prefix-cache unit (`needs_eagle_block_drop()`). These tests run DSpark but still expect the EAGLE drop. This PR updates the expected hit to the last 128-token checkpoint before the final token, `(P - 1) // 128 * 128`, and rewrites the comments that described the drop.

## Claims

- The Mooncake resend test now expects 7424 of 7449 cached tokens, which is what CI observes after #54163 removed the drop.
- The two `test_dspark_exact_resend_reuses_prompt_checkpoint` cases are unchanged in value. P=7040 and P=7296 are 128-aligned, so the old and new formulas agree. Only their comments and ids change: `eagle-proof-scan` becomes `pmu-aligned-tail`, and `eagle-double-cap` becomes `single-cap`.

```bash
pytest -v -s tests/models/kimi_k3/test_prefix_cache.py -k resend_reuses_prompt_checkpoint
```

The Mooncake case could not run on my GB300 box: Mooncake RDMA cannot register GPU memory there (`register_buffer failed ... -600`), so every store put fails and the resend hits 0. It needs the B200 nightly step: `actual=7424` comes from the CI log above. The hit-count assertion runs before `check_logprobs_close`, so since #54163 CI has not compared logprobs for this case; the nightly run on this PR checks that too.

## Details

**Coverage gap.** This file only uses DSpark, so after #54163 nothing here exercises the EAGLE trailing-unit drop with hybrid Mamba prefix caching. That includes the "attention proof" lookups that #60695 was testing. `_expected_cached` in the multi-turn test still subtracts a unit for spec modes. I left it as is: it is only a lower bound (`cached >= expected`), and the NIXL P/D path still keys off `use_eagle()`. Covering EAGLE again needs an EAGLE/MTP draft for the 8-layer dummy model, which is out of scope here.

**Not a duplicate.** I searched open PRs for `test_mooncake_resend_reuses_prompt_checkpoint`, `resend_reuses_prompt_checkpoint`, "kimi k3 prefix cache test" and `54163`. No open PR touches this test. #62141 (AMD mirror) and #54165 cover different things.
