# [Bugfix] Skip cache-served mm items in tower/connector LoRA mapping

[Upstream PR](https://github.com/vllm-project/vllm/pull/47400) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Bugfix: `set_active_mm_loras` builds tower/connector LoRA mapping rows for encoder-cache-served mm items that the encoder forward skips, shifting every later item's rows onto the wrong adapter. Rebased onto current main after #42662 rewrote the mapping loop; the bug carries over unchanged.

## Claims

- Cache-served items (`mm_feature.data is None`) are skipped by `EncoderRunner.prepare_mm_inputs` (`vllm/v1/worker/gpu/mm/encoder_runner.py:90`) in the encoder forward, but `set_active_mm_loras` (`vllm/v1/worker/gpu/mm/lora.py`) still counted them into the TOWER/CONNECTOR `LoRAMapping`s. Punica consumes the mapping positionally, so one cached item misroutes every subsequent item's rows onto the wrong LoRA — silent output corruption, and a size mismatch against the actual encoder batch M.
- Fix mirrors the exact skip when building `mm_items` (one filtered comprehension). If every scheduled item is cache-served, the existing empty-mapping early return leaves adapters untouched, matching a forward that runs nothing.

## Validation

Re-run on an A100 after rebasing onto current main (nightly `vllm 0.31.1rc1.dev376+g5555a2d8f`, `torch 2.13.0+cu129`), with the module patched by this diff:

Lint: `ruff format --check` / `ruff check` (pinned v0.14.0) pass on both changed files.

## Details

- Updated the two pre-existing `set_active_mm_loras` tests to carry sentinel `data=Mock()` (with the fix, all-`None` fixtures would be skipped entirely); every existing assertion is unchanged. Added `test_set_active_mm_loras_skips_items_without_data`: a present item mixed with a cache-served one contributes exactly its own rows, and an all-cache-served step sets nothing.
- Not a duplicate: no open PR touches this path (`gh pr list --state open --search "set_active_mm_loras"`). #42662 (merged) migrated the token-count interface in this file; this fix is orthogonal and is now expressed on top of it.
- Known related gap, deliberately out of scope: `prepare_mm_inputs` has two more skip paths (an item whose identifier is already in `encoder_cache.encoder_outputs` within the same step, and `prompt_embeds` passthrough items) that also still receive mapping rows. Same bug class; happy to follow up once this lands if maintainers agree.
