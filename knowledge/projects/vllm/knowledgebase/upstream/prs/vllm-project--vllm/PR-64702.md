# [CI] Release GPU and distributed state at every test-file boundary

[Upstream PR](https://github.com/vllm-project/vllm/pull/64702) · state: open · merged: False

## Original PR description

## Purpose

Stop GPU and distributed state from leaking between test files, the largest source of flaky tests on main recently.

Several directories override `should_do_global_cleanup_after_test` (or `cleanup_fixture`) to skip the per-test `cleanup_dist_env_and_memory()` for speed: `tests/kernels/moe`, `tests/lora` (punica), `tests/parser/engine`, and a few single files. One file's cached GPU memory or process groups then carry into whatever file runs next in the same pytest process. Runtime auto-sharding re-plans which files share a process each time its timing data refreshes, so these leaks show up as failures that appear and disappear without any code change:

| Failure on main | Leak | One-off fix |
|---|---|---|
| H200 LoRA `test_qwen2vl_lora`: engine sees 21.5 of 32.5 GiB free | `test_punica_ops.py` skips cleanup and keeps ~11 GiB cached | #62672 |
| L4 MoE Kernels `test_modular_kernel_combinations`: NCCL "Failed to CUDA calloc async 608 bytes" | MoE conftest skips cleanup; a shard re-plan put `test_gpt_oss_triton_kernels.py` first | #64576 |

**Change:** a module-scoped autouse fixture in `tests/conftest.py` runs `cleanup_dist_env_and_memory()` after every test file. It is separate from `cleanup_fixture`, so directories keep their per-test speedup but always hand the next file a clean GPU.
- **Gated:** it runs only if CUDA/XPU is initialized or a `torch.distributed` process group exists. CPU-only test files don't initialize the accelerator, so they keep the speedup the per-test skip was added for.
- **Cost:** one cleanup per file instead of per test.
- **Cleanup:** removes the now-redundant module cleanup from `tests/lora/test_punica_ops.py` (#62672). The MoE conftest's on-entry hook from #64576 is left as is; it also resets the workspace manager.
- **Ordering:** pytest sets up autouse fixtures first within a scope and tears them down last, so this runs after a module's own module-scoped fixtures (e.g. a module-scoped `LLM`) have been torn down.

**Not a duplicate:** no open PR changes the root conftest cleanup.

## Test Plan

- Pre-commit (ruff, mypy) passes. Not run on a GPU locally.
- This touches every test step, so the full CI run on this PR is the check: a regression would show up as new failures or slower steps compared with main.
