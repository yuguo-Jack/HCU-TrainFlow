# [ROCm][Perf] Skip DSA indexer scoring for short dense-MHA prefills

[Upstream PR](https://github.com/vllm-project/vllm/pull/61942) · state: open · merged: False

## Original PR description



## Overview

On ROCm, the `deepseek_v32` path (DeepSeek-V3.2, GLM-5.x) now skips the sparse indexer's scoring for pure short prefills that run on dense MHA, as CUDA already does (#48407, #51298). Builds on the ROCm dense-MHA prefill from #49263.

## Claims

- GLM-5.1-FP8, MI355X, TP4: 1K-token prefill median TTFT -8.1% at c1, -1.6% at c32. gsm8k unchanged.
- GLM-5.2-MXFP4 (indexer on 21 of 78 layers): no significant change.
- Mixed batches, prefills longer than `index_topk`, MTP layers, FULL cudagraph and capture still score. Other platforms are unchanged.

## Validation

- `test_mla_short_prefill_indexer.py`: 35 passed, 8 skipped (CUDA-only) on MI355X, 7 new. pre-commit clean.
- `test_rocm_fused_v32_dense_prefill_matches_mqa` (existing, AMD V1 Attention CI): passed, auto and fp8 KV. Its dense run skips one step whose keys a later 2049+-token decode scores.
- Serving, GLM-5.1-FP8, TP4, output 1 token, 2 runs per arm, ABBA, no failed requests:

| workload | median TTFT (ms), main → PR | change |
|---|---|---|
| 1K in, c1 | 164.5 → 151.2 | -8.1% |
| 1K in, c32 | 1948.6 → 1918.0 | -1.6% |
| 1900 in, c1 | 175.6 → 173.6 | within noise |
| 8K in, c1 (sparse path) | 620.2 → 623.4 | within noise |

- gsm8k 5-shot strict, GLM-5.1-FP8: main 0.9469 / 0.9424, PR 0.9447 / 0.9462 (stderr 0.006).
- GLM-5.2-MXFP4, MTP3, 3 runs per arm: TTFT -0.6% to -1.9%, within noise. gsm8k strict 0.9356 → 0.9356, acceptance length 3.31 → 3.31.

| PR, run 2 | 142.0 / 0.4 | 143.4 / 15.3 |

At 1K the GPU finishes within a few ms of the last launch, so the step is host-bound and the indexer's host work shows up in TTFT. At 1900 the GPU runs 12-28 ms past the host; host + tail stays at 159-162 ms in every run, and only the indexer's GPU time is saved. A torch profiler trace per step: the PR removes 312 kernels (4 per layer), 1.43 ms of GPU time at 1K and 2.17 ms at 1900; on main the indexer op costs 190-198 us of host time but 24-34 us of GPU time per call (host time inflated by the profiler).

## Details

- Placement: `DeepseekV32MLAAttention._fused_attention`, which already holds the MLA metadata. CUDA passes the layer name into its op only because the op cannot see that metadata.
- Conditions: the CUDA op's, plus the layer taking the dense-MHA branch. The flag in `DeepseekV32Attention` moves from `is_cuda()` to `is_cuda_alike()`.
- K cache: still written by `fused_norm_rope`; only scoring is dropped.
- The gain is host time: an eager 1K prefill is host-bound and each indexer call costs about 0.2 ms on the host; at 1900 the step is GPU-bound and the indexer kernels take about 2 ms per step.
- Not measured: DeepSeek-V3.2 (same code path), GLM-5.1 with MTP, TP8.

<details>
<summary>Design notes</summary>

- Moving the check into `rocm_aiter_sparse_attn_indexer` would mirror CUDA but add an argument to an op that DeepSeek-V4 shares; the model already has the MLA metadata and the dense-MHA decision.
- The ROCm indexer op is built with `skip_k_cache_insert=True`. `fused_norm_rope` writes the indexer keys and clears the top-k buffer before the decision.
- PCP leaves the flag off, as on CUDA; ROCm sparse MLA rejects DCP. MTP layers keep scoring, as on CUDA.
- This model is not torch.compiled. Prefills run eagerly under the default FULL_DECODE_ONLY; under breakable cudagraphs the eager segment re-evaluates the decision on replay. Profile and dummy runs (no metadata) still call the op, so its workspace is reserved.

</details>
