# [ROCm][Perf] Skip DSA indexer scoring for short dense-MHA prefills

[Upstream PR](https://github.com/vllm-project/vllm/pull/61942) · state: open · merged: False

## Original PR description

## Overview

On ROCm, the `deepseek_v32` path (DeepSeek-V3.2, GLM-5.x) now skips the sparse indexer's Q projection and scoring for pure short prefills that run on dense MHA. CUDA already skips the scoring (#48407, #51298), and both now use the same check. Builds on the ROCm dense-MHA prefill from #49263.

## Claims

- GLM-5.1-FP8, MI355X, TP4: 1K-token prefill median TTFT -10.7% at c1, -5.0% at c32. On every call it changes, the attention output and KV caches are bit-identical to main. gsm8k unchanged; GPQA-Diamond 0.691 on both main and this PR (8 runs each).
- GLM-5.2-MXFP4 (indexer on 21 of 78 layers): no significant change (measured on the first revision).
- Mixed batches, prefills longer than `index_topk`, MTP layers, FULL cudagraph and capture still score. Other platforms are unchanged.

## Validation

- `test_mla_short_prefill_indexer.py`: 36 passed, 8 skipped (7 need SM100, 1 needs the DeepSelect extension) on MI355X. `test_rocm_short_prefill_skips_indexer_q_and_scoring` drives `_fused_attention`: a short dense-MHA prefill runs neither `wq_b` nor the indexer, and `fused_norm_rope` still gets the indexer K cache. pre-commit clean.
- `test_rocm_fused_v32_dense_prefill_matches_mqa` (existing, AMD V1 Attention CI): passed, auto and fp8 KV. Its dense run skips one step whose keys a later 2049+-token decode scores.

At 1K the GPU finishes within a few ms of the last launch, so the step is host-bound and the indexer's host work shows up in TTFT. At 1900 the GPU runs 12-28 ms past the host; host + tail stays at 159-162 ms in every run, and only the indexer's GPU time is saved. ## Details

- Placement: `DeepseekV32MLAAttention._fused_attention`, which already holds the MLA metadata. CUDA passes the layer name into its op only because the op cannot see that metadata.
- Conditions: `should_skip_indexer_scoring()` in `sparse_attn_indexer.py`, which the CUDA op now also calls, plus the layer taking the dense-MHA branch. The flag in `DeepseekV32Attention` moves from `is_cuda()` to `is_cuda_alike()`.
- K cache: still written by `fused_norm_rope`. The indexer Q projection (`wq_b`), the indexer part of `fused_q` and scoring are dropped.
- The gain at c1 is host time: an eager 1K prefill is host-bound and each indexer call costs about 0.2 ms on the host. Dropping `wq_b` (a 2048 → 32x128 GEMM per layer) also saves GPU time, which shows at c32.
- CI: `vllm/models/deepseek_v32` is added to the source dependencies of the MI300 Model Executor step in `test-amd.yaml`, so that changes there run this test file. `test_areas/model_executor.yaml` has it since #59223.
- Not measured: DeepSeek-V3.2 (same code path), GLM-5.1 with MTP, TP8.

<details>
<summary>Design notes</summary>

- Moving the check into `rocm_aiter_sparse_attn_indexer` would mirror CUDA but add an argument to an op that DeepSeek-V4 shares; the model already has the MLA metadata and the dense-MHA decision.
- The ROCm indexer op is built with `skip_k_cache_insert=True`. `fused_norm_rope` writes the indexer keys and clears the top-k buffer before the decision.
- PCP leaves the flag off, as on CUDA; ROCm sparse MLA rejects DCP. MTP layers keep scoring, as on CUDA.
- This model is not torch.compiled. Prefills run eagerly under the default FULL_DECODE_ONLY; under breakable cudagraphs the eager segment re-evaluates the decision on replay. Profile and dummy runs (no metadata) still call the op, so its workspace is reserved.
