# [Bugfix][Benchmark] Preserve Rust SSE payloads across chunks and comments

[Upstream PR](https://github.com/vllm-project/vllm/pull/60177) · state: closed · merged: True

## Original PR description



## Overview

Preserve SSE text and usage in the Rust benchmark clients across HTTP chunk boundaries, LF/CRLF/CR event framing, and leading comment lines. This combines the related response-data-loss fixes in one small production change and one shared HTTP test fixture.

## Claims

- Preserve transport-fragment whitespace instead of stripping generated text and SSE delimiters.
- Normalize CRLF/CR framing while retaining byte buffering and early complete-JSON dispatch.
- Keep valid data fields in events beginning with comments in both OpenAI-compatible backends.

## Validation

On repository-pinned Rust 1.95, the combined backend suite passed all 20 tests; the full package passed 172 unit + 3 CLI integration tests, with 12 existing resource-dependent tests ignored. Whole-workspace fmt, all-targets/all-features clippy with warnings denied, applicable pre-commit hooks and the diff check passed. Tested Spark source SHA-256 matches local source. Independent reviews found no blocking source issues; exact-union checks confirmed no extra integration logic.

Executed on an isolated ARM64 CPU, one build/test thread, without model downloads or GPU use:

```bash
cd rust
cargo test --locked -p vllm-bench backends:: -- --test-threads=1
cargo test --locked -p vllm-bench -- --test-threads=1
cargo clippy --locked -p vllm-bench --all-targets --all-features -- -D warnings
cargo fmt --all -- --check
```

Nextest was unavailable in the isolated toolchain. Supporting standalone baseline evidence: the newline tests produced 16 passes / 3 failures, including `leadingtrailing!` instead of `leading  trailing!`; the comment tests produced 16 passes / 1 failure, returning `!` instead of `hi!` in the first completions/content case. That loop stops at its first failure, so other baseline comment cases are not claimed as executed. These are two separate pre-fix runs, distinct from the combined results above. Four added regressions exercise the handler and both real HTTP backends without new sleeps or timing-duration thresholds.

This modifies benchmark response clients, not model inference or the serving engine. The HTTP regressions use loopback fixtures, not model servers. No live model evaluation, performance improvement, or production deployment reproduction is claimed.

## Details

Three stages could lose valid response data: each backend trimmed raw byte fragments, the handler recognized only `\n\n` framing, and each backend discarded a whole event beginning with `:` before selecting its data field. The fix passes bytes intact, normalizes framing with a persisted CR state, and lets the existing multi-field selection skip comments rather than their payloads. The existing socket fixture is shared once by both HTTP regressions.

The union does not introduce a general SSE parser or change existing early-JSON, EOF, `[DONE]`, success-classification, or usage-accounting semantics. One-line comment-only messages now take the existing harmless failed-JSON path. Multiline-data and other EventSource conformance questions remain outside scope.

Live duplicate checks on 2026-10-06 found no open Rust fix covering these data-loss paths. [#51172](https://github.com/vllm-project/vllm/pull/51172) changes Python transport; merged [#50868](https://github.com/vllm-project/vllm/pull/50868) introduced the UTF-8 buffering retained here; [#59736](https://github.com/vllm-project/vllm/pull/59736) changes tokenless-chat success; [#59694](https://github.com/vllm-project/vllm/pull/59694) changes prompt-token accounting. Textual backend conflicts remain possible, but their behavioral changes are not duplicated.

Thanks for the fix. I checked that all 4 new tests fail on main's sources (`"leadingtrailing!"`, `"!"`, and the CRLF/CR cases) and pass with this PR, and that fmt and clippy are clean. The changes look correct to me. Two small requests:

1. **Skip comment-only messages explicitly.** Now that the `starts_with(':')` check is gone, a message like `: heartbeat` is only dropped because `serde_json::from_str` fails and hits `continue`. Please skip messages that have no `data:` line before parsing, for example by applying the existing `lines().find(|l| l.starts_with("data: "))` path to every message rather than only multi-line ones. That way comments aren't silently relying on a failed JSON parse.
2. **Update the handler's doc comment.** `streaming.rs` still says "Mirrors Python's `StreamedResponseHandler`", but with CR/CRLF normalization and comment-prefixed events it no longer does. Please adjust the comment so readers don't assume the two clients behave the same. The Python side can be aligned in a follow-up.
