# [Bugfix][LoRA] Don't reject LoRA for speculative decoding drafters

[Upstream PR](https://github.com/vllm-project/vllm/pull/63186) · state: closed · merged: True

## Original PR description



## Overview

Follow-up to #61884. `LoRAConfig.verify_with_model_config` now skips the `SupportsLoRA` check for speculative decoding drafters (`runner_type == "draft"`), so LoRA + spec decode works again with drafters that don't implement `SupportsLoRA`. Reported by @cjackal in https://github.com/vllm-project/vllm/pull/61884#issuecomment-6346398560 and the following comments.

## Claims

- With `enable_lora` and a drafter without `SupportsLoRA` (e.g. `DeepSeekMTPModel`), the draft `VllmConfig` validates again instead of raising `LoRA is not supported for ...`.
- Target models without `SupportsLoRA` (e.g. Zamba2) are still rejected at config time, as in #61884.
- No change for drafters that implement `SupportsLoRA` (e.g. EAGLE-Llama, Llama draft models).

## Validation

CPU reproduction: `EngineArgs(model="luccafong/deepseek_mtp_main_random", enable_lora=True, speculative_config={"method": "mtp", "num_speculative_tokens": 1}).create_engine_config()`, then `replace(cfg, model_config=cfg.speculative_config.draft_model_config)`, as `DraftModelProposer` and other proposers do:

| | main @ `71e9320633` | This PR |
|---|---|---|
| target `DeepseekV3ForCausalLM` (`SupportsLoRA`) | OK | OK |
| draft `DeepSeekMTPModel` (`runner_type="draft"`, no `SupportsLoRA`) | `ValidationError` from the LoRA check | OK |

Tests:

```bash
pytest tests/test_config.py -k lora
```

- New `test_lora_allowed_for_drafter_without_lora_support`; the existing #61884 test now sets `runner_type="generate"` and still checks the rejection.
- Full `tests/test_config.py`: 438 passed. The same 14 tests fail on main and on this branch, all on Hugging Face downloads (gated or unavailable models in my environment).
- `pre-commit run` on the changed files passes.

Validated on CPU only; I did not run LoRA + spec decode end to end on a GPU.

## Details

**Root cause:** `VllmConfig.__post_init__` calls `lora_config.verify_with_model_config(self.model_config)`. Several proposers rebuild the `VllmConfig` with the draft model config via `dataclasses.replace` (e.g. `DraftModelProposer`, Step-3.5, the MRV2 standalone/Gemma4 speculators, Qwen4Exp/Step5 MTP), so the check from #61884 also ran on the drafter.

**Fix:** skip the check when `model_config.runner_type == "draft"`. LoRA is only applied to the target model (`load_lora_model` wraps `self.model` in the model runners), so drafters don't need `SupportsLoRA`.
