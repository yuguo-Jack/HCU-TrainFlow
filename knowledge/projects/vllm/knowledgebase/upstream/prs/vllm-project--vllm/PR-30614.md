# [Feature] Default EPLB num_redundant_experts to minimum valid value

[Upstream PR](https://github.com/vllm-project/vllm/pull/30614) · state: closed · merged: True

## Original PR description

## Summary

EPLB requires enough physical experts for every expert-parallel rank. This PR
lets `num_redundant_experts` default to `None`, then normalizes it during
`VllmConfig` initialization to the minimum non-negative value that makes the
total number of physical experts divisible by the effective EP size.

## Changes

- default `EPLBConfig.num_redundant_experts` to `None`
- compute the effective EP size as `TP × PCP × DP`
- compute the default as:

  ```text
  (ep_size - num_logical_experts % ep_size) % ep_size
  ```

- normalize disabled EPLB to zero while preserving explicit non-negative values
- reject explicitly negative values
- keep downstream consumers typed against the post-initialization `int` invariant

## Tests

- EPLB enabled with the omitted default
- EPLB disabled normalization
- explicit values remain unchanged
- negative-value validation
- TP / PCP / DP combinations, including PCP values greater than one
- focused Ruff and mypy validation for the touched configuration contract

The full Python 3.10–3.13 pre-commit matrix, DCO, and Buildkite checks on the
current PR head are the final verification gates.

This is similar to how other cross-config computations work in VllmConfig's __post_init__.
