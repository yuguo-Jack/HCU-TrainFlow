# [Bugfix][Parser] Poolside: stray arg_key tags must not leak into tool-call argument keys

[Upstream PR](https://github.com/vllm-project/vllm/pull/56093) · state: open · merged: False

## Overview

`PoolsideV1ToolParser` can put stray `arg_key` tags into an argument **key**, e.g. `{"content</arg_key>": "hi"}`.

- Same bug and same fix as the GLM-4.7 parser in #54971.
- This call site was flagged during review of #54971.

## Claims

- Repeated or stray `<arg_key>` / `</arg_key>` tags no longer end up in the key.
- Well-formed input parses the same as before.
- No model eval: only malformed markup is affected.

## Details

**Root cause**

- `func_arg_regex` matched the key with `(.*?)</arg_key>`.
- `.*?` is lazy, but it can still run past the first `</arg_key>`.
- It does that when the text right after it is not `<arg_value>`, e.g. a duplicated tag.

**Fix**

```python
self.func_arg_regex = re.compile(
    r"<arg_key>([^<]*+(?:<(?!/?arg_key>)[^<]*+)*+)(?:</arg_key>\s*)+"
    r"<arg_value>(.*?)</arg_value>",
    re.DOTALL,
)
```

- The key can contain `<`, but never an `arg_key` tag, so it stops at the first `</arg_key>`.
- `(?:</arg_key>\s*)+` skips duplicated closing tags.
- This file uses the `regex` module, which supports possessive quantifiers.
- `func_arg_regex` has one call site (`extract_tool_calls`). The streaming path does not use it.

**Overlapping PRs**

- #54678 fixes backtracking in `func_detail_regex` and adds regex timeouts. It does not change `func_arg_regex`. Nearby lines, so a small rebase may be needed.
