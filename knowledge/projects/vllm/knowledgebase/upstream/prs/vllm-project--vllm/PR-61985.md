# [ROCm][Perf] MXFP4 indexer K cache for GLM-5 / DeepSeek-V3.2 DSA

[Upstream PR](https://github.com/vllm-project/vllm/pull/61985) · state: open · merged: False

## Original PR description



## Overview

On gfx950 with AITER, `--attention-config '{"indexer_kv_dtype":"mxfp4"}'` now also serves DeepSeek-V3.2 and GLM-5.x, MTP drafts included: their indexer writes the paged MXFP4 K cache that #58671 added for DeepSeek-V4.1, and the existing ROCm MXFP4 indexer scores it in place. FP8 stays the default. The code applies to main on its own; the gains below are measured on top of #61943, which should land first. Related: #48558, #60834.

## Claims

- GLM-5.2-MXFP4, MI355X, TP4, on top of #61943: KV cache +3.0% tokens; 128K/1K TPOT -5.4% / -5.9% at c8 / c16, MTP3 c8 -6.8%, TTFT -7% to -8%; c1 and 8K/1K within noise; gsm8k and passkey unchanged.
- Against main: 128K/1K TPOT -7.6% / -9.6% / -9.5% at c1 / c8 / c16, MTP3 c8 -6.7%.
- DeepSeek-V3.2, TP4, on top of #61943: KV cache +10.2% tokens; 128K/1K c8 TPOT -12.5%; c1 and 4K/1K c16 within noise; gsm8k unchanged.
- The FP8 default, gfx942, AITER off and non-ROCm platforms are unchanged.

## Details

- Write path: AITER's `k_norm_rope_mxfp4_cache` (DeepSeek-V4.1) applies RMSNorm and RoPE on the last dims; the V3.2 and GLM indexer key takes LayerNorm with bias and interleaved RoPE on the first 64 dims. So `fused_norm_rope` and `fused_q` quantize the key and query themselves, with AITER's scale rule and the page order from AITER's `cache_format()`.
- Gain: the scorer reads 68 instead of 132 bytes per key, and prefill scores the paged cache in place instead of gathering K. Both grow with context and batch. Short contexts pay the per-step decode schedule (about 25 us at 8-16 rows); 8K and 4K serving shows no change beyond noise.
- Limits: 64- or 128-token pages (other `--block-size` values fail at startup), no DCP or PCP (rejected at startup), gfx950 with AITER only. The new kernel tests need gfx950 and run in the optional MI355 kernels step.
