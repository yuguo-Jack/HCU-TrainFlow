# [Model] Update RADIO vision encoder to match the current Transformers version

[Upstream PR](https://github.com/vllm-project/vllm/pull/58468) · state: open · merged: False

## Original PR description

## Summary

vLLM's RADIO vision encoder (`radio.py`, added in #24595) is a fork of the original NVlabs remote-code RADIO: `ViTPatchGenerator` / `ClsToken` helper classes, a `model.`-nested module tree (`model.patch_generator.*`, `model.encoder.layers.*`), and a hand-rolled weight remapper that loads only the legacy remote-code checkpoint layout. This PR restructures it so the module tree and weight loading mirror the canonical Transformers `RadioModel` (`transformers.models.radio`), and fixes loading across the published C-RADIO checkpoint versions.

### Why v2, v3, and v4

vLLM's existing RADIO code (#24595) was written and tested against **C-RADIOv2** (`nvidia/C-RADIOv2-H`). The Transformers `RadioModel` this PR mirrors is shaped for **C-RADIOv4** -- its config defaults resolve to v4's token counts. Bridging the existing v2-era vLLM code to the v4-shaped Transformers modeling means the loader must span that range, so it supports **v2, v3, and v4** -- all published `C-RADIO*-H` checkpoints, which share one checkpoint layout and differ only in recipe counts (`teachers`, `register_multiple` / `cpe_num_registers`) that `RadioConfig` derives. `nvidia/C-RADIO` (v2.1 `mlpnorm`) is out of scope -- a different block architecture (per-block `mlp.norm`) that Transformers' `RadioModel` doesn't support either.

## Changes (relative to the existing vLLM RADIO)

- **Module tree** now mirrors the Transformers layout: the `model.`-nested `model.patch_generator.*` / `model.encoder.layers.N.*` becomes `embeddings.*` / `encoder.layer.N.*`. New `RadioPatchEmbeddings` / `RadioAttention` / `RadioLayer` (`norm1` / `attention` / `layer_scale1` / `norm2` / `mlp` / `layer_scale2`) / `RadioLayerScale` replace `RadioInternVisionModel`, the `ViTPatchGenerator` / `ClsToken` helpers, and the old `self.layers` / `attn` / `ls1` naming.
- **Weight loading**: the hand-rolled, legacy-only remapper is replaced by a `WeightsMapper` (`hf_to_vllm_mapper`) that maps the published checkpoint keys (`radio_model.model.blocks.*`, fused qkv) onto the new tree, and also accepts the native Transformers key layout. `load_weights` now warns when it matches zero tensors instead of silently leaving the tower at random init.
- **Config**: the token-count derivation (`num_cls_tokens` / `num_registers` / `summary_idxs`) moves from the model into `RadioConfig`. Adds `cpe_num_registers` -- C-RADIOv3 sets `register_multiple=0` and carries its register count there, and without deriving it the config built 4 register tokens where the checkpoint ships 8 (v3 failed to load). Adds `layerscale_value`.
- **Consumer**: `nano_nemotron_vl` vision-weight routing broadened (`vision_model.radio_model.` -> `vision_model.`) so RADIO tower keys reach `RadioModel`.
- **Tests**: `test_radio.py` previously covered only `C-RADIOv2-H`; now parametrized over `C-RADIOv2-H` / `v3-H` / `v4-H`, crops each image to the tower's own `min_resolution_step` (it differs across generations; the old crop hard-coded v2's geometry), and adds a weight-loading round-trip unit test.

### Unchanged from the existing vLLM RADIO (noted because they differ from Transformers)

- Attention keeps vLLM's **existing** fused `QKVParallelLinear` (renamed `attn.qkv` -> `attention.qkv`) rather than HF's split `query`/`key`/`value` -- required for tensor-parallel + quantization; the mapper fuses native split projections into it and loads the legacy fused tensor directly.
- Image normalization stays in the input processor (mean/std from config); `input_conditioner` weights are dropped, as before, avoiding fp16/bf16 precision loss.
- Dynamic-resolution packed attention (`MMEncoderAttention`), video temporal compression, and TP/quantization support are carried over unchanged.

### Why the derivation is needed

vLLM consumes NVIDIA's published `config.json` as-is, which states only the recipe (`teachers`, `register_multiple` / `cpe_num_registers`) -- never the resulting token counts, so `RadioConfig` derives them. (Transformers' `RadioConfig` instead states v4-shaped defaults and doesn't read these fields, and `AutoModel` refuses these repos entirely -- `auto_map` remote-code, no `model_type: radio` -- so it cannot load them without a caller supplying the counts from outside.)

## Testing

`pytest tests/models/multimodal/pooling/test_radio.py -v` -> **9 passed** (NVIDIA GB200, transformers 5.17.0). Cosine similarity is vLLM vs. the NVlabs remote-code reference (`trust_remote_code`):

| checkpoint | dtype | params loaded | cosine (summary / features) |
|---|---|---|---|
| nvidia/C-RADIOv2-H | half, bf16 | 387/387 | 1.000000 / 1.000000 |
| nvidia/C-RADIOv3-H | half, bf16 | 387/387 | 1.000000 / 1.000000 |
| nvidia/C-RADIOv4-H | half, bf16 | 387/387 | 1.000000 / 1.000000 |

The `RadioConfig`-derived token counts and `summary_idxs` also match each checkpoint's stored tensors exactly (v2/v3: 8 tokens, `[0,1,2]`; v4: 10 tokens, `[0,1]`).

## Model evaluation

Behavior-preserving for the models that use RADIO. Branch-vs-stock A/B on MMMU (`mmmu_val`) for two public checkpoints, verified from both arms' server logs (identical model, image, TP, decoding, and doc set):

| model | MMMU config | stock (upstream RADIO) | this branch | answer rate | result |
|---|---|---|---|---|---|
| Nemotron-Nano-12B-VL | `--limit 20`, greedy | 0.5150 | 0.5150 | 95% | equivalent, no change |
| Nemotron-3-Nano-Omni-30B | n=600, temp 0.6 / top-p 0.95, TP=4 | 0.6217 +/- 0.019 | 0.6667 +/- 0.018 | 76% | no detectable difference (~1.7 sigma), no regression |

The 30B gap is within this model's run-to-run spread at temp 0.6 (repeated measurements span ~0.045) -- not an improvement. Both 30B scores are floors: ~24% of responses never reach an answer letter and are random-guessed equally in both arms. Merging this PR does not regress either supported model.

## Not a duplicate

Updates the existing in-tree RADIO (added in #24595) to track current Transformers; not a new/competing implementation.
