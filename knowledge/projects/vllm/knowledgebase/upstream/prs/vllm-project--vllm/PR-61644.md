# [SP][Async-TP] 1/N: Add eager-mode SP + Async-TP support

[Upstream PR](https://github.com/vllm-project/vllm/pull/61644) · state: open · merged: False

## Original PR description

## Summary

This is PR **1 of a series** implement the eager-mode Sequence Parallel (SP) + Async-TP mechanism  . See the companion [RFC](https://github.com/vllm-project/vllm/issues/61626) 


### E2E Test plan

**Server**  

```bash
# Baseline
VLLM_ALLOW_LONG_MAX_MODEL_LEN=1 VLLM_WORKER_MULTIPROC_METHOD=spawn \
python3 -m vllm.entrypoints.openai.api_server \
    --model Qwen/Qwen3-32B --port 8072 --host 0.0.0.0 --trust-remote-code \
    --dtype bfloat16 --gpu-memory-util=0.9 --no-enable-prefix-caching \
    --max-num-batched-tokens=16384 --max-model-len=8448 --block-size 64 \
    -tp=4 --enforce-eager

# SP
VLLM_ALLOW_LONG_MAX_MODEL_LEN=1 VLLM_WORKER_MULTIPROC_METHOD=spawn \
python3 -m vllm.entrypoints.openai.api_server \
    --model Qwen/Qwen3-32B --port 8072 --host 0.0.0.0 --trust-remote-code \
    --dtype bfloat16 --gpu-memory-util=0.9 --no-enable-prefix-caching \
    --max-num-batched-tokens=16384 --max-model-len=8448 --block-size 64 \
    -tp=4 --enforce-eager --enable-sequence-parallel

# AsyncTP
VLLM_ALLOW_LONG_MAX_MODEL_LEN=1 VLLM_WORKER_MULTIPROC_METHOD=spawn \
python3 -m vllm.entrypoints.openai.api_server \
    --model Qwen/Qwen3-32B --port 8072 --host 0.0.0.0 --trust-remote-code \
    --dtype bfloat16 --gpu-memory-util=0.9 --no-enable-prefix-caching \
    --max-num-batched-tokens=16384 --max-model-len=8448 --block-size 64 \
    -tp=4 --enforce-eager --enable-sequence-parallel --enable-async-tp
```

- `sp` alone (decoupled path, no fused kernel) is within ±1.4% of `baseline` on every shape — it trades one collective (all-reduce) for two (all-gather + reduce-scatter) without recovering the time via overlap, as  expected.
- `asynctp` (sp + fused AllGather+GEMM/GEMM+ReduceScatter) wins on every  shape, with the largest gains on the pure-prefill shapes where there's the  most communication to hide behind compute (+23-24% total tok/s, -19% TTFT).

#### Accuracy (GSM8K, 5-shot, 250 questions, single run each)

| Case | Accuracy | Invalid rate | Questions/s | Tokens/s |
|---|---:|---:|---:|---:|
| baseline | 0.676 | 0.0 | 11.737 | 2120.38 |
| sp | 0.660 | 0.0 | 11.635 | 2063.62 |
| asynctp | 0.668 | 0.0 | 12.267 | 2200.08 |

#### Kernel microbenchmark (TP=2, single linear layer, full M sweep 128→32768; `benchmarks/kernels/benchmark_sequence_parallel.py`)

- AG side (qkv/gate_up): SP always costs more than plain-TP `baseline` — expected, plain TP has no collective at this boundary at all.
- RS side (o/down): SP beats `baseline` once M is large enough (fused reaches ~-40% at M≥8192); `fused` only beats `unfused` once M≳512-1024, below that the overlap doesn't pay for the extra kernel overhead.
- Net e2e win only comes from AsyncTP's fused kernels overlapping the AG-side cost while keeping the RS-side savings — consistent with the E2E results above.
