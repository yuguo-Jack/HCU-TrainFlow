# [2/3][Spec Decode] Run own-KV drafts on a standalone GPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/63334) · state: open · merged: False

## Original PR description

## Overview

Run supported target-conditioned own-KV EAGLE3/MTP speculators in a standalone GPU process using native MRV2 execution. Include native checkpoint loading, contract and model-level regression coverage with the runtime.

Based on [vllm-project/vllm#63333](https://github.com/vllm-project/vllm/pull/63333). Related design: [RFC #42109](https://github.com/vllm-project/vllm/issues/42109). This is part 2/3 (GPU execution) of the standalone placement series.

## Claims

- Load native draft weights and compatible shared target embedding/head tensors, including Nemotron checkpoint aliases, then warm prefill and decode before admission.
- Maintain draft KV across chunked prefill, rejection, row reordering and effective K=0..capacity; reject insufficient effective draft context before native execution.
- Verify remote proposals through the native target path and test supported MTP loading, feature contracts and standalone/native model behavior in the same increment.
- Exercise real socket-cleanup failure through the public LLM API, checking exact target-only continuation, terminal request fencing and remote recovery for a fresh request.

## Details

Standalone MTP requires the draft's effective `ModelConfig.max_model_len` to cover the target limit. Contract validation rejects a shorter draft before native model execution. Model-level tests accompany the runtime and exercise native constructors/loaders, shared-weight identity and real target/native/remote comparisons.

Execution is same-host, greedy and eager, with draft TP1. Prefix caching, async scheduling, streaming input, LoRA and multimodal requests remain restricted for this backend. The native model implementations perform computation; this change supplies process placement and its state contract.

The intended benefit is target GPU memory relief and placement flexibility, following the [MTP offload question in the RFC](https://github.com/vllm-project/vllm/issues/42109#issuecomment-4561513801). Compare performance with native local MTP/EAGLE3 as well as target-only execution. Separate processes can add transfer and preparation latency, and a dedicated draft device increases total memory use. More available target KV does not by itself establish a larger supported context length. This increment does not implement the RFC's predictive fan-out cache or claim target/draft compute overlap.
