# [Perf] Overlap FlashInfer sampler JIT with model initialization

[Upstream PR](https://github.com/vllm-project/vllm/pull/62512) · state: open · merged: False

## Original PR description



## Overview

FlashInfer's first sampling-module build can extend the model initialization critical path. Start that same build during sampler construction and wait before worker readiness or sampling, overlapping it with independent startup work.

AI assistance was used: OpenAI Codex assisted implementation, review, local validation, and preparation of this description.

## Claims

- Overlap the selected FlashInfer sampling JIT with initialization in both GPU runner implementations, using one shared implementation.
- Keep pending/readiness state per device, select the device in the build thread, and propagate build errors while allowing a later initialization to retry.
- Limit the patch to three implementation files and the existing sampler test file: 80 implementation lines and 122 test lines. The native sampler, sampling algorithm, precision, serving flags, and dependencies are unchanged.

This remains unresolved and warrants a dedicated higher-repetition check before claiming broad serving parity.

## Details

Sampler construction submits the existing FlashInfer `get_sampling_module()` build to a single-worker executor. A lock deduplicates submissions per device; successful builds are remembered. The worker joins before initialization finishes, and `flashinfer_sample` also waits before using the module. Failed futures never mark a device ready and are removed after propagating the exception. Existing eligibility checks gate scheduling, so disabled/unsupported FlashInfer does not start a build thread.

The executor is process-shared and creates its thread only on submission. No local compile timeout is added. Normal startup and shutdown were exercised, but a deliberately hung native compile and shutdown during active compilation were not fault-injected; interpreter shutdown can wait on an unfinished build. Per-device mocks are not physical multi-GPU validation.

Duplicate-work checks were refreshed on 2026-10-19 against current main and open PRs. No equivalent background sampler-build implementation was found. Related work remains distinct: #51741 handles build-failure fallback, #54630 addresses explicit-seed native warmup from #54425, #57926 changes sampler profiling parameters, and #60514 handles missing-nvcc fallback. This patch preserves current main's failure behavior; if the fallback work lands first, its policy must be reconciled with the readiness join.
