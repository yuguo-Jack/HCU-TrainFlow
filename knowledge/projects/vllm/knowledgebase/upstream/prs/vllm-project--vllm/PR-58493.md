# [Bugfix][Frontend] Avoid IndexError when verbose ASR emits only EOS

[Upstream PR](https://github.com/vllm-project/vllm/pull/58493) · state: open · merged: False

## Original PR description

## Purpose

Fixes #58492.

`_get_verbose_segments` strips a trailing EOS and then indexes `tokens_with_start[-2]`. A silent Whisper chunk can finish with only EOS, so the sequence is empty and `verbose_json` raises `IndexError`. Return no segments in that case.

Not a duplicate: no open PR covers this empty-sequence crash. #43278 only caches the `<|0.00|>` token id.

## Test Plan

- Call `_get_verbose_segments` with `()`, `(eos,)`, and a closed timestamp span.
- `.venv/bin/python -m pytest --noconftest -p pytest_asyncio tests/entrypoints/speech_to_text/transcription/test_chunk_timestamp_offset.py tests/entrypoints/speech_to_text/transcription/test_transcription_inter_chunk_spacing.py tests/entrypoints/speech_to_text/transcription/test_qwen3_asr_sanitize_prompt.py -q --disable-warnings`

## Test Result

- Empty tokens, EOS-only, and a 30s–31s `"hi"` span all returned the expected segments.
- The pytest command above: **36 passed** in 10.49s.

- Perlover · comment · 2026-10-22T09:09:09Z · [source](https://github.com/vllm-project/vllm/pull/58493#issuecomment-6337064527)

Tested this change as a backport on v0.27.1 (`vllm/vllm-openai:v0.27.1-cu129-ubuntu2404`, `openai/whisper-large-v3-turbo`) in our serving image — works for us, +1.

What we checked:

- **Function level, inside the image.** The unpatched `_get_verbose_segments` raises `IndexError` on `(eos,)` and on `()`; with this patch both return `[]`. On 400 seeded random non-empty token sequences (text tokens, monotonic timestamps, with and without a trailing EOS) plus a single-timestamp answer, the unpatched and the patched function return identical segments, field by field — no behaviour change outside the empty case.
- **Through the real server code with a stub engine.** `OpenAIServingTranscription.create_transcription` → `_create_speech_to_text` (patched files, only the engine/tokenizer stubbed): a `verbose_json` request where one chunk decodes to EOS only now returns 200 with that chunk contributing no segments, instead of the `IndexError`.
- **End to end on GPU** (RTX PRO 4000 Blackwell): 33 recordings × `json`/`verbose_json`/`text` × auto/`ru` language — 198 responses byte-identical before and after the patch, all 200.

One caveat: with large-v3-turbo we could not make the model emit an EOS-only chunk end to end (60+ probes of silence, noise, tones and short trailing chunks — it hallucinates "Thank you." instead), so the crash itself was confirmed at the function level, not from a live request. Our image carries a few other local patches to `speech_to_text`; this hunk applied cleanly on top of them.
