# [Bugfix][CI] Fix depyf compatibility with PyTorch 2.14

[Upstream PR](https://github.com/vllm-project/vllm/pull/64803) · state: closed · merged: False

## Original PR description

## Overview

Fix `compile/fullgraph/test_full_graph.py::test_custom_compile_config[compilation_config3-facebook/opt-125m-model_kwargs3]` in CI.  E.g. [main-branch Buildkite run #98732](https://buildkite.com/vllm/ci/builds/98732/table?jid=01a18d91-e51c-4804-959e-7e5d4fa8bf8d&tab=output).

Failure was exposed by the [automatic fullgraph sharding PR #64635](https://github.com/vllm-project/vllm/pull/64635).

Before sharding, the test shared a cache with another test that created an AOT artifact. After sharding, it could run alone with a cold cache and expose a pre-existing `depyf`/PyTorch 2.14 incompatibility.

## Claims

- The cold-cache test no longer fails with `patched_load_by_key_path() got an unexpected keyword argument 'set_sys_modules'`.
- The long-term fix belongs upstream in `depyf`; this is a vLLM compatibility shim until that fix is released.

## Validation

```bash
aot_cache=$(mktemp -d /tmp/vllm-aot-repro.XXXXXX)
VLLM_CACHE_ROOT="$aot_cache" \
VLLM_USE_AOT_COMPILE=1 \
VLLM_DISABLE_COMPILE_CACHE=0 \
pytest -s -v \
  'compile/fullgraph/test_full_graph.py::test_full_graph[facebook/opt-125m-model_kwargs0-3]' \
  'compile/fullgraph/test_full_graph.py::test_custom_compile_config[compilation_config3-facebook/opt-125m-model_kwargs3]'
```

Pass on both main and this PR because test_`full_graph[facebook/opt-125m-model_kwargs0-3]` created an AOT artifact in the shared cache before `test_custom_compile_config[compilation_config3-facebook/opt-125m-model_kwargs3]` ran.

```bash
repro_cache=$(mktemp -d /tmp/vllm-repro.XXXXXX)
VLLM_CACHE_ROOT="$repro_cache" \
VLLM_USE_AOT_COMPILE=1 \
VLLM_DISABLE_COMPILE_CACHE=0 \
pytest -s -v \
  'compile/fullgraph/test_full_graph.py::test_custom_compile_config[compilation_config3-facebook/opt-125m-model_kwargs3]'
```

Fails on main with `torch._inductor.exc.InductorError: RuntimeError: Failed to run autotuning code block: patched_load_by_key_path() got an unexpected keyword argument 'set_sys_modules'`. Passes on this branch.

## Details

`depyf==0.20.0` patches Torch Inductor's `PyCodeCache.load_by_key_path` but does not accept PyTorch 2.14's new `set_sys_modules` keyword. The compatibility shim adds the keyword to the patched wrapper and forwards it to Torch's original loader while preserving depyf's source dumping.

The cleanest permanent fix is to update depyf's wrapper and then bump vLLM's depyf dependency and remove the shim.
