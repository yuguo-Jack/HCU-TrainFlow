# [Docs] List the Nemotron-3-Diarization plugin

[Upstream PR](https://github.com/vllm-project/vllm/pull/65199) · state: closed · merged: True

## Original PR description

## Overview

Lists NVIDIA Nemotron-3-Diarization (`Nemotron3DiarizationForAudioFrameClassification`, [`nvidia/Nemotron-3-Diarization`](https://huggingface.co/nvidia/Nemotron-3-Diarization)) as supported through the out-of-tree [vllm-nemotron-diarization-plugin](https://github.com/Alex-Wengg/vllm-nemotron-diarization-plugin).

## Why a plugin, not in-tree

#65002 added this model in-tree. @DarkLight1337 asked there:

> This is quite a small model. I wonder how much performance improvement does vLLM actually provide here over other baselines?

Not much: the model runs the Transformers forward once per recording, so offline throughput is close to calling Transformers directly. The value is convenience. Developers who already run vLLM can add speaker diarization with one `pip install`, through the same `LLM` API as their other models, without a separate NeMo setup. A plugin gives them that without vLLM carrying the model. He closed #65002 with:

> If you are ok with maintaining it and feel that it's valuable then you could do plugin. Either way let's close this PR.

So the model lives out of tree, and I maintain the plugin.

## Claims

- One row in the plugin table in `supported_models.md`.
- No vLLM code changes.

## Validation

The plugin on CPU with the V1 model runner, fp32, against Transformers `Nemotron3DiarizationForAudioFrameClassification` (two vLLM audio assets resampled to 16 kHz):

| Check | Result |
| --- | --- |
| Logits vs Transformers (2542 and 1595 frames) | max \|Δ\| ~2e-5, identical speaker segments |
| Batched vs single requests | identical |
| Prompt without audio | no frames, no crash |

## Details

- The plugin carries #65002's model, processor and config hooks without its core changes. Model Runner V2 has no path for raw-input-only models, so the plugin's `ModelState` hands each request's audio features to the model, as the V1 runner does natively. A prompt without audio returns no frames instead of being rejected in `input_processor.py`.
- No `_OOT_SUPPORTED_MODELS` entry, as with #65005: Transformers defines `Nemotron3DiarizationForAudioFrameClassification`, so without the plugin vLLM resolves it to the Transformers backend (`TransformersForCausalLM`) before it checks that table.
- AI assistance (Claude Code) was used to write the plugin and this PR. I reviewed the changed lines and ran the validation above.
