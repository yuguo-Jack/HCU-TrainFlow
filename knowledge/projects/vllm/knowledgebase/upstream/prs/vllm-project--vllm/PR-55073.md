# [Bugfix] Reconcile mismatched NVFP4 MoE w13 global scales

[Upstream PR](https://github.com/vllm-project/vllm/pull/55073) · state: open · merged: False

## Original PR description

## Summary

NVFP4 fused MoE checkpoints may contain different per-expert global
scales for the gate and up projections.

The previous loading path detected this mismatch but retained only the
gate scale for fused w13, causing the up half to use the wrong effective
dequantization scale.

## Fix

- Reconcile gate/up `scale_2` per expert using their shared maximum.
- Rescale each half's E4M3 block scales to preserve its original
  effective dequantization scale.
- Leave the FP4 payload unchanged.
- Keep matching-scale checkpoints on a no-op path.
- Reuse the logic across ModelOpt, Quark, and compressed-tensors.
- Skip HUMMING because its converter already folds each half's
  `scale_2` into its block scales.

This follows the same max-scale policy used by vLLM's fused FP8 paths.

- sethforprivacy · comment · 2026-09-30T21:43:04Z · [source](https://github.com/vllm-project/vllm/pull/55073#issuecomment-5920242666)

_Posted by Claude (AI assistant) on behalf of @sethforprivacy, as part of our local-inference tuning work._

End-to-end data point for this fix, on a real checkpoint with a large gate/up `weight_scale_2` mismatch (the situation in #54974).

**Checkpoint.** `Blackfrost-AI/CYBER-FROST-3.8-NVFP4` @ `ac0e3c69` (`Qwen4ExpForConditionalGeneration`, ModelOpt 0.47.0rc0 `MIXED_PRECISION` export, routed experts NVFP4 W4A4 group 16). Across all 24,576 experts (48 layers × 512), w1/w3 `weight_scale_2` ratios are:

- min 0.209, p10 0.741, median 1.070, p90 1.624, p99 2.50, max 4.83
- 40 % of experts differ by more than 25 %; only 0.9 % are equal
- `input_scale` is identical for gate and up

In every sampled expert, both halves' E4M3 block scales reach 448. So each half was quantized against its own global scale. Keeping only the gate scale therefore multiplies every expert's up-projection, and so its output, by w1_scale_2/w3_scale_2.

**Setup.** vLLM v0.30.0 plus unrelated Qwen4Exp patches, on 2× DGX Spark (GB10, SM121), TP=2, `--moe-backend flashinfer_cutlass`. I hand-ported only the ModelOpt part of this PR to v0.30.0's `ModelOptNvFp4FusedMoE.process_weights_after_loading`. Per expert it takes the max of the two global scales, rescales each half's E4M3 block scales by its own scale divided by that max, and leaves the FP4 payload untouched. Everything else was identical between the two boots.

**Result.** Teacher-forced NLL (`prompt_logprobs`) on a fixed 29,166-token held-out set of Python stdlib code, C sources and GPL-3 prose:

| | mean NLL | top-1 agreement |
|---|---|---|
| v0.30.0 (gate scale only) | 0.4755 | 0.8945 |
| + this PR's reconciliation (ported) | **0.3866** | **0.9130** |

That is −18.7 % NLL from the reconciliation alone. The per-layer log lines at load match an offline audit of the checkpoint (for example, layer 0 ratio range 0.358–3.185).

One side effect, specific to this checkpoint: its BF16 MTP head agreed less with the corrected target. MTP acceptance at temperature 1 fell from 0.59 to 0.53, so single-stream decode dropped about 10 %. That comes from the draft head, not the fix.

+1 for merging. Happy to re-run on a rebased branch.
