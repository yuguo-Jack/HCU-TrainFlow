# [Bugfix][Multimodal] Fix PaliGemma prefix attention range

[Upstream PR](https://github.com/vllm-project/vllm/pull/63044) · state: open · merged: False

## Original PR description

## Overview

Fix PaliGemma prefix-LM range construction so the full prompt (image tokens plus instruction text) receives bidirectional attention. Fixes #62968.

This is a draft pending CUDA end-to-end validation with PaliGemma2 weights.

## Claims

- Marks PaliGemma as requiring full-prompt bidirectional prefix attention.
- Uses the prompt length in both the legacy GPU runner and MRV2 while keeping generated tokens causal.
- Preserves image/video-placeholder-only ranges for other multimodal prefix-LM models.

## Validation

- `.venv/bin/python -m pytest tests/v1/attention/test_mm_prefix.py::test_bidirectional_prompt_range_includes_instruction_tokens -v`: **1 passed**.
- `.venv/bin/pre-commit run --files tests/v1/attention/test_mm_prefix.py vllm/model_executor/models/paligemma.py vllm/v1/worker/gpu/attn_utils.py vllm/v1/worker/gpu/model_states/default.py vllm/v1/worker/gpu_model_runner.py`: **passed**, including Ruff and mypy.
- CUDA model evaluation: **not run** because this development host has no CUDA GPU. Before marking ready, validate `google/paligemma2-3b-pt-224` with the fixed image and `caption en` reproducer from #62968, and record before/after output.

Duplicate-work check: searched open PRs for `#62968` and PaliGemma bidirectional-prefix/instruction keywords; no matching open PR was found. The only search hit, #53979, concerns NVFP4 KV/FlashInfer and is unrelated.

## Details

PaliGemma's processor assigns `token_type_id = 0` to the entire input prompt. vLLM currently derives `mm_req_doc_ranges` only from the image placeholder, leaving trailing instruction tokens causal.

The model now declares `mm_prefix_bidirectional_prompt`. Both runner implementations use the original prompt length to emit `(0, prompt_len - 1)`; decode positions remain outside that range. This keeps the change model-scoped and avoids carrying processor-specific `token_type_ids` through the scheduler.

Trade-off: this models PaliGemma's current all-prompt prefix contract as a model capability instead of adding general per-token prefix metadata. Maintainers should confirm that this model-scoped approach is preferred before the PR is marked ready.

AI assistance was used to inspect the affected paths, implement the patch, and draft this PR. The human submitter remains responsible for reviewing every changed line and completing GPU validation.
