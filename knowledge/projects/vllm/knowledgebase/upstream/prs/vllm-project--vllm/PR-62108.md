# [Bugfix] Skip request body JSON serialization when its log level is disabled

[Upstream PR](https://github.com/vllm-project/vllm/pull/62108) · state: open · merged: False

## Original PR description



## Overview

Avoid serializing request JSON when the configured request-body logging level is disabled. This restores the logger-level guard removed by #60630 while preserving configurable body log levels.

## Claims

- Disabled request-body logging no longer calls `model_dump_json`.
- Enabled INFO body logging still works when DEBUG is disabled; existing body truncation remains unchanged.
- No measured end-to-end speedup is claimed.

## Why this is not duplicating an existing PR

Scoped searches (open and all-state) for `log_request_body`, `60630`, `isEnabledFor` + request logging, and request-body serialization found no PR adding this guard. Nearest work inspected: #60498 (Prometheus counters), #38583 (opt-in INFO prompt summaries), #58712 (LoggingConfig log_color/log_stream fields), RFC issue #57200. None touches the eager serialization in `log_request_body`.

## Details

Python evaluates `model_dump_json(...)` before `logger.log` checks its level. `BaseServing._check_model` calls this helper when request logging is enabled, including completions, chat completions and Responses paths. With the default DEBUG body level and INFO logger threshold, request bodies are needlessly serialized even though no body record is emitted. Request logging is opt-in; deployments without it are not affected. Pooling overrides `_check_model`, so this report does not claim pooling impact.

The fix checks `logger.isEnabledFor(level)` after resolving the configured level and before serialization, matching the existing `isEnabledFor` use elsewhere in this file. It does not try to predict later handler/filter rejection. Tests use a real CompletionRequest and real logger, tracking the serializer through a wrapper instead of substituting a fabricated request.

On configuration mechanism: markmc's post-merge comment on #60630 suggests the body log level belongs in the typed `--logging-config` (#57200) rather than a new env var. This guard is independent of where the level comes from: whether the level continues to be read from the env var or moves into `LoggingConfig`, serialization should still be skipped when that level is disabled. This PR intentionally does not restructure the configuration.
