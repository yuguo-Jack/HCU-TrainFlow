# [CI][Kimi-K3] Add enable_adaptive_verification to the KDA checkpoint test stub

[Upstream PR](https://github.com/vllm-project/vllm/pull/64619) · state: closed · merged: True

## Original PR description



## Overview

Fixes the `:amd: (MI355) Kimi K3` CI failure on main by adding `enable_adaptive_verification = False` to the speculative config fake in `tests/models/kimi_k3/test_amd_kda_checkpoint.py`.

## Claims

- Fixes `test_spec_checkpoint_metadata_gathers_non_spec_rows_by_index`, which currently fails with `AttributeError: '_StubSpeculativeConfig' object has no attribute 'enable_adaptive_verification'`.

## Validation

- Failing CI log, seen on PR #63205, whose branch already contains #60229: https://buildkite.com/vllm/ci/builds/98435 (`:amd: (MI355) Kimi K3`).
- Not run locally: the test needs ROCm, and I don't have MI355 access. CI on this PR covers it. pre-commit passes.

## Details

#60229 added a direct read of `speculative_config.enable_adaptive_verification` to `GDNAttentionMetadataBuilder.__init__` (`vllm/v1/attention/backends/gdn_attn.py`). `KimiK3ROCmKDAMetadataBuilder` inherits it. The test's `_StubSpeculativeConfig` doesn't define the attribute, so building the metadata builder raises. Real `SpeculativeConfig`s always define the field, so the fake is fixed rather than the builder.
