# [CI] Fix Buildkite path filters that point at moved or deleted files

[Upstream PR](https://github.com/vllm-project/vllm/pull/61058) · state: closed · merged: True

## Original PR description



## Overview

Fix Buildkite path filters (`source_file_dependencies` and two other path lists) that point at files which were moved or deleted. Part of #51225; complementary to #51345, whose six entries this PR leaves untouched so the two do not conflict.

## Claims

- 78 dead path entries across 16 pipeline files now match real files (or are removed), so the affected steps trigger again when the code they cover changes.
- Most dead entries were in the AMD/Intel mirrors and `test-amd.yaml`, which missed renames the main steps already picked up (e.g. `rust_frontend.yaml` main step lists `tests/entrypoints/launchers/test_shutdown.py`, its AMD mirror still listed `tests/entrypoints/openai/completion/test_shutdown.py`).
- No step, command or other dependency entry changes.

## Validation

- Dead-entry scan (every YAML list item under `.buildkite/` that is a repo path, matched by prefix against `git ls-files`): 84 dead entries on `61f084b5f3`, 6 after this PR, exactly the ones #51345 changes (engine `logger.py`, the two DeepSeek V4 kernel `.cu` paths, `csrc/mamba/`, the first samplers step and its mirror).
- Every remapped path was resolved from git history (`git log --diff-filter=DR -1 -- <path>`, `git show -M --stat <sha>`), not by name guessing; removed entries point at files deleted outright or never added.
- `pre-commit run --files <changed files>`: all hooks pass, including `check-buildkite-step-keys` and `check-test-tethering`; all changed YAML files parse.
- Changed-line tally (`git diff -U0 | grep '^[-+] ' | sort | uniq -c`) checked so only dependency entries changed.
- Not run: the rendered pipeline itself (the Jinja template lives in `vllm-project/buildkite-ci`).

Where the new path was already in the same list, the stale line is dropped instead of duplicated.

Tradeoff: restoring these filters means some AMD/Intel mirror steps trigger again on changes to the files they were meant to cover, which slightly raises CI load back to the intended level.

Interaction with #59706: after this PR, 18 of the 22 entries in its `source_file_dependencies_allowlist.txt` are no longer dead (the other four are the paths #51345 owns), so whichever lands second should shrink the allowlist; after both, it can be empty.
