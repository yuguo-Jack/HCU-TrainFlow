# [Core] Add context_tokens DP load-balancing policy

[Upstream PR](https://github.com/vllm-project/vllm/pull/63503) · state: closed · merged: False

## Original PR description

## Purpose

Add a `context_tokens` data-parallel load-balancing policy: `--data-parallel-lb-policy {requests,context_tokens}`. The default, `requests`, is unchanged.

The default policy balances DP engines by request counts (waiting and running). When prompt lengths vary widely, as in agentic coding workloads, request counts poorly reflect engine load. Decode cost per step is dominated by attention over each request's context, and in DP + EP decode every step waits for the slowest rank.

With `context_tokens`:

- each engine reports the total tokens (prompt + output) of its running and waiting requests alongside its request counts, and the DP coordinator relays it;
- the API servers route each request to the engine with the fewest context tokens, breaking ties with the existing request-count score;
- prompt tokens routed between coordinator updates are added locally, so a burst spreads by tokens.

## Test Plan

- Unit tests in `tests/v1/engine/test_engine_core_client.py`:
  - `test_dplb_context_tokens_policy_prefers_fewest_tokens`: the engine with the fewest context tokens wins, even with more requests; request load breaks ties.
  - `test_dplb_context_tokens_policy_counts_routed_prompts`: prompt tokens routed between coordinator snapshots are counted locally.
  - `test_dplb_context_tokens_republished_while_counts_unchanged`: under `context_tokens`, an engine republishes its context tokens once the refresh interval passes, even when its request counts are unchanged. `requests` still publishes only count changes. Covered for `EngineCoreProc` and `DPEngineCoreProc`.
  - All 17 `test_dplb_*` cases pass.
- End-to-end A/B on Kimi K3 (hybrid KDA + MLA, MXFP4) on GB300, replaying agentic coding traces at three concurrencies:
  - Disaggregated: prefill is 3 workers × TP8/EP8; decode is DEP16 (4 nodes × 4 DP ranks) with the `KIMI_K3_KV_BALANCED_MLA` attention backend.
  - The router picks the decode node, so the policy balances the 4 local DP ranks of each node (hybrid LB).
  - The baseline is vLLM main plus an unrelated Mooncake store change. The `context_tokens` arm is the same build plus this PR, and only the decode `--data-parallel-lb-policy` differs.

- **Consistent gain.** At all three concurrencies, throughput per GPU rises 2.1–2.9% and P90 ITL falls 4–7%. Interactivity rises 4–8% and P90 E2E latency falls 2.5–4.2%.
- **The gain is on decode.** Balancing by context tokens evens out the attention work across the DP ranks that each step waits on.
- **TTFT P90 rises at 288 and 336** (+0.4 s and +0.3 s). Those points are already prefill-bound, so faster decode completes requests sooner and sends more load back to prefill. At 256, where prefill has headroom, TTFT is unchanged. The prefix cache hit rate is unchanged.
