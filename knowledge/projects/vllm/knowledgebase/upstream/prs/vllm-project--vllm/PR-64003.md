# [Bugfix][Structured Output] Short-circuit validate_tokens() after FSM termination in xgrammar backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/64003) · state: closed · merged: False

## Original PR description

## Overview

Fixes #55313. `XgrammarGrammar.validate_tokens()` kept probing the xgrammar matcher after the grammar had already terminated, which could spam the "matcher has terminated... trying to accept new token" C++ warning during speculative-decoding verification.

## Root cause

`XgrammarGrammar.accept_tokens()` (`vllm/v1/structured_output/backend_xgrammar.py`) already short-circuits when `self._is_terminated` is set, and so does the parallel `GuidanceGrammar.validate_tokens()` in `backend_guidance.py` (`if self.ll_matcher.is_stopped(): return []`). `XgrammarGrammar.validate_tokens()` was the odd one out: it had no termination check at all, so once the FSM accepted its stop token, every subsequent speculative-decoding verification step still looped over draft tokens and called `self.matcher.accept_token()` on an already-terminated matcher.

This matches the root cause an issue commenter traced from source (pinning the exact missing-guard lines) in #55313, and reproduces the exact `grammar_matcher.cc` warning from that report's server logs.

## Fix

Add the same termination guard `accept_tokens()` already has, at the top of `validate_tokens()`:

```python
if self._is_terminated:
    return []
```

## Validation

New regression test in `tests/v1/structured_output/test_backend_xgrammar.py`, built the same way `test_backend_guidance.py` builds its grammar (`XgrammarBackend.compile_grammar()` with a real tokenizer), so it exercises the real `xgrammar` matcher rather than a mock:

- Drives a real grammar to termination (accepts the stop token).
- Wraps the real matcher's `accept_token` and asserts it is never called again once terminated.

**Negative control:** reverting just the 2-line fix makes the new test fail, with the matcher logging the same warning the issue reports:
```
grammar_matcher.cc:1239: Warning: The matcher has terminated after accepting the stop token, but is trying to accept new token with id 4895.
AssertionError: Expected 'accept_token' to not have been called. Called 2 times.
```
With the fix, the same test passes (0 calls).

## Not a duplicate

No open PR currently adds this guard.
