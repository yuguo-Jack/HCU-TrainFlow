# [ROCm][Perf] Fuse add-RMSNorm into AITER FlyDSL INT4 QuickReduce

[Upstream PR](https://github.com/vllm-project/vllm/pull/61021) · state: open · merged: False

## Original PR description



## Overview

With FlyDSL INT4 QuickReduce on (#59478), the `fuse_allreduce_rms` pass now runs prefill all-reduce + add-RMSNorm as one FlyDSL kernel instead of falling back to HIP QuickReduce + RMSNorm. Stacked on #59478; only the last commit is new. Needs [ROCm/aiter#6369](https://github.com/ROCm/aiter/pull/6369) (`QuickAllReduceInt4.allreduce_rmsnorm`), so this stays a draft until an AITER release ships it. #61020 builds on this PR to also fuse the MXFP4 activation quant.

Not a duplicate: searched open PRs for "FlyDSL QuickReduce RMSNorm", "quick reduce rmsnorm" and "flydsl allreduce". #56326 fuses AR + RMSNorm + per-token FP8 quant in the custom all-reduce kernel, and #55917 adds a plain FlyDSL all-reduce for RDNA4; neither touches the QuickReduce path.

## Claims

- FlyDSL QuickReduce and `fuse_allreduce_rms` can be on together. #59478's warning against combining them is removed.
- `amd/Qwen3.8-2.4T-A95B-Quark-MXFP4`, TP8, MI355X, one run per arm: +4.4% geomean output throughput (+1.5% to +7.0% across 12 points), −7.2% mean TTFT and −4.1% mean TPOT, against #59478 with the fusion off as it recommends. The candidate arm also turns on AITER's existing decode-size fusion (see Limitations).
- The fused kernel is 1.06–1.12× faster than FlyDSL all-reduce + `rmsnorm2d_fwd_with_add` for 1k–16k tokens at hidden 8192 (ROCm/aiter#6369).
- Nothing changes unless `VLLM_ROCM_QUICK_REDUCE_USE_FLYDSL=1`.

## Details

**Before.** The AITER all-reduce fusion pass sends fused all-reduces in the QuickReduce size range to AITER's HIP QuickReduce + RMSNorm. With FlyDSL QuickReduce on, turning the fusion on therefore gives up FlyDSL QuickReduce for exactly the prefill-sized all-reduces it is fastest on. #59478 warns about the combination and recommends the fusion off, which leaves the residual add and RMSNorm as separate launches after every prefill all-reduce.

**After.** The AITER PR adds an add-RMSNorm epilogue to the FlyDSL kernel. On the non-one-stage branch, `_rocm_aiter_fused_allreduce_rmsnorm_impl` asks `QuickAllReduce` first:

- `should_fused_allreduce_rmsnorm(inp, residual, weight)` accepts the call when FlyDSL QuickReduce owns the payload (the `should_quick_allreduce` window), the kernel supports the hidden size (`QuickAllReduceInt4.supports_rmsnorm`, owned by AITER), and the residual and weight are bf16, contiguous and 16-byte aligned. It reads only tensor metadata, so it adds no host-device synchronization.
- `fused_allreduce_rmsnorm(...)` runs the fused kernel and returns `(out, residual_out)`, with Gemma (`1 + weight`) norms supported.

Decode sizes, which the one-stage custom all-reduce owns, and everything FlyDSL declines keep their current path. The methods live on `QuickAllReduce` because it already owns the FlyDSL object (#59478). +46 / −12 non-test lines.

**Limitations and CI gaps**

- **Arms.** The candidate turns on `fuse_allreduce_rms`, which also enables AITER's existing one-stage custom-AR fusion for decode-sized all-reduces. The end-to-end delta therefore covers that fusion as well as this PR. A three-arm run on nightly + #59478 only (fusion off; fusion on with HIP QuickReduce + RMSNorm; this PR) is pending.
- **Prefill coverage on main.** The image carries #57547. Without it, the fusion pass's compile range stops at the custom all-reduce's 64 MiB limit (4096 tokens at hidden 8192 in bf16), so with `max_num_batched_tokens=8192`, prefill chunks of 4097–8192 tokens stay unfused.
- **Coverage.** Measured on gfx950, TP8, one model. The AITER kernel admits gfx942 but was tested only on gfx950. TP2/TP4, a second model, GSM8K and NIAH are pending.
- **CI.** The unit tests run in the MI355 "Distributed Features" step. The end-to-end runs need 8× MI355X and the 2.4T checkpoint, so they ran outside CI.
