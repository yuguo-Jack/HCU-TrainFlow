# [Bugfix] Fix engine crash when realtime streaming input is empty (#34532)

[Upstream PR](https://github.com/vllm-project/vllm/pull/34793) · state: closed · merged: False

## Original PR description

When a realtime API client sends `input_audio_buffer.commit` with `final=True` without having previously appended any audio data, the streaming input generator yields nothing. Previously, `_add_streaming_input_request` would still send a placeholder `final_req` (with `prompt_token_ids=[0]` and no multimodal data) to the engine to signal stream completion.

For models that require multimodal embeddings at every step (e.g. VoxtralRealtime), this caused the engine worker to crash with:
  AssertionError: For realtime you must provide a multimodal_embedding at
  every step.

The engine crash makes the server unable to process further requests.

Fix:
- In `async_llm.py`: When no inputs are processed from the streaming input generator, signal completion directly via `STREAM_FINISHED` without submitting any request to the engine. This prevents models requiring multimodal inputs from receiving a content-free placeholder request.
- In `connection.py`: Add missing `return` after `send_error` in the model validation check for commit events, preventing execution from continuing to `start_generation()` or queue manipulation after an error is reported.

Tests:
- Added unit test `test_empty_streaming_input_no_engine_crash` in `tests/v1/streaming_input/test_async_llm_streaming.py` that verifies empty input streams complete cleanly without calling `_add_request`.
- Added unit tests in `tests/entrypoints/openai/test_realtime_connection.py` for commit-before-validation behavior and the missing return fix.

Fixes: https://github.com/vllm-project/vllm/issues/34532
