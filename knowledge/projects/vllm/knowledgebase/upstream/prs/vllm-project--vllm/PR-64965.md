# [Bugfix][Attention] Reject TORCH_SDPA for decoder attention

[Upstream PR](https://github.com/vllm-project/vllm/pull/64965) · state: open · merged: False

## Original PR description

## Overview

Reject the ViT-only `TORCH_SDPA` sentinel from every decoder backend configuration path: direct `AttentionConfig` construction, per-KV-group overrides, and the top-level CLI/Python `attention_backend` shorthand. This fixes #64954 while keeping `TORCH_SDPA` available for multi-modal encoder attention.

No open PR addresses this issue or the same configuration validation gap.

## Claims

- Invalid decoder configurations now fail during config creation
- Global, per-kind, CLI, Python engine argument, and public `LLM` paths receive the same validation
- String and enum inputs receive the same validation
- `auto`, valid decoder backends, and the existing mutually exclusive check remain unchanged
- Multi-modal encoder configurations can still select `TORCH_SDPA`

## Details

`TORCH_SDPA` is an enum sentinel used by the multi-modal encoder path and has no decoder backend class. `AttentionConfig.__post_init__` now validates the final global and per-kind decoder backends after parsing.

The top-level `attention_backend` shorthand previously deep-copied an already constructed `AttentionConfig` and then assigned `backend` directly. Pydantic assignment validation is not enabled for vLLM config dataclasses, so that assignment did not rerun `__post_init__`. The shorthand now uses vLLM's Pydantic-compatible `replace()` helper to reconstruct the copied config, preserving its other fields while rerunning parsing and final validation.

The existing direct/per-kind tests cover string and enum inputs. The engine-argument regression exercises both a Python enum and the real CLI parser through `EngineArgs.create_engine_config()`, while the public-entry regression constructs `LLM` through `vllm_runner`. Existing tests continue to cover valid shorthand values, `auto`, dot notation, the mutually exclusive shorthand/config check, and the separate multi-modal encoder path. The field docstring documents the decoder/encoder distinction in generated config and CLI reference material.
