# [Bugfix][Frontend] Honor the constructor chat template in offline scoring

[Upstream PR](https://github.com/vllm-project/vllm/pull/61990) · state: closed · merged: True

## Original PR description



## Overview

`LLM(chat_template=...).score(...)` ignores the constructor's template unless it is passed again to every `score()` call, so cross-encoder prompts are built without a template. For rerankers that need one, like Qwen3-Reranker, the scores are wrong. This makes offline scoring fall back to the constructor's template, as online scoring and offline `chat()` (#61061) already do.

## Claims

- `LLM.score()` uses the template passed to the `LLM` constructor when no `chat_template` is given to the call.
- A `chat_template` passed to `LLM.score()` still overrides it, and scoring without any template is unchanged.

The new `test_offline_scoring_uses_default_template_unless_overridden` builds offline requests through `get_request_factory_offline` with a constructor template, a per-call template, both, or neither, renders them with `get_score_prompt` and checks the text and token IDs.

End to end on an L4, comparing the wheel for fa75d3456 (`main`) with the same wheel plus this change: `LLM("Qwen/Qwen3-Reranker-0.6B", runner="pooling", hf_overrides={"architectures": ["Qwen3ForSequenceClassification"], "classifier_from_token": ["no", "yes"], "is_original_qwen3_reranker": True}, chat_template=TEMPLATE, enforce_eager=True, dtype="bfloat16")`, where `TEMPLATE` is the reranker's query/document prompt, then `llm.score("What is the capital of France?", documents)`. The reference applies the same template with the tokenizer and takes the softmax over the "no"/"yes" logits of the Hugging Face model.

| Document | `main` | This PR | Hugging Face reference |
| --- | --- | --- | --- |
| The capital of France is Paris. | 0.9829 | 0.9972 | 0.9973 |
| The capital of Germany is Berlin. | 0.9535 | 0.0984 | 0.1097 |
| Pasta is often served with tomato sauce. | 0.5200 | 0.0116 | 0.0115 |
| Prompt lengths (tokens) | 14 / 14 / 16 | 84 / 84 / 85 | 84 / 84 / 85 |

With this change the prompt token IDs match the templated reference exactly for all three documents, and the scores match the reference within `atol=0.01, rtol=0.02` (bf16).

## Details

`PoolingOfflineMixin` passes the constructor's template to the scoring processors, and `CrossEncoderIOProcessor.get_request_factory_online` uses it (`self.chat_template`). `get_request_factory_offline` instead copied only `ctx.chat_template`, the template passed to `LLM.score()`, which defaults to `None`, so `get_score_prompt` took the path without a template. It now uses `self.chat_template` when `ctx.chat_template` is `None`. I updated the `score()` docstring, which said `None` means the model's default template, and added a sentence to the scoring docs.

Duplicate check: I searched open and closed PRs and issues for `LLM.score` with `chat_template`, "offline template ignored", `CrossEncoderIOProcessor chat_template` and the file paths. #61061 (merged) fixed the same fallback for `chat()`/`enqueue_chat()` but not `score()`. Open PRs that touch these files (#60877 saved CrossEncoder templates, #55359 CrossEncoder heads, #61772 token embeddings in `embed()`) don't change this fallback.
