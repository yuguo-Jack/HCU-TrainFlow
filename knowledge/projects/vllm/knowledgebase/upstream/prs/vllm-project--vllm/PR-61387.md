# [Bugfix][MoE] Exclude SM110 from Triton MXFP4 MoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/61387) · state: closed · merged: False

## Original PR description



## Overview

Restore MARLIN auto-selection for GPT-OSS MXFP4 on Jetson Thor (SM110) by excluding SM11x from the OAI Triton MoE device gate. Fixes #61374, a regression introduced by #58877.

## Claims

- Prevent the Triton `matmul_ogs` compilation failure during engine initialization on the tested Thor configuration.
- Preserve the CUDA support ranges for SM9x, SM10x, and SM12x, and the existing ROCm handling.

## Validation

Hardware validation reported in #61374 used Jetson AGX Thor, `openai/gpt-oss-120b` MXFP4, TP=PP=DP=1, `--max-model-len 4096`, and automatic MoE backend selection. All runs used the same pinned nightly base image; the parent/merge comparison changed only the vLLM wheel with dependencies held fixed.

| Revision | Backend | Result |
|---|---|---|
| `b3082d30`, parent of #58877 | MARLIN | Startup succeeds; GSM8K 0.5076 ± 0.0437 |
| `40c86ae1`, merge of #58877 | TRITON | `matmul_ogs` compilation failure |
| `fe4df3df0`, unpatched nightly | TRITON | Same compilation failure |
| `fe4df3df0` + this device-gate change | MARLIN | Startup succeeds; GSM8K 0.4848 ± 0.0437 |

GSM8K is flexible-extract exact match, five-shot, on a 10% subset, one run per successful configuration. This demonstrates recovery of startup and evaluation completion; no full-dataset accuracy equivalence or throughput claim is made.

The patch is based on upstream `main` at `183625d4f9`. The hardware run above applied the same executable change to `fe4df3df0`; the unchanged device-gate function matches between those bases. A new GPU run on this branch was not performed on the local macOS host. Thor validation was performed outside upstream CI; other architectures were not run.

## Details

#58877 widened the CUDA gate from `< (11, 0)` to `< (13, 0)` for SM12x support, which also admitted SM110. Its SM12x backend ordering and kernel constraints are scoped to capability family 120. Restoring the gap for SM11x keeps Thor on its existing MARLIN path and preserves the newly added SM12x support. Both Triton expert classes share this gate; explicit selection of the unsupported Triton backend on SM110 is also rejected.

The change is confined to the device-support predicate. It adds no kernel code, dependencies, synchronization, or backend-priority changes.

Duplicate-work check on October 13, 2026: no open PR was found for #61374 or this SM110 MXFP4 regression. #29339 is the merged historical safeguard, and #58877 is the merged change that reintroduced the failure. AI assistance was used to prepare this change and description.
