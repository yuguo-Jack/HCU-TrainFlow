# [Mamba] Add FlashInfer GDN ReplaySSM STP, MTP, and prefix caching

[Upstream PR](https://github.com/vllm-project/vllm/pull/65657) · state: open · merged: False

## Original PR description

## Overview

Add opt-in FlashInfer GDN ReplaySSM support for Qwen3.5, on top of [vLLM #55688](https://github.com/vllm-project/vllm/pull/55688) at `50a923892d61`.
This is a stacked draft until #55688 lands. The final commit contains the GDN changes. Earlier commits belong to that dependency.
This PR adds the GDN adapter to the parent ReplaySSM lifecycle; it does not duplicate the parent Mamba2 implementation. It does not modify FlashInfer.

Related PRs #62004 and #64699 implement Triton standard decoding. #56466 prototypes Triton speculative decoding with prefix caching.
This PR instead integrates existing FlashInfer STP, MTP, and prefix-materialization APIs with the shared lifecycle in #55688.

## Claims

- Enable with `--use-replayssm` and `VLLM_GDN_DECODE_KERNEL=flashinfer_replayssm`.
- Support draft lengths 0–7. Kernel widths are 1 for STP, 4 for draft lengths 1–3, and 8 for draft lengths 4–7.
- Preserve real scheduler lengths while padding kernel inputs with recurrent no-ops.
- Support cache modes `none` and `align`. Prefix caching requires `align`; `all` is unsupported.
- Preserve V1/V2 state ownership, canonical prefill, and aligned prefix materialization.

Its model-level cache sizing reuses the common implementation. Warmup commits extensible-cache memory before use.
V2 now derives replay classification from built GDN metadata. The parent tracker lifecycle and logical-column publication rules remain.

The integration rejects that combination rather than adding a separate GPU indexing implementation.

Runs use TP1, V2, CUDA graphs, and BF16 state. OFF selects `cuda`; ON selects `flashinfer_replayssm` with buffer length 16.

The selector alone does not establish which STP kernel executed.

## Details

```text
request
  -> classify canonical prefill or replay
  -> pack replay rows and read ring views from cache pages
  -> publish accepted state through shared ReplaySSM lifecycle
  -> materialize aligned prefix checkpoints when required
```

Intermediate prompt chunks stay canonical. The V2 runner applies this rule before graph selection, including a `64 -> 1 -> 3` prompt schedule.

Required FlashInfer APIs are `gated_delta_rule_stp_ucache_flush`, `gated_delta_rule_mtp_ucache_flush`, and `gdn_prefix_materialize` for aligned caching.
FlashInfer v0.7.3 at `775207deb340` supplies the MTP API and prefix materializer.
The exact STP module is absent from that release and main `eeed657f157b`. [STP PR #4974](https://github.com/flashinfer-ai/flashinfer/pull/4974) is closed without merging.
**Remaining dependency: this adapter still requires the STP provider API.** Materialization is upstream through merged [#5073](https://github.com/flashinfer-ai/flashinfer/pull/5073).
The measured runtime remains FlashInfer 0.7.2.post1 with unchanged provider files from those PRs. This PR does not implement FlashInfer kernels.
Set `SGLANG_GDN_WY_STRIDED_QKV=1` before process startup.

The initial configuration requires BF16 activations/state, K=V=128, and supported Qwen3.5 architectures.
Pipeline parallelism, overlapping microbatches, adaptive verification, and KV connectors remain unsupported.
GDN kernel autotuning is not added by this PR.
