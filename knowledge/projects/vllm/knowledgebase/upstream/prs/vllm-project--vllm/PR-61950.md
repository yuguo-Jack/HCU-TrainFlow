# [Bugfix][ROCm] Fix Kimi K3 online quantization with padded projections

[Upstream PR](https://github.com/vllm-project/vllm/pull/61950) · state: open · merged: False

## Original PR description

## Overview

Fix ROCm Kimi K3 online weight loading so its padded merged KDA projection can finish as soon as all checkpoint shards arrive. Declare the checkpoint-backed element count and zero-initialize declared padding when materializing meta weights.

### Summary

```text
six KDA checkpoint shards arrive
  → complete using real elements, excluding alignment rows
  → materialize with initialized padding
  → process the layer and release its input tensors
```

## Claims

- Avoid accumulating full GPU checkpoint tensors across incomplete KDA layers during online quantization.
- Preserve zero padding through meta materialization; changing completion accounting alone leaves this padding uninitialized.
- Exercise the real KDA constructor and merged weight loader in the existing reload test suite, checking prompt release of source tensors, loaded values and padding.

## Details

At TP8, KDA's local merged projection has 6284 real rows and 4 alignment rows. Without `weight_loader_numel`, the loader waits for 6288 rows although the checkpoint only contains six real projections. It defers processing and retains their sources until model finalization. With GPU-backed fastsafetensors inputs, this exhausts VRAM before loading completes. The existing `weight_loader_numel` mechanism supplies the correct completion count.

The constructor's padding `zero_()` executes on meta during online loading. Materialization uses `empty_strided`, so that initialization must be restored before actual weights are copied. This PR zeros only tensors declaring fewer loadable elements than their storage size; existing annotations are also used by zero-initialized padded unquantized MoE weights. It adds no steady-state inference work.

**Related work / duplicate check:** #50523 fixes general zero initialization for rematerialized weights. It does not declare KDA's loadable size and therefore does not resolve this source-retention failure. This PR's materialization change overlaps that prerequisite, but is restricted to explicitly declared partial tensors. If #50523 lands first, this conditional change can be dropped while retaining KDA accounting and the regression. Open KDA quantization PRs and #61287 were also checked; no matching KDA completion fix was found. This draft makes the overlap explicit rather than treating the initialization problem as a new discovery.

### Merge Danger

**Door:** two-way. **Blast Radius:** loading.

The shared materialization change affects tensors with declared partial coverage and adds a zero-fill during loading/reloading. KDA coverage uses an existing loader contract. This remains a draft for human review, including coordination with #50523 and any additional accuracy validation required before merge.
