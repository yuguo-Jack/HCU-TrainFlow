# [Bugfix][ROCm] Fix Kimi K3 online quantization with padded projections

[Upstream PR](https://github.com/vllm-project/vllm/pull/61950) · state: closed · merged: True

## Original PR description

## Overview

Fix ROCm Kimi K3 online weight loading so its padded merged KDA projection finishes as soon as all checkpoint shards arrive. Following review, the fix lives in an AMD-local `_PaddedKimiGDNMergedColumnParallelLinear`, mirroring the NVIDIA implementation; no shared loader code is changed.

### Summary

```text
six KDA checkpoint shards arrive
  → complete using real elements, excluding alignment rows (weight_loader_numel)
  → layerwise processing materializes the weight and replays the loads
  → loader re-zeroes the padding rows
  → process the layer and release its input tensors
```

## Claims

- Avoid accumulating full GPU checkpoint tensors across incomplete KDA layers during online quantization.
- Keep the alignment padding zero after online materialization, which allocates with `empty_strided` and drops the constructor's zero-init.
- Only `vllm/models/kimi_k3/amd/kda.py` changes; the shared Kimi-Linear projection and `reload/meta.py` are untouched.

## Details

At TP8, KDA's local merged projection has 6284 real rows and 4 alignment rows. Without `weight_loader_numel`, online processing waits for 6288 rows although the checkpoint only provides the six real projections, so it defers processing and retains every source until model finalization. With GPU-backed fastsafetensors inputs this exhausts VRAM before loading completes.

During online loading the constructor's padding `zero_()` runs on meta, and materialization allocates with `empty_strided`. Layerwise processing then replays the buffered calls through the layer's weight loader, so re-zeroing the padding rows there restores them. `CopyCounter` only counts `copy_`, so the zeroing does not affect completion accounting. It adds no steady-state inference work.

The subclass extends the shared Kimi-Linear projection instead of importing the NVIDIA class, which would pull NVIDIA backend modules into the ROCm path and change AMD loading through its block-scale replication.

**Related work / duplicate check:** #50523 fixes general zero initialization for rematerialized weights; it does not declare KDA's loadable size and does not resolve this source-retention failure. If it lands, the loader re-zeroing becomes redundant but harmless. Open KDA quantization PRs and #61287 were also checked; no matching KDA completion fix was found.
