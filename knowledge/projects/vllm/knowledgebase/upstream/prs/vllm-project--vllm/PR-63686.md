# [Doc] Fix store_threshold and max_tracker_size descriptions

[Upstream PR](https://github.com/vllm-project/vllm/pull/63686) · state: open · merged: False

## Original PR description



## Overview

Fix the `store_threshold` and `max_tracker_size` descriptions in `docs/features/kv_offloading_usage.md`: the threshold counts store offers, not lookups. The behavior was changed in https://github.com/vllm-project/vllm/pull/52227.

## Claims

- `store_threshold` and `max_tracker_size` descriptions match `CPUOffloadingManager` behavior.

## Validation

Docs-only change, checked against the code:

- `CPUOffloadingManager.prepare_store()` (`vllm/v1/kv_offload/cpu/manager.py`) records accesses and filters store candidates by `store_threshold`; `lookup()` does not update the counts.
- The existing `test_filter_reused_manager` (`tests/v1/kv_offload/cpu/test_manager.py`) asserts that `lookup()` does not count towards store admission.

Docs build:

```bash
API_AUTONAV_EXCLUDE=vllm mkdocs build
```

Build succeeds; the updated rows render correctly in `features/kv_offloading_usage/`.

## Details

The previous "lookups" wording was incorrect.

Not a duplicate: no open PR changes these descriptions (`gh pr list --repo vllm-project/vllm --state open --search "store_threshold"`).
