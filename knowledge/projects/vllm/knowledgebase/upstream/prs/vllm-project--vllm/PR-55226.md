# [Bugfix][Pooling] Ignore token stream intervals for pooling

[Upstream PR](https://github.com/vllm-project/vllm/pull/55226) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Prevent pooling requests from crashing AsyncLLM's output handler when `--stream-interval` is greater than one.

## Claims

- Skip token-stream buffering for pooling completion and cancellation.
- Keep generation's existing stream-interval behavior.

## Validation

On main at `68ebea7`, pooling completion and cancellation with stream intervals greater than one raise the missing-detokenizer `AssertionError`. The same cases pass on this branch. The output-processor suite and scoped pre-commit hooks pass.

To run the related suites in a configured development environment:

```sh
.venv/bin/python -m pytest tests/v1/engine
```

The [requested GPU serving check](https://github.com/vllm-project/vllm/pull/55226#issuecomment-5613201182) used Qwen3-Embedding-0.6B on an RTX 5070 Ti with MRV2, `--runner pooling`, and `--stream-interval 2`. Sequential and batched embedding requests returned HTTP 200, and the server remained healthy. That serving check was run in September and has not been repeated.

## Details

Pooling requests have no detokenizer. Return their results before token buffering so pooling and generation handling stay separate.

This overlaps #56131, which uses a detokenizer check for the same failure. Maintainers should choose one implementation.

AI assistance was used for this change.
