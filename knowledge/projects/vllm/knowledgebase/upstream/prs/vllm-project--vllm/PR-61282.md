# [Bugfix] Hybrid prefix caching: keep the Mamba prompt-boundary state until the request ends and evict it after its attention blocks

[Upstream PR](https://github.com/vllm-project/vllm/pull/61282) · state: open · merged: False

## Original PR description



## Overview

Fixes the lifetime of a hybrid request's reusable Mamba "align" state block: it stays referenced for as long as the request runs, and at request end it is the last of the request's blocks to reach the LRU free queue. FIX #61281

## Claims

- A running hybrid request no longer loses its prompt-boundary Mamba state to other requests' allocations: `MambaManager` holds one reference on that block from the moment it is registered, or taken over from the cache by a resumed or sibling request, until the request is freed, across the range retirement, the running-state swap and the partial-tail CoW copy.
- At request end attention groups are freed before Mamba groups on both the direct (`KVCacheCoordinator.free`) and the deferred (`pop_blocks_for_free`) path, so the single state block is evicted after the attention blocks it belongs with, not before.
- The next turn of a conversation now hits the previous prompt in every group; before, the attention group hit while the Mamba group returned 0 and the reconciled hit was 0.
- Cost: one extra block per Mamba group per running request (the running state plus the boundary state). Single-group and non-Mamba hybrid models are unaffected: no behaviour change in their managers, and the free order is the identity for them.

## Details

Root cause. Align mode keeps only the running state per request; every other state is a prefix-cache entry that lives in the free queue with its hash. That is fine for intermediate states, but the state at the prompt's reusable boundary is the one block a later turn needs together with the request's attention blocks, and those stay referenced until the request finishes. Three paths push the boundary block into the free queue a step into decode: `remove_skipped_blocks` -> `_remove_blocks_in_range` (boundary on a block boundary), the `last_state_block_idx` swap in the same function, and the release of the CoW copy of a partial tail by `Scheduler._free_cow_retained_blocks` once the copy step has run. Any allocation then recycles it (`get_new_blocks` -> `_maybe_evict_cached_block`), and the hybrid lookup is the minimum over groups. At request end the groups were freed in config order (direct path) or reversed config order (deferred path), so depending on the model's group order the state block was the first of the request's blocks to be evicted.

Design. Rather than special-casing each free path, the manager takes one reference on the boundary block on the request's behalf (`_retain_boundary_block`, mirroring the CoW retention refs that already exist) wherever the request comes to own that state: a full block whose hash ends at the boundary (`cache_blocks`), a re-keyed prefill checkpoint or a partial tail (`_cache_partial_tail_block`), and the hit block adopted by a resumed or sibling request (`add_local_computed_blocks`; registering the request's own boundary later replaces that hold). One helper, `_prompt_boundary`, defines the position at every site. The existing free paths then only drop the block's ref to 1 and null it out of the request's table as before. On the producer CoW the hold moves with the hash to `cow_block`, so the scheduler's post-copy release leaves the copy referenced. `pop_blocks_for_free` releases the hold: if the block is still in the request's table it just drops the extra ref, otherwise it lists the block first so it is the last one freed. The coordinator orders group frees once (`_free_order`: attention first, Mamba last) and `pop_blocks_for_free` returns groups in the reverse of that order so the caller's reversed free matches `free`.

Only the prompt boundary is held. Under sparse retention (the default `prefix_cache_retention_interval=0`) that is the request's only hashed state apart from a shared-prefix junction; under dense retention intermediate states keep their existing free-queue lifetime, so memory stays bounded at two blocks per Mamba group per running request.

Not covered / residual risk:

- A shared-prefix junction state (`shared_prefix_boundary`, behind `enable_mamba_shared_prefix_checkpoint`, off by default) is registered the same way and keeps the old lifetime; holding it too would double the per-request cost for a feature that is off by default, so it is left out.
- EAGLE/MTP: the hold follows `drop_eagle_checkpoint_block` like the partial-tail registration does, so it lands on the dropped-block boundary; the speculative scratch blocks are above the running state and never hashed, so `_relocate_speculative_block`'s writable assertion is unaffected.
- `evict_blocks` (connector-driven eviction) strips the hash from a held block; the block then stays allocated until the request ends. Harmless, and the same as a held attention block today.
- Non-align Mamba modes and non-Mamba groups take none of the new paths.
