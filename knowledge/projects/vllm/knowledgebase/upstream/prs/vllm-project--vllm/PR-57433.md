# [Scheduler] Balance async PP decode batches

[Upstream PR](https://github.com/vllm-project/vllm/pull/57433) · state: closed · merged: False

## Original PR description

## Purpose

Balance established decode batches automatically when Model Runner V2 uses asynchronous pipeline parallelism.

Async PP makes a request eligible again after `pipeline_parallel_size` scheduler steps. Prompt-completion timing can therefore create persistent, uneven cadence groups such as Q7/Q13/Q2/Q10. This change limits established decode requests selected in each step to:

```text
ceil(max_num_seqs / pipeline_parallel_size)
```

The limit applies to both `RUNNING` requests and established decode requests resumed from `WAITING`. Prefill, chunked prefill, and chunks that complete a prompt in the current step remain uncapped because mixed batches require token-aware rather than sequence-count balancing. If priority preemption removes a selected decode, its cohort slot is restored.

The policy is active only for MRV2 `AsyncScheduler` with pipeline parallelism greater than one. PP1, synchronous scheduling, and MRV1 retain the existing effective limit of `max_num_seqs`.

This advances Workstream A of #50853.

### Why this is not a duplicate

#50410 is the only overlapping open PR. It caps the total number of scheduled requests, including prefill. On a matched Kimi-K3 + DSpark Mooncake replay, that global cap reduced output throughput by 8.21% versus natural scheduling. The decode-only policy here improved output throughput by 22.95% versus natural scheduling and by 33.95% versus #50410.

The distinction is implemented and tested explicitly: all 32 prompt-completing requests are scheduled together before decode is divided into two disjoint Q16 cohorts under PP2.
