# [Feature][MRV2] Allow sparse prefill CUDA graph captures

[Upstream PR](https://github.com/vllm-project/vllm/pull/62209) · state: open · merged: False

## Original PR description

## Overview

Allow MRV2 users to select a sparse subset of mixed/prefill CUDA graph captures while preserving the shared FULL decode ladder. Related to the separate-sizing item in #61024.

## Claims

- Add opt-in `compilation_config.cudagraph_capture_sizes_prefill` for `FULL_AND_PIECEWISE`. Selected sizes must belong to the resolved shared list; omitted retains existing behavior, and `[]` disables mixed captures.
- Preserve FULL decode descriptor construction and compilation sizes. Reject MRV1, unsupported modes and late attention-backend mode downgrades.
- Demonstrate reduced final capture work on Qwen3-0.6B/RTX 4050; no generation-speedup, overall-startup or memory-saving claim.

## Validation

Base f98ae6a9fd2c73a2f80dd9fe4c534676f689394d; Ubuntu WSL2, RTX 4050 Laptop 6 GB, Python 3.12.3, torch 2.14.0+cu132, matching published vLLM natives. Candidate and unmodified source use separate environments with matching runtime dependency versions.

- Graph manager/dynamic-SD/profiling suites: 56 passed; later full-subset equivalence regression: 1 passed; selected config tests: 12 passed. Final applicable pre-commit hooks passed.
- Broader selection: candidate 144 passed/4 failed; unmodified control 119 passed/the same 4 failed, all `test_use_cudagraphs` CUDA reinitialization after fork. The broader suite is not green locally. The earlier remote-weight integration matrix was interrupted rather than completed.
- Real configuration probes pass for automatic MRV2, forced-MRV1 rejection and token-budget subset validation.
- Qwen3-0.6B BF16, TP1, chunk 256, max requests 8, fixed 1024 KV blocks. Three fresh engines per default/sparse/unmodified policy; one generation warmup and five timed windows each. Each window generates 16 tokens for 8 prompts of lengths 17–255. Compare saved final-window outputs.

The manually tuned control uses shared[1,2,4,8,32,128,256], versus sparse mixed[32,128,256]. Its three runs occur in a later block, so this is a descriptive capture-cost comparison, not an interleaved end-to-end speedup. Constructor startup includes different compilation caches and is excluded from the claim. Reservation is total allocator memory, not incremental graph memory.

All saved default/sparse greedy outputs match an unmodified-upstream repeat. One prompt changes at a tied score in upstream A/A too; common-prefix top-logprob differences reach 0.25, so this is not bitwise score parity or a full accuracy evaluation.

Prefix-cache default/sparse/empty runs exercise real cache reads (3712 hits/4956 queries each) and pass `VLLM_GPU_SYNC_CHECK=error`. Sparse/default saved greedy tokens match; empty has two differing prompts with a tie in one arm. Against original FULL_DECODE_ONLY, empty differs on one prompt with a tie in the empty arm; maximum common-prefix score delta 0.4375. Fixed GPU ngram K3 default/sparse also pass the sync checker: identical saved 128 tokens and top-logprobs, 408/1080 accepted draft tokens each, and FULL replay sizes [32,16,8,4].

Float32/TRITON_ATTN prefix-cache controls (512 KV blocks) retain identical 128 greedy tokens for default, sparse, empty and existing shared-list tuning with the option omitted. All 18 pairs pass upstream `tests.models.utils.check_logprobs_close`, which checks token/top-k compatibility rather than score closeness. Supplemental strict float32 score checks fail: dense→sparse max delta 0.009584; dense→empty 0.011940. Existing shared-list tuning alone also fails (common-key delta 0.020384 and a top-five set difference). These failures remain recorded; no tolerance was relaxed and no numerical-score parity or full accuracy claim is made.

## Details

Filter mixed capture descriptors during existing candidate construction; reuse the existing profiler, capture and dispatcher. The shared ladder still controls compilation and storage ceilings, so the mixed list is a subset rather than a separate larger allocation policy. Coarser captures can increase padding or eager fallbacks.

Public issue/PR searches found no exact implementation. #61882 extracts builders while retaining shared sizing; #56136 changes dynamic-K candidate ladders, #60265 changes the default ceiling, and #60989 adds standalone-draft graph support. This change implements none of those scopes. Duplicate checks were refreshed before submission; #61882 is still open and retains the shared ladder.
