# [Fix][MoE] Reuse FlashInfer TRT-LLM MoE workspaces across layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/62948) · state: open · merged: False

## Original PR description

## Overview

Reuse caller-owned FlashInfer TRT-LLM MoE scratch across sequential layers and smaller batches. The workspace is sized and cached using the configured **maximum row count**, not the actual token count. Controlled by env `VLLM_FLASHINFER_MOE_USE_WORKSPACE`

This makes trtllm-gen moe's workspace inside vllm's `gpu_memory_utilization` budget, allowing more straightforward memory planning. For example:

1. enable autotuning and `VLLM_FLASHINFER_MOE_USE_WORKSPACE`, then tune up the `gpu_memory_utilization`, save the autotuning cache.
2. enable the autotuning cache and disable `VLLM_FLASHINFER_MOE_USE_WORKSPACE`, and keep the `gpu_memory_utilization`

Cutlass counterpart: #60570 

Current limitation: `do_finalize=False` is not supported yet.

## Claims

- Add workspace reuse for all paths (BF16, FP8, MXFP4, NVFP4, and MXINT4).
- Cache sizing queries and reserve buffers through the existing workspace manager, with microbatch/lane isolation.
- Preserve per-call allocation fallbacks when reuse is unavailable.

## Validation


## Details

Added a base class `TrtLlmExpertsBase` for all trtllm-gen MoE classes.

Repeated scratch allocation can fragment the allocator during large prefills. Size persistent buffers for the configured token bound, including DP gathering, and reuse them through the workspace manager.

Deferred finalize, oversized batches, sizing failures, workspace manager locking, etc., fallbacks, per-call allocation. Persistent scratch remains resident for the manager’s lifetime.
