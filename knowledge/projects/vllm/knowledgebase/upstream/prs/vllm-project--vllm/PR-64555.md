# [CI][KV Offload][P2P] Wait for the handshake in the idle peer-hit tests

[Upstream PR](https://github.com/vllm-project/vllm/pull/64555) · state: closed · merged: True

## Original PR description

## Overview

`TestIdleWhileServingPeers` (both tests) fails on main:

```
FAILED v1/kv_offload/tiering/p2p/test_manager.py::TestIdleWhileServingPeers::test_pinned_peer_hit_does_not_block_idleness - assert <LookupResult.MISS: 1> is <LookupResult.RETRY: 4>
FAILED v1/kv_offload/tiering/p2p/test_manager.py::TestIdleWhileServingPeers::test_pinned_peer_hit_without_poll_thread_is_pending - assert <LookupResult.MISS: 1> is <LookupResult.RETRY: 4>
```

It is a merge race between two PRs that each passed CI on their own:

- #64501 made a probe `lookup()` return `MISS` until the peer acks the handshake (`p2p/manager.py:440`), so the request prefills locally instead of waiting.
- #63618 added these tests on a base without #64501. Its `_peer_hit` helper probes right after `on_new_request` and asserts `RETRY`.

## Fix

Test-only. `_peer_hit` probes only once the consumer session to the peer exists and is ready, and keeps driving both managers until then. Other probe tests drain a fixed number of times before probing; polling until the deadline also covers the poll-thread case, where the producer answers asynchronously. The #64501 behavior is intended and unchanged.

## Validation
