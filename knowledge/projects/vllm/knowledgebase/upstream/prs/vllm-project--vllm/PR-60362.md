# [Bugfix][Tool Parser] Parse multi-line JSON arguments in the DeepSeek V3 and V3.1 parsers

[Upstream PR](https://github.com/vllm-project/vllm/pull/60362) · state: closed · merged: True

## Original PR description

## Overview

Fixes #60342. The `deepseek_v3` and `deepseek_v31` tool parsers lose tool calls whose JSON arguments the model pretty-prints over several lines: their regexes match the arguments with `.`, which stops at a newline.

## Claims

- Tool calls with multi-line JSON arguments are now parsed by `deepseek_v3` and `deepseek_v31`, in both streaming and non-streaming mode.
- Single-line arguments and parallel tool calls are unchanged.

## Validation

Reproducer from the issue, run through the test helpers with the real tokenizers (`deepseek-ai/DeepSeek-V3`, `deepseek-ai/DeepSeek-V3.1`), with `{"city": "Tokyo", "unit": "celsius"}` dumped with `indent=2`:

| Parser | Mode | Before | After |
|---|---|---|---|
| `deepseek_v3` | non-streaming | no tool calls (`tools_called=True`, `tool_calls=[]`) | `get_weather` with the full arguments |
| `deepseek_v3` | streaming | `get_weather` with arguments `{` | `get_weather` with the full arguments |
| `deepseek_v31` | non-streaming | no tool calls | `get_weather` with the full arguments |
| `deepseek_v31` | streaming | `get_weather` with arguments `{` | `get_weather` with the full arguments |

Added `test_multiline_json_arguments` (DeepSeek-V3, two parallel calls with pretty-printed arguments) and `test_extract_tool_calls_with_multiline_arguments` (DeepSeek-V3.1), each run in streaming and non-streaming mode. All four cases fail on main and pass with this change.

```
pytest tests/tool_parsers/test_deepseekv3_tool_parser.py tests/tool_parsers/test_deepseekv31_tool_parser.py
22 passed, 1 xfailed
```

`ruff check`, `ruff format --check` and `tools/pre_commit/mypy.py` pass on the changed files.

These ran on CPU (WSL, `VLLM_TARGET_DEVICE=empty`, with the post-test GPU cleanup skipped since there is no accelerator). I did not run a server end to end with a DeepSeek-V3 checkpoint, which needs a multi-GPU node; the change is limited to the parsers' regexes.

## Details

- Root cause: `DeepSeekV3ToolParser` matches `function_arguments` with `.*` (`` .*[^\n`] `` when streaming), and `DeepSeekV31ToolParser` with `.*?` / `.*`. Without `re.DOTALL`, `.` doesn't match `\n`, so the non-streaming regex finds nothing and the streaming regex captures only the first line of the arguments.
- Fix: only the arguments group uses `[\s\S]`. It stays non-greedy in the regexes used with `findall`, so parallel calls still split at the first closing tag. The type and function-name groups keep `.`, so a name can't span lines and the whole pattern doesn't need `re.DOTALL`.
- The Rust frontend's parsers (`rust/src/parser/src/tool/deepseek_json`) don't use a regex here; `take_json_object` scans the object by brace depth, so from reading the code they already handle pretty-printed arguments. Only the Python parsers change.
- Related PRs: #60361 (opened a few minutes before this one, still a draft) makes the same change to the V3 regexes and leaves V3.1 for later; this PR covers both parsers. #47503 edits the same DeepSeek-V3 regexes to accept an optional newline before the JSON fence, which is a different case, so whichever merges second needs a small rebase. #55473 wraps these regexes with timeouts and is independent.

AI assistance was used for this change (tracking down the cause, writing the tests and this description). I reviewed every changed line and ran the tests above.
