# [Bugfix][Multimodal] Return 400 for file URLs that do not point to a file

[Upstream PR](https://github.com/vllm-project/vllm/pull/61751) · state: open · merged: False

## Original PR description

## Overview

With `--allowed-local-media-path` set, a `file://` URL inside the allowed directory that points to a missing file (or to a directory) fails the request with a 500. The path comes straight from the request, so it should be a client error like the "must be a subpath" check right above it. Noticed while reading `MediaConnector._load_file_url`.

## Claims

- An `image_url` / `video_url` / `audio_url` with a `file://` URL to a nonexistent file or a directory raises `ValueError` (HTTP 400) instead of `FileNotFoundError` / `IsADirectoryError` (HTTP 500).
- Existing files load as before.

## Validation

```python
import tempfile
from pathlib import Path
from vllm.entrypoints.serve.exception_handling.error_response import create_error_response
from vllm.multimodal.media import MediaConnector

with tempfile.TemporaryDirectory() as d:
    connector = MediaConnector(allowed_local_media_path=d)
    try:
        connector.fetch_video((Path(d) / "missing.mp4").as_uri())
    except Exception as e:
        err = create_error_response(e).error
        print(type(e).__name__, err.code, err.type)
```

```text
# main (03091e28b)
FileNotFoundError 500 InternalServerError
# this PR
ValueError 400 BadRequestError
```

Same for `fetch_image`, and for a directory. I added `test_fetch_image_local_files_not_a_file` (sync and async, missing file and directory); both cases fail on main.

```
pytest tests/multimodal/media/test_connector.py
ruff check && ruff format --check   # on the two touched files
```

Both pass locally on CPU. I didn't start a server, so the 400 is checked through `create_error_response` rather than over HTTP.

## Details

It's one `is_file()` check after the subpath check in `_load_file_url`, which both the sync and async paths go through. I used a plain `ValueError` to match the neighbouring subpath error. A remote URL that 404s is already reported as a client error since #47165; this is the local-file counterpart.

Not a duplicate as far as I can tell: I didn't find an issue or PR for missing local files. The open PRs that touch `connector.py` are about redirects and SSRF (#55539, #59716, #57825, #43897), the media cache (#56062, #55616) and decode metrics (#49682, #50875); none of them adds an existence check.
