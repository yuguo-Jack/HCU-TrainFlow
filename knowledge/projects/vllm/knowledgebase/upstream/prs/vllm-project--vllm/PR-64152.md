# [ROCm][Perf][DSv4.1] Mono: tuned K1 at TP8

[Upstream PR](https://github.com/vllm-project/vllm/pull/64152) · state: open · merged: False

## Original PR description

## Purpose

#63893 gives every layer's K1 at TP4 the tuned paths of #63027's TP2 ratio-2 builds. That covers the attention seam and front, the DSpark draft's K1 included. The gate is `MonoBuild.tuned_front`:

```python
self.tuned or (not GFX942 and not self.generic and self.tp == 4)
```

With #64101 on main (`f97a8d6647`) admitting TP8, the same K1 paths compile at TP8 with no TP-specific change (CPU compile below). This PR widens the gate to `self.tp in (4, 8)`. The numerics test asserts that the target layers' K1 at TP8 is bit-exact against the generic build; it passes on 8x MI355X (below). Everything else stays as it is:
- gfx950 only;
- K2 stays generic;
- gfx942 still builds TP4 only;
- `generic=True` is still the bit-for-bit reference.

The one code change is the gate in `mono/layer.py`. The rest of the diff is the README line.

The test needs no new case. `_check_layers` already selects its tuned-vs-generic comparison by `runner.build_key(M, ratio).tuned_front`, and main (#64101) parametrizes `test_mono_decode_layer_matches_vllm` with `tp in [2, 4, 8]`. With this gate, the TP8 case runs its ratio 0, 1 and 2 steps against a `generic=True` runner and asserts that they are equal bit for bit, as at TP4. Main's `mi355_8` CI step runs that case (`test_mono_decode_layer_matches_vllm[8]`) and the TP8 layer cases `[8-8]` and `[8-28]` for any change under `vllm/models/deepseek_v41/amd/`.

## Test Result

**CPU compile:** every build compiles on every tree, except one pre-existing gfx942 failure:
- all 93 gfx950 builds and all 8 `generic=True` builds;
- every gfx942 build except the TP4 K2 at 48 rows. That build fails on main too: gfx942 caps decode at 42 rows (`MAX_ROWS_GFX942`), so the runner never builds it.

Every TP8 and TP4 build has 0 VGPR spills and 0 private segment. The one exception is pre-existing and byte-identical on both trees: #63027's tuned TP2 ratio-2 K2 at M=48 (256 VGPRs, 6 spilled, 28 B private segment; main: 253, no spill).

| TP8 K1 (ratio 0/1/2 alike) | M=1 | M=7 | M=14 | M=28 | M=48 |
|---|---|---|---|---|---|
| VGPR, generic (base) | 122 | 142 | 142 | 167 | 239 |
| VGPR, tuned (this PR) | 132 | 148 | 148 | 148 | 154 |
| LDS (B), generic (base) | 29,184 | 38,944 | 69,632 | 78,400 | 78,400 |
| LDS (B), tuned (this PR) | 29,184 | 38,944 | 69,632 | 78,400 | 86,016 |

- **Variants:**
  - **Index source:** 134 VGPRs at M=1, and otherwise it matches the table. The generic build (base) uses 124 at M=1, 168 at M=28 and 240 at M=48. At M=28 and M=48 the tuned build also drops the generic build's lane spills (3 and 2 `v_writelane` -> 0).
  - **Draft K1:** matches the table.
  - **fold=0:** 132 VGPRs at M=1 (generic: 124) and 154 at M=48 (generic: 142).
- **LDS at M=48:** every M=48 variant of the tuned build uses 86,016 B, below TP4's tuned 86,592 B.
- **K2 at TP8:** VGPR and LDS are unchanged: 250 / 96,640 at M=7, 240 / 142,368 at M=48, and 199 for the draft K2.
  - Its binary changes because K1 and K2 of a width share one scratch layout, and K1's regions now take the tuned layout.
  - With immediates masked, the instruction stream is identical in all 8 builds.
  - The only differing instructions are 26 `s_add_u32` (27 in the index K2). Each one adds a region's base offset, and that offset moves by the growth of K1's tuned regions: +4,608 B at M=7 and +8,960 B at M=48.
  - TP4 has the same effect under #63893.
- **Byte-identical to the base:**
  - every TP2 build (24/24) and every TP4 build (24/24);
  - the TP8 FFN;
  - every `generic=True` build (8/8, including 6 at TP8), each also byte-identical to main's default build of the same config;
  - every gfx942 build that compiles (38/38).
- **The base is generic at TP8:** all 45 TP8 builds of the base are byte-identical to main.
- **The dropped guard is dead code:**
  - Re-applying it leaves all 11 K2 builds byte-identical.
  - Forcing K2's tuned path at TP8 changes the binary (3/3), but no `MonoBuild` produces that build.

**GPU (2026-10-30, 8x MI355X).** Images built from the pushed commits:
- **base:** nightly `3966924d56` + main `4b47db922b`'s mono files + #63027 + #63893 (`3d923a6848`). TP8 K1 is generic.
- **this PR:** base + `0cc5f92bd5`.

**Unit:**
- `test_mono_decode_layer_matches_vllm[8]`: PASS. The TP8 ratio 0, 1 and 2 steps of tuned K1 (M = 6, 7, 12, 36, 48) equal the `generic=True` build bit for bit, then 300 CUDA-graph replays.
- **Controls:**
  - On the base it passes too, but there the compare is vacuous, because TP8 K1 is generic.
  - This branch plus a one-ulp mutation that only TP8 tuned K1 compiles FAILS at `ratio 1, 1 x 6`. So the compare is live.
- `test_mono_decode_matches_the_model[8-8]` and `[8-28]`: PASS.
- Non-regression on this branch: `[4]`, `[2]`, `[4-8]` and `[2-8]` PASS.

**Step A/B:**
- **Server:** one TP8 `--monokernel` server per session, on the CI C1 recipe at tp=8: aiter MoE, no EP, DSpark k=6, adaptive verification off, Engram host offload off.
- **Load:** `vllm bench serve` random 32k in / 1024 out, `--ignore-eos`, synthetic acceptance length 3.87. The step is ITL p50.
- **Design:** ABBA over 4 rounds (3 x 32 prompts per conc, round and arm).
- **GSM8K:** 1319 questions, greedy, real (block-rejection) acceptance, at `--parallel 6` so that every step stays on the mono kernels. 4 base passes and 2 passes on this PR.

| TP8 mono | conc 1 step | conc 2 step | conc 4 step | GSM8K / AL |
|---|---|---|---|---|
| base (generic K1) | 5.129 ms | 6.015 ms | 7.845 ms | 0.920 / 3.580 |
| this PR (tuned K1) | 4.875 ms | 5.753 ms | 7.660 ms | 0.921 / 3.569 |
| delta | **-254 us (-4.9%)** | **-262 us (-4.4%)** | **-185 us (-2.4%)** | +0.0015 / -0.011 |

- **Every round is faster:** this PR wins in 4 of 4 paired rounds at each conc. The round deltas are -242..-268 us (conc 1), -238..-282 us (conc 2) and -165..-206 us (conc 4).
- **Noise:** the A/A spread of the per-round means is at most 34 us.
- **The saving is K1's.** Per decode step, from the torch profiler (8-rank mean), K1's GPU time drops by:
  - 250 us at 7 target rows (target 234, draft 16);
  - 261 us at 14 rows (target 244, draft 17).
- **GSM8K:** the difference is +0.0015. The standard error of a difference of two n=1319 passes is ~0.0105.
- **Greedy identity probe** (256 GSM8K prompts, `--parallel 1`): it cannot test bit-exactness on this setup.
  - Two base servers produce token-identical answers on only 70-81 of 256 prompts; base vs this PR on 67-72.
  - Each run, base or this PR, has 5-10 answers that differ from every other run. This PR has 5, all with the same final answer.

For scale: on 10-27, an older stack (#63027 @ `be9f259d42`) with tuned K1, X8R at TP8 and a poll-batch fix enabled together took -261 us at conc 1. Tuned K1 alone now takes -254 us.

**Not bit-compared on GPU:**
- the DSpark draft's TP8 K1: its only check is acceptance, and AL moves by -0.011;
- the fold=0 and index-source K1, which the layers test checks only to a tolerance;
- the conc 2 / 4 widths, 14 and 28 rows (the numerics test runs M = 6, 7, 12, 36, 48).
