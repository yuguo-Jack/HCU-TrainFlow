# [Recipes Tool][CPU] Remove obsolete TP/DP NUMA binding workaround

[Upstream PR](https://github.com/vllm-project/vllm/pull/64797) · state: closed · merged: True

## Original PR description

## Overview

Remove the temporary CPU TP/DP NUMA-binding workaround from Recipes, now that native DP NUMA affinity has been fixed by [vLLM PR #62867](https://github.com/vllm-project/vllm/pull/62867).

## Claims

- Remove the obsolete `--tp-dp-numa-bind-workaround` CLI option and binding override logic.
- Remove the unused `build_numa_omp_threads_bind()` helper.
- Rely on native vLLM CPU NUMA autobinding for TP/DP sweeps.
- Preserve recipe-provided CPU binding settings and existing sweep functionality.

## Validation

- Verify Recipes converter syntax and CLI help.
- Confirm no remaining references to the removed workaround.
- Run Xeon CPU sweeps using the latest nightly image with TP/DP configurations.
- Verify each DP rank binds to its assigned NUMA node through server logs.

## Details

The previous workaround generated explicit `VLLM_CPU_OMP_THREADS_BIND` values to avoid multiple DP ranks sharing the same NUMA node.

With PR #62867 merged, vLLM now handles per-DP-rank NUMA affinity natively. The workaround is no longer necessary and can interfere with automatic CPU reservation settings such as `VLLM_CPU_NUM_OF_RESERVED_CPU`.

This change simplifies Recipes and removes obsolete code without modifying vLLM's core CPU binding implementation. It assumes a vLLM build containing PR #62867.
