# [Bugfix][ROCm] Muse Spark: ensure shared RoPE cos_sin_cache is on CUDA for fused kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/65170) · state: closed · merged: False

## Original PR description

## Overview

Fixes test_muse_spark_rocm_mono.py failures introduced by the interaction of #62757 (shared RoPE via get_rope()) and #63440 (monokernel).

## Claims

- Fixes all 26 test_muse_spark_rocm_mono failures (cos_sin_cache must be a contiguous 2-D CUDA tensor)

## Validation

Tested on MI350X (gfx950) against vllm/vllm-openai-rocm:nightly-76c6f3f2a with both this patch and #65080 hotpatched:

- Before fix: 26 failed (cos_sin_cache error)
- After fix: 33 passed, 0 failed (29.79s)

## Details

get_rope() caches RotaryEmbedding instances globally and may create the cos_sin_cache buffer on CPU. The non-fused RoPE path handles this via _match_cos_sin_cache_dtype(), but the fused HIP kernel and the monokernel access the buffer directly.

This patch normalizes the shared cache once at load time in process_weights_after_loading, before maybe_attach_mono, so both the fused kernel and the monokernel see a contiguous CUDA buffer from the start. No forward-path overhead.
