# [Feature][Spec Decode] Add MRV2 grammar-aware draft proposal bridge

[Upstream PR](https://github.com/vllm-project/vllm/pull/64445) · state: open · merged: False

## Original PR description

Co-authored-by: @zhentaocc (Zhentao Chen), @whatghost (Yuyang Gao) and @zhangnju (Ning Zhang) from AMD
## Overview

Add an opt-in MRV2 draft-proposal grammar bridge for speculative methods,
including future EAGLE-4 plugins.

The bridge gives a speculator verified tokens and serializable structured-output
request metadata before the next proposal. A speculator that cannot install an
exact device-side grammar constraint returns no readiness mask, and vLLM
withholds its draft rows instead of emitting unconstrained proposals.

## Claims

- Keep all built-in speculators unchanged by default.
- Add request lifecycle hooks for opt-in draft grammar state.
- Pass only post-verification tokens to the bridge; do not reuse verifier
  bitmasks whose state precedes the accepted bonus token.
- Require a device boolean readiness row for each active request.
- Replace unready draft rows with speculative padding tokens (`-1`).

## Details

This is an MRV2 extension and does not copy or supersede
[#47885](https://github.com/vllm-project/vllm/pull/47885), whose shadow grammar
implementation targets V1 `SpecDecodeBaseProposer`.

The generic host bridge deliberately avoids selecting draft tokens itself. The
speculator owns the grammar matcher and device mask, preserving the boundary
between vLLM execution and an out-of-tree speculative algorithm.
