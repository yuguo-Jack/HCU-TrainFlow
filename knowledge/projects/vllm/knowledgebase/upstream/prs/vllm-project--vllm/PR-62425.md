# [Rust Frontend] Clamp logit_bias to [-100, 100]

[Upstream PR](https://github.com/vllm-project/vllm/pull/62425) · state: open · merged: False

## Original PR description



## Overview

Python's `SamplingParams.from_optional` clamps every `logit_bias` value to `[-100, 100]` for every entry point, so a bias of `250` behaves like `100`. The Rust frontend forwards the value to the engine unchanged, so the same request samples differently on the two frontends. This PR clamps biases in `vllm_text::lower_sampling_params`.

Supersedes the inactive draft vllm-project/vllm#50350, which clamps in the HTTP-only `convert_logit_bias` helper.

## Claims

- Rust clamps each `logit_bias` value to `[-100, 100]` before it reaches engine-core, matching `SamplingParams.from_optional`.
- The clamp applies to every Rust entry point: `/v1/chat/completions`, `/v1/completions`, `/inference/v1/generate`, and gRPC.
- In-range values are unchanged; key parsing and the out-of-vocab check are unchanged.

## Details

- **Where the clamp lives.** `vllm_text::lower_sampling_params` turns northbound sampling params into engine-core params, and every Rust entry point goes through it. Python clamps at the equivalent point, `SamplingParams` construction. Clamping in `convert_logit_bias` (as in vllm-project/vllm#50350) would miss `/inference/v1/generate` and gRPC, which do not use that helper.
- **NaN.** `f32::clamp` keeps NaN, while Python's `min(100.0, max(-100.0, nan))` returns `-100.0`. Over HTTP this cannot happen, since `serde_json` rejects a body with a `NaN` literal; over gRPC a NaN float would pass through unclamped. This PR leaves NaN alone: the open draft vllm-project/vllm#62038 proposes rejecting NaN biases in Python instead, and Rust should follow whichever behavior lands there.
- **Not a duplicate.** Searched open PRs for `logit_bias` (`clamp`, `Rust`, title-only). vllm-project/vllm#50350 is the only open PR for this item: a draft with no activity since 2026-09-24 that clamps in the HTTP-only helper. vllm-project/vllm#62038 (Python NaN rejection) and vllm-project/vllm#60562 (V2 sampler caps) touch different behavior.
