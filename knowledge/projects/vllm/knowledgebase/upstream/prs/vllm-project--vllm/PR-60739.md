# docs: clarify CacheConfig compilation hash behavior

[Upstream PR](https://github.com/vllm-project/vllm/pull/60739) · state: open · merged: False

## Original PR description



## Overview

Clarify the `CacheConfig.compute_hash()` docstring to reflect the current opt-out hashing implementation.

Related to #39479 (TODO #7). This complements #46714, which addresses misleading docstrings in other configuration classes.

## Claims

- Remove outdated guidance instructing developers to manually include new fields in the hash factors list.
- Clarify that dataclass fields are included by default unless explicitly excluded through `ignored_factors`.
- Document that new fields should only be excluded when doing so is safe for compilation-cache correctness.
- Preserve existing hashing behavior.

## Validation

- `git diff --check` passed.
- Reviewed the diff to confirm that only the docstring in `vllm/config/cache.py` changed.
- No runtime tests executed because this is a documentation-only change.

## Details

`CacheConfig.compute_hash()` uses `get_hash_factors(self, ignored_factors)`, which automatically includes dataclass fields unless explicitly excluded.

The previous docstring described an older opt-in approach where developers had to manually add hash-relevant fields. This update aligns the documentation with the current implementation.

Unlike #46714, this change specifically addresses `CacheConfig`, which computes a hash from its non-excluded configuration fields.

**AI Assistance:** ChatGPT was used to understand the hashing implementation and draft the docstring correction. The final change was manually reviewed.
