# [Bugfix][Frontend] Continue final assistant messages in Anthropic requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/62894) · state: open · merged: False

## Original PR description

## Overview

Continue a final assistant text prefix in Anthropic requests when it contains non-empty text and no tool calls. Generation and token counting use the same prompt. Fixes #62830.

## Claims

- `/v1/messages` continues text prefixes in streaming and non-streaming mode, and `/v1/messages/count_tokens` counts that continuation prompt.
- Final assistant messages with tool calls or no non-empty text keep the previous prompt, including the new assistant header. Tool calls are retained even when the same message contains text.
- Requests ending in a user message keep the default generation prompt.

## Details

The shared converter reuses `continue_final_message` and `add_generation_prompt`. It checks for non-empty text in string or content-block form and excludes messages containing `tool_calls`. Enabling continuation based only on the assistant role can fail for missing text or truncate a tool call rendered after the text, as reported in [this review](https://github.com/vllm-project/vllm/pull/62894#pullrequestreview-5636821173). The model's chat template must support final-message continuation.

The converter now requires non-empty text, either a string or a text part, and no `tool_calls` before setting `continue_final_message=True` and `add_generation_prompt=False`. Otherwise, it keeps the previous defaults: `continue_final_message=False` and `add_generation_prompt=True`. Both Anthropic endpoints use this check. The docs now describe these conditions, including thinking-only messages.

The tests cover these cases:

| Final assistant content | Expected behavior | Coverage |
| --- | --- | --- |
| Non-empty string or text block | Continue the text | Conversion; existing live streaming/non-streaming test uses a string prefix |
| Multiple text blocks, or thinking followed by text | Continue the text | Conversion |
| `tool_use` only | Keep the complete turn and add a new assistant header | Full template comparison and live HTTP |
| `thinking` only | Keep the previous closed-turn prompt | Full template comparison and live HTTP |
| Text plus `tool_use` | Keep both the text and tool call, then add a new assistant header | Full template comparison and live HTTP |
| Empty string, empty block list, or empty text block | Keep the previous prompt | Full template comparison |
| Image block without text | Keep continuation disabled and preserve the previous template output | Conversion/template only |

The template cases run with both generation and token-count request types. They compare the entire prompt with the previous rendering, and the tool cases also check that the tool-call block is present. The image-only case does not load or run an image model.
