# [CI] Enroll the remaining Spec Decode jobs in automatic sharding (21 jobs)

## Overview

Enrolls the remaining Spec Decode jobs in `automatic_shard`: 21 jobs (11 steps and 10 AMD mirrors). Part of a series that enrolls every remaining test step, split by test area for review. No commands change.

## Claims

| Step | Plan | AMD mirror |
|---|---|---|
| `spec-decode-mtp-deepseek-mimo` | 1 shard | 1 shard |
| `spec-decode-eagle-1-deepseek-qwen` | 1 shard | 1 shard |
| `spec-decode-eagle-2-llama3-qwen-vl-other` | 1 shard | 1 shard |
| `spec-decode-deepseek-mtp-parallel-load-2xb200-2xmi300` | 1 shard | 1 shard |

| `spec-decode-ngram-suffix` | 1 job (not plain pytest) | 1 job (not plain pytest) |
| `spec-decode-speculators` | 1 shard | 1 shard |
| `speculators-correctness` | 1 shard | 1 shard |
| `spec-decode-mtp-gemma4` | 1 shard | 1 shard |
| `spec-decode-dflash2-nightly-b200` | 1 shard | 1 shard |
| `spec-decode-xpress-nightly` | 1 shard | none |

- One-shard and one-job plans run the same tests as on main, as one job, and split by themselves once their tests grow.


## Validation

- Planned each step and mirror with ci-infra main's planner against main's timings; every plan is within 10% of the same plan run as one job.
- The sharding harness (each shard's commands run against a mock test tree, as a PR build and as main with the OTel wrapper) shows every test runs exactly once wherever a plan has 2 or more shards.
- Every step and mirror passes on recent main runs, nightly included.
- `/ci run` (98457) plus a scoped build (98468) for the optional steps and AMD mirrors on this head: every enrolled job passed, and every shard finished under 22 minutes.

## Details

- **Not plain pytest** steps (shell scripts, `torchrun`, examples) and standalone AMD steps are enrolled too; the generator keeps them as one job.
- **caplog.** Files that assert on logs sit in one-shard plans here, so their order in the process doesn't change.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job. Fallback-aware timeouts belong in a central timeout setting.
