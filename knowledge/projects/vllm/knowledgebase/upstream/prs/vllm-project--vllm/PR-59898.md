# [Distributed] Include NCCL's last error in pynccl error messages

[Upstream PR](https://github.com/vllm-project/vllm/pull/59898) · state: open · merged: False

## Original PR description



## Overview

`NCCLLibrary.NCCL_CHECK` reports only `ncclGetErrorString(result)`, which maps the result code to a fixed phrase such as "unhandled cuda error". NCCL keeps the actual cause in `ncclGetLastError()`, which `torch.distributed` already appends to its errors. This PR appends it to vLLM's pynccl errors too.

## Claims

- An NCCL failure in vLLM now shows NCCL's own explanation (the failing CUDA call and its error, or NCCL's hint such as `Disable NVLS (NCCL_NVLS_ENABLE=0)`), instead of only "unhandled cuda error (run with NCCL_DEBUG=INFO for details)".
- No change on success paths. If the library doesn't export `ncclGetLastError`, the message is unchanged.

## Validation

New test `test_nccl_error_includes_last_error` (in `tests/distributed/test_pynccl.py`, next to `test_ncclGetUniqueId`) calls `ncclGetUniqueId(NULL)` against the real library and checks that NCCL's reason (`GetUniqueId : out argument is NULL`) is in the exception. NCCL and RCCL print the same message (`PtrCheck` in `src/misc/argcheck.cc`).

## Details

Root cause: on 2x H100 SXM, `vllm serve --tensor-parallel-size 2` died in worker init with only `NCCL error: unhandled cuda error (run with NCCL_DEBUG=INFO for details)`. On the same host, `torch.distributed` failed with the real reason, because it appends `ncclGetLastError(nullptr)` ([NCCLUtils.cpp](https://github.com/pytorch/pytorch/blob/main/torch/csrc/distributed/c10d/NCCLUtils.cpp)):

```
Failed to bind NVLink SHARP (NVLS) Multicast memory of size 2097152 : CUDA error 401 'the operation cannot be performed in the present state'.
This is usually caused by a system or configuration error in the Fabric Manager or NVSwitches.
Disable NVLS (NCCL_NVLS_ENABLE=0) if you wish to avoid this error in the future.
```

Notes:
- `ncclGetLastError` is loaded as an optional symbol, like `ncclCommQueryProperties`, so a library without it still loads. NCCL has exported it since 2.13. RCCL exports it too.
- NCCL keeps the last error in one process-wide buffer and never clears it, so the text can belong to an earlier failure or to another thread. It is only read after a call has failed, and it is labeled "Last error" as in torch.
