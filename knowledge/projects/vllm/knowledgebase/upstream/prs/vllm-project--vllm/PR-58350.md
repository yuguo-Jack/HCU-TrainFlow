# [MoE][NVIDIA] Add FlashInfer NVFP4 shared-expert fusion

[Upstream PR](https://github.com/vllm-project/vllm/pull/58350) · state: open · merged: False

## Original PR description

## Summary

Integrate FlashInfer TRT-LLM-gen NVFP4 native shared-expert fusion for compatible
DeepSeek-V2/V3-family ModelOpt checkpoints on SM100.

This is an independent replacement for #53112, rebased conceptually on current
`main`; it does not depend on the stalled FP8 work in #51754. Closes #50963.

This appends shared-expert weights after the routed expert bank, keeps routing
logits limited to routed experts, and passes `num_fused_shared_experts` to the
FlashInfer monolithic MoE backend. Unsupported configurations retain the current
separate shared-MLP path.

## Changes

- propagate fused shared-expert count and multiplier through `FusedMoEConfig`;
- require an explicit backend capability before allocating appended expert rows;
- opt the FlashInfer TRT-LLM NVFP4 backend into native fusion;
- gate the path to compatible serialized ModelOpt NVFP4 DeepSeek models on
  SM100 without EP/EPLB;
- remap checkpoint `shared_experts.*` weights, block scales, and scalar scales
  into appended expert-major storage;
- add an on-by-default environment switch for controlled A/B validation; and
- add focused backend and model-loader tests.

## Validation

- formatting, static checks, compile checks, and `git diff --check`: passed;
- focused GPU tests on 8x B200: 13 passed;
- DeepSeek-R1-NVFP4-v2 startup: passed;
- GSM8K full set: 95.30% (1,319 questions, 0 invalid);
- exact 8k-input/1k-output c256: +2.41% request/output throughput;
- InferenceX-style sweep c64/c128/c256/c512/c1024: throughput change
  +0.19%/+1.10%/+2.79%/+2.22%/+2.39%; and
- four balanced c128 repeats: +1.60% mean throughput, positive in 4/4 runs.

A bounded Torch trace confirms the intended structural change: the separate
shared-path events fall from 2,320 to 0, total CUDA event count falls 12.83%,
and total summed CUDA event duration falls 4.24% over 40 rank-0 engine
iterations.

## Scope and limitations

The native path requires the FlashInfer API/kernel support and is intentionally
disabled for expert parallelism, EPLB, modular kernels, non-SM100 CUDA devices,
non-ModelOpt quantization, and incompatible shared/routed quantization. The
environment switch can restore the existing path for A/B comparison.
