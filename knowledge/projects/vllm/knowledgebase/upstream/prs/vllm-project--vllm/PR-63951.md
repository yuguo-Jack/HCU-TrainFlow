# [Bugfix][MM] Skip encoder CUDA graphs with no active modalities

[Upstream PR](https://github.com/vllm-project/vllm/pull/63951) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Skip encoder CUDA graph capture when a model disables every graph modality. Qwen3-VL currently returns an empty modality list when video pruning is configured, but the shared manager still counted and captured its graphs.

Related: #38175. This does not duplicate #60112's replay-capacity fallback or #49432's encoder interface refactor; neither addresses capture with no enabled modalities.

## Claims

- An empty modality list reports zero encoder graphs and leaves the graph pool inactive.
- Ordinary image/video graph capture and replay retain their existing behavior.
- Qwen3-VL image generation with EVS or VidCom2 configured agrees with the encoder-CG-disabled path.

## Validation

One NVIDIA RTX 4090 24 GB; Python 3.12.3, PyTorch 2.14.0+cu130, Transformers 5.20.2, FlashInfer 0.7.2.post1. Python source base: `5d35ce3934a7804b298559d2d99eec33792e1eb9`. Native libraries and packaged submodule files came from the official `6fe3d447ac6429ef13aff117744d0298e28879ed` cu130 wheel; the intervening commit changes Mistral chat templating, with no `csrc/` changes. Both comparison arms use the same native files.

| Check | Result |
|---|---|
| New constructor regressions against baseline production source | 2 failed, 1 passed: graph count was 2 instead of 0, and empty-modality capture activated a pool |
| Same constructor regressions with the fix | 3 passed |
| Complete encoder manager CUDA suite | 72 passed |
| Real Qwen3-VL-2B image generation, EVS and VidCom2 | 2 passed with `VLLM_GPU_SYNC_CHECK=error` |
| Pre-commit, including mypy and Buildkite test tethering | Passed |

```bash
.venv/bin/python -m pytest tests/v1/cudagraph/test_encoder_cudagraph.py -v
VLLM_GPU_SYNC_CHECK=error .venv/bin/python -m pytest \
  tests/models/multimodal/generation/test_vit_cudagraph.py \
  -k pruning_disables_encoder -v -s
```

The model check uses real `Qwen/Qwen3-VL-2B-Instruct` weights, revision `89644892e4d85e24eaac8bacfd4f463576704203`, 16 greedy output tokens and top-5 logprobs. It uses encoder data mode at TP=1, compares encoder-CG off/on, and checks that the enabled-but-inactive manager has no captured graphs or active pool. Existing Buildkite selections cover both test files.

## Details

The shared manager's graph count now respects `config.modalities`, and `capture()` returns before assigning a pool when that count is zero. Both runner generations consume this shared behavior; real-model execution was validated on MRV2.

The real-model regression covers image requests with pruning configured. Full video-pruning generation, multi-GPU execution and other GPU architectures were not validated. Separate exploratory runs encountered existing eager video-pruning position/synchronization failures before enabling encoder graphs; this patch does not modify that path. No end-to-end latency or memory-saving percentage is claimed.

AI assistance was used for implementation, review, tests and validation. The reported remote runs were executed by an AI agent on the submitter's server.
