# [Bugfix][Core] Widen EAGLE periodic SWA tails so a diverging sibling keeps its prefix-cache hit

[Upstream PR](https://github.com/vllm-project/vllm/pull/64843) · state: open · merged: False

## Original PR description

## Summary
Fixes #64808 (fix option B from the issue): with EAGLE spec decoding and a positive `--prefix-cache-retention-interval`, a request sharing a long prefix falls back a whole retention interval (16384 -> 8192 cached tokens in the reporter's repro) instead of hitting the cached segment tail.

## Root cause
`SlidingWindowManager.reachable_block_mask` places each periodic segment tail so its right edge sits on the aligned boundary block (the EAGLE peek block, `shift=1`). A sibling that diverges right after a segment boundary cannot use that peek block, so its sliding-window hit lands one block lower — and those blocks were never cached. The shared-prefix junction path already handles the same situation by appending `shared_prefix_boundary - block_size` as an extra reachable boundary; the periodic-segment path had no equivalent.

## Change
In the periodic-segment branch of `SlidingWindowManager.reachable_block_mask`, widen each tail by one block on the low side under EAGLE (`tail_need = need + 1`). This only ever caches additional blocks (dense caching is the safe fallback), never drops a reachable block. The non-EAGLE path, the reachable-boundary tails, and the final-partial-segment branch are unchanged. Cost: one extra cached block per periodic checkpoint, matching the reporter's measurement for option B (per-request hits 0/16256/16256/16256 instead of 0/8192/16256/16256).


## Tests
New regression test `test_swa_reachable_block_mask_eagle_periodic_tail_widens_by_one` plus updated EAGLE expectations in `test_swa_reachable_block_mask_final_partial_segment` (its old expectations encoded the pre-fix tail width).

Commands run (`.venv/bin/python -m pytest`):
- New test on the base commit (fix stashed): FAILED as expected.
- New test with the fix: passed.
- `tests/v1/core/test_prefix_caching.py -k reachable_block_mask`: 10 passed.
- Full `tests/v1/core/test_prefix_caching.py`: 218 passed, 8 failed — all 8 are `test_nixl_hisparse_full_block_import_keeps_a_writable_tail` parametrizations failing at model-config validation because this sandbox cannot download `facebook/opt-125m` from HuggingFace (egress proxy); unrelated to this change.

## Limitations / validation gap
No end-to-end validation on the reporter's hardware (B300 + Gemma-4 + FP8 KV) was possible here; the mask-level test is the cheapest level that reproduces the exact fault (the mask is the defective unit). The issue's measured per-request hit numbers are the reporter's, not re-measured here.
