# [ROCm][CI] Bake the fast-exit plugin into the test image and fix the ray-compat pin strip

[Upstream PR](https://github.com/vllm-project/vllm/pull/64132) · state: closed · merged: True

## Original PR description

- `Dockerfile.rocm`, `run-amd-test.sh`: the test image installs `amd_ci_fast_exit.py` into site-packages, so jobs no longer copy it in at start
- `check-ray-compatibility.sh`: strip the stack's local pins (TheRock torch, triton, amdsmi) on every ROCm torch, not only when download.pytorch.org has no `rocm<ver>` index

The ray-compat check only passes today because TheRock torch reports HIP 7.15 and download.pytorch.org has no `rocm7.15` index ([build 15532](https://buildkite.com/vllm/amd-ci/builds/15532)); once that index appears, the check would keep the `+rocm` pins and fail to resolve. The test image already has `.buildkite/`, so installing the pytest plugin there replaces the copy every job made, and #63426 also edits `run-amd-test.sh` around it. Follow-up to #61939; `pytest tests/tools/test_rocm_build.py tests/tools/test_amd_ci_fast_exit.py` passes, but none of this has run in AMD CI yet.

An earlier revision also worked around the AITER nightly lane's image-build failure; that is dropped, since the nightlies are now `manylinux_2_28` and pass the existing ldd check ([build 15765](https://buildkite.com/vllm/amd-ci/builds/15765)).

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
