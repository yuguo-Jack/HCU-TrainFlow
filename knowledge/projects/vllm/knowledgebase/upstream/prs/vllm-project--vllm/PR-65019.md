# [Bugfix][Parser] DeepSeek V4.1: treat DSML markers as structure only from the DSML token

[Upstream PR](https://github.com/vllm-project/vllm/pull/65019) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

V4.1 DSML markers contain a dedicated `｜DSML｜` token surrounded by ordinary text. The parser currently also accepts copies spelled entirely with ordinary tokens, turning quoted examples into tool calls or cutting reasoning and string arguments short. This change requires token provenance for DSML structure when output token IDs are available.

This is output-side work, distinct from input sanitization in #62667. #50676 and #60256 overlap with non-streaming token-ID handling; neither covers the streaming reasoning-to-tool hand-off here. #59145 addresses token-aware structural tags, a remaining compatibility gap below. #62517 and #61142 extend opener variants in the same format; they do not add this provenance guard.

## Claims

- With token IDs, ordinary-token DSML copies stay text in content, reasoning and string arguments, in streaming and non-streaming. Genuine markers retain their positions across split UTF-8 characters, held-back text and reasoning-to-tool transitions; they cannot bind to a later text copy.
- The tool parser's guard works with or without the reasoning parser. Unified reasoning/tool routing requires auto tools and both `deepseek_v41` parsers. On that route, requests without tools and `tool_choice="none"` return DSML call markup as content instead of silently dropping it, even without token IDs.
- In token-ID mode, text between and after tool-call blocks is returned as content, in order. Prompt-state detection stops at assistant, user and system role boundaries: a prompt that closes reasoning starts in content; an earlier turn's closing marker cannot disable reasoning in a new task prompt.
- Without token IDs, DSML matching remains text-based. Configurations without composite terminals retain their existing token-scanning paths.

## Details

**Root cause.** Composite DSML markers do not resolve to one token ID, so text matching bypasses the engine's protection for dedicated-token terminals. Searching text for token spellings can also rebind a genuine marker to a later copy. Separate reasoning and tool engines lose provenance at the hand-off, and non-streaming delegation does not forward output IDs.

**Mechanism.** `composite_token_id_terminals` declares each marker's required token atom. Scanner alignment produces trusted spans for the lexer, parameter conversion and open-value extension. Unaligned text stays buffered, then falls back to content at end-of-stream without trusting markers. Full ByteLevel runs with exact byte counts avoid redundant decoding unless replacement characters make counts ambiguous; one-token runs reuse the decode cache. Partial prefixes still require decoded alignment. Span mode bypasses the normal plain-content fast path; the remaining cost is in the table above.

**Routing and scope.** The V4.1 wrapper shares one reasoning/tool engine, retaining request adjustment and constrained-JSON dispatch. This preserves streaming provenance and forwards non-streaming IDs, overlapping #50676/#60256. Span tracking is generic and opt-in. Post-call content and deferred-content ordering remain gated by composite-terminal mode in shared engine files: a design tradeoff, not a general routing cleanup. Prompt boundaries are configured in V4.1; its streaming hook still applies the base prompt-state calculation because the base hook is a no-op.

**Structural-tag limitation.** Strict required/named choices use string-based structural tags. A forced call whose DSML atom is sampled as ordinary tokens would be returned as content, potentially yielding no tool call. This is inferred from the grammar/parser interaction, not reproduced with constrained model generation. There is no mitigation in this PR: token-aware tags in #59145 are the preferred direction; a future request-scoped guard bypass for constrained output is another option.

**Other limits.** Custom detokenizers whose text never aligns with IDs fall back to text. Streaming still drops a whitespace-only content delta immediately after a call, as before. No end-to-end latency or throughput improvement is claimed.
