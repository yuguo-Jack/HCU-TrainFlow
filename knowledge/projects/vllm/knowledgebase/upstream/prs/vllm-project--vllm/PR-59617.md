# [Frontend] Return Anthropic's prompt-too-long error on /v1/messages

[Upstream PR](https://github.com/vllm-project/vllm/pull/59617) · state: open · merged: False

## Original PR description

## Purpose

Part of #58647 (item 4, context overflow).

When the prompt alone is longer than the context window, `/v1/messages` now returns Anthropic's error instead of vLLM's:

```json
{"type": "error", "error": {"type": "invalid_request_error", "message": "prompt is too long: 151834 tokens > 131072 maximum"}}
```

Upstream ([context window overflow behavior](https://platform.claude.com/docs/en/build-with-claude/context-windows#context-window-overflow-behavior)):

> If the input alone already exceeds the model's context window, the API returns a 400 `invalid_request_error` ("prompt is too long") on every model.

Claude Code 2.1.286 matches `prompt is too long[^0-9]*(\d+)\s*tokens?\s*>\s*(\d+)` to start compacting the conversation. Today vLLM answers `400 BadRequestError: Input length (151771) exceeds model's maximum context length (131072).`, which Claude Code does not recognize. The session then fails every following request: the history only grows, and nothing ever compacts it.

**Change:**
- `get_max_tokens` raises `VLLMValidationError(parameter="input_tokens", value=<prompt length>)` instead of a bare `ValueError`. It is still a 400 on the OpenAI endpoints, and this is in line with the migration away from raw `ValueError`s noted in `create_error_response`. The message text is the same, plus the usual `VLLMValidationError` suffix, e.g. `… context length (65536). (parameter=input_tokens, value=70068)`.
- `AnthropicServingMessages.create_messages` turns that error into the Anthropic error when the prompt length is greater than `max_model_len`. The count is exact here, because the prompt is fully tokenized before `get_max_tokens`. Any other validation error is re-raised as before.

**Scope:** this covers prompts that reach `get_max_tokens`, as on the Harmony (gpt-oss) path, which is the setup in the Claude Code docs. On the HF-template path, the renderer rejects prompt + `max_tokens` earlier, with a lower-bound token count. #42482 and #57035 change that case to accept the request and limit `max_tokens`, so it is left out here.

This PR and #59616 together let a Claude Code session recover from outgrowing the context window with default settings (see Test Result). Neither one does it alone. The two PRs touch neighboring import lines in `serving.py`, so whichever merges second needs a one-line rebase.

**Not a duplicate:** searched open PRs for "prompt is too long", "anthropic context length", and PRs referencing #58647. #58023 makes request-validation failures use the Anthropic error envelope. It does not cover this error and does not touch the same code.

## End-to-end: Claude Code versions × direct and LiteLLM

The `overflow` scenario of `cc_e2e.py` (below) reads six ~11k-token files, one per turn, against gpt-oss-120b with `--max-model-len 65536`, so the conversation outgrows the window at turn 5, then asks for all six secret words. **main** is the base commit. **fix** is #59616 + #59617 (+ #59618) merged. LiteLLM is 1.103.1 with `hosted_vllm`, which sends Claude Code's requests to `/v1/chat/completions`.

| 2.1.75 | ✗ | ✗ same | ✗ | ✗ |

| 2.1.213, 2.1.214, 2.1.215, 2.1.218, 2.1.224, 2.1.252 | – | ✓ 7/7 turns | – | – |

What this shows:
- **Direct:** with the fix, Claude Code **2.1.213 and later** recovers by itself (2.1.212 does not). Older versions recognize the error and show "Prompt is too long", which is clearer than vLLM's message, but they don't compact automatically.
- **Through LiteLLM:** the fix doesn't apply, because LiteLLM calls `/v1/chat/completions`, not `/v1/messages`. LiteLLM passes vLLM's chat error through as `invalid_request_error: "litellm.BadRequestError: Hosted_vllmException - …"`, and a generation that fills the window comes back as `stop_reason: "max_tokens"`, since Chat Completions has no finish reason for it. Covering this path needs a LiteLLM change: its Anthropic endpoint would have to report context-window errors as `prompt is too long: N tokens > M maximum` (it already does for Bedrock Mantle) and recognize vLLM's `Input length (N) exceeds model's maximum context length (M)` wording.
- **Client-side workaround (#59619), both paths:** `CLAUDE_CODE_AUTO_COMPACT_WINDOW=65536` (2.1.75+) or `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=20` (2.0.70) completes 7/7 turns on all five versions, direct and through LiteLLM.

3. Save this as `cc_e2e.py`. It drives a real multi-turn Claude Code session and prints a verdict:

```python
"""Run a real Claude Code session against an Anthropic-compatible endpoint.

Scenarios:
  overflow  Read N large files, one per turn, so the conversation outgrows the
            server's context window, then ask for every secret word. PASS when
            every turn succeeds; "recalled" counts the words that survived
            compaction, which depends on the model's summary.
  image     Read a plain red PNG, ask for its color, then send a follow-up.
            PASS when no turn fails and the model names no color other
            than red (a text-only model should answer UNKNOWN).

Usage:
  python cc_e2e.py --claude ./node_modules/.bin/claude \
      --base-url http://localhost:8000 --model openai/gpt-oss-120b \
      --scenario overflow [--env CLAUDE_CODE_AUTO_COMPACT_WINDOW=65536]

Only the standard library is needed. Point --base-url at vLLM for
Claude Code -> vLLM (/v1/messages), or at a LiteLLM proxy for
Claude Code -> LiteLLM -> vLLM (/v1/chat/completions).
"""

import argparse
import json
import os
import random
import re
import shutil
import struct
import subprocess
import sys
import tempfile
import zlib

OTHER_COLORS = {
    "black",
    "blue",
    "brown",
    "cyan",
    "gold",
    "gray",
    "green",
    "grey",
    "indigo",
    "magenta",
    "maroon",
    "navy",
    "orange",
    "pink",
    "purple",
    "silver",
    "teal",
    "turquoise",
    "violet",
    "white",
    "yellow",
}
WORDS = ["alpha", "beta", "gamma", "delta", "epsilon", "zeta", "theta", "kappa"]


def red_png(size: int = 64) -> bytes:
    raw = b"".join(b"\x00" + b"\xff\x00\x00" * size for _ in range(size))

    def chunk(tag: bytes, data: bytes) -> bytes:
        crc = zlib.crc32(tag + data) & 0xFFFFFFFF
        return struct.pack(">I", len(data)) + tag + data + struct.pack(">I", crc)

    header = struct.pack(">IIBBBBB", size, size, 8, 2, 0, 0, 0)
    return (
        b"\x89PNG\r\n\x1a\n"
        + chunk(b"IHDR", header)
        + chunk(b"IDAT", zlib.compress(raw))
        + chunk(b"IEND", b"")
    )


def setup(
    scenario: str, work: str, files: int, lines: int
) -> tuple[list[str], list[str]]:
    """Write the scenario's files into work; return (prompts, expected words)."""
    rng = random.Random(0)
    if scenario == "image":
        with open(os.path.join(work, "logo.png"), "wb") as f:
            f.write(red_png())
        return [
            "Use the Read tool on logo.png and describe the image.",
            "What is the main color of logo.png, in one word? "
            "If you could not see the image, answer UNKNOWN.",
            "Reply with the single word OK.",
        ], []
    secrets = []
    for i in range(1, files + 1):
        secret = f"{rng.choice(WORDS)}{i}"
        secrets.append(secret)
        with open(os.path.join(work, f"part{i}.txt"), "w") as f:
            for n in range(lines):
                text = " ".join(rng.choice(WORDS) for _ in range(10))
                f.write(f"part{i} line {n}: {text}\n")
            f.write(f"END OF PART {i}: the secret word is {secret}\n")
    prompts = [
        f"Use the Read tool to read part{i}.txt in full and tell me its secret word."
        for i in range(1, files + 1)
    ]
    prompts.append("List every secret word you found so far, one per line.")
    return prompts, secrets


def main() -> int:
    ap = argparse.ArgumentParser()
    ap.add_argument("--claude", required=True, help="path to the claude binary")
    ap.add_argument("--base-url", required=True)
    ap.add_argument("--model", required=True)
    ap.add_argument("--scenario", choices=["overflow", "image"], required=True)
    ap.add_argument("--files", type=int, default=6)
    ap.add_argument("--lines", type=int, default=550, help="~20 tokens per line")
    ap.add_argument("--env", action="append", default=[], help="extra KEY=VALUE")
    ap.add_argument("--log", help="write Claude Code's stream-json output here")
    args = ap.parse_args()
    # Claude Code runs from a temporary directory, so resolve the path first.
    claude = os.path.abspath(shutil.which(args.claude) or args.claude)

    home, work = tempfile.mkdtemp(), tempfile.mkdtemp()
    prompts, secrets = setup(args.scenario, work, args.files, args.lines)
    env = {
        "PATH": os.environ.get("PATH", "/usr/bin:/bin"),
        "HOME": home,
        "TERM": "xterm",
        "ANTHROPIC_BASE_URL": args.base_url,
        "ANTHROPIC_API_KEY": "dummy",
        "DISABLE_AUTOUPDATER": "1",
    }
    for var in (
        "ANTHROPIC_MODEL",
        "ANTHROPIC_DEFAULT_OPUS_MODEL",
        "ANTHROPIC_DEFAULT_SONNET_MODEL",
        "ANTHROPIC_DEFAULT_HAIKU_MODEL",
        "CLAUDE_CODE_SUBAGENT_MODEL",
    ):
        env[var] = args.model
    env.update(kv.split("=", 1) for kv in args.env)

    proc = subprocess.Popen(
        [
            claude,
            "-p",
            "--verbose",
            "--input-format",
            "stream-json",
            "--output-format",
            "stream-json",
            "--allowedTools",
            "Read",
        ],
        cwd=work,
        env=env,
        text=True,
        stdin=subprocess.PIPE,
        stdout=subprocess.PIPE,
        stderr=subprocess.DEVNULL,
    )
    results, compactions = [], 0
    with open(args.log or os.devnull, "w") as log:
        for i, prompt in enumerate(prompts, 1):
            msg = {"type": "user", "message": {"role": "user", "content": prompt}}
            proc.stdin.write(json.dumps(msg) + "\n")
            proc.stdin.flush()
            result = None
            for line in proc.stdout:
                log.write(line)
                event = json.loads(line)
                if event.get("subtype") == "compact_boundary":
                    compactions += 1
                if event.get("type") == "result":
                    result = event
                    break
            if result is None:
                print(f"turn {i}: claude exited", flush=True)
                results.append((True, ""))
                break
            text = str(result.get("result") or "")
            results.append((bool(result.get("is_error")), text))
            status = "ERROR" if result.get("is_error") else "ok"
            print(f"turn {i}: {status:5} {text[:110]!r}", flush=True)
    proc.stdin.close()
    proc.wait(timeout=120)

    errors = sum(err for err, _ in results)
    summary = {
        "scenario": args.scenario,
        "turns": len(prompts),
        "failed_turns": errors,
        "compactions": compactions,
    }
    if args.scenario == "overflow":
        final = results[-1][1] if len(results) == len(prompts) else ""
        summary["recalled"] = f"{sum(s in final for s in secrets)}/{len(secrets)}"
        ok = errors == 0 and len(results) == len(prompts)
    else:
        answer = results[1][1].strip().lower() if len(results) > 1 else ""
        # The image is plain red: any other color was made up.
        words = re.findall(r"[a-z]+", answer)
        invented = sorted(set(words) & OTHER_COLORS)
        summary["color_answer"] = answer[:40]
        summary["invented_colors"] = invented
        ok = errors == 0 and len(results) == len(prompts) and not invented
    summary["verdict"] = "PASS" if ok else "FAIL"
    print(json.dumps(summary), flush=True)
    return 0 if ok else 1


if __name__ == "__main__":
    sys.exit(main())
```
