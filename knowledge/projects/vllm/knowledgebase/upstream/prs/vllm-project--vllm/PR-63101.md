# [Perf][MXFP4] Optimize activation quant for mxfp4. 3x kernel speedup, 5% throughput improvement

[Upstream PR](https://github.com/vllm-project/vllm/pull/63101) · state: closed · merged: True

## Original PR description

## Overview

Pass optional `sorted_expert_ids` through Cutlass MXFP4 MoE activation quantization so each sorted token row uses a direct expert index instead of searching expert offset tables.

## Claims


- Kernel: sorted_expert_id path is bitwise identical to offset_search on microbenchmark cases; up to ~3.3× lower median latency at 256 experts for representative input / intermediate_fused shapes.
- E2E: On RedHatAI/GLM-5.3-MXFP4 (TP=4, no spec), ~+5.7% output tok/s vs main.
- API change: Optional sorted_expert_ids on mxfp4_experts_quant, silu_and_mul_mxfp4_experts_quant, and get_cutlass_moe_mm_data; wired from Cutlass MXFP4 MoE when routing metadata exists.

## Details

- Motivation: After MoE routing, activation rows are grouped by expert. The original path resolves each row’s expert via offset-table search; when sorted_expert_ids is already available from Cutlass MoE metadata, that search is redundant and scales poorly with expert count (microbench ~7 µs → ~2.2 µs at 256 experts).

- Design: sorted_expert_ids is optional; when omitted, behavior matches offset_search. 


Possible follow-up: remove redundant shared-memory expert_offsets staging in the large-m_topk MXFP4 quant kernel when sorted_expert_ids is set, and extend the microbenchmark to prefill-sized batches that hit that kernel variant.
