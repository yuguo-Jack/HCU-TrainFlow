# [Refactor][torch.compile] Share compile cache hashing helpers between JIT and AOT paths

[Upstream PR](https://github.com/vllm-project/vllm/pull/62628) · state: closed · merged: False

## Original PR description



## Overview

Addresses TODO 6 of #39479: `VllmBackend.__call__` inlined its own env/config hashing and a traced-file code-hash loop that had drifted from `caching._compute_code_hash`. This makes the JIT and AOT compile-cache paths share one implementation.

## Claims

- `VllmBackend.__call__` now uses `_compute_code_hash()` instead of an inline copy of it.
- New `env_and_config_hash_factors()` in `caching.py` is shared by `VllmBackend.__call__` and `aot_compile_hash_factors()`; `envs.compile_factors()` is still evaluated once per call.
- `_compute_code_hash()` logs and skips unreadable traced files instead of raising, matching the previous inline behavior.
- AOT cache keys are unchanged. The JIT `code_hash` value changes once (see Details).

On macOS CPU `VLLM_COMPILE` is downgraded to `DYNAMO_TRACE_ONCE`, and calling `VllmBackend` directly fails before hashing on CUDA-only passes (on `main` too). This path is covered by `tests/compile` in the `PyTorch Compilation` Buildkite step, which triggers on `vllm/compilation/` changes.

## Details

**Why not a duplicate:** #40890 attempted the env/config half of this and was auto-closed as stale on 2026-10-04 without review; it also changed `aot_compile_hash_factors`' return type. No open PR covers TODO 6. #41381 (TODO 9, `Path` typing) also edits the inline loop removed here and would need a rebase.

**Behavior change (JIT `code_hash`):** the inline loop and `_compute_code_hash` differed, and the helper's semantics are kept because `_verify_source_unchanged` (AOT load) relies on `_compute_code_hash` matching `_compute_code_hash_with_content`:

| | Old inline loop | `_compute_code_hash` |
|---|---|---|
| `"<string>"` | skipped entirely | path hashed, content skipped |
| Hash function | sha256 | `safe_hash` (md5, sha256 under FIPS) |
| Missing file | path hashed + warning | path hashed with empty content, no warning |

Existing JIT compile caches therefore miss once after upgrading, and recompile. This errs towards a cache miss, never a stale hit; the outer cache-dir key is still sha256.

**AOT load path:** an unreadable traced file now hashes as empty instead of raising, so `_verify_source_unchanged` raises "Source code has changed" instead of `UnicodeDecodeError`. Both are caught by `_try_load_aot_compiled_fn`, so the outcome (recompile) is unchanged.

**Minor:** the traced-files debug log in `_compute_code_hash` is formatted eagerly and unsorted, whereas the removed inline version used `lazy()` over a sorted list. Happy to port that over if preferred.
