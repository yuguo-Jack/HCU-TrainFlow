# [Bugfix][Model] Preserve target-token scoring rows during DeepSeek-V4.1 replay

[Upstream PR](https://github.com/vllm-project/vllm/pull/62652) · state: closed · merged: True

## Original PR description

## Summary

Fixes #62651 by retaining every prefill row for `prompt_logprob_token_ids` requests during DeepSeek-V4.1 decoder replay. Generation requests in the same batch continue to trim normally.

Strengthens the existing `test_prompt_logprobs_requests_keep_their_rows` test without adding test functions or collected pytest cases relative to the PR base. It exercises request registration, ordinary and target-token scoring, late scoring offsets, one- and two-chunk prefill, non-identity request-slot mappings, eager and piecewise replay preparation, exact gather/scatter outputs, and slot reuse by generation. The standalone target-scoring test and its Buildkite entries have been removed; existing CI already runs the replay suite.

## Validation

On GCP GB200, using the same environment for the PR base and revised tests:

- Existing replay batch and replay start suites: **15 passed**.
- Three replay suites combined: **22 collected, 19 passed, 3 failed**, both on the PR base and after this revision. The same three `test_replay_graph_matches_eager` cases fail: the first hits a PyTorch `CachingHostAllocator` internal assertion during CUDA Graph capture, and the remaining two report nested graph capture. These environment failures remain unresolved.
- Regression check with the production fix removed: the strengthened existing test **fails**, detecting 172 missing scoring rows; it passes with the fix restored.
- All applicable pre-commit hooks: **passed**.
