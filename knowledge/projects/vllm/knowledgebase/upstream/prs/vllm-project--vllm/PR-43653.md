# [Bugfix] Add SWIGLUSTEP and RELU2 activation support to CPU fused MoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/43653) · state: closed · merged: False

## Original PR description

## Purpose

Fix missing `SWIGLUSTEP` and `RELU2` activation function support in the CPU fused MoE implementation (`cpu_fused_moe.py`).

The `_CPU_MOE_ACT_FN` mapping was missing entries for `MoEActivation.SWIGLUSTEP` and `MoEActivation.RELU2`. This caused an `AssertionError` at runtime when running models that use these activations on CPU. For example, `step3p5.py` sets `activation = "swiglustep"` when `swiglu_limit` is configured, which triggers:
```
assert activation in _CPU_MOE_ACT_FN, f"{activation} is not supported."
```

Closes #43326

## Changes

- Add `_swiglustep_and_mul()`: implements SwigluStep gated activation — `silu(gate).clamp(max=limit) * up.clamp(-limit, limit)` — consistent with `SwigluStepAndMul.forward_native()` in `activation.py`
- Add `_relu2_and_mul()`: implements relu-squared gated activation — `square(relu(gate)) * up` — following the same `activation(gate) * up` pattern as `SiluAndMul` and `GeluAndMul`
- Register both in `_CPU_MOE_ACT_FN`
- Add `MoEActivation.SWIGLUSTEP` and `MoEActivation.RELU2` to the parametrized test list in `tests/kernels/moe/test_cpu_fused_moe.py`

- gemini-code-assist · comment · 2026-05-26T07:34:26Z · [source](https://github.com/vllm-project/vllm/pull/43653#discussion_r3302016257)

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

The `RELU2` activation function in `MoEActivation` is registered as a gated activation function (i.e., `is_gated` is `True`). Gated activations expect the input tensor `x` to have shape `[..., 2 * d]` (consisting of a gate projection and an up projection) and must return a tensor of shape `[..., d]`. 

However, the current implementation of `_relu2_and_mul` does not perform any chunking or gated multiplication, returning a tensor of shape `[..., 2 * d]`. This will cause a shape mismatch and runtime error when the output is passed to the down projection layer. 

If `RELU2` is indeed gated, it should split the input and perform gated multiplication (e.g., `gate * relu2(up)`). If it is non-gated, `MoEActivation.RELU2_NO_MUL` should be used instead, or the input should be chunked properly.

```suggestion
def _relu2_and_mul(
    x: torch.Tensor,
) -> torch.Tensor:
    gate, up = x.chunk(2, dim=-1)
    return gate * torch.square(F.relu(up))
```

- QingZhou-YangHY · comment · 2026-05-26T08:39:46Z · [source](https://github.com/vllm-project/vllm/pull/43653#discussion_r3302416601)

File: `vllm/model_executor/layers/fused_moe/cpu_fused_moe.py` · line None

Thanks for the review! You are correct that `_relu2_and_mul` was missing the chunking step.

However, the correct gated pattern (consistent with `SiluAndMul` and `GeluAndMul`) is `activation(gate) * up`, not `gate * activation(up)`. Both `SiluAndMul.forward_native` and `GeluAndMul.forward_native` apply the activation to the **first** half (`gate`) and multiply by the **second** half (`up`):
- `SiluAndMul`: `silu(x[:d]) * x[d:]`
- `GeluAndMul`: `gelu(x[:d]) * x[d:]`

So the correct fix for `RELU2` is:
```python
d = x.shape[-1] // 2
return torch.square(F.relu(x[..., :d])) * x[..., d:]
```

This has been pushed in the latest commit.
