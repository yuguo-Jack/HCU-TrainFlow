# [Bugfix][Rust Frontend] Bind the managed-engine handshake before spawning Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/57559) · state: open · merged: False

## Original PR description

## Summary
- On `vllm-rs serve`, when `--data-parallel-rpc-port` is omitted, bind the handshake ZMQ ROUTER on `tcp://host:0` **before** spawning the managed Python engine, then pass the kernel-assigned port into `--data-parallel-rpc-port`.
- `connect_handshake` can take that already-bound socket so the port is never released between allocation and the real binder.
- This is a leftover from [#28498](https://github.com/vllm-project/vllm/issues/28498) on the Rust managed-engine path. It does **not** close that tracker; the DP world-group leftover is already covered by [#51018](https://github.com/vllm-project/vllm/pull/51018).

## Why this is not a duplicate
- [#51018](https://github.com/vllm-project/vllm/pull/51018) fixes Python DP world-group `init_process_group` via the coordination store. This PR does not touch that path.
- [#44813](https://github.com/vllm-project/vllm/pull/44813) is `get_open_ports_list` / `network_utils.py`.
- [#46158](https://github.com/vllm-project/vllm/pull/46158) only changes `kv_connector/v1/__init__.py`.
- No open PR binds the Rust managed-engine handshake ROUTER first.
