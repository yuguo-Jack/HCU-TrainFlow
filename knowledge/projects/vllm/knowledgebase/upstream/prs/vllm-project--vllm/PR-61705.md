# [Perf][Multimodal] Use FA4 for long-sequence ViT attention on Hopper

[Upstream PR](https://github.com/vllm-project/vllm/pull/61705) · state: open · merged: False

## Original PR description



## Overview

On Hopper, use FA4's SM90 kernel instead of FA3 for ViT attention calls with head_size 80 and `max_seqlen >= 8192`. FA4 is faster there; FA3 stays for everything else, including windowed attention, where FA4 is slower.

With the CuteDSL attention, and with padding removed, we can see clear win here with FA4 time compared with FA3. I

## Claims

- Nemotron-Parse-2.0 (RADIO ViT-H, 13,320 tokens/image): encoder attention **-8.5%** (54.3 -> 49.7 ms/image), whole encoder -4.8 ms/image, identical greedy output.
- Qwen2-VL-2B at 1792x1792 (16,384 tokens, full attention): **-3.8%** ms/image at batch 8.
- No change where FA4 is not faster: Qwen2.5-VL's windowed layers stay on FA3 (only its 4 full-attention layers switch), and SigLIP (head_size 72, e.g. Gemma-3) is bit-identical.
- No new CPU/GPU sync, works with encoder CUDA graphs, and an explicit `flash_attn_version` still wins.

## Validation

All on one H100 80GB, `vllm/vllm-openai:nightly` (77154ca611; the three changed files are identical between that commit and this branch's base), bf16.

**Runtime checks** (Qwen2-VL-2B, branch):

## Details

- **Why per call, on sequence length.** FA4's SM90 forward has a larger fixed cost than FA3, so it only wins once a call is long enough; for Qwen2.5-VL's 64-token windows it is ~2x slower. The choice is made inside `vit_flash_attn_wrapper`, where `max_seqlen` is already converted to a host int for the launch bounds, so it adds no sync. Under encoder CUDA graphs `max_seqlen` is fixed per captured graph, so the choice is static there.
- **Why head_size 80 only.** That is where FA4 wins and real models were validated end to end. head_size 64 also wins at >= 8k (table above), but I have no long-sequence head_size-64 model to validate, so it is left out; adding it is a one-line change to `_VIT_LONG_SEQ_FA4_HEAD_SIZES`. 72 breaks even, and 96/128 are slower.
- **Threshold.** 8192 is where the synthetic sweep crosses 1.0 for head_size 80. Real activations favour FA4 more: on Qwen2-VL's actual inputs the per-call saving is ~7% vs 3.4-4.6% synthetic at the same shape. So the threshold is conservative.
- **Scope.** Only when FA3 is the default choice (SM90), FA4 is available, and `attention_config.flash_attn_version` is unset. A100, Blackwell (FA4 is already the default there), ROCm and the FP8 ViT path are unchanged.
- **CI coverage gap.** `tests/kernels/attention` runs on L4 in CI, so `test_vit_long_seq_fa4_dispatch` skips there; `test_vit_long_seq_fa_version` (selection logic) runs everywhere. The dispatch test was run on H100 as above. Happy to add it to the existing H100 attention step if reviewers want CI coverage.
