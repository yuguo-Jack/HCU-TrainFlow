# [Feature][Pooling] Add offline fixed-length late chunking

[Upstream PR](https://github.com/vllm-project/vllm/pull/60164) · state: closed · merged: True

## Original PR description

## Overview

Implements the offline A+B scope of #58774. A document is encoded once, then its contextual token states are mean-pooled into fixed-length chunk vectors through `LLM.encode(..., pooling_task="token_embed")`. Outputs include token and source-text ranges. Includes an offline example and usage documentation.

```python
from vllm import PoolingParams
from vllm.pooling_params import LateChunkingParams

# llm uses runner="pooling" and pooler_config={"task": "token_embed"}.
output = llm.encode(
    "search_document: Berlin is in Germany. It has many museums.",
    pooling_task="token_embed",
    pooling_params=PoolingParams(
        late_chunking_params=LateChunkingParams(chunk_size=8)
    ),
)[0]
vectors = output.outputs.data  # [num_chunks, embedding_dimension]
ranges = output.late_chunking.chunks
```

## Claims

- Opted-in requests average complete contextual states in FP32 before the existing token embedding head, projection, dimension selection and normalization. Tail chunks use their actual length. Ordinary token embedding requests keep their existing behavior.
- Special tokens count toward chunk boundaries and means, including BGE-M3's BOS token. Its `BOSEOSFilter` leaves chunk outputs intact and keeps filtering ordinary token outputs.
- Token IDs and offsets come from one tokenization pass. Source ranges stay in per-document frontend holders shared through `RenderParams` and offline contexts. `LateChunkingParams` sends only `chunk_size`; `PoolingEngineInput` is unchanged. Ranges are attached only to successful, complete outputs.
- No model-name whitelist. The mode requires nonempty plain text and aligned fast-tokenizer offsets. It rejects truncation, padding, renderer text normalization, token-row filtering and late-interaction scoring. `JinaForRanking` is rejected before tokenization because its custom pooler returns document/query vectors. Existing dimension checks still apply.

## Validation

Validated on an A100 80GB with PyTorch 2.13 and Transformers 5.17. GPU checks preceded the final rebase, which preserved the tested feature files. CPU regressions and pre-commit passed on the final commits.

## Details

`TokenEmbedIOProcessor` handles input validation and source mapping. The GPU reduces complete token states before the existing embedding head, which preserves projection and normalization order and avoids transferring every token vector to the frontend. The scheduler and generic rendering and tiling loops are unchanged.

Prefix caching can stay enabled, but chunk requests bypass cache reads to recompute all prompt states. Chunked prefill reuses existing hidden-state accumulation. Character ranges are zero-based, half-open Unicode code-point ranges; special-token-only chunks have `char_range=None`.

HTTP integration, the retrieval example and remaining validation for #58774 will follow in a separate PR.
