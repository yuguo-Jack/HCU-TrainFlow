# [Perf][DSv4.1] Reuse decode topk global indices across consumer layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/57659) · state: closed · merged: False

## Original PR description

## Purpose

On DeepSeek-V4.1, every compressed attention layer maps its index source's local top-k indices to global KV-cache slots on its own (`compute_global_topk_indices_and_lens`), although the indices and the block table are shared by every layer below the same index source. DSv4.1-Flash has 38 compressed layers reading 8 index sources, so one decode step launches the kernel 38 times for 8 distinct results — inside the target CUDA graph, ~2.2 µs of GPU time each (launch-bound, a few GB/s at decode shapes). A torch-profiler trace of bs=1 DSpark decode on 4×GB200 (TP4) shows 38× `_compute_global_topk_indices_and_lens_kernel` per step, 84 µs of GPU timeline.

## Change

Build the mapping once per (index source, compress ratio) and let the layers below read through (+53/−45 in `vllm/`, no kernel change):

- `DeepseekSparseSWAMetadata` gains `decode_global_topk_cache`, cleared alongside the existing per-step FlashInfer cache in `update_draft_decode_metadata`.
- `DeepseekV4Attention._decode_global_topk` fills that cache; the FlashMLA, mega-attention and FlashInfer SM120 decode paths call it instead of the kernel.
- The SM100 FlashInfer mixed sparse indices, already cached for SWA-only layers, now cache compressed layers under `c{ratio}a:{index source}` — the same shape the DSv4 backend uses (`swa_only` / `c128a`).
- Output-neutral by construction: consumers receive the very tensors the first layer of the step built.

Not a duplicate: #57434 does this for the ROCm backend only (`deepseek_v41/amd/rocm.py`, ragged form) and leaves the NVIDIA paths untouched; #49678 is the same idea for GLM-5.2 in `v1/attention/backends/mla`; #41105 (draft) fuses the mapping into the DSv4 top-k kernel and keeps the per-layer recompute. Dup checks on 2026-09-19: `topk metadata across layers`, `reuse global topk indices`, `compute_global_topk_indices_and_lens`, `57434 in:body`. Orthogonal to #55744 / #55692 (kernel bounds fixes in `deepseek_v4/`).
