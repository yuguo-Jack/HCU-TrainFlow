# [Bugfix] Step3 tool parser: coerce nullable and object/array parameters by schema

[Upstream PR](https://github.com/vllm-project/vllm/pull/65274) · state: closed · merged: True

## Original PR description



## Overview

Fixes #65273. `Step3ToolParser._cast_arguments` only coerced a parameter when its schema had a single string `type`, so nullable parameters (`Optional[int]`, `Optional[bool]`, …) and `object`/`array` parameters reached clients as raw strings. It now resolves types with the shared `extract_types_from_schema` + `coerce_to_schema_type` helpers.

Related: #64517 / #64546, fixed for the Muse, MiniCPM5, and Poolside V1 parsers in #64539.

## Claims

- Nullable parameters are coerced to their declared type, whether written as `"type": ["integer", "null"]` or `anyOf`/`oneOf` with `{"type": "null"}` (the form pydantic emits for `Optional[...]`): `"5"` → `5`, `"true"` → `True`, `"null"` → `None`.
- `object` and `array` parameters are parsed as JSON instead of being returned as strings.
- Plain `string`/`integer`/`number`/`boolean`/`null` parameters, untyped parameters, and values that cannot be coerced (e.g. `"many"` for an integer) behave as before.

## Validation

Reproduction script from #65273 (CPU only, no model download):

```
# main
{'count': 5, 'opt_count': '5', 'opt_count_list': '5', 'opt_flag': 'true', 'filters': '{"a": 1}', 'tags': '["x", "y"]'}

# this PR
{'count': 5, 'opt_count': 5, 'opt_count_list': 5, 'opt_flag': True, 'filters': {'a': 1}, 'tags': ['x', 'y']}
```

Tests: added 13 parametrized cases to `tests/tool_parsers/test_step3_tool_parser.py` covering nullable integer/number/boolean/string via `type` lists, `anyOf` and `oneOf`, plus object, array, untyped, and uncoercible values. They construct the parser with a mock tokenizer, so they need no download.

```
pytest tests/tool_parsers/test_step3_tool_parser.py
24 passed, 8 xfailed
```

The 8 xfails are pre-existing markers on this file and are unchanged. `pre-commit` passes on both changed files. Run on CPU (WSL2, Python 3.14).

## Details

**Root cause:** `_cast_arguments` read `prop.get("type")` and dispatched on it with an `if typ == "string" / "integer" / "number" / "boolean" / "null"` chain. A list `type`, an `anyOf`/`oneOf` schema, or `object`/`array` matched no branch, so the value was left as the raw string.

**Fix:** replace the chain with `coerce_to_schema_type(value.strip(), extract_types_from_schema(prop))`, the same helpers `k2_horizon_tool_parser.py` uses. They already handle type lists, `anyOf`/`oneOf`/`allOf`, enum inference, type aliases, and non-finite numbers. The now-unused `contextlib` import is removed.

**Behavior changes inherited from the shared helper** (noting for reviewers):
- Whole `number` values come back as `5` rather than `5.0`. Both are valid JSON numbers.
- `"1"` and `"0"` are accepted for `boolean` parameters, in addition to `true`/`false`.

**Not changed:** the separate issue behind this file's existing xfail markers. Non-streaming extraction only parses calls in the `<｜tool_call_begin｜>function<｜tool_sep｜>…` form. That is out of scope here.
