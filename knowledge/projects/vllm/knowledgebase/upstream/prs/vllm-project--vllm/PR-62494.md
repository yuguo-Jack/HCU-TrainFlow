# [Bugfix] Quantize Qwen3-Omni audio linears and drop the tower host sync

[Upstream PR](https://github.com/vllm-project/vllm/pull/62494) · state: open · merged: False

## Original PR description

## Overview

Quantize the Qwen3-Omni / Qwen3-ASR audio linears from the renamed checkpoint ignore list, raise when the encoder head count is not divisible by tensor parallel size, and replace the audio-tower chunk host sync with one two-vector D2H. Fixes #62356.

## Claims

- The thinker and ASR parents rename `quant_config` in place, then pass that object into `Qwen3OmniMoeAudioEncoder` and from there into `qkv_proj`, `out_proj`, `fc1`, `fc2`, `conv_out`, `proj1`, and `proj2`. Conv2d and LayerNorm stay in full precision.
- ASR ignore entries `model.multi_modal_projector.linear_1` / `linear_2` map to `audio_tower.proj1` / `audio_tower.proj2`. The dotted weight prefixes stay.
- `encoder_attention_heads % tp_size != 0` raises `ValueError` before any `QKVParallelLinear`. `disable_tp` is gone from this tower. Divisible head counts shard (`20` heads at TP 2 → 10 local heads, TP 4 → 5). An indivisible FFN still hits `divide`.
- The forward reads `(chunk_count, pad_width)` with one D2H. For positive lengths, `pad_width` is `chunk_lengths.max()` after the zero-tail rewrite. `cu_seqlens` is an int32 device cumsum that starts at 0.
- `Qwen3ASRRealtimeGeneration` and `ClefOmniForJointSchema` still call `super().__init__`.

## Validation

Unit tests are in `tests/model_executor/test_qwen3_omni_audio_encoder.py` (heads%tp raise, quant_config on linears only, ignore-list rename, pad width, int32 `cu_seqlens`). They were not executed here: `/opt/anaconda3/bin/python` is torch 2.5.1 and cannot import current vLLM. `tests/model_executor` is already collected by `.buildkite/test_areas/model_executor.yaml`.

Torch-only checks that did run (CPU, torch 2.5.1), by executing `_gather_audio_chunks` and `_audio_cu_seqlens` from the edited source plus a 3-conv bias stack (`k=3, s=2, p=1`, GELU, generator seed 0):

- Gather matches `pad_sequence` (`torch.equal`) for lengths 1, 2, 5, 100, 101, 200, and `[1, 2, 5, 50, 100, 101]`.
- Positive-length chunking: a zero remainder stays a full window (`100 → [100]`, `200 → [100, 100]`, `101 → [100, 1]`). A short batch `[1, 2, 5]` pads to 5.
- `cu_seqlens` for `[13, 26, 1, 0, 8, 9]` with window 8 is int32 `[0, 8, 13, 21, 29, 37, 39, 40, 48, 56, 57]`.
- Padding a single chunk to `n_window * 2` (100) instead of its own length changes the biased conv. Max abs error: length 1 `4.7e-3`, 2 `9.2e-3`, 5 `5.4e-4`, 50 `9.7e-3`, 100 `0`. The length-101 tail padded to 100 differs from a length-1 conv by `4.7e-3`. Mixed `[1, 2, 5]` padded to 5 vs 100 differs by `5.4e-4`.

`ruff check` and `ruff format --check` passed on the three changed files. `python -m py_compile` passed. No GPU run, so `VLLM_GPU_SYNC_CHECK` was not run. No benchmarks.

## Details

Root cause:

1. The thinker and ASR parents are not `SupportsQuant`, and `Qwen3OmniMoeAudioEncoder` was constructed without `quant_config`. `LinearBase` reads `quant_config` only at init, and Fp8 ignore matching is exact, so HF names (`thinker.audio_tower...q_proj`, bare `linear_1`) never skipped `audio_tower...qkv_proj` or `audio_tower.proj1`. The rename mapper drops stacked `q/k/v` maps, so the packed-modules update is what makes all three shards skip `qkv_proj`.
2. `disable_tp` forced TP size 1 whenever 20 heads did not divide the world size, which also replicated the FFN. `divide` would have asserted; this change raises `ValueError` with both integers before any audio linear is built.
3. The forward synchronized `chunk_num.sum()`, `chunk_lengths.tolist()`, `feature_lens_after_cnn.max()`, and `aftercnn_lens.tolist()`. Conv bias makes padding every chunk to `n_window * 2` a different result from padding to the post-rewrite max. `pad_width` is `feature_lens.clamp(max=n_window * 2).amax()` in that same D2H. A zero remainder is rewritten to a full window before the scatter, so the tail update does not boolean-index.

`window_aftercnn` still comes from `padded_mask_after_cnn.shape[-1]`, so a short batch keeps the smaller attention window. Segment lengths stay on device (`repeat_interleave` may sync internally; that call is the one the issue asks for). The other allowed sync is `padded_embed[mask]`.

Outer `_process_audio_input` (thinker mixin and ASR) runs `_get_feat_extract_output_lengths` on CPU lengths and H2Ds only the tower inputs. Qwen2.5-Omni is unchanged.

Batch data parallel is a follow-up. `supports_encoder_tp_data` stays unset.

Limitation: a zero-length feature can still alias another item's tail index (the pre-existing index update). For positive lengths, clamp-max equals `chunk_lengths.max()` after the rewrite. A trailing zero with only short neighbors can make the rewritten chunk a full window while clamp-max stays smaller (`[50, 0]` → chunks `[100]`, clamp-max `50`). This draft keeps the one D2H formula from the issue.
