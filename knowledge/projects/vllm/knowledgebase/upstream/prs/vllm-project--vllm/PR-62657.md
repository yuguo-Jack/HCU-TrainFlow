# [Bugfix][KV Connector][Mooncake] Wake sender waiters after producer cancellation

[Upstream PR](https://github.com/vllm-project/vllm/pull/62657) · state: open · merged: False

## Original PR description



## Overview

Wake existing Mooncake sender waiters when Prefill cancellation removes their producer record, so Decode receives an explicit per-request failure without waiting for the readiness timeout.

## Claims

- Cancelled or expired producer records are reported explicitly without sending stale KV.
- A waiter cannot consume a replacement record with the same transfer ID, and repeated cleanup is harmless.

## Validation

TODO

## Details

A Decode pull is already waiting on a producer's ready event when Prefill cancellation removes the record. Signal the removed event and verify record identity before constructing transfer descriptors.

Related to #46008, which also wakes cancelled waiters as part of fixing STOPPED-prefill completion. This PR isolates cancellation handling, adds explicit per-request failure reporting and record-identity protection, and includes cancellation/replacement regression coverage. #50565 and #61006 address Decode completion ownership. This PR does not handle pulls that first arrive after cancellation, change ownerless expiry, or alter sender concurrency; it is independent of #51236 and #62658. Prepared with OpenAI Codex assistance.
