# [ROCm][Perf][Kimi-K3] Mono decode kernel: port to gfx942

[Upstream PR](https://github.com/vllm-project/vllm/pull/60997) · state: open · merged: False

## Original PR description

## Purpose

Run the Kimi-K3 mono decode (#60683, gfx950-only) on gfx942 too. Builds on #60683.

The launch shape stays 256 CTAs x 512 threads. Kernels build for the device's
arch (`FLYDSL_GPU_ARCH` overrides), and the arch is now part of the build key.
gfx950 is unchanged: its ISA is byte-identical to #60683.

## Changes for gfx942

- **64 KB LDS.** The GEMVs load the token rows one K window at a time; the
  next window loads while the current one computes. The routed experts keep
  the bf16 latent in LDS (two K phases above 6 tokens, with partial sums held
  in LDS). The down projection stages its input in K slices.
- **No MXFP4 MFMA.** The routed experts read vLLM's gfx942 int4 requant of
  the experts (`--quantization-config.moe.weight int4_per_group_32`), using
  aiter's a16wi4 layout and dequant (`common/i4.py`). Activations and the
  intermediate are bf16. Without the requant, only K1 runs fused; the MoE
  takes the original path.
- **Missing instructions.** The 16x16x32 bf16 MFMA becomes two 16x16x16
  MFMAs; permlane swaps become `shuffle_xor`.
- **`mono_decode.py`.** Accepts gfx942, refuses GPUs with fewer than 256 CUs
  (e.g. CPX), and checks the expert weight layout before using the mono path.

## Test Plan

- `tests/models/kimi_k3/test_amd_mono.py`, now on gfx950 and gfx942. On
  gfx942 it builds int4 experts with vLLM's conversion. Adds K1 at 3 tokens
  and the standalone MoE at 5 and 1 tokens.
- Compile-only probe of K1 / K2 / MoE at 1–8 tokens on gfx942.
- gfx950 ISA diff against #60683 at 1, 4 and 8 tokens.

## Test Result (8x MI325X)

| Check | Result |
|---|---|
| K1 vs unfused vLLM ops (16 cases) | pass, cos ≥ 0.9999993 |
| K2 at TP8 (normal / block-write reset) | pass, cos 0.9999951, ranks identical |
| Standalone MoE at 8 / 5 / 1 tokens | pass, cos ≈ 0.999995 |
| Routed experts vs aiter `fused_moe`, 1–8 tokens | cos ≥ 0.99997 |
| gfx942 resources, 1–8 tokens | LDS ≤ 62.5 KB / 64 KB, ≤ 224 VGPRs, no spills |
| gfx950 ISA vs #60683 | byte-identical |

Not yet measured: end-to-end serving accuracy and performance with a Kimi-K3
checkpoint on gfx942.
