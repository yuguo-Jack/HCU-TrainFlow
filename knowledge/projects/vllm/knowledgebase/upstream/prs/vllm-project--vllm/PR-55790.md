# [Bugfix][Frontend] Clean up child tasks when request wrappers are cancelled

[Upstream PR](https://github.com/vllm-project/vllm/pull/55790) · state: open · merged: False

## Original PR description

## Overview

Clean up the handler and disconnect-listener tasks before an externally cancelled `with_cancellation` request wrapper exits. Both children currently remain pending when the parent is cancelled during `asyncio.wait`.

## Claims

- Cancel and await both child tasks in `finally`, including on external wrapper cancellation.
- Preserve handler results and exceptions, and upstream's empty `Response` on client disconnect.

## Validation

- `.venv/bin/python -m pytest tests/entrypoints/serve/utils/test_api_utils.py -q` — **17 passed** against this worktree, including the existing real FastAPI ASGI disconnect regression.
- Same complete test module with the unchanged main production file at `de2b869ee95e` — **1 failed, 16 passed**. The new cancellation regression detects both child tasks remaining pending after their parent exits.
- All applicable changed-file pre-commit hooks passed, including Ruff, mypy and Buildkite test tethering; `git diff --check upstream/main...HEAD` passed.

The tests use the actual source with compatible precompiled extensions. No model inference or evaluation was run: this changes request-task cleanup, with no change to prompt construction, inference, or generated output. Current upstream CI remains pending authorization; GitHub's `pre-run-check` stops before pre-commit.

## Details

The branch is rebased onto main at `de2b869ee95e`. Both the upstream disconnect-response test and the parent-cancellation test are retained. The new regression waits until both children start, cancels their parent, and checks that they finish before it exits.

Current duplicate checks found related work with different scope: #49526 fixes disconnect load accounting and awaits the handler after disconnect; #60135 adds disconnect metrics middleware. Neither handles both children's lifetime when the parent is externally cancelled.

AI assistance (OpenAI Codex) was used to investigate, implement, rebase, and validate this change.
