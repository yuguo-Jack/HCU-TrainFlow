# [Bugfix][Frontend] Clean up child tasks when request wrappers are cancelled

[Upstream PR](https://github.com/vllm-project/vllm/pull/55790) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Clean up the handler and disconnect-listener tasks before an externally cancelled `with_cancellation` wrapper exits. Both children otherwise remain pending when the parent is cancelled during `asyncio.wait`.

## Claims

- Cancel and await both children in `finally`, including on external cancellation.
- Preserve handler results and exceptions, and upstream's empty disconnect `Response`.

## Validation

- `.venv/bin/python -m pytest tests/entrypoints/serve/utils/test_api_utils.py -q`: **25 passed**, including the real FastAPI ASGI disconnect regression.
- The same complete module with the unchanged main production file at `26cc019013`: **1 failed, 24 passed**. Only the new parent-cancellation regression fails.
- Applicable changed-file pre-commit hooks and `git diff --check upstream/main...HEAD` passed.

Tests load this worktree's source with compatible precompiled extensions. No model inference or evaluation was run; the change only handles request-task cleanup.

## Details

Rebased onto main at `26cc019013`, retaining all upstream JSON-response tests and the ASGI disconnect regression. The parent-cancellation regression uses a real `Request`, waits for both children to start, and checks that both finish before the cancelled parent exits.

Current duplicate checks found related work with different scope: #49526 fixes disconnect load accounting and awaits the handler after disconnect; #60135 adds disconnect metrics middleware. Neither handles both children's lifetime when the parent is externally cancelled.
