# fix(rocm): detect AMD APU and fix VRAM reporting for unified memory

[Upstream PR](https://github.com/vllm-project/vllm/pull/40963) · state: open · merged: False

## Original PR description

## Summary

On AMD APUs with unified memory (e.g. Ryzen AI MAX+ 395 with 96 GiB UMA), `torch.cuda.mem_get_info()` returns incorrect `total` value:

```
>>> torch.cuda.mem_get_info()
(free=102891683840,   # 95.84 GiB — correct (from GTT/unified memory)
 total=16631242752)   # 15.49 GiB — WRONG (VRAM aperture, NOT actual available memory)
```

This causes vLLM to crash with OOM when allocating KV cache, because vLLM calculates cache size based on `total`.

The sysfs reports correctly:
```
/sys/class/drm/card0/device/mem_info_vram_total: 103079215104  (96 GiB)
/sys/class/drm/card0/device/mem_info_gtt_total:  103079215104  (96 GiB)
```

**Root cause**: The HIP runtime reports only the small VRAM aperture (~16 GiB) as total memory, not the full unified memory accessible to the GPU.

## Changes

- **`RocmPlatform.is_integrated_gpu()`**: Detects AMD APU by comparing HIP-reported total memory with sysfs `mem_info_vram_total`. If sysfs reports >4x more than HIP, it is an APU where HIP only sees the local aperture.
- **`RocmPlatform.mem_get_info()`**: On APU, reads true memory from sysfs `mem_info_gtt_total` / `mem_info_gtt_used` and reserves 8 GiB for system/driver overhead.

This leverages the existing UMA detection path in `MemorySnapshot` (mem_utils.py line 109-117) that already calls `current_platform.is_integrated_gpu()` — the CUDA platform implements this, but the ROCm platform did not until now.

## Test plan

- [x] Verified on AMD Ryzen AI MAX+ 395 (gfx1151) with:
  - Debian 13 (trixie), kernel 6.18.12
  - ROCm 7.13.0, PyTorch 2.8+rocm6.3
- [x] Confirmed `is_integrated_gpu()` returns `True` on APU
- [x] Confirmed `mem_get_info()` returns ~88 GiB total (96 GiB GTT minus 8 GiB reserve)
- [x] vLLM KV cache allocation succeeds without OOM
- [ ] No impact on discrete GPUs (MI300X, RX 7900 XTX) — `is_integrated_gpu()` returns `False` when sysfs VRAM matches HIP total

- vLLM already has UMA detection for NVIDIA (`CudaPlatform.is_integrated_gpu` via `torch.cuda.get_device_properties().is_integrated`)
- `MemorySnapshot` uses `current_platform.is_integrated_gpu()` + psutil for free memory on UMA (GH200, Jetson Orin)
- Strix Halo device ID `0x1586` is already registered in `_ROCM_DEVICE_ID_NAME_MAP`

## Production validation data from AMD Strix Halo (gfx1151)

We've been running vLLM on the **Ryzen AI Max+ 395** (Radeon 8060S, gfx1151, 128GB UMA) for 6 optimization sessions and can confirm the VRAM reporting problem is real and impacts production workloads.

### Our experience

On the TheRock-based vLLM Docker image (v0.22.0, ROCm 7.14), `torch.cuda.mem_get_info()` reports ~15.5 GiB total instead of the actual ~96 GiB unified memory. Without a VRAM override, vLLM refuses to allocate sufficient KV cache and either OOMs or severely underutilizes the available memory.

Our workaround is a patched `rocm.py` that overrides `mem_get_info()` to return the true UMA size (read from sysfs `mem_info_vram_total`), with a configurable system reserve. This has been stable in production:

| Metric | Value |
|--------|-------|
| Model | Qwen3.6-35B-A3B-GPTQ-Int4 (35B params, E=256 MoE) |
| Throughput | **36.7–38.3 tok/s** (sustained, 4.2% restart variance) |
| GPU mem util | 0.60 (of 96GB, ~57.6GB allocated) |
| KV cache | FP8, 2.87M token capacity at 131K max context |
| Platform | Ubuntu 24.04, kernel 7.0.9, ROCm 7.14 |
| Uptime | 6 sessions, ~130 interactions, zero OOM crashes |

### Additional issue: TheRock MagicMock stub

We also discovered a related but distinct problem: TheRock builds stub `amdsmi` with `unittest.mock.MagicMock`, which causes `get_device_name()` to return mock objects instead of strings. This breaks MoE config file resolution (the filename includes `device_name`). We submitted a separate fix for this in #44332.

### Note on @mgehre-amd's comment

> I think this was a ROCm bug that was in the nightlies for a while, but is now gone.

On the TheRock Docker builds (which many gfx1151 users rely on since there are no official ROCm packages for RDNA 3.5), the VRAM misreporting is still present as of May 2026. The fix in this PR (or a variant of it) is still needed for TheRock-based deployments. It may indeed be fixed in stock ROCm nightlies, but that doesn't cover the TheRock Docker path.

Your `is_integrated_gpu()` + sysfs approach is the right long-term fix. Our production data confirms it works correctly on Strix Halo.


- Lafunamor · comment · 2026-06-15T15:27:31Z · [source](https://github.com/vllm-project/vllm/pull/40963#issuecomment-4709524464)

Thanks for tackling this @hephaex — APU memory reporting on ROCm definitely needs a fix. One thing worth considering: since #35356 (merged Apr 13) added `Platform.is_integrated_gpu()` and made `MemorySnapshot.measure()` fall back to `psutil.virtual_memory().available` on integrated GPUs, ROCm might be able to ride that path with a much smaller change.

On Strix Halo (gfx1151, Radeon 8060S, 128 GiB) I checked what torch/HIP actually report — on both ROCm 7.2.4 stable and a recent TheRock nightly:

```
torch.cuda.get_device_properties(0).is_integrated -> 1
torch.cuda.mem_get_info(0) total                  -> 110.0 GiB   # full GTT, not a small aperture
torch.cuda.mem_get_info(0) free                   -> 93.5 GiB
psutil.virtual_memory().available                 -> 82.4 GiB    # loaded box
```

Two implications:

1. HIP populates the `integrated` device attribute and torch surfaces it as `is_integrated` (=1 here), so `RocmPlatform` can mirror `CudaPlatformBase`:
   ```python
   @classmethod
   def is_integrated_gpu(cls, device_id: int = 0) -> bool:
       return bool(torch.cuda.get_device_properties(device_id).is_integrated)
   ```
   This is robust whether HIP reports the full GTT or a small VRAM aperture as total.
2. Once `is_integrated_gpu()` is True, `MemorySnapshot.measure()` already substitutes `psutil.virtual_memory().available` for free — which is exactly the over-report at issue here (note `psutil 82.4 < hip-free 93.5`: HIP over-reports free → over-allocation/swap; cf. the closed #35313 and downstream kyuz0/amd-strix-halo-vllm-toolboxes#65). So the custom `mem_get_info` override + hardcoded 8 GiB margin may be unnecessary.

One detail on the current `sysfs_vram > hip_total * 4` heuristic: on these ROCm builds HIP already reports the full 110 GiB total, so `sysfs_vram (small carveout) > 110×4` is False — meaning the check returns False and the fix wouldn't engage where HIP reports full GTT (the common case on current ROCm). The `is_integrated` HW flag avoids that since it's not a size ratio.

(For context, these are device-attribute probes — I haven't yet built/run a vLLM image with the change.) We've proposed the same one-line `is_integrated` override for the downstream Strix Halo toolbox (kyuz0/amd-strix-halo-vllm-toolboxes#66) and would be glad to validate end-to-end on gfx1151 and report back once it's built.

The current implementation of `is_integrated_gpu` has several critical issues:
1. It ignores the `device_id` parameter and always checks the first DRM card found by `glob.glob`. In multi-GPU systems (e.g., an APU paired with a discrete GPU), this will lead to incorrect detection and subsequent memory reporting errors.
2. It should use `device_id_to_physical_device_id` to correctly map the logical torch device index to the physical DRM card number.
3. This method should be cached using `@lru_cache` to avoid repeated sysfs reads and HIP API calls, as it is frequently called during memory profiling and snapshotting.

```python
    @classmethod
    @lru_cache(maxsize=8)
    def is_integrated_gpu(cls, device_id: int = 0) -> bool:
        """Detect AMD APU (integrated GPU sharing system memory).

        On AMD APUs (e.g. Ryzen AI MAX+ 395, gfx1151), the HIP runtime
        reports a small VRAM aperture as total memory via hipMemGetInfo,
        even though the GPU can access much more through unified memory.
        We detect this by comparing HIP-reported total with the sysfs
        VRAM total reported by the amdgpu kernel driver.
        """
        try:
            physical_id = cls.device_id_to_physical_device_id(device_id)
            vram_path = f"/sys/class/drm/card{physical_id}/device/mem_info_vram_total"
            if not os.path.exists(vram_path):
                return False
            with open(vram_path, 'r') as f:
                sysfs_vram = int(f.read().strip())
            _, hip_total = torch.cuda.mem_get_info(device_id)
            # If sysfs reports >4x more VRAM than HIP, this is an APU
            # where HIP only sees the small local VRAM aperture
            return sysfs_vram > hip_total * 4
        except Exception:
            return False
```

In `mem_get_info`, the call to `is_integrated_gpu()` lacks the `device_id` argument, causing it to always default to device 0. Furthermore, the use of `glob.glob` and `drm_cards[0]` again ignores the specific device being queried. This will cause incorrect memory reporting on multi-GPU systems. The logic should resolve the `device` parameter to a logical index and then use the corresponding physical ID for sysfs access. Additionally, `safe_total` should be clamped to 0 to prevent negative values on systems with very low memory.

```python
        # Resolve device index
        if device is None:
            device_id = torch.cuda.current_device()
        elif isinstance(device, int):
            device_id = device
        elif isinstance(device, torch.device):
            device_id = device.index or torch.cuda.current_device()
        else:
            device_id = 0

        if cls.is_integrated_gpu(device_id):
            try:
                physical_id = cls.device_id_to_physical_device_id(device_id)
                card_dir = f"/sys/class/drm/card{physical_id}/device"
                gtt_total_path = os.path.join(card_dir, 'mem_info_gtt_total')
                gtt_used_path = os.path.join(card_dir, 'mem_info_gtt_used')
                
                if os.path.exists(gtt_total_path) and os.path.exists(gtt_used_path):
                    with open(gtt_total_path, 'r') as f:
                        gtt_total = int(f.read().strip())
                    with open(gtt_used_path, 'r') as f:
                        gtt_used = int(f.read().strip())
                    # Reserve 8 GiB for system/driver overhead
                    safe_total = max(0, gtt_total - (8 * 1024**3))
                    safe_free = max(0, safe_total - gtt_used)
                    logger.info_once(
                        "AMD APU detected: using sysfs GTT memory "
                        "(total=%.1f GiB, free=%.1f GiB) instead of "
                        "HIP-reported VRAM aperture (%.1f GiB).",
                        safe_total / (1024**3),
                        safe_free / (1024**3),
                        total / (1024**3),
                    )
                    return int(safe_free), int(safe_total)
            except Exception:
                pass
```
