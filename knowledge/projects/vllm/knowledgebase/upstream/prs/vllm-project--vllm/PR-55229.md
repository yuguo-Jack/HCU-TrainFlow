# [Bugfix][DP] Make duplicate scheduler resume idempotent

[Upstream PR](https://github.com/vllm-project/vllm/pull/55229) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Make repeated data-parallel scheduler resumes safe by deciding collective participation from the shared pause-consensus state.

## Claims

- Already-running ranks skip duplicate resumes even when request-wave messages arrive at different times.
- Paused ranks and newly joined Elastic EP ranks still participate in the resume collective.

## Validation

The CPU resume regressions and scoped pre-commit hooks pass after the rebase. Duplicate resumes, paused ranks, newly joined ranks, and in-flight pause rejection were checked.

An earlier two-process Gloo reproduction timed out with the original condition when wave messages arrived at different times. It used production collective methods with scheduler/model boundaries replaced. That reproduction was not repeated after this rebase.

To run the related suites in a configured development environment:

```sh
.venv/bin/python -m pytest tests/v1/distributed
```

GPU DP model-serving validation is still needed.

Upstream checks are stopped at contributor authorization; these local results do not establish a CI pass.

## Details

`engines_running` can differ between ranks because wave messages arrive independently. `ignore_start_dp_wave` changes through pause consensus, so ranks agree on whether to enter the resume collective. The change follows the [review feedback](https://github.com/vllm-project/vllm/pull/55229#discussion_r4170893423).

#59559 handles wakeup announcements and is complementary to this duplicate-resume fix.

AI assistance was used for this change.
