# [Bugfix][Security] Account for peak GPU usage in PyNvVideoCodec pool lease

[Upstream PR](https://github.com/vllm-project/vllm/pull/52605) · state: open · merged: False

## Original PR description

The PyNvVideoCodec decode path charged only one RGB batch (B = F*H*W*3) against the frontend GPU memory pool, but during the lease up to three batch-sized GPU allocations are simultaneously live: native DLPack frames, the torch.stack result, and the contiguous NHWC tensor from permute().contiguous(). This allowed a request to pass admission while its real transient GPU usage exceeded the reserved pool budget by ~2-3x.

Apply a 3x multiplier to the pool lease to cover the measured peak transient GPU allocation, preventing CUDA OOM from requests that fit within the raw-frame budget but exceed actual device headroom.
