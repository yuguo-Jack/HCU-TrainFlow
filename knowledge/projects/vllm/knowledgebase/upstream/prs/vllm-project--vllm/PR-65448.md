# [KV Connector][Spec Decode] Support lookahead block hashes in remaining KV connectors

[Upstream PR](https://github.com/vllm-project/vllm/pull/65448) · state: open · merged: False

## Original PR description

## Purpose

Follow-up to #64096, which made block hashes cover the next `num_hash_lookahead_tokens` (L) tokens for EAGLE, EAGLE3 and MTP. With these hashes a prefix hit also proves the draft KV at the block boundary can be reused. Connectors that did not declare `supports_lookahead_block_hashes` still fell back to L=0 and the legacy EAGLE trailing-block drop.

This PR finishes the migration. It adapts the two connectors whose own reuse paths still dropped the block (UMBP and HiSparse), then removes the capability check, so lookahead hashes apply to every connector. A separate commit fixes two cache bounds that ignored a hash lookahead above one (multi-module MTP).

## Implementation

- **Every connector gets lookahead.** Core never asked a connector whether it supported the drop: it dropped on its own local hits, and each connector handled its own reuse. Lookahead now works the same way. `supports_lookahead_block_hashes` is removed from the base class, every override and the MultiConnector. L resolves whenever a KV connector is configured, even with core prefix caching off. `disable_lookahead_block_hashes` still selects the legacy drop.
- **UMBP** had copied core's drop into its lookup, hit trimming and store mask. It now uses core's L instead and caps lookups at hashed blocks. A block's hash appears only once L more tokens exist, so the last computed block may get its hash only when the final token is sampled. At request finish, UMBP therefore saves that KV and pins it until the store completes. It does this only for requests that scheduled compute, so a pending load is never saved. KV events carry the lookahead token IDs.
- **HiSparse** builds its own host block pool, which now takes the device pool's L. On finish or cancel, publication stops at pages that have a hash (the same bound as core's `cache_blocks`).
- **MoRIIO** transfers the request's own KV, so the transfer path is unaffected. When a hybrid producer truncates its last prompt token, it now also truncates the hashes that depend on that token, as NIXL does.
- **Builtin LMCache MP fallback** bounded stores and retrieves by the number of hashes. With L>0, hashes lag the tokens, so the assert fired when `N % chunk_size < L`. Both bounds now use full token blocks, the same range as before.

**Multi-module MTP bounds** (separate commit; L = 1 paths are unchanged):

- **Retention boundary.** A resend of an N-token prompt reaches at most N − L tokens, but sparse retention kept SWA and Mamba state for N − 1. With 16-token blocks, L = 3 and 66 tokens, the resend hit 0 tokens instead of 48. `replay_boundaries()` now takes L, and core, Mooncake store, UMBP and Offloading pass it.
- **Re-prefilled draft KV.** Multi-module MTP rewrites the drafter's KV for the last k − 1 tokens of each chunk. The hybrid coordinator excluded those tokens only in the legacy drop branch, so draft groups published KV that was about to be rewritten. Draft groups now cache only finalized tokens; target attention and Mamba state still cache to the chunk end.

### Connector support

P/D connectors count as supporting the drop: they move KV computed for the same request, and cross-request reuse happens only in each endpoint's local prefix cache, which follows core. Example, HF3FS, LMCache and FlexKV never supported the drop on main. They key their caches by token IDs and report how many tokens they hold, and core loads that whole hit without dropping its last block. This PR keeps that scope, and only their core local hits switch from drop to lookahead.

| Connector | EAGLE block drop on main | After this PR |
|---|---|---|
| Nixl, Mooncake, MoRIIO (P/D) | ✅ No extra drop needed | ✅ Lookahead (MoRIIO trims hashes on truncation) |
| MooncakeStore, Offloading, SimpleCPUOffload | ✅ Drop on external hits | ✅ Lookahead (since #64096) |
| UMBPStore | ✅ Drop in lookup, hit trimming and store mask | ✅ Lookahead (this PR) |
| HiSparse | ✅ Drop through the host `FullAttentionManager` | ✅ Lookahead (this PR) |
| Example, HF3FS, LMCacheV1, LMCacheMP, FlexKV | ❌ No drop on external hits: the connector matches by token IDs and reports its whole hit, and core loads it without dropping the last block. The draft KV at that block's boundary may come from a different continuation, which lowers acceptance but not output quality | Unchanged (token-keyed) |
| DecodeBench, ExampleHiddenStates | N/A: dummy KV or no external hits | N/A |
| MultiConnector | Any child without the capability forced the drop for all children | Lookahead for all children |

**Compatibility:** with EAGLE, EAGLE3 and MTP, out-of-tree connectors now receive lookahead hashes, so `request.block_hashes` may have fewer entries than full token blocks.

## Validation

**Accuracy and acceptance:** LongBench v2 `short` subset (about 15k–60k tokens), temperature 0.
