# [XPU]Fix the accuracy issue when meet topk_ids=-1 on DP+EP scenarios

[Upstream PR](https://github.com/vllm-project/vllm/pull/57787) · state: closed · merged: True

## Original PR description

When running MoE models with DP + EP, dummy/padded tokens are marked with topk_ids = -1 (e.g. from dummy batches executed by an idle DP rank). Under EP, the dispatch all-gathers these -1 entries to every rank's fused MoE kernel.
The XPU MoE kernel uses topk_ids directly as indices, so -1 causes an out-of-bounds read (undefined behavior). This corrupts not only the dummy rows but also real tokens' outputs, producing nondeterministic results and occasional NaN, which then spreads to all ranks through the EP combine.
The error found in the UT v1/distributed/test_external_lb_dp.py::test_external_lb_completion_streaming[api-1-ep-enabled-ibm-research/PowerMoE-3b] can be seen below:
        # Check that the combined text matches the non-streamed version.
>       assert "".join(chunks) == single_output, (
            "Streamed output should match non-streamed output."
        )
E       AssertionError: Streamed output should match non-streamed output.
E       assert ' (-RelatedRelated BR' == ' Share ( JavaScript CloseAn'
E
E         -  Share ( JavaScript CloseAn
E         +  (-RelatedRelated BR

The same judgement also occurs on other platforms like DeepEP HT
https://github.com/vllm-project/vllm/blob/main/vllm/model_executor/layers/fused_moe/prepare_finalize/deepep_ht.py#L225
to avoid lead topk_ids=-1 to do the calculation.
