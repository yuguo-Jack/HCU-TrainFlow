# [Bugfix][InternVL] Stop the video parser consuming image_embeds

[Upstream PR](https://github.com/vllm-project/vllm/pull/55779) · state: closed · merged: True

## Original PR description

## Purpose

`InternVLChatModel._parse_and_validate_video_input` pops `image_embeds`:

```python
video_embeds = kwargs.pop("image_embeds", None)
```

`image_embeds` belongs to the image modality. When a request carries image
embeddings and a video together, the video parser reads those embeddings, matches
the `video_embeds is not None` branch, and returns early with
`InternVLVideoEmbeddingInputs` wrapping the image data. The video is never
processed, and the caller gets image embeddings under the video modality with no
error.

Both inputs are reachable at once: `image_embeds` and `pixel_values_flat_video`
are declared fields, and `_parse_and_validate_multimodal_inputs` dispatches to the
image and video parsers from the same kwargs, so whichever key appears first in
the request does not stop the other branch running.

Pop `video_embeds` instead, which is the key the video modality owns.

This does not add video-embedding support to InternVL. `video_embeds` is not in
`_get_video_fields_config`, so the branch stays inert; supporting it needs
`get_video_repl` to accept `num_patches=None` the way `get_image_repl` already
does, plus a frame count derived from the embedding shape. That is a separate
change.
