# [Perf] Optimize packed encoder FlexAttention masks

[Upstream PR](https://github.com/vllm-project/vllm/pull/62236) · state: open · merged: False

## Original PR description



## Overview

Add a guarded Triton span builder for packed bidirectional encoder masks in FlexAttention. On supported CUDA/ROCm systems, use 64-token blocks and derive block rows from request spans instead of the generic compiled mask builder.

## Claims

- The new path covers packed global encoder masks when attention is noncausal, nonpaged, and uses the default logical mask. Local-window and unsupported mask features continue through the generic builder.
- The 64x64 default is limited to CUDA-alike platforms with Triton and PyTorch 2.9 or newer. Older PyTorch versions, TPU, and other platforms keep the generic 128x128 encoder default; explicit block-size settings still take precedence.
- On an RTX 3080, GTE ModernBERT end-to-end embedding latency improved in all three paired runs for both evaluated 8,192-token profiles. The local measurements are preliminary because they used a vLLM 0.31.0 native-extension wheel with the exact current-main and candidate FlexAttention Python sources overlaid.

### GTE ModernBERT end-to-end results

Model: `Alibaba-NLP/gte-modernbert-base` (`ModernBertModel`), FP16 pooling embeddings, eager `FLEX_ATTENTION`, four warmups and 15 timed repetitions per variant. Each profile contains 8,192 tokens. Baseline is the unmodified current-main source at `7879f3687b5b6a4be4754242e70b9c21cf7b4183`, using 128x128 generic blocks; candidate uses the span builder with 64x64 blocks. Runs were paired in randomized order on the same GPU.

| Profile | Baseline p50 (ms), 3 pairs | Candidate p50 (ms), 3 pairs | Geometric-mean speedup | Minimum embedding cosine |
| --- | --- | --- | ---: | ---: |
| 4 x 2,048 tokens | 72.975, 72.522, 80.563 | 71.600, 66.724, 66.680 | 1.102x | 0.9999989 |
| Irregular 512/768/1,024/1,536/2,048/2,304 | 96.469, 83.487, 98.227 | 84.839, 82.519, 87.913 | 1.087x | 0.9999945 |

The maximum absolute embedding delta was 0.03125 in both profiles. These measurements are local evidence, not a multi-GPU claim. The installed environment used PyTorch 2.13.0+cu132, vLLM 0.31.0 native extensions, and an NVIDIA GeForce RTX 3080 (10 GiB, driver 580.178.04); the Python FlexAttention module was switched between the exact current-main source and this candidate. A clean source installation and a second-GPU check remain independent follow-ups. See the [benchmark script](benchmarks/kernels/benchmark_flex_attention_encoder.py) to reproduce the local measurements.

The benchmark's reference comparison rejects non-finite reference or candidate embeddings and non-finite computed metrics.

## Details

The generic encoder path calls `create_block_mask_compiled` over the packed token layout. Encoder metadata already contains request start offsets and persistent request IDs, so the new Triton kernel can construct each query row's KV block lists directly. It marks blocks fully visible to every query separately from boundary blocks that still need the exact mask function. Row capacities are based on the model sequence limit, and each row writes a `-1` sentinel after its live entries for FlexAttention's one-past-row prefetch. The existing generic builder remains the fallback.

The new kernel is 189 lines and the production additions total about 239 lines, within the PR checklist's medium-complexity range. It is isolated in a helper module and is limited to the target global encoder pattern. Dispatch excludes causal/paged attention, local sliding windows, multimodal prefixes, block-sparsity hints, RSWA masks, custom logical masks, empty batches, unsupported devices, and PyTorch versions below 2.9. The fast path adds no device-to-host reads or explicit synchronization. TPU intentionally uses the unchanged generic path; this change makes no TPU performance claim.
