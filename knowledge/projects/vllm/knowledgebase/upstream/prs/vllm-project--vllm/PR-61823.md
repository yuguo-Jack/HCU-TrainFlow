# [Kernel][Perf] Tune small packed GDN decode shapes on SM89

[Upstream PR](https://github.com/vllm-project/vllm/pull/61823) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Use BV4 for small packed GDN decode shapes on SM89 with BF16 QKV and FP32 state, following the [request for a concise heuristic](https://github.com/vllm-project/vllm/pull/60403#issuecomment-6187342188). This tunes existing Triton dispatch; #60403's FlashInfer integration is separate, not duplicated here.

## Claims

- The rule selects BV4 for K=V=128, QK normalization enabled and B×Hv≤64. Other SM89 paths retain BV32; SM100 dispatch and kernel arithmetic are unchanged.
- Earlier L20 cold-cache measurements show **18.5% lower kernel latency** across 30 selected shapes (geometric mean). The new full-main FP8 TP2 run shows only **~0.3% higher throughput at C1/C2**, with no general serving-speedup claim.

## Validation

Rebased onto main `3ddc6702` as `ace90f5d`. [Full-main results, raw requests and reproduction](https://github.com/positive666/vllm/tree/db8bbea532270205d8beb992d4c2900dd0dee10f/sm89-full-main-fp8-20261019).

Two L20s, a pinned block-FP8 27B checkpoint (`Qwen3_5ForConditionalGeneration`), Marlin FP8 weights/BF16 computation, FP32 SSM state, Torch 2.14.0+cu130/Triton 3.8.0. Complete baseline/candidate source trees use identical `dd9e07a25` native artifacts; the two intervening commits do not change native build inputs. The model's local directory label is not treated as an official revision; file hashes identify the checkpoint.

A/B/B/A fresh starts, CUDA Graph enabled, 512 input/128 forced output tokens, three rounds × 16 requests per concurrency/start after warmup. **576/576 measured requests succeeded.**

| Concurrency | Output tok/s, base → candidate | Change | TPOT p50 ms, base → candidate | Change |
|---|---:|---:|---:|---:|
| 1 | 44.678 → 44.808 | +0.29% | 21.177 → 21.116 | −0.29% |
| 2 | 78.724 → 78.958 | +0.30% | 23.390 → 23.312 | −0.33% |
| 8 | 228.602 → 228.539 | −0.03% | 27.351 → 27.902 | +2.01% |

These are medians across rounds/starts, not significance estimates. C8 round TPOT medians vary approximately 27.3–28.5 ms in both arms; the aggregate increase is retained above. Full per-run ranges are linked.

- GPU reference suite: **20 passed, no skips**. Actual-wrapper checks: **78 shapes bit-exact**; **six cases × 128 changing-input graph steps** bit-exact, with padding/state checks.
- Arithmetic smoke: **16/16 per start, no truncation**; not a full accuracy evaluation. Model texts vary even across identical-baseline restarts, so no model-level bit-exactness claim.
- Separate profiles confirm BV4 at B1/B2, BV32 at B4/B8, and matching Marlin backends on both ranks. C1 target-kernel median is about **5.12 → 3.65 µs**. Profiling is excluded from serving timings.
- Ruff, formatting and applicable pre-commit hooks passed locally. L20 validation exercises the SM89 branch that B200/MI355 CI does not cover.

Recorded commands: `python -m pytest tests/kernels/fla/test_fused_recurrent_packed_decode.py -v`, `run_fp8_tp2.py`, `run_fp8_tp2.py --diagnostic`, and `wrapper_exact.py`, all executed through `uv` with the isolated venv; exact commands and flags are in the linked README.

[Earlier cold-cache/BF16 dataset](https://github.com/positive666/vllm/tree/eb1db5676107c847cbc90f96309f96fb0e799f67/sm89-heuristic-20261015): Torch 2.13/cu129, Triton 3.7.1, exact decode modules with vLLM 0.27.1 runtime dependencies. Its 18.5% kernel result is separate from this full-main serving run.

## Details

Smaller V tiles increase CTA parallelism at small B×Hv. BF16-state gains were inconsistent, so that path remains unchanged. The patch adds 11 dispatch lines and three boundary cases to the existing test. Only L20 has been measured; no SM90 or other-SM89 performance claim. The serving benefit is small and C8 latency neutrality is not established.

AI assistance was used for implementation, validation and analysis.
