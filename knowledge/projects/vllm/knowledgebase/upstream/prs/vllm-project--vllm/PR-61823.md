# [Kernel][Perf] Tune small packed GDN decode shapes on SM89

[Upstream PR](https://github.com/vllm-project/vllm/pull/61823) · state: open · merged: False

## Original PR description

## Overview

Select BV4 for small packed GDN decode on SM89 with BF16 QKV, FP32 state, K=V=128, QK normalization enabled and B×Hv≤64. This follows the [request for a concise heuristic](https://github.com/vllm-project/vllm/pull/60403#issuecomment-6187342188). Smaller V tiles increase CTA parallelism; larger shapes keep BV32.

## Claims

- Earlier L20 cold-cache measurements show **18.5% lower kernel latency** across 30 selected shapes (geometric mean).
- The full-main FP8 TP2 serving run shows only **~0.3% more throughput at C1/C2**. C8 TPOT p50 increases **2.01%**; latency neutrality and a material general serving speedup are not established.
- This is a narrow dispatch change. Kernel arithmetic, BF16-state selection and the existing SM90/SM100 rules are preserved.

## Validation

**Rebase check, November 3:** rebased onto `43b8d057` as `fc8857d8`, preserving the merged SM90 rule from #63864. The original 14 added lines are unchanged. Both arms passed **22 GPU reference tests**, with no skips. These ran in the pinned `190df0b9` Torch 2.14.0+cu130/Triton 3.8.0 runtime; the modified modules/tests, FLA helpers, platform/Triton utilities and dependency inputs are unchanged between those two main revisions. Source files match the tested files after CRLF normalization. Applicable pre-commit checks passed. This is correctness validation, not a new E2E run.

**Serving results, October 19:** main `3ddc6702`, candidate `ace90f5d`, two L20s, pinned block-FP8 27B checkpoint (`Qwen3_5ForConditionalGeneration`), Marlin weights/BF16 computation and FP32 SSM state. A/B/B/A fresh services, CUDA Graphs, 512 input/128 forced output tokens; three rounds ×16 requests per concurrency/start. **576/576 measured requests succeeded.**

| Concurrency | Output tok/s, baseline → candidate | Change | TPOT p50 ms, baseline → candidate | Change |
| --- | ---: | ---: | ---: | ---: |
| 1 | 44.678 → 44.808 | +0.29% | 21.177 → 21.116 | −0.29% |
| 2 | 78.724 → 78.958 | +0.30% | 23.390 → 23.312 | −0.33% |
| 8 | 228.602 → 228.539 | −0.03% | 27.351 → 27.902 | +2.01% |

These are descriptive medians across two starts per arm, not significance estimates. C8 per-round TPOT medians span approximately 27.3–28.5 ms in both arms. The aggregate increase is retained above.

- The October run passed 20 reference tests, 78 bit-exact wrapper cases and six cases ×128 changing-input graph steps, including padded/inactive state checks.
- Every service start scored 16/16 on the arithmetic smoke screen, without truncation. This is not a full accuracy evaluation. Text varies even between identical-baseline restarts; no model-level bit-exactness claim.
- Separate profiles confirmed BV4 at B1/B2, BV32 at B4/B8 and matching Marlin backends on both ranks. Profiling was excluded from serving timing.

[October raw requests, source/runtime identities and reproduction](https://github.com/positive666/vllm/tree/db8bbea532270205d8beb992d4c2900dd0dee10f/sm89-full-main-fp8-20261019). The local model directory name is not an official revision; checkpoint hashes identify it. The [earlier 18.5% kernel dataset](https://github.com/positive666/vllm/tree/eb1db5676107c847cbc90f96309f96fb0e799f67/sm89-heuristic-20261015) uses its own older runtime and is separate from the FP8 TP2 results.

Run the existing regression suite in the prepared environment:

```bash
uv run --offline --no-project --python .venv/bin/python \
  .venv/bin/python -m pytest \
  tests/kernels/fla/test_fused_recurrent_packed_decode.py -v
```

The bounded GPU replay used the same candidate test file in both arms with `--confcutdir=/inputs -p no:cacheprovider`; only the production dispatch file differed. The linked October README records the serving, diagnostic and wrapper-exact commands.

## Details

The patch adds 11 dispatch lines and three threshold cases to the existing test. Only L20 has been measured; no other-SM89 or SM90 performance claim. The SM90 tuning in merged #63864 targets a different architecture and is retained; #60403 adds a separate FlashInfer backend. This PR neither replaces those changes nor duplicates their execution paths.

AI assistance was used for implementation, debugging and validation. The human submitter reviewed the changed lines and personally ran the rebase regression.
