# [Bugfix][Distributed] Gate FlashInfer all-reduce on 16-byte row widths 

[Upstream PR](https://github.com/vllm-project/vllm/pull/63123) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

FlashInfer's fused all-reduce cannot run every tensor shape and [`should_use_fi_ar`](https://github.com/vllm-project/vllm/blob/ef5bcaa387632c9943f1e1cd0716354d75b99285/vllm/distributed/device_communicators/flashinfer_all_reduce.py#L469) checks all the kernel requirements. However, this is not complete as it never validated row width, so a tensor whose row is not a whole number of 16-byte vectors passed the gate and reached a kernel that cannot run it. On the MNNVL backend this kills the worker; on the trtllm backend, which has no equivalent assert, it truncates its indexing and silently returns wrong results. This PR adds the missing check so these reductions fall back to NCCL.

Mamba2 with `mamba_n_groups=1` hits this at TP>1 (see [`mamba_mixer2.py:144`](https://github.com/vllm-project/vllm/blob/87b804f09d698bdcc5dc53062d2058d7faad08ca/vllm/model_executor/layers/mamba/mamba_mixer2.py#L144)). Since https://github.com/vllm-project/vllm/pull/52998 made `VLLM_ALLREDUCE_USE_FLASHINFER` default to on, hybrid models using Mamba2 layers such as `ibm-granite/granite-4.0-h-tiny` cannot start out of the box.

To reproduce on `main`:

```
vllm serve ibm-granite/granite-4.0-h-tiny \
  --tensor-parallel-size 2 --max-model-len 1024 --trust-remote-code
```

fails to start on main (49dbf7c44f8157285db653fbe789daa30df6cfc4) with the following message:

```
(EngineCore pid=2676902) ERROR 10-20 09:35:05 [core.py:1545] RuntimeError: Worker failed with error 'Check failed: token_dim % (sizeof(float4) / sizeof(c_type)) == 0 (1 vs. 0) : token_dim must be divisible by 4', please check the stack trace above for the root cause
(EngineCore pid=2676902) ERROR 10-20 09:35:09 [multiproc_executor.py:315] Worker proc VllmWorker-0 died unexpectedly (exit code: None), shutting down executor.
```

However, it starts correctly with the VLLM_ALLREDUCE_USE_FLASHINFER disabled:

```
VLLM_ALLREDUCE_USE_FLASHINFER=0 \
  vllm serve ibm-granite/granite-4.0-h-tiny \
  --tensor-parallel-size 2 --max-model-len 1024 --trust-remote-code
```

CC: @njhill @tdoublep @jeejeelee 

## Claims

- Granite-4 (and any Mamba2 model with `n_groups == 1`) starts at TP>1 with the default FlashInfer all-reduce, instead of dying in `determine_available_memory`.
- Closes a silent-correctness hole on the trtllm backend, which vectorizes the same way but validates nothing.
- Pure gating change: shapes the kernel already accepted take exactly the same path as before. Only shapes that previously crashed now fall back.

## Validation

- **End-to-end.** On main, the serve command above does not start unless FlashInfer all-reduce is disabled:

```
VLLM_ALLREDUCE_USE_FLASHINFER=0 \
  vllm serve ibm-granite/granite-4.0-h-tiny \
  --tensor-parallel-size 2 --max-model-len 1024 --trust-remote-code
```

starts as expected. With this PR, the same command *without* the env var starts and serves.

Both the failure and the fix were exercised on the default `auto` backend, which resolves to mnnvl on this 8x H100 box. Similar results for a 2x GB200.

- **Unit test.** `tests/distributed/test_flashinfer_all_reduce.py` covers the shape/dtype combinations the gate has to separate:

```bash
pytest tests/distributed/test_flashinfer_all_reduce.py -v
```

| shape | dtype | row bytes | accepted |
|---|---|---|---|
| `(16, 1)` | fp32 | 4 | no |
| `(16, 2)` | fp32 | 8 | no |
| `(16, 1)` | bf16 | 2 | no |
| `(16, 4)` | bf16 | 8 | no |
| `(16, 4)` | fp32 | 16 | yes |
| `(16, 8)` | bf16 | 16 | yes |
| `(16, 4096)` | bf16 | 8192 | yes |

The change only diverts shapes that previously aborted the worker onto the NCCL path, which is the default reduction when the FlashInfer all-reduce is off. Shapes the kernel already accepted are unaffected, so there is no numerical delta to measure.

## Details

### Root cause

FlashInfer's fused all-reduce kernels load each token row as a `float4`, so a row must be a whole number of 16-byte vectors. The MNNVL kernel enforces this with a throwing TVM FFI `ICHECK` ([`trtllm_mnnvl_allreduce.cu:59-60`](https://github.com/flashinfer-ai/flashinfer/blob/main/csrc/trtllm_mnnvl_allreduce.cu#L59-L60)):

```cpp
TVM_FFI_ICHECK_EQ(token_dim % (sizeof(float4) / sizeof(c_type)), 0)
    << "token_dim must be divisible by " << sizeof(float4) / sizeof(c_type);
```

The divisor is dtype-dependent — 4 for fp32, 8 for fp16/bf16 — so the observed "token_dim must be divisible by 4" is the fp32 instantiation of the general rule, not a fixed bound. The trtllm path vectorizes the same way (`reinterpret_cast<float4*>` indexed as `hidden_dim / VEC_SIZE`) but carries no equivalent assert, so an undersized dim there truncates its indexing instead of aborting.

`should_use_fi_ar` validated device, rank, contiguity, dtype and workspace capacity, but never row width. A narrow tensor therefore passed the gate and the throwing assert killed the worker instead of the communicator falling back to NCCL.

Mamba2 with `mamba_n_groups=1` hits this at TP>1. The gated RMSNorm parallelizes over the reduction dim and all-reduces an fp32 `(num_tokens, 1)` partial sum ([`mamba_mixer2.py:143-144`](https://github.com/vllm-project/vllm/blob/49dbf7c44f8157285db653fbe789daa30df6cfc4/vllm/model_executor/layers/mamba/mamba_mixer2.py#L143-L144)):

```python
local_sums = x.pow(2).sum(dim=-1, keepdim=True)
global_sums = tensor_model_parallel_all_reduce(local_sums)
```

A row of one fp32 is 4 bytes, so the kernel rejects it and the engine dies inside `determine_available_memory`.

### Why nobody hit this earlier

Both halves predate the user-visible breakage:

| when | what | PR |
|---|---|---|
| 2025-02-22 | `n_groups == 1` TP all-reduce added to `Mixer2RMSNormGated` | #13660 |
| 2026-02-26 | `should_use_fi_ar` reaches current form, no row-width check | #34109 |
| 2026-08-20 | `VLLM_ALLREDUCE_USE_FLASHINFER` flipped `0` → `1` | #52998 |

The narrow shape and the unvalidated gate coexisted for ~6 months, reachable only by users who explicitly opted in. #52998 exposed the bug rather than creating it.

### Why gate, rather than fix the caller

A caller-side flatten in `mamba_mixer2.py` would be smaller, and there is precedent for it — see #44983 below. Two reasons to prefer the gate:

- **It is not Mamba2's bug.** Any caller reducing a narrow fp32 tensor hits the same kernel constraint. The gate's job is to decide which shapes the kernel can run, and it was answering that question incompletely.
- **The trtllm path needs it regardless.** A caller-side fix for Granite leaves these shapes silently corrupting results on the backend with no assert.

A `try`/`except` fallback would be worse than either: a rank that catches the assert and falls back while its peers proceed deadlocks the collective. The fix has to be a deterministic predicate that all ranks evaluate identically.

### Relation to MiniMax, #44983

MiniMax has a structurally identical reduction — a per-token fp32 variance all-reduced across TP inside an RMSNorm — and https://github.com/vllm-project/vllm/pull/44983 fixed it caller-side by flattening before the reduction ([`rms_norm_tp.py:41`](https://github.com/vllm-project/vllm/blob/49dbf7c44f8157285db653fbe789daa30df6cfc4/vllm/model_executor/layers/minimax_rms_norm/rms_norm_tp.py#L41)), relying on the `len(shape) != 2` check in `should_use_fi_ar` to keep 1-D inputs off the FlashInfer path.


## Not a duplicate

Checked per `AGENTS.md`:

```bash
gh pr list --repo vllm-project/vllm --state open --search "flashinfer all reduce"
gh pr list --repo vllm-project/vllm --state open --search "should_use_fi_ar"
```

No open PR adds a row-alignment check, so this is not a duplicate. Three open PRs are nearby, and two touch the same file:

- **#55973** — fixes FlashInfer fused all-reduce when NVLink multicast is unavailable. Same file, but entirely inside `get_fi_ar_workspace` (it caches unsupported workspace configurations and bails out during CUDA graph capture).
  It does not touch `should_use_fi_ar`. Complementary rather than overlapping: it makes workspace *creation* failures survivable, this makes a *shape* the kernel rejects survivable.
- **#53852** — honours an explicit FlashInfer size override on H200. Same file, and it rewrites the `max_workspace_size` assignment in `__init__` immediately above this change. Textually adjacent, semantically independent (it decides *how big* the workspace is, this decides *which shapes* are eligible), but expect a trivial rebase if it merges first.
- **#60011** — makes `--disable-custom-all-reduce` fall back to NCCL. A different switch, does not touch this file, and does not address shapes the kernel rejects.
