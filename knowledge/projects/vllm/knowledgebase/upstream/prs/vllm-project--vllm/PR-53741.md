# [ModelOpt] Support fused MoE weight reload

[Upstream PR](https://github.com/vllm-project/vllm/pull/53741) · state: open · merged: False

## Original PR description

## Purpose

Refs #53687.

The native MoE checkpoint loader currently reaches fused ModelOpt NVFP4 parameters through per-expert, per-projection checkpoint records. For the Qwen3-30B-A3B example in #53687, that requires:

```text
42 layers * 128 experts * 3 projections * 4 tensor kinds = 64,512 records
```

This PR adds an opt-in, layer-fused loading contract so an online quantizer can instead provide the eight complete pre-kernel tensors owned by each `RoutedExperts` layer:

- `w13_{weight,weight_scale,weight_scale_2,input_scale}`
- `w2_{weight,weight_scale,weight_scale_2,input_scale}`

That reduces the example above to `42 * 8 = 336` loader records without bypassing vLLM's reload lifecycle.

Specifically, this PR:

- adds `FusedMoEParameterLoadSpec`, through which a quantization method declares each accepted checkpoint name, destination parameter, exact shape, dtype, sharding, and scale domain;
- makes the default contract empty, so existing quantization methods retain the current per-expert path;
- opts ModelOpt NVFP4 into the contract for its eight layer-local tensors;
- copies complete tensors directly into their existing parameter storage;
- rejects duplicate, incomplete, mixed-granularity, shape-mismatched, and dtype-mismatched bundles;
- keeps normal layerwise accounting and post-load processing intact.

The fused input must already match the destination layout declared by the layer on the current rank. TP, EP, EPLB, padding, and backend-specific layout decisions remain vLLM responsibilities. The legacy expert-name mapping remains the fallback and is built lazily only when that path is used.

This does not duplicate an existing PR. Searches for #53687 and for fused MoE reload support found no open implementation; the issue also had no linked PR when this work started.

No documentation update is required because this is an internal weight-loader contract and adds no user-facing option or supported model architecture.

## Test Result

Validation was run on an NVIDIA RTX PRO 6000 Blackwell Server Edition (SM120, driver 580.173.02), with Python 3.12.14, PyTorch 2.13.0+cu132, and CUDA 13.2:

- MoE loader regression suite: `53 passed, 14 warnings in 14.96s`.
- Layerwise fused reload lifecycle regression: `1 passed, 14 warnings in 0.64s`.
- Native ModelOpt NVFP4 MoE kernel case: `1 passed, 14 warnings in 3.22s`.

The native kernel test selected `VLLM_CUTLASS` on SM120, rather than an emulation backend, and matched the reference output within the test's ModelOpt FP4 tolerance.

### Qwen3-30B-A3B loader-only benchmark

A controlled temporary benchmark used the issue's Qwen3-30B-A3B routed-expert dimensions: 42 layers, 128 experts, hidden size 2048, intermediate size 768, TP=1, EP=1, and EPLB disabled. Both paths loaded the same eight synthetic, shape- and dtype-correct GPU-resident source tensors and copied the same 339,741,696 bytes per layer. Each sample timed exactly 42 sequential `RoutedExperts.load_weights` calls, with `torch.cuda.synchronize()` immediately before and after the measured region. One warm-up was followed by five paired samples in alternating order.

| Path | Loader records | Mean | Median | Observed range |
| --- | ---: | ---: | ---: | ---: |
| Legacy per-expert | 64,512 | 5.3220 s | 5.3175 s | 5.3140-5.3410 s |
| Layer-fused | 336 | 19.928 ms | 19.929 ms | 19.924-19.933 ms |

This is a 267.1x mean and 266.8x median speedup for the isolated loader boundary. Before timing, all eight pre-kernel destination tensors loaded through the fused and legacy paths were required to be exactly equal. After timing, both layers ran the real ModelOpt NVFP4 post-load conversion and `VLLM_CUTLASS` forward path; their processed parameters and outputs were also exactly equal (`rtol=0`, `atol=0`), and the outputs were finite.

This benchmark intentionally measures only Python loader granularity plus the identical GPU copy volume. It excludes online quantization, IPC or weight transfer, layerwise finalization, post-load conversion time, and model-level reload orchestration. The 267x figure is therefore not an end-to-end `reload_weights` claim.

Additional validation:

- Fused destination tensors exactly matched their supplied inputs, while the existing legacy loader coverage remained passing.
- The reload lifecycle test invoked post-load processing exactly once and preserved both the original `Parameter` objects and their storage pointers.
- `ruff-check`: passed.
- Python 3.12 `mypy`: passed.
- `git diff --check`: passed.

Before this change, ModelOpt NVFP4 online-quantized MoE weights had to be expanded into per-expert checkpoint names. With this contract, the workload described in #53687 can present 336 complete layer-local records instead of 64,512 records, a roughly 99.5% reduction in Python loader applications.

The 90-step GB200 production benchmark reported in #53687 measured mean refit time decreasing from 18.42 seconds to 6.31 seconds (2.92x) with a downstream proof of concept. That GB200 benchmark was not rerun as part of this PR. SM120 and GB200 use different architectures, and the measurement boundaries differ, so the loader-only result above is not presented as a reproduction of that end-to-end result.

No model evaluation was run because this change does not alter quantization arithmetic, kernel selection, or model computation. It changes loader granularity while preserving exact pre-kernel tensor values and the existing post-load processing path.

## Pull request overview

This PR introduces an opt-in “layer-fused” MoE checkpoint loading contract so online quantizers (notably ModelOpt NVFP4) can provide complete per-layer pre-kernel tensors directly, drastically reducing the number of loader records while preserving vLLM’s reload lifecycle, accounting, and post-load processing.

**Changes:**
- Adds `FusedMoEParameterLoadSpec` and a default (empty) fused-loading contract on `FusedMoEMethodBase`.
- Extends `RoutedExperts.load_weights` / `weight_loader` to support all-or-nothing fused bundles, while rejecting duplicates, incompleteness, and mixed fused/per-expert inputs within a layer.
- Opts ModelOpt NVFP4 MoE into the fused contract and adds targeted regression tests (loader behavior + reload lifecycle invariants).
