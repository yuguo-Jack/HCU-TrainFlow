# [Perf][Kernel] Tune SM90 FP8 CUTLASS tiles for M in (128, 192] and (256, 448]

[Upstream PR](https://github.com/vllm-project/vllm/pull/64521) · state: open · merged: False

## Original PR description



## Overview

On Hopper, FP8 `cutlass_scaled_mm` uses one config for every M above 128: a 128x128 tile with a 2x1 cluster. At M 129-192 and 257-448 that config spends much of its time on padding rows and leaves SMs idle. This PR adds a 64x128 config for M in (128, 192] and a 64x256 config for M in (256, 448], both without a cluster.

## Claims

- Decode TPOT on one H100 at batch 160, 192, 320 and 384: 10.2-18.5% lower for Llama-3.1-8B-Instruct-FP8-dynamic and 13.9-37.6% lower for Qwen3-32B-FP8-dynamic.
- On one H200: 4.5-12.7% and 14.0-33.5% lower.
- Batch 64 and 128, which keep their config, moved by at most 0.2% on H100.
- Outputs are bitwise identical to main.

## Details

- Root cause: The persistent scheduler runs ceil(M / tile_M) row tiles, rounded up to the cluster size, times ceil(N / tile_N) column tiles on 132 SMs. At M 160 the 128-row tile computes 256 rows, and an N=4096 layer gets 64 tiles for 132 SMs. At M 320 the 2x1 cluster rounds 3 row tiles up to 4. A 64-row tile without a cluster pads at most 63 rows:

| M | N | tiles before | padded rows before | tiles after | padded rows after |
|---|---|---|---|---|---|
| 160 | 4096 | 64 | 38% | 96 | 17% |
| 192 | 5120 | 80 | 25% | 120 | 0% |
| 320 | 4096 | 128 | 38% | 80 | 0% |
| 320 | 5120 | 160 | 38% | 100 | 0% |
| 448 | 5120 | 160 | 12% | 140 | 0% |

- Cluster: The existing 64x128 config for M in (64, 128] has a 2x1 cluster, which would round 3 row tiles up to 4 at M 129-192, so the new configs drop it.
- Unchanged buckets: In (192, 256] the better new config was 0.93x the current one for Qwen3-32B, and at M 512 0.97x for Llama-3.1-8B, so those keep the current config. The sweep covered 10 configs (tile sizes, clusters, pingpong/cooperative, swap-AB) on the 8 Llama-3.1-8B and Qwen3-32B linear shapes at M 128-512.
- Numerics: The old and new configs use the same 128-wide K tile and FP8 fast-accumulation mainloop, so each output is accumulated in the same order. The new kernels matched the old ones bitwise in all 480 swept cases.
- Scope: Only the per-tensor/per-token FP8 SM90 dispatch changes. The batch-invariant path, blockwise FP8, int8, MoE and other architectures are untouched.
- Build cost: 8 more kernel instantiations, sm_90a only, adding 178 KiB of device code. `scaled_mm_sm90_fp8.cu` compiles in 167 s, under the slowest object in the same target (529 s).
- Not measured: H20, H100 PCIe, TP > 1 and per-tensor activation scales. TP shrinks N or K per GPU, which moves the tile counts but not the row padding.
- CI coverage: CI runs this test on L4 and B200, which don't use the SM90 dispatch, so the H100 run above is the coverage for the new kernels.
- Related: #20396 tuned M <= 64 and #28692 tuned M >= 8192 in this file. #60464 changes the SM90 blockwise FP8 dispatch, a different kernel. No open PR changes this dispatch.
