# [CI] List one test path per line in Buildkite pytest commands to avoid merge conflicts

[Upstream PR](https://github.com/vllm-project/vllm/pull/63408) · state: closed · merged: True

## Original PR description

## Overview

Many Buildkite commands list several test files (or `--ignore` / `--deselect` paths) on one line, e.g. `models_basic.yaml` runs 13 files in a single 500-character `pytest` line. Two PRs that each add a test to the same job conflict on that line. This PR puts every test path on its own line, with no change to what CI runs.

## Claims

- Every pytest command that names 2 or more paths (counting `--ignore` / `--deselect`) now has one path per line: ~105 commands in `test_areas/`, `test-amd.yaml`, `intel_jobs/`, `hardware_tests/cpu.yaml`, `run-intel-ci-test.sh`, plus the L4 2-node command in `distributed.yaml`.
- No CI behavior change: all edited yaml loads to the same command strings as `main`.
- `check_test_tethering.py` now joins `\`-continued lines. Without this, the `|`-block edits here would make the tethering gate count every test as tethered.
- `tests/AGENTS.md` documents the convention.

## Validation

- **Same commands.** `yaml.safe_load` of each of the 25 edited `>-` yaml files equals `main`. The 2 `|`-block files (`cpu.yaml`, `models_distributed.yaml`) and `run-intel-ci-test.sh` equal `main` once `\`+newline is joined (what bash does). `bash -n` passes.
- **Same pipelines.** The ci-infra pipeline generator (`vllm-project/ci-infra` e28b4ff355) produces byte-identical step scripts for every `>-` file. `test-amd.yaml` rendered through `test-template-amd.j2` with `minijinja-cli` is byte-identical to `main` across 8 `mirror_hw` values x 3 modes. Intel yaml strings were also compared with PyYAML, libyaml, and go-yaml v3 (`yq`).
- **Same tethering.** `python tools/pre_commit/check_test_tethering.py --all` prints the same output as on `main` (exit 0), and the normalized `load_selections()` list is identical.
- **Checker tests.** `pytest tests/tools/test_check_test_tethering.py`: 143 passed. 3 of the 5 new cases fail with `main`'s checker; the other 2 are a positive control and a guard for an escaped `\\` before a newline.
- `pre-commit run --files <changed files>` passes.
- No `.buildkite` command still names 2 or more test paths on one line, except the line noted under Details.

<summary>Reproduce the "same commands" check</summary>

```python
import re, subprocess, yaml

def norm(v):  # join shell `\` continuations, as bash does
    if isinstance(v, str):
        return re.sub(r" \\\n *", " ", v)
    if isinstance(v, list):
        return [norm(x) for x in v]
    if isinstance(v, dict):
        return {k: norm(x) for k, x in v.items()}
    return v

base = subprocess.check_output(["git", "merge-base", "origin/main", "HEAD"], text=True).strip()
files = subprocess.check_output(
    ["git", "diff", "--name-only", base, "HEAD", "--", ".buildkite/"], text=True
).split()
for f in files:
    old = subprocess.check_output(["git", "show", f"{base}:{f}"], text=True)
    new = open(f).read()
    if f.endswith(".sh"):
        same = norm(new) == old
    else:
        same = norm(yaml.safe_load(new)) == norm(yaml.safe_load(old))
    print("OK  " if same else "DIFF", f)
```

</details>

## Details

**Format.** Single-line commands become `>-` folded blocks: `pytest -v -s` on the first line, then one path per line. Option groups (`-k '...'`, `-m x`, `--shard-id=.. --num-shards=..`) stay on one line, and argument order is unchanged. `>-` is already used in `engine.yaml`, `compile.yaml`, and the Intel jobs, and every line in it is literal text, so `#` or `: ` in a `-k` expression cannot break the yaml. Lines inside existing `>-` blocks are split in place. Lines inside `|` blocks use shell `\` continuations, as `cpu.yaml` already does.

Two rules when editing a `>-` block:
- Keep every line at the same indent. A more-indented line keeps its newline.
- Delete a path line instead of commenting it out. A `#` line turns the rest of the command into a shell comment.

**Tethering checker.** `_split_shell_stages` tokenizes with `shlex`, which keeps an escaped newline inside the token. Existing `cpu.yaml` blocks only worked because `normalize_test_path` strips the leading `\n`. An indented continuation, as in `models_distributed.yaml` here, yields a bare `"\n"` token. It normalizes to `""`, which matches every test, so the full scan reported all 26 allowlist entries as "now tethered". A continued `--ignore` (`"\n--ignore=..."`) was also read as a path. The fix joins odd runs of backslash + newline before tokenizing, the same as `_parse_shell_script` already does for scripts. It changes no selection parsed from `main`'s pipelines.

**Scope.**
- The rule is 2 or more paths, so it is easy to state and check. 39 of the rewritten commands are a directory plus one `--ignore`.
- The few existing hanging-indent lists in `kernels.yaml` / `test-amd.yaml` are already one path per line and are left as they are.
- Not changed: `intel_jobs/models_multimodal_intel.yaml:76` is missing a trailing `&&` (since #59865), so `pytest ... -m core_model pytest -v -s .../test_qwen2_vl.py` runs as a single call. That changes behavior, so it is fixed separately in #TBD.
