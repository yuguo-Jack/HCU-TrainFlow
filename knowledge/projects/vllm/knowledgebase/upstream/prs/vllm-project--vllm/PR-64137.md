# [Bugfix][Spec Decode] Don't specialize MRV2 logits-stats kernels on num_logits

[Upstream PR](https://github.com/vllm-project/vllm/pull/64137) · state: closed · merged: True

## Original PR description

## Overview

MRV2 spec decode JIT-compiles `_compute_local_logits_stats_kernel` during serving. Triton specializes `num_logits` on divisibility by 16, and warmup only covers one of the two cases. This PR marks `num_logits` as `do_not_specialize` on that kernel and on `_compute_local_residual_mass_kernel`. The argument was added in #61451. Related: #49349.

## Claims

- No runtime JIT of either kernel when `num_logits` changes between steps.
- No output change: `num_logits` only bounds the bonus-logit mask.

## Validation

End to end on Gemma-4 31B BF16 + MTP (k=4), TP8, H100, `--jit-monitor-verbose`, with mixed sampling/JSON/tool traffic at batch sizes 1–64:

| | Runtime JIT of `_compute_local_logits_stats_kernel` |
|---|---|
| `main` | 2 per rank (FP32 and BF16 logits) |
| This PR | 0 |

```bash
pytest tests/v1/spec_decode/test_rejection_sampler_utils.py \
  tests/v1/spec_decode/test_synthetic_rejection_sampler_utils.py
# 98 passed
```

## Details

No new unit test. The change only drops a compile-cache specialization, and the end-to-end JIT monitor run above covers it.

Not a duplicate: #54630 and #63819 cover other warmup gaps and don't touch these kernels.
