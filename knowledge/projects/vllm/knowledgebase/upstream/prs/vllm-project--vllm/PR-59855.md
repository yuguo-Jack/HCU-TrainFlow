# [Bugfix][KV Offload] Capture event metadata for pending promotions

[Upstream PR](https://github.com/vllm-project/vllm/pull/59855) · state: open · merged: False

## Original PR description

## Overview

Capture offload event metadata on `HIT_PENDING` so KVCR inventory arriving before primary delivery has real tokens, hashes and geometry—not a zero-size FullAttention placeholder that triggers quarantine.

## Claims

- Preserve pending lookup status; do not announce a native store early.
- Hold metadata for allocated primary slots, including secondary-only residency.
- Clean up failed primary allocations without public evictions or deleting retry metadata.

## Validation

- Updated standalone CPU suites: **100 passed, 4 deselected**; new shared-prefix and retry regressions fail without their fixes.
- Broader campaign-stack suites and staged reproducer: **170 passed, 4 deselected**.
- Targeted regressions failed before the fix; hooks passed.

[Reproduction command and review fixes](https://github.com/vllm-project/vllm/pull/59855#discussion_r4187529172).

Coverage uses the real CPU manager, Scheduler lookup and EventTracker in `test_manager.py`, `test_scheduler.py` and `test_events.py`. Transport is staged/mocked.

Live pre-fix evidence: block size 0 where 1600 was expected; the exact key was not logged. Patched live-engine validation and CI remain pending. No GPU/RDMA correctness or performance improvement is claimed.

## Details

KVCR can announce committed G2 inventory before primary delivery completes. Capture the payload while the primary slot exists but is not yet readable; use internal failed-allocation cleanup and discard stale cleanup when a retry already owns the key.

Independent of #59703 and ai-dynamo/dynamo#15535. Unlike provenance redesign #52103, this backfills KVCR inventory through the existing tracker. Consumer validation is unchanged.

AI assistance was used. **Draft; human review, live-engine validation and CI required before merge.**

Failed writes never emit a native `BlockStored`, but this event becomes a public `BlockRemoved` for every constituent hash. If native chunk `[A, B]` is ready and pending chunk `[A, C]` fails, the removal decrements A's only reference even though `[A, B]` remains resident. This violates the reference-counting contract in `events.py:10–12`. Separate failed-allocation metadata cleanup from public eviction announcements, and add a shared-prefix failure regression.

- Copilot · comment · 2026-10-05T16:52:25Z · [source](https://github.com/vllm-project/vllm/pull/59855#discussion_r4186529922)

File: `vllm/v1/kv_offload/cpu/manager.py` · line 402

This queued removal can outlive the allocation it describes. `TieringOffloadingManager.lookup()` polls failed completions, then can allocate a replacement for the same key and return `HIT_PENDING`. The scheduler records the replacement's metadata before events are drained, so the old removal discards its `(CPU, None)` hold. With no remaining secondary hold or store in that event batch, the tracker deletes the payload while the replacement is still pending; a later inventory or completion event before another lookup gets a zero-size placeholder. Distinguish allocation lifetimes or process the old cleanup before recording the replacement. Add a failed-promotion/same-step-retry regression.

Claude:

vllm/v1/kv_offload/cpu/manager.py:451-459 — take_events is a generator that now mutates queued events (event.keys = [...]) while self.events.clear() runs only if the generator is exhausted. Concrete failure on partial consumption: an event with keys=[K1, K2] is pruned to [K2] and yielded, the consumer stops, clear() never runs, so the same cleanup is yielded again on the next drain — and if K2 was re-allocated and re-recorded in between, the second discard((CPU, None)) releases the replacement's hold and pops its payload, which is the exact bug this PR fixes. Not reachable today: the only in-tree consumer (vllm/v1/core/sched/scheduler.py:2379-2383) materialises via list()/extend(). Cheap to make unreachable by construction:

```
def take_events(self) -> Iterable[OffloadingEvent]:
    if self.events is None:
        return
    events, self.events = self.events, []
    for event in events:
        ...
```
  That also removes the in-place mutation of an object the caller may still hold.
