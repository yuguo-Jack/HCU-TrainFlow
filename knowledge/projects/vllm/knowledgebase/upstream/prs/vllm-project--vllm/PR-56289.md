# [Bugfix][FlashInfer] Derive CUDA-graph head count from KV-cache group's own layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/56289) · state: closed · merged: False

## Original PR description

## Purpose

`FlashInferMetadataBuilder.get_cudagraph_support()` derives `num_qo_heads` from the **target** model's global head count and uses it for every KV-cache group. For a draft/spec-decode group with different head geometry (common with MTP heads or custom TP padding), this mis-declares CUDA-graph support: at an odd TP degree (e.g. TP=3) the draft group falls from `UNIFORM_BATCH` to `UNIFORM_SINGLE_TOKEN_DECODE`, which the call site propagates to `cudagraph_mode=NONE`, turning **all** CUDA graphs off.

The builder's `__init__` and kernel-selection path already call `get_num_attention_heads_from_layers()` per-group; the classmethod never got the same treatment.

## Fix

- Add `get_num_attention_heads_from_layers()` helper to `vllm/v1/attention/backends/utils.py`.
- Add optional `layer_names: list[str] | None = None` to `FlashInferMetadataBuilder.get_cudagraph_support()`; backward-compatible fallback to global count when omitted.
- Pass `kv_cache_group.layer_names` from the call site in `gpu_model_runner.py`.

## Testing

- CPU regression test (`tests/v1/attention/test_flashinfer_cudagraph_support.py`, `pytestmark = pytest.mark.cpu_test`): draft group 12/3 → `UNIFORM_BATCH`; fallback 22/3 without `layer_names` → `UNIFORM_SINGLE_TOKEN_DECODE`; target group 24/3 → `UNIFORM_BATCH`.
- Verified `ruff check` and `ruff format` clean.

Fixes #55581
