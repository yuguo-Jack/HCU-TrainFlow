# [Security] Refresh vulnerable runtime and test dependencies

[Upstream PR](https://github.com/vllm-project/vllm/pull/62835) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Raise dependency minimums, including Sentence Transformers 5.6.0, regenerate the four compiled test requirement files, and require LMCache 0.5.6 for both CUDA connector variants. Certificate remediation is isolated in #62868; #59667 remains the separate automation change.

## Claims

- Update runtime floors for aiohttp, Pillow, MCP and multidict; update test and nightly-test inputs and their generated locks. Align ROCm Ray with the CUDA/CPU test series and update the Rust TLS lock.
- Require `lmcache>=0.5.6` for CUDA 13. For CUDA 12, use the official [0.5.6 CUDA 12.9 release](https://github.com/LMCache/LMCache/releases/tag/v0.5.6-cu129), pin `lmcache==0.5.6`, and constrain `cuda-python>=12,<13` so resolution selects the CUDA 12 build.
- Raise Sentence Transformers test minimums to 5.6.0 for CUDA, ROCm and nightly tests; pin XPU and all four compiled test locks to 5.6.0.
- Preserve unrelated pins. Certifi and OS certificate changes are excluded from this PR, allowing the certificate fix to proceed independently of LMCache compatibility validation.

## Validation

### Sentence Transformers 5.6.0 validation

- Regenerated CPU, CUDA, ROCm and XPU locks with uv 0.11.1 using their checked-in commands, preserving unrelated package versions. All applicable pre-commit hooks and `git diff --check` passed.
- Existing pooling-config/schema tests: **6 passed**. Existing pooler activation tests: **25 passed**. Commands below ran in an isolated environment with Sentence Transformers 5.6.0, PyTorch 2.14.0 and Transformers 5.16.1.
- CPU compatibility smoke: seeded, two-layer tiny BERT with mean pooling, a dense projection and normalization; five inputs including one truncated input, plus three BERT CrossEncoder pairs. Using identical saved weights, 5.2.0 and 5.6.0 produced bit-identical embeddings and scores (maximum absolute difference **0**). Loading a 5.2.0 model under 5.6.0, saving/reloading under 5.6.0, and vLLM pooling/dense config parsing passed. This is a small compatibility check; embedding quality benchmarks and GPU/model evaluations remain pending.


The initial config-test invocation with the global conftest hit the existing macOS PyTorch `empty_host_cache` teardown segfault before Sentence Transformers was installed in that environment. The scoped invocations run the selected CPU tests without that global GPU cleanup fixture.

## Details

Both source requirements and generated outputs are updated so regeneration retains patched minimums. LMCache's CUDA 12.9 wheels are published separately from the CUDA 13 PyPI build for Linux x86_64 and aarch64. Existing Docker/Buildkite installers select the CUDA-specific file and constrain the installed accelerator stack. LMCache 0.5.6 changes the multiprocess wire format: workers and servers must be upgraded together.

**Duplicate-work check:** inspected #59249, #59315, #47468, #53441, #60308 and #56643. Earlier merged floors predate these fixes; image cleanup, source-build ABI handling and Pillow request-error handling cover different controls. #56643 covers vLLM's separately vendored opt-in native hash implementation and remains necessary independently. #59570 also proposes the Sentence Transformers 5.6.0 upgrade; this PR now includes that overlapping upgrade across the source requirements, nightly tests and generated locks. Existing #48560 (CUDA fsspec) remains separate and its pin is preserved here. The certificate-only PR and #59667 address separate scopes. The split also addresses the review request to avoid coupling the certificate remediation to LMCache upgrades.

Sentence Transformers 5.6.0 meets GitHub's listed patched-version threshold. Upstream 5.6.0 still permits local custom Python modules without `trust_remote_code=True`, emits a `FutureWarning`, and schedules enforcement for v6.0. This dependency bump does not claim to enforce that boundary; vLLM's separate module-path containment PR #61430 remains independent.

This does not fix every pending alert. Accelerate, nltk and sqlitedict lack patched releases in the audited snapshot; datasets/fsspec require migration past the existing datasets cap; setuptools conflicts with current build bounds; and ROCm/TheRock PyTorch needs a coordinated accelerator-stack update.
