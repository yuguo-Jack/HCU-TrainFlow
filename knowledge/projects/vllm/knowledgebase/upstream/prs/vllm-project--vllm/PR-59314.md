# [Rust Frontend] Add per-request timing metrics to chat and completions

[Upstream PR](https://github.com/vllm-project/vllm/pull/59314) · state: open · merged: False

## Original PR description

Implements the per-request `metrics` (`--enable-per-request-metrics`) roadmap item in #44280. Speculative-decoding acceptance stats remain a separate checklist item.

## Summary

- Accept `--enable-per-request-metrics` in the Rust frontend and reject it alongside `--disable-log-stats`.
- Carry the engine's queue, schedule, first-token, and last-token timestamps through decoded text and chat output.
- Return Python-compatible timing fields in non-streaming `/v1/chat/completions` and `/v1/completions` responses. For streaming, attach them to the final usage chunk when `stream_options.include_usage` is enabled.
- Serialize unavailable timing fields as `null` in non-streaming responses and omit them from streaming usage chunks, matching Python's recursive `exclude_none=True` behavior.

## Scope

Speculative-decoding acceptance metrics are intentionally not included in this PR. `GenerateOutput` already carries terminal `spec_decode_metrics`, but mapping those values into the OpenAI `PerRequestMetrics.speculative_decoding` response field is separate follow-up work.

- #36383 is a Python frontend draft. #42198 concerns response headers. #56914 concerns reasoning/content token metrics in Python. None adds this Rust frontend response-body implementation.
