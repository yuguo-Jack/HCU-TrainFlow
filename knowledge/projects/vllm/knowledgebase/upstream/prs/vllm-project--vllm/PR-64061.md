## Overview

This PR enables the `deep_gemm_mega_moe` MoE backend on SM90 (H200) for MXFP4 routed experts. It uses DeepGEMM's new SM90 FP8 x FP4 Mega MoE kernel, which fuses dispatch, L1 GEMM, SwiGLU with FP8 quant, L2 GEMM and combine into one persistent kernel over NVLink symmetric memory.

Depends on vllm-project/DeepGEMM#44. The DeepGEMM pin in `cmake/external_projects/deepgemm.cmake` must be bumped once that PR lands. Until then the SM90 test cases skip.

## Claims

- `moe_backend=deep_gemm_mega_moe` works on SM90 with MXFP4 experts, with the same functionality as SM100 within one NVLink domain.
- On DeepSeek-V4.1-Flash, single node DP8+EP8, output throughput is 17-26% higher than main's default MoE path and 12-19% higher than main with deepep_v2, at concurrency 1 to 1024.
- On two nodes, as two DP8+EP8 replicas, output throughput is 16-27% higher than main's default and 10-16% higher than main with deepep_v2.
- In a 2-node P/D AgentX setup, ITL p50 drops by 10-11% and TTFT p50 by 12-17%.
- Greedy generations are coherent and agree in content with main's default backend.
- SM90 activations are staged with one FP32 scale per 128 channels, the format DeepGEMM#44's SM90 kernel now takes. Against the earlier revision of both PRs this is 1-2% faster under load, and GSM8K is unchanged.

## Details

- `deep_gemm_mega_moe.py`: on SM90, activations are dispatched as FP8 with one FP32 scale per 128 channels (`MEGA_MOE_MXFP4_SM90`). `prepare_megamoe_inputs` computes it as `amax * (1 / 448)` with a correctly rounded inverse, so scales and values match DeepGEMM's `per_token_cast_to_fp8` bit for bit, and stores its bits in the int32 `x_sf` buffer and in the shared-expert scale layout. SM100 keeps UE8M0. The weight loader relayouts routed FP4 shards and repacks their scales with DeepGEMM's SM90 transforms. Fused FP8 shared experts are requantized once all their shards are loaded.
- BLOCK_M hint: every rank of a launch passes `num_tokens_for_block_m`, the mean tokens per EP rank of the step. All ranks then pick the same BLOCK_M, so idle DP ranks do not run small blocks next to busy ones. Without the hint, ragged steps are 1.5-1.9x slower on the slowest rank.
- DeepSeek V4 routes with `GateLinear` and `fused_topk_bias` off SM100, because `bf16_mega_gate` does not exist there. Warmup skips those configs on SM90.
- SM100 behaviour is unchanged.
