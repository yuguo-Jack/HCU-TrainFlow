# [Bugfix][Metrics] Correct KV cache eviction and idle-time reporting

[Upstream PR](https://github.com/vllm-project/vllm/pull/60075) · state: open · merged: False

## Original PR description

## Overview

KV residency metrics counted never-cached working blocks as evictions and included active-request time in idle duration. This PR fixes both while keeping the existing metric labels and event schema.

## Claims

- Skip never-cached recycling and clear stale sampling state on reallocation.
- Measure idle time from the final reference release; emit observations at eviction. Allocated at 0s, released at 99s, evicted at 100s means **1s idle, 100s lifetime**.
- Exclude transfer-only pins from prefix-reuse statistics.
- Extend default finite buckets from 30 minutes to 24 hours in both exporters.

## Validation

**39 Python tests and 1 Rust exporter test passed**, plus repository hooks. Four filtering/cleanup regressions fail against the preceding implementation as expected.

[Earlier GPU timing reproduction](https://gist.github.com/SherifWaly/2301ebc67c054eea7a226158879ab2de): one B200, tiny dummy-weight Llama, SimpleCPU offload. Mean idle error fell **68.483 ms → 0.012855 ms**; **24/24 outputs matched**. These results predate the final filtering change; the GPU rerun was blocked by DNS errors.

## Details

Filtering/cleanup overlaps with #47715; this PR is self-contained and also corrects timing, transfer-reuse accounting, and bucket coverage.

Actually cached SWA blocks still contribute valid short lifetimes. These are GPU block-eviction statistics, excluding still-resident blocks and CPU residency. Avoid combining different bucket schemas during upgrades.
