# [Bugfix][XPU] Add record_logical_topk_ready to XPUMLASparseImpl

[Upstream PR](https://github.com/vllm-project/vllm/pull/64065) · state: closed · merged: True

## Original PR description

- **Problem:** `MLAAttention.forward` calls `impl.record_logical_topk_ready()` on every sparse layer, but `XPUMLASparseImpl` never defined it, so DeepSeek-V3.2 and GLM-5.x crash with `AttributeError` on the first forward on XPU.
- **Fix:** adds the no-op hook (as #57252 did for ROCm) and runs the XPU sparse MLA tests in Intel CI, where no step selected them.
- **Validation:** on an Arc Pro B60, `pytest tests/v1/attention/test_xpu_mla_sparse_backend.py tests/kernels/attention/test_xpu_mla_sparse.py` gives 5 passed, while the new test fails on `main` with `assert callable(hook)`; there is no `LLM`-level test because CI has no small checkpoint for this architecture.
- **Not a duplicate:** the only other open PR with this hunk is the large #59019 (meta-device op capture).
- **AI assistance:** Claude Code was used; I reviewed every changed line.
