# [Bugfix] Read generate usage.prompt_tokens in non-streaming derender

[Upstream PR](https://github.com/vllm-project/vllm/pull/64781) · state: open · merged: False

## Original PR description

## Overview

Non-streaming `/v1/chat/completions/derender` and `/v1/completions/derender` return `usage.prompt_tokens: 0` when the request omits `prompt_tokens`, because they never read the generate response's `usage`. They now fall back to the generate response's `usage.prompt_tokens`, as the streaming paths already do. Fixes #64778

## Claims

- Non-streaming chat derender without `prompt_tokens` returns the generate response's `usage.prompt_tokens` (10) instead of 0.
- Non-streaming completions derender without `prompt_tokens` returns the sum of the generate responses' `usage.prompt_tokens` (1 + 5 = 6) instead of 0.
- No change for requests that set `prompt_tokens`, 0 included.

## Details

**Root cause.** `ServingDerender.derender_chat_response` sets `prompt_tokens` to `request.prompt_tokens`, else 0, and `OnlineDerenderer._derender_completion` expands an omitted list to `[0] * n`. Neither reads the generate response's `usage`, which `/inference/v1/generate` sets on every non-streaming response. The `prompt_tokens` docstrings on `DerenderChatRequest` and `DerenderCompletionRequest` documented the 0.

**Fix.** New `resolve_prompt_tokens(prompt_tokens, usage)` returns the request value if set (0 included), else `usage.prompt_tokens`, else 0 when `usage` is absent, the order `derender_chat_stream`, `_derender_chat_stream_parsed` and `derender_completion_stream` already used inline. All five sites call it, completions once per generate response, and the two docstrings, which `derenderer.md` includes, state this order; the stream sites' `or 0` is dropped because `UsageInfo.prompt_tokens` is a non-optional `int`.

**Related PRs.**

- #64041 — adds `reasoning_tokens` and `cached_tokens` to chat derender usage. It edits the `UsageInfo` in `derender_chat_response` next to this change and keeps the `else 0`; the two merge cleanly.
- #43606 — added the `/derender` endpoints. It introduced the `else 0`, the `[0] * n` default and the "defaults to 0 if omitted" docstrings this PR changes.
- #47301 — added streaming derender. It introduced the request-then-generate-usage order that `resolve_prompt_tokens` copies.
