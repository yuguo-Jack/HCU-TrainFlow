# [Core][DP] Publish DP LB result-metric fields in engine snapshots

[Upstream PR](https://github.com/vllm-project/vllm/pull/61386) · state: open · merged: False

## Original PR description

## Why this is not duplicating an existing PR

Plumbing stage of the series started by #58070, split into reviewable
layers so each lands independently. No open PR covers this snapshot
extension.

## What this does

Plumbing only, **no behavior change**: the DP load balancer's next stage
(result-metric penalties) needs richer engine snapshots.

- `SchedulerStats` gains `mean_queue_time` (engine-side TTFT proxy:
  average wait of queued requests) and `preempted_total` (cumulative
  preemptions), both defaulted so every existing constructor keeps
  working.
- `Scheduler` publishes them: cumulative preempt counter,
  `get_mean_queue_time()` / `get_preempted_count()`, and `make_stats()`
  fills the fields so the metrics/dump paths match the DP publish sites.
- `DPCoordinator` broadcasts 5-field engine snapshots (was 3).
- The DP client unpacks only the first three fields, so existing
  consumers and new snapshots coexist.

The fields are additive and currently unused by routing.

## Tests

- `python tests/v1/engine/test_dplb_stats_plumbing.py` — 2/2 PASS
