# [XPU][Attention] Enable tensor-descriptor Q load for non-power-of-2 GQA (~1.9x Qwen2-7B)

[Upstream PR](https://github.com/vllm-project/vllm/pull/47248) · state: open · merged: False

## Original PR description

## Purpose

The Triton unified attention kernel gates its tensor-descriptor (2D-block I/O) Q-load and output-store off whenever `num_queries_per_kv` is **not** a power of 2 (`_is_pow2_nq`), because the Triton TD validator requires power-of-2 `block_shape` dims. This leaves non-pow2 GQA models — e.g. **Qwen2-7B** (28/4 = 7) — on the slow pointer Q/O path even when the TD path is otherwise available.

## Change

Enable the TD **Q-load** for non-pow2 GQA:
- Pack `BLOCK_M = BLOCK_Q * next_power_of_2(num_queries_per_kv)` and pad the Q descriptor's head dim to `NQ_PADDED`. The descriptor zero-pads the read past the real extent (as it already does for `HEAD_SIZE_PADDED`).
- Mask the padding head slots in-kernel (`head_in_group < num_queries_per_kv`) so they can't alias the next KV group.
- The TD **store** still requires pow2 `nq` (a padded store would corrupt neighbouring heads) — gated separately via `USE_TD_STORE`; non-pow2 `nq` uses the masked pointer store.
- `compute_tile_loop_bounds` max query-offset uses `BLOCK_Q - 1` instead of `(BLOCK_M - 1) // num_queries_per_kv`, which overshoots once `BLOCK_M` is padded.

**No-op for power-of-2 GQA** (`NQ_PADDED == num_queries_per_kv`).

## Test plan / results (Arc Pro B60, bf16, vs a torch SDPA paged reference)

Verified on this branch. Correct in all cases (outputs identical to baseline):

| Config (Qwen2-7B, nq=7) | before | after | speedup |
|---|---|---|---|
| prefill 4k | 46.3 ms | 24.1 ms | 1.93x |
| chunked 3x2k | 32.9 ms | 17.4 ms | 1.89x |
| decode (3D) | 0.715 ms | 0.362 ms | 1.98x |
| long-context decode | 2.77 ms | 1.46 ms | 1.90x |
| chunked, scattered block tables | 33.1 ms | 17.4 ms | 1.91x |

Power-of-2 GQA controls unchanged (GQA=4 prefill 23.931 -> 23.927 ms back-to-back; GQA=8, GQA=16 sliding-window, decode all no-op and correct).

Scope note: XPU-focused (gated on the TD path); no-op on non-XPU paths that don't set `use_td`. Independent of #47246 (prefill BLOCK_M widening); they compose but do not depend on each other.
