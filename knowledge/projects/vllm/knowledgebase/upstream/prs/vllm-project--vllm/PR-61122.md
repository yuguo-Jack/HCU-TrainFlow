# [Bugfix] Preserve empty tensor metadata in packed IPC

[Upstream PR](https://github.com/vllm-project/vllm/pull/61122) · state: open · merged: False

## Original PR description



## Overview

`packed_ipc_producer` drops the final chunk when the input contains only zero-element tensors. Flush when metadata is present so names, shapes, and dtypes survive a zero-byte payload.

## Claims

- Preserve metadata for one or more empty tensors with a one line predicate change.
- Keep an empty iterator at zero chunks and preserve existing nonempty transfer behavior.
- Add two parameterized CUDA regressions in the existing producer suite.

## Validation

GB10/SM121, Torch `2.13.0+cu130`. ## Details

Empty tensors contribute metadata but zero bytes. The final `if total_bytes:` silently omits that logical transfer. `if names:` includes it while leaving a genuinely empty iterator unchanged. No API, dependency, or buffer ownership rule changes.

This is separate from alignment PR #57665, which fixes dtype views over unaligned slices. Bounded searches found no open exact empty-only producer fix. Broader searches returned unrelated kernel PRs #48580 and #46676; neither changes this module. RFC #59502 concerns modulewise reload and integrity.

Shared CUDA tensor teardown warnings remain visible in baseline and proposed runs. This patch does not claim to fix lifetime warnings, leaks, model accuracy, or serving performance. No model benchmark is presented for this transport metadata corner case.

AI tools assisted with reproduction, the patch, tests, and PR preparation. Human line review was confirmed, and test execution was explicitly delegated to the agent. Direct human shell execution is not claimed.
