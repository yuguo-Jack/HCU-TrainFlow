# [Perf] Enable native small-head kernels in SM90 sparse FlashMLA

[Upstream PR](https://github.com/vllm-project/vllm/pull/64510) · state: open · merged: False

## Original PR description



## Overview

Enable existing native 8/16/32-head kernels in SM90 BF16 sparse FlashMLA for sufficiently large query batches, avoiding unnecessary computation from padding heads to 64.

https://github.com/vllm-project/vllm/pull/61615

## Claims

- Reduce head-padding overhead in the BF16 sparse attention path.
- Preserve the padded path for small query batches, where native small-head kernels can be slower.
- Improve output throughput by 10.0% in the recorded GLM-5.3-Flash serving benchmark.

## Details
Native heads are used on SM90 when the actual head count is 8/16/32 and the query-token count exceeds:

- SM count for 8 or 16 heads.
- Twice the SM count for 32 heads.

These are empirical performance thresholds. Each query launches one CTA, and small query batches can favor the padded kernel despite its extra head computation.

The implementation uses the actual head count, including heads gathered by DCP, and slices both queries and optional output buffers before calling FlashMLA. Existing padded workspaces remain available for fallback.

Related work and duplicate check: Reviewed open PRs matching FlashMLA small heads and SM90 sparse. #59418 (https://github.com/vllm-project/vllm/pull/59418) adds a Triton decoder that directly reads packed FP8 KV caches, while #57673 (https://github.com/vllm-project/vllm/pull/57673) adds an opt-in Triton backend. This PR integrates existing native BF16 kernels into the current FlashMLA sparse backend.
