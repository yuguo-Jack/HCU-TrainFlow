# [Perf][Attention] Fuse DCP correction output layout for reduce-scatter

[Upstream PR](https://github.com/vllm-project/vllm/pull/62288) · state: open · merged: False

## Original PR description

## Overview

The generic DCP `ag_rs` path corrects partial attention outputs in batch-major order, then copies them into head-major order for reduce-scatter. Write the correction directly into that physical layout to remove the input layout copy.



## Claims

- Remove one layout-copy kernel before reduce-scatter while retaining the logical `[B, H, D]` shape.
- Preserve correction arithmetic and the existing in-place path when the tensor already has the required layout.
- Leave the post-reduce-scatter layout conversion in place.



## Validation

### Serving evaluation

DeepSeek-V2-Lite BF16, 4 H200, TP4/EP4/DCP4, `ag_rs`, default compilation and CUDA Graph settings

```bash
MODEL=deepseek-ai/DeepSeek-V2-Lite
vllm serve "$MODEL" -tp 4 --port 9256 --enable-expert-parallel -dcp 4 \
  --load-format instanttensor --trust-remote-code
lm_eval --model local-completions \
  --model_args "base_url=http://127.0.0.1:9256/v1/completions,model=$MODEL,num_concurrent=1024" \
  --tasks gsm8k
vllm bench serve --model "$MODEL" --dataset-name random \
  --host 127.0.0.1 --port 9256 --random-input-len 4096 \
  --random-output-len 512 --request-rate inf --num-prompts 128 --num-warmups 16
# Also: --random-input-len 32768 --random-output-len 128
```

Actual runs use the downloaded checkpoint and tokenizer paths, matching seeds 1000/1001, and save raw JSON. Servers restart in A/B/B/A order. All included runs completed 128 requests with zero failures and the requested token counts.
