# [BugFix] Combine return_sampling_mask SamplingParams precondition errors

[Upstream PR](https://github.com/vllm-project/vllm/pull/61322) · state: open · merged: False

## Original PR description

## Overview

Combine the two `return_sampling_mask` request-admission checks into one actionable `ValueError`, document the contract on the flag, and warn at config verification. Fixes #61318.

## Claims

- A request that fails both `temperature > 0` and `top_k > 0` gets a single error listing both unmet conditions (with current values).
- A request that only fails `top_k` still gets a clear single-condition message (no false temperature complaint).
- Valid params (`temperature > 0`, `top_k > 0`) still pass admission.
- `ModelConfig.return_sampling_mask` docstring states both requirements.
- Enabling the flag logs a startup warning that every request must use `temperature > 0` and `top_k > 0`.

## Validation

```bash
.venv/bin/python -m pytest \
  tests/test_sampling_params.py::test_return_sampling_mask_reports_all_unmet_preconditions \
  tests/test_sampling_params.py::test_return_sampling_mask_reports_top_k_alone \
  tests/test_sampling_params.py::test_return_sampling_mask_accepts_valid_params \
  tests/test_config.py::test_sampling_replay_config \
  tests/test_config.py::test_sampling_replay_config_warns_about_request_preconditions \
  -v
# 20 passed
```

Reproduced the split-raise path on `main` via `InputProcessor._validate_params` (no GPU): `temperature=0` then `temperature=0.7` without `top_k` failed one check at a time. After this change, the first case lists both conditions in one message.

## Details

**Root cause:** `_validate_params` raised separate `ValueError`s for temperature and `top_k`, so clients discovered the full contract by trial and error. The flag is engine-level, but nothing at config time said every request needs those params.

**Approach:** Collect unmet conditions and raise once. Expand the field docstring (feeds CLI help). Warn in `_verify_sampling_replay_config` so operators see the contract before the first rejected client call. No change to which requests are accepted or rejected.

**Not duplicating:** No open PR references #61318.
