# [Bugfix][Frontend] Reject beam search with echo and logprobs in /v1/completions

[Upstream PR](https://github.com/vllm-project/vllm/pull/60876) · state: closed · merged: True

## Original PR description



## Overview

Fixes #60875.

`POST /v1/completions` with `use_beam_search`, `echo` and `logprobs` all set returns HTTP 500 with an empty message. This PR rejects that combination in request validation, so the client gets a 400 that names the conflicting parameters.

## Claims

- `use_beam_search=true` + `echo=true` + `logprobs` set now returns HTTP 400 instead of 500, both for `max_tokens > 0` and for `max_tokens=0`.
- Valid combinations are unchanged: beam search with `echo` only, beam search with `logprobs` only, and `echo` + `logprobs` without beam search still return 200.

## Validation

Reproduced and verified with `vllm serve facebook/opt-125m --max-model-len 512 --dtype float16 --gpu-memory-utilization 0.15` on the macOS CPU backend (Apple M3), sending `{"model": "facebook/opt-125m", "prompt": "Hello", "n": 2, ...}`:

| Extra request fields | main | this PR |
|---|---|---|
| `use_beam_search, echo, logprobs: 1, max_tokens: 5` | 500, `""` | 400 |
| `use_beam_search, echo, logprobs: 1, max_tokens: 0` | 500, `"Did not output logprobs"` | 400 |
| `use_beam_search, echo, max_tokens: 5` | 200 | 200 |
| `use_beam_search, logprobs: 1, max_tokens: 5` | 200 | 200 |
| `echo, logprobs: 1, max_tokens: 5` (no beam search) | 200 | 200 |

Tests:

```
pytest tests/entrypoints/openai/completion/test_completion_error.py   # 43 passed
pytest tests/entrypoints/openai/test_watermarking.py                  # 24 passed
pre-commit run                                                         # passed
```

The new test fails on main (`DID NOT RAISE VLLMValidationError`) and passes with this change. It runs in the existing `entrypoints/openai/completion` Buildkite step.

## Details

Root cause: beam search never computes prompt logprobs, but the echo + logprobs response path asserts they exist. The full trace is in #60875.

The fix adds one check in `CompletionRequest.check_logprobs`, next to the existing beam search check for `logprob_token_ids`. I chose rejection over computing prompt logprobs inside beam search, because that would change the beam search implementation for a rarely used combination. The Rust frontend already rejects `use_beam_search`, so it is not affected. Chat completions does not echo prompt logprobs, so it has no equivalent path.

Duplicate check: no other open issue or PR covers this (searched "beam search echo logprobs", "use_beam_search echo", "beam search prompt_logprobs").

AI assistance (Claude Code) was used to find the bug, write the fix and test, and run the validation. I reviewed every changed line and ran the commands above.

No, offline inference is not affected. `LLM.beam_search()` takes `BeamSearchParams`, which has no `echo`, `logprobs`, or `prompt_logprobs` fields, so passing them raises `TypeError`. `SamplingParams` also has no beam search switch.

So there is no offline path that combines beam search with echoed prompt logprobs. The failing assertion is in `OpenAIServingCompletion.request_output_to_completion_response`, which only the `/v1/completions` endpoint goes through (`vllm run-batch` also reaches it, because it reuses `CompletionRequest`). I also ran `LLM("facebook/opt-125m").beam_search(...)` with `beam_width=2` to confirm it works and returns per-token logprobs.
