# [ROCm][Compile] Fuse AITER static FP8 quant into MLA attention output

[Upstream PR](https://github.com/vllm-project/vllm/pull/62371) · state: closed · merged: True

## Original PR description

Fuse MLA attention with AITER's static per-tensor FP8 output quant on ROCm. Closes #62339.

- With AITER on and `fuse_attn_quant` enabled, MLA output quant now fuses into the attention op. On DeepSeek-Coder-V2-Lite-Instruct-FP8, 27 of 27 layers match (0 before).
- The fused path runs AITER's quant straight into the FP8 output, so it uses the same kernel as the unfused graph. Numerics are unchanged, and performance is neutral.
- No change on CUDA, or on ROCm with AITER off.

Specifically:
- `RocmMLAAttnFp8StaticQuantPattern` mirrors `RocmAttnFp8StaticQuantPattern` from #58099. AITER's per-tensor quant declares `scale` mutable, so the pattern returns it and the replacement passes it through. It is registered only on ROCm with AITER enabled.
- Matching alone made decode 2.4% slower at batch 4 (2.476 vs 2.417 s, ranges not overlapping). The fused MLA path computed bf16 output, then ran `QuantFP8` and a `copy_`, which replaced the graph's single AITER quant kernel. Running AITER's quant directly into the output removes that cost. It is gated on whether `QuantFP8` itself dispatches to AITER, so fused and unfused always use the same quant and clamp.
- This is parity rather than a speedup. On ROCm the MLA decode output is still produced in bf16 by the v_up_proj BMM and quantized afterwards. A real gain needs that BMM to write FP8 directly.
- No open PR covers this: searched for #62339, `MLAAttnQuantFusionPass` and MLA + AITER quant fusion.

Validated on: MI300X, AITER v0.1.25, `VLLM_ROCM_USE_AITER=1`, RedHatAI/DeepSeek-Coder-V2-Lite-Instruct-FP8 (static FP8, `ROCM_AITER_MLA`), `--compilation-config '{"pass_config":{"fuse_attn_quant":true}}'`. "Before" is this branch with the new pattern unregistered.

Tests:
- `pytest tests/compile/passes/test_mla_attn_quant_fusion.py tests/compile/passes/test_fusion_attn.py` passes 10/10 (31 passed, 24 skipped).
- `test_mla_attn_quant_fusion.py` passes with `VLLM_ROCM_USE_AITER` unset, `=1` and `=0`.
- The new `test_rocm_aiter_static_quant_mla_attention` fails without the new pattern (`All nodes remain for op vllm::rocm_aiter_per_tensor_quant`).
- `test_fusion_attn.py` fails 12 cases with an explicit `=1`, on `main` as well. This PR does not touch it.

The new test runs on AMD CI in the MI300 compile-passes job, which runs all of `tests/compile/passes`. It skips on NVIDIA.
