# [Feature][MoRIIO] Support hybrid WRITE transfers with DSpark

[Upstream PR](https://github.com/vllm-project/vllm/pull/60544) · state: closed · merged: True

## Original PR description

## Overview

Enable MoRIIO WRITE for hybrid attention and Mamba/KDA models, including DSpark. This extends the hybrid READ support in #51052 and #57700 using existing transfer plans and post-draft save finalization.

## Claims

- Transfer attention KV, convolution and SSM state with per-group identity and completion accounting.
- Resolve the live final prefill state, exclude speculative scratch slots and publish matching N-1 token accounting.
- Use native `wait_all` with a finite deadline and a bounded fallback for older MoRI versions; nonblocking progress is unchanged.

## Details

The three commits separate bounded completion waiting, grouped hybrid WRITE and DSpark support. Changes are confined to MoRIIO, its tests and its usage guide; no scheduler, model-runner, sampler or router implementation changes are needed.

1. Decode advertises allocated block IDs in transfer-group order.
2. Prefill resolves the live final slots and writes attention KV plus convolution and SSM state for the N-1 prompt.
3. Decode waits for all transfers before consuming the imported state and recomputing the final prompt token. A complete coupled local hit releases the producer without an empty remote load.

Set `read_mode: false` in both roles' `kv_connector_extra_config`, use matching cache layouts and TP sizes, and enable `--mamba-cache-mode align`. For DSpark, configure the same draft model on both roles. Sliding-window WRITE and other hybrid speculative methods remain unsupported. READ and plain-attention WRITE wire formats are preserved.

This adds hybrid recurrent-state WRITE, rather than duplicating attention registration work in #58585 or READ lifecycle work in #58968. The rebase retains upstream #57705 local-hit release and failure routing, per-layer registration geometry and one-shot receive guards.
