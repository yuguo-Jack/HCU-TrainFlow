# [Bugfix][GPT-OSS] Scope engine-level structured outputs to Harmony final channel

[Upstream PR](https://github.com/vllm-project/vllm/pull/61146) · state: open · merged: False

## Original PR description

## Summary

Fixes #60664.

When structured output constraints (e.g. `response_format.json_schema`) are passed directly through the engine (via `LLM.generate`) rather than through the OpenAI serving layer, the grammar bitmask applies from token 0 — blocking the model's reasoning channel entirely.

**Root cause:** `GptOssReasoningParser.is_reasoning_end()` always returns `True` (by design — the Harmony protocol uses structural tags to delineate reasoning). The OpenAI server wraps constraints in a structural tag via `HarmonyParser.adjust_request()`, but direct engine callers bypass this.

**Fix:** Extract `to_harmony_structured_outputs()` from `_adjust_output_format()` in `vllm/parser/harmony.py`, then call it from `InputProcessor.process_inputs()` when the reasoning parser is `openai_gptoss` and `enable_in_reasoning` is off. This wraps plain constraints in the Harmony structural tag so the grammar only applies to the `<|channel|>final` section, preserving the `<|channel|>analysis` reasoning channel.

- Requests that already carry a `structural_tag` are left as-is
- Only activates when `reasoning_parser == "openai_gptoss"` and `enable_in_reasoning` is disabled
- The existing OpenAI serving path is unchanged (refactored to use the same extracted function)
