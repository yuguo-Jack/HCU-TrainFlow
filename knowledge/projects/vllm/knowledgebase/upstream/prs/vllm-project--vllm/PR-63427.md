# [Bugfix][CUDA Graph] Weak-ref nested outputs of captured graphs

[Upstream PR](https://github.com/vllm-project/vllm/pull/63427) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

`weak_ref_tensors` only weak-refs one level. For a model output like `(hidden_states, [aux_hidden_states, ...])`, the inner list is returned as is, so every captured CUDA graph entry keeps its aux hidden states alive and the graph pool cannot reuse that memory for the next capture size. This PR makes `weak_ref_tensors` recurse into nested lists/tuples.

Related: #63406 lists this as "aux hidden states kept by every PIECEWISE size" in its memory breakdown. This PR is the standalone fix and also applies to main's capture sizes.

## Claims

- Captured graphs no longer pin the aux hidden states used by EAGLE3, DSpark, DFlash and `extract_hidden_states`. Before, each captured size leaked `num_aux × num_tokens × hidden_size × dtype_size` bytes (3 × 8192 × 4096 × 2 B = 192 MiB for one 8192-token size of DeepSeek-V4-Flash).
- No output change: the outputs alias the same memory as before; only the references held by the graph entries become weak.
- `weak_ref_tensors` now raises on unknown types at any nesting level, not only at the top level, and passes ints and `LayerName`s through (piecewise subgraph outputs can contain ints, and Inductor graph partition outputs can contain `LayerName`s, see below).

## Details

**Affected paths.** `weak_ref_tensors` is called on capture outputs by:
- `BreakableCUDAGraphWrapper._capture`: captures the whole model forward, so EAGLE3/DSpark targets return `(hidden_states, [aux, ...])`. Breakable CUDA graph is on by default for DeepSeek-V4/V4.1, MiniMax-M3, GLM-5-Next, Kimi-K3 and others, under both model runners.
- `CUDAGraphWrapper` in FULL mode on MRV1, which also wraps the whole model.

Not affected: torch.compile piecewise subgraph outputs are flat, and MRV2 FULL graphs copy outputs into persistent buffers instead of weak-refing them.

**Safety of the weak refs.** Once the aux tensors are weak, later captures may reuse their memory, the same as for `hidden_states` today. So the aux tensors must be consumed before the next graph replay. Every consumer copies them first: MRV1 `torch.cat`/`torch.stack` in `gpu_model_runner.py`, MRV2 DFlash `_store_hidden_states` (concatenates into its staging buffer), MRV2 `extract_hidden_states` (`torch.stack` + `copy_`).

**Type contract.** Previously, non-tensor values inside a list/tuple passed through `weak_ref_tensor` silently, which is how the nested list slipped through. Now containers recurse, ints and `LayerName`s pass, and any other type raises with its type name. The tradeoff: a model whose capture output contains a leaf type not in the table above (e.g. `None`) fails at capture time instead of passing silently. The raise already caught one such case before (`IntermediateTensors`, #24275), and caught `LayerName` in this PR's first CI run.

**Not a duplicate:** no open PR touches `weak_ref_tensors` or this leak. #63406 changes capture sizes and only references the leak in its memory accounting.

The fix and analysis originate from Bo Pang (co-author). AI assistance (Claude Code) was used to write the change, the tests and the validation scripts.
