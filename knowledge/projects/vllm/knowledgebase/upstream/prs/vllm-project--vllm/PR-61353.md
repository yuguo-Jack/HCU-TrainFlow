# [Bugfix][Spec Decode] Fix DFlash capture on FLEX_ATTENTION and honor drafter enforce_eager

[Upstream PR](https://github.com/vllm-project/vllm/pull/61353) · state: open · merged: False

## Original PR description

## Overview

Fixes #61337. DFlash on `FLEX_ATTENTION` failed at startup during drafter CUDA graph capture, and the reporter's documented workaround (`--speculative-config.enforce_eager true`) had no effect. Two independent breaks on the same path, both fixed here.

## Claims

- `_prepare_dflash_inputs_to_capture` now passes the dummy batch's `seq_lens_cpu_upper_bound` into `build_attn_metadata`, satisfying the `FlexAttentionMetadataBuilder.build_for_cudagraph_capture` assertion (`seq_lens_cpu_upper_bound is not None`) that killed capture before any draft weight was touched.
- `--speculative-config.enforce_eager true` now actually reaches the drafter: the draft `ModelConfig` honors the override instead of unconditionally inheriting the target's `enforce_eager`, and `DFlashSpeculator.init_cudagraph_manager` short circuits to `CUDAGraphMode.NONE` when the draft config is eager, so no draft graphs are captured while the target keeps its own.

## Validation

No GPU on this machine, so the capture path itself is covered by CPU-level pinning plus red/green checks; the end-to-end startup reproducer needs an H100 and is called out honestly below.

New tests (both files run on CPU):

```bash
python -m pytest tests/v1/spec_decode/test_dflash_capture_metadata.py tests/v1/spec_decode/test_dflash_enforce_eager.py -q
# 9 passed
```

- `test_dflash_capture_metadata.py` records the kwargs handed to `build_attn_metadata` from the real `_prepare_dflash_inputs_to_capture` and pins that `seq_lens_cpu_upper_bound` is present and tracks the per-request dummy split (even and uneven). Without the fix both tests fail with the field missing; with it they pass.
- `test_dflash_enforce_eager.py` pins the draft config override matrix (`True`/`False`/`None` against both target states) through the real `SpeculativeConfig` construction, and pins that DFlash's manager receives `CUDAGraphMode.NONE` when the draft is eager and the untouched `FULL_DECODE_ONLY` otherwise. The three key cases fail on unmodified main.
- Regression: `tests/v1/spec_decode/test_dflash_causality.py`, `test_dflash_prepare_inputs.py`, `tests/config/test_speculative_draft_max_position_embeddings.py` pass (20 passed, 5 skipped). `tests/config/test_speculative_draft_hf_overrides.py` could not be collected locally because this machine's transformers build predates `Glm5NextConfig`; that is an environment limitation, not a regression from this diff.
- Not run: the reporter's end-to-end `vllm serve ... --speculative-config.method dflash` startup on H100 (no GPU access here). The dflash acceptance e2e in CI exercises the captured path.

## Details

Root cause 1: `build_attn_metadata` gained the `seq_lens_cpu_upper_bound` parameter for capture-time static sizing, and every other caller (the base speculator's `_build_attn_metadata`, the model runner, the PCP manager) passes it. DFlash's standalone capture path in `dflash/cudagraph.py` was left behind. The dummy batch already computes the right value (`InputBatch.make_dummy` sets it from the per-request token split), so the fix is a pass-through.

Root cause 2: `SpeculativeConfig.enforce_eager` is declared as the draft-side override ("Override the default enforce_eager from model_config") but the draft `ModelConfig` construction ignored it, and nothing in the V2 runner consumed a draft-level eager setting. This PR makes the field effective for DFlash (the reporter's path). The same gap likely exists for the other `DraftModelSpeculator` subclasses; I kept this change scoped to the reported path and can follow up if maintainers want the override honored uniformly.

Tradeoff note: tests use a recording stand-in for `build_attn_metadata` and a faked block table, because the real capture path requires CUDA graph capture on a GPU. The pinned behavior is the contract boundary the assertion guards, which is the level the regression occurred at.
