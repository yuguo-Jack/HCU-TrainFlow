# [Docs] Fix VLLM_CPU_KVCACHE_SPACE default and units

[Upstream PR](https://github.com/vllm-project/vllm/pull/60053) · state: closed · merged: True

## Original PR description



## Overview

Fixes #60048. The docs for `VLLM_CPU_KVCACHE_SPACE` differ from the code and from each other: one section claims a 4GB default while the code default is 0 (no override), and units flip between GB and GiB across pages.

## Claims

- docs/getting_started/installation/cpu.md: corrected to default 0 (no override), value in GiB, marked as legacy with a pointer to --kv-cache-memory-bytes
- docs/configuration/conserving_memory.md: same default/unit correction in the CPU backend bullet
- vllm/platforms/cpu.py: comment typo fix ("Lagecy" -> "Legacy")

## Validation

Verified against source on main: vllm/envs.py:52 (default 0) and vllm/platforms/cpu.py:307 (env var only applied when set, value multiplied by GiB_bytes, marked legacy). Docs build not run locally (Windows, no CUDA extensions), changes are single-line markdown edits, verified via git diff.

## Details

Root cause: the code default changed to 0 (legacy setting) but parts of the docs kept the old 4GB text, and GB/GiB usage drifted between pages.
