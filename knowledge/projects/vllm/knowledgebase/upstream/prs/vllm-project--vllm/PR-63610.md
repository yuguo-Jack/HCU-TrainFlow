# [KV Connector][NIXL] Send the Mamba boundary state so the decode pod can prefix-hit

[Upstream PR](https://github.com/vllm-project/vllm/pull/63610) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

With NIXL P/D on a hybrid Mamba model (prefix caching on, Mamba `align` mode), the decode instance now also gets the prompt's Mamba state at its last full block. So a later turn sent to the decode instance alone (conditional disaggregation) gets a prefix hit instead of recomputing the whole prompt. Opt-in via `kv_connector_extra_config.ssm_boundary_state_xfer`, off by default.

## Claims

- Flag on: the decode instance's prefix-cache hit rate on second turns goes from 0% to 59% (Qwen3.5-9B, 1P1D), with no accuracy change.
- Flag off (default), or set on only one side: behaviour is unchanged. P/D peers that differ still work.
- Pull mode only. The push connector is unchanged. Off with decode context parallel (DCP > 1).

## Validation

**End-to-end, 1P1D on 2x H200, Qwen3.5-9B** (`--enable-prefix-caching --enforce-eager`, attention block size 576). There are 100 GSM8K conversations, each with a different 5-shot prefix, sent with greedy sampling and 8 at a time. Turn 1 goes through `toy_proxy_server.py` (P then D). Turn 2 (turn 1 + answer + new question) goes straight to D.

| `ssm_boundary_state_xfer` | Turn-1 acc | Turn-2 acc | D prefix hit tokens on turn 2 | D hit rate on turn 2 |
|---|---|---|---|---|
| false (default) | 0.84 | 0.89 | 0 / 123,032 | 0.0% |
| true | 0.85 | 0.87 | 73,152 / 123,251 | 59.4% |

Turn 1 runs the same code either way, yet 20 of its 100 outputs differ between the two runs. That's run-to-run nondeterminism from batching (vLLM is not batch-invariant by default), so the ±0.02 accuracy differences are noise.

## Details

**Why the hit was 0.** In P/D the prefiller computes N-1 prompt tokens and sends only its running state h(N-1). The decoder caches the prompt's attention blocks, but a Mamba prefix hit needs a saved state at a block boundary, and none was sent.

**Flow with the flag on** (N = prompt tokens after the prefiller's 1-token truncation, B = block size, b = floor(N / B) * B):

1. P, `on_new_request`: if 0 < b < N, records b for the request.
2. P, `build_connector_meta`: when the KV cache manager offers the align-mode state at b, pins that block (`touch`).
3. P, `request_finished`: puts the pinned block before the running state in each Mamba group of `remote_block_ids` and adds `remote_ssm_boundary_tokens = b`.
4. D, `get_num_new_matched_tokens`: if `remote_ssm_boundary_tokens` equals D's own boundary and the local prefix hit doesn't already cover it, asks the KV cache manager to reserve a real block at b.
5. D, `build_connector_meta`: sends `[boundary, running]` for each Mamba group. After the read completes, `cache_blocks` hashes the boundary block with the loaded prefix.
6. P, `update_connector_output`: unpins the boundary block once `finished_sending` reports the send. Aborted requests are also unpinned.

**Compatibility.**
- When N is already a multiple of B, the running state is the boundary state, so nothing extra is sent.
- If P sends the extra slot and D did not reserve one (D has the flag off, or is an older version), the worker lines up the block lists from the end, so D still reads just the running state.
- With DCP > 1 the worker lines up block lists from the start instead, which would misalign the extra slot, so the feature stays off. Hybrid Mamba NIXL transfers already require P and D to have the same DCP size, so both sides turn it off together.

**Core changes.**
- `MambaManager.reserve_external_boundary_block` (wrapped by `KVCacheManager.reserve_external_boundary_blocks`) is a small hook that doesn't depend on a particular connector. It works only before the first allocation and does nothing unless a connector calls it.
- Block sizing counts the reserved block like an internal checkpoint block.

**Cost (flag on).** One extra pinned block on P per Mamba group per request, held until D has read it, plus one extra state transfer per Mamba group.

**Not a duplicate.** Searched open PRs for NIXL + Mamba/SSM boundary state, prefix caching and conditional disaggregation. None sends the boundary state. #48195 (per-group hit length for hybrid models) fixes a different problem.
