# [CI] Shard four AMD mirrors automatically

[Upstream PR](https://github.com/vllm-project/vllm/pull/61817) · state: closed · merged: True

## Original PR description

## Purpose

ci-infra#790 lets a native AMD mirror (`dind: false`) shard at runtime when its `mirror.amd` block sets `automatic_shard: true`, planned from its own `amd-<key>` timings on its own queue. This turns it on for the AMD mirrors of the first automatic-sharding batch (#60492), whose CUDA steps already shard:

| Mirror | Command | Planned shards |
|---|---|---:|
| `amd-v1-spec-decode` | `pytest -v -s -m 'not slow_test' v1/spec_decode` (with `VLLM_WORKER_MULTIPROC_METHOD=spawn`) | 2 |
| `amd-entrypoints-integration-pooling` | `pytest -v -s entrypoints/pooling` (with `VLLM_WORKER_MULTIPROC_METHOD=spawn`) | 2 |
| `amd-kernels-mamba-test` | `pytest -v -s kernels/mamba` | 2 |
| `amd-quantized-models-test` | `pytest -v -s models/quantization` | 2 |

None of them sets `mirror.amd.parallelism`, so the plan decides the job count. Without timings, or with the endpoint down, a mirror runs as one job as it does today.

## Test Plan

- Planned each mirror with ci-infra main's `runtime_shard.plan_step` against this branch and main's AMD timings: 2 shards each, balanced.
- The same four mirrors ran sharded in ci-infra#790's validation build 94536: all 8 shards passed and per-command passed/skipped counts matched a single-job main run.
- `/ci run` on this PR, then compare each mirror's shards against main.
