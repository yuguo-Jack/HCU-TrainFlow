# [Tests][Mamba] Wait for accepted counts in fake MTP proposer

[Upstream PR](https://github.com/vllm-project/vllm/pull/61342) · state: closed · merged: True

## Original PR description



## Overview

Fix `test_mamba_prefix_cache_mrv1` / `_mrv1_async`, failing on `main` since #61134 on H200 MIG and MI250 (e.g. [main build #94362](https://buildkite.com/vllm/ci/builds/94362#01a1333b-d247-49be-b767-84df48ec72c7)): `ValueError: Mamba state is not equal for key: 576 at index 0`. Test-only change.

## Claims

- The test's fake MTP proposer read `num_accepted_tokens_cpu` before the same-step non-blocking D2H copy finished, so a GPU lagging behind the host fed off-by-one draft tokens. It now waits on `num_accepted_tokens_event` first.
- No runner change: the real proposer uses GPU tensors, and the runner already synchronizes that event in `_prepare_inputs` before reading the CPU counts.

## Validation

The failure does not reproduce on GB200 as-is (fast GPU hides the race), so I injected GPU lag with a `sitecustomize.py` that runs `torch.cuda._sleep(20_000_000)` (~10 ms) at the start of every `GPUModelRunner.execute_model`:

| GB200, `-k test_mamba_prefix_cache_mrv1*` | before | after |
| --- | --- | --- |
| no injected lag | pass | pass |
| injected GPU lag, sync | **fail** (`key: 576 at index 0`, same as CI) | pass |
| injected GPU lag, async | — | pass |

```bash
pytest tests/v1/e2e/general/test_mamba_prefix_cache.py -k "test_mamba_prefix_cache_mrv1" -s
```

`pre-commit` passes.

## Details

- In `accept_2_1`, the mismatching conv state at token 576 differed only in row 0 (the token carried over from the previous step); rows 1-2, computed in the current step, matched the reference bit-exactly. That row was produced from a wrong draft token: the fake proposer computed its offset from a stale `num_accepted_tokens_cpu` (still the value written before `postprocess_mamba_align_gpu`'s non-blocking D2H landed).
- Why now: before #61134, FP8 dummy weights were ±1e-3 (mostly rounded to 0 in E4M3), so conv states were ~0 regardless of the input token and the comparison passed vacuously. With ±1 FP8 dummy weights the states are meaningful, and slow CI GPUs (16-SM H200 MIG slice, MI250) expose the race. `main` passed this test at c6566bb9f6 and fails from the next build onward; the other commits in that window only touch DSv4.1/ROCm or Intel CI yaml.
- Related but distinct: #51571 (row-ownership race of the same CPU tensor under async scheduling, fixed in the runner by #51599/#53919). This PR touches neither; the test runs a single request and fails without async scheduling too.
- Not a duplicate: no open PR touches `tests/v1/e2e/general/test_mamba_prefix_cache.py`.
