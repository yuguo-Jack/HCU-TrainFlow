# [Refactor][KV Connector][Mooncake] Move connector metadata and wire structs to their own modules

[Upstream PR](https://github.com/vllm-project/vllm/pull/62255) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Step S1 of #62243: move the Mooncake P2P connector metadata and wire structs into `mooncake/metadata.py` and `mooncake/protocol.py`. Definition-site move, no behavior change.

## Claims

- Definition-site move: `ReqId`, `TransferId`, `PullReqMeta`, `SendBlockMeta`, `MooncakeConnectorMetadata` move to `mooncake/metadata.py`; `MooncakeXferMetadata`, `MooncakeXferResponseStatus`, `MooncakeXferResponse` move to `mooncake/protocol.py`.
- Wire formats unchanged: every msgspec field order, default, `omit_defaults`, and status-code value (`FINISH=0`, `CONTINUE=1`, `ERROR=2`, `LAYOUT_MISS=3`) is byte-identical to `main`.
- Behavior unchanged: no logic edits; `mooncake_connector.py` still re-exports every moved name, so existing `from ...mooncake_connector import MooncakeXferMetadata` imports keep working.
- One rename inside the moved code: `MooncakeConnectorMetadata.reqs_not_processed` becomes `transfers_not_processed`, with the scheduler field it is assigned from.

## Details

Names moved, and their new homes:

| Definition | New module |
| --- | --- |
| `ReqId`, `TransferId` | `mooncake/metadata.py` |
| `PullReqMeta`, `SendBlockMeta` | `mooncake/metadata.py` |
| `MooncakeConnectorMetadata` | `mooncake/metadata.py` |
| `MooncakeXferMetadata`, `MooncakeXferResponseStatus`, `MooncakeXferResponse` | `mooncake/protocol.py` |

Dependency direction is one-way and acyclic: `protocol.py` imports `ReqId`/`TransferId` from `metadata.py`; `metadata.py` imports `KVConnectorMetadata` from `..base` and `EngineId` from `kv_connector/utils.py`, and does not import `protocol.py`. `mooncake_connector.py` imports both and keeps them in its namespace, so tests and any external imports of those names are unaffected.

The rename: `MooncakeConnectorMetadata.reqs_not_processed` holds `set[TransferId]`, not request ids, while the identically named field in `nixl/metadata.py` does hold `set[ReqId]`. Since the definition moves here, it is renamed to `transfers_not_processed` together with the scheduler field assigned into it (`_transfers_not_processed`). Seven lines in the package and one attribute name in an existing assertion in `test_mooncake_connector.py`; no assertion semantics change, no wire impact.

Names inside the moved code that were left alone, and why:

- msgspec field names in `protocol.py` are wire keys; renaming any of them changes the encoded format.
- `reqs_to_recv` / `reqs_to_send` / `need_send` / `sent` / `sending` / `PullReqMeta` / `SendBlockMeta` / `d_req_id` / `p_req_id` keep their names: `reqs_to_recv` and `reqs_to_send` are shared with `nixl/metadata.py`, and #61974 constructs `SendBlockMeta(p_req_id=...)` and inserts `aborted` next to `sending`, so renaming those here would only move conflict into that PR.
- The `mooncake_` prefix in `mooncake_connector.py` / `mooncake_utils.py` and the `MooncakeXfer*` class names belong to the later steps: #62243 keeps `mooncake_connector.py` as the compatibility shim until `connector.py` exists in S5.

Out of scope, deliberately: the worker split, scheduler split, bootstrap helpers, region planning, facades, and a new `connector.py` (steps S2-S5 of #62243). The two wire protocols are not unified here.

## Why this is not a duplicate

- No other open PR moves these definitions; no open PR references #62243 in its body.
- #57309 touches the same file only to swap the spec-classification helpers to framework spec kinds; it moves no metadata or wire struct, and none of its hunks overlap the renamed lines.
- #61974 adds `mooncake_pull_connector.py` and a `compat.py`; its compatibility hash stays where that PR puts it, and is not absorbed here.
