# [Doc] Document MiniMax-M3 GB200 Dynamo AgentX profile

[Upstream PR](https://github.com/vllm-project/vllm/pull/62543) · state: closed · merged: True

## Original PR description

## Overview

Document the MiniMax-M3 NVFP4 GB200 aggregated Dynamo + vLLM profile qualified in [SemiAnalysisAI/InferenceX#4281](https://github.com/SemiAnalysisAI/InferenceX/pull/4281) (head `7aa70626`). Recipes for vLLM-served models live here since #61302, so this changes only `recipes/models/MiniMaxAI/MiniMax-M3.yaml`: a guide section plus the selector fields that make the command builder render the qualified GB200 worker command.

## Claims

- New guide section **GB200: InferenceX AgentX aggregated (Dynamo + vLLM)**:
  - the six tested points (TP4 on one tray, TP8 across two trays) with `--max-num-seqs` and CUDA graph capture sizes
  - etcd and NATS services, and the worker environment, including the `mnnvl` all-reduce backend for TP8
  - the `python3 -m dynamo.vllm` worker command with the GQA EAGLE3 draft
  - SimpleCPUOffload host KV offload for the higher-concurrency points
  - the Dynamo frontend with the KV-aware router and session affinity
- It builds on the existing NVFP4 section's attention and draft settings rather than repeating their rationale.
- **Selector (command builder):**
  - `meta.hardware.gb200: verified` (end-to-end InferenceX run below) and `meta.default_variant.gb200: nvfp4`.
  - `variants.nvfp4.hardware_overrides.gb200`: the pinned nightly image, `--enable-prefix-caching`, `--max-num-batched-tokens 16384`, `--gpu-memory-utilization 0.9`, `--no-enable-flashinfer-autotune`, `--stream-interval 20`, and `NCCL_CUMEM_ENABLE` / `NCCL_MNNVL_ENABLE` / `NCCL_NVLS_ENABLE`.
  - `features.spec_decoding.modes.eagle3_gqa.hardware_overrides.gb200`: FlashInfer draft attention with `use_local_argmax_reduction`.
  - `strategy_overrides.multi_node_tp.hardware_overrides.gb200`: `VLLM_FLASHINFER_ALLREDUCE_BACKEND=mnnvl` for TP8 across two trays.
  - A guide pointer explaining which selections reproduce the profile.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` from vllm-project/recipes passes.
- The worker commands are the ones the InferenceX run launched (taken from its server logs), minus benchmark-only arguments: synthetic acceptance, config dumps and the duplicated served-model name. Image `vllm/vllm-openai:nightly-5555a2d8f7116b2b4877f66516f4128176cf722a`, Dynamo `1.6.0.dev20261016`.
- Rendered with `resolveCommand` (GB200, NVFP4, Spec Decoding → GQA, text-only, reasoning, tool calling):
  - Single-node TP renders `--tensor-parallel-size 4` with the qualified worker flags and env; Multi-node TP with 2 nodes renders TP8 (`--nnodes 2`, `--headless` follower) with `VLLM_FLASHINFER_ALLREDUCE_BACKEND=mnnvl`.
  - Compared with the run's TP4 and TP8 `dynamo.vllm` launch lines, every engine flag matches except per-point `--max-num-seqs` / `--compilation-config` capture sizes (in the guide table), Dynamo-only flags (`--request-plane`, `--kv-events-config`, `--dyn-*` parsers) and harness flags (synthetic acceptance, `--kv-cache-metrics`, config dumps). `--max-model-len 1048576` and `--pipeline-parallel-size 1` equal the defaults.
  - Every hardware/variant/strategy/spec-mode/KV-offload combination for the other hardware renders byte-identically to `main` (6,228 combinations). On GB200, the GQA draft override and the TP8 all-reduce env also apply to the other variants, since feature modes and strategy overrides cannot be scoped per variant.
- InferenceX sweep: [run 39150937290](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/39150937290), attempt 1, all points green on the PR head.

## Details

Excluded as benchmark harness only:
- synthetic acceptance length
- AIPerf trace-replay settings
- Slurm and sbatch options, health checks and telemetry
- `ETCD_LEASE_TTL` and log-interval settings
- `kv-cache-metrics`

Loading timeouts are described rather than pinned. RDMA device selection (`UCX_NET_DEVICES`, `NCCL_IB_HCA`) is left to the deployment.

Selector limits, kept in the guide:
- per-concurrency `--max-num-seqs` and CUDA graph capture sizes;
- the Dynamo KV-router frontend and etcd/NATS services (the builder's Dynamo option exists only for `pd_cluster`);
- the exact SimpleCPUOffload budget (about 181 GiB per rank, lazy offload, `VLLM_USE_SIMPLE_KV_OFFLOAD=1`); the builder's **KV Offload → Simple** pill emits the same connector with its fixed default budget.

### Review follow-up (d8922cb1)

Addresses an independent render-based review:
- The builder keeps the current variant on a hardware switch, so the guide now says to pick **NVFP4** explicitly and gives deep links for TP4 and TP8; the ineffective `meta.default_variant.gb200` is dropped. The GB200 **Verified** badge is documented as NVFP4-only.
- Builder steps add **Text-only** (`--language-model-only`); TP8 adds `--headless` on node rank 1.
- Services: NATS with JetStream (as in the run), and `ETCD_ENDPOINTS` / `NATS_SERVER` for workers and frontend; frontend adds `DYN_REQUEST_PLANE=tcp` and `DYN_TCP_REQUEST_TIMEOUT=60`, names the `X-Dynamo-Session-ID` header, and notes the `--router-temperature` deprecation (FutureWarning in the run's frontend log).
- The **KV Offload → Simple** pill's fixed budget (220 GiB/rank, `lazy_offload: false`) is called out with the qualified replacement and `VLLM_USE_SIMPLE_KV_OFFLOAD=1`.
- Synthetic-acceptance disclosure (golden GQA AL 2.78) for the throughput points, the image digest, GB200 in the NVFP4 description, and YAML comments noting that the GB200 GQA and TP8 all-reduce overrides apply to every variant on GB200 (only NVFP4 was qualified).

Validation: `validate-source.mjs --source vllm` passes; renders are byte-identical to the previous head (guide/comments/metadata only) and differ from `main` only on GB200 (756 of 44,352 renders); the TP4 and TP8 deep-link selections render every qualified engine flag.
