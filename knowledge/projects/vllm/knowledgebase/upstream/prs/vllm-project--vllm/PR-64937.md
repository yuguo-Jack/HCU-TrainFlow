# [Bugfix][Benchmark] Count reasoning_content deltas as streamed outputs in chat

[Upstream PR](https://github.com/vllm-project/vllm/pull/64937) · state: closed · merged: True

## Original PR description



## Overview

Some servers, like SGLang, send reasoning tokens in a field called `reasoning_content`. vLLM uses `reasoning`. Since #62341, the chat benchmark client only looks for `reasoning`, so it skips SGLang's reasoning tokens.

Two things go wrong:
- TTFT is measured to the first answer token instead of the first reasoning token, so it looks much slower than it really is.
- A response that ends before the model starts answering is counted as failed.

This PR makes the client accept `reasoning_content` too.

## Claims

- TTFT is measured to the first reasoning token again, as it was before #62341. A stub streaming SGLang's chunks went from 842 ms to 205 ms, against a true 201 ms.
- Reasoning-only responses go from 0/20 to 20/20 successful.
- No change for vLLM's own server, which streams `reasoning`.

## Validation

Two tests added to `tests/benchmarks/test_endpoint_request_func_timing.py`: reasoning followed by an answer (TTFT and ITL), and a reasoning-only stream (success). Both are parametrized over `reasoning` / `reasoning_content` and both clients. 46 passed. The 4 `reasoning_content` cases fail on `main` (`assert 1 == (4 - 1)` and "Never received a valid chunk to calculate TTFT"). pre-commit passes.

End to end: `vllm bench serve --backend openai-chat`, 20 prompts, concurrency 4, against a local stub that streams SGLang's chunk sequence. The stub sends its first output at 200 ms, then 30 reasoning and 10 answer tokens 20 ms apart, and logs its own send times. Two runs each:

| | `main` | this branch | stub's send log |
|---|---|---|---|
| mean TTFT | 843 / 841 ms | 206 / 205 ms | first reasoning token ≈ 201 ms |
| reasoning-only, successful | 0 / 20 | 20 / 20 | 30 tokens sent per request |

<details><summary>Stub server and command</summary>

`stub_sglang_server.py` sends the same chunk sequence as SGLang's streaming chat endpoint, with fixed timings, and logs when it sent the first reasoning and answer tokens:

```python
"""Minimal stub of SGLang's streaming chat endpoint, for integration-testing a client.

It reproduces the chunk sequence SGLang streams as of sgl-project/sglang 504f9cf
(sse_utils.py StreamDelta/StreamChoice, omit_defaults=True; serving_chat.py):
  opening chunk  delta {"role": "assistant", "content": "", "reasoning_content": null},
                 sent when the first engine output arrives
  reasoning      delta {"reasoning_content": "..."}          (no `content` key)
  answer         delta {"content": "...", "reasoning_content": null}
  finish         delta {"reasoning_content": null}, finish_reason set
  usage          "choices": [] plus "usage"
Every choice carries logprobs, finish_reason and matched_stop, as StreamChoice serializes them.
It uses fixed, known timings and logs server-side send times per request as ground truth.

Usage: python stub_sglang_server.py --port 18731 --log ground_truth.jsonl
Binds to 127.0.0.1 only.
"""

import argparse
import asyncio
import json
import time

from aiohttp import web


def _chunk(delta: dict, finish_reason=None) -> bytes:
    # StreamChoice always serializes logprobs, finish_reason and matched_stop.
    choice = {
        "index": 0,
        "delta": delta,
        "logprobs": None,
        "finish_reason": finish_reason,
        "matched_stop": None,
    }
    body = {
        "id": "chatcmpl-stub",
        "object": "chat.completion.chunk",
        "created": int(time.time()),
        "model": "stub",
        "choices": [choice],
    }
    return f"data: {json.dumps(body)}\n\n".encode()


def _usage_chunk(usage: dict) -> bytes:
    # SGLang's final usage chunk carries no choices (serving_chat.py ~2792-2796).
    body = {
        "id": "chatcmpl-stub",
        "object": "chat.completion.chunk",
        "created": int(time.time()),
        "model": "stub",
        "choices": [],
        "usage": usage,
    }
    return f"data: {json.dumps(body)}\n\n".encode()


def make_app(args) -> web.Application:
    log = open(args.log, "a", buffering=1)

    async def chat(request: web.Request) -> web.StreamResponse:
        t0 = time.perf_counter()
        await request.json()
        resp = web.StreamResponse(headers={"Content-Type": "text/event-stream"})
        await resp.prepare(request)

        sent = {}
        # SGLang sends the opening role chunk when the first engine output arrives.
        await asyncio.sleep(args.first_token_ms / 1000)
        await resp.write(_chunk({"role": "assistant", "content": "", "reasoning_content": None}))
        for i in range(args.reasoning_tokens):
            if i:
                await asyncio.sleep(args.itl_ms / 1000)
            await resp.write(_chunk({"reasoning_content": f"r{i} "}))
            sent.setdefault("first_reasoning_s", time.perf_counter() - t0)
        for i in range(args.answer_tokens):
            await asyncio.sleep(args.itl_ms / 1000)
            await resp.write(_chunk({"content": f"a{i} ", "reasoning_content": None}))
            sent.setdefault("first_answer_s", time.perf_counter() - t0)
        n = args.reasoning_tokens + args.answer_tokens
        # Finish chunk: build_sse_content(finish_reason=...) gives delta {"reasoning_content": null}.
        await resp.write(
            _chunk({"reasoning_content": None}, finish_reason="stop" if args.answer_tokens else "length")
        )
        await resp.write(_usage_chunk({"prompt_tokens": 8, "completion_tokens": n, "total_tokens": 8 + n}))
        await resp.write(b"data: [DONE]\n\n")
        log.write(json.dumps({**sent, "tokens": n}) + "\n")
        return resp

    async def models(_request: web.Request) -> web.Response:
        return web.json_response({"object": "list", "data": [{"id": "stub", "object": "model"}]})

    app = web.Application()
    app.router.add_post("/v1/chat/completions", chat)
    app.router.add_get("/v1/models", models)
    return app


if __name__ == "__main__":
    p = argparse.ArgumentParser()
    p.add_argument("--port", type=int, default=18731)
    p.add_argument("--log", default="ground_truth.jsonl")
    p.add_argument("--first-token-ms", type=float, default=200.0)
    p.add_argument("--reasoning-tokens", type=int, default=30)
    p.add_argument("--answer-tokens", type=int, default=10)
    p.add_argument("--itl-ms", type=float, default=20.0)
    a = p.parse_args()
    web.run_app(make_app(a), host="127.0.0.1", port=a.port, print=None)
```

Run it, then benchmark it:

```bash

vllm bench serve --backend openai-chat --base-url http://127.0.0.1:18731 \

  --dataset-name random --random-input-len 16 --random-output-len 40 \

```

## Details

SGLang streams reasoning only as `reasoning_content`; its reasoning deltas carry no `content` key (`StreamDelta` in `sglang/srt/entrypoints/openai/sse_utils.py`). It fixed the same issue in its own benchmark client (sgl-project/sglang#23954). The Rust `vllm-bench` ports in #64626/#64627 have the same gap; I'll note it there.

No issue or PR covers this. #64703 edits the same file on different lines and applies independently.

AI assistance (Claude) was used to find this and write the change and tests. I reviewed every line and ran the tests and the end-to-end comparison.
