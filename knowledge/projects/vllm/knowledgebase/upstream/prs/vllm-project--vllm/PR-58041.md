# [Bugfix][HiSparse][NIXL] Keep a paused decoder stepping while split reads are in flight

[Upstream PR](https://github.com/vllm-project/vllm/pull/58041) · state: open · merged: False

## Original PR description

> [!NOTE]
> Rescoped by @MatthewBonanni (1fab475): this PR now carries only the HiSparse split-read fix, done in the NIXL connector with no core change. @S1ro1's general P/D change (cache-preserving keep pauses no longer waiting on retained KV exports) moved to #59670. The original description and live RL validation are preserved there.

## Purpose

Fix a P/D pause stall with HiSparse decoders. Since #53780, a NIXL read into a decoder with mixed DRAM/VRAM KV (HiSparse) is split into one transfer per memory type, and the producer is notified only once a worker polls both done. A `pause(mode="keep")` on the decoder hides its `WAITING_FOR_REMOTE_KVS` requests, so the engine stops stepping, nothing polls, and the notification is never sent. The producer keeps those blocks until its lease expires, and a keep pause on the producer waits for them.

## Changes

`NixlBaseConnectorScheduler` tracks reads it has handed to the workers (`awaiting_kvs`) until they come back in `finished_recving`, and reports them through the existing `has_pending_push_work()` hook, which `Scheduler.has_requests()` already honors. A paused decoder keeps running zero-token connector steps until its in-flight reads complete and their notifications go out.

- Failed reads and aborted waiting requests also arrive in `finished_recving`, so the set always drains.
- Unpaused behavior is unchanged: waiting requests already keep the engine stepping.
- Push mode overrides the hook and never marks a read as awaiting.

## Test Plan

- New `test_keep_pause_steps_until_remote_kv_arrives` (`tests/v1/kv_connector/unit/test_remote_prefill_lifecycle.py`): with a read in flight, a keep pause must keep `has_requests()` true until the receive finishes.
- NIXL / connector unit tests on CPU.
- GPU: 2×H100, shrunk DeepSeek-V3.2 (dummy weights). P is plain NIXL (pull rejects a mixed-memory producer); D is NIXL + HiSparse. A warm-up request completes the handshake; for the next request, a debug-only hook pauses D (keep) right after the step that issues its read, then the driver pauses P (keep, `clear_cache=false`).
