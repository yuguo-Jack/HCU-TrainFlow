# [Bugfix] Swap ipc_cache tensors into meta placeholders in place

[Upstream PR](https://github.com/vllm-project/vllm/pull/62115) · state: open · merged: False

## Original PR description

## Summary

`IpcModelLoader._apply_entries` replaced each meta placeholder with a **new** `nn.Parameter` object. Objects that captured the placeholder during model construction kept pointing at the meta tensor. MoE routers are such objects: models pass `gate.e_score_correction_bias` into the MoE layer, and the router (a plain `FusedMoERouter`, not an `nn.Module`) keeps it as a plain attribute — so after loading via `--load-format ipc_cache`, every router still held the meta placeholder and failed at runtime (CUDA illegal memory access / meta-tensor errors). Thank you to the reporter for the thorough issue and the minimal reproducer, which made the root cause easy to confirm.

This PR swaps the cached tensor **into the existing placeholder** with `torch.utils.swap_tensors`, preserving object identity so every captured reference sees the cached data. A plain `param.data` assignment cannot do this — it fails for meta tensors (`RuntimeError: ... incompatible tensor type`, verified on torch 2.14.1).

Two supporting changes, each verified necessary with a failing-then-passing check:

- **Buffers are applied before parameters.** `MambaMixer2` registers `conv_weights` as a view of the meta `conv1d.weight`, and `swap_tensors` refuses while such a view is alive (verified: `RuntimeError: Expected use_count of t1 to be 1 or 2 ... got 3`). Replacing the buffer first releases the view. The sort is stable, so relative order within each kind is preserved.
- **The tied-weight alias path only re-points, never swaps.** The canonical object already holds the cached data after the in-place swap; swapping an alias placeholder into it would move the meta tensor *back* into the canonical entry (verified: canonical `is_meta` becomes `True` again — silent corruption into uninitialized weights).

## Not a duplicate

I checked the issue timeline (no cross-referenced PRs) and searched open PRs for `ipc_cache`, `_apply_entries`, and `swap_tensors` — no open PR addresses this issue. Fixes #62105.

## Reproduction (CPU-only, copy-paste runnable)

The issue's minimal reproducer, run verbatim:

```python
import torch
from torch import nn

class Gate(nn.Module):
    def __init__(self):
        super().__init__()
        self.e_score_correction_bias = nn.Parameter(torch.empty(4), requires_grad=False)

class Router:  # plain object, like GroupedTopKRouter
    def __init__(self, e_score_correction_bias):
        self.e_score_correction_bias = e_score_correction_bias

def build():
    with torch.device("meta"):
        gate = Gate()
    return gate, Router(gate.e_score_correction_bias)

cached = torch.arange(4.0)

# What IpcModelLoader._apply_entries did before this PR
gate, router = build()
gate._parameters.pop("e_score_correction_bias")
gate.register_parameter("e_score_correction_bias", nn.Parameter(cached, requires_grad=False))
print("replace:", router.e_score_correction_bias.is_meta, router.e_score_correction_bias is gate.e_score_correction_bias)

# What it does after this PR
gate, router = build()
torch.utils.swap_tensors(gate.e_score_correction_bias, nn.Parameter(cached, requires_grad=False))
print("swap:", router.e_score_correction_bias.is_meta, router.e_score_correction_bias is gate.e_score_correction_bias)
```

Before (old behavior):
```
replace: True False
```
After (this PR):
```
swap: False True
```

## Checklist notes

- **Design fit:** change is isolated to the weight-cache loader (`_apply_entries` only, one caller); ~50 lines; no new abstractions or API changes.
- **Performance:** load-time only; adds one stable sort over the entry dict. No steady-state inference impact, no new synchronization.
- **Compatibility:** `torch.utils.swap_tensors` requires torch>=2.1, well below vLLM's floor. On shape/dtype mismatch it behaves with the same leniency as the old replace path (verified). Non-meta placeholders fall back to the old registration path.
