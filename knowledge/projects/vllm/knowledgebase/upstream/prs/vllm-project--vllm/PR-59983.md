# [Spec Decode][Mamba] RecoverSSM: support pipeline parallelism (non-last ranks commit in the deferred PP postprocess)

[Upstream PR](https://github.com/vllm-project/vllm/pull/59983) · state: open · merged: False

## Original PR description

Follow-up to #58863, as suggested there. **Stacked on #58863; only the last commit is new.** Independent of #59982 (XPU routing); either can merge first. The hardware run below used both changes.

## Purpose

`RecoverSSMState` holds one recorded step and commits it right after sampling. A non-last PP rank does not sample: it runs its postprocess `pp_size` steps later (`PPHandler.get_prev_sampled_outputs`), after the other micro-batch has recorded its own step. That is why RecoverSSM rejects `pipeline_parallel_size > 1`.

On non-last ranks, this detaches the recorded step right after `receive`, attaches it to the PP slot, and commits that step with the slot's `num_sampled`:
- `detach_step` clones the small commit index tensors, since later builds can rewrite them (FULL graphs stage them in persistent buffers). The replay records live in each request's own state block, so they stay intact.
- Rows whose request was freed while the commit was pending (idx -1) get an accepted count of 0, so the commit kernel skips them; their state block may already belong to a new request.
- `num_sampled` from the PP broadcast is padded past `num_reqs`; only the first `len(idx_mapping)` rows are used.

The last rank keeps the existing path. RecoverSSM with `pipeline_parallel_size > 1`, previously rejected, is now accepted. Align mode is not wired through the deferred path yet, so PP > 1 with `--mamba-cache-mode align` is still rejected.

## Test Result

- **Unit tests (CPU)**, `tests/v1/worker/test_recoverssm_pp_commit.py`: the detached step keeps its commit tensors when the buffers are rewritten; a deferred commit uses the given step, not the current record; freed rows get 0; padded rows are ignored. Plus a config test that PP=2 without align is accepted. With `tests/config/test_recoverssm_config.py`: 22 passed. `ruff check` / `ruff format` pass.
- **Tested on hardware**: 2× Intel Arc Pro B70, Qwen3.8-Flash-Next, PP=2, TP=1, MTP K=1, on our own tree with the same logic (plus #59982's routing). It ran; MTP acceptance stayed within the window-to-window variation, and per-token logprobs stayed within the run-to-run noise versus the Triton/FLA path without RecoverSSM.
- **Not tested**: this exact branch on hardware, CUDA with PP > 1, PP > 2, MTP K > 1, TP > 1 combined with PP, or the KDA RecoverSSM path.

AI assistance (Claude Code) was used; every changed line was reviewed by the submitter.
