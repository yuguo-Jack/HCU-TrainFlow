## Original PR description

# [Bugfix][KV Offload] Record GPU-local prefix reuse in offload recency

## Summary

The CPU offload cache can hold a backing copy of a prefix that is also
resident on GPU. When a request hits that prefix on GPU, it bypasses
`prepare_load()`, so CPU recency is not updated. The CPU cache may then evict
the backing copy even though the prefix was just reused.

This change records the GPU-local hit as a request-scoped access. It only
refreshes recency for keys already present and ready in CPU; it does not load,
store, or backfill GPU-only keys. Existing load/store decisions are unchanged.

## Implementation

- Add `record_access()` to `OffloadingManager` and propagate it through
  tiering.
- Record the retained GPU-local prefix once per request, including sliding
  window boundaries.
- Keep `prepare_load()` and `prepare_store()` semantics unchanged.
- Add CPU policy, scheduler, and tiering tests.

Example (simplified LRU):

```text
CPU LRU: A (oldest), B    GPU: A
Request reuses A on GPU; no CPU load is needed.
Before: CPU order unchanged; inserting D may evict A.
After:  A becomes recent; inserting D may evict B instead.
Later, if A leaves GPU, its CPU copy can still serve as a fallback.
```

## Relationship to existing work

- #51787 introduced request-scoped recency tracking; this fixes the missing
  GPU-local access source.
- #57325 changes joint lookup for `SimpleCPUOffloadConnector`; this change
  targets recency accounting in `OffloadingConnector`.
- #57646 exposes processed-prefix metadata; it does not update cache recency.
