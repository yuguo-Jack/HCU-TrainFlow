# [ROCm][CI] Enable batch invariance for eagle3 scheduling accuracy

[Upstream PR](https://github.com/vllm-project/vllm/pull/62893) · state: closed · merged: True

## Original PR description

## Summary
Enable `VLLM_BATCH_INVARIANT` on ROCm for the eagle3 async-scheduling accuracy test.
ROCm hipBLASLt may select different GEMM solutions depending on batch shape. This can introduce small numerical differences between synchronous and asynchronous scheduling, changing near-tie greedy tokens and eagle3 acceptance rates.
The same issue was previously fixed for the ngram speculative-decoding test in https://github.com/vllm-project/vllm/pull/62048. That change enabled batch invariance for ngram, but the eagle3 test was not covered.
This change factors the existing ROCm setup into a shared helper and applies it to both eagle3 and ngram tests.

## Testing
Enabling `VLLM_BATCH_INVARIANT` selected `TRITON_ATTN` and exercised the batch-invariant Triton matmul implementation. Under this configuration, the synchronous baseline and both non-preemptive asynchronous configs produced bit-identical eagle3 acceptance rates across all sampling parameter sets.
