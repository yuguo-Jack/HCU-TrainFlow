# Fix false substring match in INCConfig.get_layer_config

[Upstream PR](https://github.com/vllm-project/vllm/pull/42367) · state: open · merged: False

## Original PR description

When packed_modules_mapping contains a short key (e.g. 'qkv' from the vision encoder), it can be a substring of a longer fused layer name (e.g. 'in_proj_qkvz') in multimodal models such as Qwen3.6-35B-A3B.

The old code entered the fusion branch whenever the key appeared anywhere in the layer name. It then generated sub_names by string replacement, but none of those sub_names existed in extra_config, so get_config() silently fell back to the global default weight_bits (4). This caused a shape mismatch when loading fp16 (bits=16) checkpoint weights that the model had correctly saved without quantisation.

Fix: skip a fusion_key if none of the generated sub_names appear in extra_config. This prevents the false match without affecting genuine fused-QKV layers whose sub_names are explicitly configured.

The solution involves verifying that at least one generated sub-name is present in `extra_config` before proceeding with fusion. The check `name in self.extra_config` only performs an exact key lookup. However, `INCConfig` supports regular expression patterns in `extra_config` (as implemented in the `get_config` helper on lines 157-173). This change introduces a regression where fused layers whose sub-modules are configured via regex patterns in `extra_config` will be skipped in this fusion logic and fall back to the global default in step 5.

To maintain full functionality, this check should also account for regex matches. Consider refactoring the lookup logic from `get_config` into a helper method that can be reused here to verify if a module name is explicitly configured (either via exact match or regex).
