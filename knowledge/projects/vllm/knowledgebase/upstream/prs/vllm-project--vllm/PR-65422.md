# [Bugfix][Structured Output] Allow integer multipleOf with xgrammar

[Upstream PR](https://github.com/vllm-project/vllm/pull/65422) · state: open · merged: False

## Original PR description



## Overview

`has_xgrammar_unsupported_json_features` treats every `integer` + `multipleOf` schema as unsupported, so these schemas fall back to guidance under `auto` and are rejected when the backend is `xgrammar`. The pinned xgrammar (0.2.8) does enforce `multipleOf` for integers, but only within limits: the value must be an integer in [1, 1024] and the schema must have no `minimum`/`maximum` bound. Outside those limits it logs a warning and ignores the constraint, as it always does for `number`. This PR lets the enforced subset use xgrammar and keeps gating everything else.

@errmakov pointed out that integer `multipleOf` is enforced in https://github.com/vllm-project/vllm/pull/48416#issuecomment-5732951369 (thanks!). Tracker: #12131.

## Claims

- `{"type": "integer", "multipleOf": N}` with an integer `N` in [1, 1024] and no bounds (also nested in objects and in type lists like `["integer", "null"]`) now uses xgrammar, and the grammar enforces it. For `multipleOf: 5`, `10` and `-15` are accepted and `7` is rejected.
- Everything xgrammar 0.2.8 would silently ignore stays gated, so it still falls back to guidance as on main: `number` + `multipleOf`, non-integer `multipleOf` (`2.5`), `multipleOf > 1024`, and integer `multipleOf` with any of `minimum`/`maximum`/`exclusiveMinimum`/`exclusiveMaximum`.

| schema | accepts a non-multiple? |
|---|---|
| `multipleOf: 5` | no (enforced) |
| `multipleOf: 2.0` | no (enforced) |
| `multipleOf: 1024` | no (enforced) |
| `multipleOf: 2.5` | yes (ignored, warning) |
| `multipleOf: 1025` | yes (ignored, warning) |
| `multipleOf: 7, minimum: 0` (or `maximum`, `exclusiveMinimum`, `exclusiveMaximum` alone) | yes (ignored, warning) |
| `multipleOf: 7, minimum: 0, maximum: 10000` | yes (ignored, warning) |
| `multipleOf: 7, minimum: 0, maximum: 20` | no (enforced) |

The last row (both bounds and a narrow range) is enforced, but this PR keeps all bounded cases gated to stay conservative; it can be widened later.

## Details

- `_xgrammar_enforces_integer_multiple_of` returns whether `multipleOf` is an integer value in [1, 1024] (rejecting `bool`) with no bound keys. The gate returns unsupported for `number` + `multipleOf`, or for `integer` + `multipleOf` when that helper is false.
- Tests: integer cases move from the unsupported fixture to a new supported one, and the out-of-limit cases are added to the unsupported fixture. `test_integer_multiple_of_is_enforced` / `test_integer_multiple_of_is_ignored_outside_limits` check the xgrammar behavior the gate relies on, next to the existing grammar-acceptance tests.
- `test_abstract_parser.py` used `integer` + `multipleOf: 2` as its xgrammar-unsupported example; it now uses `number` + `multipleOf: 0.5`, like the test next to it. `test_validation.py`'s fallback case gains `"minimum": 0` so it still falls back.
- #62877 also edits the `test_validation.py` parametrize touched here; whichever lands second needs a small rebase.
