# [Bugfix] Cast the staged-write and bincount row offsets to int64 to avoid an int32 wrap

[Upstream PR](https://github.com/vllm-project/vllm/pull/57524) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #57030.

Two Triton kernels compute row offsets with `int32` arithmetic. With large
request buffers, an offset can exceed `2**31 - 1` and wrap to a negative value.
The staged-write kernel can then write outside the buffer, and the penalty
kernel can read outside it.

## Change

- `_apply_write_kernel` casts `row_idx` to `tl.int64` before it multiplies by
  the row stride.
- `_bincount_kernel` casts the request index to `tl.int64` before the stride
  calculations.

The index buffers stay `int32`. Only the address calculations change.

## Test plan

Both new tests use a `(65536, 32769)` `int32` buffer. The last row starts at
element `2147516415`, just past the signed 32-bit limit.

I tested commit `a46940b5e4` on one NVIDIA L4. For the baseline check, I kept
the new tests and restored `buffer_utils.py` and `sample/penalties.py` from
`d5f0a6e82`. Each test ran in a separate process, and both failed with a CUDA
illegal memory access.

After I restored the PR code, the full UVA test file and the new bincount
test passed: **21 passed, no skips, in 10.59 seconds**.

```bash
python -m pytest -v -s -rs \
  tests/kernels/core/test_uva.py \
  tests/v1/worker/test_gpu_bincount_i64.py
```

The test environment was Ubuntu 22.04, Python 3.12.14, PyTorch 2.13.0+cu130,
and Triton 3.7.1. I used an editable source install with the precompiled CUDA
extensions from `d5f0a6e82`, plus `cuda-compat-13-0`.
No import shim was needed.
