# [Bugfix][Gemma4] Accept legacy ModelOpt per-expert weight names

[Upstream PR](https://github.com/vllm-project/vllm/pull/61627) · state: open · merged: False

## Original PR description

## Overview

Restore loading of legacy ModelOpt Gemma 4 per-expert checkpoint names after the AutoWeightsLoader refactor in https://github.com/vllm-project/vllm/pull/55911.

## Claims

- Translate `.moe.experts.` to `.experts.` using the existing Gemma4ForCausalLM mapper, preserving projection and quantization suffixes.
- Leave current checkpoint names, router names and multimodal exclusions unchanged.

Only the per-expert `moe.experts.N.*` family is aliased; the older fused names `moe.gate_up_proj`, `moe.down_proj`, and `moe.per_expert_scale` are outside this fix.

## Validation

Offline source-extracted validation with the actual upstream WeightsMapper class and model mapper: all 46,005 legacy expert keys in the pinned bg-digitalservices/Gemma-4-26B-A4B-it-NVFP4 index translate to the current expert path; the other 1,568 keys are unchanged. The extended upstream expert-name regression passes with inert tensor placeholders.

Clean installed-vLLM validation in an isolated environment (no overlay): vLLM0.31.0, Omni0.31.0rc1, torch2.13.0, transformers5.14.1.

- `.venv/bin/python -m pytest test_installed_mapper.py -q`: unpatched13 failures/3 passes; patched16 passes.
- From `/home/aubin/gemma031-compatibility-review`, `.venv/bin/python -m pytest tests/models/language/generation/test_gemma.py -m cpu_test -q`: **4 passed, 7 deselected**. Current upstream patched test file, unchanged upstream distributed fixture and config helper extracted into the clean test environment; no altered test assertions or fixture behavior.
- Ruff using current upstream pyproject configuration on both changed files: **passed**; `git diff --check`: **passed**.

Live patched0.31 loaded the pinned Gemma26 NVFP4 weights and passed exactly two temperature0 public synthetic chat requests: `The capital of France is Paris.` and `record_count` with arguments `{"count":7}`. Both returned HTTP200 and expected finish reasons, no retries. Sampled free VRAM3500–3502MiB before/after requests. Marlin linear/MoE, FP8 KV768MiB, context4096, batch2048, one sequence; RTX5090 Laptop GPU. No tools actually executed. Quantization warnings remain: this is loader/interface smoke, not numerical equivalence or quality evaluation. The original patched0.28 service was restored with context12000 and cache1207959552 bytes, healthy and2898MiB free at verification.

The earlier unpatched0.31 log fails with `There is no module or parameter named 'layers.0.moe' in Gemma4Model`; no completion was sent in that failed startup. A fresh clean unpatched full-model startup was not repeated, because installed CPU mapper tests reproduce the exact legacy path defect.

## Details

The pinned checkpoint revision a15dd6f161881b62db952303a5bfb7be118ed15e contains names such as `model.language_model.layers.0.moe.experts.0.down_proj.weight`. The former iterator accepted that naming, whereas the refactored tree exposes experts directly on the decoder layer. Current main leaves the obsolete `moe` segment intact. This patch supplies the missing compatibility alias without restoring the custom loader.

Duplicate search checked exact failure text, Gemma4Model/moe, loader keywords and open PR bodies. Issue #38912 and PR #41988 concern older scale suffix handling; PR #60666 proposes general Transformers renamings and is related, but has no Gemma4 legacy expert alias in its downloaded diff. Immediately before submission, open-PR searches for `55911 in:body` and `"moe.experts" gemma` found no matching fix: the latter returned #50252 (stacked LoRA mapping) and #37190 (expert offloading), different changes.

AI assistance was used. The owner reviewed the patch and requested the scope clarification before authorizing publication. Broader model evaluation was not performed; the claims are restricted to checkpoint naming and bounded loading/interface smoke. The serving window was temporary; retained installed code and launcher defaults were unchanged.
