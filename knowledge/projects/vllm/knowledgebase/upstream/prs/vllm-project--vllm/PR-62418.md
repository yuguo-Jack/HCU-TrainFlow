# [Bugfix][Multimodal] Match mistral_common's EXIF handling for mistral-tokenizer models

[Upstream PR](https://github.com/vllm-project/vllm/pull/62418) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Skip EXIF orientation normalization when the model uses the mistral tokenizer, so vLLM's image decode matches the decode performed by the mistral_common chat template. Fixes #62420.

## Claims

- Fixes the HTTP 500 `Expected there to be 1 prompt placeholders ... found 0` raised when serving EXIF-oriented images (orientations 6/8) to models run with `--tokenizer-mode mistral`.
- Removes the silent pixel-layout inconsistency for orientation 3 (180°): vLLM now feeds the same pixel layout that mistral_common's chat template computed the `[IMG]` token grid from.
- No behavior change for any other model: `normalize_orientation` defaults to `True` and the gating only applies to mistral-tokenizer models.

## Details

**Root cause.** With `--tokenizer-mode mistral`, the prompt is rendered by mistral_common's chat template, which decodes image bytes itself — without applying EXIF orientation normalization. vLLM's `ImageMediaIO.load_bytes` (loading path introduced in #44974) applies `normalize_image` (EXIF transpose). For orientations that swap width/height (6/8), the image token grid computed from the two decodes differs, so `_find_mm_placeholders` finds 0 `[IMG]` placeholders for 1 image item → 500. Related history: #44974 (load-time EXIF transpose), #47566 (normalize direct PIL inputs), #52874 (Mistral3 placeholder grid, different cause).

**Fix.** Make vLLM's decode agree with mistral_common's on this path:

- `vllm/tokenizers/registry.py`: new `uses_mistral_tokenizer()` helper (reuses the existing cached resolver, so the check resolves once).
- `vllm/renderers/chat_utils/item_tracker.py`: when the model uses the mistral chat template, the tracker injects `normalize_orientation=False` into the image `media_io_kwargs`.
- `vllm/multimodal/media/image.py`: `ImageMediaIO` gains a `normalize_orientation` flag (default `True`) gating `normalize_image` in `load_bytes`.
- `vllm/multimodal/parse.py` + `vllm/multimodal/processing/context.py`: the same flag (`normalize_image_orientation`, default `True`) for PIL images passed directly, wired to `not is_mistral_tokenizer(...)`.

**Trade-offs.** Mistral-tokenizer models now see the raw stored pixel layout (identical to the mistral_common reference stack) instead of the viewer-normalized one; EXIF normalization is unchanged for all other models. The alternative — normalizing inside mistral_common — is out of tree and would change the reference behavior.

**Not duplicating existing work.** Searched open PRs/issues for "EXIF orientation", "normalize_image mistral", "mistral prompt placeholders" — no open PR addresses this tokenizer/EXIF interaction; the three related merged PRs above do not cover it.

**AI assistance.** This change was developed with AI assistance (GLM-5.3 via OpenCode); the fix, tests, and validation were reviewed and re-run by the human submitter.
