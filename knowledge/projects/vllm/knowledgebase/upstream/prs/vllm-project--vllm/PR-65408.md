# [WIP][Kernel] Fuse SiLU and FlashInfer SM90 block-FP8 quantization

[Upstream PR](https://github.com/vllm-project/vllm/pull/65408) · state: open · merged: False

## Original PR description

## Overview

Add an experimental SM90 BF16 SiLU/multiply + 1x128 FP8 quantization producer matching FlashInfer's activation-scale layout and zero-group semantics. This draft contains the kernel, internal wrapper, numerical tests, and boundary benchmark; automatic model/compiler/backend dispatch is still pending.

## Claims

- Emit packed E4M3 activations and FP32 scales with strides `(1, round_up(M, 4))`, avoiding the intermediate BF16 activation buffer before FlashInfer GEMM.
- Preserve the tested compiled activation's final BF16 rounding; an explicit `round_silu` option also preserves the intermediate rounding of the CUDA activation.
- On H100, synthetic Qwen3.8-27B down-projection shapes show a 2.5–5.2% reduction for **activation + quantization + GEMM**, depending on row count. No whole-model speedup or accuracy claim.

## Validation

Built the actual CUDA translation unit and registered the stable-ABI operator as an isolated extension on H100, then executed `tests/kernels/core/test_silu_mul_fp8_sm90.py`: **32 passed**. The test checks FP8 bytes and live scale values against FlashInfer's own quantizer for M=1/3/6/31, random/zero/tiny/large inputs, and both activation-rounding modes. Prototype GEMM outputs also matched bit-for-bit at M=3/6/16/31.

Two timing runs used CUDA graphs, 50 operations/graph, 20 replays/sample and the median of seven samples. The second run reversed baseline/candidate timing order. K=17408, N=5120, synthetic BF16 activations, synthetic FP8 weights with unit block scales:

| M | Baseline, first/repeat (us) | Fused, first/repeat (us) | Reduction |
|---|---|---|---|
| 3 | 37.81 / 37.67 | 36.75 / 36.72 | 2.8% / 2.5% |
| 6 | 38.20 / 38.09 | 36.87 / 36.97 | 3.5% / 3.0% |
| 16 | 38.99 / 38.97 | 37.55 / 37.46 | 3.7% / 3.9% |
| 31 | 41.72 / 41.52 | 39.55 / 39.52 | 5.2% / 4.8% |

The numerical and timing experiments used the existing CUDA 13.0 serving-image runtime. Full main-branch CMake/wheel integration, complete serving-model evaluation, and the DeepGEMM M>=32 branch remain unvalidated. Do not enable this automatically until those checks and human review are complete.

Reproduce after rebuilding vLLM:

```bash
.venv/bin/python -m pytest tests/kernels/core/test_silu_mul_fp8_sm90.py -q
.venv/bin/python benchmarks/kernels/benchmark_silu_mul_fp8_sm90.py
```

## Details

FlashInfer's BF16-input GEMM quantizes internally, hiding the quantization boundary from activation fusion. The existing generic fused block-quant kernel has different minimum-scale, rounding and layout behavior; directly wiring it into this backend changes FP8 bytes. This producer uses FlashInfer's reciprocal-scale arithmetic, scale=1 for zero groups, TMA-aligned column-major scale storage, and retains the chosen BF16 rounding boundary. It does not change weights, FP8 scales, backend thresholds, or the DeepGEMM quantization policy.

Duplicate-work searches covered `FlashInfer prequantized`, `SiLU block FP8`, and related kernel work. #51939 addresses shared-base/DeepGEMM input contracts; #62386 fixes generic fused-kernel scale strides. This draft specifically adds the SM90 FlashInfer-compatible producer, including its different zero/tiny-group and activation-rounding semantics. It does not duplicate either integration.
