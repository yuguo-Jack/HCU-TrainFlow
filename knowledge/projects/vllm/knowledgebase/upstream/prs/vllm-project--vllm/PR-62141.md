# [CI][AMD] Mirror ReplaySSM, MiniMax-M3 attention kernels and Kimi K3 prefix cache on MI355

[Upstream PR](https://github.com/vllm-project/vllm/pull/62141) · state: open · merged: False

## Original PR description

Adds AMD mirrors for the three test groups in `test_areas` that still had none: ReplaySSM E2E, MiniMax-M3 Attention Kernels and Kimi K3 Prefix Cache. The Kimi K3 Prefix Cache mirror needs two fixes that have not landed yet (see Details).

- `engine.yaml`: ReplaySSM E2E on `mi355_2`. The FlashInfer-only cases in `test_replayssm_decode.py` skip off CUDA.
- `kernels.yaml`: MiniMax-M3 Attention Kernels on `mi355_dpx`, plus a test that checks the AITER indexer against a reference implementation.
- `models_basic.yaml`: Kimi K3 Prefix Cache on `mi355_4` with `VLLM_ROCM_USE_AITER=1`. The existing MI355 Kimi K3 jobs now skip `test_prefix_cache.py` so it does not run twice.
- `test_prefix_cache.py`: on ROCm it gates on native MX support instead of SM100. The FlashInfer DCP xfail applies on CUDA only. The Mooncake transport can be set with `MOONCAKE_PROTOCOL` (default `rdma`), and the AMD mirror uses `tcp`.

## Validation

MI355 (gfx950), on current main with its ROCm pins (AITER `v0.1.25`, NIXL `1683cf3b`):

| Group | Runs | Result |
|---|---|---|
| ReplaySSM E2E | 10 | 10/10 pass (4 passed, 6 skipped each) |
| MiniMax-M3 Attention Kernels | 10 | 10/10 pass (161 passed, 14 skipped each) |
| Kimi K3 (existing job, with the new `--ignore`) | 1 | 336 passed, 67 skipped |
| Kimi K3 Prefix Cache, current main | 1 | 29 passed, 2 failed (`pd-tp2-dep2-block`/`-partial`, fixed by #61002) |
| Kimi K3 Prefix Cache, with #61002 and the AITER fix | 6 | 31/31 in 4 runs; the other 2 failed when another process on the shared node took the GPU memory |

## Details

The Kimi K3 Prefix Cache mirror depends on two fixes:

- #61002 (NixlConnector): pairs non-divisible hybrid MLA block sizes. Without it the two `pd-tp2-dep2` cases fail at the NIXL handshake.
- ROCm/aiter#6446: fixes an LL128 all-reduce deadlock that can hang the DCP cases under host contention. vLLM picks it up through an AITER release that includes it and a pin bump in `Dockerfile.rocm_base`. `v0.1.25` does not include it yet.

The new Mooncake test needs RDMA NICs (`mlx5_*`) by default, which MI355 runners may not have. The mirror runs it over TCP, which passes locally. The mirror inherits `optional` from the NVIDIA step, so like the 4xB200 job it runs nightly.
