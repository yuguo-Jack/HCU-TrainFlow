# [CI] Add Nightly to optional Buildkite step labels

[Upstream PR](https://github.com/vllm-project/vllm/pull/61186) · state: closed · merged: True

## Original PR description

## Purpose

Optional steps in `.buildkite/test_areas/` only run in nightly builds, but most labels didn't say so, so you can't tell from a Buildkite job name whether a step runs per-PR or nightly. This PR adds a `[Nightly]` tag right after the hardware prefix on all 91 optional steps:

- `:nvidia: (B200) LM Eval Humming Default TEMPORARY` → `:nvidia: (B200) [Nightly] LM Eval Humming Default TEMPORARY`
- `:nvidia: (DGX) Spark GPQA Eval (GPT-OSS)` → `:nvidia: (DGX Spark) [Nightly] GPQA Eval (GPT-OSS)` (DGX Spark jobs also move "Spark" into the hardware prefix)
- Labels that already ended in `Nightly` (for example `(B200) Spec Decode Eagle Nightly`) drop the suffix and get the same tag, so every label follows one pattern.

Only `label:` strings change, and the rest of each name is untouched. Step keys, commands and devices are unchanged. No other file in the repo references these labels. `test-amd.yaml`, `hardware_tests/` and `intel_jobs/` are out of scope.

## Not a duplicate

I searched open PRs for nightly/optional label renames and found none.

## Test plan

- `pre-commit run --files .buildkite/test_areas/*.yaml` passes, including the Buildkite key and tethering checks.
- A YAML parse confirms that every step with `optional: true` in `test_areas/` now has `[Nightly]` right after its hardware prefix (91/91).
- A diff check confirms that each old/new label pair differs only in the `Nightly` marker.
