# [Spec Decode] Allow per-request synthetic acceptance length

[Upstream PR](https://github.com/vllm-project/vllm/pull/59650) · state: closed · merged: False

## Original PR description

## Overview

Allow each request to select real or synthetic speculative acceptance without restarting the server. This supports benchmark sweeps on both GPU model runners.

## Claims

- A numeric `vllm_xargs.synthetic_acceptance_length` overrides the acceptance length. `null` selects real acceptance, and an omitted key inherits the server default.
- Chat, completion, and offline `SamplingParams(extra_args=...)` requests support the override when speculative decoding is enabled.
- Every request in a batch must select the same mode and numeric length. Mixed configurations assert, so drain outstanding requests before switching.

## Validation

AI assistance was used to implement, review, and test this draft. Searches for open PRs with `synthetic_acceptance_length` or per-request synthetic acceptance in their titles found no duplicate implementation.

The sampling-parameters suite passes 76 cases locally. Six request-batch cases pass locally, and 43 targeted cases pass on an H100 NVL.

```bash
.venv/bin/python3 -m pytest --noconftest tests/test_sampling_params.py -q
.venv/bin/python3 -m pytest --noconftest tests/v1/worker/test_gpu_input_batch.py -q -k synthetic_acceptance
.venv/bin/python3 -m pytest --noconftest \
  tests/test_sampling_params.py tests/v1/sample/test_rejection_sampler.py \
  tests/v1/worker/test_gpu_input_batch.py tests/v1/worker/test_gpu_rejection_sampler_chunking.py \
  -q -k 'request_synthetic or synthetic_acceptance or synthetic_all or chunked_scores or replay_on_off or sampling_metadata_in_input_batch or swap_states_in_input_batch'
```

Serving checks use Qwen3-1.7B with a Qwen3-0.6B probabilistic draft, three speculative tokens, eager execution, and greedy and random requests. Both runners process a sweep within one server process. The legacy runner uses a synthetic server default, and the newer runner uses a standard server default.

The sweep tests lengths 1, 4, and 2.6, explicit real acceptance, and inheritance. Lengths 1 and 4 are exact. The measured fractional length stays within 0.2 of 2.6. Sequential real greedy outputs match before and after switching. Concurrent requests test acceptance lengths separately because greedy outputs can depend on batch size before any override.

The checks include nonstreaming completions, nonstreaming chat, streaming chat, 59 successful requests, and eight invalid requests rejected with HTTP 400. The newer runner runs with `VLLM_GPU_SYNC_CHECK=error`. Repository pre-commit hooks pass.

## Details

The patch reuses the existing acceptance schedule and rejection kernels. It carries one acceptance configuration per batch, caches small rate tensors, and uses the existing pinned asynchronous copy helper. It does not change the server default. Block verification does not support request overrides.

On the legacy runner, a synthetic server with probabilistic drafting previously used greedy drafts. It now honors the configured draft method so requests can select real acceptance correctly. These deployments now incur the probability-buffer memory and sampling cost that standard acceptance and the newer runner already incur. Block-default behavior stays unchanged.

The legacy runner registers both rejection modes for startup warmup. The newer runner retains its existing first-use compilation behavior. Warm up each acceptance mode before measuring performance. Synthetic acceptance changes generated tokens and serves performance experiments rather than accuracy evaluation. CUDA graph execution and other request protocols are outside the validation scope.
