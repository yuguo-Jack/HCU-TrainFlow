# [Bugfix][Mooncake] Use the EAGLE replay boundary when retaining sliding-window tails

[Upstream PR](https://github.com/vllm-project/vllm/pull/61012) · state: closed · merged: True

## Original PR description

## Purpose

`MooncakeStoreCoordinator.store_mask` mirrors the core's sparse sliding-window retention (`SlidingWindowManager.reachable_block_mask`) so the store keeps the same tails the local prefix cache does. It passed the non-EAGLE replay boundary, `(num_prompt_tokens - 1,)`, while masking with `use_eagle=True`. Under EAGLE the lookup matches one block past the hit and drops back from it, so the core's `replay_boundaries` places the boundary one scheduler block lower; the store did not. For a prompt that is not block-aligned the retained tail therefore ended one block too high, the saved prefix held `need - 1` of the `cdiv(sliding_window - 1, block_size) + 1` contiguous blocks the lookup requires, and the joint hit collapsed to 0. Only block-aligned prompts hit.

Affected layout: a full-attention target group plus a sliding-window EAGLE drafter group (DFlash-style, e.g. window 2048 / block 64) with `prefix_cache_retention_interval=0`. Same family as #57610 (sparse sliding-window retention keeping a tail exactly `need` blocks long), but on the store side and with a different cause; #57613 composes with this change.

The fix extracts the core rule into a module-level `replay_boundaries()` in `vllm/v1/core/kv_cache_coordinator.py` (called directly from `KVCacheCoordinator.cache_blocks`, behaviour unchanged) and calls it from `_reachable_masks`, so the two sides cannot drift again. The non-EAGLE path still yields `(num_prompt_tokens - 1,)`. On a block-aligned prompt the store now also keeps the core's lower "resend" tail: one extra sliding-window tail per aligned prompt, identical to what the local cache retains.

Not a duplicate: #56615 pairs Mamba and attention boundaries for partial-tail handoffs and does not touch the retention boundary; #57444 changes the core boundary alignment for fine-grained hits (same function, orthogonal change; trivial rebase whichever lands first); #46906 sidesteps by making store retention dense; #57613 fixes #57610 inside `reachable_block_mask`.
