# [Bugfix][KV Connector] Mooncake store: register the committed blocks of an extensible KV cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/65331) · state: closed · merged: True

## Original PR description

## Overview

With the extensible KV cache (on by default since #56492), `MooncakeStoreConnector` fails at startup. Its worker splits each layer's view by `cache_config.num_gpu_blocks`, but `extend_kv_cache` creates the connector against the committed views before it updates that value, so `group_kernel_blocks` asserts. The worker now takes the block count from its own `kv_cache_config`, as the rest of the worker already does.

```
mooncake/store/worker.py, in register_kv_caches
    group_kernel_blocks(view, self.num_blocks)
kv_cache_interface.py, in group_kernel_blocks
    assert cache.shape[0] % num_blocks == 0
AssertionError
```

No open PR covers this (searched for Mooncake + extensible KV cache). Related: #56492, #65225, #65137.

## Validation

GLM-5.3-Flash, colocated DEP8 on 8x B200, `MooncakeStoreConnector` with a standalone store (1.3 TB DRAM plus a 6 TiB SSD tier), real MTP 5. Image nightly `e0d00e4b8e` with this change applied:

| | Before | After |
|---|---|---|
| Startup | `AssertionError` in `group_kernel_blocks` | Serves; KV cache extended to 1920 blocks (105.38 GiB, 15,728,640 tokens per rank) |
| GSM8K, 5-shot | – | 0.9727 (0.975 with `--disable-extensible-kv-cache`) |
| Needle read-back | – | 16/16 on a cold store; 32/32 after 15 minutes of AgentX at concurrency 384, by which time 2.61 TB had spilled to SSD |

Needle read-back: 16 contexts of about 20K tokens with 800 locker codes each. Each context is asked one code on a cold store, then the same code and a new one after the load.

The new unit test fails without the fix and passes with it. The rest of `test_mooncake_store_worker.py`, `test_mooncake_store_connector.py` and `test_mooncake_store_hma_e2e.py` give the same results with and without it.

```bash
pytest tests/v1/kv_connector/unit/test_mooncake_store_worker.py -k register_kv_caches
```
