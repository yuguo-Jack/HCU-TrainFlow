# [Model] Support every Decision 3.0 size (d3-flash, d3-mini, d3-nano, d3-lite, d3-edge)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61778) · state: closed · merged: True

## Original PR description

## Overview

Make every Decision 3.0 model work in vLLM: `vllm serve vllm-sr/d3-nano` stopped while loading weights, and d3-flash, d3-lite, d3-mini and d3-edge had no published validation on current vLLM. Follow-up to #61565, which added Decision 3.0 and validated d3, d3-mini and d3-edge; its "Follow-ups" section promised this PR.

## Claims

- **d3-nano loads.** Its checkpoint has one `model.safetensors` and no weight index, so the default loader also read `readout.safetensors` as a backbone file and stopped with `ValueError: There is no module or parameter named 'weight' in D3ForSequenceClassification`. `D3ForSequenceClassification` now names the readout's only tensor in `is_unused_checkpoint_weight`, so the backbone pass skips that file; the readout still loads as the FP32 `score` head through `secondary_weights`.
- **All five sizes give the checkpoint runtime's decisions** with `vllm serve vllm-sr/<model>` and no flags, on one AMD Instinct MI300X: 0 to 2 of 416 decisions changed per model, all near-ties (the reference's two most likely answers within 0.015 of each other), with a median probability difference of 0.003 (table below).
- **Throughput.** At 8 and 64 closed-loop clients vLLM serves 2.0x to 3.6x the requests per second of the checkpoint's own server on the mixed text / image / video load; one request at a time it is 7 % to 32 % slower (each question is its own engine request).
- The docs list all six models, the GPU test runs d3-nano next to d3-edge, and the test registry lists every size.

## Validation

**Setup**: one AMD Instinct MI300X (ROCm 7.2), a new `rocm/dev-ubuntu-24.04:7.2.3-complete` container with empty caches. vLLM is the ROCm nightly wheel `0.32.0rc1.dev190+g3f1bcfd82` (it contains #61565, and every file on the Decision 3.0 path is identical to `main`) with this PR's `d3.py` copied over the installed one; no kernels were built. The reference is the checkpoint's own runtime, `AutoModel.from_pretrained(..., trust_remote_code=True)`, with the versions its `requirements.txt` pins (torch 2.13.0+rocm7.1, transformers 5.17.0, flash-linear-attention 0.5.2), in its own venv on the same GPU. Checkpoints at their current `main`: `vllm-sr/d3-edge` @ cab71e6a, `vllm-sr/d3-lite` @ 9c107031, `vllm-sr/d3-nano` @ aeb70d4d, `vllm-sr/d3-mini` @ 97dd054d, `vllm-sr/d3-flash` @ 8b35c853.

## Details

- **Root cause**: without `model.safetensors.index.json`, `DefaultModelLoader._prepare_weights` keeps every `*.safetensors` file of the repo (`filter_duplicate_safetensors_files` returns them all when the index is missing), so `readout.safetensors` ({`weight`: [255, hidden]}) joins the backbone pass. Its root key `weight` matches no module, and `AutoWeightsLoader` raises. The other five checkpoints ship an index that lists only the backbone shards, so the index filter already drops the readout there. d3-nano is the only Decision 3.0 repo without an index.
- **Fix**: `is_unused_checkpoint_weight` is the existing hook the default loader passes to `filter_safetensors_files_by_weight_name` for the primary weights only; it drops a safetensors file when every tensor in it is unused. The readout file holds a single tensor named `weight`, which no backbone checkpoint has at the root. Its own `secondary_weights` source sets no such rule and keeps loading it under the `score.` prefix. For indexed checkpoints nothing changes beyond reading the shard headers, which the loader already does for pooling models (their protocol default returns False).
- **Alternatives considered**: `allow_patterns_overrides=["model*.safetensors"]` would also skip the index filter and depend on file names; adding an index to the Hub repo fixes only that copy of the checkpoint.
- **CI**: `test_d3.py` runs in the optional "Multimodal Models (Extended Pooling)" step; d3-nano adds a 4.5 GB checkpoint there. d3-lite, d3-mini and d3-flash take the same code path as d3-edge and d3-nano and are covered by the measurements above rather than CI, to keep the step's downloads and run time small.
- **Not measured**: agreement and throughput on NVIDIA GPUs (only the CI test above ran there; no NVIDIA GPU was available to me), tensor parallelism, LoRA.
- **Not a duplicate**: no open or closed PR or issue covers d3-nano or the other sizes (searched for Decision 3.0, `vllm-sr/d3`, d3-nano, `D3ForSequenceClassification`, `decision_config`); #61565 is merged.
- **AI assistance** was used for the code, tests, measurements and this description.
