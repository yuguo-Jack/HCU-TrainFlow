# [Bugfix][Benchmark] Keep numeric-string prompts as strings in CustomDataset

[Upstream PR](https://github.com/vllm-project/vllm/pull/65083) · state: closed · merged: True

## Original PR description



## Overview

Fixes #65071. `CustomDataset.load_data()` lets `pd.read_json` infer the `prompt` column's dtype, so a JSONL file whose prompts are all numeric strings (`"00123"`, `"00456"`) is loaded as integers. Leading zeros are lost and `sample()` then fails in the tokenizer.

## Claims

- JSON string prompts are kept exactly as written, regardless of what other rows contain.
- `output_tokens` and other columns are unaffected.

## Validation

New regression test `test_custom_dataset_keeps_numeric_string_prompts` (CPU-only, local `WordLevel` tokenizer, no download) builds a real `CustomDataset` and calls `sample()`.

Before the fix (source reverted to `origin/main`):

```text
$ pytest tests/benchmarks/test_custom_dataset_seed.py -k numeric_string
E   ValueError: text input must be of type `str` (single example), `list[str]` ...
1 failed, 2 deselected
```

With the fix:

```text
$ pytest tests/benchmarks/test_custom_dataset_seed.py
3 passed
```

Lint: `pre-commit` hooks pass on the commit (ruff check/format, mypy, forbidden imports, test tethering). The test is picked up by the existing "Benchmarks CLI" step (`pytest -v -s benchmarks/`).

## Details

Root cause: pandas' default `dtype=True` coerces string columns that all parse as numbers. Passing `dtype={"prompt": str}` keeps the column as-is; other columns keep their current inference, so `output_tokens` behaviour is unchanged.

The other two `pd.read_json` callers in `datasets.py` read list-valued columns (`turns` / `messages`), which pandas does not coerce, so they are left alone.

Not a duplicate: no open PR references #65071. #60506 and #61776 also touch `CustomDataset` but address output lengths / audio without a tokenizer in `sample()`, not the `read_json` dtype.
