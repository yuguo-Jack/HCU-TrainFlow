# [Bugfix][Frontend] Honor --enable-log-outputs on /v1/completions

[Upstream PR](https://github.com/vllm-project/vllm/pull/62205) · state: closed · merged: True

## Original PR description



## Overview

`--enable-log-outputs` is silently ignored by `/v1/completions`. The handler never accepted the flag or logged generated text, while chat, Responses, Anthropic (#60982), Cohere (#61089) and `/inference/v1/generate` all do. This adds output logging to completions, mirroring chat.

## Claims

- With `--enable-log-requests --enable-log-outputs`, `/v1/completions` logs generated text: one line per output when not streaming; when streaming, one line per delta (respects `--enable-log-deltas`) plus the full text when the stream ends.
- Output lines reuse the per-prompt request id from the input log (`cmpl-<id>-<i>`), so the two can be correlated.
- Nothing changes when the flag is off (the default).

## Details

The original `--enable-log-outputs` PR (#20707) implemented logging for chat and Responses only. Later endpoints that inherit from the chat handler only needed the flag forwarded (#60982, #61089). Completions has its own handler, so it needs the logging itself:

- `OpenAIServingCompletion` takes `enable_log_outputs` / `enable_log_deltas`, and `init_generate_state` passes them, as for chat.
- Non-streaming: after the response is built, log each output's generated text, token ids and finish reason.
- Streaming: log each non-empty delta, accumulate text only when logging is on, and log each choice's full text after the stream, with `finish_reason="streaming_complete"` as chat does.
- The generated text is logged, not the echoed prompt (`echo=true`); `log_inputs` already logs the prompt.

The batch chat endpoint and speech-to-text have the same gap. I'll follow up separately to keep this one small.
