# WIP: [Mamba] Add separate CuTeDSL ReplaySSM checkpoints

[Upstream PR](https://github.com/vllm-project/vllm/pull/65660) · state: open · merged: False

## Original PR description

## Overview

Adds separate CuTeDSL ReplaySSM checkpoints on top of the shared FP8/INT8 extension.
**Dependency:** this commit is stacked directly on shared FP8/INT8 PR #52962, which depends on #55688.
GitHub targets `main`, so its aggregate diff includes both parents. Review the [separate-only comparison](https://github.com/askliar/vllm/compare/927e98f31cc9f6bfafdb976ee2884b111446f371...ec4c604395924bda25f5955f75aa02d9379916c2).

```text
FP16 recurrence checkpoint with SR7
  → FP32 flush work
  → FP8/NVFP4 read checkpoint
  → BF16 readout
```

## Claims

- `--replayssm-checkpoint-mode separate --replayssm-state-dtype fp8|nvfp4` selects the separate layout.
- FP16 recurrence uses SR7. FP8/NVFP4 read checkpoints use nearest encoding.
- Preserves the SM103 kernels and GB10/SM121 accepted-prefix path, including the saved paired-output readout optimization.
- Separate mode supports up to seven draft tokens on SM121, requires history 16, and rejects prefix caching.
- Shared FlashInfer behavior remains in the parent PR.

## Validation

Current parent and split (child-only diff: 44 files, +7412/−154):

- Focused CPU checks: **50 passed, 22 skipped, 602 deselected**. The separate arithmetic file has **14 CUDA skips**.
- Changed Python files passed AST parsing, Ruff, formatting, and diff checks. All applicable pre-commit hooks passed, including mypy.
- The native pending-kernel diff matches the saved paired-readout patch. Other native source files retain the published implementation.
- CUDA arithmetic tests skipped locally. This rebased tree has no fresh GPU, model-quality, or TPS result.
- Existing CI selects the affected ordering tests. The native SM103/SM121 arithmetic path lacks a matching hosted GPU lane.

Historical evidence only: the October 28 GB10 Bolt/LiLiCorr matrix recorded 76.3966 shared BF16, 78.6049 separate FP8, and 78.6739 separate NVFP4 decode TPS/user.
It used older combined source with the paired-readout optimization, simulated subset-72 routing, synthetic AL4.3, B1/T8, 32K input, and 4K output.
Five measured requests followed two warmups per mode. These results do not establish a repeatable gain for the current split.
Earlier small natural-acceptance GSM8K checks do not establish quality parity.

The published GB10 optimization previously passed 17 GPU tests and matched 104 differential output/cache snapshots.
Those checks precede this rebase. The paired-readout component measurements also precede this split.
Reproduce current CPU checks from the local split task with `bash run-checks.sh separate`.

## Details

The native kernels derive from [ReplaySSM low_precision](https://github.com/Johnny-Liou/ReplaySSM/tree/73a9592e9d8a2268620e8883a82f5cec7442ed36/low_precision).
The vendored sources retain their license and attribution.
GB10 executes prepare, products, update/readout, and stage kernels.
Only the accepted pending prefix can modify canonical checkpoints. Rejected candidates remain outside canonical state.
The request classifier keeps intermediate prompt chunks on prefill so every chunk reaches the recurrence checkpoint.
The current parent's checkpoint-exporter, ring helpers, and committed-memory warmup contracts remain intact.

This is the separate portion extracted from #52962. It adds no benchmark-only routing simulation.
AI assistance was used for implementation, review, validation, and this description.
