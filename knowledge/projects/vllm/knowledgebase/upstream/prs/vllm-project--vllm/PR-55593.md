# [Bugfix][Spec Decode] Judge draft KV groups with the draft model's config for CUDA-graph support

[Upstream PR](https://github.com/vllm-project/vllm/pull/55593) · state: open · merged: False

## Original PR description

## Purpose

Fixes #55581.

`FlashInferMetadataBuilder.get_cudagraph_support()` judges a KV-cache group's CUDA-graph support by dividing a query-head count by the group's `num_kv_heads`. The count comes from `vllm_config.model_config` — the target model. When speculative decoding adds a draft-side KV group, `_check_and_update_cudagraph_mode` hands that same target config into the draft group's arithmetic, so whenever the two models' head ratios differ the check computes the wrong ratio and spec decode silently loses every CUDA graph (the draft still runs via XQA).

The runner now judges each group against the config that owns the group: draft-side groups (`is_eagle_group=True`) get `speculative_config.draft_model_config`, everything else keeps the target config.

## Test Plan

New regression test `test_config_for_kv_group_uses_draft_heads_for_eagle_groups` in `tests/v1/worker/test_gpu_model_runner.py`: an eagle group resolves to the draft config, a target group to the target config.

Run in a Linux container (python:3.12-slim, CPU torch): the new test passes
(1 passed). The file's teardown hooks raise a pre-existing
`torch.accelerator` RuntimeError on accelerator-less CPU boxes — the same
error appears on existing tests in this file (e.g.
test_freeze_gc_disables_and_restores_automatic_gc), so it is environmental,
not from this change. Full CI covers the GPU paths.

```
python -m pytest tests/v1/worker/test_gpu_model_runner.py -k config_for_kv_group -q
```
