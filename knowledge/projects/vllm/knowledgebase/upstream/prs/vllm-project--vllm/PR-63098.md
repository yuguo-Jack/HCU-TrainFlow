# [Feature][DSv4.1] Enable PCP with PP or DP

[Upstream PR](https://github.com/vllm-project/vllm/pull/63098) · state: closed · merged: True

## Original PR description

## Overview

Relax the model-level PCP compatibility checks for text-only DeepSeek-V4.1-Flash on NVIDIA CUDA to enable the existing PCP + PP and PCP + DP execution paths. The underlying MRV2 implementations are already provided by #59139 (PP) and #57075 (DP). No other open PR was found enabling these model-specific combinations; #49246's generic DP approach was superseded by #57075, while #63106 addresses cross-stage cache relay with PCP=1.

## Claims

- Remove the blanket PP=DP=1 restriction when PCP is enabled, allowing the existing PP or DP execution paths. Combining PP + DP is allowed when TP=1 or expert parallelism is disabled; DCP must remain 1.
- Add PP2 + PCP2 and DP2 + PCP2 cases to the existing `tests/models/test_deepseek_v41_pcp.py`, using real-weight serving and generation.

## Details

The runtime change is confined to the NVIDIA model's compatibility checks. PP/PCP execution, stage-entry Engram handling, and DP/EP communication reuse their existing implementations. The existing PCP test file adds generation cases for the newly enabled combinations: the PP case uses Flash's `14,26` partition, and the DP case sends a request to each replica.

With PCP enabled, PP>1 and DP>1 are rejected only when TP>1 and expert parallelism is enabled: PP currently disables the model's sequence-parallel path required by DP+PCP AgRs MoE communication in that topology. TP=1 or disabled expert parallelism passes this combined-topology gate; these additional combinations still require GPU validation. DCP must remain 1; KV transfer, microbatching, and MegaMoE remain disabled. Preserve main's fixed-length DSpark support with PP=1 and the existing PR's exclusion of speculative decoding with PCP + PP. Prefix caching still requires SWA bounded replay.

AI assistance was used to prepare this change. The human submitter remains responsible for line-by-line review; validation beyond the two configurations reported above remains pending.
