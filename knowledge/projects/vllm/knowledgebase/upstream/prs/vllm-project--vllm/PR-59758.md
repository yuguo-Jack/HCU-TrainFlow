# [KVConnector][NIXL] Pair push-mode requests by router transfer_id

[Upstream PR](https://github.com/vllm-project/vllm/pull/59758) · state: open · merged: False

## Original PR description

## Overview

This PR makes the NIXL push mode connector use a `transfer_id` to reliably pair requests between P and D nodes. The `transfer_id` is a unique id the router/proxy sets on the requests belonging to one router dispatch, so P and D can match the two requests to each other.

Router side: [vllm-project/router#338](https://github.com/vllm-project/router/pull/338)

## Claims

Introducing this fixes/unblocks the following topics:

- NIXL push mode reliability inventory [#48633 C4](https://github.com/vllm-project/vllm/issues/48633) (actual fix): P no longer pairs by `X-Request-Id`. It repeats when a proxy forwards the client's id, e.g. on a client retry.
- [#48633 C1](https://github.com/vllm-project/vllm/issues/48633) (enables fix): `PUSH_CANCEL` can match by `transfer_id`.
- [#48633 L1](https://github.com/vllm-project/vllm/issues/48633) / [#53095](https://github.com/vllm-project/vllm/issues/53095) (enables fix): push heartbeats can find P's lease by `transfer_id`.
- Removal of `VLLM_DISABLE_REQUEST_ID_RANDOMIZATION` ([#45688](https://github.com/vllm-project/vllm/pull/45688)): adds the explicit P/D coordination asked for there. Suffix stripping stays only as a fallback.

Found by Copilot review on the router side [router#338 review](https://github.com/vllm-project/router/pull/338#discussion_r4208853360):
- Batched `/v1/completions` requests: each prompt gets its own `transfer_id` (`<id>-<index>`) so P and D pair per prompt

## Details

My understanding is that the `transfer_id` is an agreed upon pattern, as evidenced by:

1. The Mooncake and MoRI-IO connectors already pair P and D by a router-generated `transfer_id` in `kv_transfer_params`.
2. Proposed / agreed on [#45688](https://github.com/vllm-project/vllm/pull/45688#issuecomment-4709524832) by @markmc, @njhill, @NickLucche.
3. Internal request ids are unique since the caller's id can't be trusted ([#27987](https://github.com/vllm-project/vllm/pull/27987)).
4. Same fix for pull mode ([#29665](https://github.com/vllm-project/vllm/pull/29665)).
5. The base-id matching was already [questioned in the push mode review](https://github.com/vllm-project/vllm/pull/35264#discussion_r3373493860).
6. [Slack discussion](https://vllm-dev.slack.com/archives/C0A9AAG7QR2/p1790760867615409)

## Design:

- D copies the `transfer_id` into `PUSH_REG`. The P scheduler ships it to the worker in `meta.push_transfer_ids`.
- The completion notif is unchanged: P still sends D's internal request id.
- Without a `transfer_id` on both sides, P falls back to today's base-id matching so older routers keep working.
