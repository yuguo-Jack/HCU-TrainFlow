# [KVConnector][NIXL] Pair push-mode requests by router transfer_id

[Upstream PR](https://github.com/vllm-project/vllm/pull/59758) · state: open · merged: False

## Original PR description

## Overview

This PR makes NIXL push mode pair P and D requests by a `transfer_id` from the router. The router sets the same new id on both requests of one dispatch.

- Router PR: [vllm-project/router#338](https://github.com/vllm-project/router/pull/338)

**Breaking:** push mode now needs a router that sets `transfer_id`. Without it the request skips the KV transfer (same as Mooncake): P frees its blocks while D runs the prefill itself.

This PR:
- pairs P and D by `transfer_id` instead of the request id
- removes the old base request id matching
- gives each prompt of a batched `/v1/completions` request its own `transfer_id`
- sends `transfer_id` from the toy proxy and the push demo proxy
- bumps `NIXL_CONNECTOR_VERSION` to 15

## Fixes / unblocks

- [#48633 C4](https://github.com/vllm-project/vllm/issues/48633): fixes wrong pairing when request ids repeat, e.g. on a client retry
- [#48633 C1](https://github.com/vllm-project/vllm/issues/48633): `PUSH_CANCEL` can match by `transfer_id`
- [#48633 L1](https://github.com/vllm-project/vllm/issues/48633) / [#53095](https://github.com/vllm-project/vllm/issues/53095): push heartbeats can find P's lease by `transfer_id`
- [#45688](https://github.com/vllm-project/vllm/pull/45688): push-mode pairing no longer depends on request ids

## Why transfer_id

- Mooncake and MoRI-IO already pair P and D by a router `transfer_id`
- Agreed on in [#45688](https://github.com/vllm-project/vllm/pull/45688#issuecomment-4709524832) by @markmc @njhill @NickLucche
- [Slack discussion](https://vllm-dev.slack.com/archives/C0A9AAG7QR2/p1790760867615409)
