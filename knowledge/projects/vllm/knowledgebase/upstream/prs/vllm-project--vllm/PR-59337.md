# [MoE] Disable expanded DeepEP v2 dispatch in all execution modes

[Upstream PR](https://github.com/vllm-project/vllm/pull/59337) · state: open · merged: False

## Original PR description

## Purpose

DeepEP v2 currently selects expanded dispatch and CPU synchronization from `enforce_eager`. Use `do_expand=False` and `do_cpu_sync=False` for every forward so eager execution, warmup and CUDA graph capture share the same dispatch contract.

Remove the constructor flag and unused expanded-layout receiver code. Preserve DP-wide, sequence-parallel-aware receive-capacity buckets, padding masking and GPU receive metadata. Allow preparation without a forward context by falling back to the input shape.

Expanded dispatch needs an expert backend that consumes grouped rows efficiently. Enabling it for large prefills is deferred to a backend-specific follow-up with rank-coordinated policy, tuning and serving validation. Capacity-based allocations may use more memory than the previous synchronized eager path; this PR claims no general speedup or memory reduction.

Duplicate-work check: open DeepEP PRs were inspected. #51589 proposes opt-in adaptive prefill dispatch; this change makes non-expanded dispatch unconditional. It does not duplicate #50511's padding fix or #59687's SP buffer sizing fix. Future expanded-prefill work should coordinate with #51589.

AI assistance was used for implementation, review and validation. The human submitter is responsible for reviewing every changed line, running relevant tests, and defending the change.

## Test Plan

Exercise prepare/finalize contracts and BF16/FP8 expert outputs across eager execution, capture/replay and return to eager. Validate exact 8k/16k synthetic prefills, full GSM8K, and non-overloaded 8k-input/1k-output serving with `VLLM_GPU_SYNC_CHECK=error`.
