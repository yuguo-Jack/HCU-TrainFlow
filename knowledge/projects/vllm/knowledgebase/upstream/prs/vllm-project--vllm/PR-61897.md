# [Feature][MoE] Support routed experts capture (R3) with pipeline parallelism

[Upstream PR](https://github.com/vllm-project/vllm/pull/61897) · state: open · merged: False

## Original PR description


## Overview

Enable routed experts capture (R3) with pipeline parallelism in Model Runner V2 using the multiprocessing executor. Each PP stage captures its local layers, and the executor combines stage outputs into the full per-request routing tensor.

<img width="1650" height="1185" alt="image" src="https://github.com/user-attachments/assets/be2a4c1a-7c41-4bb7-8f2c-3200576d8758" />


## Claims

- Allow `--enable-return-routed-experts` with PP > 1 and return routing data in global layer order.
- Handle auxiliary outputs on non-last PP stages asynchronously, including prefill-only steps and terminal prefill requests.
- Treat `AuxOutputConfig.max_bytes` as a total budget across PP stages, with the same block capacity on every stage.

## Validation

### Correctness

Tested GLM-4.7-Flash on veRL over 20 training steps with MTP enabled, configured to predict one speculative token per decoding step. The plot compares `training/rollout_probs_diff_mean` across TP2/PP2 with R3 disabled, TP2/PP2 with R3 enabled, and TP2/PP1 with R3 enabled. With R3 enabled, the TP2/PP2 curve closely tracks the TP2/PP1 reference throughout the run.

## Details
Enables R3 with pipeline parallelism. Each PP stage captures and stores routing data for its local layers, using the last stage’s sampled/rejected token counts to discard rejected routing rows. The executor concatenates stage outputs along the layer axis and returns the complete routing result.
