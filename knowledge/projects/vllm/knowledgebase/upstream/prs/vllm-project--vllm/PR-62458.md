# [torch.compile] Use opt-out hash factors for LoRA, multimodal and aux output configs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62458) · state: open · merged: False

## Original PR description



## Overview

Part of #39479. `LoRAConfig`, `MultiModalConfig` and `AuxOutputConfig` now hash every field except an explicit ignore list (`get_hash_factors`), instead of a hand-written list of hashed fields. The hashed fields are the same as before.

## Claims

- A field added to these configs later enters the torch.compile cache key automatically. Forgetting to list it can no longer make vLLM reuse a cache compiled for a different setting, which crashed in the Inductor kernels in #32842 (`mm_encoder_tp_mode` was missing from the `MultiModalConfig` hash).

## Validation

- `pytest tests/config/test_multimodal_config.py tests/config/test_aux_output_config.py tests/config/test_config_utils.py`: 203 passed.
- `pre-commit run --from-ref main --to-ref HEAD`: passed.

## Details

- LoRA and multimodal deployments get a one-time compile cache miss after upgrading.
- The Mooncake embedding store namespace, derived from `MultiModalConfig.compute_hash()`, also changes once after upgrading, so embeddings stored by older vLLM versions are not reused.
- Not a duplicate: no open PR migrates these configs. #58323 (adds `specialize_active_lora` to the LoRA hash) will conflict textually.
- AI assistance (Claude Code) was used. I reviewed every changed line and ran the tests above.
