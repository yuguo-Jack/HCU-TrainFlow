# [Elastic EP] Park scale-up ranks so they can be checkpointed and join as any rank

[Upstream PR](https://github.com/vllm-project/vllm/pull/64155) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Let an external-LB elastic EP scale-up rank be fully prepared before it is needed: it loads the model, allocates its KV cache and captures CUDA graphs without contacting the running ranks, then joins later as any DP rank and into a world of any size, keeping its graphs. A parked rank can be checkpointed with CRIU/cuda-checkpoint (e.g. Dynamo Snapshot) and restored on demand, so one snapshot serves every joining rank.

Depends on three NIXL EP PRs: ai-dynamo/nixl#2533 (defer agent creation), ai-dynamo/nixl#2534 (no FABRIC memory before the transport starts), ai-dynamo/nixl#2535 (rank in device memory, `Buffer.set_rank`). Builds on #62570 (process checkpoint lifecycle) and #43202 (external-LB elastic EP). Related but not overlapping: #62973 standardizes how external ranks are launched, and #62082 correlates scaling operations.

## Claims

- New `VLLM_ELASTIC_EP_JOIN_FILE` (with `VLLM_ELASTIC_EP_SCALE_UP_LAUNCH`): the rank builds against placeholder groups, writes `<file>.parked`, and joins once the file names rank 0 (`data_parallel_master_ip`, `data_parallel_rpc_port`) and optionally the DP rank to join as (`data_parallel_rank`).
- A parked rank joins a world of any size up to `--elastic-ep-max-dp-size`, and as any DP rank >= 1, without recapturing CUDA graphs.
- Scale-up drops from ~116-143 s (cold joiner) to ~14 s for DeepSeek-V2-Lite on GB300. With a snapshot restore, the step is ~14-16 s plus the restore.
- Parked ranks act as ordinary ranks in later scale-ups and scale-downs. The rank's API server now learns the DP size and rank 0's address from its engine, which also fixes later scaling of any rank started with a placeholder address.
- Configurations a parked rank cannot join with (rank 0, TP > 1, a backend other than `nixl_ep`, no `--kv-cache-memory-bytes`, the `symm_mem` EPLB communicator, speculative decoding, KV transfer or KV events, fault tolerance) are rejected at startup with a clear error.
- No behavior change unless `VLLM_ELASTIC_EP_JOIN_FILE` is set.

## Validation

GB300 (4 GPUs/node, MNNVL), DeepSeek-V2-Lite BF16, TP=1, `--all2all-backend nixl_ep --enable-eplb --elastic-ep-max-dp-size 16`, parked ranks with `--data-parallel-size 16 --eplb-config '{"num_redundant_experts":192}' --kv-cache-memory-bytes 8589934592`.

Correctness: 5 prompts x 48 greedy tokens on every rank, one rank at a time, compared with the cold world-4 reference, plus top-3 logprobs for one prompt. (When every rank serves at once, one prompt flips between two continuations whose top-2 logprobs differ by 0.125. A stock cold-joiner control flips at the same rate, so those checks are not used for pass/fail.)

Unit tests, which run without GPUs or NIXL:

## Details

How a parked rank works:
1. `_init_elastic_ep_world` and `initialize_model_parallel` build `DetachedGroupCoordinator` placeholders: no store, process group or communicator. The NIXL EP buffer is allocated with `init_transport=False`, and the EPLB communicator is deferred.
2. The engine captures CUDA graphs with all peers masked, writes `<file>.parked`, and waits for the join file.
3. `join_parked` optionally moves the rank (placeholder world group, `parallel_config`, `Buffer.set_rank`), creates the real groups with the same `create_standby_groups` path old ranks use, runs the MoE/EPLB host-state refresh factored out of `switch_and_prepare` for the world size rank 0 sent, checks M and experts-per-rank against rank 0, connects NIXL EP, then builds the EPLB communicator. The engine then runs the normal scale-up launch steps (weights, expert mapping, reshuffle).

Why graphs stay valid: everything a captured graph reads is sized by M = `elastic_ep_max_dp_size`, experts per rank, logical experts or max tokens (NIXL buffers, EPLB maps, load buffer, batched-expert workspaces) and is updated in place, which is why old ranks already keep their graphs across scale-ups. The only rank baked into graphs was NIXL EP's scalar kernel argument, which ai-dynamo/nixl#2535 moves to device memory.

Limitations: rank 0 cannot be parked. The parked rank must match rank 0's M, experts per rank and `max_num_batched_tokens` (M and experts per rank are checked). Process names keep the launch rank. ~540 added lines outside tests and docs, mostly the parked path and the shared refresh.
