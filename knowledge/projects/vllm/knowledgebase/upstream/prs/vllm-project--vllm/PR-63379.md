# [Bugfix][LoRA] Align Qwen3 audio projections with valid token mappings

[Upstream PR](https://github.com/vllm-project/vllm/pull/63379) · state: open · merged: False

## Original PR description

## Overview

Addresses the Qwen3-ASR and Qwen3-Omni audio case in [#61608](https://github.com/vllm-project/vllm/issues/61608). Partial audio chunks were projected with padding rows before the tower LoRA mapping was applied, so projected rows and mapped rows diverged.

## Claims

- Select valid post-CNN rows before the LoRA-wrapped `conv_out`, keeping positional embedding indices and attention chunk boundaries unchanged.
- Add a real `Qwen3-ASR-0.6B` LLM regression with a deterministic sparse audio-tower adapter.
- The fix is specific to Qwen3 audio. #61608 tracks other model cases that this change does not resolve.

## Validation

```bash
../.tools/bin/uv run --no-project --python .venv/bin/python python -m pytest tests/lora/test_qwen3_asr.py -v -s
```

On the upstream baseline, the real LLM regression fails with `26 projected rows vs 14 valid rows`; with this change it passes. Full pre-commit passes, including Ruff, markdownlint, Buildkite test tethering and mypy. `git diff --check` passes. Both V2/eager GPU runs use `VLLM_GPU_SYNC_CHECK=error`.

On an A100, 13 audio shapes in fp32 and bf16 (26 comparisons total), using a small one-layer randomly initialized encoder, produced bitwise-equal outputs versus the pinned upstream forward. On an A800, a pinned Qwen3-ASR-0.6B checkpoint was evaluated on the same duration-stratified 64-utterance LibriSpeech test-clean subset, at batch sizes 1 and 8. Baseline and candidate both had 32 word errors over 1,284 reference words (2.4922% WER) for both batch sizes. 127/128 output pairs matched exactly; all 128 pairs matched after text normalization. Encoder outputs were not bitwise identical in every pretrained-model call; maximum observed absolute differences were 0.05884 (batch 1) and 0.01734 (batch 8). The one raw-text difference was punctuation/capitalization. No throughput gain is claimed.

Additional Omni validation loaded all 525 audio-tower tensors from the pinned
Qwen3-Omni-30B-A3B-Instruct checkpoint into its complete 32-layer audio tower.
Four real Punica LoRA cases (same adapter, mixed adapters, swapped order, and
mixed short/full chunks) had projection error 0.5 before the fix and zero after
it against the independent sparse-adapter reference. All candidate projections
had exactly the valid row count. Nine unadapted cases had maximum absolute
encoder difference 0.001984 and minimum cosine similarity 0.9999079; six were
bitwise equal. This validates the audio tower only; no complete Omni 30B LLM
or vision/talker inference was run.

| Validation | Baseline | Candidate |

| Real ASR LLM regression | Fails: 26 projection rows / 14 valid rows | Passes; sparse LoRA projection is exact |

## Details

`conv_out` is a pointwise replicated linear applied to flattened `[chunks, time, features]` rows. Before the change it ran before `padded_mask_after_cnn` removed right-padding positions, whereas tower LoRA mappings contained only valid positions. The encoder now derives chunk and position indices from the existing mask and gathers inputs before projection. Position embeddings use selected within-chunk position indices, preserving the original non-LoRA semantics. The following transformer and connector receive the same packed valid-row sequence and cumulative chunk boundaries.

Duplicate-work checks: open PR #50793 fixes Qwen3-ASR audio QKV adapter name mappings. Open PR #62494 quantizes Qwen3 audio linears and removes a host synchronization but retains padded `conv_out` projection. Neither implements this change. The open LLaVA and Ultravox LoRA sizing PRs concern other models.

AI assistance was used for implementation and local validation. The submitting user reviewed the change and reported no problems; test commands were executed on the submitter's machine with Codex assistance.
