# [Recipe] MiniMax-M3: add B200 NVFP4 AgentX aggregated profile

[Upstream PR](https://github.com/vllm-project/vllm/pull/63163) · state: closed · merged: True

## Original PR description

## Overview

Adds the B200 NVFP4 AgentX aggregated serving profile for MiniMax-M3 from SemiAnalysisAI/InferenceX#4382 (`minimaxm3-fp4-b200-vllm-agentic-mtp` and `minimaxm3-fp4-b200-vllm-agentic-mtp-c10`).

## Claims

- The NVFP4 variant on B200 renders the qualified flags in the command builder: prefix caching, `--max-num-batched-tokens 16384`, `--gpu-memory-utilization 0.95`, `--disable-flashinfer-autotune`, `--stream-interval 20`, and the pinned B200 image.
- The GQA EAGLE3 draft on B200 uses FlashInfer draft attention with local argmax reduction, as on GB200.
- A new guide section documents the per-concurrency settings (`--max-num-seqs`, `--max-num-active-seqs`, draft tokens, CUDA graph capture sizes, SimpleCPUOffload KV offload) for both InferenceX keys, with their digest-pinned images.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <vllm>/recipes` passes against current `vllm-project/recipes` main.
- Rendered the B200 / NVFP4 / Single-node TP / GQA / text-only command with the builder's `resolveCommand` and compared it with the qualified command; TP4 requires overriding the builder's TP8 default, noted in the guide.
- The InferenceX sweep for #4382 passed its agentic and eval jobs on the head this recipe documents.

## Details

Per-point differences stay in the guide, following the GB200 AgentX section. The `-c10` arms use a different pinned image, `mnnvl` all-reduce and no local argmax reduction, so they are documented separately. The builder's NVFP4 default sets `minimax_m3_msa_decode_backend: cutlass` on every point; the qualified points set it only for concurrency 30 and 38, which the guide states.
