## Details

The MLA test was nested inside `test_handshake_decode_errors`, so pytest never collected it. Its registration call and READ assertions had drifted. The restored test runs the real asynchronous handshake: decode TP=1 reads from prefill rank 0 and notifies ranks 1–3. Both the READ completion and broadcasts must carry the remote prefill request ID, rather than the local decode ID. Only external transport is faked.

Its config is now a real one-layer `DeepseekV2Config` saved under `tmp_path`, retaining the MLA dimensions used by the fixture. With no HF cache or credentials, the test still passes. Replacing either notification ID in memory makes it fail with `decode-req-AAAA:1` versus required `prefill-req-BBBB:1`. This restores coverage; it does not claim a production request-ID defect. The active `v1-others-cpu` command selects it; collection with that working-directory and marker convention confirms one case.

The review cleanup removes 88 redundant scheduler hash wrappers, keeps 13 required by typed `ReqMeta` boundaries, and adds `_hashes()` for repeated worker lists. Scheduler `BoundaryPut` construction now matches upstream. The three specified lifetime-sensitive method overrides use `type: ignore[method-assign]`, and monkeypatch parameters are regular arguments. Original assertions, decorators and async cleanup are preserved. No production change, relaxed assertion, retry or new skip is included.

I checked the issue and related work before opening this PR; #62891 covers the separate parent/root rollup. AI assistance was used for implementation and local checks.
