# [Bugfix][LoRA] Load the head of SEQ_CLS adapters saved without modules_to_save

[Upstream PR](https://github.com/vllm-project/vllm/pull/63286) · state: closed · merged: True

## Original PR description

## Overview

Fixes #63285. PEFT adds `classifier` and `score` to `modules_to_save` whenever it loads a `SEQ_CLS` or `TOKEN_CLS` adapter, so many saved adapters keep `modules_to_save: null` while still saving the head. vLLM now does the same based on `task_type`, so the saved head loads as a full module instead of being read as a LoRA weight with no LoRA A.

## Claims

- `SEQ_CLS` and `TOKEN_CLS` adapters saved with `modules_to_save: null` load and match transformers + PEFT. On main they fail with an `AssertionError`, which kills the engine core for offline requests and stops `vllm serve --lora-modules` from starting.
- No change for adapters that already list `modules_to_save`, or for other task types.

## Validation

vLLM fp16 against transformers + PEFT fp32 on an RTX 4070 Ti SUPER, 4 prompts each:

| Adapter | Main | This PR |
|---|---|---|
| `Intradiction/BERT-SA-LORA` | `EngineDeadError` | 2.4e-3 |
| `TransferGraph/bert-base-uncased-finetuned-lora-tweet_eval_emotion` | `EngineDeadError` | 2.3e-3 |
| `EliasKD/LoRA-imdb-seq-cls` | `EngineDeadError` | 1.2e-3 |
| `leonvanbokhorst/emotion-bert-large-uncased-lora` | `EngineDeadError` | 8.2e-3 |

On a running `vllm serve`, `/v1/load_lora_adapter` with `Intradiction/BERT-SA-LORA` returns 500 on main and 200 with this PR, and requests with the adapter then succeed. `romainjeff/bert-banking77-classifier-lora` also loads with this PR. It matches transformers once its `bert.pooler.dense` LoRA is applied, which is #60211.

With PEFT 0.10.0 and earlier, a plain `get_peft_model` and `save_pretrained` of a `SEQ_CLS` adapter writes `modules_to_save: null` while saving the head. PEFT 0.11.0 and later write `["classifier", "score"]`. `tests/lora/test_peft_helper.py`, `tests/lora/test_sequence_classification.py` and `tests/lora/test_lora_checkpoints.py` pass.

## Details

`PEFTHelper` now reads `task_type`, mirroring `PeftModelForSequenceClassification.__init__` and `PeftModelForTokenClassification.__init__`. An adapter that declares the task but saves no head is unaffected, because only the tensors actually present become full modules.

Thanks for the fix! Just one question: under what circumstances would PEFT produce an adapter with `modules_to_save=None` while still saving the classification head? Is this something that can happen through the normal training and saving workflow, or does it require manually modifying the config?

- subin9 · comment · 2026-10-28T08:33:34Z · [source](https://github.com/vllm-project/vllm/pull/63286#issuecomment-6464379316)

It happens through the normal workflow on PEFT 0.10.0 and earlier, no manual editing needed. Those versions added `classifier`/`score` to `modules_to_save` on the model but not in the config, so `save_pretrained` writes `modules_to_save: null` while still saving the head. It was fixed in PEFT 0.11.0 (huggingface/peft#1615). I saved the same SEQ_CLS adapter with several PEFT versions to confirm: 0.6.2 to 0.10.0 give `null`, and 0.11.1 onward give `["classifier", "score"]`. The adapters in the table are all from early 2024.
