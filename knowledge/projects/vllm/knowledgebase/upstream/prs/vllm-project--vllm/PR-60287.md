## Overview

Fix Nemotron masked-diffusion logprobs changing or disappearing when neighbouring requests use different logprob settings. This stacked follow-up targets upstream main and depends on #58387. Tracking: #60283.

[Review the isolated four-file fixes delta](https://github.com/pst2154/vllm/compare/7dca05864dea6c2e039382d0cee3b85b388ff13b...d3df247914bbc43ebc82957cc67afe23c6b1b2d9). The comparison against main includes the unmerged model-support dependency; this is not a competing model implementation.

## Claims

- Preserve sampled-token and top-k scores from the distribution at each position's reveal step, independently of neighbouring requests.
- Use fixed per-request output offsets and GPU completion counts, avoiding host reads of convergence flags.
- Reject unsupported masked-diffusion pipeline parallelism during configuration.
- Retain the stochastic compiler workaround previously validated on SM100.

Linear-speculation bookkeeping is deferred with the removed linear-speculation feature rather than included in this fix.

Historical manual validation used public `nvidia/Nemotron-Labs-Diffusion-8B`, revision `16c67f0560b912e93e0cabb6e0c4f5c3086d95fc`, BF16, TP=1, PP=1, Triton attention and context 2,048. Diffusion/configuration subsets passed on A100, H100 and B200, including eager/compiled mixed-logprob tests and stochastic generation. Three FP32 HF-reference checks passed on H100. Those results predate this rebase; RTX was not validated.

The original H100 reproducer changed a sampled token's logprob from `-0.535999` alone to `-11.367270` in a mixed batch without changing its token. The regression compares equal-sized three-request batches, resets the prefix cache, requests `None`, `0` and `2` logprobs, and uses token budgets 17, 41 and 9. It checks token equality, complete scores and sampled-token probabilities within 0.02 absolute tolerance, including when the top-k neighbour finishes early.

## Details

Previously, the batch-wide maximum top-k request selected the score-output path for every request, which could replace reveal-time scores with final-step scores or lose scores when that neighbour completed. Per-request reveal buffers and retained top-k entries remove that dependency. Requested top-k capture can add computation; no end-to-end speedup or new model-quality score is claimed.

The PP rejection test asserts the `PP=1` restriction without depending on the old pluralized error message. No numeric tolerance was relaxed. After the dependency merges, rebase and rerun the affected CUDA checks before merge.

Codex assisted with implementation, review fixes and checks. Human review of the revised diff and confirmation of required validation remain necessary.
