# [Bugfix][Benchmark] Fix bench mm-processor crash with HF datasets

[Upstream PR](https://github.com/vllm-project/vllm/pull/64831) · state: open · merged: False

## Original PR description

## Overview

`vllm bench mm-processor --dataset-name hf`, the HuggingFace example in `docs/benchmarking/cli.md`, crashes with `AttributeError`. This one-line fix closes the same kind of gap as #56300, which fixed random-mm sampling.

## Claims

`bench mm-processor` runs on HF datasets. `bench throughput` and `bench serve` behave as before.

## Validation

```bash
vllm bench mm-processor --model Qwen/Qwen2-VL-2B-Instruct --dataset-name hf \
  --dataset-path lmarena-ai/VisionArena-Chat --hf-split train --num-prompts 5 --seed 0 \
  --load-format dummy --enforce-eager --disable-tqdm --output-json out.json

pytest tests/benchmarks/test_throughput_cli.py -k hf_dataset_with_mm_processor
```

```text
# before
AttributeError: 'Namespace' object has no attribute 'hf_name'    # both commands

# after
bench: exit 0, completed 5, failed 0, 5 encoder calls
pytest: 1 passed
```

The bench ran on an L4 with real VisionArena data and dummy weights, on a pinned wheel with the same bug and the same one-line change. The new test uses the real `VisionArenaDataset` with only the HF download stubbed, and checks for text and image chat prompts.

## Details

`get_samples` reads `args.hf_name` for every HF dataset. `bench mm-processor` has no `--hf-name` flag, and `_to_serve_args` backfills its other missing flags but not this one. With `None`, datasets fall back to `--dataset-path`.

`bench mm-processor` still accepts only its listed dataset paths, so local copies stay unsupported. I found no open PR or issue for this.
