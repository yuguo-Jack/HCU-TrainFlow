# [Bugfix][Pooling] Validate late-interaction mode and use count in the Python API

[Upstream PR](https://github.com/vllm-project/vllm/pull/63112) · state: closed · merged: True

## Original PR description

## Overview

`LateInteractionParams` had no validation, and bad inputs fail in the worst places:

- An unknown `mode` string is silently skipped by the late-interaction runner (`_parse_late_interaction_meta` returns `None` for anything outside `cache_query`/`score_doc`), so a typo produces ordinary pooler output instead of an error.
- `cache_query` with `query_uses=None` crashes on the runner's `assert query_uses is not None`.
- `query_uses <= 0` poisons the cache lifecycle: the entry pops on the first `score_doc`, so the remaining paired documents fail with a cache miss.

`__post_init__` now rejects unknown modes and non-positive use counts, the same shape as the `LateChunkingParams.chunk_size` validation added in #63051. The HTTP scoring path builds these params programmatically with valid values (`build_late_interaction_query_params` / `build_late_interaction_doc_params`), so only hand-constructed Python-API requests change behavior.

This is not duplicating an existing PR: the only open late-interaction work is about cancelling cached queries (#56617) and request tracing (#61785), which are different seams.

Good point, and the scoring path makes it concrete: it clones PoolingParams and assigns late_interaction_params per query and doc during input processing, so a construction-time check would fire before the fields are final. Moved both checks into PoolingParams.verify, at the top alongside the late-chunking verify so every task's verification reaches them before the task-specific handling. Construction now accepts a work-in-progress, and the tests drive PoolingParams.verify instead of asserting on the constructor.

LateChunkingParams still validates in __post_init__ as well (from #63051). Happy to align that one the same way if you want the convention enforced across both.
