# [CI] Shard (L4) Pipeline Parallelism tests into named jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/58464) · state: closed · merged: False

## Original PR description

## What

Splits the `(L4) Pipeline + Context Parallelism` job (~40 min of pytest in one serial job, recent `main` runs at 41–43 min wall against a 55 min timeout) into three named Pipeline Parallelism jobs: a 4-way hash-sharded `Models` job over a new `tests/distributed/pipeline_parallel/` folder, plus one-replica `CUDAGraph` and `DP V2` jobs. Test selection is unchanged on every lane: the monolith `test_pipeline_parallel.py` is split into per-family wrappers with the same 29 cases and params, and no `-k`/`-m`/`--ignore` filters are added. Every new job has an AMD mirror.

## Old

One job per lane ran three pytest commands serially:

- `:nvidia: (L4) Pipeline + Context Parallelism` (`pipeline-context-parallelism-4-gpus`): `test_pp_cudagraph.py` (1 case), `test_pipeline_parallel.py` (29 cases, most of the runtime), `v1/distributed/test_pp_dp_v2.py` (6 cases)
- `:amd: (MI250) Pipeline + Context Parallelism`: mirror of the above (the DP V2 file skips on ROCm)

The name is historical: #23734 added `test_context_parallel.py` to this job only as a commented-out line. That test runs in `(H100) Distributed Features` and `(B200) Distributed`, which this PR does not touch.

## New

| label | key | contents |
|---|---|---|
| :nvidia: (L4) Pipeline Parallelism Models Shard %N | `pipeline-parallelism-models-4-gpus`, `parallelism: 4` | `tests/distributed/pipeline_parallel/` (29 cases, pytest-shard) |
| :nvidia: (L4) Pipeline Parallelism CUDAGraph | `pipeline-parallelism-cudagraph-4-gpus` | `distributed/test_pp_cudagraph.py` |

| :amd: (MI250) Pipeline Parallelism CUDAGraph | generated `amd-pipeline-parallelism-cudagraph-4-gpus` | mirror, one replica |
| :amd: (MI355) Pipeline Parallelism DP V2 | generated `amd-pipeline-parallelism-dp-v2-4-gpus` | mirror, all six cases with `VLLM_USE_V2_MODEL_RUNNER=1 VLLM_ROCM_USE_AITER=1` (added by @AndreasKaratzas) |

The Models and CUDAGraph mirrors are copied from the original mirror (same device, inherited command). The DP V2 file previously skipped on ROCm; @AndreasKaratzas's commit makes it eligible there (`is_cuda_alike()`) and runs it on a four-GPU MI355 mirror, with the NVIDIA job and test scenarios unchanged.

Monolith split (`tests/distributed/test_pipeline_parallel.py` deleted):

```text
tests/distributed/pipeline_parallel/
├── __init__.py
├── _common.py                        # settings machinery, model catalog, _compare_tp — not collected
├── test_llama_mp.py                  # Llama-3.2-1B-Instruct detailed, mp backend (5)
├── test_llama_ray.py                 # Llama-3.2-1B-Instruct detailed, ray backend (5)
├── test_phi3_5_moe.py                # Phi-3.5-MoE detailed, multi_node_only (10)
├── test_language_generation.py       # Ilama / PowerLM / DeepSeek-V2-Lite / Jamba (4)
├── test_language_embedding.py        # e5-mistral / bge-multilingual-gemma2 (2)
└── test_multimodal_generation.py     # InternVL3 / Phi-3.5-vision / ultravox (3)
```

Consumers of the shared file move with it:

- `(L4) Distributed 2-Node` runs `VLLM_MULTI_NODE=1 pytest -v -s distributed/pipeline_parallel/` (whole folder; same cases run/skip as before).
- `(L4) RayExecutorV2` replaces `pytest distributed/test_pipeline_parallel.py -k "ray"` with `pytest -v -s distributed/pipeline_parallel/test_llama_ray.py`. The only ray-backend cases that run on a single node are Llama's (the Phi-3.5-MoE ray cases are `multi_node_only` and skip), so coverage is unchanged and the `-k` filter is gone.
- Legacy `test-amd.yaml` (`amd-ci`): the MI250 Pipeline + Context Parallelism step runs the whole folder in place of the monolith, DP V2 moves to a new four-GPU MI355 step with the same settings as the inline mirror, and the MI300 RayExecutorV2 step runs `test_llama_ray.py`.
- CODEOWNERS entry updated to the folder.

## Notes

- Coverage equivalence is verified statically: the wrappers' `TEST_MODELS` union is exactly the original 11-model list, giving the same 29 cases with the same params (llama 5 mp + 5 ray, phi3.5-moe 10, 4 fast language, 2 embedding, 3 multimodal). `check_test_tethering.py`, `yaml.safe_load` on both pipeline files, ruff, and the `bash -n` join check for the edited `amd-ci` steps pass.
- Shard count is 4 on both lanes. `pytest-shard`'s hash assignment is deterministic, and at 3 shards one shard took far more than the others on both lanes (over the 20-minute target on the mirror lane).
- The DP V2 job triggers on `vllm/v1/worker/gpu/`, `vllm/v1/worker/gpu_worker.py` and `vllm/v1/executor/` (the paths from #57735) instead of all of `vllm/v1/`. #57735 (open) also edits the old job's dependencies; whichever lands second rebases.
- AI assistance was used for this change (evidence gathering, the split, YAML edits, local checks).
