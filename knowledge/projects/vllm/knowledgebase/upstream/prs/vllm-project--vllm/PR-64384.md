# [MRV2][DBO] Select eager microbatch counts within a fixed capacity

[Upstream PR](https://github.com/vllm-project/vllm/pull/64384) · state: open · merged: False

## Original PR description

## Overview

Opt-in **eager** selection between two and three active MRV2 microbatches within a fixed capacity, tracking #64353 and parent RFC #63501. **Draft: static review, CPU unit tests and single-GPU component tests only. No model was loaded.** Captured 2/3 graph variants remain follow-up work; graph modes are rejected in this first slice.

## Claims

- Add `--dbo-ubatch-capacity 3`; the default capacity two keeps fixed two-way DBO.
- Reuse the DP handshake: select three when every rank has at least three times the relevant token threshold, otherwise two when eligible, keeping the veto/idle fallback.
- Size metadata, workspace and shared-expert state by capacity. Slicing, barriers, threads and merging use the active count from the existing `BatchExecutionDescriptor`.
- Give each microbatch its own native DeepEP HT buffer, cached across layers by the existing manager; per-microbatch buffers are intranode only.
- Capacity three requires `--enable-dbo`, DeepEP HT, MRV2, eager execution, synchronous scheduling and no speculative decoding.

## Details

Production change: **+110/-24**. The three slots own three real buffer allocations; growing a Python handle list alone would not provide the native capacity. Each reserves `VLLM_DEEPEP_BUFFER_SIZE_MB` MiB (3072 MiB per rank at the default), even on steps that use two microbatches. No speedup is assumed.

Duplicate checks searched #64353, #63501 and microbatch-count keywords and read the issue comments. No open implementation of bounded per-step count selection was found. #63823/#63556 concern fixed-count padding/replay, #64293 prepares metadata, and #61584 reserves workspace; their goals differ from active-count selection.

Before readiness: human review of every changed line; real 2→3→2 CUDA runner and native DP communication, thread completion and output/logprob checks; resource/memory and performance qualification. Captured count variants remain an explicit incomplete acceptance item for #64353. AI assistance was used for implementation, review and tests.
