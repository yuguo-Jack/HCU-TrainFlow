# [Bugfix][Reasoning] Force the V1 thinking-budget end sequence at every draft position

[Upstream PR](https://github.com/vllm-project/vllm/pull/61005) · state: open · merged: False

## Original PR description

## Purpose

Fixes #58485: on Model Runner V1 with speculative decoding, a `thinking_token_budget` that forces a multi-token `reasoning_end_str` often emits the end sequence wrong. End tokens go missing with one of the model's own tokens in their place, and some reasoning sections never close. On main `9f07d023d07f`, 17 of 32 budget-forced ends were corrupted on V1 and 0 of 32 on V2, same host, model and flags (reproduction in the issue).

The cause is `ThinkingBudgetStateHolder._update_think_state` in `vllm/v1/sample/thinking_budget_state.py`. While forcing, it walks the step's draft tokens instead of the accepted ones, and forces one position per step:

- A draft that matches the next end token advances `end_count`, and its position is left to the target's own logits. If the target samples something else there, the draft is rejected, the target's token is committed, and the next step resumes forcing past the end tokens it already counted. That is the "I have to give final based on ..." output in the issue: " final" where " the solution" belongs.
- When the drafts reach the last end token, `in_end` is cleared before any of them is verified.

V2 already forces every position of the verification window. V1 is still what runs spec decode with `suffix`, `medusa`, `mlp_speculator` or `custom_class`, with EAGLE parallel drafting, with heterogeneous-vocabulary draft models (`_get_v2_model_runner_unsupported_features` on main), and with `VLLM_USE_V2_MODEL_RUNNER=0`.

## The fix

All in `vllm/v1/sample/thinking_budget_state.py`:

- Progress through the end sequence comes from the accepted output: the longest proper prefix of the sequence the output ends with, or completion once the whole sequence appears in the newly accepted tokens.
- Every position of the verification window, drafts and bonus, is forced to its own end token, including when forcing starts part-way through a window at the budget transition.
- `_apply_forcing_to_logits` writes one end token per position: draft positions in the target call, the bonus position in the bonus call.

Without speculative decoding the window is a single position, so it still forces one end token per step. The path with no new output is untouched.

## Not a duplicate

Searched open and closed PRs for `58485`, `_update_think_state`, `thinking_budget_state.py`, and "thinking budget" with speculative decoding. None changes the forced-end draft walk. #52106 (incremental marker scans), #60077 (`sync_batch` destination state) and #44690 (`<tool_call>` as an implicit end) edit the same file, and `git merge-tree` with each is clean. #58231 is the same configuration with a different cause: split-row top-p masking emits token 0. This fix was first written inside #52677 (`df93fe6c67`) and came out of it when that PR went V2 only.

## Model evaluation

From #58485, one GB10, Qwen3.8-27B-NVFP4 with MTP-3, temperature 0.7, a 14-token `reasoning_end_str`, `thinking_token_budget` 256, 32 requests per row:

| run | corrupted | closed | final answer |
|---|---|---|---|
| main `9f07d023d07f`, V1 | 17 of 32 | 27 | 21 |
| main `9f07d023d07f`, V2 | 0 of 32 | 32 | 25 |
| this fix as `df93fe6c67` in #52677, V1 | 0 of 32 | 32 | 26 |

Fisher two-sided p = 8.2e-7 on corrupted, main V1 against the fix. The last row is #52677's tree, which differs from main in more than this change; the forcing logic is the same. A forced end only corrupts when the model disagrees with a correct draft inside the end sequence, so the rate depends on the model, the phrase and the temperature. Requests whose budget never fires take the same path as before.
