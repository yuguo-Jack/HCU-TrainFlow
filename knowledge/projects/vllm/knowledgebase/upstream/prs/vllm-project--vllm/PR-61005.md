# [Bugfix][Reasoning] Force the V1 thinking-budget end sequence at every draft position

[Upstream PR](https://github.com/vllm-project/vllm/pull/61005) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fixes #58485. On Model Runner V1 with speculative decoding, a `thinking_token_budget` that forces a multi-token `reasoning_end_str` often emits the end sequence corrupted. This forces the end sequence at every draft and bonus position, and takes progress through it from the accepted tokens instead of the drafts.

## Claims

- V1 forced ends survive speculative decoding: every position of the verification window is forced to its own end token, including when forcing starts part-way through a window, and progress comes from the accepted output.
- A forced end token with no logits row now fails an assertion instead of being dropped silently (review thread with @freyfwt).
- No change without speculative decoding (the window is one position) or on a step with no new output.

## Details

**Root cause.** `ThinkingBudgetStateHolder._update_think_state` in `vllm/v1/sample/thinking_budget_state.py` walked the step's draft tokens instead of the accepted ones, and forced one position per step:

- A draft matching the next end token advanced `end_count`, and its position was left to the target's own logits. If the target sampled something else there, the draft was rejected, the target's token was committed, and the next step resumed forcing past the end tokens it had already counted: " final" where " the solution" belongs in the #58485 output.
- When the drafts reached the last end token, `in_end` was cleared before any of them was verified.

**The fix**, all in that file: progress through the end sequence is the longest proper prefix the accepted output ends with, or completion once the whole sequence appears in the newly accepted tokens. `_apply_forcing_to_logits` writes one end token per position: draft positions in the target call, the bonus position in the bonus call.

**Why V1 still needs it.** V2 already forces every position (0 of 32 above). On main `c1d8fade8d` these configurations still select V1 (`_get_v2_model_runner_unsupported_features`): `custom_class` speculative decoding, EAGLE parallel drafting, heterogeneous-vocabulary draft models, pipeline parallelism with `external_launcher`, the DBO cases it lists, hosts without Triton, and `VLLM_USE_V2_MODEL_RUNNER=0`. Suffix decoding moved to V2 in #60339 (2026-11-03), and `medusa` and `mlp_speculator` are no longer speculative methods, so the list in earlier revisions of this description was out of date.

**Related.** #62970 (open) fixes V1 row offsets on steps with no drafts; it touches `_apply_forcing_to_logits` for a different defect and is complementary. #61120 (open) stacks its natural-end correction on this PR. #58231 is the same configuration with a different cause (split-row top-p masking emits token 0). This fix was first written inside #52677 (`df93fe6c67`) and moved here when that PR went V2-only.

**Not a duplicate.** Open and closed PRs were searched for `58485`, `_update_think_state`, `thinking_budget_state.py`, and "thinking budget" with speculative decoding. None changes the forced-end draft walk. #52106, #60077 and #44690 edit the same file for unrelated reasons.
