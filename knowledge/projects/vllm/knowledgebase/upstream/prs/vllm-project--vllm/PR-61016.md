# [Bugfix][MRV2] Keep input_ids on later PP stages for raw-token models

[Upstream PR](https://github.com/vllm-project/vllm/pull/61016) · state: closed · merged: True

## Original PR description



## Overview

Model Runner V2 drops `input_ids` on every pipeline stage after the first, so models that set
`requires_raw_input_tokens` (they read token ids inside their decoder layers) cannot run with
`--pipeline-parallel-size > 1`. This keeps `input_ids` on later stages for those models, as Model Runner V1
already does. Fixes #55515.

## Claims

- MRV2 with pipeline parallelism works for models that set `requires_raw_input_tokens` (DeepSeek-V4 and V4.1
  vision variants, Qwen4Exp with N-gram PLE, Voxtral realtime): later stages receive `input_ids` in the execute
  path and in CUDA graph capture.
- Other models are unchanged: later stages still get `input_ids=None`.

## Validation

DeepSeek-V4.1-Flash, TP4 x PP2 + EP, 8x RTX PRO 6000 Blackwell (sm_120), max-model-len 1M, CUDA graphs,
no speculative decoding. Same image both times; only the two files in this PR differ.

| | Startup | Smoke (25k- and 60k-token prompts) | Needle at 20/50/90% of a 22.5k-token prompt | ITL p50, bs1 / bs16 |
| --- | --- | --- | --- | --- |
| upstream main | fails: every PP rank 1 worker raises `ValueError: DeepSeek V4 vision MoE routing requires input_ids.` | – | – | – |
| this PR | serves (health OK after 250 s) | pass | 3/3 found | 11.1 / 17.7 ms per token |

differ.

      --enable-expert-parallel --max-model-len 1048576 --max-num-seqs 64 --block-size 64 \
      --kv-cache-dtype fp8_ds_mla --attention-config '{"backend":"FLASHINFER_MLA_SPARSE_DSV41"}' \
      --tokenizer-mode deepseek_v41

</details>

`pre-commit run` passes on the changed files. CI test: `test_distributed_oot_pp_raw_input_tokens` in
`tests/distributed/test_distributed_oot.py` serves a dummy OPT from the `vllm_add_dummy_model` plugin that sets
`requires_raw_input_tokens = True` and asserts `input_ids` is not None, with PP=2 on MRV2, eager and with CUDA
graphs, in the 2×L4 plugin step. Without the fix both cases fail on the PP rank 1 worker; reverting only the
`cudagraph_utils.py` change fails the CUDA-graph case during capture. It passes in
[Buildkite build 94033](https://buildkite.com/vllm/ci/builds/94033). A dummy model is used because DeepSeek
V4/V4.1's sparse MLA kernels need sm90+ and the step runs on L4.

## Details

Root cause: `GPUModelRunner.execute_model` (`vllm/v1/worker/gpu/model_runner.py`) and
`ModelCudaGraphManager.capture` (`vllm/v1/worker/gpu/cudagraph_utils.py`) set `model_inputs["input_ids"] = None`
on every non-first PP rank. Every rank still prepares the same input batch, so the ids are already in the input
buffer there; MRV1 passes them to all ranks (the text-only branch of `gpu_model_runner.py`). The new condition
reuses `requires_raw_input_tokens`, the check MRV2 already applies on the first rank when it passes
`inputs_embeds`.

Relation to open PRs: #55520 (DeepSeek V4) and #56444 (Qwen4Exp) relay `input_ids` through `IntermediateTensors`
per model, and #60234 forbids PLE layers on later ranks. This change fixes the runner once, with no extra
inter-stage transfer and no per-model code; the input_ids relays in those PRs become unnecessary, while their
other fixes (KV allocation, MTP drafter) are independent.
