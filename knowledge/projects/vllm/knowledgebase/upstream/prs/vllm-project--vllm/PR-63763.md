# [Rust Frontend] Keep completions top_logprobs and prompt_logprobs in the engine's order like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/63763) · state: closed · merged: True

## Original PR description

## Overview

Python builds each legacy completions `top_logprobs` entry, and each `prompt_logprobs` entry, as a dict over the engine's logprobs row, so the JSON keys come in the engine's order with the sampled (or prompt) token first. Rust collected both into a `HashMap`, so key order varied between identical requests. This PR keeps the engine's order. One commit per surface.

## Claims

- Completions `top_logprobs` keys, and `prompt_logprobs` keys on chat and completions, come out in the engine's order with the sampled or prompt token first, as in Python.
- A repeated key keeps its first position and takes the last value, which is Python's dict semantics.
- This unblocks the completions cases of `tests/entrypoints/openai/test_return_tokens_as_ids.py`, which read the first key of each echoed `top_logprobs` entry as the prompt token (`next(iter(...))`).

## Validation

Commands from `.buildkite/scripts/run-rust-frontend-cargo-ci.sh` (`style-clippy` and `test`), run from the repo root:

```
cargo fmt --manifest-path rust/Cargo.toml --all -- --check   # ok
cargo sort --workspace --check rust                          # ok
cargo deny --manifest-path rust/Cargo.toml --config rust/deny.toml check bans   # ok
cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --all-features --locked -- -D warnings   # ok
cargo nextest run --manifest-path rust/Cargo.toml --workspace --all-features --locked --no-fail-fast
# 2312 tests run: 2312 passed, 13 skipped
```

The first commit alone also passes workspace clippy and nextest.

- `completion_top_logprobs_keep_engine_order`: engine row `[C, A, B, C]` gives `{"C","A","B"}`, for strings and for `token_id:N`.
- `prompt_logprobs_maps_keep_engine_order`: keys `[3, 1, 2]`.
- Both fail with `HashMap` and pass with the fix.

## Details

Python: `append_logprobs_for_next_position` (`vllm/logprobs.py`), then the dict comprehension in `_create_completion_logprobs` (`vllm/entrypoints/openai/completion/serving.py:774-791`).

Change: `LogProbs.top_logprobs` and `PromptLogprobs` (`rust/src/server/src/routes/openai/utils/types.rs`) hold `IndexMap`s, collected in the engine row's order. `IndexMap`'s `FromIterator` already keeps a repeated key at its first position with the last value, so no extra dedup is needed. The workspace `indexmap` dependency gains its `serde` feature; no new crate.

The order is a property of the wire DTOs, whose only producers are the two converters in `utils/logprobs.rs`. The decoded entries from `vllm-text` already arrive in engine order, so only the DTO's map type changes.

Not a duplicate: no open PR changes the Rust logprobs map type.
