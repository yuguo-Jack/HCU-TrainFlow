# [Kernel][MoE] MXFP8 W8A8 MoE on FlashInfer CUTLASS

[Upstream PR](https://github.com/vllm-project/vllm/pull/65189) · state: open · merged: False

## Original PR description

## Overview

Adds MXFP8 W8A8 (MXFP8 weights and MXFP8 activations) as a FlashInfer CUTLASS MoE
backend for the MXFP8 MoE oracle, on SM10x.

## Claims

`--quantization mxfp8` (and pre-quantized MXFP8 checkpoints) can run their MoE
  layers on FlashInfer CUTLASS, selected with `--moe-backend flashinfer_cutlass`.

## Validation

- New test `tests/kernels/moe/test_flashinfer_cutlass_mxfp8_moe.py`.


**GSM8K accuracy (5-shot, 1319 questions, GB300):**

| Model | bf16 | MXFP8, default (TRT-LLM) | MXFP8, CUTLASS |
|---|---|---|---|
| Qwen3-30B-A3B (gated SiLU) | 0.8954 | 0.8954 | 0.8999 |
| Nemotron-3-Nano-30B-A3B (relu2), chat mode, thinking off | 0.8893 | 0.9014 | 0.8886 |
| Nemotron-3-Nano, plain completions (not a meaningful setup) | 0.2449 | 0.3434 | 0.3351 |

## Details

- **Kernel path** (`flashinfer_cutlass_moe.py`): MXFP8 weights pass their E8M0 block
  scales as `int32` views with a unit input scale per expert, and set
  `use_mxfp8_act_scaling`, like the existing MXFP4-weight / MXFP8-activation path.
- **Weights** (`prepare_fp8_moe_layer_for_fi`): the weights keep their layout (W31 when
  gated, as on the other CUTLASS paths). The block scales are interleaved into the
  128x4 layout of `mxfp8_quantize(..., is_sf_swizzled_layout=True)`, with experts on
  dim 0 so EPLB can move them.
- **Activations:** quantized in the prepare step with swizzled scales
  (`is_scale_swizzled` for CUTLASS in `make_fp8_moe_quant_config`).
- **Why `is_mx_quantized`:** MXFP8 has `block_shape == [1, 32]`, so
  `is_block_quantized` is true. Two places used that to mean "DeepSeek block FP8":
  - `use_deepseek_fp8_block_scale` in the CUTLASS experts;
  - the rule in `make_fp8_moe_kernel` that has all-to-all carry BF16 activations,
    because CUTLASS block-FP8 quantizes inside the kernel.
