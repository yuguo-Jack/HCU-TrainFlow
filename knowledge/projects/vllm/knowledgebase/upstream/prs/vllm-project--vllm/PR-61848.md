# [ROCm][Distributed] Enable custom all-reduce on RDNA4 over PCIe peer-to-peer

[Upstream PR](https://github.com/vllm-project/vllm/pull/61848) · state: open · merged: False

## Original PR description



## Overview

Enable vLLM's existing custom all-reduce on AMD RDNA4 (gfx1200/gfx1201) GPUs connected by PCIe peer-to-peer, such as Radeon AI PRO R9700 workstations. Today every RDNA4 tensor-parallel group uses RCCL. Three commits:

1. **`[Kernel][ROCm]` page-align uncached IPC buffers.** This is a general ROCm fix: without it, custom all-reduce fails to initialize on some HIP runtimes.
2. **`[Kernel][Distributed]` optional release/acquire start barrier.** It makes the zero-copy path correct over non-coherent PCIe. It is off by default, so there is no behaviour change for existing platforms.
3. **`[ROCm][Distributed]` enable custom all-reduce on RDNA4** for TP=2, 4 and 8, with measured per-world-size size limits.

Related: #57059 (same stale-read root cause, on MI100), #57182, RFC #55916, #55917, #57767 (see "Relation to other PRs").

- Decode TPOT, `--disable-custom-all-reduce` vs this PR (median of 3 interleaved rounds, 512 input / 128 output tokens):

- Accuracy unchanged: GSM8K 5-shot is within noise for all three models.
- Correctness: with the existing relaxed start barrier, every all-reduce over PCIe reads stale data (500/500 wrong per size). With the release barrier, 0 are wrong at TP=2/4/8.
- No behaviour change on CUDA, MI300 or RDNA3:
  - the new barrier is a template flag that defaults to off;
  - RDNA4 enablement is gated on the architecture;
  - the IPC buffer fix only rounds up an allocation size.
- `--disable-custom-all-reduce` still turns it off.

## Details

**Motivation.** RDNA4 workstations have no XGMI; GPUs talk over PCIe peer-to-peer. `RocmPlatform.use_custom_allreduce()` is false outside MI300, and `CustomAllreduce` rejects more than two GPUs that are not 1-hop XGMI. So every decode all-reduce goes through RCCL's ring: two per layer, from a few KiB to a few hundred KiB, each needing 2*(N-1) dependent PCIe steps. The one-shot custom kernel needs a single barrier.

**Commit 1: page-align uncached IPC buffers (`csrc/custom_all_reduce.cu`).**
- On ROCm, `allocate_shared_buffer_and_handle` allocates every shared buffer with `hipDeviceMallocUncached` and exports it with `hipIpcGetMemHandle`.
- Some HIP runtimes reject that export with `hipErrorInvalidValue` when the size of an uncached allocation is not a multiple of 4 KiB. Cached allocations of the same size export fine.
- `CustomAllreduce` allocates `meta_size() + max_size`, and `meta_size()` is 4864 bytes, so custom all-reduce fails to initialize (`RuntimeError: CUDA error: invalid argument`).
- The fix rounds the size up to 4 KiB on ROCm. The allocation path is shared by all ROCm GPUs. This commit could also be split into its own PR if preferred.

**Commit 2: optional release/acquire start barrier (kernel; no behaviour change).**
- **Root cause:** the kernels open with `barrier_at_start`, which uses relaxed flags and by design orders nothing written before the kernel. Under graphs, peers read each rank's registered input in place, and that input was just written by the previous kernel (the o_proj/down_proj GEMM). Over coherent links this works. Over non-coherent PCIe, peers read stale data until the producer's L2 is written back: every result in the stress test was wrong, and model output was garbage.
- **The barrier:** `barrier_at_start_release` publishes the flag with a system-scope release store. `custom_collective_common.cuh` had it until #60721 pruned it as unused; this commit restores it. On gfx1201 it compiles to `global_wb scope:SCOPE_SYS` before the store and `global_inv scope:SCOPE_DEV` after the wait.
- **Plumbing:** a `start_release` template flag on `cross_device_reduce_1stage/2stage`, and `release_start` in `init_custom_ar` and `CustomAllreduce` (default `False`). Existing callers launch the same instantiations as before.

**Commit 3: RDNA4 enablement.**
- `RocmPlatform.use_custom_allreduce()`: also true on RDNA4.
- `RocmPlatform.is_fully_connected()`: on RDNA4, true when every pair has an amdsmi PCIe link and `amdsmi_is_P2P_accessible`. `CustomAllreduce` also runs the runtime P2P check (`_can_p2p`) on RDNA4, as on CUDA.
- `CustomAllreduce` on RDNA4 always uses `release_start=True`. It sends messages at or above `ROCM_RDNA4_PCIE_CUSTOM_ALL_REDUCE_MAX_SIZES[world_size]` (`{2: 8 MiB, 4: 192 KiB, 8: 128 KiB}`) to RCCL. World size 6 is not in the table and keeps RCCL.
- `QuickAllReduce` is now constructed on RDNA4, but disables itself (MI300 only).

**Design notes / trade-offs.**
- **Gated on the architecture, not on amdsmi's coherence flag,** because the barrier choice and the size limits are measured on RDNA4 only. Enabling the release barrier on all ROCm, as #57182 proposes, would be a one-line follow-up once its MI300 cost is measured. It composes with this PR.
- **A dispatch limit (`_dispatch_max_size`) rather than a lower `max_size`,** as CUDA's `CUSTOM_ALL_REDUCE_MAX_SIZES` does. `max_size` also sizes the IPC buffers and the batch-invariant chunks, which keep their defaults. Batch invariance keeps its semantics: custom all-reduce takes every size, in `max_size` chunks.
- **One limit per world size.** At TP=8 the 2-stage kernel (256 KiB to 1.5 MiB) is 5-11% faster than RCCL again. A single exclusive limit cannot include it without the 128-192 KiB 1-stage range, which is 5-13% slower. A possible follow-up is to lower the 1-stage → 2-stage switch for RDNA4 at 8 GPUs.
- **RDNA3 is not enabled;** it needs separate validation.
- **CI gap.** vLLM CI has no RDNA GPUs. `test_custom_all_reduce.py` runs in the (optional) A100, MI300 and MI355 Distributed jobs. There the new test exercises the `release_start=True` instantiations and checks that the platform default is unchanged. The RDNA4 path was validated on the hosts above.

**Relation to other PRs.**
- **#57182 / #57059:** same stale-read root cause, on MI100 XGMI. #57182 switches all of ROCm to the release barrier, and the end barrier to system-scope loads, unconditionally. It no longer builds on main because #60721 removed `barrier_at_start_release`, which this PR restores. This PR leaves other platforms unchanged and adds a reproducer test.
- **#55917 (FlyDSL) and #57767 (native HIP RDNA3/4):** new opt-in backends behind env vars. This PR adds no backend and no env var. It enables vLLM's existing custom all-reduce on RDNA4, by default, where it is measured to win.
