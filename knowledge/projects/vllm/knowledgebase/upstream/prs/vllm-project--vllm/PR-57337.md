# [Model] Enable sequence-parallel RMSNorm for Qwen3 MoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/57337) · state: open · merged: False

## Original PR description

## Purpose

Qwen3 MoE currently shards tokens only inside `Qwen3MoeSparseMoeBlock`, leaving the input and post-attention RMSNorm replicated across TP ranks. This change follows Qwen3-Next's model-level SP layout so that both RMSNorm operations and the residual stream stay sequence-sharded. For example, with 8192 tokens and TP8, each RMSNorm processes 1024 tokens per rank.

- Gather tokens after input RMSNorm and reduce-scatter the unreduced attention output before post-attention RMSNorm.
- Disable the attention output projection's internal all-reduce, and let MoE consume and return already-sharded states.
- Shard at model entry and restore full, unpadded outputs and EAGLE auxiliary hidden states at model exit.
- Enable this path only when the existing MoE SP conditions hold, PP=1, the model is text-only, and every decoder layer is an MoE layer. Other configurations retain their existing layout.

### Related work

Reviewed the open SP PRs and issue #29139 before submission. #51656 and #55832 primarily migrate Qwen3-Next/Qwen3.5 communication into generic linear layers; they do not implement this Qwen3Moe decoder path. #35209 and #54611 implement compiler-pass optimizations. This PR supplies Qwen3Moe's explicit model-level communication path, including eager execution, without introducing a compiler pass or changing global SP configuration. #53191 addresses PP support in other model paths; this change retains the PP=1 restriction.
