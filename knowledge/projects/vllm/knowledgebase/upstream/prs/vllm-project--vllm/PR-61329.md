# [CPU] Fix underflow in FP8 AMX attention

[Upstream PR](https://github.com/vllm-project/vllm/pull/61329) · state: closed · merged: True

## Original PR description



## Overview

Fix underflow in CPU FP8 AMX attention with BF16 exponent lifting and delayed scale compensation, plus cache writes that avoid tiny FP32 intermediates. Follow-up to #39445.

## Claims

- AMX decoding retains FTZ with **four instead of six** vector conversion instructions per 32 values.
- E4M3/E5M2 attention latency: **5.4% lower** than the original decoder across six workloads per format.

### Kernel validation and performance

- Full CPU build and pre-commit passed.
- Eight targeted attention regressions passed, covering encoded subnormals, split reduction, and large cache scales.
- 28 attention behavior checks passed, including split/unsplit, sliding window, softcap, ALiBi, sinks, and VEC.
- All 256 byte encodings of each format were checked against the selected conversion contract with FTZ/DAZ enabled and disabled.

Production assembly confirms four vector conversion instructions per 32 values for E4M3/E5M2 at head sizes 128 and 256.

Three balanced rounds; five repetitions of 20 timed calls per workload. Workload medians pool 15 repetitions; ratios are geometric means across six workloads per format.

| Attention comparison | E4M3 | E5M2 | Combined |
|---|---:|---:|---:|
| This PR / original underflow-prone decoder | 0.9525 | 0.9402 | 0.9463 |
| This PR / delayed scaling without FTZ | 1.0248 | 1.0019 | 1.0133 |

Combined ratios by round were 0.9570/0.9435/0.9415 versus original and 1.0222/1.0039/1.0043 versus delayed scaling without FTZ. BF16 controls were within 0.2% overall; the small latter gap is subject to timing variation. These are kernel timings, not end-to-end serving speedups.

## Details

The old decoder scaled BF16 values by `2^-120`/`2^-112`; AMX flushed small operands/products before the later scale correction could recover them.

Both AMX decoders lift normal values by `2^8`/`2^16`, compensated in K/V scales, and flush encoded FP8 subnormals to zero. NaN/Inf correction is omitted because the cache writer saturates inputs to finite FP8 codes.

Open-PR searches for CPU FP8 attention and AMX underflow found no overlapping fix.
