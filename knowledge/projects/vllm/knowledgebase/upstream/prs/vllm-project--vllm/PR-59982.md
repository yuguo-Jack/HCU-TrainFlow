# [XPU][Spec Decode] RecoverSSM: route Qwen GDN through the Triton/FLA core on XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/59982) · state: open · merged: False

## Original PR description

Follow-up to #58863, as suggested there. **Stacked on #58863; only the last commit is new.** Independent of #59983 (PP > 1); either can merge first. The hardware numbers below come from one setup with both changes.

## Purpose

Only when RecoverSSM is active, this routes XPU through `forward_cuda` (the Triton/FLA core, where the RecoverSSM verify lives) instead of `forward_xpu`. Without RecoverSSM nothing changes on XPU, and nothing changes on other platforms.

Why: on XPU, `QwenGatedDeltaNetAttention` fixes `_forward_method` to `forward_xpu`, which calls the native XPU GDN kernel. That kernel still keeps per-draft states in speculative blocks, so with `--use-replayssm` it never reaches the RecoverSSM verify and fails in `_xpu_ops` with `spec_state_indices_tensor must be contiguous`. (The pointer-table overflow that also blocked XPU is already fixed in #58863.)

## Test Result

2× Intel Arc Pro B70, Qwen3.8-Flash-Next MXFP4, PP=2, MTP K=1:

| | native XPU GDN, no RecoverSSM | Triton/FLA GDN, no RecoverSSM | RecoverSSM |
|---|---|---|---|
| KV tokens per GiB | 15,474 | 15,360 | 22,784 (+47%) |
| single-stream decode | 32.0 ms/tok | 33.5 ms/tok | 33.3 ms/tok |

MTP acceptance stayed within the window-to-window variation (about 1.7–1.8 in all three). Greedy outputs are not deterministic run to run on this setup even without RecoverSSM, so we compared per-token logprobs over the common prefix against the Triton/FLA run (32 prompts, 1 and 13 concurrent): within the run-to-run noise.

- **Tested on hardware**: the same change on our own tree, which carries other local XPU patches that Flash-Next needs to start on XPU (e.g. for the Engram platform gate).
- **Not tested**: this exact branch on hardware, and the current #58863 head together with this change (our runs used a uint64 variant of the pointer-table fix instead of the bit-pattern version in #58863).
- `ruff check` / `ruff format` pass. No unit test yet: the dispatch is chosen in `__init__` on the XPU platform. Happy to add one with a mocked platform if that's wanted.

AI assistance (Claude Code) was used; every changed line was reviewed by the submitter.
