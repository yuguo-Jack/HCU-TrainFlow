# [XPU][Spec Decode] RecoverSSM: route Qwen GDN through the Triton/FLA core on XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/59982) · state: open · merged: False

## Original PR description

Follow-up to #58863, as suggested there. **Stacked on #62625 (→ #61309 → #58863); only the last commit (`5e22665741`) is new.** Rebased on 2026-11-05 because #62625 moves the replay records out of the Mamba page. Independent of #59983 (PP > 1) and #61017 (grouped commit); any of them can merge first. The hardware numbers below come from one setup with all three.

## Purpose

When RecoverSSM is active on XPU, this sets `gdn_xpu_backend` to `"triton"`, so `forward_xpu` takes its Triton/FLA path, where the RecoverSSM verify lives. Without RecoverSSM nothing changes on XPU, and nothing changes on other platforms.

Why: since #56835, XPU resolves the GDN backend to `"sycl"` when the vllm-xpu-kernels GDN op is built (the default). The SYCL op is a fused whole-layer kernel that still keeps per-draft states in speculative blocks, so with `--use-replayssm` it never reaches the RecoverSSM verify and fails in `_xpu_ops` with `spec_state_indices_tensor must be contiguous`.

The earlier version of this PR switched `_forward_method` to `forward_cuda`. Rebased onto #56835, it now uses the backend switch that #56835 added instead, so the change is a few lines in the RecoverSSM block.

## Test Result

The rebase did not change this commit; the run below is from the earlier base (3694757f6) and was not re-run.

2× Intel Arc Pro B70, Qwen3.8-Flash-Next MXFP4, PP=2, MTP K=1, `--use-replayssm`. One server start for each version, on the current #58863 head (3694757f6) plus #59983 and #61017:

| | earlier version (`forward_cuda`) | this version (`gdn_xpu_backend="triton"`) |
|---|---|---|
| single-stream decode (3 rounds) | 29.5 / 29.7 / 30.0 ms/tok | 29.7 / 29.7 / 29.7 ms/tok |
| MTP acceptance | 1.762 | 1.764 |
| per-token logprobs vs. a Triton/FLA run without RecoverSSM (median abs. diff, 32 prompts, 1 and 13 concurrent) | 0.009–0.012 | 0.009–0.010 |

Greedy outputs are not deterministic run to run on this setup even without RecoverSSM, so we compare logprobs over the common prefix. Within one start, the second round differs from the first by about the same amount. The log shows the switch ("using the Triton GDN backend instead of SYCL") and the RecoverSSM commit on both PP ranks.

- **Tested on hardware**: this commit on our own tree, which carries other local XPU patches that Flash-Next needs to start on XPU (e.g. the Qwen4Exp platform gate and the QSA kernels), and #58815 for the PLE rows.
- **Not tested**: CUDA/ROCm (the change is behind the XPU backend check); more than one server start per version.
- `ruff check` / `ruff format` pass. No unit test yet: the backend is chosen in `__init__` on the XPU platform. Happy to add one with a mocked platform if that's wanted.

AI assistance (Claude Code) was used; every changed line was reviewed by the submitter.
