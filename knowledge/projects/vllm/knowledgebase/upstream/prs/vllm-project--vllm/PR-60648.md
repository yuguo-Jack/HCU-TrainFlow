# feat: Add Omni support to the Transformers backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/60648) · state: open · merged: False

## Original PR description

### What does this PR do?

cc: @hmellor

→ **This PR makes the Transformers modeling backend serve Omni models, with audio, image, and video supported in a single request.** I've tried to scope the work as much as I could, but there are a lot of edge cases, such as which audio a fused `use_audio_in_video` span should pair with, bidirectional encoders sitting inside multimodal configs, and one quantity carrying three different names across the Qwen family, that we need to handle to fully cover these models. Some of these challenges may also warrant a broader design discussion upstream around a more standardized upstream interface.
→ Blocked by https://github.com/huggingface/transformers/pull/49435 and https://github.com/huggingface/transformers/pull/49437

### Notes on each evaluated model family

Ultimately, I decided against pushing anything I couldn't evaluate locally, and evaluated all Omni-model families, on 1× NVIDIA L4 (22 GiB) where they could run at all; 6/10 can now be served on the Transformers backend, while 4/10 could not be, two of them because I found no usable checkpoint that's on the Hub and two because of backend gaps that are separate, out-of-scope work.

<summary> Essential Notes on Each Evaluated Model Family </summary><br>

[Qwen2.5-Omni-3B](https://huggingface.co/Qwen/Qwen2.5-Omni-3B) ✅
→ Audio, Video, Image
→ Logprobs match HF Transformers 🤗
[gemma-3n-E2B-it](https://huggingface.co/google/gemma-3n-E2B-it) ✅
→ Audio, Image (No video tower in the family)
→ Logprobs match HF Transformers 🤗
[gemma-4-E2B-it](https://huggingface.co/google/gemma-4-E2B-it) ✅
→ Audio, Video, Image
→ Logprobs match HF Transformers 🤗
[gemma-4-12B-it-qat-w4a16-ct](https://huggingface.co/google/gemma-4-12B-it-qat-w4a16-ct) ✅
→ Audio, Image
→ 90 of 90 exact greedy tokens against HF, but not verified in the test suite because vLLM runs the 9.56 GiB checkpoint natively as w4a16 while HF decompresses it to bf16 at load, about 24 GiB for 12B parameters, which exceeds the L4's 22 GiB, so the reference had to run on CPU 👀
[Qwen3-Omni-30B-A3B-Instruct](https://huggingface.co/Qwen/Qwen3-Omni-30B-A3B-Instruct) 👀 
→ Audio, Video, Image
→ GPU poor 💪 (parity not measurable on 22 GiB). Serves and passes the processing suite, but the bf16 checkpoint is 65.7 GiB, and the 19.06 GiB AWQ one gets to 21.86 GiB in use and OOMs 222 MiB short of 22.04. I found other smaller community variants that are either untrained or expert-pruned into gibberish
[embeddinggemma-2](https://huggingface.co/google/embeddinggemma-2) 👀
→ Audio, Image, Text
→ <ins>Separate backend work</ins>: `embeddinggemma-2` is a bidirectional encoder but the backend currently treats it as causal because it is multimodal; so its embeddings diverge from HF Transformers, cosine 0.844 to 0.906 and 0.9999 once the reference is forced causal.
[phi-4-audio](https://huggingface.co/JacobLinCool/phi-4-audio) ❌
→ None served
→ <ins>No usable checkpoint</ins>: Every real-weight one I found is the legacy remote-code format, and the only real-weight one on the native architecture has its whole vision tower removed. The converter exists upstream, but no converted checkpoint has been published.
[pe-av-small](https://huggingface.co/facebook/pe-av-small) ❌
→ None served
→ <ins>Separate backend work</ins>: It has no `get_input_embeddings` override, and its ModernBERT text tower hits the same attention issue as `embeddinggemma-2`.
[Nemotron-3-Nano-Omni-30B-A3B-Reasoning-NVFP4](https://huggingface.co/nvidia/Nemotron-3-Nano-Omni-30B-A3B-Reasoning-NVFP4) ❌
→ None served
→ <ins>No usable checkpoint</ins>:
→ Every checkpoint I found uses a different architecture from Transformers' own implementation, with different config and weight names. Only 1 of 7,349 weight names overlaps, and there is no converter to bridge the two.
[Inkling-0.6B-A0.6B](https://huggingface.co/inference-optimization/Inkling-0.6B-A0.6B) ❌
→ None served
→ <ins>Separate backend work</ins>: Its `mlp.w13_dn` weight needs `Interleave(dim=0)` then `Chunk(dim=0)` which the concatenating `orig_to_new_stacked` cannot express.
