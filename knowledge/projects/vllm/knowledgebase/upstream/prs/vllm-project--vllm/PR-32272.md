# [Quark] Support online block-diagonal rotations in dense GEMM layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/32272) · state: open · merged: False

## Original PR description

This PR adds support to load quantized models making use of online block-diagonal rotations in dense GEMM layers (OCP MX, FP8, INT8) and produced through AMD Quark library, based on the config.json's `quantization_config` indicating which layers are using online rotations.

See the notes: https://quark.docs.amd.com/latest/release_note.html#support-for-online-rotations-online-hadamard-transform

This is a naive non-optimized implementation.

We'll likely release models in the future. For the moment, we simply use in the CI:
- [`amd-quark/internal-testing-qwen3_0.6b-mxfp4-hadamard`](https://huggingface.co/amd-quark/internal-testing-qwen3_0.6b-mxfp4-hadamard), [`amd-quark/internal-testing-qwen3_0.6b-fp8-hadamard`](https://huggingface.co/amd-quark/internal-testing-qwen3_0.6b-fp8-hadamard), [`amd-quark/internal-testing-qwen3_0.6b-mxfp4-tuned-orthogonal`](https://huggingface.co/amd-quark/internal-testing-qwen3_0.6b-mxfp4-tuned-orthogonal), [`amd-quark/internal-testing-qwen3_0.6b-fp8-tuned-orthogonal`](amd-quark/internal-testing-qwen3_0.6b-fp8-tuned-orthogonal).

## Motivation

Online rotation (hadamard/orthogonal) has been shown to be a promising technique to recover from the accuracy drop seen in low-precision formats as MXFP4.

Using block-diagonal hadamard or orthogonal transforms is a popular strategy recently, as per e.g.
- https://arxiv.org/abs/2509.23202
- https://rocm.blogs.amd.com/software-tools-optimization/mxfp4-online-rotation/README.html

**High Severity**

<!-- DESCRIPTION START -->

The code uses `.get()` for safe access elsewhere in the codebase, and should use `quant_config.get("algo_config")` here so the `is not None` check can properly evaluate to `False` when the key is missing.
<!-- DESCRIPTION END -->
