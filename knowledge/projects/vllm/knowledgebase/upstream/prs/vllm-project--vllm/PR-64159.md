# [Bugfix][DP] Log cross-engine step statistics ordering at debug level

[Upstream PR](https://github.com/vllm-project/vllm/pull/64159) · state: open · merged: False

## Original PR description

## Overview

Log DP coordinator out-of-order step reports at DEBUG instead of WARNING. Reports from different engines can arrive in a different step order even when each engine reports in order.

## Claims

- Avoid per-report warning output for cross-engine statistics arrival skew at the default log level; retain the diagnostic at DEBUG.
- Preserve all statistics updates, step snapshots, and wave coordination.

## Validation

- Existing run evidence: a saved audit of a 32-rank DP deployment counted 1,751,591 occurrences, totaling 290,881,789 bytes. All reports had the same wave as the global latest report; 1,751,578 lagged by one step and 13 by two steps. This is evidence of logging volume, not a measured throughput improvement.
- `ruff check vllm/v1/engine/coordinator.py` — passed.
- `ruff format --check vllm/v1/engine/coordinator.py` — passed.
- `python -m py_compile vllm/v1/engine/coordinator.py` — passed, using the existing venv.
- `git diff --check` — passed.
- `pre-commit run --files vllm/v1/engine/coordinator.py docs/usage/troubleshooting.md` — all applicable checks passed, including mypy and Markdown lint.
- Tests and model evaluations were not run. The sole executable change is the diagnostic level; no inference or statistics-processing behavior changes. No new test was added solely to assert log severity. Runtime validation remains pending for this draft.

## Details

The comparison is against one global `(wave, step)` position. For example, engine A's step 101 may arrive before engine B's step 100, causing a warning even if B's previous report was step 99. The warning alone does not establish same-engine message regression or a failed request.

This is a logging-only alternative to #52936, which adds per-engine position tracking and rejects regressing reports. It does not add state or discard reports, and it does not claim to repair cross-engine snapshot consistency. The original snapshot/load-balancing design from #21617 remains intact. Open-PR searches found #52936 but no separate logging-only fix.

The troubleshooting guide documents the diagnostic and how to enable it with `VLLM_LOGGING_LEVEL=DEBUG`. The tradeoff is reduced default visibility of this ordering diagnostic, including any anomalous cases that reach the same branch.
