# [Bugfix][MXFP4] Fix MXFP4 CuTeDSL MoE-EP megakernel weight registration

[Upstream PR](https://github.com/vllm-project/vllm/pull/64563) · state: open · merged: False

## Original PR description



## Overview

Fix MXFP4 model startup with --moe-backend flashinfer_moe_ep_cutedsl. During post-load setup, the CuTeDSL path can leave the source scale attributes as None; megakernel setup then tries to assign .data on None.

On main, the startup failed at the old .data assignment with `AttributeError: 'NoneType' object has no attribute 'data'.`


## Claims

- Register missing megakernel weight parameters with the existing replace_parameter helper.
- Preserve direct .data rebinding for parameters that already exist, keeping all four model parameters aliased to the megakernel buffers without copying.
- Add a regression test for MXFP4 CuTeDSL routed-expert startup.
- The regression came from #62326. PR changed the rebinding code to assign through .data, assuming the scale parameters already existed. MXFP4 preparation can set those parameters to None, which caused the startup error.

## Details


`process_weights_after_loading` binds the adapter’s kernel weights back to the model layer. For MXFP4 CuTeDSL, the scale attributes can be None at this point, so assigning through .data raises an exception. The change registers only missing parameters with replace_parameter; existing parameters retain the current direct rebinding behavior.
