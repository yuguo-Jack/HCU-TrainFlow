# [Quantization] Keep deleted and renamed params registered after process_weights_after_loading

[Upstream PR](https://github.com/vllm-project/vllm/pull/62407) · state: closed · merged: True

## Original PR description

## Overview

Part 3 of 3 of keeping the loaded parameter objects through `process_weights_after_loading` (PWAL). After #62326 and #62405 (both merged), a loaded param can still disappear when PWAL deletes or renames it. This PR keeps those params registered, so after PWAL every loader-visible param is still registered under the same name, as the same object, and keeps its loaded data unless that would cost real memory.

## Claims

- **Renames alias one param under both names.** The new `move_parameter(layer, src, dst)` registers the `src` param object under `dst` as well and records `dst` as its runtime name. The loader writes through the checkpoint name and kernels read the runtime name, both pointing at one storage, so a later `replace_parameter` on either name updates both and no extra memory is used. This covers:
  - compressed-tensors `*_weight_packed` (linear, NVFP4/MXFP4/W4A8 MoE);
  - INC MXFP4;
  - the NVFP4 MoE oracle;
  - Humming NVFP4 and Humming's checkpoint-to-standard renames;
  - compressed-tensors W8A16 block FP8, which now aliases `weight_scale_inv` to `weight_scale`.
- **Loaded params no kernel reads keep their data and are marked retired** (`retire_parameter`). This covers:
  - consumed NVFP4 per-tensor scales (ModelOpt, Quark);
  - small Humming leftovers (at most 1/256 of the largest converted tensor);
  - the input scales of ModelOpt and Quark NVFP4 MoE when a weight-only backend (Marlin, Humming) is selected. These used to be set to `None`, which unregistered them. The method now leaves them registered and passes `None` to the MoE quant config.
- **Large released sources stay registered with empty storage** (`replace_parameter(layer, name, t.new_empty(0))`). Their data was converted into a different-layout kernel tensor, so keeping it would double that memory. This covers:
  - unused zero points, e.g. symmetric GPTQ `qzeros` (Conch, CPU, Marlin, Zentorch via `MPLinearKernel._release_unused_zp`; int8 scaled-mm; Quark int8 linear and MoE);
  - KV-cache scale placeholders (`kv_cache.py`, compressed-tensors KV);
  - released weights (XPU W4A8, wNa8o8, dynamic 4-bit, CPU int8, Triton MXFP4 MoE, INC ARK);
  - Humming leftovers larger than 1/256 of the largest converted tensor.
- **Not changed:** `dispatch_cpu_unquantized_gemm` keeps `main`'s fresh `Parameter(empty(0))` on release, since the released weight can be a tied lm_head shared with `embed_tokens`.
- **Readers see the kernel view.**
  - `kernel_parameters(layer)` returns the live params, each object once under its runtime name. `get_live_param` treats retired or empty params as absent. Humming uses both helpers.
  - The Triton MXFP4 MoE wrapper is stored as a plain `<name>_triton` attribute read via `triton_weight()`, so it no longer takes over the param name.
- **Coverage** (whole-tree enumeration of PWAL-reachable sites on `main`, 1786 rows split across the three PRs): 73 delete/rename sites fixed here, plus 36 sites converted together with them (Humming's delete-then-recreate pattern), plus 7 n/a rows inside the changed hunks.

## Details

- **Reload:** layerwise reload restores checkpoint-format params before loading. It goes through `layer._parameters`, so both alias names are restored, and a param kept empty is never handed to a `weight_loader`.
- **Humming:** used to delete every param and re-create the set it needs. It now writes through `replace_parameter`. Leftovers are skipped if they alias a replaced param, retired if small, and emptied if large.
- **Weight-only NVFP4 MoE input scales:** Humming's MoE quant config reads the input scales from the layer, so they are retired rather than left live. A live loaded scale would switch Humming to the static checkpoint scale, while `main` uses none.
- **Known limitation:** an aliased param appears under both names in `state_dict()`, so the UVA offloader and elastic-EP scale-up copy it twice (no data change).
- **Not kept (exceptions, listed in #62326):** the online FP8 requantization-source `weight_scale`, AutoGPTQ placeholder MoE biases, and torchao tensor subclasses.

## Update: loaded storage is never shrunk, emptied or split (0dcd74c070..682db58ae5)

A loader-visible param now keeps the checkpoint bytes it had at `create_weights` after PWAL. Its storage is never emptied. When two names refer to the same bytes, they are registered as one Parameter object. This supersedes the "kept with empty storage" item above for every site that has a plain tensor to back.

- **Shrink.** `replace_parameter` copies a smaller result into a prefix view of the param's own storage instead of rebinding it to a new, smaller allocation. Results of equal or larger size are still rebound. Online quantization (`uses_meta_device`) still frees its bf16 source. This covers:
  - ModelOpt/Quark NVFP4 MoE `w13_weight_scale_2` / `w13_input_scale` (`[E,2]` → `[E]`);
  - merged per-tensor scales (`[3]` → `[1]` or scalar: Humming NVFP4 `weight_scale_2`, CT NVFP4 `weight_global_scale` / `input_global_scale`, FP8 `input_scale.max()`);
  - the CUTLASS W4A8 FP8 scales and the CPU AWQ repack, which now go through `replace_parameter`.
- **Triton MXFP4 MoE.** The weights and scales are no longer emptied. Each param holds the swizzled storage, and its `triton_kernels` tensor points at it, so no second copy is kept.
- **Humming.** A converted tensor under a new name is registered as the leftover loaded param it came from (`move_parameter`). This applies when the tensor lives in that param's storage or replaces a large leftover; other leftovers are retired with their data.
  - This removes the second Parameter object that block-FP8 MoE `w13/w2_weight_scale` and NVFP4 `input_scale_2` had over `*_weight_scale_inv` / `input_global_scale`.
  - It also removes the emptied CT WNA16 `*_weight_packed`.
- **No more emptied loaded params.**
  - Unused zero points (Marlin, Conch, CPU, Zentorch), dynamic 4-bit scales and INC ARK qzeros/scales are retired with their data.
  - Zentorch, the DeepSeek-V4 CPU `wo_a` pack, CT W4A8 int8 MoE and CT WNA8O8 put the repacked tensor into the loaded param's storage. The K3 gfx942 MXFP4 repack no longer empties its source.
- **Not changed (reported):** sites whose kernel copy is opaque or split across several tensors still release the loaded weight. Keeping it would double weight memory:
  - CPU oneDNN int8 (`scaled_mm/cpu.py`) and `dispatch_cpu_unquantized_gemm`;
  - AMX MLA `kv_b_proj`;
  - the SM12x b12x linear/MoE/Q8_0 packs.

`_in_own_storage` only keeps the result in the loaded storage when it is strictly smaller:

```python
or new.numel() * size >= _extent(old) * old.element_size()
```

A result with the **same byte size but a different shape/dtype** therefore still gets rebound to fresh memory. That's fine for this PR's memory goal, but it means the param's address isn't stable across a reload that reruns PWAL, which is what a direct (in-place) reload relies on: re-viewing the param in checkpoint layout and rerunning PWAL lands the result at a new address each time, so captured CUDA graphs keep reading the old one.

FP8 weight-only Marlin repacks the loaded FP8 weight into an int32 tensor of exactly the same size:

```
N, K = 4096, 2048
fp8 weight bytes 8388608   marlin bytes 8388608   (128, 16384) torch.int32
kept in loaded storage: False
```

On a toy model whose PWAL does `replace_parameter(layer, "weight", layer.weight.t().contiguous())` on a `[3, 5]` weight, an update that reruns PWAL moves `weight` with `>=`, and keeps its address (with correct values) when equal size is allowed.

Suggested change: `>=` → `>`. An equal-size result fits exactly, and the copy only replaces a rebind that would otherwise allocate the same amount anyway.
