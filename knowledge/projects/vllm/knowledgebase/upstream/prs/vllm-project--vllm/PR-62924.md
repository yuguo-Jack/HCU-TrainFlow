# [Bugfix][Compile] Preserve eager layouts for untagged custom ops

[Upstream PR](https://github.com/vllm-project/vllm/pull/62924) · state: open · merged: False

## Original PR description

## Overview

Fix corrupted generation when Inductor mode 2 compiles Transformers attention and KV-cache updates by preserving eager input strides for custom operators without a layout tag. Fixes #62865.

## Claims

- Default `direct_register_custom_op` to `torch.Tag.needs_exact_strides` only when no layout tag is supplied.
- Preserve explicit exact-stride, fixed-stride-order, and flexible-layout choices, including unrelated tags such as `cudagraph_unsafe`.
- Retain the fallback allow-list optimization and document the input-layout contract.

## Details

The fallback allow-list added in #42129 routes custom operators through a path that omits PyTorch's implicit exact-stride constraint. After Transformers RoPE, Inductor can pass head-major keys to `unified_kv_cache_update`; `reshape_and_cache_flash` reads the token stride and assumes packed heads. This implements the layout-tag approach (option 3) identified in #62865: an explicit default layout tag restores that input contract without removing the allow-list.

The implementation adds ten registration-time lines and no inference-time synchronization. Enforcing the layout can introduce materialization/copies that the unconstrained path omitted. Operators with an explicit layout tag keep their existing behavior. Other GPU architectures and the full model suite have not been validated locally.

Duplicate-work checks on 2026-10-21 found no PR referencing #62865 and no issue comments. #61749 changes explicit MoE layout tags, which this fix preserves; #57310 changes when the allow-list patch is imported, which this fix does not edit. The default-branch registration code still lacked the fix when rechecked immediately before submission.

AI assistance (OpenAI Codex) was used to investigate, implement, and validate this change.
