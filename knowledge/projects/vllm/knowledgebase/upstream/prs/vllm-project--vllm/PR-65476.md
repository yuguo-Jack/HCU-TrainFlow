# [CI] Run PyTorch Compilation root files as plain pytest and shard them automatically

[Upstream PR](https://github.com/vllm-project/vllm/pull/65476) · state: open · merged: False

## Original PR description

## Overview

Runs each PyTorch Compilation root test file (`tests/compile/test_*.py`) in its own plain `pytest` command instead of the `find | xargs` loop, and enrolls the step and its MI300 mirror in `automatic_shard`. The `find | xargs` pipe isn't plain pytest, so an enrollment flag alone would be ignored.

## Claims

- The same 13 root files run, each in its own process, as today. Subdirectories still run in their own steps.
- The step's commands are now plain pytest, so the planner can size it. Both the step and its mirror plan one job today and split by themselves once their tests grow.

## Validation

- A first version ran all root files in one pytest. Build 99664 failed 12 tests in `test_config.py` with `Cannot re-initialize CUDA in forked subprocess`: those tests use `@pytest.mark.forked`, and an earlier file had already initialized CUDA in the shared process. One process per file avoids this, as the old loop did.
- The sharding harness and the generator's own enrollment gate accept the step and its mirror.
- `split_check.py` finds no step whose jobs each run the whole suite.
- `/ci run` build 99690 on this head passed. H200: 2 shards, slowest 12 minutes, 172 passed and 2 skipped across the 13 commands, the same totals as main's single command in build 99608; machine time about 10% over main. MI300: one job, 170 passed and 4 skipped, as on main.

## Details

- **New root files** need a line in the YAML; the comment above the commands says so.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job.
