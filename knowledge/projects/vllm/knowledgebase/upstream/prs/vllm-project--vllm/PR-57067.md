# [CI] Split (H200 MIG 35GB / MI355 DPX) Multimodal Models (Standard) 4 into ViT CUDAGraph, Audio and Pooling + Other jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/57067) · state: closed · merged: False

## Original PR description

## What

Split `(H200 MIG 35GB) Multimodal Models (Standard) 4: other + whisper` and its MI355 DPX mirror into three named jobs: ViT CUDAGraph (3 hash shards), Audio, and Pooling + Other. Tests keep `main`'s `-m core_model` selection. No test file is split or rewritten.

## Old

```text
one job, key multi-modal-models-standard-4-other-whisper:
  pytest models/multimodal -m core_model --ignore <files owned elsewhere> --ignore test_whisper.py --ignore test_vit_cudagraph.py ...
  pytest test_vit_cudagraph.py -m core_model
  pytest test_memory_leak.py -m core_model
  spawn: pytest test_whisper.py -m core_model
```

## New

| Job | Key | Replicas | Commands |
| --- | --- | --- | --- |
| `Standard 4: ViT CUDAGraph Shard %N` | `multi-modal-models-standard-4-vit-cudagraph` | 3 | `pytest generation/vision -m core_model --num-shards --shard-id` |
| `Standard 4: Audio` | `multi-modal-models-standard-4-audio` | 1 | spawn from the repo root: `pytest generation/audio -m core_model` (whisper, moss_audio, gemma_ragged_audio) |
| `Standard 4: Pooling + Other` | `multi-modal-models-standard-4-pooling-other` | 1 | main's `pytest models/multimodal -m core_model --ignore …`, with the whisper/ViT file ignores widened to `generation/audio` and `generation/vision`; `pytest standard/memory_leak -m core_model` |

```text
standard/
├── memory_leak/test_memory_leak.py   # moved into a folder; still its own process
├── pooling/
├── test_interleaved.py
└── test_mapping.py
```

Old key `…-other-whisper` → `-vit-cudagraph` + `-audio` + `-pooling-other`. Each job shares the original trigger paths through one anchor and has its own `mirror.amd` block. The MI355 DPX legacy copy in `test-amd.yaml` follows the same split.

## Notes

- **Every command targets a directory, and nothing can fall through.** The Pooling + Other job keeps `main`'s discovery command, so any new `core_model` test anywhere under `models/multimodal` runs there unless another job owns its folder. A static check comparing this job set with `main`'s Standard 4 finds the same files, the same marker, and each file claimed once.
- **The encoder-only test needs no special job anymore.** `test_vit_cudagraph.py` is `main`'s single parametrized file again, and pytest-shard keeps collection order within a shard. So `test_eonly_vit_cudagraph_outputs`, which monkeypatches the V2 runner and leaves state that crashes later ViT cases in the same process, still runs last in whichever shard draws it, exactly as on `main`.
- Whisper keeps spawn mode, and `moss_audio` and `gemma_ragged_audio` now share that spawn process. Voxtral's core cases stay in `omni/` and run in the Pooling + Other job.
- Stack: contains #57065 and #56901, which should land first. After that the diff here is the last commit, "Split Standard 4 into…". #57066 was dropped. AI assistance was used.

## Validation — build 89748 failed, cause found and fixed

[Build 89748](https://buildkite.com/vllm/ci/builds/89748) on `971da626` (the two-job design). Reporting it because it changed the design, not just the numbers.

**Passing lanes.** Every other scoped key passed: Extended Generation 1 (3/3), Distributed 2-GPU (3/3), CPU Multimodal (4/4), Arm CPU (3/3), and on the accelerator mirror every ViT replica plus `other + whisper`. [amd-ci 13179](https://buildkite.com/vllm/amd-ci/builds/13179) rendered and ran the legacy `test-amd.yaml` copies: the one-line `case` replacement is gone, three ViT replicas plus `other + whisper` ran per copy, all passed on the primary accelerator and the second is gated as usual.

**The failure.** One ViT replica died after a retry with two `Fatal Python error: Segmentation fault` crashes, in CPU tensor allocation on two unrelated paths — gemma4 in the transformers image rescale, internvl in torchvision `to_tensor`.

The cause is ordering, and it was introduced by this PR. `test_eonly_vit_cudagraph_outputs` monkeypatches `VLLM_USE_V2_MODEL_RUNNER` and `VLLM_ALLOW_INSECURE_SERIALIZATION` and builds an encoder-only runner. On `main` it is the last test in `test_vit_cudagraph.py`, so nothing ever runs after it. Extracting it to its own file inside the hash-sharded directory put it at an arbitrary position — second of thirteen in that replica — and the next two cases sharing its pytest process both segfaulted:

```
deepseek_ocr -> test_eonly_outputs[qwen3_vl] -> gemma4 SEGFAULT -> idefics3 -> internvl SEGFAULT -> ...
```

Standard 4 has passed with exit 0 and no retries on the last ten completed `main` builds, so this is not a pre-existing flake.

**The fix** (`fcfbb18`): move it to `standard/test_vit_cudagraph_eonly.py`, outside the hash-sharded directory, and claim it with its own named job so it always gets a fresh pytest process. Standard 4 is now three named jobs per lane. A module docstring records why it must not be folded back in.

**Also measured, and not yet explained.** `other + whisper` ran 16.0m of pytest against a 11.9m prediction taken from build 89163's equivalent replica, on the identical 14 passing cases (the three processes were 10.0m / 1.5m / 4.6m). Wall was 17.9m, inside the 20m target but with less margin than predicted. I am recording this as unattributed rather than calling it variance; the revalidation gives a second data point, and if it holds the job can split along the existing seam.

Overheads were uniformly low, 0.9–1.9m per replica, attributable to checkout and image pull, with negligible queue delay — the split is not paying a setup tax.

Revalidation of all three Standard 4 keys and their mirrors, plus a fresh `amd-ci` build, is pending on `fcfbb18`. Aggregate worker-minute and budget verdicts follow with it; the numbers above are deliberately untagged by lane.
