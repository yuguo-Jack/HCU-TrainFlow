# [Perf][Attention] DiffKV: split the 192-wide QK dot instead of padding it to 256

[Upstream PR](https://github.com/vllm-project/vllm/pull/59673) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`TRITON_ATTN_DIFFKV` pads the Q/K head dimension to the next power of two, so MiMo-V2's 192-wide heads become 256
and a quarter of every Q/K tile load and Q·Kᵀ MMA is padding. In the 2D kernel (prefill and mixed batches), this
PR computes Q·Kᵀ as a 128-wide plus a 64-wide dot accumulated into one fp32 tile instead.

It touches the same file as #58177 (prefill BLOCK_M), #59085 (spec-verify split-KV) and #58128 (FP8 KV), and is
orthogonal to all three.

**Not a duplicate:** no open PR changes the Q/K padding. I searched open PRs for `diffkv` and
`triton_unified_attention_diffkv`. The open PRs on this file are #58177 (prefill BLOCK_M), #59085 (spec-verify
split-KV) and #58128 (FP8 KV), and all three are orthogonal to this change.

AI assistance: Claude (Anthropic) helped write this change, run the measurements and tests below on our GB10s, and draft this description. I reviewed the full diff before submitting.

## Claims

- **Prefill attention on GB10 (SM121):** 1.24-1.26x for MiMo-V2.6-Flash's full-attention layers at TP4, and 1.08x
  for its sliding-window layers.
- **Outputs:** bit-identical to main on every measured shape (max |diff| = 0).
- **Split-KV (3D) decode:** unchanged; the split is not used there.
- **One cost:** a single-sequence spec verify on the 2D path runs at 0.97x (with 4 sequences, 1.02x).

```python
# stable_timer.py
"""Clock-stable A/B timing for short GPU kernels: warm the GPU, then interleave the arms; every measurement runs
>= MIN_S of back-to-back calls (CUDA events). Returns per-arm medians and min/max over ROUNDS."""
import statistics, time
import torch

MIN_S, ROUNDS = 0.2, 5


def _burn(seconds=1.0):
    x = torch.randn(4096, 4096, device="cuda", dtype=torch.bfloat16)
    t0 = time.time()
    while time.time() - t0 < seconds:
        for _ in range(20):
            x = (x @ x).clamp_(-1, 1)
        torch.cuda.synchronize()


def _measure(fn, iters):
    e0, e1 = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
    e0.record()
    for _ in range(iters):
        fn()
    e1.record(); e1.synchronize()
    return e0.elapsed_time(e1) * 1e3 / iters  # us per call


def ab(arms):
    """arms: {name: fn}. Returns {name: (median_us, min_us, max_us)}."""
    for fn in arms.values():
        fn(); fn()
    torch.cuda.synchronize()
    probe = {n: _measure(f, 3) for n, f in arms.items()}
    iters = {n: max(3, int(MIN_S * 1e6 / max(t, 1.0))) for n, t in probe.items()}
    _burn()
    res = {n: [] for n in arms}
    for _ in range(ROUNDS):
        for n, f in arms.items():
            res[n].append(_measure(f, iters[n]))
    return {n: (statistics.median(v), min(v), max(v)) for n, v in res.items()}
```

```python
# qksplit_stable.py
"""vLLM main's TRITON_ATTN_DIFFKV vs main + QK split through the real launcher (stock tiles), clock-stable A/B."""
import importlib.util, json
import torch
from attn_bench import make
from stable_timer import ab


def load(name, path):
    spec = importlib.util.spec_from_file_location(name, path)
    m = importlib.util.module_from_spec(spec); spec.loader.exec_module(m); return m


main, split = load("diffkv_main", "/w/diffkv_main.py"), load("diffkv_split", "/w/diffkv_split.py")


def caller(mod, s, b, maxq):
    so, sm, se = b
    def fn():
        mod.unified_attention_diffkv(
            q=s["q"], k=s["k"], v=s["v"], out=s["out"], cu_seqlens_q=s["cu"], seqused_k=s["seqused"],
            softmax_scale=192 ** -0.5, causal=True, window_size=(s["window"] - 1, 0) if s["window"] else (-1, -1),
            block_table=s["bt"], softcap=0.0, max_seqlen_q=maxq, alibi_slopes=None, sinks=s["sinks"],
            seq_threshold_3D=128 // s["nkv"], num_par_softmax_segments=16,
            softmax_segm_output=so, softmax_segm_max=sm, softmax_segm_expsum=se)
    return fn


shapes = [("ga", 16384, 16384, 1), ("ga", 16384, 65536, 1), ("ga", 3072, 100000, 1), ("swa", 16384, 65536, 1),
          ("ga", 4, 100000, 1), ("ga", 4, 100000, 4), ("ga", 1, 100000, 1), ("ga", 1, 50000, 16), ("swa", 1, 100000, 8)]
for kind, qlen, slen, nseq in shapes:
    s = make(kind, qlen, slen, nseq)
    rows = (128 // s["nkv"]) * 4
    b = (torch.empty(rows, s["nq"], 16, 128, device="cuda", dtype=torch.float32),
         torch.empty(rows, s["nq"], 16, device="cuda", dtype=torch.float32),
         torch.empty(rows, s["nq"], 16, device="cuda", dtype=torch.float32))
    fm, fs = caller(main, s, b, qlen), caller(split, s, b, qlen)
    fm(); torch.cuda.synchronize(); ref = s["out"].clone()
    s["out"].zero_(); fs(); torch.cuda.synchronize()
    err = (s["out"].float() - ref.float()).abs().max().item()
    r = ab({"main": fm, "split": fs})
    print(json.dumps({"shape": f"{kind}:{qlen}:{slen}:{nseq}", "main_us": [round(x, 1) for x in r["main"]],
                      "split_us": [round(x, 1) for x in r["split"]], "speedup": round(r["main"][0] / r["split"][0], 3),
                      "max_abs_diff": err}), flush=True)
    del s, b; torch.cuda.empty_cache()
```

**End to end.** Our 4x GB10 deployment of MiMo-V2.6-Flash runs this split together with wider prefill tiles (the
#58177 direction). Cold 250K-token prefill went from 211 s to 104 s with both. The split alone was not measured end
to end on main.

**Accuracy:** outputs are bit-identical to main on every measured shape, and the unit grid passes against the
PyTorch reference. In our deployment (this split plus wider tiles), corpus NLL stayed within 0.001 of stock, and
long-context retrieval needles up to ~1M tokens were exact.

## Details

- **Split sizes:** `QK_SPLIT_A` / `QK_SPLIT_B` are constexprs. A is the largest power of two not above
  `head_size_qk`; B is `next_power_of_2` of the remainder, masked when the remainder is not itself a power of two.
  Power-of-two head sizes compile exactly as before.
- **2D only:** with the split also in the 3D (split-KV) kernel, decode measured 0.95-1.12x depending on the batch
  (1.12x for one sequence, 0.95x for 16 sequences, 0.97x for sliding-window decode). This PR keeps 3D on one dot;
  it can be revisited with #59085's 3D verify.
- **Shared memory:** removing the padding shrinks the Q/K tiles by 25 %. On SM121 (~99 KB per block) that lets wider
  prefill tiles fit, which is relevant to #58177's BLOCK_M discussion.
