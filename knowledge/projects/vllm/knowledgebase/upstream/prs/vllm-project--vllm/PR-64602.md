# [CI] Remove the retired A100 queue's steps; keep their live AMD mirrors standalone

[Upstream PR](https://github.com/vllm-project/vllm/pull/64602) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Remove every remaining `device: a100` declaration — the fleet is retired and the generator never emits those steps, but they still render on ci.vllm.ai/sharding as never-run jobs that count against automatic-shard enrollment. The two steps with live AMD mirrors keep those mirrors as standalone AMD steps. Supersedes #60596, which went stale and now conflicts with main.

## Claims

- Removes the `(A100) LM Eval Humming Default/Act INT8 TEMPORARY` steps, the `(A100) Batch Invariance` and `(A100) Distributed` declarations, the commented-out 4xA100 block in `lm_eval.yaml`, and the five `humming/config-a100-*.txt` shard lists only the Humming steps referenced.
- The two live AMD mirrors keep running as standalone steps, under the same emitted keys, labels, queues, commands and timeouts: `amd-distributed-tests-4xa100` (:amd: (MI355) Distributed) and `amd-batch-invariance-a100` (:amd: (MI250) Batch Invariance).
- Under a diff touching the three changed test-area files, the generated pipeline is unchanged job-for-job except one benign prefix (Details): no job is added, removed or altered. Selection under a `docker/Dockerfile.rocm_base` diff was validated separately (Details, behavior change 2).
- Difference from #60596, why this is not a plain duplicate: it predates the now-live `:amd: (MI250) Batch Invariance` mirror on `batch-invariance-a100`, so merging it as-is would delete a running job; this PR preserves both mirrors as standalone steps instead (its own description names this as the needed follow-up).

## Validation

- Generated the full Buildkite pipeline with ci-infra's pipeline generator (ci-infra@9d2935b5) for `main`'s YAML and for this change, per-key diffed, under three triggering diffs: (a) a touch of the three changed test-area files — every job identical except the prefix below; (b) `VLLM_CI_ONLY_STEP_KEYS=["amd-..."]` to force each converted job to emit — same result; (c) a `docker/Dockerfile.rocm_base` touch — `amd-batch-invariance-a100` still runs in both layouts, `amd-distributed-tests-4xa100` moves to the deferred list (behavior change 2).
- Repro: run `pipeline-generator --pipeline_config_path .buildkite/ci_config.yaml` from a checkout at this PR's head and at `main`, with `get_ecr_cache_registry` stubbed, and diff per-key.
- `tools/pre_commit/check_buildkite_step_keys.py` and `tools/pre_commit/check_test_tethering.py` pass; no test loses its CI job.
- Repo-wide grep: no remaining reference to any deleted `config-a100-*.txt`.
- No GPU run locally; a `/ci run` plus a scoped build of the two `amd-` keys exercises the converted steps for real. Recorder builds were code-read only: `_kernrec_applies`/`_fnrec_applies` see the same outcome because `KERNREC_SKIP_STEPS` names neither key.

## Details

- The converted steps keep their `amd-`-prefixed keys rather than getting fresh ones: it preserves job identity for retries, scoped builds and dashboard history, and native AMD steps with `amd-` keys already exist (e.g. `amd-kernels-mi355`).
- Each standalone step carries the fields its mirror inherited from the base step explicitly: `optional: true` and `num_devices: 4` (Distributed), and the base's commands for Batch Invariance, whose mirror had none of its own. `source_file_dependencies` are the union the generator applied to the mirror (base + mirror lists).
- Behavior change 1 (commands): the native AMD path prepends `export VLLM_TEST_GROUP_NAME=<key>` to the command string; the mirror path didn't. Harmless: nothing on main reads that variable.
- Behavior change 2 (selection): mirrors auto-run on PRs that change `docker/Dockerfile.rocm_base` even when optional (`_amd_mirror_should_run`); native steps use plain dependency matching. For the (MI250) Batch Invariance step this PR restores the old behavior by adding `docker/Dockerfile.rocm_base` to its `source_file_dependencies`, matching the other native AMD steps (`misc.yaml`). For the optional (MI355) Distributed step it is accepted instead of emulated — `optional: true` short-circuits file-dependency selection, so such PRs get it at the nightly or via manual unblock, same as every other native optional AMD step.
- Reviewer call (carried over from #60596): `humming/Qwen3-4B-mixed-quant-RTN-humming.yaml` is kept although only the deleted A100 shard lists referenced it, in case it should move to an H100 list.
- Out of scope: the commented-out, already-disabled NixlConnector A100 block in `disaggregated.yaml` (never parsed), and ci-infra's now-unused A100 queue constants.
