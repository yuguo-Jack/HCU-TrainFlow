# [Bugfix][Model] Borrow Gemma4 _get_max_soft_tokens in EmbeddingGemma2 and DiffusionGemma

[Upstream PR](https://github.com/vllm-project/vllm/pull/63538) · state: closed · merged: True

## Original PR description

- `embedding_gemma2.py`, `diffusion_gemma.py`: copy Gemma4's `_get_max_soft_tokens` alongside the `_process_image_input` they already borrow

#60687 moved the `max_soft_tokens` lookup into a new `Gemma4ForConditionalGeneration._get_max_soft_tokens` helper that `_process_image_input` now calls. `EmbeddingGemma2Model` and `DiffusionGemmaForConditionalGeneration` copy `_process_image_input` as a class attribute but not the helper, so `test_embedding_gemma2.py::test_encoder_contract` has failed since it merged, on AMD and NVIDIA ([build 97017](https://buildkite.com/vllm/ci/builds/97017/list?jid=01a16cae-f374-4a87-b95b-517c63fda082&tab=output)). The call only runs with tower-connector LoRA enabled, which neither model supports yet, so today it is a latent `AttributeError` that #60632 would turn into a real one. DiffusionGemma has the same gap but no contract test.

`test_encoder_contract` fails on main and passes 10/10 with this change; reverting only #60687's `gemma4_mm.py` hunk on main also makes it pass.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
