# [CI][LoRA] Release punica test GPU memory before later engine tests

[Upstream PR](https://github.com/vllm-project/vllm/pull/62672) · state: closed · merged: True

## Original PR description

## Purpose

Fix `:nvidia: (H200 MIG 35GB) LoRA Shard 1/2` on main. It failed deterministically on builds 96078, 96080 and 96081, on three different hosts:

```
ValueError: Free memory on device cuda:0 (21.55/32.5 GiB) on startup is less than desired GPU memory utilization (0.85, 27.62 GiB).
FAILED lora/test_qwenvl.py::test_qwen2vl_lora - RuntimeError: Engine core initialization failed.
```

**Root cause:** `tests/lora/test_punica_ops.py` overrides the autouse `cleanup_fixture` with a no-op (#47534) to keep its ~4400 kernel tests fast. So `cleanup_dist_env_and_memory()` never runs, and the pytest process keeps about 11 GiB of cached GPU memory after the module finishes. Engines started earlier in the same job saw ~31.9 GiB free; after the punica tests, `test_qwenvl` sees 21.5 GiB.

This was harmless until LoRA moved to runtime auto-sharding (#62084). The planner then went from 3 shards to 2 and put `test_punica_ops.py` and `test_qwenvl.py` in the same shard; files run alphabetically, so punica always comes first:
- 96065 (passed): `shard 1/3 runs 97 tests in 8 files`, no punica.
- 96078 (failed): `shard 1/2 runs 4522 tests in 9 files`, with punica before qwenvl.

No code in `vllm/lora`, `tests/lora` or `.buildkite` changed between the passing and failing builds.

**Fix:** keep the per-test override, but add a module-scoped autouse fixture that calls `cleanup_dist_env_and_memory()` once after the module. The punica tests keep their speedup, and later engine tests in the same process get the memory back.

**Not a duplicate:** no open PR touches `test_punica_ops.py` or this failure.

## Test Plan

Not run locally (no GPU here). The LoRA steps' CI will confirm.
