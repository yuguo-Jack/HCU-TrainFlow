# [ROCm][CI] Fix ViT backend and custom all-reduce tests with AITER on

[Upstream PR](https://github.com/vllm-project/vllm/pull/62524) · state: open · merged: False

## Original PR description

## Overview
Two tests assume `VLLM_ROCM_USE_AITER` is off and fail once AITER is on by default ([#48890](https://github.com/vllm-project/vllm/pull/48890), [#62092](https://github.com/vllm-project/vllm/pull/62092); seen in AMD CI build [13642](https://buildkite.com/vllm/amd-ci/builds/13642)). This makes them pass with AITER on or off. Test-only change.
## Claims
- `test_mha_attn_platform[hip]`: with AITER MHA enabled, ROCm correctly picks `ROCM_AITER_FA` for ViT attention, but the test hard-coded `FLASH_ATTN`. It now patches `rocm_aiter_ops.is_mha_enabled` and checks both outcomes.
- `test_custom_all_reduce.py`: with AITER on, AITER's `CustomAllreduce` replaces vLLM's, so `ca_comm` is `None` and the eager and chunked tests crash. The Ray workers now set `VLLM_ROCM_USE_AITER_CUSTOM_AR=0` so vLLM's `CustomAllreduce` stays under test. AITER's version keeps its own coverage in `test_rocm_aiter_custom_ar.py`.
## Validation
MI300X (gfx942), `main` at `8055293353`:
```bash
cd tests
VLLM_ROCM_USE_AITER=1 pytest -v kernels/attention/test_mha_attn.py::test_mha_attn_platform distributed/test_custom_all_reduce.py
VLLM_ROCM_USE_AITER=0 pytest -v kernels/attention/test_mha_attn.py::test_mha_attn_platform distributed/test_custom_all_reduce.py
```
| Test | AITER on, before | AITER on, after | AITER off, after |
|---|---|---|---|
| `test_mha_attn_platform[hip]` | failed | passed | passed |
| `test_custom_allreduce` (2 eager) and `test_custom_allreduce_chunked` (2) | failed | passed | passed |
Each command: 58 passed, 1 skipped (SM100-only).
## Details
- Not a duplicate: no open PR touches these two tests. #62092 already fixes `test_fusion_pass_op_priority` and `test_auto_selection_for_kv_connector`, so they're left out here. #62092 also keeps AMD CI on AITER off, which means these two tests still fail in any run with AITER on: local runs once the default flips, and CI once it moves to AITER on.
- Not validated on MI355; neither fix depends on the GPU.
- Out of scope: with AITER on and AITER `v0.1.24.post1`, `test_mha_attn_varlen_forward[cuda-dtype1-64-1-1-var_seq_len1]` fails on MI300 (bf16 tolerance; AITER's CK-tile kernel truncates to bf16). Not addressed here.
- AI assistance (Cursor agent) was used to investigate the failures and write the change.
