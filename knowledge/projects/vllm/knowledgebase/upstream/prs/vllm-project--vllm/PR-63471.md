# [Bugfix][GLM] Preserve kpool history at unaligned prefill boundaries

## Overview

Fix GLM-5.3-Flash kpool indexer cache writes when a prefill chunk starts inside a pool. Recover missing members from the request's existing tail before reseeding it. Fixes #63168.

## Claims

- Write complete pools at all chunk-start residues, including chunks shorter than a pool and a request following another prefill in the batch.
- Preserve the existing compression, Hadamard/FP8 quantization, cache layout, scheduler and decode writers.
- Share the strided gather between CUDA/ROCm and register compile-only startup warmup; metadata offset views do not add a new runtime-JIT variant.

## Details

Previously, pool members were gathered from preceding rows of the current batch and its leading rows were masked. At an unaligned start, some members belong to the preceding chunk. Depending on batch placement, the completed pool was skipped or used another request's rows.

The shared gather accepts a batch member only if both absolute position and tail-block ownership agree; otherwise it reads that request's ring slot. It uses real tail capacity/strides, masks invalid slots, and runs before the existing tail seed. Calls without tail metadata retain the aligned fallback. No host tensor reads or data-dependent synchronization are added to this path. Startup warmup uses the existing compile-only dispatcher and bound cache metadata; it allocates no real warmup tensors. Scalar metadata pointers are not alignment-specialized; data pointers retain specialization.

The kernel regression covers all four start residues, chunks of 1/3/12, first/later request placement and 4-slot/16-slot padded tails through real metadata/context and production indexers. The public LLM test observes the real production writer through hooks and independent pool assembly; it does not replace model methods or metadata. The JIT-monitor test is process-isolated.

**Native ROCm numerical/graph execution remains pending AMD CI.** Offline compilation of the actual gather succeeds for 16 combinations of gfx942/gfx950, ring 4/16, BF16/FP32 scores and feature stride 1/2; this is explicitly not runtime evidence. Existing B200/MI355 native-kernel and GLM model jobs select the affected tests.
