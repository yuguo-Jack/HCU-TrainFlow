# [Bugfix][DSv4.1] Mask replay-graph padding rows out of expert routing

[Upstream PR](https://github.com/vllm-project/vllm/pull/64443) · state: closed · merged: False

## Original PR description



## Overview

DeepSeek-V4.1's decoder-side SWA bounded replay pads its sub-batch to the replay CUDA graph size (the largest DP rank's under DP), but the replay forward context passes `is_padding` only under PCP. The padding rows go through expert routing; with garbage hidden states they all pick expert 0 (top-k `[0, 0, 0, 0, 0, 0]`). This PR marks them as padding so the routers and MegaMoE skip them, as they already do for the outer batch.

## Claims

- Replay-graph padding rows no longer reach MoE experts (DP, no PCP).
- No change to eager replay batches (no padding) or to PCP.

## Validation

DeepSeek-V4.1-Flash, 2P1D on 16x B200: prefill 2x DEP4 (MegaMoE, EPLB 16 redundant), decode DEP8, AgentX trace at 2048 sessions.

Top-k ids captured inside the CUDA graphs on the prefill ranks (20 snapshots per rank): in the 20 replay layers the batch is padded to 384-1536 rows, and the tail rows are all routed to expert 0. One snapshot: 4 ranks with 1024/640/384/896 real rows of 1536, so 3,200 padding rows x 6 = 19,200 pairs on expert 0, more than all real pairs of the layer.

MegaMoE replay of those snapshots (EP4, real per-rank top-k, mean over snapshots, per replay layer):

| Placement | Padding routed (main) | Padding masked (this PR) |
|---|---|---|
| No EPLB | 573-643 us | 330-366 us (-40..-47%) |
| EPLB 16 redundant, fit on the observed load | 406-421 us | 322-345 us (-18..-21%) |

End to end, same-run A/B (prefill instance 1 with the fix, instance 2 without, EPLB on): prefill step period 175.4 vs 176.6 ms (-0.7%), within run-to-run noise (+-1%). EPLB had been replicating expert 0 to absorb the padding; without EPLB the saving is about 2% of a prefill step.

## Details

- The mask lives in a persistent buffer (`_kept_is_padding`) filled before each replay: captured replay graphs read its address, so a per-step tensor would not reach them. Captures pass it too (all false), so the masking ops are in the graph.
- Only graph replays pad; eager replay batches keep `is_padding=None`, so the existing assertions on unpadded contexts still hold.
- PCP keeps its own `is_padding`.

Idle DP ranks: the outer dummy batch marks all its rows as padding (`InputBatch.make_dummy(..., is_padding=not is_profile)`), but the replay batch's single kept dummy row is left unmasked here (`False` under graphs, `None` in eager), so it still reaches the routers and EPLB counts it. Suggest marking it as padding and always passing the mask, which also drops the `run_graph` condition:

```python
if self.pcp_size > 1:
    is_padding = kept_batch.is_padding
else:
    num_real = 0 if is_dummy else num_tokens
    is_padding = self._kept_is_padding[:num_padded]
    is_padding[:num_real].fill_(False)
    is_padding[num_real:].fill_(True)
```

(The `is_padding is None` asserts at test L181/L189 would change accordingly.)
