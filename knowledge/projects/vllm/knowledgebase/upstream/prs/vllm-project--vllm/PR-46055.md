# fix(attention): add SM121 (GB10) support for sparse MLA backends (#45…

[Upstream PR](https://github.com/vllm-project/vllm/pull/46055) · state: closed · merged: False

## Original PR description

Purpose
Fixes #45317 — DSA models (GLM-5.1, DeepSeek-V3.2-family with use_sparse=True) fail to start on NVIDIA GB10/DGX Spark (SM121). The supports_compute_capability() method in FLASHMLA_SPARSE, FLASHMLA, and DeepSeekV4FlashMLA backends explicitly filters capability.major in [9, 10], excluding SM121 (major=12).

Test Plan
Run the capability check directly inside a DGX Spark container:bash
docker exec vllm-vl python3 -c "
from vllm.v1.attention.backends.mla.flashmla_sparse import FlashMLASparseBackend
from vllm.v1.attention.backends.mla.flashmla import FlashMLABackend
from vllm.platforms.interface import DeviceCapability

sm121 = DeviceCapability(major=12, minor=1)
print('FLASHMLA_SPARSE SM121:', FlashMLASparseBackend.supports_compute_capability(sm121))
print('FLASHMLA SM121:', FlashMLABackend.supports_compute_capability(sm121))
"
After patch: verify the same output returns True instead of False.

Test Result
Environment: NVIDIA GB10 (DGX Spark), CUDA 13.0, [nvcr.io/nvidia/vllm:26.03.post1-py3](http://nvcr.io/nvidia/vllm:26.03.post1-py3)--- BEFORE PATCH ---
FLASHMLA_SPARSE SM121: False
FLASHMLA SM121: False

--- AFTER PATCH (added 12 to lists) ---
FLASHMLA_SPARSE SM121: True
FLASHMLA SM121: True
The FlashMLA kernels already support SM121 at the CMake level; only the Python capability gate was blocking selection.
