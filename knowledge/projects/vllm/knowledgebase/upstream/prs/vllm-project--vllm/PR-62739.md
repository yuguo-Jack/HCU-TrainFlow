# [Bugfix][HiSparse] Read resident prefill rows by request state slot

[Upstream PR](https://github.com/vllm-project/vllm/pull/62739) · state: closed · merged: True

## Original PR description

## Purpose

HiSparse's resident prefill conversion lazily gathers a batch-ordered copy of the residency table inside the layer-0 conversion. The gather is queued after `logical_topk_ready`, but the side-stream converter waits only on that event, so it can read the table before it's written.

This PR removes the gathered table. The sparse-MLA index remap kernel gets an optional `idx_mapping` indirection, off for other callers, and HiSparse passes its persistent residency table plus `request_state_indices` directly. Both are written before the forward, so the existing event orders them. Residency is stored group-major, so each group's view is a contiguous table.

Alternative to #62401, which keeps the gather and adds a layer-0 `wait_stream`.
