# [Spec Decode] Map Cosmos3-Edge DFlash aux layers onto split blocks

[Upstream PR](https://github.com/vllm-project/vllm/pull/59690) · state: open · merged: False

## Original PR description

## Overview

Map Cosmos3-Edge DFlash auxiliary hidden states onto vLLM's split decoder blocks. Edge loads each HF block as attention then MLP, so the verified capture is `2 * (i + 1)`. Qwen and other targets keep the existing `i + 1` conversion.

## Claims

- Cosmos3-Edge DFlash captures aux states at vLLM layers `(4, 16, 28, 40, 52)` for `target_layer_ids = [1, 7, 13, 19, 25]`.
- Qwen and other non-Edge targets still use `(2, 8, 14, 20, 26)`.
- `Cosmos3EdgeForConditionalGeneration` implements the EAGLE3 aux interface, and `image_token_index` is exposed for the DFlash proposer.

## Validation

Unit tests in `tests/v1/spec_decode/test_dflash_causality.py` (17 passed). That directory is already collected by the spec-decode CI workflow. CI does not have a Cosmos3-Edge checkpoint, so the GPU checks below were run locally, once each.

- `model_type == cosmos3_edge` remaps `(2, 8, 14, 20, 26)` to `(4, 16, 28, 40, 52)`.
- `qwen3_vl` stays at `(2, 8, 14, 20, 26)`.
- `SupportsEagle3` is on the Cosmos3-Edge MRO, and `image_token_index` equals `image_token_id` (19).

GPU checks used export checkpoint `100000`, `draft_length=7`, temperature 0, `VLLM_USE_FLASHINFER_SAMPLER=0`, and no out-of-tree patch. Startup log: `Cosmos3-Edge DFlash aux layers: (2, 8, 14, 20, 26) -> (4, 16, 28, 40, 52)`.

| Check | Config | vLLM 0.27.1 + out-of-tree remap | This change |
|---|---|---|---|
| Last-token cosine vs HF `hidden_states[lid + 1]` | 5 aux layers | 0.999982, 0.999919, 0.999895, 0.999854, 0.999703 | same values, unique argmax |
| MTBench average acceptance length | 80 requests, output length 4096 | 3.338 | 3.455 |
| `common_sense_20250225` video | 80 requests, 32 frames, `max_model_len` 16384 | 2.848 | 3.171 |

MTBench histogram order is unchanged (`bin1 > bin2 > bin8 > bin3`). All 80 video requests completed on the in-tree video processor.

## Details

DFlash stores Hugging Face block ids. `get_eagle3_aux_layers_from_config` already adds 1, which is correct when one HF block is one vLLM layer. Nemotron-H / Cosmos3-Edge splits each block into attention then MLP (28 HF blocks become 56 vLLM layers), so the state that matches training is the post-MLP residual at `2 * (i + 1)`.

The multiply runs once, after the shared `i + 1` conversion, and only when `model_type == cosmos3_edge` or an architecture name contains `Cosmos3Edge`. It is not inside `get_eagle3_aux_layers_from_config`, so the DFlash FC width is unchanged. The V2 runner calls this helper from `set_eagle3_aux_hidden_state_layers`. The legacy runner calls the same helper so its duplicate `i + 1` conversion cannot diverge. The mapping is host-side integer arithmetic at load time.

The legacy vLLM 0.27.1 path also wrapped video resize and `get_image_size`. Current main already does those in `Cosmos3EdgeVideoProcessor`, so they are not part of this change.

Thanks @benchislett . Both points are addressed in c36313ce.

1. Model Runner V2 is the path that applies the scale. After the model loads, `GPUModelRunner.load_model` calls `set_eagle3_aux_hidden_state_layers`. That helper scales the aux ids and then calls `set_aux_hidden_state_layers`. The deprecated runner calls the same `apply_eagle3_aux_layer_scale` helper, so a V1 fallback still captures the scaled ids.

2. The scale is declared by the model. `apply_eagle3_aux_layer_scale` reads `eagle_aux_hidden_state_layer_scale` from the model config when that attribute is present, and otherwise from the model class. If neither has it, the scale stays 1 and the shared `i + 1` conversion is unchanged. `Cosmos3EdgeForConditionalGeneration` sets the attribute to 2, because each HF block is loaded as attention then MLP and the verified capture is `2 * (i + 1)`. For `target_layer_ids = [1, 7, 13, 19, 25]` that is `(2, 8, 14, 20, 26) -> (4, 16, 28, 40, 52)`. Qwen, and a `model_type == cosmos3_edge` object that does not declare the attribute, stay at `(2, 8, 14, 20, 26)`. The attribute is on the vLLM model class: current main takes `Cosmos3EdgeConfig` from Transformers, that config is a strict dataclass with no scale field, and vLLM no longer has its own Cosmos3-Edge config module. The helper uses the same attribute if it is present on the config.

Tests:
- `tests/v1/spec_decode/test_dflash_causality.py`: 17 passed. This file lives under `tests/v1/` because that is the current engine's test tree. The new assertions import `set_eagle3_aux_hidden_state_layers` from `vllm.v1.worker.gpu.spec_decode.eagle.eagle3_utils`, which is the helper Model Runner V2 calls. The Edge class scale is 2 and `SupportsEagle3` is on its MRO. The helper returns `(4, 16, 28, 40, 52)` only when the scale is 2. Qwen and a name-only `cosmos3_edge` config stay at `(2, 8, 14, 20, 26)`. `get_eagle3_aux_layers_from_config` still returns the unscaled ids, so the DFlash head width is unchanged.
- One H100, eager startup on the V2 runner, checkpoint `export-100000`, `num_speculative_tokens=7`, `max_model_len=4096`, `VLLM_USE_FLASHINFER_SAMPLER=0`, no out-of-tree patch. The log was `Using V2 Model Runner`, then `Eagle3 aux layers scaled by 2: (2, 8, 14, 20, 26) -> (4, 16, 28, 40, 52)`, then `Using Eagle3 auxiliary layers from config: (4, 16, 28, 40, 52)`. The process printed `STARTUP_OK` and exited 0.

The acceptance-length numbers in the PR description are for this checkpoint with aux layers (4, 16, 28, 40, 52). The H100 startup on this revision logs that same tuple, so those numbers describe the capture this commit selects.
