- RichardoMrMu · COMMENTED · 2026-08-27T13:37:33Z · [source](https://github.com/vllm-project/vllm/pull/53365#pullrequestreview-5041405691)

This moves the instrumented boundary from actual `ToolParser` calls to normal `ParserEngine.parse()` / `parse_delta()` execution after history initialization, once parser metrics are registered. The new Prometheus test explicitly counts a method-level no-tools call (`tools=None`, `tool_choice=none`, `enable_auto_tools=False`): base=0, legacy=0, head=1. A reasoning-only `parse_delta()` likewise changes 0 to 1 while legacy code remains in its reasoning phase. The direct no-tools case is not established as reachable through standard serving, but the reasoning-only case applies when compatible reasoning/tool adapters collapse to one engine. Could we either preserve the legacy tool-parser boundary or explicitly redefine/document this as parser-engine invocation telemetry?
