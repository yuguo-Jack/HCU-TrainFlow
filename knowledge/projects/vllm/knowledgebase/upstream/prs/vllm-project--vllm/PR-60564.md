## Purpose

Fixes #60561.

Since #53781, a device-resident BLHNC MLA cache registers one NIXL region per layer, because `page_contiguous` is true for every layer. For GLM-5.3 that is 99 descriptors per block instead of one, so BLHNC transfers cost more than LBHNC's (104 vs 62 strides on a decode rank).

This PR adds `kv_connector_extra_config.whole_row_regions` (default `false`):
- **Replicated (MLA) layers** of a block-major row register as one whole-row region, as they did before #53781. The row length is the block stride, as on `main`.
- **Head-sharded layers** (a GQA draft under an MLA target) never take the whole-row branch. They keep per-layer SPLIT regions, so each TP rank reads its own head slice (#58471).
- **Non-MLA models** are unaffected; the flag only changes MLA regions.
- **Rejected configurations.** The flag errors out at registration for:
  - `kv_buffer_device=cpu`;
  - HiSparse host-resident groups, so #53781's case keeps its current behaviour;
  - a layout that packs head-sharded draft pages into the target's group and row. This is BLHNC with `--disable-hybrid-kv-cache-manager`. The row's size depends on TP there, so prefill and decode rows would differ, and without the check this only failed later as a handshake assert.

**Why #57662 is needed.** Under BLHNC every KV cache group starts at byte 0 of the shared row, so the first draft page aliases the first target page's base address. Without #57662's `(base_addr, block_len)` key, the draft region folds into a target region. The rebase keeps `main`'s rule that a packed PP producer never dedups aliased regions.

**Not a duplicate:**
- #57662 fixes only the dedup key.
- #59586 splits MLA kernel rows larger than the NIXL block into dense pages. That changes per-layer page geometry; it does not register one region per block row.
- #50717 preserves packed-MLA block geometry.
- #60368 simplifies #58471's head slicing.

None of them restores whole-row registration for page-contiguous caches in pull mode.

**Separate issue:** the DFlash2 acceptance drop seen on BLHNC deployments (#60560) does not come from NIXL registration. It comes from the hybrid KV cache manager's sliding-window draft group, and is fixed by #60767. This PR neither causes nor fixes it.

- **Same two failures everywhere.** `test_abort_timeout_on_prefiller[None]` and `[ray]` start a real engine that wants 50% of GPU memory, and only 17.6 of 268 GiB were free on the shared GPU. No failures are introduced by this PR.
- **New tests** (`-k "blhnc_gqa_draft or whole_row_regions"`): 6 of 6 pass.
- **Lint:** ruff and mypy pass on the changed files.

**End to end, with this PR's code.** These are from the B300 runs above. The NIXL connector's own metrics are summed over the profiling window of each run (~5,700 transfers each):

| BLHNC, block 64 | regions | descriptors / transfer | descriptors / MB | transfer time / GB |
|---|---|---:|---:|---:|
| `whole_row_regions` on (4 runs) | target row: 1; draft: per layer | 1,309 – 1,860 | **0.48 – 0.54** | 48 – 69 ms |
| per-layer regions | 1 per layer | 46,692 | **49.3** | 77 ms |

The per-layer row ran with `--disable-hybrid-kv-cache-manager`, which changes what is transferred (decode prefix hits rise and less KV is pulled), so its transfer time is indicative only. The descriptor reduction is the direct effect of this PR.

**Earlier variant, for context.** On GB200 (128 sessions), a predecessor of this change produced:
- **Registration:** 1 stride / 26,104 descriptors on a decode rank, vs 62 / 2,488,080 with LBHNC block 1024.
- **Transfer time:** mean NIXL transfer time 85.23 → 22.30 ms.
- **TTFT:** p50 848 → 730 ms.

That predecessor also folded the head-sharded draft into the whole-row region, which this PR deliberately avoids, so these are not this PR's numbers. The target's registration is the same; this PR adds the draft's per-layer regions on top.

**Not covered:** push mode (`main`'s packed-MLA push path is unchanged) and non-MLA models (the flag does nothing there).
