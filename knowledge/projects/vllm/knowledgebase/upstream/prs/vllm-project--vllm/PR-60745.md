# [Frontend] Support image inputs in the Decisions API

[Upstream PR](https://github.com/vllm-project/vllm/pull/60745) · state: open · merged: False

## Original PR description

## Overview

Allow `/v1/decisions` requests to carry ordered `input_text` and `input_image` content through vLLM's existing multimodal renderer. Each question receives the same input content followed by its own question suffix.

This PR is now based directly on main. All Winnow-specific prompt, option mapping, calibration, tests and documentation have been removed; those belong to #60713. The shared Decisions API predecessor has already merged.

## Behavior

- Preserve image/text ordering and native processor metadata for supported vision-language strategies.
- Reuse existing media fetching restrictions, cache salt and tracing.
- Reject images on text-only deployments without starting generation.
- Preserve the existing text-only request behavior.

## Ordering and strategy boundaries

The serving layer passes ordered input to `ReadStrategy.read_input` without checking strategy classes. Generic next-token reads preserve interleaved image/text content and the strategy's own question formatter. Fixed image-prefix protocols (Liquid d1, JointSchema and D3) retain their trained layout and reject unsupported interleaving with a request error rather than silently reordering content. This does not claim arbitrary interleaving support for every model.
