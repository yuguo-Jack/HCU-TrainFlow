# [Core] Update PyTorch to 2.15.0, torchvision to 0.29.1, triton to 3.9.0 (test channel, cu132)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62519) · state: open · merged: False

## Original PR description

## Purpose

Update the PyTorch ecosystem to the **2.15.0 release candidate** on **CUDA 13.2 (cu132)**, resolving wheels from the PyTorch **test** channel (`download.pytorch.org/whl/test/cu132`). This is the cu132 counterpart of #60324, which stays on cu130: it is built on #60324's branch plus one commit that moves CUDA from 13.0 to 13.2.

| Package | From | To |
| --- | --- | --- |
| `torch` | 2.13.0 | **2.15.0+cu132** |
| `torchvision` | 0.28.0 | **0.29.1+cu132** |
| `triton` | 3.7.1 | **3.9.0** |
| `torchaudio` | 2.11.0 | 2.11.0+cu132 (test channel only) |

### CUDA libraries

These follow the `13.2` entry of `PYTORCH_EXTRA_INSTALL_REQUIREMENTS` in [`generate_binary_build_matrix.py`](https://github.com/pytorch/pytorch/blob/release/2.15/.github/scripts/generate_binary_build_matrix.py) on `release/2.15`, and match the `Requires-Dist` of the `torch 2.15.0+cu132` wheel.

| Package | From | To |
| --- | --- | --- |
| `cuda-toolkit` | 13.0.3 | **13.2.2** |
| `nvidia-cudnn-cu13` | 9.20.0.48 | **9.26.0.51** |
| `nvidia-nccl-cu13` | 2.29.7 | **2.30.7** |
| `nvidia-nvshmem-cu13` | 3.4.5 | **3.7.2** |
| `nvidia-cusparselt-cu13` | 0.8.1 | 0.8.1 |
| `cuda-bindings` | 13.0.3 | 13.0.3 (satisfies `>=13.0.3,<14`) |

### Why the test channel

`torch 2.15.0` is a release candidate, and `torchaudio 2.11.0` has no build on the stable cu132 index (0 wheels; 21 on `test/cu132`). With nothing to satisfy `torchaudio==2.11.0` there, the resolver falls back to PyPI, whose torchaudio is a cu130 build. That is silent at install time and aborts every CUDA job at import with `PyTorch has CUDA version 13.2 whereas TorchAudio has CUDA version 13.0` (Buildkite build 89462 hit this on the 2.13.0 stack: 211 of 211 blocking failures were this one signature).

### Verified on the test channel before pinning

- `torch==2.15.0+cu132`, `torchvision==0.29.1+cu132` and `torchaudio==2.11.0+cu132` each have a cp312 `manylinux_2_28` x86_64 wheel on `whl/test/cu132`.
- `triton==3.9.0` on `whl/test/cu132/triton`. `torch 2.15.0+cu132` requires `triton~=3.9.0`.
- `requirements/test/cuda.txt` pins for torch, torchvision, torchaudio and every CUDA library match what `uv pip compile requirements/test/cuda.in -c requirements/cuda.txt --extra-index-url https://download.pytorch.org/whl/test/cu132 --python-platform x86_64-manylinux_2_28 --python-version 3.12` resolves.

## Changes

1. Everything in #60324 (version pins, test-channel index URLs, CPU wheels from the test channel, the NCCL2 and attention test changes).
2. **[CI/Build] CUDA 13.2 on the test channel** (one commit)
   - `docker/Dockerfile` and `docker/versions.json` move to `CUDA_VERSION=13.2.2` and the `release/2.15` `cuda13.2` builder images (`pytorch/manylinux2_28-builder` and `pytorch/manylinuxaarch64-builder`, tag `cuda13.2-12d4d5cac0ce…`, the same image as PyTorch's floating `cuda13.2-2.15` tag). PyTorch `release/2.15` builds with CUDA 13.2.2. The cuNNN index suffix is derived from `CUDA_VERSION`, so the test-channel URL becomes `.../whl/test/cu132`.
   - `FINAL_BASE_IMAGE` stays on `nvidia/cuda:13.2.1-base-ubuntu24.04`: `nvidia/cuda` publishes no 13.2.2 image, so it is no longer derived from `CUDA_VERSION`. It only supplies the OS layer; the CUDA libraries come from the torch wheel.
   - `requirements/cuda.txt` and `requirements/test/cuda.txt` use `--extra-index-url .../whl/test/cu132`; the lock carries the 13.2.2 CUDA library pins. `requirements/build/cuda.txt`, `check-ray-compatibility.sh`, `tests/standalone_tests/python_only_compile.sh`, the quantization torchao install and the `pip-compile` pre-commit hook point at `cu132`.
   - The wheel and release-image build args (`CUDA_VERSION=13.2.2`, `release/2.15` builder images), the arm64 build script, `setup.py`, `vllm/envs.py` (`VLLM_MAIN_CUDA_VERSION`) and the CUDA install docs move from 13.0 to 13.2. The nightly image script moves to 13.2.1 and keeps its own builder, since it builds against nightly torch.
   - `nvidia-curand` is no longer in the test lock: the 2.15.0 wheel does not request the toolkit's `curand` extra.

### Not changed

- Same as #60324: `torchao` stays on its current pin, TPU and ROCm requirement files are untouched, and the `zentorch` pin is expected to fail on the CPU-Kernel lane.
- `requirements/test/cuda.txt` is hand-edited for the torch stack and CUDA libraries; unrelated transitive packages were left as they were. A reviewer with a working resolver should regenerate it to pick up transitive changes.
- The "CUDA 13.0" display labels in `.buildkite/release-pipeline.yaml` are unchanged; only the build args behind them moved to 13.2.
