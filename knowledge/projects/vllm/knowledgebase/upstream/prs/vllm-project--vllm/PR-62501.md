# [Bugfix] Chunk conformer scores and keep FunASR adaptor frames

[Upstream PR](https://github.com/vllm-project/vllm/pull/62501) · state: open · merged: False

## Original PR description



## Overview

Fixes #62351. First-cut draft, with AI assistance (Grok): chunk Cohere and FireRed conformer scores, merge only FunASR `fake_token_lengths`, and keep Granite Shaw attention per block.

## Claims

- FunASR adaptor attention and the FFN still run on the `olens` pack with `k = 1`. The LLM merge is the per-clip `fake_token_lengths` prefix (80 frames attended, 10 merged in the reported case).
- Cohere and FireRed relative scores are query chunks of 128 using the absolute row. `ac + bd` is scaled once. Cohere still fills `-10000` and then zeros those probabilities. FireRed still fills `-inf` on padded keys only.
- FunASR SANM applies `d_k ** -0.5` once. A full `T×T` pattern stays on the chunked masked matmul. Varlen flash is only the plain key-mask path, and that path leaves Q unscaled.
- Granite computes each block's Shaw bias, runs MATH SDPA, then drops that bias. The remainder is replaced with `-torch.finfo(dtype).max`. `FLASH_ATTENTION` is not selected.

## Validation

`/opt/anaconda3/bin/python` (torch 2.5.1) cannot import `vllm.model_executor` (`infer_schema` rejects `list[int]`), so the pytest modules were not executed. The helper functions were executed from the source files without that import:

- Relative-score gather versus `rel_shift`: max abs diff `0.0` in fp32, including query length 130 and query length 130 with key length 64.
- Cohere per-chunk masks versus the previous `_create_masks` pairs: 0 mismatches for `regular` and `chunked_limited` at length 130, including a zero-length row.
- `clip_fake_token_prefixes` on `olens` `[80, 50]` with fake lengths `[10, 100]` returns `[10, 50]`. With fake lengths omitted, the clips are `[80, 50]`. `pack_olens` on `[10, 0, 4]` builds `cu_seqlens` `[0, 10, 14]`.
- A fully masked SANM context is exact zeros. Softmax of constant `-10000` over 4 keys is uniform (`0.25`); the following zero-fill makes that row zeros. Softmax of `-inf` on that row is NaN.
- Shaw remainder cells outside the valid square equal `-finfo.max` exactly. The valid square is unchanged.
- Extracted `GraniteSpeechConformerAttention` versus the previous blocked SDPA, on CPU: fp32 max abs diff `1.19e-7` (16 features) and `5.96e-8` (11 features, with a remainder). bf16 max abs diff `0.0` for both. Each forward issued 2 `SDPBackend.MATH` calls. `EFFICIENT_ATTENTION` raises `No viable backend` on this CPU. `FLASH_ATTENTION` runs here and is not selected.

No GPU end-to-end run. No performance numbers.

## Details

FunASR merged adaptor `olens = (ilens - 1) // k + 1` into the LLM while the prompt length is `fake_token_lengths`. For `L = 80` and `k = 1` those lengths are 80 and 10. `k` stays 1. The adaptor packs each clip's `olens` prefix into `MMEncoderAttention` (`cu_seqlens` splits the sequence axis; `olens` is not passed as `cu_seqlens` on the padded rectangle). `get_encoder_outputs` returns one prefix per clip, not a `B * T_max` rectangle.

Cohere and FireRed built a full `T×T` relative score, and Cohere also built a `(B, T, T)` mask. The chunk gather uses the absolute row and only columns `j < key_len`, matching `rel_shift(...)[..., :key_len]`. Those paths stay on matmul: SDPA cannot both scale `bd` once and zero-fill after softmax. Each Cohere query chunk builds the same pairs `_create_masks` marked (`regular`, `chunked_limited`, and the query-and-key padding AND) as a `(B, C, K)` mask, not a `(B, T, T)` tensor. FireRed attention is `RelPosMultiHeadAttention` in `conformer_encoder.py`. `fireredasr2.py` is unchanged. `need_weights=False` does not build the probability matrix. The conformer block still reads output `[0]`. `rel_pos_local_attn` and `abs_pos` are left unwired.

SANM scales the scores once and adds FSMN after attention. A `T×T` `mask_att_chunk_encoder` does not use varlen flash. A plain prefix key mask may. If that kernel is missing or fails, the explicit masked matmul is the result that matches the previous scores. Length 0 is zeros after the post-softmax zero-fill. The output projection bias means the module output is finite and is not exact zeros. Pad-query rows can differ when varlen packing runs.

Granite used to materialize every block's Shaw bias and then run one blocked SDPA. The loop now does one block at a time and deletes that bias. One unblocked full-sequence SDPA is a different pattern and is not used. The remainder fill replaces entries with `-finfo.max` on a float mask. `input_features_mask` and the Phi-4 SDPA call are unchanged.

The Python chunk loop depends on the sequence length and is not CUDA-graph friendly. Adaptor length packing copies a host integer list onto the device inside `gpu_sync_allowed`. The production diff adds about 550 lines across the four encoder files, above the checklist's high-complexity line count. That size is the separate fill rules in each encoder: the issue says there is no shared attention module, and none was added. No model runner or scheduler code is touched.

`test_conformer_score_chunks.py` is marked `cpu_test`, as is `test_conformer_encoder.py`. New Cohere checks in `test_cohere_asr.py` are marked `cpu_test` individually so the existing tests in that file stay unmarked. The multimodal GPU job selects `-m core_model` under `tests/models/multimodal`, so these unit tests are not selected there.
