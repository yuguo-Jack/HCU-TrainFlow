# [Metrics] Preserve fractional counter values in snapshots

[Upstream PR](https://github.com/vllm-project/vllm/pull/61748) · state: open · merged: False

## Original PR description

## Overview

Preserve fractional Prometheus counter values in `get_metrics_snapshot()`. The current integer conversion truncates duration counters such as KV offload load and store times, making a value of 0.125 seconds appear as zero through the metrics reader.

## Claims

- Return the original counter sample value and describe `Counter.value` as a float.
- Keep the special speculative token vector conversion unchanged.

## Validation

On DGX Spark with the current source and an existing Python environment:

```bash
PYTHONPATH=. .venv/bin/python -m pytest --confcutdir=tests/v1/metrics tests/v1/metrics/test_metrics_reader.py -q
```

12 tests pass. Against the original reader, the four fractional counter cases fail and eight existing/control cases pass. The cases use real Prometheus counters with one and four engine label sets. All applicable pre-commit hooks pass.

The test command isolates the CPU metrics suite from the model test fixtures in the root conftest. No model evaluation was run: the change reads telemetry and does not modify model execution or generated output.

## Details

KV offload metrics already accumulate floating point transfer durations. Converting their samples to `int` silently discards information. Preserve the value as exported by Prometheus; integral counts remain numerically equal, but callers inspecting the Python type will now see a float.

Duplicate checks searched open PRs and issues for counter fractional values, counter truncation, and fractional metrics. No matching fix was found. This is separate from #46920, which handles unsupported metric types.

AI assistance: implemented, reviewed, and tested with Codex. Human review is pending.
