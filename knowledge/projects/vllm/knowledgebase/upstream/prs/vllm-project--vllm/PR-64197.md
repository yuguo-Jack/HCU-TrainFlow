# [Feature] Support per-model Hugging Face and ModelScope sources

[Upstream PR](https://github.com/vllm-project/vllm/pull/64197) · state: open · merged: False

## Original PR description

## Overview

Some deployments use a main model from ModelScope and a draft model from Hugging Face. The global `VLLM_USE_MODELSCOPE` switch cannot express this combination. This PR adds explicit, per-model Hub selection.

For example, use [GLM-4.7-Flash from ModelScope](https://modelscope.cn/models/ZhipuAI/GLM-4.7-Flash) with [thoughtworks/GLM-4.7-Flash-Eagle3 from Hugging Face](https://huggingface.co/thoughtworks/GLM-4.7-Flash-Eagle3). I could not find a same-ID ModelScope mirror of this draft.

```bash
vllm serve modelscope://ZhipuAI/GLM-4.7-Flash \
  --speculative-config '{"method":"eagle3","model":"hf://thoughtworks/GLM-4.7-Flash-Eagle3","num_speculative_tokens":3}'
```

## Claims

- Support `hf://owner/model` and `modelscope://owner/model` for the model, tokenizer, and speculative draft model.
- Explicit prefixes override the global Hub setting; bare `owner/model` IDs and local paths retain their existing behavior.
- Resolve explicit sources into local SDK snapshots before normal loading, reusing authentication and caching without cross-Hub fallback.
- Keep ModelScope optional and the shared helper under `transformers_utils`.

## Details

The initial scope is single-node Python execution with `auto`, `hf`, `safetensors`, or `pt` loaders. Explicit model sources download repository snapshots, potentially including multiple weight formats; tokenizer-only sources download metadata without weights.

Cross-repository `auto_map`, separate code revisions, and automatic speculator target inference are outside this initial scope. Unsupported cases fail explicitly and can use pre-downloaded local paths instead. This revision removes the earlier loader-specific changes.

Prior open-PR searches found no direct match for per-model HF/ModelScope selection. AI assistance was used.
