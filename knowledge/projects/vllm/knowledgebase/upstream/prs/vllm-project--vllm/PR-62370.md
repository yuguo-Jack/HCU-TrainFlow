# [Bugfix] Keep the top-p filter on one kernel path under batch invariance

[Upstream PR](https://github.com/vllm-project/vllm/pull/62370) · state: open · merged: False

## Original PR description

## Purpose

`apply_top_k_top_p_triton` (`vllm/v1/sample/ops/topk_topp_triton.py`) filters standalone top-p rows of batches of up to 64 with a split-row pipeline, whose split count is itself derived from the batch size and the SM count, and larger batches with the monolithic kernel. The two paths accumulate the partial sums that decide the cutoff in different orders, so the same logits row keeps a different token set depending on how many other requests are in the batch whenever `p` lands near a cumulative-probability boundary. Under `VLLM_BATCH_INVARIANT=1` that makes sampling with `top_p` batch dependent (the CUDA sampler reaches this kernel for seeded requests too). This PR keeps the monolithic kernel for every batch size in batch-invariant mode, in the three places that choose the pipeline (the dispatch, the `SPLIT_COVERS_PONLY` kernel flag and the JIT warmup inputs). Nothing changes when the flag is off.

## Test Plan

Kernel-level check on one NVIDIA GB300 (script below): one fixed random row of 151936 logits is filtered with the same `p` as row 0 of batches of 1, 2, 4, 8, 16, 32, 48, 64, 65, 96, 128 and 256 random rows; for 22 values of `p` (round values, the cumulative probability of the sorted row at several ranks, and those values moved one float up and down) the filtered row 0 must be bitwise identical to the batch-of-1 result. `main` at `ce49c47cbb` vs `main` + this PR, with and without `VLLM_BATCH_INVARIANT=1`, and a repeat of the two batch-invariant runs.

```python
"""Kernel-level batch-invariance check of apply_top_k_top_p_triton for standalone top-p.
Row 0 (fixed random logits) is processed in batches of different sizes (other rows random);
its filtered logits must be bitwise identical regardless of the batch size."""
import os, sys, torch
from vllm.v1.sample.ops.topk_topp_triton import apply_top_k_top_p_triton
V = int(os.environ.get("VOCAB", 151936)); dev = torch.device("cuda:0")
g = torch.Generator(device=dev); g.manual_seed(0)
row0 = torch.randn(V, device=dev, generator=g, dtype=torch.float32) * 4
sizes = [1, 2, 4, 8, 16, 32, 48, 64, 65, 96, 128, 256]
probs = torch.softmax(row0, 0).sort(descending=True).values.cumsum(0)
ps = [0.5, 0.8, 0.9, 0.95, 0.99] + [float(probs[i]) for i in (0, 1, 2, 5, 10, 50, 200, 1000, 5000)] + [torch.nextafter(probs[i], torch.tensor(1.0, device=dev)).item() for i in (1, 5, 50, 1000)] + [torch.nextafter(probs[i], torch.tensor(0.0, device=dev)).item() for i in (1, 5, 50, 1000)]
bad = 0; total = 0
print("VLLM_BATCH_INVARIANT =", os.environ.get("VLLM_BATCH_INVARIANT"), "| vocab", V, "| sizes", sizes)
for p in ps:
    outs = {}
    for b in sizes:
        logits = torch.randn(b, V, device=dev, generator=g) * 4
        logits[0] = row0
        pt = torch.full((b,), p, device=dev, dtype=torch.float32)
        out = apply_top_k_top_p_triton(logits, None, pt)
        outs[b] = out[0].clone()
    ref = outs[1]; diff = [b for b in sizes if not torch.equal(outs[b], ref)]
    kept = int(torch.isfinite(ref).sum()); total += 1; bad += bool(diff)
    print(f"p={p:.9f} kept={kept:6d} differs_from_bs1={diff}")
print(f"RESULT: {bad} of {total} p values give a batch-size-dependent row 0 -> {'FAIL' if bad else 'PASS'}")
sys.exit(1 if bad else 0)
```
