# [Bugfix][ROCm] Avoid unused index caches in MiniMax-M3 sharing layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/64403) · state: open · merged: False

## Original PR description

## Overview

Avoid allocating an unused index-key cache for MiniMax-M3 layers that reuse top-k indices on ROCm. This fixes resource registration for the existing opt-in sharing mode introduced in #47269.

## Claims

- Layers that reuse top-k indices no longer construct an indexer or register its side cache, except on the NVFP4 K/V path, where fused cache insertion still requires it. Main K/V caches, trained parameters and the sharing policy are unchanged.
- Default settings and `index_topk_freq=1` retain the existing behavior. This is a cache-capacity fix, not a throughput claim.

## Validation

MI355X base/head validation reproduced the four unwanted cache registrations and confirmed their removal, with matching lifecycle outputs and BF16 eager generation results.

The recorded runs below used BF16 main K/V on 2026-10-30: base `dbd49af222355`, head `eab3ee8b05a2`. The engine run used the official ROCm native wheel built for that exact baseline (`0.33.0rc1.dev232+gdbd49af22.rocm100`) in an isolated environment.

Check | Base | Patched |
| --- | --- | --- |
| 14 configuration/registration/state-loading cases, including NVFP4 sharing | 10 pass; 4 expected registration failures | PASS: 14 cases |
| Two five-layer BF16 eager engine cases, sharing off/on | Default passes; sharing fails the registration assertion | PASS: both cases |

In the component validation at 64 blocks, the two-layer allocated cache storage decreased from 12 to 10 MiB with the BF16 index path and 10 to 9 MiB with the FP8 index path. These are component measurements, not full-model memory savings.

The current test file contains 14 constructor cases and two engine cases. The added `nvfp4-sharing` constructor case checks that the NVFP4 K/V path retains its required indexer, cache registration and strict state-loading compatibility.

The recorded 14-case constructor suite and the two engine cases were validated separately. The engine tests use dummy BF16 weights; pretrained model quality, graph execution, throughput and native NVFP4/mono execution were not evaluated. Host-only checks covered the mono eligibility and rejection predicates.

Repository regression entry:

```bash
pytest -v -s tests/models/minimax_m3/test_index_cache_overrides.py
```

Constructor subset:

```bash
python -m pytest -q tests/models/minimax_m3/test_index_cache_overrides.py \
  -k 'not test_index_cache_engine'
```

## Details

The forward path already skips indexer execution in reuse layers, but construction still registered an index-key cache with the planner. Gate construction on that same `skip_index_topk` decision, while retaining the indexer on the NVFP4 K/V path because its fused cache insertion still uses it. No planner or cache-manager changes are needed.

The specialized mono path explicitly rejects index sharing and retains its requirement for a non-null indexer in MoE layers.
