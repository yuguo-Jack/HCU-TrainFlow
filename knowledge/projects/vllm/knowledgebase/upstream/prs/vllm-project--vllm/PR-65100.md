# [Perf][Spec Decode] Skip vocab blocks with no target token in the resample kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/65100) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

In Model Runner V2 verification, `_resample_kernel` now returns early for a vocab block whose target logits are all `-inf` (masked by top-k/top-p or a logits processor): the residual there is `-inf` too, so the draft-logit load and the Gumbel draw are skipped. Sampled tokens are bitwise identical. Part of the rejection-sampling work tracked in #61024; first of a stack (see the end of this description).

## Claims

- Resample kernel on top-p-masked verify rows (K = 3, top-p 0.95, Qwen3-0.6B logits, V = 151,936, GB300): **165.9 → 55.4 µs** (creative-writing rows) and **149.5 → 42.2 µs** (math rows) at 256 requests; 13.7 → 6.8 µs at 16 requests.
- No cost on unmasked rows: the check runs only when some request in the chunk may have masked logits (top-p = 1 rows stay at 165.1 µs; forcing the check on them would cost 173.7 µs, +5%).
- Output is bitwise identical with the skip on or off.

## Details

- **Gate.** The block max costs about 5% of the kernel when nothing is masked, so `rejection_sample` takes `skip_masked_vocab_blocks` (default off) and `RejectionSampler._verify` turns it on when any request in the chunk may have masked logits. `Sampler` records that per request in `may_mask_logits`: min-p, top-k or top-p active, or thinking-budget forcing or a logits processor (counted conservatively, e.g. logit bias). Temperature alone only scales and never sets the flag. No host/device sync: the flag is a NumPy lookup.
- **Why it is exact.** The residual is a subset of the target's support, so an all-`-inf` target block yields an all-`-inf` residual. Such a block never wins the global argmax unless every block is `-inf`, and in that case it reports index 0, which is what the argmax of an all-`-inf` block returns.
- **Not duplicating.** Searched open PRs for "resample kernel skip", "rejection sampler resample", "top-p rejection sampling" and #61024: #41258 (lazy recovery) changes the V1 sampler, #48928 (FlashInfer AIR top-p) replaces the mask itself; neither touches the MRV2 resample kernel.
- **With the on-load path.** #65102 and #65103 carry this commit. There the kernels apply the top-p cutoff to raw logits as they load them, so the raw block is never all `-inf`; their next commit tests the block after the cutoff instead, which is the same tensor on this PR's path.
- **Stack.** 1/4, independent of the rest: (2) #65101 `topp_cutoffs_lse` op, (3) #65102 top-p applied as target logits load, (4) #65103 target log-sum-exp from that op. #65104 (draft log-sum-exp from the drafter) closed: a net loss once the drafter's cost is counted.
