# [Kernel][Perf] Register-resident path for rms_norm_dynamic_per_token_quant

[Upstream PR](https://github.com/vllm-project/vllm/pull/61753) · state: open · merged: False

## Original PR description

## Overview

`rms_norm_dynamic_per_token_quant` reads each token three times (RMS, scale, quantize) with a fixed `min(hidden_size, 1024)`-thread block, so at prefill sizes it is slower than `fused_add_rms_norm` + `scaled_int8_quant` (#60499). With at least two tokens per SM, launch a new kernel that keeps each token in registers and reads input and residual once. Smaller batches and batch-invariant mode keep the existing launch.

Addresses the kernel slowdown in #60499. The int8 `QUANT_OPS` fusion entry is unchanged.

## Claims

- 1.3-3.0x faster on L4 with int8 + residual, from 128 to 1024 tokens and hidden 2048 to 8192.
- Above the threshold, faster than the unfused pair at every size in the table, e.g. 11.9 vs 14.6 us at hidden 2048, 1024 tokens (main: 36.1 us).
- No change below two tokens per SM or with `VLLM_BATCH_INVARIANT=1`.
- Within 4.5% of main at 2048+ tokens with hidden 8192, where the kernel is memory-bound.

## Validation

Tests on L4 and H100 and benchmarks on L4, L40S and H100, with the same build on each:

```
pytest tests/kernels/core/test_fused_quant_layernorm.py -k test_rms_norm
# 800 passed (L4, H100)
pytest tests/v1/determinism/test_rms_norm_batch_invariant.py -k "per_token or per_block or nonresidual"
# 80 passed (L4, H100)
```

The new determinism test checks that batch-invariant mode never takes the new kernel. It sizes its two launches from the SM count and also passes on main. With the `vllm_is_batch_invariant()` check removed from the dispatch, 18, 19 and 21 of its 48 cases fail on L4, L40S and H100.

Below the threshold, outputs, scales and residual match main bit for bit. Above it, the new kernel matches the existing kernel at the same block size (checked with a temporary build).

<summary>Benchmark script</summary>

```python
import os, statistics, sys
import torch
import vllm
from vllm import _custom_ops as ops

EPS = 1e-6
TOKENS = [int(t) for t in os.environ.get("TOKENS", "1,16,32,64,128,256,512,1024,2048,4096,8192").split(",")]
HIDDEN = [int(h) for h in os.environ.get("HIDDEN", "2048,4096,8192").split(",")]
FP8 = torch.float8_e4m3fn


def replay_us(fn, iters=100, windows=7):
    side = torch.cuda.Stream()
    side.wait_stream(torch.cuda.current_stream())
    with torch.cuda.stream(side):
        fn()
    torch.cuda.current_stream().wait_stream(side)
    g = torch.cuda.CUDAGraph()
    with torch.cuda.graph(g):
        for _ in range(iters):
            fn()
    g.replay()
    ts = []
    for _ in range(windows):
        a = torch.cuda.Event(enable_timing=True)
        b = torch.cuda.Event(enable_timing=True)
        a.record(); g.replay(); b.record(); b.synchronize()
        ts.append(a.elapsed_time(b) * 1e3 / iters)
    return statistics.median(ts)


torch.manual_seed(0)
label = os.environ.get("LABEL", "?")
unfused = os.environ.get("UNFUSED") == "1"
print(torch.cuda.get_device_name(), torch.__version__, label, flush=True)
for h in HIDDEN:
    w = torch.randn(h, device="cuda", dtype=torch.bfloat16)
    warm = torch.randn(TOKENS[0], h, device="cuda", dtype=torch.bfloat16)
    replay_us(lambda: ops.rms_norm_dynamic_per_token_quant(warm, w, EPS, torch.int8))
    for m in TOKENS:
        x = torch.randn(m, h, device="cuda", dtype=torch.bfloat16)
        r = torch.randn(m, h, device="cuda", dtype=torch.bfloat16)
        row = []
        for qd in (torch.int8, FP8):
            for res in (False, True):
                rr = r.clone() if res else None
                row.append(replay_us(lambda: ops.rms_norm_dynamic_per_token_quant(x, w, EPS, qd, residual=rr)))
        if unfused:
            y = torch.empty_like(x)
            def uf():
                ops.fused_add_rms_norm(y.copy_(x), r, w, EPS)
                ops.scaled_int8_quant(y)
            row.append(replay_us(uf) - replay_us(lambda: y.copy_(x)))
        print("ROW", label, h, m, " ".join(f"{v:.2f}" for v in row), flush=True)
```

## Details

- **Separate kernel.** A 1024-thread block cannot hold 32 floats per thread in registers. Adding the path to the existing kernel broke its 1024-thread decode launches. The new kernel uses `__launch_bounds__(512)` and covers hidden sizes up to 16384.
- **Block size.** Each thread holds 4 vec4s up to hidden 4096 and 8 above, so the block is `div_ceil(hidden_size / 4, vecs)` threads rounded up to 32. Fixed 256- and 512-thread blocks were slower at hidden 2048.
- **Threshold.** At one token per SM, H200 was up to 19% slower at 256 tokens with fp8, and L40S was slower at 64 and 128 tokens. At two tokens per SM no shape is slower beyond the memory-bound cases above.
- **Numerics.** Above the threshold the reduction order follows the new block size, so outputs can differ from main by rounding, as with `fused_add_rms_norm` when its block changes.
- **Limitations.** Measured on L4, L40S and H100; the one-token-per-SM sweep above also ran on H200. Not run on ROCm. GSM8K ran with the earlier one-token-per-SM threshold (64.7% vs 65.4% and 65.1% on main); the final threshold was not model-evaluated. int8 models do not reach this kernel today (#60499). With fp32 input, fp8 output and 8 vectors per thread, the kernel spills 8 bytes on sm_89.

Not a duplicate: no open PR references #60499. #60224 and #61641 change the conversion inside `norm_and_quant`; the new kernel calls `ScaledQuant` directly, so whichever lands second needs a small port.
