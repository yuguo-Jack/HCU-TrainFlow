# [ROCm][CI] Enable batch invariance for the ngram scheduling accuracy test

[Upstream PR](https://github.com/vllm-project/vllm/pull/62048) · state: closed · merged: True

## Original PR description

## Purpose
`test_with_ngram_gpu_spec_decoding` is flaky in `mi300_1: (MI300) E2E Scheduling Accuracy`. The ngram acceptance check for async scheduling without preemption fails by one accepted token:
```text
E   AssertionError: config=[executor=mp, preemption=False, async_sched=True, chunk_prefill=False, spec_decoding=True, spec_method=ngram_gpu, spec_mml=None], params={'logprobs': 2}: acceptance=0.07036590269400884, baseline=0.07420924574209246
E   assert 0.07036590269400884 >= (0.07420924574209246 * (1 - 0.05))
```
Failing run: <https://buildkite.com/vllm/amd-ci/builds/14602>

Sync and async scheduling build different batches, and hipBLASLt picks GEMM solutions by batch shape, so the BF16 results differ slightly and occasionally flip near-tie greedy tokens. That changes which ngram drafts match, while the HF accuracy checks still pass. 

This PR enables `VLLM_BATCH_INVARIANT=1` for this test on ROCm only. 
## Test Plan
MI300X (gfx942), in the ROCm CI image:
```bash
cd tests
pytest -v -s v1/e2e/general/test_async_scheduling_accuracy.py::test_with_ngram_gpu_spec_decoding
```

## Test Result
With default ROCm kernels the check was flaky, while with batch invariance enabled all 15 runs passed and async acceptance was bit-identical to sync (0.07605).
