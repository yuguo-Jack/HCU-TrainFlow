# [Benchmark][Spec Decode] Add reference-replay oracle benchmark

[Upstream PR](https://github.com/vllm-project/vllm/pull/62258) · state: open · merged: False

## Original PR description

## Summary

Adds a benchmark comparing baseline decoding, an oracle, ngram, and EAGLE3. The oracle replays the target model's saved output as draft tokens.

Uses the existing `custom_class` interface and adds README examples. No engine changes. Related to #61024.

## Results

Qwen3-8B, one H100, vLLM 0.31.0; bf16, greedy decoding, thinking disabled, and at most 384 output tokens.

Best tested **throughput speedups over baseline**, with async scheduling off for oracle, EAGLE3, and baseline:

| Concurrency cap | Oracle | EAGLE3 |
|---|---:|---:|
| 1 (serial) | **10.50×** (k=12) | **2.85×** (k=5) |
| 8 | **5.27×** (k=12) | **2.39×** (k=3) |
| 32 | **3.50×** (k=16) | **2.68×** (k=5) |

Serial runs use **24 prompts**; caps 8 and 32 use **224 GSM8K/HumanEval prompts**. The cap is `max_num_seqs`, not a fixed batch size.

[Full results and prompts](https://gist.github.com/jiangLLM/e95756b974f385846e4277b7ee68d6c8): **89 archived configurations**, including 18 early oracle runs. Local lint and style checks passed.

## Notes

The oracle is a performance reference for this setup, not a theoretical upper bound. Outputs can differ from the saved reference; exact-match counts are reported in the Gist and do not measure task accuracy. Use `--strict` to disable realignment.
