# [ROCm][Perf][DSv4.1] Enable decoder SWA bounded replay

[Upstream PR](https://github.com/vllm-project/vllm/pull/59039) · state: closed · merged: True

## Original PR description

## Summary

#58132 added decoder-side SWA bounded replay for the CUDA model. This PR enables it on ROCm. During eager prefill, layer 20 writes its KV for every token, then layer 20 and layers 21–39 run on each request's last 128 tokens. The final `mhc_post` runs on that replay batch. Decode graphs stay on the full batch. #59532's replay graphs are already used: the AMD model uses `DeepseekV41ModelState`.

The AMD attention class does not override `forward_kv`. Replay calls `DeepseekV4Attention.forward_kv`, which writes the uint8 SWA cache through `fused_deepseek_v4_kv_rope_insert`.

## What changed

- `vllm/models/deepseek_v41/amd/model.py`: `write_kv` on the last KV source, then `DecoderReplayLayers` from that layer. Pass `write_kv`, the attention metadata prefixes, and that layer's SWA prefix. `mhc_post` runs inside the replay batch. The return is `(hidden_states, pre_mix, *aux)`. The aux state at the cut is captured on the trimmed rows.
- `vllm/models/deepseek_v41/amd/rocm.py`: no `forward_kv` override. The shared method calls `fused_deepseek_v4_kv_rope_insert` and then the compressor insert and indexer K write.
- `vllm/models/deepseek_v41/amd/vl_model.py`: forward `decoder_replay_layers` from the language model.
- `vllm/models/deepseek_v41/nvidia/model_state.py`: when decoder replay layers exist and the prefix-cache window is 0, build `replay_start` and warm the gather kernel. The pad kernel stays on the prefix-cache path.
- Tests cover a 300-token forward (trim, both `mhc_post` calls, the cut-aux capture, the prefix set from the cut, and the SWA insert) and window 0 warming gather without the pad kernel.

## Gating

On when `cache_config.swa_bounded_replay` is set and the v2 model runner is in use. Off with `--no-swa-bounded-replay`. The last KV source must have `compress_ratio <= 1`, and no Engram layer may sit at or after it. ROCm does not read `swa_cache_layer.bounded_replay`; that flag is the prefix-cache path, and attention forces it off. CUDA still requires it. Replay graphs follow `compilation_config.cudagraph_decoder_replay` (default on) and `decoder_replay_trim_threshold` (default 768).

## Depends on

#59894 is in this base. It replaced the row buffers with `write_kv` and `first_swa_prefix`, and replay starts at the last KV source. #56638 is in this base. It replaced #59136 and bounds the ROCm prefill SWA indices at the replay start. #59532 is in this base and supplies the replay graphs. None of the three are in this diff.

## Performance

4× MI325X (gfx942), TP4, DeepSeek-V4.1-Flash, spec decode off, prefix cache off, HIP INT4 QuickReduce, `FULL_AND_PIECEWISE`. `max_num_seqs` left at the default. Head `bf6a231a018d`, rebased onto main `c75cb63cd2bb`. The bench, GSM8K, and NIAH below were measured before that rebase and were not re-run. The extension is the installed ROCm nightly `0.31.1rc1.dev1+gbb87d227d`.

Serve log: `Decoder SWA bounded replay: in eager prefill steps, layer 20 writes its KV for every token, and the rest of it and layers 21-39 run on each request's last 128 tokens only.` Also `cudagraph_decoder_replay: True` and `Capturing decoder replay CUDA graphs (PIECEWISE): 4/4`.
