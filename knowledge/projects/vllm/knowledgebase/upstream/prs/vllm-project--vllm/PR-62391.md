# [Bugfix][KV Events] Close ZMQ sockets from publisher thread

[Upstream PR](https://github.com/vllm-project/vllm/pull/62391) · state: open · merged: False

## Original PR description

## Overview

Addresses Bug6 in #56251.

Prevent `ZmqEventPublisher.shutdown()` from closing ZMQ sockets while the
publisher thread may still be using them.

## Claims

- Makes the publisher thread the sole owner of PUB and ROUTER socket cleanup.
- Preserves the bounded shutdown wait without closing an in-use socket from
  another thread.
- Adds a deterministic regression test covering an in-flight send that lasts
  beyond the shutdown timeout.
- Prevents the `zmq.ZMQError: Socket operation on non-socket` failure caused by
  the shutdown race.

## Validation

The regression test uses a real `ZmqEventPublisher` and a real ZMQ socket. It
holds `send_multipart()` in flight beyond `SHUTDOWN_TIMEOUT`, calls
`shutdown()`, and verifies that:

- the socket remains open while the publisher thread is sending;
- the publisher thread closes the socket when it exits;
- the close runs on the publisher thread; and
- the send does not fail with `ENOTSOCK`.

## Details

### Root cause

`shutdown()` performed a bounded join of the publisher thread and then closed
the PUB and ROUTER sockets without checking whether the thread had exited. If
the publisher thread was still inside a send operation, shutdown closed a
socket concurrently from another thread. PyZMQ sockets are not thread-safe,
which could result in `Socket operation on non-socket`.

### Implementation

Socket cleanup now runs from a `finally` block in the publisher thread.
`shutdown()` still performs a bounded join and emits a warning if the thread
has not exited, but it does not close sockets owned by the live publisher
thread.

The trade-off is that a permanently stuck publisher thread retains its sockets
until the thread or process exits. This avoids unsafe cross-thread socket
destruction while preserving bounded shutdown behavior.

### Duplicate-work check

No open PR was found that fixes Bug6 in #56251.

#52857 handles `queue.Full` while enqueueing the shutdown sentinel. It does not
address the cross-thread socket-close race fixed here.
