# [Bugfix][ROCm] Only set inductor batch_invariant when torch has it

[Upstream PR](https://github.com/vllm-project/vllm/pull/62274) · state: closed · merged: True

## Original PR description

## Purpose

Fix 10 AMD failures in nightly [95663](https://buildkite.com/vllm/ci/builds/95663): MI250/MI300/MI355 Batch Invariance, MI300/MI355 LoRA, MI355 Spec Decode Draft Model, and MI250 E2E Scheduling Accuracy. Every engine started with `VLLM_BATCH_INVARIANT=1` dies at init:

```
File ".../vllm/model_executor/determinism/batch_invariant.py", line 1429, in override_envs_for_invariance
    inductor_config.batch_invariant = True
AttributeError: torch._inductor.config.batch_invariant does not exist
```

**Root cause:** #61118 sets `torch._inductor.config.batch_invariant` unconditionally. The torch in the ROCm CI images has no such option, and torch's config module raises on unknown keys. All of these steps passed in the previous nightly (95553), before #61118.

**Fix:** only set the option when torch provides it. On torch versions that have it, behavior is unchanged.

**Not a duplicate:** no open PR guards this. #60074 pins Inductor kernel configs, which is a different change.

## Test Plan

Not run locally (no ROCm host). The AMD batch-invariance and LoRA steps will confirm.
