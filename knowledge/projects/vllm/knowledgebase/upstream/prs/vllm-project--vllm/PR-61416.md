# [CI] Use an ungated model in the DGX Spark XQA test

[Upstream PR](https://github.com/vllm-project/vllm/pull/61416) · state: closed · merged: True

## Original PR description



## Overview

The optional `(DGX) Spark FlashInfer NVFP4 XQA` step fails before reaching the kernel: the Spark agent cannot read the gated `meta-llama/Meta-Llama-3-8B`, which `create_vllm_config()` uses by default. This switches the test to `Qwen/Qwen3-0.6B`, which the same file already uses.

## Claims

- `test_flashinfer_xqa_nvfp4_decode_correctness` no longer fails with `OSError: You are trying to access a gated repo` on agents without access to the meta-llama repo.
- The test only uses the model to build its config. Q/K/V are random tensors, the reference is the fa2 prefill over the same tensors, and the head layout is overridden, so the values the test uses do not change.

## Validation

All four parametrizations failed with the gated-repo error in both CI builds of #60948 that ran this optional step (`ready-run-all-tests`). Locally, with an empty HF cache and no token, `create_vllm_config()` reproduces the same `OSError` for `meta-llama/Meta-Llama-3-8B` and builds the config for `Qwen/Qwen3-0.6B`.

After the test's overrides, both models give the same dtype (bf16), 24 query / 4 KV heads, head size 256, no sliding window or softcap, block size 16 and `nvfp4` cache dtype; only the architecture name differs.

The kernel part of the test has not run on SM12x yet, in CI or locally.

## Details

The step was added in #60452 as optional, so it stays blocked unless someone unblocks it or the PR has `ready-run-all-tests`; it had not run before #60948. Other tests in this file keep the default model because they run on agents that can read the gated repo.
