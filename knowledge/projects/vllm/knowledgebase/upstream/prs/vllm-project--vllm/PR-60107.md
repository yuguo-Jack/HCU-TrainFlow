# [Bugfix][KVConnector][NIXL] Size per-region replicate flags by each region's block count

[Upstream PR](https://github.com/vllm-project/vllm/pull/60107) · state: closed · merged: True

## Original PR description



## Background

With P_TP > D_TP (e.g. PCP8/DCP8 prefill → DP8 decode), each decoder rank reads a block from several prefill ranks. Each local descriptor gets a replicate flag: full-attention regions are **SPLIT** (each rank fills its head slice), MLA regions are **REPLICATE** (whole block read once).

`_fa_desc_replicated` assumed every region holds the same number of blocks. HiSparse breaks this: host-resident MLA regions hold `hisparse_host_num_blocks`, GPU regions hold `num_blocks`. Every P_TP > D_TP handshake into a HiSparse decoder failed with `AssertionError: FA desc flags N != num_fa_descs M`.

## Fix

Build the flags the same way `_build_fa_local` builds the descriptors: same region order, `region_num_blocks[i] * block_size_ratio` per region. Companion fix for the same topology: #60108. No other open PR touches this function.

## Validation

**main vs. this PR**, checked against the descriptors `_build_fa_local` emits:

| Region layout | main | this PR |
|---|---|---|
| Equal block counts | OK | OK |
| HiSparse, unequal block counts | assert | OK |
| Unequal counts that divide evenly | flags silently wrong | OK |
| Layer-name routing, region listed twice | flags silently wrong | OK |

**Unit:** `test_tp_mapping.py` + `test_nixl_connector_hma.py`: 121 passed.

**E2E** (GLM-5.3, 2 × 8 H200, PCP8/DCP8 prefill → DP8 HiSparse decode, with #60108): main asserts on the first request. With both fixes, 8 one-hour agentic benchmark points ran with 0 errors and a 100% decoder prefix-cache hit rate. That run used an earlier revision of this fix that produces identical flags for this topology.
