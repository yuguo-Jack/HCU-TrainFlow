# [ROCm] Fuse AR + add-RMSNorm + FP8 quant per token

[Upstream PR](https://github.com/vllm-project/vllm/pull/58301) · state: open · merged: False

## Original PR description

## Purpose

Add the per-token analogue of the existing per-group AR+RMS+FP8-quant fusion so the standalone `dynamic_per_token_scaled_quant` kernel that feeds the projection a8w8 GEMM is absorbed into the AllReduce epilogue, and remove the now-obsolete AITER capability probes. This is Python/vLLM integration only; the AITER kernels already exist.

  **New per-token fusion**
  - **`_aiter_ops`**: add the `rocm_aiter_fused_allreduce_rmsnorm_quant` custom op (impl calls `fused_ar_rms(post_per_token_quant=True)`, plus fake and accessor), reusing the per-group 1-stage/2-stage launcher eligibility logic.
  - **`allreduce_rms_fusion`**: add the no-add and add per-token patterns, registered before the AR+RMS-only patterns so the larger quant-inclusive subgraph wins the match.
  - **tests**: add a per-token fusion test mirroring the per-group one.

  **Cleanup: drop AITER capability probes**
  - vLLM's `docker/Dockerfile.rocm_base` pins AITER `v0.1.22.post1`, which already ships both fused launchers — per-token landed in **v0.1.12** (ROCm/aiter#1990), per-group in
  **v0.1.14** (ROCm/aiter#2823). The runtime `hasattr` probes that gated pattern registration for graceful degradation are therefore always true.
  - Removed `build_supports_per_group_quant` / `supports_per_group_quant` and their per-token equivalents; both pattern families now register unconditionally; dropped the dead `warning_once` branches and the test skip-guards.

## Test Plan

Run the AR+RMS fusion pass tests on 2xMI355X, covering both the pre-existing per-group path (regression check) and the new per-token path:

```
  python -m pytest tests/compile/passes/distributed/test_fusion_all_reduce.py -k "rocm_aiter" -v
```

The new `test_rocm_aiter_all_reduce_rmsnorm_per_token_quant_fp8_fusion_pass_replace` asserts all four pattern sites fuse (matched_count == 4), verifies the fused custom op replaces the standalone `all_reduce + per-token-quant` ops, and checks fused vs. unfused numerical agreement within FP8 tolerance.

## Test Result

All 4 tests pass (2 pre-existing per-group + 2 new per-token), no regressions:
