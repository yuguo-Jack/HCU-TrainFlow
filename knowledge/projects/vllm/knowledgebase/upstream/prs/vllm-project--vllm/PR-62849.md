# [CI][Test] Skip Machete W4A16 tests on non-Hopper GPUs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62849) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`tests/quantization/test_cutlass_w4a16.py` guards its module-level skip with `has_device_capability(90)`, a `>=` test, so the Hopper-only Machete tests are collected on every newer architecture and fail. Switch to `is_device_capability(90)`, which is what the file's own docstring and skip message already describe.

## Claims

- Machete W4A16 tests skip on non-Hopper CUDA GPUs, as `"Machete W4A16 requires Hopper (sm_90)."` already claims.
- Hopper is unchanged: `is_device_capability(90)` is `True` on sm_90, so the module is still collected there. Pre-Hopper GPUs were already skipped under both forms, and the `is_rocm()` branch is untouched.
- Test-only change, one word.

## Validation

Ran the file on GB300 (capability 103) before and after the change, in the same container (vLLM `0.31.0`):

| | `pytest -q tests/quantization/test_cutlass_w4a16.py` |
|---|---|
| main | `8 failed, 1 passed in 49.09s` |
| this PR | `1 skipped in 0.03s` — `SKIPPED [1] quantization/test_cutlass_w4a16.py:18: Machete W4A16 requires Hopper (sm_90).` |

Predicate values measured on that device:

| predicate | value |
|---|---|
| `get_device_capability()` | `103` |
| `has_device_capability(90)` | `True` — current guard lets the module through |
| `is_device_capability(90)` | `False` |

## Details

**Root cause.**

1. Machete is built on `wgmma` PTX and is sm_90-only. The module says so twice: the docstring (`"Tests for Cutlass W4A16 (Machete) kernel on Hopper"`) and the skip message.
2. The guard uses `has_device_capability(90)`, which is `>=`, so any capability above 90 passes it and the module is collected.
3. On Blackwell `choose_mp_linear_kernel` correctly returns `MarlinLinearKernel`, so every assertion expecting `MacheteLinearKernel` fails. The product behaviour is right; only the guard is wrong.

**Fix.** `is_device_capability(90)` matches sm_90 exactly, aligning the guard with the message.

**Why CI did not catch this.** `.buildkite/test_areas/quantization.yaml` pins `tests/quantization/` to `device: h200_35gb`; only `test_blackwell_moe.py` runs on B200. No Blackwell runner collects this file today, so the validation above was performed outside CI.

Not a duplicate: searched open and closed PRs for `test_cutlass_w4a16`, and for `machete` together with `is_device_capability`; nothing related. Upstream `main` still carries the original line.
