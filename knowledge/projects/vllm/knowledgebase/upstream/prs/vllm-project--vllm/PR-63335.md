# [3/3][Spec Decode] Add bounded CUDA IPC feature transport

[Upstream PR](https://github.com/vllm-project/vllm/pull/63335) · state: open · merged: False

## Original PR description

## Overview

Add explicit CUDA IPC transport for target features used by same-host remote own-KV drafting, with bounded producer storage and receiver-owned copies.

Based on [vllm-project/vllm#63334](https://github.com/vllm-project/vllm/pull/63334). Related design: [RFC #42109](https://github.com/vllm-project/vllm/issues/42109). This is part 3/3 (CUDA IPC) of the standalone placement series.

## Claims

- Reserve bounded producer arenas before target KV profiling and bind leases to GPU identity and generation.
- Copy features into receiver-owned storage before acknowledging reuse; quarantine uncertain completion and fence the runtime.
- Preserve inline and `auto` defaults, request deadlines and failure policies.
- Run the four two-rank Gloo fatal-export regressions explicitly on the CPU platform, including CI hosts with only one visible GPU.

## Details

This NVIDIA-only transport performs GPU copies and retains synchronous model execution. Receiver-owned storage must outlive producer lease reuse, including retained MTP features; uncertain completion fences further reuse.

Inline remains the default for `transport="auto"`. Historical two-GPU measurements distinguish target memory relieved, target logical KV capacity and total target-plus-draft memory. Increased KV capacity alone does not establish a larger maximum context length, and single-GPU cross-process checks do not validate cross-device IPC or RDMA.
