# [ROCm][Perf] Fuse the MXFP4 activation quant into the GDN gated RMSNorm

[Upstream PR](https://github.com/vllm-project/vllm/pull/59553) · state: open · merged: False

## Original PR description

> **Needs AITER >= 0.1.27** (ROCm/aiter#6038, `fused_rms_gated_mxfp4_quant` with `transpose_scale`). It is imported directly, with no fallback. Draft until `docker/Dockerfile.rocm_base` pins it.

<!-- markdownlint-disable -->

## Overview

On GDN models whose `out_proj` runs AITER's Triton MXFP4 linear (online MXFP4 through `quantization-config.targets`, or a Quark MXFP4 checkpoint), `RocmAiterRMSNormQuantFusionPass` replaces the gated RMSNorm, the separate MXFP4 activation quant and the GEMM with one op. The quant runs inside the norm kernel. The pass also starts matching GDN's `flatten(-2)`, which the gated-norm patterns missed in serving; that rewrite runs only when the MXFP4 pattern is registered, so FP8 graphs are unchanged. Linears on the ASM GEMM are not matched.

Not a duplicate: searched open PRs for "gated rmsnorm mxfp4", "rms_norm_gated fusion", "GDN out_proj quant" and "fused_rms_gated". #58802 fuses the gated norm into a BF16 `out_proj`; this PR applies where `out_proj` is quantized. #61902 and #59483 fuse the quant into other norms. #64509 fuses the gated norm into a static FP8 `out_proj` on NVIDIA.

## Claims

- Qwen3.8-Flash-Next MXFP4, TP2, MI355X: +0.6% geomean output throughput over the 9 cells of the 8k/1k and 60k/600 ladders, 3 repeats. The gain is at concurrency 4-32 (+0.6 to +1.3%); from 64 up it is within +0.4%.
- Per decode step, 108 launches become 72, and the step's kernel time falls 7.99 → 7.92 ms.
- The kernel is 20-49% faster per layer at M <= 512 and 2-18% at M = 1024-8192 (table in ROCm/aiter#6038).
- GSM8K 5-shot: no change beyond run-to-run noise (exact McNemar p = 0.50, 1.00, 1.00).
- On Flash-Next the gated-norm patterns did not fire in serving before this PR (`Replaced 0 patterns`); with it, a TP2 start logs `Replaced 1 patterns` 12 times across the two ranks.

## Details

**Before.** GDN's `_output_projection` normalizes the core attention output with `RMSNormGated` (per-head RMSNorm times a SiLU or sigmoid gate of `z`), flattens the heads, and calls `out_proj`. With MXFP4 `out_proj` that is `gemm_with_dynamic_quant`: a separate activation-quant kernel, then the GEMM. Since #61278, `AiterMxfp4LinearKernel.use_asm_gemm` is true only when the `a4w4` ASM CSV has the (N, K) and a preshuffled config is tuned. Flash-Next's `out_proj` (N=2560, K=6144/TP) has no ASM rows at any TP, so it runs `dynamic_mxfp4_quant` and the Triton `gemm_afp4wfp4`.

**After.** `AiterRMSNormGatedMxfp4GemmPattern` matches `RMSNormGated → reshape → gemm_with_dynamic_quant` for linears with `use_asm_gemm=False` and lowers it to `rocm_aiter_fused_rms_gated_mxfp4_gemm`. AITER's `fused_rms_gated_mxfp4_quant` writes the activation and its per-1x32 scales column-major (`transpose_scale=True`), as `dynamic_mxfp4_quant` returns them; row-major scales give the same result but `gemm_afp4wfp4` reads them 20-100% slower from M=1024 up. The pattern registers once per (epsilon, heads per rank, head dim, gate activation, output dtype) the GDN layers use, for `norm_before_gate=True`, `group_size=None` and a head dim divisible by 32.

**Matching `flatten(-2)`.** GDN flattens heads with `core_attn_out.flatten(-2)`, which compiles under a dynamic token count to `reshape(x, [s, hidden])` with `s` a graph input. The pattern is traced with `reshape(-1, hidden)`, so it would never match in serving. `reshape_symbolic_dim_to_minus_one` rewrites a reshape with exactly one symbolic size to `-1`, the same op. The pass runs it only when the MXFP4 pattern is registered and hashes it into the pass `uuid`, so FP8 graphs and their cache keys are unchanged.

**`MatcherRMSNormGated`** gains an `activation` argument in `forward_native` (default `swish`, as before), so sigmoid-gated models such as Flash-Next match.

**Limitations and CI gaps.**

- gfx950 only: MXFP4 does not run on gfx942.
- The gain is small: the fused launches save about 1.8% of a decode step's kernel time.
- Serving was measured at TP2. Norm and quant are row-local per head, so TP only changes the head count per rank (48/TP) and K; the AITER PR's kernel table covers TP1, 2, 4 and 8.
- ASM-GEMM linears are not fused.
- The `in_proj_qkvz` activation quant is not covered: on Flash-Next its input comes from the HyperConnection kernel, not from an AR+RMSNorm, so #59483 does not reach it either.
- CI: `compile/passes` runs only in the MI300 job, where the gfx950 cases skip, so the new test ran on MI355X outside CI.
