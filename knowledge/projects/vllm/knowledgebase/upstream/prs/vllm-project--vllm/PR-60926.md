# [Bugfix][Frontend] Expose completion response schemas in OpenAPI

[Upstream PR](https://github.com/vllm-project/vllm/pull/60926) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Expose JSON response and SSE event schemas for chat and legacy completions in `/openapi.json`, using existing Pydantic models and OpenAPI 3.2. Related to #25272; broader client-generator issues are out of scope.

## Claims

- Both endpoints expose distinct unary JSON and SSE contracts with resolvable model references.
- SSE `itemSchema` describes an event envelope whose `data` is a JSON chunk, JSON error, or `[DONE]`. Keep-alive comments are not data events.
- Inference and stream generation are unchanged. Early disconnects now return an explicit empty `Response()` from the shared cancellation wrapper instead of `None`, avoiding response-model validation errors without making successful response schemas nullable.
- Bundled Swagger UI is updated to v5.33.1 so offline docs can load OpenAPI 3.2 documents. Rendering the SSE item schema remains an upstream limitation (see Details).

## Details

Register unary/chunk models with FastAPI; `openapi_extra` restores the unary JSON ref because the additional response model otherwise replaces it. Request structure is unchanged, but FastAPI renames `FunctionCall` to `FunctionCall-Input`; name-dependent consumers may notice.

Set the production app's OpenAPI version to 3.2.0, which defines `itemSchema`. This is a document-version change; no FastAPI dependency bump is needed. The cancellation fix is in the shared decorator and therefore applies to its other callers too; it does not change mid-stream disconnect handling by `StreamingResponse`.

**Swagger UI limitation:** v5.33.1 can load the OpenAPI 3.2 document but does not yet render `itemSchema` for sequential media types properly: [swagger-api/swagger-ui#11065](https://github.com/swagger-api/swagger-ui/issues/11065). The SSE contract is present in `/openapi.json` and exercised by Schemathesis, even though Swagger's response-schema display is incomplete. The bundled upstream assets and license are retained verbatim.

This breaks `test_openapi_stateless`. Schemathesis validates each SSE event envelope (`{"data": "<raw string>", "event": "message"}`) against this schema, so every streaming response fails with `"model" is a required property`.

Use the shape FastAPI emits for SSE routes instead: an `itemSchema` with a required `data` string, and `anyOf` on `data` with `const: "[DONE]"`, a `contentSchema` ref to `ChatCompletionStreamResponse`, and a `contentSchema` ref to `ErrorResponse` for mid-stream errors (`contentMediaType: application/json` on both). The new unit test then reads the ref from `itemSchema`.

- sfeng33 · comment · 2026-10-09T23:44:52Z · [source](https://github.com/vllm-project/vllm/pull/60926#discussion_r4235449344)

File: `vllm/entrypoints/openai/chat_completion/api_router.py` · line None

This turns every client disconnect into a 500. `with_cancellation` returns `None` when the client disconnects before the handler finishes. Today that becomes a 200 with body `null`. With `response_model` set, FastAPI validates `None` against the model, raises `ResponseValidationError`, and the request is logged and counted as a 500.

Smallest fix is to have `with_cancellation` return `Response()` instead of `None`. If you would rather keep it in this file, `response_model=ChatCompletionResponse | None` also works since the `openapi_extra` override hides the `anyOf`.
