# [KVConnector][MoRIIO] Keep the handshake listener alive on bad messages

[Upstream PR](https://github.com/vllm-project/vllm/pull/64756) · state: open · merged: False

## Original PR description

## Overview

Keeps the MoRIIO handshake listener alive when it receives a malformed or unknown message, and makes `shutdown()` actually stop it. Addresses gap 5 of the MoRIIO RAS RFC, [ROCm/mori#759](https://github.com/ROCm/mori/issues/759). The fix mirrors the NIXL listener fix in #26404.

No open PR addresses this gap: the RFC's status table lists it as "No PR". #60743 touches the same function but fixes a different failure (a bind failure at startup), so whichever lands second needs a small rebase.

## Claims

- A malformed message (wrong frame count) or an unknown message type no longer kills the listener thread. It is logged as a one-line warning and dropped, and the worker keeps answering handshakes.
- `MoRIIOConnectorWorker.shutdown()` now stops the listener thread and releases its port, instead of returning immediately while the thread stays blocked in `recv_multipart()`.
- The bytes sent for a valid `GET_META_MSG` are unchanged.

## Validation

**The bug reproduces on main.** Start the listener, send one unknown message, then a valid `GET_META_MSG`:

```
Exception in thread Thread-1 (_moriio_handshake_listener):
    raise HandshakeError("handshake failed, unexpected msg type")
vllm.distributed.kv_transfer.kv_connector.v1.moriio.moriio_common.HandshakeError: handshake failed, unexpected msg type
NO REPLY: listener alive = False
```

```python
import socket, threading, zmq
from vllm.distributed.kv_transfer.kv_connector.v1.moriio.moriio_common import (
    MoRIIOAgentMetadata, MoRIIOConstants, zmq_ctx)
from vllm.distributed.kv_transfer.kv_connector.v1.moriio.moriio_connector import (
    MoRIIOConnectorWorker)
from vllm.utils.network_utils import make_zmq_path

s = socket.socket(); s.bind(("", 0)); port = s.getsockname()[1]; s.close()
md = MoRIIOAgentMetadata(engine_id="p", agent_metadata=b"a", kv_caches_base_addr=[0],
                         num_blocks=1, block_len=1, attn_backend_name="T")
ready = threading.Event()
t = threading.Thread(target=MoRIIOConnectorWorker._moriio_handshake_listener,
                     args=(md, ready, port, 0, 0, {}), daemon=True)
t.start(); ready.wait()
with zmq_ctx(zmq.DEALER, make_zmq_path("tcp", "127.0.0.1", port)) as sock:
    sock.setsockopt(zmq.RCVTIMEO, 5000)
    sock.send(b"not_a_handshake_msg")
    sock.send(MoRIIOConstants.GET_META_MSG)
    try:
        sock.recv_multipart(); print("listener replied")
    except zmq.Again:
        print("NO REPLY: listener alive =", t.is_alive())
```

## Details

**Flow.** Every MoRIIO worker starts `_moriio_handshake_listener` in `register_kv_caches`, on a ZMQ `ROUTER` socket at `side_channel_port` plus its rank offset. A peer that needs this worker's MoRI-IO engine and KV-buffer metadata (D dialing P in READ mode, P dialing D in WRITE mode) does:

1. The peer's `_moriio_handshake` opens a `DEALER` socket and sends `GET_META_MSG`.
2. The listener receives `[identity, GET_META_MSG]` and replies with the engine metadata, then the per-layer tensor metadata.
3. The peer registers the remote engine and starts transfers.

**Root cause.**
- The listener loop was `while True: identity, msg = sock.recv_multipart()`, and it raised `HandshakeError` on an unknown message type. Either a wrong frame count (`ValueError` on unpack) or an unknown type escaped the loop and ended the daemon thread. From then on, step 2 never happens for that worker: new peers block in step 1, since the dialer has no receive timeout (gap 3 of the RFC), and the worker cannot pair with any new peer until restart.
- `shutdown()` called `join(timeout=0)`, which returns immediately. The thread stayed blocked in a receive with no timeout, on a socket from its own `zmq_ctx` context, so `self.zmq_context.destroy()` did not reach it either. The thread and its bound port outlived the connector.

**Fix.**
- The socket gets a 1 s `RCVTIMEO`. The loop runs `while not stop_event.is_set()` and goes round again on `zmq.Again`.
- Message handling moved into `_handle_handshake_msg`. It checks the frame count before unpacking and raises `HandshakeError` for unknown types; the loop catches the error per message and logs a warning naming the port and ranks.
- `shutdown()` sets `self._stop_event`, joins the thread, and clears the reference, so a second call from `__del__` does nothing.
- The tensor metadata is now encoded once, when the listener starts, instead of on every request. This is safe because the dict is only filled in `register_kv_caches` before the thread starts.

**Tradeoffs and limitations.**
- Shutdown can take up to 1 s longer, waiting for the receive timeout. NIXL makes the same trade.
- The warning omits the traceback, so a port scanner or a stray client cannot flood the log.
- The dialing side still waits forever on a listener that never answers. That is gap 3 of the RFC, tracked separately.
- The `POP_DONE_RECV` branch is unchanged, but nothing in the repo sends that message. Removing it is left for a separate cleanup.
