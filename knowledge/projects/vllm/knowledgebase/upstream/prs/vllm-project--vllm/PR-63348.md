# [Docs] Add Qwen3-4B and tidy Qwen entries in batch invariance tested models

[Upstream PR](https://github.com/vllm-project/vllm/pull/63348) · state: closed · merged: True

## Original PR description



## Overview

Add `Qwen/Qwen3-4B` (BF16, dense) to the batch invariance tested models list in `docs/features/batch_invariance.md`, following the model-validation request in #27433.

## Claims

- Validated `Qwen/Qwen3-4B` with `tests/v1/determinism/test_batch_invariance.py` on a single NVIDIA A100 80GB GPU (SM 8.0), TP=1.
- All 22 Qwen3-4B test cases passed, covering `FLASH_ATTN`, `FLEX_ATTENTION`, and `TRITON_ATTN`, including the batch-invariance-off negative controls.

## Validation

**Test command:**

```shell
VLLM_TEST_MODEL=Qwen/Qwen3-4B \
pytest -v -s tests/v1/determinism/test_batch_invariance.py
```

**Environment:**

| Component | Configuration |
| -- | -- |
| Model | Qwen/Qwen3-4B, BF16, unquantized |
| GPU | 1 × NVIDIA A100 80GB PCIe (SM 8.0) |
| Tensor parallelism | TP=1 |
| vLLM | `0.32.1rc1.dev387+gccd4e4030` |
| Python | 3.12.13 |
| PyTorch | 2.14.0+cu130 |
| Triton | 3.8.0 |
| CUDA runtime | 13.0 |

**Test results:**

```text
22 passed, 1 skipped, 24 warnings in 1436.85s (0:23:56)
```

| Coverage | Passed |
| -- | -- |
| Needle generation across batch sizes: 3 backends × default / vllm_c RMSNorm | 6/6 |
| Bitwise logprobs, batch size 1 vs. N: 3 backends × 2 block configurations | 6/6 |
| Ragged chunked prefill: 3 backends | 3/3 |
| Simple generation: 3 backends | 3/3 |
| Batch-invariance-off negative controls: 3 backends | 3/3 |
| Decode vs. prefill logprobs: FLASH_ATTN | 1/1 |

The single skipped test, `test_online_fp8_moe_logprobs_bitwise_bs1_vs_bsN`, uses an independent Granite online FP8 MoE model and requires SM 8.9+. It does not validate Qwen3-4B.

Documentation checks also passed:

```shell
git diff HEAD^ HEAD --check
.venv/bin/pre-commit run --files docs/features/batch_invariance.md
```

The GPU validation was performed outside upstream CI. This PR only records the validated model in the documentation and does not add a CI configuration for Qwen3-4B.

## Details

- Added `Qwen/Qwen3-4B` to the existing Qwen3 (Dense) entry under Tested Models.
- Checked #27433 and open PRs; found no existing PR adding the unquantized `Qwen/Qwen3-4B` model to this list. The related documentation update in #59972 adds other models, including Qwen3-32B, and does not cover Qwen3-4B.
- Maintainer follow-up commit: merged the separate Qwen3-0.6B entry into Qwen3 (Dense), and moved Qwen3 (MoE) above Qwen3-VL so the Qwen3 text models stay together.
- The same commit removes `Qwen/Qwen3-Next-80B-A3B-Instruct`. Its `linear_attention` layers use `GDN_ATTN`, which does not support batch invariance, so startup raises `RuntimeError` under `VLLM_BATCH_INVARIANT=1` (see #42960). This comes from reading the code. The model was not run.
- Claude Code helped with the follow-up commit, which was checked with pre-commit.

This validation covers the default test-suite configurations on a single NVIDIA A100 GPU and does not claim support for all GPU architectures or inference configurations. No inference behavior is changed.
