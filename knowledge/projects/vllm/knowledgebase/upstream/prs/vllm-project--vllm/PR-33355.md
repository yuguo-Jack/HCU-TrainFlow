# [torch.compile] Avoid graph fragmentation in unified_kv_cache_update

[Upstream PR](https://github.com/vllm-project/vllm/pull/33355) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #33267
**Motivation:**

`unified_kv_cache_update` appears in piecewise cudagraph regions. Previously, each layer used a unique name, forcing each to be compiled separately. This increases cold start compilation time with Dynamo partition because the graphs can no longer be reused.

**Changes:**

This PR optimizes `unified_kv_cache_update` to use a generic name (`"from_forward_context"`) during compilation. The actual layer is resolved dynamically at runtime using `ForwardContext` and an index. This allows the compiled graph for the KV cache update operation to be reused across all layers, significantly reducing compilation overhead.

## Test Plan

Added a new integration test `tests/kernels/attention/test_unified_kv_cache_optimization_real.py` 

## Test Result

The integration test passes on GPU, confirming the optimization logic is correct and stable.

## Code Review

This pull request introduces an optimization to avoid graph fragmentation in `unified_kv_cache_update` by using a generic name during compilation and resolving the layer at runtime. This is a good approach to reduce compilation overhead. The changes are well-supported by a new integration test. However, my review found a critical issue: a refactoring related to MoE layers seems to have inadvertently broken MoE functionality by removing a necessary parameter from the `ForwardContext` initialization. I've provided a code suggestion to fix this regression. The rest of the changes for the KV cache update appear correct.
