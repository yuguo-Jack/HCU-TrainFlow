# [Tools] Fix macOS path canonicalization and Bash 3.2 portability in scripts

[Upstream PR](https://github.com/vllm-project/vllm/pull/63303) · state: open · merged: False

## Original PR description



## Overview

Fix macOS path canonicalization and `/tmp` directory cleanup in `docker/entrypoints/test_vllm_nonroot_entrypoint.sh` (used by the `test-nonroot-entrypoint` pre-commit hook) and replace Bash 4+ `${hardware,,}` syntax in `tools/recipes/serve_with_recipe.sh` with POSIX `tr` so both scripts run cleanly on macOS.

## Claims

- Canonicalizes `WORKDIR="$(cd "$(mktemp -d)" && pwd -P)"` in `docker/entrypoints/test_vllm_nonroot_entrypoint.sh` so `case8`–`case10` pass on macOS where `/var` is a symlink to `/private/var`.
- Tracks and cleans up `/tmp/vllm-home.*` fallback directories created by `case2` and `case3` in `docker/entrypoints/test_vllm_nonroot_entrypoint.sh`.
- Replaces Bash 4+ `${hardware,,}` case-conversion parameter expansion in `tools/recipes/serve_with_recipe.sh` with `printf '%s' "$hardware" | tr '[:upper:]' '[:lower:]'` so the script runs under macOS `/bin/bash` (Bash 3.2).

## Validation

- **Reproducer (without fix vs with fix):**
  - Without fix on macOS: `sh docker/entrypoints/test_vllm_nonroot_entrypoint.sh` fails at `case8` (`FAIL: case8: symlink to existing dir -> resolved target (got '/private/var/folders/...', want '/var/folders/...')`), and `/bin/bash tools/recipes/serve_with_recipe.sh` fails with `${hardware,,}: bad substitution` when `--hardware` is passed.
  - With fix: All 11 test cases in `test_vllm_nonroot_entrypoint.sh` pass (`ALL CASES PASSED.`) with zero leaked `/tmp/vllm-home.*` directories, and `serve_with_recipe.sh` lowercases `--hardware` under Bash 3.2.
- **Test commands run:**
  ```bash
  sh docker/entrypoints/test_vllm_nonroot_entrypoint.sh
  .venv/bin/pre-commit run --files docker/entrypoints/test_vllm_nonroot_entrypoint.sh tools/recipes/serve_with_recipe.sh
  ```
- **Results:** `ALL CASES PASSED.` (11/11 cases); `shellcheck` and `test-nonroot-entrypoint` pre-commit hooks passed.
- **Model evaluation:** N/A (entrypoint test script and recipe launcher shell portability only).

## Details

- **Root cause:**
  1. `vllm-nonroot-entrypoint.sh` resolves directory targets using `cd -P ... && pwd` (returning `/private/var/folders/...` on macOS), whereas `mktemp -d` in `test_vllm_nonroot_entrypoint.sh` returned `/var/folders/...` without `-P`. In addition, `case2` and `case3` triggered the entrypoint's `mktemp -d /tmp/vllm-home.XXXXXX` fallback without recording those paths for the `EXIT` trap cleanup.
  2. `${var,,}` was introduced in Bash 4.0 and fails with `bad substitution` under `/bin/bash` on macOS (Bash 3.2).
- **Duplicate-PR check:** Searched open PRs via `gh pr list --repo vllm-project/vllm --state open --search "test_vllm_nonroot_entrypoint.sh OR serve_with_recipe.sh"`; no open PR touches either file.
