# [Feature][AuxOutput] Support routed experts with P/D disaggregation

[Upstream PR](https://github.com/vllm-project/vllm/pull/62056) · state: open · merged: False

## Original PR description

## Purpose

`--enable-return-routed-experts` is rejected with P/D connectors (NIXL, MoRIIO, Mooncake), so RL runs that need routed experts (R3) must serve colocated. A decode instance never computes the remotely prefilled prompt, so it has no rows for it, and its first forward starts mid-block. With this PR a P/D decode request emits rows only from its first local forward (fixed at first schedule, so after any rewind for a failed KV load, and kept across preemption), the worker skips the partially loaded first block, and responses carry `routed_experts_start` so a proxy can prepend the prefill rows (`prefill[:decode_start - prefill_start] + decode`). This supersedes #45419 (warn-only; decode rows stay wrong). RFC #55584 proposes moving rows over NIXL instead; this is the proxy-merge alternative.

## Test Plan

New unit test in `tests/distributed/aux_output_connector/test_store.py` (fails on main). 2-node NIXL 1P1D, Qwen3-30B-A3B, `VLLM_BATCH_INVARIANT=1`: merged P/D rows and tokens identical to a colocated server for 12/12 prompts (64-6000 tokens, incl. block-edge lengths and `routed_experts_prompt_start` > 0) at concurrency 1 and 6, and on a repeat pass with prefix hits.

AI assistance (Claude) was used; all changes were reviewed by the submitter.
