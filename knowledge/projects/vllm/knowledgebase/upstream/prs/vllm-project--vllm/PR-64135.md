# [ROCm][DSv4.1] Native ASM sparse attention for DP deployments

[Upstream PR](https://github.com/vllm-project/vllm/pull/64135) · state: closed · merged: False

## Original PR description

## Overview

Add opt-in native AITER ASM sparse attention for DeepSeek-V4.1-Flash on gfx950 with attention TP1/DP>1. Write native KV directly and fuse query RoPE/FP8 packing; this removes the conversion/mirror overhead of the experimental staging implementation.

## Claims

- One native KV representation serves compressed-cache writes, SWA writes, DSpark context insertion, prefill gathers, and decode.
- Compressed-attention batches with at least 16 decode query rows use ASM. Smaller batches and SWA-only layers use the existing Triton split/reduce with a native-cache reader.
- No end-to-end performance or model-quality improvement is claimed yet. The threshold is provisional pending integrated measurements.

## Validation

MI355X, ROCm, editable local vLLM at base `5d35ce3934`:

```bash
HIP_VISIBLE_DEVICES=5 CUDA_VISIBLE_DEVICES=5 HF_HOME=/data \
  .venv/bin/python -m pytest \
  tests/kernels/attention/test_rocm_triton_attn_dsv4.py \
  -k flash_native_asm -q
# 16 passed: rows 4/8/16/32 x compression ratios 1/2 x padded insertion
```

The padded-insertion regression fails on the prior implementation (an out-of-range query row overwrites a KV row) and passes with the slot-mapping bounds guard. Tests exercise block-strided native caches, compressed-write boundaries, prefill reads, FP32 attention reference comparison, padding output clearing, and graph replay. The MI355X MLA CI mirror includes these cases. Ruff and all applicable pre-commit hooks pass.

**Serving validation:** graph-enabled DPATP2 completed 32/32 long-prefix smoke requests and 128/128 activation requests with full 1024-token graph capture and normal memory planning. A separate c128 smoke completed 256/256 requests with 128 output tokens each and 99.26% repeated-prefix cache hits. GPU traces confirm native ASM and fused gate/router execution on both ranks. These short checks did not establish long-run stability: the first serial, reindex-only, and full-overlap AgentX attempts all failed. No serving-throughput gain is claimed.

Two replay/integration fixes are included:
- PIECEWISE replay rebuilds packed queries inside the eager attention segment using current metadata. The isolated replay reproducer failed before this change and passes afterward.
- Native attention records auxiliary outputs on their consumer stream, covering both compressor and reindex branches. Full overlap stalls without this lifetime tracking; disabling compressor overlap or tracking outputs from both branches allows the serving tests to complete. Tracking only the compressor outputs is insufficient. This was sufficient for those short smoke tests, but longer AgentX runs still failed; neither the exact allocator reuse sequence nor the remaining fault is resolved.

These serving checks used an equivalent worker hook while isolating the lifetime change. The committed source is being validated with the normal worker in a separate GSM8K deployment. All applicable pre-commit hooks pass.

**Long-run status:** all three initial AgentX variants failed after warmup. Reindex-only and full overlap logged `HSA_STATUS_ERROR_MEMORY_FAULT`, followed by stalled execution / `sample_tokens` timeouts; the serial run also produced a GPU core dump. These results are invalid for performance comparison. An eight-step diagnostic torch trace had been stopped before AgentX, but profiler support remained initialized and ROCm logged a changed queue setup. Fresh serial/reindex/full runs remove both `--profiler-config` and the trace step. Fresh reindex-only and full-overlap runs without any profiler configuration reproduced GPU memory-access faults after warmup; removing profiling did not resolve the issue. A standalone kernel test also emits the ROCm queue warning without profiling, so that warning does not establish profiler causality. GPU fault diagnosis and correctness validation remain open.

**Pending:** the three-way 3600-second AgentX comparison, integrated threshold selection, and full-test-set GSM8K with real speculative acceptance on a separate GPU pair. Performance runs retain HF_HOME=/data, DSpark x5/synthetic AL3.51, prefix-affinity routing, and the prefill delayer. Synthetic acceptance is not quality evidence. The serial workaround's performance drawback and follow-up are recorded in https://github.com/vllm-project/vllm/pull/64135#issuecomment-6454910515; the submitted lifetime fix preserves overlap.

## Details

The 512-byte NoPE/scales records share a block-outermost backing allocation; a BF16 RoPE side pool uses the same physical row IDs. Reserve one fifth of the available KV allocation budget for the side pool. There is no legacy-cache mirror. Compression ratios 1/2 and Flash's shared compressed-cache ownership are preserved. Flash does not apply Pro's post-projection Q RMSNorm, so query preparation retains Flash's existing math before the new FP8 query quantization.

`VLLM_ROCM_USE_AITER_ASM_SPARSE_MLA=1` is disabled by default. The initial supported scope is MRV2, gfx950, 64 local heads, attention TP1/DP>1, `fp8_ds_mla`, with no monokernel, PCP, KV connector, or KV offloading. Engram CPU offload remains supported. Native layout increases KV storage compared with the legacy 584-byte record; prefix-cache residency must be measured. Prefill currently uses dequantize/gather plus sparse attention rather than AITER's legacy-cache reader.

Duplicate-work check: #61826 implements the related **DeepSeek V4 Pro** native layout, and closed #63634 explored that Pro stack. This draft adapts the layout concept to **V4.1 Flash**, including its ratio-1/2 compression, KV sharing, distinct query preparation, and BF16 small-batch fallback; it does not duplicate or replace the Pro integration. Open-PR searches for Flash ASM and #61826 references found no existing Flash port. Native-layout design and AITER integration are credited to #61826; this draft should be reconciled with it if both advance.

- Fangzhou-Ai · comment · 2026-10-27T22:13:42Z · [source](https://github.com/vllm-project/vllm/pull/64135#issuecomment-6454910515)

Known drawback / follow-up: native ASM currently needs a workaround for attention overlap in the Flash integration. Disabling attention's auxiliary streams makes graph-enabled serving complete, but can reduce performance by serializing query preparation and compressor work. This is a temporary workaround, not the desired final integration.

Isolation on MI355X with all three optimizations enabled (native ASM, grouped indexer, fused gate/router):
- All attention overlap disabled: 32/32 long-prefix smoke requests pass; a larger c128 smoke passes 256/256 requests with 128 output tokens each and 99.25% repeated-prefix cache hits.
- Reindex-layer overlap enabled, compressor-layer overlap disabled: 32/32 smoke requests pass; larger validation and a production DPATP2 c128 AgentX run are being prepared.
- Compressor-layer overlap enabled: stalls waiting for GPU completion. Graph debug mode alone and external event markers alone also fail to prevent the stall.

The issue is narrowed to the compressor-side overlap path, but the precise dependency or buffer-lifetime fault is not yet proven. Follow-up is to fix that path and restore safe overlap, then measure the difference against serial attention. Do not infer an end-to-end speedup from the kernel microbenchmarks or these smoke tests.

A separate packed-query replay-state bug has a local fix: PIECEWISE replay must rebuild the packed query using the current attention metadata inside the eager attention segment. That fix alone did not resolve the stall.

Production comparison retains HF_HOME=/data, prefix-affinity routing, prefill delayer, DSpark x5 with synthetic AL3.51, and full 1024-token graph capture. Performance will be reported as total input+output throughput and interactivity. Synthetic-acceptance smoke tests are not model-quality evidence.
