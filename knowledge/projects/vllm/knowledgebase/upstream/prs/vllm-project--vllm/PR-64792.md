# [Docs][ROCm] Mistral Large 4 recipe: adds TP4 and lowest-latency presets 

[Upstream PR](https://github.com/vllm-project/vllm/pull/64792) · state: closed · merged: True

## Original PR description

## Purpose

Adds TP4 and lowest-latency (specialized decode) presets to the Mistral Large 4 recipe, so MI350X and MI355X both offer them for the FP8 and Quark MXFP4 checkpoints. Also fixes the AMD `docker run` command.

New presets:
- MI350X, MXFP4 (Quark): `mi350x_mxfp4_tp4`, `mi350x_mxfp4_tp4_specialized`
- MI355X, FP8: `mi355x_tp4`, `mi355x_tp4_specialized`
- MI355X, MXFP4 (Quark): `mi355x_mxfp4_tp4`, `mi355x_mxfp4_tp4_specialized`

TP4 is the baseline at `--tensor-parallel-size 4` with DSpark. Lowest latency adds `--additional-config '{"decode_backend":"latency_specialized"}'`. FP8 also sets `VLLM_FP8_MOE_REQUANT_ACT=a4w4`. Quark sets no requant variables, because its routed experts are already MXFP4 a4w4. The MI355X specialized presets keep the baseline's `--max-num-seqs 128`. The MI350X Quark one sets `--max-num-seqs 64` to match the existing MI350X FP8 preset.

**AMD `docker run` fix.** `vllm/vllm-openai-rocm:mistral-large-4` has no entrypoint. Setting `docker_serve_command: "vllm serve"` for mi350x and mi355x renders `<image> vllm serve <model> …`.

## Test Result

All checks passed.
| MI355X preset | c1 TPOT p50 | c4 TPOT p50 | AL (c1 / c4) | KV cache per replica |
|---|---:|---:|---:|---:|
| FP8 TP4 (a8w4) | 3.75 ms | 6.26 ms | 2.91 / 3.03 | 2.18M tokens |
| FP8 specialized decode (a4w4) | 3.56 ms | 6.14 ms | 2.85 / 2.99 | 2.09M tokens |
| Quark TP4 | 3.85 ms | 6.05 ms | 2.88 / 3.03 | 2.19M tokens |
| Quark specialized decode | 3.60 ms | 6.03 ms | 2.86 / 3.03 | 2.09M tokens |

- Specialized decode vs TP4 + DSpark: 1.05x (FP8) and 1.07x (Quark) at c1, about 1.0x at c4. One DSpark verify step at 8k input (c1) takes 12.4 ms vs 13.6 ms (FP8) and 12.4 ms vs 13.0 ms (Quark).
- `--max-num-seqs`: every setting started and served with `AITER_CUSTOM_AR_MAX_SIZE` applied on all ranks, and none hit the "cannot be IPC-exported" abort. The custom all-reduce pool was allocated with expandable segments off. 64 and 128 gave the same TPOT (c1 3.64 vs 3.60 ms).
- `--monokernel` selects the same specialized decode as `--additional-config '{"decode_backend":"latency_specialized"}'` (identical log lines). The Quark model card's command passed.
