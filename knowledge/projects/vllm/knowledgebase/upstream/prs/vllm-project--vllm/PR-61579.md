# [KV Connector][2/N] KV checksums across TP replicas and block sizes

[Upstream PR](https://github.com/vllm-project/vllm/pull/61579) · state: open · merged: False

## Original PR description

## Overview

Part 2 of the KV checksum series: compare KV caches whose producer and consumer lay them out differently. This covers KV heads replicated across TP ranks and different producer and consumer block sizes.

Depends on #61578 (1/N). Only the last two commits are new in this PR, starting at "KV checksums: KV heads replicated across TP". The full series and its validation are in #61488.

Not a duplicate: this extends the series; no other open PR checksums P/D transfers.

## Claims

- **KV heads several TP ranks hold** are now checksummed instead of skipped. This covers MLA-type caches, GQA with more TP ranks than KV heads, and layers with several caches such as an attention's KV plus its indexer's (MiniMax-M3).
  - The producer counts each head once.
  - The consumer checks every copy separately, so a corrupted copy on any rank is caught.
- **Different producer and consumer block sizes** are now compared instead of reported unverified. Checksums of consecutive blocks add up to those of the larger block that holds the same tokens, so the comparison regroups them. The checksum values and the wire format do not change.

## Details

Two commits:
1. **Replicas.**
   - For layers replicated R times, the consumer adds copy k mod R to its check k. Each check therefore covers every layer once, every copy lands in some check, and every check must equal the producer's value, which sums copy 0 only.
   - MLA-type caches without `max_tp_shards` are treated as replicated, matching how NIXL classifies them.
   - MiniMax-M3's indexer cache declares `max_tp_shards=1`.
2. **Block sizes.** The consumer's scheduler sums the smaller blocks into chunks of the larger block size on both sides and compares the chunks.

Limitations:
- Block sizes that are not multiples of each other are unverified.
- So is a consumer with smaller blocks whose first loaded block starts inside a producer block, after a local prefix hit not aligned to the producer's blocks. Fail-closed recomputes such loads. This can occur only with larger producer blocks, as NIXL push and Mooncake P2P allow; NIXL pull requires the consumer's block size to be a multiple of the producer's.
