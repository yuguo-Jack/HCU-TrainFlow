# [Bugfix][KV Offload] Emit scoped invalidation on primary reset

[Upstream PR](https://github.com/vllm-project/vllm/pull/62394) · state: open · merged: False

## Original PR description



## Overview

Follow-up to [#59855](https://github.com/vllm-project/vllm/pull/59855), which this PR depends on. This change fixes stale KV offload events published after a CPU primary reset by adding a scoped invalidation event and clearing queued CPU raw events.

This is intentionally separate from #59855: #59855 fixes pending-write cleanup, while this PR fixes reset-time KV event inventory invalidation.

## Claims

- Add `OffloadingBlocksCleared` to the KV event schema for scoped offloading invalidation.
- Emit `OffloadingBlocksCleared(medium="CPU")` when the CPU primary residency is reset.
- Discard queued CPU raw events created before reset so stale `BlockStored` events are not published.
- Preserve metadata for secondary residency that is already registered, including `STORAGE`.
- Publish the clear event before events generated after reset.
- Keep the existing global `AllBlocksCleared` behavior unchanged.
- Document the four KV event definitions and the CPU scoped reset behavior.

## Details

Before this change, a CPU `BlockStored` event could remain queued while `reset_cache()` cleared the tracker metadata. The event was then published after reset with metadata that no longer described valid CPU residency, or as a placeholder with `block_size=0`.

The reset path now clears queued CPU raw events, removes only CPU primary residency from the event tracker, and queues a scoped `OffloadingBlocksCleared` control event. Secondary residency remains available across this primary reset, and the control event is emitted before post-reset events.

`AllBlocksCleared` remains a separate global invalidation for the GPU prefix cache. `OffloadingBlocksCleared` identifies the invalidated offloading medium and does not imply that other tiers such as `STORAGE` were cleared.

This PR does not implement inventory-first buffering or the follow-up fix for secondary store metadata that can complete during reset before the tracker consumes the corresponding event. That follow-up should be handled separately after this PR.
