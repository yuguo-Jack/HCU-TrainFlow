## Overview

Guard fused GDN dispatch when the compiled kernel image is unavailable for the active device. This Draft is a defensive follow-up to #53835; refreshed against main `c5f8adc0`.

## Claims

- Keep the device-scoped kernel-availability probe and Triton fallback decision.
- Move declarations/registrations into current `csrc/ops.h` and `csrc/torch_bindings.cpp`, retaining the upstream removal of the former libtorch_stable binding files.

## Validation

- `.venv/bin/python -m pytest tests/kernels/mamba/test_gdn_fused_mtp.py -k falls_back_without_kernel_image -v` — **module skipped; no tests executed** because CUDA is unavailable (pytest exits 5).
- Pre-commit on all six changed files, including clang-format/mypy/test tethering, and `git diff --check origin/main...HEAD` — **passed**.
- No supported-toolkit incremental build or kernel/model evaluation ran: installed nvcc is 12.1, installed torch targets CUDA 13.0, and the driver cannot initialize CUDA. This remains Draft pending hardware/build validation.

## Details

The original SM110 build gap is already fixed by merged #53835 and #56206 is closed. This PR does not claim to fix that issue's reported prefill illegal memory access; its scope is a defensive missing-kernel-image fallback for builds/devices that lack the required cubin.

Duplicate check: re-read #56206 and current GDN dispatch/build code and searched open PRs by issue number and kernel availability. #53835 adds architecture coverage rather than this runtime guard. The migration does not add new kernels or alter attention math.

Open since 2026-09-12. AI assistance was used for the refresh; commits are signed and signed off with Codex attribution. Human review and current-head compile/GPU validation are still required.
