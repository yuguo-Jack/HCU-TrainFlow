# [CI] Import the merge-base commit's image cache in PR builds

[Upstream PR](https://github.com/vllm-project/vllm/pull/64387) · state: closed · merged: True

## Original PR description



## Overview

PR builds of the CUDA test image now import the image cache of the commit the PR branched from, so PRs based on an older main stop recompiling every kernel. Needs vllm-project/ci-infra#863, which adds the cache source in `ci.hcl`.

## Claims

- ~13 min off the ~28% of PR image builds that recompile csrc today (PR image p90 ~32 → ~17 min, estimated).
- No change for main or non-PR builds.

## Validation

- On a checkout 5 commits behind main, the new function exports exactly that branch-point commit; on a non-PR build it exports nothing.
- `docker buildx bake -f docker/docker-bake.hcl -f <ci.hcl from ci-infra#863> --print test-ci` lists `vllm-ci-test-cache:<merge-base>` as a cache source.
- `vllm-ci-test-cache:<commit>` tags exist in ECR for recent main commits (7-day lifecycle).
- pre-commit (shellcheck) passes. The real effect will show on this PR's own image build once ci-infra#863 is merged.

## Details

Root cause: a PR imports cache only from `pr-<N>`, `postmerge-cache:latest` and `test-cache:<HEAD~1>`, and `HEAD~1` usually has no tag. If csrc changed on main after the PR branched, `COPY csrc` misses and all kernels rebuild (sampled 29-min PR builds mostly touched no csrc/cmake/setup.py).

The commit goes in a new variable, `VLLM_CACHE_MERGE_BASE_COMMIT`, not `VLLM_MERGE_BASE_COMMIT`: the latter is a Dockerfile build arg, and changing it changes the cache key. The lookup mirrors the merge-base logic in `ci-bake-rocm.sh` (shallow fetch of the base branch, deepen once if needed) and skips the source if no merge base is found. Limitation: PRs branched more than 7 days ago fall back to today's behavior.
