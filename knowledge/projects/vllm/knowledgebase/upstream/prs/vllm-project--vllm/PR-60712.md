# [Mooncake] Allow Mamba cache mode `none` for capacity-only workers

[Upstream PR](https://github.com/vllm-project/vllm/pull/60712) · state: open · merged: False

## Original PR description

Allow Mooncake capacity-only consumers to use Mamba cache mode `none`, which is selected when prefix caching is disabled.

Disabling prefix caching is required for Kimi K3 TP8 + DEP16 disaggregated serving because heterogeneous physical blocks per logical KV block are not supported with prefix caching for Mamba hybrid models. Otherwise, this configuration triggers the [runtime error](https://github.com/vllm-project/vllm/blob/d766ac98285bf1a84acfeb37c99c73d5396d4df6/vllm/distributed/kv_transfer/kv_connector/v1/nixl/base_worker.py#L2542):
```
        if (
            self._has_mamba
            and remote_physical_per_logical
            != self._physical_blocks_per_logical_kv_block
            and self.vllm_config.cache_config.enable_prefix_caching
        ):
            raise RuntimeError(
                "Prefix caching with heterogeneous physical_blocks_per_logical "
                "is not supported for Mamba hybrid models. "
                f"Local: {self._physical_blocks_per_logical_kv_block}, "
                f"Remote: {remote_physical_per_logical}. "
                "Disable prefix caching with --no-enable-prefix-caching."
            )
```
