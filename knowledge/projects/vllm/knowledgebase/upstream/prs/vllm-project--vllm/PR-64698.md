# [Doc] Clarify --base-url must not include /v1 suffix in benchmark CLI

[Upstream PR](https://github.com/vllm-project/vllm/pull/64698) · state: open · merged: False

## Original PR description

## Overview

Adds a short note to the Online Benchmark example in `docs/benchmarking/cli.md`: `--base-url` must point at the server root **without** a `/v1` suffix, otherwise every request 404s.

## Claims

- Documentation-only change (7 lines); no code touched.
- Documents a currently-undocumented footgun: `--base-url http://localhost:8000/v1` makes the tool resolve paths like `/v1/v1/completions`, so all requests fail with `404 Not Found` and the benchmark reports zero successful requests.

## Validation

Reproduced on vLLM 0.32.0 (WSL2, single GPU) against a running `vllm serve`:

```bash
# server running on 127.0.0.1:8000
vllm bench serve --backend openai --base-url http://127.0.0.1:8000/v1 \
  --model <served-name> --tokenizer <path> --dataset-name random \
  --num-prompts 4 --request-rate inf --max-concurrency 2
# → Successful requests: 0, Failed requests: 4 (all "Not Found")

# same command with --base-url http://127.0.0.1:8000 → runs normally
```

Direct `curl` to both `/v1/completions` and `/v1/chat/completions` on the same server returns 200, confirming the 404s come from the doubled prefix, not the server.

## Details

`vllm bench serve` appends the API routes itself, so a base URL that already ends in `/v1` duplicates the prefix. Nothing in the current benchmarking docs mentions this (the examples use default host/port and never show `--base-url`). Kept as a `!!! note` next to the first `vllm bench serve` example, matching the file's existing admonition style.
