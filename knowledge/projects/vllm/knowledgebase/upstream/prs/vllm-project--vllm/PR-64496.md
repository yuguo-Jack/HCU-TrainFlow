# [Bugfix][MRV2] Use IEEE tl.div_rn for temperature and repetition-penalty division in Model Runner V2

[Upstream PR](https://github.com/vllm-project/vllm/pull/64496) · state: open · merged: False

## Original PR description

## Overview

In Model Runner V2 (`vllm/v1/worker/gpu/sample/gumbel.py`, `vllm/v1/worker/gpu/sample/penalties.py`, `vllm/v1/worker/gpu/spec_decode/rejection_sampler_utils.py`, and `vllm/v1/worker/gpu/spec_decode/acceptance_estimator.py`), temperature scaling (`logits / temperature`) uses Triton's `/` operator on `tl.float32` tensors, and positive-logit repetition-penalty scaling (`logits *= tl.where(logits > 0, 1.0 / scale, scale)` in `_penalties_kernel`) multiplies by the approximate reciprocal `1.0 / scale`. On CUDA, Triton lowers `tl.float32` `/` to PTX `div.full.f32` (an approximate hardware division with up to 2 ULP error) instead of IEEE-754 round-to-nearest-even `div.rn.f32`.

By contrast, Model Runner V1 (`vllm/v1/sample/sampler.py:300` via PyTorch `logits.div_(temp.unsqueeze(dim=1))` and `csrc/sampler.cu:40` via CUDA `/` in `_custom_ops.apply_repetition_penalties_cuda`) and the MRV2 watermark sampler (`vllm/v1/worker/gpu/sample/watermark.py:536,664` via `tl.div_rn`) use IEEE-754 round-to-nearest-even division:
- Across the `6,658` `bfloat16` values with $2^{-20} \le |x| \le 64$, `div.full.f32` differs from `div.rn.f32` on `936 / 6,658` (`14.1%`) values at `T = 0.6`, `676 / 6,658` (`10.2%`) at `T = 0.7`, and `1,768 / 6,658` (`26.6%`) at `T = 0.9` (each by 1 `float32` ULP; and on `29,510 / 34,049` = `86.7%` of the finite `bfloat16` values in `[-64, 64]` at `T = 1.83`, by up to 2 `float32` ULPs).
- Across the `3,329` positive `bfloat16` values in that set under `repetition_penalty`, `logits * (1.0 / scale)` differs from `tl.div_rn(logits, scale)` on `598 / 3,329` (`18.0%`) values at `r = 1.1`, `468 / 3,329` (`14.1%`) at `r = 1.2`, and `780 / 3,329` (`23.4%`) at `r = 1.3`.

**History & non-duplication check (`AGENTS.md`):** PR `#29276` (`3e1ad40655`, comment `"Use div_rn to match the behavior of torch"`) originally introduced `tl.div_rn` in `gumbel_sample`, and PR `#29720` (`f223ed4181`) replaced it with `/` without a stated reason. Searched open issues and PRs in `vllm-project/vllm` for `div_rn`, `div.full`, `apply_temperature`, `_temperature_kernel`, `_penalties_kernel`, `gumbel_noised`, `rejection_sampler_utils`, and `acceptance_estimator`; no existing issue or PR reports or fixes this defect. Related open PRs:
- `#54417` adds `_temperature_softmax_kernel`, `_temperature_softmax_partial_kernel` and `_temperature_softmax_combine_kernel` in `vllm/v1/worker/gpu/sample/gumbel.py` dividing with `x.to(tl.float32) / denom`, which would also need `tl.div_rn` to stay bit-exact with `_temperature_kernel`.
- `#61344` fuses temperature scaling into the rejection-sampling kernels in `vllm/v1/worker/gpu/spec_decode/rejection_sampler_utils.py`, adding `target_logit / temp` divisions that would also need `tl.div_rn`.
- `#64033` renames `gumbel_noised_argmax` to `gumbel_noised_logits` in `vllm/v1/worker/gpu/sample/gumbel.py` and merges cleanly with this PR.

**AI assistance disclosure:** AI assistance (Antigravity / Gemini) was used during the investigation, test authoring, and preparation of this PR.

## Claims

- Replaces `logits = logits / temperature` with `tl.div_rn(logits, temperature)` in `_temperature_kernel` (`gumbel.py:44`) and `logits / temp` with `tl.div_rn(logits, temp)` in `gumbel_noised_argmax` (`gumbel.py:192`), guarding `gumbel_noised_argmax` with `if logits.dtype == tl.float64: logits = logits / temp else: logits = tl.div_rn(logits, temp)` so `tl.float64` callers (`_selector_walk_kernel` in DFlash2/LiLiCorr) continue to use `div.rn.f64`.
- Replaces `logits *= tl.where(logits > 0, 1.0 / scale, scale)` with `logits = tl.where(logits > 0, tl.div_rn(logits, scale), logits * scale)` in `_penalties_kernel` (`penalties.py:177`), matching V1's CUDA `_custom_ops.apply_repetition_penalties_cuda` op bit-for-bit.
- Replaces `/ temp` with `tl.div_rn(..., temp)` at the 4 speculative-decoding draft-logit loads in `vllm/v1/worker/gpu/spec_decode/rejection_sampler_utils.py` (`L182`, `L311`, `L933`) and `vllm/v1/worker/gpu/spec_decode/acceptance_estimator.py` (`L210`), restoring the invariant documented at `gumbel.py:246-249`.
- Adds `test_apply_temperature_and_penalties_ieee_rounding` in `tests/v1/worker/test_gpu_gumbel_sample.py`.

out = logits.float()

## Details

File:line references above are at `65faf4efa`. On current `main` (`16777da3` / `34091a07`, after `#64356` and `#64013`), the rebased patch has identical changed lines, the shifted line numbers are `penalties.py:178`, `rejection_sampler_utils.py` L187/L318/L943, and `gumbel.py:245-248`, and the 13-file test command gives 344 -> 345 passed.

1. **Performance (`H100`, `float32` logits `[128, 152064]`, `T = 0.7`, `repetition_penalty = 1.1` with every token penalised, median of 200 CUDA-event timings across 2 runs per state):**
   - `apply_temperature`: `56.8-56.9 us` before vs `60.2-60.3 us` after (`+6%`)
   - `apply_penalties`: `91.9 us` before vs `111.4-111.5 us` after (`+21%`)
   - `gumbel_sample` (`apply_temperature=True`): `122.7-122.8 us` before vs `125.9-127.5 us` after (`+3-4%`)
   - `gumbel_sample` (`apply_temperature=False`): `~119 us` before vs `~119 us` after (unchanged)
   - (Timings for the speculative-decoding kernels and ROCm/XPU were not measured.)
2. **`tl.float64` callers of `gumbel_noised_argmax`:** `tl.div_rn` is restricted to `fp32` by Triton's `@_check_dtype(dtypes=["fp32"])` (`triton/language/math.py:204`), whereas `/` on `tl.float64` already lowers to `div.rn.f64`. Guarding `if logits.dtype == tl.float64:` keeps `_selector_walk_kernel`'s `fp64` path working unchanged.
