# fix(evs): fix M-RoPE positions for chunks that start inside a video placeholder

[Upstream PR](https://github.com/vllm-project/vllm/pull/62997) · state: closed · merged: False

## Original PR description

## Summary of Changes
Fixed incorrect M-RoPE positions when chunked prefill splits a video placeholder (5-channel EVS path) inside the placeholder. The issue was that `recompute_mrope_positions()` didn't receive the placeholder offset and start_idx from the caller, causing wrong anchor calculations and write offsets.

## Motivation & Context
Closes #62969

The bug occurred with `--video-pruning-rate` on models using the 5-channel EVS path (Qwen3-VL and subclasses). When chunked prefill splits a video placeholder inside the placeholder, the function wrote wrong M-RoPE positions. This affected tokens of the chunk that starts mid-video, text tokens after the video, and the `mrope_position_delta` which shifts every decoded token.

## Verification
The fix has been verified with the reproduction script provided in the issue. It correctly handles all 2-chunk split scenarios inside video placeholders for both layouts (with and without outer markers). The fix ensures that placeholder token `j` gets the correct `mm_pos[:, j] + (position of the token before the placeholder) + 1` regardless of chunk boundaries.
