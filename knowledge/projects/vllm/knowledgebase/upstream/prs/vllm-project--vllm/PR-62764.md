# [Model][Quantization] Add BitNet b1.58 support

[Upstream PR](https://github.com/vllm-project/vllm/pull/62764) · state: closed · merged: False

## Original PR description



## Overview

Adds native support for BitNet b1.58 ternary checkpoints (`quant_method: "bitnet"`): a `bitnet` quantization method plus the `BitNetForCausalLM` architecture ([BitNet b1.58 2B4T](https://arxiv.org/abs/2504.12285)). Addresses #17279, #18213 and the BitNet part of #33142.

## Claims

- `vllm serve microsoft/bitnet-b1.58-2B-4T` works out of the box (no `--quantization` flag), with torch.compile + CUDA graphs.
- `quant_method: "bitnet"` checkpoints on existing architectures also load, e.g. `tiiuae/Falcon3-*-1.58bit` and `HF1BitLLM/Llama3-8B-1.58-100B-tokens` (`LlamaForCausalLM`).
- No new kernels: ternary weights are unpacked to int8 at load and run through the existing int8 W8A8 scaled-mm kernels (CUTLASS on CUDA; Triton/CPU via the existing kernel selection) with dynamic per-token int8 activations — the same math BitNet uses.
- Weight memory is ~2x smaller than bf16 (2B4T: 2.57 GiB).

## Validation

All on 1x A100-SXM4-40GB, torch 2.14 / CUDA 13.0.

**HF parity** — `pytest tests/models/quantization/test_bitnet.py -v` → 3 passed. Greedy logprobs (16 tokens, top-5) match the Transformers reference for both scale conventions:

| Checkpoint | Arch / linear class | Result |
|---|---|---|
| `microsoft/bitnet-b1.58-2B-4T` | `BitNetForCausalLM` / `AutoBitLinear` | pass |
| `tiiuae/Falcon3-1B-Instruct-1.58bit` | `LlamaForCausalLM` / `BitLinear` | pass |

Plus a CPU unit test that `unpack_ternary_weight` inverts `transformers.integrations.bitnet.pack_weights`.

**GSM8K** (`vllm serve <model>` then `python tests/evals/gsm8k/gsm8k_eval.py --port 8000`, 5-shot, 1319 questions):

| Model | Accuracy | Invalid |
|---|---|---|
| `microsoft/bitnet-b1.58-2B-4T` | 0.648 | 0.001 |
| `tiiuae/Falcon3-1B-Instruct-1.58bit` | 0.269 | 0.001 |

**Throughput** — `vllm bench throughput --model microsoft/bitnet-b1.58-2B-4T --input-len 512 --output-len 256 --num-prompts 500`: 32.92 req/s, 37,922 total tok/s, 4,214 output tok/s.

**Serving smoke test** — chat completions return coherent answers (e.g. "What is 17 * 23?" → `391`).

**`HF1BitLLM/Llama3-8B-1.58-100B-tokens`** — serves (8.46 GiB weights); layer-5 qkv / gate_up / down outputs match HF at cosine ≥ 0.99999 and first-token top-5 candidates agree, but greedy continuations drift after a few tokens: the model's next-token distribution is very flat (top-1 ≈ 13%) and HF's `BitLinear` does the int8 × ternary matmul in bf16, so it is not added as a parity test.

**No host syncs** — `VLLM_GPU_SYNC_CHECK=error` generation on bitnet-b1.58-2B-4T completes cleanly.

**Regression** — `tests/models/test_registry.py` + `tests/quantization/test_register_quantization_config.py`: 427 passed, 1 failed (`test_custom_quant[meta-llama/Llama-3.2-1B-Instruct]`: gated-repo 401 on the test box, fails identically on the base commit). `tests/models/test_initialization.py -k BitNet`: passed. `pre-commit` clean.

New tests run in the existing "Quantized Models" Buildkite step (`pytest -v -s models/quantization`).

## Details

- **Packing:** HF packs 4 ternary values per uint8 along the *output* dim in blocks (`packed[r]` holds rows `r, r+N/4, r+N/2, r+3N/4`), so packed rows can't be TP-sliced directly. The weight loader unpacks the full tensor first, then hands it to the normal (merged/QKV/row-parallel) loader.
- **Scales:** `BitLinear` stores `1/mean|W|` (output divided), `AutoBitLinear` stores `mean|W|` (output multiplied); the per-tensor scale is inverted at load for `BitLinear`, and fused QKV / gate-up scales become per-channel via the existing kernel path.
- **Model:** Llama + ReLU² gated MLP + SubLN (`attn_sub_norm` before `o_proj`, `ffn_sub_norm` before `down_proj`). Reuses `LlamaAttention` / `LlamaForCausalLM`; the decoder layer is re-declared because `LlamaDecoderLayer` hard-codes the SiLU `LlamaMLP`. Sub-norms use the existing `TPAwareRMSNorm` (all-gather under TP>1).
- The MLP computes `relu(gate)**2 * up` natively (fused by torch.compile) rather than via `ReLUSquaredActivation`: its CUDA op silently returns wrong results on non-contiguous input such as `gate_up.chunk(2)[0]` (found while validating; existing callers pass contiguous tensors, so it is not fixed here).
- **Limitations:** only pre-quantized (`quantization_mode: "offline"`) checkpoints; online mode (bf16 master weights) raises a clear error. TP>1 and ROCm were not validated (single A100 available); `bitnet` is not added to ROCm's `supported_quantization`. The bitnet-b1.58-2B-4T `config.json` has a stale `auto_map` to non-existent remote code — load it without `--trust-remote-code` (Transformers supports `bitnet` natively).
- Weights are stored as int8 (2 bits/value would need a dedicated kernel, e.g. a follow-up via humming's `BitnetWeightSchema`, already usable with `--quantization humming`).
- **Not a duplicate:** #52195 is a CPU-only reference backend that ternarizes non-BitNet models online; #40088 is a stale draft (merge conflicts since June, includes scratch files, review notes its quantization path is broken). This PR serves the actual released BitNet checkpoints on GPU via existing kernels.
