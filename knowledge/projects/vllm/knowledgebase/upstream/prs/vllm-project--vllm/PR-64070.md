# [Recipe] Qwen3.5: keep configuration-specific content out of the guides

[Upstream PR](https://github.com/vllm-project/vllm/pull/64070) · state: open · merged: False

## Original PR description



## Overview

Fixes the Qwen3.5 part of vllm-project/recipes#1156. On recipes.vllm.ai the command builder renders the selected hardware and variant. The guide below it is the same static text for every selection, yet the Qwen3.5 guides held commands for a single configuration:
- a "Docker" section that was only the Intel XPU image;
- launch commands for one GPU and checkpoint;
- a client example whose `model` only the BF16 variant serves.

Readers could not tell which instructions applied to them.

This keeps the guides to what holds for every configuration. Content that is specific to a configuration moves to `notes` and `troubleshooting`, which the builder filters by the current selection.

It also fixes Qwen3.5-4B and Qwen3.5-35B-A3B, whose builder offered no NVIDIA or AMD GPU at all.

## Claims

**Guides (all eight Qwen3.5 recipes)**

- **Removed:** the install, `docker`, and `vllm serve` blocks. The builder renders each of them for the selected configuration.
- **Kept:**
  - hardware sizing;
  - AMD measurements and explanations;
  - the MXFP4 section;
  - long context;
  - references.
- **Converted to a table:** 397B's per-workload configurations (workload, hardware, checkpoint, parallelism, other settings). Each row now names the hardware it was verified on.
- **Client examples:** they read the served name from `/v1/models` (`client.models.list().data[0].id`), so they work for every variant. This includes the Ascend variants, which set `--served-model-name qwen3.5`.
- **Thinking toggle:** the hint now sits with the client example, both per request (`chat_template_kwargs`) and per server.

**Notes and troubleshooting**

- **Notes** (shown only for a matching selection):
  - Arc Pro validation settings, including `--max-model-len 8192`, for 9B, 27B and 35B-A3B;
  - "MTP on ROCm: use an FP8 KV cache" for 397B.
- **Troubleshooting:**
  - the Mamba cache assert, on NVIDIA and AMD;
  - experimental prefix caching;
  - the CPU startup timeout (35B-A3B);
  - Encoder Parallel memory (397B).

**4B and 35B-A3B hardware**

- **The bug:** vllm-project/recipes#1029 set each variant's `supported_hardware` from the recipe's `verified` hardware, which was Xeon 6 and Arc Pro only. `supported_hardware` is an allowlist, so every other GPU was locked out of these pages, and the default page opened on Arc Pro B60.
- **The fix:**
  - BF16 has no allowlist again, so it runs everywhere. Xeon 6 and Arc remain because `meta.hardware` declares them.
  - The quantized variants list `arch:sm90/sm100/sm103/gfx942/gfx950` plus the Arc Pro ids. They still exclude Xeon, which is what #1029 wanted.

## Validation

- **Renderer check:** `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` passes against recipes main. `test-schema`, `test-guide-html`, `test-context` and `test-overlay` pass.
- **Rendered commands:** built against recipes main before and after this change and compared every JSON rendering (`command`, `argv`, `env`, `docker_command`, `worker_commands`).
  - No existing per-hardware rendering changed.
  - The changes are additions: 380 new renderings (NVIDIA and AMD for 4B and 35B-A3B, plus their promoted variants).
  - The default-hardware files of 35B-A3B moved from Arc Pro B60 to H200.
  - Xeon 6 still renders only the BF16 variant.
- **Builder:** checked locally.
  - 9B on Arc Pro B60 shows the validation note.
  - The 397B guide renders the configuration table and the MXFP4 section.
- **vllm-ascend overlay:** the 397B overlay carries no guide sections, so the guide edit doesn't change it.

## Details

- **Overlap with #63881.** That PR rewrites the 35B-A3B CPU install block that this PR deletes. Whichever merges second needs a trivial rebase. Otherwise #63881 can drop its `Qwen3.5-35B-A3B.yaml` hunk.
- **Removed outright:**
  - the 397B AMD pip note (Python 3.12, ROCm 7.0, glibc ≥ 2.35);
  - its "use `cu130-nightly` on Blackwell" line.

  The builder's install block covers both, and both had gone stale.
- **Not in this PR:** the same `supported_hardware` pattern from #1029 in the other recipes it touched (Gemma 4, Llama, Phi-4, Qwen3, …), and the other guides that still carry launch commands. Those are follow-ups.
