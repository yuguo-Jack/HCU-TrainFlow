# [Perf] Pre-warm float32 greedy-with-penalties sampler and GDN RMSNorm buckets

[Upstream PR](https://github.com/vllm-project/vllm/pull/65492) · state: open · merged: False

## Original PR description

## Overview
When serving Qwen3.5 / Qwen3Next hybrid GDN models with speculative decoding (`dflash`, `mtp`, `eagle3`), `vllm.compile.jit_monitor` reports two inference-time Triton kernel JIT compilation stalls on live traffic despite startup kernel warmup (`warmup_kernels` and `qwen_triton_warmup`):

1. **`_gumbel_sample_kernel` (`vllm/v1/worker/gpu/sample/gumbel.py`)**:
   - During startup `warmup_kernels` (`vllm/v1/worker/gpu/warmup.py`), speculative decoding warms up `greedy=True` (`SamplingParams(temperature=0.0)`) and `greedy=False` (`SamplingParams(temperature=1.0)`).
   - However, when a greedy request also uses token penalties (e.g., `temperature=0.0, repetition_penalty=1.1`), `apply_Temperature` / penalty application upcasts `logits` from `bfloat16` to `float32` before calling `gumbel_sample` (`_gumbel_sample_kernel` with `temperature=0.0`). Because plain greedy warmup (`temperature=0.0` without penalties) passes `bfloat16` logits into `_gumbel_sample_kernel`, the `(float32_ptr, int32_ptr, float32_ptr, ...)` specialization is missed during warmup and triggers an inference-time Triton JIT compilation on the very first request.
2. **`_fused_gdn_gated_rms_norm_kernel` (`vllm/model_executor/layers/mamba/ops/fused_gdn_gating.py`)**:
   - In `_warm_gated_rms_norm_kernel` (`vllm/model_executor/warmup/qwen_triton_warmup.py`), `fused_gdn_gated_rms_norm` was warmed up only at `M in (1, 16, 17)`.
   - However, `fused_gdn_gated_rms_norm` computes `rows_per_block = calc_rows_per_block(M)` (`triton.cdiv(M, 3 * num_sm * (4096 // K))`, clamped to `1..4`) and passes it as `ROWS_PER_BLOCK: tl.constexpr`. On H100 (132 SMs, `K=128`), `M in (1, 16, 17)` only covers `ROWS_PER_BLOCK=1`. When the first prefill request with `num_tokens > 12,672` (or `num_tokens > 3,168` depending on `K`) arrives, `ROWS_PER_BLOCK` changes to `2`, `3`, or `4`, triggering an inference-time Triton JIT compilation stall (~110 ms spike) mid-benchmark.

This PR extends `warmup_kernels` to also warm up `greedy="with_penalties"` (`SamplingParams(temperature=0.0, repetition_penalty=1.1)`) when speculative decoding is enabled, and extends `_warm_gated_rms_norm_kernel` to warm up a representative `M` for every reachable `(M triton.jit specialization, rows_per_block)` bucket (`1..4`).

## Claims
- Eliminates **100% of inference-time Triton JIT compilation warnings (`2 -> 0`)** reported by `jit_monitor.py` during Qwen3.5-4B + DFlash serving on H100 NVL (`_gumbel_sample_kernel` and `_fused_gdn_gated_rms_norm_kernel`), preventing ~110 ms single-request tail-latency stalls on long prompts while adding `<0.1 s` to startup warmup.

## Validation

### 1. End-to-End Benchmark & `jit_monitor` Verification on NVIDIA H100 NVL
- **Hardware**: 1x NVIDIA H100 NVL (94 GB, 132 SMs, SM90)
- **Target Model**: `Qwen3_5ForConditionalGeneration` (Qwen3.5-4B)
- **Draft Model**: `z-lab/Qwen3.5-4B-DFlash` (`method="dflash"`, $k \in \{6, 8, 10\}$)
- **Workload**: 512 production prompts (`<=4096` input tokens, `max_tokens=200`, `temperature=0.0`, `repetition_penalty=1.1`, `vllm bench serve` C=1)

| Metric | Before (`main`) | After (PR) |
|---|---|---|
| **Inference-time `_gumbel_sample_kernel` JIT compilations** | **1** (on first request, `float32` logits) | **0** (pre-warmed during startup) |
| **Inference-time `_fused_gdn_gated_rms_norm_kernel` JIT compilations** | **1** (on first prompt hitting `ROWS_PER_BLOCK=3`, ~110 ms stall) | **0** (all `(M, ROWS_PER_BLOCK)` buckets pre-warmed) |
| **Total Inference-time Triton JIT Compilations (`jit_monitor`)** | **2** | **0** |
| **512-Query `vllm bench serve` p95 E2EL ($k=6 / 8 / 10$, FP8)** | 380–390 ms (with first-hit JIT spike) | **380.15 ms / 380.98 ms / 383.85 ms** (0 JIT spikes) |

### 2. Unit Tests

- Extended `test_qwen_gdn_prefill_warmup_kernels_compile_on_gpu` in `tests/model_executor/test_qwen_triton_warmup.py` to assert that warming up `Qwen3_5ForConditionalGeneration` compiles `_fused_gdn_gated_rms_norm_kernel` and covers all reachable `(M specialization, rows_per_block)` buckets (`M=1` + `rows_per_block in {1, 2, 3, 4}` for `M > 16`).
- Added `test_warmup_kernels_exercises_greedy_with_and_without_penalties` in `tests/v1/worker/test_gpu_warmup_blocks.py` verifying that `warmup_kernels` exercises `greedy=False`, `greedy=True`, and `greedy="with_penalties"` when speculative decoding is enabled.

## Details
- **`vllm/v1/worker/gpu/warmup.py`**:
  - Generalize `greedy: bool` parameter in `_warmup_kernels` to `greedy: bool | Literal["with_penalties"] = True`.
  - When `greedy == "with_penalties"`, construct `SamplingParams(temperature=0.0, repetition_penalty=1.1)` so penalty application upcasts logits to `float32` prior to `gumbel_sample`.
  - In `warmup_kernels`, iterate `for greedy in (False, True, "with_penalties"):` when `model_runner.speculative_config is not None`.
- **`vllm/model_executor/warmup/qwen_triton_warmup.py`**:
  - In `_warm_gated_rms_norm_kernel`, compute the minimum `M` for each `rows_per_block in (1, 2, 3, 4)` using `3 * num_sm * max(1, 4096 // k)` and warm up a representative `M` for every reachable `(0 if M == 1 else (1 if M <= 16 else 2), calc_rows_per_block(M, k))` bucket.
