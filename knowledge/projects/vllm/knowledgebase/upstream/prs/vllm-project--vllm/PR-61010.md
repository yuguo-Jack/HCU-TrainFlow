# [Bugfix][Spec Decode] Alias fp8 ignored_layers to global draft layer indices

[Upstream PR](https://github.com/vllm-project/vllm/pull/61010) · state: open · merged: False

## Original PR description

## Overview

Fixes #61003. A DFlash drafter with an fp8 checkpoint never honors `modules_to_not_convert` when it is built at global layer indices above the target: `map_draft_quant_config` only offset layer indices in `exclude_modules`, while `Fp8Config` reads those skips into `ignored_layers` and matches them exactly. The globally numbered draft modules never matched their exclusions, the grouped-conv projections got built as fp8 linears, and the reporter measured acceptance dropping from 4.3 to 1.03 tokens/step. This is a restatement of this PR's original approach for the current architecture, after #63001 folded `_add_global_draft_layer_exclusions` into `map_draft_quant_config` and left the fallback only handling `exclude_modules`.

## Claims

- `map_draft_quant_config` now aliases every exclusion list a quant config carries, `exclude_modules` and `ignored_layers`, instead of returning early when `exclude_modules` is absent. This is what routes fp8 draft skips through the aliasing at all.
- Each checkpoint-local `layers.N` entry gains both the global layer-index alias and the draft module-root alias, so exact-match fp8 exclusions hit the runtime module names. Already-global entries are left untouched and are not re-rooted.
- The `ModelOptQuantConfigBase` path is unchanged; the change is confined to the non-ModelOpt fallback.

## Validation

Red-green on the new regression `test_draft_quant_exclusions_alias_fp8_ignored_layers`, which builds a real `Fp8Config` (not a stub) and asserts the aliasing: red before the fix, `ignored_layers` stays `["layers.0.attention_conv.kernel_projection", "layers.64.already_global"]`, green after. `pytest tests/v1/spec_decode/test_dflash2.py` is 15 passed, 92 skipped (the 92 are CUDA-gated, none skipped because of this change). DFlash blast radius across `test_dflash2.py`, `test_dflash_prepare_inputs.py`, `test_dflash_causality.py`, `test_dflash_lookahead.py` is 32 passed, 98 skipped. `tests/quantization/test_modelopt.py::test_draft_quant_config_uses_runtime_module_names` and `::test_draft_quant_config_preserves_quark_settings` are 5 passed, confirming the ModelOpt path is unaffected. Ruff format and check clean on both changed files. CPU only; this is quantization-config bookkeeping with no kernels involved. The reporter's and limwand's ROCm acceptance measurements are the end-to-end confirmation I cannot run here. Both showed the aliasing restores acceptance and decode throughput, and the aliasing semantics (global index offset plus the `model.` root) are preserved from the version limwand confirmed on their stack.

## Details

Root cause: `map_draft_quant_config` has two paths. The `ModelOptQuantConfigBase` path remaps names through a weights mapper and applies both the layer offset and the module root. The fallback path for other backends only did `exclusions = getattr(quant_config, "exclude_modules", None)` and returned early when that was not a list. An fp8 config keeps its skips in `ignored_layers`, not `exclude_modules`, so the fallback returned without aliasing anything and the globally numbered names never matched. That is exactly the #61003 failure.

This PR moves the fix from `_add_global_draft_layer_exclusions` (removed by #63001) into the `map_draft_quant_config` fallback, loops both exclusion-list attributes, and generalizes the hardcoded `model.` root to the `prefix` argument the function already takes, matching how the ModelOpt path roots names. The change is additive: it only appends aliases and only rewrites `layers.N` indices, so semantic-key backends that do not store module names keep their settings, and suffix-match backends gain harmless extra entries. Tradeoff and limitation: this is quantization-config bookkeeping, so the end-to-end speedup depends on the drafter checkpoint actually listing its conv projections in `modules_to_not_convert`, which is what the #61003 reporter's checkpoint does; a checkpoint that omits them is unaffected either way.

Yes, exactly. I traced the prefix chain to be sure: the draft is built as DFlash2Qwen3ForCausalLM under get_model's default prefix "", so the inner model sits at maybe_prefix("", "model") and decoder layers are constructed with prefixes like model.layers.64.attention_conv.kernel_projection (the index is already global, start_layer_id is folded in when the ModuleList is built). fp8's is_layer_skipped defaults to exact matching (prefix in ignored_layers), so a bare layers.64.* entry never matches at runtime; the bare aliases only serve pattern-matching families like compressed-tensors exclude_modules.

fed698a6bf adds the model.-rooted form of each global alias alongside the bare one. Wildcard entries keep only the bare form, since those are read by pattern matchers where the rooted spelling would be nonsense. This also matches the reporter's live workaround in #61003, which carried both layers.{i+start} and model.layers.{i+start} forms and restored acceptance.

The fp8 test now asserts both forms land and that an already-global entry is not re-aliased; it fails on the previous helper and passes with this change.
