# [Bugfix][Spec Decode] Alias fp8 ignored_layers to global draft layer indices

[Upstream PR](https://github.com/vllm-project/vllm/pull/61010) · state: open · merged: False

## Original PR description

## Purpose

Fixes #61003. A DFlash drafter with an fp8 (`quant_method: fp8`) checkpoint never honors `modules_to_not_convert` when it is built at global layer indices above the target model: `_add_global_draft_layer_exclusions` only patches `exclude_modules`, while `Fp8Config` reads those skips into `ignored_layers`. The globally-numbered aliases never match, the grouped-conv projections get built as fp8 linears, and the loader logs a dtype mismatch. The reporter measured acceptance dropping from 4.3 to 1.03 tokens/step and decode from ~210 to 46 tok/s; the target still verifies, so outputs stay correct but the draft degrades.

The aliasing now runs over every exclusion-list attribute the quant config carries (`exclude_modules`, `ignored_layers`), not just the first.

## Why this is not duplicating existing work

#44628 changes fp8 `modules_to_not_convert` substring matching on the general load path (#21669), not draft-layer global-index aliasing. #49900 handles a different draft failure (compressed-tensors scheme matching, #49893). Neither touches `_add_global_draft_layer_exclusions`.

## Test plan

New unit regression `test_draft_quant_exclusions_alias_fp8_ignored_layers` in `tests/v1/spec_decode/test_dflash2.py`: an fp8-style config with `ignored_layers` gets the globally-aliased entries after the call, with already-global entries untouched. Red without the fix (the list stays un-aliased), green with it.

Local run: `pytest tests/v1/spec_decode/test_dflash2.py` — 12 passed, 10 skipped (GPU-gated). CPU-only environment; the fix is quantization-config bookkeeping, no kernels involved. The reporter's ROCm acceptance measurement is the end-to-end confirmation I cannot run here.

- he-yufeng · comment · 2026-10-12T17:12:44Z · [source](https://github.com/vllm-project/vllm/pull/61010#discussion_r4250579123)

File: `tests/v1/spec_decode/test_dflash2.py` · line 280

Yes, exactly. I traced the prefix chain to be sure: the draft is built as DFlash2Qwen3ForCausalLM under get_model's default prefix "", so the inner model sits at maybe_prefix("", "model") and decoder layers are constructed with prefixes like model.layers.64.attention_conv.kernel_projection (the index is already global, start_layer_id is folded in when the ModuleList is built). fp8's is_layer_skipped defaults to exact matching (prefix in ignored_layers), so a bare layers.64.* entry never matches at runtime; the bare aliases only serve pattern-matching families like compressed-tensors exclude_modules.

fed698a6bf adds the model.-rooted form of each global alias alongside the bare one. Wildcard entries keep only the bare form, since those are read by pattern matchers where the rooted spelling would be nonsense. This also matches the reporter's live workaround in #61003, which carried both layers.{i+start} and model.layers.{i+start} forms and restored acceptance.

The fp8 test now asserts both forms land and that an already-global entry is not re-aliased; it fails on the previous helper and passes with this change.
