# Add extra request body for multi-turn benchmark

[Upstream PR](https://github.com/vllm-project/vllm/pull/42575) · state: closed · merged: False

## Original PR description

Fixes #42548.

## Problem

`benchmark_serving_multi_turn.py` derives per-turn `max_tokens` from the dataset reference answer length by default. For reasoning models such as Qwen3, DeepSeek-R1, and gpt-oss, the reasoning phase can consume that entire budget, so the benchmark records near-empty final answers while still exiting successfully. This makes the reported output length and throughput numbers misleading.

## Change

This PR adds two request-level controls to the multi-turn benchmark:

- `--extra-request-body JSON`: merges a user-provided JSON object into every `/v1/chat/completions` request, so benchmark users can pass model-specific OpenAI-compatible fields without editing the script.
- `--disable-thinking`: convenience shorthand that injects `{"chat_template_kwargs": {"enable_thinking": false}, "reasoning_effort": "low"}` for reasoning-model benchmarks.

The generic passthrough is intentional: different reasoning models use different request fields, and this keeps the benchmark usable without hard-coding every model-specific option.

The `merge_request_body` function performs a shallow copy when assigning values from `extra` to `base` if the key is not present in `base` as a dictionary. Since `extra_request_body` is stored in `RequestArgs` and reused across all benchmark requests, any future modification to the request payload after merging could inadvertently corrupt the shared `extra_request_body` object. While currently safe in this script's execution flow, it is a fragile pattern for a deep merge utility.

```suggestion
def merge_request_body(base: RequestBody, extra: RequestBody) -> RequestBody:
    import copy
    for key, value in extra.items():
        if isinstance(base.get(key), dict) and isinstance(value, dict):
            merge_request_body(base[key], value)
        else:
            base[key] = copy.deepcopy(value)
    return base
```

Thanks for checking this. I reviewed the current data flow and am leaving the code as-is for this PR.

`RequestArgs.extra_request_body` is created once and treated as read-only. Each request builds a fresh top-level payload, merges the extra fields, and then passes that payload directly to `aiohttp` for JSON serialization. The script does not mutate the merged payload after that point, so there is no current path that writes back into the shared `extra_request_body` object.

A defensive `deepcopy` would also be valid, but it is not needed for the behavior fixed here and would add extra work on every benchmark request. If a future change starts mutating the built payload after merge, that change should add copying at the mutation boundary.
