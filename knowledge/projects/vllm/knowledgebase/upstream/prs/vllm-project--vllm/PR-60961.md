# [Bugfix][Kernel] Validate decode top-k runtime width

[Upstream PR](https://github.com/vllm-project/vllm/pull/60961) · state: open · merged: False

## Original PR description

## Overview
Fixes #60829: reject decode `topK` outside `[1, 8192]` before GPU launch or integer narrowing.

## Claims
Adds a native guard, five regression cases, and documents the limit; accepted-width computation is unchanged.

## Validation
- Rebuilt sampler on RTX 2000 Ada: `run_repository_tests.py` ran the actual repository tests with `--confcutdir=tests/kernels -k 'rejects_invalid_top_k or (test_top_k_per_row_decode and not gfx950)'`: **55 passed**. The pre-fix 8193 case failed to raise.
- `pre-commit run --files csrc/libtorch_stable/sampler.cu tests/kernels/test_top_k_per_row.py vllm/_custom_ops.py` and `git diff --check` passed. Existing CUDA/ROCm CI includes this test file.
- MI50/ROCm, full serving, and model evaluations were not run; no model computation changes.

## Details
Uses a conservative cap to reject the reported oversized widths; device shared-memory limits may restrict smaller widths too. Duplicate checks found no PR for #60829; #46012 addresses separate Wave32 merge sizing.
