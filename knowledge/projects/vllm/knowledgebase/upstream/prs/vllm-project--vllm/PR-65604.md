# [Perf][Core] Bound FIFO eviction cost for duplicate prefixes

[Upstream PR](https://github.com/vllm-project/vllm/pull/65604) · state: open · merged: False

## Original PR description



## Overview

Bound scheduler CPU work when cache pressure evicts many physical copies of the same prefix. Preserve cache representatives, block assignments, and generated outputs while replacing repeated scans of deleted dictionary slots in large duplicate sets.

## Claims

- Real `KVCacheManager` insertion/free/eviction cycles with eight prefix blocks: median total CPU wall time falls 39.85 → 35.77 ms at 2,048 copies and 231.87 → 151.20 ms at 8,192 copies (seven interleaved paired runs). At 8,192 copies, the eviction phase falls 113.19 → 33.38 ms.
- Keep compact dictionaries below 256 copies. Promote larger sets once to `OrderedDict`, retaining insertion order and excluding the atomic ID container from cyclic GC. Singleton compaction remains unchanged.
- Actual RTX 4070 serving reaches 511 copies and 639 duplicate removals. Base and patch produce identical token IDs and cached-token counts across 739 requests.

No end-to-end throughput or model-quality improvement is claimed. The benefit is specific to large duplicate cohorts under FIFO cache pressure.

```python
import gc
import importlib.util
import json
import random
import statistics
import sys
import time

import torch

from vllm.sampling_params import SamplingParams
from vllm.utils.hashing import sha256
from vllm.v1.core.block_pool import BlockHashToBlockMap
from vllm.v1.core.kv_cache_manager import KVCacheManager
from vllm.v1.core.kv_cache_utils import get_request_block_hasher, init_none_hash
from vllm.v1.kv_cache_interface import FullAttentionSpec, KVCacheConfig, KVCacheGroupSpec
from vllm.v1.request import Request

spec = importlib.util.spec_from_file_location("base_pool", "/tmp/base_block_pool.py")
base = importlib.util.module_from_spec(spec)
spec.loader.exec_module(base)
init_none_hash(sha256)
rng = random.Random(0)


def run(copies, cls):
    config = KVCacheConfig(
        num_blocks=copies * 8 + 1, kv_cache_tensors=[],
        kv_cache_groups=[KVCacheGroupSpec(["layer"], FullAttentionSpec(
            block_size=16, num_kv_heads=1, head_size=64, dtype=torch.float16))])
    manager = KVCacheManager(config, max_model_len=144, scheduler_block_size=16,
                             hash_block_size=16, enable_caching=True)
    pool = manager.block_pool
    pool.cached_block_hash_to_block = cls(pool.blocks)
    tokens = list(range(128))
    requests = [Request(request_id=str(i), prompt_token_ids=tokens,
                        sampling_params=SamplingParams(max_tokens=1, prompt_logprobs=1),
                        pooling_params=None,
                        block_hasher=get_request_block_hasher(16, sha256))
                for i in range(copies)]
    gc.collect()
    gc.disable()
    start = time.perf_counter_ns()
    for req in requests:
        computed, hits, _ = manager.get_computed_blocks(req)
        assert hits == 0
        assert manager.allocate_slots(req, 128, hits, computed) is not None
        manager.free(req)
    filled = time.perf_counter_ns()
    mapping = pool.cached_block_hash_to_block
    assert len(mapping) == 8
    if copies > 1:
        assert all(len(ids) == copies for ids in mapping._dup_ids.values())
    memory = sum(sys.getsizeof(ids) for ids in mapping._dup_ids.values())
    start_evict = time.perf_counter_ns()
    allocated = pool.get_new_blocks(copies * 8)
    end = time.perf_counter_ns()
    assert len(mapping) == 0
    pool.free_blocks(allocated)
    assert pool.get_num_free_blocks() == copies * 8
    gc.enable()
    return dict(total_ms=(filled-start+end-start_evict)/1e6,
                eviction_ms=(end-start_evict)/1e6, retained_bytes=memory)


arms = {"base": base.BlockHashToBlockMap, "patch": BlockHashToBlockMap}
for copies in (1, 2, 8, 128, 512, 2048, 8192):
    for cls in arms.values():
        run(copies, cls)
    rows = {name: [] for name in arms}
    for _ in range(7):
        order = list(arms)
        rng.shuffle(order)
        for name in order:
            rows[name].append(run(copies, arms[name]))
    print(json.dumps({"copies": copies, "samples": rows,
                      "medians": {name: {key: statistics.median(r[key] for r in samples)
                                         for key in samples[0]}
                                  for name, samples in rows.items()}}), flush=True)
```

## Details

The current `pop()` selects the oldest remaining copy using `next(iter(dup_ids))`. FIFO removals leave deleted slots at the front of a plain dictionary; restarting its iterator repeatedly scans them, giving quadratic total work when draining a large cohort. Promotion at 256 copies bounds that scan for compact cohorts and makes removal of larger cohorts constant-time amortized while preserving the selected physical block.

The threshold limits the larger representation to substantial duplicate sets. The ordered map contains only integer IDs and None, so it cannot participate in a reference cycle and can safely use the existing `gc_untrack` helper. It is discarded when only one copy remains, preserving singleton storage and lookup behavior. No new config, dependency, GPU synchronization, kernel, scheduler policy or model behavior is introduced.

Duplicate-work checks found no open PR addressing repeated FIFO scans while many copies remain. Related [#58891](https://github.com/vllm-project/vllm/pull/58891) compacts the representation after reaching one copy; that compaction is already present here. [#64700](https://github.com/vllm-project/vllm/pull/64700) addresses per-block cyclic-GC traversal, which this patch preserves. Closed [#61570](https://github.com/vllm-project/vllm/pull/61570) optimizes other pool/hash paths. Existing Buildkite V1 Core and CPU core steps select the new tests and cover the production file.
