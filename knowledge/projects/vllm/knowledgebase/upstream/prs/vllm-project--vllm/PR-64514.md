## Claims

- With the variable set (`1` or `true`, case-insensitive, trimmed, as Python parses it), an unknown `model` is accepted and served by the base model on chat, completions, `/inference/v1/generate`, `/tokenize`, `/detokenize`, gRPC and the render server, and the response's `model` is the primary served name, as in Python.
- A loaded LoRA adapter name still selects that adapter, as in Python, where adapters are looked up before the skip check.
- Without it, behavior is unchanged, except that generate and `/tokenize` now treat `"model": ""` as unset, like chat, completions and gRPC already did and like Python.

## Details

Python reads the variable in `OpenAIServing._is_model_supported` (`vllm/entrypoints/serve/engine/serving.py`), which every `_check_model` caller goes through.

- **One owner for the decision.** A new `ServedModelNames` (`server/src/model_names.rs`) holds the selectable names (served base names, then loaded LoRA adapters; primary first) and whether any other name is accepted. Its `accepts`/`check` replace five hand-written membership checks in the chat, completions and generate validators, `/tokenize` and `/detokenize`, and gRPC `to_text_request`. `LoraManager::resolve_model` extends the base names with the adapters, so LoRA selection is unchanged and still wins over the skip.
- **Configuration fixed at startup.** The variable is read once in the CLI, like `VLLM_HTTP_MAX_REQUEST_BODY_SIZE`: a hidden clap flag bound to it for `vllm-rs serve` and `frontend`, and `apply_env_fallbacks` for the Python-supervised `--args-json` path. It lands in `ApiServerOptions` and in `RenderConfig` for `vllm-rs render`.

**Layering.** The accepted-name set is a property of the server (base names fixed at startup, adapters from the LoRA registry), so the type lives in `vllm-server` next to the LoRA registry, and each protocol entry point only asks it. The env var is read where the other frontend-read env vars are read, in `vllm-cmd`.

**Merge note.** vllm-project/vllm#64513 (generate response envelope) extracts the same response-model expression in chat and completions `convert.rs`; whichever lands second is a one-line rebase.
