# [Frontend] Support thinking_token_budget in the Responses API

[Upstream PR](https://github.com/vllm-project/vllm/pull/63896) · state: closed · merged: True

## Original PR description



## Overview

Fixes #63663. `/v1/responses` now accepts `thinking_token_budget` and passes it to `SamplingParams`, as `/v1/chat/completions` already does.

## Claims

- `thinking_token_budget` on `/v1/responses` now limits reasoning. Before, it was silently dropped, because `ResponsesRequest` did not declare it and `OpenAIBaseModel` allows extra fields.
- Validation is shared with Chat Completions through the `ThinkingTokenBudget` type: `-1` means unlimited, and other negative values return 400 instead of being ignored.
- The field shows up in the rendered Responses extra-params list (via the `responses-extra-params` snippet), and the "Thinking Budget Control" docs now mention it.

## Validation

**Server regression test** (`RemoteOpenAIServer`, Qwen/Qwen3-0.6B, reasoning parser `qwen3`): the new `test_thinking_token_budget_responses_api` sends the same greedy request with `thinking_token_budget=5` to both endpoints and checks that the reasoning text matches.

```bash
pytest -v tests/entrypoints/openai/chat_completion/test_thinking_token_budget.py
```

- Base commit (85e199e60): fails, because Responses ignores the budget.
  ```
  E   assert '\nOkay, the ...r should be 2' == '\nOkay, the user'
  E     - Okay, the user
  E     + Okay, the user is asking "What is 1+1?" and wants a concise answer. Let me think. ...
  FAILED ...::test_thinking_token_budget_responses_api[default]
  ```
- With this PR: `7 passed, 1 skipped` for the whole file (the skipped test needs 2 GPUs for FP8 + MTP). I also ran the new test 3 more times, and it passed each time.

**Unit test**:

```bash
pytest tests/entrypoints/openai/responses/test_sampling_params.py
```

10 passed. Without the fix, `test_extra_sampling_params` fails with `assert None == 128`.

**Manual E2E**: 1x H20 running `vllm serve Qwen/Qwen3-0.6B --reasoning-parser qwen3 --reasoning-config '{"reasoning_start_str": "<think>", "reasoning_end_str": "I have to give the solution based on the reasoning directly now.</think>"}'`. Each request is greedy with `max_output_tokens=2048` and the prompt "9.11 and 9.8, which is greater? Think carefully." Reasoning tokens are counted with the model tokenizer, because Responses `usage.output_tokens_details.reasoning_tokens` is not populated for `SimpleContext`.

| Request | Base | This PR |
|---|---|---|
| `/v1/responses`, no budget | 200, 535 reasoning tokens | 200, 535 |
| `/v1/responses`, `thinking_token_budget=16` | 200, **535** (ignored) | 200, **29** (same text as chat) |
| `/v1/responses`, `thinking_token_budget=-1` | 200, 535 | 200, 535 (unlimited) |
| `/v1/responses`, `thinking_token_budget=-2` | **200** (ignored) | **400** `` `thinking_token_budget` must be a non-negative integer or -1 for unlimited. `` |
| `/v1/chat/completions`, `thinking_token_budget=16` (reference) | 200, 29 | 200, 29 |

(29 = 16 budgeted tokens + the forced `reasoning_end_str` phrase.)

## Details

- Root cause: `ResponsesRequest` never declared `thinking_token_budget`, so the request body accepted it as an extra field and `to_sampling_params()` never forwarded it.
- Fix: declare the field with the shared `ThinkingTokenBudget` annotated type and forward it in `to_sampling_params()`, the same way as `ChatCompletionRequest`. There are no serving-layer changes; the budget is enforced by the existing sampler path.
- The server test lives in the existing `chat_completion/test_thinking_token_budget.py` so it can reuse that module's Qwen3-0.6B reasoning server instead of starting another one in the Responses CI step.
- Not a duplicate: there is no open PR for #63663. #43692 tried the same change earlier and was closed without review.
- AI assistance (Claude) was used. I reviewed every changed line and ran the tests above myself.
