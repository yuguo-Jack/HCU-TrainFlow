# [Bugfix][Rust Frontend] Preserve SentencePiece leading spaces in logprobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/63773) · state: open · merged: False

## Original PR description



## Overview

Preserve leading whitespace when the Rust frontend decodes SentencePiece/Metaspace tokens individually for logprobs.

Related issue: https://github.com/vllm-project/vllm/issues/44319  
Python reference: https://github.com/vllm-project/vllm/pull/48674



## Claims

- Prevents distinct tokens such as `▁the` and `the` from both being reported as `"the"`.
- Prevents `top_logprobs` entries from overwriting each other when decoded token strings are used as map keys.
- Keeps completion `text_offset` values aligned with the generated text.
- Supports direct Metaspace pre-tokenizers and Metaspace inside a `Sequence`.
- Preserves existing behavior for non-Metaspace tokenizers and normal sequence decoding.



## Validation


```bash
cargo nextest run -p vllm-tokenizer -p vllm-text -p vllm-server --all-features --locked --no-fail-fast

cargo fmt --all -- --check

cargo clippy  -p vllm-tokenizer -p vllm-text -p vllm-server --all-targets --all-features --locked  -- -D warnings
```



## Details


Metaspace represents word-boundary whitespace inside raw vocabulary pieces, for example ▁the. When such a token is decoded in isolation, the decoder treats it as the beginning of a string and may remove the leading space. Consequently, both ▁the and the can decode to "the".

Completion logprobs use decoded token strings as map keys. Identical decoded strings cause one candidate to overwrite another. The missing space also makes subsequent character offsets too small.

The tokenizer now records the configured Metaspace replacement character during construction. A dedicated per-token decoding method compares the raw vocabulary piece with the decoded string and restores only missing leading spaces. Other tokenizer implementations retain the existing decoding behavior through the default method.

The logprobs path uses this per-token method, while normal sequence and incremental decoding remain unchanged.
