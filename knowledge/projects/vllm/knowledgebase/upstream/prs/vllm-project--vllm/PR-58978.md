## Original PR description

# [Bugfix][collect-env] Report the cuDNN runtime version

## Summary

Make the `cuDNN version` field in `vllm collect-env` report the cuDNN runtime
version used by PyTorch.

## Why

The previous implementation was named `get_cudnn_version`, but it searched
OS-specific locations for cuDNN library files and returned their paths. It
could therefore report `Could not collect` when cuDNN was installed through an
NVIDIA Python wheel, even though PyTorch could use cuDNN successfully.

This change uses `torch.backends.cudnn.version()`, which reports the runtime
version available to PyTorch. It also makes the field's value match its name:
the field reports a version rather than a library path.

Library-path discovery is intentionally not retained under `cuDNN version`;
paths and runtime versions are different diagnostics and should not be mixed.
The runtime lookup is limited to CUDA builds and falls back to
`Could not collect` with a warning if PyTorch cannot initialize cuDNN.

## Before / After

In an environment where cuDNN was installed by the NVIDIA Python wheel and
was usable by PyTorch, but was not registered with the system linker:

```text
# Before
cuDNN version                : Could not collect

# After
cuDNN version                : 92000
```

The test environment contained `nvidia-cudnn-cu13==9.20.0.48`; the reported
`92000` is the version integer returned by PyTorch.

## Validation

- Installed the current worktree with precompiled artifacts using
  `VLLM_USE_PRECOMPILED=1 uv pip install -e . --torch-backend=auto`.
- Ran `vllm collect-env` and verified that it reports `cuDNN version: 92000`
  instead of `Could not collect`.
- `git diff --check` passed.
- Unit tests were not run; the change was manually validated through the CLI.
- No model evaluation is needed; this changes diagnostics only.

This is a focused cuDNN runtime-reporting fix and is distinct from existing
`collect-env` work such as #39817 (ROCm reporting) and #48354 (non-Linux
support). Those changes do not address the cuDNN version field reporting
system library paths instead of the PyTorch runtime version.

AI assistance was used for this change.
