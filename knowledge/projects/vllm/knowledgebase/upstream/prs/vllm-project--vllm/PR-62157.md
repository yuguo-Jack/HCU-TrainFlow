# fix: validate ngram_gpu compatibility with disabled compilation

[Upstream PR](https://github.com/vllm-project/vllm/pull/62157) · state: open · merged: False

## Original PR description



## Overview

Fixes #62134 by adding early configuration validation for `ngram_gpu` speculative decoding when compilation is explicitly disabled.

## Claims

*   **Bug Fix:** Prevents a fatal engine initialization crash when `speculative_config.method="ngram_gpu"` is paired with `compilation_config.mode="NONE"`.
*   **UX Improvement:** Intercepts the invalid configuration early in `create_engine_config()` and provides an actionable `ValueError` directing the user to either enable compilation or use the CPU `ngram` proposer.

## Validation

*   Verified against the reproduction script provided in #62134.
*   Initializing an `LLM` with the conflicting configs now cleanly raises the target `ValueError` during configuration setup, rather than crashing with an obscure `ValueError: No compilation mode is set` deeply inside `GPUModelRunnerV1.__init__`.

## Details

**Root Cause:** The `ngram_gpu` kernel unconditionally wraps itself in `TorchCompileWithNoGuardsWrapper`, which requires an active compilation backend. If `mode="NONE"`, this wrapper fails during EngineCore initialization, resulting in a cryptic error disconnected from the user's explicit configuration choices.

**Fix:** Added a direct compatibility check in `vllm/engine/arg_utils.py:create_engine_config()` immediately after `speculative_config` and `compilation_config` are instantiated. This cleanly rejects the combination before the engine attempts to initialize devices.
