# [ROCm][Kimi-K3] Don't read W_UK_T before weight loading in the MLA wrapper

[Upstream PR](https://github.com/vllm-project/vllm/pull/61654) · state: closed · merged: True

## Original PR description



## Overview

Fixes a Kimi-K3 startup crash on ROCm (`'MLAAttention' object has no attribute 'W_UK_T'`) that appears once #53123 turns AITER FP8 BMM off by default.

## Claims

- `KimiK3MultiHeadLatentAttentionWrapper._fused_qk_prep_supported()` no longer reads `attn.W_UK_T` in `__init__`.
- The fused decode Q-prep path stays enabled when neither AITER BMM is on, instead of being silently disabled.

## Validation

- CI failure: MI355 LM Eval Spec Decode (Fixed-length FP8), `Kimi-K3-pruned75-DSpark-AITER-TP4`, [amd-ci #14622](https://buildkite.com/vllm/amd-ci/builds/14622#01a13ad1-6ae5-4cca-85f2-e72e6996548a).
- Called `_fused_qk_prep_supported` against an `nn.Module` fake MLA attention in that build's CI image (includes #53123):

| FP4 BMM | FP8 BMM | main | this PR |
|---|---|---|---|
| off | off | `AttributeError: W_UK_T` | True |
| off | on | False | False |
| on | off | True | True |

- Not run end to end locally: the 475 GB checkpoint doesn't fit on my box. CI's MI355 Spec Decode job covers it.

## Details

`_fused_qk_prep_supported()` runs in `__init__`, but `MLAAttention.W_UK_T` is only created in `process_weights_after_loading`. Before #53123, FP8 BMM was on by default, so the expression short-circuited and never read it. `process_weights_after_loading` always creates `W_UK_T` when FP4 and FP8 BMM are both off, so the check isn't needed. Using `getattr(..., None)` instead would have turned the fused path off for every such config. No open PR fixes this; #60110 edits `_fused_decode` but not this gate.
