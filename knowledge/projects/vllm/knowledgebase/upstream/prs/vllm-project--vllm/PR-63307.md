# Build the dummy batch with one kernel per stage

[Upstream PR](https://github.com/vllm-project/vllm/pull/63307) · state: closed · merged: False

## Original PR description

## Why

A decode step that runs a dummy batch — wide-EP expert rebalancing, DP
rank padding, cudagraph capture — builds that batch eagerly on the host
side of the graph replay. On a DeepSeek V4.1 flash-decode trace (H200,
8 KV-cache groups, c16), that preamble is ~21 kernel launches per step:

- `InputBatch.make_dummy`: 2 `arange`, 1 `zeros`, 6 slice fills, a cub
  `cumsum`, 1 elementwise sub → 13 launches
- `BlockTables.get_dummy_block_tables`: one `.zero_()` per KV-cache
  group → 8 launches

With a ~3 µs gap between launches this is ~60 µs of step time that
computes almost nothing.

## What

- `_init_dummy_batch_kernel` writes every make_dummy buffer (idx_mapping,
  expanded_local_pos, seq_lens, query_start_loc, input_ids, positions,
  is_padding, cu_num_logits, logits_indices) in one launch.
- `_zero_block_table_rows_kernel` zeroes the dummy rows of all KV-cache
  groups in one launch instead of one `zero_` per group.

The cumsum disappears algebraically rather than being fused: the dummy
split gives every request `base_tokens` tokens plus one extra for the
last `num_extra` requests, so

    seq_len[i] = base_tokens + [i >= num_reqs - num_extra]
    qsl[k]     = k * base_tokens + max(0, k - (num_reqs - num_extra))

and `qsl[num_reqs] = num_tokens` falls out of the same formula, so the
tail padding value needs no separate fill either.

Launch count per dummy run at G groups:

    before: 13 + G          (21 at G = 8)
    after:   2

CPU tensors keep an eager path (same closed form): the Triton kernel
has no CPU backend and `make_dummy` runs on CPU tensors in tests.

## Verification

- `tests/v1/worker/test_gpu_input_batch_v2.py` extended: fused outputs
  checked against the numpy reference, and a smaller dummy batch over
  dirty shared buffers must clear the seq_lens/query_start_loc tails.
- Existing `test_get_dummy_block_tables_returns_zeroed_rows` covers the
  grouped zeroing kernel.
- CPU path exercised locally; GPU run pending (draft until then).
