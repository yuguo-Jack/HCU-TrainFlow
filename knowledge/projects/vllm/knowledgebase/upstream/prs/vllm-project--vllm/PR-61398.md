</html>Purpose
Migrate the base RotaryEmbedding from a plain CustomOp to a vLLM IR op (vllm.ir.ops.rotary_embedding), so the QK-norm + RoPE(+KVCache) fusion patterns match a stable IR node without having to force custom_ops=["+rotary_embedding"].

This resolves the long-standing # TODO: support rope native forward match blocks in vllm/config/compilation.py and the underlying pattern-match failure tracked in https://github.com/vllm-project/vllm/issues/28042 (RoPE only matched the fusion when registered as a custom op). It follows the direction of https://github.com/vllm-project/vllm/issues/38756 ("Port RoPE ops to IR").

RoPE now emits the same IR node on every forward path (native/CUDA/HIP), so:

fusion patterns match regardless of custom_ops, and
the actual kernel (native vs. _C vs. AITER Triton) is chosen by IR op priority during lowering instead of a global custom-op flag.
Why this is not duplicating an existing PR
The prior effort — https://github.com/vllm-project/vllm/pull/43199 ([vLLM IR][Rope] Port RotaryEmbedding to IR Ops, @wxsIcey) and its predecessors https://github.com/vllm-project/vllm/pull/39488/https://github.com/vllm-project/vllm/pull/41773/https://github.com/vllm-project/vllm/pull/42264 — is closed and unmerged (last state: merge conflicts, mergeable_state: dirty), and RoPE is not an IR op on current main. This PR differs materially:

Rebased on current main and conflict-free.
Keeps MatcherRotaryEmbedding (making it emit the IR node) instead of deleting it. Current main gained QkNormRopeKvCacheFusionPass (the AITER QK-norm+RoPE+KVCache fusion, https://github.com/vllm-project/vllm/pull/42749) after https://github.com/vllm-project/vllm/pull/43199 was written, and that pass depends on the matcher — deleting it (as https://github.com/vllm-project/vllm/pull/43199 did) would break the AITER fusion.
Completes the ROCm/AITER path: adds an aiter IR provider for rotary_embedding, decouples the AITER Triton dispatch from RotaryEmbedding.enabled(), and sets ROCm IR-op priority to prefer AITER when enabled. Removing the +rotary_embedding force otherwise silently disabled AITER RoPE on ROCm.
Scope is intentionally limited to the base RotaryEmbedding (Neox + GPT-J, full/partial rope). DeepseekScalingRotaryEmbedding, mRoPE, flashinfer, and the key=None cross-layer-KV-sharing path are left on their existing paths and can be ported in follow-ups.
