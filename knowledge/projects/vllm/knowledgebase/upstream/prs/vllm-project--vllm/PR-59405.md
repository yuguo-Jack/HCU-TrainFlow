# [CPU][Bugfix] Skip KV cache memory reservation for pooling models

[Upstream PR](https://github.com/vllm-project/vllm/pull/59405) · state: closed · merged: True

## Original PR description

## Purpose

Encoder-only and pooling models (embeddings, rerankers, classifiers) do not perform autoregressive generation and do not need a KV cache. 
Previously, `CPUWorker.__init__` eagerly required `requested_cpu_memory <= available_memory` at startup, causing models to fail in memory-constrained environments (e.g., container `--memory=5g`) unless users manually passed `VLLM_CPU_KVCACHE_SPACE=0`

This PR:
1. Skips the startup memory reservation check in `CPUWorker.__init__` when `runner_type == "pooling"`.
2. Automatically sets `kv_cache_size = 0` in `determine_available_memory()` for pooling models, matching GPU worker behavior out-of-the-box.

## Test Plan

Run an encoder-only reranker model without any KV-cache environment variables or flags:
```bash
vllm serve BAAI/bge-reranker-v2-m3 --dtype bfloat16
```
## Test Result
Server starts cleanly out-of-the-box without requiring VLLM_CPU_KVCACHE_SPACE=0
