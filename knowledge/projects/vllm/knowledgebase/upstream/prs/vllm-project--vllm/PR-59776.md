# [Test] Re-enable jina-embeddings-v3 Matryoshka test on Transformers v5

[Upstream PR](https://github.com/vllm-project/vllm/pull/59776) · state: open · merged: False

## Original PR description



## Overview

Part of #38379. Re-enables `test_matryoshka` for `jinaai/jina-embeddings-v3` in `tests/models/language/pooling_mteb_test/test_jina.py`.

**Depends on** the upstream fix to the model's remote code: https://huggingface.co/jinaai/xlm-roberta-flash-implementation/discussions/64. Until that is merged this test fails on `main` the same way it did when it was skipped, so this PR stays a draft.

## Claims

- `test_matryoshka` (HF Sentence Transformers vs vLLM embeddings with `dimensions`) runs again for jina-embeddings-v3.
- Fixes the test's `dimensions` parametrization: `16` is not in the model's `matryoshka_dimensions` (`[32, 64, 128, 256, 512, 768, 1024]`), and since #48057 (merged while this test was skipped) vLLM rejects it with `VLLMValidationError`. The test now uses `32` and `64`.

## Validation

Environment: 1x RTX PRO 6000 Blackwell, transformers 5.17.0, sentence-transformers 6.1.0, vLLM at this branch.

```bash
pytest tests/models/language/pooling_mteb_test/test_jina.py -k test_matryoshka
```

| Remote code (`jinaai/xlm-roberta-flash-implementation`) | Result |
|---|---|
| current `main` | 2 failed: `AttributeError: 'XLMRobertaLoRA' object has no attribute 'all_tied_weights_keys'` |
| with Hub PR #64 | **2 passed** (`dimensions=32`, `dimensions=64`), 4 skipped (not Matryoshka models) |

With the old `[16, 32]` parametrization and the Hub fix, `dimensions=32` passed and `dimensions=16` failed with `only supports Matryoshka dimensions [32, 64, 128, 256, 512, 768, 1024], got 16.`

Hub PR #64 was also checked outside vLLM: Sentence Transformers embeddings are bit-identical between transformers 4.57.6 (current code), 4.57.6 (patched) and 5.17.0 (patched).

`pre-commit run --files tests/models/language/pooling_mteb_test/test_jina.py` passes.

## Details

- The skip was added in #30566. The root cause is in the checkpoint's remote code: `XLMRobertaLoRA.__init__` doesn't call `post_init()`. That is reported upstream in xlm-roberta-flash-implementation discussion #62, and Hub PR #64 fixes it.
- Test-only change, no runtime code touched.
- Duplicate check: no open vLLM PRs touch `test_jina.py`'s Matryoshka test or this skip.
