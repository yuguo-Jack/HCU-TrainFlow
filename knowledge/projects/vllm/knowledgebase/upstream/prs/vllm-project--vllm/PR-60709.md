# [Bugfix] Fix InternLM2 tool parser dropping characters from streamed arguments

[Upstream PR](https://github.com/vllm-project/vllm/pull/60709) · state: closed · merged: True

## Original PR description


## Overview

Fixes #60348. If a stream chunk ended inside a JSON string, `Internlm2ToolParser` dropped the closing `"` and the final `}` from the streamed tool-call arguments. The parser now computes the argument delta from the text it has already sent to the client.

## Claims

- For the chunks `{"location": "Beijing` + `", "days": 3}}<|action_end|>`, the streamed arguments were `{"location": "Beijing, "days": 3`, which is invalid JSON. They are now `{"location": "Beijing", "days": 3}`.
- A sweep over string and structure payloads, cut at many chunk boundaries, found no stream that got worse. It found 6,649 streams that were wrong before and are right now.
- The change is in one branch of `Internlm2ToolParser.extract_tool_calls_streaming`. It adds the regression test `test_streaming_arguments_match_final_arguments`, which fails on the old code.
- Not fixed: number literals that `json.dumps` writes differently from the model's text (see Details).

## Validation

Reproducer: the script below calls the parser directly. It needs no server and no model weights. Run it with `python -P repro.py`. The issue's attached script was not available, so this script was written from the issue's description. Its failing output matches the wrong value given in the issue.

Environment: 1× NVIDIA B200, vLLM commit `43b4aaea3e40e20ef53ce2bfecfa1b72060bf2b5`, with and without this patch. The bug is in pure Python, so the GPU is not used. The bug was also reproduced on the `vllm/vllm-openai:nightly` image at the same commit.

#!/usr/bin/env python3
"""Reproduce vllm#60348: Internlm2ToolParser drops characters from streaming args."""

import sys


class MockTokenizer:
    pass


def run_chunks(chunks, label):
    from vllm.tool_parsers.internlm2_tool_parser import Internlm2ToolParser

    class MockRequest:
        tools = []
        tool_choice = "auto"

    parser = Internlm2ToolParser(MockTokenizer())
    request = MockRequest()

    collected_args = []
    previous_text = ""

    for i, chunk in enumerate(chunks):
        current_text = previous_text + chunk
        delta_text = chunk

        result = parser.extract_tool_calls_streaming(
            previous_text=previous_text,
            current_text=current_text,
            delta_text=delta_text,
            previous_token_ids=[],
            current_token_ids=[],
            delta_token_ids=[],
            request=request,
        )

        if result and result.tool_calls:
            for tc in result.tool_calls:
                if tc.function:
                    # function is a DeltaFunctionCall pydantic model
                    fn = tc.function
                    args = fn.arguments if hasattr(fn, "arguments") else fn.get("arguments")
                    if args:
                        print(f"  chunk {i} arg delta: {repr(args)}")
                        collected_args.append(args)

        previous_text = current_text

    remaining = parser.get_remaining_unstreamed_args()
    if remaining:
        print(f"  get_remaining_unstreamed_args: {repr(remaining)}")
        collected_args.append(remaining)

    result = "".join(collected_args)
    expected = '{"location": "Beijing", "days": 3}'
    status = "PASS" if result == expected else "FAIL"
    print(f"  concatenated: {repr(result)}")
    print(f"  expected:     {repr(expected)}")
    print(f"  {status}")
    return result


# The full InternLM2 model output for a weather tool call.
FULL_TEXT = (
    '<|action_start|><|plugin|>\n'
    '{"name": "get_weather", "parameters": {"location": "Beijing", "days": 3}}\n'
    '<|action_end|>'
)

# chunk_a: ends right before the parameters value (name parseable, args not yet)
chunk_a = '<|action_start|><|plugin|>\n{"name": "get_weather", "parameters": '

# --- Failing split: chunk boundary falls BEFORE the closing " of "Beijing" ---
chunk_b_bad = '{"location": "Beijing'
chunk_c_bad = '", "days": 3}}\n<|action_end|>'

print("=== Failing split (chunk boundary before closing \" of Beijing) ===")
run_chunks([chunk_a, chunk_b_bad, chunk_c_bad], "failing")

print()

# --- Good split: chunk boundary falls AFTER the closing " of "Beijing" ---
chunk_b_good = '{"location": "Beijing"'
chunk_c_good = ', "days": 3}}\n<|action_end|>'

print("=== Good split (chunk boundary after closing \" of Beijing) ===")
run_chunks([chunk_a, chunk_b_good, chunk_c_good], "good")

Chunk-boundary sweep (scratch script, not part of this PR): 5 payloads. They were the issue's example, escaped quotes with `}` and `]` inside strings, non-ASCII and emoji with `\n` and `\\`, empty string/array/object with a list of objects, and a string with a comma. Each payload was cut at every 2-way split, at every 3-way split inside the arguments, and one character at a time, for 13,887 streams in total. The original parser got 7,158 right and the patched parser got 13,807 right. No stream went from right to wrong. The 80 streams that are still wrong all cut inside the `<|action_start|>` tag, so the parser never sees a tool call. That code is not changed here, and a real tokenizer emits the tag as one token.

## Details

Root cause: `partial_json_parser` closes every open string, array and object. So for the raw text `{"location": "Beijing`, `json.dumps` of the parsed arguments gives `{"location": "Beijing"}`. The trailing `"}` is synthetic, because the model has not produced it yet. When the arguments first appear, the parser correctly sends only `{"location": "Beijing`. On the next chunk, the branch where both the previous and the current parse have arguments computed the delta with `extract_intermediate_diff(cur_args_json, prev_args_json)`. That treats `prev_args_json` as text the client already has. But `prev_args_json` contains the synthetic `"`, which was never sent, so the real `"` in the next chunk counted as already sent and was dropped. The delta never looked at what was really streamed. After that, the streamed text is no longer a prefix of the final arguments, so `get_remaining_unstreamed_args()` returns `""` and the final `}` is lost too. This is a consequence of the first problem, not a second bug. The first-arguments branch was correct and is unchanged.

Fix: the delta now starts from `sent = len(self.streamed_args_for_tool[self.current_tool_id])`.

- If the tool-call JSON is complete, send `cur_args_json[sent:]`.
- If the two parses differ, send their common prefix minus `sent`. Synthetic closers sit at the end of a serialization and change when real text arrives, so for strings and structure the common prefix holds only real text.
- If the two parses are equal, send `""`. The old code also sent an empty delta here.

`llama_tool_parser.py` and `granite_20b_fc_tool_parser.py` already use this scheme. The import changes from `extract_intermediate_diff` to `find_common_prefix`. `extract_intermediate_diff` stays in `utils.py` because `jamba_tool_parser.py` still uses it.

Limitations:

- The parser still streams `json.dumps` of the partial parse. The issue suggests streaming slices of the raw text, and this PR does not do that. So number literals that `json.dumps` writes differently can still go wrong for some splits. For `1E-3` (final `0.001`), 335 splits were wrong before and 23 after. For `0.00001` (final `1e-05`), 152 were wrong before and 37 after. Both "after" counts include 16 cuts inside the `<|action_start|>` tag. No split went from right to wrong, but the failure looks different now. For the chunks `"x": 1` + `E-3, "y": "z"}}...`, the old code sent `{"x": 10.001, "y": "z"`, which is invalid JSON. The new code sends `{"x": 1.001, "y": "z"}`, which is valid JSON with a wrong value. The llama and granite-20b-fc parsers have the same limit.
- `jamba_tool_parser.py` has the same `extract_intermediate_diff(cur_args_json, prev_args_json)` branch and may have the same bug. It is not changed here.
