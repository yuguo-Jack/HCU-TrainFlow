# [Misc][MoE] Support Qwen4Exp in benchmark_moe.py

[Upstream PR](https://github.com/vllm-project/vllm/pull/64438) · state: open · merged: False

## Original PR description

## Overview

`benchmarks/kernels/benchmark_moe.py` cannot tune `Qwen/Qwen3.8-Flash-Next` (`Qwen4ExpForConditionalGeneration`): `get_model_params()` falls through to the default branch and fails on the nested text config.

## Claims

- The tuner runs on `Qwen/Qwen3.8-Flash-Next-FP8` and writes a config for the fused MoE kernel (E=64 per GPU with TEP8/DEP8, N=640, fp8 block [128,128]).
- No behavior change for any other architecture: two names added to the branch that already handles `Qwen3VLMoe` and `Qwen3_5Moe`.

## Validation

Before, on `main`:

```
$ python benchmarks/kernels/benchmark_moe.py --model Qwen/Qwen3.8-Flash-Next-FP8 --tp-size 8 --enable-expert-parallel --dtype fp8_w8a8 --batch-size 1
AttributeError: 'Qwen4ExpTextConfig' object has no attribute 'intermediate_size'. Did you mean: 'moe_intermediate_size'?
```

After, same command on this branch (8x H100 SXM, driver 580.173, Triton 3.8.0):

```
Batch size: 1, config: {'BLOCK_SIZE_M': 16, 'BLOCK_SIZE_N': 64, 'BLOCK_SIZE_K': 128, 'GROUP_SIZE_M': 1, 'SPLIT_K': 1, 'num_warps': 4, 'num_stages': 4}
Kernel time: 36.36 us
```

A full `--tune` run on the same node produced
`E=64,N=640,device_name=NVIDIA_H100_80GB_HBM3,dtype=fp8_w8a8,block_shape=[128,128].json`.
Serving the FP8 checkpoint with that config via `VLLM_TUNED_CONFIG_FOLDER` (DP4 x TP2 + EP, MTP, long multi-turn agentic requests at 128 concurrent streams) raised prompt throughput from 124k to 137k tok/s and end-to-end agent turns/min by 9%; without the file vLLM logs `Using default MoE config. Performance might be sub-optimal!` for this shape. The config itself is not part of this PR.

## Details

Qwen4Exp stores `num_experts`, `num_experts_per_tok`, `moe_intermediate_size` and `hidden_size` under `text_config`, the same layout the `Qwen3VLMoe` / `Qwen3_5Moe` branch reads through `config.get_text_config()`. `Qwen4ExpTextConfig` is added alongside the architecture name so `--model-prefix text_config` also resolves, mirroring the existing `Qwen3_5MoeTextConfig` entry.
