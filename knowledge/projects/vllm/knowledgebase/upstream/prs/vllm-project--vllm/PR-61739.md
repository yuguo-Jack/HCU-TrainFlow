# [ROCm][CI] Stop test_quick_all_reduce leaking a fake QR handle into q…

[Upstream PR](https://github.com/vllm-project/vllm/pull/61739) · state: closed · merged: False

## Original PR description

…r_destroy

test_quick_allreduce_passes_dynamic_quant_level assigns `object()` to `QuickAllReduce._ptr` on an instance that is never closed. When the instance is garbage-collected, `__del__` -> `close()` passes that object to the real `ops.qr_destroy`, which only accepts an int, so the MI355 Distributed Features job logs a PytestUnraisableExceptionWarning (`_C_custom_ar::qr_destroy() Expected a value of type int`) and the test fails outright under `-W error::pytest.PytestUnraisableExceptionWarning`.

Set the fake handle through `monkeypatch.setattr(..., raising=False)` so teardown deletes it before `__del__` runs and `close()` becomes a no-op.
