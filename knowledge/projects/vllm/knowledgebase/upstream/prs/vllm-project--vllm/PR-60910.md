# [Refactor] Move model-specific env vars into vllm/models/<model>/envs.py

[Upstream PR](https://github.com/vllm-project/vllm/pull/60910) · state: open · merged: False

## Original PR description



## Overview

Move env vars that only one specialized model reads out of the global `vllm/envs.py` and into `vllm/models/<model>/envs.py`, next to the model code that uses them. Also document this convention for contributors and agents.

## Claims

- `VLLM_KIMI_K3_SHARD_SP_SHARED_EXPERT`, `VLLM_KIMI_K3_AUX_ATTN_RES_STREAM` and `VLLM_KIMI_K3_GEMM_AR` move to `vllm/models/kimi_k3/envs.py`.
- `VLLM_DISABLE_DSV4_MEGAMOE_SHARED_EXPERT_FUSION` moves to `vllm/models/deepseek_v4/envs.py`.
- No user-visible change: the env var names, defaults and parsing are the same, and `vllm.envs.<NAME>` still resolves.
- `AGENTS.md` and `docs/configuration/env_vars.md` describe and list the model-local env vars.

Also checked by hand:

- `Platform.validate_environ(hard_fail=True)` accepts the moved vars.
- `enable_envs_cache()` / `disable_envs_cache()` behave the same when the vars are read through the model `envs` module.
- Loading `vllm/envs.py` by path, as `setup.py` does, still works.

This is a pure refactor with no numerical change, so I didn't run model evals.

## Details

Several places look up env vars in `vllm.envs.environment_variables`: the unknown-`VLLM_*` warning, the list of vars copied to Ray workers, and `compile_factors()`. The last one matters here because `VLLM_KIMI_K3_GEMM_AR` changes the traced graph, so it has to stay in the compile-cache key. That means the model vars still need to be registered centrally.

How it works:
- Each `vllm/models/<model>/envs.py` imports only the standard library and has its own `environment_variables` dict.
- `vllm/envs.py` finds `vllm/models/*/envs.py`, loads each file by path (so the model package `__init__`, which pulls in torch and kernels, doesn't run), and registers it under `vllm.models.<model>.envs` in `sys.modules`.
- It merges each file's vars into the central dict and asserts that no name is defined twice.
- A module-level `__getattr__` in each model's `envs.py` forwards reads to `vllm.envs`, so they use the same cache.

Model code reads these vars through `from vllm.models.<model> import envs`.

Out of scope:
- Vars read by more than one model stay in `vllm/envs.py`: `VLLM_ENABLE_GEMM_RS`, `VLLM_MULTI_STREAM_GEMM_TOKEN_THRESHOLD` and `VLLM_DCP_Q_REPLICATE`.
- A few model files read env vars without the `VLLM_` prefix straight from `os.environ`: `INKLING_*`, `LAMPORT_RS_SCONV` and `XHS_VIDEO_JPEG_QUALITY`. Moving them means renaming them, so that's left for a follow-up.
