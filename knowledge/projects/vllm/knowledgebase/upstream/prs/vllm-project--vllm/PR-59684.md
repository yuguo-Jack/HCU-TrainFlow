# [ROCm][Bugfix] Warm elastic EP target groups at commit on ROCm

[Upstream PR](https://github.com/vllm-project/vllm/pull/59684) · state: open · merged: False

## Original PR description

#56610 stopped warming the target DP/EP torch device groups during asynchronous preparation on ROCm and relied on warm_and_capture to warm them at commit. warm_and_capture only drives the PyNccl communicators, so the first collective on the new EP device group is the EPLB all-reduce: in commit_scale_up's reshuffle in eager mode, and in the first periodic EPLB step after a scale-down with CUDA graphs. On MI355 that first all-reduce fails in RCCL with "hipIpcGetMemHandle failed : invalid argument" (vllm/ci builds 92231 and 92464, Elastic EP Scaling).

Warm the target groups on ROCm at commit for scale-up and for the non-removing scale-down path, while the engine is paused, regardless of whether the fused MoE kernel is reused.

Also add the MI355 AMD mirror of Elastic EP Scaling from #56679 so the fix runs on MI355.
