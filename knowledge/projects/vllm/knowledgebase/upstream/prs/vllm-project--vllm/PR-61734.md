# [Feat][Stacked] Add bidirectional single-forward reads for Nemotron fine-tunes

[Upstream PR](https://github.com/vllm-project/vllm/pull/61734) · state: open · merged: False

## Overview

Serve Nemotron Labs Diffusion checkpoints fine-tuned with bidirectional attention over the whole prompt, using `hf_overrides={"ar_mode": true, "is_causal": false}`. The model runs one bidirectional forward over prompt + mask and returns exact candidate logprobs at the mask. Stacked on #58387 → #60287 → #60288. Tracking: #60283.

[Review the isolated delta](https://github.com/pst2154/vllm/compare/1028340c3...3b4dce5c9) (one commit). The comparison against main temporarily includes the unmerged dependencies.

**Update (October 15, review by @DarkLight1337):** the `max_tokens=1` check for bidirectional reads moved from `SamplingParams` to `InputProcessor` (`validate_ar_request` hook on the HF config); no architecture names in shared code. Three existing `InputProcessor` test stubs gain `hf_config` (every `ModelConfig` has one), which also fixes `test_prompt_logprob_token_ids_require_v2_model_runner`. Docs are now a README paragraph. CPU tests 100 passed / 10 skipped; whole-stack GPU suite passed on 1x H200; public v2 checkpoint JevBench 209/231 BF16, 208/231 FP8.

## Claims

- `ar_mode` + `is_causal=False` runs every layer as encoder-only attention without KV cache, as `is_causal=False` already does for Llama-family decoders. The model selects `EncoderOnlyModelState`, which builds the non-causal attention metadata.
- Prefix caching is disabled automatically for this mode, with a log explaining why: a bidirectional prompt's keys depend on later tokens.
- Requests must use `max_tokens=1`; others are rejected before they reach the worker. The check is a `validate_ar_request` hook on the Nemotron HF config, not an architecture check in `SamplingParams`.
- Masked-diffusion mode rejects `is_causal=False` with a configuration error that points to `ar_mode`, since it keeps a causal prompt KV cache.
- The public bidirectional fine-tune [nemotron-deciffusion/Nemotron-Deciffusion-8B-v2](https://huggingface.co/nemotron-deciffusion/Nemotron-Deciffusion-8B-v2) scores 209/231 on JevBench public through this path, on upstream vLLM with no other patches.

The base checkpoint was trained with causal prompts and gets worse in this mode, so the documentation limits it to checkpoints fine-tuned for it.   .venv/bin/python -m pytest --confcutdir=tests/models/language/generation \


## Details

The change reuses vLLM's existing bidirectional-decoder path rather than adding a new attention mode. `LlamaDecoderLayer` already maps `is_causal=False` to `AttentionType.ENCODER_ONLY`. Without this PR, the Nemotron model's own `get_model_state_cls` returned `DefaultModelState` in AR mode, so no attention metadata was built for encoder-only layers and the forward failed with `KeyError: 'model.layers.0.self_attn.attn'`.

There is no KV cache, so the engine disables chunked prefill and a prompt must fit in one step: set `max_num_batched_tokens` to the longest prompt to accept. On current main a longer prompt hangs the engine; #61733 (independent of this stack) rejects it with HTTP 400 instead.

Scope: masked-diffusion reads (#60288) are unchanged and still use a causal prefill. This mode is for single-position reads; it does not change generation, the gateway or the model runner. About 70 non-test lines.

Duplicate check (October 14): no open PR adds bidirectional Nemotron reads. #59299 (merged) added the native `/v1/systemone` endpoint; this PR adds no endpoint and does not change it.
