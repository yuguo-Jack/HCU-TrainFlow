# [Feature][PCP] Support APC and encoder-side SWA bounded replay for DeepSeek-V4.1-Flash

[Upstream PR](https://github.com/vllm-project/vllm/pull/62183) · state: closed · merged: True

## Original PR description

## Overview

Follow up on #59857 to enable automatic prefix caching (APC) together with encoder-side SWA bounded replay for DeepSeek-V4.1-Flash under PCP in a colocated model instance. The initial PCP implementation rejected APC; this change enables the PCP + APC + encoder-side replay combination.

## Claims

- Enable local APC prefix hits under PCP and rebuild the SWA tail through encoder-side bounded replay while preserving cached compressed KV and indexer keys across ranks.
- Decoder-side tail trimming remains disabled under PCP; scheduled rows execute the normal decoder layers.

## Validation

- Hardware: two separate nodes, each with 8x NVIDIA H20 97,871 MiB; driver 535.161.08

## Details

Reuse the existing scheduler replay boundary and padding kernel, stage replay starts per local PCP segment, mask each rank's own cacheable slots, and gather those slots back in the same rank-major order as KV publication. All ranks participate even when a peer has no replay rows; SWA and compressor scratch mappings stay unchanged. The additional slot metadata collective applies only to PCP batches with encoder replay enabled. Production changes are confined to DeepSeek-V4.1 files, with the existing non-PCP path and other PCP restrictions retained.

This does not duplicate #61554, which targets cold-prefill decoder trimming with prefix caching disabled. Enable APC and encoder-side replay with `--enable-prefix-caching --swa-bounded-replay`. The supported scope is NVIDIA CUDA, MRV2, eager execution, synchronous scheduling and PP=DP=DCP=1. KV connectors, speculative decoding, microbatching and MegaMoE remain unsupported with PCP. AI assistance was used for implementation and Codex CLI review; human line-by-line review remains pending, while GPU/model validation is documented above.
