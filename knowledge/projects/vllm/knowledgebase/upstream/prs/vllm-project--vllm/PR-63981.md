# [Bugfix] Use a short private directory when the IPC socket path is too long

[Upstream PR](https://github.com/vllm-project/vllm/pull/63981) · state: open · merged: False

## Original PR description



## Overview

When an IPC socket path under `VLLM_RPC_BASE_PATH` (default `TMPDIR`) would exceed the Unix socket path limit, use a short private directory under `/tmp` instead of failing at startup.

## Claims

- Fixes `vllm serve` failing at startup when `TMPDIR` is long, as with per-job directories on Slurm clusters.
- The fallback directory is created per process with `mkdtemp` (mode 0700) and removed at exit; a warning names `VLLM_RPC_BASE_PATH`.

## Validation

On LUMI (Slurm), `TMPDIR=<per-job scratch dir>` (130 bytes), vLLM v0.31.0 ROCm image, Qwen/Qwen3-0.6B, TP=8:

```
# without this change:
zmq.error.ZMQError: ipc path "/scratch/.../a-deliberately-long-per-job-temporary-directory-name/1a5b4767-..." is longer than 107 characters
# with this change:
WARNING ... IPC socket directory '...' is too long for a Unix socket path; using '/tmp/vllm-aw9761p5' instead. ...
→ server starts and serves
```

New `test_get_open_zmq_ipc_path_falls_back_from_long_base` in `tests/utils_/test_network_utils.py` checks the fallback directory is under `/tmp` with mode 0700 and that a socket binds there.

```
pytest tests/utils_/test_network_utils.py   # Linux: 25 passed
```

## Details

- Root cause: socket paths are `<VLLM_RPC_BASE_PATH>/<uuid4>`; `sockaddr_un.sun_path` holds 107 bytes on Linux.
- A private directory rather than `/tmp` itself, consistent with #59113 (per-user private IPC directory). With #59113 the default moves to `<tempdir>/vllm-<uid>`, which is still under a long `TMPDIR`, so the fallback remains useful.
- `envs.py` documents the fallback for `VLLM_RPC_BASE_PATH`.
