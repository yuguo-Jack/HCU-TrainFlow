# [Rust Frontend] Support --enable-force-include-usage

[Upstream PR](https://github.com/vllm-project/vllm/pull/55971) · state: closed · merged: False

## Original PR description

## Purpose

Implements the `--enable-force-include-usage` server flag in the Rust frontend, which was previously listed in `unsupported.rs` and rejected at startup. When enabled, streaming `/v1/chat/completions` and `/v1/completions` responses always include usage in every chunk, regardless of per-request `stream_options`.

Behavior matches the Python frontend's `should_include_usage` (`vllm/entrypoints/serve/utils/api_utils.py`): when force is on, both `include_usage` and `include_continuous_usage` are forced to `true`. The flag is off by default, so existing behavior is unchanged.

## Changes

- `rust/src/cmd/src/cli.rs`: add `--enable-force-include-usage` to `SharedRuntimeArgs` (same definition pattern as neighboring flags), wired into the frontend config
- `rust/src/cmd/src/cli/unsupported.rs`: drop the now-supported entry
- `rust/src/server/src/config.rs`: add `enable_force_include_usage` to `ApiServerOptions`
- `rust/src/server/src/routes/openai/chat_completions.rs` / `completions.rs`: OR the server-level flag into `include_usage` / `include_continuous_usage` at the top of each chunk stream

## Not a duplicate

Searched open PRs for `force-include-usage` (title) and `enable-force-include-usage` (full text) — no existing PR implements this flag in the Rust frontend. No open issue requests it either.

### Reply to usberkeley — Python vs Rust SSE behavior with `stream_options`

I compared the SSE shapes between the Python and Rust frontends using the test suites already
in the repo (Python: `tests/entrypoints/openai/chat_completion/test_chat.py` /
`completion/test_completion.py`; Rust: the new `rust/src/server/src/routes/tests.rs` cases with
a deterministic mock engine). Full table below; short answer: the Rust frontend matches the
Python behavior for every `stream_options` combination, and the force flag implements the same
`should_include_usage(stream_options, force_include_usage=True)` semantics as the Python server.

#### `/v1/chat/completions`

| stream_options | Python behavior (test ref) | Rust behavior (test ref) | Match |
|---|---|---|---|
| absent | no `usage` in any chunk | no `"usage":` in body; ends `data: [DONE]` (`stream_without_include_usage_keeps_existing_shape`) | ✅ |
| `{"include_usage": false}` | every chunk `usage is None` (`test_chat_completion_stream_options` case 1) | same path as absent (no usage chunks) | ✅ |
| `{"include_usage": true, "continuous_usage_stats": false}` | token chunks no usage; after `finish_reason` chunk, one **final usage-only chunk** with `choices == []`, `usage.total == prompt + completion` (`test_chat_completion_stream_options` case 2) | finish chunk → usage chunk with `choices == []`, `usage{prompt_tokens:22, completion_tokens:3, total_tokens:25}` → `[DONE]` (`include_usage_adds_final_usage_chunk_before_done`) | ✅ |
| `{"include_usage": true, "continuous_usage_stats": true}` | **every** chunk carries `usage`; `completion_tokens` monotonically non-decreasing; total == prompt + completion (case 4) | every chunk has `usage`; per-chunk `completion_tokens` increments; final usage chunk `choices == []` (`stream_continuous_usage_stats_adds_usage_to_chat_chunks`) | ✅ |
| `stream=false` + any `stream_options` | `BadRequestError` (`test_chat_completion_stream_options` cases 3–4) | 400 `invalid_request_error` (`completions_invalid_request_returns_openai_error`, same shape for `/v1/completions`) | ✅ |
| `--enable-force-include-usage` (new flag), no `stream_options` | forces `include_usage` + `include_continuous_usage` (`tests/entrypoints/serve/utils/test_api_utils.py::test_should_include_usage_force_enables_continuous_usage`) | every chunk has `usage`; final usage chunk `choices == []` (`force_include_usage_adds_usage_to_all_chat_chunks`) | ✅ |

#### `/v1/completions`

| stream_options | Python behavior (test ref) | Rust behavior (test ref) | Match |
|---|---|---|---|
| `{"include_usage": false, ...}` | every chunk `usage is None` (`test_completion_stream_options` cases 1–2) | same path as chat without usage | ✅ |
| `{"include_usage": true, "continuous_usage_stats": false}` | token chunks no usage; **final usage-only chunk** with `choices == []` (case 3) | identical structure via shared streaming code; final usage chunk `choices == []` | ✅ |
| `{"include_usage": true, "continuous_usage_stats": true}` | **every** chunk has usage, total == prompt + completion (case 4) | every chunk has `usage`; final usage chunk `choices == []` (`force_include_usage_adds_usage_to_all_completion_chunks` asserts the every-chunk invariant) | ✅ |
| `--enable-force-include-usage`, no `stream_options` | forced `include_usage` + `include_continuous_usage` | every chunk has `usage` (`force_include_usage_adds_usage_to_all_completion_chunks`) | ✅ |

Notes:
- Exact token counts differ (Python runs a real model; Rust tests use a deterministic mock
  engine: 22 prompt / 3 completion for chat, 3 completion for completions). Only the SSE
  **shape** (chunk ordering, `usage` presence/absence, `choices == []` on the final usage
  chunk, `[DONE]` sentinel) is compared — and it matches.
