# [Rust Frontend] Accept parenthesized and name-only Gemma 4 tool calls like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/63768) · state: closed · merged: True

## Original PR description

## Overview

Gemma 4 documents tool calls as `<|tool_call>call:name{key:value}<tool_call|>`, but some checkpoints write the body in parentheses (`call:terminal(command:<|"|>ls -a<|"|>)`, vllm-project/vllm#53642). Python's parser accepts that form and the name-only `call:name<tool_call|>` since vllm-project/vllm#53657. This PR brings the Rust Gemma 4 parser to the same behavior.

## Claims

- The Rust Gemma 4 parser accepts parenthesized calls and name-only calls (empty arguments `{}`), in non-streaming and streaming at any chunk split.
- A body must end with the closer that matches its opener; `call:f(x:1}` is rejected, as a braced body without `}` already was.

## Validation

Commands from `.buildkite/scripts/run-rust-frontend-cargo-ci.sh` (`style-clippy` and `test`), run from the repo root:

```
cargo fmt --manifest-path rust/Cargo.toml --all -- --check   # ok
cargo sort --workspace --check rust                          # ok
cargo deny --manifest-path rust/Cargo.toml --config rust/deny.toml check bans   # ok
cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --all-features --locked -- -D warnings   # ok
cargo nextest run --manifest-path rust/Cargo.toml --workspace --all-features --locked --no-fail-fast
# 2312 tests run: 2312 passed, 13 skipped
```

- `gemma4_accepts_parenthesized_and_name_only_calls_at_every_split`: a paren call whose string value contains parentheses, a name-only call and a braced call, parsed whole and at every two-chunk split; checks names, arguments and tool indexes.
- `gemma4_parenthesized_call_requires_its_own_closer`: `call:set(flag:true}` fails, and `reset` returns the raw input.
- Both tests fail on `main`. Python's PR added no unit test; its reproducer is covered by the first test.

## Details

Root cause: the Rust header parser (`rust/src/parser/src/unified/gemma4.rs`) read the name up to `{` and required it. On the paren form the call never left the header state, so the request either failed at finish as an incomplete tool call, or a later braced call's `{` ended a garbage name (`terminal(command:...)<tool_call|><|tool_call>call:terminal`) carrying the second call's arguments.

Change: the header ends at `{`, `(` or `<tool_call|>`. The active call (`Gemma4CallBody`) remembers its opener, so the body must end with the matching closer, and `reset` reconstructs the raw text with that opener. The change stays in the model-specific parser; the generic argument grammar is unchanged.

Deviation from Python: Python drops a trailing `}` regardless of the opener, and a trailing `)` whenever the raw arguments have more `)` than `(`, so it also accepts mixed brackets such as `call:f(x:1}`. Rust picks the closer from the opener and rejects a mismatch. No report shows a mixed form.

Not a duplicate: no open PR changes the Rust Gemma 4 call header.
