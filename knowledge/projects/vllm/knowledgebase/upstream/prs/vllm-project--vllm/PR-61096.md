# [Perf][Qwen3-VL] Resize video frames during decoding to reduce peak m…

[Upstream PR](https://github.com/vllm-project/vllm/pull/61096) · state: open · merged: False

## Original PR description

…emory (#60985)

* Add early video frame resizing directly in Qwen3VLVideoBackend to resize sampled frames using torchvision bicubic interpolation with antialiasing during decoding rather than keeping full-resolution decoded frames.
* Add size budget extraction for Qwen3-VL and Cosmos3-Edge video processors in transformers_utils/processor.py.
* Pass _resize_size_config from chat parser and connector into video_io_kwargs.
* Add idempotency check ensuring smart_resize on target dimensions is a no-op, preserving bit-identical model inputs (video_grid_thw, pixel_values_videos).
* Add comprehensive regression tests and benchmark script.


## Overview

Reduce peak host-memory usage when decoding sampled Qwen3-VL video frames by resizing them early, avoiding unnecessary full-resolution frame buffers where the optimization is safe.

Fixes #60985.

## Claims

- Adds guarded early resizing for supported OpenCV video-decoding paths.
- Derives resize settings from supported video processor configurations.
- Preserves the existing decoding path for unsupported configurations and applicable custom sizing overrides.
- Adds regression tests and a synthetic benchmark.

## Validation

- Targeted tests: `pytest tests/multimodal/test_video.py -k "qwen3_vl" -v` — 7 passed, as reported in local testing.
- Ruff formatting and checks on changed files passed, as reported locally.
- A synthetic 720p benchmark reported frame-buffer memory decreasing from 13.18 MiB to 2.11 MiB (84% reduction).

These are local synthetic benchmark results. End-to-end server memory, production throughput, and GPU decoding performance have not been benchmarked.

## Details

The optimization uses processor-derived sizing and an idempotency check to avoid unintended additional resizing. When the optimization cannot be applied safely, the existing path is retained.

AI assistance was used during development. The implementation remains subject to project CI and maintainer review.
