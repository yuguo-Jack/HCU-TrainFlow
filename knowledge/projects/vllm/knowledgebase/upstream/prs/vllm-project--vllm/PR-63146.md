# [Test][Pooling] Cover explicit right truncation for the JinaVL score token

[Upstream PR](https://github.com/vllm-project/vllm/pull/63146) · state: closed · merged: True

## Original PR description

## Overview

Follow-up to #62783, which was merged before I could add the test case requested in [review](https://github.com/vllm-project/vllm/pull/62783#discussion_r4344897617). With an explicit `truncation_side`, `get_encode_kwargs` disables tokenizer truncation, so the cut happens in `apply_post_tokenization`. If the JinaVL score token were appended before that step (in `get_score_prompt`), right-side truncation would drop it again. This adds a `truncation_side="right"` case to `test_truncation_keeps_jinavl_score_token`.

## Claims

- The JinaVL score token test now covers an explicit right truncation side, which is the case that breaks if `post_process_tokens` moves back before `apply_post_tokenization`.
- Test-only change.

## Validation

- `pytest tests/entrypoints/pooling/scoring/test_io_processor_unit.py`: 17 passed on current `main`.
- With `post_process_tokens` moved back into `get_score_prompt` (reserved limits applied only to tokenization), the new `[4-32-right]` case fails and the existing cases still pass, so the new case is the one that catches this.
- `pre-commit run --files <changed files>`: all hooks pass.

## Details

Not a duplicate: this only extends the test added in #62783.
