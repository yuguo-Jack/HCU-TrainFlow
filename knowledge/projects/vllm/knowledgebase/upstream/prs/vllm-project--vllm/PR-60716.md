# [Bugfix][Kernel] Restore FP fusion for indexer Q quantization

[Upstream PR](https://github.com/vllm-project/vllm/pull/60716) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Make DeepSeek V4 sparse-indexer Q RoPE + FP8/FP4 quantization match the CUDA reference when Triton disables implicit floating-point fusion.

Fixes https://github.com/pytorch/test-infra/issues/9069 which was uncovered through the Triton 3.9 pin update. Root cause is https://github.com/triton-lang/triton/pull/11270 from Triton which disables `enable_fp_fusion` by default. Here we enable it for 2 callsites to preserve bitwise equivalence. 

## Claims

- Restore exact output-byte agreement for the three B200 failures reported in the issue.
- Restore Triton 3.8 fusion behavior for the FP8 and FP4 indexer Q kernels by setting `enable_fp_fusion=True` on both launches.

## Validation

| `3.9.0+gitaad2a60d` | 80 passed |

## Details

Triton [PR #11270](https://github.com/triton-lang/triton/pull/11270) disabled floating-point fusion by default. The CUDA `rotary_embedding` reference still uses fused arithmetic. Separate FP32 operations can cross a BF16 rounding midpoint and change the encoded FP8/FP4 bytes.

Both launches explicitly request `enable_fp_fusion=True`, restoring the compiler policy used in Triton 3.8. Kernel arithmetic and signatures are preserved.
