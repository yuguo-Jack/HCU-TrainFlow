# [OPT] Optimize the fusion-MOE-kernel matrix calculation for cases whe…

[Upstream PR](https://github.com/vllm-project/vllm/pull/38539) · state: closed · merged: False

## Original PR description

## Purpose
When BLOCK_SIZE_M is very small (typically 16 when bs=1~32 in the decode stage) and BLOCK_SIZE_N is greater than or equal to 64, the matrix multiplication of tl.dot(a, b) is essentially [M, K] x [K, N], where M is very small. By transposing it to [N, K] x [K, M], with the larger dimension at the front, the WGMMA instruction scheduling of Hopper can be better utilized to enhance the performance of fuse-moe.

This is a precision test.
