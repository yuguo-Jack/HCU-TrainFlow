# [Config] Infer HiSparse attention config from HiSparseConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/57041) · state: closed · merged: True

## Original PR description

## What

HiSparse needed to be turned on twice: `HiSparseConnector` in `--kv-transfer-config` *and* `--attention-config '{"hisparse_config":{}}'`. The empty `{}` carries no information — configuring the connector already implies HiSparse, and `hisparse_config` without the connector is rejected at startup anyway (`hisparse/layout.py:78`).

`VllmConfig.__post_init__` now defaults `attention_config.hisparse_config = HiSparseConfig()` when `kv_transfer_config.has_connector("HiSparseConnector")` (direct or MultiConnector child), placed before the existing HiSparse validation block so CUDA/PP/DCP/DSA/HMA errors still fire. Explicit `--attention-config` is now only for tuning (`device_buffer_size`, `eager_host_mirror`).

## How HiSparse is run now

Decode side of a NIXL P/D setup, before:

```bash
--attention-config '{"hisparse_config":{}}' \
--kv-transfer-config '{"kv_connector":"MultiConnector","kv_role":"kv_consumer",
  "kv_connector_extra_config":{"connectors":[
    {"kv_connector":"NixlConnector","kv_role":"kv_consumer"},
    {"kv_connector":"HiSparseConnector","kv_role":"kv_both",
     "kv_connector_extra_config":{"host_pool_gib":128}}]}}'
```

after: identical, minus the `--attention-config` line.
