# [Spec Decode] Batch-sharded draft logits refactor

[Upstream PR](https://github.com/vllm-project/vllm/pull/64356) · state: closed · merged: True

## Original PR description

## Context

#63554 sharded the draft logits cache under batch-sharded sampling, assigning each request to a rank by its persistent slot: owner `req_state_idx % tp_size`, row `req_state_idx // tp_size`. That ties per-rank load to how the slot allocator happens to spread requests, and it gives each rank a varying number of requests per step. The DSpark follow-up (sharding the sequential Markov block) needs per-rank shapes that are fixed for a given batch size, so it can be CUDA-graph captured.

## This PR

This PR refactors how requests are assigned to ranks, and moves the sharding logic into one object.

**Ownership by batch position.** Every draft step gives the request at batch position `i` to rank `i % tp_size`, at row `i // tp_size` of that rank's cache (`DraftLogitsCache.assign`, called from `DraftModelSpeculator.prepare_propose`). Each rank holds at most `cdiv(num_reqs, tp_size)` requests, however the slots are spread. Verification runs each request on the rank that cached its drafts, via `DraftLogitsCache.owners_of`, which `BatchSharder` uses.

**Reused rows.** Rows are reassigned every step, so a request that the scheduler skips can find its row overwritten. `inverse_row_mapping` records which request last wrote each row. `DraftLogitsCache.stale_drafts` (a Triton kernel) marks drafts whose row has since changed hands, and `RejectionSampler` routes them through the existing invalid-drafts path, so verification resamples from the target. This is lossless: only that step's acceptance drops. **Note that this staleness only affects batch-sharded draft logits.**

**`DraftLogitsCache`** (new, `spec_decode/draft_logits.py`) owns the cache and its mappings:
- `values`: `[num_rows, num_steps, vocab]`;
- `row_mapping`: request slot → row on this rank, or −1;
- `shard_mapping`: request slot → owning rank;
- `inverse_row_mapping`: row → request slot.

The speculator owns it, and `rejection_sample`, `gumbel_sample` and the DFlash2 candidate cache take it, or its `row_mapping`, instead of `num_shards`/`shard_idx` arguments. `draft_logits_row()` is the single lookup: −1 means "no row on this rank", and every writer masks on `row >= 0`. With a replicated cache, `row_mapping` is `None` and every path reduces to indexing by slot. The opt-in rules from #63554 and #64151 are unchanged: the speculator must support it, no draft watermarker, and PCP = 1.

**Balance:** I simulated TP4 with MRv2's LIFO slot allocator and measured the busiest rank's verification load relative to a perfect split.
- Steady load: both rules are within about 1% on average.
- While a burst of 256 requests drains (≤ 64 live), slot ownership averages 1.32× and hits 3.0× worst case. Batch-position ownership averages 1.00×, because it rebalances every step.

## Benchmarks

**Setup:**
- 4× GB200, TP4, `max_num_seqs=256`, probabilistic drafting, prefix caching off, natural EOS.
- 4 boots per pair, ordered base, shard, shard, base. "base" has `--enable-batch-sharded-sampling` off; "shard" has it on (sharded verification plus the sharded draft logits cache).
- GSM8K: 1319 questions. t0 is temperature 0, one run per boot. t1 is temperature 1, 3 seeds per boot.
- SPEED-Bench: `low_entropy` subset, `throughput_2k` config, temperature 1. Acceptance is measured at c64.
- Latencies are medians.
- Measured on a pre-cleanup revision of this branch. Later changes are renames, docstrings and the rebase; the logic is unchanged.

### Notes

- **c8 cost with sharding on.** At c8, step time is bound by rank 0's host work. Per-rank host timers on DFlash at c8 show +1.7 ms of host time per step with sharding on: shard plan 0.35 ms, output gather 0.29 ms, stale-drafts/assign launches about 0.2 ms, and about 0.85 ms not yet attributed. GPU work per step is unchanged. Most of this comes from batch-sharded sampling itself, which already exists on main. The main vs this PR table separates out this PR's share.
- **Not a duplicate.** This refactors the ownership scheme from #63554 and builds on #64151. No other open PR touches this code.
