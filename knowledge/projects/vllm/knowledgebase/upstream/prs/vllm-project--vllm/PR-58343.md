# [SpecDecode] Support quantized DFlash2 selectors and owned DFlash/DSpark heads

[Upstream PR](https://github.com/vllm-project/vllm/pull/58343) · state: open · merged: False

## Original PR description

## Overview

Honor draft quantization for DFlash2 selector projections and explicitly owned Qwen3 DSpark heads. Reject missing declared DFlash/DSpark heads and preserve explicitly owned DSpark heads during target sharing.

## Claims

- Selector projections use the draft's quantization config; checkpoint exclusions are respected and selector codebooks remain floating-point.
- A checkpoint declaring `has_own_lm_head=true` must supply head tensors. Explicitly owned DSpark heads are retained even when packed weight bytes match the target but scales differ.
- Unowned placeholder heads remain unquantized: weight post-processing happens before target-head sharing, and quantizing an unloaded placeholder can process missing scales.

## Details

- Quantizing an unused head unconditionally is unsafe: `get_model` post-processes quantized weights before sharing replaces the module. The published Lightning NVFP4 DSpark config does not declare an owned head or exclude `lm_head`, and its checkpoint contains no head tensors.
- Head-presence validation does not check completeness of every quantization scale.
- #57934 already supplies the shared DFlash head-construction/sharing behavior; this rebased PR retains it and adds no LiLiCorr implementation. #53662 concerns vocabulary ownership/placeholder allocation, #53104 generic missing-weight sharing guards, #53122 quantization mapping/context-KV projection, #53651 excluded-head re-tying, and #47584 optional FP8 target-head copies. None duplicates the remaining selector/DSpark allocation and declared-head validation changes here.
- AI assistance was used for implementation, tests, and independent review.
