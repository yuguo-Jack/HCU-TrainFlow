## Overview

Add opt-in logical expert-routing statistics with or without Expert Parallel Load Balancing (EPLB), without changing routing or enabling expert rearrangement.

Rebased on October 5, 2026 onto public main `54d93af9fb89d0bb8392bdb72db42bb6a17cb4ca`; head `46c8d680bd6ae15c58e209c93ceb2c72912dcecc`. This PR remains **draft** for design/code review and the remaining GPU validation.

## Claims

- One collection configuration and logical-expert JSONL schema work with EPLB on or off.
- Support interval histograms and bounded, sampled per-layer/per-target-iteration traces.
- Count rank-local source-token ownership without additional observability collectives or per-expert Prometheus labels.
- Disabled collection creates no tracker or device/export buffers. Enabled collection has instrumentation/export costs; no overhead or speedup result is claimed.

## Details

Use the same collection configuration in either mode:

```sh
# Observe without balancing.
vllm serve MODEL --data-parallel-size 2 --enable-expert-parallel \
  --expert-load-stats-config '{"enabled":true,"log_interval":1000,"output_dir":"./expert-load"}'

# Collect the same statistics while balancing.
vllm serve MODEL --data-parallel-size 2 --enable-expert-parallel --enable-eplb \
  --expert-load-stats-config '{"enabled":true,"log_interval":1000,"output_dir":"./expert-load"}'
```

Dotted CLI options and Python configuration are also supported. Existing EPLB policy, recording windows, and balancedness logging retain their meaning. Logical routing skew is distinct from physical EP-rank balance.

Instrument non-monolithic `BaseRouter` target routing: use a histogram kernel without EPLB and fuse logical counting into the existing mapping traversal with EPLB, preserving its physical counters. Explicit Triton histogram masks exclude invalid/padded/unowned lanes; sentinel binning is not safe on Triton 3.7.1.

Persistent counter buffers support graph replay. Two bounded export slots move D2H copying and writing off the inference thread; slow exports drop trace samples, not summary counts. Writer waits are confined to the reporter thread and shutdown. Filesystem failures disable JSONL writes and log once without stopping serving; console summaries and export-error counts continue. CUDA errors are not suppressed.

Iteration IDs are local target-forward counters, not synchronized DP steps. Target verification tokens count even if rejected later. Draft forwards, warmup, dummy work, padding, and shared experts are excluded. Full per-expert vectors require JSONL; console output is a compact interval overview. Global layer IDs are validated per PP stage; unselected stages and non-owning TP replicas allocate no tracker.

Initial support is CUDA/non-monolithic routing. Custom/monolithic routers, LoRA, DBO/ubatching, CP, elastic EP, encoder disaggregation, KV-sharing fast prefill, and adaptive verification fail closed; see the feature guide for full scope.

The shared collector keeps lifecycle/export logic outside the model runners. MRV2 brackets real target forwards explicitly; MRV1 retains compatibility for existing deployments using the same CLI. This larger feature still warrants maintainer design review, especially its ownership and export lifecycle. Current main's EPLB startup, dummy-weight handling, compilation tests, and CPU routed-expert tests are preserved; feature semantics are unchanged by the rebase.

Open-PR searches were refreshed on October 5. #43715 / #30696 concern physical EPLB metrics/Prometheus; #41141 concerns offline placement, #56716 EPLB warmup, and #57100 synthetic routing distributions for benchmarks. None provides this EPLB-independent logical-expert collection interface.

Checklist review: no new rebase-related code issue. Shared infrastructure, explicit unsupported-path checks, documentation, and tests are retained. GPU correctness, disabled/enabled overhead, distributed ownership, and end-to-end validation remain open; the rebase does not establish those results.
