# [Feature][MoE] Collect expert distributions with or without EPLB

[Upstream PR](https://github.com/vllm-project/vllm/pull/58220) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Collect logical expert-routing histograms without requiring EPLB. The same configuration and output schema work with EPLB enabled; routing and placement are unchanged.

## Claims

- Interval summaries and bounded, sampled per-layer/per-target-iteration JSONL traces.
- Rank-local ownership excludes padding and duplicate TP counts; no observability collectives.
- Disabled collection allocates no tracker/buffers. Enabled collection has instrumentation/export costs; no performance claim.

## Details

```sh
vllm serve MODEL --expert-load-stats-config \
  '{"enabled":true,"log_interval":1000,"output_dir":"./expert-load"}'
```

Use unchanged collection settings with `--enable-eplb`; add `"trace":true` for iteration histograms. EPLB's physical balancedness metrics and returned routed-expert capture retain their existing behavior. Trace iteration IDs are local target-forward counters, not synchronized DP steps.

Explicitly masked logical counters use persistent graph-compatible buffers. Two bounded export slots keep copying/writing off the inference thread; backpressure drops trace samples, not summary counts. Filesystem failures disable JSONL export without stopping serving.

Initial support is CUDA/non-monolithic `BaseRouter` target models in MRV1/MRV2. Unsupported modes fail closed. The feature guide documents ownership, exclusions, memory cost, and export semantics.
