# [Bugfix][Rust Frontend] Fix HTTP 500 on long conversations: fuel-limit only request templates

[Upstream PR](https://github.com/vllm-project/vllm/pull/62374) · state: closed · merged: True

## Original PR description

## Overview

On the Rust frontend, long conversations fail with HTTP 500 even when the prompt is far below the context length (#62598). A GLM-5.3 agent session of 1,730 messages (21K tokens, about 2% of its 1M context) is rejected, while the same conversation renders in 0.12 s with transformers. Once a session reaches this point, every later request in it fails, and no setting raises the limit.

The cause is the hard-coded 500K MiniJinja instruction budget per render from #50300, which also applies to the model's own template. Since #62673, request-supplied templates are refused unless `--trust-request-chat-template` is set. This PR therefore keeps the budget for those templates only and renders the server's own template without one, as the Python frontend does. `VLLM_CHAT_TEMPLATE_FUEL` overrides the request-template budget (`0` disables it), and the out-of-fuel error names it.

Fixes #62598

## Claims

- The server's own chat template renders without a fuel limit, so long conversations work by default. This matches the Python frontend, which has no instruction cap for it, only `VLLM_CHAT_TEMPLATE_RENDER_TIMEOUT`.
- Request-supplied templates, which only render with `--trust-request-chat-template`, keep the 500K budget from #50300, so the protection on that path is unchanged. `VLLM_CHAT_TEMPLATE_FUEL` raises or disables it, and the out-of-fuel error says which variable to change, as the Python render-timeout error does. The variable is read once when the renderer is built, and an invalid value fails startup.

## Details

- **Root cause.** Fuel counts executed instructions, and chat templates loop over messages. GLM-5.3's template spends about 290 instructions per message, so it reaches 500K at about 1,700 messages regardless of content length. #62598 measures the same limit at 1,682–21,740 messages across the templates in `examples/`.
- **No limit for the server's template.** That template is configured by the operator, through the model files or `--chat-template`. The Python frontend renders it without an instruction cap, and its cost grows with the request like tokenization does. If a cap is still wanted there, it is a one-line `with_fuel` on the default template.
- **Environment variable.** Like `VLLM_MAX_STOP_STRINGS`, it is declared in `vllm/envs.py` and read with `std::env::var`; `vllm-rs` inherits it when started from `vllm serve`. It is excluded from `compile_factors()`, since it does not affect compiled graphs.
- **Duplicates.** No existing PR covers this. I searched `fuel`, `VLLM_CHAT_TEMPLATE`, `50300 in:body` and `52025 in:body`; the only hit, #60199, caps `tojson` indentation. #62673 adds the flag this builds on.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Exclude the Rust-only fuel setting from compile factors**

When `VLLM_CHAT_TEMPLATE_FUEL` is changed for a Rust-frontend restart, registering it here also makes `envs.compile_factors()` include it because that function hashes every registered variable unless it is in `ignored_factors`, and this name is not. The value only controls MiniJinja rendering, but it therefore changes `env_hash` and the torch.compile cache directory in `vllm/compilation/backends.py`, preventing reuse of already-compiled model graphs; add this runtime-only knob to `ignored_factors` so raising the chat budget does not trigger an unrelated recompilation.
