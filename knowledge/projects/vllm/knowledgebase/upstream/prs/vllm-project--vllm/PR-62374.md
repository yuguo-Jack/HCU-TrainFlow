# [Bugfix][Rust Frontend] Fix HTTP 500 on long conversations: make template fuel configurable

[Upstream PR](https://github.com/vllm-project/vllm/pull/62374) · state: open · merged: False

## Original PR description



## Overview

On the Rust frontend, long conversations fail with HTTP 500 even when the prompt is far below the context length. A GLM-5.3 agent session of 1722 messages (46K tokens, under 5% of its 1M context) is rejected, while the same conversation renders in 0.12 s with transformers. Once a session reaches this point, every later request in it fails, so the agent cannot continue unless its history is trimmed, and no setting raises the limit.

The cause is the hard-coded 500K MiniJinja instruction budget per render from #50300, which also applies to the model's own template. This PR reads the budget from `VLLM_CHAT_TEMPLATE_FUEL` (default unchanged, `0` disables it) and names the variable in the error.

## Claims

- `VLLM_CHAT_TEMPLATE_FUEL` raises or disables the budget, so these sessions succeed. When it is unset, behavior matches main, so the #50300 protection is kept.
- The out-of-fuel error says which variable to change, as the Python render-timeout error does.

## Validation

`vllm-rs serve` + `vllm-mock-engine`, GLM-5.3 tokenizer and template, a synthetic agent session (one tool call and result per turn), `max_tokens=1`:

| build | `VLLM_CHAT_TEMPLATE_FUEL` | 1682 msgs (45K tokens) | 1722 msgs (46K tokens) |
|---|---|---|---|
| main `689effee` | unset | 200 | 500 `engine ran out of fuel` |
| this PR | unset | 200 | 500, error names `VLLM_CHAT_TEMPLATE_FUEL` |
| this PR | `2000000` or `0` | 200 | 200 |

New tests use a synthetic template whose cost grows per turn: `test_long_conversation_exceeds_default_fuel` snapshots the error at the default budget, and `test_raised_or_disabled_fuel_renders_long_conversation` covers a raised and a disabled budget. `test_chat_template_fuel_is_not_compile_factor` keeps the variable out of the compile cache key.

All pass, except 5 tests that also fail on main on this machine (macOS grammar-replay snapshots, a timing-sensitive audio test). Rendered output is unchanged, so no model eval.

## Details

- **Root cause.** Fuel counts executed instructions, and chat templates loop over messages. GLM-5.3's template spends about 300 instructions per message, so it reaches 500K at about 1700 messages regardless of content length.
- **Environment variable.** Like `VLLM_MAX_STOP_STRINGS`, it is declared in `vllm/envs.py` and read with `std::env::var`; `vllm-rs` inherits it when started from `vllm serve`. It is excluded from `compile_factors()`, since it does not affect compiled graphs. The Python frontend has no fuel; it uses `VLLM_CHAT_TEMPLATE_RENDER_TIMEOUT` instead.
- **One budget for all templates.** Without a `--trust-request-chat-template` gate (#52025), request-supplied templates must stay bounded, so raising the variable raises their budget too. A TODO marks where a separate budget would go.
- **Default** is kept at 500K, so this PR leaves the #50300 protection as is. That default still rejects sessions like the one above; a higher one (for example 5M, about 0.2 s per render above) would be a one-line change.
- No existing PR covers this (searched `fuel`, `VLLM_CHAT_TEMPLATE`, `50300 in:body`, `52025 in:body`; the only hit, #60199, caps `tojson` indentation).
- AI assistance (Claude Code) was used to prepare this change. I reviewed every changed line; the commands above were run locally.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Exclude the Rust-only fuel setting from compile factors**

When `VLLM_CHAT_TEMPLATE_FUEL` is changed for a Rust-frontend restart, registering it here also makes `envs.compile_factors()` include it because that function hashes every registered variable unless it is in `ignored_factors`, and this name is not. The value only controls MiniJinja rendering, but it therefore changes `env_hash` and the torch.compile cache directory in `vllm/compilation/backends.py`, preventing reuse of already-compiled model graphs; add this runtime-only knob to `ignored_factors` so raising the chat budget does not trigger an unrelated recompilation.
