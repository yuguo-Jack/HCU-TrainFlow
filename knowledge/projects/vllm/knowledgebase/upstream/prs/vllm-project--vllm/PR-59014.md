# [Perf][FlashInfer] Reuse a persistent trtllm-gen multi-CTA-KV counter buffer for MHA

[Upstream PR](https://github.com/vllm-project/vllm/pull/59014) · state: open · merged: False

## Original PR description

## Purpose

FlashInfer's `trtllm_batch_decode_with_kv_cache` and `trtllm_batch_context_with_kv_cache` allocate and zero a fresh multi-CTA-KV counter buffer on every call when `multi_ctas_kv_counter_buffer` is not passed (`_resolve_trtllm_gen_multi_ctas_kv_counter_buffer` in flashinfer 0.7.0). With trtllm-gen, this adds a fill kernel before every FMHA call, in every full-attention layer, every step, and the fill is also captured into the CUDA graphs. The kernel resets the counters at the end of each launch, so one zeroed buffer can be reused.

This PR makes the FlashInfer MHA backend own one persistent counter buffer and pass it to both trtllm-gen entry points. The buffer is sized once for the worst-case batch (`max_num_batched_tokens` × query heads; DCP decode all-gathers heads), so it never grows after graph capture. The FlashInfer MLA backend already does this (`_get_multi_ctas_kv_counter_buffer` in `flashinfer_mla.py`). The same fix was made in SGLang (sgl-project/sglang#33063).

FLASHINFER is the default backend for non-MLA causal models on SM10x (B200/GB200/B300/GB300), so this path is hit by default there. XQA (SM90) doesn't use the counter and is unchanged.

**Duplicate check:** I searched open vLLM PRs for `multi_ctas_kv_counter_buffer`, "trtllm decode counter buffer" and "flashinfer trtllm MHA workspace". No open PR covers the MHA path.
