# [ROCm][CI] Disable RCCL RAS for the MI355 DP + EP test

[Upstream PR](https://github.com/vllm-project/vllm/pull/60727) · state: closed · merged: False

## Original PR description



## Overview

Sets `NCCL_RAS_ENABLE=0` for the MI355 mirror of "Distributed DP + EP". On the ROCm 10.0 (TheRock) stack (#58761) that job aborts at process exit.

## Claims

- Only the AMD (MI355) mirror's commands change; the H100 step is untouched.
- On ROCm 7.2 this is a no-op, since RCCL 7.2.3 has no RAS thread.

## Validation

- Before: the job failed in 2 of 2 #58761 runs (ci #92942, #93360).
- After: it passed in #58761's ci retry #93436 with this change.
- It does not reproduce on MI300X (15 clean runs on ROCm 10, 8-rank and 4-rank, plus 1 on 7.2), so CI is the only signal. One pass is not proof for an exit-time race; more runs will tell.

## Details

All 8 ranks print correct generations. Then, after Python exits, 1 to 3 ranks hit `terminate called without an active exception` (SIGABRT, `<no Python frame>`): a `std::thread` destroyed while still joinable.
- RCCL is never shut down at exit. vLLM's exit cleanup runs `ncclCommAbort` on a background thread and waits only 5 s for it, and a thread dump at exit showed that thread still in `ncclCommAbort`.
- RCCL 2.30.4 (ROCm 10 SDK) has a global RAS `std::thread` that RCCL 7.2.3 lacks.
- Its `rasTerminate()` only joins the thread if sending the stop message succeeds. That failure plausibly depends on pod networking, which would explain MI355-only.

The RAS diagnosis is inferred from disassembly; nobody has captured the native stack on MI355 yet. An RCCL issue will follow.
