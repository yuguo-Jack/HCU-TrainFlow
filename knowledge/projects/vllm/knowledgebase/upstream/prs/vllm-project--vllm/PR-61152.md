# [Bugfix][Spec Decode] Preserve target-only tokens with narrower draft vocabularies

[Upstream PR](https://github.com/vllm-project/vllm/pull/61152) · state: open · merged: False

## Original PR description

﻿## Overview

Fix probabilistic rejection sampling when the draft vocabulary is narrower than the target vocabulary in both Model Runner V1 and V2, including the CPU V1 fallback.

Fixes #61112.
Fixes #61113.

## Claims

- Treat q(token) as zero for target-only token IDs without materializing padded draft tensors.
- Prevent V1 GPU and CPU kernels from reading narrow draft-probability rows with the target row width.
- Keep the CPU override, C++ signatures, and Torch operator schemas aligned with the V1 dispatch arguments.
- Preserve the full target vocabulary in V2 ordinary, block, and watermarked recovery.
- Keep equal-width, one-hot, greedy, and synthetic verification behavior unchanged.

## Validation

The narrow-vocabulary V2 regression is parameterized over standard and block verification. The watermarked path has separate coverage.

Independent 50,000-request CUDA evaluations used target probabilities `[0.5, 0.3, 0.2]` and narrower draft probabilities `[0.3, 0.7]`:

Both recover the target-only token and match the target distribution within the predeclared 0.015 absolute tolerance.

### CPU

Built the editable CPU extension under WSL with Python 3.12 and Torch 2.13.0+cpu, including the `_C`, `_C_AVX2`, and `_C_AVX512` variants.

For the dispatch-order follow-up, Triton was removed from the isolated CPU environment and `HAS_TRITON=False` was confirmed before running:

Result: **1 passed**.

The regression launches both kernels through `KernelOverride` using the original Triton argument names, then executes the genuine CPU C++ fallback. It covers positional forwarding, residual recovery of a target-only token, and acceptance handling of a draft token ID outside the draft probability width. Static signature validation also confirms that both CPU override orders exactly match their Triton kernels.

### Static checks

Command: `pre-commit run --files csrc/cpu/spec_decode_utils.cpp csrc/cpu/torch_bindings.cpp vllm/utils/cpu_triton_utils.py tests/v1/e2e/test_cpu_spec_decode.py`

All applicable hooks passed, including ruff, formatting, clang-format, mypy, test tethering, SPDX, forbidden imports, CUDA API checks, Docker graph validation, suggestions, and DCO sign-off.

A representative review microcheck showed that padding a 128 x 5 x 66 BF16 V2 buffer to width 50,257 allocated 61.3 MiB and cost about 1.67 ms per call. The final implementation performs masked in-kernel loads and introduces no padded allocation.

## Details

The V1 kernels used the target vocabulary width as the draft row stride and residual-loop bound. Narrow draft tensors therefore caused cross-row and out-of-bounds reads. The fix passes the real draft stride and width to the acceptance and recovery kernels and returns zero for out-of-range draft probabilities.

The CPU override and C++ Torch operator schemas now accept the same dispatch arguments. The C++ acceptance path treats an out-of-range draft token as having zero draft probability, while the residual loop reads draft probabilities only below `draft_vocab_size`.

V2 previously truncated the target vocabulary to the draft width. The first patch corrected the distribution by padding the full max-capacity draft-logit buffer on every verification call, but that introduced substantial steady-state allocation and copy overhead. The final fix instead threads the draft width through the logits-statistics, acceptance, block-verification, residual, and resampling kernels and masks draft loads beyond that width to negative infinity.

The change adds no host reads, device synchronization, public API, or documentation requirement. Model Runner V1 is included because #61113 demonstrates incorrect and potentially out-of-bounds behavior on deployments that still require that runner; Model Runner V2 is independently affected by #61112.

This does not duplicate #42775. That PR adds opt-in model-loading and output masking for suffix-compatible `draft_model` pairs. This PR repairs rejection sampling for already-produced narrow probabilistic tensors, including EAGLE-style heads, in both runner implementations.
