# [Bugfix][Spec Decode] Preserve target-only tokens with narrower draft vocabularies

[Upstream PR](https://github.com/vllm-project/vllm/pull/61152) · state: open · merged: False

## Original PR description

## Overview

Fix rejection sampling when the draft vocabulary is smaller than the target vocabulary, in both Model Runner V1 and V2, including the V1 CPU fallback.

Fixes #61112 and #61113.

## Claims

- Recover tokens outside the draft vocabulary without padding draft tensors.
- Fix V1 draft-row indexing and preserve the full target vocabulary in V2 standard, block, and watermarked verification.

## Validation

Local CUDA tests ran on WSL with an RTX 3050 (8 GB), Python 3.12, and Torch 2.14.0+cu132, using the PR Python source with existing CUDA libraries.

- Sampler suites: **198 passed**, including **24 boundary cases** covering multiple draft positions and the 8,192-token block boundary.
- LLM/EAGLE regression: **2 passed with each sampler backend** (native and default), covering V1 and V2. Small generated checkpoints test a known target distribution; all 7,680 evaluated tokens per run stayed in its support, with frequencies within 0.035 of the expected probabilities.
- CPU fallback: **1 passed** with a source-built CPU extension, Torch 2.13.0+cpu, and `HAS_TRITON=False`.
- Applicable pre-commit checks passed.

```bash
python -m pytest -q tests/v1/sample/test_rejection_sampler.py tests/v1/spec_decode/test_rejection_sampler_utils.py
VLLM_PLUGINS= VLLM_USE_FLASHINFER_SAMPLER=0 python -m pytest -q tests/v1/e2e/spec_decode/eagle/test_eagle_correctness.py -k narrow_vocabulary
python -m pytest -q tests/v1/e2e/test_cpu_spec_decode.py::test_cpu_rejection_sampler_supports_narrow_draft_probs
```

With the sampler files reverted to `a7407ab4455`, the boundary test recovered token 0 instead of 8,200, and the V2 engine test never emitted the target-only token (expected frequency 0.2). Both pass with the fix. The engine test checks correctness with controlled weights, not trained-model quality.

The reporter also [retested the original CPU reproducer at `63184b36e88`](https://github.com/vllm-project/vllm/pull/61152#issuecomment-6147994136): all three cases produced 0/9,898 off-support tokens. macOS/ARM remains untested.

## Details

V1 used the target vocabulary width to index draft probabilities, which could read past narrow rows. V2 truncated the target vocabulary to the draft width, dropping valid probability mass. The fix passes the draft stride and width to the kernels and treats missing draft entries as zero probability. The CPU adapters and operator schemas are updated together.

This differs from #42775, which adds model-loading and output masking support. This PR fixes sampling from narrow draft tensors already produced by the model.
