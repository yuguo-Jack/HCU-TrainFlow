# [Bugfix][Spec Decode] Warm up adaptive verification budget kernel at startup

[Upstream PR](https://github.com/vllm-project/vllm/pull/62539) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Adaptive verification's draft-budget kernel (`_assign_draft_token_budget`, `torch.compile(dynamic=True)`) never runs at startup. Dynamo therefore compiles it during serving: on the first trimmed step, and again for each specialization it meets later. This PR compiles those specializations at startup.

## Claims

- No budget-kernel compiles during generation (main: 2 per run).
- Adaptive throughput +10% at concurrency 16, matching fixed verification again.
- About 1 s extra startup.

## Validation

`pytest tests/v1/spec_decode/test_adaptive_verification.py -v` → 18 passed (RTX 5000 Ada). The new test checks that no recompile happens under `fail_on_recompile`. It fails with `warmup()` stubbed out, and with an int32 `idx_mapping`.

`pre-commit run --all-files --hook-stage manual` passes locally, including mypy.

GSM8K 1-shot, `Qwen/Qwen3-4B` + `deepseek-ai/dspark_qwen3_4b_block7`, 7 speculative tokens, probabilistic drafts, concurrency 16, 128 prompts, RTX 5000 Ada, `TRITON_ATTN`. Main and this PR alternated:

| | Output tok/s, median (range) | Compiles during generation | GSM8K accuracy |
|---|---|---|---|
| Fixed verification (n=2) | 1,909 | – | 0.828 |
| Adaptive, main (n=5) | 1,738 (1,615–1,753) | 2 | 0.82–0.84 |
| Adaptive, this PR (n=5) | 1,914 (1,710–1,921) | 0 | 0.820 |

An earlier RTX 3090 run (Qwen3.5-0.8B) showed the same: −7.9% before, no loss after.

```python
import json
import sys

from tests.evals.gsm8k.gsm8k_eval import evaluate_gsm8k_offline

mode, conc = sys.argv[1], int(sys.argv[2])
llm = LLM(
    model="Qwen/Qwen3-4B",
    speculative_config={
        "method": "dspark",
        "model": "deepseek-ai/dspark_qwen3_4b_block7",
        "num_speculative_tokens": 7,
        "draft_sample_method": "probabilistic",
        "enable_adaptive_verification": mode == "adaptive",
    },
    max_num_seqs=conc,
    max_model_len=4096,
    enable_prefix_caching=False,
    gpu_memory_utilization=0.9,
    attention_backend="TRITON_ATTN",
)
print("=== GENERATE START ===", file=sys.stderr, flush=True)
result = evaluate_gsm8k_offline(llm, num_questions=8 * conc, num_shots=1)
print("=== GENERATE END ===", file=sys.stderr, flush=True)
print("RESULT", json.dumps({"mode": mode, "conc": conc, **result}), flush=True)
```

## Details

- Startup never reaches the kernel: `warmup_kernels` disables adaptive verification, and cost profiling never trims. Dynamo then specializes on a full batch (duck-sized to `confidence_probs`), a single request, and a budget of 1.
- `warmup()` runs batch sizes {1, max−1, max} × budgets {1, 2}. It uses the manager's real buffers and `prepare_inputs`' int64 `idx_mapping` (#60736), since guards check dispatch keys and dtypes. It's skipped on the `profile_only` pass, whose buffers are torn down.
- Not a duplicate: #59976 skips adaptive verification; #58340 only adds metrics.
