# [Bugfix][NIXL] Drain handshakes before worker teardown

[Upstream PR](https://github.com/vllm-project/vllm/pull/59960) · state: open · merged: False

## Original PR description

## Overview

Prevent NIXL worker teardown from releasing resources while background
handshakes, their callbacks, or the push writer can still use them.

### Failure workflow

1. Worker shutdown starts while a handshake or its completion callback is
   still running.
2. `shutdown(wait=False)` returns without draining that work, and teardown
   releases descriptors and clears per-engine metadata.
3. The late handshake/callback can access cleared state or publish a peer
   after cleanup has already passed it.

A completed Future does not mean its callbacks have finished. In push mode,
a timed writer join likewise does not prove the writer has stopped using its
handles. Both leave resource users running across the teardown boundary.

The fix closes admission, drains running handshakes and callbacks, and stops
the push writer before final resource cleanup. This addresses shutdown ordering,
not the cause of an earlier `RPC call to execute_model timed out`.

Related lifecycle work: #59524 (rollback of incomplete registration), #55471
(recovery of invalidated peers), and #50047 (published-peer replacement cleanup).
This change addresses teardown ordering, not those registration/recovery paths.

AI assistance was used to implement, review, and test this change. The human
submitter reports reviewing the change and personally running the related tests.
This is a Draft; native/GPU validation is still outstanding.

## Claims

- Stop admission and cancel queued handshakes once shutdown starts. Drain running
  handshakes and callbacks before releasing descriptors, agents, or registered memory.
- Do not enqueue new pull/push work from late handshake callbacks during shutdown.
- Keep repeated shutdown idempotent and avoid joining the handshake executor from
  its own thread during genuine last-reference destruction.

## Details

Shutdown closes admission under the handshake lock, then drains the executor
without holding that lock because completion callbacks acquire it. Successful
in-flight handshakes still publish their resources so final cleanup can own and
release them, but late callbacks must not enqueue new pull/push work. Queued
cancellation is not counted as a handshake failure. Push send handles are
released in final cleanup after the writer and executor drain.

The required ordering is: stop admission, finish resource users, then release
their resources. The local CPU tests exercise this ordering; they do not
establish that it fixes a particular native crash or production timeout.

**Tradeoff:** shutdown can wait for a stuck native operation. This deliberately
does not return to owners that might free/unregister backing memory while a
background operation still uses it. It does not fix or diagnose the initial
`RPC call to execute_model timed out`, promise bounded in-process shutdown, or add
transport recovery. Hung-process termination remains a supervisor responsibility.
No per-token GPU synchronization or model/scheduling change is introduced.

Duplicate checks on 2026-10-05 covered #49238 and open NIXL handshake/shutdown
PRs. #56852 drains checkpoint operations, but its ordinary shutdown still calls
the executor with `wait=False`; #42753 tests scheduler-level transfer draining.
#57987 introduces an opt-in background receiver rather than fixing this default
worker teardown path. #59877 serializes agent API calls but does not drain the
executor before teardown. These are related, not replacements for this narrowly
scoped lifetime fix; their eventual integration needs re-review.
