# [Bugfix] Avoid MLA decode shared memory OOR

[Upstream PR](https://github.com/vllm-project/vllm/pull/46728) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #46721.

This PR adds a conservative `num_stages=1` fallback for large MLA decode attention tiles on NVIDIA.

The reported failure happens in `_fwd_grouped_kernel_stage1` with:

```text
triton.runtime.errors.OutOfResources: out of resource: shared memory, Required: 102400, Hardware limit: 101376.
```

The existing NVIDIA fallback only handles `BLOCK_DMODEL >= 1024`, but the MLA path with `Lk=576` uses `BLOCK_DMODEL=512` and `BLOCK_DPE=64`, so it does not hit the existing fallback. This change keeps the existing block sizes and only reduces `num_stages` for large MLA decode tiles, which should reduce shared memory usage while keeping the fix minimal.
