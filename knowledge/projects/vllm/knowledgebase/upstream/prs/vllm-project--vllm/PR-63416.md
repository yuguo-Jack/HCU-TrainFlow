# [KV Connector][NIXL] Pair KV regions by layer for every transfer

[Upstream PR](https://github.com/vllm-project/vllm/pull/63416) · state: closed · merged: True

## Original PR description

## Purpose

NIXL pairs a peer's KV regions with the local ones in several ways, depending on the transfer:

- **By index**, for PP=1 peers: region *i* there is region *i* here, and the region group lists must match. Otherwise only pure MLA models transfer, through region-mapped reads.
- **By a PP window**, for pull from a PP stage: a slice `[offset : offset + num_local_regions]` of the peer's regions (`_remote_region_offset`).
- **By layer name**, for push from a PP stage under HMA or packed caches: `_align_remote_regions_by_layer` rewrites the peer's metadata into one region per local layer. `_compute_desc_ids` then routes blocks through `_transfer_layer_group_ids`.
- **By packed-row splitting**, when only the peer packs its rows: `_split_remote_packed_rows`, which refuses multi-group rows.

`_compute_desc_ids` has a separate mode for each: flattening, group mapping (with its handling of shared `-1` regions) and layer routing.

This PR replaces all of them with one rule: **every transfer pairs regions through the layers both sides hold.**

- Every worker advertises the layers of each of its regions (`region_members`) and the cache group of each layer (`layer_group_ids`), not only push PP stages under HMA.
- On the handshake, `_pair_regions` looks each layer up on both sides and records one pair (peer region, local region, cache group) per layer, deduplicated. A layer registered as two regions (K and V apart) pairs them in order. A region shared by several groups pairs once per group it holds a layer of. So which layers share a region no longer has to match between P and D, nor between a PP stage and the decoder.
- Group numbers are compared per layer, so a mismatch is caught even inside a region shared by several groups (group `-1`), where a per-region check cannot see it. Group ids are deterministic for a given model and config (PP stages group the whole model), so this guards against P and D having different plans, e.g. when KV page sizes unify at one TP size but not the other and the sliding-window layers fall back to full attention.
- Mamba/SSM hybrids pair the same way: attention pages and SSM sub-regions (conv sub-projections, SSM state, CSA-linear PLE page) are read from the peer region their layer pairs with. A hybrid peer with a different cache-group plan is refused at the handshake. PP stages stay refused for hybrids (not validated).
- Descriptor lists stay one per region on both sides. A peer's list keeps only its regions that pair (`_select_remote_regions`). A transfer reads or writes each pair at its group's blocks, which is the only mode of `_compute_desc_ids` for attention: `pairs=(regions, keys)`.
- When only the peer packs its rows, `_expand_remote_packed_rows` first views each row as one region per layer. That also covers rows holding layers of several groups, which `_split_remote_packed_rows` refused.
- Each pairing is kept per engine (`_dst_pairs`), and every TP rank of one engine must pair the same way.
- Refused at the handshake:
  - a peer that advertises no layers;
  - a peer missing a local layer;
  - a PP=1 peer holding layers this worker does not;
  - a layer split into a different number of regions on the two sides;
  - region metadata of different lengths;
  - a Mamba/SSM hybrid peer with any layer in another cache group.
- A non-hybrid layer in different cache groups on P and D still falls back to region-mapped reads for pull (MLA only), and is refused otherwise.
- `NIXL_CONNECTOR_VERSION` 15 → 16. A peer without `region_members` fails the compatibility hash instead of pairing by index.

Removed: `_remote_region_offset`, `_align_remote_regions_by_layer`, `_split_remote_packed_rows`, `_requires_layer_name_routing`, `_tracks_region_layers`, the `_transfer_layer_*` tuples, `_uses_region_group_mapping`, `dst_uses_region_group_mapping` and `_check_mamba_pairs`.

The pull guard for PP + HMA stays. This PR changes how regions pair, not which topologies are allowed.

### Related PRs

None of these replaces how regions pair; this PR does not duplicate them.

- #53360 adds `region_members` to the pull path for PP producers, including hybrid Mamba. It pairs each stage region with one local region, by the region's first layer, and copies every member group's blocks between those two regions. With layers of several groups sharing a region, that copies one group's KV into another group's pages. Pairing by layer, as here, avoids that.
- #56187 extends push's layer-name routing to Mamba/SSM. This PR replaces that routing, so the two conflict; Mamba pairs through the same layer pairs here instead.
- #57662 changes how regions are deduplicated at registration (by base address and block length). That is orthogonal to pairing, but both PRs touch `register_kv_caches`.
- #60113 adds support for different cache-group plans on P and D; this PR only detects them.

### Real model KV layouts (simulation)

Each model's real per-layer KV plan, built with vLLM's own planner and allocator (model on the `meta` device, `load_format=dummy`, no weights). Real NIXL workers (P and D) register those caches; D handshakes with P and reads one request (pull), or P writes it (push); every recorded descriptor pair is executed as a memory copy, then every D page is compared byte for byte with tagged data written into P, and all of D's other bytes must stay zero.

TP and PP ranks are simulated in one process. Each P and D rank builds its own KV plan and caches at its TP/PP rank (a PP engine groups the layers of all its stages, as the engine core does), and D (pull) or each P rank/stage (push) handshakes with every peer rank. Attention split across TP ranks is compared per KV head, by global head index (heads replicated when TP > KV heads); MLA pages are compared whole; TP-split SSM state is compared row by row with the P rank and position holding it, each concatenated projection split on its own (Kimi-Linear conv `[q | k | v]`, Qwen3-Next conv `[q | k | v]` with key and value sizes, Nemotron conv `[x | B | C]`; recurrent and SSM state split by head). Pages are paired by token position when P and D have different logical block sizes (Kimi-Linear: 1920 vs 1024 tokens at TP1 vs TP2). Swapping two descriptors, or swapping D's q and k conv rows after the transfer, fails the check.

- **GPU**: one GB300, real GPU attention backends.
- **CPU**: CPU attention backend, block sizes 128, or 1152/1408 after Mamba alignment. FP8 checkpoints (MiMo-V2-Flash, DeepSeek-V3, Kimi-K2, MiniMax-M2, GLM-4.5-Air) are built without their quantization config, which has no CPU kernel and does not change the KV plan. Descriptor counts are from the first CPU run (TP1, same).

Every refusal is a documented guard. "Replicated KV": with fewer KV heads than TP ranks, a non-MLA, non-Mamba transfer is refused when the side issuing it (D for pull, P for push) has the lower TP (`_validate_remote_agent_handshake`, unchanged by this PR). Kimi-Linear (as any Mamba hybrid over NIXL) needs `VLLM_SSM_CONV_STATE_LAYOUT=DS`. MiniMax-M1 is not covered: `MiniMaxM1ForCausalLM` (and `MiniMaxText01ForCausalLM`) were removed from vLLM in v0.23.

DeepSeek-V3 also passes with block-major MLA on both sides (`BLNHC`, the whole block row is one region), and with P on `BLNHC` and D on `LBNHC`, where D expands P's packed row into one region per layer (`_expand_remote_packed_rows`).

Compared with older code on the same layouts:
- `main` (merge base 4541fcdd8), GPU rows plus Gemma 3 1B and MiMo-V2-Flash PP push (CPU): same results and identical descriptor counts. Main pairs PP stages by layer name in push (`_align_remote_regions_by_layer`), which this PR replaces with the one pairing rule.
- This branch before the Mamba pairing commits (`90ec0cb5c`), CPU rows: identical descriptor ids (same digests on Qwen3-Next, Nemotron, gpt-oss, DeepSeek-V3).
- `main` before this PR, DeepSeek-V3 with P on `BLNHC` and D on `LBNHC`: identical descriptor ids. The old `_split_remote_packed_rows` and the new expansion make the same reads.

Different cache-group plans on P and D are covered by the unit tests only.

### End-to-end P/D

gpt-oss-20b, pull, P TP1 → D TP2 on one GB300 node: GSM8K 5-shot (completions) flexible-extract 0.364 through the P/D proxy vs 0.362 on a single instance without P/D; 1320 requests, 2640 NIXL reads, no failed transfers or notifications.

Found along the way, independent of this PR (also before it): Qwen3-Next and Nemotron with `VLLM_KV_CACHE_LAYOUT=BLHNC` read wrong bytes and write outside the request's blocks even with identical P and D. The likely cause is that Mamba registration in `register_kv_caches` uses `block_stride = physical_page_size`, which only holds for layer-major layouts. Auto layout picks `LBHNC` for these models, so it needs the layout forced. To be fixed or refused separately.
