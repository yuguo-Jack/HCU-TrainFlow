# [Perf][DSv4.1] Fuse the SWA KV insert into the q/kv norm; wider sorted Engram lookup tiles

[Upstream PR](https://github.com/vllm-project/vllm/pull/64609) · state: closed · merged: False

## Original PR description



## Overview

Two DeepSeek-V4.1 speedups on GB200: sorted CPU-offloaded Engram lookups use 128-row tiles, and the q/kv RMSNorm + MXFP8 kernel is reworked and inserts the SWA KV into the packed MXFP8 cache itself, replacing a separate insert launch.

## Claims

- Prefill forward step, DEP2: 0.5-2.5% faster from the Engram lookup (median -1.56% over 22 shapes), plus about 0.3-1% from the q/kv norm change.
- Decode forward step, DEP2 with DSpark k=5: 0.3-1.2% faster at 1-128 requests per rank, in both of two runs with reversed arm order.
- The q/kv norm kernel is faster or within noise at every shape measured (1-32768 tokens, q widths 1280/1536/1344), fused or not.
- The Engram lookup is bitwise unchanged. The q/kv norm rounds within 1 ulp of before.

**Numerics**
- Decode up to 192 tokens/rank: the forward output is bitwise equal to main. Larger steps differ by 1.6-4e-4 relative RMS.
- Prefill: 1.3-2.5% relative RMS, identical to 9 digits to a control that only changes main's norm kernel from 8 to 4 warps (a pure reduction-order change); an A/A run of the bench gives 0.
- GSM8K (lm-eval 5-shot, strict-match, DEP4 + DSpark k=5) with the Engram change: 0.9303 (+-0.007), acceptance length 3.39.
- `VLLM_BATCH_INVARIANT=1`: every row of a 1-1024 token batch matches the same row in a 3000-token batch bitwise (without it, 1-4 KV elements differ at 511-1023 tokens).

## Details

**Engram lookup.** A sorted lookup (>= 36864 rows, prefill sized) is bound by host-read latency; 128 rows per program keep 8x the reads in flight.

**q/kv norm.**
- The kernel keeps its structure; it now normalizes several rows per program and sizes Q and KV blocks separately (KV no longer pads to the Q width).
- Launch shape: one row per program below 1024 tokens (8 warps below 512), four rows from 1024. With `VLLM_BATCH_INVARIANT` it stays at one row and 8 warps for every batch.
- With a packed MXFP8 SWA cache (`kv_mxfp8`, no PCP), `_split_qkv_and_norm(qr_kv, positions)` passes the insert to the kernel and returns `kv=None`; callers skip their insert. This covers `forward` (prefill, decode, mixed), `forward_kv` (decoder replay) and the specialized decode.
- `_fused_qnorm_rope_kv_insert` with `kv=None` returns Q as is when the attention kernel owns its RoPE and padding (MegaAttn at full heads), else runs the existing op for Q alone.
- The Triton insert reproduces the CUDA insert byte for byte (RoPE contracted as nvcc does).
- The ROCm override and the test stubs of `_split_qkv_and_norm` take the new `positions` argument; ROCm never fuses.

**Tradeoffs.** Results move by up to 1 ulp versus main (test tolerances updated).

Not a duplicate: #64500 prefetches offloaded Engram rows for eager prefill and keeps the lookup tiling; #62365 (batch invariance) bypasses this kernel by default; its MXFP8 prequant mode stays batch invariant through the fixed launch shape. No open PR changes this kernel or fuses the SWA insert.
