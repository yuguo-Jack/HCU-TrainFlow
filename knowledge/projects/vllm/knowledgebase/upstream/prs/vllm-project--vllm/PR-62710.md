# [Doc] Fix Kimi-K3 GB300 disaggregated selector and guide gaps

[Upstream PR](https://github.com/vllm-project/vllm/pull/62710) · state: closed · merged: True

## Original PR description

## Overview

Follow-up to #62563 and #62528 for the Kimi-K3 GB300 disaggregated (xPyD) Dynamo + vLLM profile from [SemiAnalysisAI/InferenceX#4047](https://github.com/SemiAnalysisAI/InferenceX/pull/4047). It fixes the gaps an independent review found after #62563 merged. It changes only `recipes/models/moonshotai/Kimi-K3.yaml`.

## Claims

- **Selector (GB300 + Prefill/Decode + Dynamo):**
  - Restates the startup timeouts the qualified workers ran with (`VLLM_ENGINE_READY_TIMEOUT_S=3600`, `VLLM_EXECUTE_MODEL_TIMEOUT_SECONDS=1800`, `VLLM_RPC_TIMEOUT=600000`). The `pd_cluster` Blackwell block replaces the recipe baseline, so they were dropped, and a load plus autotune takes about 25 minutes.
  - Sets `UCX_TLS=all` on GB300, overriding the Blackwell PD block's `rc,cuda_copy`. The qualified workers left UCX on its defaults.
- **Guide, Dynamo parser flags:** the GB300 worker note told users to add `--enable-auto-tool-choice --tool-call-parser kimi_k3` to `python3 -m dynamo.vllm`. At the pinned Dynamo (`ffbbaaa6`), `components/src/dynamo/vllm/args.py` parses leftover arguments with an `AsyncEngineArgs`-only parser (L103-126), so those API-server flags are rejected. The guide now gives the qualified flags: `--reasoning-parser kimi_k3 --dyn-tool-call-parser kimi_k3 --dyn-reasoning-parser kimi_k3 --dyn-enable-structural-tag`.
- **Guide, builder pointer:**
  - Keep the default TP pools on GB300. The DEP decode pool renders TP1 with DCP8, which vLLM rejects.
  - Leave **Spec decoding** off: the profile already carries the qualified DSpark K4 draft, and the toggle swaps in the unqualified RedHat K8 draft.
  - Untick **Tool calling**.
  - The builder decode's `--max-num-seqs 8` is the 1P2D row.
  - The guide now lists what stays guide-only: the qualified MultiConnector and Mooncake services, prefill KV events, and the router mode and session affinity.
- **Guide, environment:** adds `DYN_TCP_REQUEST_TIMEOUT=120`, `ETCD_LEASE_TTL=600` and the three timeouts, as the qualified workers and frontend ran. It also names the `X-Dynamo-Session-Id` session header.
- **Guide, low-latency section:** TP16/DCP16 at concurrency 1 and TP8/DCP8 at concurrency 2 and 4, matching the InferenceX lane. The text previously said "1 or 2" and "2 or 4".
- Bumps `meta.date_updated`.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` passes in vllm-project/recipes.
- I rendered every variant × GB300/GB200/B300/B200/H200/H100/MI355X/MI300X × compatible strategy × feature set × router (864 renders) on main and on this branch. Only the 66 GB300 Prefill/Decode renders change, and only in env.
- Qualified evidence: InferenceX #4047 run [39140771499](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/39140771499).

## Details

**Not changed in the selector:** the spec-decoding toggle conflict. `features.spec_decoding.hardware_overrides` applies to every GB300 strategy, so moving the K4 draft there would change unqualified GB300 TP and TEP renders. The guide documents it instead.

**Related:** the builder's Dynamo PD path passes vLLM API-server parser flags to `dynamo.vllm` for every recipe. That is reported in vllm-project/recipes as a separate issue.
