# [Bugfix][EC Connector] Don't create hash directories on cache-miss lookups in ECExampleConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/60826) · state: closed · merged: True

## Original PR description

## Purpose

`ECExampleConnector.has_cache_item()` resolves the safetensors path via
`_generate_filename_debug()`, which auto-creates the `<mm_hash>/` directory.
Since `has_cache_item()` is called from the scheduler's encoder-input
admission check and from `update_state_after_alloc()` on every multimodal
allocation, **every probed-but-missed hash leaves an empty directory in
shared storage**. On a long-lived deployment the EC storage root accumulates
one empty directory per unique missed hash, making the cache impossible to
inspect and polluting any listing-based tooling/backup jobs.

Fixes #60820

## Approach

Keep auto-creation on the **save** path (where the directory is actually
needed) and disable it on the **lookup** path:

- `_found_match_for_mm_data()` now passes `create_folder=False` to
  `_generate_filename_debug()`.
- `_generate_filename_debug()` gains a `create_folder: bool = True`
  parameter, forwarded to `_generate_foldername_debug()`. Defaults are
  unchanged, so `save_caches()` / `start_load_caches()` behavior is
  identical.

No behavioral change beyond the filesystem side effect.

## Testing

- Added `test_has_cache_item_miss_creates_no_folder` to the existing
  `tests/v1/ec_connector/unit/test_ec_example_connector.py`: a cache-miss
  lookup leaves no empty folder in shared storage.
- Also verified on a live A100 EPD testbed against a producer-role
  connector: `VERIFY-OK`.

## Notes

- Observed on a live deployment; the same code paths exist on current main.
- `start_load_caches` is untouched: it only loads hashes that
  `has_cache_item()` has already confirmed to exist.
