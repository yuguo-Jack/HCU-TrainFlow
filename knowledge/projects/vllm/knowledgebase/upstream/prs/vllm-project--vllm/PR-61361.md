# [MORI] Add MORI EP V2 support

[Upstream PR](https://github.com/vllm-project/vllm/pull/61361) · state: open · merged: False

## Original PR description

## Overview

Adds `--all2all-backend mori`, an expert-parallel all2all backend that runs MoRI EPv2 (`mori.ops.dispatch_combine_v2`) where it is supported and MoRI EPv1 otherwise. EPv2 dispatches and combines tokens through a MoRI CCO symmetric-memory window, so all EP ranks must sit in one load/store-accessible (LSA) team, e.g. one node.

`VLLM_MORI_EP_V2` selects the version. Unset, `mori` prefers EPv2 and falls back to EPv1 with a warning when the EP size exceeds 8 (except on gfx1250, whose UALink team can span hosts), `MORI_ENABLE_SDMA=1`, `--moe-backend aiter_mega_moe`, or a non-BF16 model. `1` forces EPv2 and `0` selects EPv1. The choice is made once in the ROCm platform's config hook. On EPv1 across nodes, `mori` uses InterNodeV1LL when the per-rank token budget is at most `VLLM_MORI_DISPATCH_INTER_KERNEL_SWITCH_THRESHOLD` (default 256), and InterNodeV1 otherwise.

The existing MoRI backends (`mori_high_throughput`, `mori_low_latency`) are unchanged and always run EPv1.

## Claims

- On DeepSeek-V4-Pro with DP8+EP8 on 8× MI355X, `mori` on EPv2 matches TP8 and the existing MoRI EP backend on GSM8K and gives about 3.9× the output throughput of `mori_high_throughput`.
- Triton MoE: `TritonExperts.moe_sum` now skips unrouted (`-1`) top-k slots whenever `topk_ids` is given, not only under an `expert_map`; the alignment never computes those slots, so their scratch rows were summed unwritten. Dynamic per-tensor FP8/INT8 also clears that scratch first, so the unwritten rows do not enter the shared activation scale.

## Validation

DeepSeek-V4-Pro, 8× MI355X, `--moe-backend aiter`, CUDA graphs, MoRI main.

| Backend | Parallelism | GSM8K (lm-eval, 1319 q, 5-shot, strict) | Output tok/s (random 1k/1k, c64) |
|---|---|---|---|
| default | TP8 | 0.950 | — |
| `mori_high_throughput` | DP8+EP8 | 0.958 | 530 |
| `mori` (EPv2) | DP8+EP8 | 0.955 | 2054 |

GSM8K ran with 4096 max new tokens, so about 33 answers per backend were cut off before the final answer. Absolute scores are lower than with a longer budget, but the backends are comparable to each other. The eager mode (`--enforce-eager`) start-up also passed.

- Duyi-Wang · comment · 2026-10-16T09:27:50Z · [source](https://github.com/vllm-project/vllm/pull/61361#discussion_r4293016658)

File: `vllm/distributed/device_communicators/all2all.py` · line None

[P1] Broadcast the CCO unique ID from the EP group's rank 0

`self.rank` above is group-local, but `src=0` here denotes global rank 0. With PP=2, DP=2, TP=1 on a single node, the EP groups are `[0, 2]` and `[1, 3]`. The second stage generates its UID on global rank 1, then this broadcast raises `ValueError: Global rank 0 is not part of group`, preventing startup even though each EP group fits within one LSA team.

Please use `group_src=0`, or translate group-local rank 0 to its global rank before passing `src`. I reproduced this by executing this method with four CPU/Gloo processes and a mocked CCO communicator; the original fails on ranks 1 and 3, while `group_src=0` passes on all four. The current manager test mocks out `broadcast_object_list`, so it does not catch this subgroup case.
