# [ROCm][Bugfix][MLA] Fix FP8 MLA prefill unpad for interleave-padded heads

[Upstream PR](https://github.com/vllm-project/vllm/pull/60907) · state: closed · merged: True

## Original PR description

## Overview
The gfx950 FP8 asm MLA prefill pads heads to a multiple of 16. When the target is a multiple of the real head count (8 → 16, e.g. Kimi-K2.x at TP8), `get_mla_padded_q` uses `repeat_interleave`, but the output was sliced back as `[:, :num_heads]`, which is only correct for tile padding. The model then attends with the wrong heads and produces garbage. Introduced by #51040.

## Claims
- Restores accuracy for interleave-padded head counts: Kimi-K2.6 MXFP4 TP8 GSM8K 0.027 → 0.933.
- No performance change: same kernels; the unpad copy is still one kernel at the same cost.
- Adds the 8-head (interleaved) case to `test_rocm_aiter_mla_fp8_prefill.py`.

## Validation
Kimi-K2.6-MXFP4, TP8, MI355X, fp8 KV cache. GSM8K 5-shot, `lm_eval --model local-completions ... --tasks gsm8k --num_fewshot 5`, num_concurrent=64:

| | flexible-extract | strict-match |
|---|---|---|
| Before (upstream main) | 0.0273 ± 0.0045 | 0.0235 ± 0.0042 |
| After (this PR) | 0.9333 ± 0.0069 | 0.9333 ± 0.0069 |

Torch profiler, random 1024/1024, 64 prompts, concurrency 64: 40 kernels per prefill MoE layer before and after.

Unit test on MI355X: `pytest -v tests/kernels/attention/test_rocm_aiter_mla_fp8_prefill.py`

| Code under test | Result |
|---|---|
| This PR | 12 passed |
| Upstream unpad, with the new test cases | 2 failed, 10 passed: only `test_fp8_prefill_matches_reference[128-8]` and `[512-8]` fail |

<details>
<summary>Failure details on the upstream unpad</summary>

- `[128-8]`: mismatched elements 81,670 / 131,072 (62.3%), greatest absolute difference 4.5 (atol 0.1)
- `[512-8]`: mismatched elements 230,240 / 524,288 (43.9%), greatest absolute difference 4.5 (atol 0.1)
- All tile-padded (12, 24) and unpadded (16) cases pass on both versions.
</details>

## Details
Real heads sit at stride `nhead // num_heads` after `repeat_interleave` and at `[0:num_heads]` after tiling; the fix selects accordingly. Existing test head counts (12, 16, 24) only exercised tile padding.
No duplicate: no open issue or PR addresses this; #59966 changes `get_mla_padded_q` but keeps `repeat_interleave` for the divisor case.
