# [CI][Test] Skip multi-node-only pipeline-parallel cases at collection

[Upstream PR](https://github.com/vllm-project/vllm/pull/65443) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

In `tests/distributed/test_pipeline_parallel.py`, skip the multi-node-only cases at collection instead of inside the fresh process that `create_new_process_for_each_test` starts for every case.

## Claims

- The ten `microsoft/Phi-3.5-MoE-instruct` cases of `test_tp_language_generation` are `multi_node_only`. On single-node CI each started a new interpreter and then skipped. All ten now skip in 0.57 s instead of 101.8 s on MI300X.
- Test IDs, the `-k "ray"` selection used by the RayExecutorV2 jobs, and the multi-node run (`VLLM_MULTI_NODE=1`) are unchanged.
- Expected CI saving: about 2 minutes per build in (MI250) Pipeline + Context Parallelism (the ten cases took about 11.5 s each in the vllm/ci build 99098 log) and about 1 minute per run in the RayExecutorV2 jobs, which select the five Phi-MoE `ray` cases.

## Validation

Environment: CI image `rocm/vllm-ci:build-01a19b0e-d62f-4889-8556-b5c2d4478cbf` (vllm/ci build 99098), MI300X. One run per row (n=1). No server is started by these commands.

Commands run:

```bash
pytest -q -rs distributed/test_pipeline_parallel.py -k "test_tp_language_generation and Phi-3.5-MoE"
pytest --collect-only -q distributed/test_pipeline_parallel.py
pytest --collect-only -q distributed/test_pipeline_parallel.py -k ray
VLLM_MULTI_NODE=1 python -c "from tests.distributed.test_pipeline_parallel import TEXT_GENERATION_MODELS as M; ps = list(M['microsoft/Phi-3.5-MoE-instruct'].iter_params('microsoft/Phi-3.5-MoE-instruct')); print(sum(m.args[0] for p in ps for m in p.marks))"
pre-commit run --files tests/distributed/test_pipeline_parallel.py
```

| Command | Before (main) | After (this PR) |
|---|---|---|
| Phi-MoE cases | 10 skipped in 101.76s | 10 skipped in 0.57s |
| `--collect-only` | 29 test IDs | the same 29 IDs, plus `test_pp_mixed_precision_kv_cache`, which landed on main after this image was built |
| `--collect-only -k ray` | 10 test IDs | the same 10 IDs |
| `VLLM_MULTI_NODE=1`: Phi-MoE cases marked skip | 0 of 10 | 0 of 10 |
| pre-commit | - | all hooks passed |

The cases that run are untouched (same parameters, same code path), so none was rerun for this PR.

CI coverage: the file runs in Pipeline + Context Parallelism (L4, nightly; its MI250 mirror on every PR), the RayExecutorV2 jobs (`-k "ray"`, L4 nightly, MI355 and MI300) and the multi-node job (`VLLM_MULTI_NODE=1`). No model output changes, so no model evaluation applies.

## Details

- `PPTestSettings.iter_params` now yields `pytest.param(..., marks=skipif(multi_node_only and not VLLM_MULTI_NODE))` instead of a bare tuple. Every case keeps its parameters and its ID.
- The existing check inside `_compare_tp` stays; it is no longer reached on a single node.
- On NVIDIA these cases fork instead of spawning, so the saving there is smaller.
- `tests/distributed/test_context_parallel.py` checks `multi_node_only` the same way, but none of its configured models sets it, so it is left as is.
- Not a duplicate: I searched open PRs for "test_pipeline_parallel" and "multi_node_only"; none changes this parametrization. #64784 edits `_compare_tp` in the same file but touches different lines.
- AI assistance: this change and this description were prepared with an AI coding assistant (Cursor). The submitter reviewed every changed line and ran the commands above.
