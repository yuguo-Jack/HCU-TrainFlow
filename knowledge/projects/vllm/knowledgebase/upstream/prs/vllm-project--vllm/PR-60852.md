# [Bugfix][MoRIIO] Handle WRITE cancellation before submission

[Upstream PR](https://github.com/vllm-project/vllm/pull/60852) · state: open · merged: False

## Original PR description



## Overview

Fix MoRIIO WRITE cancellation when a live producer is aborted after decode allocates KV blocks but before the first transport submission. Related: #59382. Depends on #57705 and #59058.

This PR includes those dependency commits with their original authorship preserved. The zero-submit fix is [one separate commit](https://github.com/yuzhouo7/vllm/commit/61f4b4ef2c4b98b499fea35dddcc6251cedb344d); the full PR diff also includes the dependencies.

## Claims

- Forward producer cancellation to workers and serialize it against the first WRITE submission.
- If cancellation wins, send `write_failed`, acknowledge release once per producer rank, and free the request once per scheduler. Duplicate late allocation/failure messages do not repeat completion or free within the retained transfer history.
- Once submission starts, cancellation adds no synthetic failure or release. Submitted handling remains unchanged; partial-submit safety is not established.

This covers live-producer cancellation, beyond #57705's deferred timeout and #59058's late `write_done` after decode abort. #58962's producer-loss watchdog remains separate.

<details>
<summary>GPU lifecycle counts and evidence limits</summary>

The six candidate cases were normal, queued cancellation, known-allocation cancellation, late-allocation cancellation, submitted control, and submitted abort. Baseline/candidate pairing at both topologies covers normal and queued cancellation; this is not a full six-case A/B matrix.

For each zero-submit case, every P rank made zero transport submissions and received one release ACK; every D rank emitted one failure completion. Each P/D scheduler freed the request once. D's 17 logical blocks reached refcount zero with no owners. P owned 0/17/16 blocks in queued/known/late cases respectively; the queued empty free is valid.

Late allocation delivered two failure notifications per D rank, with one completion and no residual unmatched failure. Normal and submitted controls made 64 transport returns per P rank. Counts exclude separately identified probes. Offline receipt review corrected probe attribution and a submitted-control oracle that incorrectly expected one return; tested source was unchanged.

Completed-ID history is bounded to 4096 entries. These runs do not establish safety after arbitrary history eviction/replay or transfer-ID reuse.

</details>

## Details

D allocates blocks and enters remote-KV wait; P is then cancelled while queued or before its first WRITE. Previously P sent no terminal failure, so D could become `FINISHED_ABORTED` while retaining its receive mapping and blocks. The fix orders cancellation against submission, notifies D, and waits for worker ACK before scheduler reclamation.

The change stays in MoRIIO's common state, connector and writer; it does not change shared scheduler code. The cross-component state is needed because the scheduler owns blocks and the writer knows whether submission has begun. Producer death, heterogeneous TP, partial-submit recovery, cross-host qualification and physical fencing remain out of scope.
