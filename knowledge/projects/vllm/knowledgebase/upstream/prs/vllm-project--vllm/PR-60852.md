# [Bugfix][MoRIIO] Handle WRITE cancellation before submission

[Upstream PR](https://github.com/vllm-project/vllm/pull/60852) · state: open · merged: False

## Original PR description

## Overview

Fix MoRIIO WRITE cancellation before the first submission, so an aborted producer can release a waiting decode request. Depends on #59058; related: #59382.

## Claims

- Serialize cancellation with one shared, irreversible submission gate across targets and layers. Pre-submit cancellation makes zero WRITE attempts and releases once; any possibly accepted attempt, including a submit exception, retains ownership.
- Preserve #61726's sessions, TP mapping, routing, writer counts and attention/Mamba paths. Cancellation remains homogeneous-TP only; #58962 stays separate.

## Details

Flow: D allocates blocks → P aborts with WRITE queued → P worker sends `write_failed` and a release ACK if cancellation wins. A later target/layer failure cannot reset a transfer to zero-submit after an earlier attempt.

**Unverified:** GPU/serving, DMA fencing, safe reuse after partial submission or peer death, heterogeneous cancellation and transfer-ID reuse. `request_terminal != io_quiescent`; ambiguous submissions may remain held indefinitely. Newer main commits are not covered by this pinned replay.
