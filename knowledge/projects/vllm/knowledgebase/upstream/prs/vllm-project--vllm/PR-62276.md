# [ROCm][CI] Bump the ROCm 10 image to torch 2.13

[Upstream PR](https://github.com/vllm-project/vllm/pull/62276) · state: closed · merged: True

## Original PR description

- Bump `TORCH_VERSION` to `2.13.0+rocm10.0.0` and `TORCHVISION_VERSION` to `0.28.0+rocm10.0.0` in `Dockerfile.rocm_base`
- Release the piecewise CUDA graphs on ROCm in Model Runner V2's `shutdown()` before distributed teardown, as the V1 runner already does

When #58761 made the TheRock image the default, AMD CI went from torch 2.13 (the ROCm 7.2 image, bumped in #50605) back to 2.12, because the TheRock Dockerfile never got that bump. #61118 sets `torch._inductor.config.batch_invariant`, which only exists from torch 2.13, so every engine started with `VLLM_BATCH_INVARIANT=1` died with `AttributeError: torch._inductor.config.batch_invariant does not exist` (Batch Invariance on MI250/MI300/MI355, the DPX LoRA shards, LoRA TP and Spec Decode Draft Model since https://buildkite.com/vllm/ci/builds/95651). #62274 now skips the setting when torch lacks it; this restores the inductor batch-invariant mode on ROCm. This goes to 2.13 rather than 2.14, which is what the ROCm 7.2 image runs: 2.14's ATen headers require C++20, while the pinned flash-attention builds its ROCm extension with `-std=c++17`, so the base image fails to build with 2.14 (https://buildkite.com/vllm/ci/builds/95690). This supersedes #59658, which made the same bump against `Dockerfile.rock_base` before #58761 renamed it.

`:amd: (MI355) Distributed DP + EP` still aborts at exit with `terminate called without an active exception` after #62241 (https://buildkite.com/vllm/ci/builds/95767). The MoE all-gather on the DP group is captured in the piecewise graphs, and RCCL's `ncclCommAbort` waits until every graph that captured the communicator is destroyed (ROCm/rocm-systems#13018). The V2 runner never released them, so the abort hung on every rank with a cold compile cache, `PyNcclCommunicator.destroy()` gave up after its 5 s join, and the process exited with the abort still inside RCCL (stack: `ncclCommAbort_impl -> commReclaim -> commDestroySync -> condition_variable::wait`). On 8x MI355 with the CI command and a fresh cache each run, the abort now finishes in under 1 s in 10/10 runs with every PyNccl communicator destroyed, and the `Distributed Torchrun + Shutdown` commands and the V2 runner tests pass. As in V1, `clear_all_graphs()` is process-wide.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
