# [XPU][Attention] Route multimodal prefix masks through the Triton/FlashAttention composite

[Upstream PR](https://github.com/vllm-project/vllm/pull/62014) · state: open · merged: False

## Original PR description


## Purpose

On XPU, multimodal prefix-LM models (Gemma 3/4) run Triton attention for every batch: the SYCL FlashAttention kernel cannot apply the image mask, and `Gemma4Config` forces `TRITON_ATTN` when FA4 is unavailable. Only image batches need the mask; text prefill and decode pay for Triton for nothing (3–4× slower per attention call than SYCL FlashAttention on Arc Pro B70).

Reuse the Triton/FlashAttention composite from #56305: image-masked batches → Triton, causal batches → FlashAttention, shared KV cache.

- `FlashAttentionBackend.supports_head_size`: allow ≤ 512 on XPU (SYCL kernels support 512; Gemma 4 global layers).
- `TRITON_FLASH_ATTN` composite: FA3/FA4 and Hopper requirements apply to CUDA only (`device_major` moved into the FA route's `supports_compute_capability`; CUDA selection unchanged).
- `platforms/xpu.py`: select the composite for mm-prefix models with head size 256/512 and bf16/fp16 when no backend is requested; float32 or other head sizes fall back to Triton.
- `Gemma4Config`: no longer forces `TRITON_ATTN` on XPU. Side effect: with multimodal disabled, Gemma 4 defaults to FlashAttention.

No kernel changes.

## Test Plan

- Backend selection checked on XPU: composite for head 256/512 with image mask; Triton for head 128 and float32; FlashAttention without image mask. No unit test in this PR.
- 4× Arc Pro B70, TP=4, `--enforce-eager`, vLLM 0.32.0rc1 nightly: Gemma-4-26B-A4B text-only prefill (16 × 2048) and decode (bs32, 128/256) with `--attention-backend TRITON_ATTN` vs new default; Gemma-4-31B greedy outputs on image and text prompts, both backends.
- Not covered: graph mode, mixed image+text batches.

## Test Result

- Text-only 26B: prefill 8.9k → 11.8k tok/s (+32 %), decode 385 → 576 tok/s (+50 %).
- Images, 31B: composite selected (`TRITON_FLASH_ATTN`, block 64); 4/7 greedy outputs identical to Triton-only, the rest diverge after 21–47 identical tokens (within TP=4 run-to-run variation); 21.9 s → 16.6 s for the set.
- Decode traces: Triton attention 283 µs (26B) / 399 µs (31B) per call at bs64 vs ~60 / 95 µs SYCL FlashAttention; with graphs, FlashAttention is 25–41 % faster end to end at bs32–64 on 26B.
