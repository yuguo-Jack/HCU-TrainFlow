# [EPLB] Add expert backup region and descriptor primitives

[Upstream PR](https://github.com/vllm-project/vllm/pull/49573) · state: open · merged: False

## Original PR description

## Summary

This is a deliberately transport-independent PR0 for #41204:

- pack named expert tensors into one aligned, contiguous CPU byte region
- describe every tensor with absolute address, byte count, shape, and dtype
- serialize/deserialize `ExpertBackupDescriptor`, including opaque NIXL agent metadata
- reconstruct zero-copy typed tensor views from a local region + round-tripped descriptor
- optionally allocate pinned host memory for a later NIXL registration layer

No sidecar process, ZMQ socket, NIXL registration, CLI flag, failure recovery, or inference-path behavior is enabled in this change.

## Why split this out?

The proposed manager/client protocol requires both sides to agree on byte layout and descriptor semantics before transport integration. Keeping this layer CPU-only makes address/offset, alignment, dtype, shape, deterministic serialization, and corrupt-descriptor behavior reviewable and testable without GPUs or NIXL.

## Validation

- `ruff format` and `ruff check` pass for both added files
- remote H20 node (`lingjun-101`) direct-cloned commit `50e806f`
- Python 3.12 `compileall` passed
- in the existing vLLM/PyTorch H20 image, packed float32 + bfloat16 tensors into a 64-byte-aligned region, checked byte-identical typed views, descriptor round-trip equality, and zero-copy pointer identity
- unit tests cover layout/views, deterministic descriptor round-trip, invalid alignment, and corrupt descriptors

2. ZMQ publication and client validation
3. batched remote READ into local expert slots
4. rank-failure injection and EPLB recovery wiring
