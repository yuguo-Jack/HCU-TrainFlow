# [Core][KVConnector] Connector "ready" state for asynchronous connector startup

[Upstream PR](https://github.com/vllm-project/vllm/pull/62337) · state: open · merged: False

## Original PR description

Cleaning up implementation in https://github.com/vllm-project/vllm/pull/51414/ while addressing some of the limitations rightfully pointed out re: block allocation tracking.
To recap, this PR only covers the interface changes required to allow connectors to initialize asynchronously (`is_ready` behaviour), so that the various implementations we support can opt in with ad-hoc methods.

One of the differences wrt original PR is how connectors can opt-in ie
```
class MyAsyncConnector(SupportsAsyncInit):  # instead of KVConnectorBase_V1
    def __init__(self, vllm_config, role, kv_cache_config):
        super().__init__(vllm_config, role, kv_cache_config)
        if role == KVConnectorRole.WORKER:
            # Connector-specific: start slow setup however suits the connector (Future here).
            self._init = ThreadPoolExecutor(1).submit(self._allocate_host_buffers)

    def is_init_done(self) -> bool:
        # Polled on workers each step until True; raising here (or exceeding
        # VLLM_KV_CONNECTOR_INIT_TIMEOUT) fails the engine.
        if self._init.done():
            self._init.result() 
        return self._init.done()
```

A connector that is either ready or does not initialize asynchronously should have zero-overhead from the scaffolding added here.
