## Original PR description

# [Bugfix][HiSparse][NIXL] Leave unaligned host-import tails for local prefill

## Problem

NIXL pull advertises the whole prompt as externally computed. The host-only
HiSparse resident manager requires imported prefixes to end on a cache-block
boundary. A 32,019-token prompt with block size 64 therefore raises:

```text
ValueError: A host-only HiSparse import must end on a cache-block boundary.
```

This escapes scheduler admission and kills the decoder engine. It was observed
on unmodified main `a08dffe21534916f218dcc93012dbaa01f942691`, on 1P TP8 + 1D
TP8, two 8xB200 nodes, using `nvidia/GLM-5.2-NVFP4` with HiSparse on D. The
new regression also fails on this patch's base, main
`9d14fd3095eb169044e2da0a2a98dd1f2c77ce22`.

## Change

- For host-only HiSparse pull imports, advertise only complete pages, aligned
  across resident and transferable cache groups.
- Omit the unimported tail from local destinations and remote source lists.
  The remote cap is applied after logical-to-kernel block expansion, before
  prefix-cache suffix matching. Rounding the count alone would shift reads
  toward the remote tail and copy the wrong blocks.
- Let normal local prefill compute the remaining tokens. No truncation of the
  user's prompt and no changes to CUDA-graph or memory-utilization settings.
- Keep notify-only receives valid when no complete block can be imported.

For 32,019 tokens / block size 64, import tokens `[0, 32000)` and compute
`[32000, 32019)` on D. Normal non-HiSparse imports retain their existing behavior.
This targets the P-to-D pull path, not bidirectional D-to-P or push admission.

```bash
  -k 'hisparse_import or nixl_hisparse' -q
```

- Final patched targeted selection, including allocation/resume and DCP

Pre-commit passed on all six changed files, including the configured mypy hook.

## Model evaluation and limitations

A B200 smoke using 32,019-token prompts completed **4/4 requests with HTTP
200**, without the admission exception or engine exit. Decoder logs showed
**64 successful NIXL transfers**, **99.9% external prefix-cache hits**, and
7.6 prompt tokens/s over the reporting interval (the four 19-token tails).
The source files on D matched this commit byte-for-byte; both roles used the
pinned main `ve` environment, with this patch applied only to D.

However, **0/4 copy-word accuracy cases passed**: the prefiller reference
returned the requested words, while D's output was garbled. The earlier
aligned plain-main test also failed all four cases. This establishes the
admission fix and real transfer activity, **not end-to-end P/D correctness**.
This patch does not claim to fix that separate correctness issue. No
performance improvement is claimed.
A follow-up with 63-token prompts (no complete block to import) also completed
4/4 requests, and both servers remained healthy. Its copy-word accuracy was
again 0/4; the no-import fallback is not evidence that output correctness is
fixed.
DCP/heterogeneous-topology model evaluation has not been run for this patch.

This does **not** claim to fix #56699's `cudaErrorLaunchFailure` or the
FULL-graph host-mirror problem addressed by #56158.
