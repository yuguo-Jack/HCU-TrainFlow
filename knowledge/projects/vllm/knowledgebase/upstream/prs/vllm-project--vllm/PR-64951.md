# [Bugfix][Spec Decode] Preserve windowed draft AOT guard after cache promotion

[Upstream PR](https://github.com/vllm-project/vllm/pull/64951) · state: open · merged: False

## Original PR description



## Overview

Keep the existing DFlash windowed-draft FA3 AOT safeguard after full cache allocation. Use the draft implementations' computation windows when the allocation-spec helper no longer reports one.

## Claims

- Preserve the disabled AOT schedule for windowed DFlash/DFlash2/DSpark computation after cache promotion.
- Keep full-attention drafts enabled even when a shared allocation spec inherits a target window; leave the allocation helper unchanged.
- Also disable AOT when Laguna DFlash clears its allocation window but retains windowed computation, including without cache promotion; verified with a real-constructor control.

## Validation

On H100, the new LLM regression fails on public base7b77ed581 with `assert True is (128 is None)` for the promoted windowed draft. Candidate0a693f7b2 passes4tests: three real-constructor allocation controls and a three-arm LLM regression with nonzero speculation and FULL graph dispatch.39neighbor/allocation-helper contract tests pass. Normal hooks, mypy, CI tethering and DCO pass.

```sh
.venv/bin/python -m pytest -vv -s tests/v1/e2e/spec_decode/test_dflash_fa3_aot.py
```

The trained Qwen3-4B/DFlash-b16 head is explicitly configured with a128-token window through native hf_overrides for this regression; this changes its released full-attention computation. It is not qualification of a released window-trained checkpoint. In a first32-question, five-shot GSM8K screen, base/promoted, candidate/promoted and candidate/native all score29/32 with1101drafts/3391accepted tokens. Both upstream logprob comparisons pass; all32token sequences match in this run. Draft/acceptance counters are also identical: this fixture does not reproduce #54374's wrong-geometry case, and target GSM8K accuracy does not measure draft quality. Motivation is preserving that merged safeguard policy. No numerical improvement or speedup is claimed; affected-path runtime cost is unbenchmarked.

## Details

FullAttentionSpec retains a window after promotion, but a merged group's field may come from the target. The existing allocation helper deliberately returnsNone for full allocation. Retain that helper and check the group's own draft Attention layers as a startup fallback. Laguna DFlash clears the layer allocation field while its implementation keeps computing windowed, so read implementation variants rather than that field. A real-constructor control reproduces that allocation-only override; a Laguna checkpoint run is not qualified. The extracted startup helper permits real-constructor inverse controls without fabricating a speculator. No steady-state instrumentation is added.

[#54374](https://github.com/vllm-project/vllm/pull/54374) added the original guard. Open[#64404](https://github.com/vllm-project/vllm/pull/64404) generalizes it to other drafters/builders but retains the promoted-window gap; it conflicts with this block. If it lands first, move this draft-layer predicate into its shared helper and repeat the tests before submitting. This patch targets the existing DFlash-family guard only.
