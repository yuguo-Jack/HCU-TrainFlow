# [HiSparse] Standardize terminology and add a nomenclature to the design doc

[Upstream PR](https://github.com/vllm-project/vllm/pull/59465) · state: open · merged: False

## Original PR description

## Purpose

Standardize HiSparse terminology and document it. Several concepts had two or three names each (e.g. "spill", "materialize" and "write back" for the same copy; "valid" and "clean" for the same page state; "reuse" meaning both a prefix hit and the pool reallocating a block), which made reviews harder than they needed to be.

Draft: this touches the same coordinator code as in-flight HiSparse PRs, so it should land after them.

## Changes

- **Design doc:** a new nomenclature section in `docs/design/hisparse.md`, one line per term, noting where code names differ. The doc's prose is aligned with it, and the write-back transaction and ownership table now describe scheduler-owned residency updates (#60647) instead of block-table edits.
- **Renames (no behavior change):**
  - `spill` → **write-back** for the GPU-to-host page copy, which runs eagerly every step, not only under memory pressure. The tracked object, which also covers restores, is a **page transfer**: `_PendingSpill` → `_PendingTransfer`, `pending_spills` → `pending_transfers`, `spills_to_send` → `transfers_to_send`, `update_spills` → `update_transfers`, `_complete_host_writes` → `_complete_transfers`, `max_spill_pages` → `max_transfers_per_step`.
  - `plan_prefix_materialization` → `plan_write_backs` (it covers every sealed page, not only a prefix).
  - `valid_pages` / "clean" → **durable** (`durable_pages`, `pinned_durable_pages`, `_page_became_durable`); `ready_prefix_pages` → `num_durable_prefix_pages`.
  - HiSparse's "unpin" → **release** (`released_pages`, `_release_page`, `_release_durable_pages`); core's `BlockPool.unpin_blocks` is unchanged. "Release" now means only that: dropping a transfer or publication lease is **free** (`release_completed_host_cow_copies` → `free_completed_host_cow_copies`).
  - `swap_in` → **`resolve_residency`**: it resolves every top-k position to a physical row, and copies from host only on a miss. The private kernel launch is now `_launch_residency_kernel`.
  - HiSparse's pool "reuse" → **evict**, matching core's `_maybe_evict_cached_block` (`_on_block_reused` → `_on_block_evicted`). `BlockPool.unpin_blocks(on_reuse=...)` is unchanged.
  - "Copy" now means only a **GPU copy** (was also "shadow page"). The host copy-on-write path is named `cow` (`_retained_cow_copies`, `take_host_cow_copies`, `host_cow_copies`, `completed_host_cow_dst_ids`).
  - GPU-copy bookkeeping is prefixed `gpu_copy`: `copies` → `gpu_copies`, `_copy_by_block` → `_gpu_copy_by_block`, `_record_copy`/`_drop_copy` → `_record_gpu_copy`/`_drop_gpu_copy`, `copies_recorded_blocks` → `gpu_copies_recorded_up_to`, `_owners` → `_gpu_copy_readers`, `_lose_page` → `_unmap_evicted_page`.
  - "Resident" → **device** for HiSparse's GPU-held pages and groups, since core's `KVCacheGroup.host_resident` uses "resident" for host-held: `HiSparseResidentSpec`/`HiSparseResidentManager` → `HiSparseDeviceSpec`/`HiSparseDeviceManager`, `resident_managers` → `device_managers`, `get/drop/revive_resident_page` → `get/drop/revive_device_page`, `all_context_pages_resident` → `all_context_pages_on_device`, and the other `resident_*` names. "Residency" and `host_resident` are unchanged. `HiSparseLayout.device_groups` (every group in the shared GPU pool) → `device_pool_groups`, so "device group" names only the page group, and `source_group` → `host_group`.
  - "Hot region" → **hot buffer** in prose. **Hot cache** is the GPU group and tensor that holds every request's hot buffer.
  - Hot-buffer requests: `require_hot`/`has_hot`/`hot_required` → `request_hot_buffer`/`has_hot_buffer`/`hot_buffer_requests`.
  - `pending_pages` → `in_flight_transfers`; `restore` flag → `is_restore`; `transition_watermark` → `read_from_host_watermark`; `has_pending_reclamation` → `has_pending_block_frees` (matching the connector method that wraps it).
  - `_PendingPublication.detached_blocks` → `leased_host_blocks`, `_publish_detached_blocks` → `_publish_finished_prefix`.
  - "Source" no longer means the host group in prose; `resident_source_index` → `resident_group_index`.
  - In the coordinator, "block" names an allocation and "page" an index or count (`page_idx`, `num_host_pages`).
  - Test names and docstrings follow the renames, including HiSparse code and tests that landed after this PR was opened.
  - "Adopt" → **revive**: a host-prefix hit takes back a released GPU copy before the pool evicts it (`_revive_gpu_copies`, `revive_resident_page`, `pages_to_adopt` → `pages_to_revive`). Not "reclaim", which elsewhere in vLLM means the pool taking memory back.
  - Host group: `HiSparseSourceManager` → `HiSparseHostManager`, `KVCacheGroupRole.HISPARSE_SOURCE` → `HISPARSE_HOST`.
  - Scheduler-to-worker types: `SparseKVOffloadCommand` → `HiSparseTransferCommand` (`build_offload_command` → `build_transfer_command`), `SparseKVPageTransfer` → `HiSparsePageTransfer`, `SparseKVRowMirror` → `HiSparseRowMirror`, `SparseKVResidencyUpdate` → `HiSparseResidencyUpdate`; `after_forward` → `runs_after_forward`.
  - Publication: `publish_when_ready` → `publish_when_durable`, `_publish_host_blocks_if_ready` → `_publish_if_durable`, `publication` → `pending_publication`.
  - Host prefix hits and imports: coordinator `commit_computed_blocks` → `record_host_prefix_hit`, `complete_host_import` folded into `finish_host_import`, its only caller, `_pending_imports` → `_pending_import_tokens`.

No config or public API renames. Outside HiSparse, the changes are HiSparse call sites in `index_group.py`, the sparse-MLA backends (`flashmla_sparse.py`, `flashinfer_mla_sparse_sm120.py`) and `sparse_mla_attention.py`; the HiSparse manager classes, docstrings and call sites in `single_type_kv_cache_manager.py`; and in `kv_cache_interface.py`, `KVCacheGroupRole.HISPARSE_SOURCE` → `HISPARSE_HOST` and `HiSparseResidentSpec` → `HiSparseDeviceSpec`.
