# [HiSparse] Standardize terminology and add a nomenclature to the design doc

[Upstream PR](https://github.com/vllm-project/vllm/pull/59465) · state: open · merged: False

## Original PR description

## Overview

Standardize HiSparse terminology and document it in a nomenclature table in `docs/design/hisparse.md`. Several concepts had two or three names each ("spill", "materialize" and "write back" for one copy; "valid" and "clean" for one page state; "reuse" for both a prefix hit and the pool reallocating a block; "resident" meaning GPU-held here but host-held in core's `KVCacheGroup.host_resident`).

## Claims

- Renames only; no behavior, config or public API changes.
- One name per concept in code, tests and docs: **write-back**, **page transfer**, **durable**, **release** (unpin) vs **free** (drop a lease), **evict**, **revive**, **GPU copy**, **device page / device group**, **hot cache / hot buffer**, **residency update**.
- Design doc updated for scheduler-owned residency updates (#60647): the write-back transaction and ownership table no longer describe block-table edits.

## Details

Outside HiSparse-owned files, changes are limited to HiSparse names: the HiSparse manager classes and call sites in `single_type_kv_cache_manager.py`; `KVCacheGroupRole.HISPARSE_SOURCE` → `HISPARSE_HOST` and `HiSparseResidentSpec` → `HiSparseDeviceSpec` in `kv_cache_interface.py`; and HiSparse call sites in `index_group.py`, `sparse_mla_attention.py`, `flashmla_sparse.py` and `flashinfer_mla_sparse_sm120.py`. "Residency" and core's `host_resident`/`BlockPool.unpin_blocks` are unchanged.

- **GPU copy** (was also "shadow page"): `copies` → `gpu_copies`, `_gpu_copy_by_block`, `_record_gpu_copy`/`_drop_gpu_copy`, `gpu_copies_recorded_up_to`, `_owners` → `_gpu_copy_readers`. - **Host** (was "source"): `HiSparseSourceManager` → `HiSparseHostManager`, `KVCacheGroupRole.HISPARSE_SOURCE` → `HISPARSE_HOST`, `source_group` → `host_group`.
- **Resolve residency** (was "swap in"): `swap_in` → `resolve_residency`, private launch `_launch_residency_kernel`.
- **Hot buffer** (was "hot region"): `require_hot`/`has_hot`/`hot_required` → `request_hot_buffer`/`has_hot_buffer`/`hot_buffer_requests`. **Hot cache** is the group and tensor holding every request's hot buffer.
- Scheduler-to-worker types: `SparseKVOffloadCommand` → `HiSparseTransferCommand` (`build_offload_command` → `build_transfer_command`), `SparseKVPageTransfer` → `HiSparsePageTransfer`, `SparseKVRowMirror` → `HiSparseRowMirror`, `SparseKVResidencyUpdate` → `HiSparseResidencyUpdate`.
- Publication: `publish_when_ready` → `publish_when_durable`, `_publish_host_blocks_if_ready` → `_publish_if_durable`, `publication` → `pending_publication`, `detached_blocks` → `leased_host_blocks`, `_publish_detached_blocks` → `_publish_finished_prefix`.
- Host prefix hits and imports: coordinator `commit_computed_blocks` → `record_host_prefix_hit`, `complete_host_import` folded into its only caller `finish_host_import`, `_pending_imports` → `_pending_import_tokens`.
- Other: `transition_watermark` → `read_from_host_watermark`, `has_pending_reclamation` → `has_pending_block_frees`. In the coordinator, "block" names an allocation and "page" an index or count.
