# [ROCm][Perf] Fuse in_proj_qkvz + in_proj_ba into AITER dual-splitk GEMM kernel (Qwen3.8-27B)

[Upstream PR](https://github.com/vllm-project/vllm/pull/65231) · state: open · merged: False

## Original PR description

## Overview

On ROCm, run the Qwen3.5 GDN `in_proj_qkvz` and `in_proj_ba` as one AITER launch (`fused_gemm_a16w16_dual_splitk`) at ≤ 64 tokens. `ba` comes back as fp32 split-K partials that the fused GDN decode sums, so there is no separate `in_proj_ba` launch and no reduce kernel.

Stacked on #61428; only the last commit belongs to this PR. Off until vLLM's AITER pin includes [ROCm/aiter#7228](https://github.com/ROCm/aiter/pull/7228) (the dual GEMM) and [ROCm/aiter#7239](https://github.com/ROCm/aiter/pull/7239) (GDN decode takes `ba` partials for the fused reduce).

## Claims

- in_proj → fused GDN decode, per GDN layer: **−3.4 to −5.2 µs at 16–64 tokens**, −10.0 µs at 8 tokens; +1.3 / +0.4 µs at 1–2 tokens.
- Serving, against #61428: **+1.4 to +3.2 % total tok/s and −1.3 to −3.7 % mean TPOT at c16–c64**, +0.3 % / −0.5 % at c4; GSM8K unchanged.
- No change on CUDA, XPU or CPU, for quantized models, LoRA or spec decode, or above 64 tokens.

- `tests/kernels/mamba/test_gdn_in_proj_qkvzba.py`: the custom op against a dense GEMM at 1, 64, 65 and 1000 tokens: 4/4 passes

## Details

- `in_proj_qkvz` and `in_proj_ba` load into one `MergedColumnParallelLinear` `in_proj_qkvzba` (`[q, k, v, z, b, a]`). It only holds the weight; its forward is never called.
- The custom op `qwen_gdn_in_proj_qkvzba` runs the dual GEMM up to 64 tokens (`skip_reduce=True`, `num_ksplit2=10`, `ba` as `[10, T, 96]` fp32 partials) and the usual two GEMMs above it. It always returns all four outputs so the fake impl has fixed shapes.
- `num_ksplit2` overrides only the split count of AITER's tuned config, because it sets the partials' shape. The tuned configs give 10 at every bucket except 2–4 tokens.
- The fused GDN decode sums the partials and rounds `ba` to bf16, as the GEMM would. Other paths sum them in torch.

Scope: ROCm only, gated by `rocm_aiter_ops.is_fused_gdn_in_proj_dual_splitk_available()`, the flat (Qwen3.5) layout, no quantization, LoRA or spec decode. CUDA, XPU and CPU forwards are unchanged.
