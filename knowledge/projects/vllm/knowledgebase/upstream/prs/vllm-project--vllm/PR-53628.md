# [BugFix][ROCM] DFlash2 fix sliding-window prefix attention NaNs

[Upstream PR](https://github.com/vllm-project/vllm/pull/53628) · state: open · merged: False

## Original PR description

## Purpose

  Fix NaNs in ROCm prefix attention when DFlash2 uses sliding-window attention with a hybrid target model. #53323 

  Out-of-window positions can reference stale physical KV-cache blocks containing non-finite values. Masking those positions only after attention computation allows `0 * NaN` to propagate. This change masks block-table and K/V loads before they participate in attention math.

  A regression test covers stale nonzero block IDs containing NaNs.

Additional kernel-level evidence and a decode counterpart to this prefix repair. The duplicate check also found #49588, so I am sharing the patch here for coordination rather than opening a competing PR.

There is a remaining partial-tile case beyond skipping whole expired blocks. With `seq_len=4352`, `sliding_window=4095` and physical/kernel block size32, live keys start at257. Token256 is expired but shares the first retained tile with live token257. Poisoning only token256 still produces NaNs with #49588's loop-start change, because that token's K/V are loaded before the score mask. Extending the existing decode load predicate to the window boundary prevents this.

Focused pytest results on an allocated AMD GPU (BF16, PyTorch2.11.0+gitd0c8b1f, ROCm7.2.53211, Triton3.6.0):

| Decode implementation | Whole expired page (8 cases) | Expired token in first retained tile (4 cases) |
|---|---|---|
| Stock decode at this PR's `aa93f64c` head | 8 poisoned-output assertion failures | 4 poisoned-output assertion failures |
| Exact #49588 diff (`0b1ffc75`) on that same source | 8 passed | 4 poisoned-output assertion failures |
| Load-mask patch below | 8 passed | 4 passed |

Every variant passed the clean-input FP64 comparison before poisoning. The unchanged bound is `atol=3e-4, rtol=3e-2`. Cases cover ordinary and padded cache strides, V-only and K+V NaNs, and null/nonzero whole-page IDs. Boundary poisoning uses direct indexed assignment so it modifies the actual cache, not an advanced-indexing copy. Full upstream conftests remained enabled, and the exact imported kernel/test hashes and per-case JUnit outcomes were checked. This is focused Python-kernel coverage on an older installed vLLM runtime, not model-evaluation or throughput qualification.
