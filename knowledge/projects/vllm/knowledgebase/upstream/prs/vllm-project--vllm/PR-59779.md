# [Bugfix][Watermarking] Keep draft prompt lengths valid under CUDA graphs

[Upstream PR](https://github.com/vllm-project/vllm/pull/59779) · state: closed · merged: True

## Original PR description





## Overview

Fix stale prompt lengths in the draft watermark deduplication mask under CUDA graphs. The bug came in with #56807. I found it while reviewing #59554, which would expose DFlash to it too.

## Claims

- With `dual_key_gumbel` and the default `deduplicate_contexts="single_turn"`, draft sampling under FULL CUDA graphs (default `FULL_AND_PIECEWISE`) read prompt lengths from a stale UVA buffer after new requests arrived. This affects EAGLE3, MTP and DSpark (reproduced; EAGLE shares the autoregressive path). Some drafts were sampled without key A where they should carry it, and some repeated contexts were not deduplicated. Graph and eager mode now agree.
- No host sync, and no end-to-end change I can separate from run-to-run noise (see Performance). The fix adds one async copy of `max_num_reqs` int32 values per propose. The captured dedup kernel then reads device memory instead of pinned host memory, which is faster in a microbenchmark.

## Validation

Engine harness: Qwen3-4B targets (Qwen3.5-0.8B for MTP) with dedup `single_turn`. It compares the dedup mask each draft row actually used against a CPU reference built from the true prompt lengths. Compared with the engine-level script under Reproduction, it also covers Poisson arrivals, MTP and DSpark. λ is arrivals per engine step.

| Workload | Before (FULL graph) | After (FULL graph) | Eager |
|---|---|---|---|
| EAGLE3 K=3, crafted (one request at a time, prompt-copying) | 576/1905 mask rows wrong; 536 accepted drafts lacked key A | 0/1896 | 0/1896 |
| EAGLE3 K=3, online Poisson (λ=0.2, mean concurrency 12) | 43/23178 mask rows wrong (41 falsely skipped, 2 missed dedup) | 0/23178 | 0/23325 |
| MTP K=3, crafted / online λ=0.02 | 32.6% / 2.06% of accepted drafts falsely skipped; online also 74 rows with missed dedup | n/a / 0 | 0 / n/a |
| DSpark K=7, crafted / online λ=0.02 | 39.5% / 2.05% of accepted drafts falsely skipped; online also 74 rows with missed dedup | n/a / 0 | 0 / n/a |

The MTP and DSpark "after" numbers come from the harness's patched `prepare()`, not from a commit tree. The EAGLE3 online "after" rows used the first revision of this fix, which differed only in copying into a `[:num_reqs]` slice. The EAGLE3 crafted "after" and eager runs use this commit.

Host sync: `VLLM_GPU_SYNC_CHECK=error`, EAGLE3 under `FULL_AND_PIECEWISE`, 12 staggered admissions and 98 `prepare()` calls: clean. A deliberate `.item()` in `prepare()` trips the check, so the check does cover this path.

The test is CUDA-only. CI runs `tests/watermarking` only in the CPU "V1 Others" step, where it is skipped. I ran it locally on a B300: it fails on main and passes with the fix, and the suite passes (148).

About 1-2% of accepted drafts are affected at low traffic (EAGLE3 0.98%, MTP 2.06%, DSpark 2.05%) and 0.54% when busy (EAGLE3). Per-category detection rates in paired runs are identical for EAGLE3 and within noise for MTP and DSpark: at most 2 of 19-20 requests differ. The bug still breaks the watermark's own contract, and graph and eager runs diverge.

### Performance

Setup: B300, Qwen3-4B with EAGLE3 (`AngelSlim/Qwen3-4B_eagle3`, K=3, probabilistic), `dual_key_gumbel`, temperature 1.0, random 1024 in / 256 out with `--ignore-eos` (64 prompts at c=1 and c=8, 256 at c=64), default `FULL_AND_PIECEWISE`. Main and fix servers ran in parallel on two GPUs, swapped each round, for 10 rounds of 2 passes. Δ is the mean of the per-round paired change, ± the 95% CI. A/A is the same comparison of main against main (4 rounds).

| 1 | 464.7 → 462.3 | −0.5% ± 0.6 | +0.5% ± 0.6 | +1.8% ± 2.0 | 1.632 → 1.632 | −0.4% ± 0.6 | +0.6% ± 3.4 |
| 8 | 3032 → 3012 | −0.6% ± 0.8 | +0.4% ± 0.9 | +2.3% ± 1.7 | 1.658 → 1.662 | −0.3% ± 3.3 | −1.2% ± 5.6 |
| 64 | 10543 → 10495 | −0.4% ± 0.8 | +0.3% ± 0.9 | +0.8% ± 1.5 | 1.533 → 1.533 | +0.3% ± 1.2 | −0.7% ± 4.1 |

Throughput and TPOT change by less than 1%, with CIs that include zero. The A/A differences are of similar size.

Mean TTFT is 0.35-0.65 ms (0.8-2.3%) higher. Only the c=8 CI excludes zero (+0.7% to +4.0%). Between two identical main servers, per-round TTFT differences range from −6% to +3%, and one A/A CI (c=64 acceptance length) also excludes zero. I read the TTFT difference as noise, but these runs cannot rule out a TTFT cost of a few percent at c=8.

`prepare()` alone, with a UVA-backed prompt-length source and the speculator's two gathers: host time goes from 48.4-48.9 µs to 51.4-52.1 µs (+3 µs for one more copy launch). The copy itself takes 4.2 µs on the GPU at `max_num_reqs=1024` and 0.9 µs at 256. The dedup kernel runs once per draft step, so three times per propose at K=3. Replayed in a CUDA graph, those three steps get faster because the kernel reads device memory instead of pinned host memory: 12.3 → 8.7 µs with 1 request and 30.2 → 17.0 µs with 1024 requests (`max_num_reqs=1024`).

### Reproduction

A standalone script shows the bug without a model. It captures the draft dedup mask in a CUDA graph, admits a request (which moves `prompt_len.gpu` to the next pool buffer), and compares the replayed graph with eager mode. Run it on a CUDA GPU with `python repro_stale_prompt_len.py`.

<details>
<summary>repro_stale_prompt_len.py</summary>

```python
# Draft watermark dedup mask under a CUDA graph reads a stale prompt length.
import torch

import vllm
from vllm.v1.watermarking.gumbel import GumbelWatermarker
from vllm.v1.watermarking.spec_decode import DraftWatermarker
from vllm.v1.worker.gpu.buffer_utils import UvaBackedTensor

print("vllm from", vllm.__file__)
dev = torch.device("cuda")
wm = DraftWatermarker(GumbelWatermarker(key=42, context_width=2), max_num_reqs=1,
                      device=dev, num_speculative_steps=1,
                      deduplicate_contexts="single_turn",
                      deduplicate_contexts_max_history=None)
prompt_len = UvaBackedTensor(1, dtype=torch.int32)  # like req_states.prompt_len
# Request in slot 0: prompt [5, 6, 9], generated [5, 6], next draft context
# [5, 6]. The context repeats only inside the prompt, so with single_turn the
# draft must use key A. Read with prompt length 0, it looks like repeated
# generated text and the draft skips key A.
tokens = torch.tensor([[5, 6, 9, 5, 6]], device=dev)
total_len = torch.tensor([5], device=dev)
ctx = torch.tensor([[5, 6]], device=dev)
enabled = torch.tensor([True], device=dev)
logits = torch.zeros(1, 8, device=dev)
idx = torch.zeros(1, dtype=torch.int32, device=dev)
temp, draft_step = torch.ones(1, device=dev), torch.tensor(0, device=dev)

def prepare():  # the speculator calls this on every propose()
    wm.prepare(ctx, enabled, tokens, prompt_len.gpu, total_len)

def uses_key_a():  # per-row mask that draft sampling uses for key A
    return wm._sampling_state(logits, idx, temp, draft_step, ctx)[1]

prepare()  # capture time: slot 0 has prompt length 0
uses_key_a()  # warm up outside capture
graph = torch.cuda.CUDAGraph()
with torch.cuda.graph(graph):
    graph_out = uses_key_a()
# A step that admits a request runs copy_to_uva(), which moves
# prompt_len.gpu to the next buffer of its round-robin pool.
prompt_len.np[0] = 3
prompt_len.copy_to_uva()
prepare()
eager = uses_key_a().item()
graph.replay()
replayed = graph_out.item()
print(f"eager: key A={eager}  graph: key A={replayed}  ->",
      "OK" if eager == replayed else "STALE prompt length in graph")
```

```python
# EAGLE3 + dual_key_gumbel: compare the dedup mask each draft row used with the
# mask recomputed, in the same CUDA graph, from the current prompt lengths.
import os
import sys

import torch

os.environ.update(VLLM_USE_V2_MODEL_RUNNER="1", VLLM_ENABLE_V1_MULTIPROCESSING="0")
import vllm  # noqa: E402
from vllm import LLM, SamplingParams  # noqa: E402
from vllm.v1.watermarking.spec_decode import DraftWatermarker as DW  # noqa: E402
from vllm.v1.worker.gpu.sample.watermark import draft_watermarking_mask  # noqa: E402

print("vllm from", vllm.__file__)
orig_init, orig_prepare, orig_state = DW.__init__, DW.prepare, DW._sampling_state
instances = []

def __init__(self, wm, max_num_reqs, device, *args):
    orig_init(self, wm, max_num_reqs, device, *args)
    self.true_pl = torch.zeros(max_num_reqs, dtype=torch.int32, device=device)
    self.stats = torch.zeros(3, dtype=torch.int64, device=device)  # rows, wrong, skip
    instances.append(self)

def prepare(self, ctx, enabled, tokens, prompt_lens, total_lens):
    orig_prepare(self, ctx, enabled, tokens, prompt_lens, total_lens)
    self.true_pl.copy_(prompt_lens)  # current prompt lengths

def _sampling_state(self, logits, idx, temps, step, ctx):
    steps, mask = orig_state(self, logits, idx, temps, step, ctx)
    ref = draft_watermarking_mask(
        self.all_token_ids, idx, self.true_pl, self.total_lens, self.prior_contexts,
        ctx, steps, self.enabled[: len(ctx)] & (temps != 0),
        self.deduplicate_contexts_max_history, False)
    self.stats += torch.stack(
        [torch.ones_like(ref).sum(), (mask != ref).sum(), (ref & ~mask).sum()])
    return steps, mask

DW.__init__, DW.prepare, DW._sampling_state = __init__, prepare, _sampling_state
wm = {"algorithm": "dual_key_gumbel", "key": 42, "context_width": 4}
spec = {"method": "eagle3", "model": "AngelSlim/Qwen3-4B_eagle3",
        "num_speculative_tokens": 3, "draft_sample_method": "probabilistic"}
llm = LLM("Qwen/Qwen3-4B", speculative_config=spec, watermark_config=wm, seed=0,
          max_model_len=4096, gpu_memory_utilization=0.5,
          enforce_eager=sys.argv[1:] == ["eager"])
(dw,) = instances
dw.stats.zero_()  # drop warmup and capture rows
text = ("The committee met on Tuesday to review the annual budget. The members agreed "
        "to fund the public libraries, repair the old bridge near the river, and hire "
        "two more nurses for the clinic. The mayor promised a full report next month.")
for i in range(24):  # one request at a time; each admission rotates the UVA pool
    ask = f"Repeat exactly, word for word:\n{text}" if i % 3 == 1 else "Say hi."
    llm.chat([{"role": "user", "content": f"[{i}] {ask}"}],
             SamplingParams(temperature=1.0, seed=i, max_tokens=96), use_tqdm=False,
             chat_template_kwargs={"enable_thinking": False})
rows, wrong, skipped = dw.stats.tolist()
print(f"draft rows={rows}  mask rows wrong={wrong}  wrongly skipped key A={skipped}")
```

## Details

**Root cause:** `req_states.prompt_len` is a `UvaBackedTensor`. `copy_to_uva()` runs from `apply_staged_writes` on steps that add requests, and it moves `.gpu` round-robin across the buffer pool. `DraftWatermarker.prepare()` stored that reference, so a captured `draft_watermarking_mask` kept reading the capture-time buffer. Newly admitted requests then see the previous occupant's prompt length until the pool comes back around:
- If the stale length is shorter than the real one, prompt n-grams count as generated history and the draft skips key A.
- If it is longer, real repeats are missed.

**Fix:** `DraftWatermarker` owns an int32 `[max_num_reqs]` buffer, and `prepare()` copies into it. This follows the existing `contexts` and `enabled` copies in the same method. It is also the principle MRV2 states for fused draft decoding: replayed tensor state must live in persistent storage.

I found no other inputs to captured draft sampling that go stale:
- `all_token_ids` and `total_len` are `StagedWriteTensor`s whose `.gpu` never moves.
- `contexts` and `enabled` are already copied into owned buffers.
- Other UVA-backed inputs to the draft path (temperature, seeds) are already copied into speculator-owned buffers. The remaining readers run eagerly.

**Unchanged behavior:** eager mode and the watermark-off path are unaffected. By code inspection, dedup modes `none` and `all` do not depend on prompt lengths: `none` returns before the mask is built, and `all` searches from position 0. The copy still runs in those modes; its cost is negligible.

**Alternatives:**
- Making `RequestState.prompt_len` a stable `StagedWriteTensor` would fix this for every future graph reader. It touches the penalties, bad_words, trace_replay and model_runner readers, and the `LogitsProcessor` interface types `prompt_len` as `UvaBackedTensor`, so it is better done as a separate refactor.
- A persistent device mirror inside `UvaBackedTensor` would cost a copy for every user.
