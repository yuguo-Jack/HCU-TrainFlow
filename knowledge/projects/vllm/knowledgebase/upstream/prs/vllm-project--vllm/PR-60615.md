# [MRV2][Spec Decode] N-gram lookup in front of MTP drafting

[Upstream PR](https://github.com/vllm-project/vllm/pull/60615) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

For a single request, copying drafts from the context in front of MTP gives **+28% decode on copy-heavy prompts and +15 to 17% on Blazedit code editing, at temperature 0 and 1**, Qwen3.8-Flash-Next-NVFP4 + MTP k=3 (stock BF16 head), one DGX Spark (GB10); SPEED-Bench +3 to 4%. Batches of more than one request are unchanged.

Adds `speculative_config.ngram_lookup` (off by default) for `method="mtp"` on Model Runner V2. When the batch has one request and its last `prompt_lookup_min` to `prompt_lookup_max` tokens (default 12 to 16) occur earlier in its context, the tokens that followed become the drafts and the MTP decode steps are skipped; otherwise MTP drafts as usual. Works with greedy and probabilistic draft sampling. Addresses #46977.

```bash
vllm serve <model> --speculative-config '{"method": "mtp", "num_speculative_tokens": 3, "ngram_lookup": true}'
```

## Claims

- **Single request, T=0:** copy probe 52.5 -> 67.4 tok/s (+28%), Blazedit 51.8 -> 60.9 (+17%), SPEED-Bench (5 categories) +4.0%.
- **Single request, T=1, probabilistic drafting:** copy probe 51.5 -> 66.2 (+29%), Blazedit 51.1 -> 58.5 (+15%), SPEED-Bench +2.8%.
- **More than one request:** no lookup, no sync, same code path as MTP.
- **Lossless:** the target verifies every draft. Copies are verified as one-hot drafts (greedy and probabilistic), checked by a unit test and by T=1 output distributions.

## Validation

1x DGX Spark GB10, vLLM nightly `81198e97ba` + this PR (+#56273, only to load the NVFP4 checkpoint), MTP k=3, stock BF16 draft head, thinking off, one request at a time, all arms of a column on one node with the baseline run twice. T=1 uses fixed per-request seeds. SPEED-Bench: coding, roleplay, humanities, summarization, math (160 prompts, 256 tokens). Blazedit: `vdaita/edit_5k_char`, normalized edit distance <= 0.25, 16 prompts, 1536 tokens. Copy probe: 5 rewrite/repeat prompts x 2.

Disclaimers:
- Measured on `b0c5f0d537` with `prompt_lookup_min/max` 12/16 set explicitly; `345940129a` only makes that the default. With 5 (the `ngram` method default) the gains were smaller: copy probe +26% / +27%, Blazedit +11% / +12%, SPEED-Bench +3.2% / +1.2% (T=0 / T=1).
- Noise: the two baseline runs differ by 0.6% (T=0) and 0.8% (T=1) on the means, up to 1.6% and 4.6% per category.
- GB10 only; no datacenter numbers yet.

<details><summary>Acceptance, overhead and the single-request rule</summary>

Per-position acceptance (instrumented build, rounds drafted by each source): copies 0.90 / 0.83 / 0.78 (T=0) and 0.89 / 0.83 / 0.78 (T=1); MTP 0.76 / 0.56 / 0.39 and 0.77 / 0.57 / 0.40. The verify width is k+1 rows on every step.

Lookup kernels: 3.6 us per step. The wait for the match flag overlaps the draft prefill and added 0.3 ms GPU idle per 65 ms step at c=1 (nsys, low-repeat prompts).

Why one request: the gain is the skipped MTP decode, which needs every request to match. An earlier revision that copied in any batch and always waited was -9% aggregate at 4 requests on Qwen3.6-35B-A3B-FP8; a revision that waited only after an all-matched round skipped in about 1% of copy rounds and lost the gain. Without the skip, a copy only displaces the MTP draft, and under probabilistic drafting a one-hot copy of token x is accepted with p(x) while an MTP draft of x is accepted with min(1, p(x)/q(x)).
</details>

## Details

- **Design.** `NgramMTPSpeculator` subclasses `MTPSpeculator`. The lookup kernels move from `NgramGPUSpeculator` into a shared `NgramLookup` with one new `has_match` output, set only when all `num_speculative_tokens` tokens could be copied. The MTP draft prefill always runs, so the draft KV cache stays complete; `TargetDependentARSpeculator` gets a `num_draft_steps` hook so the subclass can stop after the prefill.
- **Host sync.** Only single-request batches wait for the match flag, overlapped with the draft prefill. Data parallelism is rejected, since skipping on one rank would desync the others.
- **One draft length.** Copies use `num_speculative_tokens`, like MTP. The async scheduler fixes the verify width before drafting, so a copy length above the MTP depth would pad every miss step (measured -6% to -10% on SPEED-Bench); that needs variable-length verification and is left out.
- **Sampling.** With greedy draft sampling the rejection sampler already treats drafts as one-hot. With probabilistic draft sampling, matched requests get one-hot rows in the cached draft logits, so the ratio test sees q = 1 on the copied token and resampling uses the matching residual. `enable_adaptive_verification` is rejected (copies have no draft confidence).
- **Scope.** Single-module MTP only; Gemma4 and multi-module MTP use other speculator classes, EAGLE and DFlash are follow-ups. MRV1 is rejected through the existing unsupported-feature list.
- **Not a duplicate.** #24344 (ngram + EAGLE) targets MRV1 and runs both drafters every step. #52097 and #60339 add suffix drafters as standalone methods, not combined with a model drafter. No open MRV2 PR combines n-gram lookup with MTP. The design follows the review on #24344: verify long-but-rare n-gram drafts and short-but-accurate model drafts together, and skip the model drafter when every request hits, which pays for low-latency single requests ([1](https://github.com/vllm-project/vllm/pull/24344#discussion_r2400623774), [2](https://github.com/vllm-project/vllm/pull/24344#discussion_r2400631625)).

AI assistance (Claude Code) was used for the code, tests and benchmark harness. I reviewed every changed line and ran the tests and benchmarks above.
