# [Rust Frontend] Reject an empty chat tools array like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/63060) · state: closed · merged: True

## Original PR description

## Overview

Python rejects a chat request with `tools: []`, matching the OpenAI API (vllm-project/vllm#39780; vllm-project/vllm#49214 made it a `VLLMValidationError` with `parameter="tools"`). The Rust frontend accepts it and runs the request as plain chat. This PR returns the same 400.

## Claims

- `POST /v1/chat/completions` (and `/v1/chat/completions/render`) with `"tools": []` now returns 400 `BadRequestError` with `param: "tools"` and Python's message, "`tools` must not be an empty array. Either provide at least one tool or omit the field entirely." Before, it returned 200.
- As in Python, `tool_choice: "none"` does not exempt it, and `tools: null` or an omitted `tools` stay accepted.

## Validation

Commands from `.buildkite/scripts/run-rust-frontend-cargo-ci.sh` (`style-clippy` and `test`), run from the repo root:

```
cargo fmt --manifest-path rust/Cargo.toml --all -- --check   # ok
cargo sort --workspace --check rust                          # ok
cargo deny --manifest-path rust/Cargo.toml --config rust/deny.toml check bans   # ok
cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --all-features --locked -- -D warnings   # ok
cargo nextest run --manifest-path rust/Cargo.toml --workspace --all-features --locked --no-fail-fast
# 2256 tests run: 2256 passed, 13 skipped
```

- New route test `chat_rejects_empty_tools_array` snapshots the full 400 body for `tools: []`, with and without `tool_choice: "none"`. On the base the request returns 200 with a plain completion.

## Details

Python raises in `ChatCompletionRequest.check_tool_usage`, before any `tool_choice` handling. The Rust chat route only checked each tool's type (`validate_function_tools`, which an empty slice passes), and `convert_tools` then turned the empty list into no tools. The check now sits in the chat `validate_request_compat` (`routes/openai/chat_completions/validate.rs`), next to the existing `tools` type check, before `convert_tools` erases the difference between absent and empty. Every chat entry point goes through it. `/tokenize` keeps accepting an empty list, like Python's `TokenizeChatRequest`.

One wording difference: Python's `VLLMValidationError.__str__` appends ` (parameter=tools)` to the message. Like the other ported `VLLMValidationError` checks in the Rust frontend, this carries the parameter in `param` only.

Not a duplicate: no open PR adds this check to the Rust chat route.
