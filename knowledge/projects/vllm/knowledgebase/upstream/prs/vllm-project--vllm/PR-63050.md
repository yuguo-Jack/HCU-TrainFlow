# [Bugfix][Model] Load Granite Speech checkpoints saved by Transformers v5

[Upstream PR](https://github.com/vllm-project/vllm/pull/63050) · state: closed · merged: True

## Original PR description



## Overview

`ibm-granite/granite-speech-4.1-2b-plus` no longer loads in vLLM. Its checkpoint was re-saved with Transformers 5.19 on 2026-10-21 ([HF revision `e69efe37`](https://huggingface.co/ibm-granite/granite-speech-4.1-2b-plus/commit/e69efe37f97b6283c61f5a8dadda2b3eb67765d6)), and the text model weights are now named `language_model.model.model.*` instead of `language_model.model.*`. This PR maps the extra level away in `GraniteSpeechForConditionalGeneration`, so both checkpoint layouts load.

It also fixes `test_granite_speech.py::test_models[...granite-speech-4.1-2b-plus...]`, which has failed in `Multimodal Models (Extended Generation 1)` on both NVIDIA and AMD since the checkpoint update (full build [96476](https://buildkite.com/vllm/ci/builds/96476)):

```
ValueError: There is no module or parameter named 'model' in GraniteModel.
```

## Claims

- The new `granite-speech-4.1-2b-plus` checkpoint loads, and its outputs match Transformers.
- The previous revision of the checkpoint, and the other Granite Speech checkpoints, load as before. The mapping only touches names starting with `language_model.model.model.`, which no older checkpoint has.

No separate model evaluation. The change only renames weights at load time, and the test above checks the outputs against Transformers.

## Details

**Why the extra `model.`** Transformers' `granite_speech` conversion mapping has two renamings: a top-level `^language_model.model` → `model.language_model`, and `^language_model.model` → `language_model`, scoped to `GraniteSpeechModel`. The new names are most likely `save_pretrained` reversing both of them. I have not confirmed this in the Transformers source. Transformers applies both renamings on load, so it reads the checkpoint correctly. vLLM loads checkpoint names directly, so it needs the mapping.

**Relation to #60666.** That draft PR applies Transformers' checkpoint renamings in vLLM's loader generically, and would probably make this mapping unnecessary. It is large (122 files) and not ready for review yet. This PR is a minimal fix for users and CI in the meantime. The mapping can be dropped once #60666 lands.

**Not a duplicate.** Searched open PRs and issues for `granite speech`, `granite_speech` and `granite-speech-4.1-2b-plus`. Only #60666 touches this model's weight names. Its explicit Granite Speech mapping covers `model.language_model.*`. I have not tested whether its generic renamings handle the double-nested names.
