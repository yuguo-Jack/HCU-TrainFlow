# [Core][Perf] Skip gaps when searching sliding-window cache hits

[Upstream PR](https://github.com/vllm-project/vllm/pull/62338) · state: open · merged: False

## Original PR description

## Overview
Replaces the O(max_num_blocks) right-to-left scan in `SlidingWindowManager.find_longest_cache_hit` with a strided probe lattice, so low-hit-rate sliding-window requests skip uncached gaps. Also clamps the probe stride to 1 to avoid a non-terminating loop for `sliding_window=1` without EAGLE.

Fixes #62336. Related: #53276 — materially different, see Details.

## Claims
- 8192 -> 33 `get_cached_block` lookups for a 128K-token request with a 4K window and a cold cache (block_size=16); 4.49 ms -> 0.021 ms per call in the function-level harness (~200x).
- No regression for hit-heavy caches (256 -> 257 lookups; 0.23 ms -> 0.23 ms).
- Hit results are unchanged: exhaustive comparison with the previous implementation over 7,339,584 cases (all cached-block patterns up to 13 blocks, block sizes 1/2/4/8, windows 1-32, alignments 1-16, EAGLE on/off) plus 30,000 larger randomized cases (up to 4096 blocks) found 0 differences.
- Fixes a latent non-terminating loop for `sliding_window=1` without EAGLE.

## Details

**Design.** A hit requires `stride = cdiv(sliding_window - 1, block_size) (+1 for EAGLE)` contiguous cached blocks. Probing every `stride`-th block from the right therefore cannot skip a candidate run, because any `stride` consecutive indices contain exactly one probe. Probe hits expand right (the next probe missed, so the run cannot extend past `i + stride - 1`) and verify only windows containing the probe. A miss at `idx` disqualifies every window ending in `(idx, edge]`, so the search resumes at the next aligned edge below `idx - 1`. Alignment retries use `alignment_tokens // gcd(alignment_tokens, block_size)`.

**Why this is not a duplicate of #53276.** #53276 (open since 2026-08-21, no human review activity) adds a left-boundary lookahead only for the current-block miss case and otherwise still advances one block at a time; alignment retries stay per-block, the prefix fallback still comes from the full scan, and it adds no tests. This PR replaces the loop, is proven not to skip candidates, handles the alignment-period and right-expansion cases, and ships an equivalence test plus a zero-stride regression test. See the linked issue for the full comparison.

**Root cause of the zero-stride fix.** `_contiguous_blocks_for_hit` returns `cdiv(sliding_window - 1, block_size) == 0` for a one-token window when EAGLE is disabled. The new probe loop uses that value as its step, so `i -= stride` would not advance. Clamping to 1 reproduces the previous scan's behavior: a single cached block can still be reused, and a cold cache terminates with an empty hit. `_contiguous_blocks_for_hit` itself is unchanged because it is also used by `reachable_block_mask`, whose semantics depend on the raw value.

**Tradeoffs / limitations.**
- Worst case remains O(max_num_blocks), e.g. when cached blocks are arranged on the probe lattice; measured 128 lookups vs 8192 today.
- One dict of at most `stride` entries is allocated on a hit.
- Hit-heavy paths are unchanged within one lookup.
- Validation is unit/function-level, not end-to-end serving.
