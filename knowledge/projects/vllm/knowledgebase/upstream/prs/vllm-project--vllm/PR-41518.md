# [Misc] Reduce `time vllm --help` and `time vllm serve --help` to <1s warm

[Upstream PR](https://github.com/vllm-project/vllm/pull/41518) · state: closed · merged: False

## Original PR description

This PR improves feedback time for CLI-only operations such as `--help` and
misspelled or misspecified arguments for top-level `vllm` and `vllm serve`.
It still builds the full generated parser.

**`vllm bench` performance remains out of scope.**

---

```shell
hyperfine --runs 10 --export-json "$RESULT" \
  -n cold "find . -type d -name __pycache__ -prune -exec rm -rf {} + && $COMMAND" \
  -n warm "$COMMAND"
```

Median of 10 runs on my RTX 3500 Ada laptop:

| command | mode | main (`df344bf36f`) | PR (`176a9b0527`) | speedup |
| --- | --- | ---: | ---: | ---: |
| `vllm serve --help` | cold | 23.72 s | 1.64 s | 14.4x |
| `vllm serve --help` | warm | 10.01 s | 0.755 s | 13.3x |
| `vllm --help` | cold | 23.37 s | 0.475 s | 49.2x |
| `vllm --help` | warm | 10.36 s | 0.164 s | 63.2x |

The regression test warms once, measures seven runs per command, and requires a
median below 1 second.

Help output is unchanged.

File: `vllm/engine/arg_utils.py` · line 2958

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The check `if load_plugins_by_group(PLATFORM_PLUGINS_GROUP):` is problematic. `load_plugins_by_group` returns a list of loaded plugins. If no platform plugins are installed (e.g., in a standard environment using built-in platforms like CPU or CUDA), this will return an empty list, evaluating to `False`. Consequently, `current_platform.pre_register_and_update(parser)` will be skipped, and platform-specific CLI arguments will not be registered. Since `add_cli_args` is now only called for the active subcommand (thanks to the `is_cli_subcommand` check in the entrypoints), it is safe to import and use `current_platform` directly here without this extra check.

```python
        from vllm.platforms import current_platform

        current_platform.pre_register_and_update(parser)
```
