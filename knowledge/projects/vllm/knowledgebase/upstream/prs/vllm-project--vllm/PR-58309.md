# [Test][ToolParser] Regression test: required streaming does not crash on single closed tool without parameters

[Upstream PR](https://github.com/vllm-project/vllm/pull/58309) · state: open · merged: False

## Original PR description

## Purpose

This PR originally guarded `extract_required_tool_call_streaming` against an `IndexError` when a single parameter-less tool call closed within one chunk (`'[{"name": "f"}]'` → `obj[-2]` on a length-1 list).

Since then, #60354 **rewrote** `extract_required_tool_call_streaming` entirely: the `filter_delta_text` / `finishes_previous_tool` / `obj[-2]` step-back is gone, replaced by a prefix-stable span scanner (`_scan_required_tool_calls` + `_RequiredToolCallSpan`). The crash path this PR patched no longer exists, so the original one-line fix is obsolete.

Rebased onto current `main`, this PR now carries **only a regression test** that locks in the new implementation's behavior for the single-closed-tool edge case, so a future refactor can't silently reintroduce the crash.

## What the test asserts

For `'[{"name": "f"}]'` — a length-1 array whose sole object closes before a `"parameters"` key — the call is incomplete (no arguments value has started), so:

- nothing is announced (the span is not `ready`), and
- the single-element scan does not crash.

Both the chunked (4-char deltas) and whole-array-in-one-delta paths are checked, mirroring the style of the existing `test_streaming_invalid_name_string_is_never_announced`.

```python
def test_streaming_single_closed_tool_without_parameters_is_not_announced():
    text = '[{"name": "f"}]'
    assert _stream_required_tool_calls(text, _fixed_len_deltas(text, 4)) == []
    assert _stream_required_tool_calls(text, [text]) == []
```

This also corrects the original PR's assumption: a parameter-less closed tool call is incomplete per the `tool_choice="required"` schema (each element needs both `name` and `parameters`), so "announce nothing until parameters appear" — the behavior #60354 introduced — is the correct outcome, not emitting the bare name.

## Test

`ruff format --check` passes. The rewritten function was exercised directly against both delta patterns to confirm no crash and no spurious emission; a complete call (`[{"name": "f", "parameters": {}}]`) still streams its name as expected.

If maintainers prefer, I'm happy to close this in favor of #60354 instead — the behavior is already covered there; this only adds an explicit single-element regression guard.
