# [Bugfix][LoRA] Map GLM-5.3-Flash forget-gate LoRA names to the checkpoint layout

[Upstream PR](https://github.com/vllm-project/vllm/pull/60131) · state: closed · merged: False

## Original PR description



## Overview

GLM-5.3-Flash LoRA adapters trained with transformers + PEFT name the KDA forget-gate projections `self_attn.forget_gate.f_a_proj` / `f_b_proj`. vLLM's module paths and the checkpoint keep them flat (`self_attn.f_a_proj` / `f_b_proj`), so those LoRA weights match no module and are dropped without a warning. This PR maps the name back in `Glm5NextForConditionalGeneration.hf_to_vllm_mapper`, the mapper LoRA loading already applies to adapter keys.

Complements #56327 (packed mappings for the fused projections, which is needed for `f_a_proj`). Related: #53906 (model), #56718 (MLA `kv_b_proj` prefill).

## Claims

- An adapter on `f_b_proj` now takes effect. On `main` it is dropped silently: the adapter loads, no warning is logged, and outputs match the base model.
- With #56327 applied, an adapter on `f_a_proj` (fused into `in_proj_qkvbfg_a`) also takes effect. Without this PR it is still dropped there.
- Behavior is unchanged for everything else. The rename only matches `.forget_gate.`, which no GLM-5.3-Flash checkpoint key or quantization ignore list contains. Base-model log-probs are unchanged: 0.0747 from HF's in both builds.

## Validation

Model `zai-org/GLM-5.3-Flash-BF16` on 4×B200, TP=4, BF16, `max_model_len=8192`. Built from `main` at c32495d58f with `VLLM_USE_PRECOMPILED=1`.

**Method.**
- **Inputs:** 12 real chat prompts (387–2,676 tokens), each followed by a 2,039-token gold answer.
- **Score:** the log-prob of every gold-answer token (`prompt_logprobs=0`), with and without each adapter.
- **Reference:** the same token IDs scored by HF transformers 5.17 + PEFT 0.21.2, with the same weights.
- **Adapters:** LoRA r=16 trained on this model with transformers + PEFT, restricted to one module each. LoRA B is scaled ×64 so each module's effect stands clear of noise.

A cell reads `applied / dropped`:
- `applied`: mean |log p_vLLM(adapter) − log p_HF(adapter)| per answer token.
- `dropped`: the same against vLLM's base model, i.e. what a dropped LoRA would score.

The adapter is applied when `applied` ≪ `dropped`.

## Details

**Root cause.**
- transformers 5.x restructures GLM-5.3's KDA forget gate into a `forget_gate` submodule, and its `conversion_mapping` renames the checkpoint's `self_attn.f_a_proj` to `self_attn.forget_gate.f_a_proj` at load (`f_b_proj` likewise).
- PEFT saves adapter keys under the runtime module path, so the adapter carries the nested name.
- vLLM resolves each LoRA by its module's path, `language_model.model.layers.N.self_attn.f_b_proj`. The nested name matches no module.
- `check_unexpected_modules` passes, because it checks only the last name component (`f_b_proj`). So the weights load and are silently unused.

**Fix.** `hf_to_vllm_mapper` is composed with the inherited Glm4V mapper (`|`), adding `orig_to_new_substr={".forget_gate.": "."}`. `get_rename_mapper()` keeps substring renames, so LoRA loading applies it. The base checkpoint has no `forget_gate` keys, so weight loading is unaffected.

**Scope.**
- No test added. The mismatch comes from transformers' runtime naming, and CI cannot load the 598 GB checkpoint. The validation above is the end-to-end check.
- #57617 would batch `f_b_proj`/`g_b_proj` into one `bmm`. LoRA on those modules would then need its own handling.
- Not addressed here: `kv_b_proj` LoRA has no effect on `main`. An ×64 adapter scores 4.706 applied against 4.706 dropped, where the HF effect is 4.72. That's #56718's subject. With the same method, `o_proj`, `q_b_proj` and `g_b_proj` match HF on `main` (0.28 / 10.48, 0.005 / 0.203, 0.006 / 0.190).

- eilamc14 · comment · 2026-10-05T22:10:42Z · [source](https://github.com/vllm-project/vllm/pull/60131#issuecomment-6004136446)

For context, the root cause is upstream: huggingface/peft#3896. transformers' `save_pretrained` writes a base model in the original checkpoint layout, reversing its load-time renames. PEFT saves adapters under transformers' runtime module paths instead, and transformers' own adapter save path skips that reversal. So every adapter trained with transformers v5 + PEFT carries `self_attn.forget_gate.f_{a,b}_proj`, while the checkpoint and vLLM use `self_attn.f_{a,b}_proj`.

If PEFT changes this, newly saved adapters will use the flat names. The rename here is then a no-op for them, since `.forget_gate.` never appears. Adapters already trained with current PEFT still need it, so this PR stays correct either way.

The same mismatch reaches other vLLM models. I audited every transformers `main` rename against vLLM `main` (2e06395fd3), and checked each hit by reading the model code. LoRA-supporting models where an adapter trained with transformers v5 + PEFT doesn't match:

| model | adapter name (runtime) | vLLM name | result |
|---|---|---|---|
| GLM-5.3-Flash | `self_attn.forget_gate.f_{a,b}_proj` | `self_attn.f_{a,b}_proj` | silently ignored (measured; fixed here) |
| Laguna | `mlp.shared_experts.*` | `mlp.shared_expert.*` | silently ignored |
| HY-V3 | `mlp.shared_experts.*` | `mlp.shared_mlp.*` | silently ignored |
| Inkling | `self_attn.{q,k,v,r,o}_proj` | `attn.{wq_du,wk_dv,wv_dv,wr_du,wo_ud}` | adapter refused at load |
| Mixtral, GraniteMoE | `mlp.*` / `experts.gate_up_proj` | `block_sparse_moe.*` / `input_linear` | MoE expert/router LoRA only |

"Silently ignored" means the leaf name passes `check_unexpected_modules`, but the full path matches no module. Only GLM-5.3 was run. I'm keeping this PR to GLM-5.3, and the others would need the same kind of per-model mapper entry. Whether that's worth doing depends on what PEFT decides in huggingface/peft#3896.

Following @hmellor's suggestion, c538c2d250 replaces the hard-coded `.forget_gate.` → `.` rename with transformers' own `WeightRenaming`s for `glm5_next`, reversed.
