### inline_comments

- whx-sjtu · comment · 2026-10-21T04:51:38Z · [source](https://github.com/vllm-project/vllm/pull/62622#discussion_r4333154146)

File: `vllm/entrypoints/openai/completion/protocol.py` · line 87

`to_beam_search_params` (line 344) still passes `self.skip_special_tokens` straight into `BeamSearchParams`, so it is now `None` by default. `beam_search/online.py` then calls `tokenizer.decode(..., skip_special_tokens=None)`, which raises `TypeError: 'None' is not an instance of 'bool'` on transformers 5.x fast tokenizers (checked with 5.19 / tokenizers 0.23). So any `/v1/completions` request with `use_beam_search: true` and no explicit `skip_special_tokens` fails, for every model.

Resolve the default there the same way `to_sampling_params` does (`default_sampling_params.get("skip_special_tokens", True)`). `ChatCompletionRequest.to_beam_search_params` should use the model default too, instead of a hard `True`.


- whx-sjtu · comment · 2026-10-21T04:51:38Z · [source](https://github.com/vllm-project/vllm/pull/62622#discussion_r4333154155)

File: `vllm/v1/attention/backends/rocm_aiter_fa.py` · line None

Before this change `kv_sharing_workspace` existed only when a layer had `kv_sharing_target_layer_name`. Now every `ROCM_AITER_FA` builder allocates `2 x max_num_batched_tokens x kv_heads x head_dim` (about 34 MB for Llama-3-8B at 8192 tokens). And because the workspace is never `None`, `build()` now runs the CPU `repeat_interleave` and two H2D copies for `kv_sharing_metadata` on every prefill step, for every model.

Only layers that call attention with `key=None` need this. Suggest having the model mark those layers (for example an attribute set on the `Attention` layer when the fused KV insert is enabled), and keeping the old `None` default otherwise.



- whx-sjtu · comment · 2026-10-21T04:51:38Z · [source](https://github.com/vllm-project/vllm/pull/62622#discussion_r4333154168)

File: `vllm/tokenizers/hf.py` · line None

This runs for every model without a chat template, including base and embedding models. For a hub repo it adds a `snapshot_download` call on each tokenizer load, and any repo with exactly one unrelated `*.jinja` file silently gains a chat template.

vLLM already has a per-model hook for this: `register_chat_template_fallback_path` in `vllm/transformers_utils/chat_templates/registry.py` accepts a callable that receives the tokenizer path. Registering one for the Muse Spark model type keeps the behavior scoped to this model.


- whx-sjtu · comment · 2026-10-21T04:51:38Z · [source](https://github.com/vllm-project/vllm/pull/62622#discussion_r4333154169)

File: `vllm/renderers/params.py` · line None

This changes the API contract for all models. Today, `null` or `"auto"` in a request's `chat_template_kwargs` means "use the server default". After this change, with `--default-chat-template-kwargs '{"enable_thinking": false}'`, a client that sends `{"enable_thinking": null}` overrides the default with `None`, and the Qwen3 template (`enable_thinking is defined and enable_thinking is false`) turns thinking back on. If Muse Spark needs explicit nulls, this needs its own PR and a release note, or a model-scoped mechanism.


- whx-sjtu · comment · 2026-10-21T04:51:38Z · [source](https://github.com/vllm-project/vllm/pull/62622#discussion_r4333154180)

File: `vllm/models/muse_spark/amd/muse_moe_runner.py` · line None

Online MXFP4 for the routed experts is switched on by a model-specific env var, with layers 0 and N-1 hard-coded. vLLM already has `OnlineQuantizationConfig` / `Mxfp4OnlineMoEMethod` with an `ignore` list (`vllm/model_executor/layers/quantization/online/`), and the PR has no accuracy numbers for this mode. Suggest dropping it from this PR (`MuseSparkOnlineMXFP4FusedMoE`, `_quantize_experts_to_mxfp4`, `_online_mxfp4_applies`, `VLLM_ROCM_MUSE_MOE_ONLINE_QUANT` and its tests), or wiring it through the online quantization config with eval results.


- whx-sjtu · comment · 2026-10-21T04:51:38Z · [source](https://github.com/vllm-project/vllm/pull/62622#discussion_r4333154191)

File: `vllm/models/muse_spark/amd/model.py` · line None

The multiplier is folded into `router.weight` once, then set to `None` here and on `moe_router`. `materialize_residual_path_constants` runs on every `load_weights`, so after `reload_weights(...)` in checkpoint format (for example an RL weight sync) the router weight is raw again: nothing folds it, and the router no longer applies the multiplier either. With `output_multiplier != 1`, routing scores are wrong from then on.

Keep the original multiplier in a separate field and fold it on every load. Also update `_router_planes` in place rather than rebinding it, so captured graphs do not keep reading the old, freed tensor.
