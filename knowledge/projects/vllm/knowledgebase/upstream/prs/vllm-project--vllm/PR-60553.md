# [Bugfix][Scheduler] Fix encoder cache deadlock with drafter look-ahead

[Upstream PR](https://github.com/vllm-project/vllm/pull/60553) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fixes the encoder-cache deadlock with a drafter look-ahead (EAGLE / MTP) reported in the second half of #40707 ([comment](https://github.com/vllm-project/vllm/issues/40707#issuecomment-5760731067)). When two multimodal items only fit in the encoder cache one at a time and the gap between them is smaller than `2 * num_prefill_lookahead`, the request hangs forever, getting 0 scheduled tokens on every step with no error or log. The Mamba-alignment half of #40707 was already fixed by #51603.

## Claims

- A request with adjacent multimodal items that can't share the encoder cache now finishes under speculative decoding instead of hanging. Before this change it hung whenever `gap < 2 * L`, where `L = num_prefill_lookahead`.
- Output doesn't change. With temperature 0 the text matches the no-spec baseline exactly, and no `Encoder cache miss` was observed.

## Validation

**E2E** (1x GB200, MRV2, async scheduling on, prefix caching off): `Qwen/Qwen3.5-4B`, MTP with `num_speculative_tokens=1` (L=1). Each request has two 3008x4032 images of 11844 tokens each; the encoder cache is 16384, so only one image fits at a time. I used raw prompts to control how many tokens sit between the two `<|image_pad|>` runs, and confirmed the placeholder offsets in the scheduler (gap=0 gives `[(4, 11844), (11848, 11844)]`).

| | gap=0 | gap=1 | gap=2 |
|---|---|---|---|
| main, MTP | **hang** (no completion in 300 s) | **hang** | OK |
| this PR, MTP | OK (2 runs) | OK | OK |
| main, no spec (baseline) | OK | OK | OK |

At temperature 0, every OK run with this PR produces the same text as the no-spec baseline for the same prompt: "The first image contains a red circle, and the second image contains a blue rectangle." MTP acceptance was 9/9 drafts in all spec runs.

## Details

**Root cause.** Two places offset by the drafter look-ahead `L`, in opposite directions:

1. `_free_encoder_inputs` keeps item 1 until `num_computed_tokens >= end1 + L`. This was added in #46315.
2. When item 2 can't be allocated, `_try_schedule_encoder_inputs` stops the chunk at `start2 - L`.

If `start2 - L < end1 + L`, then `num_computed_tokens` can never reach the point where item 1 is freed, so item 2 is never allocated.

**Fix.** Remove the `L` offset in both places:

- **Free** once `end <= num_computed_tokens - num_output_placeholders`, as without spec decode. Both the V1 and V2 gathers read the drafter window `[c + 1, c + k + 1)`, which is ahead of `num_computed_tokens`. Once the target has passed an item, neither the target nor the drafter reads it again. Rejection rollback is still covered by `num_output_placeholders`. Async scheduling has the same timing as the existing non-spec path.
- **Stop at `start2`** instead of `start2 - L`, and only in the `can_allocate` failure branch. The drafter's read-ahead then lands on the item that isn't encoded yet. Both runners already handle that case: they fall back to token embeddings via the `start_pos >= computed + scheduled` check added in #46315. The `disable_chunked_mm_input` rollback still applies the shift.

Both changes are needed. Either one alone only narrows the hang condition from `gap < 2L` to `gap < L`.

**Tradeoff.** When the cache is full, the drafter uses token embeddings instead of image embeddings for up to `L` positions at that chunk boundary. This can slightly lower acceptance for one step. Requests whose items fit in the cache are unaffected.

**Relation to #59030.** #59030 adds a mid-schedule release of a request's consumed inputs, but it keeps the `+L` retention margin (its last commit re-added it). That release can never fire at this deadlock point, which is why its results match main in the sweep above. This PR instead argues that the margin isn't needed. The requeue half of #59030 is independent of this PR and complementary to it.

@pytest.mark.parametrize("prefill_lookahead", [1, 3])
@pytest.mark.parametrize("past_chunk_end", [0, 1, 2])
def test_drafter_lookahead_encoder_cache_cap_respects_token_budget(
    prefill_lookahead, past_chunk_end
):
    """An unallocatable input that starts past the token-budget-limited chunk
    end, reached only by the drafter look-ahead, must not grow the chunk."""
    budget = 100

    request = create_requests(

                PlaceholderRange(offset=budget + past_chunk_end, length=300),
