# [Docs] Clarify MCP label filtering and Python tool availability

[Upstream PR](https://github.com/vllm-project/vllm/pull/62630) · state: open · merged: False

## Original PR description



## Overview

Correct the guidance for disabling the GPT-OSS Python tool: `VLLM_GPT_OSS_SYSTEM_TOOL_MCP_LABELS` filters MCP labels, while native Responses tool types can still select registered tools.

## Claims

- Distinguishes tool-server registration from MCP label mapping.
- Explains that omitting an MCP label does not disable the corresponding native tool type.
- Documents how to exclude the Python namespace at the tool-server level, or disable server-side tool execution entirely.

## Validation

- `pre-commit run --files docs/usage/security.md` — all applicable hooks passed.
- `pre-commit run markdownlint-cli2 --files docs/usage/security.md` — passed.
- `pre-commit run typos --files docs/usage/security.md` — passed.
- `git diff --check` — passed.
- Checked the guidance against `extract_tool_types()`, the registered-tool checks in Responses serving, and tool-server registration. A helper-level reproduction with OpenAI SDK 3.8.0 confirmed that empty and container-only MCP allowlists exclude MCP Python/browser labels but preserve native tool selection.
- Model evaluations are not applicable: this change only updates documentation and does not change serving behavior.

## Details

The existing instruction says that omitting `code_interpreter` disables Python, but that variable only filters `mcp` entries. Native `code_interpreter` requests can still select a registered Python tool. The replacement describes the actual configuration needed to avoid registering that capability.

This corrects deployment guidance introduced in #35139. Searches of open PRs for the variable name, MCP tool security documentation, tool availability, and disabling Python found no existing PR making this correction. The browser-backend work in #61288 changes backend selection, not the scope of MCP label filtering.

AI assistance (OpenAI Codex) was used to investigate the behavior and prepare this documentation change.
