# [KV Connector] Generalize declarative connector stats (TypedKVConnectorStats)

[Upstream PR](https://github.com/vllm-project/vllm/pull/55969) · state: open · merged: False

## Original PR description

## Summary

Generalizes the offloading connector's declarative stats into `kv_connector/v1/metrics.py` so any connector can report metrics without a per-connector `KVConnectorStats` / `KVConnectorPromMetrics` subclass:

- `MetricMetadata` / `CounterMetadata` / `GaugeMetadata` / `HistogramMetadata` (moved from `vllm/v1/kv_offload/base.py`; the `Offloading*Metadata` names remain as aliases).
- `TypedKVConnectorStats`: the self-describing `{types, data}` payload with `increase_counter` / `set_gauge` / `observe_histogram`, and type-driven `aggregate` / `reduce` / `is_empty`. `OffloadingConnectorStats` is now an alias of it.
- `TypedKVConnectorPromMetrics`: registers one Prometheus metric per definition and records payloads by metric type. `OffloadPromMetrics` subclasses it and only keeps the deprecated `transfer_type`-labelled CPU offload metrics.

Because every connector using this shares one concrete stats type keyed by metric name, metrics from different families compose by recording into the same instance (or aggregating), and `MultiConnector` continues to work unchanged. Nixl / Mooncake / HF3FS keep their bespoke stats classes; the base interface does not change.

The next PR in this stack (HiSparse cache metrics) is the first non-offloading user.

Not duplicating an open PR: searched open PRs for "KVConnectorStats", "typed"/"declarative" connector metrics, and "connector metrics definitions"; #50878 (external metrics providers for stat logger plugins) and #41790 (SimpleCPU offload metrics) are unrelated.
