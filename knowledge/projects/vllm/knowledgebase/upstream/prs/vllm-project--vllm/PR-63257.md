# [ROCm][Recipe] MiniMax-M3.1-Flash: MI355X PD, DBO / SP prefill, Quark MXFP4, mono decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/63257) · state: closed · merged: True

## Original PR description

## Overview

AMD MI355X additions to the MiniMax-M3.1-Flash recipe (`recipes/models/MiniMaxAI/MiniMax-M3.1-Flash.yaml` only). No other open PR changes this recipe.

## Claims

1. **PD on MI355X**: `pd_cluster` renders the guide's 1P1D. One TP4 engine per role; BLHNC KV layout and NIXL with 4 threads; the prefill node drops `indexer_decode_cp` and offloads KV to host memory in 1 GiB HugeTLB pages (`SimpleCPUOffloadConnector`).
2. **TP4 on MI355X** for `single_node_tp` (Hopper keeps the FP8 variant's TP8).
3. **DBO / SP prefill** (opt-in feature, MI355X single node): SP + DBO, DBO, or SP. Guide section with the flags; one 32K-token prefill takes 1035 ms plain, 655 ms with DBO, 484 ms with SP + DBO (MXFP8 MoE).
4. **MXFP4 (Quark) variant**: `amd/MiniMax-M3.1-Flash-Quark-MXFP4`, MXFP4 W4A4 experts on the AITER MoE (`--moe-backend aiter`, no shared-expert fusion). `--quantization-config.moe mxfp8` moves into the default variant, since only that checkpoint stores NVFP4 experts.
5. **Mono decode** (opt-in feature, MI355X + Quark only): a decode step of up to 16 tokens runs each layer as one kernel. Needs FP8 KV and indexer caches and `FULL_DECODE_ONLY` graphs. On the released image (aiter 0.1.26) it also needs #63270, the backport of #61889, to start.
6. **Fixes**: one `fp8` variant, limited to Hopper (the merge of `main` had duplicated the key; on MI355X and Blackwell it rendered NVFP4 caches). VRAM minimums per GPU: the NVFP4 variant shows 285 GB, and MI355X gets 533 GB after the MXFP8 re-quantization.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <vllm>/recipes` passes on vllm-project/recipes `main`. Rendered commands were checked for the default, Quark, and FP8 variants on MI355X, B300, and H200, with and without the new features.
- Rendered commands served on MI355X TP4 with `vllm/vllm-openai-rocm:minimax-m31-flash`, DSpark 3, AIME26 (16 epochs, max_tokens 98304, thinking on) and MMMU-Pro (all, 3460):

  | command | AIME26 | MMMU-Pro |
  |---|---|---|
  | default (MXFP8 MoE) | 0.9351 x6 ¹ | 0.7676 x1 |
  | MXFP4 (Quark) | 0.9368 x6 | 0.7763 x1 |
  | MXFP4 (Quark) + mono decode, concurrency 4 | 0.9417 x8 | – |

  ¹ Same image, KV/indexer/MoE settings and DSpark 3, but served by our eval script (block verification), not the rendered command.

## Details

- The DBO / SP modes are offered on the default variant only (SP and SP + DBO were measured on the MXFP8 MoE); the Quark variant gets DBO.
- The recipe schema needs a mode per variant, so `mono_decode` carries an empty mode for the other variants: enabling it there changes nothing.
- The Quark MMMU run used `--limit-mm-per-prompt '{"video": 0}'`. With video inputs on, one Quark server ran out of memory in the vision encoder at MMMU concurrency 256 (`--gpu-memory-utilization` 0.92).
