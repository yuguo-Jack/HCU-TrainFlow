# [Doc][Helm] Use model-response probes in the Helm chart example

[Upstream PR](https://github.com/vllm-project/vllm/pull/62436) · state: open · merged: False

## Original PR description

## Overview

The example Helm chart probed `/health`, which only reports whether the engine process is alive. It does not generate text, so a hung but alive engine still looked healthy. This PR makes the chart's startup, readiness and liveness probes check that the model actually returns text. It makes no change to vLLM code.

## Claims

- The default startup, readiness and liveness probes send a one-token completion (`/v1/completions`, `max_tokens: 1`, `temperature: 0`) and succeed only if the response contains non-empty text.
- A new `probeRequest` value defines the request once for all three probes.
- Users can override any probe with their own handler, for example `httpGet /health`. The chart keeps it as is.
- Nothing under `vllm/` is modified.

## Validation

- `helm lint .` passes.
- `helm unittest .` passes (13 tests, 3 new).

## Details

- Each probe uses GPU time and competes with user traffic. The liveness defaults are therefore tolerant (period 30s, timeout 30s, failure threshold 6), and the startup probe allows 120 attempts every 10s. The docs describe the `/health` fallback.
- The probes send no credentials, so they do not work when the server runs with `--api-key`. This is documented.
- `probeRequest.model` must match `--served-model-name`.
