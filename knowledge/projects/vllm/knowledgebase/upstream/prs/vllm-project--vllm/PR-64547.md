# [Bugfix][Config] Preserve Ray DP master address at DP=1

[Upstream PR](https://github.com/vllm-project/vllm/pull/64547) · state: open · merged: False

## Original PR description

## Overview

Preserve the master address selected by `EngineArgs` when using `--data-parallel-backend ray --data-parallel-size 1`.

Fixes #51712.

## Claims

- Preserve automatically selected and explicitly configured Ray master addresses at DP=1, including precedence over `VLLM_DP_MASTER_IP`.
- Preserve the multiprocessing backend’s offline SPMD environment fallback.
- Add configuration regressions and a real Ray serving regression, selected by a single-GPU Buildkite job.
- Document address defaults and precedence in CLI help, which generates the argument reference.

## Details

`EngineArgs.create_engine_config()` already selects the Ray launch address or honors `--data-parallel-address`. At DP=1, `ParallelConfig.__post_init__()` subsequently overwrites it through the offline SPMD environment fallback. Restrict that fallback to non-Ray configurations.

The core fix follows the approach proposed in [vLLM #51720](https://github.com/vllm-project/vllm/pull/51720), which was closed without merging. This PR extends coverage to CLI address selection, environment precedence, and real serving, and updates the generated CLI documentation.

The merged [Dynamo #12943](https://github.com/ai-dynamo/dynamo/pull/12943) works around this bug in Dynamo’s operator by setting `VLLM_DP_MASTER_IP` to the pod IP. The underlying fallback remains in current vLLM `main`. This PR corrects that behavior within vLLM itself. Duplicate checks found no open PR addressing this fix.

The serving regression reuses `RemoteOpenAIServer`, a real Ray cluster with a non-loopback node address, and `hmellor/tiny-random-LlamaForCausalLM`. It covers derived and explicit addresses while `VLLM_DP_MASTER_IP` contains loopback, then checks generated text, token count, and finish reason.
