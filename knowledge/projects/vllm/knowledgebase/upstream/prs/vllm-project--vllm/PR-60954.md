# [Bugfix][Model] Restore AXK1 config defaults dropped with the vendored config

[Upstream PR](https://github.com/vllm-project/vllm/pull/60954) · state: closed · merged: True

## Original PR description

- Default `scoring_func` to `sigmoid` and `topk_method` to `noaux_tc` in `AXK1MoE`
- Default `moe_layer_freq` to 1 in `AXK1DecoderLayer._is_layer_sparse`
- Drop the asserts that these fields exist on the config

https://github.com/vllm-project/vllm/pull/60623 replaced vLLM's vendored `AXK1Config` with the one from Transformers. The vendored class gave defaults for `scoring_func`, `topk_method` and `moe_layer_freq`, but the Transformers class doesn't define these fields, so any AXK1 config that leaves them out now fails with `AttributeError` while the model is being built. The official checkpoint sets them explicitly, so it still loads, but the minimal config in `test_online_shared_expert_fusion.py` doesn't, and that test has been failing since the change landed: https://buildkite.com/vllm/ci/builds/93915/list?jid=01a12348-9645-4aec-9354-4373972e9a30. This reads the fields with `getattr` and falls back to the old defaults, the same pattern `deepseek_v2.py` uses. The defaults also match what the Transformers AXK1 model always does: sigmoid routing with a score-correction bias, and an MoE layer on every layer from `first_k_dense_replace` onward.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
