# [Core] Pick hybrid KV cache group size by worst-case padding bytes; add --min-kv-cache-group-layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/58207) · state: open · merged: False

## Original PR description

## Purpose

`_get_kv_cache_groups_uniform_page_size` splits each KV cache bucket into groups of `group_size` layers and pads the last group of each bucket. The current heuristic uses the smallest bucket as `group_size` (or the largest, if it is within 1.5x). A single-layer bucket, typically a speculative drafter layer whose spec cannot merge with the target's, drives this to `group_size = 1`, which means one KV cache group per layer, each rebuilding attention metadata every step. Qwen3.6-35B-A3B + DFlash ends up with 46 groups.

This PR replaces the min / 1.5x-max heuristic:

- **Search** group sizes from `--min-kv-cache-group-layers` (capped at the largest bucket) up to the largest bucket.
- **Pick** the group size that wastes the fewest worst-case bytes per request on padding layers. Each padding layer costs its spec's `max_memory_usage_bytes` at `max_model_len`, so full attention padding scales with context length, while sliding window / mamba padding stays bounded. Ties prefer fewer groups.
- **New option `--min-kv-cache-group-layers` (default 3)** trades metadata overhead (more groups) against KV capacity (more padding).
- **Equal page sizes share a group** (from tomasruizt/vllm#16, by @tomasruizt): attention layers with different head shapes but the same block size, token-slot semantics and page bytes (e.g. Qwen3.5-4B's 4×256 target and 8×128 DFlash drafter) share one KV cache group; each keeps its own spec.
- **TP-invariant planning with a KV connector:** P/D peers may run different TP sizes, which change per-rank page bytes. When `kv_transfer_config` is set, padding is costed in the pages each layer needs per request at its own page size *before* page-size unification (TP changes page bytes, not page counts), and layers are not shared by equal page size (which also depends on TP). Qwen3.6-35B-A3B + DFlash then plans 10 groups at TP 1/2/4/8 (vs 17/17/5/10 without a connector).

This subsumes the 1.5x rule (gpt-oss + eagle still pads sw 12 → 13 instead of full 13 → 24).

Grouping at `max_model_len=256k`, default `--min-kv-cache-group-layers 3`:

| Layer buckets (target + *drafter*) | main | this PR |
|---|---|---|
| Qwen3.6-35B-A3B + DFlash `[30 mamba, 10 full, *5 sw, 1 full*]` | gs=1, 46 groups | gs=3, 17 groups; 2 target full + 2 drafter full + 1 drafter sw padding layers |
| Qwen3.5-35B-A3B + Eagle3 `[30 mamba, 10 full, *1 full*]` ¹ | gs=1, 41 groups | gs=5, 9 groups; 4 drafter full padding layers |
| MiMo-V2.5 + DFlash `[9 full, 39 sw, *5 sw*]` | gs=5, 11 groups; 1 full + 1 sw padding | gs=3, 18 groups; 1 drafter sw padding |
| Kimi-K3 + DSpark `[69 KDA, 24 MLA, *5 sw*]` | gs=5, 20 groups; 1 MLA + 1 KDA padding | gs=3, 33 groups; 1 drafter sw padding |
| Gemma3-27B `[52 sw, 10 full]` | gs=10, 7 groups; 8 sw padding | gs=5, 13 groups; 3 sw padding |
| gpt-oss-20b + eagle `[12 sw, 13 full]` | gs=13, 2 groups | unchanged |
| Gemma3-1B/4B/12B, Llama4-Scout, Qwen3.5-35B-A3B | — | unchanged |

¹ Computed assuming the drafter's KV bytes per token equal the target's; not measured.

Behavior change: group sizes can now go below the smallest bucket, trading more groups for less (bounded) padding, e.g. Gemma3-27B 7 → 13 groups, MiMo-V2.5 + DFlash 18 groups. Whether to keep a floor at the smallest bucket is open (it gives 7 / 7 / 17 groups for Gemma3-27B / MiMo / Kimi-K3, at the cost of more bounded padding).

### Comparison with #58175

#58175 targets MiMo. On DFlash / Eagle3 it keeps main's per-layer grouping (gcd of `[10, 1]` = 1). On MiMo-V2.5 + DFlash this PR now picks the same group size (gs=3, 18 groups, no full attention padding, 1 drafter sw padding layer).

Relation to other PRs:
- #51742 ignores single-layer buckets when taking the min (gs=5 for DFlash) without bounding the resulting full attention padding.
- #49472 minimizes `padding + num_groups` in layer counts, without distinguishing full attention from bounded-memory padding (e.g. pads 3 full attention layers on Gemma3-27B).
