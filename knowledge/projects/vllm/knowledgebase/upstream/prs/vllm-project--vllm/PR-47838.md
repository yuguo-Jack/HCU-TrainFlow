# [Bugfix][Frontend] Preserve logprobs when top_logprobs is null

[Upstream PR](https://github.com/vllm-project/vllm/pull/47838) · state: closed · merged: True

## Original PR description


## Purpose

`/v1/chat/completions` and `/v1/responses` both accept `top_logprobs: null`. When a client explicitly requests output logprobs and serializes this optional field as JSON null, current main returns 200 but silently omits generated-token logprobs.

The request conversion uses `top_logprobs` directly as `SamplingParams.logprobs`, so `null` becomes `None` and disables logprob computation. Chat serving also checks `top_logprobs is not None` before rendering logprobs into the response.

This treats `top_logprobs: null` like an omitted `top_logprobs` only when output logprobs are requested: sampled-token logprobs are computed with zero extra top candidates. Requests that do not ask for output logprobs still keep logprobs disabled.

## Test Plan

I reproduced this with a real OpenAI-compatible server using Qwen3-0.6B against both Chat Completions and Responses. The same script fails on current main, passes after this change, fails again after reverting this patch, and passes again after restoring it.

I also added focused protocol tests for Chat, Batch Chat, and Responses request conversion.

## Test Result

Current main returns `chat_logprobs_present=false` and `responses_logprobs_present=false`. After this change, both endpoints include sampled-token logprobs with `top_logprobs=[]`. Reverting the patch brings the missing-logprobs behavior back. Restoring the patch returns both endpoints to `*_logprobs_present=true`.

Client script:

```python
#!/usr/bin/env python3
import argparse
import json
import sys
import time
import urllib.error
import urllib.request


def post_json(base_url: str, path: str, payload: dict) -> dict:
    data = json.dumps(payload).encode("utf-8")
    request = urllib.request.Request(
        f"{base_url}{path}",
        data=data,
        headers={
            "Content-Type": "application/json",
            "Authorization": "Bearer token",
        },
        method="POST",
    )
    try:
        with urllib.request.urlopen(request, timeout=60) as response:
            body = response.read().decode("utf-8")
            return json.loads(body)
    except urllib.error.HTTPError as exc:
        body = exc.read().decode("utf-8", "replace")
        raise RuntimeError(f"HTTP {exc.code} from {path}: {body}") from exc


def wait_ready(base_url: str, timeout_s: int = 300) -> None:
    deadline = time.time() + timeout_s
    while time.time() < deadline:
        try:
            with urllib.request.urlopen(f"{base_url}/health", timeout=5) as response:
                if response.status == 200:
                    return
        except Exception:
            time.sleep(2)
    raise TimeoutError(f"server did not become ready within {timeout_s}s")


def chat_logprobs_present(response: dict) -> tuple[bool, object]:
    choice = response["choices"][0]
    logprobs = choice.get("logprobs")
    if not logprobs:
        return False, logprobs
    content = logprobs.get("content")
    if not content:
        return False, logprobs
    return all("logprob" in item for item in content), content


def responses_logprobs_present(response: dict) -> tuple[bool, object]:
    for item in response.get("output", []):
        for content in item.get("content", []):
            if content.get("type") == "output_text":
                logprobs = content.get("logprobs")
                if not logprobs:
                    return False, content
                return all("logprob" in item for item in logprobs), logprobs
    return False, response.get("output")


def main() -> int:
    parser = argparse.ArgumentParser()
    parser.add_argument("--base-url", default="http://127.0.0.1:18163")
    parser.add_argument("--model", default="qwen3")
    parser.add_argument(
        "--expect",
        choices=("present", "missing"),
        required=True,
        help="Expected output logprobs state for both Chat and Responses.",
    )
    args = parser.parse_args()

    wait_ready(args.base_url)

    chat_payload = {
        "model": args.model,
        "messages": [{"role": "user", "content": "Say one word."}],
        "max_tokens": 2,
        "temperature": 0,
        "logprobs": True,
        "top_logprobs": None,
    }
    responses_payload = {
        "model": args.model,
        "input": "Say one word.",
        "max_output_tokens": 2,
        "temperature": 0,
        "include": ["message.output_text.logprobs"],
        "top_logprobs": None,
    }

    chat = post_json(args.base_url, "/v1/chat/completions", chat_payload)
    responses = post_json(args.base_url, "/v1/responses", responses_payload)

    chat_ok, chat_detail = chat_logprobs_present(chat)
    responses_ok, responses_detail = responses_logprobs_present(responses)

    result = {
        "chat_logprobs_present": chat_ok,
        "responses_logprobs_present": responses_ok,
        "chat_detail": chat_detail,
        "responses_detail": responses_detail,
        "chat_text": chat["choices"][0]["message"].get("content"),
        "responses_text": responses.get("output_text"),
    }
    print(json.dumps(result, ensure_ascii=False, indent=2))

    expected = args.expect == "present"
    if chat_ok != expected or responses_ok != expected:
        print(
            f"EXPECTATION_FAILED expected={args.expect} "
            f"chat={chat_ok} responses={responses_ok}",
            file=sys.stderr,
        )
        return 2
    print(f"EXPECTATION_OK {args.expect}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

- NolenLiang · CHANGES_REQUESTED · 2026-08-25T10:43:00Z · [source](https://github.com/vllm-project/vllm/pull/47838#pullrequestreview-5017960438)

The normalization intent is correct, but this should not merge after only a rebase.

All three new `mode="before"` validators mutate the caller-owned raw dict via `data["top_logprobs"] = 0`. That mutation persists even if later validation fails, and it changes omitted/explicit-field semantics (`model_fields_set` / `exclude_unset`). The Responses validator also gates on `isinstance(include, list)`, so an input such as a tuple—which Pydantic can coerce to the declared list type—skips normalization and can leave effective logprobs unset.

Please normalize after typed parsing, or at minimum copy the mapping before changing it. Add regressions showing:
- the input mapping remains unchanged,
- null / omitted / explicit 0 normalize as intended,
- negative cases (`logprobs=False`, or Responses without the output-logprobs include) stay disabled,
- coercible container inputs follow the same behavior.

The branch is also substantially behind main and needs a rebase plus real functional CI on the updated head.
