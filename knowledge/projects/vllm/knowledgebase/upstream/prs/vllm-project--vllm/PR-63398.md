# [ROCm][Perf] Replace MiniMax-M3 MonoKernel with ATOM full-layer implementation

[Upstream PR](https://github.com/vllm-project/vllm/pull/63398) · state: open · merged: False

## Original PR description



## Overview

Replace MiniMax-M3's FFN-only MonoKernel on TP4 MI355X with a port of ATOM's full sparse-layer pipeline into vLLM. Delete the old kernel, launcher and mode selector; `--monokernel` selects the new implementation under the existing Model Runner V2 lifecycle.

Related architecture: #60904. Related approaches: #59705 and #59653; distinctions are below.

## Claims

- The old FFN kernel, executor, synchronization code and obsolete tests are removed, along with unused dense-kernel copies from the port. The sole MiniMax MonoKernel implementation lives directly under `specialized_decode/mono/`; there is no extra `mono/layer/` namespace or `monokernel_mode` selector.
- One fused launch per sparse layer for 1–16 physical decode/verification rows, including padding and FULL graph replay. Matched traces reduce approximately 821 launches per c4 step to 275. Native modules and cache layouts remain available for prefill, dense layers and larger/mixed steps.
- The evaluated AgentX c1/c4 recipe reaches the published ATOM reference's throughput, ITL and TTFT. These are end-to-end results for the complete kernel/configuration stack, including FP8 draft projections, dense-attention tuning and the existing fastokens backend.
- All fused sparse-layer kernels and their runtime are in `vllm/models/minimax_m3/amd/specialized_decode/`; this does not depend on an external ATOM runtime or AITER's proposed MiniMax fused-layer operator. Existing FlyDSL/AITER primitive helpers, packing and ordinary attention/MoE operators are still used.

## Details

The old MonoKernel left input normalization, projections, the indexer and attention as separate launches and dequantized FP4 expert weights for BF16 MFMA. This port uses scaled MXFP8 × MXFP4 MFMA and fuses the sparse layer. The remaining end-to-end bottlenecks were under-partitioned dense decode attention, query-by-query dense prefill, a draft that did not inherit target FP8 rules, and CPU BPE tokenization.

The model-owned runtime reuses the existing per-step plan and native weights/caches, binds main and index caches independently, compiles supported widths before graph capture, and uses bounded mailbox waits with a step-end TP fence and device-side failure assertion. An execution failure stops the engine. Prefill, the first three dense layers and unsupported step widths retain native dispatch.

Precision choices follow ATOM: group-of-32 MXFP8 expert activations, BF16 router weights/logits and BF16 rotary tables. The previous FFN-only implementation and `monokernel_mode` field are deleted. Existing MiniMax deployments must configure FP8 attention projections before enabling `--monokernel`; the rendered deployment documentation includes the complete recipe.

### Related work and attribution

- **#59705:** also ports ATOM's sparse-layer fusion. The submitter has discussed its performance regression versus native with its author and requested this replacement. This PR integrates the implementation into the existing `specialized_decode` MRV2 lifecycle, with cache rebinding, independent cache mappings, padding/verification coverage, bounded cross-rank failure handling, and the full-hour AgentX results above. No independent benchmark of #59705 is claimed here.
- **#59653:** delegates the fused implementation to a proposed AITER operator. This submission keeps the sparse-layer implementation and runtime in vLLM so they can be maintained and tuned here; it does not require that external fused-layer operator.
