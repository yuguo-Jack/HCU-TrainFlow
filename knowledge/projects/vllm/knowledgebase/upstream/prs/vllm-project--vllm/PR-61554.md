# [DSv4.1][PCP] Share CPU-offloaded Engram tables

[Upstream PR](https://github.com/vllm-project/vllm/pull/61554) · state: open · merged: False

## Original PR description

## Overview

Share CPU-offloaded DeepSeek-V4.1 Engram tables across PCP replicas, reusing the existing shared-memory storage. This isolates the Engram work from #61553; the earlier replay changes in this PR are now covered by main.

## Claims

- Keep one copy of each TP head shard for its PCP group, without changing token ownership or lookup results.
- Fail early if shared-memory capacity or IPC placement is unsuitable, and keep DSpark's draft configuration separate.

Enable with `--engram-config '{"cpu_offload": true, "pcp_shared_memory": true}'`. The option defaults off and requires PCP > 1, DP = PP = 1, and co-located replicas sharing an IPC namespace.

## Validation

Four H20 GPUs, TP1/PCP4/EP4, fixed DSpark5, Humming MoE, 16K batch-token limit, APC and SWA bounded replay:

| Source / execution | Full GSM8K, 5-shot | Client time | Mean TPOT (ms/token) | Cold 64K TTFT |
| --- | ---: | ---: | ---: | ---: |
| Engram on main, eager | 1229/1319 (93.18%) | 374.35s | 43.46 | 2.348s |
| Engram + #61555, FULL_AND_PIECEWISE | 1229/1319 (93.18%) | 189.64s | 20.87 | 2.346s |

Mean TPOT averages vLLM's server-side per-request `decode time / (output tokens - 1)` over all 1,319 distinct GSM8K test questions. The separate synthetic 64K decode benchmark is not included.

In each run, all four workers mapped the same two backing files. Combined Engram PSS was **188.8 GiB**, with no private dirty pages in those mappings: one resident copy instead of four (75% less table storage). This measures table memory, not total process memory.

Client time includes evaluation harness overhead. The graph row also includes #61555, so these timings do not isolate the performance impact of Engram sharing. Cold TTFT uses three measured requests after warmup with cache resets.

Both runs passed all 21 serving probes, including changing PCP segment counts and cache reuse, with no engine/client errors. Actual FULL and PIECEWISE execution was verified in the integration run. The targeted suites passed: 31 distributed, 51 configuration and 14 DSpark tests. The existing four-GPU Engram job gains two cases: TP1/PCP4 and TP2/PCP2. No new CI job is added. Full checkpoint evaluation was performed outside CI.

## Details

The existing allocator owns and registers the shared table; each PCP rank keeps its existing lookup and staging path. Sharing is per TP shard, so TP2/PCP2 retains two distinct head shards. `dp_shared_memory` and `use_thp` cannot be combined with this option. Multimodal PCP support is separate work.
