# [DSv4.1][PCP] Enable cold decoder SWA bounded replay

[Upstream PR](https://github.com/vllm-project/vllm/pull/61554) · state: open · merged: False

## Original PR description

## Overview

Enable DeepSeek-V4.1 cold-prefill decoder SWA bounded replay with PCP by adapting the existing replay batch to PCP's local segments and collective layout. Stacked on #59857 and #61553 (fixed DSpark and optional shared Engram); the GitHub diff against main includes those dependencies. Keep this PR in Draft for broader evaluation and human review. GitHub currently reports merge conflicts against main; dependency/main integration remains pending, and the measured source has not been silently rebased.

## Claims

- Reuse `ReplayBatch`, `InputBatch`, the existing gather kernel, attention builders and PCP process group; no new scheduler, partitioner, kernel or public configuration field.
- Keep each PCP segment's intersection with the request's global scheduled tail, preserve its original owner, agree on padded sizes, and gather retained KV slots in the same rank-major order as their payload. Empty local prefill/decode partitions are dispatched by token count.
- Initial four-H20 cold-prefill measurement: **5,664.64 -> 9,729.21 input tokens/s (+71.75%)** at 64K input, concurrency 4, one output token. The global-tail follow-up measures +4.58% over the previous local-segment-tail implementation (9,302.84 tokens/s). These are sequential comparisons with three within-arm samples, not independent interleaved A/B pairs.

## Validation

**Runtime:** four H20-3e GPUs, TP1/PCP4/DP1/EP4, fixed DSpark5, Humming A16, shared CPU Engram, 8,192-token chunks, max-seqs 64, FP8 DS-MLA KV, eager/MRV2, synchronous scheduling, APC off. `VLLM_GPU_SYNC_CHECK=error` remained enabled. The lab reused compiled extensions from its existing a98247ab4 runtime; this is not a clean full native rebuild.

- Three existing replay suites: **27 passed** (10.50 s), including global-tail intersections, retained local slots, empty query partitions, padding, output scattering, prompt-logprobs and existing graph regressions. A separate CPU oracle using the actual PCP partitioner and selection logic passed 900 PCP2/4/8 cases; it does not replace distributed GPU validation. PCP collectives in unit tests are mocked; distributed evidence comes from the real model below, not these mocks.
- Four-rank real model: **32/32 fixed GSM8K canaries**, no HTTP errors or truncated answers; **3,965/5,645 real draft tokens accepted** over 1,129 draft steps.
- **8/8 additional checks:** exact 1,023/1,025-token prompts with replay and full-row prompt-logprobs controls; ragged concurrent 8,191/8,193/16,385/65,537-token prompts followed by natural decode. These are public math questions with neutral context, not a full long-context accuracy evaluation or logit-equivalence test.
- Applicable pre-commit hooks, including mypy, passed. Tests extend existing CI-wired files; the four-rank checkpoint evaluation was run outside CI. No PCP full-model CUDA Graph claim is made.

**Cold-prefill benchmark:** eight requests per round, four continuously replenished workers, 65,536 input tokens/request, output length 1, temperature 0. Every response reports zero cached tokens. One warmup followed by three formal rounds; all samples retained.

## Details

PCP presents two local segments per original request and gathers cache slots in rank-major order. Replay metadata therefore needs per-segment capacity, local slot selection before compaction, and a fresh gather after padding to a common size. Two small CPU-group all-reduces recover global scheduled bounds using shared request-state IDs, then agree on whether to trim and the retained size. Empty segments do not contribute to the bounds. They do not read GPU tensors, but add host collectives per preparation. The global tail floor uses a separate UVA staging pool so prefix-layer metadata remains intact. Inputs/indexer buffers are zero-padded and only real output rows are scattered back.

The first real trim at 1,025 tokens exposed lazy attention-builder construction copying an indexer constant to the GPU in the checked hot path. Creating those existing builders during initial metadata startup fixes this without exempting synchronization checks.

The first global-tail model run exposed an empty decode partition with nonzero decode request metadata in a mixed batch. Dispatching FlashMLA prefill/decode by actual token counts fixes the zero-row reshape; outer KV publication and PCP collectives remain intact.

Unlike the previous local-segment-tail implementation, this retains the request's global tail, as motivated by SGLang's decoder CP replay. It preserves vLLM's original zigzag owner rather than adding a new token-layout protocol. Consequently, a single long request's retained tail may concentrate on one rank while peers execute padded work; SGLang's interleave layout distributes it across ranks. Globally short chunks retain the existing replay floor. Targeted canaries do not establish equivalence to replay-disabled logits. Prefix hits, KV transfer, sequence parallelism, microbatching and PCP CUDA Graph integration remain unsupported by the applicable parent guards. Prompt-logprobs requests keep all rows.

Existing #56227/#58132 provide the replay mechanism. #60046 concerns P/D replay endpoints; #58289/#57872 concern encoder-only P/D. This change covers the cold colocated PCP adapter and does not duplicate those implementations. SGLang's decoder bounded replay and CP tail-layout code informed the comparison; the runtime patch reuses vLLM's existing components. The parent MoE padding prerequisite #60946 still applies.

AI assistance was used to implement, review and validate this change with OpenAI Codex. Human line-by-line review and broader model evaluation remain pending; this PR remains a Draft.
