# [Model] Support mm_device_do_normalize for MiniMax-M3

[Upstream PR](https://github.com/vllm-project/vllm/pull/58972) · state: closed · merged: False

## Original PR description

Wire the fused device-side input normalization into MiniMax-M3, following the Qwen2-VL integration pattern:

- Set supports_mm_device_do_normalize on MiniMaxM3SparseForConditionalGeneration (nvidia and amd variants) so the flag defaults to on.
- Build the input norm via build_mm_input_norm and apply it at the MiniMaxVLVisionTransformer entry; raw uint8 pixels are normalized on device, and the pre-casts in _process_image_input/_process_video_input are removed since the norm layer owns the dtype conversion.

The vendored MiniMaxM3VL image/video processors already emit uint8 pixel_values when do_normalize/do_rescale are off, so no processor changes are needed. With the flag off, IdentityInputNorm reproduces the previous behavior bit-identically.
