# [Rust Frontend] Complete partial cached HF snapshots when online

[Upstream PR](https://github.com/vllm-project/vllm/pull/63300) · state: open · merged: False

## Original PR description



## Overview

Fix `SourceFiles::open` in `vllm-text` so that when `HF_HUB_OFFLINE` is not enabled, a partially populated local Hugging Face Hub snapshot (for example, when `transformers` only downloaded `tokenizer.json`) does not shadow uncached optional repo files (`generation_config.json`, `chat_template.jinja`, `processor_config.json`, `config.json`) that exist on the Hub.

## Claims

- When online (`HF_HUB_OFFLINE` unset or disabled), `SourceFiles::open` queries the Hub repo file list (`repo.info()`) and reuses any file already present in the cached snapshot directory (`snapshot: Option<PathBuf>`) while downloading missing repo siblings on demand.
- When offline (`HF_HUB_OFFLINE=1`), `SourceFiles::open` continues to resolve directly from the local snapshot directory without network access.
- Adds unit test `online_resolution_completes_partial_cached_snapshot` verifying that a cached snapshot containing only `tokenizer.json` reuses the cached `tokenizer.json` and downloads `generation_config.json` from the Hub endpoint.

## Validation

- **Reproducer (without fix vs with fix):**
  - Without fix (`SourceFiles::open` returning `SourceFiles::Dir` in online mode): `online_resolution_completes_partial_cached_snapshot` fails with `assertion left == right failed: left: None, right: Some(".../snapshots/commit/generation_config.json")`.
  - With fix: `online_resolution_completes_partial_cached_snapshot` passes (`1 passed; 0 failed`), and `lower::tests::lower_text_request_uses_real_qwen_generation_defaults` and `vllm-chat` `roundtrip_qwen3` / `roundtrip_step5` / `roundtrip_qwen35` pass when the shared HF cache initially contains only `tokenizer.json`.
- **Test commands run:**
  ```bash
  cargo test --manifest-path rust/Cargo.toml -p vllm-text --locked
  cargo test --manifest-path rust/Cargo.toml -p vllm-chat --test roundtrip --locked -- roundtrip_qwen3 roundtrip_step5 roundtrip_qwen35
  cargo fmt --manifest-path rust/Cargo.toml --all -- --check
  cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --all-features --locked -- -D warnings
  ```
- **Results:** `115 passed; 0 failed; 1 ignored` in `vllm-text`; `3 passed; 0 failed` in `vllm-chat` roundtrip tests; `cargo fmt` and `cargo clippy` clean with zero warnings.
- **Model evaluation:** N/A (fixes HF file resolution when a local cache snapshot is incomplete; restores expected loading of `generation_config.json` and `chat_template.jinja`).

## Details

- **Root cause:** `SourceFiles::open` previously checked `if let Some(snapshot) = cached_snapshot_dir(&cache, &repo).map(Self::Dir) && snapshot.contains(required).await? { return Ok(snapshot); }` before checking `is_hf_hub_offline()`. Because `SourceFiles::Dir::get` only checks `dir.join(filename).is_file()`, any optional file not already downloaded into that snapshot directory was treated as absent (`Ok(None)`) even in online mode.
- **Implementation & tradeoffs:** Restricts `Self::Dir(snapshot)` for Hub repos to `is_hf_hub_offline()`. In online mode, `SourceFiles::Remote` stores `snapshot: Option<PathBuf>` and `Box<ApiRepo>` (boxed to satisfy `clippy::large_enum_variant`), and `download_known_file` returns the local snapshot path if `dir.join(filename).is_file()` before calling `repo.download(filename)`.
- **Duplicate-PR check:** Searched open PRs via `gh pr list --repo vllm-project/vllm --state open --search "model_files.rs OR SourceFiles OR HF_HUB_OFFLINE"`; no existing PR addresses partial HF snapshot resolution in `rust/src/text/src/backend/hf/model_files.rs`.
- **AI assistance:** AI assistance was used to diagnose the partial cache snapshot bug, write the unit test, and prepare this PR; all changes were reviewed and verified locally.
