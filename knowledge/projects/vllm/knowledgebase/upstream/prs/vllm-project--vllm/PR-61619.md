# [Bugfix][NIXL] Fix handshake crash for SSM-only models

[Upstream PR](https://github.com/vllm-project/vllm/pull/61619) · state: open · merged: False

## Original PR description

## Summary

Fixes #61617

`_build_fa_remote()` looks up the full-attention KV group index with a
bare `next(...)`, which raises `StopIteration` for models without any
attention group (SSM-only, e.g. Mamba models). The exception aborts the
whole NIXL handshake and every subsequent transfer fails with an
unhelpful `handshake_failed`.

The same bare lookup also exists in `_build_local_splits_from_plan()`
(heterogeneous-TP path).

## Fix

- `_build_fa_remote()`: when no attention group exists, fall back to the
  sole non-attention group's source ranks. FA descriptors are still
  emitted: on SSM-only models those slots are layout padding that the
  producer registers (`_build_fa_local`) and that `_compute_desc_ids`
  offsets SSM descriptor ids past, so they must exist for the read index
  math to stay aligned.
- `_build_local_splits_from_plan()`: same fallback for the FA split
  count.

## Test Plan

- Added unit tests for both functions with SSM-only spec types.
- End-to-end verified on GPU (A100, NIXL/UCX pull mode, P+D disagg
  serving state-spaces/mamba-130m, homogeneous TP1):
  - before the patch: the decode-side handshake dies with
    `StopIteration`;
  - with the patch applied to the same setup: handshake, KV transfer
    and remote decode all succeed (1 successful transfer, 48
    descriptors, ~1.3 MB, ~23 ms; the decode completes the prompt
    correctly with 0 transfer failures in the logs).
