# [Bugfix][NIXL] Fix handshake crash for SSM-only models

[Upstream PR](https://github.com/vllm-project/vllm/pull/61619) · state: open · merged: False

## Original PR description

## Summary

Fixes #61617

`_build_fa_remote()` and `_build_local_splits_from_plan()` look up the full-attention KV group index with a bare `next(...)`, which raises `StopIteration` for models without any attention group (SSM-only, e.g. Mamba models). The exception aborts the whole NIXL handshake and every subsequent transfer fails with an unhelpful `handshake_failed`.

## Fix

- `_build_fa_remote()`: when no attention group exists, gather the padding rows from all remote source ranks (`num_reads = len(plan.all_source_ranks)`). On SSM-only models the FA slots are layout padding that the producer registers (`_build_fa_local`) and that `_compute_desc_ids` offsets SSM descriptor ids past, so they must exist for the read index math to stay aligned. The local page is gathered from every remote source rank, so each padding row covers one remote page; a smaller count runs past the remote registered region and NIXL refuses the list (`NIXL_ERR_NOT_FOUND`).
- `_build_local_splits_from_plan()`: pass the FA padding slots through whole (`fa_num_splits = 1`). They are never read on the decode side, and keeping them whole makes the heterogeneous-block-size assert hold for any TP plan — including the in-process decode executor's `block_size_ratio` 128, where a rank-count fallback trips `Head-sharded attention reads with P_TP > D_TP and heterogeneous block sizes are not supported`.

## Test Plan

- New unit tests in `tests/v1/kv_connector/unit/test_tp_mapping.py` cover both functions for remote TP 1 and 2, including `block_size_ratio=128` (the in-process executor's ratio). On unpatched main the new cases fail with `StopIteration`/`RuntimeError: generator raised StopIteration`; with the fix, all 34 tests in the file pass.
- End-to-end verified on GPU (A100, NIXL/UCX pull mode, P+D disagg serving `state-spaces/mamba-130m`, TP1, latest main): handshake, KV transfer (48 descriptors) and remote decode all succeed — decode HTTP 200, no `StopIteration` / `handshake_failed` / `Traceback` in the decode log.

## Fix

- `_build_local_splits_from_plan`: when no attention group exists, the FA slots are layout padding the decode side never reads (`_compute_desc_ids` only assigns FA ids to attention groups). Pass them through whole (`fa_num_splits = 1`) so the heterogeneous-block-size assert holds for any TP plan. The previous version of this PR reused the SSM group's rank count instead: at P_TP 2 it mis-split the padding rows even at ratio 1, and with the in-process decode executor (`block_size_ratio` 128) it tripped `Head-sharded attention reads with P_TP > D_TP and heterogeneous block sizes are not supported`.
- `_build_fa_remote`: without an attention group, `num_reads = len(plan.all_source_ranks)`. An SSM-only model's local page is gathered from all remote source ranks, so each padding row covers one remote page; a smaller count runs past the remote registered region and NIXL refuses the descriptor list with `NIXL_ERR_NOT_FOUND`. This also answers the review question about the hetero-TP bounds: with each padding row sized to one remote page per source rank, every row stays inside the remote region that `prep_xfer_dlist` validates against.
