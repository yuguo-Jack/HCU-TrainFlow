# [ROCm][CI] Add dtype to the KDA metadata test's fake model config

[Upstream PR](https://github.com/vllm-project/vllm/pull/61650) · state: closed · merged: True

## Original PR description



## Overview

Fixes `test_kda_recoverssm_startup_metadata_flow_without_model` on MI300/MI355, broken by #60645.

Broken CI build on main: https://buildkite.com/vllm/ci/builds/94799/canvas?jid=01a13a82-312f-41d0-a166-9d38788a7f14&tab=output

## Claims

- Adds `dtype` to the test's fake `model_config`; no non-test changes.

## Validation

`pytest models/kimi_k3/test_kda_metadata.py` on MI300X with the AMD CI image from [amd-ci #14622](https://buildkite.com/vllm/amd-ci/builds/14622) (includes #60645):

| | Result |
|---|---|
| main | 1 failed, 38 passed |
| this PR | 39 passed |

Same failure in CI: `AttributeError: 'types.SimpleNamespace' object has no attribute 'dtype'` (MI300 and MI355 Kimi K3 jobs).

## Details

On MI3xx, #60645's `_resolve_gdn_prefill_backend` calls `_aiter_flydsl_unsupported_reasons`, which reads `vllm_config.model_config.dtype`. The test's `SimpleNamespace` config had no `dtype`. Real configs always do. No open PR fixes this; #61250 edits the same test file but not this config.
