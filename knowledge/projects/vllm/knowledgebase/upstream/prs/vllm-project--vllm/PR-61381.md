# [Perf][Core] Gate the common-prefix scan and compute it over scheduled requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/61381) · state: closed · merged: False

## Original PR description

## Overview

Two changes to the per-step common-prefix block scan used by cascade
attention: skip it entirely when cascade attention is disabled (the
default), and make it precise over the requests scheduled in the current
step (previously it was zeroed by any request merely holding KV cache).

## Claims

- **Default deployments (cascade attention off) no longer run the scan
  at all.** `disable_cascade_attn` defaults to `True`, so every step ran
  an O(common-prefix blocks) Python scan whose result was discarded.
  Measured 0.041 ms/step at 64 requests sharing 2,000 blocks; removed
  entirely.
- **When cascade attention is enabled, the scan now reports the common
  prefix of the scheduled set.** The old implementation compared each
  block's `ref_cnt` against *all* requests holding KV cache, so a single
  preempted or idle request with a different prefix forced the result to
  0 even when every scheduled request shared a long prefix (documented in
  the old `KVCacheManager.get_num_common_prefix_blocks` NOTE). The new
  implementation computes the true LCP over the scheduled requests only.
- **The precise scan costs O(num_scheduled × log(blocks))** instead of
  the naive O(num_scheduled × blocks): blocks are compared by physical
  identity, and because a referenced cached block is never evicted, two
  live requests share the block at a position iff they share every
  earlier position — agreement is prefix-monotone, so it binary-searches
  with one comparison per probe (~2.8k comparisons for 256 requests ×
  2,000 blocks, same order as the previous O(P) scan).

Not duplicated by open PRs: #53690 skips the old scan when only one
request has allocated KV cache (an in-scan special case) and #53683 is
its motivating issue. This PR gates the scan on its consumer and
replaces the scan itself, which covers the multi-request case #53690
keeps. The two are complementary in intent; this PR subsumes the
single-request case (single scheduled request → 0).

## Validation

- New unit tests:
  - `test_full_attention_common_prefix_among_scheduled_requests_only`:
    mixed prefixes, an idle different-prefix request holding KV cache
    (the previously-zeroing case), mid-prefix divergence, shorter
    tables, single/empty scheduled set.
  - `test_full_attention_common_prefix_with_prefix_caching`: end-to-end
    through the APC path (`allocate_slots` → `get_computed_blocks` →
    cache-hit allocation), asserting the shared physical blocks are
    reported.
  - `test_rswa_common_prefix_bounded_by_reference_region`: two requests
    sharing a reference prefix with identical null gaps must report the
    reference-region LCP, never counting the null gap (identity
    comparison alone would over-report by the gap length).
  ```
  .venv/bin/python -m pytest tests/v1/core/test_single_type_kv_cache_manager.py -q \
    -k common_prefix
  # macOS/CPU: 3 passed; B200 GPU server (CUDA platform): 3 passed
  ```
- Affected suites: `test_single_type_kv_cache_manager.py` +
  `test_prefix_caching.py` — 224 passed locally, no regressions.
  `test_scheduler.py` + `test_async_scheduler.py` — 226 passed locally
  (1 pre-existing failure is the cascade-enabled gating case, blocked
  on CPU platforms by the platform check that itself forces
  `disable_cascade_attn=True`; passes on the B200 server, both branches).
- On the B200 server (stubbed extension modules), the affected suites'
  baseline fails 46 pre-existing environment cases with and without
  this patch; the patch adds its new tests and no new failures.

### End-to-end (B200, Qwen3-0.6B, run by the submitter)

- Targeted unit tests on the serving host: 5/5 passed, covering the
  default-path scan gating, the scheduled-set common prefix, and the
  R-SWA reference-region bound.
- 24-request shared-prefix workload, baseline vs patched: 24/24 requests
  succeed on both; per-request outputs are byte-identical on the
  default path.
- Prefix cache sanity under the same workload: 22,528 / 27,648 tokens
  hit (~81.5%), confirming shared-prefix requests actually share KV.
- FLASH_ATTN backend with cascade attention enabled vs disabled on the
  patched build: all 24 request outputs identical, i.e. the precise
  scheduled-set LCP feeds cascade attention without changing results.

What this does and does not show: output equivalence under cascade
attention is verified (the strongest correctness claim), but throughput
gains from cascade attention under mixed traffic were not benchmarked;
per the description above, the patch's direct wins are the removed dead
scan under the default config and the non-zeroing of the LCP under
stragglers.

## Details

- `Scheduler.__init__` computes `compute_common_prefix_blocks` once from
  `model_config.disable_cascade_attn`. No ubatching / spec-decode
  conditions are needed: `VllmConfig.__post_init__` already forces the
  flag off under async speculative decoding, DBO, and
  `VLLM_BATCH_INVARIANT`; the CPU platform forces it too.
- `schedule()` passes the union of scheduled new/resumed/running request
  IDs to the scan. Requests scheduled this step are the batch the model
  runner executes; the model runner additionally caps the common prefix
  by the batch-wide `num_computed_tokens.min()`, so new prefill requests
  in the batch naturally cap it to 0 regardless of the reported blocks.
- The scan interface (`SingleTypeKVCacheManager.get_num_common_prefix_blocks`)
  now takes the scheduled request IDs instead of a probe request ID.
  The seven no-op managers (sliding window, mamba, chunked local,
  cross-attention, etc.) keep their explicit "not supported" overrides
  with unchanged bodies.
- Block comparison uses physical identity (`block_id`) rather than block
  hashes: with kv-sharing one physical block can carry multiple hashes,
  and for live requests identity agrees with hash-chain equality while
  being immune to partial-hash entries. Monotonicity relies on the
  BlockPool invariant that a referenced block is never evicted (so both
  requests resolve the same chained hash to the same block); CoW
  `move_block_hashes` migrations only cause under-reporting (safe).
- RSWA frees its reference-to-window gap into the shared null block,
  which every request's table references identically; identity
  comparison alone would count a matching gap as shared prefix. Instead
  of dropping the value to 0, RSWA records each request's gap start when
  `remove_skipped_blocks` frees it and bounds the search at the
  reference-region boundary — so shared prompts still enable cascade
  attention over their (always-visible) reference prefix, preserving
  the previous ref_cnt-based behavior. Covered by
  `test_rswa_common_prefix_bounded_by_reference_region`. Pure
  FullAttention tables never contain null blocks (skip count is 0, and
  the removal path is R-SWA / connector specific); circular-buffer
  managers claim one private block per request with caching disabled, so
  identity comparison naturally yields 0. External (connector) computed
  blocks are always freshly allocated, so they can only cause
  under-reporting.
- `record_function_or_nullcontext` profiler span now only wraps the scan
  when it runs.
- The V2 model runner does not read `num_common_prefix_blocks`
  (grep-verified); when it does, the gating condition should be revisited.
