# Fix MFU/MBU dropping attention and FFN for renamed quantization methods (Fixes #58742)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64313) · state: open · merged: False

## Original PR description

Fixes #58742. MFU/MBU silently dropped attention and FFN for gpt-oss (gpt_oss_mxfp4), DeepSeek-V4 FP8 (deepseek_v4_fp8), GPTQ (auto_gptq) and AWQ (auto_awq) because their quant config names were missing from _QUANT_WEIGHT_BYTE_SIZE, and ModelMetrics only logged the failure at debug level. This PR adds those four names with their verified byte sizes and, for any still-unknown method (e.g. online, humming, modelopt_mixed), falls back to the model-dtype weight size set by BaseConfigParser with a logger.warning_once instead of dropping the component. The unknown-method test now asserts that fallback (bfloat16 -> 2 bytes). Local test scope (CPU-only VM, no accelerator): tests/v1/metrics/test_perf_metrics.py - 76 passed, 0 failed; the teardown errors in that run are only vLLM's cleanup hook calling torch.accelerator.empty_cache() with no accelerator device present, not test failures. DeepSeek-V4 MLA attention gap noted in the issue is separate and not fixed here. Written with: Muse (Meta AI assistant); I ran the checks above and reviewed the results.
