# [Doc] MiniMax-M3: B300 AgentX preset: add chunked prefill, fix the autotune-flag note

[Upstream PR](https://github.com/vllm-project/vllm/pull/63810) · state: open · merged: False

## Original PR description

## Overview

Follow-up for the B300 NVFP4 AgentX lane of [SemiAnalysisAI/InferenceX#4357](https://github.com/SemiAnalysisAI/InferenceX/pull/4357) (head `8c8d7789`, key `minimaxm3-fp4-b300-vllm-agentic-mtp`) in `recipes/models/MiniMaxAI/MiniMax-M3.yaml`. #63407 moved B300 to this head's curve and #63534 turned it into the `b300_agentx` preset: image `nightly-49cb2bbf`, TP8 at concurrency 1, TP4 at 20 and 24, and TP2 with host KV offload at 24 and 28. Checked against the lane, every preset point matches except one flag, and one comment in the B300 override is no longer accurate. This PR fixes both.

## Claims

- `b300_agentx` preset: adds `--enable-chunked-prefill`, which the lane passes at every point. The builder's NVFP4 command does not include it.
- B300 override comment: the old comment said the image predates the `--disable-x` aliases. It doesn't. `nightly-49cb2bbf` contains #61479 (`1c4c3197` is an ancestor of `49cb2bbf`), and that image's `vllm/utils/argparse_utils.py` pairs `--enable-x` with `--disable-x` and still accepts `--no-enable-x`. The override keeps the lane's own spelling, `--no-enable-flashinfer-autotune`. The comment now also points to the preset instead of the guide for per-point settings.
- `meta.date_updated` is now 2026-10-26.

- esmeetu · comment · 2026-10-27T02:04:15Z · [source](https://github.com/vllm-project/vllm/pull/63810#discussion_r4384411559)

File: `recipes/models/MiniMaxAI/MiniMax-M3.yaml` · line 555

This flag is a no-op here. `enable_chunked_prefill` defaults to `None`, and `EngineArgs._set_default_chunked_prefill_and_prefix_caching_args` resolves it to `model_config.is_chunked_prefill_supported`, which is `True` for a decoder-only generate model like MiniMax-M3. I checked `49cb2bbf` (the preset image) and it has the same logic, so the builder's NVFP4 command already runs with chunked prefill on. The log line `Chunked prefill is enabled with max_num_batched_tokens=...` should appear both with and without this flag.

Matching the lane's command line word for word isn't a good reason to add flags that are already the default. It makes the preset look like it differs from the builder when it doesn't, and readers will copy the flag into more recipes, which already have about 40 redundant `--enable-chunked-prefill` occurrences. Could we drop this line? Then the PR's only change is the comment fix. If you'd rather keep the preset identical to the lane, please change the comment to say the flag only mirrors the lane and is the default (no behavior change), not that the builder is missing it.
