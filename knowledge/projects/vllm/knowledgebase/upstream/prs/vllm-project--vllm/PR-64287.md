# [Model] Remove Keye-VL and Keye-VL-1.5

## Overview

Remove `KeyeForConditionalGeneration` (Keye-VL-8B-Preview) and `KeyeVL1_5ForConditionalGeneration` (Keye-VL-1.5-8B). Over 90% of their Hub downloads come from vLLM CI, and Keye-VL-1.5's remote image processor breaks on Transformers 5.21 (#64049).

| Model | Released on the Hub | Added to vLLM |
|---|---|---|
| Keye-VL-8B-Preview | 2025-06-26 (16 months ago) | 2025-07-02 (#20126) |
| Keye-VL-1.5-8B | 2025-08-26 (14 months ago) | 2025-09-01 (#23838) |

## Claims

- Both architectures are removed from the registry, tests, examples and supported models docs.
- Both are added to `_PREVIOUSLY_SUPPORTED_MODELS` with `0.33.0`, the last release that has them (the v0.33.0 release branch is already cut), so loading one raises a clear error.
- Kwai's newer Keye checkpoints (Keye-VL-2.0, Keye-VL-671B) use architectures vLLM never supported, so nothing else is affected.
- Supersedes #49676, which fixes an error message in `keye_vl1_5.py`.

## Validation

- `pytest tests/models/test_registry.py`: 429 passed, 9 skipped.
- Resolving `KeyeVL1_5ForConditionalGeneration` raises "was supported in vLLM until v0.33.0".
- `pre-commit run` passes, and no Keye references remain (`git grep -E "Keye|keye_"`).
