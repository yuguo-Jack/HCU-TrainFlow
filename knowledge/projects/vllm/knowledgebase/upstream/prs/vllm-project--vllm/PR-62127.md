# [Bugfix][Frontend] Preserve HTTP error response headers

[Upstream PR](https://github.com/vllm-project/vllm/pull/62127) · state: open · merged: False

## Original PR description



## Overview

Preserve HTTP error headers through vLLM's shared exception handler and Cohere error-envelope conversion. A `429` raised with `Retry-After: 30` now keeps its retry delay; `401` responses keep their authentication challenge.

## Claims

- Forward `HTTPException.headers` when building the shared error response.
- Preserve headers, including repeated `Set-Cookie` entries, on translated and already Cohere-shaped errors. Regenerate `Content-Length` and `Content-Type` when replacing the JSON body; retain the original wire headers when passing it through.

## Validation

- Before the fix: **5 failed, 1 passed** in the focused regression selection. Fixing only the shared handler leaves **3 failed, 3 passed**, demonstrating the independent Cohere loss.
- Extending the repeated-header test to already Cohere-shaped errors exposes a separate loss from converting headers to a dict: **1 failed, 1 passed** before correcting the pass-through branch.
- After the fix: **261 passed** across exception-handling tests and Cohere protocol, routes, conversion and streaming tests.
- A local Uvicorn TCP smoke check passes **10 HTTP cases**, including FastAPI's real `HTTPBearer` dependency with missing and valid credentials on ordinary and Cohere paths.

## Details

FastAPI supports [headers on `HTTPException`](https://fastapi.tiangolo.com/tutorial/handling-errors/#add-custom-headers), but the shared handler constructs its `JSONResponse` without them. Cohere's middleware independently replaces an existing error response with another `JSONResponse`, discarding the original headers again. Its pass-through branch also collapses repeated headers into a dict. Forward exception headers at the first boundary and preserve raw response headers at the second, excluding the two headers regenerated when replacing the body.

Minimal reproduction through an installed vLLM exception handler:

```python
raise HTTPException(429, detail="busy", headers={"Retry-After": "30"})
```

The status and error body are returned before the fix, but `Retry-After` is absent. The same happens to `WWW-Authenticate: Bearer` emitted by FastAPI's `HTTPBearer` dependency. After this change those headers reach the client through both the ordinary and Cohere response paths.

GitHub issue and open/closed PR searches on 2026-10-17 found no matching fix. [#61947](https://github.com/vllm-project/vllm/pull/61947) handles streaming generation errors, and [#58023](https://github.com/vllm-project/vllm/pull/58023) handles Anthropic validation envelopes; neither changes these header-loss paths. This patch is based on upstream `ce49c47cbb` and does not depend on either PR.
