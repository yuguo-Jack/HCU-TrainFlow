# [Docs] Use probabilistic DSpark sampling in Kimi-K3 GB300 recipes

[Upstream PR](https://github.com/vllm-project/vllm/pull/62610) · state: closed · merged: True

## Original PR description

## Overview

Use `draft_sample_method: probabilistic` in the Kimi-K3 GB300 TP8/TP16 low-latency guide script, matching the aggregated configurations in [InferenceX #4047](https://github.com/SemiAnalysisAI/InferenceX/pull/4047).

## Claims

- Corrects the documented draft sampling method for both aggregated presets while retaining `rejection_sample_method: block`.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <vllm-checkout>/recipes`: passed schema validation, strict assembly and JSON API generation.
- `pre-commit run --files recipes/models/moonshotai/Kimi-K3.yaml` and `git diff --check`: passed.
- Extracted the guide script, checked it with `bash -n`, and captured its arguments using a stub `vllm` executable: TP8 and TP16, head and follower, emit valid speculative JSON with probabilistic sampling and block rejection.
- Existing serving/evaluation evidence: [public InferenceX run 39140771499](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/39140771499). No new GPU evaluation was run for this documentation correction.

## Details

The guide script still selects greedy draft sampling, whereas the referenced aggregated configurations use probabilistic sampling. The sampling method is part of the speculative-decoding configuration, so the example should state the intended method explicitly. The change is limited to that script setting. Searches of open Kimi-K3 recipe/sampling PRs found no existing PR addressing this correction; merged PRs #62528 and #62563 cover disaggregated guidance and selector settings.
