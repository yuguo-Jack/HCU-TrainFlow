# [CLI] Add interactive chat recovery, commands, and line editing

[Upstream PR](https://github.com/vllm-project/vllm/pull/63512) · state: open · merged: False

## Original PR description



## Overview

When a multi-turn conversation exceeds the server's context limit, `vllm chat` currently exits on an uncaught `BadRequestError`. Add opt-in `--interactive` (`-i`) so users can keep the full error diagnostics, clear history, and continue without restarting the client.

## Claims

- Local `/help`, `/clear`, and `/exit` commands; `/clear` preserves the configured system prompt. `//` sends a literal leading slash.
- Request and stream API errors print their full tracebacks and return to the prompt. Completed conversation history is preserved; failed or interrupted turns are explicitly not saved. Unexpected programming errors still propagate.
- Optional `vllm[chat]` provides arrow-key history and Ctrl+A/B/E/F line editing through `prompt_toolkit`. Input history stays in memory, survives `/clear`, and is never written to disk. Piped input and missing optional dependencies fall back to plain input.
- Existing fail-fast behavior remains the default. `--interactive` cannot be combined with `--quick`; SDK retries and model generation parameters are unchanged.

## Details

### Original failure and recovery

The CLI sends accumulated conversation history on every request. A long assistant answer can therefore make the next short user message exceed the configured context limit. Only EOF was caught in the input loop; the API error escaped and terminated the client.

The following excerpts shorten the pasted prompt and traceback for readability. The actual client prints the full SDK exception and traceback in both modes.

Before, with a server configured for 512 tokens:

```text
$ vllm chat --url http://127.0.0.1:8000/v1
Using model: HuggingFaceTB/SmolLM2-135M-Instruct
Please enter a message for the chat model:
> ["hello " repeated 600 times]
Traceback (most recent call last):
  ...
openai.BadRequestError: Error code: 400 - ... This model's maximum context length is 512 tokens. However, your prompt contains at least 513 input tokens ...
$ # Client exited with status 1; /clear cannot be entered.
```

After, with opt-in interactive mode:

```text
$ vllm chat -i --url http://127.0.0.1:8000/v1
Using model: HuggingFaceTB/SmolLM2-135M-Instruct
Please enter a message for the chat model:
Commands: /help, /clear, /exit. Prefix a message with // to send /.
> ["hello " repeated 600 times]
Traceback (most recent call last):
  ...
openai.BadRequestError: Error code: 400 - ... This model's maximum context length is 512 tokens. However, your prompt contains at least 513 input tokens ...

Request failed or response was interrupted; this turn was not saved. Previous conversation is unchanged. Use /clear to start over or enter another message.
> /clear
Conversation cleared; system prompt preserved.
> /help
Commands: /help, /clear, /exit. Use // to send a leading /.
> /exit
$ # Clean exit with status 0.
```

The live base-commit reproduction exited 1 on HTTP 400 before it could process `/clear`. With `-i`, the changed code printed the same diagnostic, processed `/clear`, successfully served another request, and exited 0 with `/exit`. Separately, the new real-key regression test failed against pre-editor commit `1e5ae0c` and passed after the editor change.

To reproduce an overflow, start a server with a small context limit:

```bash
vllm serve HuggingFaceTB/SmolLM2-135M-Instruct \
  --host 127.0.0.1 --port 8000 --max-model-len 512 \
  --max-num-seqs 4 --gpu-memory-utilization 0.1 --enforce-eager
```

In a second terminal, run the following once without `-i` and once with it:

```bash
.venv/bin/python -c 'print("hello " * 600); print("/clear"); print("/help"); print("/exit")' \
  | vllm chat -i --url http://127.0.0.1:8000/v1
```

This scripted reproduction tests error recovery and local commands. To use line editing in a terminal, install `uv pip install 'vllm[chat]'` and run `vllm chat -i` without piping stdin/stdout.

### Scope and tradeoffs

The two existing chat loops are consolidated through the existing `chat` function. A new turn enters conversation history only after a complete successful response; partial output stays visible but is explicitly excluded from subsequent requests. Startup/model-discovery failures and unexpected programming exceptions remain fail-fast.

The line editor is lazily enabled only for `-i` with terminal stdin and stdout. Keyboard history is separate from the model's conversation history, so `/clear` can recover context space without losing input recall. The mode does not add retries, silently truncate history, compact/summarize conversations, or increase the server context limit.
