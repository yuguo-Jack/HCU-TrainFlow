# [Doc][Recipe] Fix for redhat fp8 xeon support issue

[Upstream PR](https://github.com/vllm-project/vllm/pull/62245) · state: closed · merged: True

## Original PR description

## Overview

Scope RedHatAI FP8/NVFP4 recipe variants to validated hardware using the existing `supported_hardware` field.

Port the changes from [[vLLM Recipes PR #1142](https://github.com/vllm-project/recipes/pull/1142)](https://github.com/vllm-project/recipes/pull/1142) into `vllm/recipes/models/`, following the variant-level hardware scoping introduced in [[PR #1029](https://github.com/vllm-project/recipes/pull/1029)](https://github.com/vllm-project/recipes/pull/1029).

## Claims

- Fix incorrect Xeon 6 eligibility for seven unsupported RedHatAI FP8 checkpoints.
- Add explicit `supported_hardware` declarations to 11 variants across five recipes.
- Preserve Xeon 6 eligibility for two RedHatAI FP8-block variants that passed validation.
- Restrict new hardware allowlists to platforms already marked `verified` in each parent recipe.
- Preserve existing BF16, INT8, INT4, and other variant configurations.
- No changes to vLLM runtime or inference kernels.

## Validation

**Baseline Xeon recipe validation:**

- 47 recipes tested.
- 40 passed.
- 7 failed during model startup, all using RedHatAI FP8 checkpoints.
- Two RedHatAI FP8-block checkpoints passed and remain Xeon-eligible.

**Static validation:**

- Verified the five target recipe files exist under `recipes/models/`.
- Confirmed all 11 new `supported_hardware` declarations are subsets of their parent recipes' verified hardware lists.
- No existing variant hardware declarations were modified.

**Follow-up validation required:**

- Run `git diff --check` and the repository's recipe validation checks.
- Rebuild the Recipes website using the updated vLLM source.
- Confirm that the seven failing FP8 variants are excluded from Xeon 6 discovery and that the two passing FP8-block variants remain available.

## Details

Recipes with `meta.hardware.xeon6: verified` could expose RedHatAI FP8/NVFP4 variants that were not validated on Xeon, because these variants lacked explicit hardware restrictions.

This change applies variant-level `supported_hardware` allowlists without modifying model-level hardware verification or inference behavior.

Affected recipes:

| Recipe | Variants updated |
|---|---:|
| Qwen2.5-VL-7B-Instruct | 1 |
| Qwen3-4B | 1 |
| Llama-3.1-8B-Instruct | 3 |
| Llama-3.3-70B-Instruct | 3 |
| Llama-4-Scout-17B-16E-Instruct | 3 |
| **Total** | **11** |

These changes are applied directly to `vllm/recipes/models/` because the Recipes website prioritizes recipe definitions from the vLLM repository over duplicate definitions in `vllm-project/recipes`.

This is a metadata-only fix. It does not add new hardware support or claim native FP8 execution on Xeon.
