# [Bugfix][Core] Reject non-positive output processing chunk sizes

[Upstream PR](https://github.com/vllm-project/vllm/pull/54409) · state: open · merged: False

## Original PR description

## Overview

Reject non-positive `VLLM_V1_OUTPUT_PROC_CHUNK_SIZE` values when the environment variable is read, before they break the V1 async output handler.

## Claims

- Reject `0` and negative values with a descriptive `ValueError`.
- Preserve the default (`128`) and positive overrides.

## Validation

Rebased onto `main` at `03091e28b8ba` and retained its new P2P resource-limit test.

```bash
.venv/bin/python -m pytest tests/test_envs.py -v
.venv/bin/pre-commit run --files vllm/envs.py tests/test_envs.py
```

- Latest-main regression: **2 failed, 1 passed**; the zero/negative cases are accepted before the fix.
- Rebased change: **61 passed**; all applicable pre-commit hooks passed.
- Upstream pre-commit has not run: the current-head `pre-run-check` stops at the contributor-eligibility prerequisite.
- Actual `AsyncLLM` generation with local Qwen3-0.6B on an RTX 5060 Ti: default and `1` both completed four tokens. On latest main, `0` fails in `range()` and `-1` leaves generation pending until the 20-second timeout. On this branch, both invalid values fail during engine initialization with the new validation error. These probes use the checked-out Python source and existing precompiled CUDA kernels.

Model evaluation: not applicable; valid configuration values retain their behavior. The generation checks above are functional smoke tests.

## Details

The output handler uses this value as the step in `range(0, num_outputs, chunk_size)`: zero raises, while a negative step silently skips pending outputs. A small getter validates the value at the existing environment-variable boundary without adding checks to the output-processing loop.

Open-PR searches for the environment-variable name, getter, and output-processing chunk validation found no other matching fix. The remaining search results concern different audio, model, parser, and KV-cache paths.

OpenAI Codex assisted with the code, validation, rebase, and PR text.
