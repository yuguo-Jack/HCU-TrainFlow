# [Model][Kernel] Nemotron-H Lightning NVFP4: batch-invariant serving aligned with training

[Upstream PR](https://github.com/vllm-project/vllm/pull/62017) · state: open · merged: False

## Original PR description

## Purpose

Under `VLLM_BATCH_INVARIANT=1`, make every Nemotron-H Lightning NVFP4 layer
(Mamba2, FP8 attention, NVFP4 W4A16 MoE, NVFP4/FP8 linears, norms, router)
independent of batch composition, chunking and the prefill/decode split, using
kernels a training actor can call directly. The actor's forward then reproduces
rollout log-probs bit for bit. This is the vLLM side of the Nemotron-H
train/inference consistency work described in the vLLM blog post
(`2026-10-14-train-inference-consistency`); the form follows the DeepSeek-V4
preview #54955.

With `VLLM_BATCH_INVARIANT` unset, the only behavior changes are the new
CuTe-DSL W4A16 experts path (W4A16 checkpoints on the `flashinfer_cutedsl`
MoE backend) and the ModelOpt W4A16 layerwise-reload fix. No new CUDA
extension: every BI path is an existing vLLM/FlashInfer kernel pinned to a
fixed configuration.

This is a squashed rebase onto main `fa75d3456d` of the code used for the
final Nemotron-H RL runs (developed on `6e517b15c1`, head `7a0244d0dc` in
aoshen02/vllm#85). 50 files, +5666/−182. The second commit is a review
follow-up (SM10x check at config time).

### Decisions made in the rebase

- Dropped our cherry-pick of #57635 (now on main).
- GateLinear: kept #59985's behavior; Nemotron-H keeps its BF16 gate weight
  under BI (`force_fp32_compute` only when BI is off), as the trainer does.
- Mamba2: exact replay writes no internal prefill checkpoints (#57329), so
  `MambaMixer2` requests no checkpoint blocks under BI; `update_block_table`
  handles both the checkpoint metadata and the exact-replay decode buffer.
- NemotronHMTP uses `is_unused_checkpoint_weight` (#60152).
- Fixed split-KV FA4: dropped the cascade check (#61126 removed cascade).
- `utils/flashinfer.py`: kept the pinned `bmm_fp8` backend; the `*_mm_out`
  helpers were removed on main (#60517).

## Known limitations

- BI is validated only for this model on SM10x (B200/GB200/B300), TP=1.
  BI=1 Nemotron-H raises at config time on other GPUs or TP>1.
- Under BI, Nemotron-H always selects `FlashAttnFixedSplitBackend`, which
  raises at construction unless vllm-flash-attn has fixed split-KV scheduling,
  head size is 128, the KV cache is FP8 E4M3 and there is no sliding window.
- Under BI, W4A16 NVFP4 linears are forced to `HummingNvFp4LinearKernel`
  without a fallback; validated on SM100 only.
- BI relies on torch.compile with Inductor: the trainer compiles the same
  pointwise glue (MoE combine, norms), so `enforce_eager` breaks bitwise
  equality.
