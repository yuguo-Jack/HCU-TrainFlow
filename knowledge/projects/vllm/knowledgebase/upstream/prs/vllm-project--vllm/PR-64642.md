# [Bugfix][ROCm][DSv4.1] Inject Engram at a PP stage that starts at an Engram layer

[Upstream PR](https://github.com/vllm-project/vllm/pull/64642) · state: open · merged: False

## Original PR description



## Overview

On ROCm, a DeepSeek-V4.1 pipeline stage whose first layer is an Engram layer (1 or 14) skips the Engram injection. With CUDA graphs this kills startup; this PR injects Engram at stage entry, as the NVIDIA path does since #62208. Stacked on #64051, whose test file it extends.

## Claims

- `VLLM_PP_LAYER_PARTITION=14,26` (PP2, stage 1 starts at Engram layer 14) starts and serves on MI355X; before this PR its stage 1 fails CUDA graph capture.
- No change for cuts whose stages do not start at an Engram layer.

## Validation

MI355X, `DeepSeek-V4.1-Flash-1017`, PP2 × TP1, `--moe-backend aiter`, Engram CPU offload, MXFP4 indexer, decoder SWA bounded replay on.

**Before** (base: #64051 + #63617, `VLLM_PP_LAYER_PARTITION=14,26`): stage 1 dies at startup:

```text
(Worker_PP1) ... cudagraph_utils.py ... capture_end()
AcceleratorError: CUDA error: capturing stream has unjoined work (hipErrorStreamCaptureUnjoined)
```

**After**: the server starts and serves. Needle-in-a-haystack 3/3 (~7.2K tokens, 3 depths) on two separate launches; GSM8K (first 400 test questions, 8-shot, greedy):

| Config | GSM8K |
| --- | ---: |
| TP2 (reference) | 0.9025 |
| PP2 14/26, this PR | 0.910 |
| PP2 8/32 (no Engram at stage entry) | 0.900 |

**Test**: `tests/models/test_deepseek_v41_amd_pp_replay.py::test_pp_partition_matches_default_cut[14,26]` compares greedy logprobs of the 14/26 cut against the default 20/20 cut with decode on CUDA graphs.

```bash
pytest -v -s tests/models/test_deepseek_v41_amd_pp_replay.py -k "partition and 14"
```

On the base (#64051), MI355X × 2:

```text
(Worker_PP1) ERROR ... torch.AcceleratorError: CUDA error: capturing stream has unjoined work
(Worker_PP1) ERROR ... Search for `hipErrorStreamCaptureUnjoined' in https://rocm.docs.amd.com/...
E   RuntimeError: Engine core initialization failed. See root cause above. Failed core proc(s): {}

```

With this PR (run on the branch that also carries the follow-up ROCm relay PR; a 14/26 cut is a KV-group boundary, so the relay is not used there):

```text
tests/models/test_deepseek_v41_amd_pp_replay.py::test_pp_stage_starting_at_replay_cut PASSED
tests/models/test_deepseek_v41_amd_pp_replay.py::test_pp_partition_matches_default_cut[14,26] PASSED
```

(`test_pp_stage_starting_at_replay_cut` is the existing test, reworked to share the runner setup.)

## Details

Root cause: a stage receives the hc stream with the previous stage's post already applied, so `DeepseekV4DecoderLayer.forward` takes its `residual is None` branch, which went straight to the stage's first pre. The Engram injection lives only in the branch that folds the previous post. The layer's Engram embeddings were still prepared on Engram's side stream, so under CUDA graph capture that work was never joined; without graphs the stage would silently drop layer 14's Engram contribution (not verified).

The fix applies Engram to the posted stream before the first pre, matching the non-entry path, which applies it between the previous post and this layer's pre.

CI: the test runs in the `:amd: (MI355) DeepSeek-V4.1 Mono Decode Numerics` step (mi355_4, optional), which already selects this file.
