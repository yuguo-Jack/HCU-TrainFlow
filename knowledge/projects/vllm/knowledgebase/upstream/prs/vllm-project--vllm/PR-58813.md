# [Bugfix][Model] Build the Qwen3.5 MTP head unquantized when the checkpoint ships it dense

[Upstream PR](https://github.com/vllm-project/vllm/pull/58813) · state: open · merged: False

## Original PR description

## Purpose

Fixes #58807.

A compressed-tensors pack-quantized checkpoint that ships its MTP head dense (in a separate bf16 shard, plain `mtp.*.weight` names) crashes at weight load: `Qwen3_5MultiTokenPredictor` builds its Linears from the target's quant config, so the loader expects packed names (`weight_packed`) the checkpoint never had, and the weight-map walk dies with "no module or parameter named 'fc.weight'".

The file already carries two carve-outs for this family: `modelopt_fp4` forces fc unquantized (#38650), and GPTQ's `dynamic` `-:mtp` declarations unquantize the layers. Neither covers compressed-tensors checkpoints that declare nothing.

This change detects the dense MTP head from the checkpoint itself: the safetensors index is read through the same repo-file channel config-time code already uses for `recipe.yaml` (local cache first, Hub download as fallback). If any `mtp.*` tensor carries a quantization artifact suffix, the head is properly quantized and nothing changes; if every `mtp.*` entry is a plain `.weight`, the whole predictor builds unquantized (fc and layers), mirroring the two existing paths. Single-file checkpoints have no index, so they keep current behavior. NVFP4 checkpoints are unaffected: their `mtp.layers.*` carry artifacts, so detection stays false and the existing fc-only carve-out still applies.

Not a duplicate: no open PR references #58807 or touches qwen3_5_mtp.py's quant decision (checked 2026-09-26).

## Test Plan

New `tests/v1/spec_decode/test_qwen3_5_mtp_dense_head.py`:

- The naming contract end to end: dense-only, bias-carrying dense, pack-quantized (`weight_packed`), channel-wise (`weight` + `weight_scale`), no-MTP, and unknown-layout (no index) inputs.
- A real local `model.safetensors.index.json` on disk, exercising the `try_get_local_file` path.
- The no-index fallback returning None without touching the network.
