# [CPU][Test] Skip AVX512-only CPU kernel tests on AVX2 hosts

[Upstream PR](https://github.com/vllm-project/vllm/pull/62511) · state: open · merged: False

## Original PR description

## Overview

Make two CPU kernel tests behave correctly on x86 hosts that only have AVX2 (no AVX512-BF16): one crashed the whole pytest process, the other failed instead of skipping. Test-only change, no runtime code touched.

## Claims

- `tests/kernels/test_cpu_fused_sampling.py` no longer aborts with `Illegal instruction` at collection time on AVX2-only CPUs.
- `tests/kernels/test_awq_int4_to_int8.py` skips the tests that need the AVX512-BF16-only INT4 ops instead of failing, while still running the tests that do not need them.
- No behavior change on hosts that have the ops (e.g. the AVX512 CI runners).

## Validation

Host: Intel i5-12400 (AVX2, no AVX512), WSL2 Ubuntu 24.04, CPU nightly wheel `0.32.1rc1.dev36+ge68efc685`, tests taken from this branch (based on `5caabdb`).

```sh
pytest tests/kernels/test_cpu_fused_sampling.py tests/kernels/test_awq_int4_to_int8.py -rs
```

| Test file | Before | After |
|---|---|---|
| `test_cpu_fused_sampling.py` | process killed: `Fatal Python error: Illegal instruction` (exit 132) | 35 passed |
| `test_awq_int4_to_int8.py` | 13 failed, 3 passed (`AttributeError: '_OpNamespace' '_C' object has no attribute 'convert_weight_packed_scale_zp'`) | 3 passed, 13 skipped |

`pre-commit run --files <both files>` passes.

(I exported `TRITON_DEFAULT_BACKEND=cpu` only because my WSL machine also exposes an NVIDIA driver, see #62484; it is unrelated to this change.)

## Details

**Root cause.** On x86, `CpuPlatform.import_kernels()` picks one of three builds based on the CPU: `_C` (AVX512 + BF16), `_C_AVX512`, or `_C_AVX2`. `test_cpu_fused_sampling.py` hard-coded `import vllm._C`, which loads the AVX512-BF16 build directly and executes unsupported instructions on an AVX2 CPU. `test_awq_int4_to_int8.py` calls `convert_weight_packed_scale_zp` / `int4_scaled_mm_cpu`, which are only registered under `#if defined(__AVX512BF16__) && defined(__AVX512F__)` in `csrc/cpu/torch_bindings.cpp`, but had no guard.

**Fix.**
- Sampling test: call `current_platform.import_kernels()` instead of importing `vllm._C` directly.
- AWQ test: add a `requires_int4_cpu_ops` `skipif` marker (same `hasattr(torch.ops._C, ...)` approach as `test_cpu_quant_fused_moe.py`) on the two classes that use the ops. I used a marker rather than a module-level skip so `TestCreateWeightsUnchanged`, which does not need the ops, keeps running.

`vllm._custom_ops` runs `current_platform.import_kernels()` on import and is imported at the top of the AWQ test, so the marker is evaluated after the kernels are loaded.

**Limitations.** I do not have AVX512 hardware, so I could not run the AWQ tests to confirm they still execute where the ops exist; that relies on the reasoning above and on the CPU CI job (`.buildkite/hardware_tests/cpu.yaml`). Other CPU tests in that job also misbehave on my host (e.g. 16 numeric-tolerance failures in `test_cpu_fused_moe.py`); I left them out because I am not sure they are not specific to my setup.

**AI assistance:** This PR was investigated and prepared with an AI assistant (Claude), which also ran the tests above on my machine. The diff is 11 added lines and 1 replaced line across two test files; I have reviewed it and can explain it.
