# [ROCm][DSv4.1] Shard the Engram gate so TP ranks gather only the value slice

[Upstream PR](https://github.com/vllm-project/vllm/pull/63367) · state: closed · merged: True

## Original PR description

## Overview

At TP > 1, each DeepSeek-V4.1 Engram layer all-gathers its whole `wkv` output (`[T, 6400]` per rank at TP4) before the fused post kernel. The gate only needs per-token sums over `dim`, so on gfx942 and gfx950 this PR shards `wkv` by `dim` slice. Each rank exchanges its value slice plus eight FP32 partial sums per token in one all-gather (`[T, 1296]`) and finishes the gate locally. CUDA, other ROCm GPUs, TP1 and sequence parallel keep the current path. Engram DP-sharded tables combine with it: DP sharding only changes the row lookup before `wkv`.

## Claims

* DeepSeek-V4.1-Flash, MI355X, TP4, 12-point sweep: mean TTFT −5.1% on average; long-context TTFT improves 5–8%.
* Per Engram layer at 16384 tokens, the exchange plus post kernel drops from 4.69 ms to 1.13 ms. Under CUDA graphs it is 1.1 µs slower at 1 token and faster from 2 tokens up.
* The math is unchanged apart from FP32 summation order across ranks. GSM8K and NIAH (32k, 64k) scores match `main` within run-to-run noise.
* One collective per Engram layer, as before, with 5× fewer bytes. No new streams or host synchronization.

## Details

**Why.** In a 16k-token prefill chunk at TP4 on MI355X, each Engram layer spends 3.6 ms on the `[T, 6400]` all-gather and 0.63 ms on its re-layout copy (60k/64, c=16). The same gather takes 1.25 ms on B200.

**How.**

1. `wkv` becomes a `MergedColumnParallelLinear` with output sizes `[dim] * (hc_mult + 1)` and `gather_output=False`, so each rank holds one `dim / tp` slice of every key and of the value. The merged loader shards the fused checkpoint weight, block-32 FP8 scales included.
2. `_engram_gate_partials_kernel` packs, per token, the value slice and `(Σ key², Σ hidden·q·k·key)` over the rank's slice for each hc copy. Hidden states are replicated, so the hidden norm needs no exchange.
3. One `tensor_model_parallel_all_gather` along tokens exchanges those rows.
4. `_engram_gate_finish_kernel` sums the partials over ranks, computes the gate as `_fused_engram_post_wkv_kernel` does, and reads the value rank-major, with no re-layout.

**Decode.** Both paths run three kernels per Engram layer. At 1 token the partials kernel (2.3 µs) sits in front of the latency-bound collective, which leaves the sharded path 1.1 µs behind; from 2 tokens the smaller exchange wins. A 1-token fallback would need a second exchange and post kernel, since the weight layout is fixed at load time, to save about 2 µs per decode step. So there is no token-count threshold.

**Gating.** The ROCm model builds `RocmEngram` (`amd/engram.py`), which overrides two hooks of `Engram`: `_create_wkv` and `_post_wkv`. It shards on gfx942 or gfx950 (`get_cdna_version() in (3, 4)`) at TP > 1 without sequence parallel, and otherwise falls back to `Engram`. CUDA keeps the gathered layout because `nvidia/specialized_decode/engram/prefetch.py` runs `wkv` itself and reads the gathered output. The ROCm mono decode layer (`--monokernel`) calls the `Engram` module unchanged, so it takes the sharded path too. With Engram DP-sharded tables, DP sharding exchanges lookup rows before `wkv`, so it composes with the sharded gate; `EngramBatch` (batched DP lookups) requires TP1 and is unaffected.

**Complexity.** 256 non-comment lines in the new `amd/engram.py` (two Triton kernels, `RocmEngram`), 24 in `common/engram.py` (the two hooks, which move 9 existing lines) and 169 test lines.

**Limitations.** Benchmarked at on gfx950 and gfx942 TP4 only. Not benchmarked with Engram DP-sharded tables at TP > 1.

### Existing PRs

None of the open PRs found by searching for "engram", "wkv" and "engram all-gather" changes the TP layout of the Engram `wkv` output.

* #63326 (draft) runs the Engram WKV chain ahead of the decoder layers on ROCm. It conflicts with this PR in `common/engram.py` and `tests/kernels/test_engram.py`, and its ahead path reads the `ColumnParallelLinear` column split. This PR lands first. On its layout, #63326 keeps pushing each rank's whole `wkv` shard (the gate's dot product needs the layer's hidden states, which are not ready ahead) and only remaps its column offsets.
* #56989 (draft) packs FP8 Engram rows through the smaller `[T, 6, 256]` exchange before `wkv`; it composes with this PR.
* #60938 (draft) fuses the Engram update into the delayed mHC input on CUDA Blackwell TP1.
* #62091 replaces the Engram DP lookup collectives and does not touch the TP path.
