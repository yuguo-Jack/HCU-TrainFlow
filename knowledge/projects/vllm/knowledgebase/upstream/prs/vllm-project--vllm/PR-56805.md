# Enable support for Terratorch models in v2 engine

[Upstream PR](https://github.com/vllm-project/vllm/pull/56805) · state: open · merged: False

## Original PR description


## Purpose

Terratorch models (Prithvi, TerraMind, etc.) were already supported in vLLM via the
existing `Terratorch` model class. This PR extends that support to the **V2 engine**
by fixing three issues that prevent Terratorch pooling models from loading or running
under the V2 model runner.

- **`terratorch.py`** — `SupportsMultiModal.get_language_model()` walks child modules
  looking for a `VllmModel` instance. `Terratorch` is a pure pooling model with no
  inner language model, so the default implementation always raises
  `NotImplementedError`. Adding `get_language_model(self): return self` satisfies the
  interface contract and removes the need for a workaround subclass in the terratorch
  package.

- **`pooling_runner.py`** — The V2 pooling runner validates the selected task against
  an explicit allowlist. Terratorch models register task type `"plugin"` to signal that
  output post-processing is fully owned by the model plugin. This type was absent from
  the allowlist, causing the V2 engine to reject the model at startup.

- **`rejection_sampler.py`** — `get_max_chunk_logits` divides by `vocab_size`. During
  V2 warm-up this is called for all models including pooling models. Terratorch has no
  text vocabulary (`vocab_size == 0`), triggering a `ZeroDivisionError` even though
  speculative decoding is never used for pooling models. An early-return guard when
  `vocab_size == 0` prevents the crash.

## Test Plan

Run Terratorch inference (Prithvi / TerraMind) with `VLLM_USE_V2_MODEL_RUNNER=1` and
verify the model loads, warms up, and produces correct embeddings end-to-end.

## Test Result

Terratorch models load and run correctly under the V2 engine. All three failure modes
(startup rejection, `NotImplementedError`, `ZeroDivisionError`) are resolved.
