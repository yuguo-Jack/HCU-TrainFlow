# [Attention] Use packed MLA sizes for hybrid block alignment

[Upstream PR](https://github.com/vllm-project/vllm/pull/55449) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`_align_hybrid_block_size` estimates the MLA page from `head_size`. Packed ds_mla caches store a different number of bytes per token (`fp8_ds_mla` 656, `nvfp4_ds_mla` 352), so the hybrid block size is computed for the wrong page.

This is the second of two complementary PRs, stacked on #60967; only the top commit is new. #60967 stops padding Mamba pages for block-outermost layouts and changes plain fp8/bf16 MLA configurations; this PR corrects the block size for packed ds_mla configurations. Without #60967, the corrected size makes the KDA layers need a fourth group with MTP off: 80 of 384 configurations would be worse instead of 42.

## Claims

- The hybrid alignment reads the packed width from `get_mla_state_content_bytes`, the lookup `MLAAttention.get_kv_cache_spec` already used inline.
- With #60967, GLM-5.3-Flash `fp8_ds_mla` at 8k–128k: median +10.7% max concurrency vs main, worse in 42 of 384 configurations (down to −8.3%).

## Validation

GLM-5.3-Flash (real `config.json`), same CPU allocation harness as #60967, 384 reachable `fp8_ds_mla` configurations. #60967 leaves all of them identical to main, so these numbers hold against both: 340 better, 2 equal, 42 worse (−8.3% to +26.1%). The worse ones, TP8 with MTP at ≥ 32k and SM90 TP4 at 128k, keep their group count; the smaller block rounds up to a worse multiple of the packed block-stride alignment.
