# [Attention] Use packed MLA sizes for hybrid block alignment

[Upstream PR](https://github.com/vllm-project/vllm/pull/55449) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`_align_hybrid_block_size` estimates the MLA page from `head_size`. Packed ds_mla caches store a different number of bytes per token (`fp8_ds_mla` 656 or 528, set by the backend impl), so the hybrid block size is computed for the wrong page.

This is the second of two complementary PRs, stacked on #60967; only the top commit is new. #60967 stops padding Mamba pages for block-outermost layouts and changes plain fp8/bf16 MLA configurations; this PR corrects the block size for packed ds_mla configurations.

## Claims

- The hybrid alignment reads the packed width from an MLA layer's `get_kv_cache_spec`, so it sizes the block for the page the layer allocates. A platform that registers no layers (vllm-metal) keeps the `head_size` estimate.
- With #60967, GLM-5.3-Flash `fp8_ds_mla` at 8k–128k vs main: SM90 median +10.5% max concurrency, worse in 24 of 192 configurations (down to −8.3%); SM120 up to +6.2%, worse in 6 of 192 (down to −0.7%).

## Validation

GLM-5.3-Flash (real `config.json`), same CPU allocation harness as #60967, 384 reachable `fp8_ds_mla` configurations. #60967 leaves all of them identical to main, so these numbers hold against both: 232 better, 122 equal, 30 worse (−8.3% to +26.1%). The worse ones keep their group count: on SM90 (TP4 with MTP off or 1 and TP8 with MTP at 128k, TP8 with MTP 1 or 3 at 32k) the smaller block rounds up to a worse multiple of the packed block-stride alignment; on SM120 (TP1 with MTP 3 or 5 at 128k) a request needs one more block.

## Details

- Among hybrid models, only GLM-5.3-Flash can select a ds_mla cache, and only `fp8_ds_mla`.
- Without #60967, the corrected block size makes GLM-5.3-Flash's KDA layers need a fourth group with MTP off: 102 of 384 configurations would be worse instead of 30.
- #60321 adds `mxfp4_mla` with an inline width in both places; with this PR the alignment takes it from `MLAAttention.get_kv_cache_spec`, so its alignment hunk is not needed; its `test_hybrid_block_size_matches_the_layer_page` then needs an MLA layer in the forward context.
