# [Perf][Qwen4Exp] Share the QSA top-k buffer across layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/65619) · state: closed · merged: True

## Original PR description



## Overview

Qwen4Exp (Qwen3.8-Flash-Next) allocated one QSA top-k selection buffer per QSA layer (`max_num_batched_tokens x (indexer_budget + compress_ratio)` int32 each). This PR allocates one buffer on `Qwen4ExpModel` and passes it to every QSA layer, as DeepSeek V3.2/V4, GLM-5.3-Flash and MiniMax-M3 already do. The MTP drafter now reuses the target buffer through the existing proposer sharing (`load_eagle_model` / `llm_base_proposer`).

## Claims

- Removes 12 of the 13 per-layer buffers on Qwen3.8-Flash-Next (12 QSA layers + 1 MTP layer). With the default `max_num_batched_tokens=16384` each buffer is 128 MiB, so about 1.5 GiB/GPU moves to the KV cache (measured +1.52 GiB). The saving scales with `max_num_batched_tokens`, so large-chunk prefill deployments gain more.
- No accuracy or MTP acceptance change.

## Validation

Qwen3.8-Flash-Next-FP8 on 1x GB200 node, `-tp 4 -ep --enable-prefix-caching --speculative-config '{"method": "mtp", "num_speculative_tokens": 3}'`, default `max_num_batched_tokens` (16384). Baseline is `main` at 5225a1f17f; same node type, same command.

| GPU KV cache size | 9,044,352 tokens | 9,151,208 tokens (+1.2%) |

## Details

- Sharing is safe because each QSA layer writes its selection and the sparse attention reads it within the same layer call, and Qwen4Exp QSA already rejects DBO/microbatching, so layers never interleave.
- MTP: the drafter allocates its own buffer at construction (like the other sparse MTP models) and the proposer replaces it with the target's. The target does not run between draft steps, and the drafter runs one layer per step, so `index_share_for_mtp_iteration` (step-0 rows reused by later steps) keeps working.
- Only the NVIDIA implementation is changed. The ROCm implementation (`vllm/models/qwen4_exp/amd/`) has the same per-layer buffer; I'll follow up there once I can validate on ROCm.
- Not a duplicate: no open PR shares this buffer. #59279/#61242/#61728 (QSA DCP) only touch the comment next to it.

When the IPC weight-cache loader is used, `IpcModelLoader._build_model` constructs the model inside `torch.device("meta")`, and `_materialize_remaining_meta_tensors` only visits registered parameters and buffers. This allocation and the per-attention references are now plain attributes (the previous allocation used `register_buffer`), so the shared tensor remains on `meta` and the first real QSA indexer call receives no CUDA storage. Allocate it on the runtime device explicitly or register/materialize the shared tensor.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Compact the shared MTP buffer only once**

When a checkpoint has `mtp_num_hidden_layers > 1` and `index_share_for_mtp_iteration` is enabled, this gives every MTP attention the same tensor, but `compact_topk_indices()` still loops over all attentions and gathers that tensor once per layer. The first copy overwrites `[0:num_rows]`; a later `index_select(row_indices)` can therefore read already-compacted rows (for example whenever a request's selected last-token row is in that prefix), corrupting the indices reused by draft steps 1+. Compact the shared tensor once or deduplicate buffers by identity.
