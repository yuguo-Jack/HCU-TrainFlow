# [Bugfix] Initialize valid ModelOpt NVFP4 MoE dummy scales

[Upstream PR](https://github.com/vllm-project/vllm/pull/63698) · state: closed · merged: True

## Original PR description



## Overview

Initialize ModelOpt NVFP4 MoE dummy quantization scales to valid positive values. Random initialization could produce nonpositive block/input scales and inconsistent gate/up global scales when benchmarking with `--load-format dummy`.

## Claims

- Dummy NVFP4 MoE weights use positive scales and matching gate/up global scales through the existing `dummy_weight_value` loader contract.
- A regression test constructs a small Qwen3 MoE through `LLM`, confirms the FlashInfer TRTLLM backend and valid scales, and generates two tokens with finite returned log probabilities.
- The ModelOpt documentation explains dummy benchmarking and the FlashInfer MegaMoE backend flag.

## Validation

One GB200 GPU, BF16 activations, NVFP4 dummy experts, FlashInfer TRTLLM, eager execution:

| Check | Without fix | With fix |
| --- | --- | --- |
| `test_modelopt_nvfp4_dummy_scales` | Failed: `AssertionError: w13_weight_scale` at `assert (values > 0).all()` | 1 passed, 22 deselected; two generated tokens and finite returned log probabilities |

Both passed, including Ruff, mypy, Markdown lint, and test tethering. A fresh-agent local-checkout documentation search found and quoted the dummy benchmarking section.

A separate real-LLM smoke run on this PR checkout also passed with two GB200 GPUs, TP2/EP2, the same tiny Qwen3 MoE configuration, and `moe_backend="flashinfer_moe_ep_cutedsl"`: two generated tokens with finite log probabilities. This uses the native dummy loader, without a benchmark wrapper. No real-checkpoint quality evaluation was run: this change only supplies values consumed by dummy weight initialization, and dummy outputs are unsuitable for quality evaluation.

## Details

The generic dummy initializer samples floating-point values around zero. NVFP4 MoE quantization scales require positive values, and the fused gate/up projections share a global scale. The change assigns block scales `1.0`, global weight scales `1e-3`, and input scales `1e-2` using parameter metadata already supported by the loader. It adds no inference-time work; normal checkpoint loading continues to use checkpoint values.

Duplicate-work searches on 2026-10-26 for `ModelOpt dummy`, `NVFP4 scales`, `MegaMoE dummy`, and `"dummy_weight_value"` found no open PR implementing this dummy initialization fix. Related #55073 reconciles differing scales in real checkpoints, #45320 rejects missing checkpoint scales, and #55997 refactors ModelOpt MoE methods; they address different behavior. There is no associated issue.
