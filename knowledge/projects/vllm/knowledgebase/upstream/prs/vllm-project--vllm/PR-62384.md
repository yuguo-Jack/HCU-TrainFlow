# [Feature][PCP] Support decoder-side SWA bounded replay with APC for DeepSeek-V4.1-Flash

[Upstream PR](https://github.com/vllm-project/vllm/pull/62384) · state: open · merged: False

## Original PR description

## Overview

Extend #62183 to support DeepSeek-V4.1-Flash decoder-side SWA bounded replay with PCP and APC, including prefix-hit continuation.

## Claims

- Retain each request's global trailing window on its original PCP owners while preserving cached compressed KV and indexer keys.
- Keep prompt-logprobs rows and existing non-PCP behavior; padded peers participate in the same collectives and only real outputs are scattered back.

## Validation

- Baseline: encoder replay only
- Candidate: This decoder replay enabled.
- Both services use the following launch command; node placement and the runtime overlay differ by arm:

```bash
vllm serve /models/DeepSeek-V4.1-Flash \
  --host 0.0.0.0 --port 18001 \
  --served-model-name deepseek-v4.1-flash \
  --language-model-only \
  --tokenizer-mode deepseek_v41 \
  --attention-backend FLASHMLA_SPARSE_DSV41 \
  --kv-cache-dtype fp8_ds_mla \
  --block-size 64 \
  --tensor-parallel-size 2 \
  --pipeline-parallel-size 1 \
  --decode-context-parallel-size 1 \
  --prefill-context-parallel-size 4 \
  --enable-expert-parallel \
  --all2all-backend allgather_reducescatter \
  --engram-config '{"cpu_offload":true}' \
  --moe-backend humming \
  --max-model-len auto \
  --max-num-batched-tokens 4096 \
  --max-num-seqs 64 \
  --gpu-memory-utilization 0.9 \
  --enable-prefix-caching \
  --swa-bounded-replay \
  --enforce-eager \
  --no-async-scheduling
```

- Both use node-local benchmark clients.
- Direct token-ID prompts: 8,192 input tokens, one output token, request rate infinity, no warmup, and `N=10*C`.
- C1/N10 seed `210101`, C8/N80 seed `210108`, and C32/N320 seed `210132`.
- Both arms receive the same unique prompts. Every accepted run has zero prefix-cache hit tokens.

| Case | Baseline Input TPS | Candidate Input TPS | Candidate delta | Baseline Mean TTFT | Candidate Mean TTFT | Candidate delta |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| C1 / N10 | 13,742.67 | 21,993.70 | +60.04% | 595.96 ms | 372.30 ms | -37.53% |
| C8 / N80 | 14,009.87 | 22,681.53 | +61.90% | 4,472.82 ms | 2,762.46 ms | -38.24% |
| C32 / N320 | 14,021.81 | 22,559.13 | +60.89% | 17,785.26 ms | 11,052.03 ms | -37.86% |

Decoder-side replay consistently improves uncached 8K prefill throughput by about 60% across C1-C32.

## Details

Reuse the existing replay batch, gather kernel and attention builders. The PCP-local batch retains its global scheduled view to derive tail boundaries and a common padding bound without CPU collectives. Select local slots before compaction, gather them in rank-major order, and align MoE routing IDs with the compact rows. Batches that would not shrink after padding keep full execution.

Unlike #61554's APC-disabled cold-prefill path, this builds on #62183 for APC prefix hits and derives replay bounds from existing global PCP metadata. It retains the existing PCP restrictions and eager execution requirement, with no scheduler, generic model-runner or configuration changes. The branch is rebased on #62183 now in main. AI assistance was used for implementation and static checks.
