# [Core][Attention] Resolve per-layer KV dtype in attention runtime

## Original PR description

## Overview

Resolve per-layer KV-cache encoding in the attention runtime, keeping allocation
specs focused on physical storage. First prerequisite for #56156 and #56116.

## Claims

- Add a default-`None` `QuantizationConfig.get_kv_cache_dtype(prefix)` hook.
- Let FlashInfer resolve the encoding from loaded attention layers when the
  global dtype is `auto`; explicit global settings retain precedence.
- Separate incompatible runtime formats in attention-group and metadata-reuse
  keys in both GPU runners, without changing allocation-spec equality.
- Preserve the existing physical quantization mode when merging sliding-window
  MLA specs. No new logical-dtype merge assertion is introduced.

## Validation

- Scoped repository pre-commit checks pass, including Ruff, formatting, test
  tethering, and repository mypy (Python 3.11):
  `pre-commit run --hook-stage manual --files <incremental changed files>`.
- 26 test-body cases and 36 resolver combinations pass with CPU source
  isolation. Four fault-injection controls are rejected by the retained tests.
- Source-isolated checks are not full-vLLM pytest. Fresh GPU/CUDA-graph and
  serving validation on this head remain pending; no accuracy/performance claim.

## Details

Addresses [the allocation-spec review](https://github.com/vllm-project/vllm/pull/56155#pullrequestreview-5475374302)
and [merge-assertion question](https://github.com/vllm-project/vllm/pull/56155#discussion_r4159751019).
Logical encoding stays on attention layers, not `AttentionSpec`; format lookup
is initialization work, not a per-token lookup or new GPU synchronization.
Both runners need format-specific metadata plans, including the legacy runner
used by existing deployments. The hook defaults to `None`, so this PR does not
enable ModelOpt mixed KV. #56156 handles allocation and #56116 activates recipes.
