# [Bugfix] Skip more weight formats in the tokenizer/processor snapshot

[Upstream PR](https://github.com/vllm-project/vllm/pull/63922) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fixes #63925.

Since #60825, loading a tokenizer or processor first downloads every Hub file not matched by `_WEIGHT_FILE_PATTERNS`. That list misses several weight formats that classic repos still ship, so vLLM downloads unused weights before loading the model: about 1.57 GB extra for `openai-community/gpt2` and 534 MB for `google-bert/bert-base-uncased`. This adds those formats to the list.

## Claims

- The tokenizer/processor snapshot no longer downloads rust-bert (`*.ot`), TFLite, Core ML (`*.mlmodel`, `*.mlpackage/*`), NeMo, NumPy (`*.npy`, `*.npz`) or PaddlePaddle (`*.pdparams`) files.
- Tokenizer, processor and config files are still downloaded.

## Validation

New parametrized tests in `tests/transformers_utils/test_repo_utils.py` apply `_WEIGHT_FILE_PATTERNS` with `huggingface_hub.utils.filter_repo_objects` (the filter `snapshot_download` uses) to real file names from `openai-community/gpt2` and `google-bert/bert-base-uncased`. No network access.

Before (patterns reverted):

```text
$ pytest tests/transformers_utils/test_repo_utils.py
FAILED ...::test_non_weight_snapshot_skips_weight_files[rust_model.ot]
FAILED ...::test_non_weight_snapshot_skips_weight_files[64.tflite]
FAILED ...::test_non_weight_snapshot_skips_weight_files[64-fp16.tflite]
FAILED ...::test_non_weight_snapshot_skips_weight_files[coreml/fill-mask/float32_model.mlpackage/Data/com.apple.CoreML/model.mlmodel]
FAILED ...::test_non_weight_snapshot_skips_weight_files[coreml/fill-mask/float32_model.mlpackage/Manifest.json]
5 failed, 22 passed
```

After:

```text
$ pytest tests/transformers_utils/test_repo_utils.py
27 passed
```

Against the live Hub file lists (captures the `ignore_patterns` passed to `snapshot_download` and filters `HfApi().model_info(repo).siblings`), files over 50 MB that the snapshot would fetch:

| Repo | Before | After |
|---|---|---|
| `openai-community/gpt2` | `rust_model.ot`, `64.tflite`, `64-fp16.tflite`, `64-8bits.tflite` (~1.57 GB) | none |
| `google-bert/bert-base-uncased` | `rust_model.ot` (534 MB) | none |

`tests/tokenizers_/test_registry.py` and `tests/transformers_utils/test_processor.py` pass except `test_hub_processor_loads_from_local_snapshot` and `test_processor_reuses_tokenizer_snapshot`, which fail identically on main in my environment (macOS, no torchvision). `pre-commit run` passes on the changed files.

## Details

The `typos` hook flags the `ot` extension, so `ot` is added to `[tool.typos.default.extend-words]` next to the other short words already there (`fo`, `nd`, `ba`).

This keeps the deny-list approach from #60825. An allow-list of tokenizer/processor files would close the gap for future formats too, but it risks missing files that custom processors or `trust_remote_code` tokenizers need; happy to switch if preferred.

Not a duplicate: searching issues and PRs for `_WEIGHT_FILE_PATTERNS`, `get_non_weight_snapshot_path`, `rust_model.ot` and "tokenizer snapshot weights" finds only #60825 and #61272; #63482 touches the same module but not the patterns.
