# [Rust Frontend] End reasoning at a tool-call opener like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/65397) · state: open · merged: False

## Original PR description

## Overview

On the Rust frontend, end reasoning at a tool-call opener emitted before `</think>`, as Python's parser engines do for Qwen3, GLM-4.5/4.7/5, MiniMax M2, DeepSeek V4 and Kimi K2. Today the call stays in `reasoning_content` and the tool call is lost. One commit per change: the generic implicit end with five families, then Kimi K2's tool-call section.

## Claims

- For Qwen3, GLM-4.5, GLM-4.7/5, MiniMax M2 and DeepSeek V4, a tool-call opener (`<tool_call>`, `<minimax:tool_call>`, `<｜DSML｜tool_calls>`) produced by its dedicated token inside reasoning ends reasoning; the opener and what follows become content and reach the tool parser. Streaming and non-streaming agree.
- For Kimi K2, `<|tool_calls_section_begin|>` does the same.
- The opener spelled with ordinary tokens stays reasoning, as `</think>` does.
- The output grammar is unchanged: it still requires `</think>` before a tool call, a subset of what the parser now accepts.

```
reasoning parser glm47 + tool parser glm47, prompt opens reasoning, model output:
  reason<tool_call>get_weather<arg_key>location</arg_key><arg_value>Paris</arg_value></tool_call>
before: reasoning = "reason<tool_call>get_weather…</tool_call>", tool_calls = []
after:  reasoning = "reason", tool_calls = [get_weather({"location":"Paris"})], no content
```

## Details

**Python.** The parser engines of Qwen3, GLM-4.5/4.7/5, MiniMax M2 and DeepSeek V4 have a `(REASONING, TOOL_START)` transition: a tool-call opener before `</think>` ends reasoning and starts the tool call (vllm-project/vllm#45877, vllm-project/vllm#56635, vllm-project/vllm#59627). The Kimi K2 engine ends reasoning at `<|tool_calls_section_begin|>` (vllm-project/vllm#46610). The reasoning-only adapters keep the transition with tool parsing skipped, so the opener becomes content. A real generation behind it: vllm-project/vllm#59608 (GLM-5 calling a tool without closing `</think>`).

**Rust before this change.** These families' reasoning parsers ended only at `</think>`; GLM-4.7, DeepSeek V4 and MiniMax M2 were aliases of the DeepSeek V3 and Qwen3 parsers, and Kimi K2 aliased DeepSeek V3 with a TODO for exactly this. `CombinedParser` forwards only content to the tool parser, so a call opened inside reasoning landed in `reasoning_content`.

**Change.**

- `DelimitedReasoningParserBuilder::with_implicit_ends(markers)`: inside reasoning, any of the markers ends reasoning and stays in the buffer as content, with no end framing. The match is `utils::peek_markers`, a probe over a marker list now shared with `scan_markers`.
- Like the delimiters, an opener counts only where its dedicated token produced it: `Marker::special_in(tokenizer, text)` resolves the token, and a tokenizer without it gets no implicit end.
- Qwen3 and GLM-4.5 add `<tool_call>`. GLM-4.7/5, MiniMax M2, DeepSeek V4 and Kimi K2 become their own thin wrappers (`glm47.rs`, `minimax_m2.rs`, `deepseek_v4.rs`, `kimi_k2.rs`) with the same delimiters and framing as the parsers they aliased, plus their opener. Each opener is a single added token in the shipped tokenizers, except DeepSeek V4's, which is `<` + the `｜DSML｜` token + `tool_calls>`; DeepSeek V4 takes it from `DeepSeekV4ToolParser::tool_calls_start`, which reuses the tool parser's DSML marker resolution (extracted from `DsmlMarkers::new` into `dsml_token`/`dsml_marker`, no behavior change).
- **Layering.** The consumer is the delimited reasoning state machine (`reasoning/delimited.rs`), which owns the reasoning/content split for every caller (`CombinedParser` and reasoning-only use). The opener set is model knowledge and lives in each family's wrapper; generic code names no model.

**Differences from Python.**

- GLM-4.5 is included because Python's `glm45` name is the GLM-4.7 engine adapter, and vllm-project/vllm#59608 ran with `--reasoning-parser glm45`.
- Python's lexer also matches the opener by text; Rust, as for `</think>`, matches only the dedicated token.
- Not ported: DeepSeek V4's misspelled opener variants (`<｜DSML｜toolcalls>`, `<｜DSML｜tool>`) and Python's silent drop of a stray `</think>` after an implicit end; both tolerate nonconforming output.
- Unchanged: Python strips trailing reasoning whitespace for GLM-4.7, MiniMax M2, DeepSeek V4 and Kimi K2; Rust keeps it, before `</think>` as before and now before an opener too. Kimi K2's initial state still comes from the rendered prompt, not Python's `thinking` kwarg.
- Python's `qwen3_config` gives the same `<tool_call>` implicit end to MiMo, Nemotron V3, Step-3.5, Seed-OSS and MiniCPM-V; their Rust reasoning parsers are not changed here.

Not a duplicate: no open PR adds an implicit reasoning end to the Rust reasoning parsers (searched open Rust frontend PRs for reasoning, Kimi and implicit end). vllm-project/vllm#52574 adds a separate `minimax_m2_append_think` parser and does not change `minimax_m2`.
