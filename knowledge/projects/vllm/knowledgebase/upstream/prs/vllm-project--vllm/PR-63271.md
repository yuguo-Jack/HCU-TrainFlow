# [Core] Add keep_tags to the sleep-mode allocators

[Upstream PR](https://github.com/vllm-project/vllm/pull/63271) · state: closed · merged: False

## Original PR description



## Overview

Adds a `keep_tags` argument to the sleep-mode allocators, so allocations with those tags (e.g. `kv_cache`) stay mapped on the device while the allocator sleeps. Fixes #63058.

## Claims

- `CuMemAllocator.sleep(offload_tags=..., keep_tags=...)` skips allocations tagged in `keep_tags`. They keep their memory and contents and are never marked asleep, so `wake_up` (full or selective) doesn't touch them.
- If a tag is in both `offload_tags` and `keep_tags`, `sleep` raises `ValueError` before it unmaps anything.
- `XpuMemAllocator.sleep` and the `MemAllocator` protocol take the same argument, so a sleep-mode backend can pass `keep_tags` through `get_mem_allocator_instance()` on either platform.
- Callers that don't pass `keep_tags` see no change. `CuMemBackend` and `Worker.sleep` are untouched.

## Validation

I added two tests to `tests/basic_correctness/memory/cumem/test_cumem.py`:

- `test_sleep_keep_tags` allocates under `weights` and `kv_cache` and calls `sleep(offload_tags="weights", keep_tags="kv_cache")`. Afterwards only the `kv_cache` bytes are still mapped and the KV tensor reads back unchanged. After `wake_up(tags=["weights"])` the weights are back and the KV tensor is still unchanged.
- `test_sleep_rejects_tag_both_offloaded_and_kept` checks that a tag in both lists raises `ValueError` and leaves every allocation mapped with its contents.

Before the change (base `19c0e170d2`):

```text
$ python -m pytest tests/basic_correctness/memory/cumem/test_cumem.py -k "keep_tags or both_offloaded"
E   TypeError: CuMemAllocator.sleep() got an unexpected keyword argument 'keep_tags'
E   TypeError: CuMemAllocator.sleep() got an unexpected keyword argument 'keep_tags'
2 failed, 21 deselected
```

With the change, on an RTX 4060 (8 GB, WSL2):

```text
$ python -m pytest tests/basic_correctness/memory/cumem/test_cumem.py -k "keep_tags or both_offloaded"
2 passed, 21 deselected

$ python -m pytest tests/basic_correctness/memory/cumem/test_cumem.py tests/v1/worker/test_sleep_mode_backend.py
```

`ruff check` and `ruff format` are clean. `tools/pre_commit/mypy.py 3.11` on `vllm/device_allocator/` reports one error, at `cumem.py:70` (`lib_name` passed to `CUDAPluggableAllocator`). The base commit has the same error, so this change adds none.

The tests run in the existing "Basic Correctness CuMem" Buildkite step (`pytest -v -s basic_correctness/memory/cumem`), whose dependencies already cover `vllm/` and `tests/basic_correctness/`. The XPU job runs the same directory. I don't have an Intel GPU, so CI is the only coverage for the `XpuMemAllocator` change.

## Details

- Motivation, from the issue: when a pause with `mode="keep"` is followed by a sleep, the frozen requests lose their KV cache along with everything else and have to recompute after `wake_up`. RL loops that sleep between rounds also discard and re-map the KV pool every round. Plugin backends currently work around this by walking `pointer_to_data` themselves. With `keep_tags` they can use the allocator's API instead.
- If a kept tag is already asleep (for example after `discard`), it stays asleep, because `sleep` can't re-map it. That case logs the existing "cannot change the policy of already-asleep allocations" warning, as a conflicting offload request already does.
- `keep_tags` goes on the `MemAllocator` protocol as well as on the two allocators. Backends only see the protocol, and without it `allocator.sleep(keep_tags=...)` would fail type-checking. Each allocator normalizes `keep_tags` the same way it already normalizes `offload_tags`; I didn't add a shared helper.
- When something is kept, `sleep` logs one extra line with the kept GiB and tags. The existing summary line is unchanged.
- This PR doesn't wire `keep_tags` into `CuMemBackend.suspend` or add a sleep level. The issue leaves that to backends. It's an internal allocator API, so there's no docs change.
- Duplicate check: no open or merged PR adds `keep_tags`, and `main` has no such argument. Open PRs #59228 and #60003 also edit `CuMemAllocator`, but for freeing while asleep and the CPU backup on wake. They don't overlap with this change, though one side may need a small rebase. The issue author asked me to take this on in the issue thread.
- AI assistance was used to write this change. I reviewed every line and ran the tests above myself.
