# [Bugfix][Core] Keep the EAGLE-reachable SWA tail at a shared-prefix junction

[Upstream PR](https://github.com/vllm-project/vllm/pull/62206) · state: closed · merged: True

## Original PR description



## Overview

This PR fixes cross-request prefix reuse for sliding-window groups under EAGLE/MTP with sparse prefix-cache retention. The shared-prefix junction pin from #47782 kept a sliding-window tail one block too high, so requests that share only a prefix got no prefix-cache hit at all. The fix also pins the tail one block lower, which is where an EAGLE sibling's hit actually lands.

## Claims

- Under sparse retention, a sibling request that shares only a prefix now gets a prefix-cache hit when the drafter's groups are sliding-window and the full-attention groups are not EAGLE groups. On Step-5-Preview with MTP, the GSM8K 5-shot prefix goes from 0 hit tokens to a hit on every request after the first two.
- Nothing changes without EAGLE, or when every group is flagged as an EAGLE group. In those cases the junction already sits one block lower, because the full-attention group drops its block too.
- The cost is one extra cached block per sliding-window group for each request that registers a junction.

## Validation

**Unit test.** `test_swa_shared_prefix_reuse_under_zero_retention` gets a `use_eagle` case that flags only the SWA group, as https://github.com/vllm-project/vllm/pull/61455 does for drafters. It fails on main (0 instead of 48 hit tokens) and passes with the fix.

## Details

**Root cause.**
1. Request A runs alone.
2. Request B shares a prefix with A, but under sparse retention only A's full-attention blocks are still cached. `get_computed_blocks` reports the junction J as the full-attention hit length (B's shared prefix floored to a block), and B pins J.
3. The sliding-window mask keeps the `need`-block tail at J. Under EAGLE, that tail is shifted one block right, to include the block past J as the lookahead (#44082). This is right for a replay of the same prompt.
4. The block past J holds B's own tokens, so for request C it is not shared. C's SWA lookup must verify one block past its hit, so its best hit is J − block_size. That hit needs the window one block lower than the pinned tail, and the lowest block was never kept.
5. C gets no hit and pins the same J again, so no later request ever hits.

When every group takes the EAGLE drop (no group flagged), the full-attention hit is already one block lower, so J lands where the SWA hit can verify. The bug therefore shows only when a sliding-window group is an EAGLE group and the full-attention group that reports the junction is not. Step5 MTP already met this under the older "group holding the last registered layer" rule. https://github.com/vllm-project/vllm/pull/61455 makes per-group flags the general rule: drafters whose layers are sliding-window now flag only those groups.

**Fix.** Under EAGLE, `cache_blocks` registers both J and J − block_size as reachable boundaries. The masks overlap, so this keeps one extra block. Replay boundaries are unchanged, because they already account for the EAGLE drop (#54713, #61012). Mamba checkpointing reads `shared_prefix_boundary` directly and is unaffected.

**Not covered.** `OffloadingConnector` builds its own reachable boundaries from `shared_prefix_boundary` and is not changed here.
