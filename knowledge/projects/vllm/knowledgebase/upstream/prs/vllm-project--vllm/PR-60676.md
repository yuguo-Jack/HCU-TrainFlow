## Overview

Serve [`LiquidAI/d1-3B`](https://huggingface.co/LiquidAI/d1-3B) on `/v1/systemone` with answers that match the checkpoint's own `model.system_one()`, and add an `images` field to the endpoint.

**Stacked on #60696** (noul and score question types). The first commit here is that PR, rebased onto `main`; review only the second commit. I will rebase again once #60696 lands.

```bash
vllm serve LiquidAI/d1-3B
```

## Demo

d1-3B playing Snake through `/v1/systemone`, recorded in real time on one B300. Each move is one HTTP request with a single `choice` question (up / down / left / right), and the snake takes the model's top choice with no fallback logic.

![d1-3B playing Snake on vLLM](https://raw.githubusercontent.com/mgoin/vllm/pr-60676-assets/d1_snake.gif)

In this 15 second run it made 666 moves (44 a second, 23 ms median per request), ate 46 apples and died once. The state is a short text: where the apple is relative to the head, and what is in each of the four neighboring cells. Given raw coordinates or an ASCII grid instead, the model played poorly (14 and 4 apples in 400 moves, against 32). The recording used the default prefix caching; see Details for why turning it off is faster here.

## Claims

- d1-3B answers on `/v1/systemone` match the reference implementation shipped with the checkpoint, for text and image states and all three question types.
- `images` takes image URLs or data URLs. A text-only model returns 400.

## Details

- **Why a strategy.** d1 is a post-trained LFM2.5-VL-3B that expects a fixed prompt (`QUESTION:` / `Options:` / `Reply with the option code only.`) and pools label variants (`yes`/`Yes`/`YES`, `A`/` A`). `LiquidStrategy` subclasses `NextTokenStrategy` and overrides only the user turn and the label tokens.
- **Label groups.** A read now takes a group of tokens per label and scores the best one. The generic strategy uses groups of one, so its behavior is unchanged.
- **Score labels.** #60696 labels levels 1 to 9 for the generic prompt. d1 was trained on 0-indexed digits, so the Liquid strategy writes and reads those instead, and caps a score at 10 levels.
- **Selected by architecture.** d1's `config.json` is the same as the base model's, so every `Lfm2VlForConditionalGeneration` gets this prompt. Liquid's runner does the same.
- **Usage.** `input_tokens` sums the prompt of every question, so a multi-question request reports more than the reference, which counts the state once.
- **Limitations.** A `choice` is still capped at 26 options (the reference switches to two-digit codes beyond that). Images above one megapixel are not downscaled first as the reference does; only a 640x480 image was tested.
- **Latency.** On one B300 a single-question request takes about 14 ms: roughly 9 ms in the engine step, 3 ms between the API server and the engine, and 1 ms each for HTTP and for rendering the prompt. With prefix caching on (the default) and a state that changes every request, the median rises to 22 ms and is bimodal (14 / 22 / 31 ms); `--no-enable-prefix-caching` brings it back to a flat 14 ms. I did not trace the cause in the scheduler.
- **Overlap.** Not a duplicate: no other open PR serves d1. The question types come from #60696. #60465 builds on the same module.

### 1. A failed or overlapping decision breaks the next request with the same image (chat included)

`read()` renders all questions before sending any. The first render marks the image as sent in the mm sender cache (P0). If a later question fails (e.g. an 11-level score, L285), nothing reaches the engine, and the next request with those image bytes sends only the hash and hits a P1 cache miss. A request that arrives while a long decision is still rendering fails the same way. Fix: render with `skip_mm_cache=True`, as the render-only endpoints do: https://github.com/simon-veitner-redhat/vllm/commit/d11e50c847decf90ae71ca0d25bc6dc494d0ded2

<details><summary>Repro (failed request), <code>vllm serve LiquidAI/d1-3B --port 18676</code>, same on any Lfm2Vl model</summary>

```python
# Server: vllm serve LiquidAI/d1-3B --port 18676   (also any Lfm2Vl model, e.g. LFM2-VL-450M)
# A decision request that fails after rendering question 1 poisons the image cache;
# the next chat completion with the same image then fails with 500.
import base64, json, os, struct, urllib.request, zlib
URL, M = f"http://127.0.0.1:{os.environ.get('PORT', '18676')}", os.environ.get("MODEL", "LiquidAI/d1-3B")
raw = b"".join(b"\0" + os.urandom(3 * 32) for _ in range(32))  # fresh 32x32 noise PNG each run
ch = lambda t, d: struct.pack(">I", len(d)) + t + d + struct.pack(">I", zlib.crc32(t + d))
img = "data:image/png;base64," + base64.b64encode(b"\x89PNG\r\n\x1a\n" + ch(b"IHDR", struct.pack(">IIBBBBB", 32, 32, 8, 2, 0, 0, 0)) + ch(b"IDAT", zlib.compress(raw)) + ch(b"IEND", b"")).decode()
def post(path, body):
    try: r = urllib.request.urlopen(urllib.request.Request(URL + path, json.dumps(body).encode(), {"Content-Type": "application/json"})); return r.status, r.read()[:160]
    except urllib.error.HTTPError as e: return e.code, e.read()[:160]
if not os.environ.get("CONTROL"): print("decision:", post("/v1/systemone", {"model": M, "state": "x", "images": [img], "questions": {
    "a": {"type": "noul", "instructions": "Red?"}, "b": {"type": "score", "instructions": "Rate.", "criteria": list("0123456789X")}}}))
print("chat:    ", post("/v1/chat/completions", {"model": M, "max_tokens": 1, "messages": [{"role": "user", "content": [
    {"type": "image_url", "image_url": {"url": img}}, {"type": "text", "text": "Color?"}]}]}))
```

Expected: chat 200, as it is without the failed decision first (`CONTROL=1`).

### 2. Each question fetches every image again

Every render builds its own media connector, so N questions fetch, decode and hash each image N times, one after another, and a URL with changing content gives the questions different pictures. Fix: fetch once with the chat path's media rules and pass the decoded images to every question: https://github.com/simon-veitner-redhat/vllm/commit/8ca898731af7ca2d0c790bee2275155d55c5fde4

<details><summary>Repro, <code>vllm serve LiquidAI/d1-3B --port 18676</code>, same on any Lfm2Vl model</summary>

```python
# Server: vllm serve LiquidAI/d1-3B --port 18676   (also LFM2-VL-450M)
# One request, 2 identical questions, 1 image URL. The URL serves red then blue (a live snapshot).
# Each question fetches the image again, so the two identical questions see different pictures.
import io, json, os, threading, urllib.request
from http.server import BaseHTTPRequestHandler, HTTPServer
from PIL import Image
URL, M = f"http://127.0.0.1:{os.environ.get('PORT', '18676')}", os.environ.get("MODEL", "LiquidAI/d1-3B")
def png(c): b = io.BytesIO(); Image.new("RGB", (64, 64), c).save(b, "PNG"); return b.getvalue()
imgs, gets = [png((230, 20, 20)), png((20, 20, 230))], []
class H(BaseHTTPRequestHandler):
    def do_GET(self):
        body = imgs[len(gets) % 2]; gets.append(1)
        self.send_response(200); self.send_header("Content-Type", "image/png"); self.send_header("Content-Length", str(len(body))); self.end_headers(); self.wfile.write(body)
    def log_message(self, *a): pass
srv = HTTPServer(("127.0.0.1", 0), H); threading.Thread(target=srv.serve_forever, daemon=True).start()
q = {"type": "noul", "instructions": "Is the image red?"}
body = {"model": M, "state": None, "images": [f"http://127.0.0.1:{srv.server_port}/x.png"], "questions": {"q1": q, "q2": q}}
r = json.load(urllib.request.urlopen(urllib.request.Request(URL + "/v1/systemone", json.dumps(body).encode(), {"Content-Type": "application/json"})))
print("image GETs:", len(gets), "| P(red) q1 =", round(r["answers"]["q1"]["noul"], 3), "q2 =", round(r["answers"]["q2"]["noul"], 3))
```

### 3. Images above 1 MP give different answers from `system_one()`

d1's `runner.py` shrinks every picture to at most 1024×1024 px (bicubic) before the processor; here it goes in as sent, so the tile grid and the pixels differ. Same commit as 2 (`LiquidStrategy.max_image_pixels`).

<details><summary>Repro, <code>vllm serve LiquidAI/d1-3B --port 18676</code>, <code>img/cat03.jpg</code> = Wikimedia Commons Cat03.jpg</summary>

```python
# Server: vllm serve LiquidAI/d1-3B --port 18676
# The same photo sent as-is (1600x1598) and downscaled to 1 MP the way d1's runner.cap_pixels does.
# model.system_one() always sees the 1 MP version, so only the second row matches the reference.
import base64, io, json, math, os, sys, urllib.request
from PIL import Image
URL = f"http://127.0.0.1:{os.environ.get('PORT', '18676')}/v1/systemone"
im = Image.open(sys.argv[1] if len(sys.argv) > 1 else "img/cat03.jpg").convert("RGB")
s = math.sqrt(1024 * 1024 / (im.width * im.height))
for tag, pic in [("as sent ", im), ("1MP-capped", im.resize((int(im.width * s), int(im.height * s)), Image.Resampling.BICUBIC))]:
    b = io.BytesIO(); pic.save(b, "PNG")
    body = {"model": "LiquidAI/d1-3B", "state": None, "images": ["data:image/png;base64," + base64.b64encode(b.getvalue()).decode()],
            "questions": {"indoor": {"type": "noul", "instructions": "Is the photo taken indoors?"}}}
    r = json.load(urllib.request.urlopen(urllib.request.Request(URL, json.dumps(body).encode(), {"Content-Type": "application/json"})))
    print(tag, pic.size, "P(indoor) =", round(r["answers"]["indoor"]["noul"], 4), "input_tokens =", r["usage"]["input_tokens"])
```

Observed: as sent `P(indoor) = 0.1824`, 2578 tokens; capped `0.0953`, 1293 tokens.
Expected: `system_one()` on the same file gives `0.0953` with 1293 tokens. In fp32 a 3840×2880 photo flips a yes/no answer (0.454 vs 0.551).

### 4. A one-letter option name that is several tokens fails with a `max()` error

### 5. `confidence` does not match `system_one()`

The reference returns `probs[best]`; here it is `probs[top] * label_mass`, with `label_mass` summing every pooled variant. Picks and probabilities match; `confidence` is 0.004–0.020 lower on d1. Keeping one definition across models seems fine; the commit narrows the docs claim to picks and probabilities: https://github.com/simon-veitner-redhat/vllm/commit/37609180281ecb0079c9c9b833b1c0cc5bf169e3

<details><summary>Repro, <code>vllm serve LiquidAI/d1-3B --port 18676</code></summary>

### Run-to-run variance (fixed separately)

Under concurrent load a label's bf16 logit moves by one step, so near-ties flip: the Japanese case picks English in about half of loaded runs. Computing the lm_head in fp32 removes this at no measured cost (322 vs 324 req/s at 32 in flight), but `--hf-overrides '{"head_dtype": "float32"}'` is ignored for multimodal models today; I will send that as a separate [Bugfix] PR. Until then `--hf-overrides '{"text_config": {"head_dtype": "float32"}}'` works.

<details><summary>Repro, <code>vllm serve LiquidAI/d1-3B --port 18676</code></summary>

```python
# Server: vllm serve LiquidAI/d1-3B --port 18676   (bf16, default prefix caching)
# The PR's Japanese case asked alone, then 32 times mixed with 32 other requests, 32 in flight.
# Batch shape moves one label logit by one bf16 step: Japanese 0.3985 / English 0.3744 becomes
# a 0.3837 tie, and argmax picks English.
import collections, json, os, random, urllib.request
from concurrent.futures import ThreadPoolExecutor
URL = f"http://127.0.0.1:{os.environ.get('PORT', '18676')}/v1/systemone"
LANG = {"type": "choice", "instructions": "Which language is the message in?", "criteria": {"English": None, "Japanese": None, "Chinese": None}}
JA = {"model": "LiquidAI/d1-3B", "state": {"message": "注文した商品がまだ届きません。返金してください。"}, "questions": {"lang": LANG}}
def other(i):  # a different request with a random-length state
    return {"model": "LiquidAI/d1-3B", "state": "refund order crash " * random.Random(i).choice([5, 50, 300]), "questions": {"d": {"type": "noul", "instructions": "Angry?"}}}
def ask(body):
    r = json.load(urllib.request.urlopen(urllib.request.Request(URL, json.dumps(body).encode(), {"Content-Type": "application/json"})))
    a = r["answers"].get("lang")
    return a and (a["choice"], round(a["probabilities"]["Japanese"], 4), round(a["probabilities"]["English"], 4))
print("alone:", ask(JA))
jobs = [JA] * 32 + [other(i) for i in range(32)]
random.Random(0).shuffle(jobs)
with ThreadPoolExecutor(32) as ex:
    print("mixed:", collections.Counter(a for a in ex.map(ask, jobs) if a))
```

Observed: `alone: ('Japanese', 0.3985, 0.3744)`, `mixed: Counter({('Japanese', 0.3985, 0.3744): 17, ('English', 0.3837, 0.3837): 15})`.
Expected: all 32 equal to the answer asked alone (with the fp32 head, all 32 pick Japanese).
