# fix(fused_moe): remove duplicated condition in wna16 block config

[Upstream PR](https://github.com/vllm-project/vllm/pull/48751) · state: open · merged: False

## Original PR description

## Purpose

`get_moe_wna16_block_config` tests the same condition twice in a single boolean expression:

```python
if (
    num_m_blocks <= 16
    and size_k % (block_size_k * 2) == 0
    and size_k % (block_size_k * 2) == 0   # <- identical to the line above
    and block_size_k <= 512
    and num_blocks >= 512
):
```

Since `X and X` is equivalent to `X`, the second term can never affect the result. This removes it.

The duplicate dates back to the original commit (#13321, `[Kernel] moe wna16 cuda kernel`) and was preserved verbatim by the yapf-to-ruff reformat (#26247), so it has always been redundant rather than being introduced by a refactor.

I've kept this to the mechanical removal only. If the second term was meant to check a different quantity (for example `size_n` / `block_size_n`), that would be a behavior change and should be a separate PR from someone who knows the intended tuning heuristic. Happy to follow up if a maintainer confirms the intent.
