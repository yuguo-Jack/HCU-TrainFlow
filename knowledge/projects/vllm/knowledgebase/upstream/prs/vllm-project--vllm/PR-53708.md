# [Test][Model] Cover embedding modality through the Qwen3-Omni deepstack split

[Upstream PR](https://github.com/vllm-project/vllm/pull/53708) · state: open · merged: False

## Original PR description

## Purpose

The code half of this PR is no longer needed: the fix for #53700 is on main now, applied at the deepstack split via #61064 with the `copy_mm_embedding_modality` helper from #46213. What main still lacks is a model-level guard for it, which is what this PR now contributes: `embed_input_ids` is driven through the deepstack split with interleaved video/audio embeddings, asserting the interleaved merge groups by modality instead of raising. Closes #53700.

`tests/model_executor/test_qwen3_omni.py::test_interleaved_deepstack_split_keeps_embedding_modality`

- Passes on this branch (current main + the test).
- Negative control: reverting the split-site `copy_mm_embedding_modality` call locally makes it fail with the modality error reported in #53700.

AI-assisted (Kimi): the test and the verification above were prepared with AI assistance and executed locally in both directions.

So the setup is sound and the failure is specific to the interleaved path, not

### 3. With this PR's patch applied → correct output

Applying the diff from this PR to the same 0.28.0 install and re-running the
identical `use_audio_in_video` request:

which is a correct description of the `baby_reading` asset, i.e. the merged
embeddings are not just non-crashing but semantically right.

### 4. Why the combination is required

Confirmed against the real `Qwen/Qwen3-Omni-30B-A3B-Instruct` config
(`vision_config.deepstack_visual_indexes = [8, 16, 24]`, so deepstack is on by
default) by calling the unmodified
`Qwen3OmniMoeThinkerForConditionalGeneration.embed_input_ids` directly — no
weights needed, runs in seconds:

| request | deepstack | result |
| --- | --- | --- |
| interleaved (`use_audio_in_video`) | on | **ValueError** |
| interleaved | off | ok — split block skipped, `.modality` survives |
| non-interleaved | on | ok — `super().embed_input_ids` merges positionally, never reads `.modality` |
| interleaved, different V/A span shape | on | **ValueError** (not an artifact of one token layout) |

Only interleaved **and** deepstack both strips the attribute and then requires
it, which is why the existing audio-in-video fixes (#48420, #49397) did not
cover it.
