# [Bugfix][MRV2] Fix FlashInfer attention and ReplaySSM warmups on MRV2

[Upstream PR](https://github.com/vllm-project/vllm/pull/61013) · state: closed · merged: True

## Original PR description

FlashInfer attention warmup:
- The warmup ran a hard-coded 16-token mixed dummy batch without clamping to `max_num_batched_tokens`. On V1 this tripped the `num_tokens <= max_num_tokens` assert; on MRV2 `make_dummy` silently sliced input buffers shorter than `query_start_loc`, failing later in FlashInfer forward (`prefill_query.shape[0] == num_prefill_tokens`). Seen on Blackwell, where FlashInfer is the default, e.g. `tests/v1/core/test_scheduler_e2e.py`.
- MRV2's `_dummy_run` ignored `create_mixed_batch`, so the warmup never ran a mixed prefill+decode batch.

Add `mixed_batch_attention_warmup()`, used by the FlashInfer and MiniMax M3 MSA warmups. It clamps the token count, keeps the V1 mixed dummy batch, and on MRV2 uses `run_mixed_prefill_decode_warmup()` (skipping when that can't run). MRV2's `_dummy_run` now asserts the token budget like V1.

ReplaySSM autotune:
- MRV2 profile dummy runs drop Mamba metadata, so the FlashInfer ReplaySSM autotune never ran the ReplaySSM kernel on MRV2 and `valid_dummy_state_slots` had no effect. Keep Mamba metadata for profile runs that set `valid_dummy_state_slots`.
