# [RL][Frontend] Return weight-version spans on OpenAI completions and chat

[Upstream PR](https://github.com/vllm-project/vllm/pull/61347) · state: closed · merged: True

## Original PR description




## Overview

Follow-up to #59582 and #61070 (RFC #54443): `/v1/completions` and `/v1/chat/completions` now return per-choice `weight_versions` when the request sets `return_weight_versions: true`, as `/inference/v1/generate` already does.

## Claims

- Opt-in `return_weight_versions` on both routes. Each choice reports which weights sampled each range of its output tokens:

  ```json
  "choices": [{
    "index": 0,
    "finish_reason": "length",
    "weight_versions": [
      {"version": "v7", "start": 0, "end": 57},
      {"version": "v8", "start": 57, "end": 128}
    ]
  }]
  ```

- Ranges are half-open over the choice's output tokens, prompt excluded. With `n > 1` or several prompts, each choice gets its own list. An aborted choice gets ranges over its partial output, `[]` without tokens.
- Non-stream choices carry the list; when streaming, each choice's last chunk carries it.
- A streamed choice that finishes without any tokens, such as one aborted before its first token, now gets a last chunk with its `finish_reason` on both routes.

## Validation

```bash
pytest tests/entrypoints/openai/chat_completion/test_serving_chat.py tests/entrypoints/openai/completion/test_completion_error.py -k "weight_versions or lifecycle"
```

- 43 passed. The new `/v1/completions` test covers streaming and not, with the flag on and off; one of its two choices is aborted before its first token. The existing chat lifecycle test now also checks that a choice that finishes without output still gets its last chunk, without reaching its parser.
- End-to-end on H20 with Qwen3-1.7B, on main 8d7b93fec2 with this change: async scheduling on and off, plus chat with the `qwen3` reasoning parser. 188/188, 188/188 and 89/89 checks pass.
  - keep: on both routes, `pause(mode="keep")` across a weight update that zeroes `lm_head`. Every span boundary sat at the first 0 token, streamed and not.
  - abort: `pause(mode="abort")`, with a long-prompt request sent just before it. Each aborted choice got one span over its partial output. The long-prompt request was aborted before its first token with async scheduling on (both routes) and with the reasoning parser, and got a last chunk with `[]`.
  - `n=2` with two prompts, `echo`, logprobs and a stop string: each choice's span ends at its number of output tokens.

## Details

- Who needs it: TRL, open-instruct and AReaL roll out over `/v1/completions`; PipelineRL, ART and rLLM over `/v1/chat/completions`.
- Opt-in, like `return_token_ids`, because these routes serve many non-RL clients. Without the flag, no spans are returned: the field is `null` or omitted.
- Offsets count output tokens: they index the choice's `token_ids` from `return_token_ids`. In chat with a reasoning parser and `include_reasoning: false`, token IDs stay hidden, but the spans still cover every output token. Beam search doesn't return spans.
- Only the serving layer changes; it surfaces `CompletionOutput.weight_versions`, so there are no engine changes.
- Both stream loops used to skip a finished choice with no tokens as an empty prefill chunk, so it never got a last chunk; `/inference/v1/generate` already sends it. In chat, that chunk skips the reasoning and tool parsers, since there is nothing to parse and some parsers assume a non-empty delta (e.g. `hunyuan_a13b`).
- The Rust frontend's OpenAI routes are out of scope.
- Not a duplicate: no other PR returns weight versions on the OpenAI routes.
