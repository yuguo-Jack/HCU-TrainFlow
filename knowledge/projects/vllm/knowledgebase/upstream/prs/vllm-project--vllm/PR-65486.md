# [Build] Only build FA2 by default when targeting SM8x/SM12x

[Upstream PR](https://github.com/vllm-project/vllm/pull/65486) · state: open · merged: False

## Original PR description

## Summary

FA2 is now only built by default when `TORCH_CUDA_ARCH_LIST` includes SM8x or SM12x. On SM9x/SM10x/SM11x, FA2 is only an `8.0+PTX` fallback for configs FA3/FA4 don't cover, so Hopper/Blackwell-only builds skip it unless `VLLM_BUILD_FA2=1` is set (`VLLM_BUILD_FA2=0` always skips it).

- Release wheels and the Docker image are unchanged: their arch list includes SM8x, so FA2 is still built and shipped.
- SM12x keeps FA2 because it is the only FlashAttention path there (FA3 is SM90-only, FA4 doesn't support 12.x).
- On a `10.0`-only build this skips 76 compile units (~4.7 min wall at `-j64`) and a 310 MB `_vllm_fa2_C.abi3.so`.

When FA2 isn't built:
- `FlashAttentionBackend.supports_combination` rejects configs whose FA version resolves to nothing (e.g. head sizes FA4 can't handle, batch invariance on SM100), so backend selection falls through to FlashInfer/Triton.
- `FlashAttentionImpl` raises a clear `NotImplementedError` pointing at `VLLM_BUILD_FA2` when FLASH_ATTN is forced for a config that needs FA2 (e.g. ALiBi).
- `vllm.vllm_flash_attn` imports when only FA4 (CuteDSL) is present.
- `_vllm_fa2_C` becomes an empty CMake target and an optional extension in `setup.py`.

Depends on vllm-project/flash-attention#215 (respect a pre-set `FA2_ENABLED`). The FA pin here points at that PR's commit, which is `b273a02` (current pin) + that one change; it will be repointed to the merged commit.

Not a duplicate: no open vLLM or flash-attention PR makes FA2 optional. vllm-project/flash-attention#196 (native SM12x FA2 SASS) is complementary.

## Test plan

- CMake configure (against the FA branch) with `TORCH_CUDA_ARCH_LIST` = `10.0` and `9.0 10.0` → FA2 skipped; `8.0 10.0`, `12.0`, and the release list `7.5 8.0 8.6 8.9 9.0 10.0 11.0 12.0` → FA2 built (`FA2_ARCHS: 8.0+PTX`); `VLLM_BUILD_FA2=1/0` overrides both ways. `ninja _vllm_fa2_C` is a no-op when skipped.
- `pytest tests/kernels/attention/test_attention_selector.py` on B300: 100 passed, 14 skipped. The two new tests fail without the backend change.
- E2E on B300 with the FA2 `.so` blocked from importing: Qwen3-0.6B and gemma-3-1b-it, both on the default backend (FlashInfer) and with `FLASH_ATTN` forced (FA4). All four ran and produced the expected greedy output (e.g. "The capital of France is" → " Paris. ...").
- `pre-commit run`: clean.

Default/release builds are unchanged, so no model evals were run.
