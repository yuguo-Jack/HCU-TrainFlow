# [Feat] Add text-only OpenAI Decisions API

[Upstream PR](https://github.com/vllm-project/vllm/pull/60465) · state: closed · merged: True

## Original PR description

## Overview

Adds a text-only `/v1/decisions` endpoint following the [OpenAI API format](https://developers.openai.com/api/docs/guides/decisions).

Builds on #59299 and #60677, now merged into `main`.

## Claims

Supports predicate, choice, and score questions using shared label reads under `vllm/entrypoints/openai/decisions`. `/v1/decisions` is available by default on supported generation models and returns 501 when no generation read strategy is available. `/v1/systemone` also supports Clef-Omni pooling models from #61064. The new endpoint accepts text strings or user messages and returns ordered answers with probabilities and token usage.

## Validation

- 137 CPU tests passed on the rebased commit, including Clef-Flash, Liquid d1, and Clef-Omni strategy coverage, DiffusionGemma, launcher routing, cache-salt/tracing behavior, HTTP error handling, logging, limits, Qwen tokenization, and shared generative scoring. All-files pre-commit with the CI manual stage passed.
- Local SDK/schema checks passed without model inference. The OpenAPI schema test collects after extending the existing SmolVLM 501 handling to `/v1/decisions`; its live GPU case runs in Buildkite.
- Qwen3-0.6B GPU end-to-end tests on a DGX Spark: all 15 endpoint tests passed without an endpoint flag before this rebase and the test relocation. The run used `--gpu-memory-utilization 0.35` to share the device. The current checkout could not rerun GPU tests because its NVIDIA driver is unavailable.
- A small balanced Qwen3-0.6B factual eval through `/v1/decisions` scored 8/16: 6/12 predicates and 2/4 choices. All six true predicates received probabilities below 0.5. Direct Chat Completions with the same predicate prompt also returned `false` for a true case, so this result needs a stronger-model follow-up. Live OpenAI comparison remains pending.
