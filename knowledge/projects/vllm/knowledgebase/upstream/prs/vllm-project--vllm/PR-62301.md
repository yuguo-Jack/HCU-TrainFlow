# [Bugfix][Spec Decode] Preserve DP replica index for standalone draft models

[Upstream PR](https://github.com/vllm-project/vllm/pull/62301) · state: open · merged: False

## Original PR description

## Overview

Preserve the target DP replica index when constructing a standalone `method="draft_model"` model. This prevents separate replicas from sharing device-bound compiled draft artifacts and fixes a reproduced DP=2 warm-cache startup failure. Follow-up to #62285 and the standalone analysis on #62062; the root-cause analysis and suggested restoration were reported by @Siquan-Li.

#62062 currently changes DFlash/DSpark paths; this PR fixes the standalone `draft_model` loader and does not duplicate those changes.

## Claims

- Restore the replica index after draft config construction and before loading the model. General `ParallelConfig` semantics and sibling speculators are unchanged.
- Isolate draft compilation/AOT artifacts by replica. Existing loader regressions cover zero and nonzero target indices.
- Fix the observed warm-cache `CUDA driver error: invalid argument`; do not claim an accuracy improvement or serving speedup.

## Validation

61 targeted CPU cases pass:

```sh
PYTHONPATH=. .venv/bin/python -m pytest tests/v1/worker/test_gpu_model_runner_v2.py tests/v1/worker/test_dspark_utils.py tests/v1/worker/test_gpu_target_dependent_ar_speculator.py -q
```

The scoped regression without the fix fails for the three nonzero-index cases; rank-zero controls pass. It is part of the existing Buildkite `v1-executor-worker` suite. Scoped pre-commit checks passed during implementation; upstream pre-commit execution is currently gated by contributor eligibility.

[All raw commands, server logs, evaluation outputs/samples, benchmark outputs/per-request JSON and checksums](https://github.com/MuonChaser/vllm/releases/tag/pr-62301-validation-20261019).

GPU experiment: 2 H100 PCIe 80GB per arm on a shared host; Qwen3-0.6B as both target and draft; DP=2/MP, MRV2, BF16, compilation enabled, CUDA graphs disabled. Both arms start with a fresh shared compilation cache, then restart without removing it. Baseline cold serves successfully but warm restart fails in the standalone draft path; PR cold/warm both serve successfully. Reproduced over two separate cold/warm cycles per arm, with nonzero speculative acceptance on both replicas. The 16-request smoke outputs/finish reasons/token counts match across successful arms.

Full GSM8K (`lm_eval` 0.4.13, 5-shot, 1,319 questions, greedy, seed 256): default-mode accuracy **41.39% baseline vs 40.71% PR**. Unchanged-baseline repeats also varied (48/128 vs 46/128; prefix cache not reset). A separate `VLLM_BATCH_INVARIANT=1` comparison produced identical responses for all 1,319 questions (40.33% each), with compilation still enabled. These controls do not rule out a default-mode regression; all raw results are retained.

Three sequential `vllm bench serve` runs per arm: 128 prompts, input 256/output 128, concurrency 8, 16 warmups, fixed seed 256; **768 measured requests and zero failures**. All six raw outputs are retained. Shared GPU load and repeated prefix-cache effects prevent an isolated-GPU speedup/non-regression claim.

Source is the full Python tree at main baseline `494663940b9b44f667c4f61c8c2407ba8e725ceb` and PR `b2303c5e49471603cd31c1904352ad7d99164dbd`, using official nightly native/build-supplied files from parent `3c13653738dad0acd877c23373816fefffbdd373` (PyTorch 2.14.0+cu130, Python 3.12.13). Native-source files do not change between the wheel parent and baseline; CUDA kernels were not rebuilt. This is not a claim about the latest moving main. Both arms disable the unavailable optional FlashInfer sampler/toolchain. Same-model serving/cache validation does not establish different-draft quality or broader model coverage.

## Details

Independent dense DP stores replica identity in `data_parallel_index` while its distributed DP rank is reset to zero. Constructing the draft config with `replace` reconstructs the parallel config and resets the index. Restoring the target index before `get_model` gives distinct `rank_0_0`/`rank_0_1` draft caches. No steady-state inference operation or synchronization is added.

AI assistance was used for implementation and to execute/document these validations. The detailed results were collected by the agent and do not represent independent human-run H100 validation.
