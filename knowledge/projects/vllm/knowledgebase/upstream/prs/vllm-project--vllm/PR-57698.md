# [Core][Metrics] Add exact recomputed-token counter

[Upstream PR](https://github.com/vllm-project/vllm/pull/57698) · state: open · merged: False

## Original PR description

## Purpose

Preemption count alone does not show how much model work was discarded. This
change adds an exact cumulative Prometheus counter for token positions that are
executed again after scheduler preemption:

`vllm:recomputed_token_executions_total`

The scheduler records the highest completed position made stale by preemption
and counts only subsequently scheduled positions below that frontier. Prefix
cache hits are not scheduled, so they are not counted as recomputed execution.

## Scope

- Carry the per-step recomputed-token count through `SchedulerOutput` and
  `SchedulerStats`.
- Expose it through the existing Prometheus logger.
- Cover exact scheduler accounting and cumulative metric export.

This is not a duplicate: I searched open vLLM PRs for recomputed-token,
preemption-compute, and related scheduler-metric work. No other open PR adds
this exact counter; the only direct result was this PR's earlier revision.
