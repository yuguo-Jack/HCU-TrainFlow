# [Bugfix][Core] Treat a shared-prefix junction as a set of positions under EAGLE

[Upstream PR](https://github.com/vllm-project/vllm/pull/62278) · state: open · merged: False

## Original PR description

## Overview

Fixes the shared-prefix junction under per-group EAGLE flags (#61455): with a dropping EAGLE group in the lookup, siblings that share a prefix get 0 prefix-cache hits under sparse retention (default `prefix_cache_retention_interval=0`). The junction becomes a set of positions, `{J - A, J}`, computed in one place (`junction_boundaries()`) and used by every junction consumer. This is an alternative to #62206, which keeps an extra SWA tail at `J - block_size` inside the SWA mask only.

The MooncakeStore side (store lookup as a junction source, `store_mask` as a consumer) is a follow-up PR stacked on this one: #62400.

## Claims

- DeepSeek-V4-Flash + MTP (retention 0): siblings that diverge 8 tokens past an aligned shared prefix of 3840 tokens get 0 hit tokens on main and 3584 with this PR. Siblings that diverge 160 tokens past it get 3840 on both.
- Shared-prefix GSM8K (1319 questions): the prefix-cache hit rate goes from 4.7% to 82.1%, and accuracy does not change (0.943 → 0.945).
- One helper produces the junction; all consumers read it: SWA and Mamba retention masks, the Mamba junction checkpoint, the scheduler's chunk stops (one per position) and `OffloadingConnector`.
- No behavior change without EAGLE, or when no dropping (non-Mamba) EAGLE group takes part in the lookup.

## Details

**Root cause.** The junction is where the longest single-group hit exceeds the reconciled hit. A dropping EAGLE group needs a peek block past its hit. So after #61455, a sibling that shares F tokens hits F in a non-EAGLE group but at most F − A in the dropping group (A = hit alignment). Main pinned only F, and no sibling can resume there.

**Why a set.** Where a sibling resumes depends on how far past F it diverges. Divergence of less than the drop unit past F resumes at F − A; divergence further than that resumes at F. When the drop unit is smaller than A (DeepSeek-V4: SWA block 64, A 256), both cases occur, so a single position cannot serve both. The junction is therefore `{F − A, F}` whenever a dropping EAGLE group takes part in the lookup.

**Why not #62206.** #62206 fixes the SWA mask only. The Mamba checkpoint, the scheduler chunk stop and `OffloadingConnector` keep the wrong junction.

**Supersedes the first version of this PR.** The first version moved the junction to `F − A` only. That lost the hit at F for siblings that diverge further than the drop unit (a regression with mixed block sizes). This version keeps both positions.

**Cost.** One extra retained tail per junction, only when a dropping EAGLE group exists. Without EAGLE, the junction is one position, as on main.
