# [CPU][Zen] INT8 screened lm_head for greedy batches

[Upstream PR](https://github.com/vllm-project/vllm/pull/64246) · state: open · merged: False

## Original PR description

## Overview

Extends `--screened-lm-head` (#60566, FP8-capable CUDA GPUs only) to AMD Zen CPUs, using an INT8 screen through zentorch. Stacked on #60566, which is squashed into the first commit; please review the last two commits.

## Claims

- Greedy batches on Zen CPUs can use the screened lm_head. Every other batch keeps the full lm_head: sampling, logprobs, penalties, structured output and draft tokens.
- Same answers as the full lm_head: on GSM8K with Qwen3.5-9B W8A8, the extracted answer matches on 256/256 questions and both arms score 0.8867.
- lm_head time on Qwen3.5-9B drops to 0.55x at 1 token and 0.61x at 32 tokens (head-only proof-of-concept timing; end-to-end numbers to follow).
- Model Runner V1 rejects `--screened-lm-head` at config time.

## Validation

Unit tests: 21 pass with zentorch. Without zentorch (CI), 12 run and 9 skip.

```bash
pytest tests/v1/worker/test_zen_cpu_screened_head.py tests/test_config.py::test_v1_model_runner_rejects_screened_lm_head
```

Accuracy, on an AMD EPYC 9K65 (Zen 5) with zentorch 2.14.0.1, 48 cores per run:

```bash
lm_eval --model vllm \
  --model_args pretrained=RedHatAI/Qwen3.5-9B-quantized.w8a8,dtype=bfloat16,max_model_len=4096[,screened_lm_head=True] \
  --tasks gsm8k --num_fewshot 5 --limit 256 --batch_size auto --gen_kwargs max_gen_toks=2048 --trust_remote_code
```

| `--screened-lm-head` | strict-match | flexible-extract |
|---|---|---|
| off | 0.8867 | 0.8867 |
| off, repeat | 0.8711 | 0.8633 |
| on | 0.8867 | 0.8867 |

With the screen on, the extracted answer matches the first flag-off run on 256/256 questions, and 1,739 of 1,788 head calls were screened. The repeat flag-off run shows the baseline's run-to-run variation; each run had its own compile cache.

Performance: lm_head time on Qwen3.5-9B (248,320 x 4,096), from a proof-of-concept of the same screen on vLLM 0.31.0, on a 32-core Zen 5 pod with threads pinned per core. One run.

| tokens | 1 | 4 | 8 | 16 | 32 |
|---|---|---|---|---|---|
| full head (ms) | 43.6 | 50.2 | 72.2 | 111.1 | 230.8 |
| screened (ms) | 23.8 | 29.7 | 40.3 | 70.4 | 140.8 |

Without per-thread pinning, the screen was slower at 1-4 tokens. End-to-end `vllm bench serve` results will follow.

## Details

- An INT8 per-row copy of the BF16 lm_head is scored with `zentorch_dynamic_qlinear` (`ZentorchInt8ScaledMMLinearKernel`). Rows that cannot be the argmax get `-inf`, and only the survivors are recomputed in BF16 with `zentorch_bmm`.
- The screen declines a batch, and the full lm_head runs, when more than 1/16 of the vocabulary survives or the batch has more than 256 tokens.
- `ScreenedLMHead` gains `unsupported_platform_reason()`, and its `__call__` may return `None` to decline a batch. `GPUModelRunner.screened_head_cls` lets `CPUModelRunner` pick `ZenScreenedLMHead` (`vllm/v1/worker/cpu/screened_lm_head.py`).
- Cost: an INT8 copy of the lm_head, +1.0 GB on Qwen3.5-9B.
