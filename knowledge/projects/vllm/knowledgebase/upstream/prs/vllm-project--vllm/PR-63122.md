# [CI/Build][KV Connector] Mooncake tests: patch the httpx module the connector uses

[Upstream PR](https://github.com/vllm-project/vllm/pull/63122) · state: open · merged: False

## Original PR description

## Overview

The Mooncake connector tests mock the bootstrap HTTP client by patching the top-level `httpx` module. Since #56460 the connector imports `httpx` from `huggingface_hub.utils`, which `huggingface_hub` 2.x resolves to `httpx2`. With hub 2.x installed, those mocks never take effect.

## Claims

- `test_register_worker_retries_on_read_timeout` and `test_register_worker_raises_after_max_attempts` pass with `huggingface_hub` 2.x; they currently fail there.
- Behavior under the CI pin (`huggingface-hub==1.31.0`) is unchanged: there, `huggingface_hub.utils.httpx` is the same top-level `httpx` the tests patched before.

## Validation

`pytest tests/v1/kv_connector/unit/test_mooncake_connector.py` in an environment with `huggingface_hub` 2.2.0, `httpx2` 2.13.1 and `httpx` 0.28.1:

| | register_worker tests | whole file |
|---|---|---|
| main | 2 failed: `assert 0 == 3` (the stub client is never called), then real connection attempts | n/a |
| this PR | passed | 123 passed |

## Details

- **Root cause:**
  - `mooncake_connector.py` does `from huggingface_hub.utils import httpx`.
  - In `huggingface_hub` 1.x, `utils/__init__.py` does `import httpx`, with a comment that it "will be httpx2 in huggingface_hub v2.x". In 2.x, `utils.__getattr__("httpx")` returns `importlib.import_module("httpx2")`.
  - The tests did `import httpx` and patched `httpx.AsyncClient`, which is a different module object from the connector's under 2.x. The real `httpx2` client ran instead: no calls were recorded, and the retry test exhausted its attempts against a host that doesn't exist.
  - `_FlakyAsyncClient` raised the top-level `httpx.ReadTimeout`, which the connector's `except httpx.TimeoutException` (an `httpx2` class under 2.x) would not catch either.
- **Fix:** the test module now imports `httpx` exactly as the connector does. Every patch, and the stub's exception, then refers to the connector's module under either hub version.
  - `patch_worker_dependencies` switches from `patch("httpx.AsyncClient")` to `patch.object(httpx, "AsyncClient")` for the same reason.
  - Tests that open a real client against the local bootstrap server now use that same module, which works under either version.
- **CI coverage:** CI's pinned hub 1.31.0 doesn't exercise the failure, so this was validated locally with hub 2.2.0.
