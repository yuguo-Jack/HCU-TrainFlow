# [Perf][DSv4.1][PCP] Overlap KV exchange with query preparation

[Upstream PR](https://github.com/vllm-project/vllm/pull/64200) · state: closed · merged: False

## Original PR description



## Overview

Overlap DeepSeek-V4.1 PCP KV exchange and cache publication with rank-local attention and indexer query preparation on CUDA eager prefills.

## Claims

- Keep SWA KV, compressor-tail and compressed-latent collectives on the calling stream in their existing order while preparing queries on an auxiliary stream.
- Join query preparation before sparse indexing and attention, preserve the short-context indexer shortcut, and retain the existing decode, mixed-batch, compiled and captured paths.

## Details

The current PCP path serializes query preparation with cache publication to keep collectives consistently ordered across ranks. Split out SWA cache publication and the indexer's query preparation so only rank-local work moves to the auxiliary stream. Profiling initializes query GEMM resources on that same stream before workspace locking, and query outputs record the consuming stream for allocator lifetime tracking. This is a model-local scheduling change; it does not change KV formats or introduce peer-cache publication, so it complements the transport and cache-publication work in #53173 and #52863.

- wangyicong52 · comment · 2026-10-28T09:23:48Z · [source](https://github.com/vllm-project/vllm/pull/64200#issuecomment-6465311785)

Closing this after H20 testing (TP2/PCP4, eager, Humming, 8K prompts). A/B runs showed ~2.7–3.4% lower input throughput, and a same-node check reproduced ~2.8% higher TTFT. Profiling confirmed that AllGather and WQ-B overlap, but their durations increased by ~90% and ~35%, respectively, consistent with contention for GPU compute and memory resources. The slowdown outweighed the communication time hidden by overlap, so the current approach does not provide an end-to-end benefit.
