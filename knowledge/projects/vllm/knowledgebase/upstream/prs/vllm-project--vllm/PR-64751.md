# [Bugfix][Spec Decode] Honor draft moe/attention backend overrides for MRV2 standalone draft model

[Upstream PR](https://github.com/vllm-project/vllm/pull/64751) · state: closed · merged: True

## Original PR description

Proposed title: [Bugfix][Spec Decode] Honor draft moe/attention backend overrides for MRV2 standalone draft model

## Purpose

With model runner V2, `method: draft_model` (`StandaloneARSpeculator`) silently ignores `moe_backend` and `attention_backend` from `--speculative-config`. The draft inherits the target's `--moe-backend` / `--attention-backend` instead.

- V1 honors all three draft overrides (`moe_backend`, `attention_backend`, `kv_cache_dtype`) through `_create_draft_vllm_config` in `llm_base_proposer.py`, which `draft_model.py` inherits (#37880, #39930).
- The V2 standalone drafter (#43091) never got them. #61240 added `kv_cache_dtype` by hand. #57312 moved the V2 EAGLE/MTP overrides into `SpeculativeConfig.apply_draft_overrides` but did not touch the standalone path.

The fix builds the draft `VllmConfig` from `spec.apply_draft_overrides(self.vllm_config)`, the same way `load_eagle_model` does, and removes the hand-written `kv_cache_dtype` branch. Any new entry in `_DRAFT_VLLM_CONFIG_OVERRIDES` now reaches this drafter too.

`attn_vllm_config` is unchanged. `init_attn_backend` takes each group's backend from the constructed layer (`attn_layers[name].get_attn_backend()`), and the draft layers are built under the overridden config, so their builders already match the draft backend. No metadata builder reads `attention_config.backend` or `kernel_config.moe_backend`. The `kv_cache_dtype` condition is still needed because builders read `cache_config.cache_dtype`.

## Test Plan

- Extended `tests/v1/worker/test_gpu_model_runner_v2.py::test_standalone_draft_kv_dtype_override`. It now also parametrizes the draft `moe_backend` / `attention_backend`, and asserts that the draft config gets them when set, keeps the target's when unset, and leaves the target config untouched.
- Ran this test plus `tests/v1/spec_decode/test_draft_moe_backend_override.py` and `tests/v1/spec_decode/test_draft_attention_backend_override.py`.
- E2E on one GB200 GPU with a recent nightly image and the patched `speculator.py` overlaid. Model runner V2 was on, with `ibm-granite/granite-3.0-1b-a400m-base` as both target and draft. Target flags: `--moe-backend triton --attention-backend FLASHINFER`. Speculative config: `{"method": "draft_model", "num_speculative_tokens": 3, "moe_backend": "flashinfer_cutlass", "attention_backend": "TRITON_ATTN"}`. Three greedy prompts, 48 tokens each. I read the backends from the loaded target and draft modules.

## Test Result

- Unit tests: 35 passed. Without the fix, the 6 new override cases fail with `assert 'flashinfer_cutlass' == 'triton'`.
- E2E:

| | target attn / MoE | draft attn / MoE | accepted / drafted |
|---|---|---|---|
| before | FLASHINFER / TRITON | FLASHINFER / TRITON (overrides ignored) | 108 / 108 |
| after | FLASHINFER / TRITON | TRITON_ATTN / FLASHINFER_CUTLASS | 108 / 111 |

  Greedy outputs are identical in both runs. The small acceptance drop is expected now that the draft runs different kernels than the target.

- Possible overlap: #60989 (AR speculator refactor / draft CUDA graph) edits `standalone_ar/speculator.py` but not `load_draft_model`, so any conflict should be trivial. #63205 (speculator config classes) adds `standalone_ar/config.py` and edits `vllm/config/speculative.py` next to `apply_draft_overrides`, but not the method itself.
