# [Bugfix][Rust Frontend] Serve SageMaker /ping and mark /invocations unsupported

[Upstream PR](https://github.com/vllm-project/vllm/pull/64660) · state: open · merged: False

## Original PR description

## Overview

The Rust frontend returns a bare 404 for `/ping` and `/invocations`. The Python frontend always registers both for SageMaker (`vllm/entrypoints/serve/sagemaker/api_router.py`), and SageMaker health-checks a container through `/ping`, so a SageMaker deployment with `VLLM_USE_RUST_FRONTEND=1` never comes up healthy.

This serves `GET`/`POST /ping` with the existing `/health` handler, which is what Python does and what the Rust render server already does (`routes/render.rs`). `/invocations` gets the standard 501 placeholder the router uses for other Python routes it doesn't implement yet, so clients get a clear error instead of a 404.

I found this by walking every path in the Python server's `/openapi.json` against both frontends running on the same engine. These were the only routes that 404 on Rust without a 501 placeholder or an open PR (`/generative_scoring` is #46427, `/v1/responses` is #58783).

## Claims

- `GET /ping` and `POST /ping` return the same status and empty body as `/health`: 200 while the engine is healthy, 503 after the engine core dies.
- `POST /invocations` returns 501 `NotImplementedError` with the usual "not supported by the Rust frontend yet" message instead of 404.

## Validation

Live, `Qwen/Qwen3-0.6B` on the CPU engine, `vllm serve` with `VLLM_USE_RUST_FRONTEND=0` vs `=1`, same flags:

| Request | Python | Rust main `335dd77b09` | Rust this PR |
|---|---|---|---|
| `GET /ping` | 200, empty | 404 | 200, empty |
| `POST /ping` | 200, empty | 404 | 200, empty |
| `POST /invocations` | 200 (routes to completions) | 404 | 501 |

Route tests (in-process, mock engine). The existing healthy and engine-dead `/health` tests now also cover `GET`/`POST /ping`, and `/invocations` is added to `unimplemented_python_routes_return_not_implemented`:

```bash
cd rust
cargo test -p vllm-server --lib -- health_endpoint_returns unimplemented_python_routes_return_not_implemented
# main + updated tests: 3 failed
#   GET /ping: left 404, right 200 (and 503 in the engine-dead test)
#   POST /invocations: left 404, right 501
# this PR: 3 passed
cargo test -p vllm-server   # 539 passed
```

`cargo fmt --check` clean, clippy adds no warnings in the changed files, pre-commit passes.

## Details

`/invocations` in Python picks the target endpoint by validating the body against each supported request type in turn. Porting that is a separate change, so I left a TODO next to the route instead of doing a partial version here.

No existing issue covers this. I checked open PRs touching `rust/src/server/src/routes.rs` and searched for `/ping`, `/invocations` and SageMaker in issues and PRs; none add these routes.
