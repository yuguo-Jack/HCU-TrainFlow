# [CI][ROCm] Use AITER prebuilt fp8 MoE modules when inter dim is 256 aligned

[Upstream PR](https://github.com/vllm-project/vllm/pull/62032) · state: open · merged: False

## Original PR description

The modular-kernel harness only pre-shuffles weights (so AITER picks its prebuilt preshuffle_on CK MoE modules) for unquantized and fp8 block schemes. fp8 per-tensor and per-token were excluded entirely because of ROCm/aiter#5766, so every such test JIT-compiles a preshuffle_off module (about 10.5 minutes each in CI). On MI300 this pushes MoE Kernels Shard 1 to about 55 minutes against its 55 minute timeout.

aiter#5766 only rejects intermediate sizes that are not a multiple of 256 (e.g. inter_dim=384). Pre-shuffle fp8 per-tensor/per-token weights too when the intermediate size is a multiple of 256; the 384 padding cases keep JIT-compiling.

On MI300X (rocm/vllm-ci image from amd-ci #14761):
- not multigpu: 48 passed, 6 skipped (same skips as CI); JIT builds drop from 4 kernels (per-tensor/per-token stage 1 and 2) to 2 (stage 2 only).
- multigpu: 27 passed (same as CI).
