# [Bugfix][Frontend] Fold inline system messages in place for system-first templates

[Upstream PR](https://github.com/vllm-project/vllm/pull/63368) · state: open · merged: False

## Original PR description



## Overview

For chat templates that only accept a leading system message (e.g. Qwen3.5), `/v1/messages` now keeps non-leading inline system messages in place by folding them into the neighbouring user or tool message, instead of merging them into the system prompt. This keeps the prompt prefix stable across turns. Fixes #63331.

## Claims

- With a system-first template, a system message that changes from turn to turn no longer changes the start of the prompt, so prefix caching covers the conversation up to that message. On Qwen3-0.6B with a system-first template, the second turn of a two-turn replay reuses 5,952 of 6,006 prompt tokens, up from 16.
- System messages that lead the `messages` array still merge into the system prompt, as before.
- Structured tool content (`tool_reference`) is never modified.
- No change when the template accepts non-leading system messages (`merge_inline_system=False`).

## Validation

**Before/after reproducer** (RTX 4060 8 GB, WSL2). I served `Qwen/Qwen3-0.6B` with `--enforce-eager --enable-prompt-tokens-details --gpu-memory-utilization 0.6`. Qwen3's own template accepts inline system messages, so to hit the bug I passed `--chat-template` with that template plus the Qwen3.5 `loop.first` guard. The startup warning confirms the system-first path is active. The replay sends two `/v1/messages` turns shaped like the issue's: system prompt, a ~6K-token user message, an inline system reminder, an assistant reply, then a user message. Turn 2 appends one exchange and changes the reminder's text.

| Code | Turn 2 prompt tokens | `cache_read_input_tokens` |
|---|---|---|
| `main` (be08fa5355) | 6,004 | 16 |
| this PR | 6,006 | 5,952 |

I did not run an accuracy eval. The change only moves where inline system text appears in the prompt, and it only affects system-first templates.

## Details

- **Root cause:** `_detect_merge_inline_system` returns true when the template rejects non-leading system messages. `_convert_system_message` then appended every inline system message to the system prompt. Claude Code sends inline system messages whose text changes each turn, so the start of the prompt changed every turn. On the issue's Qwen3.8 setup, prefix hits stayed near 19K tokens per turn.
- **Fix:** `_convert_system_message` now merges only the system messages before the first non-system message. `_convert_messages` folds each later one into its neighbouring message:
  - into the preceding user message, or a tool message with string content, if that is the last converted message;
  - otherwise, for example right after an assistant turn, prepended to the next user or tool message, so nothing comes between an assistant `tool_use` and its result;
  - if no message follows, emitted as a final user message.
  - Text is joined with `\n\n`, or added as a separate text part when the content is a list.
- **Tradeoff:** a folded message loses its `system` role. Before, it also left its position. The startup warning now says this, and still recommends a `--chat-template` that accepts non-leading system messages.
- **Not a duplicate:** #56520 and #60555 change only the DeepSeek V4/V4.1 encoders. #47681 adds an opt-in `--inline-system-messages preserve` flag that is off by default. Draft #58772 has a wider design: a one-time probe through every renderer type. This PR is limited to the system-first merge path in `/v1/messages`.
