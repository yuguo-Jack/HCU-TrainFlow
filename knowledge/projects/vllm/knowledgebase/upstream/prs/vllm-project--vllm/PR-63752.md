# [Bugfix][Model Loader] Reject stacked weights that received only some shards

[Upstream PR](https://github.com/vllm-project/vllm/pull/63752) · state: closed · merged: True

## Original PR description

## Overview

`track_weights_loading` only diffs parameter names, so `qkv_proj.weight` counts as loaded once any one shard is written. A checkpoint missing every `v_proj` loads cleanly and serves uninitialized rows. Follow-up to #55911 agreed with @hmellor.

## Claims

- A stacked parameter (`MergedColumnParallelLinear`, `QKVParallelLinear` and their subclasses) that received only some shards now fails at load, naming the parameter and the missing shard ids.
- Same gate as the existing check (unquantized by default, `enable_weights_track` to force). Valid checkpoints are untouched.

## Validation

`pytest tests/model_executor/model_loader/test_stacked_shard_tracking.py` → 7 passed.

Qwen3-0.6B on H100, tensors deleted from the safetensors file, loaded via `LLM`:

| Checkpoint | main | this PR |
|---|---|---|
| untouched | OK | OK |
| all `v_proj` removed | loads, generates `!!!!!!!!` | `ValueError: Following weights were not initialized from checkpoint: {'model.layers.0.self_attn.qkv_proj.weight.v', …}` |
| `layers.3.mlp.up_proj` removed | loads, wrong text | `ValueError: Following weights were not initialized from checkpoint: {'model.layers.3.mlp.gate_up_proj.weight.1'}` |

No eval needed: weights of a valid checkpoint are bitwise unchanged.

## Details

New base `StackedColumnParallelLinear`: each `weight_loader`/`weight_loader_v2` records the shard it wrote on the param, and `pop_missing_shards()` reports expected shards that never arrived, then clears the record so a later load is graded on its own. Shards with zero rows on the rank are never expected. The loader runs it after the existing name check. `shard_ids` is now the single declaration per class.
