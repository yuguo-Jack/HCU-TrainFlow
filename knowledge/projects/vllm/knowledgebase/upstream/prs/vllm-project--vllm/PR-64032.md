# [Bugfix][Multimodal] Return 400 when local media access is disabled

[Upstream PR](https://github.com/vllm-project/vllm/pull/64032) · state: closed · merged: True

## Original PR description



## Overview

Return HTTP 400 instead of 500 when a request uses a `file://` media URL on a server started without `--allowed-local-media-path`. Fixes #61874.

## Claims

- Disabled local media access is reported as `400 BadRequestError` on the OpenAI chat and render endpoints (sync and async media loading). It was `500 InternalServerError`.
- The access restriction and the error message are unchanged; no file is read.

## Validation

Before/after on a CPU build (macOS arm64), `HuggingFaceTB/SmolVLM-256M-Instruct`, server started **without** `--allowed-local-media-path`:

```bash
vllm serve HuggingFaceTB/SmolVLM-256M-Instruct --max-model-len 2048 --enforce-eager \
  --limit-mm-per-prompt.image 1 --port 8811
curl -s -w '\nHTTP %{http_code}\n' localhost:8811/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "model": "HuggingFaceTB/SmolVLM-256M-Instruct", "max_tokens": 8,
  "messages": [{"role": "user", "content": [
    {"type": "text", "text": "Describe this image."},
    {"type": "image_url", "image_url": {"url": "file:///tmp/vllm-disallowed-image.png"}}]}]}'
```

| | Response |
|---|---|
| main | `{"error":{"message":"Cannot load local files without \`--allowed-local-media-path\`.","type":"InternalServerError","param":null,"code":500}}` HTTP 500 |
| this PR | `{"error":{"message":"Cannot load local files without \`--allowed-local-media-path\`.","type":"BadRequestError","param":null,"code":400}}` HTTP 400 |

## Details

Root cause: `MediaConnector._load_file_url` raised a bare `RuntimeError` when `allowed_local_media_path` is unset. `create_error_response` maps unclassified exceptions to 500, while the adjacent out-of-directory check raises `ValueError` (400). The fix raises `VLLMValidationError`, the `VLLMClientError` subclass already used in this module, so the status comes from the typed exception path rather than the raw-`ValueError` fallback slated for removal.

Not a duplicate: #61751 handles missing files when local access is *enabled* and does not touch this branch. #63749 is the Rust frontend, which does not support `--allowed-local-media-path`. @ntu-b12505041 expressed interest in #61874 on 2026-10-15 but no PR has been opened since; happy to close this in favor of theirs if one is in progress.

No other code catches `RuntimeError` for this path (only torchcodec decode handlers in `audio.py`, unrelated). The Rust frontend does not support `--allowed-local-media-path`, so no parity change.
