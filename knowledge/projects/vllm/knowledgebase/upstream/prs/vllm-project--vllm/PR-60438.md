# [Bugfix] Fall back from DeepGEMM when nvcc is older than 12.9

[Upstream PR](https://github.com/vllm-project/vllm/pull/60438) · state: open · merged: False

## Original PR description

## Overview

DeepGEMM compiles its kernels at runtime and aborts the engine when nvcc is missing or older than 12.9. vLLM only checks the GPU architecture and that DeepGEMM is installed, so on Hopper with an older toolkit, block-FP8 models crash on load. This PR adds the nvcc check, so vLLM warns and falls back to its other FP8 kernels. To find nvcc, it reuses FlashInfer's existing lookup, moved unchanged to `find_nvcc()` in `vllm/utils/platform_utils.py`.

## Claims

- Block-FP8 models load on Hopper with nvcc 12.8 or no nvcc, instead of aborting with `NVCC version must be at least 12.9`.
- The fallback logs one warning naming the nvcc version it found and where it looked.
- No change when nvcc is 12.9 or newer, or with `VLLM_USE_DEEP_GEMM=0`.
- No change to FlashInfer: `has_flashinfer` finds the same nvcc as before, and its existing tests pass unchanged apart from the patched module.

## Validation

H100 NVL, CUDA 12.8.1 toolkit (`nvcc` 12.8), driver for CUDA 13, vLLM `528772a4b` (precompiled; `vllm/utils/deep_gemm.py` is identical on current main), `Qwen/Qwen3-8B-FP8`, offline `LLM.generate` with two prompts:

| | kernel selected | result |
|---|---|---|
| main | `FlashInferFp8DeepGEMMDynamicBlockScaledKernel` | `RuntimeError: ... NVCC version must be at least 12.9`, then `Engine core initialization failed` |
| this PR | `CutlassFp8BlockScaledMMKernel` | warning below, then `'The capital of France is' -> ' Paris. ...'` |

```
WARNING DeepGEMM kernels are disabled: its JIT needs nvcc 12.9 or newer (DG_JIT_NVCC_COMPILER, CUDA_HOME,
CUDA_PATH, PATH or /usr/local/cuda), found 12.8. Set CUDA_HOME to a newer CUDA toolkit.
```

`pytest tests/utils_/test_deep_gemm_utils.py tests/utils_/test_flashinfer_utils.py`: 7/7 (nvcc 12.8, 12.9 and 13.0; missing nvcc; the `DG_JIT_NVCC_COMPILER` override; FlashInfer's existing lookup tests against the shared helper).

## Details

The check finds nvcc the way DeepGEMM's JIT does (`DG_JIT_NVCC_COMPILER` or `DJ_JIT_NVCC_COMPILER`, then `CUDA_HOME`, `CUDA_PATH`, `nvcc` on `PATH`, then `/usr/local/cuda`). After the override, that is the lookup FlashInfer already had, which is why the two now share `find_nvcc()`. The check runs once, since `is_deep_gemm_supported` is cached. A fallback instead of an error matches how vLLM already handles an unsupported GPU or a missing DeepGEMM package. The cost is speed, which the warning states. On Hopper the fallback is the CUTLASS block-FP8 path.

#49051 proposed a similar check and was closed in favor of the JIT warmup RFC #47456, which does not cover the toolchain. Unlike #49051, a missing nvcc also disables DeepGEMM here, because DeepJIT has no NVRTC path: it asserts that nvcc is executable and at least 12.9 (`include/deep_jit/backend/cuda/backend.hpp` at the pinned DeepGEMM).
