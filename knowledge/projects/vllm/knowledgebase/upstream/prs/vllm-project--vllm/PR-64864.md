# [Doc][ROCm] Document unified-memory sizing for Ryzen AI MAX (gfx1151)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64864) · state: closed · merged: False

## Original PR description

## Overview

Docs-only change: add a "Unified-memory APUs" section to
`docs/configuration/conserving_memory.md`, covering the APU memory model, measured KV cache
sizes, the shared-pool sizing rule, and two device-specific behaviors on `gfx1151`; link it
from the ROCm installation requirements so users searching for Ryzen AI MAX find it.

## Claims

- Adds, in one place, what an APU shares with the host (a GTT window over system RAM) and how
  `--gpu-memory-utilization` maps to KV cache size.
- Documents measured KV cache sizes at `--gpu-memory-utilization` 0.15 / 0.35 / 0.50 on a
  Ryzen AI MAX 395, showing the linear scaling against the 108 GiB GTT limit.
- Recommends the byte-based `--kv-cache-memory-bytes` for reproducible footprints, and
  documents the CUDA graph memory profiling default introduced in v0.21.0 that shifts the
  effective utilization.
- Records two `gfx1151` behaviors: the ROCm custom paged attention kernel is unavailable
  (Triton fallback), and graph capture works without `--enforce-eager` for small models at
  short context lengths.

## Validation

Measured on the APU itself, idle machine, ROCm 7.2.4, vLLM `0.32.0+rocm723`,
`Qwen/Qwen3-0.6B`, `--max-model-len 4096`, `--seed 0`:

```bash
vllm serve Qwen/Qwen3-0.6B --port <p> --gpu-memory-utilization <u> \
  --max-model-len 4096 --seed 0
```

| `--gpu-memory-utilization` | Available KV cache | KV cache tokens | Max concurrency @4096 |
| -------------------------- | ------------------ | --------------- | --------------------- |
| 0.15 | 14.17 GiB | 132,704 | 32.40x |
| 0.35 | 35.77 GiB | 334,928 | 81.77x |
| 0.50 | 51.97 GiB | 486,592 | 118.80x |

KV growth is exactly `Δu × 108 GiB` (0.20 → 21.60 GiB, 0.15 → 16.20 GiB), confirming that
the denominator is the GTT limit rather than a dedicated VRAM pool. The docs therefore size
the request from `free / total` and leave headroom for the host.

`uvx pre-commit run --files docs/configuration/conserving_memory.md` passes (markdownlint,
codespell, and the doc hooks). A full `mkdocs build` needs the `api-autonav` plugin to
import `vllm`, which is not available on this machine; the changed page was instead
rendered standalone with the same `pymdown-extensions` set to check the admonition and
table syntax.

## Details

- Placement: `conserving_memory.md` already owns memory-budget guidance and is in the
  configuration nav, so no new page or nav entry is added. The section is cross-linked from the
  AMD ROCm requirements note in `docs/getting_started/installation/gpu.rocm.inc.md`; that
  snippet is included only by `gpu.md`, so the relative link resolves there.
- Why this is not a duplicate: checked open PRs and issues mentioning `gfx1151`,
  Strix Halo, Ryzen AI MAX and APU memory. The open items are code changes, not docs:
  #50320 (`is_integrated_gpu()` accounting), #40963 (APU VRAM reporting), #44331 (8060S
  tuned MoE config), #64098 / #63199 / #62202 (kernel and memory-boundary fixes). No open
  PR adds APU serving documentation; this change does not touch `vllm/platforms/rocm.py`.
- The recommendation to prefer `--kv-cache-memory-bytes` over a percentage follows from
  the shared denominator: the same fraction yields different KV sizes depending on host
  load, while a byte budget does not.
- No behavior change and no code change; the numbers are machine-specific and are scoped
  to the documented setup.

AI assistance was used to collect measurements and draft the text; every changed line was
reviewed by the submitter.
