# [Attention] Reuse block tables in FlashInfer prefill planning

[Upstream PR](https://github.com/vllm-project/vllm/pull/63494) · state: open · merged: False

## Original PR description

## Overview

Pass the existing GPU block-table slice to FlashInfer's non-DCP prefill `plan()`. Without it, a backend that consumes rectangular block tables reconstructs the same table from CSR page indices during planning.

## Claims

- Avoid redundant block-table preparation using the existing public `block_tables` argument, which is already supported by the pinned FlashInfer 0.7.2.
- Keep the prefill rows aligned when a batch also contains decode requests. This follows the existing DCP caller pattern, with an explicit `num_reqs` endpoint.

## Validation

- Changed-file `pre-commit` passed, including Ruff and mypy; `git diff --check` passed.
- A separate GPU harness passed 64 public-wrapper cases across eight fresh processes: FP64-reference O and requested cuDNN LSE, nonzero CSR prefix offsets, unused table entries, table updates, fresh bindings, replan and retained CUDA Graph replay. FA2 fallback cases checked O. The table-reconstruction helper was called with the omitted argument and bypassed with the supplied table.
- Qwen3-8B HTTP serving passed 960 requests across four fresh old/new servers, followed by 1,440 requests in two servers alternating the exact old/new metadata-builder body between completed cohorts. Full prefill and cached-prefix workloads used concurrency 1 and 4. Expected cache-hit counts and one-token completion semantics passed; all 22 distinct prompt groups returned the same greedy token. This is a targeted one-token model check, not a general model-quality evaluation.

Serving used vLLM `2d40c0609f`, whose entire affected Python module is byte-identical to this PR's base `be2de71198`, and a development FlashInfer/cuDNN stack to exercise the cuDNN path. It was not a full native rebuild of the new base. Stock FlashInfer 0.7.2 was checked for argument compatibility; these results do not imply that its default selector chooses cuDNN.

The serving checks above validate execution and request semantics. No serving performance result is included in this PR.

## Details

`common_attn_metadata.block_table_tensor` already contains the required GPU table. The added argument passes a row view without copying its contents. CSR metadata remains available to FlashInfer implementations that use it. This adds no API, cache, synchronization, dispatch rule, or per-layer work.

Checked open PRs for FlashInfer prefill and block-table work. [#58519](https://github.com/vllm-project/vllm/pull/58519) concerns DCP LSE/host preparation, and [#59493](https://github.com/vllm-project/vllm/pull/59493) protects planning staging-buffer lifetime; neither forwards this non-DCP prefill table. No matching block-table forwarding PR was found.
