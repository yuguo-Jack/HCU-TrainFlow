# [draft] Migrate FlashInfer NVLink one-sided to MoEEpCommunication

[Upstream PR](https://github.com/vllm-project/vllm/pull/61655) · state: open · merged: False

## Original PR description

## Overview

Migrate `flashinfer_nvlink_one_sided` from the deprecated `MoeAlltoAll` entry point to FlashInfer's `MoEEpCommunication` API introduced in [FlashInfer #5532](https://github.com/flashinfer-ai/flashinfer/pull/5532).

This is an API prerequisite for the CFT integration discussed in [#57069](https://github.com/vllm-project/vllm/issues/57069). It does not enable CFT or migrate the two-sided backend.

FlashInfer 0.7.2 is released and upstream's stable dependency update is merged. Head `a0d97611` also addresses the public-API compatibility feedback: prefer checkpoint methods on `communication`, retain the 0.7.2 `.alltoall` fallback, and avoid importing removed legacy cache classes during test teardown. **The updated source passed all 11 one/two-sided tests on 0.7.2 and all 9 one-sided tests on the pinned upcoming FlashInfer API, with zero skips.**

## Claims

- Adopt `create_communication`, typed dispatch results, and the communication wrapper's combine interface.
- Preserve dispatch workspace sizing for BF16/FP16, NVFP4, MXFP8, and DeepSeek blockwise FP8, including padded MXFP8 scales.
- Share one communication wrapper across layers, growing token, dispatch, and combine capacities independently.
- Preserve the existing low-precision combine option and keep bootstrap metadata on CPU when CUDA is the default device.
- Extend regression coverage for workspace growth, quantized payloads, empty ranks, CUDA Graph replay, and low-precision combine.

- bobboli · comment · 2026-10-19T12:25:51Z · [source](https://github.com/vllm-project/vllm/pull/61655#issuecomment-6267163861)

Heads-up from the FlashInfer side: please use only the public `NVLinkOneSidedAlltoAll` API (`dispatch`, `combine`, `checkpoint_prepare`, `checkpoint_restore`, `destroy`). Everything around it is being removed after 0.7.2:

- flashinfer-ai/flashinfer#6047 (merged after 0.7.2) removed `MoeAlltoAll`. `NVLinkOneSidedAlltoAll` no longer wraps it, so `.alltoall` is gone; `checkpoint_prepare()` / `checkpoint_restore(comm_backend)` are now methods of `NVLinkOneSidedAlltoAll` itself. The workspace is refcounted and freed by the last `destroy()`, so no cache needs clearing.
- flashinfer-ai/flashinfer#6621 (in review) deletes `flashinfer.comm.trtllm_moe_alltoall` and `flashinfer.comm.trtllm_alltoall` (including `MnnvlMoe`).
- A planned follow-up refcounts the two-sided workspace and frees it in `destroy()`, the same way as one-sided. That fixes the shutdown SIGSEGV at its source.

In this PR, that means:

- `checkpoint_prepare` / `checkpoint_restore` use `communication.alltoall`, which breaks on the next FlashInfer. Call the methods on `communication` directly when it has them, falling back to `.alltoall` only for 0.7.2.
- The test teardown reaches into `MoeAlltoAll._WORKSPACE_CACHE` and `MnnvlMoe` class attributes. Those imports fail on the next FlashInfer. `manager.cleanup()` (→ `destroy()`) is enough for one-sided. For two-sided, keep the workaround behind a `hasattr` check until the follow-up lands, or skip it.
- Two-sided in vLLM will need to move to `flashinfer.moe_ep` (`NVLinkTwoSidedAlltoAll`) once flashinfer-ai/flashinfer#6621 lands. A separate PR is fine.
