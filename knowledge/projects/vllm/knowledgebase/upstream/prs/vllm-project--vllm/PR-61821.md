# [Perf][Kernel] Add the bias in the SM120 NVFP4 CUTLASS GEMM epilogue

[Upstream PR](https://github.com/vllm-project/vllm/pull/61821) · state: open · merged: False

## Original PR description



## Overview

NVFP4 linears add the bias in a separate kernel after the GEMM. When the output goes straight to the attention custom op (the QKV projection of BERT/XLM-R and Qwen2-style models), Inductor cannot fuse that add, and on large prefills it costs more than the GEMM. This PR adds an optional `bias` to `cutlass_scaled_fp4_mm`, applied in the SM120 epilogue (CUTLASS `LinCombPerColBias`) as the FP8 CUTLASS path already does, and passes it from `CutlassNvFp4LinearKernel`.

## Claims

- The SM120 epilogue add costs 0.007 ms on an 81920 x 3072 x 1024 GEMM, vs 0.749 ms for a separate `out + bias`.
- `CutlassNvFp4LinearKernel` passes the bias to the GEMM on SM12x unless N is padded.
- `BAAI/bge-reranker-v2-m3` NVFP4 with `linear_backend="cutlass"`: 12-13% less GPU time per batch on an RTX PRO 6000.

## Validation

RTX PRO 6000 Blackwell Server Edition (SM120), CUDA 13.4, torch 2.13.0+cu130.

- `pytest tests/kernels/quantization/test_nvfp4_scaled_mm.py`: 28 passed, 14 of them with a bias.

bge-reranker-v2-m3 (ModelOpt `NVFP4_DEFAULT_CFG`, classifier excluded), `linear_backend="cutlass"`, GPU kernel time of one `classify` call on 128 sequences; two alternating rounds per arm agree within 0.1 ms:

| | 128 x 640 tokens | 128 x 320 tokens |
|---|---|---|
| main (separate bias add) | 135.1 ms | 60.4 ms |
| this PR | **119.1 ms** | **52.5 ms** |

The QKV bias kernels (16.1 ms at 640 tokens) disappear and the GEMMs take 0.4 ms longer; Inductor already fuses the other bias adds into the next LayerNorm or GELU kernel. Recall@10 on 60 questions each of Ko-StrategyQA / MIRACL-ko: 0.898 / 0.941 vs 0.881 / 0.950 (one question or less either way); mean |logit − FP32| 0.675 / 0.702 vs 0.676 / 0.695.

## Details

**Kernel.** `Fp4GemmSm120` gets a `HasBias` template flag that switches the epilogue from `LinearCombination` to `LinCombPerColBias` (D = alpha * acc + bias[n]); the dispatch instantiates both and picks one by whether a bias is passed.

**Default backend.** SM120 selects `FlashInferCutlassNvFp4LinearKernel` first, and FlashInfer's `mm_fp4` takes no bias (flashinfer-ai/flashinfer#2290, closed as not planned), so this helps where `CutlassNvFp4LinearKernel` is selected. On bge both backends' GEMMs take about the same time, so `cutlass` becomes the faster choice there; the default stays because FlashInfer's autotuned GEMM is faster on Qwen3-4B decode shapes.

**Limitations.** SM100 is unchanged because I could not test it: its kernel rejects a bias, and the linear keeps the separate add there. CI has no SM12x runner, so the bias test cases are skipped in CI.

**Duplicate check.** No open PR adds a bias to `cutlass_scaled_fp4_mm` or to the NVFP4 linear kernels.
