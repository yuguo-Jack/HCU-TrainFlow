# [ROCm][CI] Fix Muse Spark RoPE cache leak between tests

[Upstream PR](https://github.com/vllm-project/vllm/pull/65140) · state: closed · merged: True

## Original PR description

## Overview

Fixes the remaining 26 `tests/models/test_muse_spark_rocm_mono.py` failures in `:amd: (MI355) Basic Models (Other)` on the [nightly build #99098](https://buildkite.com/vllm/ci/builds/99098/list?sid=01a19b12-86dc-48ba-811c-30a4d4e009ed). `test_muse_spark_rocm_shared_rope.py` leaves a CPU `RotaryEmbedding` in `get_rope`'s global cache, and the mono test's tiny GPU model picks it up when both files run in the same pytest session, as they do in that shard. The other 2 failures in the job (`test_layer_guards_follow_the_weight_finalize`, `test_weight_views_alias_the_rank_slices`) are fixed by #65080.

## Claims

- `test_muse_spark_rocm_shared_rope.py` runs with its own empty `_ROPE_DICT`, so its CPU RoPE no longer leaks into later tests.
- Together with #65080, `test_muse_spark_rocm_mono.py` passes when it runs after the shared-RoPE test.
- Test-only change: no model or kernel code is touched.

## Validation

MI355X (gfx950), using the ROCm wheel from build #99098 (`0e5b2ba11`) with `vllm/models/muse_spark/amd/model.py` from current `main` (#65080):

```bash
pytest -v tests/models/test_muse_spark_rocm_shared_rope.py tests/models/test_muse_spark_rocm_mono.py
```

| Run | Before | After |
|---|---|---|
| `test_muse_spark_rocm_mono.py` alone | 33 passed | 33 passed |
| `shared_rope` then `mono` | 26 failed, 8 passed | 34 passed |

Before, all 26 failures are `RuntimeError: fused_muse_spark_qknorm_rope_kv_insert, ...: cos_sin_cache must be a contiguous 2-D CUDA tensor`, the same as in CI. The four Muse Spark files in CI order (`rocm_loading`, `logits_local`, `shared_rope`, `mono`) give 48 passed. `ruff check` and `ruff format --check` pass.

## Details

- `get_rope()` caches `RotaryEmbedding` objects in the global `_ROPE_DICT` without the device in the key, so the CPU RoPE created by `test_muse_spark_rocm_shared_rope.py` stays in the cache after that test. The tiny GPU model in `test_muse_spark_rocm_mono.py` then gets that CPU RoPE, and `fused_muse_spark_qknorm_rope_kv_insert` fails because `cos_sin_cache` is not on the GPU.
- The fix isolates the cache in the test that leaks it, the same way `tests/models/quantization/test_gptq_marlin.py` already clears `_ROPE_DICT`. Adding the device to the cache key would affect every model for a test-only problem.
