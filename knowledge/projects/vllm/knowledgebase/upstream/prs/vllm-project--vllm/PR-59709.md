# [Bugfix][DSv4] Don't bake the C128 compressor skip into CUDA graphs

[Upstream PR](https://github.com/vllm-project/vllm/pull/59709) · state: closed · merged: True

## Original PR description

## Overview

On Model Runner V2, DeepSeek-V4 C128 layers stop writing compressed KV on every step that replays a PIECEWISE CUDA graph. Decode logprobs drift away from prefill, and the gap grows with sequence length. This PR makes the compressor's C128 launch skip apply only when the stream is not capturing.

## Claims

- Fixes C128 compressed-KV writes being dropped on breakable PIECEWISE graph replays (MRV2, the CUDA default).
- No throughput cost: the skip still applies to eager steps, and the compress kernel already gates each token on the GPU.

## Validation

**Regression test:** `tests/kernels/test_compressor_kv_cache.py::test_c128_skip_is_not_baked_into_cuda_graph`. It captures `DeepseekCompressor.forward` on a batch that completes no 128-token block, then counts kernel launches on replay. On `main` the replay launches nothing; with this PR it launches once. Verified on B300.

**End to end:** vLLM 0.30.0, whose `compressor.py` matches `main` except for two unrelated lines. DeepSeek-V4-Flash, 2x B300, TP2 + EP, `deep_gemm_mega_moe`. 64 prompts, 384 sampled tokens each, base weights. Each server re-scores its own sampled tokens with `prompt_logprobs`. The table reports |decode logprob - prefill logprob| per token:

| Config | mean \|Δ\| | tokens with \|Δ\| > 1 | mean \|Δ\| at tokens 0-127 / 128-383 |
|---|---|---|---|
| `enforce_eager` | 0.064 | 0.57% | 0.076 / 0.057 |
| default (`FULL_AND_PIECEWISE`) | 0.118 | 2.14% | 0.089 / 0.133 |
| default + this PR | 0.058 | 0.38% | 0.070 / 0.053 |
| `PIECEWISE` | 0.120 | 2.20% | 0.089 / 0.135 |
| `PIECEWISE` + this PR | 0.059 | 0.40% | 0.071 / 0.053 |

Without the fix, prefill on the same tokens is also nondeterministic run to run: mean k3 0.059 between two scoring passes, against 0.003 with the fix. Prefill chunks that fit a captured size hit the same path.

## Details

`DeepseekCompressor.forward` skips the C128 compress+store when the step's CPU metadata (`c128_boundary`) says no request completes a 128-token block. The old guard excluded only `CUDAGraphMode.FULL`. Since the eager region was narrowed for MRV2, though, the compressor also runs inside breakable PIECEWISE graphs. Capture uses `InputBatch.make_dummy` batches, which never complete a block, so the `return` is recorded into every PIECEWISE graph.

`torch.cuda.is_current_stream_capturing()` covers FULL capture too, so it replaces the mode check (the same guard as the indexer short-context shortcut in #52492). MRV1 runs the whole attention prep in the eager region, so it was not affected.

The ROCm two-stage compressor also branches on host `num_decode_tokens` in this region. Both of its launch paths process any token mix, so this PR leaves it alone. Untested on ROCm.

```python
"""Sample tokens via decode, re-score the same tokens via prefill
(prompt_logprobs), and print |decode logprob - prefill logprob| per token.

usage: python decode_vs_prefill.py <base_url> <model> [num_prompts] [max_tokens]
"""

import sys
from concurrent.futures import ThreadPoolExecutor

import requests

base, model = sys.argv[1], sys.argv[2]
n = int(sys.argv[3]) if len(sys.argv) > 3 else 64
max_tokens = int(sys.argv[4]) if len(sys.argv) > 4 else 384

TOPICS = [
    "the history of the printing press", "how a refrigerator works",
    "the rules of chess", "photosynthesis", "the French revolution",
    "how TCP congestion control works", "the life cycle of a star",
    "how vaccines train the immune system",
]


def run(i):
    prompt = (f"Write a detailed essay about {TOPICS[i % len(TOPICS)]}. "
              f"(variant {i})\n\n")
    r = requests.post(f"{base}/v1/completions", json={
        "model": model, "prompt": prompt, "max_tokens": max_tokens,
        "temperature": 1.0, "seed": i, "logprobs": 0,
        "return_tokens_as_token_ids": True,
    }, timeout=1800).json()["choices"][0]
    toks = r["logprobs"]["tokens"]
    dec = r["logprobs"]["token_logprobs"]
    p_ids = requests.post(f"{base}/tokenize", json={
        "model": model, "prompt": prompt}).json()["tokens"]
    ids = p_ids + [int(t.split(":")[1]) for t in toks]
    s = requests.post(f"{base}/v1/completions", json={
        "model": model, "prompt": ids, "max_tokens": 1, "temperature": 0,
        "prompt_logprobs": 0,
    }, timeout=1800).json()["choices"][0]["prompt_logprobs"]
    pre = []
    for pos, tid in zip(range(len(p_ids), len(ids)), ids[len(p_ids):]):
        pre.append(s[pos][str(tid)]["logprob"])
    return [abs(a - b) for a, b in zip(dec, pre)]


with ThreadPoolExecutor(16) as ex:
    rows = list(ex.map(run, range(n)))

flat = [d for r in rows for d in r]
early = [d for r in rows for d in r[:128]]
late = [d for r in rows for d in r[128:]]
mean = lambda x: sum(x) / max(len(x), 1)
print(f"prompts={n} tokens={len(flat)}")
print(f"mean |decode - prefill| logprob, all tokens      : {mean(flat):.4f}")
print(f"mean |decode - prefill| logprob, tokens 0-127    : {mean(early):.4f}")
print(f"mean |decode - prefill| logprob, tokens 128+     : {mean(late):.4f}")
print(f"tokens with |delta| > 1                          : "
      f"{sum(d > 1 for d in flat)} ({100 * mean([d > 1 for d in flat]):.2f}%)")
```
