# [Bugfix][DCP] Finalize the NIXL DCP interleave size before profiling

[Upstream PR](https://github.com/vllm-project/vllm/pull/62330) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

NIXL P/D + DCP resolved the KV-cache interleave after profiling, allowing sparse indexers and compiled graphs to consume a stale value. Resolve global cache groups first, finalize interleave once in the engine core, and assign the resolved value on workers before profiling.

Builds on the root-cause analysis and global-group approach in #60671 by @andylolu2, and incorporates @LucasWilkinson's [suggestion](https://github.com/NickLucche/vllm/pull/13). This updates the existing alternative PR; it retains the legacy interleave field and CLI behavior that #60671 removes.

## Claims

- The engine builds global KV-cache groups before profiling and reuses them for final allocation.
- `VllmConfig.finalize_kv_cache_layout` resolves NIXL DCP interleave once in the engine core. `set_kv_cache_layout(layout_name, cp_kv_cache_interleave_size)` sends the resolved values to workers, which only assign them.
- Connector initialization no longer adjusts interleave. Sparse indexers read the shared configuration directly instead of maintaining a separate lazy cache.

## Details

Startup order:

1. Load models and update backend block sizes.
2. Resolve the layout and global cache groups in the engine.
3. Finalize interleave once in the engine using the global groups, then send the resolved layout and interleave to workers for assignment before profiling.
4. Profile memory; allocate from the previously computed global groups.
5. Initialize the connector and capture serving graphs.

The existing layout RPC carries the resolved interleave alongside the layout name. The core owns resolution; workers assign the value to their existing `ParallelConfig`, preserving model-held references. Global groups stay in the core for final allocation. No additional RPC or configuration field is introduced.

The temporary KV cache used for CUDA-graph memory profiling still uses the model runners' existing local grouping. The core reuses its global groups for interleave resolution and final allocation; it does not redesign temporary profiling allocation or synchronize separate draft-model config copies.

Out-of-tree `set_kv_cache_layout` overrides must accept the resolved interleave argument. The legacy `dcp_kv_cache_interleave_size` field and its current precedence rules are retained.
