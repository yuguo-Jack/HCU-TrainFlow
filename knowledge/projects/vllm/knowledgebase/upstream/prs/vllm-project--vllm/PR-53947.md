# [Bugfix][Elastic EP] Release a prepared reconfiguration when scaling fails

[Upstream PR](https://github.com/vllm-project/vllm/pull/53947) · state: open · merged: False

## Original PR description

A scale prepares a reconfiguration on every engine and then commits it. If it
fails in between, the engine keeps `eep_scaling_state` and every later scale is
rejected:

```
RuntimeError: Elastic EP reconfiguration is already active
```

Only a process restart clears it, so one failed scale disables scaling on that
deployment for good.


Adds an abort that releases a prepared reconfiguration, on both the Ray and
external LB paths, and calls it when a scale fails before commit.

## Test

2 x H200, DeepSeek-V2-Lite, one DP rank per pod, `--data-parallel-external-lb`,
TP=1, EPLB on, ranks launched externally.

Posting `/scale_elastic_ep` to a single rank fails, since prepare waits for peers
that were never told. Before: every later scale returns `already active`. After:
that error does not appear in either rank's log and the engine accepts a new
reconfiguration. Scale-up is unaffected, DP2 -> DP3 still commits in ~33s.

Abort releases the engine state, it does not make a failed scale-up retryable on
its own: the joining rank is left waiting on a handshake that abort tears down,
so it has to be recreated first.

Based on #43202, conflicts with it in `async_llm.py`. Happy to rebase either way.
