# [Profiler] Synchronize iteration windows across DP ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/56491) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Add opt-in `synchronize_iterations_across_dp` to align profiler delay/duration across DP ranks sharing target-model forwards, including idle ranks doing dummy work.

## Claims

- Reuse existing DP coordination; no profiling-only collective. The fixed readiness row adds one int32 per DP rank, even when disabled.
- Preserve default rank-local behavior, DP=1, unsupported-runner fallback, and #57875's session-specific bounds.
- Support MRV1/MRV2, bounded stop, and restart. Skipped coordination and all-rank idle polls do not advance the clock.

## Validation

Local CPU checks: **109 passed, 76 skipped** (profiler); **32 passed, 10 skipped** (DP coordination). `pre-commit` and `git diff --check` passed.

```sh
.venv/bin/python -m pytest tests/v1/worker/test_gpu_profiler.py -q
.venv/bin/python -m pytest tests/v1/worker/test_gpu_ubatch_slicing.py -q
```

Local runs used the existing `skip_global_cleanup` marker via an uncommitted plugin for a platform cleanup issue; skipped accelerator tests are not passes.

An earlier CUDA run had **289 passed, 6 CPU-worker initialization failures**. All six cases remain; fresh-interpreter isolation awaits CUDA confirmation. Current-head multi-GPU/Nsight validation (idle ranks, graph replay, async/speculative execution, stop/restart) and overhead measurements remain pending. Hosted CI is not green: authorization is required, and an earlier Intel CI failure remains undiagnosed.

## Details

Add `"synchronize_iterations_across_dp":true` to `--profiler-config`. Arm every participating rank with identical settings before traffic; use `max_iterations` for aligned automatic stop. Explicit stop remains immediate locally. Independent replicas without a shared forward cadence should leave this disabled.

Worker callbacks advance the existing profiler at agreed runner boundaries. MRV1 compatibility retains the same option for existing deployments. Usage and edge cases are documented in the profiling guide.
