# [Docs][Model] Add Parakeet TDT transcription support via plugin

[Upstream PR](https://github.com/vllm-project/vllm/pull/65005) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Lists NVIDIA Parakeet TDT (`ParakeetForTDT`, e.g. `nvidia/parakeet-tdt-0.6b-v3`) as supported through the out-of-tree [vllm-parakeet-plugin](https://github.com/Alex-Wengg/vllm-parakeet-plugin), the same route as Nemotron 3.5 ASR in #59827. Refs #23943.

## Claims

- `ParakeetForTDT` is listed in the plugin table in `supported_models.md` and with the other plugin-backed encoder-decoder models in `v1_guide.md`.
- No vLLM code changes.

## Validation

The plugin on vLLM 0.32.0, one RTX A6000:

| Check | Result |
| --- | --- |
| Token parity vs Transformers `generate()`, 73 LibriSpeech clips, fp32 (`scripts/parity.py`) | 73/73 identical |
| WER through `vllm serve` (bf16 encoder), LibriSpeech test-clean / test-other (`scripts/eval_wer.py`) | 1.93% / 3.61% (model card: 1.93% / 3.59%) |
| Throughput through `vllm serve`, 64 concurrent requests, test-clean | RTFx 238 |

`pre-commit run --files docs/models/supported_models.md docs/usage/v1_guide.md` passes.

## Details

- Not a duplicate of #41708 (with MRV2 `ModelState` work), the first Parakeet TDT integration, which has been waiting since September on a decision about native support. That PR decodes each transcript at prefill and replays it as forced tokens. The plugin instead decodes step by step, batched across requests, and adds no model code to vLLM.
- The plugin follows the layout of [vllm-nemotron-asr-plugin](https://github.com/Sohaib-Ahmed21/vllm-nemotron-asr-plugin): a `vllm.general_plugins` entry point, a `VerifyAndUpdateConfig` hook, an MRV2 `ModelState` that keeps each request's encoder frames, the decode loop inside `forward`, and one-hot `compute_logits`. It differs in two ways. The TDT loop advances all requests together in GPU tensors and applies TDT's frame-skip durations. The plugin also captures its own CUDA graphs, so it runs with plain `vllm serve` and needs no `--enforce-eager` or `VLLM_USE_V2_MODEL_RUNNER=1`.
- Unlike #59827, this adds no `_OOT_SUPPORTED_MODELS` entry. Transformers defines `ParakeetForTDT`, so without the plugin, vLLM resolves the model to the Transformers backend before it checks that table, and the entry would never be used.
- AI assistance (Claude Code) was used to write the plugin and this PR. I reviewed the changed lines and ran the validation above.
