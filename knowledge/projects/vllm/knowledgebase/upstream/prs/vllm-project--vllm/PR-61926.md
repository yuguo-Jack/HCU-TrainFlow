# [ROCm][Perf][DSv4] Use AITER tuned GEMM for the compressor projections and inverse-RoPE einsum

[Upstream PR](https://github.com/vllm-project/vllm/pull/61926) · state: open · merged: False

## Original PR description

**Overview**
Route the DeepSeek-V4 compressor projections and the inverse-RoPE einsum on ROCm through aiter's tuned GEMMs instead of torch.mm / torch.einsum.

**Claims**
Replaces four torch.mm call sites in the DSv4 ROCm attention path with aiter.tuned_gemm.tgemm.mm, which selects a tuned kernel per shape.
Covers the multi-stream fork, not just the single-stream path. The fork splits the 2560×K compressor projection into 2048×K (main) and 512×K (indexer); both previously fell through to torch.mm.
Replaces torch.einsum("tgd,grd->tgr", …) in rocm_inv_rope_einsum with aiter's batched_gemm_bf16.
Validation
Profiled DeepSeek-V4-Pro, TP4, gfx1250, ISL 1024:

before
Cijk_…MT256x128x64 (hipBLASLt, from torch.mm)	120.7 ms over 364 calls
tuned _gemm_a16w16_gfx1250_compute_bound_kernel	30 calls
The 364 Tensile calls are the two multi-stream projections; only the single-stream path was reaching the tuned kernel. Both multi-stream shapes have tuned configs shipped in aiter:
configs/gfx1250/gluon/gemm/gemm_a16w16/GEMM-A16W16-N=2048-K=7168.json and …N=512-K=7168.json.

**Note: output dtype = float32 is now supported in aiter tgemm**

pre-commit run --files on both changed files: 13 passed, 21 skipped, 0 failed (incl. ruff check, ruff format, mypy, typos, SPDX).
