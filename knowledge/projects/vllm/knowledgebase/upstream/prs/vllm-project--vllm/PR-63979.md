# [ROCm] Offer TRITON_UNFUSED for MXFP4 MoE before emulation

[Upstream PR](https://github.com/vllm-project/vllm/pull/63979) · state: open · merged: False

## Original PR description



## Overview

On ROCm, MXFP4 MoE auto-selection now offers `TRITON_UNFUSED` between `AITER_MXFP4_BF16` and `EMULATION`, so CDNA2 (gfx90a, MI210/MI250X) gets the native OAI Triton kernels instead of emulation. Fixes #59151.

## Claims

- On gfx90a, `select_deepseek_v4_mxfp4_moe_backend()` (the generic MXFP4 path used by `Mxfp4MoEMethod`) picks `TRITON_UNFUSED` instead of `EMULATION`.
- One-line change to the ROCm priority list; no change on CUDA/XPU/CPU.

## Validation

New test `test_rocm_mxfp4_moe_selects_triton_unfused_without_aiter` in `tests/kernels/moe/test_ocp_mx_moe.py` runs the real oracle on ROCm with AITER disabled (runs in the MI300 MoE Kernels CI step).

On 1x MI250X GCD (gfx90a), vLLM v0.31.0 ROCm image with this change bind-mounted:

```
pytest tests/kernels/moe/test_ocp_mx_moe.py::test_rocm_mxfp4_moe_selects_triton_unfused_without_aiter
# without this change:
E       AssertionError: assert <Mxfp4MoeBackend.EMULATION: 'EMULATION'> == <Mxfp4MoeBackend.TRITON_UNFUSED: 'TRITON_UNFUSED'>
1 failed
# with this change:
1 passed
```

Full `tests/kernels/moe/test_ocp_mx_moe.py` on the same GCD: the set of failing tests is identical with and without this change (22, all pre-existing on this hardware/image: emulation, CUTLASS EP and gfx950 round-up tests), except the new test.

End to end, `TRITON_UNFUSED` serves Kimi-K3 (MXFP4) on 4 nodes x 8 MI250X GCDs (selected explicitly there, because compressed-tensors MXFP4 goes through the gpt-oss priority list); see #63978. The issue reporter ran MiMo-V2.6-Flash on 4x MI210 with the backend forced.

## Details

- Root cause: `_get_priority_backends()` on ROCm listed only `AITER_MXFP4_BF16` and `EMULATION`. AITER's MXFP4 MoE kernels require CDNA3+, while `UnfusedOAITritonExperts` already reports gfx90a as supported (`_triton_kernel_moe_supports_current_device()`).
- Tradeoff: CDNA3/CDNA4 with AITER disabled (the default, `VLLM_ROCM_USE_AITER=0`) also move from `EMULATION` to `TRITON_UNFUSED` for this path. With AITER enabled, `AITER_MXFP4_BF16` still wins.
- Not a duplicate: #54202 re-enables `TRITON_UNFUSED` in the gpt-oss list (`_get_priority_backends_for_gpt_oss()`); this PR changes the generic ROCm list. No open PR references #59151.
