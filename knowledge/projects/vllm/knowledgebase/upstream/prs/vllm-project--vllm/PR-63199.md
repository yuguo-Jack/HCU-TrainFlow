# [ROCm] Add gfx1151 W8A8 blockscale skinny GEMM

[Upstream PR](https://github.com/vllm-project/vllm/pull/63199) · state: open · merged: False

## Original PR description



## Overview

Add a gfx1151-only skinny W8A8 FP8 blockscale GEMM fast path for DeepSeek V4 decode-side native AITER blockscale linear layers.

This keeps the existing AITER FP8 quantization, scale preparation, padded weight layout, TP behavior, CUDA Graph behavior, and fallback behavior unchanged.

## Claims

- Adds a native HIP W8A8 blockscale skinny GEMM for gfx1151 over the existing native AITER tensor layout.
- Supports logical `M=1..6`, `K=4096`, `N % 128 == 0`, FP8 row-major weights with padded row strides, and FP32 `[M,K/128]` / `[N/128,K/128]` block scales.
- Enables the fast path only for explicitly marked DeepSeek V4 projections, while preserving the original AITER fallback for unmarked kernels, unsupported shapes, unsupported layouts, unsupported dtypes, and non-gfx1151 devices.
- Validates production-style padded FP8 weight rows, CUDA Graph replay, skinny dispatch, fallback routing, and invalid-stride rejection.
- Shows kernel-level speedups on the representative DeepSeek V4 projection families `N=1536` and `N=4096` for `M=1..6`.

## Details

### Design

The new HIP path consumes the same already-prepared native AITER blockscale tensors passed into `AiterFp8BlockScaledMMKernel.apply_block_scaled_mm()`. It does not introduce model-level re-quantization, weight copies, alternate weight storage, or RoPE changes.

The DSV4 ROCm model code only marks the two target decode projections:

- `fused_wqa_wkv`
- `wo_b`

The actual dispatch guard remains in the AITER scaled-mm backend and requires:

- `gfx1151`
- native AITER RDNA linear path
- `use_triton`
- output dtype `bfloat16`
- activation dtype `float8_e4m3fn`
- FP32 block scales
- `M=1..6`
- `K=4096`
- `N % 128 == 0`
- unit K-stride weight layout with aligned padded row stride
