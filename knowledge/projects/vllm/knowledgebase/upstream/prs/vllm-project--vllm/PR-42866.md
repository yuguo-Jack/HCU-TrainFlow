# [Bugfix] v1/sample: use out-of-place scatter in apply_top_k_top_p_pytorch

[Upstream PR](https://github.com/vllm-project/vllm/pull/42866) · state: closed · merged: False

## Original PR description

## Summary

Fixes #42745.

`apply_top_k_top_p_pytorch` uses an in-place `scatter_` to restore sorted logits to their original positions:

```python
return logits.scatter_(dim=-1, index=logits_idx, src=logits_sort)
```

In-place ops on captured tensors are banned during CUDA graph capture, raising:

```
torch.AcceleratorError: CUDA error: operation not permitted
# ... in apply_top_k_top_p_pytorch
    logits.scatter_(dim=-1, index=logits_idx, src=logits_sort)
```

This affects any device where FlashInfer's JIT-time arch detection rejects the architecture (e.g. Blackwell GB10, `sm_121a`) and vLLM falls back to the PyTorch-native sampler while cudagraph capture is active. The resulting `EngineCoreError` cascades to 500s on all subsequent requests.

## Fix

Replace in-place `scatter_` with out-of-place `scatter`:

```python
return logits.scatter(dim=-1, index=logits_idx, src=logits_sort)
```

Since `logits_idx` from `logits.sort()` is a permutation that covers every column index, the out-of-place semantics are identical — and the returned tensor is safe to use under cudagraph capture.

## Tests

Added `tests/v1/sample/test_topk_topp_scatter_cudagraph.py`:
- Verifies the result is a **new tensor** (not an alias of `logits`)
- Verifies `logits` is **not modified in-place**
- Verifies top-k keeps exactly `k` finite logits per row
- Verifies top-p always keeps at least one finite logit per row
- Covers combined top-k + top-p, shape preservation, and the no-op path
