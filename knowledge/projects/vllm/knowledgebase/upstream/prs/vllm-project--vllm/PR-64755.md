# [Perf][PP] Send PP outputs from a dedicated buffer on the V2 runner

[Upstream PR](https://github.com/vllm-project/vllm/pull/64755) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

On the V2 model runner, non-last PP stages snapshot outgoing intermediate tensors into one preallocated send buffer and send the snapshot instead of the live outputs, so the next forward no longer waits for the previous step's NCCL send.

- Engages only on the V2 runner, PP > 1, non-last ranks; buffer sized from the profile run's outgoing payload and charged to the KV budget.
- No new flags or env vars; the V1 runner is untouched.

## Claims

- **Stall-behind-send eliminated** on every non-last stage profiled (see table).
- **p50 TTFT −5.7% (median of 5 rounds) at 0.85× capacity** on MiniMax-M3.1-Flash PP2, prefill-heavy open loop; no consistent gain at ≤0.75×, ~+3% at ≥0.95×.
- Saturated throughput −2.7% on average, within ±5% noise.
- Qwen3.5-397B-A17B-FP8 (dummy weights): stall removed, TTFT flat — the freed time does not reach the critical path for every model/step structure.

### Correctness

- New distributed chain tests (`tests/distributed/test_pp_send_buffer.py`): PP2 and PP4 chains, varying per-step payload sizes, stages taking turns lagging; asserts payloads arrive intact while senders overwrite their outputs every step.
  `python -m pytest tests/distributed/test_pp_send_buffer.py -v` → 2 passed in 55.90s (PP2 and PP4 chains, 4× B300)
- GSM8K with real weights: pending; required before leaving draft.

## Details

- Root cause: an NCCL send completes only when the peer posts its receive, which the next stage does after its own previous forward. Sending live outputs makes the next forward wait, since it would overwrite the send's source (CUDA-graph outputs are static; relayed aux hidden states alias the persistent receive buffer). The snapshot moves that wait to the next buffer copy. This pays only when the slower stage alternates step to step; uniform full batches see no change.
- One buffer per sending rank, sized from the profile run and charged to the memory profile, so KV-cache sizing accounts for it. Cost: one payload-sized device copy per step on non-last stages. Depth 2 was evaluated and adds nothing.
- Not a duplicate: #53948 defers sampled-result receives; #64385/#64350 add stage-local DBO graphs; #63745 changes PP boundaries; #41501 shrinks residual payloads; #53102 types PP transport. None isolates outgoing-send storage.
