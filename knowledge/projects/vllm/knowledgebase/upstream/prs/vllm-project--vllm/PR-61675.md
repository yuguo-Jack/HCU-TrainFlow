# [Perf][ROCm][Kernel] Fuse Qwen3.8 MTP verify conv, GDN, and RMSNorm

[Upstream PR](https://github.com/vllm-project/vllm/pull/61675) · state: open · merged: False

## Original PR description

## Overview

Opt-in ROCm kernel that fuses flat Qwen3.8-27B MTP verify: width-1..4 causal convolution, the gated-delta recurrence, and gated RMSNorm. Enable with `VLLM_ROCM_QWEN_MTP_GDN=1` (default off). Prefill and ordinary decode stay on the stock path.

No open PR implements this fusion. The Qwen3.8 mono-decode drafts (#60833, #61325) are a different design.

## Claims

- On Qwen3.8-27B MTP verify (16 key heads, 48 value heads, head dim 128, bf16, fp32 SSM, TP=1), one Triton kernel replaces `causal_conv1d_update`, `fused_sigmoid_gating_delta_rule_update`, and `RMSNormGated`.
- The fused op is faster than that stock chain on gfx950 at widths 1–4 and batches 1, 8, and 32.
- GSM8K (1319 examples, MTP-3) stays in the same score band as the baseline. End-to-end generate time is about 1–2% faster on the paired runs.

## Details

The verify step is dispatched from `qwen_gdn_attention_core_rocm_mtp`, a custom op registered as a piecewise-graph splitting op and marked eager during CUDA-graph capture. A Python branch in the compiled forward would be specialized away on a non-spec trace. When the flag is off, both `forward_cuda` and `forward_hip` are unchanged. When it is on, `forward_hip` uses `forward_cuda` so the fused path is reachable even if AITER is present.

Uniform widths (the captured MTP batch) are one conv launch and one norm launch. Mixed widths take at most four launches. The norm is applied inside the kernel, then the caller only runs `out_proj`. Stock steps still run the core and `self.norm` once. An MTP step the kernel cannot run raises `ValueError` instead of silently falling back.

Supported shape is Qwen3.8-27B only: heads 16/48/128/128, TP=1, conv width 1–4, SiLU/swish conv, silu/swish/sigmoid norm, full-row norm-before-gate, no conv bias. Block ids use int64 addressing.

Uniform graph replay does not re-enter Python, so it does not read slots back to the host. A non-captured step does one `max().item()` per layer to reject an out-of-range slot. Ragged batches are not the captured path.

No `docs/` change. The flag is default-off and the comment in `vllm/envs.py` is included by `docs/configuration/env_vars.md`.
