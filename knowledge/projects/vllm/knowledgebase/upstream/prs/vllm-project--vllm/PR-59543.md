# [Core] Opt-in per-request return of the last hidden states in generation (MRV2)

[Upstream PR](https://github.com/vllm-project/vllm/pull/59543) · state: open · merged: False

## Original PR description



## Overview

Adds an opt-in, per-request output: for each generated token, the hidden state its logits were computed from (`SamplingParams.return_last_hidden_states`, returned in `CompletionOutput.last_hidden_states`; the engine must allow it with `--enable-return-last-hidden-states`).
Implements RFC #59542; related: #48743, #56916 / #57736, #57185 (differences in the RFC and below).

## Claims

- **New output, exact:** row `i` is the tensor `compute_logits` received for generated token `i` (gathered after sampling, not recomputed), shaped `[len(token_ids), hidden_size]`, CPU, model dtype, returned with the final output; rows follow stop tokens, `max_tokens` and `n > 1`.
- **Off by default, no change when off:** with the engine flag off the model runner holds no state and does no work; outputs are bit-identical to stock with the flag off or on and unused.
- **Cheap when used:** one row gather per asking request per step and a non-blocking device-to-host copy on the output copy stream; a median 0.12 ms per request on our deployment; no host synchronization added (checked with `VLLM_GPU_SYNC_CHECK=error`).
- **Small:** 146 library lines across 11 files, no new abstraction, following the path `prompt_token_id_logprobs_dict` already takes; Model Runner V2 only; refused at start-up with speculative decoding, pipeline or context parallelism.

## Details

**Why this is not duplicate work.**
#57185 returns the final prompt-position state for one-token, `n = 1`, non-streaming requests on native Qwen2 and Qwen3.5 through `kv_transfer_params`; #57736 (RFC #56916) captures windows of output-token rows for rollouts with a capture plan, optional auxiliary layers, and its own lifecycle; #48743 returns states captured by the extraction connector.
This change returns the exact `compute_logits` input for every generated token, on any Model Runner V2 generation model, through a typed field, in about 150 library lines; the RFC compares them in a table.

**Design.**
The runner keeps a set of asking request ids (only when the flag is on); after `sample()` it gathers their rows by the same `logits_indices` `sample()` used, into `ModelRunnerOutput.last_hidden_states`; `AsyncOutput` copies them to the host on the output copy stream; the scheduler cuts each request's rows to its kept tokens into `EngineCoreOutput.new_last_hidden_states` (appended last for `array_like` compatibility); the output processor concatenates them on finish, as `routed_experts` is.
The returned tensor is a `torch.cat` copy, never a view of the zero-copy transport frame the decoder produced (`test_last_hidden_states_do_not_alias_transport_buffers`).

**Tradeoffs and limitations.**
- Rows are returned with the final output only (like `routed_experts` and `sampling_mask`); per-step delivery could follow.
- Not exposed in the OpenAI-compatible HTTP responses; Python API only for now.
- Bitwise reproducibility is the platform's: the GPU test compares token ids exactly and logits and rows within four fp16 ULPs, within a batch and across runs, because with CUDA graphs an identical batch moved a row by 3 ULPs between runs on an RTX PRO 6000 (eager runs bit-identical), and on an RTX 4090 one of three identical sequences in a batch differed by one fp16 step in 1 of 30 batches, in both cases whoever asked.
- Configurations refused at start-up (speculative decoding, pipeline and context parallelism) can be enabled with tests later.

**Backport.**
For deployments pinned to v0.30.0: [`rfc/return-last-hidden-states-v0.30.0`](https://github.com/aminry/vllm/tree/rfc/return-last-hidden-states-v0.30.0), the same change hand-ported; the deployment numbers above come from it.
