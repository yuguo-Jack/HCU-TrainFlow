# [Bugfix] Bound threaded PT shard retention

[Upstream PR](https://github.com/vllm-project/vllm/pull/60227) · state: open · merged: False

## Original PR description

## Overview

The threaded PT/bin loader keeps completed futures until loading ends. Each future retains its loaded state dictionary, so a thread limit alone does not limit checkpoint memory. This change uses a bounded shard window and releases each consumed future.

## Claims

- Limit loader-held shards to `max_workers`, including the shard in use.
- Reduce tracked peak checkpoint-tensor memory by **52–59%** in two measured loads.
- Preserve tensor names, values, map locations, and load errors. Stop new submissions when the iterator closes early.

## Validation

| --- | --- | --- |
| Loader regression cases | 2 failed | Passed |
| Native offline weight-utils suite | — | 42 passed |
| Peak tracked tensor bytes, two loads | 1,503,264,768 in both | 723,009,024 / 622,329,856 |

The model checks used Qwen3-0.6B BF16 on one L4, converted into 11 PT shards, with two loader threads. Eight engine starts passed all 32 greedy chat requests. Prompt and output token IDs matched within each test series. Tensor-release and early-close tests also passed 100 repeats each.

Weak references tracked checkpoint tensors and included consumer-held tensors. Whole-process RSS/PSS did not show a clear reduction. The 52–59% result applies to tracked checkpoint tensors. Disk and cache state affected the few measured load times, so no general startup speed gain is claimed.

After the main update, nine CPU source-test cases passed with real checkpoint files. Both regression cases failed on main, as expected. The production iterator and test file are unchanged. Applicable hooks passed except two macOS mypy errors for Linux-only `os.posix_fadvise` symbols in unchanged code. Current main has the same errors. Isolated main and candidate type checks passed with the Linux target and Python 3.11. GPU and model checks were not rerun. Upstream test CI is blocked by the contributor gate.

## Details

Open PR searches for `multi_thread_pt_weights_iterator` and threaded PT loading found no other PR that bounds retained shard futures. This fix changes the existing iterator and adds regression checks in its existing test file.

The iterator removes a completed future before yielding its tensors. It submits a replacement after the current shard is consumed and its state dictionary is released. Early close cancels pending jobs where possible; running jobs can finish during shutdown.

The limit is a shard count, not a byte cap. A consumer can retain tensors after the loader releases them. Less read-ahead can reduce I/O overlap. The change applies to the optional threaded PT/bin path. Safetensors loading is unchanged.
