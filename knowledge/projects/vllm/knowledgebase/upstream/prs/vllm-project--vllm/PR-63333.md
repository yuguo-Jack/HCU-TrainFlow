# [1/3][Spec Decode] Add remote draft placement foundation

[Upstream PR](https://github.com/vllm-project/vllm/pull/63333) · state: open · merged: False

## Original PR description

## Overview

Add opt-in configuration, protocol and session handling for placing a speculator in a standalone process. This is the foundation of same-host remote draft placement.

Related design: [RFC #42109](https://github.com/vllm-project/vllm/issues/42109). This is part 1/3 (foundation) of the standalone placement series.

## Claims

- Negotiate model/feature compatibility and inline byte budgets before sending tensors.
- Fence requests and proposal handles by session, sequence identity and generation.
- Support strict errors or terminal target-only fallback, with bounded connection, frame and pending-work resources.
- Preserve the original typed transport failure or deadline when socket cleanup also fails, so failure policy and terminal fencing still apply.

## Details

The target retains native token verification and sampling. Requests whose remote state becomes uncertain remain terminal; reconnecting admits new identities. Native local execution remains the default, and `transport="auto"` selects inline.

The RFC author already published a [ZMQ-based disaggregated-drafting POC](https://github.com/laviier/vllm/tree/2132e0599aba8dd252b6e1880547c6617b709a2c). The POC includes a custom standalone draft runner; this series reuses native MRV2 speculators under explicit placement contracts. This increment proposes the capability, bounded-session and lifecycle foundation for that placement; it does not claim remote transport or N:M routing as new concepts. GPU execution and CUDA IPC are the next two increments. Predictive fan-out caching and cross-node execution remain outside this foundation.
