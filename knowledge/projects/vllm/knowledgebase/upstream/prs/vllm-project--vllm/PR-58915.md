# [Bugfix][Metrics] Retain components for resolved quantization configs

[Upstream PR](https://github.com/vllm-project/vllm/pull/58915) · state: open · merged: False

## Original PR description

## Overview

Fixes #58742. Resolved quantization names missing from the estimator lookup silently drop attention and FFN work from MFU/MBU estimates.

## Claims

- Resolve weight size from GPTQ/AWQ bit widths, online quantization specifications, and mixed linear/expert precision.
- Retain components with a deduplicated warning and model-dtype estimate when an unsupported method or checkpoint layer selection cannot be represented by one width.
- Preserve existing supported methods and unquantized controls.

## Validation

Rebased onto current main `276fbcf`, resolving the upstream move of `Self` into `typing`. Implementation and test bodies are unchanged from the previously tested branch.

```bash

.venv/bin/pre-commit run --files vllm/v1/metrics/perf.py tests/v1/metrics/test_perf_metrics.py
```

**100 metrics tests passed.** All applicable pre-commit checks passed, including the repository's minimum-version mypy check.

Executed 16 real checkpoint/flag combinations six times against the rebased stack: **96 online runs passed**, each evaluating prefill and decode. A separate 16-case run used the unpatched current-main estimator with identical checkpoint revisions, configuration hashes, and resolved layer lists. All repeats were identical; unaffected controls and the previously approved estimates were unchanged.

Validation used Python 3.12 and CPU Torch with actual `ModelConfig`, `VllmConfig._get_quantization_config`, and estimator execution. No weights were loaded or GPU inference run; model outputs, kernels, and serving behavior are unchanged.

## Details

Both attention and FFN parsers share weight-size resolution. GPT-OSS retains bf16 linear layers and FP4 expert accounting; DeepSeek-V4's FFN accounting is restored while its separate unsupported attention architecture remains outside this fix.

The fallback can overestimate weight traffic and does not provide per-layer accounting. Automatically discovered layer lists in the tested Qwen GPTQ/AWQ checkpoints trigger the documented 2-byte fallback rather than assuming every projection is 4-bit.

No overlapping fix was found in issue-number or area searches. Related #58745, #58836, and #54228 address speculative-token accounting, hybrid attention, and expert activation counts respectively.
