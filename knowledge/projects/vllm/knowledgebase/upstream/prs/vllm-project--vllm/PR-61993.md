# [Feature][Quantization] Add online Hadamard rotations before RMSNorm

[Upstream PR](https://github.com/vllm-project/vllm/pull/61993) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Add online Hadamard rotations before configured RMSNorm modules, restoring the original coordinates at the final norm, LM head, and MTP hidden-state boundaries of QuaRot models.

## Claims

- Add a configuration-driven RMSNorm rotation adapter, with checkpoint-loaded rotation parameters shared between the main model and MTP.
- Reuse vLLM's HadaCore for the power-of-two Hadamard component, with a small TileLang kernel for checkpoint K-axis mixing, scaling, and inverse signs. Support `K * 2^m` composite rotations and a PyTorch reference.

## Validation

GLM-5.3 W4AN / QuaRot W4AN: `GlmMoeDsaForCausalLM`, 78 main layers, hidden size 6144 (`12 * 512`), four-bit per-channel weights and BF16 activations.

Environment: 8 H20 GPUs, TP8, vLLM nightly `e97573215`, PyTorch `2.13.0+cu130`, TileLang `0.1.12`. Accuracy and performance measurements used CUDA Graph `FULL_AND_PIECEWISE` with `torch.compile` mode `NONE`.

The GLM-5.3 `P=512` configuration does not hit HadaCore's partial-warp numerical bug. Affected shapes with `32 <= P <= 256` need the fix in [#53167](https://github.com/vllm-project/vllm/pull/53167). This round's composite-operator tests, microbenchmarks, and profile use that PR's HadaCore fix.

## Details

### Main-model and MTP norm boundaries

With both the main-model and MTP residual streams rotated offline, this change restores the original coordinates at two norm boundaries:

1. **Main-model final norm.** Its output feeds both the LM head and the MTP hidden-state input. Inverse rotation before the norm restores the expected representation for both consumers.
2. **MTP's own norm.** The rotated MTP hidden state also needs inverse rotation before `shared_head.norm`, preserving the original norm and head for draft logits and subsequent MTP hidden states.

```text
main rotated residual
      ↓
inverse Hadamard
      ↓
original Final Norm
      ├── LM Head
      └── MTP input hidden state

MTP rotated residual
      ↓
inverse Hadamard
      ↓
original shared_head.norm
      ├── draft LM Head
      └── next MTP hidden state
```

In the current implementations below, MTP consumes the main model's post-final-norm hidden state. During multi-step drafting, the post-final-norm MTP hidden state also feeds the next draft step. Compensating only the LM head weights therefore does not restore the coordinates of these hidden states. Both norm boundaries use plain `RMSNorm` and can be selected through `rotation_config` without changing model forward methods:

| Model | MTP final norm |
| --- | --- |
| GLM-5.2 / GLM-5.3 / GLM-5.3-Flash | `shared_head.norm` |
| DeepSeek-V3 / V3.1 / V3.2 | `shared_head.norm` |
| MiMo-V2 / MiMo-V2-Flash | `final_layernorm` |
| LongCat-Flash | `final_layernorm` |

End-to-end tests use GLM-5.3. Qwen3-Next and Qwen3.5 can use this approach with a `GemmaRMSNorm` adapter.

### Software design

Transforms implement the rotation, the registry owns its parameters, and adapters attach it to model modules.

1. **Configure Q and where it applies.** `rotations` defines the transforms, with parameters loaded from the checkpoint; `apply` selects target modules, direction, and application mode. Multiple targets can share a tag or use different Qs. This PR provides Composite Hadamard; other rotation types can implement the `RotationTransform` interface.
2. **Attach through norm adapters.** Retain the original RMSNorm instance, weights, checkpoint paths, and CustomOp dispatch without QuaRot-specific branches in model forward methods. The adapter applies rotation after residual addition, then calls the original norm backend; the fused AllReduce/RMSNorm entry point selects the unfused path for these adapters. The adapter supports plain `RMSNorm`.
3. **Own and share Q through the registry.** Each tag's parameters are registered and loaded once on the main model, then shared by reference with main-model and MTP adapters, avoiding duplicate parameters and checkpoint namespaces.

TileLang epilogues use vLLM's JIT warmup registry. Main-model preparation registers `(K, P, inverse, dtype)` from the configuration while keeping the token dimension dynamic. Matching main/MTP keys are deduplicated, and warmup and execution share the compiled-kernel cache.

The same structure can be extended with adapters for other modules, or explicit `Identity` insertion points in model code with corresponding adapters.

### Configuration example and loading

```json
{
  "rotation_config": {
    "rotations": {
      "0": {"type": "composite_hadamard", "hidden_size": 6144, "hadamard_k": 12}
    },
    "apply": [{
      "tag": 0,
      "targets": ["model.norm", "model.layers.78.shared_head.norm"],
      "mode": "pre",
      "inverse": true
    }]
  }
}
```

This configuration applies the same inverse rotation before the two main-model and MTP norms. Checkpoint tensors are `rotations.0.sign` (INT8 `[6144]`) and `rotations.0.hk` (FP32 `[12,12]`). The registry is installed before loading, and consumers bind after main/MTP loading.

**The checkpoint stores `hk = H_K.T`, already transposed and unnormalized.** Here `H_K` is the Hadamard base used during offline conversion. Using the same signs and base, the row-vector rotation matches official LLM Compressor's [`random-hadamard` implementation](https://github.com/vllm-project/compressed-tensors/blob/37e416a370560e3bedddf37ff5b14750da08ad53/src/compressed_tensors/transform/utils/hadamard.py):

$$
Q = D\frac{\mathrm{hk} \otimes H_P}{\sqrt{N}} = D\frac{H_K^T \otimes H_P}{\sqrt{N}}
$$

$$
X_{\mathrm{rot}} = XQ, \qquad X = X_{\mathrm{rot}} Q^T
$$

Here `D = diag(sign)`, `N = K * P`, and `H_P` is the unnormalized Sylvester Hadamard matrix, with `H_P.T = H_P`. The official generator returns an unnormalized matrix, which [`HadamardTransform`](https://github.com/vllm-project/compressed-tensors/blob/37e416a370560e3bedddf37ff5b14750da08ad53/src/compressed_tensors/transform/factory/hadamard.py) divides by `sqrt(N)`; this operator applies the same normalization directly. Load `hk` as stored; `inverse: true` applies `Q.T`, restoring `X_rot @ Q.T`. K-axis mixing uses `hk` in the forward direction and `hk.T` in the inverse direction.

With MTP off, unmatched targets produce a warning and are skipped; with MTP on, all targets are checked. Configuration details are in `docs/features/quantization/online_rotation.md`.

### Relationship to existing rotation implementations

- **Application point.** [Existing Linear transforms #22486](https://github.com/vllm-project/vllm/pull/22486) apply transforms at Linear inputs/outputs. This change restores coordinates after residual addition and before main-model and MTP RMSNorms, so the norm, head, and downstream hidden-state consumers share the restored representation.
- **Matrix representation and computation.** Store only `sign[N]` and `hk[K,K]` and apply Q through its `K * P` factorization: HadaCore computes `H_P`, and TileLang handles checkpoint K-axis mixing, scaling, and inverse signs. Both directions are supported without materializing the `N * N` matrix used by a dense transform.
- **Relation to the Eagle3 proposal.** [#36225](https://github.com/vllm-project/vllm/pull/36225) compensates draft fc/embedding weights during loading; this change applies online inverse rotation at the main/MTP norm boundaries. Related discussion: [RFC #36223](https://github.com/vllm-project/vllm/issues/36223).
