# [MRV2][DBO] Compose eager PCP partitions with microbatches

[Upstream PR](https://github.com/vllm-project/vllm/pull/64382) · state: open · merged: False

## Original PR description

## Overview

Initial eager PCP × DP microbatch composition for MRV2, tracking #64351. **Draft: static review, CPU unit tests and single-GPU component tests only. No model was loaded, and distributed model correctness is not qualified.**

## Claims

- Partition with the existing PCP manager, split each rank's local rows at the existing DBO midpoint, merge DBO outputs before the PCP restore, and keep the original sampling batch.
- Split only when the first microbatch holds a causal prefix of every request across all PCP ranks, reusing the existing DP handshake. DP ranks with different PCP-local token counts keep the unsplit path, so DP padding cannot move the checked midpoint.
- Slice PCP request metadata and rank-major gathered slot mappings; size the runner by the PCP input-buffer request capacity.
- Allow PCP+DBO only for `--enable-dbo`, NIXL EP with DP>1 and expert parallelism, TP=1, DCP=1, no speculative decoding, synchronous scheduling and no CUDA graphs. Attention backends that do not support PCP are already rejected at backend selection.

## Details

Production change: **+114/-8**. There is no new collective, runner, KV allocator or publication protocol. Decode-only batches and dummy/profile runs keep the ordinary unsplit PCP path. The rendered DBO docs describe the scope.

Duplicate checks searched #64351 and PCP/DBO keywords and read the issue comments. No open PR for this composition was found. #61464 addresses speculative decoding/DCP; #52863 provides PCP KV publication and barrier lanes; neither composes PCP partitioning with the MRV2 ubatch runner as here.

Before readiness: human review of every changed line, real PCP2 × DP2 outputs/logprobs and collective ordering, request reuse/imbalance, and performance/memory qualification. AI assistance was used for implementation, review and testing.
