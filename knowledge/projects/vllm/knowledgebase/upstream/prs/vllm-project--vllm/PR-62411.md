# [KV Connector] Windowed hidden-state export for ExampleHiddenStatesConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/62411) · state: open · merged: False

## Original PR description

## Purpose

Adds experimental windowed hidden-state export to `ExampleHiddenStatesConnector`. A request can specify a response window (`start`, `end`, `min_rows`, layer layout), and only the hidden-state rows inside that window are written to the cache and exported through the existing file connector lifecycle.

This is an alternative implementation of windowed hidden-state capture, intended to be compared with the runner-level approach in #57736. The trade-offs are:

| | This PR (connector-based) | #57736 (runner-level capture) |
| --- | --- | --- |
| Coexists with a real speculative drafter | No, it uses `method=extract_hidden_states` | Yes |
| Core scheduler/engine changes | None, changes are in the connector, plus small runner/config hooks | Scheduler, request, engine protocol and output processor |
| GPU memory | Full-sequence cache is still allocated in the KV pool, only writes and export are windowed | No persistent allocation |
| Export | File via the existing connector lifecycle | In-process result returned to the caller |

It is a good fit for prefill-style feature export, where the connector already is the right abstraction. It does not cover rollouts that run a real drafter.

## Changes

- `hidden_state_window.py`: window parsing and validation. Row coordinates follow `abs = P - 1 + r`, so row `r` predicts response token `r`.
- `hidden_state_cache.py`: masked store so that rows outside the window are not written to the cache.
- `ExampleHiddenStatesConnector`:
  - exports only the rows selected by the window,
  - writes layout metadata (layer ids, window bounds, whether the final layer is included),
  - stages D2H copies in bounded pinned memory, with a pageable fallback for large windows,
  - cleans up and reports errors for cancelled or failed exports,
  - tracks completion correctly (see below).
- Config validation for the supported setup: V1 model runner, PP=1, no async scheduling, prefix caching disabled, CUDA.
- Docs, unit tests, a GPU integration test and a benchmark script.

### Completion tracking

When a request finishes with fewer rows than the window needs, the scheduler releases its blocks immediately, but the worker still receives the request ID in `finished_req_ids`. The connector used to report such an ID as a completed export when no copy event existed. The scheduler could then receive a request ID that was no longer pending and hit an assertion failure.

A finished request ID is now tracked only when a new `PendingSave` is submitted or an asynchronous copy event already exists. Other IDs are ignored. A regression test covers this case.

## Test Result

Run on an NVIDIA RTX 3080 Ti:

- Unit tests above: 57 passed.
- GPU integration tests for graph replay masking and asynchronous export staging: 8 passed, 4 deselected.

## Limitations

- Full-sequence cache allocation is retained.
- It cannot run together with a real speculative drafter.
- Only the V1 model runner is supported, and async scheduling and prefix caching must be off.
- No end-to-end model evaluation or throughput comparison against #57736 has been run yet.
