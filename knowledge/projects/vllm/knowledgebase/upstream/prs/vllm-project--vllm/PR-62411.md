# [KV Connector] Windowed hidden-state export for ExampleHiddenStatesConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/62411) · state: open · merged: False

## Original PR description

## Purpose

Adds experimental windowed hidden-state export to `ExampleHiddenStatesConnector`. A request can specify a response window (`start`, `end`, `min_rows`, layer layout), and only the hidden-state rows inside that window are written to the cache and exported through the existing file connector lifecycle.

This is an alternative implementation of windowed hidden-state capture, intended to be compared with the runner-level approach in #57736. The trade-offs are:

| | This PR (connector-based) | #57736 (runner-level capture) |
| --- | --- | --- |
| Coexists with a real speculative drafter | No, it uses `method=extract_hidden_states` | Yes |
| Core scheduler/engine changes | None, changes are in the connector, plus small runner/config hooks | Scheduler, request, engine protocol and output processor |
| GPU memory | Full-sequence cache is still allocated in the KV pool, only writes and export are windowed | No persistent allocation |
| Export | File via the existing connector lifecycle | In-process result returned to the caller |

It is a good fit for prefill-style feature export, where the connector already is the right abstraction. It does not cover rollouts that run a real drafter.

## Changes

- `hidden_state_window.py`: window parsing and validation. Row coordinates follow `abs = P - 1 + r`, so row `r` predicts response token `r`.
- `hidden_state_cache.py`: masked store so that rows outside the window are not written to the cache.
- `ExampleHiddenStatesConnector`:
  - exports only the rows selected by the window,
  - writes layout metadata (layer ids, window bounds, whether the final layer is included),
  - stages D2H copies in bounded pinned memory, with a pageable fallback for large windows,
  - cleans up and reports errors for cancelled or failed exports,
  - tracks completion correctly (see below).
- Config validation for the supported setup: V1 model runner, PP=1, no async scheduling, prefix caching disabled, CUDA.
- Docs, unit tests, a GPU integration test and a benchmark script.

### Completion tracking

When a request finishes with fewer rows than the window needs, the scheduler releases its blocks immediately, but the worker still receives the request ID in `finished_req_ids`. The connector used to report such an ID as a completed export when no copy event existed. The scheduler could then receive a request ID that was no longer pending and hit an assertion failure.

A finished request ID is now tracked only when a new `PendingSave` is submitted or an asynchronous copy event already exists. Other IDs are ignored. A regression test covers this case.

## Limitations

- Full-sequence cache allocation is retained.
- It cannot run together with a real speculative drafter.
- Only the V1 model runner is supported, and async scheduling and prefix caching must be off.
- No end-to-end model evaluation or throughput comparison against #57736 has been run yet.

## Review of c7f20141f58e

I reviewed this PR in detail, with several independent review passes that cross-checked each other. I traced every item below through the code at `c7f20141f58e`, and reproduced the ones marked as such. Line numbers refer to the PR head. `EHSC` means `vllm/distributed/kv_transfer/kv_connector/v1/example_hidden_states_connector.py` and `HSW` means `.../hidden_state_window.py`.

### Blocking

**1. A single request can crash EngineCore: int64 overflow in `request_finished`** (`HSW:22-27`, `EHSC:856`)

`from_params` only checks `type(end) is int` and `start < end`. A request with `{"hidden_state_window": {"start": 0, "end": 2**63}}` passes `validate_window_request`, because `absolute_bounds` is plain Python arithmetic. msgpack carries any uint64, so the value reaches the engine. `block_window_ranges` and `accepted_bounds` both clamp, so the request decodes normally. When it finishes, `request_finished` runs `torch.tensor([window.start, window.end])`, which raises `RuntimeError: Overflow when unpacking long` (reproduced with torch 2.8). This happens inside `Scheduler.update_from_output -> _free_request -> _connector_finished`, where nothing catches it, so EngineCore dies along with every in-flight request. Suggested fix: bound `end`, for example `end <= max_model_len`, in `from_params`/`validate_window_request`, and store the window bounds as plain metadata rather than as an int64 tensor.

**2. Scheduler-side hooks raise inside `schedule()`, and the Rust frontend skips the Python validation** (`EHSC:702-721`, `EHSC:775-780`)

`get_num_new_matched_tokens` raises `ValueError` for unsupported or malformed windows. It is called from `Scheduler.schedule()` without a guard. The Rust frontend (`rust/src/server/src/utils.rs`, `merge_kv_transfer_params`) puts `kv_transfer_params` straight into `extra_args`, so `input_processor.validate_window_request` never runs on that path. The simplest reproduction needs no special values: send any well-formed `hidden_state_window` to a server that uses `ExampleHiddenStatesConnector` without `enable_window_capture`. That raises "Set enable_window_capture=True" in the scheduler and kills EngineCore. `start=-1` does the same. Scheduler-side connector hooks should reject or skip the request, for example by returning a skip reason, and should never raise.

**3. Regression for existing (non-window) users: every aborted request leaks a `LOCK_EX` fd, a `.lock` file and a dict entry** (`EHSC:375-377`, `411-419`, `828-834`, `926-929`, `940-944`)

With `enable_window_capture=False`, the chain is:
1. `wait_for_save` still opens `<file>.lock` and holds `LOCK_EX` for every new request.
2. On abort or error, `request_finished` now returns `(False, None)` and adds the ID to `_cancelled_req_ids`.
3. The only consumer of `cancelled_req_ids` is `start_load_kv`, which returns early when `not self._window_enabled`, so the set is dropped.
4. The new eligibility filter in `get_finished` excludes the ID, so the old "Clean up any leftover lock fds (e.g. aborted requests ...)" branch can no longer be reached.

The result is one leaked fd, one `.lock` file and one `_worker_filenames` entry per scheduled request that ends ABORTED or ERROR, which is the normal client-disconnect case. This eventually leads to EMFILE in `wait_for_save`. Before this PR, aborted requests went through the delayed-save path and the fd was always closed. Handling `cancelled_req_ids` outside the window gate would fix it. A non-window abort lifecycle test should be added; it would have caught this.

### Should fix

**4. One failed write fails the next, unrelated export** (`EHSC:336-339`)

`_reserve_export` calls `future.result()` on completed futures from earlier exports. If request A's write failed (ENOSPC, EIO), the exception is re-raised inside request B's `_submit_async_write`. The handler in `get_finished` then closes B's lock, writes `B.safetensors.error` and releases B's blocks. B's export is lost even though nothing was wrong with it, and A's failure has already been logged in `_on_write_done`. Waiting on the future without re-raising would fix it.

**5. On a submission failure, the lock is released before `.error` is written** (`EHSC:909-916`)

The handler calls `os.close(fd)`, which releases `LOCK_EX`, and only then creates `.error`. A reader already blocked on `LOCK_SH` can wake up, find no `.error`, and call `load_file`. It then gets `FileNotFoundError`, or, with `allow_custom_save_path` and a reused path, silently loads the previous request's file. `_write_tensors` uses the correct order (write `.error` first, close in `finally`), and this path should match it.

**6. The engine loop blocks on other requests' disk writes** (`EHSC:336-344`, `563`, `579-598`)

The export queue holds the *write* futures, and the staging buffer is only released after `save_file` and `os.replace`. Once the budget is reached, `get_finished`, which runs inside `execute_model`, blocks every request on storage latency. The large-window path also calls `copy_stream.synchronize()` once per chunk and allocates a pageable buffer of `num_tokens x row_bytes`, bounded only by `max_tokens`. The docs only mention waits caused by a request's own staging. Consider releasing the budget on `copy_done`, or moving staging onto the writer thread, and adding an operator-side cap on window length.

**7. The new CPU unit test fails at collection in the CI image** (`tests/v1/kv_connector/unit/test_hidden_state_window.py:12-17`)

`runpy.run_path(Path(__file__).parents[4] / "vllm/...")` assumes the source tree sits next to `tests/`. The test image moves it (`docker/Dockerfile`: `RUN mv vllm src/vllm`), so collection of `v1/kv_connector/unit` fails. The module has no heavy dependencies, so a normal import works.

**8. Behaviour changes for existing `extract_hidden_states` users that are not mentioned in the PR**

- `_input_fits_in_drafter` now always returns True for the extractor (`gpu_model_runner.py:4491-4493`). This is not gated on window mode. It probably fixes stale rows at the `max_model_len` boundary, but it changes legacy `include_output_tokens` output and has no legacy test.
- `extraction_layout` now runs for every config (model, proposer and connector). Duplicate, out-of-range or non-int `eagle_aux_hidden_state_layer_ids` used to load and now fail at startup.
- Aborted and errored requests are no longer exported at all.
- Writes now go through `.incomplete` plus `os.replace`, `.error` side files are added, and exceptions from `_submit_async_write` are swallowed where they used to propagate.

### Tests and docs

- Only `test_finished_sending_ignores_requests_without_pending_export` fails on the old code. `test_finished_sending_waits_for_copy_event_before_releasing_blocks` also passes on the old code.
- `test_failed_write_removes_partial_file_and_releases_lock` never checks that `.error` was written. Its `not failed.safetensors.exists()` assertion is trivially true, because the mocked `save_file` writes to the `.incomplete` path.
- `test_async_export_and_large_window_staging_preserve_values` synchronizes every event before `fill_(-1)`, so it never tests a buffer being reused before its copy completes.
- No tests cover items 1-5, preemption/resume range recomputation, mixed window and non-window requests in one engine, or TP>1.
- The e2e tolerance `atol=rtol=0.02` is about the same size as layer-0 embedding values (`initializer_range=0.02`), so aux id 0 rows are barely checked numerically.
- `ExtractHiddenStatesModel` is not `@support_torch_compile` and the store runs eagerly, so the `enforce_eager=False` runs never replay the masked store from a CUDA graph. The "stable buffers for graph replay" claim is only covered by the isolated kernel test. For the same reason, the `KVTransferConfig.compute_hash` factor has no effect.
- `extract_hidden_states.md:126` still says chunked prefill must be disabled, while the new doc example and `test_window.py` use `enable_chunked_prefill=True`.
- "Cancellation ... close/remove unused locks" is only true in window mode (see item 3). The PR body says cancelled exports "report errors", but no `.error` is written for them.
- `final_is_normalized = layout != "auxiliary"` is written for every architecture, but it has only been checked for Llama/Qwen.

### Nits

- The benchmark's `--mode pr57736` imports `vllm.v1.hidden_state_capture` and passes a `hidden_state_capture=` kwarg; neither exists in this tree. The metrics plumbing (`_capture_metrics`, the timing return value of `_write_tensors`, `get_window_capture_metrics`) is used only by that benchmark.
- `enable_window_capture` is read for truthiness, so the string `"false"` enables it. Validate it as a bool, the same way `max_inflight_export_bytes` is validated.
- `layout="final"` still requires non-empty `eagle_aux_hidden_state_layer_ids` (`extraction_layout`, and the proposer). The runner also requires `aux_hidden_states` before it branches on layout, so final-only users must configure dummy aux layers and pay for outputs that are thrown away.
- The init-time row-size check uses `model_config.dtype`, while the runtime check uses the actual cache element size. These can disagree when the cache dtype differs from the model dtype.
- `HEADS` in `_store_window` is unused.
- `start_load_kv` does a pageable H2D `torch.tensor(..., device=cuda)` every step.
- `_on_write_done` updates `_capture_metrics` from writer threads without a lock.
- `from vllm.v1.request import RequestStatus` runs inside `request_finished` on every call.
- `response_positions` duplicates `hidden_positions - (P - 1)`.
- `.buildkite/test_areas/misc.yaml` adds `gpu_model_runner.py` as a trigger for the 20-minute H200 job but not `input_processor.py`, `config/kv_transfer.py` or `config/speculative.py`.

Checked and found correct: the row/target coordinate math (`abs = P-1+r`, clamping at `P-1+L`, which excludes the unfed last token and rejected draft rows), `block_window_ranges` clamping, null-block skipping, `first=0` on resume, `pending_saves` and `finished_req_ids` arriving in the same `schedule()` output (so the eligibility filter cannot drop a delayed request), copy-stream ordering before block release, and the kernel's masking of `slot=-1`, padding and column tails.
