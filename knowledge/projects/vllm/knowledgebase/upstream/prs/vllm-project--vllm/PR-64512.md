# [Rust Frontend] Export UMBP connector transfer metrics like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/64512) · state: closed · merged: True

## Original PR description

## Overview

Export the UMBP store connector's `vllm:umbp_transfer_*` counters from the Rust frontend. vllm-project/vllm#61793 registered `UMBPStoreConnector` in the connector factory, so deployments can now produce these stats, but the Rust frontend decodes the payload into an unknown-connector map and drops it.

## Claims

- `vllm:umbp_transfer_submitted_total`, `vllm:umbp_transfer_completed_total`, `vllm:umbp_transfer_failed_total` and `vllm:umbp_transfer_bytes_total` are exported with Python's names, help text and labels (`model_name`, `engine`, `operation`), for a bare UMBP connector and for a `UMBPStoreConnector` child of a `MultiConnector`.
- As in Python, an operation's series appears the first time the connector reports it; the counters add up across stats intervals.

## Details

Python's `UMBPStoreConnectorStats` (`vllm/distributed/kv_transfer/kv_connector/v1/umbp/stats.py`, vllm-project/vllm#61791) sends `{operation: {"submitted", "completed", "failed", "num_bytes"}}` with operations `load` and `store`, and `UMBPStorePromMetrics` exports the four counters. In Rust, `KvConnectorStats` is an untagged enum tried in order; a UMBP payload failed every typed variant and landed in `Multi`, where every key went to the opaque `other` map.

- `vllm-engine-core-client` `protocol/stats.rs`: `UmbpStats` (a closed `UmbpOperation` enum to per-operation counts), `KvConnectorStats::Umbp` ahead of `Multi`, and `MultiConnectorStats::umbp` under `UMBPStoreConnector`.
- `vllm-metrics` `scheduler.rs`: the four counter families.
- `vllm-engine-core-client` `metrics.rs`: `record_umbp_stats`, for both payload shapes.

**Layering.** `SchedulerStatsRecorder` in `vllm-engine-core-client` already owns decoding and recording connector stats for NIXL and Mooncake, so the UMBP decode and recorder sit beside them, and the families sit in `vllm-metrics` with every other Prometheus family. This follows the Mooncake store precedent, including lazily created per-operation series.

**Relation to vllm-project/vllm#58563** (connector-described metrics, open): it exports metrics for connectors that ship a descriptor and keeps the dedicated NIXL and Mooncake paths; it does not touch UMBP. If UMBP later adopts a descriptor, this dedicated path can go.

Not a duplicate: no open PR touches UMBP metrics in the Rust frontend (searched open PRs for "UMBP metrics" and "umbp_transfer"). AI assistance (Claude Code) was used to prepare this change; the human submitter reviewed every changed line.
