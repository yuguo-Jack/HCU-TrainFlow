# [Bugfix][Benchmark] Use API key for automatic model discovery

[Upstream PR](https://github.com/vllm-project/vllm/pull/63714) · state: open · merged: False

## Original PR description



## Overview

Fix `vllm bench serve` failing with HTTP 401 during automatic model discovery when the server requires an API key and the client sets `OPENAI_API_KEY`. Reuse the existing request-header helper for the `/v1/models` lookup.

## Claims

- Environment credentials authenticate automatic model discovery as well as generation requests.
- Explicit `--header` values retain precedence, and unrelated headers are preserved.
- Requests without credentials still fail against an authenticated server.

## Details

Generation requests already obtain `OPENAI_API_KEY` through `_get_headers()`, introduced by [#33488](https://github.com/vllm-project/vllm/pull/33488). Automatic discovery previously received only explicitly supplied `--header` values, so it failed before generation when the key was supplied through the environment.

Duplicate-work check (2026-10-26 17:46 Asia/Shanghai): no directly matching open PR or issue was found in searches for `get_first_model_from_server`, `OPENAI_API_KEY` with benchmark, model discovery with auth, and benchmark HTTP 401, including inspection of the latest open PRs. The merged helper work in #33488 did not cover model discovery.

Merge the existing default headers with the explicit headers in `get_first_model_from_server`, with explicit values taking precedence. This adds two production lines and no dependency or public interface. The change runs during model discovery and does not alter inference execution. Document the credential behavior in the benchmark CLI guide.
