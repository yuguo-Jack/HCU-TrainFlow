# [Perf][GDN] Slice contiguous spec/non-spec token blocks in mixed GDN batches

[Upstream PR](https://github.com/vllm-project/vllm/pull/63193) · state: open · merged: False

## Original PR description



## Overview

In mixed batches (spec decodes plus prefills), the Qwen GDN layer gathers spec and non-spec tokens with `index_select` and scatters outputs back with `index_copy_`. When the two groups are contiguous, as Model Runner V2 orders them, slices do the same job without copies.

## Claims

- The GDN metadata builder records `spec_token_start` / `non_spec_token_start` when the spec and non-spec blocks are contiguous; the layer then slices inputs and writes outputs in place instead of gathering and scattering.
- The int64 prefill state indices and the initial-state mask are built once per step instead of in every layer.
- Numerics unchanged; no new option.

## Validation

Not run yet. Planned:

```bash
pytest -v tests/v1/attention/test_gdn_metadata_builder.py tests/kernels/mamba/test_gdn_forward_core_split.py tests/kernels/mamba/test_gdn_fused_mtp.py tests/models/kimi_k3/test_kda_metadata.py
```

plus a GSM8K check and a serving benchmark on a Qwen3.5/3.6 MTP model.

## Details

Builds on the pure spec-decode slicing already in main; this extends it to mixed batches. Non-contiguous layouts keep the existing gather path. A test checks the slice path against the gather path on a mixed batch.
