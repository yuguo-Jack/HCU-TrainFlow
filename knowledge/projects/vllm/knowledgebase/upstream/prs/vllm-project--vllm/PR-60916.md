# [Rust Frontend] return_top_k_logprobs and return_token_logprobs on raw generate

[Upstream PR](https://github.com/vllm-project/vllm/pull/60916) · state: open · merged: False

## Original PR description

## Overview

Rust frontend support for `return_top_k_logprobs` on `/inference/v1/generate`, matching the Python frontend (#60915). Top-k output logprobs come back as one packed base64 block instead of per-token JSON objects. Part of RFC #57479.

## Claims

- **`return_top_k_logprobs`.** With `sampling_params.logprobs = k >= 1`, `choices[0].logprobs` is
  `{"content": null, "top_k": {"num_positions": N, "k": k, "token_ids": <b64 LE int32[N*k]>, "logprobs": <b64 LE f32[N*k]>}}`,
  with engine slots 1..=k in engine order and the raw engine logprob bits (no clamp). This is the same wire format as the Python PR.
- **Errors.**
  - `stream=true` returns 400, and so does `logprobs` absent, 0 or −1. The messages match the Python PR.
  - Malformed engine output fails only its own request with a 500: a missing position, rows narrower than k+1, or ids beyond int32.
- **Default unchanged.** Responses without the flag are unchanged.

## Validation

```bash
cd rust
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test -p vllm-server -p vllm-llm -p vllm-engine-core-client -p vllm-text --all-features --locked
```
Result: fmt and clippy are clean. 472 server tests pass, plus 266 in the other three crates (1 ignored), with 0 failures.

New tests cover:
- the exact top-k body bytes;
- top-k decoded against the default render of the same rows;
- a top-k response through the production serve loop, with an exact `Content-Length`;
- a round trip that keeps engine rows and raw f32 bits, with padded rows truncated to k;
- base64 segments that are bounded and concatenate to a one-shot encoding;
- malformed outputs failing only their request (and only top-k ids checked against int32);
- the 400 cases.

**Real GPU** (GB200, Qwen3-0.6B, `--data-parallel-size 2`, `VLLM_USE_RUST_FRONTEND=1`). Main's binary (44f0ddfd7b) and this branch's binary (767d23f615) ran against the same Python engine tree. The driver script is not part of this PR.
- **Default parity:** for 4 prompts × k ∈ {0, 1, 8, 128} (greedy, `ignore_eos`, 256 tokens), all 16 default response bodies are byte-identical to main's, with the `created` timestamp blanked.
- **Packed parity:** with `return_top_k_logprobs`, all 12 k ≥ 1 requests return 200, and the decoded `top_k` matches the default render of the same request on the same server. k = 0 returns 400.
- **Abort stress:** 32 concurrent non-streaming requests at top-128 (2,048 input tokens), with `POST /pause?mode=abort` 45 s after submission. The client only receives bytes while the clock runs and parses afterwards. Server RSS is sampled from the process tree. Runs were in A/B/B/A order. All 32 responses were valid in every run, and each run left about 400k aborted positions.

| | main, default JSON | this PR, `return_top_k_logprobs` |
|---|---|---|
| `/pause?mode=abort` returns | 0.59 / 0.28 s | 0.27 / 0.36 s |
| abort → all bodies parsed | 1.26 / 0.96 s | 0.37 / 0.44 s |
| response bytes per run | 2.60 GB | 0.56 / 0.54 GB |
| peak RSS, largest server process | 8.2 / 9.1 GiB | 4.0 / 3.9 GiB |
| peak RSS, whole server process tree | 21.6 / 22.4 GiB | 14.1 / 13.8 GiB |

At the full RL shape the gap is larger. On the earlier compact-format prototype, an abort with 245,760 output tokens at top-128 produced about 2.2 GB per response in per-token form and 337 MB as the packed block, and abort-to-parsed time went from about 21 s to about 1.8 s on DP8 with 32 requests.

## Details

- **Encoding.** Each engine step's logprobs are base64-encoded as they arrive, into segments of at most 1 MiB. They're taken off the output before the unchanged `collect_output`.
- **Body.** The response is serialized by serde as a `GenerateResponse`, with a random placeholder string for each of the two encoded arrays. The body streams the encoded segments in place of the placeholders, without copying them into one buffer, with an explicit `Content-Length`. Every other field comes from serde unchanged.
- **Types.** `GenerateLogProbs` gains an optional `top_k` field (omitted when unset), mirroring the Python `GenerateLogProbs` and `PackedTopK`.

**Not a duplicate.** No open PR adds this flag to the Rust frontend (#60789 replays logprobs through the AuxOutput connector, not the HTTP response) (`gh pr list --state open --search "57479 in:body"`, `"rust top_k logprobs"`).
