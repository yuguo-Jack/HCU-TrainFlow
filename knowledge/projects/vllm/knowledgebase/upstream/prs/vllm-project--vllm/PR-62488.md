# [Perf] Use a compact key-padding mask for audio encoders

[Upstream PR](https://github.com/vllm-project/vllm/pull/62488) · state: open · merged: False

## Original PR description

## Overview

Qwen2-Audio and AudioFlamingo3 no longer materialize a dense `[B, 1, S, S]` key-padding mask. Fixes #62350.

## Claims

- `None` and `sdpa` (including one leading `paged|`) return bool `[B, 1, 1, S]`.
- Flash attention names, including the kernels-community names after one `paged|` strip, return long `[B, S]` with 1 on visible keys.
- Eager returns float `[B, 1, 1, S]` with 0 on visible keys and `-inf` on pad keys. An all-pad row is `-inf`.
- `paged|paged|sdpa`, `flex_attention`, and any other name raise.
- A flash row with no visible keys raises.
- No successful return has both of the last two dimensions equal to `S`.
- Length math is unchanged: Qwen2 still uses `(max_mel_seq_len - 2) // 2 + 1`, and AudioFlamingo3 still uses `(max_mel_seq_len - 1) // 2 + 1`.

## Validation

CPU tests of `broadcast_audio_key_padding_mask` passed, including SDPA of the compact bool mask against the old square `0/-inf` mask (max abs diff 0 on kept query rows).

`tests/models/multimodal/test_audio_encoder_masks.py` imports vLLM. This machine has torch 2.5.1 and cannot import current main, so pytest was not collected here. The helper was loaded directly and the same assertions were run. No Qwen2-Audio or AudioFlamingo3 GPU forward was run. MiniCPM-O still builds the dense mask; it is outside this issue.

## Details

Both encoders expanded a `[B, S]` padding mask into `[B, 1, S, S]` and wrote `-inf` into the pad keys. SDPA already broadcasts a `[B, 1, 1, S]` key mask, and the flash paths take a `[B, S]` mask. One helper serves both call sites so the dispatch stays in one place. Qwen2-Audio and AudioFlamingo3 do not share an encoder class.

The default implementation is `sdpa`, read from `audio_tower.config._attn_implementation`. The flash all-pad check is a host read and runs only on that error path.

AI assistance was used (Grok). This is a first-cut draft. A GPU forward of both models is still required before this leaves draft. #62469 is a separate patch and is not updated here.
