# [Metrics] Add vllm:kv_cache_evictions counter

[Upstream PR](https://github.com/vllm-project/vllm/pull/64035) · state: open · merged: False

## Original PR description

## Overview

Add a `vllm:kv_cache_evictions` counter (scraped as `vllm:kv_cache_evictions_total`) that counts every cached prefix block evicted from the local KV cache to make room for new blocks.

## Claims

- New per-engine Prometheus counter `vllm:kv_cache_evictions`, on by default and exact (not sampled).
- O(1) overhead: one integer increment in `BlockPool.get_new_blocks`, drained once per stats interval.
- Only capacity evictions are counted. Invalidations (`KVCacheManager.evict_blocks` after a failed KV load, Mamba checkpoint hash drops) are excluded.

## Validation

```bash
pytest tests/v1/core/test_prefix_caching.py::test_evicted_blocks_stats
pytest tests/entrypoints/serve/instrumentator/test_metrics.py
```

- `test_evicted_blocks_stats` (new) checks that:
  - only cached blocks reused as new blocks are counted (a never-cached free block is not),
  - `evict_blocks` invalidations are not counted,
  - the count is reset after each `make_prefix_cache_stats` drain.
- `test_metrics.py`: `vllm:kv_cache_evictions` added to `EXPECTED_METRICS_V1`, so its presence on `/metrics` is checked.

Unit tests (CPU, `VLLM_TARGET_DEVICE=cpu`): `tests/v1/core/test_prefix_caching.py`: 214 passed (includes new `test_evicted_blocks_stats`).
E2E: vLLM v0.32.0 + this patch, Qwen2.5-7B-Instruct, P/D (1 prefill + 1 decode, TPU v5e). Each engine's KV cache holds 13,952 tokens (109 blocks of 128). Load: rounds of shared-prefix requests, then 160 unique ~560-word prompts at concurrency 64, then the shared prefixes again.
| Engine | `kv_cache_evictions_total` (before → after) | `prefix_cache_hits_total` | `num_preemptions_total` |
|---|---|---|---|
| prefill | 0 → 2349 | 0 → 132,480 | 0 → 0 |
| decode  | 0 → 3473 | 0 → 101,120 | 0 → 73 |

Evictions start only once `kv_cache_usage_perc` reaches ~1.0.

## Details

**Motivation:** `vllm:kv_cache_usage_perc` counts cached prefix blocks as free, so a high prefix-cache hit rate can hide a cache that is constantly overwriting reusable blocks. Nothing currently shows how often that happens. The `--kv-cache-metrics` residency histograms are opt-in and sampled, so they can't give an exact eviction rate.

**Implementation:**
- `BlockPool.num_evicted_blocks` is incremented when `_maybe_evict_cached_block` actually evicts a block inside `get_new_blocks`.
- `KVCacheManager.make_prefix_cache_stats` moves the count into a new `PrefixCacheStats.evicted_blocks` field and resets it. This reuses the existing scheduler-stats path to the frontend, so no new plumbing is added.
- `PrometheusStatLogger` registers the counter per engine and increments it from `prefix_cache_stats`.

**Limitations:**
- Only the local GPU prefix cache is covered. Connector or offload tiers are not.
- The unit is blocks, not tokens. Multiply by `block_size` to get tokens.
- The count is only collected when stat logging is enabled (`log_stats`), the same as the existing prefix-cache counters.
