# Update vendored LMCache connector for current IPCCacheServerKey API

[Upstream PR](https://github.com/vllm-project/vllm/pull/48479) · state: closed · merged: False

## Original PR description

the vendored fallback lmcache connector (`vllm/distributed/kv_transfer/kv_connector/v1/lmcache_integration/multi_process_adapter.py`) was stale relative to the current `lmcache` package api:

1. `IPCCacheEngineKey` -> `IPCCacheServerKey`: the key class was renamed in the lmcache codebase, the vendored connector still imported the old name, which would cause an ImportError if the fallback path were ever reached.
2. `tp_size` field -> `use_mla` field: `IPCCacheServerKey` no longer has a `tp_size` constructor argument. it now has `use_mla: bool` (backward-compatible msgspec field, defaults `False`). both `_create_key` methods updated to pass `use_mla=self.parallel_strategy.use_mla`.
3. `chunk_hash` field removed: `IPCCacheServerKey` no longer supports hash-mode keys. the `_create_hash_key` methods now raise `NotImplementedError` with a clear message directing users to the token-based `_create_key` path or to installing the `lmcache` package (which has the current, maintained adapter).

why: this vendored connector is a fallback, only used when `from lmcache.integration.vllm.vllm_multi_process_adapter import ...` fails (the lmcache package isn't installed). in the normal case the lmcache-tree adapter is used, which is kept in sync with the api. but if the fallback is ever reached (partial install, version mismatch), the stale imports would cause confusing ImportError/TypeError crashes. this pr makes the fallback at least importable and gives clear errors for the removed hash-mode api.

companion pr: [LMCache #4082](https://github.com/LMCache/LMCache/pull/4082), which enables pipeline parallelism for mla models (kimi k2, glm-4.6) in multi-server mp mode, adds the explicit `use_mla` flag to `IPCCacheServerKey` (replacing the `tp > world_size` heuristic), adds rocm platform support (pin memory, ipc wrapper, device spec), and fixes the abort-leak (lookup locks freed on request cancel).

testing: the file compiles cleanly. the vendored connector isn't directly testable without a full vllm+lmcache environment, but the changes are straightforward api renames.
