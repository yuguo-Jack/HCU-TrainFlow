# [Bugfix][Model] Preserve MiDashengLM's untied decoder default

[Upstream PR](https://github.com/vllm-project/vllm/pull/61737) · state: open · merged: False

## Original PR description

## Overview

Restore MiDashengLM's historical untied decoder default when `text_config` omits `tie_word_embeddings`, while preserving explicit settings. Fixes #61469.

## Claims

- Load the checkpoint's independent output head instead of tying it to the input embedding.
- Preserve explicit `tie_word_embeddings=True` and `False` configurations.

## Validation

Independently reproduced the public report on one A100 40GB, BF16, TP=1, eager mode. Both vLLM arms used the official `77154ca61` cu129 nightly, Transformers 5.19.0, PyTorch 2.13.0+cu129, and model revision `64d40b767071414730dc9db21f1f97bcd1e4cc9c`. The config shim, model, Qwen2 decoder, and weight loader are byte-identical between that wheel's source and this PR's `429a3da6` base. The HF reference used the same checkpoint with Transformers 4.52.4.

| Check | Original vLLM | Patched vLLM | HF reference |
|---|---|---|---|
| Reported text prompt | Empty; 16 × token 151872 | `Four`, then stop | `Four`, then stop |
| 100-utterance WER | 100% (2346/2346) | 1.49% (35/2346) | 1.53% (36/2346) |
| Outputs containing undefined tokenizer IDs | 100/100 | 0/100 | 0/100 |
| Empty outputs | 70/100 | 0/100 | 0/100 |
| Outputs reaching the 128-token limit | 100/100 | 0/100 | 0/100 |

The audio set is the lexicographically first 100 utterance IDs from LibriSpeech test-clean, fixed before inference. All arms used identical audio hashes and prompt token IDs. This is a bounded regression evaluation, not the full benchmark. Patched vLLM and HF had 95/100 identical token sequences. Re-running the other five cases serially with stepwise top-10 gave one exact sequence and four passing the project's first-divergence mutual-top-k criterion. This does not establish bitwise equivalence or a quality improvement from the one-word WER difference.

The live weight probe found aliased embedding/head storage and a mismatching head checkpoint sample before the fix. Afterward, storage was independent and both samples matched their checkpoint keys. Model-loading memory increased from 14.52 to 15.53 GiB, consistent with retaining the independent head.

## Details

The checkpoint omits `tie_word_embeddings`. Transformers moved the Qwen2.5-Omni untied default from the text config to its outer thinker config in huggingface/transformers#41541. MiDashengLM directly embeds the text config and consequently inherits the tied default. vLLM's Qwen2 decoder then aliases its head to the input embedding, and the loader skips the independent output-head tensor.

The fix supplies the historical default in the MiDashengLM config shim only. No shared Qwen2, RoPE, or loader behavior changes.

Rechecked #61469's comments/timeline, the complete open-PR title inventory, and related open/closed searches before submission. #61470 adds tower/connector LoRA and explicitly leaves this base-model issue unresolved; it does not contain this configuration fix.

AI assistance was used for investigation, implementation, and validation. This work follows a public issue and an independent reproduction; it is not presented as the submitter's production experience.
