# [Bugfix][Quantization] Repair misaligned Humming two-CTA linear configs

[Upstream PR](https://github.com/vllm-project/vllm/pull/64257) · state: closed · merged: False

## Original PR description



## Overview

Work around misaligned Humming two-CTA linear configurations that abort model initialization, as seen for Qwen3-30B-A3B-MXFP4A16 with FP8 activations in [Buildkite build 97701](https://buildkite.com/vllm/ci/builds/97701#01a17e8b-049d-4a48-8049-7dc285e7b02d). The upstream fix is [vllm-project/humming#178](https://github.com/vllm-project/humming/pull/178).

## Claims

- Detect two-CTA configurations whose block M is not divisible by 16, without restricting the workaround to a Humming package version.
- Ask Humming to reselect a configuration for aligned tile capacity, so its resource checks and pipeline selection run again. Preserve the original M intervals and already-valid configurations.
- Prepare and serialize the corrected table during weight initialization for both Humming linear integration paths; forward only consumes the stored configuration.

## Validation

Using installed Humming 0.1.18, simulated SM100/148-SM device metadata, FP8 activation/MXFP4 weights, and QKV N=5120, K=2048:

| M interval | Original block shape | Replacement block shape | Replacement CTA group / stages |
| --- | --- | --- | --- |
| (192, 208] | (104, 128, 256), invalid | (112, 128, 256) | 2 / 4 |
| (224, 240] | (120, 128, 256), invalid | (128, 128, 256) | 2 / 4 |

An ad hoc reproducer exercised the new helper, verified interval preservation and unchanged valid entries, and checked that Humming's cached original table was not mutated. Both replacement configurations compiled as actual `sm_100a` kernels with device registration disabled; they were not executed on SM100.

## Details

Humming's dense low-bit selector can halve an M tile to an eight-row-aligned size, then promote it to two-CTA execution without the required 16-row alignment. Startup compiles all M intervals, so one invalid interval is sufficient to abort initialization.

For an invalid entry, the helper preserves its tile count and requests tuning for `ceil(upper / block_m) * round_up(block_m, 16)`. This changes the selection input, not the actual tensor shape or interval boundaries. Humming chooses the full replacement configuration and reruns its resource constraints. A second alignment check rejects a still-invalid result. When no invalid entries exist, the normal implicit tuning path is retained.

MoE uses a separate candidate generator with M increments of `8 * cta_group_size`. An ad hoc sweep of both Qwen3 expert matrix shapes across indexed, grouped-contiguous, and grouped-masked GEMM found all 180 cooperative candidates aligned; MoE is unchanged.

Duplicate-work check: searched open vLLM PRs for Humming, two-CTA alignment, and build 97701. No matching workaround was found. The upstream Humming PR fixes configuration generation in the dependency; this PR covers installed affected versions without waiting for a dependency release.
