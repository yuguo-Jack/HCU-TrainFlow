# [Perf][GLM-5.3-Flash][SM90] Shape-aware launch configuration for recurrent KDA

[Upstream PR](https://github.com/vllm-project/vllm/pull/57585) · state: open · merged: False

## Original PR description

## Overview

Tune recurrent KDA launch configuration on SM90 while preserving the merged grid-indexing fix. Local kernel measurements improve most tested shapes, but two H20 TP8 serving experiments do not establish a stable C32 E2E benefit.

## Claims

- H20 microbenchmark: 11 of 12 tested shapes improve 1.41–20.86%; N32/T1/H16 regresses 0.92%.
- Complete recurrent correctness suite: 23 passed, no skips.
- No general serving acceleration is claimed. The latest A0/K/A1 C32 medians are 755.981 / 755.571 / 756.372 output tokens/s.

## Validation

The experiments, source identities, commands, negative results and limits are retained below. The 2026-10-25 follow-up covers 1,173 total requests with 36/36 natural-stop gold answers correct; MTP, native APC and external KV transfer were disabled. It is not pooled with the earlier stock benchmark.

## Details

This remains a local-kernel optimization proposal, not an accepted production performance improvement. Open related work #63544 integrates FlashInfer fused KDA on Blackwell; at head `81a449c29f72262941454038450fe78f0c612fd3`, its decode guard requires SM100-family hardware and its new prefill path permits SM100/103/107. It does not replace this H20/SM90 implementation. Narrow duplicate searches were refreshed on 2026-10-25; they are not proof of exhaustive absence of overlap.

## Purpose and source

Tune GLM-5.3-Flash recurrent KDA launches on SM90: `BV=min(next_power_of_2(V),16)`, two pipeline stages for small grids (`N * HV <= 32`), three for larger grids and one warp. Other architectures retain their existing configuration. The merged grid-indexing fix from #56974 is preserved.

Published head: `6c021edc38f49ede76a4ae5ebcf10d8c69f97f1f`, an equivalent replay on fixed main `32551991b9aff4d8af837d640e3adcd9609f7d75`. The H20 microbenchmark supports a local kernel benefit, with a counterexample; the latest standalone standard serving run **does not establish a stable C32 end-to-end gain**.

## Retained baseline trace attribution (2026-10-26)

CPU-only reanalysis of the original eight-rank 2026-10-23 diagnostic traces (96 requests, C32, MTP/APC/external cache off) links all 371 CUDA Graph launches per rank to unique same-thread `execute` scopes and explicit GPU correlations. All 12,614 recurrent KDA calls per rank belong to these generation graphs, 34 calls per graph; the 28 mixed and one context step contain none of this target symbol. Raw hashes, the original CPU schedules and target totals match the prior projections. The actual historical post-load records verify 8 local heads and head dimension 128 on all ranks; the pinned image source verifies `grid=(N*HV,NV,NK)`.

The actual launch sequence, including CUDA Graph padding, is identical across ranks:

| Effective launch N | Graphs per rank | Share |
|---|---:|---:|
| 1 | 2 | 0.54% |
| 8 | 1 | 0.27% |
| 16 | 2 | 0.54% |
| 24 | 5 | 1.35% |
| 32 | 361 | 97.30% |

Only 2/371 baseline shapes satisfy this PR's `N*HV <= 32` two-stage predicate. This is counterfactual branch eligibility, not a candidate execution trace. The wider `BV=16` change would still apply to larger shapes. The dominant N32/T1/H8 microbenchmark below saves 0.224 microseconds per call (1.41%); the best 20.86% result is N1/T4/H8 and does not represent this MTP-off workload.

Across ranks, the median per-graph target-duration sum is 0.480–0.482 ms, while median graph GPU span is 15.315–15.326 ms. Summed target durations divided by summed graph spans are 3.103–3.125%. These are profiled baseline timing descriptors, **not critical-path fractions, E2E speedup bounds, or candidate timing**; rank durations are not combined. This narrows the opportunity for the current launch-only proposal and supplies no basis for another C32 stage-threshold sweep. MTP3 behavior remains outside these traces. No kernel code changed in this update. Retained analysis SHA256: `8c2a856abb4810c6f2ba77f37b0b8dd55a6562bf8cd003315f511272cc226064`.

## Follow-up serving validation (2026-10-25)

A second isolated A0 / K / A1 run on the FW1 image, retaining the MAIN79 runtime and the same MTP-off, APC-off, external-cache-off TP8/EP configuration, again found **no stable E2E improvement**. Each arm completed 391 requests: 12 natural-stop correctness questions (all passed), 67 warmups, and three blocks of 8 C1 plus 96 C32 performance requests. Performance inputs/outputs were fixed at 2048/128 tokens. No preemptions were observed. This smaller synthetic follow-up is separate from the stock benchmark below and is not pooled with it.

| Output tok/s, median of three blocks | A0 | K: this PR | A1 |
|---|---:|---:|---:|
| C1 | 111.036 | 111.136 | 111.158 |
| C32 | 755.981 | 755.571 | 756.372 |

At C32, K/A0 is -0.05% and K/A1 is -0.11% by this follow-up's block-median definition. The all-token/all-wall sensitivity calculation gives -0.247%/+0.610%, with -0.851% baseline drift; the slow first A1 block is retained. C32 p95 first-output latency is +0.20%/+3.13% versus A0/A1. This is not a statistically established benefit. The exact candidate source was verified on all eight ranks; candidate-specific recurrent Triton variants were generated, including the two-stage variant. That verifies generation, not per-layer critical-path attribution. An initial A1 readiness-check timeout and the subsequent successful readiness check were retained before its formal measurement.

This does not change the local-kernel evidence below, but does not justify adding this patch to the measured production configuration or continuing launch-parameter sweeps without a new hypothesis.

8x H20, GLM-5.3-Flash FP8 checkpoint, TP8/DP1/EP8, `max_num_seqs=32`, batch-token budget 8192, long-prefill threshold 2048, BF16 KV with 30 GiB/GPU, context 1M. MTP, native APC and external KV transfer were disabled. All arms used the same MAIN79 (`79d5c9379`) runtime plus the existing #62479 producer, model/tokenizer bytes, dependencies and auto backend; #62603 was absent. Only the relevant PR's Python file was overlaid for each candidate. This validates those source overlays, not a rebuilt current-main binary.

Stock `vllm bench serve` was used with fixed seeded custom JSONL inputs produced using its `RandomDataset`, `--save-detailed`, `--request-rate inf`, temperature 0, `--ignore-eos`, fixed 128-token output, `--ready-check-timeout-sec 0` and `--num-warmups 0`. Primary: three 512-request C32 blocks, each 2048 input tokens. Reference: 32 requests at C1. Secondary: three 128-request C32 blocks, a fixed 3:1 mix of 2048/32768-token inputs. Separate validated shape warmups (2 C1, 64 C32 and 64 mixed requests) preceded formal measurement. Each arm also passed the same 12 synthetic gold questions, including 8K/32K inputs, with a separate natural-stop 4096-token cap.

The prespecified primary is **sum of reported output tokens / sum of all three stock durations**, not the median block or a sum across different workloads. All blocks, pauses and tails are retained. Each arm completed all 1952 formal requests with zero failures and matching prompt/generation/request counters, cache-hit zero and MTP disabled. Input generator/tokenizer fingerprints matched across arms. A configured torch profiler was inactive during formal measurement; separate diagnostic traces are excluded.

The fixed actual order was **A0b -> P -> K -> A1**, not randomized or adjacent independent A/B pairs; this table displays only this PR's candidate and the two shared baselines. Initial compiler caches were separate copies from stopped owned runs: A0b from the earlier standard baseline, P from its earlier single-PR run, and K from an earlier baseline run. A1 copied A0b's cache after A0b completed formal measurement and its separate profile. ## Microbenchmark and earlier serving limits

Historical unchanged-patch H20 microbenchmark: BF16 inputs, FP32 recurrent state, `K=V=128`, `N=1/4/32`, `T=1/4`, `H=8/16`; strict CUPTI graph replay/cold L2, untimed warmup, three ABBA blocks. All 12 shapes matched the default launch bit-for-bit and passed reference checks. Eleven improved **1.41-20.86%**, but **N32/T1/H16 was 0.92% slower in every block**. No universal SM90/all-shape benefit is claimed. The micro harness is separate from the complete pytest suite and is not a repository benchmark added by this PR. Result SHA256: `ae8a46fd8293f898ca78eb929bb9125a4de23b3db9253c5ceb404d8e44c956ca`.

A prior single checkpoint A/B combined #57585 with #57617 and MTP3: C1/C32 throughput +2.51%/+1.89%, but C32 first-output median/p95 worsened 11.54%/0.57%, and MTP acceptance/output hashes varied. That experiment did not isolate this PR or establish a serving benefit and is not pooled with the new standard benchmark.
