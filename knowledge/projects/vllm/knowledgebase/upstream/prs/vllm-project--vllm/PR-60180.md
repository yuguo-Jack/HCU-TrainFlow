# [Test] Pin reasoning token counting for the response-template parser

[Upstream PR](https://github.com/vllm-project/vllm/pull/60180) · state: open · merged: False

## Original PR description

## Overview

This PR started as a fix: with `--reasoning-parser hf`, `ResponseTemplateParser` inherited `Parser.count_reasoning_tokens`, which returns 0, so usage reported `completion_tokens_details.reasoning_tokens: 0` while returning the reasoning text.

#62052 has since replaced `ResponseTemplateParser.count_reasoning_tokens` with its own implementation, which fixes that. After rebasing, I dropped my implementation in favour of the one on main and kept only the unit tests, which `tests/parser/test_response_template.py` didn't have for this method.

## What the tests pin

`test_count_reasoning_tokens_counts_thinking_content`, with the Gemma 4 response template:

| case | output | expected |
|---|---|---|
| closed | thinking region opened and closed in the output | 2 |
| opened_by_prompt | the prompt opens the thinking region | 3 |
| unclosed | the output ends inside the thinking region | 3 |
| no_thinking | no thinking region | 0 |

Delimiters are not counted.

## Validation

```bash
.venv/bin/python -m pytest tests/parser/test_response_template.py -q

```

The four cases pass on main as of #62052 and fail on the code before it (`assert 0 == 2`, `assert 0 == 3`, `assert 0 == 3`). `pre-commit run` passes on the changed file (ruff, mypy, typos, test tethering).
