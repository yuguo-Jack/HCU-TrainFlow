# [Perf][HiSparse] Fuse per-layer slot invalidation and shorten the all-resident resolver path

[Upstream PR](https://github.com/vllm-project/vllm/pull/60103) · state: open · merged: False

## Original PR description

## Purpose

Cut HiSparse's per-layer decode overhead on the GPU and in launches:

- **One slot-invalidation launch per step.** Today it's one eager launch per leader layer after the forward graph (61 for DeepSeek-V3.2). The kernel now runs over (written tokens × index groups) using a cached device table of each group's `device_global_indices`. `HiSparseRuntime.invalidate_written_slots` is replaced by `HiSparseSlotInvalidator`.
- **Resolver masks CUDA-graph padding rows itself** from `num_valid_rows`. This removes the per-layer `copy_` + `masked_fill_` and the `request_ids`/`row_indices` buffers.
- **Cheaper all-resident resolver path.** Resident and invalid entries resolve before the host-row hash table is built, with an early exit when no host rows exist. Power-of-two block arithmetic uses shift/mask.

Stacked on #60083 (includes its commit); review only the top commit.

## Results (proxy only, not yet validated on a real server)

DeepSeek-V3.2 dummy weights, 61 layers / 8 experts, TP4, H100, batch 32, 16k context, nsys per decode step:

| kernel | before | after |
|---|---|---|
| invalidate | 495 µs (61 launches) | 5.8 µs (1) |
| resolve_residency | 421 µs | 372 µs |
| masked_fill_ + copy_ | 166 µs | 0 |

TPOT (`--out 384`, 3 reps each, back to back): 38.83 / 38.47 / 39.25 → 37.79 / 37.61 / 38.04 ms (~2.7%).
