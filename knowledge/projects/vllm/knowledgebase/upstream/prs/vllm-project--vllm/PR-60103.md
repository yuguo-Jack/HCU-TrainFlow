# [Perf][HiSparse] Fuse per-layer slot invalidation and shorten the all-resident resolver path

[Upstream PR](https://github.com/vllm-project/vllm/pull/60103) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Cut HiSparse's per-layer decode overhead in GPU time and launches: fuse per-layer slot invalidation into one launch per step, mask CUDA-graph padding rows inside the resolver, and cheapen resolver arithmetic.

## Claims

- Slot invalidation: one launch per step instead of one per leader layer. On B200 with 78 index groups, each step drops from 374–759 µs to 3.5–162 µs.
- Resolver: 1.16×–3.69× faster per layer than main at every swept shape on B200, with bit-identical outputs.
- GLM-5.3-NVFP4, TP8 B200, 16k/1k: mean TPOT −1.8% at c=16 and −0.5% at c=64.

Outputs are bit-identical between main and PR at every point.

| 78 × 64 | 634 µs | 13.0 µs |
| 78 × 256 | 759 µs | 59.1 µs |

| requests (rows/graph rows) | pages on host | main | PR | speedup |
|---|---|---|---|---|
| 64 (64/64) | 0% | 9.2 µs | 4.6 µs | 2.00× |
| 64 (64/64) | 10% | 18.8 µs | 14.0 µs | 1.34× |
| 100 (100/128) | 0% | 15.3 µs | 4.8 µs | 3.19× |

PR is faster at all 36 swept points (1–128 requests, q=1/4, 0/10/100% host pages): 1.16×–3.69×.

#### End to end (GLM-5.3-NVFP4, 8×B200, TP8, 16k in / 1k out)

Main and PR were run back to back on one node, interleaved, with 2 reps each and a server restart per point. Both have the same KV capacity (1.49M GPU + host tokens).

| concurrency | variant | output tok/s | mean TPOT (ms) |
|---|---|---|---|
| 16 | main | 802 / 809 | 15.84 / 15.67 |
| 16 | PR | 816 / 817 | 15.47 / 15.46 |
| 64 | main | 1265 / 1262 | 40.23 / 40.35 |
| 64 | PR | 1267 / 1270 | 40.12 / 40.02 |

## Details

Cut HiSparse's per-layer decode overhead on the GPU and in launches:

- **One slot-invalidation launch per step.** Today it's one eager launch per leader layer after the forward graph. The kernel now runs over (written tokens × index groups) using a cached device table of each group's `device_global_indices`. `HiSparseRuntime.invalidate_written_slots` is replaced by `HiSparseSlotInvalidator`.
- **Resolver masks CUDA-graph padding rows itself** from `num_valid_rows`, one block per padding row. This removes the per-layer `copy_` + `masked_fill_` and the `request_ids`/`row_indices` buffers. On main, one block masks the whole padding run serially, which dominates the launch on padded batches.
- **Cheaper resolver arithmetic.** Power-of-two block math uses shift/mask (compile-time for 64-row blocks), and the first row's top-k is loaded before the request lookups resolve.

- `HiSparseSlotInvalidator` caches one device table of `device_global_indices` addresses per leader set. It is built on first use, so steady-state steps do no H2D copy. All index groups must share one hot layout (checked).
- Remaining HiSparse TPOT overhead at c=64 (~1.8 ms vs no HiSparse) is outside these kernels.

Not a duplicate: no open PR touches these kernels.
