# Fix hipErrorCapturedEvent on RoCM when using LoRA with cuda graphs

[Upstream PR](https://github.com/vllm-project/vllm/pull/41756) · state: open · merged: False

## Original PR description


AI disclaimer: Created with the help of Deepseek V4 Pro.

## Purpose
CudaCommunicator inherits all_gather() from DeviceCommunicatorBase, which calls dist.all_gather_into_tensor() which is a raw PyTorch ProcessGroupNCCL operation. ProcessGroupNCCL has a watchdog thread that periodically calls isCompleted() → hipEventQuery() on events recorded in the CUDA graph capturing stream. HIP does not permit querying events in a capturing stream, causing hipErrorCapturedEvent and a crash across all ranks.

CudaCommunicator already uses pynccl_comm (which wraps NCCL directly without the ProcessGroup watchdog) for reduce_scatter, broadcast, send/recv, and all_gatherv. Only all_gather was missing the override.

The crash is triggered by tensor_model_parallel_all_gather() calls in /vllm/lora/layers/column_parallel_linear.py:64 inside LoRA column-parallel linear layers.

The fix is to call ncclAllGather() directly with pynccl_comm.all_gather instead of using dist.all_gather_into_tensor which wraps it in pytorch event management.

The `pynccl_comm.all_gather` method (and the underlying NCCL call) operates on raw memory pointers and expects the input tensor to be contiguous. If `input_` is a non-contiguous view (e.g., a result of a transpose or a slice), this will lead to incorrect data being gathered because NCCL will read `numel()` elements linearly from the data pointer. You should ensure the input tensor is contiguous before passing it to the communicator.

```suggestion
            pynccl_comm.all_gather(output_tensor, input_.contiguous())
```
