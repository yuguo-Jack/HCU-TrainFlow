# [Spec Decode] DFlash/DSpark: skip the draft forward on K=0 steps

[Upstream PR](https://github.com/vllm-project/vllm/pull/62904) · state: closed · merged: False

## Original PR description



## Overview

A per-batch-size K schedule (`num_speculative_tokens_per_batch_size`, e.g. `[[1, 96, 7], [97, 2048, 0]]`) allows K=0 so that large batches run without speculation. The V2 runner passes that K to `propose()` and masks drafts past it, but `DFlashSpeculator.propose` (inherited by DSpark and DFlash2) ignores it, so every K=0 step still runs the full parallel draft forward and its sampling, and the runner throws the result away. Related: #47737 (open) fixes a ZeroDivisionError when a schedule containing 0 reaches DSpark's draft CUDA-graph capture; different file and bug, no code overlap. #61261 (open, `draft_context_window`) edits the same `propose` and will need a rebase against this one, or vice versa.

## Claims

- On a K=0 step, `propose` runs only its context half: it stores the target hidden states, publishes the context anchor and writes the draft's context K/V for every target token, as a full step does, so the draft has the whole context when K rises again. It skips the draft forward, its attention-metadata build and sampling.
- Only without DP: with `data_parallel_size > 1` the draft forward is a DP-synchronized step every rank must run. Dummy and profile runs are unchanged, and nothing changes unless a step is scheduled with K=0.
- On 8x MI355X with DSpark, per-user decode rate at K=0 rungs goes from 0.65-0.71x to 0.96-0.98x of a server without a drafter.

## Validation

8x MI355X, an 816B-parameter MoE model in MXFP4, EP8, DSpark drafter, schedule `[[1, 96, 7], [97, 2048, 0]]`:

| rungs | per-user decode rate vs. no drafter, before | after |
|---|---|---|
| K=0 (concurrency 128-1024) | 0.65-0.71x | 0.96-0.98x |
| K=7 | unchanged within noise | |

gsm8k with most requests at K=0: 0.972 (0.972-0.980 across the other runs).

New `tests/v1/spec_decode/test_dflash_skip_draft_k0.py`: a K=0 step stores the context and writes the context K/V without reaching the draft forward (DFlash and DSpark), and the draft forward still runs for K > 0, under DP, and for dummy/profile runs (5 cases).

## Details

**About the test.** It builds the speculator with `__new__` and stands `MagicMock`s in for its buffers and helper methods, and replaces the draft forward with a function that raises. That makes it a control-flow test: it checks which steps reach the draft forward and that the K=0 path calls the context-K/V helpers, not that the K/V it writes is right. A test with real buffers needs a GPU and a DFlash/DSpark checkpoint; if reviewers prefer, we can replace it with a GPU test on a tiny random-weight drafter.

**Not tested.** DFlash2 end to end (it inherits `propose`), and NVIDIA hardware.
