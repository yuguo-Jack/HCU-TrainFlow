# [Docs][ROCm] Add MiniMax-M3.1-Flash MI355X TP4 AgentX preset

[Upstream PR](https://github.com/vllm-project/vllm/pull/64805) · state: closed · merged: True

## Original PR description

## Overview

Add the opt-in `mi355x_agentx` preset to the MiniMax-M3.1-Flash recipe: the MI355X TP4 AgentX lane from [InferenceX #4671](https://github.com/SemiAnalysisAI/InferenceX/pull/4671) on the Quark MXFP4 checkpoint, concurrency 1 to 64.

## Claims

- Adds one preset, scoped to the `mxfp4` variant, with seven concurrency points that the builder can render: 1/2/4/8 (seven-token DSpark with mono decode, FP8 KV cache), 16/32 (seven-token DSpark with DBO, NVFP4 KV cache, 0.85 memory), and 64 (three-token DSpark with DBO and a host-DRAM KV tier through `SimpleCPUOffloadConnector`, 0.90 memory).
- Every point's generated command carries the same serving flags as the InferenceX run for that point.
- The runbook records measured results and two limitations (below).
- No existing rendering changes.

## Validation

From a `vllm-project/recipes` checkout at `d460fcc`, with this branch as the `vllm` source:

```bash
node scripts/validate-source.mjs --source vllm --dir "$VLLM_CHECKOUT/recipes"
node --test scripts/test-guide-html.mjs scripts/test-presets.mjs scripts/test-schema.mjs
pre-commit run typos --files recipes/models/MiniMaxAI/MiniMax-M3.1-Flash.yaml
```

The source validator passes, 47 of 47 renderer tests pass, and `typos` passes. Building the JSON API on `main` and on this branch gives 22,575 identical files; the only differences are the new `presets/mi355x_agentx.json` and the new entry in the two parent JSONs (`MiniMax-M3.1-Flash.json` and the promoted `amd/MiniMax-M3.1-Flash-Quark-MXFP4.json`).

All seven rendered commands were compared flag by flag with the `vllm serve` commands in the InferenceX job logs. Serving flags and relevant environment variables match at every point, except that the harness flags (`--host`, `--port`, `--device-ids`, `--served-model-name`, `--disable-uvicorn-access-log`, `--max-model-len`, `--trust-remote-code`) are not part of the preset, throughput runs used synthetic rejection where the preset keeps block rejection, and `VLLM_ROCM_MINIMAX_M3_SP_PREFILL=1` (set at concurrency 64 by InferenceX) is omitted because it had no effect on this checkpoint.

Existing GPU evidence, not a new GPU run from this PR: [InferenceX run 41003224750](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/41003224750) at `a328b4435` passed all seven performance points and GSM8K at concurrency 8, 32 and 64 (0.964, 0.959, 0.957 strict exact match, 1,319 samples each). Per-point interactivity and throughput are in the runbook (single run).

## Details

**Not a duplicate.** The recipe has presets for B300, GB200 and GB300 but none for MI355X AgentX. Open PRs touching this model are code changes (#64448, #64273), not recipe presets.

**Why the DBO points pass the DBO flags directly.** The `prefill_dbo_sp` feature's modes set their own thresholds (8192, or 16384 with SP on the default checkpoint only) and a feature's flags win over a preset's `args`. This lane runs the 16384-token DBO threshold without SP, so the preset passes `--enable-dbo` and the thresholds itself, with the V2 model runner env the feature would set.

**Limitations, also in the runbook.**
- Concurrency 64 needed a rerun: the first attempt hung at its first load from the host KV tier (23 fetches in progress, none completing, then a `sample_tokens` RPC timeout) and the rerun passed. The offload point is less proven than the others.
- Sequence-parallel prefill does not apply to the Quark checkpoint: the server logged it as off even with the variable set.

AI assistance was used (Claude Sonnet 5.5, `claude-sonnet-5-5`, via Claude Code): it drafted the preset, ran the validation above, and compared the rendered commands with the InferenceX job logs. The submitter reviewed the changes.
