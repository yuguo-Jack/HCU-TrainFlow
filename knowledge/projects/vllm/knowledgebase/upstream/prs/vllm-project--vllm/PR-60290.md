# [Bugfix] Drain worker responses before fault-tolerance recovery

[Upstream PR](https://github.com/vllm-project/vllm/pull/60290) · state: open · merged: False

## Original PR description

## Purpose

Fixes #49972. A failed multi-worker RPC stops reading at the first error, leaving other workers' responses queued. Fault-tolerance recovery then reads stale results instead of the recovery command's response.

In fault-tolerance mode, consume the remaining responses before raising and report failures with their worker ranks. Preserve immediate failure when fault tolerance is off or the executor has failed. Keep the original RPC deadline while draining.

The earlier PR #49976 was closed without merging. No open PR addressing this issue was found. This patch includes regression coverage and addresses its review feedback about rank attribution, duplicate raises, and failed executors.

## Test Plan

```bash
OMP_NUM_THREADS=4 HF_HUB_OFFLINE=1 .venv/bin/python -m pytest tests/v1/executor/test_multiproc_executor.py tests/v1/executor/test_multiproc_executor_timeout.py -q
```

The regression sends failing responses followed by recovery responses through the public `collective_rpc` method. It covers blocking and nonblocking calls, fault tolerance on/off, a failed executor, and timeout during draining. Existing executor and deadline tests also run. Buildkite's existing `v1/executor` test lane includes this file.

Environment: Python 3.12, PyTorch 2.13.0+cpu, Transformers 5.18.0; source based on upstream `d1f3d8b87083a95f914c674c477796950e2ba5fe`.
