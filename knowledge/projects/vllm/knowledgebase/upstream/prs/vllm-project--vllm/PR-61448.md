# [ROCm][Model] Add fusions for Muse Glimmer for AMD backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/61448) · state: open · merged: False

## Original PR description



## Overview

1) Muse has a pattern rmsnorm + add + rmsnorm. This PR adds a fused kernel for these operations. Previously it had a single kernel that was from inductor but the custom AITER fused kernel has better perf (~2us / 40%) in decode and 30-40us / 50% in prefill.

2) Fuse the rmsnorm + reshape + rope and cache kernel.

3) (2) required AITER FA to be default. Baseline is using using vllm's ROCm FA backend which is not optimized.

## Claims

TPOT and total tok/s should speed up substantially.

## Details

Fusions improve performance in decode by amortizing kernel launch latency. Moving to fused kernels improves decode performance and in some cases also TTFT. 

Before:
<img width="1247" height="211" alt="image" src="https://github.com/user-attachments/assets/936e0f13-9cc6-4a8d-8a20-719b3ce5c76b" />

The three kernels pre-attention are ~4us each (this is (1) from the Overview). The rmsnorm is 6us and is also ~30% larger in prefill (not in screenshot) most likely due to inductor not being great at generalizing for shapes (this is (2) from Overview). Attention is 144us (this is (3) from Overview).

After:

<img width="1449" height="249" alt="image" src="https://github.com/user-attachments/assets/c35f4648-f2d9-43a2-9d56-bdfa47f4b53f" />

The fused kernel ((1)) is 4us (vs 12), rmsnorm is 4us (vs 6) and also ~30% faster and attention is 27us vs 144.

There should be no changes to any backend other than ROCm. The changes are gated to both rocm and AITER being enabled. 

There is a new fusion pass added for the rmsnorm+add+rmsnorm as that did not exist before. Same with the qk rope pass. Unit tests are added for both.
