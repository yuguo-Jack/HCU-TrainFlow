File: `vllm/entrypoints/serve/utils/api_utils.py` · line 20

🟡 (optional) Out-of-tree code that imports the moved helpers will hit ImportError after merging, if it uses the old paths. vllm-omni (which `vllm --omni` hands off to) is one such possible caller. This change deletes `vllm.entrypoints.launchers.cli_args` and removes `cli_env_setup`, `VLLM_SUBCMD_PARSER_EPILOG`, `log_non_default_args` and related helpers from api_utils. Neither old location re-exports them. Fix: keep a thin re-export at both old paths that points to `vllm.entrypoints.common.cli_args` / `vllm.entrypoints.common.setup` and raises a DeprecationWarning. This is the same pattern `vllm/entrypoints/openai/api_server.py` already uses.

<details>
<summary>Why this was flagged</summary>

The trigger is any importer outside this repo, such as a plugin, vllm-omni or a user script, that still uses `from vllm.entrypoints.launchers.cli_args import make_arg_parser` or `from vllm.entrypoints.serve.utils.api_utils import VLLM_SUBCMD_PARSER_EPILOG, cli_env_setup`. vllm/entrypoints/cli/main.py:31 delegates `--omni` runs to `vllm_omni.entrypoints.cli.main`. After the merge, api_utils.py no longer defines these names, and the old cli_args.py file is gone. Those importers now get ImportError or ModuleNotFoundError at import time, while on the base branch the import works. The repo keeps DeprecationWarning shims for other moved entrypoints (vllm/entrypoints/openai/api_server.py:15-30, vllm/entrypoints/grpc_server.py:8). Neither of the two paths moved here gets such a shim.

**Verification:** `git diff --stat` shows `vllm/entrypoints/{launchers => common}/cli_args.py` as a pure rename. Nothing re-exports these names at either old location. So `from vllm.entrypoints.launchers.cli_args import make_arg_parser` and `from vllm.entrypoints.serve.utils.api_utils import cli_env_setup` now raise ImportError where they worked on the base commit.
