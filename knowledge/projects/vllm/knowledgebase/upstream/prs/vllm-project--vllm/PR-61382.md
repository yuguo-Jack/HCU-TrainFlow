# [Build][CPU] Install Run:ai Model Streamer in vllm-openai-cpu image

[Upstream PR](https://github.com/vllm-project/vllm/pull/61382) · state: closed · merged: True

## Original PR description

## Overview

Add the `runai` wheel extra to the release-stage install in `docker/Dockerfile.cpu`, so the published `vllm/vllm-openai-cpu` image ships `runai-model-streamer` and can load the tokenizer with `--load-format runai_streamer`.

## Claims

- The CPU image is used as the CPU-side container of KV-cache-aware routers (llm-d-style EPP/inference-gateway deployments). No model weights are needed there — only the tokenizer and other non-tensor files, which are pulled from the object store through the Run:ai streamer path.
- Today this fails with `ModuleNotFoundError: runai_model_streamer` because the release stage installs only `dist/*.whl[audio,bench]` and `runai-model-streamer` is an optional dependency outside the wheel's install_requires. After this change, the tokenizer loading path works in the released CPU image.

## Validation

- `docker buildx build --check -f docker/Dockerfile.cpu .` — passes with 0 errors (only pre-existing `LegacyKeyValueFormat` warnings on unrelated `ENV` lines).
- Full image build + in-container check is pending and will be exercised by the CPU release image CI job (`.buildkite/image_build/image_build_cpu.sh`); recommended verification inside the built image:
  ```bash
  python -c "import importlib.util; print(importlib.util.find_spec('runai_model_streamer') is not None)"
  ```
- Platform compatibility is already exercised upstream: `requirements/test/cpu.txt` pins `runai-model-streamer==0.15.7`, so CPU CI already installs and tests the streamer against the CPU wheel; only the release image was missing it.

## Details

- The change reuses the existing `runai` extra from `setup.py` (`"runai": ["runai-model-streamer[s3,gcs,azure] >= 0.15.7"]`) instead of adding a new pin, so the version spec stays in one place and matches the CUDA `docker/Dockerfile` floor.
- The streamer itself is device-agnostic (tensors are streamed through CPU buffers); only the `distributed` streaming option requires CUDA/ROCm (see `docs/models/extensions/runai_model_streamer.md`).
- Not duplicating any existing PR: searched open PRs for "runai-model-streamer", "runai cpu dockerfile", and "Dockerfile.cpu" — no open PR adds the Run:ai streamer to the CPU image.
- Tradeoff: the image grows by the streamer and its S3/GCS/Azure SDK dependencies.
