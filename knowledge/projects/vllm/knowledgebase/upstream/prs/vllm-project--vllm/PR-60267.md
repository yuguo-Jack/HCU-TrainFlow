## Original PR description

# [Perf][V2] Add custom CPU DP metadata all-reduce

V2's small CPU metadata all-reduce can delay model dispatch as DP size grows. Add a recursive-doubling SUM using existing Gloo point-to-point operations: `log2(DP)` exchanges, with no GPU synchronization or new process groups.

Enable with `VLLM_DP_METADATA_TRANSPORT=gloo-tree` on every worker. The option is registered and validated in `vllm.envs`; Gloo all-reduce remains the default. The opt-in path requires power-of-two groups and serialized calls, and reserves P2P tags starting at 27100. Scratch storage follows the input shape without assuming a fixed metadata field count.

## Benchmark

**Model-serving A/B:** DeepSeek-V4.1-Flash on 16 GB300 GPUs (four nodes), TP1/DP16/EP16, client concurrency 512. Logical input/output lengths 8192/1024, DecodeBenchConnector to skip prefill, five DSpark draft tokens with synthetic acceptance 4.409. Both runs completed 5,120 measured requests with zero errors after 2,048 warmup requests. Recipes differed only in transport and job name; both used vLLM `0.30.1rc1.dev312+g36768d1bf` and PyTorch `2.13.0+cu130`.

| Metric | Original Gloo | Recursive doubling | Change |
|---|---:|---:|---:|
| Output tokens/s/GPU | 2,974.6 | 3,682.9 | +23.8% |
| Tokens/s/user (1000 / mean TPOT) | 114.40 | 139.28 | +21.7% |
| Mean TPOT | 8.741 ms | 7.180 ms | −17.9% |
| Median TTFT | 1,061.17 ms | 564.53 ms | −46.8% |
| p99 request latency | 16,168.5 ms | 17,188.3 ms | +6.3% (worse) |
| Mean CPU metadata collective wall time | 9.164 ms | 3.507 ms | −61.7% |

One independently scheduled A/B pair, not a confidence interval. CPU timings include rank arrival skew; 6,202/6,136 samples match the local decode shape within the client measurement window, rather than complete synchronized cohorts. This measures decode-focused serving performance, not real-prefill throughput or answer accuracy. No Nsight capture was taken for this pair.

**CPU microbenchmarks:** DP16, `[6, 16]` int32 / 384 bytes, one Torch thread, no CPU binding or explicit Gloo interface override. Timing includes input preparation through the complete CPU result.

| Condition | Original Gloo median | Recursive-doubling median |
|---|---:|---:|
| Idle GPU | 4.741–5.385 ms (4 blocks) | 0.618–0.681 ms (3 blocks) |
| GPU-busy control | 6.440–6.793 ms (2 blocks) | 1.539 ms (1 block) |

Each block uses 20 warmups, then 200 idle or 60 busy iterations per rank. Ranges are block medians, not confidence intervals. The busy control launches a ~9.69 ms CUDA sleep; the tree operation returned while the GPU was still busy in every measured sample. Blocks share one allocation and rank samples are correlated. All **48,320 timed rank-samples** and **512 additional dense tree checks** passed.
