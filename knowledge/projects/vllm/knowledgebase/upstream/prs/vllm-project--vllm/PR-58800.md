# [ROCm] gfx1250 optimizations and model enablement

[Upstream PR](https://github.com/vllm-project/vllm/pull/58800) · state: closed · merged: True

## Original PR description

## Purpose

  Enables and optimizes gfx1250 (ROCm) for gpt-oss-120b, DeepSeek-R1-0528, DeepSeek-V4-Flash and MiniMax-M3 (MXFP4). Every change is limited to gfx1250; other ROCm and CUDA paths behave as
  before.

  - **MoE:** new AITER Triton/Gluon W4A4 MXFP4 expert (`aiter_mxfp4_w4a4_moe.py`), with its own backend enum so the oracle picks it only on gfx1250 (MI300/MI355 defaults unchanged). gfx1250
  MX-scale swizzle and weight prep for W4A16/W4A8, router-logit sanitization and an fp32 routing bias, and routing-replay plumbing.
  - **Linear:** AITER preshuffled block-FP8 GEMM, used when a tuned config exists.
  - **Attention / sampling:** gfx1250 paths in the AITER unified-attention backend and an AITER fused sampler (`sampler.py`, `topk_topp_sampler.py`).
  - **Models:** DeepSeek-V4 AMD fixes and gpt-oss MXFP4 stride fix. gpt-oss RMSNorm+pad fusion uses the existing `fuse_act_padding` pass,
  not a model-specific op.
  - **Docker:** gfx1250 base/image updates (ROCm SDK, Triton and AITER pins).

  Not a duplicate: no other open PR targets gfx1250 enablement for these models. Kimi-K3 gfx1250 support was split out to be upstreamed separately.

  ## Test Plan

gsm8k (lm-eval) for all models along side the normal server benchmarks

  https://github.com/vllm-project/vllm/pull/58800#issuecomment-5902957137
