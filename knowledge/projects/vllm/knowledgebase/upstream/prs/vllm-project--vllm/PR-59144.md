# fix: handle sampling when all tokens are invalid (allowed_token_ids + bad_words contradiction)

[Upstream PR](https://github.com/vllm-project/vllm/pull/59144) · state: open · merged: False

## Original PR description

## Summary

Fix `allowed_token_ids` + `bad_words` (or any masking constraint) leaving every
logit at `-inf`, which made greedy `argmax` silently emit token `0` outside the
caller's allowed set. The affected request is now terminated with an explicit
error and its fabricated token is discarded; sibling requests are unaffected.

Closes #57986.

## Root cause

`allowed_token_ids` is enforced with `logits.masked_fill_(mask, -inf)` and
`bad_words` afterwards by `apply_bad_words`. When every allowed token is also
banned the whole row is `-inf`, and `argmax` returns index `0`.

## What this PR does (runtime protection only)

- Detects all-`-inf` rows after logits processing in the CPU/V1 sampler, the
  GPU/MRV2 sampler, and both rejection samplers (MRV1 and MRV2).
- Propagates the per-request mask through the sampler output, the batch-shard
  gather, and the sync/async model-runner paths to the scheduler, which marks
  the request `FINISHED_ERROR` and discards the neutralized token.
- Does **not** touch `vllm/sampling_params.py`: request-time rejection of
  provably-empty constraints is handled separately in #58101. This PR is the
  runtime half, which also covers context-dependent (multi-token / later-step)
  failures.

## GPU↔CPU synchronization (review concern)

The host branch is gone and detection is gated on CPU-side sampling metadata:

```python
def neutralize_no_valid_token_rows(logits, sampling_metadata):
    if not logits_may_be_masked(sampling_metadata):   # CPU-only gate
        return None
    no_valid_token_mask = torch.isneginf(logits.amax(dim=-1))
    logits[no_valid_token_mask, 0] = 0.0              # one finite token per row
    return no_valid_token_mask
```

`amax(dim=-1)` reduces directly (the previous `isneginf(logits).all(-1)`
materialized a `[B, V]` bool tensor). An all-`-inf` row only needs one finite
token to stay safe for `argmax`/`softmax`, so the fill is O(#invalid rows)
instead of a full `[B, V]` `masked_fill_`.
