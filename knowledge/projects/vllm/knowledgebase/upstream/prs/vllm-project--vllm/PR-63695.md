# [KV Offload] Carry request context on raw stored events

[Upstream PR](https://github.com/vllm-project/vllm/pull/63695) · state: closed · merged: True

## Original PR description

## Overview

Carry the originating `ReqContext` on internal store events across the CPU, filesystem, and object tiers. This is the transport-only first step split from #52103. Published `BlockStored` and `BlockRemoved` payloads are unchanged.

## Changes

- CPU store completion attaches the `ReqContext` it already receives. FS/OBJ retain the in-flight `TransferJob` and use its context when the asynchronous store completes, including cascaded stores. No new side map is added.
- When a successful raw store event is emitted, it carries context regardless of `self_describing_kv_events`. The option is not plumbed through managers, specs, or secondary tiers; the event tracker remains the place to decide whether to use that context for published self-describing events.
- Inventory and removal events do not gain request context. This PR does not change event payload generation or removal semantics.

## Follow-ups (not part of this PR)

- #59599 aligns per-block `extra_keys` independently; this transport-only PR does not depend on it.
- **B — complete chunks and removals:** Use the carried context to build complete-chunk `BlockStored` payloads, reusing the extra-key alignment from #59599. Emit chunk-key `BlockRemoved` events so consumers can undo their recorded chunk-to-block mapping. B should land after #59599.
- **C — partial tails and cleanup:** Build partial-tail metadata from request context, then remove the remaining `_pending_event_metadata` map and old recording hooks. C follows B.

#52103 remains the umbrella discussion for the complete change. AI assistance was used for implementation and validation. This PR remains draft for human review and testing of this revision.
