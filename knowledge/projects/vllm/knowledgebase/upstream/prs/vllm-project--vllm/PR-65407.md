# [Bugfix][ROCm][Qwen4Exp] Bind the opaque SP wrappers in the PLE layer

[Upstream PR](https://github.com/vllm-project/vllm/pull/65407) · state: open · merged: False

## Original PR description

## Overview

Bind the opaque sequence-parallel wrappers from #61471 in `amd/ple_layer.py`, which still imports the plain helpers, so that `--enable-hc-sp` compiles for Qwen4Exp on ROCm. `amd/mtp.py` has the same import and is changed in #65475.

## Claims

- Qwen3.8-Flash-Next (MXFP4 Quark checkpoint), TP2, `--enable-hc-sp`, MI355X: the nightly server fails during backbone compile; with this change it starts and answers requests.
- GSM8K with `--enable-hc-sp` and this change matches the default layout.
- `test_compiled_sp_ops_handle_untraced_token_counts` also covers `amd/ple_layer.py`: it fails on the plain imports and passes with this change.

## Validation

Nightly `vllm/vllm-openai-rocm:nightly-40941f2c4ba96fba0a7e282a5355e89cd74d9ac5` (0.33.0rc1.dev573+g40941f2c4; the SP files are blob-identical to main `cf31617992`), 2x MI355X, `amd/Qwen3.8-Flash-Next-Quark-MXFP4`.

## Details

Dynamo specializes the padding branch of the plain `sp_reduce_scatter` / `sp_shard` on the traced token count and vLLM drops the guards (comment in `amd/ops/sequence_parallel.py`). #61471 added opaque wrappers for that reason and `amd/model.py` binds them; `amd/ple_layer.py` (in `_sp_shard_embeddings` and after the short-conv op) kept the plain imports. `sp_all_gather` stays plain (no padding branch). Under compile the wrapper clones the unpadded `sp_shard` result: one extra copy per call, not measured.

The test now runs for the model and the PLE module with `torch._dynamo.reset()` between them: the compile cache is keyed by code and the guards are dropped, so the second module otherwise reuses the first module's trace (a first version without the reset passed on the plain `ple_layer.py`).

Limits: gfx950 only; n = 1 per arm for the server runs. Why the plain helpers produce the partition cycle is not traced; the nightly failure and the test failure are linked by the swap. The CUDA files (`qwen4_exp/nvidia/*`) import the plain helpers too and are not touched.

Duplicates: no open PR or issue addresses this (searched on 2026-11-03: PRs touching `amd/ple_layer.py`, `amd/ops/sequence_parallel.py` and `amd/mtp.py`; issues for the error strings). #64369 adds one import line to `ple_layer.py`: a one-line textual conflict.
