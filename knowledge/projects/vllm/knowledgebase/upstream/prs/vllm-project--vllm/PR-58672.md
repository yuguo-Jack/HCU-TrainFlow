# [Refactor][MoE] Migrate Quark static INT8 to the MoE oracle

[Upstream PR](https://github.com/vllm-project/vllm/pull/58672) · state: open · merged: False

## Original PR description

## Summary

Migrate the static-activation INT8 path in `QuarkW8A8Int8MoEMethod` to the MoE oracle and modular kernel for single-rank and naive AllGather/ReduceScatter execution.

This addresses the Quark static INT8 portion of #54959. Other all-to-all configurations retain the legacy path.

## Dependency and review scope

This PR requires the independent activation/weight scale-indexing fix tracked in #58532. Related prerequisite PR: #58570.

The branch temporarily includes my prerequisite implementation at eef597461aa5. The migration changes are isolated in subsequent commits, so the current diff against upstream main includes both the prerequisite and the migration.

This PR focuses on the oracle migration rather than proposing another standalone scale-indexing fix. Once the prerequisite lands, I will rebase onto the accepted implementation, remove the prerequisite commits from this PR, and rerun the relevant tests.

## Changes

- Route supported static INT8 configurations through oracle selection, weight conversion, quant-config construction, and modular kernel execution.
- Preserve loaded A1/A2 scales, FP16/BF16 compute dtype, bias handling, and the legacy input-side router-weight order.
- For naive AllGather/ReduceScatter, dispatch floating-point activations and quantize on the destination rank using its local static scale.
- Handle empty static INT8 inputs in the local quantization helper so empty ranks still participate in communication.
- Explicitly reject static INT8 with LoRA until router weighting is supported consistently across the base and adapter branches.
- Preserve independent weight-scale indexing in the remaining legacy fallback.

## Validation

The following results were collected on NVIDIA L20 using working trees based on `cccf7e1376ba082a2b14190a1a1fa963acb953b7` plus the prerequisite and migration patches. They are not a fresh test run of the subsequently published branch HEAD.

```bash
pytest -q tests/quantization/test_int8_moe_oracle.py
# 14 passed, 1 skipped
```

Covers backend selection, unsupported configurations, static INT8 + LoRA rejection, the simulated XPU capability path, and tensor/channel scale layouts in the legacy fallback.

```bash
CUDA_LAUNCH_BLOCKING=1 pytest -q tests/kernels/moe/test_moe.py \
  -k 'nonblock_w8a8_scale or nonblock_fp8_scale_layouts_swap_ab or quark_static_int8_moe' -x
# 30 passed, 4 skipped
```

Covers independent INT8/FP8 scale layouts, static Quark numerical references, distinct A1/A2 scales, FP16/BF16, bias and router weighting, empty inputs, and CUDA Graph capture/replay.

```bash
CUDA_VISIBLE_DEVICES=0,1 pytest -q \
  tests/kernels/moe/test_quark_static_int8_distributed.py --maxfail=1
# 1 passed
```

The two-rank test exercises real NCCL AllGather/ReduceScatter with:

- Local token counts of `[0, 1]`, where the nonempty rank routes its token to the empty rank's expert.
- Bidirectional routing with different A1/A2 scales on the two ranks, checked against a destination-scale reference.

The skipped cases require real XPU hardware or Hopper SM90.

## Remaining validation

This PR is a draft. The remaining checks are:

- Validation at the exact published commit and after rebasing onto the accepted prerequisite.
- Static Quark MoE model-level evaluation.
- Compilation through the normal runner/custom-op entry point.
- A multi-GPU CI entry that executes the distributed regression.
- Relevant Hopper, ROCm, and XPU hardware coverage.

Other all-to-all configurations remain on the legacy path pending separate migration validation.
