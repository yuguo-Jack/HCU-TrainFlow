# [Bugfix] Avoid duplicate grammar-terminal beams in offline beam search

[Upstream PR](https://github.com/vllm-project/vllm/pull/60327) · state: closed · merged: False

## Original PR description



## Overview

Clear active beams when every beam in an offline batch has finished its structured-output grammar. This prevents finalization from adding the same completed sequences a second time and displacing the next-best distinct beam.

## Claims

- Grammar-terminal beams enter the completed set once when structured beam search exits early.
- The regression covers one/two prompts, both EOS settings, and token limits before/after grammar termination; the existing abort regressions remain passing.

## Details

The structured-output path already appends grammar-terminal beams to `instance.completed`. When all beams terminate, it returns before replacing `instance.beams`; finalization then extends `completed` with those retained beams. Clearing those exhausted active lists before returning preserves the completed results and prevents duplication. Unstructured, partially active, and abort paths are unchanged.

This is a follow-up to structured beam search in [#35022](https://github.com/vllm-project/vllm/pull/35022). Searches of structured/duplicate/terminal beam PRs and diffs of the nearby open [online structured-output PR #36285](https://github.com/vllm-project/vllm/pull/36285), [stop-string PR #52621](https://github.com/vllm-project/vllm/pull/52621), and [detokenization test PR #49541](https://github.com/vllm-project/vllm/pull/49541) did not identify this same early-exit fix. These nearby changes are potential integration context, not issues this patch claims to resolve.

On 2026-10-07, all eight open beam-search PRs were checked, including allowed-token IDs [#47630](https://github.com/vllm-project/vllm/pull/47630) and length-penalty [#59506](https://github.com/vllm-project/vllm/pull/59506). None contains this early-exit fix. The affected method in upstream main `db6e3cd8c4f9b84c39fe3c44fab0b1d3117f758b` still matches the buggy baseline, and the branch merges cleanly with current main.
