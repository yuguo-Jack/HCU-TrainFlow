# [Bugfix][Reasoning] Fix Granite streaming reasoning for multi-token deltas

[Upstream PR](https://github.com/vllm-project/vllm/pull/60773) · state: open · merged: False

## Original PR description

## Overview

Fix `GraniteReasoningParser` streaming dropping reasoning when a delta carries several tokens (e.g. `--stream-interval > 1`) and reaches `Here is my response:`. Complementary to #50303, which fixes the delta straddling the end of `Here is my thought process:`.

## Claims

- Streamed reasoning matches non-streaming `extract_reasoning` for multi-token deltas that reach the response sequence.
- A delta ending exactly with `Here is my response:` no longer drops the reasoning it carries.

## Validation

Reproducer (facebook/opt-125m tokenizer), streaming vs non-streaming `extract_reasoning` on the same text; every case starts with the delta `"Here is my thought process:"`:

| Remaining deltas | non-streaming reasoning | `main` streamed reasoning | this PR |
| --- | --- | --- | --- |
| `[" The user asks", " about X. Here is my response:", " bar"]` | `" The user asks about X. "` | `" The user asks"` | `" The user asks about X. "` |
| `[" The user asks about X. Here is my response: bar baz"]` | `" The user asks about X. "` | `" "` | `" The user asks about X. "` |
| `[" foo bar Here is my response:"]` | `" foo bar "` | `""` | `" foo bar "` |

```bash
pytest tests/reasoning/test_granite_reasoning_parser.py   # 32 passed (the 5 new cases fail on main)
pytest tests/reasoning tests/parser --ignore=tests/parser/cohere   # 6799 passed
pre-commit run --files vllm/reasoning/granite_reasoning_parser.py tests/reasoning/test_granite_reasoning_parser.py   # passed
```

## Details

- `_get_delta_message_with_both_bounds` derived the reasoning start from `len(reasoning) + len(response seq) + len(content) - 1`, ignoring the start-of-reasoning sequence; it now slices by absolute positions in `current_text`.
- `_get_content_sections` cut the reasoning one character short once the response sequence was found.
- Text ending exactly with the response sequence went to the no-response branch, which returned `None`; any text containing the complete response sequence now goes through `_get_delta_message_with_both_bounds`.

Every mismatch left with this PR alone has the start sequence and the next tokens in the first delta:

```
deltas:    ['Here is my thought process: foo bar', ' Here is my response:']
reasoning: 'Here is my thought process: foo bar '
```

That is the leak #50303 fixes. The two PRs touch adjacent lines ([L222](https://github.com/vllm-project/vllm/blob/372cb983c1f92555738ebdbfc64a4c2d8935c3b1/vllm/reasoning/granite_reasoning_parser.py#L222)), so whichever lands second needs a small rebase.
