# [ROCm][CI][Bug] granite on gfx942/950 has bad accuracy when AITER on

[Upstream PR](https://github.com/vllm-project/vllm/pull/63518) · state: open · merged: False

## Original PR description

## Overview

1. On gfx942/950, when head_size=128 and AITER is enabled (ROCM_AITER_FA is chosen), AITER will use the ASM attn kernel which will silently drop sink (this is an AITER bug and the PR for it is https://github.com/ROCm/aiter/pull/6906). So we need to reroute those models with sinks to unified_attention (when the AITER PR gets merged and deployed, we will remove this reroute logic);
2. Sink in ROCM_AITER_FA could be wrongly used multiple times instead of just once. This bug is also fixed;
3. New test case is added to make sure sink is applied correctly.

## Validation

models/language/generation/test_granite.py is now able to finish successfully on gfx942/950 with AITER on.
