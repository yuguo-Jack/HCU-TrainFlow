# [Transformers backend] Support Mamba2 (SSD) layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/59224) · state: open · merged: False

## Original PR description

## Purpose

The Transformers modeling backend cannot run linear attention models today, because Transformers' linear attention layers have no equivalent of the attention interface for vLLM to plug into. huggingface/transformers#49186 (draft) adds one: a linear attention layer keeps its projections, gating and output projection, and dispatches only its stateful core (causal conv, recurrence, state handling) through a per-mechanism registry, starting with `ALL_SSD_FUNCTIONS` for Mamba2's SSD core. This PR is the vLLM side, and validates that interface.

- **`Mamba2SSM`** is split out of `MambaMixer2`: it owns the state, the conv + SSD op path, kernel warmup and the state shape/dtype, but no weights. `MambaMixer2` subclasses it with the same signature, weights, layer names and `vllm.mamba_mixer2` op, so native models are unchanged. A new `vllm.mamba2_ssd` op takes `hidden_states_B_C` and `dt` already split.
- **`SSDFuser`** detects Transformers mixers that call `ALL_SSD_FUNCTIONS` (the same AST check as `AttentionFuser`, now parameterised by registry). `TransformersMamba2SSM` is attached to each one, the way `Attention` is attached to attention modules. It reads its weights from the HF mixer and caches `A = -exp(A_log)` after loading. `vllm_ssd_forward` is registered as `"vllm"`.
- **New model classes**, `TransformersAttentionFreeForCausalLM`, `TransformersHybridForCausalLM` and `TransformersMoEHybridForCausalLM`, are selected from `layer_types` and carry the Mamba state interfaces.
- The torch.compile decorator now only lists dynamic args that the decoder's `forward` accepts, since attention free decoders (e.g. `Mamba2Model`) take no `position_ids`.

Tensor parallelism is not supported yet and raises `NotImplementedError`. It needs a rewriting fuser that shards `in_proj` (5 segments with B/C group replication), `conv1d`, `A_log`/`D`/`dt_bias` and the gated norm like `MambaMixer2` does.

Not a duplicate: no open PR adds linear attention support to the Transformers modeling backend (searched "transformers backend mamba", "transformers backend linear attention", "Transformers modeling backend hybrid", "mamba2 transformers backend"). #54993 also touches `mamba_mixer2.py` (batch-invariant Mamba2 prefill), so one of the two will need a rebase.

## Test Plan

On macOS (CPU platform) against huggingface/transformers#49186, with tiny random Mamba2 (2 SSD layers) and Bamba (2 SSD + 2 attention layers) checkpoints saved from HF configs:

- `LLM(model, model_impl="transformers", dtype="float32", enforce_eager=True)`, 3 prompts of different lengths batched together, 8 greedy tokens with top-5 logprobs, compared against native vLLM (`model_impl="vllm"`) and Transformers `generate`.
- Native Mamba2 before and after the `Mamba2SSM` split.
- `pytest tests/models/transformers`
- `pre-commit run --files <changed files>` (including mypy)

## Test Result

|---|---|---|---|
| Mamba2 | `TransformersAttentionFreeForCausalLM` | identical tokens, max logprob diff 3.3e-06 | bit-identical |
| Bamba | `TransformersHybridForCausalLM` | identical tokens, max logprob diff 9.5e-07 | n/a (native removed in 0.23.0) |

- Native Mamba2 output is byte-identical before and after the split.
- `tests/models/transformers`: 146 passed. The other 13 fail before any model code runs on this machine (the CPU backend cannot reserve the default 92% of memory, or Model Runner V2 needs Triton).
- pre-commit passes.
