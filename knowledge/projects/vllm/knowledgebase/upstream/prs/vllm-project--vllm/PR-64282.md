# [Model] Add Nemotron-3.5-Transcribe

[Upstream PR](https://github.com/vllm-project/vllm/pull/64282) · state: closed · merged: True

## Original PR description

## Overview

Adds NVIDIA Nemotron-3.5-Transcribe (`Nemotron3_5TranscribeForConditionalGeneration`), a speech-language model: a
native audio tower whose embeddings replace `<|audio|>` placeholders in the prompt of the existing NemotronH decoder.
It loads the released checkpoint `nvidia/NVIDIA-Nemotron-3.5-Transcribe-30B-A4B` and its FP8 and NVFP4 variants, serves
chat completions with audio and `/v1/audio/transcriptions`, and supports MTP and DFlash2 speculative decoding. The PR adds model files plus
the usual registry, config, docs and test entries, and, in its own commit, a small DFlash2 fix in shared
speculative-decoding code; it does not change the engine, scheduler or API server.

## Claims

- New architectures `Nemotron3_5TranscribeForConditionalGeneration` and `Nemotron3_5TranscribeMTPModel` (MTP draft).
- Native audio tower: log-mel features, the Parallel Expert Encoder (a transformer ASR encoder and an online
  Sortformer speaker branch, fused), and a projection. No Transformers implementation is needed.
- Loads the released checkpoint's NeMo SpeechLM layout (`model_type: nemo_speechlm`, architecture
  `Nemotron3_5TranscribeForConditionalGeneration`). The checkpoint's CTC timestamp head is skipped; word timestamps
  are a planned follow-up.
- Loads the FP8 and NVFP4 repos (`-FP8`, `-NVFP4`; ModelOpt FP8 and mixed FP8/NVFP4 recipes). Their decoder uses
  Hugging Face NemotronH names, one tensor per expert. The audio tower's linear layers are vLLM `ReplicatedLinear`
  layers built with the quantization config, so the recipe quantizes the ASR encoder to FP8 as it does the decoder.
  The MTP draft keeps the recipe, so the FP8 MTP head loads with its scales.
- Audio batching: a clip is batched only with clips that span as many 40 s encoder windows, and padding frames are
  zeroed before the speaker head's convolution, so a clip's result does not depend on its batch.
- `/v1/audio/transcriptions` splits long audio into pieces of up to one hour; a chat request takes one clip of up to
  one hour by default.
- DFlash2 works with this target. On main, a request in chunked prefill anchored on `<|audio|>`, past the draft
  vocabulary, and the selector's codebook lookup failed a device-side assert. The DFlash2 commit clamps the anchor
  and keeps top-k candidates inside the draft vocabulary.
- Accuracy matches the NeMo reference implementation within its run-to-run spread on the Open ASR Leaderboard
  English and multilingual quick sets; with the FP8 and NVFP4 repos, WER stays within 0.1 of the NeMo reference
  running the same checkpoints, and MTP accepts as many drafts.

## Details

- Native tower: the audio encoder has no public Transformers implementation, so it is implemented in vLLM, with the
  NeMo checkpoint names (`perception.*`).
- Names: the checkpoint declares `nemo_speechlm`, the model type of every NeMo SpeechLM checkpoint; the architecture
  name selects this model. The config class refuses other NeMo SpeechLM architectures. A checkpoint with this model's
  structure (the Parallel Expert Encoder on a NemotronH decoder) under NeMo's generic name, as older exports have,
  gets the `architectures` value to set in its `config.json`; others are pointed to the NeMo Speech vLLM plugin.
- MTP: the drafter shares the target's embedding and LM head. Its weight filter accepts the checkpoint's `llm.mtp.*`
  names, so a sharded checkpoint loads only the shards that hold the MTP head.
- DFlash2 fix (separate commit): the anchor clamp in `qwen3_dflash2.py`; `get_top_k_tokens` and `get_top_tokens` in
  `logits_processor.py` mask columns past the processor's vocabulary, as `_get_logits` drops them; the DFlash2
  candidate processor is sized by `min(get_vocab_size(), config.vocab_size)`, so targets whose vocabulary is not
  larger than the draft's behave as before. The 10 head rows past the draft vocabulary are zero, so the candidate
  path rarely fires; the anchor path crashed every smoke run.
- Pre-review: @Isotr0py reviewed this change privately before the launch and approved it.
- Model Runner V2 only: all validation ran on V2, the default on main.
- The decoder's Mamba SSM state dtype comes from the decoder config (`MODELS_CONFIG_MAP` entry), as for NemotronH.
- Long audio: the encoder cache is sized from the `--limit-mm-per-prompt` audio length, so a longer configured clip
  is admitted. Server-wide decode limits (`VLLM_MAX_AUDIO_DECODE_DURATION_S`, 600 s by default, and the 25 MB upload
  limit) still apply and are documented in the supported-models note.
- Thinking: the chat template turns thinking on by default; transcription servers should pass
  `--default-chat-template-kwargs '{"enable_thinking": false}'` (documented).
- Limitation: the audio tower runs replicated on every tensor-parallel rank.
- Quantized repos: `hf_to_vllm_mapper` maps the recipe's layer names (`backbone.*`, `lm_head`, `perception.*`) onto
  `language_model.*` and `audio_tower.*`. The tower's linear layers flatten their input to 2-D, because vLLM's
  quantized kernels take `(tokens, features)`. The NVFP4 recipe declares no KV-cache quantization; the NeMo reference
  ran it with `--kv-cache-dtype fp8`, as did the validation above. vLLM's FP8 linear layer adds the bias after
  rounding, where the NeMo reference adds it inside the CUTLASS kernel (one bf16 step on some elements).
- Memory note: the quick-set runs on main used `--gpu-memory-utilization 0.85 --max-num-batched-tokens 8192
  --max-num-seqs 512` on one 96 GB GPU (0.75 for the FP8 and NVFP4 repos). FlashInfer's autotune runs after vLLM's
  memory plan: with 32,768 batched tokens, start-up ran out of memory at both 0.85 and 0.80, and the NVFP4 repo did at
  0.85 even with 8,192. This is not specific to this model.
- Not in this PR: CTC word timestamps (follow-up through the transcription API, with forced alignment) and the
  Transformers-layout conversion of the checkpoint (Hugging Face's Transformers port uses its own layout and
  `model_type`).
- Duplicate check: no open PR adds this architecture.
