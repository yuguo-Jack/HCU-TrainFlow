# [Bugfix][Spec Decode] Recycle normalized hidden state in GLM-4 MoE MTP

[Upstream PR](https://github.com/vllm-project/vllm/pull/62986) · state: closed · merged: False

## Original PR description

## Overview

`Glm4MoeMultiTokenPredictorLayer.forward` returns the residual sum *before* the final `shared_head.norm`. As a
result, every chained draft step (`num_speculative_tokens >= 2`) feeds an un-normalized hidden state into the next
step's `hnorm`. This PR applies the contract DeepSeek MTP already uses (#45895, #47448):

- return `(pre_norm, shared_head(pre_norm))`;
- register `Glm4MoeMTPModel` in `SpecDecodeBaseProposer.model_returns_tuple()` so the V1 proposer unpacks the tuple.

**Relation to #62234 (why this is a separate PR):** #62234 fixes the same recycle via a fused `(post, post)` return and also covers GLM-4 Lite / GLM-OCR, but as of 2026-10-21 it does not register those architectures in `model_returns_tuple()`, so under Model Runner V1 the proposer indexes the tuple (`llm_base_proposer.py` ~L614) and fails even at k=1 (see review there). This PR is the minimal DeepSeek-style variant for `Glm4MoeMTP` that includes the V1 registration and a CPU-CI test of it. Happy to close this in favour of #62234 once that gap is folded in there — the goal is just to get the V1 path right.

Companion (independent, merges cleanly in either order): #62987 enables `torch.compile` for the same drafter.

## Claims

- **Draft quality:** chained draft steps (k >= 2) receive the post-final-norm hidden state, matching DeepSeek MTP,
  GLM-5 Next, and SGLang's GLM NextN.
- **Unchanged:** draft logits are unchanged, since `compute_logits` still normalizes the first tuple element. k=1 is
  unchanged. Target-model outputs are unchanged, because speculative decoding is lossless.
- **Runner coverage:** works on both Model Runner V1 (via the `model_returns_tuple` registration) and MRV2, which
  unpacks tuples generically in `target_dependent_ar` and `multi_module_mtp`.

## Validation

- **Unit tests:**
  - `tests/v1/spec_decode/test_mtp.py::test_glm4_mtp_normalizes_feedback_without_changing_logits` uses non-uniform
    RMSNorm weights so that pre-norm and post-norm values differ. It asserts that the feedback state is normalized
    and that the logits input is unchanged.
  - `tests/v1/spec_decode/test_llm_base_proposer_sampling.py::test_mtp_model_returns_tuple[Glm4MoeMTPModel-True]`.
  - Against main source, 3 cases fail and 3 control cases pass. With the fix, all 6 pass.
- **Lint:** `ruff check`, `ruff format --check`, `typos` and `mypy` (py3.11) are clean on the changed files.
- **End-to-end (earlier run):** GLM-4.7-derived FP8 checkpoint, TP8, 8×H100, vLLM 0.28, agentic multi-turn traffic.
  - Position-2 acceptance at k=2: about 0.29 before, 0.85 after.
  - k=3: 2.47 accepted draft tokens per step.
  - Caveat: the before and after numbers come from different load levels, not a paired run.
- **E2E on current main: pending.** A paired k=1/2/3 run on a public checkpoint (zai-org/GLM-4.5-Air), MRV2 and `VLLM_USE_V2_MODEL_RUNNER=0`, per-position acceptance and gsm8k, will be posted here before this leaves draft.

## Details

- **Root cause:** the layer forward ended with `hidden_states = residual + hidden_states`, and `shared_head` was
  applied only inside `compute_logits`. The proposer copies the second return value into the next step's
  `previous_hidden_states`.
- **Tradeoff:** this variant normalizes twice per step (once for feedback, once inside `compute_logits` on the
  sampled rows). It keeps the existing `compute_logits` contract and mirrors `deepseek_mtp.py`. #62234's fused
  variant avoids the second norm; either variant needs the V1 registration.
- **Scope:** GLM-4 Lite and GLM-OCR MTP have the same pattern but are left for #62234.
- **CI:** `test_mtp.py` runs in GPU CI (`v1-spec-decode`), and `test_llm_base_proposer_sampling.py` also runs in CPU
  CI. Full GLM-4 checkpoints are too large for CI.
