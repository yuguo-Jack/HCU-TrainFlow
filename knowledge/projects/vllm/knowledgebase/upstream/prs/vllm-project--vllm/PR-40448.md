This pull request updates the documentation and validation logic to clarify that per-attention-head KV-cache quantization is currently only supported with the FLASH_ATTN backend. Calling `get_class()` inside `pytest.mark.parametrize` triggers the import of the `flashinfer` module during test collection. This will cause a `ModuleNotFoundError` or `ImportError` on any environment where `flashinfer` is not installed (e.g., non-CUDA platforms or CPU-only CI runners), preventing the entire test suite from collecting. 

The backend class should be resolved lazily inside the test function, and the test should be skipped if the required backend is unavailable.

```python
@pytest.mark.parametrize(
    ("backend", "expected_match"),
    [
        (
            AttentionBackendEnum.FLASHINFER,
            "Per-attention-head KV-cache quantization is currently supported only with FLASH_ATTN, not FLASHINFER",
        ),
        (
            CustomAttentionBackend,
            "per-head quant scales not supported",
        ),
    ],
)
def test_validate_configuration_reports_per_head_quant_scale_support(
    backend: AttentionBackendEnum | type[AttentionBackend],
    expected_match: str,
):
    if isinstance(backend, AttentionBackendEnum):
        if backend == AttentionBackendEnum.FLASHINFER:
            pytest.importorskip("flashinfer")
        backend_cls = backend.get_class()
    else:
        backend_cls = backend
```

File: `vllm/v1/attention/backend.py` · line None

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

This change introduces a call to the abstract method `get_name()` within the base class's `validate_configuration` method. This will raise a `NotImplementedError` if `validate_configuration` is called on the `AttentionBackend` base class itself or any partial implementation that hasn't defined `get_name`, which is a regression in the class's robustness. 

Furthermore, hardcoding specific backend names like `"FLASHINFER"` in the base class violates modularity and the Open/Closed Principle. A more robust approach would be to handle the name check safely or move the specific validation logic to the backend itself.

```python
            # Avoid abstract method call on base class
            name = None
            try:
                name = cls.get_name()
            except NotImplementedError:
                pass

            if name == "FLASHINFER":
                invalid_reasons.append(
                    "Per-attention-head KV-cache quantization is currently "
                    "supported only with FLASH_ATTN, not FLASHINFER"
                )
            else:
                invalid_reasons.append("per-head quant scales not supported")
```
