# [Doc][Recipe] Kimi-K3: drop removed retention and RPC timeout envs

[Upstream PR](https://github.com/vllm-project/vllm/pull/64586) · state: open · merged: False

## Original PR description



## Overview

Kimi-K3 sets `VLLM_PREFIX_CACHE_RETENTION_INTERVAL` and `VLLM_RPC_TIMEOUT`, which no longer exist in `vllm/envs.py`, so vLLM silently ignores both.

## Claims

- Drops both envs from every `env` block, guide `export` line and runbook env list.
- No behaviour change: `--prefix-cache-retention-interval` already defaults to `0`, the value set here, and nothing reads `VLLM_RPC_TIMEOUT`.

## Validation

```
grep -c 'VLLM_RPC_TIMEOUT\|VLLM_PREFIX_CACHE_RETENTION_INTERVAL' vllm/envs.py  (main) → 0
grep 'prefix_cache_retention_interval:' vllm/config/cache.py                  (main) → default=0
node scripts/validate-source.mjs --source vllm --dir recipes  (vllm-project/recipes) → valid
Kimi-K3 generated JSON: RPC_TIMEOUT 3 → 0, RETENTION_INTERVAL 5 → 0; VLLM_USE_DIRECT_DCP_A2A 9 → 9 (control)
```

Not served; the check is config-level only.
