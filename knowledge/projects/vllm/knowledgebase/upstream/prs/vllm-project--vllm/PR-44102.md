# [Bugfix][Tool Parser] Preserve raw control characters in Pythonic arguments

[Upstream PR](https://github.com/vllm-project/vllm/pull/44102) · state: open · merged: False

## Original PR description

## Overview

Preserve tool calls when `pythonic` or `llama4_pythonic` output contains a raw newline inside a string argument, including streaming and parallel calls.

Fixes https://github.com/vllm-project/vllm/issues/61954

## Claims

- Reuse `escape_ctrl_chars_in_strings` before `ast.parse` and `make_valid_python`; decoded argument values retain the original control characters.
- Keep normal calls, quoted/escaped strings, non-tool text, regex-timeout handling and parallel-call reconstruction covered by the existing parser suites.
- Checked the issue and open PRs by issue ID and parser/control-character keywords; no equivalent fix for these two parser implementations was found in that search.

## Details

Raw control characters make Python string literals invalid. Complete extraction falls back to text; streaming completion cannot form a valid candidate and loses the tool call. Applying the existing escaping helper before those two parsing entry points preserves the intended argument values. No parser interface, model execution, or new dependency is introduced.

- vadiklyutiy · comment · 2026-10-21T23:19:13Z · [source](https://github.com/vllm-project/vllm/pull/44102#issuecomment-6328730452)

Thanks for picking this up. I checked this PR (head `27b5d3e`): it fixes the reported input in both parsers, streaming and non-streaming. However, it always runs `escape_ctrl_chars_in_strings` before `ast.parse` / `make_valid_python`, and that changes outputs that parse fine on `main`. The helper does not know about string prefixes or triple quotes:

1. **Raw strings silently lose their control characters.** `r'''x = 1<NL>y = 2'''` and `r'a<TAB>b'` are valid Python. On `main` the argument is `"x = 1\ny = 2"` / `"a\tb"`. With this PR, the newline or tab is turned into an escape sequence, and inside a raw string that stays a backslash plus a letter. The client gets `"x = 1\\ny = 2"` in valid JSON and cannot tell it is wrong. This happens in both parsers and in every mode.
2. **A triple-quoted string with an apostrophe loses the whole call list (non-streaming).** For `[write_file(content='''it's<NL>ok'''),<NL> get_time()]`, `main` returns both calls. With this PR, the helper loses track of the quotes at `it's` and escapes the newline *between* the calls. `ast.parse` then fails, and the whole output comes back as content.

Minimal repro on the helper:

```python
import ast
from vllm.tool_parsers.utils import escape_ctrl_chars_in_strings as esc

def arg(src):
    return ast.literal_eval(ast.parse(src).body[0].value.elts[0].keywords[0].value)

print(repr(arg("[f(x=r'a\tb')]")))       # 'a\tb'   (main)
print(repr(arg(esc("[f(x=r'a\tb')]"))))  # 'a\\tb'  (this PR)
ast.parse(esc("[f(x='''it's\nok'''),\n g()]"))
# SyntaxError: unexpected character after line continuation character
```

This also contradicts the description's claim that decoded values "retain the original control characters".

Suggestion: escape only when the text does not parse as is, so valid output keeps today's result.

```python
try:
    module = ast.parse(model_output)
except (SyntaxError, ValueError):
    module = ast.parse(escape_ctrl_chars_in_strings(model_output))
```

And in streaming:

```python
valid_and_added_text = make_valid_python(current_text)
if valid_and_added_text is None:
    valid_and_added_text = make_valid_python(
        escape_ctrl_chars_in_strings(current_text)
    )
```

A test row with `r'''line1<NL>line2'''` (expecting a real newline in the argument) in both parser suites would guard against this. It passes on `main` and fails on the current PR.

One caveat of the fallback in streaming: once a later string needs escaping, the stream switches to the escaped form. An earlier raw string with a control char, or a triple-quoted string with a CR, may then be re-sent with a different value. Such outputs already failed visibly before. The real fix belongs in the shared helper (skip `r`-prefixed strings, track triple quotes), which lfm2 also uses, so it is probably a separate PR.

You may also take a look on https://github.com/vadiklyutiy/vllm/tree/lyutiydoctor/20261021-173201-vllm-61954
