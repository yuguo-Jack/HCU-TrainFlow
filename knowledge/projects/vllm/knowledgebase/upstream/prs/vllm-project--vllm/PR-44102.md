# [Bugfix][Tool Parser] Preserve raw control characters in Pythonic arguments

[Upstream PR](https://github.com/vllm-project/vllm/pull/44102) · state: open · merged: False

## Original PR description

## Overview

Preserve tool calls when `pythonic` or `llama4_pythonic` output contains a raw newline inside a string argument, including streaming and parallel calls.

Fixes https://github.com/vllm-project/vllm/issues/61954

## Claims

- Reuse `escape_ctrl_chars_in_strings` before `ast.parse` and `make_valid_python`; decoded argument values retain the original control characters.
- Keep normal calls, quoted/escaped strings, non-tool text, regex-timeout handling and parallel-call reconstruction covered by the existing parser suites.
- Checked the issue and open PRs by issue ID and parser/control-character keywords; no equivalent fix for these two parser implementations was found in that search.

## Validation

On main source `026f6ab2689397e64c1f53a5ac57d37c4dc46b67`, both parser suites pass: **48 passed**. Restoring the baseline parser files while retaining the added cases produces **8 failed, 40 deselected** for `-k raw_newline`.

```sh
PYTHONPATH=/work/vllm HF_HUB_OFFLINE=1 HF_HUB_CACHE=/work/gpt2-cache \
TORCH_DEVICE_BACKEND_AUTOLOAD=0 VLLM_PLUGINS= PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
/work/.venv/bin/python -m pytest --confcutdir=tests/tool_parsers \
  tests/tool_parsers/test_pythonic_tool_parser.py \
  tests/tool_parsers/test_llama4_pythonic_tool_parser.py -q
```

The actual GPT-2 tokenizer fixture was used, with official tokenizer files cached at revision `607a30d783dfa663caf39e06633721c8d4cfcd7e`. Python 3.12.13, PyTorch 2.10.0+cpu, pytest 9.1.1. Changed-file pre-commit checks passed, including the repository-pinned Ruff 0.14.0.

This CPU regression validates parser outputs and reconstructed arguments. No model-generation, GPU/NPU, serving-performance or upstream-CI result is claimed.

## Details

Raw control characters make Python string literals invalid. Complete extraction falls back to text; streaming completion cannot form a valid candidate and loses the tool call. Applying the existing escaping helper before those two parsing entry points preserves the intended argument values. No parser interface, model execution, or new dependency is introduced.
