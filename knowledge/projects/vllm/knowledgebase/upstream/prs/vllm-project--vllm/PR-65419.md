# [ROCm][Perf][Attention] AITER Gluon paged attention reduce + output gate fusion (Qwen3.8-27B)

[Upstream PR](https://github.com/vllm-project/vllm/pull/65419) · state: open · merged: False

## Original PR description

## Overview

On ROCm, apply the Qwen3.5 attention output gate (`attn * sigmoid(gate)`) inside the `ROCM_AITER_FA_GLUON` decode, in AITER's split-K reduce, instead of a separate kernel per full-attention layer. The model now hands the gate to the attention layer; backends that cannot fuse it get `out * sigmoid(gate)` from `Attention.forward`, so their graphs do not change.

Stacked on #65248; only the last commit belongs to this PR. Requires [ROCm/aiter#6842](https://github.com/ROCm/aiter/pull/6842), which dispatches to Triton reduce kernel instead of HIP when output_gate is supplied as an argument.

The AITER PR also includes a fix for zero-length sequences: without it, padded CUDA-graph decode rows come out of the gated reduce as NaN.

## Claims

- 16 fewer kernels per decode step on Qwen3.8-27B (one per full-attention layer): the Inductor `mul`/`sigmoid` kernel is gone and the gate copy is not needed.
- Serving, against #65248: within ±0.5% total tok/s and mean TPOT at c4–c64 (+0.4% tok/s at c64); GSM8K unchanged.
- No change for other backends or models: without backend support, `Attention.forward` applies the gate itself.

### Tests

- `tests/kernels/attention/test_rocm_aiter_fa_gluon_output_gate.py` (new, ROCm only, needs AITER with `output_gate`): 32/32 pass. A compiled gated-attention model against an eager `attn * sigmoid(gate)` reference, for supported and unsupported backends, flat and per-head gates, 1–128 tokens; checks the `sigmoid` count and that the attention op carries `output_gate` only when supported.

## Details

- `Attention.forward(..., output_gate=None)`: when the impl supports it (`fused_output_gate_supported()`, read once at construction), the gate goes to the attention op as `[T, H, D]`; otherwise `Attention.forward` returns `out * sigmoid(gate)`.
- `unified_attention_with_output` gains `output_gate`, passed to `impl.forward` only when set. The 8 `auto_functionalized(ATTN_OP, ...)` patterns in `attn_quant_fusion.py` name `output_gate=None`, because the pattern matcher compares kwargs exactly.
- `AttentionImplBase.fused_output_gate_supported()` defaults to False.
- `ROCM_AITER_FA_GLUON` supports it when a layer takes the gluon decode and AITER has `output_gate`. Single-token decodes get the gate in the split-K reduce (launches with more than one split); every other token gets `mul_(sigmoid(gate))` in the impl.
- `Qwen3NextAttention._project_qkv_gate(..., flat_gate=True)`: the attention path passes `flat_gate=False`, so the gate stays a `[T, H, D]` view of `qkv` and needs no copy kernel. The NVIDIA `fused_sigmoid_gate_mul` path and the Qwen4Exp callers keep the flat gate.

The fused path is ROCm `ROCM_AITER_FA_GLUON` only; every other backend applies the gate in `Attention.forward`.
