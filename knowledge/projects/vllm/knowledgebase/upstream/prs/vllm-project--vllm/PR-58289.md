# [Feature][KVConnector][DSv4.1] Encoder-only prefill with NIXL P/D

[Upstream PR](https://github.com/vllm-project/vllm/pull/58289) · state: open · merged: False

## Original PR description

## Purpose

Implement encoder-only Prefill for DeepSeek-V4.1-Flash P/D serving with the direct `NixlConnector` pull path. This follows the full-prompt, cache-hit-replay design in RFC #57738 and builds on the asymmetric P/D direction in RFC #57383: P runs L0-L19 for the whole prompt and produces L20 Main KV/Indexer K, while D reconstructs the adopted replay tail through the full target and samples the first token.

This PR makes the NIXL handoff concrete without depending on the Mooncake implementation in #57872. Both connector paths share the same execution boundary, but their request and transfer protocols differ. P still loads the full target weights in this first change; weight omission is separate work.

I'll validate this PR on real GPU soon and check whether it is better to forward NIXL version before Mooncake.

## Implementation

- Add opt-in `KVTransferConfig.dsv41_encoder_only_prefill` for dedicated `NixlConnector` producer and consumer roles. Restrict this PR to the existing pull connector.
- On P, run L0-L19 normally, execute the L20 pre-mix and canonical compressor/Main-KV/Indexer-K writes, and skip L20 attention/FFN, L21-L39, final norm, LM head, sampling, and draft work.
- Finish a cache-only P request after its full prompt is consumed without generating a token. Each P worker synchronizes its cache writes before completion. The NIXL proxy marks the P request `cache_only=true`, then forwards the remote block/engine metadata returned in P's zero-token response to D for a normal NIXL pull.
- Select transferable groups from V4.1's Main-KV and Indexer-K owner layers. Missing, duplicate, or mixed global/local groups fail closed. Target SWA, compressor continuation, and draft groups stay D-local; D uses the existing bounded-replay path.
- For same-layout, non-DCP pulls, align producer blocks to the range D actually adopts after bounded replay. Use D's per-group local prefix counts to distinguish cached prefix blocks from a discarded partial P tail block; reject mismatched block geometry.
- Limit the initial configuration to NVIDIA, MRV2, PP=1, no PCP or microbatching, a 128-token bounded-replay window and the 40-layer/L20 source topology, text-only requests, and no prompt logprobs. P requires `--no-async-scheduling`; neither role enables speculative decoding in this first path. NIXL's compatibility hash includes drafter settings, so an asymmetric P-without-drafter/D-with-DSpark pair needs separate support.

Enable the option on both server roles:

```json
{"kv_connector":"NixlConnector","kv_role":"kv_producer","dsv41_encoder_only_prefill":true}
{"kv_connector":"NixlConnector","kv_role":"kv_consumer","dsv41_encoder_only_prefill":true}
```

Use the NIXL toy proxy with the dedicated P and D instances. Conventional NIXL requests ignore the proxy's `cache_only` marker when the option is off.

## Relationship to other work

RFC #57738 analyzes NIXL pull as its initial path. #57872 implements the same V4.1 execution boundary for direct Mooncake P/D and has separate H20 measurements; it does not validate NIXL. This PR does not bring Mooncake's generic empty-pull completion change into NIXL. NIXL already tracks whether D awaits KV for a real transfer. #56227 provides the bounded-replay foundation used on D.

Open PRs were checked by RFC number and by NIXL/encoder-only/V4.1 keywords. No other open PR implements this boundary on the direct NIXL pull path. The model-side execution code currently overlaps #57872; I am happy to rebase or stack the shared part if maintainers choose a common base, while keeping connector-specific handoff and tests reviewable.
