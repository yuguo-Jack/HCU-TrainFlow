# [Perf][DSv4.1] Fused all-reduce + mHC without NVLink multicast

[Upstream PR](https://github.com/vllm-project/vllm/pull/64144) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

The DeepSeek-V4.1 `latency_specialized` decode (#61868) refuses to start without an NVLink multicast mapping for its fused all-reduce + mHC mailbox. This PR adds a unicast publish path, used automatically when no multicast mapping is available.

## Claims

- The specialized decode runs when the NVLink partition has no free multicast groups. A partition has a fixed number of them (16 on our NVL72), shared by every engine in it, so engines that start later run out.
- Same single-request speed as multicast at TP4 on GB300 (DSpark, Tetris prompt: 1,159 tok/s).
- Multicast stays the default where it is available; `VLLM_DSV41_MHC_UNICAST=1` forces unicast (for testing).

## Validation

On vLLM nightly `5d35ce39` (FlashInfer 0.7.2.post1, with the version gate from #63914 applied locally), GB300:

| Test | Result |
|---|---|
| `test_numerics.py` (4 GPUs), `multicast` and new `unicast` cases | both passed. The partition had no free multicast groups at the time, so both ran unicast |
| `test_layers.py` (4 GPUs, switch on vs off) | passed |
| TP4 serve with DSpark | specialized decode on, logs "Lamport all-reduce publishes with unicast NVLink stores", 1,159 tok/s single request (earlier base `c50aca1`, same change) |
| TP8 serve over two trays (with #64146 on top) | specialized decode on, unicast, correct answers and tool calls |

Not run: `VLLM_GPU_SYNC_CHECK=error`. The change is inside the captured decode graph and adds no host reads.

## Details

- When the symmetric-memory rendezvous gives a rank no multicast mapping, the publish kernels and the publishing `wo_b` GEMM store into every rank's mailbox through a table of their base addresses, instead of one `multimem.st`.
- Each rank picks its path at startup from its own mapping. Both paths write the same slots of every rank's mailbox, so ranks that pick differently still produce the same result.
- This takes TP-1 more NVLink stores per value than multicast. At decode batch sizes the kernel is latency-bound, so the speed is the same.
- CI: `test_numerics.py` runs in the nightly 4×B200 DeepSeek-V4.1 step, and the new `unicast` case runs there too.
