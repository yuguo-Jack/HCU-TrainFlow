# [Bugfix] Keep the MiniCPM-V-4.6 vision tower unquantized for GPTQ and AWQ checkpoints

[Upstream PR](https://github.com/vllm-project/vllm/pull/59978) · state: open · merged: False

## Original PR description



## Overview

Fixes #58943. The official MiniCPM-V-4.6 GPTQ and AWQ checkpoints store the vision tower unquantized, but vLLM built it as quantized, so the server crashed at startup. With this PR, vLLM builds these layers unquantized, which matches the checkpoints.

## Claims

- `openbmb/MiniCPM-V-4.6-Thinking-GPTQ` now loads and serves. Before, it failed during weight loading with `AttributeError: 'QKVParallelLinear' object has no attribute 'data'`.
- `openbmb/MiniCPM-V-4.6-AWQ` now loads and serves. Before, it failed while building the vision MLP with `ValueError: The input size is not aligned with the quantized weight shape`.
- `openbmb/MiniCPM-V-4.6-GPTQ` and `openbmb/MiniCPM-V-4.6-Thinking-AWQ` have the same quantization config as the two above (read from the Hub). They take the same code paths, but I did not run them.
- GPTQ with `modules_in_block_to_quantize`: a layer is now built quantized only if the checkpoint stores it quantized. Language-model layers do not change.

## Validation

Hardware: 1x NVIDIA GeForce RTX 3090 (24 GiB, sm_86). Base: commit `18f8f96025b556071eb627076f94df560fbd3a22` (`0.30.1rc1.dev630+g18f8f9602`), with and without this patch.

Reproducer:

```
python -m vllm.entrypoints.openai.api_server --model openbmb/MiniCPM-V-4.6-Thinking-GPTQ --trust-remote-code --max-model-len 2048
python -m vllm.entrypoints.openai.api_server --model openbmb/MiniCPM-V-4.6-AWQ --trust-remote-code --max-model-len 2048
```

| `openbmb/MiniCPM-V-4.6-AWQ` | 1 of 1 runs crash: `ValueError: The input size is not aligned with the quantized weight shape` (in `auto_awq.py` `create_weights` for `vpm.encoder.layers.0.mlp.fc2`) | 4 of 4 runs reach `Application startup complete.`, no traceback |

The `vllm/vllm-openai:nightly` image at the same commit shows the same two crashes. With the patch, the AWQ warning `Layer 'vpm.encoder.layers.0.mlp.fc2' is not supported by AutoAWQMarlin` is gone.

After startup, I sent one image chat request to each server (a 448x448 PNG with one shape on white, `temperature=0`). The answers were right. Red circle: GPTQ `shape: circle, color: red`, AWQ `A red circle.`. Blue square: GPTQ `shape: square, color: blue`, AWQ `A blue square.`.

Unit tests (new, CPU only, in existing files):


Layer check: 11 public GPTQ checkpoints that have `modules_in_block_to_quantize` were built on the meta device, once with the old code and once with the new. The only layers that changed are tower layers that the checkpoint stores unquantized: 28 vision `qkv_proj` layers in MiniCPM-V-4.6, and 148 vision and audio tower layers in `Vishva007/gemma-4-E4B-it-W4A16-AutoRound-GPTQ` (also named in the issue, not run end to end). No language-model layer changed. This includes `TheBloke/TinyLlama-1.1B-Chat-v1.0-GPTQ` @ `gptq-8bit--1g-actorder_True`, which CI loads.

## Details

In both checkpoints, every tensor under `model.vision_tower.` and `model.merger.` is a plain float `weight`/`bias`. Only `model.language_model.` linear layers have `qweight`/`qzeros`/`scales`. Each format had its own bug that built the tower as quantized anyway.

**GPTQ root cause.** `modules_in_block_to_quantize` holds names relative to one decoder block, such as `self_attn.q_proj`. When the list was present, `AutoGPTQConfig.maybe_update_config` returned early and kept these names as they were. `is_layer_gptq_quantized` then matches them as substrings against every linear layer in the model. The vision `qkv_proj` layers (`vpm.encoder.layers.N.self_attn.qkv_proj`, `vit_merger.self_attn.qkv_proj`) have the shards `self_attn.q_proj`/`k_proj`/`v_proj`, so they got `AutoGPTQLinearMethod` and no `weight`. `QKVParallelLinear.load_weights` then fell back to the module itself (`getattr(self, "weight", self)`) and failed on `param.data`.

**AWQ root cause.** `modules_to_not_convert` lists `model.vision_tower` and `model.merger`, without a trailing dot. The model's mapper only had `model.vision_tower.` and `model.merger.`, with the dot, so `apply_vllm_mapper` left the names unchanged. vLLM names the tower `vpm`, so `is_layer_skipped` never matched it, and every vision layer was built with AWQ. `fc2` has input size 4304, which is not a multiple of the group size 128, so `create_weights` raised.

**Fix.**

1. `AutoGPTQConfig.maybe_update_config` now always reads the safetensors metadata, which it already did when the list was missing. When `modules_in_block_to_quantize` is set, it keeps only the full names of layers that the checkpoint stores quantized and that match a listed name. This can only remove layers that the old rule marked quantized. It never adds one. If no metadata is found (for example a `.bin` checkpoint), the config's list is kept as before. Like the path without the list, this relies on the model's `hf_to_vllm_mapper` to turn checkpoint names into vLLM layer names.
2. `MiniCPMV4_6ForConditionalGeneration.hf_to_vllm_mapper` drops the trailing dot from `model.vision_tower.vit_merger`, `model.vision_tower` and `model.merger`. Module names in quantization configs are now mapped too, as in `bailing_moe_v3_vl.py` and `gemma4_mm.py`. Weight names map exactly as before: 0 of 1,229 (GPTQ) and 0 of 1,079 (AWQ) checkpoint tensor names change.
