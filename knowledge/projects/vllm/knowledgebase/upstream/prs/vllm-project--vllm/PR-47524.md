# [MRV2] Draw 64-bit uniforms for fp32 Gumbel sampling

[Upstream PR](https://github.com/vllm-project/vllm/pull/47524) · state: open · merged: False

## Original PR description

## Purpose

Improve the precision of the fp32 Gumbel sampling path (the default since #41775) at negligible cost. The fp64 path is unchanged.

main now derives the fp32 uniform from one 32-bit murmur3 hash, `(r32 + 0.5) * 2**-32`, so it never resolves below `2**-33`. With the flipped transform from #45996 (`-log(-log1p(-u))`, winning tail at `u -> 0`), that floor hard-caps the fp32 Gumbel noise at `33 * ln 2 ~= 22.9`. Since the noise minimum is ~-2.8, any token whose logit trails the top by more than ~25.7 nats can never be sampled.

This PR draws 64 random bits instead: `murmur3_uniform32` uses the same two hashes as `murmur3_uniform64` (seed/pos/offset plus the `0x9E3779B9` domain) and sums their exact 16-bit pieces smallest first into fp32 `(r64 + 0.5) * 2**-64`. The `u -> 0` tail now resolves down to `2**-65` (noise up to ~45, reachable gap ~47.9 nats) with no fp64 arithmetic, so the #41775 performance concern does not apply. All fp32 Gumbel-max callers (sampler, spec-decode draft/verify, watermark candidates, DSpark/DFlash2, fused Markov) go through `gumbel_noised_argmax` and stay consistent with each other. The rejection-sampler acceptance threshold still uses `tl_rand32` and is not affected.

Rebased onto murmur3 by @aoshen02 (AI-assisted).

Not a duplicate: searched open PRs for Gumbel/sampling-precision work; existing ones (#47386, #46499, #43249) touch stream decoupling, benchmarks, and non-finite logits — none address the uniform's resolution.

## Impact

Measured on HY4-FP8 rollouts (320 DAPO-Math prompts, ~1M sampled tokens): mean probability mass per token beyond the reachable gap, and the expected number of tokens that should have been sampled but cannot be.

| | Cutoff (nats) | Mean mass beyond cutoff / token | Expected truncated per 1.7e7 tokens | per 5e8 tokens |
|---|---|---|---|---|
| fp32 on main (32-bit) | 25.7 | 2.5e-8 | 0.42 | 12.3 |
| fp32, this PR (64-bit) | 47.9 | 9.5e-20 | 1.6e-12 | 4.8e-11 |

Sampler kernel (`gumbel_sample`, CUDA graph, vocab 120,832, GB200, us):

| Batch | fp32 (main) | fp64 | fp32 (this PR) |
|---|---|---|---|
| 1 | 6.3 | 9.1 | 6.5 |
| 64 | 31.0 | 58.8 | 34.0 |
| 512 | 200.6 | 411.4 | 224.6 |

e2e serving throughput (HY4-FP8, TP4xPP2, concurrency 1/32/128) is unchanged within noise.
