# [ROCm][DSV4][Perf] Pack sparse-MLA ragged decode metadata into graph buffers

[Upstream PR](https://github.com/vllm-project/vllm/pull/58352) · state: open · merged: False

## Original PR description

## Purpose

On ROCm, the DeepSeek-V4 / V4.1 sparse-MLA decode builders pack the ragged indices in two steps on every decode step: `build_ragged_indices_from_dense()` allocates scratch `counts`, `indptr` and `flat` tensors, then `_copy_ragged_to_graph_buffers()` copies `indptr` and `flat` into the persistent buffers that FULL decode CUDA graphs captured. This runs 3 times per decode step on V4 (C128A and SWA) and 7 times on V4.1 (SWA).

This PR:

- Adds `build_ragged_indices_from_dense_out()`, which runs the count → scan → compact kernels from #58058 directly into caller-owned buffers. Counts are written into `indptr[1:]` and scanned in place. `build_ragged_indices_from_dense()` becomes an allocating wrapper around it, so the `-1` filtering has one implementation.
- Uses it in the V4 C128A/SWA and V4.1 SWA decode `build()`. The gfx950 width narrowing that `_decode_gfx950_num_splits` reads is unchanged.
- Adds a ROCm `update_draft_decode_metadata()` that repacks the ragged SWA buffers in place, and sets `supports_draft_decode_metadata_update = True` on the ROCm SWA builders so fused multi-step draft decode can run. This path comes from #52628 (co-authored by Tres Popp).

Prefill callers of `build_ragged_indices_from_dense()` get the same output. #57860 fuses indptr into a different V4.1 pack kernel and composes with this PR.

## Test Plan

MI355X (gfx950), `--kv-cache-dtype fp8`, `VLLM_ROCM_USE_AITER=1`, main `72e7874fa6`.

- Unit: `pytest tests/v1/attention/test_deepseek_v4_rocm_metadata.py tests/kernels/attention/test_rocm_triton_attn_dsv4.py`. New cases put `-1` inside a row's valid length, cover `num_rows` filtering, scan sizes across block boundaries and empty input, and check that the V4 draft update rewrites the ragged buffers without replacing their storage.
- Micro: the production helpers at serving shapes, off-grid row counts, 5 % `-1` sentinels. Four consecutive runs per arm, the first discarded, median of runs 2–4.
- e2e: a fresh server per run, 4 runs per arm per block with the first discarded, one server on the host at a time. V4.1 adds `--tensor-parallel-size 2`. The MTP config adds `VLLM_USE_V2_MODEL_RUNNER=1` and `--speculative-config '{"method":"mtp","num_speculative_tokens":3}'`, the path that runs fused multi-step draft decode.

```bash
vllm serve deepseek-ai/DeepSeek-V4-Flash --kv-cache-dtype fp8 --max-model-len 8192 --no-enable-prefix-caching --trust-remote-code
vllm bench serve --model deepseek-ai/DeepSeek-V4-Flash --dataset-name random --random-input-len 1031 --random-output-len 509 \
    --random-range-ratio 0.25 --num-prompts 509 --max-concurrency 61 --request-rate inf --ignore-eos --seed 1234
```

- Accuracy: `lm_eval --model local-completions --tasks gsm8k --num_fewshot 5`, greedy, `max_gen_toks=256`, `seed=1234`. The base arm was run twice.
