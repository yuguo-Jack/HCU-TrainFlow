# [CI] Enroll a third batch of five steps in automatic sharding

[Upstream PR](https://github.com/vllm-project/vllm/pull/60757) · state: closed · merged: True

## Original PR description

## Purpose

Third batch of automatic sharding (vllm-project/ci-infra#700), following #60492 and #60662. This adds `automatic_shard: true` to five more steps whose commands are plain pytest and which run over 20 minutes as one job:

| Step | Planned shards |
|---|---|
| `v1-sample` | 2 |
| `lm-eval-small-models` | 2 |
| `quantized-moe-test-b200` | 2 |
| `engine-1-gpu` | 2 |
| `cudagraph` | 2 |

As in the earlier batches, the generator packs each step's test files into shards of up to 18 minutes of test time using main's per-file timings, and falls back to the usual single job if timings are missing or planning fails. The AMD mirrors inherit the flag, but the generator doesn't shard AMD steps, so they still run as one job.

Notes:
- `lm-eval-small-models` and `quantized-moe-test-b200` each run a single file, so the planner splits that file by test. Each test case loads its own model, so no setup is shared across the split.
- `v1/sample/test_logprobs.py` is split by test function. Its module-scoped `vllm_model` fixture (a 1B model, with and without prefix caching) is used on both sides, so both shards load it.
- `engine-1-gpu` keeps `test_preprocess_error_handling.py` in its own pytest process, since every shard runs the step's commands as written.

## Test Plan

- Ran ci-infra's `runtime_shard.plan_step` against this checkout. All five steps produce a 2-shard plan within budget, and main has timings for every file.
- This PR's CI build should show each step as 2 parallel shard jobs with a planning annotation, and every collected test should run in exactly one shard.
