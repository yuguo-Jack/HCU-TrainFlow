# [HiSparse] Expose cache metrics via typed KV connector stats

[Upstream PR](https://github.com/vllm-project/vllm/pull/55970) · state: closed · merged: False

## Original PR description

## Summary

Reworks #53782 on top of the typed connector stats from #55969 so HiSparse cache metrics flow through the existing `KVConnectorStats` pipeline with no HiSparse-specific code in the model runner, output aggregator, scheduler, or Prometheus logger:

- The swap-in kernel accumulates hot-buffer hits and misses into a per-index-group `uint64[2]` device counter (unchanged from #53782).
- `HiSparseConnectorWorker.get_kv_connector_stats()` snapshots the counters every 2,000 worker steps via a pinned host copy ordered after in-flight swaps, and reports the completed delta as a `TypedKVConnectorStats` with three counters: `vllm:hisparse_cache_hits`, `vllm:hisparse_cache_misses`, `vllm:hisparse_host_to_device_bytes`.
- `HiSparseConnector` declares its metrics in `hisparse/metrics.py` and implements `get_kv_connector_stats` / `build_kv_connector_stats` / `build_prom_metrics` with the generic classes, so no stats subclass is needed and the stats compose with other metric families (e.g. inside `MultiConnector`).

Compared to #53782 this removes `KVConnectorBase_V1.finish_step`, `ModelRunnerOutput.hisparse_stats`, `SchedulerStats.hisparse_stats`, `HiSparseStats`, the aggregator branch, and the hard-coded counters in `PrometheusStatLogger`; it also picks up the `no_forward` and `MultiConnector` paths for free since they already call `get_kv_connector_stats`. The stats assertion in `test_hisparse_swap_in_preserves_rows_across_eviction` is fixed to use the real `swap_in` signature.

Known follow-ups (carried over from #53782, not addressed here): dummy runs (profiling, eager warmup, DP idle steps) still increment the device counters; hits/misses are summed across TP ranks; the 2,000-step sampling interval hides short runs.

Stacked on #55969; intended to replace #53782 (which #55398 currently stacks on) once reviewed.
