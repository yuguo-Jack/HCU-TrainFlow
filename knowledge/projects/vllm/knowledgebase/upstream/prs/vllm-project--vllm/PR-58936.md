# [Bugfix][XPU] Forward softcap and alibi_slopes in xpu_ops.flash_attn_varlen_func

[Upstream PR](https://github.com/vllm-project/vllm/pull/58936) · state: closed · merged: True

## Original PR description

## Purpose

`xpu_ops.flash_attn_varlen_func()` accepted `softcap` and `alibi_slopes` in its signature but dropped both at the call into `vllm_xpu_kernels.flash_attn_interface`, so models that require attention logit soft-capping (Gemma-2 and friends) ran uncapped on Intel GPUs, with no error and no warning. `get_flash_attn_version()` also short-circuits to FA2 on XPU, so the usual softcap/ALiBi backend fallback never engages.

The kernel wrapper (`vllm_xpu_kernels/flash_attn_interface.py`) already accepts and forwards both parameters down to the kernel, so this PR only forwards them from the vLLM-side wrapper.

Fixes #58912

## Test Plan

```bash
pytest tests/platforms/test_xpu_ops_softcap_forward.py
```

The new tests stub the kernel module with a recording wrapper and assert that `softcap` and `alibi_slopes` actually reach `vllm_xpu_kernels.flash_attn_interface.flash_attn_varlen_func`, including the neutral defaults on a plain call.

## Test Result

```
2 passed in 0.54s (tests/platforms/test_xpu_ops_softcap_forward.py)
```

No Intel GPU in my test environment, so the forwarding is pinned by the recording tests rather than an on-GPU numerical check.
