# [ROCm][Kimi-K3] Run KDA speculative decode through AITER's fused kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/59245) · state: open · merged: False

## Original PR description

## Purpose

On ROCm, a pure Kimi-K3 KDA speculative-decode batch now runs AITER's fused
`fused_kda_decode` (convolution, recurrence, and gated RMSNorm) instead of the
three separate kernels and the copies between them.

This depends on [ROCm/aiter#5709](https://github.com/ROCm/aiter/pull/5709).
The path is enabled only when AITER is globally enabled and its Python
signature exposes the speculative arguments. Older AITER builds and
`VLLM_ROCM_AITER_KDA_SPEC_DECODE=0` retain the existing three-kernel path.

FULL decode graphs pad the token buffer to the capture size, so the fused call
uses only the real speculative tokens and their request-local metadata. The
output is written directly into vLLM's preallocated attention output.

## Test Plan

Extend the existing Kimi-K3 AMD KDA decode suite:

- Compare AITER speculative fused output, convolution state, and recurrent
  state against the existing three-kernel chain.
- Verify that disabling the feature or using an older AITER interface keeps
  speculative decode unsupported by the fused selector.
- Retain all existing non-speculative fused-kernel comparisons.

```bash
VLLM_ROCM_USE_AITER=1 \
python3 -m pytest -q tests/models/kimi_k3/test_amd_kda_decode.py
```
