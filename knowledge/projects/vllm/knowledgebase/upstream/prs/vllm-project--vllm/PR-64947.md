# [Bugfix] Include MoE routes in adaptive verification cost profiling

[Upstream PR](https://github.com/vllm-project/vllm/pull/64947) · state: open · merged: False

## Original PR description



## Overview

Include routed-expert work when calibrating adaptive verification costs,
while preserving FULL CUDA graph dispatch.

## Claims

- Cost-profile dummy tokens route to MoE experts with `VLLM_MOE_SKIP_PADDING=1`.
- Ordinary dummy tokens remain padding; cost profiling does not force eager execution.

## Validation

H100s, BF16 `ibm-granite/granite-3.1-1b-a400m-instruct` as target and draft, K=2.
The new regression fails on `7b77ed581` with all profile expert IDs `-1`, then
passes with the fix for FULL, eager-tail and ordinary-dummy controls:


## Details

Calibration uses non-memory-profile dummy runs, whose rows were all marked
padding. Native MoE routing therefore skipped their experts. A separate
`profile_step_cost` flag makes these rows active without using `is_profile`,
which forces eager execution. Existing token-ID randomization diversifies
text inputs; embedding randomization remains separate work in #64530.

Related #63410 introduces the same flag for an attention-context repair; it
does not change the MoE padding predicate. If combined, keep one opt-in source
to avoid passing the flag twice. DP2 standalone-draft startup fails the same
existing token-count assertion on both base and changed code before calibration.
DeepEP, Sync EPLB and AMD runtime are not validated here.
