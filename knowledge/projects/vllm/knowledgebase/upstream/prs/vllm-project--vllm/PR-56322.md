# [Qwen4Exp] support Sequence Parallelism for Qwen3.8-Flash-Next

[Upstream PR](https://github.com/vllm-project/vllm/pull/56322) · state: closed · merged: True

## Original PR description


## Purpose

Add sequence parallelism (SP) to Qwen4Exp / Qwen3.8-Flash-Next to reduce replicated GR and PLE computation and support sequence-parallel MoE.

- Enable GR/PLE SP with `--enable-hc-sp` while retaining tensor-parallel MoE.
- Automatically enable model SP with the existing sequence-parallel MoE configuration (`TP>1`, `DP>1`, EP enabled, and a supported all-to-all backend).

SP currently requires PP=1 and MoE layers. External LoRA adapters on SP-sharded GR/PLE projections are not supported.

python -m pytest -q tests/models/qwen4_exp/test_config.py \

## Test Results

- Regression tests: **92 passed**, including two-GPU GR/PLE SP and four-GPU MoE SP tests.
- Ruff and `git diff --check`: passed.

### Accuracy

Models: `Qwen/Qwen3.8-Flash-Next` and its `-FP8` variant. MTP=3, PP=1, prefix caching disabled. Same prompts and generation settings within each pair: seed=1236, temperature=0.7, top_p=0.8, top_k=20, max_tokens=32768, thinking enabled.

Selected results, **SP off → on**. GSM8K: 1,319 questions; GPQA Diamond: 198 questions. Original evaluation scores are retained.

| Weights | Parallel configuration | PLE storage | GSM8K | GPQA Diamond |
|---|---|---|---|---|
| BF16 | TP2, ETP2 | CPU offload | 97.88% → 97.80% | 87.88% → 88.38% |
| BF16 | DP2/TP2/EP4, ETP4 | CPU offload | 98.10% → 98.03% | 87.88% → 85.35% |
| FP8 | DP2/TP2/EP4, ETP2 | GPU | 98.03% → 98.03% | 87.37% → 87.88% |

The SP-off EP baseline disables automatic MoE SP through a test-only override, keeping TP/DP/EP unchanged.

### Performance

BF16, PLE CPU offload, MTP=3, prefix caching disabled. Median of three runs; **SP off → on**.

Prefill: 8K/16K input, 1 output token, concurrency 2, 48 requests. Decode: 1 input token, 1,024 output tokens, concurrency 32, 128 requests. Synthetic random-token inputs; EP uses `allgather_reducescatter`.

| Parallel configuration | SP comparison | 8K TTFT (ms) | 16K TTFT (ms) | C32 TPOT (ms) | C32 output TPS (tok/s) | Improvement (%) |
|---|---|---|---|---|---|---|
| TP2, ETP2 | Off → On (level 1: GR/PLE) | 301.80 → 278.54 | 612.84 → 565.00 | 16.57 → 16.70 | 1925.64 → 1910.64 | +7.71 / +7.81 / -0.81 / -0.78 |
| DP2/TP2/EP4, ETP4 | Off → On (level 2: GR/PLE + MoE) | 311.64 → 313.95 | 455.12 → 418.47 | 19.35 → 19.49 | 1649.25 → 1629.42 | -0.74 / +8.05 / -0.75 / -1.20 |
| DP2/TP2/EP4, ETP2 | Off → On (level 2: GR/PLE + MoE) | 323.04 → 296.04 | 480.86 → 465.85 | 18.15 → 16.11 | 1707.45 → 1978.78 | +8.36 / +3.12 / +11.22 / +15.89 |

TP2 prefill improves by about 8%.  With DP2/TP2/EP4 and ETP2, C32 TPOT improves by 11.2%; decode does not improve in the other two configurations. DP scheduling contributes to run-to-run variation. Median MTP acceptance is approximately 0–0.15% at C32, so these decode results represent a low-acceptance workload.
