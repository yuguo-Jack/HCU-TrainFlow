# [Bugfix][ROCm] Make Mooncake an optional connector dependency

[Upstream PR](https://github.com/vllm-project/vllm/pull/61244) · state: open · merged: False

## Original PR description

## Overview

Move the ROCm Mooncake transfer engine to optional connector requirements. Fixes #61204.

## Claims

- ROCm source installations no longer require Mooncake when no Mooncake connector is used.
- Both ROCm Docker images still install Mooncake explicitly, including their CI base stages.

## Validation

The Python 3.14 reproducer fails because PyPI has no matching Mooncake ABI wheel:

```sh
uv pip install --python .venv/bin/python --dry-run --no-deps --python-version 3.14 --python-platform x86_64-manylinux_2_35 --only-binary :all: 'mooncake-transfer-engine-rocm>=0.3.13'
```

The optional requirements resolve on Python 3.12 / manylinux_2_35 to `mooncake-transfer-engine-rocm==0.3.13.post1`:

```sh
uv pip install --python .venv/bin/python --dry-run --no-deps --python-version 3.12 --python-platform x86_64-manylinux_2_35 --only-binary :all: -r requirements/kv_connectors_rocm.txt
```

Full optional dependency resolution, including transitive dependencies, passed with 16 packages:

```sh
uv pip compile requirements/kv_connectors_rocm.txt --python-version 3.12 --python-platform x86_64-manylinux_2_35 -o ../vllm-61204-optional-resolved.txt
```

All applicable pre-commit hooks passed for the five changed files, including ROCm test dependency compilation, Markdown lint, and the Docker dependency graph check. A local check of the actual `setup.py` requirement-reader function confirmed that the only removed base requirement is Mooncake and that the optional list contains it once.

These are dependency and static checks on macOS, not a full ROCm source installation or Docker build. No AMD hardware or Docker daemon was available. A separate binary-only resolution of the full base list also encountered a missing Python 3.14 llguidance wheel; this patch addresses the Mooncake dependency blocker and does not claim that every base dependency has a Python 3.14 wheel.

## Details

Mooncake imports are already optional. Requiring its ROCm wheel in the base list nevertheless prevents dependency resolution on Python versions it does not publish for. CUDA already keeps its Mooncake package in connector requirements.

The existing ROCm connector list contained `tblib` and `lm_eval[api]`. Both are already explicit ROCm test requirements; remove them from the connector list so installing connectors in production images does not introduce evaluation dependencies.

Checked the issue comments, timeline, issue-number PR search, and open Mooncake/ROCm PRs; no competing fix for #61204 was found. AI assistance: OpenAI Codex assisted with investigation, implementation, validation, and this description.
