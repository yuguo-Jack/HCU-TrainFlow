# [ROCm] Bump UCX to v1.23.0-rc1 so NIXL uses rocm_ipc

[Upstream PR](https://github.com/vllm-project/vllm/pull/62827) · state: closed · merged: True

## Original PR description

- Bump `UCX_BRANCH` to `v1.23.0-rc1` in `Dockerfile.rocm` and `Dockerfile.rocm_72`
- Drop `UCX_RMA_PPLN_ENABLE=y`
- Set `UCX_ROCM_IPC_SIGPOOL_MAX_ELEMS=inf`, matching the existing `rocm_copy` setting

NIXL opens its UCX endpoints with peer error handling, and at the current UCX pin `rocm_ipc` does not advertise that capability, so NIXL never uses it for GPU-to-GPU reads on ROCm. Reads fall back to TCP emulation, or, with the `UCX_RMA_PPLN_ENABLE=y` override from #49251, to a host-staged pipeline whose fragment pool grows until `/dev/shm` allocations fail; under long-context P/D load that stalled transfers and killed the decode engine. openucx/ucx#11977, included in `v1.23.0-rc1`, adds the capability. With it, `rocm_ipc` is selected again and the override is no longer needed. Each in-flight `rocm_ipc` copy holds one HSA signal, and the 1024 default made multi-request NIXL reads fail, hence the signal pool setting.

On MI355, a 256 MiB NIXL READ between two GPUs goes from 0.48 GB/s (8.8 GB/s with the override) to 60.9 GB/s. With NIXL at its current pin built against the new UCX the same way as the Dockerfile, the MI355 NixlConnector groups pass: spec decode acceptance, PD accuracy sweep, AITER PD accuracy and DP EP PD accuracy. The PD accuracy sweep's lm_eval time drops from 370s to 183s. Step-5 1P1D (TP4 + TP4) passed 10/10 rounds of GSM8K and long-context NIAH; on the current image it hung in round 5.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
