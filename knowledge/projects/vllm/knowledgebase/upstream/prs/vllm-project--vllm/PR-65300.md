# [Perf][Core] Keep per-request token and block id lists out of the cyclic GC

[Upstream PR](https://github.com/vllm-project/vllm/pull/65300) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Keep the per-request Python lists that grow with context length out of CPython's cyclic GC by untracking them at creation (`PyObject_GC_UnTrack`): block id lists, block hashes and token id lists in EngineCore, long lists received by workers, and prompt/output token lists in the API server. The prefix-cache index stores block ids so it holds no GC-tracked objects. Also sends a new request's prompt to MRV2 workers once instead of twice (from #62702).

An alternative to the per-block containers of #64700, whose prefix-cache map this reuses. Removes the cause of the EngineCore GC pauses that #63306 works around with `gc.freeze()`, including the young-generation passes reported in RFC #63363, without freezing anything. Overlaps with the GC part of #62702, whose serialization and memory gains are independent and compatible (`gc_untrack` is a no-op on arrays).

## Claims

- 256 running requests × 128K-token prompts with prefix caching, real `Scheduler`, Python 3.12: a full GC pass drops from 258 ms (1 KV cache group) / 459 ms (4 groups) to 0.1 ms, with token ids still `list[int]` (no #62702 needed for the GC cost).
- No change to the decode step; admission step +6%, chunked-prefill step +1–2%, prefix-cache lookup unchanged. (#64700's containers: admission +40%, chunked-prefill step 3.0–3.3×.)
- No behavior change: identical block ids, hashes and scheduling decisions.
- A new request's prompt is pickled to MRV2 workers once rather than twice (not separately measured).

## Validation

**CPU benchmark, real `Scheduler`** (GB200 Grace, `numactl` node 0, Python 3.12, exclusive node). Extends the #64700 reproducer with admission, chunked-prefill and prefix-lookup timings. All arms on the same base; mean of 2 interleaved rounds (rounds within ~2%); values are 1 / 4 KV cache groups. A fingerprint of block ids and hashes matched across all arms.

```python
# Extended version of the #64700 reproducer: also times the admission step,
# prefix-cache lookups and chunked prefill. Run from a vLLM checkout:
#   VLLM_ALLOW_LONG_MAX_MODEL_LEN=1 PYTHONPATH=. python bench_gc2.py <groups> <main|chunked>
import gc
import hashlib
import statistics
import sys
import time
from array import array

import tests.v1.core.utils as u
from vllm.utils.gc_utils import freeze_gc_heap
from vllm.v1.kv_cache_interface import KVCacheConfig, KVCacheGroupSpec
from vllm.v1.outputs import ModelRunnerOutput

NUM_GROUPS = int(sys.argv[1])
MODE = sys.argv[2]
PROMPT, BLOCK = 131072, 16
NUM_REQS = 256 if MODE == "main" else 16


def multi_group_config(*, kv_cache_groups, **kw):
    spec = kv_cache_groups[0].kv_cache_spec
    groups = [KVCacheGroupSpec([f"layer{i}"], spec) for i in range(NUM_GROUPS)]
    return KVCacheConfig(kv_cache_groups=groups, **kw)


u.KVCacheConfig = multi_group_config
sched = u.create_scheduler(
    max_num_seqs=NUM_REQS,
    max_num_batched_tokens=NUM_REQS * PROMPT if MODE == "main" else 8192,
    num_blocks=NUM_GROUPS * (NUM_REQS * (PROMPT + 4096) // BLOCK) + 1024,
    block_size=BLOCK,
    max_model_len=PROMPT + 4096,
    enable_prefix_caching=True,
    use_v2_model_runner=True,
)
freeze_gc_heap()  # what EngineCore does after startup
reqs = u.create_requests(
    num_requests=NUM_REQS, num_tokens=PROMPT, block_size=BLOCK, max_tokens=4000
)
for r in reqs:
    sched.add_request(r)


def step():
    out = sched.schedule()
    ids = list(out.num_scheduled_tokens)
    sampled = [
        [7] if sched.requests[rid].num_computed_tokens
        >= sched.requests[rid].num_prompt_tokens else []
        for rid in ids
    ]
    sched.update_from_output(
        out,
        ModelRunnerOutput(
            req_ids=ids,
            req_id_to_index={rid: i for i, rid in enumerate(ids)},
            sampled_token_ids=sampled,
            logprobs=None,
            prompt_logprobs_dict={},
            pooler_output=[],
        ),
    )


def full_gc_ms():
    ts = []
    for _ in range(3):
        t = time.perf_counter()
        gc.collect(2)
        ts.append(time.perf_counter() - t)
    return min(ts) * 1e3


def fingerprint():
    # Same scheduling decisions across arms -> same digest.
    h = hashlib.sha256()
    for r in reqs[:8]:
        for ids in sched.kv_cache_manager.get_block_ids(r.request_id):
            h.update(array("i", ids).tobytes())
        h.update(b"".join(r.block_hashes[:64]))
    bp = sched.kv_cache_manager.block_pool
    h.update(str(len(bp.cached_block_hash_to_block)).encode())
    return h.hexdigest()[:12]


tag = f"groups={NUM_GROUPS} mode={MODE}"
gc.disable()
if MODE == "chunked":
    t = time.perf_counter()
    nsteps = 0
    while any(r.num_computed_tokens < r.num_prompt_tokens for r in reqs):
        step()
        nsteps += 1
    total = (time.perf_counter() - t) * 1e3
    print(f"RESULT {tag} chunked_prefill_total_ms={total:.1f} steps={nsteps} "
          f"ms_per_step={total / nsteps:.3f} fp={fingerprint()}")
    sys.exit(0)

t = time.perf_counter()
step()
admit = (time.perf_counter() - t) * 1e3
gc_list = full_gc_ms()
for r in reqs:  # token ids as int32, as with #62702
    r.prompt_token_ids = array("i", r.prompt_token_ids)
    r._all_token_ids = r.all_token_ids = array("i", r._all_token_ids)
gc_i32 = full_gc_ms()
for _ in range(20):
    step()
ts = []
for _ in range(5):
    t = time.perf_counter()
    for _ in range(64):
        step()
    ts.append((time.perf_counter() - t) / 64 * 1e3)
decode = statistics.median(ts)

# Prefix-cache lookup for new requests repeating cached prompts.
wave2 = u.create_requests(
    num_requests=32, num_tokens=PROMPT, block_size=BLOCK, max_tokens=4000,
    req_ids=[f"w2-{i}" for i in range(32)],
)
lt, hits = [], 0
for r in wave2:
    t = time.perf_counter()
    _, num_hit, *_ = sched.kv_cache_manager.get_computed_blocks(r)
    lt.append((time.perf_counter() - t) * 1e3)
    hits += num_hit
print(
    f"RESULT {tag} admit_step_ms={admit:.1f} full_gc_list_ms={gc_list:.1f} "
    f"full_gc_int32_ms={gc_i32:.1f} decode_step_ms={decode:.3f} "
    f"prefix_lookup_ms={statistics.median(lt):.2f} "
    f"hit_frac={hits / (32 * PROMPT):.3f} fp={fingerprint()}"
)
```

## Details

**Root cause.** A full collection visits every slot of every tracked container. `freeze_gc_heap()` at startup hides the static heap (including the `KVCacheBlock` pool), but per-request lists are created afterwards and grow with context length, so each full pass visits one slot per token and per block, for every running request.

**Changes.**

- `vllm/utils/gc_utils.py`: `gc_untrack` (calls `PyObject_GC_UnTrack` through `ctypes.pythonapi`, which holds the GIL; no-op for untracked objects such as `array`), `untracked_list`, and `untrack_long_lists`.
- EngineCore: `req_to_blocks` lists (one per KV cache group), `Request.block_hashes`, and `Request` prompt / all / output token id lists. All are only mutated in place.
- Workers: `NewRequestData.__setstate__` untracks long lists (≥ 256) on unpickling. MRV2 copies them into its buffers, so they only live for that step; short ones are skipped since the call costs more than a young-generation scan. `CachedRequestData` never carries full block lists under MRV2 (resumed requests are sent as `NewRequestData`).
- API server (also calls `freeze_gc_heap()`): the prompt list, which is one object shared from the HTTP request through `RequestState` and each `RequestOutput`; the detokenizer's output token ids and the slow detokenizer's token strings; chat streaming's `generated_token_ids` and the Responses API's accumulated token ids.
- Prompt sent once: `Request.prefill_token_ids` returns the `prompt_token_ids` object itself while the request has no output tokens, so `NewRequestData`'s two fields are one object and pickle writes it once (from #62702, co-authored).
- Prefix cache: `BlockHashToBlockMap` maps hashes to block ids, keeping keys cached by several blocks in a small side dict, so the main dict holds only bytes and ints (from #64700, co-authored). It is also untracked explicitly, and `reset_prefix_cache` clears it in place rather than replacing it.

**Safety.** A reference cycle through an untracked container is never collected, so only containers that cannot be in a cycle are untracked: these lists hold ints, bytes, strs, or `KVCacheBlock`s that never refer back to them, and are freed by reference counting. The prefix-cache dict needs int values for this: an untracked dict holding blocks (which refer to their pool, which refers to the dict) leaks the pool on Python 3.14.

**Python versions.** 3.11–3.13 auto-untrack dicts of atomic values, which int values alone exploit; 3.14 does not, hence the explicit untrack, which on 3.14 sticks even across inserts. Checked with standalone probes on 3.11–3.14; the scheduler benchmark ran on 3.12 only.

**Tradeoffs and limitations.**

- Relies on CPython's `PyObject_GC_UnTrack` via `ctypes`; untested on free-threaded builds.
- A list that later code replaces with a new one becomes tracked again, silently losing the benefit (nothing fails).
- Untracked lists are invisible to `gc.get_objects()`, so `VLLM_GC_DEBUG` top-object counts omit them.
- The API server untracks the prompt list it was handed, which can be the caller's own list (an offline `LLM` prompt list, or the pydantic request list); safe for lists of ints.
- Not covered: MRV1's worker-side request state, non-flat logprobs, and the Rust frontend (no Python API server).
