# [Docs] Clarify Qwen4Exp PLE Engram configuration

[Upstream PR](https://github.com/vllm-project/vllm/pull/59936) · state: open · merged: False

## Original PR description

## Overview
Improves the Engram documentation for [#59897](https://github.com/vllm-project/vllm/issues/59897) with a concrete Qwen3.8-Flash-Next two-A100 configuration.

## Claims
Documents tensor parallel size 2 as the starting topology for two GPUs on one host.
 Replaces the unsupported VLLM_PLE_CPU_OFFLOAD environment-variable guidance with the supported engram-config option.
Explains Qwen4Exp PLE ETP sharding and calls out the SM8x pinned-host FP8 lookup limitation.

## Validation
 git diff --check passed.
 The pre-commit typo hook passed.
 Markdown linting was started locally but did not finish in the available Windows environment.

## Details
The existing Engram page describes CPU offload and Qwen4Exp PLE behavior, but it does not connect those controls to the Qwen3.8-Flash-Next two-A100 use case. The new section gives an actionable command, clarifies that VLLM_PLE_CPU_OFFLOAD is not read by vLLM, and distinguishes tensor parallelism from pipeline parallelism for a single host.The section explicitly states that A100 UVA support does not bypass the SM8x FP8 Triton lookup compatibility requirement, so operators do not interpret CPU offload as universally available until a release containing the lookup fix is installed.
