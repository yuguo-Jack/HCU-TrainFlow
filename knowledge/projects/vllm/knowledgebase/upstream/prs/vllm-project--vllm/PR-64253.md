# [Perf][DSv4.1] Fill same-spec SWA groups' decode metadata in one launch

[Upstream PR](https://github.com/vllm-project/vllm/pull/64253) · state: open · merged: False

## Original PR description

## Overview

DeepSeek-V4.1-Flash keeps its sliding-window KV in 8 groups with one spec, and every decode step builds each group's SWA metadata separately, though they differ only in block table and slot mapping. On decode-only steps, `DeepseekV41ModelState` now builds the first group and fills the other 7 in one Triton launch.

## Claims

- SWA metadata per decode step: host 1.1-1.2 ms -> 0.35-0.43 ms, GPU 93-102 us -> 19-23 us.
- DEP32 decode step 12.93 -> 12.68 ms, DEP16 13.60 -> 13.45 ms (earlier version of this change, internal tree).
- Same metadata as each group's own `build()`; only `vllm/models/deepseek_v41/nvidia/model_state.py` changes.

## Validation

Microbenchmark, GB200, 8 groups (window 128, block 32), median of 3 x 20 steps:

| Requests x tokens | Host before / after (us) | GPU before / after (us) |
|---|---:|---:|
| 1 x 6 | 1087 / 426 | 93.2 / 18.7 |
| 64 x 6 | 1069 / 394 | 100.4 / 21.7 |
| 128 x 6 | 1125 / 383 | 101.5 / 22.7 |
| 256 x 1 | 1170 / 402 | 97.4 / 20.5 |

End to end (earlier version on an internal P/D tree, not this branch): DeepSeek-V4.1-Flash on GB200, AgentX decode-only via `DecodeBenchConnector`, DSpark K=5, `max-num-seqs 16`, one run per arm.

| Config | Before (ms/step) | After (ms/step) |
|---|---:|---:|
| DEP32 | 12.93 | 12.68 |
| DEP16 | 13.60 | 13.45 |

Accuracy on this branch: DeepSeek-V4.1-Flash DEP4 on GB200, DSpark K=5, FULL_DECODE_ONLY, `lm_eval` gsm8k 5-shot, greedy, 1024 tokens, 32 concurrent. Strict-match 0.9318 ± 0.0069, acceptance length 3.441 (per position 0.795 / 0.650 / 0.455 / 0.330 / 0.211), in line with earlier runs (~3.42-3.45).

Correctness: `tests/v1/attention/test_deepseek_v4_swa_visible.py` plus the v41 replay tests, 48 passed. A local randomized check (4,000 batches: padding, invalid rows, replay starts, 4 window/block configs) matched `build()` bit for bit. In the DEP4 server above, a temporary counter showed every decode step taking the batched path (220+ per rank for 600-token requests).

## Details

- SWA groups are grouped by spec on the first `prepare_attn`, where the kernel is also compiled.
- Captures, PCP and steps with a prefill keep the per-group build.
- `build()` also zeroes `decode_swa_lens` past the step's tokens; the batched path skips that, since nothing reads past `[:num_decode_tokens]`.

Not a duplicate: #63393 keeps all 8 `build()` calls and merges only their index-kernel launches; this PR skips 7 of the builds and stays in the model directory. #63885 is ROCm-only.
