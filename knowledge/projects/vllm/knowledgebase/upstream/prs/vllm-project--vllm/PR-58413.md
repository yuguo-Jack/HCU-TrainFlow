# [Bugfix][KV Offload] Offload align-mode Mamba state at hash-block granularity under MTP/EAGLE

[Upstream PR](https://github.com/vllm-project/vllm/pull/58413) · state: open · merged: False

## Original PR description

Mamba/Hybrid models under MTP speculation (#52735)

# Summary
When MTP speculation is enabled on hybrid models (like Qwen3.5), OffloadingConnector fails to serve cached KV for Mamba layers, causing ext_connector_hits to drop to 0.

# What went wrong?
MTP lookahead shifts the Mamba hand-off boundary (e.g., to 99,008). This boundary is aligned with tokens_per_hash (832), but NOT with the global blocks_per_chunk grid (3328 tokens / 4 blocks).

1. Store: The connector dropped all Mamba hand-off states during store because % tokens_per_chunk != 0.
2. Load: Even if we bypass store, update_state_after_alloc was using global blocks_per_chunk to slice offload keys, causing out-of-window index lookups and crashing the engine.

# Changes

For MambaSpec in align mode with tokens_per_hash == tokens_per_block, override the group's chunk unit to be 1 hash block (tokens_per_chunk = tokens_per_hash).

Calculate chunk indices in update_state_after_alloc using the group's local tokens_per_chunk rather than the global config.

# Validation

Added 4 unit tests in test_scheduler.py reproducing the mismatch (Pass now).

E2E test on 8x H200 (Qwen3.5 27B + MTP-3 + FS offload):

Prompt cache hits: 0 -> 99,008 tokens.

TTFT: ~12s (cold) -> 377ms (warm, ~31x speedup).

Outputs are byte-identical to cold runs.

Note: This fix only addresses the align-mode single-block chunk case (#52735) and doesn't touch general per-group geometry refactoring (#54413).
