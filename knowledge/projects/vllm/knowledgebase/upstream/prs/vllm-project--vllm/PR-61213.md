# [Perf] Improve `_topk_topp_kernel()` for masked logits

[Upstream PR](https://github.com/vllm-project/vllm/pull/61213) · state: closed · merged: True

## Original PR description

* **Problem:** the `_topk_topp_kernel()` kernel wastes work searching for a top-k cutoff even when the input logits have less than `k` finite logits (the rest are `-inf`).
* **Solution:** Skip the search when `num_finite_total <= k`, preserving the existing top-p path.
* Does this make sense to the kernel authors & reviewers? @cakeng @njhill 

## Benchmarks

Using the `benchmark_topk_topp.py` script on an H100 80GB. CUPTI, 5 warmups and 20 measured iterations, cold L2, no CUDA graphs, Triton only.

### Table 1: Masked Logits

We observe multi-ms savings for `num_finite_logits <= k`. The runtimes below are a single call to `apply_top_k_top_p_triton()` plus `logits.clone()`, averaged over 20 measurements. All logits are `-inf` except for `num_finite_logits`. The scenario uses bsz=1024 and vocab=131072. This bsz happens e.g. with concurrency=64, DFlash K=15 (64 * 15+1 = 1024). The speedups are probably larger because the timings include cloning a 512 MiB logits tensor (1024 × 131072 × 4 bytes). At peak H100 SXM memory bandwidth, that copy alone takes about 320 µs (read and write).
