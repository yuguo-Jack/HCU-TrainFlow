# [RL][Model Loader] Load plan: plan_loads and TraceTensor

[Upstream PR](https://github.com/vllm-project/vllm/pull/65235) · state: open · merged: False

## Original PR description

## Purpose

Part of #64418 (tracker item P1). Builds on #64336 (direct reload).

Engines that move sharded bytes themselves (sharded RDT, NCCL M2N) need to know, for each
checkpoint tensor, which part this rank needs and where in live memory it goes. This PR adds the
engine-neutral answer from RFC §3/§4:

- `plan_loads(model, metadata)` traces the model's own `load_weights` once at init;
- it returns a `LoadPlan` with `get_boxes(name)` and `get_dest(name)`.

The NCCL broadcast engine can opt in to it (`use_load_plan`, off by default; see below), which
exercises the plan end to end on real models. Sharded RDT (E1) and NCCL M2N (E2) move onto it in
follow-ups. Cold start and the existing reload paths are unchanged.

Not a duplicate: I searched open PRs for "load plan", "plan_loads" and "TraceTensor" and none
implements this. zzhisyyds2's M0 prototype on #64418 is a measurement tool and is not proposed for
merge.

## Changes

- **`reload/trace.py`: `TraceTensor`.** It is written for the plan and modelled on sharded RDT's
  `FakeRDTTensor`, which this PR leaves untouched. The two converge when E1 moves RDT onto the
  plan.
  - View ops (`VIEW_OPS`, including `unflatten` and `split`) return a child that carries a meta
    view over the checkpoint tensor, so each child knows which checkpoint element each of its own
    elements is.
  - A `.to()` that changes neither dtype nor device returns the tensor itself.
  - `copy_` from a trace, ops outside the table, and value reads (`.item()`, `bool()`, ...) go to
    the plan's sink.
- **`reload/direct.py`: shared helpers**, so the plan does not import private names:
  - `check_direct_reload` (refusal checks only; `begin_direct_reload` now calls it);
  - `loadable_slots`;
  - `checkpoint_layout`;
  - `apply_checkpoint_attrs`.

  `begin_direct_reload` behaves exactly as before.
- **`reload/plan.py`: the public surface.**
  - `plan_loads` and `LoadPlan` (with `Entry`; §11 dataclasses plus `Entry.reason` for the report).
  - Refusals:
    - layerwise mode;
    - anything `check_direct_reload` refuses: no recorded layout, replaced parameters, layouts
      that cannot be viewed back (online quantization and humming are already refused at cold
      start);
    - EPLB;
    - duplicate names;
    - a fallback name that writes nothing when loaded alone, or whose loader fails when loaded
      alone ("move the combine into PWAL").
  - Names whose writes share a byte of storage become fallbacks ("writes overlap with
    <other name>"). They go through `load_weights` in arrival order, as they do today.
  - Destinations are built once with `storage_view` on the target's real storage, in the
    checkpoint dtype.
  - Names this rank needs nothing of return `get_boxes(name) is None` and `get_dest(name) == []`.
  - The report logs one info line per fallback reason (count and examples) plus a summary, and
    every name with its bytes at debug.
- **`reload/bake.py`: the trace.**
  - Every parameter and persistent buffer is replaced by a meta stand-in in its checkpoint
    (view-back) layout, with one meta storage per real storage so tied weights alias.
  - `load_weights` then runs once over `TraceTensor`s for all declared names. `copy_` from a trace
    is the only recorded write. Constant writes into targets (`fill_`, `zero_`, `copy_` of a
    tensor that is not a checkpoint tensor) are ignored.
  - An unsupported op makes the name a fallback and the bake continues.
  - A value read reruns the whole bake without that name, so each such name costs one full bake.
  - A dispatch mode makes a name a fallback when its loader reads its own destination
    (`composed_weight_loader`'s `param.copy_(fn(param))`).
  - Module attributes, parameter attributes and CPU tensors are snapshotted, compared and
    restored. If the full bake changed any of them, bisecting finds the names responsible, and
    those names become fallbacks.
- **`reload/geometry.py`: pure integer code.**
  - Reduces one `copy_` to a box of the HF tensor plus destination strides (the RFC's
    `P.copy_(W.t())` example is in the docstring).
  - Merges per-expert writes: v5 fused `experts.gate_up_proj` is one write under EP and two under
    expert TP.
  - Computes the byte runs used by the overlap check.
- **`reload/plan.py`: `load_planned(model, plan, weights)`.** The carve-and-copy step an engine
  runs per received batch of full tensors: `dest.copy_(full[box].reshape(dest.shape))` for each
  pair, nothing for names this rank doesn't need, and one `model.load_weights` call for the
  fallbacks.
- **Not included: the required-set check.** It needs #54477 F2, which is not upstream: direct
  reload records vLLM parameter names, not cold-start checkpoint names. A `TODO(#54477 F2)` in
  `plan_loads` marks where it goes.
- **Not included: keeping metadata-only state (RFC §4 exception).** This moves to L7. Its hook point
  is `_Snapshot.restore` in `bake.py`, which today restores every change.

## NCCL engine opt-in

- **The flag.** `use_load_plan: bool = False` on `NCCLTrainerInitInfo` and
  `NCCLWeightTransferInitInfo`. `build_worker_init_payload` passes it to the worker.
- **Metadata.** With the flag on, `trainer_init` also sends `metadata`: `(name, dtype name, shape)`
  from `source.metadata`, which is identical on every trainer rank. A trainer that inits the
  workers out of band (the JAX unique-id path) must send `metadata` itself, or leave the flag off.
- **Planning.** The worker's `init_transfer_engine` refuses unless `VLLM_RELOAD_MODE=direct` and
  the metadata is present. It then builds one `plan_loads(model, metadata)` for the target model
  and keeps it.
- **Updates.** Every sent name must match a plan entry (present, same dtype and shape). A subset
  is fine, since each broadcaster sends its own slice. Otherwise the update raises ("re-init the
  engine to re-plan").
- **Loading.** Each received batch goes through `load_planned` instead of `model.load_weights`, in
  both the packed and the unpacked receive paths. Bucketing, packing and `start_reload` /
  `finish_reload` are unchanged, so post-load processing still reruns at finish.
- **Drafts.** A draft update session (`start_draft_weight_update`) keeps `load_weights`. The plan
  is the target's, and draft models are not planned yet.
- **Sparse backend.** It shares the worker init info and refuses `use_load_plan`.
- **Cost.** Init takes the trace time longer (about 6 s per rank on Qwen3-30B-A3B). Planning
  briefly swaps the model's parameters for meta stand-ins, so the init must not overlap
  inference.

## Points for the reviewer

These are places where implementing the RFC needed a decision:

1. **Names this rank doesn't need.** §11's table gives the tied `lm_head` `writes=None`, which
   means fallback.
   - Applied to every such name, that would send non-local experts and other-PP-stage names in
     full through `load_weights`, and §4's pairing check would refuse them.
   - Here they get `boxes=None, writes=()`, so `get_dest` is `[]` and the engine copies nothing.
   - M2N's `len(dest) == 1` check (§7) then needs a "`boxes is None` → skip" branch first.
2. **Metadata-only state (§4).** The bake never sees values, so any state a loader sets during it
   depends only on metadata; "metadata-only" cannot be what separates kept state from fallback.
   The real criterion is "PWAL does not reset it", which needs an explicit declaration. This PR
   has no hook; L7 adds one with its first user. The open question is whether that should be a
   per-module declaration or a central list.
3. **Destination dtype.** "In the checkpoint dtype" is read as the HF (wire) dtype, not the
   parameter's, so `dest.copy_(hf_box)` copies bytes even for E8M0 stored as `uint8`. Reinterpreting
   to a different element size, on either side, is a fallback.
4. **`unflatten`, `split`.** Both are plan view ops (a box or a split box). The plan's tracer
   no longer shares its op table with sharded RDT, so adding them does not touch RDT's wire op
   set.
5. **Overlapping writes become fallbacks, not a refusal.**
   - The check is exact when a write splits into at most 65,536 contiguous byte runs. Beyond
     that it uses the write's whole span, which can mark names that don't really overlap; they
     then cost a full-tensor transfer.
   - No RL target model writes one byte from two names. Some MTP draft loaders do, by mapping
     the top-level and per-layer `embed_tokens` onto one parameter, but drafts are not planned
     yet.

## Known limitations

- **Planning can touch real memory outside the swap.** Only parameters and persistent buffers get
  stand-ins. A loader that runs `fill_`/`zero_` on a non-persistent buffer, or on a GPU tensor
  held as a plain module attribute, writes it for real during planning. Changes to CPU tensors
  are restored; GPU ones are not.
- **Blame for a destination read.** A destination read that no `copy_` preceded is blamed on the
  name last handed to `load_weights`. A loader that reads ahead (AutoWeightsLoader's `groupby`)
  makes that the next name. Reads through the loaded tensor itself, and reads after a `copy_`,
  are attributed exactly.
- **Shared storage.** A `Write` is labelled with the first checkpoint tensor on its storage. The
  destination is the same whichever tensor labels it, and a test checks this.
- **Draft models are not planned.** A draft update session uses `load_weights`.
- **Shallow snapshot.** Changes inside objects held by a module (for example a `quant_method`'s
  own attributes) are not seen.

## Test plan

- **`tests/model_executor/model_loader/test_load_plan.py`** (new, CPU). The shared helper checks two
  things on every model:
  - planning changes no tensor, address, registration or module attribute;
  - a planned direct reload with new random weights (boxes into `get_dest`, fallbacks through
    `load_weights`) equals a cold start on the same weights, byte for byte, at unchanged addresses.

  Cases:
  - real `QKVParallelLinear` / `MergedColumnParallelLinear` / `RowParallelLinear` under faked TP2
    (both ranks);
  - a transposing loader with a transposing PWAL (the RFC's `as_strided((4, 6), (1, 4))` example);
  - tied embedding;
  - BF16 into an FP32 parameter (cast → fallback, with the hint);
  - a step slice (→ fallback);
  - fused `[E, 2I, H]` / `[E, H, I]` experts under EP2 and expert TP2;
  - fallback reasons: arithmetic, cast round trip, value read, `__setitem__`, destination
    transform, expand;
  - a value read and a state change in a two-name model (only that name falls back);
  - a no-op `.to()` and an ignored `zero_`;
  - paired loaders, with the stash emptied and with the stash kept, the latter making the bisect
    trace a loader that fails alone (refused);
  - overlapping tied writes (both names fall back, and the result still equals a cold start);
  - `unflatten`, `split` and `t().contiguous()` slices (direct);
  - two checkpoint tensors sharing one storage (destinations at their own tensors);
  - refusals for layerwise mode, duplicate names, no recorded layout, and EPLB.
- **`tests/distributed/test_weight_transfer.py`.**
  - NCCL refuses `use_load_plan` outside direct mode and without metadata.
  - The trainer sends `use_load_plan` and the metadata.
  - An update whose names, dtypes or shapes don't match the plan raises; a broadcaster's subset
    passes.
  - The sparse backend refuses the flag.
  - The existing exact-payload tests now include `use_load_plan: False`.
- **Existing, unchanged:** `tests/model_executor/model_loader/test_direct_reload.py`,
  `tests/distributed/test_sharded_rdt_plan.py`.

### GPU end to end (NCCL opt-in, custom script)

GB200, nightly wheel 4a0dfc7b2f (this PR's base) with the branch overlaid,

1. cold start;
2. snapshot every registered and off-registry device tensor (content digest and address);

4. snapshot;
5. sync the real checkpoint;
6. snapshot.

- **Not vacuous.** The tensors the scrambled sync leaves unchanged are all non-checkpoint tensors:

- **The two paths write identical bytes.** The scrambled state is identical between the
