# [CI][XPU] Run Intel CI test steps on Kubernetes

[Upstream PR](https://github.com/vllm-project/vllm/pull/62772) · state: open · merged: False

## Original PR description



## Overview

Moves every Intel CI test step in `.buildkite/intel_jobs/` from the bare-metal `intel_gpu` agents (`run-intel-test.sh` → `docker run --privileged`) to `device: intel_gpu_k8s`. The pipeline generator turns that device into an agent-stack-k8s Pod on the `intel-gpu-k8s` queue (Arc Pro B70, GPUs allocated through DRA). `image-build-xpu` is unchanged, and the Pods run the image it pushes.

Depends on vllm-project/ci-infra#841, which adds `intel_gpu_k8s` to the generator. Merge that first.

## Claims

- All 57 Intel test steps run on Kubernetes. Labels, keys, timeouts, retries, `parallelism`, `optional`, `source_file_dependencies` and test env are unchanged, and so are the commands, apart from the runner wrapper.
- Each Pod sees only its own GPUs (DRA claim), so `ZE_AFFINITY_MASK` and per-agent GPU slicing are no longer needed.
- Fixes a missing `&&` in the llava/qwen2-vl multimodal step: `test_qwen2_vl.py` was appended to the previous pytest invocation's arguments, so it never ran as its own command.

## Validation

- Script-checked against `main`, per step: the only changes are the runner fields below, plus the `&&` fix. The `&&`-joined command list equals the old `run-intel-test.sh` string.
- Rendered with the ci-infra branch (`NIGHTLY=1`): 57 steps on `intel-gpu-k8s`, each with a `b70-<N>` claim matching its old `gpu: N+` tag.
- Ran that output on the B70 cluster, with the image pinned to `9da5f2d3` (the commit of the "Full intel CI-daily" build intel-ci#14858), and compared job by job:

| run | jobs | match intel-ci#14858 |
| --- | --- | --- |
| smoke: 1/2/4-GPU, 4-way parallel, repo-root steps | 9 | 9 (incl. the two upstream failures: `xpu-sleep-mode`, multimodal processor shard 2) |
| full (all 57 steps) | running | to be added |

- `pre-commit run check-buildkite-step-keys check-test-tethering`: pass. The tethering hook now statically resolves `test_disagg_accuracy.py` (its script is its own command now), so that entry is dropped from the allowlist as the hook asks.

## Details

Per step:

| before | after |
| --- | --- |
| `device: intel_gpu`, `agent_tags: {label, gpu: N+, mem}`, `no_plugin: true` | `device: intel_gpu_k8s`, `num_devices: N` (omitted for 1) |
| `working_dir: "."` | `working_dir: "/workspace/vllm"`, the image's tree, where `run-intel-test.sh`'s container started |
| `env: REGISTRY/REPO` | dropped: only `run-intel-test.sh` read them. The generator builds the `-xpu` image tag from `ci_config_intel.yaml` |
| `bash run-intel-test.sh '<a> && <b>'` | `commands: [a, b]` |
| `parallelism: N` | first command `export PYTEST_ADDOPTS="--num-shards=… --shard-id=…"`, which `run-intel-test.sh` used to set |

`PYTHONPATH=..`, `VLLM_DISABLE_COMPILE_CACHE=1`, `HF_TOKEN` and the HF cache come from the generator's pod template, as they came from `run-intel-test.sh` before.

`run-intel-test.sh` stays, since `.buildkite/hardware_tests/intel_xpu_ci/` still uses it.
