# [Bugfix][Frontend] Clean up failed online beam searches

[Upstream PR](https://github.com/vllm-project/vllm/pull/60550) · state: open · merged: False

## Original PR description

## Overview

Cancel and await sibling candidate tasks when online beam search fails, so their engine requests finish cleanup before the error reaches the caller.

## Claims

- Clean up outstanding candidates when one candidate raises an exception or is cancelled.
- Preserve the original exception and leave the successful beam-search path unchanged.

## Validation

The new regression is parameterized over `RuntimeError` and `asyncio.CancelledError`. Both cases fail against base `1995c0fcd02f88d5daa3fdbcd47e0f016e7b89b9` because the sibling is still running when the failure propagates.

With the patch, the affected CPU selection passes: **16 passed, 2 deselected**.

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
  .venv/bin/python -m pytest -p pytest_asyncio.plugin --noconftest -s -q \
  tests/samplers/test_beam_search_online.py \
  -k 'not warns_and_disables_watermarking' --tb=short
```

This includes the two new cases, normal beam outputs, and existing abort handling. The two logger tests were excluded because their fixtures come from the root conftest, which this isolated CPU run bypasses.

Additional validation ran real CPU inference with a locally generated GPT-2 model (2 layers, hidden size 128, vocabulary 64). After the first beam step completed, the scheduler was paused in `keep` mode and an output error was injected after both second-step candidates had been admitted. The actual `AsyncLLM`, EngineCore, output queues, and abort path were used.

| Observation when the exception reached the caller | Base | Patch |
| --- | ---: | ---: |
| Unfinished requests | 1 | 0 |
| Pending candidate tasks | 1 | 0 |
| Completed abort calls | 1 | 2 |

The normal two-beam output was identical before and after the patch: `[[6, 6], [46, 46]]`. This was a correctness check with a small random model, not an accuracy or performance evaluation.

The CPU run used the official ARM64 container at digest `sha256:c8bde509a9a98ee4d7e40a204b5131c028c38e9acc9e9949715fdd525a572741`, vLLM `0.31.1rc1.dev23+g43b4aaea3`, and PyTorch `2.13.0+cpu`, with the complete changed online beam-search module loaded from the patch. The engine, beam-search helpers, sampling parameters, and renderer source were unchanged between that runtime revision and the patch base. No GPU or full-suite validation was performed.

Ruff lint, Ruff format checking, and `git diff --check` also passed. Commit-time checks passed, including mypy and the Buildkite test-registration check. The CPU model check was rerun by the submitter before the signed-off commit.

## Details

`asyncio.gather` propagates a candidate failure without cancelling its siblings. The previous code then lost the handles needed to stop those tasks. The new exception path cancels them and awaits a second gather with `return_exceptions=True`, allowing `AsyncLLM.generate` to finish its abort cleanup before re-raising the original exception.

The regression uses events to ensure the sibling has started before the failure. Its cleanup deliberately yields once, so cancelling without awaiting would still fail the test. Test teardown also joins remaining tasks, keeping the reproducer safe to run against the unfixed implementation.

Duplicate checks found related work in #50830, which cleans up `merge_async_iterators`, and #56249, which handles `finish_reason="abort"` in beam results. This change covers raised exceptions in online beam search's own gather. The open structured-output refactor in #36285 touches the same module but did not include this cleanup when checked.

AI assistance was used for the investigation, implementation, and regression tests.
