# [Docs] Move XPress kernel types from docstrings to signatures

[Upstream PR](https://github.com/vllm-project/vllm/pull/63233) · state: closed · merged: False

## Original PR description



## Overview

Follow-up to #63228. That PR silenced the griffe missing-type warnings by adding types to docstring `Args:` entries; vLLM doesn't type docstrings, so this moves the types into the kernel signatures and restores the original docstrings.

## Claims

- The `@triton.jit` kernels annotate pointer params as `tl.tensor` and size/stride params as `int`, matching existing kernels (e.g. `top_k: int` in `fused_moe.py`).
- Triton ignores `tl.tensor`. `int` pins the arg to i32 while keeping alignment specialization, and these values (V, C, row strides) are far below 2^31, so codegen is unchanged.
- Docstrings are identical to before #63228.

## Validation

- griffe (Google parser) on the module: 0 `No type or annotation` warnings, same as after #63228.
