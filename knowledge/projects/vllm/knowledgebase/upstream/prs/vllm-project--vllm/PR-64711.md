# [Rust Frontend] Replace assert!(matches!(..)) with std assert_matches!

[Upstream PR](https://github.com/vllm-project/vllm/pull/64711) · state: open · merged: False

## Original PR description

## Purpose

Mechanical follow-up to #64710, adopting `std::assert_matches` (stabilized in Rust 1.96). On failure it prints the `Debug` representation of the actual value; `assert!(matches!(..))` only reports that the assertion failed. Matching semantics (patterns, guards, moves) are unchanged, so no test outcome changes.

- 176 assertions across 51 files rewritten mechanically (paren-balanced, string/comment-aware rewrite), preserving pattern guards and custom messages. Each using module imports the macro explicitly (`use std::assert_matches;` — it is intentionally not in the prelude).
- `assert!(!matches!(..))` (86 sites) is left as-is: std has no `assert_not_matches!`.
- Four sites keep `assert!(matches!(..))` because the matched types deliberately have no `Debug` impl (`hf::Backend`, and an error holding `dyn VisionPreProcessor`). One local test-only enum gains `#[derive(Debug)]` instead.

## Duplicate-work check

No open PR migrates to `assert_matches!`.
