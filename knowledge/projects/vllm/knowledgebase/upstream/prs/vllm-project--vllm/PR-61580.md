# [KV Connector][3/N] KV checksums for NIXL push

[Upstream PR](https://github.com/vllm-project/vllm/pull/61580) · state: open · merged: False

## Original PR description

## Overview

Part 3 of the KV checksum series: KV checksums for NIXL push. In push mode, the consumer's `kv_transfer_params` are built before the producer finishes, so the checksums cannot travel in them. This PR adds a second, connector-owned carrier and uses it to send the checksums on the completion notif of the WRITE that delivers the KV.

Depends on #61579 (2/N), which depends on #61578 (1/N). Only the last two commits are new here, starting at "KV checksums: connector-owned carrier". The full series and its validation are in #61488.

Not a duplicate: this extends the series; no other open PR checksums P/D transfers.

## Claims

- **Connector-owned carrier.** A new generic carrier, `KVChecksumCarrier.CONNECTOR`, lets a connector move the checksums in its own messages.
  - The producer's scheduler hands them to `KVConnectorBase_V1.send_kv_checksums`.
  - The consumer's worker connector returns them in `KVConnectorTransferResults.kv_checksums` by the time it reports the load finished.
  - MultiConnector delegates both.
  - Mooncake P2P (4/N) uses it too.
- **NIXL push** verifies loads end to end.
  - The checksums ride on the WRITE's completion notif, which NIXL delivers after the WRITE's data, so the consumer never waits for them.
  - `NIXL_CONNECTOR_VERSION` goes from 14 to 15 for the new notif form. Without checksums, the notif keeps its old form.
- **Cleanup:** removes the unreachable producer-side branch of the push worker's notif counting.

## Details

Two commits:
1. **Connector-owned carrier (generic).** Received checksums reach the scheduler in each worker's checksum record, on the existing per-worker output channel. The scheduler keeps the first copy for a pending load.
2. **NIXL push.**
   - **Producer scheduler:** ships the checksums with the finished blocks in the next step's connector metadata.
   - **Producer worker:** hands them to the writer thread in the same queue item as the blocks, so they add no latency to the WRITE. Every producer rank that writes sends the same bytes, and the consumer keeps the first.
   - **Cleanup:** `_get_new_notifs` now counts only consumer-side completion notifs. A request that both loads and saves on a `kv_both` instance now has its completion notif counted as a load.

Limitations:
- **Expired lease during a deferred handshake:** if a producer's lease expires while its WRITE waits for the handshake, the late WRITE goes out without checksums. The consumer then reports the load unverified, not mismatched.
- **Notif size:** the notif grows by 8 bytes per block and group, about 64 KB for a 128k-token prompt with 16-token blocks.
- **Prefix hit inside a producer block:** push allows larger producer blocks, and a consumer prefix hit that ends inside a producer block is unverified (see 2/N). The open upstream #59747 proposes rejecting different block sizes in push at handshake.
- **No MLA run:** no MLA model was run in push mode.
