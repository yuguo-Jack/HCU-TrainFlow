# [WIP][Perf][CPU][DiffusionGemma] Optimize CPU runtimes

[Upstream PR](https://github.com/vllm-project/vllm/pull/60527) · state: open · merged: False

## Original PR description

Splitting this PR in 2 components:
1. The single-pass read is an opt-in, CPU-only DiffusionGemma optimization.
2. `prompt-logprob` changes.

Because 2 is in Model Runner V2, it's better to have their own review and revert path.

## Overview

This PR runs DiffusionGemma one-step reads in a single forward pass on the CPU backend. It adds DiffusionConfig.single_pass_reads, off by default. It builds on the sync DiffusionScheduler from #59107 and the CPU causal mask fix from #59992.

It also clamps the rows that prompt logprobs report, and routes their logits through a new ModelState hook. Both apply to every model on Model Runner V2, with the flag on or off.

A one-step read sets diffusion_read_only and diffusion_max_steps=1. It is the default structured read in examples/features/structured_diffusion. Today it takes two engine steps. The first prefills the prompt and emits nothing. The second runs the canvas. With this PR the canvas runs in the step that finishes the prompt.

No open issue or PR covers this. I searched open PRs for single-pass and one-step DiffusionGemma reads.

I used Claude Code to help with this PR. I reviewed every changed line and ran the tests below.

## Claims

- One-step reads are 13 to 21% faster on CPU. Bursts of 4 reads are 5 to 12% faster.
- Each read takes one engine step instead of two.
- Outputs are close but not bit-identical. The label argmax matched in 96 of 96 reads and the emitted label token in 93 of 96, with no systematic shift.
- `single_pass_reads` is rejected with pipeline parallelism, with a KV connector and on platforms other than CPU.
- Prompt logprobs never report rows past the prompt, for every model on Model Runner V2. DiffusionGemma prompt logprobs use the full vocabulary. Both apply with the flag off.
- The structured diffusion README documents the flag.

google/diffusiongemma-26B-A4B-it in BF16 with LLM.generate, compiled, prefix caching on, max_num_seqs=16, max_num_batched_tokens=8192. The flag is diffusion_config={"canvas_length": 64, "single_pass_reads": True}. Synthetic chat prompts of 188 and 1250 tokens. Each read is read-only and one step, with a seeded canvas. Per shape, 12 single reads and 3 bursts of 4, after one warmup read and one warmup burst. Arms ran in the order flag off, flag on, flag off again.

Each single read saves 0.13 to 0.17 s. The relative gain is smaller for long prompts, where prefill dominates. Burst medians come from 3 bursts. The 1250/32 burst baseline did not reproduce, and against the second flag-off run that gain is 5.1%. Startup time did not change. Peak RSS was 63.8 GiB with the flag on, against 62.9 and 63.0 GiB with it off. Over the 60 timed calls the flag cut engine steps from 132 to 72.

| | single reads (48) | bursts of 4 (48) |
|---|---|---|
| identical tokens, flag on vs off | 34 | 41 |
| identical tokens, flag off vs off | 48 | 45 |
| label argmax agrees, flag on vs off | 48 | 48 |
| emitted label token same, flag on vs off | 46 | 47 |
| emitted label token same, flag off vs off | 48 | 48 |
| top-label logprob shift, mean (sd) / max, flag on vs off | +0.03 (0.16) / 0.98 | −0.00 (0.14) / 0.68 |
| top-label logprob shift, max, flag off vs off | 0 | 0.30 |

| label TV distance, mean / max, flag off vs off | 0 / 0 | 0.005 / 0.054 |

TV distance is between the label distributions renormalized over the 3 label tokens. Single reads with the flag off are bit-identical across runs. The differences therefore come from the fused pass. For bursts the mean TV is about 3.5x the run-to-run noise. For single reads it grows with prompt length, from 0.003 to 0.006 at 188 tokens to 0.029 to 0.033 at 1250. The worst read moved its top label from 0.86 to 0.71.

## Details

Design:

- `Scheduler` gets a no-op hook, `_final_prefill_spec_tokens`. `DiffusionScheduler` returns one canvas of placeholder drafts when a step finishes the prompt of a one-step read. The canvas must fit the token budget and `max_model_len`. If KV allocation fails with the canvas, the scheduler retries without it.
- The DiffusionGemma model state splits each fused request into a causal prompt row and a bidirectional canvas row on the same block table.
- `is_one_step_read` is the single eligibility rule for the scheduler and the sampler.

Tradeoffs:

- Outputs are not bit-identical with the flag on.
- As on `main`, prompt logits are computed for every scheduled row when any request asks for prompt logprobs. A fused step adds its canvas rows to that work and drops them.

Limitations:

- CPU only. The platform check runs in the worker. `test_scheduler.py` runs on a CPU CI agent whose platform does not resolve to CPU, and a config check would fail there.
- No CI job runs a fused forward pass. The A/B above is the end-to-end check.
