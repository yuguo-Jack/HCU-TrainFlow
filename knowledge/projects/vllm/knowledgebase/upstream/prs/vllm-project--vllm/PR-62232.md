# [Bugfix][Mamba] Support Mamba2 prefill checkpoints on CPU and declare checkpoint alignment

[Upstream PR](https://github.com/vllm-project/vllm/pull/62232) · state: open · merged: False

## Original PR description

## Purpose

Fixes #62153.

After #57329, `MambaMixer2.get_kv_cache_spec` sets `num_prefill_checkpoint_blocks=1` and `prefill_checkpoint_alignment=1`. Once a prompt is longer than `block_size`, `Mamba2AttentionMetadataBuilder` emits a mid-prefill checkpoint (`has_checkpoints = True`), which exposed three issues:

1. `_mamba_chunk_scan_combined_fwd_cpu` ignored `return_intermediate_states=True` and always returned `(batch, nheads, headdim, dstate)` instead of `(num_chunks, nheads, headdim, dstate)`, so `varlen_states[last_chunk_indices_p]` crashed with `IndexError: index 1 is out of bounds for dimension 0 with size 1`.
2. `MambaPrefillCheckpointExporter.export` (which replaced `store_prefill_checkpoint` in #63742) unconditionally launched the Triton kernel `store_cache_checkpoints_kernel`, which fails on CPU or when Triton is not installed.
3. `MambaMixer2` did not override `get_prefill_checkpoint_alignment()`, so `get_mamba_prefill_checkpoint_alignment()` returned `None` for models containing `MambaMixer2`.

## Test Plan

- Ran `pytest tests/kernels/mamba/test_mamba2_checkpoint_state.py` on CPU, including `test_store_selects_the_checkpoint_from_all_chunk_states` and `test_cpu_chunk_scan_return_intermediate_states_and_alignment`.
