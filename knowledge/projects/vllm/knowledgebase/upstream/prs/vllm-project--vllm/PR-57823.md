# [Bugfix][MoE] Respect padded row strides in top-k routing

[Upstream PR](https://github.com/vllm-project/vllm/pull/57823) · state: open · merged: False

## Original PR description

## Purpose

Fixes #56900.

Inductor can produce router logits with padded physical rows, for example shape
`[M, 60]` and stride `(64, 1)`. The native MoE top-k path used
`blockIdx.x * num_experts` to locate each input row, so it read the wrong logits
whenever the physical row stride differed from `num_experts`. This silently
changed expert routing under compilation.

This change:

- propagates `gating_output.stride(0)` to the native top-k launcher;
- uses the existing unfused softmax/sigmoid plus top-k path for padded rows;
- allocates the required workspace for padded power-of-two expert counts;
- keeps packed rows on the existing specialized path; and
- adds regression coverage for softmax and sigmoid with 60/64 and 64/72
  logical/physical row widths.

The input-row offset is `int64_t` because PyTorch tensor strides are 64-bit;
this also avoids 32-bit wraparound in the input address calculation. Open PR
[#53131](https://github.com/vllm-project/vllm/pull/53131) independently widens
packed-row pointer arithmetic more broadly, but it does not propagate
`stride(0)` or handle padded rows. The two changes overlap only on the
input-offset width; this PR addresses the separate functional stride bug.

No open PR referencing #56900 or implementing padded-row support for this
kernel was found before submission.
