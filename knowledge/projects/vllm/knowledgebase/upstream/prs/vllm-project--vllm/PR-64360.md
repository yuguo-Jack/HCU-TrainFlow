# [BugFix] Parse FunctionGemma arguments the way the chat template writes them

[Upstream PR](https://github.com/vllm-project/vllm/pull/64360) · state: open · merged: False

## Original PR description

## Overview

FunctionGemma argument parsing follows the chat template: `<escape>` values stay strings, and numbers, booleans, null, arrays, and objects are parsed from the bare form. Fixes #63983 and #63906.

## Claims

- `<escape>123<escape>`, `<escape>true<escape>`, `<escape>null<escape>`, and other escape-delimited text stay strings.
- A call shaped like the template (`days:[<escape>mon<escape>,...]`, `enabled:true`, `hour:7`, `snooze:{minutes:5}`) round-trips in non-streaming `extract_tool_calls` and in the streaming parser's accumulated arguments.
- Nested `}` no longer truncates the call. The old regex stopped at the first closing brace.

## Validation

CPU parser tests, no weights or GPU:

`python3 -m pytest tests/tool_parsers/test_functiongemma_tool_parser.py -q --noconftest`

On the previous parser the new cases failed (escape text was `json.loads`'d, bare keys were dropped, the nested `snooze` object was cut). After this commit the file reports 24 passed.

## Details

The template wraps only strings in `<escape>`. `arg_regex` required that wrapper and then ran `json.loads` on the contents, so string parameters that look like JSON changed type and every bare value disappeared. The replacement scans keys, escape strings, nested objects, and arrays, and JSON-decodes only bare scalars.
