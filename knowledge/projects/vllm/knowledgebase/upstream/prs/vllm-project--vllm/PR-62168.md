# [Bugfix][Model Runner V2] Read main_stream at step time, not at first use

[Upstream PR](https://github.com/vllm-project/vllm/pull/62168) · state: open · merged: False

## Original PR description



## Overview

Model runner V2 cached `main_stream` the first time it was read. A runner stepped later on another stream ordered its async output copy against the cached stream and crashed with an illegal memory access. This reads the stream at step time, as model runner V1 already does.

## Claims

- `GPUModelRunner.main_stream` returns the stream current on the calling thread at step time, not the one current at first use.
- Fixes a CUDA illegal memory access when an in-process engine (`VLLM_ENABLE_V1_MULTIPROCESSING=0`) is stepped inside `torch.cuda.stream(s)` after an earlier step ran on another stream: 3 of 3 runs crash on main, 0 of 3 with this PR.
- No throughput change on the default path (table below).

## Validation

**GPU reproducer** (script below), `--mode single`: one engine, one thread. RTX 5090 (32 GB), driver 595.71.05, torch 2.14.0+cu130, vLLM wheel for main @ `ce49c47cb`, `Qwen/Qwen2.5-0.5B-Instruct`, 3 runs per arm.

```bash
VLLM_USE_V2_MODEL_RUNNER=1 VLLM_ENABLE_V1_MULTIPROCESSING=0 python repro_v2_main_stream.py --mode single
```

|---|---|---|---|---|
| main @ `ce49c47cb` | 3 | 3 (`CUDA error: an illegal memory access was encountered`) | 1 of 3, 1 of 3, 1 of 2 | — (crashed in round 1) |

Before each crash, the detokenizer logged 14 to 16 token ids per run that are far outside the vocabulary, such as `4625829400468308008`. The host copy read the sampler output before the sampler wrote it. A control (the same prompts rerun with no stream switch) matched the baseline in all 6 runs: 0 of 160 differed.

```python
# Repro: model runner V2 caches `main_stream` at first read.
#
# An engine stepped inside `torch.cuda.stream(s)` after its first step ran on
# another stream orders its async output copy against the cached stream, not
# against `s`. The copy block's exit then moves the thread onto the cached
# stream, so the next step runs there with no ordering against `s`.
#
# Needs one CUDA GPU with ~6 GB free (~12 GB for --mode threads).
#
#   VLLM_USE_V2_MODEL_RUNNER=1 VLLM_ENABLE_V1_MULTIPROCESSING=0 \
#       python repro_v2_main_stream.py --mode single|threads
#
#   --mode single   one engine, stepped on one thread (no Python concurrency)
#   --mode threads  two engines in one process, each stepped from its own
#                   thread on its own stream
#
# Output:
#   STALE_STEPS=<n> of <m>  steps whose output copy waited on a stream other
#                           than the one current on the stepping thread
#                           (deterministic; 0 expected after the fix)
#   MOVED_ROUNDS=<n> of <m> rounds after which the thread was no longer on its
#                           own stream (deterministic; 0 expected after the fix)
#   CTRL_MISMATCH=<n> of <m> control: the same prompts rerun with no stream
#                           switch, compared with the baseline
#   MISMATCH=<n> of <m>     greedy outputs under the stream that differ from the
#                           baseline (timing-dependent)
#   CRASH=<exc>             if a run raised
# Exit code: 0 clean, 1 stale/moved/mismatch/crash seen, 2 setup error.

import argparse
import os
import sys
import threading

os.environ.setdefault("VLLM_USE_V2_MODEL_RUNNER", "1")
os.environ.setdefault("VLLM_ENABLE_V1_MULTIPROCESSING", "0")

import torch  # noqa: E402

from vllm import LLM, SamplingParams  # noqa: E402
from vllm.v1.worker.gpu import async_utils  # noqa: E402

stale = {"steps": 0, "total": 0}
_lock = threading.Lock()
_orig_init = async_utils.AsyncOutput.__init__


def _spy_init(self, *args, **kwargs):
    main = kwargs.get("main_stream")
    if main is not None:
        cur = torch.cuda.current_stream()
        with _lock:
            stale["total"] += 1
            if main.cuda_stream != cur.cuda_stream:
                stale["steps"] += 1
    _orig_init(self, *args, **kwargs)


async_utils.AsyncOutput.__init__ = _spy_init

PROMPTS = [f"Count from {i} to {i + 20}:" for i in range(32)]
SP = SamplingParams(temperature=0.0, max_tokens=64, seed=0)


def texts(outs):
    return [o.outputs[0].text for o in outs]


def diff(got, ref):
    return sum(x != y for x, y in zip(got, ref))


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--mode", choices=("single", "threads"), default="threads")
    ap.add_argument("--model", default="Qwen/Qwen2.5-0.5B-Instruct")
    ap.add_argument("--rounds", type=int, default=20)
    ap.add_argument("--control-rounds", type=int, default=5)
    ap.add_argument("--mem", type=float, default=0.30)
    a = ap.parse_args()
    if not torch.cuda.is_available():
        print("SETUP_ERROR: no CUDA device")
        return 2

    kw = dict(model=a.model, gpu_memory_utilization=a.mem, enforce_eager=True,
              max_model_len=1024, seed=0)
    n = 1 if a.mode == "single" else 2
    engines = [LLM(**kw) for _ in range(n)]  # all built on the main thread

    # First step on the main thread, as a warm-up would do. This is where each
    # runner caches its main_stream.
    baseline = texts(engines[0].generate(PROMPTS, SP, use_tqdm=False))
    for e in engines[1:]:
        if texts(e.generate(PROMPTS, SP, use_tqdm=False)) != baseline:
            print("SETUP_ERROR: the engines disagree with no stream switch")
            return 2
    if stale["total"] == 0:
        print("SETUP_ERROR: the AsyncOutput spy never fired (not model runner V2?)")
        return 2

    ctrl = 0
    for _ in range(a.control_rounds):
        for e in engines:
            ctrl += diff(texts(e.generate(PROMPTS, SP, use_tqdm=False)), baseline)
    stale["steps"] = stale["total"] = 0

    errors, mismatch, moved = [], [0] * n, [0] * n

    def worker(i):
        s = torch.cuda.Stream()
        try:
            for _ in range(a.rounds):
                with torch.cuda.stream(s):
                    got = texts(engines[i].generate(PROMPTS, SP, use_tqdm=False))
                    if torch.cuda.current_stream().cuda_stream != s.cuda_stream:
                        moved[i] += 1
                mismatch[i] += diff(got, baseline)
            torch.cuda.synchronize()
        except Exception as e:  # noqa: BLE001
            errors.append(f"engine{i}: {type(e).__name__}: {e}"[:400])

    if n == 1:
        worker(0)
    else:
        ts = [threading.Thread(target=worker, args=(i,)) for i in range(n)]
        for t in ts:
            t.start()
        for t in ts:
            t.join()

    runs = n * a.rounds * len(PROMPTS)
    print(f"MODE={a.mode}")
    print(f"STALE_STEPS={stale['steps']} of {stale['total']}")
    print(f"MOVED_ROUNDS={sum(moved)} of {n * a.rounds}")
    print(f"CTRL_MISMATCH={ctrl} of {n * a.control_rounds * len(PROMPTS)}")
    print(f"MISMATCH={sum(mismatch)} of {runs}")
    for e in errors:
        print(f"CRASH={e}")
    bad = stale["steps"] or sum(moved) or sum(mismatch) or errors
    return 1 if bad else 0


if __name__ == "__main__":
    sys.exit(main())
```

## Details

**Root cause.** `main_stream` was a `functools.cached_property` around `torch.cuda.current_stream(self.device)`. `AsyncOutput` and `AsyncPoolingOutput` (`gpu/async_utils.py`) use it twice:

1. The copy stream waits on it (`copy_stream.wait_stream(main_stream)`).
2. When the copy block exits, the thread's current stream is set back to it (`async_utils.stream()`).

If the step ran on stream S but the cache holds stream D, the device-to-host copy is ordered after D, not S, so it can read the sampler outputs before they are written. Step 2 then moves the thread onto D. The next step runs on D with no ordering against the work still pending on S.

**Fix.** A plain `@property` with the same body. Model runner V1 already reads `torch.cuda.current_stream()` per step (`AsyncGPUModelRunnerOutput`, `gpu_model_runner.py:296`), so V1 is not affected. On the usual path the property returns the same stream the cache held. `torch.cuda.current_stream()` is a host-side lookup and adds no GPU sync.

**Tradeoff.** The cache existed to avoid that lookup. The property is read once per step, and the table above shows no throughput change. `vllm.utils.torch_utils.current_stream()` (thread-local) would skip building a stream object, but on a thread with no stream set it creates and sets a new one, which changes behavior beyond this fix.

**Scope.** V2 only. `pp_utils.py` keeps its own `main_stream`, captured at construction, for pipeline-parallel ranks, where one runner and one stream per process is the norm. Two in-process engines stepped from two threads still fail with this PR, for a separate reason: the forward context is a module global (`vllm/forward_context.py`). In 3 runs, one raised a shape mismatch, one raised `Forward context is not set`, and one returned every output wrong.

**Not a duplicate.** Searched open and closed issues and PRs for `main_stream` and for several engines in one process. #58082 (open) changes the same line but keeps the cache. The two changes conflict textually, and either order resolves trivially.
