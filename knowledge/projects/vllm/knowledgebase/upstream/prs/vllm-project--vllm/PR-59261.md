# [Benchmark] Fix benchmark_block_fp8_gemm.py for current FP8 kernel API

[Upstream PR](https://github.com/vllm-project/vllm/pull/59261) · state: open · merged: False

## Original PR description

## Purpose

While collecting baseline numbers for #58241 (block FP8 on SM89), I found that `benchmarks/kernels/benchmark_block_fp8_gemm.py` no longer runs on main.

The script has drifted from the current FP8 kernel API in three places:

- `init_fp8_linear_kernel` now requires `input_dtype` and `weight_shape`, which the script does not pass.
- The block-scaled kernels expose `apply_weights(layer, x)`; the script still calls `apply(...)`, which no longer exists.
- `use_cutlass` was accepted but never used, so the "triton" and "cutlass" providers both ran whichever kernel the selector picked, rather than the kernel in their name.

This PR builds a small layer with `weight` / `weight_scale_inv` (the same names `Fp8LinearMethod` registers), runs `process_weights_after_loading` so each kernel sees the weights it would see in a real model, and passes `force_kernel` so each provider benchmarks the kernel it names. It also asserts that the kernel it got is the one it forced, since `force_kernel` falls back to another kernel when the forced one can't be used.

I checked that no open PR touches this file.

AI assistance was used to read through the kernel API. I wrote the fix, tested it end to end on an L4 and an H100, and reviewed every line.

## Test Plan

NVIDIA L4 (SM89), torch 2.13.0+cu132, vLLM main @ 741edeebe (precompiled install), and NVIDIA H100 PCIe (SM90), torch 2.13.0+cu130 (precompiled install of this branch):

```bash

```

`pre-commit run` passes (ruff, mypy, typos).
