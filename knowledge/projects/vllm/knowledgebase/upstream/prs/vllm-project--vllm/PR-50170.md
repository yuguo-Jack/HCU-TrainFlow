# [Bugfix][Spec Decode] Warn when Eagle3 aux layers fall back to a default

[Upstream PR](https://github.com/vllm-project/vllm/pull/50170) · state: open · merged: False

## Original PR description

Eagle3 draft heads consume auxiliary hidden states captured from several target
model layers. When the draft config does not name those layers, both model
runners fall back to a per-architecture heuristic
(`2, num_layers // 2, num_layers - 3`). If the head was trained on other layers
the drafts are computed from representations it never saw, acceptance
collapses, and the run ends up slower than plain decoding — while the server
stays healthy and output stays correct, so nothing surfaces it.

Serving `nvidia/Llama-3.3-70B-Instruct-Eagle3` on Llama-3.3-70B hits this. The
head's config omits `eagle_aux_hidden_state_layer_ids`, so the heuristic picks
`(2, 40, 77)` and the measured result is:

| | this head | correctly configured head |
|---|---|---|
| acceptance rate | 1.21% (341 / 28281 draft tokens) | 58.9% |
| mean accepted length | 1.036 | 2.77 |
| per-position acceptance | 0.036 / 0.0006 / 0.000 | 0.751 / 0.567 / 0.453 |
| throughput vs spec disabled | 0.70-0.79x | ~0.89x |

Position 2 was never accepted once across the whole run. The only signal is the
`vllm:spec_decode_num_accepted_tokens_total` / `..._num_draft_tokens_total`
metrics; the logs say nothing about the layers having been guessed.

This patch warns once when the fallback is taken and names the setting that
pins the layers. The legacy runner did not log the fallback at all. No
behavior change.

On the specific checkpoint above, the warning is as far as vLLM can go on its
own. The head ships `fc.weight` with shape `[8192, 24576]` (= 3 x 8192), so it
consumes three distinct hidden states, but its config declares
`num_eagle_features: 1` / `eagle_config.use_aux_hidden_state: false` and it
carries TensorRT-LLM's `eagle3_layers_to_capture: [-1]`, a key vLLM does not
read anywhere. Checking the three 8192-wide column blocks of `fc.weight`, all
three are fully populated with near-identical magnitudes (mean |w| 1.5957e-02 /
1.5958e-02 / 1.5958e-02) and are not element-wise equal, so this is not the
final hidden state replicated three times. Which three target layers the head
was trained against is not recoverable from the checkpoint and is not
documented, so the correct value for `eagle_aux_hidden_state_layer_ids` would
have to come from the checkpoint's publisher. Making vLLM read
`eagle3_layers_to_capture` would not help until that mapping is known.

## Test

`pytest tests/v1/spec_decode/test_eagle3_aux_layer_fallback.py` — CPU only, no
model download.

## Environment

Measured on 2x RTX PRO 4500 Blackwell (32 GB each, sm_120), TP=2, vLLM 0.25.1
container, Llama-3.3-70B-Instruct AWQ-INT4 target, `num_speculative_tokens=3`,
`max_model_len` 12288, temperature 0, 24-prompt workload. The code paths
touched here are unchanged on `main`.

## Not addressed here

On the V2 runner, `eagle_config.use_aux_hidden_state: false` is still ignored
(`gpu/model_runner.py` sets `use_aux_hidden_state_outputs = True`
unconditionally for eagle3/dflash/dspark), which makes a head that declares it
fail with a `8192` vs `24576` shape mismatch. That is a separate defect with an
actual behavior change — previously reported in #40551 and attempted in #40656.
Happy to file it separately rather than widen this PR.
