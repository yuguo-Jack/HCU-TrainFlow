# [Perf][Model] Shard large QSA prefill query rows on SM90 TP4

[Upstream PR](https://github.com/vllm-project/vllm/pull/65606) · state: open · merged: False

## Original PR description



## Overview

Qwen4Exp QSA repeats prefill scoring and Top-K on every TP rank. Assign complete prefill query rows to ranks and gather the final `int32` indices, reusing the existing scorer and Top-K with replicated K/cache.

This applies the row-ownership principle from #54394 to QSA's separate model/indexer path. It does not depend on that PR.

## Claims

- Lower long-context prefill latency on 4×H20: about **7.4% lower TTFT at 256K/C1 with MTP disabled**, reproduced across two independent boot pairs. MTP-enabled measurements also improved TTFT by 3–8% at 128K/256K, C1/C4.
- Automatically enable only for single-node MP, SM90, TP4, BF16 indexer H4/D128, selection budget 2048, compression 4, at least 4096 actual prefill rows and 64K context. Other configurations retain replicated selection; a scheduling token budget of 799 does not activate it.
- Decode uses its existing path. This is a prefill latency claim, not a claim of decode acceleration or regression-free generation.

## Validation

**Independent serving ABBA**, baseline `e11a5ada533`, identical image/flags in both arms, Qwen3.8-Flash-Next-FP8, TP4+EP, Triton MoE, token budget 8192, Mamba `align`, MTP off, prefix cache cleared per request. Two 262144-token authored document-retrieval tasks; temperature 0, seed 1731, natural EOS, up to 1024 output tokens. Four fresh starts, 32 requests including 24 formal samples, all formal structured answers correct. No APC hits, preemptions or thermal throttling.

Cells show the two boot-pair medians; changes are the geometric mean of the paired ratios.

| Task | Baseline TTFT (s) | Patched TTFT (s) | TTFT change | Full-request change |
|---|---:|---:|---:|---:|
| KV-cache document | 14.716 / 14.693 | 13.607 / 13.607 | -7.46% | -6.68% |
| Parallel-config document | 14.692 / 14.681 | 13.588 / 13.605 | -7.42% | -7.71% |

Target TPOT changed +0.74% / -1.09% across the two pairs. Natural output lengths vary, so full-request changes are observations, not fixed-workload throughput gains.

**Correctness:** 97 targeted GPU tests passed (96 reference/configuration tests + one real TP4 test), covering fallback boundaries, ragged rows, offset views, one-row chunks, and exact-score ties. Twenty-four real-input rank checks matched selected-score multisets exactly; tied scores can yield different valid index sets. Synthetic 128K/256K retrieval was 32/32 correct per arm. These are narrow regressions, not broad model accuracy evaluation.

Reproduce the suites and the included selector benchmark in a CUDA vLLM environment:

```bash
uv run --offline --no-project .venv/bin/python -m pytest tests/models/qwen4_exp/test_qsa_reference.py -q
uv run --offline --no-project .venv/bin/python -m pytest tests/models/qwen4_exp/test_tpsp.py -k qsa_tp_prefill -q
uv run --offline --no-project .venv/bin/python -m torch.distributed.run --standalone --nproc-per-node=4 benchmarks/kernels/benchmark_qsa_tp_prefill.py --output qsa-tp4.json
```

The recorded GPU runs used copies of these suites with an isolated pytest configuration against the installed candidate. All applicable pre-commit hooks passed. Existing single-GPU Qwen CI covers the reference suite; this PR adds an optional four-H100 nightly entry for the TP4 test. Full repository CI has not been run locally.

## Details

Each rank scores complete rows against the full key history; only final indices are exchanged. Equal-sized gather buffers are trimmed to the original row count. DCP/PCP, batch-invariant execution, disabled PyNCCL, NCCL symmetric-memory collectives and FULL mixed graphs fall back. See the [user documentation](https://github.com/positive666/vllm/blob/d7eb414a6694a488771e0cc57a9fd69d2a481ce7/docs/configuration/optimization.md#qwen38-flash-next-qsa-prefill).

Non-duplication checked on 2026-11-04: #54394 covers DSA, #61242 shards QSA keys/cache for DCP, #65470 compacts a kernel's mixed-request grid, and #59010 changes sparse-attention computation. This patch partitions QSA prefill query rows under ordinary TP with DCP=1. Combined performance with those changes is untested. H100/H200 performance, TP8, production P99 and broad model accuracy are unmeasured.
