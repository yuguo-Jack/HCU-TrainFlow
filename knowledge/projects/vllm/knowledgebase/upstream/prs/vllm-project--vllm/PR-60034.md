# [WIP][Perf] Tune small-M batch-invariant GEMMs on Hopper

[Upstream PR](https://github.com/vllm-project/vllm/pull/60034) · state: open · merged: False

## Original PR description

## Overview

Add small-row BF16 persistent-matmul tuning entries for five Hopper linear shapes.
This is a tuning-only draft; compiled runtime-M dispatch is covered separately by
#54503 and is a dependency for realizing the measured serving improvement.

Human review and GPU validation of this exact current-main branch are pending.

## Claims

- For the five shape pairs, use 16-row tiles at `M <= 16` instead of the previous
  128-row fallback. Retain the previous tile for larger M.
- Keep `BLOCK_K=64` across all M buckets. Do not change the reduction algorithm,
  collectives, scheduler or behavior of other architectures/shapes.
- Add an exact-byte regression against the former fallback, including target
  rows at both ends of a batch and the small/large-M bucket boundary.

## Validation

Earlier H100 experiments measured these same tile choices with CUDA-graph replay,
FlashInfer CUPTI timing and cold L2. Compilation/allocation were outside timing;
clocks were not locked. All 125 tested shape/batch/tile combinations matched the
original BF16 output; repeated target rows matched singleton outputs for M=1, 8,
16, 64 and 512. Seed 42, contiguous inputs, transposed contiguous linear weights.

Eight-row median kernel timings, microseconds:

| N / K | Previous tile | Selected tile | Previous | Selected |
| --- | --- | --- | ---: | ---: |
| 17408 / 5120 | 128x128 | 16x256 | 184.86 | 80.93 |
| 5120 / 8704 | 128x128 | 16x64 | 127.42 | 70.34 |
| 8192 / 5120 | 128x128 | 16x64 | 112.51 | 52.58 |
| 5120 / 3072 | 128x128 | 16x64 | 56.42 | 28.90 |
| 124160 / 5120 | 128x128 | 16x256 | 803.65 | 453.79 |

An earlier experiment integrating these tiles with an experimental runtime-dispatch
op on a private dense 27B checkpoint produced:

| Warm workload | Original BIC tok/s | Tuned BIC tok/s | Normal tok/s |
| --- | ---: | ---: | ---: |
| Decode | 183.78 | 306.76 | 573.36 |
| Mixed text/image/history | 109.34 | 182.50 | 365.75 |

That used BF16 TP2, two H100s, compiled serving, prefix caching, concurrency 8,
8 maximum sequences, a 512-token scheduler budget and maximum context 32768.
Three measured waves followed two warmups; mode runs were sequential, not
interleaved. Prompt/output/cache work matched across all warm waves.
Each version passed 216 response fingerprints and 8,208 sampled full-vocabulary
logit records across two ranks. This sampled positions 0..15, 31, 63 and 127 for
128-token outputs, not every vector at every token.

These are experiment-tree results, **not measured speedups from this standalone
table-only PR**. Dynamic compilation can freeze the Python tile lookup; #54503
addresses that. This draft deliberately does not duplicate its custom op or JIT
prewarming implementation. Empty-cache controls are incomplete, and there is no
claim of cold-load improvement or universal bitwise determinism.

Current draft: Ruff check/format, AST parsing and `git diff --check` passed.
The contributed GPU regression has not run: the H100 pool has no free capacity.
Run before marking ready:

```bash
.venv/bin/python -m pytest tests/v1/determinism/test_matmul_batch_invariant.py \
  -k hopper_small_m_tiles_preserve_fallback_bits -v
```

Also validate compiled runtime selection/JIT prewarming with #54503, repeat
equal-work cache-off and warm serving benchmarks on the exact integrated head,
and run public-model/non-BIC and model-quality checks. The private checkpoint,
prompts and trace artifacts are not included in the contribution.

## Details

The 128-row fallback spends much of a small decode tile on unused rows. Narrower
M tiles were faster in the measured shapes; the preferred N tile differed by
projection width. Small tiles regressed large-M prefill in the sweep, so larger
M retains the old configuration.

The duplicate-work check found #54503 (runtime dispatch), #49131 (SM80 tuning) and
#55676 (Ada tuning). This PR only adds the measured Hopper shape entries; it does
not replace those contributions. GEMM tuning is separate from GDN correctness and
TP/EP collective work.

AI assistance was used in implementation, experiments and preparation of this
draft. Human line-by-line review is pending.
