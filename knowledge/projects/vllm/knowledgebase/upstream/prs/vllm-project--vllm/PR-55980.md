# [Rust Frontend][gRPC] Honor the gRPC max_new_tokens default

[Upstream PR](https://github.com/vllm-project/vllm/pull/55980) · state: open · merged: False

## Original PR description




## Purpose

The gRPC protobuf contract documents `max_new_tokens=0` as a 20-token default. However, the request converter previously left the internal `max_tokens` unset when `max_new_tokens` was zero or `stopping` was omitted. Downstream processing could then use a model default or the entire remaining context capacity.

  Initialize gRPC sampling parameters with `max_tokens=20`. Existing positive `max_new_tokens` values continue to override the default.

  The resulting behavior is:

  - Omitted `stopping` → `max_tokens=20`
  - `max_new_tokens=0` → `max_tokens=20`
  - Positive `max_new_tokens` → preserve the requested value

This prevents unexpectedly large generation budgets and makes runtime behavior match the published protobuf contract.
