# [ROCm][Perf][GLM-5] Fused sparse-layer decode via AITER MonoKernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/60216) · state: closed · merged: False

## Original PR description



## Overview

Opt-in decode path for GLM-5 (`glm_moe_dsa`) on ROCm gfx950. With `VLLM_ROCM_GLM_MONO_DECODE=1`, each decoder layer of a pure decode step (3 dense, 75 MoE) runs as one AITER MonoKernel launch per GPU. That launch includes the sparse indexer and both tensor-parallel all-reduces.

**Depends on ROCm/aiter#6173**, which adds the kernel (`aiter.ops.flydsl.glm5_mono`). The kernel comes from ROCm/FlyDSL#1204 and ROCm/ATOM#2435. The structure follows the MiniMax-M3 fused decode in #59653.

## Claims

- 8x MI355X, GLM-5.3 MXFP4, TP8, fp8 KV, serving benchmark:
  - TPOT -40.9% at concurrency 4 and -27.4% at 8 (8K input / 1K output).
  - TPOT -18.4% at concurrency 4 and -8.1% at 8 (60K input / 600 output).
- 4x MI355X, TP4: TPOT 1.41x faster at concurrency 1 (8K input / 256 output).
- Accuracy matches the regular path: NIAH 1.000 vs 1.000, GPQA Diamond 0.899 vs 0.879, GSM8K within run-to-run noise.
- The last two commits run the dense layers in the kernel and advance its epoch once per step: TPOT -6.1% / -2.9% at concurrency 1 / 4 on TP4 and -8.8% / -5.0% on TP8, on top of the above (8K).
- Default off. When it is on, steps the kernel does not cover (prefill, mixed, more than 8 tokens) keep the regular layers and their CUDA graphs.

## Details

**When the path runs.**
- Pure decode steps of 1, 2, 4 or 8 tokens, one token per request. A step of 1 is launched as 2 with a pad row.
- Startup checks, each failing with a reason: gfx950, TP 4 or 8, `--kv-cache-dtype fp8`, `VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1`, no speculative decoding, `indexer_rope_interleave`, and indexer RoPE tables equal to the MLA ones.
- The decision depends only on the token count and the attention metadata, so every rank makes the same one.

**Residual stream.** The embedding feeds the first launch, and the kernel carries the full residual stream through all 78 layers; the final norm runs on it.

**Weights.**
- Experts are read in place: AITER-shuffled MXFP4, with the shared expert in the last slot.
- The dense layers' MLP (six times the expert width) is packed once as six expert-shaped MXFP4 slices; the kernel routes every row to all six with weight 1. This needs the row-major MXFP4 layout of the AITER Triton GEMM, the default.
- Block-FP8 attention projections are repacked once, about 4 GB per GPU.
- W_UK/W_UV are cut from `kv_b_proj`, keeping the checkpoint's FP8 blocks.
- The indexer's `wk_weights_proj` (bf16) and `wq_b` (block FP8) are bound as-is.

**Indexer.**
- On indexer layers the kernel reads and writes the layer's paged FP8 index cache through `block_table` and `req_id_per_token`.
- It writes the top-2048 global slots to `paged_kv_indices`, which the following shared-index layers reuse.
- Layer 2's fused indexer writes the slots that the following shared-index layers read, so nothing is converted outside the kernel.

**CUDA graphs.**
- Weights bind on the first eligible step, which runs eagerly before capture. Reaching the path inside a capture first raises.
- Pad rows added when a batch is padded to a captured size have slot < 0; the kernel writes no cache entry for them.
- Each kernel runtime advances its epoch once per step. Every layer has its own launch slot within the step, so the step counter is not bumped between layers.

**Numerics.** Greedy text diverges from the regular path after a few tokens. The kernel quantizes activations to MXFP8 for the MXFP4 experts, where the regular path quantizes them to MXFP4. That is why accuracy is checked with evals rather than token match.

**Size.** About 545 lines outside tests, almost all in the new `mono_decode.py`. The only change to an existing file is an 11-line hook in `DeepseekV32Model` plus one env var. No model runner, scheduler or attention backend changes.

**Limitations.**
- Only gfx950 and GLM-5 (`glm_moe_dsa`).
- Concurrency above 8 uses the regular path.
- Needs an AITER build that contains ROCm/aiter#6173.
