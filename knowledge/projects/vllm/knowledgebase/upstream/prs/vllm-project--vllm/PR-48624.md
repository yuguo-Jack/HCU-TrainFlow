# [Bugfix][NVFP4/FP8 MoE] Fix gated MoE crash on unaligned intermediate size

[Upstream PR](https://github.com/vllm-project/vllm/pull/48624) · state: open · merged: False

## Original PR description

## Purpose

Fix gated MoE intermediate size padding for FlashInfer/CUTLASS NVFP4 and FP8
kernels.

Originally found and fixed while deploying **Gemma-4-26B-A4B NVFP4** on
Jul 14 — its `moe_intermediate_size=704` is not 128-aligned after TP
sharding and fails during `process_weights_after_loading`. The same failure
has since been hit independently on other released models:

- **#57125** (resolved by this PR): Qwen3.8-Flash-Next NVFP4 fails to start
  on 4× RTX 5090 at TP=4 (640/4 = 160/rank)
- **#48921**: Step-3.7-Flash-NVFP4 at TP=8 (1280/8 = 160/rank, the same
  rank-local size), confirmed on 8× B300; lists this PR as the padding
  prerequisite for the CUTLASS path
- **#55649**: Gemma-4-26B follow-up context

Related: #46880, #42516, #46879.

Gated MoE models (e.g. Gemma-4-26B-A4B) whose `moe_intermediate_size` is not
a multiple of the kernel tile size after TP sharding fail during
`process_weights_after_loading` with either:

1. `NotImplementedError: Intermediate size padding for w1 and w3` —
   CUTLASS / VLLM_CUTLASS path
2. `AssertionError: assert M % 128 == 0` — TRTLLM path

**Root cause:** The align functions (`align_fp4_moe_weights_for_fi` and
`align_moe_weights_for_fi`) padded gated w13 weights with simple end-pad
`[gate(N), up(N), zeros(pad)]`. This breaks the gate/up boundary — the kernel
splits w13 at `padded_intermediate` to separate gate and up, but the zeros
land inside the up section, shifting the boundary. Additionally, the CUTLASS
else branch raised `NotImplementedError` for gated instead of padding, and
the TRTLLM path used `min_alignment=16` which is too weak for the shuffle's
`M % 128` assert.

**Fix (this PR):**

The split-pad half of the original fix (gating-aware padding in
`align_fp4_moe_weights_for_fi` / `align_moe_weights_for_fi`, and the TRTLLM
`min_alignment` 16→64 change) has since landed in main via #46880 / #53896.
What remains in this PR is the else-branch half, reworked per review:

1. Hoist the weight alignment out of the TRTLLM if/else in
   `prepare_nvfp4_moe_layer_for_fi_or_cutlass` so all backends share it.
2. `min_alignment = 64 if is_gated else 128`: the swizzled block scales need
   the *stacked* dim % 128, which for gated (2*I) means I % 64 suffices;
   non-gated stacks to I and needs I % 128. Padding gated to 64 (not 128)
   avoids unnecessary weight rows: Qwen3.8-Flash-Next at TP=4 pads 160→192,
   not 160→256.
3. Keep `layer.moe_config.intermediate_size_per_partition` in sync with the
   padded weight shapes. Required, not just tidy: the experts wrappers are
   constructed later in `process_weights_after_loading` (`_build_moe_kernel`)
   and the CUTLASS experts derive their GEMM N from this config value — a
   stale value would desync the launch shape from the padded weights.

The TRTLLM branch keeps only its hidden-dim alignment and static weight
prep; the else branch keeps only the two `swizzle_blockscale` calls.

Split-pad + zero-fill is mathematically correct for all TP values: padded
rows have zero weights → zero GEMM output → `f(0) * 0 = 0` for all standard
gated activations (SILU, GELU-Tanh, GEGLU) → zero contribution to final
output. The `half = w13.shape[1] // 2` split point always lands on the
gate/up boundary because `w13.shape[1] = 2 * intermediate_per_partition`
(gate and up are equal size by definition).

## Test Plan

**Unit tests** (CPU, in-tree at
`tests/quantization/test_trtllm_nvfp4_hidden_dim_padding.py`):

- gated 160→192 (no over-padding to 256), gate/up stay in separate
  zero-padded halves, `moe_config.intermediate_size_per_partition` updated
  to 192
- already-aligned gated input is a no-op (identity)
- non-gated 160→256 (I % 128)
- pre-existing TRTLLM hidden-dim padding cases unchanged

**GPU e2e** (RTX 5090, sm120, FLASHINFER_CUTLASS): synthetic lossless NVFP4
MoE (weights/scales exactly on the FP4 grid), gated I=160 (padded 160→192)
and I=192 (already aligned), real `cutlass_fused_moe` vs bf16 reference.

reference end-to-end (rtol=atol=2e-1, no NaNs from the padded tail):

- gated I=160 → padded to 192: PASS

`moe_intermediate_size=704`, per-card=352, `352 % 128 = 96 ≠ 0`.
