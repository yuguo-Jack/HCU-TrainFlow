# [Perf][Kernel] Convert two FP8 values per cvt in the FP8 quant kernels

## Overview

Follow-up to #60927: the FP8 `cvt` instruction converts two values at once, but our scalar helper issues it with a zero partner. On sm_100+ this change quantizes pairs with `__nv_cvt_float2_to_fp8x2` and lets the saturating `cvt` replace the explicit clamp. Output is bit-identical to `main`.

## Claims

- **Speedup, bit-identical output:** RMSNorm + FP8 per-token/per-block quant is 1.05–1.24x faster; static, dynamic per-tensor and per-token `scaled_fp8_quant` are 1.00–1.08x faster; `merge_attn_states` with FP8 output is up to 1.03x faster. All measured on B300 with bf16/fp16/fp32 inputs.
- **No meaningful small-batch regression:** among bf16 cases, the worst at ≤128 rows is 0.98x.
- **One arch gate:** the switch is `VLLM_FP8_CVT_X2` in `csrc/core/cuda_compat.h` (`VLLM_FP8_CVT_X2_MIN_ARCH 1000`, matching #60927). The per-token-group packed path from #60927 now uses it too, with identical SASS. Hopper and older keep today's code; ROCm is unchanged.
- **All-zero input:** dynamic per-tensor quant of an all-zero tensor now writes zero bytes. On `main` it writes 448 with a 0 scale: `0 * (1/0)` is NaN, and only the clamp turned that into 448.

## Validation

**Bit-exactness.** I dumped the raw outputs (FP8 bytes and scales) of every touched op from a build of `main` and from this branch, then compared them exactly. Coverage: bf16/fp16/fp32 inputs, hidden sizes 17/1030/2048/4096/5120, aligned and unaligned views, static, per-tensor, per-token (with and without `scale_ub`), 1x128 groups, fused RMSNorm (FP8 and int8, with and without residual) and `merge_attn_states`. Result: 0 of 515 output tensors differ.

I also checked all 2^32 fp32 bit patterns: clamp-then-`cvt` and `cvt` alone agree on every non-NaN input, and the software `c10::Float8_e4m3fn` cast matches the hardware `cvt` on every non-NaN input. NaN is the only difference: it now stays FP8 NaN instead of becoming +448.

"""CUPTI + CUDA-graph, cold-L2 timing of the FP8 quant ops. usage: cupti_bench.py out.json"""
import json, os, statistics, sys
OPS = os.environ.get("OPS")
OPS = OPS.split(",") if OPS else None
import torch
from flashinfer.testing import bench_gpu_time_with_cupti
from vllm import _custom_ops as ops

FP8 = torch.float8_e4m3fn
torch.manual_seed(0)
dev = "cuda"

def bench_us(fn):
    for _ in range(25):
        fn()
    torch.cuda.synchronize()
    t = bench_gpu_time_with_cupti(fn, use_cuda_graph=True, cold_l2_cache=True,
                                  repeat_time_ms=150)
    return statistics.median(t) * 1e3

ROWS = [1, 2, 8, 32, 128, 512, 2048, 8192]
HIDDEN = [4096, 5120, 7168, 2880, 1030, 1025, 17] if not OPS else [4096, 2880, 5120]
res = {}
for dtype in (torch.bfloat16, torch.float16, torch.float32):
    dn = str(dtype).split(".")[-1]
    hiddens = HIDDEN if dtype == torch.bfloat16 else [4096, 1030]
    rows_l = ROWS if dtype == torch.bfloat16 else [1, 32, 2048]
    for hidden in hiddens:
        for rows in rows_l:
            x = (torch.randn(rows, hidden, device=dev) * 3).to(dtype)
            w = (torch.rand(hidden, device=dev) + 0.5).to(dtype)
            out = torch.empty(rows, hidden, device=dev, dtype=FP8)
            sc = torch.tensor([0.0371], device=dev)
            dsc = torch.empty(1, device=dev)
            tsc = torch.empty(rows, 1, device=dev)
            resid = (torch.randn(rows, hidden, device=dev)).to(dtype)
            tag = f"{dn}/{hidden}/{rows}"
            cases = {
                "static": lambda: torch.ops._C.static_scaled_fp8_quant(out, x, sc, None),
                "dyn_tensor": lambda: torch.ops._C.dynamic_scaled_fp8_quant(out, x, dsc),
                "dyn_token": lambda: torch.ops._C.dynamic_per_token_scaled_fp8_quant(out, x, tsc, None),
                "rms_static": lambda: torch.ops._C.rms_norm_static_fp8_quant(out, x, w, sc, 1e-6),
                "add_rms_static": lambda: torch.ops._C.fused_add_rms_norm_static_fp8_quant(out, x, resid, w, sc, 1e-6),
                "rms_dyn_token": lambda: torch.ops._C.rms_norm_dynamic_per_token_quant(out, x, w, tsc, 1e-6, None, None),
            }
            if hidden > 64:
                xv = x[:, 1:-15] if hidden % 16 == 0 else x[:, 1:]
                outv = torch.empty(xv.shape, device=dev, dtype=FP8)
                cases["static_unaligned_view"] = lambda: torch.ops._C.static_scaled_fp8_quant(outv, xv, sc, None)
            if hidden % 128 == 0:
                gsc = torch.rand(rows, hidden // 128, device=dev) * 0.05 + 0.01
                bsc = torch.empty(rows, hidden // 128, device=dev)
                cases["static_group128"] = lambda: torch.ops._C.static_scaled_fp8_quant(out, x, gsc, (1, 128))
                cases["rms_block128"] = lambda: torch.ops._C.rms_norm_per_block_quant(out, x, w, bsc, 1e-6, None, None, 128, False)
            if dtype == torch.float32:
                cases.pop("add_rms_static", None)
            for name, fn in cases.items():
                if OPS and name not in OPS:
                    continue
                try:
                    res[f"{name}/{tag}"] = bench_us(fn)
                except Exception as e:
                    print("skip", name, tag, type(e).__name__, str(e)[:80])

# merge_attn_states with fp8 output
for T, H, D in [] if OPS else [(1, 16, 512), (64, 16, 512), (4096, 16, 512), (2048, 128, 128)]:
    p = (torch.randn(T, H, D, device=dev) * 0.1).bfloat16(); s = (torch.randn(T, H, D, device=dev) * 0.1).bfloat16()
    pl = torch.randn(H, T, device=dev); sl = torch.randn(H, T, device=dev)
    o = torch.empty(T, H, D, device=dev, dtype=FP8); ol = torch.empty(H, T, device=dev)
    sc = torch.tensor([0.02], device=dev)
    res[f"merge_fp8/bfloat16/{H}x{D}/{T}"] = bench_us(lambda: ops.merge_attn_states(o, p, pl, s, sl, ol, None, sc))

json.dump(res, open(sys.argv[1], "w"))
print("cases", len(res))

## Details

- **Design:** `scaled_fp8_conversion_vec<is_scale_inverted, fp8_type, N>` in `w8a8/fp8/common.cuh` is the one helper. It pairs elements under `VLLM_FP8_CVT_X2` and otherwise, or for an odd tail, falls back to the existing scalar `scaled_fp8_conversion`. That scalar function is unchanged.
- **Call sites:** `common.cu` reaches the helper through a small functor that passes both a scalar op and a 16-wide op to `vectorize_with_alignment`. The fused RMSNorm kernels reach it through a new `ScaledQuant::quant_vec_fn` (a plain loop for int8).
- **Zero scale:** skipping the clamp means `0 * inf` would yield FP8 NaN, so every site that feeds an inverted scale into the paired path uses `fp8_reciprocal_scale`, which returns 0 for a zero scale. It measured as free.
- **Left out after measuring:**
  - Pairing in `rms_norm_static_fp8_quant` gained 3–6% at ≥512 rows but cost 1–3% at small batches.
  - Pairing in `fused_add_rms_norm_static_fp8_quant` gained nothing.
  - Removing the clamp from the scalar path was about 2% slower in those kernels.
  - Pairing while keeping the clamp was up to 15% slower on small static quant.
  - `silu_and_mul_quant` and SiTU quant were flat.
- **Known regression:** static quant on fp32 input with hidden 1030 at 2048 rows is 4.5% slower (9.54 → 9.98 us). That branch's source is unchanged, so this is a codegen side effect of the neighbouring changes in the same kernel. bf16/fp16 on the same shape are 1.01x.
- **Hopper:** the instruction exists from sm_89, but I could only validate on Blackwell. Lowering `VLLM_FP8_CVT_X2_MIN_ARCH` is the one change needed once validated on other GPUs.
- **CI coverage:** the quantization kernel tests run on L4 (sm_89) and MI300, which take the unchanged path. The sm_100+ path was validated locally on B300 as above.
- **End to end:** no serving benchmark. Output is bit-identical, so accuracy evals are unchanged by construction. The gains are prefill-weighted; decode-size launches move by ≤11% on the fused RMSNorm quant ops and ≤4% elsewhere.
- **Not a duplicate:** #60927 (merged) covers only `per_token_group_quant`. The open #41115 changes the per-token kernel's launch configuration on a since-moved file, not the conversion.
