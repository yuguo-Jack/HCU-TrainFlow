# [Bugfix][Model Loader] Reload fixes: gpt-oss writes through the loader, FlashInfer bmm scales, KV-scale dtype

[Upstream PR](https://github.com/vllm-project/vllm/pull/65353) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Reload fixes from #61287, redone on current main (PR 10 of the direct weight reload stack, #54477). Weight writes that bypass the parameter's loader in gpt-oss and six VL models, the FlashInfer bmm scales, and the KV-cache scale dtype after a reload. The test harness from #61287 is split out into PR 9.

## Claims

- **gpt-oss Quark and fused-BF16 experts update on layerwise reload.** They were written with `param.data` / `param.copy_`, which a layerwise reload (the default `VLLM_RELOAD_MODE`) drops, because it restores parameters on meta and only sees writes through the wrapped `weight_loader`. They now go through `GptOssRoutedExperts.weight_loader` with a `gpt_oss_presliced` / `gpt_oss_presliced_padded` shard id. Fresh loads are unchanged.
- **gpt-oss streamed MXFP4 experts are split across TP in whole blocks**, as the full-checkpoint loader `_load_weights_mxfp4` splits them. The streamed per-expert path narrowed by the padded per-rank size, so at TP > 1 with padding (gpt-oss 2880 at TP4: 736 rows per rank, padded to 768) a rank got the wrong checkpoint rows. Moved here from #64352.
- **gpt-oss no longer zeroes the caller's `w2_bias`.** On TP rank ≠ 0 the three loaders called `zero_()` on the incoming tensor, which under IPC weight transfer is the trainer's buffer. They now use `torch.zeros_like`.
- **FlashInfer bmm1/bmm2 scales follow reloaded KV scales.** They were computed once from host floats at the first forward and never refreshed, so a reload that changes `k_scale` / `v_scale` kept the old ones. They are now computed per forward from the same host floats, as the other host-float scales in this backend already are. No host sync is added.
- **KV-cache scales are recreated in the model dtype on layerwise reload**, as at model init, so an FP32 checkpoint scale is rounded the same way as on a fresh load.
- **Writes go through the parameter's loader** in colpali, colqwen3, colqwen3.5, nano_nemotron_vl, nemotron_parse, pixtral and voxtral.
- Small: the inverted kernel-format warning in `reload/inplace.py` and stale comment references in `reload/layerwise.py`.

## Details

**Root cause (loader bypass).** A layerwise reload restores each layer's parameters on meta and wraps their `weight_loader` to count and buffer loads. A write that bypasses the loader (`param.data.copy_`, `default_weight_loader(param, w)` on a parameter that has its own loader) lands on the meta placeholder and is dropped; the layer's old tensors are put back. Direct reload (`VLLM_RELOAD_MODE=direct`) writes in place and is not affected.

**FlashInfer.** The scales stay host floats, recomputed per forward. trtllm-gen also accepts device-tensor bmm scales, which would let FULL CUDA graph decode follow a reload; that is left for a follow-up (see Limitations).

**Changes from #61287:**
- Dropped the DeepSeek-V3.2 / MiMo-V2 FP8 pairing-state changes: #64717 removes those buffers.
- Dropped the online block-FP8 DeepGEMM cold-start fix: it no longer reproduces on main.
- The FlashInfer fix is a per-forward recompute in `forward` instead of device tensors with a `refresh()` hook.

**Limitations (all on main too):**
- FULL CUDA graph decode keeps the pre-reload bmm scales, and `_o_scale_float` (fused output quant) is computed once.
- The FlashInfer MLA backends (`flashinfer_mla.py`, `flashinfer_mla_sparse.py`) cache bmm scales the same way.
- Quark padded expert regions are not refilled on a layerwise reload; #64352 records the padding for these paths. When #64352 rebases on this PR it can drop its local `_copy_to_expert` helper in the Quark paths and keep the loader route here.
- Quark per-expert loading with EP, and nemotron_parse at TP > 1 (`sum_proj` output not gathered), were already broken and are unchanged.
- The VL model routing was audited, not reload-tested.

**Conflicts:** #64352 touches the same two Quark call sites in `gpt_oss.py` and the import block of `reload/layerwise.py`; both are small. No overlap with #64717 or #64690.
