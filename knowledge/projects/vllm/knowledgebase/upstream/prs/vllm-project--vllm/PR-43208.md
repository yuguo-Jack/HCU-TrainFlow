![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

When using `/bin/sh -c` to launch the vLLM server, the shell becomes PID 1 and does not forward signals to its children by default. This prevents vLLM from receiving the `SIGTERM` signal from Kubernetes, which is required to trigger the graceful drain shutdown. Using `exec` ensures the vLLM process replaces the shell and receives signals directly.

```suggestion
          "exec vllm serve mistralai/Mistral-7B-Instruct-v0.3 --shutdown-timeout 45"
```

It is recommended to have `terminationGracePeriodSeconds` be strictly greater than the sum of the `preStop` sleep and the `--shutdown-timeout`. This provides a buffer for signal propagation and final process cleanup (such as flushing logs or metrics) before Kubernetes sends a `SIGKILL`.

```suggestion
terminationGracePeriodSeconds > preStop sleep + --shutdown-timeout
```

<summary>References</summary>

1. Include a buffer in terminationGracePeriodSeconds to allow for cleanup after the shutdown timeout expires.
