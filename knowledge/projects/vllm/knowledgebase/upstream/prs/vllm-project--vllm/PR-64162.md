# [Rust Frontend] Explain how to get tokenizer.json for vocab/merges-only repos

[Upstream PR](https://github.com/vllm-project/vllm/pull/64162) · state: open · merged: False

## Original PR description

## Purpose

Part of #61057 (part 1; part 2 is #61128).

`Qwen/Qwen3-ASR-0.6B` and `Qwen/Qwen3-ASR-1.7B` ship `vocab.json`, `merges.txt` and `tokenizer_config.json`, but no `tokenizer.json`. The Python frontend builds a fast tokenizer from the slow files; the Rust frontend only accepts `tokenizer.json` / tiktoken / `tekken.json` and stopped with a generic "does not contain a supported tokenizer file" error that gave no way forward.

This is option (b) from my comment in the issue: when a source has `vocab.json` and `merges.txt` but no supported tokenizer file, the error now names them and explains how to generate a `tokenizer.json` and pass it with the recently added `--tokenizer` (#62416). The hint is added on all three paths that report a missing tokenizer:

- local model directory,
- Hub repo, checked against the repo file listing so nothing is downloaded,
- `HF_HUB_OFFLINE` with a cached snapshot (the path the issue hit).

Repos without those files keep the current message unchanged. Building the tokenizer from the slow files directly (option (a)) is a larger change; happy to follow up with it if maintainers want it.

Example, with the real Qwen3-ASR-1.7B tokenizer files in a local directory:

```
tokenizer error: local model directory '.../qwen3-asr-1.7b' does not contain a supported tokenizer file (tokenizer.json, tiktoken.model, or *.tiktoken). Found `vocab.json` and `merges.txt` but no `tokenizer.json`; generate one with transformers (`AutoTokenizer.from_pretrained(<model>).save_pretrained(<dir>)`) and pass `--tokenizer <dir>`
```

## Not a duplicate

Claimed in #61057. #61128 covers part 2 (`vocab_size` under `thinker_config`) and does not touch tokenizer file discovery. #63300 also edits `SourceFiles` in `model_files.rs` (completing partial cached snapshots when online). It's a different change, but the hunks are close, so whichever lands second will need a small rebase; happy to do it on my side.

## Test Plan

- New `slow_bpe_tokenizer_files_get_a_tokenizer_json_hint`: a local directory with only `vocab.json`, `merges.txt` and `config.json` reports the hint.
- `offline_resolution_uses_hub_cache_and_reports_cache_misses` gains a cached `test/slow` snapshot with the slow files and asserts the hint on the offline path. Both missing-tokenizer cases without the slow files assert that the message is unchanged.
- Following the hint works: with the real Qwen3-ASR-1.7B files as the model and a `save_pretrained` output as the `--tokenizer` source, `ResolvedModelFiles::from_sources` resolves the generated `tokenizer.json`.
