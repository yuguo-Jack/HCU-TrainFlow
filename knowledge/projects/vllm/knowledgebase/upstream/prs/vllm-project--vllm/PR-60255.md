# [Bugfix][NIXL] Apply DCP config checks to NixlPullConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/60255) · state: open · merged: False

## Original PR description

## Overview

Fixes #60189.

`NixlConnector` and `NixlPullConnector` are two names for the same connector, but configuration checks match connector names literally. Using the newer name skips the existing DCP checks and default-setting code.

For example, with DeepSeek-V2-Lite, TP=2, DCP=2, cache block size 16, and `--cp-kv-cache-interleave-size` unset:

```text
NixlConnector:     cp_kv_cache_interleave_size = 16
NixlPullConnector: cp_kv_cache_interleave_size = 1
```

The existing code sets this value to the cache block size for NIXL. Changing the connector name should not skip that adjustment.

## Claims

- Handle both names centrally in `KVTransferConfig.has_connector()`, including inside `MultiConnector`.
- Apply the existing DCP checks and default adjustment to both names.
- Preserve valid explicit interleave values, including 1, and reject invalid explicit values under both names. Only automatically resolved values skip the block-size check.
- Do not change the DCP implementation or add non-MLA DCP support. Other connector names still match exactly. Auxiliary-output errors use the canonical `NixlPullConnector` name for either pull alias.

## Validation

The refresh preserves #62330's interleave finalization from the global KV cache groups before profiling. Configuration tests use real KV cache group objects, and the unsupported non-MLA cases exercise the public `LLM` constructor before model weights are loaded. The obsolete HiSparse warning and its regression test are removed, following #64559; the current upstream HiSparse connector requirements and tests are retained.

Validated on main `0b5a44fe08c86883a71223ec2920865ca5c1a227` plus this fix, with `HF_HUB_CACHE` pointing to the existing model-configuration cache:

```bash
CUDA_VISIBLE_DEVICES='' VLLM_TARGET_DEVICE=cpu HF_HUB_OFFLINE=1 \
  HF_HUB_CACHE="$HF_HUB_CACHE" \
  PYTHONPATH=. OMP_NUM_THREADS=2 .venv/bin/python -m pytest -q \
  tests/test_config.py tests/config/test_aux_output_config.py \
  -k 'hisparse or nixl or pd_dcp_interleave or kv_offloading_does_not or empty_kv_cache_groups'
```

- All 72 selected tests pass, with no failures, errors, or skips.
- The alias and explicit-interleave regression subset has 10 assertion failures and 22 passes on unmodified main; all 32 cases pass with this fix.
- All 32 checks through `EngineArgs.create_engine_config()` pass, covering both names, direct/nested connectors, and valid/invalid settings. Invalid-value cases also call the public downstream block-size validator.
- All 16 applicable project pre-commit checks pass for the five PR files, including Ruff, Markdown lint, mypy, and test CI wiring. The unrelated Docker dependency-graph check was skipped.

These checks use cached model configurations. They do not load model weights or test GPU inference or distributed NIXL transfers.

## Details

Alias handling is centralized in the existing lookup method instead of repeating both names at each DCP check, as requested in review. Both pull names always resolve identically, with no optional exact-name mode. The auxiliary-output list uses only the canonical pull name.

`validate_block_size()` skips NIXL interleave validation only when the value will be automatically resolved. The flag already exists upstream and is also checked by the adjustment code. This intentionally tightens the legacy name's previous unconditional exemption: explicit 3 or 32 with block size 16 now fails under either name, while explicit 1 and 8 remain unchanged. The original variable name and comment are retained.

This picks up the explicit handoff from closed #60168. #60483 and #60484 add complementary peer-handshake checks for asymmetric DCP alignment and matching interleave sizes; they do not fix the local alias checks here. A connector-owned policy refactor is not included in this revision.

AI assistance was used to prepare the local fix and validation.
