# [ROCm][Perf] Muse Spark Open aiter MoE top-k with per-slot output

[Upstream PR](https://github.com/vllm-project/vllm/pull/63298) · state: open · merged: False

## Original PR description



## Overview

Depends on https://github.com/ROCm/aiter/pull/6861

Muse Spark's MoE normalizes each expert's output before the top-k weighted sum. On ROCm, however, aiter's fused_moe only returns the sum, and currently it's worked around by copying each token once per selected expert and running top-1 call on the `[T * top_k, H]` copy. With https://github.com/ROCm/aiter/pull/6861 adding `fused_moe(..., per_slot_output=buf)`, each expert's router-weighted output can be written into a `[T, top_k, H]` buffer, and skipping the top-k sum in the meantime. This PR adds the vLLM interface to adopt the aiter feature, calling the original `[T, top_k]` routing so that the input is quantized and sorted only once per token, and the rows arrive in the buffer the finalize reads.



## Claims

- Muse Spark Open (amd/Muse-Spark-Open-816B-A42B-Quark-MXFP4) on 8x MI355X, 8k in / 1k out, concurrency 8-64:
  - **TP8+EP8:** +5.0 % to +12.3 % total throughput, mean TTFT -15 %
  - **TP8:** +2.4 % to +7.9 % total throughput, mean TTFT -4 % to -10 %
- GSM8K is unchanged (TP8+EP8 0.9477 -> 0.9515; TP8 0.9431 -> 0.9477).

## Details



Muse Spark applies RMSNorm to the output of each selected expert before producing their weighted sum, so each selected expert's output has to reach finalize independently. As aiter's `fused_moe` returns the final top-k sum today, on the ROCm aiter path, vLLM currently copies the input tokens once per selected expert into `[T * top_k, H]`, and runs `fused_moe` with top-1 call with unit weights. At 8k tokens, the copy is 512 MiB per layer, and aiter sorts and quantizes `T * top_k` rows, which is `top_k` times the token count. Under EP, aiter's adds a masked route to each row, and the call essentially becomes top-2 over `T * top_k` rows. With the 8 experts of Muse Spark open, there are 16x duplicated quantization and sorting work.

With https://github.com/ROCm/aiter/pull/6861 exposing the intermediate `per_slot_output` to the `fused_moe` interface and skipping the internal top-k reduce when `per_slot_output` is provided, the token copying and the duplicated quantization and sorting work can be dropped. This PR interfaces with the added `per_slot_output` so that `fused_moe` can be called with the `[T, top_k]` routing.

Through micro-benchmarking, this path is found to out-perform the original expanded path across all settings tested under TP8+EP. In TP8, the original expanded path is found to be more performant at 16-tokens or below. Therefore, this path is set to be enabled when EP is on, and in TP with 128 rows or above.

One Muse Spark Open MoE layer's AITER call, MXFP4 weights, top-8 over 256 experts, CUDA-graph replay.
- TP8 shape: 256 experts, intermediate 512.
- EP8 shape: 32 local experts, intermediate 4096, AITER's `expert_mask`.
- "expanded": top-1 over the `[T * 8, H]` copy (copy not included).
- "per-slot": this PR's call.
