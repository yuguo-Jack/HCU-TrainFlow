# [MRv2][Bugfix] Initialize DCP metadata

[Upstream PR](https://github.com/vllm-project/vllm/pull/53603) · state: closed · merged: False

## Original PR description

## Purpose

`InputBatch.make_dummy()` sets `dcp_local_seq_lens=None`. With DCP enabled, dummy runs pass this value to attention metadata builders and crash.

This PR adds a helper that computes `dcp_local_seq_lens` into the persistent input buffer and assigns the padded view to the batch. It is called after batch finalization for normal and dummy execution, generic CUDA graph capture, and DFlash capture.

This replaces duplicated initialization in the existing call sites. Unlike #31166, it initializes the batch instead of repairing missing metadata in a consumer.

Fixes #30736.

- quanxu2 · comment · 2026-08-26T09:43:10Z · [source](https://github.com/vllm-project/vllm/pull/53603#issuecomment-5423482816)

Thanks for this fix — I hit the same bug independently and can confirm, plus one more trigger path and a minimal workaround in case it's useful.

**Repro** (DeepSeek-V2-Lite-Chat, 4xH20, vllm `9c8e90eb`, TP=4 / DCP=2):

```python
from vllm import LLM, SamplingParams
llm = LLM(model="DeepSeek-V2-Lite-Chat", tensor_parallel_size=4,
          decode_context_parallel_size=2, max_model_len=8192,
          gpu_memory_utilization=0.50, trust_remote_code=True)
llm.generate(["The capital of France is"], SamplingParams(max_tokens=32, temperature=0))
```

**Trigger path** (in addition to the FlashInfer-autotune dummy run in the PR description): the v0.21.0 *CUDA-graph memory-profiling* dummy run (enabled by default since v0.21.0) hits the same crash, via `compile_or_warm_up_model -> _dummy_run -> execute_model(dummy_run=True)`:

```
... -> model_states.default.prepare_attn -> attn_utils.build_attn_metadata
 -> mla_attention.py:2409  seq_lens_device=seq_lens[:num_decodes]
 TypeError: 'NoneType' object is not subscriptable
```

**Root cause** (matches the PR): `execute_model` only prepares DCP metadata on the real path — `if not dummy_run: input_batch = self.prepare_inputs(...)` ([model_runner.py:1540](https://github.com/vllm-project/vllm/blob/9c8e90eb2637a863ca14e47fd436b10ed7ba6536/vllm/v1/worker/gpu/model_runner.py#L1540)), and the DCP prep lives inside `prepare_inputs` via `prepare_dcp_local_seq_lens(...)` ([model_runner.py:1238-1249](https://github.com/vllm-project/vllm/blob/9c8e90eb2637a863ca14e47fd436b10ed7ba6536/vllm/v1/worker/gpu/model_runner.py#L1238-L1249)). The dummy branch builds `input_batch` via `InputBatch.make_dummy` ([model_runner.py:1567-1575](https://github.com/vllm-project/vllm/blob/9c8e90eb2637a863ca14e47fd436b10ed7ba6536/vllm/v1/worker/gpu/model_runner.py#L1567-L1575)), which sets `seq_lens` but leaves `dcp_local_seq_lens=None`. With `dcp_world_size>1`, `MLAAttentionMetadataBuilder.build` reassigns `seq_lens = dcp_local_seq_lens` ([mla_attention.py:2395](https://github.com/vllm-project/vllm/blob/9c8e90eb2637a863ca14e47fd436b10ed7ba6536/vllm/model_executor/layers/attention/mla_attention.py#L2395)) and then `seq_lens[:num_decodes]` ([mla_attention.py:2409](https://github.com/vllm-project/vllm/blob/9c8e90eb2637a863ca14e47fd436b10ed7ba6536/vllm/model_executor/layers/attention/mla_attention.py#L2409)) crashes.

**Reference workaround** (minimal, validated end-to-end with a `vllm serve` + completion): mirror the real path's `prepare_dcp_local_seq_lens` in the dummy branch right after `make_dummy`:

```python
input_batch = InputBatch.make_dummy(...)            # existing
if self.use_dcp:
    prepare_dcp_local_seq_lens(
        self.input_buffers.dcp_local_seq_lens,
        self.input_buffers.seq_lens,
        dummy_num_reqs,
        self.dcp_size, self.dcp_rank, self.cp_interleave,
    )
    input_batch.dcp_local_seq_lens = (
        self.input_buffers.dcp_local_seq_lens[:dummy_num_reqs]
    )
```

Just sharing as a smaller-surface alternative; happy to adapt to whatever shape the maintainers prefer.
