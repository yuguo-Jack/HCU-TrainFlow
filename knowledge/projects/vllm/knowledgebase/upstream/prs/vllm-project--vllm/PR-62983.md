# [ROCm] Revert "[ROCm][Build] Compile paged attention kernels in parallel (7.6x faster attention build) (#62475)"

[Upstream PR](https://github.com/vllm-project/vllm/pull/62983) · state: closed · merged: True

## Original PR description



## Overview

Reverts #62475 to unblock the ROCm 10.0 nightly while we pick a proper fix.

## Claims

- Fixes the `Build release image - x86_64 - ROCm 10.0` nightly failure: the `_rocm_C.abi3.so` link fails with `mold: relocation R_X86_64_PC32 against .eh_frame out of range`.

## Validation

Built and linked the full `_rocm_C` with this revert in the ROCm 10.0 CI build image (same compiler, mold, 9 release archs, `RelWithDebInfo`): link succeeds.

## Details

**Root cause:** `_rocm_C`'s embedded GPU code (`.hip_fatbin`) was already ~1.94 GiB, ~80% of it uncompressed GPU debug info. Splitting attention into 12 files duplicates that debug info per file and pushed the library past the 2 GiB relocation limit. This revert only gets us back under it, with ~64 MB of headroom.

**Alternatives** (each lets us reland #62475). Measured on one attention file, 9 archs:

| Option | GPU code size | Pros | Cons |
|---|---|---|---|
| Today | 137 MiB | | |
| `-Xarch_device -g0` | 36 MiB (−74%) | Simple; ~20% faster compile | No GPU debug info (no kernel source debugging, no source lines for GPU faults) |
| `--offload-compress` | 4.9 MiB (−96%) | Keeps full debug info; output unchanged after decompression; smaller wheel | Decompression at module load (not yet measured on GPU); needs ROCm ≥ 6.2 |

Either option is a one-line CMake change. Both make every HIP object miss sccache once, so the next nightly after either lands is a cold build.
