# [ROCm][Perf][DSv4.1] Balance the FP8 paged decode indexer across rows

[Upstream PR](https://github.com/vllm-project/vllm/pull/64917) · state: open · merged: False

## Original PR description



## Claims

- Decode rows up to 4096 share KV tiles on a persistent grid (`num_sms * 8`) instead of each row getting the same CTA count.
- Scores on valid positions match the existing per-row kernel bit for bit, so top-k is unchanged.
- The launch grid does not depend on sequence lengths, so it stays CUDA-graph safe.
- Default on. Set `VLLM_ROCM_DSV41_BALANCED_DECODE_INDEXER=0` to keep the per-row grid.

## Validation

Kernel check on MI355X (gfx950), inside `vllm/vllm-openai-rocm:nightly`, 8 rows with lengths `[64, 128, 256, 512, 1024, 63, 1, 4000]`:

- `test_fp8_paged_mqa_logits_balanced_matches_per_row` passed with `atol=0`, `rtol=0` on valid positions.
- The existing torch-reference test for this kernel also passed with the balanced path mounted.

The new test is skipped off gfx942/gfx950, so NVIDIA CI will not execute it.

## Details

The per-row grid is `(rows, N_SPLITS)` with the same split count for every row. A long row then occupies its CTAs for the whole step while short rows finish. The balanced kernel assigns each program an equal contiguous share of all rows' KV tiles via a prefix sum. Tile math is the same fp8 dot, relu, head weight, and per-position scale. Batches above 4096 rows stay on the per-row grid. AITER `deepgemm` for compress ratios 1 and 2 is unchanged.
