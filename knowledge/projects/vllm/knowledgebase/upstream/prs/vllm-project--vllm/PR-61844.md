## Original PR description



## Overview

This PR is to revert the changes in https://github.com/vllm-project/vllm/pull/58173, and to add a check to make sure this doesn't happen again. I believe what happened was that a local old version of QuTLASS, before it was migrated to the stable ABI, was being built against the new flags that help ensure QuTLASS stays stable. So I also added a check in here to make sure that a version of QuTLASS after this update is being used. This checks for the file `qutlass/csrc/include/registration.h` which was only added after the migration.

- cleonard530 · comment · 2026-10-16T13:19:51Z · [source](https://github.com/vllm-project/vllm/pull/61844#issuecomment-6216394755)

@yewentao256, as @ZJY0516 and @Harry-Chen mentioned, this can allow users to use their own pytorch version and help enforce ABI stability.

For some additional context, with the current setup, QuTLASS could use symbols that are allowed under whatever version it's built with (in this case 2.13). So vLLM now has a minimum torch version of 2.13, when it could have as low as 2.11 (see new image of torch-abi-audit in description). Migrating vLLM to the stable ABI allows us to build against one PyTorch version and run against any version at or above TORCH_TARGET_VERSION, without rebuilding. However, because of this single dependency, we're unnecessarily excluding two PyTorch versions that vLLM could otherwise support. This could be inconvenient for developers who want to use older PyTorch versions without rebuilding, as well as distributors who want to package wheels for multiple PyTorch versions without maintaining a separate build for each one.

And as @Harry-Chen mentioned, this flag help us enforce that QuTLASS does not bring in any unstable symbols (the bug that caused the original PR was really a feature!). There is a CI check as well to make sure this doesn't happen, but this is an extra safeguard in case that CI check fails.    

I am not surprised that this has not caused bugs, as it's a very particular use case, and a developer probably would've just updated python if they ran into this, but I still think it's worth adding it back for the reasons described above. 

Let me know what you think or if you have any questions!
