# [Perf] Read VLLM_COMPUTE_NANS_IN_LOGITS once per IterationStats

[Upstream PR](https://github.com/vllm-project/vllm/pull/61710) · state: closed · merged: True

## Original PR description

## Overview

`IterationStats.update_from_output` read `envs.VLLM_COMPUTE_NANS_IN_LOGITS` once per request output per step. This reads it once per `IterationStats` instead.

## Claims

- Removes one `envs` module `__getattr__` and two `os.getenv` calls per request output per step from the API-server output-processing loop. Measured on the installed vLLM (CPU, aarch64): `IterationStats.update_from_output` goes from 4.1 µs to 1.6 µs per output with the envs cache off, which is the API server's state today.
- No behaviour change: the flag is read at the start of each iteration instead of for each output within it.

## Validation

- py-spy GIL profile of a `vllm serve`-based worker streaming a few thousand concurrent requests: `update_from_output` → `envs.__getattr__` → the `VLLM_COMPUTE_NANS_IN_LOGITS` lambda accounted for a little over 1% of all GIL-held samples in the API-server process. With the read hoisted that frame disappears.
- `pre-commit run --files vllm/v1/metrics/stats.py` passes.

## Details

`enable_envs_cache()` is only called in the multiprocess executor, so processes that run `OutputProcessor` (the API server, or any `AsyncLLM` host) always take the uncached path. The flag cannot change between outputs of one step in any meaningful way, so reading it per `IterationStats` keeps the semantics while taking it off the per-output path.
