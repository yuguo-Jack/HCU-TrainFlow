# [Core] Pack execute_model SchedulerOutput for multiproc RPC

[Upstream PR](https://github.com/vllm-project/vllm/pull/54406) · state: open · merged: False

## Original PR description

On TP>1, MultiprocExecutor broadcasts `execute_model(SchedulerOutput)` to every worker on each scheduling step. The default `collective_rpc` path pickles the full dataclass object graph, which carries per-field metadata and nested object overhead on this hot path. This PR uses a fixed positional tuple wire format with `array('i')` for int lists so pickle/unpickle operates on a flat schema instead of serializing the dataclass object graph.

## Purpose

When `tensor_parallel_size > 1`, `execute_model(SchedulerOutput)` is broadcast to every TP worker on every scheduling step. The generic RPC path pickles the full `SchedulerOutput` dataclass graph through MessageQueue, which adds noticeable Python serialize/deserialize overhead on large scheduler payloads (e.g. steady-state decode with many concurrent requests).

This PR:

- Packs `SchedulerOutput` into a fixed tuple schema before enqueue
- Converts large int lists to `array('i')` for faster pickle/unpickle
- Sends a 3-tuple `(EXECUTE_MODEL_FAST_PATH_TAG, packed_payload, output_rank)` for `execute_model` instead of the generic 4-tuple RPC message
- Leaves all other RPCs on the existing generic 4-tuple pickle path

## Scope / non-goals

- Only applies to `method == "execute_model"` with a single `SchedulerOutput` argument and no kwargs
- Does not change model semantics, scheduling logic, or CUDA/ROCm kernels
- Does not replace generic RPC pickle; complements tensor-oriented MQ optimizations such as [Perf] Zero-copy torch.Tensor pickling in shm_broadcast MessageQueue #48442
