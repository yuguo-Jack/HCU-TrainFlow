## Original PR description

## Overview

Stacks on #56957 to support PP + DSpark for NVIDIA DeepSeek-V4.1-Flash in colocated serving. Addresses #63157.

## Claims

- Enable DeepSeek-V4.1-Flash PP + fixed-length DSpark with the PP2 `14,26` target-layer split.
- Retain the last-stage target embedding, relay auxiliary hidden states in layer order, and cover deferred PP draft updates with a regression test.

## Details

This PR stacks on #56957. Our changes retain the target embedding on the last PP stage, relay V4.1 auxiliary hidden states in layer order, and guard the stage-entry replay boundary. Deferred PP draft writes use the existing masked update kernel, with a regression covering freed request slots. Existing restrictions on PP cuts through compressed-KV sharing groups and PCP combinations remain in place. The default 20/20 split is not covered by the support claim: it encounters an existing empty-group packed-KV allocator defect whose fix is included in #63106. Use `VLLM_PP_LAYER_PARTITION=14,26` to avoid that defect without duplicating the common-code fix or adding arbitrary-partition cache relay. The 20/20 last-stage replay boundary is also gated off to avoid an empty prefix and invalid deferred mHC state; SWA prefix-cache replay is retained.

Local checks: 64 focused CPU tests passed; CUDA-dependent cases were skipped. Relevant `pre-commit` checks (including mypy and CI tethering) and `git diff --check` passed. GPU serving, model quality and performance validation remain TODO.

AI assistance (OpenAI Codex) was used for implementation. GPT-6-Astra with xhigh reasoning reviewed the V4.1 adaptation and found no remaining implementation blocker for the NVIDIA PP2 `14,26` plus fixed-length DSpark scope; GPU validation remains TODO.

- qinqinwo · comment · 2026-11-04T03:51:01Z · [source](https://github.com/vllm-project/vllm/pull/63321#issuecomment-6622049083)

We hit the same gap and independently wrote the same model-side change for `DeepseekV4Model` (`supports_aux_hidden_states_over_pp`, the last-stage `embed_tokens` via `spec_decode_needs_target_embed`, and packing / collecting the aux hidden states across stages), so here is a data point in case it helps review.

**Setup:** DeepSeek-V4.1-Flash, TP4 × PP2 + DSpark, `--load-format instanttensor`, 8 × RTX 6000D, on a downstream build carrying this change plus the PP fixes that have since landed on main (`requires_raw_input_tokens`, per-stage KV cache groups).

**Results:**
- Server starts and serves with DSpark across the PP boundary.
- Mean DSpark acceptance length 3.20, in line with the non-PP baselines we measured on the same machine (TP8 3.04, TP4 3.05).
- 32K-token single-request TTFT 1.82 s; needle-in-a-haystack 4/4.

One more thing we needed with `--load-format instanttensor`: the draft model is only instantiated on the last PP stage, but InstantTensor plans I/O with an `all_reduce` over the world group, so draft loading deadlocks. That is independent of this PR; the fix is in #65572.
