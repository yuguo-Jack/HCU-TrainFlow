# [Bugfix][Parser] Forward skipped tool spans verbatim in the reasoning pass

[Upstream PR](https://github.com/vllm-project/vllm/pull/61217) · state: open · merged: False

## Original PR description



## Overview

Fixes the first problem reported in #61206: with an engine-based Qwen3 reasoning parser, the reasoning-only pass (`skip_tool_parsing=True`) removes a literal `</think>` quoted inside a tool parameter value before the tool pass sees the span, so `alpha <think>literal</think> omega` reaches the client as `alpha <think>literal omega`.

## Claims

- In the reasoning-only pass, a skipped tool span is now forwarded to the tool pass verbatim: non-tool terminals inside it emit their text instead of applying their reasoning-channel transitions.
- Qwen3's duplicate-`</think>` absorb in CONTENT still applies outside the span; only in-span handling changes.
- No change to normal (non-skip) parsing, streaming deltas, or generation.

## Validation

Reproducer from #61206 adapted to current main, run through the same chain the serving layer uses (reasoning pass with `skip_tool_parsing=True`, then the tool pass on the forwarded content):

```
pytest tests/parser/engine/test_engine.py::TestSkipToolParsingMarkerPassthrough \
  "tests/parser/engine/test_qwen3.py::TestNonStreaming::test_think_marker_quoted_in_parameter_survives_reasoning_pass"
```

- The 3 added tests fail on main (forwarded span loses the marker) and pass with this change.
- `pytest tests/parser/engine/`: 5866 passed. `pytest tests/parser/` (excluding `tests/parser/cohere`, which needs the optional `cohere_melody` package, not installed here): 6339 passed. `pytest tests/reasoning/`: 482 passed. `pytest tests/tool_parsers/`: 1196 passed, 15 errors that are HF gated-repo 401s fetching llama tokenizer fixtures, unrelated to this change.
- Parser-level validation only: this machine has no GPU, so no served-model run. The gate sits in the skip pass and cannot affect sampling or kernels; generated text is unchanged, only the forwarding of already-generated text is repaired.

## Details

Root cause: in `StreamingParserEngine._on_terminal`, the `skip_tool_parsing` gate intercepts tool terminals and tracks `_in_skipped_tool_span`, but any other terminal with a transition reachable from CONTENT still went through `_apply_transition` inside the span. For qwen3 that is `(CONTENT, THINK_END) -> (CONTENT, ())`, the rule that absorbs a duplicate `</think>`. Models do quote `</think>` as ordinary text inside string arguments, and the absorb deleted it from the text handed to the tool pass.

Fix: while `_in_skipped_tool_span` is set and the terminal is not one of the config's tool terminals, emit the value for the current state instead of applying the transition. Tool terminals keep their existing span-tracking path, so openers and the exit that clears the span behave exactly as before. The change lives in the engine rather than `qwen3.py` because the skip pass promises verbatim forwarding for every declarative config; qwen3's absorb rule is simply where it bites today.

Relation to nearby open PRs (checked before opening):

- #60256 keeps a text-spelled marker as content in non-streaming parse when it arrives as ordinary tokens; it does not cover a marker token inside a skipped tool span.
- #56661 defers a quoted `<tool_call>` opener in prose; this is the opposite direction, a marker inside an already-open span.
- #58407 balances `</parameter>` closers inside values within the tool parser; this fix is in the reasoning pass that runs before it.

The second problem in #61206 (finish_reason) already has #58286; the third (out-of-order tool results against an ID-less template) is a separate design question, left out of this PR.
