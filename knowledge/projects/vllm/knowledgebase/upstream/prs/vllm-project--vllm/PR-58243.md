# [Bugfix][MRV2] Reserve encoder graph memory without decoder graphs

[Upstream PR](https://github.com/vllm-project/vllm/pull/58243) · state: open · merged: False

## Original PR description

## Overview

Reserve encoder CUDA graph memory during MRV2 automatic KV-cache sizing even when decoder graph mode is `NONE`. This fixes a profiling eligibility omission, not a reproduced OOM or throughput bottleneck.

While following up on [MRV2 feedback on my earlier PR](https://github.com/vllm-project/vllm/pull/54905#issuecomment-5769718464), I found a case similar to #41714 in a different runner/configuration.

## Claims

- Admit MRV2 encoder graph profiling when decoder graphs are disabled, excluding eager execution. Reuse `needs_cudagraph_capture()` in the V2 profiler instead of decoder-only eligibility checks.
- Preserve MRV1 behavior, graph-reservation opt-out semantics and existing estimation/teardown logic. No kernels, capture sizes, batch caps or pool-sharing changes.
- Reduce the reviewed diff from 150 to **62 changed lines including tests (+51/-11)** across three files. Regression coverage extends the existing profiler helper/parameterization, including pre-bootstrap initialization and cleanup on encoder capture failure.

## Details

The Worker previously gated graph memory profiling on decoder mode alone. The V2 profiler also returned early for decoder NONE or no decoder capture descriptors, even though the encoder can capture independently. This left encoder graph memory out of automatic KV-cache sizing. The fix widens eligibility without changing the memory estimator. The pre-bootstrap configuration guard remains because the decoder manager can still be uninitialized.

This is regular multimodal generation, not the separate `--mm-encoder-only` deployment mode. Reserving previously omitted graph memory can reduce the automatically selected KV-cache capacity; that is the intended accounting correction.

### Related Work / Duplicate Check

The original duplicate check covered #49224 and its comments, open issue references, and encoder graph memory/MRV2 profiling PRs. Open issue references and area searches were refreshed before this update.

- #53306 introduced the MRV2 profiler and closed #49224. This PR addresses a remaining eligibility case, not the original issue in full.
- #57865 concerns retained-workspace/released-graph accounting; #51590 concerns MRV1 capture-footprint measurement. Their accounting-policy changes remain out of scope here.
- #54061 concerns capture tracing; #56922 concerns the separate encoder-only runner.
- Merged #58430 prevents allocator fragmentation during ordinary profiling from shrinking the KV budget. This change instead fixes omitted encoder graph memory when decoder graphs are disabled. They are complementary, despite shared files.
