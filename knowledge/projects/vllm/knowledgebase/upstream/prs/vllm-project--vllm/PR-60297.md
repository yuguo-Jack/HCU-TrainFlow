# [CI] Log host memory usage during image build bake

[Upstream PR](https://github.com/vllm-project/vllm/pull/60297) · state: closed · merged: False

## Original PR description

## Purpose

The CPU image builders run on r6in.16xlarge (512 GiB RAM). We want to downsize the instance tier, but there is no memory telemetry on these builders today (no CloudWatch agent, no node exporter), so the required memory is guesswork.

This adds a tiny sampler around the `buildx bake` in `image_build.sh`: every 5s it prints host memory used (MemTotal - MemAvailable, from /proc/meminfo) to the job log. The peak line in any build's log then tells us the real memory ceiling of an image build, per instance type.

Not duplicating existing work: searched open PRs for "memory image build" and "image_build.sh" — nothing covers build-time host memory logging.

## Notes

- The sampler is killed explicitly after the bake rather than via an EXIT trap, because the script already sets an EXIT trap for BUILD_TMP_DIR cleanup and bash keeps only one.
- Output goes to stderr (the Buildkite job log), a few hundred lines on a typical build.
- Draft: opened to measure a real build on the current instance type. Can be merged as permanent telemetry or dropped after we have the number — either is fine.

## Testing

- `bash -n .buildkite/image_build/image_build.sh` passes.
- No unit tests (shell CI glue); verification is the premerge `:docker: Build image` step itself — its log should contain "Host memory used: ... GiB" lines every 5s during the bake.
