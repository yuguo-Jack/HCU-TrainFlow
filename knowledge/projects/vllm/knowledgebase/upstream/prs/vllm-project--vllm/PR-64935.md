# [Bugfix][Frontend] Report reasoning tokens in batched chat completions

[Upstream PR](https://github.com/vllm-project/vllm/pull/64935) · state: closed · merged: True

## Original PR description



## Overview

`/v1/chat/completions/batch` never sets `usage.completion_tokens_details`, so a server started with `--reasoning-parser` omits `reasoning_tokens` from batched responses while `/v1/chat/completions` reports them for the same conversation. This counts and sums them per conversation, the way the single-conversation path does. Follows #64757, which added the prompt-side `prompt_tokens_details` to the same endpoint.

## Claims

- With `--reasoning-parser`, `/v1/chat/completions/batch` returns `usage.completion_tokens_details.reasoning_tokens` summed across conversations, including when `include_reasoning=false` (hidden reasoning is still generated and billed), matching `/v1/chat/completions`.
- Without a reasoning parser, `completion_tokens_details` stays `null`, as on `/v1/chat/completions`.

## Details

- Root cause: `chat_completion_full_generator_batch` builds `UsageInfo` without `completion_tokens_details`, and never counts reasoning tokens even though each conversation already runs through its parser.
- The fix mirrors `OpenAIServingChat.chat_completion_full_generator`: call `parser.count_reasoning_tokens(output.token_ids)` after `parse`, and gate the details on `_include_reasoning_tokens_details`. It reuses `_make_completion_tokens_details`.
- Three existing unit tests build `OpenAIServingChatBatch` with `__new__`, so they now set `_include_reasoning_tokens_details = False` (as #64757 did for `enable_prompt_tokens_details`), and the fake parser gains `count_reasoning_tokens`.
- The Rust frontend serves `/v1/chat/completions/batch` as `not_supported`, so the new test is skipped when `VLLM_USE_RUST_FRONTEND` is set, as the Rust frontend CI steps do (same pattern as `test_thinking_token_budget.py`). The Python-frontend steps run it.
- Docs: one sentence next to the `prompt_tokens_details` note for this endpoint in `openai_compatible_server.md`.

Not a duplicate: open and closed PRs and issues searched for "batch reasoning tokens", "completions/batch usage", "batched chat completions usage", "reasoning_tokens", `OpenAIServingChatBatch` and `batch_serving`. Related but different: #64757 (merged, prompt-side details only), #64041 (reasoning tokens on the derender endpoints), #58010 (hiding reasoning metadata in batch responses).
