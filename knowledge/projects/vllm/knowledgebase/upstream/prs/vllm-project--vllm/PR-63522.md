# [ROCm][MoE] Align the AITER Triton MXFP4 W4A16 intermediate size to 128 on gfx942 (Krai Ltd.)

[Upstream PR](https://github.com/vllm-project/vllm/pull/63522) · state: open · merged: False

## Original PR description

Contributed by **Krai Ltd.** (hasith@krai.ai) as part of its MLPerf Endpoints v1.0 DeepSeek-V4.1-Flash submission on 8x AMD Instinct MI300X; this commit is one of the patches disclosed in that submission.

mxfp4_round_up_hidden_size_and_intermediate_size pads the per-partition
intermediate size of the AITER_TRITON_MXFP4_BF16 backend to a multiple of 256
through the generic ROCm arm. That alignment is not something the kernel
asks for: aiter's Triton moe_gemm_a16w4 masks K tails (EVEN_K /
MASK_K_LIMIT) and N tails (wrapped loads, masked stores) itself, so its only
hard alignment is the 32-wide e8m0 scale block, and both tail paths are
already exercised in production by gpt-oss on gfx942 (2880 -> 2944 per
partition at TP1). The padded columns are zero weights with zero scales and
contribute nothing to either GEMM.

The over-padding is expensive for narrow shards: DeepSeek-V4.1-Flash
(moe_intermediate 2304) at TP4 is 576 -> 768 (+33 % expert weight bytes
streamed per rank) and at TP8 288 -> 512 (+78 %). With a 128 alignment the
same shards become 640 (+11 %) and 384 (+33 %), i.e. 17 % and 25 % fewer
weight bytes per rank for a decode phase that is bound on expert weight
streaming. The hidden size follows the intermediate alignment, exactly as
the CK W4A16 SiTU/SILU carve-out does.

Scope is deliberately narrow, mirroring that carve-out: only the W4A16
Triton backend, only SiTU/SILU (gpt-oss' SwigluOAI shapes stay as validated),
and only gfx942. gfx950 keeps 256 because its CDNA4 scale swizzle requires
BLOCK_K % 256 == 0.

Move the backend's row out of the hardware-dependent round-up table into a
test that mocks the CDNA generation, so both arms are pinned on every ROCm
host.

Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>

## Test
`pytest tests/kernels/moe/test_ocp_mx_moe.py -k round_up` pins both arms (gfx942 -> 128, gfx950 -> 256) with the CDNA generation mocked, so the rule is checked on every ROCm host. End to end on MI300X (vLLM 0.31.1rc1, 2x TP4, agentic decode workload): 17 % (TP4) / 25 % (TP8) fewer expert-weight bytes streamed per rank; numerics unchanged (the padded columns are zero weights with zero scales).
