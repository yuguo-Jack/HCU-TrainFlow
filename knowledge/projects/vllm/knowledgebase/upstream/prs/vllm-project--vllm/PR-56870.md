# [CI] Split (H200 MIG 35GB / MI355) Quantized Models into GPTQ Marlin, AWQ and Other Schemes jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/56870) · state: closed · merged: False

## Original PR description

## What

Split `quantized-models-test` into three named jobs: GPTQ Marlin, AWQ, and Other Schemes. Each runs whole test files in a single pytest process, replacing the earlier five-way hash shard. One-file edit to `.buildkite/test_areas/quantization.yaml`; no test bodies, parameters or markers change.

## Old

```text
(H200 MIG 35GB) Quantized Models   [quantized-models-test]
└── pytest models/quantization                         (one job, ~42–60m on recent main)
    mirror: (MI355) Quantized Models, same command
```

## New

| Buildkite job | key | whole coverage units | mirror |
|---|---|---|---|
| `(H200 MIG 35GB) Quantized Models / GPTQ Marlin` | `quantized-models-gptq-marlin` | `test_gptq_marlin.py` | none: every case skips on ROCm |
| `(H200 MIG 35GB) Quantized Models / AWQ` | `quantized-models-awq` | `test_awq.py` | `amd-quantized-models-awq`, same file |
| `(H200 MIG 35GB) Quantized Models / Other Schemes` | `quantized-models-other` | `test_fp8.py`, `test_fp8_per_channel.py`, `test_gpt_oss.py`, `test_mimo_v2_qkv_shard.py`, `test_modelopt.py`, `test_mxfp4.py`, `test_mxfp8.py`, `test_nvfp4.py`, `test_per_token_kv_cache.py` | `amd-quantized-models-other`, same files |

`quantized-models-test` is retired; its coverage is exactly the union of the three new jobs on the primary lane.

## Notes

- **Why named jobs instead of the hash shard:** those two files are the two largest units in the directory. The five-way shard also ran about 13 extra worker-minutes, because each replica repeated model loading and compilation that one process shares across cases. Keeping each file group in one process removes that duplication; only the per-job checkout and container start is added.
- **GPTQ Marlin stays one job and is at the 20-minute target, not under it.** The file measured 16–24 minutes whole across four recent `main` runs, at or above 20 in three of them, and a flat file cannot be divided without splitting it. The cost is in the test itself: each of its six cases starts two engines over 1–2B models, and `flaky(reruns=3)` can repeat a case. That is being raised with its owners separately.
- **Mirror-lane coverage:** the two mirror jobs claim every file except `test_gptq_marlin.py`, so the mirror no longer collects that file's six skip-only cases. Nothing that ran before stops running.
- Earlier validation comments describe the superseded five-way shard. AI assistance was used.
