# [Perf][Attention] Avoid unused host-length sync for non-causal XQA decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/58953) · state: open · merged: False

## Original PR description

## Purpose

Related to #54919; **this is not a complete fix for the mixed-prefill starvation report**.

`all_uses_trtllm` deliberately requires causal attention. Consequently an all-XQA, non-causal decode batch can still retrieve `seq_lens_cpu`, even though its attention implementation consumes the exact GPU lengths and neither native paged attention nor cascade/DCP needs that host tensor.

This change gates the host-length retrieval on its actual consumers:

- DCP and cascade still require exact host lengths.
- Native prefill and native decode still require exact host lengths.
- Pure XQA decode, including non-causal decode, does not retrieve an unused host copy.

There is **no substitution of speculative CPU upper bounds for exact GPU lengths**, no modification to sequence-length state, and no change to the attention kernel.

## Tests

Adds a real CUDA regression with head dimensions 128/256, causal/non-causal attention, decode/speculative-width queries/mixed prefill, explicit optimistic CPU upper bounds, and a FP32 paged-attention oracle. A `TorchDispatchMode` audit counts actual GPU-to-CPU copies of the sequence-length tensor.

Unused KV padding is filled with a large sentinel. A negative control deliberately supplies the optimistic lengths and must produce a visibly incorrect result, so matching the reference is not an insensitive all-zero-padding test.

```bash
pytest tests/v1/attention/test_flashinfer_host_seq_lens.py -v -rA
```

### Executed validation and exact scope

- RTX 5090 / SM120, PyTorch 2.13.0+cu130, Triton 3.7.1, FlashInfer 0.6.18.
- Standalone actual CUDA comparison: **20/20 cases passed**, including **6 cases where the exact-length D2H copy count changed from 1 to 0**. Baseline/candidate CUDA outputs were bitwise identical and matched the FP32 oracle. Native mixed-prefill controls retained their host copies.
- Actual CUDA graph replay after changing both GPU sequence lengths and Q passed for both head dimensions.
- Public pytest fixture: **12 passed, 0 skipped**. The hardened sentinel/incorrect-length negative-control version also passed **12/12** (Slurm job 1632831, exit 0; 213.52 seconds).
- Ruff 0.14.0 and `git diff --check` pass.

**Important environment limitation:** the GPU validation used the equivalent predicate change on the installed vLLM 0.29.0 stack. That stack exposes `use_dedicated_xqa`, whereas current main uses `use_xqa`; the test handles both. Both comparison arms also used the same explicit, local source prerequisite permitting SM120's locally JIT-compiled XQA when the artifactory availability probe failed. It did not replace or mock the CUDA implementation. This prerequisite is **not** included in this PR. The committed production patch is based on current main `3184226984b17fe0dba960ace5a2d7d57df44ab6`; a complete current-main build/CI run remains outstanding, hence draft status.

## Performance scope

The standalone trace verifies removal of the blocking copy. Builder host latency was measured both idle and with real queued GEMMs; these are **metadata-builder measurements, not serving-throughput improvements**. No end-to-end percentage improvement is claimed here. A full-model MTP/mixed-prefill comparison is being validated separately, and its result must not be inferred from these kernel/metadata tests.

## Attribution

AI-assisted implementation, source review and execution on the contributor's authorized GPUs. No claim of maintainer approval or completed upstream CI. The manual-tile initialization work in #56863 is unrelated and is not duplicated here.
