# [Bugfix][Frontend] Default VLLM_USE_LAYERNAME off on torch 2.11.x

[Upstream PR](https://github.com/vllm-project/vllm/pull/63862) · state: open · merged: False

## Original PR description

## Overview

Fixes #63662

MoE models crash at startup on torch 2.11.0 with vLLM's default `VLLM_USE_LAYERNAME=1`: Inductor's `graph.count_bytes()` hits an assert at `ir.py:9580` (`__obj_flatten__` on a hoisted `LayerName`) because torch 2.11.x `_inductor/ir.py` calls `is_opaque_type` with an **instance** where a **type** is expected (pytorch#173863). That upstream fix was closed without merging, so no shipped torch has it; torch 2.12 switched the call site to `is_opaque_value`.

## Claims

- The default of `VLLM_USE_LAYERNAME` becomes torch-version-gated, following the existing `VLLM_USE_AOT_COMPILE` pattern (`use_aot_compile`):
  - torch `>= 2.12.0.dev` → default **on** (upstream fixed via `is_opaque_value`)
  - `2.11.0 <= torch < 2.12.0.dev` → default **off** (the crashing configuration)
  - torch `< 2.11` → default **on** (unchanged; `LayerName` is not consumed there)
- An explicit `VLLM_USE_LAYERNAME=1` still wins on every version — only the default moves out of the crashing configuration.
- No behavior change for any torch version when the user sets the env explicitly.

## Validation

Maintainer-reproduced CPU-only in the issue (adenzhou1350):

| Environment | Result |
|---|---|
| torch 2.11.0+cpu, default diagnostics | opaque compile contract fails |
| torch 2.11.0+cpu, `LOG_TLPARSE=1` | reaches `ir.py:9580` assert in `graph.count_bytes()` |
| torch 2.11 + in-process `is_opaque_type(type(obj))` repair | all cases pass |

New unit test (`tests/test_envs.py::test_vllm_use_layername_gated_on_torch_2_11`), CPU-only, no GPU/model weights:

- torch 2.11.x → `envs.VLLM_USE_LAYERNAME is False`
- torch >= 2.12 → `True`
- torch < 2.11 → `True`
- explicit `VLLM_USE_LAYERNAME=1` on 2.11.x → `True` (user override wins)

## Details

Root cause is double-ended: torch 2.11.x ships the `is_opaque_type` misuse, while vLLM's `envs.py` enables `LayerName` by default for all `torch >= 2.11`. The minimal vLLM-side mitigation is to gate the default the same way `VLLM_USE_AOT_COMPILE` already gates on torch version (`use_aot_compile`), keeping the opt-in path intact for patched/fixed torch builds. The inductor fix itself belongs upstream (pytorch#173863).
