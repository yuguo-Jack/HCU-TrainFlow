# [Bugfix][MRV2][Spec Decode] Sync standalone draft token counts across DP ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/61827) · state: open · merged: False

## Original PR description



## Overview

MRV2 `draft_model` (`StandaloneARSpeculator`) with a MoE target and DP > 1 crashes at startup: the drafter passes the target's `num_tokens_across_dp` to its own forwards, which run a different number of tokens, and `DPMetadata.make` asserts.

Related: #56281 (same assert in DSpark, fixed by #54856), #56734 (dummy-run masking for EAGLE). Not a duplicate: no open or closed PR covers these fixes. #56136 touches the same dynamic-SD gate but not which managers capture per K.

## Claims

- Fix the `draft_model` + MoE + DP > 1 startup crash (`AssertionError: 7168 1024`).
- Port #56734's dummy-run `idx_mapping` masking to the standalone drafter, so idle DP ranks don't write draft KV through stale block tables.
- Fix the draft prefill's `seq_lens_cpu_upper_bound`, which was one short.
- Stop `DFlashCudaGraphManager` (DFlash/DFlash2/DSpark) capturing per-K FULL graphs under dynamic SD that it never dispatches.

## Validation

Qwen3-30B-A3B target, Qwen3-0.6B draft, K=3, MRV2, H100s. GSM8K 5-shot, 1319 questions.

| DP=1, draft_model | 0.889 | 81.6% |
| DP=2, draft_model, main | crash at startup | — |

- No sync warnings with `VLLM_GPU_SYNC_CHECK=warn` at DP=2.
- Prefill bound: a temporary check found the actual draft `seq_lens` above the CPU bound on 539/549 prefills before, 0 after.
- Idle-rank dummy batches: a tiny random-weight MoE at DP=2 with single and burst requests completes; main crashes.

## Details

- **DP sync.** The draft prefill runs `num_tokens + num_reqs` tokens and each decode step `num_reqs`, so each syncs its own count via `dispatch_cg_and_sync_dp(need_eager=True)`: once for prefill, once before the decode loop. That adds two CPU all-reduces per `propose` at DP > 1. Reusing the target's sync (as the target-dependent drafters do) would mean padding eager attention metadata here, since the target sync only carries the max request count.
- **Prefill bound.** The prefill kernel writes `seq_len + 1` per request for the correction token, so the prefill now passes `step=1`, as decode already does. FlashInfer TRTLLM prefill with FP8 KV and the sparse MLA backends size work from this bound.
- **DFlash capture.** New `CudaGraphManager.dynamic_sd_query_lens = True`, set to `False` on `DFlashCudaGraphManager`.
- **CI.** No CI step runs a MoE target with a draft model at DP=2; the e2e runs above were local.
