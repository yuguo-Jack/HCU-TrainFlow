# [Bugfix][Tool Calling] Dots non-streaming parse drops post-tool-call text that streaming returns

[Upstream PR](https://github.com/vllm-project/vllm/pull/63093) · state: open · merged: False

## Original PR description

## Overview

Fix the `dots` tool parser's non-streaming path dropping the text after the last
`<dots_function_call>` block, so streaming and non-streaming return the same
`content`. Related to #56270 (merged as 81f7c69), which fixed the same class of
bug in the DeepSeek-V3 parser.

## Claims

- Non-streaming `extract_tool_calls` now keeps the preamble plus the text after
  the last `</dots_function_call>` marker (previously only the preamble).
- Streaming and non-streaming return identical `content` for the same output.
- Tool-call extraction, schema coercion, unknown-tool handling, and the
  `if not tool_calls: content=model_output` early return are unchanged.

## Validation

Reproducer (stream=false):

    let me check the weather.<dots_function_call><invoke name="get_weather"><parameter name="city">Paris</parameter></invoke></dots_function_call>It is 30 degrees.

- before: `content = "let me check the weather."` (drops `It is 30 degrees.`)
- after : `content = "let me check the weather.It is 30 degrees."` (== streaming)

New regression tests in `tests/tool_parsers/test_dots_tool_parser.py`:
`test_non_stream_keeps_text_after_tool_call` and
`test_stream_keeps_text_after_tool_call`. Both use the same input and assert the
same `content`.

    VLLM_TARGET_DEVICE=cpu python -m pytest -q tests/tool_parsers/test_dots_tool_parser.py
    # => 12 passed

The non-streaming test fails without the fix:

    assert 'let me check the weather.' == 'let me check the weather.It is 30 degrees.'

## Details

**Root cause.** `extract_tool_calls` (line 250) set
`normal_text = model_output[:marker_index].strip()`, i.e. only the preamble.
`extract_tool_calls_streaming` accumulates `normal_parts` for text outside
successfully parsed blocks, including the trailing text.

**Fix.** Mirror #56270: keep the preamble plus the text after the last end
marker.

    tool_calls_end = model_output.rfind(self.tool_call_end_token)
    normal_text = model_output[:marker_index]
    if tool_calls_end != -1:
        normal_text += model_output[tool_calls_end + len(self.tool_call_end_token):]
    normal_text = normal_text.strip()

**Limitation (same scope as #56270).** Text *between* multiple
`<dots_function_call>` blocks is still not kept by the non-streaming path; the
fix only restores the trailing text.

**Not a duplicate.** #56270 fixed the same class in the DeepSeek-V3 parser and
does not touch Dots. #55199 touches only the Qwen3 Parser Engine. #60516 touches
this file but only for null/boolean coercion.
