# [Bugfix][Frontend] Bound parallel sampling by server limits

[Upstream PR](https://github.com/vllm-project/vllm/pull/65355) · state: open · merged: False

## Original PR description



## Overview

Fixes #65332 by bounding parallel sampling requests on `/v1/chat/completions` and `/v1/completions`. Requests are rejected before generation when `n` exceeds `min(VLLM_MAX_N_SEQUENCES, max_num_seqs)`.

## Claims

- Both endpoints enforce the configured global sequence limit and the server's `max_num_seqs`.
- The request models do not impose a fixed upper bound of 128.
- Documented the effective limits in the OpenAI-compatible server guide.

## Validation

- Before the server-capacity check, a request with `max_num_seqs=8` and `n=9` returned HTTP 200; the regression assertion failed with `DID NOT RAISE BadRequestError`.
- RTX 3090 end-to-end tests, using Qwen2.5-0.5B, `max_num_seqs=8`, and `gpu_memory_utilization=0.3`:

  ```bash
  HF_ENDPOINT=https://hf-mirror.com \
  PATH="$PWD/.venv/bin:$PATH" \
  .venv/bin/python -m pytest \
    tests/entrypoints/openai/chat_completion/test_parallel_sampling.py -v -s
  ```

  Result: **2 passed**, covering both endpoints.

- Focused `n` parameter tests in `test_chat.py` and `test_completion.py`: **9 passed**. These include accepting `n=129` with `VLLM_MAX_N_SEQUENCES=256` and rejecting values above the configured sequence limit.
- Ruff check and format check passed for changed Python files; `git diff --check` passed.
- No model quality evaluation or latency benchmark was run. The change rejects over-limit requests before generation; generation for accepted requests is unchanged.

## Details

The previous limit used `VLLM_MAX_N_SEQUENCES`, whose default of 16384 can exceed a deployment's `max_num_seqs`. A request could therefore expand into more parallel sequences than the server is configured to schedule. The shared serving check now applies the lower of those two limits.

No other matching open PR was found when this change was prepared. AI assistance was used to investigate, implement, and validate the change.
