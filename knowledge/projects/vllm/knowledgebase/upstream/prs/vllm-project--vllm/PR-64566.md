# [HiSparse] GLM-5.3-Flash: fill device pool blocks with multiple indexer pages

[Upstream PR](https://github.com/vllm-project/vllm/pull/64566) · state: closed · merged: False

## Original PR description

> [!NOTE]
> Stacked on #61243. Review only the top two commits (`[KV Cache] Address packed kernel blocks…`, `[HiSparse] Fill device pool blocks…`). I'll retarget once #61243 merges.

## Purpose

#61243 sizes the HiSparse indexer group's device-pool block to one 256-token kernel page. On GLM-5.3-Flash, the shared pool block is sized by the 1.18 MB KDA state pages, so each 92,928 B indexer page leaves ~92% of its block as padding.

This PR fills each pool block with as many whole indexer pages as fit (12 on Flash, a 3072-token indexer block):

- `vllm/v1/hisparse/layout.py`: size the indexer group after the hot/resident groups, to whole pages of the largest device-group page.
- `vllm/v1/worker/utils.py`: a block that holds 12 pages is no multiple of one page apart, and the previous lcm alignment would inflate it to 4.3 MB. `AttentionGroup.map_kv_cache_to_kernel_blocks` now numbers kernel pages in units of `gcd(block stride, page size)` (kernel block `j` of block `b` = `b * kernel_block_stride + kernel_block_offsets[j]`). The result is unchanged when the block stride is a whole number of pages.

Non-HiSparse runs are unaffected: their packed group layout never splits blocks this way.

The scheduler block grows from 2304 to 9216 tokens on Flash (the lcm of the group block sizes). The prefix-cache hash block is unchanged, and long-context prefix-cache hit rate is unchanged (below).
