# [CI] Lock cmake and restore (CPU) Params, Env, Tokenizers, Parser job

[Upstream PR](https://github.com/vllm-project/vllm/pull/64414) · state: open · merged: False

## Original PR description

## Overview

Re-enable the `(CPU) Params, Env, Tokenizers, Parser` CI job that #63609
disabled, by replacing its unpinned `pip install cmake` with a
hash-locked requirements file.

## Claims

- Restores the `(CPU) Params, Env, Tokenizers, Parser` job disabled in #63609.
- Removes the runtime `pip install cmake` (unpinned, unhashed) in favor of
  `requirements/ci/cmake.txt` installed with `--require-hashes`.
- Keeps `cmake==3.31.6` within the 3.x range required by the build
  (`CMakeLists.txt` `cmake_minimum_required(VERSION 3.26)`,
  `requirements/build/cpu.txt` `cmake>=3.26.1`).
- Drops the 87 test-tethering allowlist entries that were only there to
  cover the disabled job.

## Validation

Local checks (x86_64 clone; CI runs the job itself on this PR):

- `tools/pre_commit/check_test_tethering.py` full scan exits 0 — every
  test removed from the allowlist is covered by the restored job.
- `.buildkite/test_areas/misc.yaml` parses with PyYAML (24 steps) and the
  `&cpu-async-engine-deps` anchor resolves at all three alias sites.
- The three pinned hashes match PyPI's `cmake==3.31.6` glibc-linux wheels
  (`manylinux2010_x86_64`, `manylinux2014_x86_64`, `manylinux2014_aarch64`).
- `git apply --check` / `patch --dry-run` apply cleanly on current `main`.

The restored job's actual pytest run is exercised by this PR's Buildkite
CI; the submitter confirms that before merge.

## Details

`tests/test_cmake_utils.py` shells out to `cmake -P`, but the CPU test
image ships no cmake: it is only in `requirements/build/cpu.txt`, which
the `vllm-build` and `vllm-test-deps` stages install and the `vllm-test`
stage does not inherit. #63609 disabled the job rather than keep an
unpinned install.

`requirements/ci/cmake.txt` pins `cmake==3.31.6` with hashes for the
glibc-linux wheels the CPU images can run on; `--require-hashes` makes an
unpinned platform a hard error rather than a silent download. musllinux
is intentionally not pinned (the CPU image is `FROM ubuntu:22.04`).
`docker/Dockerfile.cpu` ships `requirements/ci/` into the `vllm-test`
stage because the wheel does not carry `requirements/`.

Regenerate the lock with:

```
uv pip compile --generate-hashes --no-annotate --python-version 3.12 \
  --python-platform x86_64-manylinux_2_28 <<< 'cmake==3.31.6'
```
