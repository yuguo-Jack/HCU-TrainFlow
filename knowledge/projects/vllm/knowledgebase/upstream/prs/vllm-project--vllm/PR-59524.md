# [Bugfix][NIXL] Roll back incomplete remote-agent handshakes

[Upstream PR](https://github.com/vllm-project/vllm/pull/59524) · state: open · merged: False

## Original PR description

## Overview

Roll back resources acquired by a NIXL handshake that fails before publishing
the peer. Today, failed setup can leave native metadata and descriptor state
outside the published-peer cleanup path.

### Failure workflow

1. A background handshake registers remote agents with NIXL and prepares
   descriptors before publishing the peer in `_remote_agents`.
2. Validation, descriptor preparation, or setup of a later rank raises after
   some resources have already been acquired.
3. The handshake reports failure without publishing the peer. Cleanup based on
   `_remote_agents` therefore misses the incomplete registration.

The ownership gap is between native registration and Python-side publication.
The fix tracks registrations from acquisition until publication or successful
rollback, so an unsuccessful handshake does not leave them unaccounted for.

The native/API reproducer confirmed leftover metadata, but subsequent baseline
requests also succeeded. This fixes incomplete cleanup, not a demonstrated
permanent outage or inevitable deadlock.

This complements #50047's published-peer replacement cleanup and is distinct
from #55471's recovery after NIXL invalidates an already-published peer.

AI assistance was used. The human submitter has reviewed every changed line and
personally run the relevant tests for this change.

## Claims

- Own native registrations immediately after successful registration, including
  notification-only peers and earlier ranks in a partially completed handshake.
- Reuse existing cleanup for failed setup and shutdown; retain unreleased
  resources if cleanup itself raises so a retry can finish cleanup.
- Preserve unrelated healthy peers and the original handshake exception.

## Details

A pending registration journal records native agents immediately after
registration, including notification-only peers and earlier ranks of a partial
handshake. It is discarded after successful publication, when the existing
published-peer cleanup takes ownership. Failed setup reuses the existing
per-engine cleanup to release descriptors and registrations.

Cleanup removes each resource's bookkeeping only after the corresponding native
operation succeeds. If rollback itself raises, the remaining entries stay
tracked; subsequent setup first retries the unfinished rollback. The original
handshake failure remains visible.

The change is limited to connector resource ownership; it does not retry failed
requests, change scheduling, change model output, or promise recovery of a broken
UCX context. The original failure remains visible. Tests extend existing peer
replacement fixtures. No steady-state GPU synchronization is added. Concurrent
integration with #55471 has not been validated.

Duplicate-work checks also covered #56852 (checkpoint/reinitialization hooks),
#56341 (explicit router-driven peer retirement) and #54757 (listener hardening).
They do not cover rollback of an incomplete worker-side registration.
