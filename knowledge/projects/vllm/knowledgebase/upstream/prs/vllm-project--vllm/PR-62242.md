# [Bugfix][KV Connector] Report every transfer group as loaded in Decod…

[Upstream PR](https://github.com/vllm-project/vllm/pull/62242) · state: open · merged: False

## Original PR description

## Purpose

`DecodeBenchConnector` fills a new request's own blocks in every KV cache group, like a P/D transfer, but it inherits the base `get_loaded_kv_cache_group_ids`, which reports only the prefix-cacheable groups (what a hash-addressed store holds). A bounded-replay sliding-window group (DeepSeek V4.1) is not prefix-cacheable, so the scheduler treats the window as not loaded and replays it on the first step of every filled request. That step becomes a mixed prefill step instead of a padded decode, and with DP it pulls every rank out of the FULL decode graph, so decode-only benchmarks with this connector do not reflect P/D decode.

This returns `transfer_group_ids`, the same as `NixlConnector` and `MooncakeConnector`.

## Test Plan

- New `test_decode_bench_connector_loads_bounded_replay_groups`: a full-attention group plus a bounded-replay `SlidingWindowMLASpec` group; the connector must report both groups. It fails without the fix (`(0,) == (0, 1)`).
- `pytest tests/v1/kv_connector/unit/test_decode_bench_connector.py tests/v1/core/test_prefix_replay.py`
