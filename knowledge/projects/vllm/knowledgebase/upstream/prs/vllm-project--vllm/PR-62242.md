# [Bugfix][KV Connector] Report every transfer group as loaded in DecodeBenchConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/62242) · state: closed · merged: True

## Original PR description

## Purpose

`DecodeBenchConnector` fills a new request's own blocks in every KV cache group, like a P/D transfer, but it inherits the base `get_loaded_kv_cache_group_ids`, which reports only the prefix-cacheable groups (what a hash-addressed store holds). A bounded-replay sliding-window group (DeepSeek V4.1) is not prefix-cacheable, so `_load_restores_replay_window` is false and the scheduler replays the last window on the first step of every filled request. That step becomes a prefill of about one window (128 tokens on DeepSeek V4.1) instead of a one-token decode, and with DP every rank leaves the FULL decode graph whenever any rank admits a request, so decode-only benchmarks with this connector do not reflect P/D decode.

This returns `transfer_group_ids`, the same as `NixlConnector` and `MooncakeConnector` since #59197. The connector is synchronous, so `skip_zeroing_group_ids` (async loads only) is unaffected; the only change is that the filled window is taken as is.

## Not a duplicate

No open PR changes the loaded groups of `DecodeBenchConnector`. #61543 skips non-transfer groups on the fill side (a HiSparse crash) and is complementary: with both, the connector fills and reports the same `transfer_group_ids`. #59197 added the replay skip and the NIXL / Mooncake overrides but left this connector on the default.
