# [Doc] Document Kimi-K3 GB300 disaggregated AgentX profile

[Upstream PR](https://github.com/vllm-project/vllm/pull/62528) · state: closed · merged: True

## Original PR description

## Overview

Document the GB300 Kimi-K3 disaggregated (xPyD) Dynamo + vLLM profile qualified in [SemiAnalysisAI/InferenceX#4047](https://github.com/SemiAnalysisAI/InferenceX/pull/4047) (head `0c5499b3`). Recipes for vLLM-served models live here since #61302, so this changes only `recipes/models/moonshotai/Kimi-K3.yaml` (guide text; no builder changes).

## Claims

- New guide section **GB300: InferenceX AgentX disaggregated (xPyD, TP8 + DCP8 per worker)**: the six tested topologies (1P2D, 1P3D, 1P4D, 2P3D, 2P5D; 24-56 GPUs) with decode `--max-num-seqs`, the etcd/NATS/Mooncake master services, per-role environment, the `python3 -m dynamo.vllm` prefill and decode commands, and the Dynamo frontend with session affinity.
- Prefill-only settings: EP8 with `deep_gemm_mega_moe`, `trtllm_ragged_backend: cute-dsl`, `VLLM_ENABLE_GEMM_RS=1`. Decode-only: `tokenspeed_mla_min_split_kv: 8`, `VLLM_ENABLE_GEMM_RS=0`, no EP. Both: `VLLM_KIMI_K3_SHARD_SP_SHARED_EXPERT=0`, `--enable-cumem-allocator`, connector prefetch and Mooncake `MC_*` settings.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` from vllm-project/recipes passes.
- Worker commands are the ones the InferenceX run launched (from its server logs), minus benchmark-only arguments: synthetic acceptance, config dumps and eval-only parsers. Image `vllm/vllm-openai:nightly-1b2a666391f2a24228a1436b64d547c34cc6b6ce`, Dynamo `ffbbaaa6`.
- InferenceX sweep: [run 39140771499](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/39140771499).

## Details

Excluded as benchmark harness only: synthetic acceptance length, AIPerf/trace-replay settings, Slurm options, health checks and telemetry. Loading timeouts are described rather than pinned. Cluster-specific fabric variables (`NCCL_NET_PLUGIN`, `WITH_NVIDIA_PEERMEM`) are left to the deployment.
