# [WIP][Model] Share recurrent arithmetic for Qwen GDN batch invariance

[Upstream PR](https://github.com/vllm-project/vllm/pull/60033) · state: open · merged: False

## Original PR description

## Overview

Enable batch-invariant Qwen GatedDeltaNet prefill, cached continuation and decode under `VLLM_BATCH_INVARIANT=1` by sharing recurrent arithmetic. Supersedes #49827 and addresses the prefill-partitioning concerns in #48613. AI assistance was used.

## Claims

- Non-speculative Qwen GDN tokens use the existing recurrent kernel in BIC mode, instead of switching arithmetic between chunked prefill and recurrent decode.
- Exact output and persistent-state checks pass across the tested prefill partitions and decode replay. The existing public Qwen online BS1-vs-BSN token/logprob test passes.
- The non-BIC numerical route is unchanged. Speculative decoding is explicitly unsupported; this is a correctness feature with a measured performance cost, not a speedup.

The diff is reduced from +421/-25 to **+205/-22 including tests**. The bespoke HTTP test and overlapping mock-heavy test were removed; the existing online suite and exact partition/state regression remain. This is still above the reviewer's ideal 200-line size.

## Details

### Why Shared Recurrence

Chunked prefill and recurrent decode implement the same mathematical operation but can produce different floating-point results. Scheduler batching and prefill partitioning can therefore change a request's output. Opening the backend support flag alone does not resolve that.

In BIC mode this change shares recurrent arithmetic across non-speculative Qwen GDN prefill, continuation and decode, preserving convolution/recurrent state across arbitrary tested partitions. It also adds a Qwen-specific backend identity/support gate, includes the Inductor BIC policy in the compilation cache configuration, and makes normalization row tiling independent of batch size. XPU/NIXL references account for the backend identity. No scheduler chunk-grid restriction is added.

### Related Work And Open Review Points

- #57280 addresses normalization row tiling. This PR includes overlapping policy needed by the tested path; that overlap needs resolving before merge.
- #45819 opens GDN batch-invariance support. This PR additionally shares arithmetic between prefill and decode.
- #55868 aligns prefill/cache chunk grids; this approach instead shares recurrence across arbitrary tested partitions.
- #62343 uses recurrence for short prefills with a batch-dependent threshold. It references this PR but does not replace its invariant routing policy.
- The `QWEN_GDN_ATTN` versus `GDN_ATTN` naming is under review following @ZJY0516's comment; no naming change has been made yet.

### Out Of Scope And Limits

TP/EP, MRV2, Blackwell, multi-node, prefix-cache-on serving and live disaggregated state transfer are not validated by this matrix. Speculative decoding is unsupported. Long prefills may be slower under the recurrent route.

GEMM performance (#60034) and TP collective work (#50299) remain separate follow-ups; they do not establish multi-GPU correctness for this PR. No universal determinism or merge readiness is claimed.

Local validation does not replace upstream CI. Older Intel failures discussed in the thread belong to earlier heads; this update does not claim to fix or clear them, and no unrelated CI repairs are bundled here.

**[P2] Ensure bitwise replay with the default BF16 SSM cache**

The recurrent kernel accumulates state in FP32 within a sequence, but stores it to `ssm_state` after each token. When a prefill is split across scheduler steps, the next invocation reloads the rounded cache state.

By default, `gated_delta_net_state_dtype()` uses BF16 for BF16 models, so a single 97-token prefill and a 23+74 split may no longer be bitwise identical.

The new partition regression test uses `torch.randn(...)` without a dtype, which makes the SSM state FP32 and avoids this rounding.

Could we verify the exact partition comparison with a BF16 SSM cache? If it diverges, the BIC path may need to require FP32 recurrent-state storage.
