# [WIP][Model] Share recurrent arithmetic for Qwen GDN batch invariance

[Upstream PR](https://github.com/vllm-project/vllm/pull/60033) · state: open · merged: False

## Original PR description

## What

Enable batch-invariant Qwen GatedDeltaNet execution for prefill, cached continuation
and decode under `VLLM_BATCH_INVARIANT=1`. This replaces #49827 and addresses
the prefill-partitioning concerns in #48613. The submitter has completed
line-by-line review; maintainer feedback is requested. AI assistance was used.

## Why

Qwen GDN normally uses chunked arithmetic for prefill and recurrent arithmetic
for decode. These compute the same mathematical operation but do not necessarily
produce the same floating-point result. A request can therefore change its
output when the scheduler splits its prefill differently or mixes it with decode
requests. Enabling the backend support flag alone does not address that problem.

The goal is to make the GDN computation independent of those scheduling choices,
including continuation from cached state, within a fixed execution configuration.

## How

In BIC mode, all non-speculative Qwen GDN tokens use the existing recurrent
kernel. Prefill, continuation and decode retain the same convolution/recurrent
state and follow the same arithmetic rather than switching between chunked and
recurrent implementations.

The change also adds a Qwen-specific backend identity/support gate and disables
batch-dependent Inductor transformations in BIC mode. XPU and NIXL references
are updated for the backend identity. The non-BIC numerical route is unchanged;
there are no scheduler chunk-grid restrictions.

Speculative decoding is explicitly unsupported. Long prefills can be slower on
the recurrent route; this is a correctness change, not a performance improvement.

### Serving

Each configuration ran eight public/synthetic text, image and conversation-history
cases five times, generating 32 tokens per request. Requests ran alone and in
heterogeneous loaded batches; mixed decode/prefill steps were observed.

External instrumentation hashed every full-vocabulary BF16 logit row before
sampling. Missing or duplicate records fail the check. Tokens, top-logprobs and
raw-logit hashes matched exactly across executions within each configuration.

| Model | Execution | Prefix cache | Requests / logit rows | Cached prompt tokens |
|---|---|---|---|---|
| Qwen3.5-0.8B | eager | off | 40 / 1,280 | 0 |
| Qwen3.5-0.8B | eager | on | 40 / 1,280 | 15,552 |
| Qwen3.5-0.8B | compiled | off | 40 / 1,280 | 0 |
| Qwen3.5-0.8B | compiled | on | 40 / 1,280 | 15,552 |
| Qwen3.5-4B | eager | off | 40 / 1,280 | 0 |

Cache off/on also agreed at all 256 case-positions within each execution mode.
**Eager and compiled did not agree bitwise:** all 256 positions differed between
those modes. These checks establish invariance in the tested configurations,
not equality between configurations. Cache hits establish prompt reuse, not
generated-token cross-turn state reuse.

### Performance And Quality

Unprofiled `vllm bench throughput`, Qwen3.5-0.8B, TP1/BF16/eager/cache-off:
three repetitions per mode in alternating order, four warmup prompts and sixteen
measured prompts. Each repetition processed 16,384 input and 2,048 output tokens.

| Mode | Elapsed seconds | Median requests/s | Median output tokens/s |
|---|---|---|---|
| Normal | 11.219, 11.880, 11.144 | 1.4261 | 182.54 |
| BIC | 15.711, 13.845, 13.883 | 1.1525 | 147.52 |

BIC reached 80.81% of normal median throughput. This includes global BIC GEMM
and the GDN path; it does not isolate GDN overhead or measure serving TTFT.
Logit capture was disabled.
