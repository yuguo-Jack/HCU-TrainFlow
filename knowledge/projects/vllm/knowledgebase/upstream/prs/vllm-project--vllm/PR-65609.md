## Overview

Add Kimi-K2.6 Guide insertion anchors for the Ascend overlay and make the shared client example follow the selected model.

Depends on the renderer support in https://github.com/vllm-project/recipes/pull/1170. Companion overlay: https://github.com/vllm-project/vllm-ascend/pull/20795.

## Claims

- Place Huawei prerequisites within Prerequisites, deployment instructions before Client Usage, and Ascend links in References.
- Keep one shared Client Usage example, including when no Ascend overlay is loaded.
- Replace the fixed client model ID with `{{client_model}}`, resolved by the renderer from the selected checkpoint or serving alias.

Only `recipes/models/moonshotai/Kimi-K2.6.yaml` is changed. Existing GPU launch parameters and inference code are unchanged.

## Validation

- Full recipe assembly and JSON API generation passed with the companion renderer and Ascend overlay.
- Focused checks confirmed section ordering, a single Client Usage section, reference placement, and preservation of the client example without an overlay.
- Client-model regression tests and `git diff --check` passed.
- Full repository pre-commit checks were not completed locally.
- Model evaluation is not applicable to this presentation-only change.

## Details

Without owner insertion anchors, overlay sections append to the end of the Guide. Keeping the client example in the owner recipe also avoids maintaining a duplicate Ascend example.

No matching open recipe-layout PR was found during the duplicate-work check. Merge only after recipes #1170 is deployed. Human review remains required.
