# [Test][ROCm] Add AITER MLA backend contract tests

[Upstream PR](https://github.com/vllm-project/vllm/pull/58843) · state: closed · merged: False

## Original PR description

## Purpose

Adds class-metadata contract tests for the two ROCm AITER MLA backends,
covering the backend-contract items tracked in #50453.

These are pure attribute/introspection checks - no kernels execute - so they
run on any ROCm agent in the existing `kernels/attention` sweep and require no
CI configuration change.

## What is covered

- `AiterTritonMLABackend` reuses the dense builder, and its impl subclasses the
  dense impl: it overrides only the name and implementation.
- Dense `AiterMLABackend`: no head-size restriction, the full fp8 KV-cache
  dtype set, and the permissive `MultipleOf(1)` block-size declaration.
- `ROCMAiterMLASparseBackend`: builder/impl/metadata wiring (including the
  metadata generic parameter), `is_mla()`/`is_sparse()`, and the stricter
  `[1, MultipleOf(16)]` block-size contract, including rejection of 24.

## Notes on the tracker

Two items in #50453 section 4 are obsolete: `accept_output_buffer()` and
`get_kv_cache_shape()` no longer exist in the tree, having been replaced by
`supported_kv_cache_layouts()` in the KV-cache layout refactor. The FP8
detection section is likewise already implemented in
`_check_aiter_mla_fp8_support()`, which caches its result and fails closed on
all five exception types.

One asymmetry surfaced while writing these: `ROCMAiterMLASparseBackend` does
not advertise `fp8_e5m2` while the dense AITER MLA backend does, even though
the sparse metadata builder normalizes `fp8_e5m2` to an fp8 cache dtype
(`rocm_aiter_mla_sparse.py:456`, mirroring `rocm_aiter_mla.py:580`). The test
pins the current contract; happy to widen it if that difference is unintended.

## Why this is not duplicating an existing PR

- #55611 covers `ROCM_AITER_FA`/`FLASH_ATTN` MLA prefill *execution* for #53944.
  This change touches no CI job and no execution path.
- `gh pr list --state open --search "rocm_aiter"` shows no PR covering backend
  contracts.
- #50453 has no linked PRs.
