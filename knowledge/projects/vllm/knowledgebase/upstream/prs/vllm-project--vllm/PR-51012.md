# [Models] Deprecate `torch.compile` for Qwen3.5 models

[Upstream PR](https://github.com/vllm-project/vllm/pull/51012) · state: open · merged: False

## Original PR description




## Overview

Qwen3.5 dropped `@support_torch_compile` in favor of breakable CUDA graphs (`VLLM_USE_BREAKABLE_CUDAGRAPH`, auto-enabled in `vllm/config/vllm.py`). An isolation experiment (same old code, compile vs breakable cudagraph) showed the removal alone cost **+45 ~ 64% decode-step and +22 ~ 39% prefill latency**. This change recovers the lost inductor fusions with explicit fused kernels, ending **5~11% faster than the torch.compile baseline** on decode and at parity on prefill.

## Claims

- End-to-end serving (`vllm bench serve`, up to 128 concurrent requests): decode ITL **-3.0% ~ -8.8%**, prefill TTFT **-7.0% ~ -8.9%** vs the torch.compile baseline (9B + 35B-A3B).
- Isolated forward latency (`vllm bench latency`): decode step **-4.9% ~ -10.7%**, MTP decode **-17% ~ -38%**, prefill at parity.
- Greedy decoding output is **token-identical** to the torch.compile baseline (TP1 and TP2).

## Validation

Environment: 1x NVIDIA GB200 (SM100, aarch64) per run, bf16, real weights (`Qwen/Qwen3.5-9B` dense, `Qwen/Qwen3.5-35B-A3B` MoE). Baseline = pre-removal commit (`44e88ae582^`) with default `VLLM_COMPILE`; "old+breakable" = same commit with `VLLM_USE_BREAKABLE_CUDAGRAPH=1`; "this PR" = HEAD with all fusions. Note: newer vLLM defaults prefix caching ON, which alone inflated TTFT by ~17-20% in an unnormalized run — both trees below use identical serving flags to avoid that artifact.

### End-to-end serving (vllm serve + vllm bench serve, random dataset)

Both trees with identical serving flags (`--no-enable-prefix-caching --max-num-batched-tokens 8192`; note newer vLLM defaults prefix caching ON, which alone inflated TTFT by ~17-20% in an unnormalized run — flagged here so reviewers don't reproduce that artifact). vllm bench serve --backend vllm --model Qwen/Qwen3.5-9B --host 127.0.0.1 --port 8192 --dataset-name random --ignore-eos --percentile-metrics ttft,tpot,itl,e2el --num-prompts 320 --max-concurrency 32 --random-input-len 128 --random-output-len 256   # decode cc=32 (also: 384@cc64, 512@cc128, 128@cc32 with input 4096)
```bash
vllm bench serve ... --num-prompts 16 --max-concurrency 1 --random-input-len 128 --random-output-len 256    # decode single-stream
vllm bench serve ... --num-prompts 16 --max-concurrency 1 --random-input-len 4096 --random-output-len 8    # prefill TTFT

# Isolated forward latency (per tree, per model) — full commands in ~/bench_qwen35_sbatch.sh
vllm bench latency --model Qwen/Qwen3.5-9B --num-iters-warmup 2 --num-iters 5 --max-model-len 8192 --gpu-memory-utilization 0.9 --input-len 4096 --output-len 1 --batch-size 1     # prefill
vllm bench latency ... --input-len 32 --output-len 1 --batch-size 1     # decode t(1)
vllm bench latency ... --input-len 32 --output-len 65 --batch-size 1    # decode t(65); step = (t65-t1)/64
vllm bench latency ... --input-len 32 --output-len {1,65} --batch-size 32

# MTP decode — ~/mtp_bench_qwen35_sbatch.sh
vllm bench latency --model Qwen/Qwen3.5-9B --speculative-config '{"method":"qwen3_5_mtp","num_speculative_tokens":1}' --input-len 32 --output-len {1,65} --batch-size {1,32} ...

# Kernel unit tests — ~/ktest_qwen35_sbatch.sh
python -m pytest tests/kernels/core/test_fused_sigmoid_gate_mul.py tests/kernels/core/test_gemma_rms_norm_triton.py tests/kernels/core/test_fused_pre_fc_norms.py tests/kernels/mamba/test_gdn_qwen35_strided_inputs.py -q

# Greedy-output smoke (TP1/TP2) — ~/smoke_qwen35_sbatch.sh + ~/smoke_qwen35.py
python ~/smoke_qwen35.py Qwen/Qwen3.5-9B <tp> out.json   # LLM(..., tensor_parallel_size=tp), temperature=0, 64 tokens x 4 prompts
```
