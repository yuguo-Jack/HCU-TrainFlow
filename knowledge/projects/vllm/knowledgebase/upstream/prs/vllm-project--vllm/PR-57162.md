# [Bugfix][ROCm] Skip AITER top-k/top-p sampler on gfx942

[Upstream PR](https://github.com/vllm-project/vllm/pull/57162) · state: open · merged: False

## Original PR description

## Purpose

When `VLLM_ROCM_USE_AITER=1`, vLLM selects AITER's top-k/top-p sampler. On gfx942 (MI300X) that path segfaults in `aiter.top_k_top_p_sampling_from_probs` after warmup. `--enforce-eager` does not avoid it.

gfx1250 already falls back to the native sampler via `_skip_aiter_sampler_on_gfx1250()`. This PR extends that guard to gfx942 so AITER can stay enabled for other kernels while sampling uses the PyTorch-native path.

## Test Plan

- [x] Serve `Qwen/Qwen3.8-Flash-Next-FP8` with TP=8 on 8x MI300X (`gfx942`) and `VLLM_ROCM_USE_AITER=1`
- [x] Confirm generation no longer crashes in `top_k_top_p_sampling_from_probs`
- [x] Confirm other AITER ops remain available (only the sampler is skipped)

Serve command used:

```bash
VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_MOE=0 SAFETENSORS_FAST_GPU=1 \
vllm serve /models/Qwen3.8-Flash-Next-FP8 \
  --host 0.0.0.0 --port 8000 --trust-remote-code \
  --tensor-parallel-size 8 --enable-expert-parallel \
  --max-model-len auto --gpu-memory-utilization 0.9 \
  --no-enable-prefix-caching --max-num-seqs 256
```
