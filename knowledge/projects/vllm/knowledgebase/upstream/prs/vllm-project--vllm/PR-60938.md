# [Perf][DSv4.1] Prototype Engram to delayed mHC input fusion

[Upstream PR](https://github.com/vllm-project/vllm/pull/60938) · state: open · merged: False

## Original PR description

## Overview

Prototype an opt-in fusion of the DeepSeek-V4.1 Engram gate/residual update with the following delayed mHC input collapse and RMSNorm. This is a **Draft for implementation review; GPU correctness, performance and model validation are pending**.

Inspired by the DP fusion in [SGLang #43065](https://github.com/sgl-project/sglang/pull/43065). Related vLLM tracking: [#57448](https://github.com/vllm-project/vllm/issues/57448).

## Claims

- Add a producer path that returns both the updated BF16 residual and the normalized input formed with the incoming pre-mix.
- Reuse the existing mHC `stats` specialization to generate the next coefficients without repeating the input collapse and normalization.
- Keep the prototype **off by default**. `VLLM_USE_ENGRAM_MHC_FUSION=1` selects it only on CUDA Blackwell with TP1, no sequence parallelism, and no active mHC overlap stream.

No speedup or GPU numerical-equivalence claim is made yet.

## Details

The Engram boundary currently materializes the updated residual before delayed mHC reads it again for the input collapse. The new token program computes the HC gates, writes the same BF16 residual, and accumulates the incoming pre-mix collapse while those values are available. It rounds the collapse to BF16 before RMSNorm. The separate coefficient projection still consumes the complete updated residual and produces all next pre/post/residual coefficients using the existing math.

The full residual store, WKV computation, previous-layer auxiliary observation point, mask arithmetic, and both BF16 rounding boundaries are retained. This does not fuse communication or remove coefficient work. Triton and TileLang can use different normalization reduction trees; the regression reuses the existing delayed-mHC normalization tolerance rather than claiming bitwise normalized outputs.

One token program serializes the HC gates, which may cost more than the saved read/normalization work. Register pressure and whole-model benefit need measurement. The default-off switch keeps this unvalidated prototype explicit while those results are collected.

Duplicate checks covered current open `engram mhc` PRs, the #57448 tracker and linked work, and complete public Engram/mHC and Engram/fused searches. No matching vLLM gate-to-delayed-input fusion was found. [#56633](https://github.com/vllm-project/vllm/pull/56633) retains a separate Engram boundary; [#60153](https://github.com/vllm-project/vllm/pull/60153) excludes it. This is separate from packed Engram lookup [#59923](https://github.com/vllm-project/vllm/pull/59923) and WKV sharding [#58678](https://github.com/vllm-project/vllm/pull/58678). SGLang #43065 is prior art for the fusion, not a claim of original invention here.
