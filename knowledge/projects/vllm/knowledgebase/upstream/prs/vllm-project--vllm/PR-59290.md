# [ROCm][BugFix] Don't use AITER rms_norm as an IR OP on gfx90a when AITER always on.

[Upstream PR](https://github.com/vllm-project/vllm/pull/59290) · state: closed · merged: True

## Original PR description


## Purpose
This PR disables the use of the AITER `rms_norm `on `gfx90a` as an IR OP since AITER is not currently built in the vLLM base dockerfile for that arch.

`ENV AITER_ROCM_ARCH=gfx942;gfx950`

Without this, the following test groups will all have segfaults due to this issue when AITER is always on:
  - mi250_4: Pipeline + Context Parallelism (4 GPUs)
  - mi250_1: Language Models Test (PPL)
  - mi250_1: Multi-Modal Models (Standard) 3: llava + qwen2_vl
  - mi250_1: Cudagraph
  - mi250_1: e2e Core (1 GPU)
  - mi250_1: Spec Decode Draft Model
  - mi250_1: Spec Decode Speculators + MTP

NOTE: AITER currently **does** support `gfx90a`, but it is not built for vLLM right now.  I can make an issue for this if desired, but not sure if it is really warranted.
## Test Plan
Run the 7 failing test groups and ensure this segfault does not occur.
