# [Bugfix] Fix ReplaySSM ring shape assertion when TP does not divide Mamba2 n_groups

[Upstream PR](https://github.com/vllm-project/vllm/pull/60704) · state: closed · merged: True

## Original PR description

## Overview

Fixes #60346. `MambaStateShapeCalculator.append_replayssm_ring` now extends `n_groups` for head shards, the same way `mamba2_state_shape` already does. Before this change, a single group under TP 2 raised `AssertionError: 1 is not divisible by 2`.

## Claims

- `append_replayssm_ring` no longer raises on a state shape that `mamba2_state_shape` builds without error. For `n_groups=1`, TP 2, it returns a `B_cache` shape with one group per rank, which is what the mixer's `B` tensor holds.
- Inputs that worked before give the same result. `extra_groups_for_head_shards` returns 0 when TP divides the count, so the `MambaMixer2` path, which already passes the extended count, does not change.
- Adds one unit test for the case.

## Details

**Root cause.** Under TP, Mamba2 supports a group count that TP does not divide only when `n_groups == 1`. The single group is copied to every head shard by extending the count to `n_groups + extra_groups_for_head_shards(n_groups, tp)`. `mamba2_state_shape` takes the raw count and extends it itself. `append_replayssm_ring` takes the same argument but divided the raw count by TP, so `divide(1, 2)` failed its assertion.

The ring's `B_cache` needs the extended count per rank. `MambaMixer2` views `B_d` as `(-1, self.n_groups // tp_size, dstate)` with the already-extended `self.n_groups`. The ReplaySSM Triton kernel takes `ngroups = B.shape[1]` and asserts `B_cache.shape[1:] == (ngroups, max_cache_len, dstate)`.

**Who hits it.** `MambaMixer2.get_state_shape` passes the extended count, so it worked. `NemotronHForCausalLM.get_mamba_state_shape_from_config` passes the raw `hf_config.n_groups` to both calculator methods, the same way the reproducer does. So a NemotronH model with `n_groups == 1`, TP > 1 and ReplaySSM hits this assertion when it computes its cache shapes. I found this by reading the code; I did not run it.

**Why fix it in the calculator and not in the NemotronH caller.** Fixing only the caller would leave `mamba2_state_shape` and `append_replayssm_ring` with different rules for the same `n_groups` argument. Extending inside `append_replayssm_ring` covers both callers and leaves the `MambaMixer2` path as it was. The change is one code line plus a docstring line. The old docstring said "B_cache uses the un-extended `n_groups`", which did not match what the kernel needs. It came in with the ReplaySSM change (866fea2b9).

**Limitation.** A count that TP does not divide and that is not 1 (for example 3 groups with TP 2) now gets a shape here instead of an assertion. `mamba2_state_shape` already behaved this way before this PR, and `MambaMixer2.__init__` still rejects such a count with its own assertion, which this PR does not touch.

Comparison with #60439
 - The core fix is the same one line in `append_replayssm_ring`. The difference is that #60439 also rewrites the shared `extra_groups_for_head_shards` to pad to a multiple of TP.  - Three of its four test cases use invalid Mamba2 configs (`num_heads=8` with `n_groups` 3 or 5). This PR keeps the change minimal and tests only the real case from the issue (`n_groups=1`, TP=2), reproduced on a B200 before and after the fix.
