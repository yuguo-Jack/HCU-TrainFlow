# [Bugfix][Spec Decode] Align adaptive draft prefill graph padding

[Upstream PR](https://github.com/vllm-project/vllm/pull/62796) · state: closed · merged: True

## Original PR description

## Overview

Fixes #62793. Align adaptive-verification draft-prefill CUDA graphs with the target's shared attention metadata, including when another data-parallel rank is prefilling.

## Claims

- Capture varlen draft-prefill graphs under AV and exclude prefill-bearing batches from decode-only graphs.
- Preserve the agreed `max_query_len` in `DPSyncState` and reuse it, including `None`, without another collective.
- Extend the existing regression with DP > 1 peer-prefill and longer-peer-decode cases.

## Details

Draft prefill shares the target's attention metadata and must use the same padded request layout. With DP, another rank's prefill makes the agreed query bound `None`; reusing a local decode bound can incorrectly select FULL after the target selected PIECEWISE. All state-construction paths now preserve the agreed bound, while uniform draft batches reset it to their own query length. The upstream benchmark's eager state is updated for the new field.

Duplicate checks were refreshed: #62953 handles final redispatch disagreement between rank-local graph inventories; #63523 optimizes CPU metadata math. Neither implements this target-to-draft bound reuse fix. No other open PR was found linked to #62793.

AI assistance was used for diagnosis, implementation, tests, review and validation.
