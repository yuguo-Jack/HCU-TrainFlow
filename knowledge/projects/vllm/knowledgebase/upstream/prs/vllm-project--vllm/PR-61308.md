# [Model] Add Clef-Flash support

[Upstream PR](https://github.com/vllm-project/vllm/pull/61308) · state: closed · merged: True

## Original PR description



## Overview

Add native support for [Cloudflare/clef-flash](https://huggingface.co/Cloudflare/clef-flash) through `/v1/systemone`, reusing the Qwen3.5 backbone and the joint schema head introduced for Clef-Omni in #61064.

## Claims

- Automatically detect and load the separate joint schema head, scoring `choice`, `noul`, and `score` questions in one pooling request.
- Support text/JSON, images, and videos sampled at 2 fps. Match the release's fixed prompt, media separators, schema spans, and 16K truncation.
- Share the head/pooler between Clef-Flash and Clef-Omni. Flash rejects audio inputs and ignores video soundtracks.

## Validation

Compared the full checkpoint at revision `8b2e5fd17c09fd49bc2880b805d5323ec7ff4ff3` against the release's `joint_schema_model.py` in BF16. Ten model inputs covered invoice decisions, Unicode/empty instructions, a state truncated to 16K, one/two images, video, and image+video. Prompt token IDs and question/option spans matched the reference exactly in all ten cases.

Each mode ran the ten inputs once sequentially and twice at concurrency 4:

| Mode | Requests | Highest-probability option matches | Max absolute probability difference |
| --- | --- | --- | --- |
| Eager | 30 | 57/57 | 0.001508 |
| Default compile | 30 | 57/57 | 0.000863 |

The four invoice threshold labels were correct in every repetition (12/12 per mode). These are synthetic model correctness checks. Probability normalization and input-token counts also matched; output-token counts were zero.

The reference evaluation used `encode_record`, `collate_records`, and `load_release_model(..., attn_implementation="sdpa")`, comparing each question's softmax probabilities against `/v1/systemone` responses. Serve the model with:

```bash
vllm serve Cloudflare/clef-flash \
  --served-model-name clef-flash --dtype bfloat16 \
  --max-model-len 16384 --max-num-batched-tokens 512 --max-num-seqs 8
# Add --enforce-eager for the eager comparison.
```

## Details

The checkpoint advertises `Qwen3_5ForConditionalGeneration` and supplies `joint_head_config.json` plus `joint_head.safetensors`. Architecture conversion detects that head, and the Flash wrapper uses the output embedding table for lexical option features, matching the reference implementation.

The existing Clef head/pooler is moved unchanged into `clef_joint_schema.py`. Flash shares the joint schema strategy's typed answers and span/truncation logic, with its own media rendering for adjacent placeholders and a single trailing newline.

Duplicate checks found no open Clef-Flash support PR. #61064 supports Clef-Omni; the other open Clef-related PRs concern API/frontend behavior.

Model comparisons cover BF16 with TP=1. Multi-GPU configurations, quantization, and the full Clef checkpoint were not evaluated.

AI assistance (Codex) was used to implement and validate this model support.
