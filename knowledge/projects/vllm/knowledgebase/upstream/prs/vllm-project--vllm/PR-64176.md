# [ROCm][Bugfix] Allow the deliberate syncs the GPU sync check flags on ROCm

[Upstream PR](https://github.com/vllm-project/vllm/pull/64176) · state: open · merged: False

## Original PR description

- `eplb_state.py`: wrap the ROCm-only skip-rearrange check in `EplbState.rearrange` (#47206), which compares rank load imbalances on the host
- `rocm_aiter_mla_sparse.py`: wrap the stream sync after recomputing the AITER MLA metadata, which runs only when the metadata key changes
- `int4_per_token_head.py`, `moondream3.py`, `indexer.py`, deepseek_v4 mono `peer_memory.py`: wrap one-off host-to-device tensors (cached RHT signs, per-request BOS token, DCP rank and peer addresses built at init)
- `_aiter_ops.py`: wrap AITER's GDN prefill metadata builder, which syncs inside AITER
- `diffusion_gemma.py`: wrap the converged-logprobs stash in the decode loop (logprobs requests only; avoiding that per-step sync is left to the model owners)

With `VLLM_GPU_SYNC_CHECK=error` from #43107, each of these syncs raises "GPU<->CPU sync detected" on ROCm, and together they turned 16 AMD groups red in https://buildkite.com/vllm/amd-ci/builds/15532 and https://buildkite.com/vllm/ci/builds/97758. They went unnoticed because CUDA never takes these paths and AMD CI did not run with the check until #61939 moved its tests onto the test image. All but the diffusion one run once or only when cached state changes, and AITER's sync is out of tree, so they get the same treatment as the existing allowed syncs next to them; `git diff -w` is one `with` line per site plus imports. I ran the code of each site on an MI GPU under the real checker: all eight raise before and pass after.

Once #61939 merges, this PR will also turn the check on for AMD by setting `VLLM_GPU_SYNC_CHECK=error` in the ROCm test image again (#61939 leaves it off), so the wraps and the enablement land together.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
