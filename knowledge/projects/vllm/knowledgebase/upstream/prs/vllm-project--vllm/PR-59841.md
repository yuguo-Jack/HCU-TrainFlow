# [ROCm][CI/Build] Add fix for Distributed DP Basic with AITER always on.

[Upstream PR](https://github.com/vllm-project/vllm/pull/59841) · state: open · merged: False

## Original PR description



## Overview

This PR adds a change to the `v1/e2e/general/test_sharded_sampling.py::test_sharded_sampling_outputs_match` test so the `(MI355) Distributed DP Basic` test group passes with `VLLM_ROCM_USER_AITER=1`.

The test now checks if the `rocm_aiter_ops.is_tgemm_enabled `returns `True` and monkeypatches it to return `False` to prevent the problematic kernel from being used.  Please see details below.

## Claims

The test now passes with `VLLM_ROCM_USER_AITER=1` and `VLLM_ROCM_USER_AITER=0` (default).

## Validation

`pytest -v -s v1/e2e/general/test_sharded_sampling.py`

results in

`== 10 passed, 14 warnings in 50.66s ==`

`VLLM_ROCM_USER_AITER=1 pytest -v -s v1/e2e/general/test_sharded_sampling.py`

results in

`== 10 passed, 14 warnings in 48.37s ==`

## Details

The following failure was encountered when running this test group:

```
FAILED v1/e2e/general/test_sharded_sampling.py::test_sharded_sampling_outputs_match - RuntimeError: Test subprocess 'test_sharded_sampling_outputs_match' failed (exit code 1):
E               RuntimeError: Test subprocess 'test_sharded_sampling_outputs_match' failed (exit code 1):
E               Traceback (most recent call last):
E                 File "<string>", line 12, in <module>
E                 File "/vllm-bk-13642/tests/utils.py", line 1904, in wrapper
E                   return f(*args, **kwargs)
E                          ^^^^^^^^^^^^^^^^^^
E                 File "/vllm-bk-13642/tests/v1/e2e/general/test_sharded_sampling.py", line 246, in test_sharded_sampling_outputs_match
E                   assert not divergent, (
E                          ^^^^^^^^^^^^^
E               AssertionError: 4/16 completions diverged at (prompt, position) [(7, 23), (12, 8), (13, 7), (15, 13)]; the sampling modes did not agree token for token with in-process scheduling
```

with 

`VLLM_ROCM_USE_AITER=1 pytest -sv v1/e2e/general/test_sharded_sampling.py::test_sharded_sampling_outputs_match`

Upon investigation, the source of error was confirmed to be `aiter.tuned_gemm.tgemm.mm` for the.
following input `bf16` shapes:

* M=8, N=2048, K=4096
* M=70, N=2048, K=4096

The following issue https://github.com/ROCm/aiter/issues/6114 where `aiter.tuned_gemm.tgemm.mm` was filed. 

For these shapes, a reproducer was made and the kernel returned 20 different results on 20 different calls.  Furthermore, when compared against PyTorch CPU golden, the kernel differed with the golden on ~50% of all outputs and was 10x more inaccurate when compared with the PyTorch GPU implementation F.linear.
 
Please see the issue https://github.com/ROCm/aiter/issues/6114 for more details about this failure.

This modification can be removed when the issue has been resolved.

AI assistance was used to debug and create reproducer in the issue and verified by human.
