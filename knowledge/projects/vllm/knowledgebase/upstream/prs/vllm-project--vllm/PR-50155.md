# [Bugfix] Fix sequence-parallel detection for small decode batches

[Upstream PR](https://github.com/vllm-project/vllm/pull/50155) · state: open · merged: False

## Original PR description

> [!NOTE]
> This PR was drafted with the assistance of Claude Opus 4.6.

## Fix

Fixes #50154

### Problem

In `DeepseekV2DecoderLayer.forward()`, `input_is_sequence_parallel` is determined by:

```python
input_is_sequence_parallel = (
    self.use_sequence_parallel_moe
    and residual is not None
    and hidden_states.shape[0] != full_num_tokens
)
```

For small decode batches where `full_num_tokens < tp_world_size` (e.g. 1-3 tokens with TP=4), `reduce_scatter` produces `hidden_states` with the same size as `full_num_tokens` (since `ceil(n/4) == n` when `n < 4`). This makes the shape comparison `False` even when SP is active, so `residual` is never chunked — causing shape misalignment that accumulates garbage across layers.

### Fix

1. Add fallback: also detect SP when `full_num_tokens < tp_world_size`, since scatter is effectively a no-op in this case but SP state is still active.
2. Use `residual.shape[0] != hidden_states.shape[0]` for the residual chunking decision — more robust than relying on the boolean flag alone.

### Testing

- Aggregated deployment: TP=4, EP=4, DP=2, GLM-5.2-FP8 (744B), `--enforce-eager`
- Without fix: garbled output on all short prompts
- With fix: correct generation, gsm8k accuracy ~0.95

### Raw output comparison

**Before (garbled):**
```
"Paris. Paris Paris Paris Paris Paris the the most. Paris and Paris a Paris1140 and41.1,1.0."
```

**After (correct):**
```
"Paris. It is the largest city in France and the country's political, economic, cultural, and commercial center."
```
