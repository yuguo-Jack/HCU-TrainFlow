# [Doc] Document B300 disaggregated Dynamo serving for DeepSeek-V4.1-Flash / 记录 DeepSeek-V4.1-Flash 在 B300 上的 Dynamo 分离式部署

[Upstream PR](https://github.com/vllm-project/vllm/pull/62572) · state: closed · merged: False

## Original PR description

## Overview

Document the B300 disaggregated Dynamo + vLLM deployment of DeepSeek-V4.1-Flash from [InferenceX #4231](https://github.com/SemiAnalysisAI/InferenceX/pull/4231). Follow-up to #62534, whose Dynamo section defers disaggregated settings to Dynamo's examples; those examples do not cover this topology.

## Claims

- `pd_cluster` gains a `b300` hardware override and `b300: dep` pool parallelism: N two-GPU DEP2 prefill engines (four per node) and one DEP8 decode node, with the engine flags and EFA transport env (`FI_PROVIDER=efa`, `UCX_TLS` with `srd`, `NIXL_UCX_SGL_ENABLE=0`, cumem allocator off).
- Per-role B300 overrides: prefill scheduling (`--prefill-schedule-interval 2`, `--prefix-cache-retention-interval 32768`, 16384 batched tokens); decode `--enable-eplb` with 16 redundant experts over `symm_mem`, `VLLM_MAX_ASYNC_KV_ADMITS_PER_STEP=4`, graphs every six tokens.
- A short "Disaggregated serving on B300" guide subsection documents what the builder cannot express: the `push_as_nixl` connector on NIXL's `LIBFABRIC` backend, the prefill `MultiConnector` with `SimpleCPUOffloadConnector` (70 GiB host KV per rank), the libfabric install the image needs, and the sidecar and frontend flags.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <checkout>/recipes` from vllm-project/recipes: passed.
- Every new JSON argument and the guide's JSON block parse.
- Deployment evidence: InferenceX #4231 full sweep, [run 39015109057](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/39015109057), on the original DeepSeek-V4.1-Flash checkpoint and the `nightly-x86_64-dev-20261012-59e75f4` image. No new GPU validation for the 1017 checkpoint.

## Details

The B300 override block mirrors the GB300 one and differs where the hardware does: 8 GPUs per node (DEP8 decode on one node), EFA instead of NVLink between trays (LIBFABRIC backend, VMM allocator off because the EFA provider cannot register cumem memory), and a longer gloo timeout for the Engram shard load. The `--kv-transfer-config` JSON stays in the guide rather than `extra_args` because the strategy emits its own NixlConnector config and the two would collide.

AI assistance was used: Claude (claude-fable-5-1, via Claude Code) drafted the overrides and guide text from the author's validated recipe; the author reviewed and ran the validation.
