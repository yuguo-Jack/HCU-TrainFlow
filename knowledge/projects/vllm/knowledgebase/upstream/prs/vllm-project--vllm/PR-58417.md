# feat(parser): parser cache for streaming chat derender

[Upstream PR](https://github.com/vllm-project/vllm/pull/58417) · state: open · merged: False

## Original PR description

Part of #57571.

implements the parser cache on OnlineDerenderer for streaming chat derender to avoid redundant history replay on each chunk.

summary:
- in-memory lru parser cache directly on OnlineDerenderer instance keyed by (request_id, choice_index)
- cache entries store (parser, detok_state, chunk_count, timestamp)
- on cache hit with matching chunk count, reuses the parser and incremental detokenizer state directly and skips replay
- pops entry while in use; if parse_delta fails the entry is dropped
- finish chunks evict from cache, abandoned streams expire via ttl
- opt-in via `--parser-cache-size` with default 0 (off switch)
- added on/off parity and cache lifecycle unit tests + updated derenderer docs

tool call id changes have been pulled out for a separate pr as discussed.

cc @hickeyma

- hickeyma · CHANGES_REQUESTED · 2026-10-23T15:37:31Z · [source](https://github.com/vllm-project/vllm/pull/58417#pullrequestreview-5630660175)

Thanks for the update @devtyagi3909. This is looking better. The checkout/put back, finish eviction and off-by-default all look right, and caching `ChatStreamProcessor` now that #62706 is in makes sense.

The main things to fix for now:

- Hit check misses chunk boundaries. It compares how many chunks there are, not `output_chunk_lens`. Tokens `a b c` split as `[1, 2]` or `[2, 1]` both match but leave the parser in different states. Please compare the lens.
- Hit check only looks at `tools`. The cached processor keeps the request it was built with. This means a reused `request_id` with a different `tool_choice`, `include_reasoning` or `chat_template_kwargs` gets the old settings. This is @LinzeShi's point. As agreed in #57571, please store a blake2b digest of the full `chat_request`, `prompt_token_ids` and history (tokens and lens) and compare that. It also saves keeping full copies of the prompt and output in every entry.
- Tests can't catch a bad hit. `_FakeParser` keeps no state between calls, so the parity test passes whether the cache is right or wrong. Can you run the on/off comparison against a real parser? Parametrizing the `parser_server` fixture with `--parser-cache-size` should do it. Please also add the cases we agreed: a finish-only chunk, an eviction midstream, a retried chunk and different chunk boundaries over the same tokens.
- Docs. "O(n) to O(1)" isn't right because `parse_delta` and the hit check are still O(n). Please add the routing note we agreed (route on `request_id`, hit rate is about 1/(replicas × API servers)) and a rough memory estimate per entry.

There are a few smaller things too, like the TTL having no flag and some duplicated code but those can wait until the above is in.

- hickeyma · CHANGES_REQUESTED · 2026-11-02T16:57:58Z · [source](https://github.com/vllm-project/vllm/pull/58417#pullrequestreview-5740182524)

Thanks @devtyagi3909 for the updates. Most of this is in good shape now. The digest covers chunk lens and the full request, entries no longer hold token copies and the docs are getting there.

One blocker though. As written, the cache never hits for a user. `ChatCompletionRequest.request_id` defaults to `random_uuid` and `/derender` validates a new `chat_request` from the body of each chunk. So unless the user adds `request_id` to `chat_request` (the docs example doesn't), `model_dump_json()` differs on every chunk and the digest never matches. With the flag on you get full replay plus two digests per chunk. Validating the same JSON twice shows `request_id` is the only field that differs which means `model_dump_json(exclude={"request_id"})` should fix it.

The tests don't catch this because the unit tests reuse one request object and the `parser_server` cases never hit. `parser_server` suggestion isn't enough (my bad)  without checking for hits. Please add:

- A test that runs `ChatCompletionRequest.model_validate(body)` per chunk and counts `parse_delta` calls
- on/off parity with a real or stateful parser on actual hits, including a multi-byte character split across a cached boundary
- Real assertions in the tests that pass on a hit or a miss. `test_reused_request_id_with_different_settings_misses_cache`, `test_retried_chunk_safely_replays`, the TTL test (patch `time.monotonic` rather than sleep)
