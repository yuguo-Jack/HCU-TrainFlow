# [CI] Expect 400 from /v1/embeddings for bge-m3 token_embed

[Upstream PR](https://github.com/vllm-project/vllm/pull/63067) · state: closed · merged: True

## Original PR description

## Problem

`test_bge_m3_api_server_embedding[token_embed]` fails on both AMD and NVIDIA with `openai.BadRequestError: Error code: 400 ... 'loc': 'body.encoding_format', 'msg': "Input should be 'float'", 'input': 'base64'`. It is the only failure in both `Language Models (Extended Pooling)` steps of nightly 96581.

AMD: https://buildkite.com/vllm/ci/builds/96581/list?sid=01a16238-14cb-410a-ab01-df25ca5154c3
NVIDIA: https://buildkite.com/vllm/ci/builds/96581/list?sid=01a16238-1564-453c-9761-954f5e42564f

## Cause

#61772 made the `token_embed` task serve `/v1/embeddings` itself through `TokenEmbeddingRequest`, which accepts only `encoding_format="float"`. That restriction is intentional, and the same PR asserts in `test_factories.py` that `base64` on this route returns 400.

The OpenAI client sends `encoding_format="base64"` by default, so for `token_embed` the request is now rejected at validation with 400 instead of reaching the old 500. The bge-m3 test still expected `InternalServerError` for every non-`embed` task.

## Fix

Expect `BadRequestError` for `token_embed` and keep `InternalServerError` for `token_classify`, which still behaves as before. The server is not changed.

## Test plan

`pytest -v -s models/language/pooling/test_bge_m3.py::test_bge_m3_api_server_embedding` passes for `embed`, `token_embed` and `token_classify` on MI300X.
