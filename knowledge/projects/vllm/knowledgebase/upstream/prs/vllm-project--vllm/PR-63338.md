# [CPU] Skip multimodal encoder profiling when the KV cache size is explicit

[Upstream PR](https://github.com/vllm-project/vllm/pull/63338) · state: open · merged: False

## Original PR description

## Purpose

On CPU, `profile_run` sends one maximum-size image through the vision encoder (`encoder_runner.profile_encoder_cache`). The only consumer of that measurement is the automatic KV-cache sizing in `determine_available_memory`, which reads
the worker's RSS after warmup. When the KV cache size is given explicitly -- via `VLLM_CPU_KVCACHE_SPACE` or `--kv-cache-memory-bytes` -- that branch is bypassed entirely, so the encoder pass is pure startup cost. On a 32-core Turin cpuset it
takes over four minutes for Qwen3.5-4B.

`skip_mm_profiling` already exists for exactly this trade-off; this sets it on CPU when the KV cache size is explicit, next to where `CpuPlatform` already reads `VLLM_CPU_KVCACHE_SPACE`. GPU is unchanged, and a user who sets `--skip-mm-profiling` themselves is unaffected.

The pass is kept when `compile_mm_encoder` is enabled, since there it also compiles the encoder at startup rather than only measuring memory. The per-batch `sanity_check_mm_encoder_outputs` is unaffected: it runs inside `execute_mm_encoder` on every real request, not only during profiling.

## Test Plan

Qwen3.5-4B, bf16, V2 model runner, one 32-core AMD EPYC Turin cpuset on a single NUMA node, `VLLM_CPU_KVCACHE_SPACE=8`, cold vLLM and Triton caches per arm. Each arm measures engine init, then sends the same 512x512 four-quadrant image twice and asks the model to name the colors.

```bash
VLLM_USE_V2_MODEL_RUNNER=1 VLLM_CPU_KVCACHE_SPACE=8 \
VLLM_CPU_OMP_THREADS_BIND=<32 cores> python mm_check.py --model Qwen/Qwen3.5-4B
```

## Test Result

| | engine init | 1st image request | 2nd image request |
| --- | --- | --- | --- |
| main | 441.8 s | 7.71 s | 2.98 s |
| this PR | 175.3 s | 3.97 s | 2.98 s |

Startup drops by 266 s (-60%). Both arms return identical text, and the first image request gets faster rather than paying the deferred cost, since the encoder compile it used to do at startup is smaller for a real image than for the maximum-size dummy one.
