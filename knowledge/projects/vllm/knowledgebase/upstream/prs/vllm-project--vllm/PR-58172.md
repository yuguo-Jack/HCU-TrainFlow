# [BugFix] Memoize StreamingParserEngine drop-info construction

[Upstream PR](https://github.com/vllm-project/vllm/pull/58172) · state: closed · merged: False

## Original PR description

## Purpose

Mistral's always-on `adjust_request` path rebuilds `StreamingParserEngine` per request (including `tool_choice="none"`). `_build_drop_info` recompiles regex over the full special-token vocab on the asyncio main loop, which becomes an admission bottleneck under concurrency.

Memoize `_build_drop_info` with a bounded LRU keyed by `(id(config), id(tokenizer))`. Config factories are typically `@functools.cache`'d and the serving tokenizer is long-lived; shared `_DropInfo` is read-only while per-request lexer/scanner state stays on each engine instance.
