# [Bugfix][Multimodal] Release consumed MRV2 CPU inputs

[Upstream PR](https://github.com/vllm-project/vllm/pull/57368) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Release consumed request-local CPU multimodal payloads from MRV2 workers while requests are still decoding. This extends #52041's prefix-hit stripping to inputs that actually reached a worker, while retaining EngineCore replay data and GPU embeddings.

## Claims

- Release each occurrence only after its placeholder range is confirmed consumed; exclude in-flight prefill, unconfirmed output placeholders and inputs being encoded in the same step.
- Restore payloads when KV-load rollback schedules encoding again, including inputs initially stripped by a prefix hit. Preemption and streaming request installation rebuild tracking.
- Keep SHM processor-cache descriptors on their existing ACK protocol. MRV1 and encoder embedding eviction are unchanged.

Current-revision host-memory A/B (Qwen3-VL-4B-Instruct, MRV2, TP=2, physical H200 GPUs 0/2): 16 distinct 1536px image requests arriving in two waves of 8, each generating 128 tokens. Each configuration/arm had two independent engine starts with reversed arm order on the second start, one warmup and three formal rounds per start. PSS sums the driver/EngineCore and its worker process tree, avoiding shared-page double counting. Means below use snapshots with all 16 requests alive and each having generated at least 8, 32 and 64 tokens.

| Configuration | Main decode PSS | Patch decode PSS | Reduction |
| --- | --- | --- | --- |
| Default 4 GiB LRU processor cache, arena off | 6.950 GiB | 6.567 GiB | 393.0 MiB / 5.52% |
| Processor cache off, arena off | 6.733 GiB | 6.303 GiB | 440.7 MiB / 6.39% |
| Processor cache off, arena on | 8.493 GiB | 8.131 GiB | 370.1 MiB / 4.26% |

Worker request-cache input references fell from approximately 216 MiB per rank to zero in all cases. With the arena enabled, slot-exhaustion fallbacks fell from 8 to 0 per round; all 8 slots became reusable while requests were still alive. The arena's 2 GiB pinned mapping remains allocated, so this is slot reuse, not unmapping the arena. In this small workload, the arena's fixed mapping also makes its absolute PSS larger than the arena-off configuration.

Corresponding output token IDs matched for all 576 formal requests across the three configurations, with 128 tokens per request. The two independent-start PSS reductions with default LRU caching were 402.0 and 383.9 MiB. These are workload-specific decode-residency measurements, not universal percentages or exact prefill peaks. The driver and EngineCore share a process in this harness; workers use the real multiprocess TP executor. Configuration: eager, max model length 4096, batched tokens 2048, sequences 16, GPU memory utilization 0.20, seed 0, prefix caching enabled with distinct inputs, NVLS disabled equally on both arms, and GPU sync checking enabled. No allocator trimming or production-code instrumentation was used. EngineCore replay inputs and its LRU cache are still retained.

No throughput speedup or full accuracy result is claimed for this revision. KV-load failure restoration is covered by CPU scheduler/worker tests, not a distributed KV-transfer model run.

## Details

A single `SchedulerOutput.encoder_input_updates` map carries payload replacement by request ID and input index: `None` releases an input; a payload restores it. An index has one update per step, avoiding separate restore/free ordering. The scheduler tracks only remaining releasable inputs and stops scanning once none remain.

Workers apply updates after request installation and RoPE position initialization. Replacing entries in a worker-owned list preserves EngineCore's original feature objects, including with the uniprocess executor. The same placeholder metadata remains available for embedding gathering and PrefixLM ranges.

Related work and scope:

- #52041/#53456 handle stripping before initial position computation. This patch releases after that initialization and does not change their metadata rules.
- #54994 preserves SHM address references; those descriptors remain excluded here.
- #51207 shares transport storage. It does not release request-local references, and its slots cannot be reused until their storage references are dropped. This PR adds no COW or other transport.
- #62834 checks remote encoder embedding readiness during EPD replay; it does not restore a local worker's raw inputs for re-encoding.
- Open #50871 clears EngineCore inputs for resumable sessions. This patch requires retained EngineCore payloads for rollback; combining the two requires an explicit replay policy.
- #56813 caches position ranges, which this patch does not change; #56826/#62850 optimize other cache cleanup. None implements this running-request payload lifecycle.

No user-facing configuration or behavior contract is added, so no separate design document is introduced. AI assistance was used for implementation, upstream comparison, review and validation.

Thanks for the thorough work — the lifetime analysis and the B200 validation are impressive. One process-level request: could you split this into two PRs?

1. **Early release of consumed MRV2 CPU inputs** — the scheduler/worker release protocol: `scheduler.py` (consumption boundary + reload detection + tracking resets), `sched/output.py` (the two new `SchedulerOutput` fields), `worker/gpu/mm/encoder_cache.py`, `worker/gpu/model_runner.py`, plus the scheduler/encoder-runner tests.
2. **Node-local shared storage** — the COW file-backed transport: `shared_tensor.py`, `shm_broadcast.py`, `multiproc_executor.py`, `envs.py` (`VLLM_MM_INPUT_SHARED_STORAGE_PATH`), and the shm_broadcast tests.

Rationale: the two mechanisms are independently useful and carry different risk profiles. (1) is a correctness-of-lifetime change on the hot scheduling path that reviewers need to scrutinize line by line; (2) is an opt-in transport feature with POSIX-lease subtleties. Splitting makes each reviewable and revertable on its own — and (1) can likely land much faster without the transport design discussion (e.g. the acknowledged overlap with #51207) gating it.
