# [Perf][Model] Cohere2MoE: attention/MoE dual stream, single TP all-reduce per layer, fused add + RMSNorm

[Upstream PR](https://github.com/vllm-project/vllm/pull/62101) · state: open · merged: False

## Original PR description



## Overview

This PR makes Cohere2MoE decode **1.14–1.36× faster** (TPOT) on CohereLabs/North-Mini-Code-1.0, with no accuracy change. Measured on the bf16, FP8, and W4A16 checkpoints at TP2 on H100.

Cohere2MoE layers are parallel blocks: attention and the MLP/MoE read the same normed input, and their outputs are summed. The PR makes three changes to that block:
- **Attention/MoE dual stream** (`VLLM_COHERE2_ATTN_MOE_DUAL_STREAM=1`). During decode, the MLP/MoE runs on a side CUDA stream, overlapping with attention. This accounts for nearly all of the speedup.
- **Single TP all-reduce per layer.** Attention and the MLP are reduced together instead of separately. At TP > 1, the dual stream relies on this: the layer's only collective then runs after the join, so no all-reduce runs on the side stream alongside the main-stream one.
- **vLLM fused add + RMSNorm.** It lets the existing `allreduce_rms` pass fuse that all-reduce with the next layer's norm.

The changes are confined to `cohere2_moe.py`, plus two env vars. Related: #61508 (`swiglu_limit`) edits the MLP/MoE constructors and does not overlap with this PR.

## Claims

- **Dual stream:** decode TPOT improves by 1.14–1.36× across the bf16, FP8, and W4A16 checkpoints at concurrency 1–64.
- **Default path (dual stream off):** up to 1.05× from the single all-reduce and the `allreduce_rms` fusion. The pass goes from `Replaced 0 patterns` to `Replaced 1 patterns` in every compiled subgraph.
- **No quality change:** gsm8k stays within noise. Speculative decoding acceptance is unchanged with both the EAGLE and Eagle3 drafts.
- **No new GPU→CPU syncs:** every dual-stream run passes with `VLLM_GPU_SYNC_CHECK=error`.

## Details

**Dual stream.** The MLP/MoE is wrapped in two custom ops, `vllm::cohere2_mlp_fork` and `vllm::cohere2_mlp_join`. They find the layer through the forward context, so Dynamo keeps the stream switch while attention stays the piecewise splitting op.
- Fork runs the MLP on a dedicated side stream. It is separate from `aux_stream()`, which FusedMoE already uses for the shared-expert overlap.
- Join makes the main stream wait for the side stream before the layer's single all-reduce.
- The MLP runs inline instead in these cases:
  - batches above `VLLM_COHERE2_ATTN_MOE_DUAL_STREAM_TOKEN_THRESHOLD` (default 256);
  - piecewise CUDA graphs, i.e. prefill and mixed batches, since a fork cannot span a graph boundary;
  - breakable CUDA graph capture.

  In practice, the overlap covers full CUDA graph decode and small eager batches.
- The flag is ignored with a warning in these cases:
  - MoE layers that reduce internally under TP;
  - EP all2all MoE;
  - microbatching (DBO), because each layer keeps a single fork/join state;
  - non-CUDA platforms.

**Single all-reduce.** Both branches of the parallel block end in row-parallel partial sums, so a single `all_reduce(attn + mlp)` is equivalent to reducing them separately.
- `o_proj` and the dense MLP now return unreduced outputs.
- A routed-only MoE passes `reduce_results=False` to `FusedMoEFactory` at TP > 1. When FusedMoE has to reduce internally anyway (EP all2all, sequence parallel), `Cohere2Moe.output_is_reduced` records that, and the decoder then reduces only attention.
- MoE layers with shared experts keep their existing internal reduction.

**Fused add + RMSNorm.** The model-local torch `RMSNorm` is replaced with vLLM's `RMSNorm`, using the same residual flow as Llama.
- Each layer returns its reduced block output and the residual separately; the next layer's norm (or the final norm) adds them.
- Eagle3 aux states add the residual back via `EagleModelMixin._maybe_add_hidden_state`.
- The first layer's residual is the embedding tensor itself, and the fused norm updates the residual in place. So the start-layer aux capture is cloned, only when that layer is captured.
- Checkpoints that use Cohere's LayerNorm keep the old flow.

**Limitations**
- The token threshold was tuned without speculative decoding. With speculation, each request adds `1 + k` tokens per step, so the threshold is reached at lower concurrency.

These changes are ported from Cohere's vLLM fork and adapted to current upstream. AI assistance was used in preparing this PR.
