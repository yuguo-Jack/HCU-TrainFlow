# [Bugfix] Handle unused scatter-split outputs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62399) · state: open · merged: False

## Original PR description



## Overview

Avoid `KeyError` in `ScatterSplitReplacementPass` when dead-code elimination removes unused outputs of the post-scatter split.

## Claims

- Replace or redirect only the Q/K/V outputs that still exist, without disabling the optimization.
- Extend the existing compiler regression test to cover all outputs, Q only, K only, and Q+K in FP16 and BF16. Numerical parity and scatter-removal assertions remain in place.

## Validation

Native B300 validation with Torch 2.14.0+cu130: the original pass fails 6 of the 8 cases with `KeyError`; the patched pass passes all 8. The two original all-output cases pass in both arms. Both arms use the same tests and normal project fixtures, real `TestBackend`, `RotaryEmbedding`, and Inductor.

Reproduce with:

```bash
uv run --no-project --python .venv/bin/python python -m pytest \
  tests/compile/passes/test_scatter_split_replace.py -q
```

The native run used a full vLLM `ff01a6b14` package/runtime with the exact pass and test overlaid in separate fresh processes. The original affected files are unchanged through checked main `3788269c98`; this is not a full current-main wheel/build, all-backend, or whole-model qualification. The same 20 dependency/collection warnings occur in both arms. No performance claim.

Ruff check/format and typos hooks pass. The repository's test-tethering, SPDX, root-import, forbidden-import, CUDA-call, config, and boolean-context-manager checks also pass. Full pre-commit and mypy remain unverified: Windows application control blocks newly generated hook-environment interpreters during setup. No protection was disabled. Official CI is still needed.

## Details

The pass builds `split_getitem_users` from the split's surviving users, but previously indexed keys 0, 1, and 2 unconditionally. Guarding each corresponding replacement handles unused outputs while preserving the original rewrite for live outputs. This does not change RoPE math, kernels, configuration, or the pass's matching conditions; it does not claim to handle every partial RoPE graph.

Duplicate checks found no matching open fix (`"scatter_split"`, open scatter titles, and open split/KeyError searches). Related #58838 ports RoPE to IR and does not modify this pass or its test; #57299 is already merged and does not contain this guard.

AI assistance was used. The human submitter reviewed the complete two-file diff and the validation results.
