# [Bug] fix: LLM.__repr__ handles non-torch worker models (#61366)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61414) · state: open · merged: False

## Original PR description

## Summary

Closes #61366.

`format_model_inspection()` previously assumed every worker's `get_model()` returns a `torch.nn.Module` and immediately descended into `named_children()` traversal. Non-torch worker backends (e.g. alternative runtime backends) trigger an `AttributeError` on `LLM.__repr__` because their model handle lacks torch-specific attributes.

## Change

Add an `isinstance(model, nn.Module)` guard at the top of `format_model_inspection()` and fall back to `repr(model)` for non-torch handles. The call sites (`Worker.get_model_inspection` and `LLM.__repr__`) already handle any string return value.

## Testing

- Static: syntax check passes (`ast.parse`).
- The change is purely defensive: it widens the accepted input contract without altering the torch path.
- No GPU environment was available to run vLLM's own test suite in this sandbox.
