# [Rust Frontend] Separate DeepSeek V4 content blocks like deepseek-recipe

[Upstream PR](https://github.com/vllm-project/vllm/pull/63762) · state: closed · merged: True

## Original PR description

## Overview

When a chat message carries its content as a list of blocks, the Rust DeepSeek V4 renderer concatenates the text blocks with no separator, and V4.1 concatenates assistant text blocks. The reference implementation, [deepseek-ai/deepseek-recipe](https://github.com/deepseek-ai/deepseek-recipe), joins the content blocks of every role with `"\n\n"` for both V4 and V4.1. This PR does the same in the Rust renderer.

## Claims

- V4 and V4.1 join list-form content blocks with a blank line for system, user, developer, assistant and tool-result messages, matching deepseek-recipe.
- String content, and list content with a single block, render exactly as before.

- `deepseek_v4::tests::content_parts_are_joined_by_a_blank_line_for_every_role`: two-block system, user, assistant (text plus a tool call), tool-result and follow-up user content. The snapshot matches what the recipe produces for the same messages.
- `deepseek_v41::tests::joins_assistant_text_parts_with_reference_separator`: assistant text blocks on V4.1.
- Both fail with the `deepseek.rs` change reverted.

## Details

Reference behavior (deepseek-recipe `935817c66f`): `ChatCompletionRequestContent::into_content` (`deepseek-recipe/src/protocol/openai/chat_completion/request/convert.rs:291-357`) maps each text block to its text and each image block to the image token, then returns `Prompt::join(&contents, "\n\n")`. `transform_messages` uses it for system, user, assistant and tool-result messages, and the V4/V4.1 encoders insert the joined content as is (`push_assistant_content`, `<tool_result>{content}</tool_result>`). The encoders' blank line between separate messages is already handled in Rust and unchanged.

Changes, all in `rust/src/chat/src/renderer/deepseek.rs` (shared by V4 and V4.1):

- `write_chat_content` inserts `"\n\n"` between content parts for both dialects; before, only V4.1 did. V4 image parts still return the existing unsupported-multimodal 400.
- `write_assistant_text` joins assistant text blocks with `"\n\n"` for both dialects. The server lowers each text part of an assistant message into its own `AssistantContentBlock::Text`, so this is where the recipe's assistant join belongs.

Block flattening is a model-template concern, so the fix stays in the model renderer rather than in shared request preparation. The V3.2 encoder has its own `write_assistant_text` and is not affected.

Difference from the Python renderer: Python's `parse_chat_messages` flattens text-only tool-result content with a single newline before encoding. This PR follows the recipe (a blank line) instead.

Not a duplicate: open DeepSeek V4 renderer PRs (vllm-project/vllm#62189, vllm-project/vllm#63497) change turn structure and developer instructions, not content-block joining.
