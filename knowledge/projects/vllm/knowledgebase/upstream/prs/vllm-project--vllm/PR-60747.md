# [Bugfix][Tool Parser] Use LongCat tags in the LongCat structural tag

[Upstream PR](https://github.com/vllm-project/vllm/pull/60747) · state: closed · merged: True

## Original PR description



## Overview

With strict tool calling, forced tool calls on LongCat come back as plain text. The LongCat parser inherits the Hermes structural tag, so the grammar forces `<tool_call>` tags that the LongCat parser does not recognize. This registers a `longcat` structural tag that uses LongCat's own `<longcat_tool_call>` delimiters. The bug dates from #45003, which gave Hermes a structural tag.

## Claims

- `tool_choice="required"` and named tool choice with `--tool-call-parser longcat` now return parsed `tool_calls` instead of raw tag text in `content`.
- The Hermes structural tag output is unchanged.

## Validation

Unit test `test_longcat_forced_tool_choice_round_trips_native_tags` in `tests/tool_parsers/test_structural_tag_registry.py` builds the forced grammar for the LongCat parser and checks that output in LongCat's native tags is accepted. It fails on main (2 failed: the grammar rejects the native tags) and passes with this change.

```bash
pytest tests/tool_parsers/test_structural_tag_registry.py tests/tool_parsers/test_longcat_tool_parser.py tests/tool_parsers/test_hermes_tool_parser.py
# 313 passed, 1 skipped, 1 xfailed
```

End to end, `vllm serve Qwen/Qwen2.5-0.5B-Instruct --enable-auto-tool-choice --tool-call-parser longcat` with `tool_choice="required"`:

| | main | this PR |
|---|---|---|
| `tool_calls` | FILL IN | FILL IN |
| `content` | FILL IN | FILL IN |

A small model stands in for LongCat-Flash, because the structural tag decides the output format whatever the model is.

## Details

- `_hermes_tool_tags` now takes the start and end tag, and the shared body moved into `_hermes_style_structural_tag`. `hermes` and the new `longcat` tag both call it, so no grammar logic is duplicated.
- The delimiters match the official LongCat-Flash chat template.
- Not a duplicate: PR searches for "longcat tool", "structural_tag_model inherit" and issue searches for "longcat tool_call" and "longcat required" found no fix or report. Open PR #51937 (Hermes parser migration) rewrites the LongCat adapter but keeps `structural_tag_model = "hermes"`, so it keeps this bug. If #51937 lands first, its LongCat adapter needs the same one-line setting.
- AI assistance was used to find the bug, write the fix and the test, and draft this description. I reviewed every changed line and ran the tests above.
