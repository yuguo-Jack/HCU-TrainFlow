# [Quantization][MoE] Keep MXFP4 expert scales compressed on B12X

[Upstream PR](https://github.com/vllm-project/vllm/pull/65240) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

This PR adds an opt-in mode to the b12x MoE backend: `VLLM_B12X_MOE_MXFP4_CSF=1`. In this mode, eligible W4A8 MXFP4 layers keep their E8M0 block scales in a compressed scale format (CSF) in GPU memory. On GLM-5.3-Flash with TP2, each rank uses 3.53 GiB less memory, and the KV cache holds 30.6% more tokens.

Depends on #65233. The first two commits are that PR. Review only the last commit.

## Claims

- When the switch is off, vLLM does not change.
- The mode uses the pinned `flashinfer-python==0.7.2.post1`. No new dependency is necessary.
- Ineligible layers keep uncompressed scales, and vLLM shows a warning.

## Validation

GLM-5.3-Flash, mixed MXFP4, TP2 on two DGX Spark nodes (GB10, SM121). Decode: 1,024 input and 256 output tokens. GSM8K: first 256 questions, 5-shot, temperature 0.

| | Switch off | Switch on |
| --- | ---: | ---: |
| Model memory per rank | 83.55 GiB | 80.02 GiB |
| KV cache | 629,418 tokens | 821,930 tokens |
| Output tokens/s, concurrency 1 / 4 / 8 | 16.32 / 43.48 / 63.76 | 16.22 / 42.09 / 61.21 |
| GSM8K | 247 / 256 | 248 / 256 |

`pytest tests/kernels/moe/test_b12x.py` passes on GB10. New tests cover the encoder, the eligibility rules, scale and output equality with uncompressed layers, and generation through `vllm_runner`.

## Details

- vLLM encodes the scales at load (`quantization/utils/mxfp4_csf.py`). The checkpoint does not change.
- FlashInfer expands the scales of the routed experts into one shared buffer per layer shape before each call. This costs 3% to 4% throughput at concurrency 4 and 8 with the pinned version. The b12x backend does not support expert parallelism or all-to-all kernels, so the layers run one at a time.
- With the switch on, all eligible layers use the prepared execution path of FlashInfer. GLM-5.3-Flash at TP2 (per-rank intermediate size 512) uses this path.
- Eligibility: gated SiLU experts, MXFP8 activations, hidden size a multiple of 256 (at most 7936), per-rank intermediate size a multiple of 64 (at most 8128). Intermediate sizes of 64 modulo 128 also need BF16 input.
- Weight reloading is not supported in this mode.

Replaces #64828, which depended on other open PRs.
