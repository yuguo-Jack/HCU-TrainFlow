# [EPLB] Support heterogeneous DeepSeek V4/V4.1 DSpark draft experts

[Upstream PR](https://github.com/vllm-project/vllm/pull/61395) · state: open · merged: False

## Original PR description

## Overview
Follow-up of #57549

Enable EPLB for DeepSeek V4 and V4.1 DSpark drafts when their expert topology differs from the target model.
This PR covers DSpark’s draft model loader.
Related: [#59611](https://github.com/vllm-project/vllm/pull/59611) fixes redundant expert loading in the target model. 


## Claims

- Register supported DSpark draft MoE models with the target’s EPLB state.
- Allow target and draft models to have different expert counts and topologies. Reduce load statistics for all registered models in one collective, including when their physical expert counts differ.
- Include redundant expert slots in the V4.1 DSpark fused-MoE weight mapping.

## Validation
- CPU-runnable pytest subset:.
- Add coverage for heterogeneous topology handling, EPLB registration, and DSpark redundant-slot mapping.

## Details

The target and DSpark draft can have different routed and physical expert counts. EPLB state now keeps topology-dependent counts per registered model and handles load-stat reductions when models have different physical expert dimensions.

DSpark’s custom weight loader is a separate call path from the target model’s `get_expert_mapping`. Since DSpark is now registered with EPLB, its redundant physical slots must also receive the replicated expert weights. #59611 addresses the target model’s mapping; end-to-end use with redundant experts requires that fix as well.
