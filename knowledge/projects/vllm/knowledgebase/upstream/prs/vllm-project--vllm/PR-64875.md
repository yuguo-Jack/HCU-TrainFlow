# [Bugfix][Prefix] Skip EAGLE block drop for KV-shared drafters + widen periodic SWA tail

[Upstream PR](https://github.com/vllm-project/vllm/pull/64875) · state: open · merged: False

## Original PR description

## Purpose

Fixes #64808

When EAGLE/MTP is enabled with KV-shared drafters (e.g. Gemma-4 MTP with
num_kv_shared_layers), the prefix-cache hit rate on shared-prefix workloads
drops by ~40% (17.1% -> 10.1%), and the second request in a 16K-prefix
workload hits only 8192 tokens instead of 16384.

## Root causes

There are two independent bugs:

### 1. EAGLE block drop triggered for Q-only drafters

 returns True for all eagle-style methods including
. The drop exists because the draft model writes its own KV
whose last block depends on the next token. But Gemma-4 MTP is Q-only: its
drafter shares KV with the target (num_kv_shared_layers) and writes no
independent draft KV group. The coordinator then fell back to flagging ALL
KV groups as eagle when no group was annotated as a draft group, causing
the trailing-block drop to discard valid target KV.

**Fix**: when  is on but no KV group is flagged as
an eagle group, skip the drop entirely and warn instead of silently
flagging all groups. Models that truly own draft KV layers mark them with
 during planning.

### 2. EAGLE periodic SWA checkpoint unreachable by siblings

 uses  under EAGLE,
placing the periodic segment tail so its peek block sits past the alignment
boundary. A sibling that diverges at that boundary cannot use the peek
block, so its hit lands one block lower — but the periodic-segment path
did not widen the tail to cover that lower hit. The sibling fell back a
whole retention interval (8192) instead of using the cached tail.

This mirrors the existing shared-prefix junction fix (#62278/#62206).

**Fix**: widen the periodic tail by one block when  is on.

## Benchmark

From the issue author (B300, FP8 KV, 32 GiB KV, 96x16K shared-prefix workload,
retention_interval=8192):

| Config | Hit rate | Req 1/2/3/4 cached tokens |
|---|---|---|
| MTP=0 (baseline) | 17.1% | 0 / 16384 / 16384 / 16384 |
| MTP=3 (before) | 10.1% | 0 / **8192** / 16256 / 16256 |
| MTP=3 + this PR | 15.6-16.5% | 0 / **16384** / 16384 / 16384 |

Greedy outputs are identical to MTP=0 (14/14 match).
