# [Rust Frontend] Keep load_inplace off cached LoRA requests like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/63316) · state: closed · merged: True

## Original PR description

## Overview

`POST /v1/load_lora_adapter` with `"load_inplace": true` makes the Rust frontend cache the request with `load_inplace=true`, so every later generate request for that adapter carries the flag and the engine reloads the adapter from disk on each step. Python clears the flag before caching (vllm-project/vllm#41482). This PR registers loaded adapters as their own type, so per-load options never reach generate requests.

## Claims

- After an in-place reload, chat, completions, `/inference/v1/generate`, and gRPC generate requests for the adapter carry `load_inplace=false`; the reload itself still sends `load_inplace=true` to `add_lora`.
- `/v1/models`, the gRPC adapter listing, and load/unload results are unchanged.

It fails on the base at the generate-request assertion.

## Details

The engine's `WorkerLoRAManager.add_adapter` (`vllm/lora/worker_manager.py`) reloads an adapter whenever the request it is activated for carries `load_inplace`, and adapters are activated for every scheduled step. So the flag belongs to the `add_lora` call only.

`LoraManager` used to store the `LoraRequest` it sent to `add_lora`, and every generate path copied it through `LoraModelResolution.lora_request`. It now stores a `LoadedLora` with what identifies the adapter (name, id, path, base model name, 3D-weight flag), and `LoadedLora::to_request` builds the engine request with every per-load option at its default. Only `register` sets `load_inplace`, on the `add_lora` request itself, so an operational field added to `LoraRequest` later cannot leak into generate requests through the registry either.

Related open PRs:

- vllm-project/vllm#63295 drops `tensorizer_config_dict` from `LoraRequest` and removes it from the request built in `register`. Whichever merges second needs one mechanical change: drop `tensorizer_config_dict: None` from `LoadedLora::to_request`.
- vllm-project/vllm#60222 changes failed-load cleanup in the same file; it does not touch the cached flag.

Not a duplicate: no open PR changes how the Rust LoRA registry caches requests.
