# [Kernel] Register the cudnn backend for FlashInfer BF16 mm

[Upstream PR](https://github.com/vllm-project/vllm/pull/59025) · state: open · merged: False

## Original PR description

## Purpose

Only the cute-dsl backend is wired up for unquantized BF16 linear layers, and it is restricted to sm_10x. That restriction is correct for cute-dsl (FlashInfer raises `BackendSupportedError` for it on sm_120), but `mm_bf16` also has a cudnn backend that runs there, so consumer Blackwell (sm_120/121) currently has no FlashInfer path for unquantized BF16 at all.

## Changes

Splits the shape/layout checks out of the cute-dsl predicate into a shared `_bf16_mm_shape_supported`, keeps the sm_10x gate on cute-dsl alone, and registers a new `flashinfer_cudnn` entry in `_FLASHINFER_BF16_BACKENDS`. The cudnn path is bounded by output width (`N <= 128`): swept on GB10 (sm_121, K=5120), FlashInfer wins 5-6x at `N<=128` and loses 2-4x at `N=512`, so diverting every unquantized GEMM would be a net loss on a model with a mix of widths.

```
        M=1    M=2    M=4    M=8   M=16   M=32
  N=96  1.09   6.14   6.15   1.26   1.28   1.20
 N=128  1.01   5.38   1.26   1.35   1.42   1.51
 N=192  0.85   4.31   1.17   1.26   1.38   1.31
 N=256  1.14   1.38   1.26   1.37   0.89   0.96
 N=512  0.27   0.37   0.41   0.53   0.63   0.75
```
(cuBLAS_us / flashinfer_us, >1 means FlashInfer wins)

Selection is unchanged by default; this only makes `--linear-backend flashinfer_cudnn` usable for BF16, which was already an accepted `LinearBackend` value for NVFP4.

## Relationship to other open work

This generalizes the win a GDN-specific custom op (routing `in_proj_ba` to FlashInfer, #57318) was chasing for one projection. `in_proj_ba`'s output width (`2 * num_v_heads`) is `<= 96` for every shipped Qwen GDN model, so it qualifies for this path automatically via `--linear-backend flashinfer_cudnn` (or `--unquantized-linear-backend flashinfer_cudnn` from #59021) — no GDN-specific routing code needed. Once this lands, #57318's bespoke custom op can likely be simplified or dropped in favor of this general path.

## Test plan

- `python -c "import ast; ast.parse(open('vllm/model_executor/layers/utils.py').read())"` — parses cleanly.
- Selection unchanged by default (`linear_backend` unset continues to resolve to `default_unquantized_gemm`); the new `flashinfer_cudnn` entry is only reachable when explicitly requested.
