# [Bugfix][Multimodal] Return 400 for corrupt audio that libsndfile recognises

[Upstream PR](https://github.com/vllm-project/vllm/pull/64337) · state: open · merged: False

## Original PR description

## Overview

Return HTTP 400, not 500, when a chat request carries corrupt audio that libsndfile recognises (for example a truncated WAV).

## Claims

- A truncated or otherwise corrupt-but-recognised `input_audio` / `audio_url` now maps to a 400, as the PyAV path already does.

## Validation

`pytest --noconftest tests/multimodal/media/test_audio.py::test_audio_media_io_rejects_truncated_wav_as_value_error` (CPU, no GPU needed): fails before (`soundfile.LibsndfileError`), passes after. A 30-byte WAV reproduced the 500 through `MediaConnector.fetch_audio` and `create_error_response`. `ruff check` and `ruff format` are clean.

## Details

In `load_audio`, `except soundfile.LibsndfileError` re-raises any code outside `{0, 1, 3, 4}`. A truncated WAV gives code 71 ("No 'data' chunk marker"), and `LibsndfileError` is a `RuntimeError`, so it maps to 500. The branch now raises `ValueError("Invalid or corrupted audio data...") from exc`, like the PyAV branch. The transcription endpoint already wraps this error, so only the chat path was affected.
