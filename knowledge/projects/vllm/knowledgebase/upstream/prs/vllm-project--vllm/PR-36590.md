**Bug: `vision_projector` is `None` for every projector type except `linear`**

In this dispatch, only the `linear` branch assigns to the local variable `vision_projector`. The `cabstractor`, `qwen_merger`, and `else` branches assign to `self.mm_projector` instead. This breaks the non-linear paths at several points downstream:

1. **Line 1241** — `vision_projector.to(vision_model.dtype)` raises `AttributeError: 'NoneType' object has no attribute 'to'` on every non-`linear` path.
2. **Lines 1518 / 1543** — even if (1) were bypassed, the method returns `vision_projector=None`, so `self.vision_projector` ends up `None` and subsequent calls (`self.vision_projector(image_embeds)` in `_process_image_input`, and the analogous call in `_process_video_input`) fail with `TypeError: 'NoneType' object is not callable`.
3. Weight loading is also left in an inconsistent state: the HF mapper rewrites `model.mm_projector.*` weights to `vision_projector.*`, but on these branches the class never registers a usable `self.vision_projector` module. That means the checkpoint projector weights no longer have a correctly wired destination in the model.
4. `self.mm_projector` is set but never referenced anywhere else in the forward path — it's dead state.

The published `HyperCLOVAX-SEED-Omni-8B` config uses `mm_projector_type: "linear"`, so the primary target model happens to sidestep this. But `_init_continuous_vision` is the only projector init for this class, and the non-linear branches are unreachable as written — any future config or alias that hits them will fail on model load.

Suggested fix — assign the constructed module to the local `vision_projector` in every branch:

````suggestion
            if config.mm_projector_type == "linear":
                vision_projector = nn.Linear(
                    in_features=_vision_projector_input_dim,
                    out_features=_vision_projector_output_dim,
                )
            elif config.mm_projector_type == "cabstractor":
                vision_projector = HyperCLOVAXOmniCAbstractor(
                    num_queries=config.num_queries_vis_abstractor,
                    num_input_tokens=(
                        vision_config.image_size // vision_config.patch_size
                    ) ** 2,
                    encoder_hidden_size=_vision_projector_input_dim,
                    hidden_size=_vision_projector_input_dim,
                    output_hidden_size=_vision_projector_output_dim,
                    pos_emb=config.proj_pos_emb,
                    prenorm=config.proj_prenorm,
                )
            elif config.mm_projector_type == "qwen_merger":
                from transformers.models.qwen2_5_vl.modeling_qwen2_5_vl import (
                    Qwen2_5_VLPatchMerger,
                )
                vision_projector = Qwen2_5_VLPatchMerger(
                    dim=_vision_projector_output_dim,
                    context_dim=_vision_projector_input_dim,
                )

                def new_forward(self, inputs) -> torch.Tensor:
                    x, window_index = inputs
                    x = self.mlp(self.ln_q(x).view(-1, self.hidden_size))
                    reverse_indices = torch.argsort(window_index)
                    x = x[reverse_indices, :]
                    return x

                vision_projector.forward = types.MethodType(new_forward, vision_projector)
            else:
                vision_projector = HyperCLOVAXOmniMlp(
                    config.mm_projector_type,
                    _vision_projector_input_dim,
                    hidden_features=_vision_projector_input_dim,
                    out_features=_vision_projector_output_dim,
                )
            vision_projector.to(vision_model.dtype)
````

Note: this also addresses the `self.vision_config` issue flagged separately below by using the local `vision_config` (which is already in scope here) instead of `self.vision_config` (which isn't assigned until after this method returns).
