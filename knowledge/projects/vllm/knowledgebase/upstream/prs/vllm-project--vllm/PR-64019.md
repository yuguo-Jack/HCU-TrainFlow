# [Bugfix][Pooling] Skip weight tying for omitted LM heads

[Upstream PR](https://github.com/vllm-project/vllm/pull/64019) · state: closed · merged: True

## Original PR description



## Overview
Fix initialization of pooling models with quantized token embeddings and `tie_word_embeddings=True`. Packed quantized embeddings have no dense `.weight`, causing initialization to crash when an omitted LM head attempts to tie its weights.


## Claims
- Prevents AttributeError when packed embeddings have no dense .weight.
- Skips weight tying for StageMissingLayer placeholders.
- Adds an end-to-end regression comparing pooled embeddings against a dequantized Transformers reference.


## Validation
```
.venv/bin/python -m pytest \
    tests/models/language/pooling/test_embedding.py \
    -k test_pooling_with_tied_quantized_token_embeddings -v
```

Before the fix, initialization fails with: `AttributeError: 'VocabParallelEmbedding' object has no attribute 'weight'`

  After the fix: 1 passed.



## Details
The pooling adapter replaces the unused LM head with `StageMissingLayer`. Previously, the placeholder delegated `tie_weights()` to the original head, which accessed `embed_tokens.weight`. Packed embeddings expose `weight_packed` and `scales` instead.

The placeholder now returns itself from `tie_weights()`.

This fixes omitted heads only. Sequence-classification conversions using `from_2_way_softmax` or `no_post_processing` create a real LM head and still require separate support for extracting dequantized token rows.

Related PRs #45535 and #48870 address quantized embeddings reused by active LM heads. This change specifically handles weight tying delegated through an omitted pooling head.
