# [CI] Shard Multimodal Models (Extended Generation 1) automatically, with spawned engines

[Upstream PR](https://github.com/vllm-project/vllm/pull/65234) · state: open · merged: False

## Original PR description

## Overview

Enrolls Multimodal Models (Extended Generation 1) and its AMD mirror in `automatic_shard`, and sets `VLLM_WORKER_MULTIPROC_METHOD=spawn` on the step.

Without spawn, sharding this step fails. In #65211's first build ([99300](https://buildkite.com/vllm/ci/builds/99300)), the only sharded run of this step without spawn, one of four shards ran `test_pixtral.py::test_chat_consolidated` and its engine core died with `CUDA error: initialization error` while starting. vLLM forks the engine unless `torch.cuda.is_initialized()` says CUDA is already up (`_maybe_force_spawn` in `vllm/utils/system_utils.py`). On main the step runs as one job, and an engine start early in the run (Granite Speech) finds CUDA up and switches the whole pytest process to spawn, so later engines never fork. That shard had no such test: after one engine test, only CPU unit tests ran (Moondream3 MoE, which sets up vLLM's distributed state, Nemotron Parse MTP, Pixtral's own unit tests) before Pixtral forked its engine. One of them sets up CUDA in a way torch doesn't report. Setting spawn on the step makes every engine start the way the later ones already do on main, in any shard order.

## Claims

| Job | Plan |
|---|---|
| `multi-modal-models-extended-generation-1` | 4 shards |
| its AMD mirror | 3 shards |

- Each shard stays under the 20-minute target; the planned extra machine time is the repeated job setup (a few percent).
- The step passes on recent nightlies as one job.

## Validation

- The sharding harness (each shard's commands run against a mock test tree, as a PR build and as main with the OTel wrapper) shows every test runs exactly once, base and mirror.
- The generated pipeline carries `VLLM_WORKER_MULTIPROC_METHOD=spawn` on both the NVIDIA step and the AMD mirror.
- `split_check.py` finds no step whose jobs each run the whole suite.
- PR build [99363](https://buildkite.com/vllm/ci/builds/99363) ran the step as 4 shards, all passed, slowest under 14 minutes; scoped build [99365](https://buildkite.com/vllm/ci/builds/99365) ran the AMD mirror as 3 shards, all passed. Each command's passed and skipped counts match main's latest nightly on both platforms.
- Machine time is within noise of main's one-job nightly: below it in 99363 and above it in an earlier scoped build on slower hosts, so it depends more on the hosts the shards land on than on sharding. The extra per shard is the repeated job setup, plus spawn starting each engine in a fresh interpreter.

## Details

- **Why spawn on the step, not a test fix.** Which earlier test sets up CUDA unseen isn't pinned down, and any future test could do the same. Spawn is what most of this step already runs under on main.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job.
