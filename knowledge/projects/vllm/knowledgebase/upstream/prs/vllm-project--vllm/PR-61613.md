# [Bugfix] LLM.__repr__ crashes on non-torch worker models

[Upstream PR](https://github.com/vllm-project/vllm/pull/61613) · state: open · merged: False

## Original PR description

## Background

`repr(LLM(...))` calls `collective_rpc("get_model_inspection")`. The default `WorkerBase.get_model_inspection()` passes `self.get_model()` to `format_model_inspection`, which assumes a torch `nn.Module` and walks `named_children()`.

## Problem

Out-of-tree platforms can serve non-torch models — for example vllm-metal serves MLX models. Calling `repr(LLM(...))` in a debugger or inspector raises:

```
AttributeError: 'Model' object has no attribute 'named_children'
```

The vllm-metal plugin worked around this by overriding `get_model_inspection()` in its worker, but every other out-of-tree platform hits the same wall. Root issue: the default `WorkerBase` doesn't handle non-torch models.

## Solution

Add an `isinstance(model, nn.Module)` guard in `WorkerBase.get_model_inspection()`. Non-torch models fall back to `repr(model)` instead of crashing in `format_model_inspection`.

## Testing

- `python -m py_compile vllm/v1/worker/worker_base.py` — syntax OK
- Fix is pure defensive with zero behavior change for the torch path
- Out-of-tree platforms no longer need to override `get_model_inspection()` just for repr() to work
