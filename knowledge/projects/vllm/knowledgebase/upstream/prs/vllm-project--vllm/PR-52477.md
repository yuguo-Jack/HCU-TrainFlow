# [Bugfix][Spec Decode][Structured Output] Drive grammar masks from GPU logit counts

[Upstream PR](https://github.com/vllm-project/vllm/pull/52477) · state: closed · merged: True

## Original PR description

## Purpose

Make the GPU's per-request logit counts decide which grammar mask rows are applied, instead of a CPU-built mask→logit mapping.

- The scheduler emits a fixed-width block of `num_spec_tokens + 1` mask rows per structured-output request.
- The MRV2 kernel launches once per grammar request and applies only the positions active in device `cu_num_logits` (e.g. bonus-only after an adaptive-verification zero-budget step).
- This removes `_build_grammar_mapping` and the worker's dependence on `cu_num_logits_np` / scheduled draft counts. Batch-sharded sampling slices whole blocks, and MRV1 unpacks blocks into its packed layout.

This replaces the CPU-side fix in #52436 (merged), so it is not a duplicate. Co-authored with #52436's author, `oops-oom`.

- oops-oom · comment · 2026-08-19T12:41:56Z · [source](https://github.com/vllm-project/vllm/pull/52477#issuecomment-5342245656)

Agreed on by-req — the control flow is much clearer. I'm curious whether the old by-token mapping was meant as a copy optimization? My read is it was matching the packed variable-length mask/logit layout (one mask row ↔ one logit row) rather than saving on the copy — if anything, by-req copies less (one entry per request vs one per logit row). That 1:1 pairing is also exactly what compaction breaks.

The extra bytes, if any, come from padding short requests to fixed decode_query_len blocks, not from by-req indexing itself — a no-op on a uniform spec batch. Mixed scheduled draft lengths pay more bitmask than the packed layout, but K is small so it should be fine.

One nit: the inner for position_idx in range(MASK_STRIDE) serializes a dimension that used to live in the grid. For small stride (2–6) it's minor, but we could keep it parallel by launching grid=(num_grammar_reqs * MASK_STRIDE, ...) and recovering grammar_idx = pid // STRIDE, position_idx = pid % STRIDE — req_idx/width still come from req_indices + device cu_num_logits, and inactive positions are just cheap masked-off programs like before.
