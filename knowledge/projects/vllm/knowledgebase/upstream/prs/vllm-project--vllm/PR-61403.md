# [FlashInfer] Add opt-in eager/graph autotune measurement

[Upstream PR](https://github.com/vllm-project/vllm/pull/61403) · state: open · merged: False

## Original PR description

## Overview

Add an opt-in eager/CUDA Graph measurement objective to the managed FlashInfer autotune warmup. **Refreshed on current main after #55671 merged.** This PR now contains only the measurement feature; the earlier cache-migration changes and documentation cleanup are upstream.

## Claims

- `KernelConfig.flashinfer_autotune_execution_mode` accepts `auto` (existing per-op defaults), `eager` (include recurring host cost), and `cuda_graph` (measure captured replay).
- Forward the explicit public `MeasurementPolicy` through generic and sparse-MLA warmup; reject explicit modes when autotuning is disabled or the managed-cache deployment is ineligible.
- Keep the parent's single-rank gate and existing default measurement policy. FlashInfer separates explicit policies into distinct cache namespaces; serving reuses the attached store without a new per-token dispatch or synchronization step.

This is one objective for the whole warmup, **not automatic per-path policy selection**. It does not change vLLM's graph configuration.

## Details

Kept as a follow-up because a graph-enabled vLLM engine can mix full graphs, piecewise graphs and eager fallbacks. The knob allows controlled evaluation, but automatically choosing policies also requires matching the winner store to capture and uncaptured execution. Defaults therefore remain unchanged. The configuration field participates in vLLM's kernel hash as well as the explicit policy being part of FlashInfer's managed namespace.

New-policy GPU coverage is limited to this dense FP8 model on B200. SM120 sparse-MLA and MoE need hardware/model coverage; their warmup forwarding and rejection contracts are unit-tested only. Multi-rank managed tuning remains disabled and does not depend on FlashInfer #6185 for this scope. Broader accuracy and runtime-path qualification remain before changing defaults.

Duplicate checks found no `MeasurementPolicy` integration PR. #59995 concerns MoE search strategy and #59698 cache-only startup; this adds the measurement objective on top of the existing #55671 cache migration. AI assistance was used for implementation, review, validation and this description. Human review of the new code remains required before readiness.
