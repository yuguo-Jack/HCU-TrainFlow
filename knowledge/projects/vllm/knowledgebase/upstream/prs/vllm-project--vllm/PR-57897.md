# [Bugfix] Honor tokenizer revision in DeepSeek V4.1 Engram

[Upstream PR](https://github.com/vllm-project/vllm/pull/57897) · state: closed · merged: False

## Original PR description

# [Bugfix] Honor tokenizer_revision when building DeepSeek V4.1 Engram hashes

## Purpose

`NgramHashState` independently loads a tokenizer to build its compressed token
map. It currently passes `model_config.revision`, while the serving tokenizer
uses `model_config.tokenizer_revision`. Explicitly selecting a tokenizer
revision can therefore load a different vocabulary for Engram, or fail if the
model revision does not exist in the tokenizer repository.

Use `tokenizer_revision` consistently. The existing ModelConfig fallback already
handles configurations that do not specify an independent tokenizer revision.
No hashing math, kernels, checkpoint weights, or serving parameters are changed.

The regression covers differing revisions, a tokenizer-only revision, and the
same-revision control. Two vocabularies have the same compressed vocabulary size
but different mappings; the test checks the actual constructed mapping rather
than only asserting a mocked call.

## Duplicate Work

On 2026-09-21, searches for open PRs matching `Engram tokenizer` and issues
matching `"Engram" "revision"` found no fix for this selection mismatch. Other
Engram kernel/performance/parallelism PRs address different behavior.
