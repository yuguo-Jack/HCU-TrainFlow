# [Perf][FlashAttention] FA4: pass no FP8 descale for a unit per-tensor scale

[Upstream PR](https://github.com/vllm-project/vllm/pull/63232) · state: closed · merged: True

## Overview

For an FP8 KV cache whose per-tensor scales are 1.0, FlashAttention now passes FA4 no descale at all. Before, it passed broadcast descale views that FA4 copied into contiguous tensors, three copy kernels per attention layer and step.

This PR began as the squash of the whole MiniMax-M3.1-Flash tree. That squash has since been split into the PRs below; this PR now holds only the FA4 change.

## Claims

- **Unit scales:** when FA4 runs with a per-tensor Q/K/V scale of exactly 1.0, `FlashAttentionImpl` passes `None` for that descale.
  - FA4 reads a missing descale as 1.0, so the output is bit-identical.
  - FA4's `maybe_contiguous` no longer copies the three broadcast descale views per layer and step.
- **Other scales:** calibrated per-tensor scales and per-head scales keep their descale tensors. Other FlashAttention versions get the same broadcast descale as before; only the strides of its size-1 dims are made canonical, which changes metadata, not values.
- **(1, 1) descale views:** a view with one sequence and one KV head per rank now gets canonical strides. FA4 treats such a view as contiguous and skips its copy, and its layout check then rejects the zero stride.

## Validation


148 passed, 9 skipped, 4 failed. The 4 failures are `test_sliding_window_encoder_backend_correctness` (embeddinggemma-300m). They fail the same way on `main` (2abde627d9) in this environment.

The new `test_flash_attn_fa4_unit_fp8_descale_is_exact` (Blackwell only) checks that:

- a unit scale gives no descale;
- FA4's output with no descale equals its output with the broadcast unit descale, bit for bit;
- a descale of 2 changes the output, so the comparison is not vacuous;
- calibrated and per-head scales keep their descale tensors.

Not covered:

- No end-to-end benchmark on this branch; the three copy kernels saved per layer and step were not timed.
- No accuracy eval: the output is bit-identical by the test above.
- The (1, 1) stride case is not in the new test, which uses 3 sequences and 4 KV heads.

## Details

- **Why the check is on the host:** the scales are fixed once the weights are loaded, so the `_scale_float` mirrors decide the case on the host with no GPU sync. A per-head scale's float mirror holds only its maximum, so the check also requires a single-element scale.
- **Compiled kernels:** FA4 compiles a separate kernel without descales, since descale presence is part of its compile key. A model with unit scales always takes that kernel.
- **Not a duplicate:** the open FA4 PRs change other things. #48156 warms up the paged FA4 kernels, #60372 adds SM90 FP8 MMA for Gemma-4, #63328 is sparse-MLA FP8 prefill, and #54705 covers Inkling per-tensor scales outside `flash_attn.py`. None of them changes how `FlashAttentionImpl` passes descales.

Per-layer `k` has shape `[num_ctx, num_kv_heads, head_dim]`; FlashInfer's Gemma RMSNorm expects `[rows, head_dim]`. Flattening only the leading dimensions preserves per-head normalization. This also handles empty input without a kernel call.

```suggestion
    def _normalize_context_k(self, all_k: torch.Tensor) -> torch.Tensor:
        if all_k.numel() == 0:
            return all_k
        # Context K has [num_ctx, num_kv_heads, head_dim] per layer.
        # FlashInfer's Gemma RMSNorm takes 2D input; fold only the leading
        # dimensions so each head is still normalized independently.
        return torch.stack(
            [
                layer.self_attn.k_norm(k.flatten(0, -2)).reshape_as(k)
                for layer, k in zip(self.layers, all_k)
            ]
        )
```
