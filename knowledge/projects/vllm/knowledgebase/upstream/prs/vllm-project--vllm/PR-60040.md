# [ROCm][Attention] Support multimodal Prefix-LM in ROCM_ATTN

[Upstream PR](https://github.com/vllm-project/vllm/pull/60040) · state: open · merged: False

## Original PR description


## Overview

Add bidirectional image-token attention to ordinary `ROCM_ATTN` for multimodal Prefix-LM models such as Gemma3. Related to [#48172](https://github.com/vllm-project/vllm/issues/48172) and the ordinary-backend portion of [#59095](https://github.com/vllm-project/vllm/issues/59095).

## Claims

- Support global, sliding-window and window-clamped image attention using shared Triton mask helpers.
- Enable MRV2 `FULL_AND_PIECEWISE` where image prompt extensions can safely replay the causal decode graph, including fixed multi-token speculative verification. Preserve MRV1 eager/`PIECEWISE` compatibility.
- Protect context block-table boundaries and invisible cached NaNs; fix a pre-existing zero-token padding write in paged decode.

## Validation

Gemma3-4B IT BF16 on Radeon 8060S (`gfx1151`), AITER disabled; PyTorch 2.13.0+rocm10.0.0, Triton 3.8.0. The focused attention tests pass 43 cases, and image-prefill hidden states pass the existing HF comparison. Pre-commit, Python 3.12 mypy and diff checks pass. Model evaluation and attention regression use `VLLM_GPU_SYNC_CHECK=error`.

## Details

Thread image ranges through the existing metadata/dispatcher and reuse `compute_kv_seq_mask` and `compute_tile_loop_bounds`. Active ranges use the context kernel; ranges equivalent to causal decode are removed using CPU prefill bounds, including draft placeholders. Full graphs are restricted to invariant image/window configurations; no scheduler or runner changes are required.

**Additional bug found during graph validation:** The existing Triton paged-decode kernel only skipped `query_len > 1`, so zero-token padding rows could execute and write output. Change the guard to `query_len != 1`, matching HIP. Single-token decode remains unchanged and multi-token queries still use context attention; the graph regression covers padding and changing query lengths.

**Duplicate check (2026-10-05):** Public issue timelines, open-PR searches and patches show no open PR implementing ordinary `ROCM_ATTN` multimodal Prefix-LM. [#59295](https://github.com/vllm-project/vllm/pull/59295) and the issue's AITER WIP target AITER unified attention; #59295 shares metadata edits but keeps ordinary ROCM unsupported. [#53628](https://github.com/vllm-project/vllm/pull/53628) fixes no-range sliding-window NaNs and overlaps in kernel locations; this path must also preserve image keys beyond the ordinary window. [#59637](https://github.com/vllm-project/vllm/pull/59637) optimizes the reused Triton helper; [#46754](https://github.com/vllm-project/vllm/pull/46754) provides the earlier Triton fallback. 

Existing AMD suites include these tests; upstream CI was not run here. Real-model accuracy/performance cover gfx1151 BF16 only; FP16 and FP8 KV have focused kernel coverage.
