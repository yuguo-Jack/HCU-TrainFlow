# [Bugfix][Weight Cache] Restore model state before IPC fallback

[Upstream PR](https://github.com/vllm-project/vllm/pull/59813) · state: open · merged: False

## Original PR description



## Overview

Restore model registrations and RoPE cache state when IPC model construction fails, so the disk fallback can initialize the model again. Addresses the fallback failure in #59803; does not fix the EP meta-device error itself.

## Claims

- Failed IPC construction no longer leaves duplicate layer registrations or newly cached meta RoPE modules for the disk fallback.
- Existing model registrations, MoE order, RoPE buffers and their persistence flags survive a failed load.
- Successful construction retains its new state.

## Validation

- Existing weight-cache unit cases plus three regression cases: 7 passed, 3 GPU/daemon cases deselected. With the original loader, the two failure cases fail with duplicate registrations; five other cases pass.
- RTX 3080 Ti, Qwen2.5-0.5B, FP16, eager/TRITON_ATTN: inject an exception at `_apply_entries` after real meta-model initialization. The original loader fails with `Duplicate layer name`; the patched loader loads from disk and produces the same token IDs as a normal disk load for two prompts, eight greedy tokens each.
- Vast RTX 3090, driver 595.71.05, Torch 2.13.0+cu130: real IPC daemon, Qwen2.5-0.5B FP16, eager/TRITON_ATTN. After mapping 267 real IPC entries, an injected exception reproduces `Duplicate layer name` on the original loader. With the patch, disk fallback succeeds. Baseline disk load, absent-daemon fallback, original/patched cache hits (fallback disabled), patched failure fallback, and a subsequent cache client all produce identical token IDs for two prompts, eight greedy tokens each.
- Commands: `PYTHONPATH=$PWD .venv/bin/python /root/vast-ipc-model.py baseline`, followed by `bash /root/vast-run.sh` (starts the daemon, runs before/after fault injection, and compares all six outputs). Result: `ALL_REAL_IPC_CASES_PASS`.
- Pre-commit checks on changed files passed. Python 3.12 mypy checked separately.

The local RTX 3080 Ti test stubs daemon lookup; the Vast test uses the real daemon and actual CUDA IPC mapping. Both inject an exception deliberately. Vast uses source commit `7cfd233538805f4a34607263a144bfb0f3943f32` with precompiled native extensions from `vllm/vllm-openai:v0.30.0`. This is a single-GPU output smoke check, not a two-GPU EP reproduction or dataset-level quality evaluation.

```python
import os
os.environ['VLLM_ENABLE_V1_MULTIPROCESSING'] = '0'
import json
import sys
from contextlib import ExitStack
from unittest.mock import patch
from vllm import LLM, SamplingParams
from vllm.model_executor.model_loader.weight_cache.ipc_loader import IpcModelLoader

mode = sys.argv[1]
extra = {'socket_dir': '/root/ipc-sockets', 'fallback': mode != 'warm'}
if mode == 'cold': extra['socket_dir'] = '/root/no-daemon'
with ExitStack() as stack:
    if mode == 'failure':
        original = IpcModelLoader._apply_entries
        def fail_after_mapping(self, model, state, device_index):
            original(self, model, state, device_index)
            print('INJECTED_AFTER_REAL_IPC_MAPPING', len(state.entries), flush=True)
            raise RuntimeError('injected failure after real IPC mapping')
        stack.enter_context(patch.object(IpcModelLoader, '_apply_entries', fail_after_mapping))
    llm = LLM(model='Qwen/Qwen2.5-0.5B', load_format='auto' if mode == 'baseline' else 'ipc_cache',
              model_loader_extra_config={} if mode == 'baseline' else extra,
              enforce_eager=True, dtype='half', max_model_len=128,
              max_num_batched_tokens=128, max_num_seqs=2, kv_cache_memory_bytes=64*1024*1024,
              attention_config={'backend':'TRITON_ATTN'})
    outputs = llm.generate(['The capital of France is', 'The sum of two and three is'],
                           SamplingParams(temperature=0, max_tokens=8))
    print('RESULT ' + json.dumps([o.outputs[0].token_ids for o in outputs]), flush=True)

```

## Details

Constructing a model mutates shared layer registries and the RoPE cache before it returns. Retrying after an exception must undo that attempt while keeping any existing target model. The rollback is scoped to IPC construction; it restores containers in place, including existing RoPE buffer registrations and persistence flags that IPC mapping can replace. It does not copy weight tensors.

Open #55490 and #43928 address EP meta-device construction, not this fallback state. Issue-number and IPC-fallback searches found no competing rollback PR on 2026-10-02. The final issue-number and title searches were repeated before submission.
