# [CI][ROCm][Bugfix] DeepSeek V4.1: don't pass expert intermediate padding to AITER

[Upstream PR](https://github.com/vllm-project/vllm/pull/61960) · state: closed · merged: True

## Original PR description

AITER 0.1.25's FlyDSL MoE (ROCm/aiter#6125 configs) leaves the padded intermediate columns unwritten when told about the padding, so stage 2 reads stale memory and small decode batches (M <= 4 tokens) can come out NaN. This hits DeepSeek V4.1 at TP4, where the per-rank expert intermediate size is padded 576 -> 640.

Pass intermediate_pad=0 for V4.1's routed experts so AITER computes over the zero padding instead of skipping it, which is exact. DeepSeek V4 never pads the expert intermediate size and is unchanged. Revert once vLLM pins an AITER with the fix https://github.com/ROCm/aiter/pull/6598.

This hotfix was developed to resolve the flakiness in the newly added test group `(MI355) DeepSeek-V4.1 Mono Decode Numerics`
