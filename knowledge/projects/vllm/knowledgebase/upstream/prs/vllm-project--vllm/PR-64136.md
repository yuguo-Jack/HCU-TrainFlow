# [ROCm][DSv4.1] Preserve speculative grouping in MXFP4 gather indexing

[Upstream PR](https://github.com/vllm-project/vllm/pull/64136) · state: closed · merged: False

## Original PR description

## Overview

Preserve six-query speculative grouping when launching Flash's AITER MXFP4 candidate-gather indexer on gfx950. Flattening every query to its own request loses AITER's grouped launch tuning.

## Claims

- Select grouped launches for 32 heads, 16K candidate tokens, and at least 128 rows with six query rows per request.
- Preserve per-query candidate slots and causal row ends, including padded rows; other shapes retain their existing dispatch.
- Earlier isolated pipeline measurements at 128K context/request, top-512, 2048 candidate blocks of eight tokens showed 90.33 → 79.68 µs at 192 rows and 174.22 → 144.49 µs at 384 rows. These were HIP graph measurements with reused buffers; they are not cold-HBM or serving throughput claims.

## Validation

MI355X, editable vLLM base `5d35ce3934`:

```bash
HIP_VISIBLE_DEVICES=6 CUDA_VISIBLE_DEVICES=6 HF_HOME=/data \
FLYDSL_RUNTIME_CACHE_DIR=/data/dsv41-c128-comparison/flydsl_cache \
  .venv/bin/python -m pytest \
  tests/kernels/attention/test_rocm_paged_mxfp4_indexer.py -q
```

The full suite passed: **35 passed**. The added test runs the real indexer pipeline against the Torch reference with variable context lengths, per-query candidates, compression ratios, page sizes 64/128, and a padded request. The MI355X MLA CI mirror runs the suite. Ruff and pre-commit pass.

**Pending:** combined DPATP2 c128 AgentX serving benchmark and model evaluation with native ASM and #57478. No serving throughput gain is claimed before that run completes.

## Details

Reuse `decode_native` request metadata and `_Layer.rows` for grouped query views. The gather kernel still receives per-query candidate slots and causal bounds, so grouping changes its launch shape without merging queries' visible tokens.

Duplicate-work check: #57517 introduces AITER paged MXFP4 indexing, while #63888 changes decode top-k initialization. This draft changes only the candidate-gather query grouping in the existing indexer; neither PR implements this dispatch. Searches for grouped indexer and MXFP4 gather found no equivalent open change. Closed #63634 supplied the performance investigation context, but this is Flash-specific grouping rather than its blanket top-k dispatch.
