# [ROCm][DSv4] Opt-in aiter ASM sparse MLA decode with FP8 Q (VLLM_ROCM_USE_AITER_ASM_SPARSE_MLA)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61826) · state: open · merged: False

## Original PR description



## Overview

`VLLM_ROCM_USE_AITER_ASM_SPARSE_MLA=1` (opt-in, default off) runs DeepSeek-V4 sparse MLA decode on MI355X (gfx950) the way ATOM does: KV cache in aiter's two-buffer layout, FP8 Q, and aiter's v4 nm ASM decode kernels.

## Claims

- DeepSeek-V4-Pro, 8x MI355X, DP8 attention + EP8, AgentX agentic workload. These numbers were measured on a development branch, not on this upstream branch:
  - decode step at 16 requests per rank: 53.6-54.5 -> 49.6-50.3 ms;
  - sparse MLA kernels: 7.31 -> 2.56 ms per step;
  - e2e, same node, c128: P90 interactivity 27.37 -> 30.95 tok/s/user, total tok/s/GPU +10.5%;
  - e2e, same node, c64: P90 interactivity 50.1 -> 60.32 tok/s/user, total tok/s/GPU +7.1%.
- KV capacity: -10.5% tokens per rank, taken by the RoPE side pool.
- Off by default; with the switch off, nothing changes.

## Validation

Accuracy and performance on this upstream branch are still to be added.

Development branch:
- gsm8k 5-shot, real speculative decoding, flexible / strict: 0.9704 / 0.9712 with the switch, 0.9727 / 0.9735 without.
- Unit checks with real shapes on one GPU:
  - the compressor writers write identical NoPE, scale and RoPE bytes in the old and new layouts;
  - the prefill gather is bit-identical;
  - the ASM decode vs an fp32 reference with the same FP8 Q: cos 0.999998.
- Real-weight decode calls at ~100K context vs an fp32 reference with bf16 Q: cos >= 0.99996.

This branch:
- `pre-commit run --files <changed files>`: all hooks pass, mypy included.
- No GPU tests have been run on this branch yet.

## Details

- **KV layout.** Every DeepSeek-V4 attention cache page (SWA, CSA, HCA; target and DSpark draft) holds 512-byte rows: 448 fp8 NoPE, then the 7 UE8M0 scales (each written twice), then padding.
  - The bf16 RoPE lives in a side pool. Rows are numbered across the whole block-outermost KV buffer, so the pool is 1/4 of that buffer, and the KV planner gives the cache 4/5 of the budget.
  - `register()` asserts the block-outermost layout and 512-byte alignment at KV bind time.
- **Q/K.** aiter `fused_qk_norm_rope_group_quant` does Q RMSNorm + RoPE + FP8 group quant, and K norm + RoPE + UE8M0 quant + SWA row write. The DSpark context-KV insert uses the same kernel.
- **Decode.**
  - Each row gets one merged index list: SWA window + top-k compressed rows. It is built from the persistent metadata buffers, so it is CUDA-graph safe.
  - CSA and SWA-only layers run `mla_decode_fwd_v4_nm` with aiter's split plan.
  - HCA layers run the persistent `mla_decode_fwd_v4_nm_ps` (15-32768 rows).
- **Prefill** stays on the existing bf16 path; the gather kernel reads the new layout.
  - aiter's ASM sparse prefill is gfx1250-only.
  - The gfx950 fp8 OPUS prefill measured no gain: +3.2 ms per 8K-token step in a unit A/B.
  - With the switch on, `VLLM_ROCM_USE_AITER_TRITON_SPARSE_MLA` is ignored, because that kernel reads the fp8_ds_mla pages.
- **Off path.** All new code is behind the switch. The Triton edits to the compressor writers, the prefill gather and the global top-k kernel are constexpr branches whose defaults reproduce today's code.
- **Precision.** Decode Q is FP8 (UE8M0 per 64), and RoPE is applied with bf16 cos/sin tables in aiter's kernel. Prefill attention is unchanged.
- **Limits.**
  - DeepSeek-V4 only; DeepSeek-V4.1 is unchanged.
  - fp8_ds_mla KV cache only.
  - No KV connector or offload: the side pool is not transferred.
  - The ROW_OFFSET constexpr compiles the top-k kernel once per CSA layer.
- **Relation to #56426.** That draft targets the same aiter kernel but keeps vLLM's layout and repacks the selected pages on every decode call; it reports an e2e loss. This PR changes the KV layout itself, so decode needs no repack.
- **Follow-ups.**
  - GPU unit tests: writer / gather round trip, and ASM decode vs an fp32 reference.
  - Accuracy and performance numbers on this branch.
