# Port DeepGemm MHC Kernel to CuTeDSL

[Upstream PR](https://github.com/vllm-project/vllm/pull/48619) · state: closed · merged: False

## Original PR description

## Motivation

In the long run we want to port [Hopper and Blackwell Kernels to CuTeDSL])(https://github.com/vllm-project/vllm/issues/47334).
This PR ports [the following DeepGemm Kernel](https://github.com/deepseek-ai/DeepGEMM/blob/main/deep_gemm/include/deep_gemm/impls/sm100_tf32_hc_prenorm_gemm.cuh) used for DeepSeek MHC to `CuTeDSL`.
I choose DeepGemm implementation as default because the CuTeDSL Kernel is basically on par.
I still believe this Kernel is valuable because it can serve in cases where DeepGemm is not available on B200s and can furthermore be seen as a best practice example of implementing CuTe Kernels. Furthermore we can extend it in the future to support further configurations without much developer cost.

## Current performance numbers

DeepSeek-V4-Flash, TP=8 on 8 x NVIDIA B200 GPUs, FP8 KV cache, 1,024
requests at concurrency 128.

| Input / output | DeepGemm tok/s | CuTeDSL tok/s | CuTeDSL delta |
| --- | ---: | ---: | ---: |
| 8192 / 128 | 56,352 | 55,923 | -0.76% |
| 2048 / 2048 | 10,515 | 10,493 | -0.21% |
| 128 / 8192 | 5,812 | 5,814 | +0.04% |

CuTeDSL is at end-to-end performance parity with DeepGemm across all three
workloads. All 6,144 benchmark requests completed successfully.


## Next steps

Port further DeepGemm kernels to CuTeDSL to reach above RFC. Improve performance of this kernel further (it is relatively untuned).
