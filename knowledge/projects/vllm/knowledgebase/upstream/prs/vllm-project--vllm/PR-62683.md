# [XPU][CI] Run prefix-caching tests for GDN, Mamba and pooling models on XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/62683) · state: closed · merged: True

## Original PR description

## Overview

Intel CI already checks prefix-cache hit counts (`test_hybrid_prefix_cache_hit_rate.py` in `v1/core`), but nothing on XPU checks that the cached state or outputs are correct for GDN, Mamba or pooling models. This adds three jobs, mirroring the CUDA jobs that run these tests, so the XPU cache-hit path for these model types is covered. CI config only; no test code changes. Companion to #62656, which re-enables the two `v1/core` prefix-caching e2e tests.

## Claims

- Intel CI runs `test_mamba_prefix_cache.py`, `test_hybrid.py -k apc` and `test_auto_prefix_cache_support.py`, which check prefix-cache hits on XPU for GDN, Mamba1 and pooling models. 
- All three pass on XPU (Arc Pro B60).

## Validation

```bash
cd tests
pytest -v -s v1/e2e/general/test_mamba_prefix_cache.py
pytest -v -s models/language/generation/test_hybrid.py -k apc
pytest -v -s models/language/pooling/test_auto_prefix_cache_support.py
```

| Test | New job | Result on Arc Pro B60 | Time | Timeout |
|---|---|---|---|---|
| `test_mamba_prefix_cache.py` | E2E Core (`engine_intel.yaml`) | 4 passed, 1 skipped (FlashInfer-only case) | ~17 min | 40 min |
| `test_hybrid.py -k apc` | Language Models (Hybrid) (`models_language_intel.yaml`) | 7 passed | ~16 min | 40 min |
| `test_auto_prefix_cache_support.py` | Language Models (Pooling) (`models_language_intel.yaml`, optional) | 5 passed | ~11 min | 30 min |


## Details

**Motivation.** While validating prefix caching on XPU, I found that Intel CI runs none of the upstream tests that check cached state or outputs. On XPU the prefix-cache hit path runs XPU-specific code: XPU attention kernels, Mamba state copies through XPU device pointers, and a block-size rule of multiples of 64. CUDA CI cannot catch regressions there, and they do occur: #48109 fixed an XPU-only failure in exactly this path (Mamba `align`-mode state copies overflowing int64 with XPU pointers), and at the time no Intel CI job exercised this path. Mamba prefix caching crashed on XPU from the report in #48059 (July 9) until the fix (August 19).

**What each test checks on XPU.**
- `test_mamba_prefix_cache.py`: block allocation and Mamba state copies in `align` mode for a GDN model (Qwen3-Next, dummy weights, one layer), against a reference state.
- `test_hybrid.py -k apc`: outputs with prefix caching match HF and the uncached run for Jamba-tiny-dev and falcon-mamba-7b.
- `test_auto_prefix_cache_support.py`: pooling models hit the cache (`num_cached_tokens > 0`) and their outputs match HF.

**Job layout.** Each job is named after the CUDA job that runs the same test (E2E Core, Language Models (Hybrid), Language Models (Pooling)), so other tests from those areas can be added later. `models_language_intel.yaml` is new because Intel CI has no language-model jobs yet. Language Models (Pooling) is `optional`, like CUDA's Extended Pooling job, which is where `test_auto_prefix_cache_support.py` runs on CUDA.

**Resources.** Language Models (Hybrid) needs a 24 GB device: falcon-mamba-7b (bf16, ~14 GB) runs with `gpu_memory_utilization=0.8`, which does not fit on 16 GB. E2E Core also needs 24 GB for the MRV2 cases, which CUDA moves out of its 18 GB E2E Core job into E2E Core Large Memory for their warmup allocations; on XPU all cases run in one job on a 24 GB device.

**CI cost.** Language Models (Hybrid) (~16 min) and E2E Core (~17 min) run only when prefix-caching, Mamba or XPU platform code changes, and Language Models (Pooling) is optional, so most PRs do not trigger them. They can still be run manually, and XPU kernel updates (`requirements/xpu.txt`) trigger them through `run_all_patterns`.

**Limitations.** Mamba2 is not covered. The upstream Mamba2 prefix-caching tests need 40 GB or more, or run CUDA-only paths (`test_replayssm_decode.py`, `test_hybrid_chunked_prefill.py`), and the `test_hybrid.py` apc tests use only its primary model (Jamba, Mamba1). GDN is covered at the state level only, since `test_mamba_prefix_cache.py` uses dummy weights.

**Not a duplicate.** No open PR adds these tests to Intel CI (searched Intel CI, XPU hybrid, pooling and prefix-caching PRs). #62656 is the companion change for `v1/core`.

**AI assistance.** AI assistance (Claude Code) was used to find which prefix-caching tests Intel CI skips, run them on XPU, and draft the config and this description. I reviewed every changed line and ran the tests above.
