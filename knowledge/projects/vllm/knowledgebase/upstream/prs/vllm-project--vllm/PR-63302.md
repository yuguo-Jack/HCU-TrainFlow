# [Frontend] Validate JSON body and request_ids in /inference/v1/abort_requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/63302) · state: closed · merged: True

## Original PR description



## Overview

Validate the body of `/inference/v1/abort_requests` (and `/abort_requests`) in `vllm/entrypoints/scale_out/token_in_token_out/api_router.py` with a pydantic model, so malformed payloads return `400 Bad Request` instead of raising an unhandled `500 Internal Server Error`.

## Claims

- Adds `AbortRequestsRequest` (`request_ids: str | list[str]`) to `protocol.py`; the annotation defines the contract, so non-object JSON bodies and non-`str`/`list[str]` `request_ids` are rejected by the model rather than by hand-written checks.
- Non-object JSON payloads (such as the array `["req-1"]`) now return the standard `400` `ErrorResponse` instead of crashing with `AttributeError: 'list' object has no attribute 'get'`.
- Clients that send no `Content-Type` header keep working on the legacy `/abort_requests` path.
- No test is added: the `request_ids` contract holds by definition from the model annotation, so an endpoint test would only re-test pydantic (per review feedback).

## Validation

- **Reproducer (without fix vs with fix):**
  - Without fix: `POST /inference/v1/abort_requests` with JSON body `["req-1"]` raises `AttributeError: 'list' object has no attribute 'get'` (`500 Internal Server Error`).
  - With fix: returns `400 Bad Request`, while `{"request_ids": "req-1"}` and `{"request_ids": ["req-1", "req-2"]}` return `200 OK`.
- **Behavior verified locally** with a temporary `TestClient` test asserting `400` for `["req-1"]`, `{}`, `{"request_ids": 123}` and `{"request_ids": [1]}`, `200` for valid bodies, and `200` for a body sent with no `Content-Type`. That test was removed before merge per review, since the model enforces the contract by definition.
- **Test commands run:**
  ```bash
  .venv/bin/python -m pytest tests/entrypoints/scale_out/token_in_token_out/test_protocol.py -q
  .venv/bin/pre-commit run --files vllm/entrypoints/scale_out/token_in_token_out/api_router.py vllm/entrypoints/scale_out/token_in_token_out/protocol.py
  ```
- **Results:** `35 passed`; `ruff-check`, `ruff-format`, `mypy`, and the remaining pre-commit hooks all passed.
- **Model evaluation:** N/A (input validation on an HTTP endpoint; does not alter model outputs or accuracy).

## Details

- **Root cause:** `abort_requests` called `body = await raw_request.json()` and immediately accessed `body.get("request_ids")`. Because `raw_request.json()` accepts any top-level JSON value (arrays, numbers, booleans, strings, `null`), non-dict bodies raised an unhandled `AttributeError`, and non-string `request_ids` values were forwarded straight to `engine_client(raw_request).abort(request_ids)`.
- **Tradeoff — manual parse instead of a FastAPI body parameter:** the endpoint still parses the JSON itself and calls `AbortRequestsRequest.model_validate(body)` rather than declaring the model as a body parameter. vLLM requires FastAPI >= 0.133, where `strict_content_type` defaults to `True`, so a body parameter would reject clients that send no `Content-Type` — the legacy `/abort_requests` breakage this change avoids. Pydantic errors are converted to `RequestValidationError`, so the response format matches other endpoints. The limitation is that the model does not appear in the OpenAPI schema for this route.
- **Duplicate-PR check:** searched open PRs via `gh pr list --repo vllm-project/vllm --state open --search "abort_requests token_in_token_out"`. Open PR #45249 retains a background task reference for `asyncio.create_task` in `abort_requests` and does not validate the request payload or `request_ids` types.
- **AI assistance:** AI assistance was used to identify the unvalidated payload path and prepare this PR; all changes were reviewed and verified locally.
