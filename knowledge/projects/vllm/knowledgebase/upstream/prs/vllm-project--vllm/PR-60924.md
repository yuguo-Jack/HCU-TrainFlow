# [CPU][MRV2] Run Model Runner V2 on CPU without Triton (custom sampler class + torch kernels)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60924) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

Draft, for feedback on the approach.

`CPUModelRunner` (#43225) runs MRV2 on x86 via triton-cpu. This makes it work on CPUs without Triton (Arm, macOS, ...) while keeping the GPU runner free to change without breaking CPU. The rule is: subclass where the GPU code already has a stable interface, and override individual kernels only where it doesn't.

- **Class seams for the parts that change often.** `GPUModelRunner` gets `sampler_cls` and `block_tables_cls`; nothing else on the GPU side changes. The CPU runner sets them to `CPUSampler` and `CPUBlockTables`. `CPUSampler` subclasses `Sampler` and, after the base `__init__`, swaps in:
  - `CPUSamplingStates`: temperature and min-p.
  - `CPULogitBias`, `CPUPenalties`, `CPUBadWords`: logits processors that keep their own per-request state behind the public `LogitsProcessor` interface, so they don't depend on the GPU processors' buffers.

  It also samples top-k/top-p over a small set of candidates and uses torch Gumbel. `CPUBlockTables` works on each KV-cache group's tensors directly, with no pointer arrays.
- **Per-kernel overrides only for stable kernels.** 18 kernels, down from 29: input-batch prep, RoPE and prompt-embeds positions, staged writes, KV zeroing, DCP seq lens, logprobs and prompt logprobs, the grammar bitmask, and the NaN counter. Most are numba ports of the Triton kernels, plugged in through the existing `register_triton_kernel_overrides` hook. numba is already a CPU dependency.

**Overlap:** #55847 also adds CPU fallbacks for these kernels, and fadara01 plans C++ kernels for non-Triton CPU backends. Happy to converge on whichever lands. What's new here is the class seams (sampler, block tables) and the `CPUSampler` itself.

## CPUSampler

Instead of sorting the full vocab for top-p, it runs top-k/top-p on the top 1024 logits and takes the Gumbel-max over those, using the same murmur3 noise indexed by token id. That gives the same token as the full-vocab path whenever the kept set fits in the 1024 candidates. Rows where it doesn't fit fall back to the shared path; at T=0.8/p=0.95 on Qwen3-0.6B, 99.2% of rows fit.

## Results

Apple M-series, 8 threads, Qwen3-0.6B bf16.

| Sampler, per call | batch 1 | batch 8 | batch 32 |
|---|---|---|---|
| T=0.8, top_p=0.95 | 9.6 → 1.3 ms | 19.2 → 3.0 ms | 71.9 → 7.5 ms |
| T=0.8, top_k=50, top_p=0.9 | 10.3 → 1.4 ms | 14.7 → 2.3 ms | 67.6 → 10.6 ms |

End to end (64 prompts × 128 tokens, `max_num_seqs=16`, top_p=0.95):

- `CPUSampler`: 66.0 → 77.8 tok/s (+18%).
- `CPUPenalties` works from the token history, so it needs no `[max_num_reqs, vocab]` bin-count buffers. Per call it's 0.24 ms at batch 1 (0.34 before) and 4.8 ms at batch 32 (3.1 before), with 1.5k-token histories.
- numba bookkeeping kernels, against the torch versions they replace: 72.0 → 74.0 tok/s. That's within noise, since the forward pass dominates.
- Per call, the numba kernels take 5–20 µs; the torch versions took 30–430 µs.
- The numba kernels cost about 5 s of JIT on the first run and are cached on disk afterwards.

## Tests

```
pytest tests/v1/worker/test_cpu_sampler.py tests/v1/worker/test_gpu_block_table.py \
       tests/model_executor/test_triton_dispatcher.py tests/v1/e2e/test_cpu_model_runner_v2.py
# 38 passed, 5 skipped
```

- **V1/V2 parity:** greedy, penalties, logit_bias, bad_words, min_tokens, allowed_token_ids and prompt logprobs all match V1.
- **CPUSampler vs the shared path:** on 24,576 rows of real logits, the only differences were 10 exact ties at the top-p cutoff, where `torch.sort` order is arbitrary anyway.
- **numba ports:** identical to the torch versions on 200 randomized trials.
- **CPU logits processors and sampling states:** identical to the GPU state classes, on randomized batches of bias, allowed ids, min_tokens with restore, penalties and bad words, including draft rows (400 trials).
- **`CPUBlockTables`:** identical to `BlockTables` across multi-group, DCP, disabled-slot-mapping and dummy-request cases (300 trials). `test_gpu_block_table.py` now also runs against it on CPU.

## Other changes

- **Dispatcher:**
  - passes the launch `grid` to overrides that ask for it
  - drops Triton launch options
  - skips non-dict `__dict__`s while rebinding kernels (one comes with importing numba and crashed registration)
- **Config:** MRV2 no longer requires Triton on CPU. Spec decode and `return_sampling_mask` without Triton are rejected.
- **Runner:** reads the penalties processor's `output_bin_counts` with `getattr`, as the diffusion sampler's stub already assumes. `VLLM_USE_V2_MODEL_RUNNER=1` is still needed.
- **CI:** the new tests run in the x86 (soft-fail) and Arm CPU jobs.

## Next steps

1. A `rejection_sampler_cls` seam, so spec decode works on CPU (ngram first).
2. A seam for prompt logprobs, which would remove the logprob kernel overrides.
3. A signature-parity test for the remaining overrides.

Not yet measured on x86 or Arm servers.
