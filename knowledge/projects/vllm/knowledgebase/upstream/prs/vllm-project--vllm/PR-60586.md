# [Bugfix][Frontend] Apply the JSON schema in Cohere Chat v2 response_format

[Upstream PR](https://github.com/vllm-project/vllm/pull/60586) · state: closed · merged: True

## Original PR description



## Overview

Every `/cohere/v2/chat` request with `response_format={"type": "json_object", "json_schema": {...}}` fails with a 400, because the schema never reaches structured outputs. This change passes the schema through the field's `schema` alias, as the Anthropic adapter already does.

## Claims

- A Cohere Chat v2 `json_schema` response format now constrains the output to the schema, for both streaming and non-streaming requests, instead of returning a 400.
- `json_object` without a schema and `text` behave as before.

## Validation

Unit tests (CPU):

```bash
VLLM_TARGET_DEVICE=cpu python -m pytest tests/entrypoints/cohere
```

The 219 conversion and protocol tests pass. The 9 server tests in `test_chat_v2.py` start `vllm serve`, so I ran them separately against a CPU build with `HuggingFaceTB/SmolLM2-135M-Instruct`, and all 9 pass. The new `test_json_schema_reaches_sampling_params` fails on `main` with the same `VLLMValidationError` that causes the server's 400, and passes with this change. The existing `test_json_schema` is unchanged and passes both on `main` and with this change.

Live A/B on CPU: `VLLM_ENABLE_COHERE_API=1 vllm serve Qwen/Qwen2.5-0.5B-Instruct` (revision `7ae55760`) with `--structured-outputs-config.backend xgrammar`, temperature 0. Both runs used the same CPU build of `main` (`0f112d1`); the second added this change. The schema requires `capital` (enum `["Vienna"]`) and `population_millions`, with `additionalProperties: false`.

| `response_format` | `main` | This PR |
| --- | --- | --- |
| `json_object` + `json_schema`, non-streaming | 400: "You must use one kind of structured outputs constraint but none are specified" | 200: `{"capital": "Vienna", "population_millions": 10.5}` |
| `json_object` + `json_schema`, streaming | 400, same error | 200, same JSON |
| `json_object` without a schema (control) | 200, JSON | unchanged |

Pre-commit passes on the changed files, including the mypy hooks for Python 3.10 to 3.13.

## Details

Root cause: `JsonSchemaResponseFormat.json_schema` is declared with `alias="schema"`, and `OpenAIBaseModel` allows extra fields. `JsonSchemaResponseFormat(json_schema=...)` therefore stores the schema as an extra attribute and leaves the field `None`. `structured_outputs_from_response_format` reads the field, so the request ends up with no structured-output constraint and fails validation. This has been the case since the Cohere Chat v2 endpoint was added in #47189.

The existing `test_json_schema` reads the schema back through `model_dump()`, which includes the extra attribute, so it passes on `main` too. I kept it as is and added a test that checks the schema reaches the sampling params, which is what the server uses.

Duplicate check: I searched PRs and issues for "cohere json_schema", "cohere response_format", "cohere structured output" and `JsonSchemaResponseFormat`, and found nothing related. The open Cohere PRs (#52437, #44659) change other code.

The field name is intentional, but pydantic only fills it through the `schema` alias. Passing `json_schema=` leaves the field as None (the dict ends up in the model's extra fields), which is what causes the 400 on main:

JsonSchemaResponseFormat(name="x", json_schema={"type": "object"}).json_schema  # None
JsonSchemaResponseFormat(name="x", schema={"type": "object"}).json_schema       # {'type': 'object'}

The Anthropic adapter passes `schema=` for the same reason.
