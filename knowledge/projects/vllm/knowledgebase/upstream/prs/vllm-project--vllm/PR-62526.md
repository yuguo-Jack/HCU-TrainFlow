# [Benchmark] benchmark_moe: read Gemma 4's MoE shape from its text config

[Upstream PR](https://github.com/vllm-project/vllm/pull/62526) · state: closed · merged: True

## Original PR description



## Overview

`benchmarks/kernels/benchmark_moe.py --model google/gemma-4-26B-A4B-it` crashes before tuning starts, so fused-MoE tile tables cannot be generated for Gemma 4. Same fix as #45789, which the stale bot closed for inactivity without review.

## Claims

- `benchmark_moe.py` tunes and benchmarks Gemma 4 MoE models (`Gemma4ForConditionalGeneration`, `Gemma4ForCausalLM`) instead of raising `AttributeError: 'Gemma4TextConfig' object has no attribute 'num_local_experts'`.
- The tables it writes have the shape vLLM loads at runtime (`E=128,N=704` for 26B-A4B).
- A config with no MoE experts (dense Gemma 4 31B/E2B, or any dense model) now stops with `ValueError: <architecture> has no MoE experts in its config; benchmark_moe.py only tunes MoE layers.` instead of a `TypeError` in `ensure_divisibility` or an `AttributeError` on `num_local_experts` (raised in review by @chrikrah).

## Validation

On 1x H200 NVL; the first two rows on `main@852989f`, the tuning run on `main@2534a96`:

| Command | Before | After |
|---|---|---|
| `python benchmarks/kernels/benchmark_moe.py --model google/gemma-4-26B-A4B-it --tp-size 1 --dtype auto --batch-size 1 16 256` | `AttributeError ... num_local_experts` | runs; kernel time 43.9 / 265.5 / 437.0 us at batch 1 / 16 / 256 |
| same with `--dtype fp8_w8a8` | same error | runs; kernel time 31.5 / 152.2 / 258.0 us |
| `--tune` (fp8_w8a8, 11 batch sizes) | same error | writes `E=128,N=704,device_name=NVIDIA_H200,dtype=fp8_w8a8.json`; the server logs `Using configuration from ...` for it |

`get_model_params` on real configs (CPU, `transformers` `AutoConfig`), after the dense-config check:

| Config | Result |
|---|---|
| Gemma 4 26B-A4B | `(128, 8, 704, 2816)` |
| Qwen3-30B-A3B, Qwen1.5-MoE-A2.7B, OLMoE-1B-7B, DeepSeek-V2-Lite, Granite 3.1 3B-A800M | unchanged |
| Gemma 4 31B, Gemma 4 E2B, Qwen3-0.6B, SmolLM2-135M (dense) | `ValueError: ... has no MoE experts in its config` |

## Details

Gemma 4 architectures fell through to the Mixtral branch of `get_model_params()`. Gemma 4 keeps its MoE fields on the text config under the same names as DiffusionGemma (`num_experts`, `top_k_experts`, `moe_intermediate_size`), so it joins that branch. `moe_intermediate_size` (704) is the expert width; `intermediate_size` (2112) is the dense MLP's and would produce a table vLLM never loads.
