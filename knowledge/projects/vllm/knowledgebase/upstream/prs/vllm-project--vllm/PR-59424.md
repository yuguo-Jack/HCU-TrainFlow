# [Bugfix] Reject `max_tokens < 1` in `BeamSearchParams`

[Upstream PR](https://github.com/vllm-project/vllm/pull/59424) · state: open · merged: False

## Original PR description

## Purpose

`BeamSearchParams` accepted `max_tokens=0` (or negative) without any validation, while `SamplingParams` rejects `max_tokens < 1` with `VLLMValidationError`.

With an unvalidated value, `beam_search()` silently misbehaves instead of raising:
- the offline path (`LLM.beam_search`) skips the generation loop and returns the prompt echoed back as generated text;
- the online path yields an empty completion with `finish_reason="length"`.

This change adds the same `max_tokens >= 1` check to `BeamSearchParams.__post_init__`, mirroring `SamplingParams._verify_args`.

## Test Plan

- New unit test `test_beam_search_params_rejects_non_positive_max_tokens` in `tests/test_sampling_params.py`: asserts `VLLMValidationError` for `max_tokens` in `(0, -1, -100)` and acceptance of `1` and `16`.
- Verified no in-tree callers or tests construct `BeamSearchParams` with `max_tokens < 1` (existing tests use values >= 1; internal beam-search engine calls use `max_tokens=1`), so no existing behavior changes.
