# [Bugfix][Model] Remove redundant all_gather_interleave in ViT split_qkv

[Upstream PR](https://github.com/vllm-project/vllm/pull/49062) · state: open · merged: False

## Original PR description

## Purpose

Fixes #49061.

PaddleOCR-VL, Ernie4.5-VL, and GLM-4.1V vision attention each carried a
byte-identical helper `all_gather_interleave()` that calls
`torch.distributed.all_gather()` directly on the tensor-parallel group's raw
`device_group`, followed by a per-rank re-split, inside `split_qkv()`.

There are two problems.

First, portability. The vision encoder runs eagerly (`torch.no_grad()`, outside
`torch.compile`). On any platform whose `device_group` has no c10d backend
registered for eager use, the direct `dist.all_gather()` raises
`RuntimeError: No backend type associated with device type`, which crashes the
vision-encoder worker with `EngineDeadError` for every image request at
`tensor_parallel_size > 1`. vLLM's collective API
(`tensor_model_parallel_all_gather`, routed through `GroupCoordinator`) exists to
handle exactly this case, and the hand-rolled helper bypassed it.

Second, redundancy. The gather is a no-op. Each rank's local qkv out of
`QKVParallelLinear` (`gather_output=False`) is `[q_shard | k_shard | v_shard]`
for that rank's own heads. `all_gather_interleave` gathers every rank, reorders
to `[all_q | all_k | all_v]`, then `split_tensor_along_last_dim(...)[tp_rank]`
selects back exactly this rank's own shards. For full multi-head self-attention
(`total_num_kv_heads == total_num_heads`, which all three models use) the whole
round-trip is a numerical identity, so chunking the local tensor directly is
bit-identical.

This is the same removal already merged for `glm4_1v` in #23441
("Remove redundant all gather + split"), which fixed that model's `split_qkv`
but left the now-dead `all_gather_interleave` helper behind.

## Changes

- `paddleocr_vl.py`, `ernie45_vl.py`: drop the `all_gather_interleave` gather and
  the subsequent per-rank re-split from `split_qkv`, keeping `qkv.chunk(3, dim=2)`
  and the reshape. This matches the already-merged `glm4_1v.split_qkv`.
- All three files: delete the now-unused module-level `all_gather_interleave`.
- New `tests/model_executor/test_vit_split_qkv_equivalence.py`: a CPU regression
  test asserting the local-chunk path is bit-identical to the old gather
  round-trip across `tp_size` in `{2, 4}` and several head and dim configs. It
  guards against a future reintroduced gather, or a grouped-query layout that
  would break the equal-shard assumption.

## Not a duplicate

- No open PR references #49061 (checked `gh pr list --state open --search
  "49061 in:body"` and `all_gather_interleave` / `split_qkv ViT` keyword
  searches, both empty).
- #23441 (merged) applied this exact transformation to `glm4_1v` only.
- #31402 attempted to extend the removal to these files but was never merged. It
  was auto-closed for inactivity after 90 days of no review, not rejected on
  technical grounds. This PR completes that cleanup, and unlike #31402 it also
  deletes glm4_1v's leftover dead helper, adds a regression test, and avoids
  #31402's flagged defect (which had left glm4_1v's call site intact).

## Test plan and results

- `ruff check` and `ruff format --check` on all four changed files: pass.
- New equivalence test: the identity it encodes is bit-identical (`torch.equal`)
  across `tp_size` in `{2, 4}` and head configs `{(4,8), (8,16), (16,8)}`, 18 of
  18 rank-cases. The test imports only `vllm.distributed.utils`.
- Because the change is a numerical identity, model output is unchanged, so no
  accuracy or evaluation delta is expected and none is required.
