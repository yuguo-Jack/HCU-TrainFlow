# BugFix(PCP): use persistent input buffers for PIECEWISE CUDA graphs

[Upstream PR](https://github.com/vllm-project/vllm/pull/53515) · state: closed · merged: True

## Original PR description

## Summary

Fix PIECEWISE CUDA graph execution with PCP by using persistent PCP input buffers during graph capture and sizing graph dispatch from the largest real rank-local PCP batch before padding.

## Implementation

- Decoder graph capture now uses `PCPManager.input_buffers` when PCP is active, ensuring capture and runtime partitioning share persistent `input_ids`, `positions`, and `is_padding` buffers.
- `GPUModelRunner` obtains the graph dispatch size from `PCPManager.get_num_tokens_for_dispatch()`.
- The CUDA graph dispatcher selects the smallest captured token size covering that rank-local maximum.
- The selected `BatchExecutionDescriptor.num_tokens` is passed to PCP partitioning as `padded_num_tokens`, which determines rank-local gather-index and mask capacity.
- A shared `_iter_rank_chunks()` implements rank chunking for both dispatch-size calculation and segment construction.
- PCP raises `ValueError` when `padded_num_tokens` is smaller than the largest rank-local batch.

Representative dispatch mappings:

| Workload | Global tokens | Rank-local maximum | Capture size |
|---|---:|---:|---:|
| PCP2 prefill | 8 | 4 | 4 |
| PCP2 prefill | 7 | 4 | 4 |
| PCP2, 3 decodes | 3 | 3 | 4 |
| PCP2, 3 decodes + prefill | 11 | 7 | 8 |
| PCP4, 2 decodes + prefill | 11 | 5 | 8 |

I opened #53639 as a draft alternative for comparing a materially different dispatch order. This PR selects a CUDA graph from the global scheduled token count and preserves that width through PCP partitioning. #53639 instead computes the exact maximum PCP-local width before graph dispatch, keeps global input staging separate, and pads each rank only to the selected local graph bucket. For PCP=4 with a 1024-token pure prefill, that changes the per-rank graph width from 1024 to 256; replicated decode widths remain unchanged. Only one implementation should merge.
