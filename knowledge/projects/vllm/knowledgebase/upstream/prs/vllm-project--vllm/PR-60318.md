# [Bugfix] Don't Eliminate Clones for graph I/O Aliases

[Upstream PR](https://github.com/vllm-project/vllm/pull/60318) · state: closed · merged: True

## Original PR description

## Overview

Currently, the compile clone elimination doesn't check for aliases to graph inputs and outputs, which can unexpectedly clobber values if we take a snapshot of an input that doesn't have any writes & leverage in place kernels (e.g., all reduce for TP>1) and return it outside of the compile boundary for later processing. 

I don't think that there are many models in vLLM that do this with the current compile boundaries, but an example of this case came up yesterday in vLLM Omni, since the thinker snapshots the embeddings, which get `.clone`d and forwarded to the talker (more details in: https://github.com/vllm-project/vllm-omni/pull/8532), where the audio gets mangled with TP=2 and compile, because the fused allreduce & rms norm runs in place and the clone on the embeddings is right inside the compile boundary.

This PR skips elimination when the clone is returned from the graph and its source aliases a graph input or another output (assuming the clone has no writes). It also adds a regression test for piecewise and full-graph compilation.
