# [CI] Shard (H200 MIG 35GB) Spec Decode AL DFlash Nightly into named jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/58775) · state: closed · merged: False

## Original PR description

## What
`(H200 MIG 35GB) Spec Decode AL DFlash Nightly` ran every DFlash case in one long replica, and shared `test_dflash.py` with `(B200) Spec Decode AL DFlash2 Nightly` through `-k "not dflash2"` / `-k "dflash2"`. This PR splits the file into flat per-job files in `dflash/` and gives the H200 work three named jobs (each keeping its MI300 mirror), so the partition filter is gone and every job runs under the 20-minute target.

## Old
```
acceptance_rates/dflash/
└── test_dflash.py        # 6 cases, split between two jobs by -k
```
| Job | Key | Command |
|---|---|---|
| (H200 MIG 35GB) Spec Decode AL DFlash Nightly (+ MI300 mirror) | `spec-decode-dflash-nightly` | `pytest acceptance_rates/dflash/ -k "not dflash2"` |
| (B200) Spec Decode AL DFlash2 Nightly | `spec-decode-dflash2-nightly-b200` | `pytest acceptance_rates/dflash/ -k "dflash2"` |

## New
```
acceptance_rates/dflash/
├── _dflash.py                        # helper, not collected (git: rename of test_dflash.py)
├── test_dflash_reference_mrv1.py
├── test_dflash_reference_mrv2.py
├── test_dflash_correctness.py        # qwen3-mrv1, qwen3-mrv2, laguna-nvfp4-mrv2
└── test_dflash2.py
```
| Job (replaces `spec-decode-dflash-nightly`) | Key | Command |
|---|---|---|
| (H200 MIG 35GB) Spec Decode AL DFlash Reference MRV1 Nightly (+ MI300 mirror) | `spec-decode-dflash-reference-mrv1-nightly` | `pytest dflash/test_dflash_reference_mrv1.py` |
| (H200 MIG 35GB) Spec Decode AL DFlash Reference MRV2 Nightly (+ MI300 mirror) | `spec-decode-dflash-reference-mrv2-nightly` | `pytest dflash/test_dflash_reference_mrv2.py` |
| (H200 MIG 35GB) Spec Decode AL DFlash Correctness Nightly (+ MI300 mirror) | `spec-decode-dflash-correctness-nightly` | `pytest dflash/ --ignore=<the three files above and below>` (catch-all) |
| (B200) Spec Decode AL DFlash2 Nightly (key unchanged) | `spec-decode-dflash2-nightly-b200` | `pytest dflash/test_dflash2.py` |

How `test_dflash.py` maps to the new files:
- `test_dflash_reference_acceptance_lengths[False]` → `test_dflash_reference_mrv1.py::test_dflash_reference_acceptance_lengths_mrv1`
- `test_dflash_reference_acceptance_lengths[True]` → `test_dflash_reference_mrv2.py::test_dflash_reference_acceptance_lengths_mrv2`
- `test_dflash_correctness[qwen3-mrv1|qwen3-mrv2|laguna-nvfp4-mrv2]` → `test_dflash_correctness.py`, with the same IDs
- `test_dflash_correctness[qwen3.8-dflash2-nvfp4-mrv2]` → `test_dflash2.py::test_dflash2_correctness`
- The configs and both test bodies move verbatim into `_dflash.py`.

## Notes
- Coverage-neutral: the same 6 tests run on the same devices. Each reference-acceptance pass now runs in its own job and pytest process.
- The Correctness job is the `dflash/` catch-all, so a new test file added there runs by default. Trigger paths are unchanged and shared through YAML anchors.
- The two reference passes are the long cases, so each needs its own job. Hash-sharding `dflash/` was rejected: every N from 2 to 4 either stacks both reference cases on one shard or leaves a shard empty.
- Timeouts are sized to the new jobs (30m). Nothing else consumes the old key, and `test-amd.yaml` has no DFlash acceptance step.
