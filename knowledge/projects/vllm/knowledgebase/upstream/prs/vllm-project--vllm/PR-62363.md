# [CI][AMD] Split LM Eval Small by CDNA generation, unify AMD step titles, clone MoRIIO steps into test-amd.yaml

[Upstream PR](https://github.com/vllm-project/vllm/pull/62363) · state: closed · merged: True

## Original PR description

- `models-small.txt` / `models-small-tp.txt` become `models-small.yaml` / `models-small-tp.yaml`. Each has a `common` section plus optional sections keyed by `current_platform.device_name` (`cuda`, `rocm`) and the ROCm CDNA generation (`cdna3`, `cdna4`). The gsm8k `conftest.py` runs `common` plus the sections that match the machine; plain `.txt` lists still work.
- Both AMD mirrors stay, one per GPU generation and both on the same list: the H200 step's mirror is back on MI300 as `:amd: (MI300) LM Eval Small Models`, and the B200 step's mirror stays on MI355 DPX. `models-gfx950-small.txt` becomes the `cdna4` section.
- MI300 skips the gfx950-only models, and the TP list's MI355 PCP config is `cdna4`-only.
- AMD titles: the tag now always matches the pool (`Torch Stable ABI Audit` runs on MI300, `Docker Build Metadata` on MI250). Bare ` %N` suffixes become ` Shard %N`, and three `test-amd.yaml` titles now match their `test_areas` names. The ROCm build steps drop the `AMD:` prefix (`:docker: Refresh ROCm base`, `:docker: Ensure ROCm ci_base`, `:docker: Build ROCm test image and artifacts`), matching amd-ci; vllm-project/ci-infra#833 (merged) keeps `amd_cpu` steps on `amd-cpu` whatever their title.
- `test-amd.yaml` gets clones of the two AMD-only MoRIIO steps from #60544.

#61955 moved the H200 small-models mirror to `mi355_dpx`, where the B200 mirror already ran a job with the same title, so two different jobs on one pool were both called "LM Eval Small Models". They shared `Qwen3-0.6B-FP8`, and the CI dashboard could not tell them apart. With CDNA sections in one list, each GPU generation gets its own job and its own models: CUDA and MI300 run the same 8 configs as before, and MI355 runs 12. The upstream NVIDIA lists need no change. The title inconsistency on Buildkite (`AMD: :amd: (MI355) … (mi355_2)` next to `:amd: (MI355) …`) comes from the ci-infra generator, which wraps native AMD steps. That part is fixed in vllm-project/ci-infra#833, so after both land every AMD job is `:amd: (<pool tag>) <Title>`. #60544 added two AMD-only MoRIIO steps to `test_areas/misc.yaml` without `test-amd.yaml` clones. The unit step overlaps with the KV Connectors step on 275 of its 293 tests (about 2 min per co-run), but it is the only step that triggers on MoRIIO-only changes, and removing the overlap would cost more GPU time than it saves, so it stays as is.
