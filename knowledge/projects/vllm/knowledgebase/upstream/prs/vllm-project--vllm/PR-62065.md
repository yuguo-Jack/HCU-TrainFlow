# [Bugfix][NIXL] Verify pull reads against producer lease slots

[Upstream PR](https://github.com/vllm-project/vllm/pull/62065) · state: open · merged: False

## Original PR description

## Overview

Fixes #61229: a pull-mode decoder could decode another request's KV when the producer's lease lapsed before or during the READ. The producer now exports a per-request lease slot that the decoder reads after the transfer, and the KV is used only if the producer still held the blocks.

Also fixes a second path to the same result: when a request id is reused on the producer (request id randomization disabled and the router retries with the same id), a late read notification for the earlier attempt was counted against the retry and released its blocks while the retry's decoder had not read them yet. Read notifications now carry the lease nonce, and the producer ignores those of an earlier lease.

## Claims

- A pull whose producer released the KV blocks before the READ completed fails the KV load (`kv_load_failure_policy` applies) instead of returning another request's tokens. This covers a read that starts after the lease lapsed and a lease that lapses mid-read; the check uses no clocks or heartbeat accounting.
- The producer ignores read notifications that carry the lease nonce of an earlier request with the same id, so a late reader can no longer release blocks that the current reader still needs.
- With `kv_lease_verification` on (the default), a pull that cannot be verified fails as well (no lease fields in `kv_transfer_params`, slot READ failed), and an instance that cannot register its lease slots in DRAM fails to start. `kv_lease_verification=false` restores the old behavior.
- TTFT and ITL unchanged at concurrency 1; at concurrency 16 median TTFT +1.3 ms (about one decoder step), ITL and throughput unchanged.

## Details

**Root cause.** In pull mode P frees a request's blocks when its lease expires, without knowing whether D is about to read them (the READ is one-sided). D reads by block number, so after the blocks are reused the READ still succeeds and D decodes the new owner's KV:

1. P finishes the prefill, holds the blocks and grants a 30 s lease.
2. Heartbeats stop (D stalled, network delay) or never start (the request has not reached D yet).
3. P's reaper releases the blocks; another prefill reuses them.
4. D posts the READ with the old block ids; it completes normally and D generates from foreign KV.

**Fix.** Each P worker registers an int64 array in DRAM with NIXL and advertises it in the handshake metadata.

1. When a `do_remote_decode` request is first scheduled, the P scheduler assigns a slot and a nonce; workers write the nonce in that step, before the request can finish and export its lease.
2. `kv_transfer_params` carry `remote_lease_slot` and `remote_lease_nonce`.
3. A P worker zeroes the slot before reporting the request in `finished_sending` (read notification or lease expiry); the scheduler reuses a slot only after `finished_sending`, and workers apply clears before writes within a step.
4. D submits the block READs without a completion notification. Once they completed, it reads the request's lease slot on every remote rank it read from (the checks of all requests that complete in the same step share one READ per remote rank), and reports the request as received only if every slot still holds the nonce. Only then does it send the read notification, which now carries the nonce.

Zeroing precedes any reuse of the blocks and the slot READ starts after the block READs completed, so a matching nonce proves P held the blocks for the whole READ. Declined pulls are counted in `vllm:nixl_num_lease_check_failures`.

**Tradeoffs and limitations.**

- The check delays the KV load by about one decoder step. A bounded spin on the slot READ in the same step could remove it; left out to keep the change smaller.
- Turn-2 readbacks from D in bidirectional mode are not verified yet; `_is_turn2_read_expired` still guards them.
- Lease slots live in DRAM, so the NIXL backend must transfer DRAM between the instances; with verification on, a failed registration stops the instance at startup and failed slot READs fail their pulls.

**Duplicate check.** [#61549](https://github.com/vllm-project/vllm/pull/61549) (draft) estimates the producer lease on D from clocks and heartbeat timing; it cannot rule out a heartbeat that was sent but not delivered, or clock-offset error. [#61578](https://github.com/vllm-project/vllm/pull/61578) adds opt-in KV checksums. This PR is an exact check that is on by default and costs one small READ per remote rank.
