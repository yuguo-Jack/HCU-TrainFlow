# [Docs][Model] Sync supported-model tables with the registry and add a consistency test

[Upstream PR](https://github.com/vllm-project/vllm/pull/61914) · state: open · merged: False

## Original PR description

## Overview

Syncs the supported-model docs tables with the model registry (36 undocumented architectures, 5 stale rows, 1 removed-architecture row, 2 missing `<sup>C</sup>` markers) and adds three consistency tests to `tests/models/test_registry.py` that pin the docs to the registry in both directions. Docs-only change plus tests; no runtime code touched.

## Claims

- Every architecture in the documented registry dicts (`_TEXT_GENERATION_MODELS`, `_EMBEDDING_MODELS`, `_LATE_INTERACTION_MODELS`, `_REWARD_MODELS`, `_TOKEN_CLASSIFICATION_MODELS`, `_SEQUENCE_CLASSIFICATION_MODELS`, `_MULTIMODAL_MODELS`) now has a row in the model docs tables.
- Every architecture token in the docs tables is now either a registry architecture, a converted model (row marked `<sup>C</sup>`), or a documented non-registry architecture (out-of-tree plugin / Transformers fallback / speculative decoding); pooling-mode enum tokens (`ALL`, `CLS`, `LAST`, ...) are allowlisted as non-architectures.
- Removed architectures (`_PREVIOUSLY_SUPPORTED_MODELS`) no longer appear in the docs tables.
- Three deterministic CPU-only tests enforce all three invariants going forward, red/green-verified against the pre-fix docs.

## Details

The worklist was generated mechanically (AST parse of `vllm/model_executor/models/registry.py`, resolving the `**{...}` merge of `_TEXT_GENERATION_MODELS` aliases into `_EMBEDDING_MODELS`, diffed against first-column tokens of every model docs table), not by hand. Per-row facts come from source: LoRA/PP flags from the module class bases, example models from `tests/models/registry.py` (`TBA` where the test registry has none).

Fix classes:

1. **New rows** for recent registry additions, in the table their dict dictates (text vs multimodal vs pooling page): Qwen3.5 text-only pair, Qwen4-Exp pair, GLM-5.3 pair, Laguna, Llama 4 text-only, Step3 text-only, Inkling pair, DeepSeek-V4.1, Cohere Compass, Dots3Note, FunAudioChat, Nemotron-Parse, EmbeddingGemma 2, Terratorch, DeepseekV3BidirectionalModel.
2. **Alias merges** into existing rows where the registry key is an alias of a documented arch: `LLaMAForCausalLM`, `Ministral3ForCausalLM`, `ExaoneMoEForCausalLM`, `NemotronHPuzzleForCausalLM`, `LongcatFlashNgramForCausalLM`, `HfMoondream`, `MiniCPMV4_6/4_7ForConditionalGeneration`, `NemotronH_(Super_)Omni_Reasoning_V3`, `BertForMaskedLM`.
3. **Stale renames** to current registry keys (listed in Validation). `D3ForSequenceClassification`, `ClefFlashForJointSchema` and `ClefOmniForJointSchema` were left as-is: they are already documented in `structured_decisions_models.md`, which the tests scan.
4. **Removals/markers**: the `MiniMaxVL01ForConditionalGeneration` row (arch removed in v0.23, docs keep no previously-supported section), and the `<sup>C</sup>` converted-model marker added to the two scoring rows missing it — both are served by the same online `seq_cls_model_loader` conversion as their marked siblings (bge-reranker-v2-gemma via `no_post_processing`, Qwen3-VL-Reranker).

Test design: deterministic file parsing (no network, no GPU, no model loading), skips when `docs/` is absent (installed-package runs), and carries `skip_global_cleanup` since it creates no global vLLM state. The `<sup>C</sup>` marker is the docs' own convention for converted models, so the exemption is structural rather than a name allowlist.

Not duplicating existing work: #47271 also touches `supported_models.md` but only adds the OpenPangu V2 row together with its registry entries (a consistent pair — these tests stay green under it in either merge order). No other open PR syncs the tables.

AI assistance was used to generate the worklist, the docs edits, and the tests; every changed line was reviewed and the red/green validation above was run by the human submitter's side.
