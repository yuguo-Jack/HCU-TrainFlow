# [ROCm][Model] Step-5-Preview support on ROCm

[Upstream PR](https://github.com/vllm-project/vllm/pull/61837) · state: closed · merged: True

## Original PR description

## Overview

ROCm support for [stepfun-ai/Step-5-Preview](https://huggingface.co/stepfun-ai/Step-5-Preview), complementing the NVIDIA support added in #61727. This PR adds a self-contained amd/ implementation under vllm/models/step5/ and moves the platform-independent Step-5 sparse-attention code from nvidia/ to common/.

The primary support and validation target is **MI300X/MI325X (gfx942)**. **MI355X (gfx950)** is also supported and has secondary validation from [@jamesETsmith](https://github.com/jamesETsmith).

## Claims

- Step-5-Preview FP8 weights serve at TP8 on ROCm with text and image input.
- Compressed sparse attention (CSA) runs on the 23 sparse layers for prefill, chunked prefill, decode, and MTP verification.
- The main paged K/V cache uses ROCm AITER unified attention. The sparse summary cache, speculative tail ring, region scoring, and split-K decode code are shared with the NVIDIA Step-5 path.
- Sparse layers support the default BF16 K/V cache and FP8 E4M3 K/V. FP8 K/V requires `--block-size 32`.
- Three-token MTP works through the Step-3.5 MTP proposer with comparable accuracy and about 2.3x speedup in the earlier GSM8K run.
- Prefix caching and P/D disaggregation are supported. NIXL and Mooncake keep compressed summary pages whole and reject unsupported page splitting.
- CSA uses the existing KV-cache lifecycle and does not require scheduler changes or GPU-to-CPU synchronization.

### Serving command (ROCm, MTP enabled)

<details>
<summary>Serve Step-5-Preview on 8x MI300X</summary>

```bash
VLLM_ROCM_USE_AITER=1 vllm serve stepfun-ai/Step-5-Preview \
  --tensor-parallel-size 8 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.90 \
  --moe-backend triton \
  --mm-encoder-attn-backend ROCM_AITER_FA \
  --mm-encoder-tp-mode data \
  --mm-processor-cache-type shm \
  --limit-mm-per-prompt '{"image":1,"video":0}' \
  --reasoning-parser step5 \
  --tool-call-parser step5 \
  --enable-auto-tool-choice \
  --speculative-config '{"method":"mtp","num_speculative_tokens":3}'
```

| Flag | Why |
|---|---|
| `--moe-backend triton` | Required. Every MoE layer clamps SwiGLU at 7, and AITER's block-FP8 MoE does not apply that clamp yet. |
| `--mm-encoder-*`, `--limit-mm-per-prompt` | Image input through the perception-encoder tower. |
| Default K/V dtype | BF16 sparse K/V. |
| `--kv-cache-dtype fp8 --block-size 32` | Optional FP8 E4M3 sparse K/V. |

</details>

#### In-tree reorganization (latest commit)

Same session, 8x MI300X, TP8, median TPOT (ms) over 3 runs, before vs after the reorganization:

| K/V | 1K in, 1 req | 8K in, 1 req | 1K in, 16 conc |
|---|---|---|---|
| BF16 | 38.97 / 39.42 | 86.67 / 87.01 | 45.10 / 44.80 |
| FP8 E4M3, `--block-size 32` | 39.41 / 39.32 | 91.96 / 91.90 | 44.85 / 45.66 |

Raw lm-eval GSM8K is unchanged (89.4% before; 89.4% BF16 K/V and 89.2% FP8 K/V after), and the real checkpoint loads the same tensors and values. The scored-prefill warmup cuts the first cold 9K-token prompt from 3.46 s to 1.14 s.

The same comparison on 8x MI350X (gfx950), BF16 K/V:

| | 1K in, 1 req | 8K in, 1 req | 1K in, 16 conc | GSM8K raw (flexible / strict) |
|---|---|---|---|---|
| Before | 24.83 | 79.10 | 32.18 | 89.9% / 89.7% |
| After | 24.83 | 79.17 | 32.32 | 89.1% / 88.6% |

The GSM8K gap is within one standard error (±0.86) and matches the extra client timeouts on long reasoning traces (101 before, 110 after).

The 600B checkpoint does not fit in CI, so model-level results come from real hardware. The focused kernel, metadata, configuration, warmup, and connector tests are CI-sized.

## Details

- **Layout:** `vllm/models/step5/{common,nvidia,amd}` with platform dispatch from `vllm/models/step5/__init__.py`. ROCm code lives only in `amd/`
- **Main K/V:** written by `unified_kv_cache_update` and consumed directly from the AITER unified paged layout.
- **Sparse state:** an FP8 summary cache plus a tail ring for incomplete and speculative regions, both attached to the existing KV-cache lifecycle.
- **Decode and MTP:** summary scoring, per-row top-k, and split-K paged attention support ordinary decode and four-row MTP verification, including the head-wise attention gate.
- **Scored prefill:** histories longer than `topk * region_size` use packed summary scoring. Startup warmup now covers this path  on ROCm it dispatches to `amd/warmup.py`
- **Indexer sharding:** Q and W are `ColumnParallelLinear` sharded by provider group; K and Z stay replicated.
- **P/D:** NIXL and Mooncake preserve compressed pages for compatible layouts and fail early if a layer-outer transfer would split one compressed state page. This check applies to every compressed-cache model.
- **MoE:** the shared expert runs inside FusedMoE, and the combined output is all-reduced once in the model dtype.
- **Graphs:** the CSA op is a graph-splitting op and uses real per-step metadata. Piecewise CUDA graphs are supported.

### Limitations

| Limitation | Follow-up |
|---|---|
| Piecewise CUDA graphs only | Make CSA metadata safe for full graphs |
| `--moe-backend triton` required | Add the post-SiLU clamp to AITER block-FP8 MoE |
| Sparse top-k still has unfused work | Fuse and optimize region selection |
