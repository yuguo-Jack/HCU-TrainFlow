# [ROCm][Model] Step-5-Preview support on ROCm

[Upstream PR](https://github.com/vllm-project/vllm/pull/61837) · state: open · merged: False

## Original PR description

## Overview

ROCm side of Step-5-Preview support. #61727 adds [stepfun-ai/Step-5-Preview](https://huggingface.co/stepfun-ai/Step-5-Preview) for NVIDIA (SM90/SM103 only). This PR adds the `amd/` implementation under `vllm/models/step5/`, with portable Triton kernels for compressed sparse attention (CSA) and 3-layer MTP. Validated on 8x MI300X.

The `step5` reasoning and tool parsers come from #61727. Until it lands, the existing `step3p5` parsers handle Step-5 output.

## Claims

- Step-5-Preview (FP8, TP8) serves on ROCm with text and image input, with no CUDA-only dependencies.
- CSA runs on the 23 full-attention layers for prefill, chunked prefill and decode. Its state lives in two side caches managed by the existing KV-cache manager, with no scheduler changes and no GPU-to-CPU syncs.
- MTP works with `--speculative-config '{"method":"mtp","num_speculative_tokens":3}'`: same GSM8K accuracy, about 2.3x faster (earlier revision).
- Step-5's hub `tokenizer_class` is overridden in vLLM, as for Step-3.7.

### Serving command (ROCm, MTP enabled)

<details>
<summary>Serve Step-5-Preview on 8x MI300X</summary>

```bash
VLLM_ROCM_USE_AITER=1 vllm serve stepfun-ai/Step-5-Preview \
  --tensor-parallel-size 8 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.90 \
  --attention-backend ROCM_AITER_UNIFIED_ATTN \
  --moe-backend triton \
  --mm-encoder-attn-backend ROCM_AITER_FA \
  --mm-encoder-tp-mode data \
  --mm-processor-cache-type shm \
  --limit-mm-per-prompt '{"image":1,"video":0}' \
  --reasoning-parser step3p5 \
  --tool-call-parser step3p5 \
  --enable-auto-tool-choice \
  --speculative-config '{"method": "mtp", "num_speculative_tokens": 3}'
```

After #61727 merges, switch to `--reasoning-parser step5 --tool-call-parser step5`.

| Flag | Why |
|---|---|
| `--moe-backend triton` | Required. Every MoE layer clamps SwiGLU at 7, and AITER's block-FP8 MoE does not apply that clamp yet. |
| `--mm-encoder-*`, `--limit-mm-per-prompt` | Image input through the perception-encoder tower. |
| `step3p5` parsers | Step-5 uses Step-3.5's `<think>` and `<tool_call>` format. |
| KV cache dtype | Keep the default (BF16). Sparse layers reject other dtypes. |


</details>

The 600B checkpoint does not fit in CI, so end-to-end results come from the MI300X runs. The unit tests run on any GPU runner.

## Details

- **Layout:** `vllm/models/step5/{common,amd}`. Triton kernels with explicit OCP E4M3 rounding, so gfx942 (native FP8 is E4M3FNUZ) selects the same regions as the reference.
- **Side caches:** per-token `[index_k | index_z]` rows and one summary per 8-token region, both through `MLAAttentionSpec`. Paging, prefix caching and freeing come from the KV-cache manager.
- **One custom op:** `vllm::step5_csa_attention` compresses completed regions, scores, picks the top-k and attends over the paged K/V. It is a graph splitting op, so it always sees real per-step metadata.
- **Per-batch metadata:** the index-cache metadata builder computes the token-to-request map, positions and completed-region list once per step from `CommonAttentionMetadata`.
- **K/V write:** `unified_kv_cache_update`, ordered before the CSA op through its dummy dependency.
- **Backend:** the sparse layers pin `ROCM_AITER_UNIFIED_ATTN` on their own `Attention` layer through a Step-3.5 hook, as DeepSeek-V3.2 and OpenPangu do.
- **Indexer sharding:** Q and W are `ColumnParallelLinear` sharded by provider group; K and Z stay replicated.
- **Reuse:** small class hooks in `step3p5.py` and `step3p5_mtp.py` with unchanged defaults. No changes to the scheduler, KV-cache manager, model runner or attention backends.

**Footprint:** model code 1,373 lines (11 files), tests 244 (3), registrations 39 (8), Step-3.5 hooks +21 / -11 (2).

### Limitations

| Limitation | Follow-up |
|---|---|
| Piecewise CUDA graphs only; all numbers above used them | Graph-safe CSA metadata for full graphs |
| BF16 KV cache only on sparse layers | FP8 KV |
| `--moe-backend triton` required | Post-SiLU clamp in AITER's block-FP8 MoE |
| Top-k uses a PyTorch sort | Fused radix select |
