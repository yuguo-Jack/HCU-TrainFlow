# [Bugfix][MRv1][Spec Decode] Count NaNs in logits per request, not per logits row

[Upstream PR](https://github.com/vllm-project/vllm/pull/65402) · state: open · merged: False

## Original PR description



## Overview

With the V1 model runner (MRV1) and speculative decoding, `VLLM_COMPUTE_NANS_IN_LOGITS` / `VLLM_RAISE_ON_LOGIT_NANS` attribute NaN counts to the wrong requests. Each request has `num_draft + 1` logits rows, but `count_nans_per_row` counts NaNs per row and `nans_to_dict` maps row `i` to request `i`, so request `j` gets row `j`'s count and rows past `num_reqs` are dropped. This PR sums each request's rows on device. It is the MRV1 counterpart of #65147 (MRV2).

Related: #63811 reported the MRV2 variant of this bug. #38506 fixed both runners together with a dict-to-ndarray refactor and a host copy of `cu_num_sampled_tokens`, and was closed by the stale bot on 2026-11-01 without merging. #65147 fixes MRV2 only and does not touch this file. #50283 adds a per-request aggregation for MRV2 as part of a larger NaN fault-tolerance feature and also leaves MRV1 unchanged.

## Claims

- With spec decode, `num_nans_in_logits` (and so `vllm:corrupted_requests` and the `VLLM_RAISE_ON_LOGIT_NANS` error) reports each request's own count, summed over its draft and bonus rows, under both sync and async scheduling.
- No host sync is added. The per-request sum stays on device, and the async path still copies the counts on the output copy stream. The async run below passes with `VLLM_GPU_SYNC_CHECK=error`.
- Without spec decode the result is unchanged. Only torch ops are used, since MRV1 is also the fallback when Triton is unavailable.

## Validation

pytest -v -s tests/v1/worker/test_gpu_model_runner.py -k test_get_nans_in_logits

## Details

`_calc_spec_decode_metadata` lays out the logits as each request's draft rows followed by its bonus row, so request `j` owns rows `cu_num_sampled_tokens[j-1]:cu_num_sampled_tokens[j]`. The NaN path treated the row index as the request index.

Fix:
- `count_nans_per_row(logits)` becomes `count_nans_per_request(logits, spec_decode_metadata)`. Without spec decode it returns the per-row counts as before. With spec decode it takes the prefix sum of the per-row counts at each request's last row (`cu_num_sampled_tokens - 1`) and differences it.
- `sample_tokens` passes `spec_decode_metadata` to `_bookkeeping_sync`, which uses it on both the async (device) and sync (`_get_nans_in_logits`) paths. `nans_to_dict`, `AsyncGPUModelRunnerOutput` and `ModelRunnerOutput` are unchanged.

Notes:
- MRV1 is still selected when Triton is unavailable and for configurations MRV2 does not support yet, for example parallel drafting for EAGLE or heterogeneous-vocabulary draft models. MRV2 has the same bug and is fixed separately in #65147.
- With spec decode the counts are int64 (from `cumsum`). Both paths only read them through `.tolist()`.
- `bonus_logits_indices` holds the same values as `cu_num_sampled_tokens - 1`, but `SpecDecodeMetadata.make_dummy` leaves it zeroed, so the fix reads `cu_num_sampled_tokens`.
