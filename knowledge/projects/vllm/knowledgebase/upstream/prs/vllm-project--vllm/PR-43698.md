# [Frontend] Add opt-in Unicode tag-block sanitization middleware

[Upstream PR](https://github.com/vllm-project/vllm/pull/43698) · state: open · merged: False

## Original PR description

## Overview

Adds an opt-in ASGI middleware that strips Unicode tag characters (U+E0020 to U+E007F) from request bodies sent to the LLM generation endpoints, enabled with `VLLM_ENABLE_UNICODE_FILTERING_MIDDLEWARE=true`. Supersedes #41762 (closed), which had an approval on the same design.

## Claims

- Tag characters are invisible to humans but are tokenized by the model and can steer or destabilize generations; with the flag set they are removed before the request reaches the handler, for both encodings a JSON client can use (raw UTF-8 and `\uDB40\uDCxx` escapes).
- Covers `/v1/chat/completions`, `/v1/chat/completions/batch`, `/v1/completions`, `/v1/responses`, `/v1/messages` and `/cohere/v2/chat`; all other routes, methods and characters (including emoji) are untouched.
- Off by default; zero cost on clean payloads beyond two substring checks on the buffered body.
- Fixes a bug present in the earlier revisions of this PR: the replayed `receive()` reported a synthetic `http.disconnect`, which made `with_cancellation` cancel every filtered request (empty response) and would have truncated streaming responses.

## Validation

Unit tests (`tests/entrypoints/serve/middleware/test_unicode_filter_middleware.py`, 18 cases) run the middleware against a FastAPI echo app and include a regression test that uses the real `with_cancellation` decorator and a `StreamingResponse` test; both fail on the previous revision and pass now.

End-to-end tests (`tests/entrypoints/serve/middleware/test_unicode_filter_integration.py`) start `vllm serve hmellor/tiny-random-LlamaForCausalLM --load-format dummy` with the flag set and check, via `usage.prompt_tokens`/`input_tokens` against the unfiltered `/tokenize` endpoint, that chat, completions (`echo=True`), streaming chat, Responses and Anthropic Messages requests all drop the tag characters. Both test files live under `tests/entrypoints/serve/middleware/`, which the Entrypoints Integration CI step collects.

```
.venv/bin/python -m pytest tests/entrypoints/serve/middleware/test_unicode_filter_middleware.py -v
.venv/bin/python -m pytest tests/entrypoints/serve/middleware/test_unicode_filter_integration.py -v
pre-commit run --files $(git diff --name-only upstream/main HEAD)
```

## Details

- Pure ASGI middleware (`vllm/entrypoints/serve/middleware/unicode_filter.py`), registered in `init_entrypoints_middleware` inside the authentication middleware so unauthenticated requests are rejected before any body is buffered.
- Filtering runs on the UTF-8 bytes: every codepoint in the block is a 4-byte sequence with prefix `F3 A0 80|81`, so one bytes regex covers the block without a decode/encode round trip. A second regex handles the JSON surrogate-pair escape and leaves escaped backslashes (`\\uDB40`) alone, since those are literal text.
- The body is buffered once in the middleware and replayed to the app; after the replay, `receive()` defers to the server's own `receive()` so disconnect detection keeps working.
- Limitation: only JSON-encoded tag characters in the request body are handled; characters that arrive through other channels (for example, a prompt fetched by the model from a tool result) are out of scope.
- The toggle is an environment variable, matching the predecessor PR's approved design; a `FrontendArgs` flag would also fit if maintainers prefer that.

AI assistance (Claude Code) was used for the rebase, the bug fix, the tests and this description; every line was reviewed by the submitter, and the commands above were run locally on an RTX 3500 Ada (12 GB).
