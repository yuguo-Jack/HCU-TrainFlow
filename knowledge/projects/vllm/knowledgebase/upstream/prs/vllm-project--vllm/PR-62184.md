# [CPU][RISC-V] Enable chunked prefill and prefix caching on RISC-V

[Upstream PR](https://github.com/vllm-project/vllm/pull/62184) · state: open · merged: False

## Original PR description



## Overview

Enabled chunked prefill and prefix caching on RISC-V CPUs.

## Claims

- Chunked prefill and prefix caching are enabled on RISC-V CPUs.

## Validation

Tested on main @ f98ae6a9fd + this change under QEMU (qemu-riscv64 11.0.2, RVV VLEN 128, attention ISA `rvv`) with `meta-llama/Llama-3.2-1B-Instruct`, `block_size=32`, `max_num_batched_tokens=32`, on three greedy prompts (79/79/78 tokens; prompts 2 and 3 share a 64+-token prefix and run in that order):

- Chunked prefill acted: prompts 1 and 2 were scheduled as 32 + 32 + 15 tokens per step (`SchedulerOutput.num_scheduled_tokens`); main schedules each in one 79-token step.
- Prefix caching acted: prompt 3 reported `num_cached_tokens=64` (two 32-token blocks matched by block hash) and computed the remaining 14 tokens in one step; main reports 0.
- The generated token ids equal main's on all three prompts, with the features off and on.

Kernel test, same build under QEMU: `pytest tests/kernels/attention/test_cpu_attn.py -k "normal_rvv and (seq_lens1 or seq_lens2) and dtype2 and auto"` → 72 passed
