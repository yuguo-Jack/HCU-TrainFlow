# [Doc] Add Apple Silicon model compatibility note to quickstart

[Upstream PR](https://github.com/vllm-project/vllm/pull/57739) · state: closed · merged: False

## Original PR description

## Purpose

Warns Apple Silicon (vLLM-Metal) users that some models cannot be loaded:

1. vLLM-Metal loads weights through MLX, which requires `.safetensors` checkpoints.
2. Some models, such as `facebook/opt-125m`, only ship legacy `.bin` weights and
   fail with `FileNotFoundError: No safetensors found in ...`.
3. Use a model that ships safetensors instead, for example `Qwen/Qwen3-0.6B` (the
   default model for `vllm serve`) or an MLX-optimized model from
   [mlx-community](https://huggingface.co/mlx-community) such as
   `mlx-community/Qwen2.5-0.5B-Instruct-4bit`.

Documentation-only change; no code is touched.

## Why the note moved

This PR was previously open as #57739 and put the note in the general quickstart
guide. @mgoin closed it with "This detail doesn't belong in the general docs",
which is right: the note only applies to Apple Silicon users running vLLM-Metal,
and it made the quickstart example conditional on the reader's platform.

This revision moves the note into the Apple Silicon tab of the CPU installation
page (`docs/getting_started/installation/cpu.apple.inc.md`), directly after the
vLLM-Metal tip, and drops the quickstart change entirely.

## Relationship to #62747

#50165 was closed as not planned in favour of #62747, which replaces
`facebook/opt-125m` with `Qwen/Qwen3-0.6B` across the doc examples. That
addresses the same underlying problem for the general examples.

This PR does not touch any of the pages #62747 changes, so the two do not
overlap. What is left over is the Apple Silicon installation page, which still
does not mention that the model needs to ship safetensors for MLX to load it.
