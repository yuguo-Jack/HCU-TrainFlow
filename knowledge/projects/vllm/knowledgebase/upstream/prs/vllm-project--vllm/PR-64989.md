# [Bugfix][HiSparse] Release temporary device KV bindings after graph profiling

[Upstream PR](https://github.com/vllm-project/vllm/pull/64989) · state: closed · merged: True

## Original PR description

## Overview

Release HiSparse's temporary device KV bindings after CUDA-graph memory profiling, while preserving the engine-scoped registered host pool for the real KV cache.

## Claims

- Live attention handles and runtimes no longer retain the throwaway KV slab and its per-binding tables after profiling cleanup.
- Cleanup is idempotent. Rebinding preserves host registration and clears stale hot-cache tags before the new backing is consumed.
- No throughput, accuracy, or reproduced model OOM improvement is claimed.

## Details

The profiling teardown clears the runner's normal caches, but model layers still own HiSparseCacheHandle objects. Their PagedCacheView and Runtime.hot keep the temporary device backing alive. release_pinned_state(..., []) removes only some runtime aliases; it does not detach those handle-owned device views.

Separate per-binding detachment from final host-pool shutdown. Keep the permanent index group, streams, and shared workspaces; drop only storage and metadata associated with the old KV binding. Group leaders reset the existing hot state when binding new storage.

Duplicate-work review: #61668 is the merged host-pool reuse change and leaves these device aliases attached. The inspected open ROCm PR #60358 addresses other cleanup/registration behavior, without this device-binding detachment. Searches for HiSparse profiling release and the exact cleanup function found no open PR addressing this fix as of 2026-11-01.
