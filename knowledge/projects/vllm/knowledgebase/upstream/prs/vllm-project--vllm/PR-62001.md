# [Bugfix][Kernel] Preserve output shape in FlashInfer FP8 linear

[Upstream PR](https://github.com/vllm-project/vllm/pull/62001) · state: open · merged: False

## Original PR description

## Overview

Restore the leading dimensions of FlashInfer FP8 linear outputs instead of returning the flattened GEMM result. Follows #44728 by @lishunyang12, which was closed without merging.

## Claims

- Preserve the `[..., out_features]` output contract for higher-dimensional activations.
- Leave FP8 quantization, scales, bias and GEMM computation unchanged.

## Validation

**Draft: real FlashInfer CUDA and serving-engine validation are pending.**

Base: `64175d38277f3731069cabaa9cb88983ee314f85`. CPU implementation witness: `3bb21698bdb871891f1a0e227b501bb9dca7b7a2`. Current head: `25ebcd72c70641f7d4fa70112aeb8526ba83d02b` (test-only parameterization follow-up; the runtime kernel is unchanged).

A local CPU isolation check imports the real `apply_weights` and `QuantFP8` code, replacing only the CUDA-specific FlashInfer helper with CPU `torch._scaled_mm`. BF16 plain and pre-quantized activations, with and without bias, preserve the requested 2D/3D/4D shapes after this change; the original implementation incorrectly returns 2D for the higher-dimensional cases. Flattened baseline/patched values are bitwise equal and match a dequantized FP32 reference within tolerance. This is wrapper-level validation, not execution of FlashInfer CUDA.

The existing GPU suite now exercises the concrete backend's `apply_scaled_mm` method and requests 2D/3D/4D outputs. Existing dtype, bias, autotune and padded-shape coverage is retained, and its existing Buildkite SM100 job already includes this suite.

```sh
.venv/bin/python -m pytest -q -rs tests/kernels/quantization/test_flashinfer_scaled_mm.py
.venv/bin/pre-commit run --files \
  vllm/model_executor/kernels/linear/scaled_mm/flashinfer.py \
  tests/kernels/quantization/test_flashinfer_scaled_mm.py
git diff --check
```

At the CPU implementation witness above, affected-file pre-commit, including mypy and CI test tethering, and `git diff --check` passed. The test-only follow-up retains the original numerical/autotune matrix and adds two focused higher-dimensional cases; its remote source was syntax-checked, but the new GPU cases have not run here. On the available macOS CPU environment the GPU suite is skipped at its SM100 hardware gate; real FlashInfer CUDA and serving-engine validation remain pending. No throughput or model-quality improvement is claimed.

## Details

The FP8 base class flattens activations for GEMM and passes the original leading dimensions in `output_shape`. This backend discards that argument while other ScaledMM backends restore it. Reshape the existing GEMM output with a view, without adding a copy or changing numerical operations.

Open-PR searches covered FlashInfer/FP8 output shape, the concrete class name, and the previous PR number. No open PR for this output-shape fix was found. The separate non-contiguous-input change is excluded because open #37620 already addresses it.

AI assistance was used to investigate, implement, test and prepare this change. The submitting human reviewed the diff and authorized publication as a draft with GPU validation pending. No human-run tests are claimed.
