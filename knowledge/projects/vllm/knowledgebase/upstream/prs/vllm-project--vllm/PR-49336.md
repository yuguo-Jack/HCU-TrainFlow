# [Bugfix] Fix DBRX MoE weight loading after FusedMoE/MoERunner refacto…

[Upstream PR](https://github.com/vllm-project/vllm/pull/49336) · state: open · merged: False

## Original PR description

**Purpose**
DbrxForCausalLM currently fails to load on main (and on the v0.24.0/v0.25.0 tags). Serving any DBRX checkpoint crashes immediately during weight loading with:
File ".../vllm/model_executor/models/dbrx.py", line 403, in load_weights
    param = params_dict[name]
KeyError: 'blocks.0.ffn.experts.w13_weight'

This happens before any device dispatch, so it reproduces on every backend (CPU, CUDA, or a hardware plugin).
The root cause is a missed spot from the [MoE Refactor] FusedMoE/MoERunner inversion refactor (#41184). That refactor turned FusedMoE from a class that directly owned its expert weights into a factory returning a MoERunner that wraps a separate RoutedExperts submodule, so expert weights now live one path segment deeper — experts.routed_experts.w13_weight instead of experts.w13_weight. DBRX's model definition was updated for this (DbrxExperts subclasses RoutedExperts, DbrxMoE.__init__ uses the new factory), but DbrxModel.load_weights still uses a hand-written expert_params_mapping that produces the old, one-segment-too-short names, so the lookup against the newly-nested parameters fails.

The follow-up bugfix #45054 ("Fix weight loading issues caused by #41184") patched exactly this class of bug in five other files (aria.py, qwen3_vl_moe.py, step3_text.py, step3p5.py, deepseek_v4/quant_config.py) — DBRX was simply not in that list. Most other MoE models avoided the problem because they delegate to the generic AutoWeightsLoader, which walks the new submodule structure automatically; DBRX is one of the few still using a hand-rolled loader.
This PR adds the missing routed_experts. segment to expert_params_mapping in DbrxModel.load_weights, mirroring the exact fix #45054 applied to aria.py/qwen3_vl_moe.py, plus a regression test.
Fixes #49004

**Test Plan**
Added tests/models/test_dbrx.py, a regression test that builds a real DbrxModel from a minimal DBRX config (d_model=32, n_layers=1, ffn_hidden_size=64, 4 experts) and:

Verifies the model registers its expert weights under routed_experts.w13_weight / routed_experts.w2_weight, and that the old un-prefixed names do not exist.
Calls the real DbrxModel.load_weights with HuggingFace checkpoint-format names (mlp.w1, mlp.v1, mlp.w2) and confirms the returned loaded_params contains the routed_experts.* names.

**Run with:**
bashpytest tests/models/test_dbrx.py -v
Test Result
Without the fix, the test reproduces the reported failure exactly:
vllm/model_executor/models/dbrx.py:403: KeyError: 'blocks.0.ffn.experts.w13_weight'
With the fix applied, it passes:
tests/models/test_dbrx.py::test_dbrx_load_weights_maps_checkpoint_names_to_routed_experts PASSED
pre-commit run --all-files is clean.
