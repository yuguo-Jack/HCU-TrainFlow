# [CI][XPU] Deselect Mamba deep-sleep case in Intel CI

[Upstream PR](https://github.com/vllm-project/vllm/pull/64057) · state: closed · merged: True

## Original PR description

Temporarily deselect only `test_deep_sleep[yujiepan/mamba2-codestral-v0.1-tiny-random]` in Intel CI following [build 15537](https://buildkite.com/vllm/intel-ci/builds/15537#01a17cd0-a2c9-4e46-bcd3-e20466c4b258): vllm-project/vllm#63548 exposed existing XPU model-state loss with a stronger assertion; this is a CI mitigation, not a runtime fix. This updates the existing PR rather than duplicating it, restores all other sleep-mode cases, retains the pre-existing cumem deselection, and leaves CUDA/ROCm unchanged; re-enable the Mamba case once XPU nested memory pools are supported.

Validation: parsed the YAML command and ran its exact memory-test arguments through `.venv/bin/python -m pytest --collect-only -q` from `tests/`: **35 selected, 2 deselected** (Mamba deep sleep plus the existing cumem case), with other sleep-mode cases retained; `.venv/bin/pre-commit run --files .buildkite/intel_jobs/basic_correctness_intel.yaml` passed. Collection temporarily moved aside and restored a local CUDA-only extension requiring unavailable `libcuda.so.1`; runtime tests were not rerun for this selection-only change. AI assistance was used.
