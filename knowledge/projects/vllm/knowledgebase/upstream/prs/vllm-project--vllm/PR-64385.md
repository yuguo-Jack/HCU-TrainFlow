# [MRV2][DBO] Add stage-local FULL decode graphs for pipeline parallelism

[Upstream PR](https://github.com/vllm-project/vllm/pull/64385) · state: open · merged: False

## Original PR description

## Overview

Stage-local FULL decode graphs for PP+DBO in MRV2, tracking #64354. **Depends on eager Draft #64350; not ready to merge.** Static review and CPU unit tests only.

## Claims

- Allow `FULL_DECODE_ONLY` in addition to eager for PP+DBO, under the same scope as #64350: `--enable-dbo`, NIXL EP with DP>1 and expert parallelism, TP=1, synchronous scheduling. `FULL` and `FULL_AND_PIECEWISE` stay rejected.
- Reuse the existing MRV2 graph manager, microbatch capture lifecycle and coordinated eager fallback.
- Let each stage choose its own graph padding: under DBO a stage sends only its real rows, and the next stage copies them into its persistent input buffers before padding to its own size.
- Fall back to eager under PP when a rank's last microbatch would hold only padding.

## Details

The increment on top of #64350 is **+32/-11** in production code: the graph mode in the PP+DBO condition, real-row PP send/receive under DBO in the model runner, and the empty-microbatch fallback in DP sync. The cumulative diff includes #64350 until it merges.

Duplicate checks searched #64354 and pipeline/DBO keywords and read the issue comments. #64350 is the eager prerequisite, not this graph extension. No open implementation for this scoped graph increment was found.

Before readiness: human line-by-line review, real PP2 × DP2 CUDA capture/replay on all workers, repeated changed-input replay, idle-rank recovery, graph/eager transitions, model outputs/logprobs and graph-memory/performance measurements. AI assistance was used for implementation, review and tests.
