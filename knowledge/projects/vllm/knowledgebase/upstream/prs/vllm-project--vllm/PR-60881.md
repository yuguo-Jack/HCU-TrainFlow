# [Security] Validate NIXL peer topology before rank expansion

[Upstream PR](https://github.com/vllm-project/vllm/pull/60881) · state: open · merged: False

## Original PR description

## Overview

NIXL handshake requests can carry a peer TP size that controls rank-list construction. Validate that claim against peer metadata before expanding ranks, and use constant-time rank membership for the Mooncake inbound path.

## Claims

- Reject a NIXL peer topology mismatch before peer-provided dimensions can allocate a large rank list.
- Preserve existing target-rank pairing behavior while avoiding a rank-list allocation in Mooncake's inbound validation path.

## Validation

- `.venv/bin/python -m pytest tests/v1/kv_connector/unit/test_transfer_topology_sharded.py -q` — 10 passed.
- Focused NIXL handshake regression tests — 2 passed.
- Ruff check/format, `py_compile`, `git diff --check`, and commit hooks — passed.
- Broader NIXL handshake tests could not initialize Gloo in this environment; the Mooncake test module could not collect because the installed `huggingface_hub` lacks an import expected by this checkout.

## Details

Root cause: the handshake accepted peer-provided topology dimensions and expanded the resulting target-rank list before checking whether those dimensions matched the actual peer. A forged oversized TP value could therefore trigger excessive work or memory use before validation.

The request flow is: (1) a worker sends the expected TP/DCP/PP sizes; (2) the peer returns metadata for rank (0, 0); (3) the receiver validates the actual topology against the requested sizes; (4) only then does it derive the target ranks and continue registering agents. Mooncake's corresponding inbound check now tests rank membership arithmetically instead of materializing a list.

The NIXL metadata version is incremented because TP and PP sizes are now advertised. New fields retain defaults for decoding older metadata, while the version handshake ensures incompatible peers are rejected.

Duplicate-work check: searched open and merged PRs for the NIXL handshake/topology paths and related connector changes. No existing PR implements validation of peer-advertised topology before rank expansion. PR #55470 addresses expired deferred writes, a separate lifecycle issue; PR #39529 reorganizes topology helpers but does not add this validation.

AI assistance was used to develop and validate this change; the human maintainer reviewed it.

`remote_host` and `remote_port` come from the same request-supplied `kv_transfer_params` as the size, so anyone who can forge the size can also point D at a listener that echoes it back, and this check passes. If these params can come from untrusted clients, the fix belongs at the trust boundary: reject or overwrite client-supplied `kv_transfer_params`, or allowlist prefill addresses.

Either way, a simple cap on remote_tp_size/remote_pp_size would bound the allocation more cheaply than the rank-0 probe.
