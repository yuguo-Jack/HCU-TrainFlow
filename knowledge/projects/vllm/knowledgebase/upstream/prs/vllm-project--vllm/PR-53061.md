## Overview

Apply the existing empty-splitting-ops CUDA graph downgrade before the non-VLLM_COMPILE early return. Addresses #53030; refreshed against main `c5f8adc0`.

## Claims

- Reuse the existing downgrade logic for both compilation paths, mapping PIECEWISE to NONE and FULL_AND_PIECEWISE to FULL when splitting ops are empty.
- Keep the fix and the two regression cases aligned with current compilation configuration.

## Validation

- `.venv/bin/python -m pytest tests/compile/test_config.py -k empty_splitting_ops -q` — **2 passed**.
- Both regression cases fail against unmodified main production code.
- Pre-commit on both changed files and `git diff --check origin/main...HEAD` — **passed**.
- The broader test-file attempt was stopped after **11 failed / 7 passed**: device inference/model-loading environment failures and an unrelated rotary-embedding configuration expectation. The latter also fails on unmodified main in the control run. The full suite is not reported as passing.
- No current-head speculative-decoding/model/GPU evaluation ran because CUDA cannot initialize.

## Details

The early return previously bypassed the same safety downgrade that the compiled path already applies. This change reuses that logic rather than changing graph keys or attention implementations. The issue's hardware observations are external evidence, not a current-head GPU result from this host.

Duplicate check: re-read #53030 and searched open PRs by issue number and the empty-splitting-ops guard; no other open fix for this exact early return was found. Open since 2026-08-20.

AI assistance was used for the refresh, with signed, signed-off commits and Codex attribution. Human review and current-head GPU validation remain required.
