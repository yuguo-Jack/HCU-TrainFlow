# [ROCm][CI] Download quick-reduce e2e model when cached snapshot has no weights

[Upstream PR](https://github.com/vllm-project/vllm/pull/63127) · state: closed · merged: True

## Original PR description

## Problem

`test_quick_allreduce_llm_e2e` and `test_quick_allreduce_llm_e2e_ray` in `tests/distributed/test_rocm_quick_reduce.py` fail in `(MI300) Distributed Features` because the engine cannot start: `RuntimeError: Cannot find any model weights with /home/buildkite-agent/huggingface/hub/models--Qwen--Qwen2.5-0.5B-Instruct/snapshots/7ae55760...`.

Failure: https://buildkite.com/vllm/amd-ci/builds/15208/list?jid=01a1636b-f116-4ace-b3ca-bdae8a9f5e55&tab=output

## Cause

No recent commit changed this test. `_get_model_path()` was added in #40990 and returns the local snapshot whenever `snapshot_download(local_files_only=True)` succeeds. If only the config and tokenizer are in the HF cache (for example, after another test fetched them with `hf_hub_download`), `huggingface_hub` has no cached file listing for the repo, so it cannot tell that the snapshot is incomplete and returns the folder without weights. Whether the test passes depends on the node's cache. The previous nightly passed on a node whose cache had the weights, with the same snapshot path.

## Fix

Use the cached snapshot only if it contains `*.safetensors`. Otherwise fall back to the existing download path.

## Test plan

On MI300X, with an HF cache holding only the config and tokenizer files for `Qwen/Qwen2.5-0.5B-Instruct`, so that the old code returns a snapshot without weights: `pytest -v -s tests/distributed/test_rocm_quick_reduce.py -k "test_quick_allreduce_llm_e2e and not ray"` downloads the snapshot and passes.
