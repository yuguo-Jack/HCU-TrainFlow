# [Spec Decode][GLM-5.3-Flash] Skip indexer metadata in MTP draft steps that reuse the top-k

[Upstream PR](https://github.com/vllm-project/vllm/pull/64072) · state: open · merged: False

## Original PR description

## Overview

With `index_share_for_mtp_iteration`, MTP draft steps after the first reuse the first step's top-k and skip the indexer entirely, but the fused draft loop still refreshes the indexer caches' decode metadata before every draft step. This PR skips that refresh for attention groups the draft steps do not read.

## Claims

- GLM-5.3-Flash with MTP 3: 20 fewer kernels and 31–37 µs less GPU time per decode step (2 of the 3 `paged_mqa_logits_metadata` launches and their buffer fills).
- Greedy outputs are unchanged.
- Other speculators and models are unaffected: the base speculator's new `draft_decode_reads` hook returns True for every group.

## Validation

GLM-5.3-Flash (FP8), 4x GB300, TP4, MRV2, `FLASHINFER_MLA_SPARSE`, FP8 KV cache, MTP with 3 speculative tokens, FULL decode CUDA graphs, no prefix caching.

Kernels per decode step on rank 0, from nsys traces of 24 decode steps, before -> after. A second run gave the same counts and times within 1 µs.

| batch | `paged_mqa_logits_metadata` | buffer fills (`vectorized_elementwise_kernel`) | all kernels | GPU time of the changed kernels |
|---|---|---|---|---|
| 1 | 3 -> 1 | 119 -> 103 | 1680 -> 1660 | 308 -> 272 µs |
| 8 | 3 -> 1 | 120 -> 104 | 1758 -> 1738 | 218 -> 187 µs |
| 16 | 3 -> 1 | 122 -> 106 | 1847 -> 1826 | 229 -> 192 µs |

Greedy A/B against the same build without this change, 8 prompts in one batch, 128 output tokens, top-5 logprobs, engine core in process: all 8 outputs and their logprobs are identical.

`pytest tests/v1/worker/test_gpu_target_dependent_ar_speculator.py`: 31 passed. The new test checks that the indexer group is skipped only when the top-k is shared, and that the draft model receives the last-token rows; it fails without the speculator change.

## Details

`DraftModelSpeculator._update_draft_decode_metadata` now asks `draft_decode_reads(layer_names)` before updating each attention group. The MTP speculator answers False for groups whose layers are all indexer caches when the draft model shares the top-k across draft steps, and the GLM-5.3-Flash MTP model reports those layers through `topk_cache_layers()`. The skip is safe because a draft step with `skip_topk` set does not run the indexer at all, including its K-cache write, so nothing reads or writes through that metadata. Backends that cannot update draft decode metadata in place still rebuild all metadata as before.

The MTP speculator also passes its `last_token_indices` buffer to the draft model if the model defines `set_prefill_rows`, so a draft model can compute its draft prefill only at the rows that are sampled. No model on main defines it yet; #63102 (GLM-5.3-Flash specialized decode) does.

Not a duplicate: #54790 makes the indexer's draft metadata update fused under DCP, and #61670 does the same for FlashInfer sparse MLA. Neither skips groups the draft steps do not read. #54790 touches the same speculator files, so whichever lands second needs a small rebase.
