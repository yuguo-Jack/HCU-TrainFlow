# [Perf][Startup] Keep openai out of import vllm.config via lazy ToolServer import

[Upstream PR](https://github.com/vllm-project/vllm/pull/65423) · state: closed · merged: True

## Original PR description



## Overview

Every vLLM process imports `vllm.config`, and `vllm.config.reasoning` → `vllm.reasoning` → `abs_reasoning_parsers` imports `vllm.entrypoints.mcp.tool_server` at module level, which pulls in `openai` and `openai_harmony`. `ToolServer` is only used in a type annotation there, so this PR moves the import under `TYPE_CHECKING`. This is the "`vllm.config.reasoning` → `entrypoints.mcp` → `openai.types`" item in #59433, and the PR extends `tests/standalone_tests/lazy_imports.py` as the issue proposes.

## Claims

- `import vllm.config` no longer imports `openai` / `openai_harmony` (524 modules before, 0 after on CPU; checked on CUDA as well).
- `vllm.config.reasoning` cumulative import time drops from ~310-440 ms to ~6-9 ms (`python -X importtime -c "import vllm.config"`, CPU, 3 runs).
- `tests/standalone_tests/lazy_imports.py` now fails if `import vllm.config` imports `openai` again (see the CI note below).

## Details

- `abs_reasoning_parsers.py` has no `from __future__ import annotations`, so the one annotation that uses `ToolServer` (`prepare_structured_tag`) is quoted. Nothing in the file uses `ToolServer` at runtime.
- `lazy_imports.py` blocks `openai` the same way it blocks `cv2`, and adds `import vllm.config`, since `import vllm` alone does not import the config package.
- The API server still imports `openai` through the OpenAI entrypoints; this only keeps it out of the shared config import that EngineCore and workers also pay for.
- CI: `lazy_imports.py` currently runs only in the `(CPU) Params, Env, Tokenizers, Parser` job, which is commented out in `.buildkite/test_areas/misc.yaml` (disabled by #63609). #64414 restores it. I left the Buildkite config alone to keep this PR small.
- Not a duplicate: no open PR touches `abs_reasoning_parsers.py` or blocks `openai` in `lazy_imports.py`. #57310 also adds lines after `import vllm  # noqa` in `lazy_imports.py`, so whichever lands second needs a trivial rebase.
