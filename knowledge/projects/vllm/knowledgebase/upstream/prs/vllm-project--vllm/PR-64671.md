## Changes

- CPU DP/EP uses Gloo/TCP through the existing `allgather_reducescatter`, including variable-size gather/reduce-scatter for multi-node.
- CPU dispatch (`all_gatherv`) and combine (`reduce_scatterv`) receive the current token counts for each rank. Compiled code is cached separately for each communication group and rank. Reloading standard PyTorch Inductor code skips setup needed only by vLLM’s compiler backend.
- Existing expert selection/loading and global-to-local mapping are reused; input-weighted routing preserves router weights, and separate shared experts are tested on origin tokens after routed combine.
- The existing CPU CI lane is extended, and rendered CPU installation / DP / EP documentation describes backend choice, private peer TCP reachability, dynamic listener ports, and validation boundaries.

BF16 unquantized TP=PP=PCP=1, DP=EP is the reference test configuration, not a runtime allowlist. No BF16-only gate, forced attention/expert implementation or communication dtype cast is introduced. Dynamic CPU EPLB is separate work. No performance improvement is claimed.
