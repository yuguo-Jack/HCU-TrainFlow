# [ROCm] cuMem: allow a single physical allocation per KV cache tensor

[Upstream PR](https://github.com/vllm-project/vllm/pull/62857) · state: open · merged: False

## Original PR description



## Overview

Adds `CuMemAllocator.use_memory_pool(tag, single_allocation=True)`, so that on ROCm a tensor allocated for sleep mode can be registered with an RDMA NIC. MoRIIO sleep mode (#62832) uses it for its KV cache. Part of #59055.

This is the allocator part of #60693 by @indianspeedster, trimmed and split out for separate review. Nothing else in #60693 overlaps it.

## Claims

- Inside `use_memory_pool(..., single_allocation=True)`, each allocation is backed by one physical allocation created with the POSIX fd handle type, instead of 256 MB chunks.
- The allocation keeps that handle type when sleep mode creates it again on wake-up.
- Nothing changes for other allocations, or on CUDA, which never splits allocations.

## Validation

On MI355X (ROCm 7.2), with the extension rebuilt from this branch:

```bash
pytest tests/basic_correctness/memory/cumem/test_cumem.py   # 22 passed
pre-commit run --from-ref origin/main --to-ref HEAD         # passed
```

The new `test_single_allocation_survives_sleep` covers a 600 MiB tensor allocated with the flag:
- it is one chunk;
- it keeps its contents across a sleep with offload and a wake-up;
- it is still one chunk afterwards.

A same-size tensor allocated without the flag is still chunked. The extension builds with the same compiler warnings as main. E2E with an RDMA-registered KV cache is in #62832.

## Details

On ROCm the cuMem allocator backs every allocation with 256 MB physical chunks (`VLLM_ROCM_SLEEP_MEM_CHUNK_SIZE`), created with no shareable handle type. An RDMA NIC can't register such a tensor:
- `ibv_reg_mr` and HSA's dmabuf export (`hsa_amd_portable_export_dmabuf`) both reject `hipMemCreate` memory. For an 8 GiB cuMem KV cache on MI355X, registered through Mooncake's ROCm transfer engine, they returned `ENOMEM` and `HSA_STATUS_ERROR_INVALID_ALLOCATION`. For a KV cache of the same size from `hipMalloc` (sleep mode off), `ibv_reg_mr` succeeded.
- The remaining route exports the allocation handle as a POSIX fd (`hipMemExportToShareableHandle`). That needs one physical allocation created with that handle type.

Design:
- The flag is `thread_local`, so it affects only allocations made by the thread inside the context.
- On wake-up, the handle type is read from a third item in each chunk's `(handle, size)` tuple, since the context is no longer active then.
- The chunked default stays for everything else, because the sleep-mode docs warn that larger chunks can OOM.
