# [CI][AMD] Move 17 test groups from MI300 to MI355 and test large DeepSeek/Nemotron evals on AITER

[Upstream PR](https://github.com/vllm-project/vllm/pull/61955) · state: closed · merged: True

## Original PR description

- Move 14 single-GPU groups from `mi300_1` to `mi355_dpx`, and LM Eval Large Models / ROCm Harness from `mi300_8` to `mi355_8` (`test-amd.yaml` + `test_areas` mirrors)
- Move LM Eval KV-Offload Large (DeepSeek-V4-Flash) from `mi300_4` to `mi355_4`
- Drop the MI300 copies whose MI355 twin already exists: Extended Pooling, Multimodal Extended Generation 1 / Extended Pooling, LM Eval Large Models
- Retire the MI300 DeepSeek R1 / V3.2 evals that ran on `TRITON_ATTN` (`models-mi3xx.txt`, `*_MI325.yaml`). Both models already run on MI355 with `ROCM_AITER_MLA(_SPARSE)` and AITER MoE
- Nemotron 3 Super (MI355): use `ROCM_AITER_FA` attention
- V1 E2E Hybrid Chunked Prefill: drop the stale `num_gpus: 4` (the test is TP1, and the mirror already used one GPU)

This is a subset of #60480, split out so these groups move first. DeepSeek R1, V3.2, V4 and Nemotron 3 Super should be gated on AITER on MI355 instead of Triton on MI300. R1, V3.2 and V4 already resolve to AITER on MI355, so for them this PR only removes the MI300 Triton runs and moves the V4 KV-offload eval. Nemotron 3 Super can only switch attention: AITER MoE rejects its non-gated ReLU² experts (`kernel does not support no act_and_mul MLP layer`), and there is no AITER Mamba backend. With `ROCM_AITER_FA`, the CI eval passes 10/10 for each Nemotron config on MI355 (TP4), and accuracy matches the default `ROCM_ATTN`:

| GSM8K, 10 runs | `ROCM_ATTN` (current) | `ROCM_AITER_FA` (this PR) |
|---|---|---|
| Nemotron-3-Super-FP8 | 0.9329 median (0.9295–0.9356) | 0.9325 median (0.9265–0.9409) |
| Nemotron-3-Super-BF16 | 0.9352 median (0.9325–0.9393) | 0.9352 median (0.9318–0.9409) |

The DeepSeek-V4-Flash KV-offload eval passes on MI355 (0.96–0.98 vs a 0.90 threshold).
