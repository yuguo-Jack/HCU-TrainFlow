# [XPU][CI] Re-enable `test_reset_prefix_cache_e2e` and `test_scheduler_e2e` on XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/62656) · state: open · merged: False

## Original PR description

## Overview
The Intel V1 job skips two prefix-caching end-to-end tests in `v1/core`. This PR removes both `--ignore` flags and makes `test_scheduler_e2e.py` work on XPU by optimizing the xpu block size logic. 

## Claims
- Both tests pass on XPU and now run in the Intel V1 job.

## Details
These 2 test files were skipped in the original Intel CI Enabling PR https://github.com/vllm-project/vllm/pull/37447. No change after that. But they do work well on XPU. So this PR adds them back.

Without this PR, KV Cache initialization will fail with the following error if user pass `block-size=16` to the LLM class like [here](https://github.com/vllm-project/vllm/blob/main/tests/v1/core/test_scheduler_e2e.py#L21):

The error comes from the block size limitation introduced in PR https://github.com/vllm-project/vllm/pull/57297. This PR adds the `_get_xpu_kernel_block_sizes` function to respect user's config.

After this PR, the XPU Flash Attention block size behavior is like this:

Config | Before (main) | After (this PR)
-- | -- | --
no --block-size | FA, block 64 | unchanged
--block-size 16 | `ValueError: No common block size for 16 (FLASH_ATTN: [MultipleOf(64)])` at KV cache init | FA, block 16 with `WARNING block_size=16 is supported by Flash Attention on XPU but is not a multiple of 64, which is the tuned path; performance may be lower`.
--block-size 32 | late ValueError at KV cache init as above | FA, block 32, same warning
--block-size 128 | FA, block 128 | unchanged
--block-size 129 | late ValueError at KV cache init | fails early at backend selection: `ValueError: Flash Attention on xpu does not support block_size=129. Supported: [MultipleOf(16)]`
dtype=float32, no --block-size | TRITON_ATTN, block 16, plus a spurious warning | TRITON_ATTN, block 16, no spurious warning
