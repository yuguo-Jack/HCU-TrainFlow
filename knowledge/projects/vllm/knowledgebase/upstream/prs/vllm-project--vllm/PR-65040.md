# [Doc] Use the dash-separated CLI flag names in the remaining docs

[Upstream PR](https://github.com/vllm-project/vllm/pull/65040) · state: open · merged: False

## Original PR description

## Purpose

Part of #65042

This is a documentation-consistency change.

`vllm serve` parses its arguments with `FlexibleArgumentParser`, which rewrites underscores in option names to dashes before the options are looked up, so both spellings are accepted:

```bash
--compilation_config   == --compilation-config
--logits_processors    == --logits-processors
--speculative_config   == --speculative-config
--kv_transfer_config   == --kv-transfer-config
--max_model_len        == --max-model-len
```

The underscore spellings were therefore not broken, they were only inconsistent with the rest of the docs, which use the dash-separated spelling of the very same options. This PR makes the touched pages consistent.

`docs/design/custom_op.md` additionally used a dotted spelling, `--compilation_config.custom_ops '[...]'`. That spelling is accepted as well: `FlexibleArgumentParser` rewrites the part before the first `.` to `--compilation-config.custom_ops`, which it then passes to `--compilation-config` as JSON, so it is equivalent to:

```bash
--compilation-config '{"custom_ops": ["all"]}'
```

The page now spells it out this way, which is easier to read.

Documentation-only change; no code is touched.

Files touched:

- `docs/design/torch_compile.md`
- `docs/design/debug_vllm_compile.md`
- `docs/design/custom_op.md`
- `docs/serving/expert_parallel_deployment.md`
- `docs/features/custom_logitsprocs.md`
- `docs/features/speculative_decoding/extract_hidden_states.md`
- `docs/getting_started/installation/gpu.xpu.inc.md`

## Test Plan

Every `vllm serve` command in the touched pages was replayed against the option parser that `vllm serve` actually builds, i.e. `FlexibleArgumentParser` with `EngineArgs.add_cli_args` (`vllm/engine/arg_utils.py`) and `FrontendArgs.add_cli_args` (`vllm/entrypoints/common/cli_args.py`).

With `FlexibleArgumentParser`, all documented commands parse with either spelling, before and after this change. The same commands fail on the underscore spelling only when the options are registered on a plain `argparse.ArgumentParser`, i.e. without the underscore-to-dash rewrite.

The new `custom_ops` payloads were additionally checked to be valid JSON and to match the `CompilationConfig.custom_ops` semantics (`+op` enables an op, `-op` disables it, and `all`/`none` are the base modes).

## Test Result

- 0 underscore-style options left in the touched pages.
- 0 unresolved options in the documented `vllm serve` commands.
