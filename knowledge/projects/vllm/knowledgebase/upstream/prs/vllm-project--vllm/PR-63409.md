# [ROCm][Bugfix][Kimi-K3] Pass zero positions to the fused MLA decode q-prep kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/63409) · state: closed · merged: True

## Original PR description

## Purpose
Fixes a large accuracy regression for Kimi-K3 on ROCm when DCP is off (dcp1). It comes from the fused decode q-prep path added in #59634.

`KimiK3MultiHeadLatentAttentionWrapper._fused_decode` gives AITER's `fused_qk_rope_concat_and_cache_mla` a **one-row** identity cos/sin cache (K3 is NoPE). It also passes the **real** token positions, assuming the kernel clamps them into the cache.

That assumption is false on AITER v0.1.26. DeepSeek-shaped inputs now go to the head-grouped `fused_qk_rope_concat_and_cache_mla_seg_kernel<PAGE_SIZE=0>`, which only clamps on the DCP (`compute_all_q_rope`) path:
- **One head per block**, i.e. every small decode batch (`T*H/num_CU <= 32`): cos/sin reads past the cache return 0. For every token at position ≥ 1, q_pe is written as **all zeros** and a wrong k_pe goes into the KV cache. This is silent.
- **More heads per block**: the kernel reads past the allocation and can fault (see ROCm/aiter#6879).

Since the RoPE here is the identity, position 0 gives exactly the right result for every token. This PR passes a preallocated all-zeros positions buffer, sliced to the kernel's token count (taken from `slot_mapping`). That removes the dependency on any AITER clamp behaviour.
- The buffer is allocated once in `__init__` as a non-persistent buffer, so captured CUDA graphs need no extra per-layer memset.
- The now-unused `positions` argument of `_fused_decode` is dropped.
- The comment that wrongly said the kernel clamps is corrected.

ROCm/aiter#6879 fixes the kernel side. This change keeps vLLM correct on AITER versions with or without that fix.

## Notes
- Separate from this PR: K3 has 96 heads, so TP8 gives 12 heads per rank, padded to 16. `_fused_decode` allocates `q_out_padded` with `torch.empty`, so the padding heads 12–15 go to the asm MLA kernel uninitialized. Their outputs are discarded and heads are independent, so this looks benign, but it may be worth zero-filling.
