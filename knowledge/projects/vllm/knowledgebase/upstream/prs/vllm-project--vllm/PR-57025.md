## Original PR description

# [Feature] Add routed-expert prefix omission with KV offload compatibility



## Purpose

Related RFC: [Efficient Routed-Expert Replay with Prefix Omission and KV Cache Offloading](https://github.com/vllm-project/vllm/issues/56402).

Add opt-in routed-expert prefix omission for multi-turn RL workloads and compatibility with same-engine KV offloading. Returning cached-prefix routes on every turn repeats data the caller already retains. Slicing the prompt range before gathering reduces scheduler-side NumPy gathering, response serialization/payload, and frontend concatenation work; worker-side expert D2H copies are unchanged.

- Add `--enable-omit-prefix-routed-experts`. Record `request.num_cached_tokens` at the first successful cache admission and return prompt routes starting at `max(routed_experts_prompt_start, request.num_cached_tokens)`.
- Require a stable session identity when omission is enabled and combine it with the existing cache salt, with idempotent normalization across serving paths, including split render/generate.
- During recovery before decode starts, cap GPU prefix reuse at `num_cached_tokens` and use a connector bypass hook instead of external lookup, preserving required connector initialization and cleanup.
- After decode starts, retain normal lookup: previously collected routes remain in the frontend state of the same request.
- Support SimpleCPUOffloadConnector, CPU-only OffloadingConnector with CPUOffloadingSpec, and MooncakeStoreConnector. Unsupported configurations fail validation; PD disaggregation, tiered offloading, and custom offloading specs are out of scope.

Callers must retain and correctly assemble routes across requests sharing the same identity; cache hits are not proof of response delivery. Prefix omission is disabled by default. This PR does not implement the RFC's optional slot invalidation or change expert-array dtypes.

## Test Result

### Automated tests

The exact selection above ran on a GPU worker: **390 passed, 0 failed, 0 skipped** in 78.35 seconds, with 14 Torch deprecation warnings. These tests validate scheduler/configuration/connector behavior, not full-model GPU inference, and are not a full-repository test run.

Ruff check, Ruff format check, and `git diff --check` passed for the modified test files.

### Manual end-to-end checks

Separate checks used real BF16 Step3.5 weights on 8 H200 GPUs (TP=8, PP=1, DP=1), async scheduling, prefix caching, and omission. With a 2,048-block GPU cache, a 1,024-token initial prompt, pressure from 48 distinct sessions, and three revisits, all three supported connectors produced an external hit of 1,008 tokens. Returned route shapes, MoE expert-ID ranges, and token-aligned multi-turn assembly passed. This does not establish exact expert-ID equality against an independent recomputation baseline.

Known end-to-end limitations: reset-induced preemption recovered requests with both CPU connectors, but the reset endpoint returned HTTP 500 due to held blocks. Mooncake reset during active prefill triggered an `_unfinished_requests` assertion, also reproduced on the same branch with routed-expert return and omission disabled and no bypass invocation. Successful active-request reset is not claimed; a clean upstream-baseline reproduction remains pending.

### Preliminary performance from the RFC

The following results are reported in the [RFC](https://github.com/vllm-project/vllm/issues/56402), not a fresh benchmark of this PR branch. They measure prefix omission with **KV offloading disabled**, not offload performance.

Setup: Step 3.5 FP8, 8 H200 GPUs, TP=8, PP=1, async scheduling; 128 concurrent lanes over 100 turns, starting at 640 prompt tokens and adding 320 generated plus 320 random tokens per turn. Each turn includes a 1-second pause, counted in RPM. Ratios are normalized to expert return disabled.

| Configuration | Mean latency (s, lower is better) | Requests/min (higher is better) |
| --- | ---: | ---: |
| Routed-expert return disabled | 5.695 (1.00x) | 1144.20 (1.00x) |
| Full routed-expert output | 6.642 (1.17x) | 999.29 (0.87x) |
| Prefix omission | 5.793 (1.02x) | 1127.64 (0.99x) |

In this workload, prefix omission reduces mean-latency overhead relative to no expert return from approximately 17% to 2%.
