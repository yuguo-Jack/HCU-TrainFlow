# [Bugfix][KV Connector] Support unequal P/D TP for hybrid Mamba models

[Upstream PR](https://github.com/vllm-project/vllm/pull/62251) · state: open · merged: False

## Original PR description

## Overview

Enables PD disaggregation with the Mooncake connector when prefill and decode engines use different tensor-parallel sizes (e.g. P=TP1, D=TP2) for hybrid Mamba models (Mamba1, GDN). Before this change, unequal TP either failed validation or silently registered the wrong byte ranges for packed Mamba cache pages, corrupting the transferred state.

Duplicate-work check: open PRs were searched for Mooncake, Mamba/GDN, and unequal/heterogeneous TP overlap; none address unequal P/D TP for hybrid Mamba models with the Mooncake connector.

## Claims

- Fixes silent Mamba/GDN state corruption on unequal P/D TP: each decode rank now transfers exactly the conv sub-projections and SSM state slice it owns.
- Supports both TP ratio directions (P_TP > D_TP and P_TP < D_TP) for GDN and Mamba1 in the Mooncake connector.
- Adds a `mamba_transfer_geometry` handshake (shapes, dtypes, conv layout, Mamba type, replication) so the receiving side validates the peer's state geometry before transfer. Equal-TP deployments neither send nor require it, so the wire format stays backward compatible.
- Reuses the shared `ssm_conv_transfer_utils` decomposition (previously used by NIXL/MORIIO) instead of duplicating it, and extends it to the SD `(state_len, dim)` conv layout.
- Restores region coalescing for equal TP and for replicated producer caches without Mamba regions.

## Details

Root cause: a Mamba cache page is packed (conv state followed by SSM state, and for GDN the conv state itself packs Q|K|V sub-projections), so its per-rank layout under unequal TP is not a contiguous slice of the whole page. Slicing by the TP ratio passed the length check but wrote garbage state.

The fix decomposes the page: the conv dimension is split into per-rank sub-projections derived from `MambaSpec` (shared, layout-aware helper), registered as separate transfer regions alongside the SSM state, and the sender-side plan maps each sub-region to the peer offset for both ratio directions. Attention regions keep head-clamped TP planning while Mamba regions use raw TP, matching how each cache is actually sharded.

Minimal flow for the changed path (hybrid Mamba model, P_TP=1, D_TP=2):

1. Prefill registers one transfer region per Mamba sub-piece (each conv sub-projection slice plus the SSM state slice) instead of one whole page per layer.
2. The handshake metadata carries `mamba_transfer_geometry` (per-layer shapes, dtypes, conv layout, Mamba type, replication).
3. Before planning any transfer, the peer's geometry is validated against the local one; mismatches fail fast with a clear error.
4. Per request, the sender emits one copy per sub-region: the conv/SSM slice the decode rank owns, at the peer offset determined by the TP ratio direction.
5. Each decode rank receives exactly the slice it owns; no whole-page slicing by TP ratio remains.

Limitations: Mamba2 is still rejected for unequal TP with a clear error (follow-up). The geometry handshake is only exercised when TP sizes differ.
