# [Kernel] Add opt-in NVFP4 activations for long prefills to b12x NVFP4 W4A16 linears

[Upstream PR](https://github.com/vllm-project/vllm/pull/65208) · state: open · merged: False

## Original PR description

## Overview

Builds on #64766 ([this PR's own change](https://github.com/puririshi98/vllm/compare/b12x-nvfp4-w4a16-plan...b12x-nvfp4-w4a16-prefill-fp4)). NVFP4 W4A16 checkpoints run every linear with BF16 activations. Long prefills are compute-bound, and there b12x's FP4 GEMM is 3.3–4.7× faster at 4K–8K rows. This PR adds an opt-in `--kernel-config '{"b12x_nvfp4_w4a16_a16_max_tokens": N}'`: linear inputs with more than N rows are quantized to NVFP4 with a per-call scale, and smaller inputs, including every CUDA graph replay, stay BF16. It is lossy, so it is off by default.

## Claims

- **Faster long prefills:** at N=1024, 16K-token TTFT drops 1.3× on Bolt (1,772 → 1,336 ms) and 2.6× on Qwen3-32B (5,386 → 2,089 ms). From 1.5K tokens it is also 1.2–1.3× (Bolt) and 2.1–2.8× (Qwen3-32B) faster than Marlin.
- **Decode unchanged:** C=1 inter-token latency is 6.06 vs 6.07 ms on Bolt.
- **Small accuracy cost**, measured with every prefill in FP4 (N=32): MMLU-Pro −0.17 points on Bolt and −0.57 on Qwen3-32B, and both 95% intervals include zero.
- **Prompts at or below N are up to 3.4% slower** on Bolt.
- **Unsafe settings refuse to start:** N below the largest CUDA graph capture size, data parallelism, or encoder CUDA graphs.

## Details

- **Why a custom op:** vLLM compiles with dynamic shapes and does not re-check guards, so a Python branch on the row count would be fixed at trace time. `vllm::b12x_nvfp4_w4a16_linear` picks BF16 or FP4 at run time, from one composite `plan_regimes(..., a16_max_tokens=N)` per layer built at load time as in #64766.
- **One scale per call:** every request in a step above N shares it, including that step's decode tokens, so outputs depend on batch composition, and a non-finite activation makes the whole step non-finite.
- Layers whose per-GPU input size is not a multiple of 128 keep BF16. Docs: `docs/features/quantization/b12x.md`.
- **Relation to #54614 and #54617:** they make the reverse switch, running W4A4 checkpoints as W4A16 at small batches. This PR is for weight-only checkpoints, which have no activation scales.
