# [Perf][MoE] Select full-warp top-k rows with redux.sync and keep selections in registers (SM80+)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62912) · state: open · merged: False

## Original PR description



## Overview

`topkGating` (`csrc/moe/topk_softmax_kernels.cu`) gives each row to one full warp when the row is wide enough (512 experts, 256 experts with 16-bit logits, 128-512 experts with fp32 logits). For each of the k selections it runs a 5-stage shuffle butterfly with 3 dependent shuffles per stage, then lane 0 stores the selection and later re-reads the weights to scale them.

For those rows, without a correction bias, this PR selects each expert with two `redux.sync` reductions (`__reduce_max_sync` on the score key, then `__reduce_min_sync` on the expert among the lanes that hold the max), keeps selection i in the registers of lane i, rescans only in the winning lane, and writes the row once at the end. The output is bitwise equal to `main`: the same experts, the same order, the same lowest-index tie rule and the same weight bits.

The register-resident output path is from @Gin-Sin (#64731, co-author); the SM80+ `redux.sync` selection scope is from this PR. #64731 will be closed in favour of this PR.

## Claims

- **Same output:** bitwise equal to `main` (ids, weights as bits, token-expert indices) in every case run on A100, including tie-heavy, all-equal and NaN/Inf rows.
- **Faster on SM80+:** E 512 top-10 softmax on A100: 0.59-0.68x of `main`'s time at 1-256 tokens, 0.71-0.76x at 1,024-4,096 tokens. On B300 (measured by @Gin-Sin): 1.7-2.7x faster than `main` at every full-warp shape.
- **End to end:** below serving noise. On B300 (Qwen3.8-Flash-Next-FP8, DP4 + EP, MTP 3, with the #64731 output path) throughput changed by at most about 1 %, inside the main-vs-main spread; GSM8K and greedy outputs are unchanged. Against `main`, the kernel saves 2.7-4.7 us per router call on A100 (1-256 tokens) and 2.5-6.9 us on B300 (E 512, 1-464 tokens).
- **No change elsewhere:** biased routing, k > 32, sub-warp rows (for example E 128 with 16-bit logits), ROCm and pre-SM80 GPUs keep the current loop, which is byte-identical to `main`. No new CPU/GPU sync, no new launch, no change to the op schema.

## Details

**Why it is exact.** Without a bias the choice score is the output score. After softmax or sigmoid and the existing NaN/Inf clamp every score is >= +0, so the unsigned order of the float bits is the float order. Each lane offers `key = score bits + 1` for its best unselected slot (a selected slot has key 0). The first `redux.sync` finds the maximum key; the second finds the minimum expert among lanes that hold it, which is the lowest expert index, the same tie rule as the butterfly. Only the owner lane clears its slot and rescans. Lane i keeps selection i; lanes 0..k-1 write once at the end, with the same fp32 renormalization sum order and the same scale as `main`.

**Scope.** `topkGating` rows with `THREADS_PER_ROW == WARP_SIZE`, no bias, k <= 32, `__CUDA_ARCH__ >= 800`, not ROCm; the launcher picks a separate `FULL_WARP_SELECT` instantiation, so the existing loop's code generation does not change. Rows beyond `num_rows` return per warp before the selection, so all 32 lanes reach each `redux.sync`. TensorRT-LLM uses `redux.sync` for this selection on SM100+.

**Tests.** `test_topk_without_bias_matches_zero_bias` (from #64731, extended) compares a launch without a bias against a launch with an all-zero bias, which keeps the old loop, bit for bit: E 128/352/384/512/576, k 1/10/32, bf16/fp16/fp32, softmax/sigmoid, renormalize on/off, `is_padding` rows, `routed_scaling_factor`, tie-heavy rows with NaN/+Inf, and the tie order against a stable sort (720 cases). It has not run in a full vLLM build on our side; CI will run it. The benchmark gains a `--dtype` option for fp32 router logits.

**CI.** There is no sm_80 runner. The A100 data come from our cluster.

**Related.** #64731 (Gin-Sin, same selection; its output path is folded in here). #59737 (PDL for this kernel, SM90+ only) does not overlap. #57823 (padded row strides) touches the same file.
