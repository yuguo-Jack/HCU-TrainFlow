# [Bugfix][Frontend][Kimi K3] Fix Kimi K3 XTML marker leakage in responses API

[Upstream PR](https://github.com/vllm-project/vllm/pull/62507) · state: closed · merged: True

## Original PR description



## Overview



Add `spaces_between_special_tokens` to `ResponsesRequest` so Kimi K3's `adjust_request` can turn it off on responses API endpoint, as it already does on chat completions API. Without it, XTML markers leak into Responses API output text.

Supersedes #51152, which has had merge conflicts since 2026-09-02 and no response from its author despite follow-ups. Original author credited via `Co-authored-by`.

## Claims



- `ResponsesRequest` accepts `spaces_between_special_tokens` (default `True`, same as `ChatCompletionRequest`) and passes it to `SamplingParams`. Requests that don't set it behave as before.

## Validation



### Minimal reproducer of the bug

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080/v1", api_key="DUMMY")
messages = [
    {"role": "user", "content": "What time is it now in New York?"},
    {
        "type": "function_call",
        "call_id": "chatcmpl-tool-9a1b108b61cbb7cf",
        "name": "getCurrentTime",
        "arguments": "{\"location\": \"New York\"}",
    },
    {
        "type": "function_call_output",
        "call_id": "chatcmpl-tool-9a1b108b61cbb7cf",
        "output": " Current time in New York is 2026-10-14 00:05:21.",
    },
]
for e in client.responses.create(model="moonshotai/Kimi-K3", input=messages, stream=True):
    t = getattr(e, "type", "")
    if t in ("response.output_text.delta", "response.refusal.delta"):
        print(e.delta.content or "", end="")
```

| | Streamed output text |
|---|---|
| `main` | `<\|open\|> response Current time in New York is ...` |
| this PR | `Current time in New York is ...` |
