# [Core] Update PyTorch to 2.15.0, torchvision to 0.29.1, triton to 3.9.0 (test channel)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60324) · state: open · merged: False

## Original PR description

## Purpose

Update the PyTorch ecosystem to the **2.15.0 release candidate**, resolving wheels from the PyTorch **test** channel (`download.pytorch.org/whl/test/...`). Same shape as the initial 2.14.0 iteration of #52183.

| Package | From | To |
| --- | --- | --- |
| `torch` | 2.13.0 | **2.15.0** |
| `torchvision` | 0.28.0 | **0.29.1** |
| `triton` | 3.7.1 | **3.9.0** |
| `torchaudio` | 2.11.0 | 2.11.0 (newest published on every channel) |

CUDA stays on **cu130**.

### CUDA libraries

These follow the `13.0` entry of `PYTORCH_EXTRA_INSTALL_REQUIREMENTS` in [`generate_binary_build_matrix.py`](https://github.com/pytorch/pytorch/blob/main/.github/scripts/generate_binary_build_matrix.py#L67), which is identical on `main` and `release/2.15`. `torch 2.15.0+cu130` pins them with `==` in its wheel metadata.

| Package | From | To |
| --- | --- | --- |
| `nvidia-cudnn-cu13` | 9.20.0.48 | **9.26.0.51** |
| `nvidia-nccl-cu13` | 2.29.7 | **2.30.7** |
| `nvidia-nvshmem-cu13` | 3.4.5 | **3.7.2** |
| `nvidia-cusparselt-cu13` | 0.8.1 | 0.8.1 |
| `cuda-toolkit` | 13.0.3 | 13.0.3 |
| `cuda-bindings` | 13.0.3 | 13.0.3 (satisfies `>=13.0.3,<14`) |

### Verified on the test channel before pinning

- `torch==2.15.0` (`+cu130` on `whl/test/cu130`, `+cpu` on `whl/test/cpu`).
- `torchvision==0.29.1` (`+cu130`, `+cpu`).
- `triton==3.9.0` on `whl/test/triton`, `whl/test/cu130/triton` and `whl/test/cpu/triton`. `torch 2.15.0`'s metadata requires `triton~=3.9.0`.
- `nvidia-cudnn-cu13==9.26.0.51` and `nvidia-nvshmem-cu13==3.7.2` on `whl/test/cu130`.

## Changes

1. **[Core] versions and test channel**
   - Version pins updated in `requirements/{cuda,cpu}.txt`, `requirements/build/{cuda,cpu}.txt`, `requirements/test/{cuda.in,cuda.txt,cpu.txt}`, `pyproject.toml`, `CMakeLists.txt` (`TORCH_SUPPORTED_VERSION_CUDA`/`_ROCM`) and `docker/Dockerfile.s390x`.
   - Index URLs moved to `whl/test/*` in `docker/Dockerfile` (`PYTORCH_CUDA_INDEX_BASE_URL`), `docker/versions.json`, the requirement files, the CUDA quantization torchao install and `tests/standalone_tests/python_only_compile.sh` (RELEASE-ONLY).
   - `check-ray-compatibility.sh` now offers uv both the stable and the test channels.
2. **[CI] CPU wheels from the test channel**
   - `docker/Dockerfile.cpu` uses `--extra-index-url .../test/cpu` instead of `--torch-backend cpu`, since uv's backend presets cover stable channels only.
   - RELEASE-ONLY: forces a fresh torch on every CPU build (`UV_NO_CACHE=1`, `--no-cache`), because the RC is republished under an unchanging version string.

### Not changed

- `torchao` stays on 0.17.0. No torch 2.15 build is published yet; the newest, 0.18.0, pairs with 2.14.
- TPU (`requirements/build/tpu.txt`, bumped separately) and the ROCm requirement files.
- The `zentorch` pin. No `zentorch 2.15.x` exists, so `tests/test_zentorch_version_pin.py` is expected to fail on the CPU-Kernel lane, as it does for torch 2.14.1 (#52183).

The lockfiles are hand-edited rather than recompiled; a reviewer with a working resolver should regenerate them to pick up transitive changes.
