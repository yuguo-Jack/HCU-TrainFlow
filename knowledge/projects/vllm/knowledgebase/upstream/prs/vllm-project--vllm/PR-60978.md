# [Bugfix][Pooling] Use embedding_dim for pooling output size

[Upstream PR](https://github.com/vllm-project/vllm/pull/60978) · state: open · merged: False

## Original PR description

## Overview

Fixes #60977.

`ModelConfig.embedding_size` can report the transformer hidden size instead of the final embedding width for pooling models with an output projection.

For `google/embeddinggemma-2`, this results in a reported size of 512 instead of 768, causing `PoolingParams(dimensions=768)` to fail validation.

## Claims

This change uses `embedding_dim` as a fallback for pooling models before falling back to `hidden_size`.

The existing precedence for explicit `embedding_size` values and Sentence-Transformers Dense modules is preserved. Generation runners are unaffected.

## Validation

**Tests**

```bash
pytest -q tests/test_pooling_params.py
# 14 passed
```

Added network-free tests:

- `test_pooling_embedding_dim_preferred_over_hidden_size_without_network`
- `test_matryoshka_accepts_native_embedding_width_without_network`

These cover the `embedding_dim` fallback, override/Dense/generate precedence, and Matryoshka dims 128/256/512/768 (with 0/769 rejected).

**GPU reproduction (RTX A5000)**

| Dimensions | Before | After |
| --- | --- | --- |
| Default | 768 | 768 |
| 128 | Pass | Pass |
| 256 | Pass | Pass |
| 512 | Pass | Pass |
| 768 | Validation error | Pass |
| 769 | Rejected | Rejected |

The resulting embeddings were also compared against Hugging Face, with cosine similarity ≥ 0.99997 in the tested cases.

Ruff lint and formatting checks passed.

## Details

The current fallback in `ModelConfig.embedding_size` uses `get_hidden_size()` when neither an explicit override nor a Sentence-Transformers Dense module is available.

That assumption doesn't hold for models such as EmbeddingGemma 2, where a final projection changes the embedding width.

The patch checks `hf_text_config.embedding_dim` (or top-level `embedding_dim`) for pooling runners before using the hidden size.

Other pooling models exposing this configuration field may also be affected; EmbeddingGemma 2 is the reproduced case.

The unrelated Triton shared-memory issue #60847 is outside the scope of this PR.

AI assistance was used for investigation, implementation, and testing.
