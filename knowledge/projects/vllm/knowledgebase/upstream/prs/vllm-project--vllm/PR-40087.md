## Code Review

This pull request implements priority-based preemption in the scheduler, allowing high-priority waiting requests to displace lower-priority running requests when the maximum sequence limit is reached. It includes logic to clean up resources for preempted requests and adds unit tests to verify preemption behavior and priority ordering. A review comment correctly identifies that the scheduled_loras set is not updated during preemption, which could lead to LoRA slot under-utilization if the preempted request was the sole user of a specific LoRA.

When a running request is preempted to make room for a higher-priority waiting request, its associated LoRA (if any) should be removed from the `scheduled_loras` set if no other scheduled request is using it. Failing to do so can lead to under-utilization of LoRA slots, potentially blocking a high-priority request that requires a new LoRA even when a slot is technically available.

```python
                            if lowest_running in scheduled_running_reqs:
                                scheduled_running_reqs.remove(
                                    lowest_running
                                )
                                # Update scheduled_loras if the preempted request was the only one using its LoRA.
                                if self.lora_config and lowest_running.lora_request:
                                    lora_id = lowest_running.lora_request.lora_int_id
                                    if lora_id > 0 and not any(
                                        r.lora_request and r.lora_request.lora_int_id == lora_id
                                        for r in scheduled_running_reqs
                                    ):
                                        scheduled_loras.discard(lora_id)
```
