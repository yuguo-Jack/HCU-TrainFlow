# [Bugfix][GDN] Size repeat_interleave from the device token total

[Upstream PR](https://github.com/vllm-project/vllm/pull/65340) · state: open · merged: False

## Original PR description

Fixes #65337

## Purpose

`GDNAttentionMetadataBuilder.build()` crashes with a CUDA **device-side assert** in `torch.repeat_interleave` when a batch contains both a speculative-verify row and a prefill row and the device-side `query_start_loc` reflects adaptive-verification trimming (device total < host total):

- `output_size=query_start_loc_cpu[-1].item()` is the **host** scheduled total, while the `query_lens` repeats come from the **device** `query_start_loc` that `AdaptiveVerificationManager.reallocate_drafts()` rewrites below the host plan whenever the draft budget binds.
- GDN explicitly declares support for that mismatch via `supports_device_cpu_query_lens_mismatch() == True`, and the v1 scheduler routinely mixes chunked-prefill rows into verify batches, so production reaches this shape deterministically.
- A device-side assert poisons the CUDA context — a hard engine crash, not a recoverable error.

The host-total `output_size` came from the anti-sync optimization in #52078; the input that breaks its host==device assumption became reachable with #60229 (adaptive verification). The two changes are individually correct; only their combination asserts. Upstream's adaptive tests (`test_gdn_fused_mtp.py` ids `adaptive-ragged-mtp` / `adaptive-padded-ragged-mtp`) are decode-only, so the mixed branch was uncovered.

## Approach

`output_size` is a pure optimization hint (it only avoids torch's internal sync to size the output); the host total is only a valid hint when device and host agree, which `supports_device_cpu_query_lens_mismatch() == True` explicitly disclaims. Use the device token total:

```python
output_size=int(query_lens.sum().item()),
```

Dropping the kwarg entirely is equivalent (torch then syncs itself); this form keeps the hint while sourcing it from the only authoritative total. One sync per metadata build, correctness first.

Note: draft #63196 restructures this region but retains the same host-total `output_size` in its general path; the same one-liner applies there.

## Testing

- New `tests/v1/attention/test_gdn_adaptive_mixed.py`: one verify row (4 scheduled tokens) + one prefill row (128), device qsl `[0, 2, 130]` vs host `[0, 4, 132]` (the shape `reallocate_drafts()` produces), plus a device==host control. Skips unless ROCm or CUDA compute capability 8.0+ (the builder's async H2D copies with `pin_memory=True` need an accelerator, so a CPU form of this build is not possible). On unpatched main: trimmed case fails on the Repeat.cu device assert, control passes; with this patch both pass.
- On GB200 (SM100, CUDA 13.0, torch 2.11): the standalone reproducer goes from the builder assert to a completed build; three production-shaped trimmed mixed batches (trim / bonus-only / multi-row) complete a poisoned-state full forward with clean mamba state pools in all four backend/dtype combinations (cutedsl + flashinfer × bf16/fp32 states); the non-adaptive regression suite (52 verdicts) shows zero drift against unpatched main (same 52/2 verdicts on both sides, the 2 being a pre-existing unrelated case).
