# [Bugfix][Benchmarks] Drain active multi-turn conversations

[Upstream PR](https://github.com/vllm-project/vllm/pull/57181) · state: open · merged: False

## Original PR description

Fixes #57173

## Purpose

Fix the multi-turn benchmark client exiting as soon as the task queue is exhausted, even when active conversations still have unfinished turns.

When a client receives the task-queue termination sentinel, it now stops accepting new conversations but continues draining the conversations already in `active_convs`. This prevents requests from being silently skipped and keeps exported conversation statistics complete.

## Test Plan

- Add a focused regression test covering two active four-message conversations with `max_active_conversations=2`.
- Verify that the task-queue termination sentinel is received before the remaining active turns are sent.

A method-level check executed bounded fixtures for the drain change at head `24ce3706` against base `e97ff806`, including unequal conversation lengths and the warmup-skip path. These are additional controls for the existing regression, not a separate fix proposal.

The harness extracts the upstream `client_main` unchanged except for removing annotations, substitutes an async session context and successful `send_turn`, and compares the exact multiset of `(conversation_id, current_turn)` calls against the eligible user turns. It uses two active conversations and round-robin sampling:

| User/assistant pairs per conversation | Skip first pair | Expected calls | Base calls | Head calls |
|---|---|---:|---:|---:|
| 2, 2 | no | 4 | 3 | 4 |
| 1, 3 | no | 4 | 2 | 4 |
| 2, 3 | yes | 3 | 2 | 3 |

The head matched every expected ID/turn pair exactly once in all three cases. Both base and head also retained the intentional controls: `max_num_requests=2` stops after two calls, and an already-set stop event sends none.

For the existing test, checking the full ID/turn multiset would directly encode completeness: total count plus the set of conversation IDs can still pass if one turn is duplicated and another skipped. An unequal-length case makes the sentinel arrive while the other conversation has multiple remaining turns; `skip_first_turn=True` verifies that draining does not replay the warmup pair.

Scope: Python 3.12.13; extracted `client_main` with fake queues/session/send function and no-op NumPy seeding. This check did **not** run the native pytest test, multiprocessing/HTTP/SSE, tokenizer, retry/failure paths, random conversation sampling, or a model benchmark. This is evidence for the queue-drain logic only, not an end-to-end approval of the PR.
