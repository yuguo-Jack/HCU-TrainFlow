# [Feature][Multimodal] Support KV-backed continuation through Generate inputs

[Upstream PR](https://github.com/vllm-project/vllm/pull/60526) · state: open · merged: False

## Original PR description

## Overview

Allow an image request to continue from existing decoder KV using the shared Render/Generate multimodal input format, without loading or processing the media again. Closes #60521.

The initial continuation contract supports image-only, decoder-only LLaVA with ordinary sequence positions. LLaVA GPU correctness was validated on the previous revision; model evaluation and performance measurements remain outstanding.

## Claims

- Extend the existing `MultiModalFeatures` / `PlaceholderRangeInfo` schema with `is_embed`, an explicit `requires_kv` requirement, and versioned source compatibility information. Preserve sparse masks for full-media and EC inputs as well as KV continuations.
- Reuse the existing Generate admission path and a common feature-to-engine conversion. Python export/restore is a convenience wrapper over the same `token_ids`, `features`, and `cache_salt` payload. Shared types and serialization live under `vllm.multimodal`; the engine does not import serving protocol classes.
- Preserve the KV requirement through receiver-cache handling and engine IPC. Check actual usable prefix coverage before computation, including after load failures and preemption. A transfer parameter or configured connector alone does not establish coverage; local prefix KV requires no connector.
- Cache the required KV boundary per request so ordinary multimodal decoding retains its existing range lookup. Reject unsupported re-rendering through `LLM.generate()` instead of silently losing media identity or the KV requirement. No end-to-end performance gain is claimed.

## Details

`MultiModalFeatureSpec.data=None` normally represents a receiver-cache reference. Using that meaning for intentionally absent media fails on a cold receiver, while dropping the feature loses its cache identity and layout. An explicit KV requirement preserves the feature and lets the scheduler reject execution when media computation would otherwise be needed.

The shared Generate format previously omitted sparse placeholder masks, and its metadata-only validator only allowed EC fulfillment. This change retains the existing hash/placeholder/kwargs/metadata fields, adds mask roundtripping, and accepts an explicit KV requirement independently of whether `mm_metadata` contains non-null items. The complete KV-only contract is checked at engine admission for HTTP and native Python callers before exempting those inputs from encoder capacity checks. This allows supported decode workers configured with `--limit-mm-per-prompt '{"image":0}'` to admit KV-only input while retaining prompt validation and scheduler coverage enforcement. Existing import paths re-export the common types/helpers.

**Request flow:**

1. `prepare_multimodal_kv_handoff(prompt)` renders once and returns the exact prefill engine input plus a Generate-compatible dictionary. Submit the engine input unchanged to prefill.
2. The caller binds the dictionary to the same request and corresponding KV and coordinates any transfer through existing mechanisms. It carries no KV tensors or transport handles.
3. Decode either adds `sampling_params` and submits the dictionary to `/inference/v1/generate`, or uses `restore_multimodal_kv_handoff(payload)` followed by direct `AsyncLLM.generate()` / `LLMEngine.add_request()` submission. Both use the same conversion.
4. Receiver caches bypass explicitly KV-backed features. The scheduler enforces coverage throughout the lifecycle and reports missing coverage through its existing request-error cleanup path.

The common format can carry model metadata, but the initial LLaVA continuation contract accepts no additional model state. M-RoPE/additional position state, encoder-decoder models, LoRA, speculative decoding, EC connectors on the KV continuation path, and prompt logprobs (including `prompt_logprob_token_ids`) remain unsupported. Ordinary EC and receiver-cache requests retain their existing semantics. See `docs/features/disagg_prefill.md` for Python and Generate examples.

**Related work:** this extends the shared format introduced by merged #54659 rather than adding a parallel descriptor. Merged #52697 permits KV consumers to omit MM embeddings but does not provide this processed-input export/admission and lifecycle contract. The issue-linked open-PR check returned only this PR; related-work searches did not identify another implementation of the same contract.

AI assistance (Codex) was used for implementation, tests, documentation, and this description. The commit includes DCO sign-off and AI attribution.

Dynamo is one motivating caller: [HanFa/dynamo#2](https://github.com/HanFa/dynamo/issues/2), [ai-dynamo/dynamo#15343](https://github.com/ai-dynamo/dynamo/issues/15343). Its coordination adapter remains outside this PR.

One design concern before this goes further: the descriptor/API layer looks like a third parallel schema next to the existing metadata-only paths, and I think it should be aligned with what vLLM already has instead:

1. **Descriptor format**: `MultiModalKvHandoff` largely duplicates the `mm_metadata` serialization in `token_in_token_out/mm_features.py` (hashes, placeholder offsets/lengths). The one real gap there is that `PlaceholderRange.is_embed` is not preserved on main today — fixing that in `mm_features.py` would benefit both the EC path and this one, and seems like a prerequisite either way. Could the handoff payload reuse/extend that format (e.g. model fingerprint as a field) rather than introducing a separate struct?

2. **Admission path**: instead of a new Python-only export/restore API, could this ride on the existing Generate-protocol admission for metadata-only items? `_require_ec_for_metadata_only` currently hard-couples metadata-only features to `ec_transfer_params`; generalizing it to also accept a KV-backed fulfillment claim (e.g. `kv_transfer_params` or an explicit flag) would give KV continuation the same door the EC path already uses, with the scheduler coverage check you added here as the actual enforcement.

The lifecycle contract itself (bypassing the receiver cache for intentionally-absent media, and failing the request whenever KV coverage is missing — including after preemption) has no counterpart in the EC path and does need new logic; my suggestion is only that the descriptor and admission layers not fork from the existing protocol.

<summary>Minimal example: what the KV handoff carries</summary>

There are two separate pieces: the **input descriptor** carries token IDs, media hashes, placeholder positions and the KV-coverage requirement; **`kv_transfer_params`** tells the configured connector how to retrieve the matching attention KV. The descriptor contains neither the original image nor the KV tensors. Export/restore alone does not transfer KV or prove it is present.

The following extracts the engine calls from the benchmark adapter. Run `prefill` on the P worker and pass its returned JSON to `decode` on the D worker. Both engines must already be initialized with matching model/cache settings and a working NIXL connector. These are Python engine calls, not a standalone launcher or stock HTTP route.

```python
"""Core engine calls, extracted from worker.py; not a standalone launcher.

P and D are separately initialized AsyncLLM engines with matching model/cache
settings and a working NIXL connector. Run each function on its owning worker.
"""

import json
import uuid

from vllm import SamplingParams


async def prefill(p_engine, raw_prompt):
    # raw_prompt contains text + PIL image; rendered contains image inputs.
    rendered, descriptor = await p_engine.input_processor.prepare_multimodal_kv_handoff(
        raw_prompt
    )
    params = SamplingParams(
        temperature=0, seed=42, max_tokens=1, ignore_eos=True,
        extra_args={"kv_transfer_params": {
            "do_remote_decode": True, "do_remote_prefill": False,
        }},
    )
    result = None
    async for result in p_engine.generate(rendered, params, uuid.uuid4().hex):
        pass
    assert result is not None and result.kv_transfer_params
    # Only metadata crosses HTTP here. NIXL moves the actual KV separately.
    # P's generated token is discarded; D continues from the original prompt.
    return json.dumps({"input": descriptor,
                       "kv_transfer_params": result.kv_transfer_params})


async def decode(d_engine, wire_json):
    wire = json.loads(wire_json)
    restored = d_engine.input_processor.restore_multimodal_kv_handoff(wire["input"])
    # No image loading/rendering. requires_kv is enforced by the scheduler.
    params = SamplingParams(
        temperature=0, seed=42, max_tokens=32, ignore_eos=True,
        extra_args={"kv_transfer_params": wire["kv_transfer_params"]},
    )
    result = None
    async for result in d_engine.generate(restored, params, uuid.uuid4().hex):
        pass
    assert result is not None and result.outputs[0].finish_reason != "error"
    return list(result.outputs[0].token_ids)
```
