# [Bugfix][MRV2][Spec Decode] Honor EAGLE3 single-state draft configuration

[Upstream PR](https://github.com/vllm-project/vllm/pull/61563) · state: closed · merged: True

## Original PR description



## Overview

Fix Model Runner V2 startup for the GPT-OSS-120B EAGLE3 [short-context](https://huggingface.co/nvidia/gpt-oss-120b-Eagle3-short-context) and [throughput](https://huggingface.co/nvidia/gpt-oss-120b-Eagle3-throughput) drafts, which set `use_aux_hidden_state=false`.

## Claims

- Single-state EAGLE3 drafts receive the target's final hidden state.
- EAGLE3's default auxiliary-state path and other speculative methods keep their existing behavior.

## Details

GPT-OSS-120B has [`hidden_size=2880`](https://huggingface.co/openai/gpt-oss-120b/blob/b5c939de8f754692c1647ca79fbf85e8c1e70f8a/config.json): 2880 elements per token's hidden-state vector. Three-state EAGLE3 concatenates three target-layer vectors to width `3 × 2880 = 8640`, then projects them to the draft's hidden size.

These two drafts instead consume only the final target hidden state and have no auxiliary-state projection. V2 still captures three states, and [`combine_hidden_states`](https://github.com/vllm-project/vllm/blob/c19c263ac8ea3fd6e1d2d689f0e4e725855d89cf/vllm/model_executor/models/llama_eagle3.py#L397) passes the 8640-wide tensor through unchanged. Copying it into the draft's 2880-wide input buffer fails.

The fix honors the flag during runner initialization, so the existing proposer uses the final hidden state instead.

Related: [#40656](https://github.com/vllm-project/vllm/pull/40656) proposed this fix but is closed and unmerged. [#50170](https://github.com/vllm-project/vllm/pull/50170) addresses fallback warnings, not this configuration bug. No equivalent open PR was found.
