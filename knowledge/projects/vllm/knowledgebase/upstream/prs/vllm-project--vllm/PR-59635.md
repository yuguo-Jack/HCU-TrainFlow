# [KV Connector] Support sleep mode with the NIXL pull connector

[Upstream PR](https://github.com/vllm-project/vllm/pull/59635) · state: closed · merged: True

## Original PR description

## Purpose

Stacked on #59625; only the last commit is new. This replaces the earlier lease-based revision of this PR (and the
closed #59713): there is no lease and no new protocol between engines.

#59625 refuses sleep mode with NIXL because peers keep the stale KV cache registration. Sleep keeps the virtual
addresses and maps new physical pages, so everything NIXL bound to the old pages goes stale: the memory registration
(rkeys), the local prepped dlists, the handshake payload served to peers, and each peer's loaded remote agent.

Evidence on #59625 with the NIXL refusal forced off (GB300, cross-node 1P1D, Qwen3-8B, UCX RDMA over RoCE):

- After a decode sleep and wake: 0/30 outputs match the awake control. After a prefill sleep and wake: 0/30.
- No errors and no failed transfers: on GB300 there is no `nvidia_peermem`, so UCX registers GPU memory through
  dmabuf, and the stale MR pins the old pages; peers read old data without any error.
- Sleep frees nothing of the KV cache (67763 MiB asleep instead of 2077), and after the wake the GPU holds both
  (150787 MiB instead of 85101).

This PR implements the #59625 hooks for the NIXL pull connector (`NixlConnector` / `NixlPullConnector`):

- `release_kv_caches()` (before the unmap): waits until no own read is in flight and no handshake is pending (bounded,
  `TimeoutError` keeps the registration), then releases every local prepped dlist, drops every remote engine (their
  split handles reference local memory; they are re-handshaked on demand), and deregisters the KV cache.
- `restore_kv_caches()` (after the remap): registers the same descriptors again, re-preps the local dlist, and
  rebuilds the handshake payload with the new agent metadata.
- Peer refresh through the existing handshake only:
  - After a wake-up that restored the KV cache (`tags` is None or contains `kv_cache`), `EngineCore` hands the
    workers' payloads to the scheduler (the startup code, extracted).
  - The scheduler-side connector owns the registration epoch: each republish bumps it and stamps the same epoch on
    every rank's payload, so ranks cannot advertise different epochs, even after a partly failed release.
  - The side-channel listener serves the new payloads; `request_finished` adds `remote_registration_epoch` to
    `kv_transfer_params`.
  - The reader records the epoch of the payloads it loaded (the minimum over the remote ranks of one handshake, in
    case it straddled the republish). A request naming a newer epoch drops that remote engine and handshakes again
    through the existing path; while reads through the old registration are still in flight, the request is
    re-queued instead. Older epochs never trigger a re-handshake.
  - The reader checks whether the agent is loaded once per request (`_start_read`), so a handshake that completes
    concurrently cannot install an old agent between the epoch check and the read.
- Under sleep mode the worker sets `UCX_RCACHE_ENABLE=n` and `UCX_TLS=^cuda_ipc` right before creating the agent,
  each only if the user did not set it, and logs once which defaults it applied (as `UCX_RCACHE_MAX_UNRELEASED` in
  `nixl_utils.py` does). **They are process-wide**: other UCX users in the worker process (the NIXL EPLB communicator,
  the EC NIXL connector, NVSHMEM with a UCX transport) and child processes inherit them.
  - UCX's registration cache defers the real deregistration. On GB300 the cached dmabuf MR kept the released pages
    pinned in about half of the sleeps, and `release_kv_cache_memory` freed nothing. With the cache off, every sleep
    freed the KV cache.
  - A peer's cuda_ipc import (intra-node NVLink or MNNVL) pins the exporter's pages inside the peer's UCX cache. Over
    MNNVL the outputs stayed correct, but the prefiller's KV cache stayed resident asleep and was doubled after the
    wake. Without cuda_ipc in the exporter's UCX context no peer can import it; reads use RDMA (on one node: RDMA
    loopback through the NIC). Cost measured below: none on GB300.
- Static policy, checked once at startup: `NixlPullConnector.supports_sleep_mode` is True only with the UCX backend
  (`backends == ["UCX"]`), the only one validated. `NixlPushConnector` stays refused: the producer writes through the
  decoder's registration and is not refreshed.
- `NIXL_CONNECTOR_VERSION` 13 -> 14 (payload field and `kv_transfer_params` key). Routers must forward
  `kv_transfer_params` unchanged, as they already must for `remote_block_ids`.

  slept KV cache resident (measured over MNNVL: 67763 MiB asleep, 150787 MiB after the wake; `UCX_CUDA_IPC_CACHE=n` on

- Unit: 391 passed across the files above. The failures are tests that need models this node cannot download (gated

Known limitations:
- **Host memory grows by about 1.3 MiB per sleep cycle on both P and D** (measured on the previous revision with
  `smaps_rollup` Rss at Qwen3-8B TP1, `num_threads=4`: 1.25-1.34 MiB/cycle, linear over 500 cycles; Mooncake and sleep
  without a connector are flat). Each re-handshake creates and closes UCX RC endpoints, and UCX does not return their
  send-queue buffers (about 640 KiB pinned per side per re-handshake, plus allocator fragmentation). The cost scales
  with NIXL threads and TP ranks (`num_threads=1` cuts it to 2/5). This revision keeps exactly one re-handshake per
  wake. Follow-up: keep the remote agent across a wake and reload only the peer's memory sections (NIXL partial
  metadata without connection info), which needs NIXL to replace the old sections of a loaded agent; that is not
  verified for NIXL 1.4.1. The UCX endpoint leak itself is to be reported upstream.
- NIXL backends other than UCX (refused), push mode (refused), and cuda_ipc/MNNVL transfers under sleep mode (disabled
  by default; a user who sets `UCX_TLS` with cuda_ipc keeps the peers' imports pinned, as measured above).
- A release that fails on one TP rank (timeout or deregistration error) leaves that worker released while
  `Executor.sleep` reports the engine awake, so nothing restores it. Partial-failure handling belongs to the executor
  and is shared with #59625's other connectors; it is not changed here. The registration epoch no longer diverges
  across ranks in that case, because the scheduler stamps it.
- With `enforce_handshake_compat: false`, a version-13 decoder ignores the epoch and never refreshes after a
  version-14 prefiller wakes; with the rcache-off default that shows up as failed transfers.

## Purpose

Sleep remaps the KV cache to new physical pages at the same virtual addresses, but NIXL's registration and the metadata each decoder loaded still refer to the old pages: after a wake, outputs are wrong (0/30) and the slept KV cache stays resident.

This PR supports sleep mode for `NixlConnector` (pull mode, UCX backend):

- `unregister_kv_caches` / `restore_kv_caches` deregister and re-register the KV cache, rebuild the local dlists and republish the agent metadata.
- Unlike Mooncake, NIXL does not reload a peer's keys by itself. After a wake-up, the scheduler bumps a registration generation when the published metadata changed and sends it in `kv_transfer_params`; a decoder with an older agent handshakes again. Re-registration usually gets the same keys back, so decoders keep their agent.
- Under sleep mode, `UCX_RCACHE_ENABLE=n` and `UCX_TLS=^cuda_ipc` are set unless already set, since UCX's registration cache and cuda_ipc imports keep the slept pages pinned.
- `NixlPushConnector` and non-UCX backends stay refused. `NIXL_CONNECTOR_VERSION` 14 -> 15.

Self-review of `nixl/base_worker.py`. I plan the follow-up changes below and will push them after testing.

**1. `restore_kv_caches` decodes the handshake payload, patches one field and re-encodes it.**
`register_kv_caches` already builds this payload. I'll move the `NixlAgentMetadata` / `NixlHandshakePayload` construction into `_build_handshake_payload()` and call it from both places.

**2. Registration and teardown are duplicated.**
`restore_kv_caches` repeats two steps of `register_kv_caches`: registering memory and building the local xfer handles. `unregister_kv_caches` repeats the teardown in `_finish_shutdown`: releasing handles, cleaning up remote engines and deregistering memory. I'll add one register helper and one release helper, and use them at init, wake, sleep and shutdown. The descriptor and layout setup in `register_kv_caches` still runs once.

**3. The shutdown loop `for desc in [] if self._kv_unregistered else self._registered_descs` goes away.**
After point 2, shutdown calls the same release helper, and that helper knows whether memory is still registered.

**4. Replace the process-wide UCX env vars with per-agent config.**
Right now sleep mode calls `os.environ.setdefault` for `UCX_RCACHE_ENABLE=n` and `UCX_TLS=^cuda_ipc`. That also affects other UCX/NIXL users in the same process, such as NIXL-based weight transfer or KV offload.
- NIXL's UCX backend accepts an `engine_config` init param (`KEY=VALUE,...`). It is applied with `ucp_config_modify` to that agent's UCP context only (`src/plugins/ucx/ucx_utils.cpp`). It is available in NIXL 1.5.0, the version vLLM pins, and already in 0.9.0.
- An explicit `UCX_*` env var still wins, because `config::modify` skips keys that are set in the env. That matches the current `setdefault` behavior.
- `nixl_agent_config` cannot pass backend params yet (`TODO: add backend init parameters` in `_api.py`). So the UCX backend would be created explicitly:

```python
ucx_params = {"num_threads": str(num_threads)}
if vllm_config.model_config.enable_sleep_mode:
    ucx_params["engine_config"] = "RCACHE_ENABLE=n,TLS=^cuda_ipc"
config = nixl_agent_config(backends=non_ucx_backends, capture_telemetry=True)
self.nixl_wrapper = nixl_wrapper_cls(str(uuid.uuid4()), config)
if "UCX" in self.nixl_backends:
    self.nixl_wrapper.create_backend("UCX", ucx_params)
```

Before pushing, I'll verify on hardware that both settings take effect: the KV cache memory is released while asleep, and the UCX info log shows the config.
