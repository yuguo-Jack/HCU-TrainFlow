# [CI] Disable jobs with unlocked transitive dependencies

[Upstream PR](https://github.com/vllm-project/vllm/pull/63608) · state: closed · merged: True

## Original PR description

## Overview

Temporarily disable the CI jobs listed below until their transitive dependencies are locked. Keep the job definitions commented out so they can be restored without reconstructing their configuration.

## Claims

| Package installed by job | Disabled jobs |
| --- | --- |
| `evalscope==1.10.0` | B200/H200 nightly Qwen3.8 accuracy evaluation and MI355 evaluation |
| `helion==1.4.0` | H100 and MI250 Helion kernel tests |
| `b12x==1.5.1` | DGX Spark nightly b12x linear kernels |
| `torchao==0.18.0` / `0.17.0` | H200 MIG, MI300 and MI355 DPX quantization |
| `torch-abi-audit==0.0.1` | MI300 Torch Stable ABI Audit |
| `tblib==3.1.0` | BMG Example Test that invokes `run-intel-ci-test.sh example` |

- Disable both shared definitions/AMD mirrors and the standalone AMD definitions: 15 job declarations, counting mirrors.
- Keep the NVIDIA Torch Stable ABI Audit and other Intel jobs enabled. The separate Intel pipeline's Example Test does not invoke the script that installs `tblib`, so it remains enabled.
- Record the 42 test files that lose their last CI job in the test-tethering allowlist, each with the dependency-locking reason.

## Validation

```bash
.venv/bin/python -m pre_commit run --files \
  .buildkite/hardware_tests/intel_xpu_ci/test-intel.yaml \
  .buildkite/test-amd.yaml \

  .buildkite/test_areas/lm_eval.yaml \
  .buildkite/test_areas/quantization.yaml \
  .buildkite/test_areas/torch_abi.yaml \
  tools/pre_commit/test_tethering_allowlist.txt
.venv/bin/python tools/pre_commit/check_buildkite_step_keys.py
git diff --check
```

Additional local validation parsed every Buildkite YAML file and compared the six changed YAML documents against the base commit: the only semantic changes are removal of the listed job declarations and the AMD-only ABI mirror. The locally available ci-infra `read_steps_from_job_dir` loader successfully loaded 389 steps across all `ci_config*.yaml` configurations. No active targeted package-install command remains in the affected definitions.

GPU tests/model evaluations were not run: this changes CI scheduling only, with no model, serving, or test implementation changes. Live Buildkite execution was not tested.

## Details

A top-level version pin does not freeze the transitive dependency graph. This is the requested temporary scheduling mitigation, not a dependency-locking fix or a claim that every listed package has a demonstrated vulnerable dependency.

The pipeline generator's `Step` model does not support a `skip` field, so this uses the existing commented-out-job convention. Restore the blocks and remove the corresponding temporary allowlist entries once the dependency environments are locked. Coverage is intentionally reduced while these jobs are disabled.

Duplicate-work checks searched open PRs for evalscope, Helion, dependency changes, and CI disablement. No existing PR implementing this disablement was found. #63574 updates dependency floors and lockfiles rather than disabling these jobs; #62077 changes sharding and is also distinct. No issue number was supplied.
