# [ROCm][MiniMax-M3] MXFP4 K/V and index cache (mxfp4) on gfx950

[Upstream PR](https://github.com/vllm-project/vllm/pull/64198) · state: open · merged: False

## Original PR description

## Overview

Adds `--kv-cache-dtype mxfp4` with `--attention-config '{"indexer_kv_dtype": "mxfp4"}'` for MiniMax-M3.1 on ROCm gfx950 (MI355X, TP4): K, V and the indexer's key cache are stored as MXFP4 (e2m1 values, one e8m0 scale per 32), 68 B per token and head. Reference implementation: [ROCm/ATOM#2770](https://github.com/ROCm/ATOM/pull/2770).

**Draft; not runnable yet.** #64111 has merged, so this is now rebased onto main (`16d667348d`) as 5 commits (4 feature commits plus a test-only type fix). It still waits on three open AITER PRs (#7056, #7060, #7061), merged #7057, and an AITER pin bump (see Details). Placeholder to claim the work and get early design feedback.

AI-assisted (Claude Code). No human has reviewed the diff line by line yet; this stays a draft until that is done.

## Claims

- New cache dtype `mxfp4` (uint8 storage, `KVQuantMode.MXFP4`) and a gfx950 attend for MiniMax-M3 sparse attention. Per head a 128-token page is `[128 x 64 B e2m1][128 x 4 B e8m0]` = 8704 B; the main K/V spec is `num_head_slots=2*Hkv, state_content_bytes=68`, the index spec `head_size=68`.
- The fused QK-norm / RoPE kernel (AITER `fused_qknorm_idxrqknorm`) writes the MXFP4 K, V and index-K pages and writes the main q as e4m3 into `q_out`.
- Index scores come from AITER's FlyDSL MXFP4 scorers (decode and prefill); the top-k is the one the NVFP4 indexer uses; the attend runs AITER's `pa_decode_mxfp4` on a one-block-per-page table, for decode and prefill.
- The MXFP4 decode scorer's work map is one persistent buffer built for the model-length block bound, so FULL decode CUDA graphs replay a valid map.
- Not covered: Mono decode (stays off), indexer CP, TP other than 4, the MTP/DSpark draft layers (the existing check raises).

## Details

**Prerequisites.** ROCm/aiter#7057 (fused write kernel: MXFP4 K/V and index-K, e4m3 `q_out`; this PR follows its final API, in which `q_fp8_out` and `q_scale` are gone) has merged; the remaining ROCm/aiter#7056 (FlyDSL `pa_decode_mxfp4`), #7060 (index decode scorer) and #7061 (index prefill scorers) need to merge, then an AITER pin bump in `docker/Dockerfile.rocm_base`, then this PR. The pin is not bumped here. AITER is imported inside functions behind `VLLM_ROCM_USE_AITER=1`; without the ops the layer raises a message naming those PRs.

**Commits** (on `16d667348d`):
1. `99556ddca5` Add the mxfp4 KV cache dtype and its page geometry (no behavior change on its own)
2. `507ac36aef` MXFP4 K/V and index cache on gfx950 (indexer, attend, write, tests, docs)
3. `06fdab1145` Pass the e4m3 main q as `q_out` to the aiter MXFP4 write
4. `ffd9f4a06d` Keep the MXFP4 decode work map stable for CUDA-graph replay
5. `d6dbccaac4` Fix mypy errors in `test_mxfp4_kv_cache.py` (test-only)

**Why not a duplicate.** No open or merged PR stores MiniMax-M3 K/V or index keys as MXFP4. #63547 is fp8 KV, #45838 is MXFP4 experts, #59739 (`mxfp4_mla`) and #64120 (`mxfp4_ds_mla`) are MLA/DSv4 caches. The dtype string `mxfp4` is a distinct exact-match name from `mxfp4_mla` and `mxfp4_ds_mla`; `KVQuantMode.MXFP4 = 16` avoids the 15 #64120 takes.

**Design.**
- It mirrors the NVFP4 hooks (`is_mxfp4` dispatch in `amd/model.py`, a sibling indexer and sparse backend), and reuses its metadata builders, FlyDSL top-k and the existing `sparse_pa` block-table kernels, which gain a `pages_per_block` argument (1 for a page-128 cache).
- AITER's `pa_sparse_block_topk` is not used: its build only accepts `pages_per_block == 8`, and it expects scores already pinned by the scorer, which the MXFP4 scorers do not do. A small Triton kernel writes AITER's init/local sentinels (1e30 / 1e29) on each row's causal blocks, and the existing top-k reads only a row's causal blocks, so the scorer's unwritten entries are never seen.
- The index query is bf16 and the main query e4m3 (the configuration ATOM measured).
- It needs one KV head per rank (TP4 on the 4-KV-head checkpoint); the checks raise a message with the reason otherwise.

**Size.** About 850 lines of non-test code, most of it the two new files (`indexer_mxfp4.py`, `sparse_attention_mxfp4.py`) that parallel the NVFP4 ones, plus about 700 lines of tests. Docs: one line in `docs/features/quantization/quantized_kvcache.md`.
