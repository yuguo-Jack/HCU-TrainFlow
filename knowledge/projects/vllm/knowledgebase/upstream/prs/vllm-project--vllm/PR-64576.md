# [CI][MoE] Start every MoE kernel test file from a clean GPU state

[Upstream PR](https://github.com/vllm-project/vllm/pull/64576) · state: closed · merged: True

## Original PR description

## Purpose

Fix `:nvidia: (L4) MoE Kernels Shard 2/3` on main. It has failed on every run since [98366](https://buildkite.com/vllm/ci/builds/98366) (Oct 29, 15:44Z) and shows up as a failure on unrelated PRs (e.g. #64378):

```
FAILED kernels/moe/test_modular_kernel_combinations.py::test_modular_kernel_combinations_singlegpu  (x5)
torch.distributed.DistBackendError: NCCL error ... unhandled cuda error
ncclUnhandledCudaError: Call to CUDA function failed.
Last error: Failed to CUDA calloc async 608 bytes
```

**Root cause:** order dependence, exposed by a runtime-shard re-plan. No code change caused it.
- `tests/kernels/moe/conftest.py` turns off the per-test `cleanup_fixture` and cleans on entry only for files in `NEEDS_CLEAN_ENTRY` (or tests using `dist_init`). `test_modular_kernel_combinations.py` is in neither, so it inherits whatever GPU memory earlier files left cached in the pytest process.
- The runtime-shard planner partitions files using timings from `ci.vllm.ai/api/timings/latest`. Between builds 98337 and 98366 the timing data refreshed. The test set was identical (11,004 tests), but the split changed from 2196/1653/7155 to 3941/1990/5073. That put `test_gpt_oss_triton_kernels.py` right before `test_modular_kernel_combinations.py` in shard 2.
- The worker process the test spawns then cannot allocate even 608 bytes for NCCL setup on the 22 GiB L4.

No PR's CI could catch this, since the trigger was a timing-data refresh, not a diff.

**Fix:** keep the per-test speedup, but also clean once whenever pytest moves to a new file. That is about 40 cleanups per shard instead of about 1,450 per-test ones. No file then depends on what earlier files left behind, whatever order the planner chooses. The existing allowlist and `dist_init` behavior are unchanged.

**Not a duplicate:** no open PR touches this conftest or test.

## Test Plan

Not run locally (no GPU here). The L4 `MoE Kernels` shards on this PR will confirm. Note that the PR build may use a different shard plan, so the clearest confirmation is main going green after merge.
