# [Quantization] Support ModelOpt layer-wise mixed KV cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/56116) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Consume ModelOpt layer-wise KV-cache recipes using #56155's runtime format
resolution and #56156's packed allocation. Supersedes #52813.
Producer support: [NVIDIA/Model-Optimizer#2272](https://github.com/NVIDIA/Model-Optimizer/pull/2272).

## Claims

- Parse schema-v1 `kv_cache_quantized_layers` recipes, mapping FP8 K/V layers
  to `fp8_e4m3` and NVFP4 K/V layers to `nvfp4`.
- Resolve formats by layer prefix and activate compatible packed allocation
  for homogeneous and hybrid layer-wise recipes.
- Normalize embedded `MIXED_PRECISION` metadata; preserve explicit global
  `--kv-cache-dtype` precedence and existing skip-layer behavior.

## Validation

- Scoped repository pre-commit checks pass, including mypy (Python 3.11), Ruff,
  formatting, test tethering, and Markdown checks:
  `pre-commit run --hook-stage manual --files <incremental changed files>`.
- CPU source isolation passes 26 prerequisite test-body cases, 36 resolver
  combinations, 11 platform/layout cases, and eight ModelOpt factory cases.
  These are not full-vLLM pytest results.
- Earlier-stack Nano and Qwen TP4 smokes generated 512 tokens with finite
  logprobs after CUDA-graph capture. Fresh GPU/E2E validation on this head
  remains pending; no benchmark-accuracy or performance claim is made.

## Details

Use `--kv-cache-dtype auto` to consume the checkpoint recipe. This supports
full FP8 K/V versus full NVFP4 K/V per layer; FP8-K/NVFP4-V within a layer is a
separate kernel integration. Logical formats do not enter allocation specs.
Automatic larger-manager-block optimization is not part of this change.
Upstream weight-format validation is preserved.
The serving validation target is Nano/Qwen with FlashInfer.
