# [CPU][MRV2] Reuse cross-group metadata in the builders, as on GPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/65010) · state: open · merged: False

## Original PR description



## Overview

Make the CPU MRV2 runner reuse metadata across KV cache groups through the builders' `_cross_group_cache`, as #58851 does for the GPU runner. Stacked on #58851 `8c4dca6c4d` merged with main `8530a778f7`; review only the last commit, `25fbde7cfe`.

## Claims

- Removes the CPU runner's copy of the `reuse_key` / `update_block_table` loop that #58851 removes from the GPU runner. No MRV2 runner calls `update_block_table` anymore.
- On CPU, every builder that reads `_cross_group_cache` now shares batch-level metadata across groups. Before, only non-speculative Mamba1, Mamba2 and ShortConv groups did.

## Validation

Mac CPU (Apple M4), head `25fbde7cfe` versus its parent (#58851 `8c4dca6c4d` merged with main `8530a778f7`):

```bash
VLLM_PLUGINS=none HF_HUB_OFFLINE=1 .venv/bin/python -m pytest -q \
  tests/v1/worker/cpu tests/v1/worker/test_attn_utils.py \
  tests/v1/attention/test_{gdn,mamba,replayssm}_metadata_builder.py \
  tests/v1/attention/test_mamba2_prefill_checkpoints.py \
  tests/models/kimi_k3/test_kda_metadata.py tests/models/qwen4_exp/test_ple.py
```

- This command plus 18 related Mamba/GDN/KDA modules: 473 passed / 495 skipped on both. Both fail the same 36 tests as main, mostly because this build lacks the CPU MRV2 custom ops or CUDA.
- A local script drives `build_attn_metadata` with 3 to 4 groups of GDN, KDA, PLE, Mamba1/2 and ShortConv builders (speculative and not, `align` and `none`, Mamba2 checkpoints). Builders persist across up to 11 batches. All 1122 group metadata are equal to the old loop's and to independent per-group builds, nested fields included. The 130 CUDA-only KDA cases raise identically.
- Not run end to end locally. The Arm CPU CI shard serves Qwen3.5-0.8B on this runner and runs `tests/v1/e2e/test_cpu_linear_attn_chunked_prefix.py`.

## Details

`update_block_table` and `supports_update_block_table` stay, because the V1 runner still uses them. No open PR changes this loop.
