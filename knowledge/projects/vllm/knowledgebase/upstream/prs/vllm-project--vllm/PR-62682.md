# [Spec Decode] Add opt-in budgeted ASD verification for MRV2

[Upstream PR](https://github.com/vllm-project/vllm/pull/62682) · state: open · merged: False

## Original PR description



## Overview

Add opt-in Approximate Speculative Decoding (ASD) verification for greedy requests in Model Runner V2. It can commit a longer contiguous draft prefix by allowing selected mismatches under a local regret gate, a per-block exception cap, and a persistent request-level budget.

[Paper](https://arxiv.org/abs/2608.03447) · [Reference implementation](https://github.com/Kissmetothemoon/ASD/tree/9426ce7b3b8cafb2d34f675a5bb9db2ebf0259f6)

## Claims

- Add `rejection_sample_method="approximate"` and configurable request budget, local gate, and block cap. Standard verification remains the default.
- Compute regret from existing processed target logits inside the Triton rejection kernel, without another target forward pass or host reads of logits.
- Maintain a GPU regret ledger across batch reordering, streaming input updates, and preemption. Use FP64 accumulation, with a regression test for a positive regret of `2^-26` at an exhausted budget of `1`.
- Preserve strict token-ID verification when the budget, gate, or cap is zero, including argmax ties. Stochastic requests retain ordinary rejection sampling and do not consume ASD budget.

ASD intentionally changes greedy trajectories. Its budget bounds cumulative local regret along the realized history; it does not guarantee identical output or task quality.

## Details

### Configuration and acceptance rule

Enable MRV2 with `VLLM_USE_V2_MODEL_RUNNER=1` and add these fields to a compatible speculative configuration:

```json
{
  "rejection_sample_method": "approximate",
  "asd_risk_budget": 8.0,
  "asd_max_regret_per_value": 0.25,
  "asd_max_relaxed_tokens_per_block": 2
}
```

For proposal position `i` in a block of length `K`, compute
`r_i = max(z_i) - z_i[x_i]` and `q_i = K - i + 1`.
A mismatch is accepted only if `r_i / q_i <= g`, the block's accepted mismatch
count remains at most `M`, and the request's cumulative regret remains at most
`B`. Verification stops at the first infeasible position. Only accepted
mismatches consume the persistent budget; subsequent exact matches do not.
Recovery/bonus sampling and cache rollback reuse the existing accepted-length
paths.

### Compatibility and tradeoffs

The implementation targets the standard MRV2 sampler. MRV1, custom model samplers, watermarking, and batch sharded sampling are rejected. Batch sharding can change a resumed request's owning rank, so a local ledger cannot safely follow it without additional synchronization. Regret uses the processed, constrained target logits, and non-finite mismatches cannot be relaxed.

### Related work and disclosure

Authenticated open PR title searches for `approximate` and `regret`, issue-title
searches for `ASD`, and full searches for `"approximate speculative"` returned
no matching implementation on 2026-10-20. Existing FLy uses entropy-gated deferred
windows; ASD instead applies logit regret, a block cap, and a request-wide
ledger, so the policies have different commitment rules.
