# [Test][UMBP] Cover TP=2 restore through per-rank MORI pools

[Upstream PR](https://github.com/vllm-project/vllm/pull/64657) · state: closed · merged: True

## Original PR description

- Parametrize `test_restore_matches_recompute` through its `umbp_llm` fixture over TP=1 and TP=2.
- Add a 2-GPU UMBP Connector TP2 Integration group in `test-amd.yaml` and `misc.yaml` that runs only `[tp2]`.

Rank routing and the rule that every rank must hit are only unit-tested with fake clients today, so nothing runs the real path where each TP worker binds its own lookup socket and restores its own head shard from its own MORI pool. If rank 1 loaded rank 0's shard the logprobs would diverge, and if one rank's pool missed, the external-hit count would come up short. Exactness depends on batch invariance keeping the all-reduce deterministic, and a 2-rank sum is order-independent, so the multi-GPU case stops at TP=2. On MI350X (2 GPUs) with MORI v1.2.3.post1 built with UMBP, `pytest -v -s -rs "v1/kv_connector/umbp_integration/test_mori_token_e2e.py::test_restore_matches_recompute"` passed `[tp2]` 11/11 and `[tp1]` 3/3. The existing integration group stays on one GPU, and no open UMBP PR covers this; the TP2/PP2 test that #61794 removed never ran real TP.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.

#### 1. 🟠 Should fix: TP2 CI step exits green with zero tests when fewer than 2 GPUs present
`.buildkite/test_areas/misc.yaml:266`

The new TP2 step runs only `test_restore_matches_recompute[tp2]`; if the agent ever exposed fewer than 2 GPUs, `multi_gpu_marks(num_gpus=2)` would skip it and pytest would exit 0 with nothing run. The MORI-without-UMBP case is already caught at image build: `docker/Dockerfile.rocm_base` checks `BUILD_UMBP:BOOL=ON` and imports `mori.cpp.UMBPClient`. The `misc.yaml` step is not `optional`; only the `test-amd.yaml` copy is. Optionally add a precondition such as `python3 -c "import torch; assert torch.cuda.device_count() >= 2"` before pytest.

**Who is affected:** CI maintainers, only if an `mi355_2` agent is misprovisioned with fewer than 2 visible GPUs.

_Checked against the code by an independent pass._

#### 2. 🟠 Should fix: Partial-prefix-hit UMBP fill has no TP=2 coverage: this PR parametrized only one restore test
`tests/v1/kv_connector/umbp_integration/test_mori_token_e2e.py:121`

Only `test_restore_matches_recompute` is parametrized with `tp2`. `test_restore_extends_a_local_prefix_hit` falls back to `getattr(request, "param", 1)` and runs only at TP=1, and both CI steps select just `::test_restore_matches_recompute[tp2]`. The partial-GPU-hit-plus-UMBP-fill path therefore has no TP=2 coverage. Consider adding the same `tp1`/`tp2` parametrization to that test and widening the CI selection.

**Who is affected:** Only CI coverage of the UMBP connector at TP=2; no runtime behaviour is affected.
