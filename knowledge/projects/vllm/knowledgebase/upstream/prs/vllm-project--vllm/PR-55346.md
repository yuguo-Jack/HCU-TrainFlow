# [Bugfix][ROCm] Saturate bf16->fp16 conversion in QuickReduce

[Upstream PR](https://github.com/vllm-project/vllm/pull/55346) · state: open · merged: False

## Original PR description

## Purpose

Fixes #55345.

QuickReduce packs bf16 inputs into fp16 before the codec runs
(`quick_reduce_impl.cuh`, the `cast_bf2half` branch). bf16 covers the fp32
exponent range; fp16 stops at 65504. `__float22half2_rn` does not saturate, so
any activation above that becomes `inf` and propagates through the reduction,
poisoning the whole line — silently, with no warning and no numerical check.

The conversion sits *ahead* of the codec, so this affects every quantization
mode (INT4/INT6/INT8 **and** FP), not only the quantized ones.

## Test Plan

Two ranks on MI355X (gfx950), INT8 codec, one out-of-fp16-range value on rank 0
and 1.0 everywhere else:

```python
x = torch.full((n,), 1.0, dtype=torch.bfloat16, device=dev)
if rank == 0:
    x[0] = 1.0e30           # representable in bf16, not in fp16
out = qr.quick_all_reduce(x)
print(out[0].float().item(), torch.isfinite(out).all().item())
```

Same container image in both runs, only the built extension differs, so the
difference is attributable to this change and nothing else.

## Test Result

```
before: out[0] = inf     torch.isfinite(out).all() = False
after:  out[0] = 65536   torch.isfinite(out).all() = True
```

Other elements unchanged at 2.0 in both runs.

End-to-end on GLM-5.3 (TP4, MXFP4 + fp8 attention, 8192-token chunks) the clamp
is not measurable against run-to-run noise — the surrounding loop is
bandwidth-bound and the two `fminf`/`fmaxf` pairs ride along in registers.

## Scope

This is a mitigation, not a complete fix, and I would rather state the limit
than oversell it: with N ranks each contributing a clamped 65504, the fp16
accumulation can still saturate. What it removes is the case where a single
out-of-range value destroys the entire reduction. Keeping bf16 end to end for
bf16 inputs would be the complete answer, but that is a larger change with its
own cost, and worth deciding separately.
