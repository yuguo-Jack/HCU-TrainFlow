# [Hybrid] Round the attention block size up to prefix_match_unit

[Upstream PR](https://github.com/vllm-project/vllm/pull/64624) · state: open · merged: False

## Original PR description



## Overview

For hybrid attention/mamba models, round the block size derived from the mamba state up to a multiple of `--prefix-match-unit` instead of failing at startup. AI assistance (Claude Code) was used to prepare this PR; I reviewed every changed line.

## Claims

- The derived size is often divisor-poor (2112 tokens for Qwen3.5-35B-A3B with fp8 KV), so most units failed:
  ```
  ValueError: Invalid prefix_match_unit=256; prefix-cacheable KV cache group block sizes must be divisible by prefix_match_unit. Got group block sizes=[2112, 2112, 2112, 2112], ...
  ```
- Units that already divide it are unchanged.

## Validation

```
$ pytest tests/v1/worker/test_gpu_model_runner.py -k rounds_up_to_prefix_match_unit
3 passed                                    # this PR (CPU and GB300)
1 failed, 2 passed                          # main
E       AssertionError: assert 400 == 512
```

GB300, Qwen3.5-35B-A3B, fp8 KV, `prefix_match_unit=256`: starts with this PR (block size 2112 → 2304), fails on `main`.

## Details

The step is `lcm(kernel alignment, backend alignment, prefix_match_unit)`. The mamba page is padded to the attention page anyway; this adds a little more padding, and a warning is logged when it grows the block by more than 10%. The `prefix_match_unit` docstring mentions the rounding.

- emmericp · comment · 2026-11-03T14:15:51Z · [source](https://github.com/vllm-project/vllm/pull/64624#issuecomment-6606141511)

1. Only the mamba page padding grows, by less than one rounding step per block (2112 → 2304, +9%, for Qwen3.5-35B-A3B at unit 256). I added a warning when rounding grows the block by more than 10%. Such units failed at startup before, so existing configs are unaffected.
2. The block size is derived deterministically, so P and D with the same settings get the same size. Different units mean different block sizes, which NIXL already handles like differing --block-size (it requires divisibility).
