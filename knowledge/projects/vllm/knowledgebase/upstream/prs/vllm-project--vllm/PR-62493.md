# [Bugfix][Spec Decode] Preserve Torch threads during Numba initialization

[Upstream PR](https://github.com/vllm-project/vllm/pull/62493) · state: closed · merged: False

## Original PR description

## Overview

Preserve the configured Torch intra-op thread limit when Numba lazily initializes its OpenMP pool during the first nonempty CPU ngram proposal. Fixes #62482.

## Claims

- Keep Torch's existing limit rather than allowing Numba initialization to silently overwrite it; keep existing Numba thread selection/restoration.
- Add a fresh-process regression checking real proposals and both thread settings over two calls.

## Validation

Source baseline d46cb9a6d40414fef1f27f0937a97796c351a216; affected implementation unchanged on upstream main 973dbf8071f8bdd6dd7eb2d6ee0da7cbe6a93670. Linux x86_64, Python3.12.15, Torch2.14.0+cu130, Numba0.61.2, NumPy2.2.6, llvmlite0.44.0.

```bash
OMP_NUM_THREADS=4 NUMBA_NUM_THREADS=8 NUMBA_THREADING_LAYER=omp HF_HUB_OFFLINE=1 CUDA_VISIBLE_DEVICES='' .venv/bin/python -m pytest -q --confcutdir=tests/v1/spec_decode tests/v1/spec_decode/test_ngram.py
```

## Details

Numba's first get_num_threads() initializes its OpenMP pool and, in the tested shared-runtime environment, changes Torch's effective intra-op limit. Constructor warmup has no valid ngram requests and does not initialize this pool. Capture Torch's current count before that call and restore it only if it changed. No device transfers/synchronization, new dependency, or global staging cache. MRV2 uses NgramGPUSpeculator and is not on this Numba path. Other runtime/backend combinations are not claimed to reproduce the interaction.

Duplicate searches for #62482 and ngram/Numba thread terms found no matching open PR. #49919 does not prevent this later lazy-initialization side effect. AI assistance was used for implementation, testing and drafting.

The submitting human confirmed line-by-line review and personally reran the module above; the independent test result was supplied as terminal output. E2E validation was performed with AI assistance, not represented as independently human-run.
