# [Bugfix][HiSparse] Adopt GPU prefix copies after the hit's allocation

[Upstream PR](https://github.com/vllm-project/vllm/pull/59274) · state: closed · merged: False

## Original PR description

## Purpose

Fix an engine crash (`Cannot get N free blocks from the pool`) on a HiSparse host-prefix hit under GPU memory pressure. This is an alternative to #57457.

A host-prefix hit re-pins free GPU copies of its pages so the prefix comes back GPU-resident. Admission counts those copies as free blocks, but adoption pinned them before the hit's own allocation (hot region and new pages), which could then run the pool dry.

#57457 fixes this by charging the pins at admission. That mixes host and GPU accounting in `HiSparseSourceManager.get_num_blocks_to_allocate`, and under pressure it defers a request that could run by reading its prefix from host, just to keep an optimization.

## Changes

- **Adopt after allocation.** `commit_computed_blocks` records the pages to adopt, and `update_residency` (in `cache_blocks`, after `allocate_new_blocks`) adopts the copies that survived. The allocation always gets what admission counted, so no admission accounting is needed. A copy the allocation reuses is dropped by its reuse watcher and never adopted.
- **Copies are evicted last.** `BlockPool.unpin_blocks` documents unpinned blocks as last-resort eviction candidates, but blocks freed afterwards were appended behind them, so an allocation evicted a prefix's copies before blocks nobody would reuse. `FreeKVCacheBlockQueue` now keeps a last-resort segment at its tail that later appends stay in front of, and `unpin_blocks` uses it.
- **Tail first.** HiSparse releases a prefix's pages tail first, matching `free_blocks`' convention, so pressure trims a prefix from its end.

Replaying #57457's scenario (a resumed 3-page host prefix hit, `free_blocks` left in the pool):

| `free_blocks` | main | #57457 | this PR |
|---|---|---|---|
| 5–6 | rejected | rejected | rejected |
| 7 | crash | rejected | admitted, 0/3 copies |
| 8 | crash | rejected | admitted, 1/3 |
| 9 | crash | rejected | admitted, 2/3 |
| 10+ | 3/3 | 3/3 | 3/3 |
