# [ROCm][CI] Fix AITER MXFP4 padding tests failing instead of skipping on MI300

[Upstream PR](https://github.com/vllm-project/vllm/pull/64727) · state: closed · merged: True

## Original PR description

## Purpose
`:amd: (MI300) MoE Kernels` failed in shards 1-5 of the nightly [amd-ci#15747](https://buildkite.com/vllm/amd-ci/builds/15747), with 14 `assert False` failures in `test_aiter_moe_padding_matrix_mxfp4` and `test_aiter_moe_token_padding_garbage_rows_mxfp4`.

#62996 un-skipped these tests and guards each one with `assert config.is_valid()[0]`, followed by a skip when `AiterMxfp4Experts` does not support the quant scheme. `Config.is_valid()` already returns `False` in that case, and `AiterMxfp4Experts` is gfx950-only, so on MI300 the assert fails before the skip is reached.
This PR moves the existing skip above the assert. 

## Test Plan
MI300X (gfx942), in the `rocm/vllm-dev:ci_base` image, with the same AITER env as the nightly step:
```bash
cd tests
VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_MOE=1 pytest -v -s kernels/moe/test_modular_kernel_combinations.py \
  -k 'padding_matrix_mxfp4 or token_padding_garbage_rows_mxfp4'
```

## Test Result

All 14 tests now skip with `AiterMxfp4Experts does not support quant scheme ...`.
