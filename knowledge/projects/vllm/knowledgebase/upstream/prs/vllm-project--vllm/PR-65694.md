# [Core][KV Connector] Add VLLM_KV_SCRAMBLE_BLOCKS to test and benchmark with a fragmented KV pool

[Upstream PR](https://github.com/vllm-project/vllm/pull/65694) · state: open · merged: False

## Original PR description

## Purpose

A fresh `BlockPool` hands out block ids in order, so on a new server, requests get physically contiguous KV blocks. On a server that has been running for a while, the free lists are fragmented and every request gets scattered blocks. This difference matters in two ways:

- **Hidden bugs.** Code that maps block ids to KV memory (KV connectors, transfer descriptors, kernels) can look correct while every request's blocks are contiguous and in order, and only break once they are not. Short CI runs on a fresh server almost never reach that state.
- **Misleading benchmarks.** With NIXL, contiguous blocks are merged into a single descriptor. Early requests therefore transfer with very few descriptors and little CPU overhead, and a short benchmark measures a best case that a long-running server does not see.

This PR adds a dev-only env var, `VLLM_KV_SCRAMBLE_BLOCKS=<seed>`. It shuffles the initial free-block order once, when the `BlockPool` is built, so every request sees fragmented blocks from the first allocation. `0` (the default) leaves behavior unchanged. Block 0 stays first, because it is popped as the null block, and `BlockPool.blocks` stays indexable by block id.

The PR also enables the mode by default (`VLLM_KV_SCRAMBLE_BLOCKS=1`) in the NIXL accuracy sweeps (`nixl_integration/config_sweep_accuracy_test.sh`, `config_sweep_accuracy_core_test.sh` and `nixl_push_integration/config_sweep_accuracy_test.sh`). That way, block-indexing bugs in P/D transfers show up as accuracy failures. Set `VLLM_KV_SCRAMBLE_BLOCKS=0` to run them on the unscrambled pool.

## Test Plan

- `pytest tests/v1/core/test_kv_cache_utils.py`. The new `test_free_kv_cache_block_queue_scramble` checks four things:
  - the shuffled order is a permutation;
  - it is reproducible per seed;
  - block 0 stays first;
  - the caller's block list is not reordered.
- The NIXL sweeps above, with scrambling on.
- 1P1D `Qwen/Qwen3-0.6B` with NixlConnector, P and D on one node with 2 GPUs. Prompts are sequential and distinct, at ISL 2048 and 8192 with 8 output tokens. The KV pool is capped with `--num-gpu-blocks-override 8192`. Between probes, rounds of concurrent random traffic (ISL 300–5.7k, 256 output tokens) churn the pool. Metrics are diffed from the decoder's `vllm:nixl_*` Prometheus histograms.

## Test Result

- `tests/v1/core/test_kv_cache_utils.py`: all pass.
- NIXL sweeps with `VLLM_KV_SCRAMBLE_BLOCKS=1`: `nixl_integration/config_sweep_accuracy_test.sh`: the default TP set (6 configs) and `DP_EP=1` (2) pass. `nixl_push_integration/config_sweep_accuracy_test.sh` (2) passes. `config_sweep_accuracy_core_test.sh` and the `HYBRID_SSM=1` / `SW_ATTN=1` sets are still running; I will update this once they finish.

Benchmark, ISL 8192 (512 blocks × 28 layers). Medians of 3 probes, with prefix caching on:

| churn prompts before probe | descriptors (default) | descriptors (scrambled) | NIXL post time (default) | NIXL post time (scrambled) | transfer time (default) | transfer time (scrambled) |
|---|---|---|---|---|---|---|
| 0 (fresh server) | 28 | 14,336 | 0.17 ms | 46.2 ms | 1.6 ms | 52.5 ms |
| 16 | 28 | 14,336 | 0.17 ms | 46.2 ms | 1.6 ms | 52.6 ms |
| 128 | 10,612 | 14,336 | 33.7 ms | 46.2 ms | 38.8 ms | 52.5 ms |
| 256 | 13,888 | 14,336 | 44.8 ms | 46.2 ms | 51.1 ms | 52.5 ms |
| 512 | 14,336 | 14,336 | 46.2 ms | 46.3 ms | 52.5 ms | 52.6 ms |
| 1024 | 14,336 | 14,336 | 46.3 ms | 46.2 ms | 52.6 ms | 52.6 ms |

- **Fresh server:** the default pool transfers 1 descriptor per layer, because every block is merged.
- **After churn:** after a few turnovers of the pool, the default reaches the scrambled numbers: one descriptor per block per layer, with about 270× the post time.
- **Scrambled:** it starts at that steady state, so a short run measures what a long-running server pays.
- **Prefix caching off:** the default pool is already fragmented from the second request on. Freed blocks are reused LIFO in reverse order, and descending block ids cannot be merged.
