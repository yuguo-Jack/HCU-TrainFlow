# [Benchmark] Add a timeout per socket without cancelling the full run

[Upstream PR](https://github.com/vllm-project/vllm/pull/51030) · state: open · merged: False

## Original PR description



## Purpose
Fix `vllm bench serve` runs hanging on a single stalled/ half-open response stream. Today the current guard is the 6 hour client timeout.
This PR adds an optional timeout on the socket so that even in case of a straggler, we still write results to file.
Previously, in the case of a stragglers, the last results files were not written.

## Test Plan
New tests in `tests/benchmarks/test_serve_timeout.py`:
- Unit: `calculate_metrics` warns on timed-out requests and counts them as failed; non-timeout failures do not warn.
- End-to-end: a local mocked OpenAI completions server streams one chunk then stalls on 1 of 3 requests. With `VLLM_BENCH_SOCK_READ=0.5`, `main_async()` completes (bounded by `asyncio.wait_for`) and the result JSON is written with `completed == 2`, `failed == 1`. Counter-checked manually that the same scenario without the env var never finishes and writes no result file.

## Test Result
- `python -m pytest tests/benchmarks/test_serve_timeout.py -v`: 3 passed
