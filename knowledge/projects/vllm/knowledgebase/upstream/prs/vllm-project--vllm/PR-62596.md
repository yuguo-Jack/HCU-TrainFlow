# [Kernel][Sampler] Replace Gaussian pivot with order statistic in combined top-k/top-p Triton kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/62596) · state: open · merged: False

## Original PR description

Fixes #61998

## Overview

The zeroth pass of `_topk_topp_kernel` picks the gather pivot with a Gaussian
quantile (`avg + std * sigma`) fitted to the **first 8192 logits only**. On
real logits (MiMo-V2.6 measurements in the issue) the head of the row carries
systematically higher values, and skewed rows break the Gaussian fit entirely;
the gather then returns fewer than `k` candidates and the row falls back to a
full-vocab ternary search, 3-6x slower per row, stalling every other row in
the batch.

This PR replaces the Gaussian estimate with an **order statistic of a strided
sample taken across the whole row**:

- Sample `S = BLOCK_SIZE / 4` logits uniformly across the row (one lane every
  `NUM_TILES * 4` vocab entries), so head bias cannot skew the estimate.
- Target `m = max(8, ceil(4 * k * S / V))` — the m-th largest sample value,
  found with a 12-step in-register binary search (no extra global memory
  traffic). The 4x margin over `k` keeps the gathered set small (a few
  hundred entries at V=152576) while reliably covering `k`.
- When the sample holds no finite logits (grammar bitmask hiding most of the
  vocab), the pivot degenerates to `+inf` (gather nothing) and the existing
  full-row fallback search runs with its finite, well-scaled bounds. A
  sentinel like `-1e30` would instead poison the buffer-search range and never
  converge (found via a fuzz case, fixed in `test_topk_pivot_all_masked_sample`).
- The Gaussian path, both sigma tables and the table upload, are removed.

## Claims

- Rows whose gather previously failed no longer take the full-vocab fallback:
  **3-6x lower latency per affected row**; batches containing one such row
  stop stalling.
- Gather-healthy rows are within noise of the previous numbers (the strided
  sample is a quarter of the old first-tile read).

## Details

- The buffer search and the top-p stage are untouched; only the pivot choice
  in the zeroth pass changes, so the fallback path remains as a safety net.
- Limitation: like the old code, the sample is a lattice, so adversarial
  distributions can still miss `k` by a few tokens; the fallback search then
  runs exactly as before (correct, slower). The 4x margin makes this
  measure-by-measure rare on real logits.

**Update: reworked implementation + shared-protocol benchmark (addresses the review feedback in #61998 and incorporates the fallback design from #62760).**

Rework summary (commit 8e6478c):
1. **Zeroth pass keeps the Gaussian quantile** (the paper's method), but samples **four quarters of the row** instead of tile 0 — the layout bias the issue identified. The stock 0.15 safety discount is kept: with unbiased sampling, the gather fails <1% on real decode rows at every k measured (Qwen3-8B: 0.0%/0.8%/0.8% at k=20/50/64; 7.6% at k=200; 86% only at k=1000).
2. **When the gather under-covers k**, re-gather once at a distribution-free pivot into the per-program buffer, then run the ternary search entirely in the buffer (L2-resident — the fallback shape from #62760):
   - dense rows: the m-th largest of a 2048-lane strided whole-row sample, m = max(8, ceil(4kS/V)) — no distribution assumption, so it covers the skewed rows the Gaussian cannot;

**Architecture note** (to make the tiered structure of the reworked fallback explicit, following the discussion with #62760):

```
zeroth pass: Gaussian quantile over a 4-quarter coalesced sample  (the paper's
             estimator, layout-bias fixed per #62760; stock 0.15 discount)
  ├─ gather covers k  (>99% of real decode rows at every k measured)
  │    → search the gathered buffer (unchanged fast path)
  └─ gather under-covers k
       → tier 2: re-gather once at the order-statistic pivot
         (m-th largest of a 2048-lane strided whole-row sample, 4x margin
          over k — no distribution assumption, covers skewed rows)
         ├─ dense rows (num_finite_total > 2*BLOCK_SIZE): the sample has
         │  ~450+ finite lanes, so the m-th order statistic is reliable
         └─ sparse rows (grammar masks): the sample may hold too few finite
            lanes to estimate anything — take the row minimum instead,
            which collects every finite candidate. The row is guaranteed
            to hold >= k finite logits (upstream num_finite_total <= k
            short-circuit), so this always covers k
       → all ternary-search iterations then run inside the re-gathered
         buffer (L2-resident, #62760's fallback shape)
```

Each tier only pays when the previous one fails: normal rows cost the same as main plus the (already-present) 8192-lane read, now in four segments; skewed rows pay one extra full sweep for the re-gather; sparse rows pay one more. Nothing ever falls back to the 18-iteration full-vocab DRAM search — that path is gone.
