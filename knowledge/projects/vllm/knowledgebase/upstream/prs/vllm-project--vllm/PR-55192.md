# [Bugfix][Pooling] Clear V1 pooling state after preemption

[Upstream PR](https://github.com/vllm-project/vllm/pull/55192) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Clear partial pooling state when an MRV1 request resumes after preemption, so recomputed prompt chunks are not counted twice.

## Claims

- Reset pooling state only for requests resumed from preemption.
- Preserve accumulated chunks across ordinary scheduling pauses.

## Validation

The affected worker regressions and scoped pre-commit hooks pass. Removing the reset duplicates pooling rows after preemption; the ordinary-pause control still passes.

To run the related suites in a configured development environment:

```sh
.venv/bin/python -m pytest tests/v1/worker
```

A real MRV1 run used Qwen3-Embedding-0.6B on an RTX 5070 Ti with BF16, eager FlashAttention 2, and existing precompiled extensions. `reset_prefix_cache(reset_running_requests=True)` triggered scheduler preemption after a partial chunk. The fixed output matched the unpreempted reference exactly at shape `(256, 1024)`; removing the reset produced `(320, 1024)`. That GPU run covers the published branch and was not repeated against current upstream.

Upstream checks are stopped at contributor authorization; these local results do not establish a CI pass.

## Details

Preemption resets computed tokens, but the worker otherwise retains earlier pooling chunks and concatenates them with recomputed rows. Reset the existing `PoolingStates` in the resumed-request branch.

MRV2 already clears this state when a request is removed. #58778 concerns scheduler session resumption and does not replace this worker-state fix.
