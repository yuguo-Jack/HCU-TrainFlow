# [Bugfix][Pooling] Prevent duplicated token-pooling output after MRV1 preemption

[Upstream PR](https://github.com/vllm-project/vllm/pull/55192) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Model Runner V1 retains partial token-pooling results after preemption and then appends recomputed prompt chunks. Clear those partial results when the request resumes so token-pooling output does not repeat chunks.

## Claims

- Clear partial pooling state only for requests resumed from preemption.
- Preserve accumulated results across ordinary scheduling pauses.
- Keep MRV2 behavior unchanged; it already clears pooling state when a request is removed.

## Validation

The `vllm_runner` regression fails without the fix and passes with it on B200. GPU results used NVIDIA B200 GPUs with driver 580.95.05. Each run used this branch merged onto main `3a90cc6fd0` with a precompiled build of that commit. The comparison tree is the same merge with only the production file restored to main.

```text
Without the fix: assert torch.Size([320, 1024]) == torch.Size([256, 1024])
With the fix:    final vectors have shape (256, 1024), minimum cosine similarity to an unpreempted request 0.9999998
```

The same preemption through `LLM` on MRV2 returns shape (256, 1024) and the same similarity with and without the fix, so MRV2 is not affected. The fix applies to deployments that still run MRV1, for example with `VLLM_USE_V2_MODEL_RUNNER=0`. The complete `test_all_pooling_plus_chunked_prefill.py` file passes on the merged tree. The worker-level case also fails without the fix, with `torch.Size([5, 1]) != torch.Size([3, 1])`.

```sh
.venv/bin/python -m pytest \
  tests/models/language/pooling/test_all_pooling_plus_chunked_prefill.py -v -s
.venv/bin/python -m pytest \
  tests/v1/worker/test_gpu_model_runner.py::test_token_pooling_after_request_resumes -v
```

The ordinary-pause case keeps synthetic runner setup, because no public path was found that leaves a running request unscheduled for one step. Upstream checks are stopped at contributor authorization.

## Details

Preemption resets computed tokens, but MRV1 otherwise keeps earlier pooling chunks and concatenates them with recomputed rows. Reset the existing `PoolingStates` only in the resumed-from-preemption branch. The token-embedding guide now explicitly identifies MRV1 (`VLLM_USE_V2_MODEL_RUNNER=0`) and distinguishes preemption from an ordinary scheduling pause.

MRV2 already clears this state when removing a request. #58778 concerns scheduler session resumption and does not replace this worker-state fix.
