# [Bugfix][ROCm][Disagg] Allow MoRIIO HMA per-layer block_len

[Upstream PR](https://github.com/vllm-project/vllm/pull/58585) · state: closed · merged: True

## Original PR description

## Purpose

MoRIIO KV cache registration under HMA requires a uniform `block_len` across attention layers. Hybrid models (GLM-5.2 DSA, MiniMax, Gemma4) register layers with different per-layer `block_len` / `block_size` (e.g. `9216` vs page default `2112`). Registration then raises:

```
ValueError: MoRIIO KV cache block length mismatch for layer ...: 9216 != 2112
```

and PD bring-up fails at health-gate. Layer transfers already size RDMA from per-layer geometry; the uniform check is stricter than the transfer path.

## Changes

`vllm/distributed/kv_transfer/kv_connector/v1/moriio/moriio_connector.py` (KV registration):

- Allow divergent per-layer `block_len` (bytes) always; log at debug per layer; advertise `max(block_lens)` to the peer with a single summary `logger.info`.
- Allow divergent `block_size` (tokens/page) **only when hybrid KV cache manager (HMA) is enabled** (Gemma4 SWA/full-attn from #53721). Without HMA, still raise on any `block_size` mismatch (including when `block_len` also differs — ChuanLi's case).
- Per-layer spam logs moved to `logger.debug` (okorzh).

`tests/v1/kv_connector/unit/test_moriio_hma_scheduler.py`:

- divergent `block_len` allowed
- divergent `block_size` rejected without HMA
- size+len both differ still rejected without HMA
- divergent `block_size` allowed with HMA (Gemma4)
