# [Feature][Quantization] Quantize MiMo-V2 o_proj online to FP8 behind VLLM_MIMO_OPROJ_FP8

[Upstream PR](https://github.com/vllm-project/vllm/pull/59083) · state: open · merged: False

## Original PR description

## Purpose

This PR upstreams work from the patch set of the MiMo recipe we deploy — Diffbot's MiMo-V2.6-Flash-RL FP8KV/W4A8 recipe (Hugging Face: diffbot/MiMo-V2.6-Flash-RL-FP8KV-W4A8-2x-RTX-PRO-6000, built by Mike Tung), itself porting parts from the local-inference-lab/vllm fork: the idea and the original implementation belong to the recipe's authors, not to us. Their version of this change is the recipe's own `VLLM_MIMO_OPROJ_FP8` switch; we re-derived the diff against upstream main, wrote the tests, and ran the checks.

### What and why

Opt-in runtime switch `VLLM_MIMO_OPROJ_FP8` (default off) that quantizes MiMo-V2's `o_proj` bf16 checkpoint weights online to per-tensor symmetric FP8 with dynamic activations instead of serving them in bf16. This mirrors a switch a downstream SM12x deployment runs in production; upstream it stays strictly opt-in.

The deployment's original form (`Fp8Config(is_checkpoint_fp8_serialized=False, ...)`) is rejected by current upstream — `fp8` no longer supports online quantization — so this PR expresses the same semantics through `OnlineQuantizationConfig` with `QuantSpec(weight=kFp8StaticTensorSym)`, applied to `o_proj` only.

MTP layers keep `quant_config=None` exactly as before, and with the flag off (the default) the `o_proj` quant config is passed through untouched.

### Duplicate-work check

Searched open PRs for `mimo o_proj`, `online fp8 o_proj`, and `VLLM_MIMO_OPROJ_FP8`. No open PR covers this (the only hits for the broader term are unrelated: #46400, llm-compressor alignment; #41834, DeepSeek SM12x). Re-ran the search immediately before opening this PR.

## Test Result

Results: **5 passed** — flag registered and defaulting off, gate-off keeps the original `quant_config` path, gate-on builds the online per-tensor config, the MTP prefix stays unquantized, and a real `RowParallelLinear` on meta weights resolves to `Fp8PerTensorOnlineLinearMethod`.

Disclosures: `pre-commit run` itself cannot execute in this NixOS environment (hook environments fail with the `stub-ld` dynamic-linker error), so the repo-pinned ruff 0.14.0 was run directly. **No model eval was run** — the change is default-off and gated by a flag; a deployment enabling it should measure quality on its own model before rollout. Full-suite runs are limited in this environment by pre-existing gated-repo collection errors and GPU memory.
