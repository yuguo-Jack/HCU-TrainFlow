# [Bugfix][Spec Decode] Skip V2 draft_model speculation past the draft context

[Upstream PR](https://github.com/vllm-project/vllm/pull/59517) · state: closed · merged: False

## Original PR description

## Purpose

Model Runner V2 drafts an independent `draft_model` at the target model's `max_model_len`. `StandaloneARSpeculator` (formerly `PlainDraftModelSpeculator`, renamed in #60335) stores that target length and clamps positions to it, so a draft whose own context is shorter indexes past its rotary cache and KV. The fault is asynchronous and usually surfaces as a CUDA illegal memory access in a later kernel.

The V1 runner already avoids this. It sets `effective_drafter_max_model_len` from `draft_model_config.max_model_len` (the min of the draft config, the target, and `speculative_config.max_model_len`) and `_input_fits_in_drafter` skips the drafter when `max_seq_len + num_speculative_tokens` exceeds that limit. V2 had no such gate.

#57964 raises a DFlash draft's `max_position_embeddings` to the target's `max_model_len`. That is the right fix when the draft shares the target's positional space, and the PR says so: an independent `draft_model` should keep its own limit and skip, which is a separate change. This is that change. It does not resize the draft, and it does not change EAGLE or DFlash.

On the V2 standalone draft path, `propose` now does the same comparison as V1, using the batch's CPU seq-len upper bound. If the batch does not fit, the draft forward is not run and the previous step's draft ids are cleared. With data parallelism, ranks all-reduce a min of that decision, so one rank cannot enter the draft forward while another skips it. #57749 only warns on the V1 gate, and #52546 only warns that `speculative_config.max_model_len` looked unread; neither ports the skip to V2.

Related to #57941.

## Test Plan

CPU unit test, no GPU:

```
python -m pytest tests/v1/worker/test_plain_draft_capacity_gate.py -v
```

The draft limit in the test is 100 and `num_speculative_tokens` is 3, so 97 still drafts (`97 + 3 == 100`) and 98 skips. The same boundary is checked for a dummy run. A data-parallel peer that does not fit forces this rank to skip even when the local batch is inside the limit. The target `max_model_len` in the fixture is 4096, so a check against the target length would fail the test.
