# [XPU] Fix XPU attention-sink reload test failures (Event shim + hy_v4 skip)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61722) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fixes two XPU-only failures in `test_attention_sink_deepseek_hy_loading_uses_parameter_loader` seen in [Buildkite intel-ci build 14222](https://buildkite.com/vllm/intel-ci/builds/14222#01a13cd3-6a2e-4f68-90bb-bf8575cef5c1). Follow-up to #57797, which added this test.

## Claims

- `torch.cuda.Event` shim (`_xpu_event`) was a plain function, not a class. `_torch_cuda_wrapper` patches it onto `torch.cuda.Event` permanently (by design), so any later `torch.cuda.Event | None` annotation evaluated in the same process (e.g. in `deepseek_v41/common/engram.py`) raised `TypeError`, since only types support `|`. Fixed by making `_xpu_event` a class, matching the existing `_EventPlaceholder` pattern in `vllm/v1/worker/cpu/shm.py`.
- `hy_v4` legitimately doesn't support XPU (`vllm/models/hy_v4/__init__.py` raises `NotImplementedError` on import). The test parametrization didn't skip it on XPU, so it failed outright. Added `skipif(current_platform.is_xpu())`, following the existing ROCm-only `skipif` pattern already used in this file.

## Validation

```bash
.venv/bin/python -m pytest tests/v1/worker/test_xpu_model_runner.py tests/model_executor/model_loader/test_reload.py -k "torch_cuda_wrapper or attention_sink_deepseek_hy" -v
```
All pass (hy_v4 cases skip, since this sandbox itself resolves to the XPU platform). Also reproduced the original `TypeError` against the pre-fix code and confirmed it's gone after the fix. `ruff check` passes.
