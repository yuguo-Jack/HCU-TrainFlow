# [Pooling] Register pooling routes for the selected task

[Upstream PR](https://github.com/vllm-project/vllm/pull/57706) · state: open · merged: False

## Original PR description

## Purpose

Pooling routes were registered for every supported task even though handlers existed only for the selected task. Register dedicated routes only for the selected task so unavailable APIs return 404 instead of 5xx.

## Reproducer

Start BGE-M3 with token classification selected:

```bash
CUDA_VISIBLE_DEVICES=0 VLLM_USE_V2_MODEL_RUNNER=1 vllm serve BAAI/bge-m3 \
  --runner pooling \
  --max-model-len 512 \
  --hf-overrides '{"architectures": ["BgeM3EmbeddingModel"]}' \
  --pooler-config.task token_classify
```

Then call an unselected dedicated embedding route and the selected generic pooling route:

```bash
curl -sS -X POST http://localhost:8000/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model":"BAAI/bge-m3","input":["What is BGE M3?"],"encoding_format":"float"}'

curl -sS -X POST http://localhost:8000/pooling \
  -H 'Content-Type: application/json' \
  -d '{"model":"BAAI/bge-m3","input":["What is BGE M3?"],"task":"token_classify"}'
```
