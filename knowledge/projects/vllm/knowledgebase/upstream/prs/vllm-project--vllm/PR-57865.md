# [Bugfix] Account for workspace retained by graph profiling before KV sizing

[Upstream PR](https://github.com/vllm-project/vllm/pull/57865) · state: closed · merged: False

## Original PR description

- Reserve memory retained by graph setup before sizing the KV cache, preserving forward-pass peak headroom even when optional graph reservation is disabled.
- Measure V1 and V2 graph memory from released graph allocations while temporary profiling KV tensors remain alive, excluding persistent workspace and dummy KV from the graph estimate.
- Preserve sampling and extrapolation for uncaptured graph sizes, measuring shared decoder pools and separate encoder pools through their actual release.
- Release V2's FastPrefill helper before measuring graph cleanup so its graph-manager reference cannot keep the profiling pool alive.
- Add budget, ownership, and real GPU allocation regressions for workspace allocated during bootstrap or capture.

In July, [#49208](https://github.com/vllm-project/vllm/pull/49208) moved graph profiling outside the forward memory-profiling context, leaving allocations first retained during graph setup outside the closing snapshot used for KV sizing. The September AITER upgrade in [#56885](https://github.com/vllm-project/vllm/pull/56885) exposed that older accounting gap in [CI build 90039's failing job](https://buildkite.com/vllm/ci/builds/90039/list?sid=01a0bd6c-73d2-48d6-82a3-1e021270e178&tab=output). Upstream [AITER #3606](https://github.com/ROCm/aiter/pull/3606) increased the required prefill scratch allocation as part of a correctness fix, making the unbudgeted allocation large enough to exhaust the remaining memory. The reported CI stack uses V2, while the V1 changes preserve the same released-graph-versus-retained-workspace contract for the other runner sharing Worker.

**Related work:** [#51590](https://github.com/vllm-project/vllm/pull/51590) substantially overlaps the accounting problem, but captures every V1 descriptor and includes setup/workspace and temporary KV in the graph estimate. This implementation retains sampling, separates persistent and released allocations, covers V2, and charges retained memory when optional graph reservation is disabled. [#46883](https://github.com/vllm-project/vllm/pull/46883) introduces early FlashInfer reservation, leases, and workspace locking; this change handles observed later growth without backend opt-in, and combining them requires reconciling profiling order and teardown ownership.

Implementation, investigation, tests, and this description were AI-assisted.

We only capture the two largest FULL graphs during profiling. `full_estimate` extrapolates their cost to all configured FULL graphs, while `sum(mem_samples)` is the part already sampled. The cleanup measurement includes those sampled graphs, so we subtract them to avoid counting them twice. For example, with five graphs and samples of 100 MiB and 20 MiB, the total estimate is 180 MiB. We already measured 120 MiB, so we add the remaining 60 MiB. The subtraction was also present in the previous expression. Strictly speaking, the name is shorthand: the existing 1 MiB per-graph floor can contribute some safety padding too.
