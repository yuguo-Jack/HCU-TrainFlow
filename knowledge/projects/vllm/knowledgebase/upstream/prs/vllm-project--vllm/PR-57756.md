# [ROCm] Fuse DeepSeek V4.1 decode metadata and final norm

[Upstream PR](https://github.com/vllm-project/vllm/pull/57756) · state: open · merged: False

## Original PR description

## Summary

- let the gfx950 V4.1 sparse-decode kernel consume dense logical top-k indices directly and perform block-table translation in-kernel
- retain the ragged metadata path for other architectures, with fused length/indptr construction and small-batch packing
- fuse V4.1's final carried-pre-mix HC collapse with the final RMSNorm
- preserve the baseline sparse-attention split boundaries and reduction order
- cover invalid-token masking, non-identity request/block mappings, both ragged dispatch paths, CUDA graph replay, and empty trusted sparse metadata

The sparse metadata/direct-top-k changes are vLLM Triton changes and do not modify AITER.

The final HC collapse + RMSNorm fusion is also a vLLM Triton kernel. It is narrower than #51244, which implements broader TileLang MHC post + HC head + RMSNorm fusions; this PR keeps the measured V4.1-specific final-collapse path visible for review while it remains Draft.

### Exactness-cost recovery

The first bitwise-exact direct implementation restored a standalone top-k
length scan in every compressed-attention consumer and restricted direct mode
to 5-32 rows. That unintentionally removed the direct path from C1/C4 and added
38 length-kernel launches per decode token at C5-C32.

The current implementation derives the exact length inside the existing sparse
partial kernel from the same graph-stable metadata used by the SWA builder:
`seq_lens`, `query_start_loc`, `token_to_req_indices`, and `is_valid_token`.
The formula is the indexer contract
`min((absolute_position + 1) // compress_ratio, index_topk)`. This preserves
the baseline split boundaries without scanning the 512-entry top-k row and
without allocating a length tensor or launching another kernel.

The exact direct path now covers C1-C64, the configured service range. A
same-process alternating full-path microbenchmark (diagnostic only because the
node is shared) showed exact direct ahead of ragged metadata by 23-50 us per
compressed-attention layer across rows 1/4/5/8/16/32/64. Production Kineto
traces confirm zero `_compute_topk_lens_kernel`,
`_build_global_topk_ragged_kernel`, and `_pack_global_topk_ragged_kernel`
launches at both C1 and C16. The sparse partial/reduce topology is unchanged.

The full ROCm attention test file passes 80 tests, including bitwise equality
between explicit-length, position-derived-length, and ragged paths at ratio 1
and ratio 2, rows 1-64, plus CUDA graph replay after in-place sequence-length
changes.
