# [Bugfix] Honor batch invariance in gated normalization row tiling

[Upstream PR](https://github.com/vllm-project/vllm/pull/57280) · state: open · merged: False

## Original PR description

## Purpose

Keep gated normalization row tiling independent of batch size when `VLLM_BATCH_INVARIANT=1`. The current occupancy heuristic can select different Triton reduction layouts for the same GDN row in ordinary decode and speculative verification. That changes inverse standard deviations and, in some cases, the output values.

The shared selector now returns one row per program in batch-invariant mode. Runtime dispatch and compile-only warmup use the same policy. The normal occupancy heuristic remains unchanged outside that mode; this does not serialize the batch into separate launches.

## Test Plan

```sh
pytest tests/kernels/test_fla_layernorm_guard.py -k 'batch_invariant'
```

The regression checks exact outputs and inverse standard deviations for eight positions versus serial GDN-head execution in BF16 and FP32. A separate test covers the row policy across five batch sizes.

## Test Result

Ruff passed. A native R9700 probe extracted the **actual current-main kernel and row-selector source** and exercised 32 synthetic cases (two dtypes, 16 seeds):

| Comparison with serial execution | Original policy | Fixed policy |
| --- | ---: | ---: |
| Output elements differing | 4 | 0 |
| Inverse-standard-deviation elements differing | 1,044 | 0 |

The native probe above ran successfully in the installed ROCm/Triton environment. This new port still needs testing inside a complete server built from upstream vLLM `main`, including the repository pytest harness, so it is initially a draft. **The fixed compiled Radiance stack has already completed the separate end-to-end 10,000-position model test.**

[Reproducer, aggregate receipt and wider investigation](https://github.com/Terrydaktal/d7-rdna4-report/blob/main/reports/d7-rdna4-2026-09-17/REPORT.md). The report now compares original and final eager M1 versus compiled M8 directly on the same 10K corpus. With both fixes applied, all 10,000 decode positions and 23 initial-prefill predictions match, including top-1/10/20 sets, ranking and full-vocabulary hashes. It also retains the separate 320-position isolated-stage comparisons and compiled timings. Those full-model results cover the pinned downstream integration, not this new upstream port. No model-accuracy or arbitrary-input equivalence claim is made.
