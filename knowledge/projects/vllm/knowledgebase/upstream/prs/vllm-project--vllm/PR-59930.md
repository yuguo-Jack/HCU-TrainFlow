# [Bugfix] Bound prompt_embeds decode budget per request

[Upstream PR](https://github.com/vllm-project/vllm/pull/59930) · state: open · merged: False

## Original PR description

## Overview

Fixes #59919. Make `VLLM_MAX_EMBED_DECODE_BYTES` apply to all `prompt_embeds` tensors in one request, including chat content parts and completion batches.

## Claims

- Prevents multiple prompt-embedding parts from each consuming the full decode budget.
- Enforces the shared limit before `to_dense()` for synchronous and asynchronous loading.
- Preserves the existing per-call behavior for standalone embedding loads and other embedding modalities.

## Validation

- `uv run --no-sync ruff check vllm/renderers/base.py vllm/utils/sparse_utils.py vllm/renderers/embed_utils.py vllm/entrypoints/chat_utils.py tests/renderers/test_chat_utils_prompt_embeds.py`
- `uv run --no-sync ruff format --check ...`
- Focused parser and renderer tests: `3 passed` for sync chat, async chat, sync completion batches, and async completion batches.
- Sparse validation suite: `32 passed`; 10 setup cases were blocked locally by missing `uvloop` during model-architecture inspection.
- Full serving/model validation was not run in this Windows CPU-only environment; CI and a Linux serving environment should run the completion/chat integration tests.

## Details

The old guard compared each decoded tensor with the environment limit independently. A request containing many sparse tensors could therefore allocate the limit once per part. `TensorDecodeBudget` atomically reserves each tensor's declared dense footprint, and the same request-scoped budget is shared by chat trackers and renderer batch paths, including concurrent async loads. The change adds focused sparse multi-part tests for both APIs.
