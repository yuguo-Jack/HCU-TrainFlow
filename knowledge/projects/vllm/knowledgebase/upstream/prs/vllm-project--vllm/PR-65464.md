# [Refactor] Migrate FlashInfer NVLink two-sided to MoEEpCommunication

[Upstream PR](https://github.com/vllm-project/vllm/pull/65464) · state: open · merged: False

## Original PR description

## Purpose

Follow-up to #61655, which migrated `flashinfer_nvlink_one_sided` to FlashInfer's `MoEEpCommunication` API. This migrates `flashinfer_nvlink_two_sided` the same way: off `flashinfer.comm.trtllm_alltoall.MnnvlMoe` and onto `flashinfer.moe_ep.NVLinkTwoSidedAlltoAll`.

- **Why now:** FlashInfer 0.7.3 removes `flashinfer.comm.trtllm_alltoall` (`MnnvlMoe`, `MoEAlltoallInfo`; flashinfer-ai/flashinfer#6047, #6621), so `--all2all-backend flashinfer_nvlink_two_sided` fails at import on 0.7.3. FlashInfer 0.7.2 already ships `NVLinkTwoSidedAlltoAll` (as a wrapper over `MnnvlMoe`), so this works on the current pin and keeps working after the bump.
- **Mixed `top_k`:** FlashInfer fixes `top_k` per communication, and a speculative draft's MoE can route fewer experts than the target. DSpark on DeepSeek-V4.1 routes 3 of 128 experts against the target's 6 of 384. The manager therefore keeps one `NVLinkTwoSidedAlltoAll` per `(top_k, num_experts)`. FlashInfer shares an EP group's FIFO and prepare workspaces across instances (`NVLinkTwoSidedAlltoAll._WORKSPACES`), so the extra instance adds no symmetric memory. The one-sided manager still asserts a single `top_k` ("does not support heterogeneous top_k"), so today two-sided is the FlashInfer NVLink backend that can serve DeepSeek-V4.1 with DSpark under EP.

## Changes

- `FlashInferNVLinkTwoSidedManager`: `get_communication(max_num_tokens, top_k, num_experts, hidden_size)` creates (collectively over the EP group) or grows the communication for that `(top_k, num_experts)`. The old `initialize()`/`ensure_alltoall_workspace_initialized()`/workspace tensors are gone.
- `FlashInferNVLinkTwoSidedPrepareAndFinalize`:
  - takes the MoE shape at construction and creates its communication during model construction, as the one-sided path does
  - `prepare`/`finalize` call `dispatch()`/`combine()`
  - the kernels, their arguments and the top-k slot reduction are the ones `MnnvlMoe` ran
  - padding rows keep expert id `num_experts` (`invalid_expert_id=num_experts`)
  - routing weights are returned in the router's dtype
- The per-step token bound is passed as `max_tokens_per_rank` on 0.7.2 and `runtime_max_tokens_per_rank` on 0.7.3 (flashinfer-ai/flashinfer#7099), resolved from the installed `dispatch` signature.
- `has_flashinfer_nvlink_two_sided()` checks the `flashinfer.moe_ep` exports instead of the removed module.
- `all2all_utils` passes `max_num_tokens` (`max_num_batched_tokens`, as for one-sided), `top_k`, `num_experts` and `hidden_size`.

## Test Plan

- `tests/distributed/test_mnnvl_alltoall.py`:
  - **lifecycle:** reuse, a separate communication per `top_k`, growth, cleanup
  - **data:** runs `FlashInferNVLinkTwoSidedPrepareAndFinalize` with `top_k` 2 and 1 on one manager and checks the exact round trip (`hidden × distinct expert ranks`) plus linearity, as the previous test did
- End-to-end serving with the backend on real traffic shapes.

## Test Result

Validated on a downstream build (vLLM 0.33.0 + FlashInfer 0.7.3rc1, B300). This change applied there without conflicts.

- **Serving:** DeepSeek-V4.1-Flash, P/D with 2 × DEP2 prefill (`--all2all-backend flashinfer_nvlink_two_sided`, DSpark k=5) + 3 × TP4 decode. Both communications initialize on every EP rank (`top_k 6, num_experts 384` and `top_k 3, num_experts 128`) and the lane serves normally. Before this change the same configuration fails at import on FlashInfer 0.7.3.
- **Tool-call correctness:** Moonshot Kimi Vendor Verifier tool-call schema suite, 204 cases × stream/non-stream × `tool_choice` auto/required:

  | Prefill backend | `auto` | `required` | Behaviour tests |
  |---|---|---|---|
  | this change (two-sided) | 408/408 | 407/408 | 8/8 |
  | `allgather_reducescatter` reference | 408/408 | 407–408/408 | 8/8 |

  The one `required` miss is a string `minLength` case that also fails intermittently on the reference backend (XGrammar 0.2.8 drops length bounds under its structural-tag guard).
- **Images and logprobs:** image inputs over HTTP and data URLs, and chat output logprobs, pass.
- **AgentX (agentic trace replay, C32):** 1,758 requests with 0 errors. End-to-end per-user throughput matches the `allgather_reducescatter` reference within run-to-run noise (p50 326.8 vs 328.6 tok/s/user).
- **Not yet run:** the updated `tests/distributed/test_mnnvl_alltoall.py` on GPUs, and any run on FlashInfer 0.7.2.post1 (this repo's current pin). Draft until both are done.
