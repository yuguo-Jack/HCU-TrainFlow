# [Bugfix][NIXL] Use XPU-compatible block size in sleep test

[Upstream PR](https://github.com/vllm-project/vllm/pull/62578) · state: closed · merged: True

## Original PR description

## Overview
Fixes the `:intel: (BMG) V1 test` job in [Intel CI build 14719](https://buildkite.com/vllm/intel-ci/builds/14719#01a155b5-3348-45bb-8171-136214a9dc12). This failure is a regression introduced by [#59635](https://github.com/vllm-project/vllm/pull/59635), which added the NIXL sleep/restore test with block size 16 despite FlashAttention requiring a multiple of 64 on Intel XPU.

## Claims
The test now uses a 64-token block on XPU and retains 16 on other platforms.

## Validation
- `.venv/bin/python -m pytest tests/v1/kv_connector/unit/test_nixl_connector.py::test_sleep_unregisters_and_restores_kv_caches -v` — passed
- `pre-commit run --files tests/v1/kv_connector/unit/test_nixl_connector.py` — passed

## Details
The test introduced in #59635 constructed a block-16 KV cache directly rather than using the existing `maybe_update_block_size` helper. Reusing that helper aligns both the config and KV-cache spec with the platform's supported block size. No open PR was found addressing this test-fixture regression. AI assistance was used.
