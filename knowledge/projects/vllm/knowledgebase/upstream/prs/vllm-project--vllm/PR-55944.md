# [Docs] Explain numerical differences across execution modes

[Upstream PR](https://github.com/vllm-project/vllm/pull/55944) · state: closed · merged: False

## Original PR description

## Overview

Explain how execution settings can change greedy output. Add guidance to compare logprobs at the same input prefix and check the gap between the two leading tokens.

## Claims

- Separate repeatability within one configuration from agreement across configurations.
- Explain how numerical rounding can change the selected token at a near tie.
- Make clear that a small token gap alone does not rule out a kernel bug.

## Validation

This change only updates documentation. It does not change model execution or sampling.

```bash
pre-commit run --files docs/features/batch_invariance.md
```

All applicable hooks passed on the updated branch, including spelling and Markdown lint. The execution flags were checked against the current source and compile debugging guide. No new model benchmark was run. Upstream test CI is blocked by the contributor gate.

## Details

Changing compilation or CUDA graph settings can change kernel selection and rounding. The size of a logprob difference depends on the model, prompt, hardware, and settings. The text avoids a universal numerical range and a universal default execution mode.

Open PR searches found no other documentation change for this cross-mode comparison. [#55238](https://github.com/vllm-project/vllm/issues/55238) records the related investigation. Related batch-invariance kernel PRs change execution behavior.
