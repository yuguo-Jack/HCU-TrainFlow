# [Bugfix][Frontend] systemone: refuse thinking-only chat templates

## Overview

`/v1/systemone` and `/v1/decisions` read each answer from the first token of the reply, with thinking off. Thinking-only checkpoints such as `Qwen/Qwen3-4B-Thinking-2507` and `deepseek-ai/DeepSeek-R1-0528-Qwen3-8B` use `Qwen3ForCausalLM`, so both endpoints are enabled for them. Their reply always starts inside a thought, so every read returns 200 with probabilities that are noise.

This PR checks the chat template at startup and returns 501, with the reason, when the reply would start inside a thought.

## Claims

- At startup, `NextTokenStrategy` renders the chat template with thinking off. It disables both endpoints when the reply would start inside a thought:
  - the prompt opens a thought (`Qwen3-4B-Thinking-2507`), or
  - the prompt has no closed thought, and the template drops thoughts from the assistant history (`DeepSeek-R1-0528-Qwen3-8B`).
- Hybrid Qwen3 and Qwen3.5 templates close the thought, and `Qwen3-4B-Instruct-2507`'s template has no thoughts, so these stay enabled.
- Liquid d1 is exempt. Its template drops past thoughts, but d1 answers without one. Its reads are unchanged.
- The 501 body of both endpoints names the reason, for example `/v1/decisions is disabled: the chat prompt opens a thought`. The reason also covers the existing startup failures, such as an unsupported architecture.
- Docs: `docs/models/structured_decisions_models.md` said `chat_template_kwargs` can turn thinking on. A request with `"enable_thinking": true` returns 400, so the docs now say thinking is always off.

## Details

The check runs once, at startup, in `NextTokenStrategy.__init__`:

1. Render one user turn with `enable_thinking=False` and the generation prompt. If the last `<think>` comes after the last `</think>`, the reply starts inside a thought.
2. If the prompt has no `</think>`, render a history with an assistant turn that holds a thought. A template that drops the thought from the history is a thinking template whose prompt does not close the thought.

`init_decisions_state` already turns a `ValueError` from the strategy into a disabled endpoint. It now stores the message on `app.state`, and both routers put it in the 501 body.

Limitation: the check reads only the template. A template that turns thinking off for a model that still thinks passes the check. Its reads are noise, and `diagnostics.label_mass` is near 0.
