# [Feature][Kernel] Add opt-in CuTe DSL compile and AOT caches

[Upstream PR](https://github.com/vllm-project/vllm/pull/65025) · state: closed · merged: False

## Original PR description

## Overview

Let GPU workers reuse CuTe DSL kernels across restarts with two opt-in caches. Both are off by default.

## Claims

- `VLLM_CUTE_DSL_COMPILE_CACHE=1` enables CUTLASS's existing compile cache. Tracing still runs.
- `VLLM_CUTE_DSL_AOT_CACHE=1` loads exported kernels before tracing. Unsupported inputs or unusable entries fall back to compilation.

## Validation

| Check | Result |
| --- | --- |
| Focused CPU tests | 34 passed, 5 GPU tests skipped |
| Real worker restart, one B300 | Flags-off, cold and warm runs produced identical tokens/text. Cold: 9 exports. Warm: 9 hits, no CuTe tracing or compilation. |
| Missing-hook control | The same test failed with `cold: worker hooks not installed` after disabling only the two worker installation calls. |
| M3 indexer | Six variants passed cold/warm checks; serial writer/reader checks passed on two matching B300 workers. |

The restart test uses `hmellor/tiny-random-Gemma2ForCausalLM` at `7551e53abee9dd16896a86847cd137cbfe41764f`, FLASH_ATTN, MRV2, an in-process EngineCore and greedy generation. Pre-commit passed. The new test is selected by the B200 attention CI step; that CI run is still pending.

## Details

The AOT key covers code, runtime, hardware, configuration and kernel arguments. Cache files contain executable objects and pickled metadata, so writers must share a trust boundary. Native compile-cache hits also require the same installation path.

Keeping this draft for review of the cache contract, B200 CI and representative full-model startup measurements. These checks establish cache reuse, not overall startup savings or general multiprocess/model coverage. Searches for open CuTe compile/AOT cache PRs found no matching change.
