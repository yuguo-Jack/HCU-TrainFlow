- okorzh-amd · comment · 2026-10-20T17:03:40Z · [source](https://github.com/vllm-project/vllm/pull/61879#discussion_r4327846453)

File: `vllm/entrypoints/openai/completion/protocol.py` · line 87

skip_special_tokens now defaults to None in the chat, completion and responses requests, but only to_sampling_params resolves it. That breaks three things for every model. (1) /v1/completions with use_beam_search=true and no skip_special_tokens passes None through to_beam_search_params (:344), and tokenizer.decode(..., skip_special_tokens=None) in beam_search/online.py:232 raises TypeError on HF fast tokenizers. The beam case in test_completion.py:620 takes this path. (2) online_derenderer.py:1046 reads the raw field, so derender keeps special tokens that the coupled endpoint strips. (3) 18 existing CPU tests that expect a default request to have True now fail.

Keep bool = True and using the generation-config value only when the client did not send the field: self.skip_special_tokens if "skip_special_tokens" in self.model_fields_set else default_sampling_params.get("skip_special_tokens", True)

- okorzh-amd · comment · 2026-10-20T17:06:59Z · [source](https://github.com/vllm-project/vllm/pull/61879#discussion_r4327877343)

File: `vllm/distributed/device_communicators/all_reduce_utils.py` · line 88

This changes the standalone FlashInfer MNNVL all-reduce for every model, not just Muse.
- B200/GB200 TP8 had no entry, so it fell back to the 1 MiB fusion limit. With default settings, every TP all-reduce up to 128 MiB per rank now goes to FlashInfer MNNVL instead of NCCL symm-mem or custom AR.
- On B300 TP8 this doubles the 64 MiB cutoff tuned in #53606.
- flashinfer_all_reduce.py:69 drops the -1, so every cutoff becomes inclusive.
get_fi_ar_workspace sizes the workspace from this value with no max_num_batched_tokens cap, and the test now expects 9362 tokens instead of 4681. By my reading of the flashinfer 0.7.2 sizing, that is roughly 0.75 GiB per GPU taken from the KV cache. Could you split this out with B200/B300 TP8 all-reduce sweeps and memory numbers, or gate it to Muse?

- okorzh-amd · comment · 2026-10-20T17:09:08Z · [source](https://github.com/vllm-project/vllm/pull/61879#discussion_r4327898458)

File: `vllm/models/muse_spark/amd/muse_moe_runner.py` · line 591

The Quark expert audit (_expected_quark_expert_weight_slots :746) expects w13 and w2 weight slots for every global expert. With --enable-expert-parallel --enable-ep-weight-filter, the loader skips the .weight tensors of non-local experts (ep_weight_filter.py:84). In that case a Muse Quark FP8 or MXFP4 checkpoint at TP8+EP on MI355X raises "Missing MuseSpark1x Quark expert tensors" on every rank and never starts (same at :631 for MXFP4).

chrono's format(...).to_string() panics on an invalid specifier, for example strftime_now('%Q') or a trailing %. rust/Cargo.toml sets panic = "abort", so the panic kills the frontend process.
