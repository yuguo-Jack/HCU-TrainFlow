# [Feature][ROCm] Enable gfx1030 (RDNA2) as a recognized RDNA arch

[Upstream PR](https://github.com/vllm-project/vllm/pull/52391) · state: closed · merged: False

## Original PR description

## Purpose

gfx1030 (RX 6900/6800/W6800/V620) cards are currently not in the list of
supported ROCm image despite being supported by ROCm.

## Tests

Hardware: 4× Radeon PRO V620 (gfx1030). Software: torch 2.12.0+rocm7.2,
ROCm 7.2.0. `vllm bench throughput`, 32 prompts, `--tensor-parallel-size 4`,
16k prefill + 1k output.

| Model | Kernel | c=1 | c=8 | c=32 |
|---|---|---:|---:|---:|
| Qwen3-4B (FP16) | — | 44.62 | 29.81 | — |
| Qwen2.5-7B-GPTQ | Triton W4A16 | 8.01 | 39.68 | — |
| Qwen2.5-7B-GPTQ | Exllama | 10.23 | 51.51 | — |
| Qwen3.6-27B-GPTQ-W4A16-G32 | Triton W4A16 | 6.44 | 15.83 | 26.74 |
| Qwen3.6-27B-GPTQ-W4A16-G32 | Exllama | 18.49 | 21.15 | 46.42 |

## How to reproduce

```sh
HIP_VISIBLE_DEVICES=0,1,2,3 \
VLLM_USE_V2_MODEL_RUNNER=1 \
VLLM_ROCM_USE_AITER=0 VLLM_ROCM_USE_AITER_MOE=0 \
FLASH_ATTENTION_TRITON_AMD_ENABLE=TRUE \
VLLM_RDNA_FORCE_FP16=1 \
TORCH_BLAS_PREFER_HIPBLASLT=0 \
PYTORCH_TUNABLEOP_ENABLED=1 PYTORCH_TUNABLEOP_HIPBLASLT_ENABLED=0 \
GPU_MAX_HW_QUEUES=2 VLLM_WORKER_MULTIPROC_METHOD=spawn \
HIP_FORCE_DEV_KERNARG=1 TORCHINDUCTOR_COMPILE_THREADS=1 \
VLLM_BATCH_INVARIANT=0 \
vllm bench throughput \
    --model <path-to-Qwen3.6-27B-GPTQ-W4A16-G32> \
    --input-len 16384 --output-len 1024 \
    --num-prompts 32 --max-num-seqs 1 \
    --gpu-memory-utilization 0.72 \
    --dtype float16 --tensor-parallel-size 4 --max-model-len 17472 \
    --quantization compressed-tensors \
    --trust-remote-code --language-model-only --skip-mm-profiling \
    --compilation-config '{"cudagraph_mode": "FULL_AND_PIECEWISE", "compile_ranges_endpoints": []}'
```

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Add gfx1030 to the bake arch overrides**

This default is overridden in the documented bake/CI paths: `docker/docker-bake-rocm.hcl` still defaults `PYTORCH_ROCM_ARCH` to `gfx90a;gfx942;gfx950` and passes it as `ARG_PYTORCH_ROCM_ARCH` into `Dockerfile.rocm`, whose `ENV PYTORCH_ROCM_ARCH=${ARG_PYTORCH_ROCM_ARCH:-${PYTORCH_ROCM_ARCH}}` replaces the base image value. As a result, `docker buildx bake ... final-rocm` and the CI artifact/test-image builds still compile vLLM native code without gfx1030 even though this line now advertises/builds the base dependencies for it; users of those workflows will get images/wheels that still fail to load HIP code objects on V620/RX 6000. Please update the bake/CI defaults (and any explicit Buildkite env overrides) alongside this base default.
