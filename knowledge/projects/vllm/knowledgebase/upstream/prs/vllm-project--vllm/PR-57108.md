# [Bugfix][ModelLoader] Make enable_weights_track check quantized layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/57108) · state: closed · merged: True

## Original PR description

## Purpose

`enable_weights_track` is meant to catch weights a checkpoint did not provide, but it exempts every parameter of any layer whose quant method defines `process_weights_after_loading`. `QuantizeMethodBase` defines it, so that is every linear, MoE and embedding layer, quantized or not. On a quantized model the opt-in check therefore never fires: a block-FP8 checkpoint missing a `weight_scale_inv` loads and serves garbage.

- For quantized models, where the flag is opt-in, only KV-cache quantization parameters, empty placeholders, fbgemm_fp8's config-built `input_scale_ub` and online-quantization parameters stay exempt. The check now also reaches the model's unquantized layers, such as a vision tower. Unquantized models, where the check is on by default, are unchanged.
- `MoERunner.load_weights` now prefixes `routed_experts.`, so the names it returns match the registered parameters; otherwise every expert weight is reported as missing once the check is on.

## Related PRs

- #41086 added `enable_weights_track` together with the module-wide exemption narrowed here.
- #35074 tracked quantized models by default and was reverted the same day (#35309); the false positives reported against it (#35299, #35305) were GPTQ/AWQ MoE `g_idx` parameters, which vLLM no longer registers. Here quantized models stay opt-in; the KV-cache exemption follows #35074 and the empty-placeholder one #35299.
- #34930 (open) tracks quantized models by default with a warning and keeps the current exemption. It changes when the check runs, this PR what it checks; both edit `track_weights_loading`, so whichever lands second needs a rebase.

## Test Plan

- `pytest tests/model_executor/model_loader/test_registry.py`: three new cases, each failing if its part of the change is reverted. They run in CI's Model Executor job.
- Load one checkpoint or more per quantization format with `--model-loader-extra-config '{"enable_weights_track": true}'`, intact and with one tensor removed.

The change is 34 lines in default_loader.py plus a unit test. It narrows the per-module exemption in track_weights_loading, so that --model-loader-extra-config '{"enable_weights_track": true}' actually checks a quantized model. Today that exemption marks every parameter of any module whose quant_method defines process_weights_after_loading as loaded, and nearly every quantization method defines it, so the flag silently checks nothing on exactly the layers it was enabled for.

Verified before filing: 12 unit tests (3 of them fail on main without the fix), a 7-case before/after matrix showing only two rows change, and two end-to-end boots of a 274B DeepSeek-V4-Flash-FP8 checkpoint on 8x MI300X. Happy to rebase, or to switch to a declarative optional_param_names on the quant method if that shape is preferred.
