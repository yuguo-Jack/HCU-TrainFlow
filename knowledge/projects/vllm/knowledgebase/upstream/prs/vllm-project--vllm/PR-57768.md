# [Security] Time out K2 Horizon and FunctionGemma tool-call regexes

[Upstream PR](https://github.com/vllm-project/vllm/pull/57768) · state: open · merged: False

## Original PR description

## Summary
The `k2_horizon` and `functiongemma` tool parsers run `regex` patterns on model output without a timeout, unlike sibling parsers that already pass `timeout=VLLM_TOOL_PARSE_REGEX_TIMEOUT_SECONDS`. Pathological completions can stall the API-server event loop. This applies the same limit and treats `TimeoutError` as no tool call / skip later stream deltas.

## Changes
- `vllm/tool_parsers/k2_horizon_tool_parser.py`: pass the regex timeout on `_TOOL_CALL_RE` and `_ARG_RE`; catch `TimeoutError` on the non-streaming path (streaming already calls `extract_tool_calls` once the group is closed).
- `vllm/tool_parsers/functiongemma_tool_parser.py`: pass the timeout on `tool_call_regex` / `arg_regex`; catch `TimeoutError` on both non-streaming and streaming paths, and skip later stream deltas after a timeout.

## Codepath coverage
- Non-streaming `extract_tool_calls` for both parsers (`/v1/chat/completions`, batch, `/v1/responses`, Anthropic messages, derender).
- Streaming `extract_tool_calls_streaming`: k2_horizon reuses the non-streaming parse when the IFM group closes; functiongemma times out per-delta argument scans and does not retry after a timeout.
- `/invocations` and other generate surfaces that select these parsers go through the same methods.

## Tests
- `test_regex_timeout_treated_as_no_tool_call` — timeout is fail-closed (content returned, no tool calls) and `timeout=` is passed (k2_horizon `_TOOL_CALL_RE`, functiongemma `tool_call_regex`).
- `test_arg_regex_timeout_treated_as_no_tool_call` — same for k2_horizon `_ARG_RE` and functiongemma `arg_regex`.
- `test_streaming_regex_timeout_is_not_retried_on_later_delta` / `test_streaming_regex_timeout_skips_later_deltas` — a timed-out stream delta is not retried.
