# [Bugfix][Benchmark] Fix standalone dataset statistics plotting

[Upstream PR](https://github.com/vllm-project/vllm/pull/62292) · state: open · merged: False

## Original PR description



## Overview

`vllm bench serve --plot-dataset-stats` finishes the requests but raises an `AssertionError` when used without another output option. Include dataset statistics plots when deciding whether to generate an output filename.

## Claims

- `--plot-dataset-stats` can produce its PNG without `--save-result`, `--append-result`, or `--plot-timeline`.
- The plot respects `--result-dir` and `--result-filename`; saving a results JSON remains opt-in.

## Validation

- `uv run --offline --no-project --python .venv/bin/python -m pytest tests/benchmarks/test_serve_cli.py -k dataset_stats_plot_without_saving_results -q`: **1 passed, 3 deselected**. The same regression test fails on the base commit.
- Ran the actual benchmark CLI against a local deterministic OpenAI-compatible SSE fixture, using a cached tokenizer and two requests. Before: exit 1 at the filename assertion, no PNG. After: exit 0, one dataset statistics PNG, no results JSON. This was a CPU client/plotting check, without a model server.
- `pre-commit run --files vllm/benchmarks/serve.py tests/benchmarks/test_serve_cli.py`: passed.

## Details

`main_async()` already handles dataset statistics plotting independently. The early return in `compute_result_filename()` omitted that flag. The change adds it to the existing condition and adds a CPU regression test to the CLI suite.

I checked the open PR inventory and the complete diffs of 27 related `serve.py` PRs; none of the inspected changes fixes this filename condition.
