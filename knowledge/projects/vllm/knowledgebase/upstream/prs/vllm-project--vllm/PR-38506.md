# [Core] Make ModelRunnerOutput.num_nans_in_logits np.ndarray rather than python dict. Fixed bug with calculating num nans when speculative decoding in mrv1 and mrv2

[Upstream PR](https://github.com/vllm-project/vllm/pull/38506) · state: closed · merged: False

## Original PR description


Change ModelRunnerOutput.num_nans_in_logits to be an np.ndarray instead of a python dict for host side speedup. Additionally, found a bug where num_nans_in_logits is calculated incorrectly when speculative decoding is turned on in both Model Runner V1 and Model Runner V2.

## Purpose
Part of 'Data structure clean up' roadmap item in [#32455](https://github.com/vllm-project/vllm/issues/32455).

## Test Plan
Tested on cpu only, so only old model runner v1 is hit.

## Test Result
LLM.generate showed 3.3% improvement with VLLM_COMPUTE_NANS_IN_LOGITS turned on.

This refactoring to use `np.ndarray` is a good performance improvement. However, the logic for calculating `num_nans_in_logits` appears to be incorrect when speculative decoding is used, both in the old and new versions.

With speculative decoding, `logits` has more rows than requests (one for each draft token). The current implementation `num_nans_for_index[req_index]` only accounts for the NaNs in one token's logits per request, not the sum over all of a request's tokens (original + draft). This will result in undercounting NaNs.

To fix this, `_get_nans_in_logits` needs access to `spec_decode_metadata` from `_bookkeeping_sync`. You can then use `spec_decode_metadata.cu_num_sampled_tokens` to correctly segment and sum the NaNs for each request.

Here is a suggested implementation:

```python
def _get_nans_in_logits(
    self,
    logits: torch.Tensor | None,
    spec_decode_metadata: "SpecDecodeMetadata | None",
) -> np.ndarray:
    try:
        if logits is None:
            return np.zeros(len(self.input_batch.req_ids), dtype=np.int64)

        num_nans_for_index = logits.isnan().sum(dim=-1).cpu().numpy()
        num_nans_in_logits = np.zeros(
            len(self.input_batch.req_ids), dtype=num_nans_for_index.dtype
        )

        if spec_decode_metadata is not None:
            cu_num_sampled_tokens = spec_decode_metadata.cu_num_sampled_tokens.cpu().numpy()
            # np.add.reduceat is efficient for segmented sums.
            indices = np.concatenate(([0], cu_num_sampled_tokens[:-1]))
            if indices.shape[0] == num_nans_in_logits.shape[0] and indices.shape[0] > 0:
                np.add.reduceat(num_nans_for_index,
                                indices,
                                out=num_nans_in_logits)
        else:
            for i, req_id in enumerate(self.input_batch.req_ids):
                req_index = self.input_batch.req_id_to_index[req_id]
                if req_index < logits.shape[0]:
                    num_nans_in_logits[i] = num_nans_for_index[req_index]
        
        return num_nans_in_logits
    except IndexError:
        return np.empty(0, dtype=np.int64)
```
You would also need to update the call site in `_bookkeeping_sync` to pass `spec_decode_metadata`.
