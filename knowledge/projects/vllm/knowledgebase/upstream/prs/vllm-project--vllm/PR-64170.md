# [Doc] Fix long-text embedding example pooler config and GPU pinning

[Upstream PR](https://github.com/vllm-project/vllm/pull/64170) · state: closed · merged: True

## Original PR description

## Purpose

The long-text embedding example (`examples/pooling/embed/openai_embedding_long_text/`) had two problems that break it for anyone copying it:

- The README's `--pooler-config` snippet uses `"pooling_type": "auto"`. `PoolerConfig` only accepts `CLS`, `LAST` or `MEAN`, so pasting that JSON into `vllm serve` fails validation. `auto` is only a convenience inside `service.sh`, which maps it to a real type before building the config. I changed the snippet to `MEAN` (the default for the example's e5 model) and added a short note explaining this.
- `service.sh` hard-coded `export CUDA_VISIBLE_DEVICES=2,3,4,5`. That fails on any host with fewer than 3 GPUs and silently ignores the caller's own device selection. I removed it so the normal `CUDA_VISIBLE_DEVICES` from the environment applies. I also renamed the `VLLM_ENABLE_CHUNKED_PROCESSING` shell variable to `ENABLE_CHUNKED_PROCESSING` and stopped exporting it, since vLLM never reads it and the `VLLM_` prefix suggests it's a real env var.
