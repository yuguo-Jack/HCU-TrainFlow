# [Bugfix][Structured Output] Cap grammar-compile executor workers to avoid CFS throttling in containers

[Upstream PR](https://github.com/vllm-project/vllm/pull/49461) · state: open · merged: False

## Original PR description

## Overview

Bound structured-output grammar compilation to `max(1, min(cpu_count // 2, 8))` by default, with `VLLM_STRUCTURED_OUTPUT_MAX_COMPILE_WORKERS` as a positive-value override (0 = auto). Fixes #49460.

## Claims

- The default outer compile pool becomes 8 workers on a 172-core host, instead of 86, matching the existing fill-bitmask pool.
- Preserve current tokenizer initialization, grammar compilation, and fill-bitmask behavior; only compile-pool sizing changes.
- Allow operators to tune compile concurrency explicitly.

## Validation

All applicable pre-commit hooks passed on the four changed files, including Ruff, mypy, test tethering, SPDX, and import/configuration checks.

The manager tests exercise real xgrammar compilation and executor shutdown/cancellation. The sizing tests run in the existing CPU Buildkite structured-output suite (`.buildkite/test_areas/misc.yaml`).

GPU serving / before-and-after decode latency under a container CPU quota has **not** been measured for this updated revision. The production observations in #49460 motivated the fix; they are not a benchmark of this revision. End-to-end validation remains outstanding.

## Details

The reported production incident used a 6-CPU-limit pod on a 172-core host: the host-sized pool allowed CPU-heavy grammar compiles to compete with decode, with sustained CFS throttling and inter-token latency rising from 7–9 ms to 68–93 ms (RCA in #49460).

This is a bounded default, **not cgroup quota detection**. Eight workers can still exceed a smaller quota, and backend-internal compilation threads remain unchanged. Reducing concurrency may increase schema-burst compilation latency, especially on unconstrained hosts; operators can tune `VLLM_STRUCTURED_OUTPUT_MAX_COMPILE_WORKERS`.

This updates the existing worker-cap PR rather than opening a duplicate. The open timeout proposals #54090 and #55597 bound individual compile duration, which is complementary to bounding concurrent compiles.

Recap: the grammar-compile `ThreadPoolExecutor` is sized from `multiprocessing.cpu_count()`, which is not cgroup-aware.
