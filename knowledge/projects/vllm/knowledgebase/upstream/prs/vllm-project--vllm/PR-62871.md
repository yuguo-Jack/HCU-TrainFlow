# [Bugfix][Streaming Input] Skip final request after input failure

[Upstream PR](https://github.com/vllm-project/vllm/pull/62871) · state: open · merged: False

## Original PR description

Assisted-by: OpenAI Codex



## Overview

Do not send a normal completion request after streaming-input processing fails.
Under asynchronous scheduling, it can race with the failed session's abort under the same request ID.

This is distinct from [#49722](https://github.com/vllm-project/vllm/pull/49722), which handles a valid terminal request, and [#51900](https://github.com/vllm-project/vllm/pull/51900), which caps cumulative session length. No duplicate open PR was found on 2026-10-21.

## Claims

- Input errors still reach the caller, but no final request is submitted after failure.
- Normal completion and cancellation remain unchanged.

## Validation

On main `64c5f14` with this change:

```bash
.venv/bin/python -m pytest tests/v1/streaming_input/test_async_llm_streaming.py -q  # 8 passed
.venv/bin/pre-commit run --files vllm/v1/engine/async_llm.py tests/v1/streaming_input/test_async_llm_streaming.py  # passed
```

The test file is covered by [Buildkite](https://github.com/vllm-project/vllm/blob/64c5f14f6a89aff63bb9ea729a906a055caf00a7/.buildkite/test_areas/misc.yaml#L99-L118). In a local RTX A6000 replay using Llama-3.2-1B-Instruct, FlashAttention-2, asynchronous scheduling, and a 512-token context, the first stream chunk produced output; an oversized second chunk raised `VLLMValidationError`:

| Observation | Unfixed | Fixed |
| --- | ---: | ---: |
| Final requests submitted after the error | 1 | 0 |
| Tokens from a healthy same-engine follow-up | 4 | 4 |

To reproduce, yield a valid `StreamingInput`, wait for its first model output, then yield a chunk exceeding `max_model_len`; trace `_add_request` for the non-resumable `[0]`-token completion request. The replay was local, not CI, and does not claim output corruption or a current-main KVGuard detection. It used 64 KV blocks, `VLLM_USE_FLASHINFER_SAMPLER=0` to avoid a local FlashInfer mismatch, and precompiled CUDA extensions from a nightly wheel five commits behind the tested main revision.

## Details

`handle_inputs()` already records whether input processing errored, but its `finally` block sent the completion request whenever the task was not cancelled. The fix also checks that error flag before finalizing. It adds no state, dependency, or synchronization and does not change input validation, model execution, sampling, or the public API. No user-facing docs or example change is needed.
