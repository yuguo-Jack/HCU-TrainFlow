# [Core] Add gap-tolerant prefix cache reuse

[Upstream PR](https://github.com/vllm-project/vllm/pull/60814) · state: open · merged: False

## Original PR description

## Summary
Add gap-tolerant prefix cache reuse: when a middle block in a cached prefix 
is evicted, the matching blocks on both sides of the gap can still be reused,
rather than discarding all subsequent blocks.

## Motivation
Traditional prefix caching requires continuous match from the start — 
if any middle block is evicted, all subsequent blocks become unusable. 
This wastes significant KV cache, especially in long-context scenarios 
where partial evictions are common.

## Implementation
- Add `enable_gap_tolerant_reuse` config flag (env: VLLM_GAP_TOLERANT_PREFIX_REUSE)
- Detect secondary gap hits after the contiguous prefix match
- Pin gap-hit blocks until they are grafted or discarded
- Release pinning when requests abort or complete

## Testing
- Added unit test `test_gap_tolerant_prefix_reuse` covering:
  - Normal gap hit flow
  - Gap hit after middle block eviction
  - Request abort → gap hits discarded → ref counts released
