# [Frontend] systemone: reject unknown request fields

[Upstream PR](https://github.com/vllm-project/vllm/pull/62472) · state: open · merged: False

## Original PR description



## Overview

`/v1/systemone` rejects an unknown field inside a question but silently drops an unknown field on the request itself (`OpenAIBaseModel` allows extras). A client using a sibling dialect's field, for example Jev/SystemOne's `assets` map for images, gets answers scored without its images and no error. This applies the question-level rule to the request.

## Claims

- A `/v1/systemone` request with a field outside `StructuredDecisionRequest` returns 400 `unknown field(s) [...]` before admission, instead of being read without it.

## Validation

**Real model.** `Cloudflare/clef` (27B, FP8, loaded as `ClefFlashForJointSchema`) on one L40S, v0.32.1rc0 commit `2365177d` with this change applied:

| Request | Before | After |
| --- | --- | --- |
| 20 valid requests (text, JSON, images, 16K truncation) | 200 | 200 |
| Image request in Jev form: `assets` map, no `images` | 200, scored without the image | 400 `unknown field(s) ['assets']` |
| Valid request plus `"seed": 7` | 200 | 400 `unknown field(s) ['seed']` |

**Tests.** `test_systemone_rejects_unknown_request_fields` posts a request with `assets` through the router and asserts the 400 and that nothing was admitted. It fails without the change.

```bash
pytest tests/entrypoints/generate/structured_decisions/test_decisions.py \
  tests/entrypoints/generate/structured_decisions/test_question_types.py \
  tests/entrypoints/generate/structured_decisions/test_strategies.py
# 111 passed
```

## Details

- **Compatibility:** clients that send extra fields today start getting 400. The endpoint is new (#59299, #60677), and the original example in #59299 sent `"seed": 7`, which this would now reject, so callers copying it will need to drop it. That is the intended trade: an ignored field on this endpoint changes what the model reads (media, instructions) without any signal.
- `/v1/decisions` is unchanged; it follows the OpenAI schema and its own validation.
- Docs: the request-fields section states the rule.
