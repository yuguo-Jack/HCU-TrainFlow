# [Bugfix][MoE] Avoid double router weighting in TRTLLM BF16 experts

[Upstream PR](https://github.com/vllm-project/vllm/pull/63700) · state: open · merged: False

## Original PR description



## Overview

Fix double application of router weights in `TrtLlmBf16ExpertsModular` when prepare has already weighted the inputs, as required by Llama4.

## Claims

- Input-weight mode computes `f(r*x)`, instead of `r*f(r*x)`.
- Ordinary output-weight mode is unchanged. The existing BF16/LoRA controls are retained, and the BF16 suite is wired into the B200 CI step.

## Details

Prepare scales inputs in input-weight mode. FlashInfer's fused BF16 finalization still multiplies by its supplied routing weights, so this wrapper must pass unit weights in that mode. No backend selection or default changes are needed.

Duplicate checks covered open TRTLLM/BF16 and input-router-weight PRs. #62019 handles the separate LoRA path; #54109 adds an activation format. Neither fixes this non-LoRA BF16 finalization contract.
