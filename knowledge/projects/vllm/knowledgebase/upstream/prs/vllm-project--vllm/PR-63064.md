# [Docs][KV Connector] Document standalone Mooncake EGM deployment

[Upstream PR](https://github.com/vllm-project/vllm/pull/63064) · state: closed · merged: True

## Original PR description

## Overview

Document how to deploy an external Mooncake EGM Store with `MooncakeStoreConnector`, using the existing NVLink allocator and GPU KV transfer path. Related to #45036.

## Claims

- Add a standalone EGM Provider example and a deployment guide covering requester configuration, cross-instance prefix reuse, and shutdown.
- Keep the requester's existing positive `local_buffer_size`. The Provider owns the EGM capacity; its storage-only example uses zero local buffer.
- Limit the final diff to documentation and the Provider example. There are no changes to vLLM runtime code or tests.

## Validation

- Provider CLI help, invalid capacity, setup arguments, signal handling, and setup/close error handling checked locally. Lifecycle checks used a fake Store; they do not exercise EGM transfers.
- Requester JSON checked through the existing `MooncakeStoreConfig.from_file()`; KV configuration JSON and example syntax checked.
- Ruff check/format, Markdownlint, and `git diff --check` passed.

```bash
.venv/bin/python examples/disaggregated/mooncake_store/egm_provider.py --help
pre-commit run ruff-check --files examples/disaggregated/mooncake_store/egm_provider.py
pre-commit run ruff-format --files examples/disaggregated/mooncake_store/egm_provider.py
npx --yes markdownlint-cli2@0.21.0 --config tools/pre_commit/.markdownlint.yaml docs/features/mooncake_store_connector_usage.md
git diff --check
```

Full pre-commit environment setup could not complete locally. The targeted checks above passed; commit hooks were bypassed.

The [Mooncake GB200/NVL72 report published on August 18](https://github.com/kvcache-ai/Mooncake/pull/3335#issuecomment-5323495953) records 208 successful HBM ↔ remote EGM Put/Get pairs across four GPUs on two GB200 nodes, including correctness, cleanup, and Fabric-health checks.

That report used Mooncake's `batch_put_from` / `batch_get_into` APIs with zero local buffer. **The vLLM deployment described here, including multi-buffer transfers and cross-instance prefix reuse, has not been tested end to end on hardware.**

## Details

The connector already uses registered GPU buffers for its memory-replica multi-buffer transfers. Keeping the SDK's local staging allocation does not insert a CPU staging step into that path. The guide therefore uses the existing requester configuration without adding a zero-buffer exception or new allocator restrictions.

The example starts a separate Provider with Mooncake's EGM configuration API and closes it after the requesters exit.

The duplicate-work check covered #45036 and open EGM-related PRs; no equivalent deployment guide was found. AI assistance was used for the example, documentation, and local checks.
