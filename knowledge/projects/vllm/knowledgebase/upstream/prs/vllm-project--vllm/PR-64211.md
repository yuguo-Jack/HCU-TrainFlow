# [CI][Bugfix][ROCm] Seed each MLA backend correctness case; allow one bf16 ULP for ROCm glm

[Upstream PR](https://github.com/vllm-project/vllm/pull/64211) · state: open · merged: False

## Original PR description

- `test_mla_backends.py`: seed each case at the start of `_run_backend_correctness`, so its random inputs no longer depend on which tests ran before it
- `test_mla_backends.py`: on ROCm with a bf16 KV cache and `v_head_dim=256` (glm), allow one bf16 ULP of the largest reference value as `atol`

`test_chunked_context_backend_correctness[False-trtllm-gen-auto-glm-…ROCM_AITER_FA]` fails on both `TRITON_MLA` and `ROCM_AITER_MLA` in every 4-shard run of "(MI355 DPX) V1 Attention" (e.g. https://buildkite.com/vllm/ci/builds/97849), while it passed under the old `--shard-id` layout. No code change caused it: `_run_backend_correctness` draws all inputs from `torch.randn` without reseeding, so the inputs depend on the tests that ran earlier in the process, and the runtime shard plugin changed that order. Swept on an MI300X with the main wheel, the case passes for some seeds and fails for others, and the old and new code give identical results seed for seed. In all 17 seeds the largest diff from the SDPA reference is exactly one bf16 ULP of the largest reference value (0.03125, with max |ref| between 4.0 and 4.75). That is above the `1e-2` atol, so elements near zero fail (#55609, #55611). The new `atol` is that one ULP, computed from each reference rather than a fixed number, and only for the ROCm glm bf16 combination.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
