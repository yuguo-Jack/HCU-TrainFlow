# [Recipe] Add DeepSeek V4.1 Flash Ascend A3 W8A8 configuration

[Upstream PR](https://github.com/vllm-project/vllm/pull/62794) · state: open · merged: False

## Original PR description

## Overview

Add the documented Ascend A3 W8A8 deployment to the DeepSeek-V4.1-Flash recipe, so users can generate a DP4/TP4/EP16 command with the required NPU settings.

## Claims

- Add an A3-only W8A8 variant, ModelScope checkpoint, Ascend image, V1 runner, Engram CPU offload/shared memory, and FULL_DECODE_ONLY graph settings.
- Preserve the existing NVIDIA/AMD variants and generated commands. Keep DSpark opt-in with an Ascend-specific eager draft configuration.
- Link the complete Ascend tutorial for A2 and asymmetric A3 PD deployment. Gate generic builder templates that do not reproduce those launchers.

## Validation

- `CI=true node scripts/validate-source.mjs --source vllm --dir <vllm-checkout>/recipes` — passed: strict assembly and JSON Schema/API generation for 215 models. CI copy mode avoids Windows symlink permissions.
- `node check-dsv41.mjs` (local, untracked validation harness) — passed: 9,856 unchanged NVIDIA/AMD command/environment combinations; unchanged existing variants and Guide; A3 TP/TEP both produce DP4/TP4 with EP, correct parsers, Engram settings, V1 runner, 16 devices and the Ascend Docker image; DSpark override and template gates checked.
- `git diff --check` — passed.
- The human submitter confirms the A3 single-node W8A8 DP4/TP4 configuration was already validated and requests reusing the tutorial's evidence. No new NPU serving run, task-accuracy evaluation, or performance benchmark was executed for this documentation migration. The hardware badge applies to that W8A8 configuration, not the existing FP8 variants or every feature combination.

## Details

Source: [vLLM Ascend DeepSeek-V4.1-Flash tutorial](https://github.com/vllm-project/vllm-ascend/blob/ff62595360a069343ecdc3b2cd3a0daf45b4f1f0/docs/source/tutorials/models/DeepSeek-V4.1-Flash.md). The source image tag was checked in Quay, and the ModelScope checkpoint is publicly accessible with `quant_method: ascend` / `W8A8_DYNAMIC`.

This is a recipe-only change. It uses the existing schema and command synthesis; no model/runtime code changes. `vram_minimum_gb: 663` is the schema's approximate `ceil(552B * 1 byte * 1.2)` sizing hint, not measured HBM. The tutorial's checkpoint uses INT8 Engram storage; alternate conversions in the weight repository are not covered. Select the Python frontend to match the tutorial; the existing GPU frontend default is preserved. Generic DEP emits a DP16 router, while the Ascend tutorial requires DP4/TP4; generic PD does not supply its MooncakeHybridConnector launchers. Full PD instructions remain in the linked tutorial, which labels PD a reference design.

Duplicate check: open PR searches for `DeepSeek V4.1 Ascend recipe` and `recipe ascend`, plus the author's open PRs, found no existing DeepSeek-V4.1-Flash Ascend recipe contribution. The Kimi-K3 Ascend PR concerns a different model. This PR targets vLLM because recipes are now owned by `recipes/` here; the renderer repository defers its old copies to this source.

AI assistance was used to prepare and statically validate this contribution.
