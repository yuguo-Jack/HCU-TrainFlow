# [ROCm] Add HiSparse Support on ROCm

[Upstream PR](https://github.com/vllm-project/vllm/pull/57240) · state: closed · merged: False

## Original PR description

## Purpose

Enables HiSparse (#53781) on AMD ROCm/CDNA3+, tested on gfx950 (MI355X).

HiSparse keeps the bulk of the sparse-MLA KV cache in pinned host memory and
pulls only the indexer-selected rows back just in time, so long-context agentic
sessions stop getting preempted. #53781 landed it CUDA-only.

This PR enables for ROCm.

It also fixes **one bug in shared, platform-neutral code** that affects CUDA
equally — see *Platform-neutral fixes* below. That fix is the reason GLM-5.3
produces coherent output rather than garbage, and it is not ROCm-specific.

## Changes

### 1. HIP kernel port (`csrc/`)

The four fused HiSparse cache ops now build and run on ROCm. The port is
mechanical — vectorized copy widths, `__nv_bfloat16` → `hip_bfloat16`, and
warp-primitive shims added to `csrc/cuda_compat.h`. No algorithmic change; CUDA
codegen is unaffected.

### 2. ROCm backend wiring (`rocm_aiter_mla_sparse.py`)

The substantive work. Every CUDA HiSparse backend consumes a **dense**
`[tokens, topk]` index tensor plus `valid_counts`; AITER's tuned decode kernel
consumes a **ragged** flat list plus an indptr. Bridging that is the core of
this change:

- `ROCMAiterMLASparseImpl` accepts an `index_group_builder` and registers with
  it, which is what makes `mla_attention.py:575` pick up `hisparse_cache` and
  drive KV mirroring.
- Decode: `convert_decode_logical_to_physical_topk` → dense physical top-k →
  compacted to ragged → attention runs against `physical_kv_cache` (the hot
  buffer) instead of the paged KV cache.
- Prefill: mirrors the CUDA guard, staging host rows via `stage_prefill_rows`
  when the context is not fully resident. This is not optional — once a context
  has been offloaded, `all_context_pages_resident` is False and
  `index_group.py:232` asserts outright.
- AITER's persistent work-stealing metadata is disabled under HiSparse: its
  buffers are sized in `build()`, but HiSparse rewrites the indptr at forward
  time from resolver counts. Correctness first; noted as a perf follow-up.

One new Triton kernel, `compact_topk_to_ragged_triton`. The existing
`fetch_id_to_ragged_triton` was not reusable: a mid-row `-1` must *drop out*
rather than displace a valid entry.

**ROCm does not import the CUDA sparse module.** Following the precedent at
`xpu_mla_sparse.py:85-106`, this backend declares
`ROCMAiterMLASparsePrefillMetadata` locally.

### 3. Config gate (`vllm/config/vllm.py`)

Opens HiSparse for ROCm, with `fp8_ds_mla` (the 656-byte packed row) rejected
by name rather than failing deep in a kernel. Packed-layout support on ROCm is
a separate project. Every other platform keeps the existing rejection.

## Platform-neutral fixes

These are in shared code and (I think) would affect CUDA too. 

**`vllm/v1/hisparse/binding.py` — per-layer KV offset dropped.** Both bind
sites used `byte_offset=tensor_config.offset`, omitting the
`l * layer_stride` term the addressing contract requires
(`kv_cache_interface.py:1370`). `HiSparseHotSpec` and `HiSparseResidentSpec`
both return `has_layer_views = False`, so `allocate_kv_cache` hands every layer
in a group the whole raw slab and the per-layer term must be applied at bind
time. Without it **every layer in a hot group aliases the same KV region**. 
This is invisible to the existing e2e suite, which shrinks the model to 8
layers — that yields one-layer hot groups, where `l` is always 0 and the missing
term is exactly zero. Added `tests/v1/hisparse/test_layer_byte_offset.py` to 
remedy this. 

**`vllm/v1/attention/backends/mla/index_group.py` — event record does not
survive nested `torch.compile`.** `self.logical_topk_ready.record(...)` is
traceable, so Dynamo lowers it to a `torch.ops.streams.record_event` node whose
event lives in a process-global side table. `reset_user_object_tracking()`
clears that table on compile entry. vLLM nests compiles
(`CustomOp.maybe_compile` wraps `forward_native`), so an inner compile firing
during an outer graph's execution wipes the entry that graph's node depends on.
Replaced with an opaque custom op keyed by an integer group handle, so the
event never becomes a graph input.  Believe CUDA has not hit this only because 
its call path reaches `set_logical_topk_ready` from outside the compiled region.

**`vllm/distributed/.../hisparse/worker.py` — mirror guard for unbracketed
runs.** Warmup and profiling runs execute the model with the connector
disabled, so `start_step`/`finish_forward` never bracket them and
`_per_layer_mirrored` is never cleared between passes. The second warmup pass
then trips `RuntimeError: HiSparse layer 0 mirrored twice.` Added a
`_step_in_flight` flag so mirroring is skipped outside a real step. The
double-mirror check is unchanged inside a step.

## Model Evaluation

GLM-5.3, TP4, full 78-layer model, greedy (`temperature=0`), Model Runner V2 in
both arms. MRV2 must be forced in the baseline too — HiSparse enables it
implicitly, and comparing against an MRV1 baseline reintroduces a confound.

| Prompt | HiSparse ON vs OFF |
|---|---|
| "The capital of France is" | identical ~27 tokens, then divergent filler; both correct |
| "Write one sentence explaining why the sky is blue." | identical throughout |
| "List the first five prime numbers:" | both `2, 3, 5, 7, 11` |

Divergence in trailing filler is expected: the hot-buffer decode path reorders
reductions. Bit-exactness is enforced at the kernel level by the oracle suite
above.

Before the `binding.py` fix, the same configuration produced a correct first
token followed by garbage:
`' Paris of  str of of\n\n1 - when B -11" E picture ...'`

Throughput benchmarking against a pure-CPU-offload baseline (mirroring the
GLM-5.3 hybrid-offloading blog post) is in progress and will be posted as a
follow-up comment.

## Limitations

- **`fp8_ds_mla` is not supported on ROCm** and is rejected with a clear error.
  bf16 and standard fp8 rows work — the HiSparse runtime is dtype-generic
  (`row_width` is a constructor parameter).
- **AITER's persistent work-stealing decode path is disabled under HiSparse.**
  Correctness first; a perf follow-up.
- **MTP under HiSparse on ROCm is untested.**
- **Cross-rank IPC events are unproven.** `Event(interprocess=True)` +
  `ipc_handle()` verified single-process on gfx950; TP>1 exercised end-to-end
  at TP4 without issue, but not isolated as its own test.
- Verified on gfx950 only. Other CDNA targets are untested.
