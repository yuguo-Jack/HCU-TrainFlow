# [Bugfix][Sampling] Fix thinking-budget row layout on draftless spec steps

[Upstream PR](https://github.com/vllm-project/vllm/pull/62970) · state: open · merged: False

## Original PR description



## Overview

Fix cross-request corruption in the MRV1 thinking-budget logits layout on
speculative-decoding steps that have no draft tokens. Fixes #59272.

## Claims

- On a speculative-decoding step with **no drafts**, the MRV1
  `ThinkingBudgetStateHolder` no longer collapses every budgeted request's
  forced end-of-thinking token into logits row 0.
- Each budgeted request's forced `reasoning_end` token is now written to its
  own row, so thinking-budget enforcement is correct per request.
- Behavior on all other paths (drafts present, bonus-token pass, non-spec
  mode) is byte-for-byte unchanged.
- Adds a CPU-only regression test that fails without the fix and passes with it.

## Validation

The bug and the fix are reproduced with a pure-CPU snippet (no GPU, no model
weights) that drives the holder through a spec-decoding step with an empty
`spec_token_ids` list:

```
num_spec_tokens=0: [[100, 7, 7, 200, 7, 7], [100, 7, 7, 200, 7, 7]]
```

**Before (unchanged main):**

```
num_spec_tokens=0: [[100, 7, 7, 200, 7, 7], [100, 7, 7, 200, 7, 7]]   # correct
num_spec_tokens=3: [[100, 7, 7, 200, 200, 200], [100, 7, 7, 7, 7, 7]]  # BUG
```

Request 0 (row 0) accumulates request 1's forced end token, and request 1's
budget is silently not enforced.

**After (this change):**

```
num_spec_tokens=0: [[100, 7, 7, 200, 7, 7], [100, 7, 7, 200, 7, 7]]
num_spec_tokens=3: [[100, 7, 7, 200, 7, 7], [100, 7, 7, 200, 7, 7]]   # matches
```

### Test

New regression test
`tests/v1/sample/test_thinking_budget_state.py::test_spec_mode_step_without_drafts_forces_each_request_row`:

- **Without the fix:** `FAILED` — `cu_num_tokens == {0: 0, 1: 0}` and
  `logits[1, 200] == 0.0` (request 1 never forced).
- **With the fix:** `PASSED` — `cu_num_tokens == {0: 0, 1: 1}` and both
  `logits[0, 200]` and `logits[1, 200]` are boosted.

## Details

### Root cause

`ThinkingBudgetStateHolder._apply_forcing_to_logits` (MRV1,
`vllm/v1/sample/thinking_budget_state.py`) computes `cu_num_tokens`, the
starting logits row for each request, by walking `spec_token_ids_for_layout`
and advancing the cumulative offset by `len(spec_tokens)` whenever
`in_spec_mode` is true and `predict_bonus_token` is false.

`in_spec_mode` is fixed at construction (`num_spec_tokens > 0`) and does not
depend on the step. On a step where **no drafts were proposed** (the plain
`Sampler` runs, `spec_decode_metadata is None`), every request's
`spec_token_ids` is empty, so `len(spec_tokens)` is 0 for all of them and every
`cu_num_tokens[i]` stays 0. The forced `reasoning_end` tokens for *all*
budgeted requests are then written into row 0: request 0 gets other requests'
end tokens injected, and requests 1..n-1 have their thinking budget silently
not enforced.

### Fix

Only use the draft-token row layout when the step actually has drafts. A no-draft
step (and the bonus-token pass) has one logits row per request:

```python
use_spec_layout = (
    self.in_spec_mode
    and not predict_bonus_token
    and any(spec_token_ids_for_layout)
)
...
cumulative_total += len(spec_tokens) if use_spec_layout else 1
```

This is the minimal change: it is byte-for-byte identical to the previous
behavior in every case except the buggy one (`in_spec_mode` true, not
bonus-token, and no drafts), where it now correctly assigns one row per
request.

### Model Runner V1 vs V2

This is the MRV1 sampling path (`vllm/v1/sample/sampler.py` →
`apply_to_logits`). MRV2 uses a separate `ThinkingBudgetState`
(`vllm/v1/worker/gpu/sample/thinking_budget.py`) that maps forced tokens
through an explicit `idx_mapping` / `expanded_idx_mapping` rather than a
`cu_num_tokens` dict, and is not affected by this bug. This change is scoped to
the legacy MRV1 runner still used by deployments that have not moved to MRV2.

### Non-duplication

`gh pr list --repo vllm-project/vllm --state all --search "59272"` shows a
single prior PR: **[#59291](https://github.com/vllm-project/vllm/pull/59291)**,
*"[Test][MRV2] Cover draftless thinking-budget row mapping"*, which is
**closed without merging** (`mergedAt: null`). That PR deliberately contained
**no implementation change** — it only added an MRV2 GPU test and closed on the
basis that MRV2 already has a correct mapping. No open or merged PR modifies
`_apply_forcing_to_logits` in the MRV1 path, so this is not a duplicate: it
provides the actual MRV1 fix plus a CPU regression test.

### Risks

- Change is confined to the MRV1 no-draft, non-bonus-token branch; every other
  layout case is unchanged, so the regression surface is limited to the exact
  scenario being fixed.
- No GPU/`torch.cuda` synchronization is introduced; the layout is still
  computed on CPU as before.
- The fix cannot alter output for non-speculative deployments (they never enter
  the `use_spec_layout` branch).
