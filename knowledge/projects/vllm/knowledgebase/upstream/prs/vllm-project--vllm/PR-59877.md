# [Bugfix][NIXL] Serialize NIXL agent calls across connector threads

[Upstream PR](https://github.com/vllm-project/vllm/pull/59877) · state: open · merged: False

## Original PR description



## Overview

The NIXL connector worker calls one NIXL agent from the handshake thread and the engine thread, and creates it without `sync_mode`, so NIXL's agent lock is a no-op and the two threads race on the agent's remote-agent state. This creates the agent with `NIXL_THREAD_SYNC_STRICT`.

Fixes #59870

## Claims

- The connector's NIXL agent is created with `NIXL_THREAD_SYNC_STRICT` when the installed NIXL exposes `nixl_thread_sync_t` (NIXL >= 1.1.0; `main` pins 1.4.1). Builds without it keep today's config.
- In a standalone reproducer of the connector's two-thread call pattern on NIXL 1.4.1, 8 of 8 runs without a sync mode segfault, hang or hit NIXL errors, and 8 of 8 runs with `STRICT` are clean.
- No measurable cost on an uncontended READ loop.

```python
"""Reproduce vLLM's two-thread use of one NIXL agent, with and without a sync mode.

The agent under test ("decode") is configured like vLLM's NIXL connector worker
(num_threads=4, progress thread on, capture_telemetry=True). Two Python threads
call it the way vLLM does:

- handshake thread: add_remote_agent (loadRemoteMD) + remote prep_xfer_dlist
  for a pool of peer agents, then hands the peer to the engine thread.
- engine thread: READs from a stable "prefill" agent (make_prepped_xfer,
  transfer, check_xfer_state, release), get_new_notifs, send_notif, and
  evicts handed-over peers (release_dlist_handle, remove_remote_agent), like
  TTL eviction in _ensure_handshake.

Usage: python nixl_sync_race.py {none|strict} SECONDS
Exit 0 = ran to completion with every READ verified. A crash shows up as a
signal exit code from the parent harness.
"""

import os
import queue
import sys
import threading
import time

import numpy as np
from nixl_cu12._api import nixl_agent, nixl_agent_config, nixl_thread_sync_t

MODE = sys.argv[1]
SECONDS = float(sys.argv[2])
N_PEERS = int(os.environ.get("N_PEERS", "32"))
BLOCKS = int(os.environ.get("BLOCKS", "256"))
BLOCK_BYTES = 4096


def config(sync, num_threads=4):
    kwargs = {"num_threads": num_threads, "capture_telemetry": True}
    if sync is not None:
        kwargs["sync_mode"] = sync
    return nixl_agent_config(**kwargs)


sync = None if MODE == "none" else nixl_thread_sync_t.NIXL_THREAD_SYNC_STRICT

decode = nixl_agent("decode", config(sync))
# More than two num_threads=4 agents in one process crash NIXL 1.4.1 at
# create_backend (unrelated to this repro), so the remote side uses 0.
prefill = nixl_agent("prefill", config(None, 0))
peers = [nixl_agent(f"peer-{i}", config(None, 0)) for i in range(N_PEERS)]


def make_buf(fill):
    buf = np.full(BLOCKS * BLOCK_BYTES, fill, dtype=np.uint8)
    return buf


def block_descs(buf):
    base = buf.ctypes.data
    return [(base + i * BLOCK_BYTES, BLOCK_BYTES, 0) for i in range(BLOCKS)]


local_buf = make_buf(0)
prefill_buf = make_buf(7)
peer_bufs = [make_buf(1) for _ in peers]

decode.register_memory([(local_buf.ctypes.data, local_buf.nbytes, 0, "")], "DRAM")
prefill.register_memory(
    [(prefill_buf.ctypes.data, prefill_buf.nbytes, 0, "")], "DRAM"
)
for p, b in zip(peers, peer_bufs):
    p.register_memory([(b.ctypes.data, b.nbytes, 0, "")], "DRAM")

prefill_md = prefill.get_agent_metadata()
peer_mds = [p.get_agent_metadata() for p in peers]

# Stable remote, loaded once like an engine with live traffic.
prefill_name = decode.add_remote_agent(prefill_md)
local_side = decode.prep_xfer_dlist("", block_descs(local_buf), "DRAM")
remote_side = decode.prep_xfer_dlist(prefill_name, block_descs(prefill_buf), "DRAM")

stop = threading.Event()
loaded: queue.Queue = queue.Queue(maxsize=4)
counts = {"loads": 0, "evictions": 0, "reads": 0, "notifs": 0}
errors: list[str] = []


def handshake_thread():
    i = 0
    while not stop.is_set():
        idx = i % N_PEERS
        i += 1
        try:
            name = decode.add_remote_agent(peer_mds[idx])
            handle = decode.prep_xfer_dlist(
                name, block_descs(peer_bufs[idx]), "DRAM"
            )
        except Exception as e:  # noqa: BLE001
            errors.append(f"handshake: {e!r}")
            continue
        counts["loads"] += 1
        while not stop.is_set():
            try:
                loaded.put((name, handle), timeout=0.01)
                break
            except queue.Full:
                pass


def engine_thread():
    rng = np.random.default_rng(0)
    while not stop.is_set():
        idx = rng.choice(BLOCKS, size=16, replace=False)
        try:
            h = decode.make_prepped_xfer(
                "READ", local_side, idx, remote_side, idx, b"r"
            )
            state = decode.transfer(h)
            while state not in ("DONE", "ERR"):
                state = decode.check_xfer_state(h)
            decode.release_xfer_handle(h)
            if state == "ERR":
                errors.append("read: ERR")
            decode.get_new_notifs()
            decode.send_notif(prefill_name, b"HB:x")
            counts["notifs"] += 1
        except Exception as e:  # noqa: BLE001
            errors.append(f"engine: {e!r}")
            continue
        counts["reads"] += 1
        try:
            name, handle = loaded.get_nowait()
        except queue.Empty:
            continue
        try:
            decode.release_dlist_handle(handle)
            decode.remove_remote_agent(name)
        except Exception as e:  # noqa: BLE001
            errors.append(f"evict: {e!r}")
        counts["evictions"] += 1


threads = [threading.Thread(target=handshake_thread), threading.Thread(target=engine_thread)]
for t in threads:
    t.start()
time.sleep(SECONDS)
stop.set()
for t in threads:
    t.join()

print(
    f"mode={MODE} reads={counts['reads']} loads={counts['loads']} "
    f"evictions={counts['evictions']} errors={len(errors)} first_errors={errors[:3]}",
    flush=True,
)
os._exit(0 if not errors else 3)
```

## Details

Root cause: the handshake executor (`vllm-nixl-handshake-initiator`) runs `add_remote_agent` (`loadRemoteMD`) and remote `prep_xfer_dlist`. The engine thread runs `make_prepped_xfer`, `transfer`, `check_xfer_state`, `release_xfer_handle`, `get_new_notifs`, `send_notif`, and `remove_remote_agent` during TTL eviction. The executor is limited to one worker because NIXL is not guaranteed to be thread-safe (`base_worker.py:855`). That orders handshakes among themselves and leaves them unordered against the engine thread. NIXL's Python `nixl_agent` picks `NIXL_THREAD_SYNC_STRICT` only when the listener thread is enabled and `NIXL_THREAD_SYNC_NONE` otherwise (`_api.py:218-222` in 1.4.1), and under `NONE` the agent lock does nothing (`src/core/sync.h:36-38`). The bindings release the GIL for `loadRemoteMD`, `prepXferDlist`, `makeXferReq`, `postXferReq`, `getXferStatus`, `getNotifs` and `genNotif`, so nothing serializes these calls today.

Why `STRICT`: it is the mode NIXL selects itself whenever it runs its own communication thread (`effectiveSyncMode`, `src/core/nixl_agent.cpp:166-170`), so it is the configuration NIXL already runs in practice. With the NIXL progress thread on (the default), UCX workers already run in multi-thread mode, so this adds only the agent-level lock.

Tradeoff: the engine thread now waits while the handshake thread holds the lock. The longest call under it is a remote `prep_xfer_dlist`, about 15-20 ms for 500k descriptors in the reproducer, once per remote rank per handshake. The uncontended loop shows no measurable difference.

Compatibility: `nixl_thread_sync_t` and the `sync_mode` argument both arrive in the NIXL Python API in v1.1.0. `nixl_utils` resolves `nixl_thread_sync_t` with `getattr(..., None)`, so older NIXL and RIXL builds that lack it keep today's config.

Related: #45211 (reader thread) and #57987 (opt-in background pull receiver) add more threads that call the agent. #59524 rolls back failed handshakes from the handshake thread, which calls `remove_remote_agent` concurrently with the engine thread. All three depend on the agent being thread-safe. #49238 reports `loadRemoteMD` segfaults after a prefill restart; whether this race plays a part there is not established.

Not a duplicate: no open or closed PR or issue matched `sync_mode nixl`, `nixl sync_mode`, `NIXL_THREAD_SYNC`, `nixl thread`, `nixl thread safe` or `nixl thread-safe agent` for this mechanism, and no open PR diff that touches the NIXL connector sets `sync_mode` on the agent.
