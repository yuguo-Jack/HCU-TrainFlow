# [Bugfix][Core] Redo prompt logprobs for requests resumed after reset_prefix_cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/61547) · state: open · merged: False

## Original PR description



## Overview

Fixes #61490. After `reset_prefix_cache(reset_running_requests=True)`, a request whose in-flight prefill output carried the completed prompt logprobs is resumed without re-registering the requirement on the V1 runner, so the client gets null prompt logprobs. The scheduler now marks such requests when the output is dropped as stale and passes the ids to the runner, which re-registers the requirement for the re-run prefill.

## Claims

- Fixes the null prompt logprobs from #61490 on the V1 model runner path.
- No behavior change on the default V2 runner, which already re-registers resumed requests on its new-request path, and none for requests without prompt logprobs.

## Validation

New tests in `tests/v1/core/test_scheduler.py`:

- `test_reset_prefix_cache_redoes_dropped_prompt_logprobs`: reset lands mid-prefill, the stale output carrying prompt logprobs is dropped, and the resumed schedule carries the redo directive exactly once (V1 runner).
- `test_stale_output_without_prompt_logprobs_sets_no_redo_flag`: a dropped stale chunk without prompt logprobs sets no marker.
- `test_redo_marker_cleared_on_v2_resume`: the V2 path clears the marker and sends no directive.

```
python -m pytest tests/v1/core/test_scheduler.py tests/v1/core/test_async_scheduler.py -q
# 230 passed
```

`ruff check` and `ruff format --check` are clean on all touched files.

No GPU end-to-end run here (no CUDA build on this machine); the bug and fix live in scheduler/runner bookkeeping, which the tests above drive directly through the public scheduler API. CI covers the serving path.

## Details

Root cause: the reset preempts running requests with `drop_stale_output=True`. When the in-flight output then returns, it is discarded as stale, but that output carried the completed prompt logprobs and the runner had already retired its `num_prompt_logprobs` entry at prefill completion. The resumed request goes through the V1 cached-request path, which never re-registers the requirement, so the recomputed prefill emits no prompt logprobs.

The runner cannot infer the redo on its own: when a `num_prompt_logprobs` entry is gone it cannot distinguish "popped because delivered" from "popped because the output was dropped", and re-registering on every preemption would double-deliver for ordinary decode-time preemption. So the scheduler marks the request exactly where the stale drop happens, sends the affected ids once via `CachedRequestData.redo_prompt_logprobs_req_ids`, and the runner re-registers using the same expression as its new-request path. The marker is cleared when the directive is sent, on the V2 resumed-to-new conversion, and on any fresh schedule, so it cannot leak into a later step.

Duplicate check: no open PR references #61490, and keyword searches over open PRs (`prompt logprobs reset prefix`, `reset_prefix_cache logprobs`) turn up nothing addressing this. The issue had no linked PR and no one claimed it.

MRV1 note: this fix targets the V1 runner's cached-request path, where the bug lives. MRV2 is not affected, since it converts resumed requests into new requests and re-registers prompt logprobs there; the marker is explicitly cleared on that path.

```python
"""Independent HTTP timing sweep for vLLM issue #61490.

Exit 1: response correctness failure. Exit 2: unusable baseline/reset.
This script resets active requests; use a dedicated reproduction server.
"""

import argparse
import asyncio
import hashlib
import json
import random
import time
from pathlib import Path

import httpx

WORDS = "river stone lamp window garden quiet north copper winter paper signal forest harbor".split()


def parse_delays(value):
    if ":" in value:
        return list(range(*map(int, value.split(":"))))
    return list(map(int, value.split(",")))


async def request_completion(client, model, prompt, streamed):
    body = dict(model=model, prompt=prompt, max_tokens=16, temperature=0)
    result = {"kind": "stream_echo" if streamed else "prompt_logprobs"}
    if not streamed:
        body["prompt_logprobs"] = 1
        response = await client.post("/v1/completions", json=body)
        payload = response.json()
        result.update(http_status=response.status_code, response=payload)
        if "error" in payload:
            result["failure"] = str(payload["error"])
        elif response.status_code != 200:
            result["failure"] = f"HTTP {response.status_code}"
        else:
            scores = payload["choices"][0].get("prompt_logprobs")
            count = len(scores or [])
            expected = payload["usage"]["prompt_tokens"]
            result.update(prompt_tokens=expected, prompt_logprob_entries=count)
            if count != expected:
                result["failure"] = f"{count} prompt logprob entries for {expected} prompt tokens"
        return result
    body.update(stream=True, echo=True, logprobs=5, stream_options={"include_usage": True})
    events = []
    done = False
    token_count = 0
    async with client.stream("POST", "/v1/completions", json=body) as response:
        result["http_status"] = response.status_code
        if response.status_code != 200:
            result["failure"] = f"HTTP {response.status_code}: {(await response.aread()).decode()}"
            return result
        async for line in response.aiter_lines():
            if not line.startswith("data:"):
                continue
            data = line[5:].strip()
            if data == "[DONE]":
                done = True
                continue
            payload = json.loads(data)
            events.append(payload)
            if "error" in payload:
                result["failure"] = str(payload["error"])
            for choice in payload.get("choices", []):
                scores = choice.get("logprobs")
                if scores:
                    lengths = [len(scores.get(key) or []) for key in
                               ("tokens", "token_logprobs", "top_logprobs", "text_offset")]
                    if len(set(lengths)) != 1:
                        result["failure"] = f"unaligned logprobs arrays: {lengths}"
                    token_count += lengths[0]
            if payload.get("usage"):
                result["usage"] = payload["usage"]
    result.update(done=done, returned_logprob_tokens=token_count, events=events)
    if not done:
        result.setdefault("failure", "stream ended without [DONE]")
    if result.get("usage") and token_count != result["usage"]["total_tokens"]:
        result.setdefault("failure", f"echo returned {token_count} token scores for {result['usage']['total_tokens']} tokens")
    return result


async def main(args):
    rng = random.Random(args.seed)
    results = []
    output_path = Path(args.output)
    with output_path.open("w") as output:
        def record(item):
            output.write(json.dumps(item, ensure_ascii=False) + "\n")
            output.flush()

        async with httpx.AsyncClient(base_url=args.base_url, timeout=120, trust_env=False) as client:
            models = await client.get("/v1/models")
            models.raise_for_status()
            model = models.json()["data"][0]["id"]
            record({"config": vars(args), "model": model})

            def prompt(index):
                return f"nonce {index} {rng.randrange(10**9)} " + " ".join(rng.choice(WORDS) for _ in range(100))

            for streamed in (True, False):
                warmup = await request_completion(client, model, prompt(-1), streamed)
                record(dict(warmup, warmup=True))
                if "failure" in warmup:
                    print("INVALID_BASELINE", warmup["failure"], flush=True)
                    return 2
            for repeat in range(args.repeats):
                for delay in parse_delays(args.delays):
                    for streamed in (True, False):
                        text = prompt(len(results))
                        start = time.perf_counter()
                        task = asyncio.create_task(request_completion(client, model, text, streamed))
                        reset = None
                        if args.reset_mode != "none":
                            await asyncio.sleep(delay / 1000)
                            actual_offset = (time.perf_counter() - start) * 1000
                            response = await client.post("/reset_prefix_cache", params={
                                "reset_running_requests": str(args.reset_mode == "running").lower()
                            })
                            reset = {"http_status": response.status_code,
                                     "body": response.text, "offset_ms": actual_offset}
                        result = await task
                        result.update(label=args.label, repeat=repeat, delay_ms=delay,
                                      reset=reset, prompt=text,
                                      prompt_sha256=hashlib.sha256(text.encode()).hexdigest())
                        record(result)
                        results.append(result)
                        detail = result.get("failure", "OK")
                        print(f"{args.label} reset={delay:2d}ms {result['kind']:16s} {detail}", flush=True)
                        if reset is not None and reset["http_status"] != 200:
                            print("INVALID_RESET", reset, flush=True)
                            return 2
                        await asyncio.sleep(args.pause)
        summary = {"label": args.label, "requests": len(results),
                   "failures": sum("failure" in item for item in results)}
        for kind in ("stream_echo", "prompt_logprobs"):
            subset = [item for item in results if item["kind"] == kind]
            summary[kind] = {"requests": len(subset), "failures": sum("failure" in item for item in subset)}
        record({"summary": summary})
        print("SUMMARY", json.dumps(summary), flush=True)
        return int(summary["failures"] > 0)


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--base-url", default="http://127.0.0.1:8000")
    parser.add_argument("--label", default="v1_async")
    parser.add_argument("--reset-mode", choices=["running", "idle", "none"], default="running")
    parser.add_argument("--delays", default="0:80:2")
    parser.add_argument("--repeats", type=int, default=1)
    parser.add_argument("--pause", type=float, default=0.2)
    parser.add_argument("--seed", type=int, default=61490)
    parser.add_argument("--output", default="results.jsonl")
    raise SystemExit(asyncio.run(main(parser.parse_args())))

```

- he-yufeng · comment · 2026-10-16T10:02:28Z · [source](https://github.com/vllm-project/vllm/pull/61547#issuecomment-6213047912)

Thanks again for the careful GPU matrix, it pinned the exact failure shape. I found the root cause behind both crashes and pushed a follow-up commit to this branch.

Root cause: on the redo path the resumed prefill still honors prefix-cache hits. The prompt-logprobs CPU tensor is freshly allocated with torch.empty (one row per prompt position) and only rows the resumed prefill actually covers get written. A request preempted by the reset re-hits its own just-freed blocks on the very next schedule, so the hit rows stayed uninitialized: garbage int32 ids then crashed the decode in `_update_prompt_logprobs` (your OverflowError, and the server exit), and positions that were never recomputed produced maps without their target token, which the completion-side formatter indexed without a guard (your KeyError: 220). V1 sync and V2 async were clean because the former has no drop-stale-output race and the latter re-registers on its own new-request path.

Two changes on top of the previous head:

- The scheduler now discards a prefix hit for a request that is redoing dropped prompt logprobs, so the resumed prefill recomputes the whole prompt and every tensor row is written. This mirrors the existing prefix-replay zeroing a few lines above. New regression test forces a partial hit on the resume lookup and asserts the full prompt gets scheduled; without the change it schedules only the suffix.
- The completion logprobs formatter now treats a missing sampled-token entry the same way the chat path already does (placeholder instead of KeyError), with a unit test.

Verified locally on CPU: the new scheduler and serving tests pass (red without the fix, green with it), the surrounding scheduler and completion suites are green, and my earlier source-level probes for both crash classes confirm the fixed behavior. I do not have a GPU here, so the V1 async + active-reset matrix is not rerun on my side. If you are willing to rerun your sweep against the new head, that would be the strongest check; the failure shape you measured (KeyError at 4-6 ms resets, OverflowError on the prompt-logprobs request) should both be gone, and successful requests should still match the no-reset reference exactly.
