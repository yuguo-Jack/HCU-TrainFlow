# [Bugfix][Core] Redo prompt logprobs for requests resumed after reset_prefix_cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/61547) · state: open · merged: False

## Original PR description

## Overview

Fixes #61490. Active `reset_prefix_cache(reset_running_requests=True)` exposed two opposite redo-state errors: resuming before a dropped output arrived could leave prompt-logprob rows unwritten, while resetting after a complete output was emitted could recompute and append a duplicate block.

This PR arms redo at drop-mode preemption only when complete prompt logprobs have not already been emitted. The recompute marker persists until prompt logprobs are produced, and a separate output-emitted marker prevents an unnecessary second prefill from appending `N - 1` rows after the original `N` rows.

## Claims

- A resume no longer has to wait for dropped output to arrive before redo is armed. Prefix hits cannot silently turn into unwritten prompt-logprobs rows on that first resume.
- Once complete prompt logprobs are attached to an `EngineCoreOutput`, a later reset does not request another copy. The output processor therefore does not receive the duplicate `N - 1` scored rows observed in the latest independent GPU rerun.
- Completed redo output may retire the runner-side requirement. A subsequent drop-mode preemption resets `redo_prompt_logprobs_sent` only if the completed output was not emitted, so an actually dropped result is still recomputed and re-registered.
- Requests without prompt logprobs do not arm the redo path. The sentinel-based coverage diagnostic runs after the D2H sync, and the completion formatter remains a defensive fallback rather than a substitute for recomputation.

## Validation

- The new test first accepts a non-empty prompt-logprobs result and sampled token, then resets running requests and verifies that neither the persistent redo marker nor the runner directive is re-armed.

## Details

The original missing-output path allocated a full tensor with `torch.empty` but wrote only rows after `num_computed_tokens`. Arming redo only when stale output was discarded missed the same-step reset-and-resume window. This branch keeps the full-prompt recompute active until a result is actually produced and sends a one-shot runner directive where required.

The latest failure had the opposite shape. After complete prompt logprobs had already been emitted, `_preempt_request` still set `prompt_logprobs_dropped`. The resumed prefill then returned another `N - 1` scored rows, which `LogprobsProcessor` appended to the original block containing `N` rows including its initial `None` entry.

`Request.prompt_logprobs_emitted` is set only when complete prompt-logprobs tensors are attached to an emitted `EngineCoreOutput`, not when a stale result is dropped. Drop-mode preemption skips redo for that completed case, while fresh and streaming-continuation scheduling resets the marker. V1 therefore does not re-register a retired requirement, and V2 retains its existing resume rule that skips prompt scoring when `prefill_len` already includes generated tokens.

#60960 covers the related general cache-boundary problem for prompt scoring and does not carry this dropped-output lifecycle state. If it lands first, this PR should be merged onto it while retaining both mechanisms.

"""Independent HTTP timing sweep for vLLM issue #61490.

Exit 1: response correctness failure. Exit 2: unusable baseline/reset.
This script resets active requests; use a dedicated reproduction server.
"""

import argparse
import asyncio
import hashlib
import json
import random
import time
from pathlib import Path

import httpx

WORDS = "river stone lamp window garden quiet north copper winter paper signal forest harbor".split()


def parse_delays(value):
    if ":" in value:
        return list(range(*map(int, value.split(":"))))
    return list(map(int, value.split(",")))


async def request_completion(client, model, prompt, streamed):
    body = dict(model=model, prompt=prompt, max_tokens=16, temperature=0)
    result = {"kind": "stream_echo" if streamed else "prompt_logprobs"}
    if not streamed:
        body["prompt_logprobs"] = 1
        response = await client.post("/v1/completions", json=body)
        payload = response.json()
        result.update(http_status=response.status_code, response=payload)
        if "error" in payload:
            result["failure"] = str(payload["error"])
        elif response.status_code != 200:
            result["failure"] = f"HTTP {response.status_code}"
        else:
            scores = payload["choices"][0].get("prompt_logprobs")
            count = len(scores or [])
            expected = payload["usage"]["prompt_tokens"]
            result.update(prompt_tokens=expected, prompt_logprob_entries=count)
            if count != expected:
                result["failure"] = f"{count} prompt logprob entries for {expected} prompt tokens"
        return result
    body.update(stream=True, echo=True, logprobs=5, stream_options={"include_usage": True})
    events = []
    done = False
    token_count = 0
    async with client.stream("POST", "/v1/completions", json=body) as response:
        result["http_status"] = response.status_code
        if response.status_code != 200:
            result["failure"] = f"HTTP {response.status_code}: {(await response.aread()).decode()}"
            return result
        async for line in response.aiter_lines():
            if not line.startswith("data:"):
                continue
            data = line[5:].strip()
            if data == "[DONE]":
                done = True
                continue
            payload = json.loads(data)
            events.append(payload)
            if "error" in payload:
                result["failure"] = str(payload["error"])
            for choice in payload.get("choices", []):
                scores = choice.get("logprobs")
                if scores:
                    lengths = [len(scores.get(key) or []) for key in
                               ("tokens", "token_logprobs", "top_logprobs", "text_offset")]
                    if len(set(lengths)) != 1:
                        result["failure"] = f"unaligned logprobs arrays: {lengths}"
                    token_count += lengths[0]
            if payload.get("usage"):
                result["usage"] = payload["usage"]
    result.update(done=done, returned_logprob_tokens=token_count, events=events)
    if not done:
        result.setdefault("failure", "stream ended without [DONE]")
    if result.get("usage") and token_count != result["usage"]["total_tokens"]:
        result.setdefault("failure", f"echo returned {token_count} token scores for {result['usage']['total_tokens']} tokens")
    return result


async def main(args):
    rng = random.Random(args.seed)
    results = []
    output_path = Path(args.output)
    with output_path.open("w") as output:
        def record(item):
            output.write(json.dumps(item, ensure_ascii=False) + "\n")
            output.flush()

        async with httpx.AsyncClient(base_url=args.base_url, timeout=120, trust_env=False) as client:
            models = await client.get("/v1/models")
            models.raise_for_status()
            model = models.json()["data"][0]["id"]
            record({"config": vars(args), "model": model})

            def prompt(index):
                return f"nonce {index} {rng.randrange(10**9)} " + " ".join(rng.choice(WORDS) for _ in range(100))

            for streamed in (True, False):
                warmup = await request_completion(client, model, prompt(-1), streamed)
                record(dict(warmup, warmup=True))
                if "failure" in warmup:
                    print("INVALID_BASELINE", warmup["failure"], flush=True)
                    return 2
            for repeat in range(args.repeats):
                for delay in parse_delays(args.delays):
                    for streamed in (True, False):
                        text = prompt(len(results))
                        start = time.perf_counter()
                        task = asyncio.create_task(request_completion(client, model, text, streamed))
                        reset = None
                        if args.reset_mode != "none":
                            await asyncio.sleep(delay / 1000)
                            actual_offset = (time.perf_counter() - start) * 1000
                            response = await client.post("/reset_prefix_cache", params={
                                "reset_running_requests": str(args.reset_mode == "running").lower()
                            })
                            reset = {"http_status": response.status_code,
                                     "body": response.text, "offset_ms": actual_offset}
                        result = await task
                        result.update(label=args.label, repeat=repeat, delay_ms=delay,
                                      reset=reset, prompt=text,
                                      prompt_sha256=hashlib.sha256(text.encode()).hexdigest())
                        record(result)
                        results.append(result)
                        detail = result.get("failure", "OK")
                        print(f"{args.label} reset={delay:2d}ms {result['kind']:16s} {detail}", flush=True)
                        if reset is not None and reset["http_status"] != 200:
                            print("INVALID_RESET", reset, flush=True)
                            return 2
                        await asyncio.sleep(args.pause)
        summary = {"label": args.label, "requests": len(results),
                   "failures": sum("failure" in item for item in results)}
        for kind in ("stream_echo", "prompt_logprobs"):
            subset = [item for item in results if item["kind"] == kind]
            summary[kind] = {"requests": len(subset), "failures": sum("failure" in item for item in subset)}
        record({"summary": summary})
        print("SUMMARY", json.dumps(summary), flush=True)
        return int(summary["failures"] > 0)


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--base-url", default="http://127.0.0.1:8000")

    parser.add_argument("--seed", type=int, default=61490)
    parser.add_argument("--output", default="results.jsonl")
    raise SystemExit(asyncio.run(main(parser.parse_args())))

Thanks again for the careful GPU matrix, it pinned the exact failure shape. I found the root cause behind both crashes and pushed a follow-up commit to this branch.

Root cause: on the redo path the resumed prefill still honors prefix-cache hits. The prompt-logprobs CPU tensor is freshly allocated with torch.empty (one row per prompt position) and only rows the resumed prefill actually covers get written. A request preempted by the reset re-hits its own just-freed blocks on the very next schedule, so the hit rows stayed uninitialized: garbage int32 ids then crashed the decode in `_update_prompt_logprobs` (your OverflowError, and the server exit), and positions that were never recomputed produced maps without their target token, which the completion-side formatter indexed without a guard (your KeyError: 220). V1 sync and V2 async were clean because the former has no drop-stale-output race and the latter re-registers on its own new-request path.

Two changes on top of the previous head:

- The scheduler now discards a prefix hit for a request that is redoing dropped prompt logprobs, so the resumed prefill recomputes the whole prompt and every tensor row is written. This mirrors the existing prefix-replay zeroing a few lines above. New regression test forces a partial hit on the resume lookup and asserts the full prompt gets scheduled; without the change it schedules only the suffix.
- The completion logprobs formatter now treats a missing sampled-token entry the same way the chat path already does (placeholder instead of KeyError), with a unit test.

Verified locally on CPU: the new scheduler and serving tests pass (red without the fix, green with it), the surrounding scheduler and completion suites are green, and my earlier source-level probes for both crash classes confirm the fixed behavior. I do not have a GPU here, so the V1 async + active-reset matrix is not rerun on my side. If you are willing to rerun your sweep against the new head, that would be the strongest check; the failure shape you measured (KeyError at 4-6 ms resets, OverflowError on the prompt-logprobs request) should both be gone, and successful requests should still match the no-reset reference exactly.

Answers to your three questions, and a commit that fixes the root cause rather than papering over the decode.

**1. Root cause: it is a write-coverage gap, not a read-before-write race.**

`_get_prompt_logprobs_dict` allocates the prompt-logprobs CPU tensor for the whole prompt with `torch.empty` (one row per prompt position) but only writes the rows `[num_computed_tokens, num_computed_tokens + num_logits)` for the tokens this prefill actually computes. So any scheduling path that lets `num_computed_tokens > 0` at the start of a request's prompt-logprobs prefill leaves rows `[0, num_computed_tokens)` uninitialized. Those garbage int32 ids then reach `convert_ids_list_to_tokens` and blow up in `tokenizer.decode`.

The only thing that forced `num_computed_tokens = 0` for such a request was the redo marker `prompt_logprobs_dropped`, and that marker was one-shot: it was set when a completed prompt-logprobs output was dropped as stale, and cleared the first time the request was rebuilt for the runner. A redo prefill that is itself preempted before it produces any prompt logprobs is dropped with an empty `prompt_logprobs_dict`, so the marker is not re-armed. On the next resume the request honors its own just-freed prefix blocks and advances `num_computed_tokens` past rows the fresh tensor never received.

So to your framing: "redo not reached" and "rows read before writes" are both ruled out. The redo does run and the writes do land where scheduled; the hole is that after a second preemption the scheduler stops telling the redo to recompute from position 0. I have a scheduler-level reproducer for exactly this (`test_redo_recompute_survives_a_second_preemption`) that fails before the fix and passes after.

**2. Correctness: a suppressed decode error is not a valid row, and the fix makes every row real.**

You are right that the decode guard I pushed earlier only hides the crash. An unwritten row can hold any bits, including a plausible token id. The correct invariant is that no row may be unwritten: the redo must recompute the whole prompt so that every position gets its own gathered logprob. The fix keeps the "recompute from 0" forcing active until the request's prompt logprobs are actually produced (instead of clearing it after the first resume), so it survives any number of preemptions of the redo. With that, every scored position is recomputed and there is nothing left to suppress. I treat the decode guard as a last-resort defense-in-depth, not the fix.

**3. Rerun criteria.**

Yes, compare every scored prompt position against a matched no-reset reference, including row coverage (every prompt position present), token id equality, and logprob value equality. Exact equality is the expectation for the token ids and ranks; for the logprob floats I would expect bit-equality on the same hardware and dtype since the same gather runs, but I would not insist on it across different builds. The only acceptable missing entries are positions the API never scores (the usual off-by-one at the prompt boundary).

To make a run conclusive without relying on "no OverflowError," the branch now seeds the prompt-logprobs tensor's selected-token column with a sentinel and, when a request's prompt logprobs complete, logs a warning with the request id and the uncovered positions for any row that was never written. That check subsumes the decode-fallback signal: an unwritten row is exactly what would feed a garbage id to the decode guard, so if the row check is clean the fallback cannot have been masking anything. A run that completes cleanly now still tells us whether any row was unwritten.

The fix is on the scheduler path that both model runners share, so the whole-prompt recompute now survives repeated preemptions on V1 and V2 alike (I also stopped the V2 resume from clearing the marker). The sentinel/coverage check lives in the prompt-logprobs gather.

With that in place, a fresh-server non-streamed-only sweep against the new head (`e9a81dc501`) is the check that matters: no "never written" warning and every scored position matching the no-reset reference. A streamed request in the same batch is no longer required to trigger the invalid-row condition, but keeping one streamed control in the sweep is still worth it for the echo-alignment path I fixed earlier.

def validate_response(payload, expected_ids, vocab_size):
    problems = []
    if "error" in payload or not payload.get("choices"):
        return [f"API error: {payload.get('error', payload)}"]
    choice = payload["choices"][0]
    if payload.get("usage", {}).get("prompt_tokens") != len(expected_ids):
        problems.append("usage.prompt_tokens does not match independent tokenization")
    if choice.get("prompt_token_ids") != expected_ids:
        problems.append("returned prompt_token_ids do not match independent tokenization")
    rows = choice.get("prompt_logprobs")
    if not isinstance(rows, list) or len(rows) != len(expected_ids):
        return problems + [f"prompt row count {len(rows or [])}, expected {len(expected_ids)}"]
    if rows[0] is not None:
        problems.append("first prompt position should be unscored")
    for pos, (row, gold_id) in enumerate(zip(rows[1:], expected_ids[1:]), 1):
        if not isinstance(row, dict) or str(gold_id) not in row:
            problems.append(f"position {pos} missing selected token {gold_id}")
            continue
        for token_id, value in row.items():
            if not 0 <= int(token_id) < vocab_size:
                problems.append(f"position {pos} invalid token id {token_id}")
            lp = value.get("logprob")
            rank = value.get("rank")
            if not isinstance(lp, (int, float)) or not math.isfinite(lp):
                problems.append(f"position {pos} invalid logprob {lp}")
            if not isinstance(rank, int) or not 1 <= rank <= vocab_size:
                problems.append(f"position {pos} invalid rank {rank}")
    return problems


def compare_responses(reference, actual):
    ref = reference["choices"][0]
    got = actual["choices"][0]
    left = ref.get("prompt_logprobs") or []
    right = got.get("prompt_logprobs") or []
    ids_equal = len(left) == len(right)
    ranks_equal = ids_equal
    decoded_equal = ids_equal
    floats_equal = ids_equal
    max_abs_diff = 0.0
    different_positions = []
    for pos, (a, b) in enumerate(zip(left, right)):
        if a is None or b is None:
            if a != b:
                ids_equal = ranks_equal = floats_equal = decoded_equal = False
                different_positions.append(pos)
            continue
        if set(a) != set(b):
            ids_equal = False
            different_positions.append(pos)
        for token_id in set(a) & set(b):
            x, y = a[token_id], b[token_id]
            ranks_equal &= x.get("rank") == y.get("rank")
            decoded_equal &= x.get("decoded_token") == y.get("decoded_token")
            lp1, lp2 = x["logprob"], y["logprob"]
            if lp1 != lp2:
                floats_equal = False
                different_positions.append(pos)
                diff = abs(lp1 - lp2)
                max_abs_diff = max(max_abs_diff, diff if math.isfinite(diff) else math.inf)
    text_equal = ref.get("text") == got.get("text")
    output_ids_equal = ref.get("token_ids") == got.get("token_ids")
    exact_match = all((ids_equal, ranks_equal, decoded_equal, floats_equal, text_equal, output_ids_equal))
    return dict(exact_match=exact_match, token_id_keys_equal=ids_equal,
                ranks_equal=ranks_equal, decoded_tokens_equal=decoded_equal,
                logprobs_equal=floats_equal, max_abs_logprob_diff=max_abs_diff,
                text_equal=text_equal, output_token_ids_equal=output_ids_equal,
                different_positions=sorted(set(different_positions)))
