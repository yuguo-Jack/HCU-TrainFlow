# [Bugfix][MoRIIO] Route decode requests by their own DP rank

[Upstream PR](https://github.com/vllm-project/vllm/pull/65563) · state: open · merged: False

## Original PR description



## Overview

Fix MoRIIO's single-host reference proxy sending the prefill DP rank as the decode dispatch rank. With DP2 prefill and DP1 decode, requests assigned to prefill rank 1 fail with `data_parallel_rank 1 is out of range [0, 1)`.

## Claims

- Dispatch each leg using the rank selected from that leg's own DP topology, in READ and WRITE mode.
- Preserve the prefill source in decode's `kv_transfer_params.remote_dp_rank`; KV ownership is independent of decode dispatch.
- Keep equal-DP, equal-instance-count dispatch unchanged.

## Validation

Changed-file pre-commit passes, including ruff, mypy, markdownlint and SPDX checks:

```bash
pre-commit run --files \
  examples/disaggregated/disaggregated_serving/moriio_toy_proxy_server.py \
  tests/v1/kv_connector/unit/test_moriio_toy_proxy_server.py \
  docs/features/moriio_connector_usage.md
```

The new regression test sends requests through the real Quart `/v1/completions` route to temporary HTTP backends. It checks the outbound dispatch header, unchanged prefill KV source, and forwarded response for READ/WRITE at DP2->DP1, DP2->DP4 and DP2->DP2.

The human submitter ran the same new test file against the base proxy and then the fixed proxy in `lliao_vllm_pd` (Python 3.12.15, pytest 9.2.0, GPUs hidden):

```bash
uv run --no-project .venv/bin/python -m pytest -v -rs \
  tests/v1/kv_connector/unit/test_moriio_toy_proxy_server.py
```

```text
base:  4 failed, 3 passed, 14 warnings in 4.75s
fixed: 7 passed, 14 warnings in 4.80s

base DP2->DP1 READ/WRITE: assert '0' == None
base DP2->DP4 READ/WRITE: assert '0' == '2'
```

The four unequal-DP cases fail on the base for incorrect dispatch headers; the health route and two equal-DP cases pass on both. The warnings concern existing PyTorch and pytest-asyncio deprecations. These tests exercise HTTP routing with backend stand-ins, not GPU inference.

Prior hardware validation used the same runtime routing fix with GPT-OSS-120B on MI350X: prefill TP2 x DP2 on four GPUs, decode TP1 on one GPU, MoRIIO WRITE/XGMI, 8,167-token prompts and 1,024 requested output tokens. A concurrency 1-128 sweep served 1,020 requests without errors. This was on ROCm nightly `edad8b03c5`, with the port-offset fix from #64574 and a completion-wait workaround also applied; it is not a fresh evaluation of current main.

The dedicated ROCm MoRIIO unit CI step is currently disabled in `.buildkite/test_areas/misc.yaml`. No current-main GPU inference run is claimed.

## Details

For a request assigned to prefill rank 1 with DP1 decode:

1. The proxy dispatches prefill with header rank 1.
2. The decode request retains `remote_dp_rank=1` to identify its prefill KV source.
3. Decode has no DP pin header, so its only engine accepts the request.
4. In WRITE mode, decode targets the prefill rank's notification port and separately advertises its actual decode rank in `remote_blocks`. In READ mode, the source rank selects the prefill session.

Previously, step 3 copied the prefill rank into the decode HTTP header and failed local rank validation. The fix uses the decode route's existing selected rank and updates the misleading comments and usage guide.

Not a duplicate: searched open PRs for MoRIIO proxy/decode routing and `selected_decode_dp_rank`. #64574 fixes TP x DP port offsets. #52949 changes multi-pod notification ownership; this reference proxy is single-host and this PR leaves connector notification gates unchanged.

AI assistance (Codex) was used to investigate, implement and review this change. Three independent informed, blind and ownership reviews found no introduced defects.
