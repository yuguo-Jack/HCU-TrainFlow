# [ROCm] Map device 0x744b to AMD_Radeon_PRO_W7900D

[Upstream PR](https://github.com/vllm-project/vllm/pull/65392) · state: closed · merged: False

## Original PR description

Adds one line to `_ROCM_DEVICE_ID_NAME_MAP` in `vllm/platforms/rocm.py`:

```diff
     "0x744c": "AMD_Radeon_RX7900XTX",
+    "0x744b": "AMD_Radeon_PRO_W7900D",  # Navi 31, gfx1100
```

Without it, `get_device_name()` falls back to `asic_info["market_name"]`, which on this card is
the generic string `"AMD Radeon Graphics"`. `get_device_name_as_file_name()` builds the FP8
block-quantized GEMM config filename from that, so every RDNA3 workstation card that isn't in
the map resolves to the same filename. Makes it impossible to ship a tuned config for one
without it also applying to the others.

pci.ids has `0x744b` as `Navi 31 [Radeon Pro W7900D]`. I went with `AMD_Radeon_PRO_W7900D` to
match `AMD_Radeon_RX7900XTX` / `AMD_Radeon_RX9070XT`, but `AMD_Radeon_W7900D` is fine too if
you prefer, just say and I'll change it.

I checked the config directory before opening this, since renaming changes which file gets
looked up: 244 config JSONs plus a README, and zero `AMD_Radeon_*` files (the AMD entries are
MI300X / MI325X / MI325_OAM, rest is Intel B70 and NVIDIA). Worth knowing that `0x744c`
`AMD_Radeon_RX7900XTX` is already in this map and still has no config files at all, so a name
entry doesn't imply a shipped config. Nothing in-tree gets invalidated. The only thing to
mention in release notes is that someone who hand-dropped a config under
`AMD_Radeon_Graphics` would need to rename it.

Tested by applying the diff and re-importing in a fresh process:

```python
>>> from vllm.platforms import current_platform
>>> from vllm.utils.platform_utils import get_device_name_as_file_name
>>> current_platform.get_device_name(0)
'AMD_Radeon_PRO_W7900D'      # was 'AMD Radeon Graphics'
>>> get_device_name_as_file_name()
'AMD_Radeon_PRO_W7900D'      # was 'AMD_Radeon_Graphics'
```

I didn't run `pytest tests/platforms/` — no pytest in my ROCm venv. It's a dict constant, no
branch logic changes, and `tests/platforms/` only contains `test_cpu.py`, which doesn't touch
this map.
