# [Perf][Spec Decode][GLM-5.3] Specialized GLM-5.3 MTP drafter, with a post-forward CUDA graph

[Upstream PR](https://github.com/vllm-project/vllm/pull/63387) · state: open · merged: False

## Original PR description

## Overview

This PR is stacked on #63386 (GLM-5.3 latency-specialized decode). Until that PR lands, this branch also contains its commit; only the last commit is under review.

With `--additional-config '{"decode_backend": "latency_specialized"}'`, the GLM-5.3 MTP draft layer (layer 78) moves off vLLM's stock DeepSeek-V3.2 MTP path onto CuTe DSL kernels (draft worker, draft selectors, MoE, BF16 draft head, MTP preprocess). The draft layer reads vLLM's loaded MTP-layer weights in place.

The PR also changes Model Runner V2 for low-batch speculative decode. These paths are taken only when a model state sets `ModelState.low_latency_decode` (default `False`). Only `Glm53ModelState` sets it, so every other model runs Model Runner V2 unchanged.

**Revision 2** (this push). Compared with revision 1:
- the drafter serves MTP K = 1 to 7 and batches of up to four requests (revision 1: one request at K = 3);
- the Model Runner V2 paths are enabled by the model state's `low_latency_decode` attribute; the `VLLM_POST_FORWARD_CUDA_GRAPH` environment variable is removed;
- it passes the repository's pre-commit hooks and mypy;
- it is rebased on current main and on revision 2 of #63386.

## Claims

- MTP 3 at an 8K prompt with synthetic acceptance length 2.99: lower TPOT than stock at 1, 2 and 4 requests (about -52%, -33% and -18%). MTP 1 at one request: about -49%. These numbers include the target-layer change from #63386; table below.
- GSM8K is within noise of stock: 0.923 vs 0.902 at MTP 3, 0.911 vs 0.913 at MTP off.
- Long-context and reasoning evals at MTP 3 match stock within their standard errors where both arms have finished (RULER, MRCR); GPQA and AIME stock arms are still running.
- In the runs below, no claimed decode step fell back to the stock forward after startup, and no kernel compiled at request time.
- Without the opt-in, Model Runner V2 behavior is unchanged.

## Details

**Design.**
- Drafter: the catch-up holds four rows per request (one padded window at K = 1 and 2, two windows at K = 4 to 7). Request tiers of up to four requests at K = 2 and 3, and up to two at K = 1 and 4 to 7, run the drafter beside the target's row tiers. Any other step runs vLLM's drafter.
- At K = 1, where vLLM compacts no top-k indices, the model state's postprocess hook gives the drafter its sampled rows.
- The target segment caches the attention metadata of steps whose graphs it and the drafter fully claim.

**Model Runner V2 changes** (only with `ModelState.low_latency_decode` and an MTP/EAGLE drafter on CUDA):
- one post-forward CUDA graph per uniform decode size: sampling, state update and draft-prefill inputs after each step (`vllm/v1/worker/gpu/post_forward_cudagraph.py`);
- fused draft-prefill stores;
- draft decodes that the model state claims (`ModelState.claims_draft_decode_capture`) store their drafts inside the graph;
- kernel copies inside captures.

These are attributes and branches on the existing speculator and graph classes. A state that opts in must keep `postprocess_state` safe to capture in a CUDA graph. Pipeline parallelism, context parallelism and other unsupported configurations fall back to the baseline path with a warning.

**Requirements and limits.** Those of #63386, plus: MTP needs `"use_local_argmax_reduction": true`. The drafter's request tiers add capture sizes 1 and 2 at MTP 3. Draft activations stay BF16 where the stock drafter quantizes them to FP8, so individual draft tokens can differ from the stock drafter's.

**Overlap.** #61869 (DeepSeek-V4.1) adds its own `vllm/v1/worker/gpu/post_forward_cudagraph.py`; whichever lands first, the other will build on it. The Kimi K3 (`vllm/models/kimi_k3`) and DeepSeek-V4.1 (`vllm/models/deepseek_v41`) specialized paths serve other architectures and do not specialize the MTP drafter.

**CI.** `pytest -v -s models/glm53` runs in #63386's B200 step (`glm53-unit-tests-b200`); the Model Runner V2 tests in `tests/v1/worker` run in the existing worker steps. The served TP8 path needs a full 8-GPU node and is validated outside CI.

**AI assistance.** AI coding assistants (Claude) were used to write this change and run its validation; the submitter reviewed every changed line. Commits carry a `Co-authored-by` trailer.
