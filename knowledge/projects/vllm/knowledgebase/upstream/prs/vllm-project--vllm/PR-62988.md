## Original PR description

### Benchmark: Qwen3-32B + EAGLE3, AV on `main` vs. with the verify-cost fix

**Setup**
- **Hardware:** GB200, one GPU per server (TP1). All three servers ran at the same time on separate GPUs of one node, so the arms share wall-clock conditions.
- **Target:** `Qwen/Qwen3-32B` (bf16). **Drafter:** `RedHatAI/Qwen3-32B-speculator.eagle3`.
- **vLLM:** Model Runner V2 (`VLLM_USE_V2_MODEL_RUNNER=1`).
  - Baseline: `main` @ `642c18d64c`.
  - Fix: `fix-av-cost-model` @ `83d31d56eb` plus working-tree changes.
- **Server flags (all arms):**
  ```bash
  vllm serve Qwen/Qwen3-32B -tp 1 --max-num-seqs 256 --max-model-len 8192 \
    --no-enable-prefix-caching \
    --compilation-config '{"max_cudagraph_capture_size": 2048}' \
    --speculative-config '<see arms>'
  ```
- **Arms:**

  | Arm | Code | `--speculative-config` |
  |---|---|---|
  | fixed K=3 | `main` | `{"method": "eagle3", "model": "<drafter>", "num_speculative_tokens": 3, "enable_adaptive_verification": false}` |
  | AV, K=7 | `main` | `{"method": "eagle3", "model": "<drafter>", "num_speculative_tokens": 7, "enable_adaptive_verification": true}` |
  | AV, K=7 + fix | fix branch | same as above |

- **Workload:** SPEED-Bench `throughput_2k`, all categories, chat endpoint. Qwen3's default chat template, so thinking mode is on.
  ```bash
  vllm bench serve --model Qwen/Qwen3-32B --dataset-name speed_bench \
    --speed-bench-dataset-subset throughput_2k --speed-bench-output-len 2048 \
    --backend openai-chat --endpoint /v1/chat/completions \
    --request-rate inf --max-concurrency $C --num-prompts $N \
    --num-warmups $(( C < 16 ? C : 16 )) \
    --temperature 1.0 --top-p 0.95 --top-k 20 --seed 0
  ```
  - Concurrency and prompt count (C / N): 1 / 24, 8 / 64, 32 / 128, 64 / 256, 128 / 384, 256 / 768.
  - Each server first ran a discarded warm pass (C=64, 128 prompts, seed 1).
  - One run per arm. Run-to-run noise on this setup is about 2–4%: fixed K=3 spread that much across three separate runs.

**Fitted cost terms (from the fix arm's startup profile)**
- Context reads: **0.274 ms per request**, **0.0001 ms per token**. Relative RMS error of the linear fit: 0.8%.
- 113 of the profiled sizes run several tokens per request (R = 256, T = 272–2,048). Their context cost stays flat at about 70 ms, so on dense attention a draft adds no context-read cost.

**Results: output throughput (tok/s)**
| Concurrency | fixed K=3 | AV, K=7 (`main`) | AV, K=7 + fix | fix vs. `main` | fix vs. fixed K=3 |
|---|---|---|---|---|---|

| 256 | 3,836.7 | 3,811.8 | 3,916.5 | +2.7% | +2.1% |
