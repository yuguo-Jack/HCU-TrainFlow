# [Spec Decode][DCP] DSpark: run sliding-window MLA drafts under DCP

[Upstream PR](https://github.com/vllm-project/vllm/pull/63796) · state: open · merged: False

## Original PR description

## Overview

Runs the sliding-window MLA DSpark draft layers from #63795 under DCP (disaggregated context parallelism). The draft caches are replicated on every DCP rank (DCP=1 for the draft group), and the NIXL connector pulls the replicated draft cache from one DCP prefill rank while the target KV is still read in DCP slices.

**Depends on #63795** — only the second commit is new here; review the delta against that branch.

Not a duplicate: closest open work is #61464 (DBO with spec + DCP), which touches a different disaggregation feature and does not cover draft-cache replication or the NIXL draft layout.

## Claims

- Sliding-window MLA draft caches are replicated on every DCP rank (DCP=1 for the draft group); MLA metadata builders read their DCP size from the cache spec.
- NIXL: pull the replicated draft cache from one DCP prefill rank while the target KV is still read in DCP slices.
- Other draft/DCP layouts are rejected at handshake.

## Validation

- `python -m pytest tests/v1/core/test_kv_cache_planning.py tests/v1/kv_connector/unit/test_nixl_connector_hma.py tests/v1/worker/test_dspark_utils.py -v` — extended by this change and wired into CI on CUDA.
- The DCP draft layout was exercised end-to-end during bring-up of the spec-decode stack this change originates from.

## Details

- Replicating the draft cache (rather than slicing it over DCP ranks) keeps the draft group at DCP=1, so the speculator logic is unchanged from the non-DCP path; only the metadata builders and connector need to know the layout.
- Unsupported draft/DCP layouts fail at handshake instead of mid-serve, so misconfiguration surfaces immediately.
