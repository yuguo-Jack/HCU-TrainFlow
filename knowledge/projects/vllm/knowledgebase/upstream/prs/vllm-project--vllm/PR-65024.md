# [Security] Restrict EC NIXL reads to configured producer peers

[Upstream PR](https://github.com/vllm-project/vllm/pull/65024) · state: open · merged: False

## Original PR description

## Overview

Require CPU EC NIXL consumers to authorize producer endpoints before allocating cache entries or opening connections. `ec_allowed_peers` is a server-side exact `host:port` allowlist and defaults to denying remote reads.

## Claims

- A request cannot introduce a producer outside the operator's configured allowlist, even with the correct image hash and embedding shape.
- Unapproved sources retain existing failure behavior: local encoding when media is available, request failure for metadata-only inputs.
- Approved producer transfers and local CPU offload remain supported. Existing NIXL deployments must configure their producer addresses.

## Validation

- Changed-file pre-commit checks: passed, including Ruff, mypy, Markdown, and Buildkite test tethering.
- `git diff --check`: passed.
- Local scheduler pytest execution was blocked on macOS by the Linux `/dev/shm` dependency; the normal test cleanup also crashed in PyTorch's `empty_host_cache`. No passing runtime results are claimed.
- At the maintainer's request, Linux/GPU validation will run in CI. The two-GPU EC job installs the KV connector dependencies and runs:

```bash
pytest -v -s \
  v1/ec_connector/unit/test_scheduler_nixl_consumer.py \
  v1/ec_connector/integration/test_nixl_failure.py
```

The new HTTP regression uses the producer's actual image hash without a client UUID. Metadata-only input must fail and pixel input must fall back locally, with neither contacting the unapproved control peer. A later request uses a different salt without transfer parameters. Existing integration cases verify failures from an approved peer and successful subsequent native NIXL transfers.

GPU regression results, before/after failure evidence, and model-output evaluation are pending CI. This PR should not merge until that validation and human line-by-line review are complete.

## Details

Request-selected EC coordinates previously flowed from API input to `_start_xfer`, which allocated an entry under the image hash and connected to that producer. The guard now runs before both side effects. Every frontend using this CPU EC consumer reaches the same scheduler guard: Python chat/completions/Responses/Anthropic, scale-out generate, Rust frontend, SageMaker/batch forwarding, and direct engine clients. Streaming and non-streaming share this path. Other connectors are unchanged.

The allowlist establishes operator authorization of the endpoint, not transport authentication or verification of embedding contents. Allowed producers, their DNS, and the inter-node network remain trusted. Producer compromise is outside this control.

Duplicate-work check: reviewed the diffs of #58853, #56814, #54324, #55290, #59875, #57333, #61764, #50353, #64721, and #65018. They address ack shape/error containment, extra-argument typing, serialization, resource cleanup, metrics, port allocation, request copying, or forwarded/rendered features. None restricts producer selection before CPU EC reads. Current main retains the unrestricted sink.
