# [CI] Run Anthropic contract tests on CPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/64694) · state: open · merged: False

## Original PR description



## Overview

Run the existing Anthropic protocol, error-mapping and conversion tests in a small CPU job. Frontend changes can get a CPU contract result alongside the existing H200 integration job.

## Claims

- Adds `cpu-anthropic-contracts` using the existing CPU image and queue.
- Selects the real CPU platform and covers frontend, renderer and shared SDK dependency changes.
- Keeps current H200 integration coverage; no tests, skips or retries are added.

## Validation

```bash
VLLM_TARGET_DEVICE=cpu .venv/bin/python -m pytest \
  tests/entrypoints/anthropic/test_protocol_exports.py \
  tests/entrypoints/anthropic/test_error_type_mapping.py \
  tests/entrypoints/anthropic/test_anthropic_messages_conversion.py -q
```

148 passed with normal vLLM imports, the real `CpuPlatform`, and root `conftest.py` on macOS CPU (Python3.12, Torch2.14.0). No test edits or fixture overrides.

The production CI loader/matcher and command converter select the expected frontend/test/common-requirement paths and generate `small_cpu_queue_premerge`, the `-cpu` image, and only `image-build-cpu` as the image dependency. This offline check substitutes AWS cache-tag discovery; the default selector's live decision still needs its Buildkite artifact.

Applicable named Buildkite-step-key, test-tethering and typo hooks passed. The full pre-commit environment setup hit an unrelated uv-tool download TLS error; full-hook success is not claimed.

Docker is installed locally but its daemon socket is absent. The exact Linux CPU CI image has not been run, so its qualification remains pending. No GPU serving or model-output change; model eval is not applicable.

## Details

These tests currently run as part of the H200 API Server Generate job even though their checks exercise protocol models, FastAPI responses and converter logic. Reuse them directly rather than adding another test suite. Keep GPU collection unchanged until the CPU CI image is qualified.

`VLLM_TARGET_DEVICE=cpu` makes platform selection explicit. This also avoids an unspecified local platform entering accelerator cleanup when no GPU is involved.

Live searches for Anthropic CPU lanes and `cpu-small` found no matching CI change. #58823 changes tool-result image handling, not CI scheduling. Prepared with Codex assistance.

The submitting human confirmed line-by-line review and relevant test execution before submission.
