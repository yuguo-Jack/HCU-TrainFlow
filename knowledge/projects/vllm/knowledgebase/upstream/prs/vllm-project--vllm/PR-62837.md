# [Bugfix][Multimodal] Import cv2 lazily in multimodal.video

[Upstream PR](https://github.com/vllm-project/vllm/pull/62837) · state: closed · merged: False

## Original PR description

## Overview

`vllm --version` and other text-only startups import OpenCV, which on macOS triggers duplicate Objective-C class warnings from two different FFmpeg builds in one process. Import `cv2` in the two functions of `vllm/multimodal/video.py` that use it. Fixes the vLLM-side half of vllm-project/vllm-metal#1153.

## Claims

- Text-only startup no longer loads `cv2`, so the duplicate-FFmpeg Objective-C class registration no longer happens for users who never pass video input.
- Removes ~110ms (warm) to ~210ms (cold) of `cv2` import time from every CLI invocation.
- Closes a blind spot in `tests/standalone_tests/lazy_imports.py`, which names `cv2` as a module that must not be imported early but could not actually detect it.
- No behavior change when video input is used: `cv2` is imported on first use.

## Validation

Apple M4, macOS 26.5, Python 3.12, vLLM built from this branch.


**Video decoding still works.** `resize_video` and `Glm5NextVideoBackend.read_frames` both exercised against a generated 6-frame MP4:

`ruff check` and `ruff format --check` clean on both changed files with the pinned v0.14.0.

Not run: the full `tests/multimodal/` suite (needs network assets and GPU CI), and I could not reproduce the original Objective-C warning first-hand because this machine has no Homebrew FFmpeg installed — the warning text and dylib versions come from the reporter.

## Details

**Root cause.** The import chain is:

```
vllm/multimodal/hasher.py:17      from .media import MediaWithBytes
vllm/multimodal/media/__init__.py:5   from .connector import MEDIA_CONNECTOR_REGISTRY, MediaConnector
vllm/multimodal/media/connector.py:32 from vllm.multimodal.video import get_video_loader_backend_for_processor
vllm/multimodal/video.py:24       import cv2
```

`vllm/entrypoints/cli/main.py` imports all nine CLI subcommand modules before parsing argv, and every one of them reaches `vllm.multimodal.media` — via `renderers.chat_utils`, `multimodal.inputs`, or `multimodal.utils` — so `vllm --version` pays the cost.

cv2 bundles its own FFmpeg (`cv2/.dylibs/libavdevice.61.3.100.dylib`), while torchcodec links the system FFmpeg (it ships `libtorchcodec_core{4,5,6}.dylib`, one per FFmpeg major). With both loaded, macOS reports `AVFFrameReceiver` and `AVFAudioReceiver` as implemented twice.

**Why only `cv2`.** The linked issue also suggests deferring the `torchcodec` import in `vllm/multimodal/media/audio.py`. That would not help: `torchcodec` is already in `sys.modules` by the time that line runs, pulled in by transformers via `vllm/engine/arg_utils.py` -> `vllm/config/model.py` -> `vllm/transformers_utils/config.py` -> `transformers.models.auto.image_processing_auto`. Deferring only `cv2` is sufficient, because the clash needs two FFmpeg copies and torchcodec alone uses the system one.

**Approach.** Function-local `import cv2`, matching #26869 and #33189 rather than introducing `LazyLoader`. `vllm/multimodal/video_decoders/opencv.py` keeps its module-scope import because that module is already loaded on demand through `video_decoders.__init__`'s `import_module`.

**Trade-off.** Dropping the module-scope import also drops the `PlaceholderModule("cv2")` fallback, which only applied when cv2 was absent. `opencv-python-headless` is currently required (`requirements/common.txt`), so that path is effectively unreachable today. If #40764 lands and makes it optional, a dedicated error message would be worth adding — happy to add one here instead if you'd prefer.

**Test.** The existing guard poisons `sys.modules["cv2"] = None` so an early import raises. An eager import wrapped in `try: import cv2 / except ImportError:` swallows that error while still loading the library in any normal environment, so the guard could not see this bug. The added check asserts on `sys.modules` in a clean subprocess instead, and covers the CLI subcommands rather than only `import vllm`.
