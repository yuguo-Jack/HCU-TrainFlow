# [Spec Decode] Consistent drafted, verified and accepted token counts

[Upstream PR](https://github.com/vllm-project/vllm/pull/64156) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Summary

Implements RFC #64099. Builds on #58340 and keeps its 11 commits.

Spec decode now reports three counts:

- **`drafted`**: tokens that came out of the drafter, including grammar-invalid ones.
- **`verified` (new)**: drafted tokens that went into the target forward pass.
- **`accepted`**: unchanged.

`drafted >= verified >= accepted` holds in total and at every step. `verified` is reported wherever the other two are: Prometheus, the log line, per-request metrics, `vllm bench serve` (Python and Rust) and the Rust frontend.

## What changes for users

- New counters `vllm:spec_decode_num_verified_tokens` and `vllm:spec_decode_num_verified_tokens_per_pos`, and per-request fields `num_verified_tokens` and `per_step_verified`.
- With structured outputs, `drafted` now includes grammar-invalid draft tokens (#29821 subtracted them), so `accepted / drafted` goes down.
- MRV1 `ngram_gpu` no longer counts its `-1` padding as `drafted`, so `accepted / drafted` goes up and matches CPU `ngram`.

## How it works

- Only the worker sees both the drafter's output and the target forward pass, so the model runner reports both counts per request in `ModelRunnerOutput` (`num_drafted_tokens_per_req`, `num_verified_tokens_per_req`). The scheduler only counts `accepted`.
- MRV2 counts the non `-1` draft tokens on the GPU before the drafter overwrites them. MRV1 records the count when the drafter proposes (the valid count for `ngram_gpu`).
- `verified` is the draft tokens in the forward pass, capped at `drafted`. With adaptive verification (AV) it includes the AV budget.
- Out-of-tree model runners, and MRV2 diffusion models (no drafter), don't report the counts. The scheduler then counts the scheduled draft tokens, as on main.
- Only the stats change. The rollback of `num_computed_tokens` still uses the scheduled count.

## RFC corrections and differences

- **Sync SO schedules the first grammar-invalid draft token** (#61557). So "sync, grammar rejects last 2" has `verified` 3 (not 2), and "sync, grammar rejects all 4" has `verified` 1 and the step is counted.
- **Truncated drafts** (e.g. near `max_model_len`) still count as `drafted`. The RFC excludes them.
- **`num_spec_steps`**: a step where MRV1 `ngram_gpu` finds no match is counted with 0 `drafted`, except with sync SO, where it is not scheduled. A grammar that already terminated is skipped in sync and counted in async.

Out of scope (see the RFC): draft tokens after a stop (#56101), and zero draft tokens when the drafter is skipped (#34734). The fixes proposed for them (#56137, #56195 and #34757) are compatible with the invariant: they leave `drafted` and `verified` unchanged, or drop the step from all three counts.

## Validation

- **e2e invariant check** on 1x H100, 12 configs at `97b1d9dc37` (MRV1 and MRV2, sync and async, `ngram_gpu`, CPU `ngram`, EAGLE-3, DSpark with and without AV, Rust frontend, both bench clients).
- **New CI check**: `test_async_scheduling.py` now asserts `drafted >= verified >= accepted` on the counter deltas of every spec decode run (EAGLE-3 and `ngram_gpu`, sync and async, JSON schema, preemption, chunked prefill). It passes at `97b1d9dc37` (`ngram_gpu` also with MRV1 and MRV2 forced).
- **Unit tests**: `tests/v1/core`, `tests/v1/metrics`, `tests/v1/spec_decode/test_request_acceptance.py` pass. `test_async_scheduling_pp_allows_rescheduling_with_output_placeholders` fails on main too.
- **Other GPU tests**: entrypoint tests at `97b1d9dc37`. At `09206e80a1`: `test_async_scheduling.py` and `test_async_scheduling_accuracy.py` (`-k "eagle3 or ngram_gpu"`), `ngram_suffix`, `test_ngram_gpu.py`, `aux_output_connector/test_store.py` pass.
- **Rust**: fmt and clippy clean, touched crates pass. 5 `vllm-chat` / `vllm-text` snapshot tests fail on main too.

- With AV, `verified` is well below `drafted` on free text.
- `vllm bench serve` (Python, and Rust with `VLLM_USE_RUST_BENCH=1`) prints `Verified tokens:` and saves `spec_decode_verified_tokens`.
