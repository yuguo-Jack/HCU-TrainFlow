# fix(moe): report reason for CUTLASS FP8 backend rejection

[Upstream PR](https://github.com/vllm-project/vllm/pull/62178) · state: open · merged: False

## Original PR description



## Overview

Fixes #62135. 

Currently, requesting `moe_backend="cutlass"` with online FP8 raises a bare `ValueError` without stating the reason or alternatives. This PR updates `select_fp8_moe_backend` to use `_make_log_unsupported` for the CUTLASS branch and explicitly list the supported alternative backends.

## Claims

- Fixes the error message for CUTLASS FP8 MoE backend rejections to include the specific reason and list of supported alternatives.
- Aligns the CUTLASS error reporting with sibling backends (like HUMMING).

## Validation

- Validated locally by triggering the error path with an unsupported configuration. The error now correctly prints the supported alternatives.
- Test command run: `pytest tests/model_executor/layers/fused_moe/oracle/test_fp8.py`

## Details

The root cause is a hardcoded `raise ValueError` at `oracle/fp8.py:468` that bypassed the `_make_log_unsupported` helper used by other backends in the same function. The change simply routes the CUTLASS rejection through the existing reporting helper to improve startup UX.
