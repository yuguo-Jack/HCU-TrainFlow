# [Bugfix][KV Connector][ROCm] MoRIIO: get the attention backend from the model layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/62311) · state: open · merged: False

## Original PR description

## Overview

`MoRIIOConnectorWorker.__init__` re-runs the attention backend selector with the global cache dtype. DeepSeek-V4 sets that dtype to `fp8_ds_mla` at model init, and the selector call passes no `use_sparse`, so no ROCm backend matches and the worker raises at startup. This PR reads the backend from the model's attention layers with `get_current_attn_backends`, as the NIXL and Mooncake workers already do.

It is the one hunk of #48989 that MoRIIO READ mode needs, split out so it can land on its own.

## Claims

- Fixes the `ValueError: No valid attention backend found` that the MoRIIO worker raises for DeepSeek-V4 on ROCm, for both the producer and the consumer.
- No behavior change for other models. `backend_name` is only logged and sent as `attn_backend_name` in the handshake metadata, and no code compares it.
- Unit tests keep the same path: with no registered layers, `get_current_attn_backends` falls back to the same selector call.

<summary>Reproducer for the selector call (no model load)</summary>

```python
import sys
from vllm.engine.arg_utils import EngineArgs
from vllm.config import set_current_vllm_config
from vllm.v1.attention.selector import get_attn_backend

cfg = EngineArgs(model=sys.argv[1], trust_remote_code=True, kv_cache_dtype="fp8",
                 max_model_len=8192, enforce_eager=True).create_engine_config()
mc, cc = cfg.model_config, cfg.cache_config
cc.cache_dtype = "fp8_ds_mla"  # what DeepseekV4 attention sets at model init
with set_current_vllm_config(cfg):
    get_attn_backend(mc.get_head_size(), mc.dtype, cc.cache_dtype, use_mla=mc.use_mla)
```

## Details

**Flow.**
1. `DeepseekV4` attention init rewrites `cache_config.cache_dtype` from `fp8` to `fp8_ds_mla` (`vllm/models/deepseek_v4/attention.py`).
2. `Worker.initialize_from_config` calls `ensure_kv_transfer_initialized`, which builds `MoRIIOConnectorWorker` after the model is loaded.
3. The worker calls `get_attn_backend(head_size=512, bfloat16, "fp8_ds_mla", use_mla=True)` with no `use_sparse`. Every ROCm MLA backend rejects the dtype.

The layers already hold the backends they selected. `get_current_attn_backends` reads them, so the connector no longer needs to repeat the selection with a partial set of arguments.

**Relation to #48989.** #48989 (@itej89) makes the same backend change, plus CI and Dockerfile updates, a spec-type check, WRITE-mode HMA changes and a `block_len` check removal. READ mode needs only the backend change. `MLAAttentionSpec` subclasses `FullAttentionSpec` and `SlidingWindowMLASpec` subclasses `SlidingWindowSpec`, so main's HMA check already accepts DeepSeek-V4's groups. #48989 has had merge conflicts since 10-15. If this lands first, #48989 can drop the hunk on rebase. @itej89 is credited as co-author.

**Duplicate check.** I searched open PRs for `moriio backend`, `moriio get_attn_backend`, `moriio get_current_attn_backends`, `moriio DeepSeek-V4`, `moriio fp8_ds_mla` and `moriio attention backend`. Only #48989 changes this call site.
