# [Perf][Tokenizer] Copy only the backend for tokenizer pool entries

[Upstream PR](https://github.com/vllm-project/vllm/pull/65674) · state: open · merged: False

## Original PR description

## Overview

Construct tokenizer pool members by shallow-copying the Python tokenizer and deep-copying only its Rust `_tokenizer` backend. Use the same helper when the pool temporarily runs empty. Preserve the existing public pool interface and pickle reconstruction.

## Claims

- Cached GPT-2 pool construction is **2.10–2.12× faster** in this CPU benchmark, for pools of two and four copies.
- The generic Nemotron tokenizer shows only **1–3% lower median times with overlapping ranges**; this is not evidence of a universal large-tokenizer speedup.
- Each pool member retains an independent Rust backend. This does not expand the thread-safety contract to tokenizer mutation APIs.

## Details

Whole-tokenizer deepcopy duplicates Python vocabulary/merge metadata and can rebuild cached wrapper state. The intended tokenization paths can share Python configuration, while each member needs an isolated mutable Rust backend for concurrent truncation/encoding. Python warning bookkeeping may still be updated. The benefit depends on the tokenizer class and how much Python state it owns.

Exact comparison: base `69d27bf8002a4634de1699c95fb0aeb22fb86ca5` → PR `1038593e5256c4cbb0d771a19a54e1136644da80`. The implementation was unchanged during benchmarking.

## Benchmarks

Virtualized AMD EPYC-Genoa (KVM), four allowed logical CPUs [0,1,2,3], 7.57 GiB RAM, no GPU; each child was pinned to [0]. Python 3.12.13, Torch 2.14.0+cpu, Tokenizers 0.23.3 and **unmodified installed Transformers 5.22.1** for both variants. The Transformers patch was excluded from this experiment.

Real local tokenizer artifacts: `nvidia/NVIDIA-Nemotron-Nano-12B-v2-VL-BF16@ca9543b126e8bf3176916d3d305ccc415f89fd4d` (TokenizersBackend/BPE, vocab_size 131,072; len 131,082 including added tokens), and `openai-community/gpt2@607a30d783dfa663caf39e06633721c8d4cfcd7e` (GPT2Tokenizer/BPE, len 50,257). Each uses the actual `get_cached_tokenizer` wrapper used in the tokenizer/renderer path. A new unpooled tokenizer was loaded and cached outside timing for every sample; no already-pooled tokenizer was reused.

Seven measured samples per variant and case, with a full untimed warm-up in each fresh child process. Calls ran strictly sequentially on CPU 0; base/PR order alternated, with the starting variant also alternated across cases. OMP/MKL/OpenBLAS threads=1 and TOKENIZERS_PARALLELISM=false. Imports, fixture/tokenizer preparation, initial cache-wrapper creation, downloads and correctness checks are outside timing; the entire requested API call is timed, including any tokenizer reload or wrapper reconstruction it performs. No model weights were downloaded or loaded. Local files were read before timing; Hub access was offline. Table entries are wall-clock medians and observed min–max ranges; speedup is base median / PR median and reduction is (1 − PR median / base median) × 100. These are warm local API startup measurements, not cold imports or serving throughput. No allocation tracing was used.

| Case | Base median [range], ms | PR median [range], ms | Speedup | Reduction |
| --- | ---: | ---: | ---: | ---: |
| nemotron, cached, copies=2 | 1098.095 [1043.254–1138.444] | 1066.726 [1029.717–1123.521] | 1.03× | 2.86% |
| nemotron, cached, copies=4 | 2199.382 [2115.762–2257.509] | 2171.688 [2079.089–2238.333] | 1.01× | 1.26% |
| gpt2, cached, copies=2 | 427.054 [414.277–444.302] | 201.267 [190.583–211.458] | 2.12× | 52.87% |
| gpt2, cached, copies=4 | 852.806 [827.470–891.857] | 405.754 [397.083–418.332] | 2.10× | 52.42% |

The generic Nemotron tokenizer has little Python vocabulary metadata to eliminate. GPT2 exposes more Python vocabulary/merge state and shows a different benefit. The cached wrapper's custom `__reduce__` also runs on `copy.copy`, so it rebuilds its vocabulary cache in both variants; the cached get_vocab dictionary is distinct in both. The small Nemotron difference is consistent with remaining Rust copies/cache reconstruction dominating, but this run does not profile individual cost components. Small changes should be read with their observed ranges. These data do not support applying a fixed speedup to all large tokenizers.

## Validation

Prior patch validation (not rerun as part of this benchmark): all eight `tests/tokenizers_/test_hf.py` cases passed with the ordinary conftest, including real GPT2 and ChatGLM; two supplemental pool-contract checks were validated with base negative controls. Pinned Ruff checks passed. New benchmark checks pass for every final sample: a fresh unwrapped input, preserved encoded IDs, same-object return, idempotence, the requested pool size and distinct Rust backends. Separate diagnostic pilot children passed 64 bounded concurrent truncating calls and pickle round trips for both variants and all four tokenizer/copies cases; they used at most four workers and did not grow the pool. Python `init_kwargs` are shared by PR members and distinct in base members. The cached get_vocab dictionary remains distinct in both variants.

Prior suite command: `.venv/bin/python -m pytest tests/tokenizers_/test_hf.py -v` with its normal repository conftest and real tokenizer fixtures. The separate benchmark diagnostics do not replace that suite.

## Limitations

CPU-only tokenizer pool construction scope. No model/GPU/serving evaluation or end-to-end throughput claim. The PR deliberately shares Python-side tokenizer metadata; only the Rust backends are isolated. Mutation APIs such as `add_tokens` and `add_special_tokens` remain outside the thread-safe pooled interface. Isolated Rust copies still cost time proportional to tokenizer complexity; a large vocabulary alone does not guarantee a large gain. No allocation savings were measured; whole-child peak RSS in raw diagnostics is not an allocation benchmark.

```python
"""Portable single-sample reproducer; call alternately under base/PR PYTHONPATH."""
import gc
import json
import os
from pathlib import Path
import sys
import time
import urllib.request
import subprocess
import ssl
import certifi

root = Path(os.environ["PERF_ROOT"]).resolve()
root.mkdir(parents=True, exist_ok=True)
for key, value in {"TMPDIR": root / "tmp", "HF_HOME": root / "cache/hf", "XDG_CACHE_HOME": root / "cache/xdg"}.items():
    Path(value).mkdir(parents=True, exist_ok=True)
    os.environ[key] = str(value)
os.sched_setaffinity(0, {min(os.sched_getaffinity(0))})
os.environ["HF_HUB_OFFLINE"] = os.environ["TRANSFORMERS_OFFLINE"] = "1"
from transformers import AutoTokenizer
import transformers
import vllm.tokenizers.hf as hf
repo_path = Path(os.environ["BENCH_REPO"]).resolve()
assert Path(hf.__file__).resolve().is_relative_to(repo_path)
head = subprocess.check_output(["git", "-C", str(repo_path), "rev-parse", "HEAD"], text=True).strip()
assert head == os.environ["BENCH_EXPECTED_HEAD"]
assert transformers.__version__ == "5.22.1"
assert "site-packages/transformers/" in transformers.__file__
label, copies = sys.argv[1], int(sys.argv[2])
repo, rev, names = {
    "nemotron": ("nvidia/NVIDIA-Nemotron-Nano-12B-v2-VL-BF16", "ca9543b126e8bf3176916d3d305ccc415f89fd4d", ["tokenizer.json", "tokenizer_config.json", "special_tokens_map.json", "config.json"]),
    "gpt2": ("openai-community/gpt2", "607a30d783dfa663caf39e06633721c8d4cfcd7e", ["tokenizer.json", "tokenizer_config.json", "config.json"]),
}[label]
fixture = root / label
fixture.mkdir(exist_ok=True)
for name in names:
    target = fixture / name
    if not target.exists():
        with urllib.request.urlopen(f"https://huggingface.co/{repo}/resolve/{rev}/{name}", timeout=120, context=ssl.create_default_context(cafile=certifi.where())) as response:
            target.write_bytes(response.read())
os.environ["HF_HUB_OFFLINE"] = os.environ["TRANSFORMERS_OFFLINE"] = "1"

def load():
    tokenizer = hf.get_cached_tokenizer(AutoTokenizer.from_pretrained(fixture, local_files_only=True, trust_remote_code=False, fix_mistral_regex=False))
    assert not isinstance(tokenizer, hf.ThreadSafeHFTokenizerMixin)
    return tokenizer

warm = hf.maybe_make_thread_pool(load(), copies=copies)
assert warm.encode("hello world, café, 你好")
del warm
gc.collect()
tok = load()
expected = tok.encode("hello world, café, 你好")
gc.collect()
start = time.perf_counter_ns()
pooled = hf.maybe_make_thread_pool(tok, copies=copies)
ns = time.perf_counter_ns() - start
sample = {"fixture": label, "copies": copies, "elapsed_ns": ns, "head": head, "production_file": hf.__file__, "transformers_file": transformers.__file__, "transformers_version": transformers.__version__, "affinity": sorted(os.sched_getaffinity(0)), "vocab_len": len(tok), "ok": False}
(root / "last-sample.json").write_text(json.dumps(sample) + "\n")
assert pooled is tok and pooled.encode("hello world, café, 你好") == expected
assert hf.maybe_make_thread_pool(pooled) is pooled
assert head == subprocess.check_output(["git", "-C", str(repo_path), "rev-parse", "HEAD"], text=True).strip()
sample["ok"] = True
(root / "last-sample.json").write_text(json.dumps(sample) + "\n")
print(json.dumps(sample))
```
