# [Bugfix][KV Connector][Mooncake] Keep readiness waits out of transfer slots

[Upstream PR](https://github.com/vllm-project/vllm/pull/62658) · state: open · merged: False

## Original PR description



## Overview

Separate Mooncake Prefill-readiness waits from bounded KV-transfer slots so missing producers cannot block unrelated transfers whose KV is already ready.

## Claims

- Keep actual transfer concurrency at twice num_workers while allowing independent readiness waits.
- Bound pending metadata batches with max_pending_transfers (default 1024), reject excess batches explicitly, and clean up readiness tasks on exit.

TODO

## Details

Previously, Decode metadata entered a shared queue whose fixed sender workers waited for Prefill readiness before sending KV. Enough unready pulls occupied every worker and stranded later ready transfers. Use one bounded coordinator per metadata batch and acquire a semaphore only for transfer preparation and execution; retain producer blocks while ready batches wait for a slot and restore sending counters on errors. Unlike #51236, this changes slot ownership rather than orphan expiry; it keeps the existing readiness timeout and does not depend on that PR. Prepared with OpenAI Codex assistance.
