# [Bugfix][XPU] Skip Triton allocator registration for TD scaled_mm on XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/61583) · state: open · merged: False

## Original PR description

## Purpose

Fix `tests/quantization/test_compressed_tensors.py::test_compressed_tensors_no_enforce_eager` on XPU, which fails at engine init:

```
torch/fx/passes/split_module.py, in record_cross_partition_use
    for s in sorted(free_symbols(def_val), key=str):
AssertionError: cannot extract sympy expressions from TreeSpec(tuple, None, [TreeSpec(tuple, None, []), TreeSpec(dict, [], [])])
```

### Root cause
#47205 added tensor-descriptor (TD) operand loads to `triton_scaled_mm` and registers a Triton global-memory allocator (`triton.set_allocator`) on the first TD launch. TD is auto-enabled on XPU.

Without `enforce_eager`, that first launch happens while Dynamo traces the forward, so `triton.set_allocator` is captured as `invoke_leaf_function` plus a `get_attr` whose `example_value` is a pytree `TreeSpec`. `split_graph` -> `split_module` then calls `free_symbols()` on it and asserts.

### Fix
On XPU the allocator isn't needed: Triton XPU lowers TD to 2D block IO and never calls it. Verified by installing a counting allocator and running TD `triton_scaled_mm` (M in {1, 64, 256}, K=N=4096, transposed weight): 0 allocator calls, results correct. So skip registration on XPU. Other platforms (TD opt-in on CUDA) are unchanged.

## Notes
- Not caught by CI: the XPU compressed-tensors job only runs `test_compressed_tensors_fp8` / `_fp8_block_enabled`, and #47205's benchmarks used `--enforce-eager`. Adding `test_compressed_tensors_no_enforce_eager` to the XPU job could be a follow-up.
- Other kernels with the same pattern (`fused_moe.py`, `fused_batched_moe.py`, `olmo_gdn_linear_attn.py`, LoRA `fused_moe_lora_op.py`) may hit the same issue under TD + compile on XPU; not touched here.
