# [Perf][DSv4.1] Fuse C1/C2 compression with FP8 KV cache insertion

[Upstream PR](https://github.com/vllm-project/vllm/pull/61088) · state: open · merged: False

## Original PR description

## Overview

Fuse DeepSeek-V4.1 C1/C2 compression with RoPE, FP8 quantization and the 584-byte main-cache write. Integrate ordinary attention and the target model's KV-only bounded-prefill replay path on SM90.

**Draft with complete serving integration.** Measured operator speedup is **1.18–1.53x**. The completed H20 two-TP4 crossover shows a positive cold 16K/c4 signal, but **does not establish a stable general end-to-end gain**.

The fusion boundary is inspired by [SGLang #41660](https://github.com/sgl-project/sglang/pull/41660) by @DarkSharpness. This implementation retains vLLM's own FP32 pooling/RMSNorm and BF16 latent rounding.

## Claims

- Preserve the indexer's BF16 latent, ring-state ordering, distinct state/cache slots and padding semantics.
- Integrate both callers for CUDA SM90, uint8 584-byte cache, PCP1/DCP1. Other hardware, KV formats and context-parallel configurations retain separate insertion.
- No weight conversion, extra persistent weight/cache allocation, Humming backend change, scheduler change or model-runner change.
- Operator acceleration is measured; **model acceleration is not established**.

## Validation

- **18 additional exact-byte cases passed** for state, latent and full cache contents: changed/restored graph inputs, ragged/empty/padded requests, ring wrap, negative cache slots, shrinking buffers, 128-request six-query verification and 16K prefill. No tolerance was relaxed.
- Full pre-commit passed on all four changed files, including Ruff, mypy and test tethering.

## Details

fused_save_compress_norm gains optional RoPE/cache arguments. It shares the original 584-byte store implementation with the separate insertion kernel and explicitly preserves BF16 store/reload rounding. Ring-state slots and main-cache slots remain distinct.

Q/SWA preparation still overlaps compression. Fused compression publishes both latent and main cache before the existing join; indexer preparation then consumes that latent. This removes the second insertion fork/join but can delay indexer start, so kernel gains need not translate into model gains. KV-only bounded-prefill replay also avoids duplicate insertion. The separate DSpark drafter does not own C1/C2 compressors.

**Remaining before Ready:** NCU/causal profiling, convincing repeatable model benefit, and human review. H20 counter access requires additional permission that remains pending; no capabilities or host settings were changed. Other SM90 products have not been benchmarked.

Earlier harness attempts failed before any timed samples: an incorrect draft-inventory assertion, an unavailable cache-reset endpoint, an omitted dataset manifest, and a GPU UUID metadata-prefix mismatch in the initial crossover attempt. All are archived. The crossover launcher was interrupted by the bastion idle timeout after its independent phase-0 client completed; a detached controller verified ownership and resumed only phase 1 under the original time bound, without repeating or removing samples. All six crossover containers exited 0, and all eight test GPUs were verified at 0 MiB / 0% with no compute processes.

Duplicate-work checks for the compressor/fusion area and exact fused_save_compress_norm / rope_quant_insert symbols found no equivalent CUDA producer/cache fusion PR. Adjacent #56935/#57523 concern attention/KV formats, while #57977 concerns MXFP8 activation chaining. This is a bounded public search, not a claim about private work.
