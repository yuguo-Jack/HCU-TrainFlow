# [ROCm][Perf] Fuse AITER split-K GEMM reduce into add + RMSNorm

[Upstream PR](https://github.com/vllm-project/vllm/pull/62518) · state: open · merged: False

## Original PR description

## Overview

Add an opt-in ROCm compile pass that fuses an unquantized GEMM into the residual add + RMSNorm that consumes it
(`-cc.pass_config.fuse_gemm_add_rms=True`, compile ranges of at most 256 tokens). When the GEMM runs as an AITER Triton
split-K GEMM, the fp32 partials go straight into AITER's `fused_reduce_add_rmsnorm`, so the split-K reduce kernel and
the add + RMSNorm kernel become one kernel. 

See the companion AITER PR: https://github.com/ROCm/aiter/pull/6678

## Claims

- Qwen3.8-27B BF16, TP1, MI355X, 1024×1024: per decoder layer, the split-K reduce (4.5 µs) and the add + RMSNorm (4.7 µs) after o_proj / out_proj become one 4.6 µs kernel.
- The gain needs a GEMM that splits K at decode sizes. Here, the AITER Triton config for N=5120, K=6144 (Qwen3.8 o_proj
  and out_proj) uses 3 splits for M=9–64. Where the GEMM does not split K (e.g. down_proj on hipBLASLt), the pass only
  swaps Inductor's add + RMSNorm for the AITER kernel at the same launch count.
- Off by default at every optimization level; no change for CUDA, XPU or other ROCm configurations.

## Details

- `rocm_unquantized_gemm_impl` becomes a wrapper over `_rocm_unquantized_gemm(..., skip_reduce=False)`.
  Only the two branches that reach AITER's Triton `gemm_a16w16` honour `skip_reduce`: the direct Triton branch, and the
  tuned (`tgemm`) branch when AITER's tuned config for the shape says `triton`. Those return the `[num_ksplit, M, N]`
  fp32 partials; every other branch returns the normal output. The registered `rocm_unquantized_gemm` op is unchanged.
- `rocm_aiter_gemm_add_rmsnorm(x, weight, residual, norm_weight, eps, gemma_norm)` runs the GEMM with
  `skip_reduce` and passes the result (partials or the reduced output) to `fused_reduce_add_rmsnorm`.
- Pattern matches `rocm_unquantized_gemm` → `vllm_ir.fused_add_rms_norm`, for RMSNorm and GemmaRMSNorm. The plain form requires the weight dtype to equal the activation dtype (`_rms_input_weight_dtype_match`), so it never binds Gemma's fp32 `(w + 1)` and leaves the `+1` as a separate kernel. Runs before the RMSNorm + quant passes.
- Compile ranges up to `pass_config.gemm_add_rms_fusion_max_token_num` (default is 256) tokens for decode, where split-K configs apply. Prefill keeps Inductor's kernels.
