# [Rust Frontend] Export vllm:engine_sleep_state like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/63959) · state: closed · merged: True

## Original PR description

## Overview

Python exports `vllm:engine_sleep_state`, a per-engine gauge with one series per `sleep_state` label (`awake`, `weights_offloaded`, `discard_all`). `PrometheusStatLogger` creates it with the engines awake (`vllm/v1/metrics/loggers.py:593-617`), and `AsyncLLM` updates it after each successful engine call (`vllm/v1/engine/async_llm.py:1197-1217`, `record_sleep_state` at `loggers.py:1335-1352`). The Rust frontend routes `/sleep`, `/wake_up`, `/release_kv_cache_memory` and the gRPC sleep controls, but never exports this gauge, so `tests/entrypoints/rl/state_transitions/test_sleep.py::test_sleep_mode` fails under Rust only on its metric assertions. This PR registers the gauge and records the state after each successful sleep, wake-up and KV-cache release call.

## Claims

- `vllm:engine_sleep_state{model_name, engine, sleep_state}` is exported per engine with Python's help text, and starts with `awake` at 1.
- The series follow Python's transitions: `sleep(level=1)` sets `weights_offloaded`, `sleep(level=2)` sets `discard_all`, `sleep(level=0)` and `release_kv_cache_memory()` set all three to 0, and a `wake_up` that returns fully awake sets `awake` back to 1. A `wake_up` with only part of the engine awake leaves the state unchanged.
- The gRPC `Sleep` call rejects an unknown level with `InvalidArgument` instead of forwarding it to the engine; the HTTP route already rejected it.
- With `--disable-log-stats` nothing is recorded, as in Python.

- `sleep_and_wake_calls_record_engine_sleep_state` (`vllm-engine-core-client`) drives a client against two scripted engines through `sleep(1)`, a partial `wake_up(["weights"])` where only engine 1 reports fully awake, a full `wake_up`, `release_kv_cache_memory`, and `sleep(2)`. It snapshots the rendered series of both engines after each step, and the snapshot matches the table in Details. It fails with the three record calls removed, and on the base, where all series are missing.
- `control_sleep_rejects_unknown_level`: the gRPC `Sleep` call returns `InvalidArgument` for an unknown level.

## Details

Python behavior (`vllm/v1/metrics/loggers.py`, `vllm/v1/engine/async_llm.py`):

| Call | `awake` | `weights_offloaded` | `discard_all` |
|---|---|---|---|
| startup | 1 | 0 | 0 |
| `sleep(level=1)` | 0 | 1 | 0 |
| `sleep(level=2)` | 0 | 0 | 1 |
| `sleep(level=0)` or `release_kv_cache_memory()` | 0 | 0 | 0 |
| `wake_up(tags)` returning fully awake | 1 | 0 | 0 |
| `wake_up(tags)` with only part of the engine awake | unchanged | unchanged | unchanged |

Changes:

- `vllm-metrics`: register `vllm:engine_sleep_state` with Python's help text and the labels `model_name`, `engine` and `sleep_state`.
- `vllm-engine-core-client`: `SchedulerStatsRecorder` resolves the three series per engine and sets the engines awake when it is created. `EngineCoreClient::sleep`, `release_kv_cache_memory` and `wake_up` record the new state after the utility call succeeds. A partial wake-up leaves the state unchanged.
- `SleepLevel` (`PauseOnly`, `OffloadWeights`, `DiscardAll`) in `protocol::utility`, serialized as Python's integer level. The HTTP query and the gRPC request lower into it, `EngineCoreClient::sleep` takes it, and the gauge mapping is an exhaustive `match`. `release_kv_cache_memory` gets its own `KvCacheReleased` state.

**Ownership and layering.** In Python, the state is recorded by the engine client (`AsyncLLM`), not by the HTTP route. The Rust counterpart is `EngineCoreClient`, which both the HTTP routes and the gRPC control service call, so the gauge covers both entry points. The handles live in `SchedulerStatsRecorder`, which already holds the per-engine, engine-labeled stat-logger series and exists only when engines record stats. This matches Python, where `--disable-log-stats` leaves `logger_manager` unset and nothing is recorded.

`tests/entrypoints/rl/state_transitions/test_sleep.py::test_sleep_mode` expects the metric behavior added here; the sleep, wake and tag routes themselves already pass under Rust.

Not a duplicate: no open PR exports `vllm:engine_sleep_state` from the Rust frontend. vllm-project/vllm#59130 redesigns sleep-state telemetry into new per-resource series and keeps this gauge; it has had no activity since 2026-10-10.
