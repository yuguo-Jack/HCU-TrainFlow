# [KV Offload] Mirror CPU offload region slots across nodes

[Upstream PR](https://github.com/vllm-project/vllm/pull/62933) · state: open · merged: False

## Original PR description

## Overview

Fixes `TieringOffloadingSpec` secondary tiers when the engine's workers span nodes (the bug half of #54415). The scheduler and its secondary tiers read one CPU region, on the head node; workers on other nodes now move their KV straight between their GPU blocks and their slot of that region with one-sided NIXL transfers (GPUDirect RDMA).

```text
        other node                            head node
 +---------------------+           +----------------------------------+
 | worker r            |           | worker 0          engine core    |
 |  GPU KV blocks  <---+-- RDMA ---+-> CPU region      (scheduler,    |
 +---------------------+  (NIXL)   |   chunk: [w0|..|wr|..]  tiers)   |
                                   +----------------------------------+
```

Depends on #52838 (failed offloading transfers are reported instead of asserting) and #62930 (which rejects these engines at startup; this PR lifts that). Both are included as merge commits; this PR's own changes are the non-merge commits after them. The later merges of `main` only bring the branch up to date.

## What changes

- **Where the KV lives:** the head node's region holds every worker's slot of each chunk and is the only copy. Workers on other nodes allocate no CPU region: their copy plan addresses their slot of the head region directly.
- **Stores and loads:** a remote worker writes its GPU blocks to its slot (RDMA WRITE) and reads them back (RDMA READ), in transfers of about 256 MiB; loads go ahead of stores, so a load waits for at most one transfer of a large store. A store is reported once its bytes are in the head region, so a secondary tier never reads a chunk before every slot arrived.
- **Failures:** a transfer that ends in an error is a failed transfer (#52838). One with no result after `mirror_timeout_s` could still land on a reused chunk or block, so the engine stops.
- **Supported:** one engine (no data parallelism), the same KV geometry on every worker (checked at startup), NIXL installed, GPUDirect RDMA. Still rejected across nodes: data parallelism, `canonical_layout`, `replicated_layout`, the `kvcr` tier. The fs, obj and p2p tiers store multi-node rows in their own namespace.
- Single-node deployments and multi-node deployments without secondary tiers are unchanged.

## Hardware limitation, and why earlier revisions staged through CPU memory

All the testing below runs on DGX Spark (GB10, ConnectX-7 over RoCE), and **GB10 has no GPUDirect RDMA**: the driver reports neither `CU_DEVICE_ATTRIBUTE_GPU_DIRECT_RDMA_SUPPORTED` nor dma-buf support, the NIC registers host memory only, and UCX emulates VRAM transfers by staging them through host memory. Measured with NIXL between two nodes over a direct 200 Gb/s link, 1 GiB in 2 MiB descriptors, data verified:

| Path | Write | Read |
|---|---|---|
| GPU → RDMA → remote CPU (this PR) | 1.33 GB/s | 1.45 GB/s |
| GPU → local CPU → RDMA (earlier revisions' `cpu` source) | 11.0 GB/s | 11.0 GB/s |
| CPU → RDMA → CPU (ceiling) | 13.9 GB/s | 13.7 GB/s |

That is why the earlier revisions kept a node-local CPU region on each remote worker and mirrored it to the head: on the only hardware we have, staging through host memory is about 8× faster than the direct path. Following review, this PR now targets the main use case, data-center GPUs with GPUDirect RDMA (NVL72-style racks), where the NIC reads and writes the GPU blocks itself, the extra host copy and the per-node CPU memory go away, and the head region stays the single source of truth. Host staging can come back later as an opt-in buffer, as the nixl connector does.

As a consequence, **every run below exercises the direct path in UCX's emulated mode**. It checks correctness and behaviour (complete rows, identical outputs, no failed or stuck transfers, loads overtaking stores, concurrent restores), not performance: I could not measure the direct path, or the head's bandwidth under it, on GPUDirect hardware. Help with such a run is very welcome.

## Validation

2× DGX Spark, TP=2 (`--nnodes 2`), `Qwen/Qwen3-30B-A3B-Instruct-2507-FP8`, 24 GiB CPU tier, `fs` tier on the head node's NVMe, nightly `00b6c4c565` with this branch's changed Python files on top. Recall prompts with 16 keys, `temperature=0`; each request from disk is the first after restarting both nodes:

| Prompt | Cold prefill | From disk | Keys | Output vs cold |
|---|---|---|---|---|
| 64k | 33.3 s | 13.4 s | 16/16 | identical |
| 200k | 194.2 s | 29.5 s | 16/16 | identical |

**Repeated CPU-tier hits and concurrent restores**, same setup: 8 prompts of about 22.8k tokens, each served cold once; then, three times, the GPU prefix cache is reset (`/reset_prefix_cache`, CPU tier kept) and one prompt is restored alone, then all 8 at once. The single-node row is the same test on one DGX Spark (TP=1, no mirror) for reference:

| | Cold TTFT | One restore | 8 concurrent, TTFT median / max | Output vs cold |
|---|---|---|---|---|
| 2 nodes, mirror | 4.2–5.6 s | 1.04–1.07 s | 15.2–15.9 s / 25.8–26.0 s | 24/24 identical, 0 failed transfers |
| 2 nodes, mirror, `max_tokens=1` | | 1.06–1.09 s | 5.0 s / 7.9–8.0 s | |
| 1 node, no mirror | 6.2 s | 0.25–0.29 s | 1.2–1.4 s / 1.6 s | 24/24 identical |

A restore moves about 1.1 GB per remote worker. In the emulated mode this runs at about 1.1 GB/s through host memory, so 8 restores at once take about 8 s; with the other requests decoding at the same time on the GPU they take about 26 s, since UCX's host-staged copies compete with decode on GB10. On hardware with GPUDirect RDMA the NIC reads and writes the GPU blocks itself; I could not measure that path or the head's bandwidth under it; the client used here is in a comment below for anyone who can.

## Details

- `vllm/v1/kv_offload/cpu/gpu_worker.py`: copy planning moves out of `SingleDirectionOffloadingHandler` into `CopyPlanner`, which plans from the resolved GPU block pointers and describes the CPU side by `TensorRows` (base address, row stride, row size, row count) instead of CPU tensors. The handler builds it from its CPU tensors, unchanged in behaviour; the mirror builds one against the worker's slot of the head region.
- `vllm/v1/kv_offload/cpu/region_mirror.py`: `RegionMirrorHead` registers the head region with a NIXL agent; `slot_planners` plans a remote worker's copies against its slot of the head region; `RegionMirrorClient` registers the worker's GPU KV cache and runs the transfers; `RegionMirrorWorker` runs the copies on a background thread. Only `DONE`, `ERR` or a remote disconnect end a transfer; anything else is treated as stuck.
- `vllm/v1/kv_offload/tiering/spec.py`: placement, the head region (allocated only on the head node), and the collectives that attach the mirror on every rank.
- `FileMapper`: a `slot_layout` namespace on engines the executor reports across nodes.

**Not a duplicate:** #53474 sizes node-local regions and rejects multi-node secondary tiers; #46556 moves rank-local shards to a shared filesystem through worker transfers; #59547 (one region per rank) is single-node.

```python
# Repeated CPU-tier hits and concurrent restores through the KV offload mirror.
# Serves each prompt cold once, then per round resets the GPU prefix cache (the
# CPU tier is kept) and restores one prompt alone, then all prompts at once.
# Every output must match its cold output. Needs VLLM_SERVER_DEV_MODE=1.
import hashlib, json, random, sys, time, urllib.request
from concurrent.futures import ThreadPoolExecutor

BASE, MODEL = sys.argv[1], sys.argv[2]
N, TOKENS, ROUNDS = int(sys.argv[3]), int(sys.argv[4]), int(sys.argv[5])
CONC_MAX_TOKENS = int(sys.argv[6]) if len(sys.argv) > 6 else 200
WORDS = "order customer route truck pallet batch invoice supplier shipment stock dock shift inventory".split()


def post(path, body=None):
    req = urllib.request.Request(
        BASE + path, json.dumps(body or {}).encode(), {"Content-Type": "application/json"}
    )
    return urllib.request.urlopen(req, timeout=3600)


def prompt(i):
    rnd = random.Random(1000 + i)
    paras = [" ".join(rnd.choice(WORDS) for _ in range(60)) + ".\n" for _ in range(TOKENS // 75)]
    keys = {f"KEY-{k:02d}": str(rnd.randint(100000, 999999)) for k in range(8)}
    for k, (name, value) in enumerate(keys.items()):
        paras.insert(int((k + 0.5) * len(paras) / 8), f"Note: code {name} is {value}.\n")
    question = "List the 8 codes KEY-00 to KEY-07 with their values, one per line as KEY-XX: value."
    return "".join(paras) + "\n" + question, keys


def ask(i, max_tokens=200):
    text, keys = prompt(i)
    body = {"model": MODEL, "messages": [{"role": "user", "content": text}],
            "max_tokens": max_tokens, "temperature": 0, "stream": True,
            "stream_options": {"include_usage": True}}
    start, ttft, out = time.time(), None, []
    for line in post("/v1/chat/completions", body):
        line = line.decode().strip()
        if not line.startswith("data: ") or line == "data: [DONE]":
            continue
        for choice in json.loads(line[6:]).get("choices", []):
            piece = choice.get("delta", {}).get("content")
            if piece:
                ttft = ttft or time.time() - start
                out.append(piece)
    answer = "".join(out)
    return dict(i=i, ttft=ttft, keys=sum(f"{n}: {v}" in answer for n, v in keys.items()),
                sha=hashlib.sha1(answer.encode()).hexdigest()[:12])


def reset():
    post("/reset_prefix_cache").read()
    time.sleep(1)


cold = {}
for i in range(N):
    r = ask(i)
    cold[i] = r["sha"]
    print(f"cold p{i}: ttft={r['ttft']:.2f}s keys={r['keys']}/8", flush=True)
time.sleep(15)  # let the last stores complete
for rnd in range(ROUNDS):
    reset()
    r = ask(rnd % N)
    print(f"round {rnd} alone: ttft={r['ttft']:.2f}s same={r['sha'] == cold[r['i']]}", flush=True)
    reset()
    start = time.time()
    with ThreadPoolExecutor(N) as ex:
        rs = list(ex.map(lambda i: ask(i, CONC_MAX_TOKENS), range(N)))
    ttfts = sorted(r["ttft"] for r in rs)
    same = sum(r["sha"] == cold[r["i"]] for r in rs) if CONC_MAX_TOKENS == 200 else "n/a"
    print(f"round {rnd} x{N}: wall={time.time() - start:.2f}s ttft median/max="
          f"{ttfts[N // 2]:.2f}/{ttfts[-1]:.2f}s same={same}", flush=True)
```
