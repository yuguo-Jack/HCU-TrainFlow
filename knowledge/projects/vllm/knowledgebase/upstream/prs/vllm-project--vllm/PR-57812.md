# [XPU][CI] Don't force ViT  cudagraph capture in the Qwen2.5-VL window-attention tests on XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/57812) · state: closed · merged: False

## Original PR description

## Purpose
`test_qwen2_5_vl_window_attention_image` and `test_qwen2_5_vl_window_attention_image_batch` set `cudagraph_mm_encoder=True` unconditionally. This PR makes that opt-in a no-op on XPU for 3 reasons:

#### 1.  On XPU the two cudagraph settings end up inconsistent
`XPUPlatform.check_and_update_config` forces `cudagraph_mode = NONE` unless `VLLM_XPU_ENABLE_XPU_GRAPH=1`, but it does not touch `cudagraph_mm_encoder`. The multimodal CI job runs without that env var, so both of these appear in the same run:

```bash
WARNING [xpu.py:301]               XPU Graph is disabled by environment variable
INFO    [encoder_cudagraph.py:268] Encoder CUDA graph capture complete. Captured 7 graphs across 1 paths.
```

The resulting *decoder eager + encoder captured* combination is not something XPU enables on its own, and it seems unlikely to be what users would configure in practice, so the coverage it provides on XPU looks limited.

#### 2. These two tests do not carry the platform guard used by the dedicated ViT CG suite
Both tests were added in #40830 together with the Qwen2.5-VL `SupportsEncoderCudaGraph` implementation, so their subject is ViT CUDA graph capture on the window-attention path.

The same PR also touched the dedicated ViT CG suite, `tests/models/multimodal/generation/test_vit_cudagraph.py`, and there the platform restriction is present. (see https://github.com/vllm-project/vllm/blob/7d99c2c4fd61cdeebd29cc7b60584bad10d1ef99/tests/models/multimodal/generation/test_vit_cudagraph.py#L472)

The two tests in `test_qwen2_5_vl.py` cover the same feature but do not carry that guard. This PR brings them in line with that suite.

#### 3. XPU graph has its own CI job
XPU graph support exists and is actively tested. `.buildkite/intel_jobs/test-intel.yaml` defines an `XPU Graph` job that exports `VLLM_XPU_ENABLE_XPU_GRAPH=1`, with `source_file_dependencies` covering exactly the XPU graph surface.

That job is where ViT CG coverage on XPU belongs, mirroring how `test_vit_cudagraph.py` is the home for it on cuda/rocm. It already follows an incremental-enablement style, so adding a multimodal case there is straightforward once that support is ready.


## Test Plan

```bash
pytest -v -s models/multimodal/generation/test_qwen2_5_vl.py -m core_model
```


## Test Result
All 12 `core_model` items pass on XPU. The two `window_attention*` tests now log `Skipping encoder and decoder CUDA graph capture` instead of `Encoder CUDA graph capture complete. Captured 7 graphs across 1 paths.`
