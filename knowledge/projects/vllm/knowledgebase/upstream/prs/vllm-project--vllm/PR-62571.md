# [Bugfix][KVConnector] Drop deferred notifications for evicted remote engines

[Upstream PR](https://github.com/vllm-project/vllm/pull/62571) · state: open · merged: False

## Original PR description

## Purpose

In P/D disaggregation with NixlConnector, a remote engine is evicted once it
sits idle past its TTL (engine_ttl). Eviction calls remove_remote_agent for
each of that engine's NIXL agents, but the deferred receive-notification map
(_pending_recv_notifs) is keyed by request id and keeps the removed agent
names. The next get_finished then calls _send_pending_recv_notifs, which sends
to an agent that eviction already removed. On UCX this fails; on the nixl 1.4
libfabric backend it blocks in connect() for up to 60s, the engine-starvation
path reported in #62144.

Partially addresses #62144 (the vLLM side). The 60s libfabric connect() stall
itself lives in nixl and is tracked there.

## Changes

- _cleanup_remote_engine drops _pending_recv_notifs entries whose agent
  belongs to the evicted engine, keeping entries for other engines.
- _send_pending_recv_notifs skips agents that are no longer registered,
  logging at debug instead of sending to a removed agent.

## Test Plan

- Unit tests next to test_engine_ttl_eviction, using FakeNixlWrapper.
- Reproduce on hardware: two prefill engines and one decode on one host, UCX,
  engine_ttl=60, requests round-robined, then idle past the TTL.

## Test Result

- Three new tests fail on main and pass with this change:
  test_cleanup_remote_engine_drops_its_pending_recv_notifs,
  test_ttl_eviction_never_notifies_evicted_agent,
  test_send_pending_recv_notifs_skips_unregistered_agent.
- The full tests/v1/kv_connector/unit/test_nixl_connector.py passes (190 tests).
- On one 8xH100 host, the eviction reproduces ("Evicted stale remote engine
  ... inactive for 75.2s"), and with this change the following requests still
  transfer, 4 of 4, with zero failed and zero expired.

- xuechendi · COMMENTED · 2026-10-22T15:49:49Z · [source](https://github.com/vllm-project/vllm/pull/62571#pullrequestreview-5616986494)

Thanks for picking this up. +1 to @chrikrah's blocking point about the three split-read tests. I have a more basic question about whether TTL eviction can reach the state this PR cleans up.

**TTL eviction already skips engines that have a pending notification**

1. A deferred notification is only added in `pull_worker.py:_read_blocks_mixed`, right before that request's read handles are posted. It is removed in the same `get_finished` call that sees the transfer finish: either sent (`base_worker.py:3259`) or dropped on the failure path (`:3249`). So an entry exists only while its request still has a `_recving_transfers` entry.
2. `_evict_stale_engines` skips every engine in `_engines_with_inflight_transfers()`, which covers every request in `_recving_transfers`. Cleanup of replaced engines skips any engine with `_recving_metadata`. Invalid-engine cleanup subtracts in-flight transfers too.
3. v0.31.0, the version in #62144, has the same guard (`base_worker.py:3599-3601` there).

So I don't think the "deferred `send_notif` 25 minutes after eviction" in #62144 came from a stale `_pending_recv_notifs` entry. My guess is that a later request re-handshaked with the same prefill engine. The remote agent name is that process's `uuid4`, so it comes back under the same name. In that case `_is_remote_agent_registered` returns True, the notification is sent anyway, and on libfabric it still stalls in `connect()`. This PR doesn't change that path.

The new tests write `_pending_recv_notifs` directly, without a matching `_recving_transfers` entry, which the real code never produces. They show the new helpers work, but not that the bug can happen. The 8xH100 run ("4 of 4 transferred after eviction") would look the same on main.

Could you either:
- show the new debug log (`Dropped N deferred notification(s)...` or `Skipping deferred notification...`) actually firing in your repro, or
- add a test that reaches this state through real code paths?

The one path I found that tears down an engine mid-read without an in-flight check is the registration-generation cleanup in `_read_blocks_for_req`. That may be the right one for the test, although the in-flight read there will probably fail and drop its pending entry on its own. If no real path exists, I'd retitle this as defensive hardening rather than a fix for #62144.

**Smaller points**

- **The cleanup-time drop looks redundant.** Pending entries are tied to their request's lifetime, so there's nothing to leak. The send-time check alone covers the "agent is gone" case, and it is safer if the engine re-handshakes with the same agent name before the read finishes. I'd remove `_drop_pending_recv_notifs`, or tie it to a reachable case.
- **A skipped notification isn't free.** Prefill keeps those KV blocks until the lease expires. Logging only at debug, and having the test assert that `record_failed_notification` is *not* called, hides that from operators. I'd record it with that metric or a new one and log at info.
- **Nit:** `_is_remote_agent_registered` scans every engine's agents under `_handshake_lock` for each notification. A reverse agent-to-engine map would make it O(1). It only runs on the split-read path, so this isn't blocking.


- sohom-cs · COMMENTED · 2026-10-30T03:56:57Z · [source](https://github.com/vllm-project/vllm/pull/62571#pullrequestreview-5707901196)

On @xuechendi's question about a real path: I drove the registration-generation reset in `_read_blocks_for_req` (`pull_worker.py:147-150`) during a split read, with `FakeNixlWrapper`. It removes the engine mid-read. On main the deferred notification then goes to `agent_0`, which was just removed; on this head it's dropped. So that path does reach the state this PR handles.

The same test shows a cost of the cleanup-time drop: if the prefill re-handshakes before the read finishes (same agent names), this head drops a notification that main delivers to the live agent, and P keeps those blocks until the lease expires. With only the send-time check (the drop at `base_worker.py:4082` commented out), both cases pass: no send after the reset, one send after the re-handshake.

<details><summary>The test (paste into test_nixl_connector.py)</summary>

```python
@patch(
    "vllm.distributed.kv_transfer.kv_connector.v1.nixl.base_worker.NixlWrapper",
    FakeNixlWrapper,
)
@pytest.mark.parametrize("reconnect", [False, True])
def test_generation_reset_during_split_read(default_vllm_config, dist_init, reconnect):
    worker, eid = _setup_worker_with_remote_engine(engine_ttl=10.0)
    worker.transfer_topo.block_size_ratio.return_value = 1
    worker.transfer_topo.get_engine_info.return_value = SimpleNamespace(
        remote_block_size=16, remote_physical_blocks_per_logical=1
    )
    worker._engine_by_address[("localhost", 1234)] = eid
    worker.nixl_wrapper._cycles_before_xfer_done = 1  # in flight for one poll
    md = NixlConnectorMetadata()
    for rid, blocks, gen in (("req", ([1, 2],), 0), ("reqB", ([3],), 1)):
        md.add_new_req_to_recv(
            request_id=rid,
            local_block_ids=blocks,
            kv_transfer_params={
                "remote_block_ids": ([5, 6],),
                "remote_engine_id": eid,
                "remote_request_id": f"p-{rid}",
                "remote_host": "localhost",
                "remote_port": 1234,
                "remote_registration_generation": gen,
            },
        )
    worker._recving_metadata["req"] = md.reqs_to_recv["req"]
    worker._recving_transfers["req"] = []
    worker._desc_is_dram_by_block_size = {16: np.array([True, False])}
    worker._desc_pos_by_block_size = {16: np.array([0, 0])}
    worker._read_blocks_mixed(
        request_id="req",
        local_block_size_key=16,
        local_device_handle=20,
        local_dram_handle=10,
        remote_xfer_side_handle=30,
        local_block_descs_ids=np.array([0, 1]),
        remote_block_descs_ids=np.array([5, 6]),
        notif_agent=worker._remote_agents[eid][(0, 0)],
        notif_id=b"p-req:1",
    )
    worker._recving_metadata["reqB"] = md.reqs_to_recv["reqB"]
    with (
        patch.object(worker, "_background_nixl_handshake"),
        patch.object(worker.nixl_wrapper, "send_notif") as send_notif,
    ):
        # reqB carries a new registration generation: the engine is reset mid-read.
        worker._read_blocks_for_req("reqB", md.reqs_to_recv["reqB"])
        assert eid not in worker._remote_agents
        assert worker.get_finished() == (set(), set())
        if reconnect:  # reqB's handshake lands: same process, same agent names
            with worker._handshake_lock:
                worker._remote_agents[eid] = {(0, 0): "agent_0", (0, 1): "agent_1"}
        assert worker.get_finished() == (set(), {"req"})
    if reconnect:
        send_notif.assert_called_once_with("agent_0", notif_msg=b"p-req:1")
    else:
        send_notif.assert_not_called()
```
