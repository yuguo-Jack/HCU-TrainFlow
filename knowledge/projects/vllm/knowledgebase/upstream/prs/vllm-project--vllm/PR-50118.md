# [Bug][KVEvents]: Use effective block size in DCP full KV cache report

[Upstream PR](https://github.com/vllm-project/vllm/pull/50118) · state: open · merged: False

## Original PR description

When decode context parallelism is enabled, the full KV cache report path used the raw physical page size from the cache spec instead of the DCP-effective block size from the manager. This caused an assertion failure in resolve_block_hashes() when a client set kv_cache_report_mode to "full" and a prefix cache hit existed, terminating the EngineCore.

Use manager.block_size (which includes DCP scaling) when emitting BlockStored events for cached prefix blocks in the full-report path.
