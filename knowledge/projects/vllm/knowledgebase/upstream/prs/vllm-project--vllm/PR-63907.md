# [CI] Enroll 4 steps and 2 AMD mirrors in automatic sharding

[Upstream PR](https://github.com/vllm-project/vllm/pull/63907) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Enrolls four NVIDIA steps and two AMD mirrors in `automatic_shard`. `basic-models-tests-extra-initialization` and its AMD mirror move off hand-written fixed shards now that ci-infra#836 lets the planner use up to 10 shards and counts each job's setup in the budget; ci-infra#835 has also merged.

## Claims

| Step | Was | Planned shards |
|---|---|---:|
| `basic-models-tests-extra-initialization` | 14 fixed (`--shard-id`/`--num-shards`) | 10 |
| `amd-basic-models-tests-extra-initialization` | 10 fixed (inherited flags) | 10 |
| `multi-modal-models-extended-generation-3` (nightly) | 1 job | 2 |
| `rust-frontend-openai-coverage` | 1 job | 2 |
| `amd-rust-frontend-openai-coverage` | 1 job | 1 (enrolled so it splits once it grows) |
| `v1-executor-worker` | 1 job | 2 |

- Every test runs exactly once across the shards, with the same commands, `-k` filters and environment as before.
- Basic Models (Extra Initialization) keeps its wall time with four fewer jobs on the NVIDIA side.

## Validation

- Planned each step and mirror with ci-infra main's `runtime_shard.plan_step` against this branch and main's timings.
- Rendered each step and mirror with the pipeline generator and ran every shard's commands against a mock test tree, as a PR build and with main's `pytest -p ci_otel` wrapper: every test of every command ran in exactly one shard (8/8 NVIDIA cases; the Basic Models mirror passed both modes, and the Rust Frontend mirror plans one job).
- Compared every changed step with main: only `automatic_shard`, the `Shard %N` label suffix, `parallelism` and the shard flags differ.
- `/ci run` [97488](https://buildkite.com/vllm/ci/builds/97488) ran all six, the nightly Multimodal step included, at the planned shard counts. Every shard passed, with passed/skipped totals equal to main's ([97560](https://buildkite.com/vllm/ci/builds/97560), [97527](https://buildkite.com/vllm/ci/builds/97527), [97550](https://buildkite.com/vllm/ci/builds/97550)); `v1-executor-worker` is 10 short only because main had since added 10 `test_dsv41_sparse_builders_*` cases. Basic Models (Extra Initialization) used less machine time than main's 14 fixed shards, and every other sharded step finished well ahead of its single job on main.

## Details

- **Basic Models (Extra Initialization).** One file whose tests the planner splits by test function across 10 shards; each planned shard stays under the step's 30-minute timeout. The AMD mirror has no commands of its own and inherits the base command without the shard flags.
- **`v1-executor-worker` log assertion.** `tests/v1/worker/test_worker_base.py` asserts on a log line through vLLM's `caplog_vllm` fixture, which attaches to vLLM's logger directly, so it doesn't depend on which file runs first; in its planned shard about 30 other `v1/worker` files run before it anyway.
- **Timeouts unchanged (human).** As in #62077 and #62120, `timeout_in_minutes` stays per job; fallback-aware timeouts belong in a central timeout setting.
- **Left out.** `v1-executor-worker`'s and the Multimodal step's AMD mirrors run under 20 minutes or have no main runs yet.
