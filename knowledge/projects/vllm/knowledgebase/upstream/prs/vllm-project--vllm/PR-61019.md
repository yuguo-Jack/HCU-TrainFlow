# [Bugfix][KV Connector] Serve and store OffloadingConnector partial tails with EAGLE/MTP groups

[Upstream PR](https://github.com/vllm-project/vllm/pull/61019) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

The native CPU `OffloadingConnector` serves no partial tail when a model has an EAGLE/MTP draft group and `mamba_cache_mode="align"`. Every host-tier hit therefore ends on a scheduler-block boundary, and the tokens after that boundary are recomputed. This PR ports the EAGLE proof key of #60695 (Mooncake) to the offloading scheduler, so tails are looked up at the proof position (commit 1). It also fixes the store gate, so the tail is actually stored on the CoW hand-off step (commit 2). Related: #60533 (core proof), #52832 (producer partial tails).

**Draft:** the CUDA unit tests pass, but the end-to-end serving A/B is negative on our workload (see Validation). Not ready.

## Claims

- On a hybrid attention + align-Mamba model with EAGLE/MTP block drop, a host-tier lookup can hit the prompt's Mamba checkpoint at `prefix_match_unit` granularity, as the GPU prefix cache already does. Before this change it could hit only whole scheduler blocks, minus one more block for the EAGLE pop.
- The EAGLE group's tail block is keyed at `boundary + eagle_proof_margin` (one hash unit), the same proof that core uses since #60533. The Mamba groups and the non-EAGLE groups stay keyed at the boundary.
- The tail is stored on the step that computes the proof. The old gate compared against `num_computed_tokens` before the step, so it always skipped the one-time CoW hand-off.
- No change without an EAGLE group, or where partial tails are unsupported (DCP > 1, `blocks_per_chunk > 1`, mixed block sizes, sliding-window groups).

## Details

**Root cause 1 (lookup).** `SchedulerOffloadConfig.from_spec` set `supports_partial_tail = False` when any group was an EAGLE group. The complete-chunk lookup queries one extra chunk for an EAGLE group and then pops it. So the hit ended one scheduler block before the last stored chunk, and no partial tail was tried.

**Root cause 2 (store).**
1. With EAGLE block drop, core stops the prefill at the Mamba checkpoint T = floor(P/h)·h − h.
2. On the next step (tokens T..P), the CoW copies the state, and the manager hands `(group, cow_block, T)` to the connector one time.
3. The scheduler builds the connector metadata before `_update_after_schedule`, so `num_computed_tokens == T` at that point.
4. The gate `boundary + margin > num_computed_tokens` is therefore `T + h > T`, which is always true, and the hand-off is never offered again.

**Fix.**
- Remove the EAGLE exclusion from `supports_partial_tail`.
- Key the EAGLE non-recurrent groups at `boundary + margin` in the store, the lookup and the load.
- Widen the partial search by one block, with bridge keys for the popped chunk.
- Judge the proof against `min(num_computed_tokens + num_scheduled_tokens[req_id], num_prompt_tokens)`.

This is safe because stores are only queued in `wait_for_save` and are submitted at the start of the next step. The CPU transfer stream waits on the compute stream at submission, so the copy runs after this step's forward wrote the proof block. A job created in this step cannot be in this step's flush set. The cap at the prompt length keeps the proof out of speculative tokens.

**Difference from #60695.** Mooncake stores one key per hash unit. The native connector stores whole chunks and keeps its chunk-level EAGLE pop for complete chunks, so only the partial-tail key of EAGLE groups changes.

**Limitations.**
- If the token budget stops the hand-off step before `T + h`, the tail is not stored. That cannot happen at the prompt tail when `max_num_batched_tokens ≥ 2h`.
- The wider search adds up to `block_size / tokens_per_hash` probes per lookup, and only when an EAGLE group exists.
- Existing CPU caches hold no EAGLE tails, so no migration is needed.

**Size:** `offloading/scheduler.py` +162 / −35 (no core files changed); tests +224 / −9.

## Summary

This pull lets the CPU offloading connector store and serve partial tails when a model has an EAGLE or MTP draft group. The pull is marked as a draft. We found two serious and two smaller findings. The most important problem is that a hand-off skipped because the proof is not yet computed is never offered again, so that tail is never stored.

## Serious findings

**1. A skipped hand-off is lost for good [offloading/scheduler.py]**
When the EAGLE proof has not been computed by the end of the step, the code skips the copy-on-write hand-off for that step. The hand-off is created once and cleared the next time pending hand-offs are drained, so nothing retries it and that tail is never stored.
*Change:* Defer the hand-off until the proof is computed instead of dropping it.

**2. EAGLE configs double the partial-tail lookups on every request [offloading/scheduler.py]**
With an EAGLE proof margin the search covers two blocks instead of one, which doubles the boundary iterations. Each boundary also probes extra bridge keys before the per-group lookups, which adds lookups and host-to-GPU bridge loads on a path that runs for every request.
*Change:* Avoid paying the extra lookup cost on every request, for example by only probing the second block or the bridge keys when they can change the result.
