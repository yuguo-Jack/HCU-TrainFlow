# [Bugfix][Frontend] Preserve errors before the first streamed chat token

[Upstream PR](https://github.com/vllm-project/vllm/pull/59170) · state: closed · merged: False

## Original PR description

Only skip empty prefill chunks when finish_reason is unset. An empty terminal error must reach the existing error handler instead of yielding an apparently successful stream with no tokens.

Parameterize the existing streaming error test to cover failures both before and after generated tokens. The recorded compatible-runtime validation passed both streaming cases and the non-streaming case.



## Purpose

Fix silently dropped errors in streaming chat completions when generation fails before producing any tokens.

The empty-prefill check currently skips outputs with no text, no token IDs, and no previously generated tokens, regardless of `finish_reason`. This also discards empty terminal outputs with `finish_reason="error"`, bypassing the existing error handler. Clients can receive an apparently successful stream ending with `[DONE]` but no generated tokens or error information.

Only skip empty prefill chunks when `finish_reason is None`. Terminal errors then reach the existing handler and produce an SSE `InternalServerError` with code `500`, followed by `[DONE]`. The HTTP status may remain `200` because the streaming response has already started.

Parameterize the existing streaming error test to cover failures both before and after generated tokens.

Public search found a duplicate of this fix: #40986, which has been open for months. Commented and waiting for reply.

## Test Plan

Run the focused regression tests:

```bash
.venv/bin/python -m pytest -q \
  tests/entrypoints/openai/chat_completion/test_chat_error.py \
  -k "test_chat_error_stream or test_chat_error_non_stream"
```

Verify that:

- Errors before the first generated token appear in the stream.
- Errors after generated tokens continue to appear in the stream.
- Both streaming cases end with `[DONE]`.
- Non-streaming error handling remains unchanged.

This covers both parameterized streaming cases and the existing non-streaming case.

Fault-injection validation also confirmed:

| Scenario | Before | After |
| --- | --- | --- |
| Streaming failure before the first token | HTTP 200, no generated tokens, `[DONE]`, no error event | SSE `InternalServerError` with code `500`, followed by `[DONE]` |
| Non-streaming failure | HTTP 500 | HTTP 500 |

Validation used compatible vLLM revision `84030bbe3d74d99bad477a3d2e37a973ccd8865c` with the fix applied. An isolated test copy used a local tokenizer because downloading the original GPT-2 tokenizer was blocked. The committed tests retain the original fixture.

These results do not constitute a test run on the exact PR baseline. No model-quality benchmark was run for this API error-propagation change.
