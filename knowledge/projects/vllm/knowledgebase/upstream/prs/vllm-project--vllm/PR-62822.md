# [Rust Frontend] Carry return_token_ids through render like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/62822) · state: closed · merged: True

## Original PR description

## Overview

Since vllm-project/vllm#62449, Python's `/v1/chat/completions/render` and `/v1/completions/render` copy the request's `return_token_ids` onto the rendered `GenerateRequest` (`vllm/entrypoints/scale_out/render/serving.py`). The Rust frontend's `lower_render_request` (`rust/src/server/src/routes/render.rs`) always sets `return_token_ids: None`, so a client that asks render for token IDs gets none back from `/inference/v1/generate`. This PR carries the field through.

## Claims

- On the Rust frontend, render output carries the request's `return_token_ids`. Submitting it to `/inference/v1/generate` returns `prompt_token_ids` (and output token IDs), as on Python and as `/v1/chat/completions` and `/v1/completions` do.

## Validation

Commands from `.buildkite/scripts/run-rust-frontend-cargo-ci.sh` (`style-clippy` and `test`), run from the repo root:

```
cargo fmt --manifest-path rust/Cargo.toml --all -- --check   # ok
cargo sort --workspace --check rust                          # ok

cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --all-features --locked -- -D warnings   # ok
cargo nextest run --manifest-path rust/Cargo.toml --workspace --all-features --locked --no-fail-fast
# 2222 tests run: 2222 passed, 13 skipped
```

- `render_completion_returns_generate_request_with_body_request_id` now asserts that render output carries the field, and the round trip `render_chat_response_can_be_submitted_to_generate_unchanged` asserts that generate echoes `prompt_token_ids` equal to the rendered token IDs. Both fail with the production change reverted.

## Details

The consumer is the generate route (`routes/inference/generate/convert.rs`), which already echoes prompt and output token IDs when `return_token_ids` is set; render only has to emit it. Both render handlers read the field from the request body and pass it to `lower_render_request`, which sets it next to the other request-level fields it copies (`stream`, `stream_options`, `cache_salt`).

Not a duplicate: no open upstream PR changes the Rust render lowering.
