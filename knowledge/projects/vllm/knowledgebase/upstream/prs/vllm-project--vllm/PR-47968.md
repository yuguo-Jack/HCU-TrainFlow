# [Bugfix][Tool Parser] Return early for unlisted tool names in InternLM2 parser

[Upstream PR](https://github.com/vllm-project/vllm/pull/47968) · state: open · merged: False

## Original PR description

## Purpose

In the InternLM2 tool parser's non-streaming `extract_tool_calls`, when the
parsed tool name is not among the request's `tools`, the code builds an
`ExtractedToolCallInformation(tools_called=False, ...)` but never returns it.
Execution falls through and the unlisted tool is emitted as a real tool call
anyway, so a hallucinated / unlisted tool name bypasses the tool whitelist.

```python
if not tools or name not in [t.function.name for t in tools]:
    ExtractedToolCallInformation(tools_called=False, ...)   # built, never returned
# ... falls through and returns tools_called=True
```

## Fix

- Add the missing `return`.
- Change the condition from `not tools or` to `tools and` so the whitelist is
  only enforced when tools are actually provided. The batch API constructs the
  parser with `tools=None` (`batch_serving.py`), and returning early on an empty
  tool list would otherwise drop every tool call in batch mode.

Net behavior:
- tools provided + unlisted name -> not emitted (the fix)
- tools provided + listed name -> emitted (unchanged)
- no tools provided (batch) -> emitted (no regression)

## Test

Adds regression tests to `tests/tool_parsers/test_internlm2_tool_parser.py`
covering all three cases above.
