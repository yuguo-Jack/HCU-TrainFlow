# [Bugfix] Resolve HF paths when loading sharded state

[Upstream PR](https://github.com/vllm-project/vllm/pull/61380) · state: open · merged: False

## Original PR description



## Overview

Fix loading sharded checkpoints from Hugging Face repository IDs. `load_weights()` previously treated the repository ID as a local path, causing shard lookup to fail.

## Claims

- Support HF repository IDs supplied through either `model` or `model_weights`.
- Honor the configured revision, download directory, and ignore patterns.
- Preserve existing handling for local directories and S3 paths.

## Validation

Added one parameterized regression test covering local checkpoints, HF repository IDs, and `model_weights` overrides. It uses real safetensors weights and mocks HF downloads and distributed parallel-state accessors.

- New regression cases before the fix: **2 failed, 1 passed**.
- Selected CPU tests after the fix, including all three regression cases: **28 passed, 6 deselected**.
- All applicable pre-commit hooks passed.

```bash
.venv/bin/python -m pytest \
  --confcutdir=tests/model_executor/model_loader \
  tests/model_executor/model_loader/test_sharded_state_loader.py \
  -k 'filter_subtensors or default_pattern or save_model or resolves_checkpoint_path' -q

pre-commit run --files \
  vllm/model_executor/model_loader/sharded_state_loader.py \
  tests/model_executor/model_loader/test_sharded_state_loader.py
```

Full GPU integration, live HF downloads, and the RunAI backend were not tested locally.

## Details

Resolve the selected weight source using the existing `_prepare_weights()` method before searching for shard files. This converts HF repository IDs into local snapshot paths while retaining the existing handling for local directories and S3 paths.
