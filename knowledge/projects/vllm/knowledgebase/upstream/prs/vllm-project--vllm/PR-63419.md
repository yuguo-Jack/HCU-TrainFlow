# [ROCm] Migrate Aiter sigmoid to topk_gating

[Upstream PR](https://github.com/vllm-project/vllm/pull/63419) · state: closed · merged: True

## Original PR description

## Overview

ROCm vLLM CI should succeed with `VLLM_ROCM_USE_AITER=1`, since most `vllm serve` commands run with that env var. This PR routes Aiter sigmoid calls to `rocm_aiter_ops.sigmoid_gating` instead of `rocm_aiter_ops.topk_sigmoid` when applicable. This is useful because 

+ Aiter will soon deprecate `topk_sigmoid`
+ `rocm_aiter_ops.sigmoid_gating` supports renormalize

## Validation

The test
```bash
VLLM_ROCM_USE_AITER=1 pytest tests/kernels/moe/test_fused_topk.py::test_fused_topk -k sigmoid
```
now succeeds. Without this PR -- without renormalization -- the test fails with the 96 error messages
> AssertionError: Tensor-likes are not close!

## Details

`rocm_aiter_ops.topk_gating` already supports sigmoid, so similarly to how softmax is routed to `topk_gating`, sigmoid is routed to `topk_gating`.

Heads up: green CI doesn't say much here, because the AMD MoE jobs don't set `VLLM_ROCM_USE_AITER=1`.

On main, legacy `aiter.topk_sigmoid` is actually broken at v0.1.26 (`SyntaxError` in `check_args`, fixed by ROCm/aiter#6834 after the tag), so every sigmoid case fails, not just the renorm ones. With this PR, `-k "sigmoid and not bias"` passes 10/10 loops and AITER=0 is clean.

For a model: LFM2-8B-A1B with `--hf-overrides '{"use_expert_bias": false}'` goes through this router. gsm8k 5-shot (strict):

| | gsm8k |
|---|---|
| this PR | 0.836 |
| AITER=0 | 0.835 |
| renorm dropped | 0.695 |
| main | crashes at startup |

Serving perf matches native routing, and at the kernel level topk_gating is ~1.3-1.7x faster than `vllm_topk_sigmoid`.

The main thing left is the fallback (see L151). Minor: the description says `sigmoid_gating` but the method is `topk_sigmoid_gating`, and I couldn't find a source for the deprecation note.
