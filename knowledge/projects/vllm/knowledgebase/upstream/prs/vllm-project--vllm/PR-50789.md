# Fix/nixl lease reaper ordering

[Upstream PR](https://github.com/vllm-project/vllm/pull/50789) · state: closed · merged: False

## Original PR description

## Purpose

`NixlBaseConnectorWorker.get_finished()` reclaims expired KV leases by inspecting only the **head** of `_reqs_to_send` and breaking at the first unexpired entry. That is sound only if the dict is ordered by ascending expiry. It is not, for two independent reasons:

1. **Heartbeats renew in place.** `_handle_heartbeat()` extends a lease with `self._reqs_to_send[req_id] = max(old, new_expiry)`. A renewed entry therefore keeps a stale position while holding a far-future deadline, and the early `break` fires before the scan reaches the already-expired entries behind it.

2. **Two independent TTLs share the map.** `pull_scheduler` stamps `kv_lease_duration` (default 30s) for P-side leases and `decoder_kv_blocks_ttl` (default 480s) for D-cached blocks in bidirectional mode into the same `_reqs_need_send`, which flows to the worker via `meta.reqs_to_send`. A 480s entry inserted ahead of a 30s entry breaks the ordering with **no heartbeat involved at all**.

Either way the blocks are never released. On P that also holds the associated request-plane slot, so a worker can end up refusing new work while its GPU sits idle.

This change drops the ordering assumption instead and scans the whole map.

**Not a duplicate:** no open PR addresses the reaper's iteration order. #46289 (reclaim blocks leaked by aborted remote recv) and #43509 (`best_of_n` KV leak / early-notification race) are different leak paths; #41383 is the feature that introduced this hazard; #35764 is a closed alternative lease-refresh design that independently chose "a full scan (not early-break) in `get_finished` since expiry order may change."

## Test Plan

Two regression tests in `tests/v1/kv_connector/unit/test_nixl_connector.py`, both driving the **real** `get_finished()` via `FakeNixlConnectorWorker` (modelled on the adjacent `test_reqs_to_send_deadline_rebased_to_worker_clock`), one per cause above:

- `test_expiry_sweep_reclaims_lease_behind_a_renewed_one` — real `_handle_heartbeat()` renews the head entry to a deadline that is still *earlier* than another outstanding one; asserts the expired entry behind it is reclaimed.
- `test_expiry_sweep_reclaims_short_lease_behind_a_longer_ttl` — a 480s entry inserted ahead of a 30s entry, driven through the real `start_load_kv` via `metadata.reqs_to_send`/`metadata.scheduler_clock`; asserts the short lease is reclaimed. No heartbeat involved.

Both were confirmed to **fail before the fix and pass after** — a test that passes either way would not pin this invariant.

`test_handle_heartbeat_keeps_reqs_to_send_ordered_by_expiry` is **deleted**: it asserted the invariant being removed and re-implemented the production loop inline. Replaced with `test_handle_heartbeat_never_shortens_a_lease`, which pins the `max()` semantics that `docs/design/nixl_kv_cache_lease.md` documents.

```bash
pytest -v tests/v1/kv_connector/unit/test_nixl_connector.py
pytest -v tests/v1/kv_connector/unit/test_nixl_heartbeat.py
```
