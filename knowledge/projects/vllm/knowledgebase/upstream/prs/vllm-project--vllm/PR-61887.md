# [ROCm] Rebuild rocprofiler-sdk with the split-lock fix

[Upstream PR](https://github.com/vllm-project/vllm/pull/61887) · state: closed · merged: False

## Original PR description

`Dockerfile.rock_base` cherry-picks [ROCm/rocm-systems#12089](https://github.com/ROCm/rocm-systems/pull/12089) so the ROCm 10 wheel's rocprofiler-sdk no longer bus-locks while the torch profiler reuses HSA signals. Fixes #61896.

## Overview

Replace `librocprofiler-sdk.so.1` with a build of `ROCM_RUNTIME_COMMIT` plus `86dd3bab5b`, until the ROCm 10 wheel contains that commit.

## Claims

- On one MI350X, ROCm 7.2.3 has no idle after kernel 7. The ROCm 10 hole drops by about 2–4× after the library swap. With the profiler on, a 2048-kernel replay goes from 7.50 ms to 7.09 ms, against 6.87 ms on ROCm 7.2.3. The kernel-7 idle is 13% of the profiler-on gap before the swap and 4–5% after.
- Stock `pool<signal_t>::m_buffer` at `0xba7514` is 4-byte aligned; the rebuilt library aligns it so `m_reused` stays inside one cache line.

## Validation

`HIP_VISIBLE_DEVICES=0`. The two stock columns are the nightlies built from the same vLLM commit, `3f1bcfd82bb2e93fcd364fc7a5491718453a77e2`: ROCm 7.2.3 `nightly-3f1bcfd82bb2e93fcd364fc7a5491718453a77e2` and ROCm 10 `nightly-rocm100-3f1bcfd82bb2e93fcd364fc7a5491718453a77e2`.

Overlay is an older ROCm 10 nightly, `nightly-rocm100-36768d1bfd39094681cdbc8cb37d4b31c0729c89`, not a vLLM rebuild: only the real `librocprofiler-sdk.so.1` is replaced with rocprofiler-sdk built from `ROCM_RUNTIME_COMMIT` plus `86dd3bab5b`. Everything else in that image stays the nightly bits. This PR is that same replacement inside `docker build -f docker/Dockerfile.rock_base --target final`. Probe is in #61896.

Idle after kernel 7 of each of two replays:

| N | ROCm 7.2.3 | ROCm 10 | ROCm 10 overlay | This PR |
|---:|---|---|---|---|
| 256 | ~0 µs | 56 µs, 482 µs | 69 µs, 84 µs | 48 µs, 53 µs |
| 512 | ~0 µs | 517 µs, 591 µs | 157 µs, 182 µs | 157 µs, 136 µs |
| 2048 | ~0 µs | 540 µs, 523 µs | 116 µs, 164 µs | 142 µs, 175 µs |

One replay, median of 7. Wall time is `profiler off→on (+overhead)`. Idle share is shown as `7.2 / 10.0 / PR`; it is approximate because wall time and idle come from different replays.

| N | ROCm 7.2 wall (ms) | ROCm 10.0 wall (ms) | This PR wall (ms) | Idle share: 7.2 / 10.0 / PR |
|---:|---|---|---|---|
| 256 | 0.43→0.88 (+105%) | 0.43→1.43 (+233%) | 0.43→1.07 (+149%) | ~0 / 6–48% / 8% |
| 512 | 0.85→1.73 (+104%) | 0.86→2.27 (+164%) | 0.85→1.93 (+127%) | ~0 / 37–42% / 13–15% |
| 2048 | 3.36→6.87 (+104%) | 3.39→7.50 (+121%) | 3.37→7.09 (+110%) | ~0 / 13% / 4–5% |

Most profiler overhead is present on ROCm 7.2.3 too. At N=2048 the raw ROCm 10 idle is 13% of that overhead; after this PR it is 4–5%.

CI does not build this base image. The run above is the check.

## Details

`static_object` placement-new'd `pool<signal_t>` into an unaligned byte buffer ([ROCm/rocm-systems#9639](https://github.com/ROCm/rocm-systems/issues/9639)). `m_reused` is `lock incq 0xe8(pool)`. At `mod 64 = 20` that atomic starts at byte 60 and crosses the cache line. The increment runs once a profiled kernel reuses a signal, which is the second graph replay. The core/devel symlink for the rocprofiler SONAMEs stays; the new file is installed on the devel copy those links follow. Drop the stage when the wheel ships ROCm/rocm-systems#12089.
