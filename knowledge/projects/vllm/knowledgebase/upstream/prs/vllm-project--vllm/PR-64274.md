# [Rust Frontend] Reject chat templates for native renderers

[Upstream PR](https://github.com/vllm-project/vllm/pull/64274) · state: closed · merged: True

## Original PR description



## Overview

Native Rust chat renderers (DeepSeek V3.2/V4/V4.1, Harmony, Inkling, Kimi K3) do not render Jinja templates, but they silently ignored `--chat-template` and a request's `chat_template`. This PR rejects both instead: startup fails for the flag, and the request returns 400.

## Claims

- `--chat-template` with a resolved renderer other than `hf` fails at startup, naming the renderer and pointing to `--tokenizer-mode hf`.
- A request `chat_template` on a renderer other than `hf` returns 400 with `param: "chat_template"`.
- The `hf` renderer is unchanged: a request template still goes through the `--trust-request-chat-template` check.

## Validation

- `cargo nextest run -p vllm-chat -p vllm-server -p vllm-cmd --locked`: 1118 of 1119 passed. The one failure, `roundtrip_mimo_v26` (grammar replay snapshot), also fails on `main` at `ab0e5ef795` without this change.
- `cargo clippy -p vllm-chat -p vllm-server -p vllm-cmd --lib --bins --tests --locked -- -D warnings` and `cargo fmt --all --check`: passed.
- `backend::hf::tests::only_hf_renderer_accepts_chat_template` covers both rejections and the unchanged `hf` path. Disabling either check makes it fail: the startup check returns `Ok`, and the request renders with the DeepSeek V4 encoder.

## Details

The startup check sits where `--tokenizer-mode` resolves the renderer. The request check uses a provided `ChatRenderer::renders_request_chat_template()` method that defaults to `false`, with `HfChatRenderer` returning `true`, so a new native renderer rejects request templates without opting in. `ChatRequestProcessor` checks it once before rendering, which covers chat completions, `/render`, and `/tokenize`.

Python is inconsistent here: Mistral rejects a request `chat_template` (`vllm/tokenizers/mistral.py`), while the DeepSeek tokenizers ignore it. This follows the Rust frontend's rule to reject behavior it does not implement. No recipe combines `--chat-template` with a native renderer.

This also replaces the GLM-only checks in vllm-project/vllm#62424, which used `ChatTemplateThrown` (meant for a template's `raise_exception`); that PR drops them.
