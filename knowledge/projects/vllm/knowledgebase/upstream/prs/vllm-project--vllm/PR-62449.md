# [Bugfix][Frontend] Return prompt token IDs from derender when requested

[Upstream PR](https://github.com/vllm-project/vllm/pull/62449) · state: open · merged: False

## Original PR description

## Overview

Derender now returns `prompt_token_ids` when the request sets `return_token_ids`, matching `/v1/chat/completions` and `/v1/completions`. This follows #61065 and #62114 which did the same for the generated `token_ids`.

## Claims

- Chat derender returns `prompt_token_ids` on the response in batch and stream
- Completion derender returns it on each choice in batch and stream
- `/render` now copies `return_token_ids` onto the `GenerateRequest`, so generate actually sends the prompt IDs back
- Nothing changes when `return_token_ids` is unset or false

## Validation

```bash
pytest tests/entrypoints/scale_out/render/test_render.py -v
pytest tests/entrypoints/scale_out/derender/test_derender.py -v
```

- `test_render_forwards_return_token_ids` checks that chat and completion render pass the flag on
- `test_derender_chat_returns_requested_prompt_token_ids` checks chat batch and stream over HTTP
- `test_derender_completion_preserves_requested_token_ids` (from #62114) now checks `prompt_token_ids` too

This only adds response fields when the client asks for them. Model output doesn't change, so I didn't run evals.

## Details

There were two gaps. `/render` never set `return_token_ids` on the `GenerateRequest`, so generate didn't return the prompt IDs. Derender also never put them on its responses.

Derender takes the prompt IDs from the generate response. It doesn't echo the `prompt_token_ids` the caller sent because the docs let that be just the end of the prompt (seeding only reads the last 7 IDs). Generate only sends prompt IDs on its first stream chunk, so the stream paths pass them straight through.

Not covered here:

- Responses API render which has no `return_token_ids`
- `echo`
- Streaming completions with `n > 1`. Only the first choice gets the prompt IDs while the coupled endpoint repeats them for every choice
