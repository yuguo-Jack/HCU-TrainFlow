# [Bugfix][DSV4.1] Warm DeepGEMM mHC projection specializations

[Upstream PR](https://github.com/vllm-project/vllm/pull/57843) · state: open · merged: False

## Original PR description

## Purpose

DSV4.1 can compile a DeepGEMM mHC prenorm projection during intermediate prefill because decode and maximum-prefill startup runs miss a reachable split count. Register the projection's input widths and reachable split counts with JIT warmup, then execute one dummy row per specialization. Token count is dynamic in this kernel, so large prefill buffers are unnecessary.

Extracted unchanged from #57643, where the implementation, registration, and tests have been removed. This fix is independent of all-reduce fusion and of the FlashInfer cached-tactic warmup in #57842. Open-PR checks found #51802 and #49707 addressing DeepSeek V4 TileLang warmup; neither implements this DSV4.1 DeepGEMM projection warmup.

## Validation

```bash
.venv/bin/python -m pytest tests/kernels/test_mhc_jit_warmup.py -q -rs
```

- 30 tests passed; pre-commit passed.
- Fresh-cache GB200 check compiled six specializations (widths 5120/20480, splits 1/4/16), then exercised 26 runtime shapes from 1 to 8192 tokens with subsequent compiler invocations forbidden. No runtime compilation occurred; projection and squared-sum results matched their references exactly.
- GPU validation used retained allocation 29900 on gb200-rack1-04 with `srun --overlap`.
- No model arithmetic changes or new model accuracy evaluation. The earlier combined real-model evaluation remains documented in #57643; it is not an isolated evaluation of this startup-only fix.

AI assistance was used for extraction and validation.
