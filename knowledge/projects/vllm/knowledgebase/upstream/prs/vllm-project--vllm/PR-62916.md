# [Bugfix][KV Connector] Synchronize engine IDs across PCP ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/62916) · state: open · merged: False

## Original PR description

## Overview

Synchronize KV transfer engine IDs across PCP ranks before the existing PP broadcast. This draft addresses a multi-node startup failure observed with PP2/PCP8/TP2; hardware validation is pending.

## Claims

- Workers in a TP/PCP/PP model-parallel instance converge on the ID from TP0/PCP0/PP0 before connector construction.
- PCP=1 retains the existing broadcast path, and synchronization does not cross DP engine boundaries.
- No new unit tests are included. This remains a draft until the distributed serving reproducer is validated.

## Validation

Pending validation.

## Details

Each node can construct its own KV transfer configuration. With PP2/PCP8/TP2 on four 8-device nodes, initial IDs A/B/C/D remain A/B/A/B after the existing TP and PP broadcasts. A connector that validates worker identities, such as Ascend Mooncake V2, rejects this metadata before serving starts.

Broadcasting across PCP between TP and PP instead gives A/B/C/D -> A/A/C/C -> A/A/A/A. This selects the same model-parallel origin without generating a new ID or broadcasting across DP. The additional object collective runs only during connector initialization when PCP>1, not in the token-generation loop.

Duplicate-work check: searched open PRs for `_sync_engine_id_across_tp`, PCP engine IDs, and engine-ID synchronization. No matching PCP synchronization fix was found. #39276 addresses global versus local DP suffixes and MoRIIO behavior; #43366 addresses NIXL PP support. Neither changes this PCP broadcast. Related Ascend workarounds: https://github.com/vllm-project/vllm-ascend/pull/19398 and https://github.com/vllm-project/vllm-ascend/pull/19399.
