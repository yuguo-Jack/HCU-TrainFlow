# [Quant] ModelOpt W4A16 NVFP4: fix layerwise reload

[Upstream PR](https://github.com/vllm-project/vllm/pull/62036) · state: open · merged: False

## Original PR description



## Overview

Fixes layerwise reload (`initialize_layerwise_reload` → `load_weights` → `finalize_layerwise_processing`) for ModelOpt checkpoints with W4A16 NVFP4 layers (`W4A16_NVFP4`, or `MIXED_PRECISION` with W4A16 layers).

This is one self-contained part of #62017 by @aoshen02, split out unchanged for separate review. The commit keeps his authorship. An earlier revision was reviewed as aoshen02/vllm#90.

## Claims

- During a layerwise reload, a W4A16 NVFP4 layer is processed as soon as its weights arrive. Its `input_scale` placeholders no longer hold the whole layer back until finalize.
- A deprecated `input_scale` that arrives after the layer was processed is ignored. Without this, it would raise `ValueError` in `AutoWeightsLoader` or `AttributeError` in `RoutedExperts`.
- FP8 layers are unchanged: their input scales still load, and reload still waits for them. Cold loading and kernels are unchanged.

## Validation

New test `test_modelopt_w4a16_reload_ignores_legacy_input_scale[late=False|True]` (CUDA):
- Builds a toy model with one W4A16 and one FP8 `ReplicatedLinear` under a mixed-precision config.
- Reloads it layerwise, with the deprecated `input_scale` arriving before (`late=False`) or after (`late=True`) the W4A16 layer's weights.
- Checks that the W4A16 layer is processed without its `input_scale`, the FP8 layer still waits for its own, and the reloaded state dict equals the cold-loaded one.

## Details

Root cause: weight-only NVFP4 checkpoints carry no `input_scale`, or a deprecated one. vLLM still registers `input_scale` placeholders for W4A16 layers: `w13_input_scale` and `w2_input_scale` on routed experts, and linear layers through `_DropInputScale`. That causes two problems.

1. **Reload never processes the layer early.**
   - Layerwise reload processes a layer once the numel it has loaded reaches the layer's total. The placeholders count toward that total, but the checkpoint never fills them.
   - So every W4A16 layer stays deferred until finalize and keeps all its staged tensors alive. On Nemotron-H Lightning NVFP4 (128 experts) this was 16.5 GiB extra on one GPU during a weight update (measured in aoshen02/vllm#90).
   - Fix: set `weight_loader_numel = 0` on those placeholders. Only the reload trigger reads this attribute.
2. **A late `input_scale` raises.**
   - With (1), a deprecated `input_scale` in a later weight bucket arrives after the layer was processed and `input_scale` was dropped.
   - Fix:
     - ModelOpt configs with W4A16 layers add `.input_scale` to `_ignore_unexpected_suffixes`. That list is only consulted when the parameter is absent, so FP8 input scales still load.
     - `RoutedExperts` skips a missing `input_scale` for NVFP4 W4A16 MoE.

`base_config.py` only gains a type annotation, so that the subclass override type-checks.

Tradeoff: in a mixed-precision checkpoint the ignored suffix applies to the whole config. An `input_scale` that matches no parameter, such as a misnamed FP8 one, is then dropped instead of raising. This is noted in the code.
