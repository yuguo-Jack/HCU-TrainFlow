# [KV Connector][NIXL] Pull KV from pipeline-parallel prefill stages, with the hybrid KV cache manager

[Upstream PR](https://github.com/vllm-project/vllm/pull/64397) · state: closed · merged: False

## Original PR description



## Overview

The pull `NixlConnector` reads KV from a prefill instance with `--pipeline-parallel-size > 1` into a PP=1 decoder, including attention-only hybrid KV cache layouts (HMA). Addresses #52913 (item 3 of #60791). Builds on #63416 (pair NIXL regions by layer, now on main as 8b55f9195a), whose pairing it reuses; against main the diff is this PR's 8 files.

## Claims

- A PP=1 decoder pulls from a PP-sharded prefiller: it handshakes with every prefill stage, pairs each stage's regions with the local regions that hold the same layers, and reads each layer from the stage that holds it. On main the pull path reads only PP rank 0's descriptors, and the handshake with a stage fails because `_pair_regions` requires the peer to hold every local layer.
- With HMA, a stage reads only the cache groups it holds layers of. A stage that holds no layer of any group a request has blocks in is not read, only notified, so it frees the request's blocks.
- `NixlConnector` (pull) no longer refuses `pipeline_parallel_size > 1` with HMA, except for MLA and CSA-linear caches, which keep raising at startup.
- A worker decides whether HMA is required from its KV cache groups' specs, not from the layers it holds. A PP stage can hold no layer of a group while requests still carry that group's blocks; the scheduler already decides from the groups.
- GSM8K through the pull connector with a PP2 prefiller matches the decode-only baseline for a dense model and an HMA model (7 KV cache groups), with 0 NIXL failures.

## Details

Request flow, P = TP1×PP2, D = TP1:

1. P's scheduler returns `kv_transfer_params` with `pp_size=2` (already on main). Each P stage holds the request's blocks for its own layers.
2. D's handshake queries `(pp_rank, tp_rank)` for every stage (already on main). For each stage, `_add_remote_pp_stage` pairs the stage's regions with the local regions of the same layers (`_pair_regions(..., remote_pp_stage=True)`) and keeps the pairs, the stage's region block counts and its descriptor handle per remote TP rank. Once every stage is known, it checks that each local layer is held by exactly one stage.
3. D's `_read_blocks_for_req` posts one READ per source TP rank and stage, with that stage's pairs, handle and notification agent.
4. Each P stage frees the request's blocks when its own notification arrives.

Limitations, each refused with an error: decode-side PP; Mamba/SSM hybrids, DCP and mixed-memory KV caches under a PP prefiller; MLA and CSA-linear caches under HMA; layers in different KV cache groups on the two sides.

Changing how HMA is decided also affects push PP stages: a stage holding only full-attention layers of an HMA model now runs push's HMA checks (equal block sizes, decode TP no greater than prefill TP) like the other stages.

**Not a duplicate.**
- #53360 also lifts the pull PP guards. It pairs each stage region with one local region by the region's first layer; when layers of several groups share a region, that copies one group's KV into another group's pages. It has been inactive since 2026-09-03 and conflicts with main. This change reuses #63416's pairing by layer instead.
- #63416 changes how regions pair, not which topologies are allowed; this is the PP part on top of it.
- #64127 fixes push with a PP prefiller for indexer layers, which is unrelated to pull.
