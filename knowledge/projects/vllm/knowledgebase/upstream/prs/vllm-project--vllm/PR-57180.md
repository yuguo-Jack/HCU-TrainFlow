# [Bugfix][Spec Decode] Reuse saved Mamba prompt tails with MTP

[Upstream PR](https://github.com/vllm-project/vllm/pull/57180) · state: closed · merged: False

## Original PR description

## Purpose

Fix repeated prompts missing a saved Mamba prefix-cache checkpoint with EAGLE/MTP.

There are two mismatches:

1. **Lookup:** the coordinator caps the proof scan at the reusable-token limit (`request.num_tokens - 1`). Attention lookup then drops another hash unit for speculative replay. With a 16,000-token prompt and 16-token hashes, this can stop at 15,968 and miss the saved Mamba checkpoint at 15,984. Allowing the scan through token 16,000 lets the existing drop land on 15,984.
2. **Registration:** when only attention groups are marked as draft groups, Mamba partial-tail registration uses its per-group `use_eagle` flag while the scheduler uses the global `drop_eagle_checkpoint_block` flag. The saved state and its registered boundary can disagree.

This change gives attention lookup its extra proof margin, bounded by the request's available hashes, in both reconciled and per-group connector lookup. Mamba receives no extra margin because its finder does not drop a unit. Mamba tail registration uses the scheduler's global flag. The returned reusable hit stays within the caller's limit, and the speculative proof drop remains enabled.

### Attribution and related work

Builds on work by Brian Yu, with expanded regression coverage.

Related upstream [PR #53802](https://github.com/vllm-project/vllm/pull/53802) addresses the boundary mismatch by moving checkpoint registration to positions reachable under the existing lookup cap. This patch instead preserves the saved replay checkpoint and corrects the proof-scan cap, and aligns Mamba registration with the global draft setting. This proposes an alternative at the lookup boundary, rather than the checkpoint-placement approach in #53802; the overlap is explicit so maintainers can choose or reconcile the approaches.

AI assistance was used for implementation, review, and test execution. This draft is for human review; it does not claim the submitter has already reviewed every changed line or personally rerun the tests.
