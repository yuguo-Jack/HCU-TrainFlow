# [Doc][Recipe] MiniMax-M3.1-Flash: add Hopper FP8 variant, Docker-only install

[Upstream PR](https://github.com/vllm-project/vllm/pull/63244) · state: closed · merged: True

## Original PR description



## Overview

Follow-up to #63236. Adds H100 and H200 to the MiniMax-M3.1-Flash recipe as an `fp8` variant, and makes Docker the only install path.

## Claims

- New `fp8` variant for H100 and H200. It serves the same `MiniMaxAI/MiniMax-M3.1-Flash` checkpoint at TP8, with FP8 KV and indexer K caches and the NVFP4 experts on `--moe-backend marlin`. It uses a 256K context, `--max-num-seqs 80`, and `--limit-mm-per-prompt '{"video": 0}'`. DSpark is not enabled on Hopper.
- The `nvfp4` `default` variant stays on Blackwell (GB200, GB300, B200, B300) and MI355X.
- `model.install.pip: false` hides the pip tab, so the Install block shows only the `minimax-m31-flash` Docker image.
- The guide gets a Hopper prerequisite and a "Single node (TP8, NVIDIA H100 / H200)" section.

## Validation

From a checkout of vllm-project/recipes at `origin/main`:

```bash
node scripts/validate-source.mjs --source vllm --dir ~/vllm/recipes
# ✓ vllm recipes from /Users/roy/vllm/recipes are valid against the renderer
```

The renderer (`resolveCommand`) gives this for the `fp8` variant on h100 and h200. The flags match the Hopper serving command in the guide, and there is no `--speculative-config`:

```bash
vllm serve MiniMaxAI/MiniMax-M3.1-Flash \
  --block-size 128 --disable-hybrid-kv-cache-manager \
  --kv-cache-dtype fp8 --attention-config '{"indexer_kv_dtype": "fp8"}' \
  --compilation-config '{"cudagraph_mode": "FULL_AND_PIECEWISE"}' \
  --moe-backend marlin --max-model-len 262144 --max-num-seqs 80 \
  --limit-mm-per-prompt '{"video": 0}' --gpu-memory-utilization 0.9 \
  --no-enable-log-requests --tensor-parallel-size 8 \
  --tool-call-parser minimax_m3 --enable-auto-tool-choice --reasoning-parser minimax_m3
```

The commands for B200, B300, GB200, GB300 and MI355X are unchanged from `main`. `pre-commit` passes. This PR changes docs only, so I did not run serving or model evals for it.

## Details

- **Not a duplicate:** no other open PR changes this recipe for Hopper. #63232 is the model-support PR.
- `--kv-cache-dtype nvfp4` moved from `base_args` into the `blackwell` and `amd` hardware overrides, so it doesn't leak into the Hopper command. The recipe-level `nvidia` override is renamed to `blackwell` for the same reason, so its NVFP4 flags and `VLLM_FLOAT32_MATMUL_PRECISION` stay off Hopper.
- DSpark is suppressed on Hopper with `spec_decoding.hardware_overrides.hopper.args: []`. The renderer reads feature-level `hardware: unsupported` only for modes, not for plain features.
- H100 and H200 are not marked `verified` in `meta.hardware`. The `fp8` variant's `vram_minimum_gb` was not measured. It reuses the 533 GB MXFP8 estimate as an upper bound, which fits an 8x H100 node (640 GB).
