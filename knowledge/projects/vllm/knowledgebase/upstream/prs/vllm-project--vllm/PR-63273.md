# [ROCm] Add K3 MegaMoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/63273) · state: open · merged: False

## Original PR description

## Overview

Add opt-in A8W4 Kimi-K3 MegaMoE backends on eight gfx950 GPUs: MegaMoEV2 expert parallelism, plus the earlier MegaMoeTP path. Both support the bounded graph+DSpark recipe. Default backend behavior stays unchanged. This draft records performance regressions and does not claim a speedup.

## MegaMoEV2 EP

Enable with `--tensor-parallel-size 8 --enable-expert-parallel --moe-backend aiter_mega_moe --all2all-backend mori_high_throughput --additional-config '{"k3_megamoe_tp":"off"}'`. Set `VLLM_ROCM_USE_AITER=1`, `VLLM_ROCM_USE_AITER_MOE_SITUV2=a8w4`, `MORI_SHMEM_HEAP_SIZE=8G`, `MORI_SOCKET_IFNAME=lo`, MRV2, Gluon MLA and disabled shared-expert stream. The rendered model recipe is linked from the supported-model index.

TP8 attention + EP8 routed experts + DP1 gives112 complete experts per GPU. Route the global batch before token partitioning to preserve graph padding masks, run V2 dispatch/compute/combine on each rank's slice, then gather latent rows before the original RMSNorm/up-projection. Keep the original shared MLP precision and reduce it separately; no shared requantization/fusion or duplicate routed reduction. Reuse the existing DSv4 expert loader/packing/runtime-cache implementation without changing that model's source. The K3 runtime sets SiTUv2 beta4/linear-beta25 and A8W4 explicitly.

The locked AITER path uses FlyDSL intra-node dispatch/combine with MoRI SHMEM peer pointers, not MORI-IO transfer APIs. TCP bootstrap is control initialization; the eight-GPU node topology is one-hop XGMI. Hardware traffic counters were not profiled. DP8/TP1 + the real draft exceeds the usable memory budget before MoRI/KV; it was rejected by weight accounting, not reported as an observed OOM.

Guarded scope: gfx950/BF16 model tensors/exact K3 latent shape, TP8/EP8/DP1/PP1, MRV2, <=4K context/C32/batched tokens1024, auto KV dtype, exactly8GiB KV/GPU, no prefix caching. Graph requires no Inductor, FULL_DECODE_ONLY, capture sizes `[4,8,16,32,64,128]` and actual Gluon metadata. K3 DSpark uses TP8/three draft tokens/TRITON_MLA. Reject EPLB/DBO/ubatching/CP/SP/LoRA/specialized decode and simultaneous TP Mega. Weight reload remains unsupported.
