# [Quantization] Add ModelOpt FP8/NVFP4 weight-only embeddings

[Upstream PR](https://github.com/vllm-project/vllm/pull/42791) · state: open · merged: False

<!-- markdownlint-disable -->

## Overview

Load ModelOpt FP8/NVFP4 token embeddings without treating their scale tensors as unexpected weights. Rebased onto `3f45273050ac38b705eeac9c1e4d5e5f0330034c` and simplified the original implementation.

## Claims

- Support row-major per-tensor FP8 and packed NVFP4 input embeddings, including mixed-policy `W4A16_NVFP4`; dequantize only selected rows to the model dtype.
- Keep output heads on main's existing linear path. Preserve exclusions and unquantized fallbacks; reject unsupported tied input/output embeddings explicitly.
- Reuse `VocabParallelEmbedding` metadata, remove unreachable fused-projection handling, and consolidate duplicated tests around real layer constructors. The quantization addition is reduced from 246 to 168 lines.
- Document enablement and limitations and wire the focused regressions into an H200 CI step.

## Details

```text
embedding token IDs -> gather quantized rows -> dequantize to model dtype
lm_head            -> existing ModelOpt linear method
```

FP8 scaling now happens in FP32 before casting to the layer's configured dtype. NVFP4 lookup retains the checkpoint's row-indexable packing and avoids GEMM repacking; empty and scalar inputs preserve their shapes. `input_scale` remains accepted for checkpoint compatibility and is not applied during lookup.

This does not duplicate #45535 (compressed-tensors embedding formats) or #48870 (fused tied-weight output projection). The earlier related #35660 is closed. Related ModelOpt export work: NVIDIA/Model-Optimizer#1495. Main already contains the Nemotron-H embedding config/prefix wiring, so no additional Nemotron model diff is needed.

The logic here uses `type(layer) is VocabParallelEmbedding` to strictly exclude subclasses like `ParallelLMHead`. The comment states that `ParallelLMHead` is handled by the linear path. However, `ParallelLMHead` does not inherit from `LinearBase` (it inherits from `VocabParallelEmbedding`), so it will not be caught by the `isinstance(layer, LinearBase)` check at line 211. Consequently, `ParallelLMHead` will fall through to return `None` and default to `UnquantizedEmbeddingMethod`. If the checkpoint contains quantized weights for the LM head, this will lead to a loading failure or incorrect results during sampling. Please ensure `ParallelLMHead` is correctly routed to a quantization method that can handle its weights, especially since it is often tied to the embedding layer.

File: `vllm/model_executor/layers/quantization/modelopt.py` · line None

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The multiplication by `layer.weight_scale` (which is a `float32` parameter) will promote the result to `float32`, potentially ignoring the desired `self.out_dtype` (usually `float16` or `bfloat16` in vLLM). This can lead to type mismatches in subsequent operations or unnecessary memory usage/performance overhead. The result should be explicitly cast back to `self.out_dtype`.

```suggestion
        return (rows.to(torch.float32) * layer.weight_scale).to(self.out_dtype)
```
