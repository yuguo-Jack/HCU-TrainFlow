# [Core] Remove the legacy Ray compiled-graph executor

[Upstream PR](https://github.com/vllm-project/vllm/pull/61712) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Remove the legacy Ray compiled-graph executor (`RayDistributedExecutor`). `RayExecutorV2` has been the default Ray backend; the legacy one was only reachable with `VLLM_USE_RAY_V2_EXECUTOR_BACKEND=0`.

## Claims

- `--distributed-executor-backend ray` always uses `RayExecutorV2`.
- Deletes `vllm/v1/executor/ray_executor.py`, `RayPPCommunicator`, and the V1-only `ray_utils` helpers (`RayWorkerWrapper`, the Ray `FutureWrapper`, `detach_zero_copy_from_model_runner_output`): −1257 / +14 lines.
- Removes the compiled-graph env vars `VLLM_USE_RAY_COMPILED_DAG_CHANNEL_TYPE`, `VLLM_USE_RAY_COMPILED_DAG_OVERLAP_COMM`, `VLLM_USE_RAY_WRAPPED_PP_COMM`.
- No behavior change for default configurations.

## Validation

- `pre-commit run` (ruff, mypy, forbidden imports, Buildkite checks): passed.
- Local run on 4x GB200 of `tests/utils_/test_ray_utils.py`, `tests/test_ray_env.py`, `tests/distributed/test_ray_v2_executor.py`: 28 passed. The 17 failures/errors in that run were all worker init failing with `Free memory on device cuda:0 (14.19/184.31 GiB) ... less than desired GPU memory utilization`, because another user's long-running vLLM processes occupy GPUs 0–1 on the shared node. A rerun of the 2-GPU cases on the free GPUs is in progress; I'll post results here.
- CI coverage: the existing `RayExecutorV2` Buildkite jobs (CUDA and MI355) run `test_ray_v2_executor.py`, `test_ray_v2_executor_e2e.py`, and the Ray cases of `test_pipeline_parallel.py` and `test_basic_correctness.py`. They already ran on V2 via `export VLLM_USE_RAY_V2_EXECUTOR_BACKEND=1`, which this PR drops because V2 is now unconditional.

## Details

**Not a duplicate:** no open PR removes the legacy Ray executor; searched open PRs for "ray executor", "RAY_V2_EXECUTOR", and "compiled DAG ray".

**Out-of-tree compatibility:** `vllm-project/tpu-inference` and `vllm-project/vllm-torchtpu` still read `envs.VLLM_USE_RAY_V2_EXECUTOR_BACKEND` on their Ray platform paths, so the env var stays defined for one release as a deprecated no-op (default `1`; removal planned for v0.34). Their own legacy executors import `vllm.v1.executor.ray_executor` and will break, but only when a user sets the flag to `0`. `_wait_until_pg_ready`, `WORKER_SPECIFIC_ENV_VARS`, and `RayExecutorV2`/`RayWorkerHandle`, which they also import, are unchanged. Setting `VLLM_USE_RAY_V2_EXECUTOR_BACKEND=0` against vLLM itself is now silently ignored.

**Follow-ups:** #61713 (stacked on this PR) removes `initialize_ray_cluster(require_gpu_on_driver)` and its driver-node pin, un-skips prompt embeds on Ray in `test_basic_correctness`, and corrects the `ray[cgraph]` requirement comment. The deprecated `VLLM_USE_RAY_V2_EXECUTOR_BACKEND` will be removed in v0.34.
