# [Docs] Add GLM-5.3-Flash to supported models

[Upstream PR](https://github.com/vllm-project/vllm/pull/63690) · state: open · merged: False

## Original PR description

## Overview

Adds the missing GLM-5.3-Flash entry to the multimodal supported-models table.

Context: #54062 was closed after GLM-5.3-Flash support landed in v0.30.0, but the supported-models table was not updated.

## Claims

- `Glm5NextForConditionalGeneration` is registered in
  `vllm/model_executor/models/registry.py` and has been supported since
  v0.30.0, but it was absent from `docs/models/supported_models.md`.
- The new row lists the checkpoint and its image/video modalities, following
  the adjacent GLM-4.1V / GLM-4.5V rows.

## Validation

Docs-only change; no code paths are touched.

```text
pre-commit run --files docs/models/supported_models.md
# typos, markdownlint-cli2 and the remaining applicable hooks passed
```

The model code supports image and video through the inherited Glm4v
multimodal path (`Glm5NextForConditionalGeneration` registers
`Glm5NextMultiModalProcessor` and accepts `{"image", "video"}` in its tower
model). The sibling docs change in #63643 confirms the same model's
image/video support in the encoder CUDA-graph matrix.

## Details

- LoRA is left blank because general GLM-5.3-Flash LoRA support is still in
  #56327; PP is marked supported via the inherited `SupportsPP` implementation.
- The text-only `Glm5NextForCausalLM` entry is not listed separately, matching
  the Qwen3.5 hybrid rows in this table; text-only mode is available through
  the documented `--language-model-only` path.
- No new CI test: this is a documentation row for an already-registered
  architecture.
