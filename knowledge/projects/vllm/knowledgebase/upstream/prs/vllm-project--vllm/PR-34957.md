# [Bugfix] Use getattr fallback for weight_loader in stacked-param branch

[Upstream PR](https://github.com/vllm-project/vllm/pull/34957) · state: closed · merged: False

## Original PR description

Fixes #34201.

After sleep mode level 2 discards model weights and `reload_weights()` is called, fresh `nn.Parameter` objects may no longer carry the custom `weight_loader` attribute that is set during normal model initialisation. Model `load_weights` implementations accessed `param.weight_loader` with a bare attribute lookup in the stacked-parameter loading branch, causing:

    AttributeError: 'Parameter' object has no attribute 'weight_loader'

The `else` branch of the same functions already used the defensive pattern:

    weight_loader = getattr(param, "weight_loader", default_weight_loader)

This commit makes the stacked-parameter branch consistent by applying the same `getattr` form across all affected model files.

Changes
-------
* 119 model files under `vllm/model_executor/models/` replace bare `weight_loader = param.weight_loader` with the `getattr` form in the stacked-params loop.

* `vllm/model_executor/models/bert.py` additionally imports `default_weight_loader` from `vllm.model_executor.model_loader.weight_utils` (the only file that was missing this import).

* `tests/model_executor/test_weight_loader_fallback.py` new unit tests that document the old failure mode and verify the fix.

## Code Review

This pull request addresses an `AttributeError` when reloading model weights after sleep mode by defensively using `getattr` to access `param.weight_loader`. The change is applied consistently across a large number of model files, and the newly added unit tests in `tests/model_executor/test_weight_loader_fallback.py` effectively verify the fix for the described failure mode. However, I found one critical issue in `vllm/model_executor/models/longcat_flash.py` where a direct access to `param.weight_loader` remains, which would still cause the bug this PR intends to fix. Please see the specific comment for details. Overall, this is a good and necessary bugfix. Once the identified issue is addressed, this PR should be ready for merging.

While this line correctly uses `getattr` to avoid an `AttributeError`, the code on line 694 still accesses `param.weight_loader` directly: `weight_loader = typing.cast(Callable[..., bool], param.weight_loader)`. This will cause the same `AttributeError` this PR aims to fix when `param` does not have the `weight_loader` attribute.

The cast should be applied to the `weight_loader` variable instead. You might want to refactor these lines to:
```python
weight_loader = getattr(param, "weight_loader", default_weight_loader)
weight_loader = typing.cast(
    Callable[..., bool], weight_loader
)
```
