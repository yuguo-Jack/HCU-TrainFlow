# [Perf][Parser] Skip tool-argument conversions after a replaced value

[Upstream PR](https://github.com/vllm-project/vllm/pull/64673) · state: closed · merged: True

## Original PR description



## Overview

When a tool call repeats a key whose value was already streamed, `ParserEngine._compute_arg_delta` fails the prefix check before it installs the argument value extender. Every later delta then re-converts the whole argument text, only to fail the same check, so the API server's cost per token grows with the call. This installs the extender with streaming off on that failure. Follow-up to #61253 and #64535.

## Claims

- On GLM-4.7/GLM-5.x, a long value written under a repeated key costs 15.1 us per engine step at 66K output chars, against 2514 us on main. From 64K to 256K chars the mean is 17.3 us against 6.16 ms.
- On a real server (GLM-4.7-Flash, one H200), streaming that call to 256K chars costs the API server 14 s of CPU against 215 s on main, and `/health` p99 stays at 0.8 ms against 17.9 ms.
- Streamed arguments are unchanged in every case checked, and so are non-streaming results. One case groups deltas differently: a repeated key whose new value starts with the text already streamed for the old value. It streams the rest of the value when the value closes, while main streams it at the next delta containing `>`.
- The change is in `engine/` because the wasted conversion follows any failed prefix check, whatever the parser. Only GLM's extender accepts a value under a repeated key today, so Qwen3 and DSML streams are unchanged (see Details).
- No new config, flag or API.

## Details

**Root cause.**
- A model that repeats a key replaces that key's value in the converted JSON. The JSON then stops extending `slot.streamed_json`, so `_compute_arg_delta` returns at `if prev and not safe_json.startswith(prev)`. That return comes before `slot.extend_open_value` is set.
- GLM sets `arg_structural_chars=frozenset(">")`, so every later delta containing `>` runs `arg_converter`, `_fix_arg_types` and `_safe_arg_prefix` over the whole argument text, then fails the same check.
- HTML, JSX and most code put a `>` in nearly every engine step. So the cost per step is linear in the argument and the total is quadratic. Merging deltas under load caps it near one conversion per pass, so on its own this saturates the event loop without failing liveness (replayed on `f4efba72e6`, which has the same path).

**Change.**
- On that failure, set `slot.extend_open_value` from `self._arg_value_extender(slot.args)` and set `slot.open_value_streams = False`. The existing branch at the top of `_compute_arg_delta` then returns `None` for a delta that only extends the open value, without converting.
- The extender returns `None` at the value's closing tag. The next delta then converts, and streaming resumes if the JSON extends `streamed_json` again. The final flush converts the full text as before.
- A delta that only extends the new value can make the JSON extend `streamed_json` again only when the new value starts with the text already streamed for the old one. That is the grouping difference in the equivalence table.

**Which parsers.** The change applies to every parser with an `arg_value_extender`. GLM's extender accepts an open value under a repeated key when that key is the last one. `_param_value_extender` (Qwen3) and `_dsml_arg_value_extender` (DeepSeek V3.2/V4) return `None` for any repeated key, so for them this installs nothing. On main they still pay a conversion per delta for a long value under a repeated key: 5.5 ms per step at 64K chars for `deepseek_v41` and 29.6 ms for `qwen3_coder`. Replayed at a production pod's measured API-server load, the `deepseek_v41` stream fails liveness and is killed at 335 s. Letting those extenders accept a repeated last key, as GLM's does, would be one follow-up per parser.

**Unchanged here and the same on main.** When the repeated key closes with a value that does not extend what was streamed, the flush withholds the final JSON, so the client gets truncated arguments. #53739 (open) addresses that flush.

**Not a duplicate.** #63385 (open) rewrites this block of `_compute_arg_delta` for incremental type repair and keeps the same early return on a failed prefix check. The overlap is textual, and whichever lands second rebases. #53739 (open) changes the flush fallback. #64196 (open) and #58780 (merged) cover DSML open values, and #61253 and #64535 (merged) cover GLM open values and closed pairs. No open PR covers conversions after a failed prefix check.
