# [Security] Reject local verifier references in Speculators metadata

[Upstream PR](https://github.com/vllm-project/vllm/pull/61587) · state: closed · merged: True

## Original PR description



## Overview

Reject local verifier references supplied by Speculators checkpoint metadata before replacing the selected model and tokenizer. Keep local verifiers available when the operator selects the model explicitly and supplies the draft through speculative configuration.

## Claims

- Reject absolute paths, traversal, file URLs, invalid reference types, and local entries whose names are otherwise valid repository IDs.
- Reject local symlinks, including dangling links, before engine/model loading.
- Preserve valid remote verifier references and explicitly selected local models.

## Validation

- Before the change: the 14 new rejection cases failed; the seven existing/control cases passed.
- After the change: 23 tests passed, including real JSON configuration through both EngineArgs and AsyncEngineArgs.
- HTTP server startup with a local verifier in Speculators metadata exited with the validation error before initializing EngineCore or loading a model.
- All hooks applicable to the three changed files passed, including Ruff, mypy, markdown lint, SPDX checks, and Buildkite test coverage.
- The full repository hook run found macOS-specific failures outside this diff: Linux-only mmap/os attributes in two unchanged files, and the Docker wrapper test's /var versus /private/var path comparison. Other hooks passed.

Model accuracy evaluation is not applicable: this changes configuration admission before model loading and does not modify model execution. No successful full model-generation run is claimed.

## Details

The shared Speculators resolver accepted verifier.name_or_path from repository metadata and assigned it directly to both model and tokenizer. Syntax validation alone is insufficient: a valid repository ID such as org/model can also resolve to a local directory. The resolver now requires a string accepted by the Hub repository-ID validator and rejects existing local entries and symlinks before the assignment.

This startup resolver is shared by synchronous and asynchronous engines, HTTP and gRPC serving, CLI serve/preload, batch serving, and Tensorizer configuration. Other Speculators parser helpers do not assign the selected model or tokenizer.

Compatibility: a Speculators repository that names a local verifier now fails startup. The error and feature documentation describe selecting the local verifier explicitly and configuring the checkpoint as the draft.
