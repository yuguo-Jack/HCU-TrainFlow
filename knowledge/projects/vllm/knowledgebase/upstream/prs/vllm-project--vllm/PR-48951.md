# [Rust Frontend] Fix bad_words handling in /v1/completions

[Upstream PR](https://github.com/vllm-project/vllm/pull/48951) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Make `bad_words` take effect on the Rust frontend's `/v1/completions`. Taking over this PR from @reidliu41: the original commit is kept as is, `main` is merged in (one mechanical conflict), and a route-level test is added on top. The original description is kept below.

## Claims

- `/v1/completions` forwards `bad_words` to sampling like `/v1/chat/completions` and the Python frontend, instead of silently dropping it.
- A route test pins that the scripted engine receives `_bad_words_token_ids` for `bad_words` on both chat and completions.

## Validation


- `routes::tests::openai_bad_words_reach_engine_core_as_token_ids` sends `"bad_words": ["blocked"]` to both routes and checks the engine request. With the forwarding reverted, the completions case reaches the engine without bad-word token IDs and fails.
- `prepare_completion_request_maps_sampling_fields` (from the original commit) checks the field on the lowered text request; it fails without the change too.

## Details

Python's `CompletionRequest` declares `bad_words: list[str] = []` and passes it to `SamplingParams` (`vllm/entrypoints/openai/completion/protocol.py`), like chat. The Rust completions DTO did not declare it, so the value landed in the flattened `other` map, and request conversion lowered `bad_words: None`: the request succeeded and the words were not banned. Declaring the field and passing it through reuses the existing text-layer tokenization (`vllm-text` `lower_sampling_params`, shared with chat and generate), so no other change is needed.

Changes on top of the original commit:

- Merge of `main`: `CompletionRequest` lowering gained `bad_words_token_ids` and `logprob_token_ids` since this branch was cut; the conflict keeps both next to `bad_words: request.bad_words`.
- The route test above, which observes the engine request rather than the intermediate text request, so a later routing or lowering regression on either route is caught.

## Purpose

  The Rust `/v1/completions` request type did not declare `bad_words`. The field was captured by the flattened extra-fields map, while request conversion always set `SamplingParams.bad_words` to `None`.

  As a result, requests containing `bad_words` succeeded, but the requested filtering was silently not applied.

  Declare `bad_words` as a typed completion request field and forward it into `SamplingParams`. This connects `/v1/completions` to the existing bad-word tokenization and filtering pipeline. It also ensures invalid `bad_words` element types return a request error instead of being silently accepted.
