# [Rust Frontend][Perf] Reduce per-request output channel memory

[Upstream PR](https://github.com/vllm-project/vllm/pull/65629) · state: open · merged: False

## Original PR description



## Overview

The Rust frontend creates one Tokio output channel for every active
request. Each channel currently stores 304-byte output deliveries inline,
causing a drained but warmed channel to retain about 22.5 KB of memory.

Store queued deliveries behind `Box` pointers and unwrap them at the
receiver boundary. The output type, ordering, error propagation, and
stream behavior remain unchanged.



## Claims

- Reduces the Tokio channel slot size from 304 bytes to 8 bytes on
  64-bit platforms.
- Reduces measured warmed-channel RSS from about 22.5 KB to 1.6 KB per
  active request.
- Preserves the existing output stream API and wire behavior.
- Keeps the implementation private to the per-request output channel.

The total memory savings increase with the number of concurrently active
request streams.



## Validation
```
cargo nextest run -p vllm-engine-core-client --all-features
cargo clippy -p vllm-engine-core-client --all-targets  --all-features --locked  -- -D warnings
cargo fmt --all -- --check
```

A release-mode microbenchmark repeatedly sent and drained outputs across
independent channels. Each scenario was run three times in a separate
process, and the median result is reported below.

| Queue item | RSS per channel | Change |
|---|---:|---:|
| Inline Result<Delivery> | 22,523.1 bytes | Baseline |
| Boxed Result<Delivery> | 1,572.9 bytes | -93.0% |



## Details

Tokio's unbounded MPSC channel stores messages in blocks containing 32
slots. With a 304-byte delivery, each block reserves space for 32 complete
delivery values. Warming the channel can leave reusable blocks allocated
even after all queued messages have been consumed.

Boxing the queued value makes each channel slot pointer-sized. A private
receiver wrapper delegates to Tokio's existing poll_recv implementation
and immediately unwraps the value, so downstream consumers continue to
receive Result<EngineCoreStreamDelivery>.

Boxing adds one heap allocation per queued delivery in exchange for
substantially smaller channel blocks. The change is limited to internal
queue storage and does not alter externally observable behavior.
