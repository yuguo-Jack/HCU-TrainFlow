# [Bugfix][Frontend] Honor endpoint plugin route overrides

[Upstream PR](https://github.com/vllm-project/vllm/pull/58839) · state: closed · merged: True

## Original PR description

## Purpose

Endpoint plugins are documented to support overriding core routes, but core routes are registered first and win during request dispatch. For example, a plugin can register `GET /version` successfully while requests still reach the built-in handler. OpenAPI can meanwhile describe the plugin's handler, so the schema and actual response disagree.

This change replaces earlier HTTP operations when a plugin registers the same path template and method. Other methods remain available, and the last registered plugin operation takes precedence. Plugin hooks still run after core router registration. The OpenAPI cache is also cleared so the schema reflects the routes that handle requests.

The endpoint plugin documentation is updated to describe these rules.

Duplicate-work check on September 26, 2026: searched open and closed endpoint-plugin issues and PRs and found no existing fix for this behavior.

Trigger: a plugin partially overrides a route registered with 2+ HTTP methods on one APIRoute (e.g. `@ router.api_route('/x', methods=['GET','POST'])`) — exactly what the new test test_endpoint_plugin_override_preserves_other_methods in tests/plugins_tests/test_endpoint_plugins.py exercises.
