# [Bugfix][ROCm] Skip aiter per-tensor FP8 quant dispatch on fnuz hardware

[Upstream PR](https://github.com/vllm-project/vllm/pull/62733) · state: closed · merged: False

## Original PR description

## Overview

vLLM CI on ROCm should succeed with `VLLM_ROCM_USE_AITER=1`, since most model serving commands are prefixed with `VLLM_ROCM_USE_AITER=1`. This PR disables Aiter dynamic quantization in vLLM when using fp8 fnuz.

## Claims

After this PR, the test `tests/kernels/test_concat_mla_q.py::test_concat_mla_q_fp8_nope_and_rope` passes with `VLLM_ROCM_USE_AITER=1` set.

## Validation

Run the test

```bash
VLLM_ROCM_USE_AITER=1 python3 -m pytest \
  -v -s tests/kernels/test_concat_mla_q.py \
  -k test_concat_mla_q_fp8_nope_and_rope
```

The following parameter combinations fail before this PR and pass after:

| Parameters | Before | After |
| --- | --- | --- |
| `True-0-False` | FAIL | PASS |
| `True-0-True` | FAIL | PASS |
| `True-64-False` | FAIL | PASS |

The first `True` enables testing the custom op `mla_decode_concat_quant_fp8`. https://github.com/vllm-project/vllm/blob/0ca531ba64c61af32accb3b52226e8d819c6a49b/tests/kernels/test_concat_mla_q.py#L176

## Details

Aiter's per-tensor FP8 quantization kernels saturate float8_e4m3fnuz outputs at +/-240, while vLLM's own convention clamps to +/-224.

- rjrock · comment · 2026-10-20T21:18:21Z · [source](https://github.com/vllm-project/vllm/pull/62733#issuecomment-6301698960)

> So the AITER per-tensor quant kernel doesn't support MI300 & MI325? In what way does the test fail exactly?

Aiter uses the full fp8fnuz range of [-240,240], whereas vLLM uses an adjusted range of [-224,224], presumably for accuracy reasons.

The test fails when, for instance, a clamp on the expected value saturates to 224, but on the actual value saturates to 240.
