# [Bugfix][MoE] Reject non-contiguous routing tensors

[Upstream PR](https://github.com/vllm-project/vllm/pull/57167) · state: open · merged: False

## Original PR description

## Purpose

MoE routing kernels consume `topk_ids` and `topk_weights` as dense linear
buffers. A sliced routing result such as `wide[:, :top_k]` can have shape
`(num_tokens, top_k)` but stride `(wide_top_k, 1)`. The previous
`topk_weights.stride(1) == 1` checks accepted this layout, while the kernels
ignored the row stride and could silently read incorrect routing data.

This change fails fast without introducing hidden copies:

- validate `topk_ids` in the `moe_align_block_size` C++ wrapper before the
  CUDA kernel launch;
- require fully contiguous `topk_weights` at the shared MoE dispatch boundary;
- apply the same validation in the direct Triton launcher used by the modular
  Triton backend.

## Test Plan

- Add a regression test passing sliced, non-contiguous `topk_ids` to
  `moe_align_block_size`.
- Add a regression test passing sliced, non-contiguous `topk_weights` to the
  Triton MoE launcher.
- Run the relevant formatting and static-analysis hooks.
