# [ROCm][Bugfix] Release vLLM's communicators on external-launcher shutdown

[Upstream PR](https://github.com/vllm-project/vllm/pull/62241) · state: closed · merged: True

## Original PR description

Motivation: https://buildkite.com/vllm/ci/builds/95633/list?jid=01a14c8b-4acc-4866-b9b8-e31d71cdc245&tab=output

`ExecutorWithExternalLauncher` (torchrun, `distributed_executor_backend="external_launcher"`) now destroys vLLM's model-parallel groups on shutdown, like `MultiprocExecutor`'s workers do. Without it, `:amd: (MI355) Distributed DP + EP` intermittently aborts at exit on the ROCm 10 image (#58761).

- Fixes the exit-time abort (`terminate called without an active exception`, SIGABRT on several ranks) of `examples/features/torchrun/torchrun_dp_example_offline.py --tp-size=2 --dp-size=4 --enable-ep` on MI355 with ROCm 10.
- Only vLLM-owned groups are destroyed; the world group and the default process group, which the launcher may own, are untouched.

Root cause: `UniProcExecutor.shutdown()` only calls `worker.shutdown()`. `MultiprocExecutor` additionally calls `destroy_model_parallel()` and `destroy_distributed_environment()`, which abort the PyNCCL communicators and destroy the NCCL subgroups. In external-launcher mode nothing does, so each rank exits with live RCCL communicators whose background threads are destroyed by static destructors; a `std::thread` destroyed while joinable calls `std::terminate`. ROCm 7.2's RCCL tolerates this; ROCm 10's does not, intermittently.
