## Overview

Repair two Clef-Omni boundaries on vLLM 0.32: retrying a cold image after schema refusal, and loading the full-width BF16 output lookup table with a ModelOpt NVFP4 backbone.

This targets `releases/v0.32.0` at `5df63a7203cdb9328d824a27b682e77c7b9928be`. The renderer repair and its test from the original PR head `33460c48` are unchanged.

## Claims

- Keep the existing `skip_mm_cache=True` call in `JointSchemaStrategy._render_media`, preventing a refused request from leaving sender-only media-cache state. Omni's state truncation and 64k reference cap remain unchanged.
- Represent Clef-Omni's required output lookup table with the existing `VocabParallelEmbedding`, matching its lookup-only role.
- Preserve the checkpoint parameter name, full tensor values, vocabulary layout, padding, dtype policy and tied-parameter identity. The untied output table remains distinct from the input embedding.
- Retain the original unbound lexical lookup. No required weights are skipped, reshaped or substituted; generic Qwen generation is unchanged.

## Details

### Cold media retry

Media preprocessing can populate the sender cache before the complete question schema is rejected. A fitting retry of the same image can then send only a hash to a receiver that never received the tensor. The existing processor-only cache option prevents that premature sender trust. Repeated requests may resend tensor payloads; no throughput improvement is claimed.

### Output embedding load

The observed checkpoint stores both vocabulary tables as BF16 `[152064, 2048]`, but does not exclude `lm_head` from ModelOpt quantization. The inherited `ParallelLMHead` is treated as a linear layer and allocated at packed width 1024. The actual startup trace reports 1024 versus 2048 without a parameter name; the actual-metadata CPU loader reproduction identifies the output `lm_head`.

Clef consumes this table through embedding lookups, not logits projection. A plain `VocabParallelEmbedding` uses the existing embedding quantization dispatch and loads the full-width BF16 table under the same checkpoint name. It receives the same quantization configuration; there is no forced dtype or checkpoint rewrite.

Related [#62043](https://github.com/vllm-project/vllm/pull/62043) adds the missing Omni head prefix, but prefix-only does not repair this checkpoint because its exclusions do not name the head. A counterfactual head exclusion repairs allocation but leaves an unquantized linear method without the embedding lookup Clef requires. The related [vllm-omni #4528](https://github.com/vllm-project/vllm-omni/pull/4528) concerns the separate vllm-omni repository.

The renderer repair is separate from Flash-only [#62249](https://github.com/vllm-project/vllm/pull/62249) and [#62297](https://github.com/vllm-project/vllm/pull/62297). Bounded open-PR searches did not establish another complete matching Clef output-table repair; this is not an exhaustive absence claim.

### Limits and tradeoffs

- The parent constructor allocates the old head before replacement. Transient allocation and the approximately 0.6 GB full BF16 table require native measurement.
- Qwen3-Omni's current head has no bias. A future biased head is not qualified by this replacement.
- TP2 loading layout is tested, not distributed forward or collectives.
- Activated head-LoRA behavior and type-based re-tying/deduplication optimizations are not qualified. The previous unbound lexical lookup is retained.
- A genuinely quantized output-table checkpoint is outside this BF16-table repair.
