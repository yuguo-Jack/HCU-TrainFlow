# [Bugfix][Frontend] Make tokenizer thread-safe for all renderers

[Upstream PR](https://github.com/vllm-project/vllm/pull/64036) · state: closed · merged: False

## Original PR description

Only `HfRenderer` copied and pooled its tokenizer, so other renderers backed by a `TokenizersBackend` (e.g. Cohere, Inkling, KimiK3) used the tokenizer returned by `cached_get_tokenizer` directly. With `--renderer-num-workers > 1`, the render executor calls into the same Rust tokenizer concurrently and raises `RuntimeError: Already borrowed`.

Move both steps into `BaseRenderer.__init__`:

- Copy the tokenizer before `create_processor` so the cached instance is never mutated by the multimodal processor.
- Build the thread-safe pool as the last step of `__init__`, after the processor is created: the pool snapshots the tokenizer into deep copies, so mutations performed later would not reach those copies.

`HfRenderer` keeps its early copy (it registers the prompt-embeds placeholder token before `super().__init__()`) and marks itself with `_tokenizer_copied_by_subclass` so the tokenizer is copied only once. Its now-redundant pool call is removed.

A separate Rust-tokenizer-only probe, holding the script and Python version fixed, produced 30/40 borrow errors on tokenizers 0.22.2 and zero on 0.23.2. The [v0.23.2 binding](https://github.com/huggingface/tokenizers/blob/v0.23.2/bindings/python/src/tokenizer.rs#L484-L528) uses `Arc<RwLock<Tokenizer>>`, with read locks for encoding and write locks for truncation changes.

Could you confirm the exact tokenizers version in the original customized environment, and whether the failure still reproduces with the currently supported dependencies? I have kept the candidate test as an experiment, but do not yet have a failing supported-version baseline suitable for a regression test on current main.
