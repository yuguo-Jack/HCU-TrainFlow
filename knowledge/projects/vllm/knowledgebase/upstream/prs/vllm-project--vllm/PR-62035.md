# [Perf][Parser] Stream MiniMax M2 tool argument values incrementally (16 KB call: 5.9 s to 26 ms)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62035) · state: closed · merged: True

## Original PR description



## Overview

The MiniMax M2 parser re-runs its argument converter and the engine's safe-prefix scan over the whole argument on every streamed delta, so a long parameter value (write_file, code edits) costs quadratic CPU. This adds an `arg_value_extender` for the MiniMax M2 config, the same mechanism glm47 (#61253) and gemma4 (#61494) use.

## Claims

- Parser CPU for a streamed write_file call, one Qwen3 token per delta: 1 KB 31.8 ms to 2.1 ms, 4 KB 387 ms to 6.7 ms, 16 KB 5.9 s to 26 ms. At 32 KB the old path took 22.6 s.
- Streamed output is unchanged.

## Validation

- A/B in fresh processes, 7 runs per side, median [min-max]: 16 KB 5921 [5859-6003] ms vs 25.6 [25.2-26.2] ms.
- Differential fuzz over 44k random streams (random chunking, split and spaced tags, quotes in names, unclosed values, truncated input, several invokes, with and without a schema): every per-delta `DeltaMessage` matches the parser without the extender. Disabling each guard in the extender makes the fuzz fail.
- New tests in `tests/parser/engine/test_minimax_m2.py`: streamed arguments match non-streaming extraction with and without a schema, converter calls do not grow with argument length, split closing and next-parameter tags end the value, and the cases where no extender should be built.
- `pytest tests/parser/engine tests/tool_parsers/test_minimax_m2_tool_parser.py tests/reasoning` passes; ruff and mypy are clean.

## Details

The converter is split into `_minimax_m2_parse_args`, which also returns the match of the open trailing value. The extender is built only when that value is the last JSON value and its opener can't re-parse once more text arrives, which rules out an earlier unmatched `<parameter name=` and a bare name that starts with a quote. It keeps a small window from the last `<` so a value end split across deltas (`</param` + `eter>`, `< parameter` + ` name =`) is still detected, and then hands back to the converter.
