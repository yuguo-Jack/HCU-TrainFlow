# [Rust Frontend] Accept whole-number floats for integer tool arguments

[Upstream PR](https://github.com/vllm-project/vllm/pull/61299) · state: closed · merged: True

## Original PR description

Schema-typed tool arguments in the Rust frontend now accept an `integer` written as a whole-number float like `"3.0"` and convert it to `3`, instead of falling back to the raw string.

- JSON Schema (draft 6 onward, including 2020-12) defines `integer` as any number with a zero fractional part, so `3.0` is a valid `integer` value. `jsonschema` (Draft 7 and 2020-12 validators) and Pydantic v2 both accept it, and Pydantic returns `3`.
- The fallback only applies to schema-driven conversion, so it covers the response-template parser and the other tool parsers that use `ToolSchemas` (`qwen_coder`, `glm_xml`, `minimax_m2`, `minimax_m3`, `deepseek_dsml`, `hy`). The `int` content parser keeps its strict behavior.
- Values with a fractional part (`"3.5"`), non-finite values and floats outside the `i64` range still fail the `integer` conversion, so they fall through to the next declared type or stay raw, as before.
- Matches the Python response parser change in https://github.com/vllm-project/vllm/pull/61297 and the same change in Transformers: https://github.com/huggingface/transformers/pull/49547.
