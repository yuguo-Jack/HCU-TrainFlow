# [ROCm][Perf][Qwen3.8] Fused decode for the gated full-attention layers of Qwen3.8-27B on MI355X

[Upstream PR](https://github.com/vllm-project/vllm/pull/64346) · state: closed · merged: False

## Overview

Opt-in (`VLLM_ROCM_QWEN_FUSED_FULL_ATTN=1`) fused decode for the 16 gated full-attention layers of `Qwen/Qwen3.8-27B` on MI355X, TP1, `ROCM_ATTN`. Steps of up to 32 rows run each layer from its input RMSNorm through its post-attention RMSNorm as 4 Triton launches instead of 12, with split-KV decode attention. Larger steps run the stock modules.

No open PR covers these layers. #61573 (MXFP4 27B) fuses the GDN and MLP layers and leaves full attention stock; #60833 does the same for the MoE model. #61864 fuses QK-norm + MRoPE + cache write for `ROCM_AITER_FA` via a compile pass. #51406 enables `fused_qk_rmsnorm_rope_gate` on ROCm, which this PR's fallback path calls.

## Claims

- Median TPOT, stock → fused, concurrency 1: −5.4% at 128-token prompts, −39.1% at 4k, −70.6% at 16k (41.05 → 12.08 ms). Concurrency 8: −4.0%, −30.6%, −39.1%. No cell regresses.
- Accuracy unchanged: GSM8K 0.7919 → 0.7873 (mean of 4 runs each, overlapping ranges, standard error ~1.1 pt); passkey retrieval identical at 4k / 16k / 30k.
- Decode launches per step 896 → 768 at batch 1; GPU busy time 12.44 → 11.84 ms.

## Details

- At head size 256, `ROCM_ATTN` falls back to `kernel_paged_attention_2d`, one program per (sequence, KV head) with no context split: a single 16k sequence uses 4 of 256 CUs. That is where the long-context gain comes from; at short context it is fewer launches and HBM round trips.
- Three custom ops: `rocm_qwen_full_attn_front` (residual add, input norm, QKV GEMV, q/k norm, (M)RoPE, KV-cache write; 1 launch), `rocm_qwen_full_attn_core` (split-KV attention + sigmoid gate; the `splitting_ops` entry), `rocm_qwen_full_attn_back` (split-K o_proj, add + post norm; 2 launches). The input norm's 1/rms is applied after the GEMV, so the normalized activation is never written.
- Cross-program handoffs use last-arriver counters (release/acquire) that reset themselves, so launches are graph-safe and no program waits.
- Enabled for `Qwen3_5DecoderLayer` full-attention layers with TP1, `ROCM_ATTN`, the output gate, NeoX RoPE (optionally interleaved MRoPE), no quantization, `kv_cache_dtype=auto`, bf16, and supported shapes; otherwise stock. Shapes come from the layer; tiles were tuned on the 27B shapes. Kernels follow their tensors' dtype, so fp16 needs only validation. Quantized weights and fp8 KV stay stock.
- Non-decode steps (prefill, mixed, spec-decode verify) use stock attention inside the same op. Spec decode was not benchmarked.
- About 900 non-test lines, nearly all in the new file. Outside it: the env var, `splitting_ops`, the eligibility check in `qwen3_5.py`, and an early return in `Qwen3NextDecoderLayer.forward` off by default.
- Tried and slower: split-K front GEMV, prefetch in o_proj, `tl.dot` at 1 row, smaller row blocks, blocked attention merge.

- Rishab540 · comment · 2026-10-29T15:17:37Z · [source](https://github.com/vllm-project/vllm/pull/64346#issuecomment-6500656654)

Closing this. After comparing against the other ROCm attention backends on MI355X, most of the gain here came from avoiding ROCM_ATTN at head size 256 rather than from the fusion itself:

| Median TPOT (ms), Qwen3.8-27B | ROCM_ATTN | this PR | TRITON_ATTN | ROCM_AITER_FA |
|---|---|---|---|---|
| 128 in / c1 | 11.83 | 11.25 | 11.46 | 11.44 |
| 16k in / c1 | 41.06 | 12.06 | 12.52 | 11.87 |
| 16k in / c8 | 79.43 | 47.96 | 32.17 | 27.54 |

A backend-independent version (fused projections only, any attention backend in between) was flat at c1 and 3–7% slower at c8–c32 against the same backend, since the Triton GEMVs trail the stock skinny GEMM. The remaining norm/RoPE/gate fusion is covered by #51406 and #61864, and the backend selection by #62813.
