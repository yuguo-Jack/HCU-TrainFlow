# [Doc] Add Runcrate deployment guide

[Upstream PR](https://github.com/vllm-project/vllm/pull/63688) · state: open · merged: False

## Original PR description

## Overview

Adds `docs/deployment/frameworks/runcrate.md`, a deployment guide for [Runcrate](https://www.runcrate.ai/?utm_source=vllm&utm_medium=directory&utm_campaign=gpu_pricing), next to the existing RunPod, Crusoe and Nebius pages. I work on Runcrate; our users run vLLM on our GPU instances and ask how to expose it safely, so this documents the path we tested.

## Claims

- One new docs page; no code changes. The nav picks it up from `deployment/frameworks`.
- The guide starts a single-GPU instance with the `runcrate` CLI, runs the official `vllm/vllm-openai` image with `--api-key`, serves port 8000 at an HTTPS address, and sends a chat request with curl and the OpenAI SDK.
- It documents `VLLM_ENABLE_CUDA_COMPATIBILITY=1` for hosts whose driver is older than the image's CUDA version, linking the existing section in the installation docs.

## Validation

Run end to end on 2026-10-25 on a Runcrate RTX A6000 (48 GB, driver 570.195, `ubuntu-inference` image):

- `runcrate instances create --name ... --gpu A6000 --template ubuntu-inference --max-runtime 4h`: running after about 5 minutes.
- `docker run ... -e VLLM_ENABLE_CUDA_COMPATIBILITY=1 vllm/vllm-openai:v0.32.0 Qwen/Qwen3-8B --max-model-len 8192 --api-key ...` (the `latest` tag on that date): the image pull took 2 minutes, then `Application startup complete.` about 2 minutes 20 seconds after the container started (27 s weight download, then torch.compile).
- HTTPS link created with the documented `curl` call; `/v1/models` without the key returned `401`; the chat request in the guide returned `Hello! How can I assist you today?`; the OpenAI SDK snippet returned the same.
- `runcrate instances delete`: instance terminated.
- `markdownlint-cli2 --config tools/pre_commit/.markdownlint.yaml docs/deployment/frameworks/runcrate.md`: 0 errors.

Not run: the multi-GPU sentence (`--gpu H100:4` with `--tensor-parallel-size 4`) was not exercised.

## Details

Without the compatibility variable the same image does not start on a 570 driver, and `uv pip install vllm --torch-backend=auto` on that host resolves to an old vLLM because current wheels need CUDA 12.9 or newer. The Docker route with the compatibility libraries is what the existing installation docs recommend for that case, so the guide uses it.

Not a duplicate: `gh pr list --repo vllm-project/vllm --search runcrate` and the issue search return nothing.
