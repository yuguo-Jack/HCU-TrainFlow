# [PD][NixlPush][Bugfix] Notify D of NIXL writes that failed to post so it stops waiting

[Upstream PR](https://github.com/vllm-project/vllm/pull/50754) · state: open · merged: False

## Original PR description

## Summary

Fixes row **C2** of #48633.

**Problem:** In push mode the prefill node writes KV straight into the decode node's memory. The decode node knows it has everything by counting the notifications that come in. If the prefill node cannot start one of those transfers it just logs and moves on, so the decode node counts toward a number it never reaches. The request hangs until its lease expires while holding blocks over a half-written cache.

**Solution:** This PR introduces a new NIXL message that the prefill node sends when it cannot start a transfer. The decode node counts it like a normal notification, so it still reaches the number it expects. Only then does it fail the request, which guarantees no other transfer is still writing into its blocks. From there the existing KV load failure policy applies.

The 4 failing tests are unrelated and also fail on main.

Also tested on a 3 GPU machine: a prefill instance with 2 ranks (TP=2) pushing to a decode instance with 1 rank. Ran these scenarios, 10 times each:

- **Both P ranks succeed:** D completes the request normally.
- **One P rank fails first, the other succeeds after:** D waits for the successful transfer, then fails the request.
- **One P rank succeeds first, the other fails after:** D waits for the failure message, then fails the request.

After every failure the next request succeeded with the same output as before. On main, D is never told about the failed transfer and the request hangs.
