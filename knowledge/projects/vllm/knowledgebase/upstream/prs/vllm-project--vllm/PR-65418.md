# [Bugfix][ROCm] Raise the extensible KV cache margin floor to 3 GiB

[Upstream PR](https://github.com/vllm-project/vllm/pull/65418) · state: closed · merged: True

## Original PR description

## Overview

Raises the ROCm margin floor of the extensible KV cache (#56492) from 2 GiB to 3 GiB, so torch has enough room for memory fragmentation on MI355.

## Claims
 Fixes the OOMs in `(MI355) Spec Decode Eagle Nightly` ([ci#99485](https://buildkite.com/vllm/ci/builds/99485#01a1a039-403f-474a-9c3c-6c1ae7bc7fe5)) and `(MI355 DPX) Spec Decode Speculators + MTP` ([amd-ci#15764](https://buildkite.com/vllm/amd-ci/builds/15764#01a1a0db-a987-452c-8c10-7a097faded05)).


## Validation

Tested on MI355X with the CI images. Without this PR, the Eagle and MiMo tests run out of memory when less memory is left for torch. With it, they pass, and the smallest headroom under the cap goes from 0.10 GiB to 0.67 GiB. The Eagle spec decode tests and the extensible KV cache unit tests give the same results with and without this PR.

To reproduce, run `test_eagle_correctness_medium[ROCM_AITER_FA-llama3_eagle3]` in the ci image with 100-200 MiB added to `KV_CACHE_NON_TORCH_RESERVE_BYTES`.

## Details

After warmup, vLLM limits how much memory torch can reserve. On ROCm, only about 1 GiB of that limit is left for fragmentation. The first large prefill of a 7-8B model leaves 1.3-1.7 GiB reserved but unused, so the next large allocation goes over the limit, even though the tensors in use would fit:

| Build | Limit | In use | Reserved, unused | Request |
|---|---|---|---|---|
| [ci#99485](https://buildkite.com/vllm/ci/builds/99485#01a1a039-403f-474a-9c3c-6c1ae7bc7fe5) | 18.84 GiB | 16.73 GiB | 1.27 GiB | 896 MiB |
| [amd-ci#15764](https://buildkite.com/vllm/amd-ci/builds/15764#01a1a0db-a987-452c-8c10-7a097faded05) (DPX) | 18.93 GiB | 16.81 GiB | 1.70 GiB | 688 MiB |

The limit was added in #56492, and the spare room was small from the start: about 0.05-0.08 GiB, while fragmentation changes by 0.2-0.3 GiB from run to run.
