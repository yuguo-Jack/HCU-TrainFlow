# [Perf][MRV2] Stage write contents in typed arrays

[Upstream PR](https://github.com/vllm-project/vllm/pull/63210) · state: open · merged: False

## Original PR description



## Overview

`StagedWriteTensor` keeps staged contents in a Python list and converts the whole list element by element in `apply_write`. On admission, `RequestState.add_request` stages the full prompt into `all_token_ids`, so long prompts make this conversion runner-thread time on the step's critical path.

## Claims

- Staged contents are kept in an `array.array` of the tensor's dtype. Lists go in with `array.fromlist`, and other iterables with `extend`; applying a write copies a NumPy view of the array instead of converting a list.
- A write whose contents fail to convert is rolled back and leaves no partial staged write.
- The same values reach the same rows for all current callers. Staging Python floats into an integer tensor now raises `TypeError` instead of truncating; no caller does this.
- No new option.

## Validation

Not run yet. Planned:

```bash
pytest -v tests/kernels/core/test_uva.py tests/v1/worker/test_gpu_block_table.py
```

plus a host-side timing of `RequestState.add_request` + `apply_staged_writes` with long prompts.

## Details

`clear_staged_writes` rebinds a fresh array rather than resizing one whose buffer may still be exported. `FusedStagedWriter` concatenates the int32 arrays directly. A new test checks that rejected contents leave earlier staged writes intact, on both the UVA and GPU-resident paths.

Related open PRs: #51334 keeps staged writes as NumPy chunks, which helps ndarray inputs, but lists still go through `np.asarray` element by element. #59908 and #62702 send prompts to the workers as int32 arrays, but lists stay on the current path (for example, M-RoPE models and in-process executors under #59908). This PR makes the list path cheaper for every staged tensor. An `array('i')` input is a memcpy here as well, so it complements those PRs. #62698 (chunked kernel grid) is independent. #62018 routes more admission-time staged writes through `FusedStagedWriter`, which here concatenates the typed int32 arrays directly, so the two are compatible; #62018 only fuses int32 tensors.
