# [Bugfix][MoE] Fall back to torch routing for unsupported sqrtsoftplus expert counts

[Upstream PR](https://github.com/vllm-project/vllm/pull/63687) · state: open · merged: False

## Original PR description

## Overview

Fixes #51521.

`topkGatingSoftplusSqrtKernelLauncher` only instantiates a fixed set of expert
counts, so REAP-pruned DeepSeek-V4 checkpoints with 144 experts fail with
`Unsupported expert number: 144`. This keeps the fused kernel for supported
counts and routes other counts through a torch implementation that mirrors the
kernel.

## Claims

- 144-expert sqrtsoftplus routing no longer raises. The fallback matches the
  existing torch reference for bias, hash, and vision-bias routing, padding,
  renormalization, and routed scaling.
- Expert counts the kernel instantiates (including 128/256/384/512) keep the
  existing fused path.
- Adds a regression test that fails with
  `RuntimeError: Unsupported expert number: 144` before the change and passes
  after it.

## Validation

Environment: 1x RTX A5000, PyTorch 2.13.0+cu130. This branch's
`fused_topk_bias_router.py` and `dsv4_topk.py` were applied over a vLLM 0.32.0
wheel (the wheel has the same fused kernel dispatch), so the tests exercise the
shipped compiled `_moe_C` ops.

Before:

```text
RuntimeError: topkGatingSoftplusSqrtKernelLauncher ...
Unsupported expert number: 144
```

After:

```text
pytest tests/kernels/moe/test_topk_softplus_sqrt.py -q
# 1681 passed, 7 skipped
pytest tests/kernels/moe/test_fused_topk.py tests/kernels/moe/test_topk_softplus_sqrt.py -q
# 2545 passed, 7 skipped
pre-commit run --files vllm/model_executor/layers/fused_moe/router/fused_topk_bias_router.py tests/kernels/moe/test_topk_softplus_sqrt.py
# all hooks passed (ruff, typos, mypy, SPDX, etc.)
```

The new test is
`test_fused_topk_softplus_sqrt_unsupported_expert_count`, parameterized over
regular/hash routing, renormalization, and padding.

## Details

- The set of fused expert counts is taken from the switch in
  `csrc/moe/topk_softplus_sqrt_kernels.cu`.
- The fallback uses `sqrt(softplus(logits))`, selects with the correction bias
  / hash table / vision bias, uses the unbiased scores for weights, matches the
  kernel's lower-expert-id tie-break, and handles padding rows (`0` weight,
  `-1` id).
- The fallback is only taken for counts the kernel cannot launch, so supported
  deployments are unchanged. It is slower than the fused kernel, but only
  affects checkpoints that cannot run at all today.
