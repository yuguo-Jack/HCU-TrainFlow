# [CI/Build] Publish nightly EFA image to DockerHub

[Upstream PR](https://github.com/vllm-project/vllm/pull/64028) · state: closed · merged: True

## Original PR description



## Overview

Publish the nightly CUDA 13.0 EFA image to DockerHub. Follow-up to #58768, which builds the EFA nightly but leaves it in ECR staging only.

## Claims

- Nightly builds push the EFA image as `vllm/vllm-openai:efa-nightly` and `vllm/vllm-openai:efa-nightly-<commit>` (plus `efa-nightly-x86_64` / `efa-nightly-aarch64`), and keep the last 14 like other nightly variants.
- The image's `VLLM_IMAGE_TAG` / `ai.vllm.image.tag` label for the EFA nightly now matches that published tag (`efa-nightly-<commit>` instead of `nightly-<commit>-efa`).

## Validation

- First nightly after #58768 ([release-v2 #9252](https://buildkite.com/vllm/release-v2/builds/9252)): `build-release-image-{x86,arm64}-efa` and `create-multi-arch-manifest-efa` passed, but DockerHub has no EFA tag for that commit; only `nightly-<sha>` and `cu134-nightly-<sha>` were pushed.
- New `test_nightly_variant_tags_match_published_nightly_tags` fails on `main` (helper emits `nightly-def456-efa`) and passes with this change:
  ```
  uv run --no-project --python 3.12 --with pytest python -m pytest \
    tests/tools/test_docker_build_metadata_args.py --noconftest -q -k "metadata_args or nightly_variant"
  # 36 passed (excluding test_rust_build_cache_excludes_git_metadata, which needs torch locally)
  ```
- `pre-commit` passes on the changed files.
- CI gap: the new publish step only runs in the nightly release pipeline (`NIGHTLY=1`), so the first nightly after merge is the real end-to-end check. It reuses `push-nightly-builds.sh <variant>` and `cleanup-nightly-builds.sh <prefix>` unchanged, which already publish `cu134-nightly` the same way.

## Details

- Tags use the `<variant>-nightly` prefix, not a `-efa` suffix: `cleanup-nightly-builds.sh` selects by prefix, so `nightly-<sha>-efa` would count against (and get deleted with) the default `nightly-` tags. `efa-nightly-` never matches `nightly-`.
- Not covered here: the Rubin CUDA 13.4 aarch64 EFA nightly step fails because that base builds NIXL from source with only the UCX plugin (`BUILD_NIXL=true`), so `Dockerfile.efa`'s LIBFABRIC plugin check rejects it. Rubin EFA images are not published anywhere; that will be a separate fix.
- Docs: published EFA tags are listed in `docs/contributing/dockerfile/dockerfile.md`.
- Not a duplicate: no open PR touches EFA nightly publishing (searched "efa nightly" and "Dockerfile.efa").
