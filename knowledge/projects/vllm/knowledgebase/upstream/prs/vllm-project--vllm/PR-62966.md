# [Core] Add watermark_config.enforce to override request opt-outs in EngineCore

[Upstream PR](https://github.com/vllm-project/vllm/pull/62966) · state: closed · merged: True

## Original PR description

## Overview

Add optional `WatermarkConfig.enforce` (default `False`) so deployments can override request-level watermarking opt-outs. Without enforcement, existing behavior is unchanged.

Related: #58191, RFC #53916. Alternative placement to #58202.

## Claims

- With enforcement, supported request opt-outs are watermarked, and Python watermark counters record the effective setting.
- EngineCore applies the same override to requests that skip Python admission (Rust HTTP, gRPC) and warns once per process when it overrides a flag.
- Neither check overrides greedy or trace-replay requests; beam search remains unwatermarked.

## Details

Both placements run downstream of the Python and Rust frontends. #58202 enforces in the sampler; this PR applies the policy at request admission, so Python statistics are recorded after resolution, with EngineCore covering other frontends.

Enforcement overrides the request flag; it does not make every decoding mode watermarkable. Greedy decoding, `top_k=1`, beam search and trace replay remain unwatermarked, and internal opt-outs may also be overridden. The warning is not a per-request audit log.

Thanks for the PR. I tested it on B200 against the merge-base. The override works on every path I tried: offline in-process and multiprocess, the Python server, the Rust frontend over HTTP and gRPC, streaming, preemption, TP=2, DP=2 and EAGLE3. A few things need changing before it can merge.

**1. Failing CPU test (blocking).** `tests/watermarking/test_goldens.py::test_resolved_records_every_watermark_config_field` fails because `"enforce"` is missing from `WATERMARK_CONFIG_FIELDS` in `tests/watermarking/golden_candidates.py`, and the goldens need `"enforce": false`. It passes at the merge-base.

**2. Metrics count overridden opt-outs as `not_watermarked`, in every mode.** The output processor records the status when the request is added, before EngineCore flips the flag, so in-process mode is affected too, not only multiprocess. With `n>1` in-process it is inconsistent within one request: n=4 counted as 1 `not_watermarked` + 3 `watermarked`. I'd suggest making the enforce decision in the frontend check rather than changing any metric code:

```diff
 # vllm/config/vllm.py, _check_supports_watermarking
-        if config.watermarking is False:
+        if config.watermarking is False and not watermark_config.enforce:
             return False
```

Keep the EngineCore line as the backstop for the Rust and gRPC frontends. I tested this on B200: tokens are identical to your branch, opt-outs are counted as `watermarked` in all modes, and throughput is unchanged. One knock-on: `tests/samplers/test_beam_search_online.py` uses `watermark_config = object()`, which needs an `enforce` attribute.

**3. Greedy and `top_k=1` still bypass enforce.** Both produce unwatermarked output with `enforce=true`. Since the motivation is compliance (#58191), the docs should say this plainly rather than "all requests are watermarked".

**4. The override is silent.** There is no log line or response signal when an opt-out is overridden. A `warning_once` would help operators audit it.

**5. Perf table.** At a fixed 16 req/s with 256 output tokens the offered load is about 4,096 tok/s, so throughput can't show a regression. At saturation with Qwen3-8B on B200, enforce on vs off with both 100% watermarked gave 23,415 vs 23,386 tok/s at concurrency 256, within run-to-run noise. I'd replace the table or drop it.

**6. Beam search "became deterministic".** Beam search is equally deterministic with enforce off and at the merge-base, so I'd drop that line.

**7. Tests.** Please add a CPU unit test for the override and a CLI parse test for `enforce`. The new e2e test passes on B200, but no GPU CI step runs it (`vllm/v1/engine/core.py` isn't in the GPU watermark step's source dependencies).

**8. Docs.** Under enforce, the Monitoring and Interactions sections of `watermarking.md` are out of date (opt-outs, beam search and scoring).

It would also help to state the prompt, the perf model and the EAGLE3 target/drafter pair in the description, so the numbers can be reproduced.
