# [Bugfix][KV Offload] Flush a request's promotions before finalizing its tiers

[Upstream PR](https://github.com/vllm-project/vllm/pull/62795) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Submit a request's deferred secondary-to-primary promotions before finalizing its secondary tiers. This fixes `submit_load()` being called after a tier has released its request state when an external request finishes inside `serve_external_requests()`.

Duplicate-work check: #62615 protects primary hits before batch promotions; #62650 handles OBJ submission failures and resource cleanup. Neither fixes promotion submission after request finalization. Related but distinct: #49829 and #62532.

## Claims

- Flush only the finalizing request's pending promotions, preserving batching for other requests.
- Apply the ordering at the common finalization boundary, including finalization after stores or cascades complete.
- Count deferred promotions in `has_pending_work()` and document the finalization ordering.
- Leave synchronous submission exception handling to the tier; this change does not assume that an exception makes its primary slots safe to reuse.

## Details

A secondary hit reserves primary slots and queues a `PendingPromotion` until `on_schedule_end()`. An external request may finish inside `serve_external_requests()`, before that global flush. Its tiers then receive `on_request_finished()` before the pending `submit_load()`.

`_maybe_finalize_request()` now flushes entries for the same request context after pending store and cascade guards, before notifying the tiers. Other requests remain queued for the regular per-step flush. Entries are looked up by request ID and checked by context identity.

This preserves the existing promotion policy: an external requester may still enqueue a read it cannot consume, and a tier that never reports completion can still hold a job indefinitely.
