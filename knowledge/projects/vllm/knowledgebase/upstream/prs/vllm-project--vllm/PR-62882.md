# [CI][ROCm] Set the FP8 MLA prefill scale cache in the test double

[Upstream PR](https://github.com/vllm-project/vllm/pull/62882) · state: closed · merged: True

## Original PR description

## Problem

`(MI355 DPX) Attention Kernels` fails every parametrisation of `test_fp8_prefill_matches_reference` with `AttributeError: 'AiterMLAImpl' object has no attribute '_fp8_prefill_one_scale'`. Both shards exit 1.

Failing step: https://buildkite.com/vllm/amd-ci/builds/15124/list?sid=01a15db1-bcca-4faf-841f-646f5effa40b

## Cause

#59634 stopped allocating the FP8 dequant scale on every prefill call and cached it on the impl instead. `AiterMLAImpl.__init__` now stores `_fp8_prefill_one_scale = None`, and `_mla_fp8_prefill_attn` reads that attribute before filling it in.

The test never calls `__init__`. `_make_impl` builds the object with `object.__new__` and sets only the fields the forward used to read, so the new attribute does not exist and the read raises before any kernel runs. The test file was not updated in that PR.

Upstream CI does not catch this. The module is skipped everywhere except gfx950, and the upstream AMD `Attention Kernels` mirror runs on MI300. The only step that executes it is the internal `(MI355 DPX) Attention Kernels` job.

## Fix

Set `_fp8_prefill_one_scale = None` on the test double. That is the value `__init__` stores, and the forward already allocates the real tensor the first time it is `None`.

## Test plan

`pytest -v -s kernels/attention/test_rocm_aiter_mla_fp8_prefill.py` on MI355X. The module skips on every other arch, so this is the command behind the failing step.
