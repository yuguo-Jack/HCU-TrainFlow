# [Doc] Context extension: overrides must target text_config for composite models

[Upstream PR](https://github.com/vllm-project/vllm/pull/54289) · state: open · merged: False

## Original PR description

## Purpose

Document a silent failure mode of `--hf-overrides` on the context extension page.

For multimodal / composite models whose HF config nests the language model settings under `text_config` (e.g. Qwen3-VL: no rope keys at the top level, all under `text_config`), a top-level `rope_parameters` override is applied to the outer config, while vLLM reads RoPE settings from `hf_text_config`. The extension is therefore silently not applied, and the user typically hits a confusing startup error saying the requested `max_model_len` is greater than the derived `max_model_len` — with no hint that their override went to the wrong config object.

Mechanism: `ModelConfig._apply_dict_overrides` only recurses into a key when that key already exists on the top-level config as a nested `PretrainedConfig`; otherwise the dict is set at the top level. So the working form for composite models is `--hf-overrides '{"text_config": {"rope_parameters": {...}}}'`, which this page currently doesn't mention (we lost a few hours to exactly this while extending a model to 1M context on rented GPUs).

- EagleClaw89 · comment · 2026-10-16T18:57:15Z · [source](https://github.com/vllm-project/vllm/pull/54289#issuecomment-6222591036)

Data point for this docs change, from 2x DGX Spark (GB10).

Model: `Qwen4ExpForConditionalGeneration` (`model_type qwen4_exp`, Qwen3.8-Flash-Next NVFP4). Top-level config has no `max_position_embeddings` or `rope_parameters`; both live under `text_config` (`text_config.rope_parameters.rope_type = default`).

We passed a flat override:

```
--hf-overrides '{"max_position_embeddings":1048576,"rope_parameters":{"rope_type":"yarn","factor":4.0, ...}}' --max-model-len 1048576
```

vLLM accepted the override, applied it to the wrong object, kept the derived length at 262144 and then rejected the length:

```
ValidationError: 1 validation error for ModelConfig
  Value error, User-specified max_model_len (1048576) is greater than the derived max_model_len
  (max_position_embeddings=262144.0 or model_max_length=None in model's config.json) ...
```

Nesting under `text_config` fixed it. The error text points at `VLLM_ALLOW_LONG_MAX_MODEL_LEN`, not at the override shape, so we spent a boot cycle on it (three engines died in about 30 s each). Suggestions: (1) this doc note, (2) a warning when a top-level override key exists only under `text_config` of a composite config.

Caveat: if `--max-model-len` had not been set above the native length (for example a rope-only override), we expect the override would be dropped with no error at all; we did not test that case.
