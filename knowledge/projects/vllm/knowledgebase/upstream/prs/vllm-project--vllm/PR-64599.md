# [CI] Enroll the remaining Rust frontend and OpenAI API correctness jobs in automatic sharding (6 jobs)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64599) · state: closed · merged: True

## Original PR description

## Overview

Enrolls the remaining Rust frontend and OpenAI API correctness jobs in `automatic_shard`: 6 jobs (3 steps and 3 AMD mirrors). Part of a series that enrolls every remaining test step, split by test area for review. No commands change.

## Claims

| Step | Plan | AMD mirror |
|---|---|---|
| `rust-frontend-tool-use` | 1 job (no plan) | 1 job (no plan) |
| `rust-frontend-core-correctness` | 1 shard | 1 shard |
| `openai-api-correctness` | 1 shard | 1 shard |

- One-shard and one-job plans run the same tests as on main, as one job, and split by themselves once their tests grow.

## Validation

- Planned each step and mirror with ci-infra main's planner against main's timings; every plan is within 10% of the same plan run as one job.
- Every step and mirror passes on recent main runs, nightly included.
- `/ci run` (98464) on an earlier head: every enrolled job passed. A fresh `/ci run` follows on this head.

## Details

- **Left out: steps the generator can't shard.** It only shards a step whose commands after the first pytest are all plain pytest, and ignores `automatic_shard` elsewhere. An earlier revision also enrolled Initialized Snapshot E2E, the Mooncake and scale-out EC E2E scripts, and RL entrypoints (its `export` sits between two pytest commands), with mirrors; they ran as one job regardless, so this PR no longer touches them.
- **caplog.** Files that assert on logs sit in one-shard plans here, so their order in the process doesn't change.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job. Fallback-aware timeouts belong in a central timeout setting.
