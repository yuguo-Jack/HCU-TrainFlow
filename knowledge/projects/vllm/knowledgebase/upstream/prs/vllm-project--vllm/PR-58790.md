# [Bugfix][MoE] Handle empty routing in moe_permute

[Upstream PR](https://github.com/vllm-project/vllm/pull/58790) · state: open · merged: False

## Original PR description

﻿## Purpose

Fixes #58789. Empty MoE routing can reach a zero-block calculation in the CUDA preprocessing path. Initialize expert offsets to zero and return before the sort and permutation kernels when there are no rows. Add regression coverage with and without scratch buffers.

I searched open vLLM PRs for this issue and empty `moe_permute` routing; none addresses this fix.

## Test Plan

- Build `_moe_C_stable_libtorch` with PyTorch 2.13 and CUDA 13.2.
- Run the two `test_moe_permute_empty_routing` cases on an NVIDIA GPU, plus a nonempty routing check.

## Test Result

- `_moe_C_stable_libtorch` built successfully with `ninja -j1`.
- Focused GPU regression tests: **2 passed**; nonempty routing check passed.
- The repository test file could not collect normally because this local environment lacks unrelated `_C` and FlashAttention extensions. The focused test function was run in an isolated pytest harness against the compiled MoE extension and real Python wrapper.
- Model evaluations were not run; this change handles the zero-token path, which produces no model output.

AI assistance: The code and tests were developed with Codex assistance and reviewed by the human submitter.
