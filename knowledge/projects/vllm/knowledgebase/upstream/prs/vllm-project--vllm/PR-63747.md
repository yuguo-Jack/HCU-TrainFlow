# [Bugfix][KV Offload] Reject unsupported canonical_layout for CPUOffloadingSpec

[Upstream PR](https://github.com/vllm-project/vllm/pull/63747) · state: open · merged: False

## Original PR description



## Overview

Reject `canonical_layout=true` for the default or explicitly selected `CPUOffloadingSpec`, with an actionable startup error instead of accepting an option its worker does not implement. Preserve `TieringOffloadingSpec` support and correct the usage guide.

Addresses the configuration-contract subtask in #63718; the broader tracking issue remains open.

## Claims

- Validate the normalized flag during CPU-spec construction, before allocating offload memory. The error suggests selecting `TieringOffloadingSpec` or removing the option.
- Keep omitted/false settings and Tiering canonical settings valid, including Tiering with only a CPU primary tier.
- Add factory and real-`LLM` startup regressions, select the latter in the active KV Offload CI step, and document the actual support boundary.

## Validation

Local environment: macOS arm64, Python 3.14.6, PyTorch 2.13.0, native CPU extensions built from this checkout with Apple Clang 15.0.0.

- New factory regression on the base implementation: **2 failed** with `DID NOT RAISE`; control cases: 5 passed.
- Factory, file-mapper, tiering and connector-config suites after the change: **207 passed**.
- Real OPT-125m `LLM` startup regression, omitted and explicit CPU spec: **2 passed**. On the base implementation, the macOS run reaches the pre-existing GPU-only offload restriction instead of the specific canonical-layout error; this validates configuration rejection ordering, not GPU data transfer.
- Real OPT-125m FP32 CPU generation smoke: loaded checkpoint weights, created KV cache and generated 8 greedy tokens successfully.
- Changed-file `pre-commit run --files ...`: all applicable hooks passed, including Ruff, mypy, Markdown and Buildkite test selection checks.

## Details

`build_offloading_config` preserves the requested canonical flag for either spec, but only Tiering forwards it to `CPUOffloadingWorker`. CPU construction now checks an inherited private capability; Tiering opts in, so the shared constructor does not reject its supported path. CPU subclasses inherit rejection unless they explicitly implement and opt into canonical support.

Duplicate-work check on 2026-10-26: no overlapping open PR was found by issue-number and canonical-layout/CPU-spec searches. #60005 handles LHBNC registration and #62566 handles secondary-tier topology warnings.
