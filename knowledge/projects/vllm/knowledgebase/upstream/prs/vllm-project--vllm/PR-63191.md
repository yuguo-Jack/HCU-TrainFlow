# [Security][CI/Build] Bump uv to 0.13.4 in CI scripts for eMudhra CA distrust

[Upstream PR](https://github.com/vllm-project/vllm/pull/63191) · state: closed · merged: True

## Original PR description

## Overview

Follow-up to #62868 (eMudhra CA compromise): bump the Rust CI script's uv pin to 0.13.4, the fixed version in [Python's guidance](https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576), and fix the release script's uv pin, which currently has no effect.

## Claims

- `run-rust-frontend-cargo-ci.sh` installs uv 0.11.28 via a versioned URL; uv < 0.13.4 still trusts the affected roots. Bumped to 0.13.4.
- `upload-release-wheels-pypi.sh` sets `UV_VERSION=0.11.14`, but uv's installer doesn't read that variable, so it has always installed the latest uv. Switched to the versioned installer URL so the pin is real (0.13.4).

## Validation

- `pre-commit run --files <changed files>`: passed (incl. shellcheck)
- `curl -sL https://astral.sh/uv/install.sh | grep -c UV_VERSION` → `0` (the variable is unused); `astral.sh/uv/0.13.4/install.sh` installs 0.13.4.

## Details

Pinning the release script makes it reproducible but means it needs bumping for future fixes. If you'd prefer it to keep tracking the latest uv, I'm happy to just remove the unused variable instead.

AI assistance (Claude) was used to investigate the issue and draft this description; I made and verified the changes.
