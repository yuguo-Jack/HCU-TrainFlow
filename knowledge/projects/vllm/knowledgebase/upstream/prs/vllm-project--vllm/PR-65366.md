# [Bugfix] Return 400 for empty DeepSeek V4.1 developer messages

[Upstream PR](https://github.com/vllm-project/vllm/pull/65366) · state: open · merged: False

## Original PR description



## Overview

Return HTTP 400 instead of 500 when empty or missing DeepSeek V4.1 developer content reaches rendering, without exposing the internal message dictionary. Fixes #65357.

## Claims

- Replace the assertion with a fixed-message `ValueError`, using existing HTTP error mapping.
- Preserve valid developer output and empty system content; leave global validation and other tokenizers unchanged.

## Validation

macOS arm64, Python 3.12.9, CPU. Reproduced on `eb409c9aa2f6acf9fcc45f45373e37d8da2d622b`; final branch rebased onto `b7486648bb027800e81d11ec51827a571d4f87a0`.

| Regression coverage | Before | After |
| --- | --- | --- |
| New tokenizer cases and controls | 2 failed (`AssertionError` with `_image_indices`), 2 passed | All pass; full tokenizer suite: 51 passed |
| Real `/v1/chat/completions/render` | 2 failed (`assert 500 == 400`) | 2 passed: 400, fixed error text, no dictionary |

Final combined run: **53 passed**. With the CPU virtualenv and source-only environment configured:

```bash
VLLM_TARGET_DEVICE=cpu ../../.venv/bin/python -m pytest \
  tests/tokenizers_/test_deepseek_v41.py \
  tests/entrypoints/scale_out/render/test_launch_render.py::test_empty_developer_content_returns_400 -q
```

Repository pre-commit checks pass, including Ruff lint/format, mypy, typos, Markdownlint, and CI test tethering.

Original `/v1/chat/completions` verification remains incomplete: attempts with a tiny local model and real weights failed during engine startup when the sandbox rejected POSIX shared-memory creation (`PermissionError` on `/psm_*`), before processing requests. No GPU execution or model evaluation was performed.

## Details

`AssertionError` maps to 500 and embeds the normalized `msg`, including `_image_indices`. An explicit `ValueError` maps to 400 without global handler changes.

Default thinking preprocessing can discard developer messages before the last user turn; this fix preserves that behavior and validates only messages reaching rendering. Tests use developer-only requests in chat mode.

The existing API-server integration job selects the HTTP tests via `entrypoints/scale_out`. Add the tokenizer suite to `cpu-reasoning-renderers`, remove its obsolete CI allowlist entry, and clarify the rendering condition in the docs. Fixtures use local config/tokenizer files without weights or downloads. Duplicate checks on 2026-11-03 found no open PR referencing #65357 or matching fix among related DeepSeek PRs.
