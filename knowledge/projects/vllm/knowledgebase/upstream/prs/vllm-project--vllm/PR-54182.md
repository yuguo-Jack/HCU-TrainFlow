## Overview

Add tuned Triton block-FP8 configurations for the Qwen3.5 GDN `in_proj_ba`
shape (`N=32, K=1024`) on NVIDIA H20 and RTX PRO 5000 72GB Blackwell.

## Claims

Earlier RTX PRO 5000 72GB Blackwell (SM120) hardware validation:

- 23 focused correctness and selector tests passed.
- Tuned/generic CUDA-graph speedups for M=1, 24, 128, 2048, 4096, and 8192
  were 2.50x, 2.50x, 2.50x, 1.67x, 2.00x, and 2.39x.
- Native CUTLASS returned `Invalid status` for `N=32, K=1024`, validating the
  guarded removal of that fallback on SM120.

Earlier H20 hardware validation measured a 2.62x arithmetic-mean speedup over
native CUTLASS for the target shape. Neither hardware benchmark was rerun for
the 2026-10-08 rebase.

Changed-file pre-commit hooks passed.

## Details

For exact BF16, static-128-block weight and dynamic-128-group activation
quantization:

- H20 prefers tuned Triton while retaining CUTLASS as a fallback.
- RTX PRO 5000 prefers tuned Triton and removes native CUTLASS from the fallback
  list because the SM120 CUTLASS kernel rejects this non-128-aligned N shape.
- Other shapes, dtypes, quantization schemes, devices, and explicit backend
  choices keep their existing behavior.

This does not duplicate #48588: that work addresses SM12x alignment/padding in a
different path, while this PR adds exact-shape tuned configs and an auto-selector
policy. Searches for `N=32,K=1024`, Qwen GDN FP8, H20, and SM120 selector terms
found no open PR implementing this change.
