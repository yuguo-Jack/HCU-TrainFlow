# [Bug]: Fix Rust vllm-bench missing usage.prompt_tokens

[Upstream PR](https://github.com/vllm-project/vllm/pull/59636) · state: open · merged: False

## Original PR description

**Title: [Bug]: Fix Rust vllm-bench missing usage.prompt_tokens**

**Description**
Fixes #59576

This PR resolves an issue in the Rust vllm-bench where total input tokens were being under-reported because it relied on a client-side estimate rather than the server-reported usage.prompt_tokens. This discrepancy became especially noticeable in random multimodal (VLM) benchmarks where image tokens were entirely missing from the client estimate, making Rust and Python benchmark results incompatible.

**Changes introduced:**

Backend (backends/mod.rs): Updated ChunkUsage struct to deserialize prompt_tokens: Option<u64>.
Streaming endpoints (openai_chat.rs & openai_completions.rs): Extracted prompt_tokens from the usage chunk and assigned it to output.prompt_len, superseding the initial client estimate.
Metrics (metrics/calculator.rs & metrics/steady_state.rs): Updated both the main calculator loop and the steady-state window logic to sum output.prompt_len (the actual server-reported length) instead of input_requests[i].prompt_len.
Preserves fallback behavior: if the server omits prompt_tokens, output.prompt_len retains the client-side estimate it was originally initialized with.
