- charxwu · comment · 2026-10-30T13:55:22Z · [source](https://github.com/vllm-project/vllm/pull/61798#issuecomment-6524528089)

Rebased onto main after #61794 merged. The lazy-offload restore now uses the exact-restore checks from #61794 under `VLLM_BATCH_INVARIANT=1`, through its own `lazy_umbp_llm` fixture:

- A 512-block GPU cache with `max_num_batched_tokens=1024`, so the default lazy scan (128 free-queue blocks) stores a finished prompt only once the GPU is about to reuse its blocks. Without the step that cycles the GPU cache, the test fails with zero external tokens.
- A 2 GiB pool, so MORI never evicts what that cycle stores.
- Identical tokens and logprobs and an exact external-hit count are required, both eagerly and with FULL decode CUDA graphs.

`test_umbp_lazy.py` is also added to the unit group's file list, since #64596 replaced the glob.

Tested on MI350X with MORI built with UMBP: unit 283 passed. The integration directory passed 9/9 on two GPUs, and the lazy restore passed every repeated run, eagerly and with FULL graphs.
