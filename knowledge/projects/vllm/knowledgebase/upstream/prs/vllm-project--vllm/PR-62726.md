# [Bugfix] Keep prompt logprobs when merging n>1 DELTA outputs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62726) · state: open · merged: False

## Original PR description



## Overview

A streaming `/v1/completions` request with `n > 1`, `echo` and `logprobs` can fail mid-stream with a 500 (`KeyError` in `_create_completion_logprobs`). It happens when the children of the request start generating in different engine steps.

In DELTA mode each child sends its prompt logprobs once, with its first output. The children share one `RequestOutputCollector`, and `OutputProcessor.process_outputs()` puts all outputs of an engine step into it before the server reads, so outputs of the same step are merged with `RequestOutput.add()`. When child 1's first token comes in the same step as a later token of child 0, `add()` keeps child 0's empty `prompt_logprobs` and drops child 1's. No timing between threads is needed for this; it follows from the children starting in different steps while child 0 is still generating. The server then echoes child 1's prompt with no prompt logprobs, the token and logprob lists are misaligned, and the lookup fails. This PR makes `add()` take the incoming prompt logprobs (and `prompt_token_id_logprobs`) when the merged output has none.

## Claims

- When the children start in different steps, each choice's echo now gets its prompt logprobs and the stream completes.
- Outputs that already carry prompt logprobs keep them. Nothing changes when both children start in the same step or when `n == 1`.

## Details

Why the children can start in different steps: with `echo`, `/v1/completions` sets `prompt_logprobs` (`completion/protocol.py`), and a request with prompt logprobs skips prefix-cache reads (`SamplingParams.__post_init__`), so each child runs its own prefill. When the step's token budget does not fit both prefills, the second child starts in a later step.

`OutputProcessor` pops the prompt logprobs into the first DELTA output of each child: `pop_prompt_logprobs()` leaves `[]` and `pop_prompt_token_id_logprobs()` leaves `None`. `RequestOutput.add()` already merges completions by index but never looked at the prompt fields. The fix fills each field only when the merged output's value is that empty value, so it does not overwrite prompt logprobs the merged output already has. All children share the same prompt, so either child's prompt logprobs serve for the echo. Any other DELTA consumer of an n > 1 request, such as a direct `AsyncLLM.generate` caller, now also receives the prompt logprobs in this case instead of an empty list.
