# [Bugfix][Test] Synchronise ranks before the profiled call in profile_…

[Upstream PR](https://github.com/vllm-project/vllm/pull/57001) · state: open · merged: False

## Original PR description

Adding a barrier before the profiled function, otherwise the jitter introduced by CUPTI startup from `torch.profiler.profile` impacts the dispatch duration.

Measured on 4 ranks in one node, profiling the same AllGather:

    rank 0   30.418 ms      rank 1    4.137 ms
    rank 2    0.036 ms      rank 3    3.842 ms

An 850x spread on one collective, where only the rank that happened to arrive last (rank 2) reports a meaningful number. With a barrier placed inside the profiler context, immediately before the profiled call:

    rank 0    0.034 ms      rank 1    0.105 ms
    rank 2    0.204 ms      rank 3    0.236 ms

Per-rank compute time is unchanged either way (0.064-0.070 ms), which is the check that this moves waiting out of the collectives without perturbing the work being measured.
