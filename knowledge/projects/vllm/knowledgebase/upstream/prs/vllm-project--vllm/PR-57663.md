# [V1] Add SamplingParams.hidden_state_window + position math for windowed hidden-state capture (#56916)

[Upstream PR](https://github.com/vllm-project/vllm/pull/57663) · state: closed · merged: False

## Original PR description

## Purpose

Implements the SamplingParams-level piece of #56916 (Windowed Hidden-State Collection for vLLM Rollouts): a response-relative `[start, end)` window, plus the interval math needed to map that window onto forward steps of varying size -- including speculative-decoding steps that accept a variable number of draft tokens per step.

**Not included yet:** the GPUModelRunner-side extraction (`_get_windowed_hidden_states_dict`, mirroring `_get_prompt_logprobs_dict`) and the hook into the three spec-decode branches in `_execute_model`. Opening now to get design feedback on the open questions raised on #56916 before building and testing that part against a real spec-decode run -- I don't have GPU access to validate it myself.

Checked for open PRs referencing #56916 immediately before opening this one -- none found.

Parts of this (the position-math module, its tests, and the SamplingParams field) were written with Claude's assistance. I've reviewed every line and can defend the design; the unresolved part is called out above rather than guessed at.

## Test Plan

18 passed in 0.19s

Covers ordinary decode, chunked prefill, every window/step boundary edge, and a simulated multi-step run mixing prefill + decode + variable-size spec-decode steps that reconstructs the requested window exactly, with no gaps or double-counts.
