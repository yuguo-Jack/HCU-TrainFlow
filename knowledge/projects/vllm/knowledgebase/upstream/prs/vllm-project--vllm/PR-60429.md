# [Bugfix][HiSparse] Drop the unaccounted, write-only prefill mirror staging buffer

[Upstream PR](https://github.com/vllm-project/vllm/pull/60429) · state: closed · merged: True

## Original PR description

## Purpose

`initialize_hisparse_runtime_buffers` allocates a per-layer prefill mirror staging buffer (`num_layers × max_num_batched_tokens × row_bytes`) after the KV cache is sized, so memory profiling never counts it. That's about 0.69 GiB per GPU for GLM-5.3 (78 layers).

Nothing reads it: `HiSparseConnectorWorker.start_step` sets `mirror_from_resident = True` every step, so the host mirror always copies from the resident cache, and only dummy batches ever wrote the buffer. This PR removes it, along with `mirror_write_target` and `mirror_from_resident`.

Related: #60420.

## Test Plan / Result

1×B200, GLM-5.3-NVFP4 cut to 8 layers with dummy weights, MNBT 16384, HiSparse with `host_pool_gib=24`. Measured persistent torch memory after init, excluding weights and KV:

| | allocated beyond weights + KV | KV budget |
|---|---|---|
| no HiSparse | 0.7031 GiB | 112.99 GiB |
| HiSparse, main | 0.7756 GiB | 112.96 GiB |
| HiSparse, this PR | 0.7052 GiB | 112.96 GiB |

- Greedy outputs are identical on main and this PR (4 prompts, 300–7000 tokens).
- `pytest tests/v1/worker/test_attn_utils.py -k "hisparse or profiling"`: 10 passed. The CUDA-only kv-update test now asserts only the resident write.
