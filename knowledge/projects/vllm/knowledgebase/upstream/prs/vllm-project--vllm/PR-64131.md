# [ROCm][CI] Keep nightlies off PR-writable images and trim the csrc cache key

[Upstream PR](https://github.com/vllm-project/vllm/pull/64131) · state: open · merged: False

## Original PR description

- `build.sh`: nightlies and branch builds reuse only `rocm/vllm-ci` images and cache, never read back `rocm/vllm-dev`, and write no cache of their own
- `build.sh`: the trust comment says the `pr<N>-`/`br-` prefixes keep names apart but isolate nothing, and that the per-commit test image is still pulled by tag
- `Dockerfile.rocm`: a new `csrc-inputs` stage hands the csrc compile only what `setup.py` reads from `pyproject.toml` and `envs.py`, and fails the build if the filtered `envs.py` would change a value `setup.py` reads
- `test_rocm_build.py`: only PR builds read back their own namespace, and nightlies still reuse `rocm/vllm-ci` images and cache

Every untrusted build pushes with the same `rocm/vllm-dev` credentials, so any PR could plant the `br-` images or cache an AITER nightly would reuse. Nightlies now take only what `rocm/vllm-ci` has. When a nightly's stack or runtime key is main's and CI has not pushed it yet, it waits for main's build of it (#63949) and builds it itself only if none is running; a branch whose stack or runtime inputs differ from main's now rebuilds them on every build. The nightly's per-commit test image is still pulled from `rocm/vllm-dev` by tag, and PR builds share the agents' buildkitd cache mounts with trusted builds as before, so both are left for ci-infra. Separately, 67 of the 240 commits on main that changed a csrc input over the last 60 days touched only `pyproject.toml` or `envs.py`, and each one recompiled all HIP code; replayed through the new filter, none of them changes the csrc inputs anymore. Follow-up to #61939; with main (and #63949) merged in, `pytest tests/tools/test_rocm_build.py` passes 41 tests in 10 runs out of 10.
