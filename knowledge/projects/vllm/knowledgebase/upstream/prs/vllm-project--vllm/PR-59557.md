# [Bugfix] Drop the dangling NO_ATTENTION backend registration

[Upstream PR](https://github.com/vllm-project/vllm/pull/59557) · state: open · merged: False

## Original PR description

## Purpose

Closes #59423.

`AttentionBackendEnum.NO_ATTENTION` pointed at
`vllm.v1.attention.backends.no_attention.NoAttentionBackend`, which has never existed. Backend paths
resolve lazily through `resolve_obj_by_qualname` (`registry.py:187` and `registry.py:253`), so the
member imported fine and would only have failed when something selected it.

Evidence that removing it is behaviour-neutral:

```console
$ grep -rn "no_attention\|NoAttention" . --exclude-dir=.git
vllm/v1/attention/backends/registry.py:136:    NO_ATTENTION = "vllm.v1.attention.backends.no_attention.NoAttentionBackend"
```

That enum line was the only occurrence in the tree — nothing selected it and no doc mentioned it.
@he-yufeng added the history on the issue: before the registry move (#25893) it was
`NO_ATTENTION = enum.auto()` in `vllm/platforms/interface.py` with no entry in the old
enum-to-path mapping, so selecting it already raised back then, and `no_attention.py` has never been
added on any branch (`git log --all --diff-filter=A` is empty).

Removing the member turns a `ModuleNotFoundError` into the normal unknown-backend path. If a real
no-op attention backend is wanted later it can land on its own with an implementation and tests.

## Changes

- Drop the `NO_ATTENTION` member from `AttentionBackendEnum`.
- Parametrize a test over `AttentionBackendEnum` and `MambaAttentionBackendEnum` asserting that each
  declared path names a module that actually ships, so the next stale entry fails at test time
  instead of on selection.

Two deliberate choices in the test:

- It reads `backend.value` rather than `get_path()`, so it validates the declared path and stays
  independent of the overrides that `register_backend` installs in neighbouring tests.
- It checks for the module file rather than importing it, so it runs without the device libraries
  each backend needs. Members whose value is `None` (`CUSTOM`) are filtered out at collection.

## Test Plan

```bash
pytest tests/test_attention_backend_registry.py -k registered_backend_module_exists -v
```

## Test Result

**I was not able to execute pytest for this change** — my machine has no CUDA build of vLLM, and the
test module imports `torch` at the top. What I did instead was run the test's exact logic over the
real enums with a static reader, which needs no imports:

```
before removing the member:  46 cases, 1 failure
  FAIL AttentionBackendEnum.NO_ATTENTION -> vllm.v1.attention.backends.no_attention
after:                       46 cases, 0 failures
```

So the invariant holds across every other registered backend, and `NO_ATTENTION` was the only entry
violating it. The pytest plumbing itself is unverified locally and needs CI.

## Not a duplicate

```console
$ gh api -X GET search/issues -f q='repo:vllm-project/vllm NoAttentionBackend' --jq .total_count
0
```

The seven hits for `NO_ATTENTION` are unrelated closed PRs from 2024–2025. #59423 is my own issue
for this, filed before writing the patch so a maintainer could pick a direction; I am sending the
removal because the issue has sat untriaged and this is the cheaper of the two options to review —
please close it in favour of adding a real backend if that is the preference.

One interaction worth flagging: #59425 (open) adds `NO_ATTENTION` to a `SKIP_BACKENDS` list in the
docs generator, guarded with a comment pointing here. If this lands first that entry becomes dead
config and I will drop it from that PR; if #59425 lands first this one still applies unchanged.

This change does not affect model output, accuracy or serving, so no model evaluation applies.
