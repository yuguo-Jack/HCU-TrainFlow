# [CI] Preserve DockerHub cleanup pagination across filtered pages

[Upstream PR](https://github.com/vllm-project/vllm/pull/62607) · state: open · merged: False

## Original PR description



## Overview

DockerHub cleanup stopped whenever a page contained no selected nightly tags, even if later pages remained. Follow the server pagination signal so old nightlies are included in the retention calculation, and abort before deletion if any page cannot be fetched or parsed.

## Claims

- Empty filtered pages no longer truncate the scan; the terminal page does not trigger an extra request.
- Retain the newest 14 matching tags and the existing architecture, nightly-dev and variant exclusions.
- A failed or malformed page prevents deletion using a partial inventory.

## Validation

```bash
.venv/bin/python -m pytest tests/tools/test_cleanup_nightly_builds.py -q
.venv/bin/python -m pre_commit run --files .buildkite/scripts/cleanup-nightly-builds.sh .buildkite/test_areas/misc.yaml tests/tools/test_cleanup_nightly_builds.py
bash -n .buildkite/scripts/cleanup-nightly-builds.sh
```

Original script: 6 failed, 1 passed. Changed script: 7 passed. All applicable hooks passed, including ShellCheck, mypy and Buildkite test tethering.

Tests execute the real shell CLI and jq with an offline curl fixture. They cover first/intermediate empty filtered pages, the retention and exclusion rules, and HTTP/JSON/error-response failures. No live DockerHub deletion was performed. The tests run in the existing CPU CI suite, whose image already includes jq.

## Details

Tag selection and pagination are separate operations: a page containing only other variants or protected tags still has to advance when `next` is present. Empty selections are not accumulated as blank tag rows.

The fetch and jq statuses are now propagated explicitly rather than masked by `local` assignments. Cleanup exits unsuccessfully before any deletion when the inventory is incomplete.

Duplicate checks found no open implementation using `"cleanup-nightly-builds"`, `pagination DockerHub`, and `cleanup nightly`. #55023 is the merged nightly-dev exclusion change; the current script still exhibits this pagination failure.
