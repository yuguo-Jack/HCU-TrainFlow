# [Rust Frontend] Export cache configuration metrics

[Upstream PR](https://github.com/vllm-project/vllm/pull/65462) · state: open · merged: False

## Original PR description

## Overview

Export `vllm:cache_config_info` from the Rust frontend using the capacity values
already received during engine startup, so dashboards can read each engine's
cache capacity. Closes #65277.

## Claims

- One gauge sample per engine, with value `1` and labels `engine`,
  `num_gpu_blocks`, `block_size`, and `kv_cache_size_tokens`.
- Reported zero capacity stays `"0"`; unavailable capacity is `"None"`, matching
  Python's encoding for these shared labels.
- Token capacity comes directly from the handshake, including hybrid capacities
  that differ from block count multiplied by block size.

## Validation

The regression checks final rendered metric samples for three distinct engines.
It fails on the original implementation because the metric is absent, and passes
with this change. Both affected crates' full CPU suites pass: **179 tests,
0 failures, 0 ignored**.

```bash
cargo test --manifest-path rust/Cargo.toml -p vllm-engine-core-client -p vllm-metrics --all-features --locked
cargo fmt --manifest-path rust/Cargo.toml --all -- --check
cargo clippy --manifest-path rust/Cargo.toml -p vllm-engine-core-client -p vllm-metrics --all-targets --all-features --locked -- -D warnings
```

All applicable pre-commit hooks pass. Local testing used Rust 1.95 and `cargo
test` because nextest was unavailable; the existing Rust Cargo CPU CI job runs
these tests with nextest. Python `CacheConfig.metrics_info()` was also executed
for the same values to check shared-label encoding.

Validation reaches handshake data through the real recorder and registry to
rendered OpenMetrics text. The HTTP scrape handler returns that text unchanged;
no live HTTP/GPU deployment is claimed. Model evaluation is not applicable to
this initialization-metadata change.

## Details

The handshake already carries all three capacity fields. Register the gauge
family with the scheduler metrics and populate it when the connected engines'
metric handles are created. This follows the existing startup metric pattern.
Rust exposes the handshake-available subset of Python's cache-config labels,
as documented in the metrics guide.

Issue/comment/timeline and keyword PR searches found no competing implementation;
#56515 concerns Python metrics documentation. Developed with AI assistance.
