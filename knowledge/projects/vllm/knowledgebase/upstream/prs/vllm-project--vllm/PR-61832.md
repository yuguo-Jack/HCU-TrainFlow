## Original PR description

## Purpose

Takes over #61476 (Kevin's batch 4), rebased onto main. This PR only enables `automatic_shard`; it changes no tests. Kevin's commit is unchanged apart from a conflict where main made `elastic-ep-scaling-test` nightly-only (`optional: true`) on the line where the flag goes; both lines are kept.

| Step | Command | Shards in #61476's build |
|---|---|---:|
| `e2e-scheduling-accuracy-1-gpu` | one `pytest` over `v1/e2e/general` scheduling tests | 3 |
| `lm-eval-qwen3-5-models-2xb200` | one `pytest` over `evals/gsm8k` | 2 |
| `spec-decode-draft-model-nightly-b200` | one `pytest` | 2 |
| `elastic-ep-scaling-test` | two `pytest` commands | 2 |

**AMD mirrors.** Two of these steps have AMD mirrors that run past the 20-minute target as one job, so they are enrolled too (`automatic_shard: true` in `mirror.amd`; both already have `dind: false` and no fixed `parallelism`):

| Mirror | Planned shards |
|---|---:|
| `amd-e2e-scheduling-accuracy-1-gpu` | 2 |
| `amd-lm-eval-qwen3-5-models-2xb200` (optional) | 3 |

In both, one test takes about 20 minutes by itself, so the slowest shard sits right at the target and can't go lower without splitting that test. `spec-decode-draft-model-nightly-b200`'s mirror already runs under 20 minutes; `elastic-ep-scaling-test` has no AMD mirror.

Left out: `kv-offload-large`. Its two tests land one per shard, so each shard repeats the 4-GPU model startup for a few minutes of wall time on a nightly-only step.

## Test Plan

- Build [94970](https://buildkite.com/vllm/ci/builds/94970) of #61476: every shard passed, with per-command passed/skipped counts equal to main's single job. No test ran twice. One test in `e2e-scheduling-accuracy-1-gpu` skipped instead of passing because its shard landed on a host where the GPU memory query isn't permitted; that host issue affects main too.
- Three of these steps are `optional`, so `/ci run` leaves them behind a block step without sharding them. A build scoped to them with `VLLM_CI_ONLY_STEP_KEYS` re-checks the shards on this head.
- The two AMD mirrors: rendered with the pipeline generator and ran every shard's commands against a mock test tree, as a PR build and in main's OTel mode; every test ran in exactly one shard. `/ci run` exercises the E2E Scheduling Accuracy mirror; the Qwen3.5 mirror is optional and needs the scoped build.
