# [Bugfix][Model Runner V2] Profile the batch-sharded all-to-all before sizing the KV cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/61025) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

With `--enable-batch-sharded-sampling` (#50465), the memory profile run samples through the gathered `compute_logits` path. So the sharded path's `all_to_all_single` first runs in the kernel warm-up, after the KV cache has already taken the memory budget. On memory-tight GPUs, NCCL then cannot allocate its all-to-all buffers, and start-up fails. This PR makes `_dummy_sampler_run` call `sample()`, so the profile run takes the sharded path (all-to-all, local sampler, output gather) and those buffers exist before the KV cache is sized.

## Claims

- With batch-sharded sampling on, the profile run executes the same all-to-all as serving. NCCL's buffers for it are then counted in the memory profile, not allocated after the KV cache.
- No change when the flag is off.

## Validation

**Reproducer (measured):**

The current revision reaches that sequence through `sample()` (review suggestion) and also runs the output all-gather. I have not re-run the end-to-end test on the current revision.
- Start-up passes warm-up on all 8 ranks. All ranks log "Batch-sharded sampling enabled.", there is no NCCL OOM, and the server answers requests.

## Details

- **Root cause:** `profile_run` → `_dummy_sampler_run` always called `self.model.compute_logits` (all-gather) and the sampler. `torch.distributed.all_to_all_single` on the TP device group allocates its NCCL point-to-point buffers on first use. That first use was in `warmup_kernels`, which runs after `determine_available_memory` and the KV cache allocation.
- **Fix:** `_dummy_sampler_run` calls `self.sample(hidden_states, dummy_input_batch, None)` for the default pass and the warmup-param pass, so it stays in sync with `sample()`. All ranks reach the collectives, because `profile_run` runs on every worker.
- **Ranks with no dummy request:** `sample()` skips the local sampler on a rank that owns no request. When the dummy batch has fewer requests than TP ranks (`max_num_seqs < tp_size`), some ranks own no dummy request, but they can own a real request later. A rank for which the new `BatchSharder.num_local_reqs(idx_mapping_np)` returns 0 runs its local sampler once more on a one-row dummy batch (slot 0 has the warmup params). `num_local_reqs` uses the same owner lookup as `shard_sampler_inputs` (now shared in `BatchSharder._req_owners`), so the model runner does not depend on the assignment rule. Ranks can take different branches, because the fallback runs only the local sampler and has no collective. The one-row batch is built after both `sample()` passes, because `InputBatch.make_dummy` rewrites the shared `input_buffers`.
- **Size:** +12 / −4 lines in `vllm/v1/worker/gpu/model_runner.py` (profile path only) and +18 / −9 lines in `vllm/v1/worker/gpu/sample/batch_shard.py`.
- **Trade-off:** the KV cache is smaller by the size of the NCCL all-to-all buffers. That memory was needed anyway; without the fix, start-up fails instead.
