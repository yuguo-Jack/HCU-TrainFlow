# [CI] Shard the AMD mirrors of Basic Models (Other) and PCP automatically

[Upstream PR](https://github.com/vllm-project/vllm/pull/61904) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Next AMD batch after #61817, #61860, #61861 and #61862. Turns on `automatic_shard` for the native AMD mirrors of two steps whose CUDA side already shards. Only the flag changes; no commands or tests. Two mirrors from the original batch dropped out on rebase: main already enrolled `amd-model-executor` and disabled Batch Invariance (#63609).

## Claims

| Mirror | Command shape | Shards |
|---|---|---:|
| `amd-pipeline-context-parallelism-4-gpus` | three `pytest` file commands, 4 GPUs per shard | 3 |
| `amd-basic-models-tests-other` | `pytest` over a list of model test files, plus a `VLLM_ROCM_USE_AITER=1` command with `-m` | 2 |

- Every test runs exactly once across the shards, with the same environment as main's single job.
- Each mirror finishes in well under half of main's single-job time, for about the same machine time.

## Validation

- `/ci run` [97473](https://buildkite.com/vllm/ci/builds/97473), rebased on main after ci-infra#836: every shard passed, with passed/skipped totals equal to main's single job in [97527](https://buildkite.com/vllm/ci/builds/97527), and machine time within a few percent of it.
- Rendered each mirror with the pipeline generator and ran every shard's commands against a mock test tree, as a PR build and with main's `pytest -p ci_otel` wrapper: every test of every command ran in exactly one shard, with the same env.

## Details

- **Timeouts unchanged (human).** As in #62077 and #62120, `timeout_in_minutes` stays per job; fallback-aware timeouts belong in a central timeout setting.
