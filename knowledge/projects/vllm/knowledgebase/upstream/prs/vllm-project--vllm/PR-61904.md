## Original PR description

## Purpose

Next AMD batch after #61817, #61860, #61861 and #61862. Turns on `automatic_shard` for the native AMD mirrors of four steps whose CUDA side already shards (#61202, #61474, #61475). Only the flag changes; no commands or tests.

| Mirror | Command shape | Planned shards |
|---|---|---:|
| `amd-model-executor` | `export` setup, `pytest` over `model_executor` with `-m '(not slow_test)'`, plus one file | 4 |
| `amd-basic-models-tests-other` | `pytest` over a list of model test files, plus a `VLLM_ROCM_USE_AITER=1` command with `-m` | 2 |
| `amd-batch-invariance-b200` | `export` and `pip install` setup, `VLLM_TEST_MODEL=...` prefixes, test IDs with `-k` | 2 |
| `amd-pipeline-context-parallelism-4-gpus` | three `pytest` file commands, 4 GPUs per shard | 3 |

## Test Plan

- Planned each mirror with ci-infra main's `runtime_shard.plan_step` against this branch and main's `amd-<key>` timings on the mirror's own queue.
- Rendered each mirror with the pipeline generator and ran every shard's `VLLM_TEST_COMMANDS` against a mock test tree, as a PR build and with main's `pytest -p ci_otel` wrapper: every test of every command ran in exactly one shard, with the same env.
- `/ci run`, then compare each mirror's shards against its single job on main.
