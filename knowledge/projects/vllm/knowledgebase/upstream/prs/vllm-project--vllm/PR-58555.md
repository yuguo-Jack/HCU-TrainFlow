# [ROCm][MLA] Route gfx942 DCP causal multi-token verify to Triton split-KV decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/58555) · state: closed · merged: True

## Original PR description

## Purpose

On gfx942, `ROCM_AITER_MLA` has no kernel for DSpark/MTP target verify under DCP
(causal qlen > 1 on a sharded KV cache): no ASM heuristic, no cprr kernels, and
AITER segmented MLA exceeds gfx942's 64 KiB LDS (`OutOfResources: Required:
131072`) for bf16 KV at TILE-128 and for fp8 KV with 128 heads.

This PR adds a `TRITON` DCP route for that shape only. It runs the existing
split-KV `decode_attention_fwd` over the rank-local verify rows, and the MLA
layer merges the per-rank fp32 LSEs as before. Empty shards return LSE = −inf
and get zero weight, so no masking is needed.

The split count is capped by batch occupancy. Without the cap, max-batch scratch
is 8–16 GiB and overflows the kernel's int32 offsets; with it, 0.25 GiB and
equal or faster.

Unchanged: qlen == 1, non-causal, replicated-KV DSpark, gfx950, and TRITON_MLA
(its `forward_mqa` moves into the shared helper with the same behaviour).

Serve command that fails:
```
vllm serve moonshotai/Kimi-K3 \
    --served-model-name kimi-k3 \
    --tensor-parallel-size 8 \
    --enable-expert-parallel \
    --decode-context-parallel-size 8 \
    --dcp-comm-backend a2a \
    --trust-remote-code \
    --reasoning-parser kimi_k3 \
    --mm-encoder-tp-mode data \
    --max-model-len 135168 \
    --max-num-seqs 8 \
    --max_num_batched_tokens 4096 \
    --gpu-memory-utilization 0.90 \
    --no-enable-prefix-caching \
    --quantization-config '{"moe":{"weight":"int4_per_group_32"}}' \
    --compilation-config '{"cudagraph_mode":"FULL_AND_PIECEWISE"}' \
    --speculative-config '{"method": "dspark", "model": "Inferact/Kimi-K3-DSpark", "num_speculative_tokens": 5, "attention
_backend": "TRITON_MLA", "draft_sample_method": "probabilistic", "rejection_sample_method": "block"}' \
    --host 0.0.0.0 \
    --port 8000
```

## Test Plan

pytest tests/v1/attention/test_rocm_aiter_mla_{dcp_cprr,fp8_decode_routing,mtp_split,dcp_cprr_numerics,dcp_verify_gfx942}.py

`test_rocm_aiter_mla_dcp_verify_gfx942.py` is the regression test. It runs the
real AITER builder and `forward_mqa` for all 8 DCP ranks and checks the merged
output against causal attention:

| Case | main | this PR |
|---|---|---|
| Kimi-K3: 96 heads, bf16 KV, qlen 6, 768-token blocks | `OutOfResources` | pass (Triton) |
| DeepSeek-V3: 128 heads, fp8 KV, qlen 2, 16-token blocks | `OutOfResources` | pass (Triton) |
| 96 heads, bf16 KV, 64-token blocks | pass | pass (segmented, unchanged) |

`test_segmented_lds_gate_matches_the_kernel` compiles the AITER kernel at the
boundary shapes and checks the gate against the actual compile result.
