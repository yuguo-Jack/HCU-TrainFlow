# [Bugfix][V1] Handle shutdown during collective RPC

[Upstream PR](https://github.com/vllm-project/vllm/pull/56976) · state: open · merged: False

## Original PR description

## Purpose

Addresses Bug3 in #56251.

`MultiprocExecutor.collective_rpc()` checks `is_failed` before serializing
callable RPCs. If a worker fails during serialization, the monitor thread can
shut down the executor and clear `rpc_broadcast_mq`. The RPC then attempts to
call `enqueue()` on `None`, producing a misleading `AttributeError`.

This change snapshots and rechecks the broadcast queue after serialization,
so this race follows the existing `RuntimeError("Executor failed.")` failure
contract.

This does not duplicate existing work: #56282 addresses Bug1, #56336
addresses Bug2, and #56854 addresses Bug5. No open PR addressing Bug3 was
found.

## Test Plan

- Add a deterministic CPU-only regression test that pauses callable

- Verify that the old implementation raises `AttributeError`.
- Verify that the fixed implementation raises `RuntimeError`.
- Run the executor unit tests and applicable lint/type checks.
