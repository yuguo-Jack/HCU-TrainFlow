# [Frontend][Rust][Multimodal] Add Gemma 4 image support / multimodal model spec

[Upstream PR](https://github.com/vllm-project/vllm/pull/58649) · state: open · merged: False

## Original PR description


## Purpose
Fixes #58580

This PR adds Gemma 4 multimodal model processor specification and vision preprocessor support to the Rust frontend (`vllm-chat`).

### Changes
1. **Aspect-Ratio-Preserving Size Calculation**: Implements `get_aspect_ratio_preserving_size` and `compute_num_soft_tokens` matching the Gemma 4 vision encoder geometry (`patch_size`, `pooling_kernel_size`, `max_soft_tokens`).
2. **Gemma 4 Vision Preprocessor**: Implements `Gemma4VisionProcessor` adhering to the vision tower input schema (`pixel_values` of shape `[batch, max_patches, patch_pixels]` with zero-padding and `pixel_position_ids` with `(col, row)` coordinates and `(-1, -1)` for padding patches).
3. **Dynamic Prompt Replacement**: Generates dynamic image placeholder expansions (`[boi_token_id] + [image_token_id; num_soft_tokens] + [eoi_token_id]`) where only `image_token_id` soft tokens are marked for embedding substitution.
4. **Registry Fallback**: Wires `Gemma4Spec` as an in-tree fallback in `resolve_model_spec` so that `gemma4` and `gemma4_unified` models resolve their multimodal spec directly in the Rust frontend.
