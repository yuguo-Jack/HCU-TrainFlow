# [CPU] Share FP8 MoE projections and enable native MXFP4 W4A8

[Upstream PR](https://github.com/vllm-project/vllm/pull/63424) · state: open · merged: False

## Original PR description



## Overview

Share CPU FP8/MXFP4 MoE projection execution and automatically use MXFP4 W4A8 on CPUs with native AMX-FP8 support. Extend FP8 W8A8 MoE to quantize down-projection activations, and retain explicit MXFP4 W4A16 selection through `--moe-backend cpu_mxfp4_bf16`.

## Claims

- At measured pre-rebase head `eeb4c767b7`, GPT-OSS-20B batch output throughput improves **37.0%** versus same-head explicit W4A16, and Qwen3-30B-A3B-FP8 improves **4.1%** versus `ff01a6b14f`. GPT-OSS single-request latency changes by less than 1% in all three pairs.
- FP8 and MXFP4 experts share projection, routing and panel-cache code, with independent projection biases and SiLU, exact GELU and GELU-tanh support; MXFP4 also retains GPT-OSS SwiGLU.
- MXFP4 W4A8 supports tensor parallelism, retains BF16 computation for tiny experts, and falls back to W4A16 without native FP8 support.

## Details

The existing FP8 W8A8 path quantizes incoming activations per token but computes the down projection with BF16 intermediate activations. The shared projection implementation extends FP8 execution to that second stage and reuses it for MXFP4 weights, with channel normalization and block fallback for scale ranges that cannot safely use E4M3.

MXFP4 experts with at most four routed rows retain BF16 computation and unquantized intermediate activations; larger experts use FP8 for both projections. CPU W4A8 requires BF16 inputs and does not support EP. Defaults and precision tradeoffs are documented in `docs/features/quantization/online.md`.

CPU postprocessing replaces byte-zero down-projection scales with the channel maximum only for groups containing entirely zero FP4 weights. This preserves their zero contribution while preventing padded groups from forcing block normalization.

FP8 bias conversion moves into expert construction because the factory did not invoke the former loading hook. Both projection biases are handled independently and covered through the real factory path.

Builds on merged [#49942](https://github.com/vllm-project/vllm/pull/49942) and [#50949](https://github.com/vllm-project/vllm/pull/50949). October 23 open-PR searches found no duplicate; no issue is associated with this branch. [#61346](https://github.com/vllm-project/vllm/pull/61346) targets BF16 fallback without AMX, a different scope.
