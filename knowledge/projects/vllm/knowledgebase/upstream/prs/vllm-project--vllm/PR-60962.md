# [Bugfix][Frontend] Resolve and attach logprobs on streaming parser derender path

[Upstream PR](https://github.com/vllm-project/vllm/pull/60962) · state: closed · merged: False

## Original PR description

## Purpose
Fixes the missing logprobs on the streaming parser derender path noted in RFC #47161 and PR #55029 ("That parsed path does not resolve logprobs yet; when it does, mirror the generate chat streaming path...").

Previously, `_derender_chat_stream_parsed()` in `OnlineDerenderer` dropped incoming logprobs from `GenerateTokensStreamChoice` and constructed `ChatCompletionResponseStreamChoice` without resolving or attaching them. 

This PR:
1. **Resolves logprobs on the parsed path**: When `choice.logprobs` is present, resolves them via `_resolve_logprobs` with the carried context and attaches them to `ChatCompletionResponseStreamChoice`.
2. **Honors reasoning privacy**: Aligns with `OpenAIServingChat.chat_completion_stream_generator` by suppressing logprobs (`resolved_logprobs = None`) when `include_reasoning=False`, preventing leakage of hidden reasoning tokens through logprob entries.
3. **Preserves cross-chunk context**: Updates `stream_state.logprob_context_token_ids` in `_derender_chat_stream_parsed` so byte-fallback (U+FFFD) decoding remains consistent across chunk boundaries.
4. **Updates documentation**: Updates `derenderer.md` to document that both plain and parser-configured streaming derender paths resolve logprobs, and notes the reasoning-suppression behavior.
