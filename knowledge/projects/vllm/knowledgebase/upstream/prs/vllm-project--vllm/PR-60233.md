# [Security] Fix ReDoS in error message path sanitizer

[Upstream PR](https://github.com/vllm-project/vllm/pull/60233) · state: open · merged: False

## Original PR description

## Overview

Fixes superlinear regex backtracking in `sanitize_message` (GHSA-f2g9-pmwr-xwc7). A long run of `/segments` in a client-controlled string, such as the `model` field, can stall the API server's event loop for minutes. This is a follow-up to #52120, whose fix is skipped only when the message has no `.`. Any message containing a `.`, including every model-not-found error, still takes the slow path.

## Claims

- `sanitize_message` now runs in linear time on hostile input. A 2 MB path run takes 0.13 s; on `main`, 16 KB takes 34 s.
- What gets redacted is unchanged: 0 output differences from `main` across 300,000 random inputs.
- The `"." in message` bypass of #52120 no longer applies. The new pattern is linear whether or not the message contains a dot.

## Details

**Root cause.** `(?:/[\w\-]+)+/[\w\-]+\.\w+` requires a file extension at the end of a run of `/segments`. When the run has none, the engine tries every split between the repeated group and the final segment, fails, and starts over from the next `/`. Cost grows at least quadratically with the run length (about n^2.8 measured with `regex`). `request.model` is echoed in "The model `…` does not exist." (`vllm/entrypoints/serve/engine/serving.py`) with no length limit. `sanitize_message` runs synchronously on the API server's event loop, so a single request blocks all others. The validation-error path is not affected because it already truncates echoed input to 200 characters.

**Fix.** `(?:/[\w\-]+)+(\.\w+)?` always matches a whole run, so the scanner never revisits it. A callback redacts the match only when it has an extension and at least two segments, which is the same condition the old pattern enforced.

**Alternatives considered.**
- Atomic groups or possessive quantifiers (the #52120 approach): these stop backtracking within one attempt, but the scan still restarts at every `/`, so it stays quadratic. A possessive variant took 313 s at 100K segments.
- A `"." in message` pre-check: bypassed by any dot, and every model-not-found message ends with one.

**Relation to #52120.** Same goal, different fix. That PR has had merge conflicts since `sanitize_message` moved in #52261, and its fix doesn't hold whenever the message contains a dot (see the table). If maintainers prefer, this pattern can be folded into #52120 instead.
