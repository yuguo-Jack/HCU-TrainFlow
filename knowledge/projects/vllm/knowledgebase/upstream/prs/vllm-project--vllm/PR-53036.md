# [Attention][Spec Decode] Enable varlen Mamba2 decode for adaptive verification

[Upstream PR](https://github.com/vllm-project/vllm/pull/53036) · state: closed · merged: True

## Original PR description

## Purpose

- Resolves #51868: adaptive verification needs Mamba decode batches with per-request query lengths
- Audit: the Mamba2 decode kernels already handle ragged batches from device offsets, so this is wiring only
- Flip `supports_device_cpu_query_lens_mismatch` on Mamba2; ReplaySSM still opts out
- Keep `UNIFORM_BATCH`; bound varlen FULL decode graphs via `get_varlen_cudagraph_max_query_len` = `max_decode_query_len` (#57263)
- Not a duplicate: no open PR touches Mamba varlen decode

## Test Plan

- `pytest tests/kernels/mamba/test_causal_conv1d.py` with new ragged-varlen test + uniform regression (L4)
- SSU ragged coverage already exists upstream
- Kernel perf: ragged/trimmed vs uniform-padded at Nemotron-H shapes (B200)
- E2E: Nemotron-3.5-Lightning-30B-A3B + MTP k=8, AV on/off, GSM8K 200 (B200)

One change before merging: please don't report `AttentionCGSupport.ALWAYS` from `get_cudagraph_support`. Mamba can't run mixed prefill batches in FULL graphs; this only works today because adaptive verification forces FULL_AND_PIECEWISE.

#57263 added `get_varlen_cudagraph_max_query_len` for this case. Please:
- Drop the `get_cudagraph_support` override and keep `UNIFORM_BATCH`.

- Drop the relaxed assert in `build_for_cudagraph_capture` if it's no longer needed (varlen capture passes `max_query_len = decode_query_len`).

Hi @tomasruizt Just ran your command on B200 (V2 runner, TRITON_ATTN, MTP k=8, this PR on top of 88aa0d287d).

Without this PR, startup fails: `Adaptive verification trims verification requests on device, which the Mamba2AttentionBackend attention backend does not support.` With this PR it serves correctly. GSM8K 200q: 191/200 with AV vs 190/200 without.

Throughput with GSM8K prompts, max_tokens 512, average of 2 runs (out tok/s, AV vs no AV):

| conc | AV | no AV | diff | mean accept len (AV / no AV) |
|---|---|---|---|---|
| 1 | 669 | 722 | -7% | 5.24 / 5.44 |
| 8 | 2597 | 2677 | -3% | 5.40 / 5.48 |
| 32 | 4935 | 6211 | -21% | 5.21 / 5.37 |
| 64 | 9707 | 8931 | +9% | 5.09 / 5.40 |
| 128 | 14876 | 12112 | +23% | 4.95 / 5.42 |

The direction is consistent across both runs, but the magnitude is noisy. AV helps at high concurrency and costs a bit at low/mid concurrency. I have not checked whether the conc 32 dip is specific to Mamba, or whether AV with MTP does the same on a pure-attention model.
