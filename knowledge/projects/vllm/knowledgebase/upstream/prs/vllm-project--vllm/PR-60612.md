# [Security] Isolate OpenCV video decode in a child process

[Upstream PR](https://github.com/vllm-project/vllm/pull/60612) · state: open · merged: False

## Original PR description

## Summary
Malformed video containers can native-fault inside OpenCV/FFmpeg while the default video backend opens request bytes in the API server process, taking down the listener. OpenCV decode now runs in a spawn-context process pool so a child abort becomes a request `ValueError` and the server stays up.

## Changes
- `vllm/multimodal/video_decoders/opencv.py`: run `decode_opencv` via an isolated process pool; map `BrokenProcessPool` to a fail-closed `ValueError` and recreate the pool.
- Tests covering worker abort containment, happy-path out-of-process decode, and the `VideoMediaIO` entry point.

## Codepath coverage
- Chat / messages / responses / batch / `/invocations` / gRPC / offline `LLM.generate` that reach `VideoMediaIO` → OpenCV `decode_opencv`: covered.
- `opencv` and `opencv_dynamic` (and other loaders that select the OpenCV codec via `backend="opencv"`): covered at the shared `decode_opencv` sink.
- `video/jpeg` and TorchCodec / PyNvVideoCodec / DeepStream: N/A (do not call `decode_opencv`).
