# [Deprecation] Deprecate LM Format Enforcer structured outputs backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/63423) · state: closed · merged: True

## Original PR description

## Overview

Deprecate the `lm-format-enforcer` structured outputs backend with a configuration-time warning and online/offline migration guidance. Propose warnings in v0.33.0, explicit opt-in in v0.34.0, and removal in v0.35.0; this PR implements only the warning stage.

## Claims

- Selecting LM Format Enforcer emits a once-per-process deprecation warning with the removal version and a migration link.
- Existing backend selection, dependencies, and decoding behavior remain unchanged.
- CLI/config reference documentation and the structured outputs feature page explain the migration to `auto`, `xgrammar`, or `guidance`.

## Validation

- `.venv/bin/pre-commit run --files vllm/config/structured_outputs.py docs/features/structured_outputs.md`: passed all applicable hooks, including mypy.
- CLI smoke check through `EngineArgs.add_cli_args`, `from_cli_args`, and `create_structured_outputs_config`: passed. Verified LMFE selection remains accepted, the warning includes v0.35.0 and migration guidance, repeated configuration emits no duplicate warning, other backends emit no warning, and the compilation hash is unchanged.
- `.venv/bin/python -m pytest tests/v1/structured_output/test_validation.py tests/engine/test_arg_utils.py -q`: 183 passed, 14 upstream Torch deprecation warnings, in 35.51s.
- Model evaluations were not run: this change only logs a configuration warning and updates documentation; it does not alter token filtering, backend selection, or generation. No output-equivalence or performance claim is made for switching backends.
- Local documentation discoverability review passed. Web/docs-preview and GitHub branch discovery await publication.

## Details

The motivation is to consolidate structured-output backend maintenance around XGrammar and Guidance. This does not assert that the upstream LMFE project is abandoned. The existing LMFE generation cases in `tests/entrypoints/llm/test_struct_output_generate.py` are already skipped for incomplete JSON (upstream issue https://github.com/noamgat/lm-format-enforcer/issues/169); this PR does not change those skips or resolve that issue.

Users should validate their schemas, regex patterns, and generated outputs before switching: backend support and formatting differ, including Python-style versus Rust-style regex syntax. The backend and dependency stay installed throughout this initial warning stage. The opt-in gate and removal require later PRs and minor releases under the deprecation policy; maintainers should confirm the proposed schedule before merging.

Duplicate checks found no open LMFE deprecation PR. Reviewed https://github.com/vllm-project/vllm/issues/52614 and its comments, and searched open PRs for `52614 in:body`, `lm-format-enforcer`, and structured-output deprecation keywords. https://github.com/vllm-project/vllm/pull/52661 fixes a tokenizer import compatibility issue; it is complementary maintenance during the grace period, not a duplicate of this lifecycle change. This PR does not close that issue.
