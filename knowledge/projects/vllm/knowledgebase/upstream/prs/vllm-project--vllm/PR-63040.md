# [ROCm][DeepSeek-V4] Add TP8 MegaMoE backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/63040) · state: open · merged: False

## Original PR description

## Scope

Draft opt-in `aiter_mega_moe_tp` backend for original DeepSeek-V4-Pro on gfx950 TP8/DP1. This is separate from MiMo TP8 MegaMoE (#63039) and MiMo mono MLP (#63034).

Controls:

- `VLLM_ROCM_TP_MEGA_MOE_ACT_DTYPE=fp8|fp4`
- `VLLM_ROCM_TP_MEGA_MOE_COMM_DTYPE=bf16|fp8`
- `VLLM_ROCM_TP_MEGA_MOE_AR_GATHER=bf16|fp8|auto`

FP8 uses Mega for padded M<=256 and falls back to ordinary AITER above that. FP4 is explicit precision-changing mode.

## Validation

- focused model contract tests: 24 passed;
- real gfx950 TP8 numeric/graph probes, two layers and M=1,3,16,48,96,256,8192;
- FP8 rel-L2 <=0.0383; FP4 rel-L2 <=0.0352; gate=0.06;
- cross-rank equality, graph replay, weight rebinding and native FP8 shared expert covered.

## Remaining before review

The isolated full GSM8K and serving A/B results are attached below. The measured C16 8K/1K workload regresses in throughput for both MegaMoE variants, so this is not a performance-acceptance pass. Investigate the regression and post-evaluation worker teardown before promoting this draft. Single-run accuracy differences do not establish equivalence; broader workloads and any whole-PR-versus-upstream claim need separate validation.
