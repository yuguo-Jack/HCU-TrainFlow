# [Perf][Model] Qwen4Exp QSA: SM80 launch config for indexer prefill scoring

[Upstream PR](https://github.com/vllm-project/vllm/pull/62344) · state: open · merged: False

## Original PR description



## Overview

On A100 (sm_80), the Qwen4Exp QSA indexer prefill scoring kernel `_qsa_mqa_paged_prefill_kernel` uses the GB300 launch config (16 K tiles per CTA), which leaves most of the 108 SMs idle. This PR adds an sm_80 config for the BF16 indexer cache and one warp per row for the compressor kernel on sm_80. Both keep the output bit-equal.

## Claims

- Indexer prefill scoring on A100, upstream TP8 shapes, 32k context: **2.03×** for a 512-token chunk, **1.50×** for a 2048-token chunk; the logits are bit-equal.
- `_compress_qsa_groups_kernel` on A100: 1.05–1.32× with one warp per row; bit-equal.
- No change on other GPUs, for the FP8 indexer cache, or for any other QSA kernel.

## Validation

**Kernel benchmark** (1 × A100-SXM4-40GB; Qwen3.8-Flash QSA per-GPU shapes at TP8 read from the model config; the wrapper's exact launch re-run with only the launch kwargs changed; CUDA graph of 20 calls, 128 MB L2 flush before each of 5 replays, median; each config's output compared with the default's).

| Kernel | Scenario | Before (GB300 config) | This PR | Speedup | Output |
|---|---|---|---|---|---|
| indexer prefill scoring | 512-token chunk at 32k | 87.4 µs | 43.0 µs | 2.03× | bit-equal |
| indexer prefill scoring | 2048-token chunk at 32k | 212.5 µs | 141.7 µs | 1.50× | bit-equal |
| compress groups | decode, 8k / 32k / 128k | 5.89 / 4.04 / 3.89 µs | 5.53 / 3.53 / 3.69 µs | 1.07 / 1.14 / 1.05× | bit-equal |
| compress groups | prefill 512 / 2048 | 4.86 / 9.98 µs | 3.99 / 7.58 µs | 1.22 / 1.32× | bit-equal |

The same sweep at DCP 4 shapes (with the open QSA DCP PRs, where each rank scores a quarter of the states) gives 4.38× (512-token chunk) and 1.72× (2048) for the indexer prefill scoring with this config family.

For the BLOCK_N choice: the sweep's best config was BLOCK_N 128 with 2 K tiles at both main-shape points (and 4 K tiles at 2048, 1.59× against this PR's 1.50×). At the DCP4 512-token point (4× fewer columns), BLOCK_N 32 won; the CTA-count rule picks BLOCK_N 128 when that grid gives at least 2 CTAs per SM and BLOCK_N 32 otherwise, which selects the winner at all four measured points.

Per 12 QSA layers, the indexer change saves about 0.5 ms per 512-token prefill chunk and 0.85 ms per 2048-token chunk on A100.

**Tests:** new CPU test `test_qsa_prefill_scoring_launch_config` in `tests/models/qwen4_exp/test_qsa_reference.py` (selection per GPU and cache dtype). It has not run in our environment (the vLLM test environment there could not import the newer `main` tree); it relies on CI.

**Not done:** end-to-end serving A/B; GPUs other than A100 (the change applies to capability 8.0 only); `pre-commit` (ruff not available on the machine used).

## Details

- `_prefill_launch_config(num_requests, query_rows, logits_width, cache_dtype)` returns the launch kwargs; on other GPUs it returns the existing GB300 values, so `_prefill_logits` behaves as before there.
- Measured but left out: decode scoring and sparse-attention split counts. Their best configs differ between shapes (sparse attention: 8 splits at upstream shapes, 2 at DCP4 shapes), and a split change also changes the summation order.
