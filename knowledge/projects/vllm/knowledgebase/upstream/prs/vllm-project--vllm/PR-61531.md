# [Bugfix][NIXL] Transfer Mamba2 conv state across TP sizes when B/C are replicated

[Upstream PR](https://github.com/vllm-project/vllm/pull/61531) · state: open · merged: False

## Original PR description



## Overview

Fixes #61526. Under heterogeneous TP, NixlConnector silently transferred the wrong Mamba2 conv state when TP does not divide `n_groups` (e.g. granite-4.0-h, `n_groups=1`), so decode output was wrong with no error. With this PR, D reads each conv sub-projection (x, B, C) from the P rank that holds it, also when B/C are replicated across ranks.

Not a duplicate: there is no other open issue or PR for this. The KV checksum PRs (#61488, #62211) carry the same TP-split declaration because checksums need it too (see Details).

## Claims

- NIXL pull transfers Mamba2 conv state correctly across different P/D TP sizes, including replicated B/C (`n_groups % tp != 0`).
- Offsets are unchanged whenever no segment is replicated (non-replicated Mamba2, Mamba1, GDN, MoRIIO's same-TP path).
- Combinations that cannot be transferred correctly fail at the handshake instead of corrupting state:
  - a Mamba2 layer that does not declare its TP split, under heterogeneous TP;
  - NIXL push with P TP < D TP when D replicates B/C. Both sides check, so D's request fails at the handshake (and follows `kv_load_failure_policy`) instead of waiting for a WRITE that P refuses.
- No handshake or `NIXL_CONNECTOR_VERSION` change.

## Details

**Cause.** When `n_groups % tp != 0`, `mamba2_state_shape` pads the groups to the TP size, so every rank holds a full replica of B and C. `derive_mamba_conv_split` derived the remote layout from local shapes alone and assumed B and C are sharded like x:
- D TP > P TP: odd D ranks read P's C in place of B, and every D rank read C from past the end of P's conv state.
- P TP > D TP: D read the first part of the same B/C replica from every P rank.

Shapes alone cannot tell sharded from replicated B/C (with `n_groups=1` and with `n_groups == tp` every rank holds one group), so the layout has to come from the layer.

**Fix.**
- Mamba2 layers declare how TP splits their states: `MambaStateSplit`, `MambaSpec.state_splits`, `MambaMixer2.get_state_splits`, built by `MambaStateShapeCalculator.mamba2_state_splits` from the unpadded `n_groups`.
- `derive_mamba_conv_split` records the global dims. `MambaConvSplitInfo.proj_layout(tp_size)` gives the (columns, replicas) layout of each sub-projection for any TP size, so D computes P's layout from P's TP size, which the handshake already carries.
- `remote_conv_offsets` maps each D rank's chunk to global columns, then to the P rank that holds them. D checks that P's conv state size (`ssm_sizes[0]`, already in the handshake) matches the layout it derived.

**Relation to the KV checksum PRs.** #61488 and #62211 also declare the Mamba2 TP split, to checksum Mamba state across TP sizes. Whichever PR lands second drops the duplicate.

**Limitations.**
- Push mode with P TP < D TP and replicated B/C is rejected rather than supported: push writes one chunk of the producer's page to each consumer rank, which cannot fill a segment the consumer replicates. Both P and D check at the handshake, D also in the notification-only handshake push registration uses.
- MoRIIO already rejects heterogeneous TP for Mamba and is unchanged.
- A test that used a GDN conv state too small to split across TP8 (`test_mla_hybrid_large_ppl_geometry`) now uses dims 8 ranks can split; the new divisibility assert rejected the old geometry.
