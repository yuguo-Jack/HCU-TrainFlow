## Overview

DeepSeek-V4-Pro mono decode layer on MI355X (gfx950): a decoder layer of a decode step as two persistent FlyDSL launches at TP8, opt-in with `--monokernel`. It is a standalone package, `vllm/models/deepseek_v4/amd/mono/`, docked by `deepseek_v4/amd/mono_decode.py`, in the layout and style of the DeepSeek-V4.1-Flash mono layer. No shared abstraction and no DeepSeek-V4.1 file is touched.

Related: RFC #60904; #61311 proposes the runtime layer for specialized decode kernels, which this PR does not touch.

**Attribution:** This work builds on [ROCm/ATOM's DeepSeek-V4.1 mono decode implementation](https://github.com/ROCm/ATOM/tree/97359d6df46c59736468168b7be8bc50b482a1a9/atom/models/deepseek_v41/mono), via vLLM's V4.1-Flash mono layer. ATOM contributed the reference persistent execution framework, synchronization, peer memory, mHC seam and MoE stages adapted here for Pro. The source files retain their ATOM origins, AMD copyright and MIT attribution; the package README now links the original implementation explicitly.

## Details

- **Layout.** Same as V4.1's: `common/` (execution model, mailbox, peer memory, MX arithmetic), `stages/` (mHC seam, MoE, router, all-reduce), `attention/` (sparse-MLA front and back), `layer.py`, `runner.py`, `dims.py` (Pro's widths and a TP rank's share). See `README.md` in the package.
- **What Pro needs beyond V4.1:** the non-delayed mHC seam (aiter's `mhc_pre` collapse), a weightless per-head q RMSNorm, aiter's (16, 16)-preshuffled FP8 weights with `VLLM_ROCM_FP8_PADDING` row strides, hash routing for layers 0-2, HCA layers reading every compressed row from vLLM's c128a table, and 128 x 128 block scales expanded exactly to the kernels' 32 x 32 E8M0 scales.
- **HCA key table.** At a 1M context the table is 8192 rows wide; the key table, split units and combine cover each token's own keys only (`bounded`).
- **Two-hop all-reduce** from 42 rows: 2/tp of the bytes of one hop, bit-identical.
- **Limits:** TP8 only; the compressor and indexer run as vLLM ops between K1 and K2, serially; the draft layers keep vLLM's path.
- **Duplication.** The package copies V4.1's `common/` and the generic stages rather than sharing them, as asked, so each model's kernels evolve independently. The previous revision of this PR shared them in `vllm/models/common/amd/mono/`.
- AI assistance (Claude Code) was used for the implementation, the tests and this description. The human submitter remains responsible for reviewing every changed line and validating the change before merge.
