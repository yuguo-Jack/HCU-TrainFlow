# [CI] Pace the CRCR nightly report under the relay rate limit

[Upstream PR](https://github.com/vllm-project/vllm/pull/61269) · state: closed · merged: True

## Original PR description

## Purpose

The torch-nightly CRCR report (`.buildkite/scripts/crcr_report.py`) posts one callback per Buildkite job, back to back, with no retry. The PyTorch Cross-Repo CI Relay limits callbacks per repo over a sliding 60 s window (`RATE_LIMIT_PER_MIN`, currently 100). So every nightly records only the first 100 jobs and the rest get a 429:

| Build | Report |
|---|---|
| [93355](https://buildkite.com/vllm/ci/builds/93355) | `reported 100 job(s), 244 failed` |
| [93593](https://buildkite.com/vllm/ci/builds/93593) | `reported 100 job(s), 269 failed` |
| [93820](https://buildkite.com/vllm/ci/builds/93820) | `reported 100 job(s), 270 failed` |

```
429 for :nvidia: (H100) MLA Kernel Test: {"detail": "rate limit exceeded for vllm-project/vllm"}
```

HUD's CRCR view of vLLM nightlies therefore covers about 27% of the jobs, and which jobs depends on the order Buildkite returns them in. The step is `soft_fail` and exits 0, so nothing flagged it.

## Changes

- **`crcr_report.py`:** wait `CRCR_POST_INTERVAL_S` (default 0.65 s, about 92/min, under the current limit) between callbacks. Retry a 429 with 2/4/8/16/32 s backoff, about 62 s in total so the last attempt lands in a fresh window. A full nightly (~370 jobs) now takes about 4 minutes to report.
- **`crcr-report.sh`:** the post-wait OIDC token is minted with `--lifetime 1800`, because the default five-minute lifetime no longer covers a paced report. If the agent rejects `--lifetime`, it falls back to the old call, so the report is never lost to a flag mismatch.

Relay side: pytorch/test-infra#9096 raises the limit to 300/min/repo and adds the same 429 retry to the GitHub Actions reporter. Once that is deployed, `CRCR_POST_INTERVAL_S` can be lowered.

## Test Plan

Ran `crcr_report.py` against a local fake relay:
- Responses 200, 429, 429, then 200: the second job retried after 2 s and 4 s, and all 4 jobs were reported (`reported 4 job(s), 0 failed`).
- 429 every time, with backoff shortened: every job was logged as `429 for …` after its retries, `reported 0 job(s), 4 failed`, exit 0 (best-effort, unchanged).

`ruff check`, `ruff format --check`, `bash -n` and `shellcheck` are clean.

## Test Result

The next torch-nightly run (`TORCH_NIGHTLY=1` on main) should log `reported <all> job(s), 0 failed` for the CRCR step.
