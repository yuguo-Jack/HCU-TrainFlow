# [Bugfix][KV Connector][NIXL] Fix Mamba region stride on block-outermost layouts

[Upstream PR](https://github.com/vllm-project/vllm/pull/64582) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fix NIXL transfers of Mamba/SSM hybrid state on block-outermost KV cache layouts (`BLHNC`, `BLNHC`), and add a CPU test that pulls one request between two NIXL workers on real model KV layouts and checks every byte.

Related: vllm-project/vllm#63416 changes how NIXL pairs regions. This PR does not depend on it, and #63416 rebases onto it without conflicts.

## Claims

- **Fix.** With `VLLM_KV_CACHE_LAYOUT=BLHNC`, Qwen3-Next (GDN) and Nemotron-H (Mamba2) disaggregated P/D read the wrong Mamba state and wrote outside the request's blocks, with no error. They now transfer correctly. Layer-outermost layouts (the default) are unchanged. Hybrids whose attention is MLA, such as Kimi-Linear, were not affected (see Root cause).
- **Test.** The NIXL unit tests build KV cache configs and tensors by hand. The new test plans and allocates both sides with vLLM's own planner (`get_kv_cache_configs`) and allocator (`allocate_kv_cache`), from the per-layer KV specs of 12 models. D pulls one request from P through the real worker code; the recorded descriptors run as memory copies. Every page of every layer must land in D's block for the same layer and request position, and no other D byte may change.

## Details

**Root cause.** Under the hybrid KV cache manager, cache groups share KV cache tensors. With a block-outermost layout, block *b* of every tensor sits side by side in one row, so a layer's view advances by the row: 4,718,592 B for Qwen3-Next's two tensors in the test, not by one 2,359,296 B page. `register_kv_caches` registered Mamba regions with `block_stride = physical_page_size` and took the view's stride only for CSA-linear. So every Mamba descriptor past block 0 pointed into the other tensor's pages. Attention regions on the same rows already used the view stride.

Only some hybrids hit it. A shared region keeps the stride of the first layer registered into it (layer-name order), and a later layer replaces it only if it is MLA. Mamba sub-region descriptors use the region's stride:
- In Qwen3-Next and Nemotron-H a Mamba layer comes first, and their full-attention layers never replace its page stride.
- In Kimi-Linear the MLA layer replaces it with the row stride, so its KDA descriptors were right by accident; the Kimi-Linear BLNHC case passes with or without the fix.

The fix takes the view's stride for Mamba views on block-outermost layouts too. Elsewhere the page stride stays. A view indexed by kernel block (several per logical block) has a stride of a fraction of the page, and taking the view's stride there breaks the existing hetero-block-size tests.

Flow (pull, the failing case):
1. Startup, P and D: `register_kv_caches` registers each region as `(base, len, stride, count)`; Mamba regions get stride = one page.
2. Handshake: D builds descriptors for P's Mamba sub-regions (conv q/k/v parts, SSM state) from P's metadata, and its own from its local regions.
3. Read: a descriptor id for block *b* resolves to `base + b × stride`. With stride = page instead of row, block *b*'s address lands in another tensor's page of a lower block, on both sides.

**The test.**
- Models are those tested end to end for vllm-project/vllm#63416. MiniMax-M1 is left out; vLLM removed it in 0.23.0.
- Specs mirror what each model's layers return. Nine were dumped from a meta-device model build on CPU. DeepSeek-V3.2 (sparse MLA + indexer) and Kimi-Linear (MLA + KDA) cannot be built on CPU, so their specs come from their configs and vLLM's state-shape helpers.
- Each case uses the first layers of its model, enough for its group and region pattern (2 regions for the hybrids). The largest case allocates about 120 MB per side.
- Hybrid block sizes are the ones vLLM aligns to on CPU (1152, 1408). For Kimi-Linear it is 1920, the first 64-token multiple whose MLA page holds the KDA state.

**Not covered.**
- Push, TP mismatch, PP stages, and P and D with different settings. With the same model and settings the region pairing is the identity; those cases stay with the hand-built tests.
- GPU, and an end-to-end P/D run with `VLLM_KV_CACHE_LAYOUT=BLHNC` on a hybrid model.

**Mocks.** `tests/AGENTS.md` asks for real objects. The workers are patched the same way as the existing `_make_mla_hybrid_worker` helper in this file:
- the platform reports a CUDA device, so the GPU registration path runs on a CPU host;
- attention backends and kernel block-size selection are faked, since no model layers are built;
- TP rank and size are fixed at 0 and 1;
- NIXL itself is the file's `_RecordingNixl`.

Planner, allocator, layout resolution, registration, handshake and descriptor code are all real.

**Not a duplicate.** vllm-project/vllm#62453 fixes Mamba page padding on the CPU host-buffer path, and vllm-project/vllm#64140 fixes packed Mamba addressing in the KV offloading worker. Neither touches NIXL's Mamba region stride.
