# [Bugfix][Core] Await multi-iterator cancellation cleanup

[Upstream PR](https://github.com/vllm-project/vllm/pull/50830) · state: open · merged: False

## Original PR description

Await cancelled reads before closing their async iterators so `aclose()` does not return before underlying cleanup finishes.



## Purpose

Fix incomplete cancellation cleanup in the multi-iterator path of `merge_async_iterators()`.

When the merged generator is closed, the function currently cancels each pending `anext()` task and immediately calls `aclose()` on the corresponding underlying generator. Task cancellation is asynchronous, so the generator may still be running when `aclose()` is called. In that case, `aclose()` raises:

```text
RuntimeError: asynchronous generator is already running
```

The exception is suppressed by the existing cleanup block, allowing the merged generator's `aclose()` to return before the underlying generator finishes its asynchronous `finally` cleanup.

For vLLM callers, that cleanup can include aborting an active `AsyncLLM.generate()` request. Returning before it finishes can therefore leave request cleanup running after the downstream consumer has already closed.

This change:

1. Takes a snapshot of all pending reads.
2. Cancels every pending task first.
3. Awaits each cancelled task, consuming its cancellation or exception.
4. Closes the corresponding iterator only after its pending read has stopped.

The regression test merges two generators that perform asynchronous cleanup in their `finally` blocks and verifies that both cleanups have completed when `merged.aclose()` returns.
