# [Bugfix][Model] Build the skipped DeepSeek-VL2 vision tower without meta .item()

[Upstream PR](https://github.com/vllm-project/vllm/pull/63192) · state: closed · merged: True

## Original PR description

## Purpose

Fixes the `:amd: (MI300) Push NixlConnector PP prefill PD accuracy` job, which fails on PRs that touch the Nixl connector:

- Failing job: https://buildkite.com/vllm/ci/builds/96674/list?jid=01a164e1-7805-46fd-92cc-26e90031cb29&tab=output
  (all 3 retries in that build failed the same way)

The job runs PP=2 prefill with DeepSeek-VL2-tiny. The second pipeline stage worker crashes while loading the model:

`NotImplementedError: Tensor.item() cannot be called on meta tensors`


### Root cause

#60238 ("Skip encoder towers on later PP stages under V2") made later PP stages skip the vision tower. A skipped tower is built inside `no_init_weights`, which sets the default device to `meta` so no memory is allocated.

DeepSeek-VL2 builds its vision tower with `timm.create_model(...)`. timm's `VisionTransformer.__init__` runs `[x.item() for x in torch.linspace(...)]`, and `.item()` does not work on meta tensors, so the build crashes.

This is not specific to PP. The same crash already happened on main when `limit_mm_per_prompt={"image": 0}`, because that path also builds the tower on meta.

### Fix

In `DeepseekVLV2ForCausalLM._init_vision_module`, when the default device is `meta`, build the timm model on the CPU and then move it to `meta`. The tower is never used on that stage, so no memory is kept.

When the default device is not meta (the normal case), nothing changes.
