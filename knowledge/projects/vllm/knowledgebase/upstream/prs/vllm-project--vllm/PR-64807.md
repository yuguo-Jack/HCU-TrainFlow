# [Bugfix][Tool Calling] Recover buffered prose after unclosed or liter…

[Upstream PR](https://github.com/vllm-project/vllm/pull/64807) · state: closed · merged: False

## Original PR description

…al <tool_call> in Hermes streaming parser

When serving with --tool-call-parser hermes and stream=True, if the model output contains a literal <tool_call> in ordinary prose (e.g. explaining tool syntax or unclosed markup), the streaming parser held back all subsequent text tokens awaiting tool completion. Because no valid tool call was formed, this held-back buffer was never emitted, causing the streaming output to diverge from non-streaming.

This commit:
- Implements finish_streaming on Hermes2ProToolParser to flush held-back buffered prose as content when no valid tool calls were formed.
- Updates _flush_engine_parsers in DelegatingParser to invoke finish_streaming on any tool parser implementing the hook at stream end.
- Updates run_tool_extraction_streaming in tests/tool_parsers/utils.py to flush the parser at end of stream.
- Adds differential regression tests for literal <tool_call> and invalid tool call markup in prose.

Fixes #63309.
