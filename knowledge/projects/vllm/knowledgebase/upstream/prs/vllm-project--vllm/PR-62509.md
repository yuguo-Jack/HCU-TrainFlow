# [ROCm][Perf][MiniMax-M3] Opt-in online FP8 for the attention projections

[Upstream PR](https://github.com/vllm-project/vllm/pull/62509) · state: open · merged: False

## Original PR description

## Purpose

MiniMax-M3-MXFP4 keeps the attention projections (fused q/k/v + index q/k, and o) in bf16; only the routed experts are MXFP4. This PR adds an **opt-in** switch, `VLLM_MINIMAX_M3_FP8_ATTN_PROJ=1`, that runs those projections through the existing online PTPC FP8 method (`Fp8PtpcOnlineLinearMethod`): per-output-channel FP8 weights quantized at load time and dynamic per-token FP8 activations. The routed experts keep the checkpoint's Quark MXFP4 config. It is off by default because it changes numerics.

## Results (MI355X, MiniMax-M3-MXFP4 TP4, EAGLE3-GQA, golden AL 2.78)

Base: `vllm/vllm-openai-rocm:nightly-rocm72-1b2a666391f2a24228a1436b64d547c34cc6b6ce`; this branch is based on the same commit and was tested as nightly + this patch with the flag on.

**AgenticX C24** (InferenceX recipe `minimaxm3/vllm/mi355x-fp4-mtp/agentic.yaml`, `override_tp4_c24`, 3600 s replay of `semianalysisai/cc-traces-weka-062126`, one run each, same node):

|---|---:|---:|---:|
| Token throughput per chip | 24,920 | 25,136 | +0.87% |
| Output throughput per chip | 180.2 | 180.7 | +0.28% |
| Interactivity p50 | 52.1 | 52.7 | +0.98% |
| TTFT p90 | 0.896 s | 0.868 s | −3.06% |
| E2EL mean | 18.24 s | 17.97 s | −1.47% |

**8k/1k C24** (240 requests, zero HTTP warmup, per-arm warmed compile caches, 2 interleaved rounds vs same-round baseline): output throughput **+2.44%** (+2.45 / +2.42), mean TTFT −5.8%, p99 E2EL −3.2%.

**Where it comes from:** at prefill sizes the FP8 GEMMs are close to 2× the bf16 ones. In decode (M=96) the FP8 GEMMs save ~420 µs per step, but the two dynamic per-token quant kernels add ~500 µs, so a pure-decode step is ~1% slower; the end-to-end gain is prefill-driven. Fusing the qkv-input quant into the preceding RMSNorm (as other stacks do) should recover most of that decode cost and is a natural follow-up.
