# [ROCm][Perf][MiniMax-M3.1] Tune MXFP8 linear tiles for 16 < M <= 256

[Upstream PR](https://github.com/vllm-project/vllm/pull/62509) · state: open · merged: False

## Original PR description

## Overview

Tune gfx950 MXFP8 linear tiles for MiniMax-M3.1 decode and small prefill batches (`16 < M <= 256`, local `N > 1280`). Keep the main configuration for TP2 QKV at `128 < M <= 192`, where the tuned tile regresses.

## Claims

- Tile-only change; reuse the existing Triton GEMM and preserve the fallback outside the tuned range.
- One mid-M table owns the overlapping gfx950 `17 <= M <= 64`, `N > 1280` range with #64195; integrate that overlap here rather than stacking selectors. This PR also tunes M65–256; #64195's additional small-N coverage is outside its scope.
- Keep the measured M48 MiniMax TP4 QKV tile in the table. Remove the V4.1-specific N=1792 bucket; normal V4.1 serving uses the separate block-scaled GEMM.

## Validation

### MiniMax-M3.1 GEMMs: main `ffdf26702` vs `4bfce4e2e`

MI355X, same image and inputs; 36 cases covering all six TP4/TP2 shapes at M48/64/96/128/192/256. **The 34 changed tiles reduce GEMM latency by 4.64–58.15%.** M48 TP4 QKV keeps its main tile. TP2 QKV now also keeps the main tile for `128 < M <= 192`.

The initial M192 TP2 QKV measurement regressed **23.296 → 26.608 µs (+14.22%)**. That shape/range is excluded from the tuned path; M128/129/160/192/193 boundary checks confirm the intended dispatch. The other measured buckets are retained.
