# [Perf][DSv4.1] Exchange packed FP8 Engram rows across DP and feed wkv MXFP8

[Upstream PR](https://github.com/vllm-project/vllm/pull/59923) · state: closed · merged: True

## Original PR description

## Purpose

DeepSeek-V4.1's Engram tables are already MXFP8 (FP8 rows with one ue8m0 scale per 32 values) and `wkv` is an MXFP8 GEMM, but the lookup dequantizes each row to BF16, DP replicas all-gather those 512-byte rows layer by layer, and `wkv` quantizes them right back. This PR keeps rows packed from the host table to `wkv`.

- **Packed rows, direct MXFP8.** The lookup copies each row's 256 FP8 bytes and 8 scale bytes as they are, and one unpack kernel writes them in FlashInfer's MXFP8 activation layout (F8_128x4 scales). `wkv` takes them as a `QuantizedActivation`, so both the dequant and the requant are gone, and the output is bit-identical.
- **One all-to-all per prefill step.** `EngramBatch` looks up every local Engram layer into one packed buffer and exchanges it with a single all-to-all, which sends each rank only its own tokens (264 instead of 512 bytes per head row, 1/DP of an all-gather), then unpacks all layers in one launch.
- **Peer exchange for decode.** Below 128 tokens per rank, `EngramPeerExchange` replaces the hash all-gather and the per-layer row all-gathers: ranks publish ids in symmetric memory, look up their head shard for every peer's tokens, and read their own tokens back from the peers after a barrier. All layers share one lookup and one unpack launch.

The batched path serves DP-sharded tables (`embedding_across_dp` without DP-shared memory) with TP = 1, `head_dim % 128 == 0`, no LoRA (it wraps `wkv` after construction), and a `wkv` kernel that takes F8_128x4 scales (reusing `can_fuse_query_quant`). The peer exchange also needs SM100, CPU offload, and 2/4/8 fully connected GPUs; without it every slot uses the all-to-all, which on DEP4 HBM tables at 1–127 tokens per rank is 19–58 us faster than the BF16 path. Everything else, including TP, DP-shared tables, single replicas and ROCm, keeps the existing BF16 path unchanged. Communication stays on the current stream and `wkv` still runs in `Engram.forward`.

Also changed along the way:

- `EngramBatch` is an `nn.Module`, so the peer exchange's pointer tables are model buffers that level-2 sleep restores.
- `fused_q_kv_rmsnorm_quant` and the Engram unpack kernel share the F8_128x4 scale offset and size helpers.

## Kernel microbenchmark

Engram only, two layers (lookup, exchange, and anything needed to reach the MXFP8 `wkv` input), 4 x GB300 in one node. ## Not a duplicate

Searched open PRs for `engram`, `engram fp8`, `engram all-to-all`, `engram peer` and `DeepSeek-V4.1 engram`. #56989 packs FP8 rows for the TP head exchange (opt-in, TP > 1 without SP) and dequantizes them before `wkv`; this PR leaves TP alone and covers Engram DP, feeding `wkv` directly. #57893 tunes small-lookup tiles. #58766 fed MXFP8 rows to `wkv` through the existing gathers and was closed by its author after merge conflicts, without review; this PR keeps that idea and also replaces the gathers.
