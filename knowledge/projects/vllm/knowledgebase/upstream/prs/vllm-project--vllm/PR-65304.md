# [Model] Add GRT (Geometric Rotation Transformer) model support

[Upstream PR](https://github.com/vllm-project/vllm/pull/65304) · state: open · merged: False

## Original PR description



## Overview

Adds support for the **GRT (`GRTForCausalLM`)** architecture to vLLM:
- Planar-pair butterfly Givens rotation cascades with `Cl(2,0)` bivector coupling (`GRTAttention`, `GRTMixer`, `GRTFFN`)
- Polar token embedding and tied cosine LM head (`GRTEmbedding`)
- Optional INT8/INT4 weight-only quantization for the materialized embedding/LM-head table and stage coupling tensors while keeping rotation angles and scales in FP32

## Upstream Reference & Verification

- **Upstream Hugging Face Checkpoint**: [`MatterWaveAI/grt-30m`](https://huggingface.co/MatterWaveAI/grt-30m)
- **Upstream `transformers` Implementation**: [`MatterWaveAI/transformers` (`add-grt-model`)](https://github.com/huggingface/transformers/pull/50291)
- **Tests**: `pytest tests/transformers_utils/test_grt_config.py` passes on CUDA (`max_logit_diff < 1e-4` vs. Hugging Face `transformers` FP32 reference).

- Regarding `#61276` vs `vllm/model_executor/models/transformers/causal.py`: `#61276`'s `to_output_head()` checks `if not isinstance(embeddings, nn.Linear) or embeddings.out_features != vocab_size: return None` and falls back to `ParallelLMHead` + `VocabParallelEmbedding`. In `GRTForCausalLM`, `get_input_embeddings()` is `GRTPlanarEmbedding` (polar `phase_angles` and `log_magnitudes` of shape `(vocab_size, d_model // 2)`, not `nn.Embedding`) and `lm_head` is `GRTCosineLMHead` (polar cosine similarity against `phase_angles` with `log_scale`, not `nn.Linear`, tying `lm_head.phase_angles` to `model.embedding.phase_angles` via `_tied_weights_keys`). Because `get_output_embeddings()` is not an `nn.Linear`, `#61276` returns `None` and falls back to `ParallelLMHead`, whereas the `causal.py` changes here handle non-`nn.Linear` `lm_head` modules and bind `_tied_weights_keys`.
