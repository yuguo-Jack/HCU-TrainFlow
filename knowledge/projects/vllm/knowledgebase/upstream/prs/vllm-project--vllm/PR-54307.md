## Purpose

This PR extends heterogeneous-TP sharing in `MooncakeStoreConnector` from a
single Full Attention cache group to unified Hybrid KV cache allocations. vLLM
instances whose local TP sizes divide a common Store TP size can share the same
Attention KV and Mamba/GDN state through Mooncake Store. Sharing endpoints use
the same PP size.

Hybrid KV cache adds three challenges beyond Full Attention:

- Attention KV grows by token, while Mamba/GDN groups store complete recurrent
  checkpoints with different TP replication rules;
- vLLM aligns Attention pages with Mamba/GDN state pages, so the local page size
  can change with TP size even when two endpoints use the same model;
- prefix reuse must intersect the available boundaries of every cache group,
  while Decode writeback may advance each group at a different rate.

This PR builds on the common Store TP layout from #53129 and represents each
cache group in a stable Store namespace. Attention uses TP-independent Store
chunks, while Mamba/GDN uses complete state checkpoints. These Store boundaries
are independent of the endpoint's local Hybrid page allocation.

### Unified Hybrid Store layout

Each cache group creates its Store layout from its `KVCacheSpec`:

- Attention groups divide global KV head slots into the fixed Store TP shards;
- MQA and replicated GQA use their physical head-slot count for Store sharding;
- Mamba/GDN groups store complete convolution and recurrent state units and
  map replicated local units to their Store shards;
- `UniformTypeKVCacheSpecs` is unwrapped before the group layout is planned;
- each group namespace includes its Store value format and schema fingerprint.

`StoreLayout` owns tensor interpretation, shard mapping, buffer spans, and Store
keys. The worker executes the resulting descriptors through a common path.

### Attention layouts

The heterogeneous Store path supports the backend-native LBHNC, BLHNC, LHBNC,
BHLNC, LBNHC, and BLNHC cache layouts.

- LBHNC, BLHNC, LHBNC, and BHLNC are normalized to the same head-major Store
  value order;
- LBNHC and BLNHC are normalized to the same token-major Store value order;
- endpoints whose local layouts produce the same Store value order share one
  namespace;
- head-major and token-major Store values remain isolated by their schema.

### Store chunks and local Hybrid pages

`store_chunk_size` defines the stable number of tokens represented by one
Attention Store object. A local Attention page can contain multiple Store
chunks. The connector reads and writes those chunks through tensor-offset
descriptors, so endpoints can share Store objects when their local Hybrid page
sizes differ.

Hybrid heterogeneous-TP sharing requires the same explicit
`--prefix-match-unit` on every endpoint. The connector uses that prefix-hash
boundary as `store_chunk_size` when no Store-specific value is configured. An
explicit larger `store_chunk_size` may reduce Store object and metadata
overhead:

```json
{
    "kv_connector_extra_config": {
        "store_tp_size": 4,
        "store_chunk_size": 400,
        "save_decode_cache": true
    }
}
```

The configured value must be a multiple of `prefix_match_unit`, align with
every stored state, and divide the local Attention page. Invalid or
incompatible configurations use the isolated rank-local Store namespace.

### Hybrid lookup and Decode writeback

Hybrid prefix lookup intersects the availability of all required cache groups
at each reusable boundary. Attention chunks may be stored before the next full
Hybrid checkpoint. Mamba/GDN entries remain complete state snapshots at their
reusable boundaries, so lookup exposes a longer prefix only after every group
required at that boundary is present.

Decode offloading tracks acknowledged progress per cache group. Attention can
advance independently while a Mamba/GDN group waits for its next complete
checkpoint. A failed PUT retries from the earliest unacknowledged offset for
that group. Partial physical cache blocks are stored from their copy-on-write
handoff sources, allowing a hash-aligned Store chunk to be written before its
larger local page is complete.

Scheduler Store-job boundaries, prefix-hash boundaries, local cache pages, and
KV-event block boundaries are resolved independently. KV events continue to
describe the scheduler's logical block chain while Store jobs operate on the
finer Hybrid checkpoint when required.

### Supported scope

Shared endpoints satisfy the compatibility requirements from #53129 and the
following Hybrid constraints:

- Store TP size is greater than or equal to local TP size and divisible by it;
- all sharing endpoints use the same Store TP size and PP size;
- Attention head slots and Store shards have an integral divisible mapping;
- cache groups use supported Attention specs or `MambaSpec`, including
  supported `UniformTypeKVCacheSpecs` wrappers;
- Mamba/GDN convolution state uses DS or SD layout; sharing endpoints use the
  same layout;
- PCP and DCP are disabled;
- cross-layer KV blocks are disabled.

Endpoints outside this scope retain the existing rank-local behavior.

This PR updates the Mooncake Store Connector documentation and adds regression
coverage for:

- mixed Attention and Mamba/GDN cache groups;
- per-group TP replication and Store-shard ownership;
- all six backend-native Attention cache layouts;
- head-major and token-major Store schema normalization;
- TP-independent Store chunk selection and explicit `store_chunk_size`;
- Hybrid local pages containing multiple Store chunks;
- partial-tail PUT and GET from copy-on-write cache blocks;
- per-group acknowledged Store progress and PUT retries;
- prefix lookup across cache groups with different reusable boundaries;
- scheduler Store-job, prefix-hash, and KV-event boundary separation;
- rank-local fallback for unsupported or incompatible configurations.

## Related Issues and PRs

- Issue #45036 tracks the Mooncake Store Connector roadmap, including Decode
  KV PUT and heterogeneous GQA/TP sharing. This PR extends that work to Hybrid
  KV cache allocations with divisible TP sizes.
- PR #52466 added Decode KV offloading to Mooncake Store consumers. This PR
  applies the same consumer writeback lifecycle independently across Hybrid
  cache groups.
- PR #53129 introduces the common Store TP layout for Full Attention KV cache.
  This PR uses that layout as its base and extends the Store planning,
  namespace, lookup, and writeback paths to Hybrid KV cache.
- PR #53078 adds heterogeneous-TP support for Hybrid GDN/Mamba models to
  `MooncakeConnector` direct P/D transfer. This PR targets persistent and
  reusable KV objects in `MooncakeStoreConnector`, including prefix lookup and
  Decode writeback through a shared Store pool.

checks cached-token boundaries, compares the first 64 generated token IDs with
the same-TP reference, waits for asynchronous Store jobs, and verifies Decode
writeback with a fresh Store lookup.
