# [Bugfix][HiSparse] Recover host backing for active GPU-only pages

[Upstream PR](https://github.com/vllm-project/vllm/pull/58963) · state: closed · merged: False

## Original PR description

## Description

When the HiSparse host pool fills, an active request can retain GPU-only pages
with null host entries when no host page is available. Later allocations extend
the host table, so freeing host capacity does not give those old pages backing
and their GPU blocks stay pinned.

Retry one old page per connector step after scheduler allocations. The recovered
page gets a host destination and a copy to host. Its GPU blocks become reclaimable
only after every worker completes the transfer.

In the 64-token regression case, releasing one donor host block lets the active
request backfill logical page 1. Completion makes **one GPU block per resident
group reclaimable**; partial acknowledgement makes none.

```bash
  tests/v1/core/test_single_type_kv_cache_manager.py \

```

The H100 model-path regression completed with **2 passed** (eager host mirroring
on and off):

```bash
VLLM_USE_V2_MODEL_RUNNER=1 .venv/bin/python -m pytest \
  tests/v1/e2e/general/test_hisparse.py -k host_capacity_recovery -v -s -x --tb=short
```

Each H100 case copied 3 recovered pages, reclaimed 24 GPU blocks across 8
resident groups, and preserved all 16 generated tokens with zero preemptions.
Host rows matched resident rows. The run used reduced DeepSeek-V3.2 with dummy
FP8 weights, so trained-model accuracy was not evaluated. Serving throughput
was not measured.

## Existing PRs

Open PR searches for HiSparse host capacity recovery, exhaustion, and backfill
found no implementation of recovery for old null host entries. #56109 addresses
resident cache policy and does not backfill these entries.
