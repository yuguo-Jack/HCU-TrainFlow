# [Bugfix][EC Connector] Size transfers by measured encoder output widths

[Upstream PR](https://github.com/vllm-project/vllm/pull/57904) · state: closed · merged: True

## Original PR description

## Summary

EC producers size each transfer before the item is encoded: Mooncake reserves the destination, and CPU/NIXL allocates blocks at schedule time. The size depends on the encoder output width, which varies by model and modality. For example, Qwen3-Omni's visual DeepStack output is 8192 wide and its audio output is 2048. The HF-config sniff on main misses Qwen3-Omni (it has no top-level `vision_config`), Granite4-Vision and MOSS-Audio.

- **Measure the width instead of inferring it.** After the model loads and before the KV cache is allocated, an EC producer encodes one dummy item per modality on every worker. It records the widths in `ec_transfer_config.mm_encoder_output_widths`, which is internal (`init=False`). Mooncake push specs and CPU save blocks are sized from these widths, and the config sniff is removed.
- **Fail closed.** A producer refuses to start if it measures no width or its ranks disagree.
- **Consumers take the shape from the transfer.** CPU/NIXL announcements carry `shape`, and loads restore it. Mooncake already sends the shape in the reservation.

Outside `ec_transfer/`, the change is one config field and one call in `EngineCore.__init__`. The NIXL protocol version is now 2, so producers and consumers must be upgraded together.

## Validation

Qwen3-Omni-30B-A3B-Instruct at 5003085f09, run as 1 encoder + 1 PD with TP=1, BF16, Model Runner V2 and proxy `--no-rewrite`:

| Path | Measured widths | Requests | Errors |
|---|---|---|---|
| NIXL | image/video 8192, audio 2048 | image, audio, image+audio: 3/3 OK | 0 size/shape mismatches, 0 local fallbacks |
| Mooncake | same | 3/3 OK | 0 `EC source shape mismatch` |
| CPU offload (`ec_both`) | same | 7/7 OK, then 2/2 after GPU eviction | 0 block overflows; the CPU reload matched round 1 exactly |

The measured widths match the checkpoint: 2048 × (1 + 3 DeepStack layers) = 8192. NIXL and Mooncake returned identical text.

Not run: video requests, Mooncake store, Granite4-Vision and MOSS-Audio (no checkpoints available), and accuracy evals.

## Not a duplicate

No open PR sizes EC transfers from the encoder output. #58853 (NIXL ack block-count check) and #58123 (Mooncake reservation races) touch different files. This PR is independent of #57887's audio metadata-only support.

- omerpaz95 · COMMENTED · 2026-09-22T09:25:52Z · [source](https://github.com/vllm-project/vllm/pull/57904#pullrequestreview-5275676777)

This is an excellent catch. Some items that are worth your fixes (or at least consideration) while you're here:
1. This PR fixes Qwen3-Omni specifically, but leaves other multimodal models that use deepstack untreated. Specifically, MOSS-Audio and Granite4-Vision have different config shapes:
- Granite4-Vision: width is text_config.hidden_size * (len(deepstack_layer_map) + len(spatial_target_layers)).
- MOSS-Audio: language_config.hidden_size * (1 + deepstack_count) on modality audio, so the ("image", "video") gate excludes it by construction.

This may be worth a separate PR, but I think we need to generalize this solution. Not by adding more if/else gates, but maybe adding some optional config in vllm_config, and rejecting any model that doesn't declare it.
2. If you decide not to generalize, we need to, at the bare minimum, think about how to reject unsupported models on startup. Otherwise, this same class of bug will recur in other models.
