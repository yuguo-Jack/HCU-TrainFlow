# [Bugfix][NIXL] Fix host-buffer h2d sync overwriting received KV

[Upstream PR](https://github.com/vllm-project/vllm/pull/60181) · state: closed · merged: True

## Original PR description



## Overview

With `kv_buffer_device="cpu"`, `sync_recved_kv_to_device` overwrites D's received KV with host pages NIXL never filled, for models with several KV cache groups or KV-sharing layers. Each group now copies only its own layers' host buffers; the multi-group case regressed in #53780.

## Claims

- With host buffers, D keeps the received KV for models with several KV cache groups or KV-sharing layers.
- Each layer of a transfer group is still copied once per request, as after #54483; KV-sharing layers are no longer copied.

## Details

On D, with `kv_buffer_device="cpu"`:

1. NIXL READ writes into D's per-layer host buffers. Each host buffer is its own region, and since #53780 each group's descriptors cover only its own regions, so a layer's host buffer is filled only at its own group's blocks. Layers that reuse another layer's KV cache have host buffers but no transfer group, so NIXL never fills them.
2. `sync_recved_kv_to_device` copies the host buffers into the device tensors, which layers of different KV cache groups share, as does a KV-sharing layer with its target.
   - Main copies every layer's host buffer at all groups' blocks, so unfilled host pages overwrite the other groups' received blocks. A KV-sharing layer, copied after its target, overwrites the target's received KV, even with one group.
   - This PR copies each group's layers at that group's blocks only.

The byte-level check matches in all 10 multi-group cases that build at #53780's parent and differs in all 10 at #53780.

`save_kv_to_host` still copies every layer for all groups' blocks; NIXL never reads the extra host pages.

#59037, a 60-file draft for hidden-state extraction with packed layouts, contains the same per-group copy; this PR is the standalone fix.
