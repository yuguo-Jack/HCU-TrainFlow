# [Bugfix][Frontend] Preserve whole messages in Responses auto truncation

[Upstream PR](https://github.com/vllm-project/vllm/pull/58500) · state: open · merged: False

## Original PR description

## Overview

Fixes #58421. Responses `truncation="auto"` currently slices rendered tokens, which can drop instructions and split messages. This change selects whole-message suffixes and reuses a validated render.

## Claims

- Preserve system/developer instructions, the latest message, and linked tool calls/results on standard and Harmony paths.
- Drop oldest complete messages; return a validation error if protected content cannot fit.
- Bound render attempts with binary search and reuse the selected token IDs. Stored history remains complete.
- Follow current upstream context budgeting: leave one token for generation, with requested output limits clamped downstream.

## Details

Token-level left slicing happens after formatting and therefore cannot preserve conversation boundaries. A shared cutoff search operates on structured messages before rendering. It protects instructions/latest content and excludes cutoffs inside known tool-call/result dependencies. Parser adjustment runs once after selecting the render.

Harmony grouping is conservative because call IDs are unavailable at this stage. Arbitrary templates may have non-monotonic lengths or reject retained role sequences: returned prompts are validated, but a globally maximal suffix is not guaranteed. Other validation errors propagate. Full stored history is preserved, so later requests can incur truncation again.

Duplicate check refreshed October 15: issue #58421 remains open. Related #58848 was closed without merging; it proposed linear removal on the non-Harmony path. #58554 concerns opt-in shortening of a selected Chat Completions message, a different API/contract. No merged replacement for this fix was found.
