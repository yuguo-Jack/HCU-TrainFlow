# [Bugfix][Benchmark] Fix timeline export at rounded minute boundaries

[Upstream PR](https://github.com/vllm-project/vllm/pull/64931) · state: open · merged: False

## Original PR description



## Overview

Prevent `vllm bench serve --plot-timeline` from losing its HTML output when an elapsed timestamp rounds across a minute or hour boundary. `59.9999` seconds currently becomes the invalid timestamp `00:00:60.000`, which the real Plotly export rejects.

## Claims

- Round the total elapsed milliseconds before splitting hours, minutes and seconds, so rollover produces `00:01:00.000` and `01:00:00.000`.
- Keep raw latency metrics, model execution and the output format unchanged.
- Cover timestamp rollover and real HTML export; extend the existing server benchmark test to check the requested HTML artifact.

## Validation

On main `6d018934838a0c8c6beed244aa1ca327e1ed7182`, with only the new test file added:


The two rollover assertions fail with a `:60.000` timestamp. The real exporter fails with `TypeError: Both x_start and x_end must refer to data convertible to datetimes`, caused by `DateParseError: second must be in 0..59: 00:00:60.000`.

Environment: macOS arm64, Python 3.12.13, pandas 3.1.0, Plotly 6.6.0, PyTorch 2.14.1. The plotting tests import real vLLM modules and use real Plotly/Pandas; `--confcutdir` excludes the unrelated GPU/model fixtures in the root test configuration. A generated HTML file was also rendered in Chromium with its TTFT and ITL traces present.

All applicable repository pre-commit hooks passed (exit 0), including Ruff, formatting, markdownlint, MyPy, SPDX, and test tethering.

The existing `RemoteOpenAIServer` integration test now checks the timeline artifact. `tests/benchmarks/test_serve_cli.py::test_bench_serve` has not been run on this macOS host, which has no supported serving runtime. This coverage is wired into the existing Buildkite benchmark step. No inference or model-quality result is claimed.

## Details

Previously the formatter truncated hours/minutes before formatting fractional seconds, allowing fractional rounding to leave seconds equal to 60. The correction uses integer millisecond decomposition with the standard library's `divmod`; it adds no dependency or new public API. The existing duration limit is retained.

- `vllm/benchmarks/plot.py`: normalize timestamp rollover.
- `tests/benchmarks/test_plot.py`: deterministic formatting and actual HTML export regressions.
- `tests/benchmarks/test_serve_cli.py`: verify the timeline artifact through the existing `RemoteOpenAIServer` benchmark test.
- `docs/benchmarking/cli.md`: describe relative millisecond timestamps beside the existing timeline instructions.

Duplicate-work checks repeated on November 1 found no open PR addressing timeline rounding (`construct_timeline_data`, `60.000`, and timeline/rounding searches). Other known sweep-plot and dataset-plot PRs address separate paths.

AI assistance: investigation, implementation, local test execution, and review used OpenAI Codex. The human submitter reviewed the complete patch and authorized submission.
