# [Bugfix][Kernel] GDN chunk/prefill path: honor fp32 SSM state precision

[Upstream PR](https://github.com/vllm-project/vllm/pull/62119) · state: open · merged: False

## Original PR description

## Purpose

Closes #62116.

#54146 fixed the GDN decode-update kernel overflowing fp16 with a large fp32 SSM state, but its own description flagged that the same bug exists on the chunk/prefill path:

> The same materialize-in-activation-dtype pattern exists in the chunk/prefill kernels (`chunk_o`, `chunk_delta_h`, `wy_fast`) and the `core_attn_out` buffer. This PR fixes the decode-update kernel... the chunk-path kernels are a straightforward follow-up.

This PR is that follow-up for `chunk_delta_h.py` and `chunk_o.py` (the two files that actually need it; `wy_fast.py` turned out not to, see below).

## Root cause

The recurrent SSM state is accumulated in fp32 inside the chunk-path Triton kernels, but several buffers and `tl.dot` operands silently downcast it to the activation dtype (fp16/bf16) before it's normalized:

- `chunk_delta_h.py`: the per-chunk state buffer `h` was allocated in `k`'s dtype instead of the state's. Two internal `tl.dot` calls also downcast the fp32 state (and its correction term `b_v`, which inherits the state's magnitude) to fp16 before accumulating.
- `chunk_o.py`: the output buffer `o` was allocated in `v`'s dtype, and its `tl.dot(b_q, tl.trans(b_h))` downcast the (possibly fp32) state `b_h` before computing the raw, unnormalized readout.
- `chunk.py`: `chunk_gated_delta_rule`'s public API unconditionally cast its return value back to `q`'s dtype, which would silently undo a correct fp32 computation from the two fixes above.

I initially suspected `wy_fast.py` had the same pattern (it also allocates output buffers in the activation dtype), but its `tl.dot` calls operate on per-token key/value transforms with no fp32 accumulator carried across iterations, not state, so it doesn't need this fix.

## Fix

Same approach as #54146: gate each buffer's dtype on `initial_state.dtype == torch.float32`, and upcast the activation-dtype operand (not downcast the state) in the two `tl.dot` calls. The fp16/bf16-state path is unchanged, these are no-ops when the state is already fp16, so behavior and performance for the common case are byte-for-byte identical.

**Known gap (scoped out, same as #54146 only fixed the decode kernel):** the real model code in `vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py` allocates its own `core_attn_out` buffer ,unconditionally fp16/bf16, at 5 separate call sites across the CUDA/HIP/XPU/CPU/fused-spec-decode backends,  and passes it into the chunk path via the `core_attn_out` in-place-write parameter, bypassing this PR's allocation fix entirely. Making this reach real inference end-to-end needs those 5 call sites updated too. Opening this as the library-level fix first since it's independently correct and testable; I'd happy to follow up on the caller sites in a separate PR if that's the preferred scope.

## Test Plan

Adds `test_chunk_gated_delta_rule_finite_under_large_fp32_state` to `tests/kernels/fla/test_fused_sigmoid_gating_delta_rule.py`, mirroring #54146's own test: drives `chunk_gated_delta_rule` with fp16 activations and a large (`1e6`, past fp16's ~65504 max) fp32 `initial_state`, and asserts the output and final state are finite and preserve the true magnitude (not saturated).

Also ran the full existing file (18 pre-existing decode-path tests + the new one) to check for regressions.

## Test Result

- Before (on current main): `chunk_gated_delta_rule`'s output is 100% non-finite (all 65536/65536 elements) and `final_state` is non-finite, while an fp32 `fused_recurrent_gated_delta_rule` reference from the identical inputs and initial state stays fully finite (`max|o| ≈ 3.7e6`) -- isolating the failure to the chunk path's own precision handling, not the input magnitude.
- After this fix: output and final state are both fully finite, `max|o| ≈ 3.736e6` vs. the reference's `≈3.738e6` (max abs diff ≈1944, mean ≈125,  consistent with ordinary fp32 chunked-vs-recurrent rounding, not corruption).
- `pytest tests/kernels/fla/test_fused_sigmoid_gating_delta_rule.py -v`: 19 passed, 0 failed (18 pre-existing + 1 new).

Validated on NVIDIA L40S.
