# [Bugfix][Spec Decode] Implement get_top_tokens() on the generic MTP drafter

[Upstream PR](https://github.com/vllm-project/vllm/pull/56995) · state: open · merged: False

## Original PR description

## Overview

Turning on `speculative_config.use_local_argmax_reduction` with a `deepseek_v3` MTP drafter (DeepSeek-V3, R1) fails at engine startup with `ValueError: ... DeepSeekMTP does not implement get_top_tokens()`; this PR adds `get_top_tokens()` to `DeepSeekMultiTokenPredictor` and `DeepSeekMTP`, mirroring their `compute_logits` pair.

The reduction is the existing `LogitsProcessor.get_top_tokens()`: each TP rank takes the argmax of its own vocab shard, and only `(value, index)` pairs are gathered. `LocalArgmaxMixin` does not fit this class. It has no `self.lm_head`, since the head is chosen per `spec_step_idx`, and its layer returns the pre-norm hidden state, so `shared_head`'s RMSNorm must run first. Skipping the norm, as the v3.2 MTP legitimately does, raises no error and silently changes the draft token. Both methods take `spec_step_idx`, which `MultiModuleMTPSpeculator` passes. A second commit rewrites the flag's docstring to describe it as a trade with a break-even draft batch.

The flag defaults to off, and only `DeepSeekMTPModel` gains the method. The same gap in `deepseek_v32/amd/mtp.py` needs a different change and is out of scope here.

## Claims

- DeepSeek-V3 / R1 MTP with the flag on now starts and generates. On `main` it raises at init.
- The draft tokens match `compute_logits().argmax(-1)` exactly: agreement is 1.0000 at TP=2 and TP=4 for batches 1 to 1024.
- GSM8K on DeepSeek-R1-0528 scores **0.9568**, against **0.9530 / 0.9560** for two runs of `main`. That is within the base-vs-base drift of 0.0030.
- The cost is about 20 µs per draft step at TP=2 and 95 µs at TP=4. The flag pays off only above a break-even draft batch: ≈16–32 at TP=2 and ≈128–256 at TP=4. Below break-even it is a regression.
- End to end, at concurrency 64 and TP=4, results are flat: **+0.8%** tok/s.

## Validation

The new `test_mtp_local_argmax.py` checks that `get_top_tokens()` matches `compute_logits().argmax(-1)` on a real `SharedHead`, including with a padded vocab. A non-uniform norm weight makes a skipped `shared_head` visible. On `main@7128f568ac` (MI325X):

| tree | result |
|---|---|
| `main` | 3 failed |
| this PR | **3 passed** |
| this PR without `shared_head` | 2 failed, 1 passed |

The measurements below were taken on MI355X against `main@94f4170df3`. The `get_top_tokens` path did not change between that commit and `main@7128f568ac`.

The sampling step was timed at DeepSeek-V3 shapes over five alternated pairs per point. Token agreement was 1.0000 at every point:

| TP | batch | `main` | this PR |
|---|---|---|---|
| 2 | 1 / 64 / 1024 | 222 / 399 / 3289 µs | 219 / 272 / 811 µs |
| 4 | 1 / 256 / 1024 | 225 / 573 / 1855 µs | 314 / 392 / 489 µs |

GSM8K and the serve runs used DeepSeek-R1-0528 (fp8) at TP=4 with one MTP draft token. The `main` arm ran with the flag off. GSM8K was 5-shot greedy on all 1319 items. `vllm bench serve` used random 1024-in / 512-out at concurrency 64, and the table shows the median of three runs:

| metric | `main` | this PR |
|---|---|---|
| Total tok/s | 5764.9 | 5812.4 |
| Median TPOT (ms) | 29.49 | 29.49 |
| Median TTFT (ms) | 332.0 | 328.7 |

A draft batch of 64 is below the TP=4 break-even. The per-step cost is about 0.3% of TPOT, which is inside the ~5% throughput spread. The gain needs a larger draft batch.
