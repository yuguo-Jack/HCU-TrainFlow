# [CI] Add pre-commit check for dead source_file_dependencies paths

[Upstream PR](https://github.com/vllm-project/vllm/pull/59706) · state: open · merged: False

## Original PR description

## Overview

Adds a pre-commit check that fails when a Buildkite `source_file_dependencies` entry matches no tracked file, so a stale path can no longer silently stop a CI job from triggering. Related to #51225; complements #51345 (this PR edits no pipeline YAML and shares no files with it).

## Claims

- Catches the class of problem in #51225 permanently: any `source_file_dependencies` entry in the pipeline directories declared by `job_dirs` (`test_areas/`, `intel_jobs/`, `hardware_tests/`) that is not a prefix of a tracked file fails the hook, including entries nested in `mirror.amd` blocks. Exclusions (`!path`) are skipped: a dead one excludes nothing, so it cannot stop a job from triggering.
- Starts green without touching any pipeline: the 17 paths (36 entries) already dead on main are listed in `tools/pre_commit/source_file_dependencies_allowlist.txt`, which is meant to only shrink as they are fixed.
- The new unit test runs in CI: it is added to the existing CPU job that already runs the test-tethering check's tests.

```

  .buildkite/test_areas/docker.yaml: vllm/injected_dead_dir/
...

```

The checked code never touches the GPU, and neither the check nor the test imports vllm. Full logs available on request.

## Details

- Motivation: #51225 was caused by renamed `csrc` paths leaving jobs that never trigger; the audit behind it found dead entries well beyond `csrc` (e.g. `vllm/worker/worker_base.py`, `vllm/sampling_metadata.py`). A hand fix doesn't stop it recurring.
- Design: reuses `job_dirs`/`JOB_GLOB` from `check_buildkite_step_keys.py` and `tracked_files` from `check_label_rules.py`; the allowlist follows `test_tethering_allowlist.txt`. About 80 lines of new code.
- Not a duplicate: no open PR or issue proposes this lint; #51345 and #61058 fix entries but don't prevent new ones; #61058 remaps most of the allowlisted paths, and this check complements it.
- Limitations: a path counts as live if it is a prefix of any tracked file (so `vllm/foo` is live if `vllm/foobar.py` exists); glob characters are not special-cased (none are used today); `.buildkite/test-amd.yaml` is not scanned (it is outside `job_dirs` and is being folded into `test_areas/`); a stale allowlist line is not reported, unlike the tethering check (six went stale between the first revision and the rebase and were pruned by hand).
- The check imports its sibling checks by bare name, as pre-commit runs it, so the test prepends `tools/pre_commit` to `sys.path`.

Dead exclusions are treated as errors, with a misleading message. The script strips ! and flags the path. A dead !path excludes nothing, so it can't stop a job from triggering, which is the problem the PR exists to catch. One allowlist entry, scripts/, comes only from !scripts/ in hardware_tests/ascend_npu.yaml. Either skip ! entries or print a separate message for them.
