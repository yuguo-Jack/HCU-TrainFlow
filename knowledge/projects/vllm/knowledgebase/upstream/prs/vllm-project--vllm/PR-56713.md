# [ROCm][DI][CI] Swap container ionic RoCE userspace to a host-compatible AINIC channel

[Upstream PR](https://github.com/vllm-project/vllm/pull/56713) · state: closed · merged: False

## Original PR description


## Purpose

On the AMD MI350X disaggregated-inference cluster, the `vllm-openai-rocm:nightly`
image ships an AINIC/ionic userspace provider that the hosts' ionic kernel module
rejects outright. `libibverbs` refuses every NIC at enumeration time with below error:

```
libibverbs: Warning: Driver ionic does not support the kernel ABI of 4 (supports 1 to 1) for device /sys/class/infiniband/ionic_0 [.. ionic_1 .. ionic_7]
```

**Reference**: All of the AMD DI CI fails with the same error. 
https://buildkite.com/vllm/amd-distributed-inference-ci/builds/71/list

## Fix
Add `swap_ainic_userspace.sh`, which replaces the image's ionic userspace
(`libionic1`, `libionic-dev`, `ionic-common`) with a pinned `repo.radeon.com`
channel. It resolves exact package versions from the channel's `Packages` index
rather than hardcoding them (channel names and package versions do not track each
other), then `apt-mark hold`s them so a later upgrade cannot walk them forward.
Only userspace is touched; kernel modules and NIC firmware live on the host.
`run_xPyD_disagg.slurm` applies the swap in a root container before serving, then
`docker commit`s the result and serves the job from that image. The swap is done
ahead of launch rather than inside the serving container because:
- the serving container runs as the calling user (`--user $(id -u):$(id -g)`), so
  `apt` cannot run in it, and running it as root would leave root-owned artifacts
  on shared NFS;
- the ionic mount paths are read-only bind mounts in the serving container, and
  `apt` cannot replace a bind-mount target;
- the swap purges `libionic1` first, so there is a window with no usable provider,
  which must not overlap a process that is about to call into ibverbs.
The committed tag is keyed on the source image ID, so a moving tag such as
`:nightly` rebuilds automatically instead of silently serving a swap baked on top
of an older pull. Repeat runs on the same node reuse it.
## Knobs
| Variable | Default | Effect |
| --- | --- | --- |
| `AINIC_SWAP_CHANNEL` | `1.117.3-hydra` | Channel to install. `none` disables the swap and serves the image's own provider. |
| `SKIP_IONIC_MOUNTS` | `0` | `1` skips the host ionic bind-mounts. |
The two compose: the bake deliberately runs without the mounts so `apt` can write
those paths, and the mounts are layered back on at serve time unless skipped.

## Test plan
DeepSeek-V3, TP 1P1D (`WIDE_EP_MODE=0 xP=1 yD=1`), 2x MI350X nodes, gsm8k
accuracy gate, `vllm/vllm-openai-rocm:nightly`:
| Config | Devices seen | Result |
| --- | --- | --- |
| Mounts only (pre-change baseline) | 8 | PASS `exact_match=0.9424` |
| No mounts, no swap | **0** | **FAIL** — 16 workers aborted in `RdmaManager` |
| Swap, no mounts | 8 | PASS `exact_match=0.9424` |
| Swap + mounts | 8 | PASS `exact_match=0.9484` |
| Swap, no mounts (this branch on a clean main) | 8 | PASS `exact_match=0.9477` |
The swapped image was also verified directly: packages installed and held, and
`ibv_get_device_list()` returning all 8 devices (`ionic_0`..`ionic_7`) where the
unmodified image returned 0.

## Additional Notes 
The swap defaults to **on** so this cluster's CI is correct without extra
configuration. On a cluster whose image provider already matches its kernel
module, set `AINIC_SWAP_CHANNEL=none`. It also requires the compute nodes to
reach `repo.radeon.com`.
