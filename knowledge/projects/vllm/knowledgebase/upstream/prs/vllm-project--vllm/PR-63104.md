# [Perf][Attention] FA4 sparse MLA prefill with query groups for 16-64 heads per rank

[Upstream PR](https://github.com/vllm-project/vllm/pull/63104) · state: open · merged: False

## Original PR description



## Overview

`FLASH_ATTN_MLA_SPARSE_FA4` sends sparse MQA prefill to FlashInfer's trtllm-gen kernel, one query at a time. This PR runs it on FA4 instead: 2, 4 or 8 consecutive queries of a request share each 128-head kernel row (the grouped mode of vllm-project/flash-attention#205), and a new Triton kernel builds each group's top-k union.

Depends on vllm-project/flash-attention#205: while this is a draft, `cmake/external_projects/vllm_flash_attn.cmake` points at that PR's commit. Related PRs: #48726 (LiteDSA, under review) groups neighbouring queries in the same way for the FP8 sparse MLA path, with its own SM100 kernel in the FlashInfer sparse backend, and also covers 8 heads per rank; the reviewer has asked for it to be split into separate PRs. This PR is a smaller, BF16-only change confined to the FA4 sparse MLA backend: it reuses FA4's MLA kernel through vllm-project/flash-attention#205, and the two PRs touch no common files. The same idea is merged in SGLang for SM90 and SM120 (sgl-project/sglang#32779). This PR builds on #55866 (FA4 sparse MQA decode) and leaves the masked-MHA routing from #53785 as is.

## Claims

- **Sparse MQA prefill is 1.37-1.55x faster end to end** on `nvidia/GLM-5.2-NVFP4` (TP4, B300, BF16 KV). With default routing this covers pure prefills above the masked-MHA threshold (48K tokens: 2.59 → 1.72 s) and prefills on cached context (1.42-1.43x); shorter pure prefills use masked MHA and are unchanged.
- **No accuracy loss:** with every prefill forced through the new path, GSM8K 5-shot goes from 93.63% to 93.86% (± 0.67), and perplexity over 46K teacher-forced tokens does not change.
- Decode, and the configurations grouping does not cover (DCP, PCP, HiSparse, heads per rank other than 16, 32 or 64), keep their current kernels.

```python
"""Prefill latency of two servers on public-domain text (Project Gutenberg #1342 and #2701).

Each request asks for one output token, so its latency is the prefill. Every trial uses a
different slice of text, and every prompt starts with a per-run salt, so neither trials nor
reruns hit each other's prefix cache. The servers take turns on identical prompts.
  python e2e_prefill.py --urls http://127.0.0.1:8400 http://127.0.0.1:8500 --out r.json
"""

import argparse
import json
import secrets
import statistics
import time
import urllib.request

BOOKS = ["pg1342.txt", "pg2701.txt"]  # https://www.gutenberg.org/cache/epub/{1342,2701}/pg{1342,2701}.txt
CHARS_PER_TOKEN = 4.0


def load_text() -> str:
    parts = []
    for path in BOOKS:
        t = open(path, encoding="utf-8").read()
        parts.append(t[t.index("*** START OF THE PROJECT GUTENBERG EBOOK") + 200 :])
    return "\n\n".join(parts)


def complete(url: str, prompt: str) -> tuple[float, int]:
    body = {"model": "glm52", "prompt": prompt, "max_tokens": 1, "temperature": 0}
    req = urllib.request.Request(f"{url}/v1/completions", data=json.dumps(body).encode(),
                                 headers={"Content-Type": "application/json"})
    t0 = time.perf_counter()
    with urllib.request.urlopen(req, timeout=1800) as r:
        usage = json.load(r)["usage"]
    return time.perf_counter() - t0, usage["prompt_tokens"]


def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("--urls", nargs="+", required=True)
    ap.add_argument("--pure", type=int, nargs="*", default=[8192, 16384, 32768, 49152])
    ap.add_argument("--context", type=int, nargs=2, action="append", default=None,
                    metavar=("CACHED", "NEW"), help="cached prefix tokens and new tokens")
    ap.add_argument("--trials", type=int, default=3)
    ap.add_argument("--salt", default=secrets.token_hex(8))
    ap.add_argument("--out", required=True)
    args = ap.parse_args()
    contexts = args.context if args.context is not None else [[16384, 8192], [24576, 8192]]
    text, cursor = load_text(), 0
    print(f"salt {args.salt}", flush=True)

    def take(tokens: int, salted: bool) -> str:
        nonlocal cursor
        n = int(tokens * CHARS_PER_TOKEN)
        if cursor + n > len(text):
            cursor = 0
        s = text[cursor : cursor + n]
        cursor += n
        return f"[{args.salt}]\n{s}" if salted else s

    results = []
    cases = [("pure", n, 0) for n in args.pure] + [("context", new, cached) for cached, new in contexts]
    for kind, new, cached in cases:
        runs = {u: [] for u in args.urls}
        tokens = {}
        for trial in range(args.trials):
            prefix = take(cached, salted=True) if cached else ""
            body = take(new, salted=not cached)
            order = args.urls if trial % 2 == 0 else args.urls[::-1]
            for u in order:
                if cached:
                    complete(u, prefix)  # warm the prefix cache, not timed
                dt, n_tok = complete(u, prefix + body)
                runs[u].append(dt)
                tokens[u] = n_tok
        row = {"kind": kind, "cached_tokens": cached, "new_tokens": new,
               "prompt_tokens": tokens, "latency_s": {u: [round(x, 4) for x in v] for u, v in runs.items()},
               "median_s": {u: round(statistics.median(v), 4) for u, v in runs.items()}}
        base, other = args.urls[0], args.urls[-1]
        row["speedup"] = round(row["median_s"][base] / row["median_s"][other], 3)
        print(json.dumps(row), flush=True)
        results.append(row)
    json.dump(results, open(args.out, "w"), indent=1)


if __name__ == "__main__":
    main()
```

```python
"""Teacher-forced accuracy of the prefill: per-position logprob of each prompt token and the model's
top-1 next token, read through prompt_logprobs. Every value comes out of the prefill forward, so
two servers can be compared position by position over many tokens, and two runs on one server give
the run-to-run noise floor. Prompts are ~8K-token slices of public text (Project Gutenberg #1342,
#2701 and the GPL-3 / GFDL-1.3 license texts).
  python prompt_logprob_probe.py --base-url http://127.0.0.1:8400 --cache-salt r1 --out a.json
  python prompt_logprob_probe.py --compare a.json b.json
"""

import argparse
import json
import math
from pathlib import Path

import httpx

CHARS = 32_000


def prompts() -> list[str]:
    texts = []
    for path in ["pg1342.txt", "pg2701.txt"]:  # Project Gutenberg #1342 and #2701
        t = open(path, encoding="utf-8").read()
        texts.append(t[t.index("*** START OF THE PROJECT GUTENBERG EBOOK") + 200 :])
    lic = Path("/usr/share/common-licenses")
    licenses = (lic / "GPL-3").read_text() + "\n\n" + (lic / "GFDL-1.3").read_text()
    austen, melville = texts
    return [austen[200_000 : 200_000 + CHARS], austen[500_000 : 500_000 + CHARS],
            melville[300_000 : 300_000 + CHARS], melville[700_000 : 700_000 + CHARS],
            melville[1_000_000 : 1_000_000 + CHARS], licenses[:CHARS]]


def probe(base_url: str, model: str, cache_salt: str) -> list[dict]:
    out = []
    with httpx.Client(timeout=1800) as c:
        for i, p in enumerate(prompts()):
            ids = c.post(f"{base_url}/tokenize", json={"model": model, "prompt": p}).json()["tokens"]
            r = c.post(f"{base_url}/v1/completions", json={
                "model": model, "prompt": ids, "max_tokens": 1, "temperature": 0, "prompt_logprobs": 1,
                "cache_salt": cache_salt}).json()
            # position j maps token id -> {logprob, rank} for prompt token j and the top-1 token
            rows = r["choices"][0]["prompt_logprobs"][1:]
            lp = [row[str(t)]["logprob"] for row, t in zip(rows, ids[1:], strict=True)]
            top = [int(next(k for k, v in row.items() if v["rank"] == 1)) for row in rows]
            out.append({"prompt_tokens": len(ids), "logprobs": lp, "top1": top})
            print(f"prompt {i}: {len(ids)} tokens, mean logprob {sum(lp) / len(lp):.4f}", flush=True)
    return out


def compare(a: list[dict], b: list[dict]) -> None:
    da, agree, n, sa, sb = [], 0, 0, 0.0, 0.0
    for x, y in zip(a, b):
        assert len(x["logprobs"]) == len(y["logprobs"])
        da += [abs(p - q) for p, q in zip(x["logprobs"], y["logprobs"])]
        agree += sum(p == q for p, q in zip(x["top1"], y["top1"]))
        n += len(x["logprobs"])
        sa += sum(x["logprobs"]); sb += sum(y["logprobs"])
    da.sort()
    print(f"{n} positions | mean |dlogprob| {sum(da) / n:.5f}, p99 {da[int(0.99 * n)]:.4f}, max {da[-1]:.4f} | "
          f"top-1 agreement {agree / n:.4%} | perplexity {math.exp(-sa / n):.4f} vs {math.exp(-sb / n):.4f}")


if __name__ == "__main__":
    ap = argparse.ArgumentParser()
    ap.add_argument("--base-url")
    ap.add_argument("--model", default="glm52")
    ap.add_argument("--cache-salt", default="r1")
    ap.add_argument("--out")
    ap.add_argument("--compare", nargs=2)
    a = ap.parse_args()
    if a.compare:
        compare(*(json.load(open(f)) for f in a.compare))
    else:
        json.dump(probe(a.base_url, a.model, a.cache_salt), open(a.out, "w"))
```

```python
"""Time build_query_group_union for one prefill request: N queries, top-k 2048, groups of 8.

Each group of 8 consecutive queries shares 1,900 causal positions and each query adds 148 of its own,
so unions are ~3K rows, like GLM-5.2's measured 2.3-3.2K. Median of 20 CUDA-event-timed calls.
"""

import torch

from vllm.triton_utils import triton
from vllm.v1.attention.backends.mla.sparse_utils import build_query_group_union

TOPK, GROUP, BLOCK, SHARED = 2048, 8, 64, 1900


def make_topk(n: int) -> torch.Tensor:
    pos = torch.arange(n, device="cuda")
    limit = (pos // GROUP * GROUP + GROUP).clamp(max=n)[:, None]  # causal limit of the group
    g = torch.Generator(device="cuda").manual_seed(0)
    shared = (torch.rand(n // GROUP, SHARED, device="cuda", generator=g).repeat_interleave(GROUP, 0) * limit).long()
    own = (torch.rand(n, TOPK - SHARED, device="cuda", generator=g) * limit).long()
    return torch.cat([shared, own], 1).to(torch.int32)


for n in (8192, 16384, 32768, 49152):
    topk = make_topk(n)
    block_table = torch.randperm(triton.cdiv(n, BLOCK) + 64, device="cuda")[: triton.cdiv(n, BLOCK)].to(torch.int32)
    build = lambda: build_query_group_union(  # noqa: E731
        topk, block_table, group_size=GROUP, max_seq_len=n, block_size=BLOCK, block_stride_rows=BLOCK,
        width=GROUP * TOPK)
    _, lens = build()
    times = []
    for _ in range(20):
        start, end = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
        start.record(); build(); end.record(); torch.cuda.synchronize()
        times.append(start.elapsed_time(end))
    t = sorted(times)[len(times) // 2]
    print(f"N={n:6d}: union mean {lens.float().mean():.0f} rows | build {t:.3f} ms | x21 index groups {21 * t:.1f} ms")
```

## Details

**Why.** FA4's sparse MLA kernel needs 128 query heads per KV head. Under tensor parallelism DeepSeek-V3.2 and GLM-5.x have 16-64 heads per rank, so this backend runs prefill on trtllm-gen one query at a time, and each query streams its own 2,048 KV rows. Consecutive queries select mostly the same rows, though: on GLM-5.2 the union of 8 consecutive queries' top-k is 1.2-1.7x the size of one list. flash-attention#205 lets each 128-head row hold `128 / heads` queries that gather their union once, with a membership mask per query; at 16 heads it is 4.0x faster than trtllm-gen on GLM-5.2's top-k.

**Changes**

- `sparse_utils.build_query_group_union` (Triton, two kernels): for one request, marks each group's selected positions in a byte-per-position bitmap (bit t for query t), then emits the union in position order, mapped to KV rows through the request's block table, as `row | membership << 24`, -1 padded to a whole 128-entry tile, plus the union length per group.
- `FlashAttnMLASparseFA4Impl._forward_mqa_kernel`: for prefill, the first `n // G * G` queries of each request run grouped; the last `n % G`, decode rows and padding rows run on the one-query-per-row FA4 kernel this backend already uses for decode. Prefill stays on trtllm-gen when the heads per rank are not 16, 32 or 64, under DCP or PCP, with HiSparse, when decode needs an LSE, or when the cache has 2^24 - 1 or more KV rows.
- The union depends only on the logical top-k and the block table, which an index group shares, so the group's first layer builds it and the others reuse it (`_query_group_unions`).
- `_forward_mqa_kernel` doesn't receive the metadata, so `forward_mqa` keeps it on the impl for the duration of the call.
- `flash_attn_varlen_func` passes `gather_kv_query_group_size` through (default 1, no change).

**Tradeoffs and limitations**

- **Query copy.** The DSA model's absorbed `q_nope` is head-major (`bmm(...).transpose(0, 1)`), while grouping needs token-major rows, so the grouped rows are copied (tokens × heads × 512 BF16). Producing a token-major `q_nope` in the model would remove the copy.
- **Union build scaling.** Each group scans a bitmap as long as the request, so the cost grows with prefill length × sequence length: 1.9% of the prefill at 48K. A sort-based union would avoid that if longer contexts need it.
- **Low overlap.** When consecutive queries' top-k barely overlap, grouping is slower than one query per row: break-even is near a union of 5.8 lists per group of 8, while GLM-5.2's unions are 1.2-1.7 lists (flash-attention#205).
- **First call compiles.** The grouped kernel is compiled on first use. Under default routing, the first grouped prefill of a process took ~4 s longer (5.95 s vs 1.73 s at 48K). With forced MQA, the startup dummy runs already compile it. vLLM's JIT warmup doesn't cover FA4's top-k paths yet (see the TODO in `v1/attention/backends/mla/prefill/flash_attn.py`).
- **Routing.** With this PR, MQA prefill also beats masked MHA from 8K to 32K (0.266 vs 0.346 s at 7.9K, 1.065 vs 1.474 s at 31.2K), so the FA4 entries of `_MASKED_MHA_THRESHOLDS` could move down. That changes a routing policy, so I'd propose it separately.
- **KV dtype.** BF16 KV only, like the rest of this backend.
