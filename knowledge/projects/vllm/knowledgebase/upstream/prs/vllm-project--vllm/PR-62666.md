# [ROCm][Perf] Extend ROCM_SEGMENTED_ATTN to D=512 for Gemma 4

[Upstream PR](https://github.com/vllm-project/vllm/pull/62666) · state: open · merged: False

## Original PR description



## Overview

Extend `ROCM_SEGMENTED_ATTN` with D=512 support to enable Gemma 4 usage, and improved FP8 configuration selection. bringing the opt-in backend to Gemma 4's mixed D=256/D=512 attention on RDNA.


## Claims

- On two Radeon AI PRO R9700 GPUs, the measured Gemma 4 eight-turn conversation workload shows **1.68–2.83× per-request output tokens/s for 12B** and **1.60–2.50× for 26B-A4B**, comparing the recorded automatic `TRITON_ATTN` backend with tuned, opt-in segmented attention.
- Add gfx12 native FP8-to-BF16 conversion modes and typed, with better config selection for fp8 kv-cache dtype.

### Setup and measurement

Hardware: **2× Radeon AI PRO R9700, gfx1201**, ROCm 10, TP2. 

We benchmarked **eight-turn conversations with growing input history** using GuideLLM. Each conversation adds **2,048 new synthetic prompt tokens per turn** and requests **512 output tokens per turn**. Earlier turns remain in the conversation, so the input grows to approximately 20K tokens by the last turn; prefix caching is enabled to reuse that history. The client sends streaming `/v1/chat/completions` requests with temperature 0 and runs **1, 2, 4, or 8 concurrent conversations**, producing 8, 16, 32, or 64 completed turn requests per run, respectively.

Each baseline/candidate comparison has **two repetitions, each with a fresh server**. Startup/tuning time is excluded. The serving commands are listed with each model's results.

The complete study includes the Qwen control and short MTP controls to prove there's no regression : **20 serving conditions, 2,400 successful measured turn requests, zero errors or incomplete requests**. Another 960 successful short-primer requests are excluded from measured results. [Full report, raw results, exact setup, per-repetition tables and plots](https://github.com/big-yellow-duck/vllm/blob/23807fde39070d990b0fb4ce63a15384d4e79d8e/README.md).

These measurements use preserved snapshots based on `d9a543c500e9014045d7ae769df0ca7782e31870`; file hashes and the shared-KV fix's kernel-equivalence checks connect them to this PR's `b7a87748e35bad93d4c4fb2e47edf711c14dfad4` checkpoint. They are not measurements against a newly rebased checkout of today's `main`. Results are descriptive synthetic-workload comparisons, not a statistical significance or task-quality claim. Compiler caches persist between repetitions; Qwen logged inference-time JIT in both repetitions, so persistent caches do not establish fully warmed execution.

### GSM8K accuracy (full test set)

Evaluated PR source `a78744c1740972cd0f07fc3ecc8ee2563d7540b2` on **one Radeon AI PRO R9700 (GPU1), TP1**, with both pinned Red Hat FP8 checkpoints listed below. Both arms use BF16 activations and **FP8 KV cache**. Automatic selection actually chose `TRITON_ATTN` for all 48 attention layers in 12B and all 30 in 26B-A4B; the opt-in arm used `ROCM_SEGMENTED_ATTN` throughout, with startup autotuning enabled.

| Model | Automatic (`TRITON_ATTN`) | Tuned `ROCM_SEGMENTED_ATTN` | Difference |
| --- | ---: | ---: | ---: |
| Gemma 4 12B FP8 | 1,247/1,319 (**94.54%**) | 1,248/1,319 (**94.62%**) | +0.076 percentage points |
| Gemma 4 26B-A4B FP8 | 1,264/1,319 (**95.83%**) | 1,265/1,319 (**95.91%**) | +0.076 percentage points |

Each run covers **all 1,319 GSM8K test questions**, with the first five training examples as worked few-shot prompts, greedy chat generation (`temperature=0`, seed `20260715`), thinking disabled, batches of eight and a 4,096-token output cap. All **5,276 responses completed normally**, with zero truncations or missing answer tags. These are text-only accuracy evaluations without speculative decoding. Each segmented run gets one additional question correct; paired exact McNemar p=1 for both models. This supports comparable observed accuracy for these settings, without establishing an accuracy improvement or formal equivalence.

Scoring uses the [original GSM8K tagged-answer extraction and strict string match](https://github.com/openai/grade-school-math/blob/master/grade_school_math/dataset.py), applied uniformly to the saved raw outputs. The stock vLLM final-digit extractor ignores minus signs and reads the trailing `00` in `#### 2:00 pm`; auditing found one falsely credited negative answer in 12B segmented and one correctly tagged time answer rejected in all four runs. The table uses that GSM8K matcher. For transparency, unmodified vLLM scorer counts were 1,246 → 1,248 for 12B and 1,263 → 1,264 for 26B-A4B; all original outputs and scores were retained.

<details>
<summary>Accuracy evaluation options and reproduction</summary>

Run from the PR checkout with a compatible ROCm vLLM environment, one model/backend at a time. The code below selects the 12B checkpoint; switch to the 26B-A4B model and revision shown in its section below, and set memory utilization to `0.95` for that checkpoint. Set `segmented=False` for automatic backend selection.

```python
import re
from vllm import LLM, SamplingParams
from tests.evals.gsm8k.gsm8k_eval import _build_gsm8k_prompts, load_gsm8k_data


def main():
    segmented = True
    options = dict(
        model="RedHatAI/gemma-4-12B-it-FP8-Dynamic",
        revision="2083adceb2a3df0465e6021e08a7196d21dbbb44",
        language_model_only=True, dtype="bfloat16", kv_cache_dtype="fp8",
        tensor_parallel_size=1, max_model_len=8192, max_num_seqs=8,
        max_num_batched_tokens=4096, gpu_memory_utilization=0.90,
        enable_prefix_caching=True, seed=20260715, generation_config="vllm",
        compilation_config={"cudagraph_capture_sizes": [1, 2, 4, 8]},
    )
    if segmented:
        options["attention_config"] = {"backend": "ROCM_SEGMENTED_ATTN"}
        options["kernel_config"] = {"enable_rocm_segmented_attn_autotune": True}
    llm = LLM(**options)
    prompts, _ = _build_gsm8k_prompts(1319, 5)
    _, gold = load_gsm8k_data()
    sampling = SamplingParams(temperature=0, max_tokens=4096, seed=20260715,
                              top_p=1, top_k=-1)

    def answer(text):
        match = re.search(r"#### (-?[0-9.,]+)", text)
        return match.group(1).strip().replace(",", "") if match else None

    correct = 0
    for start in range(0, 1319, 8):
        chats = [[{"role": "user", "content": p}] for p in prompts[start:start + 8]]
        outputs = llm.chat(chats, sampling_params=sampling, use_tqdm=False,
                           chat_template_kwargs={"enable_thinking": False})
        for i, output in enumerate(outputs, start):
            correct += answer(output.outputs[0].text) == answer(gold[i]["answer"])
    print(f"{correct}/1319 = {correct / 1319:.4%}")


if __name__ == "__main__":
    main()
```

Launch with physical GPU1 isolated (`CUDA_VISIBLE_DEVICES=1 HIP_VISIBLE_DEVICES=1`, `ROCR_VISIBLE_DEVICES` unset), with `VLLM_WORKER_MULTIPROC_METHOD=spawn` and `NCCL_PROTO=Simple`. The recorded runs used local snapshots of the pinned revisions, the existing Pixi runtime (`torch 2.13.0+rocm10.0.0`) and existing compiled extensions, with the PR's Python/Triton source. This is a source-worktree evaluation. A read-only worker inspection verified actual backends and both D=256/D=512 groups. The 26B-A4B segmented run reused the identity-validated D=256 tuning cache and tuned its D=512 group separately. These TP1 accuracy runs are separate from the historical TP2 serving measurements below.
