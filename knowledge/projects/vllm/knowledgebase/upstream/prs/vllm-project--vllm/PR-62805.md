# [XPU][LoRA] Support unquantized MoE LoRA via XpuFusedMoe hooks

[Upstream PR](https://github.com/vllm-project/vllm/pull/62805) · state: closed · merged: False

## Original PR description

## Overview

Route unquantized (BF16) MoE LoRA on XPU through `XpuFusedMoe` `activation_hook`/`output_hook` via a new `XPUExpertsBf16LoRA`, instead of Triton experts. Stacked on #62631 (shared `XPUExpertsLoRA` base; draft until it merges, so the diff currently includes its commits) and depends on vllm-project/vllm-xpu-kernels#648.

## Validation

AI assistance (GitHub Copilot) was used. Not a duplicate: #62631 covers MXFP4, #61310 covers FP8/W4A16; no open PR handles unquantized XPU MoE LoRA.

- `tests/lora/test_olmoe_tp.py::{test_olmoe_lora,test_olmoe_lora_mixed,test_olmoe_lora_tp2}` pass on Intel XPU (log shows "XPU Unquantized MoE LoRA backend").
- No perf comparison vs the Triton path yet.
