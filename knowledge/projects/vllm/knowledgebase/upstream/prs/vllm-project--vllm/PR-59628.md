# [ROCm] Enable DeepSeek-V3.2 / GLM-5.3 sparse MLA on gfx11

[Upstream PR](https://github.com/vllm-project/vllm/pull/59628) · state: open · merged: False

## Original PR description

## Purpose

DeepSeek-V3.2 and GLM-5.3 don't run on gfx11. For sparse MLA, `ROCM_AITER_MLA_SPARSE` is the only backend on offer, and its default path needs AITER's MLA kernels, which have no gfx11 build. On current main the server starts, but the first request fails in AITER's `get_mla_metadata_v1`:

```
RuntimeError: [module_mla_metadata] was built against a different pybind11 ABI
than module_aiter_core, so it cannot see the aiter_tensor_t registration ...
```

The Triton sparse path in the same file already handles the 512 + 64 RoPE layout, but `_use_rocm_sparse_triton()` only picks it when `head_size == kv_lora_rank`. This PR lets gfx11 take that path too.

Long-context decode on this path goes through the split-K BF16 kernel from #58584, which needs #61774 for the 576-wide layout. Without #61774, decode past 512 tokens fails with `arange's range must be a power of 2`.

Tests: one new routing test for the gfx11 case, and the existing routing tests now pin `on_gfx11` to `False` so they also pass on gfx11 hardware.

## Duplicate-work check

Searched open PRs and issues for `rocm_aiter_mla_decode_fwd`, GLM-5.3 and DeepSeek-V3.2 on gfx11, and sparse MLA fallback on ROCm. No duplicate.

- #61774 fixes the split-K reduction for non-power-of-two head dims. It is needed together with this PR for long-context decode.
- #52970 is about DeepSeek-V4 and AITER's Triton kernels. It does not touch `_use_rocm_sparse_triton`.

## Test Result

Tested on 4x Strix Halo / Radeon 8060S / gfx1151 with `TP=4`, ROCm nightly wheel, with #61774 applied.

```
vllm serve Tech2wild/GLM-5.3-Int4-Int8Mix \
    --tensor-parallel-size 4 \
    --distributed-executor-backend ray \
    --max-model-len 32768 \
    --max-num-batched-tokens 512 \
    --enforce-eager
```

Before: the first request fails with the error above.

After:

```
"What is 17 times 23?"                      -> 17 × 23 = 391
needle in a ~1.7k-token prompt               -> correct
split-K decode (16 splits at 2048 tokens)    -> runs, matches single-pass
```

```
pytest tests/v1/attention/test_rocm_glm5next_sparse.py
  35 passed
```
