# [Perf][GLM-5.3] Enable GLM low-latency BF16 GEMM on SM107

[Upstream PR](https://github.com/vllm-project/vllm/pull/62843) · state: closed · merged: True

## Original PR description



## Overview


The GLM-5.2/5.3 low-latency BF16 GEMM selection (CuTe DSL skinny GEMM + `dsv3_fused_a_gemm` at decode batch sizes) is gated to SM103, so on VRNVL72 (SM107) every unquantized decode projection runs cuBLAS. This PR enables the selection on SM107 with a table swept on VRNVL72, the same way #54606 enabled the Kimi-K3 low-latency GEMM plan on SM107.

## Claims


- **VRNVL72 coverage:** on SM107, GLM-5.2/5.3 BF16 decode projections use tuned CuTe DSL skinny GEMM / `dsv3_fused_a_gemm` configs where they beat cuBLAS. That covers fused qkv_a, q_b / indexer wq_b, o_proj (M ≤ 3), indexer wk + weights_proj, shared-expert gate_up / down and MTP eh_proj, at TP4. TP8 q_b keeps the existing SM103 row, re-measured on sm107.
- **Kernel times:** each shape is 1.2× to 1.9× faster than cuBLAS at its target M on VRNVL72 (table below).
- **End-to-end (GLM-5.3-NVFP4, TP4, VRNVL72, 8k in / 1k out, vs `main` behavior):** output throughput rises by +8.1% at c1 (ITL 6.35 → 5.86 ms), +5.9% at c2 and +2.2% at c4–c8 without speculative decoding. With MTP K=3 it rises +8.5% at c1, in a single run.
- **Accuracy:** GSM8K is unchanged within run-to-run noise: 0.9735 stock vs 0.9773 with this PR.
- **No change on other devices:** SM103 keeps its existing table and routing (same shapes, M ranges, backends and CuTe warmup set). Every other device stays on the default GEMM. Checked on B300: tests, routing, GSM8K and throughput are unchanged (see Validation).

## Validation


**Kernel microbenchmark** (one VRNVL72 GPU, BF16, CuTe DSL skinny GEMM vs cuBLAS; a (shape, M) entry is in the table only where CuTe wins by more than the 0.15 µs noise band):

| Projection (local N×K, TP4) | M | CuTe (µs) | cuBLAS (µs) | Speedup |
|---|---|---|---|---|
| fused qkv_a, replicated (2624×6144) | 4 | 5.84 | 6.91 | 1.18× |
| q_b / indexer wq_b (4096×2048) | 4 | 4.31 | 5.71 | 1.32× |
| o_proj (6144×4096) | 1 | 5.90 | 7.77 | 1.32× |
| indexer wk + weights_proj (160×6144) | 4 | 2.83 | 5.43 | 1.92× |
| shared expert gate_up (1024×6144) | 4 | 3.96 | 5.40 | 1.36× |
| shared expert down (6144×512) | 4 | 3.19 | 4.28 | 1.34× |
| MTP eh_proj (6144×12288) | 1 | 12.90 | 16.96 | 1.31× |

M=4 is the target-model batch for one request with MTP K=3. The TP8 q_b entry (2048×2048) is the existing SM103 row; re-measured on VRNVL72, it beats cuBLAS at every measured M:
- CuTe at M=1–2: 3.2–3.3 vs 5.0 µs.
- `dsv3_fused_a_gemm` at M=3–16: 4.0–4.2 vs 4.9–5.1 µs.

**Decode step profile** (nsys, GLM-5.3-NVFP4 TP4 on one VRNVL72 tray, MTP K=3, c=1; the SM107 table vs the SM103 table reused on SM107):
- Step time: 6.97 → 6.87 ms.
- Kernels per step: 2,004 → 1,801.
- Dense-GEMM kernel time: 4,355 → 3,859 µs per step.

Less of the GEMM saving reaches step time because at c=1 the routed-MoE chain on the auxiliary stream is the critical path.

**Accuracy:** GSM8K 5-shot 0.9765 with this change combined with other decode-path changes, vs 0.976 stock (GLM-5.3-NVFP4, TP4, VRNVL72, real MTP verification).

**Tests:**
- `pytest tests/kernels/test_bf16_skinny_gemm.py -k glm`.
- GPU (SM103 / SM107): the shape tests now cover the union of both tables' CuTe configs and the SM107 `dsv3_fused_a` range.
- `ruff check`, `ruff format --check` and `typos` pass at the versions pinned in pre-commit.

**End-to-end A/B** 
- **Model and hardware:** GLM-5.3-NVFP4, TP4 on one VRNVL72 node.
- **Server:** the 8k1k recipe (`--kv-cache-dtype fp8_e4m3 --max-model-len 9216 --quantization modelopt_fp4`, Rust front end).
- **Client:** aiperf, synthetic 8000 in / 1000 out, ignore_eos, at least 20 requests per point (5×C at c8).
- **Run order:** stock and this PR alternated (stock, PR, stock, PR), then the MTP arms.
- **Engagement:** every PR arm logged the SM107 table as installed, with both backends available.

| Spec decoding | c | Stock out tok/s (run 1 / run 2) | This PR out tok/s (run 1 / run 2) | Δ | Stock ITL (ms) | This PR ITL (ms) |
|---|---|---|---|---|---|---|
| none | 1 | 153.0 (152.6 / 153.4) | 165.3 (165.2 / 165.4) | **+8.1%** | 6.35 | 5.86 |
| none | 2 | 286.6 (287.5 / 285.6) | 303.5 (303.0 / 304.0) | **+5.9%** | 6.69 | 6.30 |
| none | 4 | 506.2 (505.7 / 506.6) | 517.5 (517.6 / 517.4) | **+2.2%** | 7.42 | 7.26 |
| none | 8 | 860.2 (858.0 / 862.3) | 879.4 (877.3 / 881.6) | **+2.2%** | 8.58 | 8.39 |
| MTP K=3 | 1 | 201.1 | 218.2 | +8.5% | 4.78 | 4.39 |
| MTP K=3 | 2 | 350.4 | 357.6 | +2.0% | 5.27 | 5.27 |
| MTP K=3 | 4 | 555.1 | 562.2 | +1.3% | 6.74 | 6.53 |

- **Variability:** the two runs per arm without MTP differ by at most 0.7%, well below the deltas.
- **MTP rows:** one run per arm. Sampling is at temperature 1, so acceptance varies: the mean acceptance length over the sweep was 1.58 (stock) vs 1.61 (PR), so part of the MTP difference may come from acceptance.
