# [Bugfix][Spec Decode] Separate manager and kernel block sizes in DFlash DCP slot mapping

[Upstream PR](https://github.com/vllm-project/vllm/pull/60386) · state: closed · merged: False

## Original PR description



## Overview

Separates the KV-cache manager block size (`block_sizes[gid]`) from the attention kernel block size (`kernel_block_sizes[gid]`) in DFlash/DSpark Decode Context Parallelism (DCP) slot mapping so that DCP ownership and rank-local positions are computed in manager-block coordinates before indexing the expanded kernel block table.

Fixes #59184 (follows up on #51031 and #52188).

## Claims

- Fixes DFlash/DSpark context and query KV slot mapping when `cp_size > 1` and `block_sizes[gid] != kernel_block_sizes[gid]`.
- Eliminates duplicate block-table lookup and null-block masking boilerplate between context and query slot calculations in `_prepare_dflash_inputs_kernel` by consolidating the two-phase lookup inside `cp_local_slot`.

## Details

### Root Cause

`BlockTables` (`vllm/v1/worker/gpu/block_table.py`) maintains two block sizes per KV-cache group `gid`:
1. `self.block_sizes[gid]` (physical/manager block size `B`), which defines DCP virtual-block ownership (`virtual_block_size = B * CP_SIZE`) and rank-local token position (`local_pos = virtual_block_idx * B + local_offset`).
2. `self.kernel_block_sizes[gid]` (attention kernel sub-block size `K`), into which each manager block is expanded (`bpk = B // K` kernel block IDs per manager block in `input_block_tables[gid]`).

When #51031 (`0ecc284790`) updated `BlockTables._compute_slot_mappings_kernel` to separate `kv_block_size` from `kernel_block_size`, `DFlashSpeculator.propose` and `cp_local_slot` (added in #52188, `d1e3eee6fb`) continued passing only `kernel_block_sizes[gid]` as `block_size` and indexing `input_block_tables` via `pos // (block_size * CP_SIZE)` prior to DCP localization. When `cp_size > 1` and `B != K`:
- Global positions were wrapped modulo `K * CP_SIZE` instead of `B * CP_SIZE`, assigning tokens to the wrong DCP rank.
- Because `local_offsets` spans `[0, B)` while `input_block_tables` entries have size `K`, the expanded block-table index `local_positions // kernel_block_size` must be computed *after* localizing global positions with `block_size`.

### Implementation

- **`vllm/v1/worker/gpu/cp_utils.py` (`cp_local_slot`):** Computes `local_positions` and `is_local` using manager `block_size`, then indexes `block_table_row_ptr` using `local_positions // kernel_block_size` (masked by `is_local`), checks for the null block (`block_id != 0`), and computes `block_id * kernel_block_size + (local_positions % kernel_block_size)`.
- **`vllm/v1/worker/gpu/spec_decode/dflash/speculator.py`:** Passes both `self.block_tables.block_sizes[gid]` and `self.block_tables.kernel_block_sizes[gid]` from `DFlashSpeculator.propose` into `prepare_dflash_inputs` and `_prepare_dflash_inputs_kernel`.
- **`tests/v1/spec_decode/test_dflash_prepare_inputs.py`:** Extends `_run_prepare` with `block_size` and `kernel_block_size` parameters and adds `test_prepare_dflash_inputs_dcp_with_smaller_kernel_blocks`.
