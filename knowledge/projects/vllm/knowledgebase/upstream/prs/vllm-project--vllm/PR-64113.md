# [CI/Build] Add nixl auto-label rule and assign topic owners

[Upstream PR](https://github.com/vllm-project/vllm/pull/64113) · state: closed · merged: True

## Original PR description

## Overview

Adds a `nixl` auto-label rule to `.github/mergify.yml`, mirroring the existing `mooncake` rule ([#59192](https://github.com/vllm-project/vllm/pull/59192)). PRs touching NIXL-related files or KV-offloading paths — the multi-tiered offloading path (`vllm/v1/kv_offload/`, KVCR tiering) and the NIXL KV connector (`vllm/distributed/kv_transfer/kv_connector/v1/nixl/`, `vllm/distributed/nixl_utils.py`) — are labeled `nixl` and assigned to @ovidiusm and @iyastreb, so the NIXL team gets notified of KVCR / connector changes.

The `nixl` GitHub label itself is created out-of-band (labels are not versioned in this repo, and mergify cannot add a label that does not exist).

## Claims

- PRs touching any path containing `nixl` (case-insensitive) get the `nixl` label. This covers the NIXL KV connector and `vllm/distributed/nixl_utils.py`, NIXL EP dispatch (`vllm/model_executor/layers/fused_moe/prepare_finalize/nixl_ep.py`), EC-transfer NIXL data (`vllm/distributed/ec_transfer/ec_connector/cpu/data/nixl.py`), the NIXL p2p data layer of the multi-tiered offload path (`vllm/v1/kv_offload/tiering/p2p/data/nixl.py`), and all NIXL tests, design docs, examples and tools.
- PRs touching any path containing `kv_offload` get the `nixl` label. This covers the multi-tiered offloading path (`vllm/v1/kv_offload/`, KVCR tiering), the simple offload path (`vllm/v1/simple_kv_offload/`), their tests, and `docs/features/kv_offloading_usage.md`.
- PRs with "NIXL" in the title get the `nixl` label.
- Matching PRs are assigned to @ovidiusm and @iyastreb (the assignment is what notifies them).

## Validation

- `pre-commit run --files .github/mergify.yml` — all hooks pass, including `check-label-rules` (every `files=`/`files~=` condition matches at least one tracked file).
- Verified the two regexes against `git ls-files`: 155 tracked files match, all of them NIXL or KV-offloading related; negatives (e.g. `gpu_model_runner.py`, mooncake connector/tests, `offloading_connector.py`) correctly do not match; all paths covered by the original hardcoded list are still covered (strict superset).
- `gh label list --repo vllm-project/vllm` — confirms the `nixl` label exists.
- Duplicate checks: `gh pr list --repo vllm-project/vllm --state open --search "nixl label"` and `--search "auto-label"` — no open PR adds a nixl auto-label rule.
- No model evaluations: mergify/CI configuration only, no serving, output, or accuracy impact.

## Details

- The file conditions use `files~=(?i)nixl` and `files~=kv_offload` (per @hmellor's review suggestion) instead of a hardcoded directory list, matching the style of the existing `kimi`/`rust` rules. A path regex survives files moving between directories; the `check-label-rules` pre-commit hook exists precisely because hardcoded paths silently rot.
- Scope note: the `kv_offload` substring intentionally also covers `vllm/v1/simple_kv_offload/`, and `(?i)nixl` covers NIXL EP dispatch and EC-transfer NIXL files — all NIXL / KV-offloading work the team wants to be notified of.
- The rule follows the `label-mooncake` pattern exactly: label add + `assign` to the topic owners.
- This is not duplicating an existing PR: no open PR adds a nixl label rule (see duplicate checks above), and the existing `label-kv-connector` rule only adds the generic `kv-connector` label without assigning or notifying NIXL owners.
- AI assistance was used during the creation of this PR (Mistral Vibe). The diff is a small addition to `.github/mergify.yml`.
