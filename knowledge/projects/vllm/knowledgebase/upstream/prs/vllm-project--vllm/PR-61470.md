# [Model] Enable LoRA support for tower and connector in MiDashengLM

[Upstream PR](https://github.com/vllm-project/vllm/pull/61470) · state: open · merged: False

## Original PR description



## Overview

Enable LoRA on the Dasheng audio tower and `AudioProjectorSubsample` connector of MiDashengLM, built on the `get_mm_lora_token_counts` interface from #42662. Part of #31479; sibling audio-model PRs: #45697 (Voxtral), #45944 (Qwen2-Audio).

## Claims

- `MiDashengLMModel` now declares `SupportsLoRA` and `supports_tower_connector_lora`, with `get_mm_mapping` (`decoder` / `audio_encoder` / `audio_projector`). Adapters can target the Qwen2 decoder, the Dasheng tower (`qkv`, `proj`, `fc1`, `fc2`), and the projector (`net.0`, `net.2`); no encoder rewrite was needed since the tower already uses vLLM-native linears and the HF checkpoint's fused `qkv` maps to `QKVParallelLinearWithLoRA` without packing.
- With `--enable-tower-connector-lora`, every audio item is padded to a fixed 160000 samples, so the tower always runs 250 patches and the projector 50 rows per item for the 7B config, making the tower/connector punica token mappings exact under encoder batching.
- Covered by a processor-driven unit test (real `mispeech/midashenglm-7b` processor, awkward audio lengths whose patch counts are not multiples of the projector's subsample factor), plus end-to-end GPU validation with a tower+connector adapter on a variable-length multi-audio batch.

## Validation

**Caveat (pre-existing, unrelated to this PR):** base MiDashengLM on current main emits only the untrained token id 151872 (text-only prompts included, top-1 logprob 0.0 vs −619 for rank 2). Verified pre-existing by rerunning with the pristine nightly `midashenglm.py` (same output), with no LoRA flags at all (byte-identical output, which also confirms the pad path changes nothing for non-LoRA use), and with `Qwen/Qwen2.5-0.5B-Instruct` in the same environment (correct output, ruling out the env). Tracked in #61469; adapter-quality validation on this model is blocked on that fix, mapping/plumbing validation above is not.

```python
#!/usr/bin/env python3
"""Functional smoke-test for MiDashengLM tower/connector LoRA (A100).

Validates the plumbing the PR touches, not adapter quality: with
`enable_tower_connector_lora` every audio is padded to 160000 samples, so the
tower/connector punica mappings built from `get_mm_lora_token_counts` must
match the rows the Dasheng/projector linears actually receive. A
randomly-initialized small-magnitude adapter targeting tower (qkv/fc1/fc2),
connector (net.0/net.2), and LM (q/k/v_proj) modules is enough: if the counts
or the wrapping were wrong, generation would throw a punica shape/mapping
error or the adapter load would report unexpected modules.

The batch mixes audio lengths whose patch counts are not multiples of the
projector's subsample factor (9, 82, 194 patches) with a full-length audio
(250 patches) across single- and multi-audio prompts.
"""

import faulthandler
import json

faulthandler.dump_traceback_later(2400, exit=True)

import numpy as np
import torch
from safetensors.torch import save_file

import vllm
from vllm.lora.request import LoRARequest

MODEL = "mispeech/midashenglm-7b"
SR = 16000
ADAPTER_DIR = "/tmp/mdsl_lora_val/rand_adapter"

# (in_features, out_features) per targeted module, from the 7B config:
# tower embed_dim=1280, mlp_ratio=4, subsample_factor=5, text hidden 3584,
# 28 heads / 4 kv heads, head_dim 128.
_TOWER_BLOCKS = [0, 15, 31]
_SHAPES: dict[str, tuple[int, int]] = {
    "audio_projector.net.0": (6400, 3584),
    "audio_projector.net.2": (3584, 3584),
    "decoder.model.layers.0.self_attn.q_proj": (3584, 3584),
    "decoder.model.layers.0.self_attn.k_proj": (3584, 512),
    "decoder.model.layers.0.self_attn.v_proj": (3584, 512),
}
for _i in _TOWER_BLOCKS:
    _SHAPES[f"audio_encoder.blocks.{_i}.attn.qkv"] = (1280, 3840)
    _SHAPES[f"audio_encoder.blocks.{_i}.mlp.fc1"] = (1280, 5120)
    _SHAPES[f"audio_encoder.blocks.{_i}.mlp.fc2"] = (5120, 1280)


def make_random_lora(out_dir: str) -> str:
    """Write a PEFT-format adapter with small random A/B matrices directly
    (no HF model load needed on the shared box)."""
    import os

    os.makedirs(out_dir, exist_ok=True)
    rank = 8
    rng = np.random.RandomState(0)
    tensors = {}
    for name, (fan_in, fan_out) in _SHAPES.items():
        tensors[f"base_model.model.{name}.lora_A.weight"] = torch.from_numpy(
            (rng.standard_normal((rank, fan_in)) * 0.01).astype(np.float16)
        )
        tensors[f"base_model.model.{name}.lora_B.weight"] = torch.from_numpy(
            (rng.standard_normal((fan_out, rank)) * 0.01).astype(np.float16)
        )
    save_file(tensors, f"{out_dir}/adapter_model.safetensors")
    config = {
        "peft_type": "LORA",
        "base_model_name_or_path": MODEL,
        "r": rank,
        "lora_alpha": 16,
        "lora_dropout": 0.0,
        "bias": "none",
        "task_type": "CAUSAL_LM",
        "target_modules": [
            "qkv", "fc1", "fc2", "net.0", "net.2",
            "q_proj", "k_proj", "v_proj",
        ],
    }
    with open(f"{out_dir}/adapter_config.json", "w") as f:
        json.dump(config, f, indent=2)
    return out_dir


def _audio(seconds: float, rng: np.random.RandomState):
    return ((rng.rand(int(seconds * SR)).astype(np.float32) - 0.5) * 0.1, SR)


def main() -> None:
    lora_path = make_random_lora(ADAPTER_DIR)

    free, total = torch.cuda.mem_get_info()
    free_gib = free / 1024**3
    print(f"GPU free: {free_gib:.1f} GiB / total {total / 1024**3:.1f} GiB")
    if free_gib < 15.0:
        raise SystemExit(f"ABORT: only {free_gib:.1f} GiB free (<15 GiB)")
    # Leave ~1 GiB headroom for the resident prod workload. The fp32
    # checkpoint runs as bf16 (~15.4 GiB weights), so this is tight on a
    # busy box; keep batching budgets small.
    gpu_util = round((free - 1.0 * 1024**3) / total, 3)
    print(f"gpu_memory_utilization={gpu_util}")

    llm = vllm.LLM(
        model=MODEL,
        dtype="bfloat16",
        trust_remote_code=True,
        enable_lora=True,
        max_loras=1,
        max_lora_rank=8,
        enable_tower_connector_lora=True,
        mm_processor_cache_gb=0,
        max_model_len=2048,
        max_num_batched_tokens=2048,
        max_num_seqs=4,
        limit_mm_per_prompt={"audio": 2},
        gpu_memory_utilization=gpu_util,
        enforce_eager=True,
    )

    rng = np.random.RandomState(0)
    span = "<|audio_bos|><|AUDIO|><|audio_eos|>"
    inputs = [
        {
            "prompt": f"{span}What do you hear?",
            "multi_modal_data": {"audio": [_audio(0.37, rng)]},
        },
        {
            "prompt": f"{span}{span}Compare the two clips.",
            "multi_modal_data": {"audio": [_audio(3.3, rng), _audio(7.77, rng)]},
        },
        {
            "prompt": f"{span}Describe this.",
            "multi_modal_data": {"audio": [_audio(10.0, rng)]},
        },
    ]
    # ignore_eos: the base model may emit EOS immediately on raw (non-chat)
    # prompts; force 8 decode steps so the LoRA-mapped decode path runs too.
    sp = vllm.SamplingParams(
        temperature=0, max_tokens=8, min_tokens=8, ignore_eos=True
    )

    print("=== generate WITH tower/connector LoRA ===")
    out = llm.generate(
        inputs, sp, lora_request=LoRARequest("rand_tower_conn", 1, lora_path)
    )
    assert len(out) == len(inputs)
    for i, o in enumerate(out):
        text = o.outputs[0].text
        assert len(o.outputs[0].token_ids) == 8
        print(f"[lora {i}] {text!r}")

    print("=== generate WITHOUT LoRA (same engine, padded path) ===")
    out = llm.generate(inputs, sp)
    assert len(out) == len(inputs)
    for i, o in enumerate(out):
        print(f"[base {i}] {o.outputs[0].text!r}")

    print("\n=== SMOKE TEST PASSED ===")


if __name__ == "__main__":
    main()
```

## Details

- **Why fixed padding:** scheduled audio items are grouped and batched (`group_and_batch_mm_kwargs`) and `_parse_and_validate_audio_input` pads them to the batch max, so a per-item token count derived from the item's own length can never match the rows the tower linears actually process in a mixed-length batch. Padding every item to `_MAX_AUDIO_LENGTH` (the model's existing `get_max_audio_len`) mirrors Ultravox's `pad_audio_to_max_context` and is gated on `enable_tower_connector_lora` — zero impact when the flag is off.
- **Why this needed #42662:** the pre-#42662 hook (`get_num_mm_encoder_tokens(num_embeds)`) served runtime items and punica wrapper sizing through one formula. For MiDashengLM those must differ: runtime needs the per-item constant, while sizing needs a budget-scaled bound. The `mm_kwargs` parameter disambiguates the two calls.
- **Sizing bound:** placeholder counts are derived from each audio's true length (projector rows are `patches // 5`, floored), so unlike Voxtral's chunk-padded placeholders they cannot bound the number of items within the encoder budget — a batch of many short audios would overflow a full-item-scaled buffer. The sizing path therefore assumes worst-case one-embed items (`num_mm_embeds` items). Cost: tower punica index buffers sized at ~250x the encoder budget in int64 entries (tens of MB at default budgets), only when the flag is on. A follow-up could shrink this by passing the scheduler's max item count through the interface.
- **Limitation:** with the flag on, audio longer than 160000 samples (10s, the profiled max item) is rejected with a clear `ValueError`; without the flag, longer audio behaves as before. The rejection uses the standard `_parse_and_validate_audio_input` error path (like the Ultravox tower's over-long raise); rejecting at input-processing time instead would require LoRA-config visibility in `InputProcessingContext`, which could be a follow-up.
- **Not a duplicate:** as of 2026-10-13, `midashenglm.py` on main has no LoRA support, no open PR touches it for LoRA (searched `midashenglm lora`, `MiDashengLM`, PRs referencing #31479), and MiDashengLM is unclaimed on #31479.
