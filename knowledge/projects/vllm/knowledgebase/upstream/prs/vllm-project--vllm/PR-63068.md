# [Bugfix][Multimodal] Respect meta initialization for Engram offload

[Upstream PR](https://github.com/vllm-project/vllm/pull/63068) · state: closed · merged: True

## Original PR description



## Overview

Respect meta initialization when allocating DeepSeek-V4.1 Engram tables, preventing unnecessary host-memory allocation on encoder-only instances.

## Claims

- Skip pinned, huge-page and shared host storage during meta initialization.
- Preserve normal Engram CPU offload and suppress offload logs for meta tensors.

## Validation

Started two real-weight DeepSeek-V4.1-Flash encoder instances under Slurm using `vllm serve ... --mm-encoder-only --tensor-parallel-size 1` with Mooncake TCP. After startup, worker inspection confirmed both Engram tables remain meta with zero host-table bytes on each instance, avoiding approximately 188.8 GiB of unnecessary allocation per encoder.

## Details

Encoder-only language models are constructed under `torch.device("meta")`, but Engram explicitly allocates CPU storage. The retained language-model placeholder therefore holds two unnecessary tables, approximately 188.8 GiB per TP1 encoder instance for DeepSeek-V4.1-Flash.

Reuse the existing device-local allocation path before any host-storage allocation. No runner, scheduler or connector changes. Open-PR searches found no existing fix for this meta-initialization bypass.
