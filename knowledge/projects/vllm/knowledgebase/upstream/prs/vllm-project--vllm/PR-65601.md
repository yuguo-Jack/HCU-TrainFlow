# [KV Events] Expose chunk size in BlockStored events

[Upstream PR](https://github.com/vllm-project/vllm/pull/65601) · state: open · merged: False

## Original PR description



## Overview

Add an optional token-span `chunk_size` to `BlockStored` so consumers can distinguish an independently retrievable GPU block from one offloaded chunk containing multiple advertised block hashes. This is a small, independently reviewable step toward #52103.

## Claims

- Native GPU events report the valid span of their retrievable block.
- Self-describing offload events report the full retrievable chunk span; partial tails report their valid span. Placeholder events leave the field unset.
- `block_size`, `block_hashes`, and `BlockRemoved` retain their existing meaning and behavior.

## Validation

- On GPU Server: `python -m pytest -q tests/v1/kv_connector/unit/offloading_connector/test_events.py` — 60 passed.
- On GPU Server: `python -m pytest -q tests/v1/core/test_prefix_caching.py -k event` — 21 passed.
- `pre-commit run --files` on the changed files — passed.
- The human submitter confirmed line-by-line review and relevant test execution. No model evaluation is needed for this event-metadata-only change.

## Details

An offload `BlockStored` describes one retrievable chunk; its last block hash is the chunk key. Previously, `block_size` described each constituent block but did not tell consumers the span of the retrievable unit. This adds that span without collapsing the per-block hash list or repurposing `block_size`.

The field is optional so other event producers can leave it unspecified. Rich offload events populate it from the group chunk size (or the valid partial-tail span), and GPU events populate it from the emitted block span. Serialized placeholders omit it. The offload usage guide documents the contract, including that constituent offload hashes are not independently retrievable. Removal semantics are deliberately out of scope.
