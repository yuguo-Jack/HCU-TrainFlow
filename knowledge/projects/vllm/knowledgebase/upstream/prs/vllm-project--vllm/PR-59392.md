# [Bugfix][Attention] Fix FlashInfer MLA DCP decode on ragged spec-decode batches

[Upstream PR](https://github.com/vllm-project/vllm/pull/59392) · state: open · merged: False

## Original PR description

## Purpose

Fix https://github.com/vllm-project/vllm/issues/59065

With DCP > 1 and speculative decoding, FlashInfer MLA decode crashes when the decode batch is ragged, i.e. requests carry different numbers of query tokens. That happens whenever a request has fewer drafts than the others, and also during warmup. For example, Kimi-K3 with `-tp 2 -dcp 2` and DSpark fails at engine startup:

```
ValueError: causal_seqlens_kv_global must have shape (9,), got (2,)
```

Here a 1+7 request and a 1-token request make 9 decode tokens.

DCP cannot take the compact ragged path (`cum_seq_lens_q`), because it needs LSE. So ragged batches fall to the "uneven length" branch. That branch has two problems:

- **Shape mismatch.** It splits `q` into one row per token, but it keeps `block_table`, `seq_lens` and `causal_seqlens_kv_global` per request. FlashInfer then rejects the call.
- **Silent wrong reshape.** The branch is only taken when `num_decode_tokens % num_decodes != 0`. A ragged batch whose token count happens to divide evenly (e.g. 8 + 2 tokens) is instead `view`ed as a uniform 5 + 5 batch, and each request's rows attend to the wrong KV.

## Fix

A batch is now treated as ragged when `num_decode_tokens != num_decodes * max_query_len`. Ragged causal batches are split into single-token rows:

- `block_table` and `seq_lens` are expanded per row with the existing `_flattened_decode_metadata`.
- Each row's DCP bound is `T - (tokens of its request after it)`. FlashInfer defines `causal_seqlens_kv_global` as the global exclusive causal bound of each row's newest query token, and `dcp_tot_seq_lens` (`T`) already includes all of the request's query tokens.

The non-DCP causal path is unchanged; it already goes through `cum_seq_lens_q`.

## Not a duplicate

No open PR touches this branch. #56784 edits the same file, but only for backend selection.

## Test Plan

- Kernel check on GB200, run directly against `trtllm_batch_decode_with_kv_cache_mla` with the cute-dsl backend, `cp_world=2`, both ranks, and `(T, q_len)` in `{(301, 8), (97, 8), (130, 4), (64, 1)}`:
  - One request with `q_len` rows and bound `T` gives bit-identical output and LSE (max error `0.0`) to `q_len` single-token rows bounded at `T - (q_len - 1 - j)`.
  - Negative control: bounding every split row at `T` gives a max output error of `0.26`.
- `tests/v1/attention/test_flashinfer_mla_dcp.py`: `test_flashinfer_mla_forward_uses_native_dcp_api` is extended with a ragged `(3, 1)` batch. The new `ragged-causal` case fails without this change and passes with it.

