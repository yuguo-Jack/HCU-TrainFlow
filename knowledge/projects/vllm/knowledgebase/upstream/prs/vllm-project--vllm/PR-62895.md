# [Feature][Frontend] Add local output resume support to run-batch

[Upstream PR](https://github.com/vllm-project/vllm/pull/62895) · state: open · merged: False

## Original PR description



## Overview

Add `vllm run-batch --resume` for local output files. Completed successful requests are skipped; failed and missing requests run again and append results instead of truncating the output. Fixes #60184.

## Claims

- Match successful HTTP 200 responses without an error by `custom_id`.
- Preserve existing complete records and recover an incomplete final JSONL record.
- Reject duplicate input IDs and incompatible/corrupt output before model loading or output modification.
- Avoid loading a model when every input request already succeeded.

## Validation

- Before: the new end-to-end test completes its first inference run, then fails because `--resume` is unrecognized.

- Existing dispatcher/writer/validation coverage and new corrupt-record, partial-UTF8, URL, duplicate-ID, and skip-completed cases pass.

## Details

The output is scanned read-only first, recording successful IDs and the end of its last valid record. Input validation finishes before opening the output for append or trimming its partial tail. Normal runs retain their existing overwrite behavior and do not accumulate the resume ID sets.

Use the same input and model settings; ID matching cannot detect changed prompts or sampling parameters. Existing failed attempts remain in the output. New responses retain input order among pending requests. Resume requires a regular local output file and a single writer, and stores ID sets proportional to the input/output request count.

Duplicate-work checks on 2026-10-21 found no matching open PR. The issue author expressed interest, and a later comment discusses flushing out-of-order completions; this PR only resumes records already on disk and leaves cancellation/write-order behavior unchanged.
