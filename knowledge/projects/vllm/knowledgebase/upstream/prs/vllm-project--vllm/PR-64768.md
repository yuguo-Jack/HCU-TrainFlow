# [Bugfix][Rust Frontend] Fill files missing from a cached Hub snapshot instead of treating them as absent

[Upstream PR](https://github.com/vllm-project/vllm/pull/64768) · state: open · merged: False

## Original PR description



## Overview

When the Hugging Face cache already holds a snapshot of the model that has a tokenizer, the Rust frontend reads every model file from that snapshot and never contacts the Hub. A snapshot only holds the files that were downloaded into it, so one left by a tokenizer-only download (for example `transformers.AutoTokenizer.from_pretrained`) has no `generation_config.json`, and the frontend silently treats the file as absent. For Kimi-K2.5 that drops `<|im_end|>` (163586) from the stop set, because `config.json` only lists `[EOS]` (163585): generation does not stop at the end of the assistant turn, and nothing is logged.

Python's `huggingface_hub` fetches a file that is missing from the cache. This PR does the same for a cached snapshot, at the snapshot's commit, and records files the Hub does not have the way `huggingface_hub` does, so a complete cache still starts without any network traffic.

## Claims

- A cached snapshot that lacks a file the frontend reads (`config.json`, `generation_config.json`, `tokenizer_config.json`, the multimodal processor configs) fetches it from the Hub at the snapshot's commit, into the same snapshot. `refs/<branch>` is not rewritten.
- Files the Hub does not have at that commit are recorded as `<repo>/.no_exist/<commit>/<file>`, the `huggingface_hub` layout, so the next startup skips the lookup; markers written by Python are honored and vice versa.
- A complete snapshot, or one whose gaps are all recorded, makes no Hub request. Probing for a tokenizer format the model may not use (`tekken.json`, `tokenizer.json`, tiktoken) or scanning for a chat template never contacts the Hub.
- `HF_HUB_OFFLINE` skips the lookup. When the Hub cannot be reached, one listing request per source is attempted with a 10 s timeout (the default `HF_HUB_ETAG_TIMEOUT` of `huggingface_hub`), one warning names the model, commit, missing file and reason, the missing files are treated as absent, and nothing is recorded as absent.
- Local model directories (`--model /path`, including a path into the cache) are read exactly as before.
- `roundtrip_kimi_k25`, `roundtrip_mimo_v26` and `roundtrip_step5` pass on a cache that `tests/grammar_replay.py` populated first (see "How the gap is hit" below); on `main` they fail.

## Details

**How the gap is hit.** `SourceFiles::open` accepts a cached snapshot once it holds the file that source must provide (the tokenizer, or `config.json`), and from then on every file comes from that directory. Any tool that downloads only tokenizer files leaves such a snapshot: transformers' `AutoTokenizer`, token-counting in benchmark or gateway code, shared cache volumes touched by other jobs. vLLM's own `cargo test -p vllm-chat` does it too: `tests/grammar_replay.rs` runs `grammar_replay.py`, which loads every roundtrip model's tokenizer through transformers, and it sorts before `tests/roundtrip.rs`, so on a fresh machine three roundtrip tests fail (`kimi_k25`: `<|im_end|>` missing from the stop set; `mimo_v26`: the grammar replay snapshot no longer matches, and the failure message suggests `UPDATE_EXPECT=1`, which would bake the incomplete stop set into the repo; `step5`: `config.json` missing, `vocab_size` undefined). Checking the 25 models in my cache, 10 list EOS ids in `generation_config.json` that `config.json` lacks (Kimi-K2.5, MiMo-V2.6, Qwen3, MiniMax-M2.5/M3, gemma-4, Nemotron-3, gpt-oss, Muse-Spark/Glimmer); for Kimi-K2.5 the missing id is the turn-end token.

**Commits.**
1. Refactor, no behavior change: `SourceFiles::Snapshot` keeps the model id of a cached snapshot instead of folding it into `Dir`, and `probe` is split from `get`. `probe` is used where absence is an expected answer (which tokenizer format, whether the snapshot is usable, chat template discovery); `get` where a specific file is wanted.
2. The fix, in `get` for `Snapshot` only: local file → `.no_exist/<commit>/<file>` → `HF_HUB_OFFLINE` → list the repo at the snapshot's commit (once per source, `tokio::sync::OnceCell`, `tokio::time::timeout` since `hf-hub` 0.5 exposes no timeout) → download if listed, else write the marker. A listing failure is logged once and cached as "unreachable" for the rest of that startup, so four missing files cost one request; nothing is written to disk, because an unreachable Hub says nothing about whether the files exist.
3. Tests, with `axum` (already a workspace dependency) as the fake Hub, reusing the child-process pattern of `offline_resolution_uses_hub_cache_and_reports_cache_misses`.

**Why pin to the snapshot's commit.** `hf-hub` stores a download under the commit the server reports and rewrites `refs/<revision>`. Fetching at `main` could place the file in a different snapshot and repoint `refs/main` if the branch moved, mixing versions; at the commit, the file lands in the same snapshot. `huggingface_hub` does the same when the Hub is unreachable ("Using cached commit hash"). Side effect: `hf-hub` also writes `refs/<commit>`, a one-line file Python caches do not have; `cached_snapshot_dir` never reads it.

**Trade-off.** The one behavior change for existing deployments is an air-gapped host without `HF_HUB_OFFLINE` and with a snapshot that lacks a requested file not yet recorded in `.no_exist`: startup now waits once for the 10 s timeout and logs the warning, where it previously proceeded silently with the incomplete file set. Such hosts already pay far more on the Python side, and the warning says how to make the wait go away.

**Out of scope.**
- A missing dedicated chat template file is not fetched: the template name is discovered by scanning the directory, so there is no name to look up (transformers downloads it, so tokenizer-only snapshots have it).
- Local model directories keep their current behavior, including a path that points into the cache.
- `--skip-tokenizer-init` (#64697) changes which files `from_sources` asks for, not how `SourceFiles` finds them; this PR touches `SourceFiles` and rebases onto it without conflicts in the fix itself.

**Not a duplicate.** Searched open and closed PRs for Rust frontend `no_exist`, snapshot `generation_config`, and `model_files`; none address a partial cached snapshot.
