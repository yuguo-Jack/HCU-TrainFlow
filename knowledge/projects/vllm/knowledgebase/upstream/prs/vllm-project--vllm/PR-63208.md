# [Bugfix][PCP] Run the MTP draft prefill eagerly under prefill context parallel

[Upstream PR](https://github.com/vllm-project/vllm/pull/63208) · state: open · merged: False

## Original PR description

## Purpose

Engine start fails with prefill context parallel, MTP and prefill CUDA graphs together, for example:
- `--prefill-context-parallel-size 8 --speculative-config '{"method":"mtp",...}'`
- `--compilation-config '{"cudagraph_mode":"PIECEWISE",...}'`

The failure is in `capture()` of the speculator (`spec_decode/target_dependent_ar/speculator.py`), while it captures the draft model's prefill graphs:
- The capture runs `_prefill` on generic dummy inputs.
- Under PCP, the draft prefill instead reads the inputs that the PCP manager prepares (`prepare_draft_prefill` / `draft_prefill_batch`).
- For DSA models the sparse indexer then fails during capture:

```
File ".../vllm/model_executor/layers/sparse_attn_indexer.py", line 723, in sparse_attn_indexer
File ".../vllm/utils/deep_gemm.py", line 635, in mqa_logits_mx_inputs
torch.AcceleratorError: CUDA error: invalid argument
```

The fix skips the draft prefill capture when a PCP manager is present. Dispatch then finds no prefill graph for the draft and runs it eagerly, while the target model keeps its prefill graphs. Without PCP nothing changes.

## Test Plan

GLM-5.3 FP8 and NVFP4 on 8×B300 (SM103):
- `--prefill-context-parallel-size 8 --enable-expert-parallel`;
- MTP with 1 speculative token;
- `cudagraph_mode: PIECEWISE`, capture sizes 256–4096.

## Test Result

- **Before:** engine core initialization fails with the traceback above.
- **After:** the engine starts and serves. The log shows `PCP: draft prefill runs eagerly (no prefill CUDA graphs).`
- **Latency:** cold 2k / 4k / 16k / 64k prefills take 77 / 70 / 181 / 708 ms (NVFP4 checkpoint, DeepGEMM MegaMoE experts).
- **Accuracy:** I ran the same change on a v0.31.0 build with the FP8 checkpoint. GSM8K was 96.51% vs 96.59% without prefill graphs (McNemar p = 1.0), and a needle-in-a-haystack check passed 20/20.

`pre-commit` passes.
