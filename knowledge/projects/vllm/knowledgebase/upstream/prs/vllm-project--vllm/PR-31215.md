File: `vllm/v1/core/eviction_policy.py` · line None

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

The division operation in `compute_token_importance` is susceptible to a division-by-zero error if `torch.norm(key_tensor, ...)` evaluates to zero for any token. This would produce `inf` or `NaN` values in the importance scores, which could lead to unpredictable behavior, incorrect eviction decisions, or crashes in downstream computations. To ensure numerical stability, a small epsilon should be added to the denominator.

```suggestion
        return torch.norm(value_tensor, p=2, dim=-1) / (torch.norm(
            key_tensor, p=2, dim=-1
        ) + 1e-6)
```

File: `vllm/v1/core/eviction_policy.py` · line 388

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The current implementation of `on_block_freed` deletes the block's metadata. This action erases the block's access history (recency, frequency), causing it to be treated as a new, never-accessed block if it becomes an eviction candidate later. As a result, it will receive a score of 0.0, making it a prime target for eviction. This behavior undermines the core objective of the PagedEviction policy, which is to make intelligent eviction decisions based on historical usage. A frequently used block should be less likely to be evicted, even after being temporarily freed. 

To ensure the policy works as intended, consider preserving the metadata for freed blocks. The metadata dictionary's size is bounded by the total number of blocks, so this change would not introduce a memory leak.

```suggestion
    def on_block_freed(self, block: "KVCacheBlock") -> None:  # type: ignore
        """
        Update metadata when block is freed.
        """
        # By not deleting the metadata, we preserve the block's access history,
        # which is crucial for making informed eviction decisions when the block is
        # in the free pool.
        pass
```
