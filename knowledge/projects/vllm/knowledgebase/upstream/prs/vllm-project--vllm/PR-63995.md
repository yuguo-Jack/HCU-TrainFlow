# [Bugfix][Frontend] Fix chat echo crash on multimodal content lists (streaming and non-streaming)

[Upstream PR](https://github.com/vllm-project/vllm/pull/63995) · state: open · merged: False

## Original PR description

## Summary
- Non-streaming `echo=true` raised `KeyError: 'text'` and streaming `echo=true` failed `DeltaMessage` validation when the last message content was a multimodal content list (e.g. `[{"type":"text",...},{"type":"image_url",...}]`).
- Echo now flattens content to text in both paths: only `type: "text"` parts are echoed (joined with newlines); non-text parts (images, audio, files) are skipped because they cannot be represented in the text response.
- Extracts a shared `_get_echo_text` helper used by both the streaming and non-streaming generators.

Fixes #48338

## Why this is not duplicating an existing PR
- PR #48339 fixes only the streaming side and has unresolved merge conflicts since 2026-07-29; it does not cover the non-streaming `KeyError: 'text'` path reported here for the first time.
- This PR fixes both paths with a shared helper and adds regression tests for both.
