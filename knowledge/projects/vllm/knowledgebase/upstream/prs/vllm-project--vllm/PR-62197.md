# [Bugfix][ROCm] Fix DeepSeek-V4.1 decode on gfx11/gfx12 (missing inverse RoPE)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62197) · state: open · merged: False

## Original PR description

## Purpose

DeepSeek-V4.1 decodes garbage on ROCm GPUs other than gfx942/gfx950. Prefill is fine. Tested on gfx1151.

#57435 folded the inverse RoPE into the split-K sparse decode reduce, and `rocm_sparse_attn_decode` returns how many rows it already rotated so the caller can skip them. But only gfx942/gfx950 run that split-K reduce. Every other arch takes the fallback kernel, which never applies the inverse RoPE, yet the function still reports every row as rotated. Those rows never get rotated.

This PR fixes the return value at the source: rows count as rotated only when the split-K reduce folded the RoPE. Nothing changes on gfx942/gfx950.

#52970 and #58800 avoid the bug in DeepSeek-V4's model by not requesting the fused RoPE there. DeepSeek-V4.1 has no such check and is still broken on main. With the kernel fixed, this PR removes both checks.

## Duplicate-work check

Searched open PRs for `rocm_sparse_attn_decode` and `inv_rope_positions`. No duplicate. #52970 and #58800 (both merged) avoid the bug in DeepSeek-V4's model only; this PR replaces their checks. #60154 (merged) and #61967 change the gfx942/gfx950 decode paths, not this return value.
