# [Bugfix][ROCm] Fix DeepSeek-V4 decode on gfx11/gfx12 (missing inverse RoPE)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62197) · state: open · merged: False

## Original PR description

## Purpose

DeepSeek-V4 decodes garbage on ROCm GPUs other than gfx942/gfx950. Prefill is fine. Affects every arch on the fallback kernel (gfx11, gfx12, …). Tested on gfx1151 only.

#57435 folded the inverse RoPE into the split-K sparse decode reduce, and `rocm_sparse_attn_decode` now returns how many rows it already rotated so `forward_mqa` can skip them. But only gfx942/gfx950 run that split-K reduce. Every other arch takes the fallback kernel, which never applies the inverse RoPE, yet the function still reports every row as rotated. Those rows never get rotated.

This PR reports rotated rows only when the split-K reduce ran. Nothing changes on gfx942/gfx950.

Tests: a new arch-agnostic test checks that the fused path plus the caller's pass matches the unfused path.

## Duplicate-work check

Searched open PRs for `rocm_sparse_attn_decode` and `inv_rope_positions`. No duplicate. #60154 and #61967 change the gfx942/gfx950 decode paths, not this return value.
