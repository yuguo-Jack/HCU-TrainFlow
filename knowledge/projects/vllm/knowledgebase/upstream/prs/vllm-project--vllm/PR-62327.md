# [Bugfix] Reject requests that break sampling-mask preconditions with 400

[Upstream PR](https://github.com/vllm-project/vllm/pull/62327) · state: closed · merged: False

## Original PR description

## Purpose

With `--return-sampling-mask`, a request with `temperature <= 0` or `top_k <= 0` fails with HTTP 500 and an empty message (`{"message": "", "type": "InternalServerError"}`). The cause is that `InputProcessor._validate_params` raises a plain `ValueError` for these two checks. `AsyncLLM.generate` only re-raises `VLLMClientError`, so it wraps the `ValueError` in an empty `EngineGenerateError`. Clients see a 500 and get no reason. For example, chat requests that use the default `top_k=0` all fail this way.

Fix: raise `VLLMValidationError` (with `parameter`/`value`), the same as the other request checks in `_validate_params`. The client then gets a 400 that states the reason.

Related: #61322 changes the message text of the same checks but keeps `ValueError`, so those requests would still return 500.

## Test Plan

`pytest tests/v1/engine/test_input_processor_trace_replay.py`: the new parametrized test fails on main and passes with this change.

Reproduced on v0.31.0 with Qwen3-30B-A3B and `--return-sampling-mask`. A `/v1/chat/completions` or `/inference/v1/generate` request without `top_k` returned 500 with an empty message. With `top_k` set, the same requests returned 200.

AI assistance (Claude) was used; all changes were reviewed by the submitter.
