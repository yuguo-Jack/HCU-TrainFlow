# [CPU] Move CPU-backend-only op wrappers into vllm/_cpu_ops.py

[Upstream PR](https://github.com/vllm-project/vllm/pull/64863) · state: open · merged: False

## Original PR description



## Overview

Move the Python wrappers for CPU-backend-only custom ops out of `vllm/_custom_ops.py` into a new `vllm/_cpu_ops.py`. This is the follow-up agreed in #61995 ([review thread](https://github.com/vllm-project/vllm/pull/61995)).

## Claims

- `vllm/_custom_ops.py` goes from 5,220 to ~3,665 lines. The ~1,400 lines of CPU-only wrappers now live in `vllm/_cpu_ops.py`, like `vllm/_xpu_ops.py` and `vllm/_aiter_ops.py` already do for their platforms.
- No behaviour change. The moved code is unchanged apart from rewrapping one over-long docstring line, and is still registered and loaded the same way on CPU.

## Validation

- An AST-based inventory of `vllm/_custom_ops.py` on `main` classifies every top-level statement by the `torch.ops._C` ops it uses. Ops count as CPU-only when they're registered under `csrc/cpu/` and nowhere else under `csrc/`. No wrapper mixes CPU-only and other ops, and after this change none of the remaining statements use a CPU-only op.
- Comparing non-blank lines (whitespace-normalized) between `main:vllm/_custom_ops.py` and the new `_custom_ops.py` + `_cpu_ops.py` shows no lost code. The only additions are the new module header, the CPU import hook and the rewrapped docstring line.
- A scan of `vllm/`, `tests/`, `benchmarks/` and `examples/` finds no remaining reference to a moved name through `_custom_ops`, whether by attribute access, `from ... import`, `mock.patch` string or `monkeypatch.setattr(<module>.ops, "<name>")`.
- `pre-commit` (ruff, ruff-format, mypy) passes on all touched files.
- Relying on CI (CPU-Kernel Tests and the other CPU test steps) for runtime validation.

## Details

**What moved:**
- 61 wrapper functions whose ops are registered only by the CPU build (`csrc/cpu/torch_bindings.cpp`).
- `onednn_scaled_int8_quant`, which only CPU code uses.
- The 14 `register_fake` blocks for CPU-only ops.
- The `CPUActMethod`, `CPUQuantMethod` and `CPUQuantAlgo` enums and the `_supports_cpu_fp8_w8a16` / `_supports_onednn` flags.

**What stays in `_custom_ops.py`:** the wrappers for ops registered by *both* the CPU and CUDA/ROCm builds (`rms_norm`, `fused_add_rms_norm`, `rotary_embedding`, `scaled_fp8_quant`, `scaled_int8_quant`). One Python wrapper serves both backends there.

**Fake registration:** some CPU-only ops with fake impls are called directly through `torch.ops._C`, for example `dynamic_4bit_int_moe` in `cpu_int4_moe.py`. So `_custom_ops.py` imports `vllm._cpu_ops` when running on CPU, which keeps the existing guarantee that importing `_custom_ops` registers every fake op.

**Call sites:** callers now use `from vllm import _cpu_ops as cpu_ops` / `from vllm._cpu_ops import ...`. Files that also use shared ops keep their `_custom_ops` import. The few shared, non-CPU-specific files that reference CPU ops (`mla_attention.py`, `sparse_attn_indexer.py`, `layers/utils.py`, `int_wna16.py`) only do so inside their existing CPU branches.

**CI:** `vllm/_cpu_ops.py` is added to the `source_file_dependencies` of the CPU-Kernel Tests step.

**History:** the shared/GPU code keeps the original path, since it's ~75% of the file and most of its history. This PR is a pure move, so `git blame -C vllm/_cpu_ops.py` traces the moved lines back to their original commits.
