# [Bugfix][Frontend] Forward parser grammar reasoning hint through Responses render

[Upstream PR](https://github.com/vllm-project/vllm/pull/62185) · state: open · merged: False

## Original PR description



## Overview

Preserve parser-derived Responses grammar gating across render → generate, matching coupled Responses serving introduced in #62052 and the existing transport from #60062.

## Claims

- When a parser grammar covers reasoning from the message start, Responses render emits `reasoning_ended=true`, so the existing generate consumer can apply it immediately.
- Other requests retain `reasoning_ended=null`, preserving engine prompt-based reasoning resolution.

## Details

BeamParser stores a private `_grammar_from_parser` flag when its constraint includes reasoning framing. Coupled Responses converts it to the existing engine hint, but Responses render previously discarded it when building GenerateRequest. Forward the same expression at that serialization boundary; no new field or parser logic.
