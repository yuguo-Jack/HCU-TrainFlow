# [Frontend] Support Llama for structured decisions

[Upstream PR](https://github.com/vllm-project/vllm/pull/63589) · state: open · merged: False

## Original PR description



## Overview

Register `LlamaForCausalLM` with the existing `NextTokenStrategy` for `/v1/systemone` and `/v1/decisions`, and list `meta-llama/Llama-3.2-1B-Instruct` as a supported model. This follows the existing opt-in approach in [PR 62303](https://github.com/vllm-project/vllm/pull/62303).

```bash
vllm serve meta-llama/Llama-3.2-1B-Instruct
```

## Claims

- `LlamaForCausalLM` now selects `NextTokenStrategy` for `generate` requests with both the default and `processed_logprobs` read modes.
- The supported-model table includes `meta-llama/Llama-3.2-1B-Instruct`.
- A CPU test builds `NextTokenStrategy` with the Llama 3.2 1B Instruct tokenizer. Construction checks that all 38 labels (A–Z, yes/no, 0–9) are distinct single tokens at the reply boundary; the test also checks the assistant header ending.
- Open-PR searches found no matching Llama registration for `NextTokenStrategy` (see Details).

## Validation

**Focused CPU tests.**

```bash
.venv/bin/python -m pytest tests/entrypoints/generate/structured_decisions/test_strategies.py -k 'test_strategy_selection or test_labels_start_the_reply or test_llama_labels_start_the_reply' -q
```

Result: `3 passed, 79 deselected`.

**End to end (macOS CPU, FP32).** I ran all 13 cases in the existing `test_structured_decisions_e2e.py` suite with real weights, selecting the model and FP32 dtype through local fixture overrides while leaving the assertions unchanged. These runs used a 1024-token context and prefix caching. The fixture overrides are not part of this PR. The E2E column below reports these CPU runs; the AG News columns report separate L4 BF16 runs.

**AG News evaluation (L4, BF16).** Each model was evaluated on the first 200 rows of the AG News test split using the prompt `Which category best describes this news article?` and the criteria `World: news about world events`, `Sports: news about sports`, `Business: news about business`, and `Sci/Tech: news about science or technology`. The evaluation used the registration patch on vLLM base commit `a55937f255287bc638a839cc7a441fc7e9c55aae`. All 600 requests returned valid answers.

| Model | E2E suite (macOS CPU, FP32) | AG News accuracy | Mean `label_mass` | `argmax_is_label` |
|---|---:|---:|---:|---:|
| Qwen3 0.6B (this run) | 13/13 | 81.0% (162/200) | 0.564406 | 0.645 |
| Qwen3 0.6B ([PR 62303](https://github.com/vllm-project/vllm/pull/62303) reference) | — | 79.5% | 0.638 | 0.730 |
| Llama 3.2 1B Instruct | 12/13 | 71.0% (142/200) | 0.110379 | 0.010 |
| Llama 3.2 3B Instruct | 12/13 | 84.0% (168/200) | 0.994736 | 1.000 |

The failed Llama 3.2 1B E2E case asks whether the message mentions a card. The model answered `no` where the test expects `yes`, despite returning HTTP 200 with a valid response. Although this test fails, I do not consider it a blocker for enabling Llama support, given that the Llama 3.2 3B evaluation results are comparable to those of already-supported models. I would appreciate the maintainers' judgment on whether this failure is acceptable.

The close Qwen accuracy provides a sanity check for the evaluation procedure against an already-supported model and the PR reference. The differences in the diagnostic metrics are consistent with prompt variation. Since the PR's exact prompt is unavailable, we cannot attribute the differences to the prompt alone; this is contextual evidence rather than an exact reproduction.

The low mean `label_mass` for Llama 3.2 1B, alongside the much higher value for the same architecture's 3B checkpoint, suggests checkpoint- or prompt-dependent behavior rather than an architecture-wide failure. These results do not establish the cause.

`label_mass` and `argmax_is_label` describe whether the next-token read lands on the answer labels; they do not guarantee classification accuracy.

## Details

- **Why this registration.** This adds Llama to the existing opt-in architecture registry and reuses `NextTokenStrategy`; it does not enable a default strategy for all generation models.
- **Not a duplicate.** On 2026-10-26, searches of open PRs for `Llama systemone`, `Llama NextTokenStrategy`, and `Llama structured decisions` did not find another PR registering `LlamaForCausalLM` with `NextTokenStrategy`.
