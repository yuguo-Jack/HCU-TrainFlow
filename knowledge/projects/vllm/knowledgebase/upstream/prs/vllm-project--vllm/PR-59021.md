# [Kernel] Allow steering the unquantized linear backend independently

[Upstream PR](https://github.com/vllm-project/vllm/pull/59021) · state: open · merged: False

## Original PR description

## Purpose

`--linear-backend` is consumed by two selectors: the quantized kernel picker in `model_executor/kernels/linear`, and `dispatch_unquantized_gemm` for unquantized layers. Setting it to reach the second also redirects the first, which on a mixed NVFP4/FP8 checkpoint was a net loss in our measurements even though the unquantized layers themselves improved.

## Changes

Adds `--unquantized-linear-backend` / `KernelConfig.unquantized_linear_backend`, which overrides the backend for `UnquantizedLinearMethod` only. Defaults to `"auto"`, which applies `linear_backend` as before — no behavior change unless the new flag is set.

This is separate from (and complements) `linear_backend_per_quant`, which overrides backend selection for the *quantized* kernel picker keyed by quantization scheme. That mechanism doesn't reach `UnquantizedLinearMethod`, since unquantized layers don't go through `select_linear_kernel`/`QuantKey` scheme lookup.

## Test plan

- `python -c "import ast; ast.parse(open('vllm/config/kernel.py').read())"` and same for `vllm/engine/arg_utils.py`, `vllm/model_executor/layers/linear.py` — all parse cleanly.
- Default behavior verified unchanged: `unquantized_linear_backend` defaults to `"auto"`, in which case `UnquantizedLinearMethod` falls back to `linear_backend` exactly as before this change.
