# [ROCm] Fuse GDN decode (conv1d + delta rule + gated norm) into AITER's gluon kernel (Qwen3.8-27B)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61428) · state: open · merged: False

## Original PR description

## Overview

On ROCm, run decode-only batches of Gated-DeltaNet layers (Qwen3-Next, Qwen3.5-family) through AITER's fused
conv1d + delta-rule + gated-RMSNorm gluon kernel instead of three kernels. Requires the AITER kernel PR ([#6488](https://github.com/ROCm/aiter/pull/6488)) (`fused_gdn_decode_qkvz` with `qkvz_layout`, `query_start_loc`, `out`)

## Claims

- One launch per GDN layer per decode step instead of three (conv1d, recurrence, gated norm): 882 → 730 kernels/step
- Qwen3.8-27B BF16 TP1 on MI355X, 1024×1024, concurrency 64: **+2.6% output tok/s, −3.0% mean TPOT**; Per GDN layer at 64 tokens: 91 → 70–76 µs.
- GSM8K unchanged. Prefill, mixed and speculative batches, CUDA/XPU, quantized models: no behaviour change.

## Details

- `qwen_gdn_linear_attn.py`: on ROCm, `forward_hip` calls a new custom op `qwen_gdn_attention_core_fused_norm_rocm(qkvz, ba, normed_out)` that writes the gated-normed output straight into the `out_proj` input buffer. Decode-only batches (no prefill, no spec, fp32 recurrent state) run the fused kernel; everything else runs the existing `_forward_core_rocm` followed by the layer's norm, so prefill/mixed/spec behaviour is unchanged.
- Enablement follows the existing CUDA fused-decode gate (`_fused_gdn_decode_unsupported_reason`): an init-time
  `_aiter_fused_gdn_decode_unsupported_reason` requires a bf16 model with K = V = 128, 2 or 3 value heads per key
  head, conv width 4, SiLU gating, bf16 conv cache and bf16/fp32 recurrent state, plus an unquantized `out_proj` (the
  kernel emits the normed output, so the norm cannot be fused with an `out_proj` input quantization). Unsupported
  layers log once and keep the current path. No new environment variable: the kernel is used whenever AITER provides
  it (`rocm_aiter_ops.is_fused_gdn_decode_enabled` in `_aiter_ops.py`).
