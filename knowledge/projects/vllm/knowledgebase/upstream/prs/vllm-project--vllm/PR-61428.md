# [ROCm][Perf] Fuse GDN decode (conv1d + delta rule + gated norm) into AITER's gluon kernel (Qwen3.8-27B)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61428) · state: open · merged: False

## Original PR description

## Overview

On ROCm, run decode-only batches of Gated-DeltaNet layers (Qwen3-Next, Qwen3.5-family) through AITER's fused
conv1d + delta-rule + gated-RMSNorm gluon kernel instead of three kernels. 

Requires the `qkvz_layout`, `query_start_loc` and `out` arguments of `fused_gdn_decode_qkvz`, which were added by [ROCm/aiter#6488](https://github.com/ROCm/aiter/pull/6488) in AITER release v0.1.27. Without them, the layer keeps the unfused path. 

A bf16 recurrent state (`--mamba-ssm-cache-dtype bfloat16`) also needs [ROCm/aiter#6884](https://github.com/ROCm/aiter/pull/6884), which is now merged in AITER main.

With [ROCm/aiter#6488](https://github.com/ROCm/aiter/pull/6488) but not [ROCm/aiter#6884](https://github.com/ROCm/aiter/pull/6884), a bf16-state server fails on its first fused decode with AITER's `ValueError`.

## Claims

- One launch per GDN layer per decode step instead of three (conv1d, recurrence, gated norm): 882 → 730 kernels/step.
- Qwen3.8-27B BF16 TP1 on MI355X, 1024×1024, concurrency 16–64: **+2.2–3.1% total tok/s, −2.3–2.8% mean TPOT**, TTFT unchanged. Per GDN layer at 64 tokens: 91 → 73 µs.
- With a bf16 recurrent state the fused kernel moves half the state bytes: **+7.7% total tok/s, −8.0% mean TPOT** at c64 versus the fp32 state. GSM8K and GPQA Diamond unchanged from fp32 to bf16.
- GSM8K unchanged from main. Prefill, mixed and speculative batches, CUDA/XPU, quantized models: no behaviour change.

## Details

- `qwen_gdn_linear_attn.py`: on ROCm, `forward_hip` calls a new custom op `qwen_gdn_attention_core_fused_norm_rocm(qkvz, ba, normed_out)` that writes the gated-normed output straight into the `out_proj` input buffer. Decode-only batches (no prefill, no spec) run the fused kernel. Other batches run the unfused path in `_forward_core_rocm`, then the layer's gated norm over the real tokens, so prefill/mixed/spec behaviour is unchanged.
- Enablement follows the existing CUDA fused-decode gate (`_fused_gdn_decode_unsupported_reason`): an init-time
  `_aiter_fused_gdn_decode_unsupported_reason` requires a bf16 model with K = V = 128, 2 or 3 value heads per key
  head, conv width 4, SiLU conv and gate activations, a bf16 conv cache and a recurrent state in `FUSED_GDN_STATE_DTYPES` (fp32 or bf16, the same set the CUDA gate uses), plus an unquantized `out_proj` (the kernel emits the normed output, so the norm cannot be fused with an `out_proj` input quantization). Unsupported layers log once and keep the current path. No new environment variable: `rocm_aiter_ops.is_fused_gdn_decode_enabled` (`_aiter_ops.py`) turns the kernel on when `VLLM_ROCM_USE_AITER=1`, the GPU is gfx950 and the installed AITER's `fused_gdn_decode_qkvz` has [ROCm/aiter#6488](https://github.com/ROCm/aiter/pull/6488)'s arguments.
