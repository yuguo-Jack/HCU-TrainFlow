# [Frontend] Add BROWSER_BACKEND to select the gpt-oss demo browser backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/61288) · state: open · merged: False

## Original PR description

## Overview

`HarmonyBrowserTool` (the built-in demo browser behind `--tool-server demo`) always uses gpt-oss's `ExaBackend`. gpt-oss also ships `YouComBackend` and selects between the two with a `BROWSER_BACKEND` env var in its own MCP browser server. This reads the same variable in vLLM so the demo browser can use either backend. Default stays `exa`; existing deployments are unchanged.

Successor to #47213 (closed): same env var, but Exa remains the default and [You.com](https://you.com) is opt-in via `BROWSER_BACKEND=youcom` + `YDC_API_KEY`.

## Claims

- `BROWSER_BACKEND=youcom` + `YDC_API_KEY` selects `YouComBackend`; unset/`exa` keeps today's `ExaBackend` behavior.
- Unknown `BROWSER_BACKEND` values disable browsing with a warning instead of crashing.
- Missing API key for the selected backend disables browsing with a warning naming the missing variable (as before).

## Validation

- New unit tests in `tests/entrypoints/unit_tests/test_mcp_browser_tool.py` cover: default exa selection, youcom opt-in, missing key (both backends), unknown backend, missing `gpt_oss` install. `pytest tests/entrypoints/unit_tests/test_mcp_browser_tool.py` → 6 passed. Wired into the existing `entrypoints-unit-tests` Buildkite job via `tests/entrypoints/unit_tests`.
- End-to-end smoke against `gpt_oss` installed from `openai/gpt-oss@main`: `BROWSER_BACKEND=youcom YDC_API_KEY=<key> python -c 'from vllm.entrypoints.mcp.tool import HarmonyBrowserTool; ...'` constructs `YouComBackend`; the default path still constructs `ExaBackend`.
- `pre-commit run --files` on all changed files passes (ruff, mypy, test-tethering, SPDX).

## Details

- The env var name and values match gpt-oss's own demo server, so users switching between the two see consistent configuration.
- `YouComBackend` is constructed without `api_key`: released gpt-oss (0.0.9) has no `api_key` field on it (added post-release in openai/gpt-oss#250), and it reads `YDC_API_KEY` itself in both versions.
- Known limitation: PyPI `gpt-oss` 0.0.9 points `YouComBackend` at a legacy host that rejects current You.com API keys. openai/gpt-oss#330 (merged 2026-10-12) fixes the host; the `youcom` option needs a gpt-oss release containing it. The code here works with 0.0.9 and `main` alike — only the upstream host changes.
