# [Bugfix][Perf][ROCm] RDNA launch config for kernel_paged_attention_2d

[Upstream PR](https://github.com/vllm-project/vllm/pull/63735) · state: closed · merged: True

## Original PR description



## Overview

On RDNA (`on_gfx1x()`), launch `kernel_paged_attention_2d` with `num_stages=1` and 4 / 8 / 16 warps by tile size, for tiles of 32+ tokens or ≥ 4096 elements. This fixes the gfx1201 Pattern A decode failures of #62697 that remain after #63268, and speeds up decode on gfx1100 and gfx1201. No open PR changes this launch config; #45916 and #58156 (open) add split-KV decode for RDNA and leave it as is. #58156 edits the same launch call, so whichever lands second needs a small rebase.

## Claims

- gfx1201, KV cache < 2 GiB: the new test shape and the #62697 reproducer case `p1-d128-bs528-fp16` fail on main (NaN rows, GPU memory fault) and pass with this PR. Pattern B (the cache writer) is not addressed.
- Decode throughput, PR / main at batch 1 / 32, with GSM8K unchanged:

| model | gfx1100 | gfx1201 |
|---|---|---|
| gemma-3-1b-it | 1.51× / 1.57× | 1.94× / 1.81× |
| Qwen3.5-9B | 1.15× / 1.10× | 1.07–1.09× / 1.14–1.16×* |
| Qwen3-4B `--block-size 32` | 1.30× / 1.50× | 1.12× / 1.05× |

`LLM(..., attention_backend="ROCM_ATTN")` (the RDNA default), CUDA graphs, 1024-token random prompts, 256 output tokens; GSM8K 5-shot, 1319 questions, greedy. Ratio: median of 4 adjacent main/PR run pairs (2 GPUs × 2); on gfx1100 every pair is within 2% of it.

\* gfx1201 runs fall into one of two throughput levels for both variants; these ratios compare runs at the same level, one per level.

## Validation

W7900 (gfx1100) and R9700 (gfx1201), ROCm 10.0, Triton 3.8.0:

- `test_prefix_prefill.py --optional`: no failures with this PR. On gfx1201 main, 4 nodes fail: the new shape, plus three `test_contexted_kv_attention_f32` nodes that hang.
- Of 41 kernel cases from an earlier failure sweep, 35 fail on main; none fail with this PR.
- `VLLM_GPU_SYNC_CHECK=error` and pre-commit pass.

## Details

- Trigger: Triton uses AMD buffer ops for tensors ≤ 2 GiB. Turning them off, a KV cache > 2 GiB, or `num_stages=1` each remove the failures. The Triton/LLVM root cause is unknown, so this is an empirical workaround. gfx1100 never failed.
- A few shapes get slower, down to 0.83×. Other RDNA parts were not measured.
- Only `ROCM_ATTN` calls this kernel; the opt-in `ROCM_SEGMENTED_ATTN` (#59132) uses its own kernel and is unchanged.
- No `LLM`-level test: the models we ran on main (Qwen3.5-9B, Qwen3-1.7B / Qwen3-4B `--block-size 32`, with KV caches down to 0.52 GiB) did not hit the failing shapes, so the regression test is at kernel level.
- CI has no RDNA runner, so the new test only catches regressions on gfx12.
