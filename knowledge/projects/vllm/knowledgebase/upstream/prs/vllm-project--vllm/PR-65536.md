# [Bugfix][Quantization] Normalize Quark exclude entries with parameter suffixes (#65034)

[Upstream PR](https://github.com/vllm-project/vllm/pull/65536) · state: open · merged: False

## Original PR description

### Problem Summary
Fixes #65034.

In Quark-quantized checkpoints (e.g. MXFP4 checkpoints with MTP speculative decoding or multimodal vision towers), excluded layers are frequently exported by checkpoint parameter/tensor names (such as `mtp.fc.weight`, `mtp.layers.0.self_attn.q_proj.weight`, or `model.layers.0.mlp.down_proj.weight`) rather than module prefixes.

In `QuarkConfig.get_quant_method_target()` and `should_ignore_layer()`, matching is performed against module prefixes (e.g. `mtp.fc` and `mtp.layers.0.self_attn.qkv_proj`), while fused layers are expanded against un-fused shard module names (`q_proj`, `k_proj`, `v_proj`). Because `mtp.fc` != `mtp.fc.weight`, `should_ignore_layer()` returns `False`.

Consequently:
1. Layers that are kept unquantized in the checkpoint (e.g. BF16 MTP draft layers or visual encoders) are incorrectly treated as quantized.
2. The model allocates quantized/packed parameter buffers (e.g. MXFP4 packed layout with last dimension halved).
3. Checkpoint weight loading fails ~40s into startup with:
   ```text
   AssertionError: assert self.data.shape == loaded_weight.shape
   ```

### Solution
1. In `vllm/model_executor/layers/quantization/quark/utils.py`, update `should_ignore_layer()`:
   - Normalize target strings by stripping `.weight` and `.bias` suffixes so that module-level and fused-shard matching works seamlessly regardless of whether the checkpoint exported module names or parameter names.
   - Preserve regex patterns prefixed with `re:`.
   - Guard against `None` or empty `ignore` lists (`if layer_name is None or not ignore: return False`).
2. In `vllm/model_executor/layers/quantization/quark/quark.py`, ensure `exclude_layers` defaults defensively to an empty list rather than `None`.

### Testing
- Added regression unit test `test_quant_method_dispatch_ignored_weight_and_bias_suffixes` in `tests/quantization/test_quark.py`:
  - Verified `mtp.fc.weight` resolves `mtp.fc` to `UnquantizedLinearMethod`.
  - Verified weight and bias suffixes on individual linear layers (`model.layers.0.mlp.down_proj.weight`, `model.layers.1.mlp.gate_proj.bias`).
  - Verified sharded fused layers (`qkv_proj` with `q_proj.weight`, `k_proj.weight`, `v_proj.weight`).
  - Verified regex patterns with `.weight` (e.g. `re:.*mtp\\.fc.*` and `re:.*mtp\\.fc\\.weight$`) are not mutated.
- Ran CPU unit tests:
  ```bash
  VLLM_TARGET_DEVICE=cpu pytest tests/quantization/test_quark.py -k "test_quant_method_dispatch_ignored"
  # 2 passed in 1.30s
  ```
- Validated clean `ruff check` and `ruff format` on all modified files.
