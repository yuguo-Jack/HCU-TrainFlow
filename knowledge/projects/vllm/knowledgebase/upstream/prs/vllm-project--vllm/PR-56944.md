# [ROCm][Perf] Shard DSA prefill indexer rows across TP ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/56944) · state: open · merged: False

## Original PR description

## Overview

Shard ROCm DSA prefill indexer query rows across tensor-parallel ranks, then reconstruct Top-K indices with one AllReduce(MAX). Mirrored early/late stripes distribute causal work without a stripe-size setting.

> Review head `213f069be994b20059356b7b85024c5e7f66b776` on upstream main `0f112d180033f3757cf283723f5593a40b02ed82` (AITER pin `v0.1.24.post1`). Existing review history is retained through a merge update. The historical GPU/model reports below were measured on their stated commits, **not this updated head**. GPU/model revalidation remains pending.

## Claims

- Use the cached `rocm_aiter_ops.is_cp_indexer_enabled()` predicate on the execution path. `VLLM_ROCM_USE_AITER_CP_INDEXER` remains opt-in, default off; the stripe-size env var is removed.
- Split each chunk into early/late halves and assign mirrored stripes, with round-robin remainders. A batch that needs a collective assigns **every** prefill row to exactly one rank, including short tail chunks. A batch with no chunk reaching TP-size stays replicated and issues no collective.
- Enlarge the chunk budget only for the uncompressed FP8 path that can shard. Compressed/candidate, FP4, and PCP/DCP paths retain their original bounds. CPU and paged MXFP4 chunker overrides accept the new argument without increasing their budget.
- Add real multi-GPU correctness tests plus CPU partition/budget tests. The TP2 cases are wired into the AMD distributed CI job; TP8 cases require eight GPUs.

## Validation

### This review update

It executes the exact extracted partition/chunker definitions and the committed CPU tests, checks the Top-K comparator, and exercises the actual operator body with CPU substitutes for scoring, Top-K, and the collective. This is **not** a full vLLM import, GPU-kernel, RCCL, or serving test.
- The same control-flow reproduction against the previous mirrored implementation fails four mixed-chunk cases (TP2/TP8, a large chunk plus tiny head/tail chunks). The updated implementation passes: tied rank-local sets cannot be merged into duplicate keys because each reduced row has one writer.

Includes TP2/TP8, ragged halves, mixed short/large chunks, narrow causal windows, unique valid Top-K keys, ownership, and skipping the collective for fully replicated batches. **Not run here: no ROCm GPU in this environment.**
- Previously reported operator run: 14 passed on 8x MI355X for the earlier interleaved implementation (2026-09-18); this does not validate the new mirrored/updated head.
- **Passed** `pre-commit run --files $(git diff --name-only 0f112d180033f3757cf283723f5593a40b02ed82 HEAD)`, including Ruff, Python 3.10 mypy, and Buildkite test tethering. Python syntax compilation and `git diff --check` also passed.
- Model/GPU tests, a matched A/B against #46103, and quantitative compute/memory-bandwidth roofline analysis remain pending on this head. No kernel-efficiency or merge-readiness claim is made.

### Reported GPU/model evidence

The October 2 report compares baseline `36229e1337` with mirrored implementation `78506b4278`, before this latest-main adaptation and the mixed-tail/budget fixes. On GLM-5.2-MXFP4, TP8, 8x MI355X, it reports +4.02–9.47% output throughput at ISL 50k; the full sweep and commands are retained below. These are supplied measurements, not newly executed results.

## Notes

1. **`VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS` must be unset.** With it set the server does not start — weight loading fails with `KeyError: 'layers.10.mlp.shared_experts.down_proj.weight'`. This is not caused by the CP indexer: it breaks the same way on upstream main. Both configurations therefore run with fusion off.
2. **Each number comes from a single run.** Running the same configuration twice gives results that differ by about 0.5%, just from run-to-run variation. The ISL 50k gains (3.6–8.7%) are far larger than that, so they are real. The ISL 8k differences are smaller than 0.5–1%, so they cannot be told apart from noise — that is why ISL 8k is called neutral rather than a small win.
3. Prefix caching disabled throughout, `--ignore-eos` so every request emits exactly 1024 tokens.
