# [ROCm][Perf] Shard DSA prefill indexer rows across TP ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/56944) · state: open · merged: False

## Original PR description

## Overview

Distribute ROCm DSA prefill indexer query rows across TP ranks and reconstruct Top-K indices with one AllReduce(MAX). Mirrored early/late stripes balance causal work without a stripe-size setting.

> Review head `2857a1e6d83e1f82cbaa2dfc8a34454c9c9ad59c` on upstream main `cd1effa2e7d204b22527f14739734751f38ed737` (AITER pin `v0.1.27`). Existing inline-review history is retained through a merge update. Supplied GPU/model results below retain their original measurement commits; they were not rerun on this integration head.

## Changes

- Use one `use_cp_indexer(max_prefill_seq_len, tp_world_size, chunks, candidate_blocks)` decision: gfx950, AITER MLA enabled, longest prefill sequence at least 16,384 tokens, TP > 1, no candidate blocks, and at least one chunk with a row per rank. The builder calls it before chunking to size its logits budget; the operator supplies the actual chunks.
- Run CP and replicated prefill through the same row-range loop. Every reduced row has one writer, including tiny tails; candidate-block batches remain replicated and decode rows stay outside the collective.
- Use `cp_indexer_enabled` consistently for the operator flag. Remove the feature-specific optimization-docs section as requested in review. No feature-specific enable environment variable is added.
- Reduce the GPU matrix to two shapes at TP2/TP4 and retain only the activation, row-ownership, and logits-budget CPU contracts. The AMD CI step has two MI355 GPUs, so it runs the two TP2 cases and skips TP4; no eight-GPU job is required.
