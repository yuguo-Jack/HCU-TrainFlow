# [Bugfix][KVConnector] Fix Mooncake save offset stalls with evicted SWA blocks

[Upstream PR](https://github.com/vllm-project/vllm/pull/64945) · state: open · merged: False

## Original PR description



## Overview

Fix Mooncake Store decode-save offset stalls when SWA blocks have been evicted locally but their keys already exist remotely.

## Claims

- Count remotely existing keys as saved, even when their local sources are unavailable.
- Keep the checkpoint incomplete when a key is missing remotely and has no usable local source.
- Exclude unavailable sources from value preparation and PUT.

## Validation

The new regression fails before the fix (`assert 1 == 2`: the evicted block's key was excluded from the existence query) and passes afterward. Four existing parametrized cases retain coverage for remotely missing keys with unavailable sources.

```bash
python -m pytest tests/v1/kv_connector/unit/test_mooncake_store_worker.py -q
```

**A/B:** 
DeepSeek-V4.1-Flash-1017, 8 H20 GPUs, TP=8, Mooncake Store `kv_both`, decode saves enabled, eager MRV2, block size 64. A 513-token seed prompt generates one token, followed by a 514-token prompt generating 768 tokens.

|---|---|---|
| Generated tokens | 768 | 768 |
| Decode-save checkpoint | Blocked by evicted local sources despite existing remote keys | Completed using remote existence checks |
| Saved offset across all 8 ranks | Remained at 0 | Advanced on every rank |

Counts cover parseable shared-stdout records; some lines interleaved. A separate cleanup-equivalence A/B using per-process JSONL confirmed 104/104 completed decode saves and final offset 1280 on every rank in both arms.

Real-model validation was performed locally. Full pre-commit setup timed out installing an unrelated hook; relevant hooks passed separately.

## Details

Previously, the sender skipped NULL/out-of-range sources before `batch_is_exist()` and unconditionally marked the checkpoint incomplete. SWA eviction therefore blocked offset advancement even for already-persisted keys.

The sender now builds all relevant keys, checks remote existence, and filters PUTs by local source availability.

| Remote key | Local source | Result |
|---|---|---|
| Exists | Any | Satisfied; no PUT |
| Missing | Available | PUT; require success |
| Missing | Unavailable | Do not advance offset |

This is a small connector-local change with no new synchronization. It adds existence checks for relevant keys previously skipped.

Duplicate check on 2026-11-01 found no equivalent fix. Related PRs #63511, #55097, and #62400 address async-MTP save frontiers, direct P/D alignment, and lookup boundaries respectively.
