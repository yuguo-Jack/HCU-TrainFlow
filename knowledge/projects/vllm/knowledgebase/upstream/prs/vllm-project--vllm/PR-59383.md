# [Bugfix][KV Offload] Return lazily offloaded GPU blocks to the eviction end

[Upstream PR](https://github.com/vllm-project/vllm/pull/59383) · state: open · merged: False

## Original PR description

## Purpose

In lazy mode, SimpleCPUOffloadScheduler offloads the cached blocks at the eviction end of the GPU free queue, then releases them with free_blocks, which appends cached blocks as most recently used. The blocks the CPU now holds outlive fresher blocks it doesn't hold, so the allocator evicts those instead. The scan keeps offloading new blocks, and the CPU cache turns over faster than it can serve hits.

* Adds evict_first to BlockPool.free_blocks (off by default) to free cached blocks to the front of the queue.
* Lazy store completion uses it, eager mode and abandoned stores are unchanged.
* Adds test_lazy_store_returns_blocks_to_eviction_end, which fails without the fix.

## Test Plan

Regression test fails on `main`

```bash
pytest tests/v1/simple_kv_offload/test_scheduler.py -k test_lazy_store_returns_blocks_to_eviction_end
```

The bug only affects throughput when the lazy CPU tier is smaller than the GPU KV cache, and the GPU free queue is
much longer than one lazy scan (for example `2 × max_num_batched_tokens` tokens). 

With a small GPU cache, each scan covers the whole free queue, so block order doesn't matter: in a run with a 1,024-block GPU cache on one L4, `main` and this branch served the same CPU hits.
