# [Security] Reject media reference scripts before decoding

[Upstream PR](https://github.com/vllm-project/vllm/pull/63701) · state: open · merged: False

## Original PR description

## Overview

Reject media reference scripts before decoding uploaded audio or video. These descriptors can open additional local files or sockets instead of decoding only the submitted media bytes.

## Claims

- Reject concat scripts, HLS playlists, SDP descriptions, and XML manifests with a request-scoped `ValueError`.
- Cover video media ingestion and direct decoder dispatch, plus audio dispatch and the PyAV/TorchCodec entry points, including local-file inputs.
- Keep decoding of self-contained uploaded media unchanged.

## Validation

- 43 selected pytest cases passed, covering descriptor encodings, bytes/buffer/file inputs, direct loaders, synchronous/asynchronous connectors, HTTP/data/file ingress, binary metadata, and existing video kwargs/budget behavior.
- Before/after reproduction with generated media: without the guard, both video and PyAV audio concat scripts returned local media; with the guard, both were rejected. Normal uploads produced identical decoded arrays before and after.
- All pre-commit checks applicable to the ten changed files passed.
- The full `pre-commit run --all-files` reported unrelated XPU lock regeneration and a macOS `/var` versus `/private/var` mismatch in the non-root entrypoint test.
- The submitting maintainer confirmed line-by-line review, relevant tests, and renderer validation in a working vLLM environment. The new real-server regression is included in the existing GPU multimodal CI suite; it could not start on this Mac (see limitation below). No model-accuracy evaluation was run; the decoder parity reproduction checks unchanged accepted media.

Reproduce the selected tests from the fix checkout:

```bash
VLLM_TARGET_DEVICE=cpu VLLM_PLUGINS='' .venv/bin/python -m pytest \
  tests/multimodal/media/test_base.py \
  tests/multimodal/media/test_video.py \
  tests/multimodal/media/test_audio.py \
  tests/multimodal/media/test_connector.py \
  -k 'reference_script or reference_description or binary_media_metadata or video_media_io_kwargs or video_request_budget_counts_torch_frames' \
  -q -p no:cacheprovider
```

Additional coverage: `test_video_reference_script_returns_bad_request` uses the existing `RemoteOpenAIServer` fixture and a generated video under the server working directory; it asserts a clean HTTP 400. The existing `entrypoints-integration-multimodal` Buildkite step selects the file. Local execution stopped in server setup with `FileNotFoundError: vllm`; the HTTP test has not passed on this Mac. The media format restriction is documented in `docs/features/multimodal_inputs.md`.

Baseline regression evidence (base commit `4b1c04e76f`, loading its actual audio module into the test process):

```bash
VLLM_TARGET_DEVICE=cpu VLLM_PLUGINS='' .venv/bin/python - <<'PYTEST'
import subprocess
import pytest
import vllm.multimodal.media.audio as audio
source = subprocess.check_output(
    ['git', 'show', '4b1c04e76f:vllm/multimodal/media/audio.py'], text=True)
exec(compile(source, 'vllm/multimodal/media/audio.py', 'exec'), audio.__dict__)
raise SystemExit(pytest.main([
    'tests/multimodal/media/test_audio.py::test_audio_reference_script_rejected[buffer-load_audio_pyav]',
    '-q', '-p', 'no:cacheprovider']))
PYTEST
```

Expected baseline result: `Failed: DID NOT RAISE ValueError`. With the patched module, this case passes as part of the 43-case run above.

## Details

Native format probing can interpret uploaded bytes as a resource descriptor. The shared validator rejects those descriptions before decoder construction. It examines the textual prefix before the first NUL so binary container metadata containing descriptor-like strings is unaffected. File validation preserves the caller's buffer position and uses no process-global decoder settings.

The Python chat, Responses, render, batch, SageMaker, decisions, speech-upload, and model-side soundtrack paths converge on the guarded media loaders. Direct video-loader calls also pass the shared decoder guard. The Rust frontend uses a separate external decoder implementation and is outside this Python-path patch.

Duplicate-work check: searched open, draft, and merged media PRs by file, sink, and reference-format keywords; read 25 candidate diffs. Stream-lifetime #62505, process isolation #60612, deferred decoding #57752, size limits #46836, and base64 validation #54323 do not reject reference scripts. No existing PR was found supplying this control on the affected Python paths.

AI assistance was used to develop this patch. The submitting maintainer confirmed review and validation before publication.
