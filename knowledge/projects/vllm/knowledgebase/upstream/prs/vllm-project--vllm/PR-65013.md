# [Perf][DSv4.1] Skip Q computation in replay KV prewrite

[Upstream PR](https://github.com/vllm-project/vllm/pull/65013) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

DeepSeek V4.1's final KV-source layer prewrite computes Q+KV and discards Q before replaying the trailing window. Use a standalone WKV projection and KV-only normalization for this prewrite, avoiding unused Q and indexer-weight work while retaining full Q+KV for normal attention and replay.

This targets the target-model replay prewrite: [#62817](https://github.com/vllm-project/vllm/pull/62817) changes replay row selection, [#64609](https://github.com/vllm-project/vllm/pull/64609) fuses norm/cache insertion, and [#55654](https://github.com/vllm-project/vllm/pull/55654), [#60076](https://github.com/vllm-project/vllm/pull/60076) and [#57627](https://github.com/vllm-project/vllm/pull/57627) concern DSpark draft context KV. The reviewed changes do not provide this standalone target-model prewrite projection. The norm files overlap with #64609 and will need reconciliation if it lands first.

## Claims

- Reduce projection-plus-normalization latency by removing computation whose output is discarded: **2.00x at 4096 rows and 2.16x at 8192 rows** in the measured B300 configuration.
- Add KV-only normalization entry points, sharing a 512-column CUDA specialization and retaining generic fallbacks.
- Preserve the fused projection fallback for LoRA and unsupported quantizers; register compile-only warmup and standalone WKV autotuning.

These are local operator-path gains. **No stable end-to-end model speedup is claimed.**

## Validation

Baseline: `8530a778f78dc7cd9a31e108ebc035c4b27ceb3c`; candidate: `d6eef285ecd1f8b58215c00a672b9d1b23bdd1fb`. B300, real DeepSeek V4.1 Flash checkpoint, BF16 activations, MXFP8 linear weights; H=5120, Q=1280, KV=512. Projection microbenchmarks use one GPU, CUPTI, CUDA graph replay, cold L2, both arms autotuned, and five alternating trials of 50 samples per arm.

| Rows | Q+KV projection + norm | WKV + KV norm | Speedup |
|---:|---:|---:|---:|
| 128 | 13.33 us | 11.58 us | 1.15x |
| 4096 | 56.07 us | 27.97 us | 2.00x |
| 8192 | 98.69 us | 45.63 us | 2.16x |
| 131072 | 1449.18 us | 580.52 us | 2.50x |

The two paths produce identical normalized KV for all ten tested projection sizes through 131072 rows. This measures projection plus normalization, excluding compressor, collectives and cache insertion. The model processes 128K prompts in 8K chunks; the last table row is a standalone operator stress case.

**Model validation:** TP2 on two B300 GPUs, 131072-token maximum input, chunk size 8192, prefix caching disabled, async scheduling disabled and OMP threads=8.

- 70 real-activation KV probe records: normalized KV maximum absolute and relative RMS error both zero.
- Graph A/B: generated tokens match through the first EOS in 24/24 numerical samples.
- Retrieval: 15/15 correct on each arm, with identical outputs, across 4K/16K/32K/64K/128K at three needle depths.

**End-to-end limits:** at 128K, same-process no-graph AB/BA improves by 0.10% (12 pairs; 0.34 percentage-point standard deviation), while graph A/B is 1.70% slower (3464.13 -> 3522.86 ms; nine samples per arm). Control cases also slow down, so attribution is unresolved; these measurements do not establish model acceleration or rule out a model-level regression.

**Checks:** full pre-commit, including mypy and CI test-tethering, passes. The GPU suites report **124 passed, 24 failed**, with all 24 fixture failures reproduced on baseline (`params_dtype` missing). Ten additional 131072-row norm cases and the new norm's isolated strict-JIT regression pass. Whole-model strict JIT fails on both arms at the existing top-20-logprob kernel's runtime compilation.

## Details

The layer is selected by `max(kv_source_layer_ids)` (zero-based L20 for the tested checkpoint). Full-row KV prewrite includes the trailing window; the subsequent window replay computes the Q needed for attention. Replay row selection and scheduling are unchanged.

The extra WKV weight/scale copy uses existing checkpoint loaders and GEMM implementations. Startup autotuning covers the standalone projection even on a tuning-cache hit. Tradeoffs are additional weight storage and startup work. Runtime validation covers CUDA TP2; AMD/Intel and other parallelism configurations remain untested.

AI assistance was used for implementation, review and validation. Human review and test confirmation remain required before submission.
