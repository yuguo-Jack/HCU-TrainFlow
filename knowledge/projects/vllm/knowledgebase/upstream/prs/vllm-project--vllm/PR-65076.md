# [KVConnector][Mooncake] Add per-GPU device names for MooncakeStoreConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/65076) · state: closed · merged: True

## Original PR description



## Overview

Adds an opt-in `device_name_per_gpu` key to the Mooncake Store config: RDMA device names indexed by physical GPU ID, of which each rank's store client gets only its own GPU's entry. `device_name` keeps the all-HCAs behaviour from #43799. Companion to kvcache-ai/Mooncake#5151.

## Claims

- `setup_mooncake_store` passes the current GPU's entry when the key is set, else `device_name` as before. This covers MooncakeStoreConnector and the Mooncake EC connector's embedding store, both built in GPU workers.
- The two keys are mutually exclusive. An empty list, a blank entry or a GPU with no entry raises `ValueError`. Sleep mode accepts either key.
- An entry may list several devices, so a B300 host can give each GPU its two HCAs.

## Validation

- `whx/mooncake-store-per-gpu-nic @ b74843e87`: `test_mooncake_store_worker.py` 254 passed, including the new selection and invalid-config tests; 1 setup error because I ran without `tests/conftest.py` (the `caplog_vllm` fixture). pre-commit clean.
- Not from this branch: Kimi-K3 1P1D on 2 nodes of 8x MI355X with an equivalent runtime patch (each rank limited to `rdma<physical GPU>`). The prefill Store registered 209 GiB per rank and the benchmark passed. Without it, every rank tried all 8 NICs and Store init failed (details below).

## Details

Why not all NICs: when a rank's NICs span NUMA nodes, Mooncake maps the global segment with 4KB pages, and on MI355X `ibv_reg_mr` failed with EINVAL within each rank's first 2 GiB. kvcache-ai/Mooncake#5151 fixes the allocation; whether 8 ranks then fit on every NIC is untested, and one NIC per GPU is the setup measured here.

#42689 picked one CSV entry by GPU index, which #43799 removed for B300 (8 GPUs, 16 HCAs). An explicit list keeps that case expressible and changes no default. AI-assisted (Claude in Cursor).
