# [Bugfix][Reasoning] Olmo3: end reasoning only at the latest think marker

[Upstream PR](https://github.com/vllm-project/vllm/pull/60669) · state: open · merged: False

## Original PR description

## Overview

`Olmo3ReasoningParser.is_reasoning_end` returns True if a `</think>` appears anywhere in the prompt, even when the generation prompt then opens a new `<think>`. With the real Olmo-3-7B-Think template, a user message that mentions `</think>` is enough.

## Claims

- Structured outputs no longer constrain the reasoning from the first token for such prompts.
- Streaming no longer marks reasoning as ended up front, which sent the reasoning out as `content`.

## Validation

- `pytest tests/reasoning/test_olmo3_reasoning_parser.py tests/tool_parsers/test_olmo3_tool_parser.py`: 40 passed.
- The new `test_is_reasoning_end_uses_latest_marker` fails 2 of 5 on main and passes with the fix.
- pre-commit (ruff, mypy, typos) is clean.

## Details

The scan now walks back and stops at whichever marker comes last, as `BaseThinkingReasoningParser` and `kimi_k3` already do. `<think>` has two tokenizations (`<th ink >` and `Ġ< think >`), so both are matched.

Not a duplicate: #60353 only flushes the streaming hold-back, and #48160 moves this function over unchanged.
