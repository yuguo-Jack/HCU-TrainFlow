# [Bugfix] Don't unmap cuMem allocations freed while asleep

[Upstream PR](https://github.com/vllm-project/vllm/pull/59228) · state: open · merged: False

## Original PR description

## Purpose

`my_free()` in `csrc/cumem_allocator.cpp` always calls `unmap_and_release()` on the handle returned by the Python free callback. For an allocation that is asleep, `sleep()` has already unmapped it and released the physical handle, so freeing a cuMem-pool tensor while asleep double-unmaps it. The driver error is left in the global `error_code`, so the next `create_and_map` (e.g. `wake_up()`) or cuMem allocation fails with that stale error. This happens on engine teardown while asleep, or when a pool tensor is freed during sleep. It becomes more frequent once CUDA graph pools are cuMem-backed (#59160).

Fix (CUDA path only; the ROCm path already skips an asleep allocation via an empty chunk list):
- `unmap_and_release()` sets `*p_memHandle = 0` after a successful release;
- `my_free()` skips `unmap_and_release()` for a zero handle and only frees the address reservation.

No Python change is needed: `_python_free_callback` already pops the entry, drops the CPU backup and returns the handle. The Python-only alternative, remapping physical memory before the free so the C++ unmap succeeds, can OOM when a colocated trainer holds the VRAM freed by sleep.

**Related:**
- Fixes item 2 of #36651: `my_free` on allocations already released by `sleep()`.
- #46203 fixed the same double unmap/release on the ROCm path by tracking asleep allocations. This is the CUDA counterpart.
- #46054 proposed the same zero-handle idea and was closed because the ROCm fix had landed; the CUDA path stayed unfixed.

## Test Plan

New `test_free_while_asleep` in `tests/basic_correctness/memory/cumem/test_cumem.py` (discard and offload variants): sleep, free a pool tensor while asleep by releasing the pools with `release_pools()` (as engine shutdown does), then check that the pointer is untracked, the CPU backup is dropped, no memory is remapped, and `wake_up()` succeeds with the other tensors intact.

```
pytest tests/basic_correctness/memory/cumem/test_cumem.py -k free_while_asleep
```

  - Unpatched: 4× `CUDA Error: invalid argument`.
  - Remapping in Python before free: 4× `out of memory`.
  - With this fix: a clean teardown.
