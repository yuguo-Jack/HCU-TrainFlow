# [Test][RL] Guard against direct checkpoint attention-sink writes

[Upstream PR](https://github.com/vllm-project/vllm/pull/57806) · state: closed · merged: False

## Original PR description

Add one source-level audit test for direct checkpoint-backed attention sink writes. It checks the explicit sink inventory and also discovers candidate load sites across `vllm/**/*.py`, so a loader in a different file from the parameter definition is still inspected (including HY-V4 AMD).





The AST check rejects direct parameter `copy_` destinations in checkpoint sink branches while leaving derived runtime tensors outside those branches alone. This source audit guards against direct writes; the runtime reload tests exercise the loader contract. This PR contains one commit and one test file.





Merge this audit after #57797, #57798, #57801, #57803, #57804, and #57805. Until those fixes land on `main`, this test is expected to find their old sink copies there.

### What changed in this revision

- Sink aliases are now scoped to the branch that binds them. `_load_weights_*` reuse `param` for ordinary weights elsewhere in the same function, so the previous whole-function scoping reported every non-sink `param.data.copy_` in `gpt_oss.py` as a violation (17 hits instead of the 3 real sink branches).
- A `copy_` whose destination is a parameter view is only a violation under a sink test; a bare-name destination additionally has to name the sink. `sinks.copy_(sinks.float())` inside `process_weights_after_loading` is correctly out of scope.
- The load-site scan no longer requires a `copy_(` to be present. Requiring it meant a module dropped out of the audit set as soon as its own sink load was fixed, which is exactly when the guard matters.
- Coverage is enforced by discovery rather than by the list: every module that assigns a sink-named attribute must be listed, the listed files must still be discoverable, and the scans assert a minimum yield so a misresolved repository root cannot silently no-op the audit.
- The detector has direct unit coverage for each historical violation form and for the derived-state case it must ignore.

Verified discrimination: on the pre-fix tree the detector reports 19 files / 21 sites; on the integrated tree it reports 0.
