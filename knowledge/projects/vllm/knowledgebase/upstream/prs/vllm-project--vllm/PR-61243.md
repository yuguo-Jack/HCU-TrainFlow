# [HiSparse] GLM-5.3-Flash support

[Upstream PR](https://github.com/vllm-project/vllm/pull/61243) · state: open · merged: False

## Original PR description

## Purpose

Make HiSparse work with GLM-5.3-Flash (`Glm5NextForConditionalGeneration`). Fixes #59176. Builds on #60805 (merged).

**Changes**
- Read `index_topk` from `hf_text_config`. Flash's top-level config is multimodal, so startup failed with "HiSparse is only supported for DSA models with index_topk".
- `resolve_hisparse_specs` (worker, before the KV layout is resolved) groups only the MLA specs. It also grouped Flash's non-MLA caches (KDA state, kpool tail ring), which needs the resolved layout ("KV cache layout has not been resolved yet").
- Skip per-layer host mirrors outside connector steps. Flash's MLA layers take the generic MLA path, which mirrors each layer on the TP0 host writer. Graph-capture forwards run without `start_step`/`finish_forward`, so TP0 raised "HiSparse layer 0 mirrored twice" and startup hung in the custom all-reduce.
- Backends declare `supports_hisparse()`; with HiSparse on, sparse-MLA backend selection skips backends without a HiSparse path. On Hopper, Flash (head size 512) got FlashInfer SM90 sparse MLA, which has no HiSparse path and read stale KV on prefix-cache hits: GSM8K fell on each pass over one server (0.901, 0.834, 0.745). SM90 support: #61277.
- Order the side-stream top-k convert after its block table. The leader's batch block table is built on the compute stream after the indexer recorded `logical_topk_ready`, so the side stream could read it before it was written: illegal memory accesses and NaN logits under load, and the graph-capture hang. Found by moving one HiSparse stream at a time onto the compute stream.
- **Core (`vllm/v1/worker/gpu/model_runner.py`, one line):** pass `attn_metadata` to `kv_connector.pre_forward` on PIECEWISE and eager steps too, as FULL steps already do. Without it, HiSparse's per-step prepare never ran under PIECEWISE replay; Flash's MLA layers otherwise prepare only inside the captured KV-update op, so the swap-row counter was never reset ("HiSparse swap rows exceed the configured speculative decode capacity: stop=62, capacity=32"). Other connectors ignore the kwarg.

**Not in this PR**
- Hopper with HiSparse: Flash needs #61277 (SM90 backend support). The two Hopper fallbacks failed with the side-stream race and the PIECEWISE prepare bug fixed here; not re-tested on Hopper.
