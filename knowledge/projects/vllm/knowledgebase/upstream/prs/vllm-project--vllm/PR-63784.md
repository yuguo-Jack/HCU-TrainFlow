# [Spec Decode][Feature] Add Self-Speculative Decoding for Looped Language Models

[Upstream PR](https://github.com/vllm-project/vllm/pull/63784) · state: closed · merged: False

## Original PR description



## Overview

This PR adds self-speculative decoding support for looped language models, starting with [Dory](https://huggingface.co/nvidia/NVIDIA-Nemotron-Labs-Dory1.0-4B-BF16). The implementation uses a shared interface so future looped models can add support without duplicating the decoding logic.

### What is Self-Speculative Decoding for Looped LLMs

* Dory supports variable loop counts during inference, allowing the same model to act as both drafter and verifier without a separate draft model.
* Tokens are drafted with fewer loops (e.g., k=1), then verified together using more loops (e.g., k=4).
* Since drafting and verification share model weights, they can reuse the KV cache and activations from their common layers.

## Details

- Add native `looped_self_draft` decoding with shared target weights, initially supporting Dory.
- Add `SupportsLoopedSelfDraft` so other looped models can implement the method.
- Configure draft and shared loop depths with `num_draft_loops` and `num_shared_loops`.
- Share prefix KV caches; keep private caches for unshared draft loops and output layers.
- Make draft activation reuse optional, with request validation, invalidation, and recomputation fallbacks.
