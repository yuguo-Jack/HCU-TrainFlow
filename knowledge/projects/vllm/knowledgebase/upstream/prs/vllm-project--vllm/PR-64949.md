# [Bugfix][Kernel] Synchronize Marlin MoE shared-buffer reuse

[Upstream PR](https://github.com/vllm-project/vllm/pull/64949) · state: open · merged: False

## Original PR description

## Overview

Synchronize Marlin MoE's final shared weight reads before reduction reuses the same storage.

## Claims

- Removes the observed discarded-prefetch shared-memory race.
- Preserves exact output and workspace bytes in the captured GPTQ and MXFP8 native calls.

## Validation

H100, CUDA 13.0, Torch 2.14.0; public base `e318ac09796468ac31139d64d609143874e0ed3b`. Both full native targets were rebuilt with `-lineinfo`.

The existing GPTQ case reports 55,808 Marlin read972/write1365–66 hazards on the base and zero after the fix. Both runs retain 3,072 separate cuBLAS reference hazards. Replaying its two frozen native calls removes reference GEMMs: 72,192 Marlin hazards before, zero after; exact output/workspace bytes match.

```bash
case='tests/kernels/moe/test_moe.py::test_fused_marlin_moe[a_type50-b_type50-c_type50-8-133-1024-2048-12-3-1]'
compute-sanitizer --tool racecheck --error-exitcode 86 \
  --racecheck-report all --print-level info --print-limit 0 \
  --target-processes all .venv/bin/python -m pytest \
  -p no:rerunfailures -vv -s -x "$case"
```

That case and both existing `test_mxfp8_marlin_moe_padded_round_trip` shapes pass normally on both builds; all three candidate cases pass memcheck. Direct native synccheck passes on both formats and both builds. Full-suite synccheck stops in the unchanged alignment helper at `moe_align_sum_kernels.cu:282` on both builds, before Marlin, with the same 32 errors; it is not a passing full-suite result.

Hot-buffer CUDA-graph timings: 12 counterbalanced paired blocks, 24 observations per arm, with A/A controls and driver-controlled clocks. Medians in µs:

| Native call | Base | Fixed | Paired change, median [range] |
| --- | ---: | ---: | ---: |
| INT4 W2-like M1/K768/N2048 | 6.568 | 6.566 | −0.40% [−1.78, +1.35] |
| INT4 W2-like M32/K768/N2048 | 9.556 | 9.590 | +0.38% [−0.05, +0.59] |
| Existing MXFP8 W2 M66/K128/N256 | 5.625 | 5.698 | +1.20% [+0.82, +1.63] |

INT4 changes overlap A/A variation; the small MXFP8 call has a measured cost. These measurements do not establish serving throughput or universal overhead.

## Details

The final spare weight prefetch is discarded, but its shared read can overlap another warp's reduction writes. `cp_async_wait<0>()` waits for asynchronous copies; it does not finish those shared reads across the CTA. The barrier orders them before storage reuse. No wrong-answer effect is established.

Duplicate checks found no matching fence. [#48926](https://github.com/vllm-project/vllm/pull/48926) changes signed scale extension; [#46639](https://github.com/vllm-project/vllm/pull/46639) changes batch-invariant launch geometry. The existing L4 MoE CI step selects this header; local sanitizer coverage is H100 only.
