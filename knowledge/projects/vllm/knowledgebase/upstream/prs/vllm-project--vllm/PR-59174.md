# [RFC][Core] Add a model metadata provider hook for plugins

[Upstream PR](https://github.com/vllm-project/vllm/pull/59174) · state: open · merged: False

## Original PR description

## Purpose

Plugins can replace weight loading with `register_model_loader()`, but not the config and tokenizer files that vLLM resolves first. Offline with an empty HF cache, `EngineArgs.__post_init__` fails in `get_model_path()`. ModelExpress monkey-patches `snapshot_download` to work around this.

This PR lets a general plugin register one provider with `register_model_metadata_provider()`. `prepare_source()` runs in `EngineArgs.__post_init__` before path resolution. `prepare_consumer()` runs in EngineCore and each worker, which may sit on another filesystem and read tokenizer files before `load_model()`. Without a provider the hook does nothing. One catch: `EngineArgs(**vars(ea))` now raises `TypeError`, because the source is kept in a private `init=False` field.

Open question: `LLM(...)` calls `prepare_source()` a second time from `log_non_default_args()`; online, that call asks the provider for the default revision. Should it skip the hook?

Not a duplicate: #50633 only covers `runai_streamer` object storage, and #58399 adds a ModelExpress weight transfer backend.

AI assistance (GitHub Copilot) was used for this change, its tests and this description; every changed line was reviewed by the submitter.

Part of ai-dynamo/modelexpress#640.
