# [Bugfix][Tokenizer] Honor truncation_side in MistralTokenizer.encode

[Upstream PR](https://github.com/vllm-project/vllm/pull/62071) · state: open · merged: False

## Original PR description

## Overview

`MistralTokenizer.encode(text, truncation=True, max_length=N)` returns the first N tokens, whatever the tokenizer's `truncation_side` is. `get_tokenizer` sets `truncation_side="left"` for generative models, and `MistralTokenizer.__call__`, which the renderer uses for text prompts, truncates on that side. So a prompt pretokenized with `llm.get_tokenizer().encode(...)` keeps its beginning, while the same text passed to `LLM.generate` with the same truncation keeps its end.

## Claims

- `encode` truncates on the configured side and returns the same ids as `__call__` with the same arguments, for SentencePiece and Tekken tokenizers, with and without BOS.
- `max_length=0` still returns `[]`.

## Validation

```python
from vllm.tokenizers import get_tokenizer

tokenizer = get_tokenizer("mistralai/Mistral-7B-Instruct-v0.3", tokenizer_mode="mistral")
text = "The quick brown fox jumps over the lazy dog."
kwargs = dict(truncation=True, max_length=4, add_special_tokens=False)
print("truncation_side:", tokenizer.truncation_side)
print("encode:  ", tokenizer.convert_ids_to_tokens(tokenizer.encode(text, **kwargs)))
print("__call__:", tokenizer.convert_ids_to_tokens(tokenizer(text, **kwargs)["input_ids"]))
```

## Details

`encode` called the `mistral_common` tokenizer directly and sliced `encoded[:max_length]`. The method used to carry a TODO to call `self.transformers_tokenizer.encode(...)` once huggingface/transformers#41962 was in. #56325 removed the other shims for that, but kept the slicing because Transformers doesn't truncate when `max_length=0`, and vLLM treats `truncate_prompt_tokens=0` as an empty prompt. I keep that case explicitly and otherwise call the Transformers backend, which `__call__` already uses.

Duplicate check: I searched open and closed issues and PRs for `MistralTokenizer.encode`, Mistral truncation and `truncation_side`, and the changed files. #61363 and #61524 handle special tokens when the renderer truncates with an explicit side; they don't change `MistralTokenizer.encode`. The other open PRs on these files (#38448, #45525, #52643, #59213, #58553) don't touch `encode`.
