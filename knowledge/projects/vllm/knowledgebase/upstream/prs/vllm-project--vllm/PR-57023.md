# [Model][Engram] Add node-sharded Mooncake storage

[Upstream PR](https://github.com/vllm-project/vllm/pull/57023) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Add optional node-sharded Mooncake storage for Engram tables through one
model-independent adapter shared by DeepSeek V4.1 Engram and Qwen4-Exp PLE,
including Qwen3.8-Flash-Next checkpoints.

## Claims

- Assign complete hash heads to storage nodes independently of TP, ETP, and DP
  compute ranks, while preserving each model's existing collectives,
  quantization, and prefetch behavior.
- Publish only node-owned rows through Mooncake
  `EngramStore.populate_shard_and_sync`, then perform local and remote lookups
  through one stream-ordered byte interface.
- Use vLLM's dense local worker rank as the default Mooncake `caller_id`, rather
  than the process-visible CUDA ordinal.
- Keep store references alive through model-runner teardown, then close them in
  deterministic namespace order after CUDA graphs have been released.

## Validation

## Details

### Design and compatibility

The adapter receives a model's head layout and byte-row encoding. DeepSeek
keeps TP head ownership, TP gathers, FP8/ue8m0 decoding, and side-stream
prefetch. Qwen keeps ETP vocabulary ownership, DP/ETP collectives,
sequence-parallel behavior, prefetch, and downstream quantization; its global
FP8 scale remains outside Mooncake rows and is applied exactly once by the
existing PLE layer.

`caller_id` defaults to `get_world_group().local_rank`, which remains dense
when one-GPU worker processes each see CUDA device 0. Explicit caller mappings
remain supported and are range-checked. Shutdown uses the common GPU worker
entry used by both model-runner versions: it captures attached stores before
runner teardown, releases model graphs, and then closes stores in the same
namespace order on every worker.

This implementation requires the node-sharded API from
[Mooncake #5129](https://github.com/kvcache-ai/Mooncake/pull/5129) after the
[large-local-table offset fix](https://github.com/magicYang1573/Mooncake/pull/1)
has landed in that branch. The fix prevents 32-bit offset overflow for local
tables larger than 2 GiB, including common Qwen PLE layouts. Authenticated
masters use `MC_METADATA_HTTP_TOKEN`.

### Duplicate-work check

The open [#64082](https://github.com/vllm-project/vllm/pull/64082) shares
already host-resident DeepSeek Engram tables across independent instances, and
[#64500](https://github.com/vllm-project/vllm/pull/64500) prefetches CPU-offloaded
DeepSeek rows. Neither provides node-sharded local/remote Mooncake lookup or
Qwen PLE support. [#57872](https://github.com/vllm-project/vllm/pull/57872)
uses Mooncake for KV-cache P/D transport and does not overlap this table-storage
path.

The placement contract matches
[SGLang #47673](https://github.com/sgl-project/sglang/pull/47673): contiguous
whole-head node ownership, model-load publication, per-node storage shards,
per-GPU callers, and preserved compute parallelism. The vLLM adapter is shared
by DeepSeek and Qwen rather than being Qwen-specific.

### Configuration and limitations

```json
{
  "local_dir": "/mnt/nvme/mooncake-engram",
  "shard_id": 0,
  "num_shards": 2,
  "master_addr": "http://10.0.0.10:5000",
  "session_id": "deployment-2026-11-04",
  "max_lookup_rows": 65536,
  "rdma_device": "mlx5_{local_rank}",
  "num_callers": 4
}
```

`max_lookup_rows` counts token/head IDs. Mooncake placement is an alternative
to `disk_offload`, `dp_shared_memory`, `use_thp`, and `embedding_across_dp`.
Pipeline parallelism, elastic EP, and Qwen NVFP4 PLE rows remain unsupported.
