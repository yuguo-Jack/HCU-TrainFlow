# [Doc] Add Kimi-K3 GB300 Dynamo disaggregated profile to the recipe selector

[Upstream PR](https://github.com/vllm-project/vllm/pull/62563) · state: closed · merged: True

## Original PR description

## Overview

Add the GB300 Kimi-K3 disaggregated Dynamo + vLLM profile from [SemiAnalysisAI/InferenceX#4047](https://github.com/SemiAnalysisAI/InferenceX/pull/4047) to the recipe's interactive selector, as requested in [this review comment](https://github.com/SemiAnalysisAI/InferenceX/pull/4047#issuecomment-6276636819). #62528 documented the profile as guide text only; this encodes it in the structured `pd_cluster` fields so GB300 + **Prefill/Decode Disaggregation** + the **Dynamo** PD router (`?pd_router=dynamo`) renders the qualified prefill and decode commands. Only `recipes/models/moonshotai/Kimi-K3.yaml` changes.

## Claims

- GB300-scoped `strategy_overrides.pd_cluster` additions:
  - `hardware_overrides.gb300` (both roles): TP8 + DCP8 (`--decode-context-parallel-size 8 --dcp-comm-backend a2a`, direct-DCP env), `TOKENSPEED_MLA`, fp8 KV, `--mamba-ssm-cache-dtype bfloat16`, prefix caching with `--prefix-match-unit 128`, `--gpu-memory-utilization 0.92`, `--max-cudagraph-capture-size 512`, `--enable-cumem-allocator`, the DSpark K4 draft (`Inferact/Kimi-K3-DSpark`, probabilistic draft sampling, block verification), and the NCCL/UCX/connector env.
  - Prefill: two trays (`nodes: {gb300: 2}`, TEP8), `--moe-backend deep_gemm_mega_moe`, `trtllm_ragged_backend: cute-dsl`, `--max-num-seqs 64`, `VLLM_ENABLE_GEMM_RS=1`, `VLLM_KIMI_K3_SHARD_SP_SHARED_EXPERT=0`.
  - Decode: `parallelism: {default: dep, gb300: tp}` on two trays, `tokenspeed_mla_min_split_kv: 8`, `VLLM_ENABLE_GEMM_RS=0`, and overrides for the DEP-only decode flags (`--no-data-parallel-hybrid-lb`, `--max-num-batched-tokens 16384`, `cudagraph_mode` FULL_AND_PIECEWISE). The GB300 decode MegaMoE entry is dropped because this decode pool has no expert parallelism.
- One guide line points from the existing GB300 section to the selector and lists what stays guide-only.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` from vllm-project/recipes passes; `git diff --check` is clean.
- Rendered `pd_cluster` through `resolveCommand` for GB300 with the Dynamo router (ranks 0 and 1): the prefill and decode argv/env match the qualified InferenceX launch lines for these settings.
- Rendered `pd_cluster` (native router and Dynamo) for GB200, B300, B200, H200 and MI355X: byte-identical to `main`.

## Details

- **Guide-only, because the schema has no field for them:** xPyD worker counts (1P2D-2P5D; the builder renders one pool per role), the qualified MooncakeStore `MultiConnector` options and Mooncake master (the KV Offload row's Mooncake option emits its generic connector last), and the Dynamo frontend's `least-loaded` router mode with 900 s session affinity (the frontend's router mode comes from `strategies/pd_cluster.yaml`).
- **Rendering notes:** role `vllm_args` apply to every GPU and the renderer cannot remove a flag per hardware, so GB300 shows both `--no-enable-prefix-caching` / `--enable-prefix-caching`, `--data-parallel-hybrid-lb` / `--no-data-parallel-hybrid-lb` and (prefill) `--no-enable-flashinfer-autotune` / `--enable-flashinfer-autotune`; argparse applies the later flag, which is the qualified value. The existing pd_cluster Blackwell `UCX_TLS=rc,cuda_copy` still applies on GB300.
- `--max-num-batched-tokens 16384` is vLLM's API-server default on >=160 GB GPUs (`vllm/engine/arg_utils.py`), which is what the qualified decode ran with.

## Render re-verification

Re-checked with `resolveCommand` against the qualified launch lines of [InferenceX run 39140771499](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/39140771499): every GB300 prefill and decode serving flag matches; the only difference is the benchmark-only synthetic acceptance in the run's speculative config. The contradictory-looking pairs (`--no-enable-prefix-caching` / `--enable-prefix-caching`, `--data-parallel-hybrid-lb` / `--no-…`, `--no-enable-flashinfer-autotune` / `--enable-…`) come from shared pd_cluster role flags that a model recipe cannot remove per GPU; the GB300 value is always emitted later, so argparse keeps it. Other hardware and strategies render byte-identically to main. Companion: #62542 (GB200) is stacked on this branch.
