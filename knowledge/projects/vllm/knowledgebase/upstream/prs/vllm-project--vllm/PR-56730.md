# [Bugfix][Core] Derive trace replay max_tokens from trace length

[Upstream PR](https://github.com/vllm-project/vllm/pull/56730) · state: open · merged: False

## Original PR description

## Purpose

There appears to be a bug that is an inconsistency between the documented trace replay behavior and its implementation.

The trace replay documentation [vLLM Trace Replay](https://docs.vllm.ai/en/latest/serving/online_serving/trace_replay/?utm_source=chatgpt.com#usage) states that 
- `max_tokens` is automatically set to the trace length.
- The trace is truncated if it does not fit within `max_model_len` given the prompt length.
- Generation produces exactly the trace tokens, then stops.

However, the current implementation uses `min(trace length, max_tokens)`. Since `max_tokens` defaults to 16, replay stops after 16 tokens for a longer trace. A smaller user-provided `max_tokens` causes the same issue. This PR sets `max_tokens` to the trace length after applying the `max_model_len` limit, which matches the documented behavior.
