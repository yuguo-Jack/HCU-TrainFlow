# [KV Connector][NIXL] Select push mode for NixlConnector via transfer_mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/64230) · state: closed · merged: True

## Original PR description



## Overview

Let `NixlConnector` run the push connector through `kv_connector_extra_config={"transfer_mode": "push"}`, for serving frameworks that only accept the `NixlConnector` name (e.g. Dynamo's P/D connector registry).

## Claims

- `{"kv_connector": "NixlConnector", "kv_connector_extra_config": {"transfer_mode": "push"}}` resolves to `NixlPushConnector`.
- Default (`transfer_mode` unset or `"pull"`) is unchanged: `NixlPullConnector`.
- Other values raise `ValueError` at config resolution instead of silently falling back to pull.

## Validation

```bash
python -m pytest tests/v1/kv_connector/unit/test_config.py tests/v1/kv_connector/unit/test_hma_auto_config.py -q
# 25 passed
```

The new test covers unset → pull, `"push"` → push, and an invalid value → `ValueError`. No E2E run on this branch: the resolved class is the existing `NixlPushConnector`, unchanged. Our DeepSeek-V4.1 P/D deployment on Dynamo already runs exactly this (push connector under the `NixlConnector` name), currently through a `kv_connector_module_path` alias module that this PR replaces.

## Details

- Resolution happens in `KVConnectorFactory.get_connector_class`, which every class-level hook goes through (HMA support, sleep mode, piecewise CUDA graph, KV cache layout, metrics, MultiConnector children). So these hooks see the push class, and `kv_connector` stays `"NixlConnector"` for the existing `has_connector("NixlConnector")` checks.
- `transfer_mode` matches the existing `_TRANSFER_MODE` values (`"pull"` / `"push"`) of the NIXL workers, which already feed the handshake compatibility hash.
- No duplicate: no open PR adds a mode switch to `NixlConnector` (searched `NixlPushConnector`, `transfer_mode`).
