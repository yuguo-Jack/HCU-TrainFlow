## Overview

<!-- Summarize the change in 1-2 lines. Link relevant issues and PRs. -->

Allow sweep plot filters to match values containing commas when the entire value is quoted.

Related to #60510, but separate in scope: that PR handles comparison-operator characters inside a single filter value; this change handles separators between filter expressions and leaves operator selection unchanged.

## Claims

<!-- State the accomplishments in a few concrete bullets: speedups, feature support, bug fixes, etc. -->

- Preserve commas inside matching single- or double-quoted filter values while retaining ordinary comma-separated filters.
- Start quoting only at the initial comparison's value boundary, preserving literal quotes later in an unquoted target.
- Reject unterminated quoted values with an explicit error.
- Preserve literal apostrophes and backslashes in unquoted values; update CLI help and rendered documentation.

## Details

<!-- Explain motivation, design decisions, root cause, tradeoffs, and limitations concisely. Link or collapse lengthy supporting material. -->

The previous unconditional comma split turned `_benchmark_name=="fp8,tp2"` into two invalid expressions. The parser now tracks matching quotes around a value and recognizes only unquoted commas as separators.

The implementation deliberately avoids shell tokenization so existing apostrophes and Windows-style backslashes remain literal. Tests assert actual DataFrame selection, existing numeric/boolean behavior, malformed-input errors, and the real CLI's handling of a quoted value combined with another condition. No dependencies are added.

The [follow-up commit](https://github.com/singh4jitendra/vllm/commit/66469328bb4432ea88f5f735f375d208766fea7f) addresses [BlueRaddish's review](https://github.com/vllm-project/vllm/pull/63469#pullrequestreview-5642352514): comparison-like text inside an unquoted target must not open quoting again. The scanner now remembers the first comparison's value boundary in each expression and only starts quoting while that value prefix is empty or whitespace. The boundary resets at an unquoted comma. Coverage includes the reported literal targets, a whitespace variant, three real CLI regressions, and a quoted value following an earlier expression.

Duplicate checks on October 24 searched open PRs for quoted commas, sweep quoting, and `PlotFilters`, and inspected the current patch of #60510. That patch changes `PlotFilterBase` operator selection; it leaves the comma splitting addressed here unchanged.

Before the original PR was opened, the human submitter confirmed reviewing the original patch and running its documented tests, and explicitly authorized the personal GitHub noreply DCO sign-off and required AI attribution. The author subsequently requested this review fix; the follow-up commit and its validation evidence are recorded above.

The quote scanner also starts quoting **inside an already-started unquoted target**, which regresses preservation of literal quotes in unquoted values. At `a0ada888b53b38403fb294c2e2e8234e8dfe6f39`:

```python
df = pd.DataFrame({"label": ["build=='one", "other"]})
PlotFilters.parse_str("label==build=='one").apply(df)
# ValueError: Unterminated quoted value in plot filter ...
```

The upstream merge parent `66bf931544202f159cf83c66a812826b7d5c84fb` selects `build=='one` correctly. The `endswith(tuple(PLOT_FILTERS))` condition recognizes the **second** `==` as a value boundary. The same regression affects `build!="one` and `version>='one`; it is distinct from #60510 because the first `==` already selects the intended operator and the target does not begin with an operator.

Please start outer quoting only at the initial comparison's value boundary, leaving later quotes in an unquoted value literal, and add a regression in `test_plot_filters.py`.

Verified through the real CPU/empty-target installation: **10 parent consumers pass; this head has 7 matching failures / 3 controls**, including three real CLI-to-`main()` filtering cases.
