# [Frontend] Expose canonical KV cache group metadata

[Upstream PR](https://github.com/vllm-project/vllm/pull/48121) · state: open · merged: False

## Original PR description

## Purpose

Prefix-cache aware routing needs the full KV cache spec for each group. `get_kv_cache_group_metadata()` only gives kind, block size and sliding window, so this PR fills in the rest.

- Each group now includes layer names/count, heads, head size, dtype, page size and the MLA, sink and mamba fields
- `UniformTypeKVCacheSpecs` groups list their per-layer specs under `layer_specs` so no detail gets lost
- Added `get_kv_cache_group_metadata_async` on the core client and wired it through `EngineClient`/`AsyncLLM`. The result is cached after the first call

This builds on #56925 which brought the method back after #53941 removed it and fixed block sizes under DCP. Block sizes still come from the scheduler's manager, so DCP groups keep reporting the effective size. 

Ref: "Required core change" in RFC ##38147 description.
