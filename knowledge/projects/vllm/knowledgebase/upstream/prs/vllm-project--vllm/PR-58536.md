# [Perf][DSA] Shard the decode indexer rows across TP ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/58536) · state: open · merged: False

## Original PR description

## Purpose

On CUDA, every tensor-parallel rank runs the sparse-attention (DSA) indexer on every decode row: paged MQA logits, DeepSeek-V4.1 candidate selection or mask, and top-k. Every rank ends up with the same indices. At long context this is a large part of the decode step.

This PR adds an opt-in, `VLLM_DSA_DECODE_INDEXER_ROW_SHARD=1`, that splits the decode rows across TP ranks:

- **Row assignment:** rank `r` scores the rows of requests `r, r + tp, r + 2·tp, …`. All of a request's rows stay on one rank, because the varlen `fp8_fp4_paged_mqa_logits` reads a request's KV once for all of its rows.
- **Metadata builder:** gathers each rank's rows, block-table rows and context lengths into persistent buffers and builds that rank's DeepGEMM schedule. The plan depends only on the padded row count, so CUDA graphs replay with the same buffers.
- **Indexer op:** scores the local rows, keeps DeepSeek-V4.1 candidate blocks rank-local, all-gathers the int32 top-k indices across TP ranks, and restores request order in `topk_indices_buffer`.
- **When it applies:** uniform decode batches with at least `VLLM_DSA_DECODE_INDEXER_ROW_SHARD_MIN_REQS` requests (default 8), on the varlen paged-logits path, without DCP/PCP or the sparse-logits indexer.

## Test Plan

**Serve.** DeepSeek-V4.1-Flash on 4× B200. The only difference between main and this PR is `VLLM_DSA_DECODE_INDEXER_ROW_SHARD`: `0` behaves exactly like main, `1` is this PR.

```bash
VLLM_DSA_DECODE_INDEXER_ROW_SHARD=1 \
VLLM_USE_V2_MODEL_RUNNER=1 VLLM_USE_RUST_FRONTEND=1 VLLM_ENABLE_GEMM_RS=1 \
VLLM_DISABLE_DSV4_MEGAMOE_SHARED_EXPERT_FUSION=0 \
vllm serve deepseek-ai/DeepSeek-V4.1-Flash --served-model-name dsv41 --port 8008 \
  --tensor-parallel-size 4 --enable-expert-parallel --moe-backend deep_gemm_mega_moe --language-model-only \
  --tokenizer-mode deepseek_v41 --tool-call-parser deepseek_v41 --enable-auto-tool-choice \
  --reasoning-parser deepseek_v41 --engram-config '{"cpu_offload":true}' \
  --speculative-config '{"method":"dspark","num_speculative_tokens":5,"enable_adaptive_verification":false}' \
  --max-model-len 1048576 --max-cudagraph-capture-size 512
```

**Benchmark.** AIPerf with the InferenceX AgentX traces: long-context, multi-turn agentic sessions with a mean input of ~135K tokens. 64 concurrent sessions, 1,200 s (the concurrency-128 runs use `--concurrency 128`):

```bash

  --endpoint /v1/chat/completions --endpoint-type chat --streaming --model dsv41 \

  --failed-request-threshold 0.10 --use-server-token-count --no-gpu-telemetry
```

Main and this PR ran at the same time on one 8× B200 node: one server on GPUs 0–3, the other on GPUs 4–7.

**Long-context benchmark (`vllm bench serve`).** 64 distinct 126,000-token random prefixes are sent once with 1 output token to fill the prefix cache. Each measured prompt is one of those prefixes (round-robin, so every wave of 64 requests reads 64 different KV histories) plus a fresh 2,000-token random suffix: 128,000 input tokens with 98.4% prefix reuse, 1,024 output tokens, concurrency 64. Both files use the `custom` dataset format, one `{"prompt": ..., "output_tokens": ...}` per line. Main and this PR again ran side by side on one node.
