# [Bugfix][Parser] Fix multi-token reasoning-to-tool handoff with repeated thought blocks

[Upstream PR](https://github.com/vllm-project/vllm/pull/63171) · state: open · merged: False

## Original PR description



## Overview

Fixes a streaming parser bug where a model emitting an extra `<|channel>thought...<channel|>` block before a tool call under multi-token (speculative) decoding starves `TokenIDScanner` during the reasoning-to-tool handoff, causing subsequent tool calls to leak as raw text.

## Claims

- Fixes `DelegatingParser` / `StreamingParserEngine` handoff when `REASONING_END` and a subsequent `THINK_START` arrive in the same multi-token batch (`skip_tool_parsing=True`).
- Fixes `ParserEngine.extract_content_ids` to slice after the *first* `_reasoning_end_token_id` in the current turn rather than the last, preserving intermediate tokens for `_tool_parser`.
- Fixes `Gemma4Parser._events_to_delta` to reset `_prefix_stripped` on subsequent `REASONING_START` events so repeated `thought\n` prefixes are stripped.

## Validation

Verified streaming parsing across batch sizes `1..8` (simulating MTP speculative decoding) on `Gemma4ReasoningParser` + `Gemma4ToolParser` via `DelegatingParser` with repeated thought blocks followed by a tool call:

```python
from transformers import AutoTokenizer
from vllm.parser.abstract_parser import DelegatingParser
from vllm.parser.gemma4 import Gemma4ReasoningParser, Gemma4ToolParser

tok = AutoTokenizer.from_pretrained("google/gemma-4-12b-it")

class Gemma4DelegatingParser(DelegatingParser):
    reasoning_parser_cls = Gemma4ReasoningParser
    tool_parser_cls = Gemma4ToolParser

text = (
    "<|channel>thought\nFirst thought block.\n<channel|>\n\n"
    "<|channel>thought\n<channel|>"
    '<|tool_call>call:tavily_search{query:<|"|>example search query<|"|>}<tool_call|><turn|>'
)
all_ids = tok.encode(text, add_special_tokens=False)

for step in range(1, 9):
    p = Gemma4DelegatingParser(tok)
    prev_text, prev_ids = "", []
    tools = []
    for i in range(0, len(all_ids), step):
        b = all_ids[i : i + step]
        cur_ids = prev_ids + b
        cur_text = tok.decode(cur_ids, skip_special_tokens=False)
        dm = p.parse_delta(prev_text, cur_text, cur_text[len(prev_text):], prev_ids, cur_ids, b)
        if dm and dm.tool_calls:
            tools.extend(dm.tool_calls)
        prev_text, prev_ids = cur_text, cur_ids
    assert len(tools) > 0, f"Failed to parse tool call at step={step}"
```

## Details

- **Root Cause:**
  1. When `<channel|>` (`REASONING_END`, token `101`) and a second `<|channel>` (`THINK_START`, token `100`) arrive in the same speculative decoding step, `_reasoning_parser` (`skip_tool_parsing=True`) transitions back into `REASONING_BUFFERING` and emits `content=None`.
  2. `DelegatingParser.parse_delta` detects `is_reasoning_end(delta_token_ids)` is `True` and calls `_tool_parser.parse_delta` with `current_text = reasoning_delta.content or ""` (`""`) and `current_token_ids = extract_content_ids(delta_token_ids)` (`[100]`).
  3. `_tool_parser`'s `TokenIDScanner.scan("", [100])` sees token `100` (`<|channel>`) is missing from `delta_text=""` and defers `PreLexedTerminal("THINK_START", 100, "<|channel>")`. Because `<|channel>` was already consumed in that step and never appears in future `delta_text`, `TokenIDScanner` buffers the rest of the turn (including `<|tool_call>...<tool_call|>`) in `_deferred_post_text` and flushes it as plain text at `<turn|>`.
- **Fix:**
  - In `StreamingParserEngine`, track `_reasoning_ended_in_skip_tool_mode` once `REASONING_END` fires when `skip_tool_parsing=True` so any subsequent reasoning markup terminals in the same batch are emitted as `TEXT_CHUNK` (`content`) for handoff to `_tool_parser`.
  - In `ParserEngine.extract_content_ids`, scan forward from `turn_start` when matching `_reasoning_end_token_id` (matching the existing `_reasoning_end_token_ids` behavior) so multi-token deltas with multiple `<channel|>` tokens slice after the first one.
  - In `Gemma4Parser._events_to_delta`, reset `_prefix_stripped` when a new `REASONING_START` event is encountered.
