# [Bugfix][KV Connector] Fence block reuse for producer-role loads

[Upstream PR](https://github.com/vllm-project/vllm/pull/62438) · state: open · merged: False

## Original PR description

## Overview

Prevent an aborted synchronous KV load's late failure report from affecting an unrelated request after physical block reuse. Addresses the cross-request allocation case in #61905 by extending the existing in-flight block-free fence to producer-role connectors.

## Claims

- With overlapping execution steps, aborted owners' blocks remain unavailable for reallocation until their synchronous step completes, regardless of the top-level connector role.
- An unrelated request waits under exhausted KV capacity, then reuses the blocks and completes normally after the old report is handled.
- Tests cover both failure policies, successful-load controls, all three transfer roles, async scheduling, PP and single-batch execution.

## Details

`defer_block_free` was enabled only for a consumer/both top-level role. `MultiConnector` children have independent roles, so that gate cannot establish whether a producer configuration loads KV. Under overlapping steps, cancellation can otherwise free A's blocks, C can acquire them in the next schedule, and `_handle_invalid_blocks` can attribute A's report to C by the reused physical ID.

This removes the top-level role condition and reuses the existing completion fence. Deferred blocks drain at the beginning of `update_from_output`; the normal engine path performs no scheduling allocation between that drain and failure handling. Single-batch execution keeps immediate freeing. The producer handoff control also checks completion without premature preemption when its blocks are fenced.

**Tradeoff:** pure producers also hold blocks until outstanding execution steps complete, which can delay admission or change preemption under KV pressure. Production throughput/latency impact is unmeasured; a future explicit load-capability contract could narrow this conservative policy.

**Scope and duplicate check:** #61769 handles failed-prefix eviction for aborted owners; #62287 / #61912 handle preempted-owner bookkeeping. Both leave producer-role physical block reuse to #61905. #42461 proposes a broader request-level reporting interface change. This is an interface-preserving fence extension; searches found no existing PR implementing it. It does not independently implement every expected behavior in #61905, including orphaned-prefix cleanup, or replace connector-specific protection for arbitrarily delayed asynchronous transfers.
