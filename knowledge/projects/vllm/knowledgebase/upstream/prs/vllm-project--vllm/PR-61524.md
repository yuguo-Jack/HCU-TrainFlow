# fix(renderers): preserve special tokens when truncation_side matches tokenizer default

[Upstream PR](https://github.com/vllm-project/vllm/pull/61524) · state: open · merged: False

## Original PR description

## Summary

Fix #61359: When truncate_prompt_tokens is set together with an explicit truncation_side, the special tokens (BOS/CLS/SEP) that the tokenizer adds are incorrectly cut off at the truncated end.

## Root Cause

In TokenizeParams.get_encode_kwargs(), whenever an explicit truncation_side is set, tokenizer-level truncation is disabled and vLLM applies its own slice-based truncation. This was done because the tokenizer can only truncate from its own default side. However, when the requested side matches the tokenizer default, this manual slicing is unnecessary and harmful - it cuts right through the special tokens.

## Fix

Modify get_encode_kwargs() to accept an optional tokenizer parameter. When the requested truncation_side matches the tokenizer default, we let the tokenizer handle truncation itself, because tokenizers correctly preserve special tokens at the truncation boundary. Slice-based truncation remains in place when the requested side differs from the tokenizer default.

## Testing

Verified with the reproducer from the issue:
- truncate_prompt_tokens=4, truncation_side=null → [1, ...] BOS kept
- truncate_prompt_tokens=4, truncation_side=left → [1, ...] BOS now kept (was [278, ...] before)

- chudinovAI · comment · 2026-10-17T22:21:06Z · [source](https://github.com/vllm-project/vllm/pull/61524#issuecomment-6242141515)

This PR also changes `.github/workflows/pre-commit.yml` to turn the pre-run gate's `setFailed` into `warning`, which disables the gate for every PR and is unrelated to #61359 — that hunk needs to go regardless.

On the fix itself: it only applies when the requested side equals `tokenizer.truncation_side`, but vLLM sets that per runner (`right` for pooling, `left` for generate, `tokenizers/registry.py`), so the case in the issue — BGE on an embedding server with `truncation_side="left"` / Cohere `truncate="START"` — still slices off `[CLS]`. Passing `truncation_side=` to `tokenizer(...)` is also ignored by transformers, and `MistralTokenizer.__call__` has no `**kwargs`, so `--tokenizer-mode mistral` with an explicit `"left"` now raises `TypeError: unexpected keyword argument 'truncation_side'`. Three existing tests in `tests/renderers/test_completions.py` fail (`test_explicit_side_tokenizer_unbounded`, `test_explicit_side_left_text`, `test_padding_with_left_truncation_keeps_the_prompt`), and there are no new tests. #61363 covers both sides and all tokenizers with tests.
