# [Bugfix][Quantization] Accept folded NVFP4 scales for Humming A16

[Upstream PR](https://github.com/vllm-project/vllm/pull/60337) · state: closed · merged: True

## Original PR description

## Overview

Accept folded NVFP4 FP16/BF16 scales in Humming's A16 compatibility check, without changing backend priority. Alternative to #60315.

## Claims

- Handles unequal gate/up scales, including dummy-weight initialization.
- Preserves actual weight metadata, other compatibility checks, and strict activation settings.

## Validation

With unpatched Humming on SM120: 10 schema cases and two CT MoE loading configurations passed. Changed-file `pre-commit run --files vllm/model_executor/layers/quantization/utils/humming/schema.py` passed.

2-layer Qwen3 NVFP4 dummy-weight startup and generation passed (2 prompts × 8 tokens, forced Humming, eager, FlashInfer autotune disabled). SM90 and real-model accuracy were not evaluated.

## Details

Use an FP8-scale schema copy only for A16 compatibility checks; kernels retain the original scales. Open-PR searches found no equivalent fix: #60315 changes backend order; #55073 reconciles scales and excludes Humming.

AI assistance: OpenAI Codex implemented the change and ran local validation.
