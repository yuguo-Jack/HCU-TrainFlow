# [KV Connector][NIXL] Reject asymmetric DCP transfers with interleave != block_size

[Upstream PR](https://github.com/vllm-project/vllm/pull/60483) · state: open · merged: False

## Original PR description

## Purpose

When P and D use different DCP sizes (e.g. P DCP1 -> D DCP4), NIXL hands out whole KV blocks by global block position (`_apply_dcp_prefix_caching`). That only works if each local block holds `block_size` contiguous tokens, i.e. `cp_kv_cache_interleave_size == block_size`. NIXL used to force this through the auto-pin in `adjust_dcp_kv_cache_interleave_size`. Since #55531, an explicit `--cp-kv-cache-interleave-size` skips the auto-pin. #55531 also added a matching-DCP check, but only for hybrid MLA+Mamba models. Pure-MLA models with asymmetric DCP and an explicit interleave (e.g. `1`) are still accepted, and their KV gets silently scrambled.

This PR rejects that case during the NIXL handshake (`_validate_remote_agent_handshake`): if `local_dcp > 1`, `local_dcp != remote_dcp` and the local interleave differs from the local block size (computed the same way as the auto-pin), the handshake fails with a clear error. Equal DCP sizes are untouched (rank r -> rank r works with any interleave as long as both sides match). The check uses only local config plus the remote `dcp_size`. A sibling change that adds the interleave to `NixlAgentMetadata` will let a side with DCP=1 also catch a misconfigured peer. With pull, only D validates, so this PR covers the D side.

## Why this is not a duplicate

I checked the related open PRs:
- #60255 applies the existing DCP config checks to the `NixlPullConnector` alias. It keeps valid explicit interleaves and has no handshake-time check for asymmetric DCP.
- #56256 preserves the interleave for per-slot connectors and leaves NIXL's normalization alone.
- #60275 adds DCP prefill + DEP decode for push with hybrid models and auto-resolves the interleave on that path. It does not reject explicit values for pure-MLA pull.
- #45340 handles scheduler accounting for aligned (equal) CP sizes and is explicitly out of scope for unaligned ones.

| Config | Code | gsm8k accuracy |
|---|---|---:|
| Non-disagg TP4 baseline | main | 0.636 |
| P DCP1 -> D DCP4, auto interleave (pinned to 16) | main | 0.646 |
| P DCP1 -> D DCP4, `--cp-kv-cache-interleave-size 1` | main | **0.334** (KV scrambled) |
| P DCP1 -> D DCP4, `--cp-kv-cache-interleave-size 1` | this PR | handshake rejected |

With this PR, the decode handshake fails with:
```
RuntimeError: NIXL transfers between different DCP sizes (local=4, remote=1) require cp_kv_cache_interleave_size == block_size (16), got 1. Omit --cp-kv-cache-interleave-size to let NIXL select it, or use matching DCP sizes.
```
