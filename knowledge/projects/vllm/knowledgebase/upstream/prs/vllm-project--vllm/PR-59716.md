# Block SSRF in multimodal URL fetching: per-hop validation + address filter

[Upstream PR](https://github.com/vllm-project/vllm/pull/59716) · state: open · merged: False

## Original PR description

## Purpose

Media URLs in multimodal requests (`image_url` / `audio_url` / `video_url`) are specified by the client and fetched by the vLLM server on the client's behalf. Two gaps make that fetch an SSRF vector:

- **No private-address filtering by default**: with no `--allowed-media-domains` configured (the default), a URL can target the cloud metadata service (`http://169.254.169.254/...`), loopback ports or internal services directly.
- **The domain whitelist only validates the first hop**: redirects are followed inside requests/aiohttp (`VLLM_MEDIA_URL_ALLOW_REDIRECTS` defaults to True), so every hop after the first is invisible to validation — a 302 from a whitelisted domain bypasses the whitelist entirely.

This PR closes both gaps on the existing call path, with no new dependencies (stdlib `ipaddress`/`socket`/`urllib.parse` only):

- **Per-hop validation on a guarded fetch path** (`vllm/connections.py`): when a `validate_url` callback is passed, `get_bytes` / `async_get_bytes` drive redirects manually — validate the hop, dial the urllib3-normalized URL (`_dial_url`), resolve the next `Location` against the URL actually dialed, capped at 5 hops. Dialing the re-serialized URL guarantees the validated host is always the contacted host, closing parser-differential forms like `http://public.example\@169.254.169.254/` (urllib3 and aiohttp's yarl parse the backslash-@ form differently). Callers that pass no validator (`run_batch` and the other `get_bytes` users) keep today's exact behavior.
- **Address filter over all resolved addresses** (`vllm/multimodal/media/connector.py`): the host is resolved with `socket.getaddrinfo` and every returned address is checked — RFC1918, loopback, link-local (including cloud metadata 169.254.0.0/16), CGNAT 100.64.0.0/10, 6to4 2002::/16, NAT64 64:ff9b::/96; IPv4-mapped IPv6 (`::ffff:...`) is unwrapped before filtering. Resolution also normalizes non-canonical literal hosts (decimal/hex forms) to the address that would actually be dialed. DNS failures raise `ConnectionError`, keeping today's retryable semantics.
- **Whitelist tightened per hop**: when `--allowed-media-domains` is set, every redirect hop re-checks the whitelist (and the scheme must remain http(s)), so a redirect can no longer escape it.
- **`VLLM_MEDIA_EGRESS_BLOCK_PRIVATE` (default on)** gates the address filter; deployments serving media from private networks (e.g. an internal MinIO) opt out explicitly with `VLLM_MEDIA_EGRESS_BLOCK_PRIVATE=0`.

### Design decisions

- **Default-on changes the redirect path for every deployment — disclosed**: with the default on, all media fetches go through the manual redirect driver: the hop cap tightens from requests' internal 30 to 5, and intermediate hops' `Set-Cookie` headers are no longer absorbed by client session semantics (each hop is an independent request; media fetches carry only a User-Agent, no credential headers, so no functional loss is known). If maintainers prefer to stage the behavior change, the debatable fallback is to ship `VLLM_MEDIA_EGRESS_BLOCK_PRIVATE` defaulting to `"0"` (strictly opt-in) and flip the default in a follow-up release; per-hop whitelist checking applies whenever `--allowed-media-domains` is set either way.
- **Env var, not a CLI flag**: consistent with the existing same-area switch `VLLM_MEDIA_URL_ALLOW_REDIRECTS`, and avoids threading a new argument through `config/model.py` + `arg_utils.py`; a CLI flag can follow as an independent change.

### Performance

- The async guard runs the blocking `getaddrinfo` inside the existing `global_thread_pool` (8 workers) that media decoding already shares, keeping the event loop unblocked. On main that pool already runs other media work concurrently, so the marginal risk of one extra pool task per hop is small; each hop adds one resolver round-trip (milliseconds, bounded by the system resolver timeout), while `data:` URLs and cache hits are unaffected.
