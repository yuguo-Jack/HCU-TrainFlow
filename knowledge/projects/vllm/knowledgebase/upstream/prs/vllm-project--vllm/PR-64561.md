# [CI] Shard Spec Decode AL MTP + Other Acceptance automatically

[Upstream PR](https://github.com/vllm-project/vllm/pull/64561) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Enroll the nightly Spec Decode AL MTP + Other Acceptance step and its AMD mirror in automatic sharding. The hand split (three parallel jobs, each running a different `pytest` command through `$BUILDKITE_PARALLEL_JOB` guards) becomes one plain `pytest` command, which the pipeline generator shards from recorded per-file timings.

## Claims

- The step and its AMD mirror run one `pytest` command over `acceptance_rates/mtp_other/`, and the generator plans the shards.
- The step stays under the 20-minute-per-shard target, as on other enrolled steps.
- New tests in the folder are planned automatically instead of landing in shard 0.

## Validation

- `split_check.py`: no step runs the whole suite in each of its parallel jobs.
- A scoped build of the PR's first commit recorded timings for the new command; it passed, running the step as one job.
- `/ci run` on this head checks that the planner now splits the step from those timings (3 jobs for the NVIDIA step, 2 for the AMD mirror).
- Not yet run for real: the first main nightly with the new command. It records main timings, which replace the bootstrap ones from then on.

## Details

- This is the only step whose parallel jobs run different commands, so main has timed `test_mtp.py` under several labels and the planner can't time the new single command from them. One passing build of this commit records timings under the new label first.
- Each Gemma4 MTP test is longer than one shard's budget on its own, so the planner gives each its own job, as the hand split did.
- Timeouts are unchanged: the PR's first commit raised the NVIDIA one only for that bootstrap build, and the second restores it.
