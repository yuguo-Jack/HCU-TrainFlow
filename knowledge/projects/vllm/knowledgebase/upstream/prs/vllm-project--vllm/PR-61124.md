# [SketchSSM] Add SketchSSM decode for Mamba-2 with Triton kernels

[Upstream PR](https://github.com/vllm-project/vllm/pull/61124) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Adds SketchSSM ([paper](https://arxiv.org/abs/2609.33051)) for Mamba-2 layers with Triton kernels, behind `--sketchssm`. SketchSSM builds on ReplaySSM (#48018): the state is still updated exactly once per window of W steps, and the other decode steps read a compact sketch of the state instead of the full state, cutting state-access traffic by about 10x at the default mean rank 8. NemotronH is wired up.

## Claims

- New `--sketchssm <calibration file or HF repo>` option for Mamba-2 decode (`NemotronHForCausalLM`), with `--sketchssm-mean-rank` to pick the sketch size at load time.
- Faster decode of Mamba-2 models: on Nemotron-3-Nano-4B (one RTX PRO 6000, batch 256), end-to-end decode is 2.75x faster than the default decode and 1.8x faster than ReplaySSM. The paper reports results for Nemotron-Nano-9B-v2 and Nemotron-3-Super (NVFP4).
- Accuracy preserved: GSM8K 82.9 ± 0.8 vs 82.9 ± 1.2 for the default decode (3 seeds); the paper shows mean rank 8 matches the full-state baseline on MATH-500, AIME25, GPQA Diamond and LiveCodeBench.
- Compatible with the rest of the stack: only the decode of the Mamba-2 layers changes. Prefill runs the default chunk scan, the attention and MLP layers are untouched, and model weights and weight-side optimizations (e.g. quantization) are unaffected. Mamba prefix caching works in align mode, and tensor parallelism splits the heads' ranks and the group frames across ranks.
- Without `--sketchssm`, behaviour is unchanged.

## Validation

Nemotron-3-Nano-4B with [`SketchSSM/Nemotron-3-Nano-4B-BF16`](https://huggingface.co/SketchSSM/Nemotron-3-Nano-4B-BF16) (mean rank 8, W=16) on one RTX PRO 6000 Blackwell (sm_120). ReplaySSM (Triton) requires Model Runner V1; the others run on V2.

| | Decode, batch 256 | Speedup | GSM8K 5-shot (3 seeds) |
| --- | --- | --- | --- |
| default | 38.2 ms/step | 1.00x | 82.9 ± 1.2 |
| ReplaySSM (V1) | 25.5 ms/step | 1.50x | 83.4 ± 0.9 |
| SketchSSM | 13.9 ms/step | 2.75x | 82.9 ± 0.8 |

## Details

- **Motivation.** At serving batch sizes, decode of hybrid models is bound by reading each request's recurrent state (Mamba-2: heads x head_dim x state_size FP32 per layer). ReplaySSM (#48018) writes the state only once per window of W steps; SketchSSM also avoids reading it on the other W-1 steps. The [paper](https://arxiv.org/abs/2609.33051) covers the algorithm and its accuracy.
- **Design decisions.**
  - *Exact flushes, sketched reads.* The flush is ReplaySSM's exact window update, so sketch error does not carry across windows; only the reads inside a window are approximate.
  - *Rotated, key-major state.* The state is kept in a calibrated orthogonal frame per group, key-major, so a head's sketch is its leading rows. Decode rotates only the query (and the window keys at a flush). Prefill runs the default chunk scan and rotates the final states, so prefill matches the default path.
  - *Ranks allocated at load.* The calibration file holds rank-score curves; `--sketchssm-mean-rank` allocates per-head ranks once at startup (CPU), so the accuracy/traffic budget changes without recalibrating. `layer_ids` in the file maps calibration rows to model layers.
  - *Reuse ReplaySSM.* The rings, write positions, flush flags and B·C precompute kernel are shared. SketchSSM adds sketch rows, flush rows and prompt-completion flags to the Mamba metadata; flush rows (state update and sketch rebuild in one kernel) run on the aux stream next to the sketch reads.
  - *Model Runner V2 only.* Sketches are indexed by the persistent request index (`req_idx`) of MRV2.
- **Tradeoffs.**
  - Reads inside a window are approximate, so accuracy depends on the mean rank. The default, mean rank 8, is near-lossless in the paper (average accuracy matches the full-state baseline on all four models).
  - Extra memory outside the KV cache: per-layer sketch buffers for `max_num_seqs` requests, about 6% of the FP32 state at mean rank 8 (4.8 MiB per request for Nemotron-3-Nano-4B, 7.9 MiB for Nemotron-Nano-9B-v2).
  - A per-model calibration file is needed (published for several models on [Hugging Face](https://huggingface.co/SketchSSM), or made with [SketchSSM](https://github.com/SNU-ARC/SketchSSM)).
- **Limitations.**
  - Not supported yet (rejected at config time): speculative decoding, KV connectors, a non-FP32 SSM cache, stochastic rounding, `--mamba-backend` other than triton, Model Runner V1, and Mamba prefix caching other than align mode.
  - Requires CUDA with compute capability 8.0 or newer, a Mamba-2 state size that is a power of two (at least 16) and a head dim of at least 16.
  - The Triton launch configs in `ops/sketchssm_config.py` (like `replayssm_config.py`) are tuned on an RTX PRO 6000 (sm_120) for now; configs tuned on other GPUs will be added to this file.
- **Follow-ups (planned).**
  - Optimized CUDA decode kernels for Mamba-2 SketchSSM: vLLM will use them when the `sketchssm` package is installed (`pip install sketchssm`), and fall back to the Triton kernels otherwise.
  - Support for other linear attention architectures, including Gated DeltaNet and KDA.
  - Support for the features rejected at config time today: speculative decoding, KV connectors, a BF16 SSM cache, stochastic rounding, other `--mamba-backend` options, and Mamba prefix caching beyond align mode.
