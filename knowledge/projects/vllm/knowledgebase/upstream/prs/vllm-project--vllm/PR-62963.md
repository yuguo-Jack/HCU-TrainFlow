# [Spec Decode][MRV2] Add speculator hooks for non-chain verification and draft suspension

[Upstream PR](https://github.com/vllm-project/vllm/pull/62963) · state: closed · merged: False

## Original PR description

## Overview

This PR adds five optional hooks to Model Runner V2's `BaseSpeculator`, so a speculator can verify drafts that are not a chain (a tree, for example), choose how many drafts each request verifies, and stop drafting when speculation stops paying off at large batch sizes. Each hook defaults to today's behavior, and the runner calls a per-step hook only when the speculator overrides it, so built-in speculators run as before.

Model Runner V2 verifies drafts as a chain, and only built-in adaptive verification can change how many drafts a step verifies. A tree verifier needs to rewrite positions and attention inputs before the target forward, supply its own rejection sampler, and move the accepted path's KV and recurrent state afterwards. A speculator that finds drafting no longer helps needs a way back to plain decode. The hooks sit at points where the runner already branches.

Builds on #62962; review the last 4 commits. Together the two let an out-of-tree speculator run tree verification on hybrid models.

## Claims

- `make_rejection_sampler(sampler)` lets the speculator supply the verifier. The default keeps the chain `RejectionSampler`, and `ModelState.custom_sampler` still takes precedence.
- `prepare_verify_inputs(input_batch, model_inputs, *, dummy_run)` runs before the target forward (in capture and dummy runs too), after positions, slot mappings and attention metadata exist. A tree verifier rewrites positions in place and stages what its attention backend reads.
- `post_accept(input_batch, sampler_output, num_sampled, num_rejected)` runs after sampling, before `num_computed_tokens` advances and before `propose`. A tree verifier moves the accepted path's KV and recurrent state to the slots the next step expects.
- `verify_budget(req_ids, num_draft_tokens)` returns how many of its scheduled drafts each request verifies this step, and the rest count as rejected. The runner trims the batch on the host before dispatch, so the token count and decode width that select the CUDA graph follow the budget. Built-in adaptive verification keeps precedence when enabled.
- `suspend_drafting(num_reqs, req_ids)` is asked once per scheduled batch when the speculator sets `may_suspend_drafting`. When it returns True, pending verification drains and the batch's requests decode with the target alone until they finish, on target-only attention metadata and decode CUDA graphs, without draft KV. A zero draft count behaves differently, because it still extends the draft KV.

## Validation

The other rows were measured on the previous base (`56e67b46a3`) with #62962 and #62961 underneath, on an earlier revision with the same hook bodies, whose runner called every hook on every step. The speculator rows served 88 SPEED-Bench first turns with up to 512 new tokens, one fresh server and one run per row, and their throughput is generated (output) tokens per second over the wall-clock time of the run.

## Not a duplicate

I ran the duplicate-work searches from `AGENTS.md` §1 (open PRs, with keywords for custom rejection samplers, tree verification hooks, verify budgets and suspending drafting). No open PR adds these Model Runner V2 hooks. These are related, and this PR uses no code from them:

- #53426 skips the draft forward at zero draft tokens for MTP and DFlash, as an operator opt-in. `suspend_drafting` is a decision the speculator makes per batch, and it also stops draft KV extension.
- #58340 reports the number of drafts verified under adaptive verification. The same metric would apply to `verify_budget`.
- #62682 adds approximate verification as a built-in rejection-sampling method. `make_rejection_sampler` lets an out-of-tree speculator supply its own sampler, and the two work side by side.

## Details

- The sampler contract is `RejectionSampler.__call__`'s (`sampled_token_ids`, `num_sampled`, `num_rejected`, and logprob rows in sampled-token order).
- The runner detects overrides once, when it builds the speculator, by comparing each hook on the speculator's class with `BaseSpeculator`'s.
- `suspend_drafting` and `verify_budget` take and return host data only (request ids and counts) and must not read device tensors.
- Suspended decode runs with synchronous scheduling and either eager execution or full decode graphs. When a speculator opts in, the runner rejects prefix caching, KV transfer, DBO, context, data or pipeline parallelism, and recurrent replay or recovery. Draft weights and KV capacity stay allocated.
- Non-chain verification with pipeline parallelism is outside this PR.
