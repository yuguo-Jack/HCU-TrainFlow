# feat: add BROWSER_BACKEND env var support to HarmonyBrowserTool, default to youcom

[Upstream PR](https://github.com/vllm-project/vllm/pull/47213) · state: closed · merged: False

## Original PR description

## Summary

`HarmonyBrowserTool` previously hardcoded `ExaBackend`. This adds a `BROWSER_BACKEND` env var (defaults to `"youcom"`) that lets users select between `YouComBackend` and `ExaBackend`.

This mirrors the pattern already used in gpt-oss, which defaults to `"youcom"` in all three of its entry points:

- [`browser_server.py`](https://github.com/openai/gpt-oss/blob/main/gpt-oss-mcp-server/browser_server.py) (MCP server): `os.getenv("BROWSER_BACKEND", "youcom")`
- [`chat.py`](https://github.com/openai/gpt-oss/blob/main/gpt_oss/chat.py) (CLI chat): `os.getenv("BROWSER_BACKEND", "youcom")`
- [`reference-system-prompt.py`](https://github.com/openai/gpt-oss/blob/main/gpt-oss-mcp-server/reference-system-prompt.py) (reference setup): `os.getenv("BROWSER_BACKEND", "youcom")`

vLLM's demo tool server uses gpt-oss's backend library. Defaulting to `"youcom"` aligns with the upstream project's existing choice. Users who need Exa can set `BROWSER_BACKEND=exa`.

## Changes

- Read `BROWSER_BACKEND` env var in `HarmonyBrowserTool.__init__` (defaults to `"youcom"`, matching gpt-oss)
- Select `YouComBackend` (with `YDC_API_KEY`) or `ExaBackend` (with `EXA_API_KEY`) based on the env var
- Warning message includes the relevant env var name (`YDC_API_KEY` or `EXA_API_KEY`)
