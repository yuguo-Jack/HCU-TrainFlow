# [Bugfix][Quantization] Index INT8 MoE per-channel weight scales independently of act quant

[Upstream PR](https://github.com/vllm-project/vllm/pull/58570) · state: closed · merged: False

## Original PR description

Fixes #58532

`QuarkW8A8Int8MoEMethod` can load static per-tensor activation scales with per-output-channel weight scales. The legacy Triton `fused_experts` path still used `per_act_token_quant` to pick both layouts, so static activations (`per_act_token_quant=False`) also took the tensor weight-scale branch. Routed experts' channel scales were ignored.

This keeps the legacy static-INT8 path (no oracle migration) and splits the two flags:

- `int8_w8a8_moe_quant_config` now takes `per_out_ch_quant` and Quark/compressed-tensors/online INT8 callers set it from the actual weight scheme.
- The shared non-block W8A8 Triton kernel indexes A scales with `per_act_token_quant` / `per_channel_quant` and W scales with `per_out_ch_quant`.

No open PR already covers this combo. #57092 is the opposite mixed case (per-token acts + per-tensor weights) and is still open.

LGTM, this PR fixes a real bug where `QuarkW8A8Int8MoEMethod` supports:

- weight key: `kInt8StaticChannelSym`
- activation key: `kInt8StaticTensorSym`

which currently dispatches on legacy `fused_experts`. Other model producers do NOT support mixed per-channel / per-tensor schemes like this, hence the bug from my understanding.

https://github.com/vllm-project/vllm/pull/58672 will be lighter once this fix is merged.

As per https://github.com/vllm-project/vllm/issues/61024, in a followup PR, `FusedMoEQuantConfig` should leverage `QuantKey` and stop using these custom `per_act_token_quant` and `per_out_ch_quant` flags, so part of this is temporary.
