# [ROCm] Unify ViT FlashAttention backend selection

[Upstream PR](https://github.com/vllm-project/vllm/pull/50449) · state: open · merged: False

## Original PR description

## Overview

Update FlashAttention to [4a948e9c](https://github.com/Dao-AILab/flash-attention/commit/4a948e9c94c21067994572f5b6f37318241d436d) in the ROCm Docker base images and include RDNA targets in CK builds, allowing the existing ViT FlashAttention path to use CK by default on RDNA3/RDNA4.

- **Update FlashAttention:** Change `FA_BRANCH` from `0e60e394` to `4a948e9c` in `docker/Dockerfile.rocm_base` and `docker/Dockerfile.rock_base`. This commit includes **RDNA CK support** and the CK `varlen_fwd` binding fix.
- **Include RDNA build targets:** Remove the filter that excluded RDNA architectures from FlashAttention builds and pass the full `PYTORCH_ROCM_ARCH` list to `GPU_ARCHS`.
- **Unify ViT backend selection:** Apply the same automatic FlashAttention selection conditions to CDNA and RDNA: the `flash_attn` package is available and the dtype is FP16 or BF16.
- **Remove the Triton-only restriction:** Remove the RDNA-specific requirement for `FLASH_ATTENTION_TRITON_AMD_ENABLE=TRUE` and the private implementation module probes.

Explicit backend selection and the existing CDNA AITER FlashAttention priority remain unchanged.


| ViT Backend Setting | `FLASH_ATTENTION_TRITON_AMD_ENABLE` | Before Change | After Change |
|---|---|---|---|
| Auto (no explicit override) | Unset or `FALSE` | `TORCH_SDPA` | `FLASH_ATTN` (CK) |
| Auto (no explicit override) | `TRUE` | `FLASH_ATTN` (Triton) | `FLASH_ATTN` (Triton) |
| Auto (no explicit override), CK missing | Unset or `FALSE` | `TORCH_SDPA` | `FLASH_ATTN` (Triton via FA's own fallback) |

## Details

**ViT FlashAttention support already exists in vLLM.** Previously, the Docker build excluded RDNA targets from FlashAttention CK builds, and automatic FlashAttention selection on RDNA required Triton opt-in.

Following the maintainer discussion, this revision updates the existing PR to include both the **FlashAttention dependency/build changes** and the corresponding **selector simplification**. Updating the pin alone would leave RDNA CK kernels excluded by the existing build filter.

FlashAttention handles CK/Triton implementation selection. The pinned version also falls back to Triton if importing the CK extension raises `ImportError`. This fallback does not cover GPU execution errors after a successful import.
