# [Bugfix] add group count constraint and test cases for grouped topk M…

[Upstream PR](https://github.com/vllm-project/vllm/pull/60775) · state: open · merged: False

## Original PR description

## Overview
Fixed  #60752

This PR restricts the `is_multi_group` dispatch condition in `invokeNoAuxTc` (csrc/libtorch_stable/moe/grouped_topk_kernels.cu) so configurations with more than 8 expert groups (`n_group > 8`) fall back to the general `grouped_topk_fused_kernel` instead of dispatching to the 8-warp `grouped_topk_fused_small_expert_count_kernel`.


## Claims

- **Correctness for >8 groups**: Configurations with 9, 16, and 32 groups now produce correct routing indices matching the reference implementation.
- **Safety**: Eliminates out-of-bounds shared memory accesses in `grouped_topk_fused_small_expert_count_kernel`.
- **Zero regression**: Configurations with $\le 8$ groups (such as standard DeepSeek-style MoE) continue using the optimized small expert count kernel without any behavior or performance changes.
## Validation

### Test Suite Coverage
Extended `tests/kernels/moe/test_grouped_topk.py` to parameterize group counts above 8:
- `(n_expert=144, topk=8, num_expert_group=9, topk_group=4)` (the minimal reproducer from #60752)
- `(n_expert=256, topk=8, num_expert_group=16, topk_group=4)`
- `(n_expert=256, topk=8, num_expert_group=32, topk_group=4)`
All test cases assert that the kernel output exactly matches the reference PyTorch implementation (`baseline_topk_weights` and `baseline_topk_ids`).

## Details

The optimized `grouped_topk_fused_small_expert_count_kernel` is statically bounded for small expert counts, launching with `NumDeepseekExperts` (256 threads / 8 warps) where each warp scores one expert group:
1. The shared memory array `smemGroupScores` has fixed capacity `NumWarps = MaxNumExperts / WARP_SIZE = 256 / 32 = 8`.
2. When `n_group > 8` (e.g., 9, 16, or 32 groups), groups 8 and above are never scored by the warps, causing incorrect expert selection.
3. Furthermore, when `warp 0` reads `smemGroupScores[laneIdx]` in the final selection stage, lanes with `8 <= laneIdx < numGroup` perform out-of-bounds shared memory reads.
Previously, `is_multi_group` checked `n_group > 1 && num_experts <= NumDeepseekExperts` but did not enforce an upper bound on `n_group`. Adding `(n_group <= NumDeepseekExperts / WARP_SIZE)` routes configurations with `n_group > 8` cleanly to the general fallback kernel `grouped_topk_fused_kernel`, which dynamically sizes block dimensions and shared memory based on `n_group`.
