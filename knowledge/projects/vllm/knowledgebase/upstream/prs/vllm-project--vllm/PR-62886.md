# [CPU][Zen] Give the int8 MoE experts slack for the in-place reorder

[Upstream PR](https://github.com/vllm-project/vllm/pull/62886) · state: open · merged: False

## Original PR description

ZenDNN reorders int8 MoE expert weights in place only when each expert has room for the `N * 4` byte compensation row that follows it. `process_weights_after_loading` leaves them packed back-to-back, so it falls back to duplicating every expert instead.

zentorch exposes the fix as an op, `zentorch_preprocess_weights` which re-allocates an `[E, N, K]` int8 weight with slack after each expert.
The op is merged on the zentorch plugin's main branch but is not in a released build yet, so on the pinned `2.14.0.1` this path is inert. `has_zentorch_op` returns `False` and the hook returns before touching a weight. It will reach the public package in an upcoming release.

### What the padding buys

Qwen3.6-35B-A3B W8A8, 40 MoE layers, 256 experts, 32 cores per arm on one socket each. Both arms run the same install and differ only in whether the call added here is allowed to run

```
lm_eval --model vllm --tasks gsm8k --num_fewshot 5 --limit 20 \
  --model_args pretrained=<Qwen3.6-35B-A3B-w8a8>,dtype=bfloat16,max_model_len=4096 \
  --batch_size auto --apply_chat_template
```

| layers padded | 40 | 0 |
| **peak RSS** | **70.9 GiB** | **90.7 GiB** |
| gsm8k exact_match  | 0.95 ± 0.05 | 0.95 ± 0.05
