# [Perf][DSA] Budget sparse-indexer prefill chunks by the compressed logits width

[Upstream PR](https://github.com/vllm-project/vllm/pull/63038) · state: open · merged: False

## Original PR description



## Overview

Since #61149, DeepGEMM returns the CUDA sparse-indexer prefill logits as `[rows, max_seqlen_k]`, where `max_seqlen_k` is the longest key range in the chunk. The chunk planner (`_split_indexer_prefill_chunks`) still budgets each chunk as `rows x total keys of all requests`. This PR budgets CUDA chunks as `rows x longest request`, which matches the buffer that is actually allocated.

## Why

- With the old rule, a step carrying several long prefills (for example, prefix-cache hits on long contexts) is split into more indexer chunks than the logits budget needs.
- Each extra chunk costs a metadata build per step, plus a K-gather, a logits and a top-k launch per indexer layer.
- The saving grows with the number of long-context prefills per step, and applies to every model on the shared CUDA DSA indexer path.

## What changes

- The planner takes `compressed_logits`. The builder sets it to `current_platform.is_cuda()`, the same condition #61149 uses to request compressed logits.
- XPU, ROCm and CPU return `[rows, total keys]` logits and keep today's budget.
- The K-gather workspace bound, the query split of a single over-budget request and the DeepSeek-V4.1 width clamp are unchanged.

## Safety

- Peak logits memory does not grow: every chunk keeps `rows x width x 4` within `VLLM_SPARSE_INDEXER_MAX_LOGITS_MB`, which a single long request already reaches today.
- Each row is scored against the same keys; only chunk boundaries move. Top-k can differ only among exact ties at the k-th logit, which are already unordered today (see #56749).

## Validation

```bash
pytest tests/v1/attention/test_indexer_deepseek_v4_slot_mapping.py -k "compressed_logits or budget"
pytest tests/v1/attention/test_sparse_mla_backends.py -k split_indexer_prefill_chunks
```

- The new planner tests pass on CPU and GPU. The rest of the affected test files give the same results as on `main`.
- End-to-end serving and GSM8K runs with DeepSeek-V4.1-Flash showed fewer indexer chunks and no regression, including on mixed-length batches.

## Related PRs

- #60874 (open) sizes the DeepSeek-V4.1 K-gather reservation from the current `rows x total keys` packing bound. Whichever lands second must pass that reservation to the planner as `workspace_size`. Otherwise a chunk can hold more keys than were reserved, and `cp_gather_indexer_k_quant_cache` writes past the reserved K workspace.
- #58068 (open) sets a fixed logits width on integrated GPUs. The two compose: the width is the larger of the two.
