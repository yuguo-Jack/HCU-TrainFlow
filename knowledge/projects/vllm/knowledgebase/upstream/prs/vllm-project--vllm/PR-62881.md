# [Bugfix][Test] Rotate KV into RHT domain in the INT4 unified attn test

[Upstream PR](https://github.com/vllm-project/vllm/pull/62881) · state: open · merged: False

## Original PR description




## Overview

Fix the INT4 case of `test_triton_unified_attention_per_token_head_scale`. It filled the INT4 cache with unrotated K/V and compared the result against a reference that didn't match what `unified_attention_int4` computes. The test now writes the cache in the RHT domain, like `reshape_and_cache_int4`, so it actually checks the INT4 attention kernel.

Follow-up to #40835. Removes the Intel CI deselect of `[int4-16-128-num_heads0-seq_lens1]`. Downstream report: intel/intel-xpu-backend-for-triton#8358.

**Not a duplicate:** no open PR or issue fixes this test. #62113 edits the same test but keeps the INT4 reference as is and widens the Intel deselect to two INT4 cases. See Details for how the two PRs combine.

## Claims

- The kernel output and the reference now agree (correlation 1.0000 vs ≈ 0.00 before). The test no longer passes or fails depending on the RNG stream.
- INT4 uses the same `atol=rtol=5e-2` as INT8/FP8, down from 0.5. This also removes the Hopper-only `atol=1.1`.
- The Intel CI deselect for this case is removed.
- Test-only change. No kernel or runtime code is modified.

## Details

**Root cause.** `reshape_and_cache_int4` stores `K_s = H·D·k` (RHT, with `H·H = d·I`, `D·D = I`). `unified_attention_int4` relies on that layout:
- it rotates `q' = H·D·q` and uses `softmax_scale / d`, so `q'·K_s / d = q·k`;
- it applies `D·H(·) / d` to the output, which undoes the rotation of V.

The test wrote unrotated `k`, `v` into the cache. As a result the kernel attended over `D·H·k / d` and `D·H·v / d`. Those entries have std ≈ 1/√128, so `output_q ≈ 0`, which is uncorrelated with `output_ref`.

The check `|out_q − ref| ≤ 0.5 + 0.5·|ref|` then reduces to roughly `|ref| ≤ 1`:
- kv_len 128 (`ref` std ≈ 0.15) almost always passes;
- kv_len 64/32 (`ref` std ≈ 0.25–0.3) fails on 1–2 elements whenever a `|ref|` tail exceeds 1.

That explains the reported abs diff just above 1.0 and relative diff of exactly 1.0. The failure is deterministic per seed but differs across platforms because their RNG streams differ, hence the Hopper `atol=1.1` and the Intel deselect.

**Fix.** Rotate K/V with `single_rht` (rounding through bf16, like `reshape_and_cache_int4`) before quantizing. Then inverse-rotate the dequantized reference back to the original domain, as `test_reshape_and_cache_per_token_head` and `test_per_token_head_round_trip_accuracy` already do. The original-domain values stay around N(0,1), so the reference attention is still meaningful.

**Tolerance.** The remaining error comes from bf16 rounding and accumulation order only. The worst case is 0.021 over 200 seeds on CUDA, 2.4× under 5e-2. CUDA's error is larger than XPU's because the Triton Hadamard path rotates in bf16. The reference divides by `head_size`, which equals `largest_power_of_2_divisor(head_size)` for the parametrized `head_size=128`, consistent with the rest of the file.

**Interaction with #62113.** The two PRs only conflict textually, on adjacent lines:
- the tolerance block, where #62113 appends an assert that should be kept;
- the Intel deselect line.

Whichever PR merges second should keep that assert and drop all `test_triton_unified_attention_per_token_head_scale[int4-*]` deselects.
