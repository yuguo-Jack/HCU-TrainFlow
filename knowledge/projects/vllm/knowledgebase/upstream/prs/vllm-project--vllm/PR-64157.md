# [Bugfix][CPU Offloading] Fix CPU offloading for GGUF models which breaks because weights are lazily loaded by moving offloading logic later.

[Upstream PR](https://github.com/vllm-project/vllm/pull/64157) · state: open · merged: False

## Original PR description



## Overview

Fix CPU offloading for GGUF models which breaks because weights are lazily loaded by moving offloading logic later.

## Claims

-  GGUF models lazily load weights while current offloading logic happens before weights are loaded
-  This patch is moves offloading later so it behaves correctly

## Validation
Tests with GGUF Q4_0 OLMoE-1B-7B-0125:
- Unpatched prefetch fails with `AssertionError: CPU storage for ... w13_weight_type is not pinned!`. Command to run is
```
 vllm serve models/olmoe-1b-7b/OLMoE-1B-7B-0125-Q4_0.gguf --load-format gguf --tokenizer models/olmoe-1b-7b --generation-config vllm --enforce-eager --offload-backend prefetch --offload-group-size 2 --offload-num-in-group 1 --max-model-len 1024 --gpu-memory-utilization 0.85 --port 8100
  ```
- Patched prefetch succeeds with  `[PrefetchOffloader] Initialized 8 modules. Total GPU memory saved: 1.8919 GB, Static buffer pool: 0.2362 GB" and "Application startup complete` in the logs
- Unpatched UVA: serve with `--offload-backend uva --cpu-offload-gb 2` reports `"Total CPU offloaded parameters: 0.0"`
- Patched UVA: `Total CPU offloaded parameters: 2.13`

## Details

- For GGUF models CPU offloading misbehaves. It either crashes (for prefetch backend) or does not offload correctly (for UVA)
- UVA: defer offloading to post_init() so GGUF weights are materialized
  before selection; skip zero-element params (GGUF metadata) to avoid
  crash checking for pinning and incorrect accounting.
- Prefetch: skip empty offloaded params during sync_cpu_storage() and
  recompute offloaded_bytes after materialization to report correct size.
