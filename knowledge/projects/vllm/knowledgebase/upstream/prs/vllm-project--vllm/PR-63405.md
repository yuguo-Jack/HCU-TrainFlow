# [CI] Leave GPU headroom in the offline ColBERT plugin tests

[Upstream PR](https://github.com/vllm-project/vllm/pull/63405) · state: open · merged: False

## Original PR description

## Purpose

`plugin-tests-2-gpus` ("(L4) Plugin Integration") has failed in all 7 scheduled full CI runs since Oct 21 (e.g. builds 96581, 96693, 96830, 96933), always on the same three tests:

```
FAILED plugins_tests/test_colbert_query_io_processor_plugins.py::test_colbert_query_plugin_offline[query]
FAILED plugins_tests/test_colbert_query_io_processor_plugins.py::test_colbert_query_plugin_offline[document]
FAILED plugins_tests/test_colbert_query_io_processor_plugins.py::test_colbert_query_plugin_offline_multiple_inputs
ValueError: Free memory on device cuda:0 (20.25/22.03 GiB) on startup is less than desired GPU memory utilization (0.92, 20.27 GiB).
```

The offline tests start an engine at the default `gpu_memory_utilization` (0.92) while ~1.8 GiB of the L4 is still in use from earlier in the module, which leaves 0.02 GiB of slack. PR builds usually squeeze through (6 failures in 162 runs since Oct 21); the full runs don't.

The model (jina-colbert-v2) loads in 1.04 GiB, so this sets `gpu_memory_utilization=0.5` on both offline tests, as other plugin tests already do (e.g. `test_bitsandbytes.py`).

A red step on main also hurts the CI test selector: it won't use a recording from a failed job to skip a step, so this step currently runs on every PR that might touch it.

## Test Plan

- `ruff format --check` / `ruff check` pass.
- CI: `(L4) Plugin Integration` on this PR (it changes the test file, so the step is selected).
