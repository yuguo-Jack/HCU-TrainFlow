# [Model] Add AnyModel: generic support for NAS-optimized heterogeneous architectures

[Upstream PR](https://github.com/vllm-project/vllm/pull/36512) · state: open · merged: False

## Original PR description

## Summary

This PR adds `AnyModel`, a generic model wrapper that enables vLLM to serve **heterogeneous, NAS-optimized models** -- models where each decoder layer can have a different configuration (varying KV heads, intermediate sizes, MoE expert counts, or entirely skipped attention/MLP blocks). This contribution comes directly from **NVIDIA**, where we produce these architectures via the [Puzzle](https://arxiv.org/abs/2411.19146) neural architecture search framework and need first-class vLLM support to deploy them efficiently at scale.

### Motivation

Modern NAS and model compression pipelines (Puzzle, Nemotron Elastic) produce models that are no longer "homogeneous" -- layers can differ in width, depth, and structure. Examples include:
- **Llama-3.1-Nemotron-51B-Instruct**: a 70B Llama pruned to 51B with per-layer KV head and FFN dimension variations, fitting on a single H100 with 2.17x throughput speedup.
- **gpt-oss-puzzle-88B**: a 120B MoE reasoning model compressed to 88B with heterogeneous expert pruning and selective window attention, achieving up to 2.82x throughput on a single H100.
- **Nemotron Elastic** nested submodels: multiple deployment-optimized models extracted zero-shot from a single parent.

Today, vLLM assumes all decoder layers share one global config. AnyModel is the **first implementation in any major serving framework** to support truly heterogeneous layer configurations. We are actively working with Hugging Face to upstream native support for these model formats, but in the meantime this enables immediate deployment of NAS-optimized models through vLLM.

### Design

AnyModel uses a **dynamic-parent wrapper** pattern:

1. **`__new__`** reads `base_architecture` from the HF config (e.g., `"LlamaForCausalLM"`) and creates a wrapper class `AnyModel{Arch}(AnyModel, BaseModelCls)` via Python's MRO.
2. **`__init__`** delegates to the base model's constructor (building the full homogeneous structure), then calls `_patch_anymodel_layers` which:
   - Rebuilds layers whose `block_configs` entry differs from the global config (different KV heads, intermediate size, MoE dimensions, etc.)
   - Injects **no-op** identity pass-throughs (`NoOpAttention`, `NoOpMLP`, `NoOpNorm`) for skipped sub-modules, carefully handling vLLM's fused residual-add RMS norm kernel.
3. **`load_weights`** filters out checkpoint weights for no-op modules, then delegates to the base model's loader.

All base model capabilities (forward pass, load_weights, vision towers for VL models, etc.) are inherited automatically.

### Supported base architectures

| Architecture | Type | Notes |
|---|---|---|
| `LlamaForCausalLM` | Dense | Llama family |
| `MistralForCausalLM` | Dense | Mistral family |
| `Qwen2ForCausalLM` | Dense | Qwen2 |
| `Qwen3ForCausalLM` | Dense | Qwen3 |
| `Qwen2MoeForCausalLM` | MoE | Qwen2-MoE |
| `MixtralForCausalLM` | MoE | Mixtral |
| `NemotronHForCausalLM` | Hybrid | Attention + Mamba + MoE |
| `GptOssForCausalLM` | MoE | GPT-OSS |
| `Qwen3VLForConditionalGeneration` | Multimodal | Vision-Language |

New architectures can be added either via the `_ARCH_REGISTRY` in code or via `anymodel_arch_info` in `config.json` (fully config-driven, no code changes needed).

### What's included

- **`vllm/model_executor/models/anymodel.py`** -- Core implementation (~650 lines): ArchInfo registry, per-layer config creation, no-op injection, dynamic wrapper construction, weight filtering.
- **`vllm/model_executor/models/config.py`** -- `AnyModelConfig` hook to normalize `block_configs` and patch `_model_info` from the base architecture.
- **`vllm/transformers_utils/model_arch_config_convertor.py`** -- `AnyModelArchConfigConvertor` for heterogeneous KV head and MoE expert count derivation.
- **`vllm/model_executor/model_loader/`** -- `resolve_wrapper_cls` hook so the model loader instantiates the correct dynamic wrapper; fallback weight discovery via safetensors index for subdirectory layouts.
- **`vllm/config/model.py`** -- Moved `_try_verify_and_update_model_config()` earlier in `ModelConfig.__init__` so AnyModel can override `_model_info` before downstream code reads it.
- **`tests/models/test_anymodel.py`** -- Comprehensive unit tests (830+ lines): ArchInfo, config overrides, no-op injection, registry integration. No GPU required.
- **`tests/models/test_anymodel_e2e.py`** -- E2E initialization tests (820+ lines) across all supported architectures using dummy weights. GPU required.

Ok we've discussed internally and come to a conclusion on how we will support heterogeneous architectures in Transformers. It would be best if we adopted this standard in vLLM to avoid the future pain of vLLM requiring non-standard config from Transformers.

As an example I'll convert your example from your format:

```json
{
  "model_type": "anymodel",
  "architectures": ["AnyModel"],
  "base_architecture": "LlamaForCausalLM",
  "hidden_size": 8192,
  "num_hidden_layers": 3,
  "num_attention_heads": 64,
  "num_key_value_heads": 8,
  "intermediate_size": 28672,
  "block_configs": [
    {"attention": {"no_op": false, "num_key_value_heads": 8}, "ffn": {"no_op": false, "intermediate_size": 28672}},
    {"attention": {"no_op": true}, "ffn": {"no_op": false, "intermediate_size": 14336}},
    {"attention": {"no_op": false, "num_key_value_heads": 4}, "ffn": {"no_op": true}}
  ]
}
```

to the format that Transformers will standardise on:

```json
{
  "model_type": "anymodel",
  "architectures": ["AnyModel"],
  "base_architecture": "LlamaForCausalLM",
  "hidden_size": 8192,
  "num_hidden_layers": 3,
  "num_attention_heads": 64,
  "num_key_value_heads": 8,
  "intermediate_size": 28672,
  "per_layer_config": {
    "1": {"skip_attention": true, "intermediate_size": 14336},
    "2": {"num_key_value_heads": 4, "skip_ffn": true}
  }
}
```

Key changes are:

- `block_configs: list[dict]` -> `per_layer_config: dict[int, dict]`:
  - Changes from `list[dict]` to `dict[int, dict]` so you only need to specify the layers which use the non-global config. The `int` key is the index of the layer
  - Changes the name to `per_layer_config`, indicating that the scope is the layer. This is clearer than having one dict per sub-component of the layer (`attention` and `ffn` as it is now in the PR)
- `"attention": {"no_op": true}` -> `"skip_attention": true`: While Transformers initially won't support this type of submodule deletion, this is the format we'd prefer to add support for it in vLLM.
