# [ROCm][Perf] Use AITER's indexer K-cache gather for sparse MLA prefill

[Upstream PR](https://github.com/vllm-project/vllm/pull/64148) · state: open · merged: False

## Original PR description



## Overview

On gfx950, the sparse MLA indexer's prefill path gathers the FP8 K cache with AITER's `cp_gather_indexer_k_quant_cache` instead of the Triton kernel. This is the prefill-gather part of #46172 (tjtanaa), rebased on current main. Draft until the measurements below are in.

## Claims

- GLM-5.2 / GLM-5.3 / DeepSeek-V3.2 prefill on MI355X uses AITER's gather kernel, which should lower TTFT on long prompts.
- Decode is unchanged, and so is the DeepSeek-V4 C4A block-flat case.

## Details

- AITER's op takes the layout as one flag, `preshuffle`. `preshuffle = kv_cache.shape[1] > 1` is the Triton wrapper's default (`NORMAL` when `block_size == 1`, else `SHUFFLE`).
- AITER cannot express the explicit `cache_layout="NORMAL"` override that DeepSeek-V4 C4A (`compress_ratio == 4`) needs, so that case stays on Triton.
- AITER derives the token-to-sequence map from `cu_seq_lens`, so `token_to_seq` is not passed.
- Gated on `_ON_GFX950`.

**Relation to #46172.** The rest of #46172 is on main, superseded, or skipped for these models:

| #46172 change | Status on main |
|---|---|
| `FP8_DTYPE` at module level | already present |
| `top_k_per_row_decode` to AITER | superseded by `_launch_aiter_top_k_per_row_decode` (#52882) |
| `indexer_k_quant_and_cache_triton` to AITER | not called: `fused_norm_rope` writes the indexer K cache and the indexer is built with `skip_k_cache_insert=True` |
| `cp_gather_indexer_k_quant_cache_triton` to AITER | this PR |

#46172 has had merge conflicts since 2026-08-22. Happy to close this in favour of it if it is rebased.
