# [Perf][Spec Decode] Rejection sample can skip loads in all-greedy case

[Upstream PR](https://github.com/vllm-project/vllm/pull/65489) · state: open · merged: False

## Original PR description



## Overview
When all requests are greedy: avoid redundant temperature and seed reads from UVA, reducing the runtime of the `rejection_sample()` chain by 26–66 µs (25–76%), depending on bsz and GPU. Part of sampling latency improvements for the Q4 Roadmap: https://github.com/vllm-project/vllm/issues/61024.

## Claims

- Reduce the combined GPU time of the four-kernel `rejection_sample()` verifier on Blackwell B300 and Hopper H100 for all-greedy batches, including rejected/bonus-token handling. The measurements below cover the kernels together, without attributing gains to individual kernels.
- Reuse existing kernels with `do_not_specialize`, so changing the flag does not create another compiled variant for otherwise identical arguments.

## Performance Benchmarks

Scripts and reproduction: [benchmark harness](https://github.com/tomasruizt/vllm-scripts/blob/3c2293886dcca4f199a3a6550b147eee96453fb7/experiments/specdec_sol/bench_greedy_rejection.py), [analysis SQL](https://github.com/tomasruizt/vllm-scripts/blob/3c2293886dcca4f199a3a6550b147eee96453fb7/experiments/specdec_sol/analyze_greedy_rejection.sql), [commands and setup](https://github.com/tomasruizt/vllm-scripts/blob/3c2293886dcca4f199a3a6550b147eee96453fb7/experiments/specdec_sol/README.md#greedy-verifier-microbenchmark).

The timed region is one complete `rejection_sample()` call, containing these four kernel launches in order:

| Kernel | Change exercised by `all_greedy=True` |
|---|---|
| `_compute_local_logits_stats_kernel` | Skip the UVA temperature read while computing target argmax statistics. |
| `_rejection_kernel` | Skip UVA temperature and seed reads on the existing greedy verification path. |
| `_resample_kernel` | Skip the UVA temperature read, return early for greedy corrections, and compute the bonus-token argmax without the Gumbel helper's metadata reads. |
| `_insert_resampled_kernel` | Skip the UVA temperature read when finalizing the correction/bonus token. |

Avg delta µs is the arithmetic mean of `PR − main` latencies across the accepted-prefix cases in each row, using each case's median over three measurement calls. Negative values indicate time saved. ## Details

The CPU already owns the temperature metadata, so detecting an all-greedy batch introduces no device synchronization. Masked temperature/seed loads let the existing greedy branches proceed without waiting for UVA reads. The bonus path computes its target argmax directly. Mixed-temperature batches, synthetic acceptance, FLY and watermarking retain their existing path.

`all_greedy` is required, with a Python `bool` annotation at the API and `tl.int1` in the Triton kernels, before the constexpr parameters. Triton rejects the Python `bool` annotation during GPU compilation.

Existing greedy, placeholder, NaN and adaptive-length tests exercise the flag. The existing Buildkite speculative decoding suite selects this module.

Open-work searches found no existing implementation of this MRV2 metadata-load optimization. Legacy sampler shortcuts and temperature-scaling fusion address different work. AI assistance was used for implementation, validation and this description.
