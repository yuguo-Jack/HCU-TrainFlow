# [Bugfix][Tool Parser] Fix invalid streamed JSON for MiniCPM5 string args with leading or trailing spaces

[Upstream PR](https://github.com/vllm-project/vllm/pull/62306) · state: open · merged: False

## Original PR description

## Overview

In streaming mode, the `minicpm5` tool parser produces invalid JSON for tool-call arguments whenever a string parameter has leading or trailing whitespace (e.g. a separator `", "` or `" - "`). The closing `"}` is never sent. #48846 made the lxml path keep parameter values verbatim, but the two regex paths (the streaming partial parser and the malformed-XML fallback) still `.strip()` bare values. This PR makes them keep values verbatim too. A second, separate commit fixes typed parameters: whitespace is now stripped before a non-string value is parsed, so a padded Python-style literal still gets its schema type.

The MiniCPM5 chat template only wraps a value in CDATA when it contains `<`, `&` or a newline, so padded values reach the parser bare, exactly as the model generates them.

## Claims

- Streamed tool-call arguments are valid JSON and equal to the non-streaming arguments when string values have leading or trailing whitespace.
- The regex fallback for malformed XML now matches the lxml path: values are kept verbatim, and only CDATA is unwrapped.
- Non-string parameters written with surrounding whitespace parse to their schema type in every path. For example, `"\n  True\n"` for a boolean now becomes `true` and `"\n  {'a': 1}\n"` becomes `{"a": 1}`. Before, the well-formed path (since #48846) returned the raw padded string, and streaming then broke. JSON-style values like `" true "` and `" 5 "` already worked and are unchanged.
- Adds two regression tests.

```python
"""End-to-end check against a running `vllm serve openbmb/MiniCPM5-1B
--enable-auto-tool-choice --tool-call-parser minicpm5`.

For each prompt, sends the same request non-streaming and streaming
(temperature 0) and reports whether the streamed tool-call arguments are
valid JSON and equal to the non-streaming arguments.

Run: <venv>/bin/python e2e_minicpm5_serve.py [base_url]
"""

import json
import sys

from openai import OpenAI

base_url = sys.argv[1] if len(sys.argv) > 1 else "http://127.0.0.1:8011/v1"
client = OpenAI(base_url=base_url, api_key="x")
model = client.models.list().data[0].id

tools = [
    {
        "type": "function",
        "function": {
            "name": "join_words",
            "description": "Join a list of words into one string with a separator.",
            "parameters": {
                "type": "object",
                "properties": {
                    "words": {"type": "array", "items": {"type": "string"}},
                    "sep": {"type": "string", "description": "The exact separator."},
                },
                "required": ["words", "sep"],
            },
        },
    }
]

prompts = [
    "Use the join_words tool to join apple, banana and cherry with a comma "
    'followed by a space (", ") as the separator.',
    "Use the join_words tool to join the words hello and world with a single "
    'space (" ") as the separator.',
    'Use the join_words tool to join red, green and blue with " - " '
    "(space, dash, space) as the separator.",
]


def non_streaming(messages):
    r = client.chat.completions.create(
        model=model, messages=messages, tools=tools, temperature=0, max_tokens=400,
        extra_body={"chat_template_kwargs": {"enable_thinking": False}},
    )
    calls = r.choices[0].message.tool_calls or []
    return [(c.function.name, c.function.arguments) for c in calls]


def streaming(messages):
    calls = {}
    stream = client.chat.completions.create(
        model=model,
        messages=messages,
        tools=tools,
        temperature=0,
        max_tokens=400,
        stream=True,
        extra_body={"chat_template_kwargs": {"enable_thinking": False}},
    )
    for chunk in stream:
        if not chunk.choices:
            continue
        for tc in chunk.choices[0].delta.tool_calls or []:
            entry = calls.setdefault(tc.index, ["", ""])
            if tc.function and tc.function.name:
                entry[0] += tc.function.name
            if tc.function and tc.function.arguments:
                entry[1] += tc.function.arguments
    return [tuple(calls[i]) for i in sorted(calls)]


bad = 0
for p in prompts:
    messages = [{"role": "user", "content": p}]
    ns, st = non_streaming(messages), streaming(messages)
    print(f"\nprompt: {p}")
    print(f"  non-streaming: {ns}")
    print(f"  streaming:     {st}")
    for (_, ns_args), (_, st_args) in zip(ns, st):
        try:
            ok = json.loads(st_args) == json.loads(ns_args)
            print(f"  streamed args valid JSON, equal to non-streaming: {ok}")
        except json.JSONDecodeError as e:
            ok = False
            print(f"  streamed args INVALID JSON: {e}")
        bad += not ok
    if not ns:
        print("  (model made no tool call; prompt not useful)")
print(f"\nmismatches: {bad}")
```

## Details

**Root cause.** While a call is streaming, `_parse_partial_params` builds the arguments snapshot and strips bare values (`"sep": "-"`). When the block completes, it is parsed with lxml, which keeps the value verbatim since #48846 (`"sep": " -"`). `_streaming_args_diff` only sends the remainder when the final JSON starts with what was already streamed. Here it doesn't, so it returns `None`, and the client never receives the rest of the arguments. The regex fallback in `_parse_function_block` stripped the same way, so malformed blocks disagreed with well-formed ones in non-streaming too.

**Fix.** A small `_unwrap_cdata` helper replaces the two duplicated CDATA/strip blocks. It unwraps CDATA and otherwise keeps the value as written, like the lxml path. Key names are still stripped as before.

**Second commit.** `_coerce_argument_value` now parses `value.strip()` for non-string types. `json.loads` already tolerated padding, but `safe_literal_eval` raises on leading indentation, so Python-style literals fell back to the raw string. If parsing still fails, the original value is returned unchanged.

**Known limitations (pre-existing, unchanged here).** Two other inputs still decode differently in the streaming partial parser and the final XML parse: a CDATA section surrounded by whitespace (`\n<![CDATA[A<B]]>\n`) and XML entities in a bare value (`A &amp; B`). The chat template never emits either, since it writes CDATA flush against the tags and never uses entities. A follow-up could run each complete `<param>` through the same XML parser in `_parse_partial_params`, which would remove this class of mismatch.

**Not a duplicate.** I searched issues and PRs for `minicpm5`, `MiniCPM5 tool parser`, `minicpm5 whitespace`, `minicpm5 streaming`, `minicpm5xml` and `MiniCPM5XMLToolParser`. #48846 (merged) fixed only the lxml path. #57677 touches this file (regex timeouts) but not value handling. The Rust frontend ports (#50198, #57096) are separate.
