# [Bugfix][KV Offload] Do not offload the partially computed block of a request that finished with an error

[Upstream PR](https://github.com/vllm-project/vllm/pull/63937) · state: closed · merged: True

## Original PR description

## Overview

When a request finishes with an error before its prefill is complete, the block it was computing is stored under the hash of the full block. A later request with that prefix hits the offloaded block and loads KV for tokens that were never computed. One-expression fix in `_build_store_jobs`; sibling of #59096 and #59329.

## Claims

- A request that ends in `FINISHED_ERROR` mid-prefill stores only the blocks it fully computed, as `FINISHED_ABORTED` already does.
- Requests that finished normally are unchanged: they computed their whole prompt, so the clamp is a no-op.

## Validation

```
python -m pytest tests/v1/kv_connector/unit/offloading_connector/test_scheduler.py -q -k finish_mid_prefill
python -m pytest tests/v1/kv_connector/unit/offloading_connector/test_scheduler.py -q
pre-commit run --from-ref origin/main --to-ref HEAD
```

`test_finish_mid_prefill_stores_only_computed_blocks[FINISHED_ERROR|FINISHED_ABORTED]` runs a 16-token prompt through chunked prefill at 6 tokens a step (block size 4), finishes the request after the first chunk, and checks that the finish step stores nothing beyond the one full block step 1 already stored.

On main (6fe3d447ac64) the `FINISHED_ERROR` case fails:

```
AssertionError: FINISHED_ERROR: stored 1 blocks [2] but only 1 full block(s) were computed (num_computed_tokens=6, prompt=16)
```

With the fix both cases pass; the file's other tests still pass (CPU only, macOS, no GPU run). Model outputs are unaffected, so no evals.

## Details

`_build_store_jobs` (`offloading/scheduler.py:1874-1883`) clamps the storable token count to `num_computed_tokens` only for `FINISHED_ABORTED`; every other finish uses `max(num_prompt_tokens, num_tokens - 1)`, which is the whole prompt for a request that produced no output. `storable_chunks` then only bounds by allocated blocks, so the half-written block goes out under its full hash. A request can finish this way mid-prefill through `finish_requests(..., FINISHED_ERROR)` (`sched/scheduler.py:2525-2540`): an encoder-cache mismatch, or a failed KV load under the `fail` policy.

Fix: `min(req.num_computed_tokens, max(req.num_prompt_tokens, req.num_tokens - 1))`. The spec-decode clamp is kept.

Not a duplicate: #63010 (store cursor reset on a restart from token 0) and #60810 (the block table of a resumed streaming session), both merged on 10-25, and the open #62795 (flush promotions before a request's tiers are finalized) are adjacent; none touches this clamp.
