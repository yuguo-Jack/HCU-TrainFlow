# feat(metrics): add per-step copy-on-write KV block counter

[Upstream PR](https://github.com/vllm-project/vllm/pull/65038) · state: open · merged: False

## Original PR description

## Summary

Add a per-step copy-on-write (CoW) KV block counter to the scheduler metrics.

The scheduler issues KV cache block copies (copy-on-write) when a forked sequence gets a partial prefix cache hit that ends mid-block: the shared block is duplicated into a fresh destination block. Today this work is invisible in metrics. This change exposes it as:

- `SchedulerStats.num_cow_blocks` — the number of CoW block copies issued in the most recent `schedule()` step (a per-step delta, mirroring how `prefix_cache_stats` counts per-step).
- A Prometheus counter `vllm:num_cow_blocks` — the cumulative number of CoW block copies from the engine (the logger accumulates the per-step delta into a monotonic counter).

This gives operators visibility into how often sequences fork with partial cache hits, which is a direct cost driver of KV cache usage (each CoW copy duplicates a block and temporarily holds both endpoints).

## Details

- **`vllm/v1/core/sched/scheduler.py`**: track the per-step CoW count in `Scheduler._last_step_cow_blocks`, set unconditionally after `take_kv_cache_block_copies()` (so a step with no copy resets to 0). Surfaced via `make_stats()`.
- **`vllm/v1/metrics/stats.py`**: add `SchedulerStats.num_cow_blocks` field.
- **`vllm/v1/metrics/loggers.py`**: aggregate the per-engine count and register `vllm:num_cow_blocks` Prometheus counter, incrementing by the per-step delta.
- **`tests/v1/core/test_deferred_block_free.py`**: add `test_cow_blocks_stats_per_step_delta` verifying the stat is a per-step delta (0 → 1 → 0 across steps) rather than a cumulative total.

## Test plan

- RED: on base commit the test fails (`SchedulerStats` has no `num_cow_blocks` attribute).
- GREEN: with the change the test passes, and the full `test_deferred_block_free.py` suite passes (19 tests).

File: `vllm/v1/core/sched/scheduler.py` · line 1709

With async scheduling on (the default), step_with_batch_queue calls schedule() for the next step before update_from_output() runs for this one, so this line overwrites the count before make_stats() reads it. I replayed that order on CPU (pending copy, schedule twice, then update) and a single request's CoW copy never shows up: num_cow_blocks is 0 on every step. Adding to it here with += and resetting it in make_stats(), the way prefix_cache_stats is read and reset, counts it once and your test still passes.
