# [Structured Output] Allow propertyNames with additionalProperties on xgrammar

[Upstream PR](https://github.com/vllm-project/vllm/pull/57594) · state: closed · merged: True

## Original PR description

## Purpose

Part of #12131.

xgrammar 0.2.7, pinned in #57272, includes mlc-ai/xgrammar#836: the `additionalProperties` value schema is now honored when `propertyNames` is also present (it fixes mlc-ai/xgrammar#826). `has_xgrammar_unsupported_json_features` still treats that combination as unsupported, so schemas like the one below needlessly skip the xgrammar backend:

```json
{"type": "object", "propertyNames": {"pattern": "^[a-z_]+$"}, "additionalProperties": {"type": "integer"}}
```

This PR removes the `additionalProperties` condition from the `propertyNames` fallback. The `properties`, `patternProperties` and `unevaluatedProperties` conditions stay, because they are still not enforced in 0.2.7 (I checked each against the compiled grammar).

**Not a duplicate:** no open PR touches this condition. #56557, #56753 and #48416 change other parts of the same function. For the integer `multipleOf` gap, which 0.2.7 also closes, I left a note on #48416 because that PR rewrites that line.

AI assistance (Claude Code) was used to prepare this change. I reviewed every changed line and ran the tests below.

**Additional changes from @arpera**:
For each unsupported by xgrammar schema case I added a bug tracking issue report on xgrammar to allow us more easily track bug fixes in xgrammar and react more swiftly on such things.
All my changes are equivalent to main branch, verified this by both: agent and also run all the unit tests from `tests/v1/structured_output/test_backend_xgrammar.py`.

## Test Plan

pre-commit run --files vllm/v1/structured_output/backend_xgrammar.py tests/v1/structured_output/test_utils.py

- Moved the schema from `unsupported_property_names_combinations` to the supported list.
- Added `test_property_names_keeps_additional_properties_value_schema`. It asserts that the compiled grammar accepts `{"score": 5}` and rejects both a bad key (`{"Score": 5}`) and a bad value (`{"score": "seven"}`).

## Test Result

- Before the fix: `test_supported_json_features[property_names_with_additional_properties_schema]` fails. The new grammar test already passes on xgrammar 0.2.7, which confirms the upstream fix.
- After the fix: 70 passed. ruff, mypy and the other pre-commit hooks pass.

Model evals are not needed: the change only affects which backend is chosen for this schema shape, and the grammar test covers the output constraint directly.
