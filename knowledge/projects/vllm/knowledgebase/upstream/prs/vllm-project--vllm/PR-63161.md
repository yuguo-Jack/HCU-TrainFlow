# [Bugfix][Frontend] Memoize parser-engine drop info across requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/63161) · state: open · merged: False

## Original PR description

## Overview
Fixes #58145. Grammar-capable Mistral tokenizers always run `adjust_request`, which builds a new `StreamingParserEngine` per request; each build recompiled one regex per special token (1000 on tekken) and a new `LexerShape` on the event loop.

## Claims
- `_build_drop_info` now hits an `lru_cache(maxsize=32)` keyed on the config terminals and the tokenizer's special tokens/ids, so the drop lexer is built once per (config, tokenizer).
- `StreamingParserEngine(...)` construction with the Mistral-Small-3.2 tokenizer: 56.9 ms -> 0.039 ms; `MistralParser(tokenizer)`: 60.7 ms -> 0.048 ms (Apple M-series CPU, median of 200).
- End to end on an L4, `Ministral-3-8B-Instruct-2512` with `--tokenizer-mode mistral`: median TTFT drops 2.3x at 2 req/s and 6x at 4 req/s, with equal or higher throughput (table below).

## Validation
- `pytest tests/parser/engine/test_engine.py -k drop_info`: fails on base (`assert _DropInfo(...) is _DropInfo(...)`, two different objects), passes on this branch.
- `pytest tests/parser/engine`: 6039 passed. `pytest tests/parser/mistral`: 188 passed.
- `pre-commit run --files <changed files>`: all hooks passed (ruff, mypy, typos, SPDX, test tethering).

L4 (SM 8.9) at a locked 900 MHz SM clock, cooled to 72 C before each run, `vllm bench serve --backend openai-chat --dataset-name random --random-input-len 512 --random-output-len 128 --num-prompts 200`, base and patched interleaved, 2 runs each, `VLLM_USE_FLASHINFER_SAMPLER=0` on both arms (the FlashInfer sampler JIT does not build on this node):

## Details
The drop info depends only on the config terminals and the tokenizer's special tokens, never on the request. The key is built from those values, not object ids, so it cannot alias after GC and holds no tokenizer or config reference. `_DropInfo` is read-only after construction (engines copy `extra_token_ids`; `LexerShape` is already shared across lexers), so one instance can back many engines. `lru_cache` is thread-safe. Not a duplicate: `gh pr list --state open --search "58145 in:body"`, `StreamingParserEngine`, `_build_drop_info` and `drop_info` return no open PR for this path. AI assistance (Claude) was used; I reviewed every changed line and ran the tests and benchmarks above.
