## Overview

Add documented Ascend A3/950DT deployment configurations to the existing GLM-5.1 recipe, preserving its NVIDIA/AMD configuration and Guide.

**Blocked by https://github.com/vllm-project/recipes/pull/1163.** This draft uses that renderer's named-script schema. Merge and publish the renderer/schema first; the current `Recipes` check against renderer `main` is expected to reject these new fields until then. This PR does not change or bypass that workflow.

## Claims

- Add hardware-scoped A3 W8A8 and 950DT MXFP4 variants, container preparation, Ascend parser/MTP overrides, and fixed documented topologies.
- Provide A3 two-node colocated serving and both four-node PD workflows in the upper command builder: complete node templates, separate start commands, shared role-appropriate launchers and Ascend Proxy configuration.
- Maintain scripts once in `deployment_scripts`, not as positional Guide code blocks. The concise Ascend Guide retains prerequisites, exact checkpoint links, scope/compatibility notes and fixed-revision source references.
- Preserve the existing GPU variants, common model configuration and GPU Guide. No new `verified` badge or runtime-performance claim is added.

## Details

Source: [vllm-ascend GLM5 tutorial, e5e820d5c935e6197bec8bc13e8e8936eb2740d0](https://github.com/vllm-project/vllm-ascend/blob/e5e820d5c935e6197bec8bc13e8e8936eb2740d0/docs/source/tutorials/models/GLM5.md).

| Workflow | Checkpoint / topology |
| --- | --- |
| A3 native single-node | `Eco-Tech/GLM-5.1-w8a8`, TP16, 66,600 tokens; publisher reference, not the tutorial's W4A8 settings |
| 950DT native single-node | `Eco-Tech/GLM-5.1-w4a4c8-mxfp4`, TP8, 202,752 tokens, FP8 attention/indexer KV |
| A3 colocated | `Eco-Tech/GLM-5.1-w8a8c8-MTP`, two nodes, global DP8/local DP4/TP4 |
| A3 PD | Same W8A8/C8-MTP checkpoint; Prefill PP2/TP16 with layers 41/37, Decode DP8/TP4 with four local ranks per node |
| 950DT PD | MXFP4/FP8-KV; two independent TP8 Prefill services, Decode DP16/TP1 with eight local ranks per node |

A3 Prefill runs Bash directly; Decode uses its eight-argument launcher including PP size. All four 950DT nodes use a separate seven-argument launcher. Docker images/device maps/mounts and proxy ports are hardware-specific. These are fixed configurations, not support claims for arbitrary precision/topology combinations.

The Guide records migration differences: nested configuration keys/checkpoint-path corrections, unique engine IDs, string RPC-port arguments/defaults and child-failure propagation; the A3 publisher single-node option-name mapping; and normalizing both 950DT Decode contexts to 135,000 tokens to match Prefill. W8A8C8 describes W8A8 weights plus cache quantization; published checkpoint identifiers are preserved.

**Duplication check:** searched open vllm PRs for GLM-5.1/GLM recipe and Ascend recipe work; no open PR addressing this recipe migration was found. recipes #1040 is related single-node work in the renderer repository, while this PR uses the current owning source repository and includes the fixed PD/colocated configurations. No tracking issue was supplied. No core runtime, CI configuration, generated API files or research records are changed.
