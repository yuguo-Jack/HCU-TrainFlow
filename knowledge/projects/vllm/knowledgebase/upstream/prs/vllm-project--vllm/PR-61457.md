# [Quantization] Enable per-layer fused shared expert selection

[Upstream PR](https://github.com/vllm-project/vllm/pull/61457) · state: open · merged: False

## Original PR description

## Disclosure

AI assistance was used. The changes were reviewed and tested manually.

## Overview

Allow compatible layers to use AITER fused shared experts (FSE) while other layers retain higher-precision shared experts.

Current vLLM rejects the entire model in case FSE can't be enabled for all layers, and various places assume all-or-nothing selection.

**Motivation: certain layers are less sensitive to MXFP4 shared expert quantization than others, and fusion can be enabled for them.**

## Claims

- Enable per-layer FSE through the existing `resolve_layer_fused_shared_expert` API for models migrated to layer-scoped checkpoint loading.
- Redirect checkpoint weights only for layers that allocated fused shared-expert slots; preserve separate MXFP8 shared experts alongside MXFP4 routed experts.
- Explicitly reject mixed FSE with EPLB, whose expert-weight handling assumes uniform row counts across layers.

Limitations:

- Mixed FSE with EPLB is unsupported.
- Routed and shared experts must have compatible quantization within each fused layer; heterogeneous precision inside one fused GEMM is unsupported.
- Fused layers must share routing-buffer geometry; Mori remains unsupported with FSE requested.
- Forward execution, graph replay, model evaluations, and performance are not validated; Qwen4 Exp lacks full FSE initialization/loading coverage.

## Validation

- `pytest tests/model_executor/layers/test_fused_shared_expert.py -k test_models_fse_init -s -vvvvv`
- `python -m pytest tests/model_executor/layers/test_fused_shared_expert.py tests/models/qwen4_exp/test_config.py -s -vvvvv`

## Compatibility changes

- Compared with `main`, migrated models accept mixed fusion eligibility with EPLB off, retaining incompatible shared experts separately at their configured precision.
- Internal breaking changes: `maybe_fuse_shared_experts()` requires a `fused_shared_expert_layers` collection instead of the optional `enabled` boolean/environment fallback; migrated model-wide FSE booleans become layer lists; `FusedMoEConfig.aiter_fmoe_shared_expert_enabled` becomes `is_fused_shared_expert_requested`.

## Related work

- This addresses per-layer policy, not the ModelOpt MXFP8 compatibility support in https://github.com/vllm-project/vllm/pull/57916; the duplicate-work search found no open PR implementing this same policy migration.
