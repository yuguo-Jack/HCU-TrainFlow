# [Perf][HiSparse] Segment host KV pool backing files

[Upstream PR](https://github.com/vllm-project/vllm/pull/61680) · state: open · merged: False

## Original PR description

HiSparse stores its host KV pool as one logical chunk. The segmented backing support in merged #59546 splits whole rows, so this pool still uses one `/dev/shm` file, where page-cache insertion limits parallel pre-faulting.

Split the single chunk at 2 MiB boundaries and enable up to 32 backing files for HiSparse. The mapping stays contiguous; capacity and CUDA registration ranges stay unchanged. This is the HiSparse follow-up to #59546; the landed prerequisite is no longer part of this PR's diff.

Previously measured on two nodes with 8 H100 workers and a 1 TiB pool each: RAM preparation fell from **264.5 / 232.3 s to 44.5 / 44.4 s**. Preparation plus pinning fell from **378.1 / 340.6 s to 152.3 / 146.8 s**. These benchmarks were not rerun for the merge update.

Validation after merging current main:

- `.venv/bin/python -m pytest tests/v1/kv_offload/cpu/test_shared_offload_region.py tests/v1/kv_offload/test_factory.py tests/v1/worker/test_utils.py -q --tb=short`: 161 passed, 2 skipped. In the CPU-only validation pod, 5 GPU-dependent cases failed because no NVIDIA driver was available, and 3 errored during device detection. The previous GPU validation before this merge update passed all 171 tests.
