# [Perf][HiSparse] Segment host KV pool backing files

[Upstream PR](https://github.com/vllm-project/vllm/pull/61680) · state: closed · merged: True

## Original PR description

HiSparse stores its host KV pool as one logical chunk. The segmented backing support in merged #59546 splits whole rows, so this pool still uses one `/dev/shm` file, where page-cache insertion limits parallel pre-faulting.

Split the single chunk at 2 MiB boundaries and use the shared 32-file limit (`REGION_SEGMENTS`). The mapping stays contiguous; capacity and CUDA registration ranges stay unchanged. Reserve virtual space with a sparse memfd mapping, which needs no writable temp directory and does not charge the full pool against the commit limit.

Previously measured on two nodes with 8 H100 workers and a 1 TiB pool each: RAM preparation fell from **264.5 / 232.3 s to 44.5 / 44.4 s**. Preparation plus pinning fell from **378.1 / 340.6 s to 152.3 / 146.8 s**. These benchmarks were not rerun for this update.

## Tests

On 2× H100 80GB HBM3, using the post-merge build of merge base `8bad43e2c` with this PR's changes at `54547ea4d1`:

- `tests/v1/kv_offload/cpu/test_shared_offload_region.py tests/v1/kv_offload/test_factory.py`: 135 passed.
- `tests/v1/worker/test_utils.py -k 'host_pool or registration'`: 7 passed.
- The segmented-region test fails on the previous revision when no temp directory is usable (`FileNotFoundError` from `tempfile`) and passes with the memfd reservation. It also checks that the reservation is not commit-accounted.
- Two ranks, one per GPU, sharing an 8 GiB single-chunk pool split into 8 files with real barriers and `cudaHostRegister`: segments are 2 MiB-aligned, no reservation mapping remains, GPU writes across segment boundaries are visible to the peer, and full-pool H2D runs at ~44 GB/s per GPU.
- Pre-commit passed; mypy checked with `--platform linux`.
