# [ROCm][Perf] Kimi-K3: token-sharded residual stream for long prefills

[Upstream PR](https://github.com/vllm-project/vllm/pull/59693) · state: open · merged: False

## Original PR description

### Purpose

**Scope: ROCm only, Kimi-K3 only, opt-in.** All model changes are in
`vllm/models/kimi_k3/amd/`, which is only loaded on ROCm, and the new path only
runs for Kimi-K3's attention-residual layers. It is off by default
(`VLLM_KIMI_K3_AMD_PREFILL_SP_MIN_TOKENS=0`). NVIDIA, other models and
CUDA-graph decode are unaffected.

With TP, every rank repeats the same per-token work (attention-residual mixing,
MoE router, latent down-projection, top-k) on all tokens. For eager steps with
at least `VLLM_KIMI_K3_AMD_PREFILL_SP_MIN_TOKENS` tokens (1024 recommended),
this PR shards the residual stream over tokens instead, padded to a multiple of
TP:

- Each block output all-reduce becomes a reduce-scatter plus an all-gather
before the next block, so communication volume is unchanged.
- Attention-residual mixing, the router and top-k run on the local shard only.
- The routed latent is reduce-scattered (half the bytes of an all-reduce).

It is off with PP, during graph capture, and when aux hidden states are
requested (EAGLE drafters).

The NVIDIA Kimi-K3 path has something similar (`use_sequence_parallel` in
`nvidia/model.py`), but it only turns on with expert parallelism plus DP > 1
or DeepGEMM MegaMoE, for every step. This PR covers plain TP on ROCm, and only
for long prefill steps.

### Test Plan

- New `tests/models/kimi_k3/test_amd_prefill_sp.py`: the sharded MoE tail
matches the replicated result (TP4/TP8), the routing all-gather is bit-exact,
padded gather/scatter round-trips, plus the enable conditions.
- Existing Kimi-K3 AMD tests still pass (37 total).
- End to end: 8x MI355X, Kimi-K3 MXFP4, TP8, `vllm/vllm-openai-rocm:nightly`
with and without `VLLM_KIMI_K3_AMD_PREFILL_SP_MIN_TOKENS=1024`,
`vllm bench serve`, random data, 1K output tokens.



### Test Result

Δ vs stock nightly; throughput is (input + output) tok/s/GPU.


| Input | Conc. | Throughput | TTFT          |
| ----- | ----- | ---------- | ------------- |
| 1K    | 8     | -0.1%      | +1.5% (noise) |
| 10K   | 32    | +5.7%      | -14.1%        |
| 50K   | 32    | +11.1%     | -14.6%        |
| 100K  | 8     | +7.4%      | -11.1%        |
| 200K  | 8     | +9.3%      | -10.7%        |


Geomean +6.1% over 8 points; 1K is within run-to-run noise.

Accuracy matches stock: GSM8K 5-shot 0.989 vs 0.982 (mean of 3 runs), passkey
retrieval up to 190K 0.95-1.00 vs 0.95, and first-token top-1 agreement 20/20
on real-text prompts from 2K to 190K.
