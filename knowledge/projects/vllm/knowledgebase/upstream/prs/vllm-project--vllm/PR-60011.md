# [Distributed] Make --disable-custom-all-reduce fall back to NCCL

[Upstream PR](https://github.com/vllm-project/vllm/pull/60011) · state: open · merged: False

## Original PR description



## Overview

Fixes #59987. `--disable-custom-all-reduce` is documented as "Disable the custom all-reduce kernel and fall back to NCCL", but on Hopper and Blackwell it only removes the `CUSTOM` backend. The TP group keeps the FlashInfer and symmetric-memory all-reduce, and at the default `-O2` the FlashInfer all-reduce + RMSNorm fusion stays on. This PR makes the flag turn those off too, so all-reduce falls back to NCCL.

## Claims

- With `--disable-custom-all-reduce`, the TP group's all-reduce backends are `['PYNCCL']` and the all-reduce + RMSNorm fusion is off (an explicit `pass_config.fuse_allreduce_rms=True` still turns it on).
- Without the flag nothing changes.
- GSM8K accuracy is the same with and without the change.

## Validation

2x H100 SXM (NV18), `vllm/vllm-openai:nightly-18f8f96025b556071eb627076f94df560fbd3a22` with this PR's diff applied to the installed package (`18f8f9602` is 15 commits behind this PR's base and none of them touch the changed files), `Qwen/Qwen2.5-1.5B-Instruct`, TP=2, default `-O2`:

| | All-reduce backends (startup log) | `allreduce_rms` fusion | All-reduce kernels in one 32-token request, per rank (torch profiler) | GSM8K, 1319 questions, 5-shot |
|---|---|---|---|---|
| main + `--disable-custom-all-reduce` | `['FLASHINFER', 'PYNCCL']` | on | 1824 FlashInfer `allreduce_fusion_kernel_oneshot_lamport`, 0 NCCL all-reduce | 0.540 |
| this PR + `--disable-custom-all-reduce` | `['PYNCCL']` | off | 1824 `ncclDevKernel_AllReduce_Sum_bf16_RING_LL` | 0.542 |
| this PR, no flag | `['FLASHINFER', 'CUSTOM', 'PYNCCL']` | on | 1824 FlashInfer `allreduce_fusion_kernel_oneshot_lamport` | 0.540 |
| this PR + flag + `-cc.pass_config.fuse_allreduce_rms=True` | `['PYNCCL']` | on | 1824 FlashInfer `allreduce_fusion_kernel_oneshot_lamport` | - |

1824 is 57 all-reduces per forward pass (the embedding plus two per layer, 28 layers) times 32 forward passes, so on main with the flag every all-reduce in the model ran in FlashInfer and none in NCCL. The greedy completion of the profiled request was the same in all four runs.

`SYMM_MEM` is missing from these lists because multicast does not work on this host: `SymmMemCommunicator` logs "symmetric memory multicast operations are not supported" after the CUDA driver returns error 401, the same error that made NCCL's NVLS setup fail in `ncclCommInitRank`, so all four runs used `NCCL_NVLS_ENABLE=0`. On the host in #59987 (2x H100, vLLM 0.30.0) the default list was `['FLASHINFER', 'CUSTOM', 'SYMM_MEM', 'PYNCCL']` and the flag left `['FLASHINFER', 'SYMM_MEM', 'PYNCCL']`. The unit test below covers the symmetric-memory gate.

## Details

The flag only reaches `_ENABLE_CUSTOM_ALL_REDUCE`, which gates `CustomAllreduce`, and on ROCm also AITER and QuickReduce all-reduce. FlashInfer all-reduce (on by default since #52998) and symmetric-memory all-reduce were added later with their own env vars and never tied to the flag. The fusion default, `enable_allreduce_rms_fusion`, doesn't look at it either. So on SM 9.0 / 10.x the flag leaves most all-reduces on FlashInfer: at `-O2` the ones followed by RMSNorm run inside the fused kernel, and the rest go through `['FLASHINFER', 'SYMM_MEM', 'PYNCCL']`.

The change:

- `CudaCommunicator`: FlashInfer, FlashInfer PCIe IPC and symmetric-memory all-reduce also require `_ENABLE_CUSTOM_ALL_REDUCE`, the way AITER and QuickReduce already do.
- `enable_allreduce_rms_fusion` returns False when the flag is set. This only changes the default; an explicit `fuse_allreduce_rms` still wins.
- The flag's docstring (also the `--help` text) and `docs/design/fusions.md` now say what it turns off.

Things to be aware of:

- Anyone who sets the flag today and is getting FlashInfer or symmetric-memory all-reduce will get NCCL instead, which is what the flag says it does. There is no longer a way to turn off only vLLM's custom kernel and keep FlashInfer; if that combination is needed, an env var for the custom kernel (like the existing `VLLM_ALLREDUCE_USE_*` ones) would be the natural counterpart.
- Not covered: some models call FlashInfer's fused all-reduce directly in their eager paths through `_can_use_flashinfer` in `fused_allreduce_gemma_rms_norm.py` (DeepSeek V3.2, Kimi K3, MiniMax M3). I left those out to keep this PR small and can gate them in a follow-up if you want.
- Tests that pass the flag (the tensorizer tests, Whisper) now run on NCCL. The fusion e2e and full-graph test helpers also set it by default, but their only TP=2 tests, in `test_tp2_ar_rms.py`, set it to `False`.
- A correction to the issue: it said the flag plus `VLLM_ALLREDUCE_USE_FLASHINFER=0 VLLM_ALLREDUCE_USE_SYMM_MEM=0` gives NCCL only. At `-O2` the fusion also has to be off (`-cc.pass_config.fuse_allreduce_rms=False`).
