# [Bugfix][Frontend] Stop API workers and coordinator on parent loss

[Upstream PR](https://github.com/vllm-project/vllm/pull/65506) · state: open · merged: False

## Original PR description

## Overview

Stop Python API workers and the DP coordinator when their launcher dies, so
an API-only head node cannot leave an old HTTP endpoint running. Addresses
the API-only lifecycle case in #65096
([scope note](https://github.com/vllm-project/vllm/issues/65096#issuecomment-6615887947)).

## Claims

- Locally owned API/coordinator processes detect loss of their original parent,
  request normal SIGTERM cleanup, then bound a stuck shutdown with self-exit.
- The parent PID is captured before spawning, covering loss before initialization.
- Separately owned engines are not terminated by the frontend's owner-loss handler.
- EngineCore supervision and startup-handshake deadlines are unchanged.

## Validation

Baseline process tests failed in all four requested start-method/SIGTERM cases:
`API worker/coordinator outlived their launcher`. A real API-only deployment
with tiny Llama weights also kept returning the configured model from
`/v1/models` after launcher SIGKILL. The patched standalone probe exited all
API-side processes while its separate headless launcher and engines stayed alive.

Final results: **16 process-manager tests and 1 real-server lifecycle test pass**.
The new real-server regression fails on base `37753d9` with four surviving
API-side processes, then passes with the patch, including port rebind and
separate-engine survival. All applicable pre-commit hooks pass, including Ruff,
mypy, Markdown and CI test-wiring checks.

```bash
export VLLM_TARGET_DEVICE=cpu VLLM_PLUGINS=''
export CPU_VISIBLE_MEMORY_NODES=0,0 VLLM_CPU_OMP_THREADS_BIND='0-1|2-3'

.venv/bin/python -m pytest -v -s tests/v1/distributed/test_api_only_parent_death.py
```

Run on Linux/WSL using the official vLLM 0.33.0 CPU runtime with the tested public
source revision. WSL forces coordinator `fork` requests to `spawn`; separate
direct-fork probes passed for normal/ignored SIGTERM and parent loss before
helper entry. Native fork/spawn constructor coverage is selected in CI.

Validation reaches real model loading, HTTP metadata, process/thread exit and
listener release. An attempted CPU completion on baseline timed out before
crash injection, so no generation, GPU-memory or throughput claim is made.

## Details

The launcher monitors children, but its SIGKILL bypasses the parent-side
finalizers. Give the two frontend-owned process types a private wrapper that
observes their original parent, without changing request processing.

#55846 and #40935 cover EngineCore parent death. Their API cleanup depends on
EngineCore notifying clients. An API-only head node has no local EngineCore;
its remote engines' launcher is still alive, so that mechanism cannot fire.
#44751 covers the separate startup-deadline problem. #63025/#58278 change
listener setup/ownership, not parent-death supervision. This patch covers
direct frontend ownership independently of those changes.

The dedicated real-server regression runs separately from existing
module-scoped server fixtures, uses isolated ports, and is selected by the
existing distributed DP CI jobs. Process-manager tests also cover a worker
that ignores SIGTERM. Documentation describes the API-only ownership boundary.
Developed with AI assistance.
