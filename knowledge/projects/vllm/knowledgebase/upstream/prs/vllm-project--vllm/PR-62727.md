# [Bugfix][Frontend] Honor X-Vllm-Priority in batch chat completions

[Upstream PR](https://github.com/vllm-project/vllm/pull/62727) · state: open · merged: False

## Original PR description



## Overview

`/v1/chat/completions/batch` ignores the `X-Vllm-Priority` header. The docs say the header "overrides the `priority` value in the JSON request body" for Chat Completions, and `/v1/chat/completions` does this through `_get_priority()`. The batch endpoint passes `request.priority` straight to the engine, so a router that sets priority by header loses it on every batch request. This PR makes the batch endpoint use `_get_priority()` as well.

## Claims

- With `X-Vllm-Priority: -10`, every conversation in a batch request now goes to the engine with priority -10, as on `/v1/chat/completions`.
- Without the header, or with a header that is not an integer, the body priority is used, as before.

## Validation

- New test `test_batched_priority_header_matches_single_chat`, parametrized over no header, `-10` and `not-an-int`. It sends the same request with body priority -3 to `/v1/chat/completions` and to the batch endpoint, and checks that the batch endpoint passes the same priority to the engine for each conversation. The `-10` case fails on main, where the batch endpoint passes -3.
- `pytest tests/entrypoints/openai/chat_completion/test_batched_chat_completions.py`: 9 passed on this branch. On main the new `-10` case fails and the other 8 pass. On both, the 5 tests that start a server error in my environment because they need a model download.
- `pre-commit run --files` on the changed files passes.

## Details

The fix is the one-line change in `batch_serving.py`. It passes `single_request` because `_get_priority()` takes a `ChatCompletionRequest`; each `single_request` carries the batch body's priority, which the no-header test case checks. The call sits in the per-conversation loop next to `_get_session_id(single_request, raw_request)`, which reads its header the same way. The new test builds both servers the same way as `test_batched_reasoning_wiring_matches_single_chat`, so I moved that setup into a shared `_build_chat_serving()` helper instead of copying it. Without a reasoning parser the helper passes the classes' own defaults (`""` to the serving class, `None` to `OnlineRenderer`).
