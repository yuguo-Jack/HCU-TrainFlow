# [Feature] Support DCP for Gemma 4 sliding-window/full-attention hybrids

[Upstream PR](https://github.com/vllm-project/vllm/pull/61502) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Enables DCP for GQA models that mix sliding-window and full-attention layers, such as Gemma 4. Only full-attention layers are DCP-sharded; sliding-window layers keep their window-bounded KV replicated and attend without the LSE combine.

## Claims

- Gemma 4 31B runs at `-tp 8 -dcp 2`. `main` rejects it because the GQA check counts the sliding layers' 16 KV heads.
- +42.8% KV cache capacity, accuracy unchanged.
- The V1 runner and a disabled hybrid KV cache manager fail at startup.

## Validation

8x H100, `RedHatAI/gemma-4-31B-it-FP8-block`, `-tp 8 --max-model-len 131072`, default MRV2. Needle: 6-digit code at depths 0.1/0.5/0.9 of ~7.5k/~31k/~98.5k token prompts. gsm8k: 5-shot, chat template.

| Config | KV tokens | Needle | gsm8k flex / strict |
|---|---|---|---|
| `main`, DCP=2 | rejected | | |
| DCP=1 | 2,016,290 | 9/9 | 95.68 / 95.91 |
| DCP=2 | **2,878,995** | 9/9 | 95.53 / 95.75 |
| DCP=2, `--enforce-eager` | 2,910,825 | 9/9 | 95.68 / 95.83 |

gsm8k stderr ±0.6. `main` fails with `Decode context parallelism for GQA/MQA requires --tensor-parallel-size (8) to be greater than the model's total number of KV heads (16)`. `VLLM_USE_V2_MODEL_RUNNER=0` and `--disable-hybrid-kv-cache-manager` both fail with `Decode context parallelism with sliding-window attention requires Model Runner V2 and the hybrid KV cache manager.`

```bash
vllm serve RedHatAI/gemma-4-31B-it-FP8-block -tp 8 -dcp 2 --max-model-len 131072
pytest tests/config/test_model_arch_config.py tests/test_config.py tests/v1/worker/test_cp_utils.py
```

## Details

The KV cache manager already supports replicated groups through `KVCacheSpec.dcp_sharded` (#56723, replicated drafts). This PR uses it for sliding-window layers.

- `Attention`: a sliding-window layer under DCP sets `dcp_sharded = False` and calls the new `AttentionImplBase.disable_dcp()`, which resets DCP/PCP size and rank and turns off LSE return for every impl variant (covers composite backends). Raises unless MRV2 and the hybrid KV cache manager are enabled.
- MRV2 `get_kv_cache_spec`: applies the layer's `dcp_sharded` to its KV spec, including subclasses that build their own spec.
- `ModelConfig`: the GQA DCP checks skip layers that `layer_types` marks `sliding_attention` (unless the window is disabled). Models without `layer_types` are checked across all layers, as on `main`.
- `check_attention_cp_compatibility`: the LSE assert only applies to sharded  layers.
- Docs: Gemma 4 example in `docs/serving/context_parallel_deployment.md`.

**Limitations.**
- Backend selection still passes `use_dcp=True` for sliding layers, so a backend without DCP support is rejected for them.
- The MRV2/HMA requirement is checked at model init, not config time.
- Only Gemma 4 is validated end-to-end; Gemma 3 27B and GPT-OSS cannot meet TP > KV heads on one 8-GPU node.

Related: #47541 (same idea for FlashInfer MLA only), #40996 (DCP for Mamba hybrids).
