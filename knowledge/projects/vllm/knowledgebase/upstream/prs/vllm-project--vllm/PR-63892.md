# [ROCm][Perf][DSv4.1] Mono: batch TP4 K2's X8 copies, load its push's peer bases late

[Upstream PR](https://github.com/vllm-project/vllm/pull/63892) · state: closed · merged: True

## Original PR description

## Overview

This PR makes two register-pressure fixes in the DeepSeek-V4.1 mono decode K2 (`--monokernel`) at TP4 on MI355X (gfx950), for both the target and the DSpark draft. It is bit-exact and adds no env var. The code change is +16/-1 lines in 2 files, plus one compile-only test, on main e5196e2959. It builds on #60397 and overlaps #63027 (TP2).

## Claims

- **Step time (measured on main):** c1 -51 us (-0.9%), c2 -235 us (-3.5%), TP4 with DSpark k=6, over 4 ABBA rounds. At both, every PR server ran faster than every main server. The profiler puts the saving in K2 (target and draft); K1 is unchanged.
- **Bit-exact (measured):** per-rank output hashes of K1, K2 and the FFN launch equal main's at 257 TP4 configs (every width from 1 to 48, ratios 0/1/2, index sources, the DSpark draft). GSM8K-1319 is within one pass's standard error of main's, and acceptance length does not move (main 3.576, this PR 3.579, at 2 requests in flight).
- **Compile-level (measured):** at 1-16 rows the target TP4 K2 uses 230-248 VGPRs (main: 246-256) and the draft's 161-181 (main: 166-207); neither spills. On main, 14-16 rows spill, and 13 rows at an index source. Serial X8 copy chains drop from 23-25 to 3-4. Past 16 rows only the base loads move in the source, and no width spills on either tree. TP2, TP8, every K1, the FFN launch and gfx942 are binary-identical to main's.

## Details

**Root cause.**
1. *X8 copies.* At one token tile (up to 16 rows, covering c1 and c2 at k=6), `load_x8_rows` issues one 16-byte load per branch. Each load waits (`s_waitcnt vmcnt(0)`) before its LDS store. With this PR it issues every load first, then the masked stores. The row count is a Python int on these paths.
2. *Peer bases.* K2 loads the four peer bases at its start (`peer_bases`, #60397) and holds them to the MoE all-reduce push. At 14-16 rows (13 at an index source) K2 spills 2-4 VGPRs. At 14 and 16 rows the push reloads the bases: each reload is followed by `s_waitcnt vmcnt(0)` (4 between peer stores), which on gfx950 also waits for earlier system-scope stores, so each peer's push waits for the previous ones. At 15 rows and the 13-row index source, 2 VGPRs spill with no wait between peer stores. `stage_down` now loads the bases right before its barrier, and they still land before the first push.

**Gate.** `build_mono_k2` passes a `push_bases` callable to `run_ffn`, which puts it in the MoE context only at `tp == 4`. That one entry enables both halves. `load_x8_rows` takes the batched path only when it is set, not on gfx942, and only when the row count is a Python int (one token tile). `stage_down` rebinds `peer_addr` to the bases it loads late; gfx942 returns through `stage_down_942` before that line. The FFN launch and K1 never get the entry. TP2 is excluded: its K2 does not spill on main (70 builds, including ratio 2 at every width from 1 to 48), neither half was measured at TP2, and #63027 tunes TP2 ratio 2 with its own batched copy. TP8 is #64153.

**Tradeoffs and limitations.**
- SGPR lane spills: at 7 rows (the c1 width), target builds go 103 → 174 `v_writelane` (32 in loops, main 0) and index sources 93-105 → 68. At 14 rows (c2), target builds go 75-79 → 82 and index sources 85 → 78, none in loops. Across target and index-source builds, loop-resident `v_writelane` rises on 21 of 88 at 1-16 rows (falls on none) and on 15 of 162 past 16 rows (falls on 100). The c1, c2 and c4 measurements include these builds.
- The DSpark draft K2 at 5 rows (not a k=6 width) goes 166 → 180 VGPR, the only build at 1-16 rows that uses more VGPRs; its `v_writelane` falls 219 → 63. Past 16 rows the draft gains 1 VGPR at 16 widths, without VGPR spills, and its loop-resident `v_writelane` rises at 17 of 32 widths (0 → 8-72, including the k=6 widths 36 and 42) and falls at 1. Target builds past 16 rows never use more VGPRs.
- The FFN launch keeps main's 16-row spill (256 VGPR, 2 spilled; 4 with the draft's dims). It serves only fallback layers.
- No pytest launches K2 at 9-16 rows. The hash check covers those widths, and c2 runs 14 rows.
- The ISA test uses FlyDSL privates and MiniMax-M3's `code_object` (as M3's ISA test does), and skips without `llvm-objdump` on PATH (the nightly ROCm image has it). It guards only the late base load.
- The DSv4-Pro copy (`deepseek_v4/amd/mono`, #61482) has its own `load_x8_rows` and `peer_bases`. It is not changed or checked here.

**Related.**
- **#63027** (TP2 tuned K1/K2) batches the same copies in its tuned builds (`load_x8_rows_all`, gated on `tuned`) and moves `stage_down`'s barrier into a new `down_sums`. Whichever lands second keeps one batched path, enabled by `tuned` or `push_bases`, and puts the base rebind before `down_sums`' barrier.
- **#64153** (draft) applies the same two fixes at TP8. It is stacked on this PR's previous head (92852abd06) and needs a rebase onto this version.
- **#63486** (draft) moves the test file. If it lands first, this PR's test follows it.
- **#61934** (closed, "No e2e gain observed") issued the FFN seam's static loads before their polls. Those are different loads from this PR's.
