# [Bugfix][Frontend] Preserve token IDs in completion derender responses

[Upstream PR](https://github.com/vllm-project/vllm/pull/62114) · state: closed · merged: True

## Original PR description



## Overview

Preserve requested generated token IDs in batch and streaming completion derender responses, following the chat fix in #61065.

## Claims

- Both completion derender modes forward each input choice's generated `token_ids` when `completion_request.return_token_ids=true`.
- Null/false flags retain null ID fields; decoding, usage accounting and stream state are unchanged.
- Prompt-ID metadata, echo parity and stop/logprob behavior are out of scope.

## Details

The completion derender methods receive the original `CompletionRequest` but omit generated IDs when constructing both batch and stream choices. Resolve the opt-in flag before each loop and forward the original choice IDs, matching the existing chat behavior without changing detokenization.

Fresh open-PR searches for `61065 in:body`, `derender token_ids`, and `completion return_token_ids`, plus inspection of related changes, found no exact competing fix. #59510 handles stops, #60082 adds inline derender mode, #57990 preserves prompt logprobs; merged #60286 handles the separate Rust completions route. This patch is independent of request-body logging PR #62108 and changes different files.

AI assistance was used for investigation, implementation, tests and review. The submitter additionally confirmed personally running related tests before requesting publication; the reported automated results above are from the agent-executed commands.
