# [Bugfix][Frontend] Preserve multimodal inputs in /v1/systemone prefix warmup

[Upstream PR](https://github.com/vllm-project/vllm/pull/63543) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fix shared-prefix warmup across questions in an image-bearing `/v1/systemone` request on hybrid models. The token-only warmup from #61192 loses the multimodal metadata required for prefix reuse, including on the image path added in #62181.

## Claims

- Avoid redundant prefill by preserving the warmup's multimodal inputs.
- Leave text-only and single-question behavior unchanged; skip warmup if any image falls outside the shared prefix.

## Validation

LiquidAI/d1-3B on NVIDIA GB10, BF16, base `5f63ea461c`, with the settings below. Each case has 8 measured requests per version after 2 warmups, interleaved in randomized order. Latency is p50 [min–max] in milliseconds.

| Workload | Before | After | Computed prefill tokens, before → after |
| --- | ---: | ---: | ---: |
| Street photo, 2 questions, cold KV + encoder | 666.3 [663.6–673.1] | 421.6 [418.6–425.1] | 5471 → 1887 |
| Two images, 2 questions, cold KV + encoder | 757.9 [754.6–762.2] | 476.0 [449.3–481.2] | 6245 → 2149 |
| Street photo, 6 questions, warm prefix | 171.1 [146.6–185.5] | 182.7 [157.2–189.5] | 60 → 60 |

Cold-cache runs reset prefix KV and vision encoder caches while keeping preprocessing and kernels warm. For one image and two questions, computed prefill fell 65.5% and p50 latency fell 36.7%; warm-prefix requests showed no consistent latency gain. The two-image case used the same photo plus a pigeon crop.

- 272 timed requests produced 352 matching paired answers with unchanged token usage; the largest probability difference was 0.00221. This validates the tested workloads, not overall model quality.
- Text-only, single-question, image/order/salt isolation, and prefix-cache-disabled controls passed.
- `pytest tests/entrypoints/generate/structured_decisions/test_strategies.py -q`: 83 passed. The frontend fake-engine regression test and pre-commit/mypy checks passed; d1-3B real-serving validation confirmed the fix.

<summary>How to reproduce</summary>

Run on the base revision and with this patch:

```bash
VLLM_SERVER_DEV_MODE=1 vllm serve LiquidAI/d1-3B \
  --port 18250 --served-model-name d1-3B \
  --max-model-len 4096 --max-num-seqs 8 --max-num-batched-tokens 4096 \
  --gpu-memory-utilization 0.2 \
  --enforce-eager --attention-backend TRITON_ATTN --enable-prefix-caching \
  --generation-config vllm --limit-mm-per-prompt '{"image":2}'
```

Use `tests/v1/ec_connector/integration/hato.jpg`, resized to fit within 1024×1024 and encoded as a PNG data URL. Send this request to `POST /v1/systemone`:

```json
{
  "model": "d1-3B",
  "state": "Inspect the attached street photograph.",
  "images": ["<PNG data URL>"],
  "questions": {
    "animal": {
      "type": "choice",
      "instructions": "What type of animal is in the foreground?",
      "criteria": {"bird": null, "cat": null}
    },
    "location": {
      "type": "choice",
      "instructions": "Is this scene indoors or outdoors?",
      "criteria": {"outdoors": null, "indoors": null}
    }
  }
}
```

On an otherwise idle server, before each measured request:

1. Call `POST /reset_prefix_cache` and confirm `{"success": true}`, then call `POST /reset_mm_cache` and `POST /reset_encoder_cache`. This resets both KV and vision encoder caches for the cold-cache measurements; resetting only the prefix cache does not reproduce the same latency conditions.
2. Record `vllm:request_success_total` and `vllm:request_prefill_kv_computed_tokens_sum` from `GET /metrics`, summing across labels. Send the request, then poll the metrics until the success counter increases by 3 (one warmup and two question reads).
3. Compare the prefill counter increase, not its cumulative value. In the measured setup it falls from 5471 before the fix to 1887 after, while the response reports `usage.input_tokens = 3666` in both versions.

</details>

## Details

Each question is rendered with the same images before its text. Cache hashes include image identifiers and placeholder offsets. Preserve these fields and the image data when shortening the first rendered input, and discard its full prompt text. Skip warmup if it would truncate an image. Question reads and core cache logic are unchanged.

No overlapping open fix was found; #61251 addresses tokenization and scheduling instead. AI assistance was used.
