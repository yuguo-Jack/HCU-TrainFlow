# [Bugfix] Fix hetero TP handshake assertion for GQA-replicated KV heads

[Upstream PR](https://github.com/vllm-project/vllm/pull/45860) · state: closed · merged: False

## Original PR description

Signed-off-by:  Kannak Sharma




## Purpose

Fix NIXL handshake assertion failure during heterogeneous TP when `tp_size > num_kv_heads`.

When GQA replication caps the per-rank KV head count at 1 (because `tp > num_kv_heads`), `block_len` stops scaling linearly with `tp_ratio`. The handshake validation incorrectly used raw `tp_ratio` to compute expected remote `block_len`, causing `AssertionError` for valid configurations (e.g., tp8→tp16 with 8 KV heads).

**Fix**: Use actual per-rank head ratio (`remote_heads / local_heads`) instead of `tp_ratio`. This degenerates to `tp_ratio` when neither side is capped, maintaining backward compatibility.

**Affected models**: Any with few KV heads at high TP:
- Llama-3.2-1B / Llama-3.3-70B: 8 KV heads (fails at TP > 8)
- Qwen3-MoE-235B: 4 KV heads (fails at TP > 4)
- TinyLlama-1.1B: 4 KV heads (fails at TP > 4)

Fixes: https://github.com/vllm-project/vllm/issues/45330

## Test Plan

## Test Result

Unit test test_handshake_gqa_replicated_hetero_tp added and passes. Validates that D_TP=16, P_TP=8 with 8 KV heads correctly computes remote_heads/local_heads = 1 (both capped at 1 head/
rank) instead of using tp_ratio = 2.

E2E verified on 8×A100-40GB:
- Model: TinyLlama-1.1B (4 KV heads), Prefill TP=2 → Decode TP=8
- Disaggregated via NIXL + toy_proxy_server.py
- Without fix: AssertionError: Remote P worker KV layer cache must be of shape [2, N, local_kv_heads*tp_ratio, page_size, head_dim]
- With fix: coherent decode output through disaggregated pipeline ("The capital of France is Paris...")
