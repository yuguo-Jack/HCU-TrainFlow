# [Bugfix][Spec Decode] Fix out-of-bounds read in block-verification residual mass kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/59355) · state: closed · merged: False

## Original PR description

## Summary

> Commit: `fix/spec-decode-residual-mass-oob` (12 lines added, single file:
> `vllm/v1/worker/gpu/spec_decode/rejection_sampler_utils.py`)

`_compute_local_residual_mass_kernel` (block-verification path of the V1
rejection sampler) reads `draft_sampled[logit_idx + 1]` to detect the "-1
placeholder" end-of-block marker. For the **last** expanded logit
(`logit_idx == num_logits - 1`) this reads one element past the end of the
`[num_logits]` tensor. The OOB read executes on nearly every verification
step with adaptive verification; it is silently harmless unless the tensor
happens to end at an unmapped boundary of the caching-allocator segment, in
which case it raises `cudaErrorIllegalAddress` and kills the worker.

Guard the read with `tl.num_programs(0)` (grid dim 0 is exactly
`num_logits` at the only launch site) and store a defined `0.0` for the
unused last row, matching the existing placeholder semantics.

## Root cause

`vllm/v1/worker/gpu/spec_decode/rejection_sampler_utils.py:435` (v0.30.0):

```python
if tl.load(draft_sampled_ptr + logit_idx + 1) < 0:   # draft_sampled: [num_logits]
```

The two other `+ 1` accesses in this file (in `_compute_cumulative_log_p_kernel`
and `_rejection_kernel`) are bounded by the per-request `cu_num_logits` ranges;
this kernel uses a flat index over the whole batch and is the only unguarded one.

Why it surfaces rarely: with `enable_adaptive_verification` the globally-last
row is typically a mid-draft position (not the guarded first/bonus position),
so the OOB load runs almost every step — but the 4-byte read usually lands
inside the same mapped allocator segment. Higher concurrency shifts
allocation layouts and raises the probability that the tensor ends exactly at
an unmapped boundary.

## Evidence (CUDA core dump)

Reproduced with `CUDA_ENABLE_COREDUMP_ON_EXCEPTION=1` (+ skip-memory
generation flags). `cuda-gdb` on the dump:

```
CUDA Exception: Warp Illegal Address
kernel: _compute_local_residual_mass_kernel<<<(128,16,1),(128,1,1)>>>
focus: block (127,8,0)  <- x == num_logits - 1, the last expanded logit
```

grid dim 0 = `num_logits` of that step (128), dim 1 = vocab blocks
(131072 / 8192 = 16).

Repro environment: DeepSeek-V4.1-Flash, 8x H200 (SM90), vLLM 0.30.0,
flashinfer 0.6.18.post1, TP2 x DP4 + EP, dspark spec config
`{"method":"dspark","num_speculative_tokens":5,"draft_sample_method":"probabilistic","rejection_sample_method":"block","enable_adaptive_verification":true}`,
random workload (10000 in / 5000 out), `--max-concurrency 128`.

## Verification

Same deployment, same workload, only the patch differs:

| | before | after |
|---|---|---|
| runs @ conc=128 | 2/2 crashed (cudaErrorIllegalAddress) | 1/1 clean |
| completed requests | 131/320 (189 Internal Server Error) | 320/320, 0 failed |
| server-side ERROR lines | 355 | 0 |
| new core dumps | 1 (the evidence dump) | 0 |
| output throughput | 3972 (partial) | 4031.5 tok/s |
| mean spec acceptance length | 2.145 (n=23, run died early) | 2.399 (n=54) |

At concurrency 64 the OOB read is latent (7+ full runs without fault,
same code path) — the fix removes the OOB structurally, independent of
batch composition and allocator layout.

Output equivalence: the loaded value is only used for a `< 0` skip test;
the last row's residual mass is unused by `_rejection_kernel` (the
preceding token already ends the block), and the patch stores a defined
0.0 instead of leaving the row uninitialized, consistent with the
existing placeholder path.

  `cuda-gdb` on the dump shows `Warp Illegal Address` in
