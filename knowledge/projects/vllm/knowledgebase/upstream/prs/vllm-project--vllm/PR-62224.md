# [Bugfix][LoRA] Apply text-only LoRAs to the LM of multimodal wrappers

[Upstream PR](https://github.com/vllm-project/vllm/pull/62224) · state: closed · merged: True

## Original PR description



## Overview

Fixes #48019. A LoRA trained on the text-only `*ForCausalLM` of a multimodal model silently does nothing when served on the multimodal wrapper. This resolves such adapters on the model side, in `LoRAModelManager._get_lora_layer_weights`, so it works for every multimodal wrapper without per-model mapper rules.

This builds on #49525 by @fooSynaptic (co-author), which fixes the same bug through a `WeightsMapper` fallback and only covers wrappers whose mapper has a `model.language_model.` rule. This PR covers those wrappers too, plus the ones without such a rule.

## Claims

- Text-named adapters (`model.layers.*` / `lm_head`) now apply to the language model of multimodal wrappers, including wrappers with no `model.language_model.` mapper rule or a different LM prefix (`llm.`, `model.text_model.`), e.g. Llama4, DeepSeek-V4, MiniCPM-V, Idefics3/SmolVLM.
- Adapters that already match (trained on the full multimodal class), tower/connector LoRA, and text-only models are unchanged.

## Details

**Root cause.** PEFT on the text-only class (what `AutoModelForCausalLM.from_pretrained("Qwen/Qwen3.5-*")` returns in transformers 5.x, i.e. the default TRL SFT path) names modules `model.layers.*` / `lm_head`. vLLM's multimodal wrappers mount the language model under `language_model.`, `llm.` or `model.text_model.`. `activate_adapter` looks weights up by the full module name, finds none, and serves the base model; load-time validation only checks the leaf name (`q_proj`), so nothing fails.

**Fix.** When a LoRA module has no exact match and lives under `get_mm_mapping().language_model`, look it up by its text-only name: the remainder after the prefix, or the remainder under `model.` when the prefix holds a bare decoder. All lookups, including packed (`qkv_proj`, `gate_up_proj`) and MoE packing, go through this function; text-named entries consumed by packing are dropped like the other sub-module entries.

- Exact names always win, so adapters trained on the full multimodal class are unaffected. No tower/connector prefix of any in-tree LoRA-capable multimodal model is nested under its LM prefix, so tower/connector lookups are unchanged.
- The lookup is driven by the model's real modules, so there is no double-mapping risk (e.g. `model.language_model. -> model.` mappers) and no effect on layers owned by other PP ranks.
- No change to base-weight loading or to any model's `hf_to_vllm_mapper`.
- No new validation or error path, and no separate name-matching logic: the fallback lives inside the existing lookup, so any future "adapter matches nothing" check can reuse `_get_lora_layer_weights` and stay consistent with what is actually applied.
