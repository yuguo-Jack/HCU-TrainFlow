# [torch.compile] Fix outdated ModelConfig.compute_hash docstring for opt-out hashing

[Upstream PR](https://github.com/vllm-project/vllm/pull/62435) · state: open · merged: False

## Original PR description



## Overview

Fix the outdated `ModelConfig.compute_hash()` docstring, which still describes the pre-#26468 opt-in hashing pattern. This is the remaining gap for #39479 TODO 8 ("docstrings not up-to-date in the opt-out configs"): it complements #46714 (docstrings in the opt-in configs) and #60739 (`CacheConfig`), with no overlap — neither open PR touches `vllm/config/model.py`.

## Claims

- Rewrite the WARNING paragraph of `ModelConfig.compute_hash()` to the actual opt-out semantics: all dataclass fields are hashed by default; a new field only needs to be added to `ignored_factors` when it does NOT affect the computation graph.
- Docstring-only change; no behavior change.

## Validation

- Verified against the implementation: `get_hash_factors()` in `vllm/config/utils.py` hashes every dataclass field not present in `ignored_factors`, and `ModelConfig.compute_hash()` uses exactly this pattern (in contrast to the opt-in `factors.append(...)` pattern still used by other config classes, whose docstrings remain accurate).
- Duplicate-work check: `gh pr list --search "39479 in:body"`, `"compute_hash docstring"`, `"ignored_factors doc"` — no open PR modifies the `ModelConfig.compute_hash()` docstring.
- `pre-commit run --files vllm/config/model.py` — all hooks pass.

## Details

Root cause: #26468 migrated `ModelConfig.compute_hash()` to the opt-out `get_hash_factors(self, ignored_factors)` pattern, but the docstring's WARNING was left describing the old opt-in pattern ("ensure that it is included in the factors list if it affects the computation graph"). A contributor following the old text would believe new fields must be manually registered to affect the hash, when in fact every field is hashed by default — the only required action is the opposite one: excluding non-graph-affecting fields via `ignored_factors`.

AI assistance was used (Kimi Code); every changed line was reviewed and verified by the human submitter.
