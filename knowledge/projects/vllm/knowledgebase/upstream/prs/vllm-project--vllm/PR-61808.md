# [Bugfix] Fix OOB write in fused_recurrent_gated_delta_rule non-inplace final_state

[Upstream PR](https://github.com/vllm-project/vllm/pull/61808) · state: open · merged: False

## Original PR description

## Summary

Fixes #61800. Thank you @RoelsJonas for the detailed report, reproducer, and compute-sanitizer output.

`fused_recurrent_gated_delta_rule_fwd` allocated the non-inplace final state with `T` rows, but the kernel's non-inplace branch stores the recurrent state after every token at row `bos + i_t`, where `bos = i_n * T` for sequence `i_n` in `[0, N)` (`N = B` when `cu_seqlens is None`). Any fixed-length batch with `B > 1` therefore wrote up to row `N*T - 1` past the end of the `T`-row buffer — an out-of-bounds `__global__` write, as the reporter's compute-sanitizer output confirms.

The fix allocates `N * T` rows, matching the kernel's per-token write pattern. This also agrees with the initial-state load in the same kernel (`p_h0 = h0 + bos * HV * V * K`), which already assumes per-token rows across the batch (the reporter's `h0` has shape `(B*T, HV, V, K)`). In the variable-length path (`cu_seqlens` given), `N * T` rows likewise cover every `bos + i_t` write (the wrapper enforces `q.shape[0] == 1` with flattened inputs there). The in-place path and all kernel logic are untouched; for `B = 1` the allocation is byte-for-byte identical to before. All in-tree callers (`olmo_gdn_linear_attn.py`, `qwen_gdn_linear_attn.py`) pass `inplace_final_state=True`, so this branch is unreachable in vLLM itself — the fix only hardens the public op for out-of-tree users.

**Not a duplicate:** checked open PRs for `61800 in:body` and for `fused_recurrent final_state` — no open PR addresses this.

## Reproducer (adapted from @RoelsJonas's report; only the import path updated for current main)

```python
import torch
from vllm.third_party.flash_linear_attention.ops.fused_recurrent import fused_recurrent_gated_delta_rule

torch.manual_seed(0)
dev = "cuda"
B, T, H, HV, K, V = 2, 1, 1, 1, 16, 16
q = torch.randn(B, T, H, K, device=dev)
k = torch.nn.functional.normalize(torch.randn(B, T, H, K, device=dev), dim=-1)
v = torch.randn(B, T, HV, V, device=dev)
g = -torch.rand(B, T, HV, device=dev)
beta = torch.rand(B, T, HV, device=dev)
h0 = torch.randn(B * T, HV, V, K, device=dev)
o, final_state = fused_recurrent_gated_delta_rule(q, k, v, g, beta, scale=K ** -0.5, initial_state=h0,
                                                  inplace_final_state=False, use_qk_l2norm_in_kernel=True)
torch.cuda.synchronize()
```

**Before this fix** (verbatim from the issue report):

```
$ PYTORCH_NO_CUDA_MEMORY_CACHING=1 compute-sanitizer --tool memcheck python repro.py
========= Invalid __global__ write of size 16 bytes
=========     at fused_recurrent_gated_delta_rule_fwd_kernel ...
=========     ... bytes after the nearest allocation
```

**After this fix:** the buffer now has `N*T` rows, so the same script is expected to run with no sanitizer errors. I could not execute the GPU reproducer myself — my environment has no GPU (see test notes below) — so GPU verification relies on the reporter's reproducer and CI.

Results: old `T`-row allocation is out of bounds for `B > 1` non-varlen (max written row `N*T - 1 ≥ T`); new `N*T`-row allocation is in bounds in every case, and is identical to the old allocation for `B = 1`.
