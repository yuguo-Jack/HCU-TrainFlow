# [Rust Frontend] Refactor rust frontend for latest `llm-multimodal` v1.14 crate

[Upstream PR](https://github.com/vllm-project/vllm/pull/59854) · state: closed · merged: True

## Original PR description

Track the llm-multimodal vllm-dev-rebase line at `2409b856c4a9a7e050afb149919e0e92efb82d99` (crate v1.14.0). The dependency is now pinned to the pushed rev and the temporary `[patch]` section pointing at a local checkout is removed, as promised below. The branch carries the complete per-commit smg history (the v1.12.0-era base is unchanged and the upstream commits are preserved individually).

Latest repin (2409b856c) migrations and fixes:

- Nemotron-H Omni engine-kwargs parity: the crate emits the Python model's forward inputs (`pixel_values_flat` + `num_tokens_per_image` + `imgs_sizes`; raw frames + `video_num_patches` / `frames_indices` / `frame_duration_ms` for video; clip-padded audio features), and the vllm-side tests assert the new keys. `nano_nemotron_vl.py`'s dynamic-resolution branch accepts pre-packed `(N, 3*p*p)` patch rows (what the rust frontend ships) without re-stacking. `VideoClipOptions` now carries the clip's sampling info, passed through in the video path.
- MiniMax-M3 small-image parity: the crate's short-side floor is configurable via `extra["min_short_side_pixel"]`; the frontend disables it for MiniMax-M3 unless the preprocessor config sets it explicitly, matching Python (which only raises when `max_long_side_pixel` is set).
- Renderer/spec anchor alignment for a model family whose checkpoint template emits soft placeholder tokens after its content markers: the native renderer now emits them (previously image/audio requests failed expansion under the default renderer), and the Python executors accept the crate's shared per-item-count kwarg name as a fallback.

Earlier repin (dafcf935, smg@4721b709) — smg #4174, specs build config-bound vision processors:

- `VisionProcessorRegistry` is gone; `ModelProcessorSpec::vision_processor(model_config, preprocessor_config, modality)` builds the processor once with the modality's config resolved into it. vllm's `resolve_vision_processor` matches upstream vllm main's shape (`Arc<dyn VisionPreProcessor>`, `UnsupportedModality` → `None`). The local `models` module drops its parallel vision-processor table — the local Step3-VL and Muse Spark specs build their own processors like the crate's specs.
- The local Step3-VL / Muse Spark processors are config-bound at construction again (upstream vllm main's shape restored: `from_preprocessor_config` / `from_config`); trait methods no longer take `&PreProcessorConfig`. `calculate_num_tokens` returns `Result` (Muse Spark now propagates a refused size instead of 0).
- Image preprocessing calls `preprocess_with_context(&images, &context)` — the request token budget plumbing is unchanged. Video preprocessing passes the request-scoped `VideoClipOptions` (the clip's sampled rate and long-side cap) instead of the config; GLM's per-grid fallback timestamps now derive from the clip's sampled rate, so the config `fps` reaches them through the tracker-sampled clip.
- The crate no longer forces reqwest's rustls backend; vllm's own reqwest-0-13 `native-tls` feature keeps providing media-fetch TLS — no change.
- The spec-driven video sampling wiring (`video_frame_sampling_with` / `default_video_sample_fps_with` into the tracker builders, `prompt_replacements_with_media` for GLM timestamps) survived #4174 unchanged.

Latest repin (7b7f59ec, smg@8a5abe0b) migrations:

- `ModelProcessorSpec::processor_kwargs` was dropped upstream (nothing reads it); vllm's `merge_processor_kwargs` plumbing and the Step3-VL spec's override are removed (the processor already resolves the same knobs from `PreProcessorConfig` extras with the same defaults).
- hf-hub download support is now the crate's optional `hf-hub` default feature; vllm depends with `default-features = false` and never touches `llm_multimodal::hub`, so no change (one less transitive dep: `webpki-roots` drops from the lock).
- Qwen2-VL image anchors moved to the template's `<|image_pad|>` expanding to `image_token_id` (upstream #4121); vllm only references qwen2_vl in server config-resolution tests, which set both ids — unaffected.
- `VisionPreprocessingContext { token_budget }` is back as an optional, defaulted `preprocess_with_context` (#4120 shrinks Nemotron-H Omni images to the request budget); vllm passes it again: image batches call `preprocess_with_context` with `max_model_len` minus the prompt's text tokens, restoring the vllm-project/vllm#57634 behavior.
- LLaVA/Qwen3-Omni/Qwen3-ASR/DeepSeek V4.1 anchors opt in for worker-side expansion (#3634), GLM-5.3 Flash media alignment (#4036/#4140/#4146) and Muse Spark media support (#3526) land from upstream; no vllm code action (all model tests pass unchanged).

API migrations for the new crate:

- `PreprocessedEncoderInputs.encoder_input` is now an `EncoderInput` enum (`F32` / byte-backed `U8` / `Wire`) instead of `ArrayD<f32>`; tensor collection materializes byte-backed inputs through `EncoderInput::into_f32()` (exact same values the processors produced) before lowering to the model's float wire dtype.
- `MediaConnector::new` now takes a `reqwest::ClientBuilder` and finishes the build itself (forcing its redirect policy and DNS resolver). TLS resolves to native-tls: llm-multimodal enables no reqwest TLS backend (smg-project/llm-multimodal#19), so vllm's `native-tls` reqwest feature provides it and aws-lc-rs / aws-lc-sys are no longer compiled.
- `ModelProcessorSpec::audio_processor()` returns `RegistryResult<Option<..>>`; resolution failures now propagate as load errors instead of silently disabling audio.
- `ImageFrame::data()` is gone (frames decode lazily from their raw bytes); the image path uses `frame.image()` and propagates decode errors.
- `MediaConnectorError` grew redirect/host-policy variants and a struct-shaped `Timeout`; vllm's `From` impls go through `to_report_string()` and are unaffected. `MediaContentPart`'s serde wire shape is unchanged (only optional, defaulted fields added).

smg v1.13.0 also upstreams the Nemotron-H Omni processor (spec + C-RADIO vision + Parakeet audio), so the separate follow-up commit was dropped from the rebase branch, while the Inkling audio hardening (token cap + input validation) is retained. Gemma 4 vision support is now included from upstream as well. The vllm-side Nemotron test was rewritten to the upstreamed spec's contract (model_type `NemotronH_Nano_Omni_Reasoning_V3`, packed patch rows + `patches_per_image` / `image_grid_hw` aux tensors, `<img>…</img>`-wrapped `<image>` runs).

Upstream `main` (a9bf45ed8a) is merged in; its local Step3-VL/Step5-VL support under `multimodal/models/` was ported to the stateless v1.14.0 processor API (config travels per call), and the alignment-pad expansion tests the merge resurrected were dropped since `PromptReplacement::with_alignment_pad` no longer exists in the pinned crate.

Upstream `main` (47e2b610be) is merged in as well; its local Muse Spark support (spec + NaViT vision + raw-waveform audio under `multimodal/models/muse_spark*`) was ported the same way (stateless processor, config per call, new `audio_processor` signature), and upstream's multi-token placeholder markers (`marker_token_ids: Vec<u32>` with tokenize fallback) plus the separate `feature_extractor` audio preprocessor config are adopted.

Earlier notes for this tracking branch:

- Vision processors are stateless and resolved from the shared VisionProcessorRegistry by model id / model_type; the preprocessor config travels per call (preprocess / preprocess_video / preprocess_video_rgb all take &PreProcessorConfig). The spec modality limits gate lane resolution, preserving the old factory's UnsupportedModality -> None semantics.
- audio_processor() takes the raw model config Value.
- PromptReplacement no longer carries AlignmentPad (upstream vllm-project/vllm#56554 dropped the compressor-alignment pad), so the splice-time padding logic and its tests are removed.
- MediaContentPart::{ImageUrl, VideoUrl} gained optional max_long_side_pixel / fps fields (MiniMax-M3 extensions).
- The model spec's processor_kwargs (Nemotron-H Omni's checkpoint downsample_ratio and patch limits) are merged into PreProcessorConfig.extra at load time without overwriting existing keys, so the stateless processor can resolve them per call.
- Tests follow the new model contracts: Inkling renders its checkpoint soft placeholders (<|unused_200053|>/<|unused_200054|>) with the typed content marker as structural prefix and ships tokens_per_item; the qwen2_vl spec renders "<image>" and reads vision_token_id.
