# [Bugfix][ROCm][MoRIIO] Wait for MoRIIO WRITE mode completions in short chunks

[Upstream PR](https://github.com/vllm-project/vllm/pull/64330) · state: closed · merged: True

## Original PR description



## Overview

In MoRIIO WRITE mode, the prefill (P) instance waits for a request's KV copies before it sends `write_done` to the decode (D) instance, and the READ barrier waits for its reads the same way. Both go through `MoRIIOWrapper.waiting_for_transfer_complete` which makes one MoRI `wait_all` call with the whole `transfer_timeout`. On MoRI's xGMI backend, that call polls each status once and then sleeps until its deadline, so a copy that is still running at that poll holds the wait for the full timeout (30s by default). This also happens on MoRI's scatter/gather copy path under load, where a wait that still sees `IN_PROGRESS` at its deadline fails the transfer and leaves the decode request waiting. This PR calls `wait_all` in 10ms intervals, and checks the statuses between the intervals, up to the same `transfer_timeout`.



## Claims

- On MI355X with MoRI v1.2.3.post1, a prefill process writing 118 layers (128 blocks of 32 KiB each) into a decode process on another GPU over xGMI with MoRI's default copy path, `transfer_timeout` 30s: on main all 6 of 6 waits took 29.999 s, even though every one of the 118 statuses had succeeded. With this PR, 100 of 100 waits ended after 0.210 s (median; min 0.183 s, max 0.210 s), all succeeded.
- When a status fails, the wait raises at once with `fail_fast=True` (WRITE), or once no status is in flight with `fail_fast=False` (READ barrier), as the polling fallback already does. Timeouts and error messages are unchanged.
- With P/D serving, for DeepSeek-V2-Lite-Chat served with prefill TP1 and decode TP1 on MI355X over xGMI, with `MORI_IO_XGMI_SCATTER_GATHER_THRESHOLD=0` (MoRI's scatter/gather copy path) on prefill, 16K-token prompts: on main, two of three runs at concurrency 8 left requests that never completed (92 and 95 out of 96), each after a completion wait that failed with `IN_PROGRESS` when its 30s `transfer_timeout` expired. In the run that finished, concurrency 16 reached only 2.28 req/s with a client TTFT p90 of 30.2 s. With this PR, all 96 requests completed in each of three runs, with no failed wait, at 6.96–7.20 req/s.

```python
"""Time vLLM's MoRIIO WRITE completion wait over xGMI.

A prefill process on --p-gpu writes 118 layers of 128 blocks (32 KiB each) into a
decode process's buffer on --d-gpu, one MoRI batch_write per layer, then waits
for them with MoRIIOWrapper.waiting_for_transfer_complete (transfer_timeout 30 s),
as the WRITE producer does before it sends write_done.

    python moriio_wait_repro.py --p-gpu 0 --d-gpu 1 --requests 3
"""

import argparse
import multiprocessing as mp
import os
import pickle
import tempfile
import time

LAYERS, BLOCKS, BLOCK_BYTES = 118, 128, 32768
LAYER_BYTES = 2 * BLOCKS * BLOCK_BYTES


def setup(role, port, run_dir):
    import torch
    from mori.io import (
        BackendType,
        EngineDesc,
        IOEngine,
        IOEngineConfig,
        MemoryDesc,
        XgmiBackendConfig,
    )

    buf = torch.zeros(LAYERS * LAYER_BYTES, dtype=torch.uint8, device="cuda")
    engine = IOEngine(f"{role}-repro", IOEngineConfig("127.0.0.1", port))
    engine.create_backend(BackendType.XGMI, XgmiBackendConfig())
    mem = engine.register_torch_tensor(buf)
    mine = os.path.join(run_dir, role)
    peer = os.path.join(run_dir, {"p": "d", "d": "p"}[role])
    with open(mine + ".tmp", "wb") as f:
        pickle.dump((engine.get_engine_desc().pack(), mem.pack()), f)
    os.rename(mine + ".tmp", mine)
    while not os.path.exists(peer):
        time.sleep(0.1)
    with open(peer, "rb") as f:
        peer_engine, peer_mem = pickle.load(f)
    engine.register_remote_engine(EngineDesc.unpack(peer_engine))
    return engine, buf, mem, MemoryDesc.unpack(peer_mem)


def decode(port, run_dir):
    _ = setup("d", port + 1, run_dir)
    while not os.path.exists(os.path.join(run_dir, "done")):
        time.sleep(0.5)


def prefill(port, run_dir, requests):
    from vllm.distributed.kv_transfer.kv_connector.v1.moriio.moriio_engine import (
        MoRIIOWrapper,
    )

    engine, _buf, mem, peer_mem = setup("p", port, run_dir)
    session = engine.create_session(mem, peer_mem)
    wrapper = MoRIIOWrapper(moriio_engine=engine, transfer_timeout=30.0)
    sizes = [BLOCK_BYTES] * BLOCKS
    for request in range(requests):
        statuses = []
        for layer in range(LAYERS):
            offsets = [layer * LAYER_BYTES + 2 * b * BLOCK_BYTES for b in range(BLOCKS)]
            uid = engine.allocate_transfer_uid()
            statuses.append(session.batch_write(offsets, offsets, sizes, uid))
        start = time.monotonic()
        try:
            wrapper.waiting_for_transfer_complete(statuses)
            outcome = "ok"
        except Exception as e:
            outcome = f"{type(e).__name__}: {e}"
        succeeded = sum(s.Succeeded() for s in statuses)
        print(
            f"request {request}: wait {time.monotonic() - start:.3f} s, "
            f"{succeeded}/{len(statuses)} statuses succeeded, {outcome}",
            flush=True,
        )
    open(os.path.join(run_dir, "done"), "w").close()


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--p-gpu", type=int, default=0)
    parser.add_argument("--d-gpu", type=int, default=1)
    parser.add_argument("--port", type=int, default=29600)
    parser.add_argument("--requests", type=int, default=3)
    args = parser.parse_args()
    ctx = mp.get_context("spawn")
    run_dir = tempfile.mkdtemp()
    os.environ["HIP_VISIBLE_DEVICES"] = str(args.d_gpu)
    d = ctx.Process(target=decode, args=(args.port, run_dir))
    d.start()
    os.environ["HIP_VISIBLE_DEVICES"] = str(args.p_gpu)
    p = ctx.Process(target=prefill, args=(args.port, run_dir, args.requests))
    p.start()
    p.join()
    d.join()
```

## Details

On MoRIIO's WRITE path of the prefill instance under PD disaggregated serving, for one request:

1. D allocates blocks for the request and sends their ids to every P rank.
2. In P's forward, each layer's write is scheduled with the layer's CUDA event.
3. P's write worker waits for each event and posts the layer's copies (`batch_write` on a MoRI session).
4. After the last layer, `_finalize_if_complete` waits for every copy of the request (`waiting_for_transfer_complete`) and sends `write_done`.
5. D marks the request's KV as received and starts decoding it.

Step 4 makes one MoRI call with the whole timeout:

```
vllm/distributed/kv_transfer/kv_connector/v1/moriio/moriio_engine.py's MoRIIOWrapper.waiting_for_transfer_complete
timeout_ms = ceil(self._transfer_timeout * 1000)
result = wait_all(transfers_to_wait, timeout_ms=timeout_ms)
```

On MoRI's xGMI backend, a status completes only when it is polled, and a bounded `wait_all` polls each status once and then sleeps until its deadline. If the copies are still running at that one poll, the wait costs the whole `transfer_timeout`; when the statuses are still `IN_PROGRESS` at the deadline, the transfer fails with `TransferError`, and on main no failure notice reaches decode. With the default copy path the last layers are nearly always still running when step 4 starts, so the wait lasts the whole `transfer_timeout` and the request's `write_done` reaches D 30s late. As shown in the the reproducer above, however, every status had succeeded long before the call returned. On the scatter/gather path the copies are fast, but when prefill has already queued its next step, they complete only after that step, so under load the one poll misses them there as well.

This PR addresses this by calling `wait_all` with at most 10ms and checking the statuses with `poll_transfer_batch` between calls, until `transfer_timeout`:

- every status succeeded: return;
- a status failed: raise at once with `fail_fast=True`, or once nothing is in flight with `fail_fast=False` (on main the native path ignored `fail_fast` and always waited for the deadline);
- an error result without a failed status, or the deadline: raise, with the same messages as before.
