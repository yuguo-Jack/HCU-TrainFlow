# [Bugfix][KV Connector][NIXL] Support P_TP > num_kv_heads with P_TP > D_TP in pull mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/63648) · state: open · merged: False

## Original PR description



## Overview

The NIXL pull connector rejects a GQA model whose prefill TP exceeds its KV-head count when decode TP is smaller (for example, Llama-3.3-70B with 8 KV heads at P TP16 → D TP4). This PR supports that case: D reads one P replica per KV head and notifies the replicas it skips.

## Claims

- P_TP > num_kv_heads with P_TP > D_TP now handshakes and serves in pull mode, for non-MLA, non-Mamba models. Before this change, every request failed at the `assert not (tp_ratio < 0 and is_kv_replicated)` handshake check.
- Skipped replica ranks get the read-done notification, so they free their blocks at once instead of holding them until the KV lease expires.
- No behavior change for other topologies: MLA, Mamba, push mode, and non-replicated or P_TP <= D_TP setups take the same paths as before.

## Details

**Root cause.**
1. `compute_tp_mapping` already deduplicates replicated GQA heads with `np.unique`: a D rank reads exactly one P rank per KV head it owns.
2. The block_len check already uses per-rank head counts (#45330).
3. `_validate_remote_agent_handshake` still asserted the whole case away, and nothing notified the replicas that are never read.

**Flow (P TP8, 4 KV heads, D TP1):**
1. P ranks {0,1}, {2,3}, {4,5}, {6,7} each hold the same head.
2. D handshakes with all 8 P ranks, as `handshake_target_ranks` already does.
3. The mapping picks source ranks 0, 2, 4, 6, and D posts four head-sliced READs into its local head slots.
4. D sends `"<p_req_id>:<local_consumers>"` to ranks 1, 3, 5, 7. Every P rank then reaches its expected notification count and frees the request's blocks.

**Changes:**
- `_is_gqa_replicated_pull()` detects the case (pull mode, `tp_ratio < 0`, not MLA, not Mamba, `is_kv_replicated`).
- The handshake no longer asserts on it, and validates the remote `block_len` as head-split rather than replicated.
- The layout check requires block-contiguous heads, the same as other head-split transfers.
- The existing MLA "notify the unread ranks" path is generalized from "every rank except the single one read" to "every handshaked rank not read". For MLA the behavior is identical.

**Limitations:**
- Push mode is unchanged and still rejects a remote TP above both the local TP and num_kv_heads. P validates D there, and D can validate P through its heartbeat handshake when P has PP=1. In that case D logs a failed handshake, and the registration handshake then connects it (this already happens on main). Push with P_TP > num_kv_heads > D_TP has not been validated end to end.
- Throughput for P_TP > D_TP is governed by the head-sliced descriptor size, the same as non-replicated heterogeneous TP. A larger `--block-size` helps a lot. Example: B200 TP4 → TP1 at 8K went from 3.2 to 18.1 req/s when the block size changed from 32 to 128.

**Side note.** `test_mla_broadcast_notif_uses_remote_request_id` is indented inside the preceding module-level test function, so pytest never collects it. This PR leaves it untouched. The new module-level test covers the shared notify path.
