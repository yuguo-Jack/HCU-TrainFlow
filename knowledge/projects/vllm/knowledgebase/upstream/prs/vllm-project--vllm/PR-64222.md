# [Rust Frontend] Support --root-path

[Upstream PR](https://github.com/vllm-project/vllm/pull/64222) · state: closed · merged: True

## Original PR description

## Overview

Support `--root-path` on the Rust frontend, which a placeholder rejected at startup: every route is served both under the prefix and at its bare path, as with the Python frontend's FastAPI `root_path`.

## Claims

- With `--root-path /llm`, `/llm/v1/chat/completions` and `/v1/chat/completions` both reach the chat route, on `vllm-rs serve` and on the Python launcher path.
- API-key auth guards the prefixed paths too, and HTTP metric labels and load tracking see the bare path.
- The prefix only matches up to a path segment boundary (`/llmx/...` is not stripped), and the query string is kept.

- `routes::tests::strip_root_path_keeps_query_and_segment_boundary`: snapshot of the rewritten URIs (`/llm/v1/models?limit=1` → `/v1/models?limit=1`, `/llm` → `/`, `/llmx/...` and bare paths unchanged).

- E2E on GB200 with `VLLM_USE_RUST_FRONTEND=1` and a `vllm-rs` built from this branch: `pytest -v -s tests/entrypoints/openai/chat_completion/test_root_path.py`: 4 passed. It can join the Rust frontend CI step in a follow-up.

## Details

Python's `--root-path` sets FastAPI's `root_path` (`vllm/entrypoints/launchers/app.py`). Starlette then routes a request whose path starts with the root path as if the prefix were absent (`starlette._utils.get_route_path`), while bare paths keep working, and the API-key middleware strips the prefix before deciding whether a path is guarded (`vllm/entrypoints/serve/middleware/authenticate.py`). `test_root_path.py` pins exactly this.

- `--root-path` becomes a real `SharedRuntimeArgs` option carried into `Config::root_path` on both launch paths (an empty value means no root path, like FastAPI).
- `routes::with_root_path` wraps the finished router (including router extensions) in an outer router whose fallback service strips the prefix, then routes.

**Layering.** The consumer is HTTP routing, so the prefix is stripped in the server crate before routing; an `axum` `Router::layer` runs after routing and cannot rewrite the routed path. Every layer then sees the bare path, so API-key auth, HTTP metric labels and load tracking need no root-path awareness, matching Python's auth and route-template metric labels.

Not mirrored: FastAPI's OpenAPI `servers` entry derived from `root_path`; the Rust frontend serves no docs routes.

Not a duplicate: supersedes the inactive vllm-project/vllm#44900 (no activity since 2026-09-03), which registered every route twice through `Router::nest`; with nesting, `MatchedPath` and therefore the HTTP metric labels carry the prefix, and auth sees the prefixed path.
