## Details

**1. Extract bind + `listen_address` construction into `utils/listen.py`.**

**2. Turn bind failures into more actionable errors.**

All four wrapped raises keep the original errno via `OSError(e.errno, msg) from e`:
- **UDS `EADDRINUSE`** — names the path and suggests `rm <path>` or a different `--uds`; deliberately omits `--port` / `SO_REUSEPORT` / `--api-server-count`.
- **TCP `EADDRINUSE`** — includes the holder (`pid` / `name` / `cmd`); hint branches on `reuse_port`: `False` → "change port or enable `--api-server-count > 1`", `True` → "holder is missing `SO_REUSEPORT` or is not a vLLM process".
- **TCP `EACCES`** — `OSError(errno.EACCES, ...)` auto-maps to `PermissionError`.
- **`ENOPROTOOPT` with `reuse_port=True`** — explicit "`SO_REUSEPORT` not supported on this platform; use a single API server".

Additionally:
- **`SO_REUSEPORT` constant missing** — `hasattr` pre-check raises `OSError(errno.ENOPROTOOPT, ...)` instead of letting `AttributeError` bypass the message.
- **Holder lookup failure** — `_describe_port_holder` never raises; falls back to `unknown process (query failed)`, so `EADDRINUSE` stays actionable even when `psutil` is restricted.

**3. Move `set_ulimit()` into `setup_listen_address`'s success path.** Behavior is unchanged (both TCP and UDS already reached it), but the call now travels with the bind logic.

**4. Add `_describe_port_holder` to the `EADDRINUSE` path; remove the shutdown-time port diagnostic** (blocking `psutil` scan, usually detects itself, no try/except). Removing it also eliminates the `uvicorn_kwargs["port"]` `KeyError` in UDS / missing-port cases.

**5. Add `cleanup_listen_socket`, but leave wiring to a follow-up PR.** 

**6. Fix `listen_address` construction.** Use the kernel-assigned port for `--port 0`, keep the user-supplied host (so `--host localhost` stays `localhost`), bracket IPv6, and require both keyfile and certfile for `https://`.

**7. Add scenario-based tests for `listen.py`** (UDS, TCP address construction, SSL scheme, `SO_REUSEPORT`, conflicts, permissions, unknown-errno passthrough, args adapter, cleanup, `_describe_port_holder`), asserting `errno` and `PermissionError` to guard against regressing to `OSError(msg)`.

🟡 (optional) Code that checks the error type or errno from `setup_server` stops matching after this change. Port conflicts now carry `errno=None`, and permission errors are no longer `PermissionError`. The EADDRINUSE, EACCES and ENOPROTOOPT branches raise `OSError(f"...") from e` with only a message. Python then leaves `errno`/`strerror` unset and never maps to a subclass. Fix: keep the errno and the subclass in all three wrapped raises, e.g. `raise OSError(e.errno, msg) from e`. That auto-maps EACCES to `PermissionError` and keeps the new messages.

<details>
<summary>Why this was flagged</summary>

I could not list the affected callers because they are out of tree: wrappers, test harnesses or supervisors that call `vllm.entrypoints.launchers.launcher.setup_server` (launcher.py:331) and handle bind failures with checks like `e.errno == errno.EADDRINUSE` (for example to retry on another port) or `except PermissionError`. On the base branch, setup_server re-raised the kernel's own OSError, so `errno` was 98 for a port conflict and an EACCES bind came up as `PermissionError`. After the change, listen.py:90-92, 94-96 and 98-102 each build a new `OSError(<message>)` with one argument. That object has `errno is None` and `strerror is None`, and its type is plain `OSError` even for EACCES. The errno survives only on `__cause__`, which those callers do not inspect. As a result, retry-on-conflict logic gives up and PermissionError handlers are skipped. A grep found no in-tree caller that checks the errno, so the tests and CI do not catch this.

**Verification:** In vllm/entrypoints/launchers/utils/listen.py, the EADDRINUSE branch (lines 91-93), the EACCES branch (94-97) and the ENOPROTOOPT branch (98-103) each build a single-argument `OSError(msg)`. A single-argument OSError leaves `errno` and `strerror` as None and is not mapped to a subclass, so an EACCES bind no longer comes up as `PermissionError`.

</details>
