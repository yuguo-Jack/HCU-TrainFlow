# [Bugfix][ToolParsers] Close unterminated tool-call arguments on truncated streams

[Upstream PR](https://github.com/vllm-project/vllm/pull/59620) · state: open · merged: False

## Original PR description

### Summary

`HYV3ToolParser` / `HYV4ToolParser` stream tool-call arguments incrementally and intentionally **withhold the closing `}`** of the arguments JSON until `</tool_call>` arrives (so partial values can keep growing with a stable prefix). When generation ends early — `max_tokens`, `stop`, or client disconnect — the stream never sees the closing tag, and the framework's finalize step (`_append_unstreamed_tool_args`) appends `get_remaining_unstreamed_args()` to the last tool-call chunk. Both parsers returned `""` because the in-flight tool call was never registered in `prev_tool_call_arr`, so the client received an **unterminated JSON fragment** such as `{"city": "Beijing"` that cannot be parsed.

This PR:

1. Overrides `get_remaining_unstreamed_args()` in both parsers to emit the withheld JSON tail from their incremental-streaming state (`_completed_args` / `_streamed_json_len`), so a truncated stream still ends with parseable arguments (`{"city": "Beijing"}`) and complete streams are unaffected (tail is empty).
2. Aligns `HYV4ToolExtractor.func_args_regex` with HYV3 by allowing whitespace between `</arg_key>` and `<arg_value>`. The model emits `</arg_key>\n<arg_value>`, which HYV4's regex did not match — completed kv-pairs were never recognized and the raw structural tags leaked into the streamed arguments even on a complete tool call.

### Tests

- `pytest tests/tool_parsers/test_hy_truncated_stream.py` — new regression tests (mock tokenizer, no model download): truncated stream closes JSON for both parsers; complete stream unchanged; truncated-before-args does not fabricate arguments.
- `ruff check vllm/tool_parsers/hy_v3_tool_parser.py vllm/tool_parsers/hy_v4_tool_parser.py tests/tool_parsers/test_hy_truncated_stream.py`

What I ran instead: streams replayed through the code the server actually executes — `ParserManager.get_parser(tool_parser_name=…)` → `Parser.parse_delta(delta_text, token_ids, request, finished=True)` (`entrypoints/openai/chat_completion/serving.py:662`), **one token per delta**, using the two checkpoints' **own tokenizers and chat templates** as published.

**The first commit did not close the fragment** (what the client had accumulated in `function.arguments`; HY3 shown, HY4 is the same with its `:opensource` tokens):

| generation stops | `e6f398dd` | `19fd05f5` |
| --- | --- | --- |
| right after `</arg_value>` | `{"city": "Beijing"}` | `{"city": "Beijing"}` |
| after the template's `</arg_value>\n` | `{"city": "Beijing"` ❌ | `{"city": "Beijing"}` |
| inside a value (`…<arg_value>2026`) | `{"city": "Beijing", "date": "2026"` ❌ | `{"city": "Beijing", "date": "2026"}` |

Two reasons:

1. `Parser._append_unstreamed_tool_args` consults the hook only when the **final** delta carries a tool call. HY3/HY4's template emits `\n` between `</arg_value>` and `</tool_call>`, so when `max_tokens` cuts just after a value the last delta is that newline and yields no delta at all — the hook was never called.
2. When it *is* called, the withheld tail is not always `}`: if generation stops inside a string the streamed prefix ends inside the string, and the suffix that makes it parse is `"}`.

**The tests missed it because they re-implemented the finalize step.** [The finalize in `_simulate_streaming`](https://github.com/vllm-project/vllm/blob/e6f398dd59a307d3dba5863d967708afc9879aa4/tests/tool_parsers/test_hy_truncated_stream.py#L96-L105) walks `reversed(results)` and appends to the last result that has a tool call; the serving path only ever looks at the final delta. Its last chunk `"\n<arg_value>Beijing</arg_value>"` also carries a tool call, which a per-token stream would not. Driven through the real path, the six tests in that file passed while 8 new ones failed — including the plain `</arg_value>\n` cut. (The same stream at chunk sizes 2/3/5 passes; only chunk size 1, the shape the server produces, fails.)

**Change** (`19fd05f548`):

- `vllm/parser/abstract_parser.py` — at finalize, consult the hook unconditionally and, when the final chunk has nothing to attach the tail to, emit it as its own `DeltaToolCall` on `current_tool_id`. When the final chunk does carry a tool call the existing path is byte-for-byte unchanged.
- `hy_v3` / `hy_v4` — track the exact prefix already streamed and return the shortest suffix that makes it parse, each verified with `json.loads` (`""` / `"}"` / `"\""}`). A normally-terminated call resets that state, so complete streams are untouched. HY4's `\s*` tolerance between `</arg_key>` and `<arg_value>` is kept.
- `tests/tool_parsers/test_hy_truncated_stream.py` — the six tests that re-implemented finalize are replaced by 16 that go through it: 14 fail on `main`, all pass here.

**Regression.** `tests/tool_parsers` + `tests/parser` (7 400 tests, cohere included): base 33 failed / 7 452 passed, with this change 14 failed / 7 471 passed, and **every failure under the change is already present on `main`** (14 × `test_structural_tag_registry.py` `[mimo]`, 15 × `test_llama3_json_tool_parser.py` collection errors — neither file is touched here). One existing test changes contract: `tests/parser/test_streaming.py::test_parse_delta_finished_no_flush_without_tool_call_delta` asserted the old "no tool-call delta in the final chunk ⇒ drop the withheld args", which is the behaviour being fixed, so it is renamed and now asserts the tail is delivered.
