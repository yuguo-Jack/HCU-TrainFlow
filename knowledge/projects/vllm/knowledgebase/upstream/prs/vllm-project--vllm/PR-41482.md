# [bug] Fix lora reloading from disk every step when using AsyncLLM

[Upstream PR](https://github.com/vllm-project/vllm/pull/41482) · state: closed · merged: True

## Original PR description



## Purpose
When calling load_lora_adapter endpoint with `load_inplace:true`, lora reloads from disk every generation, leading to massive slowdowns. we set lora_request.load_inplace = False after first load to so we only load it once. 

Reproduction:
```
VLLM_ALLOW_RUNTIME_LORA_UPDATING=1 vllm serve meta-llama/Llama-3.2-3B-Instruct --enable-lora --max-loras 1 --max-lora-rank 64 --gpu-memory-utilization 0.5 --port 8765

# wait for vllm server startup, then in separate terminal
curl -s localhost:8765/v1/load_lora_adapter -H 'Content-Type: application/json' -d '{"lora_name":"l","lora_path":"jeeejeee/llama32-3b-text2sql-spider","load_inplace":true}'
curl -s localhost:8765/v1/chat/completions -H 'Content-Type: application/json' -d '{"model":"l","messages":[{"role":"user","content":"hi"}],"max_tokens":256}' 

```
We observe that without the fix, lora reloads from disk on every request.

I believe this is still an issue.
5.6 sol suggests 
```python
self.lora_requests[lora_name] = msgspec.structs.replace(
    lora_request,
    load_inplace=False,
)
```
as a fix for the openai path, but e.g. 
```python
llm.chat(..., lora_request=LoRARequest(..., load_inplace=True))
```
is not covered by that. 
So maybe functionality like this:
```python
await engine_client.add_lora(
    lora_request,
    load_inplace=True,
)
```
Otherwise maybe cover all the paths that use lora requests and make sure they don't persist `load_inplace`. 

Why was it attached to load_inplace in the first place?
- The original implementation actually used add_adapter(lora_request, force_load=True), essentially our proposal. Original commit (https://github.com/vllm-project/vllm/commit/4f23aa54f191069da2d26a991a073c55f3f66ac2)
  - A maintainer then requested putting the flag on LoRARequest so replacement could be initiated through offline LLM.chat(...), since LLM had no public add_lora method. Maintainer comment (https://github.com/vllm-project/vllm/pull/31326#issuecomment-3696132947)
  - The resulting tests checked that outputs changed from adapter A to B, but never counted disk loads across decode steps. Merged PR #31326 (https://github.com/vllm-project/vllm/pull/31326)
