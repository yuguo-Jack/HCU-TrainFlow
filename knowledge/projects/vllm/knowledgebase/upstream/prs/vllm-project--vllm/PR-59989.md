# [Bugfix] Fix Qwen3-VL reranker crash on missing tie_word_embeddings in text config

[Upstream PR](https://github.com/vllm-project/vllm/pull/59989) · state: open · merged: False

## Original PR description



## Overview

Fixes #59784. Serving `Qwen/Qwen3-VL-Reranker-8B` as `Qwen3VLForSequenceClassification` crashed during weight loading with `AttributeError: 'Qwen3VLTextConfig' object has no attribute 'tie_word_embeddings'`. The seq-cls weight loaders in `adapters.py` now read `tie_word_embeddings` from the language model's config, which is where vLLM puts it for VLMs.

## Claims

- `Qwen/Qwen3-VL-Reranker-8B` with `--runner pooling` and the `Qwen3VLForSequenceClassification` override now loads, starts and answers `/rerank`. Before this change, the engine crashed while loading weights.
- Both `load_weights_using_from_2_way_softmax` and `load_weights_no_post_processing` had the same line. Both are fixed.
- Text-only models read the same value as before, because there `language_model is model`.
- A new regression test fails with the base `adapters.py` and with a `getattr(..., False)` fallback. It passes with this change.

## Validation

## Details

**Root cause.** With Transformers v5, `tie_word_embeddings` is a field of `Qwen3VLConfig` but not of `Qwen3VLTextConfig`. The 8B checkpoint sets `"tie_word_embeddings": false` only at the top level. For multimodal models, `VllmConfig.with_hf_config` copies the top-level flag into the text config. But when `architectures` is passed, it first deep-copies that text config. `Qwen3VLForConditionalGeneration` passes `architectures=["Qwen3ForCausalLM"]`. So the inner language model gets a copy that has the flag, while `model.config.text_config` still has no flag. The seq-cls loaders read the flag from `model.config.get_text_config()`, which is the original config. The read raises `AttributeError` before any weight is loaded.

**Fix.** Read the flag from `language_model.config.get_text_config()`. The language model was built with this config and uses it to tie its own `lm_head`, so now the loader and the model agree. For text-only models, `language_model is model`. When `with_hf_config` makes no copy, this is the same object as before.

**Why not `getattr(text_config, "tie_word_embeddings", False)`** (the fallback suggested in the issue): it stops the crash, but it reads `False` for a tied checkpoint whose text config has no flag, even when the top-level config says the embeddings are tied. The loader then does not tie `lm_head` to `embed_tokens`. A tied checkpoint has no `lm_head` tensor, so the score weights built from it are wrong. With that fallback, every score in the new test is 0.5.

**Test.** `Qwen/Qwen3-VL-Reranker-2B` has tied embeddings. But its real config has the flag at both levels, so by itself it does not reach the failing state. This includes the existing `tests/entrypoints/pooling/scoring/test_cross_encoder_online_vision.py`. The new test removes the flag from the 2B text config, so the config looks like the 8B one. Then it checks that the relevant document scores higher than the unrelated one.

**Other VLMs.** `language_model.config` is read without a guard. The language model classes used by other VLMs (for example `LlamaModel` and `MolmoModel`) set `self.config`, so this change adds no new failure for them. This PR does not check whether seq-cls conversion gives correct scores for those models.
