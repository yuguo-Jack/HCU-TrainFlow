# [Kernel] Honor ND group FP8 input contract

[Upstream PR](https://github.com/vllm-project/vllm/pull/64996) · state: open · merged: False

## Original PR description



## Overview

Make group FP8 CUDA quantization preserve the ND input contract already supported by the native path. This is API consistency for direct/OOT callers: current in-tree CUDA callers flatten their input, and no production-model trigger has been established.

## Claims

- Quantize 3D/4D inputs through the existing 2D kernels and restore logical value/scale shapes.
- Preserve caller-provided contiguous `out_q` storage and per-batch column-major/TMA scale layouts.
- Keep the existing 2D quantization arithmetic; compare ND values and logical scales exactly against the flattened call.

## Validation

Base `2eae56c4ba0c`; A100-SXM4-80GB, PyTorch 2.14/cu130. Test commands, source identities, environment details and raw assertion logs are in [validation.zip](https://github.com/user-attachments/files/34240984/validation.zip). Baseline comparisons apply the candidate tests to this pinned base.

```bash
.venv/bin/python -m pytest -v -s tests/kernels/quantization/test_fp8_quant_group.py
```

October 30 GPU evidence, with the same final test file and unchanged executable logic: **base: 25 failed, 11 passed; candidate: 36 passed**. The 24 ND combinations cover FP16/BF16, 3D/4D, row-major/column-major/TMA scales, and power-of-two scaling. One additional case checks `out_q` aliasing and exact value/scale bytes against the flattened 2D call. Existing 11 cases remain covered. The changed matrix uses group size 64 to keep CI cost bounded. A separate probe passed eight output-buffer/layout checks and one `torch.compile(fullgraph=True)` check.

Recorded pytest output with the candidate tests on both trees:

```text
Base:      25 failed, 11 passed in 14.38s
Candidate: 36 passed in 13.89s
```

Baseline failures include `RuntimeError: dimensionality of sizes (4) must match dimensionality of strides (3)` and dimensionality checks in the native quantization op.

## Details

The native kernels consume 2D scale tensors. Flattening only the kernel input prevents malformed ND allocation/stride arguments; the wrapper then restores the public shape. Column-major scales require an extra layout copy, and reshaping a strided input may allocate. No performance or model-quality improvement is claimed.

The obsolete 3D allocation branch is removed. Shape, strides, uninitialized padding and the contiguous-output requirement are documented in `per_token_group_quant_fp8`; the CustomOp page links to that API instead of duplicating layout details. The changed autoref was built with MkDocs/mkdocstrings and verified against the generated API file and anchor. The full documentation site was not built. The separate packed UE8M0 DeepGEMM representation is outside this change and was not tested on Blackwell. November 1 duplicate-work checks found no equivalent open PR. #60903 optimizes 2D group quantization, #41115 changes per-token quantization, and #45151 fuses quantization into attention; they do not restore this wrapper's ND output contract.

**TMA/DeepGEMM scope:** Tests validate logical scales and storage strides, not a downstream GEMM. Padding remains uninitialized. #49783 reports DeepGEMM scale-padding failures, and #56290 proposes initialization in this same helper; this PR does not resolve that issue or claim DeepGEMM 2.6+ consumer compatibility.

AI assistance was used for implementation, tests and documentation. Hosted CI and full repository tests have not run.
