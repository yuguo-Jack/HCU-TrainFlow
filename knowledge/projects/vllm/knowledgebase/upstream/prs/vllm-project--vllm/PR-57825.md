# fix(security): harden media URL fetching against SSRF

[Upstream PR](https://github.com/vllm-project/vllm/pull/57825) · state: open · merged: False

## Original PR description

Fixes #57157.

## Problem

On a default setup the multimodal media pipeline fetches any `http(s)` URL with no IP-based guard: the domain allowlist is checked once against the *initial* URL while redirects are followed unchecked (`requests`/`aiohttp` internals), and resolved IPs are never validated — loopback, RFC1918, link-local, and metadata endpoints are reachable server-side.

## What changed

`vllm/connections.py` (plus a `VLLM_MEDIA_URL_ALLOW_PRIVATE_IPS` opt-out in `vllm/envs.py` and allowlist threading in `vllm/multimodal/media/connector.py`):

- **Resolve once, validate every answer.** Each hostname is resolved a single time per hop; every resolved IP must be globally reachable (loopback, RFC1918, link-local, multicast, reserved, unspecified refused; mixed answers refused outright). The validated IP is what gets dialed — no second DNS lookup at connect time, so DNS-rebinding TOCTOU is closed.
- **Identity preserved.** Pinned urllib3 pools/connections split dial target (`_dns_host`) from identity (`host`): `Host` header, SNI, and certificate checks keep using the original hostname, so HTTPS virtual hosts keep working. Async path overrides the aiohttp connector resolver the same way.
- **Every redirect re-validated.** Manual hop loop (10-hop cap, relative `Location` via `urljoin`): each hop repeats the domain-allowlist check and the resolve→validate→dial cycle, on both sync and async paths. Library redirect-following is disabled on this path.
- **Opt-out.** `VLLM_MEDIA_URL_ALLOW_PRIVATE_IPS=1` allows private IPs (tests serving fixtures from localhost, trusted networks) while still pinning the resolved IP.

## Verification

- New `tests/multimodal/media/test_media_url_ssrf.py`: loopback-only 302 repro (sync + async), direct-loopback rejection (asserts the target server is never hit), opt-out behavior. Failed pre-fix (`DID NOT RAISE`, redirect followed), 4/4 pass post-fix.
- `tests/multimodal/media/test_unprocessable_entity_error.py`: 11/11 pass (mock-based, unaffected).
- Existing loopback-based tests in `test_connector.py` get an explicit opt-out fixture (secure-by-default requires it).
- `ruff check` + `ruff format --check` clean on all touched files.

## Notes / limitations

- `run_batch` URL fetching shares `get_bytes` and gets the same hardening; `download_file` (asset downloads) is untouched.
- Proxied requests: hostname validation still applies; dial-pinning is skipped when a proxy dials (documented in code).
- Full `test_connector.py` HTTP suite needs CI (local scratch env segfaults on the clean tree too — broken native deps, unrelated).
