# [Bugfix][CPU] Validate attention head size at CPU backend selection

[Upstream PR](https://github.com/vllm-project/vllm/pull/63508) · state: open · merged: False

## Original PR description

## Overview

Fixes #63507. The CPU platform now rejects attention head sizes its kernel can't run, at backend selection instead of on the first request.

## Claims

- A model with an unsupported head size (e.g. 26, 40, 56, 72) fails at startup with `ValueError: Head size N is not supported by the CPU attention backend. Supported head sizes: [...]`. Before this, the engine reported ready and died on the first request.
- 48 is added to `CPUAttentionBackend.get_supported_head_sizes()`. The kernel already supports it (`HEAD_DIMS_16`), and without it the new check would reject a working model.
- Encoder attention that runs through zentorch SDPA is exempt, since it doesn't use the CPU kernel.
- Supported head sizes, MLA and the KV cache dtype check are unchanged.

## Details

- Root cause: `CpuPlatform.get_attn_backend_cls` never checked `supports_head_size`, so `get_supported_head_sizes()` was never enforced on CPU. The kernel dispatch falls through to `TORCH_CHECK(false, "Unsupported CPU attention configuration ...")` at the first forward.
- As in #62665, I call `supports_head_size` instead of the full `validate_configuration`, which also checks block size and would change behaviour for configs that work today.
- `test_attention_selector.py`: the CPU cases used head size 16, which is in neither `HEAD_DIMS_32` nor `HEAD_DIMS_16`, so those tests selected a backend that can't run. I changed them to 64. The ROCm case in `test_fp32_fallback` already notes that 16 is unsupported there.
- Added 48 to `HEAD_SIZES_VEC16` so the kernel test covers it.
- CI: `test_cpu_attn.py` runs in the CPU kernel tests job, which this PR triggers because it changes that file. The `vllm_runner` test runs in the CPU language model tests job (`-m cpu_model` over `tests/models/language/generation`). It uses dummy weights because the error is raised before weights load. I checked the models in the CPU CI jobs (language, pooling, multimodal, quantization, distributed, spec decode, Arm). All use head sizes 32–256; vision and audio towers go through `MMEncoderAttention`, not this selector.
- Not in this PR: fp8 KV cache with head sizes 48/80/112 is still only rejected later, in `_get_attn_isa`. That is a separate check.
