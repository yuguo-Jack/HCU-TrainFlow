# [CI] Add unit tests for IdentityReasoningParser

[Upstream PR](https://github.com/vllm-project/vllm/pull/46171) · state: closed · merged: False

## Original PR description

## Purpose

Adds a dedicated unit test module for `IdentityReasoningParser`, which previously had no test coverage despite every other parser under `vllm/reasoning/` having one. Pass-through parser with trivial logic, but tests now lock in the abstract base contract: regressions in the ABC or the parser's pass-through behavior will now be caught.

## Motivation

`vllm/reasoning/identity_reasoning_parser.py` defines `IdentityReasoningParser`, a pass-through implementation of `ReasoningParser` used internally by several downstream parsers (deepseek_v3, poolside_v1, kimi_k2, hy_v3). It treats the entire model output as content and performs no reasoning extraction. Every other parser in `vllm/reasoning/` has a corresponding `tests/reasoning/test_<parser>.py` module; this one did not. As a result, regressions in the abstract base class contract or in the parser's identity semantics would not have been caught for this path.

A smoke test for the class exists inside `tests/reasoning/test_deepseekv3_reasoning_parser.py` (`test_identity_reasoning_parser_basic`), but it covers a single happy path. The new module provides parametrized coverage of every abstract method plus the `reasoning_start_str` / `reasoning_end_str` properties.

## Changes

- New file: `tests/reasoning/test_identity_reasoning_parser.py` (179 lines)
- 8 test functions (23 parametrized cases total) covering:
  - `reasoning_start_str` / `reasoning_end_str` return `None`
  - `is_reasoning_end` always returns `True`
  - `is_reasoning_end_streaming` always returns `True`
  - `extract_content_ids` is an identity function
  - `extract_reasoning` returns `(None, model_output)` for varied inputs (empty, multiline, unicode)
  - `extract_reasoning_streaming` returns `DeltaMessage(content=delta_text)` for non-empty delta and `None` for empty delta
- Uses module-level `facebook/opt-125m` tokenizer following the `test_granite_reasoning_parser.py` convention
- Uses a real minimal `ChatCompletionRequest` to honor the abstract base method's declared type contract, matching the pattern in `test_deepseekv3_reasoning_parser.py`
- No source code changes; no behavior changes

## Test Plan

Run only the new module: `python -m pytest tests/reasoning/test_identity_reasoning_parser.py -v`

Expected: 23 passed.

Pre-commit clean (ruff check, ruff format, mypy 3.10, SPDX, etc.).

## Test Result

All 23 test cases passed locally. Tests confirm:
- Identity pass-through semantics intact
- Abstract base class contract honored
- Streaming and non-streaming code paths covered
- Edge cases (empty, multiline, unicode) handled correctly
