# [Bugfix][V1] Retain the EAGLE hit blocks below a sliding window across a KV connector import

[Upstream PR](https://github.com/vllm-project/vllm/pull/61011) · state: open · merged: False

## Original PR description

## Purpose

Related: #57610 / #57613 (same all-or-nothing miss from a different trigger), RFC #54661.

With the hybrid KV cache manager, an EAGLE-family drafter whose layers use sliding-window attention (DFlash, window 2048, block 64) and prefix caching, a prefix-cache hit on the draft group needs `cdiv(window - 1, block) + 1 = 33` contiguous cached blocks (`SlidingWindowManager._contiguous_blocks_for_hit`): one more than the window spans, because EAGLE matches one block past the boundary and drops it. The hybrid lookup reconciles to the shortest group, so a 0 draft hit zeroes the target's hit too.

On a decode engine in P/D disaggregation that run never exists. A KV connector import allocates only the blocks inside the window (`get_num_skipped_tokens(P) = P - window + 1 - extra_retained_tokens`), NIXL ships only those, and `cache_blocks` after the load hashes only those: 32 blocks. Every later request whose prompt is longer than the window misses on all layers; the fallback only accepts a run reaching block 0. Prefill engines are unaffected, because local compute hashes the block before `remove_skipped_blocks` nulls it, which is why this only shows on the decode side.

Fix: for an EAGLE group (annotated, or every group when none is, mirroring the coordinator), widen `SlidingWindowSpec.extra_retained_tokens` by `(cdiv(window - 1, block) + 1) * block - (window - 1)` (65 tokens here), so `get_num_skipped_tokens` lands exactly that many whole blocks below the last full-block boundary for every prompt length. This includes groups packed as `UniformTypeKVCacheSpecs` by block-outermost layouts (e.g. BLHNC); the scheduler unwraps those to their first spec. The block below the window then stays allocated on the prefill until `request_finished`, is shipped by the connector, is allocated by the decoder's import and is hashed after the load. NIXL, Mooncake P2P and MoRIIO size their transfer tail through a shared `get_sliding_window_blocks_per_group` (`kv_connector/utils.py`), which counts `sliding_window + extra_retained_tokens`, so every block the decoder allocates is written. The same spec field drives admission and pool sizing, so they stay consistent (+1 block per request on that group). The widening applies only on a KV transfer instance (`kv_transfer_config.is_kv_transfer_instance`): only a connector import needs the block, so engines without a connector keep the unwidened window. `+block_size` alone was considered and rejected: it still misses prompts with `P % block == block - 1`.

Non-EAGLE sliding-window groups (gpt-oss and Gemma without spec decode, and DeepSeek-V4.1's bounded-replay groups, which are not prefix-cacheable) are unchanged: the helper is gated on `use_eagle_block_drop()`, the EAGLE annotation and `prefix_cacheable`, and `blocks_per_sw` adds a field that is 0 for them.

Out of scope, noted for reviewers: under `prefix_cache_retention_interval=0` only the previous prompt's tail is hashed, so hits are capped at that prompt's boundary; non-EAGLE sliding-window groups have a pre-existing miss at `P % block in {0, block - 1}`. The offloading connector and the Mooncake store already add `extra_retained_tokens` to their window on `main`; the remaining connectors do not clip to the window.

Not a duplicate: #57613 widens the local retention mask for the prefill-computed path and cannot help here, because the missing block is never allocated on the decode side. #60767 nulls stale block-table entries in the worker and is consistent with this change. No open PR touches `extra_retained_tokens` for EAGLE groups or NIXL's sliding-window transfer tail.

## Test Plan

- `tests/v1/core/test_prefix_caching.py::test_eagle_swa_resend_hits_after_connector_import[packed x prompt length]`: hybrid full-attention + sliding-window manager, `use_eagle`, `retention_interval=0`, groups built through `get_kv_cache_groups` with and without a block-outermost layout; connector import of a prompt longer than the window, `cache_blocks`, free, resend; asserts a hit of `(P // block - 1) * block`. - `tests/v1/core/test_prefix_caching.py::test_eagle_swa_connector_import_writes_every_allocated_block[packed x NIXL / Mooncake P2P / MoRIIO]`: a prefill's block table (prompt computed, out-of-window blocks freed, as `Scheduler._connector_finished` hands it over) and a decoder's connector import go through each connector's own clipping and pairing (NIXL `_apply_prefix_caching`, MoRIIO `_align_read_blocks`, Mooncake P2P's rule from `_build_transfer_params`); asserts every block the decoder allocates receives the prefill's KV for the same token positions, for every prompt length up to eight blocks past the window (P = 65..192). MoRIIO's own suite only runs on ROCm with `mori`; this test builds its scheduler on CUDA.
- `tests/v1/core/test_kv_cache_planning.py::test_eagle_sliding_window_group_retains_hit_blocks_below_window`: the spec is widened only for EAGLE groups, and only on a KV transfer instance. (The helper and its call site moved from `kv_cache_utils.py` to `kv_cache_planning.py` with #61183.)
- `tests/v1/kv_connector/unit/test_nixl_connector_hma.py::test_sw_sizes`: `blocks_per_sw` includes `extra_retained_tokens`.
- End to end on 2x B300: GLM-5.3 NVFP4 + DFlash2 drafter, P/D with 2x DEP4 prefill and 2x TP4 decode over NIXL, Mooncake store, `VLLM_KV_CACHE_LAYOUT=BLHNC`, `--block-size 64`, decode prefix caching on.
