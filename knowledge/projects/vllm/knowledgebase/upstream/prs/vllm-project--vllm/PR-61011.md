# [Bugfix][V1] Retain the EAGLE hit blocks below a sliding window across a KV connector import

[Upstream PR](https://github.com/vllm-project/vllm/pull/61011) · state: open · merged: False

## Original PR description

## Purpose

Related: #57610 / #57613 (same all-or-nothing miss from a different trigger), RFC #54661.

With the hybrid KV cache manager, an EAGLE-family drafter whose layers use sliding-window attention (DFlash, window 2048, block 64) and prefix caching, a prefix-cache hit on the draft group needs `cdiv(window - 1, block) + 1 = 33` contiguous cached blocks (`SlidingWindowManager._contiguous_blocks_for_hit`): one more than the window spans, because EAGLE matches one block past the boundary and drops it. The hybrid lookup reconciles to the shortest group, so a 0 draft hit zeroes the target's hit too.

On a decode engine in P/D disaggregation that run never exists. A KV connector import allocates only the blocks inside the window (`get_num_skipped_tokens(P) = P - window + 1 - extra_retained_tokens`), NIXL ships only those, and `cache_blocks` after the load hashes only those: 32 blocks. Every later request whose prompt is longer than the window misses on all layers; the fallback only accepts a run reaching block 0. Prefill engines are unaffected, because local compute hashes the block before `remove_skipped_blocks` nulls it, which is why this only shows on the decode side.

Fix: for an EAGLE group (annotated, or every group when none is, mirroring the coordinator), widen `SlidingWindowSpec.extra_retained_tokens` by `(cdiv(window - 1, block) + 1) * block - (window - 1)` (65 tokens here), so `get_num_skipped_tokens` lands exactly that many whole blocks below the last full-block boundary for every prompt length. This includes groups packed as `UniformTypeKVCacheSpecs` by block-outermost layouts (e.g. BLHNC); the scheduler unwraps those to their first spec. The block below the window then stays allocated on the prefill until `request_finished`, is shipped by NIXL (`blocks_per_sw` now includes the retained tokens), is allocated by the decoder's import and is hashed after the load. The same spec field drives admission and pool sizing, so they stay consistent (+1 block per request on that group). `+block_size` alone was considered and rejected: it still misses prompts with `P % block == block - 1`.

Non-EAGLE sliding-window groups (gpt-oss and Gemma without spec decode, and DeepSeek-V4.1's bounded-replay groups, which are not prefix-cacheable) are unchanged: the helper is gated on `use_eagle_block_drop()`, the EAGLE annotation and `prefix_cacheable`, and `blocks_per_sw` adds a field that is 0 for them.

Out of scope, noted for reviewers: under `prefix_cache_retention_interval=0` only the previous prompt's tail is hashed, so hits are capped at that prompt's boundary; non-EAGLE sliding-window groups have a pre-existing miss at `P % block in {0, block - 1}`; Mooncake P2P and MoRIIO compute their own transfer tails and are untouched.

Not a duplicate: #57613 widens the local retention mask for the prefill-computed path and cannot help here, because the missing block is never allocated on the decode side. #60767 nulls stale block-table entries in the worker and is consistent with this change. No open PR touches `extra_retained_tokens` for EAGLE groups or NIXL's sliding-window transfer tail.

## Summary

This pull keeps the extra sliding-window blocks an EAGLE drafter needs, so that prefix-cache hits on the decode side of a split prefill/decode setup stop missing. We found one serious and five smaller findings. The most important problem is that only the NIXL connector uses the widened block count: Mooncake and MoRIIO still clip off the block NIXL now ships, so the bug is fixed for one connector of three.

## Serious findings

**1. Mooncake and MoRIIO still clip transfers to the window alone [nixl/base_scheduler.py]**
The pull adds the extra retained tokens to NIXL's sliding-window block count, so NIXL now ships the retained block. Mooncake and MoRIIO build the same count from the sliding window only, so on those two connectors the retained block is still trimmed off before transfer. Admission still reserves capacity for that block on every deployment, whether or not it is shipped.
*Change:* Make the Mooncake and MoRIIO clipping use the same widened count as NIXL.

## Smaller findings

**2. The clip's docstring now contradicts the code [nixl/base_scheduler.py]**
The docstring of the function that clips exchanged blocks still says sliding-window groups keep only the in-window tail. With the widened count they keep more than that.
*Change:* Update the docstring to describe the retained tokens.

Please checkout Full report.
