# [Model] Add Nemotron Parse 3.5 serving and MTP support

[Upstream PR](https://github.com/vllm-project/vllm/pull/61651) · state: open · merged: False

## Original PR description


## Overview

Adds native serving for Nemotron Parse 3.5's causal visual-prefix architecture and a one-token auxiliary MTP proposer. This extends the Parse model implementation; related earlier-model speculative work is [#51168](https://github.com/vllm-project/vllm/pull/51168).

## Claims

- Register RadioMBartPrefixForCausalLM and process variable-resolution packed RADIO images with content-normalized positional embeddings and visual-prefix placeholder expansion.
- Add ParseAuxMTPModel, loading the checkpoint's integrated auxiliary projections and routing causal-prefix configurations to one speculative token on Model Runner V2.
- Extend HF/vLLM generation coverage to Parse 3.5 and add five MTP configuration/loading/sharing contract tests to Basic Models CI. End-to-end MTP correctness and speedup remain unvalidated.
- Older generations of Nemotron-Parse are still supported.

## Validation

Tests ran locally. The nemotron-3.5-parse (with and without mtp) and nemotron-parse-2.0 accuracy verified on internal benchmarks. Parse 3.5 mtp acceptance rate is verified at various concurrencies. Tested on A100, H100. 

## Details

New nemotron-3.5-parse model uses an updated architecture which the current vllm implementation does not support. To simplify the change, created a new nemotron_parse3_5.py implementation while leaving code for previous versions unchanged. Major differences compared to previous implementation and approaches taken for implementations: 
1. New model uses visual prefix and removes cross-attention. 
add_cross_attention field controls whether to add cross-attention in decoder layer. Parse 3.5 implementation in vllm only supports checkpoints that has it set to False (as official checkpoint). Added a hard fail check that nemotron-3.5-parse models have it set to False. 
2. New model uses GQA vs old model using MHA.
Since WhisperAttention does not support GQA, created a local attention implementation that copies Whisper but adds GQA support. Can instead add GQA support to Whisper, but this increases common-code change. 
3. New model uses dynamic-size vision encoder with packed batching (NaVit-style) vs old model using static resolution. 
New RadioMBartPrefixForCausalLM and pre-processing. Parse 3.5 is not using device-side preprocessing for parse 3.5 for simplicity (d1d8e6c). 
4. New model uses a different version of RADIO encoder.
Added RADIOv4-SO400M parameters to RADIO file. Model: https://huggingface.co/nvidia/C-RADIOv4-SO400M

## Known limitations and future work

1. Only V2 runner is supported for mtp-enabled parse 3.5. V1 runner fails because it expects kv-cache in the speculator and parse mtp does not have attention. 
2. RADIO dynamic packing causes a sync on . This code is reused between models, so leaving it as-is for this PR. The torch.tensor constructor should be replaced with async copy in the future. Will submit separate PR. 
3. Nemotron-3.5-Parse is currently not public, so the 3.5-specific tests are disabled. Those tests and additional validation for parse 3.5 was ran locally.

🟡 (optional) Users who enable Parse 3.5 MTP on Model Runner V1 get an AssertionError after weights load, not a clear config-time error. The new Parse check at speculative.py:1467-1471 only limits num_speculative_tokens. Nothing stops ParseAuxMTPModel, which has no attention layers, from reaching the V1 EAGLE proposer. Fix: add a `ParseAuxMTPModel` entry to `_get_v1_model_runner_unsupported_features` in vllm/config/vllm.py, so `_validate_v1_model_runner` rejects it at config time. This covers VLLM_USE_V2_MODEL_RUNNER=0 and every automatic V2-to-V1 fallback.

<details>
<summary>Why this was flagged</summary>

V1 runs when VLLM_USE_V2_MODEL_RUNNER=0 is set. It also runs on the automatic fallbacks in `use_v2_model_runner` (vllm/config/vllm.py:721-738): no Triton, or any entry from `_get_v2_model_runner_unsupported_features`, such as external_launcher with PP>1 or DBO ubatching. In that case the V1 proposer builds `_draft_attn_layer_names` as an empty set (llm_base_proposer.py:1334), because ParseAuxMTPModel (nemotron_parse3_5_mtp.py) has no attention layers. `initialize_attn_backend` then calls `validate_same_kv_cache_group`, which asserts the set of draft KV groups has length 1 (llm_base_proposer.py:1696-1706). It has length 0, so the engine dies with "All drafting layers should belong to the same kv cache group" after the model has loaded. The PR description lists V1 as a known limitation, but no code enforces it. `_get_v1_model_runner_unsupported_features` (vllm.py:3024) already rejects dspark and other V2-only drafts the same way, but it has no Parse entry. On the base branch this checkpoint can't be used for MTP at all, so this crash path is new.

**Verification:** Trigger: Parse 3.5 MTP is enabled while Model Runner V1 is chosen. ParseAuxMTPModel has no attention layers, so llm_base_proposer.py:1334-1338 makes `_draft_attn_layer_names` an empty set, and `validate_same_kv_cache_group` (llm_base_proposer.py:1696-1706) raises AssertionError after the model loads. `_get_v1_model_runner_unsupported_features` (vllm/config/vllm.py:3024ff) has no ParseAuxMTPModel entry.

</details>
