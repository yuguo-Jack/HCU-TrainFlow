# [Perf][GDN] Keep FlashInfer prefill states in the cache pool for mixed batches

[Upstream PR](https://github.com/vllm-project/vllm/pull/64625) · state: open · merged: False

## Original PR description



## Overview

Stacked on #64498 (only the last commit is new), which keeps FlashInfer GDN prefill states in the cache pool when no or every prefill row has a cached state. Batches that mix the two still gather, mask, cast and scatter. This PR zeroes their fresh rows in the pool with one kernel and takes the same in-place route. AI assistance (Claude Code) was used to prepare this PR; I reviewed every changed line.

## Claims

- Mixed prefill batches: one zeroing launch per GDN layer instead of gather → mask → fp32 cast → scatter.
- Results unchanged. Only checkpointed prefills from a non-fp32 pool still gather (#64498's `_fi_pool_checkpoints_supported`).

## Validation

`tests/kernels/mamba/test_gdn_forward_core_flashinfer.py` (from #64498), adapted: every case also runs forced to `"mixed"` and must match its own route and the CuteDSL reference; SSM slots start as random data, so an unzeroed fresh row fails. The checkpoint test's reference now forces the gather branch explicitly.

```
$ pytest tests/kernels/mamba/test_gdn_forward_core_flashinfer.py tests/v1/attention/test_gdn_metadata_builder.py
100 passed                                  # GB300
```

## Details

`_zero_fresh_state_rows` uses the device-side `prefill_has_initial_state`, so it needs no host sync and also covers batches whose host-side lengths are unknown.
