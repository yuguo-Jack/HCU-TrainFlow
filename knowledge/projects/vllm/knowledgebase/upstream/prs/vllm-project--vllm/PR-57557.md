# [Bugfix] Muse Glimmer: apply structured outputs to the to=user answer

[Upstream PR](https://github.com/vllm-project/vllm/pull/57557) · state: closed · merged: False

## Original PR description

## Purpose

Carries #52390 forward (thanks @sid-rp) onto current main, with the outstanding review items fixed.

`response_format: json_schema` (and other guided-decoding requests) are silently ignored for Muse Glimmer: the model free-generates prose instead of schema-constrained JSON. Root cause: the structured-outputs backend applies the grammar only after the reasoning parser reports reasoning-end, and `is_reasoning_end` never fired on a `to=user` final answer. `json_object` worked; schema-constrained output did not.

## Approach

Muse Glimmer's channel handling is kept out of the shared `DelegatingParser`. A dedicated composite `MuseGlimmerParser(DelegatingParser)` owns the model-specific routing, and grammar activation is separated from stream ownership:

- **Grammar activation** lives in `MuseGlimmerReasoningParser.is_reasoning_end` (used by the structured-outputs backend and the serving seed), which fires once the current turn opens any non-`self` channel — the `to=user` answer or a `to=<tool>` call.
- **Stream ownership** lives in `MuseGlimmerParser`: the composite keeps the muse reasoning parser on the stream for the whole turn unless the paired muse tool parser takes over, so a `to=user` answer never ends the reasoning phase mid-turn and later channels (e.g. tool markup) can't leak through the passthrough.

On top of the original PR's segmenter refactor, this branch carries eleven review rounds (five multi-angle agent-swarm reviews with differential fuzzing against the non-streaming parse, each round's findings fixed and pinned by tests), over a merge with current main:

- the streaming reasoning-end check goes through the composite's rule; mixed parser configurations are rejected at construction with a clear 400 instead of leaking raw channel markup;
- mid-stream tool calls are parsed only once a complete channel exists (a stray `<|start|>` used to emit phantom headerless calls mid-stream, double-emit them at finish, and burn the emitted-calls cursor so a later real call lost its arguments); finish-time salvage of headerless ATEM blocks skips already-emitted calls and respects `tool_choice="none"`;
- the unframed→framed transition re-anchors the content cursor unconditionally and flushes the pre-header region on the first framed delta, so prose arriving in the same (MTP/spec-decode) delta as the framing marker is never lost, and output is chunking-independent;
- finish/truncation paths flush held-back text while still stripping trailing partial structural markers and never-bodied bare tool headers; trailing self/user bare headers and quoted markers stay text;
- performance on derailment floods is linear: one-pass trailing end-marker runs, a bounded holdback fixpoint, last-occurrence-only partial-header checks, a latched end-marker search, and a bounded header probe in `current_assistant_turn` (previously several O(n²)-per-delta shapes, up to seconds per token);
- warnings that fired per delta are `warning_once`; assorted comment/docstring drift cleaned up.

Deliberate divergences from the Rust port and stream/non-stream asymmetries (all pinned or documented): pre-header text is kept in streaming (it was already emitted) but dropped by non-streaming `parse()`; post-`<|eot|>` text keeps being parsed; interior `<|eom|>`/`<|eot|>` in unframed text is kept verbatim (grammar-shaped JSON may quote markers); headerless ATEM markup streams out as text and its complete calls are salvaged once at finish; tool-only configs stream `to=self` bodies as reasoning while non-streaming has no slot for it.

## Test Result

- `tests/tool_use/test_muse_glimmer*.py`: 170 passed (checkpoint-free char tokenizer always; `meta-models/Muse-Glimmer-30B` from the Hub when network allows), including regression pins for every review finding.
- `tests/parser/` (4599), `tests/reasoning/` (432), and `tests/tool_use/` (826 passed, 24 skipped): all pass; the 78 `RemoteOpenAIServer`-fixture errors there are pre-existing environment limitations (they spawn real GPU servers) and are covered by CI.
- Differential fuzzing (streamed char-wise / random chunkings vs non-streaming `parse()`, ~250k adversarial cases across rounds): the only residual divergences are the documented classes (pre-header text kept in streaming; dead/glued ` to=`-fragment junk-volume between chunkings, a deliberate trade-off against over-holding real prose like `photo=x`).
- mypy (1.20.2, py3.12) and ruff clean on all changed files.
- The #52390 E2E matrix (json_schema / json_object / plain chat / tool_choice auto+required+named, streaming and non-streaming, plus the honest-400 combinations) was validated end-to-end against a live `Muse-Glimmer-30B` server (GB200×4, TP=4) running **this branch's Python parsers** at the merged-with-main HEAD (`--reasoning-parser muse_glimmer --tool-call-parser muse_glimmer`): 10/10, reasoning preserved under grammar. Note the Python frontend honestly rejects `response_format` combined with tools (400) — the grammar-scoped coexistence is a Rust-frontend-only capability; the same matrix had previously passed 10/10 through the Rust frontend port of this design.
