# [Model] Support precomputed image embeddings for LightOnOCR

[Upstream PR](https://github.com/vllm-project/vllm/pull/61585) · state: closed · merged: True

## Original PR description

## Overview

Add precomputed image embedding support to LightOnOCR so callers can reuse projected visual features and skip the vision encoder.

## Claims

- Support a 3D tensor or per-image 2D tensors with different feature lengths.
- Support embedding-only inference with the image limit set to zero.

## Validation

```bash
VLLM_TARGET_DEVICE=cpu .venv/bin/python -m pytest \
  tests/models/multimodal/processing/test_lightonocr.py \
  tests/models/multimodal/processing/test_mistral3.py \
  tests/utils_/test_tensor_schema.py -v
```

- Processor and tensor-schema regressions: 51 passed, 8 GPU-specific skips. Pre-commit passed.
- Local `LightOnOCR-2-1B` validation (BF16, TP=1) passed in eager, default graph and encoder-free modes, including strict sync checking for embedding-only inference. Single- and multi-image embedding outputs match pixel baselines in token IDs and sampled-token logprobs. Chat Completions comparisons and Hugging Face reference checks also passed.

## Details

Use embedding feature counts for placeholders. Override LightOnOCR image input parsing to reuse the inherited embedding processing path, with an explicit input schema supporting variable feature lengths. Pixel inputs reuse existing parsing and token-counting logic.

Duplicate checks found no overlap with [#48316](https://github.com/vllm-project/vllm/pull/48316) (model identifiers) or [#58122](https://github.com/vllm-project/vllm/pull/58122) (encoder graphs).
