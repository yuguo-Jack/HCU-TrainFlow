## Benchmarks

Both models ran on `ar-early-stop-drafting` @ `c6d92c0590` plus the AV verify-cost fix (working-tree changes), with Model Runner V2 (`VLLM_USE_V2_MODEL_RUNNER=1`).

Arms: fixed K=3 (AV off), AV only with K=5, and AV + early stop with K=5. Fixed K=3 is the best fixed draft length we measured overall on both models.

**Workload (both models):** SPEED-Bench `throughput_2k`, all categories, chat endpoint.
```bash
vllm bench serve --model <model> --dataset-name speed_bench \
  --speed-bench-dataset-subset throughput_2k --speed-bench-output-len 2048 \
  --backend openai-chat --endpoint /v1/chat/completions \
  --request-rate inf --max-concurrency $C --num-prompts $N \
  --num-warmups $(( C < 16 ? C : 16 )) \
  --temperature 1.0 --top-p 0.95 --top-k 20 --seed 0
```
- C / N: 1 / 24, 8 / 64, 32 / 128, 64 / 256, 128 / 384, 256 / 768.
- Each server first ran a discarded warm pass (C=64, 128 prompts, seed 1).
- No request failed in any run.

**Speculative configs:**

| Arm | `--speculative-config` |
|---|---|
| fixed K=3 | `{"method": <m>, "num_speculative_tokens": 3, "enable_adaptive_verification": false}` |
| AV, K=5 | `{"method": <m>, "num_speculative_tokens": 5, "enable_adaptive_verification": true, "adaptive_draft_depth": false}` |
| AV + early stop, K=5 | `{"method": <m>, "num_speculative_tokens": 5, "enable_adaptive_verification": true, "adaptive_draft_depth": true}` |

### DeepSeek-V4-Flash + MTP (4×GB200, TP4)

```bash
FLASHINFER_DISABLE_VERSION_CHECK=1 VLLM_USE_FLASHINFER_MOE_FP8=0 \
vllm serve deepseek-ai/DeepSeek-V4-Flash -tp 4 --block-size 256 \
  --max-num-seqs 256 --kv-cache-dtype fp8 --tokenizer-mode deepseek_v4 \
  --moe-backend deep_gemm --no-enable-prefix-caching \
  --kernel-config.enable_flashinfer_autotune=False \
  --speculative-config '{"method": "mtp", ...}'
```
- The arms ran one after another on the same node: AV + early stop, then fixed K=3, then AV.
- The benchmark client also used `--tokenizer-mode deepseek_v4`.
- On DSv4's sparse MLA, the verify-cost fit finds a negligible per-request context cost (about 0.004 ms), so AV's pricing here is essentially unchanged by the fix.

### Qwen3-32B + EAGLE3 (GB200, TP1)

This was benchmarked by cherry-picking the changes in https://github.com/vllm-project/vllm/pull/62988, which was necessary to correct the cost model for models with dense attention backends.

```bash
vllm serve Qwen/Qwen3-32B -tp 1 --max-num-seqs 256 --max-model-len 8192 \
  --no-enable-prefix-caching \
  --compilation-config '{"max_cudagraph_capture_size": 2048}' \
  --speculative-config '{"method": "eagle3", "model": "RedHatAI/Qwen3-32B-speculator.eagle3", ...}'
```
- Fixed K=3 and AV ran at the same time on separate GPUs of one node.
- AV + early stop was rerun alone on the same GPU immediately afterwards. Its first run, made at the same time as the others, matched within noise (average +0.6%), so there's no warm-up effect.
- The verify-cost fit gives 0.27 ms of context reads per request, versus about 0 per token.
