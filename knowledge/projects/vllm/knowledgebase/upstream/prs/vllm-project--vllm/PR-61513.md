# [Bugfix][Humming] Give per-tensor FP8 MoE w13 one scale per shard

[Upstream PR](https://github.com/vllm-project/vllm/pull/61513) · state: closed · merged: False

## Original PR description

## Purpose

Fixes the 4 `LM Eval Humming` CI jobs (B200/H100, Default and Activation FP8/INT8), which have failed in every Full CI run since 2026-10-06.

`nm-testing/Qwen3-30B-A3B-Fp8-v1` (per-tensor FP8) fails to load with `--moe-backend humming`:

```
humming/schema/base.py, in _may_process_global_scale
    assert scale.size(0) == (num_experts or 1)
AssertionError
```

Since #56997, the Humming branch of `convert_to_fp8_moe_kernel_format` installs the processed w13 scale on the layer before converting it. For per-tensor checkpoints, `process_fp8_weight_tensor_strategy_moe` has already requantized w13 to one scale per expert (`[E]`). Humming's tensor schema expects one scale per gate/up shard (`[E, 2]`) and calls `scale.view(-1, 2, 1)`, which gives `E/2` rows. Before #56997 it read the on-disk `[E, 2]` parameter.

This change broadcasts the per-expert scale to both shards. Both shards were requantized to that same scale, so the result is exact.
