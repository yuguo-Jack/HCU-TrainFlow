# [KV Connector][NIXL] Add restart lifecycle hooks for checkpoint restore

[Upstream PR](https://github.com/vllm-project/vllm/pull/56852) · state: open · merged: False

## Original PR description


## Purpose

Closes #55155.

This PR adds a connector-level restart lifecycle for KV-transfer connectors:

- Add no-op `quiesce()`, `release_for_checkpoint()`, `reinitialize()`, and
  `verify()` hooks to `KVConnectorBase_V1`.
- Forward lifecycle operations through `MultiConnector`; child quiesce and
  reinitialize operations run concurrently while the wrapper remains a
  synchronous lifecycle barrier.
- Add NIXL lifecycle handling to drain in-flight work, release rebuildable
  transport resources, recreate the NIXL agent and handshake executor,
  re-register retained KV caches, refresh handshake metadata, and verify
  readiness.
- Cover pull and push connector lifecycle behavior, failure handling, and
  checkpoint teardown/rebuild paths.

The external snapshot coordinator owns the surrounding CUDA/distributed
lifecycle. Its connector-facing portion is intentionally limited to:

```python
# Executed in each vLLM worker before checkpointing.
connector.quiesce(timeout)
connector.release_for_checkpoint()

# The external coordinator snapshots/restores runtime state here.

# Executed in each vLLM worker after restore.
connector.reinitialize()
connector.verify()
```

This PR defines only this connector lifecycle boundary; it does not add a
snapshot orchestrator or prescribe the broader checkpoint/restore sequence.

Duplicate-work check: no open PR references #55155. The closest open work,
#52859, adds opt-in NIXL lifecycle tracing; it does not implement connector
restart/checkpoint lifecycle hooks.

AI assistance was used to inspect lifecycle paths, implement portions of the
change, and prepare tests. I reviewed the resulting changes.
