# [ROCm][Disagg][CI] Give Wide-EP headless nodes the MoRIIO KV config

[Upstream PR](https://github.com/vllm-project/vllm/pull/65098) · state: open · merged: False

## Original PR description

## Purpose

Wide-EP headless nodes are started without `--kv-transfer-config`, so ranks 8–15 never open their handshake and notify ports. After [vllm-project/router#386](https://github.com/vllm-project/router/pull/386) the router schedules all 16 DP ranks per role, and KV for ranks 8–15 does not transfer.

## Changes

`.buildkite/amd-disagg/vllm_disagg.sh`, `build_ep_cmd`:

- Pass MoRIIO `--kv-transfer-config` on the headless child and the master.
- `remote_hosts`: the other role's node IPs, master first.
- `remote_dp_size_local`: `GPUS_PER_NODE`. Rank `r` dials `remote_hosts[r / GPUS_PER_NODE]` at port offset `r % GPUS_PER_NODE`.
- NIXL stays master-only.
- `fill_remote_pod_from_config` copies those two fields onto the request when the router omits them. The decode rank holding the request sends the notify.

- okorzh-amd · comment · 2026-11-04T16:33:50Z · [source](https://github.com/vllm-project/vllm/pull/65098#discussion_r4470301349)

File: `vllm/distributed/kv_transfer/kv_connector/v1/moriio/moriio_connector.py` · line 1059

The fill fixes notify, handshake and write routing, but the WRITE release path still targets the master pod. _release_write_prefill_blocks (moriio_connector.py:1007-1010) takes the host from remote_host or the request_id (the prefill master IP) and uses get_port_offset(remote_dp_rank, tp) with the global rank. It never reads remote_hosts, and its request_finished caller (:1620) runs before this fill. With this PR, prefill ranks 8-15 hold WRITE blocks. If a decode request is aborted before it is scheduled, the release for those ranks goes to master_ip:notify_port+8..15, which nothing binds, so the child keeps that request's KV blocks until defer_timeout (60 s default). The hybrid full-prefix-hit release at :1256 has the same problem. 2d2386a6c8 had the fix (fill plus a pod_index host and a fold_local_rank offset inside _release_write_prefill_blocks), and 893fbf1ca8 dropped it. Could you restore it? The code is pre-existing, but this PR is what makes it reachable on Wide-EP.
