# [Model][Qwen4Exp] FP8 QSA main KV cache on Ampere (sm_80, sm_86)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60602) · state: closed · merged: True

## Original PR description

## Summary

`--kv-cache-dtype fp8` crashes for Qwen3.8-Flash-Next on Ampere (sm_80, sm_86): the QSA Triton kernels use an `fp8e4nv` pointer, which Triton supports only from sm_89. Below sm_89 this PR reads the e4m3 cache as bytes and decodes it exactly with a bit cast. Same flag and cache format; BF16 and sm_89+ do not change.

**Why Ampere:** vLLM already enables an FP8 KV cache on sm_80 for other backends (FlashInfer, #24577); this model's QSA path is the gap. We serve Qwen3.8-Flash-Next on 8× A100, where FP8 doubles the KV capacity, and @nkuhn-vmw runs it on 4× RTX 3090 (sm_86).

## Results (8× A100-40GB, TP8 + EP)

- Fixes the crash: 4 FP8 attention tests that fail on `main` at sm_80 now pass.
- KV cache capacity ×1.83 (1.16M → 2.13M tokens). sm_86 (4× RTX 3090, by @nkuhn-vmw): ×1.87, GSM8K unchanged.
- Attention kernel time, FP8 vs BF16 cache: 0.92–1.14×. End to end at concurrency 8, client TPOT p50 is 6 % higher with FP8 (see "Decode cost").
- Prompt-logprob difference FP8 vs BF16 is close to BF16 run-to-run noise (σ 0.115 vs 0.111 nats, 150k tokens).
- Serving the full MLPerf agentic dataset (multi-turn coding, prompts up to ~200k tokens), 3 runs per row:

| Concurrency | KV cache | Requests/s | TTFT p95 (s) | Prefix-cache hit | Prompt tokens received / computed in prefill, per run (M) |
|---|---|---|---|---|---|
| 8 | BF16 | 1.15–1.24 | 1.1–1.3 | 97–98 % | 301–319 / 5.0–7.8 |
| 8 | FP8 | 1.20–1.23 | 1.2 | 98.5 % | 322–326 / 4.7–4.9 |
| 12 | BF16 | 0.96–1.09 | 18–27 | 90–92 % | 235–277 / 21–23 |
| 12 | FP8 | **1.59** | **1.5** | 98.5 % | **457–462 / 6.8–7.1** |
| 16 | BF16 | 0.58–0.64 | 73–83 | 73–77 % | 126–143 / 32–33 |
| 16 | FP8 | **1.58–1.63** | **7.5–10.4** | 96–97 % | **426–445 / 14–15** |

At concurrency 16, FP8 serves 2.7× the requests with ~9× lower p95 TTFT: it receives 3.4× more prompt tokens but computes less than half as many in prefill, because more prefixes stay cached. At concurrency 12, FP8 serves 1.5–1.6× the requests with 12–18× lower p95 TTFT and computes about a third as many prompt tokens in prefill. No preemptions in either arm. Pending: a prefix-caching-off control, and a run without our scheduler hook.

## Changes

- `ops/qsa.py`: one Triton helper, `_maybe_dequant`, chooses the decode by the cache tile's dtype: BF16 passes through, native e4m3 (sm_89+) upcasts to fp16, and `uint8` (the same e4m3 cache read as raw bytes below sm_89) is decoded with a bit cast (`2⁸` folded into the K/V scales on the host). Each K/V tile is decoded right after its load. On sm_80 FP8, 128-column / 4-warp tiles.
- `qsa.py`: on sm_89+ the uint8 cache is viewed as e4m3 once in `forward_qsa`; below sm_89 it stays `uint8`. Below sm_89 with FP8, skip the fused prepare/cache-write kernel (also an FP8 pointer); use the separate path.
- Byte decode: all 254 finite codes decode exactly (checked on A100, below). There is no CI test for it: CI has no sm_80 runner.

**Maintainer refactor (13 Oct, @gau-nernst, `a76baf2fd`…`3327e9bf1`), checked on A100.** It replaced the architecture flags with the dtype dispatch above, dropped the sm_80-only `[N, D]` + transpose K/V load, and interleaved load and dequant. On 1 × A100-SXM4-40GB, with the same synthetic reader inputs (2,048 selected tokens, TP8 geometry), the FP8 output is bitwise identical to the previous head at every row count, and all 254 finite codes decode exactly (the 2 NaN codes read as ±480, as before). | 32 | 0.179 | 0.171 | 0.171 | 0.95 |
| 80 | 0.250 | 0.285 | 0.247 | 0.99 |

| 1,024 | 1.312 | 1.866 | 1.307 | 1.00 |
| 2,048 | 1.991 | 3.002 | 1.989 | 1.00 |

BF16 is unchanged (0.98–1.02). The interleaved order matters on A100: with main's order the byte path is 12–51 % slower from 64 rows up. The serving results above were measured before the refactor; given bitwise-identical output and equal or lower kernel time, they still apply.

**NaN:** below sm_89 the two e4m3 NaN codes decode to ±480, as in vLLM's merged bit-cast FP8 decoders (Marlin FP8 on Ampere, #5975; CPU FP8 KV attention, #39445). A NaN-preserving decode costs 2.2× kernel time on A100, so it is not included. Details and a question for reviewers are under "NaN handling".

No new CPU/GPU sync. Validated outside CI (no A100 in CI). Written with AI assistance (Claude Code); the submitter reviewed every line.

<details>
<summary>NaN handling</summary>

**What this PR does.** Below sm_89, the decode places the e4m3 sign, exponent and mantissa bits into an fp16 and folds `2⁸` into the scales. All 254 finite codes are exact. The two NaN codes (0x7F, 0xFF) decode to ±1.875 · 2⁸ = ±480. The cache can only hold a NaN code if a NaN was written: the CUDA cache writer uses `__nv_cvt_float_to_fp8(..., __NV_SATFINITE, ...)`, which saturates finite overflow to ±448.

**Merged vLLM precedents with the same behaviour:**

| Path | How FP8 is decoded | NaN codes become |
|---|---|---|
| Marlin FP8, Ampere weights (#5975, `csrc/.../marlin/dequant.h`) | bits placed into fp16/bf16 fields, bias by one multiply | finite (±480) |
| CPU FP8 KV attention, AMX/AVX-512 (#39445, `cpu_attn_amx.hpp`) | payload placed into a bf16 field, bias `2¹²⁰` folded into the K/V scales on the host, as here | finite (±480); its writer also clamps NaN input to ±448, so no NaN code is stored |
| ROCm FP8 weights (`w8a8_utils.py`, `fp8_utils.py`) | e4m3fn → e4m3fnuz | the fnuz NaN pattern is set to 0 |

TurboQuant (#38479) handles Ampere differently: it stores keys in Triton's `fp8e4b15`, so its cache format depends on the architecture. This PR keeps one e4m3 format on all architectures.

**What this kernel does with NaN today, on every architecture** (from the code): a NaN value element makes only that output element NaN. A NaN key makes the row's softmax normalizer NaN; `has_values = normalizer > 0` is then false and the row is written as zeros. So a NaN key is already not propagated on sm_89+.

**NaN-preserving decode, measured and not included.** We tried two variants on one A100 against this PR's kernel, on the same inputs:

| Variant | FP8 kernel time vs this PR (8 / 32 / 80 / 128 / 512 / 1,024 / 2,048 rows) |
|---|---|
| per-tile check of `byte & 0x7F` over K and V, NaN row at the end | 1.02 / 1.22 / 1.59 / 1.69 / 2.03 / 2.15 / 2.19 |
| branch-free decode (`(low + 1) & 0x80` sets the top fp16 exponent bit) | 1.00 / 1.26 / 1.62 / 1.86 / 2.26 / 2.25 / 2.35 |

**Question for reviewers:** is ±480 acceptable under the precedents above, or should NaN handling for this kernel be addressed for all architectures in a follow-up?

Each server runs alone on the 8 GPUs, one after another (BF16, BF16 again, FP8):

```
vllm serve Qwen/Qwen3.8-Flash-Next-FP8 --served-model-name flash-fp8 \
  --tensor-parallel-size 8 --enable-expert-parallel --gpu-memory-utilization 0.9 \
  --max-model-len 262144 --max-num-seqs 4 --max-num-batched-tokens 2048 \
  --no-enable-prefix-caching --enforce-eager --no-enable-flashinfer-autotune \
  --engram-config '{"cpu_offload": true}' --attention-config '{"indexer_kv_dtype": "bf16"}' \
  --mamba-cache-dtype bfloat16 --mamba-ssm-cache-dtype float32 \
  --kv-cache-dtype {bfloat16 | fp8}
```

Client steps (script below, sha256 `e8a77f55c7053dca05e7af47c0597c97b2feb96a3797f112900a6be271d957a2`):

```
python3 logprob_trace.py build   http://127.0.0.1:8000 out mlperf_agentic_inference_dataset.jsonl   # once, on the first BF16 server
python3 logprob_trace.py run     http://127.0.0.1:8000 out bf16_a    # then bf16_b and fp8, each on its own server
python3 logprob_trace.py compare out bf16_a bf16_b fp8
```

- `build` tokenizes through the server's `/tokenize` and fixes the prompt token ids once. Every server then gets the same ids, and `compare` checks their hashes.
- Prompt sources: the official MLPerf agentic dataset (sha256 above), and the Python standard library inside the vLLM image (`/usr/lib/python3.12/*.py`, sorted) for the code prompt and the needle haystack.
- `run` sends each prompt to `/v1/completions` with `max_tokens: 1, temperature: 0, prompt_logprobs: 1`. It keeps the logprob of the actual next prompt token at each position, and fails on a missing or non-finite value.
- `compare` reports, per prompt, the standard deviation and mean of the per-position difference, and the share of positions that differ by more than 1 nat.

```python
"""Per-position prompt-logprob trace and needle check against one running vLLM server (upstream #60602 evidence).

Method of vllm-project/vllm#55557: send identical prompt token ids with prompt_logprobs=1 at temperature 0, keep the
logprob of each actual next prompt token, and compare FP8-KV against BF16 with the BF16-vs-BF16 run-to-run noise as the
floor. Prompt ids are fixed once (build) and reused verbatim by every arm; each arm records the prompt hash it served.

This is a numerical diagnostic of the KV-cache dtype only (prefix caching and MTP off, eager). It is not a task-quality
or serving result. Every step fails loudly: a short source, a missing position or a non-finite logprob is an error.

  logprob_trace.py build   <base_url> <out_dir> <dataset.jsonl>
  logprob_trace.py run     <base_url> <out_dir> <arm>
  logprob_trace.py compare <out_dir> <arm_a> <arm_b> <arm_fp8>
"""
import hashlib
import json
import math
import os
import sys
import time
import urllib.request
from pathlib import Path

MODEL = "flash-fp8"
TARGETS = {"agentic_150k": 150_000, "code_30k": 30_000, "text_8k": 8_000}
NEEDLE_TOKENS = 125_000
NEEDLE_DEPTHS = (0.1, 0.5, 0.9)
NEEDLE = "The secret passphrase for the archive is amber-falcon-42."
NEEDLE_ANSWER = "amber-falcon-42"
QUESTION = "\n\nQuestion: What is the secret passphrase for the archive? Answer: The secret passphrase is"
CODE_ROOT = Path("/usr/lib/python3.12")
METADATA_TYPE = "dataset_metadata"  # the full dataset's header row, skipped as MLCommons Endpoints does
REQUEST_SECONDS = 1500


def post(base, path, body):
    request = urllib.request.Request(base + path, json.dumps(body).encode(), {"Content-Type": "application/json"})
    with urllib.request.urlopen(request, timeout=REQUEST_SECONDS) as response:
        return json.loads(response.read())


def tokenize(base, text):
    return post(base, "/tokenize", {"model": MODEL, "prompt": text, "add_special_tokens": False})["tokens"]


def ids_sha256(ids):
    return hashlib.sha256(json.dumps(ids).encode()).hexdigest()


def write_private(path, value):
    path.write_text(json.dumps(value))
    os.chmod(path, 0o600)


def code_text(limit_chars):
    parts, size = [], 0
    for path in sorted(CODE_ROOT.glob("*.py")):
        text = path.read_text(errors="replace")
        parts.append(text)
        size += len(text)
        if size >= limit_chars:
            return "\n".join(parts)
    raise ValueError(f"code source has {size} characters, fewer than {limit_chars}")


def agentic_text(dataset, limit_chars):
    """Messages of the longest conversations, as role-tagged text, until limit_chars."""
    conversations = {}
    for line in open(dataset):
        row = json.loads(line)
        if row.get("_type") == METADATA_TYPE:
            continue
        text = " ".join(str(row.get(key) or "") for key in ("content", "reasoning_content", "tool_calls"))
        conversations.setdefault(row["conversation_id"], []).append(f"[{row['role']}] {text}")
    parts, size = [], 0
    for conversation in sorted(conversations.values(), key=lambda c: -sum(map(len, c))):
        for message in conversation:
            parts.append(message)
            size += len(message)
            if size >= limit_chars:
                return "\n".join(parts)
    raise ValueError(f"dataset text has {size} characters, fewer than {limit_chars}")


def exactly(ids, count, name):
    if len(ids) < count:
        raise ValueError(f"{name}: source gives {len(ids)} tokens, fewer than {count}")
    return ids[:count]


def build(base, out, dataset):
    out = Path(out)
    sources = {"agentic_150k": agentic_text(dataset, 1_200_000), "code_30k": code_text(300_000),
               "text_8k": agentic_text(dataset, 80_000)}
    prompts = {name: exactly(tokenize(base, sources[name]), TARGETS[name], name) for name in TARGETS}
    needle, question = tokenize(base, " " + NEEDLE + " "), tokenize(base, QUESTION)
    body = NEEDLE_TOKENS - len(needle) - len(question)
    haystack = exactly(tokenize(base, code_text(1_200_000)), body, "haystack")
    needles, positions = {}, {}
    for depth in NEEDLE_DEPTHS:
        name, at = f"needle_{int(depth * 100)}", int(body * depth)
        needles[name] = haystack[:at] + needle + haystack[at:] + question
        positions[name] = at
    write_private(out / "prompts.json", {"trace": prompts, "needle": needles})
    summary = {"lengths": {k: len(v) for k, v in {**prompts, **needles}.items()}, "needle_positions": positions,
               "sha256": {k: ids_sha256(v) for k, v in {**prompts, **needles}.items()}}
    write_private(out / "prompts-summary.json", summary)
    print(json.dumps(summary["lengths"]))


def trace(base, ids, name):
    result = post(base, "/v1/completions", {"model": MODEL, "prompt": ids, "max_tokens": 1, "temperature": 0,
                                            "prompt_logprobs": 1})
    choice, usage = result["choices"][0], result.get("usage") or {}
    rows = choice["prompt_logprobs"]
    if len(rows) != len(ids) or usage.get("prompt_tokens") != len(ids):
        raise ValueError(f"{name}: {len(rows)} logprob rows, usage {usage.get('prompt_tokens')}, sent {len(ids)}")
    values = []
    for position in range(1, len(ids)):
        chosen = (rows[position] or {}).get(str(ids[position]))
        if chosen is None or not math.isfinite(chosen["logprob"]):
            raise ValueError(f"{name}: no finite logprob for the prompt token at position {position}")
        values.append(chosen["logprob"])
    return values, {"usage": usage, "finish_reason": choice.get("finish_reason")}


def run(base, out, arm):
    out = Path(out)
    prompts = json.loads((out / "prompts.json").read_text())
    record = {"arm": arm, "trace": {}, "needle": {}, "seconds": {}, "api": {}, "sha256": {}}
    for name, ids in prompts["trace"].items():
        start = time.time()
        record["trace"][name], record["api"][name] = trace(base, ids, name)
        record["seconds"][name], record["sha256"][name] = time.time() - start, ids_sha256(ids)
    for name, ids in prompts["needle"].items():
        answer = post(base, "/v1/completions", {"model": MODEL, "prompt": ids, "max_tokens": 16, "temperature": 0})
        choice = answer["choices"][0]
        record["needle"][name] = {"text": choice["text"], "found": NEEDLE_ANSWER in choice["text"],
                                  "finish_reason": choice.get("finish_reason"), "usage": answer.get("usage")}
        record["sha256"][name] = ids_sha256(ids)
    write_private(out / f"{arm}.json", record)

                      "seconds": record["seconds"]}))


def spread(first, second, name):
    if len(first) != len(second):
        raise ValueError(f"{name}: {len(first)} and {len(second)} positions differ")
    diffs = [b - a for a, b in zip(first, second)]
    mean = sum(diffs) / len(diffs)
    sigma = math.sqrt(sum((d - mean) ** 2 for d in diffs) / len(diffs))
    return {"positions": len(diffs), "sigma_nat": round(sigma, 4), "mean_nat": round(mean, 5),
            "share_over_1_nat": round(sum(abs(d) > 1 for d in diffs) / len(diffs), 5)}


def compare(out, arm_a, arm_b, arm_fp8):
    out = Path(out)
    a, b, f = (json.loads((out / f"{x}.json").read_text()) for x in (arm_a, arm_b, arm_fp8))
    if not a["sha256"] == b["sha256"] == f["sha256"]:
        raise ValueError("arms served different prompt ids")
    table = {name: {"bf16_noise": spread(a["trace"][name], b["trace"][name], name),
                    "fp8_vs_bf16": spread(a["trace"][name], f["trace"][name], name)} for name in a["trace"]}
    table["needle"] = {arm["arm"]: {k: v["found"] for k, v in arm["needle"].items()} for arm in (a, b, f)}
    write_private(out / "compare.json", table)
    print(json.dumps(table, indent=1))


if __name__ == "__main__":
    {"build": build, "run": run, "compare": compare}[sys.argv[1]](*sys.argv[2:])
```
