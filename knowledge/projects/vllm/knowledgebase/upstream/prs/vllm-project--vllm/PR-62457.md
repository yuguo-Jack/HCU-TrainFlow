# [Bugfix][ROCm][MoRIIO] Support heterogeneous TP in READ mode for split KV heads and Mamba state

[Upstream PR](https://github.com/vllm-project/vllm/pull/62457) · state: open · merged: False

## Original PR description


## Overview

MoRIIO READ between prefill and decode instances of different TP sizes, for split KV heads (GQA/MHA) and Mamba/KDA state. It reuses #61726's TP mapping and slice offsets.

**Stacked on https://github.com/vllm-project/vllm/pull/62473** (READ fan-in release). Please review and merge that first. Until it merges, this diff also contains its changes. The part specific to this PR, on top of PR https://github.com/vllm-project/vllm/pull/62473

## Claims

- **Split heads and recurrent state across TP sizes.** READ used to accept only MLA latents and fully replicated KV heads, and raised `NotImplementedError` for split GQA/MHA heads and Mamba/KDA state. Each decode rank now reads its head and state slices from every prefill rank that holds them.
- **Per-layer KV-head counts.** Slices follow each layer's KV-head count, so models whose layers differ (Gemma4: 4 KV heads in the sliding layers, 8 in full attention) read correctly. Raised in review on #62457.

## Validation

- **Unit tests:** `test_moriio_read_tp.py` (from PR https://github.com/vllm-project/vllm/pull/62473) gains the full matrix. Every fixture model runs in every TP pair (1→2, 2→4, 2→1, 4→2, 1→4), with HMA on and off and 3 cache-layout pairs. The fixture models include GQA, sliding window, GDN and KDA+MLA hybrids, and a Gemma4-like `mixed_heads` model, which also runs at TP4 ↔ TP8.
  - It also covers a block-size mismatch, a peer without head layouts, the equal-TP session key, and lazy-handshake targets.
  - Before the per-layer fix, the mixed-head cases failed with the error from the review: `Head slice local [0, 4) / remote [0, 4) is outside 4 / 2 heads`.
- **Mapping properties** (`test_moriio_tp_mapping.py`), over every TP pair up to 8:
  - READ moves exactly the (prefill rank, decode rank, slice) set WRITE moves;
  - every prefill rank gets exactly `get_moriio_expected_ack_count` releases.
- **Full MoRIIO unit suite:** 1080 passed. Ruff is clean, and mypy reports no new errors.
- **GPU, MI355X, xGMI, ROCm 10:** READ prefill TP1 → decode TP2 passes for:
  - qwen3_dense (split GQA heads)
  - deepseek_v3 (MLA)
  - gemma3 (sliding window)
  - qwen3_5_moe (GDN state slices)

  These checks are exact external hits plus finite log-probs; a direct serve at another TP size is not an exact reference.
- **READ fan-in, bit-exact against WRITE at the same TP sizes and weights.** One MI355X node, xGMI, ROCm 7.2.3, dummy weights, the same 3 prompts. READ prefill TP2 → decode TP1 compared with WRITE prefill TP2 → decode TP1 (#61726's fan-in path):

  | Model | What READ gathers | Result |
  |---|---|---|
  | qwen3_dense (TRITON_ATTN) | split GQA heads from both prefill ranks | identical top-20 and log-probs on all 3 prompts (max difference 0.0); hits 2093 (READ, `len − 1`) vs 2096 (WRITE) |
  | qwen3_5_moe (TRITON_ATTN) | attention head slices + GDN state slices | identical on all 3 prompts; hits 3467 on both |

  On one node, MoRI's xGMI backend cannot open a session to the second prefill GPU from a decode rank that sees one GPU. For this check, xGMI memory registration ran under `torch.cuda.device(0)`, a local MoRI-side workaround that is **not** part of this PR. Current main rejects these cases with `NotImplementedError`.
- **Cross-node RDMA:** on our MI355X nodes with ionic NICs, MoRIIO READ returns wrong KV even at equal TP on unmodified main. Cross-node WRITE over the same nodes is bit-exact. That is a pre-existing READ-over-ionic issue that this PR doesn't change, tracked separately.

## Details

READ flow for one request, prefill TP4 → decode TP2 with split GQA heads (decode rank 1 shown):

1. Every prefill rank computes and keeps its KV shard.
2. The proxy forwards the block ids and `tp_size=4` to decode.
3. In `start_load_kv`, decode rank 1 handshakes once with prefill ranks 2 and 3, with sessions keyed `..._dp0_tp2` and `..._dp0_tp3`.
4. `_read_blocks` posts one READ per source and layer: heads 0–1 of each prefill rank land at heads 0–1 and 2–3 of the decode block.
5. Once every read has landed, decode releases prefill ranks 2 and 3 (PR https://github.com/vllm-project/vllm/pull/62473).

- **Mapping:** `compute_read_tp_mapping` derives a decode rank's sources from the WRITE mapping: it reads from each prefill rank exactly what that rank would write into it. Sources are computed per attention layer from that layer's KV-head count. Mamba layers use the request's mapping. Sessions are built once per source rank, and the eager and lazy handshakes cover every layer's sources.
- **Offsets:** reuse `compute_head_slice_offsets` and `compute_mamba_slice_offsets` with source and destination swapped.
- **xGMI limitation:** on one node, MoRI's xGMI backend cannot open a session to a peer GPU whose device index is at least the number of GPUs the dialing process sees. READ fan-in of split heads or recurrent state has to reach the second prefill GPU from a decode rank that sees one GPU, so it needs RDMA. Those E2E cases skip on xGMI, and the usage guide documents it.
- **The same per-layer bug in WRITE** is fixed separately on main: `fix/moriio-write-per-layer-heads`.
