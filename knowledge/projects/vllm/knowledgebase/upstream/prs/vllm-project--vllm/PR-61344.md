# [Kernel][Spec Decode] Fuse temperature scaling into the rejection-sampling kernels

[Upstream PR](https://github.com/vllm-project/vllm/pull/61344) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Targets #61024 (SIG Spec Decode: kernel fusion for rejection sampling). Removes a redundant FP32 copy+divide pass before verification by teaching the kernels to divide by temperature on load, then skipping the copy entirely when temperature is the only scaling a chunk needs.

## Claims

- `rejection_sample()` gains `target_logits_pre_scaled: bool = True` (default unchanged). When `False`, the verify kernels divide raw `target_logits` by `temperature` on load instead of requiring a pre-scaled FP32 copy — same "scale on load" pattern `draft_logits` already uses.
- `RejectionSampler._verify` now skips `apply_sampling_params`'s FP32 copy of `target_logits` whenever a chunk needs nothing beyond temperature (no logits processors, no thinking-budget forcing, no `top_p`/`top_k`/`min_p` on a non-greedy row, and no logprobs/sampling-mask mode that needs the scaled values) — raw logits go straight to `rejection_sample(..., target_logits_pre_scaled=False)`.
- Net effect: one fewer memory-bound kernel launch + one fewer full read/write pass over `target_logits` for the common temperature-only case. `top_p`/`top_k`/`min_p`, logits processors, and thinking-budget cases are untouched and still take the existing path.

New tests (`tests/v1/worker/test_gpu_sampler_flags.py::test_needs_only_temperature_scaling_*`) couldn't run in
this venv: `flashinfer-python==0.6.12` vs. the repo's `0.7.2` pin breaks `Sampler`'s import chain, independent
of this change (same break on unmodified `origin/main`). Verified the decision logic directly instead, by
binding the real `Sampler.needs_only_temperature_scaling` to a `SamplingStates`-backed instance (bypassing
only the broken import, not the logic): temp-only -> `True`, any non-greedy restriction -> `False`,
restriction confined to a greedy row -> `True`. CI should still run these for real.

No end-to-end throughput number -- this session's GPUs were contended for the full duration. The claim is
scoped to "removes the copy+divide kernel for the temperature-only case," verified structurally and via the
bit-identical kernel test above, not a measured speedup.

## Details

**Why:** `rejection_sampler.py`'s own TODO: chunking `target_logits` at a 1GB cap exists only because
`apply_sampling_params` scales it into a second FP32 buffer first. The verify kernels already upcast every
value to fp32 on load; this gives `target_logits` the same on-load path `draft_logits` already has, then
wires the one real caller to use it when safe.

**Scope:** only the temperature-only sub-case. `min_p`/`top_k`/`top_p`, logits processors, and
thinking-budget forcing are unchanged.

**Docs:** none -- internal fast path, output is bit-identical to before, no user-visible behavior changes.

**Known unrelated issue found during validation:** `test_rejection_sampler_utils.py`'s block-verification
tests are flaky (6-10 failures/run) on unmodified `main`. Not fixed here, out of scope; flagging in case it
isn't already tracked.

- zyongye · comment · 2026-11-02T18:50:48Z · [source](https://github.com/vllm-project/vllm/pull/61344#issuecomment-6585471228)

While stress-testing #65102, which builds on this PR's two commits, I found that the temperature-only skip changes FLy's decisions when T is not 0 or 1.

`rejection_sample` computes FLy's entropy up front from the logits it receives (`compute_fly_entropy(target_logits[:, :vocab_size], ..., from_logits=True)`), before any kernel applies the temperature. With `skip_scaling`, those are the raw logits, so FLy measures the entropy of softmax(x) instead of softmax(x / T).

Measured on this PR's `rejection_sampler_utils.py` (its commits rebased onto current main; GB300, real Qwen3-0.6B rows, 512 requests per configuration, FLy window 2 / threshold 0.3 / top-k 3). Each row compares the raw logits with `target_logits_pre_scaled=False` (what the skip passes) against `apply_temperature`'d logits (what `_verify` passes with the skip off):

| K | T | requests with the same tokens | mean tokens per step, skip vs processed |
|---|---|---|---|
| 3 | 0.6 | 98.8% | 3.45 vs 3.42 |
| 7 | 0.6 | 94.1% | 6.64 vs 6.35 |
| 7 | 0.6, one-hot drafts | 92.6% | 5.44 vs 5.12 |
| 7 | 1.3 | 96.5% | 6.64 vs 6.82 |

With FLy off, both inputs give bitwise-identical tokens in every configuration, and with FLy on they also match at T = 0 and T = 1, so the difference comes from the entropy alone. Below T = 1 the raw logits are flatter than the scaled ones, so FLy accepts more drafts than its threshold intends; above T = 1 it accepts fewer.

The fix in #65102 ([commit](https://github.com/vllm-project/vllm/pull/65102/commits/9160b84d2549176e3cd2684257d945e65994704d)) keeps processed logits for FLy:

```diff
         needs_processed_logits = (
             self.sampler.logprobs_mode in PROCESSED_LOGPROBS_MODES
             or self.sampler.return_sampling_mask
+            or self.fly_window_size > 0
         )
```

It also adds `assert target_logits_pre_scaled` to FLy's branch in `rejection_sample`, and a test, `test_fly_verifies_processed_logits` in `tests/v1/worker/test_gpu_rejection_sampler_chunking.py`, that fails without the change. Feel free to pull it into this PR; I'll drop it from #65102 once it's here.
