# [Kernel][Spec Decode] Fuse temperature scaling into the rejection-sampling kernels

[Upstream PR](https://github.com/vllm-project/vllm/pull/61344) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Targets #61024 (Q4 2026 roadmap, SIG Spec Decode: "optimize fusion and kernels for low-latency inference, including rejection sampling"). Folds temperature scaling into the rejection-sampling kernels so `target_logits` can be passed raw instead of pre-divided into a fresh FP32 buffer.

## Claims

- Adds `target_logits_pre_scaled: bool = True` to `rejection_sample()`. Default unchanged, so every existing caller is a no-op.
- When `target_logits_pre_scaled=False`, `target_logits` is passed raw and divided by `temperature` on load inside the kernels, in the same 5 places `draft_logits` is already handled this way (`_compute_local_logits_stats_kernel`, `_compute_global_logprobs_and_logsumexp`, `_compute_global_residual_mass`, and `_resample_kernel`'s three `residual_logits` branches), guarded against div-by-zero where the bonus-token branch can be reached at `temperature == 0`.
- This is kernel-side groundwork. It does not yet remove the FP32 `processed_logits` buffer itself -- see "Not yet done" below.

## Validation

```
.venv/bin/python -m pytest tests/v1/spec_decode/test_rejection_sampler_utils.py tests/v1/spec_decode/test_synthetic_rejection_sampler_utils.py tests/v1/worker/test_gpu_rejection_sampler_chunking.py tests/v1/worker/test_gpu_rejection_sampler_i64.py -q
# 88 passed (71 + 17 across the four files, no regressions)
```

New test: `tests/v1/spec_decode/test_rejection_sampler_utils.py::test_raw_target_logits_matches_pre_scaled_target_logits`. Builds the same `rejection_sample()` inputs twice -- once with pre-scaled `target_logits` (default path) and once raw with `target_logits_pre_scaled=False` -- with the same seed, and asserts sampled tokens and `num_sampled` are bit-identical (`rtol=0, atol=0`). Parametrized over temperature (0.0 greedy / 0.73 / 1.0), one-hot vs full `draft_logits`, and block verification on/off: 12 cases, all passing on A100.

No model eval: this path isn't wired into any model's forward pass yet (nothing calls `rejection_sample` with `target_logits_pre_scaled=False` outside the new test).

## Details

**Why:** right at the top of `vllm/v1/worker/gpu/spec_decode/rejection_sampler.py`:
```
# TODO(mgoin): Chunking is a workaround. The rejection kernels already upcast
# per vocab block on load and apply ops like temperature and gumbel, so folding
# sampling-param application into those kernels would remove this buffer and
# its traffic entirely.
```
`apply_sampling_params` currently copies `target_logits` into a fresh FP32 buffer and divides it by `temperature` before `rejection_sample()` ever sees it. That buffer is the reason verification has to chunk the batch at a 1GB cap (`MAX_CHUNK_BYTES`) at all. `draft_logits` already skips this: it's passed raw and every rejection kernel divides it by `temperature` on load. This PR extends the same "scale on load" convention to `target_logits`.

**Scope:** temperature only. `min_p`/`top_k`/`top_p` are nonlinear filtering ops, not linear rescalings of the logits, so they can't be folded the same way -- out of scope here.

**Duplicate-work check:** searched `gh issue list`/`gh pr list` (open PRs/issues, several keyword variants against #61024's roadmap bullet and against this specific TODO) before starting; found no existing issue or PR claiming this slice. Left a comment on #61024 noting this PR is in progress.

**Not yet done** (follow-up commits on this PR, not yet started): wiring `rejection_sampler.py`'s `_verify` to pass raw `target_logits` with `target_logits_pre_scaled=False` and skip `apply_sampling_params`'s temperature step and its FP32 buffer materialization when no other sampling-param processing (logits processors, min_p, top_k/top_p) is active. That caller-side change is what actually removes the buffer and lets the chunking cap be raised or removed -- this commit is only the kernel-side groundwork enabling it.
