# [Bugfix][Security] Disable ambient NETRC credentials on media fetches

[Upstream PR](https://github.com/vllm-project/vllm/pull/54729) · state: open · merged: False

## Original PR description

## Summary

- Disable ambient credential inheritance (NETRC, proxy auth) on the HTTP client used for caller-supplied media URLs, preventing a confused-deputy vulnerability where vLLM's own process credentials could be applied to attacker-chosen URLs.
- Add a `trust_env` parameter to `HTTPConnection` (default `False`) so the `global_http_connection` singleton used by `MediaConnector` no longer attaches ambient credentials to outbound media requests.
- Document the credential isolation behavior in `docs/usage/security.md`.

## Why this matters

The `aiohttp.ClientSession(trust_env=True)` setting and the default `requests.Session()` both inherit NETRC credentials from the process environment. A caller who can supply a media URL (via `/v1/chat/completions/render` or any multimodal endpoint) could cause vLLM to fetch a credential-protected resource using vLLM's own identity and return the content in the processed tensor response. This is a confused-deputy / ambient-authority issue (CWE-441) distinct from the destination-based SSRF that `--allowed-media-domains` mitigates.

## The change

| File | What changed |
|---|---|
| `vllm/connections.py` | Added `trust_env: bool = False` param to `HTTPConnection.__init__`; sync client sets `session.trust_env = self._trust_env`; async client passes `trust_env=self._trust_env` to `aiohttp.ClientSession` |
| `tests/test_connections.py` | 4 new tests: default connection disables trust_env (sync + async), opt-in trust_env=True works (sync + async) |
| `docs/usage/security.md` | Note in "Restrict Domains Access for Media URLs" section documenting credential isolation |

- Manny7717 · APPROVED · 2026-09-01T14:16:05Z · [source](https://github.com/vllm-project/vllm/pull/54729#pullrequestreview-5079155099)

Verified on head 846fd7e8 against origin/main (live probes + tests; repo venv, pytest-asyncio added locally for the async tests — env gap only).

**Vulnerability is real (both clients leak ambient creds on main):**
- Sync: `requests.Session()` defaults `trust_env=True` (netrc + env-proxy auth).
- Async: main explicitly constructs `aiohttp.ClientSession(trust_env=True)` (verified in origin/main).
- Live probe with a real local Basic-auth server + netrc entry for 127.0.0.1: `trust_env=True` session sends `Authorization: Basic ...` and gets **200**; with the new `trust_env=False` the same request sends no auth and gets **401**. Executed for BOTH clients — the confused-deputy claim (CWE-441, attacker-supplied media URL fetched with vLLM's own identity) is demonstrated end-to-end.

**Fix correct:** `HTTPConnection(trust_env: bool = False)` gates both client constructions; opt-in remains available via the constructor for callers that need proxies/netrc. `global_http_connection = HTTPConnection()` is the ONLY construction site in the codebase (grep-verified), and MediaConnector receives it as its default — so media fetches (sync `get_bytes` and async paths) are covered with no caller changes.

**Regression-proven:** new test file applied to origin/main worktree → 4/4 new tests FAIL (`TypeError: unexpected keyword argument 'trust_env'` + trust_env assertions vs main's True defaults); 9/9 PASS on head. The 5 pre-existing tests (body limits, streaming, etc.) pass on both.

**Docs:** security.md note accurately describes the credential isolation + the non-authorization-boundary caveat for `--allowed-media-domains`.

Non-blocking notes:
1. The singleton flip also affects `vllm/assets/base.py` sync `download_file` (vLLM's own public S3 assets) — netrc is irrelevant there (public bucket), but env-proxy-gated networks that previously routed asset downloads through a proxy will now connect directly. If that's a real deployment pattern, a dedicated `HTTPConnection(trust_env=True)` for assets (or an env override) would be a clean follow-up; the current default is the right security posture for attacker-influenced URLs.
2. `run_batch.py` uses `async_get_bytes` (async client) — same credential isolation now applies there; consistent with the media fix.

Clean, minimal, security-positive change. APPROVE.
