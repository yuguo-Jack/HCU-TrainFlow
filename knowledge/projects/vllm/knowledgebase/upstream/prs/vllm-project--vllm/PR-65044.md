# [Doc] Move the Ascend content of the recipes to vllm-ascend overlays

[Upstream PR](https://github.com/vllm-project/vllm/pull/65044) · state: closed · merged: True

## Original PR description



## Overview

Removes the Huawei Ascend content from the 9 vLLM recipes that carry it. [vllm-project/vllm-ascend](https://github.com/vllm-project/vllm-ascend/tree/main/recipes/overlays) already ships the same content as overlays, and vllm-project/recipes merges them at build time (vllm-project/recipes#1160), so the site keeps rendering it.

## Claims

- Ascend hardware keys, variants, overrides and hardware notes now have a single owner, vllm-ascend. Commands rendered on recipes.vllm.ai do not change.
- The one visible change is pill order on Kimi-K3: the `ascend_w4a8` variant moves after `fp8`, because overlay variants render last.
- vllm-project/recipes can enable `scope.exclude_brands: [Huawei]` on the `vllm` source once this merges and the lock bumps, which stops Ascend content from returning here.

## Validation

Compared the renderer's full JSON API output (`be6e6b2`) for vLLM `16d667348d` plus vllm-ascend `6d2866b717`, before and after this change:

```bash
# Same check as this repo's Recipes PR check
node scripts/validate-source.mjs --source vllm --dir <this branch>/recipes
# ✓ vllm recipes ... are valid against the renderer
```

- Current `main` with `exclude_brands: [Huawei]`: strict assemble fails on these 9 recipes.
- This branch with `exclude_brands: [Huawei]`: strict assemble and the JSON API build both pass.
- Output diff, ignoring provenance (`source`): 22,589 files before and after, none added or removed. 22,558 are identical, and the rest differ only in order. `models.json` swaps two Kimi-K3 entries, and about 30 recipe JSON files change key order (for example `meta.hardware`). The Kimi-K3 variant move above is the only order change that affects the page; variant and strategy order is unchanged on the other affected recipes.
- The Qwen3.8-27B guide renders byte-identical (SHA-1 checked), with the Ascend section placed at its `<!-- overlay:vllm-ascend:ascend -->` marker.
- `pre-commit run --files <changed files>` passes.

This changes recipe metadata only, so no model evaluation applies. Nothing was run on Ascend hardware, since the rendered commands are unchanged.

## Details

**Merge order:** this PR → lock bump in vllm-project/recipes → `exclude_brands: [Huawei]` there. Enabling the scope first would fail this repo's Recipes check and every lock bump.

**What stays here:** the scope check covers hardware-keyed content only, so this PR leaves the following alone:
- Prose that mentions Ascend: `performance_headline`, descriptions, guide references, and the GLM-5.3-Flash guide. Cleaning these up is a separate decision.
- Ascend-only speculative modes such as `qwen3_5_mtp` ("MTP (Ascend)"). Overlays can't add a mode today, and these modes reference variants that now come from the overlay, so renaming such a variant in vllm-ascend needs a matching change here.

**Comments:** 91 comment lines recording Ascend evidence and rationale are removed, and the overlays don't carry them. They remain in this repo's git history and could be copied to vllm-ascend.

**Open PRs affected:** #62668 (Kimi-K3 Ascend) and #62794 (DeepSeek-V4.1-Flash Ascend A3) belong in vllm-ascend, where vllm-project/vllm-ascend#19991 and vllm-project/vllm-ascend#20065 are related. #65021, #64775 and #64070 touch the same files and may need a rebase.

**Not a duplicate:** searched open PRs for Ascend, overlay and recipe keywords. None of them removes this content.
