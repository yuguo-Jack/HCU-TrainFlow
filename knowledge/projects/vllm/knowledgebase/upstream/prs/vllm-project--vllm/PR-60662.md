# [CI] Enroll five more steps in automatic sharding

[Upstream PR](https://github.com/vllm-project/vllm/pull/60662) · state: closed · merged: True

## Original PR description

## Purpose

Second batch of automatic sharding (vllm-project/ci-infra#700), following #60492. This adds `automatic_shard: true` to five more steps whose commands are plain pytest:

| Step | Planned shards |
|---|---|
| `entrypoints-unit-tests` | 2 |
| `entrypoints-integration-speech_to_text` | 2 |
| `entrypoints-integration-responses-api` | 2 |
| `pytorch-compilation-passes-unit-tests` | 2 |
| `e2e-core-1-gpu` | 2 |

As in #60492, the generator packs each step's test files into shards of up to 18 minutes of test time using main's per-file timings. If timings are missing or planning fails, the step runs as its usual single job. The AMD mirrors inherit the flag, but the generator doesn't shard AMD steps, so they still run as one job.

`entrypoints-integration-multimodal` was in the first revision and is left out. In its shard, `llm/test_mm_cache_external_injection.py` ran first in a fresh pytest process. The first engine created in a process reapplies vLLM's logging config, which sets `propagate: False` on the `vllm` logger and undoes `caplog_vllm`, so the test's log assertion saw no records. On main it passes only because `llm/test_chat.py` creates an engine earlier in the same process. It can be enrolled once that test no longer depends on running after another file.

## Test Plan

- Ran ci-infra's `runtime_shard.plan_step` against this checkout. All five steps produce a 2-shard plan within budget. Two files have no main timing yet and are counted at the step's median: `compile/passes/test_rocm_aiter_qk_norm_rope_kvcache_fusion.py` and `entrypoints/launchers/test_grpc_health.py`.
- This PR's CI build should show each step as 2 parallel shard jobs with a planning annotation, and every collected test should run in exactly one shard.
