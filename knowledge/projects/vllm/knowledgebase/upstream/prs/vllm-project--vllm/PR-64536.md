# [Feature][Structured Output] Support continued assistant prefixes

[Upstream PR](https://github.com/vllm-project/vllm/pull/64536) · state: open · merged: False

## Original PR description



## Overview

Add opt-in `structured_output_prefill` for Chat Completions so a continued assistant message can complete a structured output that has already begun. Addresses #64268.

## Claims

- Initialize the request's grammar with the final assistant content before producing its first token mask; preserve the default constraint on newly generated text.
- Support xgrammar, guidance, and outlines for their existing constraint types. Reject incompatible usage and invalid or transformed prefixes before generation.
- Cover streaming, `echo`, independent request states, and grammar rollback after prefix initialization.

## Details

`continue_final_message` puts the assistant prefix in the prompt, while the grammar previously began with only the schema. The new flag carries the exact assistant text to grammar initialization. XGrammar consumes it through `accept_string`; guidance and outlines require lossless tokenization without special token IDs. A rendered-prompt suffix check detects template transformations and prompt truncation.

Admission validation uses a separate matcher to return HTTP 400 for invalid prefixes. The engine creates its own request-local matcher; compiler caches are reused. This adds validation/compilation work for opted-in requests. A nonempty accepted prefix also marks structured content as already started for reasoning gating. Beam search and lm-format-enforcer are rejected for this option.

Enable it alongside `continue_final_message: true` and `add_generation_prompt: false`. With default `echo: false`, concatenate the returned content with the assistant prefix. With `echo: true`, the returned content includes the prefix. Usage and backend limits are documented in `docs/features/structured_outputs.md`.

Duplicate-work checks found no open PR referencing #64268 or implementing this opt-in. The existing issue discussion includes another contributor's reproduction and contract discussion; this PR implements option 3 from the report while preserving default behavior.

- Default behavior is unchanged without the flag.
- With `structured_output_prefill: true`, two-request continuations are valid for `json_object`, `choice`, `regex` and `grammar`. With a 4-line change that sends the flag on later chunks, all four are valid, while unconstrained requests are still chunked.
