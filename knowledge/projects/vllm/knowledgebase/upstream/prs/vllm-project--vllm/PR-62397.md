# [DO NOT MERGE][XPU][CI] Trace TP=2 startup and forward timeout

[Upstream PR](https://github.com/vllm-project/vllm/pull/62397) · state: open · merged: False

## Original PR description

Temporary AI-assisted diagnostics for the TP=2 startup/forward timeout in [Intel CI build 15354](https://buildkite.com/vllm/intel-ci/builds/15354#01a17636-cc33-476f-895c-61788cf0d7fe), extending this existing debug PR rather than opening a competing fix. Adds XPU-only `torch.xpu.synchronize()` before/after worker and MRV1/MRV2 loading, profiling, input preparation, forward and sampling, plus Llama embedding/layer/attention/MLP boundaries and 30-second worker stack dumps. Logs include rank/PID/thread/device/stage and synchronization begin/end; exception unwinding never synchronizes, compiled model internals bypass diagnostics, and graph capture skips synchronization.

**DO NOT MERGE:** blocking synchronization intentionally changes timing and performance and may mask races; this is evidence gathering, not a confirmed fix. Retains the existing two-iteration shutdown loop and XCCL/signal diagnostics. Human review is required before any merge.

**Validation:** Intel Arc Pro B60, devices 6/7; pre-commit passed. Before adding model-level markers, shutdown selection: **10 passed, 4 skipped**; final model instrumentation: MRV2 **4 passed** (including TP=2 startup/runtime errors, successful generation/shutdown, and compiled in-process execution), MRV1 TP=2 **1 passed**. Both ranks emitted Llama projection/layer synchronization markers; fullgraph decorator/context tracing also passed. No local timeout reproduction; the existing injected startup test also emits a rank-1 argument `TypeError`, so its pass alone does not establish correct peer-forward behavior. Some runs report multiprocessing resource-tracker warnings on exit.
