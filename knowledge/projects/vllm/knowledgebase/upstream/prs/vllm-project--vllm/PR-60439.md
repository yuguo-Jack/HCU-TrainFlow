# [Bugfix][Mamba] Pad ReplaySSM groups for tensor parallelism

[Upstream PR](https://github.com/vllm-project/vllm/pull/60439) · state: closed · merged: False

## Original PR description

## Overview

Fix ReplaySSM state shape calculation when the Mamba group count is not divisible by tensor parallel size. Closes #60346.

## Claims

- Pad group count consistently before computing ReplaySSM B-cache shards.
- Cover non-divisible counts below and above the TP size with shape regression tests.

## Validation

- `HF_HOME=/workspace/.setup/hf-home .venv/bin/python -m pytest tests/kernels/mamba/test_ssu_dispatch.py -k 'replayssm_physical_ring' -q` — 7 passed.
- `pre-commit run --files vllm/model_executor/layers/mamba/mamba_utils.py tests/kernels/mamba/test_ssu_dispatch.py` — passed.
- GPU kernel and end-to-end serving validation were unavailable in this CPU-only environment. The regression exercises the state shape calculator directly.

## Details

`append_replayssm_ring` divided the original group count by TP size, which asserted for counts such as one group over two ranks. Conv-state shapes already account for the replicated/padded groups. Reuse that padding for B-cache sizing and compute the padding as the remainder to the next multiple, including when group count exceeds TP size.

Duplicate check immediately before opening: no open PR found for `60346 in:body` or `append_replayssm_ring group sharding`.
