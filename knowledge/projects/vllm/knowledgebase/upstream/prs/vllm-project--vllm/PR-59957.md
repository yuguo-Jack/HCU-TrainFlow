# [Bugfix][NIXL] Release partial remote descriptors when a handshake fails

[Upstream PR](https://github.com/vllm-project/vllm/pull/59957) · state: open · merged: False

## Original PR description

## Purpose

Part of #59956 (the vLLM-side item; the NIXL endpoint leak itself is not addressed here).

`add_remote_agent` stores a remote dlist handle in `dst_xfer_side_handles[engine_id][rank]` plus per-engine descriptor state for each remote rank as it goes, but the engine is only committed to `_remote_agents` once every rank has succeeded. When a handshake fails on a later rank (side-channel timeout, NIXL `loadRemoteMD` error, validation error), the earlier ranks' handles stay behind uncommitted. The retry runs `add_remote_agent` for those ranks again and overwrites the handles without `release_dlist_handle`, so every failed handshake against a multi-rank prefill leaks prepped dlists. Nothing evicts that state either, because TTL eviction only walks committed engines.

This PR releases the uncommitted handles and descriptor state in the handshake failure callback. The teardown is factored out of `_cleanup_remote_engine` into `_release_remote_engine_descs` so both paths share it; eviction behavior is unchanged.

The NIXL agents loaded before the failure are deliberately left in place. NIXL reuses an already-loaded agent on re-add (measured: no new endpoints), while `remove_remote_agent` currently never returns the UCX endpoints (#59956), so removing them on every failed attempt would turn a retry storm into an endpoint leak.

Not a duplicate: #59873 (heartbeats refresh `engine_ttl`), #59874 (stalled READ timeout), #59877 (serialize NIXL agent calls) and #57507 (peer retirement RFC) touch neighbouring code, but none release state on handshake failure. Searched open PRs for `nixl partial handshake`, `nixl handshake failure cleanup dlist`, `nixl release_dlist_handle handshake`, `59956`.
