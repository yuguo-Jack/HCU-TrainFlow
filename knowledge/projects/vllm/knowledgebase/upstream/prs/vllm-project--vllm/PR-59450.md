# [Bugfix][HiSparse] Size the KV cache from the groups HiSparse allocates

[Upstream PR](https://github.com/vllm-project/vllm/pull/59450) · state: closed · merged: True

## Original PR description

## Purpose

With HiSparse, a GPU pool too small for one `max_model_len` request passes the startup check, and requests then wait forever with no error ([report](https://github.com/vllm-project/vllm/pull/55398#issuecomment-5903470382): `--num-gpu-blocks-override 160`, two 6k prompts never run).

The startup check sized HiSparse from the model's grouped specs rather than the groups HiSparse actually allocates. So it counted only indexer pages, missing the resident and hot groups, and used the wrong block size for the override.

## Changes

- HiSparse's grouping hook now returns the groups it allocates, and workers report its derived resident/hot caches. The standard startup check, override conversion and cross-rank sync then work for HiSparse unchanged.
- KV cache layout resolution skips specs without per-layer views, such as these caches, which lay out their own raw backing.
- Resident groups are sized by their admission window (`max_admission_blocks_per_request`), which #59494 now enforces at runtime.
- Auto-fit uses the startup check's criterion, so it can't pick a length that check rejects.
- Removed the HiSparse-specific memory estimate and the cross-worker `min(available_memory)` workaround.
- Projection returns a group unchanged when all its layers are on the worker, so HiSparse's group flags survive.

A pool that can't hold one request now fails the standard "max seq len" check at startup, before KV cache allocation.

## Test Plan

- Unit test: a 160-block pool is rejected at `max_model_len=8192`, and the boundary is exact at 32768 with 2048 tokens in flight (656 blocks rejected, 657 accepted). Auto-fit with 657 blocks starts. Layout resolution is unaffected by the derived caches.
- B200 (shrunk GLM-5.3, dummy weights), on this branch merged with #59494: TP=1 and TP=2 including ranks with unequal memory, 131k context, auto-fit, the reported setup, and `test_hisparse.py`.

## Test Result

- Unit tests pass.
- B200, this branch (includes #59494):
  - Too-small pools fail at startup: 160 blocks at 8192, 2400 blocks at 131072.
  - Pools that fit serve: 1000 blocks at 8192, auto-fit, and 3200 or 4000 blocks at 131072 with a 120k-token prompt. Without #59494, the 4000-block case livelocks.
  - TP=2 serves, including with unequal ranks.
  - The reported setup at 700 blocks: both 6k prompts complete.
  - `test_hisparse.py`: 4 passed.
