# [Spec Decode] Enable fused MTP updates for FlashInfer sparse MLA

[Upstream PR](https://github.com/vllm-project/vllm/pull/61670) · state: open · merged: False

## Original PR description



## Overview


Enable graph-safe fused multi-step MTP metadata updates for the FlashInfer sparse MLA backend.

## Claims


- Enables draft-decode metadata updates for FlashInfer sparse MLA when DCP is disabled.
- Refreshes `req_id_per_token` in place using the existing GPU metadata kernel.
- Preserves CUDA graph compatibility without adding allocations or host synchronization.
- Keeps the optimization disabled under DCP until its additional metadata requirements are supported.

## Validation



```bash
pytest -q \
  tests/v1/attention/test_indexer_deepseek_v4_slot_mapping.py \
  -k flashinfer_sparse_draft_metadata
```

## Details



The FlashInfer sparse MLA metadata builder did not advertise support for draft-decode metadata updates. As a result, fused multi-step MTP decode could not refresh its token-to-request mapping through the graph-safe metadata update path.
This change implements update_draft_decode_metadata by rebuilding req_id_per_token from the GPU-resident query_start_loc with compute_token_to_req_indices. The operation writes into the preallocated metadata buffer, matching the existing sparse FlashAttention MLA implementation.
Fused draft metadata refresh is enabled only when `dcp_world_size == 1`, matching the existing FlashAttention sparse MLA behavior. DCP continues to use the existing per-step metadata build path because its indexer refresh also requires rank-local sequence-length and slot-mapping updates (There is a separate [PR ](https://github.com/vllm-project/vllm/pull/54790)already open to enable this for DCP)
