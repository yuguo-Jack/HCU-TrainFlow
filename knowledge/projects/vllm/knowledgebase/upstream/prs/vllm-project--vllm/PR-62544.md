# [Model] Add Domyn Edge support

[Upstream PR](https://github.com/vllm-project/vllm/pull/62544) · state: closed · merged: True

## Original PR description



## Overview

Add support for Domyn Edge (`DomynEdgeForCausalLM`), a ~4B dense decoder released by Domyn: [`domyn/Domyn-Edge-Base`](https://huggingface.co/domyn/Domyn-Edge-Base) and [`domyn/Domyn-Edge-SFT`](https://huggingface.co/domyn/Domyn-Edge-SFT).

## Changes

- New architecture `DomynEdgeForCausalLM` with interleaved RoPE/NoPE attention layers, per-layer sliding windows (1024 tokens or full attention), QK-norm, pre/post sandwich RMSNorms (as in Gemma2), and tied embeddings.
- Outputs match the HF reference implementation, including beyond the 1024-token sliding window.
- GSM8K accuracy matches the scores published on the model cards (Base 71.8 vs 71.6; SFT 91.2 vs 94.6) using the provided script in the vLLM codebase.

## Details

Architecture highlights:

- **Interleaved RoPE / NoPE layers** (`position_layers`): NoPE layers skip the rotary embedding.
- **Per-layer sliding windows** (`window_sizes`): RoPE layers use a 1024-token window, NoPE layers use full attention.
- **Per-layer head sizes** (`head_sizes`).
- **QK-norm**, with a weightless RMSNorm on Q and a learned RMSNorm on K.
- **Gemma2-style sandwich norms**: pre- and post-norms around both attention and MLP.

The decoder stack reuses `Qwen2Model` and `Qwen2MLP`.

The test registry entry uses `trust_remote_code=True` because the HF reference implementation is shipped as remote code in the model repo.

`Domyn-Edge-SFT` is registered as an `extras` entry.

No other open PR requests for Domyn Edge have been found.

```bash
ValueError: Layer 0 does not dispatch through the Transformers attention interface and vLLM has no other way to handle it.
```
The remote modeling code calls `torch.nn.attention.varlen.varlen_attn` directly, with its own padding and KV-cache handling, instead of going through `ALL_ATTENTION_FUNCTIONS`. Supporting the Transformers backend would mean rewriting the HF attention to use the attention interface, and check the compatibility of the per-layer sliding windows (currently a custom window_sizes list).
Should we investigate further how to make our HF modeling code work with vLLM’s Transformers backend, given our architecture?
