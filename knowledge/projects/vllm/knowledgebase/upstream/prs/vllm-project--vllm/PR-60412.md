# [Bugfix] Don't warn about missing watermark config for default requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/60412) · state: closed · merged: True

## Original PR description



## Overview

Since #56801, every engine started without `--watermark-config` logs "Watermarking is enabled for this request, but the engine has no watermark configuration..." on its first request, although nothing asked for watermarking ([reported here](https://github.com/vllm-project/vllm/pull/56801#issuecomment-6032728937)). This PR keeps that warning only for requests that set `watermarking=True`.

## Claims

- On an engine without a watermark config, default requests (`watermarking` unset) no longer log the warning.
- `watermarking=True` on such an engine still warns once and runs without a watermark.
- The greedy, beam search, and trace replay fallback warnings on engines with a watermark config are unchanged.

## Validation

- `pytest tests/watermarking/` (1x H200): 184 passed, 3 skipped (the skipped tests need 2 GPUs). `tests/samplers/test_beam_search_online.py`, `tests/test_sampling_params.py` and `tests/v1/engine/test_input_processor_trace_replay.py`: 82 passed.
- CI: `tests/watermarking` already runs in the "(CPU) V1 Others" Buildkite step, which triggers on `vllm/config/`.
- With the old condition restored, the updated `test_requests_without_engine_config_are_unwatermarked` fails for all 3 of its cases.
- Offline `LLM.generate` with Qwen/Qwen2.5-0.5B-Instruct and no watermark config. Before (main c83935b300): one warning on the first default request. After: no warning for default sampling, default greedy, or `watermarking=False`. One warning for `watermarking=True`.
- `vllm serve Qwen/Qwen2.5-0.5B-Instruct` plus `/v1/completions`. Before (merged #56801 code, same condition as main): one warning after a default request. After: none for a default request, one for `"watermarking": true`.
- `pre-commit` passes on the changed files.

## Details

Root cause: the branch of `VllmConfig._check_supports_watermarking` for engines without a watermark config tested `config.watermarking is not False`, so the default `None` also warned. It now tests `is True`. The docs already say watermarking is disabled when `--watermark-config` is omitted, so no docs change is needed.

The test changes update the two assertions that expected a warning for default requests on an engine without a config. They also add a plain `SamplingParams()` case to the existing test for such requests.

The Rust frontend sets `watermarking=true` before the engine and does not go through this check, so it is unaffected.
