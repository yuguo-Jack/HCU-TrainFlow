# [Feature][Observability] Attribute inference metrics and traces to API surface

[Upstream PR](https://github.com/vllm-project/vllm/pull/62079) · state: open · merged: False

## Original PR description



## Overview

Distinguish native Messages, Chat Completions, and Completions traffic in inference metrics and traces, including requests without tools.

## Claims

- Add opt-in `api_surface` labels to existing request counts, latency histograms, token counters, and request token histograms through `--enable-api-surface-metrics` (disabled by default).
- Preserve the original metric schema and aggregate accounting unless enabled. Inference trace attribution remains independent of this setting.
- Preserve API identity through Messages conversion, parallel sampling, beam search, and streaming input.
- Cover native JSON/SSE endpoint attribution and document metric-query changes.

## Validation

656 focused CPU/unit tests passed across CLI/configuration, serving/conversion, engine admission, output processing, in-memory OTel export, metrics, beam search, and streaming input. All applicable full-branch pre-commit hooks passed, including mypy and test tethering.

Live validation on one NVIDIA H200 passed:

- 15 text-serving metric tests covering all three APIs in JSON/SSE with the flag disabled and enabled, plus existing default/chunked-prefill/hidden metric count checks.
- Two offline engine metric cases with n-gram speculative decoding, with the flag disabled and enabled.
- Six live OTLP requests with the metrics flag disabled, verifying `api_surface` on inference spans and preservation of incoming W3C trace IDs for all three APIs in JSON/SSE.

Validation used the complete candidate source on base `cffc0cfa31`, overlaid on compiled components from the October 16 nightly (`49cb2bbf71`, Torch `2.14.0+cu130`). The image has an extra MoE activation binding and an older tokenspeed-mla dependency compared with the base; neither is used by the validation models. This validates frontend behavior with precompiled components rather than an exact source-built binary.

Text serving used TinyLlama-1.1B-Chat with bfloat16, eager execution, and context 1024. Offline metrics used OPT-125m. Existing Buildkite suites cover the serving and metric tests; multimodal attribution cases are explicitly skipped.

## Details

Messages reuses the Chat serving path internally, which previously prevented general engine telemetry from identifying the originating API. Carry trusted frontend identity into request/iteration statistics and reuse existing metric collectors and inference spans.

With `--enable-api-surface-metrics`, selected metric families receive one of four bounded values: `messages`, `chat_completions`, `completions`, or `unknown` for other/offline callers.

Default startup preserves the original labels and aggregate counters. Enabling the flag replaces selected aggregate series with per-API series; it does not export both copies. Before enabling it, update dashboard aggregations and vector joins as needed, using `sum without (api_surface)` for totals across APIs. Changing the setting requires a restart and increases series cardinality.

Scheduler gauges, the iteration histogram, and admission-time cache-tier counters remain engine-wide. Metric names, buckets, and engine-request counting semantics are preserved. Trace attribution works independently of the metrics flag.

This differs from [#61571](https://github.com/vllm-project/vllm/pull/61571), which currently focuses on tool-specific outcome metrics, and [#52249](https://github.com/vllm-project/vllm/pull/52249), whose operation label does not distinguish Messages. Neither is a dependency; reconcile overlapping identity plumbing if either merges first. Render-server instrumentation is outside this change.
