# [CI][ROCM][Bug] Elastic DP doesn't work with AITER-on

[Upstream PR](https://github.com/vllm-project/vllm/pull/63053) · state: closed · merged: True

## Original PR description

## Overview

The Elastic EP Scaling test (distributed/test_elastic_ep.py::test_elastic_ep_scaling) failed with AITER on. The cause is:
1. AITER requires a torch.distributed-registered group, but Elastic EP is using stateless group, which is not torch.distributed registered at all, so we need to skip AITER AR and choose next available AR;
2. During scale-up, existing workers call _release_cuda_graphs() and then re-capture into the same global graph pool. Some memory in that pool was still allocated, because FlyDSL didn't release them correctly. Graph replay never re-enters Python, so a kernel last launched during capture holds those tensors inside the graph pool indefinitely. The pool had no graphs left but still had live blocks, so PyTorch rejected capturing into it again. Now I explicitly call _switch_to_fresh_graph_pool() to switch to a new graph pool to avoid this.

## Claims

These 2 bugs are fixed. This test case works as expected no matter AITER is on or off.
