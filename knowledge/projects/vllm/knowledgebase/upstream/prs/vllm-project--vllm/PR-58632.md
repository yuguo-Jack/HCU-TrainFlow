# [Kernel] Add fused MoE tuned configs for NVIDIA A10 (Qwen3/Qwen3.5 A3B, TP=4)

[Upstream PR](https://github.com/vllm-project/vllm/pull/58632) · state: closed · merged: False

## Original PR description

## Purpose

Add tuned fused-MoE Triton kernel configurations for **NVIDIA A10** covering two Qwen A3B MoE shapes at tensor parallel size 4 in bfloat16:

- Qwen/Qwen3-30B-A3B: `E=128` experts, `moe_intermediate_size=768`, so `N=192` per rank at TP=4
  - file: `vllm/model_executor/layers/fused_moe/configs/E=128,N=192,device_name=NVIDIA_A10.json`
- Qwen/Qwen3.5-35B-A3B: `E=256` experts, `moe_intermediate_size=512`, so `N=128` per rank at TP=4
  - file: `vllm/model_executor/layers/fused_moe/configs/E=256,N=128,device_name=NVIDIA_A10.json`

There are currently no fused-MoE configs for `NVIDIA_A10` at all, so A10 deployments fall back to the default heuristic config. These two models were chosen because they are popular MoE models that fit on a 4x A10 (96 GB) node in bf16 at TP=4. The `E=256,N=128` shape also has no bf16 config for any device yet.

I searched open PRs for A10 fused-MoE configs and found none.

## Test Plan

Generated with the standard tuning script on a 4x A10 24GB host (3 GPUs used as tuning workers; ~1.5 h per model):

```bash
python benchmarks/kernels/benchmark_moe.py --model Qwen/Qwen3-30B-A3B --tp-size 4 --dtype auto --tune
python benchmarks/kernels/benchmark_moe.py --model Qwen/Qwen3.5-35B-A3B --tp-size 4 --dtype auto --tune
```

Then compared default vs. tuned kernel time on one A10 with the same script in benchmark mode, pointing the tuned run at the generated files via `VLLM_TUNED_CONFIG_FOLDER`:

```bash
VLLM_TUNED_CONFIG_FOLDER=<dir with tuned json> CUDA_VISIBLE_DEVICES=1 python benchmarks/kernels/benchmark_moe.py --model <model> --tp-size 4 --dtype auto --batch-size 1 2 4 8 16 32 64 128 256 512 1024 2048 4096
```

Also verified that vLLM loads both checked-in configs from the repo config directory with `get_moe_configs(E, N, dtype=None)` on `NVIDIA A10`.
