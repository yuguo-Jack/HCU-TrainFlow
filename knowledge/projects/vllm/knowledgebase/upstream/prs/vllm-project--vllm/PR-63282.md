# [CI][ROCm] Run online FP8 MoE batch-invariance test on ROCm MI300+

[Upstream PR](https://github.com/vllm-project/vllm/pull/63282) · state: closed · merged: False

## Original PR description

## Purpose

Follow-up to #57092, per @AndreasKaratzas's review question there.

`test_online_fp8_moe_logprobs_bitwise_bs1_vs_bsN` was gated with `@skip_if_not_cuda`. That marker was copied from the neighboring test, not chosen because of a known ROCm limitation; the fix in #57092 was only validated on CUDA (sm_120 locally, sm_90 by a third party).

This PR switches the test to `@skip_if_not_cuda_alike` so the AMD batch-invariance jobs (which already run the whole `v1/determinism/test_batch_invariance.py`) exercise it too. On ROCm it additionally requires capability 9.4+ (MI300/MI355): gfx90a (MI250) reports 9.0 and would otherwise pass the CUDA `SM 8.9` check despite having no FP8.

Open question for ROCm owners: I could not check which MoE experts online `fp8_per_tensor` selects on ROCm (e.g. AITER vs Triton). If that path is not batch-invariant yet, this test will fail on MI300/MI355 and we'll know the ROCm path still needs the per-token activation treatment from #57092.

## Test Plan

- `pytest tests/v1/determinism/test_batch_invariance.py::test_online_fp8_moe_logprobs_bitwise_bs1_vs_bsN` on RTX 5090 (sm_120)
- ROCm coverage via the MI300 / MI355 batch-invariance Buildkite jobs (no AMD hardware locally)

## Test Result

- CUDA (sm_120): 1 passed, unchanged from before.
- ROCm: pending CI.
