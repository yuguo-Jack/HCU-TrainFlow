# Add omniasr unlimited

[Upstream PR](https://github.com/vllm-project/vllm/pull/61227) · state: open · merged: False

## Original PR description

## Overview

**Draft. Depends on #36864.** Only the commits after `fd6f7fc5ca` are new; the earlier commits belong to #36864 and will drop out of this diff once it is merged.

Adds support for the OmniASR Unlimited (streaming) variants, a follow-up to #36864 requested in its discussion. Unlimited is **not functional yet**; this PR tracks the work in progress.

## Claims

Done so far:
- Streaming variants (`is_streaming=True` in the HF config) accept up to 2 audio inputs per request (previous segment + current segment). Standard variants are unchanged (1 audio).

Planned (see Details):
- Streaming decoder layout in the multimodal processor / `embed_multimodal`
- Previous-segment text and segment markers in the prompt
- `examples/omniasr_unlimited.py`: client-side segmentation and decoding loop
- Parity test against Meta's reference implementation on long audio

## Validation

- `is_streaming` detection on both configs:
  - `ziywang50/omniASR-LLM-300M` → `False` → audio limit 1
  - `ziywang50/omniASR-LLM-Unlimited-300M-v2` → `True` → audio limit 2
- Unlimited end-to-end validation will be added with the remaining items, compared against Meta's `omnilingual-asr` reference.

## Details

Unlimited models transcribe arbitrarily long audio in 15 s segments. Each segment is conditioned on the previous segment's audio and decoded text (Meta's `generate_hypotheses_one_segment_streaming`, `n_context_segments = 1`). Per segment, the decoder input built by Meta's `create_streaming_syntax` (inference mode) is:

```
i == 0:  [lang, lid, audio_0, seg_0, BOS]
i >= 1:  [lang, lid, audio_{i-1}, regular_segment, BOS, text_{i-1}, EOS,
          audio_i, seg_i, BOS]
seg_i = last_segment (10289) if i is the final segment, else regular_segment (10290)
lid = 10288
```

Differences from the standard variants:
- The language embedding and LID marker come **first** (standard: `audio, lid, lang`).
- Two extra special tokens mark segment boundaries, hence `n_special_tokens = 3`.

Design: the vLLM transcription endpoint is single-audio and single-pass, so the segment loop runs client-side via the offline `LLM` API. Each request carries at most 2 audio inputs (previous + current segment), which is why the limit is 2 rather than unbounded.

Model: `ziywang50/omniASR-LLM-Unlimited-300M-v2`
