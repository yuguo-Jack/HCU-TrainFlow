# [Quantization] Per-shard FP8 scaling for MergedColumnParallelLinear

[Upstream PR](https://github.com/vllm-project/vllm/pull/41021) · state: open · merged: False

## Original PR description

## Problem

Online FP8 quantization (`--quantization fp8`) applies a single per-tensor scale to the entire fused weight in `MergedColumnParallelLinear`. When the fused components have different magnitude ranges, the smaller components lose precision.

This breaks GDN models (Qwen3.5, Qwen3.6) where `in_proj_qkvz` fuses Q, K, V, and Z gate projections under one scale. The Z gate has smaller magnitudes than Q, K, and V. The GDN recurrence amplifies this into NaN or "!!!!!!!!!!!" output.

It also degrades quality for every SwiGLU model where `gate_up_proj` fuses the gate and up projections. The gate feeds sigmoid, so it needs more precision in the near-zero region where the shared scale can't provide it.

Fixes #40934.

## Fix

Quantize each logical shard independently in `process_weights_after_loading`, then expand to per-channel via `convert_to_channelwise`. The result is a `[N, 1]` scale tensor that all FP8 kernels already accept.

The INT8 CUTLASS path has done this correctly since #6552 (Jul 2024). This patch generalizes it to both FP8 online classes.

## Test plan

Tests are included to show the range of behaviors caused by this bug. They take seconds to run; pure PyTorch so no GPU needed.

## Code Review

This pull request implements per-shard FP8 scaling for fused modules such as QKV and gate_up projections to prevent precision loss caused by varying magnitude ranges across shards. The changes include independent quantization of each shard and expansion to per-channel scales for kernels in both offline and online FP8 paths. Additionally, new test suites were added to validate precision preservation across different magnitude gaps. Review feedback highlighted a critical issue where torch.cat would fail when combining scalar shard scales; it is recommended to use torch.stack instead to avoid a RuntimeError.

`torch.cat` will raise a `RuntimeError` when attempting to concatenate zero-dimensional tensors (scalars), which is what `ops.scaled_fp8_quant` returns for per-tensor scales. Using `torch.stack` is the correct way to combine these scalar tensors into a 1D tensor for `convert_to_channelwise`.

```suggestion
                torch.stack(shard_scales), layer.logical_widths)
```
