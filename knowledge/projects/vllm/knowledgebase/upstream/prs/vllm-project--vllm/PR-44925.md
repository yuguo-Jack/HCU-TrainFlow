# fix(qwen3-asr): respect language parameter in get_generation_prompt

[Upstream PR](https://github.com/vllm-project/vllm/pull/44925) · state: closed · merged: False

## Original PR description

When using `/v1/audio/transcriptions`, the Whisper-compatible `language` parameter was ignored because `get_generation_prompt` only checked `to_language` and never fell back to `language`.

This adds a fallback so that when `to_language` is `None`, the `language` parameter is used instead, allowing the Whisper-compatible `language` field to correctly inject the language prefill into the assistant prompt.

Fixes: #33768



## Purpose

Fix `Qwen3-ASR` ignoring the Whisper-compatible `language` parameter when using the `/v1/audio/transcriptions` endpoint (fixes #33768).

In `get_generation_prompt`, only `to_language` was checked and `language` was never used as a fallback, causing the model to always auto-detect the language regardless of what was passed by the user.

One-line fix: fall back to `stt_params.language` when `stt_params.to_language` is `None`:

```python
# before
to_language = stt_params.to_language

# after
to_language = stt_params.to_language or stt_params.language
```

The same bug was independently identified and fixed in the upstream qwen-asr package: [[QwenLM/Qwen3-ASR#101](https://github.com/QwenLM/Qwen3-ASR/pull/101)](https://github.com/QwenLM/Qwen3-ASR/pull/101), confirming this is the correct approach.
