# [Bugfix][KV Connector] Fail fast when the NIXL side-channel listener cannot bind

[Upstream PR](https://github.com/vllm-project/vllm/pull/61472) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

A NIXL side-channel bind failure kills the listener thread before it signals readiness, leaving engine startup waiting indefinitely. Detect that exit and raise an error identifying the host, port, and configuration to check.

## Claims

- Fail startup when the listener exits before becoming ready.
- Preserve successful startup and live updates to the shared handshake metadata.

## Validation

A real `vllm serve` process with `NixlConnector` now exits with a clear error when the side-channel port is taken. Results used NVIDIA B200 GPUs with driver 580.95.05 and a precompiled build of main `b8c04dd3b4`. The comparison tree restores only the production file to main.

```text
Without the fix: zmq.error.ZMQError: Address already in use (addr='tcp://127.0.0.1:25555')
                 The server did not exit, and the 420 s limit stopped it.
With the fix:    RuntimeError: NIXL handshake listener failed to start on 127.0.0.1:25555.
                 If the port is in use, set VLLM_NIXL_SIDE_CHANNEL_PORT to a free base port.
                 The server exited with code 1 after 41 s.
```

Normal prefill and decode still work with native NIXL 1.5.2. `run_accuracy_test.sh` with `Qwen/Qwen3-0.6B` on one host measured GSM8K accuracy 0.423 against the expected value of 0.41, with no failed transfers.

The occupied-port run, the unit regression, and `run_accuracy_test.sh` also pass with this branch merged onto main `410ab341a8`, with the same build, because no native code changed between the two commits.

These runs used the same hardware and main `3a90cc6fd0`. The production code on this branch has not changed since then:

- A prefiller and a decoder on separate hosts transferred KV over `rc_mlx5` zero-copy with no failed transfers. The output was identical to an unmodified main deployment for every prompt, and it was repeatable.
- On those repetitive prompts, prefill and decode output differs from a single plain server for most prompts, and unmodified main has the same difference. With `VLLM_BATCH_INVARIANT=1`, prefill and decode output matches the plain server for every prompt, so the difference comes from ordinary batch dependence and not from the transfer.

Two regressions cover this. Both time out without the fix and pass with it.

```sh

  tests/v1/kv_connector/unit/test_nixl_connector.py::test_llm_startup_fails_when_side_channel_port_is_taken -q

  tests/v1/kv_connector/unit/test_nixl_connector.py::test_handshake_listener_bind_failure_raises \
  -m cpu_test -q
```

The `LLM` regression runs in process with `FakeNixlWrapper`, so the real `vllm serve` run above covers the multiprocess path. The whole of `test_nixl_connector.py` passes, except `test_register_packed_dsv4_mla_cache_as_single_region[v41-aliased-groups]`, which fails the same way on main on this host.

**CI coverage:** `(CPU) V1 Others` selects the scheduler regression. No active step selects the `LLM` regression, because it needs a GPU and the `V1 KV Connectors` step is disabled until the KV connector installation is locked. The regressions of this PR also pass with this branch merged onto main `b2a9480dc7`, with its own precompiled build and `VLLM_WORKER_MULTIPROC_METHOD=spawn` as in CI. Upstream checks are stopped at contributor authorization, so Buildkite has not run this branch.

## Details

1. `EngineCore` collects worker handshake metadata and asks the scheduler to start the side-channel listener.
2. The listener binds its ZMQ socket and signals readiness. A bind failure exits the thread before that signal.
3. The scheduler checks thread liveness while waiting and raises if startup failed.

The listener retains the shared handshake dictionary so registration updates remain visible. A failed listener is not retried on the same scheduler instance; initialization aborts.

The original collision occurred between inference groups in a training setup. [SkyRL #1926](https://github.com/NovaSky-AI/SkyRL/pull/1926) fixes that caller's port allocation; this change makes other listener-startup failures diagnosable too. #54757 handles malformed requests after binding, while closed, unmerged #23756 attempted a separate pre-bind port check.

Open #64371 carries an equivalent liveness poll inside a much larger NIXL checkpoint change. This PR is the small fix that can land on its own. If it lands first, #64371 can drop its copy.
