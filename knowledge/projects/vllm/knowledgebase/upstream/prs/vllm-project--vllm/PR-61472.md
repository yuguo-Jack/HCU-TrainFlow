# [Bugfix][KV Connector] Fail fast when the NIXL side-channel listener cannot bind

[Upstream PR](https://github.com/vllm-project/vllm/pull/61472) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fail engine startup when the NIXL side-channel listener cannot bind, instead of leaving the engine waiting forever.

## Claims

- Detect listener failure before its socket is ready and raise an error with the host, port, and `VLLM_NIXL_SIDE_CHANNEL_PORT`.
- Keep the existing listener interface and successful startup behavior.

## Validation

The CPU NIXL connector tests and scoped pre-commit hooks pass. The occupied-port regression runs the real ZMQ listener: the original code blocks waiting for readiness, while the fix raises `RuntimeError: NIXL handshake listener failed to start`. The listener also reports the original `ZMQError`.

Run the CPU connector tests in a configured development environment:

```sh
.venv/bin/python -m pytest tests/v1/kv_connector/unit -m cpu_test
```

The original reproduction was a port collision between inference groups in our training setup. [SkyRL #1926](https://github.com/NovaSky-AI/SkyRL/pull/1926) fixes that caller's port allocation; this change makes vLLM fail clearly if a collision or another listener-startup failure occurs.

Validation is CPU-only. GPU serving and a NIXL-enabled prefill/decode deployment remain untested. Upstream checks are stopped at contributor authorization.

## Details

The startup sequence is:

1. `EngineCore` collects worker handshake metadata and asks the scheduler to start the side-channel listener.
2. The listener binds its ZMQ socket and signals readiness. A bind error kills the thread before that signal.
3. The scheduler checks thread liveness while waiting and raises if startup failed.

This follows the existing Mooncake sender-listener pattern. A failed listener is not retried on the same scheduler instance; engine initialization aborts.

#54757 handles malformed requests after the listener has bound, so it does not cover this startup failure. Closed, unmerged #23756 attempted a separate pre-bind port check.
