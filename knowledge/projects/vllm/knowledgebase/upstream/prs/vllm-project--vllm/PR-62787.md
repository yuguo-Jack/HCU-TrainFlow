# [Bugfix][Frontend] Ignore Anthropic thinking budgets the server cannot enforce

[Upstream PR](https://github.com/vllm-project/vllm/pull/62787) · state: open · merged: False

## Original PR description

## Overview

Since #58613, `/v1/messages` maps `thinking={"type": "enabled", "budget_tokens": N}` to `thinking_token_budget`, which the engine rejects unless a reasoning parser with reasoning start/end tokens is configured. Every Anthropic request with extended thinking enabled therefore fails on servers without one: no `--reasoning-parser`, or a parser without those tokens such as `openai_gptoss`. This ignores `budget_tokens` in that case, as the endpoint already does for `display`, and logs a one-time warning.

## Claims

- `/v1/messages` with `thinking.type="enabled"` succeeds on servers that cannot enforce a thinking budget, as it did before #58613.
- Servers that can enforce it (a reasoning parser with start/end tokens) still apply `budget_tokens`.
- No change for `disabled`, `adaptive` or absent `thinking`.

## Validation

Real server on `34ac4f96a3` (Qwen3-0.6B, RTX 4090, `--enforce-eager`). Request: `{"max_tokens": 2048, "thinking": {"type": "enabled", "budget_tokens": 1024}, "messages": [{"role": "user", "content": "Say hi."}]}`.

| Server | Build | Non-streaming | Streaming |
|---|---|---|---|
| no `--reasoning-parser` | `main` | HTTP 400: `thinking_token_budget is set but reasoning_config is not configured...` | only an `error` event |
| no `--reasoning-parser` | this PR | HTTP 200, `end_turn` | full event sequence |
| `--reasoning-parser qwen3` | this PR | HTTP 200, `end_turn` (budget applied) | full event sequence |

Tests:

- New `tests/entrypoints/anthropic/test_anthropic_messages_conversion.py::TestThinkingConfig::test_enabled_ignores_budget_the_server_cannot_enforce`.
- `pytest tests/entrypoints/anthropic/test_anthropic_messages_conversion.py`: 113 passed.
- `pre-commit run --files <changed files>`: all hooks pass.

## Details

`AnthropicServingMessages._handle_thinking` set `req.thinking_token_budget = thinking.budget_tokens` unconditionally, and `InputProcessor._validate_params` raises `VLLMValidationError` when `thinking_token_budget` is set and `reasoning_config` is `None` or disabled. `reasoning_config` only exists with `--reasoning-parser`, and stays disabled for parsers without reasoning start/end strings (e.g. `openai_gptoss`, `granite`, `minimax_m2_append_think`). Because `budget_tokens` is required for `type: "enabled"`, Anthropic clients had no way to request extended thinking from such servers.

The handler now computes `_thinking_budget_supported` from `vllm_config.reasoning_config` once, and passes it to `to_chat_completion_request` for `/v1/messages` and `count_tokens`. The parameter defaults to `True`, so the scale-out render path and existing callers keep their behavior.

An alternative is to keep returning 400 with a clearer message (#57830 rewords the engine error). Ignoring matches how the endpoint treats other thinking settings it cannot honor and the behavior before #58613; happy to switch if maintainers prefer an error. This overlaps in area with RFC #58647.

Not a duplicate: I found no issue or PR for this 400 (searched "budget_tokens", "anthropic thinking enabled", "thinking_token_budget reasoning_config", "reasoning_config is not configured"). #61984 changes the render path's disabled-thinking effort, and #59180 is `count_tokens` parity.
