## Code Review

This pull request introduces support for cross-layer KV cache offloading in the `SimpleCPUOffloadConnector`. It adds a new `register_cross_layers_kv_cache` method to both the connector and its worker handler, allowing the system to manage a single flat buffer representing multiple layers. Comprehensive unit tests were also added to verify the connector's properties, worker registration logic, and error handling for multi-group configurations. A critical issue was identified in the calculation of `page_size_bytes` within the worker, where multiplying the spec's page size by the number of layers could lead to incorrect memory mapping and potential data corruption.

The calculation of `page_size_bytes` by multiplying `kv_cache_spec.page_size_bytes` by `num_layers` is potentially incorrect and fragile. If `kv_cache_spec` is a `UniformTypeKVCacheSpecs` (which is the standard way to represent grouped layers in vLLM V1), its `page_size_bytes` property already returns the sum of sizes for all layers in the group. Multiplying it by `num_layers` again would result in an incorrect (oversized) page size, leading to an incorrect `num_blocks` calculation and potential crashes or data corruption during offloading.

A more robust approach, consistent with the existing `register_kv_caches` method, is to derive `page_size_bytes` from the total storage size and the number of blocks defined in the configuration. This avoids ambiguity regarding whether the spec represents a single layer or the entire group.

```suggestion
        num_blocks = self.kv_cache_config.num_blocks
        storage = kv_cache.untyped_storage()
        assert storage.nbytes() % num_blocks == 0
        page_size_bytes = storage.nbytes() // num_blocks

        # View the raw storage as (num_blocks, page_size_bytes)
        gpu_tensor = (
            torch.tensor([], dtype=torch.int8, device=self.device)
            .set_(storage)
            .view(num_blocks, page_size_bytes)
        )
```
