## Overview

Warm the V1 align state-copy kernels and LFM2 ShortConv prefill before CUDA graph capture, so the validated first-request path survives strict JIT monitoring. Fixes #61317 for the V1 align/speculative path.

## Claims

- Cover fused align precopy and postprocess with the production launch methods and cache metadata, using inputs that preserve cache contents.
- Cover ShortConv prefill with the actual cache layout/dtype and speculative index stride, including offset views from mixed decode/prefill batches.

## Details

The raw fused-copy Triton kernels run outside the captured model region and are absent from the registered JIT warmup keys. V1 profile runs also bypass ShortConv prefill. Consequently, graph capture and registry warmup can finish before those production specializations have been compiled.

The existing Mamba warmup module now initializes the V1 align context from bound state caches and persistent block tables. Fresh precopy and no-migration postprocess inputs compile the real launch methods without touching cache contents. ShortConv uses null-block inputs, its real weights/cache layout, and an int32 index stride of `1 + num_speculative_blocks`; offset views cover the possible pointer-alignment cases. Only startup gains this work. Kernel algorithms, model outputs and steady-state execution are unchanged by the implementation.

This fixes a supported MRV1 deployment while it is being deprecated. MRV2 already warms these paths through real execution and skips the new V1-specific helpers. Compatibility checks completed two V2 requests in warn mode; strict mode still fails on the independent `_compute_local_logits_stats_kernel` gap, and warn mode also reports rejection/resampling kernels. Wider V1 batches expose an independent `fused_moe_kernel` gap, so output comparisons use warn mode. No universal strict-JIT coverage or startup/throughput improvement is claimed. ROCm, other GPU architectures and multi-GPU configurations were not validated.

Uncontrolled request submission matched 31/32 outputs, with the baseline itself varying on repeated prompts. Only the controlled fixed-batch comparison is claimed as exact equivalence. Batch-invariant mode was unavailable for `SHORT_CONV_ATTN`. This is an output regression comparison, not a task accuracy benchmark.

Current Python source was installed editable with the supported precompiled-artifact workflow, reusing the official vLLM 0.31.0 native wheel because the original validation commit's cu130 nightly metadata returned 404. The same native artifact was reused for the upstream-base repeat; archive version metadata was supplied through setuptools-scm and the exact source import path was verified. Native code was not rebuilt or changed. Single-start timings were 56.73 s before and 56.97 s after and are not a statistical performance result.
