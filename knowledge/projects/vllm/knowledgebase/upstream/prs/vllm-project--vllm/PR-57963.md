# [Model] Add AliceAI support

[Upstream PR](https://github.com/vllm-project/vllm/pull/57963) · state: open · merged: False

## Original PR description

## Purpose

Add native vLLM support for AliceAI.

[AliceAI-Foundation-80B-A3B-Base](https://huggingface.co/yandex/AliceAI-Foundation-80B-A3B-Base/blob/main/README_en.md)
is Yandex's Apache-2.0 base language model, trained from scratch. It has 80B
parameters, 3B active parameters per token, and a 262,144-token context.

Compared with Qwen3Next, AliceAI uses Kimi Delta Attention in place of Gated
DeltaNet, Block Attention Residuals in place of standard residual connections,
and sigmoid MoE routing with expert-score correction bias in place of softmax
routing.

The model has 36 KDA layers and 12 gated full-attention layers, 512 routed
experts with top-10 routing and one shared expert, and one MTP layer.

Our [published evaluations](https://huggingface.co/yandex/AliceAI-Foundation-80B-A3B-Base/blob/main/README_en.md#benchmarks)
report 91.1 on MATH-500 and 86.5 on WikiWebFacts, a Russian factual-knowledge
benchmark, compared with 81.9 and 62.4 for Qwen3.5-35B-A3B-Base. The model card
describes the evaluation setup and includes the full results.

This PR:

- adds an `AliceAIConfig` derived from the existing Qwen3Next configuration;
- reuses the existing Qwen3Next full-attention and model-loading
  infrastructure;
- uses the shared fused MoE implementation with DeepSeek-style sigmoid routing
  and expert-score correction bias;
- reuses the existing Kimi KDA layer and low-level Attention Residual primitive;
- implements the AliceAI-specific decoder topology and checkpoint weight
  mappings;
- ignores the checkpoint's MTP weights and warns when its config declares MTP
  layers;
- supports LoRA through the inherited Qwen3Next implementation;
- registers the target architecture;
- adds focused configuration, routing, weight-loading, and state-flow tests;
- lists AliceAI in `supported_models.md`.

No new C++ or CUDA kernels are introduced.

Design discussion: #57961.

No existing AliceAI implementation or competing open pull request was found.

### Current limitations

- Pipeline parallelism is not supported; `pipeline_parallel_size=1` is required.
- Sequence-parallel MoE is not supported.
- MTP speculative decoding is not supported in this PR.
- Speculative methods requiring auxiliary hidden states, including Eagle3, are
  not supported.
- CPU weight offloading is supported only with the UVA backend; the prefetch
  offloading backend is not supported.
- Multimodal AliceAI support is outside this PR.

AI assistance was used during implementation and review. I reviewed every
changed line and validated the reported test results.

## Test Result

Validated head: `44adb855e5ed869276feb5655b16614b3b3c561d`.

Focused AliceAI target and configuration tests: **30 passed, 48 warnings**.
This CPU-only run used `NUMBA_DISABLE_JIT=1` and `-p no:cacheprovider`
because the worktree could not initialize Numba's file cache.

A model-registry smoke check resolved `AliceAIForCausalLM` and confirmed that
its weight mapper drops `mtp.*` checkpoint weights. Ruff check, Ruff format,
and `git diff --check` passed.

The public model-registry initialization and GPU serving tests were not rerun
for this revision because this environment has no available CUDA device. A
previous revision loaded the target model in a TP4 H100 BF16 serving run and
generated completions with CUDA graphs enabled; that run also covered MTP,
which has since been removed.

The public checkpoint revision was previously verified against the locally
cached checkpoint: all 49 weight shards and the configuration and tokenizer
artifacts matched by SHA-256. No model-quality evaluation was run for this
revision.

The commit-time pre-commit hook failed during its first-time environment setup
with a Git index error. The index was repaired; the commit was created with the
hook bypassed. The focused tests and checks above passed, but the remaining
pre-commit hooks were not rerun. Both commits include DCO sign-off.
