# [Core][Metrics] Seed scheduler-state gauges to 0 at logger startup

[Upstream PR](https://github.com/vllm-project/vllm/pull/60155) · state: closed · merged: False

## Original PR description

Fixes #59988

With multiple engines sharing one PrometheusStatLogger, scheduler-state gauges (num_requests_running, num_requests_waiting, num_requests_swapped, gpu_cache_usage_perc, cpu_cache_usage_perc) report no samples until the first scheduler tick, so idle multi-engine deployments scrape missing/absent series. The logger now seeds these gauges to 0 at startup.

AI-assisted disclosure: generated with AI assistance.

Regression test in tests/v1/metrics/test_prometheus_stat_logger.py parameterized over 1/2/3 engines asserting all four gauges are present with samples.
