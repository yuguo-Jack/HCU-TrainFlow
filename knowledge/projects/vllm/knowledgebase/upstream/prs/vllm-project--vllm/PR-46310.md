# [Bugfix][Frontend] Reject stop strings when skip_tokenizer_init is set

[Upstream PR](https://github.com/vllm-project/vllm/pull/46310) · state: open · merged: False

## Original PR description

## Overview

Reject string stop sequences when `skip_tokenizer_init=True`. These stops need a tokenizer; accepting them silently lets generation continue without the requested stopping condition. Token-ID stops remain usable without a tokenizer.

## Claims

- Add the check to `SamplingParams.verify()`, alongside the other tokenizer-dependent validation.
- Cover scalar and list stop strings, plus the tokenizer-free no-stop and token-ID cases.

## Validation

The previous revision was checked with:

```bash
.venv/bin/pre-commit run --files vllm/sampling_params.py tests/v1/sample/test_logprobs.py tests/v1/sample/test_sampling_params.py
.venv/bin/python -m pytest tests/v1/sample/test_sampling_params.py -q
```

These are historical results from the existing branch, not fresh results against today's main. The branch needs a refresh and end-to-end validation before merge; no new serving or model evaluation results are claimed.

## Details

The existing guard for structured outputs already rejects tokenizer-free requests. This applies the same principle to string stops, without changing `min_tokens` or `stop_token_ids`.

This remains the original PR so its review history is preserved. A fresh search found no other PR specifically implementing this guard; broader tokenizer and token-ID validation changes address different cases. SGLang has the corresponding guard in sgl-project/sglang#27882.
