# [Doc] MiniMax-M3: InferenceX AgentX lanes as tuned presets

[Upstream PR](https://github.com/vllm-project/vllm/pull/63534) · state: closed · merged: True

## Original PR description



## Overview

Moves MiniMax-M3's InferenceX AgentX lanes for H200, B200 (both keys) and B300 out of guide sections and into opt-in **presets**, so recipes.vllm.ai and its JSON API render each qualified point. Today the guide tells readers to change the generated command by hand. Builds on vllm-project/recipes#1162 (presets) and vllm-project/recipes#1175 (per-point `tp`), both merged.

## Claims

- Four opt-in presets, 23 points total, each with the lane's image digest, InferenceX key, and builder choices (GQA draft, text-only, thinking always on) as data:

  | Preset | Variant | Points |
  |---|---|---|
  | `h200_agentx` | mxfp8 | 8 |
  | `b200_agentx` | nvfp4 | 4, TP4, host KV offload on three |
  | `b200_agentx_c10` | nvfp4 | 6, active-sequence caps, incl. a TP8 point |
  | `b300_agentx` | nvfp4 | 5, TP8/TP4/TP2 |

- Per-point settings come from the lane tables and are rendered as flags rather than prose:
  - `--max-num-seqs`, `--max-num-active-seqs`, capture sizes and memory utilization;
  - host KV offload (1,073 GB / 749 GB, lazy);
  - the MSA decode backend dropped where the lane omitted it;
  - draft token count, local-argmax removal and all-reduce backend.
- No existing rendering changes: the presets are opt-in.
- The guide loses the three lane sections (about 120 lines). Each preset's runbook keeps the lane description, the recipe-wide **Verified** caveat and the synthetic-acceptance note.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` passes against recipes main (fdf035b).
- Rendered every preset point (`/MiniMaxAI/MiniMax-M3/presets/<key>.json`) and checked 16 points programmatically against the lane tables. They matched on:
  - TP, `--max-num-seqs`, `--max-num-active-seqs` and capture size;
  - memory utilization and KV offload bytes / lazy;
  - MSA flag, `num_speculative_tokens`, local-argmax reduction, all-reduce backend and image.
- All 254 existing renderings across the four variants (`MiniMaxAI/MiniMax-M3`, `-MXFP8`, `nvidia/…-NVFP4`, `amd/…-MXFP4`) are identical to main apart from `guide` / `presets`.
- Builder check on B300:
  - picking the preset switches to NVFP4 with GQA, text-only and thinking;
  - points switch TP 8 → 2 → 4;
  - the TP2 point turns KV offload on (749 GB) and the TP4 point turns it off;
  - the hint reads "4 of 8 GPUs";
  - state survives a reload.

## Details

- **Opt-in:** these are benchmark lanes (fixed client counts, synthetic-acceptance throughput runs), so the builder's defaults stay the recipe's own. The variants' existing B200/B300 blocks, which already carry the lanes' shared flags, are untouched.
- **CUDA graph sizes:** the B200 lane passed `--cudagraph-capture-sizes`; the presets set the same list as `cudagraph_capture_sizes` in `--compilation-config`, as the B300 lane does. vLLM maps the former onto the latter (they are mutually exclusive), and the JSON form keeps the YAML readable.
- **Thinking always on** follows the B200 lane's command, which passes `--default-chat-template-kwargs '{"thinking_mode":"enabled"}'` (the old builder steps omitted it).
- **Not in this PR:**
  - the GB200 Dynamo lane: aggregated Dynamo serving isn't a builder option yet;
  - the MI355X MXFP4 benchmark section: it has eval and throughput arms. That is a follow-up.
