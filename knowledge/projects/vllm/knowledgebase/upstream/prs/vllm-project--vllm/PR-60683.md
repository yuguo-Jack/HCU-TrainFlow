# [ROCm][Perf][Kimi-K3] Specialized decode for Kimi-K3 on MI355X

[Upstream PR](https://github.com/vllm-project/vllm/pull/60683) · state: open · merged: False

## Original PR description

## Purpose

An opt-in specialized decode for Kimi-K3 on MI355X (gfx950), TP8, following RFC #60904. It uses the same `specialized_decode` shape as #61867 (Kimi-K3, NVIDIA) and #60889 (GLM-5.2, ROCm), in layer mode. It is enabled with `additional_config={"decode_backend": "latency_specialized"}` and has no other options.

A pure spec-verify decode step of at most 8 rows runs each MoE decoder layer as persistent FlyDSL MonoKernels. The TP all-reduces run in-kernel over peer memory:

- **Whole layers** (68 KDA layers): K1 (AttnRes, in_proj, f_b, spec conv, KDA recurrence, gated RMSNorm), then K2.
- **FFN layers** (24 MLA layers): vLLM's AttnRes and MLA up to o_proj's input, then K2.
- **K2**: o_proj + all-reduce + MLP AttnRes, then the latent MoE (router, top-16 MXFP4 experts, shared experts, latent all-reduce + RMSNorm, up_proj, final all-reduce).

The kernels read vLLM's loaded weights and KDA states in place. Every other step (prefill, mixed, wider and PIECEWISE steps) runs vLLM's layers. With `decode_backend=auto` (the default) nothing changes.

### Refusal and steps

- **Refusal.** An unsupported deployment fails at startup with one `ValueError` that lists every reason. Refusals run in three stages: the config in `__init__`, the loaded weights when the model state builds the executor, and the KV caches at every bind. Every TP rank agrees on each verdict. It is default-deny for PP/DP/EP/EPLB/PCP, DBO, LoRA, KV connectors, routed-expert capture, sleep mode, CPU offload, weight updates, adaptive or dynamic speculative decoding, ReplaySSM/RecoverSSM, the V1 runner, `STOCK_TORCH_COMPILE`, other model shapes, and other GPUs or partitioned GPUs.
- **Steps.** `plan()` runs once per step. It picks the kernels for pure spec-verify steps of whole uniform requests at a built width, i.e. multiples of `k+1` up to 8 rows.
- **CUDA graphs.** vLLM's capture sizes are not changed. Under FULL graphs the plan is baked in at capture. A replay with fewer requests than its graph pads whole requests (null state slot, one accepted token), and the kernels serve those like real ones.

### Fail-stop

Every in-kernel wait gives up after 10 s. The rank records it in its sticky health words, so a stalled peer fails every rank instead of hanging them. In `compute_logits` each rank queues a non-blocking copy of its `FAILED` word. Every 16 steps the TP ranks agree on what has landed over the TP CPU group, and then every rank raises at the same step. This keeps all ranks out of the next collective.

Detection takes up to about 16 steps. A zero-delay check through a core hook can follow in a separate PR.
