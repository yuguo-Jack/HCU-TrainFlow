# [Frontend] Share non-streaming chat message assembly with batch derender

[Upstream PR](https://github.com/vllm-project/vllm/pull/63148) · state: closed · merged: True

## Original PR description

## Overview

Moves the non-streaming chat message assembly (which `tool_calls` to keep, `content` for forced tools, `include_reasoning`) into one helper that both `/v1/chat/completions` and batch derender call. Closes #57593, part of #42729.

## Claims

- New `assemble_chat_message_fields()` in `chat_completion/message_assembly.py`, used by `chat_completion_full_generator` and `OnlineDerenderer._parse_and_assemble`.
- No output change for `/v1/chat/completions` or `/cohere/v2/chat`. Serving still builds the message through `_create_chat_message` / `_finalize_response_message`.
- `/v1/chat/completions/derender` and generate `output_mode="derender"` now drop tool calls where coupled chat already did, instead of returning them:
  - Harmony (gpt-oss) with `tool_choice: "none"`. `HarmonyParser` doesn't gate on it and coupled chat dropped them since #30867.
  - Any tool parser with `tools` set and `tool_choice: null`.
  - Auto tools off or `"auto"` with no tools.
- Drops the now unused `ChatCompletionResponseChoice` branch from `maybe_filter_parallel_tool_calls`.

## Validation

```bash
pytest \
  tests/entrypoints/openai/chat_completion/test_message_assembly.py \
  tests/entrypoints/openai/chat_completion/test_serving_chat.py \
  tests/entrypoints/openai/chat_completion/test_include_reasoning.py \
  tests/entrypoints/openai/chat_completion/test_completion_with_function_calling.py \
  tests/entrypoints/scale_out/derender/test_derender.py \
  tests/entrypoints/scale_out/derender/test_derender_stream.py \
  tests/entrypoints/scale_out/derender/test_derender_parity.py -v
pytest tests/entrypoints/cohere -q
```

New tests:
- `test_message_assembly.py`: unit tests for every branch, plus `include_reasoning`, `parallel_tool_calls=false` and tool call ID handling. No tokenizer needed.
- `test_derender_chat_drops_tool_calls_without_tool_choice`: batch derender with hermes + `tool_choice: null` and a stub parser that ignores `"none"`.
- `test_derender_text_choices_drops_tool_calls_without_tool_choice`: same for generate `output_mode="derender"`.
- `test_e2e_harmony_tool_choice_none_drops_tool_calls`: real gpt-oss render server, `"auto"` as a control.

No model eval. Generation is untouched and `/v1/chat/completions` output is the same. The derender change only picks which parser output to return.

No docs change. `docs/serving/online_serving/derenderer.md` already says derender gives the same `content` / `reasoning` / `tool_calls` split as `vllm serve`. This makes that true in more cases.

## Details

Serving and derender each had their own copy of the tool choice branching and derender's copy left out the "drop tool calls" branches. It relied on the parser to gate instead. Not every parser does: `HarmonyParser` ignores `"none"` and `AbstractParser` treats `null` as auto.

The helper takes the `Parser.parse()` output and returns the fields rather than a `ChatMessage`, so Cohere v2 can keep using its own message class. The parallel tool call filter now runs on the list before the message is built, not on the choice afterwards. `[:1]` of a non-empty list is still non-empty, so `finish_reason` doesn't change.

Not covered here: streaming (coupled streaming still keeps tool calls for Harmony `"none"` and for `null`), `role` and `echo` in derender. Those need their own issues.
