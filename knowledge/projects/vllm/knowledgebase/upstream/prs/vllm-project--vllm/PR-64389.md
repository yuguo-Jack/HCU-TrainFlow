# [Model] Muse Spark: support compressed-tensors MXFP4 experts on NVIDIA

[Upstream PR](https://github.com/vllm-project/vllm/pull/64389) · state: open · merged: False

## Original PR description

## Purpose

Add NVIDIA support for Muse Spark checkpoints quantized with llm-compressor
(compressed-tensors): FP8 block-quantized dense layers and MXFP4 routed experts.
Today only NVFP4 (modelopt) is accepted on the NVIDIA path.



## Changes

- **Quant config:** accept `CompressedTensorsConfig` and rewrite llm-compressor's
  `re:` targets from HF module names to vLLM names. Without this, experts
  silently build as BF16 and fail to load the packed MXFP4 tensors.
- **Weight loading:** load per-expert gate/up/down tensors through the generic
  `RoutedExperts` path, and keep them unstacked in the weights mapper (now
  shared with the AMD model). Fix FP8 block-scale slicing in the fused
  QKV+O-gate loader.
- **MoE method:** add `MuseSparkCompressedTensorsMxfp4FusedMoE`, which applies the
  post-expert norm via `post_gemm2_hook` on Humming (default, W4A8 block-FP8 on
  SM90+) and Marlin (W4A16).
- **Humming experts:** add `post_gemm2_hook` support to the indexed and grouped
  experts. Batched experts raise `NotImplementedError`.
- **Pooler/unpooler:** quantize them for compressed-tensors checkpoints, and
  skip the sharded-projection path when they are quantized.

## Notes / Limitations

- Marlin path ignores the declared FP8 activation scheme (W4A16).
- `post_gemm2_hook` unsupported for padded all2all batches and batched Humming.
