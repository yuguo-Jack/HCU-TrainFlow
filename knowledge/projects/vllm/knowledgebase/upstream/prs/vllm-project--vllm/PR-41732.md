# [MRV2] enable lora for cuda graph

[Upstream PR](https://github.com/vllm-project/vllm/pull/41732) · state: closed · merged: False

## Original PR description

## Purpose
Fix the FIXME(woosuk): Fix warmup for LoRA in Model Runner V2 (MRV2).

In the V2 architecture ( GPUModelRunner ), the execution path was decoupled, and the dummy run logic for memory profiling and CUDA Graph capture did not correctly activate the dummy LoRA weights. This caused the SGMV (Segmented GEMM) kernels to be omitted during the warmup phase when LoRA was enabled, leading to potential performance degradation or runtime errors when actual LoRA requests arrived.

This PR wraps the inner execute_model call inside _dummy_run and the cudagraph_manager.capture call inside capture_model with the maybe_setup_dummy_loras and maybe_select_dummy_loras context managers. This ensures that the correct number of active dummy LoRAs are injected and captured in the CUDA Graph execution plans.

This block incorrectly attempts to set active LoRAs during a `dummy_run` by querying `self.lora_state`. Since `lora_state` only tracks actual requests and does not contain the dummy request IDs generated for warmup (e.g., `_dummy_req_0`), `make_lora_inputs` will return an empty set of LoRA requests. This call to `_set_active_loras` will then overwrite and clear the dummy LoRA state previously established by the `maybe_select_dummy_loras` context manager in `_dummy_run`. Since the context manager already handles the necessary LoRA activation for warmup, this entire block should be removed.

File: `vllm/v1/worker/gpu/model_runner.py` · line 621

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The `maybe_select_dummy_loras` context manager is used here with a fixed `num_scheduled_tokens=[self.max_num_tokens]`, which results in a LoRA mapping for only a single request. However, `cudagraph_manager.capture` iterates through various batch sizes and request counts (up to `max_num_seqs`). When capturing graphs for batches with multiple requests, the LoRA layers will encounter a mapping size mismatch (e.g., prompt mapping size 1 vs batch size N), leading to runtime errors or incorrect graph capture. To support multi-request CUDA graphs with LoRA, the dummy LoRA selection must be performed for each specific capture size, which likely requires moving this logic inside the capture loop or ensuring the mapping covers the maximum possible request count and token count.
