# fix: reject unsupported encoder-only prefix caching

[Upstream PR](https://github.com/vllm-project/vllm/pull/55159) · state: open · merged: False

## Original PR description

## Motivation and Context

When an encoder-only pooling model does not support prefix caching, explicitly passing `--enable-prefix-caching` currently falls through to a warning and can later fail with an internal assertion. This change fails fast with a clear configuration error for that specific case.

Pooling models that support prefix caching, decoder pooling models, and implicit/default configuration retain their existing behavior.

Fixes #55049

## What does this PR change?

- Raise a clear `ValueError` for unsupported encoder-only pooling prefix caching.
- Add parameterized regression coverage for supported and unsupported combinations.

- Manny7717 · APPROVED · 2026-09-03T14:10:20Z · [source](https://github.com/vllm-project/vllm/pull/55159#pullrequestreview-5102986515)

Verified end-to-end with executed tests on head (aa999b9a1) and base (bb363db9a).

**Bug is real.** For encoder-only pooling models (e.g. BGE), `ModelConfig.is_prefix_caching_supported` hardcodes False (vllm/config/model.py:2102-2107: bidirectional attn → no prefix caching). `--enable-prefix-caching` overrides that default in `_set_default_chunked_prefill_and_prefix_caching_args` (arg_utils.py:2754-2764) and previously fell through to `logger.warning_once` — after which the engine dies later in `HybridKVCacheCoordinator` with the internal assertion "requires at least one cacheable group" (vllm/v1/core/kv_cache_coordinator.py:704), exactly as documented in #55049 by iharshlalakiya.

**Fix is correct and correctly narrow.** The new raise fires only in the crash class: pooling runner + explicit truthy `enable_prefix_caching` + unsupported default + `attn_type == "encoder_only"`. Decoder pooling models without official support (MEAN/CLS/STEP poolers) still take the warning-only path — correct, because they have cacheable KV groups and don't crash. `None` (auto) is consumed by the `if` branch above and never reaches the raise; supported models skip the `elif` entirely. The ValueError surfaces during engine-config creation (arg_utils.py:2023, before workers spawn) with an actionable message.

**Regression-proven (executed, VLLM_TARGET_DEVICE=cpu):** `test_prefix_cache_pooling_model_validation` — the `(True, encoder_only, False, True)` case FAILS on base code (no ValueError raised) and PASSES on head; the other 3 parametrized cases pass on both (auto/decoder/no-raise controls). Full test file: base 100 passed + 1 failed vs head 101 passed — the delta is exactly the new regression test; zero regressions.

Non-blocking nits only: (1) the guard lives on the EngineArgs path — a programmatic `VllmConfig(enable_prefix_caching=True)` construction for an encoder-only pooling model would still reach the coordinator assertion (no validator on VllmConfig/CacheConfig); CLI/LLM() users are fully covered. (2) The test's SimpleNamespace model_config is fine for unit level, though the `(True, encoder_only, True, ...)` state is unreachable today since encoder-only pooling always reports unsupported. Neither holds the PR.
