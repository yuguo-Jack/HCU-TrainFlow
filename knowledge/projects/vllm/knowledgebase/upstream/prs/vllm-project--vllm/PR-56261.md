# [Perf][KV Connector] Reuse Mooncake block grouping per group

## Original PR description

<!-- markdownlint-disable -->

## Purpose

Avoid repeating Mooncake block grouping for aligned regions with identical
request-local block selections. Cache grouped IDs only after a region's sender
plan chooses to transfer; addresses, lengths, TP offsets and coalescing remain
region-specific. NULL filtering and logical-to-physical expansion are unchanged.

The cache key is `(group_index, shared_group_ids)`: packed allocations can use
the same shared-group sentinel but select different groups or orders. The cache
is reset for each request, not shared across requests.

This is distinct from #53078/#55097 and #53237, which address heterogeneous-TP
correctness, NULL alignment or descriptor granularity rather than repeated
grouping. The current base still groups each region independently. No public
API, configuration or model change.
