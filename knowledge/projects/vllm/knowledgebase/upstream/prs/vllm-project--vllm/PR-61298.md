# [Bugfix][KV Connector][Mooncake] Fix Store reset scope and failure reporting

[Upstream PR](https://github.com/vllm-project/vllm/pull/61298) · state: open · merged: False

## Original PR description

## Overview

Fix Mooncake Store resets clearing other deployments' caches and reporting success when SDK removal fails.

## Claims

- Scope reset to the configured `cache_prefix` using `remove_by_regex(force=True)` with an escaped prefix and `@` boundary.
- Report failure for negative or invalid SDK results, including booleans.
- Preserve global removal for an empty prefix and existing send-queue draining.

## Validation

```bash
source .venv/bin/activate
uv run --no-sync .venv/bin/python -m pytest \
  tests/v1/kv_connector/unit/test_mooncake_store_{worker,connector,scheduler}.py -q
```

**301 tests passed; scoped pre-commit passed.**

Single-GPU Qwen2.5-1.5B-Instruct E2E with native Mooncake TCP SDK/Master verified prefix isolation. All 12 cold/warm/post-reset output sequences matched the pre-fix worker.

Existing native artifacts were reused; multi-rank and active-transfer reset were not tested.

## Details

The RESET handler called `remove_all()` regardless of `cache_prefix` and ignored its return value. This could delete another deployment's cache within the same tenant or acknowledge a failed removal.

All instances sharing the reset scope must be quiescent; nonnegative SDK counts do not guarantee complete deletion.

Duplicate check: #58670 handles reset events; this PR fixes deletion scope and SDK result handling.

AI assistance: OpenAI Codex assisted with implementation, review, tests and drafting.
