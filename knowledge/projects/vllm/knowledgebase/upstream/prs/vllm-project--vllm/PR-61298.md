# [Bugfix][KV Connector][Mooncake] Report Mooncake Store reset failures

[Upstream PR](https://github.com/vllm-project/vllm/pull/61298) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`LLM.reset_prefix_cache(reset_connector=True)` returns `True` even when Mooncake fails to clear the Store.

## Root cause

The worker's RESET handler calls `store.remove_all(force=True)` and always replies ACK. The SDK reports failure by returning a negative `ErrorCode` rather than raising, so the result was dropped. The scheduler already maps a worker NACK to `False`.

## Change

NACK when `remove_all()` returns a negative value:

```python
removed = self.store_worker.store.remove_all(force=True)
if removed < 0:
    logger.error("Mooncake remove_all failed with error code %d.", removed)
    self.socket.send(RESP_ERR)
```

Exceptions still NACK as before; the send-queue drain is unchanged.

## Relationship to other work

#58670 also touches reset handling but does not check the removal result. Scoping the reset to `cache_prefix` is left to a follow-up PR.

## Validation

- Mooncake store unit tests and pre-commit pass. The new test fails on main for a negative result.
- Native Mooncake Master (TCP), Qwen2.5-0.5B-Instruct: generate, then call `reset_prefix_cache(reset_connector=True)` with the Master running and again after killing it.

| | Master running | Master killed |
| --- | --- | --- |
| main | `True` | `True` |
| This PR | `True` | `False` (`remove_all` returned -900) |
