# [Rust Frontend] Pass pulled object storage model dir to the Rust frontend

[Upstream PR](https://github.com/vllm-project/vllm/pull/61788) · state: open · merged: False

## Original PR description

## Purpose

When using the rust frontend, if model tag points to object storage (eg S3), vllm serve fails at startup. This is bc the Rust frontend tries to resolve the path as a HF repo id, which returns 404.

`ModelConfig.maybe_pull_model_tokenizer_for_runai` already pulls the config and
tokenizer files into a local directory and sets `model_config.model` to it. The
weights keep streaming from `model_config.model_weights`. But
`RustFrontendProcessManager` builds `model_tag` from the raw CLI args, so the
Rust frontend never sees the local directory.

So we pass `vllm_config.model_config` to `RustFrontendProcessManager`. For
object storage models, it forwards the pulled directory as `model_tag`. Unless
`--served-model-name` was given, it also sets `served_model_name` to the
original URI, so the served model name matches the Python frontend's.
