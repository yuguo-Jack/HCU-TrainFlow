# [ROCm][DSv4] Overlap the unfused shared expert with AITER MegaMoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/61819) · state: closed · merged: True

## Original PR description



## Overview

With `--moe-backend aiter_mega_moe` and an unfused shared expert, DeepSeek-V4 on ROCm ran the shared expert after the router and MegaMoE, on the main stream. This PR runs it on the aux stream next to the router + MegaMoE through `maybe_execute_in_parallel`. It follows the existing `VLLM_DISABLE_SHARED_EXPERTS_STREAM` / `VLLM_SHARED_EXPERTS_STREAM_TOKEN_THRESHOLD` convention: the overlap applies to steps of at most 256 tokens by default, and `VLLM_DISABLE_SHARED_EXPERTS_STREAM=1` keeps the serial order. ATOM overlaps its shared expert with the routed experts the same way.

## Claims

- DeepSeek-V4-Pro, AgentX agentic workload: P90 interactivity +2.7% at concurrency 128 and +6.4% at concurrency 64.
- No accuracy change on gsm8k.
- Prefill-sized steps and the fused shared-expert path are unchanged.

## Validation

Setup:
- DeepSeek-V4-Pro on 8x MI355X, DP8 attention + EP8 AITER MegaMoE, shared expert unfused.
- AgentX agentic workload, 1200 s runs, requests counted in the 300-1200 s window.
- Single runs per configuration.

| | Without | With this PR |
|---|---:|---:|
| c128 (same node, same job): P90 interactivity (tok/s/user) | 27.13 | 27.87 (+2.7%) |
| c128: output tok/s/GPU | 335 | 346 (+3.3%) |
| c128: total tok/s/GPU | | +1.4% |
| c64 (same node, separate jobs): P90 interactivity | 48.26 | 51.33 (+6.4%) |
| c64: P50 interactivity | 61.65 | 64.31 (+4.3%) |
| c64: total tok/s/GPU | | -1.5% |
| gsm8k 5-shot, real speculative decoding (flexible / strict) | 0.9697 / 0.9704 | 0.9727 / 0.9735 |

Unit tests and lint:
- `pytest tests/models/test_deepseek_v4_aiter_mega_moe.py` on MI355X: 10 passed, against 6 on main. The 4 new cases run the shared expert on the aux stream.
- `pre-commit run --files <changed files>`: all hooks passed, mypy included. This was rerun on the current main, which includes #61262.

## Details

- When MegaMoE fuses the shared expert, `shared_experts` is `None` and the routed path runs alone, as before.
- `maybe_execute_in_parallel` falls back to sequential execution when the stream is `None` and during breakable CUDA graph capture.
- #61262's runtime selection runs inside the MegaMoE call on the main stream, so it is not affected.

- Paired over questions, the difference is +0.51 ± 0.67 pp, within the 1 pp bound of #59665.
- Both arms score above the official Think High result (89.1). Both arms see identical prompts, so only the difference between them matters here.

Setup:
- DeepSeek-V4-Pro on 8x MI355X, DP8 attention + EP8 AITER MegaMoE, shared expert unfused, DSpark K6 with real rejection sampling.
- Both arms use the same image (nightly 77154ca6). The PR arm adds this PR's `model.py` change and nothing else.
- `--max-num-seqs 32` per rank and 256 requests in flight. Decode-only steps then stay at or below 224 tokens, so every one of them takes the new overlap path (the threshold is 256).
- 198 questions from `fingertap/GPQA-Diamond`, an ungated mirror of the official set, 4 samples each.
- Sampling: thinking on with `reasoning_effort: high`, temperature 1.0 and top_p 1.0 (the model's `generation_config`), at most 131072 output tokens.
- Prompt: the simple-evals format, ending in `Answer: $LETTER`. The score is the last `Answer:` line of the final content. A response still thinking at the cap counts as wrong.

NIAH (RULER, 8 needle tasks at 64K and 128K) is running. I will post it when it finishes.

> Where do you think the c64: total tok/s/GPU regression comes from?

I think it is run-to-run noise. AgentX results vary from run to run: on this setup, 20-minute windows of one 1-hour run differ by up to ~20% in output throughput. The two c64 runs came from separate jobs, so a 1.5% difference in total tok/s is within that noise. The c128 pair ran in one job on the same node, and there total tok/s went up by 1.4%.
