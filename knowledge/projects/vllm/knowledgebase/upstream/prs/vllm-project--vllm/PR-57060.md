# [Frontend] Migrate VLLM_ENABLE_RESPONSES_API_STORE to CLI flag

[Upstream PR](https://github.com/vllm-project/vllm/pull/57060) · state: open · merged: False

## Original PR description

## Purpose

Migrates `VLLM_ENABLE_RESPONSES_API_STORE` (env var) to `--enable-responses-store` (a CLI flag on `FrontendArgs`), 

**Changes:**
- `vllm/envs.py` — removed the declaration and runtime lambda.
- `vllm/entrypoints/launchers/cli_args.py` — added `enable_responses_store: bool = False` to `BaseFrontendArgs` (auto-generates the `--enable-responses-store` CLI flag).
- `vllm/entrypoints/openai/responses/serving.py` — added `enable_store` kwarg to `OpenAIServingResponses.__init__`, updated the warning and error messages to reference the new flag.
- `vllm/entrypoints/generate/api_router.py` — threaded `enable_store=args.enable_responses_store` into the constructor.
- Six `tests/entrypoints/**/responses/*.py` fixtures — swapped `env_dict={"VLLM_ENABLE_RESPONSES_API_STORE": "1"}` for `--enable-responses-store` on the spawned server args.
- `examples/tool_calling/openai_responses_client_with_mcp_tools.py` — updated the docstring instructions.



## Test Plan

- `pre-commit run --files $(git diff --name-only)` — all applicable hooks on the changed files.
- `pre-commit run mypy-3.12 --files $(git diff --name-only) --hook-stage manual` — the strict CI-equivalent mypy check.
- The six updated integration tests under `tests/entrypoints/**/responses/` continue to exercise the store-enabled path — they now activate it via the CLI flag instead of the env var. These require GPU + Qwen3 models, so they run in CI on the vLLM infrastructure rather than locally.
