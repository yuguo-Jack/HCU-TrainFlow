# [Bugfix][Parser] Repair tool argument types without breaking streamed prefixes

[Upstream PR](https://github.com/vllm-project/vllm/pull/63385) · state: open · merged: False

## Original PR description

## Overview

Tool-call argument repair in the parser engine now keeps typed values for
untyped schema properties and rewrites arguments **in place**, so schema-aware
correction can never invalidate an already-streamed argument prefix. Streaming
correction is incremental: each delta rescans only the tail after the last
finalized member and survives ticks an argument extender streams, so long
streams no longer pay a full-document rewrite per tick. Fixes the
untyped-schema stringification reported in #47557
(typed-value half) and supersedes #47560.

## Claims

- Typed values emitted for untyped schema properties (JSON and K2
  `xml_typed`) are kept as-is instead of being stringified and re-coerced
  through a `json.dumps` round trip.
- Streamed tool-call arguments remain prefix-consistent under **any** model
  formatting: previously, a coerced or sanitized value in the middle of a
  partial object produced text that could not extend the already-streamed
  prefix, silently truncating the call (`startswith` failure in the flush).
- Streamed correction is incremental and composes with `arg_value_extender`.
  The per-slot cache resumes after the last top-level comma whose member is
  finalized and starts with a quoted key whenever that finalized prefix is
  unchanged — not only when the whole converter output is a prefix — and
  extender output advances the cache instead of invalidating it. The re-parsed
  tail must reproduce the text already emitted from that comma, including the
  extender's bytes; otherwise the delta falls back to a full pass. It never
  resumes past a structural give-up.
- Union handling is conjunctive where it decides whether a schema is untyped:
  an untyped `anyOf` branch no longer overrides a typed `oneOf`, and every
  `allOf` branch must be untyped. Declared types are still unioned across
  `anyOf`/`oneOf`/`allOf`.
- Value-preserving re-encodings stay verbatim: `5e3` under an integer schema,
  overflowing literals (`1e999`), and untyped-union literals are no longer
  rewritten to a different textual form of the same (or a wrong) value.
- K2 Horizon `xml_typed` calls honor the model's explicit `<arg_type>` tag
  when the property schema is untyped or resolves no type (an unresolved
  `$ref`), matching the missing-schema path.
- A property whose only constraint is an unresolved `$ref` (common in
  Pydantic-generated schemas, e.g. int-enum references) keeps the emitted
  type instead of being repaired toward string.
- Pathological nesting cannot crash a request. The argument rewriter and both
  schema walks share a 200-level bound: deeper argument nesting passes through
  verbatim, and a client-supplied schema nested past the cap is treated as
  unknown/constrained instead of raising `RecursionError`.
- A `false` schema contributes no type to a union and honors the caller's
  `fallback`.
- The schema-less fast path only parses when a **bare** `NaN`/`Infinity`
  token is present, not when that text merely occurs inside a string (e.g.
  `"banaNaNa"`).

Incremental correction is a clear win for parsers whose converter passes the
argument text through verbatim (Granite, Inkling). Extender-based XML parsers

## Details

**Root cause.** `_fix_arg_types` repaired argument types by round-tripping
the whole document: `json.loads` → recursive coercion → `json.dumps`. Two
defects followed. First, properties without a `type` extracted the
historical `["string"]` fallback, so an already-typed value (`5`, `true`, a
nested object) was stringified and then "repaired" back — losing structure
for containers and emitting the wrong type for scalars in the untyped-union
case. Second, the final `json.dumps` normalized separators (`", "`, `": "`)
and number forms, so the corrected text of a delta did not extend the text
already streamed for earlier deltas; the flush's `startswith` check then
silently dropped the remainder of the call whenever a middle value needed
correction and the model's formatting differed from `json.dumps` output.

**Fix.** `_ArgsRewriter` rewrites the argument text **in place**: only
complete value tokens that a property schema coerces, plus bare
`NaN`/`Infinity` literals, are replaced; every other byte — separators,
whitespace, number formats, escapes, key order — stays verbatim, so a
rewritten delta extends every earlier one by construction. `_fix_arg_types`
is the rewriter at EOF. For streaming, a per-slot `_StreamingArgs` cache
resumes the rewriter from the last finalized member instead of re-parsing the
whole accumulated document, carries the safe-prefix boundary and split-escape
state forward, and falls back to a full pass whenever the finalized prefix
changes or the re-parsed tail does not reproduce the text already emitted.
A converter that re-serializes its output rewrites the closing brace on every
tick, so the gate is the finalized prefix, not the whole previous document;
bytes an argument extender streamed advance the cache instead of invalidating
it, and the tail check covers them. It never resumes past the first structural
give-up, because a tail scan from a different start could infer different
corrections than a full pass.

Schema decisions go through `schema_admits_any_value` (explicitly untyped
schemas short-circuit coercion) and a conjunctive `anyOf`/`oneOf`/`allOf`
reading of `extract_types_from_schema`, threaded with a `fallback` parameter:
coercion callers pass `[]` so both explicitly untyped and unresolved-`$ref`
schemas keep emitted values verbatim, while callers that need a concrete type
keep the string default. Both recursive schema walks share
`MAX_NESTING_DEPTH = 200` with the argument rewriter, so neither client input
can recurse to the interpreter limit. `false` schemas honor the fallback
instead of injecting a string type, and a value-equality gate keeps
re-encodings that do not change a literal's type or value verbatim.

**Structure.** The argument rewrite and incremental-streaming subsystem
(`_ArgsRewriter`, `_StreamingArgs`, the non-finite predicates, and the
comma/resume scanners) lives in `vllm/parser/engine/arg_rewrite.py`;
`parser_engine.py` keeps the engine proper and delegates the prefix scan.
This is a pure extraction with no behavior change, and it removes the
forward reference from `_StreamingArgs` into `ParserEngine`.

**Scope.** The change is engine-level because the repaired path is reachable
from every typed-value parser (Granite, Inkling, Kimi K2, DeepSeek DSML) and
was wrong for all of them; text-format parsers are unaffected. Untyped *raw
text* behavior (the open question in #47557) is deliberately unchanged, and
the Rust frontend's string-preservation tests still pin that direction.

**⚠ Behavior change / migration note.** Values for untyped properties that
are JSON containers are now delivered as structured JSON instead of a
JSON-text string: `{"payload": {"a": [1, 2]}}` instead of
`{"payload": "{\"a\": [1, 2]}"}`. Clients that re-parsed the string are
unaffected; clients that expected a string fail loudly at their own parse
boundary. Non-finite floats (`NaN`) under untyped properties are delivered
as their string form so the arguments stay valid JSON. Likewise, a bare
number under a `$ref`-only property is no longer repaired toward string
(`{"zipcode": 12345}` stays `12345` when the type sits behind an
unresolved reference) — corrupting a correct int was judged worse than
leaving a schema-violating number unquoted, and `$defs` resolution
(#50933) will repair both directions. K2 JSON arguments containing a
non-finite literal under a typed number/integer property now keep the call
with the string form (`"NaN"`) instead of failing to serialize and dropping
the whole tool-call group; non-finite values have no valid JSON form, and
losing valid sibling calls was judged worse than a string-typed value.

**Related work.** Supersedes #47560 (its Rust half targets deleted code; its
Python half takes the coercion-guessing direction rejected here — the
text-path question remains open on #47557). Composes with the merged #55743
(exact integers). #57005 and #50933 touch the same files and should rebase
on top of this; #47643, #49318, #61410 are complementary.
