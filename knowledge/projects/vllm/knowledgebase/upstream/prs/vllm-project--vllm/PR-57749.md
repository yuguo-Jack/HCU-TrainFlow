# [Spec Decode] Warn when the batch exceeds the draft context limit

[Upstream PR](https://github.com/vllm-project/vllm/pull/57749) · state: open · merged: False

## Original PR description

## Overview

Report when MRV1 skips draft generation because a batch exceeds the draft model's context limit. This makes an existing speculative-decoding fallback visible.

## Claims

When one sequence exceeds the limit, the current code silently skips drafting for the entire batch, including shorter requests. Those requests lose speculative decoding for that step without a message that explains the cause.

The change emits one warning per context limit and identifies `speculative_config.max_model_len`. It preserves the existing fallback, scheduling, and generated tokens.

## Validation

```bash
.venv/bin/python3 -m pytest tests/v1/worker/test_gpu_model_runner.py \
  -k draft_context_limit_warning --noconftest -q
pre-commit run --files vllm/v1/worker/gpu_model_runner.py \
  tests/v1/worker/test_gpu_model_runner.py
```

The two regression cases passed on macOS arm64 with Python 3.12.13. They cover the exact boundary, the first over-limit input, the extra DFlash query token, and missing attention metadata. The cases call the real runner method with minimal metadata. `--noconftest` excludes unrelated GPU fixtures.

Restoring the predicate from main in memory makes both cases fail because no warning is emitted. All applicable pre-commit hooks passed. The test remains in the existing worker suite, and the Buildkite test-tethering hook passed.

A GPU serving reproduction of the warning remains pending. No model evaluation or throughput improvement is claimed. The Testing and Validation item remains open until the serving reproduction is complete.

## Details

`_input_fits_in_drafter()` compares the maximum sequence length plus draft query tokens against `effective_drafter_max_model_len`. A false result takes the existing fallback that suppresses draft tokens for the batch.

The warning uses the existing `warning_once` helper and a stable context-limit argument. It adds no GPU reads or synchronization. Increasing the draft limit is appropriate only when the draft model supports the requested length.

This is a diagnostic for deployments that still use MRV1. MRV2 uses separate speculator implementations and does not call this predicate, so this PR does not port the legacy warning into MRV2.

Open-PR searches for draft context-limit warnings found no other PR with this runtime diagnostic. #52546 concerns a configuration-time warning about an ignored setting.
