# [Bugfix][Benchmark] Fix sweep --resume with warmup and recorded failures

[Upstream PR](https://github.com/vllm-project/vllm/pull/59816) · state: open · merged: False

## Original PR description

## Purpose

Fixes #59809.

`--warmup-num-prompts` and `--continue-on-error` (#57305) do not compose with `vllm bench sweep serve --resume`:

1. **A resumed sweep measures a cold server.** When a sweep is interrupted partway through a combination, `--resume` starts a new server for it, finds `warmup.json` from the previous attempt, prints `[SKIPPED BENCHMARK]` and goes straight to the remaining measured runs. Those runs are not comparable with the ones measured before the interruption.
2. **A failure recorded by `--continue-on-error` breaks the next invocation.** `summary.json` is still written from the runs that succeeded, so the next invocation starts no server for that combination and `run_benchmark` raises `ValueError: Cannot find results at .../run=1.json`. Without `--continue-on-error` that aborts the resumed sweep; with it, the run is recorded as failed again on every invocation and is never retried.

Changes in `vllm/benchmarks/sweep/serve.py`:

- `run_comb` runs the warmup whenever the combination still has measured runs to do, replacing a `warmup.json` left by a previous invocation. It is skipped only when nothing is left to measure.
- `_comb_needs_server` also starts the server when a combination is missing a run result within the requested `--num-runs`, so a failed run is retried on resume. `summary.json` is still written from the successful runs, so the plotting scripts keep seeing partial results.
- The `.failure.json` of a run is removed once that run succeeds.

`vllm bench sweep serve_workload` reuses `run_comb`, so it gets the warmup fix as well; it now passes `num_runs` to `server_ctx`. The docs tip about `--resume` is updated.

Not a duplicate: I searched open and closed PRs for `sweep resume warmup`, `sweep serve resume`, `continue-on-error sweep`, `warmup-num-prompts`, `sweep in:title` and the issue number. The only PR touching this logic is #57305, which introduced both options. The open sweep PRs (#55500, #55664, #55716, #55740) touch other files.

Three tests are added. They use a stub in place of `ServerProcess` that writes the requested result file, so the real `run_benchmark` skip/raise logic is exercised:

- `test_run_comb_resume_warms_up_restarted_server`: the warmup is re-run on the new server when a measured run is pending, and not run when all runs exist.
- `test_run_combs_resume_retries_recorded_failure`: a run that failed under `--continue-on-error` is retried by the next `run_combs` call, the summary then holds all runs and the failure file is gone.
- `test_run_combs_resume_ignores_failure_outside_requested_runs`: resuming with a smaller `--num-runs` reuses the existing results and starts no server for a failed run that is no longer requested.

One compatibility case at `serve.py:173-174`: the new failure-file glob includes runs outside the current `num_runs` range. Start a three-run sweep with `--continue-on-error`, let runs 0 and 1 succeed and run 2 fail, then resume with `--num-runs 2`. Both requested results already exist, but `run=2.failure.json` starts a server. `run_comb()` only visits runs 0 and 1, so that marker remains and every later resume starts another unused server without running a benchmark.

Could retry detection be limited to the currently requested run range? This keeps in-range failures retryable while allowing a completed reduced-run sweep to reuse its results.

The additional case below passes on main and fails on this PR with `AssertionError: Started 3 servers ...` after the initial sweep and two resumes. It exercises real `run_combs()` and result files, replacing only `run_server` with the PR's stub. It can be appended to `tests/benchmarks/sweep/test_param_sweep.py`, which already imports the names it uses.

```python
def test_completed_requested_runs_ignore_failure_outside_requested_range(
    monkeypatch: pytest.MonkeyPatch, tmp_path: Path
):
    """Reducing num_runs must not repeatedly boot an unused server on resume."""
    started: list[_StubServer] = []

    @contextlib.contextmanager
    def fake_run_server(*args, **kwargs):
        server = _StubServer(failing=("run=2.json",) if not started else ())
        started.append(server)
        yield server

    monkeypatch.setattr(sweep_serve, "run_server", fake_run_server)

    def run(num_runs: int, continue_on_error: bool):
        return sweep_serve.run_combs(
            [],
            [],
            [],
            show_stdout=False,
            server_ready_timeout=1,
            serve_params=ParameterSweep.from_records([{}]),
            bench_params=ParameterSweep.from_records([{"num_prompts": 100}]),
            link_vars=[],
            experiment_dir=tmp_path,
            num_runs=num_runs,
            warmup_num_prompts=0,
            dry_run=False,
            continue_on_error=continue_on_error,
        )

    assert list(run(3, True)["run_number"]) == [0, 1]
    assert len(list(tmp_path.rglob("run=2.failure.json"))) == 1

    for _ in range(2):
        assert list(run(2, False)["run_number"]) == [0, 1]

    summary_path = next(tmp_path.rglob("summary.json"))
    assert [
        record["run_number"] for record in json.loads(summary_path.read_text())
    ] == [
        0,
        1,
    ]
    assert len(started) == 1, (
        f"Started {len(started)} servers although the two requested result files "
        "already existed; the out-of-range failure persists across resumes."
    )
```
