# [Bugfix][ROCm] Muse Spark: merge the two process_weights_after_loading hooks

## Overview

Fixes #65081, the pre-commit failure on `main` since #63440 merged:

```
vllm/models/muse_spark/amd/model.py:1214: error: Name "process_weights_after_loading" already defined on line 1207  [no-redef]
```

#64357 and #63440 each added `process_weights_after_loading` to `MuseSpark1xForCausalLM`, and the second definition replaced the first. Every pre-commit run on `main` since 04:46 UTC has failed, so any PR that reruns CI fails it too (e.g. #65005).

## Claims

- One hook that runs `materialize_residual_path_constants`, then `maybe_attach_mono`.
- On ROCm, `main` currently skips the first step: residual coefficients are recomputed every forward, the router output multiplier is never folded, and `--monokernel` refuses to attach (its guards in `mono/decoder.py` require both).

## Validation

- `mypy --python-version 3.11 --follow-imports skip vllm/models/muse_spark/amd/model.py` (mypy 1.20.2, as pinned in pre-commit): the `no-redef` error on `main`, clean with this change.
- `ruff check` and `ruff format --check` pass.
- Not run end to end: I don't have an MI355X. `tests/models/test_muse_spark_rocm_mono.py::test_layer_guards_follow_the_weight_finalize` covers this path, but it needs gfx950 and isn't in CI.

## Details

- Order matters: materializing folds the router multiplier into `router.weight` and caches the gate coefficients, and the monokernel reads both, including when it refreshes after a reload.
- Not a duplicate: no open PR touches this file's hook.
- AI assistance (Claude Code) was used. I reviewed the change.
