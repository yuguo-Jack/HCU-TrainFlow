# [Bugfix] Invalidate stale multimodal startup plans

[Upstream PR](https://github.com/vllm-project/vllm/pull/60228) · state: open · merged: False

## Original PR description

## Overview

A startup plan can reuse too much KV memory after multimodal settings change. This change includes the normalized multimodal configuration in the memory plan key, so the worker profiles memory again when needed.

## Claims

- Reject saved plans when multimodal memory-profile settings change.
- Reuse equivalent nested mappings regardless of insertion order.
- Use normal profiling for unsupported values. Preserve compiler-cache reuse.

## Validation

| Check | Baseline | Patch |
| --- | --- | --- |
| Recorded startup-plan regression cases | 7 failed, 3 passed | 10 passed |
| Worker suite in recorded native validation | — | 30 passed |
| KV allowance after settings change | Reused 16.79 GiB | Profiled 13.96 GiB |

The GPU test used SmolVLM-256M BF16 on one L4. The old plan allowed **2.83 GiB of excess KV memory** compared with a fresh profile. The image limit and encoder-profiling mode changed together in this test. Unit tests check those settings separately. No out-of-memory failure was observed.

All 36 greedy image requests passed across two test series. Prompt and output token IDs matched within each series. The checks cover serving behavior, rather than general vision accuracy. No startup or request-speed gain is claimed.

The recorded startup-plan regression checks passed on the tested base. After the main update, all applicable pre-commit hooks passed, including the current Python 3.11 mypy hook. The production plan module and startup-plan test bodies are unchanged. GPU and model checks were not rerun for this update. Upstream test CI is blocked by the contributor gate.

## Details

Open PR searches found no other fix that keys startup plans on the complete multimodal configuration. [#50908](https://github.com/vllm-project/vllm/pull/50908) changes compiler hashing for disabled modalities. [#60143](https://github.com/vllm-project/vllm/pull/60143) adds GPU budget identity.

The compiler hash omits some encoder memory-profile settings. The plan key now uses the existing `normalize_value` function for the full multimodal configuration. Unsupported values skip plan load and save, then use normal profiling.

Some settings affect only CPU work, so changing them can cause an extra profile. Existing multimodal plans need one new profile. Text-only keys remain unchanged within this patch.

This complements [#60143](https://github.com/vllm-project/vllm/pull/60143), which adds the GPU budget factor. Both changes were tested together with 30 passing worker cases. They modify the same test helper; its cache and multimodal inputs must be combined when both fixes merge.
