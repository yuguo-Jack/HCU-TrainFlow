# [Feature][Frontend] Add prefix cache hit rate to usage details

[Upstream PR](https://github.com/vllm-project/vllm/pull/44475) · state: closed · merged: False

## Original PR description

Expose cached_rate in prompt_tokens_details when prefix caching and prompt token details are enabled; centralize usage construction.
Fixes [#44377](https://github.com/vllm-project/vllm/issues/44377).
## Purpose
Add cached_rate to OpenAI-compatible usage.prompt_tokens_details when both server options are on:

* --enable-prefix-caching (APC)
* prompt token details enabled (enable_prompt_tokens_details)
cached_rate is cached_tokens / prompt_tokens (4 decimal places, 0 when prompt_tokens == 0).

Refactor chat and completion serving to build usage via shared helpers on OpenAIServing:

* build_prompt_tokens_details() in engine/protocol.py
* make_usage_info() in engine/serving.py
Streaming final usage chunks now use exclude_none=False so cached_tokens and cached_rate appear even when zero.

## Behavior: before vs after
**Before**
- `prompt_tokens_details` only when `--enable-prompt-tokens-details` and `cached_tokens > 0`.
- Fields: `cached_tokens` only (optional/nullable).
- No `cached_rate`; no requirement for prefix caching to be enabled.
- Streaming final usage may omit zero cache fields (`exclude_none=True`).

**After**
- `prompt_tokens_details` when **both** `--enable-prompt-tokens-details` and `--enable-prefix-caching`.
- Fields: `cached_tokens` (default 0) and `cached_rate` (4-decimal ratio vs `prompt_tokens`).
- Details emitted even on 0% cache hit; streaming uses `exclude_none=False`.
- Shared `build_prompt_tokens_details()` / `make_usage_info()` across chat & completion APIs.

### Before

`prompt_tokens_details` was included in the response **only when**
`--enable-prompt-tokens-details` was enabled **and** `num_cached_tokens > 0`.

**No cache hit** (typical response):

```json
{
  "usage": {
    "prompt_tokens": 1000,
    "completion_tokens": 50,
    "total_tokens": 1050
  }
}
```

**With a cache hit** — details were present, and **only** `cached_tokens` was
included:

```json
{
  "usage": {
    "prompt_tokens": 1000,
    "completion_tokens": 50,
    "total_tokens": 1050,
    "prompt_tokens_details": {
      "cached_tokens": 800
    }
  }
}
```

- No `cached_rate`
- On **zero** cache hits, `prompt_tokens_details` was usually **omitted** (old
  logic: set details only when `if num_cached_tokens:`)

### After

**Both** of the following must be enabled:

| Condition | Source |
|-----------|--------|
| `--enable-prompt-tokens-details` | CLI / `enable_prompt_tokens_details` |
| `--enable-prefix-caching` (APC) | `vllm_config.cache_config.enable_prefix_caching` |

When both are on, `prompt_tokens_details` is **always** included (including **0%**
cache hit):

```json
{
  "usage": {
    "prompt_tokens": 1000,
    "completion_tokens": 50,
    "total_tokens": 1050,
    "prompt_tokens_details": {
      "cached_tokens": 800,
      "cached_rate": 0.8
    }
  }
}
```

**Zero cache hit example:**

```json
"prompt_tokens_details": {
  "cached_tokens": 0,
  "cached_rate": 0.0
}
```

**`cached_rate` computation:** `round(cached_tokens / prompt_tokens, 4)`; `0.0`
when `prompt_tokens == 0`.
