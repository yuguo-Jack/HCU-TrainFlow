# [CI][Test] Use caplog_vllm in the legacy FP8 online quantization test

[Upstream PR](https://github.com/vllm-project/vllm/pull/62870) · state: open · merged: False

## Original PR description

## Overview

`test_legacy_fp8_online_quantization_uses_per_tensor_shorthand` asserts on `caplog.text`, which only sees records propagated to the root logger. vLLM's `"vllm"` logger has `propagate=False`, applied on the first engine init in the process — so whether this test passes depends on whether an unrelated test ran first. Switch to `caplog_vllm`, the fixture that exists for this and is already used by 27 other test files.

## Claims

- The test no longer depends on execution order within the pytest process.
- **The deprecation warning is emitted either way** — only its capture is affected. It appears in the captured stdout of the failing run.
- Reproduces and is fixed identically on **H200 and GB300**; not architecture-specific.
- Uses the existing fixture rather than a new workaround. This file is one of several still on plain `caplog`; this change does not sweep the rest.
- Test-only change, 3 lines.

## Validation

Same five steps on both devices, container `vLLM 0.31.0`. The prerequisite is `test_compressed_tensors_kv_cache_fp8_per_tensor`, which builds a real `LLM` through `vllm_runner`:

| step | command | H200 | GB300 |
|---|---|---|---|
| target alone | `pytest <target>` | `3 passed` | `3 passed` |
| **after an LLM is built** | `pytest <prereq> <target>` | **`3 failed, 1 passed`** | **`3 failed, 1 passed`** |
| same order, patched | `pytest <prereq> <target>` | `4 passed` | `4 passed` |
| target alone, patched | `pytest <target>` | `3 passed` | `3 passed` |

Process state at startup, before anything builds an engine:

```
logging.getLogger("vllm").propagate                    = True
DEFAULT_LOGGING_CONFIG["loggers"]["vllm"]["propagate"] = False
```

From the captured stdout of the failing run, showing the product behaves correctly:

```
WARNING --quantization fp8 is deprecated for online quantization;
        use --quantization fp8_per_tensor instead.
```

## Details

**Root cause.**

1. `caplog` captures only what reaches the root logger.
2. `DEFAULT_LOGGING_CONFIG` sets `propagate=False` on the `"vllm"` logger, and `configure_logging_if_needed` applies it on the first engine init in the process — not at import time.
3. This test never builds an `LLM`; it writes a minimal config and calls `get_quant_config`. Before any engine exists, propagation is still on and the test passes; afterwards `caplog.text` is empty and it fails.

**Fix.** `caplog_vllm` exists for this. Its dependency `temporary_enable_log_propagate` re-enables propagation for the duration of the test, which is what this test needs: the flag is already off when it starts, and nothing inside the test turns it off again.

#61535 later strengthened that fixture so it also survives a reconfiguration *during* the test, by monkeypatching `DEFAULT_LOGGING_CONFIG` alongside the live logger:

```python
@pytest.fixture()
def temporary_enable_log_propagate(monkeypatch):
    import logging

    from vllm.logger import DEFAULT_LOGGING_CONFIG

    # The first LLM init in a process reapplies DEFAULT_LOGGING_CONFIG, which
    # would otherwise turn propagation back off mid-test.
    monkeypatch.setitem(DEFAULT_LOGGING_CONFIG["loggers"]["vllm"], "propagate", True)
    monkeypatch.setattr(logging.getLogger("vllm"), "propagate", True)
```

That hardening is not strictly required here — this test builds no engine of its own — but it is why the fixture is robust today. `caplog_vllm` yields `caplog`, so `.text` is unchanged.

**Why CI did not catch this.** The job sets `automatic_shard: true`, so `tests/quantization/` is split across processes and whether an engine was built before this test depends on shard composition. Upstream hit this exact class in another lane: #61477 sharded a step, `test_mm_cache_stats` became first in its process, and #61535 fixed the fixture.

Not a duplicate: searched for `caplog_vllm` together with `test_online`, and for log-propagation changes; nothing related. `test_online_quant_load_format_dummy` in the same file also declares `caplog` but never uses it, so it is left alone.
