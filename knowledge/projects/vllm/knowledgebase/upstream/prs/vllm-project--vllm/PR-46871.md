- afierka-intel · comment · 2026-10-09T12:17:43Z · [source](https://github.com/vllm-project/vllm/pull/46871#issuecomment-6080712075)

Added autotuning for `BatchedTritonExperts`:

- `benchmarks/kernels/benchmark_batched_moe.py`: tuning/benchmark script (config key = per-expert capacity, `max_num_batched_tokens x EP`).
- The kernel now also forwards `num_warps`, `num_stages` and `grf_mode` from a tuned config (XPU only; they were ignored before).
- Tuned configs for Intel Arc Pro B60/B70: granite-3.0-3b-a800m, Qwen3-30B-A3B, OLMoE-1B-7B, DeepSeek-V2-Lite at EP 2/4/8.

Results, tuned vs default config:

| | median gain |
|---|---:|
| kernel, full batch (B60 / B70) | +27 % / +35 % |
| kernel, decode-sized batch | ~+2 % |
| e2e, prefill-bound (OLMoE EP2 / EP4, Qwen3 EP4, B70) | +33 % / +20 % / +18 % req/s |
| e2e, ShareGPT saturated (same models) | TTFT -27 % / -26 % / -17 %, throughput within noise |
| e2e, under-loaded ShareGPT, decode-only | no change |

So the configs help when the MoE layer is on the critical path (large prefill chunks, saturated server), not for decode-dominated serving. Not measured: accuracy, DeepSeek-V2-Lite and EP8 end to end.
