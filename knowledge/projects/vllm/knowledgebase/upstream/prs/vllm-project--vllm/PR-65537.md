# [MiniMax-M3] Support sequence parallelism with pipeline parallelism

[Upstream PR](https://github.com/vllm-project/vllm/pull/65537) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

MiniMax-M3 enables model-level sequence parallelism (SP) for TP + EP + MegaMoE (#64659), keeping the residual stream sharded by token across TP ranks, but only when pipeline parallelism (PP) is off. This PR keeps SP on under PP, handling stage boundaries the same way as DeepSeek-V4.1: non-last stages all-gather the token shards before returning `IntermediateTensors`, and the next stage re-shards them on entry. No other open PR enables this combination.

## Claims

- MiniMax-M3 with MegaMoE, TP > 1 and PP > 1 now runs the same SP path as PP = 1.
- PP2 and PP4 reproduce PP1's prompt logprobs exactly; GSM8K matches PP1 with and without DSpark.
- At PP2 × TP2, throughput is within 2.5% of the current SP-off path (decode −0.4%, mixed −2.4%, prefill +1.4%).
- PP = 1 and non-MegaMoE backends are unchanged.

`MiniMaxAI/MiniMax-M3.1-Flash` on B300, TP2 + EP + MegaMoE.

## Details

PP transport sends 1/TP of each `IntermediateTensors` entry from every TP rank and all-gathers it on the receiver, so stage outputs must cover all tokens and be identical across TP ranks. The change:

- Drop `pipeline_parallel_size == 1` from `_use_sequence_parallel`.
- On entry to a non-first stage, shard the received `residual` together with `hidden_states`.
- At a non-last stage exit, pack `hidden_states`, `residual` and the aux hidden states into one tensor and all-gather it once. On the last rank, aux states received from earlier stages are already full and are appended after the local gather, as before.
- Build the dense MLP's `down_proj` with `reduce_results=False` under SP. With PP > 1 the decoder layer asks each FFN to reduce its own output, but under SP the dense MLP already reduce-scatters the `down_proj` output, so an extra all-reduce would sum it twice.

AI assistance (Claude) was used to investigate, implement and validate this change. The submitter reviewed every changed line and the validation results.
