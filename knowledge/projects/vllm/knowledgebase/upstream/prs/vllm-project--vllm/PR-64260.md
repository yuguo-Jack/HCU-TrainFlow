## Overview

With Model Runner V2, send each sliding-window group's leading null blocks of a new request as a count (`NewRequestData.block_id_null_heads`) instead of listing them in `block_ids`. Follow-up to #61724. Tested at `b29265f637` (main at `ca8bd4c055`, 2026-11-04).

## Claims

Per admitted request, on DeepSeek-V4.1's block layout:

| | 128K tokens | 855K tokens |
|---|---:|---:|
| Block ids sent to workers | 33,793 -> 1,057 | 225,721 -> 6,873 |
| **CPU saved** | **~1 ms** | **~7 ms** |
| Admission CPU, with #62702 | 1.40 -> 0.42 ms (-70%) | 8.95 -> 1.93 ms (-78%) |
| Admission CPU, on main | 6.26 -> 5.30 ms (-15%) | 43.65 -> 36.37 ms (-17%) |

Admission CPU here is collecting the block ids, pickling and unpickling `NewRequestData`, and staging the block tables. It excludes KV block allocation and freeing, which this PR does not change.

- **Step time:** ~0.35 ms per step per rank at 0.36 admissions per step, ~1.5% of a 23 ms step (estimate). DEP32 decode measured 12.88 -> 12.48 ms/step and 3924 -> 3967 out tok/s/GPU on an older stack; not repeated on this head.
- **No behavior change:** block ids and GPU block tables match the full-list path.

## Validation

### CPU repro

GB200 Grace, `numactl` node 0. Each value is the middle of 3 interleaved rounds, each round the best of 10 calls. Both paths run in one process on real `KVCacheBlocks`, `NewRequestData` and `BlockTables`, and the script asserts that both produce the same GPU block table. The host was shared but lightly loaded. The stage row covers the block tables only.

The layout comes from a DeepSeek-V4.1 engine's KV cache config: 8 sliding-window groups (block size 32), one MLA group (block size 128) and one circular buffer. At 128K tokens, each sliding-window group has 4,096 entries (4,092 null), the MLA group 1,024 and the buffer 1.

```python
#!/usr/bin/env python
"""CPU cost of one admission's block ids: full lists vs null-head counts (#64260).

Run from a checkout of #64260. Both paths run in one process on real KVCacheBlocks,
NewRequestData and BlockTables; the block layout is DeepSeek-V4.1's (8 sliding-window
groups of block size 32, one MLA group of block size 128, one circular buffer):
    PYTHONPATH=. numactl --cpunodebind=0 --membind=0 \
        python repro_null_head_block_ids.py 2>/dev/null

No GPU needed: the staging row is skipped without one.
"""

import json
import pickle
import time

import numpy as np
import torch

from vllm import SamplingParams
from vllm.v1.core.kv_cache_manager import KVCacheBlocks
from vllm.v1.core.kv_cache_utils import KVCacheBlock
from vllm.v1.core.sched.output import NewRequestData
from vllm.v1.request import Request
from vllm.v1.worker.gpu.block_table import BlockTables

SWA_GROUPS, SWA_BLOCK, SWA_REAL, MLA_BLOCK = 8, 32, 4, 128
OOB_BYTES = 1 << 20  # MessageQueue sends buffers of at least this size out of band
null = KVCacheBlock(0, is_null=True)


def best_us(fn, n=10):
    times = []
    for _ in range(n):
        start = time.perf_counter()
        fn()
        times.append(time.perf_counter() - start)
    return min(times) * 1e6


def dumps(obj):
    oob = []

    def callback(buf):
        raw = buf.raw()
        if len(raw) < OOB_BYTES:
            return True
        oob.append(raw)
        return False

    return pickle.dumps(obj, protocol=5, buffer_callback=callback), oob


def loads(blob, oob):
    return pickle.loads(blob, buffers=[bytearray(b) for b in oob])


def make_blocks(num_tokens):
    next_id = iter(range(1, 1 << 30))

    def real(count):
        return [KVCacheBlock(next(next_id)) for _ in range(count)]

    swa_len = num_tokens // SWA_BLOCK
    swa = [[null] * (swa_len - SWA_REAL) + real(SWA_REAL) for _ in range(SWA_GROUPS)]
    return KVCacheBlocks((*swa, real(num_tokens // MLA_BLOCK), real(1)))


def measure(num_tokens, tables):
    ids = np.random.default_rng(0).integers(1000, 100000, num_tokens).tolist()
    request = Request("r", ids, SamplingParams(max_tokens=16), None)
    prefill = request.prefill_token_ids
    blocks = make_blocks(num_tokens)
    full = blocks.get_block_ids()
    trimmed, heads = blocks.get_block_ids_after_null_head()
    results = {}
    expected = None
    for arm, get_ids, block_ids, null_heads in (
        ("full", blocks.get_block_ids, full, None),
        ("counts", blocks.get_block_ids_after_null_head, trimmed, heads),
    ):
        new_req = NewRequestData.from_request(
            request, block_ids, prefill, block_id_null_heads=null_heads
        )
        assert new_req.full_block_ids() == full
        blob, oob = dumps(new_req)
        row = {
            "collect": best_us(get_ids),
            "pickle": best_us(lambda: dumps(new_req)),
            "unpickle": best_us(lambda: loads(blob, oob)),
            "ids_sent": sum(len(group) for group in block_ids),
        }
        if tables is not None:

            def stage():
                tables.append_block_ids(0, block_ids, True, null_heads=null_heads)
                tables.apply_staged_writes()
                torch.cuda.synchronize()

            row["stage"] = best_us(stage)
            pairs = zip(tables.block_tables, full)
            written = [t.gpu[0, : len(g)].cpu() for t, g in pairs]
            if expected is None:
                expected = written
            assert all(torch.equal(a, b) for a, b in zip(written, expected))
        results[arm] = row
    return results


tables = None
if torch.cuda.is_available():
    max_tokens = 1 << 20
    sizes = [SWA_BLOCK] * SWA_GROUPS + [MLA_BLOCK, 8]
    tables = BlockTables(
        block_sizes=sizes,
        max_num_reqs=4,
        max_num_batched_tokens=2048,
        max_num_blocks_per_group=[max_tokens // size for size in sizes],
        device=torch.device("cuda"),
    )

for num_tokens in (131072, 875520):
    for arm, row in measure(num_tokens, tables).items():
        out = {k: round(v, 1) for k, v in row.items()}
        print(json.dumps({"n": num_tokens, "arm": arm, **out}), flush=True)
```

## Details

- Only MRV2 gets counts: `GPUModelRunner` (V2) writes the heads as zeros in `BlockTables.append_block_ids`. MRV1 is unchanged.
- KV connectors read `scheduled_new_reqs[*].block_ids` directly in many places, so this is opt-in via a new `KVConnectorBase_V1.supports_null_head_block_ids` (default False). `yield_req_data` restores the heads with `NewRequestData.full_block_ids()`, so NIXL (reads new-request block ids only there) and DecodeBench (never reads them) opt in. `MultiConnector` opts in only if all its children do; every other connector (e.g. `HiSparseConnector`, LMCache, Mooncake) keeps the full lists.
- `null_head_len` returns the first non-null index when the null blocks are not one contiguous head, so any later null blocks stay in `block_ids`; the expansion is exact either way.

**Limitations:**

- Models without sliding-window groups have no null head and gain nothing. The extra path was not measured for them.
- Collect, pickle and unpickle run before the worker reaches the step's DP all-reduce. At DEP16 some rank admits on nearly every step, so up to ~0.63 ms of a step's lateness could go at 128K. This is an upper bound from the per-stage numbers: async overlap absorbs part of it.
- The per-step figures are arithmetic from per-admission numbers. The E2E numbers are from an older stack, and their gain is close to the node-to-node drift.

**Not a duplicate:** no open PR changes how null blocks are sent to the workers (searched `null head block ids`, `trim_null_head`, `null_head_len`, `NewRequestData block_ids null`). #62702 removes the per-token cost of prompt ids, and this removes the per-entry cost of null block ids; they are independent.
