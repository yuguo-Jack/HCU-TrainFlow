# [CI] Prebuild mamba-ssm and causal-conv1d in the CUDA test image for (H200) Language Models (Hybrid), (L4) Granite and Extended Generation

[Upstream PR](https://github.com/vllm-project/vllm/pull/58795) · state: open · merged: False

## Original PR description

## What

Build the pinned `mamba-ssm` v2.3.0 and `causal-conv1d` v1.6.0 CUDA extensions once in the CUDA test image, instead of from source in every job that needs them. `Language Models (Hybrid)`, `Granite Language Model Compatibility` and `Language Models (Extended Generation)` then only verify the prebuilt packages.

Takes over @khluu's #52333, rebased onto current `main`: his three commits are kept as-is, with authorship, and one commit on top adapts them.

## Old

Each NVIDIA job ran two source builds before pytest:

```text
rm -rf /tmp/mamba-src && git clone --depth 1 --branch v2.3.0 .../mamba /tmp/mamba-src && sed -i 's/-std=c++17/-std=c++20/g' ... && MAMBA_FORCE_BUILD=TRUE uv pip install ... /tmp/mamba-src
CAUSAL_CONV1D_FORCE_BUILD=TRUE uv pip install ... 'git+https://github.com/Dao-AILab/causal-conv1d@v1.6.0'
```

## New

- `docker/Dockerfile`, `test-deps` stage: the same two builds, run once per image and cached with the stable dependency layer. arm64 images skip them because no arm64 job runs these tests. Release images (`vllm-openai`) are unaffected.
- The three NVIDIA jobs run `python3 ../.buildkite/scripts/check-hybrid-test-deps.py` instead. The script (from #52333) asserts both versions, imports both packages, and records where each came from.
- AMD mirrors and `test-amd.yaml` are unchanged. They use the ROCm mamba fork on a different image.

| Commit | Author | Change |
|---|---|---|
| Prebuild hybrid model test dependencies | khluu | Dockerfile step |
| Verify prebuilt hybrid test dependencies | khluu | verifier script |
| Report hybrid dependency source commits | khluu | PEP 610 source identities |
| Prebuild … with the C++20 mamba checkout; drop per-job builds | this PR | see Notes |

## Notes

- **Adapted to `main`.** Since #49600 the jobs build mamba from a checkout patched to `-std=c++20`, because torch ≥ 2.14 nightly needs it. #52333's plain `git+…@v2.3.0` would no longer build, so the Dockerfile uses the same patched checkout. The verifier therefore checks that mamba came from that checkout, since a local install has no VCS identity. causal-conv1d keeps its VCS check.
- **One check, at runtime.** #52333 also asserted the versions during the image build. Both installs are pinned to exact tags, and the jobs' verifier checks versions, imports and sources, so the build-time assert is dropped. The Hybrid job's `GIT_CONFIG` HTTP/1.1 env stays as on `main`; its mirror inherits it for the ROCm source installs.
- **A failed prebuild fails only these jobs.** Every CI job uses this image, so the `RUN` step warns and continues instead of failing the image build. `check-hybrid-test-deps.py` then fails the three jobs with a pointer to the image build log, so the break shows where it is. The two fetches are tried twice, because a successful `RUN` is cached, and causal-conv1d is built with `--no-cache`, because uv keys a git build by commit, not by the torch it was built against.
- **No test or topology change.** Same commands, same replicas, same keys.
- AI assistance was used (Claude Code). Checks run: `pre-commit run` on the changed files, which includes the Dockerfile dependency-graph and `docker/versions.json` hooks, plus `yaml.safe_load` on both pipeline files.
