# [Bugfix] Fall back to repr in get_model_inspection for non-torch models

[Upstream PR](https://github.com/vllm-project/vllm/pull/61368) · state: closed · merged: False

## Original PR description

## Overview

Fixes #61366. `WorkerBase.get_model_inspection()` now returns `repr(model)` when the worker's model is not a torch `nn.Module`, so `repr(LLM(...))` works on out-of-tree workers that serve non-torch models.

## Claims

- `repr(llm)` no longer raises `AttributeError: ... has no attribute 'named_children'` for workers whose `get_model()` returns a non-torch model, such as MLX models on vllm-metal.
- Torch models still go through `format_model_inspection` with no change in output.

## Validation

Unit test, `tests/v1/worker/test_worker_base.py` (runs in the existing `pytest -v -s v1/worker` step of `.buildkite/test_areas/misc.yaml`):

```text
$ pytest -q tests/v1/worker/test_worker_base.py
without the fix: 1 failed (AttributeError: '_NonTorchModel' object has no attribute 'named_children')
with the fix:    1 passed
```

End to end, on vLLM main (ff305934f) with the vllm-metal plugin at the commit before it added its own workaround (vllm-project/vllm-metal@4499a43), on an M1 MacBook Air:

```python
from vllm import LLM

llm = LLM("trl-internal-testing/tiny-MistralForCausalLM-0.1")
print(repr(llm))
```

| | Result |
|---|---|
| main | `AttributeError: 'Model' object has no attribute 'named_children'` |
| this PR | Prints the MLX module tree: `Model(`, `(model): LlamaModel(`, `(layers.0): TransformerBlock(`, ... |

`pre-commit run` passes on the changed files (ruff, mypy, typos, SPDX headers, CI test tethering).

Environment note: vLLM has no precompiled macOS arm64 wheel for this commit, so the tests ran from the source tree in a `uv` venv with `requirements/cpu.txt` plus pytest. The change is pure Python.

## Details

Root cause: `LLM.__repr__` calls `collective_rpc("get_model_inspection")`. The `WorkerBase` default passes `self.get_model()` to `format_model_inspection`, which walks torch's `named_children()`. vLLM's own workers always return an `nn.Module`, so they are not affected. Out-of-tree workers can return other model types. vllm-metal returns MLX modules and hit this in vllm-project/vllm-metal#1082. It now overrides `get_model_inspection()` in its worker (vllm-project/vllm-metal#1087). This fallback fixes the same problem for any out-of-tree worker without an override.

The fallback lives in `WorkerBase` rather than in `format_model_inspection`, because that function is also used by `log_model_inspection` in the model loader, which only handles torch models. The worker is where a non-torch model can appear.

Not a duplicate: searches for `get_model_inspection`, `format_model_inspection` and `LLM __repr__` found no open or closed PR or issue for this.

Model Runner V1/V2: the change is in `WorkerBase`, which both runners share. It adds no work on the model execution path.
