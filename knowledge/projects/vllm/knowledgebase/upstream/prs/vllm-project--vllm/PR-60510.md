# [Bugfix] Preserve operator characters in sweep plot filter values

[Upstream PR](https://github.com/vllm-project/vllm/pull/60510) · state: open · merged: False

## Original PR description



## Overview

Sweep plots can now filter string values containing comparison operators. For example, `label!=build==one` selects every other label instead of trying to read a column named `label!=build`.

## Claims

- Parse the first comparison operator and preserve the complete target string, including repeated or leading `==`.
- Keep the existing numeric, infinity, and multiple-filter behavior.

## Validation

`python -m pytest tests/benchmarks/test_plot_filters.py --confcutdir=tests/benchmarks -q`: the three added regression cases failed on the unchanged parser, with 27 existing tests passing; the final change passes all 30. Tests invoke the real `PlotFilters` parser and apply it to pandas data. The scoped command omits the global GPU fixtures.

Scoped native Linux pre-commit hooks pass, including Ruff, mypy, SPDX, forbidden imports, and Buildkite test tethering. The existing `Benchmarks CLI` lane already runs `tests/benchmarks/`.

The submitting human reviewed every changed line and initiated the same test command through the review window; all 30 tests passed. Model evaluation is unnecessary for this CPU plot-filter parser; no model, serving engine, or GPU execution was tested.

## Details

The previous parser searched operator types in a fixed order and split every occurrence. An `==` inside the target could win over the earlier `!=`, or repeated `==` could raise an unpacking error. Split once at the first complete comparison token, preserving longer tokens before `<` and `>`.

Duplicate checks on October 7 searched open PRs for `PlotFilterBase` and plot/filter symptoms and inspected matching file patches. #55698 changes figure grouping and #55664 changes worker-result collection; neither changes filter parsing. This is independent of our sweep-name and JSON-list PRs #60328/#60329.
