# Add SVE Paged Attention FP32/FP16 and BF16 kernels

[Upstream PR](https://github.com/vllm-project/vllm/pull/62022) · state: open · merged: False

## Original PR description

This PR enables and optimizes the Paged Attention kernel on ARM CPUs for the FP16/FP32 and BF16 paths. It optimizes the SVE CPU attention GEMM kernel by improving register utilization, FP16 widening, FP32 FMLA efficiency and instruction scheduling, and adds an SVE256 BFMMLA kernel for BF16.

> [!IMPORTANT]
> **Depends on #50573.** This PR is built on top of the changes in #50573. Build with those changes applied to test it, and merge this PR only after #50573 is merged.

**Major changes**:

- Add/enable the SVE attention path for PA (Paged Attention) on ARM CPUs.
- Improve utilization of the SVE256 datapath through better register allocation and kernel scheduling, rather than relying on a raw width advantage over NEON.
- Remove intermediate register-allocation abstractions and move the SVE implementation into a self-contained ISA-specific file for performance gain.
- Apply dtype-specific optimizations for FP16 and FP32 while preserving the best-performing instruction patterns.
- BF16 PA kernel (SVE256 BFMMLA):
  - Follows the upstream NEON BFMMLA structure: Q packed once in `copy_q_heads_tile`, K/V caches in the `[..][32]` group layout.
  - Each SVE256 `bfmmla` computes two 2x2 tiles (one `ld1rq` A load feeds both 128-bit segments), with tile width chosen by row count (up to 32 columns).
  - Independent of `ProbabilityTokenStore`: P is packed inside the PV GEMM.
- Builds that are not SVE256 fall back to the NEON GEMM and NEON BFMMLA kernels.

**Performance** (Graviton3):

| Dtype    |     NEON |          SVE | SVE vs NEON gain |
| -------- | -------: | -----------: | ---------------: |
| **FP32** | 76.30 ms | **71.95 ms** |        **+5.7%** |
| **FP16** | 76.27 ms | **74.19 ms** |        **+2.7%** |
| **BF16** | 29.65 ms | **25.59 ms** |       **+13.7%** |

**Testing**:

- Added tests for the SVE PA path covering FP32, FP16 and BF16.
- Benchmarked with `benchmarks/kernels/cpu/benchmark_cpu_attn.py`

SVE is approximately 5.7% faster for FP32, 2.7% for FP16 and 13.7% for BF16 than NEON on the tested Graviton3 workload.

BF16 workload: decode, batch 64, 32 query / 8 KV heads, head size 128, KV length 2048, block size 32, single core
