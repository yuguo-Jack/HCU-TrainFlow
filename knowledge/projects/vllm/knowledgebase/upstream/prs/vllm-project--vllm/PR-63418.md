# [ROCm][Perf][DSv4] Enable custom allreduce on gfx1250

[Upstream PR](https://github.com/vllm-project/vllm/pull/63418) · state: open · merged: False

## Original PR description

## Purpose

`RocmPlatform.use_custom_allreduce()` returns true only for gfx94x and gfx95x. On gfx1250, vLLM therefore sets `disable_custom_all_reduce=True`, and every tensor-parallel all-reduce goes through RCCL. This PR adds gfx1250 to the list, so gfx1250 uses AITER's custom allreduce the same way MI300/MI350 do.

```diff
-        # We only enable custom allreduce for MI300 series
-        return any(gfx in _GCN_ARCH for gfx in ["gfx94", "gfx95"])
+        # We only enable custom allreduce for MI300 series and gfx1250
+        return any(gfx in _GCN_ARCH for gfx in ["gfx94", "gfx95", "gfx1250"])
```

No other change is needed. `VLLM_ROCM_USE_AITER_CUSTOM_AR` already defaults to on, the IPC pool (`AiterCustomAllreduce.MAX_SIZE`) is unchanged, and no AITER environment variable is required. Other architectures are unaffected.

## Test Plan

All on gfx1250. The serving and accuracy runs used ROCm's gfx1250 development branch with the identical commit applied (same patch-id). "Before" is the same build without it.

1. AITER's multi-GPU custom allreduce test at TP4 (`op_tests/multigpu_tests/test_custom_allreduce.py -t 4`): the regression suite, plus a size sweep under CUDA graphs.
2. `vllm bench serve` on DeepSeek-V4-Pro (TP4) and DeepSeek-V4-Flash (TP2): random dataset, 8k/1k and 1k/1k tokens at concurrency 16 and 64, temperature 0, `--ignore-eos`. Each config runs twice; the tables show the second run.
3. gsm8k on DeepSeek-V4-Pro: 5-shot, temperature 0, full test set, batch sizes 16 / 64 / 128.

## Test Result

**AITER custom allreduce, TP4, bf16:**

- The tail regressions pass, eager and under CUDA graphs.
- The sweep from 1K to 32M elements (64 MiB) matches the reference within bf16 rounding (max error about 2e-4).
- Latency is 7.5 µs for small messages and 345 µs at 64 MiB.
