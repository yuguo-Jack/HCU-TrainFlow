# [Spec Decode] Skip metadata build for dflash/dspark when all model backends support it

[Upstream PR](https://github.com/vllm-project/vllm/pull/60692) · state: closed · merged: True

## Original PR description

# Context
Continuing the effort from https://github.com/vllm-project/vllm/pull/58463 to remove unnecessary attention metadata rebuilds before FULL cudagraph replays for draft model-based speculators. I found an opportunity to use the same `supports_draft_decode_metadata_update` flag to gate updating the metadata within the captured decode step for DFlash/DSpark, reducing GPU kernel launch overhead.

# This PR
Adds support for skipping the full attention metadata rebuild before replaying the uniform decode cudagraph. Previously, only the `TargetDependentARSpeculator` was leveraging the `update_draft_decode_metadata` operations for its attention backends to update the attention metadata in a cudagraph-safe way. In this PR, I move that logic for deciding draft model eligibility (`supports_update_decode_metadata`) for this optimization to the base class `DraftModelSpeculator`, and then i have both `TargetDependentARSpeculator` and `DFlashSpeculator` check this eligibility. If True, capture the `_update_draft_decode_metadata` op in the graph before the draft model forward. Otherwise, rebuild the attention metadata eagerly via `_build_uniform_attn_metadata` before replaying the graph.

This optimization has been enabled for DeepSeek V4.1 + DSpark, as verified below.

## Benchmarks / Evals
**Setup (both subsections).** DeepSeek-V4.1-Flash, DSpark with `num_speculative_tokens=5`, 4x GB200 (TP4), `--max-model-len 102400 --max-num-seqs 128 --kv-cache-dtype fp8 --no-enable-prefix-caching`, `--attention-config '{"backend":"FLASHMLA_MEGA_ATTN_DSV41","indexer_kv_dtype":"mxfp4","indexer_sparse_logits":true}'`, adaptive verification off, `VLLM_USE_V2_MODEL_RUNNER=1`. Speed-Bench is 2K/2K (`throughput_16k`, `low_entropy`), with prompts scaled 8x concurrency (min 16), seed 0, and a fresh server per arm. In both subsections the PR server logged no "cannot update draft decode metadata" warning, so the in-graph metadata update was active.
