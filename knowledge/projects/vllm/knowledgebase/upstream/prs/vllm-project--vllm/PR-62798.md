# [Doc] Kimi-K3: DCP selector and TOKENSPEED_MLA draft backend on GB200/GB300

[Upstream PR](https://github.com/vllm-project/vllm/pull/62798) · state: closed · merged: True

## Original PR description

## Overview

Follow-up to #62761 for the Kimi-K3 interactive recipe on GB200 and GB300. It changes only `recipes/models/moonshotai/Kimi-K3.yaml`.

**Draft: depends on vllm-project/recipes#1159.** That PR adds the `decode_context_parallel` schema field and the builder row; this YAML fails the renderer's schema check until it merges and the renderer pin updates. I will mark this ready then.

## Claims

- **Draft backend:** The GB200 and GB300 `spec_decoding` toggle now emits `"attention_backend":"TOKENSPEED_MLA"` inside `--speculative-config`. The other speculative settings are unchanged, and the top-level `--attention-backend TOKENSPEED_MLA` still configures only the target model. B200, B300, AMD and Ascend are unchanged; TOKENSPEED_MLA on the draft was only run on GB200/GB300 in InferenceX [#3748](https://github.com/SemiAnalysisAI/InferenceX/pull/3748), [#4047](https://github.com/SemiAnalysisAI/InferenceX/pull/4047) and [#4322](https://github.com/SemiAnalysisAI/InferenceX/pull/4322).
- **DCP selector:** Opts into the new **Decode context parallel** row with sizes 8 and 16 on GB200/GB300, `a2a` comm backend and `match_tp: true`. A size is offered only when it equals the TP of every role, the layouts InferenceX qualified: GB200 TP8 x PP2 aggregated is DCP8 (#4322), TP16 per role disaggregated is DCP16 (#3748, #4322), GB300 TP8 pools are DCP8 (#4047). These are reference configurations, not universal defaults.
- **Side effect:** A TP1 DEP decode pool on GB200/GB300 used to render `--decode-context-parallel-size 16`, which vLLM rejects; it now drops the flag. A mixed-TP disaggregated layout shows no row.
- The guide's DCP bullet describes the row. Per-concurrency settings and CUDA graph sizes stay in the static GB200 sections.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <checkout>/recipes` passes against the renderer from vllm-project/recipes#1159.
- Rendered in headless Chrome: GB200 aggregated TP8/PP2 shows DCP8, GB200 disaggregated TP16 shows DCP16 on both roles, Off removes both DCP flags, GB300 disaggregated shows DCP8, B200 shows no row. The spec-decoding JSON on GB200/GB300 carries the draft backend and is unchanged on B200.
- Not done: a full variant x hardware render diff, and a live hardware-switch click-through.
