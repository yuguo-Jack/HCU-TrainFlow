# [Bugfix][Pooling] Reject multimodal inputs in chunked embeddings

[Upstream PR](https://github.com/vllm-project/vllm/pull/62859) · state: closed · merged: True

## Original PR description



## Overview

Reject multimodal embedding requests when enable_chunked_processing is enabled, instead of silently dropping their multimodal data. Return HTTP 400 with guidance to disable chunked processing.

## Claims

- Reject multimodal inputs, including short inputs, before chunk expansion or inference submission.
- Preserve text-only chunked processing and multimodal requests with chunked processing disabled.

## Validation

uv run --no-sync .venv/bin/python -m pytest \
  tests/entrypoints/pooling/embed/test_io_processor.py \
  tests/entrypoints/pooling/embed/test_protocol.py -q

72 tests passed. Added coverage for short and long multimodal inputs in mixed batches, plus the disabled-setting case. Applicable pre-commit checks passed.

Real HTTP validation used google/siglip-base-patch16-224 on an H800, BF16, eager mode, max_model_len=64, and max_num_seqs=1:

- With chunking enabled, image requests through /v2/embed and mixed text/image batches through /v1/embeddings returned HTTP 400. Subsequent text requests succeeded.
- With chunking disabled, image and mixed-batch requests succeeded; red and blue images produced different embeddings.
- A 217-token text input was split into four chunks. Its aggregated embedding matched the independently computed weighted, normalized reference within a maximum absolute difference of 3.31e-8.

## Details

maybe_pre_process_chunked() rebuilds inputs using tokens_input(), which discards multimodal payloads, hashes, and placeholders, even when the input fits in a single chunk.

This change validates the entire batch before rewriting inputs, preventing silent multimodal data loss when chunked processing is enabled.
