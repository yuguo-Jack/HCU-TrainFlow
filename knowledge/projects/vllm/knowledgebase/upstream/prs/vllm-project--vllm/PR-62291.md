# [Bugfix][Multimodal] Treat a torchcodec that cannot load its native library as unavailable

[Upstream PR](https://github.com/vllm-project/vllm/pull/62291) · state: closed · merged: False

## Original PR description



## Overview

A torchcodec wheel built for another CUDA version raises `OSError` at import, and vLLM's torchcodec import guards catch only `ImportError` and `RuntimeError`. Every `vllm serve` then stops at import, also for text-only models, because `vllm.v1.core.sched.output` imports `vllm.multimodal`. This PR treats that `OSError` as "torchcodec is not available", as vLLM already does for a missing FFmpeg.

## Claims

- `vllm serve` no longer stops at import when torchcodec is installed but its native library cannot load (for example a torchcodec built for CUDA 13 in a CUDA 12.9 environment).
- Audio and video decoding then fall back as for a missing torchcodec: `AudioDecoder` is `None`, `VideoDecoder` is a placeholder, and `check_torchcodec_available()` raises the same kind of `RuntimeError` as for a missing FFmpeg.
- No change when torchcodec loads, or when it is absent.

## Validation

**Real image** (vLLM nightly CUDA 12.9 image with torchcodec 0.17.0 built for CUDA 13, CPU node, no GPU). The check imports `vllm.v1.core.sched.output`, then calls `check_torchcodec_available()`. "With this PR" binds the image's own three files with the same edit applied:

| Code | Result |
|---|---|
| image as shipped | `OSError: Could not load this library: .../torchcodec/libtorchcodec_image.so` at import (cause: `libnvrtc.so.13: cannot open shared object file`) |
| with this PR | `import ok`; `check_torchcodec_available()` raises `RuntimeError: torchcodec cannot load its native library: Could not load this library: ...` |

The traceback without the fix: `vllm/v1/core/sched/output.py` → `vllm/multimodal/__init__.py` → `vllm/multimodal/hasher.py` → `vllm/multimodal/media/__init__.py` → `vllm/multimodal/media/audio.py:41` (`from torchcodec.decoders import AudioDecoder`) → `torchcodec/_core/ops.py` → `load_image_library()` → `OSError`.

**Unit tests** `tests/multimodal/test_torchcodec_import_guard.py` (CPU only; any `torchcodec` import raises `OSError`): both tests fail on `main` with the `OSError` and pass with this PR. They do not need torchcodec to be installed.

## Details

**Root cause.** `torchcodec/_core/ops.py` loads its native libraries at import and wraps a failed `dlopen` in `OSError` (`load_image_library`). The guards in `vllm/multimodal/media/audio.py` and `vllm/multimodal/video_decoders/torchcodec.py` were written for the two known failure modes: torchcodec absent (`ImportError`) and system FFmpeg missing (`RuntimeError`).

**Fix.** Both module-level guards also catch `OSError`. `check_torchcodec_available()` converts the `OSError` into a short `RuntimeError`, so its callers handle it as they handle a missing FFmpeg today: the EPD encoder video-backend default in `vllm/config/vllm.py` keeps CPU decoding, and `decode_torchcodec` reports the error for that request. `vllm/transformers_utils/processors/muse_glimmer.py` already catches every `Exception` and needs no change.
