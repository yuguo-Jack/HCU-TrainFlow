# [CI][ROCm] Add a ROCM_AITER_FA backend test suite (tests only, known defects as strict xfails)

[Upstream PR](https://github.com/vllm-project/vllm/pull/63675) · state: open · merged: False

## Original PR description


_Requested by **Tun Jian**_



## Overview

Adds the ROCM_AITER_FA backend test suite on its own, with no backend changes. Every defect the suite finds is registered in `known_defects.py` and marked `xfail(strict=True)`, so this PR is green on today's code. The fixes come as separate PRs stacked on this one; each fix deletes its registry entry, and strict mode then requires those tests to pass.

Part of the attention backend test standard RFC (https://github.com/vllm-project/vllm/issues/63640). The standard + skill, with this suite as its reference implementation, is #63685; the fixes stacked on this PR are listed below.

## Claims

- **Unit suite** (`tests/v1/attention/backends/rocm_aiter_fa/`):
  - capability contract, checked both ways;
  - metadata builder;
  - every `forward` dispatch path, with a kernel spy and a float32 reference;
  - every declared feature × phase × KV dtype × head size (64/128/256);
  - KV-cache writes per layout and dtype;
  - model-shape correctness;
  - CUDA graph replay;
  - workspace use;
  - rows with no query tokens after the real rows (B8): FULL CUDA graph padding (seq_len 0) and async KV connector loads (seq_len > 0, #51486), through every chunking path, with full and sliding-window attention.
- **Engine suite** (`tests/v1/e2e/attention/test_rocm_aiter_fa_runtime.py`): dummy-weight Qwen3, Muse Spark, Qwen3.8 and GPT-OSS at their smallest repeating layer block, compared with TRITON_ATTN. It covers every CUDA graph mode, model runner v1/v2, async scheduling, fp8 KV and n-gram spec decode.
- **Shapes** (`tests/v1/attention/model_shapes.py`): read from flagship HF configs, plus the deployed TP/DP/EP/PP/PCP/DCP layouts.
- **CI:** sharded Buildkite steps on MI355 (backend, engine runtime, DCP rejection, nightly full matrix).
- **Removed:** the old ROCM_AITER_FA tests this suite replaces.

## Validation

On MI350X with `vllm/vllm-openai-rocm:nightly` (AITER 0.1.26), against this branch's unmodified backend:

- **Unit, full suite incl. nightly matrix** (5 shards): 3791 passed, 78 xfailed. The xfails are the 77 registered tests plus one pre-existing kernel-test xfail. No unexpected passes.
- **Engine** (6 shards): 33 passed, 1 skipped (DCP needs 2 GPUs per shard), 16 xfailed (registered).
- **B8 update (2026-10-26)**, on MI355X with `vllm/vllm-openai-rocm:nightly` at 00b6c4c, pre-merge unit suite (3 shards): 640 passed, 85 xfailed, no failures. The new zero-query cases found two defects, registered as `zero-query-rows`: decode kernels ran zero-query rows past the real tokens (a GPU abort with unpadded buffers), and the extend chunk planner gave them context (22 chunks instead of 2).
- **Per fix:** each fix PR deletes its entry, and its tests then pass in a full unit run on that branch. The numbers are in each PR.

The registry was built by running the suite on the unfixed backend (77 unit and 16 engine failures), then re-running the failing set once per fix. Every failure is fixed by exactly one fix PR, and the fix PRs merge together without conflicts.
