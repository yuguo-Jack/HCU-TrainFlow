# [Doc] Kimi-K3: InferenceX AgentX lanes as tuned presets; DCP only in presets

[Upstream PR](https://github.com/vllm-project/vllm/pull/63552) · state: closed · merged: True

## Original PR description



## Overview

Moves Kimi-K3's InferenceX AgentX lanes and its GB300 low-latency configuration into tuned **presets** (vllm-project/recipes [SCHEMA.md](https://github.com/vllm-project/recipes/blob/main/SCHEMA.md) `presets`). The builder and the JSON API now render each lane's qualified points, builder choices and image; the guide previously told readers to adjust the command by hand. It also removes the DCP selector and DCP toggle: DCP lives only in the presets that qualified it. Follows #63520.

## Claims

**Six presets.**

| Preset | GPU · strategy | Default | Points |
|---|---|---|---|
| `gb200_agentx_agg` | GB200 · TP+PP | yes | C1–C56 (draft tokens, `--max-num-seqs`, CUDA graph sizes), Python frontend |
| `gb200_agentx_pd` | GB200 · PD 1P1D | yes | C16/C32/C48; Dynamo, Rust frontend |
| `gb300_agentx_pd` | GB300 · PD xPyD | yes | Dynamo, Rust frontend (worker counts stay in the runbook) |
| `gb300_low_latency` | GB300 · multi-node TP | opt-in, **new** | C1 TP16/DCP16 on four trays, C2–C4 TP8/DCP8 on two |
| `mi355x_agentx` | MI355X · TP | yes | every-concurrency settings, unchanged |
| `mi355x_agentx_cells` | MI355X · TP | opt-in, **new** | the ten #4393 cells: DCP8, DSpark draft, resident/offload |

**Removed:** the `decode_context_parallel` selector (GB200/GB300) and the `decode_context_parallelism` opt-in toggle. Kimi-K3 was their only user.
- DCP isn't an independent choice here: only DCP equal to the lane's TP was qualified.
- Picking Off on a preset silently dropped a qualified setting.
- DCP pairs with an attention backend and env that a size selector can't carry.
- The toggle's generic NVIDIA TP8/DCP8 form was never qualified by a lane.

The Notes entry now lists the qualified DCP layouts and how DCP pairs. cc @hshrivastava-droid, who added the selector.

**Guide:** the "Low latency serving" section becomes the `gb300_low_latency` preset's runbook. The lane runbooks drop their "select … in the builder" instructions and per-concurrency tables, which are now points and `select`.

**Default renderings that change (intentionally):** three files, now the lane as it ran. Every other rendering is identical.

| File | Change |
|---|---|
| `hw/gb200/strategies/multi_node_tp_pp.json` | adds the lane's `--compilation-config` (C32 graph sizes); Python frontend; lane image instead of `:latest` |
| `hw/gb200/strategies/pd_cluster.json` | Dynamo: `dynamo.vllm` workers plus the Dynamo frontend; tool-call API flags dropped; lane image |
| `hw/gb300/strategies/pd_cluster.json` | same as GB200 PD |

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` passes against recipes main.

  - Six preset files are added (`/moonshotai/Kimi-K3/presets/*.json`).
- Programmatic check of all 22 points against the lane sources (guide tables, the #4393 cell script and the low-latency script):
  - GB200 aggregated, 7 points: K, S, graph lists, TP8×PP2×DCP8 on four trays.
  - 1P1D, 3 points: per-role seqs, memory, graph caps; `dynamo.vllm`; Rust.
  - MI355X cells, 10 points:
    - seqs, batched tokens, compilation config (incl. `custom_ops`), draft and K;
    - the DCP8 pairing and env;
    - `--additional-config` / `--quantization-config`, offload bytes / `PYTHONHASHSEED`, image.
  - Low latency, 2 points: node count, TP=DCP, K, graph sizes, `latency_specialized`, env, one command per node.
- Builder checks:
  - GB300 low latency switches between four and two trays, and a reload keeps the preset (with vllm-project/recipes#1177).
  - The MI355X cells turn KV offload on and off per cell.
  - GB200 / GB300 PD land on Dynamo.

## Details

- **Opt-in vs default.** The three lanes that were already on for every GB200/GB300 user stay default, with the same per-point values; their remaining changes are the builder choices they ran with. The low-latency and MI355X cell configurations were guide-only, so they are opt-in.
- **MI355X split.** The per-cell settings sit on a separate preset rather than as points of the default one. The every-concurrency default keeps the rolling image and no DCP, and the cells share their DCP8, draft and image at preset level instead of repeating them per point.
- **Not in this PR:**
  - GB300 xPyD worker counts and the MI355X MoRIIO PD lane: several workers per PD role and the MoRIIO connector aren't builder features.
  - The Mooncake connector parameters of the GB200 lanes.
  - All three stay in the runbooks.

Add `variants: [default]` to this preset.
