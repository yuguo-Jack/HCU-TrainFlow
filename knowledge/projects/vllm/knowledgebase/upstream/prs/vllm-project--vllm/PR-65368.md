# [Bugfix][Parser] chat_parsing: keep large integers exact for number parameters

[Upstream PR](https://github.com/vllm-project/vllm/pull/65368) · state: open · merged: False

## Original PR description



## Overview

`_coerce` in `vllm/parser/chat_parsing/response_parser.py` converts `number`-typed tool arguments with `float()` first, so integers above 2**53 are silently rounded. This PR tries `int()` first, as the `integer` branch already does. #55743 fixed the same problem in `vllm/tool_parsers/utils.py::coerce_to_schema_type`; this is the same fix for the chat-parsing path.

## Claims

- `_coerce("9223372036854775807", ("number",))` returns `9223372036854775807` instead of `9223372036854775808`.
- Decimal, exponent, NaN and infinity inputs (`"2.5"`, `"1e3"`, `"5.0"`, `"nan"`, `"inf"`) behave as before, because `int()` rejects them and the existing float path runs.

Environment: CPU only (ARM Neoverse-N1, 4 cores), Python 3.12, torch 2.14.0. No GPU or model run; the change is limited to argument type coercion.

## Details

The `number` branch did `number = float(raw)` and then `int(number)` for whole numbers, so the integer was rounded to the nearest double before conversion. Trying `int(raw)` first keeps the exact value for integer literals and leaves every other input on the old path.

Duplicate check: #61410 also edits `_coerce`, but only the `integer` branch (whole-number floats such as `"...807.0"`); it does not touch the `number` branch. No other open PR touches `vllm/parser/chat_parsing/`.
