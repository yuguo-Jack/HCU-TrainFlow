# [Frontend] Add the Beam reasoning and tool parsers

[Upstream PR](https://github.com/vllm-project/vllm/pull/62052) · state: closed · merged: True

## Original PR description

## Overview

Second slice of #61978 (Reflection Beam), after #62042: the `beam` reasoning and tool parsers, in Python and in the Rust frontend. They take effect only with `--reasoning-parser beam` or `--tool-call-parser beam`. This does not enable the model end to end.

## Claims

- **New parsers:** `--reasoning-parser beam` and `--tool-call-parser beam` parse output with the checkpoint's `response_template` metadata, as `hf` does. They also derive a structural-tag grammar from the template, which constrains:
  - strict tools;
  - required and named tool choice;
  - structured outputs;
  - by default, every other request, so output follows the template's format. `VLLM_BEAM_ALWAYS_CONSTRAIN_OUTPUT=0` turns this off.
- **Docs:** `docs/features/tool_calling.md` documents the parser.

## Details

- **Shared code touched:**
  - `ParserManager` now picks any response-template parser, not just `hf`. A parser opts in through `unified_parser_cls()`. The `hf` behavior is unchanged except for error messages, which now name the selected flags.
  - `OnlineRenderer` passes the prompt token IDs to the parser before `adjust_request`. Beam needs this to see whether the prompt already opened reasoning or an answer. Only the response-template parsers (`hf`, `beam`) override `set_prompt_token_ids`; for all other parsers the base class method does nothing.
  - `ResponsesRequest` gets two private attributes, so a parser-built grammar can replace `text.format` without changing the request's public fields.
- **Response-template parser fixes**, which also apply to `hf`:
  - When output stops inside a closer whose last part is the next message's start anchor, the parser completes the closer instead of reporting it as malformed.
  - Reasoning tokens are counted incrementally from the template.
- **Size:** about 2.3k non-test lines. Most of it is the grammar builder (`vllm/parser/response_template_grammar.py`) and the Rust `beam` parser.
- **Not a duplicate:** no open PR adds a Beam parser.
