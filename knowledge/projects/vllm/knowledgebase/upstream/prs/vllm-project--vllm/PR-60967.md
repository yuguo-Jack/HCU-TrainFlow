# [KV Cache] Size packed Mamba groups by the unpadded state

[Upstream PR](https://github.com/vllm-project/vllm/pull/60967) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Block-outermost layouts pack Mamba states into blocks at their own page size (`_get_packed_kv_cache_groups`), so padding the Mamba page to the attention page only lowers the number of states per block. This drops that padding when the attention backends support only block-outermost layouts, and lets a packed Mamba group widen the block by up to one state when that saves a group. #55449, stacked on this PR, corrects the block size for packed ds_mla caches; the two change disjoint configurations.

## Claims

- `_align_hybrid_block_size` skips the Mamba padding when every layout from `get_supported_kv_cache_layouts` is block-outermost.
- `_get_packed_kv_cache_groups` lets a Mamba group take one more state than the block fits, which widens the block only when that saves a group. Like main's split, this depends only on the specs, so NIXL P/D peers that differ in `max_model_len`, prefix caching or TP still get the same plan; a bytes-per-request check would not.
- GLM-5.3-Flash with MTP off and an fp8 or bf16 MLA cache: 4 → 3 KDA groups, up to +26% max concurrency. SM90 bf16 at 128k without prefix caching loses up to 1.5%, and 20 of 192 configurations at 512k/1M lose up to 2.6%.
- GLM-5.3-Flash on GB10 with an `fp8_ds_mla` cache and a DFlash2 drafter, whose sliding-window layers the CPU grid does not model: 9 → 6 KV cache groups, +24% max concurrency at 404,992 tokens.

## Validation

GLM-5.3-Flash (real `config.json`) through the allocation path on CPU, 960 configurations: max concurrency is higher in 140, lower in 4 (SM90 bf16 TP1/2 at 128k without prefix caching, down to −1.5%), unchanged in the rest, including every `fp8_ds_mla` one.

## Details

- With the padding, GLM-5.3-Flash's block holds 11 KDA states, so its 34 KDA layers need 4 groups; without it, or with the extra state, 12 fit. Dropping the padding alone improves 96 configurations, both changes together 140.
- Only GLM-5.3-Flash (KPOOL tail cache) and Qwen4Exp with QSA side caches skip the padding today; Qwen4Exp is not measured.
- Related: RFC #58638 question 2 asks how to size blocks for block-outermost layouts; this keeps the alignment's block and changes only how Mamba states fill it. #56156 skips the alignment for opt-in layer-wise KV caches. #60996 restructures the same Mamba split (textual conflict) and keeps the Mamba padding.
