# [KV Cache] Size packed Mamba groups by the unpadded state

[Upstream PR](https://github.com/vllm-project/vllm/pull/60967) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Block-outermost layouts pack Mamba states into blocks at their own page size (`_get_packed_kv_cache_groups`), so padding the Mamba page to the attention page only lowers the number of states per block. This drops that padding when the attention backends support only block-outermost layouts, and lets a packed Mamba group widen the block by up to one state when that saves a group. #55449, stacked on this PR, corrects the block size for packed ds_mla caches, which this PR leaves unchanged; the two change disjoint configurations.

## Claims

- `_align_hybrid_block_size` skips the Mamba padding when every layout from `get_supported_kv_cache_layouts` is block-outermost. If the layout still resolves to a layer-outermost one, `unify_kv_cache_spec_page_size` pads the Mamba pages to the largest page.
- `_get_packed_kv_cache_groups` also builds the groups with one extra state per Mamba group and keeps them only if that saves a group and lowers the worst-case bytes per request.
- GLM-5.3-Flash with MTP off and an fp8 or bf16 MLA cache: 4 → 3 KDA groups, up to +26% max concurrency. No measured configuration loses capacity.

## Validation

GLM-5.3-Flash (real `config.json`) through the allocation path on CPU, 960 configurations: max concurrency is higher in 140, unchanged in the rest, including every `fp8_ds_mla` one.

## Details

- With the padding, GLM-5.3-Flash's block holds 11 KDA states, so its 34 KDA layers need 4 groups; without it, or with the widening, 12 fit. Dropping the padding alone improves 96 configurations, the widening alone 108, both 140.
- Only GLM-5.3-Flash (KPOOL tail cache) and Qwen4Exp with QSA side caches skip the padding today; Qwen4Exp is not measured.
- Without this PR, #55449's corrected width makes GLM-5.3-Flash with MTP off need a fourth KDA group.
- Related: RFC #58638 question 2 asks how to size blocks for block-outermost layouts; this keeps the alignment's block and changes only how Mamba states fill it. #56156 skips the alignment for opt-in layer-wise KV caches. #58380 also restructures `_get_packed_kv_cache_groups` (textual conflict); the bytes-per-request check uses the layout passed in, so it also works in #58380's planner.
