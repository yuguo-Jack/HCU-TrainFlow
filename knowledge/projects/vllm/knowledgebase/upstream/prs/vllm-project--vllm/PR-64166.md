# [Core][DP] Use exact in-flight counts with a single API client

[Upstream PR](https://github.com/vllm-project/vllm/pull/64166) · state: closed · merged: False

## Original PR description

## Overview

Prevent stale coordinator snapshots from overriding exact in-flight request counts in the internal DP load balancer when there is a single API client. Related reproduction: mobilint/vllm-mblt#54.

## Claims

- With a single client, use its exact in-flight count as the base score, including completions newer than the latest coordinator snapshot.
- Preserve snapshot backpressure for multiple clients and the existing KV-pressure waiting penalty.
- In the NPU reproduction below, eliminate the long TTFT tail and improve average throughput by approximately 7.5%. This is not a claim of equivalent gains across all backends or workloads.

## Validation

An isolated harness loading the modified checkout's actual routing/completion methods and test bodies passed 9 tests. The original implementation failed both stale-completion scenarios. Coverage also includes multi-client backpressure and KV-pressure penalties.

## Details

The existing base score is `max(client_count * inflight, waiting + running)`. Suppose three engines each run 16 requests and one request finishes. That engine's in-flight count immediately drops to 15, but the coordinator snapshot may still report 16. The engine with the newly available slot then ties with full engines. If tie-breaking selects a full engine, the new request must wait for another request to finish.

A single client tracks all requests, so it can use its exact in-flight count as the base score. With multiple clients, requests routed by peers are not directly visible, so the existing global-snapshot calculation remains unchanged. The waiting penalty protecting slow-draining, KV-bound engines is also retained. This change therefore does not eliminate every possible effect of stale waiting/KV-pressure snapshots.

An earlier commit attempted to decrement snapshot counts upon completion; the follow-up commit removes that approach. The final diff contains no snapshot-decrement helper. Routing APIs, request affinity, and completion bookkeeping are unchanged.
