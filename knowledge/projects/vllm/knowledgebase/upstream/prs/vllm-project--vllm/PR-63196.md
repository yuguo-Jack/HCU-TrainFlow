# [Perf][GDN] Index mixed-batch spec rows once per step; slice when they lead

[Upstream PR](https://github.com/vllm-project/vllm/pull/63196) · state: open · merged: False

## Original PR description



## Overview

Stacked on #63193; only the top commit is new here. The GDN metadata builder indexes request rows with host boolean masks in `build()` and again in every `update_block_table` regather. This carries the spec/non-spec row indices in the metadata and uses slices when spec rows come first.

## Claims

- Spec/non-spec row indices are computed once per step and reused by `build()` and the per-group `update_block_table` regathers.
- When spec rows lead (Model Runner V2 order), `arange` and slices replace `repeat_interleave`, `argsort` and cumsums.
- Metadata values are identical; no new option.

## Validation

Not run yet. Planned:

```bash
pytest -v tests/v1/attention/test_gdn_metadata_builder.py tests/models/kimi_k3/test_kda_metadata.py tests/kernels/mamba/test_gdn_forward_core_split.py
```

## Details

Keeps main's cross-group metadata reuse (`update_block_table`); other row orders fall back to the general path.
