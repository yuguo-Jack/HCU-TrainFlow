# [Model] Register and implement Glm4MoeLitePlusPlus model

[Upstream PR](https://github.com/vllm-project/vllm/pull/57274) · state: open · merged: False

## Original PR description

## Purpose

Adds support for **ZEDA-GLM-4.7-Flash-Dynamic** (`Glm4MoeLitePlusPlusForCausalLM`), a dynamic MoE variant of GLM-4.7-Flash that introduces **Zero-Compute Experts (ZCE)**: the router gate emits logits for all experts (n_routed_experts + sum(zce_nums) = 64 + 32 = 96), but zero-compute expert slots are not executed as FFNs — they are remapped to expert 0 with weight 0 at the fused-MoE kernel level, avoiding a per-expert Python loop and keeping the whole path graph-compilable.

The vLLM side only makes vLLM **recognize** the model and **recreate the 96-dim gate**; the actual "skip" of zero-compute experts is handled by the companion vllm-ascend patch.

**Why:**

- The model uses sigmoid + `e_score_correction_bias` + group topk routing, so the gate **must** output 96 logits for topk selection to "see" the zero-compute slots. Keeping the inherited 64-dim gate makes ZCE routing silently inactive.
- The model uses DeepSeek-style **MLA**, so it must be added to the `is_deepseek_mla()` whitelist, otherwise it falls back to plain MHA and errors with `rotary 102 != 64`.
- Config is registered in `_CONFIG_REGISTRY` so the checkpoint loads **without `trust_remote_code`** (no need for a forked transformers).
- The 96-dim `e_score_correction_bias` must be synced onto the **router** as well as the gate/experts, otherwise the Ascend `moe_gating_top_k` C++ kernel fails its dimension check (`bias_size[0] != expert_num`).

**Changes (6 files, +249 lines):**

New files:
- `vllm/model_executor/models/glm4_moe_lite_plus_plus.py` — thin override of `Glm4MoeLite`:
  - `Glm4MoeLitePlusPlusDecoderLayer`: after the parent builds the standard MoE layer, recreates `mlp.gate` as a `total_num_experts`-dim `nn.Linear`, creates a matching `e_score_correction_bias` Parameter, and sets `routed_experts.zero_expert_num` / `zero_expert_type` for the downstream fused-MoE kernel. Also syncs `e_score_correction_bias` onto `experts.router`. Dense layers (non-MoE) are left untouched via an `isinstance` guard.
  - `Glm4MoeLitePlusPlusModel`: re-implements `__init__` only to swap in the `++` decoder layer; decorated with `@support_torch_compile` so it is capturable by `torch.compile` + cudagraph (`FULL_DECODE_ONLY`), unlike the eager fallback.
  - `Glm4MoeLitePlusPlusForCausalLM`: wires up the `++` model and replicates MoE/MLA weight-loading setup (`packed_modules_mapping`, `fuse_qkv_a_proj`, `set_moe_parameters()`).
- `vllm/transformers_utils/configs/glm4_moe_lite_plus_plus.py` — `Glm4MoeLitePlusPlusConfig(PretrainedConfig)` exposing `zce_nums` / `zce_types` / `use_zce_mask` and `total_num_experts`/`total_zce` properties.

Modified files (registration plumbing):
- `vllm/model_executor/models/registry.py` — map `Glm4MoeLitePlusPlusForCausalLM` → `glm4_moe_lite_plus_plus` module.
- `vllm/transformers_utils/config.py` — `model_type` `glm4_moe_lite_plus_plus` → `Glm4MoeLitePlusPlusConfig` in `_CONFIG_REGISTRY`.
- `vllm/transformers_utils/configs/__init__.py` — lazy module path in `_CLASS_TO_MODULE` + `__all__`.
- `vllm/transformers_utils/model_arch_config_convertor.py` — add `glm4_moe_lite_plus_plus` to the `is_deepseek_mla()` whitelist (MLA attention path).

The override reuses the parent's weight loading / forward / MLA attention; no eager dispatch and no new trainable parameters (the bias is already part of the checkpoint's expert-parameter set).

## Branch notes

The vllm fork maintains two branches with **identical code changes** (6 files, +249 lines) but different bases:

| Branch | Base | Purpose |
|--------|------|---------|
| `zeda-glm47-flash` | `origin/main` (v0.29.0-dev) | **For PR submission** — the branch of this PR |
| `zeda-glm47-flash-run` | `v0.28.0` tag | **For running inference** — paired with vllm-ascend origin/main |

The run branch exists because vllm-ascend origin/main gates API usage via `vllm_version_is("0.28.0")` and relies on vllm 0.28.0 interfaces (e.g. `GPUInputBatch`, `vllm.model_executor.layers.attention.pcp`) that have been renamed or removed in vllm origin/main (v0.29.0-dev), making the two latest `main` branches incompatible at runtime.

The run branch was created by cherry-picking the PR commit onto the `v0.28.0` tag. The only difference is the `GlmMoeDsaForCausalLM` module path in `registry.py` — `v0.28.0` uses `"deepseek_v2"` while `origin/main` uses `"vllm.models.deepseek_v32"` — a context difference, not a code change.

Since vllm is installed in editable mode (`pip install -e /vllm-workspace/vllm`), switching branches takes effect immediately:

```bash
# Submit PR
git checkout zeda-glm47-flash

# Run inference (paired with vllm-ascend origin/main)
git checkout zeda-glm47-flash-run
```
