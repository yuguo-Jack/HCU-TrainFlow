# [Bugfix][Reasoning] Flush the Olmo3 streaming hold-back at end of stream

[Upstream PR](https://github.com/vllm-project/vllm/pull/60353) · state: open · merged: False

## Original PR description

## Overview

Fixes #60340. In streaming mode `Olmo3ReasoningBuffer.add_text` decides whether to hold a delta back using `string_overlap(delta_text, marker)`, and that helper reports *containment* as an overlap: any delta that merely occurs inside `<think>` / `</think>` (`think`, `in`, `k`, `>`, `/`, ...) is buffered as if it could start a marker. Two consequences:

- Mid stream the delta is needlessly delayed by one step.
- If generation ends on such a delta the buffered text is never emitted, because nothing flushes the buffer at end of stream, so streaming loses trailing content that the non-streaming path returns (repro in the issue, verified locally against current main).

`abstract_parser.py` is touched on purpose, and the repo guidance says to call that out: the missing end-of-stream flush is wrong for every legacy `ReasoningParser` with a string hold-back buffer, not just olmo3, so `finalize_generation` now gives any legacy parser that defines `finish_streaming` one chance to flush at `finished=True`. The hook is opt-in via `getattr`, engine-based parsers still flush through `_flush_engine_parsers`, and no existing parser's behavior changes except olmo3 opting in.

## Claims

- The buffer holds a delta only while its tail can still grow into a marker (a suffix of the buffer that is a proper prefix of `<think>` / `</think>`); a delta that merely occurs inside a marker streams through immediately. `string_overlap`, now unused, is removed.
- New `Olmo3ReasoningParser.finish_streaming()` drains the buffer at end of stream: held text goes out as content once the reasoning block closed, and as reasoning while it is still open, matching what earlier deltas already streamed.
- `finalize_generation` calls a legacy reasoning parser's `finish_streaming` when defined; engine-based parsers (`engine_based_streaming=True`) are untouched and flush via the existing path.

Non-streaming extraction, `is_reasoning_end`, and the token-id logic are unchanged, so model outputs/accuracy are not affected; no model eval was run for that reason.

## Follow-up tests in `c24c5e1033`

The review that verified this change named two gaps, and both are now covered on top of the head above. The numbers in the list above belong to `920b0c4778`; only the two test files were rerun for this follow-up.

- `test_char_level_streaming_holds_only_marker_characters` feeds the issue sequence one character at a time and asserts that no character of the reasoning or the content is ever held back, with a running check that what has streamed is always a prefix of the final output.
- `test_contained_delta_streams_in_the_call_that_fed_it` pins that a delta which occurs inside a marker but cannot grow into one comes back from the call that fed it rather than the next chunk.
- `test_parse_delta_contained_marker_substring_streams_mid_stream` pins the same property through `DelegatingParser.parse_delta`, so the coverage is not only against the reasoning parser directly.

All three fail on the parent. The char-level run stops at `('R', 'That is what I ')` against `('R', 'That is what I think')`, so the trailing `think` is dropped outright, and the contained delta returns `None` at both the parser and the facade level.

The other mypy version hooks did not run in this environment.
