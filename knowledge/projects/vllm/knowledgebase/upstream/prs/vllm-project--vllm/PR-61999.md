# [CI] Shard MTEB, DFlash Nightly, MoE Refactor DP and Entrypoints LLM automatically

[Upstream PR](https://github.com/vllm-project/vllm/pull/61999) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Turns on `automatic_shard` for four steps, and for the AMD mirrors of three of them. They were previously going to be split by hand (#58781, #58775, #58777, #58000), but automatic sharding replaces that approach. Only the flag changes; no commands or tests change.

## Claims

- Each step runs as parallel jobs planned from main's per-file timings, and each job runs only its share of the tests:

| Step | Command shape | Planned shards |
|---|---|---:|
| `language-models-test-mteb` (optional) | one `pytest` over a directory | 3 |
| `amd-language-models-test-mteb` (optional mirror) | same | 2 |
| `amd-spec-decode-dflash-nightly` (optional mirror) | same as its step | 1 for now (see Details) |
| `spec-decode-dflash-nightly` (optional) | `pytest` over a directory with `-k`; the large test file is split by test | 3 |
| `moe-refactor-integration-test-b200-dp-temporary` (optional) | `pytest` on one eval file with `--config-list-file`, split by test | 3 |
| `entrypoints-integration-llm` | `export` setup, then three `pytest` commands with `--ignore` | 3 |
| `amd-entrypoints-integration-llm` (mirror) | same as its step | 2 |

- Every test runs exactly once across the shards, with the same environment as the single job.
- If planning fails, the step falls back to running as one job, as it does today.

## Validation

- Planned each step on this branch with ci-infra main's `runtime_shard.plan_step`, using main's timings on the step's own queue.
- Rendered each step with the pipeline generator and ran every shard's commands against a mock test tree, as a PR build and with main's `pytest -p ci_otel` wrapper. Every test of every command ran in exactly one shard, with the same env.
- `/ci run` exercises `entrypoints-integration-llm` and its AMD mirror. The other three steps and their mirrors are optional, so a PR build doesn't run them; they need a build scoped to their keys.

## Details

- **Left out on purpose.** Some steps from the hand-split PRs aren't in this batch:
  - `pytorch-fullgraph-test` runs each file in its own pytest process; sharding would put them in one process and could change results.
  - `multi-modal-models-standard-4-other-whisper` runs one command from the repo root (`cd ..`), which the planner can't split.
  - `hybrid-ssm-nixlconnector-pd-accuracy-tests-4-gpus` runs a bash script, not pytest.
  - `lm-eval-humming-*-act` steps have no per-file timings on main.
  - `multi-modal-models-extended-generation-1` currently fails on main, so a sharded run can't be compared against a passing baseline.
- **AMD mirrors.** Every mirror that runs longer than 20 minutes as one job is enrolled: MTEB, DFlash Nightly and Entrypoints (LLM). DFlash's mirror moved to another AMD queue on main (#61955) after it was validated here (2 shards, both passed). That queue has no per-file timings for it yet, so it runs as one job, as it does today, well inside its 120-minute timeout. It starts sharding once nightly runs there record timings. MoE Refactor's mirror runs in a few minutes, so it stays one job.
- **Where to look.** The `automatic_shard: true` lines in `.buildkite/test_areas/{models_language,spec_decode,lm_eval,entrypoints}.yaml`.
