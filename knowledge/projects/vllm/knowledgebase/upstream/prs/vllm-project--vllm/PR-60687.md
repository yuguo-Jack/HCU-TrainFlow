# [Bugfix][Model] Fix Gemma4 encoder CG with `max_soft_tokens` set

[Upstream PR](https://github.com/vllm-project/vllm/pull/60687) · state: closed · merged: True

## Original PR description



## Overview



Fix Gemma4 engine crash / ~~silent accuracy drop~~(Fixed in #61365) when encoder CUDA graph is on.

## Claims



1. Fix engine crash when `max_soft_tokens` is not the default. In `prepare_encoder_cudagraph_capture_inputs` the launch-time option `mm_processor_kwargs.max_soft_tokens` is ignored, thus serving an image fails with a shape-mismatch `RuntimeError` in `pad_pixel_values` at graph replay.
2. ~~Fix wrong embeddings when the replay stride differs from the capture stride. Before the fix, capture stride depends on `max_soft_tokens` but replay stride is a fixed 70. Thus Frame 2 onwards in a video can read the wrong rows.~~ Fixed in #61365 

## Validation

```shell
pytest tests/models/multimodal/processing/test_gemma4.py -k max_soft_tokens -v
```

Or equivalently,

Launch a Gemma4 server with encoder CUDA graph on and non-default `max_soft_tokens`, and send a vision question.

```shell
# set max vision items per batch to 16 to avoid OOM
vllm serve google/gemma-4-E2B-it \
  --mm-processor-kwargs.max_soft_tokens 560 \
  --compilation-config.cudagraph_mm_encoder true \
  --compilation-config.encoder_cudagraph_max_vision_items_per_batch 16
```
