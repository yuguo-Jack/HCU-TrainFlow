# [Bugfix][Humming] Fix per-tensor FP8 MoE w13 scale

[Upstream PR](https://github.com/vllm-project/vllm/pull/61412) · state: closed · merged: False

## Original PR description



## Overview

Fixes the Humming load crash for per-tensor FP8 MoE checkpoints, which currently fails the `Qwen3-30B-A3B-Fp8-v1-humming` and `Qwen3-30B-A3B-Fp8-v1-humming-act-fp8` LM Eval configs on main (seen in the B200 and H100 Humming jobs on #60948). Regressed in #56997.

## Claims

- Per-tensor FP8 MoE with `--moe-backend humming` loads again instead of failing engine init with `assert scale.size(0) == (num_experts or 1)`.
- The fix covers every producer that requantizes w13 to one scale per expert (compressed-tensors, `fp8`, ModelOpt, online FP8). Block, channel and MXFP8 scales and non-gated MoE are unchanged.

## Validation

`nm-testing/Qwen3-30B-A3B-Fp8-v1` with `--moe-backend humming --linear-backend humming --enforce-eager` on SM80:

| | main | this PR |
|---|---|---|
| Engine init | `AssertionError` in `humming/schema/base.py` | loads |
| `Qwen3-30B-A3B-Fp8-v1-humming` GSM8K (1319 q, 5-shot, threshold 0.86) | crash | 0.8787, passed |

```bash
cd tests
pytest -s -v evals/gsm8k/test_gsm8k_correctness.py --config-list-file=<list containing Qwen3-30B-A3B-Fp8-v1-humming.yaml>
```

The `-act-fp8` config needs FP8 activations, which Humming rejects on SM80 by design. Locally it now gets past the weight conversion (w13 converts to a channel scale) and stops at that input-schema check, so its accuracy is left to the H100/B200 Humming jobs.

## Details

Since #56997, the Humming branch of `convert_to_fp8_moe_kernel_format` writes the processed tensors back to the layer before the Humming conversion. For per-tensor FP8, `process_fp8_weight_tensor_strategy_moe` has already requantized w13 to the max scale of each expert, so the layer now holds a `[E]` w13 scale. Humming's per-tensor schema expects one scale per gate/up shard: with two n-stacks it views the scale as `(-1, 2, 1)`, which turns `[E]` into `[E/2, 2, 1]` and trips the assertion.

Dropping the write-back would bring back the old pairing of requantized weights with the per-shard checkpoint scales. Instead this repeats the requantized scale for both shards, which matches the requantized weight exactly. `numel == num_experts` only holds for per-tensor scales, and non-gated w13 keeps a single n-stack. The existing Humming LM Eval configs already cover this path, so no new test.
