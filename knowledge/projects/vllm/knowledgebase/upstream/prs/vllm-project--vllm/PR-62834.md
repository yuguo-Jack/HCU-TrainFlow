# [Bugfix][EPD] Check encoder readiness for prefix replay

[Upstream PR](https://github.com/vllm-project/vllm/pull/62834) · state: closed · merged: True

## Original PR description

## Overview

Wait for encoder embeddings needed by prefix replay before admitting an EPD request.

## Claims

- Include the replayed prefix tail in EC readiness checks without changing KV-hit accounting or replay behavior when a KV load restores the window.
- Prevent missing encoder embeddings from crashing the consumer during DeepSeek-V4.1 prefix replay.

## Validation

Slurm E2E: DeepSeek-V4.1-Flash, 1E (TP1) + 1PD (TP2), Mooncake TCP, MRV2, raw-image forwarding, prefix/processor caches and CUDA Graphs enabled. After 128 disjoint random-image warmups, MUIRBench (512 questions, concurrency 64) completed with **512/512 HTTP 200**, **303/512 correct (59.18%)**, and no `Encoder cache miss`, using an 8 GiB consumer pool.

## Details

EC readiness was checked before SWA replay rewound the computed-token boundary. For example, a KV hit at 640 covers an image ending at 567, but replay starts at 512 and still needs that image. Skipping its load causes `Encoder cache miss`. Check EC readiness against the replay start while retaining the original KV-hit boundary for allocation and statistics.

Checked related open EPD/prefix-replay PRs; none addresses this missing-load path. AI assistance was used for implementation and validation.
