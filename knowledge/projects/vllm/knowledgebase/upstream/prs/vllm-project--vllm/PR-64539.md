# fix(tool-parsers): recognize nullable-string schemas in Muse, MiniCPM5 and Poolside V1

[Upstream PR](https://github.com/vllm-project/vllm/pull/64539) · state: closed · merged: False

## Original PR description

Fixes #64517

## Problem

The `muse`, `minicpm5` and `poolside_v1` tool parsers keep a parameter's raw text only when its schema is exactly `{"type": "string"}`. For any other string schema they decode the text as JSON (MiniCPM5 and Poolside V1 also fall back to `ast.literal_eval`). A `str | None` parameter (pydantic `Optional[str]`) then gets `"1.10"` as `1.1`, `"1984"` as `1984`, and a JSON file body as an object.

The root cause is a single check `schema.get("type") == "string"` that misses the nullable-string spellings JSON Schema produces for `Optional[str]`:

- `{"anyOf": [{"type": "string"}, {"type": "null"}]}`
- `{"oneOf": [{"type": "string"}, {"type": "null"}]}`
- `{"type": ["string", "null"]}`

## Fix

Add a shared `is_string_schema()` helper in `vllm/tool_parsers/utils.py` that resolves `anyOf`, `oneOf`, and array-type spellings recursively. Use it in all three parsers:

- `muse_tool_parser.py` `_collect_string_params`
- `poolside_v1_tool_parser.py` `_is_string_type`
- `minicpm5xml_tool_parser.py` `_coerce_argument_value`
