# [CI] Add nightly Python 3.14 smoke test

[Upstream PR](https://github.com/vllm-project/vllm/pull/60456) · state: closed · merged: True

## Original PR description



## Overview

All CUDA CI runs on Python 3.12, so nothing checks the other versions `pyproject.toml` declares support for. This adds an optional (nightly) Buildkite step that installs vLLM into a Python 3.14 venv and runs a short generation.

## Claims

- `tests/standalone_tests/python_only_compile.sh` accepts `PYTHON_ONLY_COMPILE_PYTHON=<version>`. When set, it creates a uv venv with that interpreter, does the precompiled editable install into it with `uv pip`, asserts the interpreter version, and generates a few tokens with `hmellor/tiny-random-LlamaForCausalLM`.
- With the variable unset, the script takes the same path as before.
- New step "Python 3.14 Smoke Nightly" in `.buildkite/test_areas/misc.yaml`, next to "Python-only Installation", on the same `h200_18gb` device and `optional: true`.

## Validation

Run by hand on a B300 with CPython 3.14.5, not in the CI image:

- `uv venv --python 3.14` then `VLLM_USE_PRECOMPILED=1 uv pip install -e . --torch-backend=auto`: resolves and installs (torch 2.13.0+cu130), all compiled extensions import.
- The generation snippet added to the script passes on that venv with `VLLM_GPU_SYNC_CHECK=error`, as the test image sets.
- The version assert fails when the expected version does not match the interpreter.
- `vllm serve Qwen/Qwen3-0.6B` on the same venv answered chat, batched completions, JSON-schema structured output, a hermes tool call, and streaming.
- `pre-commit` passes on both files (including shellcheck and the Buildkite step-key and test-tethering hooks).

Not validated: the script end to end inside the test image, and the new step through the pipeline generator. The step needs to be unblocked on this PR to get that signal.

## Details

- The script already handles resolving the merge-base commit and waiting for its wheel on wheels.vllm.ai, so the new mode reuses it rather than adding a second script.
- This works without building anything because vLLM's extensions are `abi3`, and DeepGEMM ships per-version binaries for 3.10 to 3.14.
- Limitation: compiled code comes from the merge-base wheel, not the PR. The step covers the Python source and dependency resolution on 3.14, not C++ changes that break only on 3.14.
- Limitation: only the base install is covered. For example, `tensorizer==2.10.1` (the `tensorizer` extra and the test requirements) fails to import on 3.14 with a `KeyError`, which the `except ImportError` guard in `vllm/model_executor/model_loader/tensorizer.py` does not catch; this step would not see that.
- The wheel retry loop can wait up to 25 minutes, so the 30 minute timeout may need raising if the nightly regularly hits it.
- Not a duplicate: searched open PRs for "python 3.14 CI smoke", "python_only_compile", and "3.14" in titles. The only hit is #51312, which is a torchao fix for the Rock image.
