# [Bugfix][CPU] Reuse selected memory node for KV cache sizing

[Upstream PR](https://github.com/vllm-project/vllm/pull/58924) · state: open · merged: False

## Original PR description

## Purpose

`CPUWorker` falls back to a visible memory node when the first CPU group's NUMA
identifier is not a real memory node, as can happen on s390x. However,
`determine_available_memory()` queried the CPU group identifier again, so
initialization and KV-cache sizing could use different nodes.

Persist the selected memory node and reuse it for memory binding, memory
accounting, KV-cache sizing, and related diagnostics.

No matching open PR or issue was found after searching the affected functions
and CPU memory-node behavior. No documentation or model evaluation is required.

AI assistance was used to investigate and implement this change. I reviewed
every changed line and validated the results below.

## Test Plan

- Add a CPU-worker regression where topology reports node `7` but the visible
  memory node is `0`, and verify initialization and KV-cache sizing both query
  node `0`.
- Run the CPU resource and NUMA unit tests.

## Test Result

Before the fix, the regression observed memory queries `[0, 7]` instead of
`[0, 0]`.

After the fix:

```text
CPU worker regression: 1 passed
CPU resource and NUMA tests: 48 passed
```
