# [Bugfix][Metrics] Account for speculative decode tokens

[Upstream PR](https://github.com/vllm-project/vllm/pull/58745) · state: open · merged: False

## Overview

Fixes #58719 by classifying MFU/MBU work from the non-speculative token count instead of the total number of scheduled rows.

## Claims

- Bills speculative decode verification rows as decode logits work.
- Handles `-1` padding in newly scheduled speculative requests.
- Preserves ordinary prefill, chunked prefill, and resumed prefill accounting.

Model evaluation is not applicable because this change does not affect model execution or outputs.

## Details

The existing code treats every cached request with more than one scheduled token as prefill. During speculative decoding, however, the scheduler includes verification rows in that total, so `num_tokens > 1` undercounts unembedding work by billing only one logits row.

Subtracting the number of scheduled speculative tokens recovers the scheduler phase semantics. The same calculation is used for requests newly sent to workers, where speculative slots may contain `-1` padding. A request that still schedules more than one non-speculative token remains prefill, preserving resumed and chunked-prefill behavior.

I reviewed and understand every changed line and the phase-classification behavior covered by the regression tests. I also rechecked open PRs for #58719 and related speculative decode metrics terms; no other open PR implements this fix.

Good point. I traced the scheduler path and confirmed that `_preempt_request()` clears `spec_token_ids`, while a waiting or resumed request can only receive speculative entries through `pad_spec_decode`, which produces exactly `1 + k` scheduled rows with `-1` placeholders.

The previous resumed-prefill fixture with real draft IDs therefore could not be emitted by the scheduler. I removed that combination and folded the real no-spec resumed-prefill shape into the existing newly sent prefill case. The production classification logic is unchanged. Thanks for catching this.
