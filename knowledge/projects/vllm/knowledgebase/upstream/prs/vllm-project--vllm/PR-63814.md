# [Bugfix][Frontend] Reject --fingerprint-mode custom without a value

[Upstream PR](https://github.com/vllm-project/vllm/pull/63814) · state: open · merged: False

## Original PR description

## Overview

Fail at startup when `--fingerprint-mode custom` is given without `--fingerprint-value`. Related open PRs #57399, #57390, #57436 cover mode `none`.

## Claims

- The server no longer starts silently with no `system_fingerprint` in responses when the custom value is missing or empty.

## Validation

`pytest tests/entrypoints/common/test_cli_args.py -k custom_fingerprint` (CPU, no GPU needed): the two new cases fail before (`DID NOT RAISE ValueError`) and pass after. `ruff check` and `ruff format` are clean.

## Details

`build_system_fingerprint` returns `None` for mode `custom` with no value, which behaves like mode `none`. The new check sits in `validate_parsed_serve_args` next to the other "requires" checks and needs a non-empty value.
