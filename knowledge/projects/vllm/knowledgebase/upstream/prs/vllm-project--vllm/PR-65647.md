# [Bugfix][Spec Decode] Add packed_modules_mapping to DeepSeek-V4 DSpark models

[Upstream PR](https://github.com/vllm-project/vllm/pull/65647) · state: open · merged: False

## Original PR description

### Summary

Fixes #65618.

`DSparkDeepseekV4ForCausalLM` across AMD, NVIDIA, and XPU platforms fuses `gate_up_proj` (from shards `w1`, `w3`) and `fused_wqa_wkv` (from shards `wq_a`, `wkv`) via `stacked_params_mapping`.

However, unlike the target model `DeepseekV4ForCausalLM`, `DSparkDeepseekV4ForCausalLM` omitted `packed_modules_mapping`. Consequently, when quantizers inspect whether layers are skipped via `is_layer_skipped(prefix, ignored_layers, fused_mapping=quant_config.packed_modules_mapping)`, the draft's fused layer prefixes could not be expanded to their constituent shard names.

When a checkpoint leaves these draft linear layers in unquantized BF16 via `quantization_config.ignored_layers`, the draft's fused layers still received `Fp8LinearMethod` with uninitialized weight scales (`weight_scale_inv`), leading to 0% draft token acceptance and invalid output.

### Changes
1. Added `packed_modules_mapping` to `DSparkDeepseekV4ForCausalLM` in:
   - `vllm/models/deepseek_v4/amd/dspark.py`
   - `vllm/models/deepseek_v4/nvidia/dspark.py`
   - `vllm/models/deepseek_v4/xpu/dspark.py`
   - `vllm/models/deepseek_v41/amd/dspark.py`
   - `vllm/models/deepseek_v41/nvidia/dspark.py`
2. Added unit tests in `tests/models/test_deepseek_dspark_packed_mapping.py` verifying that all DSpark draft model entry points define `packed_modules_mapping` and that `is_layer_skipped()` correctly resolves unfused shard names to skip fused draft layers.

### Testing
- `pytest --noconftest tests/models/test_deepseek_dspark_packed_mapping.py` (5 passed across v4_amd, v4_nvidia, v4_xpu, v41_amd, v41_nvidia).
- `ruff check` and `ruff format --check` clean.
