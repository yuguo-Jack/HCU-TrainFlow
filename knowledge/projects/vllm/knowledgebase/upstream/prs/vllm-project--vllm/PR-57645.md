# [Perf][Kernel] Fuse post-norm, residual add and pre-norm into one op

[Upstream PR](https://github.com/vllm-project/vllm/pull/57645) · state: open · merged: False

## Original PR description

## Motivation

Post-norm architectures (Gemma 2/3/4 among others) run `post_norm(h)` followed by `pre_norm(h, residual)` at every layer: an `rms_norm` then a `fused_add_rms_norm`, two launches and an extra round trip of the hidden state through memory. At decode batch sizes both are launch-bound.

## Change

- New IR op `rms_norm_add_rms_norm`, defined as `rms_norm` followed by `fused_add_rms_norm` with a shared epsilon (the native implementation is literally that composition).
- A one-launch Triton implementation (row kernel, native rounding points, fp32 weights supported so `GemmaRMSNorm`'s `(1 + w)` path is unchanged). CUDA prefers it; all other platforms keep the native form. Priority is configurable through `IrOpPriorityConfig` like the other norm ops.
- `rms_norm_add_rms_norm(post_norm, pre_norm, x, residual)` helper in `layernorm.py` that falls back to the two modules whenever the fused op does not apply (batch-invariant mode, variance-size override, non-CUDA-alike platforms).
- Gemma 2, Gemma 3, Gemma 4 and the Gemma 4 MTP layer use it for the post-attention boundary. Other post-norm models can adopt it the same way.

## Benchmark (historical; earlier candidate)

These measurements were recorded on an earlier candidate and were not rerun on the final rebased head (`6a07fe8700b472a940307794b404f565de00e0fb`). They are retained for historical context.

`benchmarks/kernels/benchmark_rms_norm_add_rms_norm.py`, B300, bf16, hidden 5376, 32 boundaries per CUDA graph, µs per boundary:

| tokens | rms_norm + fused_add_rms_norm, native (torch.compile) | same, vllm_c | rms_norm_add_rms_norm, triton |
|---|---|---|---|
| 1 | 4.48 | 7.61 | 2.81 |
| 16 | 4.49 | 7.96 | 2.82 |
| 128 | 6.25 | 9.97 | 3.70 |
| 2048 | 22.60 | 35.64 | 16.99 |

## Numerics

The final-head provider suite passed all 734 cases covering fp16/bf16/fp32, with and without weights and with fp32 weights, under the op's declared tolerance. The bf16 absolute tolerance is wider than for the single-norm ops because the residual add can cancel and amplify a one-ULP reduction-order difference of the first norm; the reason is documented next to the override.

## Historical end-to-end and GSM8K results (earlier candidate)

The results below were measured on an earlier candidate. They are historical context, not final-head accuracy or performance evidence; no end-to-end evaluation was run on the final rebased head.

`google/gemma-4-12b-it`, bf16, language model only, B300, same flags for both arms (control = `main` with this branch's model changes reverted, candidate = this branch), fresh server and caches per arm, A/B/A order. Wave client: 32 requests × 256 output tokens per point; stream client: 96 single-stream requests.

| metric | control A | candidate | control B | candidate vs mean control |
|---|---|---|---|---|
| single-stream tok/s (wave) | 157.8 | **160.2** | 157.8 | **+1.5%** |
| single-stream tok/s (stream client) | 157.9 | **159.8** | 157.6 | **+1.3%** |
| 8 concurrent, aggregate tok/s | 1123.5 | 1130.0 | 1122.6 | +0.6% |
| 16 concurrent, aggregate tok/s | 2391.5 | 2399.3 | 2398.4 | +0.2% |
| gsm8k, 1000 items, greedy, 1 worker | 893 | 893 | — | parity (12 flips, 6 each way; 960/1000 identical outputs) |

Note on the attention route for this run: both arms used `TRITON_ATTN`. With the FlashInfer build available on that machine the trtllm-gen path reports no decode kernel for this model's 512-wide global heads (`Missing TRTLLM-GEN kernel (decode): ... headDimQk=512 ... numTokensPerPage=128`) and the FlashInfer native path overflows its prefill workspace (`batch_prefill_tmp_s`); those are independent of this PR, but they mean the attention share of the step was larger than with a tuned route, so the fused-norm gain above is if anything understated.

The pre-commit (Ruff) and mypy results previously reported for touched files were recorded on an earlier candidate; mypy was not rerun on the final rebased head.
