# [Perf][MRV2] Trim the FULL graph output copy and the draft-token gather

[Upstream PR](https://github.com/vllm-project/vllm/pull/64701) · state: open · merged: False

## Original PR description



## Overview

Two small trims to the Model Runner V2 decode step with speculative decoding:

- A FULL graph whose model returns aux hidden states (EAGLE3, DFlash, DSpark, `extract_hidden_states`) copies its hidden and aux hidden states into the persistent buffers with one sliced `torch._foreach_copy_` instead of one copy kernel per tensor, when they are contiguous and share one dtype.
- Without structured outputs or a PP draft broadcast, the draft tokens are no longer gathered by `idx_mapping` for `set_draft_tokens`, which then reads only their width.

Both trim per-step work on the spec-decode output path; they matter most at low concurrency. Split out of #64364, as @zhou9402 suggested there; the PP branch follows their note about #64458.

## Claims

- Qwen3-8B on one GB300, concurrency 1: output throughput +0.27% with EAGLE3 (k=3) and +0.42% with DFlash (k=16); both well above the round-to-round spread (t = 4.0 and 15.6, 3 interleaved rounds).
- Concurrency 64: not resolved yet. One round per config read −1.2% (EAGLE3) and −0.9% (DFlash), while EAGLE3's median TPOT improved; 5 more interleaved rounds per config are queued and will replace this line.
- No arithmetic change: the copy moves the same bytes, and the draft-token rows are only read for their width on the path that skips the gather.

## Details

- **Why the slices.** `_foreach_copy_` hands each tensor chunk to one CTA that loops over it, so a few rows of one tensor would sit on a single CTA. Splitting each flat tensor into 16 chunks of at least 4096 elements spreads a small batch over enough CTAs and keeps large batches at the per-tensor copy's speed (the 4096-token rows above).
- **Fallback.** Without aux hidden states, if an output is non-contiguous (e.g. the split views of DeepSeek-V2's sequence-parallel path), or if the dtypes differ (Muse Spark's aux states are FP32 next to BF16 hidden states, and `_foreach_copy_` then copies one slice at a time), the per-tensor copies run as before. The destination buffers are `empty_like` the largest source, so they are contiguous whenever the sources are.
- **Draft tokens.** With structured outputs, the grammar needs the actual tokens in batch order. With PP, `broadcast_drafts` (since #64458) sends the gathered tensor from a side stream, and the next step can overwrite `req_states.draft_tokens` before it is sent, so it keeps its own batch-ordered copy. Otherwise `set_draft_tokens` stores only `draft_tokens.shape[1]` per request, and a view of the first `num_reqs` rows has the same width; no reference to the view outlives the step.
- **Where the copy runs.** `store_capture_output` runs at warm-up and inside graph capture only, so the sliced copy is one node of each FULL graph and adds no host work per step.
- **Scope.** Model Runner V2 only. No new options. Measured on CUDA (GB300) only; ROCm and XPU run the same code path but were not measured.

**Not a duplicate.** Searches for the draft-token gather, `set_draft_tokens`, aux hidden state copies and FULL graph output copies found no open PR with these changes; #55575 fuses DeepSeek-V4's residual for aux hidden states (model code), and #63406 changes how these persistent buffers are allocated (a textual neighbour, not the same change).
