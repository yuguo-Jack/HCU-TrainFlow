# [Bugfix] Support PyTorch bin checkpoints in checkpoint_has_lm_head

[Upstream PR](https://github.com/vllm-project/vllm/pull/64730) · state: open · merged: False

## Original PR description

fixes #64704

### what changed
`checkpoint_has_lm_head()` only inspected safetensors metadata. When loading pytorch `.bin` checkpoints with `tie_word_embeddings=True` where the checkpoint had an independent `lm_head.weight`, `checkpoint_has_lm_head()` returned `None`. This caused `maybe_untie_word_embeddings()` to exit early without untying, aliasing `lm_head` to `embed_tokens` and silently corrupting logits.

- inspects `pytorch_model.bin.index.json` weight map via `get_hf_file_to_dict` when safetensors metadata is absent
- inspects local/cached `pytorch_model.bin` on `meta` device with `torch.load(..., map_location="meta", weights_only=True)` to avoid memory allocation
- added unit tests covering sharded and single-file bin checkpoints in `test_config.py`
