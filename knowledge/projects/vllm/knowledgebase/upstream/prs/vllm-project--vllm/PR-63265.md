# [Quantization] Prefer Humming before Machete for 4-bit weights on SM90

[Upstream PR](https://github.com/vllm-project/vllm/pull/63265) · state: open · merged: False

## Original PR description



## Overview

On Hopper (SM90), automatic kernel selection for weight-only linear layers with 4-bit integer weights and FP16/BF16 activations (GPTQ, AWQ and compressed-tensors W4A16 checkpoints) now tries Humming before Machete. #56997 already moved Humming ahead of Marlin on SM90, but Machete ranks above both, so these layers still ran on Machete. 8-bit weights and every other linear scheme keep their current order.

## Claims

- Single-request decode (TPOT) on H200 is 23–24% faster for Qwen3-8B-AWQ and RedHatAI/Qwen3.8-27B-INT4, and output throughput rises 5–30% across concurrency 1–64. TTFT stays within ±9%.
- GSM8K accuracy is unchanged within noise: 87.7% vs 87.8% and 87.4% vs 88.2% (1319 questions, ±0.9 pt standard error).
- At the kernel level, Humming 0.1.18 takes 0.61–0.69x Machete's time at M ≤ 16 and 0.92–1.00x at M ≥ 256 (geometric mean over 14 shapes; FP16 and BF16; symmetric, asymmetric, g64, g128 and channel-wise).

## Validation

Hardware: 1x H200 NVL. Software: `vllm/vllm-openai:nightly` (`sha256:167ccd86…`, 0.32.1rc1.dev197+g8e2beaa3b, torch 2.14) with humming-kernels 0.1.18, the version main pins since #62816. The kernel sweep was also run on v0.32.0; the two runs agree to a median of 0.3% (5th–95th percentile within ±3.5%). No H100 was available.

**End to end** (`vllm serve` + `vllm bench serve`, random data, 1024 input / 128 output tokens, `--ignore-eos`, `--no-enable-prefix-caching`; Humming vs Machete forced with `VLLM_DISABLED_KERNELS`; warm Humming JIT cache):

**Kernel sweep** (`CompressedTensorsWNA16` create/process/apply path, one kernel left enabled via `VLLM_DISABLED_KERNELS`, random INT4 weights, CUDA graph over enough weight copies that weights are never L2-resident). It covers 14 (K, N) shapes from Llama-3.1-8B/70B, Qwen3-8B and Qwen3.8-27B, M from 1 to 8192, and 4 formats. <summary>Kernel sweep script</summary>

One kernel per process: `python sweep.py --kernel humming --out humming.jsonl`, then `--kernel machete`; `--bits 8` and `--dtype float16` give the other rows.

```python
"""W4A16 kernel sweep over M, shapes and quantization formats; one kernel per process, vLLM 0.32 as released.

The kernel is selected the way vLLM selects it (VLLM_DISABLED_KERNELS leaves only the requested one)
and every layer goes through vLLM's CompressedTensorsWNA16 create/process/apply path. Weights are
random INT4 codes, scales and zero points (GEMM time does not depend on their values). Each point
times one CUDA graph cycling through enough weight copies that no call finds its weights in L2.
Rows are appended to a JSONL file as they are measured.
"""
import argparse
import json
import math
import os
import statistics
import sys
import time

ALL = ['CutlassW4A8LinearKernel', 'MacheteLinearKernel', 'MarlinLinearKernel', 'ConchLinearKernel',
       'ExllamaLinearKernel', 'TritonW4A16LinearKernel', 'HummingLinearKernel']
WANT = {'marlin': 'MarlinLinearKernel', 'machete': 'MacheteLinearKernel', 'humming': 'HummingLinearKernel'}
SHAPES = {  # name: (k, n) of one TP=1 linear layer
    'llama8b.qkv': (4096, 6144), 'llama8b.o': (4096, 4096),
    'llama8b.gate_up': (4096, 28672), 'llama8b.down': (14336, 4096),
    'llama70b.qkv': (8192, 10240), 'llama70b.o': (8192, 8192),
    'llama70b.gate_up': (8192, 57344), 'llama70b.down': (28672, 8192),
    'qwen38_27b.gate_up': (5120, 34816), 'qwen38_27b.down': (17408, 5120),
    'qwen3_8b.qkv': (4096, 6144), 'qwen3_8b.o': (4096, 4096),
    'qwen3_8b.gate_up': (4096, 24576), 'qwen3_8b.down': (12288, 4096),
}
FORMATS = {  # name: (group_size or None for channel, symmetric)
    'g128_sym': (128, True), 'g64_sym': (64, True), 'channel_sym': (None, True), 'g128_asym': (128, False),
}

p = argparse.ArgumentParser()
p.add_argument('--kernel', required=True, choices=sorted(WANT))
p.add_argument('--ms', default='1,2,4,8,16,32,64,128,256,512,1024,2048,4096,8192')
p.add_argument('--shapes', default=','.join(SHAPES))
p.add_argument('--formats', default=','.join(FORMATS))
p.add_argument('--replays', type=int, default=20)
p.add_argument('--bits', type=int, default=4, choices=[4, 8], help='weight bits')
p.add_argument('--dtype', default='bfloat16', choices=['bfloat16', 'float16'], help='activation/params dtype')
p.add_argument('--out', required=True, help='JSONL, appended')
a = p.parse_args()
os.environ['VLLM_DISABLED_KERNELS'] = ','.join(k for k in ALL if k != WANT[a.kernel])

import torch  # noqa: E402
from vllm.config import VllmConfig, set_current_vllm_config  # noqa: E402
from vllm.model_executor.layers.quantization.compressed_tensors.schemes.compressed_tensors_wNa16 import (  # noqa: E402
    CompressedTensorsWNA16,
)

dev = torch.device('cuda')
ms = [int(x) for x in a.ms.split(',')]
DT = getattr(torch, a.dtype)
meta = {'bits': a.bits, 'dtype': a.dtype, 'kernel': a.kernel, 'device': torch.cuda.get_device_name(), 'uuid': str(torch.cuda.get_device_properties(0).uuid)}
if a.kernel == 'humming':
    import importlib.metadata
    import humming
    meta['humming'] = importlib.metadata.version('humming-kernels')
    meta['humming_path'] = humming.__file__
print('META', json.dumps(meta), flush=True)


def nibbles(packed, dim):
    b = a.bits
    parts = [(packed >> s) & (2**b - 1) for s in range(0, 32, b)]
    return torch.stack(parts, dim=dim + 1).flatten(dim, dim + 1)


def make_layer(k, n, group, sym, seed):
    g = torch.Generator(device=dev).manual_seed(seed)
    scheme = CompressedTensorsWNA16('group' if group else 'channel', a.bits, group, sym, f'sweep.{seed}')
    mod = torch.nn.Module()
    mod.has_bias, mod.input_size = False, k  # what LinearBase carries (no bias, TP=1)
    with torch.device(dev):
        scheme.create_weights(mod, output_size=n, input_size=k, output_partition_sizes=[n],
                              input_size_per_partition=k, params_dtype=DT,
                              weight_loader=lambda *x, **y: None)
    mod.weight_packed.data.copy_(torch.randint(-2**31, 2**31 - 1, mod.weight_packed.shape, generator=g,
                                               device=dev, dtype=torch.int64).to(torch.int32))
    mod.weight_scale.data.copy_((torch.rand(mod.weight_scale.shape, generator=g, device=dev) * 0.01 + 0.005)
                                .to(DT))
    if not sym:
        mod.weight_zero_point.data.copy_(torch.randint(-2**31, 2**31 - 1, mod.weight_zero_point.shape, generator=g,
                                                       device=dev, dtype=torch.int64).to(torch.int32))
    raw = {name: t.data.clone() for name, t in mod.named_parameters() if name != 'weight_shape'}
    scheme.process_weights_after_loading(mod)
    chosen = type(scheme.kernel).__name__
    assert chosen == WANT[a.kernel], chosen
    return (lambda x: scheme.apply_weights(mod, x, None)), raw


def dequant(raw, k, n, group):
    codes = nibbles(raw['weight_packed'], 1).float()  # (n, k)
    gs = group or k
    zp = nibbles(raw['weight_zero_point'], 0).float() if 'weight_zero_point' in raw else torch.full_like(
        raw['weight_scale'], 2 ** (a.bits - 1), dtype=torch.float32)  # (n, k // gs)
    s = raw['weight_scale'].float()
    return ((codes.reshape(n, -1, gs) - zp.unsqueeze(-1)) * s.unsqueeze(-1)).reshape(n, k)


def time_point(fns, x, calls_per_graph):
    for f in fns:
        f(x)
    torch.cuda.synchronize()
    reps = math.ceil(calls_per_graph / len(fns))
    s = torch.cuda.Stream()
    s.wait_stream(torch.cuda.current_stream())
    with torch.cuda.stream(s):
        for f in fns:
            f(x)
    torch.cuda.current_stream().wait_stream(s)
    graph = torch.cuda.CUDAGraph()
    with torch.cuda.graph(graph):
        for _ in range(reps):
            for f in fns:
                f(x)
    for _ in range(3):
        graph.replay()
    torch.cuda.synchronize()
    us = []
    for _ in range(a.replays):
        e0, e1 = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
        e0.record()
        graph.replay()
        e1.record()
        e1.synchronize()
        us.append(e0.elapsed_time(e1) * 1000 / (reps * len(fns)))
    del graph
    us.sort()
    return statistics.median(us), us[len(us) // 10], us[9 * len(us) // 10]


out = open(a.out, 'a')
with set_current_vllm_config(VllmConfig()):
    from vllm.distributed import init_distributed_environment, initialize_model_parallel
    init_distributed_environment(world_size=1, rank=0, local_rank=0,
                                 distributed_init_method=f'file:///tmp/dist-{os.getpid()}', backend='nccl')
    initialize_model_parallel(1, 1)
    for fmt in a.formats.split(','):
        group, sym = FORMATS[fmt]
        for shape in a.shapes.split(','):
            k, n = SHAPES[shape]
            weight_bytes = n * k * a.bits // 8 + n * (k // (group or k)) * 2 * (1 if sym else 1.25)
            copies = max(2, min(48, math.ceil(400e6 / weight_bytes)))
            t0 = time.time()
            try:
                built = [make_layer(k, n, group, sym, seed) for seed in range(copies)]
            except Exception as e:  # a kernel that cannot implement this format/shape
                row = dict(meta, format=fmt, shape=shape, k=k, n=n, error=f'{type(e).__name__}: {e}'[:300])
                out.write(json.dumps(row) + '\n'); out.flush()
                print('SKIP', json.dumps(row), flush=True)
                torch.cuda.empty_cache()
                continue
            fns = [b[0] for b in built]
            ref_w = dequant(built[0][1], k, n, group)
            for b in built:
                b[1].clear()
            xr = torch.randn(16, k, device=dev, dtype=DT)
            ref = xr.float() @ ref_w.T
            rel = float((fns[0](xr).float() - ref).norm() / ref.norm())
            del ref_w, ref
            for m in ms:
                x = torch.randn(m, k, device=dev, dtype=DT)
                med, p10, p90 = time_point(fns, x, 16)
                row = dict(meta, format=fmt, shape=shape, k=k, n=n, m=m, copies=copies, median_us=round(med, 3),
                           p10_us=round(p10, 3), p90_us=round(p90, 3),
                           tflops=round(2 * m * k * n / med / 1e6, 2), weight_GBps=round(weight_bytes / med / 1e3, 1),
                           rel_l2_vs_dequant_m16=rel)
                out.write(json.dumps(row) + '\n'); out.flush()
                print('ROW', fmt, shape, m, row['median_us'], flush=True)
            print('DONE', fmt, shape, f'{time.time() - t0:.0f}s', flush=True)
            del built, fns
            torch.cuda.empty_cache()
print('ALLDONE', a.kernel, flush=True)
```

## Details

- **Change:** `prioritize_humming` takes an `ahead_of` kernel name, which defaults to Marlin, so all existing callers behave as before. `choose_mp_linear_kernel` calls it once more with `ahead_of="machete"` when the layer has 4-bit weights and FP16/BF16 activations. On SM90 the order becomes CutlassW4A8 (FP8 activations only) → Humming → Machete → Marlin. W4A8, 8-bit weights, MoE and the FP8/NVFP4/MXFP linear lists are unchanged, and `--linear-backend` / `linear_backend_per_quant={"mixed_precision": ...}` still override the choice.
- **Tests:** `test_cutlass_w4a16.py` asserted that Machete is the default. Its Machete tests now disable Humming or pass `linear_backend="machete"`, so they keep covering Machete. A new test asserts the Hopper default (Humming for 4-bit, Machete for 8-bit) and runs in the H100 kernels CI job. A CPU test checks that `ahead_of="machete"` moves only Humming.
- **Tradeoffs:** Humming is slower than Machete at a few points. At M = 32 on large-N MLP shapes it is up to 1.29x, and at M = 256–1024 on some shapes up to 1.2x; 25 of 560 BF16 points are more than 10% slower. Humming 0.1.18 is slower than 0.1.17 at M = 32, reported in vllm-project/humming#163; vllm-project/humming#167 proposes a fix. End-to-end throughput still improves at every concurrency tested.
- **Humming version:** the gain needs humming-kernels 0.1.18, which main pins. With 0.1.17 the decode gain is smaller (0.78–0.83x) and a few points are slower.
- **JIT and start-up:** Humming compiles kernels on first use per shape; vLLM's JIT warmup does not cover it. The compiled kernels are cached under `~/.humming`. Engine start-up (the `init engine` time) in the end-to-end runs, one start each:

  | model | start | Humming | Machete |
  |---|---|---|---|
  | Qwen/Qwen3-8B-AWQ | first, empty caches | 75.6 s | 35.1 s |
  | Qwen/Qwen3-8B-AWQ | later, warm caches | 11.2–12.1 s | 8.1 s |
  | RedHatAI/Qwen3.8-27B-INT4 | first, empty caches | 105.3 s | 106.8 s |
  | RedHatAI/Qwen3.8-27B-INT4 | later, warm caches | 28.1 s | 26.8 s |

  A deployment that does not keep `~/.humming` between starts pays the first-start cost each time.
- **Duplicate check:** no open or closed PR or issue changes the Humming/Machete order. This follows #56997 (Humming ahead of Marlin on SM90). #44529 reports AWQ W4A16 slower than FP16 on H100 and may be related; it was not re-measured.
- **AI assistance:** AI assistance (Claude) was used for the benchmarks, the code and this description. The submitter reviewed every changed line; the validation above was run on the submitter's H200 machine.
