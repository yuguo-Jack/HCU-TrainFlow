# [Bugfix][Attention] Fix FA4 FP8 descale strides for singleton KV heads

[Upstream PR](https://github.com/vllm-project/vllm/pull/58304) · state: open · merged: False

## Original PR description

## Purpose

Fix a FlashAttention 4 FP8 KV-cache crash when a per-tensor Q/K/V scale is expanded to a descale tensor with a non-unit head stride:

```text
Expected strides[leading_dim] == 1, but got 0
```

This was encountered in a Nemotron-H deployment with two total KV heads and TP=2 on B200 (vLLM 0.29.0). Each rank has one KV head. At batch size 1, `scalar.expand(1, 1)` has strides `(0, 0)` but PyTorch considers it contiguous, so `.contiguous()` can leave the incompatible stride unchanged. FA4 converts descales to CuTe tensors with `leading_dim=1`.

Materialize only 2-D FA4 descales whose head stride is not one using `clone(memory_format=torch.contiguous_format)`. Preserve compatible inputs and the existing non-FP8 behavior. This copies the small scale tensors, not the KV cache.

## Test Plan

Add a CPU regression suite that calls the production `flash_attn_varlen_func` and replaces only the downstream CuTe kernel entry point. It verifies the forwarded descale layout, values, and reuse of compatible inputs across:

- batch sizes 1 and 3;
- one and two local KV heads;
- scalar-expanded, per-head-expanded, and absent descales;
- FP8 e4m3, FP8 e5m2, and BF16 inputs.

```bash
.venv/bin/python -m pytest --noconftest tests/kernels/attention/test_flash_attn_interface.py -q
pre-commit run --files vllm/vllm_flash_attn/flash_attn_interface.py tests/kernels/attention/test_flash_attn_interface.py
```

The sibling kernel suite requires the CUDA package initializer. This test loads the Python wrapper directly so it can also run on a CPU-only machine. The existing attention-kernel CI glob includes the new file.
