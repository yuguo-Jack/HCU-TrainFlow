# [Model Loader] DeepSeek-V4 ROCm: keep the preshuffle scales out of the module's parameters

[Upstream PR](https://github.com/vllm-project/vllm/pull/65296) · state: closed · merged: True

## Original PR description

## Purpose

With `VLLM_RELOAD_MODE=direct`, DeepSeek-V4 on ROCm crashes on the first reload:

```
KeyError: 'layers.0.attn.fused_wqa_wkv.weight_scale_inv'
KeyError: 'layers.0.ffn.shared_experts.gate_up_proj.weight_scale_inv'
```

`prepare_attn_preshuffle` and `prepare_gateup_preshuffle` store the scale `nn.Parameter` itself as a module attribute (`self._wqa_wkv_scale = ws`, `self._gateup_scale = ws`). `nn.Module.__setattr__` then registers it as a second parameter under that name, which the reload does not know.

## Fix

- Store `ws.detach()`, a plain tensor on the same storage, so nothing new is registered.
- Assign it through `refill_derived`, so a reload refills it in place at the address the captured CUDA graphs read.
- Do the same for the other derived tensors of `_prepare_fp8_wo_a`: `_wo_a_e8m0_scale`, `_wo_a_cos_cache` and `_wo_a_sin_cache`.
- Move the `replace_parameter` / `refill_derived` imports to the top of both files.

## Test Plan

DeepSeek-V4-Pro (heterogeneous, TP8, CUDA graphs, compressor GEMM fusion on) on MI355X with `VLLM_RELOAD_MODE=direct`:

1. cold GSM8K (400, 5-shot)
2. reload the original weights
3. reload perturbed weights
4. reload the original weights again

Plus a `data_ptr` report against cold start. This was run together with #65281, which fixes the compressor-fusion offset on reload.
