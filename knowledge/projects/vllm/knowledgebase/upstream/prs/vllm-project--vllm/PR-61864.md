# [ROCm][Perf] Fuse QK-norm + MRoPE + KV-cache write for gated Qwen3.5 attention

[Upstream PR](https://github.com/vllm-project/vllm/pull/61864) · state: open · merged: False

## Original PR description

## Overview

Extend the ROCm `QkNormRopeKvCacheFusionPass` so the gated Qwen3.5-family attention prologue (`attn_output_gate`, GemmaRMSNorm, interleaved MRoPE) runs as one launch of AITER's Triton `fused_qkv_split_qk_norm_rope_cache` kernel, and fix two gaps in the existing MRoPE path (K was not returned for backends that read it from the argument; the shuffled KV layout flag was never forwarded). Ungated MRoPE models keep the existing HIP kernel.

Requires the companion AITER kernel change (MRoPE sections, shuffle KV layout, optional gate / V outputs); without it the gated pattern is not registered and nothing changes: https://github.com/ROCm/aiter/pull/6779

## Claims

- With `-cc.pass_config.fuse_qk_norm_rope_kvcache=True` (default `rope_kvcache_fusion_max_token_num=256`), each Qwen3.8 full-attention layer runs one fused kernel per decode step instead of q/k RMSNorm + MRoPE + `reshape_and_cache`; at 64 tokens: 22.6 µs → 4.88 µs per-layer, 848 kernels → 784 kernels per-step
- MRoPE models whose attention backend reads K from the argument (ROCM_AITER_FA prefill) now get the normed, rotated K (`k_out`) when the fusion covers prefill ranges; previously the raw K view was returned (GSM8K dropped to 0.55 at `max_token_num=8192` before this fix).

## Details

The pass already fused QK-norm + MRoPE + cache write for dense-Q MRoPE models through `QkNormMRopeKvCachePattern`. The Qwen3.5-family prologue differs in three ways:

- **`gated_q`**: with `attn_output_gate` the projection has `2·q_size` Q columns and each head is packed `[q | gate]`; the model views `[T, H, 2D]` and `chunk(2)`s, so Q is a strided view. The pattern mirrors the model's split and returns the gate as an output so `attn_output · sigmoid(gate)` stays attached. The Triton kernel reads the packed QKV directly (`gated_qkv_layout="interleaved"`), writes Q and K into the op's buffers and skips its own gate and V copies (`return_gate=False`, `return_v=False`).
- **`gemma_norm`**: the q/k norms are `GemmaRMSNorm`, which is the Triton kernel's norm. The pass registers both norm forms for the existing HIP path and the gated form for Gemma only; `_extra_check` rejects a plain-norm match whose weight is a wildcard-bound intermediate of another dtype.
- **`k_out`**: parity with the RoPE op. The fused op writes K to the cache; ROCM_AITER_FA's prefill consumes K from the tensor argument, so the replacement must return the normed, rotated K rather than the raw view. The old `_extra_check` guard that restricted K's consumers assumed every attention op reads the cache and is removed.

`rocm_aiter_ops.do_qk_norm_mrope_kvcache_update` dispatches gated layers to the Triton kernel; the gated patterns are registered only when the installed AITER's kernel signature has the new arguments. Also forwarded: `use_shuffle_layout` (was hard-coded `False`). 

`fx_eliminate_noop_reshapes` normalizes the traced pattern the way `NoOpEliminationPass` normalizes the model graph (reshape-of-reshape, shape-preserving reshape), without which the gated split's view/chunk/reshape chain never matches.

The `ROCM_AITER_UNIFIED_ATTN` backend only gains the keyword parameters on its existing hook override (necessary plumbing, exercised by the pass test).

With the flag on, unfused ranges run the `rotary_embedding` custom op (forced by this pass) instead of Inductor's fused RoPE (which explains the TTFT increases for some concurrencies); matching the native MRoPE decomposition instead is a follow-up.
