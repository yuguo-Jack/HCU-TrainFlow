# [MyPy][5/N] Fix mypy errors in hard tests/ dirs and enforce follow-imports=silent

[Upstream PR](https://github.com/vllm-project/vllm/pull/62142) · state: open · merged: False

## Original PR description



## Overview

Part 5 of enabling mypy on `tests/` (#49569). Fixes the mypy errors in the PR 5 directories and moves them from `SEPARATE_GROUPS` to `SILENT_GROUPS` in `tools/pre_commit/mypy.py`, so they are now checked with `--follow-imports silent` and cannot regress: `tests/entrypoints/llm`, `tests/entrypoints/openai`, `tests/kernels` (absorbing the previously listed `tests/kernels/{attention,core,helion,mamba,quantization}` and the separate `tests/kernels/moe`), `tests/lora`, `tests/tool_parsers`, `tests/v1/attention`, `tests/v1/e2e`, `tests/v1/ec_connector`.

Builds on #49570 (PR 0/1) and #51043 (PR 2). Not a duplicate: no open PR touches these directories for mypy (checked `gh pr list --search "49569 in:body"` and `"mypy tests"`; the open `[MyPy]` PRs are #55485 (PR 4), #55542 (kv-A) and #55901 (kv-B)).

Partial #26533.

## Claims

- 533 mypy errors across the eight directories → 0, with `--warn-unused-ignores` also clean. (The issue's ~650 estimate predates #59428, which disabled `arg-type` and `assignment` under `tests/`.)
- Type-only: no `vllm/` changes, no `cast()`, no bare `# type: ignore`; the 29 ignores added are scoped to an error code and carry a reason (inline when the line fits in 88 columns, on the preceding line otherwise); 12 ignores that no longer suppressed anything are removed.
- 49 mock method assignments replaced with `monkeypatch.setattr`.
- Pre-existing test defects surfaced by the stricter check are fixed where safe, and flagged in a comment where fixing would change what the test exercises (list in Details).

## Details

Most fixes follow the issue's recipe: `assert x is not None` before an `X | None` access, `assert isinstance(...)` to narrow a union or an abstract base to the concrete class the test builds, annotations on fixtures and helpers, and `monkeypatch.setattr` instead of assigning to a method. Scoped ignores remain only where a test stub intentionally does not satisfy the real interface (`misc` for `None` fallbacks of optional kernel classes and a `Final` attribute, `attr-defined` for `SimpleNamespace` stubs, `type-abstract` where a test instantiates an abstract class through a factory).

Pre-existing defects the stricter check surfaced (all in tests; none changes what a test exercises):

- `tests/entrypoints/llm/test_struct_output_generate.py`: `StructuredOutputsParams(backend=...)` has no such init field (`_backend` is `init=False`), so the call raised `TypeError`; the kwarg is removed and the helper no longer takes a backend.
- `tests/lora/utils.py`: `DummyLoRAManager.init_lora` passed `embeddings_tensor=` to `LoRALayerWeights(...)`, which no longer accepts it.
- `tests/tool_parsers/test_{internlm2,longcat,phi4mini}_tool_parser.py`: `tokenizer.get_vocab = MagicMock()` permanently mutated the module-scoped tokenizer fixture and leaked into later tests; now `monkeypatch.setattr`, undone per test.
- `tests/kernels/moe/test_unquantized_backend_selection.py`: assignments to a non-existent `FusedMoEParallelConfig.use_dp` removed; the no-DP state already comes from `make_no_parallel()`.
- `tests/kernels/moe/modular_kernel_tools/{mk_objects,common,cli_args}.py`: registries and `Config` fields were annotated as holding instances although they hold classes; now `type[...]` of the Modular subclasses that are actually registered.
- `tests/v1/attention/test_mla_prefill_registry.py`: the mock prefill backends' `run_prefill_new_tokens` / `run_prefill_context_chunk` did not match the ABC (`chunk_idx` vs `chunk`, missing `out` / `output_scale`).
- `tests/v1/attention/utils.py`: `try_get_attention_backend` was annotated `type[AttentionImpl]` but `get_impl_cls()` returns `type[AttentionImplBase]`; and the `add_mock_model_methods` block is removed: its `get_num_layers` mock shadowed the real method with the wrong arity, the three `*_for_layer` hooks no longer exist on `ModelConfig`, nothing reads any of them, and no caller passed the flag.
- `tests/v1/attention/test_mla_noncausal.py`: `query_len_support` is a `ClassVar` and was assigned through an instance; the assignment is removed (the inherited default is the value it set).
- `tests/v1/e2e/general/test_mamba_prefix_cache.py`: `get_fake_sample_fn` was annotated `-> SamplerOutput` although it returns a callable.
- `tests/v1/ec_connector/unit/test_metadata.py`: asserted load entries as `(transfer_id, block_ids)` pairs; the metadata carries `(transfer_id, block_ids, shape)` and the worker unpacks three values, so the test is updated to the real contract.

Deliberately not changed, flagged with a comment and a scoped ignore:

- `tests/kernels/moe/utils.py`: the int8 non-block branch of `moe_quantize_weights_2d` calls `ops.scaled_int8_quant(w, w_s, use_per_token_if_dynamic=...)`, but the signature is now `(input, scale, azp, symmetric) -> (q, scale, azp)`, so it would raise if reached. No test reaches it (every int8 caller uses block quant and the modular-kernel CLI only accepts fp8); a replacement needs a GPU to validate, so it is left for a follow-up.

Typing gaps in `vllm/` that the per-test fixes keep running into, left for follow-ups:

- four identical `type-abstract` ignores: `select_common_block_size` / `get_supported_kv_cache_layouts` take `type[AttentionBackend]`, but the indexer backends leave `get_impl_cls` abstract;
- repeated narrowings of `Metric.value` (only `Counter` / `Gauge` have it), `LLMEngine.engine_core` (to `InprocClient`), `EmbeddingCache.get/alloc` (`CacheEntry | None`) and `FusedMoEQuantConfig.*_scale` (`Tensor | None`).

`MockMLAAttentionLayer.forward_impl` in `tests/v1/attention/test_mla_backends.py` keeps a scoped `override` ignore because the replica deliberately takes only the arguments the test passes; the prefill-registry mocks above were aligned to their ABC instead because they are registered as real backends.

The hook change is routing only: the absorbed `tests/kernels/*` entries become redundant under the `tests/kernels` parent entry and are removed, mirroring what #51043 did for `tests/plugins_tests`.
