# [MRV2][DBO] Don't microbatch a step that splits a prefix from its writer

[Upstream PR](https://github.com/vllm-project/vllm/pull/61441) · state: open · merged: False

## Original PR description

Port of DBO fix #51402 to the V2 runner. The scheduler can admit a request on a prefix cache hit against blocks another request in the same batch is only filling in this step. Run whole, every layer's KV write precedes any read; split by DBO, a reader in the first microbatch can attend over blocks the writer in the second has not written yet.

V2 keeps its block tables on the GPU only, so BlockTables gains an optional host mirror, enabled when microbatching is configured. Readers are limited to requests admitted this step (V2 receives resumed requests as new ones), which also covers the one-token query over a fully cached prompt that V1's query-length filter skips. DCP-sharded groups are indexed by virtual block.

Also parametrize tests/v1/distributed/test_dbo.py over both model runners, setting VLLM_USE_V2_MODEL_RUNNER explicitly since DBO still defaults to V1.

Isn't the case that `splits_prefix_from_writer` returns `True` when the hazard exists?

I believe it should be:

```
allow_ubatching =  not splits_prefix_from_writer(...)
```

Note V1's sibling [_allow_microbatching](https://github.com/vllm-project/vllm/blob/b965ee564d1897fdaeddaeceecc316aa15a45312/vllm/v1/worker/gpu_model_runner.py#L3668) has an inverted polarity (returns `True` when one can do microbatching "allow")
Maybe the V2 port could keep V1's name and polarity?

`table[idx_mapping_np`] materializes a `(num_reqs, max_num_blocks)` int32 copy per KV group per step isn't it?

Looks like v1 does not have this problem as the requests are condensed so that rows 0..num_reqs-1 are the current batch, in batch order.  Hence one can do  https://github.com/vllm-project/vllm/blob/0f0bc4dbb1177d3391dfb6f3dbd336f226315106/vllm/v1/worker/gpu_model_runner.py#L3700

which is actually a more efficient slice.

Maybe it is worth to rewrite for efficiency as follows:

```patch
         columns = start[:, None] + np.arange(span)[None, :]
-        written = np.take_along_axis(
-            table[idx_mapping_np],
-            np.minimum(columns, table.shape[1] - 1),
-            axis=1,
-        )[columns < stop[:, None]]
+        written = table[
+            idx_mapping_np[:, None], np.minimum(columns, table.shape[1] - 1)
+        ][columns < stop[:, None]]
```
