# [Bugfix][Parser] Align Kimi K3 response transitions

[Upstream PR](https://github.com/vllm-project/vllm/pull/60655) · state: open · merged: False

## Original PR description

## Overview

Kimi K3 can lose an answer when its JSON quotes a think marker, including after an otherwise normal thinking response. This change identifies channel boundaries from actual control-token IDs and preserves the reasoning, answer and following tool calls. It also retains recovery when the model starts a response without closing think.

Supported workflows: K3 non-streaming extraction, Chat streaming, reasoning-token accounting and structured-output activation. Depends on [#60565 at `3b2cabd`](https://github.com/vllm-project/vllm/commit/3b2cabd25977d8df70ad80252e7e4a3e1f2343a2); that PR's shared prompt-boundary dispatch remains unchanged.

## Claims

- Preserve quoted think markers in answers after normal thinking or a leading response opener. Ordinary text that spells a marker does not change channels.
- When no earlier think-close ends reasoning, use the first genuine generated response opener and keep the reasoning before it. Non-streaming extraction, streaming, counting and grammar checks use the same response-token definition.
- Preserve the engine's visible text, including stop/EOS truncation. During streaming, wait for the delimiter text before handing off to the content/tool parser; grammar activation remains token-based.
- Keep boundary discovery incremental and model-local, without changing the shared parser interface or adding a K3 special case to the shared manager.

```python
from transformers import AutoTokenizer
from vllm.entrypoints.openai.chat_completion.protocol import ChatCompletionRequest
from vllm.parser.kimi_k3 import KimiK3Parser
from vllm.reasoning.kimi_k3_reasoning_parser import KimiK3ReasoningParser

class K3(KimiK3Parser):
    reasoning_parser_cls = KimiK3ReasoningParser

tok = AutoTokenizer.from_pretrained(
    "moonshotai/Kimi-K3",
    revision="f831ab66814297da540d832a5235f8e904f29d06",
    trust_remote_code=True,
)
plain = lambda text: tok.encode(text, allow_special_tokens=False)
think_open = "<|open|>think<|sep|>"
think_close = "<|close|>think<|sep|>"
response_open = "<|open|>response<|sep|>"
body = '{"marker":"' + think_open + '"}'
request = ChatCompletionRequest(model="kimi-k3", messages=[])
for prefix in (
    plain("plan") + tok.encode(think_close),  # normal consumed-prefix thinking
    plain("plan"),                          # missing think-close
    tok.encode(think_open) + plain("plan"),  # explicit unclosed think
):
    ids = prefix + tok.encode(response_open) + plain(body)
    result = K3(tok).parse(tok.decode(ids), request, model_output_token_ids=ids)
    print(result)
    assert result == ("plan", body, [])
    assert K3(tok).count_reasoning_tokens(ids) == len(plain("plan"))
```

The third keeps the response wrapper and JSON inside reasoning. The candidate returns reasoning `plan` and the complete JSON; the same inputs also pass token-wise streaming checks.

## Details

Searching all decoded text for a think opener can mistake a JSON string for a channel boundary. Restricting response recovery to generated offset zero avoids that ambiguity but drops the existing missing-close recovery. The K3 reasoner now finds the first actual response-opener token sequence; an earlier actual think-close takes precedence. The prompt boundary excludes markers supplied by the prompt, and ordinary marker-looking token sequences do not trigger the rule.

The frontend and grammar consume different views of the same output: raw token IDs can arrive before stop buffering exposes their text. The grammar predicate stays pure and examines new IDs plus marker overlap. The frontend retains the first boundary and waits for its visible delimiter, then hands off the complete content-token tail. Text is sliced from engine output rather than reconstructed from IDs, so omitted stop/EOS text is not reintroduced. The existing text-only fallback is retained.

This investigation followed JSON failures in Moonshot AI's official [Kimi Vendor Verifier (KVV)](https://github.com/MoonshotAI/Kimi-Vendor-Verifier). The endpoint's engine/version was unavailable; the reproductions establish vLLM source defects rather than attributing those endpoint failures to a particular deployment.

Limits: wrapper cleanup is unchanged: quoted `<|close|>message<|sep|>` can still be removed from an answer, and quoted `<|close|>response<|sep|>` can still truncate it. These separate limitations remain outside this fix. This does not introduce general multiple-think-block recovery or change tools-open handling. Responses streaming with added-token spacing is outside the checked Chat streaming surface. This branch includes #60565's existing prompt-boundary dispatch and depends on that PR. No shared base-parser API change or further #60565 source update is needed.

Related work: [#57098](https://github.com/vllm-project/vllm/pull/57098), [#57366](https://github.com/vllm-project/vllm/pull/57366) and [#50291](https://github.com/vllm-project/vllm/pull/50291) address other truncated/markerless reasoning shapes. This change focuses on genuine control-token identity, quoted-marker preservation and consistent consumers of that boundary.
