# [KV Connector][NIXL] Validate DCP interleave size in handshake

[Upstream PR](https://github.com/vllm-project/vllm/pull/60484) · state: open · merged: False

## Original PR description

TL;DR: PR #55531 adds a way to specify arbitrary `--cp-kv-cache-interleave-size` for mirror DCP config. Incidentally one can now also spawn a pair with different interleave-size, which would drop accuracy. This PR checks interleave size is matching between P-D.

## Purpose

With DCP, NIXL copies whole KV blocks rank to rank. The token layout inside a block depends on `cp_kv_cache_interleave_size`: token `t` of a virtual block lives on DCP rank `(t // I) % dcp`. 
P and D therefore have to use the same value, but the connector never exchanged it. 

Since #55531, an explicit `--cp-kv-cache-interleave-size` skips NIXL's automatic pinning to `block_size`. So P on auto (= block_size) and D with an explicit `1` complete the handshake and silently exchange incompatible KV. On Kimi-Linear-48B (P TP4/DCP4 -> D TP4/DCP4) gsm8k dropped to 0.854, versus ~0.90 when the values match, and no error was raised.

This PR:
- Adds the resolved `cp_kv_cache_interleave_size` (read after `adjust_dcp_kv_cache_interleave_size` runs in the worker) to `NixlAgentMetadata`, and bumps `NIXL_CONNECTOR_VERSION` to 14.
- Rejects the handshake in `_validate_remote_parallel_config` when both peers use DCP and their sizes differ. This check runs before both `add_remote_agent` and `_add_notif_only_remote_agent`, so it covers both the pull and the push paths.

A peer with DCP=1 is not checked. Its interleave value doesn't affect its blocks. It also keeps the default value while a DCP peer gets pinned to block_size, so comparing the raw values would reject the supported asymmetric setups (DCP1 <-> DCPn). The compatibility hash is left unchanged on purpose: the parallel layout is checked at runtime, the same way as `dcp_size`.

## Not a duplicate

- #60255 and #56256 change how the interleave is resolved in config (connector alias, per-slot connectors). Neither one exchanges or validates the value between peers.
- #60275 (draft) adds the same `cp_kv_cache_interleave_size` metadata field, but only checks block alignment in the asymmetric push case (`local_dcp_size != remote_dcp_size`). It does not cover the symmetric mismatch handled here. This PR uses the same field name and type so the two fit together, and whichever lands second only needs a trivial rebase.

## Test Plan

```bash
.venv/bin/python -m pytest tests/v1/kv_connector/unit/test_nixl_connector.py \
  tests/v1/kv_connector/unit/test_nixl_push_connector.py \
  tests/v1/kv_connector/unit/test_nixl_desc_geometry.py -q
```

Run on 1x B200. The new `test_handshake_validates_dcp_interleave_size` covers three cases:
- DCP peers with matching interleave pass.
- DCP peers with different interleave are rejected.
- A DCP=1 peer with a different interleave passes.

`test_nixl_desc_geometry.py` needed a one-line fix because its hand-built worker uses a `MagicMock` `vllm_config`.

E2E setup: moonshotai/Kimi-Linear-48B-A3B-Instruct, P TP4/DCP4 -> D TP4/DCP4, TRITON_MLA, toy proxy, gsm8k (1319 questions, 5-shot).

## Test Result

Unit tests: 492 passed.

E2E:
- Mismatch (P auto -> 512, D explicit 1): every D worker rejects the handshake. With the default `kv_load_failure_policy=fail`, requests return 500 instead of being served from corrupted KV (gsm8k 0.000, every response invalid):
  ```
  RuntimeError: NIXL DCP peers must use the same cp_kv_cache_interleave_size, as it determines how tokens are laid out in transferred blocks. Local: 1, remote: 512. Set the same --cp-kv-cache-interleave-size on both instances.
  ```
- Matched (P=1, D=1): the handshake passes, gsm8k accuracy 0.894, in line with the ~0.89-0.90 baseline.
