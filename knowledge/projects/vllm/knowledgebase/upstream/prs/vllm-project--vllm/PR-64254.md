# [Fault Tolerance] Add a pause instruction for externally detected failures ( #64249 )

[Upstream PR](https://github.com/vllm-project/vllm/pull/64254) · state: open · merged: False

## Original PR description

## Overview

Adds a `pause` fault-tolerance instruction so an orchestrator can start recovery on a healthy engine as soon as it learns of a failure from outside (Kubernetes node failure, OOMKill, container exit), instead of waiting for the engine to fault on its own. Implements the core of #64249.

Not a duplicate: no open PR adds this; #64249 was filed as a follow-up to #46370 and has no linked PR.

## Claims

- `POST /v1/fault_tolerance/apply` with `{"instruction": "pause"}` moves a healthy engine to `UNHEALTHY` at its next step boundary, after which `retry` (and `scale_down` once #46370 lands) is accepted.
- No request is sacrificed to trigger fault detection when a rank dies while the deployment is idle.
- `pause` on an engine that is already unhealthy is a no-op. Duplicate or stale pause markers never pause an engine a second time.
- No behavior change unless `pause` is sent.

## Validation

- New unit test `test_pause_makes_healthy_engine_recoverable` drives the real sentinel and `EngineCoreProc._handle_client_request`: two `pause` commands enqueue one marker, the marker raises `FaultTolerancePause`, `on_fault` aborts requests and sets `UNHEALTHY`, a later `pause` is a no-op, and a stale marker is ignored.
  ```bash
  pytest tests/v1/fault_tolerance/test_engine_core_sentinel.py -q
  # 3 passed
  ```
- Confirmed the test fails if `pause_requested` is not cleared in `on_fault`, and if `pause` is left behind the UNHEALTHY-only gate.
- `ruff` and `mypy` clean.

## Details

### The problem

Recovery commands (`retry`, and `scale_down` from #46370) are only accepted while an engine is `UNHEALTHY`. An engine becomes `UNHEALTHY` only by detecting a fault itself inside a collective: an all2all timeout during expert dispatch, or a Gloo DP group timeout. If a DP rank dies while the deployment is idle, the survivors are paused and never enter a collective, so they stay `HEALTHY` and reject recovery with `status is HEALTHY`. The first request after the failure then triggers detection and is aborted, and external signals can't be acted on at all.

### How it works

1. `EngineCoreSentinel.handle_command` handles `pause` before the UNHEALTHY-only gate, on the engine's input thread.
2. On a `HEALTHY` engine it sets `pause_requested` and puts an `FT_PAUSE` marker on the engine's input queue. This also wakes an idle engine blocked on `input_queue.get()`.
3. The busy loop handles input-queue items between steps, so it reaches the marker at a step boundary, with no collective in flight, and raises `FaultTolerancePause`.
4. `fault_tolerant_wrapper` catches it and calls the existing `on_fault`, which aborts running requests, sets the engine `UNHEALTHY`, pushes the new status, and waits for a recovery command.

Reusing `on_fault` means a paused engine is in exactly the state a self-detected fault leaves it in, so the existing recovery commands work unchanged.

### Edge cases

- `pause` on an `UNHEALTHY` engine: no-op, returns success. On a `DEAD` engine: no-op, returns failure.
- Duplicate `pause` before the first is handled: only one marker is queued (`pause_requested`).
- Stale marker after recovery: `on_fault` clears `pause_requested`, so a marker processed later is ignored and doesn't pause the engine again.

### Orchestrator flow

1. External signal arrives: `pause` to every surviving engine.
2. Poll `GET /v1/fault_tolerance/status` until each reports `unhealthy`.
3. Send `retry` (or `scale_down` once #46370 lands).
4. Poll status until healthy.

Self-detection still works as the fallback.

### Limitations and follow-ups

- **Admission (item 2 of #64249) is not included.** Requests that arrive while an engine is paused wait in its input queue and are served after recovery rather than getting an immediate 503. Rejecting them at the frontend needs the client to check engine status on `add_request`, so it is left for a separate PR.
- **Send `pause` to all survivors.** If it reaches only some engines during an active DP wave, the others block in the next DP collective until it times out and then go `UNHEALTHY` through self-detection, as today.
