# [Misc] Use torch 2.14 custom class API for LayerName registration

[Upstream PR](https://github.com/vllm-project/vllm/pull/64314) · state: open · merged: False

## Original PR description



## Overview

Disables the following warning at the beginning of the engine launch:

```log
W1029 00:11:32.623000 1 torch/_opaque_base.py:6] torch._opaque_base is deprecated, use torch._custom_class_base instead
W1029 00:11:32.623000 1 torch/_library/opaque_object.py:288] register_opaque_type is deprecated, use register_custom_class instead
W1029 00:11:32.623000 1 torch/_library/opaque_object.py:211] typ='value' is deprecated, use typ='constant' instead
(APIServer pid=1) INFO 10-29 00:11:47 [startup.py:38]
(APIServer pid=1) INFO 10-29 00:11:47 [startup.py:38]        █     █     █▄   ▄█
...
```

## Claims

- torch 2.14 onwards use the new custom class API instead of pre-2.14 opaque-type API.
- torch 2.11–2.13 keep using the old API, which is the only one available there.

## Validation

Validates with the existing `LayerName` coverage in CI.

## Details

On torch 2.14, every vLLM process logs three deprecation warnings at import time because `LayerName` is registered through the pre-2.14 opaque-type API. This PR switches to the new names on torch >= 2.14 and keeps the old path for torch 2.11–2.13.
