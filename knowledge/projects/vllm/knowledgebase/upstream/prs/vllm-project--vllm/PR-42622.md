# [Dist]support for NCCL’s new shrink and grow features.

[Upstream PR](https://github.com/vllm-project/vllm/pull/42622) · state: open · merged: False

## Original PR description

## Purpose

Support NCCL’s new communicator shrink/grow APIs in vLLM’s PyNCCL wrapper.

This PR adds minimal bindings and `PyNcclCommunicator` helpers for:

- `ncclCommShrink`
- `ncclCommGetUniqueId`
- `ncclCommGrow`

These APIs are the foundation for future runtime DP/EP resizing, where active NCCL communicators can be rebuilt without fully recreating the surrounding vLLM process/control-plane state.

The implementation intentionally keeps the scope small and does not add failure-recovery APIs such as revoke/async-error handling.

When `destroy_old` is set to `True`, all ranks that were part of the original communicator must participate in the collective `ncclCommDestroy` call to avoid a deadlock. In the current implementation, ranks that are in the `excluded` list return early without calling `ncclCommDestroy`, which will cause the retained ranks to hang at line 238 while waiting for the excluded ranks to join the collective destruction of the old communicator.

```suggestion
        if self.rank in excluded:
            old_comm = self.comm
            self.available = False
            self.disabled = True
            if destroy_old:
                self.nccl.ncclCommDestroy(old_comm)
            return False
```
