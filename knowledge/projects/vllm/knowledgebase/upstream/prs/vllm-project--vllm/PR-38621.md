# [Kernel fusion] QK Norm + RoPE + Cache + Quant  

[Upstream PR](https://github.com/vllm-project/vllm/pull/38621) · state: open · merged: False

## Original PR description


                                                                                                                                                                     
  ## Purpose

  Resolves https://github.com/vllm-project/vllm/issues/36066                                                                                                           
  
  For models that use QK RMSNorm (e.g. Qwen3), the post-projection path currently requires                                                                             
  multiple kernel launches:                                       
                                                                                                                                                                       
  1.  A triton kernel for Qknorm                                                                                                            
  2. A Triton kernel for RoPE
  3. `reshape_and_cache_flash` for KV cache write + optional FP8 quant                                                                                                 
                                                                                                                                                                       
  This PR fuses all of them into a **single CUDA kernel** (`fused_qk_norm_rope_cache_quant`),                                                                          
  eliminating intermediate global memory round-trips and multiple kernel launch overheads.   wo
   kernels and the extra kernel launch overhead.                                                                                                                       
                                                                                                                                                                       
  ## What's included                                                                                                                                                 

  **CUDA kernel** (`csrc/fused_qk_norm_rope_cache_quant.cu`)                                                                                                           
  - Warp-per-head design: one warp handles RMSNorm + RoPE + cache write for a single head
  - Supports both NeoX and GPT-J RoPE styles                                                                                                                           
  - Supports BF16/FP16 compute with optional FP8 KV cache quantization                                                                                               
  - Vectorized loads (vec2/vec4) and warp-shuffle RMSNorm (no shared memory)                                                                                           
  - V is written to cache first (fire-and-forget) while K normalization runs, hiding store latency                                                                     
                                                                                                                                                                       
  **Compiler fusion pass** (`vllm/compilation/passes/fusion/qk_norm_rope_cache_quant_fusion.py`)                                                                       
  - Pattern-matches qknorm+rope+optional quant+cache write in the Inductor post-grad graph                                                                   
  - Replaces them with a single fused op call, resolving runtime KV cache context via `layer_name`                                                                     
  - Gated behind `CompilationConfig.fuse_qk_norm_rope_cache_quant` (default off)                                                                                       
                                                                                                                                                                       
  **Tests & benchmarks**                                                                                                                                               
  - Standalone correctness test against the unfused baseline (`tests/kernels/test_fused_qk_norm_rope_cache_quant.py`)                                                  
  - Kernel-level benchmark: fused vs baseline (`tests/kernels/bench_fused_qk_norm_rope_cache_quant.py`)                                                                
  - NCU profiling harness (`tests/kernels/bench_fused_qknrc_ncu.py`)

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The kernel assumes that the `cos_sin_cache` has exactly `head_dim` elements per position. However, in many models, the rotary embedding is only applied to a subset of the head dimension (`rotary_dim < head_dim`). In such cases, `cos_sin_cache` will have `rotary_dim` elements per row, and indexing with `head_dim` will lead to out-of-bounds memory access or incorrect rotary values. You should pass the actual `rotary_dim` to the kernel and use it for indexing the cache.

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The implementation of `_fused_qk_norm_rope_cache_quant_impl` assumes that `q_weight` and `k_weight` are shared across all heads by calling `.view(head_dim)`. If a model uses per-head QK normalization weights (where the weight shape is `[num_heads, head_dim]`), this call will raise a `RuntimeError` because the total number of elements won't match `head_dim`. The fusion pass should either verify that the weights are shared (broadcastable from `[head_dim]`) or the implementation should handle per-head weights correctly.

```suggestion
        weight=q_weight.view(-1, head_dim)[0] if q_weight.numel() == head_dim else q_weight.view(num_heads, head_dim),
```

Accessing `attn_layer.impl.kv_cache_dtype`, `attn_layer._k_scale`, and `attn_layer._v_scale` directly is risky as these attributes may not exist on all attention implementations or when FP8 is disabled. For example, `_k_scale` is typically only defined if the model is configured for FP8 KV cache. You should use `getattr` with appropriate defaults or check the configuration before accessing these attributes to prevent `AttributeError` during compilation.
