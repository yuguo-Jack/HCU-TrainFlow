# [CI][Rust Frontend] Run more Python server tests against the Rust frontend

[Upstream PR](https://github.com/vllm-project/vllm/pull/63320) · state: closed · merged: True

## Original PR description

## Overview

Brings `.buildkite/test_areas/rust_frontend.yaml` up to date with what the Rust frontend passes today, using Python's own server-level tests. Every `-k` exclusion and commented-out command was re-run against the Rust frontend (and against Python for every failure): 10 stale exclusions are dropped, and the remaining ones now say why they exist. 11 commands from server-level test files that were not in the Rust CI yet are added, and three tests are modernized so they can run against the Rust frontend.

## Claims

- The Rust frontend CI steps run 10 previously excluded test selections and 11 more server-level test files, plus `test_completion.py` and the online custom logits-processor test on `Qwen/Qwen3-0.6B`.
- Only `tests/` and `.buildkite/test_areas/rust_frontend.yaml` change, and no product code. A test is relaxed only where both behaviors are semantically acceptable (each relaxation also passes under the Python frontend); no assertion on the behavior under test is weakened.
- Two concurrent LoRA adapter tests in `test_lora_adapters.py` could never fail (their tasks were not awaited); they now can.

Relaxations in `test_completion.py` (both behaviors acceptable):

- `test_completion_streaming`: the last chunk may carry only the `finish_reason`; the joined streamed text is still compared with the non-streaming output (same relaxation as `test_chunked_prompt.py`).
- `test_completion_stream_options`: with `stream=false`, `{"include_usage": null}` and `{"continuous_usage_stats": null}` may be accepted as unset (Rust) or rejected (Python); the non-null cases still require a 400.

Why the offline logits-processor tests keep opt-125m: with SmolLM2-135M (bf16; Instruct and base), `test_custom_logitsprocs` failed in 2 of 3 runs of the file because a request that does not use the processor flipped a near-tied greedy token between the two `LLM` instances. Only the online test reaches the Rust frontend.
