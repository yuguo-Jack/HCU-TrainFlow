# [MoE] Shape-based padding for FlashInfer TRT-LLM MXFP8 experts (gated and non-gated)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61293) · state: closed · merged: True

## Original PR description

## Overview

The FlashInfer TRT-LLM MXFP8 MoE kernel needs `intermediate % 128 == 0` and `hidden % 256 == 0`; otherwise it fails with `No valid config found`. This PR pads MXFP8 experts by shape on that backend, for gated and non-gated experts alike, so MXFP8-MoE checkpoints with misaligned expert sizes can run.

## Claims

- MXFP8 MoE layers with misaligned intermediate or hidden sizes now run on `FLASHINFER_TRTLLM`, gated or not.
- Aligned models are unchanged: no copy and no runtime padding.
- A W4A4 checkpoint with an MXFP8 MoE that this enables reaches **1.71×** the output tok/s/GPU of the BF16 model on GB300 at concurrency 64.

## Validation

- Unit tests: `pytest tests/kernels/moe/test_flashinfer.py -k mxfp8` gives 14 passed on B200. That is the new test (gated SiLU and non-gated ReLU², aligned and misaligned shapes such as 1856×2688, against `fused_experts` on the dequantized weights) plus the 4 existing MXFP8 TRT-LLM tests.

```bash
vllm serve $MODEL --tensor-parallel-size 1 \
  --max-num-seqs 128 --max-num-batched-tokens 32768 --max-model-len 32768 \
  --gpu-memory-utilization 0.9 --trust-remote-code --async-scheduling --no-enable-prefix-caching \
  --speculative-config '{"method":"mtp","num_speculative_tokens":2,"moe_backend":"flashinfer_trtllm"}' \
  --mamba-cache-mode none --mamba-backend flashinfer --mamba-ssm-cache-dtype float16 \
  --enable-mamba-cache-stochastic-rounding --mamba-cache-philox-rounds 5 --use-replayssm \
  --compilation-config '{"mode":3,"cudagraph_mode":"FULL_AND_PIECEWISE","max_cudagraph_capture_size":32768}'
```

- Accuracy (GB300): GPQA-diamond through NeMo Gym on 1x GB300, TP1, MTP=2 (198 questions x 8 repeats, thinking on, temperature 1.0, top_p 0.95), served as above plus
  `--max-model-len 262144 --reasoning-parser nemotron_v3`. pass@1 (mean over the 8 repeats ±
  standard error) is 76.45 ± 0.70% without prefix reuse and 76.58 ± 0.45% with prefix reuse
  (`--enable-prefix-caching --mamba-cache-mode align`, no ReplaySSM).
- Perf (GB300, TP1, speed-bench 1k prompts / OSL 200, no spec decode, same serve flags otherwise, concurrency 64): the W4A4 + MXFP8-MoE checkpoint reaches **9,640 output tok/s/GPU** (189.6 tok/s/user) vs BF16 5,648 (101.2), i.e. 1.71× throughput and 1.87× per user.
- `pre-commit run --files` on the changed files passes, including mypy.

## Details

- New `align_mxfp8_moe_weights_for_fi_trtllm`, next to `align_moe_weights_for_fi`:
  - It reuses `align_moe_weights_for_fi` for the intermediate size, padding gate and up halves separately.
  - It pads the hidden size with zero weights, and pads the UE8M0 scales the same way with 127 (scale 1.0).
- `prepare_fp8_moe_layer_for_fi` calls it on the MXFP8 TRT-LLM path and sets `intermediate_size_per_partition` and `hidden_dim` at the call site. The MoE runner then pads the activations to the padded hidden size and crops the output.
- The test uses `TrtLlmFp8ExpertsMonolithic`. `TrtLlmFp8ExpertsModular` (`trtllm_fp8_block_scale_routed_moe`) never passes `activation_type`, so it always runs the kernel gated.
