# [Bugfix][Model] Fix DeepSeek V4 scale_fmt default for non-canonical quant configs

[Upstream PR](https://github.com/vllm-project/vllm/pull/41791) · state: open · merged: False

## Original PR description

## Purpose

Fixes #41604.

DeepSeek V4 attention currently reads `quantization_config["scale_fmt"]` directly. Non-canonical DeepSeek V4 quantization configs may omit this DeepSeek-specific field and fail during model initialization with `KeyError: 'scale_fmt'`.

This PR falls back to the existing canonical default `ue8m0`, matching the default used by the DeepSeek V4 attention layer implementation.

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The direct access to `config.quantization_config` followed by `.get()` is unsafe if the `quantization_config` attribute is `None` or missing from the configuration object. This is a common scenario for models that are not quantized or use a different configuration structure, and it would result in an `AttributeError`. Using `getattr` with a fallback to an empty dictionary is more robust and prevents crashes during model initialization for these configuration variants.

```suggestion
        self.scale_fmt = (getattr(config, "quantization_config", {}) or {}).get("scale_fmt", "ue8m0")
```
