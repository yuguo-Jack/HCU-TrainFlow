# [Model Loader] One post-load hook signature; the loader runs every module's hook

[Upstream PR](https://github.com/vllm-project/vllm/pull/57678) · state: closed · merged: True

## Original PR description

## Purpose

This PR now carries a follow-up to #64357. The earlier revision ran the model-level hook on every load and reload; that landed in reworked form as #64357. Part of RFC #54477.

#64357 made `finalize_model_weights(model)` run once after every full load and reload, but it calls only the **root model's** `process_weights_after_loading`. Module-level hooks still had two signatures:

| module | signature | who called it |
|---|---|---|
| attention layers (`Attention`, `MLAAttention`, `MMEncoderAttention`, Kimi-K3 MLA / KDA, DeepSeek-V4 CPU attention) | `(act_dtype)` | loader, attention pass |
| root model | `()` | `finalize_model_weights` |
| any other module (VL language models, HY-V4 inner model, Dots3 vision MoE FFN, Kimi-K3 AMD MLA wrapper) | `()` | **its parent, by hand** |

So parents forwarded the hook to their submodules by hand: VL wrappers to `language_model`, Kimi-K3 AMD through a `modules()` loop, Dots3 to `visual` and then to each `block.mlp`, and so on. When a parent forgot to forward, the submodule was never processed, with no error. The loader also carried `TODO(lucas): see if there is a way to unify the signatures`.

## Changes

1. **One signature.** Attention layers record `self.act_dtype` at init and take no argument. This is the default dtype the loader sets from `model_config.dtype` while building the model, which is the same value the loader used to pass. Backend impls (`AttentionImpl.process_weights_after_loading(act_dtype)`) are unchanged.
2. **One dispatcher.** After the quant-method pass and the attention pass, `finalize_model_weights` runs the hook of every module, each module after all of its submodules (depth-first; a submodule shared by several parents runs once, before all of them). It skips quant methods (some are `CustomOp` modules whose hook takes `layer`), does not enter quantized layers (their submodules, such as compressed-tensors Hadamard transforms, belong to the quant method and are processed in the per-layer pass), and skips attention layers, which have already run. The stages stay as they are: per-layer quant pass → attention pass → module hooks; later passes may read what earlier ones produced (e.g. MLA absorbs `kv_b_proj` through its transforms in the attention pass).
3. **No hand forwarding.** These are deleted:
   - the DeepSeek-V4 / V4.1 (AMD, NVIDIA) VL wrapper and Kimi-K3 AMD wrapper forwards to `language_model`;
   - the HY-V4 AMD forward to `self.model`;
   - the Dots3 forwards to `visual` and to the `block.mlp` loop;
   - the Kimi-K3 AMD MLA-wrapper loop.

### Behavior

- **Ordering.** As before, all attention layers run before any module hook, and a module's hook runs after its submodules', which is what the deleted forwards guaranteed. Siblings run in registration order. No hook reads a sibling's derived state.
- **No hook runs for the first time, and none runs twice.** I enumerated every class with a no-argument `process_weights_after_loading` (AST scan of `vllm/`). Each one was already reached, either as a root model or through one of the forwards deleted above.
- **Layerwise reload and the sparse NCCL engine** both go through `finalize_model_weights`, so they get the same dispatch.

## Test Plan

- **New test.** `test_finalize_runs_every_module_hook_after_its_submodules` (`tests/model_executor/model_loader/test_reload.py`) checks that each module runs exactly once (including one shared by two parents), after its submodules, with quant-method modules, quantized layers' submodules and attention layers skipped. `test_attention_post_load_reads_normalized_transform` runs the real loader `process_weights_after_loading` with a real `CompressedTensorsLinearTransformMethod` + `HadamardTransform` and checks that the attention pass sees the transform already normalized, and normalized once.
- **Updated tests.**
  - The fake attention layers in `test_reload.py`, plus `test_mla_backends`, `test_vit_fp8_scaling` and `test_mla_attn_quant_fusion`, now call the hook without an argument.
  - `test_deepseek_v4_vl` now goes through `finalize_model_weights`.
  - `test_root_model_builds_the_fold` asserted the old forward-by-hand contract, so it is deleted.
- **End to end.** GSM8K before and after weight updates, on GB300.

## Test Result

All runs are on GB300, using the same image and seed, against plain main at `7fc467825d`, the PR's base.

**GSM8K.** Each run measures GSM8K at cold start, then again after 3 full-checkpoint direct reloads (`VLLM_RELOAD_MODE=direct`).

| model | what it exercises | main: cold → after reload | PR: cold → after reload |
|---|---|---|---|
| Qwen3-8B | `Attention` reads `act_dtype` from init | 0.895 → 0.895 | 0.895 → 0.895 |
| DeepSeek-V4.1-Flash (TP2) | VL wrapper no longer forwards to `language_model` | 0.899 → 0.898 | 0.900 → 0.907 |
| gpt-oss-20b | attention sinks, MXFP4 MoE quant method is a `CustomOp` | 0.438 → 0.023 | 0.444 → 0.022 |

Cold start matches main within noise for all three models. gpt-oss-20b also collapses after a direct reload on plain main; that is a separate issue, fixed in #64692, and unchanged by this PR.

**Unit tests.** 332 passed, 21 failed, 41 skipped. The two new tests pass, and so do the updated tests. `test_attention_post_load_reads_normalized_transform` fails on the previous head of this PR (`fb3b81ad63`, attention saw `1.0` instead of `0.5`), which is the regression a review caught: that head ran Hadamard transforms in the module pass, after MLA had already absorbed `kv_b_proj`. None of the 21 failures comes from this PR:
- **7 DeepSeek-V3 reload tests** (`test_reload_weights` / `test_online_quantize_reload` with DeepSeek-V3-debug, and `test_kv_scale_reload`). They fail the same way on plain main.
- **14 GLM5-next KDA / sequence-parallel tests.** They failed only in the full batch run. Rerun on their own, they pass on both main and this PR.
