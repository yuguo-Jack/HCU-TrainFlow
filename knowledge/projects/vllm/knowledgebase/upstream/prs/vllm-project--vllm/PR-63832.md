# [Bugfix][CPU][Arm] Enable W4A16 support in Dynamic4bitLinearKernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/63832) · state: open · merged: False

## Original PR description



## Overview

Enable W4A16 compressed-tensors inference on Arm CPUs through Dynamic4bitLinearKernel using the existing PyTorch/KleidiAI INT4 operators.

Fixes #63813.

## Claims

- Add support for packed symmetric INT4 (uint4b8) weights used by W4A16 compressed-tensors checkpoints.
- Enable W4A16 execution through the KleidiAI-backed Dynamic4bit path on Arm CPUs.
- Preserve the existing signed INT4 (int4) path used by W4A8.
- Support groupwise quantization with group sizes 64 and 128.
- Add 13 regression tests covering kernel selection, weight packing, numerical correctness, and unsupported configurations.

## Validation
Environment

```
Ubuntu 24.04.3 LTS (AArch64)
PyTorch 2.14.0.dev20260707
vLLM baseline 4135590ffe
```

Regression tests: `python -m pytest tests/kernels/quantization/test_dynamic4bit_arm.py -v`

Result: `13 passed, 14 warnings in 2.18s`

Model: `RedHatAI/whisper-small-quantized.w4a16`

Unmodified upstream selects CPUWNA16LinearKernel and fails during Whisper encoder warmup:
`AttributeError: '_OpNamespace' '_C' object has no attribute 'cpu_gemm_wna16'`

With this patch, vLLM selects:
Using `Dynamic4bitLinearKernel` for `CompressedTensorsWNA16`


## Details

The existing `Dynamic4bitLinearKernel` supports signed INT4 weights but rejects uint4b8, which is used by symmetric W4A16 compressed-tensors checkpoints. On the tested Arm CPU configuration, vLLM consequently selects `CPUWNA16LinearKernel` which attempts to call an unavailable `cpu_gemm_wna16` operator. This PR extends the existing Dynamic4bit implementation by:
- Adding `scalar_types.uint4b8` support on Arm CPUs.
- Unpacking eight offset-binary INT4 values from each INT32-packed weight element.
- Converting the unpacked values into the byte-packed representation expected by the PyTorch/KleidiAI packing operator.
- Validating group sizes using partitioned input dimensions.
- Rejecting explicit zero points for uint4b8.
- Checking the availability of both PyTorch INT4 packing and matmul operators.

The existing W4A8 weight conversion path remains unchanged. The implementation builds on the Dynamic4bit/KleidiAI support introduced in #17112 and extended in #33122 and #34890.
