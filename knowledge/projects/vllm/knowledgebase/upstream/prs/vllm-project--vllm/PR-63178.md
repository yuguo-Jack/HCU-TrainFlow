# [Docs][Mistral] Note that required and named tool choice may not produce a call

[Upstream PR](https://github.com/vllm-project/vllm/pull/63178) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Document that on recent Mistral models in the official Mistral format, `tool_choice="required"` and named tool choice don't guarantee a tool call. After the review discussion with the Mistral team, this PR no longer changes the grammar; it only updates `docs/features/tool_calling.md`.

## Claims

- **Mistral known issue.** The Mistral section now explains that mistral-common's grammar allows content, including reasoning, before the tool calls, and that the model isn't told a call is required, so a forced request can run to `max_tokens` (`finish_reason="length"`) without a call.
- **Pointers.** The Named and Required Function Calling sections, which promise a call, now link to that caveat.
- **Strict tools.** The caveat also says when tool names and argument schemas are enforced, with the correction from review: names are enforced for a named choice, or for all tools once any tool sets `strict: true`; argument schemas only for `strict` tools.

## Validation

- `pre-commit run --files docs/features/tool_calling.md` passes (markdownlint, typos). The new `#mistral-models-mistral` links match the heading's generated id.
- The documented behavior was measured on `main` earlier in this PR (1× H200, temperature 0, seed 42): with `tool_choice="required"` or a named tool and a prompt the tool can't answer, `mistralai/Ministral-3-3B-Instruct-2512` and `mistralai/Magistral-Small-2509` both ended with `finish_reason="length"` and no tool call.

## Details

- **Why docs only.** Content before a required call is intended in mistral-common's grammar. The proper fix is a prompt-side signal that current Mistral models aren't trained for, as discussed in the review above. The grammar changes from earlier revisions of this PR were dropped.
- **Not a duplicate.** #60983 also edits the Mistral section's known issues, for the parallel tool call workaround; whichever lands second needs a trivial rebase. I found no other open PR documenting this caveat.

- sfeng33 · comment · 2026-10-22T22:05:44Z · [source](https://github.com/vllm-project/vllm/pull/63178#issuecomment-6352339059)

After checking with the Mistral team, the behavior on main is expected from the grammar's point of view: the grammar allows `think? content?` before the call, and the model is not told about `tool_choice="required"`, so it can answer in prose and never reach the call. It is not really a grammar bug.

That said, it does break the OpenAI spec, which says `required` means the model must call one or more tools. The right fix would be on the prompt rendering side, so the model knows the call is required. But current Mistral models are not trained for that signal.

Given that, I would suggest not changing the grammar in this PR, and instead updating the docs to say that on the Mistral grammar path `required` and named tool choice are not guaranteed to produce a call, and that the model can run to `max_tokens`. We can revisit once the models support the signal.
