# [Bugfix][Rust Frontend] Prevent stalled engines from delaying auto-aborts

[Upstream PR](https://github.com/vllm-project/vllm/pull/61623) · state: open · merged: False

## Original PR description



## Overview

Automatic aborts were sent to engines sequentially from a single loop. If one
engine's send remained pending, aborts for later healthy engines were never
attempted until that send completed.

Dispatch automatic aborts through independent per-engine workers so a stalled
engine cannot delay cancellation messages for healthy engines. This prevents
disconnected requests on healthy engines from continuing to consume resources
because another engine is unresponsive.



## Claims

- Removes cross-engine head-of-line blocking from the automatic abort loop.
- Preserves request batching and serial ordering within each engine.
- Keeps worker lifetime tied to the parent abort loop.
- Adds deterministic coverage for one blocked engine and one healthy engine



## Validation

```

cargo test -p vllm-engine-core-client  blocked_auto_abort_does_not_delay_another_engine -- --nocapture

cargo nextest run -p vllm-engine-core-client  --all-features  --no-fail-fast

cargo clippy --workspace  --all-targets --all-features --locked -- -D warnings
```



## Details


The abort loop already coalesced pending cancellations by engine, but then
awaited each engine send sequentially. A pending send for engine A therefore
prevented the loop from reaching engine B.

A lazily created worker now owns the abort sends for each engine:

- The main loop continues batching and grouping request IDs by engine.
- Each grouped batch is enqueued without waiting for the engine send.
- A worker processes batches serially for one engine, preserving ordering.
- Different engine workers progress independently.
- Worker tasks are cancelled when the parent abort loop is dropped.

The regression test uses two mock engines and a test-only send gate. It blocks
engine 0 after its automatic abort reaches the send path, then verifies that
engine 1 receives its abort before engine 0 is released. The gate is compiled
only for tests and has no production runtime cost.
