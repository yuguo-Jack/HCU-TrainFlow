# [Bugfix][Structured Outputs] Reject degenerate `structured_outputs` that crash EngineCore

[Upstream PR](https://github.com/vllm-project/vllm/pull/45346) · state: closed · merged: True

## Original PR description


## Purpose

A single request with `structured_outputs={"json_object": false}` or `{"json": ""}` crashes the **EngineCore** process: the request returns 500 `EngineDeadError` and every subsequent request fails (instance-wide DoS).

`StructuredOutputsParams` counts constraints with `is not None`, so `json_object=False` (`False is not None`) and `json=""` (`"" is not None`) are treated as "a constraint is set" → a `StructuredOutputRequest` is built and sent to the engine. But `get_structured_output_key()` only returns `JSON_OBJECT` when `json_object` is truthy, so `False` falls through to `raise ValueError("No valid structured output parameter found")`; an empty `json` schema fails in the xgrammar compiler. These `ValueError`s are raised inside the EngineCore step loop, which has no per-request isolation, so one bad request kills the engine.

Fix: reject both inputs during request validation in `SamplingParams._validate_structured_outputs` (called by `verify()`, frontend → 400), next to the existing empty-grammar / empty-choice guards:
- `json` is an empty string → `ValueError` (mirrors the empty-grammar guard).
- `json_object is False` → `ValueError` (`json_object` is a flag; only `True` selects a constraint; omit `structured_outputs` to disable).

The bad request now fails fast at the frontend and the engine keeps serving. The deeper per-request engine-step exception isolation is a separate, larger change and is intentionally out of scope here.

## Test Plan

- Unit: `tests/v1/structured_output/test_utils.py` exercises `_validate_structured_outputs` for both inputs (CPU).
- E2E: real `vllm serve`, send a degenerate request then a normal request, and check engine survival.

## Test Result

E2E (real `vllm serve`), one bad request followed by a normal request:

| request | before | after |
|---|---|---|
| `structured_outputs={"json_object": false}` | 500 `EngineDeadError` | 400 `BadRequestError` |
| follow-up normal request | connection refused (engine dead) | 200, normal generation |
| `structured_outputs={"json": ""}` | engine crash | 400 `BadRequestError` |
| follow-up normal request | n/a (engine dead) | 200, normal generation |

Unit tests: with fix `2 passed`; revert the fix and both FAIL (neither input raises). Full `pre-commit run --files` passed (ruff, ruff-format, typos, mypy, SPDX, and all vLLM custom hooks).

Before the fix:
- request (1): `HTTP=500 {"type":"InternalServerError"}`; server log: `ValueError: No valid structured output parameter found` → `EngineDeadError: EngineCore encountered an issue`.

After the fix:
- request (1): `HTTP=400 {"message":"structured_outputs.json_object must be True if set; omit structured_outputs to disable structured outputs","type":"BadRequestError"}`.
- request (2): `HTTP=200`, normal generation; the engine stays alive.
- `structured_outputs={"json":""}`: `HTTP=400 {"message":"structured_outputs.json cannot be an empty string"}`, engine stays alive.
- Server log shows only the frontend `ValueError`, no `EngineCore failed` / `EngineDeadError`.

File: `vllm/sampling_params.py` · line 945

Hi @arpera, I checked on a live server: an empty dict is fine and should not be rejected.

`json={}` is the canonical "any JSON value" schema. `get_structured_output_key` serializes it with `json.dumps({})` to `"{}"`, which xgrammar compiles to a permissive grammar, so the request returns 200 and the engine stays alive. The crash is specific to the empty *string*: `json.loads("")` raises `JSONDecodeError` inside the xgrammar compiler, which runs in the engine step loop with no per-request isolation. So `{}` is a valid (if unusual) request, and rejecting it would be a regression; this guard intentionally targets only the empty string.
