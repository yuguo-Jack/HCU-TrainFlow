## Original PR description

# DeepSeek-V4 ROCm paged-MQA CUDAGraph support and cleanup

## Purpose

Add the missing gfx1151 / Strix Halo support for the native non-stage1 paged-MQA kernel used by DeepSeek-V4 DSpark.

Before this change, the native non-stage1 paged-MQA path was not production ready under CUDAGraph replay. The full vLLM TP=2 runtime failed during graph startup/warmup on this path, with the historical failure surfacing as a ROCm GPU memory fault in `_fp8_mqa_logits_kernel`. The integration did not provide a stable graph replay contract for paged-MQA metadata, paged-MQA output logits, and FULL-capture context capacity. That made the route depend on stage1 fallback/workarounds instead of the intended native 2-D paged-MQA backend.

This PR makes the native paged-MQA backend graph-safe for gfx1151 / Strix Halo by fixing the replay contracts above, then enables the DeepSeek-V4 DSpark `FULL_AND_PIECEWISE` CUDAGraph path that depends on that backend.

## This PR

- Makes FULL capture use representative paged-KV context and skips impossible FULL descriptors.
- Stages paged-MQA `context_lens`, `block_tables`, and output logits through persistent workspace resources so graph replay sees stable pointers.
- Enables the intended native/non-stage1 ROCm paged-MQA backend for gfx1151 DeepSeek-V4 instead of relying on stage1 fallback behavior.
- Keeps compressed/uncompressed paged-MQA length validation static and capture-safe.
- Drains speculative warmup collectives between warmup shape transitions.
- Restores gfx1151 DeepSeek-V4 `FULL_AND_PIECEWISE` by bypassing piecewise breakpoints for the ROCm paged-MQA custom path.
