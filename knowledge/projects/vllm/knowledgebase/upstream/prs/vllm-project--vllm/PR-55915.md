# [Metrics] Expose per-rank FT health

[Upstream PR](https://github.com/vllm-project/vllm/pull/55915) · state: open · merged: False

## Original PR description

Related to #54963.

Expose `vllm:engine_healthy{engine="<rank>"}` so routers can exclude unhealthy FT ranks while their API ports remain alive. Each scrape uses the existing cached `get_status()` result and reports zero if the client has failed.

The implementation stays in the metrics module. A separate registry keeps rank health out of shared Prometheus files. The remaining changes are documentation and tests.

File: `vllm/entrypoints/serve/instrumentator/metrics.py` · line None

```suggestion
            scrape_registry = CollectorRegistry(support_collectors_without_names=True)
```

With `auto_describe=True`, registering the existing registry triggers an eager collection of all metrics, followed by another collection when `/metrics` is scraped. This is particularly expensive with the multiprocess collector.

`support_collectors_without_names=True` avoids the extra collection while preserving `name[]` filtering.
