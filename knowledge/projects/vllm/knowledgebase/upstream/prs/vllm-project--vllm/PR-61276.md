# [Transformers backend] Trace the output head of causal models

[Upstream PR](https://github.com/vllm-project/vllm/pull/61276) · state: open · merged: False

## Original PR description



## Overview

The Transformers modeling backend assumes every causal LM's output head is `lm_head`, plus `logit_scale`/`final_logit_softcapping` read from the config. This PR traces the model's actual `ForCausalLM` class and reproduces whatever head it finds.

It is a more general take on #61246 (Ettin / ModernBERT decoder), which handles one extra head shape by assuming what `get_output_embeddings` returns, and loads it with `AutoModelForCausalLM`, which breaks multimodal models. On top of this PR, #61246 would only need its registry, docs and test entries.

## Claims

- The backend now builds the model's real class on meta, from `transformers` or the checkpoint's remote code, honouring `revision`, `code_revision` and `trust_remote_code`. It traces the `forward` with fx and splits the head into:
  - a **transform** before the output embeddings (e.g. ModernBERT's dense -> act -> norm, or Roberta/BERT's nested `lm_head`), run as a `GraphModule` in `compute_logits`, with its layers swapped for vLLM layers by `recursive_replace`;
  - the **output embeddings**, which become `ParallelLMHead`, wherever they live (`decoder`, `cls.predictions.decoder`, ...);
  - a **soft cap** and/or **scale** applied to the logits, which become `LogitsProcessor` arguments.
- Fixes Granite (and GraniteMoe*): `logits = lm_head(h) / config.logits_scaling` was ignored on `main`, so its logprobs were wrong (greedy output was unaffected, because scaling does not change the argmax).
- If the head cannot be found (e.g. the trace fails), the old behaviour is kept. If it is found but vLLM cannot reproduce it, loading now raises instead of silently producing wrong logits. MuseGlimmer, which scales before its soft cap, is the one such case among Transformers 5.19 causal and image-text-to-text classes.

## Validation

Greedy logprobs from the Transformers backend vs native vLLM (bf16, 8 prompts x 32 tokens, A100):

| Model | `main` tokens match | `main` mean / max logprob diff | PR tokens match | PR mean / max logprob diff |
|---|---|---|---|---|
| `google/gemma-2-2b-it` (soft cap) | 8/8 | ~0.012 | 8/8 | ~0.012 |
| `ibm-granite/granite-3.3-2b-instruct` (scale) | 8/8 | 0.2173 / 1.845 | 8/8 | **0.0105 / 0.135** |
| `CohereLabs/c4ai-command-r7b-12-2024` (scale) | 8/8 | 0.0096 | 8/8 | 0.0096 |

`jhu-clsp/ettin-decoder-17m` (transform + biased `decoder`, float32): the traced transform is used in the engine, prompt logprobs match HF to within 0.005 (eager and CUDA graphs), and the greedy comparison against HF passes. On `main` it fails to load.

Sweep of `find_output_head` over every causal and image-text-to-text class in Transformers 5.19 (tiny configs on meta):
- 162 plain `lm_head`
- now handled: Roberta-likes (7), BERT-likes (7), Electra, ModernBERT, BioGpt, TrOCR, Whisper, MiniCPM3, softcap models (Gemma2/3 and others), Cohere (3), Granite
- 15 fall back to the old behaviour (multimodal or encoder-decoder edge cases)

## Details

- The base model's output is identified as the `call_module` whose module holds the input embeddings, because `base_model`/`get_decoder()` are unreliable (e.g. Mllama's `base_model` is the model itself, and ModernBERT's `get_decoder()` returns its output embeddings).
- Casts and the `logits_to_keep` slice are treated as passthrough, so models that divide before slicing (MiniCPM3) still match.
- The tracer now shims classes that override `__call__` (vLLM's `support_torch_compile`), which otherwise get traced through.
- Checkpoint names of the head's weights are mapped with an exact dict in `load_weights`, rather than `WeightsMapper` regexes that apply in a chain.
- Cost: one meta instantiation and one fx trace per model load (not measured separately).
- Not in this PR: `HfRunner` in `tests/conftest.py` computes reference logprobs as `hidden_states[-1] @ get_output_embeddings().weight`, which skips transforms, soft caps and scales. It only matters once greedy tokens diverge; using `generate(output_logits=True)` would fix it.
