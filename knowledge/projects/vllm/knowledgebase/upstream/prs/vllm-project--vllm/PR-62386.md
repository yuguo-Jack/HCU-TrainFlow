# [Bugfix][Kernel][Perf] Honor outer_scale_stride in silu_and_mul_per_block_quant for TMA-aligned transposed scales

[Upstream PR](https://github.com/vllm-project/vllm/pull/62386) · state: open · merged: False

## Original PR description

## Purpose

On Hopper (`sm90`), `1×128` / `1×64` block-scaled FP8 GEMM consumers (`FlashInfer` `fp8_blockscale_gemm_sm90` `swapAB` and `DeepGEMM` `fp8_gemm_nt` `1d2d`) load activation scaling factors via TMA, which requires **column-major scales with 16-byte (4-element FP32) aligned column strides**:
- Logical shape: `(num_tokens, num_groups)` where `num_groups = hidden_size // group_size`
- Physical strides: `(1, round_up(num_tokens, 4))` (`tma_alignment = 4`)

While `torch.ops._C.rms_norm_per_block_quant` (`layernorm_utils.cuh`) already supports strided TMA-aligned column-major scale tensors by passing `scales.stride(1)` (`outer_scale_stride`) into the CUDA kernel, `torch.ops._C.silu_and_mul_per_block_quant` had **four interconnected issues** that prevented TMA-aligned column-major scale emission and caused silent memory corruption whenever `num_tokens % 4 != 0`:

### 1. Root Cause of the C++ Memory Corruption Bug (`fused_silu_mul_block_quant.cu`)

In `csrc/libtorch_stable/quantization/fused_kernels/fused_silu_mul_block_quant.cu`, `silu_and_mul_per_block_quant_kernel` previously computed the output scale pointer as:
```cuda
int const num_tokens = gridDim.x;
int const num_groups = gridDim.y;
float* group_scale_ptr = is_scale_transposed
                             ? scales + group_idx * num_tokens + token_idx
                             : scales + token_idx * num_groups + group_idx;
```
When `scales` is allocated with TMA-aligned column-major strides `(1, round_up(num_tokens, 4))` (so `scales.stride(1) = round_up(num_tokens, 4)`), element `(token_idx, group_idx)` resides at offset `group_idx * scales.stride(1) + token_idx`.
Because the kernel hardcoded `num_tokens` (`gridDim.x`) instead of honoring `scales.stride(1)` (`outer_scale_stride`), **every group `group_idx >= 1` wrote its scale to the wrong memory address whenever `num_tokens % 4 != 0`**, leaving the true strided locations uninitialized!

Existing unit tests in `tests/kernels/core/test_fused_silu_mul_block_quant.py` and `tests/compile/passes/test_silu_mul_quant_fusion.py` only tested `num_tokens in [1, 16, 32, 64, 128, 512]` with unpadded `.t()` scales (`stride=(1, num_tokens)`), where `scales.stride(1) == num_tokens`, masking the bug.

### 2. Summary of Fixes in This PR

1. **`csrc/libtorch_stable/quantization/fused_kernels/fused_silu_mul_block_quant.cu`:**
   - Pass `scales.stride(1)` (`outer_scale_stride`) into `silu_and_mul_per_block_quant_kernel` and compute `scale_rows = ((gridDim.x + outer_scale_stride - 1) / outer_scale_stride) * outer_scale_stride` when `is_scale_transposed == true`, matching `rms_norm_per_block_quant` in `layernorm_utils.cuh`.
   - Add `STD_TORCH_CHECK` guards verifying `is_scale_transposed` when `scales.stride(1) > 1` and `scales.numel() >= num_tokens * num_groups`.
2. **`vllm/_custom_ops.py` (`ops.silu_and_mul_per_block_quant`):**
   - Add `tma_alignment: int = 0` parameter (matching `ops.rms_norm_per_block_quant`), allocating `torch.empty_strided((num_tokens, num_groups), (1, tma_aligned_m))` when `is_scale_transposed=True` and `tma_alignment == 4`.
3. **`vllm/compilation/passes/fusion/act_quant_fusion.py` (`SiluMulBlockQuantPattern.replacement`):**
   - Previously, `SiluMulBlockQuantPattern` matched `per_token_group_quant_fp8` with `is_tma_aligned=True`, but its `replacement` ignored the matched `scale` buffer and allocated a fresh unpadded `.permute(-1, -2)` tensor (`stride=(1, num_tokens)`), stripping TMA alignment when `num_tokens % 4 != 0`. It now passes the matched `scales=scale` buffer directly into `self.FUSED_OP` (matching `RMSNormGroupQuantPattern` in `rms_quant_fusion.py`).
4. **`vllm/model_executor/layers/fusion/fused_act_quant.py` (`_silu_and_mul_fp8_dynamic_block`):**
   - Allocate TMA-aligned column-major scales (`stride=(1, round_up(num_tokens, 4))`) and call `torch.ops._C.silu_and_mul_per_block_quant(..., is_scale_transposed=True)`, eliminating the downstream scale transpose+pad kernel on `sm90`.
