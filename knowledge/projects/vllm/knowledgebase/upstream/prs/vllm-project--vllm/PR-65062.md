# [Bugfix][Test] Qwen4Exp QSA: run the fp8 kernel tests the way the layer does below sm_89

[Upstream PR](https://github.com/vllm-project/vllm/pull/65062) · state: open · merged: False

## Original PR description



## Overview

On Ampere (sm_80/sm_86), 20 fp8 cases of the Qwen4Exp QSA kernel tests fail before they run: Triton refuses to compile a kernel that takes a `torch.float8_e4m3fn` tensor below sm_89. Serving is not affected. Below sm_89 the layer passes an fp8 main KV cache as its `uint8` storage (#60602), and it does not run the fp8 indexer or the fused fp8 prepare. This PR makes the tests do the same. Test-only change.

The failing cases came with #54890 (fp8 indexer cache), #55557 (fp8 main KV cache) and #57097 (fused prepare). #60602 added the Ampere path in the layer but did not update these tests, and NVIDIA CI does not run these files.

## Claims

- `test_qsa_sparse_paged_attention_correctness[*_fp8]`: below sm_89 the kernel now gets the `uint8` view of the fp8 cache, as `Qwen4ExpQSAImpl.forward` passes it, so the Ampere byte-decode path is tested against the same dense reference.
- `test_qsa_decode_selection_correctness` / `test_qsa_prefill_selection_correctness` (fp8 indexer) and `test_qsa_fused_prepare_matches_unfused[*-indexer_dtype1]` (fused fp8 prepare) are skipped below sm_89, because the layer does not run these paths there (`use_fused_qsa_prepare` requires sm_89+ for an fp8 cache).
- No change on sm_89+: the same cases run with the same tensors.

## Details

- Triton has no e4m3 (`fp8e4nv`) type below sm_89, so any kernel argument of dtype `torch.float8_e4m3fn` fails to compile there. #60602 added the Ampere path in the layer: `Qwen4ExpQSAImpl.forward` passes the cache's `uint8` storage below sm_89, and `_maybe_dequant` decodes the e4m3 bytes in the kernel (#60992 made this faster). The tests still passed `float8_e4m3fn` on every architecture.
- The fp8 indexer cache has no Ampere path: the indexer kernels take `float8_e4m3fn` tensors. These cases are skipped below sm_89, not changed. Rejecting `indexer_kv_dtype="fp8"` below sm_89 at config time would give users a clear error, but that is a behaviour change and out of scope here.
- Scope: test-only, +40 / −5 in two files.
