# [Bugfix][KV Connector][MoRIIO] WRITE: keep the RDMA completion wait off the forward thread and fail only the affected request

[Upstream PR](https://github.com/vllm-project/vllm/pull/63880) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

In MoRIIO WRITE mode, the prefill can wait for a request's RDMA completion on the model forward thread (`wait_for_save` → `seal_pending_transfers` → `_finalize_if_complete`). A transfer timeout there raises `TransferError` out of `execute_model` on one rank, and the engine dies. This PR moves that wait to the existing write-worker thread. A failed or timed-out transfer now sends `write_failed` to decode, so only that request fails.

## Claims

- A WRITE transfer that fails or times out no longer kills the prefill engine. It fails only its own request: decode reports it in `failed_recving`, and `kv_load_failure_policy` applies.
- The forward thread never blocks on RDMA completion. Previously it could stall prefill for every other request for up to `transfer_timeout` (30 s by default).
- On the write-worker path, the same failure now notifies decode. Previously the prefill freed its blocks and the decode request hung in `WAITING_FOR_REMOTE_KVS`.

## Details

**Request flow (WRITE):**
1. D allocates blocks for request R and sends them to P (`RemoteAllocInfo`).
2. In P's forward, `save_kv_layer` queues one write task per layer. The write worker thread posts the RDMA writes and records their statuses.
3. After the forward, `wait_for_save` → `seal_pending_transfers` records how many writes R expects.
4. Once all of R's writes are posted and sealed, `_finalize_if_complete` waits for R's RDMA statuses, sends `write_done` to D, and frees P's blocks. D then schedules R for decode.

**Root cause.** Two threads can run step 4: the write worker, after the last write, or the forward thread in step 3 when the worker finished first. The step-4 wait is bounded by `transfer_timeout`:
- **On the forward thread,** the wait blocks the forward. On timeout, `TransferError` escapes `execute_model` on that rank only, while the other ranks enter the next step's collectives.
- **On the write worker,** the exception is caught ("Write task failed … marking done"). P frees its blocks, but D is never told.

**Fix:**
- `seal_pending_transfers` queues sealed transfers on `_finalize_q`. The write-worker loop drains that queue before taking new write tasks, so step 4 now always runs on the worker.
- In `_finalize_if_complete`, a `TransferError` from the completion wait now sends `write_failed` to each notify target (the same message `_notify_write_failed` already uses for an allocation that never arrived) and marks the transfer done.

Tradeoffs and limits:
- `write_done` / `write_failed` now always comes from the worker thread. That adds up to one 10 ms poll interval of latency when the forward thread used to finalize.
- The worker still waits for one transfer at a time, the same as the existing worker path.
- After a timeout, D releases its blocks while the timed-out writes could in theory still land. With a sane `transfer_timeout` that needs a link stalled for that long. The READ path's `recv_abort_timeout` has the same property.
- With fan-in (several prefill ranks writing to one decode rank), one writer's `write_failed` fails the request. The other writers' later `write_done` messages are ignored.
- There is no new host/device synchronization. The `transfer_timeout` default (30 s) is unchanged; long-context deployments can raise it through `kv_connector_extra_config.transfer_timeout`.

**CI :** this path needs RDMA between MI300X/MI355X nodes and a transfer that fails. The E2E results above were measured outside CI.

Related:
- #62552 (draft) also sends `write_failed`, for a write task that fails before or while posting (e.g. a missing session). This PR covers the completion wait after the writes are posted, and moves that wait off the forward thread. The two merge without textual conflicts.
- #58962 (open) adds a consumer-side WRITE receive timeout, the other half of ROCm/mori#655. This PR makes the producer report failures right away instead of leaving D to time out.
- #39276 replaces a blocking `Wait()` with a polling loop, but that wait stays on the forward thread.
