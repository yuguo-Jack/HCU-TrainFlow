We haven't run NVFP4 ourselves, so we can't confirm or test this specific fix — but flagging the cross-reference since this looks like the same root-cause family as two other open PRs, all reproduced on Nemotron-3 checkpoints:

- #36807 — Marlin FP8 MoE, w13 N / w2 K tile-alignment (`tile_n=64`, `tile_k=16`), reproduced on `NVIDIA-Nemotron-3-Super-120B-A12B` at TP=4

All three are variations of the same underlying mismatch: Nemotron's MoE `intermediate_size` doesn't divide evenly across TP ranks, and different Marlin/WNA16 kernel variants each enforce their own alignment/group-size constraint on the per-rank shard, with no common padding utility catching it before the kernel call. Given the same model keeps tripping this across FP8, FP4, and INT4 quantization, might be worth consolidating into one shared tile-alignment helper instead of three independent per-dtype patches — would also make it easier to reason about correctness (e.g. whether zero-padding survives repacking) once instead of three times.
