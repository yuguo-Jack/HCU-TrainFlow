# [Perf][HiSparse] Allow full graphs for P/D prompt-token replay

[Upstream PR](https://github.com/vllm-project/vllm/pull/57939) · state: closed · merged: False

## Original PR description

A successful HiSparse P/D full-prompt import still replays the final prompt token to produce logits. Model Runner V2 marks that token as logical prefill, which currently disqualifies an otherwise single-token decode batch from FULL CUDA graphs. A new P/D arrival can consequently send the whole batch through the fallback graph path.

This patch records successful full-prompt imports in scheduler/request state and carries the imported length to MRV2. Graph dispatch treats the last-token replay as decode-shaped when HiSparse is enabled, the query length is one, and PCP is absent. Logical prefill state is retained for input preparation and HiSparse loading. Genuine prefills, partial imports, failed transfers, preempted requests, and speculative/multi-token replay retain their existing classification. The marker is reset on preemption and each receive completion.

Based on main `82daf9f5`. Main now has a separate sliding-window bounded-replay path; that path is explicitly excluded when recording this marker. No connector transport, model math, scheduler-overhead optimization, Rust frontend fix, or configuration change is included.

### Serving evidence and limits

The equivalent patch has run on B300 with GLM-5.3 NVFP4 (`RadixArk/GLM-5.3-NVFP4`, revision `11af4cba759e6559eda70358a5778bd1bddddd78`), 1 EP8 prefill node and 1 EP8 decode node, FP8 KV, HiSparse, index cache, NIXL, Mooncake, DeepEP LL decode, and FULL_AND_PIECEWISE breakable graphs. EPLB and speculative decoding were disabled.

An early live Scale-SWE comparison recorded:

| Observation | Before | After |
|---|---:|---:|
| Output tokens/s/decode GPU | 1,402 | 1,487 |
| Mean request TPOT | 130.9 ms | 124.4 ms |
| FULL graph steps/s | 4.58 | 7.86 |
| PIECEWISE graph steps/s | 2.93 | None reported in sampled window |
| Active decode requests | 1,491 | 1,517 |
| Mean completed prompt length | 10,363 | 9,524 |

These are unmatched live windows across a restart (three minutes before, two minutes after), with changing histories and tool activity. They demonstrate the observed dispatch change, not a controlled throughput improvement or a guarantee that D never prefills.

The current deployment also produced Nsight captures under C2048 agentic load: all eight decode ranks recorded 10 CUDA graph launches and 10 GPU graph activity events, with 218–235 active requests per rank before capture. That deployment additionally includes the separate scheduler speedup and Rust frontend fix; its total throughput is not attributed to this patch.

GPU evidence uses a local `7f47d2b`-based wheel with unchanged native binaries. **This exact current-main revision has not had GPU or token/logprob-parity validation.** Correctness testing beyond the focused checks below remains pending; this draft is for design review, not a claim of established model accuracy.
