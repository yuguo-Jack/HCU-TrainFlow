# [ROCm][Perf] Default AITER fused shared experts on for GLM-5.x MXFP4

[Upstream PR](https://github.com/vllm-project/vllm/pull/61941) · state: open · merged: False

## Original PR description



## Overview

On gfx950, GLM-5.x MXFP4 checkpoints now turn on `VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS` when it is unset, because AITER tunes their fused MoE only for the fused shared-expert shape. Related: #28985, #59221, #60604.

## Claims

- GLM-5.2-MXFP4, MI355X, TP4, MTP: output throughput +7-14%, mean TPOT -6-12%, prefill TTFT -6-7%; gsm8k within stderr, MTP acceptance unchanged.
- An explicit 0 or 1 still wins. Other models, platforms and layouts keep the default (off).

## Details

- Cause: AITER 0.1.25's `glm5_fp4_tuned_fmoe.csv` tunes this model's gfx950 W4A4 MoE only at 257 experts / top-9 (TP1/2/4/8 per-rank sizes); the unfused 256 / top-8 MoE gets default heuristics.
- Placement: the `GlmMoeDsaForCausalLM` config hook sets the env var, like the `VLLM_USE_BREAKABLE_CUDAGRAPH` auto-enable: the MoE router reads the process-wide flag, and the env var is in the torch.compile cache key.
- Gate: TP4/TP8 without DP, PCP or EP, as in #59221. The per-layer quantization check still runs, so the BF16 MTP layer of GLM-5.2/5.3-MXFP4 stays unfused (one existing warning per worker).
- Limits: TP8 and GLM-5/5.1/5.3-MXFP4 (same shapes) checked at config level only. TP2 stays opt-in, unmeasured. MI355X serving is not in CI.

Not a duplicate: #59221/#60604 cover GLM-5.3-Flash, #57916 MXFP8, #58904 weight loading; none changes the `glm_moe_dsa` default.

<details>
<summary>Design notes and duplicate search</summary>

- #28985 turned the flag off globally for mixed-precision shared experts (Kimi INT4 routed + BF16 shared), DeepSeek FP4 precision and EPLB. Here the shared expert is MXFP4 like the routed experts, the per-layer quantization check still applies and EP is excluded; gsm8k is unchanged.
- The gate is per model, like GLM-5.3-Flash's `_fused_shared_experts_tuned` and DeepSeek-V4's, because each follows its own AITER table (GLM-5.3-Flash adds gfx942 in #60604; this model's table is gfx950 only).
- A per-layer default inside the model, leaving the env var unset, would also need `GroupedTopKRouter`, `rocm_aiter_grouped_topk`, `FusedMoEConfig` and `RocmPlatform.apply_config_platform_defaults` to stop reading the global flag.
- The env var stays set for the rest of the process, as with the breakable-cudagraph auto-enable. With `VLLM_ROCM_USE_AITER` unset (vLLM's default) nothing changes.
- Searched `gh pr list --state all` for "fused shared experts GLM", "VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS default", "GLM-5 MXFP4 ROCm", "GLM-5.2 MXFP4 AITER" and "shared experts fusion ROCm GLM". Also related: #60831 (opt-in GLM-5 MonoKernel decode, which requires this flag on), #53248 (Quark exclude check), #53953 (AITER fusions for GLM-5.2-MXFP4, no FSE change), #61345 (DeepSeek-V4 MegaMoE FSE opt-in).
