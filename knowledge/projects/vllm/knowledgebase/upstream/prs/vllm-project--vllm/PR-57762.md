- njhill · comment · 2026-09-28T22:40:06Z · [source](https://github.com/vllm-project/vllm/pull/57762#issuecomment-5880022173)

I pushed an additional commit (c35bf0558a) extending this fix to Model Runner V2.

MRV2 is not vulnerable to the crash from #57719 — `Request._all_token_ids` fills prompt-embeds positions with zeros (`vllm/v1/request.py`), which `RequestState` stage-writes into `all_token_ids`, so the bincount kernel never reads stale/out-of-range indices. However, those placeholder zeros caused `_bincount_kernel` to set bit 0 of `prompt_bin_mask` for every prompt-embeds request, so the repetition penalty was silently misapplied to token 0's logit.

The commit wires the `PromptEmbedsState` is-token-ids mask (already maintained on device for the inputs-embeds overlay) into the penalty bincount kernel: embed positions are excluded for mixed prompts, and the whole prompt is skipped for pure prompt-embeds requests, matching the MRV1 semantics of this PR.

Verified with a new GPU unit test (`tests/v1/worker/test_gpu_penalties.py`, passes on RTX A1000; fails without the kernel change), plus existing `test_gpu_logit_bias.py` / `test_gpu_bad_words.py` / `test_gpu_logits_processors.py` and this PR's `test_gpu_input_batch.py` tests. `pre-commit run` (ruff, mypy, etc.) passes on the touched files.
