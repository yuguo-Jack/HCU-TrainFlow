# Feature/zoomkv v020 latest

[Upstream PR](https://github.com/vllm-project/vllm/pull/51165) · state: open · merged: False

## Original PR description

## Purpose

Integrate and stabilize the experimental ZoomKV backend on top of vLLM v0.20.0.

This PR:

- Fixes illegal memory access in the Triton paged KV gather kernel.
- Uses int64 address offsets to prevent overflow with large KV-cache pools.
- Adds logical-token and physical-block bounds checks.
- Improves mixed-batch and CUDA Graph retrieval handling.
- Adds a PyTorch reference gather and standalone Triton replay tool.
- Updates ZoomKV tests, examples, and documentation.

## Test Plan

- Run the standalone gather replay:

  `python tools/zoomkv_replay_paged_gather.py --repeats 100`

- Run ZoomKV operator tests.
- Run an end-to-end TP=4 benchmark with:
  - Model: Qwen3.6-27B
  - Input length: 65,536 tokens
  - Output length: 1,024 tokens
  - Concurrency: 8
  - Requests: 128

## Test Result

- Standalone Triton gather replay passed across batch sizes 1/2/4/8 and sequence lengths 65,536–66,560.
- End-to-end TP=4 benchmark completed all 128/128 requests without illegal memory access.
- Python syntax checks passed.

Compared with Full Attention:

- Benchmark duration: 1235.22 s vs. 1423.88 s (13.3% lower)
- Output throughput: 106.11 vs. 92.05 tokens/s (15.3% higher)
- Total throughput: 6897.30 vs. 5983.41 tokens/s (15.3% higher)
- Mean TPOT: 45.58 ms vs. 60.38 ms (24.5% lower)
- Mean TTFT: 30,545.36 ms vs. 27,198.38 ms (12.3% higher)
