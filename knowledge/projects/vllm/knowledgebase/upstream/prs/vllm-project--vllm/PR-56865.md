# [CI] Add DCP generation parity e2e and schedule Kimi DCP tests in CI

[Upstream PR](https://github.com/vllm-project/vllm/pull/56865) · state: open · merged: False

## Original PR description

## Purpose

DCP (`--decode-context-parallel-size`) e2e coverage today consists of GSM8K accuracy floors on small models (`tests/distributed/test_context_parallel.py`) plus one B200 GSM8K eval config. Nothing in CI compares DCP generations against a `dcp=1` baseline on a real model, and `tests/distributed/test_kimi_linear_context_parallel.py` — tiny-model DCP logprob parity including a partial prefix-reuse case — is not scheduled in any CI job. Output-corrupting DCP regressions (#41623, and #48003 where TP2+DCP2 with FlashInfer produced gibberish from the first generated token) have therefore only been caught by manual runs.

This PR adds two small-model, 2-GPU targeted tests:

- **`test_dcp_generation_parity`** (`tests/distributed/test_context_parallel.py`): DeepSeek-V2-Lite, TP2, identical servers with `dcp=1` and `dcp=2`. All prompts share a long (~2k token) prefix so requests after the first decode out of prefix-cache hits — the path where DCP drift has historically shown up. Two phases per server:
  - sequential requests must match the baseline **exactly**;
  - a 64-request concurrent burst (batched decode at `max_num_seqs`) must match the baseline's identical burst for >=80% of requests, reusing the MTP e2e suite's 80% exact-match heuristic. This targets the high-concurrency batched-decode regime where DCP drift/gibberish has appeared in production.
- **Schedule `tests/distributed/test_kimi_linear_context_parallel.py`** in the `(H100) Distributed Features` and `(B200) Distributed` jobs, so the existing tiny-model DCP parity tests (dcp=1 vs dcp=2 logprob parity, partial prefix reuse) actually run in CI.

Both additions run on 2 GPUs with a 16B and dummy tiny models, inside existing CI jobs — no new pipeline jobs or big-model evals.

## Not duplicating existing PRs

Checked open PRs with `gh pr list --search "decode context parallel test"`, `"DCP e2e"`, and `"test_context_parallel"`. No open PR adds DCP generation-parity e2e coverage. The closest, #48003, is a FlashInfer+DCP metadata bugfix with a unit regression test and a manually-run e2e check; it does not add CI e2e coverage, and this test would have caught that failure class in CI. #56723 and #54790 are spec-decode+DCP bugfixes, not test coverage.

