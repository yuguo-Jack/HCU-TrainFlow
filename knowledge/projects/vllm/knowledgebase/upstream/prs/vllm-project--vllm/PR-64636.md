# [Perf][Qwen4Exp] Add SM80 TP=8 skinny GEMM plans

[Upstream PR](https://github.com/vllm-project/vllm/pull/64636) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Adds A100 (SM80) TP=8 skinny GEMM plans for the Qwen3.8-Flash-Next BF16 decode linears. SM80 had no plans, so every decode linear used cuBLASLt, which on these shapes runs split-K plus a `splitKreduce` kernel. Follows #64482 and #59214.

The skinny GEMM did not compile on SM80: its epilogue used `cute.arch.elect_one()`, which CuTe DSL accepts only on SM90+ (`CONFIG_UNSUPPORTED_ARCH 'sm_80'`). Below SM90 this PR writes the per-warp partial from lane 0 instead (same meaning: one lane per warp writes its partial sum); SM90+ keeps `elect_one()`.

## Claims

- 1.06–3.1x over cuBLAS per projection on A100 at M = 1–16 (38 plan entries, 10 shapes).
- End to end on 8 x A100 at concurrency 1, two pairs in opposite arm orders: TPOT P50 −8.3 % and −8.6 %, P95 −6.6 % and −4.2 %, output tok/s +4.9 % and +5.6 %. At concurrency 8: within noise (table in Details).

## Details

- Shapes and points that lose or win by less than 3 % stay on cuBLAS. Examples: QKVZ and QSA at M = 16, LM head at M ≥ 8, and the shared-expert down projection (2560, 80), which has no valid config. I also dropped final HC down at M = 4: it was 1.07x / 1.18x in the sweep but 0.91x in the validation run.
- The local TP=8 shapes come from the model's projection sizes (for example, QKVZ 16384 / 8 = 2048, QSA 768 q + 768 gate + 512 replicated KV head + 640 replicated indexer Q/K = 2688).
- `elect_one()` stays on SM90+: `CuteSkinnyGemm` takes `use_elect_one`, set from `current_platform.has_device_capability(90)`, so SM90+ compiles the same epilogue as main and only SM80/SM86 use the lane-0 store. On H100, all 24 `QWEN4_EXP_SM90_GEMM_PLANS` entries give bitwise-equal output with main and time within −0.6 % to +0.4 %.
- End to end: 8 x A100-40GB, TP8 + EP, MTP 3, Qwen3.8-Flash-Next-FP8, v0.32.0 CUDA 13 image with these two files mounted, MLPerf agentic dataset, 30 min per arm, A then B in one job. The start-up log confirms that the plans are used (`Warming up CuTeDSL compile_units=36 names=('shape-dynamic skinny GEMM',)`). 0 failed samples in every arm.

  At concurrency 1 (decode M = 4 with MTP 3), both pairs agree, in both arm orders: TPOT P50 −8.3 % / −8.6 %, P95 −6.6 % / −4.2 %, output tok/s +4.9 % / +5.6 %. At concurrency 8 the change is within run-to-run noise: decode steps there are dominated by MoE, all-reduce and many small kernels. Accuracy, paired on the turns both arms scored (the benchmark's per-turn score): C1 pair 1, 239 turns, diff −0.011 (95 % bootstrap CI [−0.060, +0.038]); C1 pair 2, 233 turns, diff −0.003 (CI [−0.051, +0.045]); C8, 1,863 turns, diff +0.005 (CI [−0.017, +0.026]). All intervals include zero; generation is sampled, so 26–36 % of turns differ between any two runs. The kernel outputs match F.linear (cosine >= 0.999997, max error not above cuBLAS's).
- CI: the new test runs only on SM80 with CuTe DSL; it skips elsewhere, like the SM90/SM100/SM121 tests in the same file.
