# [Bugfix][KV Offload] Advertise complete chunks as retrievable cache units

[Upstream PR](https://github.com/vllm-project/vllm/pull/57304) · state: open · merged: False

## Original PR description

## Purpose

Fixes #57159. Thanks to @nilig for the report and producer/consumer analysis.

An offloaded complete chunk is retrieved by its final block hash, but its
self-describing event currently advertises the constituent GPU-block hashes
as separate cache units. A request sharing only an interior prefix can
therefore appear to hit the CPU cache even though lookup misses.

This change advertises each complete chunk with its final hash and complete
token count as `block_size`. `BlockRemoved` uses the same saved chunk hash.
The preceding chunk's hash remains the parent. Existing tests and the option
documentation are updated to the corrected representation.

### Scope and compatibility

- Only self-describing complete-chunk event metadata changes. Cache keys,
  allocation, lookup, transfers, eviction, and generation are unchanged.
- Single-block chunks, opt-out/placeholder behavior, and partial recurrent
  tails retain their existing representation.
- No wire-schema field or default changes. Consumers must nevertheless honor
  the complete retrieval unit instead of splitting it into partial hits.
- The separate consumer issue llm-d/llm-d-router#2889 is not fixed here.

### Duplicate-work check

On 2026-09-17, the issue had no assignee or claim comments. PR searches for
`57159`, `offloading events`, and retrieval/chunk granularity found no direct
implementation. Related #52103 changes event provenance and metadata
lifetime, but the inspected patch retains per-GPU-block granularity. This
patch is limited to retrieval granularity; happy to coordinate merge order
and the event contract with that work.

## Test Plan

The new CPU-level regression pairs the actual `CPUOffloadingManager` with
`OffloadingEventsTracker`: a stored 64-token chunk is queried with shared
prefixes of 0, 16, 32, 48, and 64 tokens, using hash sizes of 4 and 16 tokens.
Additional cases check that overlapping chunks store/remove distinct hashes.
Existing tests retain coverage for parents, groups, promotion, placeholders,
and partial tails. GPU worker tests cover actual CPU/GPU transfers.
