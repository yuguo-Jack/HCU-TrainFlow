# [KVConnector] Add opt-in async NIXL pull receiverFeat/nixl background pull owner

[Upstream PR](https://github.com/vllm-project/vllm/pull/57987) · state: open · merged: False

## Original PR description

Large NIXL pull transfers can stall the decode model thread during descriptor preparation and READ submission. This change adds an optional background receiver that owns preparation, submission,
  polling, notifications, and native handle release.

  - Disabled by default; enable with kv_connector_extra_config.background_receiver=true.
  - Uses bounded admission and retains receive credits until transfer completion, handle release, and retirement.
  - Preserves native ownership during cancellation and shutdown.
  - Changes seven connector runtime files; no core scheduler, KV allocator, model-runner, or kernel changes.

  Related work: #45211 (https://github.com/vllm-project/vllm/pull/45211) moves READ submission onto a reader thread. This implementation proposes single-thread ownership of the full native transfer
  lifecycle.

  Initial support covers unidirectional pull with matching TP, PP1/PCP1/DCP1, and compatible direct-CUDA cache layouts. This is experimental: request IDs must remain unique, identity history
  defaults to 100,000 lifetime requests, and producer leases must cover transfer and recovery duration. An indefinitely blocked native call can delay heartbeats.

  Validation used identical runtime code at commit d80b52aad8, before supplemental tests were removed from the proposed diff:

  "$TEST_PYTHON" -m pytest --confcutdir=tests/v1/kv_connector/unit \
    tests/v1/kv_connector/unit/test_nixl_pull_receiver.py \
    tests/v1/kv_connector/unit/test_nixl_receiver_scheduler.py \
    tests/v1/kv_connector/unit/test_nixl_receiver_worker.py \
    tests/v1/kv_connector/unit/test_nixl_push_connector.py -q

  150 passed, plus seven targeted existing pull regressions. Applicable pre-commit checks passed. Broader geometry/HMA testing produced 103 passes and 204 failures, with identical outcomes on
  pristine upstream main.

  Native/GPU transport and end-to-end model validation of this revision remain pending. No performance or correctness acceptance is claimed.

  AI assistance was used for implementation, tests, and review.
