# refactor(model_executor): use QuantKey in Int8ScaledMMLinearLayerConfig

[Upstream PR](https://github.com/vllm-project/vllm/pull/63504) · state: open · merged: False

## Original PR description

## Intent

Fix vLLM issue #32268 (vllm-project/vllm on GitHub): refactor Int8ScaledMMLinearLayerConfig boolean fields to QuantKey, following the existing FP8ScaledMMLinearLayerConfig pattern. Mechanical, compiler-checkable change, validated by the repo's own tests.

## What Changed
- `Int8ScaledMMLinearLayerConfig` drops the `is_channelwise` and `is_static_input_scheme` booleans (and the related TODO). It now carries `weight_quant_key` and `activation_quant_key` `QuantKey` fields, like `FP8ScaledMMLinearLayerConfig`. `input_symmetric` stays as a field. `init_int8_linear_kernel` takes the two keys and sets `input_symmetric` from `activation_quant_key.symmetric`.
- The int8 scaled-mm kernels (`aiter`, `cpu`, `cutlass`, `triton`, `zentorch`) read the QuantKeys instead of the removed booleans. The compressed-tensors W8A8 int8 scheme builds the keys through a new `_int8_quant_keys` helper that maps strategy, static/dynamic input and symmetry to the `kInt8*` keys. The Quark W8A8 int8 scheme is updated for the new `init_int8_linear_kernel` signature.
- `test_scaled_mm_kernel_selection.py` and `test_quant_activation_contract.py` are updated to build configs with QuantKeys.

## Risk Assessment

✅ Low: This is a mechanical refactor of one config's fields to QuantKey. Every consumer and caller I checked maps the old booleans to the same behavior, and no old-field references remain.

## Testing

On macOS I could not run the repo's own tests: the selection test segfaulted on its first case (no compiled vllm._C), and the CUDA/CPU kernels and model loading cannot run here. I instead drove the changed code directly in a disposable venv. The new config accepted QuantKeys, Zentorch can_implement returned the right accept/reject for channel, tensor, static-activation and asymmetric configs, and the compressed-tensors QuantKey mapping gave the right static/dynamic, symmetric and group-shape keys for all 8 combinations. Not driven: the Cutlass, Triton, CPU and Aiter kernel paths, the Quark scheme, and the two changed test files.
