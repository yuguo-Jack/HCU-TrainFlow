# [LoRA][Step5] Support LoRA for Step5

[Upstream PR](https://github.com/vllm-project/vllm/pull/62498) · state: closed · merged: True

## Original PR description



## Overview

Adds LoRA support to Step5 (`Step5ForCausalLM` and `Step5ForConditionalGeneration`), added in #61727.

## Claims

- LoRA on attention (`q/k/v/g_proj`), the sparse indexer projections, `sparse_indexer_w`, dense MLPs and routed experts (per-expert keys, via `FusedMoEWithLoRA`), for the text model and the VLM.
- `Step5FusedQKVIndexerWithLoRA` slices LoRA B for the seven fused slices with the layer's own offsets (KV and indexer replication included).
- `Step5SparseIndexerIndexTPLinear` becomes a `ColumnParallelLinear` with its logical index-TP rank/size, so `Step5SparseIndexerWWithLoRA` slices B like the weight loader. Non-LoRA loading is unchanged.

## Validation

GB300, `tests/lora/test_step5_lora.py` (run by the existing `lora` CI step). For every TP rank, the full weight is loaded through the layer's own weight loader, and the LoRA B slices must equal the loaded rows exactly. The fused layer's forward must also return the full `[qkv | indexer]` output.

## Details

- `share_expert` is renamed with an idempotent regex. The VLM mapper and the text model mapper both apply it, and the old substring rule produced `.moe.moe.share_expert.`.
- LoRA is rejected with `moe_backend='deep_gemm_mega_moe'`: its experts are not `FusedMoE`, and its sequence-parallel mode gives the MLP linears `N/tp` tokens.
- `fully_sharded_loras` leaves these two layers without LoRA, like other custom linear subclasses.
