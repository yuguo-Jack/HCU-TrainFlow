# [ROCm][Perf][GLM-5.3-Flash] Mono decode layer for GLM-5.3-Flash on MI355X

[Upstream PR](https://github.com/vllm-project/vllm/pull/61662) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Opt-in specialized decode (`--monokernel`, or `--additional-config '{"decode_backend": "latency_specialized"}'`) for GLM-5.3-Flash (`amd/GLM-5.3-Flash-Quark-MXFP4`) on MI355X, in the layout of RFC #60904 under `vllm/models/glm5next/amd/specialized_decode/`. In a decode step of up to 8 rows (TP2: 4), each of the 41 MoE decoder layers is one persistent FlyDSL launch: 30 KDA layers and 11 sparse-attention layers, each with its FFN half. Everything else runs vLLM's layers. Off ROCm the switch is refused at startup; without it nothing changes.

## Claims

- Lower median TPOT than vLLM's decode on the same image and flags, wherever the kernels run (decode steps of up to 8 rows; TP2: 4):
  - TP8: 23–43% at 1k and 8k input, 1–8 concurrent; 21–35% at 64k and 128k, 1–4 concurrent.
  - TP4: 10–35% at 1k and 8k, 1–8 concurrent; 20–28% at 64k and 128k, 1–4 concurrent.
  - TP2: 16–27% at 1k and 8k, 1–4 concurrent; 4.6–21% at 64k and 128k, 1–4 concurrent.
- Past the kernels' width the step runs vLLM's decode in the `--monokernel` server too, and the two are level (within 1% on re-measurement with 4× the prompts).
- Agent serving (AgentX, 1 h per point, two runs per arm): time between tokens 1.30× faster at TP4 and 1.41× at TP8 for 1 user, 1.11× and 1.22× for 8 users.
- Accuracy parity: GSM8K paired McNemar over 3 runs per arm, p = 0.31 at TP4 and 0.12 at TP8 (no significant difference); GPQA-Diamond 0.912 vs 0.909 (mean of 3 runs each, TP4); NIAH 1.0 for both at 64k and 128k, fp8 e4m3 KV.
- Follows RFC #60904: model-owned code, default-deny refusals (every reason at once), one `plan()` per step, MRV2 only, weights and caches read in place. No core changes.
- Off ROCm it refuses cleanly: on B200 both switches stop the server at startup with one `ValueError`, and without them the model serves as before (GSM8K 0.931).

## Details

**Supported deployments** (everything outside this is refused, with every reason listed, at config, after load or at cache bind):

| | supported | otherwise |
| --- | --- | --- |
| hardware | MI355X (gfx950), whole unpartitioned GPUs | refused; off ROCm, startup error |
| tensor parallel | 2, 4, 8 | refused |
| concurrency | any | — |
| steps on the kernels | pure decode of 1, 2, 4 or 8 rows (TP2: 1, 2 or 4) | prefill, mixed and wider steps run vLLM's layers |
| speculative decoding | no (MTP verify steps: #63555, stacked on this PR) | refused |
| KV cache dtype | bf16, fp8 e4m3 | refused |
| KDA recurrent state | fp32 | refused |
| CUDA graphs | FULL, FULL_DECODE_ONLY, FULL_AND_PIECEWISE, eager | piecewise-only refused; PIECEWISE replays run vLLM's layers |
| model runner | V2 | refused |
| PP, DP, EP, EPLB, DCP, PCP | no | refused |
| LoRA, KV connectors, routed-expert capture, sleep mode, CPU weight offload, weight updates, prompt embeds | no | refused |
| checkpoint | `amd/GLM-5.3-Flash-Quark-MXFP4` (geometry checked), routed experts on the `AITER_MXFP4_MXFP4` MoE backend, attention projections FP8 block-128 or bf16 | refused after load |

**Layout.** Everything is under the model; outside it only the hooks in `common/model.py` and `common/specialized_decode.py` (the switch).

```
vllm/models/glm5next/
    common/specialized_decode.py   reads --monokernel / decode_backend (both platforms)
    common/model.py                the hooks; off ROCm a requested switch raises here
    amd/model_state.py             MRv2 ModelState: builds the decode after load, binds every KV cache
    amd/specialized_decode/
        runtime/                   refusals, plan(), cache binding, fail-stop
        mono/                      the kernels; mono/ffn/kernel.py builds all launch kinds
```

```python
step = None if decode is None else decode.plan(positions, intermediate_tensors)
for idx, layer in enumerate(self._active_layers, start=self.start_layer):
    kernel = step.layer(idx) if step is not None else None
    hidden_states, residual, post, comb = (kernel or layer)(
        positions, hidden_states, residual, post, comb
    )
```

**Design.**
- Weights are views of vLLM's loaded tensors (no copy), checked for shape, dtype and sharding when the decode is built. The KDA short-conv taps are a view of vLLM's fused q|k|v `conv1d` (#60991).
- `plan()` decides once per forward for all kernel layers from metadata every rank holds alike; under FULL graphs the decision is baked in at capture.
- `Glm5NextModelState` builds every width's launches after load, before memory profiling and graph capture, and binds them to each KV cache vLLM allocates.
- Every cross-CTA and cross-rank wait is bounded (60 s of device clock). An expired wait sets its stage's error word; after each step the output rank raises with the stage names and the other ranks exit, so a stalled peer stops the engine instead of hanging it.
- Numerics that differ from vLLM's path are listed in `runtime/spec.py` and logged at startup; all are at least as precise (expert inputs MXFP8 instead of MXFP4; W_UK / W_UV in bf16 instead of AITER FP4 / FP8 BMM; an e4m3 KV cache written as vLLM writes it and read back to bf16).

**Credit.** `mono/{ops,layout,packing}.py` and `mono/ffn/{kernel,layout}.py` are adapted from the GLM-5 MonoKernel of the FlyDSL and ATOM teams: the device code from ROCm/FlyDSL#1204 (@coderfeli), the host wrapper and the TP4, FP8-KV and FP4 paths from ROCm/ATOM#2435 (@XiaobingSuper) (Apache-2.0). Each file names its origin. New for GLM-5.3-Flash: the KDA path, the sparse-attention path with the kpool indexer, this model's mHC seams, bounded waits with error words, 64-bit cache-block bases.

**Limitations / follow-ups.**
- The kernel needs every compute unit of its GPUs; a co-tenant on the same GPUs can make waits expire, which stops the engine (RFC #60904 open question 3).
- Speculative decoding is refused here; #63555 adds MTP verify steps.
- At 128k context and 8 rows (TP4) the sparse-attention launch is ~2% slower than vLLM's separate kernels (indexer scoring over the full context); a faster long-context indexer stage is a follow-up.
- Startup adds a FlyDSL compile of 2 launch kinds × 3 widths (~46 s at TP4), skipped with a kept FlyDSL cache.
