# [Bugfix] [Tokenizer] Preserve Hub model identity when loading tokenizer snapshots

[Upstream PR](https://github.com/vllm-project/vllm/pull/63482) · state: closed · merged: True

## Original PR description



## Overview

This fixes a tokenizer-routing regression introduced by #60825, "[Performance]
Load HF tokenizers and processors from a local snapshot." Loading tokenizer
files from a local snapshot can hide the original Hugging Face repository ID
from Transformers.

In `transformers.models.auto.tokenization_auto`,
`MODEL_IDS_TO_TOKENIZERS_BACKEND` routes specific Hub IDs, including
`deepseek-ai/deepseek-coder-*`, to `TokenizersBackend` by matching
`config._name_or_path`. When the config is loaded from the snapshot, that is a
local path, the pattern never matches, and the class declared on the Hub
(`LlamaTokenizerFast`) is used instead, which drops every space. That can change the
input token IDs passed to the model and affect generated output.

The fix retains local-snapshot loading while restoring the original Hub ID on
a copy of the config passed to `AutoTokenizer`. The original config remains
unchanged, and the tokenizer continues to report the Hub ID as its
`name_or_path`.
