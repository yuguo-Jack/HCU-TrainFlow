# [4/N] Expose HiSparse cache metrics via KV connector stats

[Upstream PR](https://github.com/vllm-project/vllm/pull/56061) · state: closed · merged: True

## Original PR description

Alternative to #53782, reporting the same HiSparse hot-buffer stats through the existing `KVConnectorStats` pipeline instead of adding a new `finish_step` connector hook.

## What stays identical

- Kernel counters (`atomicAdd` in the CUDA kernels) and the swap-ordering changes in `runtime.py` are unchanged from the original PR.
- Same 2000-step async sampling interval with a CUDA event for D2H ordering.
- Same three Prometheus counters: `vllm:hisparse_hits`, `vllm:hisparse_lookups`, `vllm:hisparse_l3_lookups`.

## What changes

Instead of a new `finish_step` hook on `KVConnectorBase` (plus edits to scheduler, outputs, aggregator, loggers, and `stats.py`), the worker now exposes the snapshots through the existing hook:

```python
def get_kv_connector_stats(self) -> Optional[HiSparseKVConnectorStats]:
    ...
```

and the connector wires it into the standard pipeline:

```
worker.get_kv_connector_stats()          # HiSparseKVConnectorStats (list of snapshot deltas)
  -> scheduler picks it up in SchedulerStats
  -> build_kv_connector_stats()          # HiSparseKVConnectorStats.from_proxy_stats
  -> HiSparsePromMetrics.observe()       # vllm:hisparse_* counters
```

This is the same contract NIXL, the offloading connector, and mooncake already follow — transfer/cache telemetry goes through `KVConnectorStats` and the connector's `build_prom_metrics`, with zero core plumbing. HiSparse's hot-buffer residency counters are connector telemetry, so they fit the same slot the offloading connector uses for its allocation-failure/lookup-delay stats.

Net effect: the diff drops from 16 files to 9 and avoids changes to `base.py`, `model_runner.py`, `outputs.py`, scheduler, loggers, and core `stats.py`.

Also picks up two small cleanups over the original:

- Stats emission is gated on the connector being configured (the connector owns its stats, rather than gating on `attention_config` in the model runner).
- The sampling interval advances even on no-forward steps, so long prefill stretches don't stretch the sampling cadence.

Because the stats flow through `KVConnectorStats`, CLI logging comes for free:

```
INFO ... Cumulative HiSparse stats: hits=12 lookups=4 l3_lookups=64
```
