# [DSv4.1][PCP] Support adaptive DSpark verification

[Upstream PR](https://github.com/vllm-project/vllm/pull/64463) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Enable adaptive DSpark verification for DeepSeek-V4.1 with PCP, building on #47808 and #61555. PCP needs exact query lengths on the CPU, so this path agrees on each request's verification length before partitioning the batch.

## Claims

- Keep verification lengths consistent across TP/PCP ranks and CPU/GPU layouts.
- Improve C64 output throughput by **9.5%** in the matched H20 test below. Low-concurrency regressions are included.

## Validation

4× H20, TP1×PCP4/EP4, DSpark up to 5 tokens, Humming A8, shared Engram, 32K chunk, max 64 sequences, `FULL_AND_PIECEWISE`. Same source, runtime and launch configuration; only `enable_adaptive_verification` changes.

`vllm bench serve`: fixed real GSM8K prompts, 600–710 input tokens, forced 512-token output, temperature 1, warmed prefix cache (~94% hit). Three repeats; output throughput is mean (min–max), TPOT is the mean. C1 uses 32 requests per repeat; other points use 256.

| Concurrency | Fixed output tok/s | Adaptive output tok/s | Change | TPOT ms, fixed → adaptive |
|---|---:|---:|---:|---:|
| 1 | 150.4 (148.8–151.5) | 146.6 (142.3–149.5) | -2.6% | 6.57 → 6.75 |
| 16 | 1,286.0 (1,268.9–1,295.1) | 1,256.7 (1,241.0–1,265.8) | -2.3% | 12.00 → 12.30 |
| 32 | 1,825.1 (1,795.8–1,844.9) | 1,862.5 (1,856.7–1,865.7) | +2.0% | 16.64 → 16.23 |
| 64 | 2,334.6 (2,315.7–2,356.4) | 2,556.4 (2,544.2–2,573.3) | +9.5% | 25.58 → 23.14 |

This is a short-input math workload, not the original internal SPEED-Bench subset or a long-context throughput claim.

- **Full GSM8K:** 1,319 questions, five-shot, temperature 0, C64, normal stopping. Fixed: **1,223/1,319 (92.72%)**; adaptive: **1,230/1,319 (93.25%)**. All evaluation prompt hashes match between arms. This does not establish an accuracy improvement.
- All benchmark requests completed, with no preemptions; runtime logs confirm FULL graph execution. Initial instrumented requests also passed `VLLM_GPU_SYNC_CHECK=error` and exercised trimmed budgets with matching allocations on all four ranks.
- `pytest tests/v1/spec_decode/test_adaptive_verification.py tests/v1/worker/test_gpu_pcp_manager.py -q`: **136 passed**. Four-GPU TP1/PCP4 and TP2/PCP2 layout/consensus checks and pre-commit passed.
- One adaptive GSM8K case is added to the existing PCP CI job. Upstream B200 validation is pending.

<details>
<summary>Benchmark reproduction</summary>

Build `prompts.jsonl` from the first 256 GSM8K test questions, prefixing each with the first five training question/answer pairs. Format each pair as `Question: {question}\nAnswer: {answer}\n\n`, then append `Question: {test_question}\nAnswer:`. Store each resulting string under `prompt`.

Warm up with 64 requests at C32 and 256 output tokens, then prime all 256 prompts with one output token. Use the same cache salt in both fresh servers. Run this at C1/16/32/64, using seeds 1234/1235/1236:

```bash
vllm bench serve --backend openai --endpoint /v1/completions \
  --base-url http://127.0.0.1:8000 --model dsv41-pcp \
  --tokenizer /model --tokenizer-mode deepseek_v41 \
  --dataset-name custom --dataset-path prompts.jsonl \
  --custom-output-len 512 --num-prompts 256 --max-concurrency 64 \
  --temperature 1 --ignore-eos --disable-shuffle --skip-chat-template \
  --extra-body '{"seed":1234,"cache_salt":"pcp-adaptive-decode-v1"}' \
  --save-result --save-detailed
```

Use 32 prompts at C1. Both arms use the same target capture sizes: `1,2,4,5,6,8,10,12,16,20,24,32,40,48,64,80,96,128,160,192,256,320,384`.

</details>

## Details

Reuse the host confidences already copied by adaptive DSpark for the budget and per-request draft counts, then broadcast those counts across TP and PCP. Price the target using the largest PCP-local batch; the drafter remains replicated. Mixed prefill batches retain full verification, and the non-PCP allocation path is unchanged. The tradeoffs are stale per-request confidence and CPU collective overhead.

Unlike #62769, which excludes PCP, this supplies the exact host layout required by PCP. Depends on #61555; its changes remain visible until it merges. [Adaptive implementation only](https://github.com/xijiaat/vllm/commit/404fade8). Local H20 validation used complete main-based Python source plus #61554 for Engram sharing on the existing Artifactory binary runtime.
