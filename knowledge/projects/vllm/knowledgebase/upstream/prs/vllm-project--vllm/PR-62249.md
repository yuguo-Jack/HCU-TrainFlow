# [Bugfix] Respect max_model_len for Clef SystemOne reads

[Upstream PR](https://github.com/vllm-project/vllm/pull/62249) · state: open · merged: False

## Original PR description

## Overview

Make Clef SystemOne pooling reads respect the engine's resolved `max_model_len`
and reject oversized complete prompts instead of silently truncating the state.

## Claims

- `ClefFlashStrategy` has no additional 16,384-token cap. The complete prompt,
  including expanded media, questions, options and fixed prompt tokens, must fit
  `max_model_len`. Exactly-at-limit pooling requests reserve no generation tokens.
- Oversized requests return the existing HTTP 400 response before `engine.encode`.
  Callers must shorten/split the input or configure a supported larger context.
- Clef media preprocessing uses the existing processor-only cache path, as
  `NextTokenStrategy` already does, so a rejected prompt cannot prime the sender
  cache for media the engine never received.
- Clef-Omni keeps its 64,000-token reference cap, state truncation, prompt layout
  and relative schema spans. No new CLI/API option or engine plugin is added.

That case starts with empty caches and a new synthetic image. The first oversized
request returns HTTP 400 without encoding; the same image with a shorter state
then reaches the real receiver with its actual pixel tensor, and a repeated
accepted request preserves the pixels and prompt. Disabling only
`skip_mm_cache=True` makes the first shorter retry raise a real
`MultiModalCacheMissError`: the rejected request primed the sender while the
receiver remained empty. This negative control tests the regression's
effectiveness; the previously posted implementation already contains the fix.

This is CPU component validation, not native model inference or cross-process IPC
validation. It does not establish Clef decision quality, GPU correctness, video
inference, latency or media-transfer performance.

## Details

The shared constructor previously selected `min(MAX_LENGTH, max_model_len)`;
Clef set `MAX_LENGTH=16384`, then the shared encoder sliced away the remaining
state. Move that state policy into a small base helper and override it for Clef.
The encoder already receives the expanded media prefix, so the same accounting
includes media without introducing a second processor or prompt format.

This intentionally changes Clef's overflow behavior from successful truncation
to HTTP 400. Clef-Omni remains unchanged. Processor-only caching can change media
transfer costs; native retry/performance verification is still required.

Open PR searches for `Clef context`, `Clef truncation`, `Clef max_model_len` and
`SystemOne` on 2026-10-17 found no PR implementing this fix. Related SystemOne
generation optimizations do not address Clef's pooling context cap. The publication prechecks on 2026-10-18 found no duplicate fix.
