# [Perf] Add opt-in DeepGEMM candidate-only indexer decode on SM90

[Upstream PR](https://github.com/vllm-project/vllm/pull/65610) · state: closed · merged: False

## Original PR description


## Overview

Integrate DeepGEMM candidate-only indexer decode for DeepSeek V4.1 on SM90/Hopper. Candidate-consuming layers score selected blocks directly from the paged FP8 cache, avoiding full-context logits computation and masking.

Related to #61830. Existing approaches include gather-then-score in #62000 and direct Triton scoring in #62463. This implementation integrates a native SM90 DeepGEMM kernel through the existing indexer_sparse_logits option. 

## Claims

- Enable candidate-only decode with --attention-config '{"indexer_sparse_logits": true}'; the SM90 default remains disabled.
- Produce compact FP32 logits and reuse existing top-k selection and index remapping.
- Share candidate preparation and scheduling metadata across consumer layers within a decode step.
- Support CUDA graphs and native speculative decode layouts, with scratch buffers sized for decode capacity.

## Validation

Recorded local validation used H20 GPUs and the companion DeepGEMM implementation.

.venv/bin/python -m pytest \
  tests/model_executor/layers/test_mla_short_prefill_indexer.py \
  tests/v1/attention/test_indexer_native_next_n.py \
  -k 'sm90 or candidate_blocks_to_sparse_indices' -q

Result: 28 passed, 1 skipped. The skipped case exceeds cooperative top-k's 64-row limit.

DeepGEMM numerical, CUDA graph, and large-offset checks passed. Compute Sanitizer reported no errors in the tested cases. Applicable pre-commit checks passed.

Kernel measurements used FP8 H=32/D=128, 48 query rows, 16,384 candidate positions, and top-k=512. Timing used CUPTI, CUDA graphs, cold L2, and three repeats of 25 samples.

| Workload | ALL | Candidate-only | Speedup |
|---|---:|---:|---:|
| 128K context, scorer | 223.01 µs | 59.90 µs | 3.72× |
| 128K context, four consumer layers including preparation, top-k and remapping | 1177.60 µs | 291.14 µs | 4.04× |
| 1M context, four consumer layers including preparation, top-k and remapping | 9633.92 µs | 308.29 µs | 31.25× |


End-to-end validation used DeepSeek-V4.1-Flash-1017 on 8× H20, TP8/EP8, prefix caching, and five speculative tokens. For the 128K prefix-hit workload at concurrency 8, isolated A/B/A runs measured mean ITL of 14.476 / 14.132 / 14.459 ms, a 2.26–2.37% reduction.

|---|---:|---:|
| GSM8K | 1217/1319 | 1218/1319 |
| HumanEval, 3072-token output limit | 154/164 | 152/164 |
