# [Rust Frontend] Support --max-log-len

[Upstream PR](https://github.com/vllm-project/vllm/pull/64223) · state: closed · merged: True

## Original PR description

## Overview

Support `--max-log-len` on the Rust frontend, which a placeholder rejected at startup. It bounds the output text and token IDs that `--enable-log-outputs` logs, like the Python frontend's `RequestLogger`.

## Claims

- `--max-log-len N` is accepted on `vllm-rs serve` and on the Python launcher path.
- Complete and delta output logs on chat, completions and generate log at most the first `N` characters of text (Unicode scalar values, like Python's `str` slicing) and the first `N` token IDs.

## Validation

Commands from `.buildkite/scripts/run-rust-frontend-cargo-ci.sh` (`style-clippy` and `test`), run from the repo root on this branch:


- `routes::tests::max_log_len_truncates_logged_outputs_and_token_ids`: a streamed chat request with `--max-log-len 1` and delta logging logs every delta and the complete output cut to one character and one token ID; it covers the cases of Python's `test_request_logger_log_outputs_with_truncation`, and fails with the truncation removed.
- `routes::tests::max_log_len_counts_characters`: `"中😀a"` with limits 2, 0 and 100 logs `"中😀"`, `""` and the full text, and the token IDs `[1, 2]`, `[]` and all three, like Python's slices.
- `cli::tests::frontend_args_json_passes_output_logging_into_config` also checks `max_log_len`.

## Details

Python's `RequestLogger` (`vllm/entrypoints/serve/utils/request_logger.py`) truncates everything it logs about a request to `max_log_len`: the prompt and prompt token IDs, the request body, and the output text and token IDs (`log_outputs`). The Rust frontend logs generated outputs for `--enable-log-outputs` since vllm-project/vllm#63769, so the flag now has a Rust consumer.

- `ApiServerOptions::log_outputs` becomes an `OutputLogConfig`: which outputs to log (the existing `OutputLogging` mode) plus `max_log_len`, built once from the CLI, with the same `logs_complete()`/`logs_deltas()` predicates.
- Its `log` method (formerly the free `output_log::log_output`, same body and comments) applies the bound. Call sites pass only the event: kind, text, token IDs and finish reason.

**Layering.** Like Python's `RequestLogger(max_log_len=...)`, the bound is fixed at construction in the one value that owns output logging, and `OutputLogConfig::log` is the only place the Rust frontend logs request content. The handlers and the chat `StreamDeltaLog` hold that value instead of threading `max_log_len` next to it. The Rust frontend does not log prompts or request bodies yet, so those parts of Python's truncation have nothing to apply to; whichever change adds prompt logging should apply the same bound.

**Deviation.** Python accepts a negative `--max-log-len` and slices from the end (`s[:-3]`); the Rust frontend takes a non-negative integer and rejects a negative value at startup.
