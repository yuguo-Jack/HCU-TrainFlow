# [ROCm][Perf] Request fp32 output from the AITER router GEMM (otype)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61687) · state: open · merged: False

## Original PR description

**Depends on #50535.** 

## Purpose

#50535 never runs AITER's fp32-output router kernels:
- `tgemm.mm(x, weight, None)` sets `bias`, not `otype`. The GEMM always runs with bf16 output and is then cast to fp32.
- The tuned-shape check only looks at bf16-output rows.

This PR passes `otype=out_dtype`, keys `is_bf16_gemm_tuned(N, K, out_dtype)` by output dtype, and repeats the check in `GateLinear.set_out_dtype`.

**Behaviour change:** for an fp32 gate, a shape tuned only for bf16 output now uses the existing hipBLASLt `torch.mm(out_dtype=fp32)` tier. Shapes with fp32-output rows (e.g. `128x6144`, `256x5120`) use AITER. The K3 router (`896x7168`) gets fp32-output rows from ROCm/aiter#6494.

## Test Plan

```bash
pytest -q tests/kernels/test_gate_linear_rocm_dispatch.py
```
New tests check that the op passes `otype` and that `set_out_dtype` repeats the tuned check. The hardware test now uses `128x6144` with only its M=1 fp32-output row.

## Test Result

CPU: 41 passed (5 hardware cases deselected). The new tests fail on #50535 alone.
