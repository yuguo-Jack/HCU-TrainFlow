# [Perf] Batch the Whisper conv stem and CUDA-graph the fixed mel

[Upstream PR](https://github.com/vllm-project/vllm/pull/62491) · state: open · merged: False

## Original PR description

## Overview

Batch Whisper's conv stem and CUDA-graph only the fixed full-chunk mel. Fixes #62352.

This draft is independent of #62413, which is someone else's combined draft for #62352 and #62355. This PR does not move log-mel onto the GPU worker.

## Claims

- Equal-length Whisper clips run the conv stem in one launch via `_conv_embed`. A rank-3 tensor is one conv. A list of equal-shape rank-3 chunks is concatenated (the Moss call). A list of equal-shape rank-2 clips is stacked (Kimi). Unequal lengths and a bare rank-2 tensor stay on the per-item loop. Unequal clips are not time-padded.
- `WhisperForConditionalGeneration` opts into encoder CUDA graphs for the static full-chunk mel only. Stock geometry gives `mel_len = max_source_positions * conv2.stride` (1500 → 3000). The budget is `(max_source_positions, max_num_batched_tokens)`, not `max_model_len`. The protocol stays off `WhisperEncoder`.
- Capture stays off when LoRA is set, the conv stem is not the stock geometry, or FP8 encoder attention is dynamic. `execute` returns None when graphs were not captured or the mel is not that static length. A missing budget graph still raises.

## Validation

- `tests/models/multimodal/generation/test_whisper_encoder_cudagraph.py` covers stem batching, the odd-T pad mismatch (last-frame abs diff > 1e-3 with both biases at 0), cat vs stack, budget width `(8, 16)` → batch 1 and 2, capture refusal, and that the protocol is not on the encoder. CUDA replay (one clip selects budget 8 width 1, two clips select 16 width 2, a `[16]`-only manager replays one zero-mel suffix row, mel time 15 returns None) is in the same file and skips without a device graph.
- A local torch 2.5.1 CPU script of this stem math showed batch-1 `torch.equal`, batch>1 max abs diff about `2.4e-7`, and an odd-T zero-pad last-frame diff well above `1e-3`. The same routing assertions passed in that standalone copy. The committed tests import the real helper and were not executed here: this machine's torch 2.5.1 cannot import current vLLM, and no CUDA graph was captured. No speedup number is claimed.

## Details

`WhisperEncoder.forward` launched `gelu(conv1)` / `gelu(conv2)` once per item. Equal-length full chunks already match a batched stem up to tolerance, so the loop is a launch-per-item cost. A CUDA graph is valid only for the fixed full-chunk mel: the encoder has no key-padding mask, and `EncoderCudaGraphManager` pads batch dimension 0, not time. On odd T, conv2's last window reads an implicit zero. Right-padding the mel replaces that zero and changes the last frame.

The graph is opt-in on `WhisperForConditionalGeneration` only. Kimi calls `WhisperEncoder.forward` and inherits the batched stem. Ultravox replaces the encoder forward and must not inherit the protocol. MiniCPM and Moss stay off it. Two new `SupportsEncoderCudaGraph` methods default to True, so Gemma4 and MiniCPM-O 2.6 image/video graphs keep capturing and replaying. `execute` returns None when capture was skipped or the batch is not a static full chunk; both runners already fall back to `embed_multimodal`. `assert graph_output is not None` is unchanged.

Default `max_num_batched_tokens` is 2048, so auto budgets are `[1500, 2048]` and `max_batch_size` is 1. Each default graph holds one full clip. The 2048 graph is an unused width-1 duplicate because round-up selects 1500. Two clips need `max_num_batched_tokens >= 3000`. A wider graph replays a zero-mel suffix row as its own sequence (`cu_seqlens` stays None). Scatter drops that suffix.

Whisper's `max_model_len` is the decoder target length, often 448. Clamping the encoder budget with it makes `min_budget > max_budget` and the manager raises. This budget does not do that.

First cut. AI assistance (Grok) was used. #62355 is not on this branch.
