# [Bugfix][Quantization] Keep fp32 weight_scale during batch-invariant FP8 dequantization

[Upstream PR](https://github.com/vllm-project/vllm/pull/64480) · state: open · merged: False

## Original PR description

## Overview

When `VLLM_BATCH_INVARIANT=1` takes the BF16 dequantization fallback (`not fp8_scaled_mm_is_batch_invariant(self.fp8_linear)`), `Fp8LinearMethod.apply`, `Fp8PerTensorOnlineLinearMethod.apply`, and `Fp8PtpcOnlineLinearMethod.apply` cast `layer.weight_scale` from `float32` to `bfloat16` (or `x.dtype`) before multiplying by `layer.weight`. When this fallback runs eagerly without Inductor (for example under `--enforce-eager`, `TORCH_COMPILE_DISABLE=1`, `-O0`, or compilation mode `NONE`), it double-rounds weights through `RN_bf16(w * RN_bf16(s))` instead of computing the product in `float32` and casting it once to `bfloat16` (`RN_bf16(RN_fp32(w * s))`). Under default `torch.compile` (`emulate_precision_casts=False`), Inductor fuses the elementwise chain and already computes `RN_bf16(RN_fp32(w * s))`, so this patch makes eager execution match the weights and per-layer outputs that compiled runs already produce.

No open issue or PR changes this scale cast (`gh pr list --repo vllm-project/vllm --state open --search "VLLM_BATCH_INVARIANT fp8 weight_scale"`); `#60163` updates `fp8_scaled_mm_is_batch_invariant` and weight-processing code in the same files without changing the scale cast (merged into `main`, included here through `dff26898`).

**AI assistance disclosure:** AI assistance (Antigravity / Gemini) was used during the investigation and preparation of this PR.

## Claims

- Dequantizes `layer.weight * layer.weight_scale` in `float32` and casts the product once to `torch.bfloat16` / `x.dtype` via `dequant_fp8_weight` in the batch-invariant fallback paths of `Fp8LinearMethod.apply`, `Fp8PerTensorOnlineLinearMethod.apply`, and `Fp8PtpcOnlineLinearMethod.apply`: in eager mode on FP8-capable CUDA/ROCm GPUs, a single fused Triton kernel (`_dequant_fp8_weight_kernel`) loads FP8 weights, multiplies by the `float32` scale in registers, and stores the rounded output directly across scalar, per-row, and PTPC scale layouts; under `torch.compile` (where Inductor fuses the expression into one kernel) and on other platforms (including CUDA before SM89), it keeps `(weight.to(torch.float32) * weight_scale.to(torch.float32)).to(out_dtype)` with bitwise-identical output.
- Eliminates intermediate `bfloat16` scale rounding in eager execution (up to $2^{-8}$ relative error on `weight_scale`, which shifts `122 / 252` (48%) of non-zero finite FP8 E4M3 codes by 1 BFloat16 ULP for scale `0x3a9b4c70` and affects 21-25% of non-zero weights across `RedHatAI/Qwen2-1.5B-Instruct-FP8`, `Forturne/Qwen3-0.6B-FP8`, and online-quantized `Qwen/Qwen3-1.7B`, up to 68% in a single layer).
- Aligns eager fallback weights and per-layer outputs with default `torch.compile` (`FULL_AND_PIECEWISE`), which is bitwise unchanged by this patch.

## Validation

Standalone snippet showing the intermediate scale-rounding mismatch on `RedHatAI/Qwen2-1.5B-Instruct-FP8` (`model.layers.5.mlp.down_proj`, `weight_scale` bits `0x3a9b4c70`):

```python
import torch

# Scale from RedHatAI/Qwen2-1.5B-Instruct-FP8 model.layers.5.mlp.down_proj
scale_f32 = torch.tensor([0x3A9B4C70], dtype=torch.int32).view(torch.float32)
codes = torch.arange(256, dtype=torch.uint8).view(torch.float8_e4m3fn)

# Current eager fallback: casts both to bfloat16 before multiplying
dequant_current = codes.to(torch.bfloat16) * scale_f32.to(torch.bfloat16)

# Fixed fallback: compute the product in float32, then cast once to bfloat16
dequant_fixed = (codes.to(torch.float32) * scale_f32.to(torch.float32)).to(torch.bfloat16)

finite = torch.isfinite(dequant_fixed) & (codes.to(torch.float32) != 0)
mismatches = (dequant_current.view(torch.int16) != dequant_fixed.view(torch.int16)) & finite
print(f"Mismatched non-zero finite FP8 codes: {int(mismatches.sum())} / {int(finite.sum())}")
```

## Details

Every finite `float8_e4m3fn` value is exact in both `bfloat16` and `float32`, whereas per-tensor and per-channel `weight_scale` tensors in FP8 checkpoints (and online FP8 quantization) are `float32`. Casting `layer.weight_scale` to `bfloat16` before multiplying rounds the lower 16 significand bits of `weight_scale` prior to scaling `layer.weight` whenever the fallback executes eagerly. Performing the product in `float32` and casting the result once to `torch.bfloat16` (or `x.dtype` in `Fp8PtpcOnlineLinearMethod`) preserves the `float32` scale (with a residual `5.5e-6` mis-rounding rate against exact `RN_bf16(w * s)` across random `float32` bit patterns in `[2^-14, 2^-4)` when the 28-bit exact product rounds in `float32` onto a `bfloat16` midpoint, vs 22.1% of codes when pre-rounding `weight_scale` to `bfloat16`).

In eager mode, an unfused PyTorch `float32` product (`f77be818` / `dff26898`) materializes the dequantized weight in `float32` before the cast (~19 bytes of HBM traffic per element across 3 kernels, vs ~7 bytes across 2 kernels on `main`), so transient memory grows 2.25-2.5x (for example 224 MiB -> 560 MiB for a 4096x14336 weight), a plain PyTorch dequantize-plus-GEMM call takes 1.29-1.47x as long (H100, the `main` and patched expressions in plain PyTorch, 16 and 2048 tokens), and `vllm bench serve --enforce-eager` output token throughput on H100 (`VLLM_BATCH_INVARIANT=1`, `--linear-backend torch`) drops from `2822.19` tok/s (`71.57` ms mean TPOT) on `main` (`e18e2c70`) to `2220.17` / `2237.43` tok/s (`92.01` / `91.93` ms mean TPOT) at `dff26898` on `neuralmagic/Meta-Llama-3-8B-Instruct-FP8` (and from `2660.95` tok/s / `76.10` ms mean TPOT on `main` `e18e2c70` to `2114.37` tok/s / `96.69` ms mean TPOT at `dff26898` on `Qwen/Qwen3-8B` with `--quantization fp8_per_channel`). Commit `6fee2178` eliminates that eager-mode cost by fusing the FP8 load, `float32` scale multiply, and `out_dtype` store into a single Triton kernel (`_dequant_fp8_weight_kernel` behind `dequant_fp8_weight`), reading the FP8 weight once and writing the `out_dtype` output once (~3 bytes per element, with no `float32` intermediate allocation): in `vllm bench serve --enforce-eager` on H100 at `6fee2178`, output token throughput increases to `4415.64` / `4403.70` tok/s (`41.17` / `41.14` ms mean TPOT) on `neuralmagic/Meta-Llama-3-8B-Instruct-FP8` and `3842.16` tok/s (`49.25` ms mean TPOT) on `Qwen/Qwen3-8B` (`--quantization fp8_per_channel`). Compiled runs (`torch.compiler.is_compiling()`) keep the PyTorch `float32` expression so Inductor fuses the cast and the multiply into one kernel with the same loads and stores as before (`4731.02` tok/s on `main` `e18e2c70`, `4760.99` / `4599.80` / `4733.85` tok/s at `dff26898`, and `4742.43` / `4639.07` / `4739.35` tok/s at `6fee2178` on `neuralmagic/Meta-Llama-3-8B-Instruct-FP8`; `4525.28` tok/s on `main` `e18e2c70`, `4526.97` / `4410.76` / `4526.33` / `4421.44` tok/s at `dff26898`, and `4389.27` / `4533.36` / `4521.45` / `4521.44` tok/s at `6fee2178` on `Qwen/Qwen3-8B` with `--quantization fp8_per_channel`).

```python
"""VLLM_BATCH_INVARIANT=1: the BF16 fallback of FP8 linear layers rounds weight_scale to bf16 first, so
each dequantized weight is bf16(w * bf16(s)) instead of bf16(w * s). The script reads the weight back
through quant_method.apply() with an identity input (exact) and compares it with bf16(w * s)."""
import os, sys, tempfile
os.environ["VLLM_BATCH_INVARIANT"] = "1"
import torch
from vllm.config import KernelConfig, ModelConfig, VllmConfig, set_current_vllm_config
from vllm.config.quantization import resolve_quantization_config
from vllm.distributed import init_distributed_environment, initialize_model_parallel
from vllm.model_executor.kernels.linear import fp8_scaled_mm_is_batch_invariant
from vllm.model_executor.layers.linear import ReplicatedLinear
from vllm.model_executor.layers.quantization.fp8 import Fp8Config
from vllm.model_executor.layers.quantization.online.base import OnlineQuantizationConfig
from vllm.utils.torch_utils import set_default_torch_dtype

def bf16_round(p):  # float64 -> nearest bfloat16 value, ties to even (normal range)
    m, e = torch.frexp(p)
    return torch.ldexp(torch.round(m * 256), e - 8)

def hexbits(x, dtype):  # bit pattern of a bfloat16 or float32 number
    itype, mask = (torch.int16, 0xFFFF) if dtype == torch.bfloat16 else (torch.int32, 0xFFFFFFFF)
    return f"0x{torch.tensor(x.item(), dtype=dtype).view(itype).item() & mask:x}"

def build(quant_config, weight, scale=None):  # weight: [out, in], as stored in a checkpoint
    with set_default_torch_dtype(torch.bfloat16):
        layer = ReplicatedLinear(weight.shape[1], weight.shape[0], bias=False, quant_config=quant_config)
    layer.weight.weight_loader(layer.weight, weight)  # the online methods quantize here
    if scale is not None:  # FP8 checkpoint: load its float32 scale, post-process like the loader
        layer.weight_scale.weight_loader(layer.weight_scale, scale)
        layer.quant_method.process_weights_after_loading(layer)
    assert not fp8_scaled_mm_is_batch_invariant(layer.quant_method.fp8_linear)  # -> BF16 fallback
    return layer

def check(layer):
    w, s = layer.weight.double(), layer.weight_scale.double().reshape(1, -1)  # w: [in, out]
    got = layer.quant_method.apply(layer, torch.eye(w.shape[0], dtype=torch.bfloat16)).double()
    want = bf16_round(w * s)  # w * s is exact in float64 (at most 4 + 24 significant bits)
    bad = (got != want).nonzero().tolist()
    text = f"{type(layer.quant_method).__name__} {len(bad)}/{got.numel()} words"
    if bad:
        (i, j), b16 = bad[0], lambda x: hexbits(x, torch.bfloat16)
        text += (f" (w={w[i, j].item():g} s={hexbits(s[0, j % s.shape[1]], torch.float32)}:"
                 f" got {b16(got[i, j])}, want {b16(want[i, j])})")
    return text, len(bad)

if __name__ == "__main__":
    torch.set_default_device("cuda")
    # The torch FP8 kernels are not batch-invariant, so apply() takes the BF16 fallback on SM90 as well
    cfg = VllmConfig(model_config=ModelConfig(dtype="bfloat16"), kernel_config=KernelConfig(linear_backend="torch"))
    with set_current_vllm_config(cfg):
        init_distributed_environment(1, 0, f"file://{tempfile.mkstemp()[1]}", 0)
        initialize_model_parallel(1, 1)
        codes = torch.arange(256, dtype=torch.uint8, device="cpu")
        codes[(codes & 0x7F) == 0x7F] = 0  # every finite float8_e4m3fn value (NaN codes -> 0)
        # weight_scale of model.layers.5.mlp.down_proj in RedHatAI/Qwen2-1.5B-Instruct-FP8
        scale = torch.tensor([0x3A9B4C70], dtype=torch.int32, device="cpu").view(torch.float32)
        weight = torch.randn(64, 256, device="cpu", generator=torch.Generator().manual_seed(0)).bfloat16()
        online = lambda scheme: OnlineQuantizationConfig(resolve_quantization_config(scheme, None))
        results = [check(build(Fp8Config(), codes.view(torch.float8_e4m3fn).reshape(16, 16), scale)),
                   check(build(online("fp8_per_tensor"), weight)), check(build(online("fp8_per_channel"), weight))]
    torch.distributed.destroy_process_group()
    summary = "; ".join(text for text, _ in results)
    if any(n for _, n in results):
        print(f"FAIL: dequantized FP8 weights != bf16(w * s) with VLLM_BATCH_INVARIANT=1: {summary}")
        sys.exit(1)
    print(f"PASS: every dequantized FP8 weight == bf16(w * s): {summary}")
```

Server command: `VLLM_BATCH_INVARIANT=1 vllm serve neuralmagic/Meta-Llama-3-8B-Instruct-FP8 --host 127.0.0.1 --port 18564 [--enforce-eager] --linear-backend torch`

Client command: `vllm bench serve --model neuralmagic/Meta-Llama-3-8B-Instruct-FP8 --host 127.0.0.1 --port 18564 --dataset-name random --random-input-len 1024 --random-output-len 256 --num-prompts 256 --request-rate inf --ignore-eos --seed 0 --num-warmups 16`

Benchmarked in both eager mode (`--enforce-eager`) and default compiled mode (no `--enforce-eager`) across two rounds (Round 2 ran in reverse order).

- **Eager mode (`--enforce-eager`):** Output token throughput is about 19% lower with the PR (`2757.71` / `2763.02` tok/s on `main` vs `2226.22` / `2255.13` tok/s on the PR across the two rounds) and mean TPOT increases from `71.6` ms to `91.9` ms (`71.63` / `71.48` ms on `main` vs `91.97` / `91.85` ms on the PR), likely because uncompiled execution materializes the `float32` weight upcast and product before casting to `bfloat16` (no profiler trace was collected).
- **Default compiled mode (no `--enforce-eager`):** Inductor generates an equivalent fused Triton kernel for both trees (it differs only in the position of a no-op fp32 cast; the PTX is identical, as checked from the compile caches) (with `emulate_precision_casts=False`, it drops `main`'s `bfloat16` cast of `weight_scale`), so the compiled comparison does not exercise the fix and the bug affects eager execution only in the default compile configuration. Throughput in compiled mode is unchanged within run-to-run noise (`4076.80` / `4555.51` tok/s on `main` vs `4368.02` / `4732.56` tok/s on the PR).

```python
"""VLLM_BATCH_INVARIANT=1: the BF16 fallback of FP8 linear layers rounds weight_scale to bf16 first, so
each dequantized weight is bf16(w * bf16(s)) instead of bf16(w * s). The script reads the weight back
through quant_method.apply() with an identity input (exact) and compares it with bf16(w * s)."""
import os, sys, tempfile
os.environ["VLLM_BATCH_INVARIANT"] = "1"
import torch
from vllm.config import KernelConfig, ModelConfig, VllmConfig, set_current_vllm_config
from vllm.config.quantization import resolve_quantization_config
from vllm.distributed import init_distributed_environment, initialize_model_parallel
from vllm.model_executor.kernels.linear import fp8_scaled_mm_is_batch_invariant
from vllm.model_executor.layers.linear import ReplicatedLinear
from vllm.model_executor.layers.quantization.fp8 import Fp8Config
from vllm.model_executor.layers.quantization.online.base import OnlineQuantizationConfig
from vllm.utils.torch_utils import set_default_torch_dtype

def bf16_round(p):  # float64 -> nearest bfloat16 value, ties to even (normal range)
    m, e = torch.frexp(p)
    return torch.ldexp(torch.round(m * 256), e - 8)

def hexbits(x, dtype):  # bit pattern of a bfloat16 or float32 number
    itype, mask = (torch.int16, 0xFFFF) if dtype == torch.bfloat16 else (torch.int32, 0xFFFFFFFF)
    return f"0x{torch.tensor(x.item(), dtype=dtype).view(itype).item() & mask:x}"

def build(quant_config, weight, scale=None):  # weight: [out, in], as stored in a checkpoint
    with set_default_torch_dtype(torch.bfloat16):
        layer = ReplicatedLinear(weight.shape[1], weight.shape[0], bias=False, quant_config=quant_config)
    layer.weight.weight_loader(layer.weight, weight)  # the online methods quantize here
    if scale is not None:  # FP8 checkpoint: load its float32 scale, post-process like the loader
        layer.weight_scale.weight_loader(layer.weight_scale, scale)
        layer.quant_method.process_weights_after_loading(layer)
    assert not fp8_scaled_mm_is_batch_invariant(layer.quant_method.fp8_linear)  # -> BF16 fallback
    return layer

def check(layer):
    w, s = layer.weight.double(), layer.weight_scale.double().reshape(1, -1)  # w: [in, out]
    got = layer.quant_method.apply(layer, torch.eye(w.shape[0], dtype=torch.bfloat16)).double()
    want = bf16_round(w * s)  # w * s is exact in float64 (at most 4 + 24 significant bits)
    bad = (got != want).nonzero().tolist()
    text = f"{type(layer.quant_method).__name__} {len(bad)}/{got.numel()} words"
    if bad:
        (i, j), b16 = bad[0], lambda x: hexbits(x, torch.bfloat16)
        text += (f" (w={w[i, j].item():g} s={hexbits(s[0, j % s.shape[1]], torch.float32)}:"
                 f" got {b16(got[i, j])}, want {b16(want[i, j])})")
    return text, len(bad)

if __name__ == "__main__":
    torch.set_default_device("cuda")
    # The torch FP8 kernels are not batch-invariant, so apply() takes the BF16 fallback on SM90 as well
    cfg = VllmConfig(model_config=ModelConfig(dtype="bfloat16"), kernel_config=KernelConfig(linear_backend="torch"))
    with set_current_vllm_config(cfg):
        init_distributed_environment(1, 0, f"file://{tempfile.mkstemp()[1]}", 0)
        initialize_model_parallel(1, 1)
        codes = torch.arange(256, dtype=torch.uint8, device="cpu")
        codes[(codes & 0x7F) == 0x7F] = 0  # every finite float8_e4m3fn value (NaN codes -> 0)
        # weight_scale of model.layers.5.mlp.down_proj in RedHatAI/Qwen2-1.5B-Instruct-FP8
        scale = torch.tensor([0x3A9B4C70], dtype=torch.int32, device="cpu").view(torch.float32)
        weight = torch.randn(64, 256, device="cpu", generator=torch.Generator().manual_seed(0)).bfloat16()
        online = lambda scheme: OnlineQuantizationConfig(resolve_quantization_config(scheme, None))
        results = [check(build(Fp8Config(), codes.view(torch.float8_e4m3fn).reshape(16, 16), scale)),
                   check(build(online("fp8_per_tensor"), weight)), check(build(online("fp8_per_channel"), weight))]
    torch.distributed.destroy_process_group()
    summary = "; ".join(text for text, _ in results)
    if any(n for _, n in results):
        print(f"FAIL: dequantized FP8 weights != bf16(w * s) with VLLM_BATCH_INVARIANT=1: {summary}")
        sys.exit(1)
    print(f"PASS: every dequantized FP8 weight == bf16(w * s): {summary}")
```
