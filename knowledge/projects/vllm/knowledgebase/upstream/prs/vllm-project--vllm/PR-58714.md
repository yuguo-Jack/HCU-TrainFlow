# [Perf] Optimize GLM5.x-MXFP4×FP8_BLOCK prefill on sm90

[Upstream PR](https://github.com/vllm-project/vllm/pull/58714) · state: closed · merged: False

## Original PR description

More context can be found in: https://github.com/vllm-project/humming/pull/95

Depends on next Humming release including https://github.com/vllm-project/humming/pull/95

vllm serve config:
```
  --tensor-parallel-size 4 \
  --data-parallel-size 2 \
  --enable-expert-parallel \
  --all2all-backend deepep_v2 \
  --kv-cache-dtype fp8 \
  --enforce-eager
```

vllm bench config
```
--random-input-len 10000 --random-output-len 1 \
--num-prompts 320 --max-concurrency 64
```

| Model / MoE backend | Mean TTFT | P99 TTFT | Mean TTFT vs DeepGEMM |
|---|---:|---:|---:|
| `zai-org/GLM-5.2-FP8` / DeepGEMM | 36.89 s | 42.64 s | Baseline |
| `RedHatAI/GLM-5.2-MXFP4xFP8_BLOCK` / [#95](https://github.com/vllm-project/humming/pull/95) | 39.29 s | 45.75 s | ~6% slower |

This represents a ~70% reduction in TTFT compared with MAIN W4A8 Humming on this setup, while delivering performance that is nearly on par with DeepGEMM W8A8 on hardware without FP4×FP8 Tensor Core support, making its deployment feasible on memory-constrained setups.

On gsm8k, the mxfp4 checkpoint (Humming backend) gets 94.47% vs 94.62% on fp8 (DeepGEMM)
