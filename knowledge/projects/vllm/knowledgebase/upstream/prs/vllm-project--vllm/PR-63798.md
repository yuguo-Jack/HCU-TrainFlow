# Optimize sliding window prefix cache hit search

[Upstream PR](https://github.com/vllm-project/vllm/pull/63798) · state: open · merged: False

## Original PR description

## Summary

Optimize `find_longest_cache_hit` in `SlidingWindowManager` to reduce lookup complexity from O(max_num_blocks) to O(max_num_blocks / stride) for low cache hit rate scenarios.

## Motivation

The current implementation scans every block from right to left, costing up to `max_num_blocks` `BlockPool.get_cached_block` lookups even when the cache is cold. For a 128K-token request with a 4K window, this performs ~8192 lookups (block_size=16) although a hit only needs `cdiv(sliding_window - 1, block_size) = 256` contiguous blocks.

## Changes

- **Stride-based probing**: Probe every `stride = sliding_window_contiguous_blocks` blocks from the right
- **Right expansion on hit**: On a probe hit, expand right (at most `stride - 1` blocks) to verify
- **Aligned jumps on miss**: After a miss at `idx`, resume at the next aligned edge below `idx - 1`
- **Direct cached-prefix fallback**: Compute the cached-prefix fallback directly instead of full scan

## Performance

From issue #62336 benchmarks:

| pattern | main lookups | proposed lookups | main time | proposed time |
|---|---:|---:|---:|---:|
| cold cache | 8192 | 33 | 4.49 ms | 0.021 ms |
| 1% random cached | 8192 | 33 | 4.61 ms | 0.021 ms |
| tail hit / full cache | 256 | 257 | 0.23 ms | 0.23 ms |
| adversarial (cached blocks on probe lattice) | 8192 | 128 | 4.63 ms | 0.11 ms |

The worst case remains O(max_num_blocks), but the common low-hit-rate case becomes O(max_num_blocks / stride).

## Fix Summary

Addressed @liulanze's review feedback on the stride-based probing algorithm.

### Bug Fixed
The original optimization only expanded **LEFT** from stride boundaries when a hit was found. This missed valid cache hit runs where the right edge didn't align with a probe index.

### Changes in Commit 
1. **Always check rightmost block first** - Modified probe condition to always check  regardless of stride alignment
2. **Right expansion on hit** - When a hit is found at index , first expand RIGHT to find the true  of the contiguous run
3. **Left expansion from run_end** - Then expand LEFT from  to capture the full contiguous run
4. **Alignment check at run_end** - Validate alignment at the true end of the run () instead of the initial probe position
