# [Bugfix][Frontend] Report prompt_tokens_details in batched chat completions

[Upstream PR](https://github.com/vllm-project/vllm/pull/64757) · state: closed · merged: True

## Original PR description



## Overview

Populate `usage.prompt_tokens_details` on `/v1/chat/completions/batch` when `--enable-prompt-tokens-details` is enabled, using the existing chat helper.

## Claims

- Sum cached, created-cache and multimodal counts per conversation.
- An unknown cache count leaves its total null; disabling the flag leaves details null.
- Reasoning-token details remain unchanged.

## Validation

GPU: Colab RTX PRO 6000 Blackwell, vLLM `4e3d49dda` with the precompiled wheel built at that commit, torch 2.14.0+cu132, FlashAttention 2.

```bash
python -m pytest tests/entrypoints/openai/chat_completion/test_batched_chat_completions.py -v -rA -p no:cacheprovider --timeout=900
```

Base with the new test: 1 failed, 11 passed (the new test, at `batch_details is not None`). With the fix: 12 passed.

Repro with `vllm serve Qwen/Qwen2.5-0.5B-Instruct --enable-prefix-caching --enable-prompt-tokens-details` (block size 16): on base the batch route returns `prompt_tokens_details: null`; with the fix a warm batch of two conversations returns `cached_tokens: 64`, where the warm single requests for the same conversations report 32 each.

```bash
pre-commit run --files vllm/entrypoints/openai/chat_completion/batch_serving.py tests/entrypoints/openai/chat_completion/test_batched_chat_completions.py docs/serving/online_serving/openai_compatible_server.md
```

Passed.

No model-quality evaluation: generation is unchanged.

## Details

The batch generator previously constructed only usage totals. It now aggregates prompt details once per conversation.

Single chat, completions, Responses, pooling, token-in/out, Anthropic/Cohere and run-batch use other handlers; Rust returns 501 here.

Duplicate check: no open PR changes the batch usage block. I searched `prompt_tokens_details`, `batch_serving`, `num_cached_tokens` and `chat_completion_full_generator_batch`, and read the `batch_serving.py` hunks of the 17 open PRs that touch the file. #55120/#58116 concern completions; #61431 changes serialization; #41834 changes the sampling parameters in `create_batch_chat_completion`, not the usage block.
