# [Refactor][ROCm][MoE] Let each AiterExperts subclass own its AITER call args

[Upstream PR](https://github.com/vllm-project/vllm/pull/63204) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Final part of #54966 item 5 ("Split AITER experts by weight quantization key"). #60322 split `AiterExperts` into 5 leaf classes; this PR moves each scheme's AITER call arguments into its leaf, so the shared `rocm_aiter_fused_experts()` no longer branches on quant scheme.

## Claims

- Each leaf declares its AITER `QuantMethod` (`_AITER_QUANT_METHOD`); `rocm_aiter_fused_experts()` takes `quant_method` instead of re-deriving it from `quant_config` flags.
- `AiterMxfp4Experts` owns its gate_mode / bias / `q_dtype_a` overrides (incl. DSV4 a4w4) via `_extra_fused_moe_kwargs()`.
- `AiterFp8ChannelExperts.apply()` owns the topk=1 / `apply_router_weight_on_input` dispatch to `asm_moe_tkw1` and its `num_local_tokens` restriction; the generic function has no tkw1 branch.
- `AiterFp8BlockExperts` declares it doesn't support `apply_router_weight_on_input`.
- No numerical change intended.

## Validation

MI355 (gfx950), `VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_MOE=1`:

| Command | Result |
|---|---|
| `pytest tests/kernels/moe/test_rocm_aiter_moe.py` | 88 passed |
| `pytest tests/kernels/moe/test_modular_kernel_combinations.py -k aiter` | 67 passed, 14 skipped, 2 failed* |
| `pytest tests/kernels/moe/test_mori_moe.py tests/kernels/moe/test_muse_spark_rocm_bf16_moe.py` | 53 passed |

\*Both failures are `MoriEPv2PrepareAndFinalize` + `AiterUnquantizedExperts` (multi-GPU) hitting a GPU memory fault; they fail identically on `main` without this PR.

New `test_aiter_fp8_channel_experts_owns_tkw1_dispatch` drives `AiterFp8ChannelExperts` through the modular kernel and checks both routes against the reference MoE: topk=1 → `asm_moe_tkw1`, topk=2 → `fused_moe`.

No model eval: refactor with no intended numerical change; kernel tests compare against the reference MoE.

## Details

- Direct callers that bypass the leaves (quark W4A8, DSV4, two test references) pass `quant_method` explicitly. `derive_aiter_quant_method()` and `mxfp4_w4a16_extra_kwargs()` give them the values a leaf would; the test references use these rather than the leaf under test so a wrong leaf value can't hide on both sides.
- For direct callers only, `rocm_aiter_fused_experts()` no longer auto-dispatches tkw1. No in-tree caller relied on it (quark W4A8 has no per-token activation quant, so it already took `fused_moe`). Out-of-tree callers must also pass the new required `quant_method`.
- Dropped the block-FP8 `w1_scale`/`w2_scale is not None` asserts: the FP8 oracle always builds the quant config with scales.
- Not a duplicate: this is the last open item-5 PR in the #54966 progress tracker.
