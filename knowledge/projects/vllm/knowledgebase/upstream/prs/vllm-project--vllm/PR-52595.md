# vLLM Profiling QoL Improvements

[Upstream PR](https://github.com/vllm-project/vllm/pull/52595) · state: open · merged: False

## Original PR description

## Purpose

Make profiler capture repeatable across data-parallel workers:

- Agree on both start and stop at a DP coordination step, and propagate the chosen trace prefix and iteration bounds to every rank.
- Wake idle MoE DP engines through the coordinator so a profiling command still reaches the next coordination step.
- Export Torch traces in the background while letting graceful worker shutdown wait for the export to finish.
- Rebuild the one-shot Torch profiler for each capture and allow repeated profiling rounds.

![Synchronized multi-node profiler traces](https://github.com/user-attachments/assets/a4cd5e36-2194-4a5e-a5d9-cb09340f2e41)

For non-MoE external or hybrid load balancing, each frontend owns only its local engine ranks; profiling commands must be sent to each frontend. The cross-rank profiler consensus applies to MoE DP workers.

## Test Plan

- `pytest -q tests/v1/worker/test_gpu_profiler.py -m skip_global_cleanup` (16 passed locally on macOS, CPU-only cases).
- `ruff check` and `ruff format --check` on the changed Python files (passed).
- Multi-node GPU behavior requires a distributed integration run; local hardware cannot exercise that path.
