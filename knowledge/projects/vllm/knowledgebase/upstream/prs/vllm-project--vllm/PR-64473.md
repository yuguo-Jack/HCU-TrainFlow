# [Bugfix][LoRA] Fold LoRA scaling in fp32 before casting lora_b to lora_dtype

[Upstream PR](https://github.com/vllm-project/vllm/pull/64473) · state: open · merged: False

## Original PR description

## Overview

When loading a LoRA adapter in `LoRAModel.from_lora_tensors` (`vllm/lora/lora_model.py`), `lora_b` is first cast to `lora_dtype` (the model dtype by default, e.g. `bfloat16`) and later multiplied in place by `self.scaling` inside `LoRALayerWeights.optimize()` (`self.lora_b *= self.scaling`). For `float32` adapter checkpoints (PEFT's default save format) with any non-power-of-two scaling factor `lora_alpha / r` or `lora_alpha / sqrt(r)` (rsLoRA), this double-rounds every `lora_b` element as `RN_bf16(RN_bf16(B) * RN_32(scaling))` instead of rounding the float32 product `RN_32(B * RN_32(scaling))` to `lora_dtype` once.

No open issue or PR addresses this (`gh pr list --repo vllm-project/vllm --state open --search "from_lora_tensors scaling lora_b"`).

**AI assistance disclosure:** AI assistance (Antigravity / Gemini) was used during the investigation, test authoring, and preparation of this PR.

## Claims

- Folds `loras[module_name].scaling` into `lora_b` in `float32` inside `LoRAModel.from_lora_tensors` via `(tensor.float() * loras[module_name].scaling).to(dtype or tensor.dtype)` before moving/casting to `(device, dtype)`, and sets `loras[module_name].scaling = 1`.
- Preserves the `dtype=None` contract (keeping `tensor.dtype` when `dtype` is omitted) while ensuring `lora_b` is rounded from the `float32` product once, within `bfloat16`'s rounding bound `|w - B*s| <= 2^-8 * |B*s|`.
- Eliminates intermediate `bfloat16` rounding of `lora_b` prior to scaling, avoiding 1-ULP double-rounding errors on ~26.5% of `lora_b` weights (and errors beyond `bfloat16`'s rounding bound `2^-8 * |B*s|` on ~9.9% of weights for rsLoRA `r=8, alpha=16`, $s = 16 / \sqrt{8}$, and ~26.2% / ~8.6% for `r=12, alpha=16`, $s = 4/3$).
- As a side effect, avoids mutating caller-owned tensors in place when in-memory `lora_tensors` are passed in `lora_dtype` with `scaling != 1` and `.to(device, dtype)` is a no-op (e.g. `device=None`, or CPU tensors with `device="cpu"` on the CPU platform).

## Validation

1. Standalone reproducer demonstrating the double-rounding on `float32` `lora_b` weights with rsLoRA scaling ($r=8, \alpha=16, s = 16 / \sqrt{8}$):

```python
import math
import torch

torch.manual_seed(0)
B_fp32 = torch.randn(4096, 8, dtype=torch.float32) * 0.02
scaling = 16.0 / math.sqrt(8)

# Current path: cast to bf16 in from_lora_tensors, then multiply in place in optimize()
b_current = B_fp32.to(torch.bfloat16)
b_current *= scaling

# Fixed path: fold scaling in fp32 before casting to bf16
b_fixed = (B_fp32.float() * scaling).to(torch.bfloat16)

diff_ulps = (b_current.view(torch.int16) - b_fixed.view(torch.int16)).abs()
print(f"Words differing by 1 bf16 ULP: {int((diff_ulps > 0).sum())} / {B_fp32.numel()} ({100.0 * float((diff_ulps > 0).float().mean()):.2f}%)")
```

Output:
```text
Words differing by 1 bf16 ULP: 8650 / 32768 (26.40%)
```
(On this tensor, `b_fixed` equals the exact `bf16(B * s)` for all 32,768 words, whereas `b_current` differs in 8,650 words.)

- On `main`: `45,681` of `172,032` served words (`26.55%`) do not equal `bf16(B * s)`, and `17,016` words (`9.89%`) are farther from `B * s` than `bfloat16` single-rounding allows (up to `1.2` ULP).
- With this PR: `0` of `172,032` served words are outside `bfloat16`'s error bound (`0` differ from `bf16(B * s)`).
(Because power-of-two scalings produce bit-identical served weights in `bfloat16` and non-power-of-two scalings are folded once at adapter load time outside the forward pass, checking the served `lora_b_stacked` words directly validates the change.)

<summary> End-to-end engine reproducer script </summary>

```python
"""vLLM casts a LoRA adapter's lora_B to the model dtype at load time and only then folds the scaling into
it (LoRALayerWeights.optimize: lora_b *= scaling). For a float32 adapter (what PEFT saves) whose scaling s is
not a power of two, here rsLoRA r=8, lora_alpha=16 (s = 16/sqrt(8)), the served weights are bf16(bf16(B) * s)
instead of bf16(B * s). Any correctly rounded bf16 w of x has |w - x| <= 2**-8 * |x|. Needs one GPU."""
import json, math, os, sys, tempfile

os.environ.setdefault("VLLM_ALLOW_INSECURE_SERIALIZATION", "1")  # lets LLM.apply_model ship a function
import torch
from safetensors.torch import save_file

MODEL, R, ALPHA, LAYERS, HIDDEN = "Qwen/Qwen2.5-0.5B-Instruct", 8, 16, 24, 896
S = ALPHA / math.sqrt(R)  # the scaling PEFT and vLLM's PEFTHelper compute for use_rslora=True


def read_slot(model):  # lora_B of LoRA slot 0 in every o_proj: the words the kernels use (scale 1.0)
    mods = dict(model.named_modules())
    return [mods[f"model.layers.{i}.self_attn.o_proj"].lora_b_stacked[0][0, 0].float().cpu() for i in range(LAYERS)]


def rn_bf16(x):  # nearest-even bfloat16 value of float64 x (a float64->bf16 cast would round via float32)
    i = x.view(torch.int64)
    assert not ((i & (2**45 - 1)) == 2**44).any(), "a float64 product sits on a bf16 midpoint"
    return ((i + (2**44 - 1) + ((i >> 45) & 1)) & -(2**45)).view(torch.float64)


if __name__ == "__main__":
    from vllm import LLM, SamplingParams, __version__
    from vllm.lora.request import LoRARequest

    g, d, tensors = torch.Generator().manual_seed(0), tempfile.mkdtemp(), {}
    for i in range(LAYERS):  # a float32 PEFT-format adapter on every o_proj
        p = f"base_model.model.model.layers.{i}.self_attn.o_proj"
        tensors[p + ".lora_A.weight"] = torch.randn(R, HIDDEN, generator=g) / HIDDEN**0.5
        tensors[p + ".lora_B.weight"] = torch.randn(HIDDEN, R, generator=g) * 0.005
    save_file(tensors, os.path.join(d, "adapter_model.safetensors"))
    with open(os.path.join(d, "adapter_config.json"), "w") as f:
        json.dump({"peft_type": "LORA", "r": R, "lora_alpha": ALPHA, "use_rslora": True, "target_modules": ["o_proj"]}, f)

    llm = LLM(MODEL, dtype="bfloat16", enable_lora=True, max_lora_rank=R, max_loras=1,
              enforce_eager=True, max_model_len=256, gpu_memory_utilization=0.3)
    llm.generate("Hello", SamplingParams(max_tokens=1), lora_request=LoRARequest("rslora", 1, d))
    served = torch.cat([w.flatten() for w in llm.apply_model(read_slot)[0]]).double()

    B = torch.cat([t.flatten() for k, t in tensors.items() if "lora_B" in k])  # float32
    exact = B.double() * S  # B*s to within a relative 2**-53
    want, n = rn_bf16(exact), B.numel()
    wrong = int((served != want).sum())
    outside = (served - exact).abs() > 2.0**-8 * exact.abs()  # farther from B*s than bf16 rounding allows
    late = int((served == (B.bfloat16() * S).double()).sum())  # = bf16(bf16(B) * s): scaled after the cast
    hx = lambda v: f"0x{torch.tensor([v]).bfloat16().view(torch.int16).item() & 0xFFFF:04x}"
    print(f"vllm {__version__}; s = {S!r}; {n} lora_B words, {late} of them equal bf16(bf16(B) * s)")
    if not outside.any():
        print(f"PASS: 0 of {n} served lora_B words are outside bf16's error bound; {wrong} are not bf16(B*s)")
        sys.exit(0)
    k = int(outside.nonzero()[0])
    print(f"FAIL: {wrong} of {n} served lora_B words ({100 * wrong / n:.2f}%) are not bf16(B*s) and "
          f"{int(outside.sum())} ({100 * outside.double().mean():.2f}%) are outside bf16's error bound; e.g. word {k}: "
          f"B*s = {exact[k].item():.9g}, served {hx(served[k])} = {served[k].item():.9g}, expected {hx(want[k])} = {want[k].item():.9g}")
    sys.exit(1)
```

## Details

PEFT stores `lora_A` and `lora_B` in `float32` by default. When vLLM loads an adapter via `LoRAModel.from_lora_tensors`, `loras[module_name]` is already initialized from `LoRALayerWeights.from_config(module_name, peft_helper, peft_module_name)` with its resolved `scaling` (including `use_rslora`, `rank_pattern`, and `alpha_pattern`). All adapters used in `tests/lora` have power-of-two scalings (`0.5`, `2`, `4`), where scaling only shifts the `bfloat16` exponent and masks the double rounding.

Folding `loras[module_name].scaling` in `float32` and setting `loras[module_name].scaling = 1` inside `LoRAModel.from_lora_tensors` ensures `lora_b` is rounded from the `float32` product once (within `bfloat16`'s rounding bound), while leaving `LoRALayerWeights.optimize()` and `PackedLoRALayerWeights` behavior unchanged for callers that construct `LoRALayerWeights` directly. (Note that this fixes the served `lora_b` weights rather than changing the LoRA kernel epilogue; PEFT in `bfloat16` applies `scaling` after the low-rank matmul rather than folding it into `lora_B`.)

When `LoRAModel.from_lora_tensors` receives GPU tensors already in `lora_dtype`, `tensor.to(device=device, dtype=dtype)` is a no-op ([`lora_model.py#L173`](https://github.com/vllm-project/vllm/blob/65faf4efa0281fc2e04096a28cd35fb8dc7d3218/vllm/lora/lora_model.py#L173)) and `LoRALayerWeights.optimize()` runs `self.lora_b *= self.scaling` in place ([`lora_weights.py#L41`](https://github.com/vllm-project/vllm/blob/65faf4efa0281fc2e04096a28cd35fb8dc7d3218/vllm/lora/lora_weights.py#L41), [`model_manager.py#L907`](https://github.com/vllm-project/vllm/blob/65faf4efa0281fc2e04096a28cd35fb8dc7d3218/vllm/lora/model_manager.py#L907)), multiplying the caller's `lora_B` by `s` on every rebuild. In SkyRL, staged tensors are passed to `from_lora_tensors` by reference and reused to rebuild LRU-evicted adapters ([`patch_lora_in_memory.py#L162-L174`](https://github.com/NovaSky-AI/SkyRL/blob/e4fdd8c111b2e1b757eef329c4714caf54c82840/skyrl/backends/skyrl_train/patches/vllm/patch_lora_in_memory.py#L162-L174), [`#L197-L210`](https://github.com/NovaSky-AI/SkyRL/blob/e4fdd8c111b2e1b757eef329c4714caf54c82840/skyrl/backends/skyrl_train/patches/vllm/patch_lora_in_memory.py#L197-L210)); because `"A non-unit scale would therefore compound on each reload"`, [NovaSky-AI/SkyRL#2305](https://github.com/NovaSky-AI/SkyRL/pull/2305) had to add a workaround that folds `alpha/r` itself, sets `lora_alpha = r`, and rejects `scaling != 1.0`.
