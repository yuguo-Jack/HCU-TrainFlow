# [LoRA][Model] Add LoRA support for GLM-5.3-Flash

[Upstream PR](https://github.com/vllm-project/vllm/pull/56327) · state: open · merged: False

## Original PR description

## Purpose

Enable LoRA adapters on GLM-5.3-Flash (`Glm5NextForConditionalGeneration`, added in #53906).
The class already inherits `SupportsLoRA` from `Glm4vForConditionalGeneration`, but it
inherits Glm4v's `packed_modules_mapping` too, so adapters that target the HF submodule
names cannot be mapped onto the fused runtime projections:

**`packed_modules_mapping` for `Glm5NextForConditionalGeneration`**
 (`vllm/models/glm5next/nvidia/model.py`). Maps each fused runtime linear to its
 adapter-visible submodules: `gate_up_proj` -> gate/up, the 6-way KDA projection
 `in_proj_qkvbfg_a` -> q/k/v/b/f_a/g_a, `fused_qkv_a_proj` -> q_a/kv_a_proj_with_mqa,
 `wk_weights_proj` -> wk/weights_proj, and the vision `qkv`/`qkv_proj` -> q/k/v.

- JackRao123 · comment · 2026-09-28T20:33:44Z · [source](https://github.com/vllm-project/vllm/pull/56327#issuecomment-5877992015)

This doesn't cover `lm_head` yet. An adapter that targets it loads without error, but the `lm_head` delta is never applied.

Two things on `Glm5NextForConditionalGeneration` block it:

1. There's no `embedding_modules`, so `lm_head` (a `ParallelLMHead`) isn't in `get_supported_lora_modules`.
2. `get_mm_mapping()` is inherited from Glm4v with `language_model="language_model.model"`. `_get_punica_wrapper` matches by prefix, so `language_model.lm_head` gets no wrapper and is skipped:
   ```
   Regarding Glm5NextForConditionalGeneration, no matching PunicaWrapper is found; language_model.lm_head will be ignored.
   ```
   Its adapter weights are then dropped at load with no error.

Suggested addition:

```python
    embedding_modules = {"lm_head": "output_embeddings"}

    def get_mm_mapping(self) -> MultiModelKeys:
        return MultiModelKeys.from_string_field(
            language_model="language_model",
            connector="visual.merger.",
            tower_model="visual.",
        )
```

`language_model` is the prefix Qwen2.5-VL, Qwen3-VL, LLaVA and Gemma3 already use. The other readers of `get_mm_mapping()` (`gpu_model_runner.py`, `v1/worker/gpu/mm/lora.py`) only use `connector`.

Tested on GLM-5.3-Flash FP8, TP2 on B300, `--enforce-eager`, on a 487ecf187-based build with the equivalent change applied as a runtime patch. The adapter was rank 32, after one training step, and targets `lm_head` plus attention/MLP. As a control, I made a copy with `lm_head`'s `lora_B` replaced by N(0, 1) noise. Temperature 0:

| | original adapter | `lm_head` `lora_B` = N(0, 1) |
|---|---|---|
| before | `The user is asking a simple factual question: What is the capital of France?…` | `The user is asking a simple factual question: What is the capital of France?…` (identical) |
| after | `The user is asking a simple factual question: What is the capital of France?…` | `The user asks: what is the capital ofFrance question question question…` |

Before the change the warning above is logged, and the noisy `lm_head` has no effect. After the change there's no warning.

Happy to open this as a follow-up PR instead if you'd rather keep this one scoped. (Found and tested with AI assistance.)

- eilamc14 · comment · 2026-10-05T21:44:40Z · [source](https://github.com/vllm-project/vllm/pull/56327#issuecomment-6003627647)

Tested this PR on main (c32495d58f) with GLM-5.3-Flash-BF16, 4×B200, TP=4. I compared vLLM's per-token log-probs against HF transformers + PEFT on 2,039 gold-answer tokens, using single-module adapters trained with PEFT.

* Works: q/k/v (in_proj_qkvbfg_a), q_a/kv_a (fused_qkv_a_proj), and the replicated g_a slices across TP ranks. Each matches HF; for example, q/k/v is 0.012 mean |Δlogprob| from HF, against 0.149 if the LoRA were dropped.
* Still dropped: f_a_proj (0.103 vs 0.101 dropped). transformers nests it under self_attn.forget_gate.f_a_proj, which is the name PEFT saves, so the packed mapping never finds it. f_b_proj has the same problem, and it does on main too.

#60131 fixes both with a .forget_gate. → . rename in hf_to_vllm_mapper. With both PRs applied, f_a_proj matches HF (0.022 vs 0.100 dropped).
