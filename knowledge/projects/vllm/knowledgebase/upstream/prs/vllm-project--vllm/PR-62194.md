# [Model] NemotronHMTP: share the target's embedding and LM head

[Upstream PR](https://github.com/vllm-project/vllm/pull/62194) · state: open · merged: False

## Original PR description



## Overview

`NemotronHMTP` no longer allocates or loads its own LM head, and no longer loads an embedding. It loads only `mtp.*` weights, and `load_eagle_model` always attaches the target's embedding and LM head. A weight update of the target, such as an RL refit, therefore also updates the drafter.

This is one self-contained part of #62017 by @aoshen02, split out unchanged for separate review. The commit keeps his authorship.

## Claims

- The drafter no longer allocates, loads and then compares a vocab × hidden copy of the LM head, and no longer loads the embedding. Both are always the target's modules.
- Sharing no longer depends on a load-time `torch.equal` between the drafter's copy and the target's weights. A refit of the target reaches the drafter because they are the same modules, and the drafter's own `load_weights` only ever touches `mtp.*`.

## Details

Behavior difference from main, for reviewers to confirm:
- On main, a checkpoint that contains `lm_head.*` sets `has_own_lm_head = True`. `_should_share` then compares the drafter's head with the target's and shares only when they are equal.
- With this PR, the drafter always uses the target's head.
- For Nemotron-H checkpoints the MTP `lm_head.*` is the target's, so the result is the same. A checkpoint whose MTP head genuinely differs from the target's would now have that head ignored.

Related open PR: #59727 (`NemotronHMTP.get_top_tokens()`) touches the same file. It reads `self.lm_head`, which here is the target's module after loading, so the two should compose, but they may need a textual rebase.
