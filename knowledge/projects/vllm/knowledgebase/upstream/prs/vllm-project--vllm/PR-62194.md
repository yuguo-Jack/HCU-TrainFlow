# [Model] NemotronHMTP: share the target's embedding and LM head

[Upstream PR](https://github.com/vllm-project/vllm/pull/62194) · state: closed · merged: True

## Original PR description

## Purpose

`NemotronHMTP` now loads only `mtp.*` weights and always uses the target's embedding and LM head, on every pipeline stage. Both modules start as `None`, and `has_own_embed_tokens = False` / `has_own_lm_head = False` let the existing sharing helpers attach the target's modules before execution. Because the drafter holds the target's modules, a target weight refit also updates the drafter.

Before this change, with PP=2 the drafter got its own copy of the embedding instead of the target's. MTP acceptance dropped to about 9%.

This is a self-contained split of #62017 by @aoshen02, with authorship retained.

## Behavior change

On main, a checkpoint containing `lm_head.*` sets `has_own_lm_head = True`, and the drafter shares the head only if it equals the target's. With this PR the drafter always uses the target's head. For Nemotron-H checkpoints the MTP `lm_head.*` is the target's, so the result is the same. A checkpoint with a genuinely different MTP head would have that head ignored.

## Test Plan

```bash
pytest -q tests/v1/worker/test_spec_decode_embed_sharing_pp.py tests/v1/worker/test_gpu_draft_lm_head.py
```

The new tests check two things:
- Only `mtp.*` weights are loaded, with and without the `language_model.` prefix.
- With PP=1 and PP=2 the drafter shares the target embedding, and a target refit is visible to the drafter.

Model probe: `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`, GH200, TP=1, MTP with 3 draft tokens, temperature 0, 12 prompts × 64 tokens, eager.

## Test Result

## Review of 4949efda4a58

I reviewed this PR for correctness and overall simplicity, together with a second independent reviewer, and we cross-checked each other's findings. Line numbers refer to the PR head.

### P1: with PP > 1, the drafter's embedding is neither loaded nor shared

- `NemotronHMultiTokenPredictor` still builds its own `VocabParallelEmbedding` (`nemotron_h_mtp.py:255`).
- After this PR, `is_unused_checkpoint_weight` skips the checkpoint's `embeddings`, and `load_weights` adds `"model.embed_tokens.weight"` to `loaded_params`, so the strict loading check passes without the tensor ever being loaded (`nemotron_h_mtp.py:431`, `552`).
- With PP > 1, `maybe_share_target_embed` returns early for drafters that do not declare `has_own_embed_tokens` (`v1/worker/gpu/spec_decode/eagle/utils.py:59-62`). `test_mtp_style_drafter_is_left_alone_under_pp` pins that behaviour. `NemotronHMTP` only declares `has_own_lm_head`.

As a result, on the last PP rank the drafter embeds tokens with uninitialized memory. Target outputs stay correct because they are verified, but acceptance collapses and nothing reports an error. On main this configuration worked, because the drafter loaded `embeddings` from the checkpoint.

Suggested fix, which also simplifies the change:
- Declare `has_own_embed_tokens = False` on `NemotronHMTP`. The Nemotron-H target allocates `embed_tokens` on every PP rank and loads it through `AutoWeightsLoader` (`nemotron_h.py:584`, `918`), so the drafter can share it under PP too.
- Do not construct the drafter's embedding at all: set it to `None`, as is already done for `lm_head` and as `models/inkling/nvidia/mtp.py` does. Then drop the fake `loaded_params.add("model.embed_tokens.weight")`. This avoids allocating a vocab × hidden table only to delete it. If sharing ever fails to happen, the assert in `get_input_embeddings` fails loudly instead of the drafter silently running on garbage.

### Minor

- `self.has_own_lm_head = False` is now a constant and could be a class attribute, like the other MTP/DSpark drafters.
- `hf_to_vllm_mapper`'s `orig_to_new_substr={"embeddings": "embed_tokens"}` is dead now that embeddings are never loaded.
- A checkpoint `lm_head.*` that differs from the target's is now dropped without any log line. The PR body mentions this change; a one-time warning would make it visible at runtime.

### Checked and found correct

- The `lm_head` half at PP = 1 and PP > 1: `has_own_lm_head=False` makes `_should_share` return True without reading the drafter's weight. `lm_head = None` is replaced inside `load_eagle_model`, before any profile run, dummy run or CUDA graph capture.
- TP sharding of the shared modules.
- The `language_model.` prefix handling in both `is_unused_checkpoint_weight` and `load_weights`.
- Shard filtering through the `is_unused_checkpoint_weight` loader hook.
- Draft-weight refit through layerwise reload, including the `draft_lm_head_quantization` swap.
