# [Frontend] Replace return_mm_kwargs with an mm_payload enum on render requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/61427) · state: closed · merged: True

## Original PR description

## Overview

Replaces the `return_mm_kwargs` bool from #60728 with an `mm_payload` enum on render requests. This enables the "source bytes" option from #46722 has somewhere to go later.

## Claims

- New `mm_payload: "tensors" | "none"` field (default `"tensors"`) on the chat, completions, Messages and Responses request models
- `return_mm_kwargs` still works as a deprecated alias. `false` means `mm_payload="none"`
- No behavior change for default requests or for clients already sending `return_mm_kwargs: false`

## Validation

- `pytest tests/entrypoints/scale_out/token_in_token_out/test_mm_serde.py -v`: passes
- `pre-commit run` passes, including mypy

New test `test_return_mm_kwargs_is_alias_for_mm_payload` covers the alias on all four request models. No model output change, so no evals.

## Details

`return_mm_kwargs` is in `v0.32.0rc0` but not in a final release. This means it is the cheap time to change its shape. @vMaroon suggested one three valued field (tensors, source bytes, none) in #46722. This PR lands the first two values and leaves `"source"` to #53169.

If both fields are set, `mm_payload` overrides. `extract_mm_features` now takes `mm_payload` instead of `include_mm_kwargs`.

Not a duplicate, no open PR changes this flag. #58660 speeds up render serialization, #61418 only uses the flag and #53169 adds raw image bytes which would plug into this enum.
