# [RFC][NIXL] Add graceful peer retirement example for UCX v1.22.x memory release

[Upstream PR](https://github.com/vllm-project/vllm/pull/57507) · state: closed · merged: False

## Original PR description

## Summary

Replace the earlier CPU-only sketch with the **GPU-tested, version-pinned
graceful peer-retirement example**, its source patches, CPU tests and measured
memory-reclamation evidence. This is an RFC ready for implementation/design
review, not a production-ready autoscaler or a change to default serving.

Scope: **a normally drained Prefill exits; healthy Decode instances release
its old CUDA IPC references without restarting**. The tested stack is vLLM
0.26.0, NIXL 1.4.1 and a pinned UCX v1.22.x build. Abrupt P death, OOM,
segfaults, incomplete-transfer cancellation and forced unmapping are excluded.

## Code in This PR

The old `examples/disaggregated/peer_retirement_cpu/` is removed. Its replacement,
`examples/disaggregated/peer_retirement_graceful/`, includes:

- Worker-thread prepare/commit, exact-generation fencing, busy-state checks,
  and reuse of `_cleanup_remote_engine()` / `remove_remote_agent()`.
- Authenticated, opt-in lab middleware with full-D admission fencing,
  collective-RPC validation of all TP ranks, and fail-closed handling of
  partial cleanup or an unknown result.
- SHA-256-guarded v0.26.0 patches for old-generation reads/handshakes/heartbeats,
  TTL safety and notification-only metadata cleanup.
- CPU tests using actual pinned v0.26.0 methods with a fake NIXL boundary;
  an explicit fixture preparation step makes subsequent tests offline.
- A minimal Docker layer, an isolated exercise guide and sanitized GPU results.
  The Dockerfile requires an existing matching native stack; it does not
  build or upgrade UCX.

The three core Python files have identical ASTs to the isolated GPU-tested
lab implementation; packaging changes are license headers, formatting and
test fixture paths. The host-specific controller and private operational
files are not included. This is not a one-command portable GPU reproducer.

The integration is deliberately an opt-in version-pinned example, **not an
upstream-main `/drop_peer` serving implementation**. It demonstrates the
tested lifecycle for review before merging it into an agreed production API.

## Problem and Lifecycle

For N-P/M-D serving on one multi-GPU host, a P process can exit while surviving
D workers retain imported memory resources. Its former GPU capacity can remain
occupied and prevent a replacement from loading. Stopping the entire D pool
has reclaimed that memory, but interrupts unrelated work and defeats
independent P scaling.

```text
Stop new router admissions to the exact old P generation
  -> finish admitted requests and KV handoff
  -> quiesce the D being cleaned and fence the old generation on every TP rank
  -> release destination descriptor lists, then remove the remote NIXL agent
  -> verify acknowledgements from every relevant D/rank
  -> normally stop P and measure its GPU memory
  -> verify surviving D identities and fresh transfers from another P
```

In the tested protocol, the D being cleaned has zero active HTTP responses,
and background traffic is routed to the other D. Its whole admission path is
frozen across prepare/commit. A partial failure or timeout retains that freeze
for diagnosis; potentially partial native cleanup is not blindly retried.
Python-visible connector queues are checked, not every native worker queue.

## GPU Results: UCX v1.22.x

One isolated eight-GPU **H20** host, 2P2D with TP=2 each, DeepSeek-V4-Flash
(non-0731), vLLM 0.26.0, NIXL 1.4.1. UCX was the **v1.22.x branch at
`5288e74cd40be622e109489de7bb80d821341bd5`**, not a claimed formal-release
validation. Settings: `UCX_TLS=tcp,cuda_ipc,cuda_copy`,
`UCX_CUDA_IPC_CACHE=n`, NIXL UCX `num_threads=8`.

| Check | Observed result |
| --- | --- |
| Control: normally stop P without explicit D cleanup | 42,912 MiB retained on each former P GPU for about 120 seconds |
| Explicit D cleanup, then normally stop P | Both former P GPUs at 0 MiB for all 60 samples over 119.502 seconds |
| Surviving D instances | Container identities and TP worker PIDs unchanged |
| Fresh 64K transfer from the other P to each D | Each pair added 578,062,080 NIXL bytes; zero failed-transfer increment |
| Drain / cleanup / memory observation | 163/163 logical P-D requests succeeded |
| Replacement P | New generation started on the same GPU pair |
| Background traffic during replacement | 107/107 succeeded; maximum completion gap 2.179 seconds |
| Final four P-D pair checks | Short and 64K requests: 8/8 succeeded |

With eight baseline requests, 286 logical P-D requests passed the experiment's
checks. Final transfer and notification failure counters on both D instances
were zero. Final full teardown occurred only after acceptance and is not used
as evidence that P-only retirement reclaimed memory.

Control and candidate used the same native NIXL/UCX binaries. The candidate also
contains fences, TTL guards and metadata cleanup, so this is not a one-line
comparison. Runtime library paths and cache settings were checked.

## Native Release Boundary

At the tested UCX commit, rkey release can reach
`uct_cuda_ipc_unmap_memhandle()`. Mapping references are decremented, and a
zero-reference region is destroyed when the remote mapping cache is disabled.
`UCX_CUDA_IPC_CACHE=n` does not release outstanding higher-level references
still held by D. The control case demonstrates why that setting alone is
insufficient here.

No direct `uct_cuda_ipc_destroy_cache_by_iface_address()` or forced unmap is
introduced. Individual native unmap/CUDA close calls were not traced. Therefore
`cleanup_returned` intentionally does **not** report verified native release;
the evidence is measured VRAM recovery with surviving D processes and
successful unrelated transfers. See `VALIDATION.md` for sources and limits.

## Relationship to Existing Work

- #50047 (inspected at `8d742243fa9a3032fcc014ff5c3e17aa871a2bff`) cleans a
  replaced pull peer after successful new-engine handshake at the same address.
  This explicit normal scale-down path does not require a replacement P, which
  may not exist or may be unable to load until retained memory is released.
  Cleanup mechanisms should be shared, not duplicated in production.
- #56341 handles P-side cleanup after D death: the opposite direction.
- #55471 handles locally missing NIXL metadata while P remains alive.
- Existing in-flight protections such as #54689 remain essential.

This updates the existing RFC rather than opening another overlapping PR.

The two fixtures match the public v0.26.0 sources by SHA-256. Tests are
method-level with mocked native resources, not full-import vLLM/native tests.
The historical separate lab runtime/controller suite passed 51 tests; that
number is not claimed for this new public directory.

The full pre-commit run was attempted with the repository configuration and
installed hooks, but dependency initialization did not finish within a
150-second bound (last progress: fetching the public `crate-ci/typos` hook).
It is **not** reported as passed. The checks listed above ran independently.
Commit hooks were bypassed for this packaging commit after that infrastructure
timeout; full CI/hook validation remains pending.

No new GPU run was performed during packaging; the GPU results above belong to the same core
Python logic tested on September 20. The portable Docker wrapper was not
rebuilt locally on this Mac. Model-output checks are limited to the stated
functional lifecycle exercise, not broad accuracy or throughput evaluation.
