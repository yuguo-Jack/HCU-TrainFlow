# [Bugfix][KV Offload] Preserve other writers temporary files on open failure

[Upstream PR](https://github.com/vllm-project/vllm/pull/59573) · state: open · merged: False

## Original PR description

## Overview

Fix the filesystem KV offload Python fallback deleting another writer's temporary file when exclusive creation fails. Limit cleanup to temporary files successfully opened by the current store, matching the C implementation.

## Claims

- A temporary-name collision still fails the competing store, but preserves the active writer's file so it can complete atomic publication.
- Add a deterministic real-filesystem regression covering both Python and C I/O paths.

## Validation

- Before the fix, the new regression fails on the Python path because the first writer's temporary file disappears; the C path passes. After the fix, both pass.
- A two-process reproducer running actual `batch_store_block` with identical random seeds changes from both stores failing/no published block to the owner completing successfully while the competing store reports `FileExistsError`.
- Local source-tree pytest harness: **45 passed, 1 deselected** in `tests/v1/kv_offload/tiering/test_fs_tier.py`. The harness bypasses three connector package initializers that eagerly import unavailable serving dependencies; the filesystem modules are unmodified, and the C extension was compiled from `csrc/fs_io.cpp`. The excluded existing cascade test fails at import because the local environment lacks `transformers`.
- Full pre-commit (including Python 3.10 mypy), manual Python 3.12 mypy, Ruff checks and `git diff --check` pass.

CI/reproduction target in an installed vLLM environment:

```bash
pytest -q tests/v1/kv_offload/tiering/test_fs_tier.py
```

Validation was on macOS arm64/Python 3.12 with buffered disk I/O. Linux `O_DIRECT` and full model serving were not exercised; no throughput or model-quality claim is made. The existing KV offload CI target includes this test file.

## Details

`_store_block` catches errors from `os.open(..., O_CREAT | O_EXCL, ...)` in the same handler that removes its temporary path. If another writer owns that path, the failed open does not confer ownership, but the handler still unlinks the other writer's file. That writer subsequently fails to rename its completed block. Moving open before the cleanup try preserves existing cleanup for errors after successful creation.

Shared-root filesystem caches are supported. Temporary suffixes come from Python's global random generator; identically seeded processes can collide when they reach the same RNG state. The fix does not change the naming scheme or introduce locks.

Duplicate checks covered open PRs mentioning filesystem `FileExistsError`, `O_EXCL`, temporary-file ownership and `_store_block`. #57912 adds CRC32C validation but retains the problematic open/cleanup structure; #53073 and related orphan-cleanup PRs cover shared-memory regions. None addresses this block-file ownership bug.
