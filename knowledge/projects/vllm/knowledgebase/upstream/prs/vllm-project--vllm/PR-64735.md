# [Refactor] Simplify GLM sparse indexer decode grouping with gather

[Upstream PR](https://github.com/vllm-project/vllm/pull/64735) · state: open · merged: False

## Original PR description

## Overview

This follows up on [@tomasruizt’s review comment on #60229](https://github.com/vllm-project/vllm/pull/60229#discussion_r4379617970), which suggested replacing the GLM sparse indexer’s scatter-based token grouping with a simpler gather-based implementation.

For nonuniform decode rows, the sparse indexer needs to turn the flattened token list into a padded `[request, position]` layout. The existing implementation scattered tokens into that layout and used a dummy request to absorb CUDA graph padding. This PR instead builds the source indices and validity mask, then gathers each tensor directly into the desired layout.

The uniform path does not change.

## Claims

- Removes the dummy request used to absorb CUDA graph padding.
- Replaces the scatter, `repeat_interleave`, and discard-row machinery with a reusable gather mapping.
- Reuses the same gather indices for keys, gates, slot mappings, positions, and sequence lengths.
- Keeps the NVIDIA and AMD sparse indexer implementations aligned.
- Preserves support for nonuniform adaptive-verification rows and CUDA graph replay with a smaller live token budget.
- This is a structural simplification rather than a performance claim.

## Validation

- `tests/v1/attention/test_sparse_indexer_decode_seq_lens.py`
  - `10 passed`
- Built this exact branch and loaded `zai-org/GLM-5.3-Flash` on 2×B300 with TP2/EP, MTP `k=5`, block verification, and CUDA graphs enabled.
- Tested adaptive verification both enabled and disabled at concurrency 1, 16, and 96.
- Tested short and approximately 8K-token prompts with varied output lengths and mixed prefill/decode traffic.

## Details

The gather produces a `[request, position]` tensor, so requests with fewer decode tokens leave some cells unused. Since the gather still requires a valid source index for every cell, we point those unused cells to input index zero and then overwrite their values with padding using the validity mask. Rows added only to match the captured CUDA graph size are not referenced by any valid output cell, so they are ignored entirely rather than assigned to a dummy request.

Thanks to @tomasruizt for proposing the gather-based idea/simplification.
