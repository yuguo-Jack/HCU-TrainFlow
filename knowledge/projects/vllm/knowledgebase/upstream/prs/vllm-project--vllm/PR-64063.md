# Ship mamba SSU and Helion tuned kernel configs in wheel package_data

[Upstream PR](https://github.com/vllm-project/vllm/pull/64063) · state: closed · merged: True

## Original PR description

## What this PR does

The tuned Triton kernel config JSONs under `vllm/model_executor/layers/mamba/ops/configs/selective_state_update/` and `vllm/kernels/helion/configs/` are not listed in `package_data` in `setup.py`. They only end up in the wheel through the **setuptools-scm git file-finder**: because `include_package_data` is enabled, every git-tracked file under the package is swept into the wheel.

That mechanism only works when the wheel is built from a **git checkout**. When someone builds vLLM from a source without `.git` — e.g.:

- `pip install vllm.tar.gz` (building from the **sdist** — the sdist itself does not carry the configs either, since `MANIFEST.in` doesn't include them),
- building from a `git archive` export / source tarball with `SETUPTOOLS_SCM_PRETEND_VERSION` set (common in distro and internal-mirror packaging),
- any build environment where setuptools-scm's file finder cannot run,

the file finder is inactive and only the explicitly-listed `package_data` globs are packaged. The result is a wheel that **installs and runs fine but silently drops all tuned kernel configs**:

- Mamba/hybrid models log `Using default Mamba SSU config. Performance might be sub-optimal!` and fall back to the hard-coded launch heuristic (`_get_default_ssm_launch_config`), which is badly mismatched at small batch sizes — for hybrid models on Blackwell this showed up as ~8x slower CUDA-graph capture in the small/mid batch range, with no error anywhere,
- Helion kernels similarly lose their per-device tuned configs (`nvidia_b200.json`, `nvidia_h100.json`, ...).

Notably `model_executor/layers/fused_moe/configs/*.json` *is* listed explicitly, which is why those configs survive every build path — the two new entries bring the mamba and Helion config trees to the same guarantee.

## Reproduction

```bash
# from a git checkout: wheel contains the configs
python setup.py bdist_wheel  # SOURCES.txt: 7198 files, incl. 24 selective_state_update entries

# from a .git-less export: configs silently vanish
git archive HEAD | tar x -C /tmp/export && cd /tmp/export
SETUPTOOLS_SCM_PRETEND_VERSION=0.26.0 python setup.py bdist_wheel
# SOURCES.txt: 3513 files, selective_state_update/helion entries gone
```

## Fix

List both config trees explicitly in `package_data` so wheel contents no longer depend on the build context:

```python
"model_executor/layers/mamba/ops/configs/selective_state_update/*.json",
"kernels/helion/configs/*/*.json",
```
