# [CI] Bump GitHub Actions versions and replace node20 pre-commit/action

[Upstream PR](https://github.com/vllm-project/vllm/pull/64328) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Bumps every pinned GitHub Action to its latest release, replaces the last action still running on node20, and pins markdownlint-cli2 to Node 24 so pre-commit passes again. Supersedes dependabot PRs #63928, #63929, #63931, #60167, #60166 and #47814.

## Claims

- All JavaScript actions now run on node24.
- `pre-commit/action` is replaced by `setup-uv` + `uvx pre-commit run`, because its latest release (v3.0.1) uses the node20 `actions/cache@v4`. The pre-commit cache now uses `actions/cache` v6.1.0, keyed on OS, `UV_PYTHON` and `.pre-commit-config.yaml`.
- markdownlint-cli2 is pinned to Node 24.22.1. Today, `lts` started resolving to Node 26, which needs `libatomic.so.1`, and the `vllm-runners` machines don't have it. This has broken pre-commit on main since 2026-10-28 15:39 UTC.

| Action | From | To |
|---|---|---|
| `actions/checkout` | v7.0.0 | v7.0.1 |
| `actions/create-github-app-token` | v3.2.0 | v3.3.0 |
| `actions/setup-python` (pre-commit job) | v6.1.0 | replaced by `astral-sh/setup-uv` v10.3.3 |
| `actions/stale` | v10.3.0 | v11.0.0 |
| `astral-sh/setup-uv` | v7.6.0 | v10.3.3 |
| `bufbuild/buf-action` | v1.5.0 | v1.6.0 |
| `rust-lang/crates-io-auth-action` | v1.0.5 | v1.0.6 |
| `pre-commit/action` | v3.0.1 | `uvx pre-commit` + `actions/cache` v6.1.0 |

`actions/github-script` (v9.0.0) and `cargo-semver-checks-action` (v2.9) are already at their latest releases. Only their version comments change.

## Validation

- `pre-commit run` passes locally on the changed files, including actionlint and markdownlint-cli2 with Node 24.22.1.
- I checked the breaking changes in the major bumps against the inputs these workflows use, and none apply. setup-python v7 removed `pip-install`, which we don't use. stale v11 is an ESM migration. setup-uv v10 disables `enable-cache: auto` on `pull_request_target`/`workflow_run`/`release`, but `macos-smoke-test.yml` sets `enable-cache: true` explicitly.
- The pre-commit workflow on this PR runs the new steps.
