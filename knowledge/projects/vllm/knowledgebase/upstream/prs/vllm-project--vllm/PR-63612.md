# [ROCm][Perf] Use AITER single-launch KDA decode in GLM-5.3-Flash

[Upstream PR](https://github.com/vllm-project/vllm/pull/63612) · state: open · merged: False

## Original PR description



## Overview

On ROCm with AITER, a plain decode step of a GLM-5.3-Flash KDA layer runs the conv update, the recurrence and the gated RMSNorm as separate launches. This PR runs them as one launch of AITER's Gluon decode kernel through the existing `rocm_aiter_ops.kda_fused_recurrent_packed_decode` wrapper, which the Kimi-K3 layer has used since #57392. Companion prefill change for the same layer: #63568.

## Claims

- ROCm, `VLLM_ROCM_USE_AITER=1`, CDNA4 or newer (gfx950 is the only architecture run): a plain decode step of a GLM-5.3-Flash KDA layer takes one AITER launch in place of three. No new flag or environment variable; any explicit `--kda-decode-backend` keeps the stock chain.
- GLM-5.3-Flash MXFP4, MI355X, TP2, one image plus text per request:
  - `FULL_DECODE_ONLY` graphs: output throughput +5.63 % over concurrency 16–64 (SE 0.80 pp), +13.70 % at concurrency 1, every row positive;
  - breakable `FULL_AND_PIECEWISE` graphs: +3.10 % over concurrency 16–64 (SE 1.13 pp), −1.75 % at concurrency 4 and −2.31 % on the long-prompt row;
  - GSM8K unchanged within run-to-run variation in both.
- Unchanged: CUDA, CPU and gfx942; steps that include a prefill; speculative decoding; non-fp32 recurrent states; other KDA models.

## Details

- **Scope.** `Glm5NextLinearAttention` (`vllm/models/glm5next/common/kda.py`), the KDA layer of `Glm5NextForCausalLM` and `Glm5NextForConditionalGeneration`. The MTP layer is MLA and unaffected. On `main` only `vllm/models/kimi_k3/amd/kda.py` calls this kernel.
- **Eligibility**, decided once in `__init__`: fp32 recurrent state, `head_dim` 128, width-4 conv, a lower bound, no speculative decoding, `--kda-decode-backend` at `auto`, and `rocm_aiter_ops.is_kda_gluon_decode_available()`. An unknown `kda_decode_backend` raises `ValueError`, as in Kimi-K3; `additional_config` bypasses the CLI's choices. An eligible layer logs `GLM-5.3-Flash KDA decode: AITER single-launch kernel.` once.
- **Route.** `_forward` takes the fused launch when a step has no prefill and at least one decode. The kernel applies the gated RMSNorm, so an eligible layer passes `out_gate` to `_forward` and `forward` skips `o_norm`; other steps, and profile runs without metadata, apply the norm at the end of `_forward`. The route is chosen in `_forward` because a breakable PIECEWISE graph records `forward` once on a decode-only batch and replays only the eager break against each step's metadata, so a route chosen in `forward` would be fixed at capture. FULL graphs capture `_forward` inline, which is safe because GDN FULL graphs replay uniform decode batches only.
- **Weights and indices.**
  - AITER reads the q|k|v conv weight as a contiguous `[3, width, dim]` tensor, while `conv1d.weight` is `[3·dim, 1, width]`.
  - An eligible layer keeps that layout in a non-persistent buffer, `decode_conv1d_weight`. It is allocated once in `__init__`, so graphs keep its address, as in Kimi-K3's ROCm layer.
  - The buffer is refreshed from `conv1d.weight` in two places:
    - the layer's `process_weights_after_loading`, which `BaseModelLoader.load_model` runs after loading and the layerwise reload runs at its end (`reload_weights` and the weight-transfer engines that use it);
    - the conv weight loader, after every shard load, for refits that call `load_weights` directly.
  - The IPC weight cache maps the buffer the daemon filled, so the hook skips it there.
  - State indices go in as an `[N, 1]` view because the block-table column can be strided.
- **Numerics.** AITER keeps the conv and attention outputs in fp32 through the norm; the stock chain rounds to bf16 before `o_norm`. Decode outputs therefore agree to 2 bf16 ulp, not bit for bit.
- **Trade-offs.** A step that does not take the kernel pays one extra `copy_` of the layer output, and under breakable PIECEWISE graphs runs `o_norm` eagerly, the likely cause of the (ii) long-prompt result. Fusing only the conv update and the recurrence, keeping `o_norm` in `forward`, would avoid it, at the cost of part of the decode gain and a new `_aiter_ops` wrapper.
- **Limits.** gfx1250 passes the probe and has not been run. Without a lower bound the stock kernel falls back to −5.0 while AITER's gate would be unbounded, so that configuration keeps the stock chain. AITER asserts a recurrent slot stride of whole 128-float rows. Not measured: TP 1, 4 and 8; inputs over 5120 tokens; concurrency above 64.
- **Weight writes the decode copy does not follow** (from reading the code, not run):
  - `nccl_m2n`'s direct resharding writes parameters without `load_weights` or a reload, so the copy stays stale.
  - Sharded RDT counts the buffer as part of the layer, cannot bake the layer, and stops while building its plan.
  - `--kda-decode-backend triton` keeps the stock chain for both.
  - Not checked: the tensorizer loader, which overrides `load_model`.
  - An AITER kernel that reads `conv1d.weight` in place would remove the copy.
- **Related PRs.**
  - #63544 (draft): FlashInfer fused KDA decode for this layer on CUDA, same structure; whichever lands second adapts.
  - #63070 (draft): breakable CUDA graphs as the ROCm default for GLM-5.3-Flash; configuration (ii) then applies.
  - #56298 (open): targets the separate q/k/v convs, which #60991 merged into one `conv1d` parameter; this PR no longer interacts with it.
  - #63071, #63073 (drafts): speculative decoding on this layer, which keeps the stock chain here.
