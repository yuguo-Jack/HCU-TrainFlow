# [Frontend][EPD] Support JSON metadata references in Rust HTTP frontend

[Upstream PR](https://github.com/vllm-project/vllm/pull/55842) · state: closed · merged: False

## Original PR description

## Summary

Depends on #56090 for the Python/proxy JSON metadata contract. That code has been removed from this PR; the remaining diff is Rust-only.

Accept metadata-only `image_embeds` references through the generic `llm-multimodal` interface, avoiding repeated image preprocessing. Requires `--enable-mm-embeds`, UUIDs, and EC or remote-prefill KV transfer parameters. Registered image-capable models are supported by the library; serving validation covers Qwen3.5 only. Audio/video metadata references and serialized embedding tensors remain out of scope.

Also depends on [smg-project/llm-multimodal#11](https://github.com/smg-project/llm-multimodal/pull/11), targeting `vllm-dev`. The temporary fork pin (`d2385cc50db782c6632a8b651292a203debfeeb1`) must switch to an upstream commit before merging.

Related to #52409 and #54814. No overlap with the Python prerequisite; #55047 / #52722 concern inline preprocessed gRPC features, not this HTTP interface.

## Validation

Previous validation of the combined implementation (including the Python prerequisite):

```bash
cargo test --manifest-path rust/Cargo.toml --locked -p vllm-chat --lib multimodal -j16
cargo test --manifest-path rust/Cargo.toml --locked -p vllm-server --lib prepare_chat_request_maps -j16
```

49 + 7 tests passed. The Rust implementation is unchanged by this split; applicable split-commit hooks passed. These Rust tests and serving evaluation were not rerun after the split.

Historical MUIRBench: Qwen3.5-35B-A3B + Mooncake RDMA, 4E+4PD, V2, concurrency 96, CUDA graphs through 16384 tokens, no eager; 200 warmup plus five repetitions of the first 1200/2600 questions.

|---|---:|---:|---:|
| Python | 63.48 | 59.00% | 0/6000 |
| Rust | 64.12 | 59.82% | 0/6000 |

Sequential runs; not proof of a causal performance or accuracy improvement. NIXL and ECExample were not E2E-tested with this change.
