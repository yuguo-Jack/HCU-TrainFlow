# [KV Offload] Split the CPU offload region across shm files

[Upstream PR](https://github.com/vllm-project/vllm/pull/59546) · state: closed · merged: True

## Original PR description

Pre-faulting the CPU offload region is capped by its single `/dev/shm` file: page-cache inserts into one shmem file are serialized, so more workers or threads stop helping. On one H200 node, eight processes pre-faulting disjoint parts of a 64 GiB file reach 9.8 GiB/s in total. Given one file each, they reach 24.6 GiB/s, and sixteen files reach 44.8 GiB/s. #59430 hits the same ceiling with threads.

Split the region's rows over up to 32 files of at least 1 GiB each. The files are mapped back to back over one anonymous reservation, so the region stays contiguous. Workers with per-rank slots start pre-faulting on different files. Regions under 2 GiB, and other users of `SharedOffloadRegion`, keep a single file.

## Tests

4× H200, measured on `16d4ac4ba3` with this change (the touched files are unchanged on current main):

- GLM-5.3 W4A8, TP4 + EP, 256 GiB native CPU offload: the offload startup step fell from 63.6 to 38.3 s, and pre-faulting from 42.8 to 19.4 s. A 20k-token retrieval prompt answered 8/8 lookups cold and 8/8 after `/reset_prefix_cache`, with 3.9 GB reloaded from CPU.
- `pytest tests/v1/kv_offload tests/v1/kv_connector/unit/offloading_connector tests/v1/kv_connector/unit/test_offloading_connector.py tests/v1/worker/test_utils.py`: 1183 passed. The 7 failing tests need a gated model and fail the same way on main.
- pre-commit, including mypy, passed.
