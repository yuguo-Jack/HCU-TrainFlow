# [Bugfix][ROCm][DSv4] Give zero and subnormal mono MXFP8 groups vLLM's scale code

[Upstream PR](https://github.com/vllm-project/vllm/pull/63689) · state: closed · merged: True

## Original PR description

- `stages/moe.py` (`vllm_mx_code`) and `attention/device.py` (`mx_code`) in the DeepSeek-V4 and V4.1 mono decode kernels: when `q = RN(max(amax, FLT_MIN) / 448)` is an f32 subnormal, return code 0 for `q <= 2^-127` and 1 above it, instead of the exponent-bit result, which is always 1

The four copies take the E8M0 scale code from the exponent bits of `q`. Their docstrings, and vLLM's `mxfp8_e4m3_quantize`, give `clamp(ceil(log2 q) + 127, 0, 254)`. For a subnormal `q` the bit trick gives 1, so every group with `amax <= 448 * 2^-127`, including all-zero groups, gets code 1 where vLLM gives 0. The monokernel I/O tests in #63486 catch this, and it blocks that PR. In practice, zero groups (for example a zeroed norm-weight group) only get a different scale byte and still dequantize to 0. bf16-valued inputs never dequantize differently. Only the f32 attention-output quant (XO) could, for groups with amax below 2.6e-36.

| amax | q | before | after | vLLM rule (Triton / torch op) |
|---|---|---|---|---|
| 0 | FLT_MIN / 448 | 1 | 0 | 0 / 0 |
| 1e-36 | subnormal | 1 | 0 | 0 / 0 |
| 448 * 2^-127 | 2^-127 | 1 | 0 | 0 / 0 |
| prev(448 * 2^-126) | rounds to 2^-126 | 1 | 1 | 1 / 1 |
| 1.0 | normal | 119 | 119 | 119 / 119 |

| check (MI355X) | before | after |
|---|---|---|
| every non-negative finite f32 amax (2,139,095,040), each of the 4 copies | 73,400,322 wrong codes | 0 |
| `test_mono_primitives.py -k scale_codes` (#63486) | 4 failed | 5 passed |
| DSv4.1 layer test, hard case with a zeroed norm group | 48 of 7680 codes wrong per quant, 16/16 runs | 0, 10/10 runs |
| f32-valued tiny groups, dequantized vs vLLM | 195,270 elements differ | 0 |

Decode step time, 20-step CUDA graph, median of interleaved runs (DSv4.1 TP4: 10 runs per arm; DSv4-Pro TP8: pooled runs), with #63576 applied in every DSv4.1 arm:

| case | before (us) | after (us) | delta |
|---|---|---|---|
| DSv4.1 1x1, index source | 75.94 | 76.66 | +0.94% |
| DSv4.1 1x6, index source | 102.86 | 103.03 | +0.17% |
| DSv4.1 8x6, index source | 314.73 | 314.95 | +0.07% |
| DSv4.1 8x6, hard case | 170.75 | 170.67 | -0.05% |
| DSv4-Pro 1x1 | 90.69 | 90.79 | +0.11% |
| DSv4-Pro 1x7 | 124.45 | 124.41 | -0.03% |
| DSv4-Pro 64x1 | 412.24 | 412.84 | +0.15% |

An unchanged-code control arm moved -0.21% to +0.11% on DSv4-Pro and +0.10 us on DSv4.1. The one case outside that is DSv4.1 at one row with an index source: +0.7 us in two 5-round sets and +0.3 us in a follow-up. The same step without the index source doesn't move, and K1's eager device time is unchanged (18.22 vs 18.05 us).
