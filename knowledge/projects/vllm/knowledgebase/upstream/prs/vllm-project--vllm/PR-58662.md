# [Perf][SM100] Use TGV for small-batch BF16 output projections

[Upstream PR](https://github.com/vllm-project/vllm/pull/58662) · state: open · merged: False

## Original PR description

## Purpose

Automatically select FlashInfer TGV for biasless BF16 projections with `(N, K) = (5120, 6144)` and flattened batch sizes 1, 2, 4 or 8 on SM100. This accelerates Qwen3.8-27B's attention and GDN output projections at TP1.

Reuse the existing BF16 custom op and TGV kernel. Other shapes, larger batches, unsupported layouts, batch-invariant execution and explicit backend choices retain their existing paths. The change adds 35 production lines and one parameterized test in the existing kernel test file.

## Test Plan

Compare directly against main `e6c07ea5763bada5da789ed437851ee1526fd5a8`, with only this patch applied. Run main/TGV/TGV/main on one physical GB200, with a fresh server per round and identical BF16/TP1 settings. Use 1024 output tokens, greedy generation, disabled prefix caching, and two client warmups per point. No forced tactic or seeded tuning cache.

Runtime: FlashInfer 0.7.0, Torch 2.13.0+cu132; both arms reuse native extensions from wheel commit `17e50b9b761023d5f2499f062507df1ff49092a4`, rather than a fresh native build. Exact commands, source hashes and runtime audit are in the benchmark artifacts.

```bash
TEST_PY=/home/xuting/inference/benchmarks/.venv-qwen38-tests/bin/python
"$TEST_PY" -m pytest tests/kernels/test_flashinfer_bf16_gemm.py -q
"$TEST_PY" -m pre_commit run --files vllm/model_executor/layers/utils.py tests/kernels/test_flashinfer_bf16_gemm.py
"$TEST_PY" -m pre_commit run mypy-3.12 --hook-stage manual --files vllm/model_executor/layers/utils.py tests/kernels/test_flashinfer_bf16_gemm.py
```

## Test Result

Mean time per output token across two runs per engine:

| Input tokens | Concurrency | Main (ms) | TGV (ms) | Reduction |
|---:|---:|---:|---:|---:|
| 1 | 1 | 10.5121 | 10.4320 | 0.76% |
| 1 | 2 | 10.9731 | 10.8949 | 0.71% |
| 1 | 4 | 11.1267 | 11.0656 | 0.55% |
| 1 | 8 | 11.3712 | 11.3299 | 0.36% |
| 8192 | 1 | 10.6234 | 10.5444 | 0.74% |
| 8192 | 8 | 12.5776 | 12.5367 | 0.33% |

Both adjacent pairs improved in all six cases. Output throughput improved 0.27–0.76%; TTFT results were mixed. Each engine completed 208 measured requests and 212,992 output tokens without failures. Two repeats do not establish statistical significance.

- **13 GPU tests passed**, including numerical agreement, batch-16 fallback and compiled CUDA-graph replay. Changed-file pre-commit and both mypy versions passed.
- **GSM8K subset: 62/64 for both**, no changed final answers or paired losses. There were 24 text differences and one shared truncation (example 12). This is a limited regression check.
- Separate C4 traces show **64 TGV launches per decode step versus zero on main**. They replace 64 cuBLAS GEMM/reduction pairs, removing 64 launches per step across 18 interior steps.

Results, traces and reproduction instructions: `/home/xuting/inference/benchmarks/qwen38-tgv-only-20260924/` (`REPORT.md`, `REPRODUCE.md`, `job-30981/`).
