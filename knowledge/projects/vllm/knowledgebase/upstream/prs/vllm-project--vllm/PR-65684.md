When the builder is set to the advertised MI355X hardware, this feature remains selectable because only PPU is marked unsupported, and it emits `--kv-cache-dtype nvfp4_ds_mla`. That layout is implemented only for SM100: `FlashMLASparseBackend.supports_combination` rejects it when the device capability is not 10 (`vllm/v1/attention/backends/mla/flashmla_sparse.py:250-253`), and the repository contains no ROCm implementation, so the generated MI355X command cannot start. Mark AMD/MI355X unsupported for this feature.
