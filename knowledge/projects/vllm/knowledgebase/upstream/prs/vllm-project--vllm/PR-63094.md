# [Perf][Vision] Fuse Qwen vision QK packing and rotary embedding

[Upstream PR](https://github.com/vllm-project/vllm/pull/63094) · state: open · merged: False

## Original PR description

## Overview

Fuse QK packing and NeoX rotary embedding in Qwen vision attention, removing the intermediate contiguous QK buffer. The model hook enables this on NVIDIA CUDA; unsupported shapes and dtypes use the existing path.

## Claims

- On B300, BF16 packing + rotary is 2.87–6.70x faster under CUDA graphs.
- At S=46,080/B=1 with contiguous position tables, this operation's peak allocation drops from 405 to 202.5 MiB.

## Validation

Rebased onto `1ca0dfb9` on Oct 29. The CI dependency-list conflict is resolved, retaining both upstream and PR entries. The kernel, test and model call-site files are byte-identical to tested head `9027363`. Both CPU metadata tests and applicable changed-file pre-commit checks passed. GPU tests have not been rerun on this head; the B300 measurements below retain their original tested SHA.

Tested head: `9027363e6641fb211526c20ae005251eb3d2f45d`; base: `b3b0bc30590748b859af89832ccc50482dc9b08e`.
B300 SXM6 AC (SM10.3), Python 3.12.3, torch 2.14.0+cu130, CUDA 13.0, Triton 3.8.0.

All 11 contributed tests passed, with no failures or skips. Native-path comparisons use `rtol=atol=0` and check that inputs are unchanged. An additional GPU case with 2,764,800,000 QKV elements passed, as did all 24 benchmark cases in each of two independent processes.

Selected BF16 CUDA graph results, in µs per packing + rotary operation:

| S / B | Position tables | Native p50 / p90 | Fused p50 / p90 | Speedup |
| --- | --- | ---: | ---: | ---: |
| 17 / 1 | contiguous | 3.441 / 3.446 | 1.200 / 1.207 | 2.87x |
| 8,192 / 1 | contiguous | 71.075 / 71.145 | 10.616 / 10.644 | 6.70x |
| 46,080 / 1 | contiguous | 407.770 / 407.903 | 68.722 / 68.753 | 5.93x |
| 46,080 / 1 | strided | 419.673 / 419.701 | 87.581 / 87.608 | 4.79x |

The baseline is native QK packing plus `ApplyRotaryEmb.forward_cuda`, using the same inputs (H=16, D=72). Two processes provide 30 samples per arm/case/mode with alternating order, after 30 warmup calls. Each graph captures 64 operations and each sample times three replays after five warmup replays. CUDA events exclude JIT; no samples were removed. Percentiles describe per-operation batch averages. BF16 eager speedups were 2.90–5.76x.

**FP16 stays on the native fallback:** graph speedup ratios were 0.982–1.002x; eager ratios were 0.944–1.000x, including about 6% overhead in the worst small case.

[All results, raw samples and reproduction scripts](https://github.com/rowanbyte/vllm/tree/7bb3b2d3cd9ca7a64ef69cb1a55845651b7abacb/validation/vision-qk-rope-63094) include both dtypes and layouts. Profiling shows 2→1 launches for contiguous BF16 and 4→1 for strided tables in the sampled cases. The memory figure excludes existing inputs, allocator reserves and graph pools.

```bash
CUDA_VISIBLE_DEVICES="$GPU" .venv/bin/python -m pytest tests/kernels/core/test_fused_vision_qk_rope.py -vv
```

These are B300 component measurements on a shared host with default clocks/power. Other NVIDIA architectures and full-model/TTFT/throughput effects remain untested. The native assets matched the official exact-base wheel, but the kernel environment still has unrelated serving dependency conflicts. The portable evidence scripts received CPU packaging checks; the stored measurements came from the original GPU harness.

## Details

The kernel writes rotated packed QK directly from the QKV projection, preserving the V view and attention backend. It uses FP32 rotation intermediates and wide offsets, with no sequence-length specialization. Unlike #50400's rotation of separate Kimi Q/K tensors, it also removes QK packing.

Changed-file pre-commit checks passed locally, including mypy and CI test tethering. The core-kernel CI dependencies include the kernel and model sources; upstream CI is still waiting on the contributor approval gate.
