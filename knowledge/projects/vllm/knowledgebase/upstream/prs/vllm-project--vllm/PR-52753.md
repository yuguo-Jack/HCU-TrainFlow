# [Bugfix][Core] Pin static FP8 quant pattern to group_shape=None

[Upstream PR](https://github.com/vllm-project/vllm/pull/52753) · state: open · merged: False

## Original PR description

## Summary

- Fix incorrect FP8 quant fusion when static per-group quantization is used.
- Root cause: static per-group FP8 quant reuses the static quant op with `group_shape=(-1, group_size)`, but the pattern matcher only subset-matches kwargs. An unpinned static pattern could wrongly fuse per-group quant into per-tensor fused kernels.
- Pin `group_shape=None` explicitly in `MatcherQuantFP8` static quant pattern construction.
- Include `MatcherQuantFP8` in quant fusion pass `uuid()` methods so pattern construction changes invalidate the compilation cache.

Changed files:
- `vllm/compilation/passes/fusion/matcher_utils.py`
- `vllm/compilation/passes/fusion/rms_quant_fusion.py`
- `vllm/compilation/passes/fusion/act_quant_fusion.py`
- `vllm/compilation/passes/fusion/attn_quant_fusion.py`
- `vllm/compilation/passes/fusion/mla_attn_quant_fusion.py`

## Why this is not duplicating an existing PR

Searched open PRs for static FP8 quant pattern / `MatcherQuantFP8` uuid / quant fusion cache invalidation. No open PR currently pins static quant patterns to `group_shape=None` or adds `MatcherQuantFP8` to these fusion pass uuids for this fix.

## Test plan

- [ ] Reproduce prior failure: static per-group FP8 quant path with `torch.compile` + quant fusion enabled
- [ ] Confirm per-group quant is no longer fused into per-tensor fused kernels
- [ ] Smoke RMSNorm / activation / attention / MLA quant fusion paths with static FP8
- [ ] Confirm compilation cache invalidates after matcher pattern changes (uuid update)
- [ ] Await CI compilation / quantization related jobs
