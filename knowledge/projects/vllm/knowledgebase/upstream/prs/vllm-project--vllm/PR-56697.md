# [Perf][Marlin] Reduce MXFP4 MoE padding on SM90

[Upstream PR](https://github.com/vllm-project/vllm/pull/56697) · state: closed · merged: False

## Original PR description

## Purpose

Reduce MXFP4 expert padding for ordinary Marlin on CUDA SM90 with BF16 activations and `VLLM_MARLIN_INPUT_DTYPE` unset. Use 64-channel intermediate alignment instead of 128 while retaining 256-channel hidden alignment and the existing guards for other backends/dtypes. DeepSeek-V4.1-Flash-1017 at TP8 has logical N288, so the physical intermediate width becomes **320 instead of 384**. Existing loaders forward activation dtype; no C++ kernel change is required.

Applicability: this is a backend/architecture/dtype policy, with no model-name check. It applies to MXFP4 MoE weights using ordinary Marlin on SM90, BF16 activations, and no Marlin input-dtype override. Only intermediate widths whose 64- and 128-channel rounding differ can shrink. FP8 MoE, batched Marlin and the other guarded paths retain their existing policy. DeepSeek is the model-level performance example validated below; gains for other models have not been established.
Duplicate checks refreshed on October 29 found no separate open PR implementing this alignment policy. #50583 changes Kimi model/backend allocation ownership, #55232 changes compressed-tensors backend selection, and merged #57204 removes MegaMoE/DeepGEMM model-path padding. They address different paths. Related #49951 fixes ModelOpt NVFP4 quantization-group TP boundaries; this change preserves the checkpoint partition and only reduces Marlin's physical padding.

## Model and serving results

Actual TP8 worker metadata confirmed N384→N320 on eight ranks across 40 routed target layers. Their four expert-weight/scale parameters total **48,129,638,400→40,108,032,000 logical typed bytes per rank**, saving **7.470703125 GiB (16.6667%)**. This is not total VRAM, alias-deduplicated resident allocation, allocator peak or extra KV capacity.

Serving used H20×8 TP8, Marlin BF16/non-A8, DSpark5 adaptive verification, 64K context, seq32/batch8192/long-prefill threshold2048, fixed KV allocation, no prefix cache/LMCache, common CUDA graphs and NVLS=0. P changes only padding and retains baseline FlashMLA attention. The stock primary benchmark used 128 frozen rendered-text requests, each 8192 input/512 output tokens, concurrency 32:

