# [Core][Bugfix] Roll back eager prefix-cache registration on uncommitted free

[Upstream PR](https://github.com/vllm-project/vllm/pull/43569) · state: open · merged: False

## Original PR description




## Purpose

`KVCacheManager.allocate_slots` calls `coordinator.cache_blocks`, which inserts block hashes into `BlockPool.cached_block_hash_to_block` **before** the worker writes the K/V bytes. The registration covers `total_computed_tokens + num_new_tokens` — the range the worker is *expected* to compute this step, not what it has *already* written.

If the request is preempted/aborted before the worker actually writes those bytes (priority-preempt mid-`schedule()`, KV-connector load failure, etc.), the standard free path only decrements `ref_cnt` and pushes the block onto the free queue — the hash entry and `block.block_hash` survive. A later request whose `request.block_hashes` matches will "cache-hit" a block that was never actually written to, reading uninitialized memory.

This PR adds an explicit lifecycle for eager registrations using a FIFO bucket queue:

- `BlockPool._uncommitted: list[dict[req_id, list[KVCacheBlock]]]` holds one bucket per in-flight scheduler step.
- `BlockPool.begin_step()` pushes a new bucket; called at the top of `Scheduler.schedule()`.
- `BlockPool.commit_step()` pops the oldest bucket; called at the top of `Scheduler.update_from_output()` once the worker has confirmed its writes for that step.
- `BlockPool.rollback_uncommitted(req_id)` iterates every bucket, pops the request's pending entries, and evicts them from the cache map via the existing `_maybe_evict_cached_block` helper.

Preempt and abort paths call `rollback_uncommitted` **before** `free`:

```python
# _preempt_request and KV-connector load-failure path
self.kv_cache_manager.rollback_uncommitted(request.request_id)
self.kv_cache_manager.free(request)
```

The normal finish path calls only `free(request)` (unchanged from `main`). By that point the worker has confirmed the writes and `commit_step` has already popped this step's bucket, so the entries stay in the cache map for future hits.

### Why FIFO buckets (not a single global dict)

The first version used a single `dict[req_id, list[block]]` cleared at step boundaries. Codex review correctly flagged that this is unsafe in two ways:

1. **Sync, same-step finish**: a request that hits EOS in `update_from_output` would be freed *after* the worker wrote its bytes but *before* the next `schedule()` could mark them committed — so the eager rollback would erase valid cache entries.
2. **Async batch queue** (`EngineCore.step_with_batch_queue`): multiple `schedule()` calls may be in flight before the oldest one's worker completes, so a single global commit at the next `schedule()` would erase entries whose worker writes haven't been confirmed yet.

The per-step FIFO bucket queue closes both windows: commit happens at the *top* of `update_from_output` for the specific step whose worker just confirmed; rollback iterates every still-pending bucket so a request preempted/aborted at any point removes its zombies from every in-flight step.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Hide uncommitted blocks from prefix-cache lookups**

Publishing the block hash to `cached_block_hash_to_block` before the step is committed lets other requests cache-hit data that has not been written yet. In the `A:[A B C D E F]` / `B:[A B C D G H]` case, `B` can touch `A`’s eager block, then `A` is preempted and rolled back, but `B` still remains scheduled with that prefix treated as computed, which can yield incorrect outputs from unwritten KV. The new `_uncommitted` buckets only prevent future hits; they do not protect already scheduled consumers, so uncommitted entries need to be hidden from lookup until commit (or dependent requests must be invalidated).

Independent repro, in case it helps move this forward: the bug is still present on current `main` (`a2fb482732`), and it reproduces in **sync** scheduling too, not only with the batch queue.

I hit it with a CPU-only scheduler fuzzer that keeps a shadow of what each KV slot holds. It drives the real `Scheduler`/`KVCacheManager`/`BlockPool` with no model, and checks that every position a scheduled request attends to holds that request's own token. Under the `priority` policy, a running request that was already scheduled earlier in the same `schedule()` call gets preempted for a higher-priority one. The rollback branch (`if preempted_req in scheduled_running_reqs:`) restores the budget and drops the scheduling, but the blocks `allocate_slots` eagerly cached for that chunk keep their hashes. When the request resumes, it gets a prefix-cache hit on KV that was never computed.

A deterministic, CPU-only test against current `main` (9 blocks, one low-priority chunked prefill, one high-priority request). It fails with `A resumed with 80 tokens treated as computed, but only 64 were ever computed`:

```python
# SPDX-License-Identifier: Apache-2.0
"""Repro: under the PRIORITY policy, a running request that was already
scheduled earlier in the same step can be preempted to make room for a
higher-priority one. Its scheduling is rolled back, but allocate_slots() has
already cached the full blocks of the chunk it was going to compute. Those
blocks keep their hashes, so when the request resumes it gets a prefix-cache
hit on KV that was never computed."""
import pytest

from tests.v1.core.utils import EOS_TOKEN_ID, create_requests, create_scheduler
from vllm.sampling_params import SamplingParams
from vllm.utils.hashing import sha256
from vllm.v1.core.kv_cache_utils import get_request_block_hasher
from vllm.v1.outputs import ModelRunnerOutput
from vllm.v1.request import Request

BS = 16


def _req(rid, n, priority, base):
    create_requests(1)  # initialise the NONE hash
    params = SamplingParams(ignore_eos=True, max_tokens=8)
    params.update_from_generation_config({}, EOS_TOKEN_ID)
    return Request(request_id=rid, prompt_token_ids=[base + i for i in range(n)],
                   sampling_params=params, pooling_params=None,
                   block_hasher=get_request_block_hasher(BS, sha256),
                   priority=priority)


def _step(sched):
    out = sched.schedule()
    ids = list(out.num_scheduled_tokens)
    sampled = [[] if sched.requests[r].is_prefill_chunk else [7] for r in ids]
    sched.update_from_output(out, ModelRunnerOutput(
        req_ids=ids, req_id_to_index={r: i for i, r in enumerate(ids)},
        sampled_token_ids=sampled, logprobs=None, prompt_logprobs_dict={},
        pooler_output=[]))
    return out


@pytest.mark.parametrize("async_scheduling", [False])
def test_preempted_same_step_chunk_not_cached(async_scheduling):
    sched = create_scheduler(scheduling_policy="priority", num_blocks=9, block_size=BS,
                             max_num_batched_tokens=256, enable_prefix_caching=True,
                             max_model_len=256, skip_tokenizer_init=True,
                             async_scheduling=async_scheduling)
    a = _req("A", 95, priority=1, base=1000)   # low priority
    b = _req("B", 32, priority=0, base=5000)   # high priority

    sched.add_request(a)
    sched.max_num_scheduled_tokens = 32        # chunk A's prefill
    out = _step(sched)                         # A: [0, 32)
    assert out.num_scheduled_tokens == {"A": 32}
    sched.add_request(b)
    sched.max_num_scheduled_tokens = 64
    # Cap each prefill chunk at 32 tokens (applies once >1 request is eligible).
    sched.scheduler_config.long_prefill_token_threshold = 32
    out = _step(sched)                         # A: [32, 64), B: [0, 32)
    assert out.num_scheduled_tokens == {"A": 32, "B": 32}
    assert a.num_computed_tokens == 64

    out = _step(sched)                         # A allocated for [64, 95), then preempted for B
    assert "A" in (out.preempted_req_ids or set()), out
    assert "A" not in out.num_scheduled_tokens

    # A only ever computed [0, 64). On resume it must not treat more as computed.
    for _ in range(20):                        # B decodes to completion first
        out = _step(sched)
        if "A" in out.num_scheduled_tokens:
            break
    assert "A" in out.num_scheduled_tokens, out.num_scheduled_tokens
    reused = a.num_computed_tokens - out.num_scheduled_tokens["A"]
    assert reused <= 64, (
        f"A resumed with {reused} tokens treated as computed, but only 64 were ever "
        f"computed: the block for [64, 80) was cached by the rolled-back chunk")
```

`free()` now unconditionally calls `rollback_uncommitted`, but in the normal synchronous path (`EngineCore.step`) finished requests are freed inside `scheduler.update_from_output()` before the next `schedule()` call. Since `commit_step()` only runs at the top of the next `schedule()`, any request that finishes in the same step it cached full blocks (e.g., stops on first generated token) will have those valid cache entries rolled back, causing deterministic prefix-cache miss regressions for subsequent requests sharing that prefix.
