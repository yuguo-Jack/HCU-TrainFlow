# [Rust Frontend] Register request observers through ServeExtensions

[Upstream PR](https://github.com/vllm-project/vllm/pull/61937) · state: open · merged: False

## Original PR description



## Overview

Lets a binary that embeds `vllm-server` register `RequestObserver`s: `ServeExtensions` bundles the existing router extension with request observers, and `serve_with_extensions` hands the observers to the server's `Llm`. Second of the two PRs proposed in #58313, stacked on #61936 (only the last commit is new here). Related: #44757.

## Claims

- A binary built on `vllm-server` can register observers with `ServeExtensions::new().request_observer(...)` and run `serve_with_extensions`. Every request that generates through the server's `Llm` reaches them.
- `serve` and `serve_with_router_extension` keep their signatures and behavior.
- No behavior change when no observer is registered.

The new test sends a non-streaming chat completion over HTTP with an observer registered through `ServeExtensions`, and checks that it receives exactly one `FinishedRequest` with the model name, finish reason, and generated token count. No model or serving output is affected, so no model evals were run.

## Details

**Usage.**

```rust
let extensions = ServeExtensions::new()
    .router(|router| router.route("/usage", get(usage_handler)))
    .request_observer(usage_observer.clone());
vllm_server::serve_with_extensions(config, shutdown, extensions).await?;
```

**Design.**

- `ServeExtensions` is a builder for two hooks: the existing router extension and request observers. Like `serve_with_router_extension`, it is a composition hook for custom binaries, not a stable plugin API.
- Observers run in registration order after the Prometheus recording. `RequestObserver` is implemented for `Arc<T>`, so a caller can register an observer and keep a handle to it, for example to read its counters.
- All three entry points end in one private generic `serve_inner`. `serve_with_router_extension` passes its closure through unboxed, so its signature and bounds are unchanged.
- `into_parts` splits the router extension off before startup: it is `Send` but not `Sync`, and the observers are borrowed across the startup `.await`s.
- The server already shuts down its `Llm` before returning, and `Llm::shutdown` drains the observers after the engine client (#61936), so queued observer work finishes before `serve_with_extensions` returns.

**Limitations.**

- The test builds the router with the observers that `ServeExtensions` yields instead of calling `serve_with_extensions`, because `build_state` needs a model to load backends and an engine handshake. The remaining wiring in `build_state` is a single `with_request_observers` call.
- `vllm-rs` itself has no way to register observers; a custom binary that depends on `vllm-server` is needed, as with the router extension.

**Not duplicating existing work.** The same searches as #61936 found no open PR that adds observer registration to `vllm-server`. #61639 and #61296 touch `build_state` and merge cleanly with this change.
