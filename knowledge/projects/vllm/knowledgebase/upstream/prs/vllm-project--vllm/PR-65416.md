# [XPU] fix case test_p2p_lifecycle_e2e.py and test_mm_prefix_lm.py

[Upstream PR](https://github.com/vllm-project/vllm/pull/65416) · state: closed · merged: True

## Original PR description



## Overview
Fix two independent root causes behind three failed jobs in [Intel CI build 16461](https://buildkite.com/vllm/intel-ci/builds/16461):

Align the producer and consumer block sizes in the P2P lifecycle regression test.
Pad Triton prefill attention’s head-dimension tile to at least 16.

## Root Cause
P2P lifecycle test: incompatible default block sizes
The producer uses native LLM, while the consumer uses VllmRunner. With batch invariance enabled, both select Triton Attention, but their effective defaults differ on XPU:

`test_p2p_lifecycle_e2e.py` :
Producer: 16 tokens per block.
Consumer: 64 tokens per block.
Consequently, their offloaded blocks have different byte sizes (368640 versus 1474560). The P2P handshake correctly rejects this incompatible layout. The test then fails at assert buffered.is_set() because no transfer completion arrives—not because buffered completion handling is broken.

Set block_size=16 in the shared engine parameters so both peers use the same layout. Also assert that the disconnect was injected, ensuring the test exercises its intended failure ordering rather than passing without reaching it.

`test_mm_prefix_lm.py` :
Multimodal tests: insufficient Triton dot tile width
Both multimodal jobs fail in test_mm_prefix_lm_cache_hit_inside_image. Its tiny Gemma3 model has a vision attention head dimension of 8.

The prefill kernel previously used next_power_of_2(head_dim), producing a tile width of 8. For tl.dot(p, v, acc), this is the output dimension, but the XPU Triton compiler requires it to be at least 16:


Use max(16, next_power_of_2(head_dim)). Existing masks zero-fill padded loads and restrict output stores to the actual head dimension. Tile widths for head dimensions of 16 or greater remain unchanged.
