# [Bugfix][KV Connector] Guard optional LMCache events hook

[Upstream PR](https://github.com/vllm-project/vllm/pull/62223) · state: open · merged: False

## Original PR description



## Overview

Guard the optional LMCache `get_kv_events` hook so native engines without it return no events instead of crashing the worker. Fixes #62216.

## Claims

- Engines without a callable events hook return `None`.
- Engines implementing the hook retain existing event conversion and exception behavior.
- One regression test exercises an engine without the method, which the existing unrestricted mock engine concealed.

**Compatibility changes were applied only in the private test environment and are excluded from this PR:** scheduler metadata for the lookup factory, one `lookup_unpin` call per ID, and a bridge from current vLLM KV views to LMCache 0.3.11's legacy cache layout. The same compatibility adapter was held constant for the original/patched comparison and HTTP run. This validates the events fix; it does not claim that the unmodified release combination is otherwise compatible.

SmolLM2-135M-Instruct used FP16, eager execution, V2 runner, max_model_len=512, one sequence, 256 MiB KV cache, prefix caching disabled, and two 190-token prompts. This is a correctness smoke test, not the full repository suite or a performance benchmark; the layout bridge adds staging copies. Inference exited 0 but vLLM force-killed its EngineCore during teardown; HTTP shutdown logged a semaphore warning. GPU cleanup and HTTP port closure were verified.

"""Real CUDA inference reproducer; validation artifact, outside the PR diff."""
import argparse
import json
import os
from pathlib import Path

os.environ.setdefault("VLLM_NO_USAGE_STATS", "1")
os.environ.setdefault("LMCACHE_TRACK_USAGE", "false")
os.environ.setdefault("HF_HUB_DISABLE_TELEMETRY", "1")
os.environ.setdefault("LMCACHE_CHUNK_SIZE", "64")
os.environ.setdefault("LMCACHE_LOCAL_CPU", "True")
os.environ.setdefault("LMCACHE_MAX_LOCAL_CPU_SIZE", "0.25")
os.environ.setdefault("OMP_NUM_THREADS", "4")


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--native", action="store_true")
    parser.add_argument("--output", required=True)
    args = parser.parse_args()

    import torch
    from vllm import LLM, SamplingParams
    from vllm.config import KVTransferConfig

    kwargs = {}
    if args.native:
        kwargs["kv_transfer_config"] = KVTransferConfig(
            kv_connector="LMCacheConnectorV1",
            kv_role="kv_both",
            kv_connector_extra_config={"use_native": True},
        )
    llm = LLM(
        model=str(Path(__file__).parent / "smollm2-135m"),
        dtype="float16",
        seed=0,
        max_model_len=512,
        max_num_seqs=1,
        max_num_batched_tokens=512,
        kv_cache_memory_bytes=256 * 1024 * 1024,
        gpu_memory_utilization=0.2,
        enforce_eager=True,
        enable_prefix_caching=False,
        **kwargs,
    )
    prompt = (
        "Paris is the capital of France. France is a country in Europe. "
        "The Seine river flows through Paris. "
    ) * 8 + "\nQuestion: What is the capital of France?\nAnswer:"
    results = []
    for iteration in range(2):
        response = llm.generate(
            [prompt], SamplingParams(temperature=0, max_tokens=16), use_tqdm=False
        )[0]
        generated = response.outputs[0]
        assert len(response.prompt_token_ids) >= 128
        assert generated.token_ids, "Expected nonempty generated tokens"
        result = {
            "iteration": iteration,
            "prompt_tokens": len(response.prompt_token_ids),
            "text": generated.text,
            "token_ids": generated.token_ids,
        }
        results.append(result)
        print("INFERENCE_RESULT", json.dumps(result), flush=True)
    assert results[0]["token_ids"] == results[1]["token_ids"], results
    Path(args.output).write_text(json.dumps({
        "native_lmcache": args.native,
        "gpu": torch.cuda.get_device_name(),
        "torch": torch.__version__,
        "results": results,
    }, indent=2) + "\n")
    print("INFERENCE_PASS", flush=True)


if __name__ == "__main__":
    main()

## Details

Both worker paths call the events hook each step, but the native `LMCacheConnectorV1Impl` has no `get_kv_events`. Use `getattr` plus `callable`, matching the adjacent `get_block_ids_with_load_errors` guard. Implemented-method errors still propagate. This adds no native event publishing support.

Duplicate checks refreshed on 2026-10-17: issue/comments, open PRs referencing 62216, open LMCache/events PRs, and merged `get_kv_events` PRs. No equivalent fix found. Related #61893 controls event publication, #59603 forwards failed loads, and #49689 fixes aggregation; none provides this missing-hook fallback. The issue reporter's reproducer and proposed guard motivated this patch.
