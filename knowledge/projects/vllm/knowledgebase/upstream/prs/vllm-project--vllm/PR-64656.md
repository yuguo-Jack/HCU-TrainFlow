# [Test][UMBP] Restore a Mamba2 hybrid end to end through UMBP

[Upstream PR](https://github.com/vllm-project/vllm/pull/64656) · state: open · merged: False

## Original PR description

- Add a Granite 4.0-H hybrid restore test to `test_mori_token_e2e.py`, run through embedded UMBP.
- Require bitwise-equal tokens and logprobs against a local GPU prefix hit, plus an exact external-hit count.
- Cover a prompt ending mid-block and one ending exactly on a block boundary.

No hybrid model restores through UMBP end to end today. The Nemotron-H GSM8K row never gets a prefix hit because its 1088-token hybrid block is longer than the prompts, so the Mamba boundary-state handoff is only covered with fake runtimes. Mamba hybrids have no batch-invariant kernels, so a cold run can't be the reference, and prompts go one at a time because async load timing changes the batch layout and batched hybrid outputs aren't bitwise stable. On MI350X with MORI v1.2.3.post1 built with UMBP, `pytest -v -s -rs v1/kv_connector/umbp_integration/test_mori_token_e2e.py -k hybrid` passed 10/10 in a loop and the whole file gave 3 passed, but every case fails once the restored Mamba pages are zeroed after the load. The MI355 UMBP integration group already runs this directory, so CI is unchanged. No open UMBP PR (#61795-#61798, #63002, #59276) restores a hybrid end to end, though #63830 and #63670 rework Mamba align mode and may need this test adjusted if they land first.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.

#### 1. 🟠 Should fix: Hybrid test cannot catch an align-mode checkpointing bug consistent across both paths: this PR uses the GPU hit, not the cold run, as oracle
`tests/v1/kv_connector/umbp_integration/test_mori_token_e2e.py:178`

`test_hybrid_restore_matches_local_prefix_hit` discards the cold `llm.generate` output and only compares the UMBP restore with a GPU prefix hit. Both paths resume from the same stored Mamba boundary state, so the test checks that UMBP round-trips the state pages, not that the align-mode checkpoint itself is correct. That is the documented intent: Mamba hybrids have no batch-invariant kernels, so an exact cold comparison would not hold. Checkpoint correctness against a no-cache run is covered by the `test_apc_*` tests in `test_hybrid.py`. Optionally, keep the cold output and add a tolerance check (`check_logprobs_close`) as a cheap sanity guard.

**Who is affected:** Only test coverage: CI runs of the ROCm+MORI UMBP integration test on the granite-4.0-h-350m hybrid.
