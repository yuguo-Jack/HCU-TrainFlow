# [Core] Shared abstractions for specialized decode kernels

[Upstream PR](https://github.com/vllm-project/vllm/pull/61311) · state: open · merged: False

## Original PR description

_(the text below is written by myself)_

This is an effort to (1) increase standardization and (2) limit LoC changes in model files as a result from adding numerous specialized decode kernels (_aka "monokernels"_). 

The kernels themselves will naturally remain difficult to review thoroughly, but ideally model code should remain easy to review. The abstraction layer should deliberately be made as thin as possible,

Heavily inspired by https://github.com/vllm-project/vllm/pull/61867, and https://github.com/vllm-project/vllm/issues/60904.

**Note: this PR drops `--monokernel` in favor of `--specialized-decode`**

# 1. Goal

**An author of a specialized decode kernel should write:**

1. A FlyDSL/CuTeDSL implementation and its utilities, in `vllm/models/<model>/<vendor>/`
2. The conditions under which it can run
3. Minimal glue connecting it to the model code

**The author should not have to write:**

1. Another new way to glue the kernel into the model code
3. Basic config checks during start up, re-used by many specialized kernels needs anyway (parallelism, spec decode, graph mode)
4. Checks of whether to run the specizlied kernel or regular vllm code at every step
5. TP rank agreement of the above
6. Updating of CUDA graph capture sizes
7. Kernel selection when one model has more than one specialized kernel
8. Optional: JIT/warm-up registration


This PR implements the latter points.

# 2. How

Declare when the specialized kernel can run:
```python
# refuse causes crash, skip causes fallback to regular vllm execution

@dataclass(frozen=True)
class DecodeSpec(Generic[KernelT]):
    name: str
    supports: frozenset[Feature]
    widths: Callable[[VllmConfig], tuple[int, ...]]
    refuse_config: Callable[[VllmConfig], list[str]]
    refuse_model: Callable[[Any], list[str]]
    refuse_caches: Callable[[VllmConfig, KernelT, Mapping[str, Any]], list[str]]
    skip_step: Callable[[VllmConfig, KernelT, int], str | None]
    build: Callable[[VllmConfig, Any, tuple[int, ...]], KernelT]
```

`KernelT` is a stand-in for the entire model forward, implementing

```python
class DecodeImpl(Protocol):
    cache_layers: tuple[str, ...]

    def run(self, step: Step, input_ids, inputs_embeds, **kwargs) -> Any: ...
    def bind_caches(self, caches: Mapping[str, Any]) -> None: ...
```

**Optional:** A kernel that compiles its launches from keys (one per width, per layer plan, or whatever the kernel keys on) can additionally implement

```python
@runtime_checkable
class DecodeWarmable(Protocol):
    def warmup_keys(self) -> list[Any]: ...
    def compile(self, key: Any) -> None: ...
```

which will cause the dispatcher to auto-register it for warmup. The existing DSv41 implementation uses this, and so would https://github.com/vllm-project/vllm/pull/60889, https://github.com/vllm-project/vllm/pull/60731, and https://github.com/vllm-project/vllm/pull/60683. The Kimi K3 nvidia kernel jits eagerly since its specialized decode kernel is not created in a region with an active jit registry; hence, this feature is optional.

Once the kernel author has written their CuteDSL/FlyDSL kernel, the two remaining points

> 2. The conditions under which it can run
> 3. Minimal glue connecting it to the model code

is implemented through a Spec and wiring the kernel code through a DecodeImpl. The remainder is taken place by the shared `SpecializedDecode` utility.

_Note: we deliberately put no further constraint on how one implements `run`. There is a big benefit letting each model decide exactly how to structure this. We've already seen many different ways of structuring the underlying flydsl/cutedsl kernels._

## 2.1 Model-side code

The model-side code will look like this:

```python
class MyForCausalLM(nn.Module):
    def __init__(self, *, vllm_config, prefix=""):
        self.decode_spec = select_decode_spec(vllm_config, SPECS)
        self.specialized_decode: SpecializedDecode[MyKernel] | None = None

    def process_weights_after_loading(self):
        # optionally: this code can also be placed in the model state init, but then you cannot benefit from auto-registration of warmup
        if self.decode_spec is not None:
            self.specialized_decode = SpecializedDecode(
                self.model, self.vllm_config, self.decode_spec
            )

    def forward(self, input_ids, positions, intermediate_tensors=None, inputs_embeds=None, **kwargs):
        decode = self.specialized_decode
        if decode is not None:
            step = decode.plan(positions, intermediate_tensors)
            if step is not None:
                return decode.run(step, input_ids, inputs_embeds, **kwargs)
        return self.model(input_ids, positions, intermediate_tensors, inputs_embeds, **kwargs)
```

plus one hook to prepare the kv cache

```python
class MyModelState(DefaultModelState):
    def initialize_kv_cache(self, kv_cache_config, block_tables):
        super().initialize_kv_cache(kv_cache_config, block_tables)
        if self.model.specialized_decode is not None:
            self.model.specialized_decode.bind_caches()
```

On the model side nothing else needs to be touched. 

# 3. How to: adding a second kernel for the same model

Say DSv4.1 gets a gfx942 kernel next to the gfx950 one. Write the FlyDSL kernel, then:

```python
# vllm/models/deepseek_v41/amd/specialized_decode.py

class DSV41Gfx942Kernel(DSV41Kernel):           # reuse what you want
    def run(self, step: Step, input_ids, inputs_embeds, **kwargs) -> Any: ...
        ...
        return self.runner.run_gfx942_kernel(...)

    def compile(self, key):
        width, idx = key
        self.runner.kernels(width, self.plans[idx])


def _refuse_config_gfx942(vllm_config) -> list[str]:
    reasons = []
    if not current_platform.is_gfx942():
        reasons.append("needs a gfx942 GPU")
    ...
    return reasons


DECODE_SPEC_GFX942 = DecodeSpec[DSV41Gfx942Kernel](
    name="dsv41-cdna3",
    supports=frozenset({Feature.PIPELINE_PARALLEL}),   # no spec decode here
    widths=lambda cfg: tuple(range(1, 17)),            # fewer rows than gfx950
    refuse_config=_refuse_config_gfx942,
    refuse_model=_refuse_model,                        # shared with gfx950
    refuse_caches=_refuse_caches,
    skip_step=_skip_step,
    build=DSV41Gfx942Kernel,
)

SPECS = (DECODE_SPEC_GFX950, DECODE_SPEC_GFX942)
```

Then one line in the model:

```python
self.decode_spec = select_decode_spec(vllm_config, SPECS)
```

The dispatcher takes the first compatible spec. Specializing on something other than arch works the same way. A hyper-specialized batch-size 1 kernel can just set `widths= lambda cfg: (1,)` and be placed first in the `SPECS` list.

# 4. How to: a kernel that only covers part of a layer

A specialized decode kernel might cover only part of a layer, e.g. only o-proj through post-moe AR.

The common dispatcher has no concept of this, and does not need one, because the kernel owns the layer loop. Hence it can decide at every layer whether to run it as a single monokernel, or to run it in the regular vllm model code. 

When we run part of a layer as a specialized kernel, we simply run the regular vllm model code and _inject_ the specialized kernel:

```python
class DSV41Kernel:
    def run(self, step: Step, input_ids, inputs_embeds, **kwargs) -> Any:
        self.model.prologue(input_ids, inputs_embeds, **kwargs)
        ....
        for idx in range(self.embed_layer, self.layer_end):
            layer, plan = model.layers[idx], self.plans.get(...)
            ffn = out = None
            if plan.ffn_only:
                ffn = partial(self.launch_ffn, plan)      # a part of a layer
            else:
                out = self.launch_whole(plan, hidden, positions, ...)
            if out is None:
                out = layer(hidden, positions, ..., decode_ffn=ffn) # run regular vllm and inject
            hidden, residual, post_mix, res_mix, pre_mix = out
        ...
```

```python
class DeepseekV4DecoderLayer(nn.Module):

    def forward(
        self,
        x: torch.Tensor,
        ...
        decode_ffn: Callable | None = None,
    ) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor, torch.Tensor, torch.Tensor]:
        ... # run pre etc
        x = self.attn(positions, x, None)
        if self.use_sequence_parallel:
            x = sp_reduce_scatter(x)
        elif not self.attn.wo_b.reduce_results:

```
