# [Bugfix][KV Connector][ROCm] MoRIIO hybrid READ: skip locally cached prefix pages

[Upstream PR](https://github.com/vllm-project/vllm/pull/62190) · state: open · merged: False

## Original PR description

## Overview

Draft, written with Claude Code; stays draft until the submitter reviews every line. MoRIIO hybrid (KDA/Mamba) READ re-reads attention pages the decoder already caches; this reads only external-token pages.

Not duplicates: #48471 (non-hybrid length mismatch), #62165 (SWA tail clipping), #60867 (multi-group hybrid READ at the same call site; the later one rebases).

## Claims

- With a decoder prefix-cache hit, hybrid READ moves only the attention pages for tokens `[N-1-E, N-1)` (`N` prompt length, `E` final `num_external_tokens`). KDA/Mamba transfer is unchanged.
- Tables that do not cover that range raise `MoRIIOError` instead of being tail-aligned.
- No throughput claim; the tested workload is prefill-queue bound.

## Details

Root cause on the decoder:

1. The local prefix hit covers `[0, L)`, so `E = N - 1 - L`.
2. `update_state_after_alloc` receives the complete attention table, cached pages included.
3. `_align_read_blocks` paired P and D tables by length and tail, so READ also covered `[0, L)`.
4. Fix: slice both by page `[(N-1-E) // B, ceil((N-1) / B))`, `B` = attention block size x DCP when sharded.

```diff
-local_attn, remote_attn = self._align_read_blocks(local, remote, self._max_decode_tail_blocks)
+local_attn, remote_attn = self._select_read_attention(request, num_external_tokens, local, remote)
```

- Block hashes cannot mark cached pages: synchronous READ may hash new receive pages first.
- Contract change: a shorter decoder table (the removed test's receive suffix) now raises; a real `KVCacheManager` case and the GPU run pass complete tables.
