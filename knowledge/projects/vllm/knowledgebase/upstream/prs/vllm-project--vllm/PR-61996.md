# [Perf][Sampler] Speed up the small-batch split top-p pipeline

[Upstream PR](https://github.com/vllm-project/vllm/pull/61996) · state: closed · merged: True

## Original PR description



## Overview

The small-batch split top-p pipeline (#54651) caps its grid at one program per SM (`S * B <= num_SMs`), and at that occupancy its step kernels are latency-bound. On a 148-SM GPU S drops to 2 at 38 rows, so a top-p call at 38-64 rows (e.g. 8 requests x 8 spec-decode verify tokens) takes about twice as long as at 37 rows. This PR makes two changes:

1. It keeps splitting rows past one wave while each slice still spans at least 7168 vocab entries.
2. It lets MRV2 skip the split pipeline when no row is top-p-only. Today the pipeline is still launched in that case, as 7 kernels whose programs all exit immediately.

cc @njhill

## Claims

- With the `has_topp_only_rows` hint that MRV2 passes, `apply_top_k_top_p` on <= 64 rows is as fast or faster for every row mix measured: all top-p-only, half and half, and all top-k on both GPUs, plus 1, 10% and 25% top-p-only rows on B300. This holds on B300 (148 SMs) and H200 (132 SMs), across the vocab sizes of current models (120K-262K, plus 32K). Main -> this PR:
  - Top-p-only rows, where main is at S=2: 1.22-2.16x on B300 and 1.05-1.90x on H200.
  - Batches that mix top-k rows with top-p-only rows, B >= 32, V >= 120K: 1.43-2.70x. At 32K, where S changes only from B=38 on B300 and B=34 on H200, it is 1.00-1.62x. The fewer top-p-only rows, the bigger the win: with a single top-p-only row, up to 3.7x at V=151936 and 4.4x at V=262144 (B300).
  - Batches where every row has top-k (e.g. the Qwen3.8 and Gemma 4 defaults): 1.00-1.21x. MRV2 no longer launches the split pipeline for them.
  - The worst ratio, 0.97x, is in configs where nothing changes, within the A/A noise. Callers that do not pass the hint get the same gains, except that all-top-k batches run at 0.90-0.98x (see Change 2).
- Real MiMo-V2.6 spec-decode verify rows (top_p 0.95) on B300: 561 -> 219 us at B=38 (2.56x) and 565 -> 318 us at B=64 (1.78x).
- End to end on the Triton sampler path (B300):
  - Llama-3-8B-Instruct, seeded top-p, c=48: median ITL -5.1%.
  - MiMo-V2.6-Pro TP4 with DFlash K=7, c=8: top-p goes from 558 to 301 us per step, and GPU busy time excluding MoE GEMMs drops by 0.27 ms of a 22.7 ms decode step.

<summary>Reproduction script (bench_topp_split.py)</summary>

```python
# SPDX-License-Identifier: Apache-2.0
"""Microbenchmark for the small-batch split top-p changes in topk_topp_triton.py.

Run from a checkout with the PR applied. "main" monkeypatches
_topp_split_count back to the rule on main (S * batch_size <= num_SMs) and
always launches the split pipeline, as main does; "pr" uses the module as is
and passes has_topp_only_rows computed from k and p, as MRV2 does.
Every config is captured once per variant as a CUDA graph on a scratch
copy of the logits; each rep restores the scratch copy outside the timed
region (and optionally flushes L2), then times one graph replay with CUDA
events. Variants are interleaved rep by rep, the
capture order alternates between configs, and the median is reported.
--aa adds a second capture of "pr" to show the noise floor.

    python bench_topp_split.py --vocabs 32000 128256 151936 262144 \
        --out results.json
"""

import argparse
import gc
import json

import torch

import vllm.v1.sample.ops.topk_topp_triton as tt

ap = argparse.ArgumentParser()
ap.add_argument("--vocabs", type=int, nargs="+", default=[151936])
ap.add_argument("--bs", type=int, nargs="+",
                default=[1, 4, 8, 16, 32, 37, 38, 48, 56, 64])
ap.add_argument("--modes", nargs="+", default=["p", "kp", "mixed", "k"])
ap.add_argument("--p", type=float, default=0.95)
ap.add_argument("--topk", type=int, default=50)
ap.add_argument("--reps", type=int, default=100)
ap.add_argument("--cold", action="store_true", help="flush L2 before each rep")
ap.add_argument("--real", help="optional .pt file with a [N, V] 'logits' tensor")
ap.add_argument("--aa", action="store_true", help="also time an A/A copy of pr")
ap.add_argument("--no-hint", action="store_true",
                help="pr does not pass has_topp_only_rows (non-MRV2 callers)")
ap.add_argument("--out")
args = ap.parse_args()

dev = torch.device("cuda")
props = torch.cuda.get_device_properties(dev)
NUM_SM = props.multi_processor_count
FLUSH = torch.empty(256 * 1024 * 1024, dtype=torch.int8, device=dev)
PR_RULE = tt._topp_split_count


def main_rule(batch_size: int, vocab_size: int, num_sm: int) -> int:
    splits = 1
    while splits < tt._SPLIT_MAX_SPLITS and splits * 2 * batch_size <= num_sm:
        splits *= 2
    return splits


VARIANTS = {"main": (main_rule, False), "pr": (PR_RULE, not args.no_hint)}
if args.aa:
    VARIANTS["pr_aa"] = (PR_RULE, not args.no_hint)


def make_inputs(mode, B, V, real):
    g = torch.Generator(device=dev).manual_seed(B * 7919 + V)
    if real is not None:
        cpu_g = torch.Generator().manual_seed(B * 7919 + V)
        idx = torch.randint(0, real.shape[0], (B,), generator=cpu_g)
        x = real[idx].to(dev).float().contiguous()
    else:
        x = torch.randn(B, V, device=dev, generator=g) * 3.0
    p = torch.full((B,), args.p if mode != "k" else 1.0, device=dev)
    k = None
    if mode != "p":
        k = torch.full((B,), args.topk, device=dev, dtype=torch.int32)
        if mode == "mixed":
            k[1::2] = V  # odd rows have no top-k
        elif mode == "onep":
            k[0] = V  # one row has no top-k
        elif mode.startswith("pfrac"):
            k[: max(1, round(B * int(mode[5:]) / 100))] = V
    if mode == "k":
        p = None
    return x, k, p


class Runner:
    def __init__(self, rule, hint, x, k, p):
        self.x, self.buf = x, x.clone()
        buf = self.buf

        def fn():
            tt._topp_split_count = rule
            tt.apply_top_k_top_p_triton(buf, k, p, has_topp_only_rows=hint)

        fn()  # compile and warm up outside capture
        torch.cuda.synchronize()
        gc.collect()
        gc.disable()
        try:
            self.g = torch.cuda.CUDAGraph()
            with torch.cuda.graph(self.g):
                fn()
        finally:
            gc.enable()
            tt._topp_split_count = PR_RULE
        torch.cuda.synchronize()

    def rep(self):
        self.buf.copy_(self.x)
        if args.cold:
            FLUSH.zero_()
        st = torch.cuda.Event(enable_timing=True)
        en = torch.cuda.Event(enable_timing=True)
        st.record()
        self.g.replay()
        en.record()
        return st, en


def bench(x, k, p, flip):
    items = list(VARIANTS.items())
    if flip:
        items.reverse()
    ponly = True
    if k is not None and p is not None:
        ponly = bool(((k >= x.shape[1]) & (p < 1)).any())
    runners = {
        n: Runner(rule, ponly if use_hint else True, x, k, p)
        for n, (rule, use_hint) in items
    }
    evs = {n: [] for n in runners}
    for i in range(args.reps + 5):
        for n, r in runners.items():
            e = r.rep()
            if i >= 5:
                evs[n].append(e)
    torch.cuda.synchronize()
    out = {}
    for n, lst in evs.items():
        ts = sorted(s.elapsed_time(e) * 1e3 for s, e in lst)
        out[n] = ts[len(ts) // 2]
    # Same kept sets? (they may differ only at exact ties at the threshold)
    masks = {}
    for n, r in runners.items():
        r.rep()
        torch.cuda.synchronize()
        masks[n] = r.buf != float("-inf")
    out["rows_diff"] = int((masks["main"] != masks["pr"]).any(-1).sum())
    return out


real = None
if args.real:
    real = torch.load(args.real, map_location="cpu")["logits"]
    args.vocabs = [real.shape[1]]

print(f"# {props.name}, {NUM_SM} SMs, torch {torch.__version__}, "
      f"{'cold' if args.cold else 'hot'} L2, p={args.p}, k={args.topk}, "
      f"median of {args.reps} graph replays (us)")
aa_hdr = (" A/A |", "---|") if args.aa else ("", "")
print("| vocab | mode | B | S main | S pr | main | pr | speedup | rows diff |" + aa_hdr[0])
print("|---|---|---|---|---|---|---|---|---|" + aa_hdr[1])
results = []
for V in args.vocabs:
    for mode in args.modes:
        for B in args.bs:
            x, k, p = make_inputs(mode, B, V, real)
            r = bench(x, k, p, flip=len(results) % 2 == 1)
            s_main, s_pr = main_rule(B, V, NUM_SM), PR_RULE(B, V, NUM_SM)
            row = dict(gpu=props.name, sms=NUM_SM, vocab=V, mode=mode, B=B,
                       S_main=s_main, S_pr=s_pr, **r)
            results.append(row)
            print(f"| {V} | {mode} | {B} | {s_main} | {s_pr} | {r['main']:.1f} | "
                  f"{r['pr']:.1f} | {r['main'] / r['pr']:.2f}x | {r['rows_diff']} |"
                  + (f" {r['pr_aa'] / r['pr']:.3f} |" if args.aa else ""),
                  flush=True)
if args.out:
    with open(args.out, "w") as f:
        json.dump(results, f, indent=1)
```

## Details

**Why more than one program per SM.** Each split program sweeps a `V/S` slice serially, so at small B the call time follows S, not B. I forced S to 1..128 on B300 over 425 top-p-only configs: 6 synthetic logit kinds x 4 vocab sizes plus real MiMo rows, B=1-64. Regret is time over the time at the best S <= 32:

| rule | configs > 5% slower than main | worst vs main | regret, geomean / max |
|---|---|---|---|
| main: `S * B <= num_SMs` | - | - | 1.24 / 2.95 |
| `S * B <= 2 * num_SMs` | 20 | 0.72x | 1.10 / 2.00 |
| `S * B <= 4 * num_SMs` | 69 | 0.59x | 1.07 / 1.87 |
| this PR | 0 | 0.96x | 1.02 / 1.26 |

Pure occupancy targets shrink slices down to 1000 entries at V=32K. Raising `_SPLIT_MAX_SPLITS` would not help at B=38-64, where the one-wave cap is what binds.

**Change 1: split count.** `_topp_split_count` keeps doubling S, still a power of two capped at 32, while either main's condition holds or the doubled S leaves slices of at least `_SPLIT_MIN_SLICE = 7168` entries. The value sits between two measured regimes:
- Around 200K vocab (gpt-oss, MiniMax, Muse), a forced S sweep shows S=32 (about 6.3K-entry slices) 3-24% slower than S=16 for top-p-only rows at B=16-64. S=32 wins only at B=8-24, by up to 20% for half-top-k batches at B=16. So the floor must be above 6314 to exclude it.
- At 256K-262K, S=32 (8.0-8.2K entries) is faster than S=16 in most configs, and at most 4% slower at V=256000 (9% at 262144). So the floor must be at most 8000 to allow it.

Qwen3.8 (248K) lands on S=32 with 7.8K-entry slices. I measured it against main, not against a forced S=16.

S never drops below main's value, and the workspace size is unchanged. The set of S values per vocab can only shrink: at V >= 120K it becomes {32, 16} or just {32}, instead of {32, 16, 8, 4, 2}. The warmup providers already push every B through the same dispatch functions, so no runtime JIT is added.

**Change 2: skip the idle split launch.** `apply_top_k_top_p` gains `has_topp_only_rows: bool = True`. False means no row has p < 1 together with k >= vocab_size. In that case the monolithic kernel already masks every row, including grammar rows whose top-k is a no-op, and the split pipeline is not launched. MRV2's `SamplingStates.has_topp_only_rows()` computes the flag from host-side numpy state, with no sync, and the MRV2 call sites pass it: verification and logits processing via `apply_sampling_params`, non-fused random sampling, and the watermark sampler. So does diffusion_gemma, which uses the MRV2 sampling state. The flag is computed only when both top-k and top-p are active, since it matters only then. MRV1 keeps the default: it gets the new split count but still launches the split pipeline. All-top-k batches there run at 0.90-0.98x (+2 to +23 us) at B=32-64 in the graph-captured microbenchmark (B300 and GB300, V=128K-262K; the "none, without the hint" row below), and at 0.96-0.99x (+2 to +11 us) in the upstream benchmark above.

A cutoff on the share of top-k rows would not work. The gain is largest when only a few rows are top-p-only, and only zero top-p-only rows lose (B300, V=151936):

| top-p-only rows | B=32 | B=38 | B=64 |
|---|---|---|---|
| none, without the hint | 0.97x | 0.95x | 0.91x |
| none, with the hint | 1.09x | 1.07x | 1.05x |
| 1 row | 1.96x | 3.68x | 3.66x |
| 25% | 1.60x | 3.00x | 2.83x |
| 50% | 1.50x | 2.44x | 1.86x |
| all | 1.01x | 1.93x | 1.29x |

**Unchanged: the split/monolithic handover at B=64.** On peaked logits (real MiMo rows, Zipf) the monolithic kernel at B=65 is still faster than the split pipeline at B=64, even with this PR: 318 vs 193 us on MiMo rows. On flat logits the order flips. Where to hand over depends on the distribution, so `_SPLIT_MAX_BATCH` is left alone here.

**Output changes.** S only changes how rows are partitioned, and it already varies with B on main. Kept sets differ only at the p boundary:
- On real (bf16-valued) MiMo logits, every differing token is an exact tie with the boundary logit; this affects 19% of row evaluations.
- On continuous fp32 logits (synthetic flat, peaked and Zipf), 3671 of 41424 row evaluations differ. 2536 of them are not boundary ties and come from fp32 summation order, with kept mass differing by at most 1.1e-4.
- Against a float64 reference, rows below p are unchanged (6 vs 6 over 33776 real-row evaluations). Rows that over-keep boundary copies drop from 6698 to 2445 and rows that under-keep rise from 6 to 30, mostly because the mask kernel's tie count restarts at every 8192-entry block, which shorter slices hit less often. That restart is a pre-existing bug, separate from this PR.

**Scope and limits.** Only the Triton sampler path is affected:
- Spec-decode verification, for any model.
- Non-spec batches that cannot use the fused FlashInfer sampler: per-request seeds, greedy rows in the batch, processed logprobs, or FlashInfer disabled.
- ROCm takes the split path too, and S changes there as well; for example, at V ~152K S becomes 16 from B=20 on MI300X (304 CUs). I have no AMD hardware to measure it.
- GPUs with fewer than 132 SMs were not measured either.

**Related PRs.** No open PR changes the split count for performance.
- #55414 (@njhill) buckets B before the same one-wave rule, to bound the precompiled variants. Since #56323 the warmup dispatcher enumerates every B, so I think its goal is covered. If you still plan to land it, the two compose.
- #56154 (draft) carries a copy of the same dispatchers with the 2-argument `_topp_split_count`.
