# [Model Loader] Run model-level post-load finalization from the loader hook

[Upstream PR](https://github.com/vllm-project/vllm/pull/57733) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

**`load_weights` must not assume all weights arrive in one call.** RL weight updates call it once per bucket: verl sends 512 MB buckets tensor by tensor, and the NCCL engine calls it once per tensor (inside `disable_mtp_completeness_check()`). So a weight and its scale, or the two halves of a merged tensor, can land in different calls. Any post-load work inside `load_weights` then runs on partial weights, once per bucket. Context: RFC #54477, tracker #50079.

The PR has three parts:
1. **One finish step for every load.** `finalize_model_weights(model)` runs once after a full load and once at the end of every reload, and calls the model's `process_weights_after_loading()`. There are no per-model opt-ins. This mirrors SGLang, which post-processes once at `end_weight_update`.
2. **Split merged tensors written through the weight loader.** Molmo/Molmo2 embedding halves and Llama4 DP-vision q/k/v are written straight into their rows, so any split or order of calls works. Nothing is parked across calls.
3. **Post-load work moves out of `load_weights` into the hook.** That includes the blocks that used to rebuild derived state on every call.

Coverage: an AST script enumerated every `def load_weights` in `vllm/` (447), and each was checked in source. That covers multimodal wrappers, MTP/EAGLE/DSpark/DFlash drafters, adapters, `AutoWeightsLoader`, layer-level loaders, model loaders and the `vllm/models/*` platform variants. Every model-level `process_weights_after_loading()` was also checked for whether it is safe to re-run on new weights.

## Claims

**Finish step.** `finalize_model_weights` is called from two places, and nowhere else:
- `model_loader/utils.py::process_weights_after_loading`: cold load (dummy loads too), after per-layer quant processing.
- `finalize_layerwise_reload`: used by `reload_weights` and by `finish_weight_update` in the NCCL, IPC, M2N and sharded-RDT engines.

No `load_weights` calls the model hook anymore. Code that restores layers in the middle of a load (the torchao reload decorator and the expert-substitution error path) calls `finalize_layerwise_processing` and leaves the model hook to the finish step. The DeepSeek-V4/V4.1 VL wrappers drop `finalizes_weights_during_load`, `_weights_finalized` and the regrouping that loaded the language model first, and `stream_language_model_first` is deleted.

**Split merged tensors.** Each part is written into its rows of the target parameter by a weight loader, in any order and across calls:
- **Molmo/Molmo2 split embedding:** `wte.embedding` and `wte.new_embedding` go into their rows of this rank's `embed_tokens` vocab shard (`_load_split_embedding`). Before, a call without both halves raised `KeyError`.
- **Llama4 DP-vision q/k/v:** the replicated `qkv_proj` gets a shard loader (`_load_qkv_shard`), so q/k/v go through the stacked mapping; `_consolidate_qkv_weights` is removed. Before, a split triple failed in `torch.cat`.

**Same as main (follow-up on #58382).** These combine several checkpoint tensors inside `load_weights` and keep main's handling here: FP8 indexer `wk` dequant (DeepSeek-V2, `deepseek_mtp`, DeepSeek-V3.2, HY-V4, dots3, GLM5-next), GLM5-next FP8 MLA projections, MiMo-V2/MTP fused FP8 qkv, and the Jina-v3 LoRA merge. They move to checkpoint-layout parameters combined in `process_weights_after_loading`, on top of #58382 (PR 6 in the [RFC tracker](https://github.com/vllm-project/vllm/issues/54477#issuecomment-6450991360)). Until then a weight and its scale split across calls behave as on main.

**Moved from `load_weights` to `process_weights_after_loading`:**
- **DFlash-family fused context-KV buffers:** Qwen3 DFlash, plus Qwen3 DSpark, Gemma4 DSpark and LiLiCorr through the inherited hook, and Laguna.
  - The hook now runs after quant processing, so it reads processed weights.
  - The fused path that reads raw weights is used only when the projections are unquantized and not repacked by CPU (`_reads_raw_weights`).
  - Otherwise each projection runs through its quant method, as Qwen3 DFlash already did for quantized drafts.
  - On a reload the rebuilt buffers are copied into the existing ones (`_rebuild_in_place`). Model Runner V2 records the context-KV step in its FULL CUDA graph, so a new allocation would leave the graph reading the old weights. LiLiCorr's inference buffers, used inside the DFlash2 graph, go through the same helper.
- **BERT MLM:** the tied-decoder copy, decided by `config.tie_word_embeddings`.
- **DeepSeek-V4 NVIDIA and V4.1 NVIDIA/AMD:** the mHC broadcast.
- **LiLiCorr:** the inference buffers. A `dummy` load now builds them.
- **OpenPangu:** the `post_weight_load` sweep. `StaticSinkAttention.update_sink_kv` now clears `sink_populated`, so a re-run rewrites the cached sink KV.
- **Gemma4 MTP:** the lm-head cache invalidation and the suppress-token index.
- **DeepSeek-V4 XPU:** `finalize_mega_moe_weights` for target, MTP and DSpark. The guarded lazy call in MegaMoE `forward()` stays for dummy loads.
- **DeepSeek-V4.1 NVIDIA:** the Engram page-cache drop and THP collapse.
- **dots3 vision:** the hook runs at every reload finish, so the block compile is done only once.

**Decisions on one call's loaded set run only for a complete load.** They are gated on `is_mtp_completeness_check_enabled()`, which the weight-transfer engines turn off. They used to fire on every bucket:
- `AutoWeightsLoader._check_skipped_aliases`.
- DSpark `confidence_head` drops: gemma4, qwen3, DeepSeek-V4/V4.1.
- Checkpoint checks: Qwen3 DSpark, Eagle3 `mask_hidden`, AliceAI and LiLiCorr coverage.
- The NemotronVL seq-cls head init.
- The MTP layer checks that were still ungated: Bailing V3, DeepSeek-V3.2 AMD, GLM5-next, Kimi-K3.
- **The Phi-3-V embedding tie.**
  - After the cold-load tie, `embed_tokens.weight` became the canonical name of the shared embedding.
  - So the checkpoint's `model.embed_tokens.weight` was skipped as its alias, and every reload either raised (main) or left the embedding stale.
  - The tie now re-registers `embed_tokens` last, so the language model's name stays canonical and reloads write it.

Known limitations: these fail on both arms and are not changed by this PR.
- **layerwise + a bucket buffer the sender reuses (zeroed after the call).** Layerwise staging keeps references to the caller's tensors without copying them, so any layer split across buckets is corrupted. All models hit this. With buffers that are not reused, the PR passes.
- **plain finish into already-processed FP8 params** (Qwen3-FP8, MiMo, GLM5-next, DSv3.2/V4/V4.1): the processed params can no longer take checkpoint tensors.
- **GLM5-next:** the KDA layer caches `_merged_conv_weight` on the first forward and never refreshes it. Any W0→W1 update leaves it stale, `reload_weights` and NCCL included. A separate fix will follow.
- **Gemma4 MTP drafter:** cannot be reloaded from the assistant checkpoint through `load_weights` (1536 vs 256 embed shape).
- **Hooks that cannot re-run:**
  - **dots3 vision MoE.** It FP8-packs the experts and then deletes the bf16 experts, so a vision reload has no target param and fails loudly.
  - **DeepSeek-V4 AMD MegaMoE.**
  - **XPU.**

| verdict | count | meaning |
|---|---|---|
| per-weight | 364 | dispatch, remap or transform of the incoming tensor, routing, delegation |
| loader | 6 | model-loader entry points |
| moved | 19 | post-load work now in the hook |
| multi-part | 14 + 4 gated MTPs | Molmo/Molmo2 and Llama4 DP vision write each part through a weight loader; the rest keep main's handling (follow-up on #58382) |
| gated | 18 + 10 upstream | checks/decisions on this call's loaded set, complete loads only |
| exception | 14 | per-name choices that build no derived state (Roberta prefix sniff, Whisper zero `k_proj` bias, ColPali lazy head), Inkling EP padding, error paths |

Paths that do not run the hook are unchanged: kernel-format reload (`is_checkpoint_format=False`), sparse-NCCL patches and tensorizer. None of these call `load_weights`. The raw-tensorizer change is left to #55318. verl's FP8/QAT finish paths process layers themselves. Its default path calls `process_weights_after_loading(model, ...)` and gets the finish step.
