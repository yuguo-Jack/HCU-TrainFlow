# [Model Loader] Run model-level post-load finalization from the loader hook

[Upstream PR](https://github.com/vllm-project/vllm/pull/57733) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

**`load_weights` must not assume all weights arrive in one call.** RL weight updates call it once per bucket: verl sends 512 MB buckets tensor by tensor, and the NCCL engine calls it once per tensor (inside `disable_mtp_completeness_check()`). A weight and its scale, or the two halves of a merged tensor, can therefore land in different calls. Any post-load work inside `load_weights` then runs on partial weights, once per bucket. Context: RFC #54477, tracker #50079.

The PR has three parts:
1. **One finish step for every load.** `finalize_model_weights(model)` runs once after a full load and once at the end of every reload. It raises if a multi-tensor weight is still missing a part, then calls the model's `process_weights_after_loading()`. There are no per-model opt-ins. This mirrors SGLang, which post-processes once at `end_weight_update`.
2. **Cross-call pairing.** One shared helper, `stash_weight_part`, replaces every call-local pairing buffer.
3. **Post-load work moves out of `load_weights` into the hook.** That includes the blocks that used to rebuild derived state on every call.

Coverage: an AST script enumerated every `def load_weights` in `vllm/` (447), and each was checked in source. That covers multimodal wrappers, MTP/EAGLE/DSpark/DFlash drafters, adapters, `AutoWeightsLoader`, layer-level loaders, model loaders and the `vllm/models/*` platform variants. Every model-level `process_weights_after_loading()` was also checked for whether it is safe to re-run on new weights.

## Claims

**Finish step.** `finalize_model_weights` is called from two places, and nowhere else:
- `model_loader/utils.py::process_weights_after_loading`: cold load (dummy loads too), after per-layer quant processing.
- `finalize_layerwise_reload`: used by `reload_weights` and by `finish_weight_update` in the NCCL, IPC, M2N and sharded-RDT engines.

No `load_weights` calls the model hook anymore. The DeepSeek-V4/V4.1 VL wrappers drop `finalizes_weights_during_load` / `_weights_finalized` and the language-model-first regrouping, and `stream_language_model_first` is deleted.

**Cross-call pairing.** `stash_weight_part(module, key, part, tensor, parts)` parks a part on the module, keyed by module prefix. The parked part is cloned, because transfer buckets reuse their buffers. The helper returns all parts once the set is complete and drops the entry. Leftover parts raise at the finish step and are never dropped silently. It replaces:
- **FP8 indexer `wk` weight+scale dequant:** DeepSeek-V2, `deepseek_mtp`, DeepSeek-V3.2 nvidia/amd (model and MTP), HY-V4 amd/nvidia model and nvidia MTP, dots3. Before, a pair split across calls was dropped; dots3 raised at the end of the call.
- **GLM5-next:** indexer `wk` and the BF16-kept MLA projections, model and MTP.
- **MiMo-V2 and MiMo-V2 MTP:** fused FP8 qkv. These already kept their own dict on `self`, but nothing checked it for leftovers.
- **Molmo/Molmo2 split embedding:** a call without both halves raised `KeyError`.
- **Llama4 DP-vision q/k/v concat:** a split triple failed in `torch.cat`.
- **Jina-v3 LoRA merge:** a split triple raised `KeyError`.

**Moved from `load_weights` to `process_weights_after_loading`:**
- **DFlash-family fused context-KV buffers:** Qwen3 DFlash, plus Qwen3 DSpark, Gemma4 DSpark and LiLiCorr through the inherited hook, and Laguna. The hook reads weights after quant processing. So the fused raw-weight path is used only when the projections are unquantized and not repacked by CPU (`_reads_raw_weights`). Otherwise each projection runs through its quant method, as Qwen3 DFlash already did for quantized drafts.
- **BERT MLM:** the tied-decoder copy, decided by `config.tie_word_embeddings`.
- **DeepSeek-V4 NVIDIA and V4.1 NVIDIA/AMD:** the mHC broadcast.
- **LiLiCorr:** the inference buffers. A `dummy` load now builds them.
- **OpenPangu:** the `post_weight_load` sweep. `StaticSinkAttention.update_sink_kv` now clears `sink_populated`, so a re-run rewrites the cached sink KV.
- **Gemma4 MTP:** the lm-head cache invalidation and the suppress-token index.
- **DeepSeek-V4 XPU:** `finalize_mega_moe_weights` for target, MTP and DSpark. The lazy call in MegaMoE `forward()` is gone.
- **MiniCPM-V/O:** the resampler device move. A `dummy` load used to crash.
- **DeepSeek-V4.1 NVIDIA:** the Engram page-cache drop and THP collapse.

**Decisions on one call's loaded set run only for a complete load.** They are gated on `is_mtp_completeness_check_enabled()`, which the weight-transfer engines turn off. They used to fire on every bucket:
- `AutoWeightsLoader._check_skipped_aliases`.
- DSpark `confidence_head` drops: gemma4, qwen3, DeepSeek-V4/V4.1.
- Checkpoint checks: Qwen3 DSpark, Eagle3 `mask_hidden`, AliceAI and LiLiCorr coverage.
- The Phi-3-V embedding alias.
- The NemotronVL seq-cls head init.
- The MTP layer checks that were still ungated: Bailing V3, DeepSeek-V3.2 AMD, GLM5-next, Kimi-K3.

**Raw (non-vLLM-serialized) tensorizer** checkpoints load through `BaseModelLoader.load_model`. Before, a private helper skipped per-layer quant processing. This is the same change and test as #55318.

## Validation

GB200, image `vllm/vllm-openai:nightly-1b2a666391f2a24228a1436b64d547c34cc6b6ce`. A is the image as-is; B is the image plus this commit, overlaid behind per-file SHA-256 gates.

The probe cold-loads the model and snapshots every parameter, buffer and tensor attribute. It then reloads the same checkpoint twice: once with a single `load_weights` call, and once bucketed, with one call per tensor under `disable_mtp_completeness_check`. It runs two finish modes:
- **plain:** `load_weights` followed by `process_weights_after_loading(model, ...)`, as verl does.
- **layerwise:** `initialize_layerwise_reload`, then the loads, then `finalize_layerwise_reload`, as `reload_weights` and the engines do.

Every tensor is compared bit-exactly with the cold snapshot, and greedy outputs are compared before and after.

## Details

Verdicts over the 447 `load_weights`:

| verdict | count | meaning |
|---|---|---|
| per-weight | 364 | dispatch, remap or transform of the incoming tensor, routing, delegation |
| loader | 6 | model-loader entry points |
| moved | 21 | post-load work now in the hook |
| paired | 14 + 4 gated MTPs | parts paired across calls via `stash_weight_part` |
| gated | 18 + 10 upstream | checks/decisions on this call's loaded set, complete loads only |
| exception | 14 | per-name choices that build no derived state (Roberta prefix sniff, Whisper zero `k_proj` bias, ColPali lazy head), Inkling EP padding, error paths |

Re-running each model-level hook on new weights (finish of a reload):
- **Same result as a cold start:** BERT, DFlash family, Laguna, LiLiCorr, Gemma4 MTP, MiniCPM-V/O, OpenPangu (with the `sink_populated` fix), expert substitution, DeepSeek-V4/V4.1 mHC, V4.1 Engram THP (idempotent OS hints), Beam warmup, Kimi-K3 DSpark-MLA metadata, the VL wrappers (they delegate).
- **Not re-runnable, left as follow-ups:**
  - **dots3 vision MoE.** It FP8-packs the experts, then deletes the bf16 experts. A reload of vision weights fails loudly because there is no target param. Making it re-runnable means keeping the bf16 experts resident.
  - **DeepSeek-V4 AMD MegaMoE.** The shuffle is guarded by `_runtimes`, and the fused shared-expert module is dropped. DeepSeek-V4 reload already fails earlier upstream, on both arms.
  - **XPU:** out of scope.
- **Unchanged paths that do not run the hook:** kernel-format reload (`is_checkpoint_format=False`), sparse-NCCL patches and vLLM-serialized tensorizer. None of these calls `load_weights`.
- **verl:** its FP8/QAT finish paths process layers themselves and do not call the model hook. Its default path calls `process_weights_after_loading(model, ...)` and gets the finish step.

Overlap: the tensorizer change and its test are the same as draft #55318 (nicole-lihui, co-author). Whichever lands first, the other drops it.

**AI assistance.** Done with Claude Code. Codex, Kimi and Claude audited the diff and the coverage over three more rounds. Confirmed findings were applied: a quantized Gemma4-DSpark/Laguna draft read post-quant weights raw (fixed by the shared predicate and the per-projection fallback), and a comment nit. The last round confirmed nothing; its one claim, that the V4.1 AMD hook lost the mHC call, is false.
