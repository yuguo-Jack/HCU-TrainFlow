# [Bugfix][Frontend] Accept an empty tools array like OpenAI

[Upstream PR](https://github.com/vllm-project/vllm/pull/65547) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Accept `tools: []` on `/v1/chat/completions` like an omitted `tools` field, matching what the OpenAI API does today. Supersedes #49346 (stale, conflicting) and reverses the check from #39780. The Rust frontend keeps its matching check from #63060; that is a follow-up.

## Claims

- `tools: []` with `tool_choice` omitted, `"none"`, `"auto"` or `"required"` now returns a normal chat completion (HTTP 200) instead of 400 `` `tools` must not be an empty array ``, as OpenAI does. Before, every empty array was rejected.
- `tools: []` with a named function still returns 400, and the message now names the function that is not in `tools` (also for non-empty lists), as OpenAI's does.
- Requests without a `tools` field, and with a non-empty `tools` list, are unchanged. `/tokenize` keeps accepting an empty list without its own workaround.

## Validation

**OpenAI today** (gpt-4o-mini, 2026-11-04): `tools: []` returns 200 with text for `tool_choice` omitted, `none`, `auto` and even `required`; a named function returns 400 `no function named 'f' was specified`. So the `empty_array` 400 that #39780 matched no longer exists upstream.

**Live before/after on one H200**, `vllm serve Qwen/Qwen3-0.6B --max-model-len 4096 --enable-auto-tool-choice --tool-call-parser hermes --no-enable-prefix-caching`, before = d8a13402fe (merge-base), after = this branch:

| request | before | after |
|---|---|---|
| `tools: []`, no `tool_choice` | 400 `tools` must not be an empty array | 200, text, `finish_reason=length` |
| `tools: []`, `tool_choice: "none"` | 400 | 200, text |
| `tools: []`, `tool_choice: "auto"` (stream and non-stream) | 400 | 200, text, usage present |
| `tools: []`, `tool_choice: "required"` | 400 (param `tools`) | 200, text |
| `tools: []`, named function `f` | 400 (param `tools`) | 400 `` The tool `f` specified in `tool_choice` does not match any of the specified `tools` `` (param `tool_choice`) |
| no `tools`, `tool_choice: "auto"` | 400 | 400, unchanged |
| one tool, `tool_choice: "auto"` | 200, tool call | 200, identical output |
| `/tokenize` chat with `tools: []` | 200 | 200, identical |

```bash
curl -s localhost:8000/v1/chat/completions -H 'Content-Type: application/json' -d '{"model":"Qwen/Qwen3-0.6B","messages":[{"role":"user","content":"Say hello in three words."}],"max_tokens":30,"tools":[]}'
```
