# [Bugfix][EC] Reuse runner cache hits before remote admission

[Upstream PR](https://github.com/vllm-project/vllm/pull/65079) · state: open · merged: False

## Original PR description



## Overview

Avoid fetching encoder outputs that are already in the consumer's runner cache. Previously, eviction from ECCPU's separate CPU tier could trigger a redundant transfer and fail a metadata-only request if the producer was unavailable.

Related: #55639. No duplicate open PR was found; this fixes consumer admission rather than EPD orchestration or filesystem tiering (#63294).

## Claims

- Pass valid runner-cache hits to ECCPU admission for both waiting and running requests; only uncached inputs need transfer checks.
- Keep future hits evictable. If a hit is evicted during scheduling, stop the chunk before that input and recheck admission next step.


## Details

Admission precedes the existing runner-cache lookup. The optional `local_cache_hashes` argument lets ECCPU skip remote reads for matching embedding counts. Hits are not pinned early, which could block earlier inputs under memory pressure; the scheduling pass instead detects eviction and defers the affected input.

Out-of-tree overrides of `ensure_cache_available()` must accept the new optional argument. Mooncake accepts the argument but retains its existing behavior.
