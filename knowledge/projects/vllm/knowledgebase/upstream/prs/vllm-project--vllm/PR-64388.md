# [Feature][KV Connector] Add spec-owned transfer region export

[Upstream PR](https://github.com/vllm-project/vllm/pull/64388) · state: open · merged: False

## Overview

Add an opt-in `KVCacheSpec.get_kv_cache_transfer_regions(actual_cache)` contract returning named storage-sharing views in fixed logical `[B,H,N,C]` order. Backend-specific storage adaptation belongs to the producer; connector registration signatures remain unchanged.

Contract: [vllm-project/vllm #64388](https://github.com/vllm-project/vllm/pull/64388) (`717cb2da70f03c7d8f35b61225d08da9c1f40585`). Producer: [RBLN-SW/vllm-rbln #1361](https://github.com/RBLN-SW/vllm-rbln/pull/1361) (`0cbc0453d74b082649c0fb004eb642d7da0f7399`). Consumer: [LMCache/LMCache #6155](https://github.com/LMCache/LMCache/pull/6155) (`c0f763e0306164db1e536f36860c24d68bf30628`).

## Claims

- Default specs return `None` and retain existing registration behavior. Dense producers can expose separate `key` and `value` region views with real strides and storage offsets.
- This is a new three-file proposal, independent of [the axis-descriptor proposal #63699](https://github.com/vllm-project/vllm/pull/63699), which remains unchanged and under discussion. No runner or MultiConnector propagation is added here.
- The companion RBLN exporter projects either `[B,2,H,1,N,D]` or `[2,B,H,1,N,D]` without repacking, even at `B=2`. LMCache's companion production connector consumes those views and restores original storage.

## Details

This is an alternative to arbitrary axis semantics at registration, not a revision replacing #63699. It follows #42082's fixed logical consumer ordering, but still adds a public method to `KVCacheSpec`; upstream acceptance and placement are open questions.

This API constructs regions from actual native storage. The unmerged #46387 (`a1c222e4773565f19c938211d6817a402c61adf5`) handles TP slicing of already-known BHNC regions. This proposal does not duplicate its slicing implementation or claim that integration with its final API is settled.

The vLLM base method formalizes the shared contract; it is not a strict runtime dependency of this Python implementation. RBLN defines the exporter on its subclass and LMCache discovers it optionally, so the producer/consumer pair can execute before the base method lands. Upstream agreement on the API and supported-version validation remain review/merge gates.

Dense unquantized K/V, both MP transfer modes on capable platforms, whole-block local-partition transfers. CPU/CUDA support native-owner handle registration; RBLN retains engine-driven mode because its current platform lacks IPC/event support. Kernel-block subdivision is explicitly rejected: native states per block must equal the spec block size. No arbitrary Mamba/quantized codec, heterogeneous TP conversion, unaligned token range, or in-process connector support is added. Region creation aliases storage; transfer and serialization can copy. The new RBLN consumer branch uses shared torch tensor ops and has not been performance-tested on NPU. The original native-format route may retain a lower-risk path to existing optimized operations; performance superiority is not claimed here.
