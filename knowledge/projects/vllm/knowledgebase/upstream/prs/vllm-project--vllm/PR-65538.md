# [Bugfix] Reject empty/missing content on developer/system messages (400) instead of renderer crash (500)

[Upstream PR](https://github.com/vllm-project/vllm/pull/65538) · state: open · merged: False

## Original PR description

## Problem

A `developer` (or `system`) message with empty string content or a missing `content` key passes Pydantic validation (empty string is a valid `str`) but crashes downstream renderers with a **500 Internal Server Error** — and the error body can leak internal state (e.g. `_image_indices`):

```json
{"error":{"message":"Invalid message for role `developer`: {'content': '', 'role': 'developer', '_image_indices': []}","type":"InternalServerError"}}
```

Meanwhile, `content: null` is correctly rejected with a **400** by Pydantic's string type validation. The gap: empty string and missing key slip past validation and explode at the rendering layer.

## Fix

Add a `model_validator(mode="before")` on `ChatCompletionRequest` that rejects developer/system messages with empty or whitespace-only `content`, raising a `ValueError` (→ 400) at the protocol layer — consistent with how `content: null` is already handled.

This is a ~15-line addition, placed alongside the existing message pre-processing validators.

Fixes #65357

## Testing

Reproduced on nightly `v0.33.0rc1.dev573`:

| Input | Before | After |
|---|---|---|
| `{"role":"developer","content":""}` | 500 + leaked `_image_indices` | 400 |
| `{"role":"developer"}` (no content key) | 500 | 400 |
| `{"role":"developer","content":null}` | 400 (already worked) | 400 |
| `{"role":"developer","content":"valid"}` | 200 | 200 (no change) |
