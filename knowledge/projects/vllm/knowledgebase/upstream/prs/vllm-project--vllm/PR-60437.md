# [Frontend] Resolve logprobs on the parsed streaming derender path

[Upstream PR](https://github.com/vllm-project/vllm/pull/60437) · state: open · merged: False

## Original PR description

## Overview

Streaming `/v1/chat/completions/derender` with a reasoning or tool parser returned no logprobs: #55029 resolved them only on the plain detokenization path, and the parser path built its stream choices without them. This PR resolves each chunk's logprobs on the parser path and mirrors the coupled endpoint's hidden-reasoning rule on both batch and streaming derender. Closes #59590.

## Claims

- On the parser path each generate chunk's `logprobs` are resolved once and attached to whatever delta the parser emits for that chunk (reasoning, content, tool-call delta, or an empty delta while the parser buffers markup), the same as `/v1/chat/completions`, which has one `logprobs.content` list regardless of field.
- The byte-fallback context now crosses chunks on the parser path through the existing `logprob_context_token_ids` tail, starting empty like the engine. `DerenderStreamState` is unchanged and replay never touches logprobs, as agreed on the issue.
- With a parser configured and `include_reasoning=false`, batch and streaming derender return no logprobs at all. Batch `_derender_chat` previously cleared `reasoning` but still returned them.
- No wire change. Chunks without `logprobs` still produce `logprobs: null`.

## Validation

GPU run on an A100-40G (branch overlaid onto `vllm/vllm-openai:nightly-21d93d0d8c`, which is an ancestor of this branch):

```bash
pytest tests/entrypoints/scale_out/derender/test_derender_stream.py \
       tests/entrypoints/scale_out/derender/test_derender.py
# 143 passed, 1 xfailed in 267s

pytest tests/entrypoints/scale_out/derender/test_derender_parity.py
# 12 passed, 7 skipped in 220s
```

All 7 parity skips are "Model did not emit a tool call" from `DeepSeek-R1-Distill-Qwen-1.5B`; 4 of them are pre-existing tool-call parity tests that skip on `main` for the same reason, even with `tool_choice` forced. The new reasoning and hidden-reasoning logprob parity cases pass on GPU.

Not compared against the coupled endpoint: the parser-swallowed chunk (`test_stream_parity_logprobs_tool_call` skips on the CI model) and the multi-byte split (`test_logprobs_multibyte_across_chunks`, unit only). Both are unit-tested on the real tokenizer and parser.

Locally: `pre-commit run --all-files` and `pre-commit run mypy-3.12 --all-files --hook-stage manual` clean.

New tests:

- `test_derender_stream.py` (unit, parser path): logprobs attached to each delta kind, kept when the parser swallows a chunk, dropped on every chunk with `include_reasoning=false`, a multi-byte character split across chunks, and the logprob context advancing on chunks without logprobs.
- `test_derender.py` (batch e2e): `test_e2e_parsed_logprobs_follow_include_reasoning`.
- `test_derender_parity.py` (streaming vs `/v1/chat/completions`): `test_stream_parity_logprobs_reasoning`, `test_stream_parity_logprobs_tool_call`, `test_stream_parity_logprobs_hidden_reasoning`. `utils.stream_chat_derender` gained `logprobs` and `raw_choices` parameters for these.

## Details

- **Why no replay cursor.** A generate chunk's `logprobs` cover exactly that chunk's tokens (the engine slices to the delta), so nothing is derived from replay and there is nothing to skip on re-emit. Only the 4-token byte-fallback context needs to persist, and the state already carries it (https://github.com/vllm-project/vllm/issues/59590#issuecomment-5901337931).
- **Why suppress on every chunk.** Decoded logprob token strings would reveal the hidden reasoning text, so the coupled chat endpoint drops logprobs entirely for the request when a parser is configured and `include_reasoning` is false. Derender now does the same, batch and streaming.
- **Docs.** `docs/serving/online_serving/derenderer.md` updated to describe the parser path and the `include_reasoning` rule.

Duplicate-work check: searched open PRs for `59590 in:body`, `derender logprobs` and `parsed streaming logprobs`. The only hit referencing #59590 is #60082 (derender output mode on generate), which consumes this behaviour rather than implementing it. #59518 changes which `top_logprobs` candidates derender keeps and does not touch the parser path. #57790 is engine-side `LogprobsProcessor` handling for streaming input continuations, unrelated to derender.
