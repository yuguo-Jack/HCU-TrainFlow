# [Bugfix][ROCm][Qwen4Exp] Remap Quark layer names for the MTP draft model

[Upstream PR](https://github.com/vllm-project/vllm/pull/61770) · state: closed · merged: True

## Original PR description

## Overview

Previously, `amd/Qwen3.8-Flash-Next-Quark-MXFP4` with MTP would fail with `RuntimeError: The size of tensor a (1280) must match the size of tensor b (2560)`.

Remap Quark's layer names (`exclude`, `layer_quant_config`) for the Qwen4Exp MTP draft (both AMD and NVIDIA copies) so that checkpoint names (`mtp.layers.0.*`) match the draft's layer names (`mtp.layers.48.*`), the same way `ignored_layers`, `exclude_modules` and ModelOpt `quantized_layers` are already remapped (#55513) in both copies.

Related checkpoint fix:https://huggingface.co/amd/Qwen3.8-Flash-Next-Quark-MXFP4/commit/89d245391842bf53fb9b0700646843c1f40de341.

**Checkpoint status:** AMD has updated `config.json` on both `amd/Qwen3.8-Flash-Next-Quark-MXFP4` and the `-PLEFP8` sibling with literal `mtp.layers.0.*` names only -- no catch-all regex -- matching the convention other AMD checkpoints use (e.g. `amd/Qwen3.5-397B`). Per AMD's confirmation on the checkpoint discussion linked above and the model card's own Reproduction section: without MTP, the formal `vllm/vllm-openai-rocm:v0.32.0` release runs the checkpoint as documented; with MTP enabled, that release does not remap Quark's exclude list for the draft, so this PR is required for MTP to load at all -- this is the checkpoint as shipped, not a hypothetical variant.

## Claims

- Bug fix: with a Quark checkpoint whose `exclude` list names MTP modules by checkpoint index (the form Quark exports), BF16 MTP layers are no longer built as quantized layers.
- Per-layer Quark schemes (`layer_quant_config`) for MTP modules are applied to the draft as well.
- No functional change for the target model, for no-MTP serving, or for ModelOpt checkpoints.
- Also fixes the identical bug on the NVIDIA backend: MXFP4 has real NVIDIA-native MoE backends (FlashInfer, vLLM CUTLASS, DeepGEMM, Marlin -- not just AMD's AITER path), so a Quark-quantized checkpoint with MTP hit the same dead-exclude-list bug there. Flagged by @okorzh-amd's review; same fix, ported to `vllm/models/qwen4_exp/nvidia/mtp.py`.
- Scope: entries in Quark `exclude` and keys of `layer_quant_config` that **start with** `mtp.layers.<i>.` (for `i < mtp_num_hidden_layers`) are rewritten to `mtp.layers.<mtp_start_layer_idx + i>.`; this includes globs such as `mtp.layers.0.*`. Entries that start with `re:` or `*`, and non-MTP names, are left exactly as written, matching the existing `ignored_layers`/`exclude_modules`/`quantized_layers` remaps.

## Details

**Root cause.** The AMD Qwen4Exp draft builds its layers as `mtp.layers.<num_hidden_layers + i>`, while checkpoints name them `mtp.layers.<i>`. `_make_draft_vllm_config` shifts the checkpoint names in `ignored_layers`, `exclude_modules` and `quantized_layers`, but `QuarkConfig` keeps its layer names inside `quant_config` (`exclude`, `layer_quant_config`), which was not touched. Every literal MTP entry there was dead for the draft, so `QuarkConfig.get_quant_method` fell through to the global scheme (MXFP4) for BF16 MTP modules.

**Fix.** Rename them through Quark's existing hook for this, `QuarkConfig.apply_vllm_mapper`, with a `WeightsMapper` prefix map `mtp.layers.<i>.` -> `mtp.layers.<num_hidden_layers + i>.`. The mapper is built in the draft rather than declared as a class-level `hf_to_vllm_mapper` because the target index depends on `num_hidden_layers`.

**Why keep the layer offset.** Qwen3-Next removed the same offset in #25079 and Qwen3.5 builds its MTP layer as `mtp.layers.{idx}` (#34110), so their checkpoint names match without a remap. Qwen4Exp's offset (introduced with the model in #53896) is now relied on: #60023 documents `--kv-cache-dtype-skip-layers 48` to keep only the MTP layer's KV cache unquantized, and that option selects layers by index; the offset also keeps index-keyed PLE layer assignment (`ple_layer_ids`) off the draft. Renumbering would change both silently, so this PR keeps the offset and completes the existing remap.

**Scope.** AMD and NVIDIA Qwen4Exp MTP drafts; Quark only.

**Related.** Not duplicated by: #49900 (strips the synthetic `draft_model.` root for draft-model drafters), #59040 (`mtp.fc` in `qwen3_5_mtp.py`).

**CI.** The unit test runs on CPU in the existing Qwen4Exp test file. The end-to-end validation above was run outside CI.
