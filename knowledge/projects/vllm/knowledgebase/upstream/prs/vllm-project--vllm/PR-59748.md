# [Bug fix]: Fix streaming reasoning detokenization for DeepSeek R1 (by…

[Upstream PR](https://github.com/vllm-project/vllm/pull/59748) · state: open · merged: False

## Original PR description

Root Cause
DeepSeek R1 uses a byte-level BPE tokenizer. vLLM's incremental detokenizer emits text token-by-token  each token may decode to a single UTF-8 byte. The raw delta_text fed to extract_reasoning_streaming was being streamed directly to the client. For CJK or any non-ASCII content, this produces corrupted glyphs like "Ċ", "åĹ¯" (individual bytes, not assembled UTF-8).

Fix (deepseek_r1_reasoning_parser.py)
_decode_ids() — Re-decodes a list of token IDs via tokenizer.decode(ids, skip_special_tokens=True), which assembles multi-byte UTF-8 sequences correctly across token boundaries.
_reasoning_token_ids() — Extracts only the token IDs inside the <think>…</think> span from the cumulative current_token_ids.
extract_reasoning_streaming() — On every streaming step, re-decodes the full reasoning span so far, then slices off only the fresh suffix (tracked via _prev_reasoning_decoded_len) to return as the delta. This is O(n) per step but correct the same approach used by other vLLM parsers for byte-level BPE models.
Content after </think> -Still uses delta_text directly (no corruption there since it's already in the regular content path).
