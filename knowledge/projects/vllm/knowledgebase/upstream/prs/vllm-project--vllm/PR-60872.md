# [CI][ROCm] Wait for VRAM to settle before building LLM in test_full_graph

[Upstream PR](https://github.com/vllm-project/vllm/pull/60872) · state: closed · merged: True

## Original PR description

## Overview

`tests/compile/fullgraph/test_full_graph.py` builds `LLM` directly and so skips the ROCm startup-memory guard that every `VllmRunner`-based test has had since [#49287](https://github.com/vllm-project/vllm/pull/49287). When the device is not free as a test starts, the engine fails its startup check instead of waiting for the memory to come back. Call the same guard `VllmRunner` calls.

Six tests in this file failed that way on the `:amd: (MI355 DPX) PyTorch Fullgraph` step in [Buildkite #93716](https://buildkite.com/vllm/ci/builds/93716/list?jid=01a11edf-b64d-4af0-91f8-60f8f72d7308&tab=output).

## Claims

- The memory was not this job's. `rocm-smi`, run by the step before any test started, shows a PID outside the job's pod holding 43.7 GiB on a card already 89% occupied.
- The threshold is the engine's own condition rather than a tuned constant. Startup requires free memory of at least `total * utilization`, so the wait is for used memory to fall to `total * (1 - utilization)`.
- The wait would have been long enough. The six failures span 103 seconds; usage dropped 147 s after the file started and every later test passed, against a 240 s bound.
- No-op when the device is clean, and no-op off ROCm, so NVIDIA steps are unaffected.

## Validation

1× AMD MI355X (gfx950, 287.98 GiB, SPX), ROCm 7.2, PyTorch `2.13.0+git733fca1`, vLLM `19c0bed584`. The CI condition was reproduced by holding 40 GiB in a separate process and releasing it 90 s later, which puts the device above the 23.04 GiB this card implies at the default utilization of 0.92.

| Run | Result |
|---|---|
| One test, 40 GiB held, before this change | failed in 11 s on the startup check, 247.31 of 287.98 GiB free against 264.95 needed |
| Same, after this change | waited 78 s for the release, then passed |
| Whole file, clean device | 11 passed, no wait |

The first row is the same failure as the six in CI.

## Details

Converting `run_model` to `VllmRunner` would pick up the guard at both construction and teardown, but `VllmRunner` also overrides `max_model_len`, `block_size`, `enable_chunked_prefill` and `kernel_config.enable_jit_warmup`, all of which change what a compilation test compiles. The teardown half is worth little here anyway, since every test in this file runs in its own process.
