# [Security] Gate NIXL remote-decode pulls on bidirectional transfer

[Upstream PR](https://github.com/vllm-project/vllm/pull/64891) · state: open · merged: False

## Original PR description

## Overview

With bidirectional transfer disabled, a request carrying remote-decode block metadata could reserve local blocks and wait forever for a receive that was never registered. Require bidirectional transfer before reporting a D-to-P external cache hit.

## Claims

- One-way requests compute their prompt locally instead of waiting for a disabled D-to-P receive.
- Aborting those requests frees their blocks, and a subsequent ordinary request can run.
- Enabled bidirectional transfers retain their existing behavior.

## Validation

- New scheduler regression on unmodified main: all three roles fail because the request enters WAITING_FOR_REMOTE_KVS.
- With the change and VLLM_DISABLE_REQUEST_ID_RANDOMIZATION=0: the complete test_bidirectional_kv_transfer.py suite passes (35 tests).
- Combined bidirectional and NIXL connector suites: 231 passed, 5 failed locally. The same five failures reproduce without the source change: two abort-timeout cases requiring unavailable runtime support, one packed-region alias case, and two compatibility-hash cases requiring an uncached model config.
- pre-commit on all files: unrelated macOS entrypoint-path failure and seven typing errors in two unchanged files. Changed-file checks pass.
- A dedicated one-GPU CI job starts RemoteOpenAIServer with Qwen/Qwen3-0.6B and request-ID randomization enabled. It sends the remote-decode metadata and checks completion plus a later ordinary request. Full-server validation is pending CI; the local Mac lacks NIXL and compiled vLLM extensions. GPU model accuracy evaluation was not run locally.

Commands:

```bash
VLLM_DISABLE_REQUEST_ID_RANDOMIZATION=0 VLLM_TARGET_DEVICE=cpu PYTHONPATH=$PWD uv run --no-sync .venv/bin/python -m pytest tests/v1/kv_connector/unit/test_bidirectional_kv_transfer.py -q
VLLM_TARGET_DEVICE=cpu HF_HUB_OFFLINE=1 PYTHONPATH=$PWD uv run --no-sync .venv/bin/python -m pytest tests/v1/kv_connector/unit/test_bidirectional_kv_transfer.py tests/v1/kv_connector/unit/test_nixl_connector.py -q
```

## Details

Flow: client supplies do_remote_decode and remote blocks → pull lookup claims asynchronous external tokens → scheduler allocates blocks → receive registration declines D-to-P loading because bidirectional transfer is disabled → request waits for a completion that cannot arrive. The lookup now checks the same configuration gate before claiming the hit. Existing one-way prefill/send semantics remain in use; no timeout-based reclamation is introduced.

The check sits below the NIXL facade and MultiConnector dispatch, covering every API or direct-engine entry point that reaches this pull lookup, including streaming and batch requests. Push mode does not claim D-to-P tokens through this branch.

### Duplicate-work check

Read diffs for #64860 (processed-block retries), #59874 (posted/staged receive cleanup), #56585 (incomplete prefill metadata), #55801 (recompute threshold), #62065 (lease slots), #55374 (range loads), #59343 (shared prefix loads), #57987 (background receiver), #62453 (host-buffer hybrid transfers), #64397 and merged #64733 (pipeline-parallel transfers), and #38900 (parallel sampling). None gates the initial remote-decode external hit on bidirectional transfer being enabled. This change adds only that missing gate.
