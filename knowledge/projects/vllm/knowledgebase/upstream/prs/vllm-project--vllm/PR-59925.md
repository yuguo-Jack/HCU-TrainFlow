# [DeepSeek-V4-P3] deterministic MoE DeepEP

[Upstream PR](https://github.com/vllm-project/vllm/pull/59925) · state: open · merged: False

## Original PR description

## Motivation

For DeepSeek-V4 MoE, enabling batch-invariant quantization alone does not fix expert kernel selection, routing GEMM arithmetic, DeepEP low-latency capacity, or CUDA Graph metadata. This PR wires the supported MoE/DeepEP path so those choices are explicit and unsupported kernels fail closed.

## Changes

- Enable the installed DeepGEMM batch-invariant controls from vLLM's process-wide initialization, checking for the control and masked grouped-GEMM APIs. Use the supported expert backend and stable router GEMM in batch-invariant mode rather than M-dependent low-latency routing kernels.
- Align contiguous and masked expert SiLU x Mul FP8 quantization with supported FP32/rounded FP32/packed UE8M0 scales, routed-expert clamp, and per-token accumulation. Use the static padded masked-M capacity for launch tuning, avoiding a live GPU-to-host maximum during CUDA Graph capture; recompute dynamic expert metadata outside piecewise capture where required.
- Bound DeepEP low-latency dispatch capacity with `VLLM_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK` (default 128) and stage larger local batches. The rank-wide maximum determines the number of stages, so every EP rank participates in each dispatch/combine, including empty tail stages. Align low-latency FP8 dispatch quantization and launch shared experts at most once for the full batch.
- On the DeepEP low-latency MNNVL path, prefer the shared-expert auxiliary stream when its existing preconditions hold; otherwise retain the previous overlap choice.

## Staged MoE flow

Only the DeepEP low-latency prepare/finalize contract opts into this rank-synchronous staging. The shared-expert branch is shown logically; its overlap with routed work depends on runtime preconditions.

## Performance observation

The shared-expert stream change's commit reports the following **DS4-Flash on GB200** throughput; these are author-reported measurements, not benchmarks rerun for this PR:

| Change measured | Before | After | Relative change |
| --- | ---: | ---: | ---: |
| Shared-expert overlap on DeepEP LL over MNNVL | 17,036 tok/s | 18,150 tok/s | +6.5% |

The commit does not specify GPU count, request mix, batch configuration, or variance. This is a directional observation about that stream choice, not a measured performance gain for the entire MoE/DeepEP PR or proof of numerical invariance.

## Scope and validation

Builds on #59863 and #59883. Until they land and this branch is rebased, their commits also appear in the PR diff. The guarantee being pursued is tokenwise expert computation under supported kernels; request-level routing, capacity, collective staging, and graph planning have their own execution contracts. This PR does not claim full-model batch invariance or train/rollout equivalence.

Added expert tests for backend selection, exact anchor-token output across co-batches/metadata capacities, and masked quantization behavior. `python -m compileall -q vllm tests` and `git diff --check` passed locally. CUDA runtime, multi-rank DeepEP staging, and end-to-end model evaluations were not run in the local Windows environment. AI assistance was used; human review and GPU validation remain necessary.
