## Overview

Fix FULL adaptive-verification cost profiling so timed replays use the configured KV context. TRITON_ATTN's capture metadata currently resets GPU `seq_lens` to 1, replacing the context prepared for the probe.

## Claims

- Preserve `VLLM_ADAPTIVE_VERIFICATION_PROFILE_CONTEXT_LEN` in the attention metadata used for timed FULL replays.
- Add a real-weight LLM startup regression for GPU/CPU KV-length consistency and document the profiling behavior.

## Details

The capture builder writes placeholder KV lengths into shared GPU buffers. Reusing it during cost profiling makes the replay read those placeholders rather than the probe's configured context.

The internal `profile_step_cost` flag selects normal execution metadata in the existing step-timing loop. It defaults to false and applies the same condition to ordinary and microbatched preparation. FULL capture and ordinary FULL warmup retain capture metadata. Probe generation, cost formulas and Graph allocation retain their existing behavior.

Related work covers MRV1 metadata ([#54604](https://github.com/vllm-project/vllm/pull/54604)), DCP capture context ([#61496](https://github.com/vllm-project/vllm/pull/61496)), PIECEWISE padding ([#60049](https://github.com/vllm-project/vllm/pull/60049)) and cost-model changes ([#62960](https://github.com/vllm-project/vllm/pull/62960)). This patch fixes FULL cost-probe metadata in main's existing profiling protocol and applies independently of those changes.

AI assistance was used to implement the patch, run validation, and draft this description. The submitter reviewed every changed line and personally reran the related tests and strict model comparison.
