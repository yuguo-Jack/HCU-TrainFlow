# [Bugfix][Multimodal] Transfer pruning-adjusted M-RoPE state in disaggregated P/D

[Upstream PR](https://github.com/vllm-project/vllm/pull/62732) · state: open · merged: False

## Original PR description

## Overview

Fix empty completions for EVS-pruned M-RoPE models in disaggregated
prefill/decode by transferring prefill's pruning-adjusted position matrix and
delta to decode.

## Claims

- Preserve post-EVS M-RoPE state across remote-prefill handoff for Model Runner
  V1 and V2.
- Carry that state through TP/PP output aggregation and scheduler
  `kv_transfer_params`.
- Restore the transferred state before decode instead of rebuilding it from
  the original, unpruned multimodal metadata.
- Validate the versioned JSON-safe payload and remove it from synthetic
  rejected-request cleanup messages.

## Details

The failure sequence is:

1. Prefill's Efficient Video Sampling (EVS) prunes video tokens and recomputes
   both the per-token M-RoPE positions and final position delta.
2. Disaggregated serving transfers the resulting KV blocks to decode.
3. Decode constructs a new request from the original, unpruned multimodal
   metadata.
4. Because the media prefix is already remote-cached, decode does not run the
   multimodal encoder or EVS recomputation. It therefore samples with stale
   positions and can immediately produce EOS.

This change defines a versioned `MRoPEPositionState`, captures the latest
post-EVS state only on KV producers, propagates it through worker output and
the scheduler, and restores it on the decode worker. Aggregation handles both
tensor and pipeline parallelism, including the first pipeline stage where
multimodal pruning occurs. Scheduler storage preserves the latest state across
chunked prefill and preemption/resume. Rejected-request cleanup strips the
payload because its one-token placeholder prompt only needs connector metadata
to release remote blocks.

The payload contains the full int32 position matrix plus the scalar delta. It
is approximately 20 KiB for the validated 1,704-token prompt. Transferring only
the delta is insufficient: block-aligned remote transfer can leave an uncovered
prompt suffix that still needs corrected per-token positions.

Export requires a one-time GPU-to-host materialization per pruned producer
prefill. It is wrapped as intentional because EVS already synchronizes
immediately beforehand while reading the recomputed delta; it does not add a
steady-state decode synchronization.

Thanks @NickLucche! The relevant combination in our Cosmos setup is EVS video pruning + M-RoPE + disaggregated P/D, rather than a Cosmos-specific architecture.

The sequence I traced is:

  1. Prefill runs the video encoder and EVS, then updates the per-token M-RoPE positions and final delta.
  2. Decode receives the KV cache but initializes its position state from the original multimodal metadata.
  3. Since remote KV covers the media prefix, decode skips the encoder/EVS work that produced the corrected positions. It can still call the recompute function with no media embeddings, but that returns its existing positions unchanged.

I also tested the official Qwen/Qwen3-VL-2B-Instruct checkpoint through native vLLM/NIXL P/D, without Dynamo, using video_pruning_rate=0.6 and Model Runner V1 on GB200. For 20 frames, prefill corrected the delta to −1401, while decode retained −1520. With this PR, decode received −1401 and its complete position matrix matched prefill.
