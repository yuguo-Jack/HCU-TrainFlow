# [Bugfix][Frontend] Emit kv/ec transfer params at the top level of render output

[Upstream PR](https://github.com/vllm-project/vllm/pull/61241) · state: closed · merged: True

## Original PR description

## Overview

Python render now puts `kv_transfer_params` and `ec_transfer_params` at the top level of the generate request on every route, instead of leaving them in `sampling_params.extra_args`. 

## Claims

- Chat and completions render emit the transfer params as top-level fields, the same as responses render
- `sampling_params.extra_args` no longer carries `kv_transfer_params` / `ec_transfer_params` on any render route
- Python render → Rust generate keeps the KV params. Before, P/D quietly recomputed the prompt

## Validation

```bash
pytest tests/entrypoints/scale_out/render/test_render.py -v
```

Added tests:
- Chat render: both params at the top level, `extra_args == {"foo": 1}` and the request's own `vllm_xargs` untouched
- Completions with two prompts: each generate request carries both params with no `extra_args`
- The existing responses test now also checks that `extra_args` is empty

## Details

Chat and completions only got the params through `to_sampling_params` which puts them in `extra_args`. Responses render sent them in both places. Rust generate never reads `extra_args`. It merges the top-level fields into `vllm_xargs`, so a Python render in front of a Rust generate lost the KV params with no error.

Leaving a copy in `extra_args` is also a trap. If a router clears the top-level block to turn P/D off, Python generate only copies non `None` values back, so the stale `extra_args` copy would still reach the engine.

The fix is a small helper `_hoist_transfer_params`. It copies `extra_args` before popping because `to_sampling_params ` aliases `request.vllm_xargs`. Python generate copies the top-level values back into `extra_args` for the engine, so engine behavior doesn't change.

One observable change. Anything reading `sampling_params.extra_args.kv_transfer_params` from render output won't find it there anymore. I am unaware of any such client doing this. llm-d's coordinator doesn't read it. `vllm_xargs` can't carry a dict value, so stripping these keys can't remove anything a client put there.

Not a duplicate.

🟡 (optional) Chat/completion/responses render requests can now crash with an unhandled 500 instead of a clean ErrorResponse. If a client's vllm_xargs reuses the key "kv_transfer_params" or "ec_transfer_params" with a non-dict value and the request's own dedicated field is unset, to_sampling_params leaves that value in extra_args, and _hoist_transfer_params (serving.py:51-58) pops it unchanged and feeds it into GenerateRequest.kv_transfer_params/ec_transfer_params, typed dict[str, Any] | None, raising a pydantic ValidationError. api_router.py never wraps render_chat_request/render_completion_request/render_responses_request in try/except, so it surfaces as an opaque 500. Fix: in _hoist_transfer_params, only treat the popped value as transfer params when isinstance(value, dict); otherwise leave it in extra_args or raise a proper ErrorResponse.

<summary>Why this was flagged</summary>

Trigger: a ChatCompletionRequest/CompletionRequest/ResponsesRequest with vllm_xargs={'kv_transfer_params': <str|int|float|list>} and no dedicated kv_transfer_params field set, via POST /v1/chat/completions/render, /v1/completions/render, or /v1/responses/render (api_router.py). to_sampling_params (chat_completion/protocol.py:729-732, same pattern in completion/protocol.py:367-371 and responses/protocol.py:530-534) leaves that value under extra_args['kv_transfer_params'] since self.kv_transfer_params is falsy. _hoist_transfer_params (serving.py:55-58) pops it unchanged; render_chat_request:171 assigns it to the typed GenerateRequest field, raising pydantic.ValidationError. api_router.py has no try/except around the handler call, so FastAPI returns a generic 500 instead of the router's documented 400 ErrorResponse. Before this diff, chat/completion render never promoted extra_args into a typed field, so this value stayed inert.

**Verification:** The hoist change introduces a reachable 500 regression on all three render routes. to_sampling_params (chat_completion/protocol.py:729-735) seeds extra_args from vllm_xargs and only overwrites extra_args["kv_transfer_params"] when the dedicated field is truthy, so a non-dict value under that key in vllm_xargs survives.
