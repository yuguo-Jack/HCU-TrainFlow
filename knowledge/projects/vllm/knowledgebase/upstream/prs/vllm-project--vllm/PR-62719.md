# [Bugfix][Frontend] Cut stop strings and stop tokens on derender

[Upstream PR](https://github.com/vllm-project/vllm/pull/62719) · state: closed · merged: True

## Original PR description

## Overview

Derender was decoding every token generate sent back which meant stop strings and stop tokens came back into the text. This change cuts them the way the engine does. It fixes #57052 and supersedes #59510. 

## Claims

- Batch chat and completions derender cut the stop string and drop the stop token, the same as `vllm serve`. That includes `include_stop_str_in_output`, `min_tokens` and `ignore_eos`.
- `stop_reason` is passed through from generate. If generate doesn't send it (older servers), derender fills it in from what it matched. It stays null for the primary EOS.
- Completions streaming now drops the stop token which chat already did after #61757.
- Streaming derender returns 400 when the request has stop strings and points to `output_mode=text`, as agreed on #47161.

## Validation

```bash
pytest tests/entrypoints/scale_out/derender/test_derender.py -v
pytest tests/entrypoints/scale_out/derender/test_derender_stream.py -v
```

- All pass. That includes the live render-server tests and `test_e2e_token_identity`, which checks `encode(derender(ids)) == ids` still holds.
- 19 of the 26 new tests fail without the fix. The other 7 check that nothing extra gets trimmed.
- `test_text_parity_stop_string` now asserts derender == `output_mode=text` == `/v1/completions`, both with a reported `stop_reason` and with the request's stop list. It needs a GPU and I haven't run it yet. It'll need `/ci run`.

## Details

- It reuses `check_stop_strings` from the engine detokenizer. The EOS ids and generation_config included are loaded once in `__init__` instead of on each call.
- The stop token is checked first, then the stop string on the text that's left. A matched string wins as `stop_reason` which is the engine's order.
- The parser still gets the full `token_ids`, like the main server.
- Streaming is a 400 rather than holding text back, so `DerenderStreamState` doesn't change.
- Known gaps:
  - A streaming request sent with no `chat_request` or `completion_request` can't be rejected.
  - With a parser configured, a stop string that overlaps a special token can cut differently from `vllm serve`.
  - Logprobs aren't trimmed.
