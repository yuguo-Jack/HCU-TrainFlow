# [Bugfix][Frontend] Use Anthropic error envelope for /v1/messages validation failures

[Upstream PR](https://github.com/vllm-project/vllm/pull/58023) · state: open · merged: False

## Original PR description

## Purpose
Fixes the primary bug in #57997: `/v1/messages` and `/v1/messages/count_tokens` return the OpenAI error envelope (with a Python `repr` inside the message) for request-validation failures, while handler-raised errors already use the documented Anthropic envelope. This adds route-aware handling in `validation_exception_handler` so both routes consistently return `{"type": "error", "error": {"type": "invalid_request_error", "message": ...}}` with a readable message instead of a Python dict repr.

## Not duplicating existing work
Per AGENTS.md's duplicate-work check: no open PR references #57997. #43380 touches the same general area (`vllm/entrypoints/anthropic/api_router.py`) but addresses a different, explicitly-separate part of the issue — mapping handler-raised exception class names (e.g. `NotFoundError`) to Anthropic's snake_case `error.type` vocabulary (e.g. `not_found_error`). This PR only changes `validation.py`'s pre-route FastAPI validation path and doesn't touch `api_router.py`, so it doesn't overlap with #43380.
