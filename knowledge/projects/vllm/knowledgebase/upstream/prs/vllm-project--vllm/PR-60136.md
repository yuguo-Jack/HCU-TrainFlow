# [Bugfix][Rust Frontend] Alias `qwen3_xml` to `qwen3_coder` and add `qwen3_json` for the Qwen JSON format

[Upstream PR](https://github.com/vllm-project/vllm/pull/60136) · state: closed · merged: True

## Original PR description

## Overview

In Python, `qwen3_xml` has always parsed the Qwen3-Coder XML format (`<tool_call><function=...><parameter=...>`): it was added as a second implementation of `qwen3_coder` in #25028 and became the same class in #45003. In Rust, `qwen3_xml` instead parsed the Qwen2.5/QwQ/Qwen3 JSON format (`<tool_call>\n{"name": ..., "arguments": ...}\n</tool_call>`), so recipes such as [Qwen/Qwen3.8-27B](https://recipes.vllm.ai/Qwen/Qwen3.8-27B) that use `VLLM_USE_RUST_FRONTEND=1` with `--tool-call-parser qwen3_xml` produced no tool calls.

This PR fixes the name without regressing Qwen models that rely on Rust parser auto-detection.

## Claims

- `qwen3_xml` is an alias of `qwen3_coder` in both frontends.
- The existing Rust parser for the Qwen JSON format is kept unchanged and renamed to `qwen3_json`. Rust auto-detection routes Qwen2.5, QwQ and Qwen3 models to it.
- Python registers `qwen3_json` as an alias of `hermes` for now, so both frontends accept the same `--tool-call-parser` values. A TODO tracks a dedicated Python parser.
- Explicit `--tool-call-parser hermes` keeps the generic Hermes behavior shared with Python.

## Validation

- `cargo nextest run -p vllm-parser --features test-util`: 553 passed.
- `cargo nextest run -p vllm-chat`: 392 passed, including the roundtrip tests and the XGrammar grammar replay.
- New test `factory_parses_qwen3_coder_format_with_qwen3_xml`: `qwen3_xml` parses the Qwen3-Coder XML format.
- Qwen2.5-7B-Instruct and Qwen2.5-Coder-7B-Instruct, checked locally with temporary roundtrip cases (not committed):
  - Under `hermes`, `content` gets a trailing `\n\n`.
  - Under `qwen3_json`, all three tool-choice modes (auto, required, named) roundtrip, and their grammars pass a token-zero XGrammar replay.
- QwQ-32B renders tool calls character-for-character the same as Qwen2.5.
- Python: `ToolParserManager.get_tool_parser("qwen3_json")` resolves to `Hermes2ProToolParser`.

## Details

- `qwen3_xml` registers `Qwen3CoderToolParser` directly, like `llama3_json`/`llama4_json`, instead of a separate wrapper type.
- Why Qwen models are not routed to `hermes` in Rust. The Qwen chat templates render `\n` before and between tool calls, and `hermes` does not handle it:
  - The `hermes` parser leaks this `\n` into `content`.
  - The Hermes structural tag joins calls with an empty separator, so `tool_choice=required` rejects the `\n` between parallel calls. With `hermes`, the Qwen3-0.6B grammar replay fails on exactly this token.
- `qwen3_json` keeps the newline framing and the `Model::Qwen3` structural tag, so the Qwen3 `tool_call_mix` roundtrip and its grammar replay fixture are unchanged.
- The bench is renamed from `qwen3_xml` to `qwen3_json`.

Thanks @lianakoleva  for tracking this down! `qwen3_xml` is indeed an alias of `qwen3_coder` in Python (same Qwen3-Coder XML format since #25028), so the Rust `qwen3_xml` should not parse the `<tool_call>{json}</tool_call>` format.

I rebased onto main and pushed follow-up commits with a narrower approach:

- Register `Qwen3CoderToolParser` directly under `qwen3_xml` (like `llama3_json`/`llama4_json`), instead of a separate wrapper type.
- Keep the existing Qwen JSON parser unchanged, but rename it to `Qwen3JsonToolParser` under `qwen3_json`, and route auto-detected Qwen2.5 / QwQ / Qwen3 models to it.
- Register `qwen3_json` in Python as an alias of `hermes` for now (with a TODO for a dedicated parser), so both frontends accept the same `--tool-call-parser` values.

Routing Qwen3 to `hermes` would regress the Rust auto path. The Qwen chat templates put `\n` before and between tool calls, so `hermes` leaks `\n\n` into `content`. Its grammar also uses an empty separator, so `tool_choice=required` rejects the `\n` between parallel calls (XGrammar replay fails for Qwen3-0.6B). With this change the `tool_call_mix` roundtrip and its grammar replay fixture stay as they were.
