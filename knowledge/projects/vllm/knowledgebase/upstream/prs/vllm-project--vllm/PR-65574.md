# [Perf][Frontend] Reduce chat SSE serialization and Harmony polling

[Upstream PR](https://github.com/vllm-project/vllm/pull/65574) · state: open · merged: False

## Original PR description

## Overview

Reduce per-token frontend CPU work by reusing chat SSE frame templates and polling Harmony completed messages only after message-ending tokens. Raw-stream consumers and per-token metadata retain model serialization.

Related: [#52875](https://github.com/vllm-project/vllm/pull/52875) applies frame templating to `/v1/completions`; this change targets `/v1/chat/completions` and Harmony parsing, so it does not duplicate that PR. AI assistance was used to review and prepare this contribution.

## Claims

- Eligible non-final content/reasoning frames preserve the protocol models' JSON bytes while avoiding repeated envelope construction and serialization.
- Harmony avoids repeatedly rebuilding all completed messages for every generated token; message completion, malformed-stream recovery and EOS handling remain equivalent.
- Supplied historical H100 measurements report 14,567 → 30,350 output tok/s for Qwen3-0.6B chat at c256 (+108.4%), and 10,293 → 11,818 for long-output gpt-oss-20b chat at c256 (+14.8%) with Harmony gating alone.

Example reproduction for the first benchmark, on each revision with one default API server:

```bash

  --endpoint /v1/chat/completions --dataset-name random \
  --random-input-len 64 --random-output-len 512 --random-range-ratio 0 \
  --num-prompts 2048 --max-concurrency 256 --ignore-eos
```

## Details

The template is derived once per choice through the same chunk builder and protocol serializer. Content/reasoning fields are encoded only for exact supported delta types; tool calls, subclasses, extras, unencodable text, terminal chunks, and requests needing per-token metadata use the model path. Raw-generator overrides and instrumentation retain their original dispatch path. Harmony reads completed messages after the encoding's stop tokens and after EOS, when completion can occur.

Both changes reuse existing frontend APIs and add no dependency or flag. Existing chat CI selects the serialization tests; the Harmony parser suite is added to the CPU reasoning/renderers job and removed from its tethering exception.

Benefits depend on frontend saturation. In the supplied Qwen3-8B random 512/128 c512 run, throughput improved 3.3% and TTFT p50 fell 68%, while TPOT p50 rose 19.8% as requests entered decode earlier. Instrumenting the raw generator disables frame templating. GPU/server validation remains pending and must complete before merge.
