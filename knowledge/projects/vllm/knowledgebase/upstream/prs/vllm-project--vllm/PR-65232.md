# [KV Connector] Spec-driven TP slicing for NIXL KV transfers

[Upstream PR](https://github.com/vllm-project/vllm/pull/65232) · state: open · merged: False

## Original PR description

## Overview

[3/N] of RFC #42082. KV cache specs now own `slice_for_tp_transfer`, and NIXL moves the byte ranges those slices give, replacing its own head, Mamba and `TPMapping` rank math. Mooncake and MoRIIO are unchanged.

## Claims

- **`KVCacheSpec.slice_for_tp_transfer`** returns paired views of a block for two ranks of different TP sizes. `contiguous_byte_ranges` turns them into byte ranges.
  - Attention: each receiving KV head reads the sending head at the same position among all ranks' heads. That rule covers GQA in both TP directions, replicated heads and MLA.
  - FlashInfer NVFP4 and Mamba1/Mamba2/GDN slice in spec subclasses next to their backends.
- **NIXL:** every layer, Mamba and PLE state included, is a region of kernel blocks moved as byte ranges through one descriptor model. The SSM/PLE descriptor tracks, the per-source split handles and `ssm_conv_transfer_utils.py` usage are removed.
- **Push:** P slices with its own views, so replicated KV reaches every D rank exactly once. D waits for the P ranks that write to it, and a P rank with nothing to write finishes at once.
- **Behavior changes:**
  - Hetero-TP Mamba2 with replicated groups now fails at the handshake instead of moving the wrong conv state (#61526).
  - Same-TP Mamba no longer needs `VLLM_SSM_CONV_STATE_LAYOUT=DS`.
  - `NIXL_CONNECTOR_VERSION` is 18 (`physical_blocks_per_group` replaces `physical_blocks_per_logical_kv_block`, `ssm_sizes` and `ple_block_len`).

The failures are macOS-only (Ray on CPU, triton, CUDA paths) and also fail on the base commit, plus the pre-existing `packed_dsv4[v41-aliased-groups]`. `test_nvfp4_spec_tp_slicing` in `tests/kernels/attention/test_flashinfer.py` passes.

- The existing real-model pull test (Qwen3-8B, gpt-oss, Gemma 3, DeepSeek-V3/V3.2, Qwen3-Next, Nemotron-Nano, Kimi-Linear, among others) and the hetero block-size sweeps pass with unchanged assertions.
- New tests check:
  - decode Mamba blocks assembled byte-exact from prefill blocks;
  - the push senders D waits for;
  - a P rank that has nothing to write.

**Not yet validated:** end-to-end P/D on GPUs (hybrid hetero-TP pull and push, MLA push in both TP directions, FlashInfer NVFP4). Needed before this leaves draft.

## Notes

- The remote spec is still derived by scaling the local one; engines should advertise their specs in the handshake.
- **Not a duplicate:**
  - #61531 and #55306 patch NIXL's conv-split code, and #63648 patches `TPMapping`. This PR removes both.
  - #62107 adds a layout flag to the generic spec, whereas this PR keeps format-specific slicing in backend subclasses.
- **Conflicts:** needs a rebase over the merged #64475 (NVFP4 head re-sharding), and conflicts with #61452. Supersedes #64812.
