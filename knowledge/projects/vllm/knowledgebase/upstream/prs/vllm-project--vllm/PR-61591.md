# [Bugfix][Model] Recognize Unlimited-OCR's renamed `unlimited_ocr` model_type

[Upstream PR](https://github.com/vllm-project/vllm/pull/61591) · state: closed · merged: False

## Original PR description

## Overview

Fixes `:nvidia: (H200 MIG 18GB) Multimodal Processor Shard 4`, which fails on main since 2026-10-14 (builds 94688, 94697 and later) at `test_model_tensor_schema[baidu/Unlimited-OCR]`. The `baidu/Unlimited-OCR` hub repo renamed its `model_type`, and vLLM only knew the old spelling.

## Claims

- `baidu/Unlimited-OCR` resolves to `UnlimitedOCRConfig` again with `trust_remote_code=False`, on both the latest hub revision and the previous one.
- Users serving the current checkpoint no longer hit "contains custom code ... pass `trust_remote_code=True`".
- No behavior change for other models.

## Validation

Reproduced on current main, then verified with this change. Hub revisions: `8249d20b28` (latest, `model_type: unlimited_ocr`) and `07dea832e2` (previous, `model_type: unlimited-ocr`).

| | `get_config("baidu/Unlimited-OCR", trust_remote_code=False)` on `8249d20b28` | `...` on `07dea832e2` |
|---|---|---|
| main | `ValueError: ... contains custom code ...` | OK |
| this PR | OK (`UnlimitedOCRConfig`, `model_type=unlimited_ocr`) | OK (`model_type=unlimited-ocr`) |

```
pytest tests/models/multimodal/processing/test_tensor_schema.py -k Unlimited
```

- main: `1 failed` (the CI failure).
- this PR: `1 passed`.

`ModelConfig("baidu/Unlimited-OCR", trust_remote_code=False, dtype="auto")` also succeeds on both revisions with this change.

## Details

The hub commit "Update files for compatibility with transformers (#13)" (2026-10-14 06:17 UTC) changed `config.json` `model_type` from `unlimited-ocr` to `unlimited_ocr`. `_CONFIG_REGISTRY` only had the hyphenated key, so the config fell through to the checkpoint's `auto_map` remote code, which `ModelConfig` rejects without `trust_remote_code`.

The change registers the underscore spelling next to the hyphenated one in the three places keyed on this `model_type`: `_CONFIG_REGISTRY`, `_MODEL_TYPES_WITH_INCORRECT_TOKENIZER_CLASS` and `_MODEL_TYPE_TO_CHAT_TEMPLATE_FALLBACK`. `_register_config_class` sets `config_class.model_type` to the key it registers, so one class serves both spellings. The hyphenated keys stay so older revisions and local copies keep loading.

Not a duplicate: no open PR touches this (searched open PRs for `Unlimited-OCR`, `UnlimitedOCR`, `test_tensor_schema`). The alternative of setting `trust_remote_code=True` in `tests/models/registry.py` would hide the failure in the test but leave `vllm serve baidu/Unlimited-OCR` broken for users, and would execute hub code for a natively supported model.
