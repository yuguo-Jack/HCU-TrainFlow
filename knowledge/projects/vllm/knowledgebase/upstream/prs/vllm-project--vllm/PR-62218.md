# [Bugfix][Frontend] Reject an empty conversation in every renderer

[Upstream PR](https://github.com/vllm-project/vllm/pull/62218) · state: open · merged: False

## Original PR description

## Overview

Renderers with their own chat encoding (DeepSeek V3.2/V4/V4.1) render an empty conversation to a bare BOS prompt, so `/v1/responses` with `input: []` returns 200 with text generated from nothing. This returns the same 400 that HF-tokenizer models already return.

## Claims

- An empty conversation now returns 400 `BadRequestError` ("Cannot apply chat template to an empty conversation. Provide at least one message.") for every renderer.
- Non-empty conversations are unchanged, including Responses requests with `input: []` plus `instructions` or `previous_response_id`.

## Validation

New `tests/renderers/test_empty_conversation.py`: the 3 rejection cases fail on `main` and pass with this change; the 2 controls pass on both.

## Details

`transformers` refuses an empty conversation in `apply_chat_template`, but the DeepSeek tokenizers override that method and skip the check. The check now runs at the start of `BaseRenderer.render_chat` and `render_chat_async`, after each endpoint has built its messages. The Rust frontend already rejects an empty conversation (`ChatRequest::validate`); this brings the Python frontend in line.

- Shawnsuun · comment · 2026-10-31T05:26:49Z · [source](https://github.com/vllm-project/vllm/pull/62218#issuecomment-6539551453)

One more path this doesn't reach: Harmony (gpt-oss) chat completions. `OnlineRenderer._make_request_with_harmony` builds the preamble and calls `render_for_completion(messages)` directly, so it never goes through `BaseRenderer.render_chat`. With a gpt-oss model, `POST /v1/chat/completions` with `"messages": []` still returns 200 and generates from the bare system/developer preamble.

A check at the top of `OnlineRenderer.render_chat` (before the Harmony/non-Harmony split) covers it, e.g.:

```python
if not request.messages:
    return self.create_error_response(
        "messages must contain at least one message", param="messages"
    )
```

Happy to leave it to you to fold in here rather than open a separate PR. (Found while auditing chat-completion request validation against the OpenAI spec, which has `minItems: 1` on `messages`; AI-assisted.)
