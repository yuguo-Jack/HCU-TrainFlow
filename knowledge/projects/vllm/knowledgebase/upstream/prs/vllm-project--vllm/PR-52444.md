# [Bugfix][Responses] Route browser streams to web search events

[Upstream PR](https://github.com/vllm-project/vllm/pull/52444) · state: open · merged: False

## Original PR description

Assisted-by: OpenAI Codex

## Purpose

Harmony `browser.*` recipients were classified as MCP tools during Responses API
streaming. When the browser action completed, the browser-specific dispatcher
also emitted the correct web-search lifecycle.

This caused one browser action to emit both an MCP output item and a web-search
output item.

This change:

- excludes `browser.*` recipients from MCP namespace classification;
- lets the browser-specific dispatcher exclusively emit their lifecycle;
- adds a regression test covering the complete streaming event sequence.

Fixes #52443 

## Test results

Focused test:

```text
.venv/bin/python -m pytest \
  tests/entrypoints/openai/responses/test_serving_responses.py::TestHarmonyStreamingEvents::test_browser_stream_emits_only_web_search_events \
  -vv
```
### Before the fix

The test fails. The browser action incorrectly emitted both lifecycles:

```text
response.output_item.added
response.mcp_call.in_progress
response.mcp_call_arguments.delta
response.mcp_call_arguments.done
response.mcp_call.completed
response.output_item.done
response.output_item.added
response.web_search_call.in_progress
response.web_search_call.searching
response.web_search_call.completed
response.output_item.done
```
### After the fix

The test passes. Only the web-search lifecycle is emitted:

```text
response.output_item.added
response.web_search_call.in_progress
response.web_search_call.searching
response.web_search_call.completed
response.output_item.done
```
