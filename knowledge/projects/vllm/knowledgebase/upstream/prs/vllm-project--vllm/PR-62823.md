# [Rust Frontend] Apply response_format over structured_outputs like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/62823) · state: closed · merged: True

## Original PR description

## Overview

Python applies a non-`text` `response_format` on top of `structured_outputs` (`structured_outputs_from_response_format`, `vllm/entrypoints/generate/base/protocol.py`, used by chat and completions). The Rust frontend returns `structured_outputs` as soon as it is present and ignores `response_format`. This PR merges the two like Python.

## Claims

On `/v1/chat/completions` and `/v1/completions` with both fields set, the Rust frontend now behaves like Python:

- Same constraint kind (for example `structured_outputs: {"json": ..., "disable_any_whitespace": true}` with a `json_schema` response format): the `response_format` constraint wins, and the `structured_outputs` options (`disable_any_whitespace`, `disable_additional_properties`, `whitespace_pattern`) and backend are kept. Before, the request ran with the old schema.
- Different kinds (for example `structured_outputs: {"regex": ...}` with `response_format: {"type": "json_object"}`): 400 with Python's message, "You can only use one kind of structured outputs constraint but multiple are specified." Before, the request silently ran with the regex.
- `response_format` of type `text`, or absent: `structured_outputs` unchanged.

## Details

Python uses `dataclasses.replace`, which overrides the field of the same kind and leaves a field of another kind in place; `StructuredOutputsParams.__post_init__` then rejects two constraints. `convert_from_response_format` (`rust/src/server/src/routes/openai/utils/structured_outputs.rs`) is already the one place that lowers both DTO fields into `StructuredOutputsParams` for chat and completions, so the merge lives there: it compares the constraint kinds and either replaces the constraint or rejects the request. The completions variant (`convert_from_response_format_value`) now delegates to it instead of returning `structured_outputs` first. The merged params are validated as before when `response_format` contributed, so a `response_format` schema still gets its nesting and xgrammar checks.

One deliberate difference: a malformed `structured_outputs` constraint that `response_format` would override (`structured_outputs: {"json": "{"}` plus a valid `json_schema`) is still a 400, because `structured_outputs` is validated when it is deserialized. Python accepts it only because `dataclasses.replace` drops the old value before anything reads it.

Not a duplicate: vllm-project/vllm#47176 (inactive since 2026-10-01) adds structured-output validation in the same file, but does not change how `response_format` combines with `structured_outputs`.
