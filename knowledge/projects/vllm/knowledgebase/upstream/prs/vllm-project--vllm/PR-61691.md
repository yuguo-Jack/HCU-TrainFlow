# [Feature] Add workload snapshots to iteration metrics

[Upstream PR](https://github.com/vllm-project/vllm/pull/61691) · state: open · merged: False

## Original PR description

## Overview

Add optional scheduled-workload and queued-request snapshots to completed iteration records for Dynamo performance modeling. This layer owns workload counts and phase snapshots; timing stays in #61690 and publication stays in #52061.

Dependency order: #61690 (timing) → **#61691 (workload)** → #52061 (FPM exporter). The stack is independent of, and complementary to, #61424; that PR is not a prerequisite. [Previous layer](https://github.com/vllm-project/vllm/pull/61690) · [Next layer](https://github.com/vllm-project/vllm/pull/52061) · [Review only this layer](https://github.com/tedzhouhk/vllm/compare/b677a562906a4c1b9efc1bd8f3fe712a4a6f220c...5c733548955e31fb37ec819f200d675f953db432).

The existing PR numbers and review history are retained. All three target `main`, so downstream upstream-facing diffs are cumulative; review the layer-only comparisons and merge/rebase in order. Related proposals: #61423, #39979, #38760.

## Claims

- Default-off `--enable-iteration-workload-metrics` derives required timing without verbose logging or a separate timing option. Collection is transport-independent, with no ZMQ/OTLP dependency. Unsupported required timing fails validation instead of returning untimed records.
- Completed records join scheduled counts, prefill/decode attention-context sums and population variances, queued workload and GPU duration for the same iteration. This PR owns the workload-count and phase snapshot plumbing; it does not require #61424's profiler-counter refactor.
- Existing FPM classification is preserved: recompute chunks remain prefill work. For a prefill chunk with `kv_read=x` and `scheduled_tokens=y`, attention length is `x + y/2`; variance is across those current-iteration lengths, not full prompts. Decode statistics describe logical attention context, not physical KV residency or speculative-token counts.
- Async speculative rejection corrections reuse existing CPU sampled-token results and preserve snapshot identity and preemption generation. They add no D2H transfer, events, kernels or sampling changes.
- Queued snapshots keep FPM v1 semantics: preempted/remote-KV-waiting requests count as queued decode; other waiting requests as queued prefill. Both waiting queues are included without double counting. Normal snapshots follow the associated output; dummy snapshots are captured at submission.
- Timed attention-DP dummy records have empty scheduled work and may contain queued work. EngineCore emits zero-duration idle records at most once per second only after work, input queues and pending timings drain, including coordinated DP wave state. Publisher silence does not establish idle; delayed dummy associations are retained until joined.
- The synchronous offline frontend filters idle-only records without losing control/output messages. The exporter remains EngineCore-owned, independent of frontend consumption; self-benchmark orchestration stays in Dynamo.

## Details

Transport-independent types and accumulation live in `iteration_workload.py`; the Welford helper is in `utils/math_utils.py`. Enabled collection adds CPU bookkeeping and queue scans; default-off does not collect these snapshots. The FPM recompute convention and async correction semantics are unchanged by moving workload ownership into this layer.

Required timing supports generative CUDA models, `uni`/`mp` executors and out-of-process EngineCore. Pooling, non-CUDA, Ray/external-launcher and in-process configurations are rejected. PP reports only the last-stage output worker, not whole-pipeline latency; best-effort shutdown can discard tails.
