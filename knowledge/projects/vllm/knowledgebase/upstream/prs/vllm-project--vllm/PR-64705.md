# [XPU][UT] use fp32 when hf_runner on XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/64705) · state: open · merged: False

## Original PR description

This model has a token whose top-k MoE router logits are nearly tied. Both vLLM and HF accumulate bf16 rounding noise of similar magnitude, and at this tie that noise can push either side to pick a different expert, which shifts the token's softmax past the tolerance. The default bf16 HF reference happens to land on the opposite side of the tie from vLLM here, while vLLM's bf16 selection agrees with the fp32 result. Compare against an fp32 HF reference so the golden value sits on the well-defined fp32 side of the tie instead of an unstable bf16 one.
