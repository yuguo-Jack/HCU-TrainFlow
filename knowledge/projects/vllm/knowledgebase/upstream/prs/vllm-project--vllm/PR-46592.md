# Feat/invariant with prefix cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/46592) · state: open · merged: False

## Original PR description



## Purpose

This PR makes prefix caching compatible with batch-invariant inference, as part
of the batch-invariant work tracked in
https://github.com/vllm-project/vllm/issues/27433#issuecomment-4624935971.

Prefix caching is an important performance path for real workloads with shared
long prefixes, but it introduces a new source of variation: the same prompt can
resume from different prefix-cache hit lengths depending on cache state. In
batch-invariant mode, those different hit lengths should not cause the remaining
prefill work to be scheduled with arbitrary chunk boundaries, because that makes
the effective prefill shape depend on cache state rather than on a stable
canonical policy.

This PR fixes that by using a shared canonical chunk-block policy for both:

- the prefix-cache hit length accepted by the KV cache manager, and
- the prefill chunks scheduled after the cache hit.

With this, batch-invariant prefix-cache requests resume from stable block
boundaries, and the remaining prefill work is chunked consistently even when
the raw cache-hit length differs across runs or batch compositions.

The core behavior is:

- `VLLM_BATCH_INVARIANT_CANONICAL_PREFILL_CHUNK_BLOCKS=0` means auto.
- When batch-invariant prefix caching needs canonical prefill chunking, auto
  resolves to the current default of 8 scheduler blocks.
- Explicit positive values continue to select a fixed chunk size in scheduler
  blocks.
- Prefix-cache hit canonicalization and scheduler prefill chunking now use the
  same chunk-block policy.

This keeps the high-cache-hit prefix-caching path useful under
`VLLM_BATCH_INVARIANT=1` while preserving the stable scheduling shape required
for batch-invariant behavior.

AI assistance was used in developing and validating this PR.

## Test Plan

Scheduler coverage:

```bash
.venv/bin/python -m pytest tests/v1/core/test_scheduler.py -v
```

Batch-invariance determinism coverage:

```bash
VLLM_BATCH_INVARIANT=1 .venv/bin/python -m pytest \
  tests/v1/determinism/test_batch_invariance.py -v -x --timeout=1200
```

Manual prefix-cache performance validation used a shared-prefix workload with a
high prefix-cache hit ratio. The benchmark was run on two attention backends as
validation coverage; the implementation change is in scheduler/KV-cache policy,
not backend-specific attention code.

```bash
python benchmarks/benchmark_batch_invariant_prefix_cache.py \
  --model Qwen/Qwen3-1.7B \
  --num-prompts 64 \
  --prefix-len 2048 \
  --suffix-len 256 \
  --output-len 16 \
  --num-trials 5 \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.5 \
  --backend FLASH_ATTN \
  --chunk-blocks 4,8,16
```

The same benchmark was also run with `--backend FLEX_ATTENTION`.
