# [Bugfix] Keep LRU cache views live and read-only

[Upstream PR](https://github.com/vllm-project/vllm/pull/60807) · state: open · merged: False

## Original PR description



## Overview

Saved `LRUCache.cache` views can return old values and raise `KeyError` after cache updates. Use a read-only mapping backed by the same live values and ordered keys.

## Claims

- A saved view reflects replacement and eviction without recording cache hits.
- Item assignment through the view raises `TypeError`, matching its read-only contract.

## Validation

The added repository tests failed on the baseline (3 failed, 2 passed) and pass with the repair (5 passed). A CPU harness loaded the complete actual `vllm/utils/cache.py` with installed cachetools and ran `tests/utils_/test_cache.py`; it bypassed package initialization only. Ordinary pytest with actual package initialization also passes all five tests using the existing CPU PyTorch environment; fixtures are scoped to `tests/utils_`. Normal repository hooks pass on this exact patch. The submitting human reviewed every changed line and ran the five utility tests. The current Buildkite misc workflow includes `tests/utils_`; no hosted test execution, model, or GPU serving run is claimed.

For a normal vLLM development environment:

```bash
pytest tests/utils_/test_cache.py -q
```

## Details

`UserDict` copied the values at view creation, while iteration used the live LRU key order. Replace it with the existing `Mapping` abstraction and direct lookups/length from the backing data; retain the ordering behavior. No cache lookup or eviction algorithm changes.

Current default-branch source and test blobs still match this patch's base. Searches for `_MappingOrderCacheView`, `LRUCache`, and cache-view fixes found no matching open PR. Related PRs #34749 and #40578 fix missing-key `touch()` behavior; #60607 bounds vision RoPE cache storage. Their actual diffs do not implement this view fix.

The complete baseline scan covered all 5,015 Python files; every added or modified Python file at the current tip was also checked. The sole production reader of this property, `LoRAModelManager.list_adapters`, immediately creates a separate `dict`; that snapshot behavior is retained. Multimodal and vision caches use the unchanged lookup/insertion paths. No model or serving result is claimed.
