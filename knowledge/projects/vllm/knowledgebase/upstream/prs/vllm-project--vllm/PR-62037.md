# [Attention] Add an FA4 backend with a fixed split-KV schedule

[Upstream PR](https://github.com/vllm-project/vllm/pull/62037) · state: open · merged: False

## Original PR description



## Overview

Adds `FlashAttnFixedSplitBackend`: FA4 (CuTe) attention with a fixed split-KV schedule, so a token's attention output is bitwise independent of the batch. This is for batch-invariant inference that a training-side replay can reproduce with the same kernel and schedule.

This is one self-contained part of #62017 by @aoshen02, split out unchanged for separate review. The commit keeps his authorship. An earlier revision was reviewed as aoshen02/vllm#93.

## Claims

- Bitwise-identical rows: a sequence's attention rows are the same whether it runs alone or batched with other sequences, and in prefill or decode. Decode includes a verify row of 2 or 3 query tokens.
- Unsupported layers are rejected when the impl is constructed, with a reason, instead of exceeding the schedule at runtime.
- No existing path changes. The backend is not registered as a selectable backend; a model opts in with `Attention(..., attn_backend=FlashAttnFixedSplitBackend)`. The Nemotron-H batch-invariant wiring in #62017 does this.

## Details

Schedule:
- `SEQLEN_K_PER_SPLIT=8192` keys per split, `NUM_SPLITS=32`;
- `max_seqlen_q` and `max_seqlen_k` fixed at 262144;
- scheduler metadata disabled;
- `tile_mn=(128, 128)`, `pack_gqa=True`.

Each split therefore covers the same keys for any batch composition, sequence length or phase.

Scope; anything outside it raises `ValueError` at construction:
- an SM10x GPU;
- a vllm-flash-attn build whose `_flash_attn_fwd` has `seqlen_k_per_split` and `disable_scheduler_metadata`;
- head size 128;
- FP8 E4M3 or BF16 KV cache;
- no sliding window;
- `max_model_len <= 262144`;
- plain causal decoder attention: no ALiBi, soft cap, sinks, KV sharing or DCP.

At runtime, `forward` also rejects fused output quantization and non-causal metadata.

`FlashAttentionImpl.__init__` is deliberately not called. It picks a vllm-flash-attn version and rejects FP8 KV caches, while this impl calls the CuTe FA4 kernel directly, so only the attributes other code reads are set.

Compared with aoshen02/vllm#93:
- the schedule now covers `max_model_len` up to 262144;
- a BF16 KV cache is accepted;
- the cascade-attention check is gone, because #61126 removed cascade attention.

It is meant for batch-invariant serving only and is not registered for general backend selection.
