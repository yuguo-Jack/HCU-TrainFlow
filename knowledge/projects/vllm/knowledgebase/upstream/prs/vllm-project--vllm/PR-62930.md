# [KV Offload] Reject secondary tiers on engines that span nodes

[Upstream PR](https://github.com/vllm-project/vllm/pull/62930) · state: closed · merged: True

## Original PR description

## Overview

This PR makes `TieringOffloadingSpec` fail at startup, instead of serving wrong KV, when secondary tiers run on an engine whose workers span several nodes (#54415).

It applies to `main` on its own and depends on no other PR. #62933 builds on it to support the multiprocessing executor with `--nnodes` > 1.

## Claims

- With secondary tiers and more than one worker, every worker checks at creation whether the engine's workers share a node, and raises `NotImplementedError` if they do not. This covers every way to place workers on several nodes (mp with `--nnodes`, Ray, `external_launcher`) without looking at the executor.
- Single-node engines, single-worker engines and engines without secondary tiers are unchanged.

## Validation

**Multi-node startup** on 2× DGX Spark (GB10), `vllm/vllm-openai:nightly-00b6c4c565` with this branch's changed Python files on top, TP=2, mp executor with `--nnodes 2`, `facebook/opt-125m`:

- `TieringOffloadingSpec` with an `fs` tier: both workers fail at startup with `NotImplementedError: TieringOffloadingSpec secondary tiers are not supported on engines whose workers span several nodes.`
- `TieringOffloadingSpec` without secondary tiers: starts and serves; the same prompt sent twice gives the same output.

**Unit test:** `tests/v1/kv_offload/test_factory.py::test_tiering_spec_rejects_secondary_tiers_across_nodes` fakes the TP, PP and PCP groups and `in_the_same_node_as()`: it rejects a TP, PP or PCP group that spans nodes, accepts groups that each share a node, queries all three groups even after one spans nodes, and queries none without secondary tiers. Without the fix, four of its five cases fail. CI provides one host only, so it cannot run a real multi-node rejection.

**Suites** (CPU-only container):

```bash
pytest tests/v1/kv_offload/tiering tests/v1/kv_offload/test_factory.py \
  tests/v1/kv_offload/test_file_mapper.py \
  tests/v1/kv_connector/unit/offloading_connector
# 1286 passed, 1 failed (on 71294c2e9a)
```

The one failure, `test_worker.py::test_register_packed_kv_caches_skips_scratch_group`, needs a GPU and fails the same way on `main`; it passes on GPU.

`ruff check` and `ruff format --check` pass on the changed files.

## Details

**Root cause.** The tiering scheduler and its secondary tiers run in the engine core and address only its node's `/dev/shm` region. Since #58497 every worker writes the slot of its rank, but workers on other nodes write it into their own node's region. Secondary tiers therefore persist rows without those slots, and promotions never fill them.

**Detection.** An engine's workers form a grid of its TP, PP and PCP groups (DCP lives inside TP), so they all share one node exactly when each of those groups does. `create_worker()` therefore calls `in_the_same_node_as()` on each group with more than one rank. It is a collective over that group, which every worker of the group reaches during KV cache registration. Every rank runs all three before any of them raises, so a rank whose own TP group spans nodes cannot leave the ranks of a node-local TP group waiting in the PP or PCP collective. It runs only with secondary tiers, since without them each node's region serves its own workers.

**Not a duplicate.** Searched open PRs for "54415 in:body", "multi-node offload", "secondary tiers nodes", "local_world_size offload" and "shared region node". #53474 also sizes node-local regions and rejects multi-node secondary tiers from the config; #46556 moves rank-local shards to a shared filesystem through worker transfers instead; #62058 and #53073 deal with `/dev/shm` capacity and region lifecycle, not with nodes.

**Docs:** `docs/features/kv_offloading_usage.md` states the restriction.
