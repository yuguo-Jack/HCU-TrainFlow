# [Bugfix][LoRA] Reject inconsistent checkpoint factor ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/61605) · state: open · merged: False

## Original PR description



## Overview

Reject ordinary 2D PEFT checkpoint factors whose physical rank disagrees with
the effective per-module configuration, or whose A/B pair is incomplete, before
the adapter reaches registration. Follow-up to #59801; this validates checkpoint
consistency rather than adding rank/alpha-pattern support.

## Claims

- Reject mismatched A/B rank axes and a mismatch against the module's effective
  PEFT rank, with the module name, expected rank and actual shapes in the error.
- Preserve dynamic rank patterns, checkpoint-name mapping and the existing
  flattened/stacked MoE paths. Indexed expert 2D factors remain validated.
- Change adapter loading only; no new inference operations or dependencies.

## Details

`from_lora_tensors` currently resolves per-module rank and scaling from PEFT but
assigns tensor factors without checking their physical rank. Rank-buffer padding
can conceal a mismatch: a configuration declaring rank 8 can load two rank-4
factors and retain the configured scaling. This change rejects that inconsistent
checkpoint instead of guessing a new scale.

Validation compares `LoRALayerWeights.rank`, not the global `LoRAModel.rank`,
so legitimate per-module and `save_as_lora` dynamic-rank configurations survive.
Flattened PEFT MoE records named `experts` or `experts.base_layer` are identified
before name mapping and retain their rank-times-experts layout. Non-2D layouts
retain their existing handling; this is not a general MoE shape validator.

Duplicate check: #59801 implements per-module scaling, #59924 checks incompatible
MoE adapter formats, and open #57225 adds receiver-local staging without adapter
files. Those differ from checking physical A/B factors in the checkpoint loader.
The related issue and comments were read and the open-PR searches were checked.
