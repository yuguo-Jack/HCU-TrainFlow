# [Recipe] Align Kimi-K3 Ascend variants and Mooncake V2 PD

[Upstream PR](https://github.com/vllm-project/vllm/pull/62668) · state: open · merged: False

## Original PR description

Split Kimi-K3 quantization by Ascend hardware and generate the documented A5 PD deployment instead of the generic NIXL layout.

- A3 selects only W4A8 (Ascend), using ModelScope `Eco-Tech/Kimi-K3-w4a8`. A5 selects only MXFP4(ASCEND), using the contributor-confirmed private ModelScope checkpoint `Eco-Tech/Kimi-K3-w4a8-mxfp-quarot`. FP8 remains restricted to NVIDIA/AMD.
- A5 PD requires `MooncakeConnectorV2`: each P instance is **DP1/TP8/PP4/EP8**, each D instance is **DP4/TP8/EP32**. Each instance occupies four nodes with eight NPUs per node. Default 1P1D uses eight nodes / 64 NPUs; each pool grows in complete independent 32-NPU groups.
- Mixed serving explicitly declares `worker_args: ["--headless"]` in both A3/A5 strategy hardware overrides: node 0 retains the API, and workers 1–3 join headlessly with their respective DP ranks. The guide records these roles.
- Add the official role arguments/environment and DSpark P eager=true / D eager=false settings. The companion renderer supplies the Ascend proxy, group ranks/masters and guarded UI/API choices.
- The inherited 1711 GB loading estimate remains explicitly unverified for the private A5 checkpoint.

- A5 PD exposes **Scripts → Prefill → Decode → Start_Server → Start_Proxy**. Scripts downloads only `launch_online_dp.py`. Prefill/Decode save `run_dp_template.sh`, with manual `<NIC_NAME>` / `<LOCAL_IP>` edits on each node. Start_Server supplies separate Prefill and Decode launcher commands with rank/master/port arguments and individual copy buttons; no role-selection wrapper is needed. The independent installed proxy starts in step five. The templates follow [official section 5.2](https://github.com/vllm-project/vllm-ascend/blob/main/docs/source/tutorials/models/Kimi-K3.md#52-basic-eight-node-pd-separation-deployment), retaining the required K3 model selection and PP4/DP4 topology.

Reference: [official basic eight-node PD deployment](https://docs.vllm.ai/projects/vllm-ascend-cn/zh-cn/latest/tutorials/models/Kimi-K3.html#52-basic-eight-node-pd-separation-deployment).

Companions: https://github.com/vllm-project/recipes/pull/1152 and https://github.com/vllm-project/vllm-ascend/pull/19703. Merge the renderer support first; the validation workflow temporarily pins its PR ref. The current source-PR preview renderer on main cannot render the new fields until then. This extends existing PRs and avoids duplicate work; the renderer branch includes pending overlay infrastructure from recipes#1160.

- Kimi-K3 Ascend 910C (A3) and 950DT (A5) support **KV Offload = Off only**, for mixed and PD serving. A hardware-scoped recipe policy disables all other options and normalizes stale URL/saved selections to Off; command synthesis independently ignores offload requests on those profiles.

The KV-offload restriction and nested-connector follow-up were not tested, at the user's request.

- Ascend `--headless` is confined to mixed TP+DP worker nodes. PD Prefill and Decode omit it on every rank, in generated templates and direct commands; the PD UI and guide use the same distinction. This correction follows the contributor's deployment requirement.

This headless correction has not been tested, at the user's request. Existing test expectations were updated without execution.

Earlier validation (completed before this follow-up):
- Strict merged assembly and JSON API build passed: 217 models, 279 promoted variants.
- Connector/overlay/preset regressions: 63/63, including source-driven mixed worker arguments, head/PD isolation and overlay scope.
- Schema, exclusive variants, hardware-switch fallback and core/overlay cutover checks passed.
- Compared 480 existing NVIDIA/AMD configurations against the previous renderer/source: generated commands, arguments and environment are unchanged.
- Local UI confirms manual template network values, independently copyable Prefill/Decode Start_Server commands, all five tabs, fixed topology, Mooncake V2 / Ascend Router / Python, and complete four-node groups.
- The official `launch_online_dp.py` was executed with generated role templates and mock vLLM for P/D group heads and replicated-group followers: **4/4**. Manual NIC/IP values, JSON KV/draft bindings, rank/master parameters and headless roles passed. No NPU process was started.
- `git diff --check` passed. Pre-commit is unavailable here. No NPU inference, accuracy or performance evaluation was run; the private MXFP4 checkpoint and replicated groups remain hardware-unverified.
