# [CI] Add tooling to report how job groups divide up the test tree

[Upstream PR](https://github.com/vllm-project/vllm/pull/58898) · state: closed · merged: False

## Original PR description

`check_test_tethering.py` answers "does any job run this test?" and stops there. This adds the neighbouring reports, reusing that checker's parser so the two tools cannot disagree about what a command collects.

```
--runs        files collected by more than one job group
--subsets     job pairs where one file set contains another
--dead        --ignore / --deselect arguments that match nothing
--untethered  files no job collects, annotated with allowlist status
```

No vLLM install needed, it only reads pipeline yamls and the tests tree.

```
python .buildkite/scripts/collect_report.py --runs
python .buildkite/scripts/collect_report.py --dead --untethered
```

## Result on the current tree

```
730 job groups, 1640 test modules
0 inert --ignore arguments (after #58895)
54 files collected by no job, all 54 allowlisted
```

The 54 is a cross-check: `check_test_tethering.py --all` reports the same set, so the two tools agree.

## What `--runs` should and should not be read as

1505 of 1640 files are collected by more than one group. That is not a finding on its own — vendor mirrors, per-architecture jobs, and GPU/CPU pairs split by `-m cpu_test` all do this deliberately. The tool's docstring says so, because the raw count invites the wrong conclusion.

Collection is per file, and markers are applied at collection time, so two jobs running `-m core_model` and `-m 'core_model and slow_test'` over the same directory look identical here. Separating those needs test ids from `pytest --collect-only`, which in turn needs an environment where `tests/conftest.py` can import. I built and ran that measurement separately and it is not part of this PR.

No open PR adds these reports. The tethering checker is deliberately file-granular and this builds on its parser rather than replacing it.
