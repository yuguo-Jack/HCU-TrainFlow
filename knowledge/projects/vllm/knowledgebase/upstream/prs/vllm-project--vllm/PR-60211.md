# [LoRA] Support saved multi-layer classification heads

[Upstream PR](https://github.com/vllm-project/vllm/pull/60211) · state: open · merged: False

## Original PR description



## Overview

Fixes #60197. PEFT `SEQ_CLS` adapters for RoBERTa and XLM-RoBERTa save a two-layer classification head, which vLLM failed to load. A model can now declare the linears of its head, and each one gets per-adapter weights.

## Claims

- `RobertaForSequenceClassification` and `XLMRobertaForSequenceClassification` load PEFT adapters that save `classifier.dense` and `classifier.out_proj`, for both `classify` and `score`.
- Outputs match transformers + PEFT, including batches that mix base and adapter requests or adapters with different label counts.
- LoRA A/B weights on `classifier.dense` are now applied. On main such an adapter is refused at load since #63489.
- No change for other single-linear heads, or for RoBERTa models used without LoRA.

## Validation

On main, every adapter below with a saved head fails with `ValueError: classifier.dense.bias is unsupported LoRA weight`. With this PR, max abs diff against transformers + PEFT (fp32), vLLM in fp16 on an RTX 4070 Ti SUPER:

| Adapter | Max abs diff |
|---|---|
| Synthetic `roberta-base` adapter with saved head | 1.6e-3 |
| Same, batch of base / adapter / base requests | 6.4e-4 |
| `Akashpaul123/roberta-depression-severity-lora` (4 labels, base has 3) | 4.5e-3 |
| Same, batch mixing 3-label and 4-label rows | 3.1e-3 |
| `minhnv7/bge-reranker-v2m3-lora`, `classify` | 1.9e-3 |
| Same, `score` | 4.2e-5 |
| LoRA A/B on `classifier.dense`, no saved head | 8.6e-4 (main: refused at load) |
| Backbone-only adapter | 1.9e-4 (same as main) |

The adapters change the outputs by up to 1.16 in logits, and the bge adapter moves the score of a pair from 0.9998 to 0.119. Without LoRA, scores of `cross-encoder/quora-roberta-base`, `BAAI/bge-reranker-base`, `BAAI/bge-reranker-v2-m3` and `jinaai/jina-reranker-v2-base-multilingual` are identical before and after.

Repro:

```python
from huggingface_hub import snapshot_download
from vllm import LLM
from vllm.lora.request import LoRARequest

llm = LLM(model="BAAI/bge-reranker-v2-m3", runner="pooling", enable_lora=True,
          max_lora_rank=16, dtype="float16", enforce_eager=True,
          gpu_memory_utilization=0.3)
adapter = snapshot_download("minhnv7/bge-reranker-v2m3-lora")
llm.classify(["Paris is the capital of France."],
             lora_request=LoRARequest("a", 1, adapter))
```

`pytest tests/lora/test_sequence_classification.py tests/lora/test_lora_manager.py tests/lora/test_utils.py tests/lora/test_peft_helper.py tests/lora/test_lora_checkpoints.py` passes, 101 tests with the TP test skipped since it needs 2 GPUs. The new `test_multi_layer_head_with_modules_to_save` fails on main with the error above.

## Details

Root cause: a saved head was only accepted when its tensors sit directly under `classifier` or `score`, and the LoRA manager only wrapped a head that is a single `ReplicatedLinear`. RoBERTa's head is `classifier.dense -> tanh -> classifier.out_proj`, built from `nn.Linear`.

Changes:

- Saved head tensors one level below `classifier` or `score` are parsed as full modules.
- A model with a multi-layer head opts in through a new `SupportsLoRA.lora_classifier_modules` class attribute that lists the head linears in order. The last one produces the labels. `RobertaForSequenceClassification` declares `("classifier.dense", "classifier.out_proj")`, and its head now uses `ReplicatedLinear`. Models that don't declare it keep the single `score` or `classifier` head.
- The LoRA manager wraps each declared linear with `ClassificationHeadWithLoRA`, reusing the existing per-request full-weight path. Only the last one may change the number of labels (`max_lora_cls_labels`). The others must keep their shape, and saved weights outside the declared linears are rejected at load.

Tradeoffs and limits:

- The intermediate linear (`classifier.dense`) reuses `ClassificationHeadWithLoRA` with a fixed output size.
- Each head linear keeps a full weight per LoRA slot, `hidden x hidden` for `dense`.
- Not tested with tensor parallelism.
- The new test uses a third-party adapter from the Hub, like the other tests in that file.
