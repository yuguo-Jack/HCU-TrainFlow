# [CI] Move Multimodal Processor, KV Connectors, LoRA, Spec Decode Draft and three more steps from fixed to automatic shards

[Upstream PR](https://github.com/vllm-project/vllm/pull/62084) · state: open · merged: False

## Original PR description



## Overview

Moves seven steps, and their AMD mirrors, from fixed pytest shards to `automatic_shard`, as #61200, #61477 and #62077 did for others. For each: `parallelism` is dropped, `--shard-id`/`--num-shards` come off the commands, `Shard %N` / `%N` comes out of the label (the generator adds `shard N/M`), and `automatic_shard: true` is set on the step and on `mirror.amd`. No tests change.

## Claims

| Step | Was | Planned shards | AMD mirror: was | AMD planned |
|---|---:|---:|---:|---:|
| `multi-modal-processor` | 4 fixed | 4 | 4 fixed | 4 |
| `v1-kv-connectors` | 4 fixed | 3 | 4 fixed (inherited) | 2 |
| `lora` | 4 fixed | 3 | 4 fixed (inherited) | 2 |
| `spec-decode-draft-model` | 4 fixed | 3 | 2 fixed | 2 |
| `multi-modal-models-extended-generation-2` (optional) | 4 fixed | 3 | 4 fixed (inherited) | 2 |
| `basic-correctness` | 2 fixed | 2 | 2 fixed (inherited) | 1 (one job) |
| `language-models-tests-extra-standard` | 2 fixed | 2 | 2 fixed (inherited) | 1 (one job) |

- Fixed pytest shards split by test count, so shard lengths vary widely and every shard pays the job startup again. The plan balances shards by measured time and drops shards that aren't needed, with each shard under the 20-minute target.
- Every test runs exactly once across the shards, with the same environment as before.

## Validation

- Planned each step and mirror with ci-infra main's `runtime_shard.plan_step` against this branch and main's timings on the step's own queue.
- Rendered each step and mirror with the pipeline generator and ran every shard's commands against a mock test tree, as a PR build and with main's `pytest -p ci_otel` wrapper. Every test ran in exactly one shard, with the same env. The two mirrors that plan to one shard were confirmed to stay one job.
- Not covered by the mock: `multi-modal-models-extended-generation-2` selects tests with vLLM's dynamic `split(group=0)` marker, which the mock tree doesn't define. It is optional, so a build scoped to it and its mirror checks it on real hardware.
- `/ci run` exercises the other six steps and their mirrors.

## Details

- **Left out, still on fixed shards.**
  - `language-models-tests-hybrid`: each job first builds mamba-ssm and causal-conv1d from source, which every extra shard would repeat. It waits for #58795.
  - `basic-models-tests-extra-initialization`: the plan comes out over budget, with shards over 30 minutes.
  - `multi-modal-processor-cpu`: main has no per-file timings for it.
  - `spec-decode-mtp-other-acceptance-nightly`: the planner estimates a few minutes against about half an hour on main, so its plan can't be trusted yet.
  - `entrypoints-integration-api-server`: its RPC command sets `PYTHONPATH=/vllm-workspace`, which replaces the path the generator adds for the shard plugin, so that command would fail to load the plugin. Appending `$$PYTHONPATH` makes the planner reject the command. This needs a ci-infra change so the plugin stays importable.
  - `lora-tp-distributed`: fails on main, so a PR build can't validate its shards.
  - `distributed-model-tests-2-gpus`, `kernels-b200`, and the MoE Refactor and Humming evals: they pick tests per shard by hand (a `case` script, or a config file per shard), which needs rewriting as plain pytest first.
- **`caplog`.** `v1-kv-connectors` has files that assert on log text. None of them starts an engine, so test order within a shard doesn't affect them.
- **Timeouts unchanged (human).** `timeout_in_minutes` stays per job, as in #61200 and #61477. A single-job fallback (no plan, or the `VLLM_CI_RUNTIME_SHARD` rollback switch) can outrun it. Making the timeout follow the shard count belongs in a central timeout setting.
- **Where to look.** The seven steps in `.buildkite/test_areas/{models_multimodal,misc,lora,spec_decode,basic_correctness,models_language}.yaml`.
