# [Bugfix][Multimodal] Enforce decode-byte budget for numpy image_embeds

[Upstream PR](https://github.com/vllm-project/vllm/pull/62325) · state: open · merged: False

## Original PR description

## Overview

The numpy branch of `image_embeds` deserialization
(`ImageMediaIO._load_numpy`) called `np.load` directly on
attacker-controlled bytes. `np.load` trusts the array header and
materializes the full declared shape before reading any data, so a tiny
payload could allocate gigabytes before failing on truncated data. This
PR validates the declared size against the existing
`VLLM_MAX_EMBED_DECODE_BYTES` budget before allocating, mirroring the
guard already applied to the torch/sparse branch by `safe_to_dense`.

## Claims

- A payload declaring a shape larger than `VLLM_MAX_EMBED_DECODE_BYTES`
  is rejected with `VLLMValidationError` (HTTP 400) **before any array
  allocation happens**.
- Legitimate numpy arrays within the budget deserialize unchanged.
- Unsupported format versions (not 1.0/2.0) get a clean 400 instead of
  an opaque numpy error.

## Validation

Logic-level reproduction against the real numpy 2.x format module:

- ~100-byte payload declaring shape `(2147483648,)` float32 (4 GiB):
  **rejected by the guard; tracemalloc peak 18 KB** (previously: the
  full 4 GiB was allocated before an `EOF: reading array data` error).
- 144-byte payload declaring exactly 1.0 GiB (the original finding):
  allocation bounded by the budget (at the default 2 GiB limit such
  declarations still pass, consistent with `safe_to_dense` semantics;
  operators can lower the env var).
- Legitimate arrays (3x4 float32, 1024x1024 float32) deserialize
  identically before/after the change.

## Details

The sparse-torch branch already documents this exact amplification
class in `safe_to_dense`: torch.sparse COO tensors carry their own
declared shape, so `to_dense()` allocates by declaration rather than by
request size — hence `safe_to_dense` checks `numel * itemsize` against
`VLLM_MAX_EMBED_DECODE_BYTES` before densifying. `np.load` has the same
trust-the-header property for ndarray payloads
(`np.lib.format.read_array` allocates `prod(shape) * itemsize` up
front), but the numpy branch of `image_embeds` bypassed the budget.

Fix shape: read the magic + array header with the public
`np.lib.format.read_magic` / `read_array_header_1_0` / `read_array_header_2_0`
APIs on a peek pass, reject over-budget declarations with the same
`VLLMValidationError` shape `safe_to_dense` uses (same `parameter` /
`value` fields, same env-var hint), then load from a fresh buffer.

Requires `--enable-mm-embeds` to be reachable in deployment.
