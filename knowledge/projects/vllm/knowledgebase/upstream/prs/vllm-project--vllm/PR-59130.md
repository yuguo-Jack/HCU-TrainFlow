# [Metrics] Redesign engine sleep-state telemetry for partial sleep/wake

[Upstream PR](https://github.com/vllm-project/vllm/pull/59130) · state: open · merged: False

## Original PR description

## Scope

Separate follow-up to #52864. This PR redesigns engine sleep-state telemetry; API response schemas, operation duration/in-flight metrics, and generic HTTP observability remain in #52864.

Sleep state is recorded as independent resource dimensions, rather than adding more mutually exclusive level strings:

- `vllm:engine_sleep_resource_state{model_name,engine,resource,state}`:
  - scheduler: running / paused
  - weights: resident / offloaded / discarded / unknown
  - kv_cache: resident / released / unknown
- `vllm:engine_fully_awake{model_name,engine}`: scheduling running and both resources confirmed resident.

This covers scheduler-only level-0 pause, level-1/2 memory sleep, partial wake, and KV-only release. Residency does not certify that discarded tensor contents were restored by an external weight reload.

## Implementation

- Executor records confirmed resource disposition after completed memory operations; failed collective memory RPCs mark affected resources unknown.
- Engine publishes per-engine snapshots to every frontend, including while idle, via optional appended SchedulerStats fields.
- Python and Rust expose matching new resource and fully-awake gauges. Gauge children are created only after a snapshot; older engine output remains accepted.
- State-only updates bypass request/cache/throughput recording and Rust routing-load updates.
- Python legacy engine_sleep_state series remain for migration, but partial wake immediately clears stale weights_offloaded. All legacy flags may be zero for states the old model cannot represent.
- Sync LLM operations refresh snapshots after success/error. Failed snapshot fetches do not overwrite the original operation exception.
- Wake bool propagation is retained for compatibility with #52864. Both PRs touch these methods and should be reconciled when merging.

Design and migration semantics: docs/design/engine_sleep_state.md.
