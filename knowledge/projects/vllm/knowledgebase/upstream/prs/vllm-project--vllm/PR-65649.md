# [Benchmark] Add compact FlashInfer top-k/top-p filtering

[Upstream PR](https://github.com/vllm-project/vllm/pull/65649) · state: open · merged: False

## Original PR description



## Overview

Add a compact `flashinfer-mask` implementation to the existing top-k/top-p filtering benchmark, plus configurable k/p values and input distributions. Uniform k<=128 selects candidates with `flashinfer.top_k()`, applies top-p over those candidates, and reconstructs masked logits.

## Claims

- Adds an experimental comparison for the masked-logit output contract used by speculative verification.
- Resolves uniform k outside the timed region and retains dense FlashInfer for other scenarios.
- Exposes both improvements and regressions across vocabulary sizes, batch sizes, sampling parameters, and input distributions. Inference code is unchanged.

## Validation

Tested the actual benchmark entry point on B300 and H100 with PyTorch 2.14.0, Triton 3.8 and FlashInfer 0.7.2.post1. The Triton source and PyTorch reference function match upstream main at `5225a1f17f` (main on 2026-11-04).

Factorized coverage: batch sizes 1/4/9/32/128/280/512, vocabularies 4,096/32,768/131,072/151,936/248,320/262,144 plus odd sizes 257/4,097/32,769, k=1/2/20/32/64/100/128/129/256, p=0.01/0.1/0.5/0.8/0.95/1, top-k-only/top-p-only/mixed scenarios, Zipf/Gaussian/BF16-rounded inputs, and sparse inputs with 13/128 finite logits. The k/p cross uses V=32,768/248,320 and batches 1/4/128/512, with reversed implementation order on its second pass.

Timings include fresh-input cloning and launch gaps, use cold L2 and no CUDA graphs. These are whole-call timings. The H100 V=248,320/batch=4 speedup varies from 1.09x to 1.31x across the two passes. Smaller vocabularies can regress substantially.

- Both architectures completed 2,936 scenario/shape/repeat records each, totaling 17,616 implementation timings (5 warmups, 30 samples per timing). Interrupted runs were resumed, with incomplete and superseded records excluded.
- All 3,104 Zipf compact checks match PyTorch. There are 365 differing compact checks: 361 BF16-rounded and 4 Gaussian, with maximum TV 1. All replayed Gaussian disagreements have a tied kth cutoff. An independent FP64 prefix-mass, ranking and retained-logit oracle passes all 288 cases across both architectures, including tied inputs. Exact-k selection differs from the reference's tie-preserving cutoff.
- The existing dense FlashInfer fallback has 222 reference differences, maximum TV 0.2775, including p=1 rows that lose probability mass. A direct public-API reproducer retained only 0.9956 mass for p=1 at V=151,936. These failures are retained in the results. `--check` reports differences without failing the existing benchmark process.
- Full pre-commit checks pass. Manual GPU benchmark coverage is used here, with no new CI test suite. Model evaluations are unchanged because this is a benchmark-only change.

Example reproduction from the repository root, repeated with the implementation order reversed for the second pass:

```bash
.venv/bin/python benchmarks/benchmark_topk_topp.py \
  --batch-sizes 1 4 9 32 128 280 512 \
  --vocab-sizes 4096 32768 131072 151936 248320 262144 \
  --top-k 20 --top-p 0.8 --warmup-iters 5 --benchmark-iters 30 \
  --implementations triton flashinfer-mask pytorch --check \
  --output results/topk-topp-r0.jsonl
```

For the parameter cross, run `--scenarios topk_topp_whole` with each k/p pair above at vocabularies 32,768/248,320 and batches 1/4/128/512. Run `topk_whole` once per k as well. `--distribution normal`, `--distribution bf16-rounded` and `--num-finite-logits 13`/`128` select the additional fixtures.

## Details

Sorted top-k uses `deterministic=True, tie_break=1`. Compact top-p uses PyTorch softmax/cumsum and returns original logits with other entries set to `-inf`. Odd vocabularies request FlashInfer's graph-safe selection path to avoid an observed misaligned-address failure. The compact path keeps exactly k candidates before top-p, so tied cutoffs can differ from the PyTorch reference's tie-preserving cutoff. This comparison does not establish a universal replacement policy.

No overlapping open PR was found in benchmark filename and sampling-area searches. Existing compact-sampler and shared-k work changes production sampling, while this change adds a masked-logit benchmark comparison. AI assistance was used for implementation, investigation and validation. This draft is prepared for human review.
