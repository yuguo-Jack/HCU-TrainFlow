# [Perf][Model] Muse vision encoders: no GPU<->CPU syncs, build Glimmer's vision prep once per call

[Upstream PR](https://github.com/vllm-project/vllm/pull/64822) · state: open · merged: False

## Original PR description

## Overview

The Muse Glimmer and Muse Spark (NaViT) vision encoders read window layouts back from the GPU, once per image or frame group. Under `VLLM_GPU_SYNC_CHECK=error`, which the CI test image sets (#43107), every Glimmer image or video request raises. The check is off by default, so users don't see the error, but the syncs still run on every request.

This PR builds those layouts on the host. For Glimmer, it also runs the vision prep once per call instead of once per group.

## Claims

- No GPU<->CPU syncs in either encoder: Glimmer 879 → 0 and NaViT 817 → 0 over 126 encoder calls.
- Glimmer encodes 32-frame video 1.15–1.22× faster, depending on the benchmark (see below).
- No change for images or serving. VisionArena p99 TTFT is 509 ms vs 507 / 506 ms on main, over 1,000 requests.
- Outputs are bit-identical to main on all 126 calls, with real Glimmer vision weights and random pixel values, on H100 (FlashAttention 3) and L4 (FlashAttention 2).
- Peak GPU memory is never above main (worst ratio 0.998), so the encoder profiling budget does not grow.

## Details

**Root cause.** `_get_sparse_permutation` built the 32×32 window layout on the GPU, then did a boolean-mask select and a `.tolist()`: two syncs per image or frame group. NaViT's `_get_sparse_attention_perm` has the same mask select, plus a `.tolist()` per call and a blocking `torch.tensor(list, device=cuda)` in `_seqlens_to_cu_seqlens`. All of this depends only on the patch grid, which is already on the CPU.

**Change.** Layouts are computed in numpy with the same operations and copied with `async_tensor_h2d`. In Glimmer, layouts are built once per distinct grid. `ln_pre`, RoPE, the window permutation, `ln_post` and the pixel shuffle then run once over the whole call.

**Tradeoffs.**
- The patch projection stays one matmul per group. A single matmul over the call changed output bits on 48 of 126 calls on L4 but none on H100, so a bit-exact test on CI hardware might not catch it. `test_glimmer_vision_encoder_projects_patches_per_group` pins the call count instead.
- The position embedding is still interpolated per distinct grid on the GPU, which keeps its temporary no larger than on main.

**Limits.**
- No config, flag or API change.
- The Muse Spark checkpoint is gated, so NaViT is validated with a standalone 12-layer encoder (bit-identical, no syncs), not the full model.
- CI covers the tests above. Real-weight bit-identity and the benchmarks were run outside CI.

**Related PRs.** #59470 and #61448 also touch `muse_glimmer.py`, but only the language model and RMSNorm. I found no open PR addressing these syncs.
