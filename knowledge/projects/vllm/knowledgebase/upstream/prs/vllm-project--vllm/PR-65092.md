# [Bugfix][ROCm] Reserve kpool decode indexer logits in workspace during profiling

[Upstream PR](https://github.com/vllm-project/vllm/pull/65092) · state: open · merged: False

## Original PR description

## Overview

Fixes #64874.

Serving `GLM-5.3-Flash` on ROCm crashes in decode once `batch_size * next_n * max_pool_len * 4` outgrows both the prefill K-gather workspace and the largest captured CUDA graph batch (`AssertionError: Workspace is locked but allocation from 'rocm_aiter_mla_sparse.py:...:rocm_fp8_paged_mqa_logits' requires 276.00 MB, current size is 265.00 MB`).

## Claims

- reserve the worst-case decode logits buffer on `current_workspace_manager()` during `sparse_attn_indexer_kpool`'s profiling pass, matching `rocm_aiter_sparse_attn_indexer`, and keep the `torch.empty` reservation for the `VLLM_SPARSE_INDEXER_MAX_LOGITS_MB` prefill logits cap.

## Validation

```bash
VLLM_ROCM_USE_AITER=1 pytest -v -s tests/models/glm5next/test_sparse_indexer_topk_dispatch.py -k decode_logits_workspace

# serve + benchmark (96 concurrent decode requests -> 576 decode rows -> 288.00 MB)
# with or without --limit-mm-per-prompt '{"image": 0, "video": 0}' is the same, the bug doesn't depends on mm inputs
VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_FP8BMM=0 VLLM_ROCM_USE_AITER_FP4BMM=0 \
vllm serve zai-org/GLM-5.3-Flash --tensor-parallel-size 8 \
  --attention-backend ROCM_AITER_MLA_SPARSE --kv-cache-dtype auto \
  --speculative-config.method mtp --speculative-config.num_speculative_tokens 5 \
  --max-model-len 524288 --max-num-seqs 128 \
  --limit-mm-per-prompt '{"image": 0, "video": 0}' --gpu-memory-utilization 0.90 \
  --port 8025

vllm bench serve --model zai-org/GLM-5.3-Flash \
  --base-url http://127.0.0.1:8025 \
  --dataset-name random --random-input-len 2200 --random-output-len 128 \
  --random-prefix-len 2150 \
  --num-prompts 96 --max-concurrency 96 --ignore-eos
```

| workload | main | this PR |
|---|---|---|
| unit test (`16 seqs x 6 = 96` decode rows, `max_pool_len=4096`) | `AssertionError: Workspace is locked ... requires 1.50 MB, current size is 1.27 MB` | passed |
| `GLM-5.3-Flash` e2e (`max_model_len=524288`, `max_num_seqs=128`, `MTP=5`, 92 concurrent requests = 552 decode rows) | `AssertionError: Workspace is locked ... requires 276.00 MB, current size is 265.00 MB` | 92/92 requests completed (locked workspace 384.00 MB) |

## Details

On ROCm, `sparse_attn_indexer_kpool` calls `rocm_fp8_paged_mqa_logits(..., max_model_len=max_pool_len)` on decode, which takes `out_logits` of shape `(batch_size * next_n, max_pool_len)` in `float32` (or `(heads, batch_size * next_n, max_pool_len)` on the stage-1 fallback) from `current_workspace_manager()`. Its profiling branch (`if not isinstance(attn_metadata, dict):`) was copied from the CUDA implementation, where DeepGEMM allocates decode logits through the PyTorch caching allocator (`torch.empty`), so the ROCm workspace only ever saw the prefill K-gather buffers before `lock_workspace()`.
