# [Perf][MRV2] Skip idle sampler staged writes

[Upstream PR](https://github.com/vllm-project/vllm/pull/62748) · state: closed · merged: True

## Original PR description

## Overview

Remove two host costs that Model Runner V2 pays on every decode step: re-flushing all sampler staged writes when no request was admitted, and allocating a pinned staging tensor for each per-step H2D copy in `prepare_inputs`.

## Claims

- B=1 decode step on `facebook/opt-125m` (B300, TP1): **1217 → 1078 µs (−11%)**; B=8: 1342 → 1215 µs (−10%).
- B=1 decode step on `Qwen/Qwen3.5-0.8B` (`language_model_only`): **1790 → 1605 µs (−10%)**.
- No change in outputs: greedy tokens are identical to main, with and without ngram speculative decoding.

## Validation

Decode step = (T(1024 output tokens) − T(1 token)) / 1023 through the offline `LLM` API, greedy, `ignore_eos`, 128-token random prompts, median of 5 reps per run. Configurations were interleaved over 3 rounds on one B300. At these sizes the step is host-bound, so the step time is effectively the engine's host floor.

| config | main | this PR (gate only) | this PR |
|---|---|---|---|
| opt-125m B=1 (3 runs) | 1210 / 1236 / 1205 | 1128 / 1156 / 1145 | 1068 / 1076 / 1092 |
| opt-125m B=8 (3 runs) | 1339 / 1355 / 1332 | 1272 / 1286 / 1276 | 1215 / 1202 / 1227 |
| Qwen3.5-0.8B B=1 (2 runs) | 1772 / 1808 | — | 1615 / 1594 |

The "gate only" column is the first change alone; the pinned-buffer change accounts for the remaining ~65 µs.

- `ngram` speculative decoding (k=3), opt-125m B=1: 402 → 363 µs per output token, same greedy tokens.
- `VLLM_GPU_SYNC_CHECK=error` runs (plain decode and ngram) complete with no sync errors.
- Tests (B300):
  - `pytest tests/v1/worker/test_gpu_logits_processors.py tests/v1/worker/test_gpu_input_batch_v2.py tests/v1/worker/test_gpu_logit_bias.py tests/v1/worker/test_gpu_sampler_flags.py` → 33 passed.
  - `pytest tests/v1/logits_processors/test_custom_offline.py` → 12 passed.

## Details

**Idle sampler staged writes.** #36824 moved `sampler.apply_staged_writes()` out of the `if scheduler_output.scheduled_new_reqs:` branch when it added the non-last-PP-rank `None` check.
- Every step since then re-copies each `UvaBackedTensor` of the sampling states (temperature, top-k/p, min-p, seeds, logit bias, min tokens, stop tokens, logprob ids, …) into a fresh UVA buffer: ~16 full `max_num_reqs` copies per step, ~125 µs.
- All sampler writes are staged by `Sampler.add_request()`, and its only caller is the `scheduled_new_reqs` loop in `add_requests`. Flushing them only on steps that admit requests is therefore exactly equivalent.
- `LogitsProcessor.apply_staged_writes()` (#56497) documented "called once per step". That docstring now states the actual contract: called before the forward of every step that admits requests.

**Per-step pinned allocations.** `prepare_inputs` copied `idx_mapping`, `cu_num_logits` and `query_start_loc` with `async_tensor_h2d`, which allocates a pinned staging tensor per call (~40 µs each).
- They now go through three persistent `UvaBufferPool`s in `InputBuffers`.
- These use the same round-robin contract (depth ≥ in-flight steps) as `UvaBackedTensor` and `StagedWriteTensor`, so the async-safety argument is unchanged.

**Not duplicate work.**
- #62018 fuses admission-time staged writes into fewer kernels, and #62698 parallelizes `_apply_write_kernel`. Both reduce the cost of writes that are needed. This PR skips flushes that write nothing new.
- #59981 changes UVA/staging behavior for Confidential Computing and does not touch these call sites.

Context: part of an effort to lower the B=1 host floor of hybrid Qwen3.5/3.8 decode, measured at ~1.8 ms/step on B300.
