# [Bugfix][Kernel][ROCm] Fix Wave32 LDS overflow in top-k merge launch

[Upstream PR](https://github.com/vllm-project/vllm/pull/46012) · state: closed · merged: False

## Original PR description

## Purpose

Building vLLM from source for a Wave32 AMD GPU (RDNA3/3.5/4 — e.g. `gfx1151`
Strix Halo) fails to compile `csrc/libtorch_stable/sampler.cu`:

```
error: local memory (66032) exceeds limit (65536) in
'void vllm::topKPerRowDecode<1024, true, false, true>(...)'
```

The merge pass of `top_k_per_row_decode` launches the kernel with
`kNumThreadsPerBlockMerge = 1024`. The kernel's `cub`/`hipcub` `BlockScan` +
`BlockRadixSort` temporary storage grows with the block size; on a Wave32 part a
1024-thread block (32 wavefronts) needs more shared memory than the 64 KB LDS
budget, so the template instantiation cannot be built. Wave64 parts
(MI300/`gfx942`, 16 wavefronts per 1024-thread block) stay under the limit, which
is why this was not caught.

Every other launch in this function already uses 512 threads
(`kNumThreadsPerBlock`); only the final merge pass was raised to 1024 (tuned for
NVIDIA). This change gates the merge block size on `USE_ROCM` so ROCm builds use
512 threads — matching the rest of the function and keeping shared memory within
64 KB on Wave32. Because the `<1024>` merge kernel is then never instantiated on
AMD, the overflow cannot occur on any `hipcub`/toolchain version. The NVIDIA path
is unchanged.

Fixes #45871

## Test Plan

- Compile `csrc/libtorch_stable/sampler.cu` for Wave32 targets (`gfx1151`,
  `gfx1201`) and a Wave64 target (`gfx942`) and confirm the build no longer emits
  the `local memory ... exceeds limit` error.
- Inspect the generated device code to confirm only `topKPerRowDecode<512, ...>`
  is instantiated on AMD (no `<1024>`).
- Run the merge kernel on Wave32 hardware and confirm it executes without error.

## Test Result

Validated with ROCm 7.2.1 (hipcc / HIP 7.2, Clang 22):

| GPU | Arch | Build | Merge kernel |
|-----|------|-------|--------------|
| Radeon 8060S (Strix Halo) | `gfx1151` (Wave32, RDNA3.5) | only `<512>` instantiated | runs clean |
| Radeon RX 7900 GRE | `gfx1100` (Wave32, RDNA3) | only `<512>` instantiated | runs clean |
| Radeon RX 9070 | `gfx1201` (Wave32, RDNA4) | only `<512>` instantiated | runs clean |
| (cross-compile) | `gfx942` (Wave64, CDNA3) | only `<512>` instantiated | n/a |

The block size only sets intra-block cooperation for the merge reduction, not the
selected top-k (the same kernel already runs at 512 threads in this function's
other launches), so the result is unchanged. The NVIDIA build still instantiates
`<1024>`.
