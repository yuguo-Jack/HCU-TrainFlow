# [MiniMax-M3.1][P/D] NIXL KV-head re-sharding for per-head-contiguous NVFP4 pages

[Upstream PR](https://github.com/vllm-project/vllm/pull/64475) · state: closed · merged: True

## Original PR description



## Overview

NIXL can now move MiniMax-M3.1's NVFP4 KV cache between prefill and decode instances that run different TP, e.g. prefill TP1 and decode TP4. Split out of #63232 (MiniMax-M3.1-Flash). Based on `main`; it does not depend on the other PRs of that split.

## Claims

- **Heterogeneous-TP NVFP4 transfers:** NIXL re-shards an NVFP4 KV page across heterogeneous TP when the attention spec declares that the page is laid out by KV head (`AttentionSpec.kv_head_major_slots`). MiniMax-M3's MSA NVFP4 backend declares it.
  - Today every NVFP4 cache is rejected under heterogeneous TP (#61865), because in FlashInfer's NVFP4 page a head's bytes are not contiguous.
  - FlashInfer NVFP4 stays rejected.

## Validation

  tests/v1/core/test_kv_cache_utils.py

573 passed. In this environment, the two `test_abort_timeout_on_prefiller` cases need the venv's `ninja` on `PATH`.

New tests:

- `test_nvfp4_kv_head_major_slots_match_insert` checks the layout claim on real bytes.
  - It runs the fused QK-norm/RoPE/KV-insert kernel for a TP1 page, and again for each decode rank's subset of KV heads.
  - Slicing the TP1 page at the spec's per-head byte offsets must give each rank's page byte for byte.
  - Passed on GB300 with the first revision. The review fixes do not touch the kernel, the spec or this test, and it was not re-run.
- `test_attention_merge_preserves_kv_head_major_slots` checks that every spec merge keeps the flag.
- `test_handshake_rejects_nvfp4_kv_head_split` now also covers heterogeneous TP (4→1 and 1→4) with the flag set, which the handshake accepts.

End to end: MiniMax-M3.1 NVFP4 KV with P/D, prefill TP1 → decode TP4 on GB300. The P/D result matched the non-P/D run:

| | P/D | non-P/D |
|---|---|---|
| passkey | 9/9 | – |
| gsm8k | 0.97 | 0.97 |

That run used an earlier revision of this change, in which the backend exposed an attribute that the connector looked up, instead of the spec flag. It was not re-run on this branch. The MSA NVFP4 backend supports only LBHNC, so the BLHNC packed-row code removed during review was never on that run's path.

## Details

A request's KV path under P/D, as this PR changes it:

1. Prefill (TP1, Hkv KV heads) writes NVFP4 pages with 2·Hkv slots. Slot 2h holds head h's K (E2M1 data, then scales) and slot 2h+1 its V. Each head is therefore one contiguous run of S = page_size / Hkv bytes.
2. The NIXL handshake compares the specs. With `kv_head_major_slots`, the NVFP4 heterogeneous-TP guard from #61865 is skipped, and descriptors are registered per KV head at byte offset h·S, the same as for a dense page.
3. Decode rank r (TP4, Hkv/4 heads) reads its heads' contiguous byte range of each prefill page into its own page, which has the same layout.

- **Where the flag lives:** on `AttentionSpec`, so the connector needs no backend lookup. Every spec merge copies it. ROCm's MSA NVFP4 (FlyDSL layout) does not set it.
- **Review changes:**
  - The first revision also sent the packed BLHNC rows of non-MLA models as whole rows. That broke heterogeneous TP for dense BLHNC caches (e.g. FlashInfer on SM100, P TP1 → D TP2): the peers' `packed_member_layouts` differ, and the handshake rejects the connection. Before this PR, per-layer descriptors handled it. That part is reverted, so non-MLA BLHNC registers per layer as before. MiniMax NVFP4 needs LBHNC and does not use it.
  - The local `packed_storage` in `register_kv_caches` is renamed to `replicated_shared_storage`, because `_has_packed_cache` already means packed storage.
- **Not a duplicate:** no open PR touches NIXL NVFP4 heterogeneous TP. #62107 (separate K/V head slots for unquantized FlashInfer KV) is a different layout.

The existing equality check rejects the connection before the new TP guard. Previously, per-layer descriptors supported head slicing.
