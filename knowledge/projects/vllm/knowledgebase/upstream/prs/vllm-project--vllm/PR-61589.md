# [Core][Spec Decode] Lookahead block hashes for EAGLE prefix caching

[Upstream PR](https://github.com/vllm-project/vllm/pull/61589) · state: closed · merged: True

## Original PR description



## Overview

Part 1 of 2 split from vllm-project/vllm#50897 (implements vllm-project/vllm#50438): **lookahead block hashes** for the local prefix cache. EAGLE, EAGLE3 and MTP drafters write the draft KV at a block's last position from the token after the block, so `main` drops the last matched block on every hit. This PR puts that token into the block hash and removes the drop when no KV connector is configured. KV connector support is in the stacked PR (part 2).

## Claims

- Local prefix-cache hits with EAGLE, EAGLE3 and MTP reach `floor((N - 1) / B) * B`, the same as without speculative decoding, instead of one cache unit less (544–1600 tokens on hybrid attention + Mamba/GDN models). Multi-module MTP with k modules reaches `floor((N - k) / B) * B`.
- A block is reused only when its lookahead token matches, so a hit reads the same draft KV as a cold run.
- New `SpeculativeConfig.disable_lookahead_block_hashes` restores `main`'s behavior. With any KV connector configured, this PR keeps the legacy hashes.
- KV events publish the lookahead token in a new `BlockStored.lookahead_token_ids` field, so consumers can reproduce the hashes.
- Model runners are unchanged; no new CPU/GPU synchronization.

One `E` call instead of two saves 7–17% at B ≤ 128 versus the nested form. The expanded window is cheapest, but its hash input equals a legacy hash with block size `B + 1`; keeping `tokens[e]` in the extra keys costs 3–5% more than it at B = 16 and at most 2.5% at B ≥ 128. ## Details

**Enablement.** `get_num_hash_lookahead_tokens` (`v1/core/kv_cache_utils.py`) returns `L = num_prefill_lookahead_tokens` (1, or k for multi-module MTP with k modules) when `use_eagle_block_drop()`, `not disable_lookahead_block_hashes`, prefix caching is on and there is no KV transfer config; otherwise 0, which keeps the legacy hashes and the block drop. DFlash and DSpark build draft KV from target hidden states alone; vllm-project/vllm#54163 removes them from `use_eagle_block_drop()`, after which they keep the legacy hashes with no drop. Until then they get lookahead hashes too, which is correct but unnecessary. `num_hash_lookahead_tokens` replaces the former boolean flag through the KV cache manager, coordinator, block pool and scheduler. Part 2 replaces the last condition with a per-connector capability.

**Hashing.** `get_request_block_hasher(..., num_hash_lookahead_tokens=L)` hashes a block `[s, e)` only once tokens up to `e + L - 1` are in `all_token_ids`, as `H((parent, tokens[s:e], (E(s, e + L), *tokens[e:e + L])))`; for `L = 1` that is `(E(s, e + 1), tokens[e])`. `E` is `generate_block_hash_extra_keys` over the block and its lookahead tokens, called once per block, so MM inputs or prompt embeddings there are covered too; the MM cursor then steps back to the first input the next block overlaps. The hashed tokens stay the block's tokens, and the `(E, token)` shape keeps these hashes apart from legacy ones; hashing `tokens[s:e + L]` instead would equal a legacy hash with block size `B + L`. Different `L` give different tuple lengths. All KV cache groups share these hashes.

**KV events.** `BlockStored.lookahead_token_ids` holds `tokens[e:e + L]` per block, and `extra_keys` keeps its untagged per-block shape but covers `[s, e + L)`. A block hash is reproducible from `token_ids`, `extra_keys` and `lookahead_token_ids` (`test_kv_events_reconstruct_lookahead_block_hashes`). Consumers that ignore the new field still decode events, but blocks with the same tokens at the same position can now carry different hashes, so routers that index one hash per position need to key on the lookahead tokens. The extra field widens the msgpack map header of every `BlockStored` (fixmap to map16); decoded contents are unchanged. `examples/features/kv_events/kv_events_subscriber.py` includes the field.

**Caching.** Blocks are cached at allocation, as without lookahead hashes; `SingleTypeKVCacheManager.cache_blocks` stops at the last hashed block. At request finish, `update_from_output` caches the block whose lookahead the last sampled token completes.

**Drop removal.** The scheduler clears `use_eagle_block_drop`. `KVCacheCoordinator.drop_eagle_group_ids` is empty in this mode and drives the per-group drop and `replay_boundaries`, so the last-block drop, the Mamba checkpoint back-off and the replay-boundary shift are all skipped from one place. `eagle_group_ids` stays, since `mamba_shared_prefix_checkpoint` still applies.

**Docs.** A new "Prefix caching" section in `docs/features/speculative_decoding/README.md` covers the default, `disable_lookahead_block_hashes` and `BlockStored.lookahead_token_ids`.

**Why it is correct.** The drafter writes the draft KV at `e - 1` (input `(h_{e-1}, token e)`) in the step that prefills or samples token `e`. The hash exists only once token `e` is in `all_token_ids`, which never holds draft or in-flight tokens, so a cached block's draft KV is written by the end of that step. With k-module MTP, module j writes its KV at `p` from token `p + j`, so the hash waits for tokens up to `e + k - 1`. `MultiModuleMTPSpeculator` re-prefills a slot written from a rejected draft in the step that samples its replacement, and the coordinator already keeps the last `k - 1` computed tokens out of the cache.

**Limitations**

- Multi-module MTP lookahead hashes are covered by unit tests only; the draft-KV check against a cold run has not been run for them yet.
- HiSparse requires `HiSparseConnector`, so like other connectors it keeps the legacy hashes and the block drop. Its host tier publishes pages once their host copies finish; whether those copies include the last position's draft KV needs GPU validation before part 2 lets `HiSparseConnector` opt in.
- Streaming-input sessions are not supported. When a turn ends on a lookahead boundary, the block cached with the discarded sampled token keeps that hash (its draft KV was written from that token), so later blocks of the session are unreachable by prefix lookups from other requests.
- Hybrid models lose the hit when a prompt diverges exactly at the producer's last retained Mamba boundary (0 vs one unit on `main`); see vllm-project/vllm#50897 for the reproducer.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Invalidate cached hashes when replacing the lookahead token**

When a resumable streaming turn finishes exactly on a hash-block boundary, the finish-time caching path has published the preceding block using the sampled token that this method now discards. Deleting only the request's hash leaves each manager's `num_cached_block` at the old count and the block pool mapping the old hash to the live block; the continuation then recomputes a replacement hash and overwrites the EAGLE KV at that boundary, but caching short-circuits as already cached. Consequently, a later request can hit the old hash and read KV written for the replacement token, while the replacement hash is never installed, so this path needs to detach/COW or invalidate and re-key the affected cached boundary block as well as truncating `session.block_hashes`.
