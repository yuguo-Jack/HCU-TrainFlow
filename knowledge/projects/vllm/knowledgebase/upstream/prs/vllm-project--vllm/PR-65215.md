# [Docs] Generate the quantization scheme table from source

[Upstream PR](https://github.com/vllm-project/vllm/pull/65215) · state: open · merged: False

## Original PR description

## Overview

Adds `docs/features/quantization/formats.md`, a vocabulary page for the quantization section, and generates its scheme
table from source at docs build time (`docs/mkdocs/gen_files/generate_quantization_matrix.py`), following the existing
attention-backend table. Docs and docs-build tooling only; no runtime change.

## Claims

- The new page defines terms the section assumes: checkpoint method, scheme, granularity, quant key, `W<n>A<m>`
  notation, and the numeric formats (FP8, MXFP8/MXFP4, NVFP4, INT8/INT4), plus the shorthand → weight/activation mapping.
- The 12 user-addressable schemes are rendered from `QUANT_KEY_NAMES` and the `QuantKey`/`ScaleDesc`/`GroupShape`
  definitions in `quant_utils.py`.
- `mkdocs build` fails on a scheme with no note, a note with no scheme, an unknown dtype, or a note containing `|`.

## Validation

`mkdocs build` (API reference excluded to keep the run short) succeeds and renders the table:

```console
$ API_AUTONAV_EXCLUDE=vllm .venv/bin/mkdocs build
INFO    -  Generating quantization documentation tables
INFO    -  Documentation built in 27.93 seconds
$ # exit 0; site/features/quantization/formats/index.html contains 12 scheme rows and no left-over `gen:` marker
```

The Read the Docs build for this PR also succeeded and renders the generated table at
<https://vllm--65215.org.readthedocs.build/en/65215/features/quantization/formats/>.

Injecting a stale note fails the build:

```console
ValueError: features/quantization/formats.md: note for removed scheme(s) ['__tmp_stale__'].
Update SCHEME_NOTES in docs/mkdocs/gen_files/generate_quantization_matrix.py.
# exit 1
```

Other checks:

- `ruff check` and `ruff format --check` on the generator: pass.
- `markdownlint-cli2 --config tools/pre_commit/.markdownlint.yaml` on the three pages: 0 issues.
- No model evaluation: docs and docs-build tooling only.

## Details

**Motivation.** The quantization section had no page defining its precision vocabulary, and its hand-maintained
capability tables have drifted (the landing page still lists removed and out-of-tree methods). This PR lands the
generated-table mechanism first so later pages (choose-a-scheme, kernel/backend selection, KV-cache dtypes) can use it.

**Implementation.**

- AST-only parsing, mirroring `generate_attention_backends.py`, so the docs build needs no `torch` or CUDA.
  `QUANT_KEY_NAMES` supplies names and order; `QuantKeyParser` resolves `QuantKey`/`ScaleDesc`/`GroupShape` assignments,
  including aliases, keyword arguments, and inline `ScaleDesc(...)` calls.
- `DATA_DTYPE_NAMES` and `SCALE_DTYPE_NAMES` map dtypes to display names.
- `SCHEME_NOTES` holds the hand-written notes, checked by `_validate_notes`.
- The generator only fills `--8<-- "gen:quantization-schemes"`; page prose stays tracked, per the `gen:` convention in
  `docs/mkdocs/gen_files/generated_content.py`.

**Scope and follow-ups.**

- Only the scheme table is generated here. `quantization-methods`, `quantization-backends`, `kv-cache-dtypes`, and
  `quantization-hardware` plug into `build_blocks()` in follow-ups.
- `formats.md` links only to existing pages; the router rewrite and `choosing.md` / `kernels.md` follow.
- No duplicate work: searched open PRs and issues for a quantization docs generator; none found. Three open PRs
  (#50598, #50646, #63987) and issue #62187 touch the out-of-tree plugin guide, which this PR does not modify.
