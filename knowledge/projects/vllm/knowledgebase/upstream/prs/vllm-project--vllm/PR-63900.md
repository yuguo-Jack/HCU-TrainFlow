# [KV Offload] Remove unused touch from CachePolicy and OffloadingManager

[Upstream PR](https://github.com/vllm-project/vllm/pull/63900) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Remove the now-unused `touch` hooks, as suggested in the [#61050 approval](https://github.com/vllm-project/vllm/pull/61050#pullrequestreview-5653251367). This also finishes the `touch` to `on_store_miss` cleanup from the [#51787 review](https://github.com/vllm-project/vllm/pull/51787#discussion_r4014470687), where `touch` was kept only as a compatibility fallback.

## Claims

- Nothing in the scheduler or managers calls `touch` anymore. #51787 moved recency to `on_request_finished`, and #61050 moved in-flight ordering into `insert(req_context)`. The remaining definitions only forwarded to each other.
- `CachePolicy.touch`, `OffloadingManager.touch` and `SecondaryTierManager.touch` are removed, along with their overrides. The KVCR tier now calls `_align_sequence` directly from `on_request_finished`, which is all its `touch` override did.
- `CachePolicy.on_request_finished` becomes abstract and replaces `touch` as the required recency hook. `on_store_miss` now defaults to a no-op.
- Built-in LRU and ARC behavior is unchanged.

## Details

- LRU did not override `on_store_miss`, so its store misses reached `touch` through the base default. Those keys are never resident (`prepare_store` only reports keys the policy does not hold), so `_update_recency` skipped them. The no-op default keeps LRU identical.
- ARC already overrides `on_store_miss` and `on_request_finished`; its `touch` was only reachable from tests.
- Interface change for out-of-tree `CachePolicy` implementations: they must implement `on_request_finished`. An outdated policy now fails at construction rather than silently losing recency. The custom-policy guide documents this, as #61050 did for `insert`. A no-op default would also work; I chose the explicit contract, but am happy to switch if you prefer. `touch` overrides on custom `OffloadingManager` or `SecondaryTierManager` subclasses are simply no longer called.
- `TieringOffloadingManager.touch` was the only caller of `SecondaryTierManager.touch`. The KVCR tier (#60469) overrode it only to call it from its own `on_request_finished`, so inlining `_align_sequence` there keeps KVCR's behavior unchanged.
- Tests that used `touch` to set LRU order or promote ARC chunks from T1 to T2 now go through a finished request (`prepare_load`, `complete_load`, `on_request_finished`). The ARC ghost-hit setups use `on_store_miss`, through `prepare_store` where the test allows the insert. `test_touch_forwards_req_context_to_policy`, `test_touch_propagates_to_all_tiers` and the `manager.touch.assert_not_called()` checks are removed.
- Not a duplicate: no open PR removes these hooks. Open #63578 subclasses `LRUCachePolicy` and overrides `on_request_finished`, so it is unaffected. Open #50422 still implements `touch`, but it already conflicts with `main` (it predates #51787 and the `insert(req_context)` change), so a rebase would move its recency to `on_request_finished` anyway.
