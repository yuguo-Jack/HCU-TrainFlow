# [ROCm] [Bugfix] Preserve CPU query offsets during capture

[Upstream PR](https://github.com/vllm-project/vllm/pull/51585) · state: closed · merged: True

## Original PR description

## Motivation

On ROCm, full CUDA graph capture can fail during server startup for mixed-attention models when a later metadata builder reads a query length of zero. The root cause is that `RocmAttentionMetadataBuilder` clears both device and CPU query offsets to prevent an invalid memory access in the prefix prefill kernel. The device offsets must be zeroed for safe graph capture, but the CPU offsets are not used by that kernel and remain shared with subsequent metadata builders. Clearing the CPU copy therefore removes valid batch information those builders need.

## Proposed Fix

Preserve the CPU query offsets while continuing to zero the device offsets.

This keeps the existing prefix prefill capture behavior unchanged while allowing subsequent metadata builders to calculate valid query lengths. The change is scoped to full graph capture through the ROCm metadata builder shared by `ROCM_ATTN` and `ROCM_AITER_UNIFIED_ATTN`.

## Test results

Tested on 4 GPUs, MI325, model -> `EmbeddedLLM/MiniMax-M3-FP8-dynamic`

Before the change, CUDA graph profiling failed:

```text
File "vllm/models/minimax_m3/common/indexer.py", line 317, in build

AssertionError
EngineCore failed to start.
```

After the change:

```text

Application startup complete.
POST /v1/chat/completions HTTP/1.1 200 OK
```
