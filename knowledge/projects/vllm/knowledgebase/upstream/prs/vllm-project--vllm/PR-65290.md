# [MoE] Add a generic fused gate router and backend interface

[Upstream PR](https://github.com/vllm-project/vllm/pull/65290) · state: open · merged: False

## Original PR description



## Overview


Introduce a generic fused gate interface for MoE routing and adapt the existing DeepSeek V4/V4.1 SM100 bf16_mega_gate path to it. This provides an extension point for future gate backends, including FlashInfer

https://github.com/vllm-project/DeepGEMM/pull/53

## Claims

- Add router-level set_gate() and can_fuse_gate() capabilities, allowing the runner to skip gate projection without checking concrete router types.
- Introduce a dedicated FusedGateRouter, selected through create_fused_moe_router, while reusing existing routing and fallback behavior.
- Define backend support checks, prepare(), and plan forward() interfaces with explicit contracts for routing weights, logical expert IDs, metadata, and workspace lifetime.
- Adapt the existing DeepGEMM Mega Gate path while preserving its small-batch fallback, hash/image routing, and downstream shared-expert and EPLB handling.

## Details

The modular router starts with no fused backend enabled by default. This PR introduces the common interface and migrates existing SM100 behavior; H20 Mega Gate support and a FlashInfer adapter are follow-up work. The existing vllm/utils/deep_gemm.py wrapper remains unchanged.

Related work in #64061 adds SM90 expert-kernel support, while #65069 adds optional Mega kernels under batch invariance. This PR addresses the shared gate-routing abstraction and existing backend integration, a separate scope from those changes.
