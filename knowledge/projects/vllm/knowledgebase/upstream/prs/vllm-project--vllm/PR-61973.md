# [Bugfix] Preserve batch audio handler error status codes

[Upstream PR](https://github.com/vllm-project/vllm/pull/61973) · state: closed · merged: True

## Original PR description



## Overview

Fix `vllm run-batch` incorrectly reporting audio handler failures with status 400. Preserve the standard error mapping for transcription and translation requests, including 500 for engine failures and 503 for retryable errors.

## Claims

- Map audio handler exceptions through the existing batch error handling.
- Preserve status 400 for audio download and request preparation failures.
- Keep successful responses and handler-returned errors unchanged.

## Validation

Added a parameterized regression test covering transcription and translation with engine, retryable, and validation errors.

- Before: all four 500/503 cases failed; both 400 cases passed.
- After: **26 selected tests passed**.
- All applicable pre-commit checks passed, including Ruff and mypy.

```bash
.venv/bin/python -m pytest tests/entrypoints/launchers/test_run_batch.py \
  -k 'batch_audio or download_bytes or transcription_wrapper or upload_data' -q

.venv/bin/pre-commit run --files \
  vllm/entrypoints/launchers/run_batch.py \
  tests/entrypoints/launchers/test_run_batch.py
```

## Details

`make_transcription_wrapper` previously caught both request preparation and handler exceptions, converting all failures to status 400.

Move the handler call outside the preparation `try/except` so `run_request` applies the existing exception mapping. Audio download and request preparation errors retain their previous behavior.
