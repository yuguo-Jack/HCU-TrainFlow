# Fix null fields in Chat Completions responses (#61425)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61431) · state: open · merged: False

## Original PR description

## Overview

Fixes [#61425](https://github.com/vllm-project/vllm/issues/61425) by omitting unset `annotations` and `usage.prompt_tokens_details` from Chat Completions responses and typing annotations as an optional list.

## Claims

- Strict OpenAI schema validators no longer receive `null` for these optional fields.
- Explicit annotation lists and prompt token details remain serialized.

## Validation

- `pytest tests/entrypoints/openai/test_tool_choice_content_none.py -q` — passed (run by the contributor).
- `uv run --no-sync --python 3.13 python -m compileall -q vllm/entrypoints/openai/chat_completion/protocol.py vllm/entrypoints/serve/engine/protocol.py tests/entrypoints/openai/test_tool_choice_content_none.py` — passed.
- `git diff --check` — passed.

## Details

`ChatMessage` serialized its unset `annotations` value as `null`, and `UsageInfo` did the same for unset prompt token details. The annotation field also used the SDK's single-annotation type despite the OpenAI schema defining an array. The serializers now omit those fields only when unset; supplied values are preserved. No open PR addressing this issue was found when checked. AI assistance was used to investigate and implement the change.

- vadiklyutiy · comment · 2026-10-15T23:05:11Z · [source](https://github.com/vllm-project/vllm/pull/61431#issuecomment-6204115973)

Thanks for the fix! One suggestion on how the keys are dropped.

vLLM already has a pattern for "omit this field when it is None": `exclude_if` on the field itself, e.g. `ResponsesResponse.metrics`:

https://github.com/vllm-project/vllm/blob/de7d70676d9a39353aab4796a6987d345c597991/vllm/entrypoints/openai/responses/protocol.py#L821-L824

Using the same here would keep the wire rule next to the field it applies to, and avoid adding a new wrap `model_serializer` (plus the import) to `UsageInfo` just to pop one key:

```python
# vllm/entrypoints/openai/chat_completion/protocol.py
annotations: list[OpenAIAnnotation] | None = Field(
    default=None, exclude_if=lambda value: value is None
)
```

```python
# vllm/entrypoints/serve/engine/protocol.py
prompt_tokens_details: PromptTokenUsageInfo | None = Field(
    default=None, exclude_if=lambda value: value is None
)
```

With that, the extra `pop` in `ChatMessage._serialize` and the new `UsageInfo._serialize` are no longer needed. I checked that the validation/serialization JSON schemas and the `model_dump` / `model_dump_json` output (including `exclude_unset`, `include`, and an empty `annotations` list) are identical between the two approaches. `CohereChatMessage` also picks it up through the inherited field.
