# [CI][Bugfix][Core] Size KV cache from torch reserved when profiling sees a release on any platform

[Upstream PR](https://github.com/vllm-project/vllm/pull/62806) · state: closed · merged: False

## Original PR description



## Overview




Generalize the ROCm-only startup-profiling fallback from #53591 to every
platform: when profiling measures a release of device memory by other
processes, size the KV cache from this process's torch reserved memory
instead of aborting. Fixes #56830 and the deterministic NVIDIA NIXL PD CI
failure (#62579's 2-GPU accuracy core job).

## Claims

- Startup no longer aborts with `AssertionError: Error in memory profiling.`
  when other processes on the GPU release memory during profiling —
  previously only ROCm had the fallback; CUDA and others kept the hard assert.
- Unblocks the `nvidia-l4 nixlconnector-pd-accuracy-core` CI job, which
  failed 3/3 deterministically (device free memory 14.91 → 17.29 GiB while a
  decode worker profiled).
- Existing ROCm behavior is unchanged; the removed assert is dead code once
  the fallback exists (its trigger condition is exactly the fallback
  condition).
- Unit tests now pin the fallback contract for all platforms instead of a
  ROCm-only parametrization.

  ```
  AssertionError: Error in memory profiling. Initial free memory 14.91 GiB,
  current free memory 17.29 GiB. This happens when other processes sharing
  the same container release GPU memory while vLLM is profiling during
  initialization. ...
  ```

  (build 96123, 3/3 retries with identical values). With the patch the
  worker logs
  `Free memory grew by 2.38 GiB during profiling (...) Sizing the KV cache
  from the ... torch reserved instead of the profiling difference.` and
  startup proceeds.
  CI: <fill in Buildkite build link(s) showing the nixlconnector job green>.

## Details

- Root cause: `total_consumed` is the drop in device-global free memory
  across startup. It goes negative when another process on the same GPU
  releases memory inside the profiling window — a co-tenant, or the paired
  instance of a disaggregated deployment finishing its own startup. In the
  failing NIXL PD config (2-GPU L4, prefill + decode sharing GPUs), a decode
  DP1_EP1 worker profiles while the prefill instance finishes
  deepseek-vl2-tiny's multimodal warmup and releases ~2.4 GiB.
- Design: #53591's fallback — size from this process's torch reserved delta,
  which is process-local, unaffected by other processes, and a lower bound on
  this instance's usage — is lifted from ROCm to all platforms. The warning
  is retained and the result is clamped so it can never be negative.
- Tradeoff: in the rare co-tenant-release window the KV cache may be sized
  conservatively (smaller than the device could actually support at that
  moment). This is preferable to refusing to start, and consistent with
  documented GPU co-tenancy (#56830).
- Alternative considered: #45534's opt-in
  `VLLM_MEMORY_PROFILER_ALLOW_FREE_MEMORY_INCREASE` escape hatch (unmerged).
  This PR makes the safe path the default on every platform instead.
- Related: #56830, #53591, #45620 (same class of fix for `Worker.sleep()`),
  #35929 (declined on co-tenancy-scope grounds, challenged by #56830).
