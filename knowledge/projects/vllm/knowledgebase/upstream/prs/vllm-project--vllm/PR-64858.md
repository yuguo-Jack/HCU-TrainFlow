# [Frontend] support anthropic-defined client tools on /v1/messages

[Upstream PR](https://github.com/vllm-project/vllm/pull/64858) · state: open · merged: False

## Original PR description



## Overview

`/v1/messages` now accepts anthropic-defined client tools (`bash_*`, `text_editor_*`, `memory_*`) by supplying their built-in schemas to the chat template; second work item of #64810. follows #64575, which rejected these with a named 400.

## Claims

- requests that declare `{"type": "bash_20250124", "name": "bash"}`, `text_editor_20250728` / `str_replace_based_edit_tool`, and so on no longer fail; the model sees a regular function tool and `tool_use` comes back under the name the client expects, so the client keeps running the tool as it does against the anthropic api.
- registered versions: `bash_20241022`, `bash_20250124` (`bash`); `text_editor_20241022`, `text_editor_20250124` (`str_replace_editor`, with `undo_edit`, inserted text in `new_str`); `text_editor_20250429`, `text_editor_20250728` (`str_replace_based_edit_tool`, no `undo_edit`, inserted text in `insert_text`); `memory_20250818` (`memory`).
- a registered type declared under the wrong name gets a named 400 (`tool type 'text_editor_20250728' must be named 'str_replace_based_edit_tool', got ...`).
- server tools (`web_search_*`, `code_execution_*`, ...), `computer_*` and unknown versions keep the named 400 from #64575.

## Validation

```
pytest tests/entrypoints/anthropic/test_anthropic_messages_conversion.py -k TestToolDefinitions
```

new tests per registered version check the converted chat request (function name, description, parameters, command enum, `tool_choice=auto`), the version-specific insert field, tool-level options like `max_characters` being accepted, the wrong-name reject, the reject list (web_search, code_execution, computer, unknown bash version) and that the schema isn't shared between requests. all of `tests/entrypoints/anthropic` that runs on cpu passes; the only failures (`TestDetectMergeInlineSystem::test_probes_non_jinja_renderer`) fail the same way on main in my cpu-only env. `ruff check` and `ruff format --check` are clean.

## Details

- new `vllm/entrypoints/anthropic/client_tools.py` holds a small registry keyed by the versioned type: expected name, a short description, and the input schema built from anthropic's documented parameters. `AnthropicTool`'s before-validator expands registered types into a normal tool (keeping the original `type`), so `_convert_tools`, `tool_addition` and count_tokens all work unchanged.
- a client-supplied `description` is kept if present; the schema is deep-copied per request.
- tool-level options (`max_characters`) are accepted and ignored; vllm doesn't run the tool, so truncation stays on the client side.
- `computer_*` is left out on purpose: it needs display config and screenshot (image) tool results; happy to follow up separately.
- docs: added a note to `docs/serving/integrations/claude_code.md`.
