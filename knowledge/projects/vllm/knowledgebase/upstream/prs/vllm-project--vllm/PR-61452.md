# [Core][KV Cache] Move KV cache allocation policy onto manager configs (RFC #42449 part 2)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61452) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Part 2 of #42449: `KVCacheSpec` now describes only a layer's **tensor layout**. **Allocation policy** (windows, recycling, prefix caching, Mamba modes) moves onto the KV cache manager that enforces it. Layers declare `(manager_cls, manager_config, spec)`, and a group is simply *layers that share a block table*.

**Draft:** CPU unit tests only so far; GPU and E2E validation pending.

| | Before | After |
|---|---|---|
| Spec classes | 15 (8 encode only policy) | 5 layout classes: `AttentionSpec`, `MLAAttentionSpec`, `HiddenStateCacheSpec`, `MambaSpec`, `HiSparsePageSpec` |
| Policy | spec fields + subclasses | `Manager.Config`, e.g. `SlidingWindowManager.Config(sliding_window, ...)` |
| Spec → manager | global `KVCacheSpecRegistry` + platform hook | the layer names its manager: `SlidingWindowManager.layer_config(spec, sliding_window=w)` |
| Mixed-layout groups | `UniformTypeKVCacheSpecs` wrapper | `group.kv_cache_specs[layer]` |
| Sizing | per-spec methods + wrapper aggregation | `manager.max_blocks_per_request(config, ...) × group.page_size_bytes` |
| `kv_cache_interface.py` | | +177 / −889 lines |

Overall, production code changes 113 files, +2388 / −3157 lines. No compat shims: out-of-tree specs and platform-registered managers need updating.

## Details

- **Grouping:** one rule replaces the planner's "identical spec" and "uniform type" paths. `MambaManager` additionally requires equal page sizes. Page-size unification, padding and group splitting are unchanged.
- **Behavior changes:**
  - Same-policy layers with different layouts can now share a group.
  - Builders that need policy declare `requires_kv_cache_manager_config` (Mamba, GDN, linear attention, KDA, QSA, Dots3).
  - Encoder-only attention is a manager policy, which lifts its one-spec limit.
- **Hazard reviewed:** collapsing policy subclasses into `AttentionSpec`/`MLAAttentionSpec` broadens any `isinstance` check that really meant a policy. All such checks were audited, and the ones that meant policy now test the manager:
  - the coordinator's cache-hit batching key now includes `dcp_sharded`
  - the Mooncake store's TP-sharded layout gate
  - the HiSparse MLA filter
- **Out of scope:** planning still runs in the engine core. Backend-declared configs and worker-driven allocation are later parts of #42449.
- **Not a duplicate:** open PRs were searched for #42449, `UniformTypeKVCacheSpecs`, `KVCacheSpecRegistry`, `manager_config` and `KVCacheTensorSpec`.
