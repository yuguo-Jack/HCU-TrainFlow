# [Core][KV Cache] Move KV cache allocation policy out of KVCacheSpecs (RFC #42449 part 2)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61452) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Part 2 of #42449: `KVCacheSpec` now describes only a layer's **tensor layout**. **Allocation policy** (windows, recycling, prefix caching, Mamba modes) moves onto the KV cache manager that enforces it. Each manager declares its settings as a frozen `Params` dataclass; layers return `KVCacheLayerConfig(ManagerConfig(manager_cls, params), spec)`, and a group is simply *layers that share a block table*.

**Draft:** CPU and GPU unit tests, plus E2E on GLM-5.3-Flash and DeepSeek-V4.1-Flash; remaining E2E pending.

| | Before | After |
|---|---|---|
| Spec classes | 15 (8 encode only policy) | 5 layout classes: `AttentionSpec`, `MLAAttentionSpec`, `HiddenStateCacheSpec`, `MambaSpec`, `HiSparsePageSpec` |
| Policy | spec fields + subclasses | `ManagerConfig(manager_cls, params)`, e.g. `SlidingWindowManager.config(sliding_window=w)` → `ManagerConfig(SlidingWindowManager, SlidingWindowManager.Params(sliding_window=w))` |
| Spec → manager | global `KVCacheSpecRegistry` + platform hook | the layer names its manager: `SlidingWindowManager.layer_config(spec, sliding_window=w)` |
| Mixed-layout groups | `UniformTypeKVCacheSpecs` wrapper | `group.kv_cache_specs[layer]` |
| Cache-hit lookup batching | pairwise spec matching in each coordinator | `prefix_lookup_groups`: same manager config, block size, DCP sharding and layout |
| Sizing | per-spec methods + wrapper aggregation | `manager_cls.max_blocks_per_request(manager_config, ...) × group.page_size_bytes` |
| Backend builders | read policy off the spec | read what they need from their layers and `vllm_config` (e.g. `MambaBase.get_kv_cache_checkpoint_alignment()`, the layer's sliding window); no backend sees manager params |
| `kv_cache_interface.py` | | +195 / −910 lines |

Overall, non-test code changes 126 files, +2353 / −3244 lines. No compat shims: out-of-tree specs and platform-registered managers need updating.

## Behavior notes

- Cache-hit lookups batch KV cache groups only when they share a manager config, block size, DCP sharding and layout, the same groups `main`'s core coordinator batches. Layout doesn't affect a lookup, but a batch takes the EAGLE last-block drop if any member does. The layout term (`_eagle_drop_layout_key`) can be removed once that drop is gone; #64096 extends lookahead block hashes, which replace it, to KV connectors.
- The Mooncake store coordinator now uses the same rule, so unlike `main` it no longer batches packed groups whose first layers share a spec.
