# [CI] Split (H100) V1 Attention into Sparse MLA, MLA Backends/Correctness, Dense/SSM, and DCP/ROCm jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/57238) · state: closed · merged: False

## Original PR description

## What

Replace the two opaque `(H100) V1 Attention` whole-area shards with named jobs for Sparse MLA, MLA Backends, MLA Correctness, Dense and SSM, and DCP with ROCm Compatibility. Only the two large directories use pytest sharding; the remaining jobs run whole coverage units once.

## Old

```text
(H100) V1 Attention Shard %N [v1-attention-h100-mi300]
└── pytest v1/attention --num-shards=2
```

## New

| Buildkite job | key | whole coverage unit | replicas |
|---|---|---|---:|
| `(H100) V1 Attention / Sparse MLA Shard %N` | `v1-attention-h100-mi300` | `sparse_mla/` | 2 |
| `(H100) V1 Attention / MLA Backends` | `v1-attention-h100-mla-backends` | `mla/backends/` | 1 |
| `(H100) V1 Attention / MLA Correctness Shard %N` | `v1-attention-h100-mla-correctness` | `mla/correctness/` | 2 |
| `(H100) V1 Attention / Dense and SSM` | `v1-attention-h100-dense-ssm` | `dense/` + `ssm/` | 1 |
| `(H100) V1 Attention / DCP and ROCm Compatibility` | `v1-attention-h100-dcp-rocm` | `dcp/` + `rocm/` | 1 |

## Notes

- This PR is stacked on #57063; its CI changes touch `.buildkite/test_areas/attention.yaml` and `.buildkite/test-amd.yaml`.
- The existing key stays on Sparse MLA so the generated `amd-v1-attention-h100-mi300` mirror key remains stable.
- Mirror all five H100 groups on MI300 (seven workers including shards) and all six B200 groups on MI355 (eight workers). Matching smaller native AMD jobs replace both whole-area jobs, preserving each test once per hardware lane. AMD groups retain the existing source dependencies and use an 85-minute timeout, preserving the prior 40-minute allowance over the NVIDIA parent.
- The AMD follow-up changes no test bodies, parameters, assertions, skip marks, or NVIDIA job settings. Only AMD MLA Correctness jobs explicitly enable `VLLM_ROCM_USE_AITER=1`; otherwise all 580 existing AITER correctness cases skip in the local environment. AI assistance was used.

## Expected runtime and overhead

| semantic job | replicas | prediction | main overhead cause |
|---|---:|---|---|
| Sparse MLA | 2 | under the per-replica target | checkout and container startup |
| MLA Backends | 1 | under the per-replica target | checkout and container startup |
| MLA Correctness | 2 | under the per-replica target | checkout and container startup |
| Dense and SSM | 1 | under the per-replica target | checkout and container startup |
| DCP and ROCm Compatibility | 1 | under the per-replica target | checkout and container startup |

This changes the H100 lane from two workers to seven. Existing per-file evidence supports this as the smallest named-job layout that keeps every job under the runtime target and predicts aggregate extra worker time within the 20-minute budget. Fresh scoped validation will measure the final job boundaries.

## AMD validation

This follow-up reorganizes the existing coverage from #42793, #49916, and #53351 within this PR. It replaces the broad AMD jobs rather than adding a second copy of their tests.

- Actual `pytest --collect-only -q` runs with each AMD job's paths, AITER setting, and shard flags verify all **4,514 cases exactly once per hardware lane**. Structural checks confirm all 11 mirrors match their native jobs and preserve NVIDIA definitions.
- `.venv/bin/python -m pre_commit run --files .buildkite/test_areas/attention.yaml .buildkite/test-amd.yaml` and `git diff --check` passed.
- Targeted MI355 runtime validation: **1,219 passed, 35 skipped, five setup failures**. The five failures require the gated `meta-llama/Meta-Llama-3-8B` configuration; Hugging Face returned HTTP 401 before assertions, and that configuration was not cached locally.

Portable checks used `HIP_VISIBLE_DEVICES=1 .venv/bin/python -m pytest -q <scope> --timeout=120`, with each of these scopes under `tests/v1/attention/`: `mla/backends/`, `dcp/`, `rocm/`, `ssm/`, `sparse_mla/test_indexer_deepseek_v4_slot_mapping.py`, and `dense/test_chunked_local_attention.py`. Another 12 original MLA correctness cases ran with `HIP_VISIBLE_DEVICES=0 VLLM_ROCM_USE_AITER=1`, covering DeepSeek/GLM dimensions, BF16/FP8 caches, scaled Q/K, decode/prefill/speculative batches, and all four chunked-context cases.

Runtime validation was targeted and used MI355; full-suite runtime, MI300 execution, and rendered AMD pipeline validation remain pending. Existing CUDA-only sparse/FlashInfer coverage gaps are unchanged. OpenAI Codex assisted with the AMD implementation and validation.

The current branch still contains the older six-group B200 layout from #57063. After rebasing onto that PR's latest combined layout, combine the corresponding MI355 short groups and repeat the coverage audit.
