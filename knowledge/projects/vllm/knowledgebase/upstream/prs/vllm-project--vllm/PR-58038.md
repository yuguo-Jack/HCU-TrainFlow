# [Bugfix][NIXL] Don't fail a completed KV transfer when telemetry is unavailable

[Upstream PR](https://github.com/vllm-project/vllm/pull/58038) · state: closed · merged: False

## Original PR description

## Purpose

`get_xfer_telemetry()` is called inside the `xfer_state == "DONE"` branch of
`_pop_done_transfers` — i.e. *after* NIXL has already reported the transfer complete. The enclosing
`except Exception` then routes any telemetry error into `_handle_failed_transfer()`, discarding a
transfer that succeeded.

Telemetry is optional. NIXL builds shipped with it compiled out log:

```
W nixl_agent.cpp:215] NIXL telemetry is disabled; ignoring telemetry requested through agent config
```

and then raise `nixlNoTelemetryError` from `get_xfer_telemetry()`, even though the agent was
created with `capture_telemetry=True`. vLLM enables telemetry unconditionally — the comment above
the agent config says *"Enable telemetry by default for NIXL 0.7.1 and above"*, but the code only
checks that `nixl_agent_config` imports; there is no version or capability check, and
`nixlNoTelemetryError` is not handled anywhere in the tree.

## Impact

On DeepSeek-V4.1 P/D disaggregation over the default UCX backend with a stock `nixl-cu13==1.4.1`
wheel, this failed **100% of requests**:

```
vllm:nixl_num_failed_transfers_total  17960
"Num successful transfers=0"
"Skipping KV post-processing for failed request ..."
"backend emitted finish_reason=error without a message"
→ HTTP 500 to every client
```

Guarding the call restored serving with no other change — which also confirms the KV transfers
themselves were fine throughout. Measured before/after on the same image and config:

| | unpatched | patched |
|---|---|---|
| 60k-token prompt | `{"error":{"code":500}}` | streams content |
| `nixl_num_failed_transfers_total` | 17,960 | 0 |
| benchmark | every request failed | 3526 valid / 15 errors |

## Relationship to existing work — please read before reviewing

This overlaps with work already in flight, and I want to be explicit rather than quietly duplicate it:

- **#57734** — *[Bugfix][NIXL] Guard `record_transfer` against None telemetry* (open). It supersedes
  **#57403**, which is now closed.
- **ai-dynamo/nixl#2271** — *return `None` from `get_xfer_telemetry` when telemetry is disabled* (open),
  and its issue **ai-dynamo/nixl#2266**

Those two are a **matched pair**: nixl#2271 changes the raise into a `None`, and vllm#57734 then
handles that `None`. Together they fix it properly, and I'd consider that the better long-term
shape.

**The gap this addresses:** vllm#57734 adds `if res is None: return` inside `record_transfer`
(`nixl/stats.py`). That handles the `None` return **but not a raised exception**. Against NIXL as
shipped today — which raises rather than returning `None` — the guard is never reached, because
`get_xfer_telemetry()` raises before `record_transfer()` is called. vllm#57734 alone therefore does
not fix the failure above. It takes effect once nixl#2271 lands *and* users upgrade their NIXL wheel.

So this PR is complementary rather than competing:

- it guards the **exception** path, which is what current released NIXL actually does
- it is **version-independent** — no NIXL upgrade required
- it keeps working as defense-in-depth after nixl#2271 ships

**I am happy to close this** if maintainers would rather land nixl#2271 + vllm#57734 and require a
NIXL upgrade, or to reduce it to just the `base_worker.py` hunk if the OBJ-tier change is
unwelcome. Equally happy to fold the exception guard into #57734 instead, if its author prefers.

## Changes

- `nixl/base_worker.py`: extract `_try_get_xfer_telemetry()`, which returns `None` and
  `warning_once`s instead of raising; skip the stats sample when telemetry is unavailable. The
  transfer is released and counted as DONE either way.
- `v1/kv_offload/tiering/obj/manager.py`: same guard. There the call sits **outside** any `try`, so
  it would propagate rather than be misclassified.

No behaviour change for backends that do provide telemetry.

## Test Plan

- Reproduced on DeepSeek-V4.1-Flash, 2P1D disaggregated, UCX backend, `nixl-cu13==1.4.1`.
- Before: 100% request failure, 17,960 failed transfers.
- After: 0 failed transfers; full benchmark 3526 valid / 15 errors; a 60k-token prompt streams
  content.

### Unit tests

`tests/v1/kv_connector/unit/test_nixl_connector.py`:

- `test_telemetry_exception_does_not_fail_completed_transfer` — `get_xfer_telemetry` raises on a
  `DONE` handle. Asserts the request lands in `done_req_ids` and not `failed_req_ids`, that the
  handle is still released, that `_log_failure` is not called, and that no `num_failed_transfers`
  sample is recorded. Fails on `main` without this patch.
- `test_telemetry_still_recorded_when_available` — pins the no-change case: when telemetry works,
  all four stats fields are recorded exactly as before.

`tests/v1/kv_offload/tiering/test_obj_tier.py`:

- `test_telemetry_failure_does_not_lose_successful_transfer` — a raising `get_xfer_telemetry` must
  still yield `JobResult(success=True)` with `transfer_time is None`. Only the timing is lost.

These sit beside the existing `test_post_transfer_cleanup_failure_does_not_lose_result` and
`test_release_xfer_failure_retries_without_losing_result`, which cover the same shape for the other
post-transfer cleanup calls.
