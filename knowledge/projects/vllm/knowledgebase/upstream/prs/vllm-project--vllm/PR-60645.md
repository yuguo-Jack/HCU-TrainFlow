# [ROCm][Perf] Make AITER FlyDSL GDN prefill default on gfx942/gfx950

[Upstream PR](https://github.com/vllm-project/vllm/pull/60645) · state: closed · merged: True

## Original PR description

## Overview

Under `--gdn-prefill-backend auto`, use the AITER FlyDSL GDN prefill backend from #57560 on gfx942 and gfx950, as agreed in that PR's review. It applies only to BF16 models with 128-dim linear-attention heads, and only when AITER is enabled and the build ships the FlyDSL kernels. Not a duplicate: `gh pr list --state open --search "gdn prefill flydsl"` finds no other PR that changes the default; #57560 added the opt-in backend, and #60659 changes the prefill kernels' internals, not which backend `auto` picks.

## Claims

* Lower time to first token by default for GDN models on MI300X and MI355X: −2.7% geomean on Qwen3-Next-80B (MI300X), −3.6% on Qwen3.8-2.4T (MI355X). Decode is unchanged.
* GSM8K is unchanged on Qwen3-Next (0.9606 → 0.9606).
* Anything FlyDSL cannot serve (other architecture, missing kernels, other head dims or dtype) stays on Triton/FLA under `auto`. `--gdn-prefill-backend triton` opts out.

## Validation

```bash
VLLM_ROCM_USE_AITER=1 pytest tests/v1/attention/test_gdn_aiter_flydsl.py tests/kernels/mamba/test_gdn_rocm_layout_dispatch.py
```

The new `test_auto_defaults_to_aiter_flydsl` fails against the old resolver and passes with this change. In a ROCm container without a GPU, `tests/v1/attention/test_gdn_aiter_flydsl.py` gives 12 passed, 2 skipped. The two skips are the on-device FlyDSL-vs-Triton numerics test from #57560, which this PR does not change. `ruff check` and `ruff format` (0.14.0) pass.

TTFT with FlyDSL (default) vs Triton, from this PR's earlier run and the opt-in runs in #57560:

| Hardware | Model | Mean TTFT | Accuracy, Triton → FlyDSL |
| --- | --- | --- | --- |
| MI300X, TP2 | `Qwen/Qwen3-Next-80B-A3B-Instruct` | −2.7% geomean over 4 points, ISL/OSL 8k/1k at c=4/16/64 and 60k/600 at c=4 | GSM8K flexible-extract 0.9606 → 0.9606 (8 fixed, 8 broken, McNemar p = 1.00) |
| MI355X, TP8 | `amd/Qwen3.8-2.4T-A95B-Quark-MXFP4` | −3.6% median geomean over 16 cells | GPQA-Diamond 0.9192 → 0.9343; GSM8K 0.9787 → 0.9825 |
| MI300X, TP2 | `Qwen/Qwen3.8-Flash-Next-FP8` | −1.9% geomean over 4 cells | GSM8K 0.9697 → 0.9712 |

## Details

One new `auto` branch in `_resolve_gdn_prefill_backend` returns `aiter_flydsl` when `on_mi3xx()` and the same conditions an explicit request must meet hold. Those conditions now live in one helper, `_aiter_flydsl_unsupported_reasons`. An explicit request still raises when the kernels are missing, and warns before falling back to Triton/FLA when the model is outside the gate. `test_gdn_rocm_layout_dispatch.py` pins `triton`, since it checks the Triton path and `auto` would now route it to FlyDSL.

The gain depends on the model: about −1% TTFT on Qwen3.8-Flash-Next, against −3.6% on Qwen3.8-2.4T.
