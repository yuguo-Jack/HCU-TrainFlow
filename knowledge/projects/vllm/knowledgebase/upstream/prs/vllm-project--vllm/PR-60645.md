# [ROCm][Perf] Make AITER FlyDSL GDN prefill default on gfx942/gfx950

[Upstream PR](https://github.com/vllm-project/vllm/pull/60645) · state: open · merged: False

## Original PR description

## Overview

Makes the AITER FlyDSL GDN prefill backend added in #57560 the default under `--gdn-prefill-backend auto` on ROCm gfx942 and gfx950, as discussed in that PR's review. It applies only to BF16 models with 128-dim linear-attention heads, and only when AITER is enabled and the build ships the FlyDSL kernels.

## Claims

* Lower time to first token by default on MI300X and MI355X for GDN models: −2.7% geomean on Qwen3-Next-80B (MI300X), −3.6% on Qwen3.8-2.4T (MI355X), about −1% to −2% on Qwen3.8-Flash-Next (both). Decode throughput is unchanged.
* No accuracy change: GSM8K is identical on Qwen3-Next, and GSM8K and GPQA-Diamond were within noise in #57560.
* Fails safe. Any model, dtype, architecture or AITER build that FlyDSL cannot serve stays on Triton/FLA under `auto`, without a warning. An explicit `aiter_flydsl` request raises if the kernels are missing and otherwise warns before falling back to Triton/FLA, and `--gdn-prefill-backend triton` opts out.

## Details

The change is one branch in `_resolve_gdn_prefill_backend`. When the user requests `auto` on ROCm, it returns `aiter_flydsl` under the same conditions an explicit request already has to meet, plus a gfx942/gfx950 check. Those conditions are BF16 activations, `head_k_dim == head_v_dim == 128`, and `rocm_aiter_ops.is_gdn_flydsl_prefill_available()`, which also honors `VLLM_ROCM_USE_AITER`.

* **Silent fallback under `auto`.** An explicit `aiter_flydsl` request raises when the kernels are missing and warns when the model is outside the gate, so a run never reports FlyDSL while running Triton. Under `auto` the user asked for nothing in particular, so a model outside the gate simply keeps today's backend.
* **Architecture allowlist.** FlyDSL has been validated only on gfx942 and gfx950, so other ROCm architectures such as gfx90a keep Triton/FLA.
* **Affected models.** In-tree, the gate admits the Qwen3-Next, Qwen3.5 and Qwen3.8 GDN layers. 
* **Test pin.** `tests/kernels/mamba/test_gdn_rocm_layout_dispatch.py` now pins `gdn_prefill_backend=triton`. It checks the Triton path's numerics and output layout, and `auto` would otherwise route it to FlyDSL on gfx942/gfx950.
* **Limitation.** The size of the gain depends on the model: about −1% TTFT on Qwen3.8-Flash-Next against −3.6% on Qwen3.8-2.4T. Further FlyDSL kernel work is in progress in ROCm/aiter#5732.
