# [Bugfix] Default Gemma3 Model intermediate_tensors to None

[Upstream PR](https://github.com/vllm-project/vllm/pull/50777) · state: closed · merged: True

## Original PR description

## Purpose

Currently `Gemma3Model.forward` declares `intermediate_tensors` as a required positional parameter:

```python
intermediate_tensors: IntermediateTensors | None,   # no default
```

Every other pooling-capable model defaults it, e.g. `BertModel`:

```python
intermediate_tensors: IntermediateTensors | None = None,
```

Callers that never produce intermediate tensors, for instance the pooling path, omit the argument. Binding the compiled forward then fails at engine start:

```text
File "vllm/v1/worker/gpu/cudagraph_utils.py", line 530, in forward_fn
    f_locals.update(bind_locals(self._artifacts.signature, *args, **kwargs))
TypeError: missing a required argument: 'intermediate_tensors'
```

This makes the model unusable for pooling.

## How it was found

Surfaced by CI on #48290, which defaults encoder-only pooling models to Model Runner V2. `embeddinggemma-300m` resolves to `attn_type=encoder_only`, so it moved onto the V2 path and failed at engine init in `Language Models Test (MTEB)` (`test_st_projector.py::test_embed_models_mteb`).

The fix is to make Gemma3 consistent with the convention such as the BERT encoder model.

This is a prerequisite for landing #48290: without it, that PR turns the MTEB job red.

## Test plan

Before the fix, loading the model for pooling on V2 raised the `TypeError` above at engine init. After:

```bash
VLLM_USE_V2_MODEL_RUNNER=1 python -c "
from vllm import LLM
llm = LLM(model='google/embeddinggemma-300m', runner='pooling', max_model_len=512)
print(llm.embed(['hello world'])[0].outputs.embedding.__len__())
"
```

```text
ENGINE_STARTED_OK use_v2= True
EMBED_OK dim= 768
```

Generation regression check (`intermediate_tensors` is load-bearing for pipeline parallelism):

```bash
pytest -q tests/models/language/generation/test_gemma.py
```

`1 failed, 2 passed`. The failure is `test_dummy_loader[google/gemma-3-4b-it]`, which fails identically with this change reverted, therefore, pre-existing and unrelated.

`pre-commit run --files vllm/model_executor/models/gemma3.py` passes.
