# [MRV2][Sampler] Warm up seeded native top-k/top-p without PP deadlock (#54425, #62129)

[Upstream PR](https://github.com/vllm-project/vllm/pull/54630) · state: open · merged: False

## Original PR description

### Purpose
Fixes #54425.
Addresses the remaining seeded native sampling warmup gap from #54425 while aligning with #62129 to prevent pipeline parallel deadlocks.

### Problem
1. **Unwarmed Fallback Kernels (#54425)**: Under V1 with fused sampling enabled (`sampler.use_flashinfer` or `sampler.use_xpu_sampler`), `warmup_kernels()` only exercises default unseeded `SamplingParams`. Requests with an explicit `seed` bypass fused sampling (`fused_sampler_eligible` is False) and fall back to PyTorch-native top-k/top-p and Gumbel sampling. This causes JIT compilation and memory allocation latency spikes on the first seeded request.
2. **PP Rank Asymmetry (#62129)**: Under pipeline parallelism (`PP > 1`), `self.sampler` is initialized strictly on the last PP rank. Non-last ranks have `self.sampler = None`. Gating the warmup pass purely on rank-local `sampler is not None` causes non-last ranks to skip the pass while the last rank attempts to receive activations, deadlocking the engine on startup.

### Solution
- **Symmetric Warmup Pass**: Add a dedicated `seeded=True` warmup pass in `warmup_kernels()` that gates on `flashinfer_sampler_supported()` / `xpu_sampler_supported()` when `sampler is None`. All PP ranks execute the same forward passes in lockstep, eliminating startup deadlocks. Unfused configurations skip this pass with zero overhead.
- **Tests**:
  - `tests/v1/worker/test_mixed_warmup_gate.py`: Parameterized across `is_last_pp_rank: [False, True]` and `fused_backend: ["flashinfer", "xpu", None]` to assert all PP ranks stay in sync.
  - `tests/v1/worker/test_gpu_sampler_flags.py`: Verifies `any_explicit_seed()` evaluates correctly on GPU and resets on slot reuse.

### Verification
- Replicated pipeline parallel execution and verified the pre-fix deadlock and post-fix lockstep completion.
- Tested on NVIDIA A100: confirmed seeded requests fall back to native kernels cleanly without latency spikes.
- Pre-commit checks pass cleanly (`ruff check`, `ruff format`).
