# [KV Connector] Stop mutating the prefill payload after it has been sent

[Upstream PR](https://github.com/vllm-project/vllm/pull/59351) · state: open · merged: False

## Original PR description

## Purpose

`send_request_to_service` in the NIXL toy proxy prepares the request for the
prefill instance, sends it, and then writes two keys back into the payload it
just sent:

```python
req_data = req_data.copy()
...
min_tokens = req_data.pop("min_tokens", None)
min_completion_tokens = req_data.pop("min_completion_tokens", None)
...
response = await client_info["client"].post(endpoint, json=req_data, headers=headers)
...
# Add back the min_tokens and min_completion_tokens so D can use them
req_data["min_tokens"] = min_tokens
req_data["min_completion_tokens"] = min_completion_tokens
```

The write happens after the payload has been handed to the transport and the
local copy is never read again, so it cannot change what P receives. What it
does do is leave the object in a state that contradicts what was sent: the
object is reachable by the caller of the transport, so anything inspecting it
afterwards sees `min_tokens=10` sitting next to `max_tokens=1` - a combination
the prefill instance would reject. Any retry, or a transport that defers
serialisation (e.g. `client.stream(..., json=payload)`), would then ship an
invalid request to P.

The comment is also misleading. The decode leg does need `min_tokens`, but it
does not get it from this write: because the rewrite happens on a copy of the
caller's dict, the caller still holds the original values and builds the D
request from those. Removing the write therefore cannot regress D.

This is deliberately narrower than the earlier revert attempt (#40138, closed):
that one also removed the `pop`, which would have sent `min_tokens` to P again.
Here P still never sees the key - only the write into the already-sent object
goes away.

## What changed

* the post-send write-back is deleted and the two `pop` calls no longer bind
  unused locals, with a comment that states which side of the copy each consumer
  reads from.

## Test Plan

`tests/v1/kv_connector/unit/test_toy_proxy_server_request_args.py` drives
`send_request_to_service` with a client that records the payload it is given,
and pins both halves of the contract:

* the payload handed to P is a valid single-token request: `max_tokens == 1`,
  `stream is False`, no `stream_options`, and no `min_tokens` /
  `min_completion_tokens` (`SamplingParams` rejects `min_tokens > max_tokens`);
* the caller's payload still carries `min_tokens` for the decode leg.

```bash
python -m pytest tests/v1/kv_connector/unit/test_toy_proxy_server_request_args.py -q
```
