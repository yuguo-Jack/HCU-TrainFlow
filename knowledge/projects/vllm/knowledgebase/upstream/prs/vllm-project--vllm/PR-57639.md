# [Bugfix] Skip FP8-dequant fast paths for PP-missing layers in GLM-5.3-Flash load

[Upstream PR](https://github.com/vllm-project/vllm/pull/57639) · state: open · merged: False

## Original PR description

## Purpose

Fixes #55725. GLM-5.3-Flash crashes at weight load on multi-node (2×8 H100) with `KeyError: 'layers.11.self_attn.fused_qkv_a_proj.weight'` on every second-node worker, while single-node runs fine.

## Root cause

With 2 nodes the run is pipeline-parallel (PP=2), so layer 11's params exist only on stage-0 ranks. The attached log (`layer11.log`) shows all `Worker_PP1_TP0..7` crashing; PP0 is clean. The normal load path guards every weight with `is_pp_missing_parameter` (glm5next/common/model.py), but the two FP8-dequant fast paths bypass it and index `params_dict` directly:

- `_try_load_fp8_attn_proj` → `params_dict[target_w]` (the traceback in the issue)
- `_try_load_fp8_indexer_wk` → `params_dict[fused_name]` (same class of hole)

On a PP rank that doesn't hold the layer, `params_dict` has no such key → KeyError before the normal path ever gets a chance to skip the weight.

## Fix

In both fast paths, return `False` when the target param is absent from `params_dict`, so the weight falls through to the normal path, which skips it via `is_pp_missing_parameter`. The indexer-wk guard is placed *before* buffering, so PP ranks also don't accumulate fp8 tensors that nobody loads. Behavior on ranks that hold the layer is byte-identical.

## Verification

No multi-node GPU here, so verified by driving both functions directly with the exact crashing weight names, on the MI350X pod against the patched module:

| Case | Result |
|---|---|
| PP1-style params_dict (layer 11 absent), fp8 `q_a_proj` weight + scale | not consumed, nothing loaded → falls to normal skip path (was: KeyError) |
| PP0-style control (BF16 `fused_qkv_a_proj` present) | consumed + loaded, unchanged |
| PP1, indexer `wk` weight + scale | not consumed → normal skip |
| PP0 control, indexer `wk` | consumed + loaded, unchanged |

Pre-commit: all hooks pass. Single-node (TP-only) behavior is untouched — the guards only trigger when the target param is missing.
