# [Bugfix][Frontend] Forward --enable-log-outputs to the Anthropic handler

[Upstream PR](https://github.com/vllm-project/vllm/pull/60982) · state: closed · merged: True

## Original PR description

## Purpose

Fixes #60971. `--enable-log-outputs` (and `--enable-log-deltas`) were accepted as server-wide flags but never forwarded to the Anthropic `/v1/messages` handler, so output logging stayed at its parent defaults there even though `create_messages` reuses the shared `create_chat_completion` implementation where the logging is gated on `self.enable_log_outputs`.

Two changes:

- `AnthropicServingMessages.__init__` now accepts `enable_log_outputs` / `enable_log_deltas` (defaults matching the parent: `False` / `True`) and forwards both to `OpenAIServingChat.__init__`.
- `init_generate_state` passes `args.enable_log_outputs` / `args.enable_log_deltas` when constructing the handler, same as the adjacent Chat Completions setup.

## Why this is not duplicating existing work

The issue (filed today) has no linked PR. Searched open PRs for `60971` and for `enable_log_outputs anthropic`; nothing open or merged touches the Anthropic handler's flag wiring.

## Test plan

Tests removed per maintainer review; the change is constructor-level flag forwarding only, covered by CI.
