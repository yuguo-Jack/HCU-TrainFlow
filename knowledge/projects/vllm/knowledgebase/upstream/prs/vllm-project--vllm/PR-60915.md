# [Frontend] generate: packed top-k logprobs (return_top_k_logprobs)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60915) · state: open · merged: False

## Original PR description

## Overview

Adds `return_top_k_logprobs` to `/inference/v1/generate`: top-k output logprobs as one packed base64 block per choice instead of per-token JSON objects. Part of RFC #57479.

> **Draft, stacked on #60542** (numpy-backed `FlatLogprobs` + fast default render), now rebased on current main. Only the last commit, "packed top-k logprobs (return_top_k_logprobs)", is new here. The Rust frontend counterpart is #60916.
>
> **No longer depends on #57442** (`return_token_logprobs`). The cherry-pick is gone, and this PR returns `top_k` only. Returning `sampled` alongside `top_k` is left for after #57442 lands. I placed the new code so that applying #57442 on top only conflicts where both change the same lines: the `GenerateLogProbs` field next to `content`, the `logprobs_render` import and the logprobs branch in `_build_full_response`.

## Claims

- New request flag `return_top_k_logprobs`. With `sampling_params.logprobs = k >= 1`, each choice's `logprobs` is `{"content": null, "top_k": {...}}`:
  ```python
  class PackedTopK(BaseModel):
      num_positions: int
      k: int
      token_ids: str  # base64, little-endian int32, num_positions x k (engine slots 1..k)
      logprobs: str   # base64, little-endian float32, num_positions x k (raw values)
  ```
- `stream=true`, `output_mode="text"` and `logprobs` absent, 0 or −1 with the flag return 400.
- Responses without the flag are byte-for-byte unchanged. `top_k` is omitted unless requested.

## Validation

```bash
pytest tests/entrypoints/scale_out/token_in_token_out/ tests/test_logprobs.py tests/test_outputs.py \
       tests/v1/engine/test_logprobs_processor.py tests/v1/test_outputs.py
```
Result after the rebase on GB200: 258 passed, 0 failed, including the live-server tests in `test_serving_tokens.py` (the run covered all of `tests/entrypoints/scale_out/token_in_token_out/` plus `tests/test_logprobs.py`, `tests/test_outputs.py`, `tests/v1/engine/test_logprobs_processor.py` and `tests/v1/test_outputs.py`). `pre-commit` is clean on the changed files.

New tests (in `test_logprobs_render.py`):
- the spliced body equals what `JSONResponse` gives for the same values, across k and position counts;
- decoded `top_k` matches the `content` entries rendered from the same rows;
- the 400 cases;
- responses without the flag keep their schema and bytes.

**Default path unaffected by this branch.** Before this rebase, the #60542 CPU benchmark (12.5k tokens × top-128, through `LogprobsProcessor` and `_build_full_response`) gave the same numbers on this branch as on #60542 alone: 4.4 µs ingest per engine row, 10.6 stored bytes per entry, 0.41 s response build, 181 MiB build peak, and an identical body hash. See #60542 for the end-to-end abort results of the default render (`/pause?mode=abort` about 0.4 s vs 92 s on main).

**Packed top-k performance (prototype, not yet rerun on this rebase).** On the earlier compact-format prototype, an RL `pause(mode="abort")` with 245,760 output tokens at top-128 produced about 2.2 GB per response in per-token form and 337 MB as the packed block. On DP8 with 32 such requests, the Python frontend went from about 21 s to about 1.8 s. I'll rerun this end to end on this branch before marking it ready.

## Details

- **Rendering.** The block is built from `FlatLogprobs.rows()` (#60542). Rows that don't fit the packed shape (irregular widths, ids beyond int32) return a 500 rather than a silently different layout. It's one base64 pass over `arrays[:, 1:]` per choice, spliced into the rendered body. There's no per-token Python object and no `model_dump()`.
- **Separate from `return_token_logprobs`.** The flag is independent so #57442 can land unchanged. A single logprobs-options design can follow.
- **Encoding.** Raw little-endian arrays rather than `.npy` (which `routed_experts` uses): there's no header, the Rust writer can stream it in segments, and `num_positions` / `k` already give the shape. Happy to switch to `.npy` for consistency.

**Not a duplicate.** #57442 adds only the `k = 0` sampled-token path, and this PR doesn't include it. #60789 replays logprobs through the AuxOutput connector, a side channel rather than the HTTP response. No open PR returns packed top-k logprobs on this endpoint (`gh pr list --state open --search "57479 in:body"` and `"top_k logprobs generate"`).
