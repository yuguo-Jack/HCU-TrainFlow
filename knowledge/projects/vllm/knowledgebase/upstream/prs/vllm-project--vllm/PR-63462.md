# [CI][Bench] Keep captured request headers case-insensitive in Responses test

[Upstream PR](https://github.com/vllm-project/vllm/pull/63462) · state: closed · merged: True

## Original PR description

## Purpose

Fix the `Benchmarks CLI` failure on main, on both H200 and MI355. It has failed deterministically since #62835 bumped aiohttp to 3.14.5, multidict to 7.1.0 and yarl to 1.25.1:

```
FAILED benchmarks/test_responses_request_func.py::test_request_payload_is_accepted_by_the_server_schema
    assert seen["headers"]["x-request-id"] == "bench-7"
KeyError: 'x-request-id'
```

**Root cause:** the test's aiohttp handler copies `request.headers`, a case-insensitive `CIMultiDictProxy`, into a plain `dict`, then looks keys up case-sensitively. With the new versions, the client sends the well-known header as `X-Request-ID`. A minimal aiohttp server and client, with no vLLM involved, shows the change:

| aiohttp / multidict | Header keys the server sees |
|---|---|
| 3.14.3 / 6.7.1 | `Content-Type`, `x-request-id`, `x-team` |
| 3.14.5 / 7.1.0 | `Content-Type`, `X-Request-ID`, `x-team` |

HTTP header names are case-insensitive, so the benchmark code itself is correct.

**Fix:** keep the headers case-insensitive with `request.headers.copy()`, which returns a `CIMultiDict`. The existing assertions are unchanged.

**Not a duplicate:** no open PR touches this test.

## Test Plan

- Ran the same capture-and-lookup with `.copy()` under both version sets: all three lookups (`x-request-id`, `Content-Type`, `x-team`) succeed on 3.14.3/6.7.1 and on 3.14.5/7.1.0.
- `Benchmarks CLI` CI will confirm the full test.
