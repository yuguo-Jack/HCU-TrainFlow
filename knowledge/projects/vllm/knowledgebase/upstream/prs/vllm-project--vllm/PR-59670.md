# [Core][KVConnector] Don't wait on retained KV exports during cache-preserving keep pauses

[Upstream PR](https://github.com/vllm-project/vllm/pull/59670) · state: open · merged: False

## Original PR description

> [!NOTE]
> Moved from #58041 (originally by @S1ro1), which now carries only the HiSparse split-read fix. This PR is the general P/D part: it changes core pause semantics and needs a maintainer decision.

## Purpose

`pause(mode="keep", clear_cache=False)` on a NIXL producer can wait minutes during P/D weight updates even after model execution has stopped. Finished prefill requests whose KV the connector retains for a remote reader keep the engine active until the reader acknowledges or the lease expires. In a producer-first pause, a loaded decoder keeps renewing those leases for requests it hasn't read yet; @S1ro1 measured pauses over 60 s. The delayed-free gate already existed in v0.27; this is not a regression.

Related work: #51371 prioritizes KV work while unpaused; #57810 adds an opt-out from clearing the external offload tier during pause/sleep. Neither addresses pause completion with retained exports.

## Changes

- A keep pause that preserves the cache delivers newly finished request events, then leaves connector-retained blocks allocated across the pause instead of waiting for passive leases. Cleanup resumes after resume. Active push work and device synchronization still drain.
- Cache-clearing pauses keep the existing gate (`_reset_caches()` needs the blocks released), and `release_kv_cache_memory()` rejects retained KV.
- The engine sets the flag through a new optional `SchedulerInterface.set_preserve_paused_kv()` (no-op default), so `set_pause_state()` keeps its signature for out-of-tree schedulers. Any pause-state change clears it.

Open question: `POST /pause?mode=keep` defaults `clear_cache=true` (documented as ignored for keep), so the preserving path only engages when callers pass `clear_cache=false`.

## Test Plan

- `tests/v1/core/test_scheduler.py -k "delayed_kv_connector_free_keeps_scheduler_active"`: retained KV keeps the scheduler active except during a preserving pause, and a pause-state change ends the preservation.
- `tests/v1/engine/test_engine_core.py -k "kv_cache_release_rejects or pause_synchronizes"`: memory release rejects retained KV; the preserving pause synchronizes the device without resetting caches. (CUDA-gated module; run on CPU with the module skip removed.)

## Test Result

- Scheduler/connector lifecycle tests: 215 passed (CPU). Engine pause tests: 8 passed.
- Live validation by @S1ro1 (GLM-5.3 B300 RL, 2P+1D, DPEP8 per replica, NIXL + HiSparse + MooncakeStore, 2,048 concurrent rollouts): five trainer updates with natural pauses of 1.904 s, 2.647 s, 4.085 s, 3.860 s and 2.833 s; every weight update resumed; trainer mismatch KL 0.0218–0.0261. This used an equivalent Prime-RL runtime hook over the existing wheel together with a receive-side fix (now #58041), not a build of this branch. A receive-only patch still produced a 120 s loaded pause.
