# [Bugfix][V1] Keep the executor wakeable after a failed sleep

[Upstream PR](https://github.com/vllm-project/vllm/pull/63546) · state: open · merged: False

## Original PR description

## Overview

If a worker releases its memory and then raises during `sleep()`, the executor never records the sleep. A later `wake_up()` then returns without restoring worker memory, and the engine resumes scheduling on released memory. This PR records the sleep tags even when the sleep RPC fails. Split out of #58279 and fixes part of #58242

## Claims

- After a failed `sleep()`, `wake_up()` restores the worker memory before scheduling resumes, so the engine keeps serving instead of crashing.
- A successful sleep behaves exactly as before.

## Validation

New regression test through `LLM`: `tests/basic_correctness/memory/sleep_mode/test_sleep_mode.py::test_wake_up_after_failed_sleep`. It wraps the worker's `sleep` so the wrapper raises after the real sleep has released memory.

## Details

`Worker.sleep()` can fail after `sleep_mode_backend.suspend()` has already released memory, for example from `assert freed_bytes >= 0` or from `suspend_device_comms()`. With TP > 1, one rank can also sleep successfully while another rank fails. In both cases, `Executor.sleep()` skipped `self.sleeping_tags |= SLEEP_TAGS`. As a result, `Executor.wake_up()` logged "Executor is not sleeping." and never sent `wake_up` to the workers, and `EngineCore.wake_up()` resumed the scheduler.

The fix sets the tags in a `finally`. If the failure happened before any memory was released, the next `wake_up()` is still safe, because `CuMemAllocator.wake_up()` skips allocations that are not asleep.

Related: #59130 (draft) adds sleep-state telemetry for failed transitions. This PR only fixes recovery and does not depend on it. No open or closed PR records sleep state on failure.
