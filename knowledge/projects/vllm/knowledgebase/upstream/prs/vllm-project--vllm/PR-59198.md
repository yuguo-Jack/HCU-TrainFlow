# [Build] keep CUDA PyTorch wheels aligned with image

[Upstream PR](https://github.com/vllm-project/vllm/pull/59198) · state: closed · merged: True

## Original PR description

## Summary

Fix stable CUDA Docker dependency resolution so the CUDA-specific PyTorch index is authoritative for PyTorch packages.

The Dockerfile previously passed the CUDA index as an extra index while the environment used `unsafe-best-match`. In a `cu129` build, that allowed dependency resolution to select a higher preinstalled Torch build from another source, producing the reported `torch 2.14.0+cu130` / `torchvision 0.28.0+cu129` mismatch and breaking `import torchvision`.

Stable CUDA install stages now use the CUDA index as the primary index, PyPI as the fallback for non-PyTorch packages, and `unsafe-first-match` so package resolution cannot silently substitute a different CUDA build. The change is applied consistently to base, build, test/dev, runtime, vLLM wheel, and extension install stages.

## Validation

- `git diff --check` passes.
- Resolved the CUDA requirements with uv's stable-index configuration for a Linux manylinux target; local execution of the full image is unavailable because the Docker daemon is not running.

Fixes #59157
