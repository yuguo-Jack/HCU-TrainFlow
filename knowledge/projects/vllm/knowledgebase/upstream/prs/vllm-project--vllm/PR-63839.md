# [Spec Decode] Add a decode-request floor for adaptive verification

[Upstream PR](https://github.com/vllm-project/vllm/pull/63839) · state: open · merged: False

## Original PR description

## Overview

Add `adaptive_verification_floor` to speculative decoding: verify every scheduled
draft when the number of requests with scheduled drafts is at or below the floor.
This gives deployments a fixed-verification regime at low concurrency when
adaptive budgeting varies with the cost profile or acceptance estimates.

## Claims

- Nonnegative integer, default `0` (disabled). For example, add
  `"enable_adaptive_verification": true, "adaptive_verification_floor": 8`
  to an existing speculative config to retain all scheduled drafts at up to
  eight requests with scheduled drafts.
- Requests without scheduled drafts, including draftless decodes, do not count.
  Above the threshold,
  normal adaptive selection applies. The existing logits-memory cap still applies.
- No new device synchronization, kernels, or changes to the default behavior.

## Details

The manager counts requests with scheduled drafts and selects the maximum safe
draft budget at or below the floor, skipping confidence/cost estimates and
reusing the common budget bookkeeping. Existing compaction and reallocation handle that budget. The floor may
increase verification work for low-acceptance drafts; it does not increase the
number of drafts scheduled or override memory limits. With floor 2, two drafting
requests plus a draftless decode now retain all scheduled drafts, subject to
the memory cap; the earlier implementation applied adaptive scoring in this case.

Open upstream PR searches for adaptive verification and adaptive/floor found no
matching configurable decode-count floor. Related suffix-decoding PR
https://github.com/vllm-project/vllm/pull/60339 mentions low-concurrency trimming
but implements a different drafter. The author reviewed the fork PR before
requesting this upstream submission. Codex assisted with implementation,
documentation, and validation.

Developed and validated from upstream `a0544b13f2ee6424d3aa6d03a00e1c745218dee9`.
