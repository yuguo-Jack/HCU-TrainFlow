# [Bugfix][EC Connector] Make control-plane ZMQ heartbeats take effect

[Upstream PR](https://github.com/vllm-project/vllm/pull/65593) · state: open · merged: False

## Original PR description



## Overview

The EC CPU connector's consumer sets ZMTP heartbeats on its DEALER only after `make_zmq_socket` has connected it, so libzmq never runs them. A producer that freezes or becomes unreachable is therefore never reported to `_on_peer_down`. This PR sets the options before the socket connects.

## Claims

- A producer that stops responding without closing TCP (frozen, host down, network partition) is reported within `HEARTBEAT_IVL + HEARTBEAT_TIMEOUT` = 6 s. On main it is never reported.
- A killed producer was already reported, because TCP closes. A busy producer is not reported.
- No new option, and `make_zmq_socket` is unchanged.

## Validation

**New test** `test_control.py::test_zmq_client_transport_reports_frozen_peer`: a subprocess runs a ZMQ ROUTER that takes one request and never replies. The test connects through `ZmqClientTransport`, sends a request, `SIGSTOP`s the subprocess, and waits 5 s for `poll_dead()`. Heartbeats are patched to 100 ms / 500 ms.

```
pytest tests/v1/ec_connector/unit/test_control.py -k frozen
main:     FAILED  AssertionError: frozen producer never reported
this PR:  1 passed in 0.8 s (5/5 runs)
```

**Real constants** (2 s / 4 s), same setup:

| Producer | main | this PR |
|---|---|---|
| `SIGSTOP` | no event in 11 s | reported after 6.00 s |
| Pure-Python loop holding the GIL for 12 s | no event | no event |

**EC unit tests** in a Linux CPU container: `pytest tests/v1/ec_connector/unit` gives 406 passed on main and 407 passed with this PR, with 36 skipped on both. The extra pass is the new test. Two `test_ec_transfer_params.py` cases time out on both because the container cannot reach the Hugging Face Hub. With Hub access they pass on both. `pre-commit` passes.

The new test is marked `cpu_test`, so the CPU "V1 Others" step runs it. The rest of `test_control.py` runs only in the V1 KV Connectors step, which is disabled.

## Details

**Root cause:** `ZmqClientTransport.connect()` calls `make_zmq_socket(..., bind=False)`, which connects, and only then sets `HEARTBEAT_IVL`, `HEARTBEAT_TIMEOUT` and `HEARTBEAT_TTL`. libzmq copies socket options into a connection when it is created, and most options affect only later `bind()`/`connect()` calls (see `zmq_setsockopt`). The connection therefore runs without heartbeats, and the `EVENT_DISCONNECTED` monitor fires only when TCP closes.

**Fix:** set the three options as defaults on the transport's own `zmq.Context`. pyzmq applies context defaults when `make_zmq_socket` creates the socket, before it connects. This keeps `make_zmq_socket`'s other DEALER settings and leaves its signature alone. #65575 fixes the same pitfall for the Mooncake KV connector by adding heartbeat arguments to `make_zmq_socket`.

No open PR touches `ec_connector/cpu/control/zmq.py`. I searched open PRs for EC connector, heartbeat, and `ec_connector/cpu`.
