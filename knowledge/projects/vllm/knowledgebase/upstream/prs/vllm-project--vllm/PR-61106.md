# [Test] Compare NVFP4 batch-invariance logprobs bitwise

[Upstream PR](https://github.com/vllm-project/vllm/pull/61106) · state: open · merged: False

## Original PR description

## Purpose

`tests/v1/determinism/test_nvfp4_batch_invariant.py::test_dense_nvfp4_generation_is_deterministic_across_batch_sizes_e2e` compares the needle prompt's logprobs across batch sizes with `torch.testing.assert_close(needle_logprobs, baseline_logprobs)`, i.e. with the default fp32 tolerances (`rtol=1.3e-6`, `atol=1e-5`). Batch invariance means bitwise-identical results, which is what every other test in `tests/v1/determinism/test_batch_invariance.py` checks with `torch.equal`. With the tolerance the NVFP4 test can pass while the NVFP4 GEMM is in fact batch dependent.

This PR replaces the comparison with `torch.equal` and prints both logprob lists on failure. No product code changes.

## Test Plan

- `tests/v1/determinism/test_nvfp4_batch_invariant.py` with the default model (`nm-testing/TinyLlama-1.1B-Chat-v1.0-NVFP4`), before and after the change, with the default settings and with `VLLM_NVFP4_NEEDLE_TRIALS=5 VLLM_NVFP4_NEEDLE_BATCH_SIZE=32`, on one GB300 (SM103) GPU.
- Supporting evidence that NVFP4 checkpoints are bitwise batch invariant on Blackwell with the current kernels: online bs=1-vs-batched logprob checks for `nvidia/Llama-3.1-8B-Instruct-FP4` and `nvidia/Qwen3-30B-A3B-FP4` at TP=1 and TP=4 on `main` (`d09ff77637`).
