# [Bugfix][HiSparse] Skip blocked requests in kv_holding_waiting to prevent host block deadlock

[Upstream PR](https://github.com/vllm-project/vllm/pull/62230) · state: open · merged: False

## Original PR description

## Purpose

Fixes #62217.

Under HiSparse full-ISL admission (`scheduler_reserve_full_isl`), admission reserves the request's full prompt against free host blocks at admission time, and only the imported prefix blocks are actually allocated while the async KV load is in flight:
1. Request `first` (4 blocks, 1 imported) is admitted against 4 usable host blocks (5 total including null block) and allocates 1 host block (leaving 3 free).
2. Request `second` (3 blocks, 1 imported) is also admitted because `3 <= 3` free host blocks, and allocates 1 host block (leaving 2 free).
3. Once both async loads finish, `first` at the head of `kv_holding_waiting` needs 3 more host blocks (cannot fit in 2 free), while `second` needs 2 more host blocks (can fit and finish).

Previously, when `allocate_slots` returned `None` for `first` in `kv_holding_waiting`, `Scheduler.schedule()` executed `break` instead of skipping `first` and continuing to inspect the rest of `kv_holding_waiting`, permanently stalling the scheduler with `running == []`.

Additionally, `test_hisparse_admitted_async_loads_can_finish_with_nothing_running` previously used `host_num_blocks=4`, which only admitted `first` (`admitted == {"first"}`) and rejected `second` at admission time rather than admitting both.

## Test Plan

- Updated `test_hisparse_admitted_async_loads_can_finish_with_nothing_running` in `tests/v1/core/test_prefix_caching.py` so both `first` and `second` are admitted (`assert admitted == {"first", "second"}`) and verified that `second` is scheduled and completes when `first` is blocked on host blocks.
- Ran `pytest tests/v1/core/test_prefix_caching.py tests/v1/kv_connector/unit/test_remote_prefill_lifecycle.py`.
