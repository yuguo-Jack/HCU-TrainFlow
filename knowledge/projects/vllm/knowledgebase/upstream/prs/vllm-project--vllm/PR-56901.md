# [CI] Split (H200 MIG 35GB / MI300) Multimodal Models (Extended Generation 1) into Audio, Vision and Omni jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/56901) · state: closed · merged: False

## Original PR description

## What

Group the Extended Generation 1 tests into `audio/`, `vision/` and `omni/` folders under `generation/`, and run each folder as its own named job instead of a three-replica `case` block. Every job keeps the original `-m 'not core_model'` selection and trigger paths.

## Old

```text
generation/
└── test_*.py                 # flat audio, vision and omni tests

one job, key multi-modal-models-extended-generation-1:
pytest generation -m 'not core_model' --ignore test_common.py; pytest test_mapping.py
```

## New

```text
generation/
├── audio/     # audioflamingo3, gemma_ragged_audio, granite_speech, moss_audio, transformers_audio, whisper
├── vision/    # keye, maverick, moondream3, nemotron_parse, phi4mm, phi4siglip, pixtral, vit_cudagraph
├── omni/      # ultravox, voxtral, voxtral_realtime
└── test_*.py  # core-only files owned by Standard jobs, plus test_moondream3_moe.py
```

| Job | Key | Commands |
| --- | --- | --- |
| `Extended Generation 1: Audio` | `multi-modal-models-extended-generation-1-audio` | `pytest generation/audio -m 'not core_model'` |
| `Extended Generation 1: Vision` | `multi-modal-models-extended-generation-1-vision` | main's `pytest generation -m 'not core_model' --ignore test_common.py`, now also ignoring the three folders; then spawn-mode `pytest generation/vision -m 'not core_model'` from the repo root |
| `Extended Generation 1: Omni + Mapping` | `multi-modal-models-extended-generation-1-omni` | `pytest generation/omni -m 'not core_model'`; `pytest test_mapping.py` |

The old key is referenced nowhere else. Each job shares the original `source_file_dependencies` through one anchor and has its own MI300 `mirror.amd` block.

## Notes

- **Root discovery is kept.** The Vision job's first command is main's `generation/` discovery command, with an `--ignore` added for each folder that now has its own job. A new non-core file added at the `generation/` root therefore still runs. Today that command picks up only `test_moondream3_moe.py`, a `cpu_test` that initializes a gloo group and so keeps its own process.
- Fixed `test_audioflamingo3.py`'s fixture path after the move: it now resolves to `tests/models/fixtures` again instead of silently skipping 2 tests.
- The vision folder keeps spawn mode from the repo root: `test_moondream3` holds a module-scoped in-process LLM, and an EngineCore forked after it hangs on startup. The legacy `test-amd.yaml` Extended Generation 1 copies still run the whole `generation/` tree in one command, so they need no change.
- `test_vit_cudagraph_image[deepseek_v41]` fails on `main`'s nightly (build 91173) and in this layout the same way, a GPU↔CPU sync assertion. It is a trunk failure, not caused by this PR. Stack: independent of #57065 (conflict only in Standard 4 paths); #57067 contains both. AI assistance was used.

## Expected runtime and overhead

Labelled predictions. Per-job times come from build 91132, whose Extended Generation 1 replicas ran exactly these three folders, compared with `main`'s nightly build 91173 (one job, 43.9m wall).

| --- | ---: | ---: | ---: | --- |
| Audio | ~16–19m | ~17–20m | ~1m | checkout + image pull |

Since this PR already owns the root files through the Omni + Mapping job, the suggestion below swaps the `test_mapping.py` command for a root sweep:

- `-maxdepth 1` picks up every root `test_*.py` and skips `generation/`, `standard/` etc., so no filename excludes are needed. After #57065 splits `test_mapping.py`, the sweep still picks up the root half.
- `sort` makes the run order the same on every host. Raw `find` order depends on each host's filesystem.
- `xargs -r` makes an empty match a no-op. Without it, `xargs` would run a bare `pytest` over all of `tests/`.
- `-m 'not core_model'` matches the other Extended commands. The one core test, `test_hf_model_weights_mapper`, keeps running in Standard 4's catch-all, so it isn't run twice.
- `check_test_tethering.py` parses this as `FindSelection(root='models/multimodal', max_depth=1)`. That covers the 7 root files and nothing under subdirs. `pre-commit` passes.

**Cost.** On one H200 with `main`'s CI image: 28 passed, 1 deselected, 14–23s of pytest and 25–48s wall. Today's `test_mapping.py` command takes 13s wall in [91287](https://buildkite.com/vllm/ci/builds/91287). So Omni + Mapping grows by under a minute, from about 10.0m. One process per file (`xargs -n1`) would take 97s, because every file pays about 12s of vLLM startup.

**Ordering.** Two of the six fail on `main`: `test_openpangu_vl` (a regression from #54142) and `test_mimo_v2_omni[2]` (a fixture scoping bug). The fix is in #58900. Please apply this suggestion after #58900 lands and you've merged `main`. Otherwise the nightly Omni + Mapping job will fail on those 3 cases.

**Anchor.** The second suggestion widens the shared dependency anchor to `tests/models/multimodal`, like the Standard jobs use, so the root files are included without a per-file entry. It doesn't change when the jobs run: `_step_should_run` in ci-infra returns before it reads `source_file_dependencies` for `optional: true` steps.

The Intel and legacy `test-amd.yaml` copies of Extended Generation 1 still run `test_mapping.py` only. I left them alone because `dist_init` picks NCCL on any non-CPU platform, so `test_aria` needs a check on XPU first.

## Follow-up recorded: Extended Generation 1 should be named jobs, not `case` routing

Noting this here so it isn't rediscovered. It is **not** a request to change this PR now — the sequencing below puts it after Standard 4 (#57067) lands.

### The `case` block is not justified

The three branches are already whole coverage units — `generation/audio`, `generation/vision`, and `generation/omni` plus the mapping unit tests. Parallel-index routing buys nothing over three named jobs:

- Branches 1 and 2 each need two pytest processes (moondream3_moe on its own, then vision under spawn; omni then mapping). That is not a constraint — a named job takes multiple commands.
- The key `multi-modal-models-extended-generation-1` is referenced nowhere else: no `depends_on`, no other consumer. Splitting it breaks nothing.
- Cost is +2 generated steps and +2 legacy steps per accelerator copy, the same shape as the Standard 4 split.

The benefit is the build timeline naming what ran. `Shard 1/2/3` hides that one replica is the audio suite and another is the vision suite; a failure currently needs a log to identify.

### Two separate defects, often conflated

1. **`case` routing where named jobs would do.** Reviewability only.
2. **`-m 'not core_model'` is a partition filter.** This is the more serious one: no job provably runs what a negated marker excludes, so the excluded cases are a coverage blind spot. It is load-bearing today because `generation/omni/test_ultravox.py` is still a mixed core/extended file — the only core-marked file inside this job's targets. #57066 split the other four mixed files (whisper, vit_cudagraph, voxtral, moss_audio) but left ultravox alone.

Fixing 1 does not require 2. They are independent.

### Why not now

- **No baseline.** This job is `optional: true` and is `blocked` on every recent `main` build, so there is no p50/p90 and no evidence of its current pass state. Sharding a job with no signal means a failure cannot be attributed — the only reason the Standard 4 segfault in #57067 could be proven self-inflicted was that the job was verifiably green on ten consecutive `main` builds.
- **PR hygiene.** Editing this in #57067, which stacks on top of this PR, would mix two changes and make both harder to review.

### Suggested order

1. Get Extended Generation 1 running often enough to have a baseline and a known pass state.
2. Split `test_ultravox.py` into core and extended wrappers over a shared non-collected helper, the way the other four mixed files were done. That removes `-m 'not core_model'` as redundant rather than narrowing it.
3. Replace the `case` block with three filter-free named jobs over whole units: `Audio`, `Vision`, `Omni + Mapping`, with distinct stable keys and an old to new key mapping in the PR body.
