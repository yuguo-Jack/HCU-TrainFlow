# [Bugfix][Core][KV Connector] Reusable-load handshake for align-mode Mamba under the EAGLE block drop

[Upstream PR](https://github.com/vllm-project/vllm/pull/63221) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

Companion LMCache PR: https://github.com/LMCache/LMCache/pull/5985 ("[MP][vLLM] End reloads on the engine's reusable boundary"). Each PR is inert without the other.

## Overview

This is a correctness fix for the prefix cache of align-mode Mamba models under speculative decoding.

Under the EAGLE block drop, a GPU prefix hit resumes from the Mamba state one block below the match end. A KV
connector that loads up to its longest match restores the Mamba state *at* the match end, a state that no request can
ever hit. Once the reusable state (one block lower) has been evicted from the GPU, every request misses, every request
reloads the same unreachable state, and nobody prefills locally to re-create the reusable one: the GPU prefix cache can
never recover. Measured on Kimi-K3 (MLA + KDA) + DSpark K=7: 0 % GPU prefix hit at concurrency 48 and 64, for the whole
run.

Under the EAGLE block drop, a reload must therefore end on a boundary vLLM can reuse. This PR lets vLLM tell the
connector, as data, where a load must end to be reusable (`get_reusable_load_rule()`, built on the existing checkpoint
rule), and retains the Mamba state a negotiated load ends on, so a reload re-creates a GPU-hittable state and the prefix cache recovers by
itself. The fix does not depend on a throughput gain; the benchmark below is reported as measured.

## Claims

- New connector-facing API: `KVConnectorBase_V1.get_reusable_load_rule() -> (granularity_tokens, drop_tokens) | None`
  (delegates to `KVCacheManager` / `KVCacheCoordinator`): a load for a match of `n` tokens should end at
  `max(n // granularity * granularity - drop, 0)`, the position of the existing
  `get_mamba_prefill_checkpoint_position(..., drop_eagle_block=True)`; `None` when every load end is reusable. And
  `KVConnectorBase_V1.ends_loads_on_reusable_boundary` (default `False`). About 60 lines of code.
- When a connector declares it, the scheduler retains the Mamba state at the end of each completed connector load
  (one more reachable boundary for the sparse prefix-cache retention), so the next request hits it on the GPU.
- No behaviour change for any connector that does not set the flag, or for models without align-mode Mamba under the
  EAGLE block drop (the API returns `None`). `VLLM_MAMBA_CACHE_CONNECTOR_LOAD_STATE=0` turns the retention off.
- End to end with the companion LMCache PR on Kimi-K3 + DSpark K=7, 8x MI355X: the GPU prefix cache recovers by
  itself (GPU prefix hit 0 % -> 53-55 % at concurrency 48 / 64), LMCache reloads fall 61 % (306 M -> 119 M retrieved
  tokens over concurrency 32-64), and the reusable junction states are re-created after every eviction (0 -> 378 / 462
  re-stores at 48 / 64). TTFT and throughput are not better yet; see Validation for why (duplicate concurrent loads)
  and the follow-up.

53-55 % at 48 / 64), LMCache reloads fall 61 %, and the junction states are re-created after every eviction. TTFT and

state is still evicted under KV pressure (it is an ordinary evictable cached block), and when that happens every
waiting request with the same prefix misses on the GPU and starts its **own** connector load of the same blocks. Each

0 % GPU hit; now each herd ends with a GPU-hittable state.

so a block hash is never loaded into HBM while a copy of it is already resident or in flight, and requests with the
same prefix wait for one load instead of each loading their own.

## Details

**Root cause.** Prefix match on the GPU ends at `N`; under the EAGLE block drop a hit resumes from the prefill
checkpoint one block below (`get_mamba_prefill_checkpoint_position(..., drop_eagle_block=True)`). Align-mode Mamba
states exist only at prefill step ends and are kept sparsely. When the junction state (end of block `N/B - 1`) is
evicted, every request misses on the GPU; the connector asks for the longest external match `M` and loads the Mamba
state at `M`, which the EAGLE-dropped hit never uses, and nobody prefills locally anymore, so the junction state is
never re-created. Measured on the baseline: GPU prefix hit 64.9 % at concurrency 32, 0.0 % at 48 and 64, at most 36
requests running, and every request holds a private copy of the 63k prefix.

**Design.**
- Single source of truth stays in vLLM: the connector does not re-implement the EAGLE / checkpoint rule, it reads
  `get_reusable_load_rule()` (bound through the existing `bind_kv_cache_manager`). The rule is returned as data
  (`granularity`, `drop`) so a connector, or the cache server behind it, can apply it without calling back into vLLM
  per request; `None` means every load end is reusable. A unit test checks the rule against
  `get_mamba_prefill_checkpoint_position` for every length.
- Retention is tied to the connector's declaration, not to "any connector": other connectors stay byte-identical.
- The LMCache side sends the rule to the LMCache server at startup (only the rule); the server applies it inside its
  one lookup per request. Other connectors (Mooncake, NIXL, offloading) can use the same
  API.

**Trade-offs / limitations.** A negotiated reload ends one block earlier, so that request prefills one extra block
(1,536 tokens) locally; later requests hit on the GPU. Only align-mode Mamba under the EAGLE block drop is affected.
