# Add multi-path sharding and aligned direct I/O to FS offloading

[Upstream PR](https://github.com/vllm-project/vllm/pull/53133) · state: open · merged: False

## Original PR description

  ## Purpose

  The filesystem KV offloading tier currently uses a single storage path and assumes direct I/O can be selected for an entire batch. This PR adds two capabilities to the filesystem KV offloading tier:

  - Optional whole-block sharding across an ordered, comma-separated list of storage paths using `path_sharding: "by_block_hash"`. Blocks assigned to different paths are processed in parallel, while existing single-path behavior remains unchanged.
  - Safe O_DIRECT selection based on per-path support and per-operation buffer and length alignment. Unaligned operations fall back to buffered I/O.

Documentation is included for the new configuration and block-placement behavior.

  ## Test Plan

  Focused unit tests:

  ```bash
  python -m pytest tests/v1/kv_offload/tiering/test_fs_tier.py
  ```

  Multi-path filesystem KV offloading configuration:

  ```bash
  kv_transfer_config='{
    "kv_connector": "OffloadingConnector",
    "kv_role": "kv_both",
    "kv_connector_extra_config": {
      "spec_name": "TieringOffloadingSpec",
      "cpu_bytes_to_use": 34359738368,
      "block_size": 1024,
      "eviction_policy": "lru",
      "secondary_tiers": [{
        "type": "fs",
        "root_dir": "/mnt/ps-1/kv-cache,/mnt/ps-2/kv-cache,/mnt/ps-3/kv-cache,/mnt/ps-4/kv-cache",
        "path_sharding": "by_block_hash",
        "n_read_threads": 64,
        "n_write_threads": 64
      }]
    }
  }'

  vllm serve Qwen/Qwen3-Coder-30B-A3B-Instruct \
    --tensor-parallel-size 4 \
    --max-model-len 262144 \
    --no-enable-prefix-caching \
    --kv-transfer-config "$kv_transfer_config"
  ```
  
 ## Test Result

  The native extension was rebuilt from source against CUDA 13 on H100 using an editable installation. The focused unit tests were rerun against the rebuilt extension.

  Runtime validation used four filesystem paths with TP=4 and a 128K-token request. Three storage-hit reads retrieved all `126/126` requested blocks without short-I/O or backend errors.

  The four-paths configuration reduced mean storage-hit TTFT by **41.1%**. Mean filesystem-to-CPU transfer time decreased from `1.404 s` to `0.671 s` (`52.2%`).
