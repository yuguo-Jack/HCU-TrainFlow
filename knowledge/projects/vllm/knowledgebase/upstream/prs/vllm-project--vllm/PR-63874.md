# [Bugfix][Distributed] Release FlashInfer one-sided workspaces on teardown

[Upstream PR](https://github.com/vllm-project/vllm/pull/63874) · state: open · merged: False

## Original PR description

## Overview

Release FlashInfer one-sided all-to-all resources when vLLM destroys its expert-parallel communicator, while CUDA and the CPU process group are still alive.

## Claims

- `FlashInferNVLinkOneSidedManager.destroy()` now releases its communicator instead of inheriting a no-op.
- With the pinned FlashInfer 0.7.2, remove the owned legacy workspace cache reference so symmetric allocations do not survive until Python finalization. Preserve references held by other live wrappers.

## Validation

Validated on two GB200 GPUs with PyTorch 2.14.0+cu130 and FlashInfer 0.7.2.post1:

| Check | Before | After |
| --- | --- | --- |
| Existing lifecycle worker, extended to call `destroy()` | Fails `not manager.initialized`; worker finalization also segfaults | Passes, including cache eviction, reinitialization, and repeated destruction |
| Existing workspace-growth worker | — | Passes |
| Existing BF16 dispatch/combine worker | — | Passes |
| Native `vllm bench forward`, tiny Qwen3 MoE BF16, DP2/EP2, FlashInfer CUTLASS and one-sided A2A | — | Prefill and decode finish with finite, deterministic outputs and graph/eager RMS 0 on both ranks; clean process exit |

The real distributed workers were invoked directly because this host's pytest capability marker skips the tests without `SYS_PTRACE`; its CUDA FABRIC allocation path works. No communicator or allocation was mocked. The existing B200 distributed CI step runs these tests in its supported environment.

All targeted pre-commit hooks pass. This changes resource lifetime, not model arithmetic; no quality or performance improvement is claimed.

## Details

The existing group teardown already calls the CUDA communicator's `destroy()` before destroying process groups. The one-sided manager lacked an override, and its explicit `cleanup()` only destroyed FlashInfer's wrapper. In FlashInfer 0.7.2 that leaves the symmetric workspace in a process-wide cache, which can release CUDA tensors too late during interpreter finalization.

Cleanup now synchronizes outstanding device work and ranks before destroying the wrapper and removing only cache entries that refer to that workspace. It does not clear or mutate the workspace itself, so other wrappers keep their own references. The same cleanup handles workspace growth before graph capture. Newer FlashInfer implementations without the legacy wrapper use their public `destroy()` directly. No synchronization is added to steady-state dispatch/combine.

Duplicate checks found no open PR with this lifecycle fix. The current diff of [#47733](https://github.com/vllm-project/vllm/pull/47733) changes invalid expert IDs and scaling in prepare/finalize; despite its older body mentioning destruction, it does not add this manager teardown. FlashInfer main has a newer workspace lifecycle, but vLLM currently pins the affected released version.
