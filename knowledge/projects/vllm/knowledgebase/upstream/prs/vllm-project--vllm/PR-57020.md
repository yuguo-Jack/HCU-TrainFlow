# [Bugfix][DBO] Fall back to eager at the empty-microbatch boundary

[Upstream PR](https://github.com/vllm-project/vllm/pull/57020) · state: open · merged: False

## Original PR description

## Purpose

With DP token counts `[64, 128]` and a 128-token CUDA graph, the smaller rank has no real tokens in its second microbatch. The existing guard uses `2 * min_tokens < graph_tokens`, so equality still permits FULL replay.

Change `<` to `<=` to use the existing eager microbatch fallback. Extend the existing regression test with the 64-token boundary and make its uniform-decode request counts consistent with the token counts.

Follow-up to #51700; its author [confirmed the bug and requested this fix](https://github.com/vllm-project/vllm/pull/51700#issuecomment-5681158479). Searches of open PRs by `51700 in:body`, DBO boundary, empty microbatch, and the affected function found no duplicate. #56775 concerns CI selection; #46370 changes fault-tolerance coordination, not this guard.
