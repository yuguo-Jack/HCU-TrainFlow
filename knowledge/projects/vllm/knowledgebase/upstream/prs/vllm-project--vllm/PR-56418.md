# [Bugfix][Frontend] Preserve namespaced custom tools in Responses

[Upstream PR](https://github.com/vllm-project/vllm/pull/56418) · state: open · merged: False

## Original PR description

## Overview

Fix namespaced custom tools in the Responses API after #57322. This reuses the merged custom-tool shim and fixes the remaining namespace conversion, output and history-replay paths.

## Claims

- Preserve namespaced custom tools during prompt construction and named/required selection.
- Return `custom_tool_call` with separate `name` and `namespace`, preserving streaming input events and distinguishing same-local-name function tools.
- Restore the full tool name during explicit history replay and reject unsupported grammar formats inside namespaces.
- Document namespaced custom-tool requests, streaming events and call/result replay.

### Real-model validation

Qwen3-1.7B on an RTX 5070 Laptop GPU, served from this branch with Torch 2.14.0+cu130, Transformers 5.19.0 and the official native wheel for the PR base. Local GPU tests used reduced resource limits.

- Required/named selection, streaming and non-streaming: `custom_tool_call` with `name="emit"`, `namespace="sandbox"` and `input="hello"`.
- Streamed input deltas match the done/final input, with consistent item and call IDs.
- History replay preserves the full tool name and tool result in the prompt; input token IDs and output match equivalent namespace function-call history.
- Nested grammar-format custom tools return HTTP 400.

All five new cases fail for the target defects on parent `8a8e2baa02` in the same environment. Local pre-commit, including mypy, and a strict MkDocs build also passed for this diff.

Upstream CI is pending: `pre-run-check` stops at the PR eligibility gate, and Read the Docs exits on the same result before compiling the documentation.

## Details

The model-facing shim uses the flattened tool name, such as `sandbox__emit`. Output conversion restores the public name/namespace pair, while replay reconstructs the flattened name. Streaming classification also uses the full name. The shim and decoder from #57322 remain in use.

Related work checked on 2026-10-29: #60585 addresses `allowed_tools`, and #59792 addresses client-executed `tool_search`. Neither implements this namespace custom-tool round trip; the affected paths remain unfixed on current `main`.
