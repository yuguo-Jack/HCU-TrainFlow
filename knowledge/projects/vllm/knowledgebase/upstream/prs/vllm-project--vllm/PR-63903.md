## Overview

add Responses SSE streaming with text, reasoning, function-call events, stable item IDs, and terminal handling for completion, token limits, and failures.

review order: [1/3: renderer #63901](https://github.com/vllm-project/vllm/pull/63901) → [2/3: non-streaming #63902](https://github.com/vllm-project/vllm/pull/63902) → [3/3: streaming #63903](https://github.com/vllm-project/vllm/pull/63903). all three upstream review PRs target `main`; later diffs include earlier layers.

this PR includes and depends on #63901 and #63902. the [fork layer](https://github.com/franciscojavierarceo/vllm/pull/3) isolates the streaming changes.

## Claims

- emit ordered response/item/content events, using IDs assigned by `vllm-chat`.
- terminate token limits with `response.incomplete`; close started items before `response.failed`, retain partial output, and preserve engine-supplied usage.
- use the existing SSE response helper and keep-alive configuration, with test-only HTTP regressions.

## Details

this removes layer 2's temporary streaming rejection. the rebase consumes upstream's boxed transfer metadata without cloning, accepts the updated terminal-event fields, and handles typed error finishes.

the decode-failure regression checks partial text and stable item IDs, exactly one item close before one `response.failed`, no completion event, and no fabricated missing usage. abort retains the Python-compatible completed event with cancelled response status; it is separate from the token-limit incomplete event.

the frontend remains stateless: clients replay history, and agentic-api owns persistence and tool execution. the shared native adapter tracked by vllm-project/agentic-api#359 and vllm-project/agentic-api#382 is still unfinished. accepted reasoning-summary, text-verbosity, and encrypted-reasoning inputs are documented compatibility no-ops; valid service tiers are echoed without scheduling guarantees. layer 2 describes the remaining request/feature boundaries. the rendered [Responses documentation](https://github.com/franciscojavierarceo/vllm/blob/codex/responses-streaming/docs/serving/online_serving/openai_compatible_server.md#responses-api) now includes SSE and terminal behavior.

these are the existing #58783 layers opened upstream at [@BugenZhao's request](https://github.com/vllm-project/vllm/pull/58783#issuecomment-6418403089), rather than competing implementations. the original authored history and discussion remain in #58783. @gcanlin's #53380 implementation is credited in the endpoint and streaming commits. this stack carries the prior implementation plus the current-main compatibility resolutions; the old source tips are backed up locally.

this layer is **4 files, +1267 / -57** relative to #63902. Codex assistance was used. human review of every changed line and independent validation remain required before merge.
