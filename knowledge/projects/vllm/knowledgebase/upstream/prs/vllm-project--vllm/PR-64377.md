# [CI][ROCm] Drop nvidia-cuda-cccl from the ROCm test lockfile again

[Upstream PR](https://github.com/vllm-project/vllm/pull/64377) · state: closed · merged: True

## Original PR description



## Overview

Fixes the `pip-compile-rocm` pre-commit failure on `main` by removing `nvidia-cuda-cccl` from `requirements/test/rocm.txt` again.

## Claims

- Regenerate `rocm.txt` (test) with the `pip-compile-rocm` hook, which drops the `nvidia-cuda-cccl` pin that #64302 excluded
- Turns pre-commit green again on `main` and on every open PR that merges it

## Validation

- `uvx pre-commit run pip-compile-rocm --hook-stage manual --files requirements/test/rocm.in` produces exactly this diff, and running it again changes nothing
- `uvx pre-commit run --from-ref $(git merge-base origin/main HEAD) --to-ref HEAD` passes
- The resulting file is byte-identical to the one #64302 merged (blob `e3af4cbc39`)

## Details

#64302 added `--no-emit-package nvidia-cuda-cccl` to the ROCm hook and removed the package from the test lockfile. A few hours later #61699 merged with a `rocm.txt` it had regenerated before #64302 landed, which put the `nvidia-cuda-cccl==13.3.4.3.1` entry back. Since then every pre-commit run on `main` has failed in `pip-compile-rocm` ([example](https://github.com/vllm-project/vllm/actions/runs/40783654810)), and so does every PR that runs the check. I searched for `nvidia-cuda-cccl`, `pip-compile-rocm`, and open PRs touching this lockfile and found no existing fix.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
