# [Feature][KV Connector][Mooncake] Add layerwise and chunk-wise KV transfer

[Upstream PR](https://github.com/vllm-project/vllm/pull/62504) · state: open · merged: False

## Original PR description



## Overview

Add `MooncakeLayerwiseConnector` for direct P/D KV WRITE transfer across layers and prefill chunks, reusing `MooncakeConnector`. This continues the prototype in #37686 and the upstream adaptation coordinated in #60523 / #61567.

**Draft:** establish the functional baseline; GPU accuracy and performance validation will follow.

## Claims

- Incrementally send completed KV blocks across layers and prefill chunks; send the partial tail block in the final chunk.
- Handle late D-ready notifications, including after prefill finishes without another forward.
- Group multiple cache names belonging to the same transformer layer, including independent indexer caches, while preserving each region's address and stride.
- Reuse Mooncake's TP routing, layout handshake/cache, address planning and D-side receive/completion flow. Register the connector as `MooncakeLayerwiseConnector`.

## Validation

**Functional tests only; no general accuracy or performance claim.** Serving tests ran on Ascend, with P eager, D FULL_DECODE_ONLY, and CP disabled.

| Model | Configuration | Functional coverage |
| --- | --- | --- |
| DeepSeek-V3.1 | P TP8 / D TP8, MTP off | Short requests, multi-chunk prefill, comparison with ordinary Mooncake PD; output token sequences matched. |
| GLM-5.2 | P TP8 / D TP8, MTP off | Short and multi-chunk requests; same-layer main KV and independent indexer caches. |
| GLM-5.2 | P TP8/MTP1 / D DP2×TP4/MTP3 | Short/long requests, multi-token generation and four concurrent requests; seven requests completed, both D replicas served requests, and all three draft positions had accepted tokens. |

Transfer completion was observed on P and D with no reported transfer/receive failures in these runs. Token agreement is functional evidence, not a strict numerical-accuracy result.

Ruff, formatting and diff checks pass on the submitted commit. Host-logic unit tests are included, with device events and transport mocked; a unit rerun and GPU validation remain pending.

## Details

**Design:** D allocates blocks and sends ready metadata. P's connector scheduler snapshots chunk progress; layer hooks publish available block ranges. An executor computes and aggregates addresses by destination, waits for KV writes to complete, and performs WRITE. P retains blocks through delayed free; D starts execution after all required KV arrives. Listener/ACK handling stays on the existing control loop. No core scheduler or model-runner changes are added; the base connector only extracts a shared synchronous address-planning helper.

**Current limits:** one full-attention KV transfer group (including MLA and FullAttentionSpec subclasses), PP1/PCP1/DCP1, equal peer block sizes, fixed producer/consumer roles, and no sleep/storage replacement. P requires eager or PIECEWISE hooks; FULL graphs on P are unsupported. KV writes must use one compute stream, and each layer hook must follow all KV writes for that layer. One transfer batch is in flight, with waits at step boundaries.

**Follow-up:** support multiple KV groups and non-FA KV caches, PP, and context parallelism (DCP/PCP); extend lifecycle/failure coverage. Add GPU accuracy and end-to-end performance comparisons against ordinary Mooncake, tentatively using **GLM-5.2**.

Use `"kv_connector": "MooncakeLayerwiseConnector"` with `kv_producer` on P and `kv_consumer` on D; both peers must use this connector.

**Related work:** #61974 implements decode-side READ; #51978 targets Mooncake Store/Session API. This PR implements direct P-to-D layerwise WRITE, following the division of work discussed in #60523.
