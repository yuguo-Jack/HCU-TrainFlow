# [Feature][KV Connector][Mooncake] Add layerwise and chunk-wise KV transfer

[Upstream PR](https://github.com/vllm-project/vllm/pull/62504) · state: open · merged: False

## Original PR description

## Overview

Add `MooncakeLayerwiseConnector` for direct P/D KV WRITE transfer across layers and prefill chunks, reusing `MooncakeConnector`. This continues the prototype in #37686 and the upstream adaptation coordinated in #60523 / #61567.

**Design RFC:** [Direct layerwise and chunk-wise KV WRITE with Mooncake (#64648)](https://github.com/vllm-project/vllm/issues/64648). The RFC covers the protocol, cache mapping, lifecycle tradeoffs, validation plan, and DCP follow-up roadmap.

Ready for design and implementation review; GPU accuracy and performance validation remain pending. AI assistance was used in the implementation, tests, and design documentation.

## Claims

- Incrementally WRITE completed FA/MLA KV blocks across layers and prefill chunks, then send the final partial block. Preserve separate cache names and transfer-group identities, including independent indexer caches.
- Transfer the final requested sliding-window KV ranges, final Mamba/GDN states, and final CircularBuffer pages according to each cache group's semantics.
- Match cache regions across heterogeneous P/D pipeline stages, reuse Mooncake TP routing, and support explicitly declared complete PCP replicas; only P replica zero sends.
- Handle late D-ready notifications while P retains completed prefill requests, including empty scheduler steps without another forward. Retain KV blocks until in-flight transfers are drained.
- Cache peer layouts and transfer mappings, aggregate WRITEs by destination, and submit independent destination batches concurrently. Reject requests whose receive deadline is too close without cancelling healthy requests in the same batch.

## Details

**Design:** D allocates blocks and sends ready metadata with its remaining receive timeout. P snapshots each request's chunk progress and block tables; layer hooks publish available KV ranges. Background executors plan addresses, wait for the device event, and WRITE by destination. `wait_for_save()` drains all submitted and currently ready transfers before the step ends; empty `start_load_kv()` steps also drain late-ready transfers. Completion polling does not submit new work. Listener and ACK handling remain on the control loop. Peer layouts, expected worker sets, and logical-to-kernel block ratios are cached. The base connector exposes shared planning/registration hooks. Receive-failure aggregation is reused from the rebased upstream baseline, settling all peer receive tasks before aggregate completion.

**Cache and topology boundaries:** multiple transfer groups and heterogeneous PP partitions are supported. FA/MLA streams complete blocks; SWA sends its final requested window, while windowed full-attention managers retain the full requested suffix. Mamba/GDN and CircularBuffer send final resident state and require equal P/D TP sizes. PCP requires `"pcp_cache_mode": "replicated"` on both peers and complete cache replicas on every PCP rank; this does not gather sharded caches. DCP must be 1. These are implementation boundaries, not a validated model matrix.

**Execution limits:** fixed producer/consumer roles, matching component semantics and kernel block sizes, and no sleep/storage replacement, cache transposition, or dtype conversion. P requires eager or PIECEWISE Python hooks, with KV writes on the fenced compute stream; FULL graphs on P are unsupported. Producer PD requests should use `max_tokens=1`. Opaque packed rows that lose writer identity and chunked-local attention are unsupported. Multiple destination batches may run concurrently, but each step drains them before proceeding; empty-step sends are also blocking.

**Timeouts and late readiness:** `layerwise_send_timeout_margin_s` defaults to 10 seconds. P uses its local monotonic clock and D's relative receive timeout, avoiding P/D wall-clock synchronization. Expired requests are removed before WRITE while healthy requests continue. If P has already released all requests and become fully idle, a later D-ready remains queued until scheduling resumes or D times out; waking a fully idle P is deferred.

**Roadmap:** DCP support is the first planned feature extension, covering shard mapping, completion/failure aggregation, and correctness/performance validation. Other feature milestones will be planned later; see the RFC.

Use `"kv_connector": "MooncakeLayerwiseConnector"` with `kv_producer` on P and `kv_consumer` on D; both peers must use this connector.

**Related work / non-duplication:** #61974 implements decode-side READ; #51978 targets Mooncake Store/Session API. This PR implements direct P-to-D layerwise WRITE, following the division of work discussed in #60523 and developing the earlier design in #61567. The implementation-specific RFC is #64648.
