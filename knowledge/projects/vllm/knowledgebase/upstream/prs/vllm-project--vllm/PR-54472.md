# [Bugfix][DCP] Fall back for unsupported direct A2A layouts

[Upstream PR](https://github.com/vllm-project/vllm/pull/54472) · state: open · merged: False

## Original PR description

## Summary

Fixes #54305.

- Gate direct symmetric-memory DCP A2A on the layout required by its C++ kernel.
- Fall back to the existing stride-aware NCCL A2A implementation for valid
  strided attention views.
- Add a CPU dispatch regression test covering a head-major output view.

The direct kernel requires packed head dimensions, an aligned token stride, and
packed LSE heads. The generic A2A path already handles arbitrary strides, so
this preserves the optimized path for supported inputs without changing the
numerical combine implementation.

## Why this is not a duplicate

Issue #54305 is open and unassigned. A search of open and closed pull requests
for `54305`, direct-DCP layout terms, and the C++ stride error found no change
covering this fallback. The existing direct-A2A and DCP layout work addresses
different functionality.

## Testing

- `pre-commit run --files vllm/v1/attention/ops/dcp.py tests/distributed/test_dcp_direct_a2a_lse_reduce.py`
- `.venv/bin/python -m py_compile vllm/v1/attention/ops/dcp.py tests/distributed/test_dcp_direct_a2a_lse_reduce.py`
- `git diff --check`
- Standalone tensor-stride predicate cases for contiguous, padded, head-major,
  invalid-head-dimension, and non-packed-LSE layouts.

The focused pytest invocation could not complete on this Apple Silicon host:
importing the repository's PyTorch stack stalled during collection. The
distributed GPU coverage should run in CI on the supported CUDA environments.

This routing-only change does not alter model outputs, so no model evaluation
was run locally.
