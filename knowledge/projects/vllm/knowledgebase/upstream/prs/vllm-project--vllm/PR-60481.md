# [Compile] Defunctionalize rms_norm_per_block_quant

[Upstream PR](https://github.com/vllm-project/vllm/pull/60481) · state: open · merged: False

## Original PR description



## Overview

`FixFunctionalizationPass` defunctionalizes `rms_norm_dynamic_per_token_quant` but not `rms_norm_per_block_quant`, which the norm + quant fusion emits for block-FP8 models. Inductor then copies the residual in every layer. Both ops mutate the same arguments, so this adds the per-block op to the existing branch, which should save a little decode time on block-FP8 models. Possibly the extra kernel in #37832.

## Claims

- Removes one residual copy kernel per layer per decode step.

## Validation

- New case `TestFusedAddRMSNormBlockQuant` in `tests/compile/passes/test_functionalization.py` fails on main and passes with this PR.
- H100 NVL, `Qwen/Qwen3-8B-FP8`, batch 8: the copy (`triton_poi_fused_0`, 36 per step) took 0.054 ms of each 7.3 ms decode step on main and is gone with this PR.
