# [Model][LoRA] Add tower/connector LoRA support for Nemotron Nano/Omni VL (vision + audio)

[Upstream PR](https://github.com/vllm-project/vllm/pull/58658) · state: open · merged: False

## Original PR description

## Purpose

Adds LoRA support for the vision tower (RADIO ViT), audio tower (Parakeet
conformer encoder), and their respective connectors on
`NemotronH_Nano_VL_V2` / `NemotronH_Nano_Omni_Reasoning_V3`, using the
existing `enable_tower_connector_lora` mechanism. Language-model-only LoRA
for this model already works today; this PR extends it to the multimodal
towers and connectors.

- Swaps `nn.Linear` → `ReplicatedLinear` in the vision/audio connectors
  (`mlp1`, `ParakeetProjection`) and the Parakeet encoder's non-shared
  linears, so they can receive LoRA deltas.
- Adds `get_mm_lora_token_counts()` so the multimodal LoRA runtime can
  size its per-modality tower/connector token budgets for image, video,
  and audio inputs (fixed-resolution, dynamic-resolution, and precomputed
  embeddings paths).
- Adds `hf_to_vllm_mapper` rename rules so PEFT-style LoRA checkpoint keys
  for the RADIO vision tower (`vision_model.radio_model.model.blocks.*`)
  and the audio projection (`sound_projection.*`) resolve to the correct
  vLLM module paths.

## Bugfix included in this PR

`get_mm_lora_token_counts()`'s single-image fast path only recognized a
flat `(height, width)` pair when it arrived as a `tuple`:

```python
if (
    isinstance(sizes_data, tuple)
    and len(sizes_data) == 2
    and all(isinstance(dim, int) for dim in sizes_data)
):
    image_sizes = [sizes_data]
else:
    image_sizes = list(sizes_data)
```

In practice, `MultiModalKwargsItem` stores this as a plain `list` (e.g.
`[448, 640]`) for a single image, not a `tuple`. That falls through to the
multi-image branch, which then tries to unpack the bare `int` `448` as
`(height, width)`:

```
TypeError: cannot unpack non-iterable int object
```

This crashed the **entire engine core** on any real single-image request
once `--enable-tower-connector-lora` was set — including requests with no
LoRA adapter attached at all, since the flag makes vLLM call this path
unconditionally for every image request. Fixed by also accepting `list`.

## Test Plan

Unit tests (`tests/models/multimodal/test_nano_nemotron_vl.py`, all
mocked, no GPU/weights required):

```
pytest tests/models/multimodal/test_nano_nemotron_vl.py -q
# 16 passed
```

End-to-end validation on real hardware against
`nvidia/Nemotron-3-Nano-Omni-30B-A3B-Reasoning-BF16` (4x A6000,
`vllm serve --enable-lora --enable-tower-connector-lora`):

1. **Vision**: built a zero-init LoRA adapter (`lora_B = 0`) targeting all
   32 RADIO ViT blocks' `attn.qkv/proj`, `mlp.fc1/fc2`, plus the `mlp1`
   connector (130 modules). Compared greedy-decoded output on a real image
   with/without the adapter attached: **identical text, bit-exact
   logprobs** (`max abs diff = 0.0`), confirming the no-op composition is
   correct.
2. Built a second, non-zero-init adapter on the same 130 modules. Compared
   against the zero-init adapter and base: **materially different
   output** (hallucinated an unrelated scene), confirming the LoRA path
   is genuinely applied, not silently skipped.
3. **Audio**: repeated the same zero-init vs. non-zero-init vs. base
   protocol on the Parakeet encoder + `sound_projection` connector (195
   modules: 24 conformer layers' `q/k/v/o_proj`, both feed-forward
   linears, `subsampling.linear`, plus the connector) using a real audio
   clip. Same result: zero-init is bit-exact vs. base, non-zero-init
   meaningfully changes the transcription/description.
4. **Combined**: built adapters spanning vision (130) + audio (195) + the
   LLM's 6 full-attention layers' `q/k/v/o_proj` (24, via the standard
   `packed_modules_mapping` fusion into `qkv_proj` — unrelated to this
   PR's tower/connector mechanism, included to confirm the two paths
   compose correctly) — 349 modules total. Sent a single request with an
   image, audio, and text prompt together: zero-init adapter reproduced
   the base model's output exactly; non-zero-init adapter caused
   incoherent generation, confirming end-to-end composition across both
   modalities and the LLM.
5. Loaded a real, separately-trained LoRA adapter (rank 32, rsLoRA,
   trained on the vision tower) and verified it produces coherent,
   on-distribution generations through this code path.

All adapters, test images/audio, and scripts used above are available on
request if reviewers want to reproduce.

## Notes for reviewers

- `enable_tower_connector_lora` remains opt-in and is logged as
  experimental; this PR doesn't change that.
- LLM-side LoRA in the "combined" test above uses the existing, unrelated
  `packed_modules_mapping` mechanism (already supported for this model's
  language model) — it's exercised only to confirm composition, not
  something this PR adds.
- MoE and Mamba mixer layers in the language model are out of scope for
  LoRA in this PR (as before) — only the vision/audio towers and
  connectors are new here.
