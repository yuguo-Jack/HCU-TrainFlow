# [Bugfix][Frontend] systemone: take option labels from option names

[Upstream PR](https://github.com/vllm-project/vllm/pull/61190) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fixes #61189. `/v1/systemone` and `/v1/decisions` label each option by position. A choice named `C, A, D, B` is shown as `A: C`, `B: A` and so on, so a model that answers "B" picks the option named `A`. A score named `"1".."5"` is shown as `0: 1` to `4: 5`, so a model that answers with the level's own digit reads one level high.

This PR takes the labels from the option names when the names are labels already: distinct capital letters for a choice, single digits for a score. The rule lives in `QuestionType.labels()`, so every read strategy uses it. `/v1/decisions` gets the choice rule through `make_read_question()`. The example DiffusionGemma gateway gets a copy of the same rule.

Liquid d1 keeps the score format its checkpoint was trained on: the legend `0 1`, `1 2`, ... and the digits `0` to `n-1` as readout tokens. On d1-3B that format reads `"1".."5"` at -0.10 levels (34/40 exact), and own-digit labels read it at -0.40 (23/40).

## Claims

- A choice whose options are distinct single capital letters keeps those letters as labels, on `/v1/systemone` and `/v1/decisions`. Other choices keep `A` to `Z` by position.
- A score whose levels are all single ASCII digits (`"1".."5"`, `"0".."4"`) keeps those digits as labels, and the prompt shows each level as its digit alone.
- Every other score scale (`"1 star"`, `"1".."10"`, `poor, 2, 3, 4, excellent`, words) keeps main's labels and a byte-identical prompt.
- Liquid d1 keeps the checkpoint's positional score digits. Its choice codes already used single-letter option names.
- The answer shape does not change: `score`, `legend` and `probabilities` stay 0-indexed by position.

## Details

Root cause: `build_question()` took `qtype.label_set[: len(options)]` for every question, `make_read_question()` took `LABELS[: len(options)]`, and the gateway's `parse_schema()` took `1..n` or `A..Z`. Nothing compared a label with the name next to it.

The own labels are a subset of the existing label table (digits and `A` to `Z`), so the token ids the strategies resolve at startup cover them.

`LiquidStrategy` builds the score legend and readout from `question.type.label_set`, not `question.labels`. The checkpoint's `prompt.py` writes `{i} {name}` with `i` from 0, and own-digit labels read worse on d1-3B (above).

The gateway copies the rule instead of importing it. It imports only the standard library, `pybase64` and `transformers`; importing vLLM would tie the example to a vLLM version. A shared test table pins the two copies together.

Limits:

- Own labels apply only when every name is a label. `"1 star".."5 stars"` and `poor, 2, 3, 4, excellent` keep positional labels, so a model may still answer with a level's own digit.
- The built-in endpoint still allows at most 10 score levels.
- Plus/minus grades (`A+`, `A`, `A-`) and choices that mix letters with other names (`["B", "Other"]` shows `A: B`) still clash with letter labels in the prompt.
- The built-in prompt shows an own-digit level as its digit alone (`1`); the gateway keeps `1: 1`.
