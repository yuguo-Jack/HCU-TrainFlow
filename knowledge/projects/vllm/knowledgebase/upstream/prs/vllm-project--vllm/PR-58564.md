# [Bugfix][Helm] Add startup probe for slow model initialization

[Upstream PR](https://github.com/vllm-project/vllm/pull/58564) · state: open · merged: False

## Original PR description

## Summary

Fixes #58544.

The Helm chart's liveness probe can restart vLLM while a large model is still initializing. Add a configurable startup probe on `/health:8000`, with a default allowance of approximately 30 minutes (`periodSeconds: 10`, `failureThreshold: 180`). Readiness and liveness checks begin after startup succeeds. Set `startupProbe: null` to omit the probe.

Make `progressDeadlineSeconds` configurable, defaulting to 2100 seconds instead of the hard-coded 1200 seconds. This provides a five-minute margin beyond the default startup allowance. Longer probe budgets should be accompanied by longer rollout deadlines; they also delay recovery from a stuck initialization.

Package `values.schema.json` so Helm validates values. Preserve supported CPU quantities, named probe ports, disabled readiness/liveness probes, and alternative probe handlers. Require a success threshold of 1 for startup and liveness probes. When replacing an HTTP handler, set `httpGet: null` to remove the default during Helm's map merge.

Update the chart documentation and bump the chart version from 0.0.2 to 0.1.0.
