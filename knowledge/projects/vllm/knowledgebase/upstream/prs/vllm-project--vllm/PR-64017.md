# [Bugfix][Frontend] Return per-request metrics in Anthropic messages

[Upstream PR](https://github.com/vllm-project/vllm/pull/64017) · state: open · merged: False

## Original PR description

## Overview
Fixes #64014: propagate `--enable-per-request-metrics` to `/v1/messages` and preserve metrics when converting OpenAI responses to Anthropic responses.

## Claims
- Non-streaming messages expose the existing `metrics` object alongside `usage`.
- Streaming messages expose metrics only on the final usage-bearing `message_delta`.
- Disabled metrics remain omitted. Documents the response shape and adds converter and real-server regression coverage.

## Validation
- Converter suite: `python -m pytest --confcutdir=tests/entrypoints/anthropic tests/entrypoints/anthropic/test_anthropic_messages_conversion.py -q` (using the existing uv-managed `.venv/bin/python`). 126 passed.
- Before fix, the four new converter cases produced 3 failures and 1 pass: full responses lacked a metrics attribute and streaming dropped enabled metrics.
- Ruff check, Ruff format check, and `git diff --check` passed.
- Real-server regression attempted: `python -m pytest tests/entrypoints/anthropic/test_messages.py -k per_request_metrics -q`. Both cases stop at device initialization (`Failed to infer device type`) on this macOS host. No model-serving evaluation or GPU benchmark is claimed; GPU CI validation is still required.
- The converter command excludes the parent GPU cleanup fixture because local PyTorch segfaults in `torch.accelerator.memory.empty_host_cache` during teardown. No repository fixtures were changed.
- Existing Buildkite Entrypoints Integration (API Server Generate) selects the Anthropic test directory and depends on `vllm/`.

## Details
The Anthropic handler omitted the flag when constructing its chat-serving parent, and both response converters dropped the parent's metrics. Reuse the shared `PerRequestMetrics` type and computation; no engine, scheduler, or model code changes.

The issue title and my initial claim comment refer to `usage.metrics`. This change follows the existing documented API contract: `metrics` is a top-level sibling of `usage`, including on the final Anthropic streaming event. Streaming usage is already forced by the Anthropic request conversion.

Duplicate checks: reviewed #64014 and its comments, searched open PR bodies for 64014 and open PRs for Anthropic metrics; no overlapping fix found at submission time. AI assistance was used. Human review is pending; the author requested publication now and will review after waking up.
