# [Bugfix][Benchmark] Preserve inactive expert IDs in synthetic forward routing

[Upstream PR](https://github.com/vllm-project/vllm/pull/65253) · state: closed · merged: True

## Original PR description



## Overview

Preserve inactive `-1` expert IDs in `vllm bench forward`'s Zipf and balanced routing hook. Previously, substituting the synthetic fixture could reactivate masked expert slots.

## Claims

- Inactive slots remain `-1`; active slots receive the same synthetic IDs and routing weights remain unchanged.
- The fixture is not mutated, so subsequent replays can activate previously inactive slots.

## Validation

The focused regression failed all four parameters without the fix and passed with it (positional/keyword IDs, int32/int64). The existing Zipf selection test also passed:

```bash
.venv/bin/python -m pytest tests/benchmarks/test_forward_cli.py \
  -k 'synthetic_expert_ids_preserve_inactive_slots or zipf_expert_selection' -q
```

On GB200, the real Muse router/bias test and both tiny Muse CLI configurations passed:

```bash
.venv/bin/python -m pytest tests/benchmarks/test_forward_cli.py \
  -k 'muse_synthetic_routing or balanced_routing_restores_expert_bias' -v
```

Balanced and Zipf each produced finite, deterministic prefill/decode output with exact graph/eager equality. The CLI uses the gate-logits path without capture-bucket padding; the focused hook regression establishes sentinel preservation. This does not claim end-to-end padded EP performance validation.

File-scoped pre-commit checks passed. GPU validation used `78fc2bbed0`; the rebased routing, test and documentation files are byte-identical. The rebase only reconciled the CI selector with upstream additions. [Validation details](https://github.com/Inferact/vllm-perf-data/blob/main/patches/forward-zipf-padding.md).

## Details

The generic expert-input hook replaced the entire ID tensor without preserving its inactive sentinel. A tensor selection now retains existing `-1` entries. This adds comparison/selection work inside the timed generic hook, without host synchronization. The gate-logits hook and production serving are unchanged. Docs clarify exact-shape benchmark graphs versus serving capture-bucket padding.

Duplicate checks found no competing fix. #64167 introduced the Zipf default and is merged; #57100 concerns the separate MoE kernel benchmark, #65085 concerns forward batch budgets, and #52532 concerns Marlin token ordering.

AI assistance (Codex) was used for implementation, validation, and PR preparation.
