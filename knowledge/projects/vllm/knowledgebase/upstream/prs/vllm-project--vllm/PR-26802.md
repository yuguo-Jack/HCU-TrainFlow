## Code Review

This pull request introduces Service Level Objective (SLO) management tools, primarily by adding a `tier` parameter to requests for admission control. This new mechanism allows dropping requests based on queue length and the number of pending context tokens. The changes are propagated through the configuration, protocol, and engine layers.

My review identifies a few critical issues in the new validation logic within `vllm/v1/engine/async_llm.py`. These include incorrect attribute access that would lead to `AttributeError`, potential `ZeroDivisionError` exceptions, and a type-related bug where different request parameter types are not handled correctly, which would also cause runtime errors. I have provided detailed comments and code suggestions to address these critical problems.

File: `vllm/v1/engine/async_llm.py` · line 304

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

This method has a few issues:
1.  `self.scheduler_config` is not an attribute of `AsyncLLM`. It should be `self.vllm_config.scheduler_config`. This will cause an `AttributeError`.
2.  The parameter `sampling_params` can be of type `PoolingParams` when called from `add_request` (via `_validate_request_scheduling`), but `PoolingParams` does not have an `n` attribute. This will cause an `AttributeError`.
3.  The division `current_num_requests / max_allowed_requests` can cause a `ZeroDivisionError` if `max_allowed_requests` is 0.

Here is a suggested fix that addresses these points. Note that you will also need to update the signature of `_validate_request_scheduling` to accept `params: SamplingParams | PoolingParams` and pass it along.

```python
    def _validate_max_num_reqs_scheduling(
        self,
        request_id: str,
        params: "SamplingParams | PoolingParams",
        tier: float,
    ) -> None:
        max_allowed_requests = self.vllm_config.scheduler_config.max_num_reqs
        if max_allowed_requests is None:
            return

        current_num_requests = self.get_num_unfinished_requests()
        if max_allowed_requests > 0 and current_num_requests / max_allowed_requests > tier:
            logger.info(
                "Too many requests - dropping request.",
                request_id=request_id,
                current_num_requests=current_num_requests,
                max_allowed_requests=max_allowed_requests,
                tier=tier,
            )
            raise TooManyRequestsError()

        n = params.n if isinstance(params, SamplingParams) else 1
        proposed_num_requests = current_num_requests + n
        if proposed_num_requests > max_allowed_requests:
            logger.warning(
                "The request queue is full.",
                request_id=request_id,
                n=n,
                current_num_requests=current_num_requests,
                max_allowed_requests=max_allowed_requests,
            )
            raise QueueOverflowError()
```

There are a couple of issues in this method:
1.  `self.scheduler_config` is not an attribute of `AsyncLLM`. It should be `self.vllm_config.scheduler_config`. This will cause an `AttributeError`.
2.  The division `current_pending_tokens / max_pending_tokens` can cause a `ZeroDivisionError` if `max_pending_tokens` is 0.

Here is a suggested fix.

```python
    def _validate_max_pending_context_tokens_scheduling(
        self,
        request_id: str,
        tier: float,
    ) -> None:
        max_pending_tokens = self.vllm_config.scheduler_config.max_pending_context_tokens
        if max_pending_tokens is None:
            return
        """
        Notes on implementation:
        1. We only check for current pending tokens in queue and do not check
        if the current request's context tokens would go above the limit. This
        is to ensure that large requests can still be scheduled if very low
        requests are in flight.

        2. `get_num_pending_context_tokens` currently does not take chunked
        prefill into account. To take chunked prefill into account, we need to
        share this extra information (how many prefill tokens have been
        processed) from EngineCore to OutputProcessor.
        """
        current_pending_tokens = self.get_num_pending_context_tokens()
        if current_pending_tokens > max_pending_tokens:
            logger.warning(
                "Context tokens in request queue is full.",
                request_id=request_id,
                current_pending_tokens=current_pending_tokens,
                max_pending_tokens=max_pending_tokens,
            )
            raise MaxPendingTokensError()

        if max_pending_tokens > 0 and current_pending_tokens / max_pending_tokens > tier:
            logger.info(
                "Too many pending context tokens - dropping request.",
                request_id=request_id,
                current_pending_tokens=current_pending_tokens,
                max_pending_tokens=max_pending_tokens,
                tier=tier,
            )
            raise MaxTierPendingTokensError()
```

The new request-admission checks read `self.scheduler_config` but `AsyncLLM` never assigns this attribute (only `self.vllm_config` is stored in `__init__`). Calling `generate()` now always hits `_validate_request_scheduling()` and immediately raises an `AttributeError` before a request is even queued.
