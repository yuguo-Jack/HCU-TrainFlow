# [ROCm][benchmark][perf] fix moe tuning script for RDNA

[Upstream PR](https://github.com/vllm-project/vllm/pull/41197) · state: open · merged: False

## Original PR description



## Purpose
Effective tuning for the fused_moe_triton kernel seems crucial. An optimal .json can results in +15% speedup for GLM4.7-Flash model on gfx1100. However, the existing benchmarking script is very slow (>4hrs with 8 GPUs) due to the large search space, with crashes that hang the ray worker indefinitely. 

This PR addresses three problems for RDNA:

- Remove _matrix_instr_nonkdim_ and _kpack_, which are CDNA only. This reduces the search space up to 4 times as they contribute to name hashings. For some Triton versions, using _matrix_instr_nonkdim_=32 on gfx12 results in "no matching matrix core intrinsic" **HARD FAILURE** for tl.dot. (tensorcore/WMMA is always 16*16*16)
- More pruning based on register spilling - some bad configs even cause low level kernel crashes due to cudagraph hitting illegal memory. so this is necessary.
- Proper Triton cache cleanup for Triton 3.6+

Using `16` as a default value for `matrix_instr_nonkdim` on RDNA architectures (where the key is missing from the config) can lead to incorrect pruning of valid configurations. For example, if `M < 16`, a configuration with `BLOCK_SIZE_M > 16` would be incorrectly pruned due to the check `matrix_instr_nonkdim >= M and matrix_instr_nonkdim != BLOCK_SIZE_M` on line 464. Since this parameter is irrelevant for RDNA, the default should be a value that bypasses these CDNA-specific checks, such as `0`.

```suggestion
            matrix_instr_nonkdim = config.get("matrix_instr_nonkdim", 0)
```
