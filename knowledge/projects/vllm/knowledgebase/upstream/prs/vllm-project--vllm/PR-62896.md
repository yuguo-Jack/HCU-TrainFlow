## Details

The warning treated a supported configuration as exceptional without telling users how to evaluate it. Keep the existing condition and give a concise information message with a link to guidance: compare depths and a no-speculation baseline on the same workload, and use acceptance counters as supporting measurements. The docs link to recipes and per-request metrics. They deliberately avoid a universal acceptance-rate target because a higher rate alone does not imply better latency or throughput.
