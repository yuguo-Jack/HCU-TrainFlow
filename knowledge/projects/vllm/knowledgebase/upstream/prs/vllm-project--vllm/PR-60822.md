# [Bugfix][ROCm][MLA] Normalize FlashAttention LSE layout in mixed decode/prefill scheduling

[Upstream PR](https://github.com/vllm-project/vllm/pull/60822) · state: open · merged: False

## Original PR description

## Overview

Fix ROCm MLA chunked-prefill failures by normalizing the log-sum-exp
(LSE) tensor returned by upstream FlashAttention to vLLM's expected
`[num_heads, num_query_tokens]` layout.

Upstream FlashAttention on ROCm returns the LSE tensor as
`[num_query_tokens, num_heads]`. The newer per-request MLA chunk
accumulation path expects the opposite layout. This causes a shape mismatch
when a mixed decode/prefill batch contains a continued prefill.

The normalization is performed at the FlashAttention backend boundary so
the rest of the MLA implementation receives a consistent LSE layout.

## Claims

- Fixes MLA inference crashes on ROCm when chunked prefill produces
  per-request continuation chunks.
- Normalizes upstream FlashAttention LSE output from `[tokens, heads]` to
  vLLM's `[heads, tokens]` contract.
- Preserves the existing CUDA/XPU path, where vLLM FlashAttention already
  returns LSE in the expected layout.
- Does not affect the separate ROCm AITER FlashAttention backend.

The model has 20 attention heads and uses tensor parallel size 2, resulting
in 10 local heads per worker. The failing request had 17 prompt tokens left
to process:

```text
local attention heads = 20 / 2 = 10
remaining query tokens = 128 - 111 = 17
```

The dimensions therefore correspond to these layouts:

```text
Returned LSE: [query_tokens, local_heads] = [17, 10]
Expected LSE: [local_heads, query_tokens] = [10, 17]
```

## Details

The MLA chunk accumulator expects LSE tensors in this form:

```text
[num_heads, num_query_tokens]
```

The upstream ROCm FlashAttention API uses this form:

```text
[num_query_tokens, num_heads]
```

The mismatch became observable after MLA chunked context processing moved to
per-request accumulation. That path copies an individual request's LSE slice
into an output tensor whose token dimension is the second dimension.

The fix converts the upstream FlashAttention result immediately after the
backend call:

```python
if isinstance(attn_out, tuple):
    attn_out, lse = attn_out[0], attn_out[1]
    if (
        not self._is_vllm_fa
        and lse is not None
        and lse.shape != (q.shape[1], q.shape[0])
    ):
        assert lse.shape == (q.shape[0], q.shape[1])
        lse = lse.transpose(0, 1).contiguous()
```

This condition identifies the upstream FlashAttention implementation rather
than a particular AMD GPU model. This avoids touching an already-correct square result,
though it assumes square upstream results are already in the required orientation.

The separate `ROCM_AITER_FA` backend is implemented independently and does
not execute this code. MI-series GPUs are affected only when they select or
fall back to the upstream `FLASH_ATTN` MLA prefill backend.

Older vLLM versions did not expose this failure because they merged MLA
context chunks through the earlier whole-batch accumulation path rather than
performing the new per-request sliced LSE copy.

### ROCm Triton FlashAttention LSE layout

I directly invoked the upstream ROCm Triton implementation
`flash_attn.flash_attn_triton_amd.interface_fa.varlen_fwd` with:

- FLASH_ATTENTION_TRITON_AMD_ENABLE=TRUE
- `q`: `[17, 10, 256]`
- `k`, `v`: `[111, 10, 256]`
- `cu_seqlens_q`: `[0, 17]`
- `cu_seqlens_k`: `[0, 111]`

The returned tensors were:

```text
out:         shape=(17, 10, 256), dtype=torch.bfloat16
softmax_lse: shape=(17, 10),      dtype=torch.float32
```
This confirms that the upstream ROCm Triton varlen implementation returns LSE
in `[query_tokens, heads]` layout. The vLLM MLA chunk accumulator consumes
`[heads, query_tokens]`, so the adapter must transpose the LSE at the backend
boundary.

## Compatibility

- CUDA/XPU using vLLM FlashAttention: unchanged.
- ROCm using upstream FlashAttention: LSE is normalized to vLLM's contract.
- ROCm using the AITER FlashAttention backend: unchanged.
- No public API or configuration behavior changes.
