# [Test][Renderer] Cover the reasoning -> reasoning_content mirror in chat message parsing

[Upstream PR](https://github.com/vllm-project/vllm/pull/56129) · state: closed · merged: True

## Original PR description

## Purpose

`_parse_chat_message_content` mirrors an assistant turn's `reasoning` back under the legacy name `reasoning_content`, for chat templates that still read `message.reasoning_content`. No test covers that line, and it has already broken once: #33402 removed the mirror, which broke GLM and Kimi K2 style templates (reported in #33616), and #33635 restored it four days later without a test. A refactor can drop it silently again, and the model then loses its own earlier reasoning on every turn, which reads as amnesia rather than as an error. This PR adds tests only -- **no production code changes**.

`ChatCompletionRequest` normalizes an incoming `reasoning_content` message key to `reasoning`, so by the time a message dict reaches `_parse_chat_message_content` only `reasoning` is set. That function then puts the value back under **both** names on the `ConversationMessage` handed to the Jinja renderer:

```python
if reasoning is not None:
    result_msg["reasoning"] = cast(str, reasoning)
    result_msg["reasoning_content"] = cast(
        str, reasoning
    )  # keep compatibility
```

Three tests, in `tests/renderers/test_chat_utils.py` (moved there from `tests/entrypoints/unit_tests/` by #60522, together with `chat_utils.py`, which now lives at `vllm/renderers/chat_utils.py`):

- `test_assistant_reasoning_is_mirrored_to_reasoning_content` -- the mirror itself.
- `test_assistant_without_reasoning_sets_neither_field` -- over-correction guard: no reasoning in, neither key out, so a template that renders `reasoning_content` unconditionally does not start emitting empty thinking blocks for ordinary turns.
- `test_non_assistant_reasoning_is_not_mirrored` -- a user turn carrying `reasoning` must not get it.

They drive `_parse_chat_message_content` directly with a text-only tracker stand-in, so they need no model, no network and no accelerator. (This file already imports and tests the sibling private helper `_postprocess_messages`.)

An earlier revision also added a non-streaming test of `include_reasoning` against the usage counter. I removed it: I found no bug on record for it.

### Not a duplicate

Re-searched open PRs touching reasoning / `reasoning_content` / `chat_utils` on 2026-10-10. Two are adjacent, neither overlaps:

- **#52513** ("Normalize reasoning_content on tokenize and pooling chat requests") adds a new `normalize_reasoning_content` helper in `chat_utils.py` (it still edits the pre-#60522 path `vllm/entrypoints/chat_utils.py`) and wires it into the tokenize/pooling request protocols. That is the *input* rename on request types that were missing it; this PR covers the *output* mirror inside `_parse_chat_message_content`, which #52513 does not touch. Textually disjoint (different region of the file, and this PR changes no production line at all).
- **#53340** ("add reasoning_content field ... to ChatMessage") is the response-side protocol. Deliberately not asserted on here: an earlier draft of this PR pinned "`ChatMessage` has no `reasoning_content` field", which would have blocked #53340 for no good reason. That assertion was dropped.

On `main`, a search of `tests/renderers` for `reasoning_content` finds only the Cohere and Inkling renderer tests, which pass it in as input; none covers this mirror.
