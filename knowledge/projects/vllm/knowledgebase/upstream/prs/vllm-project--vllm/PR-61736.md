# [Bugfix] Honor OPT token embedding width for prompt embeddings

[Upstream PR](https://github.com/vllm-project/vllm/pull/61736) · state: closed · merged: True

## Original PR description

## Overview

Fixes #61709. Use OPT's token embedding width for prompt embedding validation and runner buffers so `facebook/opt-350m` works with `--enable-prompt-embeds`.

## Claims

- Accept OPT-350m's 512-wide prompt embeddings and reject its incompatible 1024-wide hidden states.
- Allocate 512-wide input buffers for both model runners, matching `embed_input_ids()` and the decoder's `project_in` input.
- Preserve CLIP/SigLIP text embedding validation when their projection width differs from their hidden size.

## Details

OPT-350m embeds tokens at `word_embed_proj_dim=512`, then projects them to `hidden_size=1024` inside the decoder. Buffer allocation and request validation previously used 1024, causing startup/input-copy failures and accepting embeddings that `project_in` cannot consume.

Add `word_embed_proj_dim` to the input-buffer size lookup and use it for request validation when present. Validation otherwise retains `get_hidden_size()`: using the buffer accessor wholesale would change CLIP/SigLIP validation to their projection width. Both runners share the corrected buffer accessor; no runner-specific branches or inference synchronization are added.

Regression coverage extends existing suites with actual OPT-350m/OPT-125m/CLIP/SigLIP configurations and adds OPT-350m to the model registry and generation comparison matrix. Duplicate searches for `61709 in:body` and `word_embed_proj_dim` found no open PR addressing this fix.
