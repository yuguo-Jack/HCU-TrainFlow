# [Feature][Pooling] Serve late chunking through /v1/embeddings

[Upstream PR](https://github.com/vllm-project/vllm/pull/61772) · state: open · merged: False

## Original PR description

## Overview

Add token embeddings and optional late chunking to `/v1/embeddings` and `LLM.embed`. This is the embedding entrypoint alternative to #61419, requested for comparison in https://github.com/vllm-project/vllm/pull/61419#issuecomment-6161948029. It uses the core from #60164 and RFC #58774.

## Claims

- With the `token_embed` task, both entrypoints return token vectors by default and chunk vectors when `late_chunking_params` is set.
- Chunk results include token and source ranges. The offline example uses `LLM.embed`; `LLM.encode` remains available.
- ORJSON responses reuse the existing ndarray encoder. Ordinary `embed` output and the `/pooling` schemas are unchanged.

## Details

The handler reuses `TokenEmbedIOProcessor` and the existing chunk implementation. Route registration selects the schema for the configured task. Missing or null chunk parameters select ordinary token embeddings; malformed chunk parameters remain errors.

For offline `token_embed`, `LLM.embed` returns the existing `PoolingRequestOutput`, preserving its tensor matrix and chunk metadata. The `embed` task keeps its `EmbeddingRequestOutput` conversion. Existing `LLM.encode` validation rejects unsupported tasks and retains its configuration guidance.

For ColBERT, `LLM.embed` now returns token vectors instead of raising. Explicitly requesting `pooling_task="embed"` remains unsupported, which the updated ColBERT test checks. This does not change which models support late chunking.

The HTTP matrix-valued `embedding` and optional `late_chunking` metadata are a vLLM extension. Only float encoding is supported. Chunking requires plain text; ordinary token embeddings also accept token IDs. Ordinary `embed` servers do not enable chunking and can ignore an unrecognized `late_chunking_params` field. Cohere `/v2/embed`, the batch API and `/invocations` are not extended with chunking. On `token_embed` servers, `/v2/embed` is not registered, changing its unsupported API response from 501 to 404 for models advertising both tasks.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Preserve the ORJSON ndarray fast path**

When `orjson` is available and callers choose a small chunk size (especially `1`) on a long-context, high-dimensional model, this eagerly expands the entire `[tokens, dimension]` tensor into nested Python lists and then validates every scalar through Pydantic. That bypasses the ndarray path used by `ServingEmbedding._openai_json_response` via `encode_pooling_output_float_or_ndarray` even though `json_response_cls` is `ORJSONResponse`; large token matrices can therefore create tens of millions of Python float objects, exhaust frontend memory, and block the shared preprocessing/postprocessing executor. Build the ORJSON payload with the ndarray fast path and retain `.tolist()` only for `JSONResponse`.

Useful? React with 👍 / 👎.
