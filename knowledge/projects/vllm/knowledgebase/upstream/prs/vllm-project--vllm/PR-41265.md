# Migrate gpt-oss-20b MoE backend selection from env var to model kwarg

[Upstream PR](https://github.com/vllm-project/vllm/pull/41265) · state: closed · merged: False

## Original PR description

The `openai/gpt-oss-20b` fusion test was selecting the FlashInfer TRTLLM MXFP8 MoE backend via `VLLM_USE_FLASHINFER_MOE_MXFP4_MXFP8=1` env var set in the test runner (`conftest.py`), instead of using the proper `moe_backend` kwarg attached to the model definition.

## Changes

- **`vllm/config/kernel.py`**: Add `"flashinfer_trtllm_afp8"` and `"flashinfer_cutlass_afp8"` to the `MoEBackend` `Literal` type. These strings were already handled in `map_mxfp4_backend()` but were absent from the type definition, so pydantic would reject them.

- **`tests/compile/fusions_e2e/models.py`**: Attach `moe_backend="flashinfer_trtllm_afp8"` directly to the `gpt_oss_20b` model object, conditional on Blackwell:
  ```python
  gpt_oss_20b = ModelFusionInfo(
      model_name="openai/gpt-oss-20b",
      matches=lambda n_layers: Matches(...),
      model_kwargs={"moe_backend": "flashinfer_trtllm_afp8"} if is_blackwell() else {},
  )
  ```

- **`tests/compile/fusions_e2e/conftest.py`**: Remove the TODO block that set `VLLM_USE_FLASHINFER_MOE_MXFP4_MXFP8` via `monkeypatch.setenv`.
