# [Bugfix][NIXL] Fail pull reads whose producer lease has expired

[Upstream PR](https://github.com/vllm-project/vllm/pull/61549) · state: closed · merged: False

## Original PR description



## Overview

Fixes #61229. In NIXL pull mode, D reads P's KV blocks without checking P's lease. Once P reaps an expired lease and reuses the blocks, D's READ still succeeds and D silently decodes another request's KV. With this PR, D fails such reads through the existing KV load failure path (`kv_load_failure_policy`).

Not a duplicate: #61229 has no fix PR. #59713 (closed, unmerged) is prior art for gating on the producer's lease; this PR differs as described in Details.

## Claims

- A pull read is failed instead of decoded when P's lease has (nearly) expired: checked before the READ is issued and again when it completes, so a lease that expires while the READ is in flight is also caught.
- Healthy requests whose lease D kept alive with heartbeats are not failed, even when they are read after the lease's original expiry.
- No new `kv_transfer_params` key, no handshake change, no `NIXL_CONNECTOR_VERSION` bump.

## Details

**Cause.** Only the bidirectional turn-2 readback was gated on a remote block expiry (`_is_turn2_read_expired`), and P exported `remote_blocks_expiry_time` only from D nodes.

**Fix.**
- P also exports `remote_blocks_expiry_time` in `request_finished`.
- A pull D worker records, per (engine, remote request), the first and last time it sent a heartbeat to every agent of the engine, and the largest gap between them.
- P extends a lease by `kv_lease_duration * 2 // 3` per heartbeat and stamped the expiry E0 before D's first heartbeat, so `(2 * (E0 - first) - 2) / 3` is a lower bound on P's extension without D knowing P's config. If the heartbeats form an unbroken chain under that bound, the deadline is `max(E0, last + bound) - margin`; otherwise it is `E0 - 5 s`.
- D checks the deadline before every pull READ (replacing the turn-2-only gate) and again when the READ completes. Both go through the existing receive-failure path and the KV-expired metric.

**Difference from #59713.** #59713 ignored heartbeats, so it also failed healthy requests that queued past the original expiry while D kept the lease alive; it checked only before the READ; and it added a new key and push-mode changes. This PR credits D's heartbeats, also checks at completion, adds no key, and covers pull mode only.

**Limitations.**
- Conservative: a request whose first heartbeat leaves D within about 10 s of P's lease expiry gets no heartbeat credit and is failed if read after `E0 - 5 s` (`recompute` avoids user-visible errors).
- Clock-offset error beyond the margin, or a heartbeat that was sent but lost, can still allow a stale read.
- Push mode is unchanged: P drives the WRITEs, so it needs a check on the writer thread and a new wire message.
- For HMA models no invalid blocks are reported (existing TODO), so `recompute` is not block-precise there.
- Mixed versions: new D with old P behaves as today. An old D with `bidirectional_kv_xfer` enabled would now also gate turn-1 reads against `E0 - 5 s` without heartbeat credit, so upgrade D before P in that setup.
