# [Mooncake][PD] Support block-aligned multi-group MLA DCP transfer

[Upstream PR](https://github.com/vllm-project/vllm/pull/53205) · state: open · merged: False

## Original PR description

## Overview

Add block-aligned decode context parallelism (DCP) to the Mooncake PD-disaggregation connector for MLA KV caches, including MLA-style latent and index-cache groups used by DSA models. This continues the existing PR; related multi-group design context is tracked in #62243.

## Claims

- Route each transfer group according to its `dcp_sharded` property. Sharded groups use DCP sequence-block ownership; non-sharded groups retain the existing TP transfer path.
- Support different P/D DCP degrees, including DCP enabled on only one side. Each side uses DCP=1 or DCP=TP, and the larger DCP degree must be divisible by the smaller.
- Preserve prefix offsets, completion-only producer replicas, and per-PP-stage completion accounting. Shared registered regions are processed per group when DCP is active.

## Details

Current DCP scope is deliberately limited:

- **P and D must use the same `spec_block_size` (`kv_cache_spec.block_size`) for corresponding transfer groups and the same `interleave_size` (`cp_kv_cache_interleave_size`). For a DCP-sharded group, `spec_block_size == interleave_size`.** Both sizes remain in handshake metadata for future extensions; unequal-size mappings are not implemented in this PR. On a DCP1 endpoint, interleave does not affect token ownership.
- P/D transfer-group correspondence and `dcp_sharded` flags must match. Different P/D group partitioning, independent per-group prefix progress, different kernel block sizes, and different logical-to-kernel split ratios are not added here.
- The connector DCP path is MLA-only. DSA here refers to applicable MLA-style latent/index caches; this does not establish support for all compressed or windowed DSA variants. PCP and DCP-sharded sliding-window/chunked or compressed caches remain outside scope.

The request flow is: D records its prefix offset and group block IDs, bootstrap selects participating P workers, the pull handshake carries the layout and DCP metadata, and P intersects per-group block ownership before writing the payload. When P has DCP disabled, rank 0 sends a sharded group's payload while all participating replicas still acknowledge completion. Blocks are released only after the expected successful completions.

The current changes are based on main at `c7a683bde5909bf2862d5d4500239dd1e3bd44bc`. Repository documentation has not been refreshed for the narrowed multi-group scope in this update and remains a draft follow-up.

Hi @wjinxu, I've rebased #53205 onto the latest upstream main. Thanks for offering to help!

The current scope and constraints are:

- Single KV-cache-group MLA or GQA/full-attention models; hybrid groups, Mamba/GDN, and sliding-window attention are not supported.
- P and D must use the same physical block size, with `cp_kv_cache_interleave_size == block_size`. Logical-to-kernel block splitting is not supported.
- Different P/D TP and DCP sizes are supported when the KV head-group mapping is valid and one DCP size divides the other.
- When DCP is enabled, it must cover all redundant KV-cache replicas; for MLA, this means `DCP == TP`.
- PCP support is outside this update.

I've also completed some basic inference correctness checks on Ascend hardware using DeepSeek-V3.1-Terminus, with MTP disabled. These covered DCP8→DCP8, DCP4→DCP2, and DCP2→DCP4, using short and long prompts around block boundaries, including 1025 and 2049 tokens, and comparing PD output against direct-D inference. The checks exercised KV transfer and answer correctness, but some outputs were not token-identical, so this is not yet a full accuracy validation.

GPU resources are currently limited on my side, so I haven’t been able to validate this on GPUs yet. I’d really appreciate any help with GPU testing or code review. I also plan to gradually extend the implementation to support multiple KV-cache groups, PCP, and other configurations. Thanks again for your interest and support!
