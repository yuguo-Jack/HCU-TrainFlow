### Method

Four runs share identical dataset parameters; each request carries one random
JPEG image (buckets `{(256,256,1): 0.5, (720,1280,1): 0.5}`) plus a 512-token
text prompt, 128 output tokens, serial submission (`--max-concurrency 1`), 20
measured prompts after 2 warmups, seed 42.

| Run | Flags | What it measures |
| --- | --- | --- |
| A — baseline | (no cache) | current behavior without the cache |
| B — cache miss | `--mm-processor-cache-type shm` | every item is a miss: put overhead |
| C — hash hit | B + `--random-mm-share-image` | identical image bytes per bucket; content-hash hits skip preprocessing, fetch/decode still runs |
| D — uuid hit | C + `--random-mm-share-image-uuid` | content parts carry a stable UUID; UUID hits skip fetch, decode, and preprocessing |

Warmup uses the same shared bucket images, so measured batches start with a
warm cache (100% hits in C and D).

### Results (mean / median, ms)

| Stage | A baseline | B cache miss | C hash hit | D uuid hit |
| --- | --- | --- | --- | --- |
| `media_fetch` (base64 + JPEG decode) | 11.46 / 1.82 | 11.31 / 2.03 | 11.28 / 1.78 | **1.14 / 0.00** |
| `preprocess_image` (vision processor) | 2.37 / 0.80 | 3.82 / 1.00 | **0.41 / 0.01** | **0.36 / 0.00** |
| `preprocessor_total` (frontend mm total) | 13.85 / 2.57 | 15.16 / 2.88 | 11.70 / 1.82 | **1.52 / 0.03** |
| end-to-end mean | 416.6 | 421.2 | 394.8 | **384.3** |
| end-to-end p50 | 397.1 | 396.6 | 376.4 | **374.8** |
