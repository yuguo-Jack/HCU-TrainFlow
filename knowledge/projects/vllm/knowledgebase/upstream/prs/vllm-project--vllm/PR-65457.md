# [Bugfix] Keep the extensible tensor's PyCapsule_New prototype private

[Upstream PR](https://github.com/vllm-project/vllm/pull/65457) · state: closed · merged: True

## Original PR description



## Overview

The extensible tensor's DLPack helper configures the process-wide `ctypes.pythonapi.PyCapsule_New`. FlashInfer's MNNVL helpers (`flashinfer.comm.dlpack_utils`) reset that same object's `restype` to `c_void_p`. This PR binds a private `PYFUNCTYPE` prototype instead, so other libraries can't change it. Follow-up to #56492.

## Claims

- Fixes `RuntimeError: from_dlpack received an invalid capsule` in `ExtensibleTensor` views (e.g. `allocate_kv_cache` → `full_view`) when a FlashInfer MNNVL / symmetric-memory buffer was created earlier in the process.
- No behavior change otherwise: the same C function is called with the same signature.

## Validation

- New test `test_views_survive_shared_pycapsule_new_restype_change` in `tests/utils_/test_extensible_tensor.py` sets `ctypes.pythonapi.PyCapsule_New.restype = c_void_p` (what FlashInfer does), then takes a view. It runs in its own spawned process like the rest of the file, so the global change doesn't leak into other tests.
  - Without the fix: fails with `RuntimeError: from_dlpack received an invalid capsule ...`.
  - With the fix: passes.
- `pytest tests/utils_/test_extensible_tensor.py` on GB200: 11 passed.
- End to end: a TP4 model that allocates a FlashInfer MNNVL buffer during weight loading failed in `initialize_kv_cache` on all ranks with the error above. With this change it loads and runs.
- `ruff check` / `ruff format --check` pass.

## Details

Root cause: `ctypes.pythonapi.PyCapsule_New` is one shared `_FuncPtr`, so its `restype` / `argtypes` are global mutable state and the last writer wins. FlashInfer's `create_dlpack_capsule` sets `restype = c_void_p`, after which our call returns an int address instead of a capsule and `torch.from_dlpack` rejects it. `ctypes.PYFUNCTYPE(...)(("PyCapsule_New", ctypes.pythonapi))` creates a separate function object bound to the same symbol, so it is unaffected.

Not a duplicate: no open PR touches `extensible_tensor.py` or this error.
