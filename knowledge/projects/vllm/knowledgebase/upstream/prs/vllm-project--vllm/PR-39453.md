This pull request introduces a new `silu_and_mul` activation function, abstracting its implementation through the `vllm.ir` system. It provides a native PyTorch implementation and registers specific kernel implementations for `vllm_c` and `xpu_kernels` backends. The `SiluAndMul` layer is updated to utilize this new IR-based approach. A review comment suggests refactoring the `silu_and_mul` kernel implementations in `vllm_c.py` and `xpu_ops.py` to a common module to avoid code duplication and improve maintainability.

- gemini-code-assist[bot] · comment · 2026-04-09T21:18:22Z · [source](https://github.com/vllm-project/vllm/pull/39453#discussion_r3060716284)

File: `vllm/kernels/vllm_c.py` · line 72

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

This implementation of `silu_and_mul` is identical to the one in `vllm/kernels/xpu_ops.py`. To avoid code duplication and improve maintainability, consider defining this function in a common module (e.g., `vllm/kernels/common.py`) and importing it in both `vllm_c.py` and `xpu_ops.py`. This will ensure that any future changes only need to be made in one place.

For example, you could have:

**vllm/kernels/common.py**
```python
from torch import Tensor
import torch

def silu_and_mul_impl(x: Tensor) -> Tensor:
    d = x.shape[-1] // 2
    output_shape = x.shape[:-1] + (d,)
    out = torch.empty(output_shape, dtype=x.dtype, device=x.device)
    torch.ops._C.silu_and_mul(out, x)
    return out
```

Then, in both `vllm/kernels/vllm_c.py` and `vllm/kernels/xpu_ops.py`, you can import and register it like this:

```python
from vllm.kernels.common import silu_and_mul_impl

# ...

ir.ops.silu_and_mul.register_impl("vllm_c", supported=CUDA_ALIKE)(silu_and_mul_impl)
```
