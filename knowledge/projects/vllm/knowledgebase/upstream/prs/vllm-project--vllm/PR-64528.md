# [Misc] Bump ruff to v0.17.2 and enable UP032, UP042, B007, F403 and F405

[Upstream PR](https://github.com/vllm-project/vllm/pull/64528) · state: open · merged: False

## Original PR description



## Overview

Bump ruff in pre-commit from v0.14.0 to v0.17.2 one minor at a time, and enable UP032, UP042, B007, F403 and F405, which were ignored until now.

## Claims

- Each bump has its own commit with the fixes it needs: the v0.15 formatter style, ISC004 (v0.16), and removing `noqa` comments that v0.15 and v0.17 made redundant.
- `ruff-format` stays off Markdown (`types_or: [python, pyi, jupyter]`), because v0.16's hook now formats Markdown code blocks and turns `--8<--` snippets into `--8 < --`.
- UP042 converts 21 `(str, Enum)` classes to `StrEnum`. After an audit, the only text that changes is in error and log messages (e.g. `AttentionType.DECODER` becomes `decoder`). No hash, metric label, payload or test assertion is affected.
- Fixes `vllm/model_executor/kernels/mhc/__init__.py`, which listed 12 undefined names in `__all__` (so `from ...mhc import *` raised), and two `SIMPLE_PROMPT`s in the `test_accuracy.py` files that were accidentally 1-tuples.

## Validation

`pre-commit run --all-files` passes on ruff v0.17.2. mypy passes, apart from `cuda_checkpoint_executor.py` errors that also occur on `main`.

```bash
pre-commit run --all-files
.venv/bin/python -m pytest <each touched test file> -q
```

I ran all 109 touched test files on macOS (CPU only). 56 pass. Every failure was checked: each one also happens on the merge base, or comes from the environment (no CUDA, `ray`/`lm_eval` not installed, no `/dev/shm`). CI covers the CUDA-only paths (mhc kernels, machete generator).
