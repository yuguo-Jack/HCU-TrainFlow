## Overview

Add seeded, single-forward Nemotron masked decision reads and adapt the existing structured diffusion example gateway for Choice, Noul and Score. This PR targets upstream main and depends on #58387 and #60287. Tracking: #60283.

[Review the isolated decision delta](https://github.com/pst2154/vllm/compare/94b2a0298...1028340c3) (two commits). The main comparison temporarily includes the unmerged dependencies. This reuses the existing gateway instead of introducing a competing native endpoint.

**Update (October 15):** seeded-read validation moved from `SamplingParams` to `InputProcessor`, dispatched through the HF config's `validate_diffusion_request` hook (canvas may be `None`; Nemotron falls back to `block_size`); tests now go through the engine admission path. The OpenAPI example's description is backend-generic, and the README carries the serve/read instructions in place of the removed model guide. The read-only slot-reuse test now allows 1e-2 (BF16 tiling differs with batch shape on H200, ~5e-3; still tighter than the original 0.02). CPU tests 92 passed / 9 skipped; GPU suite passed on 1x H200, incl. the read-only test twice in eager and compiled mode, the gateway HTTP smoke (100-alternative question) and JevBench 209/231 (BF16).

## Claims

- Keep fixed template tokens while scoring masked answer positions in one bidirectional forward after causal prefill, without a causal verification/commit pass.
- Return exact requested candidate logprobs through the existing indexed-logprob machinery, including candidates outside top-k.
- Validate seeded reads against the engine canvas before worker execution, through a `validate_diffusion_request` hook on the Nemotron HF config (no architecture check in `SamplingParams`).
- Reuse `structured_server.py --backend nemotron` for the separate `/v1/systemone` example gateway. This is not a route built into `vllm serve`.
- **New:** the example gateway accepts up to 128 alternatives per question (previously 26), which covers intent sets such as Banking77. Schemas with at most 26 alternatives render byte-identical prompts.

No ordering heuristics or linear-speculation code are included. The model-runner and its state interface are unchanged.

## Details

The sampler uses staged writes, existing request-slot state and `compute_topk_scores`; read flags and seed canvases reset on slot reuse. The engine canvas is explicitly passed through admission validation.

Reads require greedy masked diffusion, the full engine canvas and `max_tokens <= canvas_length`. The example supports text/JSON state, at most 64 questions and 128 alternatives, one compatible token per answer slot and one deterministic sample. Alternatives are labelled A-Z as before. Wider questions continue with the codes from a-z, 0-9 and two-letter capitals that the tokenizer keeps as one token after `id:`. For the Nemotron tokenizer that gives 52 letters and then two-letter codes; digits are skipped because a space-prefixed digit is two tokens. Wide questions keep the `id: label` line format, because later codes can merge with an id in the compact format. A read requests at most 128 candidate tokens, vLLM's `logprob_token_ids` limit, so questions are also split into separate reads at that limit. More than 128 alternatives would need a larger indexed-logprob limit and is not attempted.

Thinking, images and multi-step reads are unsupported. Returned probabilities are uncalibrated model scores. A graph boundary avoids the previously reproduced SM100 compiler issue but can add launches; no end-to-end speedup is claimed. RTX was not validated.
