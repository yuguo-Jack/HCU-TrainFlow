# [Model Loader] Skip unused tensors with InstantTensor

[Upstream PR](https://github.com/vllm-project/vllm/pull/61449) · state: open · merged: False

## Original PR description

## Overview

Use InstantTensor 0.2.2's pre-I/O tensor filter for models that identify unused checkpoint weights, including supported MTP draft models.

Related: [scitix/InstantTensor#14](https://github.com/scitix/InstantTensor/issues/14), implemented upstream by [scitix/InstantTensor#29](https://github.com/scitix/InstantTensor/pull/29).

## Claims

### Problem

MTP speculative decoding loads a small draft model from the target model's checkpoint. vLLM can already omit checkpoint files containing only unused weights, but retained files can mix required draft weights with unused target weights. InstantTensor previously read every tensor in those retained files.

### Solution

Read tensor names from the safetensors headers and apply the model's existing `is_unused_checkpoint_weight` predicate. Pass the selected names to InstantTensor using exact matching, before native payload I/O starts.

### Benefits

- Unused tensors in mixed checkpoint files no longer need to be streamed.
- InstantTensor's progress total and buffer sizing describe the selected tensors.
- The existing model-specific rules retain shared embeddings and output heads where needed.

This is a selective-I/O feature, not a measured startup-speed claim. Aligned reads can include neighboring bytes.

## Details

### Changes

- Forward the source's unused-weight predicate to the InstantTensor iterator.
- Build an exact allowlist from checkpoint metadata, before source-prefix application or model-specific name mapping.
- Use independent per-GPU reads for sources with a predicate. InstantTensor 0.2.2 rejects filtering with any NCCL process group. Even a predicate that keeps every tensor uses this mode, so filtered loads do not depend on participation by other ranks.
- Return without opening the native loader when the predicate selects no tensors.
- Preserve coordinated distributed loading when no predicate exists, and keep `copy=True` so yielded tensors retain ownership of their storage.
- Require InstantTensor 0.2.2 and update its test requirements.

Independent reads lose InstantTensor's cooperative multi-GPU I/O, so the tradeoff depends on checkpoint layout and storage. This does not implement general pipeline-stage selection, tensor-parallel slicing, or new selection rules for models without the existing hook.
