# Refactor RMS norm quant kernel to use vectorized primitives and enable sm_89+ hardware SIMD

[Upstream PR](https://github.com/vllm-project/vllm/pull/60224) · state: open · merged: False

## Original PR description

# Warning
This code was not tested using the local tests but was tested manually using local scripts that I can provide on demand. That is because the kernel was not registered under helion to run on sm_86 hardware, which was the only available hardware for me. However the int8 refactor could have been tested on sm_86 and that is why I added the PR.
## Overview

Resolves the TODO(luka/varun) in rms_norm_dynamic_per_token_quant_kernel by extracting a type-agnostic vectorized quantization primitive. This unifies element-by-element INT8 and FP8 conversions into a single struct and enables hardware-accelerated packed conversions on supported architectures.

## Claims

Resolves Technical Debt: Replaces the scalar conversion loop in norm_and_quant with a unified ScaledQuantVec4 primitive, addressing the inline TODO.

Architecture-Ready SIMD: Enables fast-path hardware PTX instructions (cvt.rn.satfinite.e4m3x2.f32 and cvt.rni.sat.s8.f32) for vector packing on Ada (sm_89) and Hopper (sm_90+) targets.

Zero Performance Regression: Verified identical latency and bandwidth utilization on Ampere (sm_86), where the kernel safely falls back to standard scalar routines without overhead.

## Validation

Benchmarked prefill and decode shapes across FP8 and INT8 (with and without residuals) on an RTX 3070 Ti (sm_86).

Benchmark Summary (Ampere / sm_86):
Because sm_86 lacks FP8 hardware SIMD, the kernel correctly utilizes the fallback path. Performance remains identical to main, confirming zero overhead from the refactor.

The kernel is not compute bound. That might be why hardware SIMD did not improve performance on sm_86 3070ti.

Profiling confirms the baseline kernel is heavily memory-bound on Ampere (~40% DRAM throughput, ~3% FP32 peak utilization). The performance bottleneck is global memory reads and __syncthreads() during the 3-pass reduction (RMS -> Scales -> Quant), justifying why instruction-level optimization yields neutral results on pre-Ada hardware.

## Details

Details

    Design: Replaced the ScaledQuant scalar functor with ScaledQuantVec4, which takes a vec4_t<float> and returns a q8x4_t.

    Hardware Support: Uses #if defined(__CUDA_ARCH__) && __CUDA_ARCH__ >= 890 to safely branch PTX SIMD instructions away from Ampere/Turing architectures, preventing compilation failures while optimizing for the latest generation.

    Future Work: This struct can now directly replace the duplicated logic in scaled_fp8_conversion_vec in future PRs.
