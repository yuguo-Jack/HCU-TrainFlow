# [Bugfix][Mooncake] Invalidate unattempted KV blocks after split-load failures

[Upstream PR](https://github.com/vllm-project/vllm/pull/63464) · state: open · merged: False

## Original PR description

## Overview

Include unattempted KV blocks in Mooncake Store load-error reporting when a split read stops early. Otherwise, block-level recomputation can retain an unloaded prefix after TP-rank rotation.

## Claims

- Partial failures invalidate failed blocks and all later, unattempted batches.
- Exceptions invalidate the current batch and all later batches.
- Successful loads and local cached blocks are preserved.

## Validation

Base: `7a64fb8fc9239cb65e0df9313fa759594dfb206a`.

Regression: 3 targeted cases fail before the fix due to missing invalid block IDs; all 341 related tests pass after the fix.
Model validation: Qwen3-0.6B-Base, TP=1, produces identical token IDs before and after the fix across six controlled scenarios covering successful loads, partial failures, and exceptions.


## Details

The receiver rotates aligned keys and block IDs, then batches reads to fit the staging budget. Previously, stopping after a failure reported only failed keys, or only the current batch on an exception. Later batches were never read or marked invalid.

For example, read order `[2, 0, 1]` can leave block 1 unloaded when block 2 fails. Reporting only block 2 lets recomputation retain the unloaded block 1. Track the number of keys in fully successful batches to include the unread suffix in error reporting. HMA retains its existing request-level failure handling.
