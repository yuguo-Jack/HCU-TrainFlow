# [Qwen4Exp] Clean up HC and PLE implementations for Qwen3.8-Flash-Next

[Upstream PR](https://github.com/vllm-project/vllm/pull/61454) · state: closed · merged: True

## Original PR description



## Overview

Clean up Qwen4Exp HC/PLE implementations and refine PLE quantization selection, with regression coverage for the affected paths.

## Claims

- **Remove redundant custom-op registrations,** dispatcher wrappers, and fake implementations for NVIDIA HC operations and the shared PLE gate. Call the existing Triton kernel launch functions directly.
- **Move checkpoint shard overlap and copy helpers** into `PLEVocabParallelEmbedding`, using the embedding's own TP shard metadata.
- **Rename HC** `lora_rank` to `hc_lowrank` and local `lora` **variables** to `lowrank` on NVIDIA and AMD. **Use clearer names** for token counts and tensor dimensions in HC and PLE launch functions.
- **Reuse `round_up`** for PLE vocabulary padding, QSA RoPE-position alignment, QSA ring capacity, and prefill logits alignment.
- **Refine PLE quantization selection**: honor ModelOpt layer exclusions, retain serialized FP8 support, **warn and fall back to unquantized PLE for unsupported global configurations**, and reject unsupported explicit ModelOpt per-layer algorithms, embedding dtype overrides, and nonserialized `Fp8Config` usage.

## Validation

**Correctness tests:**

```bash
pytest tests/models/qwen4_exp/test_ple.py tests/models/qwen4_exp/test_hc_ops.py -q
```

Result: **123 passed, 2 skipped**. The skipped cases require ROCm. Coverage includes HC and PLE kernel correctness, checkpoint shard loading, FP8 handling, pinned-host lookup and prefetch, and quantization selection.

**Static checks:** Ruff lint and formatting checks passed for all 12 changed files. `git diff --check` also passed.

**Serving smoke validation:** Qwen3.8-Flash-Next started and served HTTP 200 requests with BF16, TP2/DP1, CPU-offloaded PLE, and MTP with 3 speculative tokens. The run recorded nonzero MTP acceptance.

**CI coverage:** Existing CPU CI covers PLE quantization selection and shard-loading tests. The H200 job covers HC operations and PLE convolution correctness.

End-to-end model accuracy evaluations and before/after performance benchmarks were not run. ROCm hardware execution and quantized-checkpoint serving validation remain pending.

## Details

The unquantized PLE fallback assumes the checkpoint contains an unquantized embedding table. NVFP4 PLE decoding and format conversion remain outside this change.
