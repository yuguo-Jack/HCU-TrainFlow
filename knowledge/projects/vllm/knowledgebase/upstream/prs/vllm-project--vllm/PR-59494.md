# [Bugfix][HiSparse] Fix a chunked-prefill preemption livelock

[Upstream PR](https://github.com/vllm-project/vllm/pull/59494) · state: closed · merged: True

## Original PR description

## Purpose

Fix a HiSparse prefill livelock: a long chunked prefill can be preempted and recomputed from token 0 forever, with no progress and no error.

Two things combine:

1. **The prefill outgrows the pool it was admitted into.** Admission caps each request's resident pages at the in-flight window (`HiSparseResidentSpec.max_admission_blocks_per_request`), assuming older pages move to host. At runtime, a request keeps its resident pages pinned until free GPU blocks fall below a fixed watermark (a tenth of the pool). A chunk that needs more than that is never switched to host reads, so the request is preempted.
2. **The preempted request resumes from nothing.** Host pages were only published once the **whole** computed prefix was durable. Host writes trail a chunked prefill by about a chunk, so nothing was published until the prefill ended. The request found no prefix hit, recomputed from 0, and was preempted at the same point again.

## Changes

`vllm/v1/hisparse/coordinator.py`:
- Publish the durable prefix of a pending publication as it becomes durable (`min(computed tokens, ready pages)`), instead of all-or-nothing. A preempted prefill resumes from it. When the whole prefix is durable this publishes exactly what it did before.
- `update_residency` also switches a request to host reads (asks for a hot region, then releases its written-back pages) once its resident pages fill the window admission reserved for it. Runtime then enforces the assumption admission makes, so these preemptions no longer happen.

`vllm/v1/core/single_type_kv_cache_manager.py`: `max_admission_blocks_per_request` becomes public so the coordinator can read it; `HiSparseResidentManager` declares it as `int` (always set for resident specs). No behavior change.

## Test Plan

- New `test_hisparse_preempted_prefill_resumes_from_durable_prefix`: chunk 1's writes are acked after chunk 2 is allocated, then the request is preempted; the resumed request must hit chunk 1's pages.
- New `test_hisparse_prefill_reads_host_once_it_fills_admission_window[4-True, 3-False]`: a prefill that fills its admission window requests a hot region while free blocks are still above the watermark; one below it does not.
- `test_hisparse_terminal_prefix_waits_for_all_workers_and_preserves_identity` now expects the page every worker finished writing to be published (it previously pinned all-or-nothing publication).
- Engine repro on H100: shrunk DeepSeek-V3.2 (8 layers: indexer + 8 resident groups share the GPU pool), 8192-token chunks, eager.
- `tests/v1/e2e/general/test_hisparse.py`; HiSparse unit tests across `tests/v1` (`-k hisparse`).
