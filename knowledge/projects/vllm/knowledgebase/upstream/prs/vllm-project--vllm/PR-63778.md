# [MRV2] Let the runner decide whether to profile CUDA graph memory

[Upstream PR](https://github.com/vllm-project/vllm/pull/63778) · state: closed · merged: True

## Original PR description



## Overview

Small follow-on to #58243: drop the encoder CUDA graph eligibility check that PR added to `Worker.determine_available_memory`, and let the MRV2 runner decide whether there is anything to profile.

## Claims

- For MRV2, the worker always calls `profile_cudagraph_memory()`. The runner already returns 0 up front when decoder mode is `NONE` and `needs_cudagraph_capture()` is False, so the worker no longer needs its own copy of the encoder rule (`cudagraph_mm_encoder and not enforce_eager`).
- No behavior change. MRV1 is unchanged.

## Validation

- Pre-commit (ruff, mypy) passes.
- No new tests: the runner-side early return is already covered by `tests/v1/worker/test_gpu_model_runner_v2_cudagraph_profiling.py`.

## Details

The early return in the runner runs before any `gc` / `empty_cache` / KV bootstrap, so calling it unconditionally costs nothing measurable at startup.
