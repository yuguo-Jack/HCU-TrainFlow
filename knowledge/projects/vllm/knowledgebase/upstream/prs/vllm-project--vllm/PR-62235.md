# [Bugfix] Keep client-written FT status keys when the engine core pushes status

[Upstream PR](https://github.com/vllm-project/vllm/pull/62235) · state: open · merged: False

## Original PR description

`AsyncMPClient._engine_status` has two writers and they were stepping on each other.

The engine core republishes its whole status payload on every push. The client's own
`handle_fault()` also writes `last_ft_request_id` and `ft_error` into the same entry when an FT
apply fails (`core_client.py:1444-1445`). The push did `_engine_status[idx] = payload`, so the
next status update from the engine core wiped both client keys, and the engine core never
resends them because it does not know they exist.

The user-visible effect is that `GET /fault_tolerance/status` loses the only record of why a
recovery attempt failed, which is exactly when an operator wants it.

It also makes an existing test racy. `tests/v1/fault_tolerance/test_fault_tolerance_e2e.py`
waits for `last_ft_request_id` to appear and then asserts `"status is DEAD" in ft_error`. That
only passes if no engine status push lands in between.

## The fix

A small helper that replaces the engine-owned keys and carries the two client-owned ones over.

I deliberately did not use `entry.update(payload)`. A plain merge would leave a stale
`fault_info` behind after a recovery push, which trades one wrong answer for another. Replacing
and carrying over keeps the engine core authoritative for everything it actually sends, and a
push that carries `ft_error` itself still wins.

## Test

New `tests/v1/engine/test_engine_status_cache.py`, five cases: the carry-over, the replace of
engine-owned keys, a push for an engine not yet in the cache, a push that carries a client key
itself, and that other engines' entries are untouched. It lands in a directory
`test_areas/engine.yaml` already globs, so no CI config change.

Ran the five tests against the function as it appears in the patched file, plus a negative
control with the old body, which fails on `KeyError: 'last_ft_request_id'`. ruff, format, SPDX
and test tethering all pass.
