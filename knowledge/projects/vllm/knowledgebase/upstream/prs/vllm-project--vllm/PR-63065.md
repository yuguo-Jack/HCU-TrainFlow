# [Bugfix][Distributed] Enable expert parallelism in test_expert_parallel

[Upstream PR](https://github.com/vllm-project/vllm/pull/63065) · state: open · merged: False

## Original PR description

## Overview

`test_expert_parallel.py` has not actually enabled expert parallelism because #14305 removed the `VLLM_TEST_ENABLE_EP` env var. This PR passes `--enable-expert-parallel` on the EP side so the test compares EP vs TP MoE execution again.

## Claims

- The EP-side server now genuinely runs with expert parallelism (previously both servers launched with identical args and EP disabled, so the test only verified run-to-run determinism).
- The TP baseline uses the same `distributed-executor-backend` as the EP side, making it a single-variable comparison (the baseline previously hardcoded `mp`, so `ray` cases differed in two variables at once).
- Removed the dead `VLLM_TEST_ENABLE_EP` env dicts and a no-op `try/except: raise`.

## Validation

Test-only change; no effect on serving behavior or model outputs.

```
pytest tests/distributed/test_expert_parallel.py -v -k "DeepSeek-V2-Lite"   # 1 passed (150s, tp=2)
pytest tests/distributed/test_expert_parallel.py -v -k "Mixtral"            # 1 passed (148s, tp=4)
```

Both cases assert exact equality of greedy and seeded-sampling outputs between the EP and TP servers. EP engagement confirmed in the EP-side server log (DeepSeek-V2-Lite, tp=2):

```
[EP Rank 0/2] Expert parallelism is enabled. Expert placement strategy: linear.
Local/global number of experts: 32/64.
```

`pre-commit run --files tests/distributed/test_expert_parallel.py` passes.

## Details

#14305 replaced the `VLLM_TEST_ENABLE_EP` env var with the `--enable-expert-parallel` CLI flag but did not update this test, leaving `VLLM_TEST_ENABLE_EP=1/0` read by nothing ever since.

Design notes:

- Both servers share `common_args` and differ only in `--enable-expert-parallel`, keeping the comparison single-variable.
- The TP baseline now uses the same parametrized `distributed_backend` instead of hardcoded `mp`.

**One point is worth discussing**. Both models in `TEST_MODELS` are natively bf16, yet the test forces `--dtype float16` ("for speed and memory savings in CI"). Since fp16 and bf16 are both 2 bytes wide,  changing this will avoid the narrowed exponent range of the bf16→fp16 cast without more memory needed. Now that the test actually compares EP vs TP, should this be `--dtype auto` (or `bfloat16`) instead?
