# [CI] Move V1 Attention, core kernels and quantization AMD mirrors from fixed to automatic shards

[Upstream PR](https://github.com/vllm-project/vllm/pull/61862) · state: open · merged: False

## Original PR description

## Purpose

Moves four AMD mirrors from fixed pytest shards to `automatic_shard`, the way #61200 and #61477 moved their CUDA steps. For each mirror: `parallelism` is dropped, `--shard-id`/`--num-shards` come off the commands, `Shard %N` comes out of the label (the generator adds `shard N/M`), and `automatic_shard: true` is set. No tests change.

| Mirror | Was | Planned shards |
|---|---:|---:|
| `amd-v1-attention-h100-mi300` | 2 fixed | 3 |
| `amd-v1-attention-b200` | 2 fixed | 4 |
| `amd-kernels-core-operation-test` | 3 fixed | 3 |
| `amd-quantization` | 4 fixed | 3 |

The MI300 V1 Attention mirror had two `commands:` keys in one block. YAML keeps only the second, so the first (`pytest -v -s v1/attention`) never ran; it's removed, and the commands that run are the same as before minus the shard arguments.

The Quantization mirror also ran its two `rocm/` test files only on the first shard, behind `if [ "$$BUILDKITE_PARALLEL_JOB" = "0" ]`. Those guards come off, so they are plain pytest commands the plan places like any other.

The Extended Pooling mirror was in this PR, but main moved it to a different AMD queue (#61955), which has no per-file timings for it yet. The planner would fall back to one job, close to the step's timeout, so it stays on fixed shards until that queue has timings.

`.buildkite/test-amd.yaml` still carries the old `Shard %N` labels; it's a separate pipeline file and is left as is.

## Test Plan

- Planned each mirror with ci-infra main's `runtime_shard.plan_step` against this branch and main's `amd-<key>` timings on the mirror's own queue.
- Rendered each mirror with the pipeline generator and ran every shard's `VLLM_TEST_COMMANDS` against a mock test tree, as a PR build and with main's `pytest -p ci_otel` wrapper: every test of every command ran in exactly one shard, with the same env.
- `/ci run` (build 95328, before the rebase): every shard of the four mirrors passed. Passed counts matched main's fixed-shard jobs; skipped counts were a few lower, because with fixed shards each shard counts the module-level skips of files it collects.
- Rebased onto main after #61955; the four mirrors' plans and the harness are unchanged.
