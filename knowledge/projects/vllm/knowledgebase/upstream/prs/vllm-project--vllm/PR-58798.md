# [Perf] Fuse MiMo partial RoPE, value scaling, and packed DiffKV writes

[Upstream PR](https://github.com/vllm-project/vllm/pull/58798) · state: open · merged: False

## Original PR description

## Purpose

MiMo's DiffKV attention prepares partial RoPE, scales V, and writes the packed KV cache in separate steps. This change combines that preparation into one Triton kernel for unquantized CUDA DiffKV attention, returning a fresh rotated Q while preserving the input QKV allocation. It supports the MiMo V2.6 QK192/V128 layout with rotary width 64 and retains the existing attention wrapper and backend.

The model selects this path for stock rotary embeddings with FA-DiffKV or Triton-DiffKV, FP16/BF16 storage, and DCP=1. Other configurations keep the existing path. Cache addressing uses actual strides and 64-bit token/head arithmetic; padded or negative slots skip stores while still producing Q.

Related work covers different operations: #58128 handles FP8/config propagation, #58177 prefill tiling, and #58141 multi-token split-KV. The standard-attention fusion in #57271 and #52363 does not cover MiMo's QK192/V128 layout, partial rotary width 64, and V scaling. #47535 and #52468 optimize standalone cache writes. This change combines rotary, scaling and cache writes; its measurements do not isolate the benefit remaining after a future merge of those writer optimizations.

## Test Plan

```bash
.venv/bin/python -m pytest --noconftest tests/kernels/attention/test_cache.py -k rope_and_cache_diffkv -v
.venv/bin/python -m benchmarks.kernels.benchmark_mimo_rope_cache --backend both --output mimo-rope-cache.json
```

The benchmark compares native Inductor RoPE/V scaling (`combo_kernels=True`, `benchmark_combo_kernel=True`) plus the existing cache writer against the fused kernel, with the same attention consumer. It records alternating A/B/A controls, eight rounds, and eight calls per captured CUDA Graph. Samples have warm intra-sample L2 and exclude projections, metadata construction and model serving.

## Test Result

On one NVIDIA B200, Torch 2.13.0+cu130 / Triton 3.7.1:

- All four added repository tests passed, using C++ rotary plus the existing cache writer as the exact reference. The isolated run used `--noconftest`; no full repository suite or upstream CI pass is claimed.
- A separate correctness harness passed 12 BF16/FP16 configurations, both rotary layouts, partial-width tails, offset/strided inputs and cache, shortened/negative slot maps, and CUDA Graph replays with changed metadata. A physical 6.60 GB allocation crossed a 3.3-billion-element head offset with exact output/store/guard checks.
- Six actual `MiMoV2Attention` cases with random QKV/output projections passed on both backends, including graph replay with changed buffers. The compiled case was bitwise equal; eager native BF16 produced small expected intermediate-rounding differences within the declared tolerances. Schema, FakeTensor and AOT dynamic opchecks passed.
- All 16 final benchmark cases had bitwise-equal Q, cache and attention outputs. A CPU source-contract probe checked 15 dispatch configurations and the profiling/fake paths; this does not claim distributed runtime coverage. All applicable pre-commit checks passed.

Final FA4 results (the automatically selected DiffKV implementation on this B200), median microseconds:

| Case | Native | Fused | Speedup |
|---|---:|---:|---:|
| Full decode, KV32K, Q/KV64/4 | 35.662 | 33.216 | 1.074x |
| SWA128 decode, batch 1, Q/KV64/8 | 10.762 | 7.993 | 1.346x |
| SWA128 decode, batch 8, Q/KV64/8 | 12.029 | 8.454 | 1.423x |
| SWA128 decode, batch 64, Q/KV8/1 | 11.786 | 8.460 | 1.393x |
| Full verify, batch 4 x query 8, KV4096 | 54.193 | 51.104 | 1.060x |
| SWA128 prefill, query 256, KV512 | 28.978 | 22.066 | 1.313x |
| SWA128 prefill, query 2048, KV4096 | 156.643 | 122.864 | 1.275x |
| SWA128 prefill, query 8192, KV8192 | 592.329 | 456.829 | 1.297x |

FA4 A/A control ratios ranged from 0.988 to 1.021; using the faster baseline control, the batch-8 speedup is 1.394x. Explicit Triton-DiffKV also improved in all eight tested cases, with larger SWA gains than the 1–2% full-attention differences. Its largest A/A difference was 4.65%, so small changes should be interpreted with that control in view.

These are bounded attention-path measurements, not model E2E or service-throughput results. The GPU environment used pinned prebuilt vLLM binaries (`0.30.1rc1.dev143+g29468dde8`) with the tested current Python sources overlaid; it was not a full fresh build of main. No full model weights were downloaded. H100, GB10, multi-rank DCP and quantized caches were not benchmarked.

Implementation and validation were AI-assisted.

The prefill rows are the ones that matter for us: 40 of MiMo's 48 layers are SWA(128) and each carries one of these rope+write calls per step.

## Two observations that may be useful for the PR

1. **The rotation convention is not the one `RotaryEmbedding.forward_static` produces on this fork.** My first cross-checks against `forward_static` showed large deltas that grew with position, which looked alarming; it turned out `forward_static` and your kernel index the cos/sin table differently here, and against your kernel's own formula the outputs are exact. If the GPU test in the PR compares against `forward_static`, it may be comparing two different conventions — worth double-checking which reference your `test_cache.py -k rope_and_cache_diffkv` case uses.
2. **Overrunning the cos/sin table is a hard device-side assert**, not a bounds check (I hit it by passing positions past `len(cache)` while sizing a test wrong). Not a defect — just noting it behaves as a hard fault if the table is undersized, which is fine for the real call path.
