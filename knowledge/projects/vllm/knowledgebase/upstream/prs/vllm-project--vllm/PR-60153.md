# [ROCm][DSv4.1][Perf] Route gfx942 mHC seams through aiter mhc_fused_post_pre_delayed

[Upstream PR](https://github.com/vllm-project/vllm/pull/60153) · state: open · merged: False

## Original PR description

## Summary

On gfx942, DeepSeek-V4.1-Flash prefill runs the delayed mHC seam as separate AITER kernels. This routes the carried attention seam and every FFN seam through `torch.ops.vllm.mhc_fused_post_pre_delayed_aiter`, which calls [aiter #6171](https://github.com/ROCm/aiter/pull/6171) `mhc_fused_post_pre_delayed`, from 64 tokens. Shorter steps stay on the folded post GEMM. Layer 0 and Engram stay on the current AITER seam.

vLLM #59802 overlaps the mHC gate projection on gfx950 and does not change this prefill seam.

## What changed

- `vllm/model_executor/layers/mhc.py`: calls the torch op from 64 tokens when AITER's `mhc_fused_post_pre_delayed_asm_supported` accepts the shape. No `gfx942_seam` flag.
- `vllm/_aiter_ops.py`, `vllm/model_executor/kernels/mhc/aiter.py`, `vllm/model_executor/kernels/mhc/__init__.py`: register `mhc_fused_post_pre_delayed_aiter`.
- `vllm/model_executor/warmup/kernel_warmup.py`: one launch at 64 tokens compiles `module_mhc_seam_asm`.
- `vllm/models/deepseek_v41/amd/model.py`: `MHCPreDelayedOp()`. Layer 0 passes `x`. Engram omits `sublayer_out`.
- `tests/kernels/mhc/test_mhc_kernels.py`: 63 stays on the folded post GEMM, 64 calls the ASM seam once, and both match post then pre.

## Gating

Only the DeepSeek-V4.1 AMD decoder constructs `MHCPreDelayedOp`. No flag, no environment variable. A seam with `sublayer_out`, no `norm_weight`, and no layer-0 `x` calls the op from 64 tokens when the probe accepts the shape. The server logs `mhc_seam: aiter mhc_fused_post_pre_delayed from 64 tokens`. gfx950 stays on the RMSNorm route. A build without the symbol stays on the current AITER seam.

AITER's few-token kernel runs below 60 (`MHC_SEAM_SMALL_MAX_T`). The `b40` in the gates binary is not that cutoff, and 64 is not a measured crossover: on this machine the fused kernel was faster at 32, 60, 63, 64, 128, and 8192. The gate counts tokens in the forward. A decode-only step at concurrency 2 or 4 has 2 or 4 tokens and stays on the folded post GEMM. A step that carries a prefill chunk takes the kernel for the whole forward.

## Depends on

[aiter #6171](https://github.com/ROCm/aiter/pull/6171), stacked on [aiter #6168](https://github.com/ROCm/aiter/pull/6168). The kernels are not in this diff. Without the symbol, the server stays on the current AITER seam.

## Performance

Same machine, same AITER build, only this dispatch differs. 4× MI325X (gfx942), TP4, DeepSeek-V4.1-Flash, language model only, speculative decoding off. vLLM `0.31.1rc1.dev1+gbb87d227d`. The on arm logged `mhc_seam: aiter mhc_fused_post_pre_delayed from 64 tokens` and loaded `mhc_seam_v3_b2_stnt`. `vllm bench serve`, 20 prompts, seed 7. Prefill chunks are 16384 tokens.
