# [PD][HeteroArch] Enable nixl kv transfer with heterogeneous buffer device

[Upstream PR](https://github.com/vllm-project/vllm/pull/53554) · state: open · merged: False

## Original PR description




## Purpose

Enable NIXL KV transfer across heterogeneous buffer devices, such as CUDA/XPU/VRAM to CPU/DRAM. E.g., it is valid to set `kv_buffer_device` to `xpu` for prefill and `cpu` for decode.

Previously, when preparing remote NIXL transfer descriptors, the connector always used the local worker's `nixl_memory_type`. This breaks heterogeneous P/D setups where the remote KV buffer resides on a different memory backend than the local worker. For example, a local XPU worker may use VRAM, while the remote producer/consumer buffer may be registered as DRAM.

The previous workaround was to use a host CPU buffer, but this requires an extra copy to the prefill worker's local host memory. With the Prefill (VRAM) → Decode (DRAM) path, we can eliminate this extra copy by leveraging UCX's underlying D2H capability, leading to a better TTFT.

This PR adds `nixl_memory_type` to `NixlAgentMetadata`, allowing each worker to advertise its own NIXL memory type during the handshake. When creating remote transfer descriptors, the connector now uses the remote agent's advertised memory type and falls back to the local memory type only if the remote metadata does not include one.
