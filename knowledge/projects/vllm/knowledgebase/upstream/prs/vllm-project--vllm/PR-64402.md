# [Platform][TPU] Fail fast with installation guidance when tpu_inference is missing

[Upstream PR](https://github.com/vllm-project/vllm/pull/64402) · state: open · merged: False

## Original PR description

## Problem

On a machine with libtpu installed but without `tpu_inference`,
`vllm/platforms/tpu.py` only logs an error and continues, leaving
`TpuPlatform` and `USE_TPU_INFERENCE` undefined. Platform resolution
(`vllm/platforms/__init__.py` -> `tpu_platform_plugin()` returns
`"vllm.platforms.tpu.TpuPlatform"` -> lazy `resolve_obj_by_qualname`)
then fails later with a confusing `AttributeError`, and the user never
sees the "please install tpu_inference" guidance from the log.

## Change

- `vllm/platforms/tpu.py`: the `except ImportError` branch now raises an
  `ImportError` with installation guidance, chained from the original
  import error (`raise ... from e`), so the failure surfaces immediately
  at import time.
- No platform detection logic is changed. `USE_TPU_INFERENCE` remains
  referenced only by this module (verified via code search).
- `tests/platforms/test_tpu.py`: regression test simulating a missing
  `tpu_inference` import and asserting the helpful `ImportError`.

## Verification

- Reproduced the old behavior with an isolated import simulation: the old
  module imports silently with `tpu_inference` absent, and accessing
  `TpuPlatform` raises `AttributeError`.
- With the new module: missing package ->
  `ImportError: tpu_inference not found, please install tpu_inference to
  run vLLM on TPU` (chained from `ModuleNotFoundError`); package present
  -> imports fine with `USE_TPU_INFERENCE = True`.
- Note: I could not run the new pytest file against the full vLLM test
  suite or on TPU hardware in this environment; the test is provided for
  CI.
