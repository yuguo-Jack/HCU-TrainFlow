# [Bugfix][Frontend] Preserve scheduling priority for online and offline beam search

[Upstream PR](https://github.com/vllm-project/vllm/pull/62253) · state: closed · merged: True

## Original PR description



## Overview

Preserve scheduling priority for beam search on `/v1/completions` and `/v1/chat/completions`, and add priority support to offline `LLM.beam_search()`.

## Claims

- Forward the effective body/header priority to every beam expansion instead of silently falling back to engine priority `0`.
- Support offline scalar or per-prompt priorities through the existing priority normalization helper, retaining each prompt's priority across all beam expansions and concurrency batches.
- Preserve default priority `0`, the existing `X-vLLM-Priority` header precedence (including header `0`), and positional-call compatibility.

## Validation

This change forwards scheduling metadata only; model execution, scoring and beam selection are unchanged. ## Details

The ordinary sampling branches already resolve request priority with `_get_priority`. The beam branches skipped that helper, and `BeamSearchOnlineMixin.beam_search` did not accept a priority argument, so every expansion used `engine_client.generate`'s default. Add a defaulted argument at the end of the existing signature and forward it from both serving endpoints through every expansion. No scheduler or model-runner changes. Offline `LLM.beam_search()` gains an optional trailing `priority: int | Sequence[int] | None = None` argument. It reuses `_priority_to_seq`, stores priority on the prompt instance, expands it to current beams and selects it with the same `active_indices` as structured-output filtering before submitting engine requests.

The regressions exercise missing headers, a nonzero header override, an explicit zero header override, omitted/default mixin priority and nonzero mixin priorities. They consume complete frontend responses and check all expansion requests rather than only the initial call.

Duplicate checks refreshed immediately before submission on October 18: open-PR searches for `beam priority` (only unrelated compressed-tensors kernel PR #55232; files inspected), `beam_search priority`, and `57243 in:body` found no same-fix PR. Open beam-title results were also checked against the overnight overlap audit: #60550 handles failed-beam cleanup, #62072 EOS tokens, #52621 stop strings, #59506 length penalty, #60787 encoder reuse, and #36285 structured output. These may touch nearby code but do not address priority propagation. #57243 prompted the adjacent priority-propagation audit; this PR does not claim it introduced the online omission.
