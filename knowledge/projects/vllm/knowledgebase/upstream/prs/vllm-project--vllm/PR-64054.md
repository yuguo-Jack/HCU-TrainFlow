# [Perf][Kernel] Enable split-K 16 for the SM90 BF16x3 router GEMM

[Upstream PR](https://github.com/vllm-project/vllm/pull/64054) · state: closed · merged: False

## Original PR description



## Overview

Enable split-K 16 for the SM90 BF16x3 router GEMM and add the small-M tile that makes it profitable. This builds on the excellent SM90 kernel from #61903; thanks to @ischencheng and the other contributors for the well-designed implementation. We used an agent-driven tuning loop on H200 to extract this follow-up gain.

## Claims

- On 1xH200, CUDA-graph kernel timings improve for all 18 measured M=1/M=8 router shapes by 1.10x-1.22x over the strongest pre-change configuration.
- Split-K 16 also improves the M=16/24/32 boundary for the long-K `(K=8192, E=256)` shape by 1.17x-1.18x.
- The heuristic selects `(8, 64, 4, 16)` for M<=8 and `(32, 128, 3, 16)` where profitable at larger small-batch sizes. A unit test fixes this selection boundary.

Measured M=1/M=8 speedups over the strongest pre-change configuration:

| Router workload `(K, E)` | M=1 | M=8 |
|---|---:|---:|
| MiniMax-M2/M2.5 `(3072, 256)` | 1.10x | 1.11x |
| MiniMax-M3 `(6144, 128)` | 1.18x | 1.17x |
| GLM-4.5/4.6/4.7 `(5120, 160)` | 1.15x | 1.16x |
| Hunyuan-V3 `(4096, 192)` | 1.12x | 1.11x |
| Hunyuan-V4 `(2816, 256)` | 1.11x | 1.10x |
| Step-5 `(4096, 352)` | 1.12x | 1.11x |
| ERNIE-4.5 `(8192, 64)` | 1.21x | 1.21x |
| Beam-1.0 `(5120, 256)` | 1.15x | 1.14x |
| Muse Spark Open `(8192, 256)` | 1.22x | 1.20x |

## Validation

- 1xH200 (GPU3), with the exact patched kernel and test files:

```bash
pytest tests/kernels/test_bf16x3_router_gemm_cutedsl.py -q --tb=short
```

Result: `81 passed, 5 skipped`. The five skips are the existing SM100-only cases.

- Measured router shapes include MiniMax-M2/M2.5, MiniMax-M3, GLM-4.5/4.6/4.7, Hunyuan-V3/V4, Step-5, ERNIE-4.5, Beam-1.0, and Muse Spark Open. Compared configurations passed cross-checks with `rtol=0, atol=2e-5`.
- Ruff, Ruff format, Python bytecode compilation, and `git diff --check` pass.
- A model-level `vllm bench forward` smoke run on a 4-layer MiniMax-M2 dummy-weight model, `decode=32*1@4096`, measured:
  - base: `45047.7 us`, sample spread `0.036%`
  - patch: `45062.8 us`, sample spread `0.012%`
  - The difference is `0.03%`, below run-to-run noise. The router GEMM is only a small part of this model forward, so this smoke run does not demonstrate an end-to-end improvement.
- This is a kernel-level benchmark. End-to-end serving impact is not included.

## Details

- Split-K 16 reuses the existing deterministic rank-order DSMEM reduction. The numerical algorithm is unchanged; only split grouping and configuration selection change.
- Split-K 16 has a larger cluster-reduction cost, so it uses separate H200-fitted coefficients rather than reusing the split-K 8 fit.
- `(8, 64, 4)` is only offered with split-K 16 for M<=24. Beyond that, the heuristic can select `(32, 128, 3, 16)`, which measured faster for the long-K boundary shapes.
- The repeated wave and K-length calculations are extracted into `_config_cost()` and shared by the base and split-16 searches.
- No workspace, synchronization, dependency, or public API is added.

Not a duplicate: #60376 targets SM100 large-batch BF16x3; #50177 and #60681 concern warmup and GateLinear custom-op dispatch rather than the SM90 kernel configuration.
