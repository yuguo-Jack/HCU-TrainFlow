# [Bugfix] Reclaim cached GPU memory during weight loading

[Upstream PR](https://github.com/vllm-project/vllm/pull/57516) · state: closed · merged: True

## Original PR description

## Purpose

Fixes #57440.

During `BaseModelLoader.load_model()`, temporary tensors created in `load_weights()` and `process_weights_after_loading()` (such as FP8/MXFP4 weight repacking buffers) remain reserved in PyTorch's caching allocator pool (`reserved - allocated`). On discrete GPUs, `release_device_memory_under_pressure()` is a no-op because it only runs on integrated GPUs, leaving raw CUDA driver allocations (such as DeepEP v2 `cuMemCreate` / DMA-BUF buffers, `NCCL_CUMEM_ENABLE=1`, or secondary model fit checks via `mem_get_info()`) starved of free driver HBM.

This PR adds `gc.collect()` and `torch.accelerator.empty_cache()` (when `current_platform.is_cuda_alike()`) at the two weight-loading lifecycle boundaries in `BaseModelLoader.load_model()`:
1. Immediately after `self.load_weights(model, model_config)` before `process_weights_after_loading()`
2. Immediately after `process_weights_after_loading(model, model_config, target_device)`
