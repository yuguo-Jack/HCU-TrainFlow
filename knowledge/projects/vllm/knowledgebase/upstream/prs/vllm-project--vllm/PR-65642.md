# [Qwen4Exp] Clean up hybrid cache spec plumbing

[Upstream PR](https://github.com/vllm-project/vllm/pull/65642) · state: open · merged: False

## Original PR description



## Overview

Cleans up how Qwen4Exp describes its hybrid cache. `get_mamba_specs_from_config` becomes a documented `IsHybrid` method, so the platform block-size alignment no longer special-cases Qwen4Exp with `hasattr`. The PLE short-conv state shape gets a single definition, and an unenforced `supports_kv_connector() -> False` is removed from the QSA backends. No behavior change.

## Claims

- `Platform._align_hybrid_block_size` calls `get_mamba_specs_from_config` for every hybrid model. The new `IsHybrid` default builds one `MambaSpec` from the existing shape/dtype classmethods, exactly what the removed `else` branch did. Qwen4Exp keeps its override (GDN state + TP-replicated PLE state), mirroring how `get_mamba_state_copy_funcs` already handles multiple Mamba types.
- The PLE conv-state shape is computed by one helper (`qwen4_exp/common/ple.py::ple_conv_state_shape`). Platform page sizing and the PLE layer's own `MambaSpec` can no longer drift apart. Both now take `num_spec` from `vllm_config.num_speculative_tokens`; the class-level copy previously read `speculative_config` directly.
- `Qwen4ExpQSABackend.supports_kv_connector() -> False` (NVIDIA and ROCm) is dropped.
  - It is only read by `AttentionBackend.validate_configuration` through the backend selector, and the QSA backend is hard-wired by the layer, so the flag was never consulted.
  - It was also misleading: the NIXL connector has a dedicated Qwen4Exp path.

## Details

- **Why a class-level spec list is still needed.** `update_block_size_for_backend` runs after model load, but each worker runs it independently. Under PP a stage only holds its own layers, and the Qwen4Exp PLE layer sits on the first stage only. Computing from config keeps every rank on the same block size.
- **The PLE state can set the page size.** Its state is TP-replicated and `hc_count x hidden` wide, while the GDN state shrinks with TP. On Qwen3.8-Flash-Next with MTP3:
  - PLE is about 246 KB.
  - GDN per rank at TP8 is about 212 KB with a bf16 SSM state, or about 408 KB with fp32.
  - So the PLE state is the largest at TP8 with a bf16 SSM state, or at TP16.
- **ROCm.** The ROCm changes are limited to the shape helper and the removed flag. They were not run on ROCm hardware.
- **Related PR.** The CPU backend for Qwen3.8 (#57294) adds a third copy of the PLE shape classmethod and the same flag. After this lands it can reuse `ple_conv_state_shape` and drop both.
- **Not a duplicate.** No open PR touches `get_mamba_specs_from_config`, the platform `hasattr`, or the QSA `supports_kv_connector` override; #57294 only adds new copies of them.
