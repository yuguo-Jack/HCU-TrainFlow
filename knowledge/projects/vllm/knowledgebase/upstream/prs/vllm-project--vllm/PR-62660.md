# [ROCm][Perf] Opt-in FlyDSL paged-attention decode for ROCM_AITER_FA, with spec-decode verify and draft passes

[Upstream PR](https://github.com/vllm-project/vllm/pull/62660) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Adds an opt-in FlyDSL paged-attention decode to the `ROCM_AITER_FA` backend for FP8 KV caches on gfx950 (`VLLM_ROCM_USE_AITER_FLYDSL_PA_DECODE=1`, default off). The kernel reads the backend's NHD KV cache directly and takes single-token decodes, uniform speculative verify steps of up to 4 query tokens, and the MTP/EAGLE draft passes.

Depends on [ROCm/aiter#5949](https://github.com/ROCm/aiter/pull/5949) (NHD page-64 layout, GPU work plan, multi-token queries, and the public `aiter.ops.flydsl` API this PR calls; needs FlyDSL 0.4.0). Without an AITER that has it, the flag logs one warning and the backend keeps its current decode path. Draft until #5949 is merged and vLLM's ROCm image carries it.

## Claims

- Qwen3.8-2.4T-A95B MXFP4, TP8 on 8x MI355X, 1M input / 1k output / concurrency 2, FP8 KV, `--block-size 64`: median ITL 11.81 ms → 10.37 ms with the flag on (single-token decode). <TODO: re-measure on a public ROCm nightly once #5949 is in>
- Same setup with MTP-3: a verify step of the two requests at 1M context takes 18.2 ms instead of 28.2 ms on Triton `unified_attention`, and the request that decodes alone gets 4.41 ms per token instead of 6.83 ms. On real text (two ~1M-token prompts of public-domain novels), 6.06 ms per token instead of 9.42 ms, with 1302 of 2094 draft tokens accepted.
- The draft passes of speculative decoding use the same kernel and work plan as the target model, instead of `paged_attention_v1`. <TODO: isolated A/B of the draft-pass change; the numbers above come from a build that already includes it>
- No accuracy change: 1M-token passphrase retrieval passes; with MTP-3, gsm8k 0.951 (0.955 without MTP, stderr ~0.006) and RULER `niah_multikey_2` at 256k 25/25.
- Off by default. With the flag off, or on any layer the kernel cannot serve, behavior is unchanged.

## Details

- **Gate.** `rocm_aiter_ops.is_flydsl_pa_decode_enabled()` requires the env flag, gfx950, and an AITER that exports `pa_decode`, `plan_pa_decode`, `pa_decode_nhd_max_query_length` and `pa_decode_default_workgroup_budget` from `aiter.ops.flydsl` (one `hasattr` check, no private symbols). Each layer asks `pa_decode_nhd_max_query_length()` once for its longest uniform query; 0 keeps the layer on the existing decode, so AITER, not vLLM, decides which head sizes and GQA ratios the kernel serves (on gfx950 FP8 head 256: 32 query rows, i.e. 4 tokens at GQA 8 and 1 at GQA 32). A layer also needs an `fp8`/`fp8_e4m3` KV cache, no ALiBi, soft cap, sliding window or sinks, and a KV block size that is a multiple of 64. Unmet requirements are logged and the layer keeps the existing decode. With the flag on, the backend also offers 64-token kernel blocks and prefers block size 64.
- **Which batches.** `_flydsl_takes_decodes()` accepts a decode batch when every sequence has the same query length (1, or a uniform verify step up to the smallest per-layer limit from AITER). Rows of length 0 are full-CUDA-graph padding at the end of the batch. Mixed widths keep `unified_attention`.
- **Work plan.** `_flydsl_plan()` builds AITER's `PADecodePlan` from `seq_lens` on the GPU, with no host readback and the work budget from `pa_decode_default_workgroup_budget()`, and keeps one plan per (batch size, query length). Later steps refresh it in place, so captured CUDA graphs keep reading valid buffers. `build()` and `build_for_drafting()` share it. `build_for_drafting()` takes the query lengths from the host copy of `query_start_loc`, so it adds no GPU sync.
- **Why the draft passes matter.** `build_for_drafting()` skips the decode/prefill split. Before this change it built decode metadata without a plan, so at 1M context the MTP draft passes ran `paged_attention_v1` over the whole prompt while the target ran FlyDSL.
- **Not covered.** gfx942 and other GPUs (the NHD kernel is gfx950 only), BF16 KV caches, sliding-window and sink models, tree attention (non-uniform verify widths fall back). Measured only on Qwen3.8-2.4T-A95B at TP8. CI has no gfx950 runner with #5949, so the tests skip there until the AITER bump.
