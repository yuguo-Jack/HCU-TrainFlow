#  [CI][ROCm] Split MI300 AITER MoE combinations by FP8 quant type 

[Upstream PR](https://github.com/vllm-project/vllm/pull/61894) · state: open · merged: False

## Original PR description

## Purpose

`:amd: (MI300) MoE Kernels Shard 1` keeps hitting its 55-minute timeout even though all of its tests pass (for example amd-ci #14545, and ci #95182 on #59677).

The cause is the AITER `test_modular_kernel_combinations.py` command:
- Its FP8 per-tensor and per-token cases compile CK 2-stage MoE kernels while the test runs, about 10.5 minutes per kernel. The prebuilt kernels in the image can't be used for these cases on gfx942 until https://github.com/ROCm/aiter/issues/5766 is fixed.
- The command is split across 5 shards by hashing test names. Tests that need the same kernel land on different shards, so the same 4 kernels get compiled 12 times per run.
- Shard 1 needed all 4 kernels, so it took about 55 minutes while shards 2-5 took 28-38 minutes.

This PR moves that command out of the 5 shards into two separate jobs:
- `:amd: (MI300) MoE Kernels AITER FP8 Per-Tensor`: `-k "not multigpu and (fp8_tensor or AiterFp8TensorExperts)"`
- `:amd: (MI300) MoE Kernels AITER Other`: `-k "not multigpu and not (fp8_tensor or AiterFp8TensorExperts)"`, the exact opposite filter, so no test is left out.

Each new job keeps the original job's trigger paths, hardware and pool. The 5 MoE Kernels shards keep the other two commands.

## Test Plan

- Took the per-test logs from ci #95182 and mapped each of the 54 single-GPU AITER test cases to the kernels it compiles.
- Checked the two `-k` filters against those test names: together they select the same 54 tests, with no overlap.
- Rendered `test-amd.yaml` with the amd-ci template (`test-template-amd.j2`, minijinja-cli 2.3.1) for a PR run and a nightly run. Both new jobs appear on `mi300_1` with the filters intact.

## Test Result

Expected time, based on the ci #95182 timings:

| Job | Before | After |
|---|---|---|
| MoE Kernels Shard 1 | ~55 min (timeout) | ~10-15 min |
| MoE Kernels Shards 2-5 | 28-38 min | ~10-15 min |
| AITER FP8 Per-Tensor (new) | - | ~39 min (16 tests, 3 kernel compiles) |
| AITER Other (new) | - | ~38 min (38 tests, 2 kernel compiles) |

The longest MoE job goes from about 55 minutes to about 40, and total machine time drops by about 50 minutes per run. I'll confirm with `/amd-ci run` on this PR.
