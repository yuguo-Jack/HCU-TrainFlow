# [ROCm][Perf][DSV4] Keep one decoder-replay row on unfinished prefills on gfx942

[Upstream PR](https://github.com/vllm-project/vllm/pull/61682) · state: open · merged: False

## Original PR description

## Overview

On ROCm, DeepSeek-V4.1-Flash decoder SWA replay (#59039) keeps `min(query_len, 128)` rows through layers 20–39 for every prefill chunk. Keep one row when that chunk does not finish the prompt. The finishing chunk, decode, and prompt-logprobs stay on the window. The check is `current_platform.is_rocm()` in the shared model state. CUDA keeps `min(query_len, window)` and the capture walk that starts at the window.

## Claims

- On ROCm, an unfinished prefill chunk keeps 1 replay row. The chunk that finishes the prompt, decode, and prompt-logprobs stay on `min(query_len, window)`. CUDA takes the previous branch: `min(query_len, window)`, and the capture walk that starts at `layers.window`.
- Median TTFT, one run of 20 prompts: 8k is flat with DSpark on or off. 256k MC2 is −7.1%. 256k MC8 is −4.9%.
- Median TPOT at 256k MC2 is +0.33 ms (+4.2%). On that same run mean TPOT is 7.81 → 7.71 ms, P99 TPOT is 11.88 → 11.47 ms, and tok/s rises. Decode keeps `min(query_len, window)`. The other median TPOT points stay within 0.1 ms, except 256k MC8 at −1.60 ms.
- On ROCm, an empty `decoder_replay_cudagraph_capture_sizes` now includes 1. The previous default started at the 128-token window, so a 1-row replay missed every graph and ran eager. An explicit list that omits 1 is rejected on ROCm for the same reason. CUDA still uses the previous default.

## Validation

### Performance

4× MI325X (gfx942), TP4, DeepSeek-V4.1-Flash, vLLM `0.32.0rc1.dev100+g77154ca61.rocm723`, ROCm 7.2.3. Same process and flags on both arms. The numbers are from the nightly with this kept-length rule. This commit is that rule behind `current_platform.is_rocm()`. With a 128-token window and a capture bound of 512, an empty capture-size list on ROCm is `[1, 2, 4, 6, 8, 12, 16, 24, 32, 48, 64, 96, 128, 256, 384, 512]`. Each entry is a padded replay-batch length that gets a CUDA graph. The baseline arm used the previous default, which starts at 128. The measured one-row arm passed that list explicitly, because the previous default did not generate it. A serve of this head is still required before the PR leaves draft.

QuickReduce is the upstream INT4 path: `Using ['QUICK_REDUCE', 'AITER_CUSTOM', 'PYNCCL'] all-reduce backends`. MXFP8 is the emulation kernel: `Using EmulationMxfp8LinearKernel for MXFP8 GEMM`.

### Accuracy

One-row arm only, probabilistic DSpark (`draft_sample_method=probabilistic`). GSM8K 5-shot, n=1319: strict-match 0.9196 ± 0.0075, flexible-extract 0.9196 ± 0.0075. Published off scores are 0.9272 / 0.9265. RULER `niah_single_2` at 16384, 0-shot, n=500: 1.0. A kernel-level max abs difference was not measured. The synthetic acceptance schedule on the benches is the configured schedule.

## Details

An unfinished 16k chunk was still building a replay batch of up to 128 rows through layers 20–39. One row carries that chunk forward. The chunk that finishes the prompt still replays the window.

`vllm/models/deepseek_v41/nvidia/model_state.py`: `is_prefilling` stays true on the chunk that finishes the prompt, so an unfinished chunk is `num_computed_prefill_tokens + query_len < prefill_len`. On ROCm that request's kept length is 1. `_keeps_rows_np` still keeps every prompt-logprobs row. `layers.window` stays the scalar the gather kernel already reads. `kept_lens` was already a host array, so this adds no device sync. CUDA leaves the limit as `layers.window`, which is the previous `min(query_len, window)`.

`vllm/models/deepseek_v41/nvidia/decoder_replay_cudagraph.py`: when the capture-size list is empty, ROCm also captures `[1, 2, 4, 6, 8, 12, 16, 24, 32, 48, 64, 96]` below the window. The walk from `layers.window` up is unchanged. On CUDA that walk is the whole list. An explicit list that does not contain 1 raises on ROCm.

`amd/model.py` and `amd/vl_model.py` still return the NVIDIA model state. There is no AMD replay-batch class.

The numbers above are gfx942 only. CUDA was not measured. The CUDA lines are the previous expressions. #59039 is the 128-row replay path this trims. #61554 is cold replay under prefill context parallel. #60320 trims DSpark draft context, not these decoder rows.

Depends on: none beyond #59039.
