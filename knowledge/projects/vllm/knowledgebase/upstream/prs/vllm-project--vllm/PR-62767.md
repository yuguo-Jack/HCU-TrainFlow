# [Bugfix] Preserve image normalization constants during dummy loading

[Upstream PR](https://github.com/vllm-project/vllm/pull/62767) · state: closed · merged: True

## Original PR description



## Overview

Preserve processor-derived image normalization constants when an engine starts with `load_format="dummy"`. Register `FusedMMInputNorm.weight` and `bias` as nonpersistent buffers so dummy initialization leaves them intact.

The Qwen3-VL path began using this normalization module in #51289. No existing issue reporting this exact bug or open PR addressing this fix was found in searches for dummy normalization, `FusedMMInputNorm`, and `mm_input_norm`.

## Claims

- Dummy loading preserves the image processor's rescale, mean, and standard deviation transform.
- A regression test in the existing normalization suite verifies unchanged buffer values and correct normalization across all uint8 pixel values.

## Validation

Validated on a CUDA GPU with Python 3.12 and PyTorch 2.13.0+cu132.

| Check | Result |
| --- | --- |
| New regression before the fix | Failed: all three scale values were overwritten |
| Complete image normalization suite after the fix | 30 passed |
| Qwen3-VL-4B-Instruct image PPL, BF16, device normalization enabled | 11.970688 vs reference 11.916607; 0.453829% difference, within the 1% tolerance |
| Applicable pre-commit checks, including mypy and test tethering | Passed |

Reproduction commands from the repository root in a configured test environment:

```bash
.venv/bin/python -m pytest tests/model_executor/layers/test_mm_input_norm.py -v
.venv/bin/python -m pytest 'tests/models/multimodal/generation_ppl_test/test_qwen.py::test_ppl[True-model_info2-32-extra_kwargs2]' -v -s
pre-commit run --files vllm/model_executor/layers/fusion/mm_input_norm.py tests/model_executor/layers/test_mm_input_norm.py
```

The regression exercises `DummyModelLoader` directly; the PPL evaluation uses a real checkpoint. Full trainer-to-engine weight synchronization was not exercised. The regression is covered by the existing Model Executor CI suite.

## Details

The normalization buffers encode `weight = rescale_factor / image_std` and `bias = -image_mean / image_std`. They come from processor configuration, but persistent registration exposes them to dummy weight initialization. Subsequent parameter-only RL weight synchronization does not restore these constants, leaving the vision encoder with incorrectly normalized inputs.

`persistent=False` excludes the buffers from checkpoint state and the dummy loader while retaining normal module device movement. The forward computation and platform kernels are unchanged.
