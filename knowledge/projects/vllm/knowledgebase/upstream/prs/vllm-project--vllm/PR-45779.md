# [DiffusionGemma-26B-A4B-it-NVFP4 ][XPU][Quant] Register NVFP4 emulation linear kernel for XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/45779) · state: open · merged: False

## Original PR description

Loading an NVFP4 (compressed-tensors) checkpoint on XPU fails at engine init with "Failed to find a kernel that can implement the NVFP4 linear layer. Reasons:" and an empty reason list, because _POSSIBLE_NVFP4_KERNELS has CUDA and ROCM entries but no XPU entry, leaving the candidate list empty.

Add PlatformEnum.XPU: [EmulationNvFp4LinearKernel], mirroring the existing ROCM entry. The MoE side already auto-selects the EMULATION backend, so no change is needed there.

Emulation dequantizes FP4 to the activation dtype per forward — a compatibility path, not a performance path — but it makes NVFP4 checkpoints runnable on XPU.

Validated serving DiffusionGemma-26B-A4B-it-NVFP4 on 4x Intel Arc Pro B70.
