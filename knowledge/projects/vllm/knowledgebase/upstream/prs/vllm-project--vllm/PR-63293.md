# [Perf][DSv4.1] Reuse sparse indices across attention layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/63293) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Unify DeepSeek-V4.1 cross-layer sparse-index reuse across NVIDIA and ROCm
attention implementations through one per-forward runtime. This extends the
existing ROCm layer-local caches to the NVIDIA decode/prefill paths and removes
redundant index-building kernels without changing sparse-selection semantics.

## Claims

- **Performance:** build the global decode top-k KV-slot mapping once per index
  source instead of once per consumer layer.
- **Performance:** build the combined prefill top-k/SWA indices once per index
  source instead of once per consumer layer.
- **Consistency:** move the existing ROCm decode/prefill layer-local caches and
  the new NVIDIA reuse paths onto the same source/consumer runtime.
- **Compatibility:** build on the merged #60613 sentinel fix; the runtime
  allocates the cached output and delegates sentinel initialization to
  `combine_topk_swa_indices`.
- **Scope:** reuse is exact, not approximate. All consumers of a source already
  read the same `topk_indices_buffer`; this change reuses their identical derived
  tensors.

## Details

### Motivation

DeepSeek-V4.1 defines a subset of layers as index sources. Each source publishes
local top-k indices into one model-wide `topk_indices_buffer`, and following
consumer layers use that same buffer. Before this change, however, every
consumer independently rebuilt:

1. the local top-k to global KV-slot mapping for decode; and
2. the combined top-k + SWA indices for prefill.

Both results are deterministic functions of the source's shared top-k buffer
and the current batch metadata. Rebuilding them for every consumer adds kernel
launches, workspace traffic, and index-construction latency without changing
the result.

### Implementation

- Add a model-specific `DeepseekV41CrossLayerRuntime` stored in the existing
  per-forward `ForwardContext.additional_kwargs` container.
- Use one backend-independent key schema: decode entries are keyed by
  `(index_source_layer_id, compress_ratio)`, while prefill entries also include
  `compressed_cache_prefix`.
- Keep backend-specific cache values: NVIDIA stores slot mappings plus lengths,
  while ROCm stores ragged decode metadata and ragged prefill indices.
- Source layers invalidate and repopulate their entries. Consumers reuse an
  entry only when the key matches; a different source falls back to building
  its own result.
- Allocate the cached combined prefill index tensors once per source group.
  `combine_topk_swa_indices(out=...)` owns the `-1` sentinel fill, including
  after the merged #60613 fix.
- Share the resulting decode tensors through FlashMLA, FlashMLA MegaAttention,
  and FlashInfer SM120 decode paths.
- Reuse group-local FlashInfer mixed sparse tables for compressed layers while
  retaining the index source in the cache key.
- Keep the state scoped to one `ForwardContext`, reusing the same mechanism
  already used for other cross-layer temporary state in vLLM. DBO microbatches,
  CUDA graph capture, decoder replay, and the next model step therefore do not
  observe stale runtime state.

### Lifecycle and feature coverage

- The prior AMD implementation stored caches on model layers and relied on the
  next source invocation to replace them. The shared runtime instead has the
  same lifetime as one `ForwardContext`, including normal eager/PIECEWISE/FULL
  execution and decoder replay contexts.
- Decoder SWA replay now runs late layers in a separate forward context. Its
  sparse-index intermediates therefore cannot overwrite or observe the parent
  batch's cache.
- PCP and nested DSpark/MTP forwards follow the same context-scoped lifecycle.
  PCP keeps its existing topology limitations.
- Failed forwards release cached tensor references when their context exits,
  rather than retaining the last produced intermediates on model modules.
- CUDA/HIP graph capture keeps stable tensor addresses; replay uses the
  graph-owned buffers without relying on cross-step Python cache state.
- The runtime is compatible with per-ubatch contexts, but DeepSeek-V4.1 Engram
  currently disables DBO/microbatching, so this is not claimed as an enabled
  production speedup today.

### DeepInfer inspiration

The design was informed by DeepInfer's
[`CrossLayerRuntime`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/model_executor/models/v4_modules/cross_layer.py),
which creates a runtime once per model forward and lets source layers publish
values for later consumers.

This change intentionally adopts only that lifetime and producer/consumer
pattern. The runtime is implemented through vLLM's existing
`ForwardContext.additional_kwargs` infrastructure rather than introducing a
parallel execution mechanism. It is also limited to the two derived sparse-index
values in this patch; DeepInfer's shared candidate schedules, prefill KV, and
index-K-KV reuse are out of scope.

### Compatibility and tradeoffs

- No changes are required to `CommonAttentionMetadata` or attention-backend
  interfaces.
- The reuse is restricted to layers that already share an index source and top-k
  buffer, so it does not change sparse-selection semantics.
- The runtime holds at most one source group's derived tensors per phase and is
  released with the forward context.
- Prefill now allocates one combined-index tensor pair per source group instead
  of reusing the layer workspace. This is required to retain the source result
  across consumer layers; its lifetime is bounded by the forward.
- The shared path covers both NVIDIA FlashMLA-family and ROCm AITER sparse
  attention implementations. Local validation here exercises NVIDIA; ROCm CI
  and hardware validation remain required before review.

### Duplicate work

- #57659 was a closed, unmerged decode-only precedent for cross-layer index
  reuse.
- #58818 shares the FlashMLA tile-scheduler plan, not sparse KV indices.
- #60936 parallelizes the combine kernel but still performs it per layer.
- #57434 is the merged ROCm decode precedent for cross-layer top-k
  ragged-metadata reuse. This PR does not duplicate that backend-specific work:
  it consolidates the ROCm caches and brings the same source/consumer protocol
  to NVIDIA decode and prefill.
- No open PR was found that directly duplicates this cross-backend
  DeepSeek-V4.1 sparse-index runtime.
