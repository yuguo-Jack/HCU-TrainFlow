# [CI][ROCm] Compare greedy output only in the AITER attn+quant test

[Upstream PR](https://github.com/vllm-project/vllm/pull/61185) · state: open · merged: False

## Original PR description

## Overview

Fixes the intermittent failure in `:amd: (MI355) Fusion and Compile FP8`: [Buildkite #94104](https://buildkite.com/vllm/ci/builds/94104/list?jid=01a12e24-6a90-4b79-b882-a91da3ba7420&tab=output).

```
FAILED tests/compile/correctness_e2e/test_attn_quant.py::test_rocm_aiter_static_attention_output_correctness
AssertionError: Results for model='...Meta-Llama-3.1-8B-Instruct-FP8' are not the same.

ref_result=    {'test': 'seeded_sampling', 'text': ' Yvonne Cohen and', ...}
compare_result={'test': 'seeded_sampling', 'text': ' Tony and I'm an',  ...}
```

The test was added in [#58099](https://github.com/vllm-project/vllm/pull/58099) and pinned to the v1 model runner from the start. [#61014](https://github.com/vllm-project/vllm/pull/61014) removed that pin as part of the MRV1 cleanup, so it now runs on v2 for the first time.

## Claims

- Only the `seeded_sampling` comparison fails. Every `temperature=0.0` comparison matches, and the unit tests for the same fusion pass with `atol=rtol=1e-2`.
- Fusing output quantization drops a bf16 round-trip, so the two settings agree on the argmax but not on the exact distribution. Sampling at `temperature=1.0` over a 128k vocabulary turns that into a different token.
- The forward pass is bit-identical on v1 and v2, and the fused/unfused gap is the same size on both. What changed is that the v2 sampler draws a different token for seed 33, and that one sits close enough to a boundary to flip. The pin was hiding the problem rather than preventing it.
- This PR compares greedy output only, as [#41102](https://github.com/vllm-project/vllm/pull/41102) already does for the cpu offload test. The five greedy comparisons and the assertion that the fusion fires in all 32 layers are unchanged.

## Measurements

Measured on MI355 by running both settings as servers and asking each the same 100 seeded prompts, plus the top-20 logprobs of the first token:

| compared | seeds that disagree | max abs delta logprob |
|---|---|---|
| unfused vs unfused | 0 / 100 | 0.000000 |
| fused vs fused | 17 / 100 | 0.045204 |
| unfused vs fused | 21 / 100 | 0.158091 |

The unfused path is reproducible across server starts; the fused one is not, so no choice of seed or tolerance makes an exact-equality check on sampled tokens stable here. Greedy output was identical in all of the above.

## Validation

`pytest -v -s tests/compile/correctness_e2e/test_attn_quant.py` on MI355:

- before, on v2: fails with the strings above
- with `VLLM_USE_V2_MODEL_RUNNER=0`: passes
- after this change, on v2: passes in 115.69 s, with `rewrite counts: [32]`
