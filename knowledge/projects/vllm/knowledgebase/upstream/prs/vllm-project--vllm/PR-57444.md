# [Bugfix][Core] Retain fine-grained EAGLE replay checkpoints

[Upstream PR](https://github.com/vllm-project/vllm/pull/57444) · state: open · merged: False

## Original PR description

With EAGLE, Mamba align mode, fine-grained prefix hits, and retention interval 0, scheduler-aligned replay retention can discard a materialized checkpoint that lookup could reuse. For a 95-token prompt with a 64-token Mamba/scheduler block and 16-token hashes, the old calculation selects 0 even though attention through 80 supports a 64-token hit after EAGLE drops 16 tokens.

Use one effective alignment in `get_replay_boundaries()`: the hash block size when partial hash hits are enabled, otherwise the scheduler block size. Compute the identical-resend and longer-sibling candidates with that alignment. The 95-token repeated-prompt hit changes from **0 to 64**, without internal checkpoint export.

This changes retention selection only. It does not change scheduler stops, checkpoint materialization, attention key publication, lookup, EAGLE-drop rules, or the retention configuration. Memory/performance impact is unbenchmarked.

## Known tradeoff

The single-alignment calculation does not retain additional scheduler-aligned fallback states. With a 160-token prompt, attention/Mamba blocks of 64, and hashes of 16, it selects 128 and 144. Attention registers keys at 64, 128, and the final partial tail at 160, but not 144. An identical resend is capped at 159, so attention matches 128 and EAGLE reduces that to 112. Neither selected Mamba checkpoint fits; the resend hit changes from **64 to 0**. A longer sibling still hits **144**.

The test retains this case and explicitly expects the lost fallback. Using one alignment does not repair the underlying attention-key/lookup limitation or preserve every previous hit.
