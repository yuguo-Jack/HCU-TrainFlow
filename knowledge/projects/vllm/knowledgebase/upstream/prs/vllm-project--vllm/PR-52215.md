## Original PR description

# [kimik3][ROCm][Perf]Fuse the MLA q/kv RMSNorm pair in the module forward

## Purpose

Merge the MLA layer's two RMSNorms — `q_a_layernorm` (q_lora_rank) and
`kv_a_layernorm` (kv_lora_rank) — into a single AITER `fused_qk_rmsnorm` launch,
emitted from `MultiHeadLatentAttentionWrapper.forward` when AITER is enabled and a
q latent exists.

Guarded by `torch.compiler.is_compiling()` so compiled models keep using
`MLADualRMSNormFusionPass`. Both paths emit the same
`torch.ops.vllm.fused_mla_dual_rms_norm` op, so this changes only where it is
chosen, not the kernel or its semantics.

## Test plan

Kimi-K3 MXFP4, MI355X TP8, DSpark MTP, ISL 128k / OSL 1k, conc 8, decode-phase
torch trace. K3 is the motivating case: it builds its MLA through
`MultiHeadLatentAttentionWrapper` but is not compiled.

Rank 0 shows `aiter::fused_qk_rmsnorm_kernel<bf16,256,8,true,1>` **144×** = 24 MLA
layers x 6 profiled engine steps, with the paired per-MLA-layer `add_rmsnorm_quant`
launches gone. Remaining `add_rmsnorm_quant` counts are the unrelated per-layer
input/post-attention norms across all 93 layers.

Compiled MLA models are unaffected by construction, and non-AITER builds never
enter the branch.
