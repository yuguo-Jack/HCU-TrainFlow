# [Bugfix] Bill hidden-state extraction at its own KV cache group width

[Upstream PR](https://github.com/vllm-project/vllm/pull/56822) · state: open · merged: False

## Original PR description

## Purpose

Fix KV-cache admission for `extract_hidden_states` on hybrid Mamba/MLA models. The 1-layer hidden-state group was charged at the width of the widest peer group (e.g. 24 MLA layers), so a ~5.4 GiB extraction cache was billed as ~130 GiB and startup failed.

Fixes #56774.

This is not a duplicate of #53074: that PR isolates hidden-state specs from DeepSeek-V4 MLA/SWA packing. This bug is on the uniform-page-size grouping path used by hybrid Mamba/MLA.

## Details

Hidden-state layers are filtered out of target grouping and appended as a singleton with the common page. The shared pool still sizes every block to `max(group width)`, and admission is `bytes_per_block * total_blocks`. The extraction group needs many blocks (small tokens/block), so it pays for unused MLA slots on every block.

Changing only the admission formula would still allocate overlay blocks at that wide width. When a hidden-state group is appended, split every group to one layer so the pool width is one page and extraction is billed at its own width. This only runs with `extract_hidden_states`; models without a hidden-state cache keep the original grouping. The block-outermost packed path is unchanged.

Merged latest `main` (2026-10-19). `get_kv_cache_groups` now lives in `vllm/v1/core/kv_cache_planning.py` (#61183), so the split and its regression test moved there (`tests/v1/core/test_kv_cache_planning.py`), adapted to the new `_pool_bytes_per_block(vllm_config, groups)` / `_max_memory_usage_bytes_from_groups(builder, ...)` signatures. `#50894`'s `_ensure_min_page_size` (TP page scaling for hidden-state extraction) is kept.
