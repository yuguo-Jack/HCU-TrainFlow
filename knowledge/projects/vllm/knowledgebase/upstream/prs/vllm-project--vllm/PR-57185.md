# [Feature] Return the final prompt hidden state from generation

[Upstream PR](https://github.com/vllm-project/vllm/pull/57185) · state: open · merged: False

## Original PR description

## Overview

Allow opted-in generation requests to return the final prompt token's
post-output-normalization hidden state in the ordinary completion response.
Related discussions: #38565, #40804 and #48743.

## Claims

- Exposes `kv_transfer_params.return_last_hidden_state` and returns the vector
  as `kv_transfer_params.last_hidden_state`, with prompt position, layer and
  representation metadata.
- Uses the existing target forward and Model Runner V2 output synchronization;
  no extra forward, pooling, L2 normalization, connector or retrieval RPC.
- Supports offline generation and Python/Rust chat and completions. Extraction
  requires one output token, `n=1`, and non-streaming output.

## Details

The vector corresponds to the last processed prompt position, including chat
template and assistant prefill, used to predict the first generated token.
Missing, wrong-sized or nonfinite results fail the request. Ordinary generation
keeps its existing behavior. Copying and serializing a vector has a cost;
no throughput or retrieval-quality improvement is claimed.

Native Qwen2/Qwen3.5 with V2 are in scope. CPU V2 requires Triton CPU. TP is
allowed; pipeline/context parallelism, speculation, KV connectors, beam search,
resumable inputs and the Responses API are rejected for extraction.

Related proposals include mean pooling (#38565, #40804), connector-based
inline return (#48743), and per-generated-token typed outputs (#59542 /
#59543, currently Python-only). RFC #65056 coordinates selected input-row
export with #57736. This PR keeps a narrower final-prompt-row contract with
Python/Rust HTTP delivery. The overlapping output semantics need maintainer
coordination; this update does not introduce another proposal. Usage and restrictions are in
`docs/features/hidden_states.md`. AI assistance was used.
