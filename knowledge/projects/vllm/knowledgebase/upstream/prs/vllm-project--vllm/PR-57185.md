# [Feature] Return the final prompt hidden state from generation

[Upstream PR](https://github.com/vllm-project/vllm/pull/57185) · state: open · merged: False

## Original PR description

## Purpose

Allow a generation instance to return the final hidden state at the last prompt position on opted-in requests. Applications can reuse their loaded LLM or VLM for prompt-based representations while continuing to serve ordinary generation from the same instance.

The returned vector is the decoder output after final normalization used to predict the first output token. It represents the last processed **prompt** token, including any assistant prefill, rather than the generated token. No additional forward pass, pooling, or L2 normalization is performed. Representation quality depends on the model, prompt, and downstream task; this feature does not establish equivalence to a dedicated embedding model.

### API

Start the server with Model Runner V2 (`VLLM_USE_V2_MODEL_RUNNER=1`). With the OpenAI Python client, against either the Python or Rust frontend:

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="unused")
response = client.chat.completions.create(
    model="Qwen/Qwen3.5-4B",
    messages=[{"role": "user", "content": "Describe a yellow bicycle briefly."}],
    max_completion_tokens=1,
    n=1,
    stream=False,
    extra_body={
        "chat_template_kwargs": {"enable_thinking": False},
        "kv_transfer_params": {"return_last_hidden_state": True},
    },
)
vector = response.model_dump()["kv_transfer_params"]["last_hidden_state"]
```

The response's `kv_transfer_params` contains:

- `last_hidden_state`: one list of `hidden_size` finite floats.
- `token_position`: the zero-based last position of the processed prompt.
- `layer_id`: the text decoder's number of layers.
- `representation`: `"post_final_norm"`.

The same opt-in is available on `/v1/completions` and through `SamplingParams.extra_args` for offline `LLM.generate()`. The request flag and vector key match the standalone plugin's client contract.

### Implementation and scope

Model Runner V2 selects only opted-in, completed prefill rows and copies them through its existing token-output synchronization. The scheduler attaches the vector to the normal completion output and releases the request. Missing, wrong-sized, or nonfinite vectors fail the request. There is no auxiliary hidden-state cache, file export, connector lifecycle, or retrieval RPC.

Initial support is limited to native Qwen2 and Qwen3.5 models on CPU, CUDA, or ROCm with Model Runner V2. CPU V2 requires a working Triton CPU backend. Tensor parallelism is allowed; pipeline and context parallel sizes must be one. Speculative decoding and KV connectors are unsupported for extraction.

Extraction requires one generated token, `n=1`, non-streaming output, and one prompt per HTTP request. Beam search, resumable input, and the Responses API are unsupported. Ordinary requests retain their usual output lengths and streaming support; offline batches can mix ordinary and extraction requests. Rust checks engine support through the startup handshake.

Related proposals include #38565 and #40804 for mean-pooled prompt representations, and #48743 for a broader connector-based inline tensor API. This change has a narrower contract: one existing final prompt row through the normal generation output path. It does not accumulate representations across prompt chunks, reconstruct cached prompt states, or depend on the proposed connector lifecycle changes.

Usage, semantics, and limitations are documented in `docs/features/hidden_states.md`. AI assistance was used in implementation, testing, and preparing this description.
