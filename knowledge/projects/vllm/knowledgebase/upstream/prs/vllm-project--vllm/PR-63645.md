# [CI] Allowlist-shrink batch 3: wire 10 CPU-safe tests into two focused CPU jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/63645) · state: open · merged: False

## Original PR description

## Summary
- Follow-up to #54867 / #58055 / #59050 (test-tethering check): shrinks the allowlist by 10 more entries by wiring CPU-safe tests into one new CPU job in `misc.yaml`, `cpu-distributed-platforms-cli` (`:computer: (CPU) Distributed, Platforms, CLI`, 20 min). It installs nothing at runtime and just runs `pytest` on the prebuilt `image-build-cpu` image, so it is unaffected by the dependency-locking disablements in #63608 / #63609. The whole set runs in well under a minute, so one job avoids paying a second pod startup.
  - Distributed (7): `test_expert_placement.py`, `test_file_store.py`, `test_kvlayout.py`, `test_kv_cache_events.py`, `test_mq_connect_ip.py`, `test_pipeline_partition.py`, `aux_output_connector/test_store.py` (added by #45635).
  - Platforms / CLI / tools (3): `platforms/test_cpu.py` (run with an explicit `VLLM_TARGET_DEVICE=cpu`), `entrypoints/cli/test_serve.py` (added by #53124), `tools/test_config_validator.py` (`tools/` is baked into the CPU test image, `Dockerfile.cpu`).
  - `source_file_dependencies` lists the modules the tests actually import (checked against each test's `vllm`/`tools` imports), not just their own directories: `vllm/distributed/`, `vllm/config/`, `vllm/platforms/`, `vllm/entrypoints/{cli,launchers}/`, `vllm/logger.py`, `vllm/utils/network_utils.py`, `expert_map_manager.py`, `vllm/v1/{core/sched/output.py,outputs.py,worker/gpu/async_utils.py}` and `tools/pre_commit/validate_config.py`.
- Despite the old "multi-GPU" wording on the `test_expert_placement.py` allowlist entry, none of the 10 files need a GPU: all pass with every GPU hidden.
- Rebased over #63608 / #63609, which commented out neighbouring blocks in `misc.yaml` and re-added many allowlist entries; the remaining "CI jobs disabled pending locked ... installation" entries are untouched.
