# [Bugfix] Fix Cohere/Cohere2 compute_logits when LoRA is enabled

[Upstream PR](https://github.com/vllm-project/vllm/pull/65532) · state: open · merged: False

## Original PR description



## Overview

With `enable_lora=True`, engine startup fails for every `CohereForCausalLM` / `Cohere2ForCausalLM` model (Command R, Aya Expanse, Tiny Aya): `AttributeError: 'VocabParallelEmbeddingWithLoRA' object has no attribute 'quant_method'`. This PR fixes LoRA-wrapped embedding detection in `commandr.py`'s `compute_logits`.

## Claims

- Cohere / Cohere2 models start and serve LoRA adapters with `enable_lora=True`. Before this change they fail at engine init.
- No behaviour change without LoRA: the unwrapped path still passes `embed_tokens` directly.

## Validation

New test `tests/lora/test_cohere_lora.py`: `CohereLabs/tiny-aya-global` (Cohere2, 3.35B) plus a synthetic LoRA on layer-0 `q_proj`/`v_proj` with `B = 0`. The engine must start, and greedy output with the LoRA must equal base output.

Run on an RTX 4080 16 GB (WSL2) with vLLM 0.22.1. The `compute_logits` block in 0.22.1 is identical to `main` at 275816d, which this branch is based on. "After" is 0.22.1 with exactly this diff applied.

```
# before (vLLM 0.22.1 as released)
$ python -m pytest -q tests/lora/test_cohere_lora.py
(EngineCore) logits = lm_head.quant_method.apply(lm_head, hidden_states, bias=embedding_bias)
(EngineCore) AttributeError: 'VocabParallelEmbeddingWithLoRA' object has no attribute 'quant_method'
1 failed

# after (same, with this patch)
$ python -m pytest -q tests/lora/test_cohere_lora.py
1 passed, 14 warnings in 112.38s
```

Also checked with real trained LoRA adapters: rank 8, and concatenated adapters up to rank 32, on 7 target modules. Serving 16 adapters per batch on Tiny Aya Global gives greedy output identical to HF + PEFT on the same adapters.

`ruff` 0.14.0 (check and format) and `typos` pass on the changed files.

**CI note:** `CohereLabs/tiny-aya-global` is gated, like the existing `Cohere2ForCausalLM` registry example (`c4ai-command-r7b-12-2024`), so the test needs the CI HF token to have access to it. The test file is picked up by the existing LoRA job in `.buildkite/test_areas/lora.yaml`.

## Details

**Root cause:** `CohereForCausalLM.compute_logits` decided whether `embed_tokens` was LoRA-wrapped with `hasattr(self.model.embed_tokens, "weight")`. `VocabParallelEmbeddingWithLoRA` defines a `weight` property that forwards to `base_layer.weight`, so the check was always true. The wrapper was then passed to `LogitsProcessor`, which reads `lm_head.quant_method`.

**Fix:** unwrap with `isinstance(embed_tokens, BaseLayerWithLoRA)`, the same check `nano_nemotron_vl.py` uses for the same purpose. No other model file uses the `hasattr(..., "weight")` pattern. `Cohere2MoeForCausalLM` (separate file) does not implement `SupportsLoRA`, so it is unaffected.
