# [Bugfix][KV Offload][P2P] Abort inbound loads when draining for a cache reset

[Upstream PR](https://github.com/vllm-project/vllm/pull/65124) · state: open · merged: False

## Original PR description

## Purpose

On a P2P consumer (decoder), `TieringOffloadingManager.reset_cache()` (`/reset_prefix_cache` with `reset_connector`, sleep, weight update) blocks the engine thread in `P2PSecondaryTierManager.drain_jobs()` for the full load timeout plus the abort-ack window (~35 s for PD, ~15 s symmetric) whenever a load waits on a prefiller that never writes. `has_pending_work` counts client loads, and the drain never aborts them.

This is the consumer-side counterpart of #63948, which #63988 fixes on the producer side (stores waiting for a fetch). It came up in review there.

`drain_jobs()` now aborts every inbound load not already aborting before it polls, through the same path a load timeout takes (#64256): `AbortFetch`, fail the job at once, defer the chunk release until the `AbortAck` or the session's `close()`. The drain then waits only for the acks, bounded by `_ABORT_ACK_TIMEOUT_S` (5 s, after which the session disconnects and `close()` releases), so every deferred release is set on return as the `drain_jobs()` contract in `tiering/base.py` requires. Lookup state is untouched.

## Test Plan

- `test_reset_cache_aborts_load_from_silent_peer` (test_manager.py): a real `TieringOffloadingManager` + CPU primary + `P2PSession`; a PD load whose peer only answers `AbortFetch`. `reset_cache()` returns after the ack, the job is finished, the chunk is released, and the session stays up. Fails on main ("drain_jobs waited on a load no peer will write").
- `test_abort_loads_fails_each_load_once` (test_sessions.py): `abort_loads()` aborts each load exactly once (skipping one already aborted by `finish_request`), fails it at once with a deferred release, and the acks release it.
- `pytest tests/v1/kv_offload/tiering/p2p/ tests/v1/kv_offload/tiering/test_tiering_offloading.py tests/v1/kv_offload/tiering/test_tier_poll_thread.py`
