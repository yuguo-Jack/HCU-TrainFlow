# [Perf] DiffusionGemma: skip the self-conditioning matmul on a read's last step

[Upstream PR](https://github.com/vllm-project/vllm/pull/58221) · state: open · merged: False

## Original PR description

## Purpose

Since read-only requests don't commit, we know that self-conditioning is unnecessary.

Approximately ~3% improvement overall in structured queries.

## Test Plan

1. Unit tests: `tests/v1/sample/test_diffusion_gemma_reads.py` and
   `tests/test_sampling_params.py -k "diffusion or read"`.
2. Exact effect: count self-conditioning GEMMs per read in a torch-profiler
   trace, before and after, over a dozen four-step reads.
3. Read correctness on the branch build: grounded 33-field region battery,
   coupled pinned reads at 1/4/8 steps, yes/no slot battery at four widths.
4. Mixed batches: 32-way traffic of reads at several widths and step counts
   beside open generations, checking failures and that the engine stays up.
5. Generation regression: open-generation tok/s sweep at concurrency
   1/4/8/16/32, engine restarted per arm, before and after.

## Test Results

GB10, NVFP4 checkpoint, Triton attention, text-only serving

1. 64 passed, 9 deselected.
2. Self-conditioning GEMMs per read 4.27 -> 3.00 (before: 11 reads, after:
   12 reads). A read runs 3 to 5 denoise passes: early convergence, the cap,
   or one pass the async scheduler queues before it sees the emit. The skip
   covers the cap step and the overshoot pass. About 9 ms of a 330 ms read.
3. Region battery 32/33 (baseline runs: 31 to 33). Coupled pins 22/24 at four
   steps and 21/24 at eight (baseline runs: 20 to 24). Yes/no slots 7 or 8 of
   8 per width, the one miss being the known borderline probe.
4. 671 requests, 0 failed, engine answering afterwards, no tracebacks.
5. Flat within run-to-run spread (variation here is normal run-to-run variance):

   | concurrency | before tok/s | after tok/s |
   |---|---|---|
   | 1 | 79.2 | 73.2 |
   | 4 | 128.4 | 132.8 |
   | 8 | 171.1 | 177.6 |
   | 16 | 190.4 | 201.0 |
   | 32 | 198.3 | 199.5 |

- kamb-code · COMMENTED · 2026-11-04T21:47:09Z · [source](https://github.com/vllm-project/vllm/pull/58221#pullrequestreview-5776311392)

Following the Local AI SIG discussion, I checked this through the real DiffusionSampler.__call__ and prepared four targeted regression cases on an RTX PRO 6000 Blackwell (SM120, CUDA 13.0).

At feb4791822, the four-step read performs three self-conditioning matmuls and skips that matmul on the capped step and on subsequent extra sampler calls. A same-width unfinished read or generation keeps the shared tile's matmul, and reusing the slot with a new cap restarts the schedule correctly. Without this change, exactly the cap and slot-reuse cases fail at the extra matmul; both mixed-request controls pass. With it, all four pass. The 21 existing read tests also pass in a separate invocation, with no skips or errors.

I repeated that A/B on main at da0b6ac221 with this change applied, with the same results. Since #61669 is approved and rewrites the sampler, I also checked a clean composition of that PR at 7711999d with main and this change: the same four cases pass, and removing only this change reproduces the same two failures. That last check covers these four cases, not #61669's whole suite.

The existing sampler-step tests call _compiled_sample_step with compute_sc supplied manually, so these additions cover the host-counter decision that they bypass. They use real state objects and synthetic tensors, with force_eager for profiler-visible matmul counts. This is sampler-level evidence, not an independent serving-speed or model-quality benchmark. The PR-head run used Torch 2.13/Triton 3.7.1; the main-based runs used Torch 2.14/Triton 3.8.

Commands with the test patch applied:
```
pytest -q tests/v1/sample/test_diffusion_gemma_reads.py -k sampler_last_step
# Without change: 2 failed, 2 passed; with change: 4 passed.
pytest -q tests/v1/sample/test_diffusion_gemma_reads.py -k 'not sampler_last_step'
# With change: 21 passed.
```

I can send the test-only patch against mmastrac/vllm:sc-last-step-skip; the main adaptation supplies compute_logits to the newer constructor.
