# [Bugfix] Avoid non-contiguous CPU tensors in Llama-4 ModelOpt weight …

[Upstream PR](https://github.com/vllm-project/vllm/pull/50227) · state: closed · merged: False

## Original PR description

## Purpose

ModelOpt Llama-4 checkpoints (for example, `nvidia/Llama-4-Scout-17B-16E-Instruct-FP8`) use fused expert weights. During weight loading, the sequence of `transpose`, `chunk`, and indexing operations produces non-contiguous CPU tensors. Copying non-contiguous tensors from CPU to GPU is significantly slower than copying contiguous tensors.

This change calls `.contiguous()` immediately before passing the tensor to `weight_loader`, ensuring efficient CPU-to-GPU transfers while preserving existing behavior. Since `.contiguous()` is a no-op for already contiguous tensors, this change is safe and has no functional impact.

Fixes #31624.

## Test Plan

No new tests are required because this is a performance optimization with no behavioral changes.

* Existing Llama-4 tests continue to verify correctness.
* `.contiguous()` is a no-op for already contiguous tensors.
* The change only ensures contiguous memory layout before GPU transfer.

## Test Results

No functional tests were run for this change. The modification is limited to calling `.contiguous()` before `weight_loader` and does not alter the weight-loading logic or model behavior.
