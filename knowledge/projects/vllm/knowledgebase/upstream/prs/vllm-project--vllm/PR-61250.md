# [Kernel] Add FlashInfer GDN and KDA prefill backend selection

[Upstream PR](https://github.com/vllm-project/vllm/pull/61250) · state: open · merged: False

## Original PR description

## Overview

Add FlashInfer prefill selection for Qwen GDN (`auto`/`cudnn`) and all eight public KDA backends for bounded GLM/Kimi KDA, with shared state handling and versioned KDA metadata. This carries the integration from [Anerudhan/vllm#1](https://github.com/Anerudhan/vllm/pull/1); benchmark result files are excluded.

## Claims

- Add separate FlashInfer implementation selectors for GDN and KDA prefill, including `cute-dsl`, `cute-dsl-persistent`, `tirx`, `ptx`, `cake`, and `small-bh` for KDA.
- Share the KDA adapter across Kimi-K3, GLM and the bounded-gate shared Kimi path, including normalization and recurrent-state handling.
- Build contiguous int64 offsets with a tensor version counter for native KDA paths under inference mode. Omit sequence-order hints for persistent CuTe DSL, TIRx and PTX, which reject them.
- Validate hardware, dtype and gate limits. Protect borrowed state, permit updates to temporary gathered state, and reject unsupported cuDNN checkpoint and batch-invariance requests. Add CLI, metadata, state-contract and GPU replay tests.

### New arguments

| Argument | Values | Use with |
|---|---|---|
| `--flashinfer-gdn-backend` | `auto`, `cudnn` | `--gdn-prefill-backend flashinfer` |
| `--flashinfer-kda-backend` | `auto`, `cute-dsl`, `cute-dsl-persistent`, `tirx`, `ptx`, `cake`, `small-bh`, `cudnn` | `--kda-prefill-backend flashinfer` |

Both resolve to `auto` when omitted. `auto` delegates to FlashInfer's dispatcher; explicit choices retain FlashInfer's input checks. The existing provider argument must select FlashInfer to use these paths.

KDA state requirements: `auto`, `cake`, and `small-bh` use BF16; `cute-dsl` and `cudnn` accept BF16 or FP32; `cute-dsl-persistent`, `tirx`, and `ptx` require FP32. Set the existing `--mamba-ssm-cache-dtype` argument to match. Extra shape, GPU and dependency limits still apply. In particular, PTX requires SM103a and H64/H96. Persistent CuTe DSL, TIRx and PTX require an explicit warmed workspace for prefill graph capture; this adapter does not manage it, so use eager prefill for those choices.

```bash
# Kimi-K3: FlashInfer auto prefill with BF16 recurrent state
vllm serve moonshotai/Kimi-K3 \
  --kda-prefill-backend flashinfer --flashinfer-kda-backend auto \
  --mamba-ssm-cache-dtype bfloat16

# Qwen GDN: explicit cuDNN prefill
vllm serve Qwen/Qwen3.5-35B-A3B \
  --gdn-prefill-backend flashinfer --flashinfer-gdn-backend cudnn
```

These examples show backend options; add the model's normal deployment flags.

## Details

The shared adapter calls FlashInfer's public dispatchers. The cuDNN KDA path uses fused additive Q/K normalization and supports bounded gates with `-5 <= lower_bound < 0`. See `docs/configuration/optimization.md` for usage and limits.

Duplicate-work checks found no matching prefill-selection PR. Related #60470 changes KDA decode; #60050 adds GDN checkpoints; #60105 optimizes native GDN gate conversion and offsets. This PR adds explicit prefill implementation selection and shared KDA integration. It does not include those separate optimizations. AI assistance was used.
