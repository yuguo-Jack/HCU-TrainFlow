# feat: add CPU/lint devcontainer with CI workflow and Renovate config

[Upstream PR](https://github.com/vllm-project/vllm/pull/64709) · state: closed · merged: False

## Original PR description



## Overview

Add a CPU-only VS Code dev container for editing and linting vLLM without a GPU, along with a GitHub Actions workflow that validates it and a Renovate config for automated image bumps.

**Not a duplicate:** Five prior devcontainer PRs (#4720, #15684, #38430, #40284, #46500) were all GPU/ROCm-oriented or bundled unrelated changes and were closed as stale without maintainer review. #46536 ("Create devcontainer.json") is an open draft that only edits a pre-commit CI workflow — it contains no devcontainer config. This is the first CPU/lint-only, uv-based devcontainer.

## Claims

- Contributors can open the repo in a fully configured VS Code dev container with a single command, with no GPU required
- The container uses `uv` exclusively (no system Python, no bare `pip`) per AGENTS.md
- A GitHub Actions workflow builds and smoke-tests the container on every PR that touches `.devcontainer/` or `requirements/lint.txt`
- The devcontainer `.venv` lives in a named Docker volume, so it never overwrites a host-side venv
- Renovate config is scoped to `enabledManagers: ["devcontainer"]` only, preventing overlap with the existing Dependabot config

## Validation

Local validation on macOS (Apple Silicon, Docker Desktop):

```bash
# Build and start
devcontainer up --workspace-folder . --remove-existing-container

# Smoke test (same commands as the CI workflow)
devcontainer exec --workspace-folder . bash -c '
  set -euo pipefail
  uv --version
  python --version | grep -F "Python 3.12"
  test "$(command -v python)" = "$PWD/.venv/bin/python"
  pre-commit --version
  test -f .git/hooks/pre-commit
'

# Lint the changed files
pre-commit run --files .devcontainer/devcontainer.json \
  docs/contributing/README.md \
  .github/workflows/devcontainer.yml \
  .github/renovate.json
# → all hooks passed

# Host venv untouched after container build
file .venv/bin/python
# → Mach-O 64-bit executable arm64
```

CI validation: the new `devcontainer.yml` workflow will run automatically on this PR.

## Details

**Base image:** `mcr.microsoft.com/devcontainers/base:2-noble` (Ubuntu 24.04, non-root `vscode` user, multi-arch). The Python devcontainer image was avoided because it ships a system Python with pip, conflicting with AGENTS.md's "never use system python3 or bare pip" rule.

**Volume design:** `.venv` uses a `${devcontainerId}`-suffixed named volume so each devcontainer instance gets its own venv, isolated from the host's macOS `.venv`. A second volume over `~/.cache` persists the pre-commit hook environment (Node, Go downloads) across rebuilds.

**uv install:** uses the official installer (`curl -LsSf https://astral.sh/uv/install.sh | sh`), matching `docker/Dockerfile` and `docker/Dockerfile.cpu`. Subsequent uv calls use `$HOME/.local/bin/uv` explicitly to avoid relying on `remoteEnv` PATH injection during lifecycle scripts.

**Hooks caveat:** `postStartCommand` runs `pre-commit install` on every container start, which rewrites `.git/hooks` with container-internal paths. If you also commit from the host, run `pre-commit install` again on the host. This is documented in the tip admonition.

**Renovate:** scoped to `enabledManagers: ["devcontainer"]` to prevent it from duplicating Dependabot's `github-actions` and `pip` coverage. Effective only after a vllm-project org admin installs the Renovate GitHub App.

**Limitations:** no GPU, no CUDA/C++ build support, Pylance will report unresolved imports for packages not installed in the container (e.g. `torch`).
