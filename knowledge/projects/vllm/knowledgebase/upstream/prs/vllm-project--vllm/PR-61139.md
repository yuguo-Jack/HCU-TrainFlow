# [Perf][Distributed] Skip movedim+reshape for dim=0 in DeviceCommunicatorBase all_gather

[Upstream PR](https://github.com/vllm-project/vllm/pull/61139) · state: open · merged: False

## Original PR description

## Overview

Skip redundant `movedim` + `reshape` tensor view operations when `dim=0` in `base_device_communicator.py`'s `all_gather`.

## Duplicate-work check

Sibling PRs #61136, #61138, #61140 each touch a different function in a different communicator class (`CudaCommunicator.all_gather`, `CudaCommunicator.reduce_scatter`, `DeviceCommunicatorBase.reduce_scatter`); none overlaps with this diff. `gh pr list --search "movedim"` and `--search "base_device_communicator all_gather"` turned up no other open PR touching this function.

## Performance

**Isolated microbenchmark** (the exact removed chain -- `reshape` + `movedim(0,0)` + `reshape` -- timed with no distributed call in the region, 2000 reps, warm-started): median delta ~3.3-3.4us/call, identical to the `CudaCommunicator.all_gather` variant (#61136) since the op chain is the same regardless of which communicator subclass calls it.

**Platform reachability -- important caveat**: `CudaCommunicator` and `CpuCommunicator` both override `all_gather`, so on CUDA and the CPU backend this base-class method is **not** reached in production. `XpuCommunicator` does **not** override `all_gather`, so this fix is only exercised by the Intel XPU backend. I do not have XPU hardware available, so I could not run an end-to-end validation on the actual production path for this specific PR -- only the isolated CPU-side-overhead number above, which is hardware-independent since it measures pure Python/ATen dispatch cost, not device execution. If anyone with XPU hardware can confirm the code path and re-measure end-to-end, I'd appreciate it; happy to close this if it turns out not to matter for XPU's actual workloads.

**Applicability**: like the CUDA variant, this only saves time in eager execution; under CUDA/graph-equivalent capture (if XPU uses an analogous mechanism) a no-op reshape enqueues no device kernel, so the benefit is per-call Python overhead only, not device time.

## Claims

- Eliminates 2-3 redundant tensor view operations per `all_gather(dim=0)` call on the XPU backend, measured at ~3.3-3.4us/call in isolation (see Performance)

## Validation

- `ruff check` and `ruff format --check`: all passed
- When `dim=0`, `movedim(0, 0)` returns the same tensor and `reshape` produces the same shape — skipping is behavior-preserving
- Isolated microbenchmark: see Performance section above (no end-to-end XPU validation; see reachability caveat)

## Details

`all_gather` in `base_device_communicator.py` calls `movedim(0, dim)` and `reshape` on every invocation. When `dim=0`, these are no-ops creating intermediate Python tensor objects. Return the output tensor directly after the collective.
