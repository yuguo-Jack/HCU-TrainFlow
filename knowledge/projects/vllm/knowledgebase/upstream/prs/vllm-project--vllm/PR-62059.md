# [ROCm][CI] Persist compile and AITER JIT caches across native AMD CI jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62059) · state: closed · merged: False

## Original PR description

Native AMD CI pods are ephemeral and point TORCHINDUCTOR_CACHE_DIR, TRITON_CACHE_DIR and VLLM_CACHE_ROOT at /tmp/vllm-native-<job>, so every job compiles from scratch: in nightly build 14707, 1,613 torch.compile runs had 14 cache hits, and AITER rebuilt the same MoE modules in every MI300 MoE Kernels shard (~10 min per module, 116 min per nightly).

Behind VLLM_CI_PERSISTENT_COMPILE_CACHE=1, restore one archive per job (Inductor, Triton, vLLM cache root including modelinfos, and newly built AITER .so modules) from the persistent HF volume before the tests and save it after them. The key covers GPU arch and torch/triton/aiter versions; the archive is replaced atomically by its own job key, so no file locks are needed on the shared NFS volume. PR builds only restore.

Measured on MI300X with the CI image of build 14821:
- MoE padding-matrix test: 201 s cold -> 79 s warm (AITER build of 113 s here; 587 s on CI MI300 pods).
- MRV2 eagle test, first two engine starts: 206 s -> 76 s; torch.compile 18.3 s -> 0.2 s and model-info inspection 11.8 s -> 0.3 s per start.
