# [ROCm][Misc] Write GDN prefill output in place for the Triton and FlyDSL backends

[Upstream PR](https://github.com/vllm-project/vllm/pull/61397) · state: open · merged: False

## Original PR description



## Overview

`QwenGatedDeltaNetAttention._forward_core` passes no output buffer to the GDN
prefill kernel, so the kernel allocates its own output and the layer copies
it into `core_attn_out` (after a `torch.cat` in mixed decode/prefill
batches). The Triton/FLA kernel already writes into a passed
`core_attn_out`, and AITER's FlyDSL kernel (#57560) takes an `o` argument
that `rocm_aiter_ops.gdn_flydsl_prefill` did not forward. This hands both
backends their slice of `core_attn_out` so the prefill writes in place.

## Claims

- Removes one full-size output copy per GDN layer per prefill step on the
  Triton/FLA backend (the ROCm default, and the CUDA fallback when FlashInfer
  is unavailable) and on `aiter_flydsl`, plus the decode/prefill
  `torch.cat` in mixed batches. The effect is small: about 37 µs per GDN
  layer at a 32K-token step with 16 value heads per rank on MI355X, roughly
  0.1% of TTFT. As such, the end-to-end impact is small.
- No numerics change, no new host-device sync. Spec-decode batches and the
  FlashInfer and CuteDSL backends are unchanged.
- Related, not a duplicate: #57039 does the same for the FlashInfer backend
  (and the gated-norm `z` clone), with the same `_forward_core` structure,
  so the two conflict textually. The backend check here is a capability flag
  on `ChunkGatedDeltaRule`, so whichever lands second adds its backend with
  a one-word change. #45717 (draft, inactive since June) does it for FLA
  behind an env flag and skips mixed batches. #61034, #60659, #60645 and
  #61250 edit the same function but do not touch the output buffer.

The E2E is offline `LLM.generate` on dummy weights with a 4-layer cut
(3 GDN + 1 full attention) of a hybrid GDN MoE config,
`max_num_batched_tokens=512`, and 10 prompts of 37–3000 tokens, so chunked
prefills share steps with decodes and both the split and prefill-only
branches run. On dummy weights the logits barely depend on the GDN output
(scaling it by 1.01 moves logprobs by at most one bf16 ULP and leaves tokens
unchanged), so the E2E A/B is a smoke test; the per-call check and the unit
tests carry the numerics claim. Model evals were not run for the same
reason.

CI: the `kernels/mamba` steps (H200 and the AMD mirrors) run the Triton/FLA
split cases; they were not run locally on CUDA. AMD CI runs without
`VLLM_ROCM_USE_AITER=1`, so the FlyDSL cases skip there; the FlyDSL
validation above was done locally.

- Compiled (non-eager) runs are not bit-comparable across trees: a source
  change gives a fresh `torch.compile` cache entry, and fresh compiles of
  this config land on one of a few results that differ by one bf16 ULP. The
  branch with the in-place path disabled lands on the same set, so it is

- Triton autotuning also picks configs by timing; the A/B used
  `TRITON_CACHE_AUTOTUNING=1` with a shared cache so both trees run the same
  configs.
- #61134 made dummy MXFP4 weights differ between runs, so both trees ran
  with `weight_utils.py` and `dummy_loader.py` from `56e3b081ae`.

## Details

- `ChunkGatedDeltaRule.writes_output_in_place` is true for the Triton/FLA
  and `aiter_flydsl` backends. FlashInfer copies afterwards (#57039 changes
  that) and CuteDSL is left out because it was not validated here.
- `_forward_core` passes the slice only when there is no spec decode (the
  prefill tokens are then a contiguous range of `core_attn_out`). In mixed
  batches the slice starts after the peeled decode tokens, and only the
  small decode output is still copied.
- The AITER kernel writes `o` without strides, so `gdn_flydsl_prefill`
  raises if `o` is not contiguous, not shaped like `v`, or not `q`'s dtype,
  instead of silently writing the wrong elements. The check reads only
  tensor metadata.
- `forward_aiter_flydsl` now expects `core_attn_out` with exactly `v`'s
  element count; it used to accept a larger flat buffer and copy a prefix.
  Its only callers are `_forward_core` and the test.
- The split test now runs `_forward_core` under `torch.no_grad()`, because
  FLA asserts grad is off when it writes into a caller's buffer (inference
  always runs that way).
- Separate, pre-existing: with `VLLM_GPU_SYNC_CHECK=error`, the first sync
  hit is the FlyDSL prefill metadata build (`gdn_attn.py` calling AITER
  `build_gated_delta_rule_prefill_metadata`, which creates a device tensor
  from a host list). Not changed here.
