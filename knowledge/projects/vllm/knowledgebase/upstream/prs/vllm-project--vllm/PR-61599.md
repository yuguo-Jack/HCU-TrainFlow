# [CPU][Bugfix] Respect expert map in unquantized MoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/61599) · state: open · merged: False

## Original PR description

## Overview

Fixes #61546 by making the unquantized CPU MoE kernel translate global router expert IDs through the rank-local expert map before indexing local weights.

This does not duplicate an existing PR. #47778 adds expert-map handling for the FP8 CPU expert path as part of broader DP/EP support, while this change fixes the existing unquantized BF16 `CPUUnquantizedExperts` path used by Qwen3.5. #51876 addresses NUMA weight placement rather than expert routing.

## Claims

- Correctly executes unquantized CPU MoE with expert parallelism and global router IDs.
- Makes routes for experts hosted by other ranks contribute zero before cross-rank reduction.
- Preserves the existing non-EP operator contract and execution path.
- Avoids ZenTorch fused MoE for EP configurations because that backend does not consume an expert map.

## Details

The CPU router produces global expert IDs, but under EP each rank stores only its local expert weights. `CPUUnquantizedExperts.apply()` previously discarded `expert_map` and passed global IDs directly to `cpu_fused_moe`, which indexed buffers sized by the local expert count.

The operator now accepts an optional expert map. With a map present, it validates global and mapped IDs before indexing, converts local routes to local expert IDs, and directs non-local routes to one zero-initialized output sentinel. This keeps the existing fixed top-k reduction shape while making non-local contributions exactly zero. Without a map, buffer sizing and routing remain unchanged, and the dispatcher argument has a default to preserve direct callers.
