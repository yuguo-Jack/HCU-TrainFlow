# [Bugfix][RecoverSSM] Correct aligned state indices at exact block boundaries

[Upstream PR](https://github.com/vllm-project/vllm/pull/59962) · state: closed · merged: True

## Original PR description

## Overview

**Upstream full-model evaluation pending.**

Fix RecoverSSM align-mode final-state indexing at exact Mamba block boundaries in both the KDA commit planner and V2 postprocessing. Fixes #59933.

## Claims

- At an exact boundary, commit and record the state for the block containing the last accepted token, rather than advancing to the next block.
- Retain the zero-length clamp and block-table upper bound; leave non-align behavior unchanged.
- Extend existing numeric-reference and mixed-batch CUDA tests to cover boundary neighbors, request remapping, and first/second exact boundaries.

## Details

Aligned state columns correspond to the block containing the last committed token. `total // block_size` advances prematurely when `total` is an exact multiple. Use `max(total - 1, 0) // block_size`, capped to the existing width limit, in both writer planning and recorded next-step state selection.

Credit: @seanphan reported #59933 with the downstream diagnosis/proposed arithmetic fix credited to @YulHeon. This patch independently reproduces the issue in upstream GPU tests and adds regression coverage. The reporter's downstream GLM A/B results are not claimed as our validation or as upstream Kimi-K3 evaluation.
