# Mxfp8 mtp triton tile tuning

[Upstream PR](https://github.com/vllm-project/vllm/pull/45875) · state: open · merged: False

## Original PR description

## Purpose

Improve decode throughput for MXFP8 MoE models on AMD CDNA4 (gfx950 / MI355X) by replacing the fixed Triton tile sizes in `rocm_native.py` and `mxfp8_native_moe.py` with per-shape tiles tuned at real MTP decode shapes.

**Linear:** At decode (M≤256, K=6144 qkv/gate_up projections), `BLOCK_N=32` with per-M buckets (M≤48/80/112/256) outperforms the previous `BLOCK_N=64/128` tile by 1.1–1.6× in kernel time. Prefill (M≥1024) keeps the wide 128×256 tile.

**MoE:** At decode (`block_m=16`), GEMM1 (K=6144→N=1536) uses `BLOCK_N=32/BLOCK_K=512/waves_per_eu=4` and GEMM2 (K=768→N=6144) uses `BLOCK_N=64/BLOCK_K=256`. Prefill keeps the wide baseline tile.

Tile size does not affect `tl.dot_scaled` numerics — output is bit-identical to the previous dispatch.

@tjtanaa, thanks for the review. There isn’t an MTP vs non‑MTP switch here: tile choice is purely shape‑based from the runtime GEMM (M, K, …).

For non‑MTP workloads that still isn’t special‑cased — it’s the same table:

When M is large (the prefill / long‑context regime, e.g. the M ≥ 1024 bucket in the comment), we intentionally select the wide baseline tile (same high‑throughput strategy as before for large M). So this isn’t “large M gets a new experimental tile”; it’s “large M stays on the known‑good wide path.”
For smaller M (typical decode / skinny projections), we pick per‑bucket tuned tiles instead of a single fixed tile — that’s where the measured win came from in the MTP decode benchmark, but any workload (MTP or not) that hits those M ranges gets the same selection.
The None sentinel row is just the catch‑all for shapes that don’t match an explicit bucket so we don’t leave gaps (not “non‑MTP fallback” specifically).
Net: non‑MTP doesn’t bypass the table; for large M it should land in the wide‑tile row (baseline‑aligned), and for small M it can pick a decode‑tuned row when applicable. I’ll add a short non‑MTP bench line in the PR if you want hard numbers for that path too.
