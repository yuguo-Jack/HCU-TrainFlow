# [Model Runner V2] Add override_model_forward hook for forward benchmarks

[Upstream PR](https://github.com/vllm-project/vllm/pull/61338) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Add `GPUModelRunner.override_model_forward(fn)` (MRV2): a context manager under which `execute_model` still builds the step's inputs, attention metadata and forward context, then calls `fn(input_batch, **model_inputs)` instead of the eager model call. Its user is `vllm bench forward` (#61339, stacked on this PR), which times the model forward of an exact batch as a one-shot CUDA graph.

## Claims

- A benchmark can run the real per-step preparation (input batch, `ModelState` metadata, DP sync, forward context) for a batch it built, and take over only the model call, without copying runner code or patching private state.
- No behavior change unless the context manager is active: one attribute check in the eager branch.

## Validation

Exercised by the stacked bench PR's tests (`tests/benchmarks/test_forward_cli.py`, end-to-end on Llama-3.2-1B in the Benchmarks CLI job) and its validation on DeepSeek-V4/V4.1 (1 to 8 GPUs, DP/TP/EP, 2 nodes). The hook alone has no caller in this PR, so it has no separate test.

## Details

- Only the eager branch (`cudagraph_mode == NONE`, no micro-batching) is overridable; the context manager asserts both, since otherwise the override would never reach the model.
- `fn` receives the `InputBatch` so a caller can check the layout the runner built (request order, query and computed lengths) and write per-request inputs, without reading runner internals.
- `sample_tokens` must not follow an overridden step, so the pending `execute_model_state` is dropped on exit.
