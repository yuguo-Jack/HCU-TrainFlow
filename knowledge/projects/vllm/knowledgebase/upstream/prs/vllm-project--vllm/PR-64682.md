# [Security] Bound decoded image copies before preprocessing

[Upstream PR](https://github.com/vllm-project/vllm/pull/64682) · state: open · merged: False

## Original PR description

## Overview

Bound decoded image copies in the Rust frontend before building the preprocessing batch. Repeated image references count separately, so a small request cannot multiply a large raster into an unbounded clone vector.

## Claims

- Apply `VLLM_MAX_MEDIA_REQUEST_DECODE_BYTES` (default 715827880, zero disables) to logical image slots before lazy decoding or cloning.
- Check actual raster bytes before each copy, including higher bit-depth images, and return a request-validation error when the budget is exceeded.
- Cover HTTP chat completions, chat tokenization, raw-media generate, and unary/streaming gRPC through their shared image preprocessing path.

## Validation

Commands run from `rust/`:

- `cargo test -p vllm-chat multimodal::image::tests --locked`: 3 passed, including eight references with the reported 12000x12000 dimensions rejected before decoding.
- `cargo test -p vllm-server image_budget_rejects --locked`: 2 passed. Tests use a child process with a four-byte budget and eight identical valid one-pixel PNG references; HTTP returns 400 and both gRPC methods return InvalidArgument.
- `cargo test -p vllm-server multimodal --locked`: 2 existing accepted-input tests passed.
- `cargo test -p vllm-server image_url --locked`: 5 passed, including accepted Qwen and Step5-VL image requests.
- `cargo clippy -p vllm-chat -p vllm-server --all-targets --locked -- -D warnings`: passed.
- `cargo fmt --all -- --check`: passed.
- `cargo test -p vllm-chat --locked -- --test-threads=1`: 451 unit tests, 18 chat integration tests, and the grammar replay test passed; roundtrip tests had 22 passes and three failures (Kimi stop-set mismatch, MiMo grammar snapshot mismatch, Step5 model config missing vocab_size). The parallel unit run had one audio timing-snapshot failure; the serial unit run passed.
- Applicable pre-commit hooks on all six changed files: passed. Repository-wide hooks ran but reported unrelated C/CUDA formatting, CUDA-checkpoint mypy errors, and the macOS non-root wrapper test failure.

The checks exercise real frontend parsing and image preparation with the repository mock engine. The large-image process-abort reproducer was not rerun, and no GPU model accuracy evaluation was performed. Accepted preprocessing remains unchanged; the added behavior rejects inputs above the image budget.

## Details

The media tracker shares repeated image references, but preprocessing previously deep-cloned every logical slot. The guard first sums header dimensions at four bytes per pixel, matching Python image admission, with checked arithmetic. It then checks actual decoded bytes before cloning. The counter is request-local and introduces no shared mutable state.

This bounds image copies, not aggregate audio/video decoding or process-wide memory. The standalone renderer uses language-model-only loading, and the main Rust server does not implement the chat render route; neither adds another image-clone path.

Duplicate-work check: inspected current main and relevant diffs for #61067, #52602, #63912, #63749, #64601, #61639, and #58649. Per-item encoded limits, item-count limits, transparency handling, error mapping, NIXL transport, processor caching, and model support do not provide this clone-byte bound. The cache change retains the shared preprocessing sink for misses and budget-sensitive processors.
