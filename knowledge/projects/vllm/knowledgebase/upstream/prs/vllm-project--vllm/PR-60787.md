# [Bugfix] Reuse Whisper encoder outputs across beam requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/60787) · state: open · merged: False

## Original PR description



## Overview

Whisper frontend beam search repeatedly encodes the same audio because each beam step becomes a new request. Reuse encoder outputs by multimodal hash while allocating and populating cross-attention K/V separately for every request. Fixes #49197.

## Claims

- Whisper beam search no longer re-encodes an audio item for every beam step while its output remains cached.
- Encoder cache hits still allocate cross-attention blocks, gather outputs in decoder batch order, and use the appropriate non-compiled prefill path.
- Reuse stays within the existing encoder-cache budget; eviction and cache reset allow recomputation.

## Validation

NVIDIA L20 (46 GB), Whisper tiny, FP16, one `mary_had_lamb` audio sample, beam width 2, 32 generated tokens, max batch tokens 2048, max sequences 8. One warmup followed by three measured runs, clearing the encoder cache before every run. Default compilation/CUDA Graph configuration; model load is excluded from timing.

| Model runner | Baseline seconds, mean ± SD | Patched seconds, mean ± SD | Speedup | Encoder executions |
|---|---:|---:|---:|---:|
| V2 | 0.6644 ± 0.0042 | 0.5227 ± 0.0281 | 1.27× | 63 → 1 |
| V1 | 0.6481 ± 0.0023 | 0.5001 ± 0.0029 | 1.30× | 63 → 1 |

Both returned beams have exactly matching token IDs, text, and cumulative logprobs in every measured run. A subsequent ordinary greedy generation also matches the baseline. V2 passed with `VLLM_GPU_SYNC_CHECK=error`. Eager-mode runs also passed for both runners.

## Details

Frontend beam search submits each beam as a new request. The previous encoder-decoder manager never reported a cache hit, and both model runners consumed only outputs of encoders scheduled in the current step. The change reuses the existing reference-counted encoder cache, separates cross-attention allocation from encoder execution, and gathers cached outputs for every request starting at token zero.

V2 kernel warmup uses modality-free, length-only encoder features; these remain excluded from output gathering, while real missing encoder entries still fail. The V1 change preserves the same behavior for deployments using the legacy runner. No extra cache budget, dependency, or GPU-to-CPU synchronization is introduced.

Duplicate-work check: #49541 explicitly excludes the Whisper recomputation problem; #31882 covers frontend beam-search changes rather than this encoder-cache path. #51228 addresses slot-release accounting in the old manager rather than cross-request encoder reuse. No open PR addressing the same reuse fix was found.
