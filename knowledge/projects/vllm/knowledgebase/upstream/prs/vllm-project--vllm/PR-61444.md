# [ROCm][BugFix][FP8] Pad weights and inputs to fix TP8 crash in ROCmFP8ScaledMMLinearKernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/61444) · state: open · merged: False

## Original PR description

## Overview

At TP8, these FP8 models fail during server startup on ROCm, with AITER on and off, on MI300X and MI355X:

| Model | FP8 linear kernel | Failing layer | K per GPU at TP8 |
|---|---|---|---|
| RedHatAI/DeepSeek-Coder-V2-Lite-Instruct-FP8 | `ROCmFP8ScaledMMLinearKernel` | layer 0 MLP `down_proj` | 10944 / 8 = 1368 |
| nm-testing/DeepSeek-Coder-V2-Lite-Instruct-FP8 | `ROCmFP8ScaledMMLinearKernel` | layer 0 MLP `down_proj` | 10944 / 8 = 1368 |
| RedHatAI/diffusiongemma-26B-A4B-it-FP8-dynamic | `RowWiseTorchFP8ScaledMMLinearKernel` | dense MLP `down_proj`, every layer | 2112 / 8 = 264 |

* `RedHatAI/DeepSeek-Coder-V2-Lite-Instruct-FP8`

      RuntimeError: Engine core initialization failed. See root cause above. Failed core proc(s): {}

The evaluation of these layers crashes with the same kind of failure in all three models. These layers run `torch._scaled_mm` with `AITER `on or off, and `torch._scaled_mm` requires K to be a multiple of 16 for `hipBLASLt`; 1368 and 264 are not.

This PR zero-pads the weight's K up to a multiple of 16 after loading, and pads the FP8 input to match at runtime. The padded rows and columns are zeros, so the result does not change. Layers whose K is already a multiple of 16 are left alone. 

This PR applies to `ROCmFP8ScaledMMLinearKernel` and the `torch._scaled_mm` kernels (per-tensor, row-wise and channel-wise). CUTLASS on CUDA already pads the same way (https://github.com/vllm-project/vllm/pull/41868):

https://github.com/vllm-project/vllm/blob/fe341a53dda00472c281a2d1f4bd34a74e7eae6e/vllm/model_executor/kernels/linear/scaled_mm/cutlass.py#L206-L274

## Claims

- The three models start and serve at TP8 with AITER on and off, on MI300X and MI355X.
- GSM8K scores at TP8 with AITER on are in line with AITER off.
