# [Rust Frontend] Render empty tool call arguments as an empty object like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/63314) · state: closed · merged: True

## Original PR description

## Overview

OpenAI clients send `"arguments": ""` for assistant tool calls to tools without parameters. Python renders that history as `{}`; the Rust frontend passes `""` to the renderer, and the HF renderer fails to parse it as JSON and returns 500. This PR lowers `""` to `"{}"`, like an absent or `null` value.

## Claims

- A chat request whose assistant history has a tool call with `arguments: ""` now renders it as `{}` with every renderer. Before: 500 on HF and DeepSeek V3.2 (`assistant tool call ... has invalid JSON arguments: EOF while parsing a value`), and an `arguments=""` parameter on DeepSeek V4/V4.1.
- Absent, `null`, and JSON-object `arguments` are unchanged; malformed or non-object strings keep today's behavior.

- New test `prepare_chat_request_lowers_empty_tool_call_arguments_as_absent` (chat lowering): `""` and `null` lower to `"{}"`, a JSON object passes through. It fails on the base with `left: ""`.
- The route tests use a fake chat backend, so the 500 itself is shown by code path: `to_template_tool_calls` (`rust/src/chat/src/renderer/hf/mod.rs`) calls `serde_json::from_str("")` and maps the error to `Error::ChatTemplate`, which the server reports as 500.

## Details

Python sets `function.arguments` to `{}` when it is absent, `null`, or an empty string (`vllm/renderers/chat_utils/chat_message.py`), and `tests/entrypoints/openai/chat_completion/test_completion_with_function_calling.py::test_no_args_tool_call[...-""]` pins it. The Rust chat DTO lowering (`convert_assistant_tool_calls`) already maps absent and `null` to `"{}"` before any renderer runs, so `""` joins that rule there instead of each renderer deciding it. This applies to `/v1/chat/completions` and chat `/tokenize`, which share the lowering.

Harmony (gpt-oss): Python renders both an absent and an empty `arguments` as empty content, while Rust already rendered an absent one as `{}`; after this PR Rust renders both as `{}`. The absent-versus-`{}` difference on Harmony predates this PR.

Out of scope: coercing whitespace-only, malformed, or non-object `arguments` to `{}`.

Not a duplicate: no open PR changes the Rust tool-call argument lowering. Once this merges, the `""` case of `test_no_args_tool_call` can run in the Rust frontend CI step.
