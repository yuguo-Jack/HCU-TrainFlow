# Fix full KV event reporting for sparse cache hits

[Upstream PR](https://github.com/vllm-project/vllm/pull/57358) · state: open · merged: False

## Original PR description

## Overview

Fix `kv_cache_report_mode="full"` for sparse and partial hybrid-cache hits. Report registered cache entries with their correct metadata when EAGLE reuses fewer tokens than an attention entry covers. Related: #63149.

## Claims

- Skip null placeholders and preserve partial-entry hashes, parents, token spans and lookahead metadata.
- For an attention entry registered at **H112** and an EAGLE reuse length of **96 tokens**, re-report H112 with its original store metadata. Do not require or register an attention H96 entry; the actual reuse count remains 96.
- Use each manager's effective block size, including DCP scaling, for event geometry.

## Validation

Real CPU `KVCacheManager`/`BlockPool` objects: block size 64, hash size 16, 80/96/112/128-token hits, DCP sizes 1/2, and EAGLE prefill steps 64 → 96 → 112.

```bash
env VLLM_TARGET_DEVICE=cpu VLLM_PLUGINS='' .venv/bin/python -m pytest \
  tests/v1/core/test_prefix_caching.py \
  tests/v1/core/prefix_cache/test_partial_prefix_cache_primitives.py \
  tests/v1/core/prefix_cache/test_partial_prefix_cache_hits.py -q
# 482 passed
```

The event-reporting selection (`-k emit_cached_block_events`) passes all **12 cases**. With the updated regression applied to the pre-follow-up emitter (`e6e4355f2`), the EAGLE case fails because H112 is omitted: **1 failed, 8 passed**. The final regression also verifies that the re-reported H112 event equals its original store event.

Additional CPU checks passed for registered aliases, different continuations, short prompts, physical-block ownership, LoRA/multimodal/lookahead metadata, and repeated full reports followed by eviction. All applicable pre-commit hooks, including lint, formatting, type checking and CI test coverage checks, pass; `git diff --check` passes.

GPU serving, actual speculative rejection/rollback and downstream consumer reconstruction were not exercised. This PR addresses the reproduced full-report cases, not the complete #63149 validation matrix.

## Details

The old path derives dense events from the block-table length, so sparse placeholders and partial tails can overrun the request's hashes. Pass the actual blocks and reconciled reuse count to a sparse/partial fallback; ordinary full-block hits retain the existing batched path.

If the reuse endpoint is not registered, search later endpoints within the same physical block and within the request's computed hashes. Emit only a matching registered key owned by that block. Reuse the existing hash/span and event-building helpers. Cache registrations, hit calculation and the event schema are unchanged: `BlockStored` describes residency, while the request's reuse count remains separate. Partial-parent resolution and subscriber recovery remain separate work.

Related work: #52371 provides reproducer tests, #44488 addresses sparse store alignment, and #50118 shares the effective-DCP-size correction required by this reporting path. This PR fixes sparse/partial full-report construction without adding a wire-format field; the duplicate-work searches found no other open PR implementing that fix.
