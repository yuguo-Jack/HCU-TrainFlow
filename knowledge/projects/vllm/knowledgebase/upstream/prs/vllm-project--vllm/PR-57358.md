# Fix full KV event reporting for sparse cache hits

[Upstream PR](https://github.com/vllm-project/vllm/pull/57358) · state: open · merged: False

## Original PR description

## Purpose

Fix a crash in full KV-cache event reporting for hybrid models that use sparse cache groups, such as Mamba `align` mode.

After `get_computed_blocks()` reconciles cache hits across groups, a sparse group can contain null placeholders and the shared hit can end between that group's block boundaries. The existing full-report path discards the actual hit block table and reconstructs events from `len(group_blocks)`, treating those sparse entries as a dense sequence. For an unaligned prompt, it eventually indexes past the request's block-hash view:

```text
BlockPool.emit_cached_block_events
  cached_hashes.append(maybe_convert_block_hash(block_hashes[i]))
BlockHashListWithBlockSize._get_value_at
  return self.block_hashes[(idx + 1) * self.scale_factor - 1]
IndexError: list index out of range
```

This change preserves the existing dense reporting path and adds a narrow
fallback only when the reconciled hit is partial or contains null placeholders:

- Pass the actual per-group hit blocks and reconciled cached-token count to the fallback.
- Skip null placeholders instead of inventing hashes for them.
- Emit one valid `BlockStored` event per real fallback block, using its exact hash, parent, and token span.

The cache contents and hit calculation are unchanged; this only corrects metadata emitted for already-cached blocks.

Related work and duplicate check:

- #52371 reproduces this sparse-Mamba `IndexError` with expected-failure tests but intentionally contains no runtime fix.
- #44488 adds `block_offsets` to describe sparse `BlockStored` events. This PR takes a different approach for reused-cache full reporting: it emits only the real non-null hit regions and does not change the event wire format.
- Searches for `emit_cached_block_events` and `sparse mamba kv events` found no other open PR fixing this full-report crash.

## Test Plan

Extend the existing prefix-caching unit suite with a CPU-only regression using a hybrid full-attention/Mamba cache and a realistic 4:1 cache-block/hash-block ratio. The test produces a sparse, partial Mamba hit, enables `kv_cache_report_mode="full"`, and verifies that reporting:

- does not raise `IndexError`;
- skips the null placeholder;
- emits the actual cached block hash;
- preserves the correct parent hash and exact token range.

```bash
VLLM_TARGET_DEVICE=cpu VLLM_PLUGINS='' \
  .venv/bin/python -m pytest tests/v1/core/test_prefix_caching.py \
  -k 'emit_cached_block_events' -q
```

Model/GPU evaluation is not applicable: this changes KV-event metadata generation only and does not alter scheduling decisions, model execution, or outputs.
