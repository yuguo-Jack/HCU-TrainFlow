# [Frontend] Add opt-in middleware for unset chat fields

[Upstream PR](https://github.com/vllm-project/vllm/pull/53832) · state: open · merged: False

## Original PR description

## Purpose

Non-streaming Chat Completions responses include unset vLLM extension fields as explicit `null`. Add an optional `OmitUnsetChatFieldsMiddleware`, enabled through the existing middleware loader:

```bash
vllm serve MODEL --middleware \
  vllm.entrypoints.serve.middleware.omit_unset_chat_fields.OmitUnsetChatFieldsMiddleware
```

The default response shape is unchanged. When enabled, the middleware omits only these six top-level fields when their value is `None`: `prompt_logprobs`, `prompt_token_ids`, `prompt_text`, `kv_transfer_params`, `ec_transfer_params`, and `metrics`.

Populated extension fields, including empty lists and maps, remain present. OpenAI-compatible fields retain their existing values, including nulls. This applies to successful JSON responses from both `/v1/chat/completions` and `/v1/chat/completions/batch`. Streaming, error, and unrelated responses pass through unchanged.

Omission is opt-in because omitted extension attributes are absent from OpenAI SDK objects instead of reading as `None`. The middleware buffers matching responses and adds JSON parsing/encoding; its performance overhead has not been benchmarked. When combining it with compression middleware, register compression afterward so filtering happens before compression. Already compressed responses pass through unchanged.

Fixes #53349.
