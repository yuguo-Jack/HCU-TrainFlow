# [Doc] MiniMax-M3.1-Flash: add the GB200 AgentX presets

[Upstream PR](https://github.com/vllm-project/vllm/pull/64283) · state: closed · merged: True

## Original PR description

## Overview

Add GB200 AgentX presets for MiniMax-M3.1-Flash, documenting the Dynamo + vLLM lanes of [SemiAnalysisAI/InferenceX#4464](https://github.com/SemiAnalysisAI/InferenceX/pull/4464) (head `25845c73`). Both presets are opt-in and only touch `recipes/models/MiniMaxAI/MiniMax-M3.1-Flash.yaml`.

- **`gb200_agentx_agg`**: aggregated TP4 `dynamo.vllm` workers, one per tray, behind the Dynamo KV router with session affinity. Points for GPU-resident KV and a host-DRAM tier via `SimpleCPUOffloadConnector`.
- **`gb200_agentx_pd`**: Dynamo prefill/decode. DEP4 prefill workers (one per tray) feed one decode worker, DEP8 (throughput) or DEP16 (lower latency). KV moves over NIXL, and all ranks share a Mooncake KV store in host DRAM.

The runbooks give tuning rules rather than a fixed layout: how many prefill workers per concurrent session, DEP8 vs DEP16, `--long-prefill-token-threshold 4096` for the TTFT tail, Mooncake pool sizing per rank, `--max-num-seqs` and offload sizing. They also cover the etcd/NATS, Mooncake master, worker and frontend commands.

## Validation

- Measured in the lane's sweep ([run 40636603138](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/40636603138)): 3 prefill + DEP8 at 256 sessions: 80.8k tok/s/GPU at 244 tok/s/user; 3 prefill + DEP16 at 280: 68.6k at 303; 4 prefill + DEP16 at 352: 70.1k at 288.
- Every serving flag and environment variable of the lane's agg, prefill and decode roles is either in the presets or explained in the runbook. Benchmark-only settings are left out (concurrency lists, synthetic acceptance, client settings, cluster plumbing).
- Preset schema checked locally; `typos` and `git diff --check` are clean.
