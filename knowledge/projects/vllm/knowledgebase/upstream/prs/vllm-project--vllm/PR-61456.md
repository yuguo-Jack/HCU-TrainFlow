# [Perf][Structured Output] Parallel guidance bitmask fill: 15% faster decode at batch 64

[Upstream PR](https://github.com/vllm-project/vllm/pull/61456) · state: open · merged: False

## Original PR description



## Overview

With the guidance backend, bitmask fill is about 25% of the decode step at batch 64 because vLLM computes one llguidance mask at a time. llguidance already ships a native parallel batch fill (`LLExecutor` + `fill_next_token_bitmask_par`), suggested by @mmoskal. This PR uses it: one executor per backend, one call per step for all non-spec rows.

## Claims

- Batch 64: **15.2% lower end-to-end decode time (1.18x throughput)**, `grammar_bitmask` time per step down 62%, on H100 with Qwen2.5-0.5B and JSONSchemaBench schemas.
- Batch 1-4 unchanged (within noise), batch 16 2.7% faster.
- Outputs token-identical to the serial path in all 360 runs.

## Validation

vLLM main (nightly image `cu129-nightly-5555a2d8`, whose `structured_output/` files equal 6849ca69), llguidance 1.7.6, H100 80GB with 16 vCPUs, `Qwen/Qwen2.5-0.5B-Instruct`, 54 JSONSchemaBench schemas, greedy, max 384 tokens, prefix caching off, `max_num_seqs=64`. Both paths run in one in-process engine and alternate per batch group; 7 paired repeats with rotated order. Medians:

| batch | E2E ms, main | E2E ms, PR | E2E faster (paired min-max) | `grammar_bitmask` µs/step, main → PR | mask share of wall, main → PR |
|---|---|---|---|---|---|
| 1 | 1783.5 | 1782.4 | 0.2% (0.1-0.6) | 82 → 77 | 4.5% → 4.2% |
| 4 | 2682.8 | 2683.9 | 0.1% (-0.8-0.7) | 116 → 114 | 6.0% → 6.0% |
| 16 | 1699.4 | 1651.8 | 2.7% (1.9-3.0) | 230 → 178 | 10.4% → 8.3% |
| 64 | 1464.5 | 1241.0 | **15.2% (14.8-15.4)** | 946 → 362 | 24.9% → 11.2% |

E2E is `llm.generate` wall time summed over the batch groups (8/4/2/1 groups at B1/4/16/64). `LLExecutor(num_threads=4)` gives the same B64 result (15.3%), so the default thread count is not critical.

Harness, raw rows, outputs and logs: https://github.com/ToukoUrsin/vllm-llguidance-bitmask-e2e/tree/main/parallel-fill

`pytest tests/v1/structured_output/test_structured_output_manager.py`: 55 passed, 1 xfailed (pre-existing) on the H100 box. The new test fills a mixed batch (constrained, still reasoning, terminated) through the new path, asserts the executor was used, and checks every row against the per-row `fill_bitmask`. `ruff check`, `ruff format` and mypy pass on the changed files.

## Details

- Only the guidance backend without speculative decoding takes the new path. Spec decoding still fills row by row because each draft token has to be accepted between rows; xgrammar, outlines and LMFE are unchanged. For guidance this also replaces the Python `ThreadPoolExecutor` path above 128 rows.
- Unconstrained rows (reasoning, terminated) are still set to the full mask in Python, as before.
- `LLExecutor()` uses llguidance's default thread count (80% of available CPUs, at most 32). The pool is created on first use and computes with the GIL released.
