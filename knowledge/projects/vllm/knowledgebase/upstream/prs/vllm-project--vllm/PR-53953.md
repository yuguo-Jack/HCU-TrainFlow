# [ROCm][Model][AMD][Performance]: Added AITER fusion on top of the existing TRITON fusion path for GLM-5.2-MXFP4 through deepseek_v32

[Upstream PR](https://github.com/vllm-project/vllm/pull/53953) · state: open · merged: False

## Original PR description

## Purpose

Adds an AITER-backed fusion path for the ROCm `deepseek_v32` (DeepSeek Sparse
Attention) forward, used by both DeepSeek-V3.2 and GLM-5.2. The existing
shared-Triton fusion path is untouched and remains the default; the AITER path
is selected at runtime per fusion via opt-in env flags, so behaviour on ROCm is
unchanged unless a flag is set.

This PR is stacked on top of: https://github.com/vllm-project/vllm/pull/51915, so needs enablement to land first before this fusion add-on.

### Fusions added

**1. MLA dual RMSNorm** 
Fuses the q and kv-a RMSNorms into one AITER call
(`fused_mla_dual_rms_norm_out`). An out-variant was added so the norms write
model-owned buffers rather than allocating per layer, which lets the call be
hoisted out of the eager region and captured by cudagraph. Also wires the
per-token-quant variant for the quantized case.

**2. Fused QK RoPE + concat + MLA cache write** 
`rocm_aiter_fused_qk_rope_concat_and_cache_mla` replaces the separate RoPE,
concat and KV-cache-write steps on the MLA path. The uint8 KV cache allocated by
`--kv-cache-dtype fp8` is viewed as `float8_e4m3fn` before the call, since the
AITER op rejects the raw uint8 buffer.

**3. Fused indexer QK RoPE + fp8 quant + cache write**
`rocm_aiter_indexer_qk_rope_quant_and_cache` fuses the lightning-indexer key
LayerNorm, RoPE, fp8 quantization, and cache write into one call for the 21
indexer layers.

**4. Fused all-reduce + RMSNorm**
Uses AITER's custom all-reduce with an in-kernel RMSNorm. Gated on custom-AR
eligibility (`should_custom_ar`) because the op asserts the kernel ran, and
oversized batches must fall back to the standard path — this is the check the
torch.compile pass performs at compile time and which an inline call has to do
itself.

**5. `VLLM_ROCM_USE_AITER_CUSTOM_AR`** exposes AITER's custom all-reduce
independently of the fused variant.

## Test Plan

To switch between the two fusion paths, use the env var below:

```bash
# ---- Triton fusion path (v32_triton) ----
export VLLM_ROCM_USE_AITER_MLA_QK_NORM_ROPE=0
export VLLM_ROCM_USE_AITER_FUSED_AR_RMSNORM=0

# ---- aiter fusion path (v32_aiter) ----
export VLLM_ROCM_USE_AITER_MLA_QK_NORM_ROPE=1
export VLLM_ROCM_USE_AITER_FUSED_AR_RMSNORM=1
``` 

```bash
OVERRIDE='{"GlmMoeDsaForCausalLM": "vllm.models.deepseek_v32:DeepseekV32ForCausalLM"}'
Serving:
vllm serve "$MODEL" --trust-remote-code \
  --tensor-parallel-size 8 --max-model-len 65536 \
  --kv-cache-dtype fp8 --no-enable-prefix-caching \
  --model-class-overrides "$OVERRIDE" --port 8000

Use --kv-cache-dtype auto for bf16 KV instead of fp8.

Bench (decode, per concurrency):
C=16   # 16 32 64 128
vllm bench serve --backend openai --model "$MODEL" --trust-remote-code \
  --host 127.0.0.1 --port 8000 --dataset-name random \
  --random-input-len 256 --random-output-len 2048 \
  --num-prompts $((C*4)) --max-concurrency $C \
  --ignore-eos --seed 0 --percentile-metrics ttft,tpot \
  --save-result --result-dir . --result-filename run.json

Eval:
python3 vllm/tests/evals/gsm8k/gsm8k_eval.py \
  --num-questions 400 --num-shots 5 --temperature 0.0 --seed 42 --port 8000
```
