# [Bugfix][Tool Parser] Extract every InternLM2 tool-call block

[Upstream PR](https://github.com/vllm-project/vllm/pull/63354) · state: open · merged: False

## Original PR description



## Overview

`Internlm2ToolParser` raised `ValueError: too many values to unpack (expected 2)` on any output containing a second `<|action_start|><|plugin|>` block, and its streaming path dropped every block after the first. Extract a tool call from every block, in both paths. Fixes #44139.

## Claims

- `extract_tool_calls` returns one `ToolCall` per block, in order, with the text before the first block preserved as `content`.
- `extract_tool_calls_streaming` emits one `DeltaToolCall` per block with an incrementing `index`, including when the whole output arrives in a single delta.
- Multi-block output no longer raises and no block is silently dropped; single-block output is unchanged.

## Details

**Root cause.** Both paths split accumulated text on `<|action_start|><|plugin|>` and unpack the result into exactly two names, which only holds for one marker. Streaming additionally had `if self.current_tool_id > 0: return DeltaMessage(content="")`, which stopped parsing for good after the first call, and `self.prev_tool_call_arr = [tool_call_arr]`, which reset its bookkeeping to a single entry.

**Fix.** The non-streaming path splits on every marker and builds one `ToolCall` per block. The streaming path loops over the blocks present in `current_text`, clearing `current_tool_name_sent` when a new block starts and appending to `prev_tool_call_arr` / `streamed_args_for_tool` instead of replacing them. Most of the diff is the existing partial-JSON argument streaming, moved unchanged into `_stream_action` so it can run per block; `_split_action` and `_stream_blocks` are the two new seams.

Deliberate behaviour changes:

- A block that is already complete when its name is first seen now emits its arguments together with the name. Those arguments were previously only flushed at end of stream by `get_remaining_unstreamed_args`, which inspects the *last* tool call only, so earlier blocks' arguments would otherwise be lost.
- A whole output arriving in one delta now yields both tool calls instead of one.

Unchanged: text before the first block is still returned as `content`; `parameters`/`arguments` handling is untouched; malformed JSON in `extract_tool_calls` still raises `JSONDecodeError`; `parallel_tool_calls=False` is still filtered upstream.

**Also removed.** In `extract_tool_calls`, the `if not tools or name not in [...]:` branch constructed an `ExtractedToolCallInformation` and never returned it, so the result was discarded and the request's tool list was never actually consulted. It is removed rather than copied into the new per-block loop. Whether that whitelist should be enforced is the subject of #47968, not of this crash fix.

**Tradeoff / limitation.** The official InternLM2 chat template emits one tool call per turn, so multi-block output is a model-misbehaviour case rather than the normal protocol (same honesty note as on #44140). The value is not crashing and not discarding data when it does happen — and matching the Rust frontend.

**Rust.** `rust/src/parser/src/tool/json/internlm2.rs` documented "Python silently drops every `<|action_start|>` block after the first" as an intentional divergence. That divergence no longer exists, so the stale bullet is dropped. No Rust behaviour changed.

**Non-duplication.** Checked immediately before opening:

- #58346 fixes the same `ValueError` with `str.partition` — only the first block is parsed, the rest are still dropped, and `extract_tool_calls` still raises. That is the approach @bbrowning asked not to take in #44140. It is also `CONFLICTING` against main with no human review.
- #48348 (stale, conflicted) handled a whole tool call arriving in one delta but left the multi-marker split untouched; that case is covered here.
- #44163 (closed) and #44140 (closed as stale) covered `maxsplit=1` and the non-streaming path only.
- #47968 is the tool-name whitelist; #60363 and #60382 are argument truncation and non-plugin `<|interpreter|>` blocks. Different bugs in the same file.

No open PR extracts every block in both paths.
