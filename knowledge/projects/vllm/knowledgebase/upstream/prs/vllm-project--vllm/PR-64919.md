# [Bugfix][Multimodal] Lazy load native media decoders

[Upstream PR](https://github.com/vllm-project/vllm/pull/64919) · state: closed · merged: False

## Original PR description

## Overview

Lazy-load OpenCV and TorchCodec so lightweight CLI commands do not initialize
native multimedia libraries. This avoids duplicate Objective-C class warnings on
macOS when vLLM-Metal and TorchCodec/OpenCV load overlapping FFmpeg libraries.

Related: https://github.com/vllm-project/vllm-metal/issues/1153

## Claims

- `vllm --version` no longer imports `cv2` or `torchcodec`.
- TorchCodec remains available on demand and preserves automatic fallback when
  TorchCodec, FFmpeg, or its native library is unavailable.
- OpenCV remains available on demand through vLLM's existing `LazyLoader`.

## Validation

- Confirmed the new CLI regression test reports both native modules as imported
  before the fix and passes after the fix.
- `python -m pytest tests/multimodal/media/test_audio.py -v`: 28 passed.
- `python -m pytest tests/multimodal/media/test_video.py -v`: 40 passed.
- `python -m pytest tests/entrypoints/unit_tests -v`: 100 passed, 1 skipped
  (FlashInfer is unavailable on the non-CUDA test host).
- Started a real CPU server with `facebook/opt-125m`; `/health`, `/v1/models`,
  and `/v1/completions` all returned HTTP 200 and completion generation succeeded.
- Verified `vllm --version` and `vllm --help` emit no duplicate Objective-C class
  warnings.
- All pre-commit hooks pass.

GPU-specific CUDA and ROCm suites were not run locally because validation was
performed on Apple Silicon. The affected entrypoint test is wired into Buildkite
through `.buildkite/test_areas/entrypoints.yaml`.

## Details

The CLI imports multimedia modules while building its command registry. Those
modules previously imported `cv2` and TorchCodec eagerly, which loaded native
FFmpeg-dependent libraries even for commands that never decode media. On macOS,
that can load duplicate Objective-C classes before inference starts.

This change defers the TorchCodec import until the TorchCodec audio backend is
actually selected and maps its existing import/load failure modes to the same
`ImportError` used by automatic backend fallback. OpenCV now uses the project's
existing `LazyLoader`. The subprocess regression test exercises the real CLI
module and asserts neither dependency enters `sys.modules` on the version-only
path.
