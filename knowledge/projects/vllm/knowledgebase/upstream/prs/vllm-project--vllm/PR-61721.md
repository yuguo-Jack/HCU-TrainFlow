# [Bugfix][Anthropic] Warn on unsupported non-text system content blocks (#61172)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61721) · state: open · merged: False

## Original PR description

## Overview

Warns when unsupported non-text content blocks (such as multimodal `image` blocks) are supplied in system messages within the Anthropic Messages API, avoiding silent data loss while preserving backward compatibility.

Fixes #61172.

## Claims

- Warns via `logger.warning_once` naming the ignored block type when unsupported non-text content blocks are supplied in `system` (`_convert_system_message`) or in inline `system` messages (`_extract_system_text`), right where the block is dropped.
- Preserves `tool_addition` and `tool_removal` blocks in inline system messages without warning, as they are legitimately resolved and applied to the tool list by `_resolve_tools`.
- Keeps `protocol.py` untouched, avoiding duplicate warnings between Pydantic schema validation and serving conversion.
- Preserves backward compatibility by discarding unsupported non-text blocks rather than rejecting valid client requests.
- Validates that user and assistant multimodal content (e.g. images) continues to pass through with zero warnings.
- Adds comprehensive regression unit tests in `TestUnsupportedSystemContentWarning` across `tests/entrypoints/anthropic/test_anthropic_messages_conversion.py`.

## Validation

1. **Unit Test Suite**:
   - `test_tool_change_blocks_do_not_warn`: Verified with `merge_inline_system=[False, True]`. Tool changes applied, 0 warnings.
   - `test_only_ignored_block_warns_next_to_tool_changes`: Verified with `merge_inline_system=[False, True]`. Only the image block warns.
   - `test_top_level_image_block_warns_and_ignored`: Image block warns once and is ignored; text block is preserved.
   - `test_inline_system_image_block_warns_and_ignored`: Image block warns once and is ignored; inline text is preserved.
   - `test_text_only_system_does_not_warn`: Plain text string and text blocks pass with 0 warnings.
2. **Code Style & Formatting**:
   - `ruff check`: All checks passed with 0 errors.
   - `ruff format --check`: 100% clean formatting.

## Details

According to the [Anthropic Messages API specification](https://docs.anthropic.com/en/api/messages), the top-level `system` field and inline system messages accept either a plain string or a list of text content blocks.

Previously, when a client supplied non-text content blocks (such as `image` blocks) inside the `system` field or inline `system` messages:
- `_convert_system_message()` and `_extract_system_text()` in `vllm/entrypoints/anthropic/serving.py` filtered exclusively for `block.type == "text"`, silently omitting non-text content without warning or validation feedback.
- The server returned HTTP 200, creating an ambiguous state where clients believed the image was being processed by downstream multimodal vision models.

This pull request mirrors the warning-based compatibility approach adopted for OpenAI system messages in #34072:
1. Emits a clean `logger.warning_once` in `_convert_system_message` and `_extract_system_text` identifying the unsupported content block type.
2. Skips `tool_addition` and `tool_removal` blocks from warning, as they are legitimately applied by `_resolve_tools`.
3. Keeps `protocol.py` clean to prevent duplicate warnings.
4. Rebased cleanly onto latest `main`.
