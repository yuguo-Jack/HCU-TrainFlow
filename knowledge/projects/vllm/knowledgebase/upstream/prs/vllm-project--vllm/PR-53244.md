# [Bugfix][NIXL] Fix PUSH heartbeat failing to renew KV leases

[Upstream PR](https://github.com/vllm-project/vllm/pull/53244) · state: open · merged: False

## Original PR description

## Purpose
Fix https://github.com/vllm-project/vllm/issues/53095. This fixes PUSH mode Heartbeats failing to renew the P-side KV lease. No wire-format change. 

In PULL mode, remote_request_id is the P-side internal request ID, so Heartbeat can use it for exact matching.
In PUSH mode, the old Heartbeat also sent `remote_request_id`, but it is actually the Router UUID. 
Because requests are sent concurrently, D cannot know the P-side `internal request ID`. 

This change aligns `Heartbeat` with the existing `PUSH_REG` protocol:

  - PUSH_REG: D → P, carrying the D-side internal request ID.
  - Heartbeat: D → P, also carrying the D-side internal request ID.
  - P strips the random suffix and matches it against its own internal request ID by base ID.

- YannikHinteregger · COMMENTED · 2026-09-30T13:50:31Z · [source](https://github.com/vllm-project/vllm/pull/53244#pullrequestreview-5367107076)

Thanks for the contribution, it's a clear improvement over the current state. Sadly it's not a full fix. And I think that with the information currently available it can't be fixed fully.

When two requests share an X-Request-Id, renewing only the first match can expire a live lease. Renewing all of them can keep stale ones alive while the id keeps being reused.

C1 and C4 from #48633 have the same underlying problem. They need an extra signal that reliably identifies the dispatched request (from the router) to be fixed without other side effects.

I opened a discussion on Slack [here](https://vllm-dev.slack.com/archives/C0A9AAG7QR2/p1790760867615409) on how best to introduce that signal.

The question for this PR is whether we merge it as a temporary improvement or wait for that decision to fix these bugs together. I'd leave that to @NickLucche.

If we merge it as a temporary improvement, I'd suggest moving the push-only logic from base_scheduler.py and base_worker.py into push_scheduler.py and push_worker.py.
