# [Model] Support box and ground decisions with GUI-Actor

[Upstream PR](https://github.com/vllm-project/vllm/pull/62248) · state: open · merged: False

## Original PR description



## Overview

Adds `box` and `ground` as structured-decision primitives, answered by
GUI-Actor's pointer head, and the `GuiActorForConditionalGeneration`
architecture that serves it. `/v1/systemone` gains two question types that
locate a target in an image instead of picking an option.

The primitives follow the TypeSafe "System One" contract, so a request written
for the reference serving layer answers here the same way.

Closes #62247, which carries the API design write-up.

No other PR covers this: searched `box ground`, `gui-actor`, `pointer head`,
`bounding box question`, `ground question` and `systemone` for open PRs — the
`systemone` hits are unrelated frontend fixes, none adds a spatial question type
or a pointer-head model.

## Claims

- `/v1/systemone` accepts `{"type": "box"}` and `{"type": "ground"}` questions:
  a box returns four normalised edges, a ground returns a 0–999 click point,
  each with a confidence.
- `microsoft/GUI-Actor-{3B,7B}-Qwen2.5-VL` serve through vLLM, detected from
  their weights with no config change.
- Answers are decoded from the pointer head's per-patch distribution using the
  reference implementation's arithmetic, byte-identical on 600 randomised grids.
- Scores **90.49 / 95.12 / 84.87** (All / text / icon) `hit_top1` on ScreenSpot,
  against **79.09 / 83.79 / 73.39** for the Jev reference `box`.
- A model that cannot answer a question type returns 501, not 400.

## Details

### Why the pooler returns raw logits

`GuiActorPooler` returns the head's raw `proj_dec @ proj_enc.T / sqrt(d)` scores.
Softmaxing them in the pooler would give a row that already sums to one, and the
decode softmaxes again at the checkpoint's temperature — a second softmax over a
normalised row flattens the distribution and moves every decoded edge.

### Why the temperature never moves the geometry

The checkpoint ships a fitted `pointer_temperature`. It scales the confidence
only: the region or box is extracted from the raw distribution first, and the
temperature is applied to the probability mass afterwards. This matches the
reference, and `test_spatial.py` pins it.

### Why the embed-layer capture is cloned

The head's encoder side reads the embed layer's output, the vision features as
they were scattered into the placeholders. `embed_input_ids` clones it because
the runner writes the result into a preallocated buffer it reuses every step;
holding a reference would read the next step's tokens at pooling time.

### Why chunked prefill and prefix caching are off

The answer is read from the image patches of the prompt's own prefill. A chunked
prompt leaves the capture without them, and a cached image prefix skips the
embed forward entirely. Both are disabled in
`GuiActorForConditionalGenerationConfig`. The reference layer hit a related bug
by keying its image prefix cache on token ids — Qwen2.5-VL renders an image as a
fixed run of `<|image_pad|>` whose length depends only on the image size, so two
equal-size screenshots collided.

### Why detection keys on tensor names

`is_gui_actor_checkpoint` accepts either a `...WithPointer` architecture name or
the `multi_patch_pointer_head.` tensor prefix. The tensors are authoritative: a
config can declare the pointer token ids without a trained head, and such a
model would serve a random grounding score. The architecture name is checked
first because it costs no download.

The weight check is gated on the config still naming a Qwen2.5-VL architecture.
Without that gate the class rewrites its own `text_config` and constructs itself
from inside its own `__init__` — 34 levels deep, allocating a model per level,
until the device runs out of memory.

### Why other backbones are rejected

`MODEL_ARCH_CONFIG_CONVERTORS` dispatches on `model_type`, and only `qwen2_5_vl`
has a GUI-Actor convertor. A pointer checkpoint over another backbone would
otherwise load as a plain backbone with its pointer tensors silently unmatched.
`assert_no_foreign_gui_actor`, called from the base convertor, rejects a
`...WithPointer` architecture on any other model type at load.

### Scope and follow-ups

- **Only Qwen2.5-VL backbones.** The head's projection is square, which needs the
  vision tower's output width to equal the language model's. Qwen3-VL and Qwen3.5
  are a follow-up.
- **`/v1/decisions` does not accept the new types.** It keeps OpenAI's schema; a
  box or ground question there is a 422, unchanged.

### Complexity

Production diff is **+1434/−29**. Of that, 382 lines are `spatial.py`, a
straight port of the reference decoder whose correctness is established by
comparison rather than design; 344 are the new model architecture, comparable
to `d3.py` plus its pooler; the rest extends the existing question-type and
strategy contracts rather than adding parallel implementations. New primitives
and a new architecture account for the size.
