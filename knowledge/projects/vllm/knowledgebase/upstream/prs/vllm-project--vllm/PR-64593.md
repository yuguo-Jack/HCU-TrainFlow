# [CI] Enroll the remaining Distributed, EP and fault-tolerance jobs in automatic sharding (25 jobs)

## Overview

Enrolls the remaining Distributed, EP and fault-tolerance jobs in `automatic_shard`: 25 jobs (13 steps and 12 AMD mirrors). Part of a series that enrolls every remaining test step, split by test area for review. No commands change.

## Claims

| Step | Plan | AMD mirror |
|---|---|---|
| `distributed-compile-comm-4-gpus` | 1 shard | 1 shard |
| `distributed-torchrun-shutdown-tests-2-gpus` | 1 job (not plain pytest) | 1 job (not plain pytest) |
| `distributed-comm-ops` | 1 shard | 1 shard |
| `sharded-rdt-weight-transfer` | 1 shard | 1 shard |
| `distributed-tests-8xh100` | 1 job (not plain pytest) | 1 job (not plain pytest) |
| `preload-2-gpus` | 1 shard | 1 shard |
| `distributed-compile-rpc-tests-2-gpus` | 1 shard | 1 shard |
| `gemm-rs-ar-2xb200` | 1 shard | 1 shard |
| `distributed-tests-2xb200` | 1 shard | 1 shard |
| `qwen4-exp-sp-tests-4-gpus` | 1 shard | 1 shard |
| `eplb-execution` | 1 shard | 1 shard |
| `eplb-algorithm` | 1 shard | 1 shard |
| `amd-fault-tolerance-e2e-2xh100` | 1 shard | none |

- One-shard and one-job plans run the same tests as on main, as one job, and split by themselves once their tests grow.


## Validation

- Planned each step and mirror with ci-infra main's planner against main's timings; every plan is within 10% of the same plan run as one job.
- The sharding harness (each shard's commands run against a mock test tree, as a PR build and as main with the OTel wrapper) shows every test runs exactly once wherever a plan has 2 or more shards.
- Every step and mirror passes on recent main runs, nightly included.
- `/ci run` (98458) plus a scoped build (98469) for the optional steps and AMD mirrors on this head: every enrolled job passed, and every shard finished under 22 minutes.

## Details

- **Not plain pytest** steps (shell scripts, `torchrun`, examples) are enrolled too; the generator keeps them as one job. Standalone AMD steps plan like any other since vllm-project/ci-infra#871.
- **caplog.** Files that assert on logs sit in one-shard plans here, so their order in the process doesn't change.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job. Fallback-aware timeouts belong in a central timeout setting.
