# [Bugfix][Multimodal] Reject prefill caps smaller than an intact item

[Upstream PR](https://github.com/vllm-project/vllm/pull/62030) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fixes #62031.

Reject a nonzero long-prefill cap smaller than the configured maximum multimodal item when item chunking is disabled. This replaces an accepted configuration that can permanently stall contended requests with an actionable startup error.

## Claims

- Validate the cap alongside the existing maximum-item versus batch-budget check.
- Cover fixed and adaptive caps; retain disabled-cap, equal/larger-cap, chunkable-input, and disabled-modality behavior.
- Preserve the scheduler, hard budgets, whole-item guard, and fairness policy. Defaults remain unchanged.

## Details

The scheduler caps proposed prefill work before checking whole-image boundaries. If the cap is below an intact item, the boundary guard schedules zero tokens. With multiple eligible requests, the cap stays active and the same state repeats. The baseline remained stuck for 1,000 scheduling passes. Adaptive fair share can also stay below the item size.

The fix adds a 12-line check to compute_mm_encoder_budget, following its existing batch-budget validation. The error tells users to disable the cap with zero or raise it sufficiently. The optimization guide and field documentation explain that validation uses the configured maximum item size, even if a particular request is smaller or alone. Encoder-decoder configuration already resets the threshold to zero.

This matches the fail-fast approach proposed in the [review of #52412](https://github.com/vllm-project/vllm/pull/52412#pullrequestreview-5407246881), while preserving the merged boundary fixes in [#52412](https://github.com/vllm-project/vllm/pull/52412) and [#59721](https://github.com/vllm-project/vllm/pull/59721). The proposal itself has not received maintainer approval.

Tradeoff: conservative startup rejection. A low cap that would work for one request, small images, or light adaptive contention is rejected because later requests could make it unschedulable. Default cap zero and configurations allowing item chunking are unaffected. No performance or output-quality improvement is claimed.

Duplicate searches on October 16, 2026 found no matching open cap-validation fix. [#59030](https://github.com/vllm-project/vllm/pull/59030) changes waiting-queue requeueing. [#61733](https://github.com/vllm-project/vllm/pull/61733) validates whole prompts when chunked prefill is disabled after startup; this validates a multimodal item's per-request cap in configurations that still allow chunked text prefill.
