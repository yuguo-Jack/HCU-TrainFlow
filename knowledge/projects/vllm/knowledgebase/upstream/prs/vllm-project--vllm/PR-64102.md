# [Bugfix][Frontend] Report a bad run-batch url instead of raising KeyError

[Upstream PR](https://github.com/vllm-project/vllm/pull/64102) · state: open · merged: False

## Original PR description

## Overview

Report a missing, null or non-string `url` in a `vllm run-batch` input line as `Invalid request on line N: ...` instead of a raw `KeyError: 'url'`.

## Claims

- `validate_batch` now rejects a bad `url` with its normal per-line error, before the model loads.

## Validation

`pytest tests/entrypoints/launchers/test_run_batch.py -k validate_batch` (CPU, no GPU needed): the new `test_validate_batch_reports_a_bad_url_field` fails before (3 failed, `KeyError: 'url'` at `run_batch.py:188`) and passes after (5 passed). `ruff check` and `ruff format` are clean.

## Details

`BatchRequestInput.check_type_for_url` reads `info.data["url"]`. Pydantic still runs the `body` validator after `url` fails, so the key is absent, and `validate_batch` only catches `pydantic.ValidationError`. The fix uses `info.data.get("url")` and returns the body untouched when `url` is `None`, so the `url` error is the one reported. No method check or other validation is added.
