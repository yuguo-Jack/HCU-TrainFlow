# [Compile][SP] Record reduce_scatter divisibility so AsyncTP all-gather fusions match

[Upstream PR](https://github.com/vllm-project/vllm/pull/60530) · state: closed · merged: False

## Original PR description

Purpose
Fixes https://github.com/pytorch/test-infra/issues/8870

Note an alternative or co-fix is to allow pattern matcher to specialize. https://github.com/pytorch/pytorch/pull/200303
 
Root cause. pytorch/pytorch#195383 ("[inductor]  makes the pattern matcher re-trace each match and require the graph's fake-tensor shapes to equal the re-traced ones, checked with statically_known_true.


The SP pass rewrites x (length s) into all_gather(reduce_scatter(x)). That produces length tp * (s // tp), while downstream nodes keep length s. The two are equal only if s % tp == 0. vLLM guarantees this: _pad_for_sequence_parallelism pads num_tokens to a multiple of TP, and the runner asserts it. But the padding happens before the compiled model runs, so the ShapeEnv never learns the fact and the all-gather + GEMM matches are rejected:

expected_meta: unsqueeze val does not match ((1, 2*((s72//2)), 4096), torch.float8_e4m3fn, ...)
Fix. After the SP rewrite, record torch._check(size % world_size == 0) on the input of each vllm.reduce_scatter the pass inserted. This adds no assumption beyond what the reduce-scatter rewrite already relies on, and it runs only when SP matched. With the fact recorded, and the diff i landed last week pytorch/pytorch#198808 ("Restore exact FloorDiv cancellation") simplifies tp * (s // tp) to s, and the matcher accepts the fusions.

Note: pytorch/pytorch#195383 is on PyTorch main/nightly and not yet in a release.
