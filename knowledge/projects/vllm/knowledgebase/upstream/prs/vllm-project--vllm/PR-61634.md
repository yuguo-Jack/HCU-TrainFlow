# [Bugfix][Attention] Make the query contiguous for TRTLLM ragged MLA prefill

[Upstream PR](https://github.com/vllm-project/vllm/pull/61634) · state: closed · merged: True

## Original PR description

## Overview

`TRTLLM_RAGGED` MLA prefill passes the query straight to FlashInfer's `trtllm_ragged_attention_deepseek`, whose launcher forwards K/V strides but not Q strides, so a strided query is read as if it were packed and prefill attention is silently wrong. This makes the query contiguous at both call sites (a no-op for callers that already pass a contiguous query, such as native models).

The Transformers modeling backend hits this because it hands MLA a transposed query (`[1, heads, tokens, dim] -> [tokens, heads, dim]`), and `TRTLLM_RAGGED` is the default MLA prefill backend on Blackwell.

## Claims

- Fixes MLA prefill for strided queries with `TRTLLM_RAGGED`, which broke every MLA model on the Transformers backend on Blackwell (e.g. GLM-4.7-Flash gsm8k 0.8% -> 83.5%, native 83.6%).
- No change for contiguous queries.

## Validation

GLM-4.7-Flash, gsm8k (5-shot, 1319 questions), 1x B200:

| Config | Accuracy | Invalid |
|---|---|---|
| Native | 83.6% | 0.1% |
| Transformers backend, `main` | 0.8% | 31.8% |
| Transformers backend, this PR | 83.5% | 0.0% |

```bash
vllm serve zai-org/GLM-4.7-Flash --max-model-len 8192 [--model-impl transformers]
python tests/evals/gsm8k/gsm8k_eval.py --port 8000
```

On a small random-weight GLM-4.7-Flash-architecture checkpoint, the first generated token's logprob vs HF eager (same prompt, teacher-forced) went from 0.19 off to 0.00 with `TRTLLM_RAGGED`. Other MLA backends were already correct with the strided query: `FLASH_ATTN` prefill, and `FLASHINFER_MLA` / `CUTLASS_MLA` / `TRITON_MLA` decode.

Tests on B200:

```bash
pytest tests/v1/attention/test_mla_prefill_registry.py tests/v1/attention/test_mla_prefill_selector.py  # 47 passed
pytest tests/v1/attention/test_mla_backends.py -k TRTLLM_RAGGED  # 580 passed
```
