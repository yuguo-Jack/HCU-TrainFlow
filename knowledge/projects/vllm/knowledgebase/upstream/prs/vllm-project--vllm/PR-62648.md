# [Bugfix][Model] Build Pixtral vision position ids on device

[Upstream PR](https://github.com/vllm-project/vllm/pull/62648) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fixes the `Multimodal Models (Extended Generation 1)` CI job, where `test_pixtral.py::test_chat_consolidated` fails on main in every full build (e.g. [95829](https://buildkite.com/vllm/ci/builds/95829), [95887](https://buildkite.com/vllm/ci/builds/95887)) with `RuntimeError: GPU<->CPU sync detected`.

## Claims

- The Pixtral vision encoders no longer do a blocking host-to-device copy on every encoder forward: both the Mistral-format `VisionTransformer` and the HF-format `PixtralHFVisionModel` (used by Mistral3) on transformers >= 5.17.
- `test_chat_consolidated` passes again under `VLLM_GPU_SYNC_CHECK=error`, and the HF-format path no longer trips the check either. Outputs are unchanged.

## Validation

On 1x GB300 with `VLLM_GPU_SYNC_CHECK=error` and transformers 5.20.2 (the CI pin):

| Path | main | this PR |
|---|---|---|
| Mistral format: `pytest tests/models/multimodal/generation/test_pixtral.py -k test_chat_consolidated` | failed, `GPU<->CPU sync detected` at `pixtral.py:1033` (same trace as CI) | 1 passed, logprobs match the stored H100 reference |
| HF format: `mistralai/Ministral-3-3B-Instruct-2512` loaded from `model.safetensors` (`Mistral3ForConditionalGeneration`), one image chat request | failed, `GPU<->CPU sync detected` at `pixtral.py:1596` | passes; greedy output identical to main run with the sync check disabled |

## Details

`position_meshgrid` built the per-patch `(row, col)` coordinates with `torch.arange` on the CPU, and `VisionTransformer.forward` then moved them to the GPU with `.to(self.device)`. The source tensor is pageable, so the copy blocks the host, which the sync checker in CI (`VLLM_GPU_SYNC_CHECK=error`) reports as a failure. The fix creates the coordinates directly on the device of the patch embeddings, which removes the copy.

The HF-format path (`PixtralHFVisionModel`) has the same pattern in `position_ids_in_meshgrid`. It is fixed the same way. CI does not catch it today because the HF-format Pixtral tests are skipped as large-GPU tests. Its `.to(self.device)` stays, because on transformers < 5.17 the function delegates to the transformers implementation, which still builds the ids on the CPU. When the ids are already on the device, the call does nothing.
