# [Bugfix][HiSparse] Stop the host pool feeding device KV cache residency metrics

[Upstream PR](https://github.com/vllm-project/vllm/pull/58725) · state: closed · merged: True

## Original PR description

> **NOTE:** This PR was reduced to a one-line change: the HiSparse host pool no longer gets the device pool's metrics collector (`metrics_collector=None` in `HiSparseSourceManager.bind_host_pool`), so host blocks stop feeding the device `vllm:kv_block_*_seconds` histograms. That removes the block-ID collision described below at its source, instead of keying samples by pool. Host-tier residency metrics are proposed separately in #59485 (on top of #58949). The description below is the original.

## Purpose

With HiSparse and `--kv-cache-metrics`, the host and GPU pools share a metrics
collector, but each pool numbers its blocks independently. The collector keys
samples by `block_id` alone.

This results in incorrect metrics recording in KV cache block activities
when using HiSparse.

A false lifetime, idle-time, and reuse-gap histogram will affect users
relying on it to investigate cache turnover and reuse.

For example, allocate GPU block 1 at t=1 s and host block 1 at t=2 s. The host
allocation currently emits a false one-second GPU eviction sample, even though
the GPU block remains allocated. With this fix, **both histories remain active
and no eviction sample is emitted**.

This MR key samples by `(block.pool, block.block_id)` in allocation, access
and eviction callbacks. Allowing the KV cache block activities to be correctly
accounted.


The callbacks only update telemetry; allocation and eviction decisions are
unaffected. Ordinary hybrid/SWA groups sharing one pool retain their existing
behavior.


## Test Coverage
