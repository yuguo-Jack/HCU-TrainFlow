# [Spec Decode][MRV2] Add request lifecycle hooks to speculators

[Upstream PR](https://github.com/vllm-project/vllm/pull/64306) · state: open · merged: False

## Original PR description



## Overview

Forward request add/remove and engine shutdown from the MRV2 model runner to the speculator, as no-op hooks on `BaseSpeculator`. Speculators that keep per-request state, such as custom speculators (vllm-project/vllm#63205), can then track requests without reaching into the runner.

## Claims

- `BaseSpeculator` gains no-op `add_request(req_index, new_req_data)`, `remove_request(req_id)` and `shutdown()`. In-tree speculators are unchanged.
- The runner calls `remove_request` before the request's slot is freed, and only for requests it knows. `add_request` also covers resumes after preemption and streaming input updates.

## Validation

- `pytest tests/v1/worker/test_gpu_model_runner_v2.py`: the new `test_speculator_request_hooks` passes, and fails if the runner changes are reverted, if `remove_request` runs after the slot is freed, or if it runs for unknown requests.
- End to end on one B300 (n-gram drafting, a KV cache small enough to force preemption, one request aborted mid-decode), with the hooks overridden to record calls: every request, including warmup requests, got `add_request` then `remove_request` before its slot was freed, again after preemption; `shutdown` ran once. Greedy outputs match the unpatched build with sync scheduling.

## Details

- vllm-project/vllm#60339 (MRV2 suffix decoding) looks up `add_request` on the speculator by name and calls `add_request(req_index)`. Once the base method exists, that lookup always finds it, so the call needs to match this signature. Its suffix-specific hooks (`on_requests_finished`, `reset_state`) are out of scope here.
