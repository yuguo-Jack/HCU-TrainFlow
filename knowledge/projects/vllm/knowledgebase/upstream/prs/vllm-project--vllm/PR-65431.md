# [Model] Gemma 4: native packed vision tower on MMEncoderAttention

## Overview

Gemma 4's vision tower becomes a native vLLM tower that packs images and video frames with `cu_seqlens` instead of padding them, so it runs on any `--mm-encoder-attn-backend` (#43178, review of #43440).

Not a duplicate: #60577 keeps SDPA with a mask and is superseded; #60478 patches the transformers tower this PR removes. Tower LoRA (#42662) keeps working: same weight names.

## Claims

- Native tower from vLLM layers (`MMEncoderAttention`, `get_rope` + `ApplyRotaryEmb`, moonvit's packed merger); same checkpoints, no mapper. Reused by DiffusionGemma and EmbeddingGemma2.
- MMStar unchanged (within 1 point); TTFT up to 7% lower with the default backend and 6-17% lower with `TRITON_ATTN`, which picks up gfx1151's encoder attention work (#56450).
- Encoder CUDA graphs follow token budgets like Qwen3-VL.
- Packed `TORCH_SDPA` under `cudagraph_mm_encoder` now fails at startup with a clear error (it used to fail with a device-copy error during capture).

```python
# mmstar.py MODEL OUT.json: first 300 MMStar questions, greedy, 64 tokens.
# Needs mmstar.parquet from https://huggingface.co/datasets/Lin-Chen/MMStar
import io, json, os, re, sys
os.environ["VLLM_ENABLE_V1_MULTIPROCESSING"] = "0"
import pyarrow.parquet as pq
from PIL import Image
from vllm import LLM, SamplingParams

def letter(text):
    text = text.strip()
    m = (re.match(r"\(?([A-D])(?:$|[\s.:)])", text)
         or re.search(r"(?:answer|option)(?: is)?[:\s*]*\(?([A-D])\b", text, re.I)
         or re.search(r"\*\*\(?([A-D])[:.)*]", text))
    return m.group(1) if m else None

model, out = sys.argv[1:3]
rows = pq.read_table("mmstar.parquet").to_pylist()[:300]
llm = LLM(model=model, max_model_len=4096, max_num_seqs=8,
          limit_mm_per_prompt={"image": 1}, gpu_memory_utilization=0.85, seed=0)
msgs = [[{"role": "user", "content": [
    {"type": "image_pil", "image_pil": Image.open(io.BytesIO(r["image"])).convert("RGB")},
    {"type": "text", "text": r["question"] + "\nAnswer with the option's letter."}]}]
    for r in rows]
outs = llm.chat(msgs, SamplingParams(temperature=0, max_tokens=64),
                chat_template_kwargs={"enable_thinking": False})
answers = [letter(o.outputs[0].text) for o in outs]
print("accuracy", sum(a == r["answer"] for a, r in zip(answers, rows)) / len(rows))
json.dump(answers, open(out, "w"))  # compare two runs answer by answer
```

```python
# ttft.py MODEL [BACKEND]: one-image requests, max_tokens=1, new image each time.
import base64, io, os, statistics, sys, time
os.environ["VLLM_ENABLE_V1_MULTIPROCESSING"] = "0"
import numpy as np
from PIL import Image
from vllm import LLM, SamplingParams

kw = dict(model=sys.argv[1], max_model_len=4096, max_num_seqs=1,
          limit_mm_per_prompt={"image": 1, "video": 0},
          gpu_memory_utilization=0.85, seed=0)
if len(sys.argv) > 2:
    kw["mm_encoder_attn_backend"] = sys.argv[2]
llm = LLM(**kw)
rng = np.random.default_rng(0)
for w, h in [(336, 336), (1024, 800)]:
    times = []
    for i in range(3 + 15):
        buf = io.BytesIO()
        Image.fromarray(rng.integers(0, 255, (h, w, 3), dtype=np.uint8)).save(buf, "PNG")
        url = "data:image/png;base64," + base64.b64encode(buf.getvalue()).decode()
        msg = [{"role": "user", "content": [
            {"type": "image_url", "image_url": {"url": url}},
            {"type": "text", "text": "Describe the image."}]}]
        t0 = time.perf_counter()
        llm.chat(msg, SamplingParams(temperature=0, max_tokens=1), use_tqdm=False)
        if i >= 3:
            times.append((time.perf_counter() - t0) * 1e3)
    print(f"{w}x{h}: median {statistics.median(times):.1f} ms, "
          f"stdev {statistics.pstdev(times):.1f} ms")
```

## Details

Three commits:

1. **[NFC]** Move the `cu_seqlens` graph-buffer padding shared by Qwen2.5-VL and Qwen3-VL to `MMEncoderAttention.cu_seqlens_buffer_padding(backend)`.
2. **Encoder CUDA graphs** (+18 lines): `EncoderItemSpec.eager_only` and the clear `TORCH_SDPA` error.
3. **Gemma 4:** new `gemma4_vision.py` (440 lines) while `gemma4_mm.py` drops 679, net −12 non-test lines. Removes the resolution buckets, `_encoder_chunk`, the tower LoRA padding and the row-width graph axis. Graphs size their sequence slots (`budget // 35`) and `max_seqlen` (configured `max_soft_tokens`) to what they can hold; larger items run eager.

Trade-offs:

- **Behavior change:** Gemma 4 with `TORCH_SDPA` (RDNA default) and `cudagraph_mm_encoder` (off by default) now needs another backend, e.g. `TRITON_ATTN`; documented in `docs/design/cuda_graphs_multimodal.md`.
- **Same as the old tower:** replicated linears (DP is #60314), and separate q/k/v and gate/up projections, because each clipped linear has its own bounds.
- **Numerics:** `GELUTanh` is used directly because `get_act_fn` swaps in exact GELU on ROCm. vLLM's `RMSNorm` rounds differently from transformers', which MMStar covers.
- **FlashInfer:** a new `separate_qkv` flag on `maybe_recompute_cu_seqlens`; GQA is rejected.

Thanks for upstreaming this, @roberteg16. I validated it on NVIDIA H100 (SM90), rebased locally onto `2d858ac60a`. Two things break there; both fixes are below.

**1. The Triton case of `test_gemma4_vision.py` fails on NVIDIA**

```
FAILED test_packed_tower_matches_transformers[False-AttentionBackendEnum.TRITON_ATTN]
FAILED test_packed_tower_matches_transformers[True-AttentionBackendEnum.TRITON_ATTN]
Greatest absolute difference: 0.0222 (up to 0.001 allowed)
```

On NVIDIA GPUs, Triton runs fp32 `tl.dot` in TF32. With `TRITON_F32_DEFAULT=ieee` the test passes at 1e-3. Fix: keep 1e-3 for SDPA and allow 3e-2 for Triton on CUDA (https://github.com/hnt2601/vllm/commit/802ac1fcd3e11d824edbb84542f425880a3ec202).

**2. Packing the whole encoder batch into one eager call costs KV cache**

`google/gemma-4-31B-it`, FA, eager, `max_model_len=8192`, `gpu_memory_utilization=0.9`, same H100:

| | peak activation (profile) | available KV | starts? |
|---|---|---|---|
| main | 2.78 GiB | 8.31 GiB | yes |
| this PR | **3.83 GiB** | 6.09 GiB | **no**: needs 6.89 GiB for one 8192-token request |
| this PR + cap below | 2.81 GiB | 7.99 GiB | yes |

The memory profile now runs the tower on every dummy image in a single call, so the encoder's peak activations grow. Fix: cap each eager call at 4 × 1120 soft tokens (https://github.com/hnt2601/vllm/commit/f77e4f64948608c2c7bb17f2930b8bec0603eeed). Tower LoRA still uses one call, because the adapter mapping spans the encoder batch.

**H100 results with both fixes** (`google/gemma-4-31B-it`, BF16, 1× H100 80GB):

| ViT backend | eager | `cudagraph_mm_encoder` |
|---|---|---|
| FLASH_ATTN (auto on SM90, head_dim 72) | OK | OK (KV +6.7% vs main's graphs) |
| FLASHINFER | OK | OK |
| TRITON_ATTN | OK | OK |
| TORCH_SDPA | OK | startup error (intended) |

Results are greedy over 6 image prompts with 64 tokens, compared against main. Every divergence falls within the top-5 logprobs, and FA vs SDPA on the native tower diverge by the same amount, so it is bf16 noise. Graph runs used MRV1, because encoder graphs on MRV2 OOM during capture for 31B on main as well. That MRV2 issue is unrelated to this PR, and I'll file it separately.

These fixes are in #65591. It is stacked on this PR and only adds the commits above. I'll keep it a draft until this PR lands; feel free to pull the commits in here instead if you prefer.
