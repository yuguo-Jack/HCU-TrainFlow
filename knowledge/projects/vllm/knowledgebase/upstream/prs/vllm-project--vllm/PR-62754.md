# [Attention] Conditional device/CPU query-lens mismatch support for FlashInfer XQA (SM120/121)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62754) · state: open · merged: False

## Original PR description

### Summary

Enables `supports_device_cpu_query_lens_mismatch()` for the FlashInfer
dedicated XQA decode kernel on SM120/SM121, so adaptive verification can run
full attention on FlashInfer instead of falling back to Triton. Gated by a
single self-contained predicate; fail-closed at the cudagraph gate and builder
finalization if a configuration that passes the predicate cannot reach
device-ragged decode.

### Problem

Adaptive verification trims per-request verify windows **on device**; the
device `query_start_loc` diverges from the CPU copy while token totals stay
conserved. The FlashInfer backend opted out of
`supports_device_cpu_query_lens_mismatch()` because parts of its decode
planning read the CPU copy — so adaptive verification was forced onto Triton
for full attention, ~2-2.5x slower than FlashInfer *adaptive* at long context
on SM120 (parent campaign E31b: Triton adaptive 40.7/32.4 t/s vs FlashInfer
adaptive ~82 t/s at 32K ctx; the FlashInfer *static* control arm was 141 t/s).

FlashInfer's dedicated XQA API takes a CUDA `q_cu_seq_lens` the kernel
dereferences on device, with a scalar max-draft-length bound — so the XQA
decode path *can* serve device-ragged layouts. This PR admits that path under
the configurations where it is proven safe.

Note: the 141 t/s figure is the FlashInfer *static* arm (a control), not this
patch's adaptive result. The parent campaign's FlashInfer + DSpark *adaptive*
arm measured ~82 t/s on the same workload; the adaptive width policy (which
trims to narrow widths on fast backends) is independent of this patch and is
the residual gap, not the backend path this PR enables.

### Design

1. **One shared predicate** `_adaptive_xqa_mismatch_safe(vllm_config)` —
   self-contained in its argument (no thread-local config reads). True only
   when: adaptive verification on + SM120/SM121 + DCP=1 + causal target
   attention + `supports_trtllm_attention(is_prefill=False)` + not
   forced-native + model-config head-count divisibility (mirrors the SM100
   classmethod gate). The selector gate, the manager's independent scan, and
   the varlen-decode cudagraph result all consult this one predicate, so they
   agree on the configurations the PR admits (a configuration that passes the
   predicate but cannot reach device-ragged decode fails closed at capture).

2. **Deferred finalize** (`_finalize_adaptive_decode(decode_query_len,
   is_target)`): the runner's resolved decode width is the authoritative bound
   (model-state data, not on `SpeculativeConfig`); the group's target-layer
   role comes from the runner-derived target layer names (all KV-cache
   attention layers minus the speculator's draft layers, the #52783
   derivation), resolved per group in `init_attn_backend`. Allocation + kernel
   warmup are transactional; the mode flag flips last; finalization is one-shot
   at runner init.

3. **Mismatch-safe classification**: the CPU even-distribution decides only
   the provable single-token fast path (all widths exactly 1); otherwise device
   offsets pass through untouched with the fixed runner-resolved bound. A
   threshold clamp routes anything wider than the bound through prefill (never
   through uniform-XQA metadata).

4. **Persistent device-built packed mask** (Triton kernel, preallocated buffer,
   binary search over device offsets, stale-proof tail zeroing) rewritten from
   device offsets every step — never built from CPU data.

5. **Exclusions**: cascade disabled for mismatch batches before any wrapper
   planning; defense-in-depth asserts against native decode, DCP>1, and
   uniform-only TRTLLM-API metadata.

6. **SM100 unchanged**: merged #52157 owns the SM100 trtllm-gen varlen path;
   this PR leaves SM100 behavior exactly as merged (SM100 adaptive already
   gets `get_varlen_cudagraph_max_query_len() == 8` while the enum stays
   `UNIFORM_BATCH`; this PR adds the XQA branch to that function without
   changing the SM100 path).

### Validation

**In-tree tests** (reproducible in CI):
- Predicate truth table (`test_predicate_gates`): adaptive off, DCP>1,
  non-causal, forced-native, `None` config.
- Finalization role gating (`test_finalize_role_gating`,
  `test_finalize_xqa_incapable_target_fails`,
  `tests/v1/worker/test_attn_utils_adaptive_finalize.py`).
- Mismatch-safe classification and device mask
  (`test_classification_passes_device_truth`, `test_build_ragged_metadata`,
  mask-versus-oracle tests).
- Varlen cudagraph capability
  (`test_flashinfer_varlen_cudagraph_capability`): the XQA case now expects
  the decode-width bound (8) when the predicate is true, so the varlen gate
  agrees with the predicate.
- DP-sync prefill exclusion
  (`test_dp_sync_keeps_prefill_rank_out_of_varlen_decode_graph`).

**Hardware probe (SM120 / RTX 5090, now in-tree):**
- `tests/v1/attention/test_flashinfer_xqa_w0_probe.py` — SM120/121-gated +
  ninja-gated pytest test. Run it on an SM120 GPU with `ninja` in PATH to
  reproduce: a CUDA graph captured with uniform geometry replays across
  in-place-updated ragged layouts — bitwise-identical to eager XQA and within
  one bf16 ulp of an SDPA oracle, no host synchronization, on the
  production-flags module (fp8 KV + SWA + spec width 8).
- Serving-time evidence: FULL-cudagraph replays with device != CPU widths
  (e.g. dev `[6,2,1,7,0,...]` vs cpu `[4,4,4,4,0,...]`) logged immediately
  before `graphs[desc].replay()`; identity oracle vs static 8/8
  token-identical (record held by submitter).

SM121 uses the same dedicated XQA API and is admitted by the same predicate
(capability family 120), but the W0 probe and serving-time evidence above are
SM120-only; SM121 has not been separately probed.

### Known limitations (documented for review)

- Class-level capability cannot see per-group head counts; a hybrid model with
  group head counts differing from model-wide can pass the selector and fail
  closed at finalize instead of falling back. The upstream-shaped fix is a
  group-aware capability query (out of scope here).
- Head-dim groups that fail `_is_xqa_head_dim_supported` (e.g. the Gemma-4 512
  path) also fail closed at finalize (the same shape as the head-count case);
  they are not listed in the classmethod gate.
- The predicate reads `supports_trtllm_attention(is_prefill=False)`, which is
  false under `VLLM_BATCH_INVARIANT` or when the NVIDIA artifactory check
  fails; it also rejects `num_kv_heads == 0`. The XQA decode path shares the
  trtllm-attention cubin infrastructure (the same cubin that the trtllm-gen
  path uses), so the predicate requires it as a prerequisite. These inputs
  are not visible to the classmethod gate (which is evaluated before any
  builder exists), so a configuration that passes the gate can still be
  rejected by the predicate — the selector then falls back to another backend.
- The adaptive width *policy* (argmax over confidence-survival /
  boot-profiled cost) is drafter-independent of this patch; where it trims to
  a narrow width on a fast backend it is a measured net loss (parent campaign
  policy-residual analysis). This PR enables the backend path; it does not
  change the width policy.
