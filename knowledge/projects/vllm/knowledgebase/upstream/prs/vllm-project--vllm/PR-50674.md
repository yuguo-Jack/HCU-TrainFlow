# [Bugfix] Fix MoRIIO pending ACK resource exhaustion vulnerability

[Upstream PR](https://github.com/vllm-project/vllm/pull/50674) · state: open · merged: False

## Original PR description

Reject duplicate release messages for already-terminal transfers in _handle_release_message (matching the existing guard in _handle_remote_blocks_message). This prevents unbounded ACK object creation from repeated releases targeting the same transfer_id.

Add TTL (30s) and capacity (1024 entries) bounds to _pending_unmapped_acks in the producer get_finished path. ACKs whose transfer_id is never mapped (e.g. from rejected requests that never reach update_state_after_alloc) are now evicted instead of accumulating indefinitely and being rescanned every scheduler tick.
