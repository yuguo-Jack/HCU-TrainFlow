# [KV Offload] Emit self-describing events for recurrent state groups

[Upstream PR](https://github.com/vllm-project/vllm/pull/62613) · state: closed · merged: True

## Original PR description

## Purpose

`OffloadingEventsTracker` emits a `block_size=0` placeholder `BlockStored` for every group that has a load window. `MambaSpec` groups get a one-chunk window because they depend on a single state, not because their hashes are meaningless: the offloaded chunk is the recurrent state checkpoint at the chunk's last hash. External consumers that index offload residency (a KV-aware router with a CPU/KVCR tier) therefore cannot see where a hybrid prefix is reusable and overestimate it from the attention group (vllm-project/vllm#62510).

## Changes

- `events.py`: `describes_group()` returns true for full-attention and `MambaSpec` groups; windowed attention groups keep the placeholder.
- A recurrent chunk (or partial tail) is announced as **one state checkpoint**: `block_hashes` is the chunk's last hash only, `parent_block_hash` is the hash before it, `token_ids` is empty, `kv_cache_spec_kind="mamba"`, `group_idx` and `block_size` as for attention. `BlockRemoved` fans out to that same single hash. Consumers align it by hash with the attention group's blocks; announcing the whole hash range would let them treat every hash in a multi-hash chunk as a resumable position. The payload is also small: no per-chunk `token_ids` copy is retained for recurrent groups.
- Tests: Mamba chunk store/remove, a multi-hash (chunk-mode) chunk announcing only its last hash, and partial tail (store and lookup); windowed groups still skip.
- `docs/features/kv_offloading_usage.md`: one sentence.

## Test plan

- `tests/v1/kv_connector/unit/offloading_connector/test_events.py`: 51 passed in a CPU-only `vllm/vllm-openai:nightly` container with this `events.py` dropped in; the 4 tiering-config tests in that file fail there identically without the patch (`VllmConfig` hybrid-KV-manager validation in that environment), so they need the CI environment.
- Qwen3.5-4B, `mamba_cache_mode=align`, `CPUOffloadingSpec` + `self_describing_kv_events`, ZMQ subscriber: before, the three SSM groups publish only `block_size=0` events; after, they publish one `kv_cache_spec_kind=mamba` event per chunk carrying the chunk's last hash, at the same hash as the attention group's chunk (table in the first comment; re-run on the checkpoint-only payload pending).
