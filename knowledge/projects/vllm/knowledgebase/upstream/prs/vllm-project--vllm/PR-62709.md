# [Docs] Use release tags for documentation source links

[Upstream PR](https://github.com/vllm-project/vllm/pull/62709) · state: closed · merged: True

## Original PR description

## Overview

Point documentation source links at the Git ref being built, so versioned docs link to the matching source instead of `main`.

Fixes #62669.

## Claims

- Links to this repository's `blob/main` or `tree/main` (hand-written, generated from relative links, or generated example pages) are rewritten to the Read the Docs Git ref. Query strings, fragments and autolink text are preserved.
- Tag builds (including `stable`) use the release tag, from `READTHEDOCS_GIT_IDENTIFIER`.
- Pull request builds use `READTHEDOCS_GIT_COMMIT_HASH`, because their Git identifier is the PR number.
- `latest` and local builds keep `main`.
- Links already pinned to another ref, links to other repositories, code literals and edit links (`edit/main/docs/`) are unchanged.

## Validation

`mkdocs build` with the API reference disabled, once per Read the Docs version type:

| Build | Env | Rewritten links | Ref |
|---|---|---|---|
| Local | none | 432 | `main` |
| `latest` | `TYPE=branch`, `GIT_IDENTIFIER=main` | 432 | `main` |
| `stable` | `TYPE=tag`, `GIT_IDENTIFIER=v0.31.0` | 432 | `v0.31.0` |
| PR | `TYPE=external`, `GIT_IDENTIFIER=62709`, `GIT_COMMIT_HASH=<sha>` | 432 | `<sha>` |

The 22 links already pinned to commit hashes were identical in all builds. In the `stable` build, `design/fusions` links to `blob/v0.31.0/vllm/compilation/passes/fusion/allreduce_rms_fusion.py`.

```bash
API_AUTONAV_EXCLUDE=vllm \
READTHEDOCS_VERSION_TYPE=tag READTHEDOCS_GIT_IDENTIFIER=v0.31.0 READTHEDOCS_VERSION=stable \
mkdocs build -q -d site-stable
grep -rhoE 'href="https://github\.com/vllm-project/vllm/(blob|tree)/[^/"#?]+' site-stable --include='*.html' \
  | sed -E 's#.*/(blob|tree)/##' | sort | uniq -c | sort -rn
```

GitHub serves fork commits under the upstream URL, so PR preview links resolve (checked with a commit from this PR).
