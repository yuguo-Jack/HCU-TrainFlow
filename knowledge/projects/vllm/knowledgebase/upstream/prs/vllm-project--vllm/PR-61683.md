# [Observability] Add tool-calling telemetry to HTTP render endpoints

[Upstream PR](https://github.com/vllm-project/vllm/pull/61683) · state: open · merged: False

## Original PR description



## Overview

Add tool-calling metrics to Chat Completions and Messages rendering, plus linked traces for the render server's render, tokenize/detokenize, and derender HTTP endpoints. Complements the HTTP tokenizer client in [llm-d-router#3374](https://github.com/llm-d/llm-d-router/pull/3374).

## Claims

- Count validated tool-field render attempts with `vllm:tool_call_render_requests_total`, labeled by served model, API surface, and rendered/error outcome.
- Honor the existing OTLP configuration and emit W3C-linked server spans for Chat Completions, Messages, Completions, and Responses render; tokenize/detokenize; and Chat/Completions derender (streaming and non-streaming). Spans for tool-bearing Chat Completions and Messages render requests carry sanitized presence, count, choice, API surface, and outcome attributes under `vllm.tool_calling.*`, aligned with the planned inference-tracing PR.
- Keep counting independent of tracing, without changing rendering or error handling. Exclude non-tool requests from tool counters and summary attributes.

## Validation

128 tests passed, including real CPU rendering and OTLP export. Coverage includes Chat Completions and Messages tool requests, tool-choice policies, success/error outcomes, disabled/unsampled tracing, and sensitive-value exclusion. Applicable pre-commit hooks passed. Additional coverage checks linked spans for tokenize/detokenize, Completions/Responses render, and streaming/non-streaming Chat/Completions derender.

Reproduce the test selection in an installed CPU environment:

```
VLLM_TARGET_DEVICE=cpu .venv/bin/python -m pytest \
  tests/entrypoints/scale_out/render/test_render.py \
  tests/entrypoints/scale_out/render/test_launch_render.py \
  tests/entrypoints/scale_out/render/test_render_tracing.py \
  --confcutdir=tests/entrypoints/scale_out/render -q
```

Local macOS validation used the renderer’s Python entry point instead of the unavailable vllm console command. Tests are covered by the existing Buildkite scale-out entrypoint suite.

## Details

Adapts the minimal tracing foundation from [#51747](https://github.com/vllm-project/vllm/pull/51747) with attribution preserved. Tool metrics apply to Chat Completions and Messages render requests; the other endpoints receive request spans without tool-specific attributes.

Unlike http_requests_total, the counter separates tool-field render attempts from non-tool requests independently of trace sampling. It cannot detect fields dropped or changed upstream.

Telemetry reads validated request objects without rereading bodies or exporting tool names, schemas, arguments, or exception text. Existing request/error logging is unchanged.

rendered means rendering succeeded – not per-field preservation or arbitrary-template equivalence. Controlled-template tests validate rendering intent. Pre-handler validation failures are not counted as render outcomes.
