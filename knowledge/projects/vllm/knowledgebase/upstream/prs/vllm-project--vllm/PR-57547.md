# [ROCm][Perf] Fuse all-reduce + RMSNorm with AITER FlyDSL INT4 QuickReduce

[Upstream PR](https://github.com/vllm-project/vllm/pull/57547) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`VLLM_ROCM_QUICK_REDUCE_QUANTIZATION=INT4` routes QuickReduce to the FlyDSL kernel. With `fuse_allreduce_rms` on, two things kept the prefill all-reduce from being fused with the add-RMSNorm:

1. `RocmAiterAllReduceFusionPass` gated on the 64 MiB custom-all-reduce pool, so at hidden 4096 in bf16 the fusion stopped at 8192 tokens and the default 16384-token chunk (128 MiB) was never matched.
2. Inside the pool, the all-reduce ran through FlyDSL and a separate add-RMSNorm followed.

AITER v0.1.27 adds the add-RMSNorm epilogue to the FlyDSL kernel (`QuickAllReduceInt4.allreduce_rmsnorm`). This PR (two commits) lifts the pass's ceiling to the QuickReduce workspace where that kernel can run, and routes the payload through it. HIP QuickReduce is discontinued, so its `qr_all_reduce_rmsnorm` route is removed. #61020 builds on this PR to also fuse the MXFP4 activation quant.

Not a duplicate: searched open PRs for "allreduce rmsnorm ceiling quickreduce", "FlyDSL QuickReduce RMSNorm" and "flydsl allreduce". #55347 changes `effective_max_size()` for `AITER_CUSTOM_AR_MAX_SIZE`; the two compose.

## Claims

- With INT4 QuickReduce on, `fuse_allreduce_rms` takes the fused FlyDSL kernel for every prefill all-reduce the pass covers, up to the QuickReduce workspace: the 128 MiB and 256 MiB chunks of `max-num-batched-tokens` 16384 and 32768 at hidden 4096. On main, chunks above 8192 tokens are not matched at all and the rest run FlyDSL all-reduce + a separate RMSNorm.
- `amd/Qwen3.5-397B-A17B-MoE-MXFP4`, TP2, MI355X: NIAH at 64k and 128k is 1.000 on both arms. Mean TTFT is lower with the PR in 12 of 13 rows (geomean -2.3% at `max-num-batched-tokens` 16384 and -1.2% at 32768), individual deltas are mostly within run-to-run spread, and output tok/s and TPOT do not move, as expected for a prefill change.

## Details

**Before.** `RocmAiterAllReduceFusionPass` gated on the custom-all-reduce IPC pool (`effective_max_size()`, 64 MiB), but the FlyDSL QuickReduce kernel stages through the QuickReduce workspace (2 GiB by default). At hidden 4096 in bf16 the pass stopped at 8192 tokens. Inside the pool, `_rocm_aiter_fused_allreduce_rmsnorm_impl` ran the FlyDSL all-reduce and then a separate add-RMSNorm.

**After.**

1. `AiterCustomAllreduce.fused_rms_max_size(hidden_dim, dtype, qr_comm)` returns `max(pool, qr_comm.qr_max_size)` where the FlyDSL kernel can run (`QuickAllReduce.supports_fused_rmsnorm`: INT4 FlyDSL up, bf16, a hidden size `QuickAllReduceInt4.supports_rmsnorm` accepts), and the pool otherwise. The vLLM and AITER communicators are sized from the same `VLLM_ROCM_QUICK_REDUCE_MAX_SIZE_BYTES_MB`.
2. The per-group-FP8-quant variants lower to custom-AR kernels with no QuickReduce path, so they move to their own `PatternMatcherPass`, applied only for compile ranges within the pool. `VllmConfig` already puts a compile-range boundary at the pool, so a range is either fully inside or fully above it. The quant matcher runs first, as before.
3. `_rocm_aiter_fused_allreduce_rmsnorm_impl` keeps decode sizes on the one-stage custom all-reduce. Otherwise it asks `QuickAllReduce`:
   - `should_fused_allreduce_rmsnorm(inp, residual, weight)` accepts the call when `all_reduce` would run the payload through FlyDSL (`uses_flydsl_int4`), the kernel supports the hidden size, and the residual and weight are bf16, contiguous and 16-byte aligned. It reads only tensor metadata, so it adds no host-device synchronization.
   - `fused_allreduce_rmsnorm(...)` runs the fused kernel and returns `(out, residual_out)`, with Gemma (`1 + weight`) norms supported.
4. A payload FlyDSL takes but the kernel declines keeps the unfused all-reduce + RMSNorm. The HIP `qr_all_reduce_rmsnorm` route and its communicator are removed. AITER's HIP fused kernel has codecs only for FP8, INT6 and INT4 (every other level, INT8 and INT3 included, falls to the FP codec in its default case), and INT4 now runs on FlyDSL. The route has also not run on main since AITER 0.1.19.post1: `qr_get_handle(ptr)` changed signature in ROCm/aiter#4421, the call raises, and the `except` swallows it, so the communicator never comes up. Removing it therefore changes no behaviour; the other codecs keep QuickReduce all-reduce + a separate RMSNorm.

**Shared code.** `VllmFusionPatternMatcherPass.register` gains an optional `pm_pass` argument; the default is the old behaviour. Nothing changes on CUDA. Net non-test change is +131 / -124 lines.

**Limitations**

- gfx950 and bf16 only; the kernel admits hidden sizes 2048, 4096, 8192 and 16384 (AITER main adds 6144 at world size 2 and 4). Other sizes, such as Qwen3.8-Flash-Next's 2560, keep the unfused path.
- QuickReduce levels other than INT4 have no fused RMSNorm route (the HIP one never ran on main and is removed).
- One model and TP2 end to end; the unit tests cover the dispatch and the gates.
- The unit tests run in the MI355 "Distributed Features" step; the end-to-end runs need the 397B checkpoint and 4 GPU pairs, so they ran outside CI.
