# [PCP][Spec Decode] Prefer sharded MTP with replicated draft fallback

[Upstream PR](https://github.com/vllm-project/vllm/pull/53427) · state: closed · merged: False

## Original PR description

## Summary

Extend the PCP speculative-decoding support already merged in [#56107](https://github.com/vllm-project/vllm/pull/56107) with backend-aware draft execution:

- Prefer the upstream PCP-sharded draft prefill for single-module MTP when the selected draft attention backend supports PCP.
- Fall back to a global replicated drafter when the selected backend does not support PCP, while keeping the target model PCP-sharded.
- Keep DSpark on its existing replicated path.

This allows PCP-capable and non-PCP-capable draft backends to coexist without disabling the upstream sharded implementation.

## Implementation

Draft mode is resolved before model construction from the effective draft attention backend, including `attention_backend` from the speculative config and `backend_per_kind` precedence:

- Automatic backend selection remains shard-first because the selector receives `use_pcp=True` and considers PCP-capable candidates.
- An explicitly selected backend with `supports_pcp() == false` builds the drafter with `prefill_context_parallel_size=1`.

The two runtime contracts remain separate:

| Draft mode | Hidden states | Prefill metadata | Input/capture buffers |
|---|---|---|---|
| PCP sharded | Rank-local target states | Reuse rank-local target metadata | PCP local buffers |
| Replicated fallback | PCP-restored global states | Rebuild from global positions, sequence lengths, and block tables | Drafter-owned global buffers |

For PIECEWISE graphs, replicated drafting captures with drafter-owned attention groups and buffers. Runtime graph-padding rows receive zero hidden states and the global `is_padding` mask.

Warmup follows the same selection: sharded MTP stays rank-local, while replicated drafters restore the global batch before `propose()`.

## Scope

- Single-module MTP uses capability-selected sharded or replicated draft prefill.
- DSpark remains replicated as implemented by #56107.
- PCP continues to support PIECEWISE CUDA graphs; full graph modes remain outside the current PCP contract.
- Existing PCP+DCP restrictions are unchanged.

AI assistance was used for implementation and validation. The human submitter reviewed the changes.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Refresh the draft max sequence length before metadata**

For the standard `AutoRegressiveSpeculator` MTP path, this helper builds metadata before `propose()` updates `draft_max_seq_len` from the current batch, so `_build_draft_attn_metadata()` uses the preceding batch's value. If the longest request accepts all K drafts plus its bonus token, the next batch's sequence upper bound grows by K+1 while the saved bound only included K lookahead tokens, making `max_seqlen_k` one token smaller than `seq_lens`; FlashAttention MLA may then reject the launch or process invalid draft attention. Compute the current bound before this call or pass it directly rather than relying on mutable state from the previous proposal.
