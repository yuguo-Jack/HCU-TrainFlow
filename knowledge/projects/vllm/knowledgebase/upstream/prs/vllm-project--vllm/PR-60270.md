# [Bugfix] Detect NVFP4 when a compressed-tensors format is a list

[Upstream PR](https://github.com/vllm-project/vllm/pull/60270) · state: open · merged: False

## Original PR description

## Purpose

Fixes #60260.

Mixed-scheme compressed-tensors checkpoints declare the top-level `format` as a list, e.g. `["nvfp4-pack-quantized", "float-quantized"]` (`nm-testing/TinyLlama-1.1B-Chat-v1.0-NVFP4-FP8-Dynamic`). `ModelConfig.is_nvfp4_quantized()` called `.lower()` on it, so building the config failed with `AttributeError: 'list' object has no attribute 'lower'`. That happens when `enable_act_fusion` computes the optimization-level defaults, before any weights load.

This PR moves the compressed-tensors check into `_compressed_tensors_has_nvfp4()`, next to the existing `_modelopt_mixed_has_nvfp4()` helper, and accepts either a string or a list. Single-string behaviour is unchanged.

## Not a duplicate

- No open PR references #60260.
- #55367 changes the same function to detect NVFP4 groups in `"mixed-precision"` checkpoints. It still calls `quant_config.get("format", "").lower()`, so it doesn't cover a list-typed `format`. The two changes are complementary; whichever lands second needs a small rebase.
