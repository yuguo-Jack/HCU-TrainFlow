## Original PR description

## Purpose

Move `diskcache` out of the default vLLM install path and into an explicit `outlines-cache` extra. This reduces default dependency/SBOM exposure to the public `diskcache` unsafe deserialization advisory while preserving the opt-in V1 outlines disk cache behavior.

This PR:
- removes `diskcache` from `requirements/common.txt`
- adds `vllm[outlines-cache]`
- keeps `diskcache` lazily imported only when `VLLM_V1_USE_OUTLINES_CACHE=1`
- raises an actionable error when the optional package is missing
- documents the outlines cache directory trust boundary

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

The `LRUCache` returned at the end of this function (line 209) does not implement the `.set()` method, which is required by the `outlines_core` backend. This will cause an `AttributeError` at runtime when the backend attempts to cache compiled FSMs. 

Note that the `FakeCache` in the new unit tests (`tests/v1/structured_output/test_outlines_cache.py`, line 84) explicitly implements this method, which confirms the requirement was recognized but missed in the actual implementation. You should use a wrapper or a subclass of `LRUCache` that provides a `set(key, value)` method (e.g., mapping it to `__setitem__`).

- gemini-code-assist[bot] · comment · 2026-04-29T04:14:19Z · [source](https://github.com/vllm-project/vllm/pull/41191#discussion_r3158537814)

File: `vllm/v1/structured_output/utils.py` · line 221

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The `get_outlines_cache` function currently creates a new cache instance (either `diskcache.Cache` or `LRUCache`) on every call. This defeats the purpose of the in-memory `LRUCache` and causes redundant expensive operations, such as disk cache initialization, metadata version checks, and log spamming. 

Since a global `CACHE` variable is already defined at line 41, this function should implement a singleton pattern to ensure the cache is initialized once and reused across calls.
