**Reference-only draft; please do not merge.** Expose `min_tokens` and `ignore_eos` on `/v1/messages` and forward them through the existing chat request conversion. This draft is shared at the request of the submitting user to illustrate a P/D integration fix, with validation still pending.

## Details

### Motivating flow

1. A proxy sends a non-streaming one-token prefill request with `min_tokens=1`, optionally `ignore_eos=true`, and KV transfer metadata.
2. The current Messages schema/conversion does not expose either sampling control, so they do not reach engine sampling.
3. A first-token EOS can cause a stopped completion. Connectors whose transfer handoff requires length-capped completion can then omit transfer metadata. This is connector-dependent and must be reproduced on the deployment in question.
4. This patch exposes the existing sampling controls. The proxy must still check returned transfer metadata and preserve the client's original stopping settings on the decode request.

The patch does not modify scheduler behavior, connector lifecycle, or proxy error handling. `ignore_eos` does not disable other stopping conditions.
