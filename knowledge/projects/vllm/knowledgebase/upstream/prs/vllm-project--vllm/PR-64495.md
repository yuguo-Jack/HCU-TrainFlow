# [Bugfix] Preserve multimodal processor-cache hits during request eviction

[Upstream PR](https://github.com/vllm-project/vllm/pull/64495) · state: closed · merged: True

## Original PR description

## Overview

Prevent `AssertionError: Expected a cached item` when a multimodal request exceeds the processor-only LRU capacity. Retain requested payload references before inserting misses, so an earlier insert cannot discard a later hit.

Related #26195. This differs from #34749, which converts cache assertions into request errors without preserving the evicted payload. No open PR implementing request-local processor-only retention was found.

## Claims

- Requests such as `[new C, cached A, cached B]` succeed with a cache that holds only two images.
- Retained tensors, prompt updates, image ordering and repeated-image placeholders match uncached processing exactly.
- Payload lookups use constant-time `LRUCache.peek()`, which leaves eviction order and hit statistics unchanged. No cache-wide dictionary or tensor copies are made.
- Metadata-only and shared-memory sender behavior and the LRU storage budget are preserved.

### Lookup performance

The previous accessor constructed `_MappingOrderCacheView`, whose `UserDict` constructor copied every cache entry for each requested item. The review refinement replaces this with a direct lookup in the LRU's backing dictionary.

Measured on macOS arm64, Python 3.12.11, cachetools 7.2.6. Times are medians of five samples; each sample performs 20 old lookups or 50,000 `peek` lookups. Temporary allocation is traced separately.

| Cache entries | Previous lookup | `peek` lookup | Previous temporary allocation | `peek` temporary allocation |
| --- | --- | --- | --- | --- |
| 1,000 | 49.50 µs | 0.039 µs | 39,152 B | 0 B |
| 10,000 | 532.36 µs | 0.037 µs | 311,536 B | 0 B |
| 100,000 | 6,354.41 µs | 0.039 µs | 5,767,408 B | 0 B |

This is a lookup microbenchmark, not an end-to-end throughput or capacity measurement.

```sh
import importlib.util
import statistics
import timeit

spec = importlib.util.spec_from_file_location("cache", "vllm/utils/cache.py")
module = importlib.util.module_from_spec(spec)
spec.loader.exec_module(module)
for count in (1_000, 10_000, 100_000):
    cache = module.LRUCache(count)
    for index in range(count):
        cache.put(str(index), index)
    key = str(count // 2)
    for name, lookup, number in (
        ("previous", lambda: cache.cache.get(key), 20),
        ("peek", lambda: cache.peek(key), 50_000),
    ):
        samples = timeit.repeat(lookup, number=number, repeat=5)
        print(count, name, statistics.median(samples) / number * 1e6, "us")
PY
```

## Details

Touching all requested hashes cannot protect every hit when a request's working set exceeds the cache budget. Inserting C can evict A even though A was classified as cached before processing; the merge then supplies `None` for A and asserts.

Snapshot requested local payload references before inserts, using `LRUCache.peek()` without changing eviction order or statistics. If a hit is subsequently evicted, supply the retained tensor/update tuple through the existing insertion path. Sender caches inherit a local lookup returning `None` and keep their existing behavior.

The request-local dictionary and references last through the merge. The LRU remains bounded, but tensors needed by an in-flight request can outlive their cache entries; the optimization guide documents this transient memory. No tensors are copied, and there are no model-runner, scheduler, GPU encoder-cache or speculative-decoding changes.

Earlier Kimi validation used the pinned v0.30.0 image, TP8/DCP8/PP2, DSpark K=3 and eight API servers. CPU offload used 128 GiB/rank and 12,000 eager blocks, with actual PP0/PP1 pools of 69.21/103.82 GiB per rank. Offload behavior is unchanged.
