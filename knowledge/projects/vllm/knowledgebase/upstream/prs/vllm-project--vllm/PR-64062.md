# [Bugfix][Core] Align streamed token ids with stop-buffered text

[Upstream PR](https://github.com/vllm-project/vllm/pull/64062) · state: open · merged: False

## Original PR description



## Overview

Streamed outputs of requests with stop strings send token ids that are ahead of their text: the detokenizer holds back the last `max(len(stop)) - 1` chars, but not the tokens they decode from. Parsers that match markers by token id then misparse reasoning and tool calls. This PR holds back text at token boundaries, and sends each output's `token_ids`, `logprobs` and `sampling_mask` for exactly the tokens its text covers.

Fixes #51641

## Claims

- In streaming, every output's `token_ids` decode to its `text`, also when stop strings hold text back. `logprobs` and `sampling_mask` stay aligned with `token_ids`. Holds for `DELTA` and `CUMULATIVE` outputs, and for multi-token steps (i.e. speculative decoding).
- This fixes, for streaming requests with `stop` and `include_stop_str_in_output=False`:
  - Tool call arguments corrupted by engine-based parser that matches markers by token id. With Qwen3 + `hermes`, `{"cmd": "echo hi"}` streams as `{"cmd": "echo hi"}}`. With GLM-4.7, the arguments are lost.
  - Reasoning split at the wrong place by legacy parsers (#51641). With `deepseek_r1`, reasoning is cut at `…saf` and content starts with `/think>`.
- No parser changes, so every parser gets aligned input. Requests without stop strings, or with `include_stop_str_in_output=True`, hold nothing back and are unchanged.
- Text is still held back as before: no part of a stop string is streamed before it is matched. Concatenated streamed text and tokens equal the non-streamed result.

```python
import gc
import itertools
import json
import random
import statistics
import sys
import time
from pathlib import Path

import numpy as np

TOKENIZER = "Qwen/Qwen3-0.6B"
NUM_REQUESTS = 256
OUTPUT_LEN = 512
KINDS = ["DELTA", "CUMULATIVE"]
# (name, stop, include_stop_str_in_output)
STOPS = [("none", None, False), ("stop", ["</block>"], False),
         ("stop+incl", ["</block>"], True)]
TOKENS_PER_STEP = [1, 4]
NUM_LOGPROBS = [0, 5]
WARMUP = 1
REPEAT = 5

TEXT = (
    "The quick brown fox jumps over the lazy dog. In a distributed serving "
    "system, the frontend process receives sampled token ids from the engine "
    "core, detokenizes them incrementally, checks stop strings, and streams "
    "the resulting text back to clients. 다국어 텍스트도 포함합니다: 안녕하세요, "
    "こんにちは, 你好. <tool_call>{\"name\": \"bash\", \"arguments\": "
    "{\"cmd\": \"echo hi\"}}</tool_call> Numbers like 3.14159 and 2,718 "
    "appear, as do emojis 🚀🔥 and code: `for i in range(10): print(i)`.\n"
)


def make_token_streams(tokenizer) -> list[list[int]]:
    base = tokenizer.encode(TEXT, add_special_tokens=False)
    corpus = base * (OUTPUT_LEN // len(base) + 2)
    rng = random.Random(0)
    return [
        corpus[(o := rng.randrange(len(base))) : o + OUTPUT_LEN]
        for _ in range(NUM_REQUESTS)
    ]


def build_steps(streams, tokens_per_step: int, num_logprobs: int):
    from vllm.v1.engine import EngineCoreOutput, FinishReason
    from vllm.v1.outputs import LogprobsLists

    rng = np.random.default_rng(0)
    vocab = max(max(s) for s in streams) + 1
    steps = []
    for start in range(0, OUTPUT_LEN, tokens_per_step):
        step = []
        for i, stream in enumerate(streams):
            new_ids = stream[start : start + tokens_per_step]
            logprobs = None
            if num_logprobs:
                n = len(new_ids)
                topk = rng.integers(0, vocab, size=(n, num_logprobs))
                logprobs = LogprobsLists(
                    np.concatenate([np.array(new_ids)[:, None], topk], axis=1),
                    -rng.random((n, num_logprobs + 1), dtype=np.float32),
                    np.ones(n, dtype=np.int64),
                )
            out = EngineCoreOutput(
                request_id=f"req-{i}", new_token_ids=new_ids, new_logprobs=logprobs
            )
            if start + tokens_per_step >= OUTPUT_LEN:
                out.finish_reason = FinishReason.LENGTH
            step.append(out)
        steps.append(step)
    return steps


def run_once(tokenizer, streams, kind, stop, include_stop, tps, num_logprobs):
    from vllm.sampling_params import RequestOutputKind, SamplingParams
    from vllm.v1.engine import EngineCoreRequest
    from vllm.v1.engine.output_processor import OutputProcessor

    processor = OutputProcessor(tokenizer, log_stats=False)
    for i in range(NUM_REQUESTS):
        params = SamplingParams(
            max_tokens=OUTPUT_LEN,
            output_kind=RequestOutputKind[kind],
            stop=stop,
            include_stop_str_in_output=include_stop,
            logprobs=num_logprobs or None,
        )
        request = EngineCoreRequest(
            request_id=f"req-{i}",
            external_req_id=f"req-{i}",
            prompt_token_ids=[1, 2, 3],
            mm_features=None,
            sampling_params=params,
            pooling_params=None,
            arrival_time=0,
            lora_request=None,
            cache_salt=None,
            data_parallel_rank=None,
        )
        processor.add_request(request, prompt=None)
    steps = build_steps(streams, tps, num_logprobs)

    gc.collect()
    gc.disable()
    try:
        t0 = time.perf_counter()
        for step in steps:
            processor.process_outputs(step)
        elapsed = time.perf_counter() - t0
    finally:
        gc.enable()
    assert not processor.request_states, "requests finished early (stop matched?)"
    return elapsed


def run(out_path: str) -> None:
    from vllm.tokenizers import get_tokenizer

    tokenizer = get_tokenizer(TOKENIZER)
    streams = make_token_streams(tokenizer)
    results = {}
    for kind, (stop_name, stop, incl), tps, num_lp in itertools.product(
        KINDS, STOPS, TOKENS_PER_STEP, NUM_LOGPROBS
    ):
        args = (tokenizer, streams, kind, stop, incl, tps, num_lp)
        for _ in range(WARMUP):
            run_once(*args)
        med = statistics.median(run_once(*args) for _ in range(REPEAT))
        key = f"{kind.lower()}/{stop_name}/tps={tps}/lp={num_lp}"
        results[key] = med
        print(f"{key:<36} {med * 1e3:9.2f} ms", flush=True)
    Path(out_path).write_text(json.dumps(results, indent=2))


def compare(base_path: str, new_path: str) -> None:
    base = json.loads(Path(base_path).read_text())
    new = json.loads(Path(new_path).read_text())
    us_per_token = 1e6 / (NUM_REQUESTS * OUTPUT_LEN)
    print("| config | main (ms) | PR (ms) | main us/tok | PR us/tok | change |")
    print("|---|---:|---:|---:|---:|---:|")
    for key, t in new.items():
        b = base[key]
        print(
            f"| `{key}` | {b * 1e3:.1f} | {t * 1e3:.1f} | "
            f"{b * us_per_token:.3f} | {t * us_per_token:.3f} | "
            f"{(t / b - 1) * 100:+.1f}% |"
        )


if __name__ == "__main__":
    if sys.argv[1] == "--compare":
        compare(*sys.argv[2:4])
    else:
        run(sys.argv[1])
```

## Details

**Root cause.** `BaseIncrementalDetokenizer.get_next_output_text` held back `stop_buffer_length` characters, but `RequestState._new_completion_output` sent the step's new token ids regardless. Parsers that act on token ids, such as the `ParserEngine` token-id terminals and `BaseThinkingReasoningParser`'s end-token check, then see a marker's token before its text.

For example, a `ParserEngine` sees the `<tool_call>` token while `delta_text` ends in `<too`. It splices the terminal into the middle of the text (`<too<tool_call>l_call>{…`), and `hermes` no longer finds complete JSON.

**Change.**
- **`detokenizer.py`:** when stop strings hold text back, the detokenizer records where each output token's text ends. `get_next_output` (renamed from `get_next_output_text`) releases text only up to the last token boundary that a stop string can no longer claim. It returns the number of tokens still held back.
- **`output_processor.py`:** `RequestState` holds back the same number of trailing tokens and sends them, with their logprobs and sampling-mask positions, together with their text later.

**Behavior change.** For streaming requests with stop strings, a token id is now streamed with its text instead of up to a few tokens earlier. An output can therefore carry no tokens, which outputs without new tokens already could. On upstream main, these requests already stream text that lags behind tokens.

**Cost.** One int per output token, kept only for requests that hold text back, plus a bisect per output.

**Why not in the parsers.**
- #38864 (Qwen3), #39044 (base thinking parser and others) and #51669, #51671 (base thinking parser) make individual reasoning parsers prefer visible text over token ids.
- They don't cover `ParserEngine` token-id terminals or tool parsers, which is where the tool call corruption above comes from. They would also need the same care in every current and future parser.
- Aligning the detokenizer output fixes the input that all of them receive. Those parser changes stay valid, but are no longer needed for this case.
