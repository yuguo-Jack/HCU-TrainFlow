## Purpose

Fix the Mori build in the ROCm Docker image (Dockerfile.rocm_base) and update the installation documentation to reflect Mori's new build system.

- billishyahao · comment · 2026-06-08T11:01:52Z · [source](https://github.com/vllm-project/vllm/pull/44374#issuecomment-4648211540)

Hi @tjtanaa @AndreasKaratzas I made some investigation from my side. And the key takeaway is that we need to preserve current build process for mori 

### Environment
  - Base image: `rocm/dev-ubuntu-22.04:7.2.3-complete` → **Ubuntu 22.04, glibc 2.35**
  - `PYTHON_VERSION=3.12`

  ### 1. PyPI `amd-mori` cp312 wheel can't be installed on the base
  PyPI files for `amd-mori 1.1.1`:
  - `amd_mori-1.1.1-cp310-cp310-manylinux_2_35_x86_64.whl`
  - `amd_mori-1.1.1-cp312-cp312-`**`manylinux_2_39`**`_x86_64.whl`

  The cp312 wheel requires **glibc ≥ 2.39** (Ubuntu 24.04+), and there is no sdist. Resolving against a glibc-2.35 target fails:

  ```console
  $ pip download --only-binary=:all: --python-version 3.12 --abi cp312 \
        --platform manylinux_2_35_x86_64 "amd-mori>=1.1.0"
  ERROR: No matching distribution found for amd-mori>=1.1.0   # (exit 1)
  ```

  ### 2. The github-release wheel is able to be installed, but won't load at runtime
  The GitHub `…-cp312-cp312-linux_x86_64.whl` uses the generic `linux_x86_64` tag, so pip/uv install it without a glibc check. However, its shared objects require **GLIBC_2.38**, which does not exist in glibc 2.35:

  | `.so` | max GLIBC required |
  |---|---|
  | `libmori_io.so` | **2.38** |
  | `libmori_shmem.so` | **2.38** |
  | `libmori_application.so` | **2.38** |
  | `libmori_ops.so` | 2.34 |
  | `libmori_pybinds.so` | 2.32 |

  So `import mori` would fail at runtime on Ubuntu 22.04 with a `version 'GLIBC_2.38' not found` error. (It's the same binary PyPI tags as `manylinux_2_39`.) This wheel also **does not bundle its dependencies** — loading it first fails on a missing `libibverbs.so.1`.

  ### 3. Only the cp310 wheel is actually compatible with Ubuntu 22.04
  The cp310 `manylinux_2_35` wheel is properly auditwheel-repaired: it **bundles all dependencies** (libibverbs, libamdhip64, librocm_smi64, libnuma, libmpi, libhsa-runtime64, …) and its max requirement is **GLIBC_2.34 ≤ 2.35** → it would run on Ubuntu 22.04. But our image is py3.12, not py3.10.

  ### Conclusion
  There is **no upstream cp312 MoRI build compatible with glibc 2.35**. Neither PyPI nor the GitHub `linux_x86_64` wheel works at runtime on the current Ubuntu 22.04 + py3.12 base.
