# [Bugfix] Keep attention impl state in the runtime pool under sleep mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/62634) · state: open · merged: False

## Original PR description

## Purpose

Part of #59055 (sleep-mode memory). Same pattern as #62358 (LoRA).

Attention backend impls derive device tensors from their inputs/weights, e.g. ALiBi slopes (built in `__init__`) and the FlashInfer/B12x fp32 sinks copy (built in `process_weights_after_loading`). With `enable_sleep_mode`, model construction runs inside the `weights` cuMem pool, so these tensors land there too. Level-2 sleep discards that pool, and they are not parameters or buffers, so nothing restores them: after wake-up the model generates garbage even though the weights are correct.

This PR builds the impl, and runs the impl's `process_weights_after_loading`, inside the `runtime` pool when sleep mode is on. Sleep offloads and restores the `runtime` pool at every level, so the impl state survives. No backend changes; nothing changes without sleep mode or on non-CUDA-alike platforms.

Split out of #60009.

## Test Plan

`sleep_ab.py`: greedy baseline, then 3 x (sleep(level=2) -> wake -> regenerate, compare tokens), GSM8K before/after. `inplace` = `sleep_preserve_parameter_names=["*"]`; `reload` = wake weights, `reload_weights()`, wake KV cache. GB200.
