# [Perf][Tool Parser] Avoid O(N^2) partial JSON re-parsing on open string arguments

[Upstream PR](https://github.com/vllm-project/vllm/pull/62448) · state: open · merged: False

## Original PR description

## Purpose

When streaming tool calls with large string arguments (e.g. code blocks, file diffs, SQL queries, or Markdown documents), `Granite20bFCToolParser` and `Internlm2ToolParser` currently re-parse the entire accumulated JSON buffer from byte 0 via `partial_json_parser.loads()` + `json.dumps()` on every generated token, causing $O(N^2)$ CPU overhead in the streaming loop.

Cross-pollinating the incremental open-string streaming fast path from [`sgl-project/sglang#45113`](https://github.com/sgl-project/sglang/pull/45113) (and extending the incremental JSON streaming approach from [`vllm#19425`](https://github.com/vllm-project/vllm/pull/19425) / [`vllm#44596`](https://github.com/vllm-project/vllm/pull/44596) for `MistralToolParser` / `MistralParser`), this PR introduces shared helpers in `vllm/tool_parsers/utils.py` (`_check_open_top_level_arg_string`, `_decode_simple_json_str_delta`, `_try_arm_open_arg_string_fast_path`, and `_step_open_arg_string_fast_path`) and wires them into `Granite20bFCToolParser` and `Internlm2ToolParser` *(note: `Llama3JsonToolParser` was migrated to `ParserEngine` with `stream_arg_deltas=False` in #63569, so its `llama_tool_parser.py` hunk was dropped after #63569 landed)*:

1. Once `partial_json_parser` has emitted the opening prefix of a top-level string argument (`{"key": "...`), the parser records the raw character cursor in the current tool call's JSON slice.
2. On subsequent tokens while that string remains open, only the newly appended slice `[raw_cursor:]` is scanned in $O(|\text{delta}|)$ time.
3. Trailing incomplete escape sequences (`\`, `\u`, `\u1`, `\u12`, `\u123`) are held back until the remaining characters arrive in a later chunk, preventing premature emission of literal backslashes (`\\`) that `partial_json_parser` would otherwise synthesize on split escapes.
4. When the string closes (`"`) or contains surrogate-pair escapes (`\uD800`..`\uDFFF`), the parser transparently falls back to the existing `partial_json_parser` path.

### Benchmark (400 streamed chunks, ~8 KB string argument)

| Tool Parser | Before (`partial_json_parser` per token) | After ($O(|\text{delta}|)$ open-string fast path) | Speedup |
| --- | ---: | ---: | ---: |
| `Granite20bFCToolParser` | 150.32 ms | 3.24 ms | **46.4x** |
| `Internlm2ToolParser` | 124.26 ms | 2.71 ms | **45.9x** |
