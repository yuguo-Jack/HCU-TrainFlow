# [MM][CG] Support ViT full CUDA graph for BLIP-2

[Upstream PR](https://github.com/vllm-project/vllm/pull/59193) · state: open · merged: False

## Original PR description

## Purpose

Part of #38175. Adds ViT full CUDA graph support for BLIP-2.

BLIP-2 resizes every image to a fixed size and the Q-Former always outputs 32 tokens per image, so the only thing that changes between batches is the number of images. The graph is captured per token budget and covers the vision tower, the Q-Former and the language projection; replay slices `pixel_values` along dim 0. I moved the pixel path out of `_process_image_input` into `_process_image_pixels`, which the regular path, the graph path and the eager fallback now all use.

One thing to note: the model runners currently hand requests with precomputed `image_embeds` to the graph manager as well, which fails with `KeyError: 'pixel_values'` and takes the engine down. #58122 already adds a check in both runners to skip those, so I didn't duplicate it here, and all the tests below were run with those two lines applied. Would you prefer to wait for #58122 to land first, or should I include that line in this PR too?

## Test Plan

On RTX 4090 (1 and 2 GPUs), A100-40GB and RTX 5090, with blip2-opt-2.7b and 6.7b:

- the new `blip2` case in `test_vit_cudagraph.py`
- encoder timing and a bitwise comparison against eager, plus TTFT with `vllm bench serve`
- greedy output comparison and the first 500 VQAv2 validation questions, also covering vision-tower LoRA, 6.7B, TP=2, and `image_embeds` mixed with raw images in the same batch

## Test Result

The new case passes on all three GPUs. When the batch matches a graph size, encoder outputs are bitwise identical to eager. With one image per call the encoder is 3.1x faster on the 4090, 2.8x on the A100 and 1.4x on the 5090, and roughly even at 8 images. On the 4090, mean TTFT goes from 71.8 ms to 33.5 ms at concurrency 1 and from 97.8 ms to 65.8 ms at concurrency 4.

VQAv2: 41.60 eager vs 42.20 with the graph. The few mismatches in the output comparison come from padding: when the number of images doesn't match a graph size, the batch is padded, and the different batch shape changes bf16 rounding. The graph output is bitwise identical to eager on the same padded batch, and eager alone shows a similar number of mismatches when only the batch composition changes. Mixing `image_embeds` with raw images doesn't crash and gives the same outputs.

ruff passes and mypy reports no new errors. For the docs table, Blackwell was tested on an RTX 5090 (sm120), not on B200.
