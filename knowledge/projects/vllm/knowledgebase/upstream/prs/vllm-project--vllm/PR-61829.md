# [CI/Build] Build DeepEP for SM103 (B300/GB300) in the Docker image

[Upstream PR](https://github.com/vllm-project/vllm/pull/61829) · state: closed · merged: True

## Original PR description



## Overview

The Docker image builds DeepEP for `9.0a 10.0a` only, so DeepEP cannot run on SM103 (B300/GB300). This adds `10.3a` to DeepEP's arch list when building with CUDA >= 12.9.

## Claims

- `--all2all-backend deepep_high_throughput` (and the other DeepEP backends) work on SM103 GPUs with the image's DeepEP.
- No change for CUDA < 12.9 builds (12.8 has no SM103 target) or for other GPUs: `9.0a` and `10.0a` cubins are unchanged.

## Validation

On 8x B300 (SM103, driver 595.91.07, CUDA 13.0, torch 2.13.0+cu130, NVSHMEM 3.4.5), DeepEP at the image's commit (`d4f41e4e`) built with `TORCH_CUDA_ARCH_LIST='10.0a 10.3a'`, replacing the DeepEP wheel in `vllm/vllm-openai` v0.31.0:

| Check | Stock image DeepEP (`9.0a 10.0a`) | With `10.3a` |
|---|---|---|
| `cuobjdump --list-elf deep_ep/_C*.so` | `sm_90a`, `sm_100a` | `sm_100a`, `sm_103a` |
| `tests/legacy/test_intranode.py --num-processes 8 --num-tokens 4096 --hidden 6144 --num-topk 8 --num-experts 256` | n/a (kernels cannot launch) | 24/24 dispatch/combine checks pass (BF16/FP8, sync/async); best dispatch FP8 0.41 ms, combine 0.67 ms |
| `vllm serve` GLM-5.3 FP8, prefill context parallel 8 + EP 8, `--all2all-backend deepep_high_throughput` | startup fails: `CUDA runtime exception (DeepEP/csrc/kernels/legacy/intranode.cu:21): 999 (cudaErrorUnknown)` | starts with `DeepEPHTAll2AllManager`; greedy answers match the default all2all backend on a fixed prompt set |

Version gating of the shell snippet (`CUDA_VERSION` from the stage):

```
CUDA 12.8.1 -> 9.0a 10.0a
CUDA 12.9.1 -> 9.0a 10.0a 10.3a
CUDA 13.0.3 -> 9.0a 10.0a 10.3a
```

Not done: a full rebuild of this Dockerfile (the change only alters the DeepEP arch list passed to `install_python_libraries.sh`). CI has no SM103 runners, so this path is not exercised in CI. `pre-commit run --files docker/Dockerfile` passes (with `update-dockerfile-graph` skipped locally: the stage graph is unchanged).

## Details

- Root cause: arch-specific (`a`) cubins only run on their exact compute capability, and DeepEP's build embeds no PTX, so `sm_100a` code does not load on SM103 (10.3). The failure surfaces as `cudaErrorUnknown` (999) from DeepEP's legacy intranode/layout kernels at the first dispatch.
- `10.3a` requires CUDA 12.9+, hence the gate on `CUDA_VERSION`; the default image is CUDA 13.0.
- Build time grows by one more arch for DeepEP only (its wheel is built in parallel with the csrc build).
- Performance is not a claim of this PR. On the configuration above, a closed-loop real-prompt prefill load (12 and 24 requests in flight, unique prompt prefixes, `cached_tokens` = 0) measured, in prompt tokens/s: `allgather_reducescatter` with FlashInfer TRT-LLM MoE 60.4k / 60.7k, `deepep_high_throughput` (which selects DeepGEMM MoE) 56.5k / 56.9k, `deepep_v2` with FlashInfer TRT-LLM MoE 54.0k / 62.2k (the first run includes DeepEP v2 JIT warm-up). Single runs on one node. An earlier version of this description cited a DeepEP gain; that comparison was inflated by prefix-cache hits from repeated prompts and is withdrawn.
