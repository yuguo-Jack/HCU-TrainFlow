# [Bugfix][ROCm][Kimi-K3] Stage fused KDA decode weights after loading

[Upstream PR](https://github.com/vllm-project/vllm/pull/61207) · state: closed · merged: True

## Original PR description

## Overview

The ROCm Kimi-K3 fused KDA decode read uninitialized memory as its conv1d and gated-norm weights whenever weight loaders were skipped, as with `--load-format dummy`. This intermittently produced NaN logprobs. Those copies are now built from the final parameters after loading.

## Claims

- `process_weights_after_loading` stages `decode_conv1d_weight` and `decode_norm_weight` from `conv1d.weight` and `o_norm.weight`, and the two side-effect weight loaders are removed.
- This fixes the intermittent HTTP 400 (`Out of range float values are not JSON compliant: nan`) in `test_prefix_cache.py` on MI355.

## Validation

MI355 (gfx950), `VLLM_ROCM_USE_AITER=1`. In `test_prefix_cache.py[offload-partial]`, NaN runs went from 5 of 21 to 0 of 20. The new `test_decode_weights_staged_after_loading` fails before (18432/18432 elements are NaN) and passes after. `models/kimi_k3` passes: 311 passed.

The perf runs used `riverclouds/Kimi-K3-8L-dummy` at TP1, 5 interleaved runs per column, each with a fresh server. Values are mean ± sd.

| `vllm bench serve` (4096 in / 256 out, conc 16) | Before | After |
|---|---|---|
| Request throughput (req/s) | 7.687 ± 0.025 | 7.672 ± 0.009 |
| Mean TTFT (ms) | 634.4 ± 6.5 | 633.5 ± 2.5 |
| Mean TPOT (ms) | 5.434 ± 0.004 | 5.454 ± 0.017 |

No real-weight Kimi-K3 checkpoint was available for an accuracy run. With real weights, the buffers receive the same values the loaders wrote before.

## Details

The fp32 copies from #50654 are non-persistent `torch.empty` buffers that were written only inside the conv1d and o_norm weight loaders. `DummyModelLoader` skips both, so the fused decode used whatever the allocator returned: usually zeros, sometimes NaN. That poisoned the recurrent state from the first decode step. The post-load hook runs for every loader, including layerwise reload (the buffer storage is reused, so CUDA graphs stay valid). It skips weights that arrive already processed. The NVIDIA `KimiK3DeltaAttention` has the same latent issue and is left for a follow-up. #59245 reads these buffers and will need a rebase.
