# [Bugfix][Rust Frontend] Fix cancellation during request submission

[Upstream PR](https://github.com/vllm-project/vllm/pull/64742) · state: open · merged: False

## Original PR description



## Overview

Fix a race in the Rust frontend where cancelling a request during submission can send `Abort` before `Add`, allowing the engine to process a request that the caller has already cancelled.

## Claims

- Keep the output stream alive in the spawned Add send task until the send completes, preventing cancellation from enqueueing Abort before Add.
- Add a deterministic regression test that cancels the caller after the send task is spawned but before it runs.

The regression test is covered by the existing Rust Frontend Cargo CPU CI job.

## Details

Add is sent by a spawned task that continues running when its caller is cancelled. Previously, cancellation dropped the output stream in the caller and triggered auto-abort while Add could still be pending. The scheduler ignores aborts for unknown request IDs, so an Abort received before Add does not prevent the subsequent Add from starting generation.

Move the output stream into the existing send task and return it after the send completes. If the caller has already been cancelled, the returned stream is dropped when the send task completes, triggering auto-abort. The existing send-error registration rollback remains in place.
