# [Bugfix][Benchmark] Preserve synthetic datasets in throughput validation

[Upstream PR](https://github.com/vllm-project/vllm/pull/59881) · state: open · merged: False

## Original PR description



## Overview

Preserve `random-mm` and `random-rerank` in `vllm bench throughput` when no dataset path is supplied. Previously, argument validation replaced either selection with `random`, so the documented multimodal command sampled text-only requests.

## Claims

- Keep the requested synthetic dataset through validation; retain the existing default random-text fallback and `prefix_repetition` behavior.
- Verify that throughput's parser, validation, and shared sampler produce image-bearing chat requests without `--dataset-path`, while retaining the existing `mm-processor` regression coverage.

## Validation

Run from the checkout with a uv-managed Python 3.12 environment. Local validation used WSL and an existing CPU installation, with this checkout first on `PYTHONPATH`.

```bash
PYTHONPATH=. .venv/bin/python -m pytest tests/benchmarks/test_throughput_cli.py -q -k without_dataset_path
```

Before the production fix: **2 failed, 3 passed**. The failures were `random-rerank` being renamed and throughput's `random-mm` producing text-only prompts.

```bash
PYTHONPATH=. .venv/bin/python -m pytest tests/benchmarks/test_throughput_cli.py --deselect tests/benchmarks/test_throughput_cli.py::test_bench_throughput -q --disable-warnings
```

After the fix: **13 passed, 2 deselected**; all applicable pre-commit hooks, Python 3.12 mypy, and whitespace checks passed. Pytest's deselection prefix excludes the model-running `test_bench_throughput` and `test_bench_throughput_accepts_custom_audio_args`. No GPU benchmark or model accuracy evaluation was run; this change is limited to benchmark workload selection. Existing Benchmarks CLI CI runs the entire `tests/benchmarks/` directory on NVIDIA and AMD.

## Details

The no-path fallback exempted only `prefix_repetition`. Add the other two pathless synthetic datasets to that exemption, leaving the existing `random` validation path intact. Clarify the documented `random-mm` invocation.

Duplicate-work checks found no open PR for this fix. Searches covered `"random-mm" "throughput.py"`, `"throughput" "dataset" in:title`, `"random-rerank"`, and related validation/fallback terms. File: `vllm/benchmarks/throughput.py` · line 646

🔴 Running `vllm bench throughput --dataset-name random-rerank --no-reranker` without --dataset-path (and without an explicit --random-batch-size) now reaches RandomDatasetForReranking.sample instead of being silently rewritten to the random dataset, and crashes with a raw, unhandled AssertionError (pre-existing bug) because --random-batch-size defaults to 1 while `assert num_requests > 1 and batchsize > 1` at vllm/benchmarks/datasets/datasets.py:814 requires batchsize > 1 whenever --no-reranker is set. Fix: validate_args should raise a clear ValueError when --no-reranker is combined with --random-batch-size <= 1, covering both the with- and without---dataset-path cases, instead of letting the assert fire deep inside the sampler.

<details>
<summary>Why this was flagged</summary>

Trigger: `vllm bench throughput --dataset-name random-rerank --no-reranker` with no --dataset-path and no --random-batch-size, entering validate_args (vllm/benchmarks/throughput.py:642-646, now exempting random-rerank) then get_requests -> get_samples -> RandomDatasetForReranking.sample. --random-batch-size defaults to 1 (datasets.py:1922) and is_reranker=not args.no_reranker is False, so `assert num_requests > 1 and batchsize > 1` at datasets.py:813-814 fails. Before this diff, this combination was silently rewritten to dataset_name='random', never reaching that code; now it crashes with an unhandled AssertionError and no actionable message. The assert is already reachable with --dataset-path set, so it is pre-existing, but no validate_args check guards the --no-reranker/--random-batch-size interaction for either case.

**Verification:** pre-existing. The scenario is reachable: throughput.py:642-646 exempts random-rerank from the no-path rewrite, so running without --dataset-path or --random-batch-size flows into RandomDatasetForReranking.sample with batchsize=1. At datasets.py:813-814, `assert num_requests > 1 and batchsize > 1` fails, raising a raw AssertionError. validate_args has no guard requiring batchsize>1 for --no-reranker; throughput.py:681-698 only emits "ignored" warnings.

</details>
