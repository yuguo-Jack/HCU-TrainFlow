# [MoE] Support REAP-pruned and MoNE checkpoints with non-uniform per-layer expert counts

[Upstream PR](https://github.com/vllm-project/vllm/pull/61460) · state: open · merged: False

## Original PR description

## Overview

Serves MoE checkpoints pruned to a **non-uniform number of experts per layer**, in two parts:

1. **MoNE** (builds on the landed expert-substitution support): a layer's novice constants may be stored as a single packed `values` tensor of shape `[num_substituted, hidden_size]`, alongside the existing per-expert `approx_value` and explicitly-named `value` formats.
2. **REAP** (new): checkpoints whose `quantization_config.moe_sparsity_config` records a per-layer retained expert count (`method: "prune"`) now serve end to end, including alongside compressed-tensors NVFP4 quantization. The pruner (llm-compressor `ExpertPruner`) compacts both the router gate and the expert weights to the per-layer count while the model config keeps the maximum, so vLLM must consume the per-layer counts to size and route every layer.

Checkpoint format reference: `nm-testing/Qwen3.6-35B-A3B-NVFP4-REAP10-nonuniform` (10% of experts pruned globally, non-uniform: 9216/10240 retained, per-layer counts from 8 to 256).

> Note: this PR was rebased onto the current main, which already contains the full MoNE expert-substitution implementation. The earlier, separate REAP/MoNe implementation on this branch was dropped in favor of the landed design; this PR adds the REAP "prune" format that the landed design does not cover.

## Claims

- A MoNE checkpoint may provide `<experts prefix>.values` — one `[num_substituted, hidden_size]` tensor per substituted layer — loaded 1:1 into the substitution module's `values` parameter (rows in ascending substituted-expert-ID order). Existing load paths (`approx_value`, explicitly-named `value`, `approximate_experts`) are unchanged, and non-local layers pass packed `values` through.
- A REAP-pruned checkpoint (`moe_sparsity_config.method == "prune"`) is parsed into per-layer expert counts:
  - `QuantizationConfig.get_num_experts_for_layer(layer_idx)` base hook returns `None` by default.
  - `CompressedTensorsConfig` implements it from `moe_sparsity_config.num_experts`; `method` values other than `"prune"` (e.g. MoNE `"novice"`) and malformed counts are rejected with a clear error. Layers outside the recorded list (e.g. MTP drafts) fall back to the model config's count.
  - `determine_expert_counts` applies the per-layer count, so the router's top-k range, the expert map, and the expert weight allocation are all consistent; EPLB redundant experts are rejected.
  - `Qwen3NextSparseMoeBlock` (Qwen3-Next / Qwen3.5 / Qwen3.6 family) sizes its router gate, `n_routed_experts`, and TP check from the same hook, so gate, router, and experts share the per-layer count.
- Qwen3.5-family REAP checkpoints serve end to end with NVFP4 (W4A4) expert quantization on Blackwell.

## Details

- **Root cause (REAP):** nothing in vLLM read `quantization_config.moe_sparsity_config`, so models were built with the model config's maximum expert count and loading died on the compacted gate. The landed MoNE substitution path covers constant-substitution checkpoints (`approximate_experts` / `transform_config.expert_substitution`) and rejects quantized experts, so it cannot serve the prune format either.
- **Design:** a `get_num_experts_for_layer(layer_idx)` hook on `QuantizationConfig` (default `None`) keeps the mechanism quant-config-owned, mirroring how the checkpoint records the counts. `determine_expert_counts` resolves the layer index from the MoE prefix via the existing `decoder_layer_index` helper and overrides `num_experts`, which flows to the router, `ExpertMapManager`, and `RoutedExperts` unchanged. The model-side gate resize is required because the pruner also compacts the router weight; since the gate produces exactly the retained experts' logits, top-k over the compacted gate is REAP inference semantics (routing and renormalization are unchanged).
- **Tradeoffs / limitations:**
  - Only Qwen3Next-family MoE blocks resize their gate; other architectures given a REAP checkpoint fail loudly at weight load (gate shape mismatch) rather than silently mis-routing.
  - EPLB redundant experts are rejected with the per-layer counts (uniform physical expert placement does not apply).
  - Startup runs MoE autotuning per distinct expert-count shape; with many distinct counts this adds a few minutes on 4×B200 (observed with the 40-count checkpoint).
  - `docs/design/expert_substitution.md` covers the MoNE substitution format; a short section for the prune format is a natural follow-up.

Duplicate-work check: `gh pr list --search "moe_sparsity_config in:body"`, `"REAP in:body"`, and `"expert pruning in:body"` over open PRs in vllm-project/vllm return no overlapping work (hits are runtime/dynamic expert pruning — XShare, RIY — or unrelated process-reaping fixes).
