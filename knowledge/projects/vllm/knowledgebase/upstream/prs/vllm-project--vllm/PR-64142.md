# [ROCm][Perf] Re-land the AITER preshuffled FP8 block-scale GEMM, plain GEMM first

[Upstream PR](https://github.com/vllm-project/vllm/pull/64142) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Re-lands the AITER preshuffled FP8 block-scale GEMM (#51692 by @simondanielsson, #56433 by @mawong-amd), which #57132 reverted after DeepSeek-V4-Pro GSM8K fell to 0.0008. This version finds and fixes that cause, folds in @bichowdh's #56234 (tuned-shape gate), and makes the plain blockscale GEMM the first choice: the preshuffled GEMM only takes shapes whose plain AITER table is less tuned than its own.

Draft. Still to run on this head: DeepSeek-V4-Pro GSM8K and a GLM-5.3 sweep with the new priority rule.

## Claims

- **DeepSeek-V4 accuracy cause, fixed.** `DeepseekV4MoE` builds `shared_experts` before the fused MoE. Their FP8 linears were shuffled in their own post-load step, and then `prepare_heterogeneous_shared_expert` / mega MoE copied the shuffled bytes as if they were the checkpoint layout. The shared experts are now marked `skip_weight_relayout` when a fused MoE copies them. DeepSeek-V4-Pro TP8 GSM8K: 0.0008 before the fix, 0.957 after (main: 0.954).
- **The plain GEMM comes first.** `AiterPreshuffledFp8BlockScaledMMKernel.can_implement` refuses when AITER's plain `a8w8_blockscale` table has at least as many tuned batch sizes for (N, K) as the `a8w8_blockscale_bpreshuffle` table, so selection falls through to `AiterFp8BlockScaledMMKernel`. With both tuned they perform the same (table below), and the plain GEMM needs no weight relayout. The preshuffled GEMM still serves shapes only its table covers, e.g. Qwen3.8-27B on gfx950 (0 plain rows, 160 preshuffled).
- **N guard is `N % 16`** instead of `N % 128`, so shapes like DeepSeek-R1's `fused_qkv_a_proj` (N = 2112) qualify.

## Validation

**GLM-5.3 TP4, MI355X, one node** (`amd/GLM-5.3-Quark-MXFP4-AttnFP8`, vLLM nightly `5d35ce39`). Four arms, total throughput vs the kernel-off arm, 11 points (8k/1k at concurrency 4-256, 60k/600 at 4-32). "Tuned plain GEMM" adds 88 gfx950 rows to AITER's plain table (ROCm/aiter#7381) through `AITER_CONFIG_GEMM_A8W8_BLOCKSCALE`.

| Arm | Geomean | 8k c4 | 8k c64 | 8k c256 | 60k c32 | GSM8K (200) |
|---|---|---|---|---|---|---|
| Off (plain GEMM, AITER's current rows) | baseline | | | | | 0.99 |
| Preshuffled GEMM (previous head) | +6.8% | +0.6% | +7.1% | +12.2% | +12.4% | 0.99 |
| Plain GEMM, tuned rows | +7.1% | +1.5% | +6.4% | +11.8% | +12.2% | 0.995 |
| Both | +6.8% | +0.6% | +7.2% | +12.1% | +12.4% | 0.99 |

The two GEMMs tie once both are tuned, and they do not stack. That is why the plain GEMM now has priority.

**DeepSeek-V4-Pro-0813 TP8 GSM8K** (5-shot, 1319 questions, the #57132 setup, `VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1`):

| Build | strict-match |
|---|---|
| Nightly, kernel off | 0.9538 |
| Previous head (re-land without the fix) | 0.0008 |
| Previous head, fused shared experts off | 0.9530 |

The final head keeps the transposed-scale quant (`group_fp8_quant(transpose_scale=True)`) rather than #56234's transpose copy: on GLM-5.3 TP4 it was about 2% faster, with the GPU halves swapped between two pairs. The scale layout is covered by `test_rocm_fused_qkv_quant_matches_preshuffled_gemm_scale_layout`.

## Details

**Changes against the reverted code.**

- `vllm/_aiter_ops.py`: `blockscale_tuned_m_count(n, k, preshuffled)` counts the sampled batch sizes (M = 1 to 32768) with a tuned row, through AITER's own `get_CKGEMM_config` lookup. `is_blockscale_bpreshuffle_tuned` (the #56234 gate) and `prefers_plain_blockscale` build on it.
- `scaled_mm/aiter.py`: the plain-first check in `can_implement`; the `N % 16` guard; layers marked `is_bmm` or `skip_weight_relayout` keep the plain layout and run the plain GEMM; the e8m0 scale upcast now runs before that early return; shuffled linears are tagged `aiter_bpreshuffled`.
- `deepseek_v4/amd/model.py`: `skip_weight_relayout` on the shared experts when a fused MoE copies them.
- `deepseek_v4/amd/rocm.py`: `weight_already_preshuffled()` reads the `aiter_bpreshuffled` tag.
- Tests: `tests/kernels/quantization/test_aiter_preshuffled_blockscale_selection.py` (priority rule), and in `tests/models/test_deepseek_v4_vl_rocm.py` a test that fused shared experts keep the checkpoint layout, plus the earlier `wo_a`, `gate_up_proj` and scale-layout tests.

**Trade-off.** The tuned-shape check probes 15 batch sizes per (N, K) once at startup (cached). A shape whose plain rows cover fewer batch sizes than its preshuffled rows still picks the preshuffled GEMM, even if the plain rows would be as fast at the sizes that matter.

**Related PRs.**

- ROCm/aiter#7381 adds the GLM-5.3 plain-table rows used above.
- #56502 by @eky-amd (fusion patterns for the transposed-scale quant) applies on top of this.
- #63217 adds the gfx1250 preshuffled path. #63604 adds a DeepSeek-V4 bpreshuffle switch and touches the same shuffle code.
