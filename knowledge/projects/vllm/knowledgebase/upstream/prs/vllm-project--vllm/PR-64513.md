# [Rust Frontend] Report the generate response envelope like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/64513) · state: closed · merged: True

## Original PR description

## Overview

Report the `/inference/v1/generate` response envelope like the Python frontend: `model`, `created`, `usage` and `output_mode` on non-streaming responses, and `output_mode` on every streamed chunk. The Rust frontend omitted all four, so a client reading `usage` from a non-streaming generate response, which vllm-project/vllm#42748 added for disaggregated serving, got nothing.

## Claims

- Non-streaming responses carry `model` (the LoRA adapter name when the request resolved to one, otherwise the first served model name, as on chat and completions), `created`, `usage` (prompt, completion and total tokens, plus `prompt_tokens_details` under `--enable-prompt-tokens-details`) and `output_mode: "tokens"`. As in Python, `usage` does not depend on `stream_options`.
- Every streamed chunk, including the usage-only chunk, carries `output_mode: "tokens"`. Chunks still carry no `model` or `created`, as in Python.
- `output_mode` is always `tokens`: `text` and `derender` still return 400 on the Rust frontend.

## Details

Python builds the non-streaming response with `model_dump()` (`scale_out/token_in_token_out/serving.py` `_build_response_fields`, `protocol.py` `GenerateResponseBase`), so every field is present. `usage` was added on purpose in vllm-project/vllm#42748, and `output_mode` has been the response discriminator since vllm-project/vllm#58588 (`test_generate_stream.py` pins `"tokens"`). The old Rust comment "non-streaming raw generate responses do not include usage" mirrored Python from before #42748.

- Commit 1 moves the response-model rule, duplicated in the chat and completions `convert.rs`, into `LoraModelResolution::response_model()` without changing behavior, so generate reuses it instead of adding a third copy.
- Commit 2 adds the fields to the generate response DTOs (`routes/inference/generate/types.rs`) and fills them in `collect_generate` and the chunk stream; `usage` reuses `Usage::from_token_usage`, which the streaming path already uses. Nothing below the server crate changes.

**Differences from Python kept.** `usage.completion_tokens_details` is serialized as on the other routes today (`{"reasoning_tokens": 0}`) where Python sends `null`; vllm-project/vllm#64219 changes that on every route. Python's token chunks serialize `"usage": null` and choice-level `null`s; Rust omits them, as before.
