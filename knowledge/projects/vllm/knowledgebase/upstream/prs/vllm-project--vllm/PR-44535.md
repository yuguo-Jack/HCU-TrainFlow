# [Profiler] Support multiple profiling windows

[Upstream PR](https://github.com/vllm-project/vllm/pull/44535) · state: open · merged: False

## Original PR description

## Purpose
Currently only a single profiling window is supported, this PR extends `delay_iterations` and `max_iterations` to accept multiple disjoint profiling windows.

Example command:
```
nsys profile --trace-fork-before-exec=true --cuda-graph-trace=node --capture-range=cudaProfilerApi --capture-range-end=[:2] vllm serve $MODEL --profiler-config.profiler=cuda --profiler-config.delay_iterations=2000,3000 --profiler-config.max_iterations=100,100
```

## Test Plan
Added some unit tests to cover new feature.

- tomeras91 · comment · 2026-06-23T09:15:35Z · [source](https://github.com/vllm-project/vllm/pull/44535#discussion_r3458477410)

File: `vllm/config/profiler.py` · line 88

This is still accepting a str of comma-separated ints. It's just a redundant complication.
`delay_iterations` can be just a list of ints:
```python
delay_iterations: list[int] = Field(default_factory=lambda: [0])
```

With that, you don't need all the logic in `_parse_iteration_values` - passing multiple values in the CLI will automatically parse into a list of ints (uses `nargs="+"` in the arg parser - see `collection_to_kwargs` in `arg_utils.py`). So, the CLI line:
```bash
--profiler-config.delay_iterations 10 100
```
or, equivalently
```bash
    --profiler-config '{"profiler":"cuda",
                        "delay_iterations":[10,100],
                        "max_iterations":[20,100]}'
```
Will just be parsed to `delay_iterations=[10,100]` in this class. 

Furthermore, you can even use:
```python
delay_iterations: list[Annotated[int, Field(ge=0)]] = Field(default_factory=lambda: [0])
```
And then you gat the `>=0` validation natively from pydantic (and you can delete that logic from `_validate_profiler_config`.

To handle the single window case (and auto-parse to a single-element list), you can add a "before" field validator:
```python
@field_validator("delay_iterations", mode="before")
@classmethod
def _wrap_scalar(cls, v):
    return [v] if isinstance(v, int) else v

@field_validator("max_iterations", mode="before")
@classmethod
def _validate_max_iterations(cls, v):
    v = [v] if isinstance(v, int) else v
    # here you can also add the "max_iterations can be 0 only for the final window logic". It belongs here and not in `_validate_multi_window_config` which should just check things that are a property of the window and not the delay/max values themselves.
    return v
```
