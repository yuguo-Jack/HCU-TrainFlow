# [Fast Start] Support online FP8 and CUTLASS NVFP4 weight-cache restarts

[Upstream PR](https://github.com/vllm-project/vllm/pull/63672) · state: closed · merged: True

## Original PR description

## Overview

Allow the weight-cache daemon to reuse online FP8/MXFP8 linear weights and ModelOpt NVFP4 CUTLASS MoE weights across engine restarts. Related to #56049; this covers a subset of its quantization roadmap.

## Claims

- Restore online quantization runtime state without quantizing or transforming shared weights again. FP8 is limited to CUTLASS; MXFP8 requires the selected kernel's pre-processed-weight capability. Requantization from serialized checkpoints and online MoE remain excluded.
- Preserve the unpadded CUTLASS FP8 output width when IPC loading skips weight post-processing.
- Restore ModelOpt NVFP4 CUTLASS MoE kernels without multiplying activation scales into shared weight scales a second time.

## Details

Online methods previously rejected daemon caching despite successful ordinary loading. The restore paths opt in only when their kernel state can be reconstructed. NVFP4 CUTLASS otherwise performs an in-place scale fusion during kernel initialization, which must not run again on shared daemon tensors.

Adds focused loading regressions, extends the existing padding test to construct a real kernel, adds L4/B200 Buildkite selection, and documents supported paths in the preload guide. No model-runner/scheduler changes or new steady-state host synchronization.

Duplicate checks on October 26 examined issue #56049 and its comments and searched open PRs for the issue, preload quantization, and weight-cache FP8. #62734 covers daemon-loss detection and #63506 covers kernel cache keys; neither adds these restore paths. #60015 concerns compressed-tensors scale registration and is outside this change. No duplicate implementing this scope was found in those searches.
