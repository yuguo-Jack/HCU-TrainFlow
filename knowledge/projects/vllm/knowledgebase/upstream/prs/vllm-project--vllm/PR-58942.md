# [Bugfix] Terminate streaming sessions on ABORT/ERROR and prevent zombie sessions

[Upstream PR](https://github.com/vllm-project/vllm/pull/58942) · state: closed · merged: True

## Original PR description

## Purpose

Split out from #53861 (bugs 2 and 3 of the 4 streaming-input session lifecycle fixes there), with the original author included as co-author — this is a carve-out for independent review/merge, not duplicate work. Bugs 1 (collector merging across chunk boundaries) and 4 (zero-chunk streams / DP sticky routing) are being split separately.

**Bug 2 — engine-side ABORT/ERROR treated as a normal chunk boundary.** `OutputProcessor.process_outputs` treated any `finish_reason` on a streaming-input request as "chunk done, wait for next chunk". ABORT and ERROR end the whole session, so treating them as a chunk boundary left `generate()` waiting forever and desynced the frontend/scheduler chunk queues. Fix: only non-terminal finish reasons are chunk boundaries (`streaming_chunk_boundary`); ABORT/ERROR finish the request state and also send an abort back to the engine (see below).

**Bug 3 — a chunk sent after the session finished resurrects it as a zombie.** If a chunk ADD reaches the engine after the session was aborted/finished, the scheduler sees an unknown resumable id and admits it as a new session. That session then sits in `WAITING_FOR_STREAMING_REQ` forever, holding KV blocks, with no frontend state left to abort it. Fix (reworked per review, no new request fields):
- `handle_inputs` checks `output_processor.has_request()` before each non-first chunk and before the final empty request, and stops if the session is gone. There is no `await` between this check and the ADD send, and `AsyncLLM.abort()` removes frontend state before sending ABORT on the same socket, so any chunk that passes the check is ordered before the abort. This holds for every abort path, including direct `abort()` calls (e.g. realtime `cleanup()`).
- For the engine-finished race (engine finishes the session with ABORT/ERROR while a chunk sent before the frontend saw that finish is in flight), the output processor always re-sends an abort for a terminally-finished streaming session. That abort is ordered after any such chunk, so a re-created session is cleaned up.
- `DPLBAsyncMPClient.abort_requests_async` broadcasts aborts for ids with no routing entry to all engines, since the routing entry is dropped when the engine reports the request finished.
