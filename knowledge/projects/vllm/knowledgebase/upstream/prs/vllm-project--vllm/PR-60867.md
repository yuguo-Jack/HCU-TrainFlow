# [KV Connector][ROCm] MoRIIO: hybrid READ for several attention groups and shared-group speculative methods

[Upstream PR](https://github.com/vllm-project/vllm/pull/60867) · state: open · merged: False

## Original PR description

## Purpose

GLM-5.3-Flash (`Glm5NextForConditionalGeneration`) cannot run MoRIIO hybrid READ P/D on `main`. It has two transferable attention groups (MLA + indexer, and the kpool tail ring, a `CircularBufferSpec`), KDA groups, and MTP. `main` allows one attention group and DSpark only. With the packed `UniformTypeKVCacheSpecs` layout, `main` also classifies KDA groups as attention and silently skips recurrent-state transfer.

Changes (connector-only: `moriio_connector.py`, tests, one docs line):

- Hybrid READ payload is `[*attn_groups, *mamba_groups]`, byte-identical to `main` with one attention group.
- `_align_read_blocks` runs per attention group. Non-prefix-cacheable groups are read even on a full local hit.
- Each hybrid layer is routed to its own payload group. READ destinations of all attention groups are excluded from KV zeroing.
- A group is Mamba when every layer spec it covers is a `MambaSpec`.
- READ: the DSpark-only check is replaced by "the drafter shares the target's attention groups" (MTP, DSpark). Hybrid WRITE (#60544) is unchanged, including its DSpark check.
- `CircularBufferSpec` is accepted only for hybrid READ. Non-hybrid and hybrid WRITE still fail closed (`NotImplementedError` at init).
- Usage guide: drop the single-attention-group requirement.

Scope:

- Non-hybrid models do not reach the changed code (all scheduler changes are under `_has_mamba`).
- Single-attention-group hybrid READ is covered by byte-identity unit tests only.
- Drafters with a separate attention group are out of scope.

Requires #58585 (per-layer `block_len`), merged. The branch includes `main` with #60544 (hybrid WRITE).
