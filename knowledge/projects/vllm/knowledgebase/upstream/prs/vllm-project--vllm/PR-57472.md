# [Bugfix][Offload] Respect --cpu-offload-gb budget for UVA parameters

[Upstream PR](https://github.com/vllm-project/vllm/pull/57472) · state: open · merged: False

## Original PR description

## Summary

- Check each parameter size before copying it to CPU in `UVAOffloader`.
- Stop before a parameter would push the cumulative logical payload beyond
  `--cpu-offload-gb`.
- Count the precomputed parameter payload size after a successful offload.

This enforces the configured logical CPU offload budget at parameter admission
time. It does not claim that RSS or allocator-backed host memory is an exact
match for the configured value.

## Why this is not duplicate work

The open [#56413](https://github.com/vllm-project/vllm/pull/56413) avoids
duplicate host allocation in the UVA path and retains pinning for the non-UVA
fallback. It addresses physical host allocation behavior, but does not prevent
a whole parameter from pushing the cumulative logical payload past the
configured budget.

The open [#54610](https://github.com/vllm-project/vllm/pull/54610) prioritizes
sparse MoE parameters and preserves lazy layer construction. Its offload loop
still checks only whether the current total has reached the limit before
offloading the next whole parameter. Its discussion reports 47.69 GB of
tracked offload with `--cpu-offload-gb 47`, which is the over-admission guarded
by this PR.

The merged [#57834](https://github.com/vllm-project/vllm/pull/57834) releases
the process-global offloader during shutdown and does not overlap with this
budget check.
