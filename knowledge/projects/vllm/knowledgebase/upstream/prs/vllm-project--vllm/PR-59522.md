# [Feature][KV Connector] Add selective Mooncake recurrent checkpoint leases

[Upstream PR](https://github.com/vllm-project/vllm/pull/59522) · state: closed · merged: False

## Original PR description

## Purpose

Mooncake recurrent lookup currently queries and leases every candidate state, including states beyond the KV-supported resume point. Add the default-off `mooncake_kda_last_hit_only` option for FullAttention + align-mode Mamba caches, using the selected-only `LastHitOnly` contract proposed in [Mooncake RFC #4255](https://github.com/kvcache-ai/Mooncake/issues/4255).

One existing coordinator pass bounds legal checkpoints from KV evidence, including Eagle and final-token recomputation. The connector sends recurrent keys in checkpoint-major order across the actual group/rank namespaces and returns the exact selected checkpoint for subsequent loading. Partial-hash KV tails retain their existing physical-key handling. Invalid responses and probe failures return a cache miss without a lease-renewing recurrent existence fallback. Shared group leases and unsupported cache types are rejected on opt-in; the default path and lookup wire format remain unchanged.

This draft depends on matching client/Master implementations from [Mooncake PR #4314](https://github.com/kvcache-ai/Mooncake/pull/4314), tested at `7943c052be6aab81c71b60fea9483952dec21141`. The selected-only response interface is still under review. No overlapping open vLLM PR was found for `4255 in:body` or `mooncake LastHitOnly` on 2026-10-01. The change is based on vLLM `2e52a558f04307b3f6f842e937e35aac079121c1` and contains 889 changed lines across code, tests, documentation and the benchmark.

## Test Plan

Run the six Mooncake Store suites in the existing Thor Python 3.12 / PyTorch 2.13.0+cu130 runtime, with the separately built CPU/TCP Mooncake binding exposed through `PYTHONPATH` and `LD_LIBRARY_PATH`:

```bash
MOONCAKE_LAST_HIT_MASTER=127.0.0.1:23351 "$PYTHON" -m pytest -q \
  tests/v1/kv_connector/unit/test_mooncake_store_{worker,coordinator,connector,layout,scheduler,hma_e2e}.py

for divisor in 1 8; do
  "$PYTHON" benchmarks/benchmark_mooncake_last_hit_only.py \
    --checkpoints 128 --iterations 1000 --kv-divisor "$divisor"
  "$PYTHON" benchmarks/benchmark_mooncake_last_hit_only.py \
    --checkpoints 128 --iterations 1000 --kv-divisor "$divisor" --master 127.0.0.1:23351
done
```

Run each benchmark scenario in three fresh processes, using `--selective-first` in the second. Also run the dependency's `test_batch_probe_policy.py` against the same Master and `master_service_probe_policy_test --gtest_filter='BatchProbePolicyTest.*'` to verify lease deadlines, soft pinning and eviction behavior directly.
