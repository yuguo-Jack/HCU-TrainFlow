## Problem

Under KV pressure, resumable streaming-input sessions that are paused (`WAITING_FOR_STREAMING_REQ`) or resumed-but-unscheduled retain their KV blocks indefinitely. This causes a scheduler deadlock:

1. Sessions park holding KV blocks
2. When they resume with continuations, no blocks fit
3. Preemption only scans `self.running` — which is empty because every session is between chunks
4. Every `schedule()` breaks out of the waiting loop with `scheduled=[]`
5. Engine freezes until external intervention

Related: Issue #60137.

## Solution

Add `_try_reclaim_streaming_kv()` to `Scheduler`, called at the waiting loop's allocation-failure point. The helper:

1. **Picks victims by preference**: paused sessions first (`WAITING_FOR_STREAMING_REQ`, completely idle), then resumed-but-unscheduled sessions (`WAITING`)
2. **Picks the newest / lowest-priority victim** — mirrors running-loop preemption semantics
3. **Frees blocks identical to preemption**: blocks, encoder cache, inflight-prefill tracking, `num_computed_tokens = 0`, PREEMPTED event, `reset_preempted_req_ids`
4. **Preserves accounting**: victim keeps its resumable status and `num_waiting_for_streaming_input` counter
5. **Moves victim out of kv-holding queues** into `waiting` for clean recompute on next resume
6. **Termination guarantee**: each reclaim strictly shrinks the candidate set; deferred-freedom cases are skipped since they can't help this step's allocation

Also adds a filter in the skipped-request re-queue path to avoid re-inserting a reclaimed request into `kv_holding_waiting`.
