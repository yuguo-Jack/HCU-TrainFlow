# fix: remove misleading `--quantization gptq` hint from Marlin shape errors

[Upstream PR](https://github.com/vllm-project/vllm/pull/62597) · state: open · merged: False

## Original PR description

## Summary
`verify_marlin_supports_shape()` in `vllm/model_executor/layers/quantization/utils/marlin_utils.py` hardcodes the hint *"Consider reducing tensor_parallel_size or running with --quantization gptq."* for both the `min_thread_n` and `min_thread_k` divisibility checks.

For an already-AWQ (or other Marlin-backed) model this suggestion is wrong/redundant — the model is already quantized, so switching `--quantization` does not apply. This has confused multiple users (see linked issue, e.g. Qwen2.5-VL-72B-Instruct-AWQ discussions/#2 and Reddit r/LocalLLaMA).

This PR replaces the hint with an accurate, quantization-agnostic message that points to the real constraint (per-partition weight dimension must be a multiple of the Marlin thread-tile size under the selected TP) and the actual remediation (reduce `tensor_parallel_size`).

## Test plan
- Added `tests/quantization/test_marlin_utils.py` asserting the new error messages no longer mention `--quantization gptq` and still mention `tensor_parallel_size`.
