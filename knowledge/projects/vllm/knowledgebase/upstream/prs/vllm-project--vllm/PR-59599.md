# [KV Offload] Publish block extra keys in self-describing offload events

[Upstream PR](https://github.com/vllm-project/vllm/pull/59599) · state: open · merged: False

## Original PR description

## Purpose

With `self_describing_kv_events`, offload `BlockStored` events carry each block's parent, tokens and LoRA, but `extra_keys` is always `None` (`_OffloadEventMetadata` marked it deferred). The GPU block pool publishes each block's LoRA, multimodal, cache-salt and prompt-embeds keys. A consumer that keys blocks by tokens and extra keys therefore gives an offloaded LoRA, multimodal or salted block a different key from its GPU copy, so prefix-cache routing misses the CPU copy.

This builds each block's extra keys with `generate_block_hash_extra_keys` while the request is available. It seeks the first multimodal input overlapping the chunk with `get_mm_features_in_window`, as `request_block_hasher` does, and carries the index across the chunk's blocks as the block pool does. Full chunks use the group's block size and partial recurrent tails the hash block size, matching the `block_size` each event already reports. Events for blocks without extra keys now publish `[None]` per block, as GPU events do.

Raised in review of #57789 (KV event snapshots), where a snapshot recorder has to reconcile GPU and offload stores of the same hash. #43468 introduced self-describing offload events and deferred extra keys; #52068 and #57453 keep that metadata alive until removal. #52103 (draft) rewrites the tracker to build stored payloads from the request carried by each store event and to emit key-only removals, and since its Oct 13 revision also generates per-block extra keys with the same helper. This PR is the standalone fix against the current tracker and leaves removal events unchanged.

AI assistance (Claude Code) was used for implementation and tests.
