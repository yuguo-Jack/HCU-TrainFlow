# [Rust Frontend] Stream kv_transfer_params on the final chunk like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/63772) · state: closed · merged: True

## Original PR description

## Overview

Python's streaming chat and completions return the request's `kv_transfer_params` on the chunk that carries `finish_reason` (vllm-project/vllm#40186), as the non-streaming responses already did, so a P/D proxy can stream and still get the transfer handle. The Rust stream response types had no such field, so streaming dropped it. This PR adds it.

## Claims

- Rust streaming chat and completions put `kv_transfer_params` on the finish chunk, taken from the terminal event. The usage chunk and every other chunk leave it unset, as in Python.
- Non-streaming responses are unchanged.

## Validation

```
cargo nextest run --manifest-path rust/Cargo.toml --workspace --all-features --locked --no-fail-fast

```

- `chunk_stream_puts_kv_transfer_params_on_finish_chunk_only` (chat) and `completion_stream_puts_kv_transfer_params_on_finish_chunk_only` (completions) drive the real chunk streams with a terminal event carrying params, then check the serialized JSON: only the finish chunk has the key. Both fail with the assignment removed.
- `completion_chunk_stream_hides_internal_prompt_only_token` (`echo` with `max_tokens=0`) now also asserts the params on its finish chunk, covering the prompt-only terminal branch; it fails with forwarding removed in that branch only.

## Details

Rust already carries the value to both stream handlers (`ChatEvent::Done.kv_transfer_params`, `Finished.kv_transfer_params`). This PR adds `kv_transfer_params: Option<Value>` to `ChatCompletionStreamResponse` and `CompletionStreamResponse`, and each stream's `final_chunk` sets it. The value is per-protocol response serialization, so the change stays in `vllm-server`'s stream types and terminal-chunk builders; nothing below the server changes.

Known difference: Python constructs every content chunk with `kv_transfer_params=None` set explicitly, so under `exclude_unset` the non-final chunks carry `"kv_transfer_params": null`. Rust stream chunks skip `None` fields (as they already do for `finish_reason`), so the key is absent there. This PR does not change the stream types' null-key policy.

No Python test pins the streaming field (vllm-project/vllm#40186 added none). The multiturn disaggregation proxy example reads it from streamed JSON.

Not a duplicate: no open PR adds `kv_transfer_params` to the Rust stream responses.
