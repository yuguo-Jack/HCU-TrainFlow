# [Profiler] Record the first N profiled iterations with stacks and shapes

[Upstream PR](https://github.com/vllm-project/vllm/pull/63213) · state: open · merged: False

## Original PR description

## Purpose

Adds `profiler_config.torch_profiler_detailed_iterations`. The first N profiled iterations are recorded with stacks and input shapes into a separate trace (worker name ending in `_detailed`). The profiler then restarts with the configured settings for the rest of the session.

Why: stacks and shapes are what tie a kernel to the code that launched it, but they slow each rank by a different amount, so with them on for the whole session every collective looks slower than it is (all-reduce waits for the slowest rank; we see 2-4x on TP8). Recording them for a few iterations gives the call structure of a step, while the remaining iterations keep production timing. One profiling run then serves both purposes, instead of a separate eager run for structure and a production run for time.

If saving the detailed trace fails (for example a full disk), the error is logged with the rank and directory and profiling continues, instead of stopping the worker.

```bash
vllm serve <model> --profiler-config '{"profiler": "torch", "torch_profiler_dir": "/tmp/traces", "torch_profiler_detailed_iterations": 16}'
```

Defaults to 0, which keeps today's single session. Cannot be combined with `warmup_iterations` or `wait_iterations` (validated).

## Before / after

One prefill step of GLM-5.3-Flash on B200 (TP8, rank 0), opened in Perfetto, the same `aten::mm` selected in each.

**Before:** a normal profiled step. The op has no Python stack above it and no input shapes, so nothing says which layer launched it.

![before](https://raw.githubusercontent.com/amd-sriram/vllm/59fc23655c34b382a784f65c0af00d2d0765439c/pr1_before_timing_step.png)

**After:** one of the first N steps with `torch_profiler_detailed_iterations`. The same op now sits under the Python and `nn.Module` stack (`Glm5NextMergedColumnParallelLinear_0` in `Glm5NextLinearAttention_0`) and carries its input types, strides and shapes. The step after these keeps the normal settings.

![after](https://raw.githubusercontent.com/amd-sriram/vllm/59fc23655c34b382a784f65c0af00d2d0765439c/pr1_after_detailed_step.png)

## Test Plan

```bash
pytest tests/v1/worker/test_gpu_profiler.py
```

New tests: the detailed session runs for N iterations and then switches to the configured settings, it writes the `_detailed` trace, the config validation, and a failed detailed save that logs and keeps profiling.

## Test Result

The new tests pass. The same change, carried in our serving images, has produced the detailed and timing traces for GLM-5.3-Flash TP8 profiling runs on MI355X and B200.
