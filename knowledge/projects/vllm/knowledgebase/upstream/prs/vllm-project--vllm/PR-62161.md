# [ROCm][CI] Give the MoE parallel-launch watchdog room for AITER JIT builds

[Upstream PR](https://github.com/vllm-project/vllm/pull/62161) · state: closed · merged: True

## Original PR description

Raises the parallel-launch watchdog added in #61695 from 900 s to 1800 s on ROCm only, so `MoE Kernels Shard 1` on AMD CI stops timing out while AITER JIT-compiles its CK MoE modules. Related: ROCm/aiter#5766.

- Fixes `test_modular_kernel_combinations_singlegpu[...AiterFp8TensorExperts-1]` on MI300, which can never finish within 900 s.
- No change on CUDA or other platforms (still 900 s, which is what #61695 needs for the B200 NVSHMEM hang).

AITER JIT build times for the stage modules this case needs, from the logs above (MI300, gfx942):

| Module | main #14821 | #14868 |
|---|---|---|
| `module_moe_ck2stages_f8_f8_preshuffle_off_b16_silu_per_tensor_mulWeightStage1` | 595 s | — (killed) |
| `module_moe_ck2stages_f8_f8_preshuffle_off_b16_silu_per_tensor_mulWeightStage2` | 609 s | 558 s |

- Checked that `LAUNCH_TIMEOUT_S` is 1800 on a ROCm GPU and 900 without one; pre-commit passes.
- **Not yet validated on hardware:** the case needs gfx942/gfx950 and I only have MI250 locally. This PR stays a draft until AMD CI's `MoE Kernels Shard 1` passes on it.

## Details

Root cause: the AITER wheel built in `docker/Dockerfile.rocm_base` (`PREBUILD_KERNELS=1`) ships only the `preshuffle_on` fp8 `moe_ck2stages` modules. `AiterFp8TensorExperts` uses the `preshuffle_off` ones, so the first launch compiles two modules (~10 min each) inside the watched region. The real fix is on the AITER side (prebuild these modules, see ROCm/aiter#5766); then this bump can be reverted.
