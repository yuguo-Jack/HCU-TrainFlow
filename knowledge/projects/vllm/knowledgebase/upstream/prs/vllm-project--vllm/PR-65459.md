# [Bugfix][Frontend] Support min_tokens in the Anthropic Messages API

[Upstream PR](https://github.com/vllm-project/vllm/pull/65459) · state: closed · merged: True

## Original PR description



## Overview

The Anthropic Messages API (`/v1/messages`) silently ignores `min_tokens`, while Chat Completions supports it. This adds `min_tokens` as a vLLM extra parameter on `AnthropicMessagesRequest` and forwards it to the engine.

Fixes #65095. The Responses API counterpart is #64009 / #64015; this PR does not touch that path.

## Claims

- `/v1/messages` accepts `min_tokens` (default `0`), and it now reaches `SamplingParams`, so EOS and stop sequences cannot end the response before that many tokens.
- Out-of-range values are rejected by the existing `SamplingParams` checks (`0 <= min_tokens <= max_tokens`), the same as for Chat Completions.
- Documented under "Anthropic APIs" in the online serving docs.

## Validation

New regression test `test_min_tokens_delays_stop_sequence` in `tests/entrypoints/anthropic/test_messages.py` (`RemoteOpenAIServer`, `Qwen/Qwen3-0.6B`, greedy). It first checks that a `"\n"` stop sequence ends the response early without `min_tokens`, then sends `min_tokens=16`.

Without the fix (`vllm/entrypoints/anthropic/` from `origin/main`, new test kept):

```
$ pytest tests/entrypoints/anthropic/test_messages.py -k min_tokens
E       AssertionError: assert 2 >= 16
E        +  where 2 = Usage(... input_tokens=15, output_tokens=2, ...).output_tokens
1 failed, 8 deselected
```

With the fix:

```
$ pytest tests/entrypoints/anthropic/test_messages.py -k min_tokens
1 passed, 8 deselected

$ pytest tests/entrypoints/anthropic
163 passed
```

Run on CPU (macOS arm64). `pre-commit` passes on the changed files. The `entrypoints/anthropic` Buildkite step already runs the whole directory, so the new test runs in CI.

## Details

- Root cause: `AnthropicMessagesRequest` had no `min_tokens` field, and `AnthropicServingMessages._build_base_request` did not set it on the `ChatCompletionRequest` it builds, so `to_sampling_params` always used `0`.
- No request-level range check was added. Keeping it in `SamplingParams` matches Chat Completions and avoids a second copy of the rule.
- P/D: the reference proxies (`tests/v1/kv_connector/nixl_integration/toy_proxy_server.py`, `disagg_proxy_multiturn.py`) already strip `min_tokens` from the prefill leg (`max_tokens=1`) and restore it on the decode leg, so the prefill leg does not trip `min_tokens <= max_tokens`.
- `min_tokens` is not part of Anthropic's spec. It sits with the other vLLM extra fields (`cache_salt`, `watermarking`, `kv_transfer_params`, ...). Anthropic SDK users pass it via `extra_body`.
