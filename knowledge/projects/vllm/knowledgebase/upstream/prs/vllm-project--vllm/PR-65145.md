# [CI] Bake hash-locked KV connectors into the CI image and re-enable their jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/65145) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Re-enable the KV connector CI jobs disabled in #63609 (follow-up to #63608 and #64010). Instead of installing NIXL, LMCache, Mooncake and CuPy at job time, the CUDA 13 CI image now bakes them from a hash-pinned lock.

## Claims

- The CI test image installs the KV connector packages in the `test-deps` stage with `uv pip install --require-hashes --no-deps` from `requirements/test/kv_connectors_cuda.txt`. That lock is compiled against `requirements/test/cuda.txt` and regenerated by a new `pip-compile-kv-connectors` pre-commit hook. At build time it adds 16 packages and changes none already in the image.
- `install-kv-connectors.sh` becomes `check-kv-connectors.sh`. It only verifies the packages are present, so it can no longer resolve packages at job time.
- **ROCm needs no image change.** `kv_connectors_rocm.txt` (`tblib`, `lm_eval[api]`) is fully covered by `requirements/test/rocm.txt`, so the runtime installs were no-ops. They and the file are removed.
- **26 job blocks re-enabled.** The CUDA and AMD jobs are listed in the build below.
- **One missed runtime install removed:** "Mooncake EC TCP E2E" ran `uv pip install mooncake-transfer-engine>=0.3.12` into a venv. It now uses the image's Mooncake through `--system-site-packages`.
- 6 tethering-allowlist entries removed.

## Validation

- `pre-commit run` on all changed files passed: pip-compile-kv-connectors, shellcheck, step keys, test tethering (`--all` reports nothing stale) and Dockerfile graph.
- All Buildkite YAML parses. Each restored block matches its pre-#63609 definition except for the script rename and the dropped ROCm install line.
- Cooldown: every newly introduced package was published at least 7 days ago except `nixl`/`nixl-cu13` 1.5.2 (PyPI Oct 29). Main already pins it in `requirements/kv_connectors.txt` since #64585. **Please don't merge before Nov 5** if we hold to the 7-day rule.
- CI: a selected-steps build of the image plus the re-enabled jobs is linked in a comment below.

## Details

- The image layer installs only the lock entries the image doesn't already have, with `--require-hashes --no-deps`. It then fails the build if any preinstalled package changed. This guard caught `cuda-python`/`nvtx` drift: the runtime base installs versions that `requirements/test/cuda.txt` doesn't pin. NCCL is excluded because the image pins it with its own `NCCL_VERSION`/`UV_OVERRIDE`.
- **Scope:** only the stable x86_64 CUDA 13 image. Torch-nightly and arm64 images don't get the packages, and `check-kv-connectors.sh` fails fast there with a clear message. The KV jobs only run on x86 L4/H100/H200/B200 pools.
- **Still disabled:**
  - A100 "NixlConnector PD + Spec Decode acceptance": the A100 queue was retired in #64602. Its MI355 mirror needs a standalone conversion.
  - The two Intel jobs that `pip install -r requirements/kv_connectors.txt` on the XPU image. They need an Intel image change.
- The release images (`INSTALL_KV_CONNECTORS=true`) are unchanged.
