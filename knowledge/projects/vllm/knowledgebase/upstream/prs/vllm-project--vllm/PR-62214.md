# [CI] Fix Rust frontend version mismatch from dirty wheel version

[Upstream PR](https://github.com/vllm-project/vllm/pull/62214) · state: closed · merged: False

## Original PR description

## Purpose

Fix the Rust frontend version mismatch that fails `:nvidia: (H200 MIG 18GB) Rust Frontend OpenAI Coverage` and `Serve/Admin Coverage` on main (since [95599](https://buildkite.com/vllm/ci/builds/95599)). `test_uds.py::test_show_version` asserts `rust_frontend_version == VLLM_VERSION`, but the Python wheel is stamped `...+g<sha>.d20261017` while the Rust frontend is not.

**Root cause:** #61302 added `/recipes` to `.dockerignore`. Those files are tracked, so in the Docker build context setuptools-scm sees them as deleted, marks the tree dirty, and appends `.dYYYYMMDD` to the wheel version. The `rust-build` stage already sets `SETUPTOOLS_SCM_PRETEND_METADATA="{dirty=false}"`; the wheel build did not.

**Fix:** apply `dirty=false` to the wheel build unconditionally, so both stamps derive from the same metadata. A regression test in `tests/tools/test_docker_build_metadata_args.py` checks the wheel build sets it.

**Not a duplicate:** this supersedes #53719 (same author), which applied the pin only for `PYTORCH_NIGHTLY=1` builds; this version also covers the nightly case. I'll close #53719 once this lands.

## Test Plan

- I extracted the new test's assertion and ran it standalone (the repo conftest needs a full env): it passes on this branch and fails on `origin/main`.
- CI for the Rust Frontend coverage steps will confirm end-to-end. The Docker build was not run locally.
