# [ROCm] Add head-fused HIP sparse MLA decode kernel for gfx950

[Upstream PR](https://github.com/vllm-project/vllm/pull/57282) · state: open · merged: False

## Original PR description

## Purpose

Add head-fused HIP sparse MLA decode kernel for MI355X (gfx950). The kernel groups MQA heads (HG=2) so each token's KV latent is loaded once and reused across heads, cutting KV read traffic ~2x vs the per-head Triton path. Targets DSpark spec-decode batch range B=33-72 (C=8 → B=48 for DeepSeek-V4.1-Flash).

Gated behind `VLLM_ROCM_USE_HIP_SPARSE_MLA=1` env var — opt-in, zero impact when disabled. Falls through to existing Triton ragged decode outside the dispatch range.

## Test Plan

1. Build kernel: `hipcc -x hip --offload-arch=gfx950 -O3 -std=c++17 -fPIC -shared csrc/rocm/mla/sparse_mla_decode_m5.hip -o libsmla_m5.so`
2. Set env vars: `VLLM_ROCM_USE_HIP_SPARSE_MLA=1 VLLM_ROCM_HIP_SPARSE_MLA_M5_SO=<path>/libsmla_m5.so`
3. Microbench: rocprofv3 kernel trace at B=48/64, verify device time < Triton baseline
4. E2E: 3600s agentx bench on MI355X TP=4 C=8 with MTP spec-decode (DeepSeek-V4.1-Flash)
5. Fallback: unset env var, verify Triton path fires unchanged

## Test Result

**Microbench (rocprofv3, MI355X gfx950):**

| Batch | M5 (µs) | Triton (µs) | Speedup |
|-------|---------|-------------|---------|
| B=48  | 9.9     | 12.4        | 1.25x   |
| B=64  | 10.1    | 13.9        | 1.38x   |

SNR vs Triton reference: 51.77 dB at B=48.

**E2E (agentx, 3600s, C=8, TP=4, MTP spec-decode, DeepSeek-V4.1-Flash, MI355X):**

| Metric | Baseline | With M5 | Delta |
|--------|----------|---------|-------|
| P90 Interactivity (tok/s/user) | 139.5 | 146.6 | **+5.1%** |
| P90 TTFT (s) | 1.067 | 0.970 | **−9.1%** |
| Output tok/s/chip | 93.0 | 93.7 | +0.8% |
