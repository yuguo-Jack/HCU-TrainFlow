# [Bugfix][Frontend] Copy caller's prompt list at streaming-session entry

[Upstream PR](https://github.com/vllm-project/vllm/pull/54226) · state: open · merged: False

## Original PR description

## Overview

Prevent streaming sessions from mutating caller-owned prompt token lists, so a later request can safely reuse the same prompt. Fixes #54215.

## Claims

- Copy token lists before `InputProcessor` retains them, covering bare lists, structured `TokensInput`/`MultiModalInput` dictionaries, and nested encoder-decoder prompts.
- Add three regression tests that check value preservation and distinct token-list identity.
- Preserve the empty-stream behavior and regression test introduced by #59015.

## Details

`RequestState` retained the caller's token list by reference, and `OutputProcessor.apply_streaming_update()` extended that list with subsequent chunks in the client process. Copying the relevant token list at streaming-session entry gives the session ownership of its mutable token storage without deep-copying multimodal data or changing non-streaming requests.

Structured prompts use typed shallow copies so the defensive copy also preserves `TypedDict` information for static checking.

The existing review feedback about structured inputs is covered by the structured and encoder-decoder regressions. Searching open PRs for #54215 found this PR as the only matching fix; #59015 addresses empty input streams and is retained independently.

**[P2] Copy token IDs from structured engine inputs as well.** `StreamingInput.prompt` is declared as `EngineInput`; its token form is a `TokensInput` dict such as `tokens_input(prompt_token_ids=caller_ids)`, so this `isinstance(..., list)` branch is skipped. `split_enc_dec_input()` returns that dict unchanged, `InputProcessor.process_inputs()` assigns `decoder_input['prompt_token_ids']` directly to `EngineCoreRequest`, and `RequestState` retains that same list before `apply_streaming_update()` extends it.
