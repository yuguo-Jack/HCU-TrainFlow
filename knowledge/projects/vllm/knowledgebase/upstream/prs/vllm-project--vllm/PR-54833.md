# [Rust][Metrics] Consume LoRA load events in the Rust frontend

[Upstream PR](https://github.com/vllm-project/vllm/pull/54833) · state: open · merged: False

## Original PR description

The Rust frontend decodes `EngineCoreOutputs.lora_load_event` (added in #51433) but drops it, so its `/metrics` lags the Python frontend's. This registers the same series with the same labels: `vllm:lora_adapter_loaded{adapter_name, level, pinned, rank}`, `vllm:num_gpu_loaded_lora_adapters`, `vllm:num_cpu_loaded_lora_adapters`, `vllm:max_gpu_lora_adapters` (from the handshake's `max_loras`), and `vllm:lora_adapter_load_seconds{transition}`. Each per-engine snapshot is diffed against the last one so evicted adapters lose their series.

## Stack

1. #51433 LoRA residency on `EngineCoreOutputs` + Python Prometheus metrics
2. #54833 Rust frontend consumer for the same metrics (this PR)

This PR is based on `main` and includes #51433's commits; review only the last three.

`cargo test -p vllm-engine-core-client --lib`: 147 passed.

Test report: ran this on an H200 on coreweave with an image built from this branch plus #54837 (so the Rust frontend could take `--lora-modules`).

`vllm serve Qwen/Qwen3-0.6B --enable-lora --max-loras 2 --max-cpu-loras 3 --lora-modules alice=charent/self_cognition_Alice`, `VLLM_USE_RUST_FRONTEND=1`, `VLLM_ALLOW_RUNTIME_LORA_UPDATING=1`.

Startup, before any request:

```
vllm:num_gpu_loaded_lora_adapters{engine="0"} 1
vllm:num_cpu_loaded_lora_adapters{engine="0"} 1
vllm:lora_adapter_loaded{engine="0",adapter_name="alice",level="gpu",pinned="false"} 1
```

After loading `bob` and `carol` over `/v1/load_lora_adapter`: gpu=2, cpu=3, `alice` drops to `level="cpu"`.
After one chat request on `alice`: `alice` back on gpu, `bob` on cpu (this is the step-time doorbell from #54830).
After `/v1/unload_lora_adapter` for `bob`: series gone, cpu=2.

Same sequence on the Python frontend gives the same numbers, except the unload step, which is #54839.
