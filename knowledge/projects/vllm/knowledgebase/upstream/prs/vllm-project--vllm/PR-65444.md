# [Perf] Make detokenizer output-text appends O(1) per token

[Upstream PR](https://github.com/vllm-project/vllm/pull/65444) · state: open · merged: False

## Original PR description



## Overview

`BaseIncrementalDetokenizer.update()` appends each decoded token with `self.output_text += piece`. Because `output_text` is an attribute, CPython copies the whole text on every append, so each token costs O(output length) on the front-end process. This PR keeps the text as buffered pieces and joins it only when read.

## Claims

- Per-step detokenizer cost no longer grows with output length for non-streaming (`FINAL_ONLY`) and streaming (`DELTA`) requests: **12.3x / 7.4x** less detokenizer time at 32k-token outputs (256 concurrent requests, CPU microbenchmark below).
- End to end, in a multi-node deployment with long outputs and hundreds of concurrent requests per engine, front-end-delivered tokens rose **+30–35%** while the engines were loaded (runtime patch equivalent to this change, see Validation).
- Output is unchanged: identical text, stop strings, truncation and token trimming in all three output modes (600-case differential against the current code).
- `CUMULATIVE` mode is roughly neutral (0.9–1.1x): its API returns the full text every step, which is O(length) either way.

## Validation

**Tests.** New `tests/detokenizer/test_output_text_buffer.py` covers outputs spanning several buffered chunks: full text vs. decoded pieces, streamed deltas reassembling the text with stop-string hold-back, and a stop string straddling tokens after several chunks (with/without `include_stop_str_in_output`, single- and multi-token steps). It runs in the existing `detokenizer` CI step.

```
       tests/detokenizer/test_check_stop_strings.py tests/detokenizer/test_min_tokens.py
```

Run on the CPU platform (`VLLM_TARGET_DEVICE=cpu`, aarch64, Python 3.12). Tests needing gated checkpoints or a running engine were not run locally and are left to CI.

**Differential test against the current code.** The current and new `detokenizer.py` were loaded side by side and fed the same 600 randomized requests through `FastIncrementalDetokenizer` with a real fast tokenizer (`facebook/opt-125m`): random/real text, multi-token steps (up to 7), `min_tokens`, `skip_special_tokens`, stop-terminated last tokens, stop strings sampled from the output (389 of 600 cases hit one), outputs up to 3,194 tokens, and `FINAL_ONLY` / `CUMULATIVE` / `DELTA` reads every step. Per-step return values, final `output_text` and `output_token_ids` were compared: **0 mismatches**.

**Microbenchmark.** 256 requests decoded in lockstep, one token per request per step, `facebook/opt-125m` fast tokenizer, CPU only (aarch64, 96 cores). "ms/step at end" is the cost of one step over all 256 requests, averaged over the last 100 steps.

| | 32k | 178.5 s (13.81) | 24.2 s (0.75) | **7.4x** |
| `CUMULATIVE` | 4k | 3.6 s (1.19) | 4.2 s (1.28) | 0.9x |

**End to end.** Multi-node RL rollout serving: 138 vLLM engines (TP4) behind the OpenAI server, non-streaming chat completions, several hundred concurrent requests per engine, mean output length growing to tens of thousands of tokens. `py-spy --gil` on the AsyncLLM process showed the front end holding the GIL 76–87% of the time, about a quarter of it on this one line (`decode_next` itself was small). With a runtime patch implementing this change on vLLM 0.29, generated tokens delivered through the front end in the first 10/20 minutes rose +35%/+30% over the same setup without it. Two runs of the baseline agreed within 1–2%; the patched arm was run once. The gain is in tokens delivered while engines are loaded; it does not change GPU work.

```python
"""Differential test and benchmark: vLLM main's detokenizer.py vs. the buffered one.

  python diff_and_bench.py diff
  python diff_and_bench.py bench
"""

import importlib.util
import os
import random
import sys
import time
from types import SimpleNamespace

from transformers import AutoTokenizer

from vllm import SamplingParams

HERE = os.path.dirname(os.path.abspath(__file__))


def load(name, path):
    spec = importlib.util.spec_from_file_location(name, path)
    mod = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(mod)
    return mod


ORIG = load("detok_orig", os.path.join(HERE, "detokenizer_orig.py"))
NEW = load("detok_new", os.path.join(HERE, "detokenizer_new.py"))
TOK = AutoTokenizer.from_pretrained(os.environ.get("TOKENIZER", "facebook/opt-125m"))
TEXTS = [
    "def f(x):\n    return x * 2\n\nprint(f(21))\n</tool_call>\nDone.",
    "Das ist ein Test. 这是一个测试。 これはテストです。 🙂🚀👩‍💻 café naïve",
    "<think>Let me reason step by step.\n\n1. First...\n2. Then STOP</think>\nA: 42",
    '{"name": "bash", "arguments": {"cmd": "ls -la /tmp && echo ok"}}\n\n\n' * 3,
]


def request(sp, prompt):
    return SimpleNamespace(
        request_id="r", prompt_token_ids=prompt, prompt_embeds=None, sampling_params=sp
    )


def run_case(mod, c):
    sp = SamplingParams(
        stop=c["stop"],
        include_stop_str_in_output=c["include"],
        min_tokens=c["min_tokens"],
        skip_special_tokens=c["skip_special"],
        max_tokens=len(c["ids"]) + c["min_tokens"] + 1,
    )
    d = mod.IncrementalDetokenizer.from_new_request(TOK, request(sp, c["prompt"]))
    trace = [type(d).__name__]
    ids, pos, k = c["ids"], 0, 0
    while pos < len(ids):
        step = ids[pos : pos + c["steps"][k]]
        k += 1
        pos += len(step)
        last = pos >= len(ids)
        stop_str = d.update(step, c["stop_terminated"] and last)
        finished = last or stop_str is not None
        if c["mode"] == "final":
            trace.append([stop_str])
        else:
            text = d.get_next_output_text(finished, c["mode"] == "delta")
            trace.append([stop_str, text])
        if finished:
            break
    trace.append([d.get_next_output_text(True, False), d.output_text, d.output_token_ids])
    return trace


def cases(n, seed=0):
    rng = random.Random(seed)
    vocab = TOK.vocab_size
    base = [TOK.encode(t, add_special_tokens=False) for t in TEXTS]
    out = []
    for i in range(n):
        reps = rng.choice([1, 1, 20, 60])  # long outputs span several chunks
        ids = []
        for _ in range(reps):
            ids += base[rng.randrange(len(base))]
            if rng.random() < 0.3:
                ids += [rng.randrange(vocab) for _ in range(rng.randint(1, 10))]
        full = TOK.decode(ids)
        choice = i % 4
        if choice == 0:
            stop = None
        elif choice == 1:
            stop = ["\n\n", "STOP"]
        else:
            stop = []
            for _ in range(rng.randint(1, 3)):
                a = rng.randrange(max(1, len(full) - 2))
                stop.append(full[a : a + rng.randint(1, 8)])
            stop = [s for s in stop if s] or ["\n"]
        out.append(
            dict(
                prompt=TOK.encode("Hello there.", add_special_tokens=False),
                ids=ids,
                stop=stop,
                include=bool(rng.getrandbits(1)),
                min_tokens=rng.choice([0, 0, 3, 50]),
                skip_special=bool(rng.getrandbits(1)),
                steps=[rng.choice([1, 1, 1, 2, 4, 7]) for _ in ids],
                stop_terminated=bool(rng.getrandbits(1)),
                mode=rng.choice(["final", "cumulative", "delta"]),
            )
        )
    return out


def cmd_diff():
    cs = cases(600)
    bad = 0
    for i, c in enumerate(cs):
        a, b = run_case(ORIG, c), run_case(NEW, c)
        if a != b:
            bad += 1
            if bad <= 3:
                print("MISMATCH case", i, c["mode"], c["stop"], "\n orig", a[-1][0][-80:], "\n new ", b[-1][0][-80:])
    hit = sum(any(s and s[0] for s in run_case(NEW, c)[1:-1]) for c in cs)
    longest = max(len(c["ids"]) for c in cs)
    print(f"differential: {len(cs)} cases, {bad} mismatches, {hit} hit a stop string, "
          f"longest {longest} tokens, modes final/cumulative/delta")
    sys.exit(1 if bad else 0)


def cmd_bench(n_req=256, lengths=(4000, 16000, 32000)):
    ids = TOK.encode(" ".join(TEXTS) * 200, add_special_tokens=False)
    for mode in ("final", "delta", "cumulative"):
        for L in lengths:
            row = []
            for name, mod in (("main", ORIG), ("buffered", NEW)):
                sp = SamplingParams(max_tokens=L + 1)
                dets = [
                    mod.IncrementalDetokenizer.from_new_request(TOK, request(sp, ids[:16]))
                    for _ in range(n_req)
                ]
                t0 = time.perf_counter()
                late = 0.0
                for s in range(L):
                    tid = ids[s % len(ids)]
                    ts = time.perf_counter()
                    for d in dets:
                        d.update([tid], False)
                        if mode == "delta":
                            d.get_next_output_text(False, True)
                        elif mode == "cumulative":
                            d.get_next_output_text(False, False)
                    if s >= L - 100:
                        late += time.perf_counter() - ts
                for d in dets:
                    d.get_next_output_text(True, mode == "delta")
                row.append((time.perf_counter() - t0, late / 100 * 1e3))
            (tm, lm), (tb, lb) = row
            print(f"{mode:10s} {n_req} reqs x {L:6d} tok: main {tm:6.1f}s ({lm:5.2f} ms/step at end)"
                  f"  buffered {tb:6.1f}s ({lb:5.2f} ms/step at end)  speedup {tm / tb:4.1f}x", flush=True)


if __name__ == "__main__":
    {"diff": cmd_diff, "bench": cmd_bench}[sys.argv[1]]()
```

## Details

**Root cause.** CPython grows a `str` in place for `s += t` only when `s` is a local with refcount 1. `self.output_text` is an attribute, so evestring and copies the whole text so far. The detokenizer runs `update()` for every running request on every engine step, on the front-end eventloop, so with long outputs and many concurrent requests the copying dominates the front end and delays delivery of outputs, new admissions and other work on that loop.

**Change.** `output_text` becomes a property over `_text_chunks` (joined text) and `_text_pieces` (pieces since the last fold). `update()` appends pieces and folds every 64 into a chunk, keeping the number of objects small. Reading `output_text` joins once and caches the result as a single chunk. The setter (used
for stop-string truncation) resets the buffer.

- Stop strings: `check_stop_strings` only searches the last `new_char_count + len(stop) - 1` characters, so it is now given that tail (`_text_tafset is converted back to an absolute position. The `token_offsets` / `bisect_left` trimming from #47616 uses absolute offsets as before.
- `get_next_output_text(delta=True)` reads only the new characters from the tail instead of slicing the full text.
- `get_next_output_text(delta=False)` reads the full text, so `CUMULATIVE` still pays O(length) per step. That cost is inherent to returning thetable shows it neutral within noise, with small-length overhead from the property and join.

**Tradeoffs and limits.** Memory overhead is a small list of chunk objects per request (one per 64 tokens). `FINAL_ONLY` joins once at finish (a change to `IncrementalDetokenizer` (no-tokenizer path), `SlowIncrementalDetokenizer` or `FastIncrementalDetokenizer` beyond inheriting thebuffered base. Front-end only; no GPU synchronization or engine-core changes.

**Linting.** `pre-commit` hooks that apply to these files pass locally: ruff 0.14.0 (check + format), typos 1.51.1, mypy 1.20.2 (Python 3.11), and the SPDX-header, test-tethering, forbidden-import, `torch.cuda`-call and lazy-import checks.
