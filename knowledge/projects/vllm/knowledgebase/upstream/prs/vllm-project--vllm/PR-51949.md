# [Model] Enable LoRA support for tower and connector in Cosmos3-Edge

[Upstream PR](https://github.com/vllm-project/vllm/pull/51949) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Enables LoRA on the vision tower and the connector of `nvidia/Cosmos3-Edge`
(`Cosmos3EdgeForConditionalGeneration`), so that the model can be adapted to a new visual domain
without full fine-tuning. Part of #31479 (closed once most towers supported LoRA; no closing keyword,
like the merged siblings).

## Claims

- `--enable-lora` now works for Cosmos3-Edge. Before this change, the engine refused to start with
  `ValueError: Cosmos3EdgeForConditionalGeneration does not support LoRA yet.`
- With `enable_tower_connector_lora=True`, adapters apply to the vision tower (`visual.`) and the
  connector (`visual.projector`) for image and video inputs.
- `get_mm_lora_token_counts` returns exactly the row counts that reach the tower and the connector,
  measured on real tensors (table below).
- `docs/models/supported_models.md` marks Cosmos3-Edge as LoRA-capable.

With `enable_lora=True, enable_tower_connector_lora=True, max_lora_rank=8`, the engine starts and logs
the "experimental" warning, and does not log "This will be ignored". The LoRA manager builds Punica
wrappers for `language_model`, `visual.` and `visual.projector`.

Forward pre-hooks record the rows that enter `visual.encoder.encoder.layers.0.self_attn.qkv_proj`
(tower) and `visual.projector.linear_fc1` (connector), and the script compares them with the hook's
output:

| input | LLM tokens | tower rows observed | hook | connector rows observed | hook |
|---|---|---|---|---|---|
| image | 1107 | 4428 | 4428 | 1107 | 1107 |
| video, 4 frames | 4180 | 16720 | 16720 | 4180 | 4180 |

The counts are the same with and without an adapter attached.

The adapter reaches both modules. The test adapter was a random rank-8 adapter (alpha 16, nonzero B)
on layer 0 of the tower and on `visual.projector.linear_fc{1,2}`. vLLM wraps 109 tower and 2
connector linear layers, and their Punica ops are active only with the adapter. The output of the
tower's `qkv_proj` changes by 2.78% for the image and 2.70% for the video (`||a - b|| / ||b||`, with
identical input). The output of `projector.linear_fc2` changes by 16.5% and 18.6%. This shows that
the adapter path is used. It is not a model-quality measurement.

No new test is added, in line with review on the sibling PRs #51780, #49788 and #48215. CI has no
Cosmos3-Edge LoRA job, so the GPU validation above is the coverage for this path.

```python
import argparse
import os

os.environ.setdefault("VLLM_ENABLE_V1_MULTIPROCESSING", "0")

from types import SimpleNamespace

from vllm import LLM, SamplingParams
from vllm.assets.image import ImageAsset
from vllm.assets.video import VideoAsset
from vllm.lora.request import LoRARequest
from vllm.model_executor.models.cosmos3_edge import (
    Cosmos3EdgeForConditionalGeneration as C3E,
)
from vllm.transformers_utils.config import get_config

parser = argparse.ArgumentParser()
parser.add_argument("--adapter", help="LoRA dir; enables tower/connector LoRA")
args = parser.parse_args()

MODEL = "nvidia/Cosmos3-Edge"
TOWER = "visual.encoder.encoder.layers.0.self_attn.qkv_proj"
CONNECTOR = "visual.projector.linear_fc1"

seen: dict[str, list[int]] = {"tower": [], "connector": []}


def install_hooks(model):
    def record(key):
        def hook(_module, args):
            seen[key].append(args[0].shape[-2])

        return hook

    for name, module in model.named_modules():
        if name == TOWER:
            module.register_forward_pre_hook(record("tower"))
        elif name == CONNECTOR:
            module.register_forward_pre_hook(record("connector"))


lora_kwargs = (
    dict(enable_lora=True, enable_tower_connector_lora=True, max_lora_rank=8)
    if args.adapter
    else {}
)
lora_request = LoRARequest("probe", 1, args.adapter) if args.adapter else None

llm = LLM(
    model=MODEL,
    max_model_len=16384,
    limit_mm_per_prompt={"image": 1, "video": 1},
    gpu_memory_utilization=0.85,
    enforce_eager=True,
    allowed_local_media_path="/",
    mm_processor_cache_gb=0,
    **lora_kwargs,
)
llm.apply_model(install_hooks)

config = get_config(MODEL, trust_remote_code=False)
tokenizer = llm.get_tokenizer()
start = tokenizer.decode([config.vision_start_token_id])
end = tokenizer.decode([config.vision_end_token_id])
image_pad = tokenizer.decode([config.image_token_id])
params = SamplingParams(temperature=0.0, max_tokens=1)


def check(label, output, token_id, modality):
    llm_tokens = output[0].prompt_token_ids.count(token_id)
    encoder_rows, connector_rows = seen["tower"][-1], seen["connector"][-1]
    stub = SimpleNamespace(
        visual=SimpleNamespace(
            spatial_merge_size=config.vision_config.spatial_merge_size
        )
    )
    predicted_encoder, predicted_connector = C3E.get_mm_lora_token_counts(
        stub, modality=modality, mm_kwargs=None, num_mm_embeds=llm_tokens
    )
    print(
        f"{label:<8} llm_tokens={llm_tokens}  "
        f"encoder observed={encoder_rows} helper={predicted_encoder} "
        f"{'OK' if encoder_rows == predicted_encoder else 'MISMATCH'}  "
        f"connector observed={connector_rows} helper={predicted_connector} "
        f"{'OK' if connector_rows == predicted_connector else 'MISMATCH'}"
    )


check(
    "image",
    llm.generate(
        {
            "prompt": f"<|im_start|>user\n{start}{image_pad}{end}Describe."
            f"<|im_end|>\n<|im_start|>assistant\n",
            "multi_modal_data": {"image": ImageAsset("stop_sign").pil_image},
        },
        params,
        lora_request=lora_request,
    ),
    config.image_token_id,
    "image",
)

video = VideoAsset(name="baby_reading", num_frames=4)
check(
    "video",
    llm.chat(
        [
            {
                "role": "user",
                "content": [
                    {
                        "type": "video_url",
                        "video_url": {"url": f"file://{video.video_path}"},
                    },
                    {"type": "text", "text": "Describe."},
                ],
            }
        ],
        params,
        lora_request=lora_request,
    ),
    config.video_token_id,
    "video",
)
```

The video prompt goes through the chat template. A hand-built video placeholder leaves out the
per-frame timestamp tokens, which misplaces the embeddings without raising an error and would
invalidate the comparison.

## Details

A model opts in by declaring `SupportsLoRA`, setting `supports_tower_connector_lora`, and implementing
`get_mm_lora_token_counts`. Cosmos3-Edge's `get_mm_mapping` and `packed_modules_mapping` were already
correct, so those three are the whole change.

- **The capability flag is required.** `vllm/lora/model_manager.py:244` enables tower/connector LoRA
  only when the model sets `supports_tower_connector_lora` (default `False`,
  `interfaces.py:209`, from #53092). Without the flag, the engine logs "This will be ignored" and
  serves without the adapter, which is the LFM2-VL bug that #53519 fixed.
- **Only the unified hook is implemented**, in the shape that #55071 (merged) gives Keye and Qwen3-VL.
  Each LLM token corresponds to `spatial_merge_size**2` rows that enter the tower and to one row that
  enters the connector, for images and video alike, so `modality` and `mm_kwargs` are unused.
- **The merge factor comes from `self.visual.spatial_merge_size`.** This is the value the model
  already uses to split vision embeddings per item (`cosmos3_edge.py:685`).
- **There is no divisibility assertion.** At engine init, `model_manager.py:291` calls the hook with
  the whole-batch encoder budget, which need not be a multiple of anything.
- **Why exact counts matter.** Wrong counts don't raise. The LoRA metadata buffer keeps its values
  between forward passes, so a row that the count misses reads a stale adapter index, and the request
  gets plausible output from the wrong adapter. That is why the counts are measured rather than
  derived.

**Duplicate check** (`AGENTS.md`), re-run on 2026-11-03:
`gh pr list --repo vllm-project/vllm --state all --search "Cosmos3-Edge"` and
`--state open --search "cosmos3 lora"`. No other PR adds LoRA to Cosmos3-Edge; #53149 does the same
for GLM-ASR. Related:
- #52229 (open, encoder CUDA graphs for this model) edits the same class bases and import block, so
  whichever PR lands second has a one-line conflict.
- #47400 (open) fixes cache-served items in the same mapping builder. It is independent of this
  change.

**Known limitation: video pruning (EVS).** Cosmos3-Edge doesn't implement
`SupportsMultiModalPruning` (#51221 was closed), so EVS can't interact with tower LoRA here. On models
that do implement it, `PlaceholderRange.get_num_embeds()` returns the post-prune count while the tower
has processed every frame, so the tower count is short. The cause is in the shared call sites
(`vllm/v1/worker/gpu/mm/lora.py:62`, `gpu_model_runner.py:2810`) and is out of scope for this PR. If
EVS support is added to Cosmos3-Edge later, it should reject EVS combined with tower LoRA.
