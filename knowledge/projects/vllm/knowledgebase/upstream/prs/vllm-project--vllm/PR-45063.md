# fix: [Bug]: Wrong timestamps if audio > 30s

[Upstream PR](https://github.com/vllm-project/vllm/pull/45063) · state: closed · merged: False

## Original PR description

## Summary

`vllm/entrypoints/speech_to_text/base/serving.py` - `OpenAISpeechToText._create_speech_to_text` computed each audio chunk's `start_time` as `idx * max_audio_clip_s`.


## Root cause

`vllm/entrypoints/speech_to_text/base/serving.py` -
`OpenAISpeechToText._create_speech_to_text` computed each audio chunk's
`start_time` as `idx * max_audio_clip_s`. This assumed every chunk is exactly
`max_audio_clip_s` seconds long, but `split_audio` uses `find_split_point` to
search for a low-energy (quiet) region up to `overlap_duration_s` (default 1s)
before the nominal boundary. So the actual split can be up to 1s earlier than
the nominal position. The error accumulates: for a 65s clip split into 3 chunks
at 30s intervals, chunks actually start at [0, 29, 58] seconds while the code
was using [0, 30, 60], giving per-chunk errors of 0, 1, and 2 seconds.


## What changed

`vllm/entrypoints/speech_to_text/base/serving.OpenAISpeechToText._preprocess_speech_to_text`:
- Return type changed from `tuple[list[EngineInput], float]` to
 `tuple[list[EngineInput], float, list[float]]`.
- After `split_audio` (or the no-split single-chunk path), compute
 `chunk_start_times` by accumulating actual sample counts divided by the
 sample rate. This gives the exact start time for each chunk regardless of
 where `find_split_point` placed the boundary.

`vllm/entrypoints/speech_to_text/base/serving.OpenAISpeechToText._create_speech_to_text`:
- Unpack the new third return value `chunk_start_times`.
- Replace `float(idx * chunk_size_in_s)` with `chunk_start_times[idx]` when
 computing the `start_time` passed to `_get_verbose_segments`.
