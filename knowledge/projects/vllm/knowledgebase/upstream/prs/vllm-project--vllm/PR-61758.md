# [Bugfix] Include KV cache quantization settings in IPC weight cache key

[Upstream PR](https://github.com/vllm-project/vllm/pull/61758) · state: open · merged: False

## Original PR description




## Overview

Fix incorrect KV scales when an engine reuses IPC-cached weights prepared with a different KV cache quantization configuration.

Related to #56049

## Claims

- Detect incompatible KV cache dtype or skipped-layer settings through the existing cache mismatch and fallback handling.
- Retain the KV cache configuration used during initial loading for subsequent standalone weight reloads.

## Validation

Added one parameterized regression test covering dtype mismatches, skipped-layer mismatches, and equivalent skipped-layer lists. It checks initial loading and standalone reloading, including after the caller's configuration is mutated.

- Before: **2 failed, 1 passed**.
- After: **9 passed, 3 deselected**.
- All applicable pre-commit hooks passed.

```bash
.venv/bin/python -m pytest \
  --confcutdir=tests/model_executor/model_loader \
  tests/model_executor/model_loader/test_weight_cache.py \
  -k 'not cold_start_and_warm_restart' -q
```

GPU validation used an H800 NVL, PyTorch `2.14.0+cu130`, and a synthetic FP8 checkpoint derived from DeepSeek-R1-Distill-Qwen-1.5B, with BF16 activations, TP=1, eager execution, and the Torch FP8 linear backend. Three prompts were tested with greedy decoding, 32 output tokens, and prompt logprobs.

| Scenario | Result |
|---|---|
| Before: `auto` daemon → `fp8` engine | Incorrectly accepted cached weights; K/V scales became `1.0` instead of `0.0250244140625`, changing generated tokens for all three prompts |
| After: mismatch, fallback disabled | Raised `CacheConfigMismatchError` naming `kv_cache_dtype` |
| After: mismatch, fallback enabled | Both `zero_copy` and `copy` matched disk loading |
| After: matching `fp8` configurations | Both modes loaded 424 cached tensors and matched disk loading |

For matching configurations and fallback loading, KV scales, generated token IDs, and prompt logprobs matched disk loading exactly. Disk-loading results were unchanged by the fix. These checks validate loading consistency for the tested FP8 path, not model accuracy or all quantization backends.

## Details

The daemon caches tensors after weight processing, which depends on the KV cache configuration. The existing fingerprint includes model quantization settings but omits the KV cache dtype and skipped layers, allowing incompatible processed scales to be reused.

Include `kv_cache_dtype` and `kv_cache_dtype_skip_layers` in `WeightCacheKey`. Sort and deduplicate skipped layers so equivalent lists still match.

Pass `CacheConfig` when constructing daemon and engine keys. Save a copy on models returned by the IPC loader, including disk fallback, so standalone `load_weights()` calls retain the configuration used during initial loading without requiring an active configuration context. Models without a saved configuration use the current vLLM configuration.
