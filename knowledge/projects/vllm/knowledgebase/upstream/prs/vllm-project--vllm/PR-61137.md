# [Bugfix][Spec Decode] Apply min_tokens at the V1 bonus-token position

[Upstream PR](https://github.com/vllm-project/vllm/pull/61137) · state: open · merged: False

## Original PR description



## Overview

Fix V1 speculative decoding suppressing EOS on a bonus token that already satisfies `min_tokens`, causing extra output. Fixes #61115.

## Claims

- Use committed output length plus the actual draft count to determine bonus-token stop eligibility.
- Preserve ordinary decoding, draft-row masking, and structured-output stop-logit restoration.

## Details

With `n` committed tokens and `k` scheduled drafts, the bonus token is used only if all drafts are accepted. Its minimum-length mask must therefore use `n + k < min_tokens`. The old path checked only `n`: with 6 committed tokens, 3 drafts, and a minimum of 7, it incorrectly masked EOS at output index 9.

The patch routes the bonus min-tokens processor through the existing speculative masking method, using one row per request. It does not mutate committed-history state or change other processing steps. MRV2 already checks each row's token position and needs no change.

Duplicate check (2026-10-12): issue comments/timeline and open-PR searches for `61115 in:body` and `min_tokens bonus` found no competing fix. The latter matched #41834, whose sampler changes address NaN recovery.
