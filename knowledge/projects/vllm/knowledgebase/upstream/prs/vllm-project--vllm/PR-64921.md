# [Bugfix][Model] DeepSeek-V4.1: keep decoder replay off when its cut cannot be replayed

[Upstream PR](https://github.com/vllm-project/vllm/pull/64921) · state: open · merged: False

## Original PR description

## Overview

`DeepseekV4Model` (NVIDIA) uses the last KV source layer as the decoder replay cut. Three configurations break:

- `kv_source_layer_ids` is empty: `max()` raises `ValueError: max() iterable argument is empty` at construction.
- The cut is the first layer of this pipeline stage: replay is turned on, but the layers that write the KV it replays from run on another stage, so the replay prefix is empty and the forward hits the residual assert.
- The last KV source also writes compressed KV: construction fails `assert self.layers[cut].attn.compress_ratio <= 1`.

In each case replay now stays off. The compressed case goes through `_decoder_replay_supported`, which logs the reason like its other checks.

Split from #62365 by @aoshen02.

## Changes

- `vllm/models/deepseek_v41/nvidia/model.py`: `max(config.kv_source_layer_ids, default=None)`; replay requires `start_layer < cut < end_layer - 1`; `_decoder_replay_supported` rejects `compress_ratio > 1` at the cut.
- `tests/models/test_deepseek_v41_model_init.py` (new, CPU): `test_prefix_replay_requires_an_uncompressed_kv_source` builds the model with stubbed layers and checks the replay decision for five configurations. Added to the Basic Models (Other) step in `.buildkite/test_areas/models_basic.yaml`.
