# [Kernel] Allow registering OOT block-scaled FP8 linear kernels

[Upstream PR](https://github.com/vllm-project/vllm/pull/62026) · state: closed · merged: True

## Original PR description



## Overview

Lets out-of-tree platforms register block-scaled FP8 linear kernels by adding `kernel_type="fp8_block"` to `register_linear_kernel`.

## Claims

- `register_linear_kernel(..., kernel_type="fp8_block")` adds the kernel to `_POSSIBLE_FP8_BLOCK_KERNELS`.
- OOT platforms can now serve `--quantization fp8_per_block`, which previously failed during kernel selection because the OOT platform had no entry in the block-kernel list.
- The docstring now lists every `kernel_type` the function accepts. It previously listed only `mp`, `int8` and `fp8`.

## Validation

- `pre-commit` passes (ruff, mypy, typos, SPDX).
- The change adds one `elif` branch that matches the existing `fp8`, `mxfp8`, `nvfp4`, `mxfp4` and `mxfp6` branches. Existing kernel types behave as before.

## Details

`Fp8PerBlockOnlineLinearMethod` (and `Fp8LinearMethod` with `block_quant`) use a `GroupShape(1, 128)` activation key. Because `is_per_group()` is true for that shape, `init_fp8_linear_kernel` picks the kernel from `_POSSIBLE_FP8_BLOCK_KERNELS`. That dict only has entries for CUDA, ROCm, CPU and XPU, and `register_linear_kernel` had no way to add to it. An OOT platform that registered its FP8 kernel with `kernel_type="fp8"` therefore got per-tensor and per-channel FP8 but never block-wise.

To support both, an OOT plugin registers the same class twice, once as `"fp8"` and once as `"fp8_block"`. If that class subclasses `FP8ScaledMMLinearKernel`, the block path already builds it with `layer_param_names` (see the `issubclass` branch in `init_fp8_linear_kernel`), so no new base class or interface change is needed.
