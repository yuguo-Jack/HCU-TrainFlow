# [Rust Frontend] Carry reasoning controls over gRPC

[Upstream PR](https://github.com/vllm-project/vllm/pull/59836) · state: closed · merged: True

## Original PR description

## Overview

Carry thinking-token budgets and per-request engine reasoning-gate inputs through the Rust gRPC `Generate` and `GenerateStream` APIs. External frontends can preserve engine-managed structured-output gating while migrating to full-output grammars.

## Claims

- Group optional `reasoning_ended` and effective `chat_template_kwargs` in `GenerateRequest.engine_reasoning_gate`, preserving omitted versus explicit `false`.
- Keep the internal `ReasoningParserKwargs` representation typed and unchanged.
- Forward `StoppingCriteria.thinking_token_budget`, including zero and the existing disabled-budget semantics.

## Validation

From `rust/`:

```sh
cargo test --locked -p vllm-server -p vllm-text -p vllm-chat -p vllm-llm -p vllm-engine-core-client --lib -- --quiet
cargo fmt --all -- --check
```

1,048 tests passed; one existing text test is ignored. The reasoning-gate regression exercises protobuf serialization, gRPC conversion, and text-to-engine lowering for unary and streaming requests, including absent/empty gates, explicit booleans, template kwargs, and budget presence. The existing server suite also exercises real gRPC transport with a mock engine-core.

Scoped pre-commit checks and `cargo publish --manifest-path rust/proto/Cargo.toml --locked --dry-run` passed. No real-model/GPU evaluation has been performed; validation establishes request propagation, not model-output quality.

## Details

The engine-core request and shared text layer already support these controls, but the gRPC schema and converter could not carry them. The nested `EngineReasoningGate` is transitional: it applies when the engine runs its own reasoning parser and the constraint covers only post-reasoning output. Full-output grammars enforced from the first generated token are the preferred direction, and grouping these controls makes their eventual deprecation explicit.

This extends the gRPC interface and complements the HTTP generate work in #60062. Output parsing remains the caller's responsibility.

The protobuf fields are additive, and `vllm-proto` is bumped to 0.5.0. Old servers ignore the new fields, so clients relying on them require an updated server; no capability-negotiation flag is added.

Downstream integration: https://github.com/ai-dynamo/dynamo/pull/15550. Independent generation-controls and cache-usage changes: #59837.
