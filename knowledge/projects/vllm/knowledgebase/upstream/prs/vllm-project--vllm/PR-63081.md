# [Core] Warn at startup when a quantized KV cache meets a large first-layer key bias

[Upstream PR](https://github.com/vllm-project/vllm/pull/63081) · state: open · merged: False

## Original PR description

<!-- posted to #63081 on 2026-10-22 (author approved); design-notes and validation lines updated 2026-10-22 with the V2 hook (author approved) -->
## Overview

Some models carry a large bias on the key projection of their first attention layer. Qwen2, Qwen2.5 and their fine-tuned and distilled derivatives are the known cases. Under a per-token or per-head quantized KV cache these models answer at chance, and the engine reports success.

This PR adds a startup warning for that combination. It changes no behaviour.

The failure is the one #59671 describes and #59674 corrects in the kernel. This PR is the backend-independent warning.

## Claims

- On a 300-item key-value retrieval set, Qwen2.5-7B answers 297 unquantized and 0 under `int4_per_token_head`. Qwen2.5-1.5B answers 262 and 0. The bias-free Qwen3-4B-Base answers 298 under both.
- Keeping layer 0 unquantized (`--kv-cache-dtype-skip-layers 0`) restores 289 and 191. It runs within 3 percent of the quantized option's throughput.
- The warning separates the two groups. On the eleven checkpoints where the statistic was read next to a collapse count, every collapsed model read 116 to 456 and every intact model read 12 to 73.
- The check reads the weights, not the architecture. It therefore covers model classes and attention backends that #59674 does not. It also covers the fp8 cache at default scales, which collapses the same two models (60 and 0 of 300).

## Validation

- `pytest tests/v1/worker/test_kv_key_bias_preflight.py`: 9 tests, CPU only, all pass. They cover the band on NeoX and GPT-J layouts, partial rotary dims, the warning above the threshold and its absence below, the skip conditions, the first-layer rule, and the separate `k_proj` path.
- Manual: `vllm serve Qwen/Qwen2.5-1.5B --kv-cache-dtype int4_per_token_head` logs the warning. With `--kv-cache-dtype-skip-layers 0` or `--kv-cache-dtype auto` it does not. `Qwen/Qwen3-4B-Base` (no key bias) does not.
- Executed on vLLM 0.32.0 with the models built through vLLM's own loader: Qwen2.5-0.5B reads 130 and warns under `int4_per_token_head` and `fp8`, stays silent with `--kv-cache-dtype-skip-layers 0` and under `auto`; Qwen3-0.6B (no key bias) stays silent.
- The counts above were the same on an RTX 5090, an L40S and an H100. They were the same under vLLM 0.28.0 and 0.31.0 (the op's source is byte-identical between the two), with and without CUDA graphs.

## Details

**Why these models fail.** The bias puts the same offset on every cached key of layer 0. The quantizer's per-token range is then set by the offset, not by the signal. The signal rounds away, and the rotated query reads noise.

**What the check does.** It runs once after the weights load (not for dummy weights). It finds the first attention layer with a key bias: a fused `qkv_proj` with `q_size` / `kv_size`, or a separate `k_proj`. It reads the largest |bias| on the slowest-rotating eighth of the rotary pairs. If that value exceeds 100, the cache is quantized, and layer 0 is not already in `--kv-cache-dtype-skip-layers`, it logs one warning that names the remedy.

**Why 100.** Eleven checkpoints have this statistic next to a collapse count. The six that collapsed read 116 to 456. The five that held read 12 to 73 (Qwen2.5-14B 33, GLM-4-9B 12, PowerLM-3b 72, StableLM-2-1.6B 36, StarCoder2-3B 26). A 49-checkpoint survey on the coarser all-dims maximum agrees: every non-Qwen model is at or below 73, and the collapsed Qwen carriers are at 316 to 414. The threshold is a constant with a docstring, not a config option, because the check only warns.

**Why a warning next to the kernel fix.** #59674 changes three things: the Qwen2 model class, the Triton attention backend, and the `int4_per_token_head` op. A model with the same bias under another architecture class is not covered. Another backend is not covered. The fp8 cache is not covered. Today the engine gives the user no signal at all. If #59674 lands, the warning still earns its place for those cases, and it can be narrowed then.

**Design notes.** The check is 150 lines in a new module. Both GPU model runners (V1 `gpu_model_runner.py`, V2 `gpu/model_runner.py`) gain the same 11 lines: one import and one call in `load_model()`. The KV-cache quantization docs gain one paragraph. The statistic is read per rank from that rank's K slice, so under tensor parallelism the warning may print from several ranks (`warning_once`, global scope). Models with a `k_norm` after the projection (Qwen3) have no key bias and are skipped.

**AI assistance.** AI tools assisted with the code, the tests and this description. The measurements and the analysis are the author's. The author reviewed every changed line.
