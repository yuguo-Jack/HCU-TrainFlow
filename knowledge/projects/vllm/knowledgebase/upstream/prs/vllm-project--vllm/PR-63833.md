# [Bugfix][ROCm] Wait on per-slot events in packed NCCL consumer

[Upstream PR](https://github.com/vllm-project/vllm/pull/63833) · state: closed · merged: True

## Original PR description



## Overview

On ROCm, the packed NCCL consumer's per-slot `streams[i].synchronize()` can also wait for another slot's later `post_unpack_func` work, such as a layerwise reload replay. That stalls the host and removes the multi-buffer overlap. This PR waits on a per-slot event instead. Follow-up to #62555.

## Claims

- Fixes the MI300X failure of `tests/distributed/test_packed_tensor.py::TestPackedBroadcastDeferredConsumer::test_freed_pack_not_reused_while_replay_pending` (all three parameterizations) when slot streams share a HIP hardware queue. The failure was seen in AMD CI.
- Restores the overlap on ROCm when queues are shared. The consumer-only layerwise benchmark gets up to 7.9% faster on MI300X.
- No regression on H100: every latency change is within ±0.41%, and memory is identical.

## Details

**Root cause.** HIP multiplexes streams onto a small pool of hardware queues per process (`GPU_MAX_HW_QUEUES`, default 4).

- **Before:** when two slot streams share a queue, `hipStreamSynchronize` on one also waits for work queued later on the other. The consumer's `streams[buffer_idx].synchronize()` before reusing slot `i` then waits for slot `j`'s `post_unpack_func` work, such as a layerwise replay. The host can't issue the next receive until that replay ends. The overlap the `num_buffers` window exists for is lost, and the test's assertion that the replay is still pending while the window's receives are issued fails.
- **Why only ROCm:** CUDA streams don't serialize host synchronization this way.

**Fix.** After `post_unpack_func`, record a `torch.Event` on the slot stream (`slot_done[buffer_idx]`). Before reusing the slot, wait on that event instead of synchronizing the stream.

- **Same coverage:** the event covers the same work as before, the receive, unpack and `post_unpack_func` work on that slot's stream, but nothing queued after it.
- **First use:** on a slot's first use there is nothing to wait for, so the wait is skipped. That's `num_buffers` fewer waits per call.
- **Drain:** the closing `for stream in streams: stream.synchronize()` drain is unchanged.

**Tradeoff.** The change adds one event record per pack. In the consumer-only microbenchmark with no queue sharing, B is about 0.4–1.6% slower on MI300X (beyond noise in some configs, with sub-millisecond packs), and within noise on H100. This doesn't show up with a real RCCL/NCCL transfer or end to end.

**CI.** `tests/distributed/test_packed_tensor.py` already runs on AMD CI, which is where the failure appeared. No new test is added. Whether the existing test catches a regression of this fix depends on the runner's queue assignment. Forcing `GPU_MAX_HW_QUEUES=1` reproduces it every time.
