# [Docs][Core] Document that callers serialize sleep control operations

[Upstream PR](https://github.com/vllm-project/vllm/pull/64185) · state: open · merged: False

## Original PR description

## Overview

Document that callers serialize sleep, wake, pause and resume operations, including across clients. This is the standalone split requested by @aoshen02 in https://github.com/aoshen02/vllm/pull/185, extracted from #58183.

## Claims

- Explain that `sleep(mode="wait")` completes after draining and worker sleep, while EngineCore can still process other control messages during the drain.
- State that overlapping control requests are unsupported and a client timeout does not establish the operation's outcome.
- Cover successful sleep completion and immediate/deferred worker failures using the existing engine test fixture.

## Validation

On standalone main `06e172b5cf8845c80c40a6eaaecbcbde3e38e8df` plus this change: **25 selected engine tests passed**. Applicable pre-commit checks, including mypy, passed.

`.venv/bin/python -m pytest tests/v1/engine/test_engine_core.py -k "checkpoint or pause or sleep or kv_cache_release or wake_up or reject" -q -rs`

This documents existing behavior; it does not add runtime serialization or claim a before/after behavior fix. No new GPU benchmark was needed.

### Earlier integration evidence and contract correction from #58183

The combined revision `a2472393067b4e04e83cdb7bc3f93aa52c8a67fa` passed real HTTP request-draining, partial-wake and matching post-wake-output scenarios with insecure serialization disabled. The original report also recorded rejection of overlapping management transitions in that revision. That is historical behavior of the combined implementation; it is **not** a guarantee provided by this documentation-only control contract. This split requires callers to serialize operations, including across clients.

The later combined revision `c9171d7ad9eedd77d7633d5cdb0355018ff9b29a` passed 5 opt-in H20 GPU regression configurations (TP1/2/4 peer-to-peer and TP2/4 forced shared memory, three cycles each with Qwen3-0.6B), covering both partial-wake orders and repeated sleep. Those runs provide integration context for the documented call sequence, not evidence that concurrent control requests are now serialized internally.

The current branch's three targeted regression cases check successful drain-and-sleep completion, immediate worker failure and deferred worker failure in the existing engine fixture; together with the selected regressions, **25 tests passed**. Historical GPU scenarios from [#58183](https://github.com/vllm-project/vllm/pull/58183) were not rerun for this documentation/test split.

## Details

The change is limited to `docs/features/sleep_mode.md`, the `EngineCore.sleep()` docstring/comment, and three existing-fixture regression cases. Related to #48311; CUDA checkpointing remains a separate change.
