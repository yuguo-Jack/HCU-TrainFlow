# [ROCm][Perf] Triton port of the fused GDN MTP decode kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/61855) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->
## Overview

GDN layers with the flat qkvz layout (Qwen3.5 family) fall back to the unfused speculative-decode path on ROCm because `fused_gdn_decode_post_conv_mtp` (#51674) only builds for CUDA. This adds a Triton port with the same signature and uses it on ROCm: a state-update kernel tiled over the value dimension like `fused_sigmoid_gating_delta_rule_update` (tile size chosen from the grid size) plus a small gated-RMSNorm epilogue. It covers every model built on `QwenGatedDeltaNetAttention` with the flat layout: the Qwen3.5 family, Qwen3.8-27B and Qwen3.8-Flash-Next (table below). Qwen3-Next (interleaved layout) stays ineligible, as on CUDA.

## Claims

- Qwen3.5-35B-A3B, MTP k=3, 1x MI350X, one request at a time: decode 2.39 -> 2.08 ms/token (-13%), E2E 544 -> 488 ms (-10%), on vLLM main (nightly `77154ca`) with aiter main. The first version of this PR (one program per value head, no V tiling) gave 2.19 ms/token in the same side-by-side run.
- Per decode step on MI350X: copy/fill/cat kernels 1.56 -> 0.31 ms, kernel launches 1008 -> 768, GPU kernel time 7.74 -> 6.71 ms.
- Faster at higher concurrency too: per-step time (median ITL) -12% at 1, -6% at 8 and -6% at 32 concurrent requests, output throughput +14% / +16% / +10% (`vllm bench serve`, 2K/256).
- Numerics match the unfused path: the existing MTP kernel test, parametrized over CUDA op / Triton port, passes for the Triton port on MI350X and MI300X (22/22 each); states are bit-identical to the first version at every tile size, and outputs are too or differ only in the rounding of the norm's sum; MTP acceptance unchanged (2.85-2.87 accepted tokens per step).
- Accuracy unchanged: GPQA Diamond 0.821 (main) vs 0.826 (this PR), needle-in-a-haystack 100% for both at 4K-64K tokens.
- Long context (64K in / 1K out): decode step (median ITL) -12% / -6% / -3% at 1 / 8 / 32 concurrent requests; prefill unchanged.
- MI300X (gfx942): per call, 49-60% faster than the unfused path at 1 request and 25-44% at 32 (table below).
- GSM8K unchanged within run-to-run variation (base 0.854-0.861 over 4 runs, this PR 0.848-0.862 over 3 runs), above the 0.84 threshold in `tests/evals/gsm8k/configs/Qwen3.5-35B-A3B-DEP2.yaml`.
- CUDA unchanged: the CUDA op is still used wherever it is built.

## Details

Models that take the fused path on ROCm with this change (eligibility is unchanged from the CUDA op: flat qkvz layout, K = V = 128, value/key head ratio 1/2/3/4/8, BF16 activations, at most 8 tokens per verify):

| Model | vLLM model code | GDN K/V heads (ratio) | GDN layers | Validated |
|---|---|---|---|---|
| Qwen3.5-397B-A17B | `qwen3_5.py` | 16/64 (4) | 45 | kernel test |
| Qwen3.5-122B-A10B | `qwen3_5.py` | 16/64 (4) | 36 | kernel test |
| Qwen3.5-35B-A3B | `qwen3_5.py` | 16/32 (2) | 30 | end to end (this PR) |
| Qwen3.5-27B / 9B / 2B | `qwen3_5.py` | 16/48 (3) / 16/32 (2) / 16/16 (1) | 48 / 24 / 18 | kernel test |
| Qwen3.8-27B | `qwen3_5.py` (`Qwen3_5ForConditionalGeneration`) | 16/48 (3) | 48 | kernel test |
| Qwen3.8-Flash-Next (incl. FP8) | `vllm/models/qwen4_exp` (same GDN layer, flat layout) | 16/48 (3) | 36 | kernel test |
| Qwen3-Next-80B-A3B | `qwen3_next.py` (interleaved layout) | 16/32 (2) | - | not eligible (unchanged) |


- **Root cause.** On ROCm the layer logs `Falling back to the Triton GDN spec decode path: torch.ops._C.fused_gdn_decode_post_conv_mtp is not built`. The AITER fused GDN path only covers non-speculative decode, so every GDN layer's verify step runs ~8 small kernels around the recurrent kernel: contiguous copies of `a`/`b`, three copies plus a `cat` to unpack q/k/v, a zero-fill, an output copy, and the gated RMSNorm.
- **Kernels.** Two launches. The update kernel runs one program per (request, value head, tile of the value dimension). It reads q/k/v and `a`/`b` in place from the projections and runs the gated delta-rule update over the request's tokens with the same state reads and writes as `fused_sigmoid_gating_delta_rule_update`: start from the state at the last accepted token, store the state after every token, slot index <= 0 means no state. Each tile writes its rows of the output and their sum of squares per token. The epilogue, one program per (request, value head, token), adds the partial sums and applies the gated RMSNorm, the only step that needs the whole value dimension, then writes the `out_proj` input. Recurrent state layout is `[slot, HV, V, K]`, BF16 or FP32.
- **Tile size.** 32 rows per program while there are fewer (request, value head) pairs than CUs, 64 up to 4x the CUs, else one tile per value head. A sweep of 32/64/128 rows on MI300X and MI350X (both head shapes, both state dtypes, 1-32 requests) put this rule within 8% of the best tile size everywhere; a fixed 32 was up to 36% slower at 16-32 requests on MI300X.
- **Wiring.** Same keyword signature as the CUDA op; the layer picks the Triton port on ROCm. `forward_hip` routes speculative-decode configs to the packed fused-norm path (`forward_cuda`); non-speculative ROCm decode keeps the AITER path. Opt out with the existing `VLLM_GDN_DECODE_KERNEL=triton`.
- **Per call.** Qwen3.5-35B-A3B shape (16/32 K/V heads), 4 tokens per request, CUDA-graph replay, current ROCm nightly image; "first version" is this PR before the review (one program per value head):

  | GPU | State | Requests | unfused | first version | this PR |
  |---|---|---|---|---|---|
  | MI350X | FP32 | 1 | 30.0 us | 18.7 us | 11.5 us |
  | MI350X | FP32 | 8 | 46.7 us | 26.8 us | 21.8 us |
  | MI350X | FP32 | 32 | 91.4 us | 71.9 us | 64.3 us |
  | MI350X | BF16 | 1 | 28.3 us | 12.5 us | 10.2 us |
  | MI350X | BF16 | 32 | 68.1 us | 36.5 us | 39.6 us |
  | MI300X | FP32 | 1 | 30.2 us | 21.7 us | 13.3 us |
  | MI300X | FP32 | 8 | 56.7 us | 38.5 us | 33.3 us |
  | MI300X | FP32 | 32 | 145.7 us | 96.8 us | 88.8 us |
  | MI300X | BF16 | 1 | 28.5 us | 16.3 us | 11.3 us |
  | MI300X | BF16 | 32 | 117.0 us | 66.5 us | 65.2 us |

  With FP32 state, the Qwen3.5 and Qwen3.8 default (`mamba_ssm_dtype: float32`), this PR is faster than the first version at every batch size on both GPUs. With BF16 state at 32 requests on MI350X it is 8-9% slower than the first version (one tile per head plus the epilogue launch), still well ahead of the unfused path. The 16/48 head shape behaves the same way.
- **Coverage.** End to end this was run on Qwen3.5-35B-A3B only. The other models in the table are covered by the kernel test, which runs every eligible head ratio (1/2/3/4/8) at TP 1-16, but were not run end to end.
- **CI.** The parametrized test runs the Triton port on any GPU (NVIDIA too), so existing CUDA CI covers its numerics; AMD CI covers the ROCm path where it runs `tests/kernels/fla`.
- **Related open PRs (not duplicates).**
  - #61675 adds an opt-in (`VLLM_ROCM_QWEN_MTP_GDN`), shape-specialized ROCm kernel that also fuses the conv. It accepts only 16/48 K/V heads (Qwen3.8-27B), TP=1 and verify widths up to 4, and raises for any other shape, including Qwen3.5-35B-A3B (16/32). This PR makes the default ROCm path fused under the same contract and eligibility as the upstream CUDA op (head ratios 1/2/3/4/8, any TP, up to 8 tokens). The two can coexist, with #61675 taking over when it is enabled.
  - #61434 defers state stores inside the unfused Triton spec-decode kernel (FP32 state, `mamba_cache_mode="none"`). On ROCm this PR replaces that path whenever the fused path is eligible; the deferred-store idea could be applied to this kernel in a follow-up.
  - #59366 adds a separate CUDA replay op for RecoverSSM and leaves the op ported here unchanged.
  - #60833 / #61325 (Qwen3.8 mono decode on MI355X) run vLLM's GDN core for verify steps, so this change applies there too.
- **Provenance.** The first version of the kernel was written and validated in Meta's internal vLLM fork; the V tiling was added in this PR after review.
- **AI assistance.** Drafted with Claude Code (port, V tiling and tile-size rule after review, test parametrization, benchmarks); reviewed and run by the submitter.
