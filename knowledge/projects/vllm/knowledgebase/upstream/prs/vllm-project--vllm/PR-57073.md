# [MoE] Integrate FlashInfer CFT counted-write MoE all-to-all (issue #57069)

[Upstream PR](https://github.com/vllm-project/vllm/pull/57073) · state: open · merged: False

## Original PR description

## Summary

This PR adds vLLM-side scaffolding to integrate the CFT (Compute Fabric Transport) counted-write MoE all-to-all kernel through the FlashInfer backend, addressing [#57069](https://github.com/vllm-project/vllm/issues/57069).

The CFT path uses CUDA Logical Endpoints and `fabric.try_put.counted` operations to write directly into peer receive buffers over the NVLink fabric. A counted write atomically increments a destination-side counter by the number of bytes delivered; the receiver polls that counter rather than a separate fence-and-flag handshake, reducing NVLink round-trips on latency-sensitive workloads.

**This PR is not duplicating existing work** — no open PR addresses issue #57069 or the `flashinfer_cft_counted_write` backend. Existing backends (`flashinfer_nvlink_one_sided`, `flashinfer_nvlink_two_sided`) use different transport mechanisms and the CFT counted-write path is a new kernel class from TRT-LLM.

## Changes

- **`vllm/config/parallel.py`**: adds `"flashinfer_cft_counted_write"` to `All2AllBackend`, extends `use_sequence_parallel_moe`, and documents `sm_100+`/CUDA 13.4+/NVLink prerequisites.
- **`vllm/utils/flashinfer.py`**: adds `has_flashinfer_cft_counted_write()` which gate-checks `flashinfer.comm.cft_alltoall`, `sm_100+` capability, and CUDA >= 13.4.
- **`vllm/distributed/device_communicators/all2all.py`**: adds `FlashInferCFTCountedWriteManager` mirroring the one-sided manager, with conditional imports from `flashinfer.comm.cft_alltoall`.
- **`vllm/distributed/device_communicators/cuda_communicator.py`**: wires the new backend name to `FlashInferCFTCountedWriteManager`.
- **`vllm/model_executor/layers/fused_moe/prepare_finalize/flashinfer_cft_counted_write.py`**: new `FlashInferCFTCountedWritePrepareAndFinalize` class.
- **`vllm/model_executor/layers/fused_moe/config.py`**: adds `use_fi_cft_counted_write_kernels` property to both `FusedMoEParallelConfig` and `FusedMoEConfig`.
- **`vllm/model_executor/layers/fused_moe/all2all_utils.py`**: imports and dispatches to `FlashInferCFTCountedWritePrepareAndFinalize`.
- **`tests/distributed/test_mnnvl_alltoall.py`**: adds `test_cft_manager_lifecycle` and `test_cft_dispatch_combine`, skipped on systems without `sm_100+`/CUDA 13.4+/NVLink fabric.

## Prerequisites / fallback behavior

The `flashinfer_cft_counted_write` backend requires:
- `flashinfer.comm.cft_alltoall` module (FlashInfer CFT support — upstream integration tracked in [flashinfer-ai/flashinfer](https://github.com/flashinfer-ai/flashinfer))
- sm_100+ (Blackwell) hardware
- CUDA 13.4+
- A compatible NVLink fabric environment

`has_flashinfer_cft_counted_write()` returns `False` on any system that does not meet these requirements, so existing behavior is completely unchanged unless the user explicitly selects `--all2all-backend flashinfer_cft_counted_write`.
