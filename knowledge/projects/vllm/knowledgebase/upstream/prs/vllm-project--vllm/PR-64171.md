# [Bugfix] Make Counter.reset() restore the start value

[Upstream PR](https://github.com/vllm-project/vllm/pull/64171) · state: open · merged: False

## Original PR description

## Purpose

`Counter(start=N).reset()` in `vllm/utils/counter.py` resets the counter to `0` instead of `N`, so a counter built with a non-zero start loses its offset after a reset. The fix stores `start` and resets to it. The default `start=0` behaves exactly as before, so existing callers (`LLM`, offline entrypoints) are unaffected.

`vllm/utils/counter.py` had no tests, so I added `tests/utils_/test_counter.py`:
- `test_counter_reset_restores_start`: reproduces the bug (fails on main, passes with this change)
- `test_atomic_counter_concurrent_inc_dec`: checks that `AtomicCounter` stays consistent under concurrent `inc`/`dec` across 8 threads, which is the reason it holds a lock

Thanks for taking a look, @njhill.
