# [Benchmark] Add SLO attainment and output-token goodput reporting

[Upstream PR](https://github.com/vllm-project/vllm/pull/60482) · state: open · merged: False

## Original PR description



## Overview

Add per-objective and combined SLO attainment plus output-token goodput to generation benchmarks using `vllm bench serve --goodput`. Save the configured thresholds with units in the standard JSON results. Fixes #60414.

## Claims

- Report passing counts and percentages for configured TTFT, TPOT, and E2EL objectives and their intersection. All measured requests, including failures, form the attainment denominator; warmups, readiness checks, and probes are excluded.
- Report output tokens/second from requests satisfying every configured objective. If a qualifying request lacks a usable server count and tokenizer fallback, report `null`/`N/A` rather than counting the placeholder token.
- Preserve existing request-goodput values, inclusive thresholds, and the TPOT convention for outputs of at most one token. Add documentation and fields only to generation reporting with `--goodput`.

Additional local validation:

- Two subprocess runs of `python -m vllm.entrypoints.cli.main bench serve` against a synthetic completions server, with server usage counts and with counts omitted. Each run used three measured requests (two successes and one failure), two warmups, all three SLOs, `--skip-tokenizer-init`, and `--save-result`. Verified attempted/completed/passing counts, saved thresholds, request goodput, and output-token goodput or `null`. The server bundled multiple tokens into one streamed chunk.
- Compared every existing `BenchmarkMetrics` field and output-length list against upstream `947dd62c07` for 800 deterministic cases covering all eight objective subsets, failures, and missing/single/multiple output-token counts: all unchanged.
- A broader run including `test_responses_request_func.py` produced 66 passes and one failure in `test_request_payload_is_accepted_by_the_server_schema` (`KeyError: 'x-request-id'`). The same failure reproduces on an untouched archive of upstream `947dd62c07` with the same environment; neither the test nor its request implementation is changed here.

No GPU inference or model evaluation was run. This change only calculates and reports client-side results after the measured run; it does not change inference, scheduling, request payloads, or generated model outputs. The existing Buildkite benchmark suite discovers the new tests.

## Details

New standard JSON fields are `attempted`, `goodput_thresholds_ms`, `slo_passed`, `slo_attainment_pct`, `slo_attainment_by_metric`, and `output_token_goodput`. Existing `completed`, `failed`, and `request_goodput` fields retain their meanings. The `_ms` suffix records threshold units (ms/token for TPOT). These names and the all-attempted denominator follow the issue proposal and remain open to maintainer feedback.

Token accounting reuses server counts or the existing tokenizer fallback. Retokenization can differ from server tokenization. Zero server counts retain the existing missing-count treatment; unknown counts on nonqualifying requests do not invalidate token goodput. No passing requests yields zero goodput; no measured requests yields null attainment percentages. Nonpositive benchmark durations now raise a descriptive `ValueError` instead of dividing by zero.

Duplicate checks: issue #60414 has no maintainer comments, and searches for open PRs referencing `60414 in:body` or `goodput` found no equivalent reporting change. Related issue #24555 requested token goodput and is closed. Open PR #59032 addresses serialization/pooling omissions; this PR adds attainment and qualifying-token accounting.
