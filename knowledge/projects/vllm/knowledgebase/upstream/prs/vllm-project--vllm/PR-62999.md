# [Bugfix][Spec Decode] Don't apply target LoRA to shared drafter embedding

[Upstream PR](https://github.com/vllm-project/vllm/pull/62999) · state: closed · merged: False

## Original PR description

## Purpose

With LoRA enabled, the V1 drafter shares the target's LoRA-wrapped `embed_tokens`. Draft steps after the first embed one token per request against punica metadata built for the target step, so `num_speculative_tokens >= 2` with LoRA requests hits a CUDA illegal memory access. Share the base embedding instead, as MRV2 already does in `maybe_share_target_embed`.

## Test Result

Qwen3.5-0.8B, MTP `num_speculative_tokens=2`, random MLP LoRA, base and LoRA requests in one batch, `PYTORCH_NO_CUDA_MEMORY_CACHING=1`, H200: illegal memory access in the draft step's `embed_input_ids` before the fix; passes after.

No open PR covers this. AI assistance (Claude Code) was used.
