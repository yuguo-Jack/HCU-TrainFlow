# [Bugfix][KV Connector] Replace HF3FS block table on MRV1 resume

[Upstream PR](https://github.com/vllm-project/vllm/pull/61247) · state: open · merged: False

## Original PR description



## Overview

Replace HF3FS's retained physical block table when an MRV1 request resumes from preemption. This applies the scheduler contract already used by MooncakeStore in #46595.

## Claims

- A resumed `CachedRequestData` table replaces the freed placement rather than being appended to it.
- An ordinary cached request still appends its allocation delta.
- Logical token history and the saved-content cursor are preserved in the cached-request path.

## Details

The scheduler marks a cached request as resumed when `new_block_ids` contains its complete replacement table. HF3FS keeps scheduling state across preemption but previously appended that table to its old, freed physical IDs. Subsequent saves select physical sources positionally, leaving logical positions and physical placement inconsistent.

The change passes `resumed_req_ids` into the existing private update and replaces only the physical IDs. It adds 15 production lines across two connector-local files, no public API and no device synchronization. MRV2 resumes use `NewRequestData`; HF3FS's existing initializer already replaces their physical table. This patch targets the still-supported MRV1 cached-request representation, not a new MRV1 feature or complete source-lifetime protection.
