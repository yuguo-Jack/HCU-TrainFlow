# [Perf][MiniMax-M3] Two-shot fused MoE finalize + all-reduce + norm + MXFP8 up to 512 tokens

> **Depends on #65433**. This branch contains its 5 commits; this PR's own change is the last 3 commits. Base: `main` 9a56d4fec6.

## Overview

This extends MiniMax-M3's existing fused MoE finalize (`FUSED_MOE_FINALIZE_MAX_TOKENS`: 32 on `main`, 128 after the PR above) to decode steps of up to 512 tokens with a two-shot all-reduce.

On NVIDIA (SM100 family, TP without EP, NVLink multicast), MiniMax-M3 leaves a decode step's MoE top-k finalize to the next layer's input norm. A fused kernel pair there does the finalize + shared-expert add + TP all-reduce + Gemma RMSNorm + MXFP8 quantization of the `qkv_proj` input. Its all-reduce is one-shot multicast: every rank multicasts all of its rows and reduces every token. Per-rank NVLink traffic and local mailbox reads therefore grow as 6·m·hidden bytes, so the fused path lost to the regular tail above 128 tokens.

Above 64 tokens this PR switches to the two-shot (BT) all-reduce that #63921 added to DeepSeek-V4.1's `AllReduceMHC`, reusing its kernels rather than adding a second two-shot mode. There are three PDL-chained kernels:

1. The finalize publish is `_QuadFinalizePublishDeviceKernel` with `owner_capacity`. It sends each token's TP-partial row only to the token's owner rank (`t % tp`). This is a unicast store into the owner's `[generations, tp, ceil(m/tp), hidden]` Lamport mailbox, addressed through a device table of the ranks' mailbox addresses, which is built the same way `AllReduceMHC` builds its table.
2. The owner reduce is `_OwnerReduceMulticastDeviceKernel`. On each owner rank it sums the ranks' rows in rank order in FP32, rounds to BF16 and multicasts the sum into every rank's `[generations, m, hidden]` reduced mailbox. The one change to DSV4.1's code is here: the kernel now takes an optional `residual` and adds it to the FP32 sum before rounding, as FlashInfer's BT kernel does. The argument defaults to `None`, so `AllReduceMHC` compiles and launches the kernel as before.
3. MiniMax's existing consumer reads the reduced mailbox in a new `reduced_input` mode (one source row, no residual add, no generation advance), the counterpart of the mHC consumer's `reduced_input`. It then runs the residual store, Gemma RMSNorm and MXFP8 quantization.

MiniMax needs the residual in the owner reduce for bitwise identity. Its one-shot consumer adds the residual to the FP32 rank sum before the single rounding to BF16. If the owner rounded the sum first and the consumer then added the residual, two-shot outputs would differ from one-shot outputs.

Each kernel spins only on stores of kernels that ran before it, on its own GPU or another, never on a CTA of its own grid. Liveness therefore does not depend on grid size, CTA dispatch order or occupancy. Per-rank NVLink ingress drops from about 6·m·hidden bytes to about 3·m·hidden bytes.

The model now uses one-shot up to 64 tokens and two-shot from 65 to 512 tokens. Above TP4 the one-shot cutoff shrinks as the previous PR's cap does: `min(64, 256 // tp)`. `FUSED_MOE_FINALIZE_MAX_TOKENS` goes from 128 to 512, which covers decode steps of up to 64 requests with 7 speculative tokens. The two-shot publish keeps MiniMax's 4-element fragments: 8-element fragments, as DSV4.1's BT uses, were 0.6 µs faster at 512 tokens but slower below 8 tokens in the same benchmark.

## Claims

- **Kernel** (GB300, 4 ranks, CUDA-graph timed, µs per call, hidden 6144, top-k 4; on `main` 9a56d4fec6's nightly build):

  | tokens | one-shot | two-shot | regular AR+norm+MXFP8 quant (MoE finalize and shared add not included) |
  |---|---|---|---|
  | 32 | 6.34 | 6.60 | 9.47 |
  | 64 | 8.61 | 7.60 | 9.06 |
  | 128 | 13.18 | 9.73 | 10.27 |
  | 192 | 17.74 | 11.91 | 11.59 |
  | 256 | 23.05 | 15.06 | 14.05 |
  | 512 | 40.78 | 24.75 | 25.27 |

  The regular tail also runs the MoE finalize (about 5–8 µs) and the shared add (2–3 µs), which the fused kernels include. Built on `main`'s BT kernels, the two-shot path takes the same time as this PR's previous, separate kernels: 9.75 / 15.06 / 25.70 µs at 128 / 256 / 512 tokens in the same run.
- **Identical outputs:** two-shot equals one-shot bitwise (MXFP8 codes, scales and the BF16 residual) at 13 batch sizes from 1 to 512, on all ranks. The benchmark op uses `one_shot_max_tokens=1`, so every size above 1 is two-shot. (`one_shot_max_tokens=0`, every size two-shot, was checked before the rework only.) The one exception is a sum that is exactly −0.0: the Lamport protocol reserves −0.0 as its empty marker, so the residual stores +0.0 there.
- **End to end:** −1.6% decode step period at concurrency 32 (256 tokens per step) and −2.7% at concurrency 64 (512) against the previous PR, measured before the rework. After the rework, the per-layer MoE tail is equal or lower than before; see Validation.
- **Memory:** about 9.4 MB for the one-shot mailbox (64 tokens), 18.9 MB for the two-shot owner mailbox and 18.9 MB for the reduced mailbox, all symmetric memory per GPU, for hidden 6144 at TP4.

## Details

- `vllm/models/minimax_m3/nvidia/ops/finalize_allreduce_norm.py`: the two-shot path, built from DSV4.1's BT publish and owner-reduce kernels; the owner mailbox, its address table and the reduced mailbox; the consumer's `reduced_input` mode; and `one_shot_max_tokens` (`None`: one-shot only; `0`: every batch two-shot).
- `vllm/models/deepseek_v41/nvidia/ops/cute_dsl/all_reduce_mhc.py`: `_OwnerReduceMulticastDeviceKernel` takes an optional `residual`. Without it, as in `AllReduceMHC`, nothing changes.
- `vllm/models/minimax_m3/nvidia/model.py`: cap 512 and the one-shot cutoff `fused_moe_finalize_one_shot_max_tokens(tp_size)`.
- The post-attention all-reduce is not touched; it still uses FlashInfer above 32 tokens.
- **Related:** NVIDIA's InferenceX MiniMax-M3.1 work also tried a 64-token fused-finalize cap; with two-shot, 64 tokens is where this PR switches from one-shot to two-shot rather than where fusion stops. #64957 adds a general compile-time MoE finalize + all-reduce + RMSNorm fusion pass; this PR only changes MiniMax-M3's existing model-level fusion.
