# [Bugfix][Spec Decode] Resolve communication for draft MoE overrides

[Upstream PR](https://github.com/vllm-project/vllm/pull/63875) · state: open · merged: False

## Original PR description

## Overview

Fix explicit draft `moe_backend` overrides when the target uses a self-dispatching FlashInfer MoE backend. Resolve the draft's communication setting together with its backend, before validating the derived config.

## Claims

- A regular draft backend no longer inherits the target's inferred `all2all_backend='passthrough'`, which previously prevented MTP model loading.
- The target configuration and unrelated explicitly selected communication backends remain unchanged.

## Validation

GB200 validation of the retained tests: 4 cases passed, including the public LLM/MTP regression. All targeted pre-commit checks pass.

The public LLM regression reproduces the base validation failure:

Final full test file: **8 passed** in 47.25 s on one GB200. On the base commit, the new constructor and public LLM regressions fail with the validation error above; the three neighboring constructor cases pass (2 failed, 3 passed, 3 deselected in 10.25 s). All pre-commit hooks pass, including mypy.

A public `LLM` regression uses a tiny local MiMo model, MTP with two draft tokens, target `flashinfer_moe_ep_cutedsl` configuration and draft `flashinfer_trtllm`. On one GB200 GPU it loads and generates four valid tokens after the fix. This is a config/startup regression: the tiny model is dense and uses dummy weights, so it makes no claim about MegaMoE kernels, multi-GPU communication, or model quality. The user-visible failure occurs during draft config validation, before such kernels can run.

## Details

`KernelConfig` resolves the target's default all-to-all setting to internal `passthrough` when its MoE backend owns dispatch/combine. Draft overrides previously replaced only the kernel sub-config, validating it while the inherited parallel sub-config still contained `passthrough`. A regular draft backend rejects that invalid combination.

When an explicit override switches away from a self-dispatching backend, rebuild the draft parallel config with the regular default `allgather_reducescatter`, then apply all sub-config replacements atomically. Unset overrides, compatible self-dispatching drafts, and existing explicit communication settings keep their prior behavior. No serving model-runner or communication-kernel code changes.

Duplicate checks searched open PRs for `"apply_draft_overrides"`, `"draft" "all2all_backend"`, and `"draft" "passthrough"`. [#58332](https://github.com/vllm-project/vllm/pull/58332) changes config hashing, [#54109](https://github.com/vllm-project/vllm/pull/54109) adds a DeepEP activation format, and [#43319](https://github.com/vllm-project/vllm/pull/43319) handles DeepSeek draft checkpoint quantization. None resolves inherited internal communication during draft overrides. The finding came from local GLM PCP/MTP experiments; it has no linked GitHub issue. This change does not expand PCP/speculation support or overlap with PCP capture fixes.
