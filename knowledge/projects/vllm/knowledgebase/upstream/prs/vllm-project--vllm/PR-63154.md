# [Bugfix][MRV2] Release the warmup memory cached on the capture streams

[Upstream PR](https://github.com/vllm-project/vllm/pull/63154) · state: closed · merged: True

## Original PR description



## Overview

Empty the caching allocator once at the end of the Model Runner V2 `capture_model()`, before it reads free memory, so that warmup activations cached on the discarded capture streams are released. Fixes #63052.

## Claims

- With breakable CUDA graphs and no FULL graphs (`cudagraph_mode=PIECEWISE`), the largest warmup's activations stay reserved on the capture stream for the life of the process and are reported as CUDA graph memory. On DeepSeek-V4.1-Flash prefill (GB200, DP4) that is 10.49 GiB per rank; this PR releases it.
- Modes with FULL graphs already end in this state, because `torch.cuda.graph()` empties the cache before each FULL capture.
- 3 lines; graph pools and allocated memory are unchanged.

## Validation

GB200, DeepSeek-V4.1-Flash prefill, DP4, `max_model_len` 1M, breakable graphs with capture sizes up to 16384 tokens, v0.32.0-based build. Per rank, at the end of `capture_model()`, with the default-pool segments of `torch.cuda.memory._snapshot()` grouped by stream:

| | `PIECEWISE` (`main`) | `PIECEWISE` + `empty_cache()` at the end | `FULL_AND_PIECEWISE` (`main`) |
|---|---|---|---|
| model capture stream: reserved (in use) | 7.93 (1.77) GiB | 2.43 (1.77) GiB | 2.43 (1.77) GiB |
| replay capture stream: reserved (in use) | 6.65 (1.65) GiB | 1.70 (1.65) GiB | 1.70 (1.65) GiB |
| graph capture memory (free-memory delta) | 26.39 GiB | 15.90 GiB | 21.00 GiB |
| `memory_allocated()` at the end | 119.12 GiB | 119.12 GiB | 119.16 GiB |

- The first two columns differ by 10.49 GiB per rank, all of it cached warmup memory. The graph pools (5.63 + 5.18 GiB), the allocated memory, and a smoke test are the same in both.
- The middle column comes from a diagnostic run that calls `empty_cache()` at the same point, after taking the snapshot above. This exact commit has not been run on a GPU.
- `FULL_AND_PIECEWISE` also captures 44 FULL decode graphs and 39 FULL DSpark graphs, so its total is higher; its capture streams end up in the same state as the middle column.

No test is added: the effect needs a breakable PIECEWISE capture whose warmup is large enough to matter, and CI has no runner for that configuration.

## Details

**Root cause.**

1. `capture_model()` empties the cache once before capturing, and reads free memory at the end without emptying it again.
2. Each `CudaGraphManager.capture()` enters `graph_capture()`, which creates a new stream, and runs every size eagerly once before capturing it. The caching allocator keeps the freed warmup blocks on that stream. Sizes are captured largest first, so the cache ends up holding the largest warmup's peak, and nothing allocates on that stream afterwards.
3. `capture_model()` runs under `freeze_gc_for_cudagraph_capture()`. While gc is frozen, breakable capture skips its per-descriptor `gc.collect()` + `empty_cache()` (#54646).
4. With FULL graphs, `torch.cuda.graph.__enter__` empties the cache before each FULL capture and releases these blocks as a side effect. With PIECEWISE only, nothing does.

The blocks are released only when some caching-allocator allocation fails and the allocator frees all cached blocks to retry. Allocations outside the caching allocator (NCCL, NVSHMEM, CUDA module loading) see the memory as used.

**KV budget.** `profile_cudagraph_memory()` measures `capture_model(profile_only=True)`, so the CUDA graph estimate subtracted from the KV budget also includes these blocks today; with this change it no longer does (from reading the code; the KV cache size was not measured). This complements #59368, which measures the graph pool for the estimate: with #59368 alone, the estimate would exclude this cache while the real capture still holds it.

**Tradeoff.** As noted in #50780, on a model whose profile run under-counts long-prefill activations, these cached blocks acted as reclaimable headroom. With this change that memory goes to the KV cache instead, which is the state `FULL_AND_PIECEWISE` already ends in.

Related: #62965 (the decoder replay graphs' separate stream and pool).
