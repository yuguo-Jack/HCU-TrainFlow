# [ROCm] Support DeepSeek-V4 hash routing in AITER Triton W4A16 MoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/60282) · state: closed · merged: True

## Original PR description

## Purpose

#57867 rejects monolithic MoE kernels for hash-routed models, which disables the AITER Triton W4A16 backend for DeepSeek-V4. This adds a `_supports_hash_routing()` capability (default `False`), threads `input_ids`/`hash_indices_table` through `apply_monolithic`, and routes hash layers in `AiterW4A16ExpertsMonolithic` with aiter `routing_from_hash` (available in the pinned v0.1.24.post1).

Not a duplicate: #57478 only fuses the non-hash router gate. #58800 adds the same `_supports_hash_routing()` hook for its gfx1250-only W4A4 expert; this PR covers W4A16 (gfx950). Whichever lands second drops the shared `modular_kernel.py` hunk.
