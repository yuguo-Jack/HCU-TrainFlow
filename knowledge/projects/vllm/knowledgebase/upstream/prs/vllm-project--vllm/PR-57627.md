# [Perf][DSv4.1] Stack DSpark context KV projections

[Upstream PR](https://github.com/vllm-project/vllm/pull/57627) · state: closed · merged: False

## Original PR description

## Purpose

On DeepSeek-V4.1, the DSpark drafter's `precompute_and_store_context_kv` projects the same context hidden states once per draft layer through each layer's fused `wq_a|wkv` projection and discards the Q half every time — 3 activation quantizations + 3 Q+KV GEMMs per step, with ~70% of the GEMM output columns (the Q half) dead. This eager path sits on the bs=1 spec-decode host critical path: a torch-profiler trace shows ~352 µs of host time per `vllm::mm_mxfp8` wrapper call for ~8.5 µs of GPU work.

## Change

Stack the draft layers' KV projections into one existing `MergedColumnParallelLinear` (+32/−6 in `vllm/models/deepseek_v41/nvidia/dspark.py`):

- Each checkpoint `mtp.*.attn.wkv.{weight,scale}` now additionally loads into the corresponding shard of `model.context_wkv_proj`; the per-layer `fused_wqa_wkv` still receives its own copy because the draft layers' attention forward continues to use it.
- The step does one activation quantization + one KV-only GEMM over the stacked weight, then per-layer norm / RoPE / cache insert are unchanged.
- No new kernel and no private ABI: it reuses the existing FlashInfer cute-dsl MXFP8 backend and the merged-linear loader.

Trade-off: the stacked replica adds ~7.73 MiB per TP rank (K=5120, 3×512 KV rows, native MXFP8). Configs whose checkpoint scale layout is not 128-row-concatenable, or checkpoints with more draft layers than shards, fail loudly at load time in the merged-linear weight loader, not silently.

Not a duplicate: #54674 (merged) did the same restructuring for V4 (`deepseek_v4`); this PR is the V4.1/MXFP8 port, which #55654 explicitly does not cover (V4-only, and it changes insert/norm rather than the projection). Dup checks on 2026-09-18: `context_wkv_proj` (0 open PRs), `KV-only`, `dspark context`, `deepseek v4.1 projection` — nothing else covers the V4.1 context projection. Independent of #57122 and of the input-prep fusion work.
