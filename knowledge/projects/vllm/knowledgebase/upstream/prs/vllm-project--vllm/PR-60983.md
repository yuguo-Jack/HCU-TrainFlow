# [Docs] Clarify Mistral parallel tool call workaround in tool_calling.md

[Upstream PR](https://github.com/vllm-project/vllm/pull/60983) · state: open · merged: False

## Original PR description



## Overview

Clarify the Known issue for Mistral 7B parallel tool calls in `docs/features/tool_calling.md`. The current text describes the problem but does not point readers to the existing workaround, which is already documented under a separate issue in the same section.

## Claims

- The Known issue for Mistral 7B parallel tool calls now explicitly references `examples/tool_chat_template_mistral_parallel.jinja`, which was previously only described under issue 2 of the same section.
- No code changes; documentation-only.

## Validation

Verified with `mistralai/Mistral-7B-Instruct-v0.3` on vLLM `v0.31.1rc1.dev114+gb49c921a2` (A100-80GB).

Four test prompts, each requesting three tools (weather, forecast, air quality) with varying wording:

| Template | Returns all 3 tool_calls |
|----------|--------------------------|
| `tool_chat_template_mistral.jinja` (default) | 2/4 prompts |
| `tool_chat_template_mistral_parallel.jinja` | 4/4 prompts |

Steps to reproduce:

1. Start the server with the default template:
   ```bash
   vllm serve mistralai/Mistral-7B-Instruct-v0.3 \
     --tokenizer-mode mistral --load-format mistral --config-format mistral \
     --enable-auto-tool-choice --tool-call-parser mistral \
     --chat-template examples/tool_chat_template_mistral.jinja \
     --port 8000
   ```
2. Send each of the four prompts with `tool_choice="auto"` and count the returned `tool_calls`.
3. Restart the server with `--chat-template examples/tool_chat_template_mistral_parallel.jinja` and repeat.

## Details

The Known issue currently reads:

> Mistral 7B struggles to generate parallel tool calls correctly.

It describes the symptom but not the workaround. The `tool_chat_template_mistral_parallel.jinja` template, which addresses exactly this problem, is documented under issue 2 (about the Transformers tokenization backend). Readers who only scan issue 1 may not realize a fix already exists.

This PR adds a one-line reference from issue 1 to the existing template description. The change is intentionally minimal: it does not restructure the section, only links the problem statement to the already-documented solution.
