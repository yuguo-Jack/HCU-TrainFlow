# [Security] Reject unresolved multimodal inputs before execution

[Upstream PR](https://github.com/vllm-project/vllm/pull/62152) · state: open · merged: False

## Original PR description

## Overview

Reject multimodal requests whose encoder payload is missing before the model runner receives them. A cache-only input can reach the worker unresolved when the corresponding encoder output is absent, causing a request to terminate the engine.

## Claims

- Missing payloads without a matching local encoder output or external encoder cache item finish as request-scoped errors.
- Existing local encoder cache hits, external encoder cache hits, and fully cached prefix tokens remain eligible for scheduling.
- The check covers items later in a chunked prompt, before worker admission.

## Validation

- `VLLM_TARGET_DEVICE=cpu PYTHONPATH=. .venv/bin/python -m pytest tests/v1/core/test_scheduler.py -q --tb=short`: 224 passed.
- `VLLM_TARGET_DEVICE=cpu PYTHONPATH=. .venv/bin/python -m pytest tests/entrypoints/scale_out/token_in_token_out/test_mm_serde.py -q --tb=short`: 23 passed.
- `pre-commit run --files vllm/v1/core/sched/scheduler.py tests/v1/core/test_scheduler.py`: passed.
- Repository-wide pre-commit run found unrelated macOS failures in `mypy` (`mmap.MADV_HUGEPAGE`, `os.posix_fadvise`) and the non-root entrypoint wrapper (`/var` versus `/private/var` path comparison).
- GPU end-to-end validation on the reported `/render` to `/generate` reproducer: **pending maintainer CI run**. Serve `Qwen/Qwen2-VL-2B-Instruct` with `--enable-scale-out --mm-processor-cache-gb 0`, render a previously unseen base64 image with `return_mm_kwargs: false`, forward the render response to `/inference/v1/generate`, and confirm a request-scoped error while a subsequent valid request succeeds.

## Details

`/inference/v1/generate` accepts `features.kwargs_data: null`, which becomes a multimodal feature with `data=None`. Without a receiver-cache hit, the scheduler could admit the request while its encoder output was absent. Qwen's worker can inspect the unresolved feature during request admission, before its placeholder tokens are scheduled; other models can fail later when gathering embeddings. The scheduler now checks unresolved features before admission and again before scheduling encoder computation, then finishes only that request as an error.

This is not duplicate work. The merged layout validation in #51898 does not check for an unresolved encoder payload. The related open work in #60526 and #61656 addresses different cache or continuation paths; #57796 concerns combined feature inputs. The render change in #60728 can produce a null payload but does not reject it downstream.

The change adds no model output or accuracy behavior for valid requests. No model evaluation was run for malformed-input rejection.

Thanks @jperezdealgaba for picking this up. The guard covers the basic case but I don't think it closes the issue yet.                                                                                        

The cache hit paths (prefix cache, encoder cache, EC connector) still let a `data=None` item reach the worker. On M-RoPE models like Qwen2-VL, the worker reads `mm_feature.data` in `add_request` whatever the cache state is. Those paths therefore still take the engine down. Inline comments have the details.

The client also still gets a 500. I'd rather this come back as a 4xx or reuse the retryable `multimodal_cache_miss` error.
