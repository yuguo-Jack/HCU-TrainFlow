# [Security] Reject unresolved multimodal inputs before execution

[Upstream PR](https://github.com/vllm-project/vllm/pull/62152) · state: open · merged: False

## Original PR description

## Overview

Reject unresolved multimodal features before worker admission, including when
prefix, encoder, or external encoder caches are warm. Layout-only requests to
`/inference/v1/generate` return HTTP 400 before submission to the engine.

## Claims

- Validate every feature once in `EngineCore.preprocess_add_request`, after
  receiver-cache lookup; unresolved items raise `MultiModalCacheMissError`.
- Preserve valid receiver-cache hits and existing EC metadata inputs.
- Remove the scheduler guards, repeated cache queries, and zero-token returns.
- Return HTTP 400 for scale-out features with neither payload nor metadata,
  including streaming requests. Render with `mm_payload: "tensors"` to include
  the payload.

## Validation

- `VLLM_TARGET_DEVICE=cpu PYTHONPATH=. HF_HUB_OFFLINE=1 .venv/bin/python -m pytest tests/v1/core/test_scheduler.py tests/entrypoints/scale_out/token_in_token_out/test_generate_stream.py tests/entrypoints/scale_out/token_in_token_out/test_mm_serde.py -q --tb=short`: **307 passed**.
- Admission tests cover LLaVA and Qwen2-VL with cold cache, future chunk input,
  encoder hit, EC hit, prefix hit, and receiver hit. The Qwen encoder-hit test
  fails without the new guard because admission does not raise the typed error.
- HTTP tests exercise the actual FastAPI route with whole-field and per-item
  null payloads, both streaming and non-streaming.
- Changed-file pre-commit hooks and `git diff --check`: passed.
- Repository-wide pre-commit: unrelated macOS failures for Linux-only APIs in
  mypy and `/var` versus `/private/var` in the non-root entrypoint wrapper.
- GPU end-to-end: **pending**. Added
  `tests/entrypoints/scale_out/token_in_token_out/test_serving_multimodal_tokens.py::test_layout_only_features_return_bad_request_and_server_recovers`
  to the existing Buildkite entrypoints suite. It verifies layout-only render
  output receives HTTP 400 and subsequent rendering with tensors generates
  successfully on Qwen3-VL. This test has not been run locally.
- No model evaluation was run: successful-request model outputs and sampling
  are unchanged; the change rejects unresolved inputs.

## Details

Encoder outputs and cached prefix tokens do not supply the feature data used
by M-RoPE setup during worker admission. Allowing a null item through on those
cache hits still reaches model assertions. Receiver-cache resolution must run
first, then every unresolved feature must be rejected before scheduling.

The HTTP path now rejects layout-only features before calling the engine.
For direct engine callers, the guard reuses the existing typed cache-miss path.
General generation cache-miss recovery is handled separately in #61656; this
revision does not duplicate its output-processor or endpoint retry changes.
The explicit continuation contract in #60526 is separate from ordinary
multimodal admission. Both related diffs were checked before this revision.

Public `/generate` callers must now supply payload data or the existing EC
metadata contract for each feature. Hashes and placeholder positions alone are
insufficient. Internal receiver-cache references still resolve normally.

AI assistance was used to develop and review this revision. The human submitter
reviewed the changes and approved pushing with GPU end-to-end validation pending.
