# [ROCm][Quantization] Add regression tests for symmetric GPTQ on the RDNA hybrid W4A16 kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/63825) · state: open · merged: False

## Original PR description



## Overview

Adds regression tests for #63597 (symmetric GPTQ crashes on the RDNA hybrid W4A16 kernel). The fix itself is #52637 by tangzzycc; this PR only adds tests for it. **Depends on #52637: please merge after it.**

## Claims

- A layer test drives a symmetric GPTQ layer through the real `AutoGPTQLinearMethod` path (`create_weights` → `process_weights_after_loading` → `apply`) on `RDNAHybridW4A16LinearKernel` and compares with a dequantized reference, for both the HIP skinny path (M=1) and the Triton path (M=64).
- It covers a case #52637's description does not mention: when K/G == N/8, the stale `qzeros` passes every shape and stride check, and the kernel silently uses zero point 7 instead of 8 (output error ≈ 0.36 against a 2e-2 tolerance).
- An end-to-end test loads a real symmetric GPTQ checkpoint (`JunHowie/Qwen3-0.6B-GPTQ-Int4`) on the hybrid kernel and compares logprobs with the Triton kernel, asserting which kernel each run used.

## Validation

Hardware: AMD Radeon AI PRO R9700 (gfx1201, RDNA4), WSL2. vLLM `main` cannot be built here, so the tests ran in `rocm/vllm:rocm10.1.0_ubuntu24.04_py3.14-pytorch_2.13.0_vllm-0.29.0` (vLLM `0.29.1.dev0+g98dff2a81`): once with the image's own `auto_gptq.py` (fails), once with #52637's 4-line loader change applied to that file (passes). The test files are identical to this PR.

```bash
pytest tests/kernels/quantization/test_rdna_hybrid_w4a16_gptq.py tests/models/quantization/test_gptq_rdna_hybrid.py
```

Without the fix (the image's own `auto_gptq.py`) — 5 failed:

On this older image the K/G == N/8 case also fails loudly (its kernel checks `(N, num_groups)`); on `main` the zero-point layout is `[N/8, K/G]`, so there the stale `qzeros` passes the shape and stride checks and only the numeric comparison catches it.

With #52637's loader change — 5 passed:

```text
PASSED kernels/quantization/test_rdna_hybrid_w4a16_gptq.py::test_symmetric_gptq_matches_reference[256-128-128-M=1_skinny]
PASSED kernels/quantization/test_rdna_hybrid_w4a16_gptq.py::test_symmetric_gptq_matches_reference[256-128-128-M=64_triton]
PASSED kernels/quantization/test_rdna_hybrid_w4a16_gptq.py::test_symmetric_gptq_matches_reference[2048-128-128-M=1_skinny]

PASSED models/quantization/test_gptq_rdna_hybrid.py::test_gptq_rdna_hybrid_matches_triton[5-32]
```

CI coverage: vLLM CI has no gfx11/gfx12 runners. On CUDA the files skip at module level; on MI300/MI355 every test skips (the hybrid kernel is gfx11/gfx12 only, and gfx1100 selects `RDNA3W4A16LinearKernel` first). The tests therefore run only on RDNA hardware; the results above are that run.

## Details

- Why not a duplicate: #52637 fixes the bug and includes a unit test with a mock kernel; #61891 (draft) was asked for a regression test. This PR adds no fix, only tests on the real kernel and a real checkpoint. If the #52637 author prefers, these two files can be folded into that PR instead.
- The layer test builds the layer with `AutoGPTQLinearMethod.create_weights` (not the existing dummy-layer helper), because the bug is that the GPTQ loader's `qzeros` reaches the kernel; the dummy layer never registers it.
- AI assistance (Claude) was used to write these tests and this description. I reviewed every line and ran the tests above.
