## Overview

Fixes #55718 by validating the parsed endpoint path while preserving the original request URL. Benchmark URLs can include query parameters or fragments without failing endpoint validation.

- The shared validator covers completion, chat, Responses, audio, embedding, reranking, pooling, and profiling requests.

- ParBproject · COMMENTED · 2026-09-09T03:53:49Z · [source](https://github.com/vllm-project/vllm/pull/55719#pullrequestreview-5149553004)

There is one URL-shape regression in switching validation to `urlparse(api_url).path`: `urlparse()` splits the semicolon `params` component out of `path`, so `https://host/v1/completions;foo` now validates as if its path were `/v1/completions`. The request still uses the original `api_url`, though, and clients such as aiohttp/yarl preserve `;foo` in the HTTP path, so the benchmark can pass validation and then hit a different/nonexistent route. The old full-string suffix check rejected this form. Could validation either reject a non-empty parsed `params` component or validate a reconstructed path that includes it? A regression case with `/v1/completions;foo` would distinguish this from the intended query/fragment support.
