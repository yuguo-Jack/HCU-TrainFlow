# [Misc] Consolidate csrc shared headers and prune dead code

[Upstream PR](https://github.com/vllm-project/vllm/pull/60721) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Tidy `csrc/`: merge one-macro/one-function headers, rename the misnamed `attention/` dtype directory, move stragglers next to the extension that builds them, delete unreferenced code, and flatten `csrc/libtorch_stable/` back into `csrc/` now that nearly every GPU kernel is stable-ABI. No functional change intended.

Not a duplicate: the only open PR touching this area is #38134 (WIP, removes the KV cache dtype enum), which has a different goal and predates the `libtorch_stable/` layout.

## Claims

- `csrc/` is now `core/` (shared by every extension), `cpu/` and `rocm/` (legacy-ABI code), and everything else is the stable-ABI CUDA/HIP tree. `libtorch_stable/` is gone; extension names (`_C_stable_libtorch`, `_moe_C_stable_libtorch`) are unchanged.
- Every quoted `#include` resolves to the same file before and after the flatten (scripted over all 250 sources).
- The built CUDA extensions register the same 160 op schemas as `main`.
- Every `csrc/` path in the CI `source_file_dependencies` filters exists again. 68 entries had been left naming paths that moved under `libtorch_stable/`.

## Details

**Layout**

```
csrc/
  core/             registration.h  scalar_type.hpp  cuda_compat.h
                    utils.hpp       (math.hpp + batch_invariant.hpp)
                    vec_dtypes/     (was attention/)
  cpu/              + ops.h, dynamic_4bit_int_moe_cpu.cpp
  rocm/             + dispatch_utils.h, quickreduce/
  attention/ moe/ quantization/ cutlass_extensions/ mamba/ gdn/ kimi_k3/
  *.cu, *.cuh, ops.h, torch_bindings.cpp   (was libtorch_stable/)
  cumem_allocator.*, fs_io.cpp, spinloop.cpp, *_registration.cpp
```

- `csrc/attention/` only held `Vec`/`FloatVec` dtype helpers. ROCm paged attention is the one place they are used for attention; elsewhere they are half/bf16/FP8 conversions. Hence `core/vec_dtypes/`.
- The legacy `_C` extension is ROCm-only and contains just quickreduce, so its bindings, kernel and headers live in `rocm/quickreduce/`. The op namespace (`_C_custom_ar`) is unchanged.
- The top-level `ops.h` only declared CPU ops (plus quickreduce), so it moved to `cpu/`.

**Removed as unreferenced**

- Files: `core/exception.hpp`, `cache.h`, `torch_utils.h`, `attention_utils.cuh`, `mamba/static_switch.h`, `cutlass_extensions/common.cpp`, the int8 `per_token_group_quant.cu` wrapper and its header, the second Marlin `generate_kernels.py`.
- Symbols: `VLLM_IMPLIES`, `Qk_dot`, `VLLM_SHFL_SYNC`, `TORCH_LIBRARY_IMPL_EXPAND`, `DEVICE_INLINE`/`HOST_INLINE`, the legacy `AT_*` dispatch macros other than `VLLM_DISPATCH_FP8_TYPES`, `cuda_utils::ceil_div` (now `div_ceil`), `TrivialEpilogue`, `identity`, `equivalent_cutlass_type`, `enable_sm120_only`, `barrier_at_start_release`, and the non-stable-ABI branches in two CUTLASS headers.

**Things reviewers may want to look at**

- `TORCH_UTILS_CHECK` is replaced by `STD_TORCH_CHECK`. The stable build already resolved to it; in the legacy-ABI `_rocm_C` extension an unsupported KV cache dtype string now raises `std::runtime_error` instead of `c10::Error`.
- `div_ceil` is `constexpr` without `__device__` and is now called from device code in `cache_kernels.cu`, which is also built for HIP.
- The CUTLASS include dirs and `CUTLASS_ENABLE_DIRECT_CUDA_DRIVER_CALL` were dropped from the ROCm-only `_C` target, which no longer includes CUTLASS headers.
- The flatten renames about 190 files, so open PRs touching `csrc/libtorch_stable/` will need a rebase (git follows the renames for edits; newly added files need moving by hand).
- CI: the filter commits change which jobs trigger. Also, quickreduce and the CPU `ops.h` now sit under `csrc/rocm/` and `csrc/cpu/`, which `ci_config.yaml` excludes from its run-all pattern, so changes to them only trigger jobs listing those paths.

**Out of scope**

- Grouping the loose kernel files at the `csrc/` top level into subdirectories.
- `get_device_attribute` in `cuda_utils_kernels.cu` caches its first result in a function-local `static` regardless of arguments, so the SM-count and max-shared-memory queries can return each other's value. Found while reviewing; it needs its own fix.
