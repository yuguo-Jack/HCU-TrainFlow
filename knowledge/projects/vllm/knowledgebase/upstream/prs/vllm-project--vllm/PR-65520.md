# [Model] Nemotron-3.5-Transcribe: support ReplaySSM

[Upstream PR](https://github.com/vllm-project/vllm/pull/65520) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Follow-up to #64282. vLLM main refuses `--use-replayssm` for Nemotron-3.5-Transcribe, and every serve command in
the model card passes it. This PR declares ReplaySSM support for the model.

## Claims

- vLLM accepts `--use-replayssm` for `Nemotron3_5TranscribeForConditionalGeneration`. NemotronH already sizes the
  ReplaySSM buffers; the wrapper only declares `SupportsReplaySSM`.
- On Model Runner V2, every configuration in the card starts and serves with ReplaySSM (table below).
- CI now runs the model's tests that need the published checkpoint.

## Validation

On main before this PR, the card's serve command stops at startup: `ValueError: --use-replayssm is not supported for
architecture 'Nemotron3_5TranscribeForConditionalGeneration'`.

With this PR, on an RTX PRO 6000 (Blackwell) with the BF16 checkpoint and Model Runner V2, every configuration
starts, and 24 short clips get the same transcript from chat completions and from `/v1/audio/transcriptions`:

| Configuration | Endpoints agree | Mean acceptance length |
|---|---|---|
| MTP8 (the card's default) | 24/24 | 7.25 |
| MTP2 | 24/24 | 3.00 |
| No speculative decoding | 24/24 | – |
| DFlash2 K=7 | 24/24 | 5.46 |

From `tests/`, with Hub access, all pass: `models/test_registry.py -k Nemotron3_5Transcribe` (2),
`models/multimodal/processing/test_nemotron3_5_transcribe.py` (30),
`models/multimodal/processing/test_common.py -k Nemotron-3.5-Transcribe` (3),
`models/test_initialization.py -k Nemotron3_5Transcribe` (2),
`models/multimodal/processing/test_tensor_schema.py -k Nemotron-3.5-Transcribe` (1).

## Details

- **Root cause.** `VllmConfig` refuses `--use-replayssm` unless the architecture declares `SupportsReplaySSM`.
  NemotronH declares it, but the Transcribe wrapper contains a NemotronH decoder rather than subclassing it, so the
  flag was missing. The wrapper already passes the Mamba state shape, dtype and copy-function calls to NemotronH,
  which adds the ReplaySSM ring buffers, so the declaration is the whole fix.
- **Constraints.** With speculative decoding, vLLM's FlashInfer ReplaySSM needs `--mamba-backend flashinfer` and
  `--no-enable-prefix-caching`; the card sets both, and the docs note now says so.
- **Model Runner V1.** The card currently selects V1 for the NeMo vLLM plugin's word timestamps. Since Model Runner
  V1 is being removed, this PR is validated on V2 only.
- **CI coverage.** CI cannot serve the 30B checkpoint end to end, so the serving validation above ran locally. With
  the registry entries online, CI runs the model's registry, initialization, processing and tensor-schema tests.
- **Related PRs.** No open PR changes these lines. #65379 (native CTC word timestamps) also edits the model file.
