# [Bugfix] Reject duplicate ranks in tiktoken vocab files

[Upstream PR](https://github.com/vllm-project/vllm/pull/51135) · state: open · merged: False

## Original PR description

## Summary

- Reject duplicate ranks while parsing tiktoken vocab files.
- Add a regression test that loads two valid base64 tokens with rank `0` through `TiktokenTokenizer::new()`.

Fixes #50954

## Reproduction and result

Before this change, the production fallback reached `tiktoken-rs::CoreBPE::new`, which panicked because encoder and decoder lengths differed for duplicate ranks.

After this change, the shared tiktoken parsing boundary returns:

```
tokenizer error: duplicate rank 0 in tiktoken file
```

The malformed input is therefore rejected before either tokenizer backend receives it. Sparse but unique ranks remain allowed.
