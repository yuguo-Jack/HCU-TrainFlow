# [Bugfix][Attention]Allow the one-time sync when building INT4 RHT signs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62946) · state: open · merged: False

## Original PR description

### Purpose
_get_rht_signs builds the INT4 Randomized Hadamard Transform sign vector on the CPU and copies it to the GPU on first use. Warmup doesn't run the INT4 KV-cache write path, so with enforce_eager that first use lands inside execute_model, and VLLM_GPU_SYNC_CHECK=error kills the engine:

_get_rht_signs (int4_per_token_head.py:1142)
```
RuntimeError: GPU<->CPU sync detected - avoid it or wrap with gpu_sync_allowed()
Seen in amd-ci build [#14868](https://buildkite.com/vllm/amd-ci/builds/14868).

```
The copy runs once per sign vector (it is cached), so this wraps it in gpu_sync_allowed(). Copy behavior and sign values are unchanged.

### Test Plan
In the amd-ci image on MI300X, with VLLM_GPU_SYNC_CHECK=error:

pytest tests/models/quantization/test_per_token_kv_cache.py -k int4_per_token_head
pytest tests/quantization/test_per_token_kv_cache.py -k int4

### Test Result
Before: the end-to-end int4 test fails with GPU<->CPU sync detected.
After: the end-to-end int4 test passes (2 out of 2 runs), and the kernel unit tests pass (26 passed).
