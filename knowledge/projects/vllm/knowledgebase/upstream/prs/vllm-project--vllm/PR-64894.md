# [Bugfix][ROCm] Fall back to torch.cuda in RocmPlatform when AMDSMI cannot init (#64664)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64894) · state: open · merged: False

## Original PR description



## Overview

Fall back to torch.cuda and safe defaults in RocmPlatform.get_device_name, get_device_uuid, and is_fully_connected when amdsmi_init fails (such as on WSL2 where /dev/dxg is exposed instead of /dev/kfd).

Fixes #64664

## Claims

- Prevents RocmPlatform.get_device_name, get_device_uuid, and is_fully_connected from crashing with AmdSmiLibraryException when ROCm platform detection succeeds via the WSL PyTorch fallback (#38434) but AMDSMI cannot initialize.

## Validation

```bash
pytest tests/test_zen_cpu_platform_detection.py -k test_rocm_platform_falls_back_when_amdsmi_fails -v
```

## Details

While #38434 added a WSL PyTorch/HIP fallback to rocm_platform_plugin() when amdsmi_init() fails, and _get_gcn_arch() and RocmPlatform.get_device_total_memory() already catch AMDSMI exceptions and fall back to torch.cuda, RocmPlatform.get_device_name(), get_device_uuid(), and is_fully_connected() were decorated directly with @with_amdsmi_context. Wrapping the AMDSMI queries in helper functions and falling back to torch.cuda.get_device_name(device_id), "rocm:{device_id}", and False allows ROCm startup to proceed in WSL2 environments where AMDSMI is unavailable.
