# [Bugfix] MambaManager.find_longest_cache_hit ignores drop_eagle_block, silent corruption with prefix caching + MTP/EAGLE

[Upstream PR](https://github.com/vllm-project/vllm/pull/57128) · state: open · merged: False

## Original PR description

<!-- AI-assisted PR: drafted and tested with Claude (Anthropic) assistance, reviewed and submitted by the author. -->

## Purpose

`MambaManager.find_longest_cache_hit` (`vllm/v1/core/single_type_kv_cache_manager.py`) accepts `drop_eagle_block` as a parameter but never acts on it. When native MTP/EAGLE speculative decoding is combined with `--enable-prefix-caching` on a hybrid Mamba/GDN model, a matched block containing recurrent state written over rejected draft positions stays reachable through the prefix cache and gets reused by later requests sharing that prefix. This causes silent corruption (empty or repeated-character output, no error, no crash) -- matches #53912.

The root cause is also visible in `kv_cache_coordinator.py`: the coordinator deliberately skips the eagle_margin for `MambaSpec` groups, with a comment explaining *why* it doesn't need to (`MambaManager`'s own finder is expected to apply the drop) -- but the finder never did.

An earlier, simpler fix (#43650) addressed an older version of this function by pre-shrinking the search ceiling by one unit before scanning. That approach doesn't carry over to the current, rewritten `find_longest_cache_hit`: in `mamba_cache_mode="align"`, real state checkpoints only exist at sparse block boundaries, not at every fine-grained hash unit, so pre-shrinking the ceiling reliably lands in a gap between checkpoints and yields **0% cache-hit-rate** (confirmed live, see Test Plan).

## Fix

Mirror `FullAttentionManager`'s drop semantics, adapted to Mamba's snapshot (not chained-block) write model: scan the full, unrestricted window, and skip only the *first* (most recent) checkpoint actually found when `drop_eagle_block` is set, then keep scanning for the next (older, already-committed) one. This excludes exactly the one block that may hold unverified draft state, without blanking the whole tail of the search window. Applied to both the fine-grained and coarse-grained branches of the function.

`kv_cache_coordinator.py` only needed a comment update (no logic change) -- the coordinator's existing choice to skip the eagle_margin for Mamba groups was already correct, it just documented the wrong reason.

## Test Plan

- `ruff check` / `ruff format --check`: clean.
- New unit tests in `tests/v1/core/test_single_type_kv_cache_manager.py` covering `MambaManager.find_longest_cache_hit` with `drop_eagle_block=True/False`, through both the coarse and fine-grained branches, plus the single-checkpoint edge case (drop must fall back to no hit, never a corrupted match). Passed locally (Python 3.12, CPU-only, `torch==2.8.0` + `requirements/common.txt`).
- Live end-to-end test against a real hybrid Mamba/GDN model:
  - **Hardware**: 2x NVIDIA RTX 5060 Ti 16GB (TP=2)
  - **Image**: `vllm/vllm-openai:v0.29.0-cu129`
  - **Model**: Qwen3.8-27B-NVFP4 (hybrid linear-attention/full-attention, `full_attention_interval=4`, native MTP head)
  - **Config**: `--kv-cache-dtype turboquant_4bit_nc`, `--speculative-config '{"method":"mtp","num_speculative_tokens":1}'`, `--enable-prefix-caching`, `--max-model-len 131072`
  - Before this fix: `--enable-prefix-caching` + MTP together gave 0% prefix-cache-hit-rate (the pre-shrink approach) or corruption risk (with drop_eagle_block unhandled).
  - With this fix: confirmed real cache hits under concurrent shared-prefix load (8 concurrent requests, ~4.4k shared prefix, no corruption in repeated correctness checks) and on a larger, more realistic shared prefix (~24k tokens): warm requests dropped from ~77s (cold) to ~30-32s, with instrumented logging confirming a genuine partial hit of 15,440 of ~18,528 available tokens (5 of 7 candidate blocks, correctly skipping the most recent/unverified one).

## Test Result

All new and existing tests pass. Live smoke tests show no corruption and a real cache-hit speedup on realistic shared-prefix traffic.
