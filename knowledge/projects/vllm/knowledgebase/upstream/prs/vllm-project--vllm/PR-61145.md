# [Bugfix][Frontend] Load tool/reasoning parser plugins in run-batch

[Upstream PR](https://github.com/vllm-project/vllm/pull/61145) · state: open · merged: False

## Original PR description

## Overview

`vllm run-batch` accepts `--tool-parser-plugin` and `--reasoning-parser-plugin` but never imports them, so a parser registered by a plugin can't be used in batch mode. `vllm serve` imports both in `setup_server`, and #53124 did the same for `--headless`; `run-batch` is the entrypoint that was left out.

## Claims

- `run_batch.main` imports the tool and reasoning parser plugins before it validates the args and builds the engine config, in the same order as the API server.

## Validation

With a plugin file that registers `my_reasoner` (a subclass of the DeepSeek R1 parser):

```console
$ vllm run-batch -i in.jsonl -o out.jsonl --model Qwen/Qwen3-0.6B \
    --reasoning-parser my_reasoner --reasoning-parser-plugin /path/to/my_reasoning_plugin.py
  File "vllm/config/reasoning.py", line 84, in initialize_token_ids
  File "vllm/reasoning/abs_reasoning_parsers.py", line 247, in get_reasoning_parser
KeyError: "Reasoning parser 'my_reasoner' not found. Available parsers: cohere_command3, ..."
```

With the change the same command gets past config creation and reaches `Initializing a V1 LLM engine`.

The new test in `tests/entrypoints/launchers/test_run_batch.py` writes two small plugin files, parses real `run-batch` arguments and checks that both parsers are registered by the time the engine client is built. On main it fails with `AssertionError: assert 'batch_plugin_tool' in [...]`.

```
pytest tests/entrypoints/launchers/test_run_batch.py -k "plugins or download or upload or transcription_wrapper"
ruff check && ruff format --check   # on the two touched files
```

Both pass locally. This was a CPU-only box, so the tests in that file that spawn `vllm run-batch` with real weights were not run, and the engine in the manual run above did not finish starting.

## Details

Noticed while reading the plugin-loading call sites. The tool parser half fails later than the reasoning one: nothing looks the tool parser up until the chat handler is built, so `--enable-auto-tool-choice --tool-call-parser my_tool --tool-parser-plugin ...` only dies there. I checked that half through the registry in the test, not with a full run.

Not a duplicate as far as I can tell: #53072 / #53124 cover `vllm serve --headless` only, and #52026 changes the module name plugins are imported under, not where they are imported.
