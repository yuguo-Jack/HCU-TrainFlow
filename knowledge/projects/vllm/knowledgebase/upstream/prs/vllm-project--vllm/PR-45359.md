# [Rust Frontend] Add mistral reasoning parser

[Upstream PR](https://github.com/vllm-project/vllm/pull/45359) · state: closed · merged: False

## Original PR description

## Purpose

Add a reasoning parser for Mistral `[THINK]` / `[/THINK]` models (Magistral,
Ministral-*-Reasoning) to the Rust frontend, registered under the name `mistral`
for parity with the Python frontend (`vllm/reasoning/mistral_reasoning_parser.py`).

Implementation:
- Reuses the shared `DelimitedReasoningParser` with **content-first** state, since
  `[THINK]` is optional and a response may start directly in content.
- Reports `preserve_special_tokens() = true`: `[THINK]` / `[/THINK]` are Mistral
  special tokens that a default decode would strip before the parser sees them.

### Why it is NOT auto-selected by model ID

The parser is reachable **only** via explicit `--reasoning-parser mistral`. It is
deliberately not auto-routed from the model ID, because:

1. **Magistral's reasoning format changed across releases.** `Magistral-Small-2506`
   (v1.0) wraps reasoning in plain-text `<think>` / `</think>` via the system prompt.
   From `Magistral-Small-2507` (v1.1) onward, Mistral switched to `[THINK]` / `[/THINK]`
   as real special control tokens. This is documented in the official 2507 model card
   ("Changes from Magistral Small 1.0 to 1.1") and defined in `mistral-common` as
   `SpecialTokens.begin_think` / `end_think`. A `"magistral"` substring match cannot
   distinguish 2506 from 2507+, so auto-routing would attach this `[THINK]` parser to
   2506 and silently extract no reasoning.
2. **Reasoning vs non-reasoning Mistral models share a prefix.** Other `[THINK]`
   models (e.g. `Ministral-*-Reasoning`) share a name prefix and architecture with
   their non-reasoning instruct variants, so they can't be safely auto-detected.
3. **Parity with the Python frontend**, which has no model-ID-based reasoning-parser
   auto-selection at all — `reasoning_parser` defaults to empty and requires an
   explicit flag.

This does not duplicate any open PR; it ports the existing Python `mistral` reasoning
parser to the Rust frontend.

### End-to-end test

Built `vllm-rs` from this branch and served `mistralai/Ministral-3-8B-Reasoning-2512`
on an RTX 4090 with the Rust frontend + parser enabled:

```bash
VLLM_USE_RUST_FRONTEND=1 \
VLLM_RUST_FRONTEND_PATH=rust/target/release/vllm-rs \
vllm serve mistralai/Ministral-3-8B-Reasoning-2512 \
  --config_format mistral --load_format mistral \
  --reasoning-parser mistral --max-model-len 8192 --enforce-eager
```

**Request**

```json
{
  "model": "mistralai/Ministral-3-8B-Reasoning-2512",
  "messages": [{ "role": "user", "content": "What is 17 * 24? Show your reasoning." }],
  "temperature": 0,
  "max_tokens": 500
}
```

**Response** — the `[THINK]`-delimited reasoning is split out into `reasoning`, the rest stays in `content` (content abbreviated):

```json
{
  "choices": [{
    "finish_reason": "length",
    "message": {
      "role": "assistant",
      "content": "### … First, I need to understand what the user is asking … 17 * 20 = 340 … 17 * 4 = 68 … 340 + 68 = 408. … Therefore, the final answer is 408.",
      "reasoning": "Okay, the user is asking for the product of 17 and 24, and they want to see the reasoning behind the calculation. I need to break this down … I recall that multiplication can be broken down using the distributive property. So, I can split 24 into 20 and 4 …"
    }
  }]
}
```
