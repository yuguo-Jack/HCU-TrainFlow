# [Perf][FlashInfer] Opt-in trtllm-gen generation kernel for long-prefix chunked prefills

[Upstream PR](https://github.com/vllm-project/vllm/pull/63194) · state: open · merged: False

## Original PR description



## Overview

Chunked prefills with a long cached prefix and a short new chunk underuse the trtllm-gen context kernel. This adds an opt-in path that runs them on the trtllm-gen generation kernel with a split-KV CTA count chosen per batch.

## Claims

- New `AttentionConfig.trtllm_gen_split_kv_prefill` (default off). When on, long-prefix prefill batches use the generation kernel where a cost model predicts a gain; supported configurations are listed in the option's docstring.
- Off by default because split launches are not bitwise identical to the context kernel.
- Passes `sm_count` to FlashInfer when the installed version supports it; otherwise overrides FlashInfer's SM-count lookup for that one call.

## Validation

Not run yet. Planned:

```bash
pytest -v tests/v1/attention/test_flashinfer_trtllm_gen_prefill.py tests/v1/attention/test_trtllm_attention_integration.py
```

plus GSM8K with the option on and off, and a serving benchmark with prefix caching.

## Details

The SM-count override is interim until FlashInfer exposes an `sm_count` argument on `trtllm_batch_decode_with_kv_cache`.
