# [Bugfix][Frontend] Refresh echoed text after prompt truncation

[Upstream PR](https://github.com/vllm-project/vllm/pull/62691) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

When `/v1/completions` truncates a text prompt with an explicit `truncation_side`, `echo=true` still returns the original text. This change updates the echoed text to match the tokens sent to the engine, following up on #61876.

## Claims

The fix applies to streaming and non-streaming responses. Requests whose tokens are unchanged keep their original text. Requests that do not need prompt detokenization do not perform an additional decode.

## Validation

With `Qwen/Qwen3.5-0.8B` served as `qwen`:

The role labels below are plain text in the completion prompt.

```bash
curl -s http://localhost:8000/v1/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen",
       "prompt":"Role: You are a helpful geography assistant. Answer in one sentence.\nUser: What is the capital of France?\nAssistant:",
       "echo":true,"truncate_prompt_tokens":12,"truncation_side":"left"}'
```

The prompt has 27 tokens and is truncated to 12. Compare the echoed prefix of `choices[0].text`, omitting the generated continuation. Before the fix, it still includes the discarded system-style instruction:

```text
Role: You are a helpful geography assistant. Answer in one sentence.
User: What is the capital of France?
Assistant:
```

After the fix, the echoed prefix contains only the retained user question and assistant label:

```text
User: What is the capital of France?
Assistant:
```

Both versions report 12 prompt tokens. Generation uses the request defaults; no logprobs are requested.

The request was tested three times before and after the initial fix. All three responses included the discarded instruction before the fix and only the retained prompt after it. Only the echoed prefix was compared; the generated continuation is not part of this check.

The regression tests reproduce the added BOS echo with the original tokenization path, and an HTTP 500 / streaming error for a BOS-only prefix without the empty-text fix. All six regression cases now pass.

## Details

Post-tokenization validation truncates the token IDs but leaves the original `prompt` string in place. The detokenization added by #61876 is skipped because that string is still present. `BaseRenderer` now also detokenizes when validation replaces the token sequence, rebuilding the text from the retained tokens in both synchronous and asynchronous paths.

For text prompts, an encoding-time `special_tokens_mask` distinguishes automatically added tokens from special tokens in the user's text. The mask follows truncation and is consumed when rebuilding text, without changing the model input IDs. Empty echoed prefixes are preserved when creating engine inputs.

This covers truncation during post-tokenization validation, not truncation performed inside the tokenizer.

This is separate from #61876, which fixes detokenization order for token-ID inputs, and #62684, which handles Rust echo with `return_token_ids=true`.
