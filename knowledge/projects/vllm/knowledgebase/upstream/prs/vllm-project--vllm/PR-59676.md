# [Bugfix] Honor Qwen3-Next routed gate quantization

[Upstream PR](https://github.com/vllm-project/vllm/pull/59676) · state: open · merged: False

## Original PR description

## Overview

Fixes #59248 by honoring checkpoint quantization for Qwen3-Next routed MoE gates when the quantization format provides prefix-aware gate quantization metadata, while preserving the historical unquantized gate behavior for other formats.

## Claims

- Fixes loading of `Intel/Qwen3-Coder-Next-int4-AutoRound`, whose routed MoE gate is stored as quantized `mlp.gate.qweight`.
- Allows INC/AutoRound and mixed-precision ModelOpt configurations to apply their prefix-specific routed-gate quantization.
- Preserves the existing unquantized Qwen3-Next routed-gate behavior for homogeneous ModelOpt and other quantization formats.
- Adds a regression test that verifies the resulting `GateLinear` parameter layout and wires it into Buildkite CI.

## Details

`Qwen3NextSparseMoeBlock` previously constructed its routed `GateLinear` without the model quantization config. As a result, the gate always selected the unquantized linear path and exposed `weight`, even when the checkpoint contained a quantized routed gate such as `gate.qweight`.

Simply forwarding every quantization config would change existing Qwen3-Next behavior for homogeneous ModelOpt checkpoints. As discussed in #59248, unconditional propagation is not free: quantized gates may require format-specific handling. Local validation also shows that a homogeneous ModelOpt config without an explicit gate exclusion would quantize the routed gate.

This change therefore forwards the quantization config only for formats that can resolve routed-gate quantization from prefix-specific metadata:

- `inc`, used by the affected AutoRound checkpoint
- `modelopt_mixed`, whose per-prefix configuration determines whether the gate is quantized

Other formats retain Qwen3-Next's historical unquantized routed-gate path.

The regression test instantiates the real `GateLinear` and verifies the resulting parameter layout:

- `inc` -> quantized gate with `qweight`
- `modelopt_mixed` -> quantized gate with `qweight`
- `modelopt_fp4` -> unquantized gate with `weight`

The shared expert gate remains unchanged and unquantized.
