# [Kernel][DSA] Restore FP32 indexer MQA logits for non-DeepSeek models and add `indexer_logits_dtype`

[Upstream PR](https://github.com/vllm-project/vllm/pull/64580) · state: closed · merged: True

## Original PR description



## Overview

Bump DeepGEMM to `vllm-project/DeepGEMM` `dev` tip `ae4fd25`. It restores FP32 output for `fp8_fp4_(paged_)mqa_logits` behind a `logits_dtype` argument (vllm-project/DeepGEMM#46) and fixes the mega_mhc CUDA-graph replay barrier (vllm-project/DeepGEMM#48). The tip also includes MegaMoE NVFP4 epilogue and BF16 weight-layout changes (vllm-project/DeepGEMM#51), which touch no MQA-logits kernel.

This PR also adds `--attention-config.indexer_logits_dtype` (`auto` default, `float32` or `bfloat16`) for the DSA sparse indexer. #61149 had forced BF16 indexer logits on SM100, because that DeepGEMM release dropped `logits_dtype`. `auto` restores FP32 for GLM-5, GLM-5.3 and HY-V4, and keeps DeepSeek-V3.2/V4/V4.1 on main's behaviour (BF16 on SM100).

## Claims

- New option `-ac.indexer_logits_dtype={auto,float32,bfloat16}`. It applies to every CUDA user of DeepGEMM's dense MQA-logits kernels:
  - the DSA sparse indexer (DeepSeek-V3.2, GLM-5.x, DeepSeek-V4/V4.1, HY-V4);
  - the GLM-5.3 kpool indexer;
  - the DeepSeek-V4.1 specialized decode indexer.
- **Per-model default (`auto`).** On SM100, GLM-5, GLM-5.3 and HY-V4 go back to FP32 logits, and DeepSeek-V3.2/V4/V4.1 keep main's BF16. Against an FP64 reference on GB300, FP32 logits select the exact top-2048. BF16 logits change 0.4–0.75% of the selected tokens.
  - The DeepSeek default is set in the `DeepseekV32ForCausalLM` and `DeepseekV4ForCausalLMConfig` config hooks. GLM-5 runs the DeepSeek-V3.2 model class, so the default is keyed on the architecture name rather than on the layer.
  - Indexer models without a hook resolve `auto` to FP32. An explicit `float32` or `bfloat16` overrides the model default.
- **SM90/SM120 behaviour is unchanged by default**, for every model including DeepSeek. These architectures always produced FP32; `bfloat16` is now also available there.
- With the default top-k backend (`auto`), FP32 decode logits skip the `as_fp32_logits` upcast that main launches on SM100.
- `bfloat16` keeps main's current SM100 behaviour: BF16 head weights, BF16 reduction, and DeepSelect ranking BF16 logits directly.
- The sparse MQA-logits path (`indexer_sparse_logits`) is unchanged and always BF16.

**Logits accuracy.** The script below runs both dtypes through vLLM's wrappers on random inputs (64 heads, head dim 128). It compares each against an FP64 reference computed on the same FP8-quantized inputs. Overlap is the fraction of each row's top-2048 tokens that match the FP64 top-2048. Time is the median `do_bench` µs in eager mode. The BF16 column includes the FP32 upcast that every non-DeepSelect top-k needs.

| Case | Rel. error FP32 / BF16 | Top-2048 overlap FP32 / BF16 | µs FP32 / BF16 + upcast |
|---|---|---|---|
| prefill 2048 q × 16K kv | 6.4e-8 / 4.8e-3 | 1.0000 / 0.9959 | 217 / 210 |
| prefill 4096 q × 64K kv | 6.3e-8 / 4.8e-3 | 1.0000 / 0.9929 | 1770 / 1645 |
| decode b=64, ctx 16K | 6.5e-8 / 4.9e-3 | 1.0000 / 0.9958 | 54 / 93 |
| decode b=8, ctx 64K | 6.7e-8 / 5.0e-3 | 1.0000 / 0.9925 | 49 / 92 |

- In prefill, BF16 is 3–7% faster even after the upcast.
- In decode, the gap is mostly the extra upcast launch; these timings are not CUDA-graphed. DeepSelect with BF16, which skips the upcast, was not timed.

**Per-model default.** `tests/models/test_indexer_logits_dtype_config.py` (CPU) resolves `auto` through each indexer architecture's config hook, on and off SM100, and checks that explicit values win: 30 passed.

**CLI.** `--attention-config.indexer_logits_dtype` defaults to `auto` and accepts `float32` or `bfloat16`; other values (e.g. `float16`) are rejected.

**E2E: GLM-5.3 GSM8K.** `zai-org/GLM-5.3-Flash` (FP8), TP4 on 4x GB200, no MTP, at `afb1192fd7` with DeepGEMM `ae4fd25`. Run with `lm_eval` local-completions, 5-shot, on all 1319 questions.

```python
"""FP32 vs BF16 indexer logits through vLLM's DeepGEMM wrappers: error against
an fp64 reference on the same quantized inputs, top-k agreement, and rough
kernel timings (incl. the FP32 upcast the default top-k needs for BF16)."""

import torch
from triton.testing import do_bench

from vllm.model_executor.layers.sparse_attn_indexer import as_fp32_logits
from vllm.utils.deep_gemm import (
    _ceil_to_ue8m0,
    fp8_fp4_mqa_logits,
    fp8_fp4_paged_mqa_logits,
    get_num_sms,
    get_paged_mqa_logits_metadata,
    mqa_logits_mx_inputs,
    mqa_logits_use_mx_scales,
)

torch.manual_seed(0)
H, D, TOPK = 64, 128, 2048
DTYPES = (torch.float32, torch.bfloat16)


def quant_k(k):
    sf = _ceil_to_ue8m0(k.abs().float().amax(-1, keepdim=True).clamp(1e-4) / 448.0)
    kq = (k / sf).to(torch.float8_e4m3fn)
    return kq, sf.squeeze(-1)


def encode(sf):
    if not mqa_logits_use_mx_scales():
        return sf
    b = (sf.view(torch.int32) >> 23).to(torch.uint8)
    return b[..., None].repeat_interleave(4, -1).view(torch.int32)[..., 0]


def topk_overlap(a, b, valid):
    a = a.masked_fill(~valid, float("-inf")).topk(TOPK, -1).indices.sort(-1).values
    b = b.masked_fill(~valid, float("-inf")).topk(TOPK, -1).indices.sort(-1).values
    hits = [
        torch.isin(x, y).float().mean().item() for x, y in zip(a, b, strict=True)
    ]
    return sum(hits) / len(hits)


def prefill(seq_len, seq_len_kv):
    q = torch.randn(seq_len, H, D, device="cuda", dtype=torch.bfloat16)
    k = torch.randn(seq_len_kv, D, device="cuda", dtype=torch.bfloat16)
    w = torch.randn(seq_len, H, device="cuda") / H
    q8 = q.to(torch.float8_e4m3fn)
    k8, ksf = quant_k(k)
    rows = torch.arange(seq_len, device="cuda", dtype=torch.int32)
    ks = torch.zeros_like(rows)
    ke = rows + (seq_len_kv - seq_len) + 1
    width = int((ke - ks).max())
    # fp64 reference on the dequantized inputs, compressed like the kernel
    # (ks == 0); row chunks bound the [rows, H, N] fp64 intermediate.
    kd = (k8.double() * ksf.double()[:, None])[:width]
    ref = torch.cat(
        [
            (
                torch.einsum("mhd,nd->mhn", q8[i : i + 256].double(), kd).relu()
                * w[i : i + 256].double()[..., None]
            ).sum(1)
            for i in range(0, seq_len, 256)
        ]
    )
    valid = torch.arange(width, device="cuda")[None] < (ke - ks)[:, None]
    out = {}
    for dt in DTYPES:
        qs, wk = mqa_logits_mx_inputs(q8, None, w, dt)

        def run(dt=dt, qs=qs, wk=wk):
            lg = fp8_fp4_mqa_logits(
                (q8, qs), (k8, encode(ksf)), wk, ks, ke, width, logits_dtype=dt
            )
            return as_fp32_logits(lg, ke - ks)

        lg = run()
        err = (lg.double() - ref).abs().masked_fill(~valid, 0)
        rel = (err.sum() / ref.abs().masked_fill(~valid, 0).sum()).item()
        out[dt] = (lg, rel, do_bench(run, warmup=25, rep=200))
    return out, ref, valid


def decode(batch, ctx, block=64):
    q = torch.randn(batch, 1, H, D, device="cuda", dtype=torch.bfloat16)
    nblk = batch * ctx // block
    k = torch.randn(nblk, block, D, device="cuda", dtype=torch.bfloat16)
    w = torch.randn(batch, H, device="cuda") / H
    q8 = q.to(torch.float8_e4m3fn)
    k8, ksf = quant_k(k)
    cache = torch.empty(nblk, block * (D + 4), device="cuda", dtype=torch.uint8)
    cache[:, : block * D] = k8.view(nblk, -1).view(torch.uint8)
    cache[:, block * D :] = encode(ksf).view(torch.uint8).view(nblk, -1)
    cache = cache.view(nblk, block, 1, D + 4)
    tables = torch.randperm(nblk, device="cuda", dtype=torch.int32).view(batch, -1)
    lens = torch.full((batch, 1), ctx, device="cuda", dtype=torch.int32)
    idx = torch.arange(batch, device="cuda", dtype=torch.int32)
    sched = get_paged_mqa_logits_metadata(lens, block, get_num_sms(), indices=idx)
    kd = (k8.double() * ksf.double()[..., None])[tables.long()].view(batch, -1, D)
    ref = torch.einsum("bhd,bnd->bhn", q8[:, 0].double(), kd).relu()
    ref = (ref * w.double()[..., None]).sum(1)
    valid = torch.ones_like(ref, dtype=torch.bool)
    out = {}
    for dt in DTYPES:
        qs, wk = mqa_logits_mx_inputs(q8, None, w, dt)

        def run(dt=dt, qs=qs, wk=wk):
            lg = fp8_fp4_paged_mqa_logits(
                (q8, qs), cache, wk, lens, tables, sched, ctx,
                logits_dtype=dt, indices=idx,
            )
            return as_fp32_logits(lg, lens.view(-1))

        lg = run()[:, :ctx]
        rel = ((lg.double() - ref).abs().sum() / ref.abs().sum()).item()
        out[dt] = (lg, rel, do_bench(run, warmup=25, rep=200))
    return out, ref, valid


def report(name, res):
    out, ref, valid = res
    f32, b16 = out[torch.float32], out[torch.bfloat16]
    print(
        f"{name}: rel_err fp32={f32[1]:.2e} bf16={b16[1]:.2e} | "
        f"top{TOPK} overlap vs fp64 ref: fp32={topk_overlap(f32[0], ref, valid):.4f} "
        f"bf16={topk_overlap(b16[0], ref, valid):.4f} | "
        f"us fp32={f32[2] * 1e3:.1f} bf16(+upcast)={b16[2] * 1e3:.1f}"
    )


print(torch.cuda.get_device_name(), "mx_scales:", mqa_logits_use_mx_scales())
report("prefill 2048x16384", prefill(2048, 16384))
report("prefill 4096x65536", prefill(4096, 65536))
report("decode  b=64 ctx=16384", decode(64, 16384))
report("decode  b=8 ctx=65536", decode(8, 65536))
```

## Details

**Semantics per architecture**, following vllm-project/DeepGEMM#46:
- On SM100, the head-weights dtype selects the reduction. `mqa_logits_mx_inputs` now takes `logits_dtype` and casts the weights to it:
  - FP32 weights reduce in FP32;
  - BF16 weights reduce in BF16 and emit BF16 logits.
- SM90/SM120 keep FP32 weights for either output dtype.

**Memory profiling.** The indexer's dummy logits allocation is now sized from `logits_dtype` instead of from the architecture. The GLM-5.3 kpool profile also counts the BF16 output alongside its FP32 copy.

**Interaction with open PRs.** #62170 (emit BF16 indexer weights on SM100) and #62172 / #64138 (BF16 input for cooperative / persistent top-k) optimize the BF16 path. They still apply wherever the logits are BF16, including DeepSeek's SM100 default. With FP32 logits:
- #62170's BF16 weights would be upcast back to FP32;
- the top-k changes don't engage, since the logits are already FP32.

**Upstream DeepGEMM note.** vllm-project/DeepGEMM#46 relaxed the shared weights-dtype check. As a result, the sparse MQA-logits kernels, which read BF16 weights, now also accept FP32 weights on SM100. vLLM always passes BF16 there (`sparse_mqa_indexer.py`), so it is unaffected; this should be fixed in DeepGEMM.

**Not a duplicate.** Open-PR searches for `logits_dtype`, `indexer fp32 logits`, `mqa logits bf16`, `DeepGEMM bump` and `deepgemm.cmake` found no PR that restores FP32 indexer logits or bumps to this pin. The related PRs listed above build on the BF16 path rather than adding a dtype switch.
