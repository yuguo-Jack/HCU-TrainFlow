# [Bugfix][KV Offload] Deduplicate in-flight partial-tail loads

[Upstream PR](https://github.com/vllm-project/vllm/pull/64400) · state: closed · merged: True

## Original PR description

## Overview

This is a small and focused bug fix that prevents duplicate asynchronous KV transfers for concurrent partial-tail hits.

When a partial-tail key is already being loaded to GPU, the scheduler now waits for the existing transfer instead of submitting the same load again.

## Claims

- Prevents duplicate GPU load jobs for concurrent requests sharing an in-flight partial-tail key.
- Preserves existing complete-chunk and synchronous-load behavior.

## Validation

The regression test uses real `Request` objects and `CPUOffloadingManager` state. The first request starts an asynchronous partial-tail load; a second request waits for that transfer and leaves the scheduler with one load job. Without the fix, the second request accepts the hit and creates a duplicate job.

## Details

The complete-chunk lookup already checks `_chunks_being_loaded`, but `_lookup_partial_tail()` previously accepted an offload-manager `HIT` without checking whether the same key was already loading to GPU. An offload manager can report the source chunk as ready while that earlier GPU load is still in flight, allowing a concurrent request to enqueue the same transfer. The fix applies the existing in-flight check to partial-tail keys; the existing retry path then waits for the transfer to finish.
