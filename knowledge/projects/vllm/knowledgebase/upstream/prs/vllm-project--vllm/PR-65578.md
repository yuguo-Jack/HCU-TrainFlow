# [Perf][Kernel] Fuse bias add + GELU + NVFP4 quant for BERT-style FFNs

[Upstream PR](https://github.com/vllm-project/vllm/pull/65578) · state: open · merged: False

## Original PR description



## Overview

NVFP4 BERT, RoBERTa and XLM-R write the FFN's bias add + GELU output in 16 bits and read it back to quantize it for the down projection. This PR fuses the three into one kernel, called from BERT's FFN through the manual act+quant fusion (`maybe_fused_act_quant`, #51415). Follows #61755.

## Claims

- New op `gelu_nvfp4_quant`: NVFP4 of `gelu(input + bias)` computed in fp32 with one rounding, in `scaled_fp4_quant`'s layout. It shares a templated kernel with `silu_and_mul_nvfp4_quant`, whose output is unchanged.
- BERT hands the up projection's bias to the kernel only when the down projection takes NVFP4 input, so FP16 and FP8 are unchanged.
- `BAAI/bge-reranker-v2-m3` NVFP4 on an RTX PRO 6000: 16-20% less GPU time, now 17-23% below FP8, with unchanged ranking quality.

## Validation

RTX PRO 6000 (SM120), torch 2.14.0, FlashInfer 0.7.2.post1, main 34d5de18.

- `pytest tests/kernels/quantization/test_gelu_nvfp4_quant.py tests/kernels/quantization/test_silu_mul_nvfp4_quant.py tests/compile/passes/test_silu_mul_quant_manual_fusion.py`: 108 passed.
- `silu_and_mul_nvfp4_quant`: identical bytes to main (20 cases).
- `gelu_nvfp4_quant` vs `scaled_fp4_quant` of the fp32 reference: 1 of 68M bytes differs.
- Unfused fallback (`requires_unquantized_input` on the down projection, as under LoRA): scores identical to main.

GPU kernel time of one `classify` call on 128 sequences (ModelOpt `NVFP4_DEFAULT_CFG`, `LLM(runner="pooling", dtype="float16")`, mean of 3 runs, 2 for FP8, spread < 1.3%):

| Tokens/seq | FP8 | NVFP4, main | NVFP4, this PR |
|---|---|---|---|
| 160 | 27.8 ms | 27.7 ms | 22.3 ms (-19.5%) |
| 320 | 65.1 ms | 60.2 ms | 49.8 ms (-17.3%) |
| 640 | 137.1 ms | 134.6 ms | 113.5 ms (-15.7%) |

Recall@10 vs PyTorch FP32 on all 741 questions (Ko-StrategyQA / MIRACL-ko): 0.879 / 0.929 on main, 0.873 / 0.931 with this PR. Scores differ slightly from main because Inductor's bias + GELU rounds differently in about 1% of fp16 values.

## Details

- **Bias:** BERT sets `skip_bias_add` on the up projection when the down projection exposes the NVFP4 input key. If no fused kernel applies at run time (e.g. LoRA on the down projection), `maybe_fused_act_quant` adds the bias itself. With LoRA on the up projection, the bias now comes after the LoRA delta.
- **Duplicates:** no open PR fuses exact GELU into NVFP4 quant. #59467 (GELU-tanh x mul) templates the same kernel the same way, so whichever lands second rebases.
- **CI:** the kernel test is added to `(B200) Kernels`; the fusion test already runs in `(B200) Fusion and Compile`. Validated at TP=1 only.
- **AI assistance:** prepared with Claude Code (kernel, wiring, tests, validation, this text). I reviewed every changed line and the results.
