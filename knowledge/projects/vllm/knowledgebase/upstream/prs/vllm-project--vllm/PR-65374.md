# [Rust Frontend] Omit unset usage prompt_tokens_details and message annotations like Python

[Upstream PR](https://github.com/vllm-project/vllm/pull/65374) · state: closed · merged: True

## Original PR description

## Overview

Leave unset `usage.prompt_tokens_details` and `choices[].message.annotations` out of Rust frontend responses instead of sending them as `null`, matching the Python frontend since vllm-project/vllm#64177 (issue vllm-project/vllm#61425). The OpenAI spec types both as optional but not nullable, and strict schema validators reject the `null`.

## Claims

- `usage.prompt_tokens_details` is omitted when `--enable-prompt-tokens-details` is off, on every route that reports usage (chat, completions, generate; streamed or not). With the flag on, it is reported unchanged.
- `choices[].message.annotations` is omitted on non-streaming chat completions. The Rust frontend never produces annotations, so the key is always absent.
- Other unset fields keep their explicit `null`, including `completion_tokens_details` (Python also still sends `null` there).

Before (Rust), after this PR both keys are absent:

```
"message":{"role":"assistant","content":"hi","refusal":null,"annotations":null,"audio":null,"function_call":null,"reasoning":null}
"usage":{"prompt_tokens":22,"total_tokens":25,"completion_tokens":3,"prompt_tokens_details":null,"completion_tokens_details":null}
```

## Details

One commit per field:

1. **`usage.prompt_tokens_details`**: `#[serde(skip_serializing_if = "Option::is_none")]` on `Usage::prompt_tokens_details` (`routes/openai/utils/types.rs`). `Usage` is the single wire type that chat, completions and generate report, streamed or not, mirroring Python's single `UsageInfo`; the field-level attribute is where Python's `exclude_if` sits, so every route and stream mode follows one rule.
2. **`message.annotations`**: the same attribute on `ChatCompletionMessage::annotations` (`routes/openai/chat_completions/types.rs`), the non-streaming chat message wire type. Python's typing change to `list[...]` has no wire effect while the value is always unset.

Python consistency: `prompt_tokens_details` is omitted on every Python route and in both stream modes (field-level `exclude_if`; stream chunks already drop it), and `annotations` exists only on the non-streaming chat message. The OpenAI SDK parses responses without either key.

Not changed: an unset `completion_tokens_details` on stream chunks. Python drops it on the usage-only final chunk (`exclude_none`) and on completions continuous-usage chunks (`exclude_unset`), but sends `null` on its own chat and generate continuous-usage chunks; matching that needs a usage representation that depends on the chunk kind, so it is left for a separate change.

Not a duplicate: no open PR changes these fields in the Rust frontend (searched open PRs for `prompt_tokens_details`, `annotations` and Rust frontend usage; vllm-project/vllm#60624 adds `multimodal_tokens` and vllm-project/vllm#64573 is a Python change).
