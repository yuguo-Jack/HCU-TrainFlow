# [Perf][KV Offload] Calibrate the DMA/Triton load cutoff at handler init (opt-in)

[Upstream PR](https://github.com/vllm-project/vllm/pull/57569) · state: open · merged: False

## Original PR description

## Purpose

Part of #57555. Stacked on #57343, so the first two commits here are from that PR.

**Updated 2026-10-05:** the first version timed the default-stream fallback instead of `cuMemcpyBatchAsync`, and inside a server it didn't run at all ([details](https://github.com/vllm-project/vllm/pull/57569#issuecomment-5981553144)). Fixed in a0cc5ad4e; 8eed6a0f4 adds a 5% margin and e26e6e9d4 calibrates on rank 0 only. The numbers below are re-measured inside `vllm serve`.

The CPU→GPU load path picks between `cuMemcpyBatchAsync` and the Triton kernel with two constants tuned on one H100 (`THRESHOLD_BYTES = 28 KiB`, `MIN_N = 16`). The numbers in #57555 (H100, A30, GB10) show that where the two paths cross depends on the copy size, the batch size and the machine, so this lets a worker measure it instead.

With `"calibrate_load_path": true` in `kv_connector_extra_config`, rank 0 times both paths when the offloading worker is created, for its copy sizes, at N = 16, 32, 64, 128, 256, on a dedicated stream like real transfers. Every rank then uses the smallest N from which Triton is more than 5% faster at every larger N; where the two are within 5%, the default decides. If Triton never gets there the handler stays on DMA. The source is the real pinned CPU tensor and the destination is a scratch GPU buffer (at most 16 MiB), so no KV block is written. Copy sizes above 64 KiB would need a bigger scratch and are not measured. If anything goes wrong (no room for the scratch, host region too small, the op raising) the handler keeps the defaults and logs a warning.

The worker init is the natural place for this: the real GPU tensors, the pinned host region and the copy sizes all exist there, the GPU is idle, and `_select_swap_blocks_fn` already runs at that point.

To carry the result, the size cutoff and `MIN_N` are resolved into one `min_n` per handler at init and passed to the Triton wrapper, which still does a single comparison per call. With the option off the values are the same as today, so the default behaviour does not change.

On handlers with more than one copy size (the point @hclsys raised in #57555): one transfer sends all of a handler's sizes in a single call, so the per-size results are reduced to one. I kept that conservative, the largest `min_n`, and DMA for everything if any size never wins on Triton, which is what `max(sizes)` does today. When the sizes disagree the handler logs it, so it is visible how often this happens. Splitting the call by size is left for a follow-up once there is data from a hybrid model.

New tests:

- `test_batches_below_min_n_use_dma`: the wrapper falls back to DMA below the `min_n` it is given (runs without CUDA).
- `test_pick_min_n`: Triton taking over at N=64, ahead everywhere, never ahead, a win at N=32 that doesn't count because N=64 loses again, and cells within the 5% margin left to the default.
- `test_measure_load_paths_times_every_probed_n`: times every probed N on a real pinned tensor, and returns nothing when the host region is too small.

`calib_57569.py`:

```python
"""GH200 run of vllm #57569's load-path calibration, called the way the worker
calls it (gpu_worker._measure_min_n): copy size = page size,
chunk = min(next_pow2(page), 8192), host = a pinned CPU tensor whose rows are
read every other row. Usage: calib_57569.py REPEATS OUT.json [--extend]
--extend raises CALIBRATION_MAX_SCRATCH_BYTES so 128 and 256 KiB copies are
measured too (outside the PR's own cap; reported separately)."""
import collections
import json
import statistics
import sys
import time

import torch

import vllm.v1.kv_offload.cpu.swap_blocks_triton as sbt
from vllm import _custom_ops as ops
from vllm.triton_utils import triton

repeats, out_path = int(sys.argv[1]), sys.argv[2]
extend = "--extend" in sys.argv
sizes = [4096, 8192, 16384, 32768, 65536]
if extend:
    sbt.CALIBRATION_MAX_SCRATCH_BYTES = 64 * 1024 * 1024
    sizes += [131072, 262144]
dev = torch.device("cuda:0")
host = torch.empty((1024, 256 * 1024), dtype=torch.int8).pin_memory()


def bandwidth(size: int, chunk: int, n: int = 256, reps: int = 20) -> dict:
    """Median GB/s of each path for n copies of `size` bytes, same setup as
    measure_load_paths (every other host row, dedicated stream)."""
    scratch = torch.empty(n * size, dtype=torch.int8, device=dev)
    idx = torch.arange(n, dtype=torch.int64)
    src = (host.data_ptr() + 2 * host.stride(0) * idx).pin_memory()
    dst = (scratch.data_ptr() + size * idx).pin_memory()
    z = torch.full((n,), size, dtype=torch.int64).pin_memory()
    paths = {
        "dma": lambda: ops.swap_blocks_batch(src, dst, z, is_src_access_order_any=True),
        "triton": lambda: sbt.swap_blocks_batch(src, dst, z, bytes_per_chunk=chunk, min_n=0),
    }
    res = {}
    with torch.cuda.stream(torch.cuda.Stream(device=dev)):
        for name, fn in paths.items():
            fn()
            ts = []
            for _ in range(reps):
                torch.accelerator.synchronize()
                t0 = time.perf_counter()
                fn()
                torch.accelerator.synchronize()
                ts.append(time.perf_counter() - t0)
            res[name] = round(n * size / statistics.median(ts) / 1e9, 1)
    return res


out = {"device": torch.cuda.get_device_name(0), "torch": torch.__version__,
       "repeats": repeats, "extend": extend, "sizes": {}}
for size in sizes:
    chunk = min(triton.next_power_of_2(size), 8192)
    default = sbt.default_min_n(size)
    picks, runs, ms = [], [], []
    for _ in range(repeats):
        t0 = time.perf_counter()
        r = sbt.measure_load_paths(size, chunk, host, dev)
        ms.append((time.perf_counter() - t0) * 1e3)
        assert r is not None, f"not measurable at {size}"
        runs.append(r)
        picks.append(sbt.pick_min_n(r, default))
    med = [round(statistics.median(x), 2) for x in zip(*runs)]
    out["sizes"][size] = {
        "chunk": chunk, "default_min_n": default,
        "picks": {str(k): v for k, v in collections.Counter(picks).items()},
        "median_ratio_triton_over_dma": dict(zip(map(str, sbt.CALIBRATION_NS), med)),
        "ratio_min_max": [[round(min(x), 2), round(max(x), 2)] for x in zip(*runs)],
        "calibration_ms_first_median": [round(ms[0], 1), round(statistics.median(ms), 1)],
        "gbps_at_n256": bandwidth(size, chunk),
    }
    print(size, out["sizes"][size], flush=True)
json.dump(out, open(out_path, "w"), indent=1)
```

`sweep_57569.py`:

```python
"""Per-copy cost of each load path across 16-32 KiB on GH200, to locate the
DMA step that #57555 saw on GB10 between 24576 and 25600 bytes (N=512).
Same setup as measure_load_paths: every other row of a pinned host tensor,
dedicated stream, median of REPS timed calls. Usage: sweep_57569.py OUT.json"""
import json
import statistics
import sys
import time

import torch

import vllm.v1.kv_offload.cpu.swap_blocks_triton as sbt
from vllm import _custom_ops as ops
from vllm.triton_utils import triton

REPS = 30
dev = torch.device("cuda:0")
host = torch.empty((1024, 256 * 1024), dtype=torch.int8).pin_memory()  # same rows as calib_57569.py
rows = {}
for size in range(16 * 1024, 32 * 1024 + 1, 1024):
    chunk = min(triton.next_power_of_2(size), 8192)
    for n in (256, 512):
        scratch = torch.empty(n * size, dtype=torch.int8, device=dev)
        idx = torch.arange(n, dtype=torch.int64)
        src = (host.data_ptr() + 2 * host.stride(0) * idx).pin_memory()
        dst = (scratch.data_ptr() + size * idx).pin_memory()
        z = torch.full((n,), size, dtype=torch.int64).pin_memory()
        paths = {
            "dma": lambda: ops.swap_blocks_batch(src, dst, z, is_src_access_order_any=True),
            "triton": lambda: sbt.swap_blocks_batch(src, dst, z, bytes_per_chunk=chunk, min_n=0),
        }
        with torch.cuda.stream(torch.cuda.Stream(device=dev)):
            for name, fn in paths.items():
                fn()
                ts = []
                for _ in range(REPS):
                    torch.accelerator.synchronize()
                    t0 = time.perf_counter()
                    fn()
                    torch.accelerator.synchronize()
                    ts.append(time.perf_counter() - t0)
```
