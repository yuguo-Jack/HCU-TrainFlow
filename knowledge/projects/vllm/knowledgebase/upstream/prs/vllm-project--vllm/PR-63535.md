# [AuxOutput] Validate SHM capacity and warn on host memory pressure

[Upstream PR](https://github.com/vllm-project/vllm/pull/63535) · state: open · merged: False

## Original PR description

## Overview

Validate AuxOutput SHM arena coverage before allocation and report conservative
host-memory estimates with actionable KV block adjustments. This isolates the
memory checks extracted from #49555.

## Claims

- Reject an explicit `aux_output_config.max_bytes` that cannot cover all GPU KV
  blocks. Unset or increase the arena cap to resolve this configuration error.
- Warn and continue when estimated host-memory demand exceeds current headroom:
  cgroup usage can include reclaimable cache. Keep the selected arena capacity;
  do not automatically shrink it or change GPU KV blocks.
- Estimate system/cgroup headroom, all local DP output workers, staging, per-object
  metadata and runtime reserve, rounded to complete hash objects. No new
  environment variable or configuration field is added.
- Give a smaller KV block suggestion only when it fits the required
  `max_model_len`; require a matching arena adjustment for explicit `max_bytes`.
  Do not suggest unchanged or zero block counts.

## Details

For N GPU KV blocks, B tokens per block and payload width R, the default arena is
N * B * R bytes per output worker. Host demand includes the arena, estimated
512-byte metadata per hash object, existing staged blocks and in-flight CPU
snapshots, plus max(512 MiB, 5% of current headroom) runtime reserve.

System available RAM is capped by valid cgroup limit minus current usage.
Unavailable or invalid cgroup readings fall back to system available RAM.
This subtraction is conservative because usage includes reclaimable cache;
insufficient estimated headroom therefore produces a warning rather than a
startup rejection. Logs describe a conservative capacity estimate, not an
absolute supported maximum or proof that the configuration is impossible.

An explicit arena is independent of KV block count. Reducing blocks alone cannot
shrink it, so the warning prioritizes unsetting/resizing that cap and explicitly
couples it with a block adjustment when needed. Block advice must accommodate
`max_model_len`; staging exhaustion receives a separate diagnostic.

The Store uses anonymous shared mmap storage, so /dev/shm filesystem free space
does not define its capacity. These checks are startup estimates, not atomic
reservations or runtime memory limits: allocation can still fail and concurrent
allocations or later SHM growth can still cause OOM.

This PR integrates with the existing R3 output worker. It does not change Store
storage/LRU/growth, the SHM protocol, Capture/Replay, Indexer model adapters, or GPU
KV initialization/profiling. When combined with #49555, the caller must account
for the combined artifact width and temporary packed Indexer staging.

Duplicate-work checks were refreshed for #47280 and open AuxOutput/host-memory
PRs. This updates the existing extracted PR, rather than opening a competing
implementation. #49555 and #62915 cover Indexer capture/replay; #57968 adds a
Mooncake backend. The host-memory diagnostics remain isolated here.
