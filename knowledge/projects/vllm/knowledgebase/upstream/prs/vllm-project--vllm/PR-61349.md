# [Transformers backend] add DistilBERT sequence classification via Transformers Backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/61349) · state: open · merged: False

## Original PR description

## Overview

Adds `DistilBertForSequenceClassification` (e.g. `distilbert/distilbert-base-uncased-finetuned-sst-2-english`) to the pooling runner through the Transformers backend.

## Claims

- `vllm serve distilbert/distilbert-base-uncased-finetuned-sst-2-english --runner pooling` plus `POST /classify` works and matches HF probabilities (float32, max abs diff 1.5e-4).
- The attention fallback never replaces a registration made through `layer_idx`, and models without a registered head still use the existing classifier path.

## Validation

Environment: 1x H100 80GB HBM3, PyTorch 2.13.0+cu130, Transformers 5.19.0. float32 unless noted.

pytest tests/models/language/pooling/test_classification.py -k "distilbert or Qwen"
pytest tests/models/transformers/test_backend.py -k "test_unindexed_attention_registration or test_attention_dispatch_is_required"
pytest tests/models/transformers/test_backend.py::test_pooling -k TransformersForSequenceClassification
pytest tests/models/test_registry.py tests/models/test_initialization.py -k DistilBertForSequenceClassification

## Details

DistilBERT didn't work out of the box, for two reasons.

**1. No `layer_idx` on the attention module.**
The backend finds attention layers through `layer_idx`. `DistilBertSelfAttention` doesn't have one (it is encoder-only), so no layer got registered and loading failed with `Layer 0 does not dispatch through the Transformers attention interface`.
`_register_unindexed_attention` in `base.py` assigns an attention module to the layer it sits under, but only when no module with a `layer_idx` already serves that layer and exactly one unindexed module sits in it.

**2. The classifier head isn't a single module.**
HF does `pre_classifier -> relu -> classifier`, with the ReLU written inline in `forward`. Generic discovery only finds the final `classifier` linear, so `pre_classifier` and the ReLU would be silently dropped and the outputs would be wrong. The generic wrapper also adds a `.unsqueeze(1)` that doesn't suit this head.
`pooling.py` now has a small `_CLASSIFIER_HEADS` table keyed by `model_type`. DistilBERT maps to `_PreClassifierHead`, which keeps both linears and the ReLU. A weight mapper renames the flat checkpoint keys (`pre_classifier.*`, `classifier.*`) to the nested layout. Dropout is omitted since this is inference only.

**Test changes.**
- With `rtol=2e-3` and the previous `atol=1e-8`, 2 of 8 prompts fail for DistilBERT float32 even though the max abs diff is only 1.7e-4, because near-zero probabilities fail the relative check. I set `atol=5e-4` for DistilBERT only, as a provisional value, via a per-model `float_atol` parameter. Qwen2.5 keeps `1e-8`, and the half-precision tolerances are unchanged. The cause of the 1.7e-4 gap was not investigated.
- The comparison uses `torch.testing.assert_close` for clearer failure output.
- Both `test_models` params now have explicit `id=` values. Without it, the Qwen ID contained the float tolerance (`...-1e-08`), which broke the test selector in `run-cpu-test-ppc64le.sh`.

**Not covered**
- Quantized checkpoints, TP and PP are untested.
- ROCm was not tested.
