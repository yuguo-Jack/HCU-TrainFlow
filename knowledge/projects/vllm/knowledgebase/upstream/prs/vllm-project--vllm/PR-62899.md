# [ROCm][Ray] Refresh cached AITER env toggles after applying driver env

[Upstream PR](https://github.com/vllm-project/vllm/pull/62899) · state: open · merged: False

## Original PR description



## Overview

On ROCm, a multi-node run with the Ray V2 executor and AITER enabled fails on every worker, even though both variables are set in the driver and in the actor's `os.environ`:

```
ValueError: Unquantized MoE backend ROCm AITER does not support the deployment
configuration since kernel does not support current device rocm. AITER MoE is not
enabled -- set VLLM_ROCM_USE_AITER=1 and VLLM_ROCM_USE_AITER_MOE=1 to enable it.
```

Single-node `mp` runs of the same model work. The fix calls the existing `rocm_aiter_ops.refresh_env_variables()` in `RayWorkerProc.initialize_worker()` after the driver env is applied. Related: #53293 (forwards some env vars through the actor's `runtime_env`).

## Claims

- On ROCm, `initialize_worker()` refreshes the cached `VLLM_ROCM_USE_AITER*` toggles right after applying `driver_env_vars` / `env_vars` and before `WorkerProc.__init__` builds the model, so the MoE oracle and the kernels' `is_supported_config()` agree.
- No change on other platforms or with the `mp` executor; a one-time call at worker init.

## Validation

Multi-node Ray executor on 8x MI355X nodes, `VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_MOE=1`: without the fix every worker raised the error above; with the same `refresh_env_variables()` call at the end of `initialize_worker` (applied out of tree) the workers selected the AITER MoE backend and served normally, and our multi-node deployments have run with it since.

New `tests/distributed/test_ray_v2_executor.py::test_initialize_worker_refreshes_aiter_toggles`: the actor imported vLLM without `VLLM_ROCM_USE_AITER`; `initialize_worker` then receives it in `driver_env_vars`, and the cached toggle must be on afterwards. It runs without a Ray cluster or GPU (`WorkerProc.__init__` is patched out, `is_rocm` patched to true).

## Details

**Root cause.**

1. `vllm/_aiter_ops.py` snapshots every `VLLM_ROCM_USE_AITER*` toggle into `rocm_aiter_ops` class attributes at import.
2. The raylet starts the `RayWorkerProc` actor without the driver's environment, apart from what `update_runtime_env_for_worker_import` forwards.
3. The actor imports vLLM (and `_aiter_ops`); `initialize_worker()` then copies the driver env in with `os.environ.setdefault`, after the snapshot.
4. The MoE oracle reads the live env through `vllm.envs` and selects `UnquantizedMoeBackend.AITER`; `is_supported_config()` reads the stale `rocm_aiter_ops.is_fused_moe_enabled()` and rejects it.

`refresh_env_variables()` exists for this; today only `cleanup_dist_env_and_memory()` calls it.

**Alternative considered.** Forwarding `VLLM_ROCM_*` through the actor's `runtime_env`, as #53293 does for `VLLM_USE_BREAKABLE_CUDAGRAPH`. That relies on every cached toggle matching the forwarded prefix; refreshing after the env is applied keeps the cache consistent with whatever `initialize_worker` installs. Happy to switch if reviewers prefer.

**Not changed.** The legacy `RayDistributedExecutor` (`VLLM_USE_RAY_V2_EXECUTOR_BACKEND=0`) applies env through `WorkerWrapperBase.update_environment_variables` and may have the same issue; we did not reproduce it there.
