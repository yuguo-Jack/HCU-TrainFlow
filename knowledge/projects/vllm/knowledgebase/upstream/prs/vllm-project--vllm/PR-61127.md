# [Bugfix][CPU] Reject -1 placeholder drafts in the C++ rejection sampler

[Upstream PR](https://github.com/vllm-project/vllm/pull/61127) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Reject negative placeholder drafts before indexing probabilities in the CPU C++ random rejection sampler. Fixes #61117.

## Claims

- On CPU builds without Triton, a `-1` draft is rejected and replaced with the recovered token. The sampler cannot accept the placeholder and continue into padding.
- Nonnegative-draft behavior is unchanged. The guard matches the existing Triton rule. This fixes the CPU MRV1 path; GPU/MRV2 samplers are separate.

## Validation

Fresh Linux Cloud runs compare task-start main `a9b727a6122a0817ecb4eba61baeeb52e9a7d7f5` with PR `5dcbc3329fabf47ffee8255cc410e8257ff6e008`: two logical x86 CPUs, AVX2, native C++ extensions, no Triton.

- [Reproduction: complete commands, stdout/stderr and JUnit](https://gist.github.com/SeverinVisionary/b1b82a0ffedc36dd4e497f487d6780b3). Identical regression-test bytes cover both draft-probability modes: two assertion failures on main, two passes on the PR. The same 600-request structured-output reproducer gives 27 accepted placeholders / 3 invalid/error outputs on main, versus 0 / 0 on the PR.
- [lm_eval: commands, raw logs, aggregate JSON and every example](https://gist.github.com/SeverinVisionary/210363f11b96657c197f9bc2d918c540). Qwen2.5-0.5B-Instruct, zero-shot raw completions, full ARC-Challenge (1,172 questions), non-speculative loglikelihood: both `acc=360/1172`, `acc_norm=397/1172`. A supplementary speculative GSM8K probe covers the first 64 test questions: strict 0/64 on both; flexible 6/64 on main and 10/64 on PR (temperature 1, seed 256, max 128 generated tokens).
- [vllm bench serve: commands, raw logs and detailed request JSON](https://gist.github.com/SeverinVisionary/5c0d8d27eb41ec61ee3ab297274062dc). Same pinned Qwen target/draft, two speculative tokens, probabilistic sampling, float32/eager. Random workload: 128 requests, nominal input/output 128/32, range ratio 0.5, temperature 1, seed 61127, rate inf, requested concurrency 8. Both have 128 successes / 0 failures and 15,837 input / 3,770 output tokens. Main 1029.06 s / 3.66 output tok/s; PR 1026.91 s / 3.67 tok/s. One timed pass each, native counter off.

Both arms use the same #55005 expand copy-back and #61131 slot-mapping workarounds. Main uses Torch 2.14.0+cpu; PR uses 2.13.0+cpu. These source/dependency differences and the single timing pass do not support an isolated patch speedup claim. Full pins, configuration and workarounds are attached.

Instrumented pretrained probes exercise native random rejection sampling and speculative acceptance, but record zero padded requests. The regression and standalone 600 cover the placeholder branch. The 64-example stochastic probe does not establish an accuracy gain or a full GSM8K score.

At `5dcbc332`, all five changed files passed pre-commit in Cloud without source changes. GitHub's contributor-label prerequisite fails and skips upstream pre-commit. Read the Docs also stops at its pre-run check because that same prerequisite failed. The test is wired into x86/ARM CPU CI and excluded from GPU kernel CI; actual runtime coverage here is Linux AVX2. ARM, macOS, GPU and the full upstream suite were not run.

## Details

The old loop used `-1` in target and draft probability lookups, reading the previous row's last entry or memory before the buffer. An accepted placeholder could lead into an unmasked padding row. The guard rejects before either lookup and uses the existing recovery path, which suppresses the bonus token after rejection.

The deterministic test places a normal request beside a padded request and covers both draft-probability modes. It uses `current_platform.import_kernels()` to select the host's native ISA extension.
