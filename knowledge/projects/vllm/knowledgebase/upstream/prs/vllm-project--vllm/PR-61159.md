# [Model] Add native TeleOCR support with a Qwen3 text decoder

[Upstream PR](https://github.com/vllm-project/vllm/pull/61159) · state: open · merged: False

## Original PR description



## Overview

Add a native TeleOCR model implementation that reuses the Qwen2.5-VL vision stack and constructs a Qwen3 text decoder from the nested text configuration.

This PR does not establish that native support is necessary instead of the Transformers backend: a same-checkpoint backend comparison remains outstanding. The validation below covers an external version-pinned Ascend integration, not the current main branch on all supported platforms.

## Claims

- Register `TeleOCRForConditionalGeneration` without replacing the Qwen2.5-VL architecture globally.
- Initialize Qwen3 with `hf_text_config`, including its head dimension and Q/K normalization, while retaining the existing multimodal processor and weight-loading path.
- Add an example to the model initialization test registry and document the required architecture override. This native path avoids the official model-specific plugin; this is not a claim that the Transformers backend cannot support the model.

## Details

The published checkpoint advertises Qwen2.5-VL, but its text decoder is Qwen3. Selecting the ordinary Qwen2 decoder therefore gives the wrong attention implementation. Passing the outer multimodal config to Qwen3 also fails because text attributes such as `vocab_size` are nested. A protected decoder-construction hook lets TeleOCR select Qwen3 with the text sub-configuration and reuse the vision implementation. The default Qwen2.5-VL construction is preserved.

This adds a dedicated built-in architecture instead of the official external vLLM 0.11 plugin's global replacement. AI assistance was used to implement, validate, and prepare this contribution.
