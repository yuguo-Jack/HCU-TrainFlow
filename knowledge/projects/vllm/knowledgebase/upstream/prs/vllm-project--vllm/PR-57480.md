# [Bugfix][LoRA] Skip None weights when detecting LoRA device

[Upstream PR](https://github.com/vllm-project/vllm/pull/57480) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #57503.

Some quantized layers retain a `weight` attribute whose value is `None` after moving the usable weight to `weight_packed` or `qweight`. `_get_lora_device` currently checks only whether each attribute exists, so LoRA wrapper creation can fail with an `AttributeError` instead of continuing to the usable weight.

This change treats `None` weights as unavailable while preserving the existing candidate order. It also adds a regression test covering multiple `None` candidates followed by a valid quantized weight.

A duplicate-work check found no active, mergeable PR providing this focused fix and regression coverage.

AI assistance was used to analyze the downstream change, implement the patch, and run validation. The submitter reviewed the resulting changes.

## Test Plan

- Run the broader LoRA layer test suite.
- Serve a compressed-tensors W4A8 model with LoRA enabled on two Intel XPUs and send an OpenAI-compatible completion request.

```bash
source /opt/intel/oneapi/setvars.sh >/dev/null 2>&1
export VLLM_WORKER_MULTIPROC_METHOD=spawn

.venv/bin/python -m vllm.entrypoints.openai.api_server \
  --model /llm/models/Qwen3.5-9B-Text-W4A8-Dynamic-Per-Token \
  --served-model-name qwen3.5-9b-w4a8 \
  --host 127.0.0.1 \
  --port 18080 \
  --dtype float16 \
  --tensor-parallel-size 2 \
  --block-size 64 \
  --gpu-memory-utilization 0.70 \
  --max-model-len 512 \
  --max-num-batched-tokens 512 \
  --max-num-seqs 8 \
  --enforce-eager \
  --enable-lora \
  --max-loras 1 \
  --max-lora-rank 8
```

The export uses INT4 symmetric group-128 weights and dynamic per-token INT8 activations. The server selected `CompressedTensorsW4A8Int` with `XPUW4A8IntLinearKernel` and reached `Application startup complete`.

```bash
curl -sS --fail-with-body http://127.0.0.1:18080/v1/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.5-9b-w4a8","prompt":"The capital of France is","max_tokens":8,"temperature":0}'
```

The request returned HTTP 200 and generated `" Paris. This is a well-established fact"`. At the parent commit, the identical server configuration failed deterministically during LoRA wrapper creation at `_get_lora_device` with `AttributeError: 'NoneType' object has no attribute 'device'`.

- `pre-commit run --all-files`: changed-code checks passed. The full-tree run additionally regenerated the unrelated ROCm test lock file under the local XPU resolver and failed the unrelated non-root entrypoint case 3; the generated lock-file change was discarded.
