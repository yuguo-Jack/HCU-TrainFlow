# [Bugfix] Preserve shape tuples when decomposing size nodes

[Upstream PR](https://github.com/vllm-project/vllm/pull/62452) · state: open · merged: False

## Original PR description

## Overview

Preserve whole-shape tuples when decomposing `Tensor.size()` nodes across compilation graph partitions, including keyword arguments.

## Claims

- Fixes `torch.reshape(x, shape)` becoming an invalid flattened call after splitting.
- Rewrites keyword and nested argument references so the original size node can be removed safely. The existing `getitem` scalar path is unchanged.

## Validation

Extended the existing graph-partition tests with positional and keyword reshape cases captured by real TorchDynamo, split around sigmoid, at batch sizes 4 and 8:

```sh
uv run --no-project --python .venv/bin/python python -m pytest \
  tests/compile/test_graph_partition.py -k decompose_size -q
```

| Check | Baseline | Changed |
| --- | --- | --- |
| Project size-decomposition selection | 2 passed, 2 failed | 4 passed |
| Additional actual `VllmBackend` / standalone Inductor checks | 4 failed | 4 passed |
| Separate default-cache, mega-AOT checks | 2 failed | 2 passed |
| B300 one-layer dummy Llama, MRV2 + Inductor, CUDA graphs disabled | Generates `[30, 30]` | Generates `[30, 30]` |

The native environment uses Python 3.12 / Torch 2.14.0+cu130 / private vLLM ff01a6b14 runtime, with the affected baseline `backends.py` verified byte-identical to this PR's base and inspected main fb61ac07. This is not a claim of a complete latest-main runtime, official-weight model accuracy, warm-cache reload or performance improvement. The dummy-model check is non-regression coverage, not the bug reproducer; the Dynamo tests reproduce the bug.

Ruff check/format, whitespace checks and the project's test-tethering, SPDX, forbidden-import, new-CUDA-call and boolean-context checks pass. Full pre-commit was stopped during tool bootstrap and is not claimed passed; full CI/mypy remain unverified.

## Details

The previous code expanded the size dimensions into a user's top-level positional arguments and ignored kwargs. Use the existing `fx.map_arg` traversal over both argument trees, replacing the size node with one tuple of scalar dimensions. Default lambda arguments bind the current loop node and dimensions.

Found during source auditing. Open-PR searches for `_decompose_size_nodes`, size tuples and shape kwargs found no matching fix; no public issue ownership is claimed. AI assistance was used, and the human submitter reviewed every changed line.
