# [ROCm][Perf][Qwen4Exp] Tune sparse GQA prefill profile on gfx942 and gfx950

[Upstream PR](https://github.com/vllm-project/vllm/pull/62590) · state: open · merged: False

## Original PR description

## Overview

Tunes the >512-program (prefill) launch profile of `qsa_sparse_paged_attention` on CDNA3 (gfx942) and CDNA4 (gfx950). This PR now includes #65341 by @eppaneamd, combined as proposed and measured by @mjkvaak-amd in [this comment](https://github.com/vllm-project/vllm/pull/62590#issuecomment-6602689746):

| arch | K/V | BLOCK_M | profile (BLOCK_N, warps) |
|---|---|---|---|
| gfx942 | BF16 | >= 16 (TP1, TP2) | (32, 2), from the earlier commit of this PR |
| gfx942 | FP8, or BF16 with BLOCK_M < 16 | any | (64, 1) |
| gfx950 | BF16 / FP8 | any | (64, 1), from #65341 |
| other ROCm archs, CUDA, others | | | (64, 2), unchanged |

BLOCK_N=32 with one warp faults on gfx942 (`HSA_STATUS_ERROR_MEMORY_FAULT`, BF16, BLOCK_M=16), so the two rules are exclusive. The FP8 condition is new: the kernel accepts fp8 K/V since #61529, and BLOCK_N=32 is only 1.2x there (0.78x at TP2 with 520 rows), while one warp is 1.7-1.8x.

`get_cdna_version()` returns 3 only on gfx942 and 4 only on gfx950. The branch was merged with main to pick up the fp8 path; the PR diff against main is these two files.

## Measured results (by AMD, kernel level)

From @mjkvaak-amd's comment linked above. These were measured on a combined `qsa.py` built from the same hunk, not on this branch's commit: image `vllm/vllm-openai-rocm:nightly-40941f2c4ba96fba0a7e282a5355e89cd74d9ac5`, one MI300X and one MI355X. Speedup over main at 8,192 rows (min-max over 520 to 16,384 rows):

| arch | K/V | TP1 (24q/2kv) | TP2 (12q/1kv) | TP4 (6q/1kv) | TP8 (3q/1kv) |
|---|---|---:|---:|---:|---:|
| gfx942 | bf16 | 1.94x (1.80-2.03) | 1.92x (1.39-2.14) | 1.19x (1.17-1.32) | 1.19x (1.14-1.20) |
| gfx942 | fp8 | 1.76x (1.69-1.79) | 1.84x (1.07-1.84) | 1.33x (1.17-1.36) | 1.29x (1.15-1.43) |
| gfx950 | bf16 | 1.63x | 1.69x | 1.37x | 1.25x |
| gfx950 | fp8 | 1.56x | 1.59x | 1.79x | 1.24x |

The combined rule was faster than either PR alone, or equal to the better one, in every measured cell. Outputs are bitwise equal to main except gfx942 BF16 at TP1/TP2 (BLOCK_N=32), which differs by at most 2.0e-3 absolute from accumulation order; rel_l2 against an fp64 reference matches main's for every variant. With that `qsa.py`, the reference test (main's cases plus `tp2_split1`, `tp1_split1_prefill` and two extra shapes, bf16 and fp8) gave 18 passed on both MI300X and MI355X.

```python
    else:
        block_n, target_splits, partial_warps = 64, 1, 2
        if current_platform.is_rocm():
            from vllm.platforms.rocm import get_cdna_version

            # One warp per program is faster on CDNA3 and CDNA4, except BF16
```
