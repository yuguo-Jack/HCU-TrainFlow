## Original PR description

### Description
This PR adds character-level throughput metrics (`output_char_throughput` and `mean_chars_per_token`) to `vllm bench serve` to address benchmarking distortion for non-Latin / multilingual workloads where token-to-character ratios vary significantly.

### Fixes
Fixes #51963

### Changes
- Integrated `total_output_chars`, `output_char_throughput`, and `mean_chars_per_token` calculations.
- Formatted terminal table output and added JSON output support in `--save-result`.
- Added CPU unit tests covering multilingual Unicode (CJK/Thai) and empty edge cases.

**[P2] Avoid publishing character metrics with inconsistent or synthetic semantics**

`total_output_chars` currently counts whitespace even though the linked issue specifies non-whitespace characters by default, while this ratio can use the `output_len = 1` fallback when no tokenizer or backend usage is available. Consequently, whitespace-only output reports positive throughput and `--skip-tokenizer-init` runs can persist an invented chars/token value. Please apply the specified whitespace rule, make `mean_chars_per_token` unavailable or nullable unless its denominator is a measured token count, and add regressions for whitespace-only and no-tokenizer/no-usage responses.
