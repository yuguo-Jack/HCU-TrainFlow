# [Bugfix][Spec Decode] Fix DeepSeek V4 DFlash input and cache formats

[Upstream PR](https://github.com/vllm-project/vllm/pull/58759) · state: open · merged: False

## Original PR description

## Purpose

Addresses #58733: DeepSeek-V4-Flash with the RedHatAI DFlash checkpoint fails during draft attention setup or profiling, and its published FC weight shape does not match the existing hidden-state path.

- Fall back to model-dtype draft KV storage when the target uses `fp8_ds_mla`, preserving explicit draft overrides. Share the resolution between model loading and attention metadata configuration, including the legacy runner.
- Keep the DFlash context buffer at the projected draft width (4096), rather than the raw HC residual width (16384).
- Infer the FC input width from `hc_mult` when `target_hidden_size` is absent, and export full stream-major auxiliary states from the NVIDIA DeepSeek V4 target when requested by the draft. Preserve mean-pooled states for other drafters and size PP receive buffers to the exported width.

For this checkpoint, five 16384-wide auxiliary states feed an `[4096, 81920]` FC weight and produce 4096-wide context features. The training-side HC handling is documented in https://github.com/vllm-project/speculators/pull/524.

The patch changes six existing source files, with no new files or test changes. It is scoped to the NVIDIA target implementation reported in the issue.

Duplicate check: no open PR references #58733. Related #48381 addresses DSpark KV storage and DCP; it does not fix this DFlash buffer/FC/auxiliary-state path.
