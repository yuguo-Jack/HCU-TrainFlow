# [CI][CPU] Initialize DFlash test FC after loading weights

[Upstream PR](https://github.com/vllm-project/vllm/pull/63973) · state: closed · merged: True

## Original PR description

## Overview

Closes #63972. Initialize the DFlash dtype regression's FC through its existing post-load hook before the first forward, fixing the deterministic `cpu_linear` error in **CPU-Spec Decode Tests**.

## Claims

- The existing FP32-to-draft-dtype test now runs on a CPU platform.
- Retains the test's dtype and output assertions; no runtime code, skips or tolerances change.

## Validation

macOS arm64, Python 3.12, torch 2.14.0; base `5d35ce39`.

```bash
VLLM_TARGET_DEVICE=cpu .venv/bin/python -m pytest \
  --confcutdir=tests/v1/spec_decode \
  tests/v1/spec_decode/test_dflash2.py::test_dflash_fc_runs_fp32_target_hidden_states_in_draft_dtype -q
```

Before: **1 failed** with `AttributeError: 'ReplicatedLinear' object has no attribute 'cpu_linear'`. After: **1 passed**.

```bash
VLLM_TARGET_DEVICE=cpu .venv/bin/python -m pytest \
  --confcutdir=tests/v1/spec_decode \
  tests/v1/spec_decode/test_dflash2.py \
  tests/v1/spec_decode/test_dflash_causality.py -q
.venv/bin/pre-commit run --files tests/v1/spec_decode/test_dflash2.py
git diff --check
```

**26 passed, 92 skipped** (existing accelerator-only cases); applicable hooks and diff check passed. Intel CPU packed-GEMM execution remains pending CI. This test-only setup correction does not change model behavior or require model evaluation.

## Details

The test added in #63436 directly initializes `fc.weight` and calls forward, bypassing the loader's post-load processing. The CPU linear implementation requires that processing to initialize `cpu_linear`. Run the same hook after filling the weight.

The exact base fails in [main CI #97527](https://buildkite.com/vllm/ci/builds/97527#01a17bf7-46e5-4f1f-bc9e-95f8e3cd8d54); #63972 records the traceback and another occurrence. The existing `cpu-spec-decode-tests` job already selects this file, so no CI configuration change is needed.

Duplicate checks found no fix for this test. #55318 concerns Tensorizer loading, and #57733 concerns model-loader finalization; neither covers this direct-construction test. #62796 only records the unrelated CI failure.

AI assistance was used for diagnosis, the one-line change, review and local validation.
