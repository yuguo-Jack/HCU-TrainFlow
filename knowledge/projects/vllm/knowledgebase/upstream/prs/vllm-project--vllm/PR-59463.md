# [Core] Add lifecycle hooks for worker extensions

[Upstream PR](https://github.com/vllm-project/vllm/pull/59463) · state: closed · merged: True

## Original PR description

## Purpose

Related to https://github.com/vllm-project/vllm/issues/59120. Worker extensions currently require callers to initialize their state manually. This change adds optional `init_worker_extension()` and `destroy_worker_extension()` hooks: initialization runs after device and distributed setup, and cleanup runs before worker shutdown. Hooks are selected from the configured extension class, so a previously injected extension cannot be called by mistake. Ray executors currently force-kill worker actors, so cleanup is not guaranteed on Ray shutdown.

Currently the implementation is a rough initial draft. Will need further discussion in https://github.com/vllm-project/vllm/issues/59120.

AI assistance: OpenAI Codex assisted with implementation and review.

- aoshen02 · COMMENTED · 2026-10-02T14:08:51Z · [source](https://github.com/vllm-project/vllm/pull/59463#pullrequestreview-5392787614)

Reviewed commit `3461bd74f68ed2498b4c07e6a019aee2f3ad4311` with the current Codex model, Claude Opus 5.5, and Kimi K3. Both external reviewers completed their reports; the conclusions below were cross-checked against the implementation.

One P2 shutdown robustness issue is recorded inline: a failing extension destroy hook still allows `worker.shutdown()`, but aborts the remaining engine/executor teardown. No P0/P1 issue was confirmed.

Before finalizing the hook API, please document the contract beside `ParallelConfig.worker_extension_cls` or in the worker-extension documentation:
- Define the supported signature as an ordinary instance method, e.g. `def init_worker_extension(self)`, with no extra arguments. The current class lookup plus explicit worker argument is not normal descriptor binding for a no-argument static/class method.
- Init runs after device/distributed setup and before model loading/KV-cache initialization. Destroy is best-effort; Ray force-kill does not guarantee it, and failed startup currently does not guarantee a matching destroy call.
- State whether repeated shutdown and partial initialization must be tolerated by the extension. Avoid promising exactly-once paired lifecycle callbacks without implementing that guarantee.

Simplicity/test suggestions (non-blocking): the production change is already small, so no generic hook dispatcher or framework is needed. Keep configured-class lookup and `self.__dict__.get("worker")`; replacing these with unconditional instance lookup or ordinary `getattr(self, "worker", None)` can reintroduce stale-extension dispatch or `__getattr__` recursion. Preserve the existing sequential A/B/A test because it intentionally exercises persistent class injection. Add a focused failure-path test that checks outer scheduler/distributed cleanup, rather than asserting only the inner worker shutdown. The pre-existing conflict between two injected classes that both define the same methods is a limitation to document/test, not a new independent regression to attribute to this patch.

Validation: the new `tests/v1/worker/test_worker_base.py` passed (1 test). CPU probes using the actual wrapper and unchanged shutdown-method bodies with mocked collaborators confirmed skipped outer cleanup on a hook exception. No GPU, real distributed-executor, or Ray end-to-end run was performed; broader worker tests are limited by missing CUDA extensions. This is a COMMENT review, not an approval or a claim of complete runtime validation.

[P2] Finish outer teardown when an extension destroy hook fails

The `finally` guarantees `worker.shutdown()`, but the hook exception still escapes afterward. On the in-process path, `UniProcExecutor.shutdown()` propagates it through `EngineCore.shutdown()` before `scheduler.shutdown()`, `gc.unfreeze()`, and `cleanup_dist_env_and_memory()` can run. On the multiprocess path, it also skips `WorkerProc.shutdown()`'s `destroy_model_parallel()` and `destroy_distributed_environment()`. This is especially relevant to colocated training/inference that keeps the hosting process alive. CPU probes with the unchanged shutdown methods reproduce the skipped cleanup; the new test only checks that the inner worker shutdown ran. Please catch and log ordinary extension teardown errors while continuing cleanup, or ensure every outer cleanup step runs before re-raising. Add a regression test for that outer failure path.
