# [KV Connector][NIXL] Register packed MLA KV rows as a single region

[Upstream PR](https://github.com/vllm-project/vllm/pull/61074) · state: closed · merged: True

## Original PR description

## Purpose

With a block-outermost KV cache layout (`VLLM_KV_CACHE_LAYOUT=BLHNC`), all layers' pages of a block sit in one contiguous row. 
NIXL still registers one region per layer, so each block moves as one descriptor per layer (effectively rendering BL* useless). 

This PR registers the row once, fixing registration back to its intended use.

Example: GLM-5.3-NVFP4, TP4, BLHNC. Input to `register_kv_caches` on rank 0 is 99 views over one 43.8 GB storage:

```
model.layers.0.self_attn.indexer.k_cache  (14323, 1, 64, 132)  stride(0)=3059712  offset 0
model.layers.0.self_attn.attn             (14323, 1, 64, 576)  stride(0)=3059712  offset 177408
...

row b: [ idx L0 | idx L1 | ... | mla L0 | mla L1 | ... | mla L77 ]   3059712 B
```

**Before** (`elif storage_is_block_major:` branch), each view is its own region:

```
region 0:  base S + 177408, block_len 36864, stride 3059712   # layers.0.attn
region 1:  base S + 0,      block_len 8448,  stride 3059712   # layers.0.indexer
...
-> 99 regions, 99 x 14323 = 1.42M descriptors; a 2-block request = 198 descriptors
```

**After** (the existing whole-row branch, previously push-only), every view emits the same region and dedup folds them into one:

```
region 0:  base S, block_len 3059712, stride 3059712           # whole row, all layers
-> 1 region, 14323 descriptors; a 2-block request = 2 descriptors
```

### HiSparse

A HiSparse decoder can't register rows: its MLA cache is in host DRAM and its indexer on GPU, so it keeps per-layer regions LB*. 
P can still advertise each layer's `(offset, page_size)` within the row (BL*).
When the peer is per-layer, `_split_remote_packed_rows` (added with this PR) maps P's row onto the peer's per-layer regions.
 
BLHNC P + HiSparse D therefore works as before, with the same descriptor count as `main`.
cc @LucasWilkinson the alternative is to enforce P also uses LB* here, not sure if there's disadvantages (considering .

Out of scope: GQA spec-decode drafts under an MLA target, deferred to #60564.

## Related PRs

#60851 and #60564 target the same descriptor blow-up. #60564 puts whole rows behind an opt-in `whole_row_regions` flag that must be set on both P and D, and rejects HiSparse. Here it is the default for BLHNC, needs no flag, and HiSparse decoders keep working. 

#60564 also handles GQA draft head-sharding, which this PR leaves to it.
