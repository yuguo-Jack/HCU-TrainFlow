# [Bugfix][LoRA] Scale embedding LoRA deltas by the base layer's embed_scale

[Upstream PR](https://github.com/vllm-project/vllm/pull/62470) · state: open · merged: False

## Original PR description

## Overview

On Transformers-backend models with a scaled input embedding (VaultGemma; Gemma with `--model-impl transformers`), an `embed_tokens` LoRA adapter gets only `1 / embed_scale` of its effect. This scales the LoRA delta by the embedding's `embed_scale`, matching PEFT.

## Claims

- For an embedding that carries `embed_scale` (a Transformers `*ScaledWordEmbedding` after the backend rebases it), the `embed_tokens` LoRA output now matches PEFT 0.21.1.
- Embeddings without `embed_scale` (all native vLLM models) are unchanged.
- No per-step cost: the scale is applied once in `set_lora`, in place on the device copy.

## Validation

Tiny VaultGemma (random weights saved with `save_pretrained`) and a PEFT 0.21.1 adapter with `target_modules=["embed_tokens"]`, same token ids on both sides. PEFT reference: `PeftModel.get_input_embeddings()(ids)`. vLLM: `EngineArgs(enable_lora=True)` -> `get_model` (`TransformersForCausalLM`, embedding `VaultGemmaTextScaledWordEmbedding`) -> `load_lora_model` -> `set_active_adapters` -> `embed_input_ids`.

| | `main` | this PR |
|---|---|---|
| LoRA delta, vLLM / PEFT | 0.0625 (`1 / embed_scale`, `embed_scale = 16`) | 1.0000 |
| max abs diff vs PEFT embeddings | 1.11 | 2.4e-07 |
| max abs log-prob diff (HF forward on each embedding) | 1.18 | 0.000 |

```
pytest tests/lora/test_layers.py -k test_embeddings
```
48 passed. The new `embed_scale=16.0` cases (24) fail on `main` with every element mismatched.

Full `tests/lora/test_layers.py` on CPU: the same 102 tests fail on `main` and with this change (`'OffsetReplicatedLinear' object has no attribute 'cpu_linear'`, from this machine's build), so no new failures.

Not run: a GPU end-to-end serving run (no GPU available).

## Details

Root cause: the Transformers backend rebases a HF `*ScaledWordEmbedding` onto `VocabParallelEmbedding` and keeps its `forward`, which returns `lookup * embed_scale` (`replace_embedding_class` in `transformers/utils.py`). `VocabParallelEmbeddingWithLoRA.forward` calls that `base_layer.forward` and then adds the unscaled LoRA delta. PEFT's LoRA `Embedding.forward` multiplies the adapter output by `embed_scale` (huggingface/peft#2825, released in 0.18.0), and a merged adapter is scaled by construction.

Fix: in `set_lora`, multiply the slot's `lora_b` by `embed_scale` after copying it to the device.

Affected: VaultGemma (Transformers backend by default) and Gemma 1 to 4 with `--model-impl transformers`, which is the only way to load an `embed_tokens` LoRA for Gemma since the native classes do not declare `embedding_modules`. Native models with an embedding multiplier (Granite, MiniCPM, Falcon-H1, HyperCLOVA X) apply it after the LoRA-wrapped lookup and are unaffected.

Limitation: adapters trained with PEFT 0.17 or earlier saw an unscaled delta in the unmerged training forward. This change follows current PEFT and merged-adapter behavior.

Duplicate check: no open or closed PR or issue covers this (searched `embed_scale lora`, `ScaledWordEmbedding`, `VocabParallelEmbeddingWithLoRA`, `vaultgemma lora`, `transformers backend lora embedding`, `lora embed_tokens gemma`).
