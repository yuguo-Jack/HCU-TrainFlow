# [ROCm][Perf] Use AITER tuned configs to select a4w4 gemm kernel instead of env var

[Upstream PR](https://github.com/vllm-project/vllm/pull/61278) · state: closed · merged: True

## Original PR description

## Purpose

`VLLM_ROCM_USE_AITER_FP4_ASM_GEMM` is currently used to select the weight layout (preshuffled vs plain) for every layer. With preshuffled layout, ASM gemm is used for prefill and preshuffled Triton gemm for decode. 

In previous PRs, attempted to remove the environment variable altogether and default to on, but caused regressions because various models (Kimi, DS) do not have tuned preshuffled Triton decode kernels. Ideally we would like to have this active for the models that it helps (Llama, mostly) without the environment variable. 

This PR removes the environment variable and decides per layer at weight-load time. A layer takes the preshuffled (ASM) layout only when aiter has tuned configs for both the ASM and Triton preshuffled kernels.

### Serving setup

MI350X ×8, fresh server per arm, two restarts per arm. "Before" is `VLLM_ROCM_USE_AITER_FP4_ASM_GEMM=0` on main.

```bash
VLLM_ROCM_USE_AITER=1 vllm serve $MODEL -tp $TP --no-enable-prefix-caching \
  --disable-uvicorn-access-log --trust-remote-code --max-model-len 16384 --load-format dummy

vllm bench serve --model $MODEL --trust-remote-code --dataset-name random \
  --random-input-len 1024 --random-output-len 1024 --ignore-eos --temperature 0 \
  --percentile-metrics ttft,tpot,itl,e2el --max-concurrency $C --num-prompts $((4 * C))
# C = 1 4 8 16 32 64 128 for Llama-3.3-70B (min 8 prompts); C = 1 (8 prompts) and 32 (192 prompts) for the other models
```
