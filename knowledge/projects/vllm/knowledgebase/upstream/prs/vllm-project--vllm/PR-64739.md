# [Model Loader] Find safetensors shards listed in a subdirectory

[Upstream PR](https://github.com/vllm-project/vllm/pull/64739) · state: open · merged: False

## Original PR description

## Overview

Lets the default loader find safetensors shards that `model.safetensors.index.json` lists in a subdirectory. NVIDIA's FP4-Local checkpoints keep shards under `tensors/`: Qwen3.8-Flash-Next-FP4-Local has all 21 there, and GLM-5.3-Flash-FP4-Local has one there next to 41 shards in the repo root. The loader only globs the root, so on main the first finds no weights and the second fails the index check with `Weight files referenced in index but missing`.

Split out of #64312, which needs this to load either checkpoint from the Hub.

## Claims

- When the index is present, `_prepare_weights` also takes safetensors from subdirectories, and the existing index filter keeps only the ones it lists. Without an index, nested files are ignored as before.
- A Hub snapshot with nested safetensors fetches the index once, before this check. Other repos make no extra request.
- `hash_checkpoint` in the IPC weight cache does the same, so its key covers the nested shards.
- Sources with explicit allow patterns don't change.

## Validation

On CPU, main (`335dd77b09`) plus this PR:

```text
pytest tests/model_executor/model_loader/test_filter_duplicate_safetensors.py  # 8 passed
pre-commit run --files <changed files>                                          # passed
```

The new test covers a Hub snapshot with shards only under `tensors/`, one with shards in the root and under `tensors/`, and a `.bin`-only one. The first two fail on main.

On a local copy of Qwen3.8-Flash-Next-FP4-Local with the Hub layout, `_prepare_weights` returns exactly the 21 shards the index lists and `hash_checkpoint` returns a key. Main raises `Cannot find any model weights` on the same copy.
