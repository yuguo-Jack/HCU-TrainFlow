# Skip out-of-window partial-tail store jobs instead of crashing EngineCore (#61970)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62012) · state: open · merged: False

## Original PR description

Fixes #61970

## What does this PR do?

In the native KV-offloading scheduler, `_build_partial_tail_store_jobs()` asserted `boundary <= max_boundary`, crashing the whole EngineCore when a retained Mamba boundary-state snapshot exceeds the request's *current* offloadable window (e.g. after a resume with a smaller `max_offload_tokens` / `num_prompt_tokens`) — the exact scenario of hybrid Attention/Mamba deployments in the issue (Kimi-K3, long context, high concurrency).

The sibling path for the **same** handoffs, `_build_aligned_boundary_store_jobs()`, already handles the identical out-of-window condition by **skipping the store job** (`continue`). The mooncake connector's analogous boundary handling skips the same way. This PR makes the partial-tail path mirror that established semantics — log a warning (with req id, boundary and window numbers) and skip — instead of crashing.

The removed assertion guarded a runtime-recoverable race, not an invariant: all structural checks (`boundary > 0`, hash alignment, single boundary per request, CoW block consistency) are preserved and still assert.

## Tests

New `tests/v1/kv_offload/test_offloading_partial_tail_skip.py` (CPU-only, no GPU needed): loads the real module source with minimal dependency stubs, hand-assembles the hybrid Attention + Mamba-CoW configuration and drives `_build_partial_tail_store_jobs` directly.

- Red (pristine module): the exact `AssertionError: boundary <= max_boundary` from the issue reproduces (boundary=40 vs window=32).
- Green (patched): the job is skipped with zero state pollution (no jobs/counters/transfer side effects), the warning fires; a normal in-window partial-tail job is still built with all fields intact; the preserved hash-alignment invariant still asserts; the aligned path behaves bit-identically before and after the fix. 9/9 pass.

## Notes

GPU/e2e reproduction (real hybrid model under load) was not possible on this machine; the unit test drives the actual scheduling code path directly instead.
