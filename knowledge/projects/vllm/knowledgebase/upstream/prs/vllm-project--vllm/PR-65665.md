# [hw-agnostic] Triton attention backend for the Transformers backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/65665) · state: open · merged: False

## Original PR description

## Overview

Adds a hw-agnostic copy of the Triton attention backend. With `VLLM_USE_HW_AGNOSTIC=1`, the Transformers backend uses it for its decoder attention layers instead of the backend the platform would select. This is the attention counterpart of the hw-agnostic norm, activation and linear layers (#60218, #65454).

## Claims

- `vllm.model_executor.hw_agnostic.v1.attention.backends.triton_attn` is a copy of `vllm/v1/attention/backends/triton_attn.py` without its platform-specific fast paths. The Triton kernels are shared with in-tree.
- With `VLLM_USE_HW_AGNOSTIC=1`, every decoder `Attention` layer the Transformers backend builds uses it, including sliding-window and heterogeneous head sizes (e.g. Gemma 4's 256 sliding / 512 full).
- Accuracy is unchanged against the platform-selected backend (FlashAttention, FlashInfer). It also works under `torch.compile` with full CUDA graphs and at TP=2.
- No behavior change when `VLLM_USE_HW_AGNOSTIC` is unset: the platform still selects the backend.

## Validation

End-to-end (GPU, in "Basic Models (Other)"). The existing tiny-Llama test now also reports which attention backend each layer uses. It must be the platform's with the variable unset and the hw-agnostic one with it set, and logprobs must match:

```bash
pytest -q tests/models/transformers/test_layer_registry_e2e.py
# 1 passed (1x A100)
# with the base.py change reverted:
#   {'attn_backend': 'vllm'} != {'attn_backend': 'hw_agnostic'}
```

Unit tests (`test_layer_registry.py` 12 passed, 2 xfailed; `test_backend.py -k attention` 11 passed), `pre-commit run` and the mypy hook pass.

Run outside CI, which has no eval, TP=2 or compiled run for this path. Tiny Llama, greedy, 16 tokens, 2 prompts, variable `0` vs `1`:

| Setup | Backend (`0` → `1`) | Tokens | max \|Δ logprob\| |
|---|---|---|---|
| TP=2, eager | FLASH_ATTN → hw TRITON_ATTN, both ranks | 32/32 | 3.9e-3 |
| TP=1, `VLLM_COMPILE` + `FULL_AND_PIECEWISE` CUDA graphs | FLASH_ATTN → hw TRITON_ATTN | 32/32 | 3.9e-3 |

The differences are expected for a different attention kernel and stay well below what would flip a token.

Model evaluation, gsm8k 5-shot, all 1319 questions, 1x A100 80GB, `enforce_eager=True`:

```bash
VLLM_USE_HW_AGNOSTIC={0,1} lm_eval --model vllm \
  --model_args "pretrained=ibm-granite/granite-4.2-8b,model_impl=transformers,tensor_parallel_size=1,gpu_memory_utilization=0.85,max_model_len=4096,enforce_eager=True" \
  --tasks gsm8k --num_fewshot 5 --batch_size auto
```

| Model | Metric | `VLLM_USE_HW_AGNOSTIC=0` | `VLLM_USE_HW_AGNOSTIC=1` | Δ |
|---|---|---|---|---|
| `ibm-granite/granite-4.2-8b` (FLASH_ATTN → hw TRITON_ATTN) | flexible-extract | 0.7930 ± 0.0112 | 0.7945 ± 0.0111 | +0.0015 |
| | strict-match | 0.8302 ± 0.0103 | 0.8340 ± 0.0102 | +0.0038 |
| `google/gemma-4-E2B-it`¹ (FLASH_ATTN + FLASHINFER → hw TRITON_ATTN) | flexible-extract | 0.6550 ± 0.0131 | 0.6611 ± 0.0130 | +0.0061 |
| | strict-match | 0.4913 ± 0.0138 | 0.4905 ± 0.0138 | −0.0008 |

All differences are below one stderr. With the variable set, the log shows `Using hardware agnostic attention backend TRITON_ATTN`. On Gemma 4, all 35 attention layers use the hw-agnostic backend: 28 sliding-window with head size 256, and 7 full with head size 512.

¹ Gemma 4 was run with `--apply_chat_template --fewshot_as_multiturn` and `limit_mm_per_prompt` 0 for image, audio and video. Without disabling audio, startup fails on `main` with the variable at both `0` and `1` ("Unable to get max input length from Gemma4AudioConfig"), which is unrelated to this PR. The variable-`1` run also had the not-yet-merged hw-agnostic embedding, linear and GeGLU changes applied, so it exercises the full hw-agnostic stack.

## Details

- **Size.** About 850 non-test lines are added, but 822 of them are the copy of `triton_attn.py`. It differs from in-tree in about 75 lines, so the diff against in-tree can be reviewed directly. The new logic is a 22-line change in `base.py`.
- **The backend is ported, the layer is not.** The engine and the compile passes find attention layers by the in-tree `Attention` class, e.g. `get_layers_from_vllm_config(config, Attention)` for KV-cache specs and sharing. So the layer stays in-tree and only its backend changes. The backend is passed as `attn_backend=`, the argument native models already use to pin a backend. `get_name()` stays `"TRITON_ATTN"`, because `Attention.__init__` looks it up in `AttentionBackendEnum`.
- **Not through `hw_agnostic.resolve`.** `resolve` returns layers from `vllm.model_executor.layers`, and with the variable unset a backend must not be pinned at all; the platform must keep selecting. So the variable is checked directly where the layers are built.
- **What the copy removes:**
  - ROCm: the AITER fused RoPE and KV-cache update, the 32-bit KV pointer range, and FP8 query quantization.
  - XPU: tensor descriptors, including the `VLLM_TRITON_USE_TD` override.
  - CUDA: FP8 query quantization, and the SM120 64-segment split-K.

  The flags are set to `False`, or to `0` segments, rather than removing every call site, to keep the diff against in-tree small.
- **What the copy keeps:** `customize_spec`, which sizes the KV cache for the per-token-head quantization modes, and the CUDA check that rejects FP8 KV cache below SM89 and bfloat16 KV cache below SM80. Both concern correctness, not speed.
- **Triton is required.** Without a usable Triton (`HAS_TRITON`), building the model raises `NotImplementedError` instead of failing at the first kernel launch or silently using another backend.
- **Trade-offs.** With the variable set, the platform's choice is overridden: on CUDA, FlashAttention and FlashInfer are not used, and on ROCm, the AITER paths aren't either. This may cost speed, and has not been measured. The variable is off by default.
- **Limitations:**
  - Encoder-only and MLA attention keep the platform's selection. `EncoderOnlyAttention` wraps the backend the selector picks, and the Triton backend does not implement MLA.
  - A backend passed as `attn_backend=` skips the selector's `validate_configuration`, as it does for native models that pin a backend. An unsupported configuration therefore fails in the backend rather than with the selector's message.
  - Out-of-tree platforms choose their backend in `Platform.get_attn_backend_cls`, which is not consulted with the variable set. An override hook for the hw-agnostic backend, analogous to `register_oot` for layers, is left for a follow-up.
