# [CI] Run 4xB200 steps nightly only

[Upstream PR](https://github.com/vllm-project/vllm/pull/61541) · state: closed · merged: True

## Original PR description



## Overview

Run the two remaining per-PR 4xB200 steps only on nightly builds: `(4xB200) Kimi K3 Prefix Cache` (2 shards) and `(B200) Distributed MooncakeConnector PD accuracy` (4 GPUs). The other 4xB200 steps (LM Eval HiSparse, PCP, Spec Decode, Qwen3.8 accuracy) are already `optional`.

## Claims

- On PR and main builds these steps are skipped unless someone requests them. Nightly and daily Full CI builds still run them.
- The `:amd: (MI355) Distributed MooncakeConnector HIP PD accuracy` mirror stays per-PR (`optional: false`, as kernels.yaml and distributed.yaml already do).

## Validation

- ci-infra `_step_should_run` returns True for every step on nightly builds, and False for `optional` steps otherwise. So these steps now run only on nightly/daily builds, or when requested explicitly.
- The mirror's `optional` comes from `amd.get("optional", step.optional)`, so the explicit `false` keeps the AMD job's current behavior.
- pre-commit passes, including the step-key and test-tethering checks.

## Details

**Why.** A read-only look at the b200-k8s cluster (01:35Z Oct 14) showed 6 schedulable nodes with 47 GPUs, all in use, and **22 pods pending, every one asking for 4 GPUs**. Some had waited about 3 hours, for example build 94519's Kimi K3 Prefix Cache shard. Freed GPUs go to 1- and 2-GPU pods first, so a node rarely has 4 free GPUs at once. Pods that wait too long are failed by agent-stack-k8s as `stack_error`. This is the same pattern seen on main's daily builds since Oct 5.

**Tradeoff.** PRs touching `vllm/models/kimi_k3/`, the Mooncake connector, or the other source dependencies of these steps no longer get these tests per PR. Regressions show up on the next nightly instead. Authors can still request the steps explicitly.

**Not a duplicate:** I searched open PRs for these step keys and found none.
