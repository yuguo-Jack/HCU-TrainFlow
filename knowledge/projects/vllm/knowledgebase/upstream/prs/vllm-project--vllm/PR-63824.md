# [KV Offload][KVCR] Serve KVCR Guard-owned blocks without framework source handoff

[Upstream PR](https://github.com/vllm-project/vllm/pull/63824) · state: open · merged: False

## Original PR description

## Summary

Allow a secondary KV-offload tier to suppress publication of primary CPU cache events. The manager still drains those events and continues publishing events from secondary tiers.

This is the generic tiering change needed by the KVCR Guard integration in [mkhazraee/vllm#5](https://github.com/mkhazraee/vllm/pull/5). That integration adds the `no_pinning_mode` option and sets `suppresses_primary_events` when Guard owns the remotely servable blocks. The Guard source transfer implementation is in [ai-dynamo/kvcr#127](https://github.com/ai-dynamo/kvcr/pull/127).

## Implementation

- Check whether any secondary tier sets `suppresses_primary_events` before publishing primary-tier events.
- Continue draining the primary event stream and publishing every secondary-tier event.
- Test the event selection with a Guard-owned CPU event and an unrelated secondary-tier event.

## Tests and scope

The PR changes `tiering/manager.py` and `test_tiering_offloading.py` only. It does not add the KVCR option or change EngineCore shutdown behavior; those changes live in separate PRs. AI assistance was used to update this description after the PR scope changed.
