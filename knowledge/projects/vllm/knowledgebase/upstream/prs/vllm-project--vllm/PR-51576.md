# [KV Offload] Add TieringAdmissionPolicy skeleton (factory/base/always)

[Upstream PR](https://github.com/vllm-project/vllm/pull/51576) · state: open · merged: False

## Original PR description

## Purpose

First step of #51240 ([RFC] Tiering Admission Policy Design): adds the
`TieringAdmissionPolicy` ABC, `AlwaysAdmitPolicy` (no-op default, matches
current behavior exactly), and `AdmissionPolicyFactory` (config-dict
registry, mirrors `SecondaryTierFactory`).

Scope matches what @orozery proposed on the RFC thread: no metrics, no
concrete backpressure/concurrency policies, not wired into the manager yet.
Those are explicit follow-ups, not part of this PR.

## Not a duplicate

Checked open/closed PRs referencing #51240, `TieringAdmissionPolicy`,
`AdmissionPolicyFactory`, `always_admit`, and the
`kv_offload/tiering/admission` path -- no existing PR implements this.
\#50087 also touches an "admission" concept but at a different layer
(GPU-scheduler store-candidate selection, not this RFC's job-submission
gate) and doesn't touch `tiering/`.

## Test plan

```
.venv/bin/python -c "
from vllm.v1.kv_offload.tiering.admission.factory import AdmissionPolicyFactory
p = AdmissionPolicyFactory.create_policy({'type': 'always_admit'})
assert p.should_admit(None) is True
"
pre-commit run --files vllm/v1/kv_offload/tiering/admission/*.py
```

## Test result

Import + instantiation via the factory works; `pre-commit` (ruff, mypy,
SPDX headers) passes clean. No behavior-affecting tests yet since nothing
is wired into the manager -- this PR only adds the interface and a no-op
default implementation.
