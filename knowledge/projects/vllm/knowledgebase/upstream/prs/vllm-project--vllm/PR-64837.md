# [Tests] Handle Triton async compile cleanup callback

[Upstream PR](https://github.com/vllm-project/vllm/pull/64837) · state: open · merged: False

## Original PR description

## Overview

Fix the async warmup failure regression test for Triton's new `cleanup_fn` argument while retaining compatibility with Triton 3.8. AI assistance (Codex) was used; this draft is for human review.

## Claims

- The test reaches its intended compile-failure and context-restoration assertions instead of failing at `AsyncCompileMode.submit()` argument binding.
- Signature inspection supplies the no-op cleanup callback only when supported. Production code and the existing assertions are unchanged.

## Validation

Executed the upstream test file in a CUDA sandbox using Python 3.14.7 and Triton `3.9.0.dev20261027+cuda.13.4.sm120.znver4.ga5f620fa`. The installed vLLM runtime is our fork; its original warmup modules were restored during this validation so the separate compiler fixes were not involved.

```sh
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 CUDA_VISIBLE_DEVICES=2 \
  /opt/trim-wheels-20261030/bin/python -m pytest \
  --noconftest --import-mode=importlib -q --tb=short \
  /opt/trim-wheels-20261030/test_upstream_async_cleanup.py
```

The file above is a copy of this PR's test file. Before the fix, the affected case failed with `TypeError: AsyncCompileMode.submit() missing 1 required positional argument: 'cleanup_fn'`. After the fix, the complete file reports **15 passed**.

Also executed the exact patched submission block with the official Triton v3.8.0 and current main `_async_compile.py` implementations. Both propagated the intended `RuntimeError("warmup failed")` and cleared `active_mode`. This checks both API shapes, rather than claiming a full Triton 3.8 environment run.

`pre-commit run --files tests/model_executor/test_jit_warmup_triton_launcher.py`, Ruff check/format, and `git diff --check` pass. Model evaluation is not applicable to this test-only change.

## Details

[triton-lang/triton#11552](https://github.com/triton-lang/triton/pull/11552) added the required cleanup callback. Triton v3.8.0 still has the three-argument form, so unconditionally adding a fourth argument would break that version. The test inspects the supported signature and preserves the same failure injection for both forms.

Checked open upstream PRs for `cleanup_fn warmup` and `AsyncCompileMode submit`; no duplicate was found. No public serving behavior, documentation, or kernel math changes.
