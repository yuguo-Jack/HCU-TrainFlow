# [ROCm][DSv4.1] Share Engram host tables across DP ranks with HIP VMM

[Upstream PR](https://github.com/vllm-project/vllm/pull/65595) · state: open · merged: False

## Original PR description

- `amd/ops/engram_host_table.py`: ROCm counterpart of the CUDA host-NUMA cuMem tables. Rank 0 allocates HIP VMM host memory and sends each chunk's dmabuf FD to the other DP ranks over a unix socket under /dev/shm
- `engram.py`: use it on ROCm; any failure on any rank still falls back to /dev/shm everywhere
- `test_engram_dp_shard.py`: run the shared-table test on ROCm, including the host-table success, create-failure and import-failure cases

Follow-up to #62298, which runs `test_engram_dp_shard.py` on AMD by guarding its CUDA-only imports. This PR adds a ROCm path for the shared host tables that #62359 added for CUDA, so DP-shared Engram tables work the same way on both platforms. HIP can't export host allocations as FABRIC handles (`hipErrorInvalidValue` on MI350X, HIP 7.15), so the tables are shared as POSIX FDs over SCM_RIGHTS. HIP also gives peers no CPU access to imported host allocations, so the CPU maps the dmabuf FDs directly. HIP currently ignores the requested host NUMA node, so the creator watches host-wide free memory as well as the GPU's node. On 4x MI350X this doesn't change serving speed or accuracy. Its gains are faster table placement and roughly 3% faster lookups in isolation, without needing shmem THP on the host. I'm opening it as a draft to hear whether that parity is worth a ~300-line module. Searches for ROCm Engram host-table sharing found no open PR; #64082 is CUDA-only cross-instance sharing.

| DeepSeek-V4.1-Flash, DP2 x TP2, 4x MI350X | /dev/shm (main) | HIP VMM (this PR) |
|---|---|---|
| GSM8K 5-shot (lm_eval) | 0.928 ± 0.007 | 0.933 ± 0.007 |
| `vllm bench serve` output tok/s, 3 runs | 663 / 680 / 711 | 700 / 709 / 706 |
| Median TPOT (ms), 3 runs | 88.1 / 88.0 / 86.6 | 87.3 / 86.8 / 87.0 |
| Engram table placement (4 x 47 GiB) | 38 s | 5 s |
| Lookup kernel, 32 GiB table, 16384 tokens | 3045 µs | 2946 µs |

The baseline's first two serving runs were still warming up (eager mode). Serving ran random 1024 in / 256 out, 512 prompts, concurrency 64, with `VLLM_ROCM_USE_AITER=1`, fp8 KV and expert parallel. `pytest tests/distributed/test_engram_dp_shard.py` passes 29/29 on MI350X, and the shared-table test passed 10/10 in a loop. AMD CI runs this file once #62298 lands.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
