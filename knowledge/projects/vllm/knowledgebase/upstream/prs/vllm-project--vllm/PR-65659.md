# [Bugfix][Multimodal] Normalize audio layout before resampling

[Upstream PR](https://github.com/vllm-project/vllm/pull/65659) · state: open · merged: False

## Original PR description

## Overview

Fix corrupted audio when a raw `(samples, channels)` array needs resampling for a model that normalizes channels. A one-second stereo clip at 48 kHz currently becomes three seconds at 16 kHz; the equivalent transposed input is correct.

## Claims

- Canonicalize the channel axis before resampling, using the existing layout heuristic.
- Preserve resampling-before-channel-reduction ordering and passthrough behavior.
- Cover both documented layouts through the parser and real Whisper inference.

## Details

The resamplers operate on the trailing dimension, but `_parse_audio_data` previously detected samples-first input only during subsequent channel normalization. Canonicalizing the array first prevents resampling the channel axis. Channel averaging remains after resampling, preserving the existing numerical order.

This addresses documented raw-array inputs. HTTP audio loaders generally already downmix. Live issue/PR searches found no matching fix; #51022 changes downmix reduction, #46375 changes PyAV chunking, and #57752 preserves the same resample/normalize order in a broader experiment.
