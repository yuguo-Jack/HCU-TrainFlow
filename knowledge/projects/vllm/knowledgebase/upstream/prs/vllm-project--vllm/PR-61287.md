# [Bugfix][Reload] Reload fixes, and a refit-equals-fresh harness

[Upstream PR](https://github.com/vllm-project/vllm/pull/61287) · state: open · merged: False

## Original PR description

## Overview

Reload bugs on today's path (layerwise reload / NCCL-IPC weight transfer), plus the refit-equals-fresh test harness. This is the first PR of the plan in #59502 (modulewise reload) and #60931 (SupportsReload). Nothing here depends on the new reload framework; every fix applies to main as it is.

## Claims

- **gpt-oss: Quark and fused-BF16 experts now update on reload.** They were written through `param.data` copies, which hit the meta placeholders during a reload and were silently dropped. They now go through the param's loader with a `gpt_oss_presliced` shard id, which copies with `copy_` exactly as the old direct writes did (a mismatched shape still raises). The two Quark paths that were partial copies into padded params on purpose (MXFP4 weights/scales and biases) use `gpt_oss_presliced_padded`.
- **Attention KV-cache scales are recreated under the model dtype on reload**, so an FP32 checkpoint scale is rounded the same way a fresh load rounds it.
- **FlashInfer bmm1/bmm2 scales follow reloaded KV scales.** They were computed once from host floats at the first forward and never updated. `FlashInferImpl.refresh()` now recomputes them from attention post-load processing into device tensors that are allocated once, and trtllm-gen / XQA decode read those tensors, so captured CUDA graphs see the new values. Decode paths that still take host floats (output-quant fusion, DCP, the FlashInfer decode wrapper) keep the pre-reload scales inside FULL CUDA graphs, as on main; `refresh()` now logs a warning when a reload hits that case with scales that can change (FP8 KV cache or output-quant fusion).
- **Online block-FP8 (`quantization="fp8_per_block"`) no longer crashes at cold start on DeepGEMM.** It enables the CUDA QuantFP8 op.
- **Rule "every write goes through the param's `weight_loader`"** applied to colpali, colqwen3/3.5, nano_nemotron_vl, nemotron_parse, pixtral and voxtral.
- **Streamed reloads keep FP8 indexer weight/scale pairs, and drop stale ones.** DeepSeek-V3.2's pairing state now lives on `self`, as in DeepSeek-V2, so a pair split across streamed `load_weights` calls is kept. Layerwise reload clears such cross-call pairing state when a reload starts, so a half-pair left by an aborted update isn't paired with the next update's tensor, and warns if a load ends with a tensor still unpaired. This covers DeepSeek-V2/V3.2 (`_pending_indexer_wk_fp8`) and MiMo-V2 (`_pending_fp8_qkv_proj`, `_pending_qkv_proj`).
- **Small fixes:**
  - gpt-oss `w2_bias` zeroed the caller's tensor in place on TP ranks ≠ 0, which corrupts a buffer shared with the trainer under IPC.
  - The kernel-format reload warning text was inverted.
- **Tests:** `reload_harness.py`, a worker extension that streams a checkpoint through `load_weights` with device tensors and checksums every registered and off-registry tensor, and `test_reload_refit.py`, which checks that reloading A→B equals a fresh B with CUDA graphs on and no pointer changes (including tensors that disappear on reload). Cases that still fail on main are `xfail(strict=True)`; later PRs remove the marks.

**Remaining differences, which later PRs in the plan address:**
- On MoE models, kernel-held derived state (`moe_quant_config` scales and alphas, `g1_scale_c`) and MXFP4 routed experts still differ after a reload, on main and here. MoE methods rebuild their kernels on every post-load pass; that's PR 3 of the #59502 / #60931 plan.

## Details

**Root causes:**
- **Writes that bypass the loader (gpt-oss and the 6 models).** A reload restores params on meta and wraps their `weight_loader` to count and buffer the loads. A write that bypasses the param's loader lands on a meta placeholder and is silently dropped: `param.data.copy_(...)`, `default_weight_loader(param, w)` on a param that has its own loader, or `.to(param.device)` of the incoming tensor. The module never completes, and its old tensors are put back.
- **FlashInfer bmm scales.** They are host floats computed lazily at the first forward and never invalidated.
- **KV-scale dtype.** The KV-cache scales are 0-dim params of the default dtype. At model init that's the model dtype, but reload recreates them outside `set_default_torch_dtype`, so they come back as FP32 and an FP32 checkpoint scale isn't rounded the way a fresh load rounds it.
- **Online block-FP8.** Under torch.compile the native QuantFP8 path emits float32 activation scales, but DeepGEMM's UE8M0 kernels need the packed int32 scales the CUDA op produces. The config now enables `+quant_fp8` when any linear uses blocked FP8 weights, as the ModelOpt and compressed-tensors configs already do.

**The 6 models' loader routing** was audited site by site rather than tested with reloads (no reload checkpoints for them here). colpali, colqwen3/3.5, nano_nemotron_vl, pixtral and voxtral only reach plain torch modules or `RMSNorm`, which have no `weight_loader` on a fresh load, so the call falls back to `default_weight_loader` and cold start is unchanged. nemotron_parse reaches `ColumnParallelLinear` (`sum_proj`) and `ParallelLMHead`; neither receives a pre-sharded tensor, so the result is identical wherever main worked, and the cases where main failed its size assertion (TP>1, or a vocab size that isn't a multiple of 64) now load.

**Not included:**
- **k2_horizon and MiMo-V2 (+MTP).** Their loaders shard the checkpoint tensor themselves before handing it to a TP-aware param, so routing it through the param's loader shards it twice and breaks fresh loads at TP>1. They need model-specific handling and end-to-end reload tests, in a follow-up.
- **`collective_rpc` stale replies after a one-rank failure.** On main, a failure on one rank raises before the other ranks' replies are read, so the next call returns them. Draining them can hang on a peer blocked in a collective; the proper fix is to tag replies with a call id, in a separate PR.
- Fixed on main already: MLA `W_UK_T_dcp_qrep` reallocated on reload (#60389); the "all weights loaded" check exempting every quantized layer (#57108).

**CI cost:** the non-`slow_test` refit cases (dense block FP8, MLA + MoE, Mamba hybrid) run in the CUDA `model_executor` step and load two engines each. Happy to move more of them to `slow_test` if that's too heavy.

**Model runner:** no model-runner changes. The reload entry point (`reload/inplace.py`) is shared by MRV1 and MRV2.
