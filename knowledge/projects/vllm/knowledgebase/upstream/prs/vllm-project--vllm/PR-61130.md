# [Core] Expose prefix reuse policy in KV cache group metadata

[Upstream PR](https://github.com/vllm-project/vllm/pull/61130) · state: open · merged: False

## Original PR description

## Overview

External prefix-cache-aware routers cannot determine a group's prefix reuse policy from its attention kind alone. This PR exposes `prefix_cacheable` and `prefix_replay_tokens` from the resolved spec through `EngineCore.get_kv_cache_group_metadata()`.

## Claims

- Report whether each group participates in prefix caching and its required tail replay length.
- Cover KpoolTail, Sliding MLA with bounded replay on/off, and uniform-type wrappers in the existing CPU metadata suite.

## Validation

```bash
VLLM_TARGET_DEVICE=cpu PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
  .venv/bin/python -m pytest -p no:cacheprovider -q \
  tests/v1/engine/test_kv_cache_group_metadata.py
.venv/bin/ruff check vllm/v1/engine/core.py tests/v1/engine/test_kv_cache_group_metadata.py
.venv/bin/ruff format --check vllm/v1/engine/core.py tests/v1/engine/test_kv_cache_group_metadata.py
git diff --check HEAD^ HEAD
```

Result: **5 passed**, including the existing DCP effective-block-size test. Omitting the added fields caused all 4 new cases to fail with `KeyError: 'prefix_cacheable'`. Ruff and whitespace checks passed.

Validation ran in CPU mode with Python 3.12.3 and PyTorch 2.13.0+cu130. Model evaluation is not applicable to this metadata-only addition.

## Details

KpoolTail is classified as sliding-window attention but has `prefix_cacheable=False`. Bounded-replay Sliding MLA also opts out of shared prefix lookup and declares a replay window. These properties let external consumers identify participating groups and account for replay when estimating reuse benefits.

Related to [#48121](https://github.com/vllm-project/vllm/pull/48121), which expands canonical metadata and frontend access. Its current diff does not include these two prefix-policy properties; this PR adds only those fields to the existing RPC.
