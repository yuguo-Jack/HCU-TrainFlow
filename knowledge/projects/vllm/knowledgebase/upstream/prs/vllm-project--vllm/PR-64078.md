# [Bugfix][CPU][RISC-V] Define all erf lanes with sign injection

[Upstream PR](https://github.com/vllm-project/vllm/pull/64078) · state: open · merged: False

## Original PR description

## Overview

Fix undefined nonnegative lanes in the RISC-V RVV error-function implementations used by exact GELU and fused MoE GELU. Replace masked negation with sign injection in both FP32Vec8 and FP32Vec16.

## Claims

- Define every active erf output lane regardless of the implementation's mask-agnostic fill policy, while preserving the input sign, including negative zero.
- Extend the existing deterministic CPU GELU-and-multiply regression to cover exact and tanh variants.

## Details

The `_m` masked intrinsic uses a mask-agnostic policy. The old sign-restoration step only selected negative inputs, leaving nonnegative lanes without a passthrough value. `vfsgnj` copies the input sign to the computed magnitude and defines all active lanes.

Duplicate-work checks found no open `RISC-V erf` or `vfneg` fix. Related #51132 optimizes polynomial FMA evaluation and leaves this sign-restoration step unchanged.
