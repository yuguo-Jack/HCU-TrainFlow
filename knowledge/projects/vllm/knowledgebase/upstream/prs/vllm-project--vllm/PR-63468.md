## Overview

<!-- Summarize the change in 1-2 lines. Link relevant issues and PRs. -->

Reject sweep figure groups that would write to the same PNG after filename sanitization, before starting plotting jobs.

Related to #60794 and #60795, but scoped to figure outputs: #60795 protects benchmark result/cache directories and does not validate the paths produced by `--fig-by`.

- Preserve existing non-conflicting filenames and allow collisions removed by per-figure filters.
- Cover the real plotting CLI, including valid PNG output, without starting a model or server.

## Details

<!-- Explain motivation, design decisions, root cause, tradeoffs, and limitations concisely. Link or collapse lengthy supporting material. -->

Distinct labels such as `case/a` and `case_a` produce the same figure filename. Previously, separate plotting workers could write to that shared destination.

The preflight groups figure jobs by their existing generated paths. For potentially conflicting paths, it respects the existing per-group filters so an empty group does not reserve a destination. An error is raised if multiple nonempty groups still share a path. Valid filenames are not renamed, and no dependencies are added.

The [review follow-up](https://github.com/singh4jitendra/vllm/commit/bffe08fe82aae50a0575d8689aa84d7790d1c091) moves optional pandas setup above the per-path loop, as [requested by dilberx](https://github.com/vllm-project/vllm/pull/63468#discussion_r4424252115). Setup runs once, and only when filters and colliding paths require it; ordinary dry-runs retain their optional-dependency behavior.

Duplicate checks on October 24 inspected the current issue discussion, matching open PRs, and the changed-file scope of #60795. Its result-directory guard does not cover PNG figure destinations; this change leaves benchmark planning and cached results untouched.

Before the original submission, the human submitter confirmed reviewing the original patch and running its documented tests, and explicitly authorized the personal GitHub noreply DCO sign-off and required assistance attribution. The author subsequently requested the review follow-up; its validation is recorded above.
