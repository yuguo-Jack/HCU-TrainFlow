# [ROCm] Fused DSpark draft sampling: markov GEMV + sample epilogue

[Upstream PR](https://github.com/vllm-project/vllm/pull/63181) · state: closed · merged: False

## Original PR description

## Overview

Two decode-time launch-elimination fastpaths for the DSpark draft sampling chain on gfx950 (MI355X): a fused markov-bias GEMV (embed + GEMV + add in one Triton kernel) and a fused sample epilogue, engaged at draft batches at or below `VLLM_DRAFT_SAMPLING_FUSION_MAX_TOKENS` (default 2 — the measured crossover; above it the stock GEMM's tiled weight reuse wins).

Part of the DSV4.1-Flash MI355X serving fastpath series — four **independent** single-commit PRs (originally cut on `main`@90c4a1a73e), each reviewable and mergeable separately, in any order. Siblings: #63179 (tiny-M quant fusion + lm_head guard), #63180 (fused shared experts), #63182 (draft-prepare fastpaths). The four series PRs all register kill switches in `vllm/envs.py` at the same anchor and therefore conflict textually with each other there; the resolution is to keep both sides. Rebased onto current `main` (`717cf84342`): the `apply_output_logit_transform` hook that landed inside the region this PR touches in `dspark/speculator.py` is kept alongside the fused-epilogue call (both sides), and the rebased tip was re-verified with a fresh quick A/B pair (see the current-base benchmark under Validation).

## Claims

- **Fused markov bias GEMV** (`dspark_markov_fused_gemv.py`): the stock per-draft-step chain runs an embed gather, a bf16 GEMV against `markov_w2` [129280, 256], and an add — three launches whose latencies add serially at b ≤ 2. One Triton kernel does all three (fixed-order fp32 accumulation, no atomics). The sampler is untouched (identical RNG stream); only the GEMM accumulation order can differ (≤ 2 bf16 ULP from the stock chain, both within 1 ULP of an fp64-grounded reference). Kill switch `VLLM_DISABLE_MARKOV_FUSED_GEMV`.
- **Fused sample epilogue** (`sample_epilogue_fused.py`): the stock `_sample_logits` epilogue runs a `sample_pos` offset, an `idx_map` copy, `gumbel_sample`, `argmax`, a gather and a `draft_tokens` copy per draft position. One Triton kernel replicates that chain bit-exactly (same block width and noise helpers as the stock kernel) and writes the `draft_logits` cache rows and `draft_tokens` cells in-kernel; a persistent scratch buffer keeps the output address stable for CUDA-graph replay and the arrival counters self-clean. Armed only on the exact chain it replicates: probabilistic full-vocab drafting, no d2t scatter, no draft watermarker. Kill switch `VLLM_DISABLE_DRAFT_SAMPLE_EPILOGUE_FUSION`.
- **−550 µs median decode ITL (−9.0%) on the current base** (`main`@`717cf84342`) — official DSV4.1-Flash serving command at TP=4 on MI355X, complete separation among the sampled runs (current-base benchmark under Validation). The submission-base study measured **−3.51% (−255/−297 µs)** over 12 position-balanced A/B cycles with complete distribution separation; the absolute win deepened as `main` got faster (−609 µs on `be03d19750`, −550 µs on the current tip — the same launch elimination cuts deeper on a faster base). TTFT unchanged within noise (draft-path only).

Both arms run this branch's tip; the OFF arm disables only this PR's two levers. |---|---|---|---|

## Details

Both gates are read per call and baked at CUDA-graph capture, so an eager in-process A/B works and each captured graph size keeps a fixed engagement. The levers win by launch elimination at tiny draft batches, and the fused GEMV re-reads `w2` per row, so wide batches keep the stock chain. The draft-MoE topk fastpath developed alongside these was measured neutral at the serving shape and is not carried here.
