# [Bugfix][LoRA] Run MoE LoRA on tokens gathered from other DP ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/61714) · state: open · merged: False

## Original PR description

## Purpose
Part of #61453.

With DP > 1 and no EP, the MoE layer runs on tokens gathered from all DP ranks, and the token to LoRA slot mapping is gathered with them. But the MoE LoRA path still returned early on this rank's own `no_lora_flag`, and only aligned this rank's own active LoRA ids. So a rank with only base model requests added no expert LoRA delta for the LoRA tokens of its peers.

This PR:
- In `PunicaWrapperGPU`, when a gathered mapping is passed in, skips the local early return and aligns over all slots. Rows are already masked by the mapping, and disabled slots exit on `adapter_enabled`.
- In `LoRAKernelMeta.prepare_tensors`, copies the mapping before the `no_lora` early return. Before this, a rank whose batch was all base sent its stale mapping from an older step to the other ranks.
- Does the same for the `_batch_has_no_lora` fast path in the TRT-LLM LoRA experts.

What this does not fix is a fully idle peer. Its dummy step activates a zero weight warmup adapter, and it never loaded the real adapter in the first place. That needs the slots to be consistent across DP ranks, which is the second point in the issue and a bigger change.

No open PR touches this.

## Test Plan
- `pytest tests/lora/test_punica_ops.py`. `test_add_lora_fused_moe_early_exit` now also checks that the mapping is copied when all ids are -1, and that a gathered mapping with LoRA tokens still runs the kernel.
- E2E on 4xH100: `allenai/OLMoE-1B-7B-0125-Instruct` with `-dp 2 -tp 2 --enable-lora --max-loras 1 --max-lora-rank 8`, adapter `jeeejeee/olmoe-instruct-text2sql-spider` (has expert LoRA). 4 SQL prompts with the adapter are scored with `prompt_logprobs` and pinned to DP rank 0 with `X-data-parallel-rank: 0`. Rank 1 is either idle, busy with 16 adapter streams, or busy with 16 base streams after it served one adapter request (so it holds the adapter in its slot). Each case is compared to rank 1 busy with the adapter.
