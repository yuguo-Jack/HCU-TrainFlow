# [Rust Frontend][1/3] Map developer messages to system for templates without the developer role

[Upstream PR](https://github.com/vllm-project/vllm/pull/63901) · state: closed · merged: True

## Overview

port Python's HF-renderer fallback for templates without a `developer` role (#43590), so developer instructions are no longer silently dropped or rejected by templates such as Qwen3 and Qwen3.5.

review order: [1/3: renderer #63901](https://github.com/vllm-project/vllm/pull/63901) → [2/3: non-streaming #63902](https://github.com/vllm-project/vllm/pull/63902) → [3/3: streaming #63903](https://github.com/vllm-project/vllm/pull/63903). all three upstream review PRs target `main`; later diffs include earlier layers.

## Claims

- like Python, when a request has developer messages and the template text lacks `"developer"`/`'developer'`, rename them to `system` (dropping message-local tools) and merge all system messages into the first one.
- preserve string and OpenAI-array content shapes when merging. a merge that would move a non-leading system/developer message with media ahead of earlier media returns a 400 instead of reordering media: templates can reorder messages arbitrarily, so placeholder order cannot be predicted in general, and Python fails on the same input after flattening the content to text.
- keep the change in the shared Chat Completions/Responses renderer; this layer adds no endpoint.

## Details

a plain-string merge can lose policies for array-based templates, so the merge preserves the effective content representation. moving system/developer messages can also reorder placeholders without moving their media; such requests are rejected rather than reordered.

the rebase retains upstream's request-template fuel controls and uses the normal template constructor in the new upstream fuel-test fixture. the renderer changes also affect Chat Completions.

these are the existing #58783 layers opened upstream at [@BugenZhao's request](https://github.com/vllm-project/vllm/pull/58783#issuecomment-6418403089), rather than competing implementations. the original authored history and discussion remain in #58783. @gcanlin's #53380 implementation is credited in the endpoint and streaming commits. duplicate checks found #63497 affects DeepSeek renderers and #56391 affects Python's HF renderer; neither covers this Rust HF path. the [fork layer](https://github.com/franciscojavierarceo/vllm/pull/1) retains the isolated review history.
