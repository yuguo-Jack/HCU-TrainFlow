# [CI][ROCm] Run the online FP8 MoE batch-invariance test on ROCm

[Upstream PR](https://github.com/vllm-project/vllm/pull/63283) · state: closed · merged: True

## Original PR description

Run the online FP8 MoE batch-invariance test from #57092 on ROCm too. It was gated on `skip_if_not_cuda`, but the fix it guards (per-token activation quant for the online FP8 MoE experts) applies on ROCm as well.

- `test_online_fp8_moe_logprobs_bitwise_bs1_vs_bsN` now uses `skip_if_not_cuda_alike` and runs where online FP8 works: CUDA compute capability 8.9+, or MI300/MI355 on ROCm. MI250 has no FP8, and ROCm reports it as capability 9.0, so the old `has_device_capability(89)` check alone would not skip it there.
- `vllm.platforms.rocm` is imported lazily, because importing it resolves the GPU arch at module load and fails on NVIDIA.
- This also resolves the pre-commit failure (`F821 Undefined name skip_if_not_cuda` from ruff and mypy) in #62298 once it picks up main. #62298 converts the file's other CUDA-only test and drops the `skip_if_not_cuda` import, so the decorator #57092 added no longer resolves after the merge. Pre-commit on main itself is green.

Validated on MI300X (gfx942):
- The test passes 13 times in a row (10 with the decorator change alone, 3 with the final gate).
- With #57092's source fix reverted, it fails: `logprobs are not bitwise equal between BS=1 and BS=8; max abs diff 2.239e-01`. So it exercises the fix on ROCm and isn't passing vacuously.
- `pytest tests/v1/determinism/test_batch_invariance.py`: 8 passed, 1 skipped (the other CUDA-only test, which #62298 converts).
