# [Bugfix][Spec Decode] Avoid reusing random draws across block verification rounds

[Upstream PR](https://github.com/vllm-project/vllm/pull/61161) · state: open · merged: False

## Original PR description

## Overview

Fixes #61114. Give block verification fresh acceptance and draft random draws when an uncommitted position is revisited in a later round.

## Claims

- Removes the cross-round sampling bias for deterministic and probabilistic drafts in Model Runner V2.
- Keeps standard verification output unchanged and preserves seeded repeat, request-order and batch-splitting behavior in the repaired block path.
- Uses the current round's starting position without adding scheduler state, host synchronization or kernel launches.
- Covers ordinary draft sampling, the shared DFlash2/LiLiCorr candidate walk, DSpark and ordinary watermark fallback.

## Details

Block verification reads uniforms for draft positions past the finally accepted prefix. Reusing `(request seed, position)` in the next round reuses randomness conditioned on the preceding decision. Probabilistic drafting has the same problem with its position-keyed Gumbel noise.

The existing kernels now mix the round's starting position into the upper 32 bits of the request seed. The rejection kernel reads its first position; the draft kernel subtracts the cached draft step from its source position. The DFlash2/LiLiCorr walk reads the source position before its first candidate, and DSpark forwards the same block-only flag with its existing step column. The position advances after each round, independently of request-slot or batch order. Both ordinary and fused watermark fallback samplers receive that flag; context-keyed watermark draws are unchanged.

Seeded block output intentionally differs from the biased old output, while remaining reproducible in the repaired version. This is distinct from #59355/#60945's residual lookahead bounds and #60652's grammar-invalid drafts, and complements #54282's within-round draft/target stream separation.

Related PR #61153 addresses the same bug. Its implementation passes an explicit round-position tensor and uses a different seed mixer. This implementation derives the key from positions and draft-step metadata already available inside the kernels, avoiding an additional round-position tensor. The same four deterministic/probabilistic, standard/block multi-round distribution cases pass on both implementations, including #61153 at `170dcc217`, using a local argument adapter for its different sampler API. This is an alternative implementation of the same repair, not a claim that #61153 is incorrect.
