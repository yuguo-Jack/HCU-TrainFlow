# [Bugfix][Spec Decode] Avoid reusing random draws across block verification rounds

[Upstream PR](https://github.com/vllm-project/vllm/pull/61161) · state: closed · merged: True

## Original PR description

## Overview

Fixes #61114. Give block verification fresh acceptance and draft random draws when an uncommitted position is revisited in a later round.

## Claims

- Removes the cross-round sampling bias for deterministic and probabilistic drafts in Model Runner V2.
- Preserves seeded repeat, request-order and batch-splitting behavior in both verification modes. Standard probabilistic token sequences change, but their target distribution is retained.
- Uses a shared step-seed helper without new forwarding parameters, round-position tensors, scheduler state, host synchronization or sampling kernel launches.
- Covers ordinary draft sampling, the shared DFlash2/LiLiCorr candidate walk, DSpark and ordinary watermark fallback.

## Details

Block verification reads uniforms for draft positions past the finally accepted prefix. Reusing `(request seed, position)` in the next round reuses randomness conditioned on the preceding decision. Probabilistic drafting has the same problem with its position-keyed Gumbel noise.

Following review, `spec_step_seed(seed, step)` mixes the draft step into the seed's upper 32 bits. Cached Gumbel sampling uses its existing cache column; the DFlash2/LiLiCorr walk uses its loop step. A request's `(position, step)` pair does not repeat across rounds. Block acceptance calls the same helper with `i` inside its verification loop, always starting from the original request seed. No new flag is needed, including in DSpark and the watermark adapters. The fused ordinary watermark fallback uses the same cached step seed; context-keyed watermark draws are unchanged.

Cached draft seeding now applies under standard verification too. This changes standard probabilistic seeded sequences, not their target distribution; the updated implementation remains reproducible. This is distinct from #59355/#60945's residual lookahead bounds and #60652's grammar-invalid drafts, and complements #54282's within-round draft/target stream separation.

Related PR #61153 addresses the same bug with an explicit round-position tensor and a different seed mixer. This implementation instead uses the existing draft step inside the kernels. Both implementations passed the earlier shared four-case CUDA distribution comparison on #61153 at `170dcc217`; that comparison predates this reviewer-requested simplification. This is an alternative implementation of the same repair, not a claim that #61153 is incorrect.

- TheEpicDolphin · comment · 2026-10-14T19:51:49Z · [source](https://github.com/vllm-project/vllm/pull/61161#discussion_r4275533910)

File: `vllm/v1/worker/gpu/sample/gumbel.py` · line None

Instead of computing the round start from the position and draft step (col), we can just apply the draft step directly on the seed. For a request, `(position, step)` never repeats across rounds, so it gives the same guarantee. This unifies the seed computation, and every site can invoke one helper. Example:

```
@triton.jit
def spec_step_seed(seed, step):
    return seed ^ (tl.cast(step, tl.int64) << 32)
.
.
.
- round_start = pos.to(tl.int64) - col.to(tl.int64)
- seed ^= round_start << 32
+ seed = spec_step_seed(seed, col)
```
