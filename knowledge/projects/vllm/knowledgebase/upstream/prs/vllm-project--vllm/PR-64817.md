# [Perf][Kimi] Run one packed prefill convolution

[Upstream PR](https://github.com/vllm-project/vllm/pull/64817) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Kimi K3's KDA prefill path split the packed q|k|v projection into three views and ran one causal convolution per view, then materialized dense Q/K/V for FlashKDA. The convolution weights and the conv state are already stored packed, so run a single convolution over the packed input and pass the resulting row-strided views straight to FlashKDA (vllm-project/FlashKDA#15), which consumes them without copies.

This turns three prefill convolution launches per KDA layer into one and removes the three `.contiguous()` calls. Decode is untouched, and the raw projection is still available for the conv-state checkpoint export.

The FlashKDA pin bump this originally needed is already in `main` via #61614, so this PR now only contains the Kimi K3 call-site change. The merged-convolution path is taken only when `kda_prefill_backend == "flashkda"`; the triton and flashinfer backends keep three dense convolutions.

## Claims

- One `causal_conv1d_fn` per KDA layer per prefill step instead of three, with lower total convolution GPU time.
- Prefill output is bit-identical to the previous path.
- No change to the FlashKDA operator, the convolution weight/state layout, or decode.

## Validation

Model-level A/B on 8×H200 (SM90), TP8, `mgoin/Kimi-K3-pruned75` (the CI K3 checkpoint: 93 layers, 69 of them KDA, MXFP4 experts), vLLM at this PR's head. The arms differ only in `vllm/models/kimi_k3/nvidia/kda.py`.

### Serving A/B/A

`vllm bench serve`, random ISL 2048 / OSL 1, `--max-concurrency 32`, 256 prompts, 3 repeats per rate; servers started fresh per arm:

| Arm | rate=20 req/s | rate=inf req/s | median TTFT |
|---|---:|---:|---:|
| A1 base | 5.25 / 5.27 / 5.26 (5.258) | 5.26 / 5.26 / 5.26 (5.259) | 6041 ms |
| B packed | 5.26 / 5.27 / 5.26 (5.264) | 5.27 / 5.27 / 5.27 (5.268) | 6035 ms |
| A2 base | 5.25 / 5.27 / 5.26 (5.260) | 5.26 / 5.27 / 5.26 (5.262) | 6041 ms |

Throughput is neutral within run-to-run noise (+0.10% at rate=20, +0.14% at rate=inf; TTFT −0.1%). The convolution is under 1% of Kimi K3 prefill time at this scale — the MoE dominates — so this is a cleanup of redundant launches rather than an end-to-end throughput win.

### Correctness

- GSM8K, 5-shot greedy, 1314 questions: base `0.3340943683409437`, packed `0.3340943683409437` (identical; the CI threshold for this checkpoint is 0.33).
- Greedy, 32 fixed prompts × 32 tokens, temperature 0: all three arm pairs (A1↔B, B↔A2, A1↔A2) produce identical text on 32/32 prompts.
- KDA layer microbench: `max |out_base − out_packed| = 0.0`.

### Profiling

Torch profiler, one rank, 64 prompts at concurrency 32. Per KDA layer per prefill step:

| | base | packed |
|---|---:|---:|
| `_causal_conv1d_fwd_kernel` launches | 3 | 1 |
| convolution GPU time per 8192-token prefill step | 5.99 ms | 4.49 ms |

(The two profiling runs scheduled the same workload into different numbers of steps, so only the per-step figures are comparable.)

### KDA layer microbench

Real K3 layer shapes (hidden 7168, head_dim 128, short-conv k=4, 4×2048-token prefill), both variants built from their own `kda.py` with identical weights, interleaved A/B iterations, median:

| Shape | layer forward base | packed | Δ | conv block split(3) | merged(1) | Δ |
|---|---:|---:|---:|---:|---:|---:|
| TP8 per-rank (12 heads) | 2.012 ms | 1.804 ms | −10.3% | 0.497 ms | 0.145 ms | −70.8% |
| TP1 full layer (96 heads) | 13.384 ms | 13.417 ms | +0.25% | 0.427 ms | 0.417 ms | −2.2% |

The standalone layer timing runs eagerly, so it includes the launch/Python overhead of three calls that CUDA graphs hide in serving; the in-serving effect is the profiling row above.

## Details

- The packed convolution output is split into `local_projection_size` views and reshaped to `[1, T, H, D]`; FlashKDA accepts the `3 * H * D` token stride through its TMA descriptors, so no copies are needed.
- `mixed_qkv_ns` is left intact, so `checkpoint_exporter.export(..., raw_qkv=mixed_qkv_ns, ...)` still stores raw projections for prefill checkpoints.
- New test: `tests/models/kimi_k3/test_kda.py::test_prefill_convolution_preserves_raw_cache_history` (parametrized over the flashkda and triton backends), which checks finite output plus that the conv state retains raw projections, including checkpoint entries.
