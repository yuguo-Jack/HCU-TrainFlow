# [Bugfix][Tool Parser] xlam, hunyuan_a13b: keep tool calls whose arguments are not an object

[Upstream PR](https://github.com/vllm-project/vllm/pull/65367) · state: open · merged: False

## Original PR description



## Overview

The non-streaming `extract_tool_calls` of the `xlam` and `hunyuan_a13b` tool parsers drops **every** tool call in the output when one call's `arguments` is not an object (e.g. `"arguments": null` for a zero-argument function). This PR keeps those calls.

## Claims

- A call with `"arguments": null` is returned with arguments `"{}"`, and the other calls in the same output are kept.
- Other non-string values (lists, numbers) are JSON-encoded instead of being passed raw into `FunctionCall.arguments: str`.
- String and object arguments are handled exactly as before.

## Validation

## Details

Root cause: both parsers built `FunctionCall(arguments=...)` with `json.dumps(args) if isinstance(args, dict) else args`. For a non-dict, non-string value, pydantic rejects the field, the broad `except Exception` catches it, and the parser returns `tools_called=False` with the raw output as content, losing the valid calls too.

The fix keeps strings unchanged and JSON-encodes anything else. `null` is mapped to `{}`, which is how other parsers treat missing or null arguments (e.g. `dots`). A call without an `arguments` key is still skipped, as before. The streaming path is not touched.

Duplicate check: open PRs on these files (#49535, #47954, #51698, #60360, #64962, #59620) all change the streaming path; none changes non-streaming argument handling. `gh pr list --state open --search "xlam null arguments"` returns nothing.
