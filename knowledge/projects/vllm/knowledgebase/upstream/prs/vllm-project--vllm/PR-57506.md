# [Bugfix][KV Offload] Fix private CPU buffer lifetime during shutdown

[Upstream PR](https://github.com/vllm-project/vllm/pull/57506) · state: open · merged: False

## Original PR description

## Summary

Fix two related shutdown ownership bugs in CPU KV offload.

### 1. Shared handler reference lists

Before this change, the store and load handlers received the same mutable
`cpu_tensors` list. When one handler cleared its tensor references during
shutdown, it also cleared the other handler's list. This alias existed for
both shared-region and private-tensor paths.

Each handler now owns its own reference container. The tensor objects and
their backing storage are not copied.

### 2. Private tensor lifetime after shutdown failure

When `mmap_region=None`, the worker uses private CPU tensors and has no shared
region object as an independent backing-memory owner. The existing device-wide
synchronization was only attempted inside the shared-region cleanup branch.
If a handler failed to synchronize an end event, private tensor references
could be released before outstanding accelerator work was known to be complete.

The worker now retains an independent owner for private CPU tensors and only
releases it after handler shutdown and any required accelerator synchronization
complete successfully.

## Changes

- Give each `SingleDirectionOffloadingHandler` its own tensor-reference lists.
- Keep worker-owned private CPU tensors alive through handler shutdown.
- Synchronize the current accelerator after either handler reports a shutdown
  failure, regardless of whether a shared mmap region is used.
- Preserve the existing shared-region cleanup order.

## Relationship to existing PRs

- Related context: #57160 changed ROCm CPU KV offload to use private pinned
  tensors after shared mmap registration failures. It made the private path
  more visible but did not introduce these generic ownership issues.
- Related but distinct: #53073 fixes shared mmap-region ownership and startup
  cleanup. This PR fixes handler reference ownership and private buffer lifetime
  during asynchronous shutdown.

## Scope

The existing behavior after a shared-region device synchronization failure is
unchanged and is outside this PR's scope.
