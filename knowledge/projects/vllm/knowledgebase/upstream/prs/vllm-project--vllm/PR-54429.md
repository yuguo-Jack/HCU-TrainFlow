# [Rust Frontend][Perf] Fast-path single-token tiktoken decoding

[Upstream PR](https://github.com/vllm-project/vllm/pull/54429) · state: open · merged: False

## Original PR description




## Purpose

  The Rust frontend decodes each logprobs candidate independently with
  decode(&[token_id], skip_special_tokens). The general tiktoken decode path
  allocates temporary token ID and byte buffers for every call, even though the
  decoded text for each known token ID is already stored in TokenMetadata.

  Use the precomputed token text when exactly one known token ID is decoded.
  Special tokens still honor skip_special_tokens, unknown IDs fall back to the
  existing backend behavior, and empty or multi-token inputs remain unchanged.

  This removes repeated allocation and backend decoding work from the logprobs
  hot path. The targeted single-token decode benchmark showed:
```
   Backend           Before        After    Time reduction
  ━━━━━━━━━━━━━  ━━━━━━━━━━━  ━━━━━━━━━━━  ━━━━━━━━━━━━━━━━
   riptoken       720.67 ns    243.63 ns             66.2%
  ─────────────  ───────────  ───────────  ────────────────
   tiktoken-rs    1.1643 µs    235.98 ns             79.7%
```
