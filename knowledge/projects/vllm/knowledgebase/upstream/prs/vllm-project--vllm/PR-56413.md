# [Bugfix][Offload] Avoid duplicate host allocation for UVA weights

[Upstream PR](https://github.com/vllm-project/vllm/pull/56413) · state: open · merged: False

## Original PR description

## Overview

Avoid PyTorch caching-host-allocator rounding when initially offloading weights through UVA. Fixes #56410 for this initial-offload path.

## Claims

- Pass unpinned CPU tensors directly to the UVA helper, which allocates mapped host memory at the requested tensor size on CUDA/ROCm.
- Preserve `pin_memory()` on the non-UVA fallback for asynchronous host-to-device copies.
- Add a CPU-only regression test for the two allocation paths.

## Details

`Tensor.pin_memory()` uses PyTorch's caching host allocator, whose rounding can materially exceed the logical offload-byte accounting. For unpinned input, the CUDA view helper already calls `cudaHostAlloc(..., nbytes, cudaHostAllocMapped)` and copies the tensor into that buffer. Skipping the earlier pin removes the caching allocation from this path. This adds a host copy and transient pageable-source storage during loading; it does not change the fallback path.

This PR was opened before #58185. That later PR [explicitly acknowledges the overlap](https://github.com/vllm-project/vllm/pull/58185#issuecomment-5861194597) and additionally covers re-offload in `device_loading_context`, an opt-in to caching pinning, and GB300 measurements. Those additions are outside this focused patch. Its author offered to retain only the delta if maintainers land this PR first.

[GB300 measurements on the related PR](https://github.com/vllm-project/vllm/pull/58185#issuecomment-5833189800) report a roughly 2.5–2.8% decode-throughput cost for the exact-size path on one Grace-Blackwell setup. This PR has no local throughput measurements and makes no claim of unchanged performance.
