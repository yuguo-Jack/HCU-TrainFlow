# [Bugfix][KV Offload][OBJ] Namespace object keys by blocks_per_chunk

[Upstream PR](https://github.com/vllm-project/vllm/pull/63655) · state: closed · merged: True

## Original PR description

## Overview

Fixes #63654. The OBJ tier built its `FileMapper` without `blocks_per_file`, so its namespace digest ignored `blocks_per_chunk`. This passes `blocks_per_file=offloading_spec.blocks_per_chunk`, as the fs and p2p tiers already do.

## Claims

- OBJ tiers with different `blocks_per_chunk` no longer map an `OffloadKey` to the same object key, so a hit can't load a chunk written with a different size and layout.
- OBJ keys now follow the same run-configuration digest as the fs tier, as `kv_offloading_usage.md` documents.
- No change for the default `blocks_per_chunk=1`: the digest already hashed `blocks_per_file=1`, so existing buckets keep their keys.

## Validation

New test `test_obj_tier_namespace_includes_blocks_per_chunk` builds two tiers that only differ in `blocks_per_chunk` (1 and 4) and compares the object key for the same `OffloadKey`.

Without the fix (on main):

```
$ pytest tests/v1/kv_offload/tiering/test_obj_tier.py::test_obj_tier_namespace_includes_blocks_per_chunk
E   AssertionError: assert 'test/840e65f0//test_model_c32b90738e47_r0/000/00_g0/0000000000000001.bin' != 'test/840e65f0//test_model_c32b90738e47_r0/000/00_g0/0000000000000001.bin'
1 failed
```

With the fix:

```
$ pytest tests/v1/kv_offload/tiering/test_obj_tier.py
39 passed
$ pytest tests/v1/kv_offload/tiering tests/v1/kv_offload/cpu/policies tests/v1/kv_offload/test_file_mapper.py tests/v1/kv_offload/test_factory.py
646 passed, 10 skipped
```

Not run end to end against a real object store (no NIXL OBJ setup available here); the change only affects the key namespace, which the test checks directly.

## Details

The test stubs in `test_obj_tier.py` are `SimpleNamespace` specs without `blocks_per_chunk`, which every real `OffloadingSpec` has (`base.py`), so they gain `blocks_per_chunk=1`, matching their config.

All three `FileMapper.from_offloading_spec` callers now pass the same value. Happy to instead derive it inside `from_offloading_spec` so a future tier can't miss it, if you prefer.
