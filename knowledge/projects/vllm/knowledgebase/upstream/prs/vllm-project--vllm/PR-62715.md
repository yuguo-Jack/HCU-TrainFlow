# [Bugfix][MRV2] Fix GDN states and prefill metadata in AV profiling

[Upstream PR](https://github.com/vllm-project/vllm/pull/62715) · state: open · merged: False

## Original PR description

## Overview

**AV profiling underestimates GDN work because dummy verification reads null recurrent states and returns early.** Increasing the query length can therefore make the measured cost fall.

Draft stacked on #54065 and the GDN AV support prerequisite from #60229. The additional GDN fix is limited to [these three files](https://github.com/tomasruizt/vllm/compare/65d3336435493d70bc23c1ef0f025ef457872565...9327f598972d9a206cca8f65c185adc507c87600). The upstream diff includes the unmerged prerequisites until they land.

## Claims

- Populate the recurrent state columns accessed by dummy verification with valid, nonzero IDs, reusing bounded state slots when the synthetic batch exceeds the pool.
- Give dummy GDN prefills the correct flags, draft counts and zero prior context. Preserve #54065's batch split.

This complements the tail-shaping work in #54065 and #54077. Neither tail-shaping fix addresses the null GDN state reads demonstrated below.

Warmup runs before each concurrency's first trial and is excluded from measurements. The second trial reuses the warm server. Natural EOS is enabled, capped at 1,024 output tokens.

**Analysis.** Keep only records with `metadata.phase_name == "profiling"`. The steady window starts at the concurrency-th request completion and ends when the final request is issued. Throughput counts output tokens received in that window, and TPOT averages requests issued inside it. The [existing analysis helper](https://github.com/tomasruizt/vllm-scripts/blob/master/experiments/qwen_dflash_av_60229/build_report.py) implements the window and streamed-token accounting. Plot each valid run at `(1000 / mean_tpot_ms, throughput)` and connect the per-concurrency means. Measured windows were 26.9–37.3 seconds.

Exclude runs with errors, cancellations, incomplete requests, preemptions, queueing, server running p50 below 90% of concurrency, or a steady window shorter than five seconds. Two C128 runs each had one connection error and were excluded, leaving 70 valid runs.
