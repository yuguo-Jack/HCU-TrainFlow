# [Bugfix][Bench] Handle packed hybrid KV and speculative recurrent state

[Upstream PR](https://github.com/vllm-project/vllm/pull/63873) · state: closed · merged: True

## Original PR description

## Overview

Fix `vllm bench forward` on hybrid attention/recurrent models: initialize packed KV caches using manager-block views and reserve/restore all speculative recurrent state slots.

## Claims

- Packed hybrid KV layouts no longer fail with `No block dim of size ...` during benchmark initialization.
- Verify requests get disjoint recurrent scratch blocks for every configured speculative token, and replay restores all those blocks.
- Changes are confined to benchmark setup and replay state; serving execution and the timed model-forward interval are unchanged.

## Validation

GB200 validation of the retained tests: 3 cases passed (native CLI, cache isolation, recurrent state). All targeted pre-commit checks pass.

Base: `b82393b77315692f390880d2e931fdc1fbd13928`. Validation used four GB200 GPUs, native MRV2, and dummy weights (this checks benchmark execution/state, not model accuracy).

| Reproducer | Base | Fixed |
|---|---|---|
| Native GLM-5.3-Flash TP4, FP8 KV, FlashInfer sparse MLA, ngram 5 target-only | All ranks fail: `ValueError: No block dim of size 3979 in (6619401, 64, 132)` | Decode, Verify, Mixed finish; all ranks finite, deterministic, graph/eager relative RMS 0 |
| Tiny Qwen3Next public CLI | `assert 5 == (1 + (7 * 2))` fails: only one state per request | Passes: all speculative slots counted, Verify/Mixed finite and deterministic |
| CPU speculative-state regression | Too few recurrent scratch slots per request | Passes capacity, non-overlap, and complete state-restoration checks |
| CPU packed-view regression | Native GLM reproducer above covers the original layout failure | Passes; adjacent interleaved layers remain unchanged |

Native cases: `decode=1*1@512`, `verify=2*6@512:5`, `mixed=128@512,2*6@512:5`; two samples of two replays. Measured medians were 4.723 / 8.443 / 20.134 ms respectively, with sample spreads 0.04% / 0.03% / 0.05%. These are execution checks, not a speedup claim.

## Details

Hybrid cache groups can pack multiple attention kernel blocks inside one manager block and interleave layers. The existing `AttentionGroup.map_kv_cache_to_manager_blocks` reconstructs the correct manager view without copying. Recurrent state requires one base slot plus `MambaSpec.num_speculative_blocks`; unlike attention tails, every recurrent slot may be read or overwritten during verification.

These three fixes form one benchmark-state correctness change: without the packed-view fix the affected hybrid model cannot initialize; without either recurrent-state fix verification allocates or restores the wrong state. The CPU tests check allocation capacity and memory isolation without pinning block IDs or a complete storage layout. The snapshots use additional GPU memory proportional to the actual speculative state slots. Their copies remain outside the measured interval.

Duplicate-work checks searched open PRs for `"bench forward" "KV"`, `"bench forward" "Mamba"`, `"bench forward" "KDA"`, and `"packed" "benchmark"`. No open PR addressed these benchmark-state failures. The issue inventory came from local model experiments and has no linked GitHub issue number. Existing packed-cache connector and kernel PRs affect different paths.
