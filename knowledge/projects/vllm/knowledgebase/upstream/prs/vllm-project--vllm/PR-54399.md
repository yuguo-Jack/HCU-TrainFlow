# [Bugfix][Model] Fix CohereASR FP16 attention bias dtype

[Upstream PR](https://github.com/vllm-project/vllm/pull/54399) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Preserve CohereASR runtime FP16 relative-position bias buffers when loading FP32 checkpoint tensors. Fixes #54377; refreshed against main `c5f8adc0` after #55190.

## Claims

- Remove the loading-time buffer dtype override; keep the normal weight loader and shared attention-buffer references.
- Move the existing regression into `tests/models/multimodal/test_cohere_asr.py`, as requested by @ekagra-ranjan, retaining upstream fusion and audio-token tests.

## Validation

- `.venv/bin/python -m pytest tests/models/multimodal/test_cohere_asr.py -v` — **6 passed**.
- The migrated bias-loading regression fails against unmodified main production code (`float32` rather than `float16`) and passes with this fix.
- `.venv/bin/pre-commit run --files vllm/model_executor/models/cohere_asr.py tests/models/multimodal/test_cohere_asr.py` — **passed**, including mypy and Buildkite test tethering.
- `git diff --check origin/main...HEAD` — passed.
- No new Turing/H100 model or WER evaluation ran on this host: CUDA cannot initialize (driver 12.4; installed torch CUDA 13.0). Earlier H100 testing reported by the reviewer is prior-head evidence in this discussion, not a fresh result.

## Details

The custom `param.data.to(loaded_weight.dtype)` replaced the runtime FP16 buffer with an FP32 tensor before loading, overriding `--dtype` and leaving attention with mixed dtypes. The normal loader already casts checkpoint values into the existing destination dtype.

Duplicate check: re-read #54377 and searched open PRs by issue number and CohereASR/pos_bias; no competing open fix was found. #55190 is a merged attention optimization, whose tests are preserved. Current main still contains the offending conversion. This PR has been open since 2026-08-30.

AI assistance was used for this refresh and validation. Commits include Signed-off-by and OpenAI Codex attribution; human review of the updated diff and remaining hardware validation are still required.
