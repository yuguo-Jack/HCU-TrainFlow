# [Bugfix][Metrics] Keep Ray metrics usable without Ray Serve

[Upstream PR](https://github.com/vllm-project/vllm/pull/64164) · state: open · merged: False

## Original PR description

## Summary

- Import optional Ray Serve separately from Ray metrics.
- Keep `RayPrometheusStatLogger` usable when Ray is installed without the Serve extra.
- Fall back to an empty `ReplicaId` when no Serve replica context is available.

## Context

`RayPrometheusStatLogger` only uses Ray Serve to retrieve a replica ID. If `ray.serve` fails to import because `ray[serve]` dependencies are absent, the shared `try` block also discards the successful `ray.util.metrics` import. Metric construction then raises the misleading error that Ray is not installed.

This is the vLLM-side counterpart to ray-project/ray#67444. That change fixes one Serve-extra import failure in Ray. vLLM should still keep its Ray metrics independent from optional Serve dependencies.

## Duplicate check

I searched open vLLM PRs and issues for `ray_wrappers`, the `RayPrometheusMetric requires Ray to be installed` error, and Ray Serve extras. I found no existing change that separates these imports.

## Tests

- `/home/ubuntu/work/vllm-main/.venv/bin/python` smoke check with `ray.serve` unavailable and `ray.util.metrics` available: passed. Constructed a `RayCounterWrapper` and verified its tags were `{"ReplicaId": ""}`.
- `/home/ubuntu/work/vllm-main/.venv/bin/pre-commit run --files vllm/v1/metrics/ray_wrappers.py`: passed, including ruff, mypy, and repository checks.
