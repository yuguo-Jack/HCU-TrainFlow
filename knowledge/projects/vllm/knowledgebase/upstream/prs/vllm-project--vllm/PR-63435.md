# [Bugfix][Muse] Flush header-less output as content at stream end

[Upstream PR](https://github.com/vllm-project/vllm/pull/63435) · state: open · merged: False

## Original PR description

## Overview

With `--reasoning-parser muse`, a streamed generation that ends before any channel header completes (for example `max_tokens=1`, or an answer written without a header) returns an empty stream. Non-streaming returns the same text as `content`. This PR makes the streaming fallback return that text, so the two paths agree.

## Claims

- Bug fix: a streamed Muse response with no `<|message|>` in its output now carries the generated text as `content`, the same as the non-streaming response. Before this change, the stream had no `content`, no `reasoning` and no `tool_calls`.
- No change to outputs that contain a channel header (`to=self` / `to=user` / tool channels).

## Details

**Root cause.** Muse writes its channel header (` to`, `=self`, `<|message|>`) as ordinary generated tokens after the `<|start|>assistant` generation prompt. While the header is incomplete, `extract_reasoning_streaming` holds the text back, because it can still become framing. At stream end, `DelegatingParser.finalize_generation` calls `get_streaming_fallback_content`, which returned only the channel-classified `to=user` body. Output with no `<|message|>` has no channel, so the fallback returned nothing and the held-back text was lost. Non-streaming `extract_reasoning` returns such output as `content` (no Muse message found). AgentX warmup uses `max_tokens=1`, so all its warmup requests hit this.

**Fix.** In `get_streaming_fallback_content`, if the output contains no `<|message|>`, return the text not yet streamed as content. The condition is the same one that makes `extract_reasoning` return the whole output as content (`_muse_messages` finds no header without `<|message|>`). The fallback runs only once, at stream end, and only when the reasoning phase did not end. Output with a header takes the existing path without change.

**Not a duplicate.** We searched open and closed PRs and issues (`muse streaming`, `muse reasoning parser`, `get_streaming_fallback_content`, `muse empty stream`, `muse max_tokens=1`). No PR or issue reports or fixes this case. #62728 (open, perf) changes the same file, but not `get_streaming_fallback_content`; a rebase conflict is possible, but the two changes are independent. #60969 makes a similar fallback fix for K2 Horizon.

**CI.** `tests/tool_use/test_muse.py` runs in the "Entrypoints Integration (API Server Generate)" step (`pytest -v -s tool_use`; `source_file_dependencies` include `vllm/` and `tests/tool_use`). The new test needs no checkpoint and no GPU. We cannot add a CI regression test through `RemoteOpenAIServer` with real weights: the only Muse checkpoint is an 816B model that needs 8 GPUs. We did the end-to-end validation above outside CI.
