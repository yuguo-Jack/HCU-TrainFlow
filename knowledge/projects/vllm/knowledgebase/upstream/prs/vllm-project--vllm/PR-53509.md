# [Weight Reload] Add module-owned runtime buffers and staged reload lifecycle

[Upstream PR](https://github.com/vllm-project/vllm/pull/53509) · state: open · merged: False

## Original PR description

## Purpose

Implements the ownership and reload lifecycle in #57895. Part of #53343; split from #53344.

PWAL can produce a correct temporary tensor and then restore a graph-captured allocation containing the previous value. Helpers may also keep aliases to discarded temporary storage. Source-dropping model transforms additionally need the current checkpoint weights to remain available until packing completes.

## Changes

- Declare semantic derived buffers, preserve None/late schemas, and distinguish derived state from static and protocol buffers.
- Materialize once; validate shape/dtype/device and update existing storage in place.
- Preserve first derived allocations produced during reload; commit PWAL-produced values before stable placement.
- Run quant/module preparation hooks before any meta placement, so unsupported reload can fail before changing weight storage.
- Stage opted-in source modules until their owner/parent process_weights_for_reload() consumes checkpoint values and releases sources; then restore stable runtime storage.
- Add common publishing and helper binding/rebinding without a hard-coded MoE namespace.
- Dispatch post_weights_reload() only after all primary storage and deferred attention are final, children before parents and quant methods before module hooks.
- Retain existing CUTLASS W4A8, FlashInfer CUTLASS/B12x and TRT-LLM FP8/MXFP4 consumers as integration examples.

Source-dropping representations use staged transform/copy-back. Recomputable secondary state uses completion from final weights. A materialized cache does not prove freshness.

## Boundaries

This supplies lifecycle/storage primitives, not selective reload eligibility or support. A future #54477 dispatcher can call completion after refresh_derived_state(). Wake protocol state stays in #53510/#53511. Opaque FlashInfer packed weights remain unsupported for reload; #59002 only owns explicit alphas and rejects unsafe reload. The CUDA Graph oracle is a separate validation follow-up.
