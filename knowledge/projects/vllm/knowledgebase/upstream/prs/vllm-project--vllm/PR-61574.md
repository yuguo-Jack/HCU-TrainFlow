# [Bugfix][Structured Output] Mask grammar-invalid implicit reasoning ends

[Upstream PR](https://github.com/vllm-project/vllm/pull/61574) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

With an engine-based reasoning parser, a structured-output request fails with "grammar rejected tokens" and HTTP 500 when the model samples an implicit reasoning end, such as GLM's `<tool_call>`, that the request's grammar cannot start with. Reasoning rows of the bitmask are unconstrained, so the token can be sampled, and since #59627 it is fed to the grammar. This masks those tokens while the request reasons. Implicit ends the grammar accepts stay allowed.

Related: #60722 (RFC; this is the "remaining issue" it describes, using its first option restricted to grammar-rejected tokens), #59627 (feeds the implicit end to the grammar), #59608 (`required`/named tool calls, which must keep `<tool_call>` allowed), #61456 (open; also edits `_fill_bitmasks`).

## Claims

- A request whose grammar rejects an implicit reasoning end as its first token (a JSON schema, `tool_choice="none"` with `response_format`) can no longer sample that token while reasoning, so it no longer ends in "grammar rejected tokens".
- Requests whose grammar accepts the implicit end are unchanged: `tool_choice` `required`, named, and `auto` with tools (with or without `response_format`).
- The explicit end (`</think>`) and every other token stay allowed while reasoning. Draft and bonus rows under speculative decoding are masked the same way.

## Details

Path of the failure, `enable_in_reasoning=False`:

1. A request with a JSON schema is reasoning. `_get_constraint_bounds` puts `constraint_start` past every scheduled row, so `grammar_bitmask` fills each row with the full mask.
2. The model samples `<tool_call>`, which `Glm47MoeParser` treats as an implicit reasoning end: it ends reasoning and starts a tool call.
3. `accept_tokens` finds that end and, since #59627, sets `grammar_start` to its offset, so `<tool_call>` is fed to the grammar. A JSON grammar rejects it and `accept_tokens` returns False.
4. The scheduler logs "Unexpected: grammar rejected tokens" and finishes the request with `FINISHED_ERROR`.

The change, in `StructuredOutputManager`:

- `ParserEngine.implicit_reasoning_end_token_ids`: reasoning-end tokens other than the explicit end, the same split `find_reasoning_end` uses to report an implicit end. Exposed through `ParserEngineReasoningAdapter`. This only adds a read-only property, so no parser changes behavior.
- `_masked_reasoning_ends`: the implicit ends the grammar rejects as its first token (`validate_tokens([t])`, non-mutating in every backend). The grammar does not advance before reasoning ends, so the set is computed once per request and cached on `StructuredOutputRequest`.
- `_fill_bitmasks`: a row the grammar does not constrain allows every token except those ids. Only rows before `constraint_start` (including the bonus row while reasoning) get them, in both the serial and the parallel fill. Constrained rows and rows after padding are unchanged.

Tradeoffs and limits:

- This changes the reasoning distribution only by removing tokens whose sampling makes the output invalid under the request's own constraint. The model keeps reasoning or ends with the explicit end. The alternative outcome is an error, so there is no flag.
- Same scope as #59627: engine-based parsers and single-token implicit ends. Multi-token or text-only ends (`deepseek_v4`, `inkling`) are not covered.
- Cost: one `validate_tokens` call per implicit end per request, and a bit clear per masked id on reasoning rows. No device work and no host sync.
- #61456 replaces the guidance path of `_fill_bitmasks` with a batch fill. Whichever lands second has to keep the reasoning-row mask.

# Reproducing the GLM-5.3 structured-output 500 (PR #61574)

## What fails

GLM-5.3 can end reasoning implicitly by emitting `<tool_call>` (token 154843) instead of `</think>`.
While the request is still reasoning, its grammar bitmask is not applied, so the sampler can pick 154843 freely.
Since #59627, that token is then fed to the request's grammar.
When the grammar is a pure JSON schema (`response_format` with no tools, or `tool_choice: "none"`), it cannot accept `<tool_call>`.
xgrammar rejects the token, the engine logs `Failed to advance FSM`, and the request returns HTTP 500.
Before #59627 the same requests returned a 200 with empty content.

PR #61574 masks implicit reasoning-end tokens in reasoning rows when the grammar cannot start with them.
The model then ends reasoning with `</think>` and produces schema-valid JSON.

With `tools` and `tool_choice: "auto"` the grammar is a structural tag that accepts `<tool_call>`, so that shape does not 500.

## The failing request

The conversation is a `Read` tool call whose result quotes GLM's own tags (`<tool_call>`, `<arg_key>`, `<arg_value>`).
The final turn asks for a JSON summary through `response_format: json_schema`.
Seeing the tags in context makes the model emit `<tool_call>` mid-reasoning on most seeds.

`repro_glm_so_500.py` below sends each row with seeds 0..N-1 and prints HTTP codes and JSON validity.
It uses only the standard library.

def messages(tool_result):
    return [
        {"role": "user", "content": "Read docs/parser.md, then give me a one-sentence "
         "summary of it and whether it mentions tags."},
        {"role": "assistant", "content": "", "tool_calls": [{"id": "call_1",
         "type": "function", "function": {"name": "Read",
                                          "arguments": "{\"file_path\": \"docs/parser.md\"}"}}]},
        {"role": "tool", "tool_call_id": "call_1", "content": tool_result},
    ]


ROWS = {

        messages=messages(TAGGED), response_format=RF),
    "fail3: tagged + json_schema, tool_choice none": dict(

    # Deterministic: forces <tool_call> during reasoning. Spec decode rejects
    # logit_bias with a 400, so this row only applies without MTP.
    "det: logit_bias <tool_call>, json_schema": dict(

}


def post(body):
    req = urllib.request.Request(
        f"http://localhost:{PORT}/v1/chat/completions", data=json.dumps(body).encode(),
        headers={"Content-Type": "application/json"})
    try:
        with urllib.request.urlopen(req, timeout=600) as r:
            return r.status, json.loads(r.read())
    except urllib.error.HTTPError as e:
        return e.code, None


def json_valid(resp):
    try:
        obj = json.loads(resp["choices"][0]["message"].get("content") or "")
        return isinstance(obj, dict) and set(obj) == {"summary", "mentions_tags"}
    except (ValueError, KeyError, TypeError):
        return False

        valid += code == 200 and json_valid(resp)
    print(f"{name:50} codes={codes} 500s={codes.get(500, 0)}/{N} json_valid={valid}/{N}",

@yzong-rh On the flag: I think the mask has to be the default, so a flag would only fit as an opt-out.
