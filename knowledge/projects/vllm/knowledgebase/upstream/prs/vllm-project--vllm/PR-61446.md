- JohnZhao01 · comment · 2026-10-17T17:13:19Z · [source](https://github.com/vllm-project/vllm/pull/61446#issuecomment-6237349488)

Thanks for this. I tested #61446 on DeepSeek-V4.1-Flash (4×H200, vLLM nightly-92044241, Rust frontend), in a build that
also contains #62189 (cc @BugenZhao @njhill, who are reviewing #62189).

**It fixes the role error.** Without this PR, any chat request with a `latest_reminder` message returns HTTP 400
(`chat role latest_reminder is not supported by this chat renderer`); `/tokenize` returns 500 with the same message.
With it, `[user, latest_reminder]` and `[system, user, latest_reminder]` return 200 in both chat and thinking mode, and the
prompts match the DeepSeek reference encoder (`encoding/encoding.py` @df42c109) token-for-token.

**Overlap with #62189.** Whichever of the two lands second needs a small rebase:

1. Code: #62189 refactors the transition block in `deepseek.rs`. `next_rendered_entry` is now computed once, and a single
   `should_write_transition` expression covers user-like entries and a final assistant entry. This PR's new arm
   `Some(ChatMessage::Custom { role, .. }) if role == "latest_reminder" => true` goes into the user-like `match` of that
   refactored block, and that is the whole resolution. I built and tested exactly that merge.
2. Test: `latest_reminder_before_assistant_still_transitions` uses the default `add_generation_prompt=true` and expects the
   prompt to end at `<｜end▁of▁sentence｜>`. With #62189 a final assistant message opens a new turn in that mode
   (#46256), so the expected string gains a trailing `<｜Assistant｜></think>`. The test checks the reminder → assistant
   transition, not the trailing prompt, so pinning `generation_prompt_mode = NoGenerationPrompt` in it, as the shared
   fixtures do, keeps it valid either way.

If this PR lands first, I'll handle both in #62189.

**FYI, model-side, not a renderer bug.** In chat mode the reference format puts the reminder after `</think>`
(`…<｜Assistant｜></think><｜latest_reminder｜>…`). For that prompt the model returned only EOS in 5/5 raw completions,
and 19/20 chat requests came back with empty content. In thinking mode the reminder sits inside `<think>`, and 20/20
replies followed it. It may be worth a note for users who send `latest_reminder` with thinking off.
