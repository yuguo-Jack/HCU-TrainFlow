# [Security] Skip target-only sampling observations in the acceptance estimator

[Upstream PR](https://github.com/vllm-project/vllm/pull/57533) · state: open · merged: False

## Original PR description

## Summary

When adaptive verification uses the online acceptance estimator, draft sampling copies only temperature and seed. Request-specific transforms such as `allowed_token_ids`, penalties, and `bad_words` are applied on the target but not on the draft, so accept/reject labels from those requests were pooled into worker-wide estimator coefficients used to size verification for later unrelated requests. This change drops those observations from estimator updates. Requests without those transforms still train the estimator as before.

## Changes

- `vllm/v1/worker/gpu/sample/sampler.py`: add `target_only_sampling_transforms()` for the draft-ignored sampling fields.
- `vllm/v1/worker/gpu/spec_decode/speculator.py`: drop masked rows before `OnlineAcceptanceEstimator.step`.
- `vllm/v1/worker/gpu/model_runner.py`: pass the mask from the sampler into `observe_verification`.

## Codepath coverage

- All OpenAI-compatible and SageMaker/gRPC inference entry points reach this sink through `GPUModelRunner` → `DraftModelSpeculator.observe_verification`. The skip is applied at that sink.
- DSpark with a confidence head does not construct the estimator (`acceptance_estimator is None`), so it is unchanged.
- Offline `LLM.generate` uses the same worker path.

## Duplicate-work check

Searched open/merged PRs for "acceptance estimator", "adaptive verification", "observe_verification", and "draft sampling parameters".
- https://github.com/vllm-project/vllm/pull/56724 applies draft-side top-k/top-p for acceptance rate; it does not isolate estimator updates and does not cover `allowed_token_ids`.
- https://github.com/vllm-project/vllm/pull/57107 disables Triton specialization on estimator kernels; not this control.

## Tests

- `test_target_only_sampling_transforms_match_draft_ignored_fields` / `test_target_only_sampling_transforms_are_per_request`: mask is true for `allowed_token_ids` and other draft-ignored fields, false for temperature-only.
- `test_observe_verification_drops_target_only_sampling_requests`: skipped rows do not accumulate into the estimator.
- `test_select_estimator_observations_*`: row filter keeps, drops-all, and passthrough cases.

- TheEpicDolphin · COMMENTED · 2026-10-29T21:44:19Z · [source](https://github.com/vllm-project/vllm/pull/57533#pullrequestreview-5705391630)

To make sure I understand correctly, this PR pauses fitting the acceptance estimator on requests that have extra sampling parameters applied by the target model but not by the drafter, which is pretty much all of them except temperature. Many models' set top-p/top-k by default, so this would cover most requests even when the client only sends temperature. It seems like this change is overly strict, and will stop the acceptance estimator from learning on most workloads while it keeps predicting with its initial/stale coefficients.

In https://github.com/vllm-project/vllm/pull/52228 I benchmarked with top-k and top-p sampling applied by the target model and observed on-par performance with the DSV4-Flash DSpark confidence head. For a reasonably confident target model, the acceptance estimator seems to predict well even with top-k and top-p applied. Have you observed poor fitting when any of the extra sampling parameters are applied?
