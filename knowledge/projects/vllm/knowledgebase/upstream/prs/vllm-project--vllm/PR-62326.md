# [Quantization] replace_parameter keeps the parameter object by default

[Upstream PR](https://github.com/vllm-project/vllm/pull/62326) · state: open · merged: False

## Original PR description

## Overview

`process_weights_after_loading` (PWAL) often replaces a loaded parameter with a fresh `torch.nn.Parameter`. That drops the parameter's class (`ModelWeightParameter`, ...) and its loader attributes (`weight_loader`, `output_dim`, ...), so weight reload and RL refit have to rebuild them.

This PR makes `replace_parameter` keep the registered object, like SGLang's `copy_or_rebind_param`. It is part 1 of 3:
- #62405 converts the remaining `layer.x = Parameter(...)` sites.
- #62407 keeps deleted and renamed params registered.

## Claims

- **`replace_parameter(layer, name, tensor)` keeps the existing parameter object:**
  - It copies `tensor` in when shape, stride, dtype and device match (`data_ptr` is kept); otherwise it rebinds `.data`.
  - It carries the new tensor's attributes over.
  - It registers a new param only when the name is not registered yet.
- **The `prefer_copy` flag is removed.** The one internal exception is online requantization sources (marked `requantization_source`), which `release_requantization_source_weights` releases by identity, so they still get new params.
- **Kept params keep their checkpoint-layout dim tags** (`input_dim`, `output_dim`, `packed_dim`), because the loader uses them to TP-shard on the next load. `parameter.py` is unchanged.
  - `MPLinearKernel._transform_param` hands each transform a shallow copy of the param: a new object of the same class that shares the data and has its own copy of the attributes. `permute_param_layout_` and Conch's zero-point unpacking retag and rebind that copy, and only its data goes to `replace_parameter`, so the kept param's tags are never touched.
  - The RDNA hybrid W4A16 kernel used to permute registered params directly. It now permutes through `_transform_param` too.
  - Compressed-tensors W8A16 FP8 transposes its weight to (K, N). It no longer retags the param; it sets `layer.processed_weight_dims = (0, 1)`, which Humming's `convert_linear_layer_to_humming_standard` reads.
- **`layer_utils.replace_parameter`** now delegates its re-register fallback to the core helper.
- **Existing callers that the new default affects:**
  - The per-site `prefer_copy=True` is dropped (MLA, Kimi-K3 MLA). Unquantized MoE now keeps the objects on the first load as well, not only on weight updates.
  - FlashInfer MoE-EP: the params must alias the megakernel buffers, which EPLB permutes in place, so it rebinds `.data` explicitly instead of copying.
  - The quantized lm_head copy (`online/lm_head.py`) is never loaded and shares the source storage, so it assigns a new Parameter directly instead of copying into the head.
  - ModelOpt NVFP4 `_nvfp4_*_for_gather` buffers are cloned. A kernel may now write its layout into the params in place, which would change these buffers.
  - The obsolete "plain Parameter for TorchDynamo" comment in `MPLinearKernel` is removed.

- `pre-commit` passes.

  - the single keep behavior;
  - the requantization source;
  - attribute carry-over;
  - a kept param transposed by a kernel transform keeps its checkpoint dims.
- `tests/quantization/test_keep_param_objects.py` (new; SM100 only) checks that each loaded param is the same object after PWAL, with its attributes, its loader and its checkpoint dim tags.

## Details

- **Coverage.** A whole-tree enumeration found 1786 statements reachable from PWAL that replace, delete or rename a module param (on `main`). This PR covers:

  | Rows | What |
  |---|---|
  | 282 | Converted: 270 existing `replace_parameter` call sites that now keep the object, plus 12 sites changed here |
  | 7 | Exceptions (below) |
  | 1238 | n/a: creation time, not a loader-visible param, or already keeps the object |

  #62405 covers 141 rows and #62407 covers 109 rows, plus 9 n/a rows that sit inside their hunks.

- **Exceptions** (no object is kept):

  | Site | Why |
  |---|---|
  | `online/requantization.py` release and `online/fp8.py` `del weight_scale` | requantization sources |
  | `online/lm_head.py` | the derived head is never loaded and shares the source storage |
  | `auto_gptq.py` MoE bias placeholders (2) | absent from the checkpoint; dropped so kernels see no bias |
  | `torchao.py` (2) | tensor subclasses cannot be written through `.data` / `copy_` |

- **torch.compile.** Kept `BasevLLMParameter` subclasses are traced through `__torch_function__`, so the Inductor graph split can differ from `main`. The semantics are the same: there were 0 graph breaks, and the logprob differences seen were within Inductor autotune run-to-run noise. `main` already keeps these subclasses for unquantized linear weights.
- **CI.** The new test is skipped on the H200/MI300 CI runners (it needs SM100).
