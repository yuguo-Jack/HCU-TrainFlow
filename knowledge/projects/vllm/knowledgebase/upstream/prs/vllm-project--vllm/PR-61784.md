# [Perf][Attention] FA2: faster short-query attention over long cached contexts

[Upstream PR](https://github.com/vllm-project/vllm/pull/61784) · state: open · merged: False

## Original PR description

> PR Description is Generated by AI Tools



## Overview

On FA2 GPUs (SM8x: A100, A10, L4, RTX 30/40), a short query over a long cached context runs on a handful of SMs and reads the KV cache once per query head. This PR routes that shape through a head-packed, KV-split context attention plus a causal new-token attention, merged by LSE. It is related to, but different from, #51320 / vllm-project/flash-attention#176 and #58013 (see Details).

## Claims

- Per-layer attention for a short query (2–64 tokens) over a 128K cached context on A100: **3.24 ms → 0.28–0.54 ms per layer (6.1× at GQA 4, 9–11.6× at GQA 5–8); 3.3–3.4× at 32K** (FA2 one call → this PR). Breakeven is around **8K** cached tokens, so the path is gated to `>= 32768`.
- End-to-end TTFT of a fully cached turn (token-id prompts, conc 1, A100): **Qwen2.5-7B at 128K: server prefill 126 → 43–54 ms, TTFT 301–308 → 219–230 ms (−26%); at 64K TTFT 171–177 → 122–131 ms (−28%)**.
- No change for decode (`q_len == 1`), uniform batches replayed from full CUDA graphs, FA3/FA4, DCP, quantized KV, sliding window, ALiBi, softcap, or sinks: all fall through to the existing call.
- Accuracy unchanged: needle retrieval through a cached 64K/120K prefix (path active) and GSM8K match `main`.

## Details

**Root cause.** FA2 packs the query heads of a GQA group into one tile, and turns on split-KV, only when `max_seqlen_q == 1` (`seqlenq_ngroups_swapped`). For any longer query its grid is `num_reqs × num_q_heads × cdiv(q_len, 64)`. A turn that appends a few tokens to a 128K cached prefix on Qwen2.5-7B (28 q heads, 4 KV heads) therefore launches 28 CTAs on 108 SMs, and each one streams the whole context for one query head, reading the KV cache 7 times. At q=50, K=128K that is 3.3 ms per layer, about 11× the HBM roofline, which is most of the server-side prefill time of the turn.

**Change.** When the batch qualifies, the builder plans, once per batch on the CPU (from `query_start_loc_cpu` and `seq_lens_cpu_upper_bound`, no device sync):
1. **Context.** Query heads are folded into rows (`[T·G, H_kv, D]`), so each CTA covers a whole GQA group and each KV block is read once per KV head. Each request's context is cut into block-aligned chunks presented to FA2 as separate varlen sequences (`seqused_k` per chunk, sliced block table), which gives FA2 the KV parallelism it lacks for `q_len > 1`. This is a non-causal call, since every query token sees the whole context.
2. **New tokens.** A causal call over the current step's K/V, the same as the DCP path already does.
3. **Merge.** One Triton kernel merges the chunk partials and the new-token result by log-sum-exp, writing the final output in place.

Per-chunk KV lengths are derived on the device from `seq_lens`, so an over-estimated CPU upper bound only adds empty chunks. FA2 reports `+inf` LSE for an empty sequence, and the merge skips those chunks.

**Gating.** The path is on only when all of these hold:
- FA2 is in use and the model uses GQA (`H_q > H_kv`).
- The KV cache is unquantized and DCP is off.
- The batch is causal, `max_query_len > 1`, and it is not a uniform batch that replays a full CUDA graph (`max_query_len <= max_decode_query_len`).
- `max_query_len × G <= 512`, and the longest cached context is at least 32768 tokens.

The layer itself must also have no sliding window, ALiBi, softcap, sinks, or KV sharing. The two constants come from the kernel sweep above.

**Relation to other work.**
- #51320 and vllm-project/flash-attention#176 enable FA2 split-K for `q_len > 1` inside the kernel. That fixes the parallelism but not the per-query-head KV re-reads, and it is blocked on the FA submodule bump. With it merged, the packed context call here would still read KV G× less.
- #58013 splits mixed decode+prefill batches so the decodes get the `q_len == 1` path. That is complementary and does not cover requests whose own query is longer than one token.
- FA3/FA4 already pack GQA and split KV, so this is FA2-only.

**Limitations.**
- Speculative-decoding verify steps (`q_len = k+1`) usually run as uniform batches replayed from full CUDA graphs, so they are not covered here. Making the plan graph-capturable would need persistent, max-sized plan buffers, which is a follow-up.
- Below the context gate, three launches cost more than they save.
- Code size is about 390 lines outside tests, mostly the planner and the merge kernel.
