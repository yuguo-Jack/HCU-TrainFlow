# [Bugfix][MRV2] Preserve MTP query lengths in idle DP batches

[Upstream PR](https://github.com/vllm-project/vllm/pull/64878) · state: open · merged: False

## Original PR description

## Overview

Fix a DP synchronization failure in MTP with adaptive verification. When a MoE replica is idle, its dummy batch can use a different query length from the target's DP agreement. Draft prefill then hits an assertion, and the server becomes unhealthy.

## Claims

- Preserve the agreed query length while keeping dummy rows and CUDA graph padding separate.
- Add a two-GPU server regression covering EP off and on.

## Validation

Tested with Qwen3.5-35B-A3B-FP8, TP1/DP2, MTP3, adaptive verification, Triton attention/GDN/MoE, `FULL_DECODE_ONLY` and prefix caching disabled. Each run sent waves of 32, 1 and 8 requests with 64 output tokens each.

| Configuration | Before | After |
| --- | --- | --- |
| EP off | DP sync assertion; `/health` returns 503 | 41 requests complete; health checks return 200 |
| EP on, `allgather_reducescatter` | Same assertion and 503 | 41 requests complete; health checks return 200 |

The before-fix logs show:

```text
AssertionError: reusing a DP sync taken over a different batch
E assert 503 == 200
```

The InputBatch and DP utility suites passed 16 tests. All applicable pre-commit hooks passed, including mypy and Buildkite test tethering. The added CI job has not run upstream.

Both arms used Python sources at `7b77ed581d92fa14e34ab43344837bb1ca1b4257`, identical tests, two RTX PRO 5000 72GB GPUs and Torch 2.14.0+cu130. They reused precompiled `d492ee786` native extensions. The local model snapshot is recorded as revision `9d1823d2dee688a6b25e77009dc727688c44936e` in its existing manifest; weights were not rehashed for this review. The test constrains output to one token ID to check liveness and output bookkeeping; it is not an accuracy or performance evaluation.

## Details

A varlen FULL graph can reserve four request slots for four tokens. The dummy batch used that capacity to construct four one-token rows, even when the target DP agreement specified one four-token row. Draft prefill reused the agreement and rejected the mismatch.

Pass the agreed uniform count to `make_dummy` and keep the graph capacities separate from the active dummy rows. Padding rows have zero query and sequence lengths; context and state-slot writes only cover active rows. When the agreed count is `None`, the existing even split is retained. This also corrects uniform dummy geometry in single-rank varlen profiling.

Related work: [#60049](https://github.com/vllm-project/vllm/pull/60049) addresses PIECEWISE padding and shares some padding/context changes; it does not cover this FULL/DP agreement mismatch. [#54798](https://github.com/vllm-project/vllm/pull/54798) adds an opt-in MiniMax-M3 execution contract. [#54065](https://github.com/vllm-project/vllm/pull/54065) and [#62715](https://github.com/vllm-project/vllm/pull/62715) address profiling shapes and GDN state metadata.
