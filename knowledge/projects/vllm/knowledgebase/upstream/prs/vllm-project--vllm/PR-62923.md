# [Feature][Spec Decode] Add GQA DSpark prefill context-KV-only loading

[Upstream PR](https://github.com/vllm-project/vllm/pull/62923) · state: open · merged: False

## Original PR description

## Overview

Add opt-in context-KV-only weight loading for Qwen3 GQA DSpark drafts on
dedicated disaggregated-prefill producers. Keep the complete draft on decode.

## Claims

- Add `prefill_context_kv_only`, default false, for a dedicated MRV2 KV producer.
- Construct and load only the auxiliary-hidden-state projection, hidden norm,
  context K/V and K norm. Do not allocate draft query/output, MLP, embedding,
  vocabulary, Markov or confidence weights on the producer.
- Reuse DFlash fused context-KV computation and the existing cache transfer
  contract. Skip producer draft queries and draft graph capture; leave normal
  consumer drafting, sampling and verification unchanged.

## Validation

PP4 end-to-end validation used the PP-PD integration associated with #56957
(integration fork `65bad2204be2c848652e6f2c1c888239212ed2f2`) and vLLM v0.31.0
native libraries. This validation environment includes the PP-PD patches.

Environment: one eight-GPU CUDA node, compute capability 10.3, 267.69 GiB
CUDA-visible capacity per GPU; PyTorch 2.13+cu130, Mooncake CUDA13 0.3.13.post1,
MRV2 and BLHNC transfer. P: TP1/PP4, layers 22/20/20/16. D: TP1/DP4/EP.
Eight speculative tokens, probabilistic drafting, block verification, adaptive
verification off, target/draft FP8 KV, prefix caching off, decode CUDA graphs on.
Producer batch tokens 32768/max-seqs 8; decode batch tokens 128/max-seqs 32.

Private fixed business workload: reservoir 300 requests from a fixed 800,
seed 20260918, concurrency 8, output cap 1024, natural EOS. Original sampling,
tools and chat-template arguments are retained. Request-body hashes and input
token counts match across producer variants; warmups are excluded and the same
decode processes remain resident. No checkpoint tensors were changed.

| Producer | Acceptance including target | Token-weighted TPOT / ms | Success/errors |
|---|---:|---:|---:|
| Complete draft | 4.206129 | 6.1364 | 300/0 |
| Context-KV-only, public option | 4.183596 | 5.9190 | 300/0 |

Acceptance is `1 + accepted_draft_tokens / draft_rounds`; counter windows are
clean. These results show no material observed quality/latency regression, not
bitwise equivalence or a guaranteed speedup. Sampling and timing vary. One
additional prototype context-only run measured 4.196787 and 6.0182 ms; it is not
substituted for the public-option result.

Producer draft-exclusive parameter storage falls from 5.553 GiB to
**0.585950 GiB** (629,159,168 bytes, eight tensors), on the final PP stage.
Removing an additional 240 MiB duplicate fused-KV weight buffer makes the model
load profile fall from 119.58 to 114.38 GiB, about **5.20 GiB**. An already-shared
target vocabulary head is not counted as saved memory. Freed memory can be
reallocated to KV; total `nvidia-smi` usage need not fall by the same amount.

The GQA-only candidate passes **14 targeted CPU regression cases**: selected
weight loading, two-layer fused K/V ordering, optional checkpoint prefixes,
missing/duplicate/shape/dtype rejection, and dedicated producer role checks.
The isolated local wrapper imports the candidate module and runs the selected
suite with `--noconftest --import-mode=importlib`; it does not modify serving
runtime sources.

After rebasing onto upstream `817fa3518cd4bcc94b31e044c534c002e701c801`, all
14 targeted cases and relevant lint/type/config/CI-tethering checks were rerun
and passed. Only the feature-index link placement required conflict resolution;
the GQA feature patch is otherwise unchanged. The business measurements above
are the original local validation, not a new post-rebase model benchmark.

The entry point for a configured source checkout is:

```bash
.venv/bin/python -m pytest tests/models/test_dspark_mla.py -k context_only -q
pre-commit run --files <changed-files>
```

The existing basic-model CI job already runs this test file, including its
shared DSpark Markov tests. The private checkpoints/business data cannot run in
upstream CI; the model evaluation above is local validation. The producer was
also exercised with `VLLM_GPU_SYNC_CHECK=error`.

## Details

Minimal PD flow:

1. P runs the normal target and captures configured auxiliary hidden states.
2. The partial draft projects/normalizes those states and writes each layer's
   context KV, without executing draft query generation.
3. The existing connector transfers target and draft context KV under unchanged
   layer names and cache geometry.
4. D keeps its complete draft, reconstructs query-tail KV and verifies normally.

The producer model is constructed selectively before loading, rather than
allocating a complete draft and pruning it. GQA K/V weights are loaded directly
into the fused buffer; checkpoint tensors and file formats are unchanged.
Layer count, KV heads, head dimension and per-layer SWA/full attention come from
configuration, not from a hardcoded checkpoint or five-layer layout.

Initial scope: `Qwen3DSparkModel`, bias-free non-quantized BF16 draft weights,
dedicated `kv_producer`, MRV2, target/draft TP1 and PCP1/DCP1. Unsupported
architectures and roles fail closed. Do not enable this option on a consumer or
send standalone multi-token generation to the producer. Omitting the option
retains the existing full-draft behavior and graph-hash factors.

This saves producer weights and query computation, **not context KV storage**.
Cache capacity, stage balance and long-prefill temporary workspace remain
separate constraints. No new CUDA kernels, checkpoint-side runtime files or
connector-protocol changes are included.

This does not duplicate #55654/#60076 (KV insertion without selective weight
construction), #60320 (trailing-window context compute) or #54036 (PCP context
sharding). The implementation isolates partial model construction and weight
loading instead. Open PR duplicate checks were repeated before submission.

AI assistance (OpenAI Codex) was used. The human submitter reviewed the
implementation, confirmed running relevant code and approved submission.
