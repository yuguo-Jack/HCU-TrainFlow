# [Bugfix][Parser] Add flint parser

[Upstream PR](https://github.com/vllm-project/vllm/pull/63957) · state: open · merged: False

## Original PR description

## Overview and claims

Flint assistant turns may not generate `<think></think>` blocks at all, particularly on swe trajectories.
This breaks existing parsers.

The current recipe's glm47 parser (#62938) starts every reply in reasoning, so a reply without `<think>` would have its content/tool calls populate the reasoning field.
Forcing `<think>` every turn would probably be ok, but the model was not trained this way.

We implement a fix by subclassing the glm47 parser, rather than a minimal patch that adds flags to make the think block optional in glm47. Only flint would use those flags, which is a waste of API space.

This PR used AI, and the remainder of this PR description is AI-generated.

## Details

- **Fix:** `flint_config()` is `glm47_moe_config()` starting in content. `wait_for_reasoning=True` keeps the tool-call grammar, which excludes `<think>`, from starting before `</think>` or `<tool_call>`. `_events_to_delta` ends reasoning when a reply starts with text or a tool call, so a streamed reply without `<think>` reaches the tool parser.
- **Tradeoff:** deployments on the current recipe must switch to `--reasoning-parser flint --tool-call-parser flint`; the recipe and docs are updated.
- **Limitation:** on a turn with neither `<think>` nor a tool call, structured outputs never start, so `response_format` and `tool_choice="required"` are not enforced on that turn.
- **Not a duplicate:** the open Flint PR and issues (#63826, #63020, #63605) are about kernels, GGUF loading and KV cache. #62938 added the model with the `glm47` parsers.
