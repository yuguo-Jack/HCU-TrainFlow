# [Bugfix] Require mistral-common 1.13.1 for `developer` role support

[Upstream PR](https://github.com/vllm-project/vllm/pull/64861) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fix #64793: with `--tokenizer-mode mistral`, `/v1/responses` and `/v1/chat/completions` reject any input message with `"role": "developer"`. mistral-common 1.13.1 ([mistral-common#430](https://github.com/mistralai/mistral-common/pull/430)) now maps `developer` → `system` itself, so this PR raises the minimum to `mistral_common >= 1.13.1` and adds regression tests. vLLM's renderer code is unchanged.

## Claims

- With mistral-common 1.13.1, `developer` messages render to exactly the same prompt tokens as the equivalent `system` messages, so the issue's failing request now behaves like the working `system` request.
- Covers `/v1/responses`, `/v1/chat/completions` and `LLM.chat`, which all go through `MistralRenderer` → mistral-common's OpenAI-message conversion.
- A mid-conversation `developer` message renders exactly like a `system` message in the same position; it is not moved to the front.
- The caller's messages are not mutated.

## Validation

**Regression tests** in `tests/renderers/test_mistral.py`. Both use the real wiring (`ModelConfig(..., tokenizer_mode="mistral")` → `renderer_from_config`) and the real `mistralai/Mistral-7B-Instruct-v0.3` tokenizer, and call `render_messages_async` (the path both HTTP endpoints use):
- `test_renderer_treats_developer_role_as_system`: the `developer` prompt equals the `system` prompt, and the input is unchanged.
- `test_mid_chat_developer_preserves_native_system_message_grouping` (contributed by @anencore94 from #64934): `[user, developer, user]` gives the same token IDs as `[user, system, user]`, keeps two `[INST]` turns, and leaves the input unchanged.

```bash
python -m pytest tests/renderers/test_mistral.py tests/tokenizers_/test_mistral.py -v
```

| mistral-common | result |
|---|---|
| 1.13.0 (current minimum) | 2 failed (`ValueError: Unknown message role: developer`) |
| 1.13.1 (new minimum) | 72 passed, 2 skipped |

`pre-commit run --files <changed files>` passes, including the `pip-compile*` lockfile hooks. 1.13.1 has the same `requires_dist` as 1.13.0, so the lockfiles change only in the `mistral-common` version line.

CI: `tests/renderers/` is covered by the `:computer: (CPU) Reasoning + Renderers` step (`pytest -v -s renderers`), which installs from the updated `requirements/test/cpu.txt`.

Not run: an end-to-end `vllm serve` check against the 1T Large 4 model (no GPU access). Only prompt rendering changes, and the tests cover that path with a real tokenizer.

## Details

**Root cause.** `MistralRenderer` passes the request messages to `MistralTokenizer.apply_chat_template`, which calls mistral-common's OpenAI-message conversion. Up to 1.13.0, mistral-common only accepted `system`/`user`/`assistant`/`tool` and raised `Unknown message role: developer`. The OpenAI spec allows `developer` in both Chat Completions and Responses.

**Design.** An earlier revision of this PR mapped `developer` → `system` in `vllm/renderers/mistral.py`, reusing the HF renderer's helper. After @juliendenize released mistral-common 1.13.1 with the mapping built in, that code was dropped: the fix belongs in mistral-common, which owns the Mistral prompt format. The version bump follows the same set of files as #64169 (the 1.13.0 bump).

**Prior work.** #64800 (by @xixi-box) proposed the renderer-side mapping and was closed for procedural reasons. #64934 (by @anencore94) proposed the same; at @DarkLight1337's request it was consolidated here, and its mid-chat test is included as a separate commit with its original authorship and sign-off.
