# [Bugfix][RL] Handle non-contiguous sparse NCCL patches

[Upstream PR](https://github.com/vllm-project/vllm/pull/57131) · state: open · merged: False

## Original PR description

## Purpose

Fixes #57130.

NVIDIA defines [`ncclBroadcast`](https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/api/colls.html#ncclbroadcast) as copying `count` elements from a raw `sendbuff` pointer without PyTorch stride information. vLLM passes `tensor.data_ptr()` and `tensor.numel()` to NCCL, so a non-contiguous view such as `[0, 1, 2, 3][::2]` sends adjacent storage elements `[0, 1]` instead of logical values `[0, 2]`.

This PR makes sparse patch indices and values contiguous before broadcasting, adds a real two-GPU NCCL regression test using stride-2 CUDA views, and verifies that the inference worker correctly applies the logical sparse update.

Other built-in weight-transfer paths are not affected: packed NCCL linearizes tensors in `pack_tensors`, unpacked NCCL contiguousizes tensors before broadcasting, IPC exports contiguous tensors, and sharded RDT materializes contiguous buffers or preserves shape, stride, and offset metadata. Only sparse NCCL previously passed indices and values directly to PyNccl without normalization.
