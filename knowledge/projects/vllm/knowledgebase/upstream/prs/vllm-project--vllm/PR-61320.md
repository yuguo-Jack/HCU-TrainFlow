# Log EAGLE draft rope base at startup; warn on silent default

[Upstream PR](https://github.com/vllm-project/vllm/pull/61320) · state: open · merged: False

## Original PR description

## Overview

EAGLE/EAGLE-3 draft heads build their rotary embedding from the draft checkpoint's config only. When that config carries no rope keys, transformers silently defaults to base 10000, which can mismatch a target running at a different base. This PR adds startup logging of the resolved draft rope base and a warning for the silent-default case. Fixes #61231. No numerics are changed.

## Claims

- `SpeculativeConfig` logs the resolved EAGLE draft rope base and `rope_type` at startup.
- Warns when the draft resolves to transformers' silent default (base 10000) while the target uses a different base, naming both values.
- Documents in the EAGLE speculative-decoding guide that draft rope comes from the draft config only.

## Validation

- New `tests/config/test_speculative_draft_rope.py`: 4 tests, all pass (`pytest tests/config/test_speculative_draft_rope.py -v` → 4 passed).
- `ruff check` and `ruff format --check` pass on changed files.
- Neighboring `tests/config/test_speculative_draft_max_position_embeddings.py`: 3 unit tests pass; 3 Hub-dependent integration tests fail identically with and without this change (no HuggingFace Hub access in this environment).
- No numerics changed, so no model eval is needed.

## Details

- Root cause: `EAGLEConfig` wraps the draft checkpoint's `hf_config` without copying rope keys from the target; `get_rope` then resolves `rope_parameters.get("rope_theta", 10000)`. The mismatch is silent — no log line names the base in use.
- Design decision (per the issue reporter's own analysis): this deliberately does NOT inherit the target's rope base. Some draft checkpoints intentionally pin base 10000, and silently moving them to the target's base would be a regression. The fix is observability only (log + warn) plus docs.
- The "looks like default" check mirrors `get_rope`'s resolution exactly, so the log matches what the model actually builds.
