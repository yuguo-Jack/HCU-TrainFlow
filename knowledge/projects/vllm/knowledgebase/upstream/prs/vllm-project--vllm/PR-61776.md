# [Bugfix][Benchmark] Preserve custom audio without a tokenizer

[Upstream PR](https://github.com/vllm-project/vllm/pull/61776) · state: open · merged: False

## Original PR description

## Overview

Preserve custom audio benchmark inputs when `--skip-tokenizer-init` is used. `CustomAudioDataset.sample(tokenizer=None)` currently drops audio, breaking ASR requests and sending text-only chat requests.

## Claims

- Retain waveform/sample-rate payloads for ASR and base64 WAV payloads for multimodal chat without a tokenizer.
- Preserve existing prompt lengths, output-length defaults/overrides, and tokenizer/chat-template behavior.

## Validation

```bash
.venv/bin/python -m pytest tests/benchmarks/test_audio_dataset.py -q
# 35 passed
.venv/bin/python -m pytest tests/benchmarks/test_audio_dataset.py tests/benchmarks/test_endpoint_request_func_timing.py -q
# 56 passed
```

The 24 added parameterized cases cover both payload formats, tokenizer presence, output lengths, and template behavior. Restoring the original production code produces 10 additional failures in the tokenizer-free audio regressions. A separate localhost HTTP check also verified that real ASR multipart and chat JSON clients deliver the original 1,600 audio samples at 16 kHz; this is transport validation, not model inference.

I reviewed and understood every changed line and ran local testing successfully before submission. No model, hardware, inference command, or model-evaluation result is claimed by the automated checks above.

Applicable Python pre-commit hooks (including Ruff, mypy, typos, SPDX and test tethering) and `git diff --check` passed. The aggregate pre-commit command stopped on unrelated Go/actionlint installation. Broader neighboring tests retained baseline failures in Responses request IDs, GPT2 download setup, and CPU-only teardown. Existing Benchmarks CLI CI includes this test module.

## Details

Audio loading and payload construction were nested inside the tokenizer-present branch, while the tokenizer-free branch assigned `mm_content = None`. Construct audio once before token-length handling and keep chat prompts plain for the existing message builder. No endpoint, model, dependency, or generic `CustomDataset` behavior changes.

Duplicate checks found no open fix for audio retention without a tokenizer. #60506 concerns output lengths in the base `CustomDataset`; #44519 concerns chat-template kwargs; #61534 concerns SSE framing. Those behaviors are outside this patch.

AI assistance was used for investigation, implementation, tests, validation, and PR preparation. The human submitter reviewed the patch and approved the DCO sign-off.
