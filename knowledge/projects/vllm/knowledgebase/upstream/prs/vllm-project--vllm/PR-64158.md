# [ROCm][Bugfix][Kimi-K3] Build the folded q_b_proj / W_UK weight on the root model

[Upstream PR](https://github.com/vllm-project/vllm/pull/64158) · state: closed · merged: True

## Original PR description

## Purpose

#60110 folds `q_b_proj` and W_UK into one GEMM for Kimi-K3's MLA decode query on ROCm. The folded weight, `_w_fold`, is built in `KimiLinearForCausalLM.process_weights_after_loading`. But Kimi-K3 checkpoints load as `KimiK3ForConditionalGeneration`, and the model loader calls only the root model's `process_weights_after_loading`. The root model doesn't define one, so `_w_fold` stays `None`.

The fold is on whenever AITER MLA runs with an fp8 KV cache and no DCP / PCP. Every such serve then fails during startup, at the first CUDA graph capture (see the reproduction below). DCP > 1 is unaffected because the fold is off there.

This PR makes `KimiK3ForConditionalGeneration.process_weights_after_loading` call the text model's hook, which builds each MLA layer's `_w_fold`.

## How this PR fixes it

`process_weights_after_loading` now runs on the text model, which calls `_build_w_fold()` on every MLA wrapper. `_fused_decode` therefore gets a real `_w_fold`. The fold's math is unchanged; only the missing call is added.

```python
def process_weights_after_loading(self) -> None:
    self.language_model.process_weights_after_loading()
```
