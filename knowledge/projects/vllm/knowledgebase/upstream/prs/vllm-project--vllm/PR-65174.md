# [Bugfix][Kimi-VL] Set pad_token_id explicitly in KimiVLConfig

[Upstream PR](https://github.com/vllm-project/vllm/pull/65174) · state: closed · merged: True

## Original PR description



## Overview

`KimiVLConfig` passed `pad_token_id` to `super().__init__` as a keyword argument. With the dataclass-based `PreTrainedConfig`, `pad_token_id` is not a declared field.

## Claims

- Fixes the `TypeError: __init__() got an unexpected keyword argument 'pad_token_id'` raised when `KimiVLConfig` is constructed on a `PreTrainedConfig` base that does not forward unknown keyword arguments.
- `pad_token_id` is now assigned explicitly on `KimiVLConfig` before the `super().__init__` call, so the attribute exists regardless of how the base class handles unused kwargs.
- No change to the public constructor signature: existing callers passing `pad_token_id=` continue to work.
- No change to serialization behavior for the `pad_token_id` value itself; the fix only removes the reliance on an implicit `setattr` path.

## Validation

- Reproduction before the fix: construct `KimiVLConfig` on a base that rejects unknown kwargs (or monkeypatch the base `__init__` to not forward extras); observe `TypeError: __init__() got an unexpected keyword argument 'pad_token_id'`.
- After the fix: the same construction succeeds, and `config.pad_token_id` returns the supplied value.

## Details

`PreTrainedConfig` is a dataclass, and `pad_token_id` is not a declared field on it; the field is only used by `KimiVLConfig` itself.

I've checked the code on [huggingface](https://huggingface.co/moonshotai/Kimi-VL-A3B-Instruct/blob/main/configuration_kimi_vl.py) and #16387, it can be confirmed that MoonshotAI has modified the base `PreTrainedConfig`.
