# [Bugfix][Multimodal] Don't validate model-built dummy inputs against mm limits

[Upstream PR](https://github.com/vllm-project/vllm/pull/65689) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fixes engine startup for Pixtral (+ other models with the same problem) when a modality is embedding-only (`--limit-mm-per-prompt '{"<modality>": 0}'` with `--enable-mm-embeds`). This is the root cause of the failure observed in #65648.

## Claims

- Every model registered as of now obeys the contract that #32493 introduced.

## Validation

```shell
vllm serve mistralai/Pixtral-12B-2409 --tokenizer-mode mistral \
    --limit-mm-per-prompt '{"image": 0}' --enable-mm-embeds
```

## Details

#32493 added embedding input for disabled modality. It introduced the following split:

- User inputs are checked against `--limit-mm-per-prompt` and `--enable-mm-embeds` once, in the renderer (`BaseRenderer` calling `info.parse_mm_data`).
- Data the processor builds or re-parses is parsed with `validate=False`. #32493 switched both call sites:
  - the dummy inputs used for profiling (`get_dummy_inputs`)
  - the cache-miss items in `_get_cache_missing_items`

The split is needed because `MultiModalBudget` profiles each embedding-only modality with `mm_counts={modality: 1}` while its limit is 0. A dummy input that gets validated can never pass that check.

4 models including Pixtral override `get_dummy_inputs` and call `self.info.parse_mm_data(dummy_mm_data)` with the default `validate=True`. This PR fixes the processor-side contract violation. Without it, any deployment of these models that relies on embedding-only modalities still crashes at startup, including KV/EC consumers that should receive embeddings.
