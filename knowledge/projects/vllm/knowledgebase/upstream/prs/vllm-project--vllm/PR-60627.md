# [Perf][DCP] Vectorize SM100 direct Output/LSE consumption

[Upstream PR](https://github.com/vllm-project/vllm/pull/60627) · state: open · merged: False

## Original PR description

## Overview

Speed up the direct symmetric-memory DCP Output/LSE consumer introduced in
#50484. Publication, signaling, allocation, and buffer lifetimes stay unchanged;
this is a focused follow-up from our Shared-DCP work in #50009.

```text
ASIS
publish O/LSE -> signal -> one CTA per head
                          serial peer waits + shared weights -> final O

PR
publish O/LSE -> signal -> four independent warp/head consumers per CTA
                          parallel peer waits + vector loads -> final O
```

## Claims

- On 4x GB200, GLM-5.2-NVFP4 c1 TPOT improved by 2.27% and output throughput
  by 2.07% across two matched fresh-process pairs. c32 serving was neutral.
- Complete direct Output/LSE operator latency improved by 32.4%-40.7% across
  the tested GLM decode shapes, including publication and synchronization.
- No new workspace, communication phase, or runtime option. Dispatch uses the
  warp consumer for SM100-family GPUs, a 512-element value dimension, and at
  most 32 peers. Other devices/layouts retain the existing consumer.

## Validation

### Output/LSE operator: 32.4%-40.7% lower latency

Complete operator timing includes publication and synchronization, not just the
consumer kernel. On 4x GB200: BF16 O, FP32 LSE, 64 total heads, D=512, DCP4.
Mean of three process medians; seven timing trials per process, maximum-rank
CUDA-graph latency.

| Rows | Base | PR | Latency reduction |
| ---: | ---: | ---: | ---: |
| 1 | 17.162 us | 11.143 us | 35.07% |
| 8 | 17.162 us | 11.276 us | 34.30% |
| 32 | 18.951 us | 12.569 us | 33.68% |
| 64 | 22.021 us | 14.883 us | 32.42% |
| 128 | 36.527 us | 21.672 us | 40.67% |

Candidate process CV was 0.015%-0.053% across the full row sweep. These are
operator improvements, not end-to-end serving gains.

### Serving: 2.27% lower c1 TPOT; c32 neutral

GLM-5.2-NVFP4, TP4/DCP4/EP4, FlashInfer sparse MLA, FP8 KV, 3072 input tokens,
128 output tokens, prefix caching disabled, 1800 MHz SM clocks. Each process
used 8 counted c1 requests and 128 counted c32 requests after warmup.

| Load | Base TPOT | PR TPOT | Base throughput | PR throughput |
| --- | ---: | ---: | ---: | ---: |
| c1 | 19.552 ms | 19.109 ms | 46.576 tok/s | 47.538 tok/s |
| c32 | 81.386 ms | 81.386 ms | 340.973 tok/s | 340.987 tok/s |

c1 TPOT improved by 2.09% and 2.44% in the two pairs; candidate process CV was
0.19%. c1 p99 ITL improved by 3.49%. Mean TTFT changed by +0.27% at c1 and
-0.06% at c32; c32 p99 ITL changed by +0.13%. These small TTFT/c32 differences
are not claimed as improvements.

**Serving validation scope:** both arms use the same pinned model runtime
`71323cbf1a` (including the merged #54908 prefill correctness fix), with only
the stable-ABI Output/LSE operator rebuilt from base `d61081dc3d` or this PR.
This is a matched kernel A/B in an integrated model, not a full current-main
model-build validation. MRV2 uses FULL_DECODE_ONLY/breakable CUDA graphs with
compilation disabled. Both arms use the same explicit FlashInfer workspace
size and disabled FlashInfer all-reduce/JIT-autotune settings.

- Distributed test: 4 passed on DCP2/DCP4, covering FP16/BF16, both LSE bases,
  empty shards, padded strides, partial CTAs, both workspace slots, and
  changing-input CUDA-graph replay. Wired into the existing two-B200 CI job.
- Same 32-question GSM8K smoke with prompts padded to 3072 tokens: baseline
  28/32 and 26/32; candidate 29/32 and 30/32. All returned finite logprobs.
  This is a small smoke test, not a full accuracy or bitwise-equivalence claim.
- Applicable pre-commit checks passed. The contributed benchmark also passed
  a four-GPU smoke run.

## Details

Each warp handles one output head. Lanes load peer readiness/LSE in parallel,
then combine aligned 16-byte payloads in FP32 registers. Four heads share a CTA,
removing the consumer's shared-weight staging and CTA-wide barrier. Final output
still waits for every contributing peer. Zero-weight payloads remain unread,
preserving empty-shard handling and fail-closed timeout behavior.

This does not duplicate #48196's project-before-merge/helix transport changes.
It changes neither the reduction's mathematical contract nor its transport, and
does not include Query, Top-K, Indexer, or generic Shared-DCP framework changes.
The test fixture also keeps query boundaries explicitly int32, as required by
the existing operator API.
