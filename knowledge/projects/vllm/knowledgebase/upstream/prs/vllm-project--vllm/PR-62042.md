# [Kernel] Add router GEMM kernels for (5120, 256) and BF16 output to ll_bf16_gemm

[Upstream PR](https://github.com/vllm-project/vllm/pull/62042) · state: closed · merged: True

## Original PR description



## Overview

First, low-risk slice of #61978 (Reflection Beam): kernel coverage for Beam's router shape and a BF16 output for `ll_bf16_gemm`. Nothing here selects Beam-specific code, and existing shapes, dtypes and dispatch are unchanged. This does not enable the model end to end.

## Claims

- `fp32_router_gemm` supports `(hidden=5120, experts=256)` for up to 48 tokens, with a Blackwell-tuned launch geometry. `GateLinear` uses it for that shape: on SM100 with BF16 input, up to 48 tokens when the count is a multiple of 8, otherwise up to 16. Larger batches go to BF16x3.
- `ll_bf16_gemm` accepts `output_dtype=torch.bfloat16`. It still accumulates in FP32 and only the epilogue changes. This PR also adds tuned split-K configs for K=5120, N∈{1792, 3584}. FP32 output stays the default, and both dtypes keep separate compile-cache entries.
- BF16x3 router GEMM fixes:
  - It raised `KeyError` when a shape had overrides but none for the current token bucket; it now falls back to the heuristic.
  - It returns early for zero tokens.
  - It adds a `(5120, 256)` tile override.
- `grouped_topk` returns empty outputs for zero tokens, e.g. on an idle DP rank, instead of launching the kernel.

## Details

- The new router GEMM instantiations cover M=1..48 for `(5120, 256)` only. The other shapes keep their limit of 32.
- An existing model would also switch to the FP32 kernel if it has an FP32 router weight, hidden size 5120 and 256 experts, since that pair is now in `GateLinear.FP32_SUPPORTED_SHAPES`.
- Beam's remaining pieces will follow in separate PRs: MegaMoE deferred finalize, parsers and the model itself.
- Not a duplicate: open PRs that touch the router GEMMs (#61903, #50177, #60681) cover other shapes, architectures or compile behavior.
