# [Bugfix] Validate activation schemes for Marlin and Triton WNA16 MoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/57091) · state: closed · merged: False

## Original PR description

## Problem and change

Marlin and Triton WNA16 MoE capability checks currently accept arbitrary activation keys whenever the weight key matches. An NVFP4 W4A4 request can consequently select a Marlin path that does not implement NVFP4 activation quantization.

Require the activation contract actually used by these integrations (`activation_key=None`). Apply the check in `MarlinExpertsBase`, covering standard and batched Marlin, and in `TritonWNA16Experts`. Preserve FP8's existing Marlin fallback by explicitly resolving its effective activation key in the FP8 oracle, matching the quantization config it constructs. INT WNA16 and MXFP4 selectors already supply the corresponding effective key.

**This does not mean Marlin cannot quantize activations.** Marlin supports internal INT8/FP8 activation quantization selected separately through `VLLM_MARLIN_INPUT_DTYPE`; those existing integrations still use `activation_key=None` and pass unquantized inputs into the experts wrapper. The environment-controlled A8 mode, its weight preparation, and the internal quantizer are unchanged. Nonempty activation keys must not be accepted merely because some other activation quantization mode exists. The stale constructor comment saying activation quantization is unimplemented is replaced with this distinction.

Declared NVFP4 W4A16 remains eligible; explicit/automatic NVFP4 activation-quantized requests cannot substitute Marlin. Per-token keys and CuTe-DSL support remain in the later split PRs.

## Relationship to existing work and attribution

This is the first prerequisite extracted from #50030 following the [requested three-way split](https://github.com/vllm-project/vllm/pull/50030#issuecomment-5690078085). The Marlin guard is taken from S1ro1's change, with S1ro1 retained as the first commit author. This extends that fix to Triton WNA16, protects FP8 fallback compatibility, and adds regression coverage. This PR owns all Marlin activation-contract changes. The per-token-specific Marlin guard is removed from #57176 in favor of this generic check, so merge order is #57091 → #57176 → #50030. No per-token key needs to be introduced here: any nonempty activation key is rejected by the existing generic rule.

Searches for open Marlin/activation, weight-only activation, and #50030-related PRs found no separate PR for this capability fix. Related but distinct work: #56535 fixes B12x's W4A16 execution handoff; #55675 concerns compressed-tensors MXFP4 linear activation-declaration reporting. Dense Marlin linear kernels have separate, intentional weight-only fallback interfaces and are not changed here. The OCP MX emulation capability predicate is intentionally unconditional because its oracle selects it directly.
