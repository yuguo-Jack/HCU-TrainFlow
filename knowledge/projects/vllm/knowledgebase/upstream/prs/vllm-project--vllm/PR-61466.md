# [Mamba] Declare prefill checkpoint alignment once per layer

[Upstream PR](https://github.com/vllm-project/vllm/pull/61466) · state: open · merged: False

## Original PR description



## Overview

Each Mamba layer declares the token alignment of the prefill checkpoints it can export from inside a forward pass once, in `MambaBase.get_prefill_checkpoint_alignment()`. `MambaBase.get_kv_cache_spec` derives `num_prefill_checkpoint_blocks` and `prefill_checkpoint_alignment` from it. Mamba2 (#57329), GLM-5.3-Flash KDA (#56960) and Kimi-K3 KDA (NVIDIA and AMD) drop their `get_kv_cache_spec` overrides. Split out of #60050.

## Claims

- No behavior change. Every layer publishes the same spec fields as before: Mamba2 `1`, FlashKDA `16`, ROCm fused KDA `KDA_CHECKPOINT_ALIGNMENT`, every other Mamba layer none.
- Four copies of the same `replace(spec, num_prefill_checkpoint_blocks=..., prefill_checkpoint_alignment=...)` override become one, so the two fields can no longer disagree. A checkpoint block reserved without an alignment would cache a state that is never written.
- The platform gets one place to read a layer's checkpoint grid. #60050 reads it to keep align-mode blocks on FlashInfer GDN's 64-token grid; once both land, the KDA layers' alignments feed the same rule.

## Details

- `get_prefill_checkpoint_alignment()` returns `None` by default. Readers act on it only in align mode, as before.
- Kimi-K3 AMD's "KDA prefill checkpoint enabled" log moves from `get_kv_cache_spec` to `__init__`.
- Not a duplicate: no open PR touches these overrides (searched 2026-10-13). #60888 changes the checkpoint validity rule in `kv_cache_interface.py`, which this PR does not touch.
