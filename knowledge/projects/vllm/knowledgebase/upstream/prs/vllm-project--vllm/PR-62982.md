## Overview

Follow-up to #61929: add opt-in startup auto selection, small-batch split-K tuning, and one-sided prefill page gathering with NCCL fallback.

**Depends on #61929.** [Review only this PR's increment](https://github.com/wolfcomos/vllm/compare/8684e46b5b96f1be802aebca4285442019e66f2e...a7d1ba0e367e8fbce8aed7cede3b1d723e177b8f): **+358/−12, four files**. Files changed includes the prerequisite until it merges; merge #61929 first.

## Claims

- `indexer_cache_sharding="auto"` selects once at startup: supported TP4, full decode graphs, Q1, and configured context/capacity ≥192Ki/32 or ≥1Mi/8. Default remains off; TP2 uses explicit `on`.
- Tune decode splits for small batches and gather prefill pages through symmetric staging; use NCCL when staging is unavailable or insufficient.
- No per-request cache-layout switching or new dynamic kernel-selection mechanism.

## Validation

```bash
pytest tests/distributed/test_minimax_m3_indexer_sharding.py -v
```

Local pre-commit and focused documentation rendering passed. GPU validation is manual and outside CI; public GPU validation evidence remains to be provided.

## Details

This tunes sharded storage introduced by #61929; #59979 changes FMHA scoring, and #59980 retains replicated index-K storage. Auto uses deployment limits, not actual request lengths/batches; short requests can regress. AI assistance was used.
