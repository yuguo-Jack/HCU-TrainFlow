# [Quantization] Support nvfp4_per_token MoE activation override for compressed-tensors

[Upstream PR](https://github.com/vllm-project/vllm/pull/64209) · state: open · merged: False

## Original PR description



## Overview

Make compressed-tensors NVFP4 MoE checkpoints honor `--quantization-config.moe.activation=nvfp4_per_token`, which today only works for ModelOpt checkpoints (#56740).

Not a duplicate: no open PR adds the per-token override to compressed-tensors; the closest, #56740 (merged), covers ModelOpt only.

## Claims

- Problem: on a compressed-tensors NVFP4 MoE checkpoint, the per-token activation override never reaches `CompressedTensorsConfig`, so the MoE keeps using the checkpoint's static input scale. compressed-tensors has no field for a per-token global scale, so a checkpoint cannot request it either.
- Fix: pass the existing runtime override to `CompressedTensorsConfig` (same path ModelOpt uses) and on to `CompressedTensorsW4A4Nvfp4MoEMethod` as its `activation_key`, which already handles per-token activations on main. The checkpoint format is unchanged; without the override nothing changes.
- Effect: per-token NVFP4 MoE activations now work for compressed-tensors checkpoints, with GSM8K accuracy matching the static-scale path.

## Validation

GB200, `RedHatAI/Qwen3-30B-A3B-NVFP4`, GSM8K 5-shot, 1319 questions (`tests/evals/gsm8k/gsm8k_eval.py`):

| Config | static input scale (default) | `moe.activation=nvfp4_per_token` |
|---|---|---|
| TP1 | 0.886 | 0.879 |
| TP4 + EP | 0.889 | 0.886 |

With the override, all 48 MoE layers report `per_token_activation=True` on the FlashInfer TRT-LLM backend; without it, `False`.

```bash
vllm serve RedHatAI/Qwen3-30B-A3B-NVFP4 --quantization-config.moe.activation nvfp4_per_token
python tests/evals/gsm8k/gsm8k_eval.py --port 8000 --num-questions 1319 --num-shots 5
```

Tests: new unit tests in `tests/quantization/test_compressed_tensors.py` (override plumbing and validation, mirroring the ModelOpt ones) and a Blackwell init test in `tests/quantization/test_blackwell_moe.py`. `test_compressed_tensors.py`, `test_modelopt.py` and `test_quantization_config_args.py`: 204 passed; the same 6 fail on the base commit on GB200 (e.g. INT8 GEMM not supported on SM100).

## Details

Same restrictions as the ModelOpt path: W4A4 checkpoints only, and only MoE backends that support per-token activations (validated on FlashInfer TRT-LLM); the checkpoint input global scales are ignored when the override is set.
