## Overview

Roll back a newly registered NIXL agent when descriptor preparation fails in the P2P KV-offload transport. Related to #63602, gap 4 only.

AI assistance (OpenAI Codex) was used for investigation, implementation, tests, and this description. The human submitter confirmed completion of manual review and authorized submission. The reviewed contribution carries their DCO sign-off. Original-submission results below are the recorded server runs; review follow-up results are the recorded local runs. No additional human test execution is asserted.

## Claims

- A failure in `get_xfer_descs` or `prep_xfer_dlist` rolls back the unpublished remote registration.
- A failed repeat using already-published native metadata leaves that registration owned by its existing peer.
- Cleanup failure is logged without replacing the original registration exception. Native cleanup success cannot be guaranteed when NIXL itself rejects removal.

## Details

The registration worker can register native metadata and then fail before `_publish_peer` records cleanup ownership. `_build_peer_handles` now uses the existing independent teardown helper on that exception path, while preserving the exception and avoiding removal of an already-published native name. All registration builds now use the existing single-worker executor, including the synchronous entry point; the generation/publish flow is unchanged. No steady-state inference work, synchronization, public option, or model arithmetic is added.

Duplicate checks covered the issue discussion, open PRs referencing #63602, and P2P/NIXL rollback keywords. #59524 fixes incomplete registration in the separate KV connector `nixl/base_worker.py`; this change fixes the P2P secondary-tier transport. #61667 covers consumer-slot quarantine for unconfirmed writes. Contributor `tejachavali` expressed interest in the broader issue; this PR does not claim assignment or close the full issue.

- nilig · COMMENTED · 2026-10-26T05:47:15Z · [source](https://github.com/vllm-project/vllm/pull/63628#pullrequestreview-5647876614)

The published-name check leaves a window when the synchronous `add_remote_peer` runs alongside an async registration for the same peer. If the older registration fails after the newer one has called `add_remote_agent()` but before its `_publish_peer`, the name is not published yet, so the rollback removes the agent the newer registration then publishes. The transport ends up with a published dlist for an agent that no longer exists. Reproduced at `18349008c` with the real `NixlTransport` constructor and a fake external agent:

```
B entered prep while A was blocked: True
published={'peer:1': 'nixl-peer-name'} registered=set()
AssertionError: published agent was removed
```

The P2P session only calls `add_remote_peer_async`, so this is an API-level race, not a path production hits today. Wonder if we could also route the synchronous `add_remote_peer` through `_reg_executor`: async registrations are already serialized there, so the published-name check and the rollback would both finish before the next build starts. The synchronous call would then raise when superseded, as the async one does. Probe below in case it is useful as a regression test.

<details><summary><code>test_probe_window.py</code></summary>

```python
"""Older failed registration A rolls back while newer sync registration B
has added the agent but not yet published it."""

import threading
from unittest.mock import MagicMock, patch

import numpy as np

from vllm.v1.kv_offload.tiering.p2p.data.nixl import NixlTransport


def test_rollback_while_newer_registration_is_building():
    agent = MagicMock()
    with (
        patch("vllm.v1.kv_offload.tiering.p2p.data.nixl._NixlAgent", return_value=agent),
        patch("vllm.v1.kv_offload.tiering.p2p.data.nixl._NixlAgentConfig"),
    ):
        transport = NixlTransport("test:1", memoryview(np.zeros((8, 1024), dtype=np.uint8)))
    registered: set[str] = set()

    def add_remote_agent(metadata):
        registered.add("nixl-peer-name")
        return "nixl-peer-name"

    a_in_prep, release_a = threading.Event(), threading.Event()
    b_in_prep, release_b = threading.Event(), threading.Event()
    calls = 0

    def prep_xfer_dlist(*args, **kwargs):
        nonlocal calls
        calls += 1
        if calls == 1:
            a_in_prep.set()
            assert release_a.wait(10)
            raise RuntimeError("A failed")
        b_in_prep.set()
        assert release_b.wait(10)
        return MagicMock(name="remote_dlist")

    agent.add_remote_agent.side_effect = add_remote_agent
    agent.remove_remote_agent.side_effect = registered.discard
    agent.prep_xfer_dlist.side_effect = prep_xfer_dlist
    errors = []

    def register_b():
        try:
            transport.add_remote_peer("peer:1", b"meta", 0x1000, 8, 1024)
        except BaseException as exc:
            errors.append(exc)

    try:
        old = transport.add_remote_peer_async("peer:1", b"meta", 0x1000, 8, 1024)
        assert a_in_prep.wait(5)
        transport.remove_remote_peer("peer:1")
        b = threading.Thread(target=register_b)
        b.start()
        concurrent = b_in_prep.wait(1.0)
        print(f"B entered prep while A was blocked: {concurrent}")
        release_a.set()
        try:
            old.result(timeout=5)
        except RuntimeError as exc:
            print(f"A: {exc}")
        assert b_in_prep.wait(5)
        release_b.set()
        b.join(timeout=5)
        published = dict(transport._peer_nixl_names)
        print(f"published={published} registered={registered} b_errors={errors}")
        assert errors == []
        assert registered == {"nixl-peer-name"}, "published agent was removed"
        assert transport.write_blocks("peer:1", [0], [1]) is not None
    finally:
        release_a.set()
        release_b.set()
        transport.close()
```

Drop it into `tests/v1/kv_offload/tiering/p2p/` and run `pytest --confcutdir=tests/v1/kv_offload/tiering/p2p tests/v1/kv_offload/tiering/p2p/test_probe_window.py -s`.
