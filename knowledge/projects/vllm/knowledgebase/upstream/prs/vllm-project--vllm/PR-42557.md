The current implementation of `extra_body` merging overwrites the `model` and `messages` fields, which contradicts the documentation in the help text (line 1548) and the comment at line 232. To ensure that built-in fields take precedence as intended, use `setdefault` when merging `extra_body` into the `payload`.

```suggestion
    # Merge extra_body fields as defaults so explicit payload keys take precedence
    if extra_body:
        for key, value in extra_body.items():
            payload.setdefault(key, value)
```

`json.loads()` can return non-dictionary types (like lists or null), which would cause `extra_body.update()` to raise a `TypeError`. Additionally, the current error handling only catches `JSONDecodeError`. It is safer to verify that the parsed result is a dictionary before updating.

```suggestion
    if args.extra_request_body:
        try:
            parsed_extra = json.loads(args.extra_request_body)
            if not isinstance(parsed_extra, dict):
                raise ValueError("The provided JSON must be an object.")
            extra_body.update(parsed_extra)
        except (json.JSONDecodeError, ValueError) as e:
            raise ValueError(
                f"--extra-request-body is not valid JSON object: {e}"
            ) from e
```
