# [Docs] Document kv_load_failure_policy in MooncakeStoreConnector guide

[Upstream PR](https://github.com/vllm-project/vllm/pull/63055) · state: open · merged: False

## Original PR description

Closes #62866

### What this does
The MooncakeStoreConnector documentation doesn't mention `kv_load_failure_policy`. When running Mooncake as a shared prefix cache (or with single-node disk offloading), the default `"fail"` policy can cause requests to terminate silently with an empty response if a store node drops or a disk read times out.

This PR adds documentation for `kv_load_failure_policy` and provides an example using `"recompute"` so vLLM recovers by computing missing blocks locally. It also adds a quick note clarifying that `MC_RPC_*` timeout variables are read by Mooncake rather than vLLM.

### Motivation & Scope
I kept this change minimal (+19 lines) and placed it directly under `## KV Transfer Config` where users look for `--kv-transfer-config` options, keeping everything in one place without duplicating notes.
