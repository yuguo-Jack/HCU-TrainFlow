# [Beam] Enable CuTeDSL NVFP4 MegaMoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/62073) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Run Reflection Beam with attention DP + expert parallelism on FlashInfer CuTeDSL MegaMoE (`--moe-backend flashinfer_moe_ep_cutedsl`). **Stacked on #62366** (Beam's fused all-reduce, base branch `woosuk/beam-fused-allreduce`), which builds on the merged #62074. The diff shows only this PR's commit. Like #62366, Beam's kernels here are built ahead of time under `csrc/beam/` instead of JIT-compiled from the model folder.

**Depends on FlashInfer nightly** for `forward_unfinalized`, `do_finalize` and `create_workspace`. These are detected at runtime, and the new paths stay off with older FlashInfer.

## Claims

- **Prefill throughput:** attention DP4 + MegaMoE reaches 1.71× TP4's peak prefill throughput for Beam.
- **EP deferred finalize:** `FusedMoEConfig.defer_moe_finalize(allow_ep=True)` lets a consumer take the top-k finalize under replicated-token EP (TRTLLM-Gen NvFP4 at TP=1, EP>1, reduced by Beam's fused all-reduce) and MegaMoE under DP/EP. This moved here from #62366, which stays TP-only. MegaMoE returns `UnfinalizedMoEOutput` through `forward_unfinalized`.
- **Beam MegaMoE boundary:** Beam finalizes the local rows fused with the post-MoE norms and residual (`csrc/beam/moe_finalize.cu`). With sequence parallelism it restores the replicated tokens through the Lamport workspace (gather kernels in `csrc/beam/allreduce_norm.cu`). Exposed as `torch.ops._C.beam_moe_finalize`, `beam_moe_finalize_norm` and `beam_moe_gather_norm`.
- **Decode workspace:** MegaMoE keeps a second, decode-sized workspace: `max_num_seqs × (1 + num_speculative_tokens)` tokens per sequence-parallel rank. It is used when every DP rank's batch fits, since peer buffer offsets depend on the capacity.
- **Idle ranks:** passthrough-all2all experts now run on ranks with zero tokens instead of returning early, because these experts own the EP collective that every rank must join.

## Validation

**Prefill**, 4×GB300, 32K input / 1 output token, FlashInfer nightly:

| Configuration | Peak input throughput (tok/s) |
|---|---:|
| Attention DP + MegaMoE | 168.8K |
| TP4 | 98.7K |

The prefill numbers were measured before the kernels moved to `csrc/beam/`; the kernel code is unchanged and they were not re-measured.

**Unit tests** on this branch (rebased onto #62366), GB200 (4 GPUs), FlashInfer 0.7.0.post1 (none of the nightly APIs), `_C_stable_libtorch` built for SM100:

```bash

  tests/kernels/moe/test_flashinfer_moe_ep.py \
  "tests/test_config.py::test_dflash_candidate_draft_forces_v2_model_runner"
# 390 passed, 4 skipped
```

- **Same as before the restack:** the previous revision of this branch (JIT kernels) gives the same 390 passed, 4 skipped in this environment. The 8 `test_init_warmup_forward_is_exact_on_grid_inputs` failures reported earlier with FlashInfer 0.7.2 do not occur with 0.7.0.post1.
- **TP8 across two GB200 nodes:** the all-reduce numerics worker passes at hidden 5120 and 8192.
- **Skipped:** the DP-boundary MegaMoE test, which checks bit-exact output for unequal and empty batches with CUDA graph replay, needs FlashInfer nightly. The MegaMoE runtime paths still need CI or a nightly-FlashInfer machine.

## Details

- **Kernels in `csrc/beam/`:** `moe_finalize.cu` is compiled with one 16-byte pack per thread, the only variant the JIT path built; it shares the SM90/SM100 gate and `--fmad=false` with the all-reduce. The MegaMoE boundary is enabled only when these ops are built.
- **Effect on existing MegaMoE users (e.g. DeepSeek-V4 with `flashinfer_moe_ep_cutedsl`):**
  - With FlashInfer nightly, they also get the decode workspace. This adds one more workspace allocation and its warmup.
  - Idle ranks now run the experts and join the collective.
  - Deferral stays off unless a model asks for it.
- **Rebase onto the released Beam schema:** Beam now hardcodes its post-feedforward norm and depth-scaled residuals, so the MegaMoE boundary always receives a post-norm weight and scales. `beam_norm_residual_norm` regains an optional post-norm only for the fused finalize, which applies the post-norm itself.
- **Not a duplicate:** no open PR adds EP deferral or MegaMoE workspace selection.
