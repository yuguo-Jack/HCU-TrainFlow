Without an out-of-place copy, this causes an all-zero-accuracy issue under torch.compile — see https://github.com/vllm-project/vllm/pull/39844.

If we really want to use inplace allreduce, we may need to rely on an environment variable or some other mechanism to determine whether inplace is actually safe to use here. torch.compiler.is_compiling() doesn't work when use custom op all_reduce.
