# [Bugfix] Hide stop text on batch derender

[Upstream PR](https://github.com/vllm-project/vllm/pull/59510) · state: open · merged: False

## Original PR description

## Overview

Batch `/derender` was decoding the stop token the engine had already left out of the text, so `stop` and `stop_token_ids` leaked and `stop_reason` stayed null. Fixes the batch half of #57052. Streaming `/derender` now returns 400 when the request carries stop strings, which is the direction on #47161.

## Claims

- A batch chat or completions derender drops the last token only when `finish_reason` is `stop` and that id is in the client's `stop_token_ids`, equals `tokenizer.eos_token_id`, or is in the model's `generation_config` `eos_token_id` list. `finish_reason=stop` alone does not drop a token. `include_stop_str_in_output` keeps it.
- The token check runs first. The stop-string check then runs on the text that remains, using the same `check_stop_strings` as the engine. A matched stop string wins. The space before the stop word stays.
- `stop_reason` is the matched string, or the token id. It stays empty for the primary EOS.
- Token ids on the generate response are not rewritten.
- Streaming `/derender` returns 400 if the chat or completion request carries stop strings.

## Validation

`pytest tests/entrypoints/scale_out/derender/test_derender_stop.py` — 12 passed. The tests use a tiny in-memory tokenizer and do not need a GPU. They cover a stop string, keeping that string when asked, an ordinary last token left in place, a client `stop_token_ids` drop, a primary EOS drop with an empty `stop_reason`, a `generation_config` EOS drop, keeping the stop token when asked, the token check before the string scan, a `length` finish, and the completions stop string.

The live server tests in `test_derender.py` were not run. This machine cannot start `vllm serve`.

```bash
pytest tests/entrypoints/scale_out/derender/test_derender_stop.py
```

## Details

The engine truncates `output_text` and then appends the stop token id back onto `token_ids`. ServingTokens ships those ids. Derender decoded the full list, so the stop word came back and `include_stop_str_in_output` did nothing.

Derender does not assume every `finish_reason=stop` input ends in a stop id. Round-trip fixtures encode real text and do not append one. Dropping that token broke `encode(derender(ids)) == ids`.

The batch pass recomputes the cut on the derender side because `GenerateResponseChoice` still has no `stop_reason` (#47313). Once that lands, derender can pass the field through instead of scanning.

The parser path scans text with special-token markers kept. The engine scans with `skip_special_tokens` applied, so a stop string that overlaps a marker can cut differently.

Streaming with no `chat_request` has no stop list to refuse, so that leak stays until `output_mode` (#56851).

Streaming is a 400, not a hold-back buffer. The engine-side fix is `output_mode` (#56851).

Logprobs are not trimmed to the shortened text.

- shimib · comment · 2026-10-07T16:44:19Z · [source](https://github.com/vllm-project/vllm/pull/59510#issuecomment-6042497492)

@pOpO1-9 cc @hickeyma

Once #60251 lands, generate reports the engine's `stop_reason` directly, so derender can use it instead of re-deriving the match. Suggested rule, which also sidesteps the fact that `None` from a new generate host and a missing field from an old one look identical after parsing:

1. If `choice.stop_reason is not None`, use it as-is and only apply the text/token trimming for that specific match.
2. If it is `None` and `finish_reason == "stop"`, run the local scan (stop token ids first, then stop strings, as this PR already does) and set `stop_reason` only when the scan actually matches.
3. Otherwise leave it `None` and don't trim.

Step 2 is a no-op exactly in the cases where a new host would have sent `None` anyway (EOS, `length`, abort), because there is nothing for the scan to match. So old and new hosts converge on the same answer, and derender never invents a `stop_reason` the engine didn't have. Whichever of the two PRs lands second rebases the five choice sites.
