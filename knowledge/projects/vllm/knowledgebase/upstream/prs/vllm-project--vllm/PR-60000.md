# [KV Offload] Add admission policy framework and backpressure adapter

[Upstream PR](https://github.com/vllm-project/vllm/pull/60000) · state: open · merged: False

## Original PR description

## Summary

This PR implements the `TieringAdmissionPolicy` framework described in [RFC #53485](https://github.com/vllm-project/vllm/issues/53485), building on the admission-policy skeleton in [#51576](https://github.com/vllm-project/vllm/pull/51576).

It places the existing per-tier backpressure detectors from [#50045](https://github.com/vllm-project/vllm/pull/50045) behind one admission gate for cascade stores and promotions. The production configuration preserves the existing backpressure decisions while making admission a policy-level extension point.

## Functionality

- Add `TieringAdmissionPolicy`, `AlwaysAdmitPolicy`, `BackpressureAdmissionPolicy`, and `AdmissionPolicyFactory`.
- Evaluate cascade admission before primary-tier pinning and job-ID allocation.
- Evaluate promotion admission before primary allocation.
- Route admitted-job completion and cache-reset lifecycle events through the policy.
- Reuse the existing backpressure detectors, drop accounting, labels, metrics, and transition logging.
- Move backpressure metric definitions and collection into the policy.
- Update P2P and KVCR callers to handle rejected store jobs.
- Add policy and manager-wiring tests.

The policy receives plain admission inputs (`keys`, `tier_idx`, and `is_promotion`). Promotion admission hooks run once for the real batched job, while `JobMetadata` remains defined by the manager and is referenced by policies through `TYPE_CHECKING`.
