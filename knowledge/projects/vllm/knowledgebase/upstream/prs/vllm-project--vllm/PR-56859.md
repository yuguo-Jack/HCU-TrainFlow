# [watermarking] Add SBW (Stateless Bernoulli Watermarking) algorithm

[Upstream PR](https://github.com/vllm-project/vllm/pull/56859) · state: open · merged: False

## Original PR description

## Purpose

Adds SBW (Stateless Bernoulli Watermarking) as a second watermarking algorithm
alongside the existing Gumbel-max scheme introduced in #54053 and extended in #56122.

Reference: Ceppi & Sanchez, "Flip, Don't Shuffle: Watermarking LLMs at the
Speed of Inference", EMNLP 2026. https://arxiv.org/abs/2609.03844

SBW is a KGW-family (Kirchenbauer et al.) logit-bias watermark. Like KGW, it
derives a pseudorandom green list from the token context and adds a bias `+delta`
to green token logits before sampling. Unlike KGW, green-list membership is
determined per token independently via a single counter-based PRF call
(Philox 4x32-10), with no vocabulary partitioning or hash list. This makes
the scheme stateless and O(1) per (token, context) pair. The detector
re-derives the same green lists from context and runs a z-score test over the
fraction of green tokens in the output.

The Philox 4x32-10 PRF is implemented from scratch over int32 to match the
paper's integer-domain greenness test exactly (`CBRNG(v, seed_t) < gamma *
INT31_MAX`). The same implementation is used in both the sampler and the detector,
ensuring bit-identical results across devices and releases. Detection requires
only the output token IDs and the watermark parameters; no model weights are needed.

Two seeding schemes are supported via `sbw_scheme`:
- `selfhash` (default): anchored minhash PRF, seed depends on context and the
  candidate token. More robust to substitution attacks. Default `context_width=4`.
- `lefthash`: additive PRF, one seed per context row. Faster. Default `context_width=1`.

Key parameters: `sbw_gamma` (green-list fraction, default 0.5), `sbw_delta`
(logit bias for green tokens, default 2.0).

SBW is compatible with greedy decoding and has native speculative-decoding support.

This PR also adds a `supports_greedy` property to the `Watermarker` ABC. SBW
biases logits rather than adding noise, so greedy requests (`temperature=0`)
can be watermarked normally. `GPUWatermarkSampler` branches on this property;
Gumbel and dual-key Gumbel keep `False` (behavior unchanged).

Note on implementation architecture: `GPUWatermarkSampler` currently passes
pre-top-k/top-p logits to `watermarker.sample()`, which fits noise-based
watermarkers like Gumbel naturally. SBW requires the bias to be applied on raw
logits (before temperature scaling and top-k/top-p filtering) to match the
paper's semantics and the standalone [vllm-sbw](https://github.com/si-mon-jinn/sbw)
reference implementation. This PR handles this via a `sample()` override in
`GPUWatermarkSampler` that intercepts raw logits for bias-based watermarkers
(`supports_greedy=True`). A cleaner long-term architecture would have the
`Watermarker` ABC own the full pipeline from raw logits to token ids, making
`GPUWatermarkSampler` fully watermarker-agnostic. Happy to implement this
generalization here or as a follow-up, based on reviewer preference.

(Qwen3 recommended defaults), 3x512 prompts, 30 input / 200 output tokens.

### Detection quality and text quality (100 C4 samples)

Perplexity scored by Qwen3.5-27B-FP8. Diversity is the n-gram diversity score
(higher = less repetitive). Detection at p_value_threshold=0.01 with context
deduplication enabled.

| Algorithm      | TPR  | FPR  | z_wm | PPL wm (median) | PPL unwm (median) | Diversity wm | Diversity unwm |
|----------------|------|------|------|-----------------|-------------------|--------------|----------------|
| SBW            | 0.96 | 0.04 | 5.09 | 4.06            | 3.48              | 0.482        | 0.525          |

SBW achieves the highest TPR (0.96) and z-score (5.09) at a modest perplexity

(introduced in #56122) recovers the diversity loss and is perplexity-neutral
with zero FPR, at the cost of not supporting greedy decoding.

- si-mon-jinn · comment · 2026-10-12T12:10:42Z · [source](https://github.com/vllm-project/vllm/pull/56859#issuecomment-6123999795)

Hi @TQCB, thanks for taking a look!
  
Yes, SBW is distortionary. It adds a +delta bias to green token logits, shifting the sampling distribution toward green tokens. This is the same approach as the original KGW watermark (Kirchenbauer et al.).
  
Distortion-free watermarking (like Gumbel) fundamentally cannot support greedy decoding or beam search. If the token distribution is unchanged, then argmax and beam rankings are unchanged, leaving no detectable signal. The watermark signal in distortion-free schemes comes from how you sample, not what you sample from. Thus, deterministic decoding strategies have nowhere to embed it.
  
I think the two approaches are complementary with the following tradeoffs: Gumbel is distortion-free and better preserves output quality, but is limited to temperature>0 sampling. SBW has some perplexity cost (tunable via `sbw_delta`), but supports greedy, beam search, and opens the watermarker interface to a different family of watermark schemes.
  
For quality-sensitive use cases, likely Gumbel remains the better choice (depending on context and on watermark signal strength and robustness requirements). SBW fills the gap for greedy/beam decoding, when KGW-family properties are preferred or for compatibility with existing KGW-family based detection infrastructure.

Hi @TQCB,
  
Thanks for raising this. Should I tag a maintainer directly, or is this thread visible enough? In case, who should I tag?
  
In the meantime, I think it's worth highlighting that the problem with Gumbel-like schemes is not only at temperature 0 itself. The lower the temperature, the less entropy there is in the sampling distribution, and thus less space for the watermark signal to occupy. When the distribution is sharply peaked, there's little room to steer the sampling and at the limit (T=0), the argmax is deterministic and there's nowhere to embed a signal at all.
  
I ran some comparative experiments that illustrate this. Here's TPR (p<0.01) vs temperature for both algorithms:
  
<img width="1200" height="750" alt="tpr_vs_temperature" src="https://github.com/user-attachments/assets/523feee6-68c6-4733-b33b-29d9a36ed708" />
  
You can notice that:
  - SBW maintains ~87-96% TPR across all temperatures, including T=0
  - Gumbel drops sharply at low temperatures: ~2% at T=0.1, ~20% at T=0.3, ~80% at T=0.6
  - The two algorithms only reach parity at T≥1.0
  
Beyond the T=0 edge case, this suggests SBW provides more consistent detection across a wider temperature range, which matters in practice since most production workloads run at T<1.0.
  
More broadly, I think vLLM benefits from supporting multiple watermark families, similar to how it supports multiple models and inference backends. Different watermarks have different properties (robustness, quality impact, detection ecosystem compatibility), and operators should be able to choose based on their requirements rather than being locked to a single approach.
  
Let me know if there's something I should do from my side to get maintainer attention on this.
