ROCm image builds can finish out of order. The base and `ci_base` jobs currently write the mutable `:base` and `:ci_base` tags themselves, so an older post-merge build can overwrite a newer result. Base refresh is also based on a Git diff, which can rebuild an image that is already available in Docker Hub. This changes selection to use the actual image inputs. The base key includes the Dockerfile, effective build arguments, metadata version, and resolved parent digest. `ci_base` is keyed the same way and includes the selected base digest. An exact registry hit skips the build, a confirmed miss rebuilds, and registry or metadata errors are retried and then fail instead of being treated as misses.

PR images and caches remain isolated from trusted main. PRs may read a validated main image and reuse their own images, while main never consumes PR-scoped output. The selected base and `ci_base` are passed between jobs by digest. The long builds stop writing stable tags. The base build publishes an input-addressed tag, and `ci_base` publishes content-, commit-, and build-scoped tags. AMD jobs use `ci_base-build-$BUILDKITE_BUILD_ID`, so overlapping evaluations do not share a mutable handoff.

A serialized promotion job becomes the only writer of `:base` and `:ci_base` in this flow. Before updating either tag it requires a successful commit-image smoke test, fetches main again, verifies that the build is still the latest main commit, rechecks the parent digest, and validates both candidates and their relationship. It no-ops when the stable tags are already current and restores previous values after an ordinary partial failure.

Artifact-only mode is still optional. It is used only outside trusted main when `ROCM_CI_ARTIFACT_ONLY=1` and both build-required values are explicitly `0`. Missing metadata falls back to a full image. Main always builds and smoke-tests the commit image. Promotion is smoke-gated; it does not wait for the complete AMD test suite.
