# [Perf][Model] Qwen4Exp QSA DCP: follow-ups to #59279 (combine, workspace buffers, MTP decode path)

## Overview

Follow-up to #59279, as discussed with @sungsooha. It cuts per-step DCP cost of Qwen4Exp QSA decode context parallelism, mainly on the sm_80 (A100) path: fewer kernels and copies in each DCP attention step, no indexer prefill path for MTP verify rows, and MTP with an interleave above 1.

**Depends on #59279.** This branch is #59279 (head 6f650772a) plus 10 commits; as @sungsooha asked, the follow-up work and its benchmarks are here, next to the code. Until #59279 merges, the diff below also shows its commits; review only the commits after 6f650772a. Our earlier commit that dropped the empty-owner LSE neutralize is gone: @sungsooha made the same change in #59279 (6f650772a).

## Claims

- MTP verify rows stay on the QSA decode path under DCP. Before, every DCP + MTP verify step ran the indexer prefill path, also inside FULL CUDA graphs.
- The DCP combine runs without layout copies and fuses the output gate; the DCP buffers come from the workspace, reserved before CUDA graph capture.
- Each new selection is localized once and reused by MTP `skip_topk` steps.
- The reader stores the LSE directly when it runs one split (no merge kernel). Bitwise equal.
- The replicated selector declares `supports_mtp_with_cp_non_trivial_interleave_size`, so MTP works with `--cp-kv-cache-interleave-size` > 1.
- No change without DCP. The default selector stays replicated.

## Validation

## Details

| Commit | What and why |
|---|---|
| keep MTP verify rows as decodes | `supports_dcp_with_varlen=True` for the GDN builder and the QSA side-cache builder. The QSA side caches, the GDN state and the replicated selector are not DCP-sharded, so the reorder threshold stays 1 + num_spec. MRV2: QSA side cache only (GDN routes by draft count). Not bitwise: verify rows move from `qsa_select_paged_prefill` to `qsa_select_paged_decode`. |
| copy-free LSE combine, fused gate | `qsa_dcp_lse_ag_out_rs`: all-gather of the LSE, head-major LSE correction into a reserved buffer, dim-0 reduce-scatter; no `movedim`/`contiguous` copies. One Triton gate kernel (`expf` + IEEE division, the fp32 PyTorch sigmoid formula). Other combines (`dcp_a2a_lse_reduce`) are called unchanged, with `ctx` and `is_lse_base_on_e`. |
| reserve DCP buffers in the workspace | Partial output, LSE and the combine buffer come from `current_workspace_manager().get_simultaneous`, sized for `max_num_batched_tokens`, so the workspace does not grow after capture. |
| localize each selection once | The indexer writes the rank-local selection into `topk_buffer`; MTP `skip_topk` steps reuse it, and the attention no longer localizes. |
| store the LSE directly for one split | With `return_lse` and one split, the reader writes output and LSE without the merge kernel. Bitwise. |
| tests: indexer wiring, combine, DCP 4 interleave 1 | |
| allow MTP with a non-trivial interleave | The replicated QSA impl declares `supports_mtp_with_cp_non_trivial_interleave_size`; a GPU test checks MTP verify rows against the single-rank result at interleaves 1, 4, 16 and 8. |
| run the FP8 cases on Ampere | Below sm_89 the reader takes e4m3 as uint8 bytes; the tests use that storage instead of skipping. |
| keep the FP32 DCP partial of the base | Rebase adaptation to the FP32 partial of #59279. |
| import the QSA module after the model module | Test-only: qsa.py and model.py import each other, so the tests import the model first. |

**Size:** +378 / −93 outside tests (6 files); tests +702 / −1. Most of it is two Triton kernels (combine correction, gate) and their warmup.

**Limits.** The serving A/B is one run per arm and on an earlier base. The sharded selector (opt-in) is not in this PR; it follows as a separate PR on top of this one.
