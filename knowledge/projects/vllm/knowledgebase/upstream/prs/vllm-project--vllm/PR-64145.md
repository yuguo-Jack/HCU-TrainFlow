# [Core] Configurable async scheduling depth for Model Runner V2

[Upstream PR](https://github.com/vllm-project/vllm/pull/64145) · state: open · merged: False

## Original PR description



## Overview

Add `--async-scheduling-depth` (`SchedulerConfig.async_scheduling_depth`, default 2): how many steps Model Runner V2 keeps in flight with async scheduling. The default keeps today's count (`pp_size + 1`).

## Claims

- New option, default unchanged. With depth N the scheduler runs up to N − 1 steps ahead of the step on the GPU (plus one per extra pipeline stage, as before).
- It helps when the host round trip per step (output processing, scheduling, the broadcast to the workers, input preparation) is longer than a GPU step: low-batch decode with speculative decoding, across nodes.
- On DeepSeek-V4.1-Flash, TP8 over two GB300 trays with DSpark (7 draft tokens), one request: **885 tok/s at depth 2, 1,212 at 3, 1,263 at 4, 1,359 at 6** (plateau). That is with #61869 and the TP8 specialized decode (#64146).

## Validation

- `tests/test_config.py`: new tests for `max_concurrent_batches` (PP 1 at depths 2 and 6, PP 2 at depths 2 and 4) and for rejecting depth < 2. They pass on GB300, along with the existing async-scheduling tests.
- End to end on vLLM main (nightly `5d35ce39`), TP8 as above but without #61869: 899 → 942 tok/s (depth 2 → 6, 8 runs each). The gain is smaller here because main runs the DSpark draft on the stock path, so the GPU step is longer than the host round trip.
- The UVA staging pools, the engine core's batch queue and the aux-output store already size themselves from `max_concurrent_batches`, so nothing else changes.

## Details

- Only `VllmConfig.max_concurrent_batches` reads the new field.
- Model Runner V1 ignores it: async scheduling there stays at 2 concurrent batches.
- A deeper queue holds more steps' inputs and outputs in flight. The cost is a little pinned host memory.
- The scheduler already handles several steps in flight (PP > 1, and async scheduling at depth 2). Depth only raises the count. Our DeepSeek-V4.1 deployment runs depth 6 with DSpark and up to 8 sequences.
- Not run: `VLLM_GPU_SYNC_CHECK=error` (no new code on the step path).
