# [DeepSeek-V4-P1] Reuse persistent SiLU FP8 quantization for batch invariance

[Upstream PR](https://github.com/vllm-project/vllm/pull/59863) · state: open · merged: False

## Original PR description

## Overview

Add DeepSeek-V4's fused, token-local SiLU x Mul FP8 quantizer to vLLM's existing stable `_C` extension. Its CUDA source lives under `csrc/quantization/fused_kernels/`, rather than a new extension or a model-specific source directory. Contiguous and masked expert inputs share this fused operator; this PR does not enable a model path by itself.

- Preserve token-local clamp, BF16 rounding, and FP8 conversion for FP32, rounded FP32, and packed UE8M0 scales. Hopper and Blackwell retain their respective arithmetic behavior.
- Support 64-bit group/output offsets, including tensors above `2**31` elements. The existing persistent masked quantizer also gains BI-compatible clamp and arithmetic options; its default behavior remains compatible.
- Default non-BI execution is unchanged.

## Test

- H20 on the current PR head: `tests/kernels/moe/test_silu_mul_fp8_quant_deep_gemm.py` **29 passed**; `tests/kernels/moe/test_silu_mul_per_token_group_quant_fp8_colmajor.py` **117 passed**.
- H20: the large-shape regression from the reference implementation passed **2/2** for `numel > 2**31`, with bitwise parity against chunked quantization. This diagnostic was run outside the PR diff.
- Reference fused kernel comparison: **42/42** H100 cases had byte-identical FP8 values and scales across masked/contiguous layouts, scale formats, clamp modes, and BF16-pattern inputs.
- SM100 behavior was not measured on B200.

### Acc

In a two-step H100 DP4/EP4 integration with the other DeepSeek-V4 changes and weight reload, `training/rollout_probs_diff_max` and `rollout_corr/log_ppl_abs_diff` were **0 at both steps** (3031 tokens per DP worker, `max_num_batched_tokens=1024`, `gpu_memory_utilization=0.55`). This is a combined-path result, not an isolated model evaluation of P1.
