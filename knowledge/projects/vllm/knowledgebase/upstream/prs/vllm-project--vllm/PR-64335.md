# [Bugfix][RL] Destroy the previous NCCL communicator when the weight-transfer engine is re-initialized

[Upstream PR](https://github.com/vllm-project/vllm/pull/64335) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

If a trainer reconnects to a running server without calling `/shutdown_weight_transfer_engine` first (for example after it crashed), `init_transfer_engine` in the NCCL and sparse NCCL engines overwrites `model_update_group` with a new communicator and never destroys the old one. `PyNcclCommunicator` has no finalizer, so the old communicator and its GPU memory stay alive on every worker, one more per reconnect. This PR makes both engines call their own `shutdown()` first.

We hit this in [Halo](https://github.com/whitecircle/halo), where trainers reconnect to long-running vLLM servers, and we patch it in our vLLM image for now.

Not a duplicate: #40646 tried the same fix and was closed by its author before review, and #61060 added the explicit shutdown but left re-init as it was. I found no open PR for this.

## Claims

- Re-initializing the NCCL or sparse NCCL engine destroys the previous communicator first.
- Server GPU memory stays flat across reconnects. With Qwen3-0.6B, main grows by about 630 MiB per reconnect.

```python
"""Server GPU memory across trainer reconnects that skip shutdown_weight_transfer_engine.

`vllm serve Qwen/Qwen3-0.6B` with the NCCL weight-transfer backend runs on SERVER_GPU;
this process is the trainer on TRAINER_GPU. Each cycle opens a new transfer connection
(trainer_init), sends the weights once, and closes only the trainer side, as a trainer
that restarts without calling /shutdown_weight_transfer_engine does.

Run from a vLLM checkout with two free GPUs:
    python reinit_leak_repro.py [cycles]
"""

import os
import signal
import subprocess
import sys
import time

import requests
import torch
from transformers import AutoModelForCausalLM

from vllm.distributed.weight_transfer import (
    HTTPVLLMWeightSyncClient,
    ModuleSource,
    WeightTransferTrainerFactory,
)
from vllm.distributed.weight_transfer.nccl_engine import NCCLTrainerInitInfo
from vllm.utils.network_utils import get_ip, get_open_port

MODEL = "Qwen/Qwen3-0.6B"
SERVER_GPU = os.environ.get("SERVER_GPU", "0")
TRAINER_GPU = int(os.environ.get("TRAINER_GPU", "1"))
PORT = 8000
URL = f"http://localhost:{PORT}"


def server_gpu_used_mib() -> int:
    out = subprocess.check_output(
        [
            "nvidia-smi",
            "--query-gpu=memory.used",
            "--format=csv,noheader,nounits",
            "-i",
            SERVER_GPU,
        ]
    )
    return int(out)


def start_server() -> subprocess.Popen:
    env = dict(os.environ, VLLM_SERVER_DEV_MODE="1", CUDA_VISIBLE_DEVICES=SERVER_GPU)
    proc = subprocess.Popen(
        [
            "vllm",
            "serve",
            MODEL,
            "--port",
            str(PORT),
            "--enforce-eager",
            "--gpu-memory-utilization",
            "0.5",
            "--weight-transfer-config",
            '{"backend": "nccl"}',
        ],
        env=env,
        start_new_session=True,
    )
    deadline = time.monotonic() + 900
    while time.monotonic() < deadline:
        if proc.poll() is not None:
            raise RuntimeError("server exited")
        try:
            if requests.get(f"{URL}/health", timeout=5).status_code == 200:
                return proc
        except requests.RequestException:
            pass
        time.sleep(2)
    raise RuntimeError("server did not start")


def main() -> None:
    cycles = int(sys.argv[1]) if len(sys.argv) > 1 else 8
    server = start_server()
    try:
        torch.accelerator.set_device_index(TRAINER_GPU)
        model = AutoModelForCausalLM.from_pretrained(MODEL, dtype=torch.bfloat16)
        model.to(f"cuda:{TRAINER_GPU}")
        world_size = (
            requests.get(f"{URL}/get_world_size", timeout=10).json()["world_size"] + 1
        )
        baseline = server_gpu_used_mib()
        for cycle in range(1, cycles + 1):
            engine = WeightTransferTrainerFactory.trainer_init(
                init_info=NCCLTrainerInitInfo(
                    master_address=get_ip(),
                    master_port=get_open_port(),
                    world_size=world_size,
                    rank=0,
                    packed=True,
                ),
                client=HTTPVLLMWeightSyncClient(URL),
                source=ModuleSource(model),
            )
            engine.send_weights()
            engine.shutdown()
            print(f"cycle {cycle}: server GPU {server_gpu_used_mib() - baseline:+d} MiB")
    finally:
        os.killpg(server.pid, signal.SIGTERM)
        server.wait()


if __name__ == "__main__":
    main()
```

## Details

M2N refuses a second init instead. For NCCL I tear the old group down, because the trainer that should have called shutdown may be gone, and a restarted trainer can't know an old connection is still open. Happy to switch to refusing if you prefer.

The tests cover the NCCL engine. The sparse engine gets the same one-line change without a test of its own. `docs/training/weight_transfer/nccl.md` now mentions the re-init behavior.
