# [Core] Admit beam-search groups as one scheduling unit

[Upstream PR](https://github.com/vllm-project/vllm/pull/63241) · state: open · merged: False

## Original PR description

## Overview

Draft first slice of #61880. `LLM.beam_search()` is unchanged. A beam group is a set of sibling requests the scheduler admits and decodes all-or-nothing, instead of letting the waiting scan schedule them one by one.

## Claims

- `Scheduler.add_beam_group` registers the slots outside the normal waiting queue.
- A group is scheduled only when every slot fits in the active-sequence limit, the token budget, and the KV pool. A partial free-slot hole is left open for the head group.
- Running groups are decoded together. Beam slots are not preemption victims.
- Aborting one slot aborts the group.
- Speculative decoding, pipeline parallelism, structured outputs, and multimodal encoder inputs are rejected so callers can keep the existing wrapper.

## Validation

CPU scheduler tests in `tests/v1/core/test_beam_group_scheduler.py` (10 passed):

- equal chunk size for a 4-slot group
- admission and the following decode step schedule every slot
- a token budget smaller than the prompts chunks every slot by the same amount
- a group that needs more free sequence slots than are open is not partially admitted, and does not give that hole to another waiting request
- a KV allocation miss schedules nobody in the group
- aborting one slot finishes the group

## Details

This is the scheduling primitive from the RFC (step 1). It does not implement KV fork/copy-on-write, GPU top-k selection, or wiring `LLM.beam_search()` to the engine. Those stay on the entrypoint loop until later slices.
