# [Frontend][Parser] Stream long DSML parameter values for DeepSeek tool calls

[Upstream PR](https://github.com/vllm-project/vllm/pull/64196) · state: open · merged: False

## Original PR description

## Overview

DeepSeek models emit tool-call arguments as DSML parameters. With `arg_structural_chars = frozenset(">")`, `ParserEngine._compute_arg_delta()` drops every delta that contains no tag boundary, and `_dsml_arg_converter` only re-serialises the whole parameter list. A long `string="true"` value contains no `'>'` at all, so it is buffered until its closing tag arrives: the client receives **zero bytes for the entire generation**. A 15k-character `Write` payload keeps the stream silent for 130–220 s, far past any client read timeout, while the engine keeps decoding normally.

This PR wires an `arg_value_extender` into the DeepSeek V3.2 / V4 / V4.1 configs so the open parameter value streams while it is generated.

## Claims

- Long DSML parameter values stream incrementally instead of being flushed once, when the closing tag lands.
- Nothing changes for values the engine does not consider streamable (`string="false"` numbers/objects, keys whose schema type is not `string`) — they still go through the full converter.
- The final arguments are unchanged: the streamed text stays prefix-safe and equals what the full conversion produces.

## Validation

- Added `tests/parser/engine/test_deepseek_long_arg_streaming.py`, parametrised over `deepseek_v4` / `deepseek_v41` / `deepseek_v32`. It asserts the value arrives in many fragments, that no fragment carries most of it, and that a value containing `<` / a partial closing-tag prefix is not corrupted.
- Offline replay of main's `_compute_arg_delta` (real `_dsml_arg_converter` + `_safe_arg_prefix` + the new extender) over a 3 KB value: **4** argument deltas with a **2168-char** silent gap before, **273** deltas with a max **88-char** gap after; prefix-safe and parse-equal for all three dialects.
- ⚠️ Not run locally: the authoring machine has no vLLM runtime, so the new tests still need to run in CI. Please treat the PR as pending CI validation.

## Details

- **Root cause.** `_compute_arg_delta()` returns `None` when `arg_structural_chars.isdisjoint(raw_delta)`. DSML only guarantees a `'>'` at tag ends, so every delta of a value body is suppressed. `_safe_arg_prefix()` is already able to stream an unterminated trailing string, but it is only reached when a delta survives that gate.
- **Fix.** `make_param_value_extender(param_start, param_close, extra_stop_tags)` returns an extender that re-serialises only the value tail, using the same `json.dumps` escaping as `_dsml_arg_converter` (`json.dumps(visible)[1:-1]`). A trailing partial tag is held back via the existing `partial_tag_overlap` helper; when the closing tag (or another tag) appears, the extender returns `None` and the engine clears it and falls back to the full converter.
- **Dialects.** V4.1 uses spaced DSML (`<｜DSML｜ parameter`), so it rebuilds the extender from its own constants instead of inheriting V4's; V3.2 reuses the V4 parameter format with a different outer wrapper.
- **Limitation.** The extender only streams what `open_value_streams` permits, i.e. the trailing value the schema types as a string. Object/array arguments keep the current behaviour, and a value whose key is not declared as a string in the tool schema is also unchanged.
