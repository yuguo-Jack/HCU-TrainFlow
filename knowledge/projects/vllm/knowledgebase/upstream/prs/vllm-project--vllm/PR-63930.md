# [Bugfix][Model Loader] Restore loaders on skipped reload layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/63930) · state: open · merged: False

## Original PR description

## Overview

When a layerwise reload skips a bias-bearing layer, the restored bias keeps an inactive temporary loader and silently ignores later writes. Restore its original loader alongside the saved runtime tensors so subsequent updates change the value in place. Related: #58382.

## Claims

- Remove only `online_process_loader` wrappers from restored parameters/buffers, using the existing unwrapping helper.
- Preserve the original layer parameters and their bound loaders; the CPU regression verifies a later update from ones to sevens.

## Validation

Draft: supported-runtime execution of the OPT regression and model evaluation remain pending. No end-to-end serving or GPU result is claimed.

CPU environment: macOS arm64, Python 3.12.3, PyTorch 2.11.0, Transformers 5.5.3. Tests use an isolated venv with installed Torch dependencies. Base: `3d81a510f9ebc802a7864ced38832182295f4cad`.

All applicable pre-commit hooks passed, including Ruff, Markdown lint, test tethering, mypy and SPDX. Both regressions are selected by the existing AMD Model Executor CI job. The real `vllm_runner` OPT-125M test collects successfully but is unrun on this host, which has no compiled vLLM serving runtime or CUDA/ROCm GPU.

## Details

Ordinary weights move to separate meta placeholders during reload, so their saved original parameters keep the original loaders. Bias stays live under `SKIP_TENSORS`, yet receives the same temporary wrapper. Restoring that object and resetting reload state leaves a loader that returns without copying. `_place_kernel_tensors` now removes that wrapper after restoring tensors.

This is a narrow follow-up to #58382's documented layerwise/direct interaction. It is distinct from #61287's pending-load-state/KV-scale fixes and #50523's padding initialization. Open-PR searches and inspection of #61287's layerwise diff found no implementation of this restoration fix. Concurrent reload sessions and broader direct-mode changes are outside this patch.
