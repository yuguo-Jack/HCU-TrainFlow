# [RFC / Prototype] KV-PP (LayerSplit) KV cache planning and placement decoupling (#58329)

[Upstream PR](https://github.com/vllm-project/vllm/pull/58428) · state: open · merged: False

## Original PR description

## Summary
Draft PR / Prototype reference implementation for **RFC #58329: KVPP (KV pipeline parallel, LayerSplit) for vLLM**.

This PR implements **Phase 1: Decoupled Logical KV Cache Planning & Physical Layer Ownership Placement** for core vLLM v1.

 NOTE
> This is submitted as a **Draft PR** to provide a concrete, fully-tested architectural reference for RFC #58329 and gather early maintainer feedback on the decoupled planning data structures before proceeding to Phase 2 (runtime execution & communication).

---

## Motivation & RFC Alignment
- **RFC**: #58329
- In standard vLLM execution, every worker process allocates physical memory for all layers. Under KV pipeline parallelism (KV-PP / LayerSplit), attention layers of the target model are partitioned across pipeline ranks.
- To enable this without breaking engine coordinator and scheduler invariants, logical planning (`num_blocks`, block indices, common logical block footprint) is decoupled from rank-local physical tensor allocation.

---

## Key Design & Changes

### 1. Configuration (`vllm/config/cache.py`)
- Added `kv_pipeline_parallel_size: int = Field(default=1, ge=1)` to `CacheConfig`.
- Added `is_kv_pp_enabled` property.

### 2. Dataclass & Interface (`vllm/v1/kv_cache_interface.py`)
- Added `@dataclass(frozen=True) class KVPPPlacementPlan`:
  - `rank: int`: Current pipeline rank.
  - `kv_pp_size: int`: Total number of pipeline stages.
  - `owned_layer_names: set[str]`: Set of layer names physically allocated by this rank.
  - `rank_layer_distribution: dict[int, list[str]]`: Global mapping of ranks to assigned layers.
  - `scratch_buffer_bytes_per_block: int`: Budgeted memory for double-buffering inter-stage transfers ($2 \times$ max target layer bundle size).
- Extended `KVCacheConfig` with `kv_pp_placement: KVPPPlacementPlan | None` and `is_layer_owned_by_rank(layer_name, rank)`.

### 3. Slicing & Planning Algorithm (`vllm/v1/core/kv_cache_utils.py`)
- Implemented `compute_kv_pp_placement_plan`:
  - Partitions target layers contiguously across ranks with balanced divmod distribution (remainder layers assigned to earlier ranks).
  - Isolates draft model groups (e.g. EAGLE/MTP `is_eagle_group=True`) as strictly rank-local across all ranks.
  - Budgets `scratch_buffer_bytes_per_block = 2 * max_target_layer_bytes`.
- Updated `_get_kv_cache_bytes_per_block` and `get_kv_cache_config_from_groups`:
  - Instantiates physical `KVCacheTensorSpec` only for owned layers + local draft layers.
  - Computes conservative common logical block size for scheduler calculations.

### 4. Comprehensive Unit Tests (`tests/v1/core/test_kv_pp_planning.py`)
- `test_kv_pp_placement_plan_uniform`: Validates even layer partitioning across ranks (32 layers / 4 ranks = 8 layers each).
- `test_kv_pp_placement_plan_remainder_distribution`: Validates odd remainder distribution (30 layers / 4 ranks $\to$ [8, 8, 7, 7]).
- `test_kv_pp_draft_model_isolation`: Validates speculative decoding / EAGLE groups remain rank-local on all ranks.
- `test_kv_pp_block_scaling_and_scratch_buffer`: Validates double-buffer calculation ($2 \times$ max bundle) and ~3.2x block capacity expansion at PP4.
- `test_get_kv_cache_config_with_kv_pp`: End-to-end integration test generating `KVCacheConfig` under KV-PP.
- `test_kv_pp_validation_bounds`: Validates rank out-of-bounds guards.
