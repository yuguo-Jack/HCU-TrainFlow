# [Bugfix][CI] Muse Spark: keep the shared-RoPE test's CPU RoPE out of get_rope's cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/65138) · state: closed · merged: False

## Original PR description

## Overview

Fixes the red `amd-mi355-basic-models-other` shard 2/2 on main since #63440 (main CI at be09292f0 and 5689c2790c; also every PR that merges main, e.g. #64448): 26 tests of `tests/models/test_muse_spark_rocm_mono.py` fail with `cos_sin_cache must be a contiguous 2-D CUDA tensor`.

Root cause: `test_muse_spark_rocm_shared_rope.py` builds `MuseSpark1xAttention` on the CPU, and `get_rope` caches its `RotaryEmbedding` in the process-wide `_ROPE_DICT`, keyed by shape and dtype but not device. The mono test runs next in the same pytest command and builds its tiny model on the GPU with the same RoPE key (head 64, 4096 positions, theta 5e5, GPT-J style, fp32), so it gets the cached CPU table and the fused QK-norm / RoPE / KV-insert op rejects it. #63440's own CI did not run the two files in one process.

The fix gives the shared-RoPE test its own cache dict through `monkeypatch`, as `tests/models/quantization/test_gptq_marlin.py` does with `_ROPE_DICT.clear()`. Test-only change.

## Validation

MI355X, image `vllm/vllm-openai-rocm:nightly-76c6f3f2a95f` (same `csrc` as 5689c2790c) with main 5689c2790c's Python on top; one pytest process runs `models/test_muse_spark_rocm_shared_rope.py models/test_muse_spark_rocm_mono.py`, with a probe that prints the `cos_sin_cache` the fused op receives:

| | `cos_sin_cache` | result |
|---|---|---|
| main, `-k "share_fp32 or 1-0-dspark"` | `cpu`, fp32, (4096, 64) | 1 failed, 1 passed (the CI error) |
| this PR, same selection | `cuda:0`, fp32, (4096, 64) | 2 passed |
| this PR, both files | `cuda:0` | 34 passed |
