# [Spec Decode] Support LFM2 MoE targets for DSpark

[Upstream PR](https://github.com/vllm-project/vllm/pull/64304) · state: open · merged: False

## Original PR description

## Overview

Enable `LiquidAI/LFM2.5-8B-A1B` as a DSpark target with its official `LiquidAI/LFM2.5-8B-A1B-DSpark` drafter, reusing the existing auxiliary-feature interface and Qwen3 DSpark implementation.

Depends on #61352.

## Claims

- Expose the checkpoint-requested auxiliary residual streams from `Lfm2MoeForCausalLM` through `SupportsEagle3`.
- Include speculative history in the MoE target's ShortConv cache planning.
- Add real-model coverage across consecutive request batches, a documented usage example, and CI source dependencies.

## Validation

Validated on one Radeon 8060S (`gfx1151`), PyTorch 2.13.0+ROCm10, MRV2, TP=1, BF16, eager; async scheduling, adaptive verification, and prefix caching disabled. GPU runs used `VLLM_GPU_SYNC_CHECK=error`.

### Regression tests

| Check | Result |
| --- | --- |
| Prerequisite config and Dense/VL capture/cache suites | 30 passed |
| MoE real-model test, consecutive 1/2/1-request batches | 1 passed; acceptance 30.4% / 29.3% / 46.1% |
| Same MoE test with the dependency-only target implementation | Expected startup failure: `Model does not support EAGLE3 interface` |
| Applicable pre-commit hooks, including mypy and CI test tethering | Passed |

### GSM8K evaluation

First 32 test questions, 5-shot chat, greedy sampling, seed=0, output cap 8192, context 16384, maximum concurrency 4. Both modes use the same chat template and natural EOS without manually configured stop strings.

| Configuration | Correct answers | Accuracy |
| --- | --- | --- | 
| Target only | 30/32 | 93.75% | 
| Target + DSpark, K=9 | 29/32 | 90.625% |

DSpark accepted 39.29% of draft tokens, with mean acceptance length 4.54. Neither run had truncated outputs or unclosed reasoning blocks.

The runs differed on three final answers. Repeating those cases with `max_num_seqs=1` produced identical final answers in both modes (2/3 correct). The full 32-question accuracy difference remains unresolved.

## Details

The dependency recognizes the official drafter, but the MoE target lacks the auxiliary-feature interface requested by MRV2. Reuse `EagleModelMixin` to capture `hidden_states + residual` before normalization at the existing post-layer boundaries. Pass the speculative-token count to the existing ShortConv state-shape calculator; for K=9, the state grows from `(2, 2048)` to `(11, 2048)`.

#61352 provides common Liquid draft configuration and Dense/VL target support; this follow-up adds the MoE target. #44296 mentions a planned MoE/EAGLE follow-up, but its current diff only fixes ShortConv rollback (merged via #50272). Searches found no open PR implementing this MoE DSpark integration.

The new test runs through the existing NVIDIA/AMD DSpark CI jobs. Auxiliary capture across pipeline-parallel ranks remains unsupported.

AI assistance (Codex) was used for review, and local validation.
