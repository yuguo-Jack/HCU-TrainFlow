# [Bugfix][Structured Output][v0.32] Honor resolved backends and mask widths

[Upstream PR](https://github.com/vllm-project/vllm/pull/62295) · state: open · merged: False

## Original PR description



## Overview

Backport the mixed automatic structured-output backend repair from #62246/#62284 to official v0.32.0 (`5df63a7203cdb9328d824a27b682e77c7b9928be`). Related: #55152. The existing PRs target main and v0.31; this targets the separate official release branch, preserving its newer ConstraintBounds APIs. A bounded search found no open structured-output PR on this release branch; no exhaustive duplicate-absence claim.

## Claims

- Compile each request with its validated backend, avoiding guidance `KeyError: triggers` when JSON and named/required structural-tag requests arrive in mixed order.
- Keep backend-native mask widths isolated, normalize active rows to model vocabulary, and clear out-of-model tail bits. Use distinct serial/speculative/bonus/parallel row indices.
- Preserve v0.32 implicit reasoning-end semantics and existing executor shutdown, releasing every cached backend afterward. No default backend is changed.

## Validation

Exact final bytes on real CPU torch2.14.0+cpu, xgrammar0.2.7 and llguidance1.7.6, cached GPT-2 tokenizer, no stubs:

```bash
VLLM_TARGET_DEVICE=cpu HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
PYTHONPATH="$PWD:$NATIVE_SITE" "$CPU_PYTHON" -m pytest \
  tests/v1/structured_output/test_structured_output_manager.py -q -x
```

Whole candidate file: **75 passed,1 existing expected xfail,0 failures/errors/ordinary skips/deselections**,76 collected. Existing xfail: guidance EOS validation on an already-complete object. The pristine release with identical final test bytes, selected with `-k test_auto_backend_selection_ignores_request_order`, fails the first case on actual `KeyError: triggers`, then stops with `-x` (1 failure,64 deselected; the other11 selected cases were not run).

All15 original test definitions remain AST-identical. New cases exercise JSON/named/required ordering, synchronous/asynchronous compilation, mixed serial/parallel buffers, tokenizer/model width differences and tail masking. Existing speculative/reasoning/shutdown cases run in the whole file. Normal upstream file-scoped pre-commit hooks, including the release's mypy3.11 hook, pass without bypass and preserve final bytes.

## Details

The manager used one compiler alias selected by the first request. A later request validated for another backend therefore entered the wrong serializer. Cache backend instances by request validation result; preallocate their native buffers before parallel fills. Reuse the output buffer for equal widths; copy/intersect native rows into model-width output otherwise. Additional CPU buffer memory is bounded by active backend count and configured batch/speculative row limits.

Only the manager and its existing test file change. ConstraintBounds, implicit reasoning ends, validate_tokens and accept_tokens retain the release's behavior. This is a generic engine correction, not a backend override, model/checkpoint change or deployment mechanism.

Limits: CPU grammar/tokenizer tests only; no GPU/weights, model evaluations, e2e generation/serving, image ABI/import, latency or performance measurement. No customer request replay. Actual image build and fresh serving qualification remain separate.
