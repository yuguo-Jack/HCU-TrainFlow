# [ROCm][Qwen4Exp] Add get_top_tokens to the AMD MTP draft

[Upstream PR](https://github.com/vllm-project/vllm/pull/64022) · state: open · merged: False

## Original PR description

## Overview

The AMD Qwen4Exp MTP draft (`vllm/models/qwen4_exp/amd/mtp.py`) didn't implement `get_top_tokens()`, so `speculative_config.use_local_argmax_reduction` (vocab-parallel local argmax for greedy draft tokens, skipping the full-vocab all-gather) could not be enabled for this model — the speculator hard-errors on `get_top_tokens` missing. Every other MTP drafter (`deepseek_v4`, `deepseek_v32`, `inkling`, `glm5next`) already implements it; this brings Qwen4Exp's AMD draft to parity via a one-line delegation to `LogitsProcessor.get_top_tokens`, same pattern as the others.

Not a duplicate: checked open/closed PRs and issues for "get_top_tokens" + Qwen4Exp/MTP; #60387 (generic reduced-vocabulary `get_top_tokens`, speculator-side) touches `speculator.py`/`envs.py` only, not any model file, and is orthogonal to this per-model implementation.

## Claims

- `Qwen4ExpMTP.get_top_tokens` returns the same token `compute_logits().argmax(-1)` would.
- No functional change when `use_local_argmax_reduction` is unset (the default).

## Validation

```bash
.venv/bin/python -m pytest tests/v1/spec_decode/test_qwen4_exp_amd_mtp_local_argmax.py -v
```

New test `test_qwen4_exp_amd_mtp_local_argmax.py`: one assertion, builds a real `Qwen4ExpMTP` + `ParallelLMHead` + `LogitsProcessor` and checks `get_top_tokens` matches `compute_logits`'s argmax -- the one real risk for a 1-line delegation (a wrong head/tensor typo silently returning a different draft token). Padded-vocab and multi-batch-size cases are deliberately left out: those exercise `LogitsProcessor.get_top_tokens` itself, already covered by `tests/v1/sample/test_head_dtype.py`, and there's no batch-size-dependent branching here to catch. ROCm-gated like the implementation; CPU collection is clean (skipped, 0 errors), real execution needs ROCm hardware -- not run here. `ruff check`/`ruff format --check` pass.

No separate end-to-end run: this unlocks a flag with no other caller yet in-tree, so there's nothing to serve-and-measure beyond the unit test above.

## Details

**Root cause.** `vllm/v1/worker/gpu/spec_decode/speculator.py::_validate_local_argmax_reduction` raises if `use_local_argmax_reduction=True` and the draft model lacks `get_top_tokens`. The AMD Qwen4Exp draft never implemented it.

**Fix.** Add `get_top_tokens`, delegating to `self.logits_processor.get_top_tokens(self.lm_head, hidden_states)` — identical head/tensor pair `compute_logits` already uses, matching how `deepseek_v4`/`glm5next`/`inkling` implement the same method.

**Scope.** AMD Qwen4Exp backend only; no change for the NVIDIA backend or any other model.
