# [Feature][PCP] Support DeepSeek V4 with FlashMLA on NVIDIA

[Upstream PR](https://github.com/vllm-project/vllm/pull/65305) · state: open · merged: False

## Original PR description

## Overview

Enable DeepSeek V4 prefill context parallelism (PCP) on NVIDIA GPUs with Model Runner V2, FlashMLA sparse attention, and replicated SWA/compressed KV caches. Supports eager execution, `PIECEWISE`, `FULL_DECODE_ONLY`, and `FULL_AND_PIECEWISE` CUDA graph modes alongside tensor and expert parallelism.

Base commit: `5689c2790c911a55c75825aac5166305df0b591d` (#60946). Related #43809 implements partitioned KV attention with global output/LSE merging; this PR uses local queries, replicated KV, and standard MoE dispatch/combine.

## Claims

- Support DeepSeek V4 prefill context parallelism (PCP) with FlashMLA sparse attention and replicated SWA/compressed KV caches.
- Gather KV and compressor inputs prior to cache insertion and C4/C128 pooling across PCP rank boundaries.
- Unify token-dependent routing input gathering (`input_ids`) with MoE activations and logits in `MoERunner._maybe_dispatch`.
- Enable CUDA graph modes (`PIECEWISE`, `FULL_DECODE_ONLY`, `FULL_AND_PIECEWISE`) for DSv4 PCP via persistent metadata buffers and zero-compressed-chunk prefill handling.

## Validation (commit d5681888d)

- **GSM8K Accuracy**: Evaluated on full `DeepSeek-V4-Flash-0731` checkpoint across all 1,319 GSM8K test questions (5-shot, greedy, max 256 tokens):
  - **Baseline** (TP4 EP4, `FULL_DECODE_ONLY`): 1235 / 1319 (**93.63%**)
  - **Candidate** (PCP4 TP1 EP4, `FULL_AND_PIECEWISE`): 1240 / 1319 (**94.01%**)

The current follow-up commit shares PCP SWA metadata, compressed-slot mapping, and KV insertion helpers between DeepSeek V4 and V4.1. Model-specific compression algorithms, quantization arguments, and existing graph restrictions remain unchanged. The measurements above predate this refactor; follow-up validation records are retained locally.

## Details

- **KV Replication and Compressor Gathering**: PCP ranks compute queries for local token shards while maintaining replicated SWA and compressed KV caches. Token activations are gathered before C4/C128 compressor pooling to allow pooling windows to span across PCP shard boundaries. SWA auxiliary streams are disabled under PCP to preserve collective communication ordering.
- **CUDA Graph Replay Safety**: Metadata builders in `compressor.py`, `flashmla.py`, `sparse_mla.py`, and `indexer.py` pre-allocate persistent buffers updated in place via `.copy_()` to preserve static tensor addresses across graph replays. Empty prefill chunks in short sequences are safely skipped to avoid empty reduction errors during graph capture.
- **MoE Routing**: In `MoERunner._maybe_dispatch`, `input_ids` are gathered together with `hidden_states` and router logits across PCP ranks when expert parallelism is disabled, ensuring consistent row mapping for token-dependent routing.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Avoid multiplying full-context compressor tables by PCP size**

With PCP=4, `max_model_len=1_048_576`, and `max_num_seqs=1024` (the H100 default), the C4 builder allocates 8 GiB per GPU for this gathered table plus 2 GiB for its local copy; the C128 builder adds another 5 GiB. These allocations occur even for a one-request workload, since slicing by `gather_num_reqs` later does not reduce the backing storage. This removes substantial KV-cache capacity and, with non-extensible KV caches, can cause initialization OOMs because the activation profile skips attention before these builders are initialized. Deduplicate the rank-local request tables using global request indices, or otherwise bound this storage, and include the remaining allocations in memory sizing.
