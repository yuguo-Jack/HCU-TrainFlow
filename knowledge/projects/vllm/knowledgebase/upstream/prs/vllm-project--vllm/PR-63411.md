# [Core][Bugfix] Drop bounded_replay when promoting SlidingWindowMLASpec

[Upstream PR](https://github.com/vllm-project/vllm/pull/63411) · state: open · merged: False

## Original PR description



## Overview

With `--disable-hybrid-kv-cache-manager`, KV cache planning crashes on any model with `SlidingWindowMLASpec` layers (DeepSeek-V4), because promotion to `MLAAttentionSpec` forwards the SWA-only `bounded_replay` field. Introduced by the interaction of #56227 (adds `bounded_replay`) and #61183 (moves the promotion into `kv_cache_planning.py`).

## Claims

- Fixes `TypeError: MLAAttentionSpec.__init__() got an unexpected keyword argument 'bounded_replay'` at startup for sliding-window MLA models with the hybrid KV cache manager disabled.
- Adds a regression test for `unify_hybrid_kv_cache_specs` with a `SlidingWindowMLASpec` layer, which no existing test covered.

## Validation

**Unit test**, run on MI300X (gfx942) in a ROCm 7.2 image built from this branch's tree; the fix was reverse-applied to the installed package for the "without" column:

| | `-k swa_mla` | full `tests/v1/core/test_kv_cache_planning.py` |
|---|---|---|
| without fix | 1 failed (the `TypeError` above) | 62 passed, 1 failed (the new test) |
| with fix | 1 passed | 63 passed |

```bash
pytest tests/v1/core/test_kv_cache_planning.py -k swa_mla
```

**End to end**, DeepSeek-V4-Flash and DeepSeek-V4-Pro, disaggregated prefill/decode (MoRIIO connector, 2P/2D and 4P/4D, `-tp 1` + DP + EP), MI300X, `--disable-hybrid-kv-cache-manager`:

- without the fix, every worker dies in `_promote_local_kv_cache_specs` during `get_kv_cache_configs`;
- with the fix, all prefill and decode workers start, size their KV cache, and serve requests (concurrency sweeps 1–32 at 1024/1024 complete on both models).

```bash
vllm serve deepseek-ai/DeepSeek-V4-Flash --disable-hybrid-kv-cache-manager ...
```

## Details

When the hybrid KV cache manager is off and full-attention layers are present, `_promote_local_kv_cache_specs` rebuilds each sliding-window spec as its full-attention counterpart through `replace_as`, which forwards every field of the source spec. `SlidingWindowMLASpec` has two fields `MLAAttentionSpec` lacks: `extra_retained_tokens`, which was already dropped, and `bounded_replay`, which was not. The field is always present, so the crash happens even at its default `False`.

Dropping it is semantically right for the same reason as `extra_retained_tokens`: a promoted spec allocates blocks for every token and never frees below the window, so window-bounded prefix replay has nothing to bound. The promoted spec reports the ordinary full-attention `prefix_cacheable`, which is correct because it retains the full prefix.
