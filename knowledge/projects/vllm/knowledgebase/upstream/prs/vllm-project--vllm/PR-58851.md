# [Perf][MRV2] Share GDN, Mamba and Kimi-K3 KDA batch metadata across KV cache groups

[Upstream PR](https://github.com/vllm-project/vllm/pull/58851) · state: open · merged: False

## Original PR description

## Overview

Move MRV2 cross-group metadata reuse into GDN, Mamba and Kimi-K3 KDA builders, extending merged #58762 to KDA and speculative Mamba.
Explicitly avoiding the MRV1 code reuse from the interim solution in #58762 

## Claims

- Share batch metadata while preserving group-local state, checkpoints and CUDA graph buffers. Every group, the first included, derives those in one per-group function; cross-group tests compare every metadata field with an independent build.
- Extend Mamba aligned-index precompute from plain GDN and nvidia KDA to Mamba1, Mamba2, ShortConv, PLE short-conv and ROCm KDA, and remove redundant slices. No MRV1 features restored.
- PLE short-conv, for non-speculative batches, and ROCm KDA now also share metadata; neither is GPU-tested.
- Move Mamba2's per-group checkpoint regather from #57329 into `_update_state_indices`, so the V1 `update_block_table` path and the MRV2 cross-group path both use it.
- Works with MRV1 fully removed: MRV2 no longer calls `update_block_table` or reads `supports_update_block_table`. With `gpu_model_runner.py` and that API deleted, the 13 Mamba test modules still pass on `eb206ad240` (CPU).

## Validation

Two GB10 nodes, CUDA 13, full Python sources with compatible precompiled binaries. Measured `8abc56f46c` against main `710ac56e69`.

```bash
.venv/bin/python -m pytest -q \
  tests/v1/attention/test_{gdn,mamba,replayssm}_metadata_builder.py \
  tests/models/kimi_k3/test_kda_metadata.py \
  tests/v1/worker/test_mamba_hybrid_model_state.py \
  tests/v1/worker/test_attn_utils.py \
  tests/v1/worker/test_gpu_target_dependent_ar_speculator.py::test_pcp_draft_metadata_keeps_graph_padding_in_decode
```

- Focused: **204 passed, no failures/skips**. Wider: **1194 passed / 5 failed / 188 skipped**, versus main **1189 / 4 / 188**.
- Four failures reproduce on main (CUPTI/Proton). Final `b2f2182ce8` fixes the remaining string-device constructor failure; the GPU reproducer passes with MRV2 on/off. No full-suite or benchmark rerun after that one-line fix.
- **103 metadata scenarios match; 279 CUDA captures and 837 changing-input replays per revision pass.** All eight serving synchronization checks pass.
- Serial greedy tokens/logprobs match on all four models. Mixed-batch variation also occurs on main. Kimi uses dummy weights; no quality claim.

Output-interval change with paired 95% intervals: five independent main/PR pairs, four for TP2. CUDA API counts use separate 200-step profiles.

No regression means it maintains the performance improvement from #58762
