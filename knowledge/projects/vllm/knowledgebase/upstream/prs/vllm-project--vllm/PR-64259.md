# [CI][Bugfix] Fit the MLA backend bf16 atol to a bf16 SDPA reference

[Upstream PR](https://github.com/vllm-project/vllm/pull/64259) · state: closed · merged: True

## Original PR description

- `test_mla_backends.py`: raise the bf16 (`kv_cache_dtype="auto"`) atol in `_run_backend_correctness` from 1e-2 to 2e-2.

`test_chunked_context_backend_correctness[False-trtllm-gen-auto-glm-MLAPrefillBackendEnum.ROCM_AITER_FA]` started failing in MI355 V1 Attention Shard 2/4, for example in https://buildkite.com/vllm/ci/builds/97849 and in main build 97866. TRITON_MLA and ROCM_AITER_MLA both failed with max diff 0.015625. No vLLM PR caused it. The runtime-shard plan is rebuilt from rolling main timings, and the new plan put 286 `test_backend_correctness` cases ahead of this test in the same process. The module seeds only once, at import, so those cases move the default CUDA generator's offset, and the GLM case gets a different random draw. The test compares against a torch SDPA reference that is also computed in bf16. At GLM dims, both the reference and the AITER prefill are up to about 0.012 off an fp32 result. Their difference goes over 0.01 + 0.01*|x| on about 6% of random draws, so 1e-2 is tighter than the reference's own error. Re-seeding per case would only pin one draw that passes, so this widens the bf16 atol to cover two bf16 kernels. A real chunk or merge bug still shows errors of 0.1 or more.

<summary>Tests (MI355X, ROCm 7.2.3, AITER v0.1.26)</summary>

All commands run from `tests/` with `VLLM_ROCM_USE_AITER=1`.

- Before the fix:
  - A small_prefill `test_backend_correctness[deepseek-...-small_prefill]` run right before the GLM chunked case: 3/3 failed with the CI signature (`TRITON_MLA, ROCM_AITER_MLA ... Max diff: 0.015625`).
  - The GLM chunked case over fresh random draws: 6/100 failed.
  - The exact CI Shard-2 order (303 tests, rebuilt from `RUNTIME_SHARD_PLAN`) passes on this node, but only by about 0.0004; CI's ROCm 10.0 wheel is likely enough to tip it over.
- After the fix:
  - Pair: 10/10 pass.
  - Failing test alone: pass.
  - CI Shard-2 order: 10/10 pass (302 passed, 1 skipped).
  - GLM and deepseek chunked cases over 200 random draws each: 400/400 pass.
- `pytest -v v1/attention/test_mla_backends.py v1/attention/test_sparse_mla_backends.py`: 8/10 clean (760 passed, 304 skipped). Neither failure touches the changed tolerance:
  - `test_sparse_mla_backends.py::test_sparse_backend_decode_correctness[...large_q_pure_prefill-ROCMAiterMLA]` (abs diff 11.0 on 0.1% of elements) is a separate flake; it also fails about 1/20 when run alone, without this change.
  - `test_sparse_mla_backends.py::test_rocm_fused_v32_dense_prefill_matches_mqa[fp8]` hit `EADDRINUSE` because I ran five loops in parallel on one host.

Duplicate check: `gh pr list --repo vllm-project/vllm --state open --search` for `test_mla_backends`, `chunked_context`, `mla tolerance` and `manual_seed attention test`. The closest is #55611, which adds an rtol override for ROCm `v_head_dim=256`. That does not cover this failure: it happens on small outputs, where atol is the limit.
