# [Feature][Multimodal] Make the media fetch User-Agent configurable

[Upstream PR](https://github.com/vllm-project/vllm/pull/62833) · state: open · merged: False

## Original PR description



## Overview

Add `VLLM_MEDIA_USER_AGENT` to override the `User-Agent` header vLLM sends when fetching media URLs (multimodal `image_url`/`audio_url`/`video_url` inputs and `run-batch` `file_url`). The default stays `vLLM/<version>`.

## Claims

- New env var `VLLM_MEDIA_USER_AGENT`; when set, its value is sent as `User-Agent` on all media fetches (sync and async clients).
- Default behavior is unchanged when the variable is unset or empty.
- Excluded from `compile_factors()`, so setting it does not invalidate the torch.compile cache.

## Validation

Unit tests (new `test_media_user_agent`, using the existing local HTTP server fixture, no mocks):

```bash
.venv/bin/python -m pytest tests/test_connections.py tests/test_envs.py -q
# 67 passed
```

The override case fails when the `connections.py` change is reverted.

End-to-end through `MediaConnector.fetch_image` / `fetch_image_async` against a local HTTP server that records the received header, with the real environment variable:

| `VLLM_MEDIA_USER_AGENT` | Received `User-Agent` (sync, async) |
|---|---|
| unset | `vLLM/<version>`, `vLLM/<version>` |
| `my-service/1.0 (ops@example.com)` | `my-service/1.0 (ops@example.com)`, same |

## Details

Motivation: the outbound `User-Agent` is hard-coded. Changing it currently requires registering a custom media connector via `VLLM_MEDIA_CONNECTOR` that reimplements the HTTP fetch path, or patching vLLM. Use cases:

- Identifying individual deployments in outbound traffic logs.
- Egress proxy / firewall rules keyed on `User-Agent`. Outbound HTTPS goes through a CONNECT tunnel, so a forward proxy cannot rewrite the header without TLS interception.
- Policies that do not expose the software name or version in outbound requests.

Design notes:

- All media fetches go through `HTTPConnection._headers()`, so this is the single change point.
- An env var rather than a CLI flag, consistent with the existing `VLLM_MEDIA_*` settings; `global_http_connection` is a module-level singleton with no path for CLI args.
- An empty value falls back to the default instead of omitting the header, since some hosts reject requests without a `User-Agent`.
- Per-request `extra_headers` still take precedence, as before.
- Docs: `docs/configuration/env_vars.md` is generated from the `envs.py` definitions, so no separate doc update is needed.

Not a duplicate: searched open/closed issues and PRs for "User-Agent"; none make the media fetch User-Agent configurable.
