# [ROCm][CI] Fix int8 GEMM kernel selection logic for ROCm platform

[Upstream PR](https://github.com/vllm-project/vllm/pull/62099) · state: closed · merged: True

## Original PR description

## Overview
When using VLLM_ROCM_USE_AITER=1 as default, 2 test cases will fail:
1. quantization/test_quark.py::test_quark_int8_w_per_tensor_a_per_tensor;
2. quantization/test_compressed_tensors.py::test_compressed_tensors_no_enforce_eager
The cause is the int8 GEMM kernel selection logic selects AITER by mistake -- AITER supports only per-token/per-channel case. So we need to update the selection logic to fix this issue.

## Claims
1. Now AITER kernel is correctly excluded for unsupported cases even when VLLM_ROCM_USE_AITER=1;
2. A new test case is added to make sure AITER kernel is selected only for its support cases;
