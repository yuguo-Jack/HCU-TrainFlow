# [Perf] Enable PDL for fused MoE top-k gating

[Upstream PR](https://github.com/vllm-project/vllm/pull/59737) · state: closed · merged: True

## Original PR description



## Overview

The FP32 router GEMM supports programmatic dependent launch (PDL), but fused MoE `topkGating` uses an ordinary launch. Enable PDL for the consumer on SM90+ with CUDA 12+, allowing it to start early and wait before reading producer-dependent data.
<img width="842" height="150" alt="image" src="https://github.com/user-attachments/assets/05cdfe4d-2bdc-40d5-9559-a74492884ce3" />


## Claims

- On GB200, the M=4 MiniMax-M3 router-to-gating CUDA Graph chain saves **0.486 us (-9.12%)** with hot weights and **0.466 us (-7.77%)** with rotating weights.
- In ordinary MiniMax-M3 aggregated serving, mean TPOT improves **0.61–1.16%** at request concurrency 1/16/32. All three paired runs improve for both tested input lengths at these concurrencies. C4 is effectively unchanged.
- Pure-prefill C16/C32 mean TTFT regresses **0.54%/0.49%**. The results support a modest decode benefit on this setup; broader workload and platform coverage remains open.

## Validation

**End-to-end accuracy (`713192bab`):** Full GSM8K (1,319 questions, 5-shot, temperature 0, concurrency 8), MiniMax-M3 NVFP4, TP8 on the same 8x GB200 GPUs, with real EAGLE3 verification and three draft tokens. Each variant ran twice without restarting its server.

| Strict-match accuracy | Baseline | PDL |
| --- | ---: | ---: |
| Run 1 | 1247/1319 (94.54%) | 1248/1319 (94.62%) |
| Run 2 | 1254/1319 (95.07%) | 1249/1319 (94.69%) |
| Mean | 94.81% | 94.66% |

Mean change is -0.152 percentage points; baseline repeats differ by 0.531 points. These two repeats per variant do not establish accuracy equivalence. All evaluation requests succeeded. Baseline uses official vLLM v0.29.0; the candidate overlays the pinned PR kernel in the same image, rather than a full PR checkout build.

**Serving:** MiniMax-M3 NVFP4, 8x GB200 on two four-GPU nodes, TP8 with expert parallelism disabled, one aggregated worker, FP8 KV/indexer cache, FlashInfer/TRTLLM attention, no prefix caching or speculative decoding. Direct `vllm serve` / `vllm bench serve` uses the same physical GPUs for A/B, three valid pairs per workload, and 64 measured requests per variant per pair.

| Request concurrency | TPOT change, ISL/OSL 128/1024 | TPOT change, 8192/1024 | TTFT change, 8192/1 |
| ---: | ---: | ---: | ---: |
| 1 | -0.61% | -0.63% | +0.89% |
| 4 | +0.05% | -0.01% | -0.12% |
| 16 | -1.16% | -1.00% | +0.54% |
| 32 | -0.93% | -1.09% | +0.49% |

Negative latency changes are better. Changes are computed within each pair and then averaged. For 128/1024 C1, mean TPOT is 3.874 → 3.851 ms; individual paired changes range from -0.82% to -0.48%. These finite bursts and three repeats do not establish statistical significance or sustained-load capacity.

**Kernel chain:** M=4, H=6144, E=128, top-4 sigmoid; three same-GPU A/B pairs. Hot-weight latency is 5.330 → 4.844 us. Rotating weights use 64 distinct 3 MiB matrices; paired changes range from -8.28% to -6.51%. Each repetition ends with a non-PDL serial boundary to prevent overlap into the next repetition and premature logits-buffer reuse. Its approximately 0.682 us cost is included equally. Latencies are medians across rounds; savings are medians of paired differences. Isolated gating with that boundary saves 0.076 us (-2.16%).

**Correctness and integration:**

- 866 unchanged upstream fused-top-k and FP32-router tests passed against the pinned runtime with the PDL overlay.
- 360 representative original-versus-patched operator cases per process match with zero tolerance: FP32/FP16/BF16, expert counts 6–512, selected index types/top-k values, bias, normalization, padding, ties and nonfinite values. Equal NaNs are accepted; NaN payload-bit identity is not asserted.
- 1,200 preallocated-chain and 960 runtime-dispatch changing-input graph checks passed, including poisoned intermediates and the M=32/33 dispatch boundary.
- The changed SM100a CUDA translation unit compiled; the original standalone harness passed Compute Sanitizer memcheck with zero errors.
- All 74 raw serving measurements completed: 4,736 requests, zero failures. One JIT-contaminated pair is excluded and replaced as described below.
- Separate untimed GPU traces confirm PDL gating on all eight TP ranks. Directly adjacent router/gating calls overlap in residence in 6,720/6,720 patched pairs versus 0/6,720 baseline pairs. Residence includes dependency waits; it does not directly measure time saved.

## Details

The dependency wait and completion signal precede dependent reads and row-dependent exits. CUDA launches set the PDL attribute without a host architecture query, matching `topk_softplus_sqrt` and `per_token_group_quant`, and check `cudaLaunchKernelEx` errors. Device-side PDL instructions remain guarded by `__CUDA_ARCH__ >= 900`. Routing math, launch geometry, output layout and the operator API are unchanged. ROCm and the unfused fallback retain their existing paths. Hopper, ROCm and a full current-main build remain unvalidated.

For the host-launch cleanup in `09647c0364`, `git diff --check` and `.venv/bin/pre-commit run --files csrc/libtorch_stable/moe/topk_softmax_kernels.cu` passed. GPU tests were not rerun for this cleanup; the accuracy results above remain pinned to `713192bab`.
