# [CI] Move L4 Distributed Models and LoRA TP and their AMD mirrors from fixed to automatic shards

[Upstream PR](https://github.com/vllm-project/vllm/pull/62537) · state: closed · merged: True

## Original PR description



## Overview

Moves `distributed-model-tests-2-gpus` and `lora-tp-distributed`, with their AMD mirrors, from hand-written fixed shards to `automatic_shard`. Both were left out of #62120 until the L4 queue was back so they could be validated.

## Claims

| Step | Was | Planned shards |
|---|---|---:|
| `distributed-model-tests-2-gpus` | 3 fixed (`case` block) | 3 |
| `amd-distributed-model-tests-2-gpus` | 3 fixed (`case` block) | 4 |
| `lora-tp-distributed` | 4 fixed (`test ... \|\|` guards) | 3 |
| `amd-lora-tp-distributed` | 4 fixed (`if ...; fi` guards) | 3 |

- Every test runs exactly once across the shards, with the same environment and `-m` filters as before.
- A test file added later is placed by the planner rather than by editing a `case` branch.

## Validation

- Planned each step and mirror with ci-infra main's `runtime_shard.plan_step` against this branch and main's timings; every planned shard is well under the 20-minute target.
- Rendered each step and mirror with the pipeline generator and ran every shard's commands against a mock test tree, as a PR build and with main's `pytest -p ci_otel` wrapper: every test of every command ran in exactly one shard, with the same env (4/4 NVIDIA cases, 4/4 AMD mirror cases).
- `/ci run` [97471](https://buildkite.com/vllm/ci/builds/97471), rebased on main after ci-infra#836: every shard of both steps and both mirrors passed, with passed/skipped totals equal to main ([97556](https://buildkite.com/vllm/ci/builds/97556), [97527](https://buildkite.com/vllm/ci/builds/97527)). The NVIDIA steps' machine time is in line with main. The AMD mirrors' shards ran a few minutes longer than the same plans did before the rebase ([96709](https://buildkite.com/vllm/ci/builds/96709)): every job that day spent longer starting up before its first command, and its tests ran slower too. The Distributed Models mirror's slowest shard still finished well ahead of main's slowest fixed shard that day.

## Details

- **Commands.** Each `case` branch or guarded line becomes one plain command. The AMD mirror's `&&` chains become separate commands; a failing command still fails the job.
- **Timeouts unchanged (human).** As in #62077 and #62120, `timeout_in_minutes` stays per job. A single-job fallback (no plan, or the `VLLM_CI_RUNTIME_SHARD` rollback switch) would outrun it; fallback-aware timeouts belong in a central timeout setting.
- **Left out.** The separate `.buildkite/test-amd.yaml` copy of the Distributed Models mirror keeps its fixed shards.
