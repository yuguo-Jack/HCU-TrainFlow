# [Perf][Mamba] Cache the conv_state transpose view per state-cache tensor

[Upstream PR](https://github.com/vllm-project/vllm/pull/65396) · state: open · merged: False

## Original PR description

## Summary

The Mamba/SSM mixers (`MambaMixer2`, `MambaMixer`, `ShortConv`) re-derived their
`conv_state` view from `self.kv_cache[0]` on every forward: in the default SD
layout this is a `transpose(-1, -2)` to give the conv kernels a
`(..., dim, state_len)` view. The view depends only on the cache tensor
storage/strides, fixed once allocated, so deriving it per call is pure host
overhead that multiplies by `num_mamba_layers × tokens`. The mixer forward runs
inside a `direct_register_custom_op` (dispatched via `no_compile_layers`), so it
is opaque to `torch.compile` and executes eagerly even under the default
compiled regime — exactly the per-call view-derivation class of #59534 / #64572,
in a different subsystem (Mamba/SSM, not attention).

Add `get_conv_state_view` in `mamba_utils`, caching the view per cache-tensor
identity (mirroring the FlashAttention fix #64571), and clear it in
`clear_layer_kv_caches` so the detached profiling state cache is not pinned. The
identity check rebuilds the view when the profiling cache is replaced by the
real one.

Related: #59534, #64571, #64572

## Testing

`pytest tests/kernels/mamba/test_conv_state_view_cache.py` — 4 passed (CPU-only):
SD layout caches the transpose and hits on the same tensor, the cache rebuilds
when the tensor is replaced, an in-place write through the view aliases the base
storage, and the DS layout returns the base tensor unchanged (no copy).

Host time per `transpose(-1, -2)` vs a cached-view hit (CPU, N=20000 after
warmup, blocks=2000/state_len=4/dim=2048): **1.75 µs → 0.21 µs/call**, ×
num_mamba_layers × tokens. `pre-commit` clean (ruff, ruff-format, mypy).

## Duplicate check

`gh pr list --state open --search "conv_state transpose ..."` and
`"mamba conv_state cache"`: no matching open PR. Open Mamba PRs concern
checkpointing, prefill batching, and CUDA-graph/metadata — none touch the
per-call conv_state view derivation.
