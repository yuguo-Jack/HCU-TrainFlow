# [Perf][KV Offload] Publish async lookup results per request group

[Upstream PR](https://github.com/vllm-project/vllm/pull/57474) · state: closed · merged: True

## Original PR description

## Overview

`AsyncLookupManager` batches each scheduler step's tier-existence probes, then checks request groups sequentially on its worker. This change publishes a request group's result as soon as that group's lookup finishes, so completed groups no longer wait for later groups before the scheduler can use their results.

## Claims

- A completed group can resolve at the next scheduler drain even while later groups are still being checked; a HIT can therefore become eligible to start promotion earlier.
- The worker remains FIFO and single-threaded. Each group's `batch_lookup()` must finish before its results are published; lookup verdicts and promotion policy are unchanged.
- Results remain grouped by `req_id`; this does not publish a partially consumed group.

This replay isolates result-publication timing; it does not run the full scheduler, allocate primary-tier slots, or execute promotion transfers. Its step duration is simulated, so these results are directional and are not a serving-throughput claim. Absolute wall-clock timings varied. The scratch replay harness is not part of this PR.

No model evaluation was run because this change affects lookup-result publication timing, not model outputs or accuracy. No end-to-end serving benchmark was run.

## Details

The worker still receives the step's accumulated keys at `flush()` and groups them by `req_id`. Previously, it collected results from every group and posted one combined result batch after the last group completed. The new code posts each group's results immediately after fully consuming that group's `batch_lookup()` output. This removes the result-publication wait between independent groups; it does not start the worker earlier or parallelize the group lookups.

I found no open PR for this exact result-publication change. Related #61292 moves Mooncake connector lookups to the input thread, and #62615 protects primary-tier hits during promotion; both address different paths. #23622 is a non-merge PoC for different connector lookup semantics.
