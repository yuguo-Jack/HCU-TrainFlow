# [Docs] Add a Slurm multi-node deployment guide

[Upstream PR](https://github.com/vllm-project/vllm/pull/63982) · state: open · merged: False

## Original PR description



## Overview

Add a "Using Slurm" deployment guide and example scripts for multi-node `vllm serve` with Apptainer/SingularityCE and the multiprocessing backend (one `srun` task per node, no Ray).

## Claims

- New `docs/deployment/slurm.md` and `examples/deployment/slurm/{serve_multinode.sbatch,node.sh}`.
- Covers the cluster-specific startup failures the scripts avoid (long TMPDIR, user site packages, ROCR_VISIBLE_DEVICES with Ray, `--rocm` host libraries, Triton cache location and shared-filesystem races, `--trust-remote-code` module race, `--env` comma splitting, interconnect interfaces).

## Validation

The example scripts as committed, on LUMI (MI250X, 8 GPUs/node, Slingshot, SingularityCE 4.1), `vllm/vllm-openai-rocm:v0.31.0`, Qwen/Qwen3-0.6B: 2 nodes (`TP=8 PP=2`) and 4 nodes (`TP=16 PP=2`) start and answer a completion request. Final runs of the committed scripts: 2 nodes served after 46 min, 4 nodes after 42 min (cold compile; Triton cache node-local).

## Details

- Existing multi-node docs (`parallelism_scaling.md`, `examples/ray_serving/run_cluster.sh`) assume Docker and Ray; HPC sites usually have Slurm and Apptainer/SingularityCE without root.
- Not a duplicate: no Slurm guide exists in `docs/` or `examples/`, and no open PR adds one.
