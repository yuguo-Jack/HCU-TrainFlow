# [CI] Remove lm-eval configs that no config list references

[Upstream PR](https://github.com/vllm-project/vllm/pull/60593) · state: open · merged: False

## Original PR description

## Overview

Remove lm-eval configs and lists that no config list or CI job references, so they are never evaluated.

Legacy-test tracker: A5

## Claims

- Deletes 13 `.buildkite/lm-eval-harness/configs/*.yaml` named by no `configs/*.txt` list: the Meta-Llama-3-8B variants, QQQ (a removed quant method), Minitron-4B, Mixtral-8x22B/8x7B FP8, the Qwen2-1.5B pair, and Llama-3.2-1B FP8-CT.
- Deletes `models-small.txt`, which is byte-identical to `models-small-rocm.txt` and used by no job, and `models-mm-large-h100.txt` with its Maverick-MM config. The example in the `test_lm_eval_correctness.py` docstring now points at `models-small-rocm.txt`.
- Deletes 3 gsm8k moe-refactor configs that no list references. The three Llama-4-Scout ModelOpt configs parked by #35870 are kept.

## Validation

- `pre-commit run` on the changed files passes, including test tethering (no test loses its CI job).
- A repo-wide grep (vllm/, tests/, benchmarks/, examples/, tools/, docs/, .buildkite/) finds no remaining reference to any deleted file.
- ruff and mypy pass on `test_lm_eval_correctness.py`. For each deleted config, a grep over every `configs/*.txt` and `.buildkite` yaml confirms nothing names it.
- GPU tests not run locally; CI covers them.

## Details

- Reviewer call: `moe-refactor-dp-ep/Llama-4-Scout-Fp8-ModelOpt-triton.yaml` is deleted because no dp-ep list ever referenced it. It is a different file from the #35870-parked ones.
- Split out of the original #60591 cleanup so each part reviews on its own. Part of a legacy-test audit; no test that currently runs is affected. Not a duplicate: open-PR searches found no PR removing these files.
