# [EPD] Metadata-only image and video inputs for GLM-5.3-Flash

[Upstream PR](https://github.com/vllm-project/vllm/pull/64071) · state: closed · merged: True

## Original PR description

## Overview

GLM-5.3-Flash can now take metadata-only image and video inputs in Python EPD, the same out-of-band placeholder path as Qwen-VL (#50390) and audio models (#57887). The encoder publishes `image_grid_thw`, and for video `video_grid_thw` plus one timestamp per temporal patch. The consumer rebuilds placeholders from those fields and receives embeddings through the EC connector.

No open PR covers this. #61418 is routing-metadata adapters, not EPD media metadata.

## Claims

- An EC consumer no longer reruns GLM-5.3-Flash vision preprocessing when the encoder published the placeholder metadata.
- On a cold 1E+1PD pair this is about 1.14× request throughput and 0.86× TTFT versus forwarding the raw image. The same ratio holds after each arm has warmed its own CUDA graphs.
- On 32 greedy image requests and 16 greedy video requests, prompt token counts and answer text matched the raw-media path on every request. Image and video throughput are separate tables. The image ratio above is not a video result.

## Details

`Glm4vMultiModalDataParser.embedding_fields` marks the grid and video timestamps as placeholder metadata and the embeds as values, so `allow_missing_mm_embeddings` drops only the embeds on an EC consumer. Timestamps are computed with the existing GLM-5.3 frame sampler and stored on the processed video item, which is what the encoder publishes and what the prompt replacement reads. Image replacement was already grid-sized; it now works when the request carries only `image_grid_thw`.

Video still needs those timestamps because a GLM placeholder includes one timestamp string per temporal patch, not only `grid.prod()`. Requests that omit the metadata stay on the raw-media path.
