# [Rust Frontend] Pass attributed deltas and the tokenizer to tool parsers

[Upstream PR](https://github.com/vllm-project/vllm/pull/62874) · state: closed · merged: True

## Original PR description



## Overview

Give Rust tool parsers what a token-aware parser needs: `ToolParser::parse_into` takes the attributed `DecodedText` delta instead of `&str`, and `ToolParser::create` receives the model tokenizer. Behavior-preserving; the bottom of a stack whose next PR makes the DeepSeek DSML tool parser match its markers by token identity.

## Claims

- `ToolParser::parse_into(&mut self, chunk: DecodedText, ..)`, as `ReasoningParser::push` and `UnifiedParser::parse_into` already are. `CombinedParser` passes reasoning content through with its attribution instead of dropping it to `content.text`.
- `ToolParser::create(tools, tokenizer)` and the chat `ToolParserFactory`, so a parser can resolve its marker token IDs once at construction, as reasoning and unified parsers do.
- No parser output changes: every existing tool parser matches by spelling and reads only `chunk.text`, and none reads the tokenizer yet.

## Validation

From `rust/`:

```bash
cargo nextest run --workspace --features vllm-parser/test-util --no-fail-fast
cargo clippy -p vllm-parser -p vllm-chat --all-targets --features vllm-parser/test-util -- -D warnings
```

The workspace suite passes unchanged apart from call-site updates (the `parse_chunk` / `collect_stream` test helpers keep their `&str` inputs and wrap them as unattributed text), and Clippy is clean. Pure interface change, so no new tests.

## Details

- Why: a tool parser cannot tell a dedicated marker token from an ordinary-token spelling of the same bytes while the trait hands it plain text, and it has no tokenizer to learn the marker's token ID. Unified parsers (Kimi K3) already have both.
- Changing the signature in one pass rather than adding a defaulted `parse_decoded_into` keeps one entry point, matching how `ReasoningParser::push` and `UnifiedParser::parse_into` were migrated. The diff is mechanical: one line per parser plus imports and test call sites.
- `reset() -> String` is unchanged: recovery does not need attribution.
- Two commits: the delta type and the tokenizer argument.

Not a duplicate: the open DSML PRs (#62517, #62259, #54686, #58322) change the Python parsers or tokenizer encoding; none touches the Rust `ToolParser` trait.
