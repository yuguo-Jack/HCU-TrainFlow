# [Perf][GDN] Skip FLA chunk metadata when FlashInfer GDN prefill is active

[Upstream PR](https://github.com/vllm-project/vllm/pull/61569) · state: closed · merged: True

## Original PR description



## Overview

Skip building FLA chunk metadata (`prepare_chunk_indices`/`prepare_chunk_offsets` + two H2D copies per prefill-containing step) when the FlashInfer GDN prefill backend is active — the FlashInfer wrapper consumes only `cu_seqlens` and never reads them. Same exemption as the existing `aiter_flydsl` path. 4-line change, no behavioral difference.

## Claims

- Removes ~5 µs of CPU work and 2 H2D copies per prefill-containing scheduler step under `gdn_prefill_backend=flashinfer` (auto default on SM90, and SM100/SM120 with `head_k_dim=128`). With MTP this covers mixed steps too (non-spec 1-token decodes are reclassified into the chunk-kernel path).
- Output-neutral by construction: `fi_chunk_gated_delta_rule` has no `chunk_indices`/`chunk_offsets` parameters.

## Validation

- `pytest tests/v1/attention/test_gdn_metadata_builder.py -q`: 61 passed.
- Removed work, timed on the exact skipped calls (`FLA_CHUNK_SIZE=64`): 3.5-5.4 µs CPU + 1.0-64.5 KiB H2D per step for 1-64 seqs x 8k tokens.
- E2E A/B (no-regression): Qwen3.8-Flash-Next-FP8, TEP4 on 4x GB300, 8k-in/1-out, auto backend. Worker logs confirm FlashInfer GDN prefill engaged on both branches.

## Details

Duplicate-work check: nearest open PRs inspected by diff — #60050, #61034, #60105, #57039; none skip the chunk-metadata build. Verified compatible with #60050 (FlashInfer prefill checkpoints) in either landing order: its checkpoint path calls `fi_chunk_gated_delta_rule` directly without chunk indices, and its fallback branch only passes them through the dispatch wrapper, which the FlashInfer backend ignores.

No accuracy eval: nothing in the change can affect outputs (see Claims); the e2e run above exercised the modified path at c1-64.
