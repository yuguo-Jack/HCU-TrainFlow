# [Bugfix][Rust Frontend] Correct DP routing after request removal

[Upstream PR](https://github.com/vllm-project/vllm/pull/59631) · state: closed · merged: True

## Original PR description


## Overview

Correct Rust frontend data-parallel routing when requests finish or are aborted
before the next scheduler snapshot. This follows the routing estimates added in
#58956 and prevents stale admissions from steering work to a busier engine.

AI assistance was used to develop and validate this change.

## Claims

- Remove finished or aborted current-generation admissions from the routing
  estimate.
- Preserve admissions already incorporated into a newer scheduler snapshot.
- Keep an idle engine eligible instead of routing live work to an engine with
  higher scheduler-reported load.

## Validation

- Before main (`ab5266769e`): the focused regression failed with
  `([Some(0), Some(0)], Some(1))`; after two requests finished on idle engine 0,
  the next live request incorrectly chose engine 1 with one running request.
- After this change: the same regression passed with
  `([Some(0), Some(0)], Some(0))`; the live request chose idle engine 0.
- `cargo nextest run -p vllm-engine-core-client registry_finished_requests_do_not_route_live_work_to_a_busier_engine`
  — passed.
- `cargo nextest run -p vllm-engine-core-client` — 125 passed, 0 skipped.
- `cargo clippy -p vllm-engine-core-client --all-targets -- -D warnings` —
  passed.
- `cargo fmt --all -- --check` — passed.

## Details

`admitted_since_stats` is incremented for each admission after a scheduler
snapshot and reset when the next snapshot arrives. Request removal previously
decremented only `inflight`, so a request completed before the next snapshot
continued contributing phantom load to the routing score.

Each engine now advances a generation when scheduler counts are applied, and
each post-snapshot admission records that generation. Removal decrements
`admitted_since_stats` only when the request belongs to the current generation.
This avoids subtracting work already represented by a newer snapshot without
scanning active requests when stats arrive.

Duplicate checks were repeated immediately before drafting across the affected
symbols, functions, invariant, and fix mechanism. Diff inspection confirmed
that open #59453 handles transport failure in `imp.rs`, while #53454 handles
resumable request lifecycle; neither fixes completion/removal accounting in
`state.rs`.

Model/serving evaluation was not run because this changes Rust frontend
control-plane routing bookkeeping only; it does not affect model inputs,
outputs, numerical accuracy, or token generation.
