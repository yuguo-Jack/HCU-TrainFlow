# [Bugfix][Pooling] Honor the CrossEncoder activation saved by Sentence Transformers v6

[Upstream PR](https://github.com/vllm-project/vllm/pull/62785) · state: open · merged: False

## Original PR description

## Overview

Sentence Transformers v6 saves a CrossEncoder's `activation_fn` in `config_sentence_transformers.json` instead of `config.json`, but vLLM only reads the `config.json` keys. Rerankers trained or re-saved with ST v6 and an `Identity` activation are therefore scored with the default sigmoid instead of returning raw logits. This reads the saved setting and exposes it where the classifier activation lookup already reads it. It is only used for plain CrossEncoders whose ST pipeline is a single Transformer module, and an activation set through `hf_overrides` still wins.

## Claims

- `/score`, `/rerank` and `/classify` apply the activation that plain ST v6 CrossEncoders declare, matching `CrossEncoder.predict`.
- Precedence follows Sentence Transformers: an activation set through `hf_overrides` (a dict or a callable, through `sentence_transformers.activation_fn` or `sbert_ce_default_activation_function`) wins, even when it equals the value in `config.json`, then `config_sentence_transformers.json`, then `config.json`'s `sentence_transformers.activation_fn` and the legacy `sbert_ce_default_activation_function`. `problem_type` keeps its existing priority in vLLM.
- No change for checkpoints without a CrossEncoder `config_sentence_transformers.json`, or whose ST pipeline has more or custom modules. That covers Qwen3-Reranker, Qwen3-VL-Reranker and jina-reranker-m0, which save `activation_fn: Identity` on top of a `LogitScore` or custom module that vLLM scores itself.

## Validation

Offline `LLM.score` on RTX 4090 (`enforce_eager=True`), one query and three documents, compared with `sentence_transformers.CrossEncoder.predict` (CPU). The ST "Sigmoid" row passes `activation_fn=torch.nn.Sigmoid()`, and the vLLM override rows set `torch.nn.modules.activation.Sigmoid`.

|---|---|---|---|
| Sentence Transformers | 8.3557 | -7.0466 | -8.0292 |
| Sentence Transformers, Sigmoid | 0.9998 | 0.0009 | 0.0003 |
| vLLM `main` | 0.9998 | 0.0009 | 0.0003 |

| this PR, dict / legacy-key / callable override | 0.9998 | 0.0009 | 0.0003 |

Tests:

- New `tests/test_config.py::test_get_sentence_transformers_activation_fn` (CPU, `tmp_path` checkpoints): returns the activation only for a `CrossEncoder` config that declares one and has no `modules.json` or a single Transformer module, and `None` for `Transformer` + `LogitScore` or a custom module.
- New `tests/test_config.py::test_sentence_transformers_cross_encoder_activation_fn`: `ModelConfig` for the ettin reranker (config files only), with and without an older Sigmoid in `config.json`, resolves to `PoolerIdentity`, or to `PoolerClassify` when `hf_overrides` sets Sigmoid through either key or a callable. The default case fails on `main` (`PoolerClassify(num_labels=1)`), and the override cases fail if the saved activation overwrites `hf_overrides`, including when the override equals `config.json`.
- `pytest tests/test_config.py tests/transformers_utils tests/model_executor/layers/test_pooler_activations.py`: 621 passed, 4 failed. The same 4 fail on `main` (gated Llama checkpoints).
- `pytest tests/entrypoints/pooling/scoring`: no failures beyond `main`'s. Only `test_cross_encoder_online_vision.py` cases fail, and they fail intermittently on `main` too (2 or 3 of them across runs).
- `pre-commit run --files <changed files>`: all hooks pass.

## Details

`get_act_fn` (`vllm/model_executor/layers/pooler/activations.py`) looks for `config.sentence_transformers["activation_fn"]` and the legacy `sbert_ce_default_activation_function` on the HF config. ST v6 writes `activation_fn` to `config_sentence_transformers.json` on every save (`CrossEncoder._get_model_config`) and reads it from there first (`CrossEncoder._parse_model_config`), falling back to the `config.json` keys only when it is absent. On load it also deletes the legacy key, so re-saving an older `cross-encoder/*` fine-tune with v6 leaves only the new file.

The fix adds a cached `get_sentence_transformers_activation_fn` next to `get_sentence_transformers_chat_template_kwargs`, and in `ModelConfig.__post_init__`'s pooling block (next to the existing `get_pooling_config` merge) writes the value into `hf_config.sentence_transformers["activation_fn"]`. That is where older ST versions stored it and where `get_act_fn` already looks, so the pooler code is unchanged and the existing `torch.nn.modules.` restriction still applies.

- ST applies the activation to the output of the last module. It only matches the classifier output vLLM computes when the pipeline is a single Transformer module (`_ST_TRANSFORMER_MODULE_TYPES`), so `modules.json` is checked as well.
- `hf_overrides` has already been applied in the pooling block, so the saved value is skipped when the overrides set either activation key (`is_cross_encoder_activation_overridden`). A dict is checked directly. A callable is run on a dummy config, the same way `HFConfigParser` probes a callable for `model_type`.

Not a duplicate: I found no issue or PR for this (searched "config_sentence_transformers activation_fn", "CrossEncoder activation_fn", "sentence transformers v6 cross encoder", "reranker sigmoid Identity"). #31563 (closed, unmerged) and #60877 handled ST v6 reranker chat templates, not the activation.
