# [Bugfix][Rust Frontend] Preserve tool schema numbers in HF templates

[Upstream PR](https://github.com/vllm-project/vllm/pull/64173) · state: open · merged: False

## Original PR description

## Overview

Addresses item 4 of #63917: large integers in tool schemas lose precision during HF template rendering, and small scientific exponents differ from Python's spelling.

## Claims

- Preserve request-level tool-schema integers through 128 bits in HF templates for chat completions and `/tokenize`.
- Render `1e-07` and `123456789012345678901234567890` without shortening the exponent or rounding the integer.
- Retain existing `tojson` sorting, indentation, separator, and escaping behavior.

## Validation

```bash
cargo test --manifest-path rust/Cargo.toml -p vllm-chat -p vllm-server --lib -q
# 433 chat tests and 534 server tests passed

cargo test --manifest-path rust/Cargo.toml -p vllm-chat --test chat --test grammar_replay -q
# 19 tests passed

cargo clippy --manifest-path rust/Cargo.toml -p vllm-chat -p vllm-server --lib --tests -- -D warnings
cargo fmt --manifest-path rust/Cargo.toml --all -- --check
git diff --check
# All passed
```

The regression checks final HF-rendered prompts after request deserialization and lowering for both endpoints. It fails on the unmodified base and passes with this change. The tests are included in the existing Rust Frontend Cargo CI suite.

A broader chat-suite run encountered four roundtrip failures (`roundtrip_kimi_k25`, `roundtrip_mimo_v26`, `roundtrip_qwen3`, `roundtrip_step5`), also reproduced on the unmodified base. Validation covers request lowering and prompt rendering; no live-server or real-model generation/quality evaluation was run.

## Details

Preserve raw schema JSON at the request boundary and convert it into native MiniJinja values for rendering. Serialize those values without narrowing integers through `serde_json::Value`. This avoids enabling workspace-wide `arbitrary_precision`.

Exact-integer preservation covers request-level schemas within the `i128`/`u128` range. Developer-message schemas, larger integers, and complete Python floating-point formatting parity remain outside this change.

Duplicate-work checks found no overlapping fix: #63974 addresses item 1, #63926 addresses items 2-3, and #60199 bounds indentation allocation in the same filter.
