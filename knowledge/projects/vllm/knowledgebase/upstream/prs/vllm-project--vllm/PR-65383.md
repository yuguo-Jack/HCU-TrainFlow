# [Bugfix] Report reasoning_tokens in /inference/v1/generate derender usage

[Upstream PR](https://github.com/vllm-project/vllm/pull/65383) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`/inference/v1/generate` with `output_mode: "derender"` now reports `usage.completion_tokens_details.reasoning_tokens` in batch and stream mode, summed over the choices, as `/v1/chat/completions` does. Fixes #65360.

**Stacked on #64041.** The first commit (b5701018c5) is #64041 cherry-picked onto main; review only the commits after it (170677d681, 658be9d6a6). This PR reuses the reasoning-token count #64041 adds to `OnlineDerenderer._parse_and_assemble`, so it can't land first. I'll rebase once #64041 merges.

## Claims

- With `--reasoning-parser`, batch and stream generate derender usage include `completion_tokens_details.reasoning_tokens`. Before this change it was `null` on both paths.
- The count matches `/v1/chat/completions`, including with `include_reasoning: false` and summed across choices when `n > 1`. Stream with `n > 1` works here, unlike chat derender in #64041, because generate keeps a live parser per choice.
- Without a reasoning parser (or with only a tool parser), `completion_tokens_details` stays `null`, as on chat.
- `tokens` and `text` output modes are unchanged.

## Details

**Root cause:** `ServingTokens` built `UsageInfo` from token counts only, in `_build_response_fields` (batch) and in the final stream usage chunk. #63103 left `reasoning_tokens` out of scope.

**What changed:**
- **Batch:** `OnlineDerenderer.derender_text_choices` now also returns `completion_tokens_details`. It sums the per-choice count from `_parse_and_assemble` (#64041). It is `None` unless `--reasoning-parser` is set.
- **Stream:** `serve_tokens_stream_generator` keeps each choice's output token IDs. At the end, `OnlineDerenderer.stream_completion_tokens_details` counts them with that choice's `ChatStreamProcessor` parser. Coupled chat does the same.

**Limitation:** per-chunk `continuous_usage_stats` usage still has no details. Coupled chat recounts every token on every chunk to fill them; I left that out to keep this small. It's noted in the docs.

**Not a duplicate:** no open PR references #65360 or touches generate usage. #64041 covers `/v1/chat/completions/derender` only and lists generate as out of scope. #64935 covers `/v1/chat/completions/batch` only.
