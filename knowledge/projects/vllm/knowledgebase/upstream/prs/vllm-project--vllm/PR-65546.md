# [Frontend] Optional lifecycle hooks for endpoint plugins

[Upstream PR](https://github.com/vllm-project/vllm/pull/65546) · state: open · merged: False

## Original PR description



## Overview

Adds four optional lifecycle methods to endpoint plugins (`start`, `ready`, `drain`, `stop`) and a `request_shutdown` callback, so an out-of-tree plugin with long-lived sessions or its own listener can start, report readiness, drain on SIGTERM and stop cleanly. Linked from RFC #65545; builds on endpoint plugins (#46565, #47454).

## Claims

- Existing endpoint plugins are unchanged: the methods are found with `getattr`, outside the `runtime_checkable` Protocol members, and the existing `isinstance` check still passes for plugins without them.
- `start` runs in load order during lifespan startup; if one raises, core calls `stop` on the plugins already started, in reverse order.
- `/health` returns 503 while any graceful shutdown is in progress and while a plugin reports not ready. This follows vLLM's convention (the DP supervisor's `/health` returns 503 on SIGTERM; the gRPC server sets `NOT_SERVING`).
- On SIGTERM, drains run concurrently under one `--shutdown-timeout` deadline (one `asyncio.TaskGroup` under one `asyncio.timeout`); the engine gets the remaining time, as before. A drain still running at the deadline is cancelled and awaited.
- `stop` runs exactly once per started plugin, after HTTP stops and before app state is deleted, including after a watchdog exit. It first cancels and awaits a drain still in progress.
- Core's own transcription/translation `shutdown()` teardown now goes through the same stop path, as in-tree adapters.
- The render server now receives `--shutdown-timeout` (it was left at 0, so its drains never ran).
- A plugin that owns a non-HTTP listener refuses to start with `--api-server-count` other than 1.

Each fix was checked by reintroducing its bug (sequential drains, no cancel-and-wait in `stop`, no cancellation deferral, the missing render timeout): each fails a test. `pre-commit` passes, including mypy.

## Details

- 12 files, +763/−29: source +196/−25 (`plugins/endpoint_plugins/interface.py` +141/−6, lifespan and stop adapters +27/−10, launcher +15/−1, health +12/−8, render +1), tests +480, docs and CI +87.
- `stop` has no timer, like upstream lifespan teardown (uvicorn does not bound lifespan shutdown; the transcription and translation `shutdown()` calls had no bound). The process manager's forced termination stays the backstop. A shared timeout around the stop loop would need a new option, and a hung plugin would starve the core stop adapters, which stop last.
- Admission during drain: core sets `state.draining` before anything is awaited; plugin authors must check it in their admission paths. No extra hook.
- Data-parallel external load balancing: documented, not refused. A DP supervisor child is indistinguishable from a legitimate one-rank-per-host external-LB launch; the supervisor already refuses `--grpc` for the same collision.
- Normal-path cost: when no started plugin implements `drain`, the drain helper returns without awaiting.
- Docs: `docs/design/endpoint_plugins.md` (lifecycle table, shutdown order), a security note for plugin-owned listeners in `docs/usage/security.md`, and a usage example.
- Limits: shutdown is process-local; `drain` relies on cooperative cancellation; `stop` has no timer; a plugin-owned listener's authentication is the plugin's responsibility (security note in the docs); `/health` returns 503 during drain, which also affects liveness probes pointed at it (RFC open question 3). Validation uses a dummy plugin and a fake engine on CPU, plus the A100 launcher suite; no streaming model or live-session validation yet.
- Draft follow-ups (from `/pr-checklist`): replace the render test that only checks `--shutdown-timeout` forwarding with one that shows a render-server drain runs; fold the manually built startup-failure test into the lifespan rollback test; give the live-server helper guaranteed bounded teardown, and bound the remaining task and shutdown awaits in the tests (the event waits are bounded).
- Not a duplicate: open PRs searched for endpoint plugin lifecycle, drain and shutdown. The nearest, #60505, adds a separate `/health_generate` readiness route.
