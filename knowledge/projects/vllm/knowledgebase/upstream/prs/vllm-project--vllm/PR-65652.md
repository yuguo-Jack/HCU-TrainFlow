# [torch.compile] Replace config `compute_hash` with `compile_factors`

[Upstream PR](https://github.com/vllm-project/vllm/pull/65652) · state: open · merged: False

## Original PR description



## Overview

Replaces every config's `compute_hash() -> str` with `compile_factors() -> dict`, covering the remaining TODOs in #39479.

Closes #39479 It revives #40246, which was approved but closed when its branch was deleted, rebased onto current main.

## Claims

- Configs return their compile factors; `normalize_value` uses a nested config's `compile_factors()`, so `CompilationConfig` and `KernelConfig` no longer special-case `pass_config`, `dynamic_shapes_config` or `ir_op_priority`.
- `hash_config()` / `hash_config_cached()` replace `compute_hash()` / `compute_hash_cached()` for callers that need a string (EPLB, DP validation, serve fingerprint, startup plan, FlashInfer autotune cache).
- `cache_key_factors.json` now records the full env, config, code and compiler factors, not just env factors and hashes.
- JIT (`VllmBackend`) and AOT (`aot_compile_hash_factors`) share one env/config hash helper, and the JIT cache key and AOT source check share one code hashing helper. `CompilationConfig.traced_files` is now `set[Path]`.
- Every config that affects the graph is now opt-out: it hashes all fields except an explicit `ignored_factors` set, so new fields are hashed by default. Configs that don't affect the graph return `{}` and say how to switch if that changes.
- `get_compile_factors` raises on unknown `ignored_factors`, so a typo can't silently leave a field hashed.
- The set of hashed fields is unchanged, but hash values change, so existing compile caches miss once.
- **Breaking for out-of-tree code:** `additional_config` objects and `CompilerInterface` subclasses must implement `compile_factors()` instead of `compute_hash()`. A `CompilerInterface` subclass still defining `compute_hash` raises `TypeError`, since it would otherwise silently drop out of the cache key (for example `AscendCompiler` in vllm-ascend).
- The worker sentinel now uses `hash_config_cached`, like every other EPLB `model_states` lookup, avoiding a `KeyError` after `max_model_len` auto-fit.
- Supersedes #62458, #61885 and #62628.
