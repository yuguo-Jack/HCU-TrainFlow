# fix(responses): unflatten namespace tool names before returning function calls

[Upstream PR](https://github.com/vllm-project/vllm/pull/46784) · state: closed · merged: False

## Original PR description

Fixes #46737

### Description
This PR fixes the tool name flattening issue in the Responses API path. It introduces a `unflatten_tool_name` utility in `vllm/entrypoints/openai/responses/utils.py` to map flattened namespace tool names (e.g. `mcp__computer_use__get_app_state`) back to namespace-local tool names (`get_app_state`) and the corresponding namespace (`mcp__computer_use`). This is integrated in both the streaming and harmony paths to ensure the Codex client receives the correct format.

Thanks for the review! You are right that a naive `rsplit("__")` would break valid function names such as `get__weather`.

I've updated the PR so that `unflatten_tool_name` now accepts the original `tools` list from the request. It will only unflatten a tool name if the client explicitly defined it inside a `NamespaceTool` (i.e., `type: "namespace"`) and the flattened name matches the `{namespace}__{tool}` format. This guarantees that regular tools are left completely untouched, while still resolving the issue for the Codex client.
