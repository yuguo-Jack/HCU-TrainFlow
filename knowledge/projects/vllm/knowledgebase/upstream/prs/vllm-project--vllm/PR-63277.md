# [Bugfix][Tool Calling] Fix zero-argument and named tool calling in Qwen3 tool parser

[Upstream PR](https://github.com/vllm-project/vllm/pull/63277) · state: closed · merged: False

## Original PR description



## Overview

Fixes tool call parser behavior for Qwen3 (`qwen3_coder` and `qwen3_xml`) when handling zero-argument tools and forced/named tool choices (`tool_choice="required"` or `tool_choice={"type": "function", "function": {"name": ...}}`), preventing Pydantic / MCP client validation failures (e.g., `unexpected_keyword_argument: __unparsedToolInput`).

## Claims

- Skips JSON guided decoding enforcement (`structured_outputs.json`) for `tool_choice="required"` and named tool choices in `Qwen3EngineToolParser` when structural tags are not used, allowing Qwen3 to emit its native XML format (`<tool_call><function=...`) instead of triggering structured output mismatches (mirrors `Gemma4EngineToolParser` and `Glm47MoeToolParser`).
- Trims whitespace and newlines from function names in `ParserEngine` (`_emit_name_delta` and `_handle_tool_end`), preventing downstream client tool lookup failures when models emit `<function=name \n>`.
- Updates `AnthropicServingMessages` streaming completion check so zero-argument tool calls without argument chunks are recognized as complete (`tool_complete = True`) with `stop_reason="tool_use"` rather than falling back to `stop_sequence`.
- Clarifies zero-argument invocation syntax in `examples/tool_chat_template_qwen3coder.jinja` prompt instructions (`<tool_call>\n<function=name>\n</function>\n</tool_call>`).

## Details

### Root Cause
1. **JSON Guided Decoding Conflict**: `ToolParser` defaults `supports_required_and_named = True`. When client requests used `tool_choice="required"` or a named tool choice (common in MCP tool orchestration agents), `ToolParser.adjust_request` set `request.structured_outputs` to JSON guided decoding. Because Qwen models generate XML (`<tool_call><function=...`), JSON guided decoding either restricted output to raw JSON (which Qwen chat template did not prompt for) or caused fallback wrappers (`__unparsedToolInput: {"raw": "{}", "summary": {}}`) in client frameworks (e.g., Pydantic AI / MCP). Overriding `adjust_request` in `Qwen3EngineToolParser` (matching Gemma4 and GLM4 implementations) skips JSON guided decoding when structural tags are not active, preserving native XML tool output generation and parsing.
2. **Trailing Whitespace in Tool Names**: During streaming, function names split or formatted with trailing whitespace/newlines (e.g. `<function=describe_cluster \n>`) were emitted directly into `DeltaFunctionCall.name`, causing client agent lookup failures.
3. **Anthropic Message Stop Reason**: In `AnthropicServingMessages`, zero-argument tool calls emit no argument delta chunks (`last_tool_args == []`). `_is_json("".join(last_tool_args))` evaluated `_is_json("") -> False`, setting `tool_complete = False` and returning `stop_reason="stop_sequence"` instead of `stop_reason="tool_use"`. Defaulting empty argument buffers to `"{}"` ensures zero-argument tools are marked complete.
