# [Bugfix][Frontend][Rust Frontend] Accept DeepSeek V4.1 reasoning effort aliases

[Upstream PR](https://github.com/vllm-project/vllm/pull/62226) · state: open · merged: False

## Original PR description

## Overview

Accept the standard `reasoning_effort` aliases `minimal` and `medium` in the Python and Rust DeepSeek V4.1 renderers. Fixes #62220.

## Claims

- Map `minimal` to the existing low budget of `50`.
- Map `medium` to the existing high budget of `75`.
- Preserve all existing named efforts, numeric budgets, precedence rules, and validation behavior.
- Keep the Python and Rust frontend implementations consistent.

## Details

The DeepSeek V4.1 renderers previously accepted only `low`, `high`, `xhigh`, and `max`, even though clients can send the standard `minimal` and `medium` effort values.

This change adds model-specific compatibility aliases in both implementations. `minimal` uses the same numeric budget as `low`, while `medium` uses the same numeric budget as `high`. Focused tests cover the aliases at the Python encoding boundary and through both the request-level and template-argument paths in the Rust renderer. Invalid names and out-of-range numeric budgets remain rejected.

No overlapping open PR was found through searches for `#62220`, DeepSeek V4.1 reasoning-effort aliases, and the affected Python and Rust renderer paths. Related PRs #52739 and #61094 provide optional generic, operator-configured mappings rather than this model-specific zero-configuration behavior.
