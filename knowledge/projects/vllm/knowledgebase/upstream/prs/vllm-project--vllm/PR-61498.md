# [ROCm][Perf][Kimi-K3] Mono decode layer for Kimi-K3 on MI355X w/ vanilla decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/61498) · state: open · merged: False

## Original PR description



## Overview

Extend Kimi-K3's MI355X MonoKernel from [#60683](https://github.com/vllm-project/vllm/pull/60683) to support ordinary autoregressive decode without speculative decoding.

This is a stacked extension of [#60683](https://github.com/vllm-project/vllm/pull/60683) and should merge only after that PR.

## Claims

- Supports pure, uniform regular-decode steps with widths 1–8.
- Preserves the existing speculative-verification path.
- Continues routing prefill, mixed batches, unsupported graph modes, and widths above eight through standard vLLM layers.
- Requires no speculative decoding, MTP, or DSpark configuration.
- Improves output throughput by 46.2% at concurrency 1, 37.4% at concurrency 4, and 17.5% at concurrency 8 on the tested 80K-input workload.
- Falls back as designed above width eight: concurrency 16 remains within 1.3% of mono-off throughput.

## Details

### Motivation

[#60683](https://github.com/vllm-project/vllm/pull/60683) currently requires speculative decoding and only routes spec-verification steps through the Kimi-K3 MonoKernel. Ordinary autoregressive decode is refused at configuration time even though its one-token decode shape can use the existing `qlen=1` K1 specialization and K2 kernels.

This change removes only that restriction and adapts regular-decode metadata to the existing kernel interface.

### Design

For regular decode:

- `non_spec_state_indices_tensor` supplies one KDA state slot per active row.
- State indices are exposed to K1 as `[requests, 1]`.
- A device-resident tensor of ones supplies graph-stable accepted-token counts.
- Eligibility requires:
  - no prefill rows;
  - no speculative rows;
  - one regular-decode row per active request;
  - valid one-dimensional state indices;
  - launch width no greater than eight.

When speculative decoding is configured, the existing spec-verification path remains unchanged.

### Limitations

The existing [#60683](https://github.com/vllm-project/vllm/pull/60683) constraints remain:

- MI355X/gfx950.
- TP8.
- FULL CUDA graphs for decode.
- Pure decode steps only.
- Maximum MonoKernel width of eight rows.

Other steps continue using standard vLLM execution.

At concurrency 16, the width limit intentionally routes almost every step through standard vLLM execution, explaining the near-parity performance result.

### Performance
`vllm bench serve`, 64K shared cached prefix + 16K unique input, forced 1K output with ignore-EOS, 16 warm-ups, and `10 × concurrency` measured prompts. Mono off and on use the same image and server settings; only `--monokernel` differs.

### Not a duplicate

This does not duplicate [#60683](https://github.com/vllm-project/vllm/pull/60683): it is a small stacked extension enabling the non-speculative case that the base PR currently refuses.

A search of open vLLM PRs found no other Kimi-K3 change adding ordinary regular decode to this MonoKernel.

Related Kimi-K3 MonoKernel work:

- [#60683](https://github.com/vllm-project/vllm/pull/60683) introduces the MI355X Kimi-K3 MonoKernel for spec-verification steps and is this PR's base.

    --device /dev/dri \
    --group-add video \
