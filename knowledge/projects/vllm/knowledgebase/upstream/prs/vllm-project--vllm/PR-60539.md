# [XPU] Compile passes porting llm-scaler decode optimizations, multi-row decode fixes (QKV/norm/GEMV/MoE router/all-reduce)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60539) · state: open · merged: False

## Original PR description

XPU decode optimizations for gated-attention / GDN / MoE models (Qwen3.5 / Qwen3.6-A3B), all as vLLM compile post-grad passes (no model or common `fused_moe/` changes; the one non-XPU change is the speculative-decoding warmup fix in `fc84b8304`, below). FP16 and BF16 activations are supported. The kernels are in vllm-project/vllm-xpu-kernels#622.

## Base / testing
- Based on `main` (`a4b14e57b`); merges cleanly into the current `main`.
- All passes are off by default (`pass_config` flags below) and check that the vllm-xpu-kernels ops they need are available.
- Tested on Intel Arc Pro B70 (Xe2), Qwen3.6-35B-A3B with `--quantization fp8`, `--dtype float16` and `--dtype bfloat16`, TP=2, in `vllm/vllm-openai-xpu:v0.31.0` (torch 2.14) with the kernels PR above: every pass matches all target layers of the model, greedy outputs checked against the unfused path, unit tests below pass.

## MoE + shared-expert fusion (`5246fc07e`)

Per MoE layer the pass rewrites

```
out = vllm.moe_forward_shared(hidden, hidden, hidden, None, layer, 0)
y   = out[0] + out[1]
```

into `y = vllm.xpu_moe_shared_fused(hidden, hidden, layer)`, which runs the router, top-k, routed experts and the sigmoid-gated shared expert through `torch.ops._xpu_C.moe_shared_fused_decode_interface` (vllm-xpu-kernels). The TP all-reduce after the MoE layer stays in the graph.

The op lives in `vllm/_xpu_ops.py` next to the other XPU custom ops (as `gdn_attention_core_xpu` does, and as ROCm keeps its ops in `vllm/_aiter_ops.py`) and is registered in `xpu_ops.register_ops_once()` when the kernel is available. `vllm/model_executor/layers/fused_moe/` is unchanged.

| File | Scope | Change |
|---|---|---|
| `vllm/_xpu_ops.py` | XPU only | `xpu_moe_shared_fused_available()`, `xpu_moe_shared_fused_unsupported_reason(runner)`, lazily built kernel plan, `vllm::xpu_moe_shared_fused` impl + fake, registered in `register_ops_once()` |
| `vllm/compilation/passes/fusion/xpu_fusion.py` | XPU only | the pass (`XpuMoESharedFusionPass`) |
| `vllm/config/compilation.py` | common | `PassConfig.fuse_xpu_moe_shared` (XPU only, default off), `xpu_moe_shared_fusion_max_token_num` (default 8) |
| `vllm/config/vllm.py` | common | disable the fusion for models that are not fp16 / bf16; add the compile-range endpoint when enabled |
| `vllm/compilation/passes/pass_manager.py` | common | register the pass when the flag is set |
| `tests/compile/passes/test_xpu_fusion.py`, `tests/compile/test_config.py` | tests | graph rewrite, preconditions, op schema, XPU numerics, PassConfig / compile ranges |

Fusion conditions:
- **Compile range**: only ranges ending at or below `xpu_moe_shared_fusion_max_token_num`, so prefill keeps the unfused path.
- **Model level** (pass init): fp16 or bf16 model, per-tensor FP8 quantization, Qwen3.5/3.6-A3B MoE shape (hidden 2048, 256 experts, top-8, shared expert), no LoRA, no expert parallel / EPLB, kernel available, and every MoE layer passes `xpu_moe_shared_fused_unsupported_reason()`; otherwise the whole pass is disabled with a warning naming the layer and reason.
- **Per layer**: `XPUExpertsFp8` routed experts, router gate held by the runner and not fused with the shared-expert gate, sigmoid-gated shared expert, SiLU, `routed_scaling_factor == 1`, `apply_router_weight_on_input` off, no LoRA / EPLB / EP / expert map / DP / PCP / SP, no bias, fp8-e4m3 per-tensor weights (per-expert routed scales, scalar shared scales), shared gate and router gate of the activation dtype, matching shared/routed intermediate size, kernel `supports()`.
- **Per node**: `router_in is hidden`, shared input is hidden, no `input_ids`, `hidden_dim_unpadded == 0`, exactly the two `getitem` users feeding one `aten.add`, fp16 / bf16 hidden states with last dim 2048. Nodes that don't match are left unchanged.

The kernel plan is built on first call and cached on the runner, so graphs loaded from the AOT compile cache (where the pass does not run) work. The only private access is the shared MLP wrapped by `SharedExperts` (`_layer`), read defensively in one helper.
