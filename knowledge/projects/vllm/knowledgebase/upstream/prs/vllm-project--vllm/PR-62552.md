# [Bugfix][KV Connector] MoRIIO: wait for the decode-rank handshake before WRITE

[Upstream PR](https://github.com/vllm-project/vllm/pull/62552) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

MoRIIO WRITE waits for the target decode rank's handshake before the RDMA write, and sends that rank `write_failed` if the write still cannot finish.

## Claims

- Fixes the cold parallel-dispatch `KeyError: '<host>:<port>_dpN'`.
- On a write error or handshake timeout, prefill frees its blocks and notifies the owning decode rank, so decode leaves `WAITING_FOR_REMOTE_KVS`.

## Validation

- `pytest tests/v1/kv_connector/unit/test_moriio_write_done_routing.py -q --tb=line`: 21 passed. CPU teardown `Cannot access accelerator device` also happens on base `7879f3687b`.
- Each new test fails if the old behavior is restored.
- - Hardware used the upstream vLLM ROCm release image `public.ecr.aws/q9t5s3a7/vllm-release-repo:7960eeb9de293137b7fca35cd4ae92c4c50ea286-rocm`, which does not contain this fix. Only the readiness gate was injected. 2P2D, DP=16: 32/32 HTTP 200, ranks `dp0`–`dp15` registered, no `KeyError`. The `write_failed` path is not in that image.

## Details

- Decode's block list can arrive before that rank's handshake metadata. The old gate treated "blocks allocated" as ready, then `_get_built_session` raised `KeyError` and prefill marked the transfer done without `write_failed`.
- The new gate requires `<dst>_dp<decode_dp_rank>` in `remote_moriio_metadata`. No allocation still uses the existing broadcast.
- Not a duplicate of #60852 (cancel-before-submit; will conflict), #58962 (consumer timeout), or #62020 (`FINISHED_STOPPED`).
- AI assistance was used to draft this change and its tests.
