# [Model] Add LiquidAI LFM3-VL (Lfm3VlForConditionalGeneration)

[Upstream PR](https://github.com/vllm-project/vllm/pull/65450) · state: open · merged: False

## Original PR description



## Overview

Adds LFM3-VL ([`LiquidAI/LFM3-VL-2B`](https://huggingface.co/LiquidAI/LFM3-VL-2B), `Lfm3VlForConditionalGeneration`), step 3 of #64645.

Depends on #64959 (the LFM3 text model), which carries #64647 (width-7 causal conv). Both commits are included unchanged, with their authorship, so this branch runs. Only the last commit is new; the other two drop on rebase once those PRs merge.

No other LFM3-VL PR exists: `gh pr list --search "64645 in:body"` returns only #64647 and #64959.

## Claims

- New `lfm3_vl.py`:
  - Native vision encoder: 14 layers over the patches of each frame, 8 gated depthwise 3×3 conv layers and 6 bidirectional GQA attention layers with QK RMSNorm and axial 2D RoPE.
  - The projector that merges each 2×2 block of vision tokens into one LFM3 token.
  - `Lfm3ForCausalLM` from #64959 as the language model.
- Image inputs go through the checkpoint's processor. Its image processor is the Qwen2-VL algorithm (same `smart_resize` and merge-block patch order), so processing reuses `Qwen2VLProcessingInfo` and `Qwen2VLMultiModalProcessor`.
- Registry, test registry and `supported_models.md` entries.

## Validation

The model was compared with the HF remote code (`AutoModelForImageTextToText`, `trust_remote_code=True`) on an Apple M5 Pro, using the vLLM CPU backend, fp32, greedy decoding and 48 new tokens. The checkpoint's `generation_config.json` sets `repetition_penalty: 1.1`, so the HF reference passes `repetition_penalty=1.0`.

| Case | Prompt tokens | Tokens matching HF | Max \|Δ logprob\| |
| --- | --- | --- | --- |
| One image (54×82 patches) | 1131 | 48/48 | 1.8e-4 |
| One image (74×110 patches) | 2054 | 48/48 | 8.9e-5 |
| Two images of different sizes in one prompt | 1428 | 48/48 | 3.2e-4 |
| Text only | 20 | 48/48 | 1.8e-4 |
| Text only, past the 256-token sliding window | 759 | 48/48 | 4.0e-5 |

The three image prompts sent in one `generate` call produce the same tokens as sending them one at a time.

**Not validated yet (why this is a draft):**
- CUDA. On GPU, the vision attention runs through `MMEncoderAttention` with FlashAttention and the language model through #64959's Triton kernels.
- bf16.
- TP/PP.
- Video inputs. The processor supports video with per-frame timestamps, but video is not wired up here.

## Details

- **Vision attention:** `MMEncoderAttention` with per-frame `cu_seqlens`, 16 query and 8 KV heads. The axial RoPE has the same layout as Qwen2-VL's vision RoPE (height and width each rotate a quarter of the head dim, NeoX pairing), with theta 1e6 from the vision config.
- **Conv layers:** each frame is reordered from merge-block order to raster order, run through a depthwise `conv2d` and reordered back. Frames of one shape convolve as one batch. The conv weight is sharded along channels to match `in_proj`.
- **Text positions:** plain 1D (no M-RoPE), so the wrapper calls `Lfm3Model` directly.
- **`trust_remote_code=True`:** needed for the config and processor, since Transformers doesn't ship LFM3-VL yet.
- **AI use:** AI assistance (Claude Code) was used to write the code and this description.
