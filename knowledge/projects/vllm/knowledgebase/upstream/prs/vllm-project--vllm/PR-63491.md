# [ROCm][MiniMax-M3.1] Sequence-parallel prefill under pure TP (split PR of M3.1)

## Original PR description

## Overview

**Split PR of M3.1 (#63232):** sequence-parallel prefill for MiniMax-M3.1 under pure TP on ROCm (TP4, gfx950), with its FlyDSL kernels. Opt-in: `VLLM_ROCM_MINIMAX_M3_SP_PREFILL=1`.

Based on main: #63232's M3.1-Flash landed as #64111 without this code (#63490 took it out). Carries #63483 (DBO under pure TP) as a merge of its branch: its 11 files (`vllm/config/`, `vllm/distributed/parallel_state.py`, `vllm/v1/worker/`, `fused_allreduce_gemma_rms_norm.py`, `prepare_finalize/no_dp_ep.py`, `tests/v1/worker/test_dbo_pure_tp.py`) belong to #63483; review the other 30.

## Claims

- With the switch off nothing changes: no extra weights, no pools, the regular forward.
- With it on, forwards from 4096 tokens (and DBO microbatches from 8192) keep the residual stream sharded by tokens. Per layer the two bf16 TP all-reduces become an o_proj all-to-all + gathers and a reduce-scatter + gathers of MXFP8 codes; norms, quants and the router run on a quarter of the tokens.
- The MoE runs FlyDSL prefill chains on the routed experts' weights: MXFP8 (`AiterMxfp8Experts`) and MXFP4 W4A4 (`AiterMxfp4Experts`, TP4).
- M3.1-Flash, TP4, MI355X, single-request TTFT (median of 3): 32K 1035 -> 689 ms (-33%), with DBO 655 -> 484 ms (-26%); 8 concurrent 16K prompts 32.3K -> 48.4K tok/s (+50%).

## Details

- `amd/sp_prefill.py` holds the sharding, the collectives and the model glue; `model.py` gets three hooks (the whole `o_proj_full`, the forward entry, its weight loading) and splits the attention into `qkv_proj` -> `attend` -> `o_proj`.
- MXFP8 MoE: the FlyDSL prefill chain (`ops/moe_mxfp8`, `ops/moe_flydsl_common`) on `AiterMxfp8Experts`' weights. The regular forward keeps aiter.
- MXFP4 MoE: SP quantizes the post-attention rows to per-token MXFP4 (aiter's kernel, as the regular path) before the all-gather, then runs sort -> aiter's scale sort -> gemm1 (gate/up + SwiGLU-OAI + MXFP4) -> gemm2 (routing-weighted bf16 partials) -> fixed-order reduce (`ops/moe_mxfp4`).
- An unfused shared expert runs as a dense MLP on the same gathered codes.
- qkv, `o_proj_full` and the dense MLP read the gathered codes through main's pre-quantized input path, `RocmDotScaledMxfp8LinearKernel.apply_weights` on a `QuantizedActivation`; `rocm_native.py` is unchanged.
- Memory per rank at TP4: `o_proj_full` +3.1 GB, collective pools 2.5 GB (KV cache 11.19M -> 10.84M tokens).
- Under DBO each phase is one microbatch hand-off on its comm stream (`dbo_tp_collective` from #63483), and both microbatches see the whole split (`ubatch_slices`), so they take the same path.
- FlyDSL pull collectives (`ops/sp_coll`) on TP4 / gfx950, RCCL otherwise.
