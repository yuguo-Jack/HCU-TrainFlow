# [Bugfix] Align routed_experts with streamed and final output token spans

[Upstream PR](https://github.com/vllm-project/vllm/pull/37094) · state: open · merged: False

## Original PR description

## Purpose

Fix incorrect `routed_experts` output semantics in V1 generation outputs.

Before this change:
- the scheduler only attached `routed_experts` when a request stopped
- `OutputProcessor` could return `token_ids` for only the current chunk while `routed_experts` still contained cumulative history
- `RequestOutputCollector` merged delta outputs by extending `token_ids` and `logprobs`, but did not merge `routed_experts`

This could produce missing or misaligned routed-expert data for:
- streamed `DELTA` outputs
- final outputs that only emit the latest generated tokens
- async/slow-consumer cases where multiple delta outputs are coalesced

This PR fixes that by:
- emitting `routed_experts` whenever decode emits new tokens
- slicing `routed_experts` to the same token span as the emitted `CompletionOutput.token_ids`
- concatenating `routed_experts` when delta outputs are coalesced

## Why this is not duplicating an existing PR

I checked the currently open routed-experts PRs and they address different failures:

- `#36419` fixes capturer singleton reinitialization after KV-cache profiling / CUDA graph memory profiling
- `#32415` fixes buffer sizing, `/dev/shm` fallback, and TP memory handling for routed-expert return
- `#35626` fixes routed-expert capture persistence with pipeline parallelism

This PR does not change capturer lifecycle, TP buffer sizing, or PP ownership/writes. It fixes output alignment in the scheduler/output-processor path after capture has already succeeded.

## Changes

- Emit routed experts on non-final decode steps in `Scheduler.update_from_output`
- Slice routed experts to the emitted token span in `RequestState._new_completion_output`
- Concatenate routed experts in `RequestOutput.add` when delta outputs are aggregated
- Add regressions for:
  - scheduler emission before stop
  - output slicing for final outputs
  - delta aggregation for async streaming/coalescing
  - real `FusedMoE` capture binding path

> Thanks for the alignment fixes — clearly correct.
> 
> One concern for multi-turn RL training (router replay in verl/slime): each turn is a separate vLLM request with the cumulative prompt. With this PR's routed_experts[-len(token_ids):] slice, each turn streams only its own decoded body. The initial prompt rows, inter-turn tool-result rows, and per-turn boundary tokens all get dropped — even though prefill captured them. So a multi-turn consumer can't reconstruct the full-trajectory routing the actor needs to replay during training.

Thanks for feedback, I've just pushed a fix to output_processor.py. We now only slice routed_experts[-len(token_ids):] when returning a stream DELTA. In FINAL_ONLY mode, the array is left unsliced, fully preserving the prompt/prefill routing data
