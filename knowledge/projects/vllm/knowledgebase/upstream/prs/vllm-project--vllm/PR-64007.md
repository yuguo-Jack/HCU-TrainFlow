# [Feature][Frontend] Report input audio duration in streaming transcription

[Upstream PR](https://github.com/vllm-project/vllm/pull/64007) · state: open · merged: False

## Original PR description



## Overview

`stream=true` transcription and translation responses return the transcribed text but not the length of the input audio, so a client that bills or budgets per audio second has to decode the upload itself before it can look at the stream. This adds `duration` (input audio length in seconds) to every streaming chunk, with the same name and position that non-streaming `verbose_json` already uses.

Not a duplicate: open PRs and issues for streaming transcription do not add the audio length to a stream chunk. #49073 (merged) made `verbose_json.duration` a float and #48543 (merged) added `diarized_json`; #50356 and #50362 ask for `verbose_json` on a diarized model. All four are non-streaming.

## Claims

- `/v1/audio/transcriptions` and `/v1/audio/translations` with `stream=true` now include `duration` on every chunk.
- The value is identical to the `duration` that `verbose_json` returns for the same file.
- The change is additive: no existing field is renamed, removed, or moved.

## Details

- **Placement.** `TranscriptionResponseVerbose` already has a top-level `duration`, and `TranscriptionResponseDiarized` does too. Putting the streaming field in the same place with the same name keeps one shape across response formats; a nested `usage.seconds` would be a second, integer-rounded representation of the same quantity.
- **Every chunk, not the first.** The generator skips deltas with no text and no `finish_reason` (`base/serving.py:775`), so "the first chunk" is not a stable anchor, and a client that starts reading late would miss it. `model` and `created` are already repeated on every chunk, so repeating one scalar follows the existing shape. The cost is roughly 20 bytes per chunk.
- **Not only the terminal usage chunk.** That chunk exists only when `stream_include_usage=true`, and it is never produced if the client disconnects or the request is cancelled — exactly the case where a billing client still wants to know how much audio it served.
- **Compatibility.** Additive JSON field. Clients that ignore unknown fields are unaffected; the field is also present on the terminal usage chunk when that chunk is sent.
- **Limitation.** `response_format=text` returns a plain-text body with nowhere to put the duration. That format is unchanged here.
