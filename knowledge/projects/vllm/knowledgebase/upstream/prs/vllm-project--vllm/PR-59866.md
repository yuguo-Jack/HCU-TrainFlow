# [Kernel] Add opt-in SM90 Triton MXFP8 W8A8 linear backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/59866) · state: closed · merged: False

## Original PR description

## Purpose

Add an experimental, opt-in Triton MXFP8 W8A8 dense linear backend for SM90 with BF16 activations. On Hopper, automatic MXFP8 linear selection currently uses Marlin W8A16. This backend dynamically quantizes activations per K32 group and executes independent GEMV/GEMM paths for decode and prefill, without Marlin fallback or a second packed weight copy.

Select it with:

```bash
vllm serve <model> \
  --kernel-config '{"linear_backend_per_quant":{"mxfp8":"triton"}}'
```

The implementation retains contiguous E4M3 weights, decodes E8M0 weight scales to FP32, and uses shape-dependent tiling, fused activation quantization, and split-K reduction. M=1 uses a fused GEMV. The backend accepts two-dimensional weights with positive K divisible by 32; batched weights use the existing separate selection. This does not replace MoE or attention kernels. Automatic selection retains its existing preferred backends.

W8A8 is the quantization contract; not every internal path executes native FP8 tensor-core instructions. Activation quantization changes W8A16 numerics. Performance validation is on H20 only.

### Real-checkpoint serving and evaluation

DeepSeek-V4.1-Flash, 8 x H20-3e, TP8, BF16, fixed 16 GiB KV cache per GPU, max sequence length 16384, max sequences 32, max batched tokens 8192, prefix caching/speculation disabled, compile mode 0 with FULL_DECODE_ONLY graphs. Serving numbers are means across three runs. Decode requests use 128 input / 64 output tokens; prefill uses 8192 input / 32 output tokens.

| Workload | Metric | Marlin W8A16 | Triton W8A8 | Change |
| --- | --- | ---: | ---: | ---: |
| Decode C1 | Mean TPOT | 6.943 ms | 6.465 ms | -6.88% |
| Decode C8 | Mean TPOT | 9.882 ms | 9.864 ms | -0.19% |
| Decode C16 | Mean TPOT | 12.330 ms | 12.417 ms | +0.71% |
| Decode C32 | Mean TPOT | 17.167 ms | 16.718 ms | -2.62% |
| Prefill C2 | Mean TTFT | 1585.996 ms | 1449.532 ms | -8.60% |

GSM8K 5-shot, all 1319 test questions: Marlin 1204/1319 (91.28%), Triton 1194/1319 (90.52%), a decrease of 0.758 percentage points. Paired wins/losses were 28/38; the observed difference does not establish quality equivalence. Evaluation responses were checked for empty, malformed, and zero-token results.

C16 decode TPOT regresses slightly, and individual kernel shapes can remain slower than Marlin. This PR makes no universal performance or accuracy-equivalence claim and keeps the backend experimental and opt-in.
