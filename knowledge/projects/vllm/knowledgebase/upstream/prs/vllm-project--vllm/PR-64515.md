# [Bugfix][XPU] Use int64 token index in the DeepSeek-V4 qnorm/RoPE kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/64515) · state: open · merged: False

## Original PR description

- **Problem:** `_xpu_qnorm_rope_kernel` (`vllm/models/deepseek_v4/xpu/xpu_qnorm_rope_kv_fp8_insert.py`) computes `token_idx * num_heads * HEAD_DIM` in int32, so the Q address wraps once a step holds more than 2^31 Q elements (65,536 tokens with 64 local heads); on Intel Arc Pro B60 this ends in `UR_RESULT_ERROR_DEVICE_LOST`. The 1M-context DeepSeek-V4 models hit this with a single prompt over 65,536 tokens at TP=1 and `--no-enable-chunked-prefill`. Fixes vllm-project/vllm#52416.
- **Fix:** promote `token_idx` to int64 (as the sibling DeepSeek-V4 kernels `fused_inv_rope_fp8_quant.py` and `fused_mtp_input_rmsnorm.py` in `vllm/models/deepseek_v4/common/ops/` already do), which also widens the KV offset; `head_idx` stays int32 because `head_idx * HEAD_DIM` is at most 128 × 512. A new regression test calls the public `xpu_qnorm_rope_kv_fp8_insert` op past the boundary, and a new Intel kernels CI step runs it.
- **Validation:** on Intel Arc Pro B60 with `vllm/vllm-openai-xpu@sha256:14d76dee` (nightly, 2026-10-29) on `main` 5082c45853, `pytest tests/kernels/test_deepseek_v4_xpu_qnorm_rope_large_batch.py -v` gives 1 passed with this PR and 1 failed (`UR_RESULT_ERROR_DEVICE_LOST`) without it; below the boundary (4096×64, 8192×8, 8192×64, 32768×16 tokens × heads) Q and the KV cache are bitwise identical to `main` and the op time is within ±0.1%. The new test is short and cheap: a single case on one card, about 15 s for the whole pytest session including the vLLM import (15.5 s with this PR, 16.1 s on `main`), and it needs about 8 GiB of free device memory, skipping otherwise.
- **Not a duplicate:** this supersedes vllm-project/vllm#52427 (same cast, applied to both program ids, no test; closed by its author on 2026-09-20 without a maintainer review) and adds the regression test and CI step it lacked; no open PR references vllm-project/vllm#52416; vllm-project/vllm#46685 (merged) and vllm-project/vllm#52582 fix the overlapping-store bug in the same kernel and do not touch the index type.
- **AI assistance:** this PR was written with AI assistance; I reviewed every changed line and ran the tests above.
