> [!NOTE]
> Adds end-to-end support for draft models using a different tensor-parallel (TP) size than the target model.
> 
> - Relax `SpeculativeConfig._verify_and_get_draft_tp` validation so `draft_tensor_parallel_size` is no longer restricted to `{1, target TP}`
> - In `GPUModelRunner`, initialize a dedicated draft TP process group and run drafter ops under `patch_tensor_parallel_group(...)` (for load, propose, dummy_run)
> - In `EagleProposer`:
>   - Store original `tp_group` and implement `_reshard_draft_tp_tensor(...)` that `all_gather`s shards and slices to match the draft TP partition
>   - When sharing `embed_tokens`/`lm_head`, if shapes differ, reshard target weights to the draft TP shard; otherwise reuse modules directly
>   - Minor import consolidation (`get_pp_group`, `get_tp_group`) and small logging adjustments
>

## Code Review

This pull request introduces support for different tensor parallel sizes for the draft model in speculative decoding. The core idea of using a separate TP group for the draft model and patching it during drafter operations is sound. However, I've found two critical issues:
1. The initialization of the draft model's TP group in `gpu_model_runner.py` is incorrect for distributed setups with data or pipeline parallelism.
2. The weight resharding logic in `eagle.py` for shared embeddings and lm_head is flawed, as it performs an `all_gather` operation in the wrong process group context. This will lead to incorrect weights being loaded.
I've also pointed out a leftover debug print statement. Addressing these critical issues is necessary for the feature to work correctly in distributed environments.

This new method has two issues:
1.  The `all_gather_into_tensor` call on line 1326 is incorrect. It should gather shards of the main model's weight (`src_tensor`) across the main model's tensor parallel group. However, this function is executed when the active TP group is patched to be the draft model's group. Using the default world group for `all_gather_into_tensor` is also incorrect if `TP_size < world_size`. This will lead to incorrect weights being loaded for the draft model.
2.  The `print` statement on line 1328 appears to be for debugging and should be removed.

A potential fix for the first issue is to obtain the main model's TP group before patching and pass it down to this function to be used explicitly in the `all_gather_into_tensor` call.

### Resharding assumes matching parameter names between models

**Medium Severity**

<!-- DESCRIPTION START -->
The `_reshard_draft_tp_tensor` function uses `name` from the draft model's `named_parameters()` to directly access the target model's state dict via `sd[name]`. This assumes both models have identical parameter naming hierarchies. If the draft model has a different module structure (e.g., `model.model.embed_tokens.weight` vs `model.embed_tokens.weight`), this will raise a `KeyError` when attempting to access the target model's state dict with the draft model's parameter name.
