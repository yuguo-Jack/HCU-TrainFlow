# [Bugfix][Spec Decode] Fix GLM-5.3-Flash DFlash2/EAGLE3 aux hidden-state capture with the upstream config

[Upstream PR](https://github.com/vllm-project/vllm/pull/60763) · state: closed · merged: True

## Original PR description



## Overview

`Glm5NextModel._aux_hidden_state` (added in #56983) reads `self.config.mhc_num_residual_streams`, but since #57387 the config is the upstream `Glm5NextTextConfig`, which calls it `hc_mult`. So capturing aux hidden states for a DFlash2 / EAGLE3 drafter on GLM-5.3-Flash raises `AttributeError` during startup. #56983 was developed on a base from before #57387, so it never hit the rename.

## Claims

- GLM-5.3-Flash with the recipe's DFlash2 config no longer dies with `AttributeError: 'Glm5NextTextConfig' object has no attribute 'mhc_num_residual_streams'`.
- Adds a CPU test that runs `_aux_hidden_state` against the upstream config.

## Validation

New test, red/green:

```bash
pytest tests/models/glm5next/test_aux_hidden_state.py
```

main: fails with the `AttributeError` above. This PR: passes.

E2E on 1xH100: `zai-org/GLM-5.3-Flash` with dummy weights, all 45 layers kept (the drafter reads layers 5/14/24/33/42), `hf_overrides={"text_config": {"n_routed_experts": 8}}` to fit one GPU, `language_model_only`, `enforce_eager`, and the recipe's `--speculative-config '{"method":"dflash","model":"incoai/GLM-5.3-Flash-DFlash2","num_speculative_tokens":7}'`:

| code | DFlash2 startup |
|---|---|
| main | `AttributeError: 'Glm5NextTextConfig' object has no attribute 'mhc_num_residual_streams'` |
| main + this PR | gets past aux capture, then `NotImplementedError: Layer ...indexer.k_cache: page size is not divisible by the maximum page size and cannot be padded` (KV grouping, #59656) |
| main + #59656 | same `AttributeError` |
| main + #59656 + this PR | starts and generates |
| main, no speculative decoding | starts and generates |

## Details

`hc_contract` only averages over the stream dim and ignores its `n` argument, so the change does not affect numerics; it just stops the attribute lookup from failing.

DFlash2 on GLM-5.3-Flash also needs the KV-cache grouping change that was split out of #56983 into #59656: with only this fix, startup moves on to `NotImplementedError: Layer ...indexer.k_cache: page size is not divisible by the maximum page size and cannot be padded`. The two changes are independent; the table above shows both are needed.

Not a duplicate: no open PR touches this line; #57171 (PP for GLM-5.3-Flash) predates #56983 and adds new code that still uses the old name.
