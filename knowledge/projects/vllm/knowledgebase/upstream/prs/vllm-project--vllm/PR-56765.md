# [XPU] Add tuned Mamba SSU configs for Intel Arc Pro B60

[Upstream PR](https://github.com/vllm-project/vllm/pull/56765) · state: closed · merged: True

## Original PR description

## Purpose

`selective_state_update` picks its Triton launch config from a per-device JSON
keyed on `(headdim, dstate, device_name, cache_dtype)`. #50534 added that
lookup and shipped configs for Intel Arc Pro B70. Intel Arc Pro B60 has no
entry, so every B60 run falls back to the heuristic.

This PR adds the missing B60 files. No code changes.

## Changes

Eight config files under
`vllm/model_executor/layers/mamba/ops/configs/selective_state_update/`, one
per `(shape, cache_dtype)` pair, across four `(headdim, dstate)` shapes:

- `headdim=64, dstate=128` — float16 and float32 (Mamba2 family, Zamba2-1.2B,
  Nemotron-H-8B, Granite-4.0-h-tiny, Falcon-H1-0.5B)
- `headdim=128, dstate=256` — float16 and float32 (Falcon-H1-3B/7B/34B)
- `headdim=64, dstate=64` — float16 and float32 (Zamba2-2.7B)
- `headdim=64, dstate=256` — float16 and float32 (Falcon-H1-1.5B(-Deep))

The first two shapes are the same ones the B70 PR shipped, so the two devices
are directly comparable; the latter two cover Zamba2 and Falcon-H1 checkpoints
the B70 PR did not exercise.

## Method

Generated on a single Intel Arc Pro B60 (23.91 GiB) with the in-tree
`benchmarks/kernels/benchmark_selective_state_update.py --save-configs`,
sweeping effective batch 8..131072, on vLLM 0.28.0 / torch 2.13.0+xpu.

### Triton version

All eight files record `"triton_version": "3.8.0"`. They were first tuned on
Triton 3.7.x, then re-checked on Triton 3.8.0 (torch 2.14.0+xpu, one B60 per
shape, tune and cross-eval in the same pod). Seven shapes keep their winners:
the shipped config is within 1.006-1.036x geomean of the best re-measured one.
`headdim=64, dstate=128, float16` moved on 3.8.0 (shipped config 1.10x geomean,
up to 1.99x slower at small batch), so that file now holds the 3.8.0 winners for
effective batch 8..32768 and keeps the 65536/131072 entries from the original
sweep. The end-to-end numbers below were measured with the Triton 3.7.x configs
and not repeated on 3.8.0.

## Results

### Numerical validation

Every shipped config (all 8 shape/cache_dtype combinations) was validated
against the fp32 reference (`--validate`) across the capped batch grid
8..2048 (9 points) — all 72 checks passed.

### Kernel speedup

Heuristic vs. tuned, `--compare`, on the first two (B70-comparable) shapes:

| shape | cache_dtype | geomean | min | max |
|---|---|---:|---:|---:|
| headdim=64, dstate=128 | float16 | 3.36x | 1.42x | 4.91x |
| headdim=64, dstate=128 | float32 | 2.68x | 1.26x | 6.38x |
| headdim=128, dstate=256 | float16 | 6.12x | 3.73x | 10.26x |
| headdim=128, dstate=256 | float32 | 3.83x | 3.05x | 7.27x |

Overall geomean **3.71x** across 54 (shape, cache_dtype, batch) entries; every
single entry improves over the heuristic.

### End-to-end

`vllm serve` + `vllm bench serve`, 512 in / 128 out, 32 prompts, paired by rep,
arms alternating base/tuned within each rep. Base is the pristine package (no
B60 file present); tuned installs the configs above.

| model | shape | base tok/s | tuned tok/s | speedup | reps won |
|---|---|---:|---:|---:|---:|
| Zyphra/Zamba2-1.2B-instruct (run 1) | 64,128 | 490.05 | 568.08 | +15.92% | 6/6 |
| Zyphra/Zamba2-1.2B-instruct (run 2) | 64,128 | 500.00 | 658.53 | +31.71% | 6/6 |
| Zyphra/Zamba2-2.7B-instruct | 64,64 | 133.47 | 136.16 | +2.02% | 6/6 |
| tiiuae/Falcon-H1-3B-Instruct | 128,256 | 296.51 | 651.06 | +119.57% | 6/6 |
| tiiuae/Falcon-H1-1.5B-Instruct | 64,256 | 504.41 | 780.34 | +54.70% | 6/6 |

All five runs are significant under a paired permutation test (p=0.0321, the
smallest a 6-pair test can report), and tuned wins every rep in every run.

## Test plan

- Regenerate with `benchmark_selective_state_update.py --save-configs` on B60
  and confirm the same winners.
- `--validate` every shipped key; a failing config is dropped, not shipped.
- Serve a Mamba2/Zamba2/Falcon-H1 model on B60 and confirm the tuned file is
  the one loaded.
- No CUDA/ROCm behaviour changes: this PR is data only.
