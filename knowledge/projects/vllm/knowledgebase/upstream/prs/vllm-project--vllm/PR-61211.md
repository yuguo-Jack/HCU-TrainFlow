# [Bugfix] Keep VLLM_RAY_BUNDLE_INDICES out of the compile cache key

[Upstream PR](https://github.com/vllm-project/vllm/pull/61211) · state: closed · merged: True

## Original PR description



## Overview

Exclude `VLLM_RAY_BUNDLE_INDICES` from `envs.compile_factors()`, so engines that differ only in which placement-group bundles they run on share a torch.compile cache key.

## Claims

- Fixes cache misses across engines and runs: with this variable hashed, every engine of a multi-engine Ray deployment that sets it per engine (e.g. RL frameworks placing one engine per GPU group of a shared placement group) compiles under its own key, and a later run reuses the cache only if each engine happens to get the same bundles again.
- No change for deployments that don't set the variable.

## Validation

Unit test (new `test_ray_bundle_indices_is_not_compile_factor`), CPU, `vllm/` from this branch on `PYTHONPATH` with dependencies from the vllm 0.31.0 wheel; `--noconftest` because `tests/conftest.py` needs the full test requirements:

```
PYTHONPATH=$PWD VLLM_TARGET_DEVICE=cpu python -m pytest -q --noconftest tests/test_envs.py
```

End to end: the identical one-line my RL runs on vLLM 0.25.1 (10 TP8 engines with `RayExecutorV2`, each with its own `VLLM_RAY_BUNDLE_INDICES`, on a multi-node GB300 job). Before it, each run wrote ~10 torch.compile cache keys (one per engine); with it, a cold run writes one key and warm runs load it (Dynamo + Inductor ~12 s -> ~2 s per engine). Not re-run end to end on `main`: the change only edits the `ignored_factors` set, and both consumers (`compilation/backends.py`, `compilation/caching.py`) still hash `envs.compile_factors()` the same way.

## Details

Root cause: `compile_factors()` hashes every known env var not in `ignored_factors`. `VLLM_RAY_BUNDLE_INDICES` only selects which bundles (GPUs) of a placement group the engine's workers use (`v1/executor/ray_executor.py`, `ray_executor_v2.py`); it has no effect on the compiled graphs. Same category as `VLLM_HOST_IP` and `VLLM_PORT`, which are already ignored.

Interaction with #42136 (envs.py to pydantic-settings): that branch keeps `ray_bundle_indices` hashed as well. If it lands first, the equivalent fix is `json_schema_extra={"compile_factor": False}` on that field; happy to rebase either way.

Not a duplicate: searched open issues/PRs for `VLLM_RAY_BUNDLE_INDICES`, `compile_factors` and `ignored_factors`; none excludes this variable. #39479 (hashing refactor follow-ups) and #42136 touch the same function but not this variable.
