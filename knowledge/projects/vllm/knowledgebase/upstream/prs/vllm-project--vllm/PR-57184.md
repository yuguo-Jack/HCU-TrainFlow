# [Prototype][MRV2] Stage DeepSeek decode tokens for imbalanced DBO graph replay

[Upstream PR](https://github.com/vllm-project/vllm/pull/57184) · state: closed · merged: False

## Original PR description

## Purpose

Related issue: #57177; RFC: #50738. Built on MRV2 FULL-graph DBO support in #51700.

During imbalanced DP decode, a rank can leave the last physical microbatch empty even though a FULL CUDA Graph was captured. The original prototype stages real tokens into the captured regions and restores logical request order before sampling. It also keeps returned routed-expert records in the correct microbatch and slot order.

This update extends that path to a synchronized active microbatch count and adjusts NIXL EP dispatch capacity and communication handoff. It remains a prototype for design review.

## Duplicate-work check

Open-PR searches for `57177 in:body` and `DBO staging` were refreshed on 2026-09-28. This updates the existing #57184; the former search found only this PR, and the latter found no other PR for the same MRV2 NIXL staging path. Open #57020 handles the empty-tail boundary by falling back to eager; this PR stages eligible real tokens to retain FULL replay. The overlapping predicate still needs reconciliation before merge.

## Changes

- Keep conditional staging, post-forward input restoration, and routed-expert record ordering. Capability gates cover FLASH_ATTN_MLA and a constrained unquantized BF16 FLASH_ATTN path with FULL/AOT metadata; they still exclude unsupported parallel layouts and auxiliary inputs.
- Let `--ubatch-size` specify a fixed count. With MRV2, NIXL EP, DP>1, `--enable-dbo`, and no fixed count, select an active count from 2 up to the configured resource limit (default 8) using synchronized DP load and captured graph layouts. Capture the corresponding variants and use the selected count for slices, threads, workspace, and shared-expert state.
- Keep DeepEP at two microbatches; reject larger counts for backends with only two handle slots.
- Use synchronized padded execution metadata, with NIXL receive-extent alignment, for runtime dispatch capacity. Keep the static scheduler budget as a reservation limit. Match batched expert output views to the runtime shape.
- Hand NIXL DBO dispatch/combine between communication and compute streams and preserve receive data ownership when more than two microbatches overlap.

More capture variants and receive snapshots can increase startup work and memory use. These changes do not establish a throughput gain.

Thank @algebra-MCX for the optimization, which leads to a significant throughput increase.
To conclude my review, the staging can be generalized (odd graph sizes, more than two microbatches)

The `% 2 == 0` and `num_ubatches == 2` restrictions come from hard-coding `capacity = N // 2` and two equal halves. The captured graph is already split by `create_ubatch_slices` (`sp = N // k`, the last region takes the remainder), so staging can reuse those slices:

- Spread the `n` single-token requests evenly: `counts = [n // k + (i < n % k) for i in range(k)]`. Each count is `<= ceil(n / k) <= sp`, so it always fits.
- Stage with one scatter per buffer instead of copy/zero/fill loops. This stays correct if source and destination overlap (possible with `k > 2`):

  ```python
  staged = torch.zeros_like(buf[:num_padded])
  staged[dst] = buf[:n]
  buf[:num_padded].copy_(staged)
  ```

  Slot mappings do the same with `-1` fill, and `is_padding[dst] = False`.
- Restoring the output order becomes one line, replacing `compact_conditional_output` (whose `capacity: int = 64` default looks like a leftover):

  ```python
  model_output[: staged_rows.numel()] = model_output[staged_rows]
  ```
- The DP gate generalizes to "some rank's last microbatch would be empty":

  ```python
  min_tokens = int(num_tokens_across_dp.min())
  if min_tokens <= ubatch_desc.num_tokens // num_ubatches * (num_ubatches - 1):
      runner = cudagraph_manager.ubatch_runner
      if not (
          ubatch_desc.cg_mode == CUDAGraphMode.FULL
          and runner is not None
          and runner.stage_real_tokens
          and synced_uniform_token_count == 1
          and min_tokens >= num_ubatches
      ):
          ubatch_desc = None
  ```

  For `k = 2` this is exactly the current `2 * min <= N`, including odd `N`.
- In `prepare()`, stage when `input_batch.num_tokens <= ubatch_slices[-1].token_slice.start`, and rebuild each microbatch's `query_start_loc` / `seq_lens` with its own region size instead of a shared `capacity`.

File: `vllm/v1/worker/gpu/dp_utils.py` · line None

 `can_stage` has several redundant conditions

Five of the ten conditions in `dp_utils.py` are implied by others:

- `num_ubatches == 2` — already part of `conditional_real_split`.
- `torch.all(num_reqs_across_dp == num_tokens_across_dp)` — implied by `synced_uniform_token_count == 1` (every rank reported a uniform query length of 1).
- `ubatch_desc.num_reqs == ubatch_desc.num_tokens` — a FULL microbatched descriptor only comes from `_maybe_ubatch_twin`, whose `uniform_token_count = num_tokens //
num_reqs` must match the synced count of 1.
- `ubatch_desc.num_tokens >= 4` — implied by `min >= 2` and `2 * min <= num_tokens`.
- `runner is not None` + `getattr(...)` — a FULL microbatched descriptor only exists when `ubatch_runner` is set; `runner` is typed, so `getattr` is only there for the `SimpleNamespace` in the test.

The same eligibility rules are also repeated in `prepare()` and in the asserts of `stage_conditional_decode`. `prepare()` doesn't need its own copy: if the DP sync picked FULL and this rank's last microbatch is empty, the DP-level staging check must already have passed.
