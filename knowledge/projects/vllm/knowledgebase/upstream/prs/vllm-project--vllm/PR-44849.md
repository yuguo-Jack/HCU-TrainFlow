# [ROCm][MiniMax-M2] Dispatch fused QK-norm + AllReduce via AITER

[Upstream PR](https://github.com/vllm-project/vllm/pull/44849) · state: closed · merged: True

## Original PR description

⚠️ **Requires:** AITER build containing ROCm/aiter#3163 (Optionally ROCm/aiter#3189 for additional performance)

Co-developed with @pbkowalski who wrote the initial dispatch re-wiring 

Adds ROCm dispatch for MiniMax-M2's QK-norm custom op to use AITER's fused kernel (`custom_fused_qknorm_ar` from ROCm/aiter#3163 + aiter#3189 further pushes the perf)

Supersedes #42602 (closed as that used a compile-time FX pass which has now been removed upstream)



## Change summary

Single file: `rms_norm_tp.py`
- Probe AITER for `custom_fused_qknorm_ar` at first call (cached)
- Gate on `rocm_aiter_ops.is_enabled()` + dimension alignment check
- Fallback with `warning_once` if the kernel errors at runtime
- CUDA path untouched; TP=1 and batches >2048 tokens fall through as before

## Test result on MI355X, TP=4

Baseline vs fused, 96 prompts (ISL=1000, OSL=100), concurrency 16

| Metric | Baseline | Fused | Δ |
|---|---|---|---|
| Output tok/s | 982 | 1126 | **+14.7%** |
| Median TPOT | 12.61 ms | 10.54 ms | **−16.4%** |

Larger uplift vs #42602 because ROCm/aiter#3189 removed the 80-token cap, so the fused path now covers all captured batch sizes 🎉
