# [Bugfix][Frontend] Reject apply_softmax=false in /generative_scoring under --logprobs-mode *_logits

[Upstream PR](https://github.com/vllm-project/vllm/pull/64468) · state: open · merged: False

## Original PR description

## Overview

In `ServingGenerativeScoring` (`POST /generative_scoring`), setting `apply_softmax=false` computes `{token_id: math.exp(logprob) ...}` under the assumption that `read.logprobs` holds normalized log-probabilities (`log(softmax(logits))`). When the server runs with `--logprobs-mode raw_logits` or `processed_logits`, `read.logprobs` contains unnormalized logits `z_t`, so the endpoint returns HTTP 200 with `exp(z_t) = Z * p_t` (for example `18205689644.4261` instead of `0.808466` (`raw_logprobs`) / `0.808465` (exact softmax) on `Qwen/Qwen3-0.6B`, or `20629749057.596176` instead of `0.809585` with `--enforce-eager`) as a probability score.

**Duplicate check (`AGENTS.md`):** Searched open and closed issues and PRs for `generative_scoring` with `logprobs_mode`, `raw_logits`, and `apply_softmax`. No existing issue or PR addresses this (note: open PR `#46427` adds a Rust frontend generative-scoring route with the same `exp()` pattern and would need the same mode check if merged; open PR `#63625` touches unrelated hunks of `serving.py` and `generative_scoring.md` with no conflict).

**AI assistance disclosure:** AI assistance (Antigravity / Gemini) was used during the investigation, test authoring, and preparation of this PR.

## Claims

- Rejects `apply_softmax=false` in `ServingGenerativeScoring.create_generative_scoring` with an HTTP 400 `BadRequestError` when `self.model_config.logprobs_mode` is not in `("raw_logprobs", "processed_logprobs")`, matching the logprobs-mode guard in `/v1/decisions` (`vllm/entrypoints/openai/decisions/strategies.py:1462-1487`).
- Leaves `apply_softmax=true` (the default subset softmax over `label_token_ids`) enabled in all `--logprobs-mode` settings, since `softmax(z_L)` is shift-invariant and equals `softmax(log_softmax(z)_L)`, and leaves the logprobs modes (`raw_logprobs`, the default, and `processed_logprobs`) behavior and scores unchanged.
- Documents the `--logprobs-mode` requirement for `apply_softmax=false` in `docs/serving/online_serving/generative_scoring.md`.

## Validation

Standalone reproducer against `vllm serve Qwen/Qwen3-0.6B --logprobs-mode raw_logits`:

```python
import requests

resp = requests.post(
    "http://localhost:8000/generative_scoring",
    json={
        "query": "Answer the question with Yes or No.\nQuestion: ",
        "items": ["Is Paris the capital of France?\nAnswer:"],
        "label_token_ids": [7414, 2308],
        "apply_softmax": False,
    },
)
print(resp.status_code, resp.json())
```

- **Before:** HTTP `200` with `'score': 18205689644.4261` (`math.exp(23.625)` on the default compiled server, or `20629749057.596176 = math.exp(23.75)` with `--enforce-eager`, instead of a probability in `[0, 1]`).
- **After:** HTTP `400` with `{'error': {'message': 'apply_softmax=false requires --logprobs-mode raw_logprobs or processed_logprobs, got raw_logits.', 'type': 'BadRequestError', 'param': None, 'code': 400}}` (while `apply_softmax=true` continues to return HTTP `200` with `'score': 0.8175744761936437`).

Tests run and results:
- `pytest tests/entrypoints/generate/generative_scoring/test_generative_scoring.py`: **18 passed** (14 existing + 4 new parametrized cases in `TestValidation::test_apply_softmax_false_needs_logprobs_mode`; the `raw_logits` and `processed_logits` cases fail without the fix).
- `pytest tests/entrypoints/generate/generative_scoring/test_generative_scoring_logits_mode.py`: **2 passed** (`apply_softmax=True` returns 200 in `[0, 1]`, `apply_softmax=False` returns 400; fails without the fix with HTTP 200 and `score=2549.7484851158824`).
- `pytest tests/entrypoints/generate/generative_scoring/test_generative_scoring_e2e.py tests/entrypoints/generate/structured_decisions/test_strategies.py::test_strategy_selection tests/v1/sample/test_logprobs.py::test_logprobs_mode`: **11 passed**.

## Details

`next_token_label_reads` (`vllm/entrypoints/generate/label_reads.py:80`) reads `output.logprobs[0][t].logprob` from the sampler output. Since PR `#43125` (V1 sampler) and PR `#47680` (V2 sampler), that field carries raw or processed logits when `--logprobs-mode` is `raw_logits` or `processed_logits`. Full-vocabulary probabilities (`apply_softmax=false`) cannot be recovered from only the gathered subset of unnormalized logits without the full-vocabulary log-partition function `log(sum_j exp(z_j))`, so `apply_softmax=false` requires a logprobs mode.
