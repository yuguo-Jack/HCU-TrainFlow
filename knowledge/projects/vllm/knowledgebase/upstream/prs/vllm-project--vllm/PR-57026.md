## Original PR description

## Summary

- raise the MTP sharded-sampling cross-boot divergence allowance from 2 to 3 of 20 prompts
- align the spec-decode check with the general sharded-sampling test's measured allowance of 3
- update the docstring so it no longer promises bit-exact output while the assertion deliberately permits measured near-tie noise

## Why

The exact `seeded: 3/20 prompts diverged` boundary has opened and later resolved the same L4 alert repeatedly on main, including builds #88182, #88430, #88630, #88968, #89028, and now #89107. The triggering merges touched unrelated paths; #89107 is PR #56387's DSpark EPLB fix, while this test uses Qwen3.5 MTP TP=2. In the latest job, the other five commands passed 40 tests and only this one-prompt-over-bound assertion failed.

A real request-routing or gather bug produces wholesale divergence. Keeping a small named bound of 3 still catches that signal while covering the measured boot-to-boot near-tie tail already accepted by the non-spec sharded-sampling test.
