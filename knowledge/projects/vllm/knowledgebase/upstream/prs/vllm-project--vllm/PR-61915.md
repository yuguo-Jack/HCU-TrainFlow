# fix(models): reject LoRA on Jamba with descriptive ValueError (#61853)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61915) · state: open · merged: False

## Original PR description

## Summary

Rejects `enable_lora=True` at model initialization for Jamba with a descriptive `ValueError` before launching worker initialization or profiling forward passes.

## Motivation & Context
Jamba (`JambaForCausalLM`) is an SSM/hybrid architecture that does not implement `SupportsLoRA`, nor does it have LoRA adapter implementations for its Mamba/MoE projection layers. When `enable_lora=True` was passed, `JambaModel` previously accepted the configuration and forwarded `is_lora_enabled=True` to `MambaMixer`. During the worker profiling forward pass, unaligned/non-contiguous tensor operations in the unadapted Mamba mixer triggered a CUDA illegal memory access (`torch.AcceleratorError`) and a fatal process abort (`terminate called after throwing an instance of 'c10::AcceleratorError'`).

This patch checks `vllm_config.lora_config` at the start of `JambaModel.__init__` and raises `ValueError("enable_lora=True is not supported for Jamba.")`, matching the explicit rejection pattern used in Mamba2 and Zamba2. Includes CPU-side unit test verification.

Fixes #61853
