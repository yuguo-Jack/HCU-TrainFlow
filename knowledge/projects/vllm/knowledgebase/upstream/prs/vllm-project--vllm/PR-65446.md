# [torch.compile] Only flag `_buffers.update` in the cudagraph buffer assignment check

[Upstream PR](https://github.com/vllm-project/vllm/pull/65446) · state: open · merged: False

## Original PR description

## Overview

The cudagraph "Assigning / modifying buffers" check from #11596 raises on any `update` in Dynamo's residual bytecode, so it also rejects unrelated dict updates. This PR only flags `<module>._buffers.update`, which is what Dynamo emits for a buffer assigned during forward.

## Claims

- Transformers backend models whose config sets `is_causal` (e.g. Ettin / ModernBERT decoder) compile with cudagraphs again: Transformers' `is_causal` handling leaves `kwargs.update({'is_causal': ...})` in the residual bytecode.
- Buffer assignment during forward is still rejected.
- Needed by #61276, whose Ettin test hits this.

## Validation

`tests/compile/test_wrapper.py::test_cudagraph_buffer_assignment_check` covers both cases on CPU; the kwargs case fails without the fix.

```bash
pytest tests/compile/test_wrapper.py
pytest tests/models/transformers/test_backend.py::test_output_head_transform  # with #61276
```

Tests: `test_wrapper.py` passes (CPU and B200); with #61276, Ettin `test_output_head_transform` goes from failing to passing and all 58 `test_backend.py` tests pass on B200.
