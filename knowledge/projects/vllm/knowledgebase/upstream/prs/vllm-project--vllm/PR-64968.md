## Overview

Implement the complete integration and acceptance scope of
[issue #64907](https://github.com/vllm-project/vllm/issues/64907) in this PR:
batch-invariant Qwen GDN execution, MTP speculative decoding and prefix caching
must coexist. For a fixed checkpoint, tokenizer, MTP depth and decoding
configuration, the same request must return identical text, token IDs,
complete returned top-5 logprob objects and finish reason when run alone or
under heterogeneous concurrent traffic, including prefix-cache reuse.

All remaining implementation and regression work belongs to this PR and will
be added to its existing branch. Its final scope is the full #64907 integration.
Related: #42960; builds on shared-recurrence work in #60033 and normalization
policy in #57280.

## Full #64907 acceptance checklist

Unchecked items remain requirements of this PR. An item is complete only when
both its implementation and current-head validation evidence are available.

- [ ] **Combined execution:** BI + MTP + prefix cache together on the documented
  Qwen GDN configuration, using MRV2 and async scheduling. Validate public
  checkpoint/tokenizer revisions and MTP1/2/3/4, with MTP0 as the control.
- [ ] **Complete response equality:** compare text, token IDs, every entry and
  field in the returned top-5 logprob object, and finish reason with zero
  floating-point tolerance. Selected-token logprobs alone are insufficient.
- [ ] **Cache and batch matrix:** cold reference, warm reuse, reset/cold repeat,
  cold-mixed and warm-mixed B2/B4/B8 traffic, target first/last and changing
  request rows. Include boundary ±1, double-boundary ±1, the 2,442-token case
  and lengths adapted to the actual cache grid; confirm real cache hits.
- [ ] **Persistent-state precision and replay:** exact BF16 and FP32 conv/SSM
  state replay across prefill partitions, decode and speculative verification,
  with independent component regressions.
- [ ] **Checkpoint export/reload:** export actual prefix-checkpoint conv and
  recurrent state, reload it, and compare the resumed state and output suffix
  against uninterrupted execution.
- [ ] **Acceptance/rejection recovery:** integrated tests that exercise both
  accepted and rejected drafts and check the recovered conv/SSM state and
  complete response; validate async accepted-count ownership as request rows
  change.
- [ ] **Preemption and scheduling:** force and observe preemption/resume and
  request-row changes under heterogeneous and CPU-limited workloads, then
  verify exact responses and state recovery.
- [ ] **Long output and top-p boundaries:** exact long-output comparisons,
  stable top-p filtering at tied/boundary logits, and authorized real tensor
  fixtures for top-p and gated-normalization replay.
- [ ] **Upstream regression and evaluation:** run determinism/component/E2E
  regressions, model-quality evaluation and ordinary-mode compatibility checks
  on the final head; retain commands and raw before/after evidence.
- [ ] **Serving performance:** run `vllm bench serve` with BI and prefix cache
  enabled in both MTP0 and MTP-enabled configurations, preserve raw responses
  and counters, report variability and TTFT/TPOT tradeoffs, and investigate
  ordinary-mode performance uncertainty.
- [ ] **Reproduction and submission:** publish portable reproducers, source
  manifests and shareable evidence with pinned base/head/model/tokenizer,
  rendered documentation and final human review.

Cross-depth/MTP-disabled losslessness and sampling-distribution equivalence
must be investigated and reported separately from fixed-depth batch invariance,
as #64907 specifies. CUDA graphs, multi-GPU and multimodal execution are
separate extensions beyond that issue's text/eager/TP1 acceptance configuration.
Historical experimental 27B results do not establish current-head coverage;
any model added to the final matrix needs verifiable public provenance.

## Prior integration validation (`0f229513`)

- With BI enabled, token IDs and selected-token logprobs match exactly across
  batch composition, ordering, queueing, and cold/warm prefix-cache conditions
  at each tested MTP depth: 0/1/2/3.
- Greedy outputs and selected logprobs also match across those MTP depths.
  Fixed-seed sampling is tested at each depth; this does not claim universal
  sampled sequence equality between different speculative depths.
- Full five-shot GSM8K has no observed aggregate accuracy drop in this run:
  0.8B is unchanged, 2B gains one correct answer, and 9B gains two. These small
  changes are not evidence of a statistically established accuracy improvement
  or broad quality equivalence.
- On the evaluated offline GSM8K generation workload, BI + MTP3 is
  2.04/2.98/3.07 times as fast as BI without MTP for 0.8B/2B/9B, with identical
  generated token digests.
- In the 9B greedy short-output HTTP comparison, BI + MTP3 delivers
  1.786× the throughput of BI MTP0, with identical decoded response texts.
  This is a workload-specific result; TTFT increases and default random
  sampling does not show the same benefit.

### Serving with BI enabled

The primary performance baseline is BI enabled with MTP disabled (MTP0).
The 9B greedy comparison uses `temperature=0`, request `seed=42`, random
1,024-input/32-forced-output requests and concurrency 64. Each BI configuration
has one fresh server load, one discarded full 128-request warmup and two
measured 128-request rounds: 512 measured requests, all completed.

| Configuration | Output token/s median [two runs] | vs BI MTP0 | Mean-TTFT median ms | Mean-TPOT median ms |
| --- | ---: | ---: | ---: | ---: |
| BI MTP0 | 129.56 [128.38, 130.74] | 1.000× | 3,188.05 | 380.54 |
| BI MTP3 | 231.41 [219.79, 243.03] | **1.786×** | 5,074.79 | 83.87 |

Throughput increases 78.6% and TPOT decreases 78.0%, while TTFT increases
59.2%. Draft-token acceptance is 67.80% in both MTP3 rounds. Decoded response
texts match across BI MTP0/MTP3; the HTTP benchmark does not retain token IDs
or selected logprobs, so this does not replace the exact consistency matrix.
Raw Prometheus before/after deltas match the benchmark counters, and all
request/token counts and per-position acceptance formulas pass.

To meet the requested runtime budget, these BI configurations run on different
H100 GPUs in two phases of a parallel two-GPU schedule. Each has only one
independent load and two resident-server measurements; host contention, GPU
mapping and phase order remain limitations. This is not a balanced crossover
experiment or a statistical performance guarantee.

Reproduce each mode using the documented server configuration, the same
scheduling budget and an explicit request sampling mode:

```bash
export MODEL=Qwen/Qwen3.5-9B
VLLM_BATCH_INVARIANT=1 VLLM_USE_V2_MODEL_RUNNER=1 \
VLLM_USE_BREAKABLE_CUDAGRAPH=0 \
vllm serve "$MODEL" \
  --revision c202236235762e1c871ad0ccb60c8ee5ba337b9a \
  --dtype bfloat16 --enforce-eager --tensor-parallel-size 1 \
  --max-model-len 4096 --max-num-seqs 64 --max-num-batched-tokens 2048 \
  --gpu-memory-utilization 0.65 --enable-chunked-prefill \
  --no-enable-prefix-caching --limit-mm-per-prompt '{"image":0,"video":0}' \
  --attention-config '{"backend":"FLASH_ATTN"}' \
  --additional-config '{"gdn_prefill_backend":"triton"}' \
  --speculative-config '{"method":"mtp","num_speculative_tokens":3}'
```

Run the client in another shell with the same `MODEL` value:

```bash
vllm bench serve --backend vllm --base-url http://127.0.0.1:8000 \
  --model "$MODEL" --dataset-name random \
  --random-input-len 1024 --random-output-len 32 --random-range-ratio 0 \
  --num-prompts 128 --max-concurrency 64 --num-warmups 0 --ignore-eos \
  --seed 42 --temperature 0 --extra-body '{"seed":42}' \
  --save-result --save-detailed
```

Run a discarded full-work round before the two measured rounds.
Keep BI enabled in both servers; omit `--speculative-config` for MTP0 and use
`{"method":"mtp","num_speculative_tokens":3}` for MTP3. Both use eager MRV2,
64 active slots, 2,048 batched tokens, context 4,096 and prefix cache disabled.

Historical default-sampling results:

The earlier suite completed 54 equal-work HTTP benchmark runs: 128 requests per run,
1,024 input/32 forced output tokens, concurrency 64, 16 warmups.
Three consecutive trials reuse each server and configuration order is fixed;
these are not independent fresh-server repetitions.

| Model | BI MTP0 output token/s median | BI MTP3 output token/s median | MTP3 vs BI0 |
| --- | ---: | ---: | ---: |
| 0.8B-Base | 167.46 | 128.40 | −23.32% |
| 2B | 174.54 | 145.49 | −16.65% |
| 9B | 132.67 | 63.56 | −52.09% |

Those commands omitted temperature and used server-default `temperature=1`,
`top_p=1`, with no request sampling seed. CLI `--seed=42` fixes the corpus
only. These results show no MTP throughput benefit under that sampling mode;
they do not describe greedy serving. Per-request recurrent execution carries
substantial BI costs, and the feature remains opt-in. Offline generation
timings do not substitute for an HTTP benchmark.

### Ordinary-mode compatibility

With BI disabled, serial/cold/reverse before/after comparisons match exactly.
Warm ordinary-mode differences are fully reproduced by the unmodified base;
both versions produce the same two complete output variants. Controlled
all-request admission restores exact before/after outputs and scheduler
traces. Ordinary mode is not required to acquire BI guarantees.

A separate ordinary-mode 0.8B guard completed 12 equal-work runs, using two
fresh server pairs, swapped GPU mappings, a discarded equal-work warmup round
per server and alternating version order. All requests completed, but the
two GPU mappings disagree on the throughput effect. These measurements do
not establish performance equivalence or rule out an ordinary-mode regression.
That question remains open; this PR does not claim zero serving impact.

## Details

Use one per-request convolution and sigmoid-gated recurrence for prefill,
decode and speculative verification, passing accepted lengths through the
existing state interfaces. CPU query offsets define local request boundaries;
the inference path does not read GPU offsets back to the host.

#60033 shares non-speculative recurrent arithmetic and explicitly excludes
speculative decoding; this increment targets MRV2 and accepted-length MTP
state recovery. #57280 overlaps normalization policy and must be attributed.
#45819 retains separate chunked-prefill/recurrent-decode arithmetic; #55868
changes the prefix-cache grid and scheduler alignment. This contribution
does not transplant those scheduler changes. Backend naming and dependency
overlap remain maintainer review points. This does not close the full
MoE/A100 scope of #42960.

Validated scope: dense Qwen3.5 0.8B-Base/2B/9B, SM90, TP1, BF16,
FP32 recurrent state, eager MRV2. CUDA graphs, other devices, TP>1, MoE and
Qwen4Exp are outside the validation scope. Per-request launches and recurrent
prefill carry substantial throughput costs.

AI assistance was used for implementation, testing and preparation. The
submitting human must review every changed line, run relevant tests and confirm
DCO before publication. Raw model revisions, run manifests, counters and logs
are prepared locally for attachment; they are not yet publicly uploaded.
