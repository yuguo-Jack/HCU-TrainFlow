# [Bugfix][Worker] Track CUDA graph memory in CuMemAllocator to fix sle…

[Upstream PR](https://github.com/vllm-project/vllm/pull/47700) · state: open · merged: False

## Original PR description


This PR fixes the GPU HBM memory leak during `sleep-mode` when running multimodal models loaded with `--mm-encoder-tp-mode data` (Issue #47654).

## Purpose

When running sleep-mode transitions, vLLM offloads/remaps tracked memory blocks. However, during model warming and capture, both decoder and encoder CUDA graphs (the latter of which contains static input/output buffers for the vision encoder in DP mode) are captured outside of any active memory pool context. As a result, the memory allocated for these graphs is not registered in the allocator's tracker (`pointer_to_data`), causing them to leak on sleep and block multi-container sleep-swap.

This PR implements a `reuse_memory_pool` context manager for the allocator and wraps the persistent CUDA graph capture logic in `capture_model()` with the `"weights"` memory pool so that the allocations are tracked, offloaded, and remapped correctly during sleep/wake cycles.

Closes #47654

### Changes
*   **vllm/device_allocator/__init__.py**: Added `reuse_memory_pool` signature to `MemAllocator` protocol.
*   **vllm/device_allocator/cumem.py**: Implemented `reuse_memory_pool` context manager for `CuMemAllocator`.
*   **vllm/device_allocator/xpumem.py**: Implemented `reuse_memory_pool` context manager for `XpuMemAllocator`.
*   **vllm/v1/worker/gpu_model_runner.py**: Implemented `_maybe_reuse_memory_pool_context` helper and wrapped the CUDA graph capture block in `capture_model` to reuse the `"weights"` memory pool.
