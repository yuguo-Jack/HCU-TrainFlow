# [MoE] Add platform construction hooks for fused MoE components

[Upstream PR](https://github.com/vllm-project/vllm/pull/51006) · state: open · merged: False

## Original PR description

## Overview

Add three construction-time Platform hooks so out-of-tree backends can adapt fused MoE routers, routed experts, and runners without replacing `FusedMoEFactory`. Default platform behavior and upstream selection priority stay unchanged.

Related: #51005. This updates the existing PR; the open-PR duplicate checks found no other implementation of these construction hooks. EPLB lifecycle and transfer hooks remain separate in #49700.

## Claims

- Adapt the class already selected by the factory or model, including explicit model-specific expert loaders and runners.
- Accept compatible sibling router constructors and validate all returned components against their common contracts.
- Add no platform lookup, synchronization, or state management to the forward path. Explicitly supplied router instances remain directly usable.

## Details

The platform receives the selected class at its construction boundary. Expert and runner adaptation happens after model-specific and expert-substitution selection. Router adaptation happens at each existing construction site, including the simulator wrapper after the real router has supplied its kernel routing method. Default implementations return the selected class. The platform remains responsible for preserving model loading and routing semantics.
