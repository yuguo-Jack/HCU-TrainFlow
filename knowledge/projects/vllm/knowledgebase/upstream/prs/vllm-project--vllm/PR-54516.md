# [Bugfix][Model] Cap Voxtral Realtime transcription at audio boundary

[Upstream PR](https://github.com/vllm-project/vllm/pull/54516) · state: open · merged: False

## Original PR description

## Purpose

fix #52926.

Voxtral Realtime requires decoding positions to stay aligned with audio embedding positions. At each position, the model may generate a text token, a blank token (ID 32), or EOS. For some audio inputs, the model does not generate EOS before the available audio embeddings are exhausted.

Previously, offline `/v1/audio/transcriptions` used the generic request or model context length as the generation limit. As a result, decoding could continue after the audio embeddings had already been exhausted. At that point, there is no corresponding multimodal embedding for the current token position, so Voxtral Realtime falls back to a zero embedding and may continue generating blank tokens until EOS is produced or the generic length limit is reached.

I reproduced the same flood of empty-multimodal-embedding warnings and a significant increase in request latency, but I did not reproduce the issue where the entire service permanently stops responding.

This PR:

* Adds an optional model-level generation length hook for speech-to-text serving.
  ```python
  def get_speech_to_text_max_tokens(cls, engine_input: EngineInput) -> int:
    assert engine_input["type"] == "multimodal"

    audio_placeholders = engine_input["mm_placeholders"].get("audio", [])
    assert len(audio_placeholders) == 1, (
        "Voxtral realtime transcription requires exactly one audio input"
    )

    audio_placeholder = audio_placeholders[0]

    max_tokens = (
        audio_placeholder.offset
        + audio_placeholder.length
        - len(engine_input["prompt_token_ids"])
    )
    if max_tokens < 1:
        raise ValueError("Audio is too short for the transcription prompt")

    return max_tokens
  ```
* Computes the generation boundary in `VoxtralRealtimeGeneration` from the rendered audio placeholder:
  ```python
  audio_end = audio_placeholder.offset + audio_placeholder.length
  max_tokens = audio_end - len(prompt_token_ids)
  ```

* Uses the smaller of the existing request/model limit and the audio-derived limit.
* Adds a real-model GPU regression test that ignores EOS and forces generation to the configured length limit, verifying that the final generated token lands exactly on the last valid audio-aligned position.

Models that do not implement this hook retain the existing behavior. The limit is applied only to offline speech-to-text serving and does not modify the `/v1/realtime` streaming path.

This fix does not change the public API, so no documentation update is required.

Duplicate-work check: I searched open PRs using `#52926` and Voxtral transcription/audio-embedding related keywords and did not find another PR addressing the same issue.

Using the same 16-second audio input, the transcription text was identical before and after the change.

**Before fix:**

```text
{"text":" First words I spoke in the original phonograph. A little piece of practical poetry. Mary had a little lamb, it sleeps with quite a flow, and everywhere that Mary went, the lamb was sure to go.","usage":{"type":"duration","seconds":16}}

```

**After fix:**

```text
{"text":" First words I spoke in the original phonograph. A little piece of practical poetry. Mary had a little lamb, it sleeps with quite a flow, and everywhere that Mary went, the lamb was sure to go.","usage":{"type":"duration","seconds":16}}
HTTP=200 TIME=1.368523s
```

| Version | HTTP status | Request latency | empty-embedding warnings observed in server logs |
| ------- | ----------: | --------------: | -----------------------------------------------: |
| Before fix  |         200 |         55.36 s |                                             7,944 |
| After fix   |         200 |          1.37 s |                                                 2 |

The 2 warnings observed after the fix are emitted during V2 Model Runner startup kernel warmup. The dummy warmup request contains no real audio, so these warnings do not come from the actual transcription request. No empty-embedding warnings are emitted while processing the real audio request.

The latency difference comes from eliminating thousands of unnecessary autoregressive decode steps, not from a general model or kernel performance improvement.

Before this change, the request effectively used the generic `max_model_len=8192` as its primary generation budget. When the model did not produce EOS before the audio embeddings ended, decoding continued past the audio placeholder boundary. Each subsequently generated blank token still required another serial model forward pass, using the zero-embedding fallback.

The 7,944 warnings observed before the change roughly correspond to thousands of out-of-range decode steps. Writing the warning logs also adds some I/O overhead, but the main performance cost comes from the GPU continuing to execute unnecessary autoregressive decoding.

After this change, the generation length is bounded by the embeddings actually provided by the current audio input. The model can still stop early by generating EOS. If it does not generate EOS, decoding stops at the last valid audio-aligned position instead of entering out-of-range decoding with zero embeddings. In this reproduction, request latency decreased from 55.36 seconds to 1.37 seconds while producing the same transcription output.

These timings are specific to this input and test environment and should not be interpreted as a general performance benchmark.

## Update
- Added `get_speech_to_text_max_tokens()` to `SupportsTranscription`, returning `None` by default for compatibility with existing transcription models.
``` python
  @classmethod
  def get_speech_to_text_max_tokens(
      cls,
      engine_input: "EngineInput",
  ) -> int | None:
      """
      Return a model-specific generation limit for transcription.
      A return value of ``None`` applies no additional limit.
      """
      return None
```
- The serving layer now calls the interface directly and passes the result to `get_max_tokens()` as `override_max_tokens`.
``` python
  model_max_tokens = self.model_cls.get_speech_to_text_max_tokens(
      engine_inputs[0]
  )
  max_tokens = get_max_tokens(
      max_model_len,
      request.max_completion_tokens,
      input_len,
      self.default_sampling_params,
      override_max_tokens=model_max_tokens,
  )
```
- Updated the affected test stubs to implement the new interface.
