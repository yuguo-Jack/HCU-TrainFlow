# [Bug][KV Offload] Fix OffloadKey metadata loss and race condition from delayed BlockStored events (#63037)

[Upstream PR](https://github.com/vllm-project/vllm/pull/63129) · state: open · merged: False

## Original PR description

### Summary of Changes
This PR fixes a race condition in `OffloadingEventsTracker` where reusing a content-addressed `OffloadKey` after cache eviction could cause an older removal or delayed asynchronous store to corrupt or wipe out metadata for newer generations.

- **Generation-Aware Lifecycle Tracking**: Introduced a generation/versioning structure within `_OffloadEventMetadata` via a specialized dictionary subclass (`_PendingEventMetadataMap`) to manage overlapping lifecycle transitions for the same key.
- **Decoupled Store & Removal Matching**: Isolated primary and secondary tier residencies (`Medium.CPU`, `Medium.STORAGE`) so that in-flight store generations are no longer prematurely depleted or removed by stale `BlockRemoved` events.
- **Preventing Empty Placeholders**: Ensured delayed or in-flight async `BlockStored` events retain their complete block hashes, token IDs, and block size instead of falling back to empty placeholders (`block_size=0`).

### Testing & Verification
- Added comprehensive regression unit tests in `tests/v1/kv_connector/unit/offloading_connector/test_events.py` covering:
  - Minimal event ordering for reused keys with delayed stores after eviction.
  - Same-batch evictions and stores.
  - Overlapping in-flight concurrent stores.
- Verified all 32 tests pass cleanly and local pre-commit checks pass successfully.
