# [Model][DSv4.1][Engram] Share host tables across independent instances

[Upstream PR](https://github.com/vllm-project/vllm/pull/64082) · state: open · merged: False

## Original PR description

## Overview

Add opt-in sharing of DeepSeek-V4.1-Flash's immutable Engram tables across independently launched vLLM instances. One CUDA HOST_NUMA owner exports FABRIC handles; P and D import read-only GPU views and use the existing Engram gather. P/D KV transfer remains on its own connector. Implements the storage seam in [RFC #64002](https://github.com/vllm-project/vllm/issues/64002).

## Summary

```text
ASIS
P TP2 instance --> host Engram tables A (188.833 GiB)
D TP2 instance --> host Engram tables B (188.833 GiB)
```

```text
PR
one persistent owner --> P TP2: imported read-only GPU views --> Engram gather
(188.833 GiB)        +-> D TP2: imported read-only GPU views --> Engram gather
```

The measured table extent for two instances changes from 377.666 to 188.833 GiB, saving one complete table backing. This is table capacity, not total RSS, page cache or HBM.

## Claims

- Workers validate an immutable generation, checkpoint config/index hashes, FP8/E8M0 layout and table extent before importing FABRIC handles. The owner retains backing until every mapping detaches; a lost control connection becomes an uncertain lease.
- Consumers skip the two large table tensors before safetensors `get_tensor`, including mixed shards, while loading the smaller weights normally. In-place reload and weight transfer reject external Engram because a new checkpoint needs a new owner generation.
- The [runnable owner/P/D example](https://github.com/foraxe/vllm/tree/e50524f1ecaea17028a7ec82e9d8e5e0ba4498ea/examples/disaggregated/shared_engram) and [SGLang consumer example](https://github.com/foraxe/sglang/tree/cf1b37ee058b96611faee9a3879e5ee7f1baebe5/examples/engram_shared) use the same owner protocol. Each engine keeps its own KV-transfer path.

## Details

- This differs from merged #62359, which shares HOST_NUMA cuMem inside one DP group: this PR gives an owner an independent lifetime and lets separate DP1 P and D instances attach. #57023 uses Mooncake ranged reads into local buffers; here the Engram kernel reads the mapped owner backing directly.
- Usage, trust boundary, generation handoff and PID-only shutdown are in [the feature guide](https://github.com/foraxe/vllm/blob/e50524f1ecaea17028a7ec82e9d8e5e0ba4498ea/docs/features/engram_shared_host.md). The TCP control channel is unencrypted and requires a trusted network and private token file. The owner must not free an uncertain lease until the consumer GPU context is known gone.
- Only one four-GPU GB200 host was available. Cross-host NVL72/IMEX import, remote Grace read latency, active-graph owner failure, image-bearing requests and production SLOs remain unqualified. The [two-host gate](https://github.com/foraxe/vllm/blob/0c5abb0959234d4fd6c9e306542ddc393facc65c/evidence/shared_engram_nvl72/TWO_HOST_VALIDATION.md) is ready when a second host is available.
- AI assistance was used for source analysis, implementation, testing and this description. Human submitter line review and upstream model CI remain before merge.
