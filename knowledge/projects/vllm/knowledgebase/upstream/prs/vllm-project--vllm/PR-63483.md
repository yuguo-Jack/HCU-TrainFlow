# [Core][DBO] Dual batch overlap under pure tensor parallelism (split PR of M3.1)

[Upstream PR](https://github.com/vllm-project/vllm/pull/63483) · state: open · merged: False

## Original PR description



## Overview

**Split PR of M3.1 (#63232; the model itself landed in main as #64111):** the engine part of its ROCm work, dual batch overlap under pure TP, split out to be reviewed and merged on its own.

Dual batch overlap for pure tensor parallelism (one DP rank, no EP) on Model Runner V2: each microbatch's TP all-reduces run on the comm stream while the other microbatch computes.

Related: #44677 (same goal on Model Runner V1, see Details), #63373 (removes Model Runner V1).

## Claims

- `--enable-dbo` with `--tensor-parallel-size N` (N > 1) and no DP / EP works on MRV2 (`VLLM_USE_V2_MODEL_RUNNER=1`). Steps above `--dbo-prefill-token-threshold` split into two microbatches, and each TP all-reduce becomes a microbatch hand-off on the comm stream.
- Multimodal models are allowed in this mode; the vision encoder runs outside the split. (Speculative decoding under DBO comes from main since #61464, in every mode.)
- ROCm: the comm stream runs at high priority, and a hipBLASLt handle warm-up fixes a GPU hang of DBO steps (root cause below).
- MRV1 rejects this mode with an explicit error.

## Details

- **Split decision.** With one DP rank, `dispatch_cg_and_sync_dp` decides locally; a split step runs eager (`CUDAGraphMode.NONE`). Decode steps keep their CUDA graphs when `--dbo-decode-token-threshold` is above the decode batch.
- **All-reduce hand-off.** `init_dbo_tp_comms` builds one `PyNcclCommunicator` per microbatch and installs a hook in `GroupCoordinator._all_reduce_out_place`. That function runs under the `vllm.all_reduce` custom op, so compiled graphs reach the hook. Inside a microbatch thread the hook yields to the other microbatch, runs the all-reduce on the comm stream over that microbatch's communicator, and switches back; elsewhere it returns `None` and the normal path runs. One communicator per microbatch keeps the two microbatches' collectives off one NCCL queue.
- **Fused all-reduce + norm.** `fused_allreduce_gemma_rms_norm` skips its FlashInfer / AITER fused kernels inside a microbatch, so every all-reduce is a hand-off. Unsplit steps keep the fusion.
- **MoE.** `MoEPrepareAndFinalizeNoDPEPModular.supports_dbo()` returns `True`: there is no all2all, the hand-offs are the TP all-reduces.
- **Microbatch outputs.** `merge_ubatch_outputs` (tuples and lists since #61464) also passes `None` through, which DSpark's auxiliary outputs need.
- **Workspaces.** Both microbatches compute on one stream, so the workspace manager keeps one set (`num_ubatches=1`).
- **ROCm comm stream priority.** At the default priority, comm and compute can share one hardware queue and serialize.
- **hipBLASLt hang (ROCm).** `hipblasLtCreate` allocates the Stream-K flag buffer and clears it with a `hipMemset` on the null stream. The call returns at once; the clear ran 3-33 ms later behind other work. torch keeps one Lt handle per (thread, stream), and the microbatch threads are new every step, so a step can create handles. When a Stream-K GEMM on the comm stream starts before the late clear, the clear zeroes flags that partner workgroups already set, and the owners spin forever in `label_SK_Fixup` (found with rocgdb). The fix fills the handle pool at `UBatchRunner` init: each microbatch thread runs one small GEMM on the compute, capture and comm streams.
- **vs #44677.** #44677 adds the yield in `tensor_model_parallel_all_reduce` and opens the DP=1 path in Model Runner V1 (`gpu_model_runner`, `gpu_ubatch_wrapper`), which #63373 removes. This PR targets MRV2's `UBatchRunner`, hooks below the custom op, uses one communicator per microbatch, and adds the ROCm pieces.
- **Limitations.** Split steps run without CUDA graphs.
