# [Model] Add native StartLux-Decision dense and MoE pooling

[Upstream PR](https://github.com/vllm-project/vllm/pull/60375) · state: open · merged: False

## Original PR description

## Purpose

Add native StartLux-Decision pooling for the dense Qwen3.5 4B and MoE 35B-A3B checkpoints.
A normal generative endpoint does not expose the reference decision protocol: it needs
last-prompt-token A–Z logits, an FP32 projection of selected output-head rows, and
question-specific candidate restriction and calibration without token generation.

The model classes reuse the existing Qwen3.5 dense/MoE backbones. The small output
head is captured before vocabulary sharding; the example reuses the official renderer
and decision postprocessing. Model registration is in vLLM, with no Ascend model patch
or model-runner changes. The example uses eager execution and rejects image requests.
PP>1 is rejected. Graph execution, images and 256K contexts are outside this validation.

Open StartLux model-support submissions were searched in both upstream repositories;
no matching open submission was found. This work is AI-assisted. Human line-by-line
review and the upstream CI/model-evaluation gates remain required before merging.

collects the numerical tests. The CPU-only fixture opts out of accelerator teardown,
not numerical assertions. No golden outputs or tolerances are relaxed.

### Accuracy evidence (validated v0.30.0 pair, eager)

The seven-suite evaluation used official StartLux weights and unmodified prompts,
question/option order, per-type temperatures and official scoring. Each model
covered all 10,751 rows / 12,351 decisions, with zero missing rows or invalid decisions.
The average is the unweighted mean of the seven accuracies, not pooled accuracy.
