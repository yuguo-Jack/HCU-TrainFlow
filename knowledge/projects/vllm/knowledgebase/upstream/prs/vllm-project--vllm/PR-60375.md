# [Model] Add StartLux Instant decisions and platform-safe D3 prefix ranges

[Upstream PR](https://github.com/vllm-project/vllm/pull/60375) · state: open · merged: False

## Original PR description

## Overview

Serve StartLux Instant through native decisions, and preserve platform/hybrid model state when D3 supplies prefix attention ranges.

## Claims

- Retain StartLux prompt formats, per-type temperature calibration and independent reads.
- Replace the D3-specific model-state override with model-supplied inclusive ranges, preserving platform and recurrent-state handling.
- Carry ranges through hybrid metadata; retain default multimodal ranges for other requests.

## Validation

StartLux v1.1 27B Instant: three identical-token choice/predicate/score cases, Eager and PIECEWISE HTTP200, zero output tokens. Maximum probability errors: CPU BF16 vs Eager 0.0022137952; CPU vs graph 0.0029519529; Eager vs graph 0.0007381577. These are observed smoke errors, not a retrospective benchmark pass criterion.

d3-turbo: real 26B weights, Eager and actual PIECEWISE replay; reordered/repeated inputs agree. Maximum error against the historical same-checkpoint CPU FP32 reference was 0.0001267673. Final hook revision reproduced the four graph-mode responses exactly.

19 isolated StartLux protocol tests and relevant local pre-commit checks passed. The extended D3 real-runtime test is selected by the existing multimodal pooling CI route; it was not run on CUDA/ROCm in this task.

Device validation used Ascend 910B4-1, BF16, TP1, the `quay.nju.edu.cn/ascend/vllm-ascend:v0.30.0rc2` base image (digest `sha256:6348403a0ebb19f52bc1b7497de1daeb6df0e4650f9051c169e47a011527a6c3`), and source overlays: [vLLM](https://github.com/Liuchenbing-2026/vllm/commit/d74c7f54aefa0f4be5fafb2362950290886328b5) and [vLLM-Ascend](https://github.com/Liuchenbing-2026/vllm-ascend/commit/cdca8d2c6fec142fbd336ca28a4e9f87f68ca2d8). Torch 2.10.0, torch_npu 2.10.0.post7, CANN 9.2.0 and Transformers 5.19.0 were used. These results are from the combined fixed-source stack, not the unmodified rc2 image or upstream CI.

AI assistance was used; human review remains required.

## Details

The distinct change is preserving the platform/hybrid state while delivering model-specific request boundaries. D3 prefix support incorporates [the upstream model implementation](https://github.com/vllm-project/vllm/commit/dfa830766b0d082870ff2f64b0fdc5ab0daaab49) by Xunzhuo Liu. Ascend prefix pooling requires the matching hardware backend. StartLux AutoThink, broad benchmark accuracy, multimodal precision and shared-state computation are outside the validation scope.
