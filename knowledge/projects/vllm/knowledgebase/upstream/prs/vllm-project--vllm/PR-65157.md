# [Docs] Fix accidental cross-references in docstrings

[Upstream PR](https://github.com/vllm-project/vllm/pull/65157) · state: closed · merged: True

## Original PR description



## Overview

Docstrings render as Markdown, so array shapes like `[block][2][16]` were parsed as reference links and produced `mkdocs_autorefs` "Could not find cross-reference target" warnings. This wraps them in code spans. A pre-commit hook to stop them coming back is in #65158.

## Claims

- Fixes the 11 reported `mkdocs_autorefs` warnings (`kimi_k3`, `muse_spark`) plus 3 more of the same kind (`_custom_ops.py`, `minimax_m3`).

## Validation

The hook from #65158 reports 14 hits on the `upstream/main` versions of these files (all 11 reported warnings + 3) and 0 on every `vllm/**/*.py` in this branch. `pre-commit run` passes.

No open PR addresses this (searched "autorefs", "mkdocs_autorefs", "cross-reference docstring"). I didn't run a local mkdocs build; the RTD preview build on this PR covers that.
