# [Core] Drop the Ray driver-node GPU pin left over from the legacy executor

[Upstream PR](https://github.com/vllm-project/vllm/pull/61713) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Follow-up to #61712 (merged). Removes Ray code that only the legacy compiled-graph executor needed.

## Claims

- `initialize_ray_cluster` loses `require_gpu_on_driver` and the driver-node bundle pin. The legacy executor ran rank 0 inside the driver process, so it needed a GPU on the driver node. `RayExecutorV2` runs every worker as a remote actor and already passed `False`.
- Deletes `tests/distributed/test_multi_node_assignment.py` and its step in the multi-node CI job; it only asserted that pin.
- Drops the Ray 2.9 `available_resources_per_node` import shim in `ray_utils.py` (test requirements pin Ray 2.55/2.56).
- Un-skips the `enable_prompt_embeds` + Ray case of `test_models_distributed`; the skip reason blamed the Ray compiled DAG.
- Drops the `ray[cgraph]` extra from the CUDA, ROCm and nightly test requirements. Its only other effect was pulling in cupy (removed from `cuda.txt`/`cpu.txt` on recompile). `test_weight_transfer_nccl_uid` already `importorskip`s cupy and no Buildkite job runs it.

−160 / +7 lines.

## Validation

- `pre-commit run` (ruff, mypy, Buildkite checks, pip-compile): passed.
- Local run on the two free GPUs (2–3) of a shared 4x GB200 node:
  - `tests/basic_correctness/models/test_basic_correctness.py -k "test_models_distributed and ray"` (`TARGET_TEST_SUITE=L4`), including the un-skipped prompt-embeds case: 4 passed.
  - `tests/distributed/test_ray_v2_executor.py`, 2-GPU cases: 13 passed. The 4-GPU cases couldn't run because another user's processes hold GPUs 0–1.
  - `tests/distributed/test_pipeline_parallel.py -k ray`: the only 2-GPU case (PP=2, TP=1) brought up the Ray server and served completions, then failed with a 400 from the Rust frontend's JSON parser on a list-of-strings `prompt`. The `mp` backend fails the same way, so this is my stale local `vllm-rs` binary and unrelated to this PR; CI covers this case.
- CI: the RayExecutorV2 Buildkite jobs (CUDA L4 and MI355) run the un-skipped case.

## Details

**Compatibility:** `initialize_ray_cluster` is exported from `vllm`, so a caller that passes `require_gpu_on_driver` now gets a `TypeError`. A search of the vllm-project org found no caller passing it: tpu-inference and vllm-torchtpu use their own `_initialize_ray_cluster`, and vllm-omni defines its own function of the same name. Callers that relied on the default pin now get a plain `PACK` placement group with no driver-node constraint.

**Not a duplicate:** no open PR touches this; it is the follow-up list from #61712.
