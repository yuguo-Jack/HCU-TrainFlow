# [BugFix] Reject logprobs larger than the vocabulary

[Upstream PR](https://github.com/vllm-project/vllm/pull/64361) · state: open · merged: False

## Original PR description

## Overview

Requests for more logprobs than the vocabulary pass validation when `--max-logprobs` is larger than the vocab, then crash in `torch.topk`. Validation now caps the allowed count at the vocabulary size. Fixes #64291.

## Claims

- `SamplingParams(logprobs=20)._validate_logprobs` raises when `max_logprobs` is 20 and the vocab size is 10.
- The same cap applies to `prompt_logprobs`.
- A request for exactly the vocab size is still accepted.

## Validation

`python3 -m pytest tests/test_sampling_params.py::test_logprobs_above_vocab_size_are_rejected tests/test_sampling_params.py::test_non_diffusion_models_unaffected -q --noconftest`

Before the cap, the new test did not raise. After it, both tests passed. No GPU run: the worker `topk` crash is the consequence of the validation hole, and the test drives `_validate_logprobs`.

## Details

`_validate_logprobs` compared the request only with `model_config.max_logprobs`. That default is 20 and is not tied to the vocab. `topk` requires `k <= vocab`. The allowed maximum is now `min(max_logprobs, vocab_size)` when the vocab size is positive. `max_logprobs == -1` still means the full vocabulary.
