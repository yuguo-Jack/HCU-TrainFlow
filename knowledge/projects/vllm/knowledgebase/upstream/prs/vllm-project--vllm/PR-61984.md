# [Bugfix] Resolve disabled thinking effort in Anthropic render

[Upstream PR](https://github.com/vllm-project/vllm/pull/61984) · state: closed · merged: True

## Original PR description



## Overview

Fix `/v1/messages/render` bypassing the disabled-thinking effort resolution used by `/v1/messages` and token counting. This caused render requests with `thinking.type="disabled"` to fail on GPT-OSS and ignore `--anthropic-disabled-thinking-effort`.

## Claims

- Apply the existing disabled-thinking effort resolution to Messages render requests.
- Honor configured effort in both API and standalone render servers.
- Preserve existing behavior for requests without disabled thinking.

## Validation

Added parameterized regression tests covering automatic fallback, explicit effort, explicit `none`, and requests without disabled thinking.

- Before the fix, the automatic-fallback and explicit-effort cases failed.
- With the fix, all regression cases passed; **152 tests passed** across the related suites.
- HTTP validation with `openai/gpt-oss-20b` confirmed disabled-thinking render requests succeed and produce the same tokens as Chat render with the resolved effort.
- All applicable pre-commit checks passed, including Ruff and mypy.

```bash
.venv/bin/python -m pytest \
  tests/entrypoints/anthropic/test_anthropic_messages_conversion.py \
  tests/entrypoints/anthropic/test_protocol_exports.py \
  tests/entrypoints/scale_out/render/test_render.py \
  tests/entrypoints/launchers/render/test_app_state.py -q
```

## Details

Messages render previously converted disabled thinking to `reasoning_effort="none"` without applying the configured override or automatic fallback. Harmony rejects `none`, causing GPT-OSS render requests to fail.

Extract the existing effort probe and caching logic into a reusable resolver, and pass the configuration through both server initialization paths. The probe rules remain unchanged, and resolution only runs for disabled-thinking requests.
