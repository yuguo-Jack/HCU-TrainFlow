# [Perf][DSv4.1] Tile the NVFP4 compressed-KV dequant-gather

[Upstream PR](https://github.com/vllm-project/vllm/pull/63018) · state: closed · merged: True

## Original PR description



## Overview

Speed up `_dequantize_and_gather_k_nvfp4_kernel`, the Triton kernel that dequantizes and gathers the DeepSeek-V4.1 NVFP4 compressed K cache (`nvfp4_ds_mla`) for sparse prefill. Output is bit-identical.

## Why

- The old kernel handled one token per loop iteration: a chain of dependent block-table, record and scale loads, so long gathers were bound by load latency, not memory bandwidth.
- The new kernel handles 8 tokens per iteration with one vector load each for block ids, packed values and scales, and decodes e2m1 with exact bit placement instead of `exp2`/`select`.
- Replaced in place: same signature and callers, no new flags, other cache formats unchanged.

## Results (B300, kernel time)

| gather | before (us) | after (us) | speedup |
|---|---:|---:|---:|
| 1 x 16K rows | 17.4 | 11.3 | 1.5x |
| 8 x 64K rows | 341.0 | 128.0 | 2.7x |
| 32 x 100K rows | 1,707 | 722 | 2.4x |
| skewed: 1 x 100K + 3 x 64 rows | 181.2 | 33.8 | 5.4x |

- Single-request gathers of up to ~1K rows are within one ~2 us timer tick of the old kernel.
- End to end at 16-32K contexts there is no measurable change: the gather is well under 1% of a prefill step. Output is bit-identical, so accuracy is unchanged.

## Validation

```bash
pytest tests/kernels/test_compressor_kv_cache.py
```

- B300: 180 passed, 19 skipped (the skips are ROCm-only).
- The new tests compare raw bits against the previous kernel, kept in the test as the reference. They cover ragged batches (empty requests, partial last blocks, a context past the grid cap, `-1` in unread block-table slots, random cache bytes including NaN and subnormal scales), plus every (packed byte, scale byte) pair.
