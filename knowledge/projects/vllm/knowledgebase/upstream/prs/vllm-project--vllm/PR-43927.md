# fix: update WNA16 Marlin MoE fake signature

[Upstream PR](https://github.com/vllm-project/vllm/pull/43927) · state: closed · merged: False

## Original PR description

#### Summary

Update the fake implementation for `_moe_C::moe_wna16_marlin_gemm` to match the registered op/Python wrapper signature.

The real op and Python wrapper include optional trailing tuning arguments:

- `thread_k`
- `thread_n`
- `blocks_per_sm`

The fake implementation did not accept those arguments, so fake/meta execution can fail with a signature mismatch even though the real op path accepts them.

This PR also mirrors the real op's output behavior: if an output tensor is provided, return it; otherwise allocate the `(size_m * top_k, size_n)` output.

#### Tests

- `python3 -m py_compile vllm/_custom_ops.py`

I could not run broader local tests in this checkout because local test dependencies (`torch`, `pytest`) are not installed; CI should cover import/fake-op registration.
