# [Bugfix][Spec Decode] Judge draft KV groups with the draft model's config for CUDA-graph support

[Upstream PR](https://github.com/vllm-project/vllm/pull/62964) · state: open · merged: False

## Original PR description

## Overview

This PR builds on #55593 by @he-yufeng and completes it, so a speculative drafter whose attention heads differ from the target's keeps full CUDA graphs on both model runners. His two commits come first with his authorship and messages. On top of them, one commit applies his rule to Model Runner V2 and one tags the draft KV cache group early enough for his V1 check to take effect on current `main`. Fixes #55581.

## Claims

- Model Runner V2 keeps `FULL_AND_PIECEWISE` with a drafter of its own head count, where `main` drops to `PIECEWISE` for every layer, the target's included.
- The V1 runner keeps `FULL_AND_PIECEWISE` with an EAGLE-style drafter of its own head count.
- Only KV groups holding draft layers take the draft model's config, so runs without a drafter resolve the same graph mode as before.

## Validation

AI assistance (Claude) was used to prepare this change; I reviewed every changed line and ran the tests listed below.

I ran the engine on one B300 with FlashInfer attention, TP1, the Qwen3.8-27B target (24 query and 4 KV heads per rank) with dummy weights, and a dummy-weight drafter with 40 query and 40 KV heads, head size 128 and 2 speculative tokens. Model Runner V2 used a 2-layer Qwen3 `draft_model` drafter and V1 a 1-layer EAGLE3 drafter. Every run generated 32 tokens for each of 4 prompts.

| Runner | Tree | Resolved `cudagraph_mode` | FULL graphs captured |
|---|---|---|---|
| Model Runner V2 | `main` | `PIECEWISE` | none |
| Model Runner V2 | this PR | `FULL_AND_PIECEWISE` | 8 batch shapes |
| V1 | `main` | `PIECEWISE` | none |
| V1 | #55593's commits on `main` (with the Model Runner V2 commit) | `PIECEWISE` | none |
| V1 | this PR | `FULL_AND_PIECEWISE` | 6 decode batch shapes |

On `main` both runners log `CUDAGraphMode.FULL_AND_PIECEWISE is not supported with spec-decode for attention backend FlashInferBackend (support: AttentionCGSupport.UNIFORM_SINGLE_TOKEN_DECODE); setting cudagraph_mode=PIECEWISE`.

Each new test fails on the tree without its fix and passes with it. His V1 test fails on `main`, the Model Runner V2 test (`test_draft_layers_cudagraph_support_uses_draft_model_config`) fails on his commits alone, and the grouping test (`test_groups_from_builder_tag_eagle_groups`) fails without the last commit. On CPU, `test_attn_utils.py`, `test_gpu_model_runner_v2.py`, `test_gpu_model_runner.py`, `test_kv_cache_utils.py`, `test_kv_cache_planning.py` and `test_kv_cache_config_builder.py` give the same results on `main` and this PR apart from the three new tests. Seven tests in `test_gpu_model_runner.py` fail on both trees because they need a GPU. `pre-commit run --from-ref main --to-ref HEAD` passes, mypy included.

## Details

FlashInfer reports full CUDA-graph support for a KV cache spec when trtllm-gen decode can serve it, and it takes the query-head count for that check from `model_config`, which is the target's. A draft layer with 40 KV heads under a target with 24 query heads per rank fails `24 % 40 == 0`, the check reports `UNIFORM_SINGLE_TOKEN_DECODE`, and with speculative decoding the runner drops to `PIECEWISE` for all layers. #55593 fixes this on V1 by judging draft-side KV groups (`is_eagle_group`) with `speculative_config.draft_model_config`.

Model Runner V2 asks each attention group's builder with the runner's `vllm_config` in `get_attn_cg_support` and in the varlen check used by adaptive verification, so it needs the same rule. It already tags draft layers (`is_draft_layer`, set by its EAGLE-style and `draft_model` speculators). `init_attn_backend` copies that tag onto the group's KV cache spec, because merged group specs drop it, and both checks pick the draft config from it. The tag is a `compare=False` field, so KV cache grouping and layouts stay the same.

On current `main` the V1 runner resolves its graph mode twice, first for the minimal KV cache config of the CUDA-graph memory profiling pass and then for the real one. Only `get_kv_cache_configs` set `is_eagle_group`, so the profiling pass saw an untagged draft group, judged it with the target's config and dropped the mode to `PIECEWISE`, which the second pass keeps. The last commit moves the tagging into `get_kv_cache_groups_from_builder`, which both configs are built from. The warning about an untagged EAGLE group with Mamba layers stays in `get_kv_cache_configs`, so it is logged once.

V1 tags draft groups only for methods that use EAGLE block dropping, so a V1 `draft_model` drafter is judged with the target's config as before. On `main` that setup also stops at the first prefill with `assert is_strictly_contiguous(block_tables_prefill)` in FlashInfer, a separate issue this PR does not touch. Model Runner V2 covers `draft_model`. I measured on B300 only (SM103, trtllm-gen decode).

### Not a duplicate

I searched open and closed PRs for `get_cudagraph_support` with FlashInfer, drafters with a different head count, `can_use_trtllm_attention`, and `55581 in:body`. #55593 is the open fix for #55581 on V1, and this PR keeps it whole and adds the Model Runner V2 side and the profiling-pass tagging it needs on current `main`. Maintainers can take this PR in place of #55593 or merge #55593 first, after which this PR reduces to the last two commits. #56289 by @XFDG (closed) read the head count from the group's own layers inside FlashInfer. This PR uses none of its code.

- TheEpicDolphin · COMMENTED · 2026-11-03T06:19:52Z · [source](https://github.com/vllm-project/vllm/pull/62964#pullrequestreview-5747973310)

I think there's a simpler fix for FlashInfer's cudagraph support. This PR passes the draft's model config for draft groups so that `get_cudagraph_support` reads the draft's query head count. But it turns out we don't need the query head count at all. Its only use is in `can_use_trtllm_attention`, which checks `num_qo_heads % num_kv_heads == 0`. That's redundant, since the attention constructor already asserts it for every layer: https://github.com/vllm-project/vllm/blob/40941f2c4ba96fba0a7e282a5355e89cd74d9ac5/vllm/model_executor/layers/attention/attention.py#L335

So the head count can be safely dropped from the check:
```
has_uniform_batch_support: bool = (
    len(kv_specs) > 0
    and force_use_trtllm_attention() is not False
    and supports_trtllm_attention(is_prefill=False)
)
```
The loop then only keeps the XQA head-dim and nvfp4 checks. This fixes both runners and the varlen check, with no draft config or group tagging needed. Would you be open to reducing the PR to this?
