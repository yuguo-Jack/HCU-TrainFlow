# [Frontend] Support allowed_tools in Rust chat requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/51535) · state: open · merged: False

## Original PR description

## Overview

Accept the nested Chat Completions `tool_choice.allowed_tools` shape in the Rust frontend and restrict the renderer to the allowed function tools. Implements the roadmap item in #44280.

## Claims

- Accept `auto` and `required` modes with strict `allowed_tools` and `function` discriminators.
- Validate allowed names against top-level `tools`, then filter top-level and developer-message declarations in declaration order.
- Treat an empty `auto` list as no tools; reject an empty `required` list and undeclared functions with HTTP 400.

## Details

The current request type expects `mode` and `tools` as flat fields, while Chat Completions clients nest them under `allowed_tools`. Consequently, the nested request fails deserialization; the old flat representation also fails conversion as unsupported.

For a Rust frontend serving `served-model`, reproduce with:

```bash
curl http://localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "served-model",
    "messages": [{"role": "user", "content": "What time is it?"}],
    "tools": [
      {"type": "function", "function": {"name": "get_time", "parameters": {"type": "object"}}},
      {"type": "function", "function": {"name": "get_weather", "parameters": {"type": "object"}}}
    ],
    "tool_choice": {
      "type": "allowed_tools",
      "allowed_tools": {
        "mode": "auto",
        "tools": [{"type": "function", "function": {"name": "get_time"}}]
      }
    }
  }'
```

Before: JSON deserialization rejects the request. After: request preparation accepts it and exposes only `get_time` as callable. The nested payload is exercised by the in-process HTTP tests; the curl command was not run against a live checkpoint.

Filtering happens before `ResolvedToolContext` and rendering. Existing duplicate-name and tool-choice resolution remain in place, and renderer, parser, and engine interfaces are unchanged. All declared tool types are validated before filtering. A developer-local tool cannot authorize an otherwise undeclared allowed name. The obsolete flat shape remains unsupported. The supported shape and edge cases are documented in `docs/features/tool_calling.md`.

The rebase preserves upstream's nullable-boolean and selected-logprob tests, adds the new `defer_loading: None` fixture fields, and updates our HTTP assertions to upstream's current error types and numeric status codes.

Duplicate checks were refreshed for `allowed_tools Rust` and `44280 in:body`. #60585 targets the Responses API, and #58783 adds the Rust Responses endpoint; neither implements this Chat Completions request path. The original scope was discussed in https://github.com/vllm-project/vllm/issues/44280#issuecomment-5229310963.

AI assistance was used for implementation, review, and rebasing. The submitting human reviewed and accepted the original change; the rebase-specific changes are described above for review.
