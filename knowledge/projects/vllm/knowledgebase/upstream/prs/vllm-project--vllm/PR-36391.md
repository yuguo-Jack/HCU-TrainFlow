# [Core] Decouple draft-token hook from speculative decoding

[Upstream PR](https://github.com/vllm-project/vllm/pull/36391) · state: closed · merged: False

## Original PR description

## Purpose

Remove the `self.use_spec_decode` gate from the draft-token hook in `EngineCore.post_step()` and `step_with_batch_queue()`, enabling plugins (e.g. dLLM schedulers/workers) to reuse the spec-decode data path without requiring speculative decoding to be enabled.

Ref: https://github.com/vllm-project/vllm/issues/36155

### Background

The dLLM (diffusion Language Model) RFC proposes reusing the speculative decoding data path (`Request.spec_token_ids`, `SchedulerOutput.scheduled_spec_decode_tokens`, etc.) with overloaded semantics for block-based token generation models like LLaDA. The first step is decoupling the draft-token hook so that `take_draft_token_ids()` is called whenever the model executes, not only when `use_spec_decode=True`.

### Changes

**`post_step()`** (`core.py:416`): Removed `self.use_spec_decode` from the condition.

Before: `if not self.async_scheduling and self.use_spec_decode and model_executed:`
After: `if not self.async_scheduling and model_executed:`

The default worker's `take_draft_token_ids()` returns `None` when not doing speculative decoding, and the existing `if draft_token_ids is not None:` guard prevents any downstream call — so this is fully backward compatible.

**`step_with_batch_queue()`** (`core.py:524`): Removed the `if self.use_spec_decode:` block and replaced the hard `assert draft_token_ids is not None` with a soft `if draft_token_ids is not None:` guard.

This avoids crashes when a plugin returns `None` (no draft tokens available for this step) and allows the code path to be used by dLLM workers that provide draft tokens intermittently.

## Test Plan

```bash
python -m pytest tests/v1/engine/test_post_step_draft_hook.py -v
```

New test file with 5 unit tests using `MagicMock` stubs (no GPU required):

1. **`test_post_step_calls_hook_without_spec_decode`** — Verifies `take_draft_token_ids()` is called and `update_draft_token_ids()` receives the result when `use_spec_decode=False`.
2. **`test_post_step_noop_when_draft_ids_none`** — Verifies `update_draft_token_ids()` is NOT called when `take_draft_token_ids()` returns `None` (default worker behavior).
3. **`test_post_step_noop_when_model_not_executed`** — Verifies the hook is skipped when `model_executed=False`.
4. **`test_post_step_noop_with_async_scheduling`** — Verifies the hook is skipped with async scheduling (draft tokens are updated in the worker process).
5. **`test_post_step_still_works_with_spec_decode`** — Backward compatibility: verifies the hook still works correctly when `use_spec_decode=True`.
