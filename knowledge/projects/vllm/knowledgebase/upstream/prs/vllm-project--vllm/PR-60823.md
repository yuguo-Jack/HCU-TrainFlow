# [Chore] Port more vendored configs and processors to upstream Transformers

[Upstream PR](https://github.com/vllm-project/vllm/pull/60823) · state: open · merged: False

## Original PR description

## Overview

Follow-up to #60623. Ports the vLLM code for 9 more models to the upstream Transformers 5.16.1 schemas, and deletes their vendored configs and processors (12 files). Also fixes registry entries that kept models out of CI.

Related PRs:
- **#44031:** patches DeepSeek-V4 for upstream's normalized `compress_ratios`. This PR supersedes it.
- **#57818:** edits the vendored `deepseek_v4.py`, which this PR deletes.
- **#47438:** a stale draft (last updated 2026-07-16) with a partial OpenCUA fix. This PR supersedes it.

## Claims

- Deletes the vendored configs for `deepseek_v4`, `step3p5`, `minimax_m3`, `muse_glimmer`, `cosmos3_edge`, `colpali`, `colmodernvbert` and `qianfan_ocr`. It also deletes the vendored `cosmos3_edge`, `muse_glimmer` and `inkling` processors, and the model code now reads the upstream fields:
  - **DeepSeek-V4:** `compress_ratios`, `num_hash_layers` and the mm-prefix flags are derived from `layer_types` / `mlp_layer_types` / `compress_rates` by three helpers in `deepseek_v4_utils.py`. V4.1 configs, which keep the legacy fields, are unchanged. `is_rope_parameters_nested` now accepts V4's `{"main", "compress"}` rope layout.
  - **Step3p5 and MiniMax-M3:** they read `layer_types` / `mlp_layer_types` / `index_*` / per-type `rope_parameters`. Upstream `Step3p7TextConfig` and `MiniMaxM3VLConfig` are registered in `_CONFIG_REGISTRY`, because both models' hub remote code fails or uses the old schema.
  - **MuseGlimmer and Cosmos3-Edge:** they consume upstream processor outputs. Cosmos3-Edge reorders upstream's merge-window patches back to raster order before SigLIP2.
  - **ColPali:** reads PaliGemma from `vlm_config`.
  - **Qianfan-OCR:** a small adapter maps the upstream vision fields onto InternViT's.
  - **ColModernVBERT:** `ModernVBertModel` is mapped to `ColModernVBertForRetrieval`.
- **Fixes:**
  - **ColModernVBERT:** the vendored config dropped the checkpoint's sliding-window `rope_theta` (160000 → 10000). vLLM now matches the HF reference.
  - **Step-3.5-Flash MTP:** built with an `IndexError` before; it now builds.
  - **Re-saved MiniMax-M3 checkpoints** in the upstream schema (e.g. `lukealonso/MiniMax-M3-NVFP4`): failed with "Unsupported activation: silu"; they now get past config loading.
  - **InternS1-Pro:** failed to initialize (`model_config` was not set).
  - **OpenCUA:** Transformers v5 builds a processor's sub-processors from its `__init__` signature, which here only exposed `tokenizer`, so the processor had no `image_processor`. Fixed by overriding `get_attributes`.
  - **Kimi-K2.5:** the spec-decode image token is now read from `image_token_id`. `ModelConfig.is_quantized()` now uses the arch config, so it sees quantization configs nested in `text_config`.
- Renames the vendored `InternVL{,Image,Video}Processor` to `InternVLChat*`, so they stop shadowing the upstream classes.
- **Registry entries CI was skipping:**
  - FireRedASR2, FunASR and InternS1 caps removed; they work on Transformers v5.
  - Isaac and InternS1-Pro caps narrowed to the HF comparison.
  - Phi-4-reasoning-vision and OpenCUA pinned to the compatible `refs/pr/8` and `refs/pr/10` (OpenCUA's cap narrowed to the HF comparison).
  - Cohere2-MoE switched to the renamed `CohereLabs/North-Mini-Code-1.0`.
- **Kept vendored:**
  - `qwen3_asr`: upstream silently loads the original nested checkpoints with default sizes.
  - Inkling configs: renamed and missing fields across the nvidia, amd and MTP code.
  - Step3p7 and MiniMax-M3 processors: upstream tiles differently, or lacks the opt-in resize modes.

## Validation

|---|---|
| DeepSeek-V4-Flash / -Pro / -Flash-Vision-Exp | No CPU build in either tree. RoPE `cos_sin_cache`, MLA dims, layer schedule and the MTP draft config are identical. |
| DeepSeek-V4.1-Flash | 0 (config) |
| Step-3.5-Flash, Step-3.7-Flash (+ MTP drafts) | 0 |
| MiniMax-M3 (+ MTP draft) | 0 |
| Cosmos3-Edge | 0 params and modules. `num_layers` goes 56 → 28: the attention layers only, as Nemotron-H no longer counts MLP blocks. |
| Muse-Glimmer-30B (+ DFlash drafter) | 0 params. Constant `use_qk_norm` / `use_output_gate` flags dropped. |
| colpali-v1.3-hf, Qianfan-OCR | 0 |
| colmodernvbert-merged | sliding-window `rope_theta` 10000 → 160000 (the fix above). vs HF fp32: max abs diff 0.39 → 8e-5. |

Processor outputs, bit-identical to `main` unless noted:
- **Inkling:** pixels, dMel ids and token ids are identical.
- **Cosmos3-Edge:** pixels are identical after the raster reorder.
- **Qianfan, ColPali, ColModernVBERT:** identical.
- **Muse-Glimmer:** upstream's torchvision LANCZOS differs from PIL by at most 1 uint8 level on about 0.3% of pixels.
