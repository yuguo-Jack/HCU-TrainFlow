# [HiSparse] Switch to host reads once a request fills its admission window

[Upstream PR](https://github.com/vllm-project/vllm/pull/59495) · state: closed · merged: True

## Original PR description

> **Stacked on #59494.** Optional: #59494 alone fixes the livelock; this avoids the preemptions behind it.

## Purpose

Admission caps each request's resident pages at the in-flight window (`HiSparseResidentSpec.max_admission_blocks_per_request`, derived from `max_in_flight_tokens`), on the assumption that older pages move to host. At runtime, though, a request keeps its resident pages pinned until free GPU blocks fall below a fixed watermark (a tenth of the pool). A chunked prefill whose next chunk needs more than that outgrows the pool it was admitted into and is preempted, even though its written-back pages could have been released. With #59494 it resumes from host, but the preemption is still wasted work.

## Changes

`HiSparseCoordinator.update_residency` also switches a request to host reads (asks for a hot region, then releases its written-back pages) once its resident pages fill the window admission reserved for it. Runtime then enforces the same assumption admission makes, with no second estimate. `HiSparseResidentManager` exposes that window as a read-only `max_admission_blocks_per_request` property; nothing else in `vllm/v1/core` changes.

Released pages stay readable until the pool reuses them, so a long request that switches early only pays for its hot region.
