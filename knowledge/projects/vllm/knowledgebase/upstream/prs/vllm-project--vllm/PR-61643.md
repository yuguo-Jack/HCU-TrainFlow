# [Bugfix][MoE] Keep routing rows during DeepSeek V4.1 decoder replay

[Upstream PR](https://github.com/vllm-project/vllm/pull/61643) · state: closed · merged: True

## Original PR description

## Overview

Keep every prefill routing row when DeepSeek V4.1 decoder replay runs with returned routed experts enabled. Extracted from #61388 as a standalone fix based on `main`.

## Claims

- R3 requests use the existing prompt-logprobs keep-row mechanism so decoder replay does not omit their routing computations.
- Cover eager and PIECEWISE replay in the existing replay-batch suite.
- The diff contains the request row-retention policy and its regression coverage in two files.

## Validation

- **20 isolated CPU policy cases passed** using the actual request-admission, graph-selection, and replay row-selection methods with real CPU tensors. The same checks against unmodified `main` reproduce **6 failures / 14 passes**, including a 300-row prefill incorrectly reduced to 128 rows.
- Applicable pre-commit hooks, including mypy and Buildkite test tethering, and `git diff --check`: passed with local UTF-8/Git Bash interpreter adaptations.
- The pre-split #61388 validation recorded real-weight DeepSeek-V4.1 TP1/DP2/EP, 300/301-token prefill: late layers previously executed only 128 rows; the keep-row fix retained all rows in all 40 layers. The request-retention change is preserved from that combined revision.

GPU/model runs were not repeated for the split. CPU checks stop at the row-selection boundary and substitute configuration/base-state/input-gather fixtures; they do not validate CUDA kernels or attention numerics. The GPU regression remains in the existing CI-tethered suite:

```bash
.venv/bin/python -m pytest -q tests/models/test_deepseek_v41_replay_batch.py
```

## Details

Decoder replay can normally skip older prefill rows when only final logits are needed. Returned routing needs every accepted token's decisions; scattering the remaining rows cannot recover computations that never ran. Mark R3 requests as requiring every row when admitted, using the existing keep-row policy.

R3-enabled replay therefore retains prefill work that could otherwise be trimmed. No throughput measurement is claimed.

Duplicate-work checks refreshed open PR searches for `61388 in:body`, routed-expert capture, and decoder replay. #52902 adds API consistency tests, #57184 handles DBO staging/offsets, and #56778 implements terminal transport; they do not implement this NVIDIA V4.1 admission policy. The same fix has been removed from #61388, so this is its single review location.

AI assistance was used to split and validate the existing fix.
