# [Rust][Frontend] Return routed experts from the OpenAI routes

[Upstream PR](https://github.com/vllm-project/vllm/pull/63481) · state: closed · merged: False

## Original PR description

## Overview

Return routed-expert rows from the Rust OpenAI frontend, matching the Python
frontend's non-streaming `/v1/chat/completions` and `/v1/completions` behavior.
`routed_experts` is a vLLM extension (it is absent from the OpenAI OpenAPI 2.3.0
spec), so the extension semantics follow the Python API server.

## Changes

- Add `routed_experts_prompt_start` to both OpenAI request DTOs and pass it into
  the shared sampling params. The default is 0; an explicit `null` or negative
  value is rejected at body validation, and `0 <= value <= prompt_len` reuses
  the existing lower-layer check (HTTP 400 with
  `param=routed_experts_prompt_start`), like Python.
- Carry per-update routed rows through `vllm-llm`, `vllm-text`, and `vllm-chat`.
  Non-streaming OpenAI choices return the engine payload as base64 `.npy`; the
  dtype, byte order, shape, and expert order are preserved.
- Keep the per-update rows available when the frontend stops on a stop string
  before the engine terminates. Rows for surplus tokens (including several
  tokens accepted in one update) are trimmed from the tail, `stream_interval`
  deliveries stay ordered, and stop-token rows are not trimmed. No row is
  synthesized for the last sampled token, which was not forwarded.
- Move the NumPy encoder to a shared server module used by `/generate` and the
  OpenAI routes, and remove the corresponding `TODO`/fixed `None`.

OpenAI streaming choices are unchanged: Python's stream choice has no
`routed_experts` field, and the Rust SSE shape stays the same.

## Duplicate-work check

No open PR returns routed experts from the Rust OpenAI routes. #49555 is
Indexer-only and is not a base for this change; this PR is based directly on
`main`. Existing `/inference/v1/generate` routed-expert delivery is preserved.

## Incremental validation: routed-expert trim boundary

New commits on the branch:

- `1ce3563f9d` — merge of `origin/main` (`c9dbc92630`); the upstream diff contains no `rust/` files.
- `ad1450f788` — the routed-expert trim/data-integrity changes.

### What I confirmed

I first added a failing text-layer test with two engine outputs:

- previous output: 100 routing rows for one token;
- current output: 3 sampled tokens, 1 routing row, stop string matches at the
  first token.

Python `OutputProcessor._trim_surplus_tokens()` only replaces
`routed_experts_chunks[-1]` with `output.routed_experts[:-num_dropped]`, so the
previous 100 rows must survive. Rust previously concatenated all outputs and
dropped two rows from the merged tail, returning 99 rows. The new test failed
with `[99, 1, 2]` vs the expected `[100, 1, 2]`.

The current code now keeps each `GenerateOutput`'s `routed_experts_delta`
separate from already accumulated outputs and trims only the output that matched
the stop string. Later updates in a merged `stream_interval` delivery are
discarded; the matching update's chunk is trimmed; earlier outputs are never
touched. A legal zero-row payload is preserved instead of becoming `None`.

### Is the old over-trim reachable from real EngineCore?

No production input was found that reaches it. `AuxOutputConnector.take_output()`
returns `rows[:request.num_tokens - 1 - token_start]`: a decode/speculative
update returns one row per accepted sampled token, and a prefill update returns
the prompt rows, which are at least the one sampled token. Therefore every
EngineCore update has `routing_rows >= len(new_token_ids)`, and
`num_surplus_tokens <= rows` cannot cross into an earlier output for valid data.
The change is defensive and makes Python's per-output trim scope explicit; it
does not alter normal terminal or stop-token results. The stop-token path has
`num_surplus_tokens == 0` and remains untrimmed.

### Data validation

`WireNdArray` carries raw bytes without validating them, and the old
`drop_trailing_rows()` used `data.len() / rows`, silently truncating malformed
data. Added `validate_routed_experts_rows()`:

- rejects empty shape, shape-product overflow, unresolved data, and byte-length
  mismatch with a typed `RoutedExpertsDataLengthMismatch` error;
- allows `shape[0] == 0` as a legal empty payload;
- is used before `concat_routed_experts_rows()` and row slicing, so malformed
  data returns an error instead of panicking or being truncated.

### Memory

- `WireNdArray::clone()` only clones the shape `Vec` and increments the `Bytes`
  refcount; no routing bytes are copied.
- Terminal outputs now clear the accumulated per-update chunks once the
  whole-request terminal rows are selected.
- A single chunk is returned without the old concatenation copy; multiple chunks
  are still concatenated exactly once (required for a contiguous `.npy`).
- The early-stop path concatenates only the kept chunks, and
  `drop_trailing_rows()` uses a zero-copy `Bytes` slice.
- `npy_base64()` still copies into the `.npy` buffer and base64 string; that is
  serialization, not duplicate routing storage.

### New tests

Text layer (`vllm-text`):

  rows, current 1 row / 3 tokens, stop at first token → 100 rows (failed with 99
