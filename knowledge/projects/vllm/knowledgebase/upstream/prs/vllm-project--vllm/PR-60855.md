# [Model] Support EAGLE3/DFlash aux hidden states for Granite

[Upstream PR](https://github.com/vllm-project/vllm/pull/60855) · state: closed · merged: True

## Original PR description



## Overview

Implement `SupportsEagle3` for `GraniteForCausalLM`, so dense Granite models can serve as targets for EAGLE3/DFlash speculative decoding.

## Claims

- Granite targets can now attach aux-hidden-state drafters (EAGLE3, DFlash). Previously, engine init rejected them because `supports_eagle3` was absent.
- Accuracy is unchanged with speculation, and drafts are accepted.

## Validation

Target `ibm-granite/granite-4.2-8b` with an internal DFlash drafter (`num_speculative_tokens=15`), on an Intel Xeon 6972P:

```python
LLM(model="ibm-granite/granite-4.2-8b",
    speculative_config={"method": "dflash", "model": "<draft>", "num_speculative_tokens": 15})
```

| GSM8K (100 questions, greedy, no-think) | Accuracy | Mean acceptance length |
|---|---|---|
| No draft | 75% | — |
| + DFlash | 75% | 3.74 |

Aux hidden states also match HF `output_hidden_states` at the requested layers (fp32, rel. err ~1e-6).

```bash
pytest tests/models/test_initialization.py -k 'GraniteForCausalLM or GraniteSWAForCausalLM or Granite4Vision' # 3 passed
pytest tests/v1/worker/test_eagle3_aux_hidden_states_pp.py # 9 passed
pre-commit run --files vllm/model_executor/models/granite.py # passed
```

## Details

- Follows the existing aux-hidden-state pattern in `minicpm.py` and `apertus.py`. Pipeline parallelism is not supported: MRV2 rejects PP > 1 for this model.
- No public Granite drafter exists yet, so no e2e test is added.
- No existing PR covers this.
