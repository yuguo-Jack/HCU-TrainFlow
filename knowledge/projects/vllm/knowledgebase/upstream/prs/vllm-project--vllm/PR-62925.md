# [Frontend] Add /parse_function_call endpoint

[Upstream PR](https://github.com/vllm-project/vllm/pull/62925) · state: closed · merged: False

## Original PR description

## Purpose

SGLang exposes `POST /parse_function_call`, which runs the server's tool parser over text that the caller already has. This adds the same endpoint to vLLM.

It is useful whenever model output is parsed outside the chat-completion path: an agent loop that owns its own turn structure, an RL rollout harness, or a disaggregated deployment where the generate tier returns text that still has to be turned into tool calls (cf. the derender RFC #42729).

## Design

- `tool_call_parser` in the request body selects the parser; when omitted, the server's `--tool-call-parser` is used.
- The parser instance is built with the served tokenizer and the requested `tools`, so parsers that resolve argument schemas keep working.
- Response shape matches SGLang: `{"normal_text": ..., "calls": [...]}`.
- Missing/unknown parser returns a 400 `ErrorResponse`; nothing is generated, so the endpoint never touches the engine.

## Tests

`tests/entrypoints/unit_tests/test_parse_function_call.py` covers explicit and server-default parser selection, text without a tool call, and both error paths. The tests build their own FastAPI app, so they need no GPU or running server.

- nankingjing · comment · 2026-10-22T04:44:03Z · [source](https://github.com/vllm-project/vllm/pull/62925#issuecomment-6332909530)

Closing after re-evaluating against `AGENTS.md` (duplicate-work checks).

vLLM already exposes `POST /v1/chat/completions/derender` and `POST /v1/completions/derender`, and `ServingDerender` runs the configured tool/reasoning parser to return `reasoning`, `content` and `tool_calls`. That covers the same capability this endpoint proposed; the only difference is text input instead of token IDs. Since the derender path is also the design direction being worked through in #42729, a second, narrower parse surface in the normal OpenAI router does not justify its maintenance cost.

The branch stays at `nankingjing:parse-function-call-endpoint` if a text-in variant is ever wanted as an addition to the derender design.
