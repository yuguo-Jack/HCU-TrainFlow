# [Bugfix][Metrics] Uncount tokens trimmed past a stop string

[Upstream PR](https://github.com/vllm-project/vllm/pull/61661) · state: open · merged: False

## Original PR description

## Overview

Follow-up to #47616. When a stop string completes mid-step under speculative decoding, the output drops the tokens after it, but the generation token stats still count them.

## Claims

- `vllm:generation_tokens`, the per-request generation token histogram and the logged generation throughput no longer count tokens trimmed past a stop string.
- `mean_time_per_output_token` for those requests uses the kept token count.

## Validation

New `test_stop_string_trim_updates_generation_token_stats` (6 tokens in one step, stop string completes at token 4):

```
pytest tests/detokenizer/test_stop_string_while_stop_model_terminates.py
  main:        2 failed (assert 6 == 4), 34 passed
  this branch: 36 passed
pytest tests/detokenizer/test_check_stop_strings.py tests/detokenizer/test_min_tokens.py \
       tests/detokenizer/test_stop_string_while_stop_model_terminates.py
  this branch: 48 passed
```

CPU only (macOS). Not run here: `tests/v1/engine/test_output_processor.py`, whose imports load xgrammar's native library, which crashes on this machine. No model eval: this changes metrics only, not outputs.

## Details

`process_outputs` records iteration stats from `new_token_ids` (step 1) before the detokenizer matches stop strings, so `_trim_surplus_tokens` dropped the tokens from the output after they were counted. It now subtracts the dropped tokens from the iteration and request stats.

Not a duplicate: a search of open PRs and issues for this trimming path and the generation token stats found none. #47616 fixed `token_ids` and logprobs only.
