# [CI][Test] GLM-5.3-Flash layer-pruned checkpoint tests (e2e, KV offload, NIXL PD)

[Upstream PR](https://github.com/vllm-project/vllm/pull/57537) · state: open · merged: False

## Original PR description

## Purpose

Give the GLM-5.3-Flash serving stack (hybrid KDA + DeepSeek-sparse-MLA with the kpool indexer / tail
scratch group, fp8 MoE, mHC, MTP, PD disaggregation, KV offload) CI coverage that does not need a
4-GPU node holding the 328 GB checkpoint.

The asset is a **layer-pruned real checkpoint**, `JaredforReal/GLM-5.3-Flash-4L`: original layers 0-3
(one 3x KDA + 1x DSA-MLA period, dense MLP on 0-2, MoE on 3) plus the MTP layer, with **every width
unchanged** (288 routed experts, 64 KDA heads, MLA/indexer dims, vision tower). Only whole layers were
removed, so kernel selection and the KV cache layout match the 300B model: the same
`{MLA+indexer}`, `{kpool tail}` and Mamba groups aliasing the MLA slot, and the same auto block size
(4352 / 2176 / 1152 tokens at TP1 / TP2 / TP4). 18.5 GiB, loads in ~8 s. Derivation and the exact config
edits are documented in the model card.

New tests (SM90/SM100 only: the DeepGEMM paged-MQA indexer and FlashMLA/FlashInfer sparse MLA do not run on L4):

| test | GPUs | guards |
|---|---|---|
| `tests/models/glm5next/test_pruned_e2e.py` | 1 | KV groups = {MLA + indexer}, {kpool tail}, 3 Mamba groups aliasing the MLA tensor; greedy reproducibility across a block boundary with a prompt longer than `index_topk`; MTP drafter loads and agrees with target-only greedy. A strict xfail documents the `fused_recurrent_kda` gridDim.z overflow at 64 heads x 1024 seqs (#56973, fixed by #56974; the marker must be dropped once that lands).; **prefill checkpoint pages**: a prompt crossing a block boundary leaves, in every Mamba group, a cached checkpoint page equal to a cold prefill ending at that boundary (relative error <= 0.03 observed, >= 1 when a group's checkpoint goes to another group's page, the #59536 regression that the greedy repeat test does not notice) |
| `tests/v1/attention/test_gdn_metadata_builder.py::test_update_block_table_matches_fresh_build` | 1 | `update_block_table()` for a sibling Mamba group equals a fresh `build()` on that group's block table in every metadata field (recursively over nested dataclasses), so a per-group field added later cannot stay pointed at the source group; fails before #59536 on `checkpoint.state_indices` |
| `tests/v1/kv_offload/test_glm5next_pruned_e2e.py` | 1 | SimpleCPUOffloadConnector / OffloadingConnector round trip through `reset_prefix_cache`, asserting CPU hits and identical tokens. Fails on main today because the kpool tail group (block 4, not prefix-cacheable) is not skipped (`resolve_block_hashes` assert / `tokens_per_block=4 not divisible by tokens_per_hash`); SimpleCPUOffload passes with #56810. |
| `tests/v1/kv_connector/nixl_integration/run_glm5next_pd_test.sh` + `test_hybrid_pd_consistency.py` | 2 | NixlConnector 1P1D with `VLLM_SSM_CONV_STATE_LAYOUT=DS`; reuses `test_mamba_prefix_cache.py` (its ~9000-token prompt spans two 4352-token blocks) and checks P-only vs P->D top-1 logprobs within a tolerance. Hybrid PD recomputes the last prompt token on D (`_prefill_backoff`), so exact text equality as in `test_edge_cases.py` is not the right assertion for this model. |

Buildkite: single-GPU jobs on `h200_35gb` (models_language.yaml, lm_eval.yaml), the PD job on 2x `h100`
(disaggregated.yaml); MIG slices cannot do cross-device NIXL and the existing PD sweeps run on L4. The
Pruned E2E step also depends on `vllm/v1/attention/backends/gdn_attn.py`, `vllm/model_executor/layers/mamba/`,
`vllm/v1/worker/gpu/` and `vllm/v1/core/`: #58762 (cross-group metadata reuse) changed only those paths and
would not have triggered a step keyed on `vllm/models/glm5next/` alone.

Known interactions: #55219 (draft) replaces `KpoolTailSpec` with a `CircularBufferSpec` tail, which
would change the spec names asserted in `test_kv_cache_layout`.

plain test now), #56810 (SimpleCPUOffload tail-group skip, the offload test's expected fix), #55219 (tail spec
rework), #59536 (the checkpoint-page regression the new test guards; merged 2026-10-01).

`token_logprobs` contains each run's selected token probability, but the selected token identities are discarded.
