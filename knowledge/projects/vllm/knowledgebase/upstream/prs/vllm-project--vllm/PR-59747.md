# [Bugfix][NIXL] Reject push handshakes between different P/D block sizes

[Upstream PR](https://github.com/vllm-project/vllm/pull/59747) · state: open · merged: False

## Original PR description

## Overview

NixlPushConnector now rejects P/D peers with different block sizes at the handshake, so their requests fail at once instead of stalling or crashing D.

## Claims

- A P/D pair that differs in kernel block size or kernel blocks per logical block is rejected at the handshake: each request fails at once and D keeps serving.
- Pull and equal-block-size push are unchanged.

## Validation

```bash
pytest tests/v1/kv_connector/unit/test_nixl_push_connector.py tests/v1/kv_connector/unit/test_nixl_desc_geometry.py
```

`test_push_handshake_rejects_different_block_sizes` covers the new check. Of the two tests of the removed check, `test_layer_handshake_rejects_unsupported_geometry` keeps only its TP case, and `test_packed_mla_rejects_unequal_block_sizes_before_peer_registration` is removed: the new check does not depend on packed MLA or PP and runs before any registration.

CPU, this PR at `22086c1844` on main `89ac8d971b`: the new test's 3 cases fail without this PR and pass with it. Other NIXL unit tests are unchanged.

GB10, Qwen3-0.6B, NixlPushConnector, P and D on one GPU, greedy, `--enforce-eager`, main `0cbac6cd13` without and with this PR at `5a908a9e72`:
- P 16 / D 64, FLASH_ATTN: on main, P's handshake fails with `Local block size 16 is not divisible by remote block size 64` and D's requests are still pending after 150 s. With this PR, D's handshake raises `NixlPushConnector requires identical P/D block sizes.` and each request fails at once.
- FLASHINFER, P 128 / D 64, both with 64-token kernel blocks: on main, D's EngineCore dies with `IndexError: tuple index out of range` in `get_transfer_results`. With this PR, D's handshake rejects it the same way.
- In both rejected cases D keeps serving requests.
- 64/64: outputs and logprobs are bitwise equal to main's push.

## Details

NixlPushConnector cannot convert or re-pair blocks when P and D differ in kernel block size or kernel blocks per logical block, and D registers P for notifications without checking either. On main, for such a pair:

1. D handshakes with P and sends `PUSH_REG` with its block ids.
2. P handshakes with D and WRITEs into those blocks. Depending on the sizes, P's handshake fails or P writes misaligned blocks.
3. D waits for a WRITE that never comes, or its receive fails on the block-size-ratio assert or on empty push block ids.

This PR rejects such peers in `_validate_remote_parallel_config`, which `_nixl_handshake` runs for P's and both of D's handshakes (registration and heartbeat) before registering the peer, so the request fails like any failed handshake. It replaces the PP-only block-size check in `add_remote_agent` and removes push's `block_size_ratio > 1` branch in `_xfer_blocks`, which can no longer run.

No open PR rejects push peers with different block sizes.
