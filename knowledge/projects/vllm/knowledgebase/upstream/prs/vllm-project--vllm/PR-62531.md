# [ROCm][CI] Bump the default ROCm image to ROCm 10.1; use TheRock's triton wheel

[Upstream PR](https://github.com/vllm-project/vllm/pull/62531) · state: closed · merged: False

## Original PR description

Bumps the default TheRock image from ROCm 10.0 to 10.1, keeping torch 2.13 (`2.13.0+rocm10.1.0`).

TheRock's 10.1 torch pins `triton==3.8.0+git669b31ac.rocm10.1.0`, the `release/internal/3.8.x` commit we build from source today, so this also:
- installs TheRock's triton wheel; drops the triton source build, the torch repack and the torch METADATA edit
- drops the nightly extra index: every pin resolves from `stable.repo.amd.com/rocm/whl-next`
- deletes the unused `requirements/build/rock.txt`, refreshes `requirements/build/rocm.txt`

The variant becomes `rocm101` (setup.py derives it from the SDK version): renames the release pipeline's `rocm100` steps and the perf-eval image tag, and updates the install docs. `:nightly`/`:latest` move to 10.1; `nightly-rocm100` stops updating.

**Open**
- `build_rocm_runtime` (patched ROCr/CLR from rocm-systems `25e14349`) is kept; need to confirm it still builds on 10.1 / whether 10.1 already carries the fixes
- Recipes pinned to `nightly-rocm100` (DeepSeek-V4.1-Flash, Kimi-K3) need re-verification on `nightly-rocm101` by their owners

Conflicts with #61939 and #62530 (same `Dockerfile.rocm_base` lines); will rebase. No other open PR bumps ROCm to 10.1.

**Test**
- `pip install --dry-run` (stable index only) of SDK 10.1, torch/torchvision/torchaudio, device extras and triton: resolves, all from stable
- `therock_wheels.py external-links` with the new Dockerfile + real torch wheel: all 36 linked projects (9 arches) found
- Image build + GPU tests: pending CI

AI assistance (Claude Code) was used; I reviewed every change.
