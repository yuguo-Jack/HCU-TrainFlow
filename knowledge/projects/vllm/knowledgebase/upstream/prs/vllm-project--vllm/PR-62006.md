# [Feature] Chi-squared and perplexity watermarking

[Upstream PR](https://github.com/vllm-project/vllm/pull/62006) · state: open · merged: False

## Original PR description

## Overview

Adds the chi-squared watermark and the two perplexity watermarks, `ppl_hard` and `ppl_soft`, from [Gloaguen et al. (2026)](https://arxiv.org/abs/2602.06754). The implementation is built on top of the watermarking infrastructure introduced in #53916 / #54053. 

## Claims

- `--watermark-config '{"algorithm": "chi_squared", "key": 42}'` samples from `q = p * w`, where `p` is the unwatermarked distribution, and `q` maximizes the expected watermark score minus a chi-squared distance from `p` (Theorem D.6 of the [Gloaguen et al. (2026)](https://arxiv.org/abs/2602.06754)). Each token score is Binomial(30, 1/2), computed using the Philox PRF from the key and the last `context_width` tokens (default 4). The variable `delta` (default 1.0) sets the strength of the watermark.
- `"algorithm": "ppl_hard"` and `"ppl_soft"` use the same scores, but bound the expected surprisal `-log p` of the watermarked token above the model's entropy. The variable `epsilon` (default 0) is that budget in nats, met for every key (`ppl_hard`) or on average over keys (`ppl_soft`).
- `BinomialScoreWatermarkDetector` returns a one-sided binomial p-value for all three.
- All three reject speculative decoding, also with `allow_target_only_watermarking: true`.

## Validation

Tests: `tests/watermarking/test_chi_squared.py`, `test_perplexity.py` and `test_binomial.py` (new), the new golden candidates (`tests/watermarking/golden_candidates.py`, `watermarking_goldens.json`), `tests/watermarking/test_watermarking_e2e.py`, `test_watermarking.py`, `tests/test_config.py`, `tests/model_executor/test_watermark_sample_warmup.py`.

**Parity with the reference implementation.** A separate harness ran each watermark in vLLM and in the authors' implementation ([eth-sri/unified-watermarking](https://github.com/eth-sri/unified-watermarking), as Model Runner V1 logits processors) with the same model, prompts, sampling settings and keys: Qwen3.8-27B, 100 prompts each from ELI5 economics, ELI5 mathematics, WildChat and MMLU-Pro, 5 keys, temperature 0.7, top-k 50, 10 to 512 new tokens, context width 4, and vLLM's context deduplication off, as the reference has none. The two sides derive their randomness differently (Philox over the ordered context in vLLM, SumHash in the reference), so their texts differ, and the harness compares distributions: intervals come from a bootstrap over prompts and keys, and |z| ≥ 3 flags a difference. For chi-squared, the reference's `log w` is multiplied by `T`, so that both sides sample `p * w`.

| Watermark | Strength | TPR@1% FPR: reference -> vLLM |
|---|---|---|
| chi-squared | delta = 1.0 | 0.865 -> 0.861  |
| `ppl_hard` | epsilon = 0.2 | 0.849 -> 0.841  |
| `ppl_soft` | epsilon = 0.1 | 0.942 -> 0.936  |

The signal is the mean standardized score of a generated token. Excess surprisal is the mean of `-log p(x) - H(p)` over generated tokens, in nats, where `p` is the distribution the watermark saw.

## Details

- **Fused sampling:** after a log-sum-exp pass, `_philox_score_levels_kernel` reads each row's logits once more and reduces them to the 31 score levels. Each algorithm then works on the levels instead of the vocabulary, without host synchronization:
  - chi-squared solves for its normalizer on the levels and adds `log w` to the logits, and the request's Gumbel sampler draws the token;
  - `ppl_hard` solves the linear program on 32 candidates, the most probable token of each score and the least probable token of the top score, and draws from the solution with the noise `gumbel_sample` uses;
  - `ppl_soft` finds `beta` by bisection over 128 Monte Carlo draws, each drawn as the ranks at which the scores first appear in probability order, instead of scoring the vocabulary 128 times.
- **Faithfulness:** each kernel follows a function adapted from reference code. As in the reference implementation, an output's first `context_width` tokens are sampled without the watermark and are not scored. Two differences are deliberate: `ppl_soft` draws and selects among the 4096 most probable tokens only, and `ppl_soft` derives its Monte Carlo draws from the context with a public Philox key instead of drawing them anew at every step, so its output is reproducible and independent of the rest of the batch.
- **Logprobs:** processed logprobs report the logits before the watermark, same as for Gumbel-max.
- **Detection:** a token's score is the number of Binomial(30, 1/2) CDF thresholds below its Philox uniform, so the detector recomputes it from token IDs alone. In case of no watermark, the summed score of `n` tokens is Binomial(30n, 1/2). The p-value is the survival probability of the summed score under Binomial(30n, 1/2).
- **Docs:** `docs/features/watermarking.md` has chi-squared and perplexity sections with usage.
