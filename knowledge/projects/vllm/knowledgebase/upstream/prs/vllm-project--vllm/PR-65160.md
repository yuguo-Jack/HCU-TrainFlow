# [Feature][MooncakeStore] Add automatic deployment cache prefixes

[Upstream PR](https://github.com/vllm-project/vllm/pull/65160) · state: open · merged: False

## Original PR description

## Overview

Add an opt-in automatic deployment namespace to MooncakeStoreConnector so code or configuration changes can invalidate shared KV cache without a manually calculated prefix.

## Claims

- `kv_connector_extra_config.cache_prefix="auto"` derives a full SHA-256 prefix from build identity, effective configuration, and relevant environment settings.
- Custom prefixes and the empty default retain their behavior. Scheduler capacities and derived batch sizes do not change the namespace.
- Composed online quantization is supported; its runtime timers and layer inventory are excluded.

## Validation

- 34 configuration/key regression tests passed: `python -m pytest --confcutdir=tests/config tests/config/test_mooncake_cache_prefix.py -k 'not test_llm' -q` in a temporary uv-managed Python 3.12 environment on macOS.
- The new online-quantization regressions reproduced three failures before the serializer fix and passed afterward.
- 6 existing Docker build-metadata tests passed: `python -m pytest --confcutdir=tests/tools tests/tools/test_docker_build_metadata_args.py -q`.
- All pre-commit hooks passed, including Ruff, mypy, documentation lint, and Buildkite test wiring; `git diff --check` passed. A Buildkite step includes the full suite and the real `LLM` startup regression.
- GPU startup, real Mooncake transfers, model-output evaluations, and performance benchmarks have not been run locally. This is a draft starting point for review and GPU validation; no accuracy or performance improvement is claimed.

## Details

The worker resolves the prefix once before Store initialization. Public release builds already embed `VLLM_IMAGE_TAG` and `VLLM_BUILD_COMMIT`; custom builds must supply an immutable image identity or a known commit. Missing/default development identities fail startup in automatic mode.

`cache_prefix.py` contains the fingerprint logic and explicit exclusions. Worker integration is limited to resolving the existing metadata field. The docs explain enablement and compatibility; tests cover stable replica keys, invalidation, batching exclusions, environment filtering, and nested quantization.

Isolation is conservative and can partition compatible deployments. The exact string `auto` becomes reserved. Live weight updates or overwriting weights without changing their identity are not detected. Unregistered plugin variables outside the documented environment families must be represented in configuration or added to the fingerprint.

Related upstream work: https://github.com/vllm-project/vllm/pull/56971 fingerprints the resolved Store payload format and changes the default key format. This draft adds a separate opt-in deployment namespace that also changes with code/image identity and environment settings while preserving the default and literal custom prefixes. It complements payload-format compatibility checks rather than implementing the decode-phase Mamba/GDN fixes in that PR.

This upstream draft replaces the starting-point PR at https://github.com/hj-mistral/vllm/pull/2. The signed branch predates current upstream main by 40 commits; a merge-tree check against upstream commit `30565c39372c08b91d164779a120b1f3ba77dc85` reported no conflicts. GPU/Store validation remains outstanding before review readiness.
