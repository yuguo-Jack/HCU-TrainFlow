# [Bugfix][Rust Frontend] Fix macOS build: read inherited listener family from its address

[Upstream PR](https://github.com/vllm-project/vllm/pull/62177) · state: closed · merged: True

## Original PR description

## Purpose

Fixes the macOS arm64 CPU wheel build, which fails on main (release-v2 #8588) and on `releases/v0.32.0` (release-v2 #8575):

```
error[E0599]: no method named `domain` found for struct `socket2::Socket` in the current scope
 --> src/engine-core-client/src/transport.rs:408:25
408 |     let domain = socket.domain()?;
```

#54113 uses `socket2::Socket::domain()` (`SO_DOMAIN`) in `adopt_listener` to tell inherited TCP and Unix listeners apart. socket2 only provides that method on Linux, Android, FreeBSD and Fuchsia, so `vllm-rs` doesn't compile on macOS. The macOS wheel is in the "additional wheels" group, which only runs when unblocked, so nothing caught this when it landed.

## Change

Read the family from the listener's bound address instead: `socket.local_addr()?.domain()`. `SockAddr::domain` works on every platform. The TCP/Unix branching after it is unchanged.

Also adds `inherited_unix_listener_is_adopted_without_rebinding`, a Unix-socket counterpart to the existing inherited TCP listener test. Before this, the Unix branch had no test.

## Test Plan

On macOS (arm64, rustc 1.95):
- `cargo check -p vllm-engine-core-client`: failed with the error above before the change, passes after.
- `cargo test -p vllm-engine-core-client inherited`: both inherited listener tests pass (TCP and Unix).
- `cargo check --manifest-path rust/src/cmd/Cargo.toml --release --features native-tls-vendored --bin vllm-rs`, the wheel build's cargo invocation: passes.
- `cargo fmt --check` and `cargo clippy --all-targets`: clean.

Linux CI covers the Linux path.

Wanted for v0.32.0 (milestone "v0.32.0 cherry picks"), since it blocks the macOS wheel there too.
