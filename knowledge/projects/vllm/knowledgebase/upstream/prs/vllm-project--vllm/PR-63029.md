# [ROCm][DSv4.1] Dispatch pre-quantized MXFP4 through MoRI for the A4W4 MoE

[Upstream PR](https://github.com/vllm-project/vllm/pull/63029) · state: open · merged: False

## Original PR description

## Motivation

With `VLLM_ROCM_USE_AITER_MOE_A4W4_DSV4=1`, DeepSeek-V4.1's routed experts run AITER's A4W4 MoE: the activations are quantized to MXFP4 (group-32, E8M0 scales) inside `fused_moe`. Under MoRI expert parallelism they are therefore dispatched as BF16, 2 bytes per element, and every rank a token is routed to quantizes it again on arrival — about 4.4 of 8 ranks at topk=6 for DeepSeek-V4.1-Flash (the same accounting as #61962).

#59596 added the pre-quantized route for mxfp4 w4a4: the rank that owns a token quantizes it once in `prepare()`, MoRI moves packed FP4 plus E8M0 block scales (0.5 + 1/32 bytes per element, about a quarter of BF16), and AITER takes the pre-quantized input, sorting only the scales (`mxfp4_moe_sort_fwd`). This PR lets the DeepSeek-V4.1 A4W4 path take the same route.

## Summary of changes

- **`envs.py`**: `VLLM_MORI_A4W4_FP4_DISPATCH` (default off).
- **`all2all_utils.py`**: `use_fp4_dispatch` is also set when `moe.use_mxfp4_w4a4_dsv4` and the flag are. DeepSeek-V4.1 A4W4 runs on a W4A16 quant config whose activations AITER quantizes to MXFP4, so `quant_config.use_mxfp4_w4a4` alone never selects it.
- **`experts/rocm_aiter_moe.py`**: `AiterExperts.workspace_shapes` already sizes the output at the unpacked hidden size (`K * 2`) for packed FP4 input under w4a4; the same predicate now covers this case. Without it the expert output is allocated at half the hidden size and the copy fails with `RuntimeError: The size of tensor a (2560) must match the size of tensor b (5120)`.

Opt-in because the A4W4 path itself is opt-in; happy to make it the default for A4W4 with MoRI if preferred.

The flag applies to MoRI EPv1 (`mori_high_throughput`, `mori_low_latency`, or `mori` with `VLLM_MORI_EP_V2=0`). EPv2 (#61361) dispatches BF16 and ignores it.

Engagement: the dispatch kernel switches from `EpDispatchIntraNodeKernel_bf16` to `EpDispatchIntraNodeKernel_fp4`. In a DEP8 decode profile at concurrency 256 (8x MI355X), the dispatch on the last-arriving rank — its own transfer cost, with no waiting for peers — drops from 48.5 to 28.0 µs per MoE layer, and the time per decoder layer from 729 to 709 µs.

## Results

8x MI355X (gfx950), DeepSeek-V4.1-Flash, DEP8 with `mori_high_throughput`, A4W4 MoE (`VLLM_ROCM_USE_AITER_MOE_A4W4_DSV4=1`), speculative decoding and prefix caching off. 8192 in / 1024 out with `--ignore-eos`, 4 x concurrency prompts, against the stock nightly (`0.32.0rc1.dev190+g3f1bcfd82`) with **only this change applied**.

## Reproduction

Server (the patched arm adds `VLLM_MORI_A4W4_FP4_DISPATCH=1`):

```bash
export VLLM_ROCM_USE_AITER=1
export VLLM_ROCM_USE_AITER_MOE=1
export VLLM_ROCM_USE_AITER_MOE_A4W4_DSV4=1
export VLLM_ROCM_USE_AITER_TRITON_SPARSE_MLA=True
export VLLM_USE_BREAKABLE_CUDAGRAPH=1
export VLLM_USE_RUST_FRONTEND=1
export MORI_SHMEM_HEAP_SIZE=16G  # MoRI's buffers at 8192 batched tokens outgrow the 2 GB default

vllm serve /model/DeepSeek-V4.1-Flash \
  --served-model-name deepseek-ai/DeepSeek-V4.1-Flash \
  --tensor-parallel-size 1 \
  --data-parallel-size 8 \
  --enable-expert-parallel \
  --all2all-backend mori_high_throughput \
  --moe-backend aiter \
  --max-model-len 16384 \
  --gpu-memory-utilization 0.9 \
  --max-num-batched-tokens 8192 \
  --max-cudagraph-capture-size 1024 \
  --block-size 128 \
  --tokenizer-mode deepseek_v41 \
  --tool-call-parser deepseek_v41 \
  --reasoning-parser deepseek_v41 \
  --enable-auto-tool-choice \
  --language-model-only \
  --no-swa-bounded-replay \
  --no-enable-prefix-caching \
  --disable-uvicorn-access-log \
  --attention-config '{"indexer_kv_dtype":"mxfp4","indexer_sparse_logits":true}'
```

Benchmark, at concurrency 64, 128 and 256 with 4 x concurrency prompts:

```bash
vllm bench serve \
  --model deepseek-ai/DeepSeek-V4.1-Flash \
  --tokenizer /model/DeepSeek-V4.1-Flash \
  --dataset-name random \
  --random-input-len 8192 \
  --random-output-len 1024 \
  --ignore-eos \
  --num-prompts 256 \
  --max-concurrency 64 \
  --temperature 0 \
  --seed 0 \
  --percentile-metrics ttft,tpot,itl,e2el \
  --metric-percentiles 50,90,99
```

Accuracy:

