# [Dependency] Upgrade FlashInfer to 0.7.2 and restore KDA auto backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/61913) · state: closed · merged: True

## Original PR description



## Overview

Upgrade FlashInfer to 0.7.2 and let FlashInfer select the Kimi-K3 KDA prefill backend. Follows #60948, which pinned 0.7.1 and forced `cute-dsl`.

## Claims

- Pin `flashinfer-python==0.7.2` in `requirements/cuda.txt`.
- Pass `backend="auto"` from `_flashinfer_kda_prefill`.

## Validation

Passed locally:

```bash
.venv/bin/pre-commit run --files requirements/cuda.txt vllm/models/kimi_k3/nvidia/kda.py
.venv/bin/python -m py_compile vllm/models/kimi_k3/nvidia/kda.py
git diff --check
```

GPU tests, end-to-end serving, model evaluations and benchmarks were not run; this host has no NVIDIA GPU. Existing KDA prefill and CUDA graph tests in `tests/models/kimi_k3/test_kda.py` still need validation with 0.7.2. No accuracy or performance claim is made.

## Details

This changes two values and uses FlashInfer's existing dispatcher. Automatic selection can choose a different kernel from the previous forced CuTe DSL path, so GPU validation remains pending.

Duplicate checks found no open PR for this version bump (searches: `60948 in:body`, `"0.7.2"`, and `FlashInfer KDA`). Related #61250 adds configurable GDN/KDA backends and a shared adapter; it does not update the dependency pin. #60470 concerns KDA decode, while this change concerns prefill.
