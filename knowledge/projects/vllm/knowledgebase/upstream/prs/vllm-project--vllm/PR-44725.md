# [Bugfix][Frontend] Fix Anthropic count_tokens decorator order driving server load negative

[Upstream PR](https://github.com/vllm-project/vllm/pull/44725) · state: closed · merged: True

## Original PR description

## Purpose

The Anthropic `/v1/messages/count_tokens` route nests its decorators in the reverse order of every other load-aware route:

```python
# create_messages (and the OpenAI routes): correct
@with_cancellation
@load_aware_call

# count_tokens: reversed
@load_aware_call
@with_cancellation
```

On a client disconnect this double-counts the load decrement:

- `load_aware_call` increments `server_load_metrics` on entry.
- `listen_for_disconnect` sees `http.disconnect` and decrements it once.
- `with_cancellation` cancels the handler and returns `None` (it does not raise).
- The outer `load_aware_call` sees a non-`Response` return value, takes its else-branch, and decrements a second time.

`server_load_metrics` goes negative and stays there. With `--enable-server-load-tracking`, `/load` then under-reports (negative), which breaks autoscaling / load-balancing decisions that read it.

In the correct order the handler being cancelled propagates `CancelledError` out of `load_aware_call`'s `await func` (not caught by its `except Exception`), so the counter is decremented exactly once.

Fix: swap the two decorators to match `create_messages`.

## Test Plan

Verified against a live server by polling `GET /load` before and after mid-request client disconnects on `/v1/messages/count_tokens`.

## Test Result

Real `vllm serve --enable-server-load-tracking` (TinyLlama-1.1B, served as `claude-3-7-sonnet-latest`), poll `GET /load`:

| step | before (reversed) | after (fixed) |
| --- | --- | --- |
| initial | `0` | `0` |
| after a normal count_tokens | `0` | `0` |
| after 8 disconnect-mid-request | `-8` (persistent) | `0` |

Each disconnect nets `-1` on the buggy order; with the fix `/load` stays `0`.

<details>
<summary>repro (serve + disconnect client)</summary>

```bash
vllm serve TinyLlama/TinyLlama-1.1B-Chat-v1.0 \
  --served-model-name claude-3-7-sonnet-latest \
  --enforce-eager --max-model-len 2048 --enable-server-load-tracking
```

```python
# send a count_tokens request with a large body, then close without reading
# the response, so the disconnect is detected before the handler finishes.
import socket, json
body = json.dumps({"model": "claude-3-7-sonnet-latest",
                   "messages": [{"role": "user", "content": "x " * 120000}]})
req = ("POST /v1/messages/count_tokens HTTP/1.1\r\nHost: 127.0.0.1\r\n"
       "Content-Type: application/json\r\n"
       f"Content-Length: {len(body)}\r\nConnection: close\r\n\r\n" + body)
for _ in range(8):
    s = socket.create_connection(("127.0.0.1", 8000))
    s.sendall(req.encode()); s.shutdown(socket.SHUT_RDWR); s.close()
# curl http://127.0.0.1:8000/load  ->  {"server_load":-8} before, {"server_load":0} after
```
