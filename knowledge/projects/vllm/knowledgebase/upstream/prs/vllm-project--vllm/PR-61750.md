# [Bugfix][Metrics] Clean up live gauges in spawned API workers

[Upstream PR](https://github.com/vllm-project/vllm/pull/61750) · state: open · merged: False

## Original PR description

## Overview

Clean up the exiting API worker's live Prometheus gauges using `PROMETHEUS_MULTIPROC_DIR`. Spawned workers inherit this path but not the parent's `TemporaryDirectory` object, so their current shutdown returns without marking the process dead.

## Claims

- Remove only the current process's live gauge files during shutdown, including when the metrics directory is supplied by the user.
- Preserve other processes' gauge contributions and accumulated counters. Repeated shutdown remains safe.

## Validation

On DGX Spark with Python 3.12 and the current source:

```bash
PYTHONPATH=. ~/vllm-work/testenv2/bin/python -m pytest --confcutdir=tests/v1/metrics tests/v1/metrics/test_prometheus.py tests/v1/metrics/test_metrics_reader.py -q
```

10 tests pass. Both new subprocess cases fail on the original implementation: the aggregated live gauge remains 10 after one worker calls shutdown, instead of dropping to 5. With the fix, the remaining worker contributes 5 and the counter total stays 6. The cases cover automatic and externally configured directories and call shutdown twice.

Changed-file pre-commit passes. The new tests are marked `cpu_test` and are covered by the existing `v1/metrics` CPU test command in `.buildkite/test_areas/misc.yaml`.

A broader run including `test_histogram_buckets.py` had 22 passes and four failures. The same four histogram registration cases also fail on the original code because this environment lacks the CUDA FlashAttention extensions used for model inspection. No model generation or full serving benchmark was run. The focused command isolates these CPU tests from the root model fixtures.

## Details

`run_multi_api_server()` creates the shared metrics directory before starting the API workers. `AsyncLLM.shutdown()` calls this cleanup helper in each worker, where the process-local directory owner is absent. Read the same environment path used by the Prometheus collector and pass it to `mark_process_dead()`. The parent retains ownership of directory cleanup.

This concerns live gauges, including WebSocket connections and in-flight sleep and weight operations. It does not change non-live gauge modes, counters, sampling, or model execution, and does not add cleanup for a process killed without running shutdown.

Open PR and issue searches for `shutdown_prometheus`, `mark_process_dead`, `Prometheus multiprocess`, `stale gauge`, and `metrics process cleanup` found no overlapping fix. #50878 concerns external stat logger providers. #61748 concerns counter snapshot precision.
