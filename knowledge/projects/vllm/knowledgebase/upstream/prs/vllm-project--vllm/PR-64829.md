# [CPU][Perf] Speed up GDN speculative-decode recurrent update

[Upstream PR](https://github.com/vllm-project/vllm/pull/64829) · state: open · merged: False

## Original PR description

**Purpose:** Speed up `fused_sigmoid_gating_delta_rule_update_spec_cpu`, which runs in every GDN layer during speculative-decode verify on CPU (e.g. Qwen3.5/3.6 with DFlash/MTP).
- Work is split over (sequence, value head, 64-column block) instead of (sequence, value head). At batch 1, Qwen3.6 now has 64 work items instead of 32.
- Each item loads its fp32 state block once and keeps it in cache across all draft tokens. The old kernel re-read the previous slot twice per token.
- The per-token intermediate states, which are only read again on a later step, are written with streaming stores (AVX-512, aligned addresses). This avoids the read-for-ownership on every store.

**Test plan:**
- New `test_fused_sigmoid_gating_delta_rule_update_spec_cpu`: fp32/bf16/fp16 state; uneven, empty and 0-accepted rows; value dim not a multiple of the vector width. All existing GDN CPU tests pass.
- New `benchmarks/kernels/cpu/benchmark_cpu_gdn_spec.py`: cold-state, 30 layers.

**Results (GCP c4-standard-48, 23 threads):**
- Kernel, 30 layers, 8 tokens: fp32 state 9.01 → 4.91 ms (−45%); bf16 state 4.90 → 2.61 ms (−47%).
- End-to-end, Qwen3.6-35B-A3B + DFlash2 (7 speculative tokens), HumanEval, concurrency 1: median ITL 127.85 → 120.08 ms (−6.1%), mean TPOT 23.23 → 22.07 ms (−5.0%), output throughput 38.17 → 39.92 tok/s (+4.6%). Acceptance length 5.58 vs 5.53.

**Kernel, batch scaling (fp32 state, 8 tokens per request, 30 layers):**

 | batch | before | after |
 |---|---|---|
 | 1 | 8.97 ms | 5.45 ms (−39%) |
 | 4 | 28.60 ms | 20.77 ms (−27%) |
 | 16 | 110.86 ms | 82.89 ms (−25%) |

 **Accuracy:** gsm8k (5-shot, limit 200) through the full DFlash2 + Qwen3.6-35B-A3B server: 0.290 after vs 0.295 before (±0.032 standard error). Outputs are not bit-identical: the summation order changed, and with bf16/fp16 state the running state stays fp32 between draft tokens within a step.

 **Tests:**
 - `pytest tests/kernels/mamba/cpu/test_cpu_gdn_ops.py`: 224 passed, including the new spec-kernel test with an unaligned state cache.
 - `pytest tests/v1/e2e/test_cpu_spec_decode.py -k mtp`: Qwen3.5-0.8B (GDN) with MTP, 1 passed.
