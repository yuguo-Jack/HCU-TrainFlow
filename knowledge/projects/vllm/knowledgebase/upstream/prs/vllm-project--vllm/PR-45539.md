# Fix moe_wna16 sorted token bounds

[Upstream PR](https://github.com/vllm-project/vllm/pull/45539) · state: open · merged: False

## Original PR description

## Purpose

Fixes #45496.

Prevents `moe_wna16_gemm` from reading past the end of `sorted_token_ids` when `num_tokens_post_pad[0]` covers more padded token slots than the allocated sorted-token buffer. The kernel now receives the actual `sorted_token_ids` length, guards both sorted-token reads with that length, and exits early when a block has no valid tokens.

## Test Plan

- Add a CUDA regression that recreates the reported `size_m=17`, `BLOCK_SIZE_M=16`, `sorted_token_ids.shape=[129]`, `num_tokens_post_pad=144` case.
- Run local whitespace and Python syntax checks.
