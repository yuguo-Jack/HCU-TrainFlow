# [Feature] Conditional prefix logging for stdout/stderr

[Upstream PR](https://github.com/vllm-project/vllm/pull/28582) · state: open · merged: False

## Original PR description

~~Add conditional logging prefixing based on `VLLM_ENABLE_PREFIX_PROC_LOGS` environment variable.~~

**Update:** per [@markmc's suggestion](https://github.com/vllm-project/vllm/pull/28582#issuecomment-3526137301) (see also #25700, #28666), this now uses an explicit `--log-prefix` / `--no-log-prefix` CLI argument and `ObservabilityConfig.log_prefix` config setting instead of an environment variable.

## Suggestion
Python's logging module already exposes `processName` as a standard LogRecord attribute `(%(processName)s)`, giving users full control over format without custom code. 

Separately: in enterprise environments, logs need to be parseable — no ANSI colors (breaks parsers/log aggregators), and a consistent format across all services.

__add_prefix works against both: it hardcodes format/color outside the standard Formatter pipeline, so users can't override or reposition it, and it likely forces colors even in non-TTY/production contexts.

**Basic example**: Companies using ELK stack, must update their parsers just for vLLM. 

I would recommend to deprecated this feature and instead encourage people to use logging format. 
- https://docs.python.org/3/library/logging.html#logging.LogRecord
- https://docs.vllm.ai/en/stable/examples/others/logging_configuration.html?h=logging

## Code Review

This pull request introduces a way to conditionally disable the prefixing of logs on stdout and stderr by using the `VLLM_PREFIX_LOGS` environment variable. This is a useful feature for environments where structured logging is important. However, the implementation has a critical flaw: the new environment variable `VLLM_PREFIX_LOGS` is used in `vllm/utils/system_utils.py` but is not defined in `vllm/envs.py`, which will cause a runtime `AttributeError`. I've added a comment with a suggestion on how to fix this. I've also suggested adding automated tests for this new functionality to prevent future regressions.

This will enable prefixes by default and allow users to disable them by setting `VLLM_PREFIX_LOGS=0`.
