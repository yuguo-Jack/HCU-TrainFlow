# [Bugfix][Frontend] Count prompts over max_model_len in Anthropic count_tokens

[Upstream PR](https://github.com/vllm-project/vllm/pull/65697) · state: open · merged: False

## Original PR description

## Overview

`/v1/messages/count_tokens` returns HTTP 400 ("This model's maximum context length is ...") for any conversation longer than `max_model_len`, so a client cannot learn how long such a conversation is, which is exactly when it needs the number to trim it. `/tokenize` counts the same messages. This makes `count_tokens` tokenize without the context-length check, as `/tokenize` does; generation requests keep the check.

## Claims

- `/v1/messages/count_tokens` returns `input_tokens` for a prompt longer than `max_model_len`, equal to the `/tokenize` count for the same messages, instead of a 400.
- Prompts within the limit are counted as before, and `/v1/messages` and `/v1/chat/completions` still reject over-length prompts.

## Details

- Root cause: `count_tokens` converts the request with `to_chat_completion_request` and renders it through `render_chat_request`, which tokenizes with `ChatCompletionRequest.build_tok_params` (`max_total_tokens=max_model_len`). Tokenization then stops at `max_model_len + 1` tokens and `_token_len_check` raises. `/tokenize` renders with `max_total_tokens=None`.
- Fix: `render_chat_request`, `OnlineRenderer.render_chat` and `OnlineRenderer.preprocess_chat` take an optional `tok_params` that replaces `request.build_tok_params(...)`; the default keeps the current behavior. `count_tokens` passes the chat request's own params with `max_total_tokens=None`, which turns off both the length check and the early truncation.
- Harmony (gpt-oss) chat rendering does not apply tokenization params, so `count_tokens` already counted over-length prompts there; unchanged.
- Counting an over-length prompt now tokenizes all of it, the same work `/tokenize` already does for such a prompt; generation paths are unchanged.
- Why count rather than reject: Anthropic presents token counting as the way to check that a prompt fits the context window before sending it ("Use token counts to ... fit prompts to a target length", [token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting)), and an error that says "at least 2049" does not tell the client how much to trim. #64050 (open) adds an OpenAI Responses `input_tokens` endpoint that mirrors the generation request's validation; this PR does not touch it.
- #61063 (open) also adds a keyword argument to `render_chat_request` / `render_chat`, to skip tool-parser validation when counting. The two changes are independent; whichever lands second needs a trivial rebase.

Not a duplicate: searched open and closed issues and PRs for `count_tokens` (by title: #63573/#61063 tool-parser requirement, #59180 thinking and `output_config`, #52896/#47753 Rust frontend, #44725 load counter, #35588 the original endpoint), "count_tokens max_model_len", "count_tokens maximum context length" and "count tokens context length". #59616/#59617 (open) change `/v1/messages` context-overflow errors and stop reasons, not counting.
