# [Bugfix] Omit inactive CP checkpointing kwargs in FlashInfer GDN prefill

[Upstream PR](https://github.com/vllm-project/vllm/pull/65491) · state: open · merged: False

## Original PR description

## Overview
In `vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py`, `fi_chunk_gated_delta_rule` unconditionally passes context-parallel (CP) checkpointing keyword arguments (`state_checkpoints`, `checkpoint_cu_starts`, `checkpoint_every_n_tokens`, `use_cp`, `backend="flashinfer"`) to `flashinfer.gdn_prefill.chunk_gated_delta_rule(...)`.

On `flashinfer <= 0.6.6` (which does not accept CP checkpointing keyword arguments in `chunk_gated_delta_rule`), running any Qwen3Next / Qwen3.5 GDN model on SM90 (H100) crashes during prefill warmup with:
```text
TypeError: chunk_gated_delta_rule() got an unexpected keyword argument 'state_checkpoints'
```
even when context-parallel checkpointing is completely inactive (`state_checkpoints is None` and `not use_cp`). This forces users on H100 (`SM90`) to fall back to `--gdn-prefill-backend triton`, losing both FlashInfer SM90 tensor-core prefill speed and exact FP32 recurrent state propagation into decode / speculative decoding drafters.

This PR guards the CP checkpointing keyword arguments in `fi_chunk_gated_delta_rule` so they are only passed to `flashinfer.gdn_prefill.chunk_gated_delta_rule` when CP checkpointing is active (`state_checkpoints is not None` or `checkpoint_cu_starts is not None` or `checkpoint_every_n_tokens > 0` or `use_cp`).

## Claims
- Fixes `TypeError: chunk_gated_delta_rule() got an unexpected keyword argument 'state_checkpoints'` on `flashinfer <= 0.6.6` when running Qwen3.5 / Qwen3Next GDN models on SM90 (H100) without CP checkpointing.
- Restores the default `--gdn-prefill-backend flashinfer` path on H100 NVL, reducing **mean TTFT by 6.35 ms (`70.93 ms -> 64.58 ms`, -9.0%)**, improving DFlash speculative decoding acceptance length $\tau$ from **`2.96` to `3.06`** (via exact FP32 recurrent state vs Triton BF16 state rounding), and reducing **mean E2EL by 11.29 ms (`307.75 ms -> 296.46 ms`)**.

## Validation

### 1. End-to-End Benchmark on NVIDIA H100 NVL
- **Hardware**: 1x NVIDIA H100 NVL (94 GB, SM90), `flashinfer 0.6.6`
- **Target Model**: `Qwen3_5ForConditionalGeneration` (Qwen3.5-4B, 24 GDN LinearAttention layers + 8 FullAttention layers)
- **Draft Model**: `z-lab/Qwen3.5-4B-DFlash` (`method="dflash"`, `num_speculative_tokens=8`)
- **Workload**: 512 production prompts (`<=4096` input tokens, `max_tokens=200`, `temperature=0.0`, `repetition_penalty=1.1`, `max_num_seqs=1`, `--mamba-ssm-cache-dtype float16`)

|---|---|---:|---:|---:|---:|---:|---:|

### 2. Unit Tests
```bash
pytest tests/kernels/mamba/test_gdn_prefill_flashinfer.py -v
```
- Added `test_flashinfer_gdn_prefill_omits_cp_kwargs_when_inactive` verifying that:
  1. When `fi_chunk_gated_delta_rule` is called with default arguments (`use_cp=False`, `state_checkpoints=None`), a FlashInfer implementation whose signature rejects `state_checkpoints` succeeds without `TypeError`.
  2. When `use_cp=True` (or CP checkpointing arguments are provided), the CP keyword arguments (`state_checkpoints`, `checkpoint_cu_starts`, `checkpoint_every_n_tokens`, `use_cp`, `backend="flashinfer"`) are forwarded as expected.

## Details
- In `fi_chunk_gated_delta_rule` (`vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py`), construct `cp_kwargs` only when `state_checkpoints is not None or checkpoint_cu_starts is not None or checkpoint_every_n_tokens > 0 or use_cp`.
