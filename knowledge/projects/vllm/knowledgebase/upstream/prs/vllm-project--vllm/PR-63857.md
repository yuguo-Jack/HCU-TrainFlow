# [Recipes Tool] Fix TP auto-detection for heterogeneous per-layer attention models

[Upstream PR](https://github.com/vllm-project/vllm/pull/63857) · state: closed · merged: True

## Original PR description


## Overview

Fix automatic tensor-parallel (TP) selection for models with heterogeneous per-layer attention configurations, such as Gemma 4.

Previously, accessing the global `num_key_value_heads` attribute raised an exception, causing the Recipes tool to fall back to TP=1.

Follow-up to [[PR #60170](https://github.com/vllm-project/vllm/pull/60170)](https://github.com/vllm-project/vllm/pull/60170).

## Claims

- Extract attention-head and KV-head constraints from individual layers.
- Support heterogeneous attention models without TP detection failures.
- Preserve existing TP compatibility checks and homogeneous model support.

## Validation

- Three targeted model tests passed.
- Gemma 4 on Xeon 6 (4 NUMA nodes): correctly selected TP=4 and initialized all four workers.
- Gemma 4 TP=4 subsequently encountered a KV-cache capacity issue; DiffusionGemma TP=2 encountered a runtime warmup stall. Both are outside the scope of this fix.

## Details

The original implementation assumed globally uniform KV-head counts. Models with heterogeneous attention configurations reject this global attribute access.

The fix extracts head constraints from each attention layer and uses the existing TP selection logic to determine a compatible TP size. No changes to inference kernels or distributed execution are required.
