# [Security] Fail EC NIXL reads when the ack block count mismatches

[Upstream PR](https://github.com/vllm-project/vllm/pull/58853) · state: open · merged: False

## Original PR description

## Summary
An ECCPUConnector NIXL consumer treats `ec_transfer_params` as the producer address and then trusts that peer's `XferAck.src_block_indices`. When that list is not the same length as the locally allocated blocks, `NixlDataTransport.post_read` raises `ValueError` inside the scheduler poll. The exception is not contained, so EngineCore shuts down. `ConsumerXfer.handle_ack` now rejects a non-list or wrong-length index list, and a `ValueError` from `post_read`, by returning failure. `ConsumerSession` already tombstones a failed ack, so the request fails or falls back to local encoding instead of killing the engine.

## Changes
- `vllm/distributed/ec_transfer/ec_connector/cpu/session.py`: reject a mismatched or non-list `src_block_indices` before issuing the NIXL read, and turn a `ValueError` from `post_read` into the same per-transfer failure.
- `tests/v1/ec_connector/unit/test_session.py`: cover the mismatch, a non-list index list, a `ValueError` from `post_read`, and session poll tombstoning that ack without completing the transfer.

## Codepath coverage
Every API that accepts `ec_transfer_params` (chat completions, completions, responses, Anthropic messages, and `/inference/v1/generate`) stores it on the v1 request. The consumer scheduler is the only caller of `ConsumerXfer.handle_ack`, and that is the only production caller of `NixlDataTransport.post_read`. The check sits on that shared path. Mooncake EC uses a different connector and is unchanged.

## Duplicate-work check
No open or merged PR already rejects a mismatched EC NIXL ack block count. Searched open and merged PRs for `src_block_indices`, `post_read`, `ec_transfer_params`, and `ec_connector/cpu`. Read the diffs of #57904 (Qwen3-Omni transfer shapes; does not touch ack validation), #57275 (Mooncake transfer lifecycle), #56814 (reserved keys inside `vllm_xargs`), and draft #57333 (CPU EC metrics). None of those diffs contain this check. #47941 introduced the connector and is already merged.
