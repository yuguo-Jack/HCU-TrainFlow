# [Bugfix][Frontend] Send `usage: null` on stream chunks when `include_usage` is set

[Upstream PR](https://github.com/vllm-project/vllm/pull/64573) · state: open · merged: False

## Original PR description



## Overview

Emit `"usage": null` on every streamed chunk before the final usage chunk when `stream_options.include_usage` is set, for `/v1/chat/completions` and `/v1/completions`, matching the OpenAI spec.

## Claims

- With `include_usage: true` (or `--enable-force-include-usage`), non-final chunks now carry `"usage": null` instead of omitting the field. The final `choices: []` usage chunk is unchanged.
- Without `include_usage`, output is unchanged (no `usage` key).
- `continuous_usage_stats` behavior is unchanged (every chunk already carries a populated `usage`).

## Validation

The OpenAI spec (`ChatCompletionStreamOptions.include_usage`, [openapi.yaml](https://github.com/openai/openai-openapi/blob/master/openapi.yaml)):

> If set, an additional chunk will be streamed before the `data: [DONE]` message. The `usage` field on this chunk shows the token usage statistics for the entire request, and the `choices` field will always be an empty array.
>
> All other chunks will also include a `usage` field, but with a null value.

Tests (CPU, mocked engine through the SSE serializer):

- `tests/entrypoints/openai/chat_completion/test_serving_chat.py::test_streaming_reasoning_usage_counts_across_deltas` additionally asserts `usage` is `null` / absent / populated on choice chunks for each `stream_options` case.
- New `tests/entrypoints/openai/completion/test_completion_text_offset.py::test_stream_chunks_carry_null_usage_when_usage_requested` covers `/v1/completions` with and without `include_usage`.

```
$ pytest tests/entrypoints/openai/completion/test_completion_text_offset.py \
    tests/entrypoints/openai/chat_completion/test_serving_chat.py \
    -k "null_usage or reasoning_usage_counts"
# without the fix: 17 failed, 65 passed
# with the fix:    82 passed

$ pytest tests/entrypoints/openai/completion/test_completion_text_offset.py \
    tests/entrypoints/openai/chat_completion/test_serving_chat.py \
    tests/entrypoints/openai/completion/test_completion_error.py
# 270 passed, 10 errors (TestGPTOSS* server fixtures: `vllm` binary not on PATH in my local env, unrelated)
```

E2E against a live server was not run: I have no GPU, so validation covers only the mocked-engine serving tests above. Those tests exercise the actual SSE serialization path (`chat_completion_stream_generator` / `completion_stream_generator`), so the exact wire output is asserted.

## Details

Root cause: chat choice chunks are serialized with `model_dump_json(exclude_unset=True, ...)` and completion choice chunks with `model_dump_json(exclude_unset=True)`, so the default `usage=None` was dropped. The fix explicitly assigns `chunk.usage = None` (marking the field as set) when usage was requested and not already populated.

- For chat, the change is in `chat_completion_stream_generator` (the SSE wrapper) rather than `chat_completion_stream_generator_raw`, so the Anthropic and Cohere converters, which consume the raw chunks, are unaffected.
- The derender endpoints already emit `usage: null` (they use `model_dump()`), so this also aligns coupled and derendered streaming output.
- The Rust frontend also omits null fields (`skip_serializing_none`); that is tracked separately in #63656 and is out of scope here.

Not a duplicate: no open issue/PR found for `usage null` / `stream_options include_usage` chunk shape (searched open issues and PRs).
