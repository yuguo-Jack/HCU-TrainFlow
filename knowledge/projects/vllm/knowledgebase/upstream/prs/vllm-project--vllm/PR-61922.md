# [Attention] Add opt-in FlashInfer fused DCP combine for MLA and GQA/MQA

[Upstream PR](https://github.com/vllm-project/vllm/pull/61922) · state: open · merged: False

## Original PR description



## Overview

Add opt-in `--dcp-comm-backend fi_a2a_fused` for MLA and FlashInfer GQA/MQA decode. It calls `decode_cp_a2a_lse_reduce` to exchange partial attention outputs and perform LSE-weighted reduction in one operation, reading vLLM's output/LSE views without layout copies.

**Draft:** depends on [FlashInfer #6483](https://github.com/flashinfer-ai/flashinfer/pull/6483), which extends the NCCL implementation from [#4929](https://github.com/flashinfer-ai/flashinfer/pull/4929) with mask and stride support. The repository's pinned dependencies cannot run this path. Dependency pins are unchanged; a supported minimum version will be selected after [FI #6483](https://github.com/flashinfer-ai/flashinfer/pull/6483) is released and qualified.

## Claims

- Wire the backend into the MLA manager and FlashInfer GQA/MQA decode dispatcher. Existing defaults, Q/KV partitioning and prefill paths requiring merged LSE are preserved.
- Pass destination-major O and independently strided LSE through tensor views. FI receives the existing LSE log base and a source-rank token-validity mask.
- Use one `DCPValidTokenMask` helper across dense MLA, sparse MLA and FlashInfer metadata builders. Each builder owns its persistent buffer; existing normal, capture and drafting paths refresh it, including empty shards and graph padding. `AttentionGroup` and `CommonAttentionMetadata` are unchanged.

## Details

The adapter lives in `vllm/v1/attention/ops/flashinfer_dcp.py`; mask allocation/update is owned by the DCP helper and uses the Triton metadata kernel. Workspace capacity includes speculative width and graph padding, with independent state per observed stream and existing microbatch slot.

The path requires SM90+, FP16/BF16 O, FP32 LSE, compatible PyTorch/NCCL device APIs, NCCL ≥2.29, DCP size 2–64 within one supported NCCL LSA domain, and PCP=1. GQA/MQA additionally requires the FLASHINFER attention backend, unquantized KV cache and no attention sinks; existing TP/KV-head constraints apply. Initialization requirements and explicit opt-outs for conflicting symmetric-memory collectives are documented in `docs/serving/context_parallel_deployment.md`.

Related work:

- [#48248](https://github.com/vllm-project/vllm/pull/48248) replaces exchange with `decode_cp_a2a_alltoall` and retains separate Triton combine. This PR includes reduction in the FI call.
- [#48196](https://github.com/vllm-project/vllm/pull/48196) targets sparse MLA projection/merge ordering and Helix exchange. This PR adds the fused-combine backend and its metadata integration.
- [#50484](https://github.com/vllm-project/vllm/pull/50484) provides the existing native direct symmetric-memory path, which remains a comparison baseline alongside packed NCCL.

Reviewer notes:

- Dependency:  [FI #6483](https://github.com/flashinfer-ai/flashinfer/pull/6483).
- Review mask lifetime/padding and workspace warmup. Each capture stream must be warmed on every rank.
