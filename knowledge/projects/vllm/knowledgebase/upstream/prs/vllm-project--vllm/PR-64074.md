# [Hardware] SM120 FP8 KV cache prefill optimization

[Upstream PR](https://github.com/vllm-project/vllm/pull/64074) · state: closed · merged: False

## Original PR description

## Overview

Enable FP8 KV cache for prefill on Blackwell **SM120** by extending the FlashAttention capability gates (previously SM90/SM100 only) to accept SM120. 1 commit, 3 files, +14/−8.

## Claims

- SM120 now selects **FlashAttention 4** in `get_flash_attn_version` when `is_fa_version_supported(4)`; previously `major == 12` fell through to the FA2 fallback.
- `flash_attn_supports_kv_cache_dtype` now reports FP8 KV support for SM120 (`is_device_capability_family(120)`) when FA4 is selected, so the FP8 KV cache check no longer rejects SM120 prefill.
- `uses_fa4_hd256_kernel` accepts device capability major `12`.
- `flash_attn_varlen_func` routes the FA4 fp8-KV dequant path for capability major in `(9, 10, 12)` — this also aligns that gate with `flash_attn_supports_kv_cache_dtype`, which already accepted SM100 + FA4 (it was previously hard-gated to `== 9`).
- Support is strictly conditional: every new branch is behind `device_capability` / `current_platform` checks, and SM120 still falls back to FA4 only if `is_fa_version_supported(4)` holds, otherwise to FA2 as before.

## Validation

- **DCO**: `Signed-off-by` present on the commit (CI DCO ✅).
- **Lint (local, matches repo pre-commit config):** `ruff check` and `ruff format --check` clean on all 3 changed files; repo scripts `check_spdx_header`, `check_forbidden_imports`, `check_init_lazy_imports`, `check_boolean_context_manager`, `check_trust_remote_code`, `check_torch_cuda` all pass.
- **Scope:** diff touches only capability/branch conditions and messages — no kernel, layout, or scheduling changes; non-SM120 devices evaluate the same predicates as before (SM100 additionally gains the FA4 fp8-KV dequant branch, per the claim above).
- **CI:** the `pre-commit` workflow has not run yet — its `pre-run-check` gate requires a `ready`/`verified` label (author has fewer than 4 merged PRs), so CI-level lint is still pending on that label.

## Details

SM120 (consumer Blackwell) was not matched by any FA4 branch: `get_flash_attn_version` fell back to FA2, `flash_attn_supports_kv_cache_dtype` returned false for FP8 KV, and the FA4 fp8-KV dequant branch in `flash_attn_varlen_func` was hard-gated to `capability[0] == 9`. The result was that FP8 KV cache prefill could not be enabled on SM120.

The change mirrors the existing SM100 handling rather than introducing a new code path: one extra `elif` for FA4 selection, widening three existing predicates, and updating the user-facing error/comment strings (`"or FA4 on SM100/SM120"`).

Trade-offs / limitations:

- Requires an FA4 build that supports `sm_120`; when `is_fa_version_supported(4)` is false the behavior is unchanged (FA2 fallback, FP8 KV not reported as supported).
- SM110 is untouched and still falls back to FA2.
- No SM120 hardware run is included in this PR; validation above is static/lint-level, and the change is inert on hardware other than SM120 (plus the SM100 dequant-gate alignment noted above).
