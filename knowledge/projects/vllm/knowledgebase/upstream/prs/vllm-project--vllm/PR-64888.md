# [Bugfix][ROCm] Fix AITER FA extend_forward zero-chunk and drafter KV workspace (#64680)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64888) · state: open · merged: False

## Original PR description



## Overview

Fix two speculative-decoding drafter failures in ROCm AITER FlashAttention (ROCM_AITER_FA): handle zero-chunk extend steps in AiterFlashAttentionImpl.extend_forward without calling merge_attn_states on None, and size AiterFlashAttentionMetadataBuilder workspaces from kv_cache_spec rather than the target model's model_config.

Fixes #64680

## Claims

- Fixes AttributeError in merge_attn_states when AiterFlashAttentionImpl.extend_forward runs on an extend step with num_chunks == 0 (for example during drafter warmup when there is no cached prefix context).
- Fixes out-of-bounds KV gather writes in cp_mha_gather_cache when a speculative-decoding drafter KV-cache group has a different per-rank num_kv_heads or head_size than the target model.

## Validation

```bash
pytest tests/models/test_muse_spark_rocm_loading.py -v
```

## Details

1. In AiterFlashAttentionImpl.extend_forward, chunked_output and chunked_lse remain None when num_chunks == 0 (an extend batch with no cached context blocks). Copy out directly into output when chunked_output is None instead of invoking merge_attn_states with prefix_output=None.
2. In AiterFlashAttentionMetadataBuilder.__init__, read num_heads_kv and headdim from the group's kv_cache_spec rather than vllm_config.model_config so extend_workspace, swa_workspace, and ASM KV scale tables match the drafter group's KV geometry.
