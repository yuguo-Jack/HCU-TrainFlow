# [Feature][Quantization] Gather MiMo fused-QKV FP8 rows exactly by default

[Upstream PR](https://github.com/vllm-project/vllm/pull/59053) · state: open · merged: False

## Original PR description

## Purpose

This PR upstreams work from the patch set of the MiMo recipe we deploy — Diffbot's MiMo-V2.6-Flash-RL FP8KV/W4A8 recipe (Hugging Face: diffbot/MiMo-V2.6-Flash-RL-FP8KV-W4A8-2x-RTX-PRO-6000, built by Mike Tung), itself porting parts from the local-inference-lab/vllm fork: the idea and the original implementation belong to the recipe's authors, not to us. Their version of this change is tracked in local-inference-lab/vllm#874; we re-derived the diff against upstream main, wrote or extended the tests, and ran the checks.

### Motivation

`_shard_fp8_qkv_proj` re-quantizes every gathered row through a dequantize-requantize round trip whenever `tp_size != ckpt_tp`: the fallback re-derives each block scale in fp32 and only reproduces the checkpoint's bytes when rounding cooperates.

When `ckpt_tp` is a multiple of `tp_size`, the rank's rows can be taken from the checkpoint byte-for-byte instead, in two shapes:

- **Block-aligned segments** (MiMo SWA chunks: 3712 = 29 x 128 rows, all three segments multiples of 128): a pure block permutation — gather the rows directly, no arithmetic, no scale re-derivation.
- **Straddling segments** (GA/Pro chunks: a 192-row K segment, one and a half scale blocks): each owned chunk keeps its K and V rows together, zero-padded to a whole block count, so every row still carries its checkpoint scale — the rank's parameter becomes the zero-padded `[Q_1 | ... | Q_g | K_1 V_1 pad | ... | K_g V_g pad]` layout, built as a `MergedColumnParallelLinear` instead of a de-interleaved `QKVParallelLinear`. The forward splits that padded output back per chunk. A checkpoint whose scales form one continuous grid (rather than one grid per chunk) fails loudly with a `ValueError` naming the precondition instead of dying in a shape assert at load.

Layouts failing the divisor or Q-segment alignment conjunct keep the existing path unchanged.

The exact gather is now the default: it is selected by geometry alone, so a rank whose layout qualifies takes checkpoint rows byte-for-byte. A padded layout whose scales are not per chunk now raises instead of silently requantizing. Four signed commits: the block-permutation gather with its tests, the padded gather for straddling segments, the module wiring with its round-trip test, and the removal of the environment gate.

## Test Result

Results: **31 passed, 2 skipped** — the 19 pre-existing sharding tests, unchanged, plus:

- `test_exact_gather_permutes_checkpoint_rows` (SWA geometry, tp 1 and 2): weights and scales byte-identical to the checkpoint rows the rank owns;
- `test_exact_padded_layout_matches_checkpoint` (GA and Pro geometries, tp below `ckpt_tp`): every weight byte equal to the checkpoint's `[Q | K V pad]` order with zero pad rows, and every scale row in the padded order;
- `test_split_qkv_round_trips_the_padded_layout` (GA and Pro, tp below `ckpt_tp`): `_split_qkv` on the transposed rank slice returns exactly the checkpoint rows the rank owns, byte for byte — pinning the writer's padded order to the reader's so a one-sided layout change cannot slip through with shapes intact.

The 2 skips are `tp_size >= ckpt_tp` cases of the padded tests: the plain-chunk path covers that region, not the padded one. `test_flag_off_keeps_requantizing_loader` went away with the gate; the requantizing loader keeps its coverage in `test_fused_qkv_proj_sharding` at `tp_size=8`.

`pre-commit run` itself cannot execute in this NixOS environment (hook environments fail with the `stub-ld` dynamic-linker error), so the repo-pinned ruff 0.14.0 was run directly.

**No model eval was run.** The exact gather takes checkpoint rows without arithmetic and is now the default for the geometries that qualify, so a deployment should compare its outputs against a requantizing build on its own model before rollout — that comparison is not part of this PR.

+1 from another deployment of the same lineage (diffbot recipe -> local-inference-lab#874 -> our port), with an independent byte-level audit.

We have been running this exact scheme in production since **2026-09-26** (~9 days continuous) on the official fp8 checkpoint: 4× CMP 170HX (sm80), **PP=4, i.e. tp_size=1 per rank** — so the `ckpt_tp % tp_size == 0` case is our daily driver, on the wtdcode/vllm-backport v0.13 (V1 engine) stack. Our port: [kaka86mm/vllm-backport `mimo-v3-stack`](https://github.com/kaka86mm/vllm-backport/tree/mimo-v3-stack) (patch set also mirrored in [kaka86mm/vllm-mimo-170hx](https://github.com/kaka86mm/vllm-mimo-170hx)). The construction matches this PR hunk for hunk: SWA chunks (14848 = 4 × 29 × 128 rows) as a pure block permutation, GA chunks (13568 = 4 × 3392) with each chunk's K|V kept together zero-padded to whole scale blocks, the Merged layout plus a forward split.

Corroborating measurements, with the caliber stated:

- **Byte-level audit at tp_size=1**: every layer — 9 GA + 39 SWA — sharded through the exact loader, comparing **every emitted fp8 weight byte and every scale byte against the checkpoint: 0 changed elements across all 48 layers**. Script (runs in-container against the checkpoint): [`scripts/audit-exact-qkv.py`](https://github.com/kaka86mm/vllm-mimo-170hx/blob/main/scripts/audit-exact-qkv.py).
- **No measurable decode cost vs the dequant→requant fallback** on our rig (single-stream throughput identical within run-to-run noise when we switched the loader over; the motivation was purely numerical fidelity — the recipe authors measured the requant round trip perturbing the GA layers' K/V values on most weights, which is what we wanted out of the serving path).
- Production traffic on this path includes tool calls, multimodal, and contexts up to 1M tokens.

Two notes for reviewers, from running a sibling implementation:

1. Our port has **no env gate** — the exact path engages structurally (module built with `kv_chunk_rows > 0`), with the requant fallback kept for `kv_chunk_rows = 0`. The `VLLM_MIMO_EXACT_QKV` default-off flag here is the safer rollout choice for main; just flagging the naming so downstream forks don't grow two different gates for the same behavior.
2. Our loader additionally **auto-detects the two scale grids** the checkpoints ship (per-chunk padded vs a single continuous 128-row grid over the whole tensor) before choosing the gather; this PR instead fails loudly on the continuous grid. We've only ever seen per-chunk grids in the wild, so the strict check is defensible — the auto-detect is there mainly to keep odd re-exports loading.

Happy to share the audit output or any measurements if useful.
