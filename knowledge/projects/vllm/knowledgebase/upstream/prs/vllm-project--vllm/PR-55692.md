# [Bugfix][Kernel][DSv4/4.1] Bound sparse MLA block-table gathers

[Upstream PR](https://github.com/vllm-project/vllm/pull/55692) · state: open · merged: False

## Original PR description

## Purpose

Fixes #55636.

DeepSeek V4 / V4.1 sparse MLA maps local top-k indices through a 2-D
block table. The gather currently trusts both selectors after checking only
`local_idx >= 0`. An invalid request row or logical block column can therefore
read outside the intended block-table view, producing a wrong KV slot or an
illegal memory access.

Current `main` already pads the producer-side block table consistently during
CUDA-graph capture, so this PR is intentionally limited to defensive consumer
hardening plus focused regression coverage.

## Change

For both current shipped paths:

- `vllm.models.deepseek_v4`
- `vllm.models.deepseek_v41`

the mapper now:

- passes the logical row and column counts from `block_table.shape`;
- requires `0 <= req_idx < block_table_rows`;
- requires `0 <= block_indices < block_table_cols`;
- includes `is_valid_token` in the gather mask;
- maps invalid entries to `-1`;
- compacts surviving valid entries into the prefix consumed by `topk_lens`;
- excludes invalid entries from `topk_lens`.

The regression is kept in the existing
`tests/kernels/attention/test_flashmla_sparse.py` suite and covers both V4 and
V4.1, including a non-contiguous block-table view where `stride(0) > shape[1]`
and an invalid-before-valid ordering.

## Duplicate-work check

I checked the linked issue and open sparse-MLA bounds PRs before the current
update.

PR #55744 was opened later on 2026-09-07 and overlaps this bug, but it is not an
equivalent fix:

- its current column check uses `block_table_stride` rather than logical
  `block_table.shape[1]`; CodeRabbit flagged that as allowing padded-view
  columns outside the logical table;
- its current output is not left-compacted when an invalid entry precedes a
  valid entry, while downstream consumers use `topk_lens` as a prefix length;
- it currently changes the V4 implementation only, while this PR keeps V4 and
  current V4.1 (`deepseek_v41`) aligned;
- #55744 is currently conflicted/unmergeable and has unresolved review
  comments around its optional `num_reqs` override.

Related #49896 is also distinct: it exposed bad local top-k indices reaching the
same mapper, whereas #55636 is the orthogonal request-row failure. The common
hardening point is the same 2-D gather boundary.

When an out-of-range positive index precedes a valid top-k entry, this mask excludes the bad entry from `topk_lens` but the output remains in its original order, such as `[-1, valid_slot]` with length 1. Consumers treat the length as a prefix cutoff—`xpu_sparse_decode_fp8.py` explicitly selects positions `< topk_lens`, while FlashMLA receives it as `extra_topk_length`—so the later valid slot is dropped and the invalid position may be attended instead. This is exactly possible for the malformed column indices being hardened here; compact valid slots into a contiguous prefix before returning their count.
