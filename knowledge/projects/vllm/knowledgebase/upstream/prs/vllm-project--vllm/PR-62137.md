# [Bugfix] Keep the Triton attention tiling fixed under batch invariance

[Upstream PR](https://github.com/vllm-project/vllm/pull/62137) · state: open · merged: False

## Original PR description

## Purpose

`unified_attention` (`vllm/v1/attention/ops/triton_unified_attention.py`) switches to a tuned large-head launch (`BLOCK_M=32`, a 128-wide KV tile, 8 warps, 2 stages) when `head_size == 256`, the batch contains a query longer than one token, `num_queries_per_kv <= 16` and the GPU is SM100-family. The condition is evaluated for the whole batch, so a decode request's attention is tiled, and its online softmax accumulated, differently when another request in the same step happens to be prefilling. Under `VLLM_BATCH_INVARIANT=1` that makes the output of a request depend on its batch mates: the batch-invariance suite's ragged chunked-prefill test fails on every head-size-256 model on Blackwell (Gemma 3 here).

This PR keeps the default tiling in batch-invariant mode (one extra condition). Nothing changes when the flag is off.

## Test Plan

One NVIDIA GB300 (SM 10.3), `main` at `ce49c47cbb` vs `main` + this PR, `unsloth/gemma-3-1b-it` (head size 256, 4 query heads per KV head), TP=1, `VLLM_BATCH_INVARIANT=1`:

- `test_logprobs_bitwise_batch_invariance_ragged_chunked_prefill[TRITON_ATTN]` three more times on each side.
