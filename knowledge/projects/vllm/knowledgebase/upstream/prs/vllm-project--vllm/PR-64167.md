# [Bench] Default to Zipf routing for forward benchmarks with dummy weights

[Upstream PR](https://github.com/vllm-project/vllm/pull/64167) · state: closed · merged: True

## Original PR description

## Overview

Add `vllm bench forward --routing zipf` for skewed synthetic target-model MoE routing, with fixed alpha=1.25. The default `auto` selects Zipf with dummy weights and real routing otherwise; sequence-parallel TP ranks select their corresponding fixture token rows.

## Claims

- Each token selects distinct experts with weighted sampling without replacement; a seeded permutation assigns popularity ranks to expert IDs per layer.
- Reuse the existing gate-logit and explicit expert-ID hooks. Generate fixtures outside timing and keep them fixed across graph replays.
- Sequence-parallel ranks use their corresponding fixture slice instead of repeating rank zero's token rows.

## Validation

On GB200, with dummy weights:

| Check | Result |
| --- | --- |
| Zipf frequency, distinct IDs, deterministic row prefixes | Passed |
| Existing Qwen3-Next hybrid CLI verification/mixed cases, default `auto` and explicit `balanced` | 2 passed; `auto` reports Zipf, override reports balanced; finite, deterministic graph outputs |
| Native DeepSeek V4.1 TP4/EP4 MegaMoE Q6/prefill | Correct fixture slices on all four ranks for both modes; finite outputs; Q6 graph/eager exact |

The native check uses a four-layer dummy DeepSeek V4.1 config (hidden size 512,
384 experts/top-6), `deep_gemm_mega_moe`, and cases `verify=6@1024:5` and
`prefill=1024`. Against the unmodified main routing module, ranks 1–3 reuse
rank zero's rows for both cases; the branch reconstructs the global fixture
exactly. For the first balanced Q6 layer this changes 12 distinct experts to
the intended 34. A separate real-TP-group check confirms replicated Q2 keeps
offset zero.

Native prefill output is not bitwise deterministic on either main or this
branch (eager-repeat relative RMS: 1.38% main, 1.42% balanced, 1.41% Zipf).
Those values are recorded as an existing limitation, not hidden by a relaxed
test tolerance. The fixture-row checks are exact.

```bash
.venv/bin/python -m pytest tests/benchmarks/test_forward_cli.py \
  -k 'zipf_expert_selection or bench_forward_hybrid_verify' -v
.venv/bin/pre-commit run --files \
  vllm/benchmarks/forward/routing.py vllm/benchmarks/forward/main.py \
  tests/benchmarks/test_forward_cli.py docs/benchmarking/cli.md \
  docs/cli/README.md .agents/skills/model-microbenchmark/SKILL.md
```

The existing Benchmarks CLI CI step selects both the sampler check and parameterized CLI test. Multi-GPU native MegaMoE validation is external to that single-GPU CI step. No serving code changes or model-quality claims: this option intentionally substitutes synthetic routing for benchmark inputs.

## Details

Exponential races implement weighted sampling without replacement with weights proportional to `rank**-1.25`. Chunked CPU generation bounds temporary memory. The expert-ID permutation avoids systematically assigning hot experts to the lowest EP ranks; load imbalance remains intentional. Seeding from global gate names keeps layer popularity stable across PP partitions.

The TP fix uses the native forward context's padded token count to recognize a local sequence shard. Replicated rows retain offset zero. Both synthetic modes share this correction. Grouped top-k remains unsupported; explicit Zipf also rejects prefill context parallelism, whose token mapping needs separate handling. When a synthetic fixture is unsupported, `auto` warns and falls back to real routing. Synthetic routing applies to the target, not the drafter.

Duplicate-work checks searched open PRs for `forward routing` and `zipf`. [#57100](https://github.com/vllm-project/vllm/pull/57100) is complementary: it changes only `benchmarks/kernels/benchmark_moe.py` and uses a Gaussian-logit bias; it does not add full-model forward routing. [#63872](https://github.com/vllm-project/vllm/pull/63872) addresses Muse gate discovery/bias handling, not this new distribution. This branch is based directly on OSS main and does not bundle local timing experiments.
