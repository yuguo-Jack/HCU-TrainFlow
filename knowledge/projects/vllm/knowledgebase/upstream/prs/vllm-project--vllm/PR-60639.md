# [MoRIIO] Bound shared registrations and address recurrent regions

[Upstream PR](https://github.com/vllm-project/vllm/pull/60639) · state: closed · merged: False

## Original PR description

## Overview

Shared MoRIIO registration must cover every transferable conv/SSM region without extending outside its allocation. Reuse that MR for recurrent regions and add each endpoint's region offset when posting READs.

Rebased onto main `bfa7e5b7afe40ebe48288801a2baf5c1135cd881`. This remains an independent child of closed #58968.

## Claims

```text
P/D cache allocation -> in-storage shared MR covering all regions
D READ address = endpoint MR base + conv/SSM region offset + slot offset
```

- Include the final SSM region and avoid rounding the registration end beyond storage.
- Reject cross-storage or out-of-storage registrations.
- Address conv and SSM relative to their own local and remote MR bases.

## Details

The first transferable layer may follow disabled layers. Choose the first region's aligned MR start only when it lies inside the original storage, and retain the actual final byte as the end. Region addresses already present in peer metadata determine remote offsets; no wire-format change is needed.

The shared allocator remains unchanged. This does not make an unaligned allocation safe when alignment would start before owned storage. Hybrid WRITE remains unsupported on this base; integration with #60544 must also account for shared-region offsets in its new WRITE planner.

Duplicate checks: #58585 changes per-layer block-length validation, and #60544 introduces hybrid WRITE. Neither implements this shared-MR READ addressing fix. #58968 was superseded by the split PRs.

**Merge danger:** two-way door; blast radius: MoRIIO registration and recurrent READ addressing. Exact-source ROCm/RDMA validation remains required.

#60867 changes hybrid group routing and should be composition-tested with these per-region offsets; it does not implement this MR extent/address fix.

AI assistance was used for implementation, rebase, regression checks and this description. Human line-by-line review and the runtime acceptance items above remain pending. No performance improvement is claimed.
