# [CI] Enroll 6 steps and 10 AMD mirrors in automatic sharding

[Upstream PR](https://github.com/vllm-project/vllm/pull/64569) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Enrolls six steps and their AMD mirrors in `automatic_shard`, plus four AMD mirrors whose base step is already enrolled. This continues the earlier enrollment batches (#64174, #64272, #64355). No commands change.

## Claims

| Step | Plan | AMD mirror |
|---|---|---|
| `v1-logits-oracle` | 2 shards | 1 shard |
| `async-engine-inputs-utils-worker` | 2 shards | 1 shard |
| `kernels-fusedmoe-layer-test-2-h100s` | 1 shard | 1 shard |
| `lm-eval-turboquant-t3nc` / `-k3v4nc` / `-t4nc` | 1 shard each | 1 shard each |
| `batch-invariance-b200` | already enrolled | 2 shards |
| `multi-modal-models-extended-generation-3` | already enrolled | 2 shards |
| `v1-executor-worker` | already enrolled | 1 shard |
| `entrypoints-integration-multimodal` | already enrolled | 1 shard |

- The 2-shard plans cost one extra job setup each and bring every shard under the 20-minute target.
- One-shard plans run the same tests as on main, as one job, and split by themselves once their tests grow.

## Validation

- Planned each step and mirror with ci-infra main's planner against main's timings.
- The sharding harness (each shard's commands run against a mock test tree, as a PR build and as main with the OTel wrapper) shows that every test runs exactly once for each plan with 2 or more shards.
- Every step and mirror passes on recent main runs, nightly included.
- `/ci run` and a scoped build for the AMD mirrors it leaves out: every job passed. The two-shard steps finished in under half main's wall time and used less machine time than main (pytest time -22% for V1 Logits + Oracle, -17% for Async Engine).
- Spec Decode AL DSpark was dropped after its build: splitting its one file by test cost 43% more machine time with no shorter wait, because each shard loads the model again.

## Details

- **Async Engine.** `-m 'not cpu_test'` deselects eleven `tests/multimodal` files entirely, so main never times them. The planner counts a small estimate for each, which is why it plans 2 shards. Those files still run no tests.
- **caplog.** `v1-executor-worker` and `entrypoints-integration-multimodal` have files that assert on logs. Their NVIDIA steps are already enrolled with the same files, and the mirrors plan one shard.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job. Fallback-aware timeouts belong in a central timeout setting.
