# [Feature][ROCm][DSv4.1] Relay KV-sharing state across ROCm pipeline stages

[Upstream PR](https://github.com/vllm-project/vllm/pull/64643) · state: open · merged: False

## Original PR description



## Overview

Enable #63106's cross-stage cache relay on the ROCm DeepSeek-V4.1 path, so PP can cut inside a KV-sharing group and balance the stages under decoder SWA bounded replay. Stacked on #63106, #64051 and #64642.

## Claims

- On MI355X, PP2 × TP1 with `VLLM_PP_LAYER_PARTITION=10,30` or `11,29` serves DeepSeek-V4.1-Flash; before this PR these cuts are refused ("PP splits inside a v4.1 kv-sharing group are not supported").
- Prefill throughput at concurrency ≥ 8 per instance: **1.29–1.41x TP2 + replay** on the same GPUs, **1.12–1.15x the best cut supported today (8/32)**.
- GSM8K and needle-in-a-haystack match TP2 within run-to-run noise.

## Validation

One MI355X node, four 2-GPU instances (TP2, PP2 8/32, 10/30, 11/29) loaded side by side and measured one at a time while the other three idle; two loads with the configs on different GPU pairs, two rounds per load (instance order reversed). `DeepSeek-V4.1-Flash-1017`, replay on, Engram CPU offload, MXFP4 indexer, `--max-num-batched-tokens 16384`, no prefix caching, breakable CUDA graphs. Prefill-only load (`--random-output-len 1`).

## Details

- `RocmPipelineRelay` subclasses #63106's `PipelineRelay`. The compressed main KV has the 584 B record the shared `copy_pipeline_cache_rows` reads. aiter writes the MXFP4 indexer K pages preshuffled for its MQA-logits kernel (`[chunk, token, byte]` runs and lane-major scales), so `copy_rocm_mxfp4_index_rows` uses the offsets of aiter's `k_norm_rope_mxfp4_cache`, with the page geometry from `rocm_paged_mxfp4_cache_layout`.
- `DeepseekV41ROCMAiterMLAAttention` consumers memoize their ragged top-k on the index source's module, which on the receiving stage is the relayed replica. The replica never runs, and the relay is captured inside the breakable CUDA graph, so the stage's first consumer of the relayed source refreshes the memos instead: its attention runs eagerly at replay, as the index source's own refresh does.
- Scope: a cut must keep its index source equal to its KV source and come before the candidate source (layer 20). Replay already requires the stage holding layer 20 to hold every later layer, so this covers every cut that balances a replay prefill. Other cuts are refused at startup.
- Shared code: `copy_pipeline_cache_rows` passes `launch_pdl` only on CUDA, as the other kernels in that file do.
- Tradeoffs: the receiving stage holds the relayed source's caches, so the KV pool shrinks with the cut (per instance: TP2 44.1M, 8/32 9.95M, 10/30 16.4M, 11/29 19.7M tokens). At concurrency 1–2 PP2 stays slower than TP2 (0.75–0.77x) whatever the cut; this targets throughput-bound prefill.
- `RocmPipelineRelay.transfer` repeats the base loop to pick the copy per cache; a per-cache hook in `PipelineRelay` would remove that if #63106 prefers it.
- CI: the kernel test's file is CDNA4-only, and its `kernels/attention` step runs on MI300, so the relay case is added to the `:amd: (MI355) DeepSeek-V4.1 Mono Decode Numerics` step (mi355_4, optional) with the model test.
