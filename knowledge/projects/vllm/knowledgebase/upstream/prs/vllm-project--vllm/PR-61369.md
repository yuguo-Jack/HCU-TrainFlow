# [Bugfix] Initialize fused shared expert flag in mistral eagle

[Upstream PR](https://github.com/vllm-project/vllm/pull/61369) · state: open · merged: False

## Original PR description

## Overview

`EagleMistralLarge3Model` crashes while loading draft weights since v0.28.1 (incl. v0.31.0 and current main):
`AttributeError: 'EagleMistralLarge3Model' object has no attribute 'is_fused_shared_expert_enabled'`.
Same bug class as #44846 / #45217; regression introduced by #51695.

## Claims

- Fixes EAGLE speculative decoding with Mistral Large 3 / Mistral Small 4 drafters (e.g. `mistralai/Mistral-Small-4-119B-2603-eagle`), which currently fail at startup.
- Also initializes `hidden_size`, read by `DeepseekV2Model.forward` in the sequence-parallel all-gather branch (latent; not hit today).
- Extends the #45217 regression test and adds a CPU test that runs the inherited `DeepseekV2Model.load_weights` on the drafter, so the next attribute added to that path fails in CI rather than at serve time.

## Details

`EagleMistralLarge3Model` subclasses `DeepseekV2Model` but calls `nn.Module.__init__` and recreates only a subset of the parent's attributes, while inheriting `forward` and `load_weights`. #51695 added `self.is_fused_shared_expert_enabled` to `DeepseekV2Model.__init__` and reads it in `load_weights`, so the drafter breaks at weight loading. CI missed it because the #45217 regression test only covers `__init__` and `forward`. `tests/models/test_initialization.py` does instantiate this drafter (re-enabled by #45352), but it uses `load_format="dummy"`, which never calls the model's `load_weights`. With this PR, every `self.*` attribute read by the inherited `forward`, `load_weights` and `embed_input_ids` is set by the drafter's `__init__`.

`is_fused_shared_expert_enabled` is computed exactly as in `DeepseekV2Model.__init__` (`is_model_fused_shared_expert_compatible(self.layers, DeepseekV2MoE, "mlp")`) rather than hardcoded to `False`. For the current drafter both are `False`: its `params.json` has `"moe": null`, so `first_k_dense_replace` is set to the layer count (then offset by `start_layer_id`) and every draft layer is dense. The helper stays correct if a future drafter has MoE layers. Happy to switch to a plain `False` if preferred.

Not duplicating existing work: no open PR or issue covers `is_fused_shared_expert_enabled` for this model. #45114 (closed) only addressed `use_mha`, which #45217 fixed. #57633 (merged) fixed a different drafter bug (#57630). #50691 edits the same test file for an unrelated SP change.

Possible follow-up (kept out of this PR to keep the fix minimal): have `EagleMistralLarge3Model` call `DeepseekV2Model.__init__` (or share an init helper) so new parent attributes can't silently go missing again.
