# [Bugfix] Fix words lost at chunk cuts when transcribing long audio

[Upstream PR](https://github.com/vllm-project/vllm/pull/62995) · state: open · merged: False

## Original PR description



## Overview

Fixes #61820. When the server splits long audio into 30 s pieces, it looks for the cut point only in the last 1 s before the limit. Most cuts then go through speech, and words are lost. This PR makes the default search region 10 s, at most half of the clip limit.

## Claims

- On the issue's reproducer (`KBLab/kb-whisper-large`, FLEURS sv_se, files of about 300 s), the joined WER goes from 7.35 % (24 deletions) to 4.86 % (11 deletions). The same clips sent one by one give 5.22 % (9 deletions).
- `SpeechToTextConfig.overlap_chunk_second` now defaults to `None`, and `split_audio` turns `None` into `min(10.0, max_clip_duration_s / 2)`. Every model that uses the default gets the fix: Whisper, Qwen3-ASR, Kimi-Audio, FunASR, FireRedASR2, GLM-ASR and Granite Speech. Explicit values (Cohere ASR's config, direct callers of `split_audio`) are used as given, as before.
- The offline `split_audio` example in `docs/features/multimodal_inputs.md` passed the same 1.0 and had the same bug. It now passes `None`.
- On natural long-form speech (`test_long_audio_wer_correctness`: Whisper large-v3, about 2 h of earnings calls), the WER goes from 9.44 to 8.99.

## Validation

All runs: 1 x NVIDIA A100-SXM4-80GB. "Before" is vLLM at commit `8e2beaa3bff595577a069d49d96bde9074294ec2`. "After" is the same commit with this patch. Model `KBLab/kb-whisper-large` at revision `d5d5984b`. Data: `google/fleurs` sv_se, test split.

**Reproducer** (from the issue). The script sends each FLEURS clip (under 30 s) alone. Then it sends the same clips joined with 0.3 s of silence, as 3 files of about 300 s. Each request is `POST /v1/audio/transcriptions` with `language=sv`, `response_format=json` and `temperature=0`. The only difference between the two paths is the server-side split.

```python
"""vLLM Whisper: words lost at the internal 30 s cut points (json response_format).

Same server, same audio: FLEURS clips sent one by one (each < 30 s, never split) vs the same clips joined into one
~5 min file (split by vLLM's split_audio). Only the splitting differs, so any extra WER on the joined file comes
from the cuts. Data: google/fleurs (CC-BY-4.0), test split.

  pip install requests soundfile numpy jiwer huggingface_hub
  BASE_URL=http://localhost:8000 MODEL=KBLab/kb-whisper-large FLEURS_LANG=sv_se python repro_chunk_loss.py
"""
import io, os, re, csv, tarfile, random
import numpy as np, requests, soundfile as sf, jiwer
from huggingface_hub import hf_hub_download

BASE = os.environ.get("BASE_URL", "http://localhost:8000").rstrip("/")
MODEL = os.environ.get("MODEL", "KBLab/kb-whisper-large")
FL = os.environ.get("FLEURS_LANG", "sv_se"); LANGCODE = FL.split("_")[0]
KEY = os.environ.get("API_KEY", "")
FILES, TARGET_S, GAP_S, SEED = int(os.environ.get("FILES", "3")), 300.0, 0.3, int(os.environ.get("SEED", "0"))
SR = 16000

def norm(t):
    t = re.sub(r"[^\w\s']", " ", t.lower())
    return re.sub(r"\s+", " ", t).strip()

def transcribe(pcm):
    buf = io.BytesIO(); sf.write(buf, pcm, SR, format="WAV", subtype="PCM_16")
    r = requests.post(f"{BASE}/v1/audio/transcriptions", timeout=900,
                      headers={"Authorization": f"Bearer {KEY}"} if KEY else {},
                      files={"file": ("a.wav", buf.getvalue(), "audio/wav")},
                      data={"model": MODEL, "language": LANGCODE, "response_format": "json", "temperature": "0"})
    r.raise_for_status(); return r.json()["text"]

tsv = hf_hub_download("google/fleurs", f"data/{FL}/test.tsv", repo_type="dataset")
tar = hf_hub_download("google/fleurs", f"data/{FL}/audio/test.tar.gz", repo_type="dataset")
rows, seen = [], set()
for r in csv.reader(open(tsv, encoding="utf-8"), delimiter="\t", quoting=csv.QUOTE_NONE):
    if r[0] not in seen:                     # one recording per sentence (FLEURS has 2-3 readers per sentence)
        seen.add(r[0]); rows.append((r[1], r[3]))
audio = {}
with tarfile.open(tar) as t:
    for m in t:
        if m.isfile() and m.name.endswith(".wav"):
            audio[os.path.basename(m.name)] = m
    want = {f for f, _ in rows}
    pcm = {}
    for name, m in audio.items():
        if name in want:
            x, sr = sf.read(io.BytesIO(t.extractfile(m).read()), dtype="float32"); assert sr == SR; pcm[name] = x
rows = [r for r in rows if r[0] in pcm]
random.Random(SEED).shuffle(rows)

tot = {"single_ref": [], "single_hyp": [], "joined_hyp": []}; i = 0
for k in range(FILES):
    parts, dur = [], 0.0
    while dur < TARGET_S and i < len(rows):
        parts.append(rows[i]); dur += len(pcm[rows[i][0]]) / SR + GAP_S; i += 1
    gap = np.zeros(int(GAP_S * SR), dtype="float32")
    joined = np.concatenate([np.concatenate([pcm[f], gap]) for f, _ in parts])
    ref = " ".join(norm(t) for _, t in parts)
    single = " ".join(norm(transcribe(pcm[f])) for f, _ in parts)
    whole = norm(transcribe(joined))
    print(f"file {k}: {len(parts)} clips, {len(joined)/SR:.1f} s | WER one by one {jiwer.wer(ref, single)*100:.2f} % "
          f"| WER joined {jiwer.wer(ref, whole)*100:.2f} % | words ref {len(ref.split())}, one by one {len(single.split())}, joined {len(whole.split())}")
    tot["single_ref"].append(ref); tot["single_hyp"].append(single); tot["joined_hyp"].append(whole)
R, S, J = " ".join(tot["single_ref"]), " ".join(tot["single_hyp"]), " ".join(tot["joined_hyp"])
ms, mj = jiwer.process_words(R, S), jiwer.process_words(R, J)
print(f"ALL: one by one WER {ms.wer*100:.2f} % (del {ms.deletions}, ins {ms.insertions}, sub {ms.substitutions}) | "
      f"joined WER {mj.wer*100:.2f} % (del {mj.deletions}, ins {mj.insertions}, sub {mj.substitutions}) | ref words {len(R.split())}")
```

## Details

**Root cause.** `split_audio` (`vllm/multimodal/audio.py`) searches for the cut only in the last `overlap_duration_s` before `max_clip_duration_s`. There it takes the quietest 100 ms window, with no silence threshold. The server passes `SpeechToTextConfig.overlap_chunk_second`, and the default is 1 s. Despite the name, chunks never overlap; `docs/contributing/model/transcription.md` already says the value only sets the search window. One second of running speech rarely holds a pause, so the cut usually lands inside a word. On the seed-0 files, only 1 of 30 cuts fell in silence. Each piece is decoded alone and the texts are joined with a space. So the word at the cut is lost or mangled. Sometimes Whisper also stops early and drops the last sentence of the piece; single drops of 24, 31 and 61 words were seen.

**How it was found.** When the old split is done on the client, the text is exactly the server's text. So prompts, language and join order are not involved. When the same audio is cut in the middle of the silent gaps instead, the extra loss goes away: seed 0 gives 4.92 % (del 12), seed 1 gives 5.35 % (del 17). Two other ideas were tested and are not the cause. One is the off-by-one in `find_split_point`, where the last window is never scanned (#52927). Fixing it alone made seed 0 worse (del 54). The other is cutting at the start of the quietest window instead of its middle; deletions did not change.

**Why 10 s.** A sweep of the region width over 5 seeds showed this. Up to 5 s, some seeds still drop whole sentences (seed 3 at 5 s: del 61). From 8 s, every seed is at the level of the ideal cut. 10 s leaves a margin.

**Why `None`, resolved in `split_audio`.** A fixed 10 s does not fit a short clip limit. With a 10 s limit, it gave hard cuts and 0.1 s pieces. So the default is `min(10.0, max_clip_duration_s / 2)`. It is resolved in `split_audio` on every call, so it always matches the limit in use. That holds even if `max_audio_clip_s` is set after the config is built, or the config is copied with `dataclasses.replace`. Explicit regions are not capped. No in-tree model has a limit under 20 s, so the cap does not act in tree. For a 30 s limit, `None` gives the same cuts as 10.0.

**Compatibility.** The public field `SpeechToTextConfig.overlap_chunk_second` changes from `int = 1` to `int | None = None`. Out-of-tree code that reads it and does arithmetic with it now gets `None`. In `vllm/`, the only reader is `serving.py`, which passes it straight to `split_audio`.

**Cost.** Pieces are now 20–30 s long instead of 29–30 s. On 30.9 min of speech there are about 19 % more pieces (13 % on the reproducer audio). Whisper pads each piece to 30 s, so encoder work grows with the piece count. `split_audio` takes about 66 ms instead of 5 ms on 30.9 min of audio. It runs in the preprocessing thread pool.

**Limitations.** If the 10 s region holds no real pause, the cut can still fall inside a sentence. In the "clips trimmed" case above there is no gain. Overlap with a text merge, or a VAD, would handle this, but that is a new feature, and the current design has no overlap. The example in the `split_audio` docstring still passes `overlap_duration_s=1.0`. It only shows the call on random noise, so it is left as is.

**Needs maintainer attention.** `test_long_audio_wer_correctness` checks `assert_close(wer, 9.5, atol=1e-1, rtol=1e-2)`, which allows only 9.305 to 9.695 in both directions. The better WER (8.99 on A100) fails it. This PR does not change the expected value. It should be set to about 9.0 after a check on CI hardware, or the check could be made one-sided, as #49853 did for `test_wer_correctness`.
