# [Perf][Spec Decode] Reduce padded n-gram verification in MRV2

[Upstream PR](https://github.com/vllm-project/vllm/pull/65570) · state: open · merged: False

## Original PR description

## Overview

Use n-gram match lengths to budget adaptive verification on Model Runner V2, reducing compute spent on filler draft slots at high concurrency. Enable this by default only on supported CUDA attention-only configurations, with an explicit opt-out.

Related: [#62960](https://github.com/vllm-project/vllm/pull/62960) corrects adaptive-verification cost-model profiling; this n-gram path uses no cost model and addresses filler verification instead. The shared files may need conflict resolution. Other open n-gram work on legacy dynamic drafting, asynchronous acceptance and hybrid state handling addresses different mechanisms. AI assistance was used to review and prepare this contribution.

## Claims

- Mark matched draft positions with nonzero confidence and fillers with zero, then reuse existing adaptive admission to prioritize matched prefixes.
- Budget from the previous step's matched count without startup cost profiling; keep small steps untrimmed and avoid rebuilding device boundaries when all drafts fit.
- Supplied historical H100 results report Qwen3-8B n-gram K=5 ShareGPT c128 improving from 5,152 to 8,339 output tok/s (+61.9%).

  --random-range-ratio 0 --num-prompts 512 --max-concurrency 128 --ignore-eos

The target must support variable-length decode graphs (for example FA3 on Hopper or explicit `TRITON_ATTN`). Confirm the startup message says adaptive verification is on.

## Details

The n-gram proposer still emits K draft slots, but records which positions actually matched. The shared verification manager budgets from stale host confidence counts and ranks current prefixes on device. A 128-token floor protects small decode steps. The stale budget can omit newly matched drafts or retain some fillers; it is not a promise to verify every current match and no filler.

Default-on resolution excludes unsupported platforms/backends, hybrid SSM models, LoRA, pipeline/context parallelism, DBO, batch-sharded sampling, batch-invariant execution, synthetic rejection sampling, sampling-mask replay and auxiliary outputs. Explicit `enable_adaptive_verification=false` restores fixed-width verification. Documentation describes the default, exclusions and sample dependence on the batch.

Tradeoffs in the supplied measurements: random c128/c256 median TPOT rose 14.4%/10.7% despite throughput and tail-latency gains; c1 TTFT p50 rose 1.5%. The reused confidence path adds per-step transfers and synchronization. TP/DP coverage, `VLLM_GPU_SYNC_CHECK=error`, new CUDA tests and fresh end-to-end evaluation remain pending and must complete before merge.
