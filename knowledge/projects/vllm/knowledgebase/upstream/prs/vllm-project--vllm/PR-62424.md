# [Rust Frontend] Add native GLM-5.3 / GLM-5.3-Flash chat rendering

[Upstream PR](https://github.com/vllm-project/vllm/pull/62424) · state: closed · merged: True

## Original PR description

## Overview

Add native Rust GLM5Next chat rendering for GLM-5.3 and GLM-5.3-Flash, including tool calls and reasoning options. Rust `auto` selects it for the `glm5_next` model type (GLM-5.3-Flash); GLM-5.3 shares `glm_moe_dsa` with GLM-5 through GLM-5.2, so it uses `--tokenizer-mode glm5_next` explicitly.

## Claims

- Replace MiniJinja template interpretation with model-specific Rust rendering for both model templates.
- Produce token IDs with control markers resolved through the added vocabulary, while literal text uses the base vocabulary.

Previous author-reported frontend benchmarks compared both templates against HF MiniJinja with identical requests, 4 server CPU cores, concurrency 64, and two 4-second runs per configuration:

| Workload | Native / HF throughput |
| --- | --- |
| Short tool conversations | 1.50x |
| Parallel tool calls | 1.75–1.79x |
| Long tool histories | 1.77–1.86x |

These measurements cover frontend rendering and tokenization, excluding model inference, and were not rerun for this upstream sync. GPU serving and model evaluations were not rerun on the local macOS host.

## Details

This PR adds chat rendering; multimodal preprocessing is owned by `llm-multimodal`, with the GLM processor work handled in [smg-project/smg#4036](https://github.com/smg-project/smg/pull/4036). The Python frontend continues to use the HF tokenizer and renderer. The tokenizer-mode docstring generates the user-facing argument reference, both GLM recipes include deployment examples, and the tool-calling guide documents the default tool-definition policy for the native GLM renderer.

Both `glm5_next` and upstream's `alpamayo2_super` tokenizer modes are preserved. GLM tool definitions follow the effective tool list; the server owns the exclusion policy, rather than the renderer's tool-parsing flag. Chat Completions conversion retains empty explicit reasoning strings; `reasoning` / `reasoning_content` are vLLM extensions absent from the OpenAI OpenAPI 2.3.0 assistant-message schema checked on 2026-10-25.

Rejecting `--chat-template` and request `chat_template` for native renderers, including `glm5_next`, is handled generically in vllm-project/vllm#64274.

Duplicate-work check: this continues the existing native GLM renderer PR; the earlier GLM/Rust/tokenizer search found no other PR implementing the same renderer.
