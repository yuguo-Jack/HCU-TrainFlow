# Add native Rust GLM-5.3 / GLM-5.3-Flash tokenizer support

[Upstream PR](https://github.com/vllm-project/vllm/pull/62424) · state: open · merged: False

## Original PR description



## Overview

Add native Rust GLM5Next chat rendering for GLM-5.3 and GLM-5.3-Flash through `--tokenizer-mode glm5_next`, supporting both model templates, tool calls, reasoning options, and multimodal content.

## Claims

- Support both GLM-5.3 and GLM-5.3-Flash with native Rust rendering.
- Compared with the HF MiniJinja backend, text/tool rendering throughput reaches:
  - **1.50x** for short tool conversations.
  - **1.75–1.79x** for parallel tool calls.
  - **1.77–1.86x** for long tool histories.

## Validation

- Targeted GLM5Next tests: **14 passed, 1 ignored**. The ignored video decoding test requires FFmpeg and ffprobe.

  ```bash
  cd rust
  cargo test -p vllm-chat glm5_next --lib
  ```

- Benchmarked both model templates against the HF MiniJinja backend using identical requests, **4 server CPU cores**, and **concurrency 64**. Results above use two 4-second runs per configuration.
- Online validation covered image requests, multiple images, streaming responses, and tool calls with images.
- Multimodal token sequences and pixel tensors matched Transformers in the tested reference cases.

## Details

Replace template interpretation with model-specific Rust rendering while reusing existing tokenization and engine integration. Implement GLM5Next image and video preprocessing according to Transformers behavior.

Performance measurements cover frontend rendering and tokenization, excluding model inference. Video preprocessing retains vLLM's existing 30,000-token budget.
