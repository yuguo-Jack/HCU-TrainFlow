# [Perf] Fuse GLM-5.x MoE finalize into the next RMSNorm's all-reduce

[Upstream PR](https://github.com/vllm-project/vllm/pull/62174) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

GLM-5.x (the `DeepseekV32` NVIDIA path) now leaves each decode MoE layer's top-k reduction open. The next RMSNorm's
fused all-reduce then finalizes it in one FlashInfer kernel (`trtllm_moe_finalize_allreduce_fusion`). This uses
the existing deferred-finalize contract (`MoEOutput`, `defer_moe_finalize`) that DeepSeek-V4.1 and Kimi-K3 already
use.

**Needs flashinfer-ai/flashinfer#6630 (deadlock fix) and flashinfer-ai/flashinfer#6631 (speed); draft until a
FlashInfer release with both is pinned.** Without the first the kernel can hang under back-to-back launches; without the
second, deferring is slower than the unfused path. flashinfer-ai/flashinfer#6632 (cluster sizing) adds most of the gain
at 5-7 running requests.

## Claims

With the FlashInfer fixes, on GLM-5.2-NVFP4, TP4, MTP 3, B300:

- Target verify forward (`vllm bench forward`, spread < 0.1%): -1.2% to -1.3% at 1 request, -1.5% at 3, -0.8% at 7.
  Serving decode at batch 1: -1.2% ms/token.
- Per MoE layer, the GEMM2 tail is one kernel instead of three: finalize, shared + routed add, all-reduce +
  residual + RMSNorm.
- Accuracy: GSM8K unchanged within run-to-run noise (see below). The fused kernel accumulates in FP32.
- On InferenceX AgentX, GLM-5.3 vs SGLang, with FlashInfer flashinfer-ai/flashinfer#6630 to flashinfer-ai/flashinfer#6632: decode time on the same turns drops 1.2-3.1% at concurrency 1-8 and 0.4% at 16 on 4x GB200 (1.6-3.1% on 4x B300).

## Details

- `fused_allreduce_rms_norm` accepts a `MoEOutput`. If the routed part is unfinalized, and TP > 1 with the TRT-LLM
  workspace in use, it calls `trtllm_moe_finalize_allreduce_fusion`, which does the top-k sum, routed scaling,
  shared add, all-reduce, residual add and RMSNorm. Called without that kernel available (only possible from
  outside these layers, for example the unit test), it finalizes in torch and takes the normal path.
- `moe_finalize_allreduce_max_num_tokens` bounds deferral by the kernel's one-shot limit (128 tokens) and by the
  size up to which vLLM already picks the one-shot all-reduce. It also creates (or reuses) the shared TRT-LLM
  all-reduce workspace and returns 0 if that fails, so a layer only defers when the fused kernel will run. Above
  the bound, or when the backend isn't `trtllm`, the layer finalizes as before.
- A decoder layer defers only when its experts are TRT-LLM-Gen (NVFP4 or BF16 monolithic/modular, the ones that
  can stop after GEMM2), it isn't sequence parallel, and the router folds `routed_scaling_factor` into the routing
  weights (the deferred output carries no scaling of its own, so the experts' factor must be 1.0). Each
  local layer defers except the last one on a non-last PP rank, since its output leaves as `IntermediateTensors`.
  Layers that feed an aux hidden state (EAGLE-3) don't defer. The MTP block defers into its final norm.
- `_forward_impl` and `_unpack` are used directly, as in `deepseek_v41/nvidia/model.py`, because the runner's
  custom op returns tensors only.
