# [ROCm][Perf][Kimi-K3] Overlap MoE routing and MLA gate projections

[Upstream PR](https://github.com/vllm-project/vllm/pull/60248) · state: open · merged: False

## Original PR description

## Purpose

Overlap two independent Kimi-K3 ROCm decode pairs on dedicated HIP streams:

1. MoE router GEMM/grouped top-k with the latent routed down-projection.
2. MLA attention frontend with the output-gate projection.

Both paths are opt-in and decode-gated to at most 128 tokens:

- `VLLM_KIMI_K3_AMD_MOE_ROUTER_DOWN_PROJ_STREAM=1`
- `VLLM_KIMI_K3_AMD_MLA_GATE_STREAM=1`

Prefill is unchanged. DCP/PCP, naive EP dispatch, routing capture, EPLB, and
monolithic routing configurations retain the sequential path.

The MoE side stream passes its precomputed expert selection through the
existing `router_logits` tensor slot as packed FP32 weights and bit-cast INT32
ids. A thin router wrapper accepts packed selections while preserving raw-logit
fallback. The runner still receives the original hidden states as
`shared_experts_input`, so generic shared-expert overlap remains unchanged.

No open vLLM PR implements these Kimi-K3 AMD stream overlaps.

Latest same-node/image/day full 60-minute scored comparison:

```text
overlap off: p90 interactivity 163.94 tok/s
overlap v4:  p90 interactivity 172.89 tok/s
gain: +8.95 tok/s
```

Earlier token-count sweeps showed improvements through 128 tokens and no gain
at 256, which defines the decode threshold.

- direct AITER grouped-top-k parity;
- original versus projected runner inputs;

- existing latent-MoE runner, direct-return MLA, and environment tests.
