# [Bugfix][MoE] Keep the gate's hash_indices_table out of RoutedExperts parameters

[Upstream PR](https://github.com/vllm-project/vllm/pull/61930) · state: closed · merged: True

## Original PR description



## Overview

Fixes `KeyError: "attribute 'hash_indices_table' already exists"` when building any DeepSeek-V4 MoE layer that uses hash routing. Main has hit it since #58800 merged (build 95246), on both NVIDIA and AMD. Example: https://buildkite.com/vllm/ci/builds/95273#01a14218-f99c-4f41-a508-15d43366b27e

## Claims

- DeepSeek-V4 models with hash-routed MoE layers initialize again.
- Fixes on main:
  - `(MI355) DeepSeek V4 MoE Integration`: `test_deepseek_v4_vl_rocm.py::test_rocm_moe_routing_and_shared_experts_match_reference[text-hash, vision-hash]`
  - `(MI355 DPX) Basic Models (Extra Initialization) Shard 9`
  - `(H200 MIG 35GB) Basic Models (Extra Initialization) Shard 7`: `test_can_initialize_large_subset[DeepseekV4ForConditionalGeneration]`
- `hash_indices_table` stays out of `RoutedExperts`' registered parameters, as #60282 intended.

## Validation

Not run locally. The jobs listed above are the check: they fail on every main build since 95246 and should pass on this PR's CI.

## Details

**Root cause: two changes that conflict once both are on main.**
1. #60282 (merged 14:10Z Oct 15) gave `RoutedExperts` a class-level default `hash_indices_table = None`. It has `FusedMoEFactory` attach the gate-owned table with `object.__setattr__`, so the gate's `nn.Parameter` is not registered a second time under the experts module.
2. #58800 (merged 21:52Z Oct 15, branched before #60282) also passes `hash_indices_table` into `RoutedExperts.__init__` and assigns `self.hash_indices_table = hash_indices_table`.
3. The table is an `nn.Parameter`, so that assignment calls `register_parameter`. The class attribute from (1) already exists, so `register_parameter` raises `KeyError`.

Each PR passed CI on its own.

**Fix.** `RoutedExperts.__init__` stores the table with `object.__setattr__`, before `_get_quant_method` as #58800 needs, and `FusedMoEFactory` drops its now-redundant `object.__setattr__`. `hash_indices_table` is already in `NON_EXPERT_WEIGHTS` for EPLB and is never a registered parameter of `RoutedExperts`, so nothing else changes.

**Not a duplicate:** I searched open PRs for `hash_indices_table` and found none. This affects main only: `releases/v0.32.0` predates both #58800 and #60282.
