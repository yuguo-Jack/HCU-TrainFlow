# [Bugfix][LoRA] Reject non-linear expert placement with EP

[Upstream PR](https://github.com/vllm-project/vllm/pull/62797) · state: closed · merged: True

## Original PR description

## Overview

Fixes #62801.

Reject non-linear expert placement when wrapping fused MoE layers with LoRA and expert parallelism. Adapter loading slices a contiguous range of global experts per EP rank, which does not match round-robin ownership.

## Claims

- Check the MoE runner's resolved placement and raise a `ValueError` naming the incompatible strategy before adapter weights are allocated.
- Preserve linear placement, including requested round-robin placement that resolves to linear, and configurations without EP.

## Validation

```bash
.venv/bin/python -m pytest tests/lora/test_moe_lora_ep_load.py tests/distributed/test_expert_placement.py -q
pre-commit run --files vllm/lora/layers/fused_moe.py tests/lora/test_moe_lora_ep_load.py
```

- 12 tests passed. The added regression fails on unmodified main: 1 failed, 4 passed. It uses `ExpertMapManager` to exercise actual placement resolution, including the linear fallback.
- Changed-file pre-commit passed, including mypy.
- Real two-process XPU EP validation: a tiny randomly initialized DeepSeek-V2 fixture with two expert groups starts with round-robin on main; both workers reject it with the new error after this change.
- Tiny Qwen3-MoE FP16, TP2+EP, eager, `allgather_reducescatter`: linear and requested round-robin resolving to linear both completed base → nonzero expert adapter → base generation (two prompts, eight output tokens each). Token IDs and logprobs matched unmodified-main linear results exactly across all three phases (maximum logprob difference 0.0); both workers confirmed nonzero expert adapter weights.
- All-files pre-commit was run. It regenerated an unrelated ROCm dependency lockfile, and the entrypoint test failed under root. All 11 entrypoint cases passed as a non-root user; generated lock changes are excluded. Type checking reported no errors; the final changed-file run passed.

The existing Python 3.12 / PyTorch 2.13 XPU / Triton 3.7 environment was preserved; main pins PyTorch 2.14. The model fixtures validate distributed startup and generation behavior, not trained-model quality. CUDA/ROCm hardware validation was not run.

## Details

`MoERunner.expert_placement_strategy` forwards the resolved expert-map strategy. Checking the requested parallel configuration would incorrectly reject valid fallback-to-linear configurations. The check runs once during wrapper initialization.

For example, with four experts and EP2, round-robin rank 0 owns experts 0 and 2, while the contiguous LoRA checkpoint filter selects experts 0 and 1.

Duplicate-work checks found no PR implementing this placement guard. Related open work [#49058](https://github.com/vllm-project/vllm/pull/49058) addresses SP restrictions and padded LoRA buffers; [#48460](https://github.com/vllm-project/vllm/pull/48460) handles partial fused MoE adapters. Their diffs do not validate resolved expert placement.

AI assistance was used for implementation and validation. The human submitter reviewed every changed line and ran the relevant tests.
