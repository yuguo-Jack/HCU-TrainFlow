## Overview

PR #52228 provides support adaptive verification without a confidence head and this PR enable it for XPU path. We identified perf gap caused by FA kernel and can be addressed by PR [647](https://github.com/vllm-project/vllm-xpu-kernels/pull/647). With these 2 PRs, we got below bench results:

## Performance Summary

Benchmarked Muse-Glimmer-30B + DFlash2 on **8 Intel Arc Pro B60 GPUs (TP8)**,
comparing adaptive verification enabled/disabled at K=3/5/7.

Server launch:
```
ADAPTIVE=true

"${VLLM[@]}" serve "$MODEL" \
  --served-model-name "$MODEL" --port 8000 \
  --tokenizer-mode deepseek_v4 --trust-remote-code \
  --tensor-parallel-size 8 \
  --max-model-len 8192 --max-num-batched-tokens 8192 \
  --max-num-seqs 128 --gpu-memory-utilization 0.88 \
  --compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY"}' \
  --no-enable-prefix-caching \
  --speculative-config "{
    \"method\":\"dflash\",
    \"model\":\"z-lab/Muse-Glimmer-30B-DFlash2\",
    \"attention_backend\":\"FLASH_ATTN\",
    \"num_speculative_tokens\":${K},
    \"draft_sample_method\":\"probabilistic\",
    \"enable_adaptive_verification\":${ADAPTIVE}
  }"
```

Output throughput change with adaptive verification enabled, relative to
disabled at the same K:

| Workload | K3 | K5 | K7 |
| --- | --- | --- | --- |
| SPEED, high entropy, BS24 | -2.59% | +5.40% | +6.25% |
| SPEED, low entropy, BS24 | -4.99% | +3.81% | +2.21% |
| Sonnet, BS32 | -3.18% | +11.10% | +11.70% |

- **SPEED:** 12 configurations, 512 requests/configuration, 512 output
  tokens/request. Adaptive verification improves K5/K7 throughput, while K3
  without adaptive remains the fastest measured configuration.
- **Sonnet:** 6 configurations, 96 requests/configuration, 2048 output
  tokens/request. K5 + adaptive achieves the highest throughput
  (**468.55 tok/s**), 2.80% above K3 without adaptive. Mean E2E latency decreases
  by **8.17% at K5** and **10.98% at K7** versus their respective disabled controls.
- All **6,720 requests succeeded**, with zero failures.
