# [Spec Decode][DSpark] Markov sampling in the Gumbel kernel, wider DFlash padding, top-p fix

[Upstream PR](https://github.com/vllm-project/vllm/pull/64476) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

This PR speeds up the DSpark/DFlash draft step under MRV2 and fixes a top-p masking bug. It contains:

- the Markov bias added inside the Gumbel kernel;
- wider DFlash input padding;
- `is_padding` written by the positions kernel;
- a fix for the Triton top-k/top-p kernel.

Split out of #63232 (MiniMax-M3.1-Flash). Based on `main`; it does not depend on the other PRs of that split. Batch-sharded DSpark draft sampling was dropped from this PR; #63886 covers it.

## Claims

- **Markov sampling:**
  - The Gumbel kernel adds the Markov bias itself and caches the biased logits it samples from, so verification stays lossless.
  - One kernel combines the per-block maxima, replacing `argmax` + `gather`.
  - The temperature divide is skipped at 1.0.
  - Draft ids and cached draft logits are bit-identical to adding the bias first.
- **DFlash:** `prepare_dflash_inputs` pads the per-request buffers in 1024-wide blocks. Before, it used `BLOCK_SIZE`, which is 8 in a decode step, so the padding took thousands of serial iterations.
- **MRV2:** with `VLLM_MOE_SKIP_PADDING` (on by default), the positions kernel writes `is_padding`, replacing two `fill_` launches per step. The result is the same, including after adaptive compaction.
- **Triton top-k/top-p, more than 64 rows (bug fix):** a top-p below the fp32 resolution of the kept mass (e.g. 1e-9) could mask every token of a row. The kernel now keeps the max token(s) in that case. It is also warmed up with V2's contiguous FP32 row stride.

New tests:

- `test_dspark_markov_sampling.py::test_markov_sampling_matches_unfused` runs the Markov loop with the real LM-head, Markov embedding and Markov bias layers. For greedy and probabilistic drafting, with full and reduced draft vocabularies, it checks that the loop gives the same draft ids and cached draft-logits rows as adding the bias first.
- `test_gpu_gumbel_sample.py::test_gumbel_combine_preserves_first_nan_and_maximum` checks that the combine kernel follows `torch.argmax`: the first NaN wins, otherwise the first maximum.
- `test_rejection_sampler_utils.py::test_block_verification_is_unbiased_across_steps` drafts with `gumbel_sample` over many steps and checks that block verification keeps the target distribution.
- `test_gpu_input_batch_v2.py::test_prepare_positions_preserves_padding_after_compaction` checks the `is_padding` writes.
- `test_topk_topp_sampler.py::test_tiny_p_keeps_max_token` fails on `main`'s kernel (2 failed) and passes here.

Performance:

| | before | after | measured on |
|---|---|---|---|
| Markov loop, kernels per draft step | 7 | 4 | this branch, torch profiler, 1 request, 3 steps: 17 kernels for the loop vs 24 with the bias added outside the kernel; `main`'s 7 also has `argmax` + `gather` in place of the combine kernel |
| DFlash input preparation per draft step | 21 us | 6 us | the internal branch these changes come from, GB300, MiniMax-M3.1 DSpark, 1 request, nsys |

The 4 kernels per step are the Markov embedding, the bias GEMM, the Gumbel kernel and the combine kernel. The fused path removes the bias add and the per-step copy into `draft_tokens`.

Not covered: no end-to-end benchmark or accuracy eval on this branch.

## Details

- **Not a duplicate:**
  - #63886 (WIP) batch-shards DSpark draft sampling across TP ranks. This PR no longer touches that; its Markov-loop change is in the replicated loop and the shared Gumbel kernel.
  - Other open PRs cut the cost of DSpark's Markov sampling in different ways: #61824 (draft) is a greedy-only local argmax over vocab shards in the generic DSpark speculator; #64031 is Kimi-K3 on ROCm, sharded over the vocabulary inside the model; #64442 and #61869 are fused loops specific to DeepSeek-V4.1.

  This PR keeps the generic Gumbel loop and its draws, so it works with probabilistic drafting and any DSpark draft model.
- **When the bias is fused:** probabilistic full-vocab drafting with no watermarking, acceptance estimator or output logit transform. Greedy drafting, a reduced draft vocab and those features still add the bias first, because they need the biased logits.
- **Shared code touched:**
  - `gumbel_sample` gains an optional `bias`.
  - Every caller now uses the combine kernel, which has `torch.argmax`'s tie and NaN semantics.
  - `prepare_dflash_inputs` padding.
  - `prepare_pos_seq_lens` gains optional `is_padding` outputs.
  - The Triton top-k/top-p kernel.
- **Size:** about 220 non-test lines.
