# [Bugfix][MRV2] Use int64 index mappings to fix row-offset overflow

[Upstream PR](https://github.com/vllm-project/vllm/pull/60736) · state: closed · merged: True

## Original PR description

Kernels compute row offsets as `req_state_idx * stride`. With int32 idx_mapping / expanded_idx_mapping this wraps once the product crosses 2**31 (e.g. slot 2148 at 1M context, slot 716 for mrope positions), causing illegal memory accesses or silent writes to the wrong row.

Restore int64 for the request-slot index mappings at their creation sites (main and dummy input batches, speculator and dflash buffers, batch-shard local copies, penalties bincount mapping) so the offset math is promoted to int64 in every kernel, rather than casting at each load site. Derived tensors in batch_shard / pcp_manager now use new_empty/new_zeros to inherit dtypes from their source. expanded_local_pos stays int32. The staged-write kernel casts its own int32 row index to int64.

Fixes #57030. Supersedes #60535; the test is adapted from that PR.

Co-authored by @vllmellm.
