# [ROCm][Perf][DSv4.1] Tune MXFP8 block32 GEMM for DEP8 full-shape projections on MI355X

[Upstream PR](https://github.com/vllm-project/vllm/pull/62533) · state: closed · merged: False

## Original PR description

## Summary

DeepSeek-V4.1-Flash runs attention **data-parallel** at DP8/EP8 (TP=1), so each rank sees the **full (unsharded)** attention + shared-expert projections. Four of these decode shapes were **not** in the `_TUNED` table for `rocm_mxfp8_block32_gemm` and fell through to `_default_config`, which drops to a `128x128x128` tile past M=256 that under-occupies these large-N shapes and roughly **doubles** the per-call cost.

This PR adds tuned tiers for the three shapes that benefit (microbenched per-shape on MI355X, DSpark K6, same method as the existing TP2/TP4 tiers). `shared_down (5120x2304)` was already optimal and is left unchanged. The kernel math is unchanged — only tile selection differs (each candidate was checked to match the baseline output numerically).

## Per-kernel wins (decode M, MI355X)

| Shape | Projection | Win |
|---|---|---|
| `4608 x 5120` | shared gate_up | ~**2.0x** at M≥272 (45→22 µs) |
| `5120 x 8192` | wo_b | ~**1.9x** at M≥272 (61→32 µs); 1.2–1.3x at low M |
| `32768 x 1280` | wq_b | ~**1.4x** at M=224–256 |

## End-to-end (8k/1k, DP8/EP8, MoRI; A/B = these entries on vs off)

| | c256 | c384 |
|---|---|---|
| decode TPOT | −3.9% | −3.8% |
| prefill TTFT | −5.8% | −9.1% |

0 failures over 1k+ requests per side.

## Test plan
- Per-shape microbench vs `_default_config`, with numerical-equality check against the baseline tile.
- End-to-end serving benchmark (8k/1k) at c256/c384, tune on vs off.
