# [Bugfix][KVConnector] Split MLA kernel rows larger than the NIXL block into dense pages

[Upstream PR](https://github.com/vllm-project/vllm/pull/59586) · state: open · merged: False

## Original PR description



## Overview

The NIXL connector registers MLA KV cache regions incorrectly when the model runner picks a larger kernel block for a KV cache group than the block size NIXL negotiates across all attention backends. This PR splits such rows into dense NIXL transfer pages. It reuses the path #53906 added for compressed MLA states.

## Claims

- Fixes `AssertionError: KV cache view cannot be partitioned into NIXL regions` at `register_kv_caches` when an MLA group's kernel row spans several NIXL pages.
- Fixes a silent case of the same mismatch. When the view happens to cover a block-major storage span, NIXL registers the whole backing storage as one region with the kernel-row stride. Transfers then address the wrong bytes without any error.
- Covers sliding-window MLA (`SlidingWindowMLASpec`) groups as well as full MLA.

## Validation

**Unit test.** New `test_register_mla_kernel_rows_larger_than_transfer_block` in `tests/v1/kv_connector/unit/test_nixl_desc_geometry.py`. NIXL negotiates 64-token blocks (a second backend supports only 64) while the MLA group keeps a kernel block of 128 or 256.

| kernel block | `main` | this PR |
|---|---|---|
| 128 | silently registers 1 region over the whole storage with stride = kernel row (wrong descriptors) | pass: 1 dense region per layer, 64-token pages |
| 256 | `AssertionError: KV cache view cannot be partitioned into NIXL regions` | pass |

**Regression suites** (B200): `test_nixl_desc_geometry.py` + `test_nixl_connector.py`: 379 passed (main: 377 passed; the difference is the 2 new cases).

**E2E smoke** (B200, 1P + 1D, NixlConnector):
- Model: `deepseek-ai/DeepSeek-V2-Lite` on `TRITON_MLA`, `--block-size 128`, with Eagle3 drafter `yschoi31/DeepSeek-V2-Lite-Eagle3` on `FLASHINFER` (`use_trtllm_attention=false`). NIXL logs `logical block size (128) does not match physical kernel block size (64)`.
- GSM8K, 5-shot, 400 questions:

| setup | accuracy |
|---|---|
| standalone (no P/D) | 0.347 |
| P/D, `main` | 0.333 |
| P/D, this PR | 0.330 |

> [!NOTE]
> The e2e setup does **not** hit the bug. The target MLA layers and the drafter share one KV cache group, so the runner also picks 64 for the MLA group. I could not find an open-weights checkpoint on upstream that places MLA layers in a group without the smaller-block backend (e.g. MLA + sliding-window MLA layers with a drafter). The fix is therefore validated by the unit test, and the e2e run serves only as a no-regression smoke test.

## Details

**Root cause.**
- `prepare_kernel_block_sizes` selects a kernel block per KV cache group from that group's backends.
- `NixlBaseConnectorWorker._sync_block_size_with_kernel` selects one block size from *all* attention backends in the process. That includes a drafter on a backend with a smaller supported block set.
- When some group's kernel block (e.g. 128) is larger than NIXL's (64):
  - the cache view is `[num_blocks, 1, 128, C]`, so `stride(0)` is two NIXL pages;
  - NIXL's `num_blocks` is doubled, so `num_blocks * block_stride` exceeds the view.
- This either trips the partition assert or, when the storage-span check happens to match, registers whole storage rows.

**Fix.** Drop the `tokens_per_state > 1` requirement from `_uses_dense_virtual_transfer_pages` and accept `SlidingWindowMLASpec`. The geometry checks are unchanged:
- contiguous single-head-slot view;
- row is a whole multiple of the NIXL page;
- page count matches NIXL's `num_blocks`;
- view bytes equal `num_blocks * page`.

MLA rows are token-major and contiguous, so consecutive NIXL pages tile them exactly. Both peers derive the same pages, since `block_len`/`block_stride` are advertised in the handshake as before.

**Compatibility.**
- Unchanged: views whose row equals one NIXL page (the common case) and packed/strided views (not contiguous).
- DeepSeek-V4 `SlidingWindowMLASpec` caches only take the new path when their row spans several NIXL pages. That geometry was already broken before this change.
