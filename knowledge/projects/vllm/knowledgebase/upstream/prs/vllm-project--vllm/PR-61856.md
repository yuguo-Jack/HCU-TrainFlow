# [Bugfix] [Rust Frontend] Fix HTTP metrics for streaming and cancelled requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/61856) · state: open · merged: False

## Original PR description



## Overview


Fix Rust frontend HTTP metrics so streaming latency includes the complete response-body lifetime and cancelled requests are not omitted.

This prevents HTTP request volume and latency from being understated for streaming workloads.



## Claims

- Record HTTP request counts and durations when the response body completes or is dropped.
- Preserve existing metric names, labels, excluded routes, response status codes, and body behavior.
- Add regression coverage for SSE response lifetimes and pre-response cancellation.



## Validation

```
cargo nextest run -p vllm-server  --all-features --locked --no-fail-fast

cargo clippy  --workspace --all-targets --all-features  --locked  --  -D warnings
```



## Details

The middleware previously recorded metrics immediately after next.run(req).await. For streaming responses, that future completes when the response headers and body object are ready, before the body emits generated tokens. Cancellation before that future completed also skipped all metric recording.

The metrics state is now held by a guard created before invoking the handler. After a response is available, the guard is moved into a transparent response-body wrapper. Dropping the request future or response body records the request count and elapsed duration exactly once.
