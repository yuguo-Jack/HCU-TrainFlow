# Fix suppress_stdout to target the real stdout fd

[Upstream PR](https://github.com/vllm-project/vllm/pull/59389) · state: open · merged: False

## Original PR description

## Summary

`suppress_stdout()` derived the file descriptor from `sys.stdout`, which is fragile in two ways:

1. **Crash when `sys.stdout` has no fd** — inside `contextlib.redirect_stdout(io.StringIO())` or a Jupyter/IPython kernel, `sys.stdout.fileno()` raises `io.UnsupportedOperation: fileno`. Since `suppress_stdout()` sits on the core distributed-init path, this aborts engine startup. (Fixes #59268)
2. **Silently suppresses stderr** — under the common `sys.stdout = sys.stderr` idiom, the fd is `2`, so `suppress_stdout()` redirects *stderr* to `/dev/null`, discarding error messages and tracebacks emitted by C libraries during `torch.distributed` group creation. (Fixes #59269)

## Fix

Derive the fd from `sys.__stdout__` instead, which always refers to the real stdout that C libraries write to.

## Tests

Added two regression tests in `tests/utils_/test_system_utils.py`:
- `test_suppress_stdout_without_fileno` — verifies no crash when `sys.stdout` is a `StringIO`.
- `test_suppress_stdout_does_not_suppress_stderr` — verifies stderr is preserved when `sys.stdout = sys.stderr`.
