# [UMBP][7/10] Add standalone mode backed by a node-local server

[Upstream PR](https://github.com/vllm-project/vllm/pull/61795) · state: closed · merged: True

## Original PR description

This PR is split from the original full PR: https://github.com/vllm-project/vllm/pull/58568

Add the node-local UMBP server runtime and its endpoint and startup checks.
Share one DRAM pool across engines and DP ranks. vLLM does not start the server, and KV bytes stay on HIP IPC instead of the Unix socket.
Fail closed when the server is unreachable, reject pool-sizing and `dram_*` options, and hold stores while the shared pool is blocked.
Key the shared namespace on the effective model config (dtype, quantization, and `hf_config` after `hf_overrides`), so engines that share a model path but produce different KV never read each other's blocks.
Fail transfers queued behind a blocked store instead of waiting on them forever, and bound shutdown so a stalled server cannot hang worker close or process exit.

Implementation only. Usage is in the Standalone mode section of `docs/features/umbp_store_connector_usage.md`. Tests are in the next PR.

Commit: `e02b5bccd8`. Review slice of [vllm-project/vllm#58568](https://github.com/vllm-project/vllm/pull/58568) for [RFC #57187](https://github.com/vllm-project/vllm/issues/57187). Related upstream draft: [vllm-project/vllm#59275](https://github.com/vllm-project/vllm/pull/59275).

Cancelled queued futures can reach this branch even though they never touched GPU memory. `_DaemonTransferPool.shutdown(cancel_futures=True)` removes the queued work and calls `Future.cancel()`, but those futures are never processed by `_run()` and therefore are not transitioned to the cancelled-and-notified state recognized by `concurrent.futures.wait()`.

I reproduced a running transfer completing successfully while a queued transfer is cancelled: both futures report `done()`, but `wait_futures()` returns the cancelled future in `in_flight`, and we unnecessarily abandon the registered storages.

Please distinguish cancelled/completed work from genuinely running transfers before abandoning resources. Add a regression with one running transfer that completes and one queued transfer cancelled during close; client cleanup should occur and no storages should be abandoned.
