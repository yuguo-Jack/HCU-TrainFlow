# [Core][Mamba] Keep align-mode Mamba state in fixed block-table slots on MRV2

[Upstream PR](https://github.com/vllm-project/vllm/pull/64303) · state: open · merged: False

## Original PR description



## Overview

In Mamba "align" prefix caching, a block-table column is two things at once: column `p` holds the state after `(p + 1) * block_size` tokens, and it is the physical slot a kernel reads or writes. A prefill over `[s, e)` can only use columns `(s - 1) // B` to `(e - 1) // B`, yet it needs a fixed set of slots: initial state, running state, internal checkpoint, speculative-decode slots. A prefill spanning fewer than about two Mamba blocks does not get enough columns, and the roles collide:

| Columns | Result | Current workaround |
| --- | --- | --- |
| checkpoint column = initial-state column (a shared hit block) | no internal checkpoint | split at the block boundary and at the prompt tail: 3 forward steps |
| checkpoint column < initial-state column | no internal checkpoint | split at the prompt tail: 2 steps |
| prompt within one block (`checkpoint column < 0`) | no internal checkpoint | 2 steps |
| running column = hit column | the running state would overwrite a shared block | copy-on-write on partial hits |
| a chunk starting mid-block crosses the boundary | the slot holds the initial state but would be published under the full-block hash | block-aligned split / publish masks |

With `--prefix-match-unit` below the Mamba block size, this is the common case for multi-turn chat: every turn hits inside a block and appends a few hundred tokens.

This PR gives Model Runner V2 a layout where these collisions cannot happen: **fixed state slots**. A request's Mamba row is `[running, spec_1..spec_n, checkpoint, boundary]` for its whole lifetime, the same running/speculative layout as without prefix caching. Cached states never live in the running slots:

- **Hit:** the cached block is copied into the running slot before the forward (`kv_cache_block_copies`, as for CoW today). The hit block never enters the row.
- **Export:** the scheduler decides which positions to cache and sends them per request (`SchedulerOutput.mamba_state_exports`); the manager puts a fresh block in the checkpoint or boundary slot.
  - checkpoint: the prefill kernel exports the state inside the chunk, as today, but into its own slot, so the column rule is gone;
  - boundary: after the step a GPU kernel copies the state at the boundary position, if the step's accepted tokens reached it, from the running/speculative slots. This covers prefill chunk ends, plain decode, and speculative decode with any acceptance count.
- **Publish:** an exported block is cached at its exact position once its tokens are verified (`cache_blocks`), and released by the request from the next scheduler step on.

The scheduler keeps its other split points; only the checkpoint-column condition is dropped, so the short-prefill splits above go away.

Scope (`use_mamba_fixed_state_slots`): MRV2, generative models, no KV connector, no PP/DCP/PCP, no ReplaySSM/RecoverSSM. MRV2 is the default runner for these models, so this becomes the default path for hybrid models with prefix caching. Everything else keeps the positional layout, unchanged. No new configuration.

## Claims

- **Short prefills run in one step.** A prefill that resumes mid-block and spans fewer than two Mamba blocks exports its prompt-tail checkpoint in the same forward (scheduler: 3 / 2 / 2 steps -> 1 for the cases above).
- **Multi-turn TTFT on Qwen3.5-4B with MTP:** p50 141.9 ms -> 78.9 ms, p90 183.2 ms -> 141.6 ms, at the same 78% prefix-cache hit rate. With the positional layout, prefix caching is slower than no caching here (p50 71.7 ms); with fixed slots it is close to it.
- **No accuracy change.** GSM8K is within run-to-run noise of the baseline, with prefix caching on and off.
- **Cached states are exact.** Every cached Mamba block holds the state its key claims, including speculative-decode boundaries a step's drafts did not reach (CPU ledger tests), and outputs after mid-block hits with short appends match a run without prefix caching (`test_apc_short_suffix_after_mid_block_hit`).

## Details

**Scheduler (`MambaFixedSlotManager`, selected for `MambaSpec.fixed_state_slots`).** Before allocating a step, `plan_state_exports` picks at most one checkpoint and one boundary position per request:

- checkpoint: the prompt tail (`get_mamba_prefill_checkpoint_position`), when the chunk covers it and the kernel can export it (`is_mamba_prefill_checkpoint_valid` without the column condition);
- boundary: for a prefill chunk, its end if retained; for decode, the first retained block boundary in the step's window. Retention is the positional layout's (`reachable_block_mask`, replay boundaries, shared-prefix junction), so the default `prefix_cache_retention_interval=0` still keeps only the replay boundaries and the prompt tail.

`allocate_new_blocks` fills the export slots with fresh blocks. `cache_blocks` publishes an export once `num_computed_tokens` and the block hashes cover its position. Export blocks are released from the next scheduler step on, after the worker has run the step. A boundary armed for a speculative or async step that the accepted tokens did not reach stays armed until a step reaches it. A hit block keeps its reference until the copy into the running slot has run, as for CoW.

**Worker (MRV2).** `BlockTables` rewrites fixed rows instead of appending to them. The Mamba metadata gets the running and speculative slots only; the checkpoint offset comes from the scheduler's position (`get_fixed_slot_checkpoints`). After sampling, `run_boundary_export` copies the state at the boundary position from slot `num_accepted - 1 - (num_computed - position)`, reusing the speculative-decode copy routine, and skips positions the step did not reach. `preprocess_state` no longer pre-copies the accepted state for these groups: the kernels read it from the accepted slot, as with `mamba_cache_mode="none"`. MRV2 warmup schedules one boundary export so the export kernel is compiled before serving.

**Tradeoffs and limitations.**

- Two layouts coexist. The positional one stays for MRV1, KV connectors (P/D, offloading), PP, DCP/PCP and ReplaySSM/RecoverSSM. Each can move to fixed slots separately (connectors need loads into the running slot instead of the row), after which the positional path and its split/CoW/publish-mask logic can be removed.
- Per running request each Mamba group holds `1 + num_speculative_blocks` running blocks plus up to two export blocks, about what the positional layout holds; block-table rows shrink to `3 + num_speculative_blocks` columns.
- `MambaSpec.max_num_blocks_per_req` follows the smaller row, so the logged "Maximum concurrency" for these models changes; the block pool size does not.

**Not a duplicate.**

- #60888 relaxes the column rule within the positional layout (first chunk only, plus a fresh-row flag for the worker). This PR removes the positional coupling instead, and also covers running requests, block-aligned hits on a shared block, prompts within one block and speculative-decode boundaries.
- #63720 adds an opt-out that skips the prompt-tail stop, giving up the tail state to save a step. With fixed slots the tail state is exported in the same step, so there is nothing to trade on MRV2.
- #63670 drops the scheduler split; it is orthogonal and gains from this (its "short prompts" and "unaligned chunk starts" limitations come from the same column rule). #64161 changes how budget-limited chunks advance and keeps the positional invariant; it does not interact with this layout.

"""Mamba "align" partial hit followed by a checkpointed chunk spanning columns.

Invariant: a hash-cached Mamba slot holds the state its key claims.

With a hash unit finer than the Mamba block and in-step prefill checkpoints,
request A (2500 tokens) prefills in one chunk and keys its checkpoint slot as
state@2496 (mid-block). Request B, A's prompt plus 2500 tokens, hits that
checkpoint, gets a private CoW copy of it at column 1, and is scheduled as one
chunk [2496, 5000) because its own internal checkpoint (column 2) is valid, so
`_mamba_block_aligned_split` suppresses the next-block-boundary stop. The
worker writes only the chunk-end column (3) and the checkpoint column (2); the
CoW copy at column 1 keeps state@2496. `allocate_slots` then caches 5000 tokens
unrounded and `cache_full_blocks` keys every non-null block positionally, so
the CoW copy is published as state@3200. A later request C sharing that 3200
token prefix restores state@2496 under that key.

Worker model (CPU test, no kernel): the initial state is read from column
`(start - 1) // B` (gpu/model_states/mamba_hybrid.py `add_request`), the
running state is written to column `(end - 1) // B` (backends/utils.py
`(seq_lens - 1) // block_size`), the in-step checkpoint lands in the column
`compute_mamba_prefill_checkpoints` returns, a CoW copy makes the destination
hold the source's state, and no other column is written during prefill.

import pytest
import torch

MAMBA_BLOCK_SIZE = 1600  # Mamba block B
NUM_SPEC = 3
MAMBA_GROUP_ID = 1

# A's checkpoint is floor((2500 - 1) / 16) * 16 = 2496, inside column 1.

def _make_hybrid_kv_cache_manager() -> KVCacheManager:
    config = KVCacheConfig(
        num_blocks=10000,
        kv_cache_tensors=[],
        kv_cache_groups=[
            KVCacheGroupSpec(
                ["full_layer"],
                FullAttentionSpec(
                    block_size=ATTN_BLOCK_SIZE,
                    num_kv_heads=1,
                    head_size=1,
                    dtype=torch.float32,
                ),
            ),
            KVCacheGroupSpec(
                ["mamba_layer"],
                MambaSpec(
                    block_size=MAMBA_BLOCK_SIZE,
                    shapes=((1, 1),),
                    dtypes=(torch.float32,),
                    mamba_cache_mode="align",
                    num_speculative_blocks=NUM_SPEC,
                    num_prefill_checkpoint_blocks=1,
                    prefill_checkpoint_alignment=ATTN_BLOCK_SIZE,
                ),
            ),
        ],
    )
    return KVCacheManager(
        config,
        max_model_len=262144,
        scheduler_block_size=MAMBA_BLOCK_SIZE,
        hash_block_size=ATTN_BLOCK_SIZE,
        enable_caching=True,
        use_eagle=False,

def _make_request(request_id: str, prompt_token_ids: list[int]) -> Request:
    init_none_hash(sha256)
    sampling_params = SamplingParams(max_tokens=16)
    return Request(
        request_id=request_id,
        prompt_token_ids=prompt_token_ids,
        sampling_params=sampling_params,
        pooling_params=None,
        mm_features=None,
        block_hasher=get_request_block_hasher(ATTN_BLOCK_SIZE, sha256),
    )


def _split(
    request: Request, num_new_tokens: int, num_new_local_computed_tokens: int = 0

        use_eagle_block_drop=False,
        num_hash_lookahead_tokens=0,

        mamba_shared_prefix_checkpoint=False,

        request,

def _apply_worker_step(
    manager: KVCacheManager,
    request: Request,
    start: int,
    end: int,
    state_at: dict[int, int],
) -> None:
    """Mirror what the forward pass writes for the chunk `[start, end)`.

    `state_at` maps physical mamba block id -> token offset of the state it
    holds (see the module docstring for the modelled kernel behaviour).
    """
    mamba_manager = manager.coordinator.single_type_managers[MAMBA_GROUP_ID]
    blocks = mamba_manager.req_to_blocks[request.request_id]
    # The queued copy fills the CoW block before the forward reads it.
    for source, cow in mamba_manager.take_pending_cow_copies():
        state_at[cow.block_id] = state_at[source.block_id]
    if start > 0:
        initial = blocks[(start - 1) // MAMBA_BLOCK_SIZE]
        assert state_at.get(initial.block_id) == start, (
            f"initial-state column holds state@{state_at.get(initial.block_id)}, "
            f"the chunk resumes at {start}"
        )
    (offset,), (col,) = compute_mamba_prefill_checkpoints(
        [end],
        [end - start],
        hash_block_size=ATTN_BLOCK_SIZE,
        mamba_block_size=MAMBA_BLOCK_SIZE,
        checkpoint_alignment=ATTN_BLOCK_SIZE,
        drop_eagle_block=False,
        cache_hit_alignment_tokens=ATTN_BLOCK_SIZE,
    )
    if col >= 0:
        assert not blocks[col].is_null
        state_at[blocks[col].block_id] = start + offset
    state_at[blocks[(end - 1) // MAMBA_BLOCK_SIZE].block_id] = end


def _assert_cached_mamba_slots_hold_claimed_state(
    manager: KVCacheManager, request: Request, state_at: dict[int, int]
) -> int:
    """Assert every hash-cached mamba slot holds the state its hash claims."""
    mamba_manager = manager.coordinator.single_type_managers[MAMBA_GROUP_ID]
    checked = 0
    for pos, block in enumerate(mamba_manager.req_to_blocks[request.request_id]):
        if block.is_null or block.block_hash is None:
            continue
        claimed = block.block_hash_num_tokens
        assert state_at.get(block.block_id) == claimed, (
            f"mamba slot {pos} (block {block.block_id}) is hashed as "
            f"state@{claimed} but holds state@{state_at.get(block.block_id)}"
        )
        checked += 1
    return checked


def _prefill_in_one_chunk(
    manager: KVCacheManager,
    request: Request,
    state_at: dict[int, int],
) -> int:
    """Schedule `request`'s whole prompt in one step. Returns its hit length."""
    manager.new_step_starts()
    blocks, num_hit, _ = manager.get_computed_blocks(request)
    num_new = _split(
        request,
        request.num_tokens - num_hit,
        num_new_local_computed_tokens=num_hit,
    )
    assert num_new == request.num_tokens - num_hit, (
        f"{request.request_id}: split [{num_hit}, {num_hit + num_new}) is not "
        "the whole remaining prompt"
    )
    assert (
        manager.allocate_slots(
            request,
            num_new,
            num_new_computed_tokens=num_hit,
            new_computed_blocks=blocks,
            num_lookahead_tokens=NUM_SPEC,
        )
        is not None
    )
    request.num_computed_tokens = num_hit + num_new
    _apply_worker_step(manager, request, num_hit, request.num_tokens, state_at)
    return num_hit


def test_partial_hit_then_checkpointed_chunk_rekeys_cow_block() -> None:
    """B's CoW copy of A's mid-block checkpoint must not be keyed as a boundary.

    Upstream main, unmodified: B's column-1 CoW block is keyed as state@3200
    while it holds state@2496.
    """
    manager = _make_hybrid_kv_cache_manager()
    state_at: dict[int, int] = {}
    shared = [1] * PROMPT_A

    req_a = _make_request("A", shared)
    assert _prefill_in_one_chunk(manager, req_a, state_at) == 0
    assert _assert_cached_mamba_slots_hold_claimed_state(manager, req_a, state_at)
    manager.free(req_a)

    req_b = _make_request("B", shared + [2] * (PROMPT_B - PROMPT_A))
    hit_b = _prefill_in_one_chunk(manager, req_b, state_at)
    # Preconditions of the hazard: a mid-block hit on A's checkpoint, then a
    # single chunk crossing two column boundaries (3200, 4800).
    assert hit_b == get_mamba_prefill_checkpoint_position(
        PROMPT_A, ATTN_BLOCK_SIZE, drop_eagle_block=False
    )
    assert hit_b % MAMBA_BLOCK_SIZE != 0
    assert (PROMPT_B - 1) // MAMBA_BLOCK_SIZE - (hit_b - 1) // MAMBA_BLOCK_SIZE >= 2

    _assert_cached_mamba_slots_hold_claimed_state(manager, req_b, state_at)
    # A decode step's caching keys the same block.
    req_b.append_output_token_ids(7)
