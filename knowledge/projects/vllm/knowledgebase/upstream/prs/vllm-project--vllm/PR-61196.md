# [Bugfix][Model] Fix Gemma 4 image/audio placeholder strings

[Upstream PR](https://github.com/vllm-project/vllm/pull/61196) · state: open · merged: False

## Original PR description



## Overview

Fixes #61195. `Gemma4ForConditionalGeneration.get_placeholder_str` returned Gemma 3n's `<image_soft_token>` / `<audio_soft_token>`, so with `--chat-template-content-format string` every Gemma 4 image or audio chat request failed with `Failed to apply prompt replacement`. It now returns `<|image|>` / `<|audio|>`, the tokens the prompt replacements target.

## Claims

- Gemma 4 image and audio chat requests work with `--chat-template-content-format string` instead of returning HTTP 500.
- `DiffusionGemmaForConditionalGeneration`, which registers Gemma 4's multimodal processor, gets the same image fix. `Gemma4UnifiedForConditionalGeneration` inherits the Gemma 4 method and is covered without a change.
- No change for the default `openai` content format: there the chat template inserts `<|image|>` itself, and `get_placeholder_str` never reaches the prompt text.

## Validation

New test `test_placeholder_str_is_replaced` in `tests/models/multimodal/processing/test_gemma4.py`. It resolves the model class the way the chat frontend does (`get_model_cls`), writes its `get_placeholder_str` into a prompt, and runs the real multimodal processor (configs and tokenizer only, no weights).

| Case | Before (main) | After |

| `google/gemma-4-E2B-it`, image | `Failed to apply prompt replacement for mm_items['image'][0]` | passed |
| `google/gemma-4-E2B-it`, audio | `Failed to apply prompt replacement for mm_items['audio'][0]` | passed |
| `google/gemma-4-E2B-it`, video | passed | passed |
| `google/diffusiongemma-26B-A4B-it`, image | `Failed to apply prompt replacement for mm_items['image'][0]` | passed |

Through the chat frontend: `parse_chat_messages(..., content_format="string")`, then the Gemma 4 chat template, then the processor, with `google/gemma-4-E2B-it` and one image + text user message:

- Before: content is `'<image_soft_token>\nWhat is in this image?'`, and processing fails with `AssertionError: Failed to apply prompt replacement for mm_items['image'][0]`.
- After: content is `'<|image|>\nWhat is in this image?'`, and the image placeholder lands at offset 4 with length 258, the same as with the `openai` format. The two rendered prompts differ only by the `\n` that the string path puts between content parts.

Not tested: a GPU server run of this branch, and model evals. The original failure came from `vllm/vllm-openai:v0.24.0` serving a Gemma 4 31B instruction model, and this machine has no GPU.

## Details

Root cause (full write-up in #61195):

- `_get_prompt_updates` targets the HF processor's `image_token_id` / `audio_token_id`. In Gemma 4's `tokenizer_config.json` these are `<|image|>` (258880) and `<|audio|>` (258881), and the chat template emits the same tokens.
- `<image_soft_token>` / `<audio_soft_token>` are the Gemma 3n strings (`gemma3n_mm.py`) and are not in Gemma 4's vocabulary.
- In the `string` content format, `MultiModalItemTracker.add` returns `get_placeholder_str(...)`, and `_get_full_multimodal_text_prompt` writes it into the message text. So the replacement target never appears in the prompt.

`get_placeholder_str` is a classmethod with no processor access, so the fix keeps the hard-coded strings that `gemma3_mm.py`, `gemma3n_mm.py` and the existing Gemma 4 `"<|video|>"` branch use. The Gemma 4 offline example (`examples/generate/multimodal/vision_language_offline.py`) and the Rust frontend's Gemma 4 spec in #58649 already use `<|image|>`.

Why this is not a duplicate: I searched open and closed issues and PRs for `image_soft_token`, `get_placeholder_str` + Gemma 4, `Failed to apply prompt replacement`, and Gemma 4 + content format. #41452 / #41459 fixed the same error message for images in tool messages, which has a different cause (the tool-message template). The follow-on `Expected a cached item for mm_hash` error described in #61195 is the general cache desync tracked in #46354 and is not addressed here.
