# [Rust Frontend] Stop binding --data-parallel-rank to VLLM_DP_RANK

[Upstream PR](https://github.com/vllm-project/vllm/pull/65369) · state: closed · merged: True

## Original PR description

## Overview

Stop binding `vllm-rs serve --data-parallel-rank` to the `VLLM_DP_RANK` environment variable. An exported `VLLM_DP_RANK` silently put the Rust frontend into external DP load balancing with that rank, while `vllm serve` turns on external LB only from the CLI flag.

## Claims

- `VLLM_DP_RANK` in the environment no longer changes how `vllm-rs serve` sets up data parallelism; with `--data-parallel-size 4` it now selects internal LB, as `vllm serve` does.
- `--data-parallel-rank` keeps working: an explicit rank still selects external LB.

## Validation

Commands from `.buildkite/scripts/run-rust-frontend-cargo-ci.sh` (`style-clippy` and `test`), run from the repo root on this branch:

- `data_parallel_rank_is_not_bound_to_vllm_dp_rank` asserts the arg has no env binding (process env is shared across tests, and the crate has no env-isolated harness). It fails with the binding restored.
- Checked with separate processes: `VLLM_DP_RANK=1 --data-parallel-size 4` selects external LB on `main` and internal LB with this change; an explicit `--data-parallel-rank 3` selects external LB on both.

## Details

- **Status quo.** `DataParallelLbArgs::data_parallel_rank` (`rust/src/managed-engine/src/data_parallel.rs`) is declared with `env = "VLLM_DP_RANK"`. vllm-project/vllm#64451 kept that binding when it moved the arg from an unsupported marker, where the same export used to fail startup.
- **Python.** `vllm serve` turns on external LB from `args.data_parallel_rank` (`vllm/entrypoints/cli/serve.py`). `VLLM_DP_RANK` (`vllm/envs.py`) is read only in `ParallelConfig`'s environment fallback (`vllm/config/parallel.py`), used for example by offline SPMD, and nothing in vLLM sets it for child processes.
- **Change.** Drop the binding. `DataParallelLbArgs::resolve` reads only the parsed arg, and clap's declaration is where the environment entered it, so that is the layer to change.
- **Behavior change.** A deployment that relied on an exported `VLLM_DP_RANK` to select external LB under `vllm-rs serve` must pass `--data-parallel-rank`, as `vllm serve` requires.

Not a duplicate: no open PR changes the `VLLM_DP_RANK` binding of the Rust frontend (searched open PRs for `VLLM_DP_RANK` and Rust frontend data-parallel arguments; vllm-project/vllm#64426 touches multi-port DP serving, not this arg).
