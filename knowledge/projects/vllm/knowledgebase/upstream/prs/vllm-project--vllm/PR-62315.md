# [Frontend][Metrics] Add vllm:request_reasoning_effort counter

[Upstream PR](https://github.com/vllm-project/vllm/pull/62315) · state: open · merged: False

## Original PR description



## Overview

Adds a Prometheus counter showing the distribution of reasoning efforts sent to the model, in both the Python and Rust frontends.

Stacked on #61094 (Python `--reasoning-effort-map`) and #62312 (Rust `--reasoning-effort-map`). Only the last commit, 4a74a6f082, is new here.

## Claims

- New counter `vllm:request_reasoning_effort_total{model_name, reasoning_effort}`, counted once per chat completions, Responses or Anthropic Messages generation request.
- It records the effort the request was rendered with: after `--reasoning-effort-map`, including `chat_template_kwargs` and server defaults.
- Bounded cardinality: `reasoning_effort` is one of `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, `other` or `unset`. Custom map values, template-specific strings and numbers all become `other`. All 9 series are registered at startup.
- Render, tokenize and render-server requests are not counted.

## Validation

End to end with `Qwen/Qwen3-0.6B` (`--load-format dummy`) and `--reasoning-effort-map '{"medium":"low","xhigh":"custom_level"}'`, run with both frontends:

| Sent | Label | Python | Rust |
|---|---|---|---|
| `medium` (mapped to `low`) | `low` | 2 (chat and Responses) | 1 (chat; Rust has no Responses endpoint) |
| `xhigh` (mapped to `custom_level`), and kwargs `42` | `other` | 2 | 2 |
| `high` | `high` | 1 | 1 |
| `none` | `none` | 1 | 1 |
| nothing | `unset` | 1 | 1 |

Tests:

```bash
.venv/bin/python -m pytest tests/entrypoints/openai/test_reasoning_enable_thinking.py \
    tests/entrypoints/openai/chat_completion/test_serving_chat.py \
    tests/entrypoints/openai/responses/test_serving_responses.py \
    tests/entrypoints/launchers/test_cli_args.py -q
# 369 passed, 4 skipped, 1 xfailed
cd rust && cargo test -p vllm-metrics -p vllm-server -p vllm-cmd -p vllm-chat --lib
```

New tests check that the labels stay bounded, in Python and Rust. `vllm:request_reasoning_effort_total` is also added to `EXPECTED_METRICS_V1`. `multimodal::audio::tests::audio_pipeline_attributes_stage_timings_to_request` flakes locally, on the base branch as well.

## Details

- **Python:** recorded in `OpenAIServingChat` (which Anthropic Messages also uses) and `OpenAIServingResponses` after a successful render, from `_effective_chat_template_kwargs`. Registration follows `vllm/parser/metrics.py`.
- **Rust:** recorded in `ChatLlm::chat`, so only generation is counted, from the renderer's effective template kwargs.
- **Known difference:** when thinking is disabled without an effort, Rust's native renderers (DeepSeek, Harmony, ...) report `none`, while Python reports `unset`.

Not a duplicate: #56914 counts reasoning tokens, not efforts. AI assistance (Claude) was used.
