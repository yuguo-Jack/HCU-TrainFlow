# [Security] Require trust for remote prefill cache accounting

[Upstream PR](https://github.com/vllm-project/vllm/pull/64918) · state: open · merged: False

## Original PR description

## Overview

Require explicit backend trust before accepting remote-prefill cache-hit accounting from request metadata. Python and Rust reject the field by default, preventing clients from choosing the cached-token share reported in usage.

## Claims

- Reject both oversized and plausible false cache-hit counts before engine submission on normal Python and Rust serving paths.
- Protect Python output processing if parameter-construction validation is bypassed.
- Preserve P/D cache accounting with `VLLM_TRUST_REMOTE_PREFILL_CACHED_TOKENS=1`, documented for backends accessible only through a trusted proxy that replaces client accounting metadata.

## Validation

- Python regression: 18 failures against the original source; all 22 regression cases pass with the fix.
- Sampling-parameter and Responses mapping suites: 87 passed. Output-processor remote-prefill cases: 6 passed. These runs use the repository's `skip_global_cleanup` marker through a local test plugin to avoid a macOS PyTorch cleanup segmentation fault.
- Runtime protocol admission checks: completions, chat (shared by batch and invocations), Responses, Anthropic Messages, and scale-out reject both `999999` and `5`.
- `cargo test --locked -p vllm-llm --lib --tests`: 31 passed, including streamed and collected accounting and rejection before engine submission.
- `cargo test --locked -p vllm-server --lib untrusted_remote_cache_accounting`: 2 passed, covering HTTP completions/chat and gRPC Generate/GenerateStream.
- `cargo test --locked -p vllm-server --lib error::tests`: 19 passed.
- `cargo clippy --locked -p vllm-llm -p vllm-text -p vllm-server --all-targets -- -D warnings`, Rust formatting, and pre-commit on changed files pass.
- Full pre-commit was attempted: unrelated existing mypy issues and the Linux non-root wrapper's macOS path handling prevent an all-files pass. The broader Python output suite also requires inaccessible gated Llama fixtures.
- No live-model/P-D hardware validation: the Mac environment has no compiled `vllm._C`. Model evaluation is not applicable to the accounting admission control; generation algorithms and weights are unchanged.

## Details

The frontend currently trusts `remote_prefill_cached_tokens` whenever request metadata declares remote prefill. That metadata can arrive from an ordinary client, even without a connector. Bounds alone cannot distinguish actual cache hits from an in-range false claim.

Python checks the field in shared `SamplingParams` validation and guards consumption in `RequestState`. Rust checks it before the engine call and classifies rejection as an HTTP 400 / gRPC invalid argument. Existing trusted P/D deployments must explicitly opt in on the decoder frontend; deployments exposing that backend to untrusted clients must keep the option disabled.

Duplicate-work check: #63659 (open) and #58730 (closed) only clamp the count and leave plausible false claims possible. This change does not repeat that bound. #58885 (merged) adds the Rust override; #63292 (merged) groups cache-usage reporting. Neither adds a trust control. #44633 addresses legitimate P/D statistics, rather than metadata provenance. Their diffs were inspected.

This change was developed with AI assistance.
