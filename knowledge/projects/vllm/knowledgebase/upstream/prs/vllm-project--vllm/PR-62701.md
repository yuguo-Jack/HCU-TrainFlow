# [Core][Sleep Mode] Use torch.accelerator in CuMemAllocator free/sleep

[Upstream PR](https://github.com/vllm-project/vllm/pull/62701) · state: closed · merged: True

## Original PR description

## Overview

Finish the supported `torch.accelerator` migration in `vllm/device_allocator/cumem.py` (RFC #30679) by replacing the last two generic `torch.cuda` calls:

- `_python_free_callback()`: `torch.cuda.synchronize(data.handle[0])` -> `torch.accelerator.synchronize(data.handle[0])`
- `sleep()`: `torch.cuda.empty_cache()` -> `torch.accelerator.empty_cache()`

The CUDA-specific allocator APIs (`CUDAPluggableAllocator`, `MemPool`, `use_mem_pool`, `cudaMemcpy`/`cudaMemset`, `CudaRTLibrary`, and the cuMem C extension) are intentionally unchanged, as are `get_pluggable_allocator()`, `use_memory_pool_with_allocator()`, `cudagraph_pool()`, and `_trim()`.

Status: open for human review; the submitting human should review every changed line before merge.

## Claims

- The two remaining generic calls in `cumem.py` now dispatch through `torch.accelerator`; the device index and call positions are preserved.
- No CUDA/ROCm behavior change: the free path still synchronizes before returning the handle (and before the C extension unmaps), the ROCm already-asleep short-circuit still returns an empty chunk list without an extra sync, and `sleep()` still clears the cache once after `gc.collect()`.
- Hardens the existing `test_basic_cumem` case instead of adding a test file: it records `torch.accelerator.empty_cache` around `sleep()` and `torch.accelerator.synchronize` around a freed cuMem allocation, asserting the cache is emptied once and the free callback synchronizes the allocation's device index.
- Updates the `torch.cuda.empty_cache()` comment in `use_memory_pool()` to the unified API while retaining the PyTorch issue references.
- No new dependency, no public API change, no C++/CUDA change.

## Details

- `torch.accelerator.synchronize(device)` forwards the device index exactly as `torch.cuda.synchronize(device)` did. The existing `data.is_asleep and current_platform.is_rocm()` return stays before the sync, so already-unmapped allocations still skip it.
- `torch.accelerator.empty_cache()` still runs after `gc.collect()`, so cache cleanup order and the allocator's offload/discard bookkeeping are unchanged.
- `test_basic_cumem` wraps the accelerator entry points; a revert to a non-accelerator call leaves the recorded calls empty and fails the test. It does not mock private methods or log order.
- `torch.accelerator.synchronize` is used in `discard()` and `wake_up()` already; this change removes the remaining generic calls without touching them.
- Why not duplicate: searched open PRs for `cumem`, `device_allocator`, and `torch.accelerator`; none covers these two calls. #59523 migrated the other calls in this file and is merged.
