# [PP][Perf] Consolidate residual tensors at PP boundaries.

[Upstream PR](https://github.com/vllm-project/vllm/pull/41501) · state: open · merged: False

## Original PR description

## Purpose

This PR reduces pipeline-parallel communication overhead for decoder models whose
intermediate tensors contain both `hidden_states` and `residual`.

For fused residual + RMSNorm decoder layers, `hidden_states` and `residual` can
have the same shape and are both propagated across PP boundaries. This increases
the amount of tensor data transferred between adjacent PP stages.

This PR adds `IntermediateTensors.consolidate_residual()` to fold `residual` into
`hidden_states` before intermediate tensors leave a PP stage. On the receiving
stage, a zero residual tensor is materialized locally to preserve the expected
`IntermediateTensors` structure for model execution, `torch.compile`, and CUDA
graph paths.

The optimization is enabled by default. The previous behavior can be restored
with:

```bash
VLLM_PP_DISABLE_RESIDUAL_CONSOLIDATION=1
```

Main changes:

- Add `IntermediateTensors.consolidate_residual()`.
- Consolidate residual tensors before PP send.
- Materialize zero residual tensors on PP receive when residual consolidation is used.
- Apply the same behavior in CUDA graph and V2 model runner paths.
- Skip non-tensor values when marking dynamic dimensions on `IntermediateTensors`.
- Add `VLLM_PP_DISABLE_RESIDUAL_CONSOLIDATION`.

- Prefix caching: disabled
- Dataset: random

## Test Result

PP serving completed successfully with both residual consolidation enabled and
disabled.

Correctness / stability:

- Default path completed successfully.
- Fallback path with `VLLM_PP_DISABLE_RESIDUAL_CONSOLIDATION=1` completed successfully.
- All benchmark cases finished with 64 successful requests and 0 failed requests.
- The receiving PP stage materializes a zero residual tensor locally, so model
  execution does not observe a `None` residual.

the tested long-context configurations. The end-to-end gain depends on the
communication/computation ratio and the hardware topology.

Setting `self.tensors["residual"] = None` breaks several existing methods in `IntermediateTensors` that expect all values in `self.tensors` to be `torch.Tensor` objects. Specifically, `__getitem__` (when using a slice), `__eq__`, and `empty_like` will all crash with a `TypeError` or `AttributeError` when encountering a `None` value. While `torch.compile` paths are updated in this PR, other parts of the codebase or tests using these methods on consolidated tensors will fail. Please update these methods to handle `None` values gracefully.

File: `vllm/v1/worker/gpu_model_runner.py` · line None

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

Zeroing the entire persistent buffer for `k` might be incorrect if `is_rs` (residual scattered for sequence parallelism) is true. In the scattered case, each rank only owns a slice of the residual tensor. While zeroing the whole buffer is safe if it's rank-local, it's inconsistent with the `copy_` logic below which only operates on `copy_len`. It would be better to zero only the active slice `[:copy_len]` to maintain consistency and avoid unnecessary operations on padded regions.

```suggestion
                    self.intermediate_tensors[k][:copy_len].zero_()
```
