# [KV Offload] Rename the filtered group index to config_group_idx

[Upstream PR](https://github.com/vllm-project/vllm/pull/65197) · state: open · merged: False

## Original PR description

## Overview

Rename the filtered group-config index in the KV offloading connector from `config_idx` to `config_group_idx`.

This is a draft against `main` without #64286. Rebase and fix it after #64286 merges.

## Claims

- `config_group_idx` now names the position in `OffloadingConfig.groups` (the filtered `kv_group_configs`).
- `group_idx` keeps its current meaning: the `KVCacheConfig` group id. This covers `GroupOffloadConfig.group_idx`, the offload key, and the KV events.
- Behavior does not change. The diff renames variables only.

## Validation

- `pre-commit run --files vllm/distributed/kv_transfer/kv_connector/v1/offloading/scheduler.py` passes.
- `pytest tests/v1/kv_connector/unit/offloading_connector` gives 693 passed, 2 skipped, 9 failed.
- The same 9 tests fail on a clean `upstream/main` 3b6eeb0606. They need `/dev/shm`, which is not available on this macOS host: `test_partial_tail_store_uses_attention_and_recurrent_cow_sources`, `test_eagle_partial_tail_round_trip_serves_mamba_checkpoint[False/True]`, and 6 `test_cache_reset_*` tests.

## Details

The offloading scheduler uses two group indices:

1. `group_idx`: the id in `KVCacheConfig.kv_cache_groups`.
2. `config_idx`: the position in the filtered offloading groups.

Some locals named `group_idx` or `grp_idx` hold the second index. The names hide the difference between the two indices. This change gives the second index one name, `config_group_idx`, at every site in `scheduler.py`.

The change is internal. It does not change user-visible behavior, so it needs no docs.

AI assistance was used to prepare this change. The human submitter must review every line and run the tests.
