# [Bugfix][Quantization] Map renamed prefixes in compressed-tensors regex targets

[Upstream PR](https://github.com/vllm-project/vllm/pull/64011) · state: open · merged: False

## Original PR description

## What

llm-compressor writes compressed-tensors `ignore` and `targets` with the checkpoint's HF module names, often as regexes. `CompressedTensorsConfig.apply_vllm_mapper` maps literal layer paths to vLLM's names but leaves every `re:` pattern as written. A regex anchored on a prefix the model renames therefore never matches in vLLM.

The clearest case is Qwen3-VL / Qwen3.5, which renames `model.visual.` to `visual.`. The usual `"re:model\\.visual\\..*"` in `ignore` no longer excludes the vision tower. With `"targets": ["Linear"]`, its BF16 Linear layers are built as FP8 and load without a warning. Image and video requests then return wrong hidden states: NaN under torch.compile, finite but wrong in eager. Text-only requests are unaffected, which hides the problem.

- `apply_vllm_mapper` now rewrites a `re:` pattern whose leading literal text is a key of `orig_to_new_prefix`. The key may be escaped (`model\.visual\.`) or plain (`model.visual.`); the longest key wins, and the new prefix is written escaped.
- Every other pattern is unchanged: unanchored ones (`re:.*proj`, `re:.*embed_tokens`), and prefixes the mapper drops (`None`).

## Why this is not a duplicate

Searched open and closed work on `apply_vllm_mapper` and compressed-tensors `ignore`.
- #49900 strips a draft model's root prefix before matching. That is a different prefix, added by vLLM rather than renamed by the model.
- #59978 keeps the MiniCPM-V vision tower unquantized for GPTQ and AWQ, not compressed-tensors.
- #41994 extends the ignore list for Qwen3.5 MTP experts in the model file.

None of them rewrites regex targets.

Nothing is filed in compressed-tensors or llm-compressor either. llm-compressor's examples sidestep the mismatch by listing both spellings (`"re:visual.*", "re:model.visual.*"`, llm-compressor#1545 and #1766) or an unanchored `"re:.*visual.*"` (#2597). Those PRs describe the transformers rename of the checkpoint names; the second spelling also happens to match vLLM's name. Most published checkpoints never hit this: llm-compressor's `oneshot` saves `ignore` as explicit module names (e.g. 163 entries such as `visual.blocks.0.attn.qkv` in `RedHatAI/Qwen2.5-VL-7B-Instruct-FP8-Dynamic`), and literal paths are already mapped. `model_free_ptq` keeps the regexes as the user wrote them, so a checkpoint that lists only the HF spelling loads its vision tower quantized in vLLM.

## Results (vLLM 0.31.0, 1x B200)

`Qwen/Qwen3-VL-2B-Instruct` quantized with llm-compressor 0.13:

```python
model_free_ptq("Qwen/Qwen3-VL-2B-Instruct", out, scheme="FP8_DYNAMIC",
               ignore=["lm_head", "re:.*embed_tokens", r"re:model\.visual\..*"])
```

Prompt: "Describe this image in one sentence." with vLLM's public test images ([`stop_sign.jpg`](https://vllm-public-assets.s3.us-west-2.amazonaws.com/vision_model_images/stop_sign.jpg), [`cherry_blossom.jpg`](https://vllm-public-assets.s3.us-west-2.amazonaws.com/vision_model_images/cherry_blossom.jpg)), greedy, 64 tokens. NLL is teacher-forced on BF16's answer (`prompt_logprobs`), mean over its tokens:

| | stop_sign NLL | cherry_blossom NLL |
|---|---|---|
| BF16 | 0.354 | 0.308 |
| FP8, before | **nan** | **nan** |
| FP8, after | 0.434 | 0.318 |

Answers for `stop_sign.jpg`:

- **BF16:** "A red stop sign stands in the foreground of a street in the Chinatown district of a city, with a black SUV passing by under a traditional red and gold archway, flanked by stone lions and surrounded by shops and signs."
- **FP8, before:** "locklocklocklock…" (all 64 tokens)
- **FP8, after:** "A red stop sign stands in the foreground of a bustling street in the Chinatown district of a city, with a traditional red gate, stone lions, and a black SUV passing by."

Before the change the vision tower runs as FP8 although the checkpoint stores it in BF16, and every image request degenerates. After it, the vision tower stays in BF16 and the FP8 model tracks BF16 within normal FP8 error. The same failure showed up on a Qwen3.5-4B-based video model: with eager mode the outputs were finite but wrong (multiple-choice accuracy 20.8% against 54.2% for BF16), and with torch.compile they were NaN.

## Tests

- `pytest tests/quantization/test_compressed_tensors.py -k maps_regex_prefixes`: one case added. It maps a Qwen3-VL-like mapper over escaped and plain regexes, an unanchored regex and a literal path. It then checks `should_ignore_layer` on vLLM names: the vision tower and a renamed language-model layer are ignored, and a neighbouring layer is not.
- `ruff check` and `ruff format` on both changed files: clean.
- End to end: the table above, offline `LLM` with the same checkpoint, once on stock 0.31.0 and once with this `apply_vllm_mapper` patched in.

## Notes / open questions

- Only a leading literal prefix is rewritten. A pattern that names the renamed part later (`re:.*\\.visual\\..*`) or uses `orig_to_new_regex` / `orig_to_new_substr` renames is still left as written. Translating arbitrary regexes through arbitrary renames is not well defined, and the leading prefix is what llm-compressor writes.
- Loading a BF16 weight into a layer that expects an FP8 weight and a `weight_scale` gives no warning today. Failing at load time when a quantized layer receives no scale would have surfaced this immediately; that is left for a separate change.
- The unit test was run against 0.31.0 with this function patched in, not on `main` directly.
