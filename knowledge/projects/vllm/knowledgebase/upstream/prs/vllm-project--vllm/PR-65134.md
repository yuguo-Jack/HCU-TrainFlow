# [ROCm][Perf] Add fused MoE config for Gemma 4 26B-A4B on MI350P

[Upstream PR](https://github.com/vllm-project/vllm/pull/65134) · state: open · merged: False

## Overview

Adds the Triton fused-MoE tile config for Gemma 4 26B-A4B (BF16, `E=128,N=704`) on AMD Instinct MI350P (gfx950, 128 CUs). MI350P has no config for this shape today, so vLLM logs `Using default MoE config` and runs the default tiles. Config file only.

## Claims

- `google/gemma-4-26B-A4B-it` on 1x MI350P with vLLM's Triton fused MoE: peak prefill throughput +2.9% (8000 in / 50 out), +3 to +4% at concurrency 8-64.
- Tradeoff: prefill at concurrency 2 and 4 is lower (-14%, -5%), and decode (50 in / 4096 out) is 1-4% lower at every concurrency, -0.8% at the decode peak.
- GSM8K unchanged (0.948 vs 0.951). One run per arm; a repeat is pending before this leaves draft.

## Validation

One run per arm, same image and GPU; the arms differ only in `VLLM_TUNED_CONFIG_FOLDER` pointing at this file. Peak over the concurrency sweep:

| Workload (1x MI350P, TP1) | Default tiles | This config | Change |
|---|---|---|---|
| Prefill 8000/50, total tok/s, concurrency 2-64 | 50,911 | 52,381 | +2.9% |
| Decode 50/4096, output tok/s, concurrency 32-1024 | 11,537 | 11,449 | -0.8% |
| GSM8K 5-shot, strict match | 0.948 | 0.951 | |

## Details

- Why: on ROCm, Gemma 4's GELU-tanh MoE runs on vLLM's Triton `fused_moe` (AITER's fused MoE does not support it without #55251, and `VLLM_ROCM_USE_AITER` is off by default), so MI350P users get the default tiles for this shape.
- Limitation: the ROCm search space of `benchmark_moe.py` was cut to about 2.9k of ~26k configs (`BLOCK_K` without 16, `num_warps` 2/4/8, `GROUP_M` 1/8/16, `waves_per_eu` 0/2, `kpack` 2) to keep tuning time reasonable. The small-batch and decode losses above may come from that; a full-space retune of the small batch sizes is the next step if the repeat confirms them.
- The image also carries Gemma 4 fusion PRs (#53918, #53273, #58838) and the AITER MI350P PRs; none of them touch the Triton fused-MoE path, and both arms use the same image.
- CI has no MI350P; coverage is the runs above.
