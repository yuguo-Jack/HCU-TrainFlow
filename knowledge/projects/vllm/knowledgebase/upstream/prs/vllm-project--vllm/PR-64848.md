# [Test] Check supported-models docs against model registry

[Upstream PR](https://github.com/vllm-project/vllm/pull/64848) · state: open · merged: False

## Original PR description

## Overview

Add `tests/test_supported_models.py`, which parses the model registry and the supported-models doc tables as plain text and asserts every documented architecture is registered, either as a registry key or as an implementation class name (the docs mix both, e.g. `NVLM_D_Model` is the class registered under the `NVLM_D` key).

## Claims

- Guards against docs-vs-registry drift of the kind previously fixed by hand (architectures listed in docs but missing from code, or vice versa).
- Stdlib-only: no torch, no vLLM import, no downloads, so it runs in any CI job.

## Validation

- `pytest tests/test_supported_models.py -v` locally: 2 passed.
- Negative control: with the documented exception removed, the test fails with exactly one architecture, `MiniMaxVL01ForConditionalGeneration`, so it is sensitive rather than vacuous.
- `ruff check` and `ruff format --check` clean.
- Also verified via the standard path (full repo conftest, no `--noconftest`): 2 passed.

## Details

- Only the docs-to-registry direction is asserted. The reverse is not: many registry architectures are legitimately absent from the docs (e.g. speculative-decoding draft models).
- Tables are parsed only between `## List of Text-only Language Models` and `## Model Support Policy`, which excludes the Plugins section (plugin models live outside the native registry by design).
- One documented exception: `MiniMaxVL01ForConditionalGeneration` is listed in the docs but present only in `_PREVIOUSLY_SUPPORTED_MODELS` (supported until v0.23.0). It is kept as an explicit exception so the stale row stays visible; removing it is a docs follow-up, not something to hide inside this test.
