# [Model] Fall back to block_configs for heterogeneous Nemotron-H MoE layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/62362) · state: open · merged: False

## Original PR description

## Summary
Heterogeneous ("puzzle") Nemotron-H models such as NVIDIA Nemotron 3.5 Bolt
(74B-A9B) describe a *different* MoE configuration per layer in
`config.block_configs` - Bolt has 40 MoE layers with 12 distinct
`(n_routed_experts, moe_intermediate_size, num_experts_per_tok)` combos.

vLLM only honored per-layer configs when the HF config class implemented
`get_nemotron_h_config_for_layer`. For any heterogeneous config that does not
implement the hook, every MoE layer was silently built from the global config:
wrong `n_routed_experts` (weight shape mismatch at load time) and, worse,
silently wrong routing because `num_experts_per_tok` / `moe_intermediate_size`
fell back to unrelated HF defaults (2 and 7688; Bolt needs 9 and
1536-2560 per layer).

## Change
Add `_get_nemotron_h_layer_config()` in `vllm/model_executor/models/nemotron_h.py`:
- keeps the existing `get_nemotron_h_config_for_layer` hook's precedence
  (NVIDIA's `NemotronHPuzzleConfig` keeps working exactly as before),
- otherwise builds the per-layer config from `block_configs` directly,
  handling both dict and object (dataclass) block entries,
- returns the config unchanged for non-MoE layers, homogeneous models, and
  out-of-range indices (no behavior change there),
- never mutates the original config (shallow copy + attribute overrides).

All three decoder layer types (MoE / MLP / attention) now resolve through it.

## Testing
- No GPU available here, so verified the config-resolution logic directly
  against the real `nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-BF16` `config.json`:
  all 40 MoE layers resolve to the correct per-layer
  `(n_routed_experts, moe_intermediate_size, num_experts_per_tok)` through the
  new fallback path (dict entries and dataclass entries), hook precedence
  confirmed against `NemotronHPuzzleConfig.get_nemotron_h_config_for_layer`,
  non-MoE layers / homogeneous configs return the identical config object,
  and the source config is never mutated.
- `python -m py_compile` clean on the edited file.

Fixes the vLLM side of heterogeneous Nemotron-H MoE support; pairs with the
per-layer config support in NVIDIA's `NemotronHPuzzleConfig`.
