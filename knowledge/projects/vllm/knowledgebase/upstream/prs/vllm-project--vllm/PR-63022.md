# [Bugfix] Log a real duration when load_weights() skips the weights iterator

[Upstream PR](https://github.com/vllm-project/vllm/pull/63022) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #63019.

`DefaultModelLoader.counter_before_loading_weights` is only assigned inside `_get_weights_iterator()`, which runs when the generator returned by `get_all_weights()` is first pulled from. A model whose `load_weights()` never consumes that iterator — the reported case is a GGUF path that reads the checkpoint itself — leaves the counter at its `0.0` default, so the log line computes `time.perf_counter() - 0.0` and prints the raw monotonic clock, roughly the host's uptime:

```
(EngineCore pid=7234) INFO 10-22 01:46:51 [default_loader.py:501] Loading weights took 197518.83 seconds
(EngineCore pid=7234) INFO 10-22 01:46:58 [model_runner.py:429] Model loading took 21.84 GiB memory and 23.915460 seconds
```

The engine process had started 21 seconds earlier, so the first number is not a duration.

## Change

Take `load_weights_start = time.perf_counter()` on entry to `load_weights()`, and fall back to it when `counter_before_loading_weights` is still `0.0`.

The normal path is untouched: when the iterator is pulled from, `counter_before_loading_weights` is set there as before, so weight *download* time stays out of the reported duration. Only the case that previously printed the raw clock changes.

This follows the approach suggested in the issue.

## Test Plan

No test is included, and I would rather say why than quietly omit it. The change affects one log line inside `load_weights()`, and exercising it would mean mocking most of that method — the quantization config, the EP and multimodal weight filters, `get_all_weights()`, and the strict weight-tracking check — for an assertion about a logged number. That seemed more likely to be brittle than useful.

I also could not run the suite locally: I am on macOS without a CUDA toolchain, so I verified the change by reading the code path, plus `ruff check` and `ruff format --check` on the file. If you would like a test regardless, say which shape you prefer and I will add it.

## Test Result

`ruff check` and `ruff format --check` pass on the changed file. No behavioural change outside the log line.
