# [Bugfix][Benchmark] Skip the client-side chat template on chat backends

[Upstream PR](https://github.com/vllm-project/vllm/pull/65245) · state: closed · merged: True

## Original PR description

The `custom`, `hf`, `spec_bench` and `speed_bench` datasets apply the tokenizer's chat template to each prompt unless `--skip-chat-template` is passed. With `--backend openai-chat`, `openai-responses` or `vllm-chat`, that already-templated prompt is sent as the content of a user message, and the server (or `LLM.chat` for `vllm bench throughput`) applies the template a second time. The model sees two nested templates, and input token counts are inflated.

`get_samples` now treats chat backends as `--skip-chat-template`. Completion backends (`openai`, `vllm`) keep the client-side template, since their endpoint takes raw text.

On Qwen2.5-1.5B with 8 custom-dataset prompts and `--backend openai-chat`, using server-reported usage:

| client | total input tokens | per request |
|---|---|---|
| main | 384 | 48 |
| this PR | 232 | 29 |

232 matches the same prompts sent through `--backend openai` with the client template, so the chat path now sends one template.
