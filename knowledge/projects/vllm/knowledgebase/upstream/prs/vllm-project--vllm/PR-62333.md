# [Bugfix][Frontend] Require a KV connector for decode-side prompt id reuse

[Upstream PR](https://github.com/vllm-project/vllm/pull/62333) · state: open · merged: False

## Original PR description

Fixes #62307.

## Why

`kv_transfer_params["prompt_token_ids"]` is the disaggregated-serving reuse path: the decode stage skips templating and tokenization because the prefill stage's ids arrive alongside the transfer coordination (`do_remote_prefill` / `do_remote_decode`). The reuse funnel `_reused_prompt_token_ids` checked the ids' shape (#55771) and vocabulary (#59555), but never checked that the server actually runs a KV transfer connector. On a plain server, any client could send harmless-looking `messages` plus attacker-chosen ids and have the model run on the ids instead, with the chat template (and any system prompt it carries) silently dropped. First affected release: 0.27.0 (#48145).

## What changed

One gate in `vllm/renderers/online_renderer.py::_reused_prompt_token_ids`: after the existing `echo` / non-text-content bail-outs (which neutralize the ids and still render `messages`), the ids are now rejected with a 400 unless `renderer.config.kv_transfer_config` is set. The connector is the capability boundary the reuse contract already assumes, and both entry funnels (`preprocess_chat` and the Harmony branch) pass through this helper, so chat completions and responses are covered by the same check.

Not done deliberately: restricting reuse to `/v1/chat/completions` only. The docs example uses chat completions, but disaggregated deployments front the same engine with the responses API too, and the connector gate is what removes the deceptive surface; an endpoint ban would break those deployments without adding safety. Happy to add it if maintainers want the stricter reading.

## Tests

- New `test_chat_kv_transfer_prompt_token_ids_rejected_without_kv_connector`: well-formed ids on a connector-less server now raise `VLLMValidationError` naming `--kv-transfer-config`; goes red if the gate is removed (mutation-checked).
- New `test_chat_kv_transfer_prompt_token_ids_reused_with_kv_connector`: with a connector present, well-formed ids skip templating and tokenization (`conversation == []`, engine input carries the ids, remaining `kv_transfer_params` preserved).
- The two existing render-side shape/vocabulary tests now give their mock engine a connector sentinel, since the gate runs before the shape checks; the Harmony-path tests use a `MagicMock` renderer whose config satisfies the gate unchanged.
- Local run of `tests/entrypoints/openai/chat_completion/test_serving_chat.py`: 208 passed; the 10 errors are `TestGPTOSS*` fixture setup failures that reproduce identically on pristine upstream/main on this machine (missing harmony deps), unrelated to this change. `ruff check` and `ruff format` clean on both touched files.
