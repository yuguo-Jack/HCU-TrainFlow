# [Refactor][Core] Use torch's device-agnostic streams and events in the V2 model runner

[Upstream PR](https://github.com/vllm-project/vllm/pull/58082) · state: open · merged: False

## Original PR description

## Purpose

The V2 model runner (`vllm/v1/worker/gpu/`) creates its copy streams and events as `torch.cuda.Stream` / `torch.cuda.Event`, switches streams with `torch.cuda.stream(...)`, and reads the current stream with `torch.cuda.current_stream()` in `async_utils`, `pp_utils`, `structured_outputs`, `spec_decode/utils`, `spec_decode/adaptive_verification` and the runner's `main_stream`. None of that code is CUDA-specific: it needs a stream, an event and the current stream of whatever accelerator torch is running on.

This PR switches those sites to torch's device-agnostic API: `torch.Stream(device=...)`, `torch.Event(device=..., blocking=True)`, `torch.accelerator.current_stream()`, and the existing lightweight `stream()` context manager in `async_utils`, which now uses `torch.accelerator.set_stream()`. On CUDA these resolve to the same objects, so in-tree behaviour is unchanged. `cudagraph_utils` and `ubatch_utils` keep `torch.cuda`, since graph capture and the cuBLAS handle are CUDA features.

Why: every non-CUDA runner today gets past these lines by aliasing `torch.cuda` process-wide. The in-tree XPU runner rebinds `torch.cuda.Stream`, `Event`, `graph` and `CUDAGraph` around `super().__init__()` (`vllm/v1/worker/xpu_model_runner.py`), the in-tree CPU runner installs `_StreamPlaceholder` / `_EventPlaceholder` (`vllm/v1/worker/cpu/shm.py`), and vllm-ascend assigns twelve `torch.cuda.*` attributes to `torch.npu.*` with an empty `finally` (`vllm_ascend/worker/v2/utils.py`). The checklist to route these through the platform in #9268 has been open since 2024. Using the generic API removes the need for any routing: torch dispatches to the current accelerator.

The CPU V2 runner (`vllm/v1/worker/cpu/model_runner.py`, a `GPUModelRunner` subclass) has no accelerator. On CPU-only torch, `torch.accelerator.current_stream()` / `set_stream()` raise, and a CPU `torch.Stream` cannot `wait_stream`. `cpu/shm.py` already maps `torch.Event` and `torch.cuda.*` to its placeholders, so this PR adds `torch.Stream`, `torch.accelerator.current_stream` and `torch.accelerator.set_stream` to that list.

Two small semantic notes for review:

- `copy_event.record()` inside a `with torch.cuda.stream(s):` block becomes `copy_event.record(s)`, which records on the same stream explicitly.
- `torch.Event(device=..., blocking=True)` is the generic spelling of `torch.cuda.Event(blocking=True)`. The step timing events in `async_utils` (`StepTimingEvents`) become `torch.Event(enable_timing=True)`.

- `pre-commit run --files` on the changed files (ruff, mypy, typos).
