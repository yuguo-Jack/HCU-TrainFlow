## Overview

Compute the LSE in fp32 in the DCP packed A2A test references, matching `_dcp_a2a_unpack_combine`, so the fp16/bf16 `return_lse=True` cases pass. Test-only change.

Related: intel/intel-xpu-backend-for-triton#8361, where the single-device cases are currently skipped.

## Claims

- Fixes `TestPackedA2AKernels::test_pack_unpack_combine_matches_reference[*-True-float16|bfloat16]` (4 cases).
- Fixes the same issue in `_distributed_packed_a2a_worker` (`test_distributed_packed_a2a_matches_reference[float16|bfloat16]`, `test_distributed_packed_a2a_with_workspace_matches_reference`).

## Validation

<summary>Single-device emulation of the distributed test</summary>

`python emulate_distributed_packed_a2a.py xpu input` (before) / `... xpu fp32` (after):

```python
# Single-device emulation of _distributed_packed_a2a_worker: real pack/unpack
# kernels, all_to_all_single replaced by indexing the per-rank send buffers.
import sys

import torch

from vllm.v1.attention.ops.dcp import (
    _dcp_a2a_lse_pack_dim,
    _dcp_a2a_pack_send,
    _dcp_a2a_unpack_combine,
    _lse_weighted_combine,
)

device, upcast = sys.argv[1], sys.argv[2] == "fp32"
world_size, B, h_per_rank, D = 4, 5, 2, 32
H = world_size * h_per_rank
for dtype in (torch.float16, torch.bfloat16, torch.float32):
    pack_dim = _dcp_a2a_lse_pack_dim(dtype)
    outs, lses, sends = [], [], []
    for rank in range(world_size):
        g = torch.Generator(device=device)
        g.manual_seed(1234 + rank)
        out = torch.randn(B, H, D, device=device, dtype=dtype, generator=g)
        lse = torch.randn(B, H, device=device, dtype=dtype, generator=g)
        send = torch.empty(world_size, B, h_per_rank, D + pack_dim, device=device, dtype=dtype)
        _dcp_a2a_pack_send(out, lse, send, world_size, h_per_rank, D, pack_dim)
        outs.append(out), lses.append(lse), sends.append(send)
    status = "ok"
    for rank in range(world_size):
        recv = torch.stack([s[rank] for s in sends])
        _, actual_lse = _dcp_a2a_unpack_combine(recv, D, pack_dim, True, True)
        sl = slice(rank * h_per_rank, (rank + 1) * h_per_rank)
        ref_out = torch.stack([t[:, sl, :] for t in outs]).float()
        ref_lse = torch.stack([t[:, sl] for t in lses])
        if upcast:
            ref_lse = ref_lse.float()
        _, expected_lse = _lse_weighted_combine(ref_out, ref_lse, return_lse=True, is_lse_base_on_e=True)
        try:
            torch.testing.assert_close(actual_lse, expected_lse, rtol=1e-4, atol=1e-4)
        except AssertionError as e:
            status = str(e).splitlines()[0]
            break
    print(f"{str(dtype):15} {status}")
```

## Details

Regressed in #50484, which switched the test LSE inputs from fp32 to the input dtype without updating the references. The kernel combines in fp32 and returns an fp32 LSE, so the expected LSE had the wrong dtype, and casting it is not enough: combined in fp16/bf16 it differs from the kernel by up to ~1.5e-3/~1.5e-2, beyond the 1e-4 tolerance. Upcasting the LSEs fixes both while keeping the reduced-precision coverage, and makes the reference weights fp32 as in the kernel.

#55492 also makes these cases pass, by widening the LSE tolerance to 3e-2, and wires this file into CI (no Buildkite step runs it today). This PR keeps 1e-4 instead, per `tests/AGENTS.md` ("keep tolerances as tight as the math allows"). The two PRs merge without conflict in this file, so once this lands #55492's LSE tolerance changes are unnecessary and would loosen the check again.
