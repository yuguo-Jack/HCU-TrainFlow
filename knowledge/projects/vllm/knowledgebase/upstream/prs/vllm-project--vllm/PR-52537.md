# [Feat][Bench] Allow random dataset to sample real tokens from --dataset-path

[Upstream PR](https://github.com/vllm-project/vllm/pull/52537) · state: open · merged: False

## Original PR description

## Purpose

Allow the `random` dataset in `vllm bench serve` to accept `--dataset-path`. When provided, tokens are sampled from the file and truncated/repeated to fill `--random-input-len`, instead of using purely random token IDs. File format is auto-detected from the extension (.json, .jsonl, .txt).

This aligns vLLM's benchmark behavior with SGLang, enabling realistic input distributions at fixed lengths for speculative decoding benchmarks.

Closes #52536

## Changes

- Remove `"random"` from the dataset-path restriction list in `serve.py`
- Add auto-detect file format logic in `RandomDataset.sample()`:
  - `.json` → ShareGPT format (conversations array)
  - `.jsonl` → custom format with "prompt" field
  - `.txt` → plain text, one line per entry
- Use top-level imports (`json`, `random`, `Path`) instead of local aliases
- No new CLI arguments added

## Test Plan

```bash
# Test with ShareGPT
vllm bench serve \
    --dataset-name random \
    --dataset-path /data/ShareGPT_V3_unfiltered_cleaned_split.json \
    --random-input-len 8192 \
    --random-output-len 1024 \
    --num-prompts 8 \
    --max-concurrency 8

# Test without dataset-path (existing behavior unchanged)
vllm bench serve \
    --dataset-name random \
    --random-input-len 8192 \
    --random-output-len 1024 \
    --num-prompts 8 \
    --max-concurrency 8
```

## Test Result

Both commands ran successfully on a server with 8x NVIDIA GPUs (DeepSeek-V4-Flash model, TP=8, kv-cache-dtype=fp8, DSpark speculative decoding with num_speculative_tokens=5). With `--dataset-path`, `Total input tokens` was 8192 per request (confirmed from benchmark output). Without `--dataset-path`, behavior is unchanged (purely random token IDs).

- wuhangxian · comment · 2026-08-26T07:48:04Z · [source](https://github.com/vllm-project/vllm/pull/52537#issuecomment-5422229530)

Pushed `1061889`, which hardens the source-sampling RNG behavior and adds an offline regression test. Recap for reviewers:

### The problem
The `RandomDataset` source-sampling path (loading prompts from a `--dataset-path` file) did two things it shouldn't:

1. **Polluted global RNG.** It called `random.seed(self.random_seed)` and `random.shuffle(...)` on Python's *global* `random` module. Any other code in the same process that relies on the global RNG (or on it being left alone) is silently perturbed by running the benchmark dataset loader.
2. **Biased the sample.** It scanned only the head of the file, extending `source_token_pool` until it hit `max(input_lens) * 2`, then `break`ing — so the "random" sample was really just the first N entries, in file order.

### The fix
Collect the full candidate text list first, then shuffle it once with the class-isolated generator `self._rng` (`np.random.default_rng(self.random_seed)`), leaving global `random`/`np.random` state untouched. The token pool is now a random sample over the whole dataset and is reproducible from the seed without side effects. Blank `.jsonl` lines and ShareGPT turns missing a `value` key are skipped instead of raising. The change is confined to the source-sampling block; other dataset paths are untouched.

### Tests
Two files cover this at different levels:

- **`tests/benchmarks/test_random_dataset_source.py`** (already in this PR, 8 tests) — end-to-end against a real `openai-community/gpt2` tokenizer: sharegpt/jsonl/txt sources, `input_len` handling, no-source path unchanged, same-seed reproducibility, unsupported extension, empty file.
- **`tests/benchmarks/test_random_dataset_source_offline.py`** (new here, 5 tests) — uses a tiny `FakeTokenizer` so it needs no network download and no GPU, pinning the exact guarantees of the fix: global RNG untouched, blank `.jsonl` lines skipped, malformed ShareGPT turns skipped, sampled tokens originate from the pool, and same-seed reproducibility. This is the CI-stable guard; the real-tokenizer file provides end-to-end coverage where an HF download is available.
