# [Doc] Use Qwen/Qwen3-0.6B instead of OPT in docs examples

[Upstream PR](https://github.com/vllm-project/vllm/pull/62747) · state: open · merged: False

## Original PR description



## Overview

Replace `facebook/opt-125m` / `facebook/opt-13b` in the docs examples with `Qwen/Qwen3-0.6B`, which is also the default model for `vllm serve`. Addresses #50165.

## Claims

- Quickstart, `arch_overview`, `generative_models`, `custom_logitsprocs`, FP8 quantization, CPU install, tensorizer, parallelism, and XPU install docs now use `Qwen/Qwen3-0.6B`.
- The docs match the CLI default, and examples work on backends that need safetensors (OPT ships only `.bin`, which breaks `vllm-metal` per #50165).

## Validation

- Ran the FP8 doc snippet with `Qwen/Qwen3-0.6B` on 1x B300 (`LLM("Qwen/Qwen3-0.6B", quantization="fp8_per_tensor")`): it generates coherent text. I replaced the stale OPT log line in that snippet (`0.1550 GB`) with the real output (`Model loading took 0.71 GiB memory`).
- `pre-commit run` on the changed files: markdownlint and typos pass.

## Details

- Left unchanged on purpose:
  - `supported_models.md`: the OPT entry in the supported-models table.
  - `triton.md`, `production-stack.md`: these describe external projects' tutorials, which use opt-125m.
  - `helm.md`: it mirrors the chart's `values.yaml`.
- The TP=4 (`parallelism_scaling.md`) and TP=8/PP=2 (XPU) examples now use Qwen3-0.6B too. It has 8 KV heads and 28 layers, so these layouts are valid; the examples only show syntax.
- `examples/` still has ~17 files using `facebook/opt-125m`. I'm leaving them for a follow-up so each one can be run.
- Not a duplicate: the earlier PRs for #50165 (#50167, #51591) are closed and only added a Metal note to the quickstart. No open PR replaces OPT in the docs.
