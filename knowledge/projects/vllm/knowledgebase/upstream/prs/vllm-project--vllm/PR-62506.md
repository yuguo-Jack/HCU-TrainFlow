# [Bugfix][Frontend] Validate chat response JSON Schema keyword values

[Upstream PR](https://github.com/vllm-project/vllm/pull/62506) · state: open · merged: False

## Original PR description



## Overview

Validate the contents of chat `response_format.json_schema.schema` before generation. A well-shaped request can currently contain invalid keyword values such as `minLength: -1`, which xgrammar 0.2.8 also accepts.

## Claims

- Reject malformed schema keyword values with `VLLMValidationError(parameter="response_format")` at request construction.
- Map these failures to HTTP 400 before the route handler for both `stream=false` and `stream=true`.
- Preserve valid schemas, including backend-supported Unicode regex properties, and apply the existing JSON nesting limit before recursive meta-schema validation.

## Validation

Python 3.12.15, PyTorch 2.14.1+cpu, jsonschema 4.26.0, xgrammar 0.2.8, Linux x86_64. Complete target request modules and actual vLLM exception handlers, without a GPU model engine.

  tests/entrypoints/openai/chat_completion/test_chat_error.py

For `{"type":"string","minLength":-1}`, a comparison using complete baseline/candidate protocol modules and vLLM's exception handlers in a minimal FastAPI app gave:

| Request | Baseline | Candidate |
| --- | --- | --- |
| non-streaming | request accepted, route reached (200) | rejected before route (400) |
| streaming | request accepted, route reached (200) | rejected before route (400) |

This is request-boundary validation, not a full `vllm serve`/generation test. Independently, baseline `to_sampling_params` followed by `validate_xgrammar_grammar` accepted this invalid schema. No model score or throughput improvement is claimed.

Tradeoff: a five-repeat, 100-requests-per-repeat constructor microbenchmark of a small object schema measured median ~27.90us before vs ~660.82us after on this shared host. The added validation has CPU cost; requests without `response_format.type=json_schema` skip it. The human submitter confirmed review of the changes before publication. These are agent-run tests; a separate human-run test result is not asserted. AI assistance was used for investigation, implementation and validation.

## Details

The existing validator checks that the `json_schema` wrapper exists, while Pydantic checks the dictionary shape. Neither establishes that the dictionary is a valid JSON Schema. Select the validator from its declared dialect and validate against its meta-schema, without a Python regex format checker: grammar backends accept regex features such as `\p{L}` that Python's `re` format check rejects. This does not rewrite schemas or enforce backend feature support; existing backend validation remains responsible for that.

Ported from downstream C550 request-validation work. The existing nesting bound runs first so the new recursive validator does not bypass nesting protection. This PR only changes Chat Completions response-format schemas; it does not change tools, structural tags, the Responses API or grammar generation.

Duplicate search on 2026-10-20: `json_schema validation`, `schema check_schema`, `schema metaschema`, and `JSON Schema invalid`. #43751 validates outer response-format shapes, not schema keyword values; #58940 handles backend-unsupported features nested in structural tags; #47176 targets Rust parity. This patch addresses schema validity inside an otherwise well-shaped Python chat request.
