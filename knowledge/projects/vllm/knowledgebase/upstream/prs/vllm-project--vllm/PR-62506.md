# [Bugfix][Frontend] Validate chat response JSON Schema keyword values

[Upstream PR](https://github.com/vllm-project/vllm/pull/62506) · state: open · merged: False

## Original PR description

## Overview

Reject invalid Chat Completions JSON Schemas before generation. For example, `{"type":"string","minLength":-1}` currently passes request validation and is also accepted by xgrammar 0.2.8.

## Claims

- Invalid schema keywords return HTTP 400 with `error.param=response_format`, for both streaming modes.
- Explicit non-string `$schema` values are rejected before dialect selection, fixing the reviewer's `{"$schema":42}` HTTP 500 reproducer.

## Validation

Rebased onto `1ca0dfb9` on Oct 29 with the same PR patch. The CPU JSON Schema suite passed again: 34 passed, 30 deselected. Applicable changed-file pre-commit checks also passed.

The expanded CPU suite produced 10 failures / 24 passes against the original protocol and 34 passes / 30 deselections with the fix. It covers invalid keywords and dialect values, omitted/valid dialects, Unicode patterns, nesting limits, and HTTP 400 before the handler. 

```bash
VLLM_TARGET_DEVICE=cpu VLLM_PLUGINS='' .venv/bin/python -m pytest \
  tests/entrypoints/openai/chat_completion/test_chat_error.py \
  --confcutdir=tests/entrypoints/openai/chat_completion -k json_schema -q
```

Python 3.12.15, torch 2.14.1+cpu, jsonschema 4.26.0 and xgrammar 0.2.8. Tests use the complete request modules and actual exception handlers in-process. Applicable pre-commit hooks passed, including mypy and CI test tethering. No model generation test was run.

There is added CPU cost: a small-schema constructor benchmark measured median 27.90 µs before and 660.82 µs after (five repeats of 100 requests on a shared host). Requests without `response_format.type=json_schema` skip this validation.

## Details

Pydantic validates the wrapper's shape, but not whether its contents form a valid JSON Schema. This checks the schema against its declared dialect's meta-schema after the existing nesting check.

A Python regex format checker is deliberately omitted: grammar backends support patterns such as `\p{L}` that Python's `re` rejects. Backend feature validation remains in place. The change is limited to Chat Completions response-format schemas.

The non-string dialect fix is in [8244126](https://github.com/rowanbyte/vllm/commit/82441264842ba2f9dd0dddf609e1c87673033bb6).
