## Code Review

This pull request aims to enable FP8 quantized query support for the Triton attention backend on ROCm platforms, enhancing performance. The change involves modifying a platform check from `is_cuda()` to `is_cuda_alike()`. While this correctly extends the feature to ROCm, it is overly broad as it enables the feature on all CUDA and ROCm devices, irrespective of their native FP8 hardware support. My review includes a critical suggestion to instead use `current_platform.supports_fp8()`. This provides a more robust, platform-agnostic check that correctly gates the feature based on hardware capabilities, preventing potential runtime errors on unsupported devices while still fulfilling the PR's objective.

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

The `supports_quant_query_input` flag should be tied to the platform's native FP8 support rather than just the platform type (CUDA/ROCm).

Using `current_platform.is_cuda_alike()` enables this feature for all CUDA and ROCm devices, including older hardware that lacks native FP8 support (e.g., NVIDIA Ampere GPUs). This could lead to runtime errors or performance issues if an unsupported FP8 format is used.

A more robust approach is to use `current_platform.supports_fp8()`. This method correctly checks for the specific hardware capabilities required for efficient FP8 operations (e.g., Hopper+ for NVIDIA, MI300+ for AMD), ensuring that quantized FP8 queries are only used on platforms that can handle them natively.

```suggestion
        self.supports_quant_query_input = current_platform.supports_fp8()
```
