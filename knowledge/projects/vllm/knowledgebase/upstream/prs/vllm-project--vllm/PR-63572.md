# [Bugfix] Wrap parallel-sampling child seeds into int64

[Upstream PR](https://github.com/vllm-project/vllm/pull/63572) · state: open · merged: False

## Original PR description



## Overview



Fix an EngineCore crash for parallel sampling (`n>1`) when the request seed is the top of the int64 range; child seeds are now wrapped into int64 instead of overflowing. Follow-up to #57018, which bounds only the parent seed.

## Claims



- `SamplingParams(n=2, seed=2**63 - 1)` no longer kills the EngineCore with `OverflowError` / `EngineDeadError` on Model Runner V2 (default runner).
- No change in output for any seed that did not overflow before: child seeds are still `seed + index` whenever that fits in int64
- On Model Runner V1 the wrapped seed initializes the `torch.Generator` identically to the old unwrapped one, so MRV1 outputs are unchanged even for the edge case.

## Details



**Root Cause:** `ParentRequest._get_child_sampling_params` derives each child's seed as `seed + index` on a shallow copy of the parent `SamplingParams`, after validation has already run. The OpenAI protocol (and #57018 for `SamplingParams`) accepts any seed in `[-2**63, 2**63 - 1]`, so a parent seed near the top of that range yields child seeds above `2**63 - 1`. MRV2 stores per-request seeds in an int64 `UvaBackedTensor` (`SamplingStates.add_request`), and the numpy assignment raises `OverflowError` inside EngineCore, killing the engine for every in-flight request.

**Fix:** Wrap the child seed into int64 with two's complement: `(seed + index - INT_64MIN) % 2**64 + INT_64MIN`. This is the identity whenever `seed + index` already fits, so existing seeded results are reproducible bit-for-bit, and children still get distinct seeds (`n` is far below `2**64`). Wrapping (rather than rejecting the request) keeps every seed the API accepts usable with `n>1`, and matches how `torch.Generator.manual_seed` interprets negative seeds, so MRV1 behavior is unchanged.

**Why this is not a duplicate.** #57018 (open) bounds `SamplingParams.seed` itself; the overflow here happens to *derived* child seeds after that check, so it is not fixed by #57018. No open PR touches `vllm/v1/engine/parallel_sampling.py`. #58914 (Rust frontend `n` support) and #58438 (DiffusionGemma `diffusion_samples`) derive per-sample seeds with the same `seed + index` pattern and may want the same wrap; they are not changed here.

**Tests.** A parametrized unit test on `ParentRequest` pins the child-seed contract (including the identity case), and one LLM-level test in `tests/v1/engine/test_llm_engine.py` reproduces the crash through `LLM.generate`. Both run in the existing ":nvidia: (L4) V1 Engine" Buildkite step (`pytest -v -s v1/engine`).
