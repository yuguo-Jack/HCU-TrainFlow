# [Bugfix][Spec Decode] Clear stale block-table rows for padded MTP decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/61174) · state: open · merged: False

## Original PR description

## Purpose

Mixed prefill/decode batches can select an MTP decode graph with more rows than the target batch. The extra block-table rows can retain another request's block IDs. On GLM-5.3-Flash, a padded KPool tail write then corrupts that request's KDA state.

Refresh the shared block tables after choosing the draft graph size. During dummy runs, clear only the extra rows, preserving valid profiling slots.

This fixes the MRV2 draft block-table rows, separate from #45005 (legacy slot-mapping padding) and #60767 (sliding-window columns). No LMCache dependency or model-math change.
