# [Bugfix] Apply the missing prefill decay step in lightning attention

[Upstream PR](https://github.com/vllm-project/vllm/pull/61735) · state: open · merged: False

## Original PR description

## Overview

Fixes #61730: apply the missing decay step to incoming KV state during lightning-attention prefill, making long prompts and cached chunks consistent with the decode recurrence.

## Claims

- Correct output after the first 256-token block and from the first token when continuing from nonzero history.
- Add 20 FP64-reference regression cases covering block boundaries, partial blocks, final KV state, and history preservation.

## Validation

Tested on WSL with RTX 3050 OEM (8 GB), Python 3.12, PyTorch 2.14.0+cu132, and Triton 3.8.0, reusing existing compiled extensions.

| Check | Result |
| --- | --- |
| New regression cases before fix | 14 failed, 6 passed |
| Complete attention test file after fix, default precision | 30 passed |
| Complete attention test file with `TRITON_F32_DEFAULT=ieee` | 30 passed |
| Real MiniMax prefill wrapper: 599 tokens, full prefill versus chunks 63/257/19/256 followed by four decode tokens; nonzero history, three seeds | Outputs and final states match FP64 recurrence; IEEE max absolute error / output RMS ≤ 4.8e-6 |
| Repository pre-commit hooks, including mypy and test CI tethering | Passed |

Reproduce the committed regressions:

```bash
python -m pytest tests/kernels/attention/test_lightning_attn.py -q
TRITON_F32_DEFAULT=ieee python -m pytest tests/kernels/attention/test_lightning_attn.py -q
pre-commit run --files vllm/model_executor/layers/lightning_attn.py tests/kernels/attention/test_lightning_attn.py
```

Regression lengths: 1, 63, 64, 65, 255, 256, 257, 300, 512, and 769, with and without history; two batches, four slopes including zero. Comparisons use FP64 closed-form recurrence and per-head normalization with tolerance for default TF32 rounding.

Full pretrained-model generation/quality evaluation was not run: the affected full models do not fit this 8 GB GPU. Validation covers the actual MiniMax prefill caller and decode transition, rather than a complete serving run. Head size 64 was tested; other head sizes and ROCm/XPU remain unvalidated.

## Details

The incoming KV state represents the state immediately before the block. Its contribution to query position `c` therefore needs `exp(-s * (c + 1))`. The previous `exp(-s * c)` skipped one decay step, while diagonal attention and decode already followed the correct recurrence. The fix changes only this exponent; it adds no launch, allocation, synchronization, or interface changes.

The regression cases extend the existing attention suite. No performance improvement is claimed.

Duplicate check: no open PR referencing #61730 or addressing this decay-index fix was found before submission. #41508 changes shared-memory sizing and addresses a different issue. The issue discussion includes another contributor expressing interest.

AI assistance was used to implement and validate this change.
