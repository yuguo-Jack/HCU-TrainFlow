# [CI] Split (H100) LM Eval Humming Activation FP8/INT8 into per-model jobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/58587) · state: closed · merged: False

## Original PR description

> **Stacked on #58195** (B200 split). Review only the top commit; this PR also contains #58195's commit until that one merges.

## What

`:nvidia: (H100) LM Eval Humming Activation FP8/INT8 TEMPORARY` runs the same 16 GSM8K activation-quant configs as the B200 job (`config-act-fp8.txt` + `config-act-int8.txt`) as two sequential pytest invocations in one optional pod, several times over the 20-minute target. This replaces it with seven content-named single-replica jobs, one config list each, following #57965 and #58195.

```
lm-eval-humming-h100-act   "(H100) LM Eval Humming Activation FP8/INT8 TEMPORARY"   timeout 90
├── config-act-fp8.txt   (9 configs)
└── config-act-int8.txt  (7 configs)
```

Old → new key: `lm-eval-humming-h100-act` → the seven `lm-eval-humming-h100-*` keys, each with its own `config-h100-*.txt`. This job was the last consumer of `config-act-fp8.txt` and `config-act-int8.txt`, so both are removed.

## Expected runtime and overhead

Predictions from per-config log timestamps on the three most recent passing `main` runs that include both lists, as a share of the old job's pytest time:

| job | pytest (share of old) | non-pytest overhead | main overhead cause |
| --- | ---: | ---: | --- |
| Qwen3.5 35B Activation INT8 | ~20% | ~1m | pod setup + checkout |
| Qwen3 30B W4 Activation FP8 | ~17% | ~1m | pod setup + checkout |
| Qwen3 30B Activation INT8 | ~16% | ~1m | pod setup + checkout |
| Small Models | ~16% | ~1m | pod setup + checkout |
| Qwen3 30B W8 Activation FP8 | ~11% | ~1m | pod setup + checkout |
| Qwen3.5 35B Activation FP8 | ~10% | ~1m | pod setup + checkout |
| GPT-OSS | ~9% | ~1m | pod setup + checkout |

- Slowest job stays under the 20-minute target on the worst of the three runs; timeouts drop 90 → 30.
- Aggregate: about +7 worker-minutes versus the unsharded job (six repeated pod setups), inside the ≤20 budget.
- **Why seven jobs, not #58195's five:** on this lane the Qwen3.5 35B group and the Qwen3 30B Activation FP8 group each exceed 20 minutes. They are split along axes the configs already encode: Qwen3.5 by activation dtype, Qwen3 30B FP8 by weight width (W8 = FP8 weights; W4 = MXFP4, GPTQ-Int4, AWQ).

## Notes

- **Same 16 configs, unchanged.** The seven lists are multiset-equal to `main`'s `config-act-fp8.txt` + `config-act-int8.txt`, including `Qwen3-30B-A3B-AWQ-humming.yaml`, which runs in both lists today and so appears in both the W4 FP8 and INT8 jobs. No config YAML is modified.
- **Convention:** content-named single-replica jobs with per-job config lists, as in #57965 — no `parallelism`, no `Shard %N`, no indexed shard lists.
- **Seven block steps instead of one.** Each job keeps `optional: true`, device, `num_devices` and `source_file_dependencies` from the old job.
- No test files move; no AMD mirror; no other consumer of the old key or the removed lists (grep across this repo, ci-infra, vllm-dashboard).
