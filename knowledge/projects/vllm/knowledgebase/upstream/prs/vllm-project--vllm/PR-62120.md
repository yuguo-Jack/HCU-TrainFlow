# [CI] Move B200 Kernels and MoE Refactor evals from manual to automatic shards

[Upstream PR](https://github.com/vllm-project/vllm/pull/62120) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Moves three steps that split their tests by hand onto `automatic_shard`, following #62077 and #62084. `kernels-b200` ran a hand-written `case "$$BUILDKITE_PARALLEL_JOB"` block per shard. The two MoE Refactor integration steps read a different config list in each shard (`config-*-shard-$$BUILDKITE_PARALLEL_JOB.txt`). Each now runs plain pytest, the planner splits it using main's timings, and new tests or configs no longer need placing in a shard by hand.

## Claims

| Step | Was | Planned shards |
|---|---:|---:|
| `kernels-b200` | 3 hand-written `case` shards | 3 |
| `moe-refactor-integration-test-b200-temporary` | 4 config-list shards | 6 |
| `moe-refactor-integration-test-h100-temporary` | 4 config-list shards | 4 |

- Every test and every config runs exactly once across the shards, with the same environment as before.
- A test file or config added later is placed by the planner, not by editing a `case` arm or a shard list.
- Labels drop `Shard %N`; the generator names jobs `<label> shard N/M`.
- The AMD mirrors (NVFP4 Dense Emulation, both MoE Refactor mirrors) are short. They stop inheriting the fixed shards and run as one job each.

## Validation

- Planned each step with ci-infra main's `runtime_shard.plan_step` against this branch and main's timings.
- Rendered each step with the pipeline generator and ran every shard's commands against a mock test tree, as a PR build and with main's `pytest -p ci_otel` wrapper. Every test of every command ran in exactly one shard, with the same env (6/6 cases).
- For the config-list steps, also ran the generated shard jobs against vLLM's real `tests/evals/gsm8k/conftest.py` and config files, with the test body stubbed. All 19 B200 configs and all 12 H100 configs ran once each across the shards. No shard printed `not in the plan`, so the plan matched every config ID that main has timings for.
- `/ci run` [97474](https://buildkite.com/vllm/ci/builds/97474), rebased on main after ci-infra#836:
  - `kernels-b200` passed in 3 shards. Its 28 pytest runs total 2640 passed, 504 skipped and 1424 deselected, the same as main [97527](https://buildkite.com/vllm/ci/builds/97527); machine time in line with main.
  - The MoE Refactor B200 step passed in 6 shards and the H100 step in 4, with all 19 B200 and all 12 H100 configs passing once each, as on main. Machine time is in line with main for both.
  - All three AMD mirrors passed as one job each.

## Details

- **`kernels-b200` setup.** `python3 examples/basic/offline_inference/chat.py` was in shard 1 only. The planner needs plain pytest after the first pytest command, so it now runs as a setup command, once in each shard.
- **Config lists.** `moe-refactor/config-b200.txt` already listed exactly the union of the four B200 shard lists. `config-h100.txt` is the union of the four H100 shard lists. The per-shard lists are removed.
- **ROCm list kept twice.** The H100 step's AMD mirror now reads a new combined `config-rocm.txt`. `config-rocm-shard-*.txt` stay because the separate `.buildkite/test-amd.yaml` still reads them.
- **`moe-refactor-integration-test-h100-temporary`.** Before ci-infra#836 the planner gave it 3 shards that ran longer than the old fixed shards. With each job's setup now in the budget it plans 4, each under the 20-minute target.
- **Timeouts unchanged (human).** As in #62077 and #62084, `timeout_in_minutes` stays per job. A single-job fallback (no plan, or the `VLLM_CI_RUNTIME_SHARD` rollback switch) would outrun it. Fallback-aware timeouts belong in a central timeout setting.
- **Left out.** `distributed-model-tests-2-gpus` and `lora-tp-distributed` move in #62537, and `basic-models-tests-extra-initialization` in #63907. `spec-decode-mtp-other-acceptance-nightly` and the Humming A100/H100 steps stay on fixed shards: their fixed shards are already as short as a plan can make them, or they have no timings.
