# [Doc][CI][ROCm] Attention backend test standard (agent skill) with the ROCM_AITER_FA reference suite

[Upstream PR](https://github.com/vllm-project/vllm/pull/63685) · state: open · merged: False

## Original PR description


_Requested by **Tun Jian**_



## Overview

This proposes a test standard for vLLM attention backends, as an agent skill, together with its reference implementation: the ROCM_AITER_FA test suite. It is opened for review of the standard itself; see the RFC (https://github.com/vllm-project/vllm/issues/63640). The same suite lands separately in #63675 (tests only, with known defects as strict xfails), and each defect it found is fixed in its own PR stacked on #63675 (#63676 to #63684).

## Claims

- **Standard** (`.agents/skills/attention-backend-testing/`, also linked from `.claude/skills/`). It sets rules for:
  - enumerating every dispatch path and testing each one with a kernel spy and a float32 reference;
  - testing declarations both ways;
  - covering phases and their mixtures;
  - taking shapes from real model configs;
  - testing boundaries (including rows with no query tokens after the real rows: CUDA graph padding and async KV connector loads, through every chunking path) and CUDA graph modes;
  - keeping hidden syncs out of captured paths and sizing the workspace per config;
  - running a dummy-weight model through the runtime;
  - testing context parallelism or rejecting it;
  - sharding;
  - landing the suite before its fixes.
  It also has a "nuances that make a passing test meaningless" section.
- **References:**
  - a coverage matrix to copy into each backend's PR;
  - model shapes;
  - a CI and perf/accuracy artifact plan;
  - a review checklist.
- **Review checklist:** per-request chunk planners must never emit a chunk with no query tokens (#55695, #51489).
- **Reference implementation:** the ROCM_AITER_FA unit and engine suites, the strict-xfail registry `known_defects.py`, and sharded MI355 CI steps (identical to #63675).

## Validation

The suite here is the one in #63675. On the current backend it runs green on MI350X: 3791 unit tests pass, 33 engine tests pass, and the 93 registered tests are strict xfails. Each fix PR (#63676 to #63684) was verified with a full unit run on its own branch.

With all fixes applied, every registered backend defect passes. One new entry remains: #63677 found that AITER's gfx950 Gluon `unified_attention` misreads KV blocks beyond a 2 GiB offset when the per-layer K view is 1-2 GiB, because its 32-bit buffer-load check ignores the interleaved K/V stride. #63677 registers it as a defect outside the backend.

## Details

A readable version of the standard, with the ROCM_AITER_FA findings, is at [vLLM Attention Backend Test Standard](https://claude.ai/artifact/MsYhGoXzoMVb8YSLZAcRSP).

Workflow the standard proposes for a new backend suite:
1. Land the suite with every found defect registered as a strict xfail.
2. Land one PR per defect that deletes its registry entry.

Strict mode makes a fix prove itself: a registered test that starts passing fails the run.
