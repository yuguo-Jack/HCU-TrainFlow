# [Bugfix] Close newly allocated ZMQ sockets when setup fails

[Upstream PR](https://github.com/vllm-project/vllm/pull/61376) · state: open · merged: False

## Original PR description



## Overview

`make_zmq_socket` leaves its newly allocated socket open if configuration or binding fails. Close that socket with zero linger before propagating the original failure.

## Claims

- Failed socket setup closes the socket allocated by this helper, including interruption during setup.
- The caller's context and existing sockets remain open; successful configuration and the returned socket are unchanged.

## Validation

The six new cases use actual synchronous and asynchronous ZeroMQ contexts. They reproduce an occupied TCP bind, an invalid address, and `KeyboardInterrupt` during configuration. All six fail on the original code and pass after the repair.

On Windows with CPU PyTorch, 26 tests pass:
```bash
uv run --active --no-project --python /path/to/cpu-python -m pytest tests/utils_/test_network_utils.py --confcutdir=tests/utils_ -q -p no:cacheprovider -k 'not adopts_listener and not failed_ipc_bind and (not get_open_port or reserved or ephemeral or get_open_ports_list)' -vv
```

Three existing listener/IPC cases were not run in this Windows scope. The omitted existing `test_get_open_port` fails identically on the original source with `WinError 10048`. All applicable normal pre-commit hooks pass in a Linux-local checkout after verifying all 7,739 baseline Git blobs. Linux runtime tests were not run because the cached lint environment lacks real PyTorch and other runtime dependencies; no GPU or serving performance claim is made.

The existing Buildkite utility lanes run `pytest -v -s utils_`, which includes this test file.

This is a failure-resource ownership repair in a shared utility: successful socket options, operation order, and return type are unchanged. Validation exercises that utility with real ZeroMQ objects; it does not start an engine or constitute serving end-to-end validation. No CPU engine/manager integration repro was run.

The human submitter reviewed every changed line and personally reran the CPU checks above before publication.

## Details

Allocation succeeds before socket options, address parsing, and bind/connect. An exception retains the local socket in its traceback, while the caller never receives a socket it can close. Catching `BaseException` around setup releases this owned resource before re-raising, without destroying the shared context.

The shared helper is used by engine/coordinator clients and KV/EC connectors with both context types. This change covers the allocated ZeroMQ socket; it does not claim to repair every inherited-listener file-descriptor ownership case.

Open overlapping-file PRs were checked: [#30520](https://github.com/vllm-project/vllm/pull/30520) changes wildcard address binding and [#59113](https://github.com/vllm-project/vllm/pull/59113) changes IPC permissions. Neither closes the socket when setup fails, so this is a separate resource-ownership repair.
