# [Perf][Distributed] Skip movedim+reshape for dim=0 in CudaCommunicator all_gather

[Upstream PR](https://github.com/vllm-project/vllm/pull/61136) · state: open · merged: False

## Original PR description

## Overview

Skip redundant `movedim` + `reshape` tensor view operations when `dim=0` in `CudaCommunicator.all_gather`, the common case for sequence parallelism.

## Duplicate-work check

Sibling PRs #61138, #61139, #61140 each touch a different function in a different communicator class (`CudaCommunicator.reduce_scatter`, `DeviceCommunicatorBase.all_gather`, `DeviceCommunicatorBase.reduce_scatter`); none overlaps with this diff. `gh pr list --search "movedim"` and `--search "cuda_communicator all_gather"` turned up no other open PR touching this function.

## Performance

**Isolated microbenchmark** (the exact removed chain -- `reshape` + `movedim(0,0)` + `reshape` -- timed with no NCCL call in the region, 2000 reps, warm-started, p10/p90 spread <0.2us across all shapes/devices tested):

| | old (median) | new (median) | delta |
|---|---|---|---|
| all_gather tail | 3.40-3.55us | 0.08us | **~3.3-3.4us** |

**End-to-end** (real NCCL TP=2 on 2x RTX 5090, 100 trials/condition, old/new order alternated, both ranks' times reduced with MAX): the effect is there in direction but mostly inside this host's own call-to-call noise (shared machine, other users' GPU jobs running throughout):

| shape | old median | new median | speedup | old p10-p90 | new p10-p90 |
|---|---|---|---|---|---|
| (2, 4096) | 68.37us | 67.54us | 1.01x | 49-88us | 43-85us |
| (4096, 4096) | 1761.79us | 1769.47us | 0.996x | 1510-1997us | 1528-2025us |

**Applicability**: this only saves time in eager execution (prefill, or decode without CUDA graphs). Under CUDA graph capture, a no-op `reshape` on an already-contiguous tensor enqueues no GPU kernel, so captured-graph replay time is unaffected either way -- the benefit is per-prefill-call, not per-decode-step.

**Reachability**: `dim=0` `all_gather` is exercised by the sequence-parallel path in DeepSeek-V2/V3, Llama4, Qwen3 (MTP/Next MTP), GPT-OSS, and the vision multimodal embedding-gather path -- this is live production code, not a rarely-hit branch.

**Rough extrapolation**: a 60-layer sequence-parallel model doing one `all_gather` per layer during prefill would save on the order of 60 x 3.3us ~= 200us per request from this PR alone -- small but real and directionally consistent across shapes, devices, and 2000 isolated repetitions.

## Claims

- Eliminates 2-3 redundant tensor view operations per `all_gather(dim=0)` call, measured at ~3.3-3.4us/call in isolation (see Performance)
- On the TP forward pass hot path for sequence-parallel models, in eager/prefill execution

## Validation

- `ruff check` and `ruff format --check`: all passed
- Logic verification: when `dim=0`, `movedim(0, 0)` returns the same tensor (no-op), and `reshape` produces the same shape -- skipping them is behavior-preserving
- Isolated and end-to-end microbenchmarks: see Performance section above

## Details

`all_gather` with `dim=0` performs:
1. `output_tensor.reshape((world_size,) + input_size)` — creates a view
2. `output_tensor.movedim(0, 0)` — no-op, returns same tensor
3. `output_tensor.reshape(output_size)` — same shape as before step 1

All three are redundant when `dim=0`. Return `output_tensor` directly after `all_gather`.
