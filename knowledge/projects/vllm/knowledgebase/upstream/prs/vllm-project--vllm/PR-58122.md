# [Model][Perf] Add LLaVA encoder CUDA graphs for CLIP, SigLIP, and Pixtral

[Upstream PR](https://github.com/vllm-project/vllm/pull/58122) · state: open · merged: False

## Original PR description

## Purpose

Standard `LlavaForConditionalGeneration` currently cannot use the multimodal encoder CUDA graph option. This change captures its CLIP/SigLIP or HF-format Pixtral vision tower and multimodal projector through the existing encoder graph manager. It supports image batches, preserves graph output ownership, and retains eager fallback. HF Pixtral supports variable image resolutions by packing patches before capture and isolating padding as an extra attention sequence. Its graph path requires full vision features and FLASH_ATTN or TRITON_ATTN.

Precomputed `image_embeds` bypass the image graph in both model runners. Auto-generated graph budgets also accommodate one complete image when the decoder uses a smaller chunked-prefill budget.

Related to #38175. Duplicate checks on 2026-09-22 found #57379, which implements the separate `llava_onevision.py` architecture with any-resolution/video handling. This PR targets `llava.py`; it does not duplicate OneVision. The September 29 Pixtral follow-up addresses the review request here. Related open #56277 targets native Pixtral/Mistral3, whereas this change handles HF Pixtral through `LlavaForConditionalGeneration`.

## Original CLIP/SigLIP performance and limits

Single RTX 4090, PyTorch 2.13.0+cu132, BF16, vision TRITON_ATTN, graph budgets [729,1458], maximum image batch 2. Decoder compilation/graphs and prefix/processor caches disabled in both arms. Results below are medians of per-process medians (3 processes per arm); this is a small offline experiment, not an HTTP load test or VQA accuracy evaluation.

| Measurement | Eager | Encoder graph | Change |
|---|---:|---:|---:|
| Engine first-token latency | 98.18 ms | 86.46 ms | −11.9% |
| Full 32-token request | 451.04 ms | 442.63 ms | −1.9% |
| Encoder, 1 image | 10.336 ms | 9.281 ms | −10.2% |
| Encoder, 2 images | 17.490 ms | 17.400 ms | −0.5% |
| Encoder, 4 images (graph splits 2+2) | 30.939 ms | 34.887 ms | +12.8% |

Encoder measurements use six alternating rounds of 20 forwards in one process. Startup medians were 13.04 s eager / 13.99 s graph, with a 21.50 s eager outlier; these do not isolate capture cost. Initial allocated tensor memory increased by 15.86 MiB; allocator reservation is workload dependent.

BF16 output is sensitive to batch shape: native eager batch 3 differs from eager split 2+1 (maximum absolute embedding difference 5.0), while graph split 2+1 is bitwise equal to eager split 2+1. This change does not promise identical generation across arbitrary padding/splitting geometries. The measured end-to-end cases contain one or two images. Full real-weight CLIP, multi-GPU, other GPU architectures, and broad quality benchmarks are untested.

Runtime provenance: main Python source at `f92b78f6ef9c9b28f60668da77af5b65645b1a45` with existing vLLM 0.29.0 precompiled native libraries. This is a source-overlay validation, not a clean main wheel build; upstream CI remains required. Benchmark scripts, raw JSON/logs, and reproduction notes are prepared with the patch for reviewer sharing.

## HF Pixtral follow-up validation (September 29)

- 88 focused tests passed using the same three regression files above, including variable-resolution Pixtral replay, changed image geometry, output ownership and oversized fallback. GPU cases cover FP16/BF16 and FLASH_ATTN/TRITON_ATTN. The five new Pixtral cases failed before implementation and passed afterward.
- Those five Pixtral cases also passed with Transformers 5.16.0 (flattened RoPE), in addition to 5.17.0 (axial RoPE).
- Upstream `test_vit_cudagraph_image[pixtral_hf]` passed with default decoder compilation/graphs, FLASH_ATTN and a 4096-token encoder graph budget. This is a one-layer dummy-weight integration test, not real 12B generation validation.
- Pre-commit checks, including Ruff and mypy, passed for all five follow-up files.
- Real vision/projector weights from `mistral-community/pixtral-12b`, revision `c2756cbbb9422eba9f6c5c439a214b0392dfc998`: all 222 source tensors loaded, eight image-output comparisons per backend, mixed resolutions, replay ownership and oversized fallback. FP16 (checkpoint weights cast in both arms) passes cosine >= 0.999 and relative L2 <= 0.02: worst relative L2 0.016704 / 0.008078 and minimum cosine 0.999862 / 0.999968 for FLASH_ATTN / TRITON_ATTN.

**BF16 limitation:** the real-weight native-eager comparison fails that strict tolerance: worst relative L2 0.053815 / 0.024370 and minimum cosine 0.998553 / 0.999705 for FLASH_ATTN / TRITON_ATTN (max absolute error 16.875 / 9.75). Isolated diagnostics show exact unpadded packed-vs-native and exact padded-eager-vs-replay outputs. Padding/batching changes low-precision GEMM geometry; disabling BF16 reduced-precision reduction did not eliminate the difference. No precision flag changes or relaxed real-weight tolerance are included in the patch. Full real-weight 12B generation/VQA evaluation remains untested, so the dummy generation test and encoder similarities should not be read as full-model accuracy evidence.
