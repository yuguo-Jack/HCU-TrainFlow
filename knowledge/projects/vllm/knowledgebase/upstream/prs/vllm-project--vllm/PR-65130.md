# [Model Runner V2][Spec Decode] Draft token heads for block-diffusion speculators

[Upstream PR](https://github.com/vllm-project/vllm/pull/65130) · state: open · merged: False

## Original PR description

## Purpose

A step toward modular block-diffusion speculators, where the backbone, the causal corrector and the acceptance estimator can be combined independently. Builds on the speculator config registry from #63205.

## What this enables beyond main

- **DSpark + online acceptance estimator.** The new `confidence_head` speculative config field (`"trained"` or `"online_estimator"`) lets DSpark adaptive verification use the online acceptance estimator over the draft logits instead of the checkpoint's trained confidence head. Works with existing DSpark checkpoints. If unset, the trained head is used when the checkpoint has one (unchanged behavior).
- **XPress + online acceptance estimator.** XPress feeds the estimator the Jacobi-refined logits it samples from (`jacobi_refine_greedy(..., with_logits=True)`).
- **(Causal Refiner): Pluggable draft token head on the DFlash backbone.** A `DraftTokenHead` turns a draft block (`DraftBlockInput`) into draft tokens plus the acceptance estimator's input (`DraftBlockOutput`). `SpeculatorConfig.create_draft_token_head()` creates it and `DFlashSpeculator` takes it as a required constructor argument. An out-of-tree `SpeculatorConfig` registered with `register_speculative_method` can therefore put its own corrector on the DFlash backbone without subclassing or copying `DFlashSpeculator`.
- **XPress is DFlash + `XPressDraftTokenHead`.** `XPressSpeculator` is removed, and `XPressSpeculatorConfig` only provides the head and the draft model loader.
- **Shared sampling and estimation primitives.** `sample_independently` (`vllm/v1/worker/gpu/sample/draft.py`) and `AcceptanceEstimationInput` are used by both the autoregressive speculators and the draft token heads, so the estimator no longer depends on how a speculator produced its logits.

Not in scope yet: selecting backbone, corrector and estimator independently from `config.json`, and moving DFlash2, LiLiCorr and the DSpark Markov head onto draft token heads.
