# [ROCm] Enable eager PCP for DeepSeek-V4.1-Flash

[Upstream PR](https://github.com/vllm-project/vllm/pull/62981) · state: open · merged: False

## Original PR description

## Overview

Enable eager ROCm prefill context parallelism for the text-only DeepSeek-V4.1-Flash path in Model Runner V2, using the existing shared PCP metadata and attention logic.

This builds on [#59857](https://github.com/vllm-project/vllm/pull/59857) and [#60946](https://github.com/vllm-project/vllm/pull/60946).

## Claims

- Enables PCP for the `ROCM_FLASHMLA_SPARSE_DSV41` backend in eager mode.
- Gathers routing input IDs after local Engram/sequence-parallel preparation
  when expert parallel is disabled.
- Uses the shared sequential attention path under PCP and restores ROCm
  auxiliary streams even when attention raises.
- Rejects unsupported graph, parallel, cache, speculation, and kernel
  configurations at startup.
- A PCP rank with no decode rows returns an empty ragged top-k and skips the
  fused packer, instead of calling `reshape(..., -1)` on a 0-element tensor.
- `forward_mqa` zeros the PCP-padded token tail the same way CUDA FlashMLA
  does. On a gfx950 MXFP8 output that zeros both `data` and `scale`.

## Details

The AMD model previously rejected PCP before constructing its ROCm sparse MLA
attention. The ROCm backends inherit the shared V4.1 PCP metadata builders, so
this change declares that capability and wires the AMD model into the existing
path. No ROCm graph rewriting, HIP capture/replay, DSpark, bounded replay,
prefix-cache, NIXL, Kimi K3, or DeepSeek V4 behavior is changed.

PCP shards decode requests. The rank that owns no rows receives a 0-element
index buffer. `reshape(n, -1)` cannot infer a width from zero elements, and
the exception leaves the other rank blocked in the shared-memory broadcast.
That rank now returns the empty ragged triple the decode path already accepts,
and `rocm_sparse_attn_decode` returns before the same reshape.

PCP also pads each rank's batch. `forward_mqa` now follows CUDA FlashMLA
(`nvidia/flashmla.py`: real tokens are `num_decode_tokens + num_prefill_tokens`,
the tail is `zero_()`'d, and a zero-token step returns). Kernels write only
the real rows, so the tail was uninitialized when inverse RoPE read the bf16
output and when gfx950 consumers read MXFP8 `data` and `scale`. The MXFP8
branch zeros both buffers. The review thread is answered in a reply and left
open.

This does not duplicate an open PR. A search on 2026-10-27 still found no
other AMD eager DeepSeek-V4.1 PCP implementation.
[#61555](https://github.com/vllm-project/vllm/pull/61555) is CUDA decode-only
graph work. [#64135](https://github.com/vllm-project/vllm/pull/64135) is ROCm
native ASM sparse attention for DP, not this eager PCP path. The branch was
not rebased; existing merge conflicts with main remain.
