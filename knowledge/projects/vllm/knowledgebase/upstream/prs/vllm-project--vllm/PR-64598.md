# [CI] Enroll the remaining quantization and benchmarks jobs in automatic sharding (4 jobs)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64598) · state: closed · merged: True

## Original PR description

## Overview

Enrolls the remaining quantization and benchmarks jobs in `automatic_shard`: 4 jobs (1 step and 3 AMD mirrors). Part of a series that enrolls every remaining test step, split by test area for review. No commands change.

## Claims

| Step | Plan | AMD mirror |
|---|---|---|
| `quantized-fusions` | 1 shard | 1 shard |
| `benchmarks-cli-test` | already enrolled | 1 shard |
| `quantized-moe-test-b200` | already enrolled | 1 shard |

- One-shard plans run the same tests as on main, as one job, and split by themselves once their tests grow.

## Validation

- Planned each step and mirror with ci-infra main's planner against main's timings; every plan is within 10% of the same plan run as one job.
- Every step and mirror passes on recent main runs, nightly included.
- `/ci run` (98463) plus a scoped build (98474) for the optional steps and AMD mirrors on an earlier head: every enrolled job passed. A fresh `/ci run` follows on this head.

## Details

- **Left out: steps the generator can't shard.** It only shards a step whose commands after the first pytest are all plain pytest, and ignores `automatic_shard` elsewhere. An earlier revision also enrolled the EPLB and prefetch-offload accuracy scripts, the Ray dependency check and the attention benchmark smoke test (15 jobs with mirrors); they ran as one job regardless, so this PR no longer touches them.
- **caplog.** Files that assert on logs sit in one-shard plans here, so their order in the process doesn't change.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job. Fallback-aware timeouts belong in a central timeout setting.
