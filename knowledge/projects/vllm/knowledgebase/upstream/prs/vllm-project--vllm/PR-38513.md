## Summary

Closes #38511

When `--dns-aid-enabled` is set, the vLLM OpenAI-compatible server publishes a [DNS-AID](https://dns-aid.org) SVCB ServiceMode record on startup encoding model capabilities. This enables AI agents implementing the DNS-AID standard ([RFC 9460](https://www.rfc-editor.org/rfc/rfc9460) SVCB/HTTPS profile) to discover vLLM endpoints via DNS without a bootstrap API call.

- **Opt-in**: disabled by default, no behavior change for existing deployments
- **Optional dependency**: `pip install vllm[dns-aid]`
- **Rank-aware**: only global rank 0 registers in TP/PP/DP configurations
- **Graceful lifecycle**: registers after socket bind, deregisters on SIGTERM/ASGI shutdown

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The current logic for checking if the process should register the DNS record is based on `tensor_parallel_size`. This is insufficient for other distributed topologies like Pipeline Parallelism (PP) or Data Parallelism (DP), where `tensor_parallel_size` might be 1 but there are multiple ranks. This could lead to multiple workers attempting to register the same DNS record.

The `_is_global_rank_zero()` function correctly identifies the global rank 0 worker in any distributed setup. Relying solely on this function simplifies the code and correctly handles all multi-rank configurations (TP, PP, DP), ensuring only one record is registered per deployment.

```suggestion
    if not _is_global_rank_zero():
        logger.debug("DNS-AID: skipping registration on non-zero global rank.")
        return None
```
