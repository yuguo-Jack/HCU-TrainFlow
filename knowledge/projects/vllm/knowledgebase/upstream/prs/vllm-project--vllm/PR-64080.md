# [Bugfix][CPU][RISC-V] Include bundled OpenMP runtime preload

[Upstream PR](https://github.com/vllm-project/vllm/pull/64080) · state: open · merged: False

## Original PR description

## Overview

Apply the existing Linux bundled-OpenMP preload policy to RISC-V CPU workers, consistent with the other supported Linux CPU architectures.

## Claims

- Search PyTorch's `torch.libs` and `torch/lib` directories for bundled libgomp on RISC-V.
- Preserve an explicitly preloaded OpenMP runtime and leave configurations without bundled libgomp unchanged.
- Add real VllmConfig/CpuPlatform configuration regressions and wire the suite into the existing CPU configuration CI job.

## Details

RISC-V was absent from the architecture tuple guarding the established Linux preload policy. This adds it without changing library selection or overriding user-selected OpenMP runtimes. The CPU thread-binding FAQ documents the existing policy and source/distribution-build fallback.

Duplicate searches found no open RISC-V preload fix. #52858 changes CMake oneDNN handling; #35910 concerns distro build-library discovery; #51876 does not modify this runtime platform path. The historically referenced PyTorch issue is closed, so this PR makes no claim that its original utilization bug is reproduced on current PyTorch/RISC-V.
