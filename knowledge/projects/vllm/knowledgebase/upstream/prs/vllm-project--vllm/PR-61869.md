# [Perf][DSv4.1] DSpark draft on the specialized decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/61869) · state: open · merged: False

## Original PR description

## Overview

This is the DSpark half of the DeepSeek-V4.1-Flash specialized decode on GB300 (#61868). With `decode_backend` set to `latency_specialized`, the DSpark draft layers now run on the same decode executor as the target model, on its fused all-reduce + mHC kernel, attention and routed-expert GEMMs. The draft also samples through the model's `sample_sequential` hook: the fused Markov loop from #64442, plus a Markov chain sharded by vocabulary over the TP ranks at small batches.

Everything is under `vllm/models/deepseek_v41/nvidia/`, with its tests. The speculators, the model runner and the other shared code are unchanged. With the switch off, nothing changes.

## Claims

DeepSeek-V4.1-Flash on one GB300 tray (TP4) with DSpark (5 draft tokens), the switch on in both arms, this PR against `main`:
- Decode step: −5.1% at batch 1 and −2.5% at batch 8; unchanged at batch 40.
- GSM8K accuracy and the DSpark acceptance length are unchanged, within the spread of repeated runs.

### Performance

**Decode step.** The speculative step with its draft, timed from the client over long-context decodes: one 524K-token request at batch 1, eight of 84K to 648K tokens at batch 8, and five times those eight at batch 40, with 3,000 output tokens each. The runs are ABBA blocks on one GB300 tray, with one server per block and two repeats per batch size. They compare `main` `866bccf0` with this PR merged onto it, with the switch on in both. Both arms share one FlashInfer autotune cache, so they run the same GEMM tactics.

| Batch | `main` (µs) | This PR (µs) | Change |
| ---: | ---: | ---: | ---: |
| 1 | 4,276 | 4,057 | −5.1% |
| 8 | 8,915 | 8,692 | −2.5% |
| 40 | 16,703 | 16,626 | −0.5% |

At batches 1 and 8, every block of this PR beats every block of `main`. At batch 40, the blocks overlap.

**Sharded chain.** The same ABBA on a second tray compares this PR with and without the sharded chain. Without it, the fused loop samples at every batch size.

| Batch | Without (µs) | With (µs) | Change |
| ---: | ---: | ---: | ---: |
| 1 | 4,109 | 4,061 | −1.2% |
| 8 | 8,873 | 8,880 | +0.1% |
| 40 | 16,703 | 16,565 | −0.8% |

The chain runs only up to 8 request rows, so the batch-40 difference is noise between blocks. The chain saves about 50 µs per step at batch 1 and nothing measurable at batch 8. It is 1,565 of this PR's 2,475 added lines, all in `specialized_decode/sampling/`. If reviewers prefer the smaller diff, it can be dropped without touching the rest.

### Design notes

**Structure.** The DSpark draft model registers itself when it is built with the switch on. The target's model state from #61868 then builds the draft's executor right after the target's, on the same fused kernel, mailbox and mHC side stream, and the draft model's forward asks it for a step the same way (`plan()`, then `run()`). Once the executor is built, the draft model replaces its `sample_sequential` (#64442's `FusedMarkovSampler`, which the switch implies) with one that sends batches of up to 8 request rows to the sharded chain and the others to the fused loop. `DSparkSpeculator._sample_sequential` already asks that hook first, so the speculator is unchanged.

**Sharded chain: rank lockstep.**
- The chain exchanges each position's winner between ranks through a symmetric-memory mailbox, a cross-rank spin inside the draft step and its FULL graph, so every rank must launch it the same number of times.
- Whether it is installed depends only on configuration, and CPU all-reduces at load make the ranks agree on it.
- The per-call choice depends only on the padded batch shape. It applies up to 8 request rows (4 at 8 ranks).
- Steady state reads nothing back from the GPU.
- The draws reproduce the speculator's `gumbel_sample` loop, except for the bias reduction order before its BF16 rounding, so a bias element can differ from cuBLAS's in its last bit. The fused loop above 8 rows draws by inverse CDF (#64442); both sample the cached draft distribution exactly.
