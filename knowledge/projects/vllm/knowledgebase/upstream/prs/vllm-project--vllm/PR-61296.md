# [Rust Frontend] Support `--max-num-queued-reqs` and `--max-num-queued-tokens`

[Upstream PR](https://github.com/vllm-project/vllm/pull/61296) · state: open · merged: False

## Original PR description



## Overview

Add configurable admission control to the Rust frontend through
--max-num-queued-reqs and --max-num-queued-tokens.

Operators can limit the number of unfinished requests and the prompt-token
backlog still in prefill. When either limit is reached, the frontend returns a
retryable HTTP 503 response, helping load balancers redirect excess traffic
while keeping queue growth and tail latency predictable.



## Claims

- Limits the number of unfinished requests accepted by the Rust frontend.
- Limits prefill pressure using the prompt-token backlog.
- Supports human-readable token limits such as 2.5k and 1K.
- Returns HTTP 503 and gRPC Unavailable when admission is rejected.
- Exposes rejection metrics labeled by model and limit type.
- Leaves existing behavior unchanged when neither limit is configured.

The Rust frontend and its managed engine were started together for the following end-to-end tests:

| Configuration | Workload | Result |
|---|---|---|
| max-num-queued-reqs=0 | One request | HTTP 503; request rejection metric increased |
| max-num-queued-tokens=0 | One request | HTTP 503; token rejection metric increased |
| Request limit 8 | 16 concurrent requests | 8 completed and 8 returned HTTP 503 |
| Token limit 100, request limit 64 | 16 concurrent 901-token prompts | 1 completed and 15 returned HTTP 503 |
| Request limit 8, token limit 512 | Normal generation | HTTP 200 with generated output |



## Details


Admission is enforced atomically in the shared request registry:

- max-num-queued-reqs counts all unfinished requests.
- max-num-queued-tokens counts prompt tokens until a request produces its
  first engine output.
- Capacity is released on normal output and all request cleanup paths,
  including abort, removal, rollback, finish, and shutdown.

The token limit follows the existing waterline semantics. A request is rejected
when the current prefill backlog has already reached the configured limit.

Rejected requests return HTTP 503 or gRPC Unavailable. The
vllm:admission_rejections_total metric distinguishes request-count rejections
from prompt-token rejections.

Both limits remain disabled by default.
