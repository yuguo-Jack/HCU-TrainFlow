# [CI] Run the NIXL PD accuracy sweeps as one pytest test per config and shard them automatically

[Upstream PR](https://github.com/vllm-project/vllm/pull/62568) · state: closed · merged: False

## Original PR description



## Overview

The NIXL PD accuracy steps run `config_sweep_accuracy_test.sh`, a bash loop that runs 6–7 configs one after another in one job. CI's automatic sharding only plans `pytest` commands, so these steps can't be split across parallel jobs. This PR adds `test_config_sweep.py`, which runs each config of the same script as its own pytest test. It then switches the four long sweep steps, and their long AMD mirrors, over to it and enrolls them in `automatic_shard`.

## Claims

- Each config is one test, with a stable ID built from the config, for example `test_config_sweep[PREFILLER_TP_SIZE=1-DECODER_TP_SIZE=2-deepseek-vl2-tiny]`.
- The script is still the only list of configs and the only place that picks the attention backend:
  - `--list` prints the configs selected by the usual env vars (`DP_EP`, `HYBRID_SSM`, …).
  - `SWEEP_CONFIG=<config>` runs just that config, with the same backend args.
- Running the script directly (`bash config_sweep_accuracy_test.sh`) does what it did before, so the `test-amd.yaml` steps and the steps not converted here are unchanged.
- Converted and enrolled:

| Step | Configs | Lanes |
|---|---:|---|
| `distributed-nixlconnector-pd-accuracy-4-gpus` | 6 + sleep/wake | NVIDIA, AMD (6) |
| `distributed-flashinfer-nixlconnector-pd-accuracy-4-gpus` | 6 | NVIDIA; AMD mirror already runs `test_accuracy_rocm.py`, enrolled as is |
| `crosslayer-kv-layout-distributed-nixlconnector-pd-accuracy-tests-4-gpus` | 6 | NVIDIA, AMD |
| `hybrid-ssm-nixlconnector-pd-accuracy-tests-4-gpus` | 7 | NVIDIA, AMD |

- Each converted lane runs as one job until main records per-test timings for the new file. After that, the planner spreads its configs over 2–3 jobs. The FlashInfer AMD mirror already has timings and plans to 3 jobs now.

## Validation

- In a Linux container with stand-in versions of `run_accuracy_test.sh` and the import canary, the old bash path and the new pytest path ran the same configs with the same arguments for every selector (default, `FLASHINFER`, `CROSS_LAYERS_BLOCKS`, `HYBRID_SSM`, `DP_EP`, `ATTENTION_BACKEND`, `WITH_SLEEP_WAKE`). A failing config fails its own test.
- Rendered every converted lane with ci-infra main's pipeline generator, using stand-in per-test timings, and ran each shard's commands against a mock test tree, as a PR build and with main's `pytest -p ci_otel` wrapper. Every config ran exactly once with the same env. The import canary runs in every shard, as it did at the start of the old script.
- `/ci run` runs the real sweeps on the four AMD mirrors. The four L4 steps are nightly only (#62564), so they get a separate build scoped to their keys. Each converted lane runs as one job, since main has no timings for the new file yet.

## Details

- **Sleep/wake run:** the (L4) Distributed step ran it as a separate `run_accuracy_test.sh` command. It is now a config, added with `WITH_SLEEP_WAKE=1`, so it can land in any shard.
- **Import canary:** it is a setup command (`python3 -m pytest -s -x …/test_nixl_imports.py`) so every shard fails fast, as before. The script skips it in `--list` and `SWEEP_CONFIG` modes.
- **Nightly-only L4 steps:** sharding still applies to them on nightly runs; their AMD mirrors keep running on PRs (#62567).
- **Left out:** the DP-EP, push and spec-decode sweeps and Mooncake all run in under 15 minutes. Per-job timeouts are unchanged.
