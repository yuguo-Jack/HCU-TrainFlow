While the transpose is necessary to fix the layout detection for square matrices in the Marlin kernel, calling `.contiguous()` here is redundant and inefficient. The Marlin repacking process (specifically `pack_fp8_to_int32` called within `prepare_fp8_layer_for_marlin`) already handles transposing the weight back to its original (N, K) layout and ensuring contiguity. By passing a non-contiguous view (`.t()`) here, you avoid creating an intermediate full-weight copy that would be immediately discarded and re-copied later, saving significant peak memory during model loading.

```suggestion
            replace_parameter(layer, "weight", layer.weight.t())
```
