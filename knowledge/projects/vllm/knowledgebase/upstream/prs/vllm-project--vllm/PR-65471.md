# [Perf][Model] Qwen4Exp QSA: SM120 launch config for indexer prefill scoring

[Upstream PR](https://github.com/vllm-project/vllm/pull/65471) · state: open · merged: False

## Original PR description



## Overview

Qwen4Exp QSA: add an sm_120 launch config for the indexer prefill scoring kernel `_qsa_mqa_paged_prefill_kernel`, which uses its GB300 config on every GPU today. It is selected by the existing `_is_sm120` gate of `nvidia/ops/qsa.py`. Bit-equal. Stacked on #65470 (its commit `b07d5d1` is the first of this branch; only the second commit is new). Related: #62344 (sm_80 config for this kernel; the second to merge needs a small rebase in `_prefill_logits`).

## Claims

- On RTX PRO 6000 (sm_120), 8k to 64k context, over mixed steps, equal chunks and single chunks: 1.13x to 5.42x with a BF16 index cache, 1.10x to 3.69x with FP8. Faster than the GB300 config in every cell; bit-equal.
- Other GPUs keep the GB300 values.

## Validation

**Tests** (8 passed on 1 x RTX PRO 6000; 46 with the compact-grid and selection tests): new `tests/models/qwen4_exp/test_qsa_indexer_launch_config.py`, added to the `qwen4_exp` CI step, checks the sm_120 config against the default bit for bit (BF16 and FP8; one request, equal chunks, uneven requests, a mixed step), switching by patching `_is_sm120`. The CI step runs on H200 and there is no sm_120 runner, so in CI it guards bit-equality of the two configs compiled for sm_90.

**Config choice:** sweep TILE_R {16, 32, 64} x BLOCK_N {32, 64, 128} x K_TILES {2, 4, 8, 16} x STAGES {1, 2} x num_warps {4, 8}, each on the grid `_prefill_logits` picks. Every config that compiled was bit-equal; 8 BF16 configs (TILE_R=64, BLOCK_N=128, STAGES=2) ran out of shared memory (114,688 bytes needed, 101,376 available). Chosen per cache dtype: the best geomean speedup among configs faster than the default in all 12 cells (56 BF16 and 37 FP8 qualified; geomeans 1.82x and 1.70x). It is within 32% of each cell's own best (largest gaps 32%, 24%, 18%); per-shape keys would add compile variants and fit single measurements. Values (TILE_R, BLOCK_N, K_TILES, STAGES, num_warps): BF16 (16, 64, 4, 1, 4), FP8 (32, 64, 4, 2, 4).

**Kernel benchmark:** 1 x RTX PRO 6000 Blackwell Server Edition (driver 580.82.07, CUDA 13.0), torch 2.14.0+cu130, triton 3.8.0, vLLM `3b6eeb06` + compact grid + this PR (the branch is rebased onto `866bccf`; the touched files differ only by the `_topk` condition of #56102). `Qwen/Qwen3.8-Flash-Next` indexer shapes at TP=1, random tensors. Same process, final tree: the kernel at the GB300 config on the grid `_prefill_logits` picks (before) against `_prefill_logits` (after); CUDA graph of 20 calls, 128 MB L2 flush before each of 5 replays; median of 3 runs (run-to-run spread of a speedup at most 0.9%).

## Details

The launch kwargs move into `_PREFILL_CONFIG` (GB300, unchanged values) and `_SM120_PREFILL_CONFIG`, each keyed by index cache dtype; `_prefill_launch_config(cache_dtype)` picks one and `_prefill_logits` passes it to the launch.
