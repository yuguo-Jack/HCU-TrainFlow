# [Bugfix] Retry incomplete HTTP response bodies

[Upstream PR](https://github.com/vllm-project/vllm/pull/62674) · state: closed · merged: True

## Original PR description



## Overview

Retry HTTP downloads when the response body is interrupted. These failures currently bypass the existing retry logic, even when attempts remain.

## Claims

- Retry requests.exceptions.ChunkedEncodingError and aiohttp.ClientPayloadError.
- Preserve the existing attempt limit and backoff, while continuing to enforce download size limits.

## Validation

Added four parameterized cases covering sync and async downloads, successful recovery, and retry exhaustion. All four fail before the fix and pass afterward.

.venv/bin/python -m pytest tests/test_connections.py -q
13 passed

pre-commit run --files vllm/connections.py tests/test_connections.py
Passed

The test file is already included in the Buildkite CPU misc job.

Also validated /v1/chat/completions/render using the LLaVA 1.5 preprocessing configuration, the same explicit chat template on both revisions, and a local HTTP image server. The attempt limit was set to 2.

| Image download | Before | After |
|---|---|---|
| Completes normally | HTTP 200, 1 attempt | HTTP 200, 1 attempt |
| First response is interrupted | HTTP 500, 1 attempt | HTTP 200, 2 attempts |
| Every response is interrupted | HTTP 500, 1 attempt | HTTP 500, 2 attempts |

After recovery, the rendered prompt token IDs exactly match the successful control request.

This validates HTTP preprocessing; GPU inference and upstream CI were not run.

## Details

Body-read failures use different exception classes from connection failures, so _is_retryable does not currently recognize them. This change adds those classes to the existing retry classification.

These exceptions can also represent malformed responses. Such responses may be retried, but still fail once the configured attempt limit is reached.
