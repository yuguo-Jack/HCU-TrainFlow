# [CI] Label MiniMax M3 and M3.1 PRs and issues

[Upstream PR](https://github.com/vllm-project/vllm/pull/63380) · state: open · merged: False

## Original PR description



## Overview

Add `M3` and `M3.1` model labels to Mergify PR labeling and the issue autolabel workflow so MiniMax model work can be triaged by version.

## Claims

- PRs touching MiniMax M3 implementation paths receive both version labels and the existing `minimax` family label because M3 and M3.1 share that implementation.
- Explicit M3.1 paths, such as `MiniMax-M3.1-Flash.yaml`, receive `M3.1` without `M3`.
- PR and issue title matching distinguishes MiniMax M3 from M3.1 and requires the MiniMax name to avoid Apple M3 and BGE-M3 matches. Issues search titles only.

## Validation

- `.venv/bin/pre-commit run --files .github/mergify.yml .github/workflows/issue_autolabel.yml`: passed, including actionlint and `check-label-rules`.
- `git diff --check`: passed.
- Local matching checks: 12 PR titles, 8 file paths, and 14 issue workflow scenarios passed. Issue checks executed the actual workflow script against a stubbed GitHub client, including body-only mentions and existing labels.
- Tracked-path audit: all 51 MiniMax M3-named paths matched both shared-implementation rules.
- Full file-list audit of #63232: all 107 MiniMax M3/M3.1-named paths matched `M3.1`; the 106 M3-named paths also matched `M3`, while the M3.1 recipe did not.
- Model evaluation: not applicable; these changes affect labeling configuration only.

## Details

The existing `minimax` rules do not provide version-level triage. These rules reuse the existing labeling mechanisms without adding dependencies or changing model execution. A change confined to generic shared files must name MiniMax M3 or M3.1 in its title to receive a version label.

Duplicate checks found no open PR adding these version labels. #56352 broadens existing family-level path matching; this change leaves that rule untouched and adds version-level PR and issue labeling. No tracking issue was supplied or found in the targeted open-issue search.

Before merge, a maintainer must create the repository labels `M3` and `M3.1`. Label creation was attempted but GitHub returned HTTP 404; the current credentials have triage access without push, maintain, or admin access. Both labels can use the existing `minimax` color `e70113`.

AI assistance (Codex) was used to implement and validate this change. The submitting human reviewed the proposed diff and confirmed that the pre-commit checks passed or were skipped before publication, as required by AGENTS.md.
