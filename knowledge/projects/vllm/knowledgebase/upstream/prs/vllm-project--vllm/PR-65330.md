# [Core] DRYup KV cache block allocation loop

[Upstream PR](https://github.com/vllm-project/vllm/pull/65330) · state: open · merged: False

## Original PR description



## Overview

Deduplicate `BlockPool.get_new_blocks()` into one allocation loop, storing `enable_caching` and `metrics_collector` in local variables.

Closes #65327.

## Claims

- Keep reference-count and allocation-metrics updates in one place while retaining one pass over the allocated blocks.
- Preserve capacity checks, queue allocation, reuse-watcher notification, and the eviction → reference-count increment → allocation-metrics order.

## Validation

The same five existing suites passed before and after the refactor: **323 passed** on upstream `67791dd94d`, and **323 passed** with this change.

All applicable pre-commit checks passed. No new tests were needed for this behavior-preserving refactor; the existing suites cover allocation, cache reuse/eviction, metrics, partial prefix caching, and deferred frees.

The [benchmark script and full results in #65327](https://github.com/vllm-project/vllm/issues/65327) compare the original method with this exact candidate. The relevant allocator sources are unchanged between that benchmark's baseline (`82a48b7c1e`) and this PR's base. Measurements use an Apple M4 Pro, Python 3.12.13, two sweeps of 24 paired samples per configuration, and 1% metrics sampling when enabled. Raw samples and bootstrap intervals are generated by the script; small differences vary between runs.

For **512 blocks/call**, allocation without cached-block eviction:

| Caching | Metrics | Existing (ns) | Refactored (ns) | Runtime gain/loss |
|---|---|---:|---:|---|
| On | On | 110,845.7 | 109,855.8 | 0.89% gain |
| On | Off | 57,888.4 | 57,846.0 | 0.07% gain |
| Off | On | 44,548.8 | 43,331.4 | 2.73% gain |
| Off | Off | 18,039.7 | 18,386.4 | 1.92% loss |

These are macOS/ARM64 allocator microbenchmarks, not end-to-end serving or model-evaluation results. This PR makes no serving-throughput claim.

## Details

Both references are captured after reuse-watcher notification. The optional eviction and allocation-metrics operations stay in their original positions inside the loop. The change also removes the duplication comment. There is no additional fast path, API change, or configuration change.

Duplicate-work checks covered #65327's comments and open PR searches for the issue number and `get_new_blocks`. No existing PR implements this refactor. Related PRs #63441, #64491, and #64035 add event batching or metrics and retain the duplicated loops in their reviewed patches.
