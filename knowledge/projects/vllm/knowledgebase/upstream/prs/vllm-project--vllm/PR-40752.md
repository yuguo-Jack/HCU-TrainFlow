## Original PR description

## Purpose
This PR introduces Expert Parallel Load Balancing (EPLB) support for Kimi K2.5 and K2.6 models utilizing the Marlin kernel.

## Test Plan
Test locally by serving moonshotai/Kimi-K2.5 with EPLB enabled, utilizing Ray for distributed execution.
`vllm serve moonshotai/Kimi-K2.5 --tensor-parallel-size 8 --data-parallel-size 4 --data-parallel-size-local 1 --enable-expert-parallel --port 8000 --tool-call-parser kimi_k2 --reasoning-parser kimi_k2 --enable-auto-tool-choice --trust-remote-code --distributed-executor-backend ray --data-parallel-backend=ray --gpu-memory-utilizatio 0.8 -dcp 8 --load-format instanttensor --enable-eplb --eplb-config '{"log_balancedness":true, "num_redundant_experts":128}'`

Verification Steps:

1. Check that the server starts without throwing the NotImplementedError.
2. Monitor the server logs to ensure EPLB rearrangement triggered and the balancedness metric improved post-rearrangement.
3. Send test curl requests to the endpoint to confirm the model returns reasonable and coherent answers.

The MoE hyperparameter initialization in `__init__` has two issues:
1. `num_expert_groups` is hardcoded to `1`. Since Kimi K2.5 is based on the `DeepseekV2ForCausalLM` architecture, it should proxy this value from the underlying language model (which uses `n_group` from the config) to ensure the EPLB rebalancing policy respects expert grouping constraints.
2. The `expert_weights` attribute is missing. Because `MixtureOfExperts` is a `runtime_checkable` protocol, the absence of this attribute will cause `isinstance(self, MixtureOfExperts)` to return `False` immediately after construction. This can prevent EPLB from being correctly initialized or identified by the distributed executor.

```suggestion
        self.num_expert_groups = self.language_model.num_expert_groups
        self.num_logical_experts = self.language_model.num_logical_experts
        self.num_physical_experts = self.language_model.num_physical_experts
        self.num_local_physical_experts = self.language_model.num_local_physical_experts
        self.num_routed_experts = self.language_model.num_routed_experts
        self.num_shared_experts = self.language_model.num_shared_experts
        self.num_redundant_experts = self.language_model.num_redundant_experts
        self.moe_layers = self.language_model.moe_layers
        self.num_moe_layers = len(self.moe_layers)
        self.expert_weights: list[list[torch.Tensor]] = []
```

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The `update_physical_experts_metadata` method only updates the underlying `language_model`. However, the wrapper model `KimiK25ForConditionalGeneration` also stores these values as attributes (initialized in `__init__`). These should be updated in the wrapper as well to ensure consistency when external components (like the EPLB state manager) access them via the wrapper instance.

```suggestion
    def update_physical_experts_metadata(
        self,
        num_physical_experts: int,
        num_local_physical_experts: int,
    ) -> None:
        self.language_model.update_physical_experts_metadata(
            num_physical_experts=num_physical_experts,
            num_local_physical_experts=num_local_physical_experts,
        )
        self.num_physical_experts = num_physical_experts
        self.num_local_physical_experts = num_local_physical_experts
```
