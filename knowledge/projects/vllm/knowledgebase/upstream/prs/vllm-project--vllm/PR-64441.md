# [Feat][BI][1/N] add batch-invariant DeepSeek V4 support (top-k order)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64441) · state: open · merged: False

## Original PR description

When  VLLM_BATCH_INVARIANT  is enabled, sort the sparse attention indexer's selected KV indices before attention. This avoids reduction-order differences when top-k returns the same tokens in a different order, while keeping  -1  padding at the end.

The default path is unchanged, and ties at the top-k cutoff are still not resolved. Adds tests for ordering, padding, buffer preservation, and native prefill/decode top-k outputs.

> Hi, thx for the pr. I think deepselect itself is batch invariance? Did you ever compare the perf with deepselect?

Thanks @aoshen02, good suggestion! 
I checked that vLLM’s current DeepSelect integration is limited to CUDA GPUs in the SM100/SM103 family. We’d like the BI path to work across a broader range of hardware, since inference workers used for RL aren’t necessarily running on those GPUs. That’s one of the motivations for this PR.

For context, as discussed with @yewentao256, the plan is to establish functional correctness first, then tune performance once the BI path is working end to end. I haven’t benchmarked against DeepSelect yet, but it would definitely be one of the options to evaluate in that phase, alongside the other available backends.

Does this phased approach sound reasonable to you?
