# [Core][Spec Decode] Replace EAGLE group heuristics with explicit draft-layer tags

[Upstream PR](https://github.com/vllm-project/vllm/pull/61455) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

`is_eagle_group` decides which KV cache groups take the EAGLE last-block drop. The planner used to guess these groups from `non_causal_multi_token_decode` and from "the group holding the last registered layer" (MTP, DeepSeek-V4), and only on some grouping paths. This PR replaces the guesses with an explicit per-layer tag that the runners report, so a group is flagged iff it holds a draft layer. Supersedes #41640 (closed; its compared per-model field changed grouping) and #56026 (adds another guessing rule).

## Claims

- DFlash / DSpark drafters on hybrid models no longer make every group take the drop, so Mamba groups keep their prefix-cache reuse (#57032, #54360).
- A drafter spanning several groups (e.g. DeepSeek-V4 / V4.1 DSpark) gets every one of its groups flagged, not only the group holding the last layer.
- Gemma4 MTP no longer flags an unrelated target group. Its drafter shares the target's KV, so no group holds draft-owned KV and the coordinator's existing "flag all" fallback applies.
- The flags survive pipeline parallelism. Before, the scheduler config (worker 0's projection) cleared the flag of every group with no layers on worker 0, so with PP >= 2 the draft groups on the last stage were never flagged and the coordinator flagged every group.
- New draft models need no planner code to be identified. Out-of-tree runners must tag draft specs to benefit; untagged runners keep the conservative "flag all" fallback.

## Details

- Speculators set `AttentionLayerBase.is_draft_layer` on their layers at load time (V2 already did; V1 now does too). Both runners copy it onto `KVCacheSpec.is_draft`.
- `KVCacheSpec.is_draft` describes ownership, not cache format, so it uses `compare=False`: it never changes equality, hashing, grouping, or the cross-worker spec check. The `merge` assertions skip `compare=False` fields, because a group can mix target and draft layers (Qwen3.5 MTP). The field is only meaningful on per-layer specs; groups expose `KVCacheGroupSpec.is_eagle_group`.
- `get_kv_cache_configs` sets `is_eagle_group` after `get_kv_cache_groups_from_builder`, so it also covers groupings from a model's `SupportsKVCacheGrouping` or a platform builder. Flags are only set when `use_eagle_block_drop()` is true.
- `_project_kv_cache_groups_to_worker` now keeps the global flag. Every `is_eagle_group` consumer (coordinator, OffloadingConnector scheduler, Mooncake store coordinator) runs on the scheduler side.
- Behavior change: on uniform models the OffloadingConnector now drops the tail chunk like the GPU coordinator. Newly flagged groups recompute one tail chunk on external hits; this is a performance cost, not a correctness one.
- HiSparse resident/hot specs are not tagged; their groups are not prefix-cacheable, so no hit lookup reads the flag.
