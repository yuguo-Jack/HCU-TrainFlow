# [Bugfix][Rust Frontend] Count tool call deltas as generated tokens in vllm-bench openai-responses

[Upstream PR](https://github.com/vllm-project/vllm/pull/64557) · state: closed · merged: True

## Original PR description

## Overview

The Rust `vllm-bench` `openai-responses` backend marks every tool-call-only response as failed. It counts only `output_text` and `reasoning_text` deltas as tokens, and a forced tool call streams only `function_call_arguments` deltas. This counts the four tool delta events the vLLM Responses server emits. #62753 is the same fix for the Python `vllm bench serve` client.

## Claims

- 100 tool calls the server completed with HTTP 200 went from 0 to 100 successful.
- Added events: `function_call_arguments`, `custom_tool_call_input`, `mcp_call_arguments`, `code_interpreter_call_code` (from `vllm/entrypoints/openai/responses/streaming_events.py`). Tool arguments are timed but not added to `generated_text`.

## Validation

Two new tests in `openai_responses.rs`: a tool-call-only response (TTFT, ITL, latency, usage) and each tool delta type on its own. Both fail with the old match arm. `cargo test -p vllm-bench` passes (215), and `cargo fmt --check` and `cargo clippy -p vllm-bench --all-targets -- -D warnings` are clean.

RTX 3080, `Qwen/Qwen2.5-0.5B-Instruct` with `--enable-auto-tool-choice --tool-call-parser hermes`, 100 prompts, concurrency 16, `tool_choice: "required"` via `--extra-body`:

| | `main` | this branch |
|---|---|---|
| completed / failed | 0 / 100 | 100 / 0 |
| total generated tokens | 0 | 2,090 |

The 2,090 output tokens match the Python bench on the same workload.

## Details

The backend came in with #59489. Leaving tool calls out fails the request, so tool-calling workloads such as BFCL can't be measured with it.

No issue or PR covers this. AI assistance (Claude) was used to write the change and tests. I reviewed every line and ran the tests and GPU comparison.
