# [Bugfix] Fix MiniMax-M3 attention warmup deadlock under PP>1 (#60791)

[Upstream PR](https://github.com/vllm-project/vllm/pull/65602) · state: open · merged: False

## Original PR description

Follow-up to #64338 and resolves Item 8 in #60791.

### Root Cause & Context
MiniMax-M3 is a hybrid model architecture: early layers (layers 0–2) use dense attention + standard MLPs, while subsequent layers (layers 3+) use MiniMax-M3 Sparse Attention (MSA) + MoE.

When partitioned across pipeline stages under `pipeline_parallel_size > 1` (e.g. PP=2 where stage 0 only hosts layers 0–2):
1. **Asymmetric MSA Gate:** Stage 0 detects no `MiniMaxM3SparseAttention` modules in its local layer partition and returns early from `minimax_m3_msa_warmup`. Later stages (hosting layers 3+) proceed into `mixed_batch_attention_warmup(worker)`, invoking `worker.execute_model`. Because model execution participates in pipeline activation send/recv and broadcasts across stages, later stages hang indefinitely waiting for Stage 0 until the NCCL watchdog timeout fires.
2. **Asymmetric KV Block Capacity Check:** In `v1/worker/gpu/warmup.py:run_mixed_prefill_decode_warmup`, if non-uniform KV block allocations cause one PP stage to have fewer committable blocks than `required_blocks`, that rank early-exits while other ranks enter `model_runner.execute_model`, resulting in the identical PP hang.

### Solution
1. In `minimax_m3_msa_warmup`: All-reduce MSA module eligibility across the pipeline group via `pp_group.cpu_all_reduce_` (following the pattern established in #64338 for FlashInfer and #62129 for speculative warmup). Every PP rank makes a symmetric warmup execution decision:
   - Rank-local kernel compilation (`_msa_prebuild_kwargs` / `fmha_sm100.warmup`) only runs on ranks that host sparse modules on supported SM100 hardware.
   - `mixed_batch_attention_warmup(worker)` executes symmetrically across all PP ranks if any rank contains MSA layers (under V2 runner).
2. In `v1/worker/gpu/warmup.py:run_mixed_prefill_decode_warmup`: All-reduce `has_capacity` across `pp_group` so KV block capacity decisions remain uniform across all pipeline stages.
3. Added CPU regression test suite `test_minimax_m3_msa_warmup_gate` in `tests/model_executor/test_attention_warmup.py` exercising 8 combinations of MSA rank distributions and runner variants.
