# [Bugfix][Core] Fall back when numactl --membind is blocked in constrained containers

[Upstream PR](https://github.com/vllm-project/vllm/pull/45438) · state: closed · merged: True

## Original PR description


## Purpose

Explicit NUMA binding (`--numa-bind` with `--numa-bind-nodes` or `--numa-bind-cpus`) writes `--membind` into the numactl wrapper without checking whether the container can set a NUMA memory policy. In a constrained container with `set_mempolicy` blocked, `numactl` exits before it execs Python, so the worker or EngineCore subprocess dies with exit code 1 and no Python traceback. This is the same failure reported by @chengcuiping in sgl-project/sglang#27368.

The automatic NUMA-detection path already guards this through `_can_set_mempolicy()`. This patch adds a runtime probe for the explicit path before installing the wrapper. If the full numactl args fail, memory binding is dropped while CPU binding is kept; if CPU binding also fails, the subprocess starts without the numactl wrapper. I did not keep a `--preferred` tier because it uses the same memory-policy syscall: on the repro host, both `--membind` and `--preferred` fail, while CPU-only succeeds.

Scope: the fallback is intentionally coarse for multi-node EngineCore bindings. If the combined `--membind=...` args are rejected, vLLM drops memory binding for that subprocess instead of trying to keep a partially valid subset of nodes.

## Test Plan

1. Real before/after through the vLLM subprocess wrapper path: run the same explicit `--numa-bind --numa-bind-nodes 0` worker setup on current main and on this PR, and verify that main exits before Python starts while this PR degrades to CPU-only binding and runs Python.
2. Real numactl precondition check on the same host: verify that `--membind` and `--preferred` both fail with `set_mempolicy`, while CPU-only binding succeeds.
3. Minimal regression coverage: `pytest tests/utils_/test_numa_utils.py tests/utils_/test_system_utils.py tests/engine/test_arg_utils.py`.
4. Changed-file lint and static checks: `pre-commit run --files vllm/utils/numa_utils.py tests/utils_/test_numa_utils.py`.

## Test Result

On an A800-80GB constrained container, the current main path aborts before Python starts. With this PR, the same `configure_subprocess(..., process_kind="worker")` path degrades to CPU-only binding and Python runs.

| scenario | current main | this PR |
|---|---|---|
| explicit `--numa-bind --numa-bind-nodes 0`, worker wrapper | `set_mempolicy: Operation not permitted`, exit 1, Python does not run | args degraded to `--cpunodebind=0`, exit 0, Python runs |

Related tests passed: `114 passed, 16 warnings`. The changed files also pass the full pre-commit hook set.

Bare numactl confirms the environment: memory policy calls fail, CPU-only binding works.

```
$ numactl --cpunodebind=0 --membind=0 python -c 'print("BARE_MEMBIND_RAN")'; echo "membind_rc=$?"
set_mempolicy: Operation not permitted
setting membind: Operation not permitted
membind_rc=1

$ numactl --preferred=0 python -c 'print("BARE_PREFERRED_RAN")'; echo "preferred_rc=$?"
set_mempolicy: Operation not permitted
setting preferred node: Operation not permitted
preferred_rc=1

$ numactl --cpunodebind=0 python -c 'print("BARE_CPU_RAN")'; echo "cpu_rc=$?"
BARE_CPU_RAN
cpu_rc=0
```
