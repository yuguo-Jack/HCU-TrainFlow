# [ROCm][Perf][Qwen3.8] Add dense mono decode for Qwen3.8-27B on MI355X.

[Upstream PR](https://github.com/vllm-project/vllm/pull/61573) · state: open · merged: False

## Original PR description



## Overview

Opt-in FlyDSL decode for `amd/Qwen3.8-27B-Quark-AWQ-MXFP4` (`qwen3_5_text`, TP1 or TP2, gfx950). Set `VLLM_ROCM_MONO_DECODE=1`. The K1 and K2 kernels are adapted from SGLang #43558. This pull request is their vLLM integration and the TP1 and TP2 dispatch. The MoE mono decode for the larger Qwen3.8 is #60833.

## Claims

On a pure decode inside the row cap, K1 replaces the linear-attention mixer and K2 replaces the MXFP4 feed-forward. Norms, full attention, and the tensor-parallel all-reduces stay outside those launches.

8k input / 1k output, `sglang.bench_serving`, random dataset. A positive percent is an improvement: more output tokens per second, or a lower median TTFT, ITL, or TPOT. The TP1 cells set both row caps to 8. TP2 uses the default cap of 8.

- Concurrency 4 and 8 sit inside the caps, so K1 and K2 run. Output throughput, median ITL, and median TPOT improve on TP1 and TP2. Median TTFT improves only at TP1 concurrency 4.
- Concurrency 16 and above is past the caps, so the mono kernels do not launch. Those cells replay the stock CUDA graph, including FlyDSL QuickReduce, and stay with non-mono.
- Accuracy holds. GPQA Diamond 0.8232 → 0.8434 (TP1) and 0.8232 → 0.8333 (TP2). NIAH 64k / 128k stay within 0.002 at TP1 and are flat or higher at TP2. TP2 MMMU val 0.5211 → 0.5256.

## Details

A step enters the mono graph only when it is a pure decode (`num_prefills == 0`, at least one decode row, no spec-decode mask) and the row count is inside the kernel build. The builds cover 1–8 rows at TP1 and 1–16 rows at TP2. Serving defaults are narrower: K1 and K2 each default to 4 rows at TP1 and 8 rows at TP2. Override either cap with `VLLM_ROCM_QWEN38_DENSE_MONO_K1_MAX_ROWS` or `VLLM_ROCM_QWEN38_DENSE_MONO_K2_MAX_ROWS`. A value outside 1..8 at TP1 or 1..16 at TP2 is clamped and a warning is logged.

TP1 compiles one whole-step graph and folds the norms into K1 and K2. TP2 compiles a split graph: stock norms and the full-attention block stay visible, and each rank's K1 and K2 partial is all-reduced after the launch. `VLLM_ROCM_QWEN38_DENSE_MONO_OPROJ` (default on) folds `out_proj` into the TP1 graph and into the TP2 K1 partial. `VLLM_ROCM_QWEN38_DENSE_MONO_K2` (default on) selects the K2 launch on the TP2 graph.

The flag applies only to `qwen3_5_text`. A set flag on a deployment these kernels cannot run raises and lists the reason: TP other than 1 or 2, a GPU other than gfx950, pipeline parallel, LoRA, a KV connector, sequence parallel, speculative tokens, or a shape or quant method other than this Quark MXFP4 27B dense MLP.

```text
amd/mono/
    dense_gdn.py     K1, the GDN mixer
    dense_ffn.py     K2, the MXFP4 FFN
    helpers.py       step tag, sigmoid, e8m0
    sources.py       kernel source digest
    common/          device ops, mailbox sync, MX helpers, plan / build keys
```
