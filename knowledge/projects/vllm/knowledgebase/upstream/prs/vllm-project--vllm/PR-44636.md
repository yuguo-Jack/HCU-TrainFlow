# Move DP sync to a dedicated CUDA stream

[Upstream PR](https://github.com/vllm-project/vllm/pull/44636) · state: closed · merged: False

## Original PR description

Async scheduling + (multi-node) DP + spec dec has bubbles caused by the DP synchronization steps because of the Gloo comms (NCCL falls back to Gloo for DP synchronization with async to avoid a GPU sync). This fix keeps NCCL comms but moves then onto a dedicated stream to avoid a gpu sync.

As far as I can tell, this affects all `async_scheduling` + DP configs, but is aggravated by:
- multi-node / high rank DP
- speculative decoding (more DP syncs)

This is why the regression only showed up on certain models, in the other cases the advantages from async were masking it. This fix improves performance across the board

- TQCB · comment · 2026-06-09T10:37:59Z · [source](https://github.com/vllm-project/vllm/pull/44636#issuecomment-4658917741)

It looks like this change is not compatible with TP and leads to IMA errors. A solution would be gating this behind TP, but doing so naively would mean that all TP+DP configs would regress to using async_scheduling=False. Another solution is to maintain the dedicated stream path for TP+DP configs, but they would continue to suffer from the sync bubble that this was trying to resolve.

I think the most sensible would be to maintain both paths, because the async + DP regression only shows up at:
- low BSZ
- high / multi node DP
- with spec dec

Additionally, if anyone has any insight on why this may be incompatible with TP, I would love to hear. I had some theories about the custom all reduce used for TP but have not managed this issue when adjusting this, so it seems more general.
