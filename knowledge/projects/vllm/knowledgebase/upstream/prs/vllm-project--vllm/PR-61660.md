# [Bugfix][Frontend] Do not count the token sampled for echo with max_tokens=0

[Upstream PR](https://github.com/vllm-project/vllm/pull/61660) · state: open · merged: False

## Original PR description

## Overview

`/v1/completions` with `echo=True, max_tokens=0` reports `completion_tokens: 1` and, with `return_token_ids`, returns a token id that is not in the response.

## Claims

- Usage counts no completion tokens for echo with `max_tokens=0`, in both streaming and non-streaming responses.
- `token_ids` is empty for that case instead of carrying the hidden token.

## Validation

New `tests/entrypoints/openai/completion/test_completion_echo_usage.py`:

```
pytest tests/entrypoints/openai/completion/test_completion_echo_usage.py tests/entrypoints/openai/completion/test_completion_text_offset.py
  main:        2 failed (completion_tokens: assert 1 == 0), 1 passed
  this branch: 3 passed
```

`test_completion_error.py` and `test_prompt_validation.py`: 93 passed, 4 failed on both main and this branch (xgrammar and model downloads are unavailable in my environment). Model evaluation does not apply: generated text and logprobs are unchanged. I did not run a live server.

## Details

`CompletionRequest.to_sampling_params` runs echo with `max_tokens=0` as `max_tokens=1`, and the serving code drops that token from the text, but both paths still added `len(output.token_ids)` to usage and returned `output.token_ids`. The fix counts and returns no generated tokens in that case.

Not a duplicate: open PRs and issues searched for echo, `max_tokens=0` and completions usage; none touch this. #59324 changes `finish_reason` elsewhere and does not touch completions serving.
