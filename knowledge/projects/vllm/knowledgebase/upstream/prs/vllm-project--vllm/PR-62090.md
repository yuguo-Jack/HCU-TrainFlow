## Overview


Why the buffer grouping is necessary

  The test runs multiple MoE configurations within the same distributed workers. NIXL retains a process-wide communication buffer whose expert capacity is established during its first initialization.

  In the failing sequence, the first configuration allocates capacity for eight experts. Later configurations request 64 experts, but receive the same buffer. NIXL then rejects the request with its active/maximum expert-bound assertion. Running the affected configurations in fresh processes removes that assertion.

  Calling the manager’s destroy() between configurations does not resolve this: it intentionally retains the buffer to support elastic expert-parallel scaling.

  Why rename _group_deepep_ll_configs

  The existing helper already implements the required pattern: group compatible configurations and launch separate workers for incompatible groups. Its purpose now applies to both ROCm DeepEP low-latency and NIXL EP.

  Renaming it to _group_configs_by_buffer_requirements describes that shared responsibility and avoids maintaining two implementations of the same grouping logic. The key includes:

  • Routed hidden size.
  • Expert-parallel size.
  • Total expert count.

  For latent MoE, the routed hidden size is k // 2, so grouping must account for the input transform. Token capacity and the other allocation settings are fixed within the outer test case.

  Fresh workers provide a clear lifetime boundary without changing production buffer management or its elastic-scaling behavior. Grouping also retains buffer reuse among compatible cases: this matrix needs four worker groups, rather than restarting workers for every one of its 52 subcases.

  Why preserve padded weights

  The latent configurations generate 1024-wide expert weights, while NIXL requires a supported hidden size of at least 2048. The layer correctly allocates padded parameters, but the test replaces them with smaller tensors. Activations remain padded, producing:

  Hidden size mismatch 2048 != 1024

  The patch keeps the allocated parameter, zeros its padding, and copies the original weights into the valid hidden-dimension slice. This preserves W13’s input padding and W2’s output padding. Other dimension mismatches still fail an assertion.

  Both corrections belong in the test setup: one respects the communication buffer’s lifetime, and the other respects the layer’s allocated weight layout.

  Related work, PR #61156 (https://github.com/vllm-project/vllm/pull/61156), limits NIXL dispatch token capacity. It addresses a different dimension of buffer sizing and does not fix these test weight-loading or cross-configuration lifetime problems.

Validation used two SM107 and SM100 GPUs with the Oct16 nightly container, NIXL 1.5.0, FlashInfer 0.7.2, and PyTorch 2.16.0.dev20261009+cu134.

Additional worker launches increase test setup overhead and change random draw sequences. This validates the same configuration matrix with unchanged numerical checks; it is not an identical-tensor replay.
