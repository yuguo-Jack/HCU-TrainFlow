# [Bugfix][Tool Parser] Fix HYV4 guided prefix loss, nested marker splitting, and O(N^2) arg scanning in HYV3/HYV4

[Upstream PR](https://github.com/vllm-project/vllm/pull/62502) · state: open · merged: False

## Original PR description

## Purpose

Fixes three streaming correctness and complexity bugs in `HYV4ToolExtractor` (`vllm/tool_parsers/hy_v4_tool_parser.py`) and `HYV3ToolParser` (`vllm/tool_parsers/hy_v3_tool_parser.py`):

1. **Guided streaming drops held-back partial prefixes (`HYV4ToolExtractor.extract_tool_calls_streaming`, `guided=True`)**:
   - When `<tool_calls...>` is not yet present in `current_text`, the parser holds back `partial_tag_overlap(current_text, marker)` characters at the tail of `current_text` (`safe_end = len(current_text) - partial_tag_overlap(current_text, marker)`).
   - However, on the next delta, it sliced `current_text[len(previous_text) : safe_end]` (and `current_text[len(previous_text) : content_end]` when the marker arrived) instead of starting from the previously emitted offset `prev_safe_end = len(previous_text) - partial_tag_overlap(previous_text, marker)`.
   - Consequently, any held-back partial prefix of `<tool_calls>` (even a single `<` at the end of a delta such as `"Result: x <"` followed by `" 10"`, or `"Compare a <"` followed by `"<tool_calls>..."`) was permanently lost from streamed assistant `content`.

2. **Unguided streaming splits literal `<tool_calls>` inside tool arguments (`HYV4ToolExtractor` & `HYV3ToolParser`)**:
   - In both `HYV4ToolExtractor.extract_tool_calls_streaming` (`guided=False`) and `HYV3ToolParser.extract_tool_calls_streaming`, `if self.tool_calls_start_token in delta_text:` ran on every delta even after `self.tool_calls_start_token_id` had already been seen in `previous_token_ids` (and called `.split(self.tool_calls_start_token)` without `maxsplit=1`).
   - If a tool call argument contained the literal substring `"<tool_calls>"`, the parser split the argument delta, leaked the argument text preceding `"<tool_calls>"` as assistant `content`, stripped `"<tool_calls>"`, and corrupted the streamed JSON arguments.

3. **Duplicate $O(N^2)$ regex rescanning and control-character escaping in `_extract_streaming_incremental` (`HYV3ToolParser` & `HYV4ToolExtractor`)**:
   - Both parsers ran `self.func_args_regex.findall(args_text)` from index `0` and immediately ran `self.func_args_regex.finditer(args_text)` from index `0` again on every token delta. Tracking `self._scanned_args_len` allows a single `finditer(args_text, self._scanned_args_len)` pass over only newly arrived argument text.
   - Aligns `HYV3ToolParser`'s partial string escaping with `HYV4ToolExtractor` (`json.dumps(partial_value, ensure_ascii=False)[1:-1]`) so control characters (`\b`, `\f`, `\u0000`–`\u001f`) do not produce invalid JSON or prefix mismatches on close.
