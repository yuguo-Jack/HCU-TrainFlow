# [Multimodal] Refactor encoder cuda graph to support share graph buffer reuse

[Upstream PR](https://github.com/vllm-project/vllm/pull/65084) · state: open · merged: False

## Original PR description

<!-- vLLM PR description format: Purpose / Test Plan / Test Result -->

## Purpose

Encoder CUDA graphs are captured once per token budget, and every captured graph allocates its own full set of I/O buffers sized by that budget. That per-budget O(budget) memory cost is the only reason the default budget table is a coarse power-of-2 ladder — which forces ~33% average padding waste (round-up to the next power of two).

This PR removes the memory cost **generically, with zero model changes**, following the decoder's `input_ids[:num_tokens]` pattern:

1. **Universal shared capture buffers.** At capture time the manager keeps the first (largest) budget's buffers per (path, axis) as the shared allocation; for every later budget it probes shapes via the model's unmodified `prepare_encoder_cudagraph_capture_inputs()` and, per buffer key, checks prefix compatibility (same ndim/trailing dims/dtype, rows fit). Compatible keys capture into a prefix view of the shared buffer (probe content is copied in so the capture-time forward sees correct metadata); incompatible keys silently keep their per-budget allocation. Scalars are shared by identity. This works because all encoder buffers are packed-contiguous row buffers and replay only ever writes `buf[:real_rows]`. Output buffers are shared the same way. No protocol changes, no model changes, no config knobs.

2. **Subdivided default budget table.** With extra graphs costing ~zero buffer memory, the auto-inferred default becomes a subdivided table (4 steps per octave up to 1024, 2 above; 64→16384 = 25 tiers, expected padding waste ~10% vs ~33% for power-of-2). Explicit `encoder_cudagraph_token_budgets` still overrides. Capture-time cost is one extra forward per extra tier; the existing 64-graph warning covers capture-axes blowups.

Duplicate-work check: no open PR covers encoder-graph buffer sharing; complements #41714 (pool memory in profiling) and follows the padding-semantics precedent of #42796.

### Capture cost (DSV4.1, TP=4, per-rank)

| Run | Budget table | Encoder graphs | Capture memory | Capture time |
|---|---|---|---|---|
| Upstream default | pow2, 9 tiers | 9 | 4.19 GiB | 14 s |
| **This PR (default)** | **25 tiers, subdivided** | **25** | **3.80 GiB** | 21 s |

The dense table's 16 extra graphs cost zero buffer memory, and total capture memory ends up *below* the upstream default (Σbudgets ≈ 2×max → 1×max for encoder buffers) at a one-time +7 s capture cost.

### Request latency (concurrency-1 probes, medians of interleaved rounds)

| Probe | pow2 | this PR | Change |
|---|---|---|---|
| pad2_heavy: 5×1344² imgs, 5120 tok (8192 → 6144 tier) | 577.9 / 570.2 ms | 569.0 / 553.0 ms | ~-2-3% |
| mid_pad: 1×714² img (512 → 320 tier) | 134.6 / 136.6 ms | 138.7 / 135.9 ms | neutral |
| no_pad control (994 tok → 1024 both) | 211.4 / 214.8 ms | 223.0 / 215.7 ms | neutral |
| cliff_900 (508 tok → 512 tier both) | 159.6 / 157.3 ms | 162.0 / 156.5 ms | neutral |

VisionArena-Chat TTFT at concurrency 1: medians identical (~127-129 ms); means are dominated by warmup-order noise (an established property of this benchmark on this cluster).

### Notes / caveats

- The latency win scales with per-batch padding; high-padding workloads (multi-image requests landing just above a power of two) gain a few percent, everything else is neutral. The structural point of this PR is making fine-grained budgets free (memory), not the probe numbers.
- Prefix-incompatible buffers (hypothetical; none among the 21 current encoder-CG models) degrade gracefully to per-budget allocation.
- `docs/design/cuda_graphs_multimodal.md` is updated accordingly.
