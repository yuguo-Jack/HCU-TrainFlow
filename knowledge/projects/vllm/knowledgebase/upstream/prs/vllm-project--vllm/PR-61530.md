# [Model][DSV4.1] Support MXFP4-packed Engram embedding tables

[Upstream PR](https://github.com/vllm-project/vllm/pull/61530) · state: open · merged: False

## Original PR description

## Overview

Support DeepSeek-V4.1 checkpoints whose Engram embedding table is stored as MXFP4 (E2M1 nibbles packed two per byte, UE8M0 block-32 scales) instead of FP8. FP8 behavior is unchanged.

## Claims

- A checkpoint with `quantization_config["engram_embed_quant"] = "mxfp4"` now loads: the table is allocated as `[rows, dim // 2]` uint8 and decoded in the lookup kernel.
- The packed table halves the host memory: 12.16 GiB per rank vs 23.60 GiB for FP8 (`DeepSeek-V4.1-Flash`, TP=4).
- GSM8K accuracy of the packed checkpoint matches the FP8 baseline (0.967 vs 0.966), including with `dp_shared_memory`.
- An unknown `engram_embed_quant` value raises instead of being ignored.

## Validation

### End to end (GB300)

`DeepSeek-V4.1-Flash`, one GB300 node per run, on `vllm 0.31.1rc1.dev360+g44f0ddfd7` (this PR's base). Compiled ops come from the precompiled wheel for that commit, with this PR's Python overlaid. GSM8K: 1319 questions, 5-shot, chat endpoint, `--max-tokens 4096`.

| Run | Engram table | Parallelism | GSM8K acc. | Invalid | Output tok/s |
|---|---|---|---|---|---|
| FP8 baseline | 23.60 GiB per rank (host-pinned) | TP=4 | 0.966 | 0.004 | 1275 |
| MXFP4-packed | 12.16 GiB per rank (host-pinned) | TP=4 | 0.967 | 0.005 | 1218 |
| MXFP4-packed, `dp_shared_memory` | 48.64 GiB shared across 4 DP replicas | DP=4, TP=1, EP | 0.967 | 0.003 | 1299 |

- One run per row. A 0.001 accuracy gap is within noise (about ±0.5 points standard error). tok/s is not a clean comparison (single runs, different parallel layouts).
- DP-shared packed storage (`DPSharedEngramStorage`) loads and serves correctly.
- The FP8 baseline is `DeepSeek-V4.1-Flash-nvfp4-experts-blend`. I did not check that its expert quantization matches the packed checkpoint's, so the accuracy comparison is not isolated to the Engram table.
- Not covered: long-context and other benchmarks, DP=4 with FP8.

  --max-tokens 4096 --save-results gsm8k.json

The checkpoint needs `quantization_config["engram_embed_quant"] = "mxfp4"`.

## Details

- `ParallelEngramEmbedding` takes `packed_fp4`; the row size is `dim // 2` bytes when packed. `DPSharedEngramStorage` and the offload memory log count the packed row size.
- `_engram_lookup_kernel` gets a `PACKED_FP4` constexpr (even column in the low nibble); the block scales are unchanged.
- `EngramBatch.create` returns `None` for packed tables, because the staged exchange carries FP8 rows only.
- `Engram._create_embedding` reads the format from the HF config (default `"fp8"`).
- Limitations:
  - GPU-resident lookup is about 36% slower for packed tables (nibble decode). The deployed host-pinned mode is within 1-3%.
  - `can_share_engram_tables` still sizes `/dev/shm` from the FP8 row size, so it over-estimates by about 2x for packed tables. This is conservative, and I left it out to keep the diff small.
- Existing tests that build layers through `__new__` need a `model_config` stub, which this PR adds.
- Not a duplicate: #58782 (DeepSeek-V4/V4.1 hybrid FP8/MXFP4 quant routing, AMD) changes quant config and weights mapping, not the Engram table path. #60938 also edits `engram.py` and `test_engram.py` (Engram to mHC fusion prototype), so it may conflict textually.
