# [Bugfix] Mark tool_result is_error in Anthropic converter

[Upstream PR](https://github.com/vllm-project/vllm/pull/58700) · state: open · merged: False

## Original PR description

## Purpose

Part of #58647 (item 9) — `AnthropicContentBlock.is_error` is parsed
off the wire but never used, so a failed tool call and a successful
one produce identical `tool` messages. The model has no way to tell
"the file doesn't exist" from "here's the file contents."

Added a small `_mark_tool_error` helper used in both places a
`tool_result` gets converted (the normal user-role path and the
rarer assistant-role echo path), prefixing the content with
`Error:` when `is_error` is true.

Used Claude to help identify and implement this fix and draft the
tests — reviewed and ran everything locally before submitting.

## Test Plan

Added tests for: error with content, error with empty content
(should say "Error" not ""), and confirming the non-error path is
unaffected.

## Test Result

`pytest tests/entrypoints/anthropic/test_anthropic_messages_conversion.py -v`
— 84 passed, 0 failed.

- YS-OH-CORE · comment · 2026-09-27T10:10:00Z · [source](https://github.com/vllm-project/vllm/pull/58700#issuecomment-5854924783)

A small integration note for this change and #58823: the error marker will need to handle structured content when the two behaviors are combined.

I checked #58700 at `16155d78b50beb86522a6018f7105b16ad327619` and #58823 at `a9cdfa3b645773684b40359e11e78fb49f4c57e8`. The latter returns a list for an image-bearing tool result. Passing that list to this PR's unchanged `_mark_tool_error(..., True)` produces a Python-repr **string**, so the URL remains as text but no structured image part remains:

```python
parts = [{"type": "image_url", "image_url": {
    "url": "https://example.invalid/synthetic.png"
}}]
marked = AnthropicServingMessages._mark_tool_error(parts, True)
assert isinstance(marked, str)
assert marked.startswith("Error: [")
```

This is an **authored composition experiment, not a bug claim against either standalone PR or an already-merged branch**. In the image converter I changed only the first tool-message content assignment to call this helper; the helper itself was unchanged. With `is_error=False` or absent, the structured list survives.

A list-aware branch can prepend a text part without stringifying the original parts, while retaining your existing string/empty-string behavior:

```python
if isinstance(tool_content, list):
    if not is_error:
        return tool_content
    return [{"type": "text", "text": "Error:"}, *tool_content]
# Existing string handling follows.
```

The useful integration regression is `is_error=True` together with text/image/text (also image-only and multiple images): preserve the image parts, relative order and tool-call ID, and leave successful results unchanged. My isolated candidate passed 21 parameterized contracts (7 shapes × absent/false/true); 4 separate characterization cases confirmed the stringification in the explicit composition. The exported test copy also passed all 25.

Scope: hash-pinned, unchanged extracted conversion methods and the real Pydantic content-block class, Python 3.12.14 / Pydantic 2.13.5. **No full vLLM import, renderer/tokenizer, image decoding, endpoint or model run.** This is a review aid for the existing work, not a second PR or a claim of production readiness.
