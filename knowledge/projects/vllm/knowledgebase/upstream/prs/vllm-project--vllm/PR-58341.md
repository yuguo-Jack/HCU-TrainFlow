# Guard /invocations with the API key check

[Upstream PR](https://github.com/vllm-project/vllm/pull/58341) · state: closed · merged: False

## Original PR description

Fixes #58144

I ran a server with --api-key and noticed /v1/chat/completions correctly returned 401 without credentials, while the same body posted to /invocations came back 200 with a full completion. Both paths end up in the same handlers, so the difference comes down to the middleware only looking at /v1, /v2, /inference and /cohere prefixes while the SageMaker router sits at the root on every deployment.

This change adds /invocations to the guarded prefixes. I verified with a small TestClient script that /invocations without a token now returns 401, with a valid bearer token returns 200, and /ping stays open for health checks. The existing auto-discovery auth tests cover guarded versus unguarded routes by prefix, so the new prefix falls under the same assertions.
