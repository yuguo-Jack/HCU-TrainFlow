# [Core][NIXL] Transfer KV between different P/D KV cache group plans

[Upstream PR](https://github.com/vllm-project/vllm/pull/60113) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

NIXL can now transfer KV between P and D whose hybrid KV cache group plans differ, so NixlConnector no longer needs #58207's TP-invariant planning, except for MLA. Motivated by RFC #58638. Stacked on #58207 at `e55909cad0`, #58860, #59746, #59747 and #59330; only [the last four commits](https://github.com/lucamotz/vllm/compare/77126176e8aad50c41bd402428c30686cf264f0c~4...77126176e8aad50c41bd402428c30686cf264f0c) are new.

## Claims

- Connectors say whether their peers need matching KV cache groups: `requires_matching_kv_cache_groups()` defaults to True, so every other connector keeps #58207's planning.
- NixlConnector pull between different plans is exact: Qwen3.6-35B-A3B-FP8 + DFlash at P TP2 ↔ D TP4 gives bitwise-identical outputs to TP-invariant plans, with 7–28% more KV tokens on D.
- This also covers plans that differ under TP-invariant planning, which depends on each side's `--max-num-batched-tokens`, PP and async scheduling.

## Details

- **Hook:** replaces the planner's `kv_transfer_config is not None` check. MultiConnector asks the connectors it wraps; OffloadingConnector with `CPUOffloadingSpec` and SimpleCPUOffloadConnector return False, since their KV doesn't leave the engine.
- **Group pairs:** the handshake, version 15, advertises each region member's KV cache group, KV heads and tokens per page. Where plans differ or the model-wide head mapping doesn't fit every layer, layers transfer per pair of local and remote KV cache groups, in pull and push. Matched plans that the model-wide mapping fits keep today's path.
- **Who plans independently:** NixlConnector returns `use_mla`. NixlPushConnector stays TP-invariant, since a PP push producer routes layers by name. MLA, CSA-linear and PP push producers reject peers with different plans at the handshake.
- **Log:** names the `--block-size` that makes P and D pages divide, once per remote engine.

Not covered: MLA, where a GQA draft under an MLA target stays with #58471 and #59071; DCP; GPUDirect RDMA across nodes. The NIXL compatibility doc isn't updated yet.

The four commits change +700/−51 production lines. The hook can go as a small PR on top of #58207 and the NIXL commits after it, if that is easier to review. No open NIXL PR, and none citing #58638 or #58207, transfers between different KV cache group plans.
