# [Turing] Restore flashinfer support for SM75

[Upstream PR](https://github.com/vllm-project/vllm/pull/55380) · state: open · merged: False

## Original PR description

## Overview

Restore automatic `FLASHINFER` attention selection on NVIDIA Turing GPUs (SM75), with a capability-aware head-size limit and user documentation. Related: #47549.

The SM75 head-dimension-256 shared-memory regression was fixed upstream in [FlashInfer #3526](https://github.com/flashinfer-ai/flashinfer/pull/3526). This PR restores the existing backend after that fix and relies on upstream FlashInfer for AOT/JIT cache handling.

## Claims

- Enable FlashInfer selection on SM75 for compatible FP16 configurations with head sizes 64, 128, or 256.
- Reject `head_size > 256` on SM75 during configuration validation; automatic selection can choose another compatible backend, while explicit incompatible selection fails early.
- Use FlashInfer's existing architecture-aware AOT → JIT fallback. Installed cache providers for other architectures can remain installed; the previous SM75 cache-uninstall warning and its helpers/call sites have been removed.
- Document SM75 selection, head-size limits, and JIT toolchain requirements in `docs/design/attention_backends.md`.

### End-to-end: Qwen3-0.6B, wall-clock milliseconds

Model: **Qwen/Qwen3-0.6B**, real pretrained weights, FP16, TP=1. Prompts repeat a fixed text to the requested token length; generation uses `temperature=0` and `ignore_eos=True`.

### Attention-only: standalone paged-attention kernels

Inputs are seeded random FP16 Q/K/V tensors with **Qwen3-0.6B's attention geometry**: 16 query heads, 8 KV heads, head dimension 128, page size 16, NHD layout, and random page tables. FlashInfer uses FA2 paged-prefill and tensor-core paged-decode wrappers; Triton uses `unified_attention` with its 16-segment decode path.

Both backends received five warmup calls, correctness checks, and five further warmups for the captured backend. Each result covers five calls using fixed tensors and KV lengths. Nsight Compute 2026.2.1 measures the sum of GPU kernel durations per layer and batch, including merge/reduction, with application replay, `--cache-control none`, and `--clock-control none`. Q/K/V preparation, KV-cache writes, and planning are outside the capture.

Triton 3.8.0 uses FMA for SM75 dot operations following the [deprecation of its pre-SM80 Tensor Core/MMA path](https://github.com/triton-lang/triton/pull/5066).

<summary>End-to-end benchmark script</summary>

Select the intended SM75 GPU using `CUDA_VISIBLE_DEVICES`, then run this once for each backend:

```python
import statistics
import time
import torch
from vllm import LLM, SamplingParams

backend = "FLASHINFER"  # repeat with "TRITON_ATTN"
llm = LLM(
    model="Qwen/Qwen3-0.6B", dtype="half",
    attention_config={"backend": backend},
    max_model_len=8192, max_num_seqs=32, max_num_batched_tokens=8192,
    gpu_memory_utilization=0.65, enable_prefix_caching=False,
    enforce_eager=True, seed=0, disable_log_stats=True,
)
tokenizer = llm.get_tokenizer()
for length, output, batch in ((2048, 1, 1), (8000, 1, 1),
                               (512, 128, 1), (512, 128, 8)):
    ids = tokenizer.encode(" The quick brown fox jumps over the lazy dog.")
    ids = (ids * (length // len(ids) + 1))[:length]
    requests = [{"prompt_token_ids": ids} for _ in range(batch)]
    params = SamplingParams(temperature=0, max_tokens=output, ignore_eos=True)
    for _ in range(2):
        llm.generate(requests, params, use_tqdm=False)
    times = []
    for _ in range(5):
        torch.cuda.synchronize()
        start = time.monotonic()
        result = llm.generate(requests, params, use_tqdm=False)
        torch.cuda.synchronize()
        times.append(time.monotonic() - start)
        assert all(len(item.outputs[0].token_ids) == output for item in result)
    print(length, output, batch, statistics.mean(times), statistics.pstdev(times))
```

The measured FlashInfer run used automatic backend selection; the explicit setting above reproduces its backend choice.

<summary>Attention benchmark script and profiling command</summary>

Save this as `profile_attention.py` in the vLLM checkout with the dependencies above installed in `.venv`:

```python
"""Compare warmed paged-attention paths on identical data, then profile one path."""

import argparse
import json

import torch
import flashinfer
from vllm.v1.attention.ops.triton_unified_attention import unified_attention

parser = argparse.ArgumentParser()
parser.add_argument('--backend', choices=['FLASHINFER', 'TRITON_ATTN'], required=True)
parser.add_argument('--query-len', type=int, required=True)
parser.add_argument('--kv-len', type=int, required=True)
parser.add_argument('--batch', type=int, default=1)
parser.add_argument('--profile', action='store_true')
parser.add_argument('--profile-iters', type=int, default=5)
args = parser.parse_args()
assert 1 <= args.query_len <= args.kv_len
torch.manual_seed(0)
torch.set_grad_enabled(False)
device = 'cuda'
qh, kh, dim, page = 16, 8, 128, 16
pages = (args.kv_len + page - 1) // page
blocks = pages * args.batch
q = torch.randn(args.batch * args.query_len, qh, dim, device=device, dtype=torch.float16)
cache = torch.randn(blocks, page, kh, dim * 2, device=device, dtype=torch.float16)
k, v = cache.split(dim, dim=-1)
table = torch.randperm(blocks, device=device, dtype=torch.int32).view(args.batch, pages)
qo = torch.arange(args.batch + 1, device=device, dtype=torch.int32) * args.query_len
kv_ptr = torch.arange(args.batch + 1, device=device, dtype=torch.int32) * pages
indices = table.flatten().contiguous()
last = torch.full((args.batch,), args.kv_len % page or page, device=device, dtype=torch.int32)
lengths = torch.full((args.batch,), args.kv_len, device=device, dtype=torch.int32)
fi_out, tr_out = torch.empty_like(q), torch.empty_like(q)
workspace = torch.empty(128 * 1024 * 1024, device=device, dtype=torch.uint8)
if args.query_len == 1:
    wrapper = flashinfer.BatchDecodeWithPagedKVCacheWrapper(
        workspace, 'NHD', use_tensor_cores=True, backend='fa2')
    wrapper.plan(kv_ptr, indices, last, qh, kh, dim, page,
                 q_data_type=torch.float16, kv_data_type=torch.float16)
else:
    wrapper = flashinfer.BatchPrefillWithPagedKVCacheWrapper(workspace, 'NHD', backend='fa2')
    wrapper.plan(qo, kv_ptr, indices, last, qh, kh, dim, page,
                 causal=True, q_data_type=torch.float16, kv_data_type=torch.float16)
segments = 16
scratch = torch.empty((args.batch, qh, segments, dim), device=device, dtype=torch.float32)
seg_max = torch.empty((args.batch, qh, segments), device=device, dtype=torch.float32)
seg_exp = torch.empty_like(seg_max)


def run_fi():
    return wrapper.run(q, (k, v), out=fi_out)


def run_tr():
    unified_attention(q=q, k=k, v=v, out=tr_out, cu_seqlens_q=qo,
                      max_seqlen_q=args.query_len, seqused_k=lengths,
                      max_seqlen_k=args.kv_len, softmax_scale=dim**-0.5,
                      causal=True, window_size=(-1, -1), block_table=table,
                      softcap=0.0, q_descale=None, k_descale=None, v_descale=None,
                      seq_threshold_3D=128//kh, num_par_softmax_segments=segments,
                      softmax_segm_output=scratch, softmax_segm_max=seg_max,
                      softmax_segm_expsum=seg_exp)
    return tr_out


# Compile/plan and warm both paths equally before comparing or collecting counters.
for _ in range(5):
    run_fi()
    run_tr()
torch.cuda.synchronize()
torch.testing.assert_close(fi_out, tr_out, atol=1e-2, rtol=1e-2)
cross_error = (fi_out-tr_out).abs().max().item()
samples = sorted(set([0, min(1, args.query_len-1), min(7, args.query_len-1),
                      args.query_len//2, args.query_len-1]))
errors = {'FLASHINFER': [], 'TRITON_ATTN': []}
for i in range(args.batch):
    ks = k[table[i].long()].reshape(-1, kh, dim)[:args.kv_len].float()
    vs = v[table[i].long()].reshape(-1, kh, dim)[:args.kv_len].float()
    ks = ks.repeat_interleave(qh//kh, dim=1).transpose(0, 1)
    vs = vs.repeat_interleave(qh//kh, dim=1).transpose(0, 1)
    qs = q[i*args.query_len:(i+1)*args.query_len][samples].float().transpose(0, 1)
    scores = (qs @ ks.transpose(1, 2)) * dim**-0.5
    mask = torch.arange(args.kv_len, device=device)[None, :] > (
        args.kv_len - args.query_len + torch.tensor(samples, device=device)[:, None])
    ref = (scores.masked_fill(mask, float('-inf')).softmax(-1) @ vs).transpose(0, 1).half()
    for name, out in [('FLASHINFER', fi_out), ('TRITON_ATTN', tr_out)]:
        observed = out[i*args.query_len:(i+1)*args.query_len][samples]
        torch.testing.assert_close(observed, ref, atol=1e-2, rtol=1e-2)
        errors[name].append((observed-ref).abs().max().item())
selected = run_fi if args.backend == 'FLASHINFER' else run_tr
for _ in range(5):
    selected()
torch.cuda.synchronize()
print(json.dumps({'event': 'attention_warmup_complete', 'backend': args.backend,
                  'gpu': torch.cuda.get_device_name(), 'capability': torch.cuda.get_device_capability(),
                  'batch': args.batch, 'query_len': args.query_len, 'kv_len': args.kv_len,
                  'q_heads': qh, 'kv_heads': kh, 'head_dim': dim, 'page_size': page,
                  'warmups_each_backend': 5, 'warmups_selected_after_validation': 5,
                  'profile_iterations': args.profile_iters,
                  'full_output_cross_backend_max_abs_error': cross_error,
                  'fp32_reference_max_abs_error': {n: max(e) for n,e in errors.items()}}), flush=True)
if args.profile:
    torch.cuda.profiler.start()
    for _ in range(args.profile_iters):
        selected()
    torch.cuda.synchronize()
    torch.cuda.profiler.stop()
    print(json.dumps({'event': 'attention_profile_complete'}), flush=True)
```

## Details

SM75 has a 64 KiB opt-in shared-memory ceiling. The backend keeps head sizes above 256 ineligible on SM75 while preserving the existing behavior on SM80 and newer devices.

The tested vLLM revision pins **FlashInfer 0.7.2.post1**, which contains the relevant upstream changes:

- [FlashInfer #4514](https://github.com/flashinfer-ai/flashinfer/pull/4514): architecture-provider discovery and architecture/module-aware AOT selection, with uncovered modules using the existing JIT path.
- [FlashInfer #5096](https://github.com/flashinfer-ai/flashinfer/pull/5096): provider-only releases, removal of monolithic-cache discovery, and per-architecture dispatch with JIT fallback for uncovered calls.

The released [AOT resolver](https://github.com/flashinfer-ai/flashinfer/blob/v0.7.2.post1/flashinfer/jit/env.py#L296) and [build/load lifecycle](https://github.com/flashinfer-ai/flashinfer/blob/v0.7.2.post1/flashinfer/jit/core.py#L337) show the path directly. The shared lifecycle was refactored in [#3874](https://github.com/flashinfer-ai/flashinfer/pull/3874), preserving NVCC's earlier behavior.

The official provider inventories for 0.7.2.post1 and 0.7.3 still omit SM75. This affects precompiled coverage, not the availability of runtime compilation. JIT needs to remain enabled with a usable nvcc/ninja toolchain and runtime libraries. Installed providers for other architectures can remain installed.

Validation used GPU hardware outside CI. The selector regression is collected by the existing Buildkite attention-selector job; SM75 kernel/serving coverage is documented above. The new documentation was checked for local discoverability and navigation; a full MkDocs render was not run.

Follow-up on the SM75 `flashinfer-jit-cache` warning: I traced the architecture-aware AOT → JIT path to these upstream changes:

- [flashinfer-ai/flashinfer#4514](https://github.com/flashinfer-ai/flashinfer/pull/4514), **split cache into architecture provider wheels**: introduced provider discovery and architecture/module-aware AOT selection. When no compatible provider artifact exists, the resolver leaves the module on the normal JIT path.
- [flashinfer-ai/flashinfer#5096](https://github.com/flashinfer-ai/flashinfer/pull/5096), **enable provider-only wheel releases**: enabled the published provider layout, removed monolithic-cache discovery, and extended selection/dispatch so calls targeting an uncovered architecture can use JIT even when other AOT providers are installed.
- For background, [flashinfer-ai/flashinfer#3874](https://github.com/flashinfer-ai/flashinfer/pull/3874) factored the shared `try_load() → build() → load()` lifecycle into `JitSpec.build_and_load()`; its NVCC behavior was preserved, so it should not be described as the first introduction of architecture-aware provider fallback.

The vLLM revision tested pins **FlashInfer 0.7.2.post1**, which includes these changes.
