# [KV Cache] Add layer-sharded MLA cache with NCCL broadcast (KVPP)

[Upstream PR](https://github.com/vllm-project/vllm/pull/59059) · state: open · merged: False

## Original PR description

## Summary

Add opt-in `--enable-kvpp` for replicated MLA KV caches on NVIDIA GPUs. Each layer bundle has one persistent owner within a **PCP × TP** replica group; other ranks materialize it in two reusable scratch slots. NCCL broadcast prefetches the next bundle before the current attention, with CUDA events protecting cache writes and buffer reuse.

The intended workload is multi-prefix serving where limited KV memory causes cache eviction. Layer ownership increases cache capacity while preserving ordinary attention tensor views.

## Integration and usage

- Reuse the existing logical block, prefix-cache, scheduler, and KV config construction flows. Account for owner storage and scratch in capacity calculation, then apply physical placement after the common block count is finalized.
- Share one storage plan between allocation, broadcast, and owner-only `SimpleCPUOffloadConnector` registration.
- Manage the KVPP communicator in `parallel_state`, scoped to each DP replica and PP stage. Reuse PCP's existing KV gathering with DCP=1.

Requires Model Runner V2 and PCP × TP ≥ 2. Use `--enforce-eager`, or:

```text
--enable-kvpp -cc.mode=3 -cc.cudagraph_mode=PIECEWISE -cc.use_inductor_graph_partition=false
```

Keep the default attention/KV-update splitting ops. FULL graphs and GPU MRV1 are unsupported. PCP MoE also requires `VLLM_MOE_SKIP_PADDING=0`. See [design and compatibility limits](https://github.com/pisceskkk/vllm/blob/codex/kvpp-attn-prefetch-bcast/docs/design/kv_cache_layer_sharding.md) for other combinations.

## Accuracy and correctness

**DeepSeek-V2-Lite-Chat, 4×H100, TP2 × PCP2, MRV2, compiled PIECEWISE:**

| Check | Replicated baseline | KVPP |
| --- | ---: | ---: |
| GSM8K accuracy, 200 questions / 5-shot | 64.0% | 63.0% |
| Invalid answers | 0 | 0 |
| Mixed short/long and repeated-prefix smoke | Reference | 8/8 token-for-token matches |

Both GSM8K results pass the existing 0.65 ± 0.08 threshold (max output 256, concurrency 8). Evaluation used `08cccd2edf` with the eager-only guard removed. Commit **`74a2ceb3a9`** passed a fresh four-GPU startup/capture, the same eight-request comparison, and all **9 configuration tests**. Observers confirmed graph replay with KVPP prefetch executing outside capture.

Earlier distributed tests cover owner/scratch lifetimes, communicator isolation, PP-stage ownership, and teardown/reinitialization. The `DeepSeek-V2-Lite-Chat-KVPP.yaml` e2e guard uses PIECEWISE. Ruff check/format and `git diff --check` passed.

## Best observed TP + KVPP prefix-pooling result

**DeepSeek-V2-Lite-Chat, 4×RTX 5090, TP4, MRV2 eager, attention-before broadcast.** Both placements use a 512 MiB KV budget per rank. Four prefix families each have 4,096 shared tokens plus a 1,024-token unique suffix; 256 requests per round, concurrency 4, one output token. Two measured rounds exclude warmup.

| Metric | Replicated baseline | KVPP |
| --- | ---: | ---: |
| Logical KV capacity (tokens) | 17,248 | 51,776 |
| Prefix-cache hit rate, rounds 1 / 2 | 37.8% / 38.3% | 80.0% / 80.0% |
| Input tokens/s, rounds 1 / 2 | 67,988 / 68,586 | 124,651 / 124,638 |
| Mean input tokens/s | 68,287 | **124,645 (+82.5%)** |

This is GPU-resident prefix pooling without CPU offload. Throughput counts cached input tokens; the gain combines greater cache residency and broadcast scheduling. Both sides disabled FlashInfer autotune and used `NCCL_P2P_DISABLE=1`; configured max model length was 8,192 for baseline and 16,384 for KVPP, with identical 5,120-token requests.

These measurements describe the earlier eager implementation and this one-token-output workload. Current-revision throughput and long-output decode gains remain unmeasured. Gains are device/workload dependent: attention-before broadcast regressed in the H100 cropped-DSv3.2 CPU-offload pool experiment.
