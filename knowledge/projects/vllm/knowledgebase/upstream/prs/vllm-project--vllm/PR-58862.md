# [Bugfix][Structured Output] Reject structural_tag and unhandled specs in backend validation

[Upstream PR](https://github.com/vllm-project/vllm/pull/58862) · state: closed · merged: True

## Original PR description

## Purpose

With the `outlines` or `lm-format-enforcer` structured-output backend, `structural_tag` requests currently pass validation even though neither backend supports them. They then fail in the engine with `ValueError` and finish as `FINISHED_ERROR` instead of being rejected with a 400. This can also affect requests that do not explicitly specify `structural_tag`, since vLLM can construct these constraints internally (e.g. tool parsers using `structural_tag_model` and the Responses API).

This adds a `structural_tag` rejection to both validators, consistent with the existing `grammar` rejections.

Per review, the outlines, lm-format-enforcer and xgrammar validators now also reject any spec they do not handle with a `VLLMValidationError` (400) instead of failing in the engine.

**Not a duplicate:** searched open and closed PRs/issues on 2026-09-26 for `structural_tag`/validation-related reports. Relevant hits (#45893, #44993, #44297, #52452, #54003) do not modify these validators.


## Test Plan

Three regression cases in `test_unsupported_grammar_is_a_client_error`: `structural_tag` (a valid tag) on outlines and on lm-format-enforcer, and `json_object` on outlines.

Also, `test_supported_spec_is_not_rejected` (supported specs, including `regex=""` and `json={}`, still pass) and `test_unhandled_spec_is_a_validation_error`
