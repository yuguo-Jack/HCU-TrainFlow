# [Attention] Add MiniMax M3 indexer CP for prefill and decode

[Upstream PR](https://github.com/vllm-project/vllm/pull/61929) · state: open · merged: False

## Original PR description

## Overview

Add opt-in MiniMax M3 indexer context parallelism for P128 on single-node NVLink TP2/TP4, covering prefill and decode. [P256 support](https://github.com/vllm-project/vllm/pull/63671) is stacked on this PR.

## Claims

- Store 1/TP of index K per rank; replicate index Q while main KV remains head-sharded.
- Score local K, select Top16 and exchange/merge at head owners. Prefill uses bounded scratch and one exchange per layer; decode uses fused publication and generation tags.

## Validation

CPU offload update: built-in `SimpleCPUOffloadConnector` with the CPU backend now retains index-K sharding. Added TP2/TP4 store/overwrite/reload checks followed by indexer output and graph-replay comparisons. GPU roundtrip and full-model prefix-reload validation are pending; the E2E measurements below do not cover this new combination.

## Details

```bash
--attention-config '{"indexer_kv_dtype":"fp8","indexer_cache_sharding":"on","indexer_prefill_cp":"local_score"}'
```

CP defaults off; omitting `indexer_prefill_cp` retains gather. The experimental `local_score_unified` mode also applies local scoring to mixed-batch decode queries. Layout stays fixed at startup.

Requires [MSA #46](https://github.com/vllm-project/MSA/pull/46), currently `b41e5f2c`, built via `FMHA_SM100_SRC_DIR` until the vLLM dependency pin is updated after that PR merges. Its APIs are absent from the default vLLM MSA pin.
