# [WIP][Attention] Shard MiniMax M3 indexer cache across TP ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/61929) · state: open · merged: False

## Original PR description



## Overview

Add opt-in tensor-parallel sharding of the MiniMax M3 FP8 indexer cache. On supported TP4 Blackwell deployments, each rank stores one quarter of the token rows in every index-K page and exchanges partial block maxima for the existing Top-K selection.

## Claims

- Reduce persistent index-K bytes per block per rank by 75%, with separate symmetric receive/staging buffer overhead. Main attention Q/K/V partitioning and cache precision are unchanged.
- Support decode, CUDA Graph replay, and prefill reconstruction through the MSA backend, behind `--attention-config '{"indexer_cache_sharding":"on","indexer_kv_dtype":"fp8"}'`. The default is `off`; `auto` applies backend-specific eligibility and workload thresholds.
- Coordinate catchable rank-local allocation failures and prefill-gather kernel compilation/loading failures before the corresponding peer rendezvous, so ranks select the same fallback instead of entering different collectives.

## Details

Rank `r` owns token rows `r, r+4, ...` within each 128-token page, retaining all 128 index-K dimensions for each owned token. All index-Q heads are projected locally. The score kernel sends partial block maxima to each head's owner, which reduces them before existing Top-K selection. Prefill reconstructs full pages using symmetric staging, with NCCL fallback.

Eligibility is limited to TP4, SM100-family GPUs, FP8 index cache, MSA top-16, supported speculative methods with index-head count times maximum query length at most 32, and no prefill/decode context parallelism. Unsupported deployments retain replicated storage. Query replication and communication add work; shorter contexts may be slower. The change keeps the upstream prefill planner.

Initialization coordinates each local preparation phase over the TP CPU group before its corresponding peer rendezvous. Receive-buffer allocation/initialization is coordinated first; page-gather allocation and kernel compilation/loading are coordinated before the later staging-buffer rendezvous. This handles catchable local setup failures; process death or communication-internal failures remain engine errors. Decode kernels compile during the normal warmup path.

Related work: [#59980](https://github.com/vllm-project/vllm/pull/59980) retains replicated index-K storage and distributes whole-block scoring, with query and Top-K candidate gathers. [#57909](https://github.com/vllm-project/vllm/pull/57909) implements AMD block-scoring CP and shares the replicated index-Q loader mechanism; that loader support should be reused when either change lands. This PR changes physical token-row ownership and reconstructs pages for prefill. [#59979](https://github.com/vllm-project/vllm/pull/59979) separately changes prefill planning.

Adapted from Suyog Gupta's [index-K sharding commit](https://github.com/xinli-sw/vllm/commit/69a7c7bf290843181349fc958b10f902276e7b09), with backend integration, reduced scope, initialization coordination, and tests. AI assistance was used for extraction, implementation, review, and validation.
