# [Bugfix][DeepSeek V4.1] Fix system-only prompt rendering

[Upstream PR](https://github.com/vllm-project/vllm/pull/62459) · state: open · merged: False

## Original PR description

## Overview

Fix DeepSeek V4.1 prompt rendering when the final rendered message is a
`system` message. This covers a `system`-only request and a leading `system`
message before an `assistant` history turn. The V4.1 encoder only appends the
assistant transition for system messages at index > 0, so these prompts ended
at the system role and generation could stop immediately or continue the
system text.

This mirrors the V4 fix from #51262 in both the Python tokenizer and the Rust
frontend.

## Claims

- A `system`-only chat request now renders `<｜Assistant｜><think>` (thinking)
  or `<｜Assistant｜></think>` (chat) and returns a normal response instead of
  an empty or malformed one.
- A leading `system` message followed by an `assistant` turn now gets the
  assistant header, so the history turn is no longer concatenated
  (`rulesanswer` -> `rules<｜Assistant｜></think>answer`).
- V4 rendering is unchanged. The removed Rust dialect guard was already true
  for V4, and the V4 Python encoder already has the #51262 rule.
- Mid-conversation `system` messages and the existing
  `system -> user -> system` behavior are unchanged.

## Validation

### End-to-end

Deployment: vLLM 0.31.0, TP8 + EP.

| Request                                | Result after the fix                                         |
| -------------------------------------- | ------------------------------------------------------------ |
| `system` only, thinking on             | normal answer, `prompt_tokens=30`, `reasoning_tokens=39`     |
| `system` only, `reasoning_effort=none` | normal answer, `prompt_tokens=5`, `reasoning=null`, `reasoning_tokens=0` |
| `system` + `user`                      | normal answer, `prompt_tokens=37`                            |
| `system` + `user` + trailing `system`  | normal answer, `prompt_tokens=45`                            |

Reproducer:

```bash
curl -s http://HOST/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "dsv41-flash",
    "messages": [{"role": "system", "content": "Hello"}],
    "reasoning_effort": "none",
    "stream": false
  }'
```

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": "Hello! How can6 can I help you today?",
      "reasoning": null
    },
    "finish_reason": "stop"
  }],
  "usage": {
    "prompt_tokens": 5,
    "total_tokens": 17,
    "completion_tokens": 12,
    "completion_tokens_details": {"reasoning_tokens": 0}
  }
}
```

Before the fix, the same request rendered:

```jinja2
<｜begin▁of▁sentence｜><｜System｜>Hello
```

and could return an empty or abnormal response. After the fix it renders:

```jinja2
<｜begin▁of▁sentence｜><｜System｜>Hello<｜Assistant｜></think>
```

The reported `prompt_tokens=5` matches BOS + `<｜System｜>` + content +
`<｜Assistant｜></think>`, i.e. the two transition tokens are present. The
thinking-on request similarly reports `prompt_tokens=30` and a populated
`reasoning` field, confirming that `<｜Assistant｜><think>` is in the prompt.

## Details

Root cause: `render_message()` in
`vllm/tokenizers/deepseek_v41_encoding.py` appends the assistant transition
only when `role == "system" and index > 0`. A leading system message is
rendered at index 0, so a system-only request ends the prompt at the system
content. The model has no `<｜Assistant｜>` role marker and can emit EOS
immediately or continue the system text.

Fix: append the transition when the system message is the last message or is
followed by an assistant message, matching the V4 rule merged in #51262.
Mid-conversation system messages keep their existing behavior.

Rust: `render_request_with_media_order()` in
`rust/src/chat/src/renderer/deepseek.rs` already gates the transition on
`should_write_transition()` (next assistant, or final message with
`add_generation_prompt`). The change only adds V4.1 system messages to the set
of entries considered for the transition, so:

- leading system + user/developer/system: no transition (unchanged)
- leading system as the final message: transition (fixed)
- leading system + assistant: transition (fixed)
- mid-conversation system: unchanged

No documentation update is needed. This restores existing tokenizer behavior
without adding options or APIs.
