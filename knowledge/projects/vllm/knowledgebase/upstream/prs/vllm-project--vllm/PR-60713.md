# [Feature] Add Winnow read strategy to the Decisions API

[Upstream PR](https://github.com/vllm-project/vllm/pull/60713) · state: open · merged: False

## Original PR description

## Overview

Add an explicit Winnow read strategy to the existing Decisions API, preserving the checkpoint's trained prompt and candidate-token protocol. This PR is stacked on **#60745 (general Decisions image API support)**. Review/merge #60745 first, then this PR. The shared Decisions API from #60465 has already merged.

The generic strategy uses a chat prompt and JSON-quotes choice values. Winnow requires its canonical state, question and option serialization. Explicit strategy selection keeps that behavior isolated without changing generic routing or adding a new model loader.

## Behavior

- Support predicate, choice and score questions through existing Decisions response types.
- Apply external conditional temperature while retaining raw full-vocabulary confidence.
- Preserve cache salt and trace headers.
- Reject unsupported model architectures, invalid configuration and chat overrides.

This PR includes Winnow-specific image integration: native `Gemma4ForConditionalGeneration` selection, the trained image-attachment serialization, and expanded-context checks. It requires the general image transport from #60745 and a checkpoint containing its matching vision tower/projector. Text-only exports remain text-only.

## Stack and review scope

1. **#60745:** general image transport and rendering for the Decisions API, based on main.
2. **This PR:** Winnow text and image strategy support, on top of #60745.

[Review only Winnow changes above the image API branch](https://github.com/Txoka/vllm/compare/feat/winnow-decisions-vision...feat/winnow-decisions).

GitHub's full diff against main temporarily includes #60745. After #60745 merges, this PR will be rebased onto main to remove those predecessor changes. Model-specific Winnow code remains out of #60745.
