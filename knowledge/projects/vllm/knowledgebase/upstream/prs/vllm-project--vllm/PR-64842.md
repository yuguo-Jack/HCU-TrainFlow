# [Bugfix][NixlPush] Supervise the push writer thread (W2)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64842) · state: open · merged: False

## Original PR description



## Overview

Item W2 of #48633 ([claim](https://github.com/vllm-project/vllm/issues/48633#issuecomment-5974469436)). The `nixl-push-writer` loop catches every error once per pass and continues ([push_worker.py#L256-L306](https://github.com/vllm-project/vllm/blob/a20280f30e3169d33a7e21d1d117e9719bace00b/vllm/distributed/kv_transfer/kv_connector/v1/nixl/push_worker.py#L256-L306)). One failing request drops other requests' work, a persistent error re-runs the pass every 1 ms while P holds unmatched blocks, and nothing notices if the thread dies.

## Claims

- An error for one request no longer drops the rest of the pass. On P it becomes that request's send failure, like a WRITE that failed to post. On D, an error before PUSH_REG is sent fails that receive.
- A pass that keeps raising backs off: it waits 2 ms, doubling up to 1 s.
- `get_transfer_results` raises once the writer thread has exited.

## Details

Flow on P:

1. P's finished blocks wait in the writer for D's PUSH_REG.
2. A `get_new_notifs()` batch brings that PUSH_REG.
3. The writer pops the waiting blocks, and `_do_start_push_kv` raises (for example `NotImplementedError` for different cache-group layouts).
4. On main the pass-level `except` only logs it. The popped pair is lost with nothing recorded, and so is the rest of the batch (other PUSH_REGs, and notifs for the main thread such as heartbeats). With this change, step 4 records a send failure for that request and the batch continues.

- The helpers reuse existing failure paths: `_send_failures` and `_handle_failed_transfer` on P (as in `_xfer_blocks`), `_failed_recv_reqs` on D. P does not free early, since a WRITE posted before the error may still run. No new P-to-D message. The backoff waits on `_push_writer_stop`, so shutdown is not delayed. A wedged (alive but stuck) writer and restarting the writer are out of scope.
- Not a duplicate: no open PR isolates per-request errors in the writer, backs off, or checks that the writer is alive. #62055 reworks the same loop and keeps the pass-level `except`; it conflicts with this in that `except` and at the top of `get_transfer_results`, and on top of it this passes the push tests once the backoff wait sits outside its `_nixl_io_lock`. #57722 (a writer-loop error counter), #50754 and #59758 have small conflicts. I'll rebase on whichever lands first.
- Open questions: should a dead writer fail the engine (this draft) or fail only the pending requests and keep running? Is a 1 s backoff cap right?
