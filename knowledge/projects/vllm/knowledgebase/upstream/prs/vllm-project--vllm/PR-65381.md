# [Feature][HiSparse] Add backend hooks for private host allocation

[Upstream PR](https://github.com/vllm-project/vllm/pull/65381) · state: open · merged: False

## Original PR description

## Overview

Extend the existing HiSparse platform backend with private Host backing allocation and alignment hooks. This lets hardware plugins supply compatible CPU storage without replacing the common allocator.

Follow-up to #62592; Ascend consumer: vllm-project/vllm-ascend#19109. Draft for the submitter's interface review; device and model qualification remain pending.

## Claims

- Add `allocate_host_backing(size)` and `host_pool_alignment` to `HiSparseBackend`. Common code retains alignment, padded-range registration, and storage ownership.
- CUDA inherits the existing `torch.empty(..., dtype=torch.int8, device="cpu")` allocation and 4096-byte alignment, and keeps its existing CUDA registration/unregistration implementation.
- Shared mmap pools bypass the new hook. No kernels, stream/event ordering, KV layout, scheduler policy, or Tensor ABI callback changes are included.

## Validation

- Source-isolated CPU execution of the two new test bodies: **7 passed in 2.20 s**. The checks cover both the base and CUDA backend defaults, exact payload/registration sizes, 4 KiB/64 KiB alignment, shared storage ownership after dropping the original Tensor, and invalid storage rejection.
- The same source-isolated checks against base `0eb619dc521c1f1ed5e6ce23caf506ff652620fa`: **7 failed in 2.17 s** because the backend allocator/alignment hook is not used. This is not a full-package pytest result.
- Full-package collection of `tests/v1/kv_connector/unit/test_hisparse_connector.py -k private_host_backing` was attempted locally and stopped at missing `tblib` in `tests/conftest.py`; no full-package pass is claimed.
- Added `test_hisparse_private_host_pool_cuda_registration` to the existing sparse-MLA CUDA suite. It exercises real CUDA registration, a nonblocking Host-to-device copy, synchronization, exact byte comparison, and unregistration. **Not run on CUDA hardware yet.**
- Changed-file repository pre-commit checks passed, including pinned Ruff, formatting, mypy (Python 3.11), Markdown, test tethering, and API checks; `git diff --check` passed. Hooks for unchanged workflow/C++/shell/requirements files were skipped. The Dockerfile graph hook was also checked separately through Git Bash because Windows cannot directly execute its `/bin/bash` shebang. Pending before ready-for-review: full-package unit tests, real CUDA registration test, and integrated startup/model validation for this exact patch. No NPU validation, model-output equivalence, memory/performance gain, or completed human line-by-line review is claimed.

## Details

`allocate_pinned_host_pool` currently selects a fixed 4096-byte alignment and creates the CPU backing directly. A backend can customize registration but cannot choose storage appropriate for that registration without replacing the common function. The new hook supplies only unregistered backing; common code validates its CPU/int8/one-dimensional/contiguous/exact-size contract, takes aligned views, and registers the complete padded range once.

Duplicate-work review on 2026-11-03 found no open PR for `allocate_host_backing` or `host_pool_alignment`. #62592 already supplies the platform abstraction; this is an incremental allocator contract. The inspected ROCm #60358 changes device operations and Host pointer handling without this allocation hook. #63970 and #63289 concern shared-pool mapping/registration and do not supply the private-allocation contract.

AI assistance was used for implementation, source analysis, tests, and this description. The human submitter requested this draft for review; line-by-line review and device/model validation remain pending.
