# [Doc][Recipe] Ring-1T-FP8: replace removed use_inductor with backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/64587) · state: open · merged: False

## Original PR description



## Overview

The default FP8 command passes `--compilation-config '{"use_inductor": false}'`. `CompilationConfig` rejects `use_inductor` since v0.13.0, so the command fails at startup on current vLLM.

## Claims

- Replaces it with `{"backend": "eager"}`, the replacement named in the v0.11 deprecation notice (`use_inductor=False` means `backend="eager"`).
- Works from the recipe's 0.11.0 floor, so the floor is unchanged.

## Validation

```
CompilationConfig(use_inductor=False)   v0.11.0 → ok   main → ValidationError
CompilationConfig(backend="eager")      v0.11.0 → ok   main → ok
node scripts/validate-source.mjs --source vllm --dir recipes  (vllm-project/recipes) → valid
Ring-1T-FP8 generated JSON: use_inductor 14 → 0
```

## Details

Not served (FP8 needs ~1.2 TB of GPU memory); validated at config level only.
