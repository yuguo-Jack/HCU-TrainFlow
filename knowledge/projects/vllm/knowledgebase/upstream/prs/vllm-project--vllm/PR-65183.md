# [Bugfix][Transformers Backend] Respect use_mla=False when detecting MLA

[Upstream PR](https://github.com/vllm-project/vllm/pull/65183) · state: closed · merged: False

## Original PR description

## Overview

Fixes #65171. HunyuanOCR checkpoints from before the 2026-08-26 config update fail at engine startup with `RuntimeError: shape '[-1, 16, 192]' is invalid`. The Transformers backend sizes the attention heads at 192 while the model uses 128.

No other PR addresses this. The issue has no comments or linked PRs, and searches for `65171`, `HunyuanOCR` and `HunyuanVL head_dim` turned up no open PRs.

## Claims

- HunyuanOCR at revision `449e7d47` (the last revision whose config has `kv_lora_rank`) starts up and runs OCR correctly. On `main` it crashes during `profile_run`.
- A config that sets `use_mla: false` is no longer treated as MLA by the Transformers backend: neither when sizing attention heads in `_create_attention_instances`, nor in `ModelConfig.use_mla`.
- Configs without a `use_mla` key (e.g. DeepSeek V2/V3) are unchanged.

## Validation

## Details

**Root cause.** Older HunyuanOCR `config.json` revisions carry MLA fields (`kv_lora_rank=512`, `qk_nope_head_dim=128`, `qk_rope_head_dim=64`) together with `use_mla: false` and `head_dim: 128`. The model itself uses dense attention. With the default `model_impl`:

1. `ModelConfig.use_mla` is already False on `main`, so `_get_attn_cls` picks `Attention` without trying MLA.
2. `_create_attention_instances` treats any `kv_lora_rank` as MLA. For an MLA model that runs on full attention, it overwrites `head_size` with `qk_nope_head_dim + qk_rope_head_dim = 192`.
3. The HF attention module still produces 128-dim heads, so `query.view(-1, 16, 192)` fails in `profile_run`.

**Fix.** A shared `transformers_uses_mla()` helper in `vllm/transformers_utils/config.py` treats `kv_lora_rank` as MLA unless the config explicitly sets `use_mla=False`. A missing or `None` value keeps the existing behaviour.

- `_create_attention_instances` uses it. This is the change that fixes #65171.
- `ModelConfig.use_mla` uses it on the Transformers backend path, so the two checks can't disagree. That path is only taken when `using_transformers_backend()` is True, i.e. with `--model-impl transformers` for HunyuanOCR. There, `main` reports `use_mla=True` with 1 KV head and this PR reports `use_mla=False` with 8. End-to-end, HunyuanOCR with `--model-impl transformers` fails at engine startup with a bare `AssertionError` from EngineCore on both `main` and this PR, whichever `use_mla` value is picked, so that path is covered by the unit test only; I will open a separate issue once I have the full traceback.

`_create_attention_instances` can't read `model_config.use_mla` instead. When MLA fusion fails, `_get_attn_cls` sets `VLLM_MLA_DISABLE=1`, so `use_mla` turns False for exactly the real MLA models that still need the head_size override.
