# [Bugfix] Clean up async client sockets after event loop closure

[Upstream PR](https://github.com/vllm-project/vllm/pull/57757) · state: closed · merged: True

## Original PR description

## Purpose

Fix skipped async ZMQ socket cleanup when `AsyncLLM` shuts down after its event loop has closed. This PR routes closed loops to the existing direct-cleanup path. Live-loop behavior and inference are unchanged.

## Reproducer

Run this manual, CPU-only reproducer from the repository root. 

```bash
PYTHONWARNINGS=ignore .venv/bin/python - <<'PY'
import asyncio

import zmq
import zmq.asyncio

from vllm.v1.engine.core_client import BackgroundResources


loop = asyncio.new_event_loop()
task = loop.create_task(asyncio.sleep(0))
loop.run_until_complete(task)
loop.close()

with zmq.asyncio.Context() as ctx, ctx.socket(zmq.PULL) as output_socket:
    resources = BackgroundResources(
        ctx=ctx,
        output_socket=output_socket,
        output_queue_task=task,
    )
    print(f"loop_closed={loop.is_closed()}")
    print(f"socket_closed_before={output_socket.closed}")
    resources()
    print(f"socket_closed_after={output_socket.closed}")
PY
```

## Output on main / on branch

### Main

```text
loop_closed=True
socket_closed_before=False
socket_closed_after=False
```

The socket is still open after `BackgroundResources` runs, demonstrating that cleanup was skipped.

### This branch 

```text
loop_closed=True
socket_closed_before=False
socket_closed_after=True
```

The same cleanup call closes the socket after the event loop has closed.
