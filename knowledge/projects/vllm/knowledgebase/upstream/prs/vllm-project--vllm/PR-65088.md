# [Bugfix][Model] Fix Ling3 SwiGLU clamping

[Upstream PR](https://github.com/vllm-project/vllm/pull/65088) · state: open · merged: False

## Original PR description

## Overview

While investigating an accuracy issue during training–inference alignment for Ling RL, we found that routed experts applied the SwiGLU gate limit before SiLU, whereas the training/reference implementation applies it after SiLU. This mismatch can affect RL accuracy through inconsistent training and rollout computations, even though its impact is not obvious in standalone inference evaluations.

Use the existing `swiglustep` activation for Ling layers with a configured limit and forward that limit through the common MoE activation paths.

## Claims

- For limited Ling routed experts, compute `clamp(SiLU(gate), max=L) * clamp(up, -L, L)` instead of `SiLU(clamp(gate, max=L)) * clamp(up, -L, L)`.
- Honor the configured limit in both standard and masked `SWIGLUSTEP` activation paths.
- Keep unlimited Ling layers on `silu` and retain the default `SWIGLUSTEP` limit of `7.0` when no limit is supplied.
