# [NIXL] Drop unreachable producer-side notif counting in push mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/62210) · state: closed · merged: True

## Original PR description



## Overview

Remove the producer-side branch of `NixlPushConnectorWorker._get_new_notifs`, which no push-mode code path can reach. Split out of #61488 / #61580 as an independent simplification, as suggested in https://github.com/vllm-project/vllm/pull/61580#issuecomment-6237375565.

## Claims

- No behavior change for P or D in push mode: the removed branch only ran on a plain `"<req_id>:<n>"` notif arriving at P, which push mode never sends.
- `_get_new_notifs` now only counts consumer-side completion notifs and always returns an empty set; P keeps reporting finished sends from its WRITE handles in `get_transfer_results`.
- 26 insertions, 59 deletions.

## Validation

- `pytest tests/v1/kv_connector/unit/test_nixl_push_connector.py tests/v1/kv_connector/unit/test_nixl_heartbeat.py`: 103 passed.
- `pytest tests/v1/kv_connector/unit/test_nixl_connector.py`: 182 passed. The two `test_abort_timeout_on_prefiller` cases fail locally on main as well.
- With a tripwire in the removed branch, the push, heartbeat and NIXL connector unit tests pass without reaching it.
- On GB200, the tripwire was not reached in end-to-end push runs with TP1 → TP1, producer TP2 → consumer TP1 and producer TP1 → consumer TP2, and those runs met their expected outputs. These runs used the same `push_worker.py` change on the #61488 branch.

## Details

In push mode, D sends P only two kinds of notifs:
- `PUSH_REG`, consumed by the writer thread before notifs are forwarded to `_get_new_notifs`;
- `HB:`, handled at the top of `_get_new_notifs` before the counting.

Plain `"<req_id>:<n>"` notifs to P come from `_pending_recv_notifs`, which only `pull_worker.py` fills. P → D completion notifs are attached to the push WRITEs and are counted on D, which is the branch this PR keeps.

The removed code is the producer-side counting copied from pull mode, the `transfer_topo` assert it needed, and the counter cleanup for finished pushes in `get_transfer_results`. One edge case changes: on a `kv_both` instance where one request is both loading and saving, a completion notif for it is now counted as a load instead of a send. Push mode never sends such a notif to the producer side.

Not a duplicate: #55470 also edits `_get_new_notifs` (it adds a failed-WRITE notif path) but keeps the producer-side branch. Whichever merges second needs a small rebase.
