# [Bugfix][ROCm][MoRIIO] Release every prefill rank a READ holds

[Upstream PR](https://github.com/vllm-project/vllm/pull/62473) · state: open · merged: False

## Original PR description


## Overview

Fix three MoRIIO READ-mode bugs: prefill blocks left allocated after a fan-in read, a scrambled equal-TP read between different cache layouts, and a single-node xGMI crash in the flexible MLA mirror. Also add READ cases to the dummy-weight P/D E2E, and fix a port collision in that test. Follow-up to #61726. Split-head and Mamba READ across TP sizes is a separate PR stacked on this one.

## Claims

- **READ fan-in releases every prefill rank that holds the request.** Decode used to release only the rank it read from. With a larger prefill TP size, including the flexible MLA mirror (TP prefill + DP decode), the other prefill ranks kept the request's blocks until the `defer_timeout` reaper freed them: 60 s by default, logged as "Reaped N deferred sends".
- **Equal-TP READ between different cache layouts reads the right bytes.** Whole-block copies scrambled heads and tokens when prefill and decode lay them out differently. Such reads now move heads one by one. Matching layouts keep the same whole-block path.
- **Flexible MLA mirror on xGMI reads the fixed source.** The round-robin over prefill TP ranks spreads RDMA NIC load. On one node over xGMI it picked prefill ranks whose GPU MoRI cannot open a session to from a decode rank that sees one GPU ("MoRI could not open a session ... _tp1"). RDMA keeps the round-robin.

## Validation

- **Unit tests:** new `tests/v1/kv_connector/unit/test_moriio_read_tp.py`, 93 tests. Each decode rank runs the real READ path on real cache tensors, and a fake transport executes the posted reads. The tests check that decode ends up byte-exact and that each prefill rank is released exactly as many times as it waits for. They cover:
  - equal TP for every fixture model × 3 cache-layout pairs
  - MLA in every TP pair, and replicated GQA at TP2 ↔ TP4
  - abort and failure releases
  - the RDMA round-robin vs the xGMI fixed source
- **The tests catch the bugs:** releasing only one holder fails 16 tests, and always copying whole blocks fails 12.
- **Full MoRIIO unit suite:** 818 passed. Ruff is clean, and mypy reports no new errors.
- **GPU, MI355X, xGMI:**

| Case (dummy-weight P/D) | Result |
|---|---|
| Equal-TP READ vs direct serve: kimi_linear, qwen3_5_moe, qwen3_dense, qwen3_dense HMA_off, deepseek_v3 HMA_off, gemma3 HMA_off | distance 0.0 on every prompt (ROCm 10; kimi_linear and qwen3_dense also on ROCm 7.2) |
| READ negative control (corrupted prefill KV): kimi_linear, qwen3_dense | detected |
| READ deepseek_v3 MLA, prefill TP1 → decode TP2 and TP2 → TP1 | pass, exact external hits. TP2 → TP1 crashed on main. |

## Details

- **Release accounting:** `get_moriio_read_holder_tp_ranks` lists the prefill ranks holding a decode rank's share. Decode releases all of them on completion, failure and abort, so prefill's existing `get_moriio_expected_ack_count` is met in both directions.
- **READ hit count in the E2E:** a READ decode always computes the last prompt token itself, so it reports `len − 1` external hits per prompt.
- **Port collisions in the E2E:** every TP rank binds the configured MoRIIO handshake and notify port plus its rank offset, and vLLM scans upward from each server's `VLLM_PORT`. The test handed out single ports, so a TP > 1 server's later ranks could land on another server's ports (`ZMQError: Address already in use`). This also affected #61726's heterogeneous WRITE cases. The test now reserves blocks of free ports.
