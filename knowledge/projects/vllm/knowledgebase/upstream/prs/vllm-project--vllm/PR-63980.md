# [Bugfix] Treat a RuntimeError from importing Ray as Ray being unavailable

[Upstream PR](https://github.com/vllm-project/vllm/pull/63980) · state: open · merged: False

## Original PR description



## Overview

Treat a `RuntimeError` from `import ray` like a missing Ray, so `vllm serve` starts on AMD GPU nodes where Slurm sets only `ROCR_VISIBLE_DEVICES` and Ray is installed.

## Claims

- Fixes a startup crash of every `vllm serve` on such nodes, also with the multiprocessing backend.
- Requesting the Ray backend there still fails, with Ray's own message, via `assert_ray_available()`.

## Validation

On an MI250X node under Slurm (`ROCR_VISIBLE_DEVICES=0,...,7`, `HIP_VISIBLE_DEVICES` unset), `import ray` raises with Ray 2.54.0 and 2.59.0:

```
RuntimeError: Please use HIP_VISIBLE_DEVICES instead of ROCR_VISIBLE_DEVICES
```

`vllm serve` (v0.31.0 ROCm image + Ray 2.59.0) crashes while importing the CLI:

```
vllm/entrypoints/cli/serve.py → launchers/dp_supervisor.py → v1/engine/utils.py → v1/executor/ray_utils.py: import ray
RuntimeError: Please use HIP_VISIBLE_DEVICES instead of ROCR_VISIBLE_DEVICES
```

With this change it starts and serves (Qwen/Qwen3-0.6B, TP=8).

New `test_ray_import_runtime_error_means_ray_unavailable` in `tests/utils_/test_ray_utils.py` makes `import ray` raise that error in a subprocess and imports `vllm.entrypoints.cli.serve`:

```
pytest tests/utils_/test_ray_utils.py
# without this change: 1 failed (RuntimeError: Please use HIP_VISIBLE_DEVICES instead of ROCR_VISIBLE_DEVICES), 6 passed
# with this change: 7 passed
```

## Details

- Root cause: Ray's `AMDGPUAcceleratorManager` raises at import time on AMD GPU nodes when `ROCR_VISIBLE_DEVICES` is set without `HIP_VISIBLE_DEVICES` (it does not on nodes without AMD GPUs, so it does not show on login nodes or in CPU CI). vLLM imports Ray on every launch (`ray_utils` at module level, `is_ray_initialized()` while building the config) and only caught `ImportError`.
- The official ROCm image does not ship Ray, so it is affected only when Ray is installed (`pip install ray`, multi-node Ray setups, images that include Ray).
- Not a duplicate: no open PR or issue covers this.
