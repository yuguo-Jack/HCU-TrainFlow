# [CI/Build] Skip DeepEP low-latency tests on B200 until the NVSHMEM fix

[Upstream PR](https://github.com/vllm-project/vllm/pull/62908) · state: open · merged: False

## Original PR description

## Overview

Skip the DeepEP low-latency tests on B200 until the NVSHMEM bug in pytorch/test-infra#9101 is fixed. Both B200 jobs are `optional: true`.

## Claims

- `config-b200.txt`: the four `deepep-ll` entries are commented out.
- The B200 EPLB job runs only `deepep_high_throughput` (`SKIP_DEEPEP_LL=1`).
- Other entries, H100 and ROCm are unchanged, and the rest of each shard still runs.

## Validation

- On `main` over 60 days, these two jobs failed in 76 of 364 runs (about 21%; 4.5% to 42% by week, 11.5% and 4.5% in the last two). Of the 24 most recent failures, 19 show the NVSHMEM chain `ibv_modify_qp failed` → `ep_connect failed` → `nvshmem setup connections failed`, and each costs about 50 minutes. Examples: [daily 96139](https://buildkite.com/vllm/ci/builds/96139), [nightly 95338](https://buildkite.com/vllm/ci/builds/95338). Build 96292 (#55387) hit it in all three jobs, and retries passed.
- `config-b200.txt` parses to 9 configs with no `deepep-ll`. The EPLB backend choice was checked with and without the flag, and `shellcheck` is clean. The Buildkite jobs were not run.

## Details

Cause: an NVSHMEM bootstrap bug, probably fixed in 3.8.0, not a torch issue. This drops the B200 low-latency signal while it is in place; other tests in a failing shard still ran and passed in 96292. Alternatives: test NVSHMEM 3.8.0, or add an automatic retry.
