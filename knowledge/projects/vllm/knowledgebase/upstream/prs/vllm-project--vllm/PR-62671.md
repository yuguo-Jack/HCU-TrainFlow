# [Bugfix] Avoid mutating shared config class model_type across aliases

[Upstream PR](https://github.com/vllm-project/vllm/pull/62671) · state: open · merged: False

## Original PR description

## Overview

Fixes #62645. Loading a second config alias that shares one Hugging Face config class no longer changes a previously loaded config's serialized `model_type`.

## Claims

- `kimi_k2` and `deepseek_v32` (both `DeepseekV3Config`) keep their own serialized `model_type` no matter which alias is loaded second.
- A single alias still serializes as that alias.
- `hf_overrides` checkpoints whose on-disk `model_type` differs still resolve to the overridden config class for both names (`#39554`).

## Validation

Before the fix, `tests/transformers_utils/test_config_alias_model_type.py` failed:

- load `kimi_k2`, then `deepseek_v32`: the first config's `to_dict()` became `deepseek_v32`
- load `deepseek_v32`, then `kimi_k2`: the first config's `to_dict()` became `kimi_k2`
- load `kimi_k2` twice: the first config stayed `kimi_k2`, but `DeepseekV3Config.model_type` was rewritten

After the fix:

```sh
python -m pytest tests/transformers_utils/test_config_alias_model_type.py \
  tests/transformers_utils/test_hf_overrides_model_type.py -v
pre-commit run ruff-check --files vllm/transformers_utils/config.py \
  tests/transformers_utils/test_config_alias_model_type.py
pre-commit run ruff-format --files vllm/transformers_utils/config.py \
  tests/transformers_utils/test_config_alias_model_type.py
pre-commit run mypy --files vllm/transformers_utils/config.py \
  tests/transformers_utils/test_config_alias_model_type.py
```

The new test and `test_hf_overrides_model_type.py` passed. ruff and the mypy hook passed. No model eval: this does not change serving output or accuracy.

## Details

`PreTrainedConfig.to_dict()` saves `type(config).model_type`. `_register_config_class` assigned `model_type` on the shared class because `AutoConfig.register` requires that attribute to match the key. The next alias replaced the class attribute, so an existing instance serialized as the new alias even though its own `model_type` field was unchanged.

Registration now uses one cached subclass per alias when the class does not already declare that `model_type`. Classes that already declare it are registered unchanged. For an `hf_overrides` `model_type` that differs from the file on disk, both names still point at that same class: `model_type` is set only for the `AutoConfig.register` check and then restored.
