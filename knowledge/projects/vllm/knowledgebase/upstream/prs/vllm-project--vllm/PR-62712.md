# [ROCm][Perf][MiniMax-M3] MonoKernel decode for M3 MXFP4 on MI355X

[Upstream PR](https://github.com/vllm-project/vllm/pull/62712) · state: closed · merged: True

## Original PR description

### Summary
Adds an opt-in specialized decode path (`--monokernel`) for MiniMax-M3-MXFP4 on gfx950. During decode, layers 3–59 run their FFN half as one persistent FlyDSL launch:
- TP all-reduce, residual add and post-attention RMSNorm;
- the FP32 router with top-4 selection;
- the shared and routed BF16×MXFP4 experts;
- the final TP all-reduce.
Attention, the dense layers 0–2, prefill and mixed batches stay on the stock path.
- Follows the RFC #60904 / Kimi-K3 layout: `vllm/models/minimax_m3/amd/specialized_decode/`. There is one `plan()` per step, and layers are selected with `step.layer(i)`.
- Supports eager and FULL CUDA graphs, at 1–16 decode rows. Larger batches, PIECEWISE steps and prefill use the stock path.
- Startup refuses unsupported configs (default-deny), with every reason reported. Kernel faults fail-stop on every rank, and no token is returned from a failed step.
- Requirements: TP4 on gfx950, `--kv-cache-dtype fp8`, `--attention-config '{"indexer_kv_dtype":"fp8"}'`, `--moe-backend aiter`, `VLLM_ROCM_SHUFFLE_KV_CACHE_LAYOUT=1`, and `VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1`.
- Temporary dependency: imports the DeepSeek-V4.1 `mono.common` FlyDSL helpers (peer memory, sync), to move once a common AMD runtime lands.
### Results (MI355X, TP4, FULL_DECODE_ONLY graphs)
Baseline is the recommended serve command. `--monokernel` adds the flags it requires.
**Random 1024 in / 1024 out**
| Concurrency | Baseline TPOT (ms) | `--monokernel` TPOT (ms) | TPOT | Output tok/s |
|---|---|---|---|---|
| 1 | 5.12 | 4.27 | **−16.6%** | 192 → 230 (**+19.6%**) |
| 2 | 5.54 | 4.85 | **−12.5%** | 355 → 403 (+13.4%) |
| 4 | 6.23 | 5.69 | **−8.7%** | 628 → 687 (+9.3%) |
| 8 | 7.46 | 6.88 | **−7.8%** | 1054 → 1136 (+7.8%) |
| 16 | 8.89 | 8.87 | parity | 1755 → 1751 |
| 32 (stock fallback) | 11.51 | 11.54 | parity | 2684 → 2708 |

**Long context, 8192 in / 1024 out:** TPOT −14.9% at concurrency 1 (5.25 → 4.47 ms), −9.0% at 4 (6.42 → 5.84 ms), and −3.4% at 16 (10.12 → 9.78 ms).
**MT-Bench (chat, greedy, ≤1024 output tokens):** TPOT −17.0% at concurrency 1 (5.00 → 4.15 ms; 196 → 235 tok/s), −8.6% at 4 (6.30 → 5.76 ms), and parity at 16.
Kernel-only effect, against the same server with identical flags and no `--monokernel`: TPOT −19.1% at concurrency 1, −14.3% at 2, −11.1% at 4, −8.8% at 8, and parity at 16.

### Accuracy (GSM8K 5-shot, full 1319, flexible-extract)
| Config | Score |
|---|---|
| Same flags, no `--monokernel` | 0.8969 |
| `--monokernel` | 0.9052 (paired +0.83 pp, 95% CI [−0.83, +2.50], McNemar p=0.37) |

### Commands
Baseline:
```bash
VLLM_ROCM_USE_AITER=1 VLLM_USE_BREAKABLE_CUDAGRAPH=0 VLLM_ROCM_USE_AITER_MOE=1 \
VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1 \
vllm serve amd/MiniMax-M3-MXFP4 --block-size 128 --trust-remote-code \
  --compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY"}' \
  --mm-encoder-tp-mode data --mm-encoder-attn-backend ROCM_AITER_FA \
  --tensor-parallel-size 4 --attention-backend TRITON_ATTN \
  --tool-call-parser minimax_m3 --enable-auto-tool-choice --reasoning-parser minimax_m3 \
  --max-model-len 10240
```
`--monokernel`, which is the baseline plus:
```bash
VLLM_ROCM_SHUFFLE_KV_CACHE_LAYOUT=1 ... \
  --kv-cache-dtype fp8 --attention-config '{"indexer_kv_dtype":"fp8"}' \
  --moe-backend aiter --monokernel
```
Benchmarks. Each point is preceded by a discarded warmup with a different seed. `--num-prompts` is max(32, 4×concurrency) for random and max(16, 4×concurrency) for MT-Bench.
```bash
# random
vllm bench serve --model amd/MiniMax-M3-MXFP4 --trust-remote-code --backend vllm \
  --dataset-name random --random-input-len 1024 --random-output-len 1024 --ignore-eos \
  --num-prompts 32 --max-concurrency 1 --seed 1234 \
  --percentile-metrics ttft,tpot,itl,e2el --metric-percentiles 50,90,99
# MT-Bench
vllm bench serve --model amd/MiniMax-M3-MXFP4 --trust-remote-code \
  --backend openai-chat --endpoint /v1/chat/completions \
  --dataset-name hf --dataset-path philschmid/mt-bench --skip-chat-template \
  --hf-output-len 1024 --temperature 0 --num-prompts 16 --max-concurrency 1 --seed 1234
# accuracy
lm_eval --model local-completions \
  --model_args base_url=http://127.0.0.1:8000/v1/completions,model=amd/MiniMax-M3-MXFP4,num_concurrent=4,max_retries=3,tokenized_requests=False \
  --tasks gsm8k --num_fewshot 5 --seed 1234
```
### Limitations / follow-ups
- Spec decoding is refused in this PR. The stock path is about 1.6× faster than `--monokernel` 
- TP4 only. TP2 and TP8 are follow-ups.
- At 16 rows the kernel is at parity
