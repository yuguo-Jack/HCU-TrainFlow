# [LoRA][Perf] Skip inactive adapters per layer in eager mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/58277) · state: open · merged: False

## Original PR description

## Purpose

A batch-wide no-LoRA check cannot skip work when a request uses an adapter but
the current layer has no weights for that adapter. For example, a q_proj/v_proj
adapter still carries a valid LoRA ID through o_proj and MLP layers.

This matters for heterogeneous serving. If resident adapters target q/v,
q/k/v/o, and gate/up/down respectively, the static union covers every module,
but a request using only the q/v adapter has no useful LoRA work in most layers.

This PR:

- tracks which adapter slots are populated for each LoRA layer;
- derives active token and sampler slot sets from the existing CPU mapping;
- bypasses dense, embedding, and logits LoRA work in eager mode when the active
  and populated slot sets are disjoint;
- preserves the existing path under torch.compile and graph modes, without any
  device-to-host synchronization; and
- conservatively keeps a packed wrapper active when any packed slice is
  populated.

MoE and fully-sharded override paths are unchanged.

This does not duplicate #47951, which handles only batches with no active LoRA.
It is also materially different from #48887: that PR's host-level decision uses
the static union of all loaded adapters and explicitly cannot skip a layer when
heterogeneous resident adapters collectively cover all modules. This PR
intersects the current batch's active slots with the current layer's populated
slots.

AI assistance was used for investigation, implementation, testing, and
benchmark analysis. The submitting author reviewed the changes and remains
responsible for them.
