# [Bugfix][MoE] Fix online-FP8 NaN from skipped padding slots in TritonExperts

[Upstream PR](https://github.com/vllm-project/vllm/pull/61708) · state: open · merged: False

## Original PR description



## Overview

Fixes #57017. With `VLLM_MOE_SKIP_PADDING` (the default), CUDA-graph padding tokens are routed to expert −1, so
`TritonExperts`' first GEMM never writes their workspace rows. The dynamic per-tensor a2 scale is taken over all rows,
so a stale inf there makes the scale inf and every request in the batch returns NaN. This PR zeroes the unrouted rows
before the global a2 quant, and makes `moe_sum` skip negative-id slots so that a padding token's own row is zero.

**Why a separate PR:**
- #57094 (linked to #57017) changes the Triton MLA decode kernel. With it applied, the issue's reproducer still fails on
  0.30.0 and 0.31.0 (5/5 NaN rounds at K = 3, 4 and 8). The inf comes from the MoE workspace, and the a2 amax ignores
  NaN but not inf [code reading]. This PR alone fixes the reproducer; every "after" number below is without #57094.
- #58051 (merged) and #54083 (draft) made the reduction pad-aware under EP only. Padding slots without an `expert_map`,
  and the a2 scale, are not covered.

## Claims

- No NaN logits once ≥3 sequences decode together with online FP8 MoE under CUDA graphs (#57017). Verified on an RTX
  5090 with DeepSeek-V2-Lite-Chat, on 0.31.0 and on main (nightly `2308b6f00`).
- GSM8K on main: 0.004 / 0.001 without this PR (every request has NaN logits), 0.638 / 0.632 with it, 0.635 / 0.625
  with `VLLM_MOE_SKIP_PADDING=0` (bug-free reference).
- Behavior changes only for `TritonExperts` with a dynamic per-tensor a2 scale, plus the `moe_sum` dispatch.

## Details

**Root cause.**
1. `prepare_inputs` marks padded tokens, and the router sends their top-k slots to −1.
2. `moe_align_block_size` drops negative ids, so GEMM1 never writes those rows of `intermediate_cache1`. SiLU-and-mul
   still runs over all rows into `intermediate_cache2`.
3. `moe_kernel_quantize_input` takes one dynamic amax over all `num_tokens * top_k` rows.
4. On FULL-graph decode steps with a padded slot, those rows held inf. A probe found inf only in unrouted rows, never in
   routed ones. The a2 scale became inf and the batch went NaN.

What writes the inf under FULL-graph replay is not identified; the fix does not depend on it. The EP path already
guards this hazard (`a2_scale_is_global`, #58051). Padding is not covered, because the alignment drops negative ids
whatever `ignore_invalid_experts` says.

**Hunk 1** masks the unrouted rows only when the a2 scale is global. It is one broadcast `masked_fill_`, with no host
sync and no data-dependent shape, so it is CUDA-graph safe.

**Hunk 2** dispatches to the pad-aware `moe_sum` whenever `topk_ids` is given, so a padding token's row is zero instead
of a sum of stale rows. A non-finite padding row would otherwise reach the next layer, where a per-tensor quant whose
amax propagates NaN could spread it to the batch (shown by injection, not seen in serving).

**Alternatives.** `VLLM_MOE_SKIP_PADDING=0` avoids the NaN, but it routes the padding token for real. The a2 scale on
padded steps then peaks at 24–25 per round, against about 0.2 with this PR. If the prefill cost matters, the mask can
be skipped on unpadded steps or folded into the activation kernel.
