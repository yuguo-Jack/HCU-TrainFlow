# [Bugfix][NIXL] Stop clearing finished_sending for replicated-PCP producer ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/59325) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

With prefill context parallelism (PCP) and a replicated KV cache (DCP=1), the prefill instance (P) never frees a request's blocks after the decode instance (D) has read them, in both pull and push NIXL mode. PCP ranks > 0 report a synthetic completion for every request, and two paths drop those reports.

## Claims

- Both modes: `NixlBaseConnector.get_transfer_results`, which `NixlPushConnector` inherits, no longer clears `finished_sending` on replicated-PCP ranks > 0, so `KVOutputAggregator` sees all `world_size` reports and frees the request.
- Push mode: `NixlPushConnectorWorker.start_load_kv` also records the synthetic completion on those ranks, as the pull worker does; before, it returned without recording one.
- DCP-sharded PCP and PCP=1 are unchanged.

VLLM_TARGET_DEVICE=cpu python -m pytest tests/v1/kv_connector/unit/test_nixl_connector.py tests/v1/kv_connector/unit/test_nixl_push_connector.py -q

On this branch (Linux CPU): `-k pcp` 12 passed. The two files: 290 passed, 2 failed. The 2 are `test_abort_timeout_on_prefiller[ray]` and `[None]`, which start a real engine; they fail the same way on main (8321d1119b: 288 passed, 2 failed).

`test_replicated_pcp_producer_send_aggregation_completes`, in both files, builds connectors for PCP ranks 0 and 1 of a replicated producer and feeds both ranks' `get_transfer_results` into `KVOutputAggregator(world_size=2)`. Rank 0 completes the way it does in that mode: in pull mode D's read notification arrives through the NIXL wrapper, and in push mode rank 0's WRITE handle reports `DONE`. The request must come out in `finished_sending`. With main's `connector.py`, `push_worker.py` and `base_worker.py`, both fail:

```
E       AssertionError: assert None == {'req'}
```

`test_noncanonical_pcp_rank_only_pushes_distinct_shards` also checks that a replicated push rank > 0 records the synthetic completion.

CI: these tests don't run in CI today. The GPU "V1 KV Connectors" step is disabled on main, and the CPU step runs only `cpu_test`-marked tests. I can mark the PCP tests `cpu_test` if you'd like CI to run them.

End to end, ibrahimnd2000 [ran the pull-mode fix](https://github.com/vllm-project/vllm/pull/59325#issuecomment-6034820906) on 8x B300 with PCP8. Without it, prefill KV usage stuck at 91-98%; with it, 48/48 ~188k-token prompts completed and KV usage returned to 0.0%. That run used this PR's first commit; the pull change has since gained only a comment. Push mode is unit-tested only. Model outputs are unaffected, so no evals.

## Details

Replicated PCP (DCP=1), step by step:

1. P's scheduler asks every worker to send request R (`reqs_to_send`).
2. Only PCP rank 0 holds the KV that D reads. In pull mode D reads from rank 0 and notifies only rank 0; in push mode rank 0 writes to D and sees its WRITE handles finish.
3. Ranks > 0 report R as sent at once: a synthetic completion, since #53903.
4. `KVOutputAggregator` frees R's blocks on P only after all `world_size` workers report R.
5. Before this PR, the reports from ranks > 0 were lost, so step 4 never completed and P's KV usage only grew:
   - `get_transfer_results`, which both modes share and both model runners now call instead of `get_finished`, cleared `finished_sending` on those ranks (#53903 removed that clear from `get_finished`, and #53781 brought it back in the new method);
   - in push mode, `start_load_kv` also returned early on those ranks without recording the completion.

The alternative is to keep the clear and have `get_finished_count()` return `world_size // pcp_size`. That also changes how receive completions are counted, so I went with the smaller change. Short comments state the contract where P reports completions and where a peer's PCP layout is checked (`_validate_remote_parallel_config`).

Not a duplicate: no other open PR changes `get_transfer_results` or the replicated-PCP branch of the push worker. #61746 (PCP prefill with NIXL P/D for DSv4.1) is stacked on this PR and carries its first commit. #59071 and #45340 change other parts of the NIXL PCP code.

I also checked the aggregation with the real `KVOutputAggregator(expected_finished_count=8)`. Ranks 1–7 report first and the request stays pending with 1 report outstanding. Rank 0 reports and it's added to `finished_sending`.
