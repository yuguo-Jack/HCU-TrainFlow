# [Core] Fix transitional step bug

[Upstream PR](https://github.com/vllm-project/vllm/pull/37922) · state: closed · merged: False

## Original PR description



## Purpose
This PR fixes a bug in the transitional step when speculative decoding is enabled.
The issue is that when structured output is enabled, draft tokens are not validated during reasoning until the end of reasoning is detected, which may lead to them being incorrectly accepted. This PR proposes dropping all draft tokens once the end of reasoning is detected during the transitional step.

## Test Plan
```

from vllm import LLM, SamplingParams
from vllm.sampling_params import StructuredOutputsParams

speculative_config = {
    "model": "RedHatAI/gpt-oss-20b-speculator.eagle3",
    "method": "eagle3",
    "num_speculative_tokens": 3,
}

structured_outputs_config = {
    "reasoning_parser": "openai_gptoss",
}

schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "age": {"type": "integer"},
        "address": {
            "type": "object",
            "properties": {
                "city": {"type": "string"},
                "zip": {"type": "string"},
            },
            "required": ["city", "zip"],
        },
    },
    "required": ["name", "age", "address"],
}

llm = LLM(
    model="openai/gpt-oss-20b",
    trust_remote_code=True,
    enforce_eager=True,
    gpu_memory_utilization=0.92,
    tensor_parallel_size=1,
    max_model_len=16384,
    max_num_seqs=32,
    seed=42,
    structured_outputs_config=structured_outputs_config,
    speculative_config=speculative_config,
)

sampling_params = SamplingParams(
    max_tokens=1024,
    temperature=0.0,
    structured_outputs=StructuredOutputsParams(json=schema),
)

messages = [
    {
        "role": "user",
        "content": (
            "She is 'Alice', age 30, she lives 'NYC' and zip '10001'."
        )
    },
]

outputs = llm.chat(messages, sampling_params=sampling_params)
content = outputs[0].outputs[0].text
print(content)

```

## Code Review

This pull request introduces a fix for a bug related to speculative decoding and structured outputs, where draft tokens were not being correctly validated. The core of the change is to detect the end of a reasoning phase within draft tokens and truncate them accordingly. This is achieved by adding new methods (`reasoning_end_index`, `reasoning_end_delta_index`) to the `ReasoningParser` interface and implementing them across all parsers. While the overall approach is sound, I've identified a critical issue in the new API contract that leads to incorrect behavior for models with multi-token reasoning-end markers.

File: `vllm/reasoning/abs_reasoning_parsers.py` · line None

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

The docstring for `reasoning_end_index` specifies that it should return the index of the *last* token of the reasoning-end marker. However, the scheduler uses this index to slice draft tokens (`spec_token_ids[:spec_token_end_index]`), implying it expects the index of the *first* token of the marker to correctly truncate the sequence. This discrepancy can lead to incorrect behavior, especially for parsers with multi-token end markers like `GptOssReasoningParser`, where only part of the marker would be truncated.

To fix this, the contract should be changed to return the index of the **first** token of the marker.

```suggestion
        Returns the index of the first token in the reasoning-end marker, or
```
