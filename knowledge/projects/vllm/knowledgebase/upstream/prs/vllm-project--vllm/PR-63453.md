# [CI][ROCm] Take MoRIIO P/D test port blocks from below the ephemeral range

[Upstream PR](https://github.com/vllm-project/vllm/pull/63453) · state: closed · merged: True

## Original PR description

- `test_write_dummy_e2e_rocm.py`: `_open_port_block` picks its block below the kernel's ephemeral range instead of starting from `get_open_port()`

The MoRIIO dummy-weight P/D test hands each server handshake and notify ports that MoRIIO only binds, plus one port per TP rank, after the model loads. #62473 already stopped the test from handing the same port to two of its own servers. But the blocks still started at `get_open_port()`, i.e. inside the ephemeral range, and a released port there can go to any other `bind(0)` listener the servers start in the meantime (RCCL, gloo, ZMQ). The listener thread then dies with `Address already in use`, e.g. a TP1 decode server's notify port in [amd-ci build 15267](https://buildkite.com/vllm/amd-ci/builds/15267/table?jid=01a167fe-b072-4523-b8b6-522a7cfa0163&tab=output) and a handshake port in [build 96960](https://buildkite.com/vllm/ci/builds/96960/list?jid=01a16a64-0c77-44f1-bcd6-4c5ade40c544&tab=output). The race has been there since the test was added in #60544. `bind(0)` and `connect()` never hand out ports below `/proc/sys/net/ipv4/ip_local_port_range`, so taking the blocks from there removes it. #60743 is complementary: it makes MoRIIO fail startup loudly when the bind fails.

Locally, a released `bind(0)` port came back to a later `bind(0)` listener in 26 of 5000 trials with 32 listeners, while 200,000 `bind(0)` calls never returned a port below 32768. The new `_open_port_block`, called from 8 threads, gave 400 disjoint blocks of 8, all below 32768 and none containing any of 614 ports held by another process.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
