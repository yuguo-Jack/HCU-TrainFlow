# [Bugfix][KV Offload][P2P] Settle buffered terminal messages after disconnect

[Upstream PR](https://github.com/vllm-project/vllm/pull/64299) · state: closed · merged: True

## Original PR description

## Overview

A poll can receive both a disconnect and the terminal confirmation for a completed transfer. Dropping every message once the connection is dead loses that confirmation and reports the completed load as a failure.

Extracts **B** from #61667 as [requested in review](https://github.com/vllm-project/vllm/pull/61667#pullrequestreview-5651552184). Refs #61532.

## Claims

- Validated TransferDone and AbortAck messages already buffered during disconnect settle their matching load.
- Work-starting traffic is still dropped after disconnect, and malformed terminals cannot settle a load.

## Details

The dead-connection dispatch guard accepts buffered terminals only after peer Disconnect or socket-monitor death. Local protocol errors, repeated dispatch errors, handshake/lookup deadlines, send errors and abort-ack timeouts disable this exception. Terminal messages still pass their existing validation and match by request ID and round. Work-starting messages retain the previous guard. A malformed terminal also disables subsequent terminals in the same batch, even when a peer disconnect was observed first. AbortAck settles the deferred release established by #64256 without producing a second failed outcome. The data-plane teardown and slot-release contract are unchanged.

Is the trust edge case here intended? The guard now accepts terminals whatever the cause of death, including deaths we declared ourselves. Example: a peer sends a malformed message, `_protocol_error` marks the session dead, and a `TransferDone(success=True)` later in the same batch is now accepted as a successful load from a peer we just judged to be misbehaving. The same applies after our own lookup-timeout or abort-ack-timeout disconnects.

For the race this PR targets (peer `Disconnect` / socket monitor), accepting the buffered completion makes sense. If trusting a peer we already faulted isn't intended, one option is to exempt terminals only when the death came from the peer side (`DisconnectMsg` or the monitor), not from our own protocol-error or timeout verdicts. If it is intended, a short comment explaining why would help.
