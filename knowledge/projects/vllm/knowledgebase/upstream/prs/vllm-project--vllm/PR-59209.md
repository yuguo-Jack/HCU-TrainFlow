# [Hisparse] Support HiSparse for QSA 

[Upstream PR](https://github.com/vllm-project/vllm/pull/59209) · state: open · merged: False

## Original PR description

## Purpose

Support HiSparse for single-engine Qwen3.8-Flash QSA, whose full K/V heads differ from sparse MLA geometry. QSA can read selected history after its GPU pages are reclaimed, using the existing resident/hot/host policy.

The indexer's selection budget, logical positions and valid counts are preserved. Indexer caches, raw-key rings and recurrent state stay on GPU; no additional attention approximation is introduced.

## Changes

- Add full-row QSA geometry, BLNHC layout, TP ownership and host accounting.
- Connect writes and selected reads to residency/refill, including nonresident prefill and independent BF16/FP8 main and indexer formats.
- Preserve MTP selection reuse with stable selected-K/V storage and a private padding request map for native FULL replay and async execution.
- Preserve writable ownership across partial prefix hits, recompute, cancellation and cleanup.

NIXL/P-D and DCP are outside this PR.

## Usage

Initial eager TP2 example with a compatible checkpoint:

```bash
VLLM_USE_V2_MODEL_RUNNER=1 .venv/bin/python -m vllm.entrypoints.cli.main serve "$QSA_MODEL" \
  --tensor-parallel-size 2 --dtype bfloat16 --kv-cache-dtype bfloat16 \
  --attention-config '{"indexer_kv_dtype":"bf16","hisparse_config":{}}' \
  --enforce-eager --no-async-scheduling \
  --no-enable-prefix-caching --no-enable-chunked-prefill \
  --max-model-len 8192 --max-num-batched-tokens 8192 \
  --kv-transfer-config '{"kv_connector":"HiSparseConnector","kv_role":"kv_both","kv_connector_extra_config":{"host_pool_gib":8}}'
```

Keep the hybrid cache manager enabled. Host capacity is logical per DP replica; physical allocation depends on TP ownership/alignment. 

## Tests

```bash
.venv/bin/python -m pytest -q tests/models/qwen4_exp/test_qsa_reference.py
.venv/bin/python -m pytest -q tests/v1/core/test_prefix_caching.py \
  tests/v1/core/test_kv_cache_utils.py tests/v1/worker/test_attn_utils.py
```

Coverage includes TP ownership, BF16/FP8 main and indexer formats, refill after page reuse, MTP selection reuse, CUDA graph replay, prefix reuse and cleanup. Targeted regressions, lint and mypy passed. A three-request startup check with TP2, MTP3, FULL_DECODE_ONLY and async scheduling passed, followed by graceful shutdown. The latest main synchronization passed 65 targeted CPU regression cases, lint and mypy. GPU startup and model tests were not rerun after this synchronization.

**GSM8K: 197/200 with HiSparse off and 197/200 on**, with no question-level gains or losses. This 200-question subset includes one HiSparse-on response that reached the 4096-token limit and remained scored incorrect.

**Low-concurrency overhead remains unresolved.** Slowdowns occur without observed hot misses/H2D. The enabled path still performs location resolution, gather launches, index copies, stream ordering and eager host mirroring. In a separate single-run, fixed-work C32 comparison, disabling mirroring improved throughput by 2.14% but remained 16.59% below off; a BMM variant also changed, so the gap cannot be attributed entirely to mirroring or refill.
