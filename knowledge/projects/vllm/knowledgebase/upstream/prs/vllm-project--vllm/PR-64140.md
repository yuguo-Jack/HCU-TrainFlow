# [Bugfix][KV Offload] Fix packed Mamba CPU reload addressing

[Upstream PR](https://github.com/vllm-project/vllm/pull/64140) · state: open · merged: False

## Original PR description

## Overview

Fix incorrect Mamba state restoration after CPU offload with packed cache layouts.
Use the tensor's physical block stride when registering cache views, addressing the Mamba layout subtask of #63718.

## Claims

- Restore packed Mamba states through the existing whole-row transfer path, without changing CPU allocation sizing or adding synchronization.
- Add exact-byte roundtrip coverage and a real Mamba-130M CPU reload regression that verifies completed transfers, cache hits, generated tokens, and log probabilities.
- Run the regression in the active KV Offload CI job and document the tested support boundary.

## Details

Packed Mamba caches interleave layers within each physical block. For Mamba-130M, one layer's page is 116,736 bytes but the physical block stride is 2,801,664 bytes. Registration previously used the page size as the block stride, so transfers addressed the wrong state. Reading `ref.stride(0) * elem_size` selects the existing whole-row path, matching the calculation already used for attention.

The engine regression starts with zero cached tokens, completes CPU stores, resets GPU prefix residency, and replays the same 65-token prompt. It verifies a 64-token cache hit and a completed CPU load before comparing outputs. Greedy tokens alone matched even before the fix; log probabilities expose the corruption. The byte test also checks padding and untouched blocks.

The compact CI dependency list uses `vllm/`, `tests/v1/`, and the existing lmeval test path. This preserves existing triggers and includes connector-only changes, at the cost of running the KV Offload job for more source changes. Other jobs retain their existing dependency filters.

Whole-row transfers include padding when present. The committed model regression is CUDA-only and documents the TP=1 Mamba1 FP32 BLHNC slice; broader local checks do not establish support for every Mamba family, hybrid, canonical offload, or secondary tier. No performance improvement is claimed.

Duplicate-work checks found no matching Mamba registration-stride fix. #63747 addresses CPU canonical-option validation, #62479 addresses prefill handoffs, and #59265 addresses packed-layout selection. This change fixes addressing after a packed layout has already been selected.
