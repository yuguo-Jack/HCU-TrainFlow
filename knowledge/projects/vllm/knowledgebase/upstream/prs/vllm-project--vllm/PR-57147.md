# [Frontend][Responses] Reject namespace tool names that exceed the input budget

[Upstream PR](https://github.com/vllm-project/vllm/pull/57147) · state: open · merged: False

## Original PR description

Split out from #51892 at a maintainer's request.

A Responses request can define a namespace tool with a very long name and many nested functions. When those are flattened into `<namespace>__<function>` names, the long namespace is copied into every one — a ~464 KiB request can grow renderer memory by ~272 MiB before the model runs, with nothing to stop it.

This adds up the projected length of the flattened names before building them. If it's larger than what the model can accept as input (`max_input_tokens × max_chars_per_token`), the request is rejected with a 400 that reports the projected and allowed sizes. Harmony requests are unchanged. Test: `tests/entrypoints/openai/responses/test_namespace_tool_budget.py` (4 failing → 5 passing).

Credit: @KernelClint (Clinton Thomas) and @dhalf (Lucas Bourtoule), Patch the Planet (Trail of Bits + OpenAI); found with GPT-5.5-Cyber. All commits are DCO signed-off.
