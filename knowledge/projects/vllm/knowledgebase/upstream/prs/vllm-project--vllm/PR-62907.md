# [CI][ROCm][MoE] Add MXFP4 SWIGLUOAI_UNINTERLEAVE/SITU test coverage on MI355

[Upstream PR](https://github.com/vllm-project/vllm/pull/62907) · state: closed · merged: True

## Original PR description

## Purpose

Implements item 2b from the progress tracker in #54966: add SITU / SWIGLUOAI_UNINTERLEAVE modular-kernel test coverage for MXFP4, building on the existing W4A16/W4A4 MXFP4 coverage. Also enables these (and the rest of `test_modular_kernel_combinations.py`'s AITER-gated cases) on MI355 CI, which was previously silently no-op skipping them.

No open PR duplicates this (checked `54966 in:body` and SITU/SWIGLUOAI_UNINTERLEAVE keyword searches against open PRs).

## Changes

- `tests/kernels/moe/modular_kernel_tools/common.py`: thread `activation_situ_beta`/`activation_situ_linear_beta` and `swiglu_limit`/`swiglu_alpha`/`swiglu_beta` through `Config`, `torch_experts()`, and `FusedMoEConfig` construction, so the reference and modular-kernel paths use matching activation parameters (MiniMax-M3 convention for SWIGLUOAI_UNINTERLEAVE, Kimi-K3 convention for SITU). Generalized the mxfp4 reference-impl assert to accept both SWIGLUOAI and SWIGLUOAI_UNINTERLEAVE.
- `tests/kernels/utils.py`: extend `torch_experts()` to accept and forward the same activation parameters to the custom-op constructor.
- `tests/kernels/moe/test_modular_kernel_combinations.py`:
  - Generalize the W4A16 MXFP4 SWIGLUOAI smoke-test carve-out in `is_nyi_config()`/`rank_worker()` to also cover SWIGLUOAI_UNINTERLEAVE, since AITER forces `gate_mode=INTERLEAVE` for any W4A16 MXFP4 call regardless of activation.
  - Extend `MK_ACTIVATIONS` to include `SWIGLUOAI_UNINTERLEAVE` and `SITU`.
  - Mark SITU as NYI unconditionally: the installed AITER build's W4A4 MXFP4 kernel codegen (`gen_instances.py`) does not accept the `situv2` activation, so the kernel build fails before numerics can be compared. SITU is kept in `MK_ACTIVATIONS` so coverage turns on automatically once AITER's codegen catches up.
  - Skip `test_aiter_moe_padding_matrix`'s 6 `{none,hidden} x {fp8_channel_token,fp8_tensor_tensor,fp8_tensor_token}` cases: AITER v0.1.26's `ck_moe_stage2` no longer supports this raw (unpadded) `intermediate_size`, a regression vs v0.1.25 unrelated to this PR (root-caused below).
- `.buildkite/test-amd.yaml`: run `test_modular_kernel_combinations.py` on `(MI355 DPX) MoE Kernels Shard %N` with `VLLM_ROCM_USE_AITER=1`/`VLLM_ROCM_USE_AITER_MOE=1`, mirroring the MI300 step. Without this, `VLLM_ROCM_USE_AITER` defaults to `False` and every `@require_aiter_moe` case in this file silently no-ops on MI355 today — confirmed via a real `vllm/amd-ci` build where this file's AITER-gated cases showed as `SKIPPED` rather than collected/run.

## Validation

This environment's installed AITER (0.1.24.post1) predated what `main` now requires (`topk_gating(num_shared_experts=...)`). Rebuilt/installed AITER v0.1.26 (the version #62486 already bumped the ROCm Docker images to) on an MI355X (gfx950):

```bash
export VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_MOE=1
pytest tests/kernels/moe/test_modular_kernel_combinations.py::test_modular_kernel_combinations_singlegpu -k "SWIGLUOAI_UNINTERLEAVE and Aiter" -v   # 1 passed
pytest tests/kernels/moe/test_modular_kernel_combinations.py::test_modular_kernel_combinations_singlegpu -k "MoEActivation.SITU" -v                 # 0 collected (NYI-gated, as intended)
pytest tests/kernels/moe/test_modular_kernel_combinations.py -v     #time: 593.18s (≈9m53s)  # 45 passed, 39 skipped (33 multigpu + 6 new padding-matrix skips), 0 failed
```

Root-caused the `ck_moe_stage2` GEMM-shape regression by diffing AITER's `topk_gating`/`gen_instances.py` across v0.1.24.post1 → v0.1.26 and reproducing the failure on a freshly rebuilt v0.1.26 wheel; it's the same class of behavior change #62486 found and fixed in a different test file, just not covering this one.

For the `.buildkite/test-amd.yaml` change: pulled a real `vllm/amd-ci` build ([#15056](https://buildkite.com/vllm/amd-ci/builds/15056), triggered on #62486) and confirmed `(MI355 DPX) MoE Kernels Shard %N` already executes on real gfx950 hardware and passes, but every `@require_aiter_moe` case in this file shows `SKIPPED` there today (missing env vars), not run — so the new SITU/SWIGLUOAI_UNINTERLEAVE coverage would otherwise never actually execute in CI.

`pre-commit run --files` on all 4 touched files is clean.

Related: #54966
