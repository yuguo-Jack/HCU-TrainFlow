# [Bugfix][ROCm] Keep the AITER GDN decode fast path off for the DS conv-state layout

[Upstream PR](https://github.com/vllm-project/vllm/pull/63558) · state: closed · merged: True

## Original PR description

- `qwen_gdn_linear_attn.py`: take the AITER GDN decode fast path only when the conv state is not dim-first (`VLLM_SSM_CONV_STATE_LAYOUT=DS`)
- `test_gdn_rocm_layout_dispatch.py`: check that a DS conv state routes decode to the generic path

`:amd: (MI300) Hybrid SSM NixlConnector PD accuracy` fails on every weekly AITER-on build ([14875](https://buildkite.com/vllm/amd-ci/builds/14875), [15350](https://buildkite.com/vllm/amd-ci/builds/15350)) with `APIConnectionError`: the Qwen3.5 decode server dies on an `AssertionError` in AITER's `fused_reshape_causal_conv1d_update_single_token`, which still requires `conv_state.stride(-2) == 1`. #53623 removed the `gqa_interleaved_layout` guard, so flat-qkvz models like Qwen3.5 now take `_forward_core_decode_aiter` even when the test sets `VLLM_SSM_CONV_STATE_LAYOUT=DS`, whose conv state is (blocks, dim, state_len) with the feature stride 3. Falling back to the generic path for DS, as the KDA path already does, avoids the stale AITER assertion; dropping that assertion in AITER is a separate follow-up.

On MI350X with the AITER v0.1.26 pin, Qwen3.5-0.8B with AITER and the DS layout fails on main with the same assertion and passes with this change in 3/3 runs, with output byte-identical to AITER with the SD layout; the new dispatch test fails without the change and passes with it.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
