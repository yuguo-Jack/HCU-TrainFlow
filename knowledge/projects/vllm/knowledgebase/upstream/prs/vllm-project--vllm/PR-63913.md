# [Bugfix][MRV2][Spec Decode] Profile rejection sampling before sizing the KV cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/63913) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

MRV2's startup profiling runs only the regular sampler on one logits row per request, so it never measures spec-decode verification: logits for every draft position plus the bonus token, then rejection sampling. The KV cache is therefore sized from a peak verification exceeds. This runs the rejection sampler on a dummy batch with a full draft per request during profiling, as MRV1 does via `SpecDecodeMetadata.make_dummy`. Fixes #63942. MRV2 counterpart of the mrv1-only #46270.

## Validation

A6000, `Qwen/Qwen3-0.6B`, ngram drafter, `max_num_seqs=256`, `max_num_batched_tokens=8192`, 256 requests with full drafts and sampling (temperature, top-p/top-k, penalties, logprobs). Activation peaks above the steady-state baseline:

| K | profiled (main) | profiled (this PR) | real decode peak |
|---|---|---|---|
| 4 | 241 MiB | 1212 MiB | 1127 MiB |
| 8 | 241 MiB | 1792 MiB | 1711 MiB |

With spec decode off nothing changes (241 MiB profiled).

`tests/v1/spec_decode/test_mrv2_spec_decode_profile.py`:

```
main:     AssertionError: spec-decode activation peak 1126.2 MiB exceeds the profiled peak 240.6 MiB  (2 failed)
this PR:  2 passed
```

The test asserts accepted drafts, so it exercises verification. It runs in the existing V1 Spec Decode step.

## Details

I first tried only holding verification-sized logits during the regular sampler pass. That covers greedy decoding but still under-profiles sampled requests (909 vs 1711 MiB at K=8), because rejection sampling with temperature and top-k/top-p allocates well beyond the logits, so this runs the real rejection sampler instead. The pass uses the warmup sampling params already registered for the regular sampler pass and caps requests at `max_num_batched_tokens // (1 + K)`.
