# [Bugfix][V1] Register accepted spec-decode tokens before terminal cleanup

[Upstream PR](https://github.com/vllm-project/vllm/pull/54979) · state: open · merged: False

## Overview

Register accepted speculative tokens in the local prefix cache before terminal cleanup releases their blocks. Follow-up to the GPU-cache question on [#52771](https://github.com/vllm-project/vllm/pull/52771#issuecomment-5507841294).

## Claims

- A finished speculative request publishes its finalized KV before cleanup, restoring reuse of accepted draft tokens by a later request.
- The registration excludes later in-flight work and verifier output trimmed by stopping, and retains the coordinator's existing MTP safety fence.
- An async Mamba retry preserves the durable copy-on-write cache entry instead of also attaching its key to mutable request state.

## Details

The last speculative verification may accept tokens after the normal allocation-time cache registration. If the same output terminates the request, there is no later allocation pass to register them. Before freeing a request that entered stop handling as `RUNNING` and actually finished, the existing cache coordinator now registers:

```python
min(max(0, request.num_computed_tokens - request.num_in_flight_tokens),
    request.num_tokens)
```

The new terminal call can retry a Mamba partial boundary already moved to a durable copy-on-write block. While async work remains in flight, a boundary at or behind the optimistic computed frontier must not be reattached to the mutable request-table source. First publication beyond that frontier remains allowed. The guard follows mandatory eviction of transient/unretained checkpoints and preserves #60533's revised boundary calculation and validation. The cleanup test now uses periodic retention to exercise a transient intermediate checkpoint, and retries only the settled 127-token prefix when one of 128 tokens is in flight. It adds no device synchronization, public API, or model-runner change.

Scope is local/core prefix-cache registration. This does not claim propagation of the newly published terminal Mamba state through an external KV connector.

**Duplicate and related-work check (2026-10-13):** reread #52771 and searched open and merged work for terminal cache registration, accepted tokens and references to #54979. The fresh scheduler ablation proves the missing registration remains on this exact base. #60533 changes hybrid checkpoint boundaries, not this terminal call. Merged #60071 preserves existing GPU publication while fixing SimpleCPU offload selection, and explicitly identifies #54979 as separate. #57646 exposes offload metadata; #58668 fixes resumable stop-trimmed accounting and explicitly preserves this PR's terminal cap. #53802 changes prompt-boundary reachability. #50551 predates this work and deserves credit for finalized Mamba decode checkpoints; its opt-in recurrent checkpoint mechanism does not register the ordinary attention/ngram terminal case reproduced here. #52244 also predates this work and deserves credit for its hybrid prompt-tail/replay corrections, which address a different lifecycle boundary.
