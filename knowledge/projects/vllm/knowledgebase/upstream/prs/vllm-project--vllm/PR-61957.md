# [Bugfix][Frontend] Remove stale `--uds` socket files so a server can restart on the same path

[Upstream PR](https://github.com/vllm-project/vllm/pull/61957) · state: open · merged: False

## Original PR description

## Overview

Fixes #61959. `vllm serve --uds <path>` could not be restarted on the same path: the socket file was never removed, so the second start failed with `OSError: [Errno 98] Address already in use` although nothing was listening. Remove a stale socket file before binding and remove our own file on shutdown.

## Claims

- Restarting on the same `--uds` path works without an external `rm` of the socket file (verified end to end on an A100, before/after below).
- A path that a live server still listens on is not taken over: the connect probe succeeds, the file is left alone, and `bind` fails with `EADDRINUSE` exactly as before.
- A regular (non-socket) file at the path is never deleted; `bind` fails on it as before.
- The process that bound the socket removes the file on shutdown: single API server (`run_server`), the multi-API-server launcher (after its workers, which share the socket, have exited), the render server and the snapshot server. Workers in `run_server_worker` do not remove it, so one exiting worker cannot unlink the file under its siblings.
- TCP serving is untouched; the new code runs only when `--uds` is set.

## Validation

**CPU tests** (new `tests/entrypoints/launchers/test_unix_socket.py`, no model): stale file replaced and connectable; live listener not taken over (`EADDRINUSE`, still reachable); regular file left alone; `remove_unix_socket_file` removes a socket file, ignores a missing path, leaves a regular file. `4 passed`. The stale-file case fails on `main` with `[Errno 98] Address already in use`.

**End to end** (1x A100-40GB, `Qwen/Qwen3-0.6B --enforce-eager`, start → request over the socket → `SIGTERM` → start again on the same path):

| | before (v0.31.0; `create_server_unix_socket` is identical on main) | after (this PR's commit cherry-picked onto v0.31.0, identical hunks) |
|---|---|---|
| socket file after clean shutdown | still present | removed |
| second start on the same path | exits during startup: `OSError: [Errno 98] Address already in use` | healthy after ~55 s, `/health` → 200; file removed again after the second shutdown |

`pre-commit run --files <changed files>` passes (ruff, ruff-format, typos, mypy, SPDX and the other local hooks).

## Details

`create_server_unix_socket` now calls `_remove_stale_unix_socket(path)` first: if `path` exists and is a socket, it connects to it; `ConnectionRefusedError` means no server is behind the file and it is unlinked (with a warning in the log); a successful connect or any other `OSError` leaves the file for `bind()` to report. This mirrors what asyncio does for `create_unix_server(path=...)`, which uvicorn relies on in its own `--uds` mode, but is more conservative: asyncio removes any socket file, this only removes one nothing listens on.

`remove_unix_socket_file(path)` unlinks the file only if it is a socket and ignores a missing file. It is called in the `finally` of each socket owner next to the existing `sock.close()`; in `run_multi_api_server` it runs after the API server manager, engines and coordinator have been shut down.

Not changed: abstract-namespace sockets (paths starting with NUL) never create a file and go through the same code without effect.
