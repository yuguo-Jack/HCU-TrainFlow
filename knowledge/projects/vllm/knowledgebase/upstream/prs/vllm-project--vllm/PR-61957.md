# [Bugfix][Frontend] Remove stale `--uds` socket files so a server can restart on the same path

[Upstream PR](https://github.com/vllm-project/vllm/pull/61957) · state: open · merged: False

## Original PR description

## Overview

Fixes #61959. `vllm serve --uds <path>` could not be restarted on the same path: the socket file was never removed, so the second start failed with `OSError: [Errno 98] Address already in use` although nothing was listening. Remove a stale socket file before binding and remove our own file on shutdown.

## Claims

- Restarting on the same `--uds` path works without an external `rm` of the socket file (verified end to end on an A100, before/after below).
- A path that a live server still listens on is not taken over: the connect probe succeeds, the file is left alone, and `bind` fails with `EADDRINUSE` exactly as before.
- A regular (non-socket) file at the path is never deleted; `bind` fails on it as before.
- The process that bound the socket removes the file on shutdown: single API server (`run_server`), the multi-API-server launcher (after its workers, which share the socket, have exited), the render server and the snapshot server. Workers in `run_server_worker` do not remove it, so one exiting worker cannot unlink the file under its siblings.
- Cleanup removes only the file this server created: the owner captures the socket file's `(st_dev, st_ino)` right after binding and removes the path only if it still matches, so a replacement socket bound by another server, or a symlink placed at the path, is left alone (the check and the unlink are not atomic; this narrows ownership mistakes, it is not a defence against a hostile writer in the socket directory).
- Abstract-namespace paths (leading NUL) have no file and skip every filesystem step.
- TCP serving is untouched; the new code runs only when `--uds` is set.

## Validation

**CPU tests** (new `tests/entrypoints/launchers/test_unix_socket.py`, no model): stale file replaced and connectable; live listener not taken over (`EADDRINUSE`, still reachable); regular file left alone; `remove_unix_socket_file` removes a socket file, ignores a missing path, leaves a regular file. Plus: a replacement socket at the path survives the old owner's cleanup and stays connectable; a symlink at the path is kept; an abstract-namespace socket binds without touching the filesystem. `7 passed`. The stale-file case fails on `main` with `[Errno 98] Address already in use`.

**End to end** (1x A100-40GB, `Qwen/Qwen3-0.6B --enforce-eager`, start → request over the socket → `SIGTERM` → start again on the same path):

| | before (v0.31.0; `create_server_unix_socket` is identical on main) | after (this PR's commit cherry-picked onto v0.31.0, identical hunks) |
|---|---|---|
| socket file after clean shutdown | still present | removed |
| second start on the same path | exits during startup: `OSError: [Errno 98] Address already in use` | healthy after ~55 s, `/health` → 200; file removed again after the second shutdown |

`pre-commit run --files <changed files>` passes (ruff, ruff-format, typos, mypy, SPDX and the other local hooks).

## Details

`create_server_unix_socket` now calls `_remove_stale_unix_socket(path)` first: if `path` exists and is a socket, it connects to it; `ConnectionRefusedError` means no server is behind the file and it is unlinked (with a warning in the log); a successful connect or any other `OSError` leaves the file for `bind()` to report. This mirrors what asyncio does for `create_unix_server(path=...)`, which uvicorn relies on in its own `--uds` mode, but is more conservative: asyncio removes any socket file, this only removes one nothing listens on.

`unix_socket_file_identity(path)` is captured by each owner right after `setup_server`; `remove_unix_socket_file(path, identity)` unlinks only while `lstat(path)` still reports that same socket inode. It is called in the `finally` of each socket owner next to the existing `sock.close()`; in `run_multi_api_server` it runs after the API server manager, engines and coordinator have been shut down.

Abstract-namespace sockets (paths starting with NUL) never create a file; both helpers return early for them.

### Follow-up: shutdown cleanup must retain the socket owner identity

I reproduced a cleanup ownership gap at head `c67b33858d3646bc9f532b4ff4a5389710df0220` using the real `create_server_unix_socket` / `remove_unix_socket_file` functions with AF_UNIX sockets on Linux aarch64, without loading a model:

1. Create old socket A at path P.
2. Unlink P while A remains open.
3. Create socket B at P and call `listen`.
4. Close A, then invoke its shutdown cleanup `remove_unix_socket_file(P)`.
5. P disappears; a new client connecting to B through P gets `FileNotFoundError`.

Checking only `S_ISSOCK` cannot distinguish A's socket from B's replacement. A proposed extension captures `(st_dev, st_ino)` immediately after owner setup and passes it to cleanup, which uses `lstat` and only unlinks a matching socket. The four owner sites need the captured identity; API workers must continue not removing the shared listener path.

A separate small regression: at the tested PR head, abstract paths starting with NUL raise `ValueError: embedded null byte` from `os.stat` in `_remove_stale_unix_socket`, contrary to the PR description. Explicitly skipping filesystem operations for abstract sockets fixes that case.

Twelve CPU unittest cases pass using extracted actual helper ASTs and real sockets: baseline replacement deletion, baseline abstract-path error, fixed replacement reachability, own/missing/regular/symlink cleanup, live listener protection, stale restart, duplicated worker descriptors, and static checks of all owner cleanup sites. This is not an end-to-end multiworker vLLM or GPU validation; the seven upstream-style pytest helper tests additionally passed with real imports in the v0.31.0 image, with only patched `launcher.py` overlaid (14 Torch deprecation warnings; 10.95 seconds). Other lifecycle owner modules were not exercised by those tests.

The identity check reduces accidental deletion but does not make check/unlink atomic or protect against hostile directory writers, inode reuse or all stale-probe races. This should extend the existing PR rather than duplicate its stale-socket work.
