# [Bugfix][HiSparse] Wait for resident block table before index conversion

[Upstream PR](https://github.com/vllm-project/vllm/pull/62401) · state: open · merged: False

## Original PR description

## Overview

Order resident HiSparse block-table creation before sparse-index conversion, fixing invalid KV indices and FlashMLA startup crashes.

## Claims

One device-stream dependency on the first index-group layer; no host synchronization.

## Validation

```sh
.venv/bin/python -m pytest tests/v1/attention/test_sparse_mla_backends.py -q -k 'hisparse or index_group or sparse_mqa'
```

H100: **47 passed**; both extended regression cases fail without the fix. Pre-commit passes.

GLM-5.3, 8 H100s, TP8/EP8, MTP3, CUDA graphs, 64 GiB HiSparse, 32 GiB CPU weight offload/rank: **26 HTTP-200 requests**, including 6,331-token context, 128-token decode, 6,208-token prefix reuse and nonzero MTP acceptance. GSM8K smoke: **19/20** (first 20 questions, zero-shot, concurrency 4; no unpatched accuracy baseline).

## Details

`batch_block_table()` queues its producer after `logical_topk_ready`, previously the side converter’s only dependency. Follow-up to #60647 and #60417. Extends the existing stride test. Open-PR searches found no duplicate fix.
