# [ROCm] Fix circular import in GCN arch detection

[Upstream PR](https://github.com/vllm-project/vllm/pull/41596) · state: open · merged: False

## Original PR description

- Problem: When `amdsmi` fails during platform initialization, `logger.warning_once` creates a circular import loop inside `vllm/platforms/rocm.py` preventing vLLM from starting in containers.
- Changes: Avoid `warning_once`, use `warning` instead, and fallback to `PYTORCH_ROCM_ARCH` environment variable.
- Fixes part of #40081.

The warning message is slightly misleading. It states that it's falling back to `torch.cuda` after `amdsmi` fails, but it actually tries the `PYTORCH_ROCM_ARCH` environment variable first. To improve clarity for users who might be debugging this path, the message should mention that both `amdsmi` and the environment variable were tried.

```suggestion
    logger.warning(
        "Failed to get GCN arch via amdsmi and PYTORCH_ROCM_ARCH is not set. "
        "Falling back to torch.cuda. This will initialize CUDA and may cause "
        "issues if CUDA_VISIBLE_DEVICES is not set yet."
    )
```
