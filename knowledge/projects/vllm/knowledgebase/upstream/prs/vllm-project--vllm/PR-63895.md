# [CI][XPU] Give test_mrv2_weight_offloading more GPU memory headroom

[Upstream PR](https://github.com/vllm-project/vllm/pull/63895) · state: closed · merged: True

## Original PR description

Raise `test_mrv2_weight_offloading` GPU memory utilization from 0.02 to 0.03 so XPU startup overhead does not exhaust the test budget before its offloader assertions. [Intel CI build 15605](https://buildkite.com/vllm/intel-ci/builds/15605#01a17e53-adce-4b74-b35e-243d58a2eaec) fails on main (`eaf1627c01f5`) with `available_memory=-736133`; the same failure was seen in [build 15474](https://buildkite.com/vllm/intel-ci/builds/15474). The 0.02 setting was introduced by vllm-project/vllm#51440; that identifies its origin, not the first failing revision. No tests or assertions are skipped, and runtime defaults are unchanged.

This existing PR already addresses the exact build-15605 failure, so no duplicate PR was opened. Validation on Intel Arc Pro B60 with `ZE_AFFINITY_MASK=6,7 VLLM_WORKER_MULTIPROC_METHOD=spawn .venv/bin/python -m pytest -v -s tests/basic_correctness/cpu_offload/test_cpu_offload.py -k test_mrv2_weight_offloading`: **2 passed, 6 deselected** on PR head `b5e17c41c977` (27.65s); both UVA and prefetch assertions ran. Current upstream baseline also passed locally (39.12s), so the CI failure was not reproduced here; UVA had only about 0.02 GiB KV headroom before, versus about 0.25 GiB with the fix. `.venv/bin/pre-commit run --files tests/basic_correctness/cpu_offload/test_cpu_offload.py` passed. Only targeted offload cases were run, not the full file; CUDA/ROCm were not available.

AI assistance (GitHub Copilot) was used.
