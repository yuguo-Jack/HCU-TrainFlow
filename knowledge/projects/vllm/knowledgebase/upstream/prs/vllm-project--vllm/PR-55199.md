# [Bugfix][Parser] Preserve prose after tool calls

[Upstream PR](https://github.com/vllm-project/vllm/pull/55199) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Preserve assistant text after tool calls in non-streaming engine-parser responses.

## Claims

- Retain prose before, between, and after tool calls.
- Preserve tool order, arguments, and the parser's whitespace behavior.

## Validation

The Qwen3 parser suite and scoped pre-commit hooks pass. Restoring the original complete-parse method reproduces the lost-text regression.

To run the related suites in a configured development environment:

```sh
.venv/bin/python -m pytest tests/parser/engine
```

A BF16 Qwen3-0.6B server using the `qwen3_coder` parser and existing precompiled extensions preserved prose and tool arguments through `/v1/chat/completions` in streaming and non-streaming responses. Structured output forced the reproducer text through real token generation. This exercises the serving/parser integration; model quality was not evaluated. The plain-text control also passed.

Upstream checks are stopped at contributor authorization; these local results do not establish a CI pass.

## Details

The shared complete-parse converter must flush deferred post-tool prose for every engine-backed parser. Drain that prose through the existing delta conversion before normalizing the response. Validation here uses Qwen3.

#59234 proposed an overlapping fix and was closed without merging. This PR includes adapter-level regression coverage; no open replacement was found.

AI assistance was used for this change.
