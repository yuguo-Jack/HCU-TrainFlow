# [Bugfix][Parser] Preserve prose after tool calls

[Upstream PR](https://github.com/vllm-project/vllm/pull/55199) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->
## Overview

Preserve assistant prose after tool calls in non-streaming engine-parser responses by draining deferred converter content before final normalization.

## Claims

- The adapter-path regression covers tail-only prose and prose before, between, and after two ordered tool calls.
- Tool arguments and whitespace policy remain intact.
- PR #59234 proposed an overlapping fix and was closed without merging on 2026-10-06. This PR remains open with adapter-level regression coverage.

## Validation

Validated on 2026-10-10 at published head `8a37565ae7` and in a temporary merge with upstream `276fbcff2717bd934cfa37c8a2e4c391f3e7237b`. The published branch was not rebased.

```sh
VLLM_TARGET_DEVICE=cpu CUDA_VISIBLE_DEVICES='' .venv/bin/python -m pytest tests/parser/engine/test_qwen3.py -q
.venv/bin/pre-commit run --hook-stage manual --files vllm/parser/engine/parser_engine.py tests/parser/engine/test_qwen3.py
```

The Qwen3 suite passes **53 tests at the PR head** and **68 on current upstream plus the fix**; all applicable scoped hooks pass. Restoring the original complete-parse method fails both adapter regression cases. A 128-case runtime matrix checks prose tails, whitespace-only tails, two-tool prose, and parser whitespace options.

**Native GPU/HTTP check:** published Python source, `Qwen/Qwen3-0.6B` (`c1899de289a04d12100db370d81485cdf75e47ca`), RTX 5070 Ti, BF16, FlashAttention 2, eager execution, existing precompiled extensions. The server used `--enable-auto-tool-choice --tool-call-parser qwen3_coder --max-model-len 1024`. Optional autotuning and warmups were disabled through supported kernel settings.

Three `/v1/chat/completions` requests returned HTTP 200. A `structured_outputs.choice` literal forces prose before, between, and after two XML tool calls through actual token generation. The non-streaming response returns `content="Before.  Between.  After."` and ordered `get_weather(city=Tokyo)`, `get_time(timezone=Asia/Tokyo)` calls. Streaming preserves the same prose and calls; the plain control returns `Plain response.` with no tool calls.

This validates forced content through token generation, HTTP, and the native adapter. It is not a model-quality benchmark. The server was stopped after the check.

## Details

The converter defers post-tool text for streaming order; complete parses previously ended without draining it. Normal parse/streaming entry points reset converter state, so a private flag difference between the competing implementations did not establish a separate defect.

The distinct contribution here is adapter-level regression coverage, including exact tool order and arguments. Related #59234 was closed without merging on 2026-10-06, and its author marked #59218 completed the same day. Neither closure included an explanation. The overlap analysis above remains relevant, but #59234 is no longer an open competing PR.

Upstream CI is blocked at contributor authorization. AI assistance was used for investigation, implementation, tests, and review.
