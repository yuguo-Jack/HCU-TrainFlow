# [Doc][CPU] Document startup failure from default --gpu-memory-utilization

[Upstream PR](https://github.com/vllm-project/vllm/pull/62653) · state: open · merged: False

## Original PR description

## Overview

Add a FAQ entry to the CPU installation guide explaining why `vllm serve` can fail at startup with `Available memory on node ... is less than desired CPU memory utilization` and how to fix it. Docs only.

## Claims

- On the CPU backend, `--gpu-memory-utilization` (default `0.92`) is the fraction of each NUMA memory node's total memory that vLLM reserves. The CPU guide did not mention this, and `--gpu-memory-utilization` does not appear anywhere in it.
- With the default, startup fails on machines or VMs where less than 92% of a node's memory is free, such as a ~16 GiB WSL2 instance.
- The new entry documents the default, how to lower it, and that the check is skipped when `--kv-cache-memory-bytes` is set.

## Validation

Host: Intel i5-12400, WSL2 Ubuntu 24.04 with 15.5 GiB RAM, CPU nightly wheel `0.32.1rc1.dev36+ge68efc685`, `facebook/opt-125m`.

| Command | Result |
|---|---|
| `vllm serve facebook/opt-125m` | fails: `Available memory on node 0 (13.03/15.5 GiB) on startup is less than desired CPU memory utilization (0.92, 14.26 GiB)` |
| `vllm serve facebook/opt-125m --gpu-memory-utilization 0.5` | starts; `/v1/models` and `/v1/completions` respond |
| `vllm serve facebook/opt-125m --kv-cache-memory-bytes 1073741824` (default 0.92) | starts; the error does not appear |

The default is defined in `vllm/config/cache.py` (`gpu_memory_utilization: float = Field(default=0.92, ...)`) and the check in `vllm/v1/worker/cpu_worker.py`.

`pre-commit` (including `markdownlint-cli2` and `typos`) passes.

## Details

The error message was already improved in #42479; this adds the same information to the documentation so users can find it before hitting the error. I did not find an existing issue or PR that documents this. #60053 and #55263 touch `VLLM_CPU_KVCACHE_SPACE` in the same file but not this flag.

**Limitations.** The example command in the docs uses `Qwen/Qwen2.5-1.5B-Instruct` to match the quickstart; I verified the flag behavior with `facebook/opt-125m`, not with that model. The "about 16 GiB" example is based on my 15.5 GiB WSL2 instance.
