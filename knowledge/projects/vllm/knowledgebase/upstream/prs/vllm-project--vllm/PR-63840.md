# [CI][Frontend] Let the SSL refresher test's fake server accept peer_loads

[Upstream PR](https://github.com/vllm-project/vllm/pull/63840) · state: closed · merged: True

## Original PR description

## Purpose

Fix `Entrypoints Unit Shard 2/2` on main (H200 and MI355). It has failed since #55699 merged ([build 97411](https://buildkite.com/vllm/ci/builds/97411)):

```
FAILED entrypoints/launchers/test_ssl_cert_refresher.py::test_serve_http_stops_ssl_refresher_when_server_exits[signal]
TypeError: test_serve_http_stops_ssl_refresher_when_server_exits.<locals>.<lambda>() got an unexpected keyword argument 'peer_loads'
```

**Root cause:** #55699 added this test. It replaces `launcher.NoSignalServer` with `lambda _config: server`, but `serve_http` has called `NoSignalServer(config, peer_loads=peer_loads)` since #60723 (Oct 9). #55699's only CI run was build 88245 on Sep 11, against a base from before #60723, so the test passed there and broke once merged.

**Fix:** the fake accepts and ignores keyword arguments (`lambda _config, **_kwargs: server`). The test still checks what it is meant to check: that the SSL refresher stops when serving exits.

**Not a duplicate:** no open PR touches this test.

## Test Plan

Not run locally (no torch environment here); ruff passes. The `Entrypoints Unit` steps will confirm.
