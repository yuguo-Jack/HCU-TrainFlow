# [Bugfix][Frontend] Materialize DeepSeek V4.1 content iterators before deepcopy

[Upstream PR](https://github.com/vllm-project/vllm/pull/62647) · state: closed · merged: True

## Original PR description

## Overview

Fix DeepSeek V4.1 chat requests whose message `content` is an empty array. Before this change, both streaming and non-streaming requests can fail before generation:

```json
{
  "model": "deepseek-ai/DeepSeek-V4.1-Flash",
  "messages": [{"role": "user", "content": []}],
  "stream": false
}
```

The non-streaming request returns HTTP 400; the streaming request emits an error SSE. The underlying exception is:

```text
TypeError: cannot pickle 'pydantic_core._pydantic_core.ValidatorIterator' object
```

After `ChatCompletionRequest` validation, `content=[]` can remain a Pydantic `ValidatorIterator`. DeepSeek V4.1’s message normalization deep-copies the messages, which raises this exception.

## Claims

- Materializing iterator-form `content` before the deep copy allows the affected request to render.
- Saving the resulting list in the message allows repeated rendering without consuming a one-shot iterator.
- The change is confined to the DeepSeek V4.1 tokenizer. General request validation and `tool_calls` handling are unchanged.

## Validation

- Reproduced the failure with streaming and non-streaming `content=[]` requests before the fix.
- Added regression coverage for empty content in both modes, text content parts, repeated rendering, and request JSON serialization.
- `python -m pytest --noconftest tests/tokenizers_/test_deepseek_v41.py -q` — **48 passed**.
- Ruff check and format check passed.

## Details

The fix converts `content` to a list only when it is an iterator, immediately before `_normalize_messages()` calls `copy.deepcopy(messages)`. Existing string and list content follows the previous path. Related materialization fixes for `tool_calls` do not cover this `content=[]` case.
