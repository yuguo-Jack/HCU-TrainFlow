# [Bugfix][Frontend] Hold partial ATEM markers out of streamed content

[Upstream PR](https://github.com/vllm-project/vllm/pull/55419) · state: open · merged: False

## Original PR description

Fixes #55395.

## Problem

The MuseGlimmer tool parser holds back partial channel-framing markers (`<|message|>` and friends) in an open body, but nothing covered ATEM. A suffix like `<atem:func` or an attribute-carrying `<atem:invoke name="ge` at the tail of a growing body was emitted as ordinary content immediately, so a split marker was briefly committed before the next chunk completed the tag, and a turn truncated mid-marker left the protocol fragment visible at stream end.

## Fix

Reworked onto the refactored parser family: MuseGlimmer is now a thin subclass of MuseToolParser, whose `_safe_open_body` withholds any trailing prefix of `_STRUCTURAL_MARKERS`. The set now includes the ATEM tags, and `_trailing_partial_marker_len` additionally catches an unclosed ATEM opener stem by shape — attribute-carrying openers like `<atem:invoke name="ge` grow past their marker stems, so prefix matching alone cannot see them. Fragments release once the closing `>` arrives, a closed body keeps ATEM text it legitimately contains, and prose that merely mentions `<atem:` (a space, which no tag allows) is never held back. Tool-call extraction is untouched; complete invokes parse exactly as before.

## Tests

Four new tests in `tests/tool_use/test_muse_glimmer.py`, none needing a checkpoint: the marker machinery holds bare and attribute-carrying partials, holds a closer cut mid-word, holds nothing once text continues past a tag and never holds prose mentions; the streaming path holds a split tag until it completes (then releases it intact) and drops the fragment when the turn truncates.

Verification on current main (e0e5e6ee0a lineage), CPU-only, `VLLM_TARGET_DEVICE=cpu`: the file's 29 tests pass with the change; the three behavioral cases fail against unmodified main (the partial marker leaks as content), pass with it. No GPU was available, so the coverage here is parser-level; the parse_delta suite needs a real MuseGlimmer checkpoint and runs in CI. ruff format/check clean on both files.

AI assistance disclosure: prepared with AI assistance (Kimi K3). The leak mechanism was verified by running the parser locally against the reproduction before writing the fix.
