# [Bugfix][KV Offload] Reject misaligned chunked-local CPU suffix hits

[Upstream PR](https://github.com/vllm-project/vllm/pull/63266) · state: closed · merged: True

## Original PR description



## Overview

Fix incorrect output from `SimpleCPUOffloadConnector` when a GPU prefix ends inside an attention chunk. Keep the GPU prefix and recompute the suffix when CPU lookup cannot safely preserve absolute chunk boundaries.

## Claims

- Reject CPU suffix lookup when the local prefix is not aligned to every participating chunked-local attention group.
- Preserve CPU reuse for requests without a GPU prefix and for chunk-aligned GPU prefixes.
- Add scheduler and real-`LLM` regressions and document the recomputation fallback.

## Details

CPU lookup slices off the GPU-local prefix and passes the remaining hashes and token budget to the coordinator. Chunked-local lookup interprets that budget using absolute chunk positions, so a prefix ending inside a chunk changes which blocks are treated as null padding.

With a 16-token GPU prefix and an 81-token prompt, CPU lookup reports a 64-token suffix hit with four null chunk entries. The claimed absolute hit is 80 tokens, so tokens 64–79 still require a real chunk KV block. The load planner skips that block, producing incorrect inference. The new alignment guard declines this lookup. Its tradeoff is additional prefill for misaligned mixed hits.

Duplicate-work checks were refreshed on 2026-10-23. #57325 introduces broader joint GPU/CPU lookup while retaining the legacy suffix API for fallback paths, including composed connectors. This patch protects that retained API and does not implement joint lookup. #61375 changes `OffloadingConnector` partial-tail stores; #39702 concerns CPU-hit pinning across lookup/allocation. Neither addresses this chunk-position error.
