# [ROCm][Perf] Split-K BF16x3 router GEMM for decode batches

[Upstream PR](https://github.com/vllm-project/vllm/pull/62614) · state: closed · merged: False

## Original PR description

## Purpose

The ROCm BF16x3 router tier (`bf16x3_router_gemm_rocm`, fp32 gate weights as in MiniMax-M2/M3) only serves batches of 2048+ tokens. Decode batches above the gfx950 fp32 low-M kernel (M ≤ 32) and below 2048 fall back to `F.linear(x.float(), w)` on the fp32 pipe, which is both slower and less accurate.

This PR adds a split-K Triton kernel for that range:
- Each program loads one `BLOCK_M × K/SPLIT_K` slice of the bf16 activations and the matching slices of the three bf16 weight terms, and accumulates the three terms in separate fp32 accumulators (small terms are summed among themselves before meeting the large one).
- A second kernel sums the K partitions in a fixed order (deterministic, no atomics).
- `SPLIT_K` is chosen so the grid stays within 768 programs while each split keeps ≥192 of K (within 3% of the best split on average, 16% worst case, over M ∈ [64, 2047] and six router shapes).

Dispatch (`rocm_bf16x3_router_gemm_dispatch`): M ≤ 32 → existing fp32 low-M kernel (still fastest there); 32 < M < 2048 → split-K; M ≥ 2048 → existing stacked hipBLASLt GEMM. Arbitrary M/N/K are supported via masks (N=17/384, K=1000/2880 and padded activation rows are tested).
