# [Distributed] Lazily initialize unused NCCL2 process groups

[Upstream PR](https://github.com/vllm-project/vllm/pull/60751) · state: open · merged: False

## Original PR description

Co-authored-by: OpenAI Codex <codex@openai.com>
Signed-off-by: Tushar Jain <tushar00jain@users.noreply.github.com>

### Summary

#### Pipeline-parallel groups

Fix pipeline-parallel group creation when `split_group` is enabled. NCCL pipeline-parallel groups consistently use `new_group` instead of `split_group`.

On the NCCL2 path, pipeline-parallel groups use `nccl-lazy` for independently initialized per-peer communicators, allowing communication with different pipeline peers to overlap.

#### Lazy NCCL2 process groups

Create NCCL2 groups with `lazy_init` when their normal communication path uses a vLLM device communicator such as PyNCCL, DeepEP, or another custom backend. NCCL2 remains available as a fallback and initializes automatically if it is used.

Singleton groups and vLLM’s optional world subgroup are also initialized lazily. This avoids registering GPU memory for NCCL2 communicators that may never be used, while preserving correctness for groups that are used later. Legacy NCCL behavior is unchanged.

The default group is also created with `lazy_init`.

#### Attention Test Initialization

Remove unnecessary distributed initialization from V1 attention tests that do not perform distributed communication.

MLA, sparse MLA, DSpark, and Mamba selector tests now use single-rank TP metadata without creating NCCL process groups. This avoids repeated NCCL initialization and teardown across parameterized cases and addresses the B200 attention-test timeout regression.

### Test plan

- Verified pipeline-parallel groups use `ProcessGroupNCCLLazy`.
- Verified disjoint pipeline-parallel P2P transfers overlap.
- Verified a device-communicator-backed group leaves its NCCL2 communicator uninitialized until a direct PyTorch collective uses it.
- Ran representative CI failure tests and measured 1,168–2,334 MiB/GPU savings from lazy singleton initialization, versus the 133–164 MiB CI shortfall.
- Ran the exact DBO + DeepEP high-throughput test; NCCL2 completed without OOM and peaked only 230 MiB/GPU above legacy NCCL.
- Verified affected V1 attention tests run without distributed initialization; Mamba selectors and representative MLA/HiSparse cases passed, while the DSpark matrix had 10 passes and 20 architecture-gated skips on H100.
