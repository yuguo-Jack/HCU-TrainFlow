# [Bugfix][KV Connector] Reset output placeholders and drop stale outputs on sync KV load failure (#65131)

[Upstream PR](https://github.com/vllm-project/vllm/pull/65686) · state: closed · merged: False

## Original PR description

## Overview

Fixes #65131. Resolves an assertion failure (`assert request.num_output_placeholders >= 0` in `AsyncScheduler._update_request_with_output`) when recovering from synchronous KV cache load failures under pipelined async scheduling (`async_scheduling=True`).

## Claims

- **Fixes Crash**: Prevents `AssertionError: assert request.num_output_placeholders >= 0` during prompt recomputation after synchronous KV load failure.
- **Prevents Output Cache Poisoning**: In-flight outputs computed with corrupt/uninitialized KV cache prior to synchronous rollback are correctly dropped instead of being appended to `output_token_ids`.
- **Maintains Scheduler Accounting Invariant**: Synchronous failure recovery mirrors `_preempt_request()` and `finish_turn()` by resetting `num_output_placeholders = 0`, setting `drop_stale_output = True`, and setting `num_stale_output_tokens = request.num_in_flight_tokens`.
- **Adds Regression Unit Test**: Adds `test_sync_load_failure_with_async_scheduling` covering pipelined batches, synchronous failure injection, stale output dropping, placeholder reset, and complete recomputation to `FINISHED_LENGTH_CAPPED`.

## Details

### Root Cause Analysis
In `AsyncScheduler` (`async_scheduling=True`), multiple batches can be scheduled into the GPU execution queue (`batch_queue_size > 1`) before previous batches complete:

1. **Step T (Batch 1)**: Request is scheduled with external KV cache hit. Since the prompt is completed, the request transitions to decode mode and increments `request.num_output_placeholders = 1`.
2. **Step T+1 (Batch 2)**: Before Batch 1 returns from the GPU, Batch 2 is scheduled concurrently in flight, incrementing `request.num_output_placeholders = 2` and updating `num_in_flight_tokens`.
3. **Step T+1 Return (Batch 1 Output)**: The worker reports synchronous KV cache load failure (`invalid_block_ids`). `_handle_invalid_blocks()` rolls back `request.num_computed_tokens = idx * block_size` and reschedules the request to recompute the prompt.
4. **The Bug**: `_handle_invalid_blocks()` did **not** reset `request.num_output_placeholders = 0`, did not set `request.drop_stale_output = True`, and did not set `request.num_stale_output_tokens = request.num_in_flight_tokens` (unlike `_preempt_request()`).
5. **Cascading Failure**:
   - When Batch 2 returns from the GPU, its output was generated using corrupt KV cache before rollback. Because `drop_stale_output` was `False`, `_update_request_with_output()` appended a corrupt token to `request.output_token_ids`.
   - This corrupt token inflated `request.num_tokens` (`len(prompt_token_ids) + len(output_token_ids)`).
   - During subsequent chunked prefill recomputation, `request.is_prefill_chunk` evaluated to `True` instead of `False` at the end of the prompt because `request.num_computed_tokens + scheduled < request.num_tokens`. Consequently, placeholder incrementation was skipped.
   - When the worker sampled a token at prompt completion, `_update_request_with_output()` decremented `num_output_placeholders` from 0, triggering:
     ```python
     assert request.num_output_placeholders >= 0  # CRASH
     ```

### Solution
In `Scheduler._handle_invalid_blocks()`, for every synchronous failed request:
```python
for req_id in sync_failed_req_ids:
    request = self.requests.get(req_id)
    if request is not None:
        request.drop_stale_output = True
        request.num_stale_output_tokens = request.num_in_flight_tokens
        request.num_output_placeholders = 0
        request.spec_token_ids = []
```
This properly marks all remaining in-flight batches as stale, drains them in lockstep via `num_stale_output_tokens`, discards their invalid sampled tokens via `drop_stale_output`, and resets placeholders to 0 so prompt recomputation starts with a clean slate.
