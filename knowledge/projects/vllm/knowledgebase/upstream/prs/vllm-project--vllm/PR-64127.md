# [Bugfix][KV Connector][NIXL] Fix PP push prefill for models with indexers on only some layers

[Upstream PR](https://github.com/vllm-project/vllm/pull/64127) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fix `NixlPushConnector` with a pipeline-parallel prefiller (PP>1) on models whose KV regions are not evenly spread across layers, e.g. GLM-5.2 (indexer cache on only some layers). Related: #63416 rewrites the same region-pairing code; its by-layer pairing would supersede fix 1 here.

## Claims

- Prefill with PP=2 + `NixlPushConnector` starts and completes P/D transfers for `tiny-random/glm-5.2`; on `main` the prefiller crashes at startup.
- Fix 1: PP stage regions are matched to the PP=1 decoder's regions by name instead of by `regions_per_layer * start_layer`.
- Fix 2: sparse-MLA indexer backends no longer enter the push compatibility hash, so PP stages and the decoder agree.

## Validation

2x H200, `vllm/vllm-openai:nightly` with this branch's Python overlaid; P: PP=2, D: TP=1, `--enforce-eager --no-enable-prefix-caching`, greedy, 12 prompts (4 longer than `index_topk`=2048), toy proxy. `NCCL_NVLS_ENABLE=0` was needed on the host.

| Setup | Result |
|---|---|
| `main`, PP=2 | prefiller crashes in `register_kv_caches` (`assert num_local_layers > 0 and self.num_regions % num_local_layers == 0`) |
| `main` + fix 1 only | handshake fails: `NIXL compatibility hash mismatch` |
| this PR, PP=1 (control) | no errors; disagg first-token logprobs equal local to ~1e-6; 10/12 text matches (the 2 diffs are near-tie tokens that also differ with PP=1) |
| this PR, PP=2 | no errors; 8/12 match decoder-local, 5/12 match prefiller-local |

The PP=2 text mismatches come from a separate GLM-5.x bug: layers that reuse top-k indices read a stale buffer at a stage start under PP (#63170, draft fix #59961). The prefiller output itself differs from the PP=1 output, independent of the connector.

Larger model: `zai-org/GLM-5.3` truncated with `--hf-overrides '{"num_hidden_layers": 10}' --load-format dummy --kv-cache-dtype auto` (`--enforce-eager --max-model-len 8192`), P: PP=2 on 2 GPUs (`VLLM_PP_LAYER_PARTITION=6,4`, so stage 1 starts on an indexer-producing layer and avoids #63170), D: TP=1 on a third GPU. 12 greedy prompts (4 longer than 2048 tokens): 12/12 match prefiller-local and 12/12 match decoder-local; D's external prefix-cache hit rate was 89-98%. Random weights, so this checks that the transfer is consistent, not model accuracy. No PP=1 control or `main` run was done on this model.

Unit tests (`test_nixl_push_connector.py`, `test_nixl_connector.py`, `test_nixl_connector_hma.py`, `test_nixl_desc_geometry.py`): 644 passed; the 1 failure (`test_fewer_blocks_with_hma[google/gemma-3-1b-it-512]`) needs a gated HF model. `test_push_compatibility_backend_ignores_indexers` and the updated `test_add_remote_agent_slices_remote_regions_to_local_pp_window` fail on `main` and pass here. `pre-commit` passes.

Request flow that failed on `main` (P: PP=2, D: PP=1):
1. D starts: registers its regions, `[L0.attn, L0.indexer, L1.attn, L2.attn, L3.attn]`.
2. P stage 1 (owns L2, L3) registers `[L2.attn, L3.attn]`; stage 0 (owns L0, L1) registers `[L0.attn, L0.indexer, L1.attn]`. Per-layer region counts differ, so `num_regions % num_local_layers != 0` and startup asserts (fix 1). Without the assert, a fixed `regions_per_layer * start_layer` offset would still pick the wrong D regions.
3. P stage 1 reports backend `FLASH_ATTN_MLA_SPARSE`, D reports `DEEPSEEK_V32_INDEXER` (first backend in the list), so the handshake hash differs and D rejects the push registration (fix 2).

## Details

- Fix 1 (`base_worker.py`): the PP-window slice in `add_remote_agent` indexes the remote metadata by `region_names`; removes `_remote_region_offset` and the registration-time assert.
- Fix 2 (`base_worker.py`): new `_compat_backend_name()`; for workers that support PP+HMA (push), drops `DeepseekV32IndexerBackend` subclasses before hashing. Pull is unchanged.
- Docs: `nixl_connector_compatibility.md` notes the hash change.
- Not duplicating an existing PR: searched open PRs/issues for NIXL push + PP, `_remote_region_offset`, and the compat hash. #63416 (draft) is the closest; it replaces the offset slice with by-layer pairing for all transfers but does not touch the hash.
- Limitation: PP>1 output for GLM-5.x stays wrong until #63170 is fixed.
