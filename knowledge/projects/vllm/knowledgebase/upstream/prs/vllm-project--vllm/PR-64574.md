# [Bugfix][ROCm][KV Connector] MoRIIO: fix port collision with TP > 1 and DP > 1

[Upstream PR](https://github.com/vllm-project/vllm/pull/64574) · state: open · merged: False

## Original PR description



## Overview

MoRIIO gives two workers the same handshake and notify port when an instance has both TP > 1 and DP > 1, so a TP2 x DP2 prefill hangs at startup. This PR computes every port offset with the TP size of the instance that owns the port.

## Claims

- A MoRIIO instance with TP > 1 and DP > 1 (here prefill TP2 x DP2 x EP4) starts and serves requests. Before this change, prefill hung at startup with `ZMQError: Address already in use (addr='tcp://*:6302')`.
- Every worker of a TP x DP instance gets a unique notify port and handshake port, and the WRITE allocation and release notifications reach the right prefill rank.
- Port numbers do not change when TP = 1 or DP = 1, so existing deployments are not affected.

## Validation

- `test_notify_ports_are_unique_across_tp_and_dp_ranks`: the listener side.
- A new `remote_dp_rank=1` case in `test_release_reaches_every_prefill_rank_and_no_other`: the sender side.

The end-to-end run also needed two fixes that are not part of this PR:
- **The toy proxy pins the decode leg to the prefill DP rank.** With DP1 decode, that fails with `data_parallel_rank 1 is out of range [0, 1)`. That's a separate fix.
- **mori `WaitAll` on XGMI returns only at `transfer_timeout`.** That added ~30 s to TTFT. Separate issue, not fixed here.

The same port fix, applied as a local patch, also served a full 8K-in / 1K-out sweep at concurrency 1-128 (1,020 requests) on this 4:1 layout with no errors.

## Details

**Root cause.** Each MoRIIO worker binds its handshake and notify sockets at `base + get_port_offset(dp_rank, tp_rank, tp_size)`, and its peers have to compute the same number to reach it. `tp_size` defaulted to 1, and the call sites disagreed:

| side | call site | offset |
| --- | --- | --- |
| notify listener | `MoRIIOConfig.from_vllm_config` | `dp + tp` |
| handshake listener | `MoRIIOConnectorWorker.__init__` (`side_channel_port`) | `dp + tp` |
| WRITE alloc notify / release to prefill | `update_state_after_alloc`, `_release_write_prefill_blocks` | `dp + tp` |
| WRITE `write_done` to decode | `MoRIIOWriter._resolve_notify_endpoint` | `dp + tp` |
| handshake dial | `_moriio_handshake` | `dp * tp_size + tp` |
| READ release | `_read_blocks` | `dp * tp_size + tp` |

With TP2 x DP2, `dp + tp` gives offset 1 to both (dp0, tp1) and (dp1, tp0), so the second bind fails. That kills its listener thread, and the engine hangs in the first collective.

**Fix.** Make `tp_size` a required argument and pass the TP size of the instance that owns the port at every call site:
- Listeners pass their own TP size.
- Senders pass the peer's TP size: `get_moriio_peer_tp_size` for prefill, `WriteTask.remote_tp_size` for decode.
- When the peer's TP size is unknown, senders fall back to the local TP size, which is the existing "unknown means homogeneous" convention.

Making the argument required means a future call site can't silently fall back to `dp + tp`.

**Compatibility.** Offsets only change when TP > 1 and DP > 1, and that setup could not start before. Prefill and decode instances must run a vLLM version that both have this fix, which is already required for the other MoRIIO TP x DP changes.

**Not a duplicate.** I searched open PRs and issues for MoRIIO port, `get_port_offset`, handshake port and TP/DP. #58435, #39276 and #38813 edit lines next to two of these call sites, but they keep the two-argument `get_port_offset(dp, tp)`, so none of them fixes the mismatch. Whichever lands second may need a trivial rebase.

**Tests.** The existing tests in `test_moriio_write_done_routing.py` computed their expected ports with `get_port_offset(dp, tp)`, so they encoded the mismatch. They now pass the owner's TP size. The new listener test builds a real `VllmConfig` and patches only the TP rank and size, because a real TP2 rank needs two GPUs.
