# [Refactor][Mamba] 1/N: Unify device-pointer tensors to uint64

[Upstream PR](https://github.com/vllm-project/vllm/pull/58308) · state: open · merged: False

## Original PR description

## Why

Per the convention proposed in #50834, device pointers stored in tensors (`data_ptr()` values) are semantically unsigned 64-bit and should use `torch.uint64` instead of `int64`, which silently overflows/wraps for addresses `>= 2**63` (observed on XPU USM pointers).

This PR only covers `MambaSpecDecodeGPUContext.state_base_addrs` / `block_table_ptrs` in `vllm/v1/worker/mamba_utils.py`: switch them to `torch.uint64` and drop the `_reinterpret_u64_as_i64` int64 bit-pattern workaround, assigning `data_ptr()` directly.

## Torch requirement

torch's element-wise tensor `__setitem__` overflow-checks the assigned Python int as a signed `long long`, even when the target tensor is `torch.uint64` (pytorch/pytorch#191458), so `state_base_addrs[idx] = state.data_ptr()` raises `OverflowError: Python int too large to convert to C long` for real device pointers `>= 2**63` on torch versions without the upstream fix (pytorch/pytorch#191604).

torch 2.14 includes the fix, and both XPU and CUDA are now pinned to `torch==2.14.0` (`requirements/cuda.txt`, `requirements/xpu.txt`, `pyproject.toml`), so this PR is no longer blocked on the torch upgrade.
