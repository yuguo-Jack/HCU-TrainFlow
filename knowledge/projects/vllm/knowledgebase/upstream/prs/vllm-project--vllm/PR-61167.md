# [Model Loader] Apply EP weight filtering in InstantTensor

[Upstream PR](https://github.com/vllm-project/vllm/pull/61167) · state: closed · merged: True

## Original PR description

## Overview

Apply EP weight filtering before InstantTensor I/O using scitix/InstantTensor#29, released in InstantTensor 0.2.2.

Skip non-local expert payloads while retaining scales, shared experts, and fused tensors. Keep collective loading for checkpoints without filterable expert weights, and match checkpoint names literally.

#58016 covers the standard safetensors reader; this change reuses its EP predicate for InstantTensor.

- almogtavor · comment · 2026-10-12T12:06:50Z · [source](https://github.com/vllm-project/vllm/pull/61167#discussion_r4247814861)

`tensor_filter` doesn't exist in instanttensor 0.1.9, and the pin is still `>= 0.1.9` (setup.py, requirements/cuda.txt). So `--load-format instanttensor --enable-ep-weight-filter`, which loads fine today without filtering, would raise a `TypeError` in `safe_open`. The new test mocks `instanttensor`, so CI won't catch it. Bump the pin to the release that includes InstantTensor#29 in this PR, or check `inspect.signature(instanttensor.safe_open)` and fall back to the unfiltered path.

- almogtavor · comment · 2026-10-12T12:06:50Z · [source](https://github.com/vllm-project/vllm/pull/61167#discussion_r4247814868)

File: `vllm/model_executor/model_loader/weight_utils.py` · line None

This turns off NCCL loading whenever EP filtering is enabled, even when the filter keeps every tensor. On fused-expert checkpoints (e.g. GPT-OSS), `parse_expert_id` returns None for every name, so nothing is skipped, but every rank still reads the full model from storage on its own (about 8x the storage reads at EP=8). Only drop the process group when the filter actually skips something, e.g. by checking the names in `model.safetensors.index.json` first.

- almogtavor · comment · 2026-10-12T12:06:50Z · [source](https://github.com/vllm-project/vllm/pull/61167#discussion_r4247814875)

File: `vllm/model_executor/model_loader/weight_utils.py` · line None

With NCCL off, every rank reads all dense and shared-expert weights itself instead of splitting them. The scale tensors kept for non-local experts also sit between skipped weights, so each becomes its own tiny read (for FP8 DeepSeek-V3, tens of thousands per rank). Together this can make the filtered load slower than the unfiltered NCCL load, and multi-GPU EP is untested. Could you benchmark a real EP=8 load against the current path before merging?
