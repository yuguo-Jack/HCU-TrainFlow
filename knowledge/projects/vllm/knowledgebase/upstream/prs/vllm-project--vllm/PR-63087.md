# [CPU] Use a smaller block size for the MRV2 bitmask-unpack kernels

[Upstream PR](https://github.com/vllm-project/vllm/pull/63087) · state: closed · merged: False

## Original PR description

## Purpose

On x86 CPU the first request that uses penalties or structured output waits 70-80 s for its first token with the V2 model runner. `_penalties_kernel` and `_apply_grammar_bitmask_kernel` both unpack a packed bitmask with `(packed[:, None] >> tl.arange(0, 32)[None, :]).reshape(BLOCK_SIZE)`, and triton-cpu lowers that `vector.shape_cast` to LLVM IR that grows quadratically
with `BLOCK_SIZE`: ~48 MB and ~70 s of compile per kernel at 8192.

This uses `BLOCK_SIZE = 1024` for these two kernels on CPU, set in `vllm/v1/worker/cpu/shm.py` next to the other CPU overrides for the V2 model runner. GPU is unchanged. The lowering itself is reported upstream in triton-cpu (link to follow).

It also unblocks running `warmup_kernels` on CPU (#62888), which compiles these kernels at startup and so currently adds ~250 s to engine init.

## Test Plan

- Cold compile and steady-state runtime of both kernels at several block sizes (Qwen3.5 vocab, 248320), with OpenMP threads bound as the CPU worker does.
- End to end: Qwen3.5-9B, BF16, `--kv-cache-dtype fp8_e4m3`, v0.32.0 CPU wheel with and without this diff, cold Triton cache, AMD EPYC Turin (32 cores). Rounds of 2 concurrent requests, each round enabling one sampler feature for the first time.

## Test Result

Cold compile per kernel:

| BLOCK_SIZE | `_penalties_kernel` | `_apply_grammar_bitmask_kernel` | LLVM IR |
|---|---|---|---|
| 1024 | 1.7 s | 1.4 s | 0.8 MB |
| 2048 | 2.4 s | 2.1 s | 3.0 MB |
| 4096 | 10.6 s | 9.9 s | 11.9 MB |
| 8192 | 71.0 s | 70.5 s | 47.9 MB |

Runtime is no worse at 1024 (µs per launch):

| tokens | penalties, 1024 | penalties, 8192 | bitmask, 1024 | bitmask, 8192 |
|---|---|---|---|---|
| 1 | 29.6 | 28.6 | 20.7 | 20.4 |
| 8 | 57.0 | 102.0 | 27.6 | 30.0 |
| 64 | 403.0 | 764.3 | 102.1 | 151.0 |

TTFT of the first request using each feature (s):

| build | penalties | structured output (`choice`) |
|---|---|---|
| v0.32.0 | 81.0 | 73.7 |
| v0.32.0 + this PR | 10.0 | 3.7 |

What remains is the other sampler kernels compiling on first use, which
#62888 moves to startup. With both applied the same requests take 1.7 s and
2.5 s, and engine init goes from 317 s to 100 s.
