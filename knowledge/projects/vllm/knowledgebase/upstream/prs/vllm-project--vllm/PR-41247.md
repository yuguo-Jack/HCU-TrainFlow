# [Feature]Support Dynamic Chunked Pipeline Parallel with Profiling

[Upstream PR](https://github.com/vllm-project/vllm/pull/41247) · state: open · merged: False

## Original PR description

## Purpose
Support Dynamic Chunking in the pipeline parallel to achieve lower TTFT latency.

This PR ports profiling-based dynamic chunk sizing from vllm-ascend PR #7896 (commit bec63146cf), which is also similar to the [dynamic chunk](https://www.lmsys.org/blog/2026-01-15-chunked-pipeline/#background-why-pipeline-parallelism) in SGlang. Instead of using a fixed `max_num_scheduled_tokens` chunk for prefill, vLLM profiles prefill latency at startup, fits a quadratic model, and predicts optimal chunk sizes at runtime to equalize execution time across pipeline stages. ** This is proven to be beneficial for long-sequence prefill, as shown in the [SGLang Blog](https://www.lmsys.org/blog/2026-01-15-chunked-pipeline/#background-why-pipeline-parallelism). **

### How it works

1. **Startup profiling**: At `EngineCore` init, `Scheduler.run_profiling_chunk_init()` sweeps 64 chunk sizes via `collective_rpc("profile_prefill_latency")`. `GPUWorker.profile_prefill_latency()` runs a real `_dummy_run(profile_cpp=True)` and times each forward pass with device sync. Only the first PP rank's timing is used.
2. **Model fitting**: The scheduler collects `(chunk_size, latency_ms)` pairs and calls `ChunkSizePredictor.fit()` to fit the basic quadratic model `f(L) = a·L² + b·L + c`. Solves `a·x² + (2aL+b)·x − T = 0` to predict chunk size for a target latency.
3. **Runtime prediction**: In `schedule()`, a `time_budget` (default 10 ms) gates each step. For each request, `predict_chunk_size()` solves the quadratic, applies exponential smoothing (`smooth_factor`, default 0.8), and aligns to `max(page_size, 64)`. `predict_time()` deducts predicted time per scheduled chunk from `time_budget`.
4. **Online refinement**: `EngineCore` wraps `update_from_output` to feed each step's measured `execution_time_ms` (recorded by `GPUModelRunner`) into `record_batch_execution_time()`. After 5–30 real batches, the history-aware model `f(C,H) = a·C·(C+H) + b·C + c·H` is fit, and prediction switches to `predict_with_history` for better accuracy.

### Configuration

Enable via `additional_config`:
```python
additional_config={
    "profiling_chunk_config": {
        "enabled": True,           # default: False
        "smooth_factor": 0.8,       # default: 0.8
        "min_chunk": 4096,         # default: 4096
    }
}
```
