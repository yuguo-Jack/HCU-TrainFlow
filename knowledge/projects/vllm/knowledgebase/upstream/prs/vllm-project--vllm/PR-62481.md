# [ROCm] Monitor FlyDSL JIT compilation after warmup

[Upstream PR](https://github.com/vllm-project/vllm/pull/62481) · state: closed · merged: True

## Original PR description

## Purpose

Add FlyDSL hook so compilations at runtime warns or fail like the other backends (cutedsl, triton, ...).

Especially helpful for monokernels, where we now will get informed about runtime compilation if for instance
- width >= max capture size
- width is not among the captured sizes

## Test Plan

```python
import torch

from vllm._aiter_ops import rocm_aiter_ops
from vllm.utils import jit_monitor

assert rocm_aiter_ops.is_gdn_flydsl_prefill_available(), "FlyDSL GDN kernels not importable"

jit_monitor.activate(mode="warn")

T, H, D = 64, 4, 128
dev = "cuda"
q, k, v = (torch.randn(1, T, H, D, device=dev, dtype=torch.bfloat16) for _ in range(3))
g = torch.randn(1, T, H, device=dev, dtype=torch.float32)
beta = torch.rand(1, T, H, device=dev, dtype=torch.bfloat16)
state = torch.zeros(1, H, D, D, device=dev, dtype=torch.float32)
cu_seqlens = torch.tensor([0, T], device=dev, dtype=torch.int32)

rocm_aiter_ops.gdn_flydsl_prefill(
    q=q,
    k=k,
    v=v,
    g=g,
    beta=beta,
    initial_state=state,
    output_final_state=True,
    cu_seqlens=cu_seqlens,
    aiter_prefill_metadata=rocm_aiter_ops.build_gdn_flydsl_prefill_metadata(
        [T], cu_seqlens=cu_seqlens
    ),
    use_qk_l2norm_in_kernel=False,
)
print("done")
```

- okorzh-amd · comment · 2026-10-20T17:48:23Z · [source](https://github.com/vllm-project/vllm/pull/62481#discussion_r4328287688)

File: `vllm/utils/jit_monitor.py` · line None

MlirCompiler.compile only runs when FlyDSL's disk cache misses. That cache is on by default, aiter/__init__.py points it at aiter's bundled jit/flydsl_cache (about 7.5k entries: launch_gemm*, launch_mixed_moe_gemm*, launch_gdn_h...), and mono/runner.py:46 keeps a persistent writable one. On a disk hit, JitFunction.__call__ returns at jit_function.py ~1432-1450 without calling compile, but the first post-warmup use still unpickles, parses the MLIR, builds an LLVM ExecutionEngine and loads the module. Ranks that pick up a peer's compile through the compile lock skip it too. Triton's hook does fire on its own disk-cache hits (it runs after self.compile in jit.py). I ran your monitor twice in a row on nightly-rocm100-df3bd094 with no GPU (COMPILE_ARCH=gfx950) and the same cache dir: the first run warns, the second is silent. So the uncaptured-width case goes quiet from the second launch onward. Wrap flydsl.compiler.jit_executor.CompiledArtifact._ensure_engine instead. It runs once per kernel variant per process, on both a fresh compile and a cache load, and never per launch. 

- okorzh-amd · comment · 2026-10-20T17:50:10Z · [source](https://github.com/vllm-project/vllm/pull/62481#discussion_r4328304936)

File: `vllm/utils/jit_monitor.py` · line None

func_name is the Python @flyc.jit launcher's name. All three DSv4.1 mono launchers are called launch (mono/layer.py:336, 742, 953), as are many aiter FlyDSL launchers. Because warn mode deduplicates on that name, only the first post-warmup FlyDSL compile in a process is logged, as "FlyDSL ... : launch". A later k1/k2/ffn compile at another width prints nothing, and the one line that is logged does not say which kernel or width needs warmup. Pass the gpu.func symbol (it carries the width, e.g. dsv41_mono_k1_s..) as detail. It can be read from the MLIR text (module here, or self._ir_text in the hook above) with flydsl's _infer_kernel_names_from_asm.
