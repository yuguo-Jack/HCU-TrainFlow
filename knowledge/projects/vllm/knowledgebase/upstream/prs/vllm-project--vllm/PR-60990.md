# [Bugfix][ROCm][MiniMax-M3] Reject unbuilt index-head counts in the AITER indexer

[Upstream PR](https://github.com/vllm-project/vllm/pull/60990) · state: closed · merged: True

## Original PR description

## Overview

The MiniMax-M3 AITER indexer selector now rejects index-head counts AITER has no kernels for. At attention TP=1 (4 index heads per rank), the server now fails at load with a clear error instead of crashing on the first decode step.

## Claims

- `aiter_indexer_unsupported_reason` accepts only 1 or 2 index heads, the counts AITER builds its MSA score kernels for (`SPARSE_DECODE_TABLE`/`SPARSE_PREFILL_TABLE`, unchanged from the `v0.1.24.post1` pin through AITER main).
- A new regression test in `test_minimax_m3.py` fails without the fix and passes with it.

## Validation

MI355 (gfx950). At TP=1, `amd/MiniMax-M3-MXFP4` crashed before the fix at the first forward with `pa_sparse_block_score_decode: no build for num_idx_heads=4`. With the fix it refuses to start with a configuration error. `tests/kernels/attention/test_minimax_m3.py` passed 10/10 runs.

At TP=2 the same AITER kernels run before and after. I ran 5 interleaved runs per column, each with a fresh server, using `VLLM_ROCM_USE_AITER=1` and the fp8 index cache. Values are mean ± sd.

| `vllm bench serve` (4096 in / 256 out, conc 16) | Before | After |
|---|---|---|
| Request throughput (req/s) | 2.366 ± 0.007 | 2.365 ± 0.009 |
| Mean TPOT (ms) | 18.83 ± 0.73 | 18.53 ± 0.86 |

| gsm8k (5-shot, n=1319) | Before | After |
|---|---|---|
| strict-match | 0.8799 ± 0.0089 | 0.8708 ± 0.0089 |

The gsm8k difference is not significant (Welch p ≈ 0.14).

## Details

The selector only rejected head counts above the 16 MFMA columns, so 4 heads got through and failed inside AITER's kernel dispatch. A rejected config falls back to the platform-neutral indexer, which turns this case into a load-time error. TP ≥ 2 still gives each rank 1 or 2 heads, so it keeps the AITER path. The test asks the selector instead of naming an architecture, so it keeps working as more CDNA targets are added. No open PR fixes this. If #57909 (which moves this selector to `indexer_msa.py`) lands first, the guard belongs there.
