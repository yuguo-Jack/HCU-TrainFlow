# [Bugfix][MRV2] Capture DCP FULL cudagraphs with KV context

[Upstream PR](https://github.com/vllm-project/vllm/pull/61496) · state: closed · merged: True

## Original PR description



## Overview

On MRV2, GQA models with DCP produce garbage under the default `FULL_AND_PIECEWISE` cudagraph mode, including the Qwen3-235B `-tp 8 -dcp 2` example in `docs/serving/context_parallel_deployment.md`. This PR captures DCP FULL graphs with KV context, as V1 already does (`get_dcp_dummy_context_len`).

## Claims

- Fixes GQA + DCP + FULL cudagraphs on MRV2. Qwen3-235B at TP=8 DCP=2: needle retrieval 0/9 → 9/9.
- No regression for MLA + DCP (DeepSeek-V2-Lite).

## Validation

8x H100, `main` @ de8291e24f, default settings. Needle: 6-digit code at depths 0.1/0.5/0.9 of ~8k/~31k/~100k-token prompts, greedy. gsm8k: 5-shot, chat template.

```bash
pytest tests/v1/cudagraph/test_cudagraph_manager.py  # new test fails on main
```

## Details

**Root cause.** For DCP, the FlashAttention metadata builder skips context attention on the host when no request has context (`should_skip_dcp_context_attention`, #40996). MRV2 captures FULL graphs from a dummy batch with `seq_lens == query_lens`, so every FULL graph records the skip path and replays ignore the KV cache. Piecewise and eager rebuild metadata each step and are unaffected.

**Fix.** On FULL capture with `cp_size > 1`, give the dummy batch `cp_size * cp_interleave` tokens of context through the existing `set_dummy_context`. Applied on both FULL capture paths, normal and DBO. Capture-time only.

**Limitations.**
- The FA2 decode/prefill split (`should_split_fa2_dcp_context_attention`) is still decided at capture; unchanged by this PR.
- `set_dummy_context` clamps context to `max_model_len - max_query_len`, so a capture size within `cp_size * cp_interleave` of `max_model_len` still gets zero context.
- The DBO path is not tested end-to-end (needs DeepEP).

**Alternative.** Forcing `skip_dcp_context_attention=False` in the FlashAttention builder during capture. The runner-side fix matches V1 and is backend-agnostic.

No existing PR or issue covers this; nearest are #59951 and #54300 (different code paths).
