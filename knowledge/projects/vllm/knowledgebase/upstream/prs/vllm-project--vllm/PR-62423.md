# [Bugfix] Respect root_path when formatting Cohere errors

[Upstream PR](https://github.com/vllm-project/vllm/pull/62423) · state: open · merged: False

## Original PR description



## Overview

Fix Cohere error envelopes when vLLM runs behind a path prefix or as a mounted application. Invalid requests to `/proxy/cohere/v2/chat` now receive Cohere's `{message, id}` body instead of the internal `{error: ...}` envelope.

## Claims

- Select the Cohere error format using the application route path, preserving validation errors and request IDs behind `root_path` and mounts.
- Keep ordinary API errors unchanged when `root_path` is `/cohere`, and avoid misclassifying unrelated mounted applications.

- Production `build_app` served through Uvicorn and HTTPX: **56/56 HTTP checks passed**, versus **33/56** with the original middleware. Covers prefixed and stripped paths, mounts, error statuses, and request IDs.

## Details

FastAPI supports deployments with a [proxy path prefix and `root_path`](https://fastapi.tiangolo.com/advanced/behind-a-proxy/). Routing accounts for that prefix, but the Cohere middleware checked the full URL path. This both misses prefixed Cohere routes and incorrectly matches ordinary routes beneath `/cohere`.

Reuse Starlette's `get_route_path` helper, which its router already uses, and capture the result before `call_next`: a downstream mount can mutate `scope.root_path`. This adds no dependency, though the helper lives in Starlette's private `_utils` module.

GitHub issue and PR searches on 2026-10-19 found no matching fix. [#62127](https://github.com/vllm-project/vllm/pull/62127) preserves error headers; [#52794](https://github.com/vllm-project/vllm/pull/52794) fixes authentication path matching. Neither fixes Cohere error-format selection. This patch is based on upstream `3c8245b73d`.
