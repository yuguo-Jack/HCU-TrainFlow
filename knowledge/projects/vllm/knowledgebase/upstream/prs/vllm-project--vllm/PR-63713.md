# [Bugfix] Fix Pixtral FP8 attention sequence metadata

[Upstream PR](https://github.com/vllm-project/vllm/pull/63713) · state: open · merged: False

## Original PR description





## Overview
Fix FP8 attention metadata in both Pixtral vision towers so FlashInfer uses correct buffer offsets for batches containing multiple images.


## Claims
- Pass the FP8 padded hidden size through Pixtral’s packed sequence metadata generation.
- Use matching Q/K/V offsets for separately quantized FP8 buffers, avoiding out-of-bounds V reads.
- Preserve the existing non-FP8 metadata behavior.


## Validation

Needs Blackwell (SM 100+); FP8 ViT attention isn't supported on Hopper.

  ```bash
  vllm serve mistralai/Pixtral-12B-2409 --tokenizer-mode mistral \
    --mm-encoder-attn-backend FLASHINFER --mm-encoder-attn-dtype fp8 \
    --limit-mm-per-prompt '{"image": 1}' --max-model-len 8192
  ```

  Then send ~16 concurrent chat requests, each with a different 1024x768 image (a single request may not trigger it).

  - Before: the engine core crashes with `CUDA error: an illegal memory access`; the in-flight and subsequent requests return 500 (`EngineDeadError`). 
  -  After: all requests return 200.


## Details
FlashInfer FP8 attention quantizes Q/K/V into separate contiguous buffers. Pixtral omitted the FP8 padded hidden size when generating metadata, causing V offsets to retain the packed-QKV layout’s 3x stride. For subsequent images, these offsets can point beyond the V buffer.
Both vision towers now resolve the padded hidden size during construction and pass it through metadata generation, reusing the existing FP8 offset handling.
