# [Bugfix] DSA: all-reduce partial hidden_states before PP send

[Upstream PR](https://github.com/vllm-project/vllm/pull/60477) · state: open · merged: False

## Original PR description



## Overview

Fixes wrong activations at every pipeline-parallel stage boundary for DSA models (`vllm/models/deepseek_v32/{nvidia,amd}/model.py`, which serves DeepSeek-V3.2 and GLM-5.x) when TP > 1. The last layer's un-reduced MLP/MoE output is now all-reduced into the residual before the PP send.

Separate from, and complementary to, #59961 (stage-local shared indexer top-k).

## Claims

- GLM-5.3 BF16 with TP8PP2 now matches TP16 on GSM8K accuracy and on output length. Without this fix, it loses 7–9 points and generates about 7.6× more tokens.
- The cost is one extra TP all-reduce per step at each PP stage boundary. There is no change when PP = 1 or TP = 1.

## Details

**Root cause.** DSA decoder layers run MLP/MoE with `reduce_results=False`, and the TP all-reduce happens inside the next layer's `fused_allreduce_rms_norm`. The last layer on a non-final PP stage therefore returns `hidden_states` that are a per-TP-rank partial sum. `gpu_worker` sends `IntermediateTensors` with `all_gather_group=get_tp_group()`, which assumes the tensors are identical on every TP rank. TP rank `r` sends only `tensor.reshape(tp, -1)[r]`, and the receiver all-gathers (`isend_tensor_dict` / `irecv_tensor_dict`). With partial sums, the receiver ends up with token chunk `r` holding rank `r`'s partial sum. It then all-reduces again, so chunk `r` becomes `tp × partial_r` instead of `Σ_r partial_r`.

**Fix.** On the sending stage, reduce `hidden_states` into `residual` and send zeros as `hidden_states`. The receiving stage's first layer still computes `all_reduce(hidden_states) + residual`, which now gives the correct value. Both sent tensors are replicated across TP, so the sliced send stays valid.

**Tradeoffs.** One extra all-reduce of `[num_tokens, hidden_size]` per step per stage boundary. Sending zeros keeps the `IntermediateTensors` interface and the receiver path unchanged. Skipping the receiver-side all-reduce instead would need a stage-aware branch in the decoder layer.

**Symptom.** The output stays fluent, so the bug is easy to miss. It shows up as much longer reasoning, repetition loops, and repeated `</think>`.
