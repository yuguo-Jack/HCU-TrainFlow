# [ROCm] Optional non-expandable CUDA graph pool to skip the AITER all-reduce copy-in

[Upstream PR](https://github.com/vllm-project/vllm/pull/57481) · state: open · merged: False

## Original PR description

Blocked on https://github.com/ROCm/aiter/pull/5799

With expandable_segments enabled, hipIpcGetMemHandle cannot export the VMM-backed pointers the caching allocator hands out, so AITER's custom all-reduce falls back to staging every input through a device-to-device copy. On an 8x MI355X Kimi-K3 decode that is one copyBuffer per all-reduce, 1160 of 1160 launches across all ranks, ~1.2 ms per forward pass.

The activations feeding those all-reduces are allocated inside CUDA graph capture from the graph's private pool, so disabling expandable segments for the duration of capture is enough to make them IPC-exportable and let AITER take its registered path. Weights, KV cache and eager allocations keep expandable segments.

Off by default behind VLLM_NON_EXPANDABLE_CUDAGRAPH_POOL. The toggle follows CuMemAllocator.use_memory_pool, which flips the same allocator setting around the sleep-mode pool.
