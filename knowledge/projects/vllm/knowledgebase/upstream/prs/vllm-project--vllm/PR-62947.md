# [Bugfix] deepseek_v32: honor the decoder's deferred MoE all-reduce on the naive all2all path

[Upstream PR](https://github.com/vllm-project/vllm/pull/62947) · state: open · merged: False

## Original PR description

## Summary

Every deepseek_v32-NVIDIA decoder builds its MoE with `reduce_results=False` and performs the all-reduce itself in the next layer's `fused_allreduce_rms_norm`. When the MoE runs the naive all-gather/reduce-scatter all2all container (EP on, TP>1, prefill CP>1), the build-time formula in `fused_moe/layer.py` also clears `skip_final_all_reduce`, so the runner all-reduces as well. Every MoE layer's output then enters the residual stream scaled by `tp_size`. Serving `nvidia/GLM-5.3-NVFP4` in that shape silently returns garbage (GSM8K 0.00 on 0.31.0 and 0.32.0; mechanism and full measurements in #62945).

This adds a module-level helper in the NVIDIA decoder, `_defer_moe_allreduce(moe_cfg)`, called once after the MoE build, which restores `skip_final_all_reduce=True` on exactly that path (`use_ag_rs_all2all_kernels and not is_sequence_parallel`). The AMD variant already defers decoder-side the same way for its non-MoRI backends (`deepseek_v32/amd/model.py:86-94`). Nothing else changes: no-all2all layouts already defer, self-reducing combines (DeepEP, MoRI, NIXL, MoonEP, both NVLink pairs, passthrough) return the output reduced and stay protected by the runner's coexist assertion, and sequence parallel owns its own reduction.

The deeper fix, making the `layer.py` formula consult `output_is_reduced()` and the caller's `reduce_results` so no decoder-side override is needed, is a good follow-up discussion; this change is kept minimal and inside what was measured. The MoRI-style `zero_mlp_output` covers the self-reducing corner at TP>1 (AMD precedent, unmeasured here).

## Testing done

- New regression test `tests/models/deepseek_v32/test_moe_deferred_allreduce.py` drives the real `MoERunner._maybe_reduce_final_output` across a (tp, pcp, dp, ep, backend) grid with a counting `tensor_model_parallel_all_reduce`. It is red on main, green with this change, and red again if the gate is widened to self-reducing combines (the coexist assertion fires). A four-state CPU check across the same grid: patched 20/20 passed; unpatched main fails at import (helper missing); a no-op helper fails exactly the all-gather/reduce-scatter cells; an unconditional force fails exactly the self-reducing cells.
- Serving A/B on one 8×RTX PRO 6000 node, stock vLLM 0.32.0 PyPI stack: the failing shape scored GSM8K 0.00 and healed to 0.85 with the equivalent one-line fix, clean at every stage. That A/B ran as a site edit on the 0.32.0 wheel, so this patch has not been GPU-run on main; the main-side claim rests on the byte-identical code path plus the test.
- On current main `4a3ee9a0` (the patch applies cleanly there; run on CPU, torch 2.14.1+cpu, no GPU): `pytest -v tests/models/deepseek_v32/test_moe_deferred_allreduce.py` → 20 passed. On pristine main, collection fails with `ImportError: cannot import name '_defer_moe_allreduce'`, the intended red while the fix is absent.
