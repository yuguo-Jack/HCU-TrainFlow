# [CI] Re-enable disabled jobs whose installs are already locked

[Upstream PR](https://github.com/vllm-project/vllm/pull/64010) · state: closed · merged: True

## Original PR description



## Overview

Re-enable the 27 CI job definitions disabled by #63608 and #63609 whose only runtime installs are packages already pinned in the test image locks. Their install lines were no-ops, so this restores the jobs without the install lines and does not resolve anything at job time.

## Claims

| Disabled install | Already pinned in | Restored jobs |
| --- | --- | --- |
| `pip install pytest-timeout pytest-forked` | `requirements/test/{cuda,rocm}.txt` (`2.3.1`, `1.6.0`) | Batch Invariance: A100, H100, B200 + MI250/MI300/MI355 mirrors; standalone MI250/MI300/MI355 in `test-amd.yaml` |
| `pip install 'opentelemetry-*>=…'` | `requirements/test/{cuda,rocm}.txt` | Metrics, Tracing: L4 + MI300 mirror; standalone MI300 |
| `uv pip install -r requirements/kv_connectors_rocm.txt` (`tblib`, `lm_eval[api]`) | `requirements/test/rocm.txt` (`tblib==3.1.0`, `lm-eval==0.4.12`, all `[api]` extras) | 18 standalone AMD Nixl/Mooncake PD and Elastic EP jobs in `test-amd.yaml` |
| `run-intel-ci-test.sh` (`tblib==3.1.0`, `av`) | `requirements/test/xpu.txt` (`tblib==3.1.0`, `av==18.1.0`) | Intel BMG Example Test, Server test |

- The install lines are removed. The Intel steps still call `run-intel-ci-test.sh` unchanged; its two installs are no-ops against the XPU test image.
- The `requirements/kv_connectors_rocm.txt` source-file dependency is dropped from the restored AMD jobs, since they no longer install from it.
- 17 test files that are tethered again are removed from the test-tethering allowlist.
- Still disabled: everything that needs a new lock (KV connectors on NVIDIA, evalscope, helion, torchao/conch, plugins, gguf, modelscope, cmake, apt, git sources). Follow-ups will add hash-locked `requirements/ci/*.txt` files.

## Validation

- Every restored step was compared against its definition before #63609 (or #63608 for the Intel Example Test). All 31 step labels, mirrors included, match exactly once the removed install commands and the `kv_connectors_rocm.txt` dependency are excluded.
- `pre-commit run` passed, including `check-test-tethering` (full scan) and the Buildkite step-key check.
- Buildkite run of only the restored main-pipeline steps: CI_RESULTS_PLACEHOLDER

## Details

These jobs were disabled because their commands contained runtime `pip install`s. For this subset, every requested package was already present at a satisfying version in the image, so the installs resolved nothing new. Removing the lines keeps it that way if the image locks change, and makes it fail loudly rather than silently installing from PyPI.

Duplicate-work check: no open PR re-enables these jobs.
