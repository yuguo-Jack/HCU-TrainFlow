# Add Mooncake EP all-to-all backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/58375) · state: open · merged: False

## Original PR description

## Motivation

Mooncake provides an expert-parallel all-to-all communication backend for MoE models. This PR proposes integrating Mooncake EP into vLLM as an optional `mooncake_ep` A2A backend.

Mooncake EP has already been integrated into SGLang. We would like to bring the backend to vLLM and discuss the appropriate evolution path with the vLLM community.

## Changes

- Add `mooncake_ep` to the A2A backend registry.
- Add the Mooncake EP CUDA communicator manager.
- Add `MooncakeEPPrepareAndFinalize`.
- Integrate Mooncake EP with the modular `FusedMoEKernel` path.
- Add a two-GPU kernel/adapter correctness test covering:
  - Mooncake dispatch and combine;
  - reference local-expert execution;
  - modular `FusedMoEKernel` execution;
  - BF16 inputs with different token counts.

The implementation follows the existing vLLM EP integration patterns used by DeepEP, NIXL-EP, and MoonEP. The Mooncake dependency remains optional and is detected through vLLM's package probe mechanism.

## Testing

Tested on two H20 GPUs with:

- PyTorch 2.13.0+cu130
- Mooncake 0.3.13.post1

```bash
pytest -q tests/kernels/moe/test_mooncake_ep.py
```

Thanks for the contribution!

Could you elaborate on the advantages of integrating Mooncake EP? As far as I can tell, its main differentiator is fault tolerance / elastic EP (via `active_ranks` + `timeout_us`), but this PR doesn't enable it: every call passes a fresh all-ones `active_ranks` and `timeout_us=-1`. Without that, it seems functionally close to the existing `deepep_low_latency` and `nixl_ep` backends, which already support vLLM's fault-tolerance and elastic EP paths. Do you have any performance numbers compared with those backends?

| 48 | 45.23 | 42.64 | 42.94 |
| 64 | 50.88 | 49.14 | 46.27 |
| 80 | 56.27 | 52.37 | 56.27 |
| 96 | 55.11 | 57.74 | 55.70 |
| 112 | 62.52 | 63.10 | 64.07 |
| 128 | 65.38 | 65.27 | 64.48 |
| 160 | 72.62 | 73.06 | 70.83 |
| 192 | 74.17 | 74.33 | 75.02 |
| 224 | 78.05 | 77.88 | 78.42 |
| 256 | 80.64 | 80.93 | 81.05 |

We view this PR as the first step for Mooncake EP in vLLM. It establishes the healthy serving path and backend integration, while dynamic membership, fault recovery, and replacement-rank rejoin will be added in follow-up work. We would be happy to discuss the preferred evolution path with the community.
