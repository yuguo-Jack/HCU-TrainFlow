# [ROCm][Perf][DeepSeek-V4.1] Fused mega-attention prefill kernel for MI355X

[Upstream PR](https://github.com/vllm-project/vllm/pull/65146) · state: open · merged: False

## Original PR description



## Overview

Adds a ROCm/HIP "mega attention" kernel for DeepSeek V4.1 prefill on MI355X (gfx950).
One launch reads ROCm's paged 584-byte FP8 KV records and does dequantization, sparse attention (causal top-k compressed rows plus the SWA window), inverse RoPE and the MXFP8 output cast.
A new attention class, `DeepseekV41ROCMAiterMegaAttnAttention`, is picked automatically when the config supports it.
Every other config, and all decode, keeps using the existing ROCm sparse path.

## Claims

- New `_rocm_C` ops: `fused_norm_rope_attn_rope_cast_{fwd,prefill,decode}` (`csrc/flashmla/fused_norm_rope_attn_rope_cast_fwd_rocm.cu`).
- Prefill on MI355X / MI355X VF uses the fused kernel by default. This removes the separate dequantize, gather and sparse_fwd steps and the bf16 gather workspace they need.
- Prefill speedup over the current ROCm sparse path:
  | Tokens | speedup |
  | :-: | :-: |
  | 16 | 1.73x |
  | 128 | 1.72x |
  | 512 | 1.29x |
  | 2048 | 1.15x |
- Conservative auto-selection (`is_available_for`). It falls back to `DeepseekV41ROCMAiterMLAAttention` for unsupported dtype, KV cache dtype, TP split, KV connector or context parallelism, so it does not change behavior anywhere else.
- No-op refactor: the warmup workspace reservation moves into `_reserve_prefill_workspace` (ROCm and FlashMLA), and the `attn_metadata.get(...)` + `assert` pattern becomes direct indexing in the DSv4.1 backends.

## Details

- **Kernel design**: each CTA owns one query and 16 heads. Four waves split 32-key steps and run independent online softmaxes, so the main loop has no barrier. K is read straight from registers (`S^T = K Q^T`), and P^T stays in the MFMA output layout. Paged loads stay in the global address space so they count only against `vmcnt`. Staged K rows are swizzled across banks so the transposed V reads don't hit bank conflicts. Invalid keys read a sentinel record instead of branching, so every tile issues the same loads.
- **Selection conditions** (also in `docs/getting_started/installation/gpu.rocm.inc.md`): MI355X or MI355X VF; the prefill op is compiled in; BF16 model with `head_dim=512` and `qk_rope_head_dim=64`; KV cache dtype `auto`, `fp8` or `fp8_ds_mla`; positive sliding window; TP divides both heads and `o_groups` with whole heads per local group; no KV connector; PCP and DCP both equal to 1.
- **Limitations**: decode still goes through the ordinary ROCm sparse path. The decode op and `_forward_decode_mega` are included and tested at kernel level but not routed yet; switching decode over will be a follow-up with its own perf data. The backend reports itself as `ROCM_FLASHMLA_MEGA_ATTN_DSV4`.
