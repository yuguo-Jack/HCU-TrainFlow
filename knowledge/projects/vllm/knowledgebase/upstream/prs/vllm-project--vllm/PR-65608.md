# [Bugfix][Structured Output] Honor request stop tokens in Guidance

[Upstream PR](https://github.com/vllm-project/vllm/pull/65608) · state: open · merged: False

## Original PR description



## Overview

Honor the complete request stop-token set in Guidance structured outputs.
This implements the separate Guidance follow-up identified in the
[review of #49227](https://github.com/vllm-project/vllm/pull/49227#pullrequestreview-4769227512).

## Claims

- Mask additional model EOS tokens and request `stop_token_ids` until the grammar accepts termination.
- Preserve request-local stop sets, original speculative draft token IDs, atomic rejection, and the existing rollback and reset behavior.
- Cover the behavior with real-backend regressions, a deterministic `LLM.generate()` regression, and user documentation.

## Details

### Root Cause

`StructuredOutputManager` already forwards
`SamplingParams.all_stop_token_ids`. Guidance's grammar compiler accepted that
argument but ignored it, allowing an ordinary string-content token to stop
the request before the JSON string was complete.

### Implementation

Each grammar now stores an immutable set of additional stop tokens.
Bitmask updates use `is_accepting()`, including accepting states that still
allow continuation.

Matcher operations map additional stops to canonical EOS while validation
returns the caller's original token IDs. Existing EOS rollback handling is
reused, and reset also clears termination bookkeeping.

### Request Isolation and Performance Considerations

The shared tokenizer stays request-independent. All added bitmask operations
use the existing CPU buffer.

Native multi-EOS configuration alone leaves ordinary character stop tokens
allowed in an unfinished string in llguidance `1.7.6`, so the accepting-state
mask is explicit.
