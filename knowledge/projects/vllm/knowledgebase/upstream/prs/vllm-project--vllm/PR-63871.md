# [Bugfix][Muse] Finalize dummy-loaded MegaMoE weights

[Upstream PR](https://github.com/vllm-project/vllm/pull/63871) · state: closed · merged: True

## Original PR description

## Overview

Fix Muse Spark dummy loading with `deep_gemm_mega_moe`. Run expert repacking and residual-constant materialization through the existing model post-load hook, and initialize custom NVFP4 expert scales with valid dummy values.

## Claims

- Dummy-loaded BF16 and NVFP4 Muse MegaMoE models finish initialization and generate finite outputs.
- Checkpoint and dummy loaders share the same post-load finalization hook.

## Validation

GB200 validation of the retained tests: 2 generation cases passed. All targeted pre-commit checks pass.

On one GB200, using `.venv/bin/python -m pytest tests/quantization/test_blackwell_moe.py -k test_muse_megamoe_dummy_loading -x -v -s`:

| Configuration | Before | After |
| --- | --- | --- |
| BF16 Muse, 1 layer, hidden 512, 8 experts, top-2, MegaMoE | `AssertionError: finalize_weights() not called` at `mega_moe.py:313` | Pass |
| NVFP4 Muse, same shape and backend | Not run on baseline after first failure | Pass |

The regression generates two greedy tokens with finite log probabilities for both weight formats through the normal LLM dummy-loading entry point. It registers the native text class via ModelRegistry to avoid initializing unrelated multimodal towers. It does not assert private packed-weight layouts or residual-buffer structure.

Targeted pre-commit hooks passed. The existing B200 Quantized MoE CI step runs this suite, with Muse sources added to its dependency selection. No checkpoint accuracy evaluation is claimed: the reported failure and added scale metadata concern synthetic dummy weights.

## Details

DummyModelLoader initializes parameters directly and does not invoke the model's `load_weights`. Muse's expert repacking and residual coefficient setup previously lived only there. Exposing the existing operations through `process_weights_after_loading` makes them run after dummy initialization and per-layer quantization finalization. Both checkpoint and dummy loading reach the standardized model hook in BaseModelLoader; the multimodal wrapper inherits it directly.

Muse's custom MegaMoE parameter allocator also bypasses ModelOpt's generic expert scale setup. Use the existing `dummy_weight_value` parameter contract with the same constants as ModelOpt NVFP4 (block scales 1, global weight scales 0.001, input scales 0.01). This metadata does not change checkpoint values.

Open-PR searches for `"Muse" "dummy"`, `"Muse" "finalize"`, `"Muse" "post-load"`, and `"Muse" "dummy_weight_value"` found no duplicate. Merged #63698 covers generic ModelOpt parameters, which Muse's custom MegaMoE allocator does not use. Open #52487 concerns reload after sleep. No associated issue number exists.

AI assistance was used to implement and validate this change. The human submitter confirmed review of every changed line and execution of the relevant tests before submission.
