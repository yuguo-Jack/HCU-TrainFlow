# [Bugfix] Preserve missing parser-plugin dependency diagnostics

[Upstream PR](https://github.com/vllm-project/vllm/pull/61377) · state: open · merged: False

## Original PR description



## Overview

When an importable parser plugin has a missing dependency, `import_plugin` mistakes the dependency failure for a missing plugin and replaces its diagnostic with a failed file lookup. Preserve and log the original dependency error while retaining the existing `None` return contract.

## Claims

- Named and dotted plugins report the missing dependency from their original `ModuleNotFoundError`.
- Truly missing module names still try file loading, including a relative `.py` filename whose dotted parent is absent.

## Validation

The two new regressions import real temporary plugins with a missing dependency. Both fail on the original source because the logged replacement error has the wrong name; both pass after the repair. The relative-file fallback case also passes.

With ordinary CPU PyTorch on Windows, 11 tests pass:
```bash
uv run --active --no-project --python /path/to/cpu-python -m pytest tests/utils_/test_import_utils.py --confcutdir=tests/utils_ -q -p no:cacheprovider -k 'not placeholder'
```

The existing placeholder test needs installed vLLM package metadata and is deselected in this source checkout. All applicable normal pre-commit hooks pass in a Linux-local checkout after verifying all 7,739 baseline Git blobs. Linux runtime tests were not run because the cached lint environment lacks real PyTorch and other runtime dependencies. The existing Buildkite utility lanes run `pytest -v -s utils_`, which includes this test file.

The human submitter reviewed every changed line and personally reran the CPU checks above before publication.

## Details

`ModuleNotFoundError.name` identifies what import resolution could not find. File fallback is appropriate when that name is the requested module or one of its dotted parents. A different name identifies a missing dependency inside the plugin, so log that active exception and return `None` instead of trying to open the module name as a file.

The reasoning and tool-parser registries both call this helper for registration side effects and discard its return value. Their error-handling contract remains unchanged. Errors without a `.name` retain the legacy fallback.

Open overlapping-file PRs were checked. [#61075](https://github.com/vllm-project/vllm/pull/61075) rolls back failed file imports in `import_from_path`; this change corrects named-module error classification in `import_plugin`. [#41834](https://github.com/vllm-project/vllm/pull/41834) and [#59912](https://github.com/vllm-project/vllm/pull/59912) change optional-package availability helpers, so neither addresses this failure.
