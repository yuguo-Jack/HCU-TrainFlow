# [ROCm][Perf][Qwen3.8] Keep dense mono K2 on during MTP verify.

[Upstream PR](https://github.com/vllm-project/vllm/pull/64720) · state: open · merged: False

## Original PR description

Depends on #61573. This branch is that mono-kernel branch plus one commit. Review the latest commit for the MTP change. The other files are #61573 and are not new here.

An MTP verify step is wider than a plain decode, so the mono graph turned off. K1 stays on vLLM's GDN core, which can roll a rejected draft back. K2 stays on the fused MXFP4 feed-forward while the step fits the K2 cap. Quark MXFP4 checkpoints store `mtp.*` as BF16 under `quantization_config.exclude`, so those draft weights load unquantized.

Serve with `speculative-config: {"method": "mtp", "num_speculative_tokens": 3}` and `VLLM_ROCM_MONO_DECODE=1`. k=3 is the best combined geomean at TP1 and TP2. VL is highest at k=2.

MI355X, 20-config sweep per TP, versus the best Argos mono kernel with no speculative decoding. The k=1 column is from the earlier k=1 summary.
