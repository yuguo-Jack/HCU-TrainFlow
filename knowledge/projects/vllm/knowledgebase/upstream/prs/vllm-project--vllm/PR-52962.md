# [Mamba] Add shared FP8/INT8 FlashInfer ReplaySSM checkpoints

[Upstream PR](https://github.com/vllm-project/vllm/pull/52962) · state: open · merged: False

## Original PR description

## Overview

Adds shared FP8/INT8 SSM checkpoints to FlashInfer ReplaySSM.
PR #55688 merged into `main` at `750cad1973f037fe00116cbf58cd3b3bd8701cd4`.
This branch now uses `main` at `4527515cd705db206ae927cf5acef506abc64bdd`. The separate CuTeDSL implementation remains in draft #65660.

Review the [shared-only comparison](https://github.com/askliar/vllm/compare/4527515cd705db206ae927cf5acef506abc64bdd...911ffe1d78cbb31b618a87fd2911fa6b57fd4597).
This PR no longer includes the unmerged parent history.

```text
BF16 inputs → shared FP8/INT8 checkpoint + FP32 row scales → FlashInfer SSU
```

## Claims

- `--replayssm-state-dtype fp8|int8` selects a shared quantized checkpoint. The default `auto` path retains floating-point state.
- Prefill, cache copying, and prefix materialization preserve each checkpoint with its FP32 scales.
- Existing stochastic-rounding controls apply to shared decode writes. Prefill encoding uses nearest rounding.
- This layer adds no separate checkpoint mode or vendored CuTeDSL kernels.

### FP8 diagnosis

The native SM103a conversion probe passed 2,112 packed comparisons with zero hardware/software mismatches.
The representable-value oracle passed. Sixteen graph replays produced sixteen unique seeds.
This checks selected conversion inputs and the default PyTorch graph RNG.
The probe does not check the full vLLM graph or SSM state arithmetic.

Full-model FP8 without stochastic rounding scored **926/1319 (70.20%)**, with **265 invalid answers** and **308 truncated outputs**.
The quality drop persists with SR disabled. The root cause remains unresolved.

Set `CUDA_VISIBLE_DEVICES=0` and `VLLM_USE_V2_MODEL_RUNNER=1`. Use one fresh process per cell and one persistent FlashInfer tuning cache.

**Workload and timing**

- Standard: batch 256, `max_model_len=1256`, `enable_chunked_prefill=False`, `max_num_batched_tokens=16384`, and one 128-token warmup generation.
- Standard prompt: `My cat wrote all this CUDA code for a new language model and`, repeated across the batch.
- MTP: batch 256 or 512, `max_model_len=2048`, chunked prefill enabled, and `speculative_config={"method": "mtp", "num_speculative_tokens": 3}`.
- MTP prompts: the first B pinned GSM8K test questions, with `chat_template_kwargs={"enable_thinking": False}`.
- MTP warmup: repeated full-batch 256-token generations for at least 30 seconds.
- MTP graph capture: `sizes=(1,2,4,8,16,24,32,48,64,96,128,192,256,384,512)`. Use `sorted({4*min(n,batch) for n in sizes})` and maximum capture size `4*batch`.
- Throughput sampling: `n=1`, `temperature=0`, `seed=0`, `ignore_eos=True`, and equal minimum/maximum output counts of 1,000 or 256.
- Synchronize CUDA before and after timed generation. Calculate output TPS as `batch * output_tokens / elapsed_seconds`.
- Accuracy sampling: `n=1`, `temperature=0`, `seed=0`, `ignore_eos=False`, `max_tokens=1024`. Process all test questions in chunks of at most 256.

## Details

The implementation extends the merged ReplaySSM five-state cache with a matching scale page for the quantized SSM payload.
The three replay rings and convolution cache retain their existing types.
Prefill uses floating-point working state and encodes final or prefix-boundary checkpoints before publication.
The implementation rejects malformed records that omit scales.
The merged ReplaySSM exporter, ring-shape helpers, and extensible-cache warmup remain in use.

This is the shared portion of the requested split, not a competing implementation of #52962.
The child PR contains the separate checkpoint layout, native kernels, and separate-only request-ordering changes.
AI tools assisted implementation, review, validation, and this description.
