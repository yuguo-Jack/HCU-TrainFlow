# [Core][MRv2] Build ModelState through an overridable runner method

[Upstream PR](https://github.com/vllm-project/vllm/pull/65549) · state: open · merged: False

## Original PR description



## Overview

Adds `GPUModelRunner._init_model_state()`, so a subclass of the MRv2 runner can supply its own `ModelState` without patching the module-level factory. The first step of RFC vllm-project/vllm-omni#9848; its consumer is vllm-project/vllm-omni#9849, which uses the hook instead of its lock-and-swap patch of `init_model_state` when the installed vLLM provides it, and keeps the patch only for older versions (vllm-project/vllm-omni#1770 asks to stop monkeypatching).

## Claims

- `load_model` builds the model state through a new overridable method, which calls `init_model_state(vllm_config, model, encoder_cache, device)` exactly as before.
- No behavior change for vLLM: the default method forwards the same four arguments to the same factory.

## Validation

No new test in this PR. MRv2 runner tests that reach `load_model` build the runner without its constructor, which `tests/AGENTS.md` rules out for new tests, and a real-constructor test needs a GPU and a model.

CPU (macOS), at `0940a00246`:

```bash
python -m pytest tests/v1/worker/test_gpu_model_runner_v2_eplb.py -v
```

5 passed; three of these tests call `load_model`, now through the new method, with mocked dependencies. vLLM-Omni's runner tests (in the linked Omni PR) pass against this branch and against vLLM `main` at `a512f0e727`, which lacks the hook (67 passed each); its hook tests replace upstream `load_model`, so they establish dispatch behavior, not real loading. `pre-commit` passes.

## Details

- 1 file: `vllm/v1/worker/gpu/model_runner.py` +11/−3. Not user-visible, so no docs change.
- vLLM-Omni builds its MRv2 stage models (a `ModelState` per stage) through this factory. Today it swaps `vllm.v1.worker.gpu.model_runner.init_model_state` under a lock for the duration of `load_model`. An overridable method replaces that patch with a supported extension point.
- Not a duplicate: open PRs searched for `init_model_state` and MRv2 model-state hooks; none add this. The nearest, #64306, adds request-lifecycle hooks to MRV2 speculators.
- No GPU run: the change only moves one call behind a method. An MRv2 smoke through the Omni runner follows once this lands.
