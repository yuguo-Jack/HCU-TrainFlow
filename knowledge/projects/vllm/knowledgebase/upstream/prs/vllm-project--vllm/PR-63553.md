# [Spec Decode] Allow Gemma4 MTP with KV-sharing fast prefill

[Upstream PR](https://github.com/vllm-project/vllm/pull/63553) · state: open · merged: False

## Original PR description

## Overview
Extend the Gemma 4 KV-sharing fast prefill support introduced in [#38879](https://github.com/vllm-project/vllm/pull/38879) to work with Gemma 4 MTP on Model Runner V2. This PR narrows the compatibility guard,
reuses the existing execution path, and adds an A/B regression test for output agreement and speculative acceptance.

## Claims

- Add a narrow exception for Gemma 4 MTP on MRV2, retaining the compatibility guard for other configurations.
- Extend the fast-prefill compatibility guard to cover auxiliary hidden-state consumers such as `extract_hidden_states`.
- Add a compiled, chunked-prefill A/B regression test that compares output text and first-position speculative acceptance with fast prefill enabled and disabled.
- Document the combined configuration. Fast prefill remains opt-in.

## Validation
The revised regression test was validated locally at commit `7815aea3bd44323dc4d91c78a432fa3c9e105ad5` using an RTX 3090, Gemma 4 E2B IT and its assistant, TP=1, MRV2, and `TRITON_ATTN`. Earlier latency and GSM8K measurements below were collected at `7b1d07440dde8426a8b3d85e5f5815c06913eb82`.

### Regression Tests
The revised compiled MRV2 A/B regression test passed locally (`1 passed`, RTX 3090, E2B, TRITON_ATTN): 99/101 outputs matched exactly (required:81/101), and first-position acceptance was 55.51% with fast prefill off versus 55.29% on (required: ≥90% of baseline). Batch invariance was disabled.

B's strict-match score was **1.0614 percentage points lower than A's**, and the repeated baseline A2 also showed variation. The cause remains undetermined; these results establish neither losslessness nor a systematic quality regression caused by the optimization.

All three runs completed **1,319 questions** with matching question and prompt hashes. Speculative drafting and acceptance occurred in every run, with no empty/null responses or unresolved request or parsing errors.

## Details
Gemma 4's Q-only assistant reuses target KV and does not need skipped prompt rows to populate an independent draft KV cache. Non-shared target layers still populate prompt KV; trailing KV-sharing layers compute selected output and speculative-verification rows. This makes the existing fast-prefill path usable with Gemma 4 MTP on MRV2.

The production change only narrows the configuration guard. Prompt logprobs remain unsupported. Local validation covers E2B on CUDA; other model sizes and backends were not tested locally.

Open-PR searches on 2026-10-25 found related work on [V1 fast-prefill metadata (#60445)](https://github.com/vllm-project/vllm/pull/60445), [Gemma 4 MTP compute (#60689)](https://github.com/vllm-project/vllm/pull/60689), and [MTP draft-prefill attention pruning (#63195)](https://github.com/vllm-project/vllm/pull/63195), but no matching PR enabling this MRV2 joint configuration. This change enables the existing target KV-sharing fast-prefill path with Gemma 4 MTP; it does not add draft-attention pruning or MTP kernels.

The added test looks pretty heavy and does not check whether drafter has received the right hidden state. I'd suggest comparing acceptance rates in this test.

```suggestion
@single_gpu_only
def test_gemma4_mtp_fast_prefill(monkeypatch, vllm_runner):
    """Skipping prompt rows keeps target outputs and draft acceptance intact."""
    monkeypatch.setenv("VLLM_USE_V2_MODEL_RUNNER", "1")
    speculative_config = {
        "method": "mtp",
        "model": "google/gemma-4-E2B-it-assistant",
        "num_speculative_tokens": 2,
    }
    prompts = [
        "Calculate 17 times 23. Explain your calculation.",
        "Write a Python function that reverses a singly linked list.",
        "Background: "
        + "The cache stores keys and values. " * 200
        + "Explain why prefill can delay other requests.",
    ]
    results = []
    acceptance_rates = []
    for fast_prefill in [False, True]:
        with vllm_runner(
            "google/gemma-4-E2B-it",
            speculative_config=speculative_config,
            kv_sharing_fast_prefill=fast_prefill,
            language_model_only=True,
            attention_backend="TRITON_ATTN",
            max_model_len=4096,
            block_size=None,
            enable_chunked_prefill=True,
            max_num_batched_tokens=512,
            max_num_seqs=4,
            enable_prefix_caching=False,
            disable_log_stats=False,
            seed=42,
        ) as runner:
            tokenizer = runner.llm.get_tokenizer()
            formatted = [
                tokenizer.apply_chat_template(
                    [{"role": "user", "content": prompt}],
                    tokenize=False,
                    add_generation_prompt=True,
                )
                for prompt in prompts
            ]
            results.append(
                runner.generate_w_logprobs(
                    formatted,
                    SamplingParams(
                        temperature=0.0, max_tokens=64, ignore_eos=True, logprobs=5
                    ),
                )
            )
            acceptance_rates.append(compute_acceptance_rate(runner.llm.get_metrics()))
    check_logprobs_close(
        outputs_0_lst=results[0],
        outputs_1_lst=results[1],
        name_0="MTP",
        name_1="MTP with fast prefill",
    )
    assert acceptance_rates[1] == pytest.approx(acceptance_rates[0], abs=0.05)
```
