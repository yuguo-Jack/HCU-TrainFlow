# [Bugfix][Frontend] Stop accepting gRPC connections when shutdown starts

[Upstream PR](https://github.com/vllm-project/vllm/pull/65163) · state: open · merged: False

## Original PR description

## Overview

Fixes #65155 along with #65156. tonic holds on to the listener passed to `serve_with_incoming_shutdown` until every connection has drained. So if a gRPC call was still open during a `--shutdown-timeout` drain, new gRPC clients could still connect but never got a response. Now the incoming stream drops the listener as soon as shutdown starts, like the HTTP server already does, and tonic still drains the open connections.

## Claims

- After shutdown starts, new gRPC connections are refused, even while other gRPC calls are running.
- Calls that are already open still finish.

## Validation

Same setup as #65156: `VLLM_USE_RUST_FRONTEND=1 vllm serve ... --grpc-port 50052 --shutdown-timeout 40` on `vllm/vllm-openai-cpu:latest` (0.33.0). This time a `GenerateStream` was running at SIGTERM. For the last row I built `vllm-rs` from v0.33.0 with this change and applied #65156.

| | New gRPC client | New HTTP client | Running stream |
|---|---|---|---|
| Before | `Health.Check` times out after 5s | no reply after 5s | finishes |
| #65156 only | `Health.Check` times out after 5s | refused | finishes |
| #65156 + this PR | refused | refused | finishes |

The new test, `shutdown_refuses_new_connections_while_streams_drain`, keeps a stream open, starts shutdown, checks that new connections get refused, then lets the stream finish and checks that the server stops. Without the fix, new connections keep going through and the test times out.

```
cargo test -p vllm-server --lib    # 553 passed
cargo clippy -p vllm-server --all-targets -- -D warnings
```

## Details

`stop` is the signal `HealthMonitor::serve` gives once the health services report `NOT_SERVING` (#63870), so the listener now closes right after that instead of when the drain ends. tonic gets `std::future::pending()` as its own shutdown signal, so the drain starts when the incoming stream ends. If tonic also got `stop`, its `select!` could pick it first and stop polling the stream, leaving the listener open. `start_grpc_test_server` gets the same change so it still matches `serve`.
