# [Bugfix][Structured Output] Reject unproductive $ref cycles before backend selection

[Upstream PR](https://github.com/vllm-project/vllm/pull/63748) · state: open · merged: False

## Original PR description



## Overview

A JSON schema whose `$ref` only points back at itself is accepted, scheduled, and then killed on the first sampled token with HTTP 500. This rejects that schema while the request is validated, so the caller gets HTTP 400. Fixes #57725. The malformed spec HTTP 500 in the same issue is already fixed on main by #52394.

Thanks @MohamedZakkaria2004 for picking this issue up earlier.

## Claims

- A `$ref` cycle with no base case is a client error for `auto`, `xgrammar`, `guidance`, `outlines`, and `lm-format-enforcer`.
- A recursive schema that can emit a token still validates. In `auto` it stays on xgrammar. Covered cases include an optional recursive property, `anyOf` with a string branch, a required recursive property, and `enum` next to a cyclic `anyOf`.
- This does not overlap with #60036. That cap counts nested objects and arrays in the document. A cycle is a shallow document, so the depth cap does not catch it.

That is why the check runs before backend selection.

## Details

`Grammar.from_json_schema` succeeds for `{"$ref": "#/$defs/n", "$defs": {"n": {"$ref": "#/$defs/n"}}}`. The grammar allows no token. The scheduler logs `grammar rejected tokens` and finishes the request as an error, which the API serves as HTTP 500.

The new check is a fixpoint over local `$ref` targets. A reference can emit a token once its target can. `anyOf` and `oneOf` can emit when any branch can. `enum` and `const` can emit on their own. An object, an array, or a scalar can emit before a nested reference is followed. A root that cannot emit is rejected with `VLLMValidationError`, which already maps to HTTP 400.

The check runs in `_validate_structured_outputs` before a backend is chosen, and again in `validate_xgrammar_grammar` because tool parsers call that function directly. It has to be before backend selection. `auto` catches `VLLMValidationError` from xgrammar and falls back to guidance, and guidance accepts this schema.

#57788 by @RohitRathod0 started on this earlier and was a helpful reference. It raises the error inside `validate_xgrammar_grammar`, and on current main the `auto` path then switches to guidance, which still accepts the schema. This version runs the check before backend selection so that fallback can't happen, and it is written against current main after #60036.

`allOf` is not inspected. xgrammar does not implement it consistently. One `allOf` branch that is only a cycle allows no token, but that cycle next to an `anyOf` base case still allows a token. Several `allOf` branches are already rejected for xgrammar as an unsupported feature (#59061). Dangling and remote `$ref` values are left to the backend.

No model eval. The change rejects a schema before generation and does not change tokens for schemas that already validate.
