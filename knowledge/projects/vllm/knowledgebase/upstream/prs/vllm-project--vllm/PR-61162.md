# [Bugfix][MRV2][LoRA] Fix LoRA metadata binding for non-eager KV-sharing fast prefill

[Upstream PR](https://github.com/vllm-project/vllm/pull/61162) · state: open · merged: False

## Original PR description



## Overview

Follow-up to [#59067](https://github.com/vllm-project/vllm/pull/59067), which fixes eager MRV2 LoRA KV-sharing fast prefill. This PR fixes metadata binding and compact graph capture for Gemma3n and Gemma4 under compile-only, compiled PIECEWISE and breakable PIECEWISE execution.

## Claims

- Bind LoRA Linear and Embedding kernels to compact metadata in the compact cross-decoder, fixing the reproduced illegal memory access.
- Capture separate compact graphs for compiled and breakable PIECEWISE execution, preventing reuse of full-batch graphs for compact requests.
- Restore the original descriptor and LoRA mapping on success and failure.

## Validation

Gemma4 E2B tests used identical requests, nonzero rank-1 LoRAs, `TRITON_ATTN`, greedy sampling, disabled prefix caching and capture sizes 1/2/4. Each after-fix configuration ran three repeats of mixed-adapter, single-LoRA and one-token requests (12 requests, up to four generated tokens).

| Fast-prefill configuration | Before fix | After fix |
| --- | --- | --- |
| Compile-only (`VLLM_COMPILE`, CUDA Graph `NONE`) | CUDA illegal memory access on the first mixed base/LoRA batch | 12/12 completed |
| Compiled PIECEWISE | CUDA illegal memory access on the first mixed base/LoRA batch | 12/12 completed |
| Breakable PIECEWISE | Single-LoRA first token 95502 vs 711; first-row top-10 overlap 0/10 against full/eager in all three repeats | 12/12 completed |
| FULL_AND_PIECEWISE, two LoRAs | All 12 outputs differed from full prefill; 48/48 logits rows contained non-finite values | 12/12 completed |

After the fix, output IDs and top-1 matched same-mode full prefill (42/42 rows per configuration). Maximum logits differences span the vocabulary and exclude warmup:

| Fast-prefill path | Max abs. logits difference vs full | Minimum top-10 overlap vs full |
| --- | --- | --- |
| Compile-only | 3.0 | 9/10 |
| Compiled PIECEWISE | 0.5 | 9/10 |
| Breakable PIECEWISE | 0.5 | 10/10 |
| FULL_AND_PIECEWISE, two LoRAs | 0.78125 | 9/10 |

Against eager fast prefill, breakable logits matched bitwise; compile-only and compiled PIECEWISE matched output IDs and top-1, with maximum logits differences of 3.25 and 1.4765625. Logits matched across repeats within each process. These comparisons do not isolate the cause of fast/full numerical differences.

Full-prefill controls matched before/after output IDs and top-1 (42/42). Eager and breakable logits matched bitwise; FULL_AND_PIECEWISE had a maximum absolute difference of 1.25.

- Traces confirmed compact prefill, non-compact decode and both adapters in two-LoRA captures at 2/4 tokens. Padded dummy runs (3 to 4 tokens) passed before and after requests without compact metadata preparation.
- Gemma3n without LoRA in breakable PIECEWISE completed 6/6 requests: output IDs and top-1 matched full prefill (24/24), with maximum logits difference 0.625 and top-10 overlap 10/10.

Focused tests: 131 passed. Pre-commit checks and `git diff --check` passed.

Command: `pytest -q tests/lora/test_fast_prefill_lora_mapping.py tests/v1/cudagraph/test_cudagraph_manager.py tests/v1/cudagraph/test_breakable_cudagraph.py tests/v1/worker/test_attn_utils.py`.

Distributed execution, speculative decoding and alternative backends were not validated end-to-end.

## Details

The self-decoder uses the full batch; the cross-decoder uses only logits rows. Runtime context changes cannot rebind compiled metadata tensors, so a separate compact compilation unit binds the correct buffers. Batch descriptors select full or compact metadata and distinguish breakable graph entries. Compact graphs are captured before outer breakable graphs reference them, with weights owned by the existing cross-decoder and context restored in `finally`. FULL graph replay retains its full-batch path. The extra unit adds compilation and graph storage. Compact mapping preparation still includes GPU-to-CPU synchronization; its performance cost remains unmeasured.
