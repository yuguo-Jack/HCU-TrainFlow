# [Performance] Stream and split token-logprob reductions

[Upstream PR](https://github.com/vllm-project/vllm/pull/61742) · state: closed · merged: False

## Original PR description

## Summary

Implements the main kernel optimization proposed in #60095:

- Replace the two vocabulary scans with a numerically stable online log-sum-exp reduction in the one-program-per-row path.
- For small batches, split vocabulary rows across independent Triton programs, then merge partial log-sum-exp statistics and gather only requested token logprobs.
- Keep the single-row kernel for larger batches and when `VLLM_BATCH_INVARIANT` is enabled.
- Add CPU-interpreter regression coverage for FP32/FP16/BF16, non-power-of-two vocabulary sizes, all-`-inf` and partially masked rows, and requests for more than 1024 token logprobs.
- Allow `TRITON_INTERPRET=1` to use Triton when no accelerator driver is active.

## Validation

The new numerical regression test runs in a fresh subprocess with `TRITON_INTERPRET=1`, so it does not require a GPU or inherit earlier Triton imports.

**Not yet measured:** I do not have access to a CUDA benchmark host in this environment, so I am not claiming a throughput improvement number here. Before merging, please run the issue's required GPU benchmarks against the baseline and this branch, including small and large batches and with batch-invariant mode enabled.

Fixes #60095.

AI assistance was used for implementation; the code and design choices are submitted for maintainer review.
