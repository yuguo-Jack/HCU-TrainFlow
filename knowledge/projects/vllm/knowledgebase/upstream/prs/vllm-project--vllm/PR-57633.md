# [Bugfix][Spec Decode] Fix multimodal embedding merge in Llama 4 and Mistral Large 3 EAGLE drafters

[Upstream PR](https://github.com/vllm-project/vllm/pull/57633) · state: closed · merged: True

## Original PR description

## Purpose

Fixes #57630.

Regression from #50417 (first released in v0.28.0): that change marked these drafters as `SupportsMultiModalEmbeddings` so the speculator started routing multimodal batches through their `embed_input_ids`, which had been an unreachable alias of `SupportsMultiModal.embed_input_ids` until then. cc @TQCB

`EagleLlama4ForCausalLM` and `EagleMistralLarge3ForCausalLM` implement `SupportsMultiModalEmbeddings` by borrowing the method object `SupportsMultiModal.embed_input_ids`. That method calls `self._embed_text_input_ids(...)` and reads `self._has_oov_mm_tokens`, both of which live on `SupportsMultiModal`, which the drafters do not inherit. Any multimodal target paired with one of these drafters fails during the first draft prefill (already in the profile run at startup):

```
File "vllm/v1/worker/gpu/spec_decode/autoregressive/speculator.py", line 427, in _run_model
File "vllm/model_executor/models/interfaces.py", line 507, in embed_input_ids
AttributeError: 'EagleLlama4ForCausalLM' object has no attribute '_embed_text_input_ids'. Did you mean: 'embed_input_ids'?
```

Reproduced on main (bf13ecc) and present in v0.28.0 and v0.29.0 with `RedHatAI/Llama-4-Scout-17B-16E-Instruct-quantized.w4a16` + `morgendave/EAGLE-Llama-4-Scout-17B-16E-Instruct`, TP=4, `--speculative-config '{"method":"eagle","model":...,"num_speculative_tokens":3}'`, default cudagraph mode. The same aliasing exists in `EagleMistralLarge3ForCausalLM`; Model Runner V1 takes the same `embed_input_ids` path.

## Change

Replace the borrowed method with an explicit `embed_input_ids` in both drafters that embeds the draft input ids via `self.model.embed_input_ids` and merges external multimodal embeddings with `_merge_multimodal_embeddings`, the same shape `EagleMistralForCausalLM` already uses. No behavior change for text-only batches.
