# [ROCm][Perf][Bugfix] wvSplitK: launch tiles of their own for gfx1151 and gfx1150; fix bigType for A_CHUNK 16

[Upstream PR](https://github.com/vllm-project/vllm/pull/63835) · state: closed · merged: True

## Original PR description

## Overview

Faster wave32 `wvSplitK` on gfx1151 and gfx1150/gfx1152/gfx1153: one launch tile per arch, chosen from a sweep of every non-spilling launch configuration. Related: #63015 (gfx9 rows only), #62718 (moves these kernels to a header; textual conflict), #51511 (disables the skinny GEMM on gfx1151; this PR makes it faster there instead).

## Claims

- bf16/fp16 `wvSplitK` kernel time against `main`: +0.8% to +4.9% on gfx1150, +1.8% to +4.1% on gfx1151; 99.3-99.8% of the per-shape best tile (`main`: 96-98%).
- Fixes `bigType` for A_CHUNK = 16 (64 B instead of 32 B: reads past the activation row, overlapping LDS writes).
- GSM8K unchanged within noise.

## Validation

**Performance.** Interleaved A/B against `main`, cold caches, weights padded as at load, median of 5 rounds. 43 shapes x N = 1..5, bf16 and fp16; 13 shapes not used for tuning (odd M, K = 768/1000/2880 among them); bias on 4 shapes.

| | gfx1150 | gfx1151 |
|---|---:|---:|
| Shapes used for tuning | +1.8% to +1.9% | +2.7% to +3.0% |
| Other shapes | +0.8% to +4.9% | +1.8% to +3.2% |
| With bias | +1.7% | +4.1% |

Cells slower by more than 2%: at most 3 of 150 per dtype, none below 0.98x.

**Accuracy.** GSM8K, full set, 5-shot, greedy, a 1.5B bf16 instruct model, `max_num_seqs=5` (decode batches N = 1..5 through `wvSplitK`), gfx1151:

| | flexible-extract | strict-match |
|---|---:|---:|
| `main` | 0.5807 ± 0.0136 | 0.5307 ± 0.0137 |
| this PR | 0.5785 ± 0.0136 | 0.5292 ± 0.0137 |

3 and 2 of 1319 answers differ: the tile changes the summation order and `v_dot2_f32_bf16` the rounding.

```
lm_eval --model vllm --model_args pretrained=Qwen/Qwen2.5-1.5B-Instruct,dtype=bfloat16,max_num_seqs=5,max_model_len=4096,seed=0 \
  --tasks gsm8k --num_fewshot 5 --batch_size auto --gen_kwargs temperature=0 --seed 0
```

**Tests.**
- `pytest tests/kernels/quantization/test_rocm_skinny_gemms.py -k test_rocm_wvsplitk_kernel`: 126 passed on gfx1151, including new K % 16 != 0 and N = 5 cases. The file's other failures on gfx1151 (`test_rocm_wvsplitk_fp8_kernel`, `test_rocm_llmm1_kernel`) are the same 184 on `main`.
- All 43 shapes x N = 1..5, bf16/fp16, with and without bias, against `torch.nn.functional.linear`: correct on gfx1150 and gfx1151.
- `pre-commit` passes.

## Details

1. **`bigType` sized by A_CHUNK.** `half4` was (A_CHUNK / 2) x bf16; it is now 4 x bf16, the operand of its only consumer. No launch used A_CHUNK = 16 before this PR.
2. **bf16 `DOT2C` on gfx11/gfx12** issues `v_dot2_f32_bf16`, as fp16 issues `v_dot2_f32_f16`, instead of widening both operands to f32.
3. **Launch rows** (`WVSPLITK_CFG_AC` takes A_CHUNK; `WVSPLITK_CFG` keeps 8):
   - gfx1151: (YTILE 1, UNRL 4, A_CHUNK 16); (2, 4, 8) for K < 1024.
   - gfx1150, gfx1152, gfx1153: (2, 1, 16); (1, 2, 16) when M <= 32 * CUs.
   - A_CHUNK 8 when K % 16 != 0 (wider chunks give wrong results there).
   - Other archs: unchanged.

The sweep covered YTILE 1-4, UNRL 1/2/4/8, A_CHUNK 8/16/32 and WvPrGrp 16/32, excluding configurations that spill.
