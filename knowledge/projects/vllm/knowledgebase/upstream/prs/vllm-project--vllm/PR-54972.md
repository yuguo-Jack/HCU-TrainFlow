# [Bugfix][Offloading] UVA offloader: release the accelerator blocks it frees

[Upstream PR](https://github.com/vllm-project/vllm/pull/54972) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

With `--offload-backend uva --cpu-offload-gb N`, model loading can run out of GPU memory part-way through, whatever `N` is.

- Cause: offloaded weights free their GPU memory, but the caching allocator keeps it reserved.
- Fix: release that cached memory after each module is offloaded.

## Claims

- `torch.accelerator.empty_cache()` runs once per module that offloaded at least one parameter.
- It runs before the next module is built, so the freed memory can be reused.
- Modules that offload nothing do not flush the cache.
- No model eval: weights and forward computation are unchanged.

## Details

**Root cause**

- `_maybe_offload_to_cpu` copies each parameter to host and points `p.data` at the host copy.
- The old GPU storage is freed, but the caching allocator keeps the block reserved.
- With `expandable_segments:True`, the next module grows the segment instead of reusing that block.
- So reserved memory grows with every offloaded module, while live memory does not.

**Why per module**

- `make_layers` passes `wrap_modules` a lazy generator.
- Module N+1 is only built after module N is offloaded.
- Releasing once after the loop would be too late to prevent the OOM.

**Not covered**

- `PrefetchOffloader` drops GPU storage the same way and may have the same issue.
- I have not reproduced it there, so it is left out of this PR.

**Overlapping PRs**

- Several open PRs touch `uva.py`: #54610, #56413, #46690, #53981, #57215, #57472, #60299, #43453.
- None of them releases the cached blocks (checked their diffs on 2026-10-14).
- #46690 also adds `tests/model_executor/test_uva_offloader.py`, so that file may conflict.
