# [Test] Add Qwen3 streaming tool-call regression tests across stream intervals

[Upstream PR](https://github.com/vllm-project/vllm/pull/46274) · state: open · merged: False

## Original PR description

## Purpose

Regression coverage for #45256.

That issue reported that with `--stream-interval > 1`, the Qwen3 coder tool parser could emit **invalid JSON** in streamed `delta.tool_calls[].function.arguments` (e.g. `{"page": 1` with the final `}` dropped) when the closing `</parameter>`, `</function>` and `</tool_call>` tags arrived batched in a single delta.

The streaming parser engine introduced in #45413 replaced the old parser and fixes this. A maintainer noted on the issue that #45413 *likely* resolves it but asked for confirmation. I verified the fix against the current engine and am adding tests that **lock in** the behavior and document the `--stream-interval > 1` contract.

### Why this isn't already covered

The existing engine streaming tests (`tests/parser/engine/test_qwen3.py`) split the model output at tag boundaries (one tag per chunk) and only attach *special* token IDs to each chunk via `simulate_tool_streaming`. They therefore never exercise the case the report is about: several tokens — including the `<tool_call>` start, the `<function=...>` name, and multiple closing tags — landing in **one** delta, with the full per-token ID list that the serving layer actually passes to the parser.

## Changes

Adds `tests/parser/engine/test_qwen3_stream_interval.py`, which:

- feeds realistic `(delta_text, delta_token_ids)` pairs — the complete per-token ID list, with `<tool_call>`/`</tool_call>` as dedicated special tokens and the XML tags split into sub-word tokens;
- regroups the same token stream at a range of stream intervals (`1, 2, 3, 4, 5, 8, 13, 64`) to emulate `--stream-interval`;
- asserts the streamed arguments always accumulate to **valid JSON** equal to the non-streaming result, for both single- and multi-parameter calls.

The single-parameter case mirrors the exact `read_pdf(page=1)` reproduction from the issue. The assertions (`json.loads(args) == {...}`) fail on the pre-#45413 `{"page": 1` output, so these are meaningful guards.

No production code is changed.

feed fixed-size *text* chunks through the shared `simulate_tool_streaming` helper,
