# [Build] Install infiniband-diags for DeepEPv2 RDMA bandwidth detection

[Upstream PR](https://github.com/vllm-project/vllm/pull/63588) · state: open · merged: False

## Original PR description



## Overview

Install `infiniband-diags` (provides `ibstat`) in the runtime image, verify it at build time, and document it as a prerequisite for multi-node DeepEPv2. Fixes #62677.

## Claims

- The final `vllm-openai` image contains a working `ibstat`; the image build fails if it doesn't.
- Multi-node `--all2all-backend deepep_v2` no longer fails with `ZeroDivisionError` in `get_theoretical_num_sms()` because `ibstat` is missing.
- Docs explain that `ibstat` must be available inside the container and that DeepEP reads the NIC named by `EP_NIC_NAME` (default `mlx5_0`).

## Validation

- `pre-commit run --files <changed files>`: passed.
- `infiniband-diags` is in Ubuntu universe for 24.04 (50.0) and 22.04 (39.0), on amd64 and arm64. `ffmpeg` is installed from universe in the same stage.
- `ibstat --version` exits 0 before it opens any device (rdma-core `ibdiag_common.c`), so the build check works on builders without InfiniBand.

Deployment: 2 nodes × 8 B300, GLM-5.3, TP=8, DP=2, EP=16, `--all2all-backend deepep_v2`, Kubernetes LeaderWorkerSet.

CI does not exercise multi-node DeepEPv2; only the image build covers this change.

## Details

Root cause (DeepEP `d4f41e4e93`, pinned in `docker/Dockerfile`): `deep_ep/utils/envs.py::get_rdma_gbs()` runs `ibstat` and returns `0` on any failure. `ElasticBuffer.get_theoretical_num_sms()` then divides by it. vLLM calls this from `DeepEPV2All2AllManager.get_handle()`. `check_fast_rdma_atomic_support()` also runs `ibstat` and silently returns `False` without it, which changes QP allocation.

Catching the exception in vLLM is not enough because the SM count depends on the detected bandwidth. Guarding the zero belongs upstream in DeepEP.
