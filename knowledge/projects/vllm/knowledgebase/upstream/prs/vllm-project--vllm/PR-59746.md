# [Bugfix][NIXL] Pair P/D blocks by the last token with different block sizes

[Upstream PR](https://github.com/vllm-project/vllm/pull/59746) · state: open · merged: False

## Original PR description

## Overview

With different P/D block sizes, NIXL pull pairs D's and P's block lists by position, so KV lands in the wrong blocks, or D crashes, when the two lists start or end at different tokens. This pairs them by the request's last token and rejects DCP across different P/D logical block sizes.

## Claims

- With different P/D block sizes, D receives every page into the right block, also after a partial prefix hit on D or sliding-window clipping.
- Equal kernel blocks under different logical block sizes (e.g. FLASHINFER) land in the right blocks too, and D's EngineCore no longer dies on `assert num_decode_blocks <= len(prefill_group)`.
- DCP across different P/D logical block sizes is rejected at the handshake.
- Pulls between equal P/D block sizes are unchanged.
- Without `remote_num_tokens`, pulls between different P/D block sizes keep positional pairing and warn once per remote engine.

## Details

With different P/D block sizes:

1. P's scheduler returns its block ids and `remote_num_tokens` in `kv_transfer_params`, with the sliding-window blocks that left the window dropped.
2. D's scheduler hands NIXL its block ids past a local prefix hit, window-clipped the same way. The hit and the clipping start the two lists at different tokens, and each side pads to its own logical block past the last token.
3. D's pull pairs each group's block lists by position: `_map_block_ids_for_block_size_ratio` front-clips D's sub-blocks to P's count, then `_apply_prefix_caching` end-trims P to D's count. That holds only if both lists start and end at the same token, which step 2 breaks. Pages then land one or more blocks off.
4. D's receive post-process zeroes the sub-blocks the read did not cover.

Equal kernel blocks under different logical block sizes (e.g. FLASHINFER) shift pages the same way; when D's padded list is longer than P's, D's read fails `assert num_decode_blocks <= len(prefill_group)` and its EngineCore dies.

This drops each side's padding past the last of the `remote_num_tokens` that P already sends and pairs the lists backwards from there, once per request in `_read_blocks_for_req`. `ReadSpec.paired` keeps `_read_blocks` from mapping them again, and `ReqMeta.covered_sub_blocks` lets the receive post-process zero exactly what P doesn't send: D's padding, and D's leading sub-blocks when D's sliding window starts before P's.

DCP reads keep positional pairing, which needs equal logical block sizes because each side shards tokens at its own.

#51527 (draft) lets Mamba hybrids with different logical but equal kernel block sizes use prefix caching, pairing their full-attention groups from new scheduler metadata; it leaves the attention-only end-trim and the `block_size_ratio > 1` pairing fixed here unchanged. #60483 (draft) rejects different P/D DCP sizes when `--cp-kv-cache-interleave-size` differs from the block size; this PR rejects DCP across different P/D logical block sizes. #60484 rejects DCP peers with different interleave sizes; since NIXL sets the interleave to the block size by default, that overlaps this PR's DCP guard when both sides use DCP.
