# [CI][ROCm] Skip the AITER MoE garbage-rows test for fp8 per-tensor until the AITER fix

[Upstream PR](https://github.com/vllm-project/vllm/pull/63559) · state: closed · merged: True

## Original PR description

- `test_modular_kernel_combinations.py`: skip `test_aiter_moe_token_padding_garbage_rows` for fp8 per-tensor configs until the AITER fix is in the pinned `AITER_BRANCH`

`test_aiter_moe_token_padding_garbage_rows[single_inf-fp8_tensor_tensor]` and `[single_nan-fp8_tensor_token]` failed on MI300 in [amd-ci 15340](https://buildkite.com/vllm/amd-ci/builds/15340) with `mean |mk_out| = 0`. The bug is in AITER, not vLLM: `fused_moe_2stages` allocates `a2` with `torch.empty`, stage 1 never writes the slots of `topk_ids == -1` rows, and the dynamic per-tensor a2 quant then takes its scale over that stale memory, which can push every real row to fp8 zero. Per-token and block schemes scale row by row and are unaffected, so only configs with fp8 per-tensor weights (which the test runs with no static a2 scale) are skipped. The AITER fix is ROCm/aiter#6568; this guard should be removed when `AITER_BRANCH` includes it. #62927 targets the same failure from the vLLM side but does not fix it (details in that PR).

On MI350X with AITER v0.1.26, poisoning the caching allocator with 1e30 makes exactly the four skipped params fail (3/3 runs) while the other nine pass; nothing was run on MI300, where CI failed (1 failing nightly of ~10 since 2026-10-08). With the guard, the group runs 9 passed, 7 skipped. This adds a skip, which tests/AGENTS.md discourages; it is a temporary ROCm-only guard until the AITER bump, alongside the existing ROCm/aiter#6275 skip in the same test.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
