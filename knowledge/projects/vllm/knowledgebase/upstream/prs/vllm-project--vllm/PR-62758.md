# [ROCm] Include vLLM Router in runtime images

[Upstream PR](https://github.com/vllm-project/vllm/pull/62758) · state: closed · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

ROCm runtime images require an extra installation before users can run vLLM Router for DP-aware session affinity. Include `vllm-router==0.1.16` in the standard, ROCm 7.2, and gfx1250 runtime images.

## Claims

- Install the router alongside the vLLM wheel using each image's existing dependency constraints.
- Allow version overrides with `--build-arg VLLM_ROUTER_VERSION=...`.

## Validation

- `pre-commit run --files docker/Dockerfile.rocm docker/Dockerfile.rocm_72 docker/Dockerfile.rocm_gfx1250`: passed.
- `git diff --check`: passed.
- **Pending:** build the three runtime images and validate `vllm-router==0.1.16` in them. Docker/Podman are unavailable on the development host.
- Local nightly-container compatibility: installed `vllm-router==0.1.16` and its missing dependency `orjson` into the serving environment; all 332 existing packages retained their versions and locations, with no new dependency incompatibilities. Torch, Triton, MoRI, vLLM, FastAPI, and the router Rust extension import successfully.
- Local functional checks with four mock DP workers: c16/c32 conversation affinity, DP-rank headers, incremental SSE streaming, completion forwarding, `/v1/models`, error passthrough, and Prometheus metrics passed. All 64 tested sessions kept their rank across turns, version 0.1.14 to 0.1.16, and router restart.
- Real-model validation on DeepSeek-V4.1-Flash / 4× MI355X / DP4+EP4 passed: 96 requests across two-turn conversations at c16/c32, 48 streaming requests with usage, model discovery, and two 20,528-token prefix-reuse requests. The second request reused 20,352 tokens (99.14%); all 97 real conversation IDs stayed on their selected rank and exercised all four ranks.
- Real-rejection GSM8K sanity evaluation: **125/128 (97.66%)** through 0.1.16, matching the earlier direct-server check. This is a 128-question sanity check, not a full quality-parity evaluation.
- `uv pip install --system --dry-run "vllm-router==0.1.16"`: only router and `orjson` additions; no existing dependency changes. `<venv>/bin/python -c "import vllm_router_rs"` and `<venv>/bin/vllm-router --help`: passed.
- The one-hour AgentX performance profiles retain reference router 0.1.14 and are separate from this version verification.

Full runtime image builds remain pending CI; the current nightly container passed local installation, routing, and real-model verification.

## Details

During DeepSeek-V4.1-Flash DEP4 testing on MI355X, direct load-based routing between attention DP ranks caused later turns to reuse different KV caches and repeat prefill. The [NVIDIA DEP2 reference](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/39351570949/attempts/1) uses a separate DP-aware router with consistent hashing of AgentX's `X-Correlation-ID`. Shipping the router makes that deployment configuration available in the ROCm runtime image.

The package is image tooling, so it is installed in the runtime stages rather than added to vLLM's library requirements. Users launch and configure the router explicitly. For example, a four-rank worker can be fronted with:

```bash
vllm-router --worker-urls http://127.0.0.1:8000 \
  --port 8080 --policy consistent_hash --intra-node-data-parallel-size 4
```

Duplicate-work checks searched open PRs for ROCm/router image installation and inspected related changes. #58702 and #58757 document DP-aware routing; they do not install the package in ROCm runtime images. The other matching open PRs do not add this installation.
