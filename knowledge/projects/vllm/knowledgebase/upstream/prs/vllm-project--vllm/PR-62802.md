# [EPD] Support DeepSeek-V4.1 image metadata-only inputs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62802) · state: closed · merged: True

## Original PR description

## Overview

Support metadata-only image EPD for DeepSeek-V4.1-Flash so P/D can skip duplicate image preprocessing. Related to #52409.

## Claims

- Publish `llm_grid` through the existing EC metadata protocol and reconstruct identical image placeholder spans on the consumer.
- Accept image embedding references in the DeepSeek chat template while preserving image ordering and the raw-image path.

## Validation

GB200, PR `29e15453b1e4` (main `f1df4a3ae95e`), 2E (TP1 each) + PD (TP2), Mooncake RDMA, Model Runner V2 and CUDA Graphs. Same 512 task-stratified MUIRBench questions, concurrency 96. Each path used freshly started E/PD/proxy services, the same 1,736 synthetic-image warmup requests (disjoint from evaluation data), and one measured pass. Caches remained enabled.

| Metric | Raw images | Metadata-only | Change |
| --- | ---: | ---: | ---: |
| Total token/s | 17,645 | 19,618 | +11.19% |
| token/s/GPU | 4,411 | 4,905 | +11.19% |
| Mean E2E latency | 10.40 s | 9.30 s | -10.62% |
| P90 E2E latency | 12.41 s | 11.58 s | -6.68% |
| Accuracy | 62.11% (318/512) | 61.91% (317/512) | -0.20 pp |

All 1,024 requests succeeded; input/output token counts matched, no runtime JIT was detected, and every metadata-path request was rewritten. Throughput counts input + actual output tokens; per-GPU throughput divides by all four GPUs.

## Details

Reuses existing EC transport and metadata parsing; no proxy, scheduler, or model-runner changes. An image span contains `h * (w + 1) + 2` positions, so `llm_grid` is sufficient without pixels or layout tensors.

Open-PR searches found no duplicate EC implementation. #61418 instead optimizes routing metadata from source images for `/render`.
