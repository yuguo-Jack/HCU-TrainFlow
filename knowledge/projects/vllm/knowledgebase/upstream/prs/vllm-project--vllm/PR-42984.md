# Resolve silu mul quant padded NaN corruption correctness

[Upstream PR](https://github.com/vllm-project/vllm/pull/42984) · state: open · merged: False

## Original PR description

## Purpose

Addresses issue  no. 4 from #40047. Specifically, it addressed two points:

1. Failing `test_fp4_experts_quant_orphan_row_padding`

The core issue is that the underlying kernel  initialized rowIdx with 0 but uses this pattern:

`if (rowIdx >= current_offset && rowIdx < next_of) { ... }`

while scanning for expert to land. This means that orphaned rows get mapped to expert 0.

2. `test_fp4_experts_quant_no_cross_row_scale_corruption` failure

This test seems to break the 128-row M-tile alignment required by the swizzled SF layout (`mTileIdx = mIdx >> 7` in `cvt_quant_to_fp4_get_sf_out_offset`),  causing inter-expert scale region overlap. Fixed by computing blockscale_offsets with (rows + 127) // 128 * 128 rounding, matching compute_expert_blockscale_offsets in moe_data.cu:81

This PR includes a fixed version of that test which passes even without this PR. 

Note, the above tests were included as part of #40047.

## Test Plan

Add two tests:

* `test_fp4_experts_quant_orphan_row_padding` where this PR addresses the orphaned rows case noted above.
* `test_fp4_experts_quant_no_cross_row_scale_corruption` corrects the faulty test from #40047 where the test breaks because the 128-padding is violated.
