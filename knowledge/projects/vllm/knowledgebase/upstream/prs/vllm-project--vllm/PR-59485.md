# [HiSparse] Report host-pool block residency as HiSparse metrics

[Upstream PR](https://github.com/vllm-project/vllm/pull/59485) · state: closed · merged: True

## Original PR description

## Purpose

With HiSparse and `--kv-cache-metrics`, host-pool block residency (how long evicted prefixes stay recoverable from host) is not observable: since #58725 the host pool has no metrics collector, because sharing the device collector mixed host and device samples through colliding block IDs. Sizing `host_pool_gib` needs this signal.

This gives the host pool its own `KVCacheMetricsCollector` (same sample rate, only with `--kv-cache-metrics`) and reports its eviction samples through the scheduler-side HiSparse connector stats as:

- `vllm:hisparse_host_block_lifetime_seconds`
- `vllm:hisparse_host_block_idle_before_evict_seconds`
- `vllm:hisparse_host_block_reuse_gap_seconds`

Like the device `vllm:kv_block_*_seconds` histograms (which keep covering only the GPU pool), they are registered only with `--kv-cache-metrics` and use the same buckets and `custom_histogram_buckets` overrides.

```
pytest tests/v1/kv_connector/unit/test_hisparse_stats.py \
  tests/v1/kv_connector/unit/test_hisparse_connector.py tests/v1/core/test_kv_cache_metrics.py \
  tests/v1/worker/test_utils.py tests/v1/kv_connector/unit/test_multi_connector.py \
  -k "hisparse or host or stats or metrics"
```

`test_hisparse_host_residency_reported_as_hisparse_metrics` fails on main (the host pool records nothing) and passes here; it also checks that host evictions don't reach the device collector. `test_prom_metrics_observe_host_metrics[False]` checks the histograms aren't registered without `--kv-cache-metrics`.

E2E on 1×H100: shrunk DeepSeek-V3.2 (4 layers, dummy weights), FP8 KV, `--max-model-len 8192 --kv-cache-memory-bytes 2000000000`, `HiSparseConnector` with `host_pool_gib: 0.05` (319 host blocks, so it evicts), `--kv-cache-metrics --kv-cache-metrics-sample 1.0`. Load: `vllm bench serve --dataset-name random --random-input-len 2000 --random-output-len 16 --max-concurrency 4`, seeds 1 ×12, 2 ×4 twice (identical prompts, for host prefix hits), 3 ×16, 4 ×16.
