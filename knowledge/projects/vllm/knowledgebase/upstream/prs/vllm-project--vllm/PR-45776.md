# [DiffusionGemma-26B-A4B-it FP8][XPU][Quant] Enable native XPU FP8 MoE for per-token dynamic activations

[Upstream PR](https://github.com/vllm-project/vllm/pull/45776) · state: open · merged: False

## Original PR description

A compressed-tensors FP8_DYNAMIC MoE checkpoint (per-tensor weight scale, per-token dynamic activations) could not reach the native XPU MoE backend and failed with "Unsupported FP8 MoE backend: NONE". Two selection gates blocked it; both are fixed here (neither is sufficient alone):

1. XPUExpertsFp8._supports_quant_scheme: accept (kFp8StaticTensorSym, kFp8DynamicTokenSym). XpuFusedMoe takes unquantized activations and quantizes them inside the kernel, so per-token dynamic activation scaling is equivalent for its purposes.

2. CompressedTensorsW8A8Fp8MoEMethod.__init__: allow the (TENSOR weight, TOKEN activation) strategy combination (previously it fell through to an assert requiring BLOCK).

Scope: enables per-tensor-weight FP8 checkpoints on the native XPU MoE. Does not address per-channel weights, which still route to the Triton FP8 MoE fallback.

Validated serving DiffusionGemma-26B-A4B-it FP8 on 4x Intel Arc Pro B70; the log selects "Using XPU Fp8 MoE backend" and output is coherent.
