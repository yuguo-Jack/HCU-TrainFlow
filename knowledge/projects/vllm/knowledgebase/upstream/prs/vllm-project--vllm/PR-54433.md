## Original PR description

# [Spec Decode][Perf] Support vocab-parallel DSpark top-k for DeepSeek V4

## Purpose

The existing `dspark_draft_topk` optimization limits each sequential DSpark
Markov projection to the top-k base-logit candidates, but it is currently
usable only by Qwen3's single-rank draft vocabulary. DeepSeek-V4-Flash-0731
uses a full target vocabulary sharded across tensor-parallel ranks, so its
greedy DSpark path still all-gathers dense logits and evaluates the Markov
projection over the full vocabulary for every speculative step.

This change extends the opt-in path to DeepSeek-V4 DSpark:

- select top-k base logits locally on every vocabulary shard;
- all-gather only candidate values and global token IDs, then select the
  global top-k;
- gather the corresponding rows from the replicated Markov head and score
  only those candidates;
- sample the winning candidate sequentially, preserving the dependency on the
  previous draft token; and
- keep the existing dense path unchanged unless `dspark_draft_topk` is set.

For TP=8 and top-k=512, candidate communication is proportional to
`2 * k * TP` entries per row instead of the full 129,280-token vocabulary.
The new path is currently limited to greedy DeepSeek-V4 DSpark drafting; the
existing dense sampling path remains in use whenever draft logits are needed.

There is no linked issue.

## H200 profile and serving A/B

The controlled A/B was collected on upstream commit `9236159bb6` before the
final rebase. Both arms used the same source and server configuration except
for `dspark_draft_topk=512` in the candidate:

```text
8 x NVIDIA H200, TP=8, expert parallelism
FP8 KV cache, DSpark with 7 speculative tokens, greedy drafting
max_num_batched_tokens=8192, max_num_seqs=256
1024 input tokens -> 128 output tokens
32 prompts, concurrency=32, ignore_eos, temperature=0
five steady-state measurements per arm
```

| Metric | Dense baseline | top-k=512 | Change |
|---|---:|---:|---:|
| Output throughput | 830.80 token/s | 881.45 token/s | **+6.10%** |
| Per-run median TTFT | 493.38 ms | 461.62 ms | **-6.44%** |
| Per-run median TPOT | 23.50 ms | 23.02 ms | **-2.05%** |
| Draft acceptance | 47.66% | 51.36% | **+3.70 pp** |

For output throughput, an independent bootstrap with 200,000 resamples gave a
95% interval of `[+1.49%, +10.00%]`. The exact one-sided permutation p-value
was 0.01984 and the exact one-sided Mann-Whitney p-value was 0.04762.

This is an end-to-end result, not a pure kernel-time attribution. The candidate
also raised draft acceptance by 3.70 percentage points, so the measured gain
combines reduced computation/communication with the changed truncated proposal
distribution. A low-concurrency probe was noisy and did not establish a gain;
the feature therefore remains opt-in rather than becoming a default.

The TP8 trace attributed 59.71% of rank-0 GPU kernel time to communication and
showed 64 full-vocabulary all-gathers plus 224 sequential Markov projections in
the captured window. This optimization directly targets those two repeated
operations.
