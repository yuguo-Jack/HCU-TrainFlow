# [Attention] Add KV cache fake quantization (NVFP4/MXFP4 QDQ) for accuracy studies

[Upstream PR](https://github.com/vllm-project/vllm/pull/62454) · state: open · merged: False

## Original PR description

## Overview

Add an opt-in KV-cache **fake quantization (QDQ)** mode, `VLLM_KV_CACHE_FAKE_QUANT=nvfp4|mxfp4`, for studying the accuracy impact of 4-bit KV caches on hardware without FP4 KV kernels (e.g. ROCm). Off by default; no behavior change when unset.

## Claims

- With the flag set, K and V of every `Attention` layer are quantized and dequantized to NVFP4 or MXFP4 right after RoPE, before they are written to a plain BF16/FP16 KV cache. This reproduces the 4-bit numerical error while reusing the existing attention kernels.
- NVFP4 reuses vLLM's existing NVFP4 emulation (`ref_nvfp4_quant_dequant`); MXFP4 reuses the existing Quark `qdq_mxfp4` wrapper in `mxfp4_utils.py`. No new quantization math is added.
- This is an accuracy-study tool only. The cache stays BF16, so there is no memory or speed benefit.

## Validation

Operator level only so far (this is why the PR is a draft). On one ROCm GPU, random BF16 K/V of shape `[300, 4, 256]`:

- NVFP4 (vLLM emulation) vs an independent PyTorch reference (E2M1 grid, E4M3 block scale, per-16 blocks, global scale 1.0): 99.93% of elements identical, max abs diff 1.875 (one E2M1 step at rounding boundaries). Relative error vs input 9.5%.
- MXFP4: runs, shape/dtype preserved, relative error vs input 11.3%.

End-to-end results (MMLU-Pro and RULER-128K on a dense and an MoE Qwen model, FP8 KV as baseline) are in progress and will be added here before this leaves draft. Not yet verified: behavior under `torch.compile`/CUDA graphs, and each attention backend's cache-write ordering.

## Details

- `vllm/model_executor/layers/attention/kv_fake_quant.py` (new): reads the env var, and registers `kv_cache_fake_quant` as a custom op so `torch.compile` does not trace the Triton/Quark kernels.
- `Attention.forward`: applies the op to `key`/`value` after the reshape and before the cache update and attention call. Semantics are "fully quantized": the current step's attention also reads quantized K/V (more pessimistic than a kernel that attends to raw K/V for the current chunk).
- Requires `--kv-cache-dtype auto`; any other value raises at layer construction.
- Limitations: standard `Attention` only (MLA not covered); layers without a KV cache (e.g. linear-attention) are untouched; no per-layer format selection; no unit tests yet (the feature needs a ROCm GPU and Quark).
