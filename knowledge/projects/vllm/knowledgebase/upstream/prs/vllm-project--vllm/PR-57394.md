# [Bugfix] Reject empty logprob_token_ids and fix falsy validation in OpenAI request protocols

[Upstream PR](https://github.com/vllm-project/vllm/pull/57394) · state: open · merged: False

## Original PR description

## Purpose
Fixes #49319. Supersedes stalled PR #49320 by addressing review feedback from @NolenLiang.

In `ChatCompletionRequest`, `CompletionRequest`, and `BatchChatCompletionRequest`:
  - Explicitly check `is not None` and reject `logprob_token_ids=[]` with `VLLMValidationError`.
  - Skip length checks if input isn't a `list`, letting Pydantic handle type errors cleanly without crashing on `TypeError`.
  - Add `min_length=1` to `Field(...)` so the OpenAPI schema reflects `minItems: 1`.
  - Stop coercing `logprob_token_ids or None` in `to_sampling_params()`.

## Test Plan
Added standalone unit tests covering empty lists, non-list inputs, and missing `logprobs`:

```bash
pytest tests/entrypoints/openai/chat_completion/test_logprob_token_ids_validation.py
ruff check
ruff format --check
```

## Test Result

- Before: `logprob_token_ids: []` returned 200 OK (silently dropped to null), and non-list inputs like 1 caused a TypeError.
- After: Both return 400 Bad Request with clear error messages (must not be an empty list and Input should be a valid list).
