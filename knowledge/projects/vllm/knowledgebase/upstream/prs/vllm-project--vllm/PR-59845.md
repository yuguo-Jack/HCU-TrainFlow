# [Bugfix][Quantization] NVFP4 linear: keep each fused shard's global weight scale

[Upstream PR](https://github.com/vllm-project/vllm/pull/59845) · state: open · merged: False

## Original PR description

## Purpose

`KNvfp4Static.process` runs a fused NVFP4 linear (`q/k/v`, `gate/up`) under the max of its shards' global weight scales (`weight_scale_2`), and only warns when they differ. Every smaller shard is then dequantized `gs_max / gs_shard` times too large. ModelOpt quantizes each projection with its own per-tensor amax, so fused shards often do differ.

Example: `tiyuvta/GLM-5.3-Flash-NVFP4` (ModelOpt 0.46.0 W4A16) quantizes the shared experts and dense MLPs. Their gate/up global scales differ in nearly every MoE layer, with up/gate ratios from 0.46 to 2.51 across a layer sample, so one projection is inflated by up to 2.5x in every layer for every token. Greedy output stays coherent, which is why this hides. Sampled output at the checkpoint's own defaults (temperature 1, top_p 0.95) degenerates into multilingual word salad within a few hundred tokens.

## Changes

- `_reconcile_nvfp4_shard_global_scales`: before the shared max is taken, each smaller shard's e4m3 block scales are multiplied by `gs_shard / gs_max`.
  - The factor is at most 1, so block scales cannot overflow.
  - Each shard keeps its effective dequant scale within e4m3 rounding.
  - The FP4 payload is unchanged.
- Shared-scale checkpoints are bit-exact no-ops. The previous warning remains for layers whose shard widths (`logical_widths`) cannot be verified against `weight_scale`.
- This is the same policy as FP8's `requantize_with_max_scale` for fused linears, and as #55073 for NVFP4 MoE w13. #55073 does not touch the linear path.

## Related work

- #47515 fixes the same problem for **compressed-tensors** NVFP4 linears (`compressed_tensors_w4a4_nvfp4.py`). It is exact for two-partition layers, using a per-partition multiply on the GEMM output at runtime. This PR covers the **ModelOpt** path (`KNvfp4Static`, shared by W4A4 and W4A16), which #47515 does not touch. It handles any partition count at load time, at the cost of e4m3 rounding of the rescaled block scales. If reviewers prefer one approach for both paths, I can switch this to #47515's exact output rescale.
- #55073 / #54974 are the NVFP4 MoE w13 counterpart.
- No other open PR or issue covers the ModelOpt linear path. Searched `global weight scale differs across parallel layers`, `NVFP4 linear global scale fused` and `nvfp4 qkv weight_scale_2 max`.
