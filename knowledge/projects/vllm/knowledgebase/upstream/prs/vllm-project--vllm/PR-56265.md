# [Bugfix][Parser] Keep post-tool-call text in the DeepSeek-V3 non-streaming parse

[Upstream PR](https://github.com/vllm-project/vllm/pull/56265) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #56263. `DeepSeekV3ToolParser.extract_tool_calls` truncated content at the tool-calls block and never resumed, while `extract_tool_calls_streaming` emits the trailing text as content deltas. The parser disagreed with its own streaming mode, and non-streaming `/v1/messages` silently lost the trailing text. Content now spans the text before and after the tool-calls block. Hermes has the same truncation pattern (`hermes_tool_parser.py:109`) and is left for a separate discussion.

## Test Plan

.venv/bin/python -m pytest tests/tool_parsers/test_deepseekv3_tool_parser.py -v

## Test Result

New regression test `test_post_tool_call_text_kept_in_both_modes` fails without the fix and passes with it; full parser suite: 17 passed, 1 xfailed.
