# [Bugfix][Model] Don't carry realtime context into single-turn prompt models

[Upstream PR](https://github.com/vllm-project/vllm/pull/56218) · state: open · merged: False

## Original PR description

## Purpose

Fixes #51374. Fixes #51376.

`/v1/realtime` runs one resumable request per session, and
`Scheduler._update_request_as_session()` appends the previous chunk's output
tokens to the next chunk's prompt. That is right for models whose realtime
prompt is a running conversation and which consume `input_stream`. It is wrong
for Qwen3-ASR: `buffer_realtime_audio()` emits a fresh single-turn ChatML prompt
per 5 s segment and never reads `input_stream`, so the generic carry-over turns
the session into a growing fake conversation whose assistant turns are the
model's own transcripts. When a segment's acoustic evidence is weak, the decoder
reproduces that history.

Segment N+1's prompt today:

```
[segment N prompt] + [segment N output tokens] + [segment N+1 single-turn prompt]
```

This change lets the model class declare whether earlier segments belong in its
context, and rebuilds the session from the new chunk alone when they do not.
Text, multimodal features, KV and block hashes move together, which is the
invariant asked for in #51376.

## Measurements

vLLM at 144e79c, Qwen3-ASR-0.6B, one session per row, `temperature=0`. The
"alone" column is a fresh session containing only that audio, which separates
history contamination from the model's own behaviour on weak input.

English, using the `mary_had_lamb` and `winning_call` assets already in the repo:

| segment 2 audio | before | after | alone |
| --- | --- | --- | --- |
| a different utterance | correct but drifts | correct, matches alone | correct |
| digital silence | copy of segment 1 | `Ahora.` | `Ahora.` |
| white noise | copy of segment 1 | empty | empty |
| 1.2 s utterance + silence | copy of segment 1 | `And they.` | `And they.` |
| short utterance, reverse order | copy of segment 1 | `哎呀！` | `哎呀！` |

Mandarin (FLEURS `cmn_hans_cn`, public) behaves the same on all five rows. After
the change every second segment matches its solo control verbatim, and the word
drift in the first row disappears with it.

## The default path is unchanged

Flipping `realtime_carries_context` back to `True` for the same model on the same
audio reproduces the unpatched baseline byte for byte (`diff` reports no
difference). A unit test asserts the same at the scheduler level.

## Why this is per-model and not a scheduler-wide change

Voxtral realtime consumes `input_stream` and is built around cross-segment
context. In a separate environment on 0.29.0, applying the reset to it
unconditionally produced three empty segments where the unpatched path
transcribes three consecutive slices as one continuous sentence. I could not
re-run that check for this PR: the checkpoint does not load on either vLLM
version in my environment (`VoxtralRealtimeEncoderConfig` has no
`downsample_factor` with transformers 5.16/5.17), identically with and without
this change.

## Cost for opted-out models

12 segments: median first delta 53 -> 60 ms, median segment completion
314 -> 534 ms, still about 9x real time for 5 s segments. The "before" figures
are measured on contaminated output, so segment completion is not a
like-for-like comparison; first delta is unaffected by that.

## Alternative considered

#51037 keeps same-request KV reuse via a stable-window policy. That is the better
end state; this is the small correctness-first step and does not conflict with it
(a model that gains a stable-window implementation sets the flag back to `True`).
There was also an offer to investigate #51376 in August; this is meant as a
concrete starting point, not a claim on the issue.

## Design question for reviewers

The scheduler resolves the served model class once, lazily, on the first
streaming-session update. The same policy could instead ride on
`EngineCoreRequest`/`Request` next to `resumable`, set where `AsyncLLM` marks
streaming requests; that avoids the registry lookup in the scheduler at the cost
of touching more files. Happy to switch.

## Test Plan

- `python -m unittest tests/v1/streaming_input/test_scheduler_streaming.py`
- A seven-scenario realtime script on Qwen3-ASR-0.6B, English and Mandarin.

## Test Result

10 passed (8 existing, 2 new). Realtime scenarios as tabulated above.
