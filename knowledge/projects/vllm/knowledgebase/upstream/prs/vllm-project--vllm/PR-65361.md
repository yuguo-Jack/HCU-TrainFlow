# [Feature][LoRA] Coordinate MoE adapter admission and residency

[Upstream PR](https://github.com/vllm-project/vllm/pull/65361) · state: open · merged: False

## Original PR description

## Overview

This adds opt-in group-wide LoRA admission and residency for MRV2's internal MoE DP path. It follows the draft proposal in #65209.

Stacked on #61714 and #63077. The new work is [this incremental diff](https://github.com/MagellaX/vllm/compare/faf4a54103bee17f479786226c551404427e93ef...fad06f7a16afa54981c28f80f610db7e17704fe1); those prerequisites are included in the main-based diff. The latest [rollback delta](https://github.com/MagellaX/vllm/compare/867a0b4156151f41ae980b6db0b3911f44c91f56...fad06f7a16afa54981c28f80f610db7e17704fe1) is separate for review.

## Claims

- Bound the participating engines' adapter union by `max_loras`, including pins and running requests. Other adapters wait; free slots can be reused while unrelated requests continue.
- Register group-wide IDs so separate frontend counters cannot alias different adapters.
- Load through the existing managers, retire GPU readers before replacement, and publish readiness only after every worker acknowledges matching source fingerprints.
- Keep coordination out of the per-layer path and preserve existing adapter-buffer addresses. The feature is off by default.
- Roll back rejected updates from retained CPU objects, restoring cache order and pins before admission resumes. Lost workers or failed restoration still fail closed.

This does not duplicate the idle-preservation, residency-reporting, or slot-update work: it coordinates admission and eviction across engines rather than only managing each worker's local state.

## Details

Enable `--enable-group-lora-admission` with `--enable-lora` and `--all2all-backend allgather_reducescatter`. The controller lives separately from the scheduler; the scheduler only checks the admitted IDs.

This stays a draft. Each update retains the previous CPU models until all workers commit, so rollback does not depend on rereading a failed checkpoint. This can temporarily exceed the CPU cache budget; GPU buffer addresses remain stable. Rollback does not restart dead workers or recover invalid CUDA contexts. PP, external/hybrid DP, elastic EP, fault tolerance, streaming inputs, structured outputs and in-place adapter updates remain refused. Multi-node and multi-frontend end-to-end coverage are still outstanding. These are correctness results, not model-quality claims.

Docs are findable locally and on GitHub. The rendered preview is unavailable: [RTD build](https://app.readthedocs.org/projects/vllm/builds/35610032/) stops at the upstream contributor/label pre-run gate, before rendering; local changed-file checks passed.
