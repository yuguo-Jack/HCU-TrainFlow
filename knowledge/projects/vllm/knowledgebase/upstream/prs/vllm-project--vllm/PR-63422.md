# [CI] Add missing `&&` in the Multi-Modal Models (Standard) 3 command

[Upstream PR](https://github.com/vllm-project/vllm/pull/63422) · state: closed · merged: True

## Original PR description

## Overview

#59865 added the `test_qwen2_vl.py` line to `:intel: (BMG) Multi-Modal Models (Standard) 3` without a trailing `&&` on the line before it. The `>-` block therefore folds two pytest commands into one. This PR adds the `&&`.

## Claims

- `test_gemma_ragged_audio.py` and `test_qwen2_vl.py` run as two pytest commands again, as #59865 intended.
- The same 5 tests run as before. Only the process split and the `-m` value change.

## Validation

`DRY_RUN=1` of `run-intel-test.sh` on the step's parsed command:

```
# main
... && pytest -v -s models/multimodal/generation/test_gemma_ragged_audio.py -m 'core_model pytest' -v -s models/multimodal/generation/test_qwen2_vl.py -m core_model
# this PR
... && pytest -v -s models/multimodal/generation/test_gemma_ragged_audio.py -m core_model
    && pytest -v -s models/multimodal/generation/test_qwen2_vl.py -m core_model
```

In intel-ci build 15243 on `main`, the step passed with both files in one process (`collected 5 items`, `5 passed`). `pre-commit` passes.

## Details

Without the `&&`, pytest receives `... test_gemma_ragged_audio.py -m core_model pytest -v -s ... test_qwen2_vl.py -m core_model`. It works only by accident:
1. `run-intel-test.sh`'s `re_quote_pytest_markers` swallows the stray `pytest` into `-m 'core_model pytest'`.
2. The later `-m core_model` overrides that.
