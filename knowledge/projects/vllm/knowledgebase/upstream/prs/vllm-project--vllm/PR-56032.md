# [Bugfix][KV Offload] Recover from disk I/O failures

[Upstream PR](https://github.com/vllm-project/vllm/pull/56032) · state: open · merged: False

## Original PR description

## Purpose

Disk I/O errors can terminate a `SimpleCPUOffloadConnector` background thread
before it reports completion, leaving KV transfers pending.

Following discussion about the initial error-propagation approach, this revision
keeps the I/O thread available for subsequent transfers and reports failed loads
through the scheduler's existing recompute/fail policy.

- Handle disk syscall errors and short reads/writes within the transfer loop.
  Drain outstanding DMA before publishing completion or reusing buffers.
- Skip unreadable blocks while continuing other loads in the same batch.
  Single-group loads report failed block IDs, preserving the valid prefix.
  Multi-group loads use `KVConnectorTransferResults.failed_recving`, following
  upstream #56855. Transfer positions identify affected requests even when
  block IDs overlap, and the mapping survives later idle steps.
- Invalidate failed disk cache entries before releasing their references.
  Failed stores are discarded after all ranks report completion, without
  publishing incomplete data as valid cache.
- Drain queued disk work before preempted blocks are reused. Device setup,
  CUDA, event, and stream synchronization failures remain fatal.

Recomputation uses the existing `kv_load_failure_policy="recompute"` setting.
The default, `"fail"`, ends affected requests. This PR does not change the core
scheduler or add a new failure-policy option.

Related PRs cover different work: #52838 targets `OffloadingConnector`, and
#55424 addresses O_DIRECT alignment. This change handles failure recovery in
SimpleCPUOffload's disk backend.

## Test Plan

The added real-file checks reuse the existing threaded disk/worker fixture,
with synchronous CPU tensor copies replacing GPU DMA. They exercise:

1. Real file writes and reads, with byte-for-byte round-trip checks.
2. A real short read after truncating the isolated cache file: only the missing
   block fails, and its destination never receives stale staging-buffer data.
3. One injected `EIO` at the read syscall boundary, scoped to the cache file
   descriptor and selected block offset.
4. One injected `ENOSPC` at the write syscall boundary, with store failure
   metadata reaching the worker's output.

Every failure case verifies a later successful real-file store/load using the
same threads. The EIO and ENOSPC cases inject exceptions; the short-read case
uses actual file truncation. Filesystem I/O is buffered (`use_page_cache=True`).

To run these four checks:

```sh
.venv/bin/python -m pytest tests/v1/simple_kv_offload/test_disk_errors.py \
  -k test_disk_real_ -v
```

Full local validation command (macOS arm64, without CUDA):

```sh
VLLM_TARGET_DEVICE=cpu HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
VLLM_NO_USAGE_STATS=1 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 \
.venv/bin/python - <<'PY'
import pytest

class CpuOnlyCleanup:
    def pytest_collection_modifyitems(self, items):
        for item in items:
            item.add_marker(pytest.mark.skip_global_cleanup)

raise SystemExit(pytest.main([
    "tests/v1/simple_kv_offload",
    "tests/v1/kv_connector/unit/test_kv_load_failure_recovery.py",
    "tests/v1/kv_connector/unit/test_simple_cpu_offload_connector.py",
    "tests/v1/kv_connector/unit/test_output_aggregator.py",
    "tests/v1/executor/test_multiproc_executor.py",
    "-q", "--tb=short",
], plugins=[CpuOnlyCleanup()]))
PY
```

The local plugin applies the existing `skip_global_cleanup` marker to avoid
a host PyTorch allocator-cleanup crash. It does not patch connector behavior.
On a supported test host, use `.venv/bin/python -m pytest` with the same paths.
