# [Tool Parser] Fix truncated/unclosed DSML parameters and add incremental DSML arg streaming

[Upstream PR](https://github.com/vllm-project/vllm/pull/62259) · state: open · merged: False

## Original PR description

## Purpose

Part of #62051 (the truncated/unclosed-parameter rows only; the block with no invoke, the cut inside a tool name, and the V4 spellings are not addressed here, so the issue should stay open) and extends the `arg_value_extender` incremental streaming architecture (introduced for `qwen3_xml` in #62027 and `minimax_m2` in #62035) to the DeepSeek DSML parsers (`deepseek_v32`, `deepseek_v4`, and `deepseek_v41`).

### Problem (#62051)
1. **Unclosed / Truncated DSML Parameters Produce Invalid JSON on Stream Flush**:
   - In `_dsml_args_to_json(raw_args, partial)`, trailing unclosed `<｜DSML｜parameter name="..." string="...">...` tags were matched via `_PARTIAL_PARAM_RE` **only when `partial=True`**.
   - When `partial=False` (called during `extract_tool_calls(...)` or during `_flush_arg_converter()` at `</｜DSML｜invoke>` / `finish_streaming()`), `_PARTIAL_PARAM_RE` was skipped.
   - As a result:
     - **Case 1 (Truncated at `max_tokens`)**: During streaming, `converter(raw_args, True)` emitted `{"url": "https://example.com` (`prev_converted_len > 0`). On `finish_streaming()`, `_flush_arg_converter()` called `converter(raw_args, False)` which returned `"{}"` (length 2 < `prev_converted_len`), so no closing `"}` delta was emitted—leaving clients with invalid, unclosed JSON (`{"url": "https://example.com`).
     - **Case 4 (Model omits `</｜DSML｜parameter>` before `</｜DSML｜invoke>`)**: Non-streaming `extract_tool_calls` dropped the parameter (`{}`), while streaming emitted unclosed JSON (`{"file_path": "/tmp/a`).
2. **Quadratic Re-conversion of Long DSML Tool Arguments**:
   - Unlike `Qwen3Parser` (#62027) and `MinimaxM2Parser` (#62035), DeepSeek DSML parsers lacked an `arg_value_extender` and re-ran full regex conversion over `slot.args` whenever `>` appeared inside streamed argument content (e.g., code, HTML, shell redirects, markdown).

### Solution
1. **Consistent Unclosed Parameter Recovery + Partial Tag Holdback**:
   - Extract `_dsml_parse_args` so trailing unclosed `<｜DSML｜parameter ...>` blocks at the end of `raw_args` are recovered in both `partial=True` and `partial=False`.
   - Add `_value_end_window(text, value_end_re)` using `regex.fullmatch(..., partial=True)` against `</｜DSML｜parameter>|<｜DSML｜parameter\s+name=` so any trailing suffix of an open parameter value that could still complete into a closing or sibling parameter tag is held back during `partial=True` streaming (since `DeepSeekV4Parser` has no lexer transitions on `PARAM_START`/`PARAM_CLOSE` in `TOOL_ARGS`).
   - Hold back `_unwrap_wrapper_args` when `partial=True` and a single `arguments`/`input` wrapper parameter contains an incomplete JSON string, preventing premature streaming of `"arguments": ` before unwrapping.
2. **Incremental DSML String Argument Streaming (`_dsml_arg_value_extender`)**:
   - Implement `_dsml_arg_value_extender` for `deepseek_v4`, `deepseek_v41`, and `deepseek_v32`, streaming open `string="true"` DSML parameter values in $O(1)$ conversions with respect to argument length (reducing partial converter calls on a 200-line `write_file` call from 206 to 6).

## Test Plan
