# [CPU] Add BF16 fallback for MXFP4 MoE without AMX

[Upstream PR](https://github.com/vllm-project/vllm/pull/61346) · state: open · merged: False

## Original PR description

## Overview

Add a BF16 fallback for MXFP4 MoE checkpoints on CPUs without a native AMX kernel. Addresses #61027 while retaining the AMX capability check and preferring the existing native backend when available.

## Claims

- Automatic selection and `--moe-backend cpu` can select portable CPU experts for BF16 activations on non-AMX CPUs.
- Decode packed E2M1 expert weights and per-32 E8M0 scales once at load time, then reuse CPU grouped GEMM. Preserve checkpoint layout, GPT-OSS interleaved SwiGLU, bias handling and routing.
- Share the existing FlashInfer load-time MXFP4 decoder through the quantization utilities and document the approximately 4x expert-weight storage requirement.

## Validation

Base: `df6c7ad03194a3051a197d57ca4a94e4a063014e`. Validation ran on Linux aarch64 in the existing CPU container, with PyTorch 2.13.0 and Python 3.12.15. Current Python sources were overlaid on native binaries from `43b4aaea3`; this was not a native build of the base commit.

```bash
.venv/bin/python -m pytest tests/kernels/moe/test_cpu_fused_moe.py \
  -k 'mxfp4 or shape_support or (128 and not 2880 and vec)' \
  -q --tb=short -p no:cacheprovider
```

Result: **52 passed, 474 deselected**, including 18 new cases. These cover native-AMX preference and non-AMX selection, both checkpoint conversion paths, independent bit-level dequantization including E8M0 special values, and actual CPU expert outputs with and without bias. This is a targeted suite, not the full CPU or vLLM suite.

All applicable pre-commit hooks passed, including Ruff, mypy, SPDX and test tethering. `git diff --check` passed.

A seeded two-layer GPT-OSS model (hidden size 128, intermediate size 96, four experts, top-k two, vocabulary 128) was saved both as an MXFP4 checkpoint and as an independently decoded BF16 checkpoint. On three tokenized prompts, each producing eight greedy tokens, both paths returned identical tokens and top-five log probabilities (maximum difference 0.0). Replacing the four modified implementation files with their exact base-commit contents causes the MXFP4 model to fail initialization with no supported backend.

The engine comparison required a diagnostic-only adapter for the separate upstream CPU slot-mapping signature mismatch already addressed by #61151. The adapter was applied identically to both paths and is excluded from this PR. Unadapted generation at this base still encounters that upstream bug. These are random-weight correctness checks, not pretrained-model accuracy results or performance claims; AMD EPYC, zentorch, native AMX execution and distributed deployments have not been tested.

A `vllm bench latency` smoke run on the same two-layer MXFP4 architecture, with vocabulary 32,000, batch size two, eight input/output tokens, one warmup and three measured iterations, completed with a mean latency of 11.94 ms. This also used the diagnostic slot-mapping adapter and is only a CLI/model execution check, not a production performance result.

## Details

The AMX guard is necessary for the native kernel. This fallback instead uses an existing unquantized CPU implementation after expanding expert weights to BF16. It supports loading MXFP4 checkpoints when sufficient host RAM is available, but does not preserve packed MXFP4 memory usage. It logs a warning about expanded expert storage; loading also requires temporary buffers. Scales remain attached to the layer so later quant-config inspection retains the established parameter contract.

Duplicate checks on 2026-10-13 found no linked implementation for #61027 or overlapping CPU MXFP4 fallback PR. Existing native AMX support remains intact. The separately owned #61151 is used only to identify the integration-test limitation.

Codex assisted with backend investigation, implementation, tests, validation and this description.

<summary>Reproduce the model comparison and CLI smoke check</summary>

Save this as `/tmp/cpu_mxfp4_smoke.py`. From the checkout in a CPU vLLM environment, run `PYTHONPATH="$PWD" .venv/bin/python /tmp/cpu_mxfp4_smoke.py` for the paired comparison, or append `benchmark` for the CLI smoke check. The CPU slot-mapping adapter is deliberately confined to this diagnostic.

```python
"""Deterministic, random-weight GPT-OSS checkpoint smoke test; no model download."""

import json
import subprocess
import sys
from pathlib import Path

import torch

ROOT = Path("/tmp/cpu-mxfp4-probe")


def prepare(vocab_size=128):
    from safetensors.torch import save_file
    from transformers import GptOssConfig, GptOssForCausalLM

    from tests.quantization.reference_mxfp4 import dq_mxfp4_torch

    torch.manual_seed(17)
    config = GptOssConfig(
        hidden_size=128, intermediate_size=96, num_hidden_layers=2,
        num_attention_heads=2, num_key_value_heads=1, head_dim=64,
        num_local_experts=4, num_experts_per_tok=2, vocab_size=vocab_size,
        max_position_embeddings=128, sliding_window=64,
    )
    config.architectures = ["GptOssForCausalLM"]
    model = GptOssForCausalLM(config).to(torch.bfloat16)
    quantized = {}
    for layer_id, layer in enumerate(model.model.layers):
        for name, rows, columns in (("gate_up_proj", 192, 128), ("down_proj", 128, 96)):
            packed = torch.randint(0, 256, (4, rows, columns // 2), dtype=torch.uint8)
            scales = torch.randint(119, 122, (4, rows, columns // 32), dtype=torch.uint8)
            decoded = dq_mxfp4_torch(packed, scales, torch.bfloat16)
            getattr(layer.mlp.experts, name).data.copy_(decoded.transpose(-1, -2))
            prefix = f"model.layers.{layer_id}.mlp.experts.{name}"
            quantized[prefix + "_blocks"] = packed
            quantized[prefix + "_scales"] = scales
    reference = ROOT / "bf16"
    quant = ROOT / "mxfp4"
    model.save_pretrained(reference)
    state = dict(model.state_dict())
    for key in list(state):
        if key.endswith(("experts.gate_up_proj", "experts.down_proj")):
            del state[key]
    state.update(quantized)
    quant.mkdir(parents=True, exist_ok=True)
    save_file(state, quant / "model.safetensors", metadata={"format": "pt"})
    config.quantization_config = {"quant_method": "mxfp4"}
    config.save_pretrained(quant)


def install_cpu_slot_mapping_adapter():
    # Upstream df6c7ad's CPU slot-mapping replacement still has the old
    # positional signature. Adapt it only in this diagnostic, identically
    # for both checkpoints; do not count this as unmodified-engine validation.
    import vllm.utils.cpu_triton_utils as cpu_triton

    def slot_mapping(num_tokens, max_num_tokens, query_start_loc_ptr, positions_ptr,
                     block_table_ptr, block_table_stride, slot_mapping_ptr,
                     KV_CACHE_BLOCK_SIZE, TOTAL_CP_WORLD_SIZE, TOTAL_CP_RANK,
                     CP_KV_CACHE_INTERLEAVE_SIZE, PAD_ID, BLOCK_SIZE):
        assert TOTAL_CP_WORLD_SIZE == 1
        torch.ops._C.compute_slot_mapping_kernel_impl(
            query_start_loc_ptr, positions_ptr, block_table_ptr,
            slot_mapping_ptr, KV_CACHE_BLOCK_SIZE,
        )

    cpu_triton._compute_slot_mapping_kernel_impl = slot_mapping


def generate(kind):
    install_cpu_slot_mapping_adapter()
    from vllm import LLM, SamplingParams

    llm = LLM(
        model=str(ROOT / kind), dtype="bfloat16", skip_tokenizer_init=True,
        max_model_len=64, max_num_seqs=4, max_num_batched_tokens=128,
        enforce_eager=True, enable_prefix_caching=False,
        enable_chunked_prefill=False, disable_log_stats=True, seed=17,
    )
    prompts = [{"prompt_token_ids": ids} for ids in ([1, 2, 3], [4, 5, 6, 7], [25, 26])]
    results = llm.generate(
        prompts, SamplingParams(temperature=0, max_tokens=8, ignore_eos=True, logprobs=5),
        use_tqdm=False,
    )
    output = []
    for result in results:
        generated = result.outputs[0]
        output.append({
            "tokens": list(generated.token_ids),
            "logprobs": [{str(k): v.logprob for k, v in item.items()}
                         for item in generated.logprobs],
        })
    (ROOT / f"{kind}.json").write_text(json.dumps(output))


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "benchmark":
        # bench latency samples token IDs below 10,000.
        prepare(vocab_size=32000)
        install_cpu_slot_mapping_adapter()
        from vllm.entrypoints.cli.main import main

        sys.argv = [
            "vllm", "bench", "latency", "--model", str(ROOT / "mxfp4"),
            "--dtype", "bfloat16", "--skip-tokenizer-init", "--enforce-eager",
            "--max-model-len", "64", "--max-num-seqs", "4",
            "--max-num-batched-tokens", "128", "--input-len", "8",
            "--output-len", "8", "--batch-size", "2",
            "--num-iters", "3", "--num-iters-warmup", "1",
        ]
        main()
    elif len(sys.argv) > 1:
        generate(sys.argv[1])
    else:
        prepare()
        for kind in ("mxfp4", "bf16"):
            subprocess.run([sys.executable, __file__, kind], check=True)
        quant = json.loads((ROOT / "mxfp4.json").read_text())
        reference = json.loads((ROOT / "bf16.json").read_text())
        max_error = 0.0
        for q, r in zip(quant, reference, strict=True):
            assert q["tokens"] == r["tokens"], (q["tokens"], r["tokens"])
            for a, b in zip(q["logprobs"], r["logprobs"], strict=True):
                assert a.keys() == b.keys(), (a.keys(), b.keys())
                max_error = max(max_error, *(abs(a[k] - b[k]) for k in a))
        assert max_error < 0.04, max_error
        print(json.dumps({"prompts": 3, "tokens_each": 8,
                          "tokens_equal": True, "max_top5_logprob_error": max_error}))
```
