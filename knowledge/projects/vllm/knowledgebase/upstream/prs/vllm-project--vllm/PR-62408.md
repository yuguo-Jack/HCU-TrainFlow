# [Bugfix][Metrics] Preserve FFN layer contributions under pipeline parallelism

[Upstream PR](https://github.com/vllm-project/vllm/pull/62408) · state: open · merged: False

## Original PR description



## Overview

Fix FFN FLOPs and memory-traffic underestimation when dense/MoE layer counts are not divisible by pipeline parallel size.

## Claims

- Preserve fractional average-stage contributions for dense, routed and shared FFNs.
- Keep all breakdown outputs integer-valued.

## Validation

```sh
.venv/bin/python -m pytest tests/v1/metrics/test_perf_metrics.py -q
# 75 passed

.venv/bin/pre-commit run --files vllm/v1/metrics/perf.py tests/v1/metrics/test_perf_metrics.py
# All applicable hooks passed
```

Three parameterized regression cases check contribution conservation and integer outputs. Additional CPU validation with four official model configs at PP=1/2/4 passed all 36 breakdown checks.

For [GLM-5.3](https://huggingface.co/zai-org/GLM-5.3/blob/ba32f8c19c8738e2c57c71798c601d477a7bf844/config.json), TP8/PP2 with four prefill tokens changes FFN FLOPs/device from 12,796,821,504 to the expected 13,079,937,024, fixing a 2.16% underestimate.

Validation covers estimator arithmetic on CPU. GPU serving was not tested; model-output evaluation is not applicable to this metrics-only change.

## Details

Flooring dense and MoE layer counts separately discards contributions: GLM-5.3 at PP=2 counts `1 dense + 37 MoE` instead of the average `1.5 dense + 37.5 MoE`. Retain fractional counts until final integer conversion, consistent with `AttentionMetrics` after #55624.

Duplicate checks on 2026-10-19 found no matching open fix. Related #54228 changes activated-expert estimation and #58836 adds linear-attention accounting; neither fixes FFN PP division.
