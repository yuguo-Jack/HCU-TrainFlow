# [Perf][Frontend] Reduce sampled-logprob return-path overhead

[Upstream PR](https://github.com/vllm-project/vllm/pull/65571) · state: open · merged: False

## Original PR description



## Overview

Reduce the CPU cost of returning sampled logprobs by transporting narrow rows as Python lists, caching single-token strings, retaining bounded DELTA history, and reusing serialized completion-stream frames. HTTP fields and values stay unchanged.

## Claims

- Narrow sample-logprob rows avoid per-array IPC hooks; rows wider than 33 columns retain the NumPy path.
- Repeated token strings and cumulative streaming history no longer repeat unnecessary frontend work. Non-final completion frames use a guarded template and fall back to the existing response models when needed.
- The supplied benchmark archive reports +32.9% / +51.0% throughput for streamed completions with logprobs 1 / 5 on Qwen3-8B, one H100. These historical results have **not** been rerun on this rebased branch.

## Details

`EngineCoreRequest.return_logprob_rows` opts compatible clients into `EngineCoreOutput.new_logprob_rows`. Both new fields are appended to preserve array-like message compatibility; the default remains the array form for other clients. The width gate is evaluated for the whole step, so opted-in readers must handle either representation on every output. The transport contract is documented in the architecture overview.

The cache stores original token strings, before context-dependent UTF-8 repair. DELTA outputs retain the four positions repair needs after delivering their full delta; cumulative outputs retain their history. Completion templates are derived from the real response model and checked against pydantic once per process. Per-chunk usage, token IDs, final fields and unsupported scalar types retain model serialization.

Related open work was inspected before preparing this PR:

- [#42211](https://github.com/vllm-project/vllm/pull/42211) deduplicates decoding **within one conversion call**. This change instead keeps a vocabulary-bounded cache on the tokenizer across calls, and also optimizes IPC/history/stream framing. It does not copy that PR's implementation.
- [#62342](https://github.com/vllm-project/vllm/pull/62342) optimizes **non-streaming** response construction and serialization; its description explicitly leaves streaming and the engine output path unchanged. This PR covers those paths.

No new dependency, public API option, logits computation or sampling rule is introduced. The cache consumes bounded memory proportional to the tokenizer vocabulary. Wide-row fallback prevents large-K Python object construction on the engine thread. GPU timing, distributed execution and the GPU sync check were not rerun locally.

Prepared with AI assistance. The tests use real protocol objects and a locally constructed tokenizer; new integration coverage uses the existing real OpenAI server fixture. Human review and current-branch GPU validation remain pending.
