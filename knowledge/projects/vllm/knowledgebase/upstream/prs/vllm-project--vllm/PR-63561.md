# [Quantization] Prefer Humming over Marlin for int4 g128 on SM100

[Upstream PR](https://github.com/vllm-project/vllm/pull/63561) · state: open · merged: False

## Original PR description



## Overview

On SM100, prefer Humming over Marlin for dense int4 symmetric group-128 weights. Extends #56997 (SM90); roadmap #61024.

## Claims

- 3.1x faster 4k prefill on `RedHatAI/Qwen3.8-27B-INT4`, decode unchanged.
- `vllm bench serve`: TTFT 2.6-3.6x lower and TPOT flat at concurrency 1/8/32 ([raw results](https://github.com/vllm-project/vllm/pull/63561#issuecomment-6412985534)).
- Group-32/zero-point weights keep Marlin, where Humming decodes 5-6% slower.

## Test Plan

```text
pytest tests/kernels/quantization/test_scaled_mm_kernel_selection.py -> 27 passed, 1 skipped
LLM(RedHatAI/Qwen3.8-27B-INT4) -> Using HummingLinearKernel for mixed-precision linear
LLM(cyankiwi/Qwen3.8-27B-AWQ-INT4) -> Using MarlinLinearKernel for mixed-precision linear
```

Decode step = (T(out=128) - T(out=1)) / 127 at 128 input tokens; 2 interleaved rounds, spread < 0.5%.

| Qwen3.8-27B, 1xB200 | Marlin (main) | Humming |
|---|---|---|
| INT4 g128 sym, prefill 4k | 555.5 ms | **179.6 ms** |
| INT4 g128 sym, decode bs1 / 8 / 32 | 8.15 / 8.72 / 12.00 ms | 8.11 / 8.71 / 12.12 ms |
| AWQ g32 asym, decode bs1 / 8 / 32 | 8.30 / 8.89 / 12.20 ms | 8.83 / 9.38 / 12.78 ms |

## Details

MoE and other formats unchanged; SM103 untested.
