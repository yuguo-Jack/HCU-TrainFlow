# Fix GPT-OSS weight loading for DP and EP

[Upstream PR](https://github.com/vllm-project/vllm/pull/51130) · state: open · merged: False

## Original PR description

## Summary

Fix GPT-OSS BF16 weight loading for pure data parallelism (DP) and data parallelism with expert parallelism (DP+EP).

## Root cause

In pure DP mode, `FusedMoE` folded the DP world size into its internal tensor-parallel configuration. This incorrectly sharded expert weights across DP replicas, producing a parameter dimension of 1440 while the checkpoint dimension was 2880.

In DP+EP mode, the expert start and end bounds were passed in reverse order. This produced empty slices such as `[16:0]` and `[32:16]`, so the parameter contained 16 local experts while the sliced checkpoint weight contained zero experts.

## Fix

- Use `dp_size=1` for `FusedMoE` when expert parallelism is disabled, ensuring that each DP rank owns a complete model replica.
- Replace expert start/end slicing with explicit `expert_offset` and `expert_length`.
- Use `weight.narrow(0, expert_offset, expert_length)` for expert weights.
- Pass loader arguments by keyword to prevent argument-order mistakes.
- Handle arbitrary EP world sizes and uneven expert counts without hard-coding DP/EP size 2.
- Apply the same offset/length convention to BF16 and MXFP4 loading paths.

## Validation

- Pure DP loaded all 5/5 checkpoint shards on both ranks.
- Each pure-DP rank loaded the complete model (`39.2461 GiB`).
- DP+EP loaded all 5/5 checkpoint shards.
- EP rank 0 loaded experts 0–15.
- EP rank 1 loaded experts 16–31.
- Both configurations started successfully and returned HTTP 200 chat-completion responses when configured with sufficient GPU memory.

The original `--gpu-memory-utilization 0.3` setting was sufficient to reproduce and verify the weight-loading failure, but it is too low to allocate KV cache after loading this BF16 checkpoint on 64 GiB GPUs. End-to-end validation used `0.8` for pure DP and `0.5` for DP+EP, with `--enforce-eager` to avoid an unrelated ROCm/NCCL graph-capture issue.
