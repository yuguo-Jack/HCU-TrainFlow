# [Perf][Spec Decode] Defer GDN spec decode state stores to the next step

[Upstream PR](https://github.com/vllm-project/vllm/pull/61434) · state: open · merged: False

## Original PR description

## Overview

When the Triton GDN spec decode kernel runs with an FP32 state and `mamba_cache_mode="none"`, it now stores the recurrent state once per step instead of once per draft token. It records the raw inputs of the remaining tokens, and the next step replays only the accepted ones.

## Claims

- Qwen3.8-27B + `z-lab/Qwen3.8-27B-DFlash2` (7 draft tokens) on MI355X: output throughput is +5.6% at concurrency 16 and +10.6% at concurrency 64. Concurrency 1 is unchanged.
- The GDN spec decode kernel drops from 347 µs to 225 µs (N=64, T=8, HV=48, K=V=128).
- Outputs match per-token state storage up to fp32 reduction order. Acceptance length is unchanged.

## Details

**Why.** The spec decode path of `fused_sigmoid_gating_delta_rule_update` writes the full state (HV×V×K fp32) after every token, so the next step can resume from slot `num_accepted - 1`.
- For Qwen3.8-27B that is 3 MB per sequence per layer per token, and most of those states are thrown away.
- In a c=64 profile this kernel took 18% of GPU time.

**How.** With `defer_spec_state=True`:
- Slot 0 of each `ssm_state_indices` row keeps the state after the step's first token.
- Each program writes its own copy of `k` (BK), its `v` slice (BV), `a` and `b` for tokens 1..T-1 into slot 1. Slot 1 holds HV×V×K elements, much more than needed; an assert checks the capacity.
- The next step loads slot 0 and replays `num_accepted - 1` records with the same step function the main loop uses. A barrier separates replay reads from the new record writes.
- The per-token math is factored into `_gated_delta_rule_step`, which is shared by both paths, so the non-deferred path is unchanged.

**Exactness.** The replay recomputes the same fp32 recurrence from the same raw inputs. With a bf16 state, the per-token path rounds between tokens and the replay does not, so the mode requires an FP32 state. Qwen3.5/3.8 checkpoints set `mamba_ssm_dtype=float32`.

**Launch configuration.** Deferred mode moves far less memory per token, so it is bound by the serial token loop. It uses BV=16 and one warp, the best of the sweep. This is also why N=1 is about 2 µs slower.

**When it is enabled.** In `QwenGatedDeltaNetAttention`, all of the following must hold:
- `gdn_decode_kernel == "triton"`. The CUDA fused MTP op keeps its own state layout and is unaffected.
- `num_speculative_tokens > 0`.
- `mamba_cache_mode == "none"`.
- The SSM state dtype is fp32.

**Limitations.**
- `align` mode, the default when prefix caching is on, copies per-token states at block boundaries in `preprocess_state`, so it cannot use this mode yet. Supporting it would mean replaying in the pre-copy. That is left for a follow-up.
- Every spec step of a request must use the same mode. This holds because the flag is fixed per layer at init.
- Nothing else reads the per-token slots in `none` mode. On both V1 and V2, decode rows always take the spec path, and new requests reset `num_accepted` to 1.
- No host synchronization is added.
- Validated end to end on MRV2 only.

**Kernel microbenchmark.** Run this after applying the PR. It compares `defer_spec_state=False/True` at Qwen3.8-27B shapes. `False` is the unchanged per-token path.

```python
import torch
from triton.testing import do_bench

from vllm.third_party.flash_linear_attention.ops.fused_sigmoid_gating import (
    fused_sigmoid_gating_delta_rule_update,
)

# Qwen3.8-27B GDN layer, 7 draft tokens (T=8), 4 tokens accepted per step.
H, HV, K, V, T = 16, 48, 128, 128, 8
for N in (1, 16, 64):
    g = torch.Generator(device="cuda").manual_seed(0)

    def randn(*shape, dtype=torch.bfloat16):
        return torch.randn(*shape, device="cuda", dtype=dtype, generator=g)

    args = dict(
        A_log=randn(HV, dtype=torch.float32),
        a=randn(N * T, HV),
        b=randn(N * T, HV),
        dt_bias=randn(HV, dtype=torch.float32),
        q=randn(1, N * T, H, K),
        k=randn(1, N * T, H, K),
        v=randn(1, N * T, HV, V),
        initial_state=0.1 * randn(1 + N * T, HV, V, K, dtype=torch.float32),
        cu_seqlens=torch.arange(N + 1, device="cuda", dtype=torch.int32) * T,
        ssm_state_indices=1 + torch.arange(N * T, device="cuda").view(N, T).int(),
        num_accepted_tokens=torch.full((N,), 4, device="cuda", dtype=torch.int32),
        use_qk_l2norm_in_kernel=True,
    )
    t = {}
    for defer in (False, True):
        t[defer] = do_bench(
            lambda: fused_sigmoid_gating_delta_rule_update(
                **args, defer_spec_state=defer
            )
        ) * 1e3
    print(f"N={N:2d}: per-token stores {t[False]:6.1f} us, "
          f"deferred {t[True]:6.1f} us ({t[False] / t[True]:.2f}x)")
```

On MI355X it prints about 23 → 25 µs at N=1, 102 → 74 µs at N=16 and 345 → 225 µs at N=64.
