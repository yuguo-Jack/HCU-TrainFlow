# [ROCm][CI] Drop the -inf padding check from the AITER MQA logits test

[Upstream PR](https://github.com/vllm-project/vllm/pull/61420) · state: closed · merged: True

## Original PR description

## Purpose
`test_unpaged_mqa_logits_preserves_intervals_and_scale_layout` fails on MI355 in `(MI355 DPX) Attention Kernels Shard 1` for both scale layouts:
```text
FAILED test_unpaged_mqa_logits_preserves_intervals_and_scale_layout[vector]
FAILED test_unpaged_mqa_logits_preserves_intervals_and_scale_layout[column]
>       assert torch.equal(torch.isneginf(actual), ~valid)
E       AssertionError: assert False
```
Failing run: <https://buildkite.com/vllm/amd-ci/builds/14534/list?jid=01a1347e-aad0-4a29-9623-d798e9c54fad&tab=output>

#58724 added the test while `rocm_fp8_mqa_logits` used AITER's default `clean_logits=True`, which fills positions outside `[start, end)` with `-inf`. #51314 switched the dispatch to `clean_logits=False`, so those positions are now unspecified.

This PR removes the `-inf` padding assertion. The top-k consumers only read the ragged interval, so the test now compares just the values inside it. The AITER dispatch and scale-layout checks are unchanged. No production code changes.
