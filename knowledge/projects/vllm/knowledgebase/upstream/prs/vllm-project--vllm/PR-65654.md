# [Frontend] Support repetition_detection in Responses and Messages to stop repetitive generation

[Upstream PR](https://github.com/vllm-project/vllm/pull/65654) · state: open · merged: False

## Original PR description

## Overview

Add opt-in `repetition_detection` support to Responses and Anthropic Messages using the existing Chat Completions detector.

## Claims

- Both APIs stop repetitive generation in streaming and non-streaming requests, including repetition in reasoning and tool arguments.
- Messages reports `stop_reason: "repetition"`. Responses reports `status: "completed"` and ends streaming with `response.completed`.
- Non-streaming Messages preserves incomplete tool arguments as text rather than returning HTTP 400. Complete tool calls and reasoning content are retained.

The feature is disabled by default; the engine is unchanged.

## Validation

Tested locally on CPU with **Qwen/Qwen3-0.6B** through `RemoteOpenAIServer`:

- **147 passed:** Responses sampling and Messages conversion tests.
- **6 passed:** both APIs × streaming/non-streaming, plus named tool calls with detection off/on.
- Pre-commit and `git diff --check` passed. Existing Buildkite jobs select the tests; GPU validation was not run locally.

Before parameter forwarding was added, all four HTTP repetition tests failed: Messages reached `max_tokens`, and Responses returned `incomplete`.

The named-tool test uses `VLLM_ENFORCE_STRICT_TOOL_CALLING=0` and a fixed JSON schema to force repetitive arguments. Without truncated-argument handling, enabling detection produced:

```text
anthropic.BadRequestError: Error code: 400
invalid_request_error: Unterminated string starting at: line 1 column 10 (char 9)
```

With the fix, it returns the partial argument text and `stop_reason: "repetition"`. With detection off, it returns the complete tool input.

</details>

## Details

Both APIs now declare and forward `RepetitionDetectionParams`. Chat Completions can return incomplete JSON in the string-valued `function.arguments`, but Messages requires an object in `tool_use.input`. When repetition interrupts that JSON, Messages preserves the raw arguments in a text block. Streaming may already have emitted incomplete argument fragments.

`repetition` is a vLLM-specific stop reason, following the existing Chat Completions convention; standard mapping remains unresolved in #47753. Messages returns no stop sequence, and Responses keeps `incomplete_details: null`.

No duplicate open PR was found on 2026-11-04. Related work covers different scopes: automatic enablement (#40099), server defaults (#51036), and detector cost (#46700).
