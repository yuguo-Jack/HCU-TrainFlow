# [Bugfix][KV Offload] Retain offload mappings after unsafe KVCR startup failure

[Upstream PR](https://github.com/vllm-project/vllm/pull/57500) · state: closed · merged: True

## Original PR description

## Purpose

If KVCR startup fails while its native thread is still running, the teardown path still unmaps the offload region — `CPUPrimaryTierOffloadingManager.shutdown()` calls `SharedOffloadRegion.cleanup()`, and `TieringOffloadingSpec.get_manager()` only logs a failed `tier.shutdown()` before continuing. NIXL has that memory registered, so the NIC can complete writes into pages the process has already unmapped and reused: corruption, not a leak.

KVCR now signals this case with `KVCRStartupError` (ai-dynamo/kvcr#43). This translates it into `OffloadingStartupError`, hands the affected buffers to `retain_until_exit()`, and skips the unsafe cleanup. A leaked mapping in a process that is failing to start beats corrupting one that isn't. Ordinary failures keep their existing cleanup, and interrupts still propagate as themselves.

Requires the paired KVCR change; the worker-side mapping is untouched, since NIXL registers the separate scheduler-side view.

## Test Plan

```bash
pytest tests/v1/kv_offload/test_factory.py tests/v1/kv_offload/tiering/test_kvcr_tier.py
```

Both tests extend existing files and are parametrized over the three paths that must differ: an ordinary `RuntimeError` (cleanup runs), the startup error (buffers retained, cleanup skipped), and `KeyboardInterrupt` (retained, re-raised unchanged). One covers `TieringOffloadingSpec`, the other the KVCR tier; the latter asserts on a real `mmap` and `memoryview` rather than mocks.

## Test Result

All passing. Note `test_kvcr_tier.py` is gated by `pytest.importorskip("kvcr")`, so it needs an environment with the kvcr package to exercise.

No model evaluation: startup failure handling only, with no effect on the offload data path or generated output.
