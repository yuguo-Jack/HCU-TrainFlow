# [Attention][DCP] Support a2a DCP comm backend for FlashMLA sparse

[Upstream PR](https://github.com/vllm-project/vllm/pull/61285) · state: closed · merged: True

## Original PR description

## Purpose

`FlashMLASparseMetadataBuilder` rejects any DCP comm backend other than `ag_rs`. 
The mixed-batch fp8 path already returns `(out, lse)` for every MQA token, with packed heads and with rows that have no local top-k candidates set to `(0, -inf)`. That is the input `MLADCPManager`'s `a2a` combine expects, both the direct symmetric-memory kernel and the NCCL all-to-all fallback for batches larger than the direct workspace. This PR removes the guard.

PCP + DCP still requires `ag_rs`. The MRV2 PCP manager enforces that (`MRV2 PCP + DCP requires dcp_comm_backend='ag_rs'`), and PCP is MRV2-only.

With `ag_rs`, each layer's combine is an NCCL all-gather of the LSEs plus a reduce-scatter of the outputs, which means many small NCCL kernels per decode step. With `a2a` it is one exchange per layer.

There is also a side effect for GLM-5.x: `GlmMoeDsaForCausalLM` defaults DCP to `a2a`, so with this change it no longer fails at startup when FlashMLA sparse serves DCP (`--attention-backend FLASHMLA_SPARSE`, or SM90).

## Not a duplicate

Searched open and merged PRs for `dcp a2a flashmla`, `dcp_comm_backend`, `FlashMLA sparse DCP`, `decode context parallel symmetric memory`, `dcp a2a`, `flashmla sparse a2a`:
- #59310 fixes the same startup failure from the other side: it keeps GLM DSA's DCP defaults on `ag_rs` wherever FlashMLA sparse serves DCP. Its description mentions lifting the guard as the alternative but leaves it alone because it was not validated. This PR is that alternative, with validation below. If this PR lands, #59310's Hopper/forced-backend fallback is no longer needed.
- #54472 and #60373 change direct-A2A layout handling (strided output and LSE). FlashMLA sparse already hands the combine packed heads (the fp8 kernel's LSE is token-major; checked on SM100), so this PR does not depend on either one.
- #46514 added the guard. Nothing else touches it.

## Test Plan / Results

Unit tests (GB300):
```
pytest tests/v1/attention/test_sparse_mla_backends.py -k dcp     # 7 passed (incl. new test_fp8_dcp_accepts_comm_backend[ag_rs|a2a])
pytest tests/distributed/test_dcp_a2a.py tests/distributed/test_dcp_direct_a2a_lse_reduce.py
# 44 passed, 12 failed -- the same 12 fail on unmodified main (test-side dtype/mock/query_start_loc issues), unrelated to this change
```

Combine precision check (4x GB300, 64 heads, D=512, T=40, rows empty on some ranks set to `(0, -inf)`), measured against an fp32 LSE-weighted reference: the direct a2a combine has max error 0.010-0.013 and mean 0.0009. The ag_rs path (correct_attn_out followed by a bf16 reduce-scatter) has max error 0.026-0.032 and mean 0.0015. No NaNs in either.

End-to-end setup: `zai-org/GLM-5.3` (FP8) on 2x4 GB300, TP8, `--attention-backend FLASHMLA_SPARSE --kv-cache-dtype fp8_ds_mla --no-enable-prefix-caching --max-model-len 65536 --max-num-batched-tokens 8192`. Default runner (MRV2), FULL_AND_PIECEWISE CUDA graphs. The DCP runs add `--decode-context-parallel-size 8 --no-dcp-q-replicate` and either `--dcp-comm-backend ag_rs` or `--dcp-comm-backend a2a`. The log confirms `Using direct symmetric-memory DCP A2A for MLA.`

GSM8K (`tests/evals/gsm8k/gsm8k_eval.py --num-questions 1319 --max-tokens 512`, 5-shot):

| config | accuracy |
|---|---|
| TP8 | 0.918 |
| TP8 + DCP8 ag_rs | 0.917 |
| TP8 + DCP8 a2a | 0.914 |

Prompt logprobs on 3 fixed texts (115 positions, mean abs diff): a2a vs TP8 0.065, ag_rs vs TP8 0.058. For comparison, TP8 against itself under different concurrent load gives 0.073. Greedy outputs are identical run to run for a given config.

`vllm bench serve --dataset-name random --random-range-ratio 0 --ignore-eos`, a different seed per point, mean TTFT/TPOT in ms:

| point | TP8 | DCP8 ag_rs | DCP8 a2a | a2a vs ag_rs |
|---|---|---|---|---|
| prefill 8k, c1 (TTFT) | 541 | 923 | 867 | -6% |
| prefill 32k, c1 (TTFT) | 2193 | 3653 | 3433 | -6% |
| decode 1k/256, c1 (TPOT) | 9.50 | 15.17 | 13.45 | -11% |
| decode 1k/256, c16 (TPOT) | 15.71 | 23.28 | 20.84 | -10% |
| decode 1k/256, c64 (TPOT) | 27.35 | 38.83 | 34.97 | -10% |
| decode 32k/256, c1 (TPOT) | 9.59 | 14.84 | 13.10 | -12% |

DCP8 holds 21.95M KV tokens versus 2.75M for TP8 (8x).
