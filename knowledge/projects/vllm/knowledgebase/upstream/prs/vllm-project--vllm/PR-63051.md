# [Bugfix][Pooling] Bound late chunk sizes in the Python API

[Upstream PR](https://github.com/vllm-project/vllm/pull/63051) · state: closed · merged: True

## Original PR description

## Overview

Bound `LateChunkingParams.chunk_size` to `0 < chunk_size < 2**63`, matching the HTTP schema added in #61772.

## Claims

Reject oversized chunk sizes before engine handoff. The maximum valid value, `2**63 - 1`, still works.

## Validation

123 tests passed:

```bash
CUDA_VISIBLE_DEVICES='' .venv/bin/python -m pytest -q \
  tests/test_pooling_params.py \
  tests/entrypoints/pooling/token_embed/test_late_chunking.py \
  tests/model_executor/layers/test_pooler_methods.py
```

Pre-commit checks passed. On RunPod with an NVIDIA L4 and `intfloat/multilingual-e5-small`, both model runners passed 7 tests, including the new `LLM.encode` regression, ordinary inputs and mixed chunk sizes:

```bash
for runner in 1 0; do
  VLLM_USE_V2_MODEL_RUNNER=$runner .venv/bin/python -m pytest -q \
    tests/entrypoints/pooling/token_embed/test_offline.py \
    -k 'test_late_chunking_rejects_oversized_chunk_size or test_e5_late_chunking_mixed_requests or test_str_prompts or test_token_ids_prompts'
done
```

The new regression changes `chunk_size` to `2**64` after construction, then checks that `LLM.encode` rejects it without leaving unfinished requests.

## Details

Positive integers of `2**64` or more currently pass Python parameter validation but fail MessagePack encoding after the request is registered. The shared guard rejects them during construction and request validation.

Found during [review of #61419](https://github.com/vllm-project/vllm/pull/61419#discussion_r4266235103). #61772 fixed the HTTP schema; this covers the remaining Python API path.
