# [Bugfix][ROCm] attention: Bound AITER FA varlen graph support

[Upstream PR](https://github.com/vllm-project/vllm/pull/64407) · state: open · merged: False

## Original PR description

Co-authored-by: @zhentaocc (Zhentao Chen), @whatghost (Yuyang Gao) and @zhangnju (Ning Zhang) from AMD

## Overview

Declare and enforce bounded variable-query-length graph support for ROCm AITER
FlashAttention, and make graph-capture metadata use the promised speculative
verify width.

This is a backend capability change, not a new dynamic speculative policy. It
serves the existing adaptive-verification path and future registered EAGLE-4
chain policies.

## Claims

- Advertise varlen decode-graph support only up to
  `max_decode_query_len(vllm_config)`.
- Make capture metadata carry the graph's promised multi-token verify width
  instead of the one-token dummy row width.
- Fail closed for DCP, non-causal attention, shuffled KV cache, and requests
  wider than the declared bound.
- Do not change scheduler policy, `verify_budget`, or registered-speculator
  hooks.

## Details

`AiterFlashAttentionMetadataBuilder` supports speculative multi-token decode
through unified attention, but its capability remained `UNIFORM_BATCH` with no
bounded varlen-graph declaration. Graph capture also built metadata from dummy
one-token rows, leaving `decode_metadata.max_query_len` narrower than the graph
shape selected by the runner.

The new capability is intentionally conservative. It exposes only the width
already derived from the speculative config and refuses combinations not
covered by the backend's varlen execution path.

### Not a duplicate

- #62963 introduces generic `verify_budget` and `suspend_drafting` hooks.
- #63028 introduces registered-speculator varlen host selection.
- This change does not reproduce either host path; it supplies the missing
  ROCm AITER FA backend capability and capture behavior.
