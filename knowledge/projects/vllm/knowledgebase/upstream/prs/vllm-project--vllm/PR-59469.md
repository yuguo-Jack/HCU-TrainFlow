# [Model][Hardware][AMD] Fuse Two-pass MHA into single Causal MHA

[Upstream PR](https://github.com/vllm-project/vllm/pull/59469) · state: open · merged: False

## Original PR description




## Purpose

In chunked prefill with the AITER MLA backend, any prefill batch with context in the KV cache takes two passes: one causal attention over the new tokens, and a second non-causal one over the context, and merging the two states in the end. This results in multiple kernel launches for setting up each of the attention launches, and the merge kernel.

This PR replaces the two-pass approach with one fused causal `flash_attn_varlen_func` launch. This fusion can be controlled by the `VLLM_ROCM_USE_AITER_FUSED_MLA_PREFILL` env variable.

It also adds an env variable (`VLLM_ROCM_USE_AITER_FP8_MLA_PREFILL`) for the FP8 ASM prefill, that was always on by default with no way of disabling it in models that do not benefit from the FP8 ASM kernel.

### Benchmarks

Server:

```bash
#!/bin/bash

MODEL_PATH="${1:-/shareddata/amd/DeepSeek-R1-0528-MXFP4-MTP-MoEFP4}"

export VLLM_ROCM_USE_AITER=1
export VLLM_ROCM_QUICK_REDUCE_QUANTIZATION=INT4
export VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1

export ROCPROFILER_QUEUE_INTERPOSITION=0

USE_INDUCTOR_GRAPH_PARTITION="-cc.use_inductor_graph_partition=True"
FUSE_ROPE_KVCACHE="-cc.pass_config.fuse_rope_kvcache_cat_mla=True"

rm -rf ${HOME}/.cache/vllm /tmp/torchinductor*
vllm serve $MODEL_PATH \
  --tensor-parallel-size 8 \
  --gpu-memory-utilization 0.9 \
  --dtype auto \
  --kv-cache-dtype fp8 \
  --max-num-batched-tokens 8192 \
  --no-enable-prefix-caching \
  --disable-uvicorn-access-log \
  --max-model-len 32768 \
  --max-num-seqs 512 \
  --trust-remote-code \
  $USE_INDUCTOR_GRAPH_PARTITION \
  $FUSE_ROPE_KVCACHE
```
