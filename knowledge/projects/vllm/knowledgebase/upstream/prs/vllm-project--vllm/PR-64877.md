# [Frontend] Accept managed global DP ranks in request headers

[Upstream PR](https://github.com/vllm-project/vllm/pull/64877) · state: open · merged: False

## Original PR description



## Overview

Allow the Python frontend to accept managed global DP ranks in `X-data-parallel-rank` with hybrid or external load balancing, while preserving existing local-index callers. Fixes #64801.

## Claims

- Normalize an accepted global rank to the local engine index expected by the core client.
- Preserve local-index precedence when ranges overlap, unpinned requests, and internal-LB behavior. Reject ranks outside both valid ranges.
- Document the frontend-specific header semantics and cover the normalization and real HTTP request paths.

## Details

The frontend previously checked only `[0, data_parallel_size_local)`, while routers, metrics and the Rust frontend use global ranks. `InputProcessor` now falls back to the endpoint's managed global range only after the local range fails, subtracting `data_parallel_index` before dispatch. This leaves the core client's local-index contract unchanged and adds no scheduler or GPU-kernel changes.

Overlap is intentionally backward compatible: with start=1/local_size=2, header `1` still means local index 1 (global rank 2). This does not claim identical Python/Rust semantics in overlapping ranges.

Local-index compatibility is not strict global-rank ownership validation: a request sent to the wrong endpoint is still accepted if its header is a valid local index there. With uneven per-node sizes, overlapping local/global ranges can also make a router-intended global rank select a different local engine. The serving guide now explicitly warns about both limitations, as discussed in [the issue feedback](https://github.com/vllm-project/vllm/issues/64801#issuecomment-6575504490).
