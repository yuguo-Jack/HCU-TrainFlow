# [MM] Move Nemotron VL image normalization to device

[Upstream PR](https://github.com/vllm-project/vllm/pull/57924) · state: closed · merged: True

## Original PR description

## Purpose

Move image and video rescaling/normalization for the Nano Nemotron VL models from CPU preprocessing to the model device. This follows the shared GPU-side normalization mechanism introduced in #50411.

Before this change, the processor converted raw `uint8` pixels to `float32` before bicubic interpolation, normalized them on the CPU, and returned pixels in the model dtype. This made resizing more expensive and doubled the amount of pixel data transferred for `bfloat16` models.

This PR:
- opts `NemotronH_Nano_VL_V2` into `mm_device_do_normalize`
- keeps resized image and video pixels as `uint8` through preprocessing and transfer (restoring pre-#40283 numerical behavior)
- applies the existing `FusedInputNorm` immediately before the C-RADIO encoder
- handles both fixed-resolution `NCHW` inputs and dynamic-resolution packed patches
- preserves CPU normalization when device normalization is disabled

Bicubic interpolation remains under `torch.compile`. Both normalization modes, with and without resizing, produce one Dynamo graph each with zero graph breaks under the Inductor backend.

### Performance

The renderer and executor are separate processes, so the timings below are
reported per stage and are not added together. Executor work may overlap with
subsequent renderer work.

Setup:

- CPU: Intel Core i9-10920X, one PyTorch intra-op thread
- GPU: NVIDIA GeForce RTX 3070 Ti
- Model dtype: `bfloat16`
- Reported values: median latency

#### One 1536 x 1536 image

| Stage | Before | After | Improvement |
| --- | ---: | ---: | ---: |
| Renderer: resize and normalize/prepare pixels | 20.619 ms | **7.161 ms** | **2.88x** |
| Executor: H2D transfer and device normalization | 1.758 ms | **1.255 ms** | **1.40x** |
| Pixel payload | 13.50 MiB | **6.75 MiB** | **2x smaller** |

#### 32 video frames at 512 x 512

| Stage | Before | After | Improvement |
| --- | ---: | ---: | ---: |
| Renderer: resize and normalize/prepare pixels | 50.683 ms | **20.509 ms** | **2.47x** |
| Executor: H2D transfer and device normalization | 6.226 ms | **4.378 ms** | **1.42x** |
| Pixel payload | 48.00 MiB | **24.00 MiB** | **2x smaller** |

## Test Plan

The tests cover:

- retaining `uint8` through compiled bicubic interpolation when device normalization is enabled
- exact `bfloat16` agreement between CPU normalization and `FusedInputNorm`
- both fixed-resolution `NCHW` and dynamic-resolution packed-patch layouts
- CPU-normalized and device-normalized paths for both image and video processors
- rejection of partially enabled rescaling/normalization.
