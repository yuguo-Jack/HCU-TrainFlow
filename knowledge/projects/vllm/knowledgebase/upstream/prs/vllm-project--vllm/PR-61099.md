# WIP: [Bugfix][ROCm] Preserve 64-bit QuickReduce phase offsets

[Upstream PR](https://github.com/vllm-project/vllm/pull/61099) · state: open · merged: False

## Original PR description

## Overview

Keep the QuickReduce phase-two communication offset in 64 bits. A valid maximum capacity of 4096 MiB currently narrows the phase-two offset to 32 bits, placing both phases at the same address even for small inputs.

## Claims

- Preserve the configured 4 GiB phase separation in the phase-two write and read pointer arithmetic.
- Add a fresh-process TP2 regression candidate with a 4096 MiB capacity and a small, exactly checkable FP reduction.

## Validation

Draft: not ready for merge. ROCm compilation, pre-fix failure/post-fix success on supported dual AMD GPUs, end-to-end inference evaluation, and human line-by-line review remain outstanding. No GPU wrong-output reproduction is claimed.

```sh
.venv/bin/python -m pytest tests/distributed/test_rocm_quick_reduce.py -q -k four_gib
```

Local macOS arm64 result: 1 skipped (ROCm / two GPUs unavailable), 41 deselected. `pre-commit run --files csrc/rocm/quickreduce/quick_reduce_impl.cuh tests/distributed/test_rocm_quick_reduce.py` passed after merging upstream main (698e79f) on 2026-10-13 to incorporate the source-directory relocation. The PR now merges cleanly. Upstream CI remains blocked by the contributor-verification gate; no new ROCm execution is claimed. Static analysis confirms narrowing of 4294967296 + offset to uint32 aliases the first-phase offset. Runtime race exposure is not deterministic and still needs characterization.

## Details

`data_size_per_phase` and native allocation sizes are already int64. Change only the phase-two offset type to match. The phase-one offset is bounded by the fixed grid and tile dimensions. Both phase-two pointer sites consume the widened value directly.

The test uses 16 MiB FP input, rank-distinct values 1 and 2, exact expected output 3, and repeated reductions. A 4096 MiB phase capacity allocates approximately 8 GiB per rank plus flags, so validation requires sufficient free GPU memory. This change does not add support for input payloads >=4 GiB or address communicator reinitialization allocation behavior.

Open upstream PR searches for `"QuickReduce" offset` and `QuickReduce 4096` did not identify the same fix. No upstream issue number is associated with this change. AI assistance (OpenAI Codex) was used to investigate and prepare this draft. Human review and hardware validation are explicitly pending.
