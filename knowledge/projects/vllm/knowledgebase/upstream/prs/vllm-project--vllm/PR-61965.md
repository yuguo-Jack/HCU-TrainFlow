# [CPU][Bugfix] Flatten >2-D activations in the AMX int8 W8A8 linear path

[Upstream PR](https://github.com/vllm-project/vllm/pull/61965) · state: closed · merged: True

## Original PR description

## Purpose

Fixes #61964.

On AMX CPUs, `CPUInt8ScaledMMLinearKernel` routes symmetric W8A8 linears with aligned shapes to `_apply_weights_sgl` (the SGLang-derived `int8_scaled_mm_with_quant` kernel), which has been the default since #50801. That path passes activations straight to the kernel, and the kernel enforces `CHECK_DIM(2, mat1)`. The Whisper encoder runs on `B x T x D`, so W8A8 Whisper fails on AMX machines with `RuntimeError: mat1 must be a 2D tensor`. Non-AMX CPUs fall back to `_apply_weights_onednn`, which already flattens to `[M, K]` and restores the leading dims, so the model works there.

This PR applies the same flatten/reshape in `_apply_weights_sgl`. It matches `_apply_weights_onednn` and `CPUFp8BlockScaledMMKernel` in the same file, and the W4A16 fix in #58268. 2-D inputs (all decoder-only models) are unaffected.

**Not a duplicate:** I searched open PRs and issues for `_apply_weights_sgl`, `int8_scaled_mm_with_quant`, and CPU/Whisper W8A8. The only related item is #56029, which fixes the ROCm Triton `scaled_mm` path (#56024) and doesn't touch the CPU kernel.

## Test Plan

- New unit test `test_cpu_sgl_int8_linear_accepts_3d_input` in `tests/kernels/quantization/test_scaled_mm_kernel_selection.py` (already a `cpu_test` file). It builds a layer through `CPUInt8ScaledMMLinearKernel.process_weights_for_sgl`, runs `apply_weights` on a `[2, 3, K]` input, and checks the result is bit-identical to the flattened `[6, K]` call reshaped back. The test is skipped when `int8_scaled_mm_with_quant` is not built.
- `pytest tests/kernels/quantization/test_scaled_mm_kernel_selection.py -v`
- `pre-commit run --files <changed files>`
