# [MRV2][PP] Fix spec-decode draft/sampled-token broadcast issues

[Upstream PR](https://github.com/vllm-project/vllm/pull/64458) · state: closed · merged: True

## Original PR description

Fixes several problems in the PP sampled-token and draft broadcasts added in #50514:

- Remove a GPU<->CPU sync on non-last PP ranks. Received drafts were filtered with a boolean mask built via torch.as_tensor; the draft update now happens in the post_update kernel, reusing idx_mapping (which already marks excluded rows with -1).
- Avoid some unnecessary torch ops / gathers.
- Fix a race in broadcast_drafts: the gather from the shared req_states.draft_tokens buffer ran on the broadcast stream, so the main stream could overwrite those rows first. The gather now runs on the main stream.
- Skip the draft broadcast when no drafts were proposed this step (e.g. skip_drafts), and gate it on whether sampled tokens were broadcast instead of recomputing the mask.
- Size the sampled-token broadcast per step (1 column without drafts) instead of always padding to num_speculative_steps + 1.
- Move the EAGLE3 aux-hidden-state PP support check into set_eagle3_aux_hidden_state_layers.
