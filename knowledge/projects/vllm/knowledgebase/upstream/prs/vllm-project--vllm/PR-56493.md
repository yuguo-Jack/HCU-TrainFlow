# [Perf][Marlin] Group full-K tiles for wide block-FP8 GEMMs on SM89

[Upstream PR](https://github.com/vllm-project/vllm/pull/56493) · state: open · merged: False

## Original PR description

## Summary

Marlin's full-K traversal sweeps N before the next M row. This patch groups complete M tile rows in batches of eight, bringing uses of the same weight tile closer together. It targets wide block-FP8 prefill on SM89; Stream-K tails, partial rows, reduction order and the public operator interface stay unchanged. Cache locality is the design motivation; L2 hit rate was not measured.

The guard requires BF16 activations, E4M3 block128 weights, no bias, FP32 reduction, per-split M ≥256, N ≥24576 and K 4096–8192. No model-name checks or runtime autotuning.

## Results

One L20, TP1, Auto selecting Marlin; independently restarted **A/B/B/A** services, concurrency 1:

| Input / output tokens | TTFT change | Complete-request latency change |
| --- | ---: | ---: |
| 8192 / 64 | **−5.02% to −5.38%** | **−3.00% to −3.26%** |
| 128 / 64 | — | +0.11% to −0.54% |

No decode speedup claim: mean TPOT changes stay below 0.25%. E2E long-prefill sampled SM means were 2458–2459 MHz for baseline and 2516–2520 MHz for candidate, so these are automatic-boost results, not equal-clock attribution.

An additional real-weight gate/up ablation at M=256, N=34816, K=5120 reduced cold/warm kernel time by **20.71% / 12.55%**. Both arms' measurement-window clock samples were 2520 MHz; clocks were not locked. Operator results are separate from E2E results.

## Validation

- Both arms: **625 passed, 13 skipped** in Marlin GEMM/tile-padding suites, plus **20** guard/strided/bias/graph-stream cases. Skips are existing invalid shape/group combinations. Two Marlin-filtered Compute Sanitizer cases per arm: **0 errors**. Applicable pre-commit hooks passed.
- E2E: **34 paired 64-token outputs match**, including warmups. Eight fixed GSM8K sanity questions: **8/8 in each arm**, identical outputs; a small regression screen, not a full accuracy evaluation.
- Operator ablation: six shapes, **24 correctness checks, 48 timing records, 3072 CUPTI samples**; all four runs' output hashes match. Negative controls differ by less than 0.33%.

Tested base: `190df0b90007eead441d97d3abf6270f84f2c63e`; PR: `d4a0f2b8f24a50be324fca419575fd9ac80020d2`. Same Python/runtime on both arms; complete `_C_stable_libtorch` rebuilt separately. Evidence is limited to this checkpoint and L20/TP1; no throughput, TP2 or cross-architecture claim. GPU CI is still needed.
