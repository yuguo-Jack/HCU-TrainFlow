# [Bugfix][V1][Mamba] Keep recurrent-state bookkeeping when a running request is skipped for a step

[Upstream PR](https://github.com/vllm-project/vllm/pull/63176) · state: open · merged: False

## Original PR description

## Overview

Fixes #63175. If a running request isn't scheduled for one step (not preempted, just out of token budget), the V1 runner drops it from the persistent batch and adds it back next step. `add_request` then resets two values that point at the request's existing recurrent state:

- `replayssm_decode_base` (Triton ReplaySSM): ring tokens not flushed yet get dropped.
- `num_accepted_tokens` (hybrid + spec decode, e.g. Qwen3.5 + MTP): GDN/Mamba read the state from slot `num_accepted_tokens - 1`, so resetting it to 1 drops the tokens accepted in the last step.

No error, the output just drifts from there.

## Claims

- A skipped request keeps both values. Preempted requests still reset them, since their state is recomputed.
- Works in sync, async and align modes.

## Validation

New e2e tests hold one of several running requests back for one step (small `scheduler_cls`) and compare greedy output with the no-skip run.

```
pytest tests/v1/e2e/spec_decode/mtp/qwen3_5/test_skipped_step.py   # Qwen3.5-0.8B-Base + MTP
pytest tests/v1/e2e/test_replayssm_decode.py -k skipped_step       # Nemotron-3-Nano-4B, ReplaySSM
```

v0.32.0, H200:

| test | before | after |
|---|---|---|
| MTP sync | differs from token 18 | pass |
| MTP async | differs from token 20 | pass |
| MTP align | differs from token 18 | pass |
| ReplaySSM | differs from token 23 | pass |

`tests/v1/worker/test_gpu_input_batch.py` and `test_gpu_model_runner.py` pass as well.

## Details

Both values move to `CachedRequestState`. `num_accepted_tokens` is saved when the request leaves the batch and put back when it returns. One cost: saving it waits on `num_accepted_tokens_event`, which async non-align mode otherwise doesn't, but only in steps where a hybrid spec request is left out. I can keep it on the GPU instead if that's a concern.

Not a duplicate: #52942 / #40738 (ngram no-draft step) and #51508 (discarded async rows) are different paths. V2 runner isn't affected.
