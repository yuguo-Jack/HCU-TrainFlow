# [Feature][NIXL] Add prefix cache reset to the toy proxy

[Upstream PR](https://github.com/vllm-project/vllm/pull/65136) · state: open · merged: False

## Original PR description

## Overview

`POST /reset_prefix_cache` returns 404 at the documented NIXL toy proxy even when native reset endpoints are enabled on its backends. Add a development-mode route that forwards the reset to every configured prefiller and decoder and combines their results.

## Claims

- Preserve the native development-mode gate and reset-option defaults. When `OPENAI_API_KEY` is configured, require the same Bearer token and forward it to the backends.
- Reset every configured backend without advancing the round-robin iterators. Use the root reset URL rather than appending it to the clients' `/v1` base URL.
- Return per-backend results, preserve retryable `success=false` replies, and report HTTP/transport/protocol failures without hiding successful resets elsewhere.

## Details

The flow is `client -> toy proxy -> every configured P/D native reset endpoint -> combined response`. Both query options default to false. `reset_external=true` is optional and adds connector-managed tiers to the local-cache reset.

When every backend returns a valid HTTP-200 result, the proxy returns HTTP 200; aggregate success is true only when all backends explicitly succeed. Unavailable, non-200, or malformed responses produce HTTP 502 with per-backend error information. Each request has a 30-second deadline, does not follow redirects, and is not automatically replayed. Partial resets are not rolled back.

The existing CPU test step selects the HTTP and native-route cases. The new GPU step selects the cache-effect regression. Usage and defaults are documented alongside the proxy startup instructions in the NIXL guide.
