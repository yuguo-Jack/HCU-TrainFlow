# [Perf][Mamba] Capture the Mamba2 mixer in piecewise CUDA graphs

[Upstream PR](https://github.com/vllm-project/vllm/pull/61528) · state: open · merged: False

## Original PR description



## Overview

Lets the Mamba2 mixer run inside the piecewise CUDA graphs of prefill and mixed prefill+decode
steps, instead of eagerly between graph pieces. It is opt-in: leave `vllm::mamba_mixer2` out of
`compilation_config.splitting_ops`. This PR is part of a series that brings piecewise CUDA graphs to
Mamba2 prefill steps, and it is stacked on #61501 and #61497. Tested with #61293 applied, but it
does not depend on it. Like #61501, it needs flashinfer-ai/flashinfer#6100 (`cu_seqlens` in
`SSDCombined`), which is merged into FlashInfer main but not yet in a release.

## Claims

- Up to 1.30x output throughput (OTPS/gpu) over `main` + #61293 with the whole series, on 1x B200
  with Nemotron-3.5-Lightning-NVFP4-W4A4 and MTP=2 (up to 1.14x without this PR). On its own, this
  PR is 1.08-1.14x over #61501 at concurrency 8-32, 1.05-1.06x at 2-4 and 64, and flat at 1 and
  128.
- At concurrency 16, a mixed prefill+decode step takes 10.3 ms instead of 24.9 ms (nsys, vs
  #61501): 7 graph launches and 105 eager kernels instead of 30 and 336, and 5.9 ms of host time
  instead of 22.4 ms.
- p90 inter-chunk latency at concurrency 16-32 drops from 21-22 ms to 11-12 ms (vs #61501).

## Details

`vllm::mamba_mixer2` is a piecewise splitting op, so in every prefill or mixed step each Mamba2
layer runs eagerly between graph pieces. That work is host-bound: a decode request that shares a
step with a ~1k-token prefill waits 20-30 ms instead of ~3 ms. #61497 and #61501 trim the host
overhead; this PR captures the mixer.

Changes:

- Opt-in with no new flag: leave `vllm::mamba_mixer2` out of `splitting_ops`. Requires the V2 model
  runner, FlashInfer ReplaySSM decodes, `--mamba-prefill-backend flashinfer` and
  `--mamba-cache-mode none`, checked at startup.
- Captured steps run `conv_ssm_forward_static()`, whose shapes depend only on the padded token
  count. `Mamba2AttentionMetadataBuilder` writes its per-step metadata into persistent buffers with
  one upload, on piecewise steps only.
- Prefill: `causal_conv1d_fn` and `mamba_chunk_scan_flashinfer_static`. Decode rows and padding up
  to the next 128-token boundary are identity rows (zeroed inputs, dt = -1e4); later padding is
  skipped. Steps with more prefills than the scan's slots (about one per 512 tokens, at least 8)
  run eagerly.
- Decode: the varlen conv1d update and FlashInfer ReplaySSM over the padded decode rows.
- Steps above the largest capture size, FULL decode graphs and eager steps keep the existing path.
  A static Triton scan is a separate change.
