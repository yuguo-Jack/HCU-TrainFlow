# [ROCm][DBO] QuickReduce and SDMA INT4 all-reduce for pure-TP microbatches

[Upstream PR](https://github.com/vllm-project/vllm/pull/64930) · state: open · merged: False

## Original PR description

**Stacked on #63483 (pure-TP dual-batch overlap).** Only the last two commits belong to this PR; I'll rebase once #63483 lands.

## Purpose

With DBO under pure TP (#63483), microbatch all-reduces run on a comm stream through a per-microbatch RCCL bf16 communicator. On a TP2 pair that has a single xGMI link, that costs more than the overlap gains (−12.5% here). This PR adds two opt-in paths on ROCm:

1. `VLLM_DBO_TP_QUICK_REDUCE=1`: microbatch all-reduces within QuickReduce's size window run QuickReduce on the comm stream.
2. `VLLM_DBO_TP_DMA_AR=1` (TP2 only, never during graph capture): a one-shot INT4 all-reduce over the SDMA copy engines. Quantize to INT4 (fp16 scale per 32 values), push to the peer with `hipMemcpyDeviceToDeviceNoCU` (no CUs), signal/wait with `hipStreamWriteValue64`/`hipStreamWaitValue64` (no host sync), then sum both dequantized messages in fp32. Both ranks get bitwise-identical results. Knobs: `VLLM_DBO_TP_DMA_AR_MAX_MB`, `VLLM_DBO_TP_DMA_AR_LAYOUT` (ipc|peer).

Why SDMA: a QuickReduce kernel under a GEMM on another stream competes for CUs and hides only 1–9% of its time; the SDMA copy hides 89–100%.

## Test Result

MiniMax-M3 VL TP2 on MI355X (DBO for prefill steps ≥ 8192 tokens), output throughput vs DBO off: RCCL bf16 per microbatch −12.5%; QuickReduce on the comm stream −0.3%; SDMA INT4 **+9.5%** (rows +5.9..+17.0%), TTFT −9%, TPOT −5%; MMMU val 0.639–0.644 (DBO off 0.632–0.646). Standalone 2-rank test (256–16384 tokens × 6144): max mismatch vs a torch reference ≤ 1.1e-4, identical on both ranks, 400-call slot-reuse stress OK.

## Open points

- The standalone test still needs to become a pytest under `tests/distributed/`.
- The HIP calls go through ctypes; happy to move them into the ROCm custom-op layer if preferred.
- TP2 one-shot only; a TP4/TP8 design (reduce-scatter/all-gather over SDMA) is not covered.
