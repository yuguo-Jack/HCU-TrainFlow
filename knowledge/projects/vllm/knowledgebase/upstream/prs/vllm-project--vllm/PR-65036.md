# [Bugfix][Frontend] Report the prompt cache split in the first streamed usage

[Upstream PR](https://github.com/vllm-project/vllm/pull/65036) · state: closed · merged: True

## Original PR description



## Overview

Fixes #65035. The first continuous-usage chunk of a Chat Completions stream now carries `prompt_tokens_details`, so the Anthropic `message_start` reports the same split as `message_delta`.

## Claims

- With `--enable-prompt-tokens-details`, the first streamed usage chunk carries the same `cached_tokens` and `created_cache_tokens` as the final one.
- `message_start.usage.input_tokens` excludes cache reads and writes, matching `message_delta`.

## Validation

```
# unit test, base
pytest tests/entrypoints/openai/chat_completion/test_serving_chat.py -k test_streaming_first_chunk_reports_prompt_tokens_details
E       KeyError: 'prompt_tokens_details'
1 failed, 221 deselected
# unit tests, this branch
pytest tests/entrypoints/openai/chat_completion/test_serving_chat.py -k "usage or prompt_tokens_details"
124 passed, 98 deselected
```

End to end on v0.32.0 (MI300X, Qwen/Qwen3.8-27B-FP8, `--enable-prefix-caching --enable-prompt-tokens-details`), the issue's reproducer, second request:

| | `message_start` | `message_delta` |
| --- | --- | --- |
| v0.32.0 | `input_tokens` 3656, no cache fields | 520 uncached, 3136 cache read, 0 written |
| v0.32.0 + this patch | 520 uncached, 3136 cache read, 0 written | 520 uncached, 3136 cache read, 0 written |

`test_anthropic_streaming_cache_usage` now expects the split in `message_start`. It needs a GPU server, so I checked that behaviour with the run above instead.

## Details

The first iteration already reads `num_cached_tokens` and `num_cache_creation_tokens`, but only the final usage chunk passed them to `_make_prompt_tokens_details`. The first chunk now does too. With the flag off it still returns `None`, so cache fields stay absent as #40912 intends.
