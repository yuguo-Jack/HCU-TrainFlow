# [Perf][Spec Decode] Apply top-p cutoffs as target logits load in verification

[Upstream PR](https://github.com/vllm-project/vllm/pull/65102) · state: open · merged: False

## Overview

For verification chunks whose requests use only temperature and top-p, `RejectionSampler` now computes each row's top-p cutoff on the raw bf16 logits with `topp_cutoffs_lse` (#65101) and skips `apply_sampling_params`; every kernel that reads target logits masks values below the row's cutoff and divides by the temperature as it loads them. 3/4 of a stack; part of #61024.

**Stacked, draft.** This branch contains #65101 and the two commits of #61344 (by AlejandroParedesLT, rebased onto current main; authorship kept), which add the on-load temperature path this extends, and #65100. **New code is five commits:** top-p on load; keeping FLy on processed logits (which also fixes #61344's temperature-only path); the cheaper exact on-load divide; letting #65100's block skip fire on this path; and an end-to-end `LLM` test. Cherry-picked: #65101's kernel rework and its int64 index-mapping fix, and #65100's commit (conflicts resolved, below). The branch will be rebased as those land.

**Fix (2026-11-03).** An end-to-end serving test of this stack found that the first top-p request took EngineCore down: `topp_cutoffs_lse` accepted only an int32 `expanded_idx_mapping`, and Model Runner V2 has built its index mappings as int64 since #60736. The unit tests built int32 mappings, so they passed. #65101 now reads int64, the test helpers here build int64 mappings as the model runner does, and a new `LLM` test serves top-p requests through MTP verification.

## Claims

- Verification step for top-p requests (K = 3, top-p 0.95, Qwen3-0.6B creative-writing logits, GB300), vLLM main vs this branch: **2,121 → 457 µs** at 256 requests, 323 → 46.6 µs at 16, 66.9 → 25.3 µs at 1 (T = 1); 2,156 → 486 µs at 256 requests with T = 0.7.
- MiniMax-M3.1-like verification (DSpark K = 7, block verification, V = 200,064, top-p 0.95): **3.0–5.0× faster than main at T = 0.95** and 3.0–5.3× at T = 1, from 1 to 128 requests (table below).
- Never slower than main across a 360-configuration stress matrix (K ∈ {1, 3, 7}, block verification on/off, T ∈ {0.6, 0.95, 1, mixed greedy/0.6/1/1.3}, top-p ∈ {0.95, 1}, 1/16/128 requests, V ∈ {151,936, 202,048}, one-hot and full draft logits): 1.16–8.3×, median 3.35× (run with #65101's first commit; its rework only makes the cutoff kernel faster).
- Output changes only at ties: every token tied with the cutoff is kept, where the sort-based mask keeps an arbitrary subset of a tie. On the step-time rows every request sampled what main sampled except 1 of 256 (T = 1, 256 requests). In the stress run, every request that differs from main (34 of 528 configurations, ≤ 2 of 24 requests each) is explained by the mask alone: main's kernels fed the ties-kept mask sample exactly what this branch samples.
- Serves: Qwen3.5-0.8B with MTP (K = 3), temperature 1 and top-p 0.95, runs the cutoff op on the model runner's own index mappings (new `LLM` test). Against the op before the int64 fix the same test fails with `expanded_idx_mapping must be int32`.
- With #65100 in the branch, its resample skip now fires here too (it tested the raw block, which is never all `-inf` on this path): `rejection_sample` on the raw logits, real Qwen3-0.6B rows, K = 3, top-p 0.95, **320 → 200 µs** at 256 requests (T = 1), 90 → 61 µs at 64, 31 → 24 µs at 16; bitwise identical with the skip on and off. The step times below predate it.
- On-load division is `x / T` rounded to nearest, bitwise equal to `tl.div_rn` (what `topp_cutoffs_lse` uses; #64496 moves MRV2's temperature kernels to it), but computed as `x · RN(1/T)` plus one correction by the exact FMA remainder instead of `div.rn` per element. Checked bitwise over every bf16 value of magnitude ≥ 2⁻¹⁰⁰ and 4,034 temperatures, and 8M random fp32 values.

## Details

- **Gate** (`Sampler.needs_only_temperature_and_top_p`): no thinking-budget forcing or logits processors, and no min-p or top-k on any non-greedy row; bf16 logits; no processed logprobs or sampling mask requested; no FLy; `topp_cutoffs_lse` built and the GPU SM90 or 10.x. Every other chunk keeps today's path.
- **FLy.** It computes its entropy from the logits `rejection_sample` receives, so it needs them processed; it now counts with processed logprobs in `needs_processed_logits`, which also turns off #61344's temperature-only skip for it (that path handed FLy unscaled logits), and `rejection_sample` asserts it.
- **Kernels.** `_scale_target_logits` is the single on-load transform: `-inf` below the row's cutoff (compared on the raw value), then `x / T` rounded to nearest (skipped at T = 1, where it is exact). It replaces #61344's `x / temp` at its four target load sites; `target_topp_thresh` is threaded next to its `SCALE_TARGET_LOGITS`. The residual-mass kernel runs with 8 warps when it scales on load (138 registers at 4 warps cut its occupancy); the caller-scaled path keeps 4 and is unchanged.
- **Ties.** The cutoff kernel keeps every token whose logit equals the cutoff. For an exact top-p over a distribution this is the natural rule; the sort-based mask instead keeps whichever tied tokens the sort put first. Rows without a tie at the boundary sample the same tokens.
- **#65100 in this branch.** Its commit conflicts with #61344's in `Sampler.add_request`, `rejection_sample`'s signature and the resample kernel's arguments; the resolution keeps both. `may_mask_logits` is set from `SamplingStates.masks_logits` (now read off #61344's `needs_restriction`) or forcing/logits processors, and the fake samplers in two tests gain the field. The block skip tests `scaled_target_logits`, the block after the cutoff and the temperature: `-inf` stays `-inf` through the divide, and on the caller-scaled path it is the same tensor.
- **Index mappings.** `_verify` passes the model runner's int64 `expanded_idx_mapping` to the op unchanged; the test helpers build int64 mappings too.
- **Changes to the included #61344 commits:** resolving the test-file conflict with current main (its new test now goes through `DraftLogitsCache`), and the `SimpleNamespace` sampler in `test_verify_rejects_unproposed_drafts` gaining the fields `_verify` now reads (in the first new commit).
- **Not duplicating.** #61344/#53090 cover temperature-only chunks; this adds top-p. #48928 (FlashInfer AIR top-p for rejection sampling) and #65004 (Triton histogram-bracket top-p) replace the mask kernel but keep the fp32 copy and the separate stats pass; neither keeps ties whole nor yields a log-sum-exp. Searched open PRs for "top-p rejection sampling", "rejection sampler temperature", "spec decode top-p verification", and #61024.
- **Stack.** 1 #65100 (included here) · 2 #65101 · **3 this** · 4 #65103 target log-sum-exp from the cutoff op. #65104 (draft log-sum-exp from the drafter) closed: a net loss once the drafter's cost is counted.
