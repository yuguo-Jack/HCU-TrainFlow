# [Misc] Log unsupported FlashAttention version as a one-time warning

[Upstream PR](https://github.com/vllm-project/vllm/pull/63592) · state: open · merged: False

## Original PR description

## Purpose

`get_flash_attn_version()` logs an **ERROR** when the selected FlashAttention version is not supported:

```
ERROR [fa_utils.py:212] Cannot use FA version 2 is not supported due to FA2 is only supported on devices with compute capability >= 8
```

On pre-Ampere GPUs (e.g. Tesla T4, V100) this is an expected, handled case: the `AssertionError` is caught, `get_flash_attn_version()` returns `None`, and the run continues normally. However:

1. It is logged at **ERROR** level, although nothing failed.
2. It uses `logger.error` (not `*_once`), so it can repeat, e.g. once per worker in multi-GPU runs.
3. The sentence is malformed ("Cannot use FA version 2 is not supported due to ...").

This makes successful runs look like failures and buries real errors among it:
- #13766: a V100 user saw it and asked how to disable FlashAttention.
- #29707: it is logged next to the actual failure (an unsupported quantization scheme), making the real cause harder to spot.
- #22279: the same malformed sentence on an RTX 5090.

This PR logs it once as a warning with clearer wording, matching the other fallback messages in the same function, which already use `warning_once` / `info_once`. No behaviour change.

Note: on newer GPUs, this message can also indicate a missing FlashAttention build. It stays visible as a warning; happy to keep ERROR for that case if maintainers prefer.

## Test Plan

Tesla T4 (compute capability 7.5), Google Colab, `Qwen/Qwen2.5-0.5B-Instruct`, `dtype="half"`: ran the same script before and after the change, compared the FlashAttention log lines, and checked that generation is unchanged. `pre-commit run --files vllm/v1/attention/backends/fa_utils.py` passes.

- Raghu-dev-pixel · comment · 2026-11-02T22:12:17Z · [source](https://github.com/vllm-project/vllm/pull/63592#issuecomment-6589769038)

> What FA version gets run on pre-ampere?

Thanks for taking a look! On pre-Ampere, no FA version runs. `FlashAttentionBackend.supports_compute_capability()` requires SM80+, and FlashInfer is currently gated to SM80+ too, so the selector falls back to Triton. From a T4 (SM75) run on stock v0.33.0:

```
ERROR [fa_utils.py:212] Cannot use FA version 2 is not supported due to FA2 is only supported on devices with compute capability >= 8
INFO  [cuda.py:508] Using TRITON_ATTN attention backend out of potential backends: ['TRITON_ATTN', 'FLEX_ATTENTION'].
```

The ERROR comes from helper checks that still call `get_flash_attn_version()` during setup. It defaults to FA2, finds FA2 unsupported, logs, and returns `None` through the caught `AssertionError`, so it refers to a version that would never be used. For comparison, the FlashInfer sampler handles the same situation on this GPU as a warning: `FlashInfer top-p/top-k sampling unavailable: unsupported compute capability 7.5; falling back.`

If you'd prefer, I can instead make `get_flash_attn_version()` return `None` early (without logging) when the device capability is below 8.0, so nothing is logged on these GPUs. I'm happy to go either way.
