# [Model][Core] Register every persistent device tensor as a parameter or buffer

[Upstream PR](https://github.com/vllm-project/vllm/pull/60009) · state: open · merged: False

## Original PR description

## Overview

Sleep mode level 2 discards the weights memory pool. On wake, only `model.named_buffers()` are restored in place, and parameters come back through the weight update. A device tensor that is built at load and kept as a plain attribute is therefore garbage after sleep level 2 + wake.

This PR fixes each such tensor at its own site. Most fixes are `register_buffer(name, t, persistent=False)` with the same tensor object, so addresses do not change. It adds no walker, no exemption table and no CI scan. Context: #54477, #50079.

## Fixed (one site each)
- NVFP4 linear emulation: the layer holds the E2M1 lookup table as a buffer.
- Humming linear (MXFP4/6/8, NVFP4, mixed precision, FP8/INT8 scaled-mm, `HummingLinearMethod`): `locks` is a layer buffer.
- `Attention`: `_k_scale_cpu`/`_v_scale_cpu` are created on CPU explicitly. ALiBi slopes / fp32 sinks (impl-derived state) moved to #62634 (runtime cuMem pool, as in #62358).
- `_k_scale_cpu`/`_v_scale_cpu` are created on CPU. They were built under the target-device context, so on main they landed on the GPU.
- DSv4.1 mega attention: the three `permute_on_load` permutations are built on CPU. They are used only at load time: the weight-loader closures keep them and apply them on every (re)load, and `forward` never reads them. Built on GPU they landed in the weights pool, so after level-2 sleep a `reload_weights()` permuted with garbage indices; `gather` already moves them to the parameter device.
- DSv4.1 fused mHC all-reduce: `_stage_state` is a model buffer.
- Model constants are buffers: GraniteSpeech `attention_dists`, Phi-4-MM `pe`, Bailing/MiniMax `tp_slope`, Gemma4 MTP `_suppress_idx`, Gemma4-DSpark `_v_norm_weights` (constant ones), OpenPangu-VL `inv_freq`.

## Known limitations / follow-ups
- MoE kernel tensors (experts constants, activation gscales, MXFP4 permute cache): follow-up PR.
- Kimi-K3 latent-MoE tail fusion still raises under sleep mode; unchanged here.
- Kimi-K3 `SpecializedDecode` state is built at load in the weights pool. It is off by default and rejects sleep mode.
- Held by non-module objects: DCP workspaces, EPLB maps, MiniMax Lamport workspace, Qwen4Exp `ngram_context_offsets`.
- LoRA slots: handled by #62358 (LoRA state restore on level-2 wake).
- Same pattern, left out: ROCm/XPU-only sites, INC `ark_bias`, CT wNa8o8 static scales, FlashAttn-MLA-sparse `cu_seqlens_q_buffer`, Qwen4Exp deepstack embeds.
- Weight-derived copies (DFlash, Gemma4-DSpark k-norm stack, Kimi-K3 DSpark context-KV norm weights/scales, beam DFlash2, LiLiCorr, DSv4/DSv4.1 `hc_attn_fn_broadcast`) stay plain attributes. Layerwise reload skips copying non-persistent buffers it did not load, so registered copies would come back stale. Fix that in reload first.
- Staleness after weight updates, not sleep (#57733 territory): MoE fused router/shared gate, GLM5-next `_wp_fp32`/`_merged_conv_weight`, CPU attention sinks cast, and non-persistent derived buffers on layerwise reload.
- Risk, IPC weight cache + DSv4.1 fused mHC: an IPC client replaces `_mhc_ar_stage_state` with the daemon's tensor, so it no longer aliases the kernel state and sleep restores the wrong memory.

## Validation

All on the current head (9af0eaaff4), A/B against its base (4bd75e952a), same image and node.

**Tensor-level sleep probe** (GB200). Dummy weights, `enable_sleep_mode=True`, in-place restore (`sleep_preserve_parameter_names=["*"]`). Before sleep, every non-parameter CUDA tensor reachable from the model runner is snapshotted and classified by cuMem pool. A tensor is *at risk* if it lives in the `weights` pool and is not a module buffer, so level-2 sleep discards it and nothing restores it. Then `sleep(level=2)` -> `wake_up()` and every snapshot is compared byte for byte.

| Config | At risk on main, fixed here |
|---|---|
| Qwen3-30B-A3B NVFP4, Humming linear | Humming linear `locks`; `_k_scale_cpu`/`_v_scale_cpu` |
| Qwen3-30B-A3B FP8 and Qwen3-0.6B FP8, Humming linear | Humming `fp8_linear` `locks`; `_k_scale_cpu`/`_v_scale_cpu` |
| Qwen3-30B-A3B NVFP4, emulation linear | `_k_scale_cpu`/`_v_scale_cpu` (the E2M1 table is a global, so the probe cannot see it; covered by the new unit test) |
| Phi-4-MM | `pos_emb.pe` (value changed on main, equal here) |
| GraniteSpeech | `attention_dists` (value changed on main, equal here) |
| Ring-2.5 (Bailing V2.5 linear attention) | `tp_slope` (value changed on main, equal here) |
| Qwen3 (control) | none on either side |

Still at risk here, all listed under limitations or unused after init:
- MoE: NVFP4 `a1/a2` gscale, MXFP4 permute cache, `gemm1_clamp_limit`, Humming MoE `locks` (follow-up PR).
- DSv4.1 `hc_attn_fn_broadcast`.
- Unused or rewritten every step:
  - DSv4.1 `EngramLayout.offsets`: the model reads the registered `offsets` buffer, which is restored.
  - Gemma4 `has_weight=False` norm weights: never passed to the kernel.
  - Bailing `slope_rate`: only used at init to slice `tp_slope`.
  - Per-step scratch: Gemma4 `per_layer_embeddings`, DSv4.1 top-k and candidate-block buffers.
  - Sampler state.

DSv4.1 fused mHC all-reduce (`_mhc_ar_stage_state`) is not exercised: sleep mode with the custom all-reduce fails at startup on main too (`custom_all_reduce.cuh:164 invalid argument`).
