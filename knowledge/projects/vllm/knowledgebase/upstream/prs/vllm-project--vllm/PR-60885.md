# [Bugfix] Reject mismatched float16/bfloat16 KV cache dtype

[Upstream PR](https://github.com/vllm-project/vllm/pull/60885) · state: closed · merged: True

## Original PR description

## Overview

Reject an explicit `float16`/`bfloat16` `kv_cache_dtype` that differs from the model dtype in `VllmConfig.__post_init__`, before backend selection and CUDA-graph capture. Fixes [#60859](https://github.com/vllm-project/vllm/issues/60859).

No other open PR addresses this issue (`gh pr list --search "60859 in:body"`).

## Claims

- `dtype=bfloat16` with `kv_cache_dtype=float16` raises `ValueError` while the engine config is built, so `mha_varlen_fwd` never sees a bfloat16 query and a float16 key.
- The error is `kv_cache_dtype="float16" is incompatible with dtype="bfloat16". Please set --kv-cache-dtype to auto or bfloat16.`
- The swapped pair is rejected the same way. A `float32` model with an explicit `float16` KV cache is rejected with a hint to use `auto` only, because `float32` is not a legal `--kv-cache-dtype`.
- `"auto"`, a matching float16/bfloat16 pair, and FP8 stay valid.

## Validation

```bash
.venv/bin/python -m pytest tests/test_config.py -k mismatched_float_kv_cache -q
```

6 passed: both mismatched float pairs and `float32` with a `float16` KV cache raise `ValueError`; matching `float16`, `"auto"`, and `"fp8"` are accepted. A direct `VllmConfig.__post_init__` call with a bfloat16 model and `kv_cache_dtype="float16"` raises the same error. `ruff check` and `ruff format --check` (v0.14.0) pass.

End-to-end `LLM.generate` on A6000 was not run (no CUDA GPU here).

## Details

**Root cause.** FlashAttention `mha_varlen_fwd` requires the query and the key to share a dtype. The engine accepted `dtype=bfloat16` and `kv_cache_dtype=float16`, then crashed during CUDA-graph capture.

**Why config-level.** The review asked to reject this mix once in `VllmConfig.__post_init__` rather than deselect backends. The check runs after `try_verify_and_update_config()`, so a model hook can still rewrite the cache dtype first (DeepSeek V3.2 rewrites an explicit `bfloat16` cache to `auto`). Triton can cast an unquantized KV tile up to the query dtype; this change refuses the mismatched pair instead of falling through to that path. The A100 data on #60859 supports rejecting rather than steering selection: FlashInfer asserts at init, and FlexAttention runs but produces silently wrong output (mean NLL 13.98 vs 3.96 with `auto`).
