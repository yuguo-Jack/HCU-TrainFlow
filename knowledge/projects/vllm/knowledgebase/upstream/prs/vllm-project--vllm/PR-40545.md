# [Kernel] Support fused_moe tuning with Kimi-VL-A3B

[Upstream PR](https://github.com/vllm-project/vllm/pull/40545) · state: closed · merged: False

## Original PR description

## Purpose

Adds \`KimiVLForConditionalGeneration\` to \`get_model_params\` in \`benchmarks/kernels/benchmark_moe.py\`.

Kimi-VL wraps a DeepseekV3-family text backbone inside a vision-language outer config. The MoE fields (\`n_routed_experts\`, \`num_experts_per_tok\`, \`moe_intermediate_size\`, \`hidden_size\`) live on \`config.get_text_config()\`, so the existing default fallback — which reads \`num_local_experts\` off the text_config, Mixtral-style — raises \`AttributeError\` on this architecture.

Same pattern as the \`Qwen3VLMoeForConditionalGeneration\` dispatch branch immediately above, and parallel to #40181 which does the same for Gemma4.

After this PR, \`benchmark_moe.py --model moonshotai/Kimi-VL-A3B-Instruct --tune\` works without a \`--model-prefix\` hack.

- varjoranta · comment · 2026-04-21T19:34:27Z · [source](https://github.com/vllm-project/vllm/pull/40545#discussion_r3119879972)

File: `benchmarks/kernels/benchmark_moe.py` · line 808

Appreciate the suggestion, but recursion doesn't work for Kimi-VL.

`config.get_text_config()` returns a `DeepseekV3Config` with `architectures=None`, so inside `get_model_params` the dispatch key becomes `type(text_config).__name__ == "DeepseekV3Config"` — not `"DeepseekV3ForCausalLM"`. Neither matches any branch, execution falls through to the Mixtral/Llama4 fallback, and that raises `AttributeError: 'DeepseekV3Config' object has no attribute 'num_local_experts'`. Verified locally with `transformers==5.5.4`.

This is presumably why the adjacent `Qwen3VLMoeForConditionalGeneration` branch does the same hardcoded-fields pattern rather than recursing (Pixtral can recurse because its sub-backbones are full LLMs whose `config.json` sets `architectures`). Keeping the hardcoded approach here for consistency with the Qwen3VL precedent.
