# [Rust Frontend] Accept top_logprobs=0 without logprobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62428) · state: open · merged: False

## Original PR description



## Overview

The Python chat validator (`check_logprobs` in `vllm/entrypoints/openai/chat_completion/protocol.py`) requires `logprobs=true` only when `top_logprobs` is `-1` or positive, so `top_logprobs: 0` (the OpenAI default) is accepted on its own. The Rust frontend rejects any `top_logprobs` without `logprobs`, so clients and SDKs that always send `top_logprobs: 0` get a 400 that Python would not return. This PR applies Python's condition in the Rust chat checks.

## Claims

- `POST /v1/chat/completions` with `top_logprobs: 0` and no `logprobs` now returns 200 on the Rust frontend, matching Python.
- `top_logprobs: 1` or `-1` without `logprobs` is still rejected with 400.

Without `logprobs`:

| `top_logprobs` | Python | Rust before | Rust after |
|---|---|---|---|
| `0` | 200 | 400 | 200 |
| `1` or `-1` | 400 | 400 | 400 |

The new `validate_request_compat_accepts_zero_top_logprobs_without_logprobs` fails on the base (checked by reverting only the two conditions). The existing rejection test now covers `-1` and `1` through both the schema validator and `validate_request_compat`.

## Details

The Rust frontend has two checks for this dependency, and both are changed in place: the schema validator (`validate_chat_cross_parameters` in `chat_completions/types.rs`), which runs first in `ValidatedJson`, and `validate_request_compat` in `chat_completions/validate.rs`, which runs during request preparation. They duplicate each other; merging them is out of scope here.

Not a duplicate: open upstream PRs touching `top_logprobs` in the Rust frontend (vllm-project/vllm#58711, vllm-project/vllm#60916) change logprob output and raw generate, not this request validation.
