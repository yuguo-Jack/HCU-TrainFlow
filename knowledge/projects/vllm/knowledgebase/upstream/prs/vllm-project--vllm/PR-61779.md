# [Perf][GDN] Static mixed-batch metadata and grids for the GDN prefill path (CUDA graph prep 1/2)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61779) · state: open · merged: False

## Original PR description



## Overview

Put the GDN metadata of batches with prefills (mixed steps) into persistent, padded buffers, and give the GDN prefill kernels a static-grid mode (FLA `use_graph`, `causal_conv1d_fn(num_programs=...)`). The eager forward does not change. This is the first of two PRs to run the GDN core inside a CUDA graph in mixed steps; the second is #61952. Kernel form ported from FLA [#1212](https://github.com/fla-org/flash-linear-attention/pull/1212) (merged, KDA) and [#1230](https://github.com/fla-org/flash-linear-attention/pull/1230) (GDN, open). Related: SGLang issue [#35851](https://github.com/sgl-project/sglang/issues/35851) (same per-layer break cost). Nearby open PRs that touch the same files but do something else: #60659 (FLA prefill checkpoints), #61434 (deferred spec-decode state stores), #38315 (fused kkt + solve_tril).

## Claims

- `GDNAttentionMetadataBuilder.build()` puts every mixed-batch field at a fixed address: state indices, cu_seqlens (spec / non-spec / prefill), `num_accepted_tokens`, `has_initial_state` (all / prefill), token indices, FLA `chunk_indices` / `chunk_offsets`, causal_conv1d `batch_ptr` / `token_chunk_offset_ptr`. The rows after the real rows hold documented pads (`MIXED_BATCH_PAD_VALUES`), so a padded view of any length is valid for a static grid.
- The FLA GDN chunk kernels (cumsum, kkt, solve_tril, wy_fast, chunk_o) skip `[-1, 0]` sentinel chunks when `use_graph=True`. `chunk_gated_delta_rule_fwd_h` needs no change: a zero-length padded sequence writes its initial state as its final state.
- `causal_conv1d_fn` can launch a static program count; the existing `PAD_SLOT_ID` exit handles the extra programs.
- No behaviour change: the staged fields keep their length, values and dtype. The causal_conv1d program buffers (`batch_ptr`, `token_chunk_offset_ptr`) now have the capacity length instead of a new `max(1024, n) * 2` allocation; the kernel reads only the first `nums_dict[8]["tot"]` entries and the rest are `PAD_SLOT_ID`, as before. The NVIDIA Kimi-K3 KDA builder, which computes its own conv metadata, uses the same buffers. All new arguments default to the old path. No new host sync, no new H2D copy, fewer per-step device allocations.

## Details

**Motivation (measured from nsys traces, our deployment, C32, DCP 4, 8x A100).** A mixed step is host-bound: 99.6 ms of host time (p50, NVTX range) against a GPU compute bound of about 65-70 ms. The GDN eager breaks take 55.2 ms of that host time and 720 of 1,348 launches (20 launches per layer, 36 layers). nsys adds a fixed cost per API call, so 55.2 ms is an upper bound for an unprofiled run. In FULL decode steps the GDN core is already captured; in mixed steps `eager_break_during_capture` runs it eagerly because its metadata is new in every step and its grids depend on the batch.

**What this PR does not do.** The forward stays eager and `_cudagraph_support` stays `UNIFORM_BATCH`. #61952 adds a branch-free mixed forward on the padded views and removes the eager break when the static form applies. `build_for_cudagraph_capture` keeps its decode-only check: with `UNIFORM_BATCH` no caller can reach a mixed capture yet, so a worst-case mixed form would be dead code in this PR.

**Design.**
- One buffer per field, sized by `max_num_seqs` and `max_num_batched_tokens`; chunk capacity `cdiv(T, 64) + S - 1`, conv program capacity `cdiv(T, 8) + S - 1` (each sequence adds at most one partial chunk or program). The `_stage()` helper (copy to the front, fill pads, return the view) also replaces the existing FULL-decode staging code. The decode buffers do not change, so subclasses that size their staging by them (Kimi-K3 KDA) do not change.
- FLA chunk metadata is padded on the CPU and goes to its buffer with one H2D copy per tensor, as before, but into a persistent buffer instead of a new device tensor.
- Pads: `NULL_BLOCK_ID` state indices (pad rows touch only the null block), repeated last cu_seqlens value (zero-length sequences), `has_initial_state=False`, `num_accepted_tokens=1`, token index 0, chunk `[-1, 0]`, conv `PAD_SLOT_ID`.
- Kernel form follows FLA: a `USE_GRAPH` constexpr and `if USE_GRAPH and i_n < 0: return`. `USE_GRAPH` is not an autotune key, so graph mode reuses tuned configs (it compiles one more variant; warm it up before capture). Unlike FLA, uncovered output rows stay `torch.empty`: inference reads only real rows.

**Limitations.**
- Static chunk metadata covers the default Triton/FLA prefill path. FlashInfer (no FLA chunk metadata), CuteDSL and AITER FlyDSL keep their own metadata, and subclasses that override `_build_chunk_metadata` (KDA) keep new tensors.
- Mamba prefix-caching checkpoint metadata (`align` mode) and the FlashInfer checkpoint plan are not staged.
- `spec_sequence_masks` in mixed batches is not staged (the forward uses it only as a flag).
