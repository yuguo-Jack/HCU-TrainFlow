## Original PR description

# [MoE] Add configurable TRTLLM NVFP4 MoE chunk cap

## Purpose

Add `VLLM_TRTLLM_NVFP4_MOE_MAX_CHUNK_SIZE`, an optional positive-integer cap
on the number of input tokens processed by one TRTLLM NVFP4 MoE invocation.
The effective value is the minimum of the configured value and the backend's
existing grid-safe limit. Leaving it unset preserves current behavior.

Large expert-parallel all-gathers can otherwise put the full gathered tensor
through one fused-MoE call, making the routed GEMM temporaries much larger than
the KV cache. For example:

```bash
VLLM_TRTLLM_NVFP4_MOE_MAX_CHUNK_SIZE=32319 vllm serve ...
```

The value is read once when the expert backend is constructed and reused by
deferred-finalization eligibility, FlashInfer tuning, and runtime chunking.
Smaller chunks lower peak activation memory but add kernel launches.

The strict AWS DEP16 experiment used the same Kimi-K3 NVFP4 experts-only
checkpoint and image on both sides:

| Configuration | Peak activation/GPU | KV cache/GPU | Job |
|---|---:|---:|---:|
| Default 300,000-token cap | 39.86–41.45 GiB | 12.27–13.92 GiB | 272229 |
| Configured 32,319-token cap | 9.35–10.94 GiB | 42.83–44.44 GiB | 302060 |

The measured 30.51–30.52 GiB activation reduction matches the allocation
model's 30.493 GiB prediction. An independent FP8-per-block DEP16 run (job
783600) completed graph capture and endpoint coherence with the same cap.

This is not duplicate work. I repeated searches of open/draft PRs, issues, and
current `main` on October 22, 2026. PR #43599 introduced the existing fixed
300,000/grid-safe chunking, but neither `main` nor another open PR exposes a
configurable cap.

The environment-variable registry comment documents the setting, enablement,
default, and trade-off for the generated environment-variable reference.

OpenAI Codex assisted with the duplicate search, implementation, rebase,
tests, and this description. The submitter will review and understand every
changed line and the validation evidence before requesting review.
