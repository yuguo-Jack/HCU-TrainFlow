# [Bugfix][V1][Multimodal] Fail only offending request on feature/placeholder embed mismatch

[Upstream PR](https://github.com/vllm-project/vllm/pull/63790) · state: open · merged: False

## Original PR description



## Overview

Fixes #55546. Isolate multimodal encoder-output vs. placeholder token count mismatches in V1/V2 model runners so only the offending request fails with `VLLMValidationError` (HTTP 400) and poisoned cache entries are evicted across worker, scheduler, and processor caches instead of crashing the entire V1 engine tree.

Prior PR #57696 (`bbc4ddeca9`) rejected scheduler-side `EncoderCacheManager` hits when a client reused an already-cached identifier with a different placeholder length, but did not catch worker-time mismatches between actual `encoder_output.shape[0]` and `mm_position.get_num_embeds()`, populate a `validation_error` message, or invalidate DP/SHM/receiver processor caches. Checked open PRs (`gh pr list --state open --search "55546 in:body"` and `"_merge_multimodal_embeddings"`) — no existing PR addresses this.

## Claims

- Detects `encoder_output.shape[0] != mm_position.get_num_embeds()` (both `actual < expected` and `actual > expected`) during multimodal embedding gather in MRV1 (`GPUModelRunner._gather_mm_embeddings`) and MRV2 (`EncoderRunner.gather_mm_embeddings`) without raising inside the worker forward pass or introducing CPU-GPU synchronization.
- Masks only the offending request's multimodal positions to text embeddings for the in-flight batch step so co-batched generation/pooling requests execute unaffected, prevents saving mismatched encoder outputs to `ECConnector`, and forwards `mm_embed_mismatches` across PP ranks (`PP > 1`) and Msgpack worker IPC.
- Aborts only the offending request in `Scheduler.update_from_output` with `RequestError(code="validation_error", message=...)` (`VLLMValidationError` / HTTP 400) while evicting tainted prefix-KV blocks written during the failed prefill step (and attaches `validation_error` on scheduler-side `#57696` rejections as well).
- Evicts poisoned multimodal cache entries across worker encoder caches, `EncoderCacheManager`, `EngineCore` receiver cache (`LruKeyReplicatedReceiverCache`), `MultiModalProcessorOnlyCache` (`DP > 1`), and `ShmObjectStoreSenderCache`, while preserving `validation_error` in `OutputProcessor` for pooling requests.

## Details

- **Root Cause:** When processor placeholder expansion and worker encoder output drifted (e.g., corrupted/variable-frame video metadata, mismatched `prompt_embeds`, or cross-replica cache drift), `_merge_multimodal_embeddings` raised an uncaught `ValueError("Attempted to assign ... multimodal tokens to ... placeholders")` inside the worker forward pass, terminating `EngineCore` (`EngineDeadError`) and taking down the entire DP engine group. In addition, `MultiModalProcessorOnlyCache` (used when `data_parallel_size > 1` with internal LB, as in #55546) inherited the no-op `BaseMultiModalProcessorCache.invalidate()`, leaving poisoned entries cached indefinitely.
- **Design & Trade-offs:**
  - Checking `int(encoder_output.shape[0]) != pos_info.get_num_embeds()` at gather time catches both underflow (`138` vs `638` on chunk 0 instead of waiting for the final chunk) and overflow (`638` vs `138` silent wrong-slice corruption) using host-side tensor shape metadata with zero D2H synchronization. Both MRV1 (still default in many multimodal deployments) and MRV2 share `evict_mismatched_mm_features` in `vllm/multimodal/utils.py`.
  - Recording evicted identifiers in `poisoned_mm_hashes` until `free_encoder_mm_hashes` arrives prevents same-step duplicate requests or speculative drafter `+1` look-ahead gathers from raising `RuntimeError("Encoder cache miss")`.
  - Reuses `EngineCoreOutput.mm_cache_miss_hashes` (`#46747` / `#62164`) to drive P0/P1 processor cache invalidation while preserving `RequestError(code="validation_error")` in `OutputProcessor` for both generation and pooling requests.
