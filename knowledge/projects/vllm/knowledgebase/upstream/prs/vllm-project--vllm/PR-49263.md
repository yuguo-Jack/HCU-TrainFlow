# [Perf] [Feat] [ROCm] Add densemha support to ROCm AITER Sparse MLA

[Upstream PR](https://github.com/vllm-project/vllm/pull/49263) · state: closed · merged: True

## Original PR description

## What is the feature about?

Adds dense MHA for short prefill in the ROCm AITER Sparse MLA backend, following #47327. Prefill at or below the sparse top-k threshold (2,048 tokens for DeepSeek-V3.2) uses dense attention; longer prefill and decode retain sparse MQA. The fused DeepSeek-V3.2 path is integrated so mixed prefill/decode batches use the correct metadata.

## Test plan

- Compare BF16/FP8-KV engine outputs and log probabilities against forced sparse MQA; cover unequal/chunked prompts, the 2,048-token boundary, and mixed prefill/decode
- Trace the actual pretrained dense/sparse paths separately from timing; run existing metadata, sparse-attention, and sink tests collected by MI300/MI355 CI
- Compare matched pretrained GSM8K/harder-task accuracy and short/long-prompt serving at concurrency 1/8/32

## Test results

Published `7abb8ef` has the same tree as validated `e34b94e`; baseline: `b538d807`. **187 passed, 116 skipped, 14 warnings; local staged pre-commit passed.** Runtime tracing confirmed dense prefill through 2,048 tokens, sparse at 2,049, and mixed dense-prefill/sparse-decode execution.

Pretrained runs: official DeepSeek-V3.2, 8× AMD gfx950/TP8, FP8 weights, BF16 activations/KV, AITER, eager execution, prefix caching off. ROCm 7.2.3, Torch `2.13.0+git733fca1`, AITER 0.1.23, Triton `3.8.0+git669b31ac`.

| Serving: short prompts | TTFT ms, baseline → PR | Paired TTFT change [95% interval] | TPOT/ITL ms | Output tok/s |
|---|---:|---:|---:|---:|
| Concurrency 8 | 526.61 → 480.76 | -8.69% [-16.87%, -0.51%] | 160.60 → 158.75 | 48.07 → 48.79 |
| Concurrency 32 | 975.01 → 904.60 | -7.07% [-20.12%, +5.99%] | 143.40 → 139.69 | 198.15 → 204.27 |

Three paired process rounds, fixed 64-token outputs, warmup, 864/864 successful timed requests. These are bounded bursts, with one measured wave at concurrency 32. Long-prompt TTFT was roughly unchanged; short/concurrency-1 throughput decreased 1.23%. Most throughput intervals span zero; these are not production compiled-mode or broad no-regression claims.

| Matched raw-response accuracy | Baseline | PR | Δ |
|---|---:|---:|---:|
| GSM8K 5-shot, strict | 95.38% | 95.53% | +0.15 pp |
| GSM8K 30-shot, strict | 95.30% | 95.38% | +0.08 pp |
| MMLU-Pro, final-answer extraction | 80.13% | 79.69% | -0.45 pp |
| MMLU-Pro, supplementary first-answer extraction | 80.36% | 79.24% | -1.12 pp |

MMLU-Pro is a pinned, category-balanced zero-shot diagnostic, not the full benchmark. At 4,096 output tokens, 37 baseline/45 PR responses hit the cap; selected 8,192-token retries still capped 16/18. Extraction and repeat sensitivity materially limit conclusions. A selected GSM8K control also produced adverse candidate output; its cause remains unresolved. **No equivalence or non-inferiority claim.**
