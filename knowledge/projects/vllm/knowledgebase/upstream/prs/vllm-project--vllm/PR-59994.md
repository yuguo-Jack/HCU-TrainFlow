# [Bugfix] Offload model runner construction buffers on sleep

[Upstream PR](https://github.com/vllm-project/vllm/pull/59994) · state: open · merged: False

## Original PR description

## Purpose

Follow-up to #59158. Part of RFC #59055.

#59158 builds the KV-cache initialization state inside the `runtime` cuMem pool, so sleep backs it up to CPU and restores it on wake. Buffers that the model runner allocates in its constructor are still allocated outside every pool, so they stay on the GPU while asleep. On DeepSeek-V4-Flash with MTP, the drafter's `hidden_states` buffer (`spec_decode/autoregressive/speculator.py`) is 512 MiB/GPU.

The earlier revision of #59158 built the model runner inside the `runtime` pool too; that part was dropped before merge. This PR brings it back:

- `Worker` builds the model runner inside the `runtime` pool.
- The one-allocator-per-process check moves from the `weights` pool to that first pool entry.

## Test Plan

- New test `test_model_runner_buffers_survive_sleep` in `tests/basic_correctness/memory/cumem/test_cumem.py` (levels 1 and 2): a buffer allocated while the runner is built lands in the `runtime` tag and keeps its contents across sleep and wake.
- `tests/basic_correctness/memory/cumem/test_cumem.py`, `tests/v1/worker/test_gpu_worker.py`, `tests/v1/worker/test_sleep_mode_backend.py`, with and without this change.
- GB300, DeepSeek-V4-Flash TP4 + EP4 with MTP, level-1 sleep: memory while asleep, with and without `--enable-nccl-comm-suspend`, and outputs after wake compared with the awake run.

## Test Result

- The new test passes 3/3 with this change and fails 3/3 without it (`assert set() == {'runtime'}`).
- `test_cumem.py`: 16 passed with this change vs 14 on main; the 7 failures are the same on both sides (models not in the offline cache). `test_gpu_worker.py` + `test_sleep_mode_backend.py`: 29 passed on both.
- DeepSeek-V4-Flash TP4, memory per GPU while asleep:

| | main (+ graph pool released) | this PR |
|---|---:|---:|
| sleep mode | 8633 MiB | 8121 MiB (−512) |
| + `--enable-nccl-comm-suspend` | 6451 MiB | 5939 MiB (−512) |

- The `runtime` tag grows from 4704 to 5218 MiB. Outputs after two wakes are identical to the awake run, and wake time is unchanged.
- Not yet covered: Model Runner V1 and GSM8K.
