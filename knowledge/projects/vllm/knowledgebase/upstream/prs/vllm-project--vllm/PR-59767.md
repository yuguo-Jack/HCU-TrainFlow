# [Model] Migrate Aria to the Transformers modeling backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/59767) · state: open · merged: False

## Original PR description

## Overview

Move Aria to the Transformers modeling backend, now that huggingface/transformers#48907 (5.18.0) puts its MoE on the standard experts interface. Deletes `aria.py` (534 lines). The shared backend changes landed in #57410.

## Claims

- `AriaForConditionalGeneration` → `TransformersMultiModalMoEForCausalLM`, requires `transformers>=5.18.0` (clear `ImportError` otherwise).
- `test_common` runs Aria again; `tests/models/multimodal/test_aria.py` (native internals only) is removed.
- Image outputs differ from `main` by design: HF masks padded vision patches, native vLLM doesn't (#36206).

## Validation

1x A100-80GB, `transformers` 5.19.0. "+ HF fix" adds huggingface/transformers#49594, which stops HF keeping every vision layer's hidden states (identical features).

| | `main` | branch | + HF fix |
|---|---|---|---|
| gsm8k | 0.642 | 0.640 | |
| ChartQA | 0.658 | 0.612 | 0.604 |
| KV cache (tokens) | 81,456 | 72,864 | 81,552 |
| Text output tok/s | 947 | 683 | |
| Image output tok/s | 2,226 | 1,660 | 2,327 |

Single runs. ChartQA differences between the last two columns are batching nondeterminism.

```bash
vllm serve rhymes-ai/Aria --max-model-len 8192 --gpu-memory-utilization 0.9
python tests/evals/gsm8k/gsm8k_eval.py  # ChartQA: evalscope against the same server
vllm bench throughput --model rhymes-ai/Aria --input-len 1024 --output-len 256 --num-prompts 1000
vllm bench throughput --model rhymes-ai/Aria --backend vllm-chat --dataset-name random-mm --num-prompts 500 \
  --random-mm-base-items-per-request 1 --random-mm-limit-mm-per-prompt '{"image": 1}' --random-mm-bucket-config '{(980, 980, 1): 1.0}'
pytest tests/models/test_initialization.py tests/models/multimodal -k aria  # 6 passed
```

**Open:** text throughput is 28% below native; vision masking (keep HF's?).
