# Experiment OCTAVE KV on GFX1151

[Upstream PR](https://github.com/vllm-project/vllm/pull/65696) · state: open · merged: False

## Original PR description

## Overview

This PR enables Octave KV (`ROCM_OCTAVE`) on gfx1151 (Strix Halo, RDNA3.5).

Upstream currently allows Octave only on gfx942 and gfx1100, so `--kv-cache-dtype octave_*` can't run on gfx1151. To try it, I modified the build and kernel dispatch to accept gfx1151, then ran `vllm bench` on real hardware. This PR contains those changes and the results.

[#59774](https://github.com/vllm-project/vllm/pull/59774) reports that, on 4x RX 7900 (gfx1100), Octave stores 4.6x more KV tokens than fp16 and matches its GSM8K accuracy, with `octave_k3v3` scoring 92.4 against 91.8 for fp16. Those are its numbers, not mine. The results below are the gfx1151 measurements.

I'm aware that RDNA3 (gfx1100) and RDNA3.5 (gfx1151) are different architectures, so the gfx1100 results don't automatically carry over to gfx1151. I'm opening this PR for enablement: it makes Octave available on gfx1151 using the existing kernels, not tuned for RDNA3.5.

**Serving**

The baseline omits `--kv-cache-dtype octave_k3v3` or `octave_k3v4`.

```bash
vllm serve cyankiwi/Qwen3.8-27B-AWQ-INT4 \
  --dtype float16 \
  --kv-cache-dtype octave_k3v3 \ # Or octave_k3v4 in k3v4 benchmark
  --tensor-parallel-size 1 \
  --max-model-len 131072 \
  --max-num-seqs 6 \
  --max-num-batched-tokens 2048 \
  --language-model-only \
  --speculative-config '{"method":"qwen3_next_mtp","num_speculative_tokens":3}'
```

**Benchmark**

```bash
MODEL=cyankiwi/Qwen3.8-27B-AWQ-INT4
TAG=octave_k3v3 # Or octave_k3v4 in k3v4 benchmark

run() {
  vllm bench serve \
    --model $MODEL \
    --dataset-name random \
    --random-input-len $1 \
    --random-output-len 512 \
    --ignore-eos \
    --seed 0 \
    --num-prompts $2 \
    --max-concurrency $3 \
    --percentile-metrics ttft,tpot,itl,e2el \
    --save-result --result-filename bench_${TAG}_${1}_c${3}.json
}

run 8000   6  1
run 32000  4  1
run 100000 3  1
run 8000   64 16
```
