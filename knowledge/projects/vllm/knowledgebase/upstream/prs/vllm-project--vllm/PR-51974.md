# [Profiling] Add support for profile_prefix payload in HTTP /start_profile endpoint

[Upstream PR](https://github.com/vllm-project/vllm/pull/51974) · state: open · merged: False

## Original PR description

## Proposal: Upstream Support for Dynamic Profiling Options (`profiler_kwargs`)

Allow users to pass dynamic profiler configuration options (`profiler_kwargs`) via both the HTTP `/start_profile` endpoint and `LLM.start_profile(...)` / `AsyncLLM.start_profile(...)` without requiring engine server restarts. This enables on-the-fly customization of native [`torch.profiler.profile`](https://docs.pytorch.org/docs/2.13/profiler.html#api-reference) options (e.g., `record_shapes`, `with_stack`, `profile_memory`, `with_flops`, `with_modules`) as well as backend-specific profiler options in downstream hardware plugins (e.g., TPU / XPU).

### Current Gap
Currently, profiler settings are statically bound at server startup via `--profiler-config`:
* **❌ Online Serving (`api_router.py`):** The `/start_profile` endpoint accepts no request body or dynamic parameters, making it impossible to toggle expensive profiler options (such as `record_shapes`, `with_stack`, or hardware-specific experimental trace levels) per profiling session on a running server.
* **❌ Offline & Engine Plumbing (`LLM` / `AsyncLLM` / `EngineCore` / `Worker`):** `start_profile` and `TorchProfilerWrapper` only consume static `ProfilerConfig` fields and do not accept a `profiler_kwargs` dictionary to override or forward per-session profiler options downstream.

### Purpose & Implementation
This PR introduces an explicit, optional `profiler_kwargs: dict[str, Any] | None = None` parameter that flows cleanly from the entrypoints down to the worker profilers:

1. **HTTP Router & Engine Protocol (`api_router.py`, `protocol.py`, `llm.py`):**
   - Updates `POST /start_profile` to accept an optional JSON dictionary body (`profiler_kwargs: Annotated[dict[str, Any] | None, Body()] = None`).
   - Updates `EngineClient.start_profile` and `LLM.start_profile` to accept `profiler_kwargs`.
2. **Engine Core & Multiprocess IPC (`async_llm.py`, `llm_engine.py`, `core_client.py`, `core.py`):**
   - Forwards `profiler_kwargs` through `InprocClient`, `SyncMPClient`, and `AsyncMPClient` (`call_utility` / `call_utility_async`) into `EngineCore.profile`.
3. **Executor & Worker RPC (`abstract.py`, `gpu_worker.py`, `xpu_worker.py`, `cpu_worker.py`):**
   - `Executor.profile` forwards `kwargs={"profiler_kwargs": profiler_kwargs}` via `collective_rpc` only when `profiler_kwargs is not None`, preserving 100% backward compatibility with out-of-tree worker plugins when `profiler_kwargs` is omitted.
   - Resets `self.profiler = None` on `stop()` for `"torch"` (matching `"proton"`) so subsequent `/start_profile` runs honor updated `profile_prefix` and `profiler_kwargs`.
4. **Profiler Wrapper (`wrapper.py`):**
   - Updates `TorchProfilerWrapper` to merge `profiler_kwargs` into the `torch.profiler.profile(...)` argument dictionary (`profile_args.update(profiler_kwargs)`), allowing callers to safely override default flags without raising duplicate keyword `TypeError`s.
5. **Documentation (`docs/contributing/profiling.md`, `docs/serving/offline_inference.md`, `docs/serving/online_serving/README.md`):**
   - Documents `profiler_kwargs` for both online (`POST /start_profile`) and offline (`LLM.start_profile`) usage.

## Test Plan
1. Start an API server with profiling enabled:
   ```bash
   vllm serve facebook/opt-125m --profiler-config '{"profiler": "torch", "torch_profiler_dir": "./vllm_profile"}'
   ```
2. Trigger the profiler over HTTP, passing dynamic options inside the JSON body:
   ```bash
   # Override standard torch.profiler.profile options:
   curl -X POST http://localhost:8000/start_profile \
     -H "Content-Type: application/json" \
     -d '{"record_shapes": true, "with_stack": true}'

   # Or pass backend-specific options (e.g., for TPU profiler backend):
   curl -X POST http://localhost:8000/start_profile \
     -H "Content-Type: application/json" \
     -d '{"host_tracer_level": 3, "e2e_enable_fw_throttle": true}'
   ```
3. Issue generation requests to capture traces.
4. Stop the profiler:
   ```bash
   curl -X POST http://localhost:8000/stop_profile
   ```
