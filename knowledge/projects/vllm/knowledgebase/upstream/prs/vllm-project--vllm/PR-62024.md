# [Bugfix][Mistral] Route json_schema without tools to schema-only grammar

[Upstream PR](https://github.com/vllm-project/vllm/pull/62024) · state: closed · merged: False

## Original PR description

## Why

When a chat completion request sets `response_format=json_schema` (or an equivalent `structured_outputs`) and omits tools, `MistralToolParser.adjust_request` normalizes `tool_choice=null` to `MistralToolChoiceEnum.auto` and falls through to `grammar_factory.get_lark_from_jinja` with `tools=None, json_schema=X, json_only=False`.

That renders:

```lark
start: body | SAFE_WS? %json {USER_SCHEMA}
body: content | (content? fcalls)
fcalls: ([TOOL_CALLS] SAFE_WS? /.+/ [ARGS] SAFE_WS? %json {"type":"object"} SAFE_WS?)+
content: ...
```

The grammar permits free text and wildcard `[TOOL_CALLS] /.+/ [ARGS] {anything}` tool-call emissions alongside the schema branch. The user asked for a schema-constrained output; the grammar does not enforce it. In practice a model trained with tools-in-prompt is biased against emitting `[TOOL_CALLS]` without tools, so outputs are *usually* fine — but the structural guarantee the API advertises isn't held.

## Reachability

Reachable from the OpenAI-compatible API with `tools=None` and `response_format=json_schema` when either:
- `tool_choice: null` is explicitly in the JSON (several OpenAI SDK clients send this by default), or
- `tool_choice` is unset *and* the client uses `structured_outputs` (through the equivalent null path).

The request validator at `vllm/entrypoints/openai/chat_completion/protocol.py` rejects `tool_choice="auto"` / `"required"` without tools, so only `null` / `"none"` (/omitted) reach the parser.

## Fix

Route `(json_schema set, no tools)` to `get_lark_for_json_schema` regardless of `tool_choice`. The previously-handled `tool_choice="none"` + tools + schema case is preserved by an added match arm.

```python
has_tools = mistral_tools is not None and len(mistral_tools) > 0
match tool_choice, has_tools, json_schema is not None:
    case _, False, True:
        lark_grammar = grammar_factory.get_lark_for_json_schema(...)
    case MistralToolChoiceEnum.none, True, True:
        lark_grammar = grammar_factory.get_lark_for_json_schema(...)
    case _, _, _:
        lark_grammar = grammar_factory.get_lark_from_jinja(..., json_only=False)
```

Resulting grammar for the buggy request becomes:
```lark
start: SAFE_WS? %json {USER_SCHEMA}
```

## Model evaluation

This change tightens an existing structured-output grammar from "schema OR text OR wildcard tool call" to "schema only" when no tools are present. It does not affect any path where tools are provided, nor any non-schema path. Model behavior on grammar-constrained generation is unchanged for all tool-using requests; for the fixed path, output is already dominated by the schema branch at inference time due to the training distribution (models rarely emit `[TOOL_CALLS]` without tools in the prompt), so observable output quality is not expected to regress. A full generation eval was not run because the change is a grammar-structure correctness fix rather than a numerical change, and the test suite covers the routing contract.
