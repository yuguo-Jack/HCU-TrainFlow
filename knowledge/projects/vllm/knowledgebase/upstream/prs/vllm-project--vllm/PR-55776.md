# [Bugfix][KV Connector] Include model revisions in NIXL compatibility hash

[Upstream PR](https://github.com/vllm-project/vllm/pull/55776) · state: open · merged: False

## Original PR description

## Purpose

NIXL's compatibility hash checks model geometry but not the primary model's
revision. During a rolling update, prefill and decode replicas can therefore load
different weights from the same model repository, pass the handshake, and mix KV
states.

fix: Include the resolved primary model `revision` and the supplied
`code_revision` in the hash, and bump the connector version so older hash
semantics cannot interoperate silently.

`code_revision` is not resolved by vLLM, so this catches different supplied
code revisions but not the same branch resolving to different code commits.
Covering that would require tracking the actual loaded code commit, including
code hosted in a separate repository, and using it in the handshake.

## Test Plan

- Focused NIXL compatibility-hash unit test before and after the fix.
- Ruff check, Ruff format check, and `git diff --check` on the changed files.
- Live NIXL P/D evaluation on two NVIDIA L4 GPUs with two commits of
  `microsoft/Phi-3-mini-4k-instruct` that have identical KV geometry but different
  checkpoint blobs.
- Duplicate check: no matching open issue or PR. #52999 exposes this hash to
  routers during rolling upgrades but does not add model revision identity.

## Test Result

- Unit test RED: 3 failed, 1 passed, 107 deselected.
- Unit test GREEN: 4 passed, 107 deselected.
- Unpatched A-prefill/B-decode passed the compatibility handshake. Compared with
  B-prefill/B-decode, generated tokens differed for 25/32 fixed-token prompts;
  the mean shared-top-logprob delta was 13.46× the same-revision control.
- Patched A-prefill/B-decode logged a compatibility-hash mismatch and rejected
  the remote KV, then recovered through local computation.
- Patched and unpatched A/A outputs were byte-identical across all 32 prompts.
- Ruff check/format and `git diff --check` passed. Applicable pre-commit code and
  content hooks passed; three shell-only hooks could not start on Windows because
  `/bin/bash` was unavailable.
