# [Bugfix][DSA] Disable native padded decode on ragged spec-decode batches (#64855)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64887) · state: open · merged: False

## Original PR description



## Overview

Disable native padded decode in DeepseekV32IndexerMetadataBuilder when positive per-request decode lengths in a speculative decoding step are non-uniform, falling back to per-token flattened decode.

Fixes #64855

## Claims

- Fixes wrong indexer logits and top-k block selection on ragged multi-token decode batches when native padded decode is enabled without varlen or flattening.

## Validation

```bash
pytest tests/v1/attention/test_indexer_native_next_n.py -v
```

## Details

When max_decode_len > 1 and a batch mixes requests with different positive decode lengths (such as a 1-token request alongside a (1 + k)-token request after rejected draft tokens or a freshly prefilled request), the native padded path expands every request's context lengths using max_decode_len and packs queries into (B, max_decode_len) while top_k_per_row_decode reads the first batch_size * next_n rows as a dense prefix. Requiring uniform positive decode_lens for use_native routes ragged steps through the existing per-token flattening path.
