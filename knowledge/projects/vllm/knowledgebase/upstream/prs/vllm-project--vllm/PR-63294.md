# [WIP] Add ECTieringConnector filesystem tiering for encoder cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/63294) · state: open · merged: False

## Original PR description

## Overview

Add an experimental local-filesystem secondary tier for the native encoder cache. CPU memory remains the primary tier, while encoder outputs can be written to and asynchronously promoted from filesystem storage through the new `ECTieringConnector`.

This is a draft for early architecture and implementation feedback. Full end-to-end and accelerator validation is still pending.

## Claims

- Adds `ECTieringConnector` while reusing the existing `ECCPUConnector` worker and CPU-to-device transfer path.
- Supports asynchronous CPU-to-filesystem write-through and filesystem-to-CPU promotion.
- Stores one complete encoder-cache item per `.ec` file.
- Reuses the existing KV offload `DualQueueThreadPool` directly. The encoder cache owns a separate pool instance.
- 
## Details

The data paths introduced by this change are:

```text
encoder output
  -> device to CPU through the existing ECCPU worker
  -> CPU entry becomes ready
  -> pin CPU entry
  -> asynchronous CPU to filesystem write
  -> publish the .ec file
  -> release the CPU pin
```

```text
filesystem index hit
  -> allocate a not-ready CPU entry
  -> submit an asynchronous filesystem read
  -> defer the request without blocking the scheduler
  -> mark the CPU entry ready after successful completion
  -> use the existing ECCPU CPU-to-device load path
```
