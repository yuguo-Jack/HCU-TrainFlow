# [ROCm] Enable fused QK-norm+RoPE+gate Triton kernel for Qwen3-Next/Qwen3.5

[Upstream PR](https://github.com/vllm-project/vllm/pull/51406) · state: open · merged: False

## Original PR description

## Purpose

`Qwen3NextAttention` fuses the gated QKV split + QK-RMSNorm + (partial) NeoX RoPE + gate copy into a single Triton kernel (`fused_qk_rmsnorm_rope_gate`, added in https://github.com/vllm-project/vllm/pull/44176). The kernel is pure Triton and backend-agnostic, but it is gated behind `current_platform.is_cuda()`, so ROCm falls back to the slow multi-op eager path, even though the kernel runs correctly and fast on AMD GPUs.

This PR relaxes that one-line guard to `is_cuda_alike()` so ROCm gets the same fusion. It affects the whole `Qwen3NextAttention` family: Qwen3-Next, Qwen3.5, Qwen3.5-MoE

Measured on MI325X (gfx942), bf16, against the model's real eager branch
(`GemmaRMSNorm` + the `rotary_emb` custom op), 300 timed iters after 50 warmup:

| Seq len (tokens) | Eager (µs) | Fused (µs) | Speedup |
|---|---|---|---|
| 1 (decode) | 279.4 | 33.0 | 8.47× |
| 8 | 279.3 | 33.6 | 8.32× |
| 64 | 281.7 | 33.9 | 8.32× |
| 512 | 277.4 | 33.7 | 8.22× |
| 4096 | 562.3 | 138.7 | 4.05× |

Note: https://github.com/vllm-project/vllm/pull/47719 is an opt-in AITER path that additionally fuses the KV-cache write.

## Test Plan

Additional data from MI355X (gfx950) in favor of this change, from the DFlash2-on-ROCm work tracked in #61761.

**Setup.**
- Qwen3.8-27B + `z-lab/Qwen3.8-27B-DFlash2` (7 draft tokens), one MI355X, bf16, MRV2.
- Both sides include #61433, so the target uses `ROCM_AITER_UNIFIED_ATTN` and the drafter uses `TRITON_ATTN`. The only difference is this PR's `is_cuda_alike()` guard.
- Image `vllm/vllm-openai-rocm:nightly-rocm100-0cbac6cd1305f710e12193596b27488397bcb205`.

**Kernel.** For the Qwen3.8 full-attention shape (24 q heads + gate, 4 KV heads, head_dim 256, rotary_dim 64), the fused kernel vs. the Inductor-compiled path:
- about 14 → 2.2 µs per layer at 8 tokens (6.3×);
- 2.1× at 512 tokens;
- max abs error 0.062 in bf16.

`tests/kernels/test_fused_qk_norm_rope_gate.py` passes on MI355X.

**End to end.** ShareGPT, 512 output tokens, temperature 0. Output tok/s, mean of 2 runs with the GPUs swapped between the two sides:

| | c=1 | c=16 | c=64 |
|---|---|---|---|
| main | 267.8 | 2382.7 | 3956.3 |
| with this change | 269.5 | 2400.3 | 3981.0 |

- That is +0.6–0.7%, which is below the 1–1.5% spread between runs. With 16 attention layers in a 64-layer hybrid model, the saving is a small part of a step.
- Acceptance length is unchanged.
- GSM8K (5-shot, 1319 questions, `tests/evals/gsm8k/gsm8k_eval.py`): 0.792 → 0.785 (8 questions).

@xuebwang-amd, could you rebase? #56096 has since changed the same line on main to `current_platform.is_cuda() or current_platform.is_xpu()`, so the rebased guard would be `current_platform.is_cuda_alike() or current_platform.is_xpu()`. Main now also has `tests/kernels/test_fused_qk_norm_rope_gate.py`, which already runs on ROCm (`is_cuda_alike()` skip). Your added test may overlap with it.
