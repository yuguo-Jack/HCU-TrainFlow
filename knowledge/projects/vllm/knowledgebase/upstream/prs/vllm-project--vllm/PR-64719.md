# [CI] Narrow CUDA image cache inputs and reuse published ancestors

[Upstream PR](https://github.com/vllm-project/vllm/pull/64719) · state: open · merged: False

## Original PR description

## Overview

Reduce unnecessary CUDA image rebuilds by narrowing requirement bind mounts and supplementing main's parent/latest cache imports with published ancestor caches. The separate warm-worker change is [ci-infra PR #822](https://github.com/vllm-project/ci-infra/pull/822).

## Claims

- Changes to unrelated requirement files no longer invalidate the five Docker stages that consume only Rubin or KV-connector requirements.
- Main can reuse up to three published caches from the previous 20 first-parent ancestors beyond its parent when that parent is still building. Existing cache sources remain intact.
- Lookup uses one ECR metadata request, has bounded timeouts, and fails open; it does not serialize image builds.

## Validation

- `/tmp/image-build-venv/bin/python -m pytest --confcutdir=tests/tools tests/tools/test_docker_build_metadata_args.py -q`: **11 passed**. New tests use real Git history and an external-service stub for ECR; they cover reverse-ordered registry results, unavailable caches, invalid responses, and PR bypass.
- `pre-commit run --files` on changed files: passed, including shellcheck, ruff, CI test tethering, Docker version validation, and documentation lint.
- Real BuildKit regression using the five bind-mount configurations extracted from the base and changed Dockerfile: changing only `requirements/build/rocm.txt` invalidated all five before the change and zero afterward. Changing Rubin pins still invalidated its three consumers; changing CUDA-12 KV pins still invalidated its consumer.
- `docker buildx bake --print` verified ancestor imports append to, rather than replace, current-commit, parent, and configured cache imports.
- Same-commit image-only CI validation: [warm queue](https://buildkite.com/vllm/ci/builds/98686), [cold queue](https://buildkite.com/vllm/ci/builds/98683). Results pending.
- No serving/model behavior changes or model evaluations. End-to-end CI speedup is not yet established.

## Details

A [20m18s main image build](https://buildkite.com/vllm/ci/builds/98406#01a188e0-9e99-4d6e-9002-54ea70bf001c) rebuilt the CUDA dependency/native layers after a ROCm-focused requirement change. The entire requirements directory was included in bind-mount cache keys. Mounting only the consumed files retains invalidation for those files and avoids unrelated backends invalidating these layers.

A [19m42s Rust-only main build](https://buildkite.com/vllm/ci/builds/98659#01a18bfd-87a6-433b-8845-c46ea90ffde4) could not import its parent's cache because the parent was still building. Ancestor lookup supplements the rolling cache with a bounded set of completed first-parent caches. This does not guarantee a hit after a genuine dependency or native-source change and cannot eliminate every duplicate in-flight build.

Duplicate-work checks found no open PR for these CUDA bind mounts or this main-ancestor lookup. Existing [ROCm cache work](https://github.com/vllm-project/vllm/pull/64131) addresses the separate ROCm build path. The warm-worker fix reuses the existing ci-infra PR rather than duplicating it.
