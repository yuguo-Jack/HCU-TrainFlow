# [Performance][NIXL] Optimize nixl descriptors for block-outermost kv cache layout

[Upstream PR](https://github.com/vllm-project/vllm/pull/60851) · state: open · merged: False

## Original PR description



## Overview

Coalesce eligible, physically adjacent MLA KV-cache layer views into packed NIXL memory regions within each transfer group. This reduces repeated block-descriptor registration while preserving the transfer-group mappings.
The new partial-span coalescing applies to NIXL pull workers only. Push keeps its existing packed-row registration; this change does not add partial-span coalescing or mixed-layout fallback for push. Push can be supported with this optimization in follow-up PRs.

## Claims

The optimization requires a block-outermost KV-cache layout; the GLM-5.3 deployment used `BLHNC`. Coalescing also requires compatible region geometry and adjacency. Other layouts and ineligible regions use the standard registration path.

Validated with `RedHatAI/GLM-5.3-MXFP4` on a GB200 NVL72, using one EP8 prefill replica and one EP8 decode replica. The deployment used the block-outermost `BLHNC` layout. The workload was Weka agentic multi-turn replay, with roughly 110–160K input tokens and 900–1,000 output tokens per request.

At concurrency 32, the NIXL numbers are:

- **NIXL post p95:** about 3.85 s before optimization, with spikes to 5 s; about 52 ms after.
- **NIXL transfer p95:** about 4.52 s before; about 81 ms after.
- **Pool-level registered descriptors:** 3,234,222 before versus 121,580 after, about 96% fewer, assuming comparable KV-pool sizes and configuration.

Latency figures are medians across the dashboards’ repeated p95 estimates during each run.

## Details

### Root problem
With GLM-5.3’s block-outermost KV layout, adjacent MLA layer views can occupy contiguous memory. NIXL’s registration loop still registers those views separately, repeating block descriptors across layers. This increases registered descriptor volume and contributes to NIXL post overhead.


### Design

Coalesce adjacent, geometry-compatible MLA views into a wider NIXL region within the same transfer group. Preserve the layer-to-region mapping and exclude packed-span regions from later address-based deduplication.

The optimization is guarded by backing-storage, device, cache-spec, stride, block-count, and adjacency checks. Ineligible regions continue through the normal registration path.
