# [Attention] Enable FA4 CUDA graphs for adaptive verification

[Upstream PR](https://github.com/vllm-project/vllm/pull/58591) · state: open · merged: False

## Original PR description

## Summary

Enable full CUDA graph replay for FlashAttention 4 when adaptive speculative
verification is enabled.

Adaptive verification changes per-sequence query lengths between replays while
keeping the captured token buffer size fixed. FA4 consumes the device-side
query offsets during replay, so the metadata builder can return
`AttentionCGSupport.ALWAYS` for this configuration. Other FlashAttention
versions retain the existing backend default.

This PR also adds a regression test that captures one FA4 graph and replays it
with uniform and ragged device-side query lengths. BF16 is tested wherever FA4
is supported; FP8 inputs are tested on SM100.

## Validation

- Local capability test: `4 passed`
- Ruff lint and format: passed
- Test tethering and `git diff --check`: passed

The replay test is wired into the existing B200 kernel job for current-main
BF16 and FP8 validation.

An equivalent override was also used with vLLM v0.29.0 on 2x B200 for
Nemotron-H + DSpark adaptive verification. The recorded chat, decode,
long-context, and summarization runs completed with zero failed requests.
