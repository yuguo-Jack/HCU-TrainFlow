# [Quantization][MoE] Prefer Humming over Marlin for MXFP8 MoE on SM12x

[Upstream PR](https://github.com/vllm-project/vllm/pull/63777) · state: open · merged: False

## Original PR description

## Purpose

On SM12x GPUs (RTX PRO 6000 Blackwell, RTX 50xx, GB10) the 8-bit Marlin MoE kernel has no fitting thread tile for MXFP8 expert shapes whose intermediate size is not a multiple of 128, and fails at warm-up:

```
RuntimeError: marlin_mm, csrc/moe/marlin_moe_wna16/ops.cu:348, Invalid thread config: ... for MKN = [8192, 2688, 1856] and num_bits = 8, group_size = 32, ... max_shared_mem = 101376
```

Reproducer: `vllm serve nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16 --quantization mxfp8` on an RTX PRO 6000 (intermediate size 1856).

Humming has no such limit and is the announced successor to Marlin, so the MXFP8 MoE backend selection now moves Humming directly ahead of Marlin on SM12x. The reorder is local to `oracle/mxfp8.py`, mirroring the SM11x/SM12x special case in `oracle/mxfp4.py`; `humming/priority.py` is untouched. Other compute capabilities and all other kernel families are unchanged. Marlin remains selectable with `--moe-backend marlin`.

## Test Plan

- `tests/kernels/quantization/test_scaled_mm_kernel_selection.py`: new parametrized case checks that on SM12x Humming is directly ahead of Marlin in the MXFP8 backend order, on non-SM12x Marlin stays ahead, and no other backend moves. Passes in the v0.32.0 container on an RTX PRO 6000 (live order: FLASHINFER_TRTLLM, DEEPGEMM, HUMMING, MARLIN, ...).
- RTX PRO 6000 Blackwell Server Edition (SM120, 99 KB smem), vLLM v0.32.0 image with only `oracle/mxfp8.py` replaced.
- Nemotron 3 Nano BF16 `--quantization mxfp8`: stock selects MARLIN and crashes as above; patched selects HUMMING and serves.
- Decode-heavy A/B on a public MXFP8 MoE model that Marlin already handles (Qwen3-30B-A3B, `--quantization mxfp8`, forced via `--moe-backend`), `vllm bench serve`, random 1024 in / 256 out, `--ignore-eos`.
- GSM8K, lm_eval 5-shot, 1319 samples, chat template, `max_gen_toks=1024`, thinking disabled.

## Test Result

Qwen3-30B-A3B MXFP8, same shapes for both kernels:

| Concurrency | Metric | Marlin | Humming |
|---|---|---|---|
| 1 | Median TPOT (ms) | 5.83 | 5.73 |
| 1 | Output tok/s | 164.8 | 166.3 |
| 1 | Median TTFT (ms) | 64.4 | 78.7 |
| 32 | Median TPOT (ms) | 19.60 | 19.69 |
| 32 | P99 TPOT (ms) | 24.21 | 23.53 |
| 32 | Output tok/s | 1346 | 1374 |
| 32 | Median TTFT (ms) | 671 | 505 |
| 32 | Median E2EL (ms) | 5633 | 5412 |

GSM8K exact_match (strict / flexible):

| Model | Backend | strict | flexible |
|---|---|---|---|
| Qwen3-30B-A3B MXFP8 | Marlin | 0.9105 ± 0.008 | 0.9181 ± 0.008 |
| Qwen3-30B-A3B MXFP8 | Humming | 0.9075 ± 0.008 | 0.9158 ± 0.008 |
| Nemotron 3 Nano MXFP8 | Humming (patched; stock crashes) | 0.9075 ± 0.008 | 0.9067 ± 0.008 |

Decode is at parity within noise; at concurrency 32 Humming is slightly ahead on throughput, tail TPOT, TTFT and E2E. Accuracy is identical within stderr. Only SM120 was tested; SM121 (GB10) is included on the basis of its documented 99 KB shared-memory limit.
