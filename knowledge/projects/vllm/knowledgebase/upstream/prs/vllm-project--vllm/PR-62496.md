# [Bugfix] Drop the Ultravox encoder host sync and 3000-mel LoRA pad

[Upstream PR](https://github.com/vllm-project/vllm/pull/62496) · state: open · merged: False

## Original PR description

## Overview

Fixes #62349.

The Ultravox encoder and transformer projector read chunk lengths back to the host inside the forward, and tower/connector LoRA padded every mel to 3000. This draft builds the attention index on the host before the tower, zeros the conv1 tail before conv2, and drops that pad.

This is a first-cut draft. AI assistance was used (Grok). GPU end-to-end was not run.

## Claims

- The encoder and both projectors no longer call `feature_lens.cpu().numpy()`. The gather index is built from host `audio_lens` before the tower runs.
- After `gelu(conv1)`, conv1 time `t >= audio_lens` is zeroed before conv2, so a later right pad does not change odd-length clips.
- `pad_audio_to_max_context` and the `F.pad` to `max_context_length` are gone. `mel <= max_context_length` still raises. Tower/connector LoRA runs one tower and projector pass; `_MAX_ENCODER_BATCH_SIZE` applies only when that LoRA is off.
- `get_mm_lora_token_counts` keeps three formulas. Init sizing (`mm_kwargs is None`) is an upper bound: 3008 → `(24064, 3008)`, 8192 → `(66000, 8272)`. Runtime 17 mel → `(9, 2)`. Missing `audio_lens` → `(0, 0)`, so a later audio item still gets a connector map.
- Ultravox does not opt into the Whisper encoder CUDA-graph protocol. #61608 (punica sizing buffer) is a different bug and is not fixed here.

## Validation

No GPU end-to-end run, no benchmark numbers, and no `collect_env` output. The machine used here has torch 2.5.1, no CUDA, and no MPS. `/opt/anaconda3/bin/python` can import the `vllm` package root and cannot import `vllm.model_executor.models.ultravox` (`direct_register_custom_op` rejects `list[int]` on torch 2.5.1). `tests/models/multimodal/test_ultravox_encoder_pack.py` imports vLLM, so it was not collected or executed. It is marked `core_model`, which the multimodal GPU job already collects via `pytest -v -s models/multimodal -m core_model`. The CUDA `feature_lens` case in that file is `skipif(not torch.cuda.is_available())` and was not run.

A CPU-only script, `/tmp/vllm-62349-check.py` (not committed), parsed `vllm/model_executor/models/ultravox.py` and executed the real helpers plus the encoder, feed-forward projector, transformer projector, and `UltravoxModel` methods in a torch-only namespace. It exited 0. It checked:

- Init bounds `(24064, 3008)`, `(66000, 8272)`, and a non-default config `(5 embeds, max_source 10, stack 3) → (20, 8)`. Runtime 17 mel → `(9, 2)` even when `num_mm_embeds` is 16. Two 1-mel chunks → `(2, 2)`. Stack factor 4 and 17 mel → `(9, 3)`. A meta-device `audio_lens` raises without `.cpu()`. Missing `audio_lens` → `(0, 0)` and the connector count is not `None`.
- Pack index for mels 17 and 3000 at width 3000 has length 1509, head `0..8`, tail `1500..2999`, positive lengths `[9, 1500]`. A short batch of 17 and 31 stays width 31. One tower pass under LoRA; 17 chunks split `16+1` only when LoRA is off. Connector split lengths `[2, 188]`.
- Conv1 zero `t >= L` matches an unpadded conv for `L` in `{1, 2, 16, 17, 31, 3000}` and right pads in `[L, 3000]`. Zeroing `t > L`, zeroing conv2-time `t >= feat_len`, and no zero all fail for odd `L` when the pad is longer than `L`.
- Packed SDPA matches per-chunk SDPA on unpadded keys. An odd-length chunk batched with a longer chunk differs from today's no-zero 3000-pad forward.
- Stack tails for `feat_len` in `{1, 9, 1500}` are zero-filled (`1`, `1`, and `4` real frames). Extra frames after `feat_len` do not enter the last token.
- Encoder forward under a `Tensor.cpu` / `.numpy` monkeypatch. `max_seqlen` is the real feat length, a 0-dim CPU tensor, not the padded conv width.
- FlashInfer pad: lengths 3 and 5, hidden 16, tp 1 → scaled `[0, 48, 128]`, bucket 8, V section `* 3`, concat length 18, seq lens `[3, 5, 0, 0, 0, 0, 0, 0]`, int32. FP8 padded 32 and tp 2 uses scale 16 on both halves and does not multiply by 3. `bucket_flashinfer_max_seqlen(5) == 1024`. SDPA and FLASH_ATTN keep unscaled CPU `cu_seqlens` and `max_seqlen` 5.
- Feed-forward last token is frame 8 plus 7 zeros. Transformer positions are per chunk (`[0, 0, 1]`), not a global index. The rectangular fallback uses the time axis for `max_seqlen`, not the flattened row count.

CPU `Conv1d` is not bit-exact across input lengths. The largest correct-mask gap measured in that script was about `5.7e-6`. Positive compares use `rtol=1e-4, atol=1e-4`. Wrong odd-`L` masks differ by O(1) and still fail that tolerance. `ceil(feat_len / stack_factor)` matched `ceil(L / (2 * stack_factor))` for stack factors `{1, 2, 4, 5, 7, 8, 10, 16}` and `L` in `0..5000` (placeholder count vs packed connector rows).

## Details

`_build_chunk_attn_metadata` did `lens_np = feature_lens.cpu().numpy()` from `UltravoxWhisperEncoder.forward` and from `UltravoxTransformerProjector.forward` (`audio_token_len` lives on device). Wrapping that read in `gpu_sync_allowed()` would leave the stall in the encoder. `audio_lens` and `audio_num_chunks` are already `keep_on_cpu`. The pack index is `feat_len = (L - 1) // 2 + 1`, flat `b * T_conv + t` for `t < feat_len[b]`, with zero-length rows dropped on the host. The index, lengths, and `cu_seqlens` move with `async_tensor_h2d`. Attention is one segment per positive chunk. `max_seqlen` is a 0-dim CPU tensor so the flash wrapper `.item()` does not touch CUDA. The post-tower `.item()` / `.tolist()` on `audio_token_len` and `num_chunks` stay inside the existing `gpu_sync_allowed()` in `_process_audio_input`.

`pad_audio_to_max_context` existed so punica would see a fixed width of 3000. Punica uses `x.size(0)` on the flattened rows and has no such width. `pad_and_concat_to_dim3` already zero-pads to the batch max. Conv1 is kernel 3, stride 1; conv2 is kernel 3, stride 2, and has a bias. Even `L = 2k` has `feat_len = k`, and the last frame stays inside `[0, L)`. Odd `L = 2k + 1` has `feat_len = k + 1`, and the last frame reads one past `L`. A right pad makes `gelu(conv1)` at `t = L` nonzero, so every real query differs from an unpadded forward. Zeroing conv1 time `t >= audio_lens` before conv2 removes that tap. Host lengths are copied up for the compare; a CUDA length tensor is not sent back with `.cpu()`. Odd-`L` outputs differ from today's 3000-pad forward on purpose. Even-`L` conv outputs already matched.

The three LoRA formulas are separate. `max_tokens_per_chunk = ceil(max_source_positions / stack_factor)` is 188 for the current 1500 and 8. Both tower terms are required:

- 3008: `ceil(3008 / 188) = 16`, `max(16 * 1500, 3008 * 8) = max(24000, 24064) = 24064`, connector `16 * 188 = 3008`.
- 8192: `ceil(8192 / 188) = 44`, `max(44 * 1500, 8192 * 8) = max(66000, 65536) = 66000`, connector `44 * 188 = 8272`.

24064 is 64 above `16 * 1500` because `188 * 8 = 1504 > 1500`. That is the issue formula on the current config constants, not a new constant. Runtime counts ignore `num_mm_embeds` and sum that item's chunks: tower `sum((L - 1) // 2 + 1)`, connector `sum(ceil(feat_len / stack_factor))`. 17 mel is `(9, 2)`. `(0, 0)` rather than `(0, None)` keeps `set_active_mm_loras` from returning before a later connector map is installed. The init upper bound also leaves the #61608 punica sizing buffer at least as large. That bug is not fixed here.

FlashInfer scale and batch-bucket padding are reimplemented with tensor ops in `ultravox.py`. `mm_encoder_attention.py` is unchanged, because its numpy helpers need a host array. Batch size is `len(cu_seqlens) - 1`. `sequence_lengths` is padded with 0 to the `add_padding_to_seqlens` bucket. Each cumulative vector is padded to `bucket + 1` by repeating its last value on device. The BF16 path concatenates the Q/K section with a `* 3` V section. FP8 uses `get_fp8_padded_hidden_size(attn.num_heads * tp_size, attn.head_size) // tp_size` for both sections and does not multiply by 3. Whisper's `num_heads` is already TP-local. `get_tensor_model_parallel_world_size()` runs only on the FlashInfer path. `max_seqlen` is bucketed on the CPU integer before the 0-dim tensor is built. SDPA keeps unscaled `cu_seqlens` on the CPU; its wrapper `.tolist()` stays out of the encoder.

If a CUDA length tensor arrives, it stays on device. `max_seqlen` is the Python int `T_conv` from `inputs_embeds.shape[-2]` after the permute to `[B, T, D]`, not `flat.shape[0]`. The fallback attends full rows, and the projectors keep the rectangular path plus the existing post-tower mask trim. Packed width is the CPU index, not `hidden[mask]` / `nonzero`.

Stacking uses the existing `StackAudioFrames` zero-fill on each chunk, then the connector linears run on the packed rows. The last token stays zero-filled when `feat_len % stack_factor != 0`. Transformer projector positions are `0 .. n_tokens - 1` per chunk.
