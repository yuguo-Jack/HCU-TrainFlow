# [CI] Run pip-compile pre-commit hooks only when requirements change

[Upstream PR](https://github.com/vllm-project/vllm/pull/59526) · state: open · merged: False

## Original PR description

  ### Summary
  - **Problem:** CI runs pre-commit with `--all-files`, so the 5 `pip-compile` hooks re-resolve every lockfile against PyPI and `download.pytorch.org` on every run, even when nothing in `requirements/` changed. When those indexes return a 502/503, pre-commit fails for changes that have nothing to do with dependencies.
- **Impact:** During a burst of 502s from `files.pythonhosted.org` (Aug 15–19), 57 PR pre-commit runs failed inside these hooks. Main went red 18 times from May to Sep for the same reason (see Examples).
- **Fix:** skip `pip-compile` in the `--all-files` run, and run it separately on only the files the commit changed. The hooks' existing `files:` filters then decide whether they need to run, so they only touch the network when requirements change.
- If `.pre-commit-config.yaml` changed, they still run on all files, because a uv bump or a hook-args edit can change the lockfiles without touching `requirements/` (as in #26591).

- khluu · comment · 2026-10-01T06:15:47Z · [source](https://github.com/vllm-project/vllm/pull/59526#discussion_r4152394043)

File: `.github/workflows/pre-commit.yml` · line None

`uv pip compile` also reads `[tool.uv]` from `pyproject.toml`, and we keep `exclude-dependencies` and `no-build-isolation-package` there. I checked with uv 0.11.2: with `exclude-dependencies = ["six"]`, compiling `python-dateutil` drops `six`; without it, `six` is back. So a PR that only changes the `[tool.uv]` section would skip the check, and stale lockfiles would merge. The next PR that touches `requirements/` would then fail on a diff it didn't cause.

Rather than adding `pyproject.toml` to this `if`, I'd put `pyproject.toml` and `.pre-commit-config.yaml` into each pip-compile hook's `files:` pattern and always run with `--from-ref`/`--to-ref`. That drops the if/else, and local `pre-commit` behaves the same way.
