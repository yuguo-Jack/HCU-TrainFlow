# [Bugfix] Report the real reason when the vLLM CUTLASS FP8 MoE backend is rejected

[Upstream PR](https://github.com/vllm-project/vllm/pull/64297) · state: closed · merged: False

## Original PR description

## Overview

`select_fp8_moe_backend()` rejected an explicit `moe_backend="cutlass"` with a
reason-free error. This makes that one branch report the actual reason, matching
every sibling backend in the same function. Fixes #62135.

## Claims

- The `cutlass` / batched-cutlass rejection now names the backend and the real
  reason instead of the opaque `"vLLM CUTLASS FP8 MoE backend is disabled for
  this configuration."`.
- Behavior is unchanged: the same configurations are still rejected; only the
  error message improves.
- Consistent with the sibling backends, which already route their rejections
  through `_make_log_unsupported(backend, reason)` in the same call.

## Validation

- `ruff check` and `ruff format --check` (v0.14.0, the pinned pre-commit
  version) pass on the changed file.
- The module imports cleanly.
- No existing test asserts the old message string, so no test needed updating.

## Details

`moe_backend="cutlass"` is a legal value, but the vLLM-native CUTLASS FP8 MoE
kernels are only enabled (`allow_vllm_cutlass=True`) for per-channel weight +
per-token activation (PTPC) FP8 and compressed-tensors w8a8 FP8. For other FP8
schemes (e.g. online `fp8_per_tensor`) the branch raised a message that did not
say why. The reason is now surfaced via the existing `_make_log_unsupported`
helper.

Scope is intentionally limited to the error-message inconsistency (problems 1
and 2 in the issue). Moving this validation earlier to `create_engine_config()`
(problem 3) is a larger change left for a follow-up.
