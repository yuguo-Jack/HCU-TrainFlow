# [Build] Bump vllm-flash-attn to compress fatbins with --compress-mode=size

[Upstream PR](https://github.com/vllm-project/vllm/pull/65518) · state: open · merged: False

## Original PR description



## Overview

Bump vllm-flash-attn to d8dca8f to pick up vllm-project/flash-attention#216, which compresses FA's fatbins with `--compress-mode=size` on CUDA >= 13 as vLLM's own extensions already do. The x86_64 wheel shrinks by about 82 MB (about 25%).

## Claims

- The wheel is about 82 MB smaller (335 MB → about 253 MB for v0.33.0 x86_64), and installed size drops by about 347 MB.
- Kernel code is unchanged: every FA2/FA3 SASS kernel is byte-identical to the v0.33.0 release.
- The only other commit picked up is vllm-project/flash-attention#199 (FA4 CuteDSL: SM90 FP8 MMA forward for hdim 512). It is Python-only and doesn't change the compiled `.so` files.

## Validation

I built `_vllm_fa2_C`/`_vllm_fa3_C` from this branch's FA commit (CUDA 13.0, `TORCH_CUDA_ARCH_LIST='7.5 8.0 8.6 8.9 9.0 10.0 11.0 12.0'`) and compared against the `.so` files in the v0.33.0 x86_64 wheel on PyPI (FA b273a02, also nvcc 13.0.88):

| | installed | `.nv_fatbin` | deflated (wheel cost) |
|---|---|---|---|
| `_vllm_fa2_C` v0.33.0 | 308.0 MB | 297.2 MB | 129.6 MB |
| `_vllm_fa2_C` this PR | **77.1 MB** | 63.3 MB | **65.0 MB** |
| `_vllm_fa3_C` v0.33.0 | 172.6 MB | 133.7 MB | 42.6 MB |
| `_vllm_fa3_C` this PR | **56.9 MB** | 17.2 MB | **24.8 MB** |

- **Same kernels.** I extracted every image with `cuobjdump -xelf/-xptx` and hashed each kernel's `.text.*` section. FA2 has 2,904/2,904 SASS kernels identical to v0.33.0, and FA3 has 1,333/1,333. The 76 FA2 PTX files differ only in nvcc's per-TU `_INTERNAL_<hash>` symbol names.
- **Runtime on B300.** FA2 on B300 (sm_103) JITs from the compressed compute_80 PTX. A causal varlen call (bf16, hdim 128, GQA 32/8) matches fp32 `scaled_dot_product_attention` with a max abs error of 0.0118.
- **Startup cost.** I timed `cuModuleLoadData` on B300 for one FA2 TU compiled to sm_100 SASS (4.4 MB uncompressed). It takes 12.7 ms uncompressed and 14.6 ms with `--compress-mode=size`, so about 2 ms per TU (about 0.45 ms per MB of SASS). With lazy module loading, only the TUs whose kernels run are loaded, once per process. Loading every image for one arch would cost about 100 ms for FA2 (sm_80) and about 60 ms for FA3 (sm_90a).
- **Fetch.** `FetchContent` checks out d8dca8f from `vllm-project/flash-attention`.
- **Not run on Hopper or Ampere.** I have no such hardware, so FA3 and the FA2 sm_80 SASS path weren't run. Coverage there rests on the identical-SASS check above, plus CI.

## Details

- `VLLM_FA_GPU_FLAGS` doesn't inherit `VLLM_GPU_FLAGS`, so FA never got the `--compress-mode=size` that `CMakeLists.txt` sets for vLLM's own targets. By default `fatbinary` compresses only PTX and debug images, which left all FA SASS stored raw.
- `-Xfatbin=-compress-all` (FlashInfer's approach) adds nothing on top of `--compress-mode=size` and gives larger output when used alone. Details are in the FA PR.
- **#199 compatibility.** It adds new FA4 SM90 `fp8_kv_dequant` guards (for example, it now requires head_dim 512). vLLM already restricts SM90 FA4 FP8-KV to head size 512 (`fa_utils.py` `flash_attn_supports_fp8`), so no supported vLLM path changes.
- **Duplicate check.** #65203 also moves the FA pin, but it's a do-not-merge upstream sync. No other open PR bumps the FA pin.
