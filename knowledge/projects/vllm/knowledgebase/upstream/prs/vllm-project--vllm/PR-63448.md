# [Bugfix][Frontend] Set completed_at on completed Responses

[Upstream PR](https://github.com/vllm-project/vllm/pull/63448) · state: open · merged: False

## Original PR description

## Overview

`/v1/responses` omits `completed_at` even when `status` is `completed`, so OpenAI SDK clients always read `None`. Set the field from `ResponsesResponse.from_request`. Fixes #63183.

This does not duplicate an open PR.
[PR #63234](https://github.com/vllm-project/vllm/pull/63234) attempted the
same fix and was closed without merge.

AI assistance was used. The human submitter reviewed and understood every
changed line.

## Claims

- A completed Responses object includes `completed_at` as Unix seconds, and that value is greater than or equal to `created_at`.
- `queued`, `in_progress`, `incomplete`, `failed`, and `cancelled` responses include `completed_at: null`.
- Non-streaming responses, the final streaming event, and a stored background response all go through `from_request`, so they pick up the same field.

## Validation

Before the fix, on `main`'s `protocol.py`:

```bash
.venv/bin/python -m pytest \
  tests/entrypoints/openai/responses/test_serving_responses.py \
  -q -p no:cacheprovider -k test_completed_at_only_set_when_completed
```

6 failed. Each failure is `assert 'completed_at' in response`.

After the fix, the same command: 6 passed.

`tests/entrypoints/openai/responses/test_basic.py` asserts the field on the real OpenAI client for both unary and streaming responses. That test needs a model server and was not run on this CPU-only machine. CI's `entrypoints/openai/responses` step already collects that file.

All pre-commit hooks applicable to the four changed files passed, including
ruff, markdownlint, test tethering, mypy, and SPDX checks.

Spec: OpenAPI `components/schemas/Response.completed_at` (openai-openapi `master`, 2026-10-24) is a unixtime or null, "only present when the status is `completed`". `openai==2.44.0` `Response.completed_at` is `Optional[float]`.

## Details

Root cause: `ResponsesResponse` never declared `completed_at`, so response
serialization could not emit it. `from_request` is the shared constructor used
by the final object, the in-progress streaming snapshot, and the background
store update.

`completed_at` uses `int(time.time())` at construction, matching `created_at`. It is not copied from `created_at`, because generation can finish later. Cancelling a queued response only mutates `status`; that object was built with a non-completed status, so `completed_at` stays null.

No new sampling behavior and no benchmark.
