# [KV Connector] Add checkpoint_prepare and checkpoint_restore connector hooks

[Upstream PR](https://github.com/vllm-project/vllm/pull/64370) · state: closed · merged: False

## Original PR description



## Overview

Adds `checkpoint_prepare()` and `checkpoint_restore()` to `KVConnectorBase_V1` and `ECConnectorBase`, and calls them from the process checkpoint lifecycle added in #62570. Connectors can then release what a process checkpoint must not contain, such as transports and peer state, and rebuild it on restore. The NIXL implementation follows in #64371.

## Claims

- KV and EC connectors get two hooks that do nothing by default. `MultiConnector` forwards them.
- Preparing calls them once the engine has drained and released its KV cache: first the scheduler-side instance, then every worker-side instance, before the device communicators. Restoring calls them in reverse, before the KV cache wakes.
- Connectors that don't override the hooks behave as before.

`test_checkpoint_prepare_then_restore_run_in_order` now checks where the scheduler-side connectors run relative to the worker hooks and the KV cache wake-up.

## Details

- The scheduler side stops before the workers release what it uses, and restarts after they rebuild it. Workers create connectors after the communicators, so connectors release first and rebuild last.
- Relation to #56852 (#55155): that PR adds four worker-side KV hooks (`quiesce`, `release_for_checkpoint`, `reinitialize`, `verify`) for an external coordinator to call. Since #62570 the engine drives the checkpoint lifecycle itself: it drains before preparing, and failures move the checkpoint state to FAILED. This PR wires two hooks into that lifecycle on both the scheduler and worker sides and also covers EC connectors.
