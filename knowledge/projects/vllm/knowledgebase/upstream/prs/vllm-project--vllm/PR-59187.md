# [Bugfix][Core] Keep KV offload lookup worker alive on iterator errors

[Upstream PR](https://github.com/vllm-project/vllm/pull/59187) · state: closed · merged: False

## Original PR description

## Purpose

If a secondary tier's `batch_lookup()` returns an iterable that raises during iteration, `AsyncLookupManager._worker()` currently exits: only the call to `batch_lookup()` is inside the exception handler. The current batch is never published, and subsequent queued lookups have no worker to resolve them.

Consume the iterable inside the existing exception boundary. An iteration failure then follows the existing all-misses fallback for that request group, and the worker continues processing other groups and future batches.

## Test Plan

The regression injects failures both before the first result and after yielding a hit. It verifies misses for the failed group, a successful group in the same batch, and progress on a later batch.

- Fixed async-lookup, filesystem-tier, object-tier, and tiering-manager suites: **158 passed**.
- All applicable manual pre-commit hooks passed, including mypy for Python 3.10–3.13.
- Filesystem coverage includes real disk I/O on Python and native paths; object-tier coverage uses the existing mocked backend. The native filesystem extension was rebuilt from tested base `6ebb5bd64f5ef75dbe1471ee88c009003b3d03ec`. No model-generation benchmark was run.

## Duplicate-work check

Searched open PRs for `AsyncLookupManager`, `batch_lookup exception`, and `lookup iterator`. The related #57474 publishes results per request group, but its current patch still consumes the iterator outside the exception handler; it does not fix this failure. #59096 concerns `mark_miss()` racing an in-flight probe. This change preserves the current publication granularity and lookup-state transitions.
