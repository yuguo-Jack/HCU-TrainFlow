# [Bugfix][Pooling] Validate truncated Jina ranking prompts

[Upstream PR](https://github.com/vllm-project/vllm/pull/55200) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Reject Jina ranking inputs when truncation removes the markers needed to match embeddings to the query and original documents. Cover `/score`, `/rerank`, `/pooling`, and `LLM.encode` through the shared Jina processor.

## Claims

- Reject marker loss before engine dispatch, including direct token-embedding requests.
- Keep untruncated inputs and marker-preserving truncation working on both truncation sides.

## Validation

The focused ranking, embedding, request-factory, and late-chunking suites pass, along with scoped pre-commit hooks. The new regression reproduces the `/pooling` and `LLM.encode` bypass before the fix; valid-input controls pass.

To run the related suites in a configured development environment:

```sh
.venv/bin/python -m pytest tests/entrypoints/pooling
```

Fresh jina-reranker-v3 GPU smoke checks pass with BF16 and MRV2 on an RTX 5070 Ti. `LLM.encode` returns the expected document/query vectors for valid inputs and rejects marker loss. `/pooling`, `/score`, and `/rerank` accept marker-preserving truncation and return HTTP 400 with `param="truncate_prompt_tokens"` when markers are lost, on both truncation sides.

The smoke checks reused precompiled native extensions and disabled FlashInfer autotuning. The local environment uses Torch 2.13 rather than this branch's 2.14 pin. Full model evaluation and upstream GPU CI were not run on this head. Upstream checks are stopped at contributor authorization.

## Details

Left truncation can remove a document marker and shift score indices; right truncation can remove the query marker and treat a document embedding as the query. The existing guard only covered scoring. Move it into the Jina mixin shared with the token-embedding processor, checking rendered token IDs after sanitization and truncation. Callers can shorten their inputs or raise the truncation limit.

No competing Jina truncation fix was found in the overlap review.
