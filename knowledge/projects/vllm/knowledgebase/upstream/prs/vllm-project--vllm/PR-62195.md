# [Bugfix][kv-events] Making partial blocks emit all tail hashes

[Upstream PR](https://github.com/vllm-project/vllm/pull/62195) · state: open · merged: False

## Original PR description



## Overview

Issue: partial full-attention cache events can reference a parent hash that was never published, as described in https://github.com/vllm-project/vllm/issues/58119. 

Solution: have BlockStored contain all completed tail hashes of a partial full-attention block.

## Claims



We fix https://github.com/vllm-project/vllm/issues/58119, which is particularly important for llm-d's precise KV cache report mode, in models which use `prefix_match_unit`, such as kimi-k3.

## Validation



We add the following tests:

- `test_full_attention_tail_events_preserve_local_lookup`:  exercises cache manager with partial-prefix hits enabled. Verifies the core logic works and we emit all the hashes for all tail hashes.

- `test_dense_partial_event_splits_multimodal_extra_keys`: check the main logic with image data (accounted for in `extra-keys`)

-  `test_reported_partial_hashes_follow_block_lifecycle`: checks eviction, movement, promotion to full block, replacement, and cache reset.

We add some checks on:

- ` test_cache_partial_block_kv_cache_events`: now also runs with `report_all_hash_boundaries=True`.


## Details



The main motivation is to ensure consumers of `kv-events` can reconstruct KV cache chains. Previously, a partial block would emit an event stating a parent block that was never emitted. This is particularly consequential for precise KV cache routing on llm-d, as it relies on ZMQ kv-events to understand which pods have which KV blocks.

Hence, the main design decision is to go from this:

```
BlockStored(
      block_hashes=[H14],
      parent_block_hash=H12,
      token_ids=[12, 13],
      block_size=2,
      extra_keys=[
          (("B", -1),),
      ],
      group_idx=0,
      # Unrelated fields omitted.
  )
```

to 

```
BlockStored(
      block_hashes=[H10, H12, H14],
      parent_block_hash=H8,
      token_ids=[8, 9, 10, 11, 12, 13],
      block_size=2,
      extra_keys=[
          (("A", -2),),             # [8, 10)
          (("A", -4), ("B", 1)),    # [10, 12)
          (("B", -1),),             # [12, 14)
      ],
      group_idx=0,
      # Unrelated fields omitted.
  )
```

We introduce the `report_all_hash_boundaries` arg on `cache_partial_block`.

Therefore, with the latter, the consumer of `kv-events` can know the parent of `H14` (H12). Before, we'd just receive `H14`, and `H12` was never announced. Consequently, `H14` had a missing parent.

Most importantly, this does not impact the hashes registered for local lookup, only the hashes published in `kv-events` through ZMQ. Thus, there's no effect in how cache hits are computed.

Thanks @andylolu2 for helping on iterating on the solution.

So I added this condition as the final tail hash is already tracked by the cache index. But we need extra reporting for the additional tail hashes. Basically, if we didn't have the if, the only consequence would be `self.reported_block_hashes_by_block` dict having an entry with an an empty set as value when `len(block_hashes) == 1`. 
Basically, `self.reported_block_hashes_by_block` does the accouting for all the intermediate tail hashes of a partial block, so we can emit evict events for them later.

For `mamba` events my reasoning is that flushing those intermediate tail hashes could be misleading. I agree that, for both full attention and mamba, the cache lookup stays the same (the additional intermediate hashes reported for the partial block are not registered for prefix lookup). Either way, if you believe `mamba` events should get the same treatment, happy to remove the flag.

Exactly, I did it this way to 'solve' the routing issue without changing the current lookup behaviour. I felt it would be slightly tricky to align with `mamba` events in the edge case where we the final hash block was evicted, and we lost the `mamba` checkpoint, but are left with a non-tail KV block. 

Added the following comment block in `block_pool.py` before `if len(block_hashes) > 1`:

```
  # Intermediate hashes provide ancestry for KV-event consumers.
  # They are not registered as lookup aliases for this block, even when
  # the corresponding KV is present. Only the final hash is registered
  # for prefix lookup.
```
