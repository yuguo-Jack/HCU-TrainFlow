# [CI/Build] Mirror release and nightly images to the vllm/vllm, vllm/vllm-rocm and vllm/vllm-xpu DockerHub aliases

[Upstream PR](https://github.com/vllm-project/vllm/pull/65107) · state: open · merged: False

## Overview

Publish release and nightly images under the short `vllm/vllm` name, and release ROCm/XPU images under `vllm/vllm-rocm` and `vllm/vllm-xpu`, alongside the existing `vllm/vllm-openai*` repos. Each alias has the same digest as its source tag.

## Claims

- **Release** (`publish-release-images.sh`):

  | Source | Also published as |
  |---|---|
  | `vllm/vllm-openai:{latest,vX}` | `vllm/vllm:{latest,vX}` |
  | `vllm/vllm-openai:{latest,vX}-efa` | `vllm/vllm:{latest,vX}-efa` |
  | `vllm/vllm-openai-rocm:{latest,vX}` | `vllm/vllm:{latest,vX}-rocm` |
  | `vllm/vllm-openai-rocm:{latest,vX}-<variant>` | `vllm/vllm:{latest,vX}-<variant>` (e.g. `-rocm100`) |
  | `vllm/vllm-openai-cpu:{latest,vX}` | `vllm/vllm:{latest,vX}-cpu` |
  | `vllm/vllm-openai-xpu:{latest,vX}` | `vllm/vllm:{latest,vX}-xpu` |
  | `vllm/vllm-openai-rocm:*` (all release tags, incl. `-base`) | `vllm/vllm-rocm:*` |
  | `vllm/vllm-openai-xpu:*` (all release tags, incl. `-x86_64`) | `vllm/vllm-xpu:*` |

- **Nightly** (`push-nightly-builds{,-cpu}.sh`, `xpu/push-nightly-builds-xpu.sh`, `rocm/publish.sh`): the mutable tag is also published as `vllm/vllm:nightly`, `nightly-cu134`, `nightly-cpu`, `nightly-xpu`, `nightly-rocm` and `nightly-<variant>` (e.g. `nightly-rocm100`).
- **Docs:** `docs/deployment/docker.md` gets a "Short image names" section with this mapping.

## Validation

- v0.33.0 was aliased by hand with this mapping (`crane copy`). Every alias digest matches its source, e.g. `vllm/vllm:v0.33.0` = `vllm/vllm-openai:v0.33.0` = `sha256:d825baf9ce4b…`, `vllm/vllm-rocm:v0.33.0` = `vllm/vllm-openai-rocm:v0.33.0` = `sha256:4fcd39b758b6…` (16/16 `vllm/vllm-rocm` + `vllm/vllm-xpu` tags match).
- Digest behaviour of `docker buildx imagetools create`, tested against a local `registry:2`:

  | Source | Copy keeps the digest? |
  |---|---|
  | OCI index / Docker `manifest.list.v2` (1 or 2 entries, as `docker manifest create` makes) | yes |
  | Single-arch manifest (by tag or by digest) | **no**: wrapped in a new 1-entry list |
  | One `create` call with `-t` in several repos | yes: all tags get one digest |

- Dry run of every target (`publish-release-images.sh rocm|xpu`, the four nightly scripts, `rocm/publish.sh rocm images` with `NIGHTLY=1`, `NIGHTLY=0` and `ALIAS_HUB=`) with `docker`/`aws`/`buildkite-agent` stubbed: prints exactly the tags above, and nothing under `vllm/vllm` for `NIGHTLY=0` or `ALIAS_HUB=`.
- `bash -n`, shellcheck and pre-commit pass (no new shellcheck findings).
- Not exercised in CI: these scripts only run in the release pipeline. The first nightly after merge and the v0.34.0 release are the first real runs. `vllmbot` can already push to `vllm/vllm-rocm` and `vllm/vllm-xpu` (used for the v0.33.0 copies).

## Details

- **ROCm images are single-arch**, so copying a published ROCm tag with `imagetools create` would wrap it and change its digest. The ROCm aliases (`vllm/vllm:*-rocm*`, `vllm/vllm-rocm:*`) are therefore extra `-t` flags on the `create` call that writes the canonical tags. CUDA, EFA, CPU and XPU copy a manifest list, which keeps the digest. XPU pushes the same image and list to both repos in a loop.
- **Nightly aliases are mutable tags only.** Every `vllm/vllm` nightly family shares the `nightly-` prefix, so `cleanup-nightly-builds.sh` could not prune commit tags per family, and it would delete the mutable `nightly-<suffix>` tags as well. Commit-pinned, per-arch and `base-nightly` tags stay in the canonical repos, so `vllm/vllm` needs no cleanup.
- `rocm/publish.sh` takes `ALIAS_HUB` (default `vllm/vllm`, empty to skip), like the existing `HUB` override.
- Not covered: `-rocm72` release tags (not published by this script), the EFA nightly (pending in #64028), and nightlies in `vllm/vllm-rocm` / `vllm/vllm-xpu`.
- Not a duplicate: no other open PR touches these scripts for aliasing (`gh pr list --search "publish-release-images in:files"`; #64028 only adds the EFA nightly).
