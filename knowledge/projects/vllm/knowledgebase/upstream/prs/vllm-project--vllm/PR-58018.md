# [Bugfix][Frontend] Fix Responses item status and Harmony event lifecycle

[Upstream PR](https://github.com/vllm-project/vllm/pull/58018) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fixes #57998 and the existing zero-delta Harmony streaming lifecycle failure. Truncated non-Harmony Responses output items report `incomplete`; Harmony messages with no deltas receive their missing item lifecycle events.

## Claims

- Mark only the final non-Harmony output item incomplete on token-limit truncation, preserving completed earlier items across parser, fallback, multi-turn, and streaming paths.
- Initialize zero-delta Harmony items through the existing event builders before emitting done events, with distinct IDs and consistent indices.
- Preserve the upstream streamed-item reuse behavior from #59307 and #59859 after rebasing onto `194da61de1`: final responses retain streamed status, IDs, call IDs, and logprobs.

## Details

Non-Harmony output builders previously hardcoded completed item status. The final item now follows token-limit truncation, including streaming completion with an empty terminal chunk. Zero-delta Harmony messages previously skipped their added/in-progress events and consequently their done events; the existing builders now initialize that lifecycle.

The rebase conflict was in `SimpleStreamingEventProcessor.close_current()`: this PR updates item status, while upstream collects completed streaming items for the final response. Both operations are retained, updating status before collecting the items. The upstream Harmony test now expects the lifecycle restored by this PR and checks that both messages retain their own IDs.

Duplicate checks were refreshed against #57998 and Responses/Harmony lifecycle keywords. #59324, opened after this PR, overlaps the item-status fix and explicitly identifies this PR's Harmony zero-delta lifecycle fix as independent. #45386 concerns the terminal response event type; #54236 concerns empty-argument events in the simple streaming path. This update resolves conflicts in the existing PR.
