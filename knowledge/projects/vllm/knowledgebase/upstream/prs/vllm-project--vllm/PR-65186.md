# [Perf][GDN] Export Triton prefill checkpoints into the paged state cache

[Upstream PR](https://github.com/vllm-project/vllm/pull/65186) · state: open · merged: False

## Original PR description



## Overview

Export Qwen GDN prefill checkpoints directly from the Triton/FLA chunk recurrence
into the paged state cache. In Mamba `align` mode, this avoids stopping a prefill
at its last cache boundary and avoids rerunning its tail.

## Claims

- Triton/FLA prefill reads initial state and writes final state in the paged
  cache, removing per-layer gather/scatter and masked state initialization.
- The recurrence stores the checkpoint at a 64-token chunk boundary; the shared
  Mamba exporter supplies its convolution window. Autotune replays preserve the
  input cache rows, and warmup covers representative sequence-count buckets.
- Full GSM8K A/B and prefix-hit continuation checks cover standard decoding,
  MTP, and checkpoint reuse. Scores and performance tradeoffs are below.

## Validation

Baseline `7fc467825d`, 2x NVIDIA H20-3e, Qwen3.8-Flash-Next-FP8, TP2,
Triton/FLA, prefix caching enabled, block size 1600, 8192-token step budget.
PyTorch 2.14.0+cu132, Triton 3.8.0, driver 580.105.08; both source checkouts
share precompiled extension artifacts from `7b1d07440d`.

Standard decoding and MTP have one matched run each. In the two cached runs,

`check_logprobs_close` comparison. Full-model FP8 outputs are not bitwise equal:
an unchanged-upstream control also changes greedy tokens when primer batching
changes. Kernel and exported-state tests retain exact assertions.

The metadata-view regression fails on the preceding implementation because an

in either serving benchmark pass.

available locally; the existing FLA CI step and the H200/MI355 large-memory e2e
steps select the new tests.

### Serving performance

Two interleaved passes on the same allocated pair of H20s, 8000 input / 128
output tokens, 16/32/128 requests at concurrency 1/4/16, no prefix hits. Fresh
server and warmup per arm/pass; block size explicitly fixed to 1600 in both.

| Concurrency | Mean TTFT ms, baseline → PR | TTFT change | Mean TPOT ms, baseline → PR | Output tok/s change |
| --- | ---: | ---: | ---: | ---: |
| 1 | 708.6 → 672.6 | -5.1% | 6.29 → 6.24 | +3.0% |
| 4 | 1955.2 → 1620.4 | -17.1% | 13.29 → 15.23 | +2.5% |
| 16 | 3882.8 → 3375.2 | -13.1% | 61.84 → 65.22 | +0.7% |

TPOT increases by 14.6% at concurrency 4 and 5.5% at 16 on this short-output
workload, despite lower TTFT and slightly higher throughput. This is a latency
tradeoff, not a decode-kernel speedup. At concurrency 16, the two run means are
3852.6/3912.9 ms for baseline and 3375.9/3374.5 ms for the PR. Every request
completed successfully.

## Details

- **Overlap:** #60659 implements the same Triton checkpoint goal using host-side
  row splitting and a second chunk pipeline over the tails, and also covers
  AITER FlyDSL. This is a materially different kernel implementation: direct
  paged-state I/O plus a checkpoint store, with no tail rerun. FlyDSL is outside
  this change. The implementation difference is documented in
  [the existing discussion](https://github.com/vllm-project/vllm/pull/60659#issuecomment-6581991861).
  #64498/#64625 concern FlashInfer state-pool access instead.
- **Reuse:** uses the checkpoint declaration/grid and shared exporter introduced
  for FlashInfer in #60050; generic scheduler/cache-manager interfaces stay as
  they are. Preserves current upstream int64 indexing and FlashInfer output I/O.
- **Tradeoffs:** internal checkpoints reserve one checkpoint block and can reduce
  effective KV capacity. The 64-token grid must be supported by every Mamba
  layer in the model. CUDA and ROCm use this path; XPU retains gather/scatter.
- **Configuration:** `additional_config["gdn_prefill_checkpoint"]` defaults to
  true; false restores split prefill while retaining direct Triton state I/O.
  Usage and the default are documented in Automatic Prefix Caching.
- AI assistance: Claude Code implemented the initial kernel/integration and
  experiments; Codex consolidated the changes, updated upstream compatibility,
  documented the behavior, and ran the validation above.
