# [Bugfix][Distributed] Fix PP rank derivation when prefill context parallelism is enabled

[Upstream PR](https://github.com/vllm-project/vllm/pull/65539) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fix PP rank calculation when pipeline parallelism (PP) and prefill context parallelism (PCP) are enabled together. The current calculation ignores the PCP dimension, causing incorrect MooncakeStoreConnector keys, model layer metadata, and Ray actor names.

Workers follow a PP × PCP × TP layout, so each PP stage contains `tp_size * pcp_size` workers. This PR replaces `rank // tp_size % pp_size` with `rank // (tp_size * pcp_size) % pp_size` in all three affected locations.

It also rejects negative layer counts in `VLLM_PP_LAYER_PARTITION`, such as `"-1,5"`, instead of allowing invalid layer ranges.

## Claims

- MooncakeStoreConnector uses the correct PP stage in store keys, restoring external prefix cache hits in the tested PP2 × PCP2 configuration.
- `ModelConfig.get_layers_start_end_indices` returns the correct stage's layer range, including the layer count used by KV connectors and EAGLE drafters for uneven partitions.
- Ray actor names report the correct PP and PCP indices.
- Negative custom layer counts fail validation at startup. PP rank calculation is unchanged when PCP = 1.

## Validation

- Connector: `MooncakeStoreConnector`, `kv_both`, standalone store, asynchronous loading.
- Workload: GSM8K 5-shot, run twice against the same server so the second pass can reuse stored prompt KV. Local prefix caching is disabled.

## Details

At PP2 × PCP2 × TP1, ranks 0–3 belong to PP stages `[0, 0, 1, 1]`, but the old formula returns `[0, 1, 0, 1]`. In MooncakeStoreConnector, this makes the computed PP rank equal the PCP rank: only `(PP, PCP)` key combinations `(0, 0)` and `(1, 1)` are written. Each stage's lookup requires all PCP shards, but `(0, 1)` and `(1, 0)` are missing, preventing cache hits.

Model layer construction already uses the PP process group through `make_layers`. The model-config fix aligns the reported layer ranges and counts with that existing assignment.
