# [Perf][GLM-5.3-Flash] Produce dense QKV directly in prefill convolution

[Upstream PR](https://github.com/vllm-project/vllm/pull/61614) · state: open · merged: False

## Original PR description



## Overview


GLM-5.3-Flash prefill convolution produces strided Q/K/V slices that FlashKDA copies into three contiguous buffers. Produce dense `[3, tokens, projection_dim]` output directly in the existing convolution to eliminate those copies.

## Claims



- Automatically enable the producer for pure-prefill SM90/BF16/D128 FlashKDA, preserving convolution arithmetic, cache updates and raw projections used for checkpoint export.
- Full-model profiles on all four H200 ranks show **4 → 1 copy kernels per FlashKDA prefill**. The three Q/K/V copies are eliminated; the native beta transpose remains.
- Same-GPU serial A/B, ISL2048/OSL1, RPS=inf, Rust benchmark client: **2.83% higher median throughput**, from **21.130 to 21.728 requests/s**, across three runs per arm.

## Details

The existing convolution writes Q/K/V directly into dense token-major regions. This removes activation packing through the producer's output stores rather than adding a separate packing kernel or merging convolution parameters.

The shared convolution API retains its legacy output layout by default. GLM selects grouped stores only for the eligible pure-prefill FlashKDA path; mixed/speculative steps and other backends retain the existing route. Raw pre-convolution projections remain available for checkpoint export.
