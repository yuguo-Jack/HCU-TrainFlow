# [Spec Decode] Support AdaFlash length heads with DFlash adaptive verification

[Upstream PR](https://github.com/vllm-project/vllm/pull/63532) · state: open · merged: False

## Original PR description

## Overview

Support the released [AdaFlash Qwen3-8B](https://huggingface.co/AdaFlash/Qwen3-8B-AdaFlash) length head in DFlash adaptive verification. Reference: [SGLang #34171](https://github.com/sgl-project/sglang/pull/34171).

## Claims

- Load the checkpoint directly and use its predicted lengths with the existing adaptive verification backend.
- Keep the integration to seven files; preserve fixed-length DFlash and existing confidence-based policies.

## Validation

On H800: **33 manager tests and 2 real-checkpoint generation tests passed**, along with all pre-commit checks. The head matches the training implementation, and the adaptive E2E test checks that target verification actually uses shortened blocks.

Offline generation throughput, output tokens/s (**mean ± SD, 3 runs**). Single GPU, Qwen3-8B, BF16, concurrency 64, 256 requests per dataset. AR disables speculation; fixed and AdaFlash use the same drafter.

## Details

Enable with `method="dflash"`, `num_speculative_tokens=15` and `enable_adaptive_verification=true`. The head selects a draft prefix and reuses existing compaction, attention, KV handling and rejection sampling.

The CPU currently waits for predicted lengths before selecting the verification shape. This synchronization tradeoff needs review against MRV2's async design. Validation covers Qwen3-8B, TP1, BF16 text generation.

AI assistance was used. An open-PR search found no other AdaFlash implementation.
