# [Bugfix][Core] Check multimodal chunk boundaries before encoder cache reuse

[Upstream PR](https://github.com/vllm-project/vllm/pull/59721) · state: closed · merged: True

## Original PR description



## Overview

Apply the existing `disable_chunked_mm_input` boundary guard before warm encoder-cache hits and same-step image deduplication can bypass it. Related to #52306; this addresses a separate cache-hit failure from #52412's equality-boundary fix.

## Claims

- Cached and same-step duplicate images obey the same existing no-chunking guard as uncached images.
- Preserve encoder reuse without changing the guard predicate, EAGLE shift arithmetic, configuration, or public API.
- Add regressions to the existing CPU scheduler suite. No performance improvement is claimed.

## Details

Both cache fast paths previously returned before the boundary guard. Reusing encoder embeddings does not supply decoder K/V for the image under a different text prefix, so cache state must not bypass the decoder-span policy. The fix relocates the existing guard intact; the shared scheduler path serves both model runners.

Tradeoff: a cached image can now wait for sufficient decoder-token budget. Deferred items are not prematurely pinned; an invalid cached embedding-count mismatch may be reported when the item is admitted instead.

Duplicate checks on 2026-10-02 covered #52306 and its comments, #52412's patch/discussion, and open/merged PRs for the flag and cache/chunking keywords. No existing guard-order fix was found. #52412 changes `<` to `<=`; this PR preserves `<`, and that equality-only change still permits the cache-hit bypass. #59330 changes the P/D prompt-end bound, not these fast paths.

Limits: equality-boundary and prefix-cache mid-item behavior are unchanged. Existing EAGLE rollback arithmetic can still split an adjacent image (for example `[100,300)`, `[300,500)`, shift 1, budget 400 rolls back to 299). This PR does not fix that; GPU validation did not enable EAGLE. HTTP load, production-duration workloads, other attention backends, and quantization were not validated.
