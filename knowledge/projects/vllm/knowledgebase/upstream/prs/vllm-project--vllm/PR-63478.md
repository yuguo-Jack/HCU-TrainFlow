# [Spec Decode] draft_lm_head_quantization: quantize a drafter's own lm_head

[Upstream PR](https://github.com/vllm-project/vllm/pull/63478) · state: closed · merged: False

## Original PR description

## Purpose

`draft_lm_head_quantization` only applies when the drafter shares the target's `lm_head`. A drafter that ships its own head (e.g. `Inferact/MiniMax-M3-EAGLE3-GQA`, whose head differs from the target's) is rejected with a `ValueError`, so its bf16 head is read in full on every draft step.

This PR quantizes the drafter's own head instead in that case, with the same online methods (`fp8`: per-row weight / per-token activation scales; `nvfp4`: weight-only W4A16). The shared-head path is unchanged; the head selection moves into `resolve_draft_lm_head` so it can be tested directly.

As with the shared case, the bf16 source head stays resident as the source for `refresh_quantized_lm_heads` / draft weight updates, so the copy adds memory (307 MB per rank for MiniMax-M3 at TP4) rather than saving it.

## E2E (MI355X, MiniMax-M3-MXFP4, TP4, EAGLE3-GQA K=3, `draft_lm_head_quantization: fp8`)
