# [Doc][KV Offload] Document KV cache layout support for OffloadingConnector

[Upstream PR](https://github.com/vllm-project/vllm/pull/65239) · state: open · merged: False

## Original PR description



## Overview

Adds a "KV Cache Layouts" section to `docs/features/kv_offloading_usage.md`: how the layout is chosen, a support table for the six `KVCacheLayout` values across CPU, Tiered direct and Tiered canonical, and the same by model family. Each cell names the test on main that covers it, or says "not verified".

Part of #63718 (Documentation item).

## Claims

- Docs only; no code or default changes.
- Every "supported" cell names a test on main. Cells without one say "not verified", or link the open issue that tracks a known failure.
- The known gaps are in one place: `LHBNC` returns wrong output after a reload when the extensible KV cache is off (#60004), Tiered direct does not record the layout in its storage namespace (#55904), and Mamba with block-outer layouts is unverified.

## Validation

`markdownlint-cli2` v0.24.0 with `tools/pre_commit/.markdownlint.yaml`: 0 issues. The pre-commit hook passes on macOS too, main `28dd9c36b5`.

Each cell was checked against main `76c6f3f2` (11-02):

- Layout choice: `OffloadingConnector.get_required_kvcache_layout()` (`LBHNC`, or `BLHNC` with HiSparse) and `resolve_kv_cache_layout()` (an explicit `VLLM_KV_CACHE_LAYOUT` must be one the attention backend supports; the connector's request is dropped with a warning when the backend can't use it).
- Extensible KV cache (#56492, merged 11-01): with it on and any KV connector configured, `resolve_kv_cache_layout()` keeps only block-compact layouts (`KVCacheLayout.is_block_compact`: `L` and `B` outermost), so `VLLM_KV_CACHE_LAYOUT=LHBNC` or `BHLNC` fails at startup. It is on by default on CUDA and ROCm with the V2 model runner (`VllmConfig._resolve_extensible_kv_cache()`). `tests/v1/engine/test_engine_args.py::test_extensible_kv_cache_connector_needs_block_compact_layout` covers `LHBNC`; `BHLNC` follows from the same check and has no test.
- "Supported": the named test runs that combination, end to end where marked GPU, as a unit test otherwise.
- "Not supported": the existing Canonical Layout limitations (packed and cross-layer layouts), or a fail-closed case in `test_canonical_mapping.py::test_fail_closed_cases`.

I did not build the site with mkdocs locally.

## Details

**What does not change.** Code, defaults, and the existing Canonical Layout section. The new section sits between Canonical Layout and Info Metric Labels. The open PRs that touch this file (#63747, #49048, #63686, #55907) edit other parts of it.

**Not in this PR.**

- The connector check that rejects `LHBNC` without the extensible KV cache too (#60005). When it lands, that row changes to "rejected at startup", and I'll update it in the same PR or right after.
- The Naming and Testing items of #63718, which others have taken.
- Enabling `LHBNC`, which needs a GPU check.

Not a duplicate: no open PR adds layout support docs for OffloadingConnector (searched `kv_offloading_usage`, `KVCacheLayout offloading` on 11-02).
