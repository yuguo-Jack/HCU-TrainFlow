# [Perf][Kernel] Size cooperative_topk's single pass by row length, not stride

[Upstream PR](https://github.com/vllm-project/vllm/pull/62171) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

`cooperative_topk` now chooses between its single-pass and two-pass paths from each row's length instead of the
logits row stride. Rows that fit the single-pass staging no longer stream through TMA twice just because the
buffer is wide (`max_model_len`).

## Claims

- On B300, the decode top-k for rows that fit the single-pass staging is up to 8% faster when the logits stride is
  larger than the per-block staging, for example `max_model_len` 1M at 1-8 rows, or about 200K at 9-64 rows.
- Selection is unchanged: both paths compute the same exact radix top-k.
- On InferenceX AgentX, GLM-5.3 vs SGLang: together with #62170 and #62172, decode time on the same turns drops 2.0-2.9% on 4x GB200 (2.5-4.1% on 4x B300) at concurrency 1-16; by the forward benchmark this PR is about half of that.

## Details

The DSA indexer allocates its decode logits with `max_model_len` columns, and `cooperative_topk` gets that as
`stride`. The kernel sized `per_block` (elements per CTA of the cluster) from the stride. But `large_topk` splits
the row by its actual length (`seq_len`, in 16-byte units across the cluster ranks). With a long `max_model_len`,
every row took the two-pass streaming path even when its context fit the all-stages-resident single pass. For
example, 16 rows use 4-CTA clusters, and a 256K stride gives 64K elements per block, above the 48K single-pass
staging, while a 40K-token row needs only 10K per block.

`per_block` is now `ceil(seq_len / CS)`, so each row picks its path from its own length. `large_topk` rounds each
block to 16-byte units, but the single-pass limit and the stage size are multiples of that unit, so this gives the
same path and stage count as the exact split. Rows in one launch can take different paths. Each row is its own
cluster, and the barrier setup already follows the chosen path.
