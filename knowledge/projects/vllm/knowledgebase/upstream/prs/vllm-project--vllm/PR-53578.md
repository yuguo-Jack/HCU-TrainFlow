# [Bugfix][ROCm][Disagg] Always run DP dummy on zero-token ranks (no stale sticky skip)

[Upstream PR](https://github.com/vllm-project/vllm/pull/53578) · state: open · merged: False

## Original PR description

## Purpose

With `data_parallel_size > 1` and expert parallel enabled, only some DP ranks may hold tokens on a given engine step while others schedule zero tokens. Idle ranks must still run a dummy forward so per-layer EP collectives stay in lockstep; otherwise the busy rank deadlocks in all2all.

Today `execute_model` only runs that dummy when `distributed_executor_backend == "external_launcher"`. Multiproc / MoRIIO WideEP disagg uses a different backend, so zero-token ranks skip the dummy and hang.

Headless / idle ranks may only enter via `Worker.execute_dummy_batch`. That path must also always `_dummy_run(1)` for `dp_size > 1`. Do **not** skip via a sticky latch set by `execute_model`: under dp_lockstep the latch can remain `True` across later engine steps when `execute_dummy_batch` was not paired with the call that set it. Skipping a needed dummy desyncs EP ranks (GLM-5.2 tip WideEP mid-gsm8k hang). Same-step double dummy is safe; a skipped dummy is not.

## Changes

* `vllm/v1/worker/gpu_model_runner.py` (`execute_model`):
  * On zero-token steps, run `_dummy_run(1)` whenever `data_parallel_size > 1` (not only `external_launcher`).
* `vllm/v1/worker/gpu_worker.py` (`execute_dummy_batch`):
  * When `data_parallel_size > 1`, always `_dummy_run(1)` (no sticky early-return).

```bash
export VLLM_ROCM_USE_AITER=1
export VLLM_ROCM_USE_AITER_MLA=1
export VLLM_ROCM_USE_AITER_MOE=1
export VLLM_ROCM_USE_AITER_RMSNORM=1
export VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=0
# HT/LL path (unset ALL2ALL_BACKEND); P eager / D PIECEWISE

# PREFILL — master (node0, DP ranks 0–7)
vllm serve /data/models2/GLM-5.2-FP8 \
    --host $PREFILL_IP --port 20005 -tp 1 \
    --data-parallel-size 16 \
    --data-parallel-size-local 8 \
    --data-parallel-address $PREFILL_IP \
    --data-parallel-rpc-port 13345 \
    --enable-expert-parallel \
    --trust-remote-code \
    --kv-cache-dtype fp8 \
    --gpu-memory-utilization 0.85 \
    --enforce-eager \
    --kv-transfer-config '{"kv_connector":"MoRIIOConnector","kv_role":"kv_producer",
      "kv_connector_extra_config":{"proxy_ip":"'$PREFILL_IP'","proxy_port":"10001",
      "proxy_ping_port":"36367","http_port":"20005","handshake_port":"6301","notify_port":"61005"}}'

# PREFILL — child (node1, headless, DP ranks 8–15)
vllm serve /data/models2/GLM-5.2-FP8 \
    -tp 1 \
    --data-parallel-size 16 \
    --data-parallel-size-local 8 \
    --data-parallel-address $PREFILL_IP \
    --data-parallel-rpc-port 13345 \
    --data-parallel-start-rank 8 \
    --headless \
    --enable-expert-parallel \
    --trust-remote-code \
    --kv-cache-dtype fp8 \
    --gpu-memory-utilization 0.85 \
    --enforce-eager

# DECODE — master (node2) / child (node3): same DP16 layout, kv_consumer,
# PIECEWISE cudagraph (not enforce-eager), same MoRIIO proxy ports.
```
