# [XPU][LoRA] Support unquantized MoE LoRA

[Upstream PR](https://github.com/vllm-project/vllm/pull/62807) · state: open · merged: False

## Original PR description

## Overview

Route unquantized (BF16) MoE LoRA on XPU through `XpuFusedMoe`'s
`activation_hook`/`output_hook` instead of Triton experts, by mixing
`LoRAExpertsMixin` into `XPUExperts` (a single class, like `TritonExperts`).
 
## Changes
- `XPUExperts` now mixes in `LoRAExpertsMixin` as a single class, mirroring `TritonExperts`.
- FP8 / BlockFP8 / WNA16 / MXFP4 opt out via `supports_lora()`.
- Intel CI now runs `tests/lora/test_olmoe_tp.py`.

## Validation

AI assistance (GitHub Copilot) was used. Not a duplicate: #62631 is MXFP4, #61310 is FP8/W4A16; no open PR covers unquantized XPU MoE LoRA.

- `pytest tests/lora/test_olmoe_tp.py` on Intel XPU: 7 passed (log shows "XPU Unquantized MoE LoRA backend"), with kernels#648 installed locally.
- No perf comparison vs the Triton path yet.
