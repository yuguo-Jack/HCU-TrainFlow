# [ROCm][Perf][MiniMax-M3] Defer the FFN all-reduce into the next layer's norm

[Upstream PR](https://github.com/vllm-project/vllm/pull/61119) · state: open · merged: False

## Original PR description

## Overview

Make the AMD MiniMax-M3 model defer each layer's FFN all-reduce into the next layer's norm, the same way the NVIDIA model already does. On its own this does not change performance. It is a prerequisite for ROCm all-reduce kernel work that is still in progress (see Details).



## Claims

- Both all-reduces in each AMD MiniMax-M3 layer can now go through the fused all-reduce + norm path. Before, only the attention-site one could.
- No performance change on its own. Output tok/s is within about 0.2 % of baseline in 6 of 7 configs. The 7th (8k/1k, c8) is +1.4 %, which I read as run-to-run noise.
- No quality regression. NIAH/GSM8K scores are identical to baseline.


## Validation

**Unit test (CPU only).** `pytest tests/models/minimax_m3/test_xlayer_allreduce_fusion.py` gives `8 passed`. The test drives the real `MiniMaxM3Model` wiring methods with stand-in layers. It covers the dense-then-MoE chain, which captures reduce, and every defer pattern and EAGLE3 capture set for 1 to 6 layers. In every case each deferred all-reduce is completed exactly once, and no capture sees a partial sum.

## Details

**What changes.** The NVIDIA model (`vllm/models/minimax_m3/nvidia/model.py`) leaves each layer's FFN output un-reduced. The next layer's `input_layernorm`, or the final norm, then finishes the all-reduce through `fused_allreduce_gemma_rms_norm`. The AMD model never got this wiring. At TP > 1, every AMD layer pays for a separate full-size all-reduce and a separate norm on its FFN output. This PR ports the NVIDIA wiring:

- `MiniMaxM3MoE` and `MiniMaxM3MLP` are built with `reduce_results=False`. `MiniMaxM3DecoderLayer.ffn_all_reduce_deferred` reports whether a layer left its FFN output un-reduced.
- `MiniMaxM3Model._configure_allreduce_fusion` sets `fuse_input_allreduce` on each layer that follows a deferring layer. The final norm picks up the last layer's reduce.
- MTP blocks (`is_mtp_block=True`) and PP > 1 keep reducing as before. MTP adds the residual directly, and PP sends hidden states across stages.
- An EAGLE3 aux capture taken right after a deferring layer reduces a copy, so it never records a per-rank partial sum.

**Why land this before it shows a speedup.** An upcoming PR will move MiniMax-M3 on ROCm to a faster fused all-reduce + norm kernel (the AITER side is ROCm/aiter#6404 has already been merged). That kernel only helps the FFN all-reduce if the model defers it into the next norm, which is what this PR does. In our MI350X runs (TP4) this combination gave about +5 % at 60k/600 c64 and about +2 % at 8k/1k c32, against about +3 % at 60k c64 without this PR. NVIDIA already does this, so it also brings the two models in line. Full numbers will come with that PR.

**Not a duplicate.** I searched open PRs for "MiniMax-M3 all-reduce", "fuse_input_allreduce" and "ffn_all_reduce_deferred". Nothing open ports this wiring to the AMD model.
