# [ROCm][Perf][MiniMax-M3] Defer the FFN all-reduce into the next layer's norm

[Upstream PR](https://github.com/vllm-project/vllm/pull/61119) · state: open · merged: False

## Original PR description

### Purpose

`vllm/models/minimax_m3/nvidia/model.py` leaves each layer's FFN output un-reduced. The next layer's `input_layernorm`, or the final norm, then completes that all-reduce through `fused_allreduce_gemma_rms_norm`. `amd/model.py` never got this wiring, so it fuses only the attention-site all-reduce. At TP > 1, every AMD layer pays a separate full-hidden all-reduce plus a separate norm for its FFN output.

This PR ports the NVIDIA wiring to the AMD model:

- `MiniMaxM3MoE` and `MiniMaxM3MLP` are built with `reduce_results=False`. `MiniMaxM3DecoderLayer.ffn_all_reduce_deferred` reports whether the FFN output was left un-reduced.
- `MiniMaxM3Model._configure_allreduce_fusion` sets `fuse_input_allreduce` on each layer that follows a deferring layer. The final norm absorbs the last layer's reduce.
- MTP blocks (`is_mtp_block=True`) and PP > 1 keep reducing. MTP adds the residual directly, and PP ships hidden states across stages.
- An EAGLE3 aux capture taken right after a deferring layer reduces a copy, so it never records a per-rank partial sum. The deferral chain itself is untouched.

Each FFN-site all-reduce now goes through the same fused helper as the attention site. On ROCm that means AITER's one-stage fused AR + RMSNorm at decode sizes, and FlyDSL QuickReduce's fused kernel at prefill sizes once #61021 and its follow-up land.

### Not a duplicate

Searched open PRs for "MiniMax-M3 all-reduce", "fuse_input_allreduce", and "ffn_all_reduce_deferred". The NVIDIA model already has this wiring; nothing open ports it to the AMD model.

### Test Plan

- Unit test, CPU only: `pytest tests/models/minimax_m3/test_xlayer_allreduce_fusion.py`. It drives the real `MiniMaxM3Model` wiring methods with stand-in layers and checks:
  - the dense-then-MoE chain;
  - which captures reduce;
  - every defer pattern × EAGLE3 capture set for 1–6 layers: each deferred all-reduce is completed exactly once, and no capture sees a partial.
- End to end on MI350X (gfx950), TP4, `amd/MiniMax-M3-MXFP4`. Serve flags: fp8 KV, chunked prefill 32768, AITER MoE, FP8 attention via `--quantization-config`. `vllm bench serve` random, 2 repeats. GSM8K 5-shot.

### Test Result

| | 8k/1k c32 tok/s | 60k/600 c64 tok/s | GSM8K (n=400) |
|---|---|---|---|
| main | 1997 | 489.4 | 0.8425 |
| this PR | 1993 (−0.2 %) | 488.9 (−0.1 %) | 0.8300 |
| this PR + FlyDSL QuickReduce fused prefill norm (#61021 + follow-up) | 2037 (+2.0 %) | 515.3 (+5.3 %) | 0.8275 |

On its own the change is perf-neutral and that is because at prefill sizes today the deferred all-reduce still runs unfused, just one layer later. It is the prerequisite for fusing both all-reduce sites per layer. FlyDSL QuickReduce plus the fused prefill norm without this PR gives +3.2 % at 60k c64, no better than FlyDSL QuickReduce alone (+3.3 %); with this PR, +5.3 %.
