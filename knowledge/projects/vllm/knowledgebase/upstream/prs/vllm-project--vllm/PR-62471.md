# [Frontend] systemone: let joint schema models take more options than labels

[Upstream PR](https://github.com/vllm-project/vllm/pull/62471) · state: open · merged: False

## Original PR description



## Overview

`/v1/systemone` and `/v1/decisions` cap a Clef question at 26 options, the A–Z label set of next-token strategies. Clef's joint schema head reads each option's own span and no label token, so the cap does not apply. This lets `JointSchemaStrategy` (Clef-Omni) and `ClefFlashStrategy` take up to 255 options, the `/v1/decisions` choice limit.

## Claims

- A Clef-Flash or Clef-Omni `choice` question with more than 26 options is answered instead of returning 400 `at most 26 options for this model`.
- Next-token, Liquid and DiffusionGemma strategies keep their label-bound limits. `DecisionLimits.labeled` already models this (D3 uses it); the joint schema strategy now sets it, and `/v1/decisions` now respects it in `make_read_question`.

## Validation

**Real model.** `Cloudflare/clef` (the 27B checkpoint, `Qwen3_5ForConditionalGeneration` + joint head, loaded as `ClefFlashForJointSchema`), FP8 W8A8 (compressed-tensors), one L40S, on the v0.32.1rc0 commit `2365177d` with this change applied:

| Request | Before | After |
| --- | --- | --- |
| 1 choice question, 26 options | 200 | 200, same answer |
| 1 choice question, 59 options | 400 `at most 26 options` | 200; same pick as our reference server, max probability gap 0.017 |
| 2,500 real emails, 59-option document-type question + 1 noul | every request 400 | 2,494 scored (6 inputs had no text); verdicts match our pre-existing reference server (Clef's `joint_schema_model.py` head over vLLM 0.30 hidden states) on 2,484, document type on 2,436, median probability gap 0.003 |

**Tests.** `test_joint_schema_reads_more_options_than_labels` (both joint schema strategies, 59 options) and `test_backend_takes_more_choices_when_options_are_not_labeled`. Both fail without the change and pass with it; the rest of the suite is unchanged:

```bash
pytest tests/entrypoints/generate/structured_decisions/test_decisions.py \
  tests/entrypoints/generate/structured_decisions/test_question_types.py \
  tests/entrypoints/generate/structured_decisions/test_strategies.py
# 113 passed
```

## Details

- 255 matches `ChoiceQuestion.choices` (`max_length=255`) on `/v1/decisions`. A larger question is still bounded by the prompt: the strategy already rejects a schema longer than its context.
- Scores keep their 10-level limit through the request schema on `/v1/decisions`; on `/v1/systemone` a joint schema score is bounded by `max_options` like a choice, since its levels are read by span as well.
- Docs: the limits table notes the Clef value.
