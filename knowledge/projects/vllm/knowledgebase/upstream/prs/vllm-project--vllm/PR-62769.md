# [Bugfix][Spec Decode] Synchronize adaptive DSpark decisions across TP ranks

[Upstream PR](https://github.com/vllm-project/vllm/pull/62769) · state: open · merged: False

## Original PR description


This carries #56831 by @CedricHwong forward to current main. That PR has been idle since 09-14 and no longer passes CI after the rebase. Cedric's commit is kept unchanged, with his authorship. The two commits on top address the review comments on that PR.

Adaptive verification (DSpark) picks the per-step draft budget on the host from rank-local stale confidences, then picks which slots to keep on the device from rank-local live confidences. If TP ranks disagree on either one, they run different batch layouts: different token counts, or equal totals with different request boundaries. That breaks the collectives that follow and can hang them (#54011). This PR makes TP rank 0 authoritative:

1. `get_num_tokens`: `draft_budget` is broadcast with `broadcast_object` (shm MessageQueue, host only).
2. `reallocate_drafts`: on steps that trim, the per-request `capacities` are broadcast from rank 0 before `cu_num_logits` / `query_start_loc` are built.

Both conditions around (2), `draft_budget == 0` and `draft_budget < scheduled drafts`, depend only on the broadcast budget and scheduler-provided counts. Every TP rank therefore takes the same branch, and the collective cannot be entered unevenly.

### Changes vs #56831

- **Test updates for current main.** #56888 renamed `async_copy_to_gpu` to `async_tensor_h2d`; the old monkeypatch no longer resolved, giving 12 failures, and `cpu.yaml` runs `-x`. #58466 made `reallocate_drafts` also return the admitted draft counts. #63421 replaced the compiled budget assignment with a Triton kernel; the CPU test stands in for it with its global top-k reference. #55939 made `tests/v1/spec_decode` type-checked, so the test now narrows `_batch_budget` before indexing it.
- **Real multi-rank test.** `test_tp_ranks_agree_on_verification_layout[2, 4]` spawns gloo ranks with a real TP `GroupCoordinator` and drives the real `get_num_tokens` / `reallocate_drafts`. The ranks' confidences differ by one fp32 ULP, across three cases: a draft-budget tie, an equal-total boundary split, and 64 randomized steps. Every rank must end up with the leader's budget, capacities, `cu_num_logits` and `query_start_loc`. It replaces the single-process budget emulation.
- **Transport.** The capacities sync uses plain `get_tp_group().broadcast`, i.e. c10d on the TP device group, as in #56831.
  - Routing `GroupCoordinator.broadcast` through the device communicator (PyNCCL) would be about 2x cheaper per call. On CUDA it would also avoid creating the device group's NCCL communicator on the first trimmed step. But it changes every `GroupCoordinator.broadcast` caller (PCP `sync_drafts` too) and needs XPU validation, so it will be a separate PR.

Scope: this covers TP. It also covers DCP when PCP = 1; DCP groups span PCP before TP. With PCP > 1, each PCP slice's TP group has its own leader. Since #61994, DeepSeek-V4.1 on NVIDIA rejects AV + PCP (it requires fixed-length DSpark). The generic `PCPManager` path still admits it, which predates this PR and is a follow-up.

- MI355X end to end:
  - Model: Qwen3-4B + `deepseek-ai/dspark_qwen3_4b_block7` with `enable_adaptive_verification: true`, V2 model runner, ROCM_ATTN.
  - Workload: 600 GSM8K CoT prompts, output 512, greedy.
  - A/B: main vs this PR, conc 1/16/64, 4 interleaved rounds per arm.
  - Divergence check: an instrumented main that all-gathers every rank's locally computed budget, capacities and confidences on every step.

## Test Result

- **Unit tests** (on main `7e3e3f6ab6`): `test_adaptive_verification.py` gives 31 passed and 7 skipped (the CUDA-only kernel tests). mypy and ruff are clean, and the real-rank test passed 10 of 10 runs.
  - **Without the budget broadcast:** the real-rank test fails on the budget tie; 36/64 random steps diverge at TP2, 53/64 at TP4.
  - **Without the capacities broadcast:** the real-rank test fails on the boundary case (4/64 random steps at TP2, 10/64 at TP4: equal totals, different request boundaries). The emulated reallocation tests at TP 2/4/8 fail too.
- **Multi-rank harness:** 0 mismatches on this branch at every world size and drift level.
  - Without the fix, a single fp32 ULP is enough to change the layout. Mismatching steps per 1000 at TP 2/4/8 (capacities or boundaries):
    - 1-16 ULP: 0-2
    - 1e-4 relative: 2-9
    - 1e-2 relative: 65-382
  - Most mismatches have equal totals across ranks but different request boundaries.
- **Per-step cost, MI355X, p50 (p90), slowest rank:**

| | TP2 | TP4 |
|---|---|---|
| `broadcast_object(budget)`: every step that has drafts, host only | 6.7 us (7.5) | 7.9 us (8.2) |
| `capacities` broadcast (c10d, as in this PR): trimmed steps only. Host enqueue + in-stream GPU time; does not depend on num_reqs from 1 to 256 | ~32 + ~25 us | ~33 + ~26 us |
| Worst-case total for a trimmed step, with no overlap | ~64 us | ~68 us (p90 ~76) |

  That is 0.4-1.4% of a 5-15 ms decode step, at most. The host part overlaps GPU work under async scheduling. With PyNCCL (the planned follow-up), a trimmed step costs about 25-29 us.
- **End to end at TP2, measured with the capacities sync on PyNCCL (an earlier revision of this PR); the c10d path still needs an e2e run (GPUs were busy): no measurable regression.** Each delta is within about 1.2 standard deviations; run-to-run CV is 0.2-0.6%.

| conc | output tok/s, main | output tok/s, this PR | delta | TPOT p50, main → PR |
|---|---|---|---|---|
| 1 | 721.0 ± 4.1 | 727.7 ± 10 | +0.9% | 1.311 → 1.314 ms |
| 16 | 5489 ± 12 | 5493 ± 15 | +0.1% | 2.755 → 2.763 ms |
| 64 | 10590 ± 50 | 10585 ± 19 | -0.1% | 5.615 → 5.629 ms |

  Acceptance length is unchanged (±0.7%). There were 0 failed requests in 24 runs. The `capacities` broadcast fired on about 97% of c16/c64 steps and about 7% of c1 steps.
- **Natural divergence was not observed on this setup.**
  - Instrumented main ran 8434 steps at TP2 and 7886 steps at TP4: 0 budget, capacities or confidence mismatches.
  - A separate DeepSeek-V4.1 TP4 MI355X serving trace ran about 478k AV steps, also with 0 mismatches.
  - Here the confidence inputs are bitwise identical across ranks, because the custom all-reduce sums in a fixed rank order. Divergence needs rank-asymmetric numerics, such as rank-order-dependent reductions, non-deterministic kernels, or the TP8 H20 DeepSeek-V4 setup in #54011.
  - The fix is cheap insurance against that: per the numbers above, about 7 us host per step plus about 19 us per trimmed step.

Co-authored with @CedricHwong (original fix, #56831). Supersedes #56831.

ar_size_mismatch.py
`python ar_size_mismatch.py --tp 2 --impl qr --tokens 1345 --delta -1   # HANG (505 vs 504 tiles)`
```
# SPDX-License-Identifier: Apache-2.0
"""Model-free reproducer: TP all-reduce when one rank passes a different size.

Mirrors adaptive DSpark verification when TP ranks disagree on draft_budget:
every rank all-reduces a [num_tokens, hidden] bf16 activation, but one rank's
num_tokens is off by `delta`. Each case runs in fresh processes with a timeout.

  python ar_size_mismatch.py --tp 4 --impl qr --tokens 1345 --delta -1
Outcome line: OK | WRONG (sum mismatch) | HANG (timeout) | CRASH (rank error)
"""

import argparse
import os
import queue
import sys
import traceback

import torch
import torch.multiprocessing as mp

HIDDEN = 6144  # MiniMax M3.1 hidden size


def worker(rank, args, port, q):
    try:
        torch.cuda.set_device(rank)
        from vllm.config import VllmConfig, set_current_vllm_config
        from vllm.distributed import init_distributed_environment, initialize_model_parallel
        from vllm.distributed.parallel_state import get_tp_group

        with set_current_vllm_config(VllmConfig()):
            init_distributed_environment(
                world_size=args.tp, rank=rank, local_rank=rank,
                distributed_init_method=f"tcp://127.0.0.1:{port}", backend="nccl",
            )
            initialize_model_parallel(tensor_model_parallel_size=args.tp)
        tp = get_tp_group()
        comm = tp.device_communicator
        qr, ca, nccl = comm.qr_comm, comm.ca_comm, comm.pynccl_comm
        if rank == 0:
            q.put(("info", f"qr={'off' if qr is None or qr.disabled else 'on'} "
                   f"flydsl={getattr(qr, '_flydsl_int4', None) is not None} "
                   f"ca={'off' if ca is None or ca.disabled else 'on'}"))

        def make_x(it):
            bad = args.bad_iters < 0 or it < args.bad_iters
            n = args.tokens + (args.delta if rank == args.bad_rank and bad else 0)
            return torch.ones(n, HIDDEN, dtype=torch.bfloat16, device=rank)

        x = make_x(0)
        if rank == 0:
            nbytes = x.numel() * x.element_size()
            uses = {
                "auto": "dispatch",
                "qr": f"qr_ok={qr is not None and qr.should_quick_allreduce(x)}",
                "ca": f"ca_ok={ca is not None and ca.should_custom_ar(x)}",
                "nccl": "",
            }[args.impl]
            q.put(("info", f"rank0 bytes={nbytes / 2**20:.2f}MiB {uses}"))

        def run():
            if args.impl == "auto":
                return tp.all_reduce(x.clone())
            if args.impl == "qr":
                return qr.quick_all_reduce(x)
            if args.impl == "ca":
                return ca.custom_all_reduce(x)
            out = x.clone()
            nccl.all_reduce(out)
            return out

        worst = worst_after = 0.0
        for it in range(args.iters):
            x = make_x(it)
            out = run()
            torch.cuda.synchronize()
            common = min(args.tokens, args.tokens + args.delta)
            err = float((out[:common].float() - args.tp).abs().max())
            worst = max(worst, err)
            if 0 <= args.bad_iters <= it:
                worst_after = max(worst_after, err)
            q.put(("iter", rank, it, err))
        q.put(("done", rank, (worst, worst_after)))
    except Exception as e:  # noqa: BLE001
        q.put(("crash", rank, f"{type(e).__name__}: {str(e)[:300]}",
               traceback.format_exc()[-1500:]))


def main():
    p = argparse.ArgumentParser()
    p.add_argument("--tp", type=int, default=4)
    p.add_argument("--impl", choices=["auto", "qr", "ca", "nccl"], default="qr")
    p.add_argument("--tokens", type=int, default=1345)
    p.add_argument("--delta", type=int, default=-1)
    p.add_argument("--bad-rank", type=int, default=-1, help="default: last rank")
    p.add_argument("--iters", type=int, default=20)
    p.add_argument("--bad-iters", type=int, default=-1,
                   help="disagree only on the first N iterations (default: all)")
    p.add_argument("--timeout", type=float, default=90)
    args = p.parse_args()
    if args.bad_rank < 0:
        args.bad_rank = args.tp - 1
    port = 20000 + os.getpid() % 10000
    ctx = mp.get_context("spawn")
    q = ctx.Queue()
    procs = [ctx.Process(target=worker, args=(r, args, port, q)) for r in range(args.tp)]
    for pr in procs:
        pr.start()
    done, crash, worst, worst_after, infos = {}, None, 0.0, 0.0, []
    deadline_hit = False
    import time
    t_end = time.time() + args.timeout
    while len(done) < args.tp and crash is None:
        try:
            msg = q.get(timeout=max(0.1, t_end - time.time()))
        except queue.Empty:
            deadline_hit = True
            break
        if msg[0] == "info":
            infos.append(msg[1])
        elif msg[0] == "done":
            done[msg[1]] = msg[2]
            worst = max(worst, msg[2][0])
            worst_after = max(worst_after, msg[2][1])
        elif msg[0] == "crash":
            crash = msg
    # Collect a late crash from another rank, if any.
    time.sleep(2)
    while not q.empty():
        m = q.get()
        if m[0] == "crash" and crash is None:
            crash = m
    for pr in procs:
        pr.join(timeout=5)
        if pr.is_alive():
            pr.kill()
    exitcodes = [pr.exitcode for pr in procs]
    if crash:
        outcome = f"CRASH rank{crash[1]}: {crash[2]}"
    elif deadline_hit:
        outcome = f"HANG (ranks finished: {sorted(done)}; timeout {args.timeout}s)"
    elif any(c not in (0, None) for c in exitcodes):
        outcome = f"CRASH exitcodes={exitcodes}"
    elif worst > 0.5:
        outcome = f"WRONG max_err={worst:.3g} max_err_after_agree={worst_after:.3g}"
    else:
        outcome = f"OK max_err={worst:.3g}"
    print(f"tp={args.tp} impl={args.impl} tokens={args.tokens} delta={args.delta} "
          f"bad_rank={args.bad_rank} iters={args.iters} bad_iters={args.bad_iters} | {'; '.join(infos)} | {outcome}",
          flush=True)
    if crash and len(sys.argv) and os.environ.get("AR_VERBOSE"):
        print(crash[3])


if __name__ == "__main__":
    main()
```

- olka-amd · comment · 2026-11-03T09:04:30Z · [source](https://github.com/vllm-project/vllm/pull/62769#issuecomment-6599550028)

Update on investigation:
```
The hang comes from torch.topk breaking exact ties nondeterministically on ROCm inside adaptive verification's 
draft ranking. TP ranks with bitwise‑identical inputs sometimes admit different draft slots, drift apart, 
and eventually launch all‑reduces of different sizes, which deadlocks. Making the tie order deterministic 
fixes it with no extra communication. With the fix, the config that hung in 3 of 3 attempts has run 
16 minutes clean at c420 with both #62769 broadcasts off.

This explains:
  - AMD only: CUDA's topk apparently breaks ties consistently in practice; ROCm's doesn't.
  - #62769 works: broadcasting rank 0's budget and capacities overrides each rank's own choice.
  - High concurrency: large batches mean many new requests at 1.0 and tight budgets, so the cut often lands inside a tie group.
  - Fixed draft length never hangs: shapes don't depend on the ranking.
  - M3.1 with its confidence head stayed clean: its continuous confidences and looser budgets rarely put the cut inside a tie group.
```
The fix came in #63421 (Oct 26), which replaced the torch.compile + topk ranking with a Triton kernel that hands out tied slots in request order.
