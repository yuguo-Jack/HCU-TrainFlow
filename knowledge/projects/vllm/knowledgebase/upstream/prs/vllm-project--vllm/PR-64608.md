# [Bugfix][Whisper] Raise default max_num_batched_tokens to fit the encoder input

[Upstream PR](https://github.com/vllm-project/vllm/pull/64608) · state: open · merged: False

## Original PR description



## Overview

Whisper fails at engine startup when `max_num_seqs` is 3 or lower and `max_num_batched_tokens` is not set. This raises the default token budget to fit one encoder input for encoder-decoder multimodal models, the same way #43051 does for prefix-LM models.

## Claims

- `LLM("openai/whisper-...", max_num_seqs=1)` (up to 3) and `vllm serve openai/whisper-small --max-num-seqs 1` start and transcribe. Before this change they fail with `ValueError: Chunked MM input disabled but max_tokens_per_mm_item (1500) is larger than max_num_batched_tokens (448). Please increase max_num_batched_tokens.`
- Prefix-LM models (for example Gemma 4) take the same path as before, and every configuration that starts today keeps the same budget.
- Whisper now reports its per-item audio token count directly, so the budget no longer needs dummy-input processing for it.

## Details

**Root cause.** `EngineArgs._set_default_max_num_seqs_and_batched_tokens_args` clamps the default `max_num_batched_tokens` to `max_num_seqs * max_model_len`. For Whisper, `max_model_len` is the decoder length (448), but one audio input is 1500 encoder tokens. Encoder-decoder models always run with `disable_chunked_mm_input`, so `compute_mm_encoder_budget` rejects any budget below 1500. The floor from #43051 only covered prefix-LM models, and it runs before the clamp.

**Fix.**
- The floor logic moves into `_raise_batched_tokens_to_mm_floor`.
- The prefix-LM call stays where it was, before the clamp.
- A second call runs after the clamp, only for encoder-decoder multimodal models, because their encoder input is not bounded by the decoder's `max_model_len`.
- `WhisperProcessingInfo.get_mm_max_tokens_per_item` returns `max_source_positions`. This equals the dummy-input count by construction: `WhisperMultiModalProcessor._get_prompt_updates` sizes every audio placeholder with the same `get_num_audio_tokens()`.

**Trade-off.** For `max_num_seqs <= 3`, the decoder token budget becomes 1500, although the decoder can use at most `max_num_seqs * 448` tokens per step. This matches how #43051 handles prefix-LM models. A larger alternative is to size the encoder budget separately from `max_num_batched_tokens` in `SchedulerConfig` and `compute_mm_encoder_budget`. I kept this change small, and I'm happy to switch if maintainers prefer that. When the floor fires, startup also logs the existing `SchedulerConfig.verify_max_model_len` warning, `max_num_batched_tokens (1500) exceeds max_num_seqs * max_model_len (448)`. The documented workaround (`--max-num-batched-tokens 1500`) logs the same warning today. Silencing it for encoder-decoder models would mean passing `is_encoder_decoder` into `verify_max_model_len`, which I left out of scope.

**Other models on the same path.** These are the encoder-decoder multimodal models, the ones using `EncDecMultiModalProcessor`:
- `whisper`: fixed here.
- `nemotron_parse`: already overrides `get_mm_max_tokens_per_item`, so the new floor covers it.
- `cohere_asr`: has no override, so its behavior is unchanged. Its checkpoint is gated, so I could not verify its encoder token count or test an override.

**Not a duplicate.** I found no open issue or PR for this failure; searches included `"max_tokens_per_mm_item (1500)"`, `whisper max_num_seqs`, and `encoder-decoder max_num_batched_tokens`. #62139 caps the default at `max_model_len` to reduce profiling memory. For Whisper that goes the opposite direction and would make this failure happen at every `max_num_seqs`, so the two PRs need to agree on encoder-decoder behavior. #41239 adds `--max-num-encoder-input-tokens` and `--encoder-cache-size` but keeps the defaults, and the failing check compares against `max_num_batched_tokens`, so it does not fix this. It would make the separate-encoder-budget alternative above easier.

**Docs.** No documentation change: this fixes a startup failure and adds no option, and no documented default changes.
