# [Core] Handle new requests and aborts while waiting for model output

[Upstream PR](https://github.com/vllm-project/vllm/pull/65466) · state: closed · merged: True

## Original PR description

With the multiproc executor, the engine core thread waits for each step's output by busy-polling the workers' response queues. New requests that arrive in the meantime sit in the input queue until the step completes, which with async scheduling is up to a full step later than necessary.

Instead, poll for the step's output without blocking and handle `ADD` and `ABORT` inputs from the input queue as they arrive. Any other input (e.g. a utility call) ends this early handling: it and all inputs after it are processed once the step completes, preserving their order.

Requests then reach the scheduler, and the KV connector's `on_new_request()`, up to a step earlier. This gives connectors with asynchronous lookups (e.g. external KV cache stores) a head start before the request is scheduled.

It also moves more work off of the CPU critical path.

The uniproc executor is unchanged, TBD about extending for this too.
