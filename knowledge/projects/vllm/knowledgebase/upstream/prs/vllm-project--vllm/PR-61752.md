# [Bugfix][Frontend] Allow structured_outputs with text.format type "text" in Responses API

[Upstream PR](https://github.com/vllm-project/vllm/pull/61752) · state: open · merged: False

## Original PR description

## Overview

On `/v1/responses`, sending vLLM's `structured_outputs` (choice, regex, grammar) together with `text: {"format": {"type": "text"}}` is rejected with "Cannot specify both structured_outputs and text.format". `{"type": "text"}` is the plain, unconstrained format, and Chat Completions already ignores `response_format: {"type": "text"}` in `structured_outputs_from_response_format`. `ResponsesRequest.extract_structured_outputs` only checked that `text.format` was set, so I made it treat the "text" type like no format.

## Claims

- `structured_outputs` plus `text.format.type == "text"` is accepted on the Responses API, same as on Chat Completions.
- `json_schema` or `json_object` plus `structured_outputs` still raises the conflict error.

## Validation

Noticed while comparing the two `extract_structured_outputs` implementations.

```python
so = {"choice": ["yes", "no"]}
chat = ChatCompletionRequest.model_validate(
    {"messages": [{"role": "user", "content": "hi"}],
     "response_format": {"type": "text"}, "structured_outputs": so}
)
print("chat:", chat.to_sampling_params(16, {}).structured_outputs.choice)
resp = ResponsesRequest.model_validate(
    {"input": "hi", "text": {"format": {"type": "text"}}, "structured_outputs": so}
)
print("responses:", resp.to_sampling_params(16).structured_outputs.choice)
```

```text
# main (03091e28b)
chat: ['yes', 'no']
VLLMValidationError: Cannot specify both structured_outputs and text.format (parameter=structured_outputs)

# this PR
chat: ['yes', 'no']
responses: ['yes', 'no']
```

I added `test_structured_outputs_with_plain_text_format`; it fails on main with the error above, and the existing json_schema conflict test still passes.

```
pytest tests/entrypoints/openai/responses/test_sampling_params.py tests/entrypoints/openai/responses/test_protocol.py
ruff check && ruff format --check   # on the two touched files
```

Both pass locally. No GPU here, so this was checked at the request-model level only, not against a live `vllm serve`.

## Details

The both-set check came in with #33709. Not a duplicate as far as I can tell: #50544 and #53006 are open and edit the same function, but for `json_schema` with `strict=false`, and neither changes how the "text" type is handled. #50544 adds its own early return right below this condition, so whichever lands second needs a small rebase.
