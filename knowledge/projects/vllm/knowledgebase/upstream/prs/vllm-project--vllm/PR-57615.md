# [Docs] Document NIXL KV connector metrics aggregation semantics

[Upstream PR](https://github.com/vllm-project/vllm/pull/57615) · state: open · merged: False

## Original PR description

## Summary

Documents the NIXL KV connector's metrics aggregation semantics, addressing
confusion around how transfer metrics are reported in multi-rank (TP > 1)
deployments.

## What was added

- **`stats.py`**: Comprehensive docstrings for `NixlKVConnectorStats` class and
  all methods (`reset`, `record_transfer`, `record_failed_transfer`,
  `record_failed_notification`, `record_kv_expired_req`, `clone_and_reset`,
  `is_empty`, `aggregate`, `reduce`, `num_successful_transfers`).
- **`stats.py`**: Inline comment in `reduce()` clarifying that throughput is
  average per-rank throughput, not aggregate system throughput.
- **`metrics.py`**: Module-level docstring explaining the full metrics pipeline
  and multi-rank aggregation semantics.
- **`metrics.py`**: Docstrings for `KVConnectorStats`, `KVConnectorLogging`,
  `KVConnectorProm`, `KVConnectorPromMetrics`, and all their methods.

## Key clarification for users

When TP > 1, metrics are aggregated across all ranks via list concatenation.
This means:
- "Num successful transfers" is total across all ranks, not per-rank
- "Throughput (MB/s)" is `sum(bytes) / sum(durations)` = average per-rank throughput
- Percentiles are computed over the combined distribution from all ranks

Fixes #41230
