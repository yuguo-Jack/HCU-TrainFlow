# [Bugfix][Spec Decode] Fix autoregressive draft decode capture with dynamic SD

[Upstream PR](https://github.com/vllm-project/vllm/pull/49652) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #48494.

Dynamic speculative decoding (DSD) derives target verification / draft-prefill decode query lengths from the configured speculative-token schedule. That derivation is valid when `decode_query_len` includes the speculative tokens, but it is not valid for autoregressive draft decode: every draft step processes exactly one token per request and dispatches with `num_tokens == num_reqs` and `uniform_token_count == 1`.

Applying the target-model DSD schedule to the draft-decode manager can therefore construct invalid or missing CUDA Graph candidates. For schedules that include smaller K values (including K=0), this can eventually reach dummy-input construction with an invalid descriptor and fail at:

```text
assert 0 < num_reqs <= num_tokens
```

## Fix

This revision is rebased onto current `main` and keeps the fix local to the autoregressive speculator CUDA Graph manager rather than changing the shared `CudaGraphManager` logic.

`SpeculatorCudaGraphManager` now uses a shallow `VllmConfig` copy with `speculative_config=None` **only while capture candidates are initialized when `decode_query_len == 1`**. That is the autoregressive draft-decode path, whose query length is fixed at one. The manager then restores the original `vllm_config` for capture/runtime behavior.

As a result:

- autoregressive draft decode always builds FULL candidates for query length 1;
- autoregressive draft prefill continues to use DSD-derived query lengths;
- multi-module MTP / other speculator managers with query length >1 keep their existing behavior;
- current upstream DSD schedule clamping and shared `CudaGraphManager` behavior remain untouched; and
- the fix does not suppress the assertion or fall back to eager execution.

The regression test uses a representative schedule below the configured upper-bound K:

```text
max K = 4
K schedule = 3 / 1 / 0
```

It verifies that draft prefill still captures the scheduled query lengths, draft decode captures only query length 1, and FULL dispatch succeeds for request counts 1 through 8.
