# [Bugfix][Rust Frontend] Fix completions echo with return_token_ids

[Upstream PR](https://github.com/vllm-project/vllm/pull/62684) · state: open · merged: False

## Original PR description



## Overview

Align Rust `/v1/completions` echo with Python when `return_token_ids=true`, and fix the empty single-token prompt-only `logprobs.tokens` fallback. Related: #44280 ([claim](https://github.com/vllm-project/vllm/issues/44280#issuecomment-6287803290)).

## Claims

- For string prompts, omit the prompt from `text` when both `echo` and `return_token_ids` are enabled, matching Python and the existing Rust token-ID-input behavior.
- Decode single-token prompt-only logprobs from the actual prompt token ID instead of the visible echo text. Token-ID prompts already return `tokens: [""]` here before this PR; clearing string echo would otherwise expose the same bug for string prompts.

## Validation

Reproducer (`facebook/opt-125m`, CPU, `add_special_tokens=false`):

```bash
curl -s localhost:8000/v1/completions -H 'content-type: application/json' -d '{
  "model": "facebook/opt-125m", "prompt": "Hi",
  "echo": true, "return_token_ids": true, "max_tokens": 0, "logprobs": 0
}'
```

Python and Rust frontends were compared sequentially with real CPU inference at `e68efc685`, streaming and non-streaming:

| Input / response field | Rust before | Rust after | Python |
| --- | --- | --- | --- |
| `"Hi"` / `text` | `"Hi"` | `""` | `""` |
| `[30086]` / `logprobs.tokens` | `[""]` | `["Hi"]` | `["Hi"]` |

The single-token logprobs matrix covered 16 requests (both input types, both response modes, `return_token_ids`, `return_tokens_as_token_ids`).

After rebasing onto `0d00d8b9`, which only adds an unrelated commit to these files (#51488):

```sh
cd rust
cargo +1.95 test --locked -p vllm-server                     # 474 passed
cargo +1.95 clippy --locked -p vllm-server --all-targets -- -D warnings
cargo +1.95 fmt --all --check
```

Clippy and formatting pass. The existing HTTP regression test now covers text/token-ID inputs in both streaming and non-streaming responses; a unit test covers the single-token fallback.

## Details

Root cause: `completion_echo_text` only blanked the echo for token-ID prompts, and `prompt_only_logprobs_to_openai` copied the visible echo text as the token string when the engine returns no prompt logprobs for a one-token prompt.

Keep `Some("")`, not `None`: response assembly still needs to recognize prompt-only echo.

Not duplicate work: #62495 handles batch prompts and streaming echo prompt logprobs, and still keeps string echo with `return_token_ids` and the visible-text fallback. Both touch the same helpers; I'll rebase onto whichever lands first. Echo plus prompt truncation is a separate follow-up PR.

Known streaming differences outside this fix:

1. `echo=true, return_token_ids=false`: Python includes `prompt_token_ids`; Rust omits them.
2. `max_tokens=0, return_token_ids=true`: Python exposes the internally sampled token ID; Rust does not. #61660 removes this from Python, so Rust does not copy it.
