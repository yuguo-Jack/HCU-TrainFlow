# [CI][AMD] Add queue fallback config for AMD GPU queues

[Upstream PR](https://github.com/vllm-project/vllm/pull/62147) · state: open · merged: False

## Original PR description

- Add `health.yaml`: where the queue-health checker publishes its snapshot and which pipeline it watches
- Add AMD `defaults.yaml`: close a queue on a high infra failure rate, then probe it for reopening
- Add `clusters.yaml`: the MI300, MI355 and MI250 queues that share one cluster are judged and closed together
- Add `mi300.yaml`, `mi355.yaml`, `mi250.yaml`: the fallback chain for each AMD device
- Point `ci_config.yaml` at the new `queue_fallbacks` directory

With this config, the pipeline generator moves AMD steps off a queue that the queue-health checker has marked as closed and sends them to the next open device in that device's chain. Main builds also run a few probe jobs on the closed queue so it can reopen once it is healthy again. Health is computed only from main builds, so failures on PR builds never close a queue. The generator side is in vllm-project/ci-infra#827, and the config does nothing until that lands and the `QUEUE_FALLBACK_BUILDKITE_API_TOKEN` secret and the `queue-health` pipeline exist. Until then every queue is treated as open and the generated pipeline is the same as today. NVIDIA queues are left out on purpose for now.

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
