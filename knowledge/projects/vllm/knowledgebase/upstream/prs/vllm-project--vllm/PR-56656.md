# [Bugfix] Include mixed prompt embedding masks in prefix cache keys

[Upstream PR](https://github.com/vllm-project/vllm/pull/56656) · state: open · merged: False

## Original PR description

## Overview

Fixes #56655. Include the per-block `prompt_is_token_ids` routing mask in mixed prompt-embedding prefix-cache keys, preventing a request from silently reusing KV computed for different effective inputs.

## Claims

- Changing the routing mask cannot reuse the affected prefix blocks, even when token IDs and supplied embedding tensors match.
- Identical requests still reuse cached KV. Absent/all-False masks and decode-only blocks retain existing key behavior.
- Regression coverage includes real-weight `LLM.generate` inference, block-boundary cases, both supported SHA256 hash variants, and KV event extra keys.

## Details

`prompt_is_token_ids` selects whether each row comes from the token embedding table or the supplied tensor. Previously the hash covered the tensor but omitted this selection, so distinct effective prompts could share KV. The fix keeps the cached tensor digest and upstream's `("prompt_embeds", digest)` tag, then appends `("prompt_is_token_ids", bytes(block_mask))` when that block contains token-ID positions. This also preserves complete mask bytes in KV cache events.

The latest conflict was confined to the test helper signature. The resolution retains upstream's `sampling_params` argument together with the mixed-input arguments; production logic is unchanged from the previous revision. Added real-model regression coverage and a prefix-caching section in the existing [prompt embedding documentation](https://github.com/ai-yang/vllm/blob/fix/mixed-prompt-embeds-prefix-cache/docs/features/prompt_embeds.md#prefix-caching).

The added work is CPU mask slicing/encoding per hash block, with no new GPU synchronization or tensor transfer. Semantically equivalent inputs expressed with different masks may conservatively miss the cache; no performance improvement is claimed.
