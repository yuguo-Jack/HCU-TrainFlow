# [Model] Add opt-in PrimTS attention for Step5 on Blackwell

[Upstream PR](https://github.com/vllm-project/vllm/pull/62550) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Add opt-in PrimTS DSA and sliding-window attention for Step5 on Blackwell (SM100/103/107), supporting BF16 and pure E4M3 QKV. Requires [FlashInfer #7106](https://github.com/flashinfer-ai/flashinfer/pull/7106); builds on #61727.

## Claims

- Native remains the default. When enabled, PrimTS handles supported prefill; BF16 decode uses PrimTS at captured/padded batch size ≥32 with MTP=3. FP8 decode always uses PrimTS.
- Reuses existing cache producers, selectors and gate. FP8 Q quantization is fused into the Q/KV producer, with output retained in the model activation dtype.
- SWA uses the runtime-length FlashInfer `max_q_len` API. Logical Q/KV capacities remain planning/workspace bounds, while compiled attention is reused across changing lengths.
- Fixed-Q decode derives metadata from KV lengths; packed prefill shares asynchronously uploaded grouping offsets across layers. Scheduler and CUDA-graph padding behavior are unchanged. Upstream native SM100 admission is preserved.

## Validation

Rebased onto vLLM main `5ea83019`; measured at vLLM `8612c29ed3` / FlashInfer `c7f1a3ca`. Four GB300 GPUs, TP=4/MTP=3, CuTe DSL 4.8.0, PyTorch 2.14 NVIDIA build / CUDA 13.4. Other stack versions and raw outputs are retained with the validation artifacts.

**Compilation.** Empty independent software compilation caches for each backend, followed by a fresh-process restart reusing that arm’s caches. After server readiness, prompt lengths 128, 512, 1024, 2048, 4096, 8192 and 16384 each run twice.

| Native BF16 | 706.4 | 328.2 | 0 | 0 |
| PrimTS BF16 | 804.4 | 336.2 | 0 | 0 |

¹ Readiness includes model loading, JIT compilation and graph warmup; filesystem weight-cache state is uncontrolled. Build records may repeat across TP ranks. The previous 20–40 s Prims-TS bucket stalls no longer reproduce in the tested prompt matrix. A shared score-scheduler compile of about 0.9 s remains at first 8K and also occurs in native; this is separate from Prims-TS attention specialization. The full accuracy runs also add zero Prims-TS specializations in either PrimTS arm; each backend adds nine shared score-scheduler variants.

**Accuracy.** Full GPQA Diamond, AIME 2024 and GSM8K, two repeats per backend: **9,282 responses**. Natural prompts, temperature=1.0, top_p=0.95, high reasoning, max_tokens=1,000,000, max_model_len=1,048,576. Identical frozen prompts/seeds across backends. A common native BF16 local model extracts every saved response without reference answers; supporting quotations and extraction disagreements are audited. Predictions are frozen before comparison; two GSM8K reference items stated in shoe pairs are converted to individual-shoe units before exact numeric comparison. Scores use this common audited extraction, so they are not a direct reproduction of the earlier parser.

**Local correctness.** 16 adapter tests and 18 fused-producer tests pass, including BF16/FP8 long-KV cases (8K/160K), partial packed requests, inactive requests and CUDA-graph replay against independent references. Numerical references/tolerances are unchanged. The numerical fixture restores TF32 state explicitly for compatibility with PyTorch’s cuBLAS proxy.

The changed CUDA target is rebuilt with CUDA 13.4/SM103 over published native libraries whose compiled sources match the pinned main commit. Pre-commit passes for the rebased range and follow-up.

## Details

Enable with `--kernel-config '{"step5_attention_backend":"prims_ts"}'` and `--kv-cache-dtype bfloat16` or `fp8_e4m3`. Block size 32; MTP=3 means three draft tokens plus one target token (Q=4). Query dtype follows backend/cache configuration independently of batch routing.

Hardware validation covers GB300/SM103. SM100/107 remain untested locally, and H200 CI cannot execute the PrimTS adapter cases. No duplicate Step5 PrimTS integration exists in pinned main; existing integrations for other models are distinct. AI assistance was used for implementation and validation.
