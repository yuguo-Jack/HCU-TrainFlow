# [Test] Add MTP acceptance-length regression test for DeepSeek-V3 (4xB200 FP8)

[Upstream PR](https://github.com/vllm-project/vllm/pull/41655) · state: open · merged: False

## Original PR description

Adds test_mtp_acceptance_length() to cover the regression class demonstrated by vllm#33771 (MTP acceptance fix revert). The test runs 80 MT-Bench prompts at temp=0 on deepseek-ai/DeepSeek-V3 with 4-way TP and FP8 quantization, asserting mean acceptance length (1 + accepted/drafts) stays within rtol of a pinned baseline. Also adds the corresponding nightly CI step on 4xB200 in spec_decode.yaml.

Also fixes a pre-existing bug in get_mt_bench_prompts() where enable_multimodal_chat was missing from the SimpleNamespace, causing runtime failures with current datasets.

**Need buildkite to run for final confirmation**, which needs hardware upgrades

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The `gpu_memory_utilization` of `0.7` is too low for DeepSeek-V3 (671B parameters). In FP8, the model weights alone require approximately 671 GB. On 4x 189 GB GPUs (total 756 GB), the weights occupy ~88.7% of the total VRAM. Setting utilization to `0.7` will cause vLLM to fail during initialization because the weights exceed the reserved memory (which would be ~529 GB). This should be increased to at least `0.9` to accommodate the weights and the MLA KV cache.

```suggestion
            gpu_memory_utilization=0.9,
```
