# [ROCm] Select AITER FP8 blockscale B-preshuffle when the shape is tuned

[Upstream PR](https://github.com/vllm-project/vllm/pull/56234) · state: open · merged: False

## Original PR description

## Summary
- Prefer `AiterPreshuffledBlockScaleFp8ScaledMMKernel` for ROCm FP8 blockscale linears when AITER reports a tuned B-preshuffle kernel for `(N, K)`.
- Shuffle weights once at load with `layout=(16, 16)` and call `gemm_a8w8_blockscale_bpreshuffle`. Activation scales are K-major at apply, because ROCm `group_fp8_quant` still emits row-major scales. e8m0 weight scales are widened to fp32 at load.
- `is_blockscale_bpreshuffle_tuned` probes several M values (including prefill and M=3307), not M=1 only. A missing AITER #5141 config is treated as untuned, so the existing blockscale kernel stays the fallback.
- Split-K added in AITER #5141 stays inside that op. The tuned kernel name selects it. This PR does not pass a split-K argument.
- Branch includes current `vllm-project/vllm` main (`5c975563`). The gfx1250 Triton preshuffle path already on main is unchanged and remains on `AiterFp8BlockScaledMMKernel`.

Depends on AITER exporting `gemm_a8w8_blockscale_bpreshuffle` ([ROCm/aiter#5141](https://github.com/ROCm/aiter/pull/5141), head `61b717e`).

## Test plan
- [x] On gfx942, load an FP8 blockscale model (e.g. Qwen3.6-27B-FP8, TP8) and confirm selected kernel is `AiterPreshuffledBlockScaleFp8ScaledMMKernel` for QKV / gate+up / down / o-proj.
- [x] Isolated GEMM: K-major activation scales match CK; row-major scales must not be used.
- [x] Chat / greedy decode remains coherent vs the existing `AiterFp8BlockScaledMMKernel` path.
- [x] Throughput smoke: ISL=1024, OSL=1024, TP8. After AITER small-M FlyDSL CSV, CUDA-graph M (e.g. 120) hits a tuned row (no `not found tuned config`).
- [ ] Re-check the same gfx942 load against AITER #5141 head `61b717e` after this merge with main. The call contract is unchanged, so this is a regression check, not a new kernel.
