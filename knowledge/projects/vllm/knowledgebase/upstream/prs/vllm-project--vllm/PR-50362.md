# [Frontend] Add verbose_json support for MOSS-Transcribe-Diarize

[Upstream PR](https://github.com/vllm-project/vllm/pull/50362) · state: open · merged: False

## Original PR description


## Purpose

Closes #50356

Add OpenAI-compatible `verbose_json` responses to `/v1/audio/transcriptions` for `OpenMOSS-Team/MOSS-Transcribe-Diarize`. MOSS emits a canonical `[start][Sxx]text[end]` transcript, whereas the existing verbose path expects Whisper timestamp tokens. This change adds the small model capability required to parse MOSS's textual timestamps, preserve
the generated token IDs and log probabilities per segment, and retain the existing Whisper path unchanged.

The OpenAI verbose-transcription schema has no `speaker` field. Therefore, speaker labels are preserved in `text` as `[S01]...`, both per segment and in the aggregate transcript, rather than being discarded or adding a
non-standard response field.

The OpenAI-compatible verbose response schema requires a non-null [`language`](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create#(resource)%20audio.transcriptions%20%3E%20(model)%20transcription_verbose%20%3E%20(schema)%20%3E%20(property)%20language) field. MOSS accepts a language hint but does not expose language identification. The supplied request language is returned; when it is absent, the response uses `"unknown"` rather than emitting `null`. Returning `null` would violate the response contract and can break strongly typed OpenAI clients.

MOSS only produces segment-level timestamps. As with the existing endpoint behavior, `timestamp_granularities[]=word` is accepted but does not synthesize word timestamps.

### Local end-to-end validation

Sent requests to a local vLLM server using:

- Model: `OpenMOSS-Team/MOSS-Transcribe-Diarize`
- Audio: [AMI Meeting Corpus](https://groups.inf.ed.ac.uk/ami/corpus/) `ES2002a.Mix-Headset.wav`, recut to a 90-second mono, 16 kHz WAV
- Request parameters: `language=en`, `temperature=0`
- Hardware: AMD Ryzen 5 5600 and AMD Radeon RX 7700 XT
- Runtime: ROCm 7.2.4
- Serving configuration: `--gpu-memory-utilization 0.80 --max-model-len 20000`

After one excluded warm-up per format, five sequential alternating `json` and `verbose_json` requests were issued. Every verbose response returned HTTP 200, 26 non-empty speaker-prefixed segments, non-empty token arrays, valid `start <= end` timestamps, and top-level `text` equal to the space-joined segment text. Additional `verbose_json` requests without `language` and with `timestamp_granularities[]=word` both returned HTTP 200; the former returned `language: "unknown"` and the latter returned no synthetic `words` entries.

The mean end-to-end difference is `+0.143773 s` (`+3.08%`). This includes verbose-only logprob collection and the larger response payload; the isolated MOSS parser cost is 0.214 ms per response.
