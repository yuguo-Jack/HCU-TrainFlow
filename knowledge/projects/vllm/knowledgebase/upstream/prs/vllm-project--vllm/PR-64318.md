# [CI] Enroll Language Models (Standard) in automatic sharding

[Upstream PR](https://github.com/vllm-project/vllm/pull/64318) · state: closed · merged: True

## Original PR description

## Overview

Enrolls `language-models-tests-standard` and its AMD mirror in automatic sharding, and moves the step's `not slow_test` exclusion from `-m` to `-k`:

```
- pytest -v -s models/language -m 'core_model and (not slow_test)'
+ pytest -v -s models/language -m core_model -k 'not slow_test'
```

The step's tests sit in 5 files main times; about 40 more files under `models/language` have no `core_model` tests. The shard planner treats an `-m`/`-k` filter containing `not` as an exclusion and charges each untimed file at the median file time, which planned 5 shards far over the cost rule. With the exclusion in `-k`, the planner reads `-m core_model` as picking tests and charges the empty files 5 s. This replaces the planner change in vllm-project/ci-infra#859; nothing here depends on it.

## Claims

| Job | Plan |
|---|---|
| `language-models-tests-standard` | 2 shards, about 11 minutes each, against about 21 minutes as one job |
| `amd-language-models-tests-standard` | 2 shards, about 11 minutes each, against about 19 minutes as one job |

- The same tests run: main selects 32 tests on the NVIDIA job and 42 on the AMD mirror, and the shards together must select the same counts.
- Every test runs exactly once across the shards, with the same environment as before.

## Validation

- `pytest -k` matches marker names as well as test names, so `-k 'not slow_test'` drops the 7 tests marked `slow_test`. No test, module or parameter id under `tests/models/language` contains `slow_test`, so nothing else is dropped.
- `/ci run` build 98064 on this head: every shard passed, and the shards together selected the same tests as main. `language-models-tests-standard`: 10 + 22 = 32 selected, 29 passed, 3 skipped (main: 32, 29, 3). `amd-language-models-tests-standard`: 20 + 22 = 42 selected, 33 passed, 9 skipped (main: 42, 33, 9).

## Details

- **Cost.** The plan counts each of the 40 empty files at 5 s; they run nothing, so the real extra cost is the second job's setup.
- **Timeouts unchanged.** `timeout_in_minutes` stays as it is.
