# [Bugfix][Frontend] Handle buffered JSON embedding responses in run-batch

[Upstream PR](https://github.com/vllm-project/vllm/pull/63189) · state: closed · merged: True

## Original PR description

## Overview

Fix batch embedding responses after #58660. The shared serializer returns a plain `Response`, which `run-batch` currently misidentifies as a stream and writes as a 400 error.

## Claims

- Decode buffered JSON responses while continuing to reject streams.
- Make the existing embedding batch test check successful results and the expected unknown-model error, rather than just the output schema.

## Validation

Ran the real `vllm run-batch` CLI on an Apple M4 Pro CPU with `intfloat/multilingual-e5-small`, using the four requests from `INPUT_EMBEDDING_BATCH`:

| Result | Main (`60a7d568f`) | With fix |
| --- | --- | --- |
| Three valid requests | 400: `Request must not be sent in stream mode` | 200, each with 384 finite embedding values |
| Unknown model | 404 | 404 |
| CLI exit code | 0 | 0 |

```bash
OMP_NUM_THREADS=4 VLLM_CPU_OMP_THREADS_BIND=nobind vllm run-batch \
  -i embeddings.jsonl -o results.jsonl \
  --model intfloat/multilingual-e5-small \
  --gpu-memory-utilization 0.1 --enforce-eager --max-num-seqs 4
```

The model-backed result above was recorded before this rebase using PyTorch 2.14.0 and model snapshot `614241f622f53c4eeff9890bdc4f31cfecc418b3`. The memory setting accommodates the RAM available on this machine. On the rebased head, the local CPU extension needs rebuilding: the CLI stops before serving because it lacks `prepare_prefill_inputs_cpu`. The focused response tests and pre-commit pass on the rebased head.

The focused response tests fail on main for the shared serializer and pass with this fix:

```bash
.venv/bin/python -m pytest --noconftest \
  tests/entrypoints/launchers/test_run_batch.py \
  -k 'batch_embedding_json_responses or batch_rejects_json_stream' -q
```

`--noconftest` avoids a macOS crash in the global PyTorch cleanup fixture. Calling `torch.accelerator.memory.empty_host_cache()` without importing vLLM reproduces it. No fixture is changed in this PR. The model-backed validation above ran the actual CLI and engine separately.

Pre-commit passes, including mypy and test tethering. The existing `entrypoints-unit-tests` Buildkite job selects these tests.

## Details

Accept non-streaming `application/json` responses at the batch boundary and parse their bytes with the cached response adapter, leaving the shared serializer unchanged. Add a CLI documentation example explaining per-request status and errors.

No open PR was found for this regression. #63005 changes TypeAdapter caching in the same function but retains the `JSONResponse` check, so it addresses a separate issue. Closed #39248 concerned `ORJSONResponse`, which inherits `JSONResponse`; this failure involves a plain `Response`.

AI assistance was used for implementation and validation.
