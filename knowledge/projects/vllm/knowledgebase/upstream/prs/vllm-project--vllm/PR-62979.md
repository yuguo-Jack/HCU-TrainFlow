# [Bugfix][HiSparse] Reserve in-flight imports' host pages at admission

[Upstream PR](https://github.com/vllm-project/vllm/pull/62979) · state: closed · merged: True

## Original PR description

## Purpose

Fixes #62217. Alternative to #62230.

HiSparse admits an async KV load only if its prompt fits in free host pages, but it ignores pages that earlier admitted loads still need. Two waiting loads can each hold pages the other needs. Waiting requests are never preempted, so the scheduler stalls forever with `running == []`.

Fix: reserve host pages for admitted loads, as `reserved_blocks` does for the GPU pool. The change is confined to `HiSparseSourceManager` and `HiSparseCoordinator`; the scheduler loop is unchanged.

- At admission of a load, `HiSparseSourceManager` sizes its host pages (prompt + spec decode step) and admits it only if they fit beside the pages other loads still need.
- The coordinator keeps a running total of outstanding pages (O(1) check), reduced as each load allocates its pages and dropped when the request is freed.
- Local admissions are not gated (they can be preempted), matching the GPU pool.

Alternatives: #62230 skips past held waiting requests in the scheduler loop. It changes the core loop, can starve the head of the queue, and still deadlocks when no admitted load fits.

Trade-off: a load whose host pages don't fit beside those reserved for in-flight loads waits for them, instead of being admitted and risking the deadlock.


Fresh decoder per run, interleaved. NIXL over TCP (no IB on that node), so the run is transfer-bound with the host pool ~96% full.
