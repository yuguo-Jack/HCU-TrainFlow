# [CI][Test] Skip unavailable models before spawning a test process

[Upstream PR](https://github.com/vllm-project/vllm/pull/65442) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

In `tests/models/test_initialization.py` and `tests/models/multimodal/processing/test_tensor_schema.py`, mark cases whose model is not available online or needs another transformers version as skipped at collection, so they no longer start a fresh test process only to skip.

## Claims

- These modules run every case in a new interpreter (`create_new_process_for_each_test`, spawn on ROCm). The availability checks ran inside it, so each such case paid 9-11 s to start and then skipped. Now they are skipped before any process starts.
- No skip is added or removed, the skip reasons are unchanged, and the collected test IDs are identical.
- Expected CI saving, from the vllm/ci build 99098 logs and the last 7 days' run rate of main plus PR builds: 64 such cases per build in (MI355 DPX) Basic Models (Extra Initialization) and 19 in (MI355 DPX) Multimodal Processor, about 23 machine-hours a day.

## Validation

Environment: CI image `rocm/vllm-ci:build-01a19b0e-d62f-4889-8556-b5c2d4478cbf` (vllm/ci build 99098) with this PR applied as a patch, one MI300X. One run per row (n=1) on a shared machine.

Commands run:

```bash
pytest --collect-only -q models/test_initialization.py models/multimodal/processing/test_tensor_schema.py   # before and after
pytest -v -s -rs --durations=0 models/test_initialization.py -k "test_can_initialize_large_subset and (Rnj1ForCausalLM or DeepseekV32MTPModel or MiniCPMV4_7ForConditionalGeneration or K2HorizonForCausalLM or MolmoForCausalLM or PhiForCausalLM)"
pytest -v -s -rs --durations=0 models/multimodal/processing/test_tensor_schema.py -k "MiniMax-M3 or Molmo-7B-O-0924 or MOSS-Transcribe-Diarize or Qwen2-VL-2B"
pre-commit run --files tests/models/utils.py tests/models/test_initialization.py tests/models/multimodal/processing/test_tensor_schema.py
```

| Check | Before (main) | After (this PR) |
|---|---|---|
| Collected test IDs (both modules) | 597 | the same 597 |
| init: 4 not available online + 1 transformers version | `call` 9.6-10.6 s each, skipped | skipped at collection, no `call` |

The init "before" total includes a one-off 152 s memory-settle wait after one case; the per-case `call` times are the like-for-like comparison. Skip reasons in `-rs` match main ("Model is not available online", "`transformers==…` installed, but `transformers<=4.48` is required…"). This PR was also run together with #65441: both modules passed.

CI coverage: the changed modules run in Basic Models (Initialization), Basic Models (Extra Initialization) and Multimodal Processor on NVIDIA and their AMD mirrors, and in the Intel XPU jobs (which select or deselect cases by ID; IDs are unchanged). No model output changes, so no model evaluation applies.

## Details

- `skip_unavailable_models(ids, get_info)` in `tests/models/utils.py` returns the parametrize values, as `pytest.param(..., marks=pytest.mark.skip(reason))` for models that are not available online or fail the transformers version check (`check_max_version=False`, `check_version_reason="vllm"`, the arguments both tests already used). Both test modules use it in their `parametrize` lists, and the same checks are removed from the test bodies.
- The checks only read static fields of the test example registry, so evaluating them at import is cheap and safe. Skips that need the model class or the GPU (`does not support tensor schema validation`, device-capability checks) stay in the test.
- On NVIDIA these cases fork instead of spawning, so the saving there is smaller.
- Independent of #65441; the two touch different hunks and merge cleanly in either order.
- Not a duplicate: I searched open PRs for "check_available_online", "test_initialization spawn" and "tensor schema"; none changes where these skips run.
