# [Bugfix][NVFP4] Fix NaN logits and garbage output from uninitialized fused act+quant scales

[Upstream PR](https://github.com/vllm-project/vllm/pull/63382) · state: closed · merged: True

## Original PR description



## Overview

Make the fused `silu_and_mul_nvfp4_quant` kernel initialize the padded entries of the swizzled NVFP4 block-scale buffer, as the unfused `scaled_fp4_quant` kernel already does. Fixes a regression from #53568, which switched the scale allocator to `torch.empty` (previously `torch.zeros`, restored in #45739).

## Claims

- Fixes NaN logits and garbage output (`other other other ...`) on NVFP4 checkpoints, e.g. `nvidia/Llama-3_3-Nemotron-Super-49B-v1_5-NVFP4`.
- Fixes HTTP 400 `Out of range float values are not JSON compliant: nan` on `/v1/chat/completions` with `logprobs`.
- Covers both users of the kernel (the `ActivationQuantFusionPass` and the manual fusion in `fused_act_quant.py`) with no allocator memset.

## Validation

Setup: 8x RTX PRO 4500 (sm120), TP=8, `nvidia/Llama-3_3-Nemotron-Super-49B-v1_5-NVFP4`, FlashInfer-Cutlass NVFP4 linear backend, `fuse_act_quant: True`, built from source with CUDA 13.2.

Repro:

```bash
# 1. Serve (TP=8)
vllm serve nvidia/Llama-3_3-Nemotron-Super-49B-v1_5-NVFP4 \
  --tensor-parallel-size 8 --trust-remote-code \
  --served-model-name nvidia/llama-3.3-nemotron-super-49b-v1.5 --port 8000

# 2. Once the server is up, send 100 chat+logprobs and 100 completions requests
NAME=nvidia/llama-3.3-nemotron-super-49b-v1.5
echo -n "chat:  "; for i in $(seq 1 100); do curl -s -o /tmp/r_chat_$i.json -w '%{http_code}\n' localhost:8000/v1/chat/completions -H 'Content-Type: application/json' -d "{\"model\":\"$NAME\",\"logprobs\":true,\"top_logprobs\":1,\"messages\":[{\"role\":\"system\",\"content\":\"You are a helpful assistant.\"},{\"role\":\"user\",\"content\":\"Hello!\"}],\"max_tokens\":100}"; done | sort | uniq -c | tr '\n' ' '; echo
echo -n "compl: "; for i in $(seq 1 100); do curl -s -o /tmp/r_compl_$i.json -w '%{http_code}\n' localhost:8000/v1/completions -H 'Content-Type: application/json' -d "{\"model\":\"$NAME\",\"prompt\":\"What is the test plan?\",\"logprobs\":2,\"max_tokens\":50,\"temperature\":0}"; done | sort | uniq -c | tr '\n' ' '; echo
echo "nan-errors: $(grep -l 'Out of range float' /tmp/r_*.json | wc -l)"
```

Unit tests: `tests/kernels/quantization/test_silu_mul_nvfp4_quant.py`, 20 passed (12 existing, 8 new).

## Details

The fused `silu_and_mul_nvfp4_quant` kernel only wrote valid rows of the swizzled block-scale buffer, but the NVFP4 GEMM reads the padded entries, so since #53568 switched the allocator to `torch.empty` it consumed stale memory as scales and produced NaN logits. This PR makes the kernel zero the padded scale rows and columns itself (as `scaled_fp4_quant` does) and keeps the allocators as `torch.empty`, so there is no extra memset.
