# [ROCm][CI] Pin Inductor pointwise configs in the MoRIIO dummy-weight P/D test

[Upstream PR](https://github.com/vllm-project/vllm/pull/62280) · state: closed · merged: True

## Original PR description

- Turn off Inductor pointwise autotuning (`triton.autotune_pointwise`) next to deterministic mode in `test_write_dummy_e2e_rocm.py`, and update the comment and docstring that explain why

Since the ROCm 10 image became the default (#58761), the attention-only cases fail with first-token log-prob distances of one or two bf16 steps (0.03-0.14), e.g. https://buildkite.com/vllm/ci/builds/95663. P/D is not involved: two plain direct serves of the same model on the same GPU disagree by the same amount, while each server is bitwise stable across repeats. Inductor's deterministic mode only pins reduction configs and still picks the XBLOCK of pointwise kernels by timing. On ROCm the XBLOCK changes which multiply-adds of the fused QK-norm + RoPE kernel get contracted into FMAs (e.g. 4 unfused packed adds at XBLOCK 1024, none at 4096), and the candidates are within timing noise of each other, so each server ends up with a random config. Pinning every pointwise kernel's config in two fresh processes makes them agree bitwise; flipping only the QK-norm + RoPE kernel's XBLOCK reproduces the CI distances.

With this change the CI-failing `qwen3_dense-TRITON_ATTN-P_FULL_AND_PIECEWISE-D_FULL_AND_PIECEWISE` case passes 10/10 on MI355 with ROCm 10 (distances exactly 0.0, full external prefix-cache hits).

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
