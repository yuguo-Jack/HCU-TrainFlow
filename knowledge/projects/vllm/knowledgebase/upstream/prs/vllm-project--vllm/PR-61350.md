# [ROCm][Bugfix] Run the AITER AR+RMSNorm fallback test on the platform…

[Upstream PR](https://github.com/vllm-project/vllm/pull/61350) · state: closed · merged: True

## Original PR description

`tests/distributed/test_aiter_rms_fallback.py::test_rocm_aiter_gemma_rmsnorm_falls_back_after_allreduce` fails in `:amd: (MI355) Distributed Features`. The test was added yesterday by #58547, together with the fallback it covers.

[The failing job.](https://buildkite.com/vllm/ci/builds/94315/list?jid=01a131ef-a206-418e-b06e-7a6311a6c957&tab=output)

> NotImplementedError: Could not run 'vllm_aiter::fused_add_rms_norm' with arguments from the 'CPU' backend. This could be because the operator doesn't exist for this backend, or was omitted during the selective/custom build process. 'vllm_aiter::fused_add_rms_norm' is only available for these backends: [CUDA, Meta, BackendSelect, ...].

The test builds its tensors on the CPU, while the fallback it exercises leaves Python through `torch.ops.vllm_aiter.fused_add_rms_norm`. That op is registered for the platform's dispatch key alone, which is `CUDA` on a ROCm build, so a CPU tensor has nothing to dispatch to and the test fails before reaching any of its assertions. The two neighbouring tests in `test_quick_all_reduce.py` do pass with CPU tensors, because their path calls into AITER directly with no registered op in between.

Building the tensors on `current_platform.device_type` is enough, which is what 125 other test files already do. The AITER kernel behind the op stays faked, so the test needs neither real hardware nor an AITER install, and it still passes on a CPU only box, where that device and the dispatch key are both CPU. No `skipif` is needed and nothing outside the test changes.

Worth noting that this is not AMD specific. `vllm/kernels/__init__.py` imports the AITER ops unconditionally and the registration does not need AITER installed, so the op exists on NVIDIA builds too and the test would fail there in exactly the same way. It is only ever run in the AMD step, so nobody sees it.

## Test Result

The test passes on MI355, and the two neighbouring tests in `test_quick_all_reduce.py` still pass.
