# [Bugfix][MiniMax-M3] Recover tool-call params when opening tag is elided

[Upstream PR](https://github.com/vllm-project/vllm/pull/61148) · state: open · merged: False

## Original PR description

## Summary

Fixes #52613.

With MiniMax-M3 (`stream: true` + tools), generation halts after the reasoning block closes — empty delta with `finish_reason: stop`, no tool call produced. Non-streaming works fine.

**Root cause:** MiniMax-M3 sometimes elides (skips) the opening tag for a parameter, producing `value]<]minimax[>[</param_name>` instead of `]<]minimax[>[<param_name>value]<]minimax[>[</param_name>`. The parser's `_parse_invoke_params()` expects `ELEMENT_START` at the current position; when it's missing, parsing stops — losing all remaining parameters.

**Fix** (`vllm/parser/minimax_m3.py`): Add `_recover_untagged_param()` that recovers elided-opener parameters by extracting the name from the closing tag. Includes a guard: if a well-formed opening tag appears before the closing tag, recovery is skipped (the text is junk before a valid element, not an elided opener).
