# [Bugfix][MiniMax-M3] Recover tool-call params when opening tag is elided

[Upstream PR](https://github.com/vllm-project/vllm/pull/61148) · state: open · merged: False

## Original PR description

## Summary

- Fixes MiniMax-M3 tool calls losing all parameters when the model elides an opening parameter tag
- `_parse_invoke_params` previously stopped at the first non-element text and returned no parameters; now `_recover_untagged_param` extracts the parameter name from the bare closing tag and treats preceding text as the value
- This allows later well-formed parameter elements to be parsed normally

## Context

After #59743/#59744 removed the Rust parser bridge, the remaining issue is that `_parse_invoke_params` in `vllm/parser/minimax_m3.py` stops at the first malformed element. When the model emits `value]<]minimax[>[</name>` instead of `]<]minimax[>[<name>value]<]minimax[>[</name>`, the parser returns `{}` for arguments, dropping all parameters — including subsequent well-formed ones.

- [ ] Verify well-formed tool call output is unchanged
