# [Qwen4Exp] Remove FlashAttention dependency and standardize QSA naming

[Upstream PR](https://github.com/vllm-project/vllm/pull/64110) · state: closed · merged: True

## Original PR description



## Overview

Decouple Qwen4Exp QSA from FlashAttention backend, implementation, and metadata classes across NVIDIA and AMD. Retain the naming and metadata cleanup that makes indexer ownership explicit and removes redundant per-layer consistency checks.

## Claims

- Remove QSA's direct FlashAttention imports, inheritance, and availability probes while retaining its existing sparse-attention kernels and cache writers.
- Make the distinction between the QSA indexer and main attention explicit and consistent across implementations, warmup, and tests.
- Preserve computation, checkpoint parameter names, cache layouts, and public configuration for valid inputs.
- Retain builder-local validation while removing repeated cross-cache comparisons from forward paths. No performance improvement is claimed.

Continues the QSA/FlashAttention decoupling motivated by [#57395](https://github.com/vllm-project/vllm/pull/57395). Unlike that implementation, this change also replaces FlashAttention metadata/builders and preserves the current AMD FP8 and Octave paths. No overlapping naming-cleanup PR was found in upstream searches on 2026-10-28; related [#58449](https://github.com/vllm-project/vllm/pull/58449) and [#61529](https://github.com/vllm-project/vllm/pull/61529) address separate kernel/cache changes.

## Details

1. **Removing FlashAttention dependency: use generic interfaces and QSA metadata.** QSA already runs its own sparse kernels, so remove FlashAttention inheritance and availability probes. Use `Qwen4ExpQSABackend(AttentionBackend)` / `Qwen4ExpQSAImpl(AttentionImplBase)` and shared `Qwen4ExpQSAMetadata` / `Qwen4ExpQSAMetadataBuilder` containing only batch bounds and cache addresses. Dispatch sparse attention through `forward` and reuse `reshape_and_cache_flash` for cache updates, retaining AMD's Octave writer/workspace setup and CUDA graph and draft-decode support.
2. **Module names: group code by indexer ownership.** Rename the NVIDIA/AMD `indexer_qsa.py` modules to `qsa_indexer.py`, matching the existing QSA indexer ops module. Rename the shared `qsa_cache.py` module to `qsa_indexer.py` because it owns metadata, a builder, a backend, and cache classes. This follows the indexer-centered organization used by GLM5Next's shared and platform implementations, for example [glm5next/nvidia/sparse_indexer.py:24](https://github.com/vllm-project/vllm/blob/main/vllm/models/glm5next/nvidia/sparse_indexer.py#L24). Update imports and the warmup module lookup together so startup continues to find the renamed implementation.

3. **Metadata names: identify the component that consumes them.** Rename `QSAForwardMetadata` / `QSAMetadataBuilder` to `QSAIndexerMetadata` / `QSAIndexerMetadataBuilder`, and change `side_metadata` to `indexer_metadata`. These objects describe indexer cache addressing and selection, while main attention uses separate metadata. The naming follows `MiniMaxM3IndexerMetadata` / `MiniMaxM3IndexerMetadataBuilder` in [minimax_m3/common/indexer.py:186](https://github.com/vllm-project/vllm/blob/main/vllm/models/minimax_m3/common/indexer.py#L186) and [indexer.py:205](https://github.com/vllm-project/vllm/blob/main/vllm/models/minimax_m3/common/indexer.py#L205).

4. **Cache and backend names: describe ownership and stored data.** Rename `_QSAStateCache` / `QSAStateBackend` to `_QSAIndexerCache` / `QSAIndexerBackend`, consistent with `DeepseekV4IndexerCache` in [deepseek_v4/attention.py:886](https://github.com/vllm-project/vllm/blob/main/vllm/models/deepseek_v4/attention.py#L886), `Glm5NextIndexerCache` in [glm5next/common/attention.py:79](https://github.com/vllm-project/vllm/blob/main/vllm/models/glm5next/common/attention.py#L79), and `MiniMaxM3IndexerBackend` in [minimax_m3/common/indexer.py:64](https://github.com/vllm-project/vllm/blob/main/vllm/models/minimax_m3/common/indexer.py#L64). Rename `QSAKeyStateCache` to `QSARawKeyCache` to pair directly with `QSACompressedKeyCache` and distinguish raw keys from compressed keys. Update the internal backend identifier to `QWEN4_EXP_QSA_INDEXER` to match this ownership and remove the duplicated `EXP` segment.

5. **Field comments: make coordinate systems and units explicit.** Document that `logical_positions` uses original-token coordinates, `visible_blocks` counts complete compression groups, `k_work_metadata` contains compression tasks, and `storage_block_size` counts key rows per physical block. These distinctions matter because compressed rows and original tokens have different units. Keep explanations beside their fields, following the approach used for indexer split counts in [minimax_m3/common/indexer.py:193](https://github.com/vllm-project/vllm/blob/main/vllm/models/minimax_m3/common/indexer.py#L193).

6. **Repeated checks: keep validation at the construction boundary.** Remove 32 lines comparing raw/compressed token counts, batch splits, logical positions, and main/indexer token counts. These values derive from the same batch inputs and builder rules, so every layer was repeating the same comparisons. Keep builder-local request-count, token-count, and uniform-decode checks, as well as independent cache-specific block tables and slot mappings. Deliberately inconsistent metadata loses the removed early errors; an independent batch ordering or token-trimming path would require revisiting this assumption. The removed `torch.equal` checks ran only on CPU tensors, so no GPU synchronization reduction is claimed.
