# [CI] Recheck test coverage after shell script edits

[Upstream PR](https://github.com/vllm-project/vllm/pull/65404) · state: open · merged: False

## Original PR description



## Overview

Run test-tethering checks for shell-script edits so removing a script's pytest command cannot silently orphan an unchanged test.

## Claims

- Select `.sh` files in the pre-commit hook and reuse the existing non-strict full scan for those changes.
- Cover scripts under `tests/`, `.buildkite/scripts/`, and `tools/` with real CLI regressions and a check of the configured hook filter.

`--confcutdir=tests/tools` isolates these standalone tooling tests from the root model/GPU fixtures. No model weights, runtime stubs, or serving changes are involved; model evaluation is not applicable.

The full pre-commit run exits 1 on this Windows host because the unchanged `update-dockerfile-graph.sh` shebang uses `/bin/bash`. Running that exact script and filename list with the installed Git Bash exits 0. All other applicable hooks, including mypy, documentation lint, forbidden imports, and the coverage check, pass. Native Linux hook execution has not been run locally.

To reproduce the CLI failure independently of the hook filter, use the current test and hook configuration with `tools/pre_commit/check_test_tethering.py` from the base revision. All three cases fail with:

```text
assert after.returncode == 1
E assert 0 == 1
3 failed, 143 deselected
```

Using the original hook configuration instead fails all three cases at `assert re.search(hook["files"], script_path)`. Calling pre-commit with that original configuration and `--files tools/check_repo.sh` reports `(no files to check)Skipped`.

The active `cpu-multimodal-config` Buildkite job already runs this test file. Its source dependencies now include `.pre-commit-config.yaml` so filter changes run the regression suite.

The human submitter confirmed completing line-by-line review and the relevant test rerun before publication.

## Details

The parser already follows shell scripts referenced by Buildkite jobs, including nested scripts. However, `.pre-commit-config.yaml` only selected test Python files and pipeline/allowlist files, and `_change_set_touches_ci_config()` did not recognize a shell-only change. Both layers therefore needed to change: updating only the hook filter would still select changed-file mode and ignore the unchanged orphaned test.

Any modified `.sh` file now conservatively triggers a full scan because job scripts may live outside `.buildkite/`. This can add scan time to unrelated shell edits; the hook's existing `require_serial` setting ensures one scan per batch. Existing stale allowlist entries remain advisory. Deleted-only scripts, which pre-commit does not pass to filename-filtered hooks, remain outside this fix.

Duplicate-work checks on 2026-11-03 searched open issues/PRs for `tethering`, `tether script`, `check-test-tethering shell`, `tethering full scan`, and the checker filename. No PR implementing this script-only trigger fix was found. Related #64414 restores a CPU test job and changes its lock/allowlist; it does not change the hook filter or CLI scan trigger. This is a CI correctness fix, not a cleanup.
