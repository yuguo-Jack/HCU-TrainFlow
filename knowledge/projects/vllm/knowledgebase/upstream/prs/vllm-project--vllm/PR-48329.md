# [Bugfix] Skip Dynamic SD schedule for autoregressive speculator decode CUDA graphs

[Upstream PR](https://github.com/vllm-project/vllm/pull/48329) · state: closed · merged: False

## Original PR description




## Purpose

Dynamic speculative decoding (DSD) builds multiple target-model decode CUDA graph shapes from `num_speculative_tokens_per_batch_size`. `CudaGraphManager._init_candidates()` is shared by the target model and draft speculators, but the DSD query-length derivation was applied to every manager.

For MTP with `AutoRegressiveSpeculator`, the decode capture manager uses `decode_query_len=1` (one autoregressive draft token per request per step). Reusing the target formula there yields invalid lengths—for example, with `num_speculative_tokens=7` and a schedule entry `K=1`, the derived length becomes `1 + (1 - 7) = -5`. That produces capture descriptors where `num_reqs > num_tokens`, triggering `AssertionError` in `InputBatch.make_dummy()` during speculator CUDA graph capture.

This change limits DSD schedule expansion to managers whose `decode_query_len` exceeds `num_speculative_tokens` (i.e. the target verification manager, where `decode_query_len = K_max + 1`). Draft decode managers keep a fixed `decode_query_len` and are unaffected by the runtime DSD `K` schedule.

Fixes CUDA graph capture failures when serving models like Qwen3.5 with MTP + Dynamic SD on Model Runner V2.
