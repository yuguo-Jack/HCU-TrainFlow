# [Perf][Bugfix] Prefer MNNVL for single-node FlashInfer allreduce again

[Upstream PR](https://github.com/vllm-project/vllm/pull/61989) · state: closed · merged: True

## Original PR description

## Purpose

Fixes a 3-5% decode regression in v0.32.0, caused by #56891.

#56891 changed automatic FlashInfer allreduce selection to use `trtllm` for every node-local process group. Before it, single-node runs used `mnnvl`, falling back to `trtllm` on nodes without NVSwitch multicast. The PR included no perf data, and on single-node NVSwitch systems `trtllm` is slower.

## Evidence

The perf-eval nightlies show a step in the 14 commits between the 2026-10-03 and 2026-10-04 nightlies, and #56891 is the only distributed change among them. Only TP>1 workloads moved:

| workload | before (10-03) | after (10-04 on) |
|---|---|---|
| Qwen3.5-397B NVFP4, 8xB200 | ~5650 tok/s, TPOT 20.8 ms | ~5460 tok/s, TPOT 21.6 ms |
| gpt-oss-120b TP4, H200 (same host) | 10883 tok/s, TPOT 11.20 ms | 10571 tok/s, TPOT 11.54 ms |
| GLM-5.3-Flash TP4, B200 | ~2770 tok/s | ~2650-2720 tok/s |
| MiniMax-M3 TP8, H200 | TPOT 35.9 ms | TPOT 36.8 ms |
| gpt-oss-120b TP1, B200 | unchanged | unchanged |

A/B on the v0.32.0rc2 image with `VLLM_FLASHINFER_ALLREDUCE_BACKEND` forced:

| workload | default (`trtllm`) | `mnnvl` |
|---|---|---|
| Qwen3.5-397B NVFP4, 8xB200, 8k/1k conc 128 | 5462 tok/s, TPOT 21.78 ms | **5728 tok/s, TPOT 20.22 ms** |
| GLM-5.3-Flash TP4, B200, 3 repeats | 2533 / 2753 / 2771 tok/s | **2581 / 2811 / 2845 tok/s** |

## Change

For node-local groups, auto-selection goes back to `mnnvl` with `allow_trtllm_fallback=True`. The existing fallback still builds a `trtllm` workspace when `mnnvl` can't create one (no NVSwitch multicast). Multi-node selection from #56891 is unchanged: `mnnvl` on Blackwell, disabled on Hopper. The unit test's expectations are updated to match.

cc @elvircrn: is there a case where single-node `mnnvl` misbehaved that #56891 was fixing? The PR description only covers the multi-node cases.
