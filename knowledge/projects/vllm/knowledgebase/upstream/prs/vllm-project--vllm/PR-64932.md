# [Bugfix][MoE] Fix MiniMax-M3.1 NVFP4 experts failing to load on Hopper

[Upstream PR](https://github.com/vllm-project/vllm/pull/64932) · state: open · merged: False

## Original PR description

## Overview

MiniMax-M3.1-Flash fails to load on Hopper unless `--moe-backend marlin` is passed:

```
ValueError: Per-token NVFP4 activation scales are not supported by HUMMING.
```

Its NVFP4 experts always declare a per-token FC1 scheme (#64111). On SM90 the auto selection puts Humming first (#56997), and Humming runs NVFP4 experts as W4A16 there. `make_nvfp4_moe_kernel` already drops the per-token metadata for Marlin W4A16. This PR does the same for Humming when its quant config has no activation dtype.

The recipe's Hopper serve command pins `--moe-backend marlin` and already loads. Its Hopper strategy didn't pass that flag, so this PR adds it there, and the Hopper notes now say the experts run as W4A16 on Humming when no MoE backend is given. No open PR or issue covers this.

## Claims

- MiniMax-M3.1-Flash's NVFP4 experts load and run on SM90 with the default MoE backend (Humming W4A16) or an explicit `--moe-backend humming`.
- Configs that loaded before are unchanged. Marlin keeps the same condition, and Humming with quantized activations still raises.

## Validation

New test `tests/kernels/moe/test_minimax_m3_hopper_nvfp4_moe.py`, on 1x H100. It builds the experts the way M3.1 does (`ModelOptMxFp8Config` with NVFP4 MoE, `qat_activation_key=kNvfp4DynamicToken`), loads a random NVFP4 checkpoint, and compares the forward against a dequantized reference. It runs in a new H100 CI step.

A 4-layer cut doesn't produce text (both arms repeat one token), so this run checks real-weight loading and that the two W4A16 backends agree.

Decode on the full layer count, 1x H200 with the MiniMax-M3.1-Flash config cut to one TP8 rank's shapes (8 q heads, 1 KV and index head, FFN widths and vocab / 8, all 60 layers and 128 experts, dummy weights) and the recipe's Hopper flags. ## Details

- `ModelOptMxFp8Config` builds M3.1's experts with the model's `qat_activation_key` (`kNvfp4DynamicToken`) on every platform, so `per_token_activation` is set on Hopper too.
- Humming's quant config has `quant_dtype is None` when it runs A16. For Marlin's NVFP4 config that is the same check as `use_nvfp4_w4a16`.
- With the metadata dropped, the experts take the same Humming W4A16 path other NVFP4 checkpoints use on SM90.
- The ModelOpt NVFP4 `nvfp4_per_token` override doesn't reach this code on Hopper. `ModelOptNvFp4FusedMoE` rejects any backend other than FlashInfer TRTLLM first.
