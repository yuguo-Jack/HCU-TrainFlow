## Original PR description

Fix reasoning parser leaking reasoning content into response after tool results in multi-turn conversations. The parser wasn't properly clearing reasoning state after tool calls. Fixes #39885.

## Code Review

This pull request updates the extract_reasoning_streaming function to handle scenarios where an end token is split across chunks or followed by extra content. However, the implementation contains a data loss bug because it discards text appearing before the end token in the current delta and lacks error handling for when the end token string is not found. Furthermore, the logic for tracking reasoning state needs refinement to prevent content leakage in multi-turn conversations.

The current implementation of the fix for redundant or split end tokens introduces a data loss bug. When `self.end_token_id` is found in `delta_token_ids`, the code extracts only the content *after* the end token string in `delta_text`, effectively discarding any text that preceded it in the same delta (e.g., in `"some content</think>more content"`, `"some content"` is lost). Additionally, if `self.end_token` is not found in `delta_text` (which can happen with certain tokenizers even if the ID is present), `find` returns -1, leading to incorrect slicing.

Furthermore, this change does not appear to address the root cause of reasoning leakage in multi-turn conversations. Since `self.end_token_id in previous_token_ids` remains true for all subsequent turns after the first reasoning block, the condition at line 130 will be true for all subsequent turns, causing any new reasoning content (e.g., in Turn 2) to be treated as regular content at line 139. A more robust fix would involve checking if the model is *currently* inside a reasoning block by looking at the last marker in the history (e.g., using `self.is_reasoning_end(previous_token_ids)`).

```suggestion
                if self.end_token_id in delta_token_ids:
                    end_index = delta_text.find(self.end_token)
                    if end_index != -1:
                        # Preserve content before and after the end token
                        content = delta_text[:end_index] + delta_text[end_index + len(self.end_token) :]
                        return DeltaMessage(content=content if content else None)
```
