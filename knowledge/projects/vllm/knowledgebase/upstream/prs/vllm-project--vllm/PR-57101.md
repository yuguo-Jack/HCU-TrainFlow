# [Perf] Optimize Molmo2 pooling preparation

[Upstream PR](https://github.com/vllm-project/vllm/pull/57101) · state: closed · merged: True

## Original PR description

### Purpose

Molmo2 pooling currently materializes a tiled batch-index tensor and uses
multi-dimensional advanced indexing before masking invalid patches and reducing
the attention query.

This change keeps the implementation in native PyTorch while reducing that
overhead. It flattens the batch-local patch indices into global row indices,
uses `torch.index_select` for the gather, masks invalid entries in place, and
performs the existing sum/mean query reduction without changing the subsequent
attention, projection, or token filtering behavior.

No Triton kernel or custom-op dispatch is added, so there is no extra JIT
startup cost or platform-specific fallback path.

### Tests and validation

Pooling coverage is consolidated into the existing
`tests/models/multimodal/processing/test_molmo2.py` suite. Two parametrized
cases exercise `Molmo2VisionBackbone.forward` with lightweight substitutes
for the encoder and learned layers, checking masked and ordinary means,
partially/all-invalid groups, repeated indices, cross-batch indexing, attention
masks, and invalid-group filtering against explicit expected values.

The standalone 228-line pooling test file and benchmark script have been
removed. The pooling implementation is unchanged by this review follow-up.

Agent-run on macOS 15.1 ARM64, Python 3.12.13 and PyTorch 2.14.0, from the
PR worktree using the parent checkout's virtual environment:

The suite uses the existing `skip_global_cleanup` marker because these CPU

`empty_host_cache` teardown crash in the local environment.

### RTX 4090 Microbenchmark (historical)

The script is preserved at [the pre-follow-up commit](https://github.com/Levius-Fubuki/vllm/blob/e26ed1564398652949f446d78fa252eac26b40a2/benchmarks/kernels/benchmark_molmo2_pooling.py); the command below refers to that version. These measurements were not rerun for this test-only follow-up.

```bash
VLLM_TARGET_DEVICE=cpu python benchmarks/kernels/benchmark_molmo2_pooling.py \
  --batch-sizes 1 2 \
  --dtypes float16 bfloat16 \
  --warmup 50 --repeats 200 --trials 10
```

Hardware/software: NVIDIA RTX 4090, PyTorch 2.12.1+cu130, Triton 3.7.1.

The benchmark compares the exact upstream native preparation path against the
optimized native helper. Across 24 image/video rows, every measured case
improved. The geometric-mean speedup was 1.29x, with a range of 1.06x--1.50x.

| B | kind | dtype | groups | Upstream median / IQR (us) | Optimized median / IQR (us) | Speedup |
|---:|:---|:---:|---:|---:|---:|---:|
| 1 | image K=4 | FP16 | 550 | 165.55 / 0.17 | 118.42 / 0.34 | 1.40x |
| 1 | video K=9 | FP16 | 256 | 175.82 / 13.33 | 117.49 / 0.82 | 1.50x |
| 1 | video K=9 | BF16 | 4096 | 991.10 / 0.44 | 927.38 / 0.53 | 1.07x |
| 2 | video K=9 | FP16 | 4096 | 1954.28 / 5.32 | 1830.80 / 0.18 | 1.07x |


### Limitations

The performance measurements isolate pooling preparation rather than full-model
end-to-end latency. This follow-up was validated against the PR source with local
Python dependencies and no built vLLM native extensions. CUDA tests, full-model
evaluation and benchmarks were not rerun; GPU evidence above is historical.
The new validation results are agent-run, not human-run.
