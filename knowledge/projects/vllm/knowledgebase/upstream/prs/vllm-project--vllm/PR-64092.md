# [Bugfix] Swap ipc_cache tensors into meta placeholders in place

[Upstream PR](https://github.com/vllm-project/vllm/pull/64092) · state: open · merged: False

## Original PR description

## Summary

`--load-format ipc_cache` left MoE routers on **meta** placeholders. `IpcModelLoader._apply_entries` used to `pop` + `register_parameter` a *new* `nn.Parameter`, so objects that captured the placeholder during construction (e.g. routers holding `gate.e_score_correction_bias`) kept pointing at the meta tensor → illegal memory access / meta-tensor errors at runtime.

This PR swaps cached weights **into the existing placeholder** with `torch.utils.swap_tensors`, preserving object identity for every captured reference.

Credit to @nealvaidya for the diagnosis and proposed approach in #62105. Prior attempt #62115 was closed without merge (deferred to the reporter).

Supporting changes:

- **Buffers before parameters** — stable sort so views like `MambaMixer2.conv_weights` are replaced before param swap (avoids `swap_tensors` use-count failures).
- **Tied-weight aliases** — re-point only; never swap alias placeholders into the canonical tensor.
- Post-quantization tensors still absent from the meta model keep the register path.

Fixes #62105

## Reproduction

From #62105 (needs a single GPU > 80 GB; tested there on an H200). Start the daemon:

```bash
vllm preload --model nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16 \
    --enforce-eager --max-model-len 4096
```

Then load through the cache with fallback disabled:

```python
import os
os.environ["VLLM_ENABLE_V1_MULTIPROCESSING"] = "0"
from vllm import LLM, SamplingParams

llm = LLM(
    model="nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16",
    load_format="ipc_cache", model_loader_extra_config={"fallback": False},
    enforce_eager=True, max_model_len=4096, max_num_seqs=1, gpu_memory_utilization=0.5,
)
out = llm.generate(["The capital of France is"], SamplingParams(temperature=0, max_tokens=24))
print(repr(out[0].outputs[0].text))
```

Before this PR: `RuntimeError: Triton Error [CUDA]: an illegal memory access was encountered` and the process aborts (exit 134). `LiquidAI/LFM2-8B-A1B` (~17 GB) reproduces the same way on smaller GPUs.

## Testing

```bash
pytest tests/model_executor/model_loader/test_ipc_loader.py -v
```

**Result:** 5 passed (CPU-only; no GPU / no IPC daemon). Coverage: router identity after swap, buffer-before-param ordering, tied-weight aliases, post-quant new tensors, no residual meta tensors.

**Note:** the fix is covered by the CPU unit tests above; I have not yet done a GPU end-to-end run of the reproduction.
