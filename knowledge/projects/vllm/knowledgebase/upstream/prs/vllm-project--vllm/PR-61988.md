# [Bugfix][KV Offload] Scope async lookup verdicts per request

## Overview

Fix async KV offload lookup consistency when multiple requests share one
lookup generation. This is implemented on top of [#61717](https://github.com/vllm-project/vllm/pull/61717)
and adds generation-aware, request-scoped `mark_miss` handling.

**Dependency:** This PR depends on #61717 and must be merged after #61717.
This is the updated implementation of #61988; #61717 provides new-request
reprobes, while this PR isolates failed-load corrections to the request that
experienced them.

Compared with #61754, the failed-load correction still preserves the
request-specific `MARKED_MISS` state and additionally carries the request and
generation through the load job, so an old completion cannot affect another
request.

## Claims

- A failed promotion changes only the originating request's lookup verdict.
- A stale load completion cannot modify a newer lookup generation.
- Submission lifecycle and per-request result state are represented separately.
- `request_statuses` is the only result source of truth.

## Trigger

Requests A and B can share a resolved `HIT`. If A's promotion fails after the
shared lookup is resolved, a key-only `mark_miss()` can incorrectly change B's
result or update a newer generation.

## Behavior

```text
Before:  A HIT, B HIT -> mark_miss(key) -> A/B MISS
After:   A HIT, B HIT -> mark_miss(A token) -> A MARKED_MISS, B HIT
```

The token contains `(key, req_id, generation)`. A stale token is ignored. The
marked state remains indexed until a new request observes its
`MARKED_MISS` status and replaces it with a fresh generation; existing requests
retain their own results. Promotion jobs must have a resolved lookup token;
missing tokens are treated as a caller error rather than silently skipping the
correction. The promotion itself may remain in flight after the lookup has
resolved; its later failure is applied through that token.

## Details

### Data structure

```python
_current_state_by_key: dict[OffloadKey, LookupState]
_request_states: dict[str, dict[OffloadKey, LookupState]]  # reverse index

@dataclass
class LookupState:
    generation: int
    submission_status: LookupSubmissionStatus
    request_statuses: dict[str, LookupResultStatus]
```

`request_statuses` is the only result source of truth. The reverse
`_request_states` index stores state identity so cleanup and stale tokens can
find an older generation after the current-key index has advanced.
