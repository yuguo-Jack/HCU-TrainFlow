# [Spec Decode] Fuse the DSpark draft prologue into fewer kernels

## Motivation

A torch-profiler trace of the five-PR stack (campaign
dsv41-pd-fusions-prof-002, 8xH200 PD decode, c16, MTP 3) also
covers the DSpark draft graph: its FULL-cudagraph prologue spends
~105 us of in-graph GPU per decode step before the draft layers.
Three items in it are removable work; this PR carries them,
cutting ~35 us and 6 launches per step.

## One merged context_wkv_proj GEMM

The context-KV precompute ran one `fused_wqa_wkv` GEMM
([T,5120]x[5120,1792]) per draft layer and discarded the q_lora
half of each output — only the 512-wide WKV rows were consumed, so
1280 of 1792 output rows per layer were dead compute (~26 us across
the three GEMMs). A merged `context_wkv_proj`
([T,5120]x[5120,1536]) now projects every layer's WKV in one GEMM,
and `precompute_and_store_context_kv` slices the stacked output per
layer. Weight loading duplicates each `mtp.{i}.attn.wkv` shard into
the merged projection with the layer index as shard id, mirroring
the DeepSeek V4 dspark implementation that already ships this
pattern. The 512-wide output sections keep the fp8 block-quant
shards 128-aligned, so quantization is unchanged.

## kv_norm folded into the KV rope/insert kernel

The per-layer kv_norm RMSNorm ran as a separate kernel on the
projected KV before the rope/quantize/insert op, with a copy in
between for the strided slice. `fused_deepseek_v4_kv_rope_insert`
now takes the norm weight and a row-strided KV view (plus the
row stride), so the projection output slice is normalized, roped,
quantized and inserted into the cache with no intermediate kernels
— V4 still norms outside its dummy-q insert. The warp-shuffle
reduction order differs from torch's, so the kernel test asserts
against the fp8 code granularity (one code of slack on the NoPE
half, 2 bf16 ULP after RoPE).

## 2D broadcast entry into draft layer 0

The draft entered layer 0 by repeating the 2D embedding to
[24,20480] for the full `hc_attn_fn` matrix multiply, then summing
the identical hc copies back. The target's entry layer already has
the broadcast form: `hc_attn_fn_broadcast` ([24,5120]) applied to
the 2D input, with the summed weight finalized once after load. The
draft now uses the same path — `finalize_mhc_broadcast_weights` runs
on the draft's `process_weights_after_loading`, since the draft
loads outside the target's finalize. Mathematically identical: the
column-block sum of identical copies, with the same RMS mean.

## Tests

- `test_dsv41_context_wkv_weights_are_duplicated_by_draft_layer` —
  shard ids and storage identity of the duplicated WKV weights.
- `test_dsv41_context_kv_uses_one_stacked_wkv_projection` — one
  projection call, per-layer slices inserted with their slot
  mappings.
- `test_dsv41_draft_entry_finalizes_broadcast_mhc_weights` — the
  broadcast weight equals the hc-sum of the full matrix.
- `test_kv_insert_fused_norm_row_strided` — the fused-norm insert
  against a torch RMSNorm + rope + quantize reference, parametrized
  over token counts, block sizes and row widths.
- `test_v41_dspark_loads_linear_scales` extended: WKV scales also
  load into the merged projection as shard 0.
