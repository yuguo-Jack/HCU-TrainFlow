# [Perf] Emit the DSA indexer weights in BF16 on SM100

[Upstream PR](https://github.com/vllm-project/vllm/pull/62170) · state: open · merged: False

<!-- markdownlint-disable -->

## Overview

On SM100, `fused_q` now writes the DSA indexer weights directly in BF16, the dtype DeepGEMM's MQA logits kernels
take. This removes the FP32 to BF16 copy `mqa_logits_mx_inputs` launched on every indexer call.

## Claims

- InferenceX AgentX, GLM-5.3-NVFP4 on 4x GB200: together with #62171 and #62172, decode time per turn
  drops 2.8%, 2.5%, 1.5% and 1.5% at concurrency 1, 4, 8 and 16 (main vs main: within 0.7%). This PR is
  about 1/6 of that.
- One fewer kernel per indexer call (prefill chunks and decode) on SM100/SM103 for DSA models using `fused_q`
  (DeepSeek-V3.2, GLM-5.x).
- No precision change. The SM100 logits kernels only take BF16 weights, so main already rounds them to BF16 with a
  separate `.to(torch.bfloat16)` in [`mqa_logits_mx_inputs`](https://github.com/vllm-project/vllm/blob/c50aca14416ef29f6ed0ed256302f30646726dcd/vllm/utils/deep_gemm.py#L635). `fused_q` now
  does that rounding in its store, and the kernels get bit-identical weights.
- Other platforms are unchanged (FP32 weights).

## Details

`mqa_logits_use_mx_scales()` already decides that the SM100 logits kernels take BF16 weights, and
`mqa_logits_mx_inputs` returned `weights.to(torch.bfloat16)`. That was a real copy kernel for every indexer call,
since `fused_q` (Triton and CuTeDSL) always wrote FP32. `fused_q` now allocates its weights output in the dtype the
logits kernels take, and both kernels cast on store. `.to(torch.bfloat16)` then returns the tensor as-is.

The CuTeDSL kernel's compile key gains the output dtype.
