## Original PR description

## Overview

Add the opt-in `mi355x_agentx_tp8` preset to the DeepSeek-V4.1-Flash recipe: the TP8, concurrency-1 AgentX point from [InferenceX #4666](https://github.com/SemiAnalysisAI/InferenceX/pull/4666), served with `--monokernel` on a nightly that carries [#64101](https://github.com/vllm-project/vllm/pull/64101) (mono decode at TP8 on MI355X).

## Claims

- Adds one preset with one point (concurrency 1, TP8) for MI355X, pinned to `vllm/vllm-openai-rocm:nightly-335dd77b09161c5d63139b4e7ae51bb9928305b1@sha256:3c634cc2…7291`.
- The generated command carries the same serving flags as the InferenceX run; the TP8 point keeps `--monokernel` and GPU-resident Engram tables (`cpu_offload: false`), with one sequence at a time and 32768-token prefill chunks, as the TP4 concurrency-1 point does.
- The runbook documents that TP8 mono is a concurrency-1 configuration and needs a build with #64101.
- No existing rendering changes.

## Details

**Not a duplicate.** I found no open or merged PR that adds a TP8 preset for this recipe; #63665, #63344 and #63560 cover the TP2/TP4 `mi355x_agentx` preset, and #64589 adds an unrelated MI325X preset. This preset is separate from `mi355x_agentx` because `source` (InferenceX key and revision) is per preset, and this lane has its own key, revision and image pin.

**Limits.** #64101 validated TP8 mono with six DSpark drafts; this lane runs five (the recipe's value), measured by the InferenceX run above. The preset makes no claim beyond concurrency 1. The `mi355x_agentx` preset is untouched.

The preset is placed at the end of the presets block, away from the MI325X preset proposed in #64589, to avoid a textual conflict between the two.

AI assistance was used (Claude Sonnet 5.5, `claude-sonnet-5-5`, via Claude Code): it drafted the preset, ran the validation above and compared the rendered command with the InferenceX job log. The submitter reviewed the changes.
