# [Doc][ROCm] Update DeepSeek-V4.1-Flash MI355X AgentX scheduling profiles

[Upstream PR](https://github.com/vllm-project/vllm/pull/63665) · state: closed · merged: True

## Original PR description

## Overview

Align the existing DeepSeek-V4.1-Flash MI355X AgentX preset with [InferenceX #4480](https://github.com/SemiAnalysisAI/InferenceX/pull/4480), extending the [#4409 profiles](https://github.com/vllm-project/vllm/pull/63344) now represented as tuned presets by [#63560](https://github.com/vllm-project/vllm/pull/63560).

**Ready for review. Merge dependency:** resolve the source PR's [OperatorX capture-selection finding](https://github.com/SemiAnalysisAI/InferenceX/pull/4480#discussion_r4369225363), then re-freeze #4480 and confirm these profile values before merging this recipe update. The finding remains reproducible at the audited source head.

## Claims

Only `recipes/models/deepseek-ai/DeepSeek-V4.1-Flash.yaml` changes. The six low-concurrency points gain the exact source scheduling limits:

| Points | Max sequences | Batched tokens | Graph capture maximum |
| --- | ---: | ---: | ---: |
| TP4 c1/c2; TP2 c1/c2/c4 | 1 | 32768 | 8 |
| TP2 c8 | 2 | 8192 | 16 |

TP2 c16/c32 retain sequence caps 4/8 and 8192-token budgets; c64 keeps `max-num-seqs` unset (the engine default) and its 16384-token budget. All three retain capture 1024. Baseline commands, other hardware/presets, the pinned image, model/draft configuration and quantization remain unchanged.

The preset keeps real block rejection. Synthetic acceptance remains a throughput-only qualification method. These workload-specific caps target interactivity and can increase queueing, TTFT or end-to-end latency; no throughput gain is claimed.
