# [MM][CG] Support ViT full CUDA graph for DeepSeek-VL2

[Upstream PR](https://github.com/vllm-project/vllm/pull/46005) · state: closed · merged: True

## Original PR description

## Purpose

Support ViT full CUDA graph capture/replay for DeepSeek-VL2, as tracked in #38175.

Previously, `DeepseekVLV2ForCausalLM` ran vision encoding (SigLIP ViT + MLP
projector) eagerly on every forward pass, incurring repeated CPU kernel-dispatch
overhead. This PR implements the `SupportsEncoderCudaGraph` protocol so
`EncoderCudaGraphManager` can capture the ViT + projector forward pass once and
replay it, eliminating that overhead for batches that fit within a captured
budget.

**Key design decisions:**
- `encoder_cudagraph_forward` returns raw per-tile projector output
  `[N_tiles, hw, D]`; newline tokens and the view-separator are reattached in
  `postprocess_encoder_output` (outside the graph), keeping the captured
  computation simple and shape-static.
- `encoder_eager_forward` calls the existing `_pixel_values_to_embedding` and
  returns a flat `[total_tokens, D]` tensor, matching what `scatter_output_slices`
  expects in the eager-fallback path.
- `_proj_hw()` derives projector output spatial size from config
  (`ceil((image_size // patch_size) / downsample_ratio)`), consistent with the
  token-count formula in `DeepseekVL2ProcessingInfo.get_num_image_tokens`.

- littlecircle0730 · comment · 2026-09-28T06:57:56Z · [source](https://github.com/vllm-project/vllm/pull/46005#discussion_r4119372266)

File: `vllm/model_executor/models/deepseek_vl2.py` · line None

Thanks for the suggestion. 

For DeepSeek-VL2, global and local tiles use the same `vision_config.image_size` and are processed by the same vision encoder. Upstream DSVL2 concatenates all global/local tiles along the batch dimension and runs them together through a single `self.vision(total_tiles)` call. For a valid image, there is also always at least one local tile.

Because the per-tile input shape and encoder computation are identical, the current implementation represents the dynamic number of global/local tiles as a dynamic tile batch (`N_tiles`) rather than separate encoder paths.

Ref:
https://github.com/deepseek-ai/DeepSeek-VL2/blob/main/deepseek_vl2/models/modeling_deepseek_vl_v2.py

Would you still prefer using the multi-path CG abstraction here for consistency with the framework, even though both paths would have the same input shape/computation?
