# [Perf][NIXL] Fuse cached-block counting and pull block-ID collection

[Upstream PR](https://github.com/vllm-project/vllm/pull/63933) · state: open · merged: False

## Original PR description

## Overview
Collect NIXL pull block IDs and per-group cached-block counts in one admission traversal, using the existing null-prefix trimming helper.

## Claims
Preserve interior-null filtering, interleaved hashes, DCP offsets, transfer-group clipping and empty transfers for full local hits. Reduce scheduler CPU work; no end-to-end throughput or TTFT gain is claimed.

## Validation

The existing per-group regression now covers a long null prefix and no-transfer admission with real scheduler construction. Whole-diff pre-commit including mypy passed.

Earlier CPython 3.12 admission microbenchmark: 100 warmups, 8 alternating rounds, 400 calls/long case. A 128K-equivalent layout (1,000 hashed full-attention blocks plus eight null-prefixed sliding-window groups) measured **1,609 → 153 µs** for the complete admission callback; 32K measured **431 → 50 µs**. Production matches that measurement. Earlier differential and synthetic NIXL P/D correctness checks passed; no fresh GPU/performance run this round.

## Details
D allocates blocks, this callback produces pull IDs and cached counts, then the existing transfer/release protocol runs. No persistent cache or switch is added. This follows merged #61724; #55374 addresses piecewise loading. AI assistance was used for implementation and validation.
