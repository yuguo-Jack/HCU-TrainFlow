# [Rust Frontend] Accept null for nullable request booleans

[Upstream PR](https://github.com/vllm-project/vllm/pull/62662) · state: closed · merged: True

## Original PR description

## Overview

Python declares several request booleans as `bool | None`, so an explicit `null` validates and behaves like omission. The Rust frontend declares them as plain `bool` and returns 400 ("invalid type: null, expected a boolean"). This PR accepts `null` for exactly those fields, and resolves the `watermarking` default once in the text layer, as Python's `SamplingParams` does.

## Claims

- `null` now means the same as omission for chat `logprobs`, `stream`, `watermarking`; completions `echo`, `stream`, `watermarking`; generate `stream` and `sampling_params.watermarking`; and `/tokenize` `return_token_strs` (prompt and messages bodies).
- `watermarking: null` keeps watermarking on, as in Python, where `None` requests it.
- Booleans Python declares as plain `bool` (`ignore_eos`, `skip_special_tokens`, `add_special_tokens`, ...) still reject `null` on both frontends.

- `openai_watermarking_defaults_and_opt_out_reach_engine_core` gains a `null` case: chat and completions, streaming and not, reach the engine with watermarking on.
- Generate `prepare_generate_request_preserves_watermarking_defaults_and_opt_out` gains a `null` case.

All fail on the base.

## Details

Each DTO field's Rust shape follows its Python declaration, so there is one form per case:

| Python declaration | Rust field | `null` |
|---|---|---|
| `T \| None = None` | `Option<T>`; the owner of the `None` meaning resolves it | same as absent |
| `T = d` (not nullable) | `T` with `#[serde(default)]` or `default = "default_true"` | 400, like Python |
| `bool \| None = False` | `bool` with `#[serde(default)]` + `serde_with::DefaultOnNull` | `false` |

`null` handling is a wire-format concern, so it stays on the route-owned DTOs. `watermarking` is `bool | None` on both Python's request and its `SamplingParams`, where `None` means enabled, so it becomes `Option<bool>` through `vllm_text::SamplingParams` and `lower_sampling_params` resolves `None` to `true` in one place. Previously chat, completions and gRPC each resolved it, and generate relied on `SamplingParams::default()` and rejected `null`. `DefaultOnNull` would have turned `watermarking: null` into `false` and silently opted the request out.

Not a duplicate: no open upstream PR changes `null` handling on these Rust DTOs.
