# [Attention] Run SM90 FP8-KV attention on FA4 native FP8

[Upstream PR](https://github.com/vllm-project/vllm/pull/63139) · state: open · merged: False

## Original PR description

## Overview

On SM90 with an FP8 KV cache, this PR runs attention on FA4's native FP8 forward from vllm-project/flash-attention#206, which computes attention on E4M3 Q/K/V with FP8 WGMMA:
- **FA3 → FA4 upgrade.** `get_flash_attn_version` upgrades FA3 to FA4 on SM90 when the KV cache is FP8 E4M3 and FA4 supports the head size: 64, 96, 128, 192 or 256, with the same V head size, no softcap and no batch invariance. An explicitly set `flash_attn_version` is kept.
- **Gemma4 on FA4 for all layers.** With an FP8 KV cache on SM90, `main` runs Gemma4's sliding-window layers on FA3 and its full-attention layers on FA4. This PR uses FA4 for all layers, as Gemma4 already does in other configurations:
  - **Sliding-window layers (head dim 256)** quantize Q to FP8, as FA3 does, and run FA4's native FP8 forward.
  - **Full-attention layers (head dim 512)** keep FA4's FP8-KV dequant forward with BF16 Q, as on `main`.
- The FlashAttention metadata builder takes `aot_schedule` from the layer's FlashAttention version instead of the global one.
- **DFlash/DSpark drafters with head dim 512.** `AttentionGroup.update_draft_decode_metadata()` now maps the block table to FA4's 64-token kernel blocks, so FULL CUDA graph draft replays no longer read a stale kernel block table; on gemma-4-12B-it with the [`deepseek-ai/dspark_gemma4_12b_block7`](https://huggingface.co/deepseek-ai/dspark_gemma4_12b_block7) DSpark drafter, acceptance length goes from 1.02 to 2.05.

The FlashAttention pin is bumped once vllm-project/flash-attention#206 merges.

## Claims

- **Faster.** On gemma-4-31B-it-FP8 on H200, output throughput is 1.21x `main` on the `8k-in-1k-out` benchmark of [`gemma_4_31b_it_h200`](https://github.com/vllm-project/perf-eval/blob/main/workloads/gemma_4_31b_it_h200.yaml).
- **Accuracy-neutral.** GPQA Diamond, AIME 2025, MMLU-Pro and GSM8k all match `main` and BF16 within noise.
- **Fixes a TP=4 crash, with #206.** With `main`'s FlashAttention, Gemma4 with FP8 KV at TP=4 fails at startup with `RuntimeError: Expected strides[leading_dim] == 1, but got 0`. The crash is in the d512 FP8-KV dequant path, which `main` and this PR both use; #206 fixes it.

## Validation

**Serving.** The `8k-in-1k-out` benchmark of [`gemma_4_31b_it_h200`](https://github.com/vllm-project/perf-eval/blob/main/workloads/gemma_4_31b_it_h200.yaml) on one H200 at TP=1. `main` is the mean of 4 GPUs and this PR is the median of 3 runs; no request failed.

| | Output tok/s | Mean TPOT (ms) | Median ITL (ms) |
|---|---|---|---|
| `main` | 796.1 | 129.5 | 75.9 |
| This PR | **966.6 (1.21x)** | **106.7** | **51.7** |

**Accuracy.** gemma-4-31B-it-FP8 on 4x H200 at TP=1/DP=4. Sampling is temperature 1.0 and top_p 0.95, with thinking on.

| | GPQA Diamond avg@16 | AIME 2025 avg@64 | MMLU-Pro | GSM8k |
|---|---|---|---|---|
| `main` | 85.54 ± 0.70 | 86.93 ± 0.72 | 86.54 ± 0.31 | 94.01 ± 0.65 |
| This PR | 86.05 ± 0.63 | 87.45 ± 0.68 | 86.19 ± 0.31 | 94.31 ± 0.64 |
| BF16 (model card) | 85.42 | 87.29 | 86.44 | 94.62 |

<details><summary>Reproduce</summary>

Accuracy server. The evals call it directly:
- GPQA Diamond and AIME 2025 use `simple_evals`. The GPQA answer regex also accepts `Answer: $X`. AIME is graded by an LLM judge.
- MMLU-Pro uses `simple_evals` with one pass.
- GSM8k uses `lm-eval` `gsm8k_cot_zeroshot` over chat completions, scored by flexible-extract. The system prompt asks for a final line of `The answer is X`.
- All of them sample with temperature 1.0 and top_p 0.95, with up to 131,072 output tokens.

```bash
vllm serve $MODEL --served-model-name gemma \
  --tensor-parallel-size 1 --data-parallel-size 4 \
  --max-model-len 262144 --max-num-batched-tokens 8192 --enable-chunked-prefill --max-num-seqs 16 \
  --trust-remote-code --kv-cache-dtype fp8 --attention-backend FLASH_ATTN --block-size 64 \
  --hf-overrides '{"text_config":{"use_bidirectional_attention":null}}' \
  --chat-template $THINKING_CHAT_TEMPLATE
```
