# [Perf] Tune the Triton packed GDN decode tile on SM90

[Upstream PR](https://github.com/vllm-project/vllm/pull/63864) · state: closed · merged: True

## Original PR description



## Overview

Use `BV = 4` for the Triton packed GDN decode kernel on SM90 (H100/H200) when the recurrent state is FP32,
the SM90 counterpart of #61355 (SM100). The kernel is unchanged; this adds one dispatch branch.

Not a duplicate: no open PR changes this kernel's SM90 tile (searched open PRs for "packed decode" and
"GDN decode"; #62961 only touches this kernel's tests). Sibling tunings: #61355 (SM100, merged), #61823
(SM89, open), #54181 (SM120, closed).

## Claims

- **1.02–2.16x faster kernel, 1.34x geometric mean** over 99 `(H, HV, batch)` points on H200 with an FP32
  state (cold L2, CUPTI). `BV = 4` is the fastest tile at all 99 points.
- **1.0–1.8% lower decode latency** serving Qwen/Qwen3.8-27B-FP8 (FP32 state is its checkpoint default),
  matching what the kernel saving predicts; throughput within noise.
- Output and updated recurrent state are **bitwise identical** to `BV = 32` at every measured point.
  BF16 state is unchanged.

## Validation

### Kernel (cold L2)

H200 NVL (132 SMs, 60 MiB L2), `K = V = 128`, BF16 qkv, QK L2-norm on. Each CUDA graph cycles through
enough disjoint state slots that the state touched between two uses of a slot is >= 4x L2 (240 MiB), so
the state is never L2-resident, as in a decode step. Kernel time from CUPTI (`torch.profiler`) over graph
replays; 7 rounds with the tile order shuffled each round, median reported (round-to-round spread <= 1.8%).
Speedup of `BV = 4` over `BV = 32`, FP32 state:

state).

### End to end

Qwen/Qwen3.8-27B-FP8 (48 GDN layers), vLLM 0.32.0 with this rule applied, H200 NVL, `vllm bench serve`,
random 1024 in / 128 out, prefix caching off, `max_num_seqs 64`; unpatched and patched interleaved,
2 runs each (mean):

| concurrency | metric | unpatched | patched | change | predicted from kernel |
|---|---|---|---|---|---|
| 1 | median TPOT | 10.78 ms | 10.65 ms | −1.2% | −1.2% |
| 8 | median ITL | 11.72 ms | 11.51 ms | −1.8% | −1.8% |
| 32 | median ITL | 14.60 ms | 14.45 ms | −1.0% | −1.4% |
| 1 / 8 / 32 | output tok/s | 86.1 / 503.7 / 1085.6 | 86.6 / 508.4 / 1088.0 | +0.5 / +0.9 / +0.2% | |

"Predicted" is the per-call kernel saving at that batch x 48 layers over the step time. The kernel is 3%
of a step at batch 1 and 19% at batch 32.

<summary>Microbenchmark script</summary>

```python
"""Packed GDN decode kernel (vLLM's Triton fused_recurrent_gated_delta_rule_packed_decode), cold L2:
time per call for each value-tile size BV, batch size and (H, HV) head layout, FP32 and BF16 state.

The wrapper is vLLM's own, with its fixed `BV = min(next_power_of_2(V), 32)` line replaced by a module
variable. Each CUDA graph cycles through enough disjoint state-slot sets that the state touched between
two uses of the same slot is at least 4x the L2 (a decode step touches each sequence's state once).
State slot 0 is the kernel's null slot (skipped), so real slots start at 1. Output and updated state
are compared bitwise with BV=32 at every point. Kernel time comes from CUPTI (torch.profiler) over graph
replays; CUDA-event time per call (which includes the gaps between graph nodes) is recorded too.
BV order is shuffled in each of ROUNDS rounds; reported values are medians over rounds.
usage: gdn_decode_bv_cold.py <out.json>
"""
import inspect, json, math, random, statistics, sys
import torch
from torch.profiler import profile, ProfilerActivity
from vllm.third_party.flash_linear_attention.ops import fused_recurrent as fr

src = inspect.getsource(fr.fused_recurrent_gated_delta_rule_packed_decode)
needle = 'BV = min(triton.next_power_of_2(V), 32)'
assert src.count(needle) == 1
ns = dict(fr.__dict__)
exec(compile(src.replace(needle, 'BV = _BV'), '<packed-decode-bv>', 'exec'), ns)
wrapper = ns['fused_recurrent_gated_delta_rule_packed_decode']

LAYOUTS = [(16, 48), (8, 24), (4, 12), (2, 6),      # HV/H = 3 (Qwen3.8-27B at TP1/2/4/8)
           (16, 32), (8, 16), (4, 8), (2, 4),       # HV/H = 2
           (16, 64), (8, 32), (4, 16)]              # HV/H = 4
BATCHES = [1, 2, 4, 8, 16, 32, 64, 128, 256]
BVS = [4, 8, 16, 32]
if __import__('os').environ.get('GDN_QUICK'):
    LAYOUTS, BATCHES = [(16, 48), (2, 6)], [1, 64]
K = V = 128
ROUNDS = 7
EVENT_REPS = 10
CUPTI_REPS = 3
dev = 'cuda'
props = torch.cuda.get_device_properties(0)
L2 = props.L2_cache_size
FOOTPRINT = 4 * L2
torch.manual_seed(0)
random.seed(0)
print('DEVICE', torch.cuda.get_device_name(), 'SMs', props.multi_processor_count, 'L2', L2, flush=True)


def kernel_us(g, sets):
    """Mean CUPTI duration of one packed-decode kernel over CUPTI_REPS graph replays."""
    torch.cuda.synchronize()
    with profile(activities=[ProfilerActivity.CUDA]) as prof:
        for _ in range(CUPTI_REPS):
            g.replay()
        torch.cuda.synchronize()
    durs = [e.device_time for e in prof.events()
            if 'packed_decode' in e.name and e.device_type == torch.autograd.DeviceType.CUDA]
    if not durs:
        durs = [e.cuda_time for e in prof.events() if 'packed_decode' in e.name and e.cuda_time > 0]
    return (sum(durs) / len(durs), len(durs)) if durs else (None, 0)


def event_us(g, sets):
    us = []
    for _ in range(EVENT_REPS):
        e0, e1 = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
        e0.record(); g.replay(); e1.record(); e1.synchronize()
        us.append(e0.elapsed_time(e1) * 1000 / sets)
    return statistics.median(us)


rows = []
for state_dtype in (torch.float32, torch.bfloat16):
    for H, HV in LAYOUTS:
        A_log = torch.randn(HV, device=dev, dtype=torch.float32) * 0.1
        dt_bias = torch.randn(HV, device=dev, dtype=torch.float32) * 0.1
        for B in BATCHES:
            elsize = torch.empty((), dtype=state_dtype).element_size()
            set_bytes = B * HV * V * K * elsize
            sets = max(2, math.ceil(FOOTPRINT / set_bytes))
            pool = torch.randn(1 + B * sets, HV, V, K, device=dev, dtype=torch.float32).mul_(0.02).to(state_dtype)
            pristine = pool[:1 + B].clone()   # slot 0 (null) + set 0; timing updates `pool` in place
            qkv = torch.randn(B, 2 * H * K + HV * V, device=dev, dtype=torch.bfloat16)
            a = torch.randn(B, HV, device=dev, dtype=torch.bfloat16)
            b = torch.randn(B, HV, device=dev, dtype=torch.bfloat16)
            idx = [torch.arange(1 + s * B, 1 + (s + 1) * B, device=dev, dtype=torch.int32) for s in range(sets)]
            out = torch.empty(B, 1, HV, V, device=dev, dtype=torch.bfloat16)
            real = torch.arange(1, 1 + B, device=dev, dtype=torch.int32)
            res, graphs = {}, {}
            for bv in BVS:
                ns['_BV'] = bv
                st = pristine.clone()
                wrapper(qkv, a, b, A_log, dt_bias, K ** -0.5, st, out, real, True)
                res[bv] = dict(out=out.clone(), state=st[1:].clone(), ev=[], cu=[])
                def step(bv=bv):
                    ns['_BV'] = bv
                    for s in range(sets):
                        wrapper(qkv, a, b, A_log, dt_bias, K ** -0.5, pool, out, idx[s], True)
                stream = torch.cuda.Stream(); stream.wait_stream(torch.cuda.current_stream())
                with torch.cuda.stream(stream):
                    step()
                torch.cuda.current_stream().wait_stream(stream)
                g = torch.cuda.CUDAGraph()
                with torch.cuda.graph(g):
                    step()
                g.replay()
                graphs[bv] = g
            torch.cuda.synchronize()
            ncupti = {}
            for _ in range(ROUNDS):
                order = BVS[:]
                random.shuffle(order)
                for bv in order:
                    res[bv]['ev'].append(event_us(graphs[bv], sets))
                    cu, n = kernel_us(graphs[bv], sets)
                    ncupti[bv] = n
                    if cu is not None:
                        res[bv]['cu'].append(cu)
            ref = res[32]
            us_ev = {v: round(statistics.median(res[v]['ev']), 3) for v in BVS}
            us_cu = {v: (round(statistics.median(res[v]['cu']), 3) if res[v]['cu'] else None) for v in BVS}
            have_cu = all(us_cu[v] is not None for v in BVS)
            basis = us_cu if have_cu else us_ev
            row = dict(state=str(state_dtype).split('.')[-1], H=H, HV=HV, B=B,
                       sets=sets, footprint_MB=round(sets * set_bytes / 2**20, 1), L2_MB=round(L2 / 2**20, 1),
                       us_cupti=us_cu, us_event=us_ev, cupti_kernels_per_bv=ncupti,
                       speedup_bv4_cupti=(round(us_cu[32] / us_cu[4], 3) if have_cu else None),
                       speedup_bv4_event=round(us_ev[32] / us_ev[4], 3),
                       best_bv=min(BVS, key=lambda v: basis[v]),
                       round_spread_bv4_cupti=(round((max(res[4]['cu']) - min(res[4]['cu'])) / us_cu[4], 3) if have_cu else None),
                       out_abs_max=float(ref['out'].float().abs().max()),
                       out_nonzero_rows=int((ref['out'].float().abs().amax(dim=(1, 2, 3)) > 0).sum()),
                       bitwise_out={v: bool(torch.equal(res[v]['out'], ref['out'])) for v in BVS},
                       bitwise_state={v: bool(torch.equal(res[v]['state'], ref['state'])) for v in BVS})
            rows.append(row)
            print('ROW', json.dumps(row), flush=True)
            del graphs, pool, res
            torch.cuda.empty_cache()
json.dump(dict(device=torch.cuda.get_device_name(), sms=props.multi_processor_count, l2_bytes=L2,
               footprint_bytes=FOOTPRINT, rounds=ROUNDS, rows=rows), open(sys.argv[1], 'w'), indent=1)
print('DONE', flush=True)
```

## Details

- The rule is batch-independent, so on SM90 with an FP32 state only one tile variant is reachable and
  graph capture compiles it; there is no batch-size boundary to warm up.
- BF16 state keeps `BV = 32`: no single rule wins everywhere on SM90 (the best, `4` for `B*HV <= 96`
  else `16`, is 1.18x geometric mean but up to 6% slower, and >2% slower at 7/99 points).
- Measured on H200 NVL only. The branch also covers H100 and H20 (fewer SMs, lower bandwidth), where I
  have not measured it.
- CI: `kernels/fla` runs on B200 and MI355 only, so CI does not reach this SM90 branch. The test above was
  run on H200 against this change.
- No new host synchronization: the branch reads only the state dtype and the device capability, like the
  SM100 branch above it.
