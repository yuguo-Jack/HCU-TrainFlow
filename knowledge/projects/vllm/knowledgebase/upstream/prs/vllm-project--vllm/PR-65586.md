## Overview

Adds MonkeyOCRv2 ([`zenosai/MonkeyOCRv2-B-Parsing`](https://huggingface.co/zenosai/MonkeyOCRv2-B-Parsing), about 265k downloads/month, # 1 open model on MDPBench, Apache-2.0). Today vLLM resolves it to `TransformersForCausalLM` and fails at startup (`Unrecognized configuration class MonkeyOCRv2Config ... for AutoModel`). No vLLM PR or issue covers it; the authors keep an out-of-tree copy of `dots_ocr.py` in their repo.

## Changes

- The model is the dots.ocr vision encoder (768 wide, 12 layers) plus a Qwen3 language model. The one real difference is the axial RoPE layout: height and width frequencies are interleaved (`h0, w0, h1, w1, ...`) instead of concatenated.
- `monkeyocr_v2.py` subclasses `DotsOCRForCausalLM` and overrides `rot_pos_emb`. Like `OpenCUAForConditionalGeneration`, it builds its own vision tower and language model (Qwen3) in `__init__`, so `dots_ocr.py` is unchanged. Processing reuses the Qwen2-VL path.
- Registry, test registry and docs entries.

## Validation

CPU (Apple M5 Pro), fp32, greedy decoding, compared with the HF remote code:

| Case | Prompt tokens | Tokens matching HF | Max \|Δ logprob\| |
| --- | --- | --- | --- |
| Text document | 691 | 57/57 (EOS) | 8.4e-4 |
| Photo with text | 1445 | 64/64 | 5.7e-4 |
| Both images in one prompt | 883 | 57/57 (EOS) | 8.5e-4 |

- Batched and single requests give the same tokens.
- With dots.ocr's RoPE layout instead, the document comes out as `1. 2. 3. ...`.
- The HF reference needs one fix on Transformers 5: the remote vision tower's non-persistent `inv_freq` buffer loads as zeros.
- `pytest tests/models/multimodal/processing/test_common.py -k "MonkeyOCRv2 or dots.ocr"`: 6 passed. Registry tests and pre-commit pass.
- **Not validated:** CUDA, bf16, TP/PP, LoRA.
