# [ROCm][Bugfix] Fix non-power-of-two sparse MLA split-K reduction

[Upstream PR](https://github.com/vllm-project/vllm/pull/61774) · state: open · merged: False

## Original PR description



## Overview

Fix a Triton compilation error in the ROCm sparse MLA split-K reduction kernel when the combined head dimension is not a power of two, such as the 512 NoPE + 64 RoPE layout used by DeepSeek-V3.2 and GLM-5.3.

## Claims

- Pad the reduction block width to the next power of two and mask out-of-range loads and stores.
- Preserve the existing memory layout and power-of-two reduction behavior.
- Add BF16 regression tests covering 512/576-dimensional layouts, different split counts, attention sinks, and invalid KV indices.

## Validation

- gfx1100 (W7900): 18/18 new regression tests passed.
- gfx1201 (R9700): 18/18 new regression tests passed.
- Baseline: All 12 cases exercising the 576-dimensional reduction failed compilation before the fix.
- gfx1100 E2E: Successfully ran inference-optimization/GLM-5.3-0.6B-A0.4B with real weights, BF16 KV cache, and long-context decode. Observed 204 successful split-K reduction launches with COMB_DIM=576 and COMB_BLOCK=1024.
- gfx1201 E2E: Successfully ran the same checkpoint with BF16 KV cache and long-context decode. Observed 204 successful split-K reduction launches with COMB_DIM=576 and COMB_BLOCK=1024.
- Numerical comparison: Split-K versus single-pass output had a maximum absolute difference of 1.56e-2 and relative L2 difference of 9.5e-4.
- Existing 512-dimensional path: No measurable performance regression in the tested configurations.

The gfx1100 E2E test used the routing change from #59628, temporarily extended to gfx1201 for testing. Additional environment-specific workarounds were required on gfx1201. These changes are not part of this PR.

## Details

The partial attention kernel already handles non-power-of-two head dimensions, but the shared reduction kernel previously used tl.arange(0, COMB_DIM), which fails compilation when COMB_DIM=576.

This change introduces COMB_BLOCK=next_power_of_2(COMB_DIM) for Triton block shapes while retaining the original logical dimension and memory strides. Padded lanes are masked off.

Related: #59628
