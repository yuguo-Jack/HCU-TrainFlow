# [ROCm][Bugfix] Fix non-power-of-two sparse MLA split-K reduction

[Upstream PR](https://github.com/vllm-project/vllm/pull/61774) · state: open · merged: False

## Original PR description



## Overview

Fix a Triton compilation error in the ROCm sparse MLA split-K reduction kernel when the combined head dimension is not a power of two, such as the 512 NoPE + 64 RoPE layout used by DeepSeek-V3.2 and GLM-5.3.

## Claims

- Pad the reduction block width to the next power of two and mask out-of-range loads and stores.
- Preserve the existing memory layout and power-of-two reduction behavior.
- Add BF16 regression tests covering 512/576-dimensional layouts, different split counts, attention sinks, and invalid KV indices.

## Validation

- gfx1100 (W7900): 18/18 new regression tests passed.
- gfx1201 (R9700): 18/18 new regression tests passed.
- Baseline: All 12 cases exercising the 576-dimensional reduction failed compilation before the fix.
- gfx1100 E2E: Successfully ran inference-optimization/GLM-5.3-0.6B-A0.4B with real weights, BF16 KV cache, and long-context decode. Observed 204 successful split-K reduction launches with COMB_DIM=576 and COMB_BLOCK=1024.
- gfx1201 E2E: Successfully ran the same checkpoint with BF16 KV cache and long-context decode. Observed 204 successful split-K reduction launches with COMB_DIM=576 and COMB_BLOCK=1024.
- Numerical comparison: Split-K versus single-pass output had a maximum absolute difference of 1.56e-2 and relative L2 difference of 9.5e-4.
- Existing 512-dimensional path: No measurable performance regression in the tested configurations.

The gfx1100 E2E test used the routing change from #59628, temporarily extended to gfx1201 for testing. Additional environment-specific workarounds were required on gfx1201. These changes are not part of this PR.

## Details

The partial attention kernel already handles non-power-of-two head dimensions, but the shared reduction kernel previously used tl.arange(0, COMB_DIM), which fails compilation when COMB_DIM=576.

This change introduces COMB_BLOCK=next_power_of_2(COMB_DIM) for Triton block shapes while retaining the original logical dimension and memory strides. Padded lanes are masked off.

Related: #59628

Thanks @dllehr-amd! Here is additional reproduction and performance validation on gfx1100 and gfx1201 including model-level E2E comparisons for both 576- and 512-dimensional sparse MLA layouts.

#59628 enables the Triton sparse MLA path on gfx11, which requires this fix for 576-dimensional split-K decode. The gfx1201 validation uses an experimental extension of that routing to gfx12. This PR only addresses the reduction kernel itself, keeping the model enablement changes separate.

### 1. Bug reproduction (576-dimensional GLM-5.3)

**Model:** `inference-optimization/GLM-5.3-0.6B-A0.4B` (512 NoPE + 64 RoPE = 576, BF16 KV cache)

**Environment:** ROCm 10.2 nightly, PyTorch 2.14, Triton 3.8, AITER 0.1.24.

Both baseline and fixed trees used the same experimental Triton routing based on #59628 (extended to gfx12).

```bash
export FLASH_ATTENTION_TRITON_AMD_ENABLE=TRUE

# Additionally required on gfx1201:
# export VLLM_ROCM_USE_AITER=1
# export CU_NUM=64

vllm serve inference-optimization/GLM-5.3-0.6B-A0.4B \
  --dtype bfloat16 --kv-cache-dtype auto \
  --tensor-parallel-size 1 --enforce-eager \
  --max-model-len 8192 --max-num-batched-tokens 1024 \
  --max-num-seqs 4 --gpu-memory-utilization 0.5 --seed 0
```

After a short request, I sent four concurrent completions with 3000/3097/3194/3291 prompt tokens, `max_tokens=32`, and `temperature=0`.

| GPU | Before #61774 | With #61774 |
|---|---|---|
| gfx1100 | `CompilationError` at `tl.arange(0, COMB_DIM)` | E2E success; 204 split-K reductions |
| gfx1201 | Same compilation error | E2E success; 204 split-K reductions |

The original kernel fails because `tl.arange(0, 576)` requires a power-of-two range. With the fix, all requests complete, and rocprofv3 confirms 204 split-K partial and 204 reduction launches on each GPU.

Also validated the current PR head (`8d257fa`) on gfx1201: 18/18 new regression tests passed, with successful E2E inference and 204 reduction launches. Replaying each reduction through single-pass on the same inputs gave a relative L2 error of 9.4e-4.

### 2. Existing 512-dimensional paths - kernel-level regression

For existing power-of-two dimensions, `COMB_BLOCK == COMB_DIM`, so no additional padding is introduced.

- All tested 512-dimensional reduction variants produced byte-identical ISA before and after the fix.
- Verified natively on gfx1100/gfx1201 and through AOT compilation for gfx942/gfx950, including inverse-RoPE, MXFP8, and adaptive variants.
- Kernel benchmarks across five interleaved rounds showed differences within −0.8% to +0.6%, consistent with measurement noise.

### 3. Existing 512-dimensional model -E2E performance

I additionally tested `inference-optimization/GLM-5.3-Flash-2.6B-A2.3B-small` (512 NoPE + 0 RoPE) on gfx1201, comparing the current PR head (`8d257fa`) against its main parent (`47fd76e`).

Both trees used the same experimental one-line RDNA4 indexer gate change, which is not part of this PR. No attention routing changes were needed.

The model exercises the exact modified reduction kernel with `COMB_DIM=512` and `COMB_BLOCK=512`. rocprofv3 confirmed 130 split-K reduction launches in both runs.

| Metric | Baseline | With PR |
|---|---:|---:|
| Split-K reduction launches | 130 | 130 |
| Reduction latency | 2.8–3.9 us | 2.8–4.0 us |
| Serving TPOT (median) | 10.95 ms | 10.59 ms |
| Reduction ISA | Identical | Identical |

The compiled reduction kernels are byte-identical with no additional padding or register spills. 
Per-run TPOT medians ranged from 10.4–11.2 ms. The observed difference is within run-to-run variability.

### 4. 576-dimensional performance

For the GLM-5.3 E2E workload (four concurrent ~3k-token requests, 128 output tokens):

| GPU | Split-K TPOT(with #61774) | Forced single-pass TPOT (with #61774) |
|---|---:|---:|
| gfx1100 | 9.88 ms | 11.71 ms |
| gfx1201 | 6.58 ms | 9.07 ms |

The reduction kernel contributes approximately 2–26 us, accounting for at most ~2% of split-K decode attention latency in the tested configurations.

**One caveat:** At larger decode batch sizes on gfx1100, the existing split heuristic can select split-K when single-pass is faster for 576-dimensional inputs (e.g., 3109 vs 2110 us at 16 heads x 64 rows). This relates to partial-kernel padding rather than the reduction change. Since these configurations fail compilation on main, this is not a regression against the existing implementation. I can investigate the heuristic separately.

Overall, the fix enables the previously failing 576-dimensional split-K path, while both kernel-level and model-level measurements show no measurable regression in the existing 512-dimensional path on the tested hardware.
