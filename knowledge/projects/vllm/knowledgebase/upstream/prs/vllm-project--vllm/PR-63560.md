# [Recipe] DeepSeek-V4.1-Flash: AgentX lanes as tuned presets

[Upstream PR](https://github.com/vllm-project/vllm/pull/63560) · state: closed · merged: True

## Original PR description

## Overview

Moves DeepSeek-V4.1-Flash's InferenceX AgentX lanes into tuned **presets** (vllm-project/recipes [SCHEMA.md](https://github.com/vllm-project/recipes/blob/main/SCHEMA.md) `presets`). Each preset carries the lane's concurrency points, builder choices and image. Readers previously had to adjust the command by hand from tables in the guide. Same pattern as #63534 (MiniMax-M3) and #63552 (Kimi-K3, merged).

Relies on two renderer fixes, both merged:

- vllm-project/recipes#1178 sizes the DEP router from the engine's `--data-parallel-size`, which the DEP2/DEP4 presets set.
- vllm-project/recipes#1179 makes `json_args` edit-only on toggle flags, so unticking Speculative decoding leaves no half-built `--speculative-config`.

## Claims

**Six presets**, all scoped to `[fp8, default]`. The lanes served the 0909 checkpoint, so the JSON API renders them on 0909. The builder applies them to 1017 too, since it has the same format and memory layout.

| Preset | GPU · strategy | Default | Points | Source |
|---|---|---|---|---|
| `b200_agentx_tp` | B200 · TP | yes | TP4 c1/4/8/16/32/128, TP2 c1 | InferenceX #3837 |
| `b200_agentx_dep` | B200 · DEP | yes | DEP2 c8–32, DEP2 + host KV c64/128, DEP4 c96/128 | InferenceX #3837 |
| `b300_agentx_tp` | B300 · TP | opt-in, **new** | TP4 c1/8/16, specialized decode | InferenceX #4332 |
| `b300_agentx_dep` | B300 · DEP | opt-in, **new** | DEP2 c8–64, host KV c128/192 (Simple offload, 50 GiB/rank) | InferenceX #4332 |
| `mi355x_agentx` | MI355X · TP | opt-in, **new** | TP2 c1/2/4/8/16/32/64 (c16/c32 capped), TP4 c1/2 | InferenceX #4409 |
| `gb300_agentx_pd` | GB300 · PD | yes | unchanged DEP4 + DEP16 1P1D | InferenceX #3941 |

Every preset except GB300 PD also does the following:
- pins the lane image;
- selects Rust, Speculative decoding and Text only, with Encoder parallel off;
- turns adaptive verification off, as the lanes ran.

The DEP presets size the engine with `--data-parallel-size 2` or `4`, on part of the node.

**Guide:**
- The B200 per-concurrency tables, the B300 aggregate table and the MI355X TP2 scheduling table become the presets' points.
- The MI355X benchmark-server command (InferenceX #3058, an older revision of the #4409 lane) is removed. The opt-in preset renders the current lane.
- The **Dynamo disaggregated serving on B300 and GB300** section is untouched (#62711 edits it).

**Default renderings that change (intentionally):** B200 TP and DEP, plus the two Mooncake renderings that wrap the TP preset, which change image only. Each appears under both the 0909 and 1017 IDs, so 8 files in all, and every one now shows the lane as it ran:

| File | Change |
|---|---|
| `hw/b200.json` (TP2 c1) | lane image; Speculative decoding with `enable_adaptive_verification:false`; `--language-model-only` instead of `--mm-encoder-tp-mode data` |
| `hw/b200/strategies/single_node_dep.json` (DEP2 c32) | the same, plus `--data-parallel-size 2` (was 8) |
| `hw/b200/strategies/kv_store_*_mooncake.json` | lane image only |

Every other DeepSeek-V4.1-Flash rendering is identical (176 of 184 files). B300, MI355X and GB300 open on Baseline or their unchanged default as before.

## Validation

- `node scripts/validate-source.mjs --source vllm --dir <this checkout>/recipes` passes against recipes main.
- **First commit** (lane blocks moved into presets): every DeepSeek-V4.1-Flash rendering is identical to main.
- **Lane check:** a script expands each lane's srt-slurm config at the InferenceX commit pinned in `source.revision` and compares its server arguments and env with the preset point's rendering (renderer with #1178 and #1179). It covers every point the master rows run: 33 points across B200, B300 and MI355X. All match, with three equivalent exceptions:
  - The lanes pass vLLM defaults explicitly (`--tensor-parallel-size 1` under DEP, `--prefill-schedule-interval 1`).
  - MI355X sets `VLLM_ROCM_USE_AITER_TRITON_SPARSE_MLA=True` where the recipe has `1`.
  - `--served-model-name`, `--max-model-len 1048576` and `--disable-uvicorn-access-log` are left out (the last is telemetry).
- **Builder (local):**
  - B200 opens on AgentX TP, TP2 at concurrency 1; the TP4 points switch TP. The DEP points switch DP2/DP4 on the engine and the router tab, with the new "runs DP=2 on 2 of 8 GPUs" hint.
  - Unticking Speculative decoding drops the spec config, and a reload keeps the point.
  - B300 AgentX DEP2's host-KV points turn on Simple offload at 50 GiB per rank.
  - MI355X AgentX TP2 switches TP2/TP4 on the pinned image.

## Details

- **Default vs opt-in.** B200 TP/DEP and GB300 PD already rendered their lanes for every user, so they stay default. Their remaining default changes are the image and builder choices the lanes ran with.
  - **B300** was opt-in because its lanes need a dev image: the specialized decode from #61868 (merged 2026-10-21) and its DSpark draft path from #61869 (still open).
  - **MI355X** was opt-in because its lane pins an image digest. The guide described it as a recommendation for AgentX-like traffic.
- **Baselines.** B200 TP keeps the Engram CPU offload TP2 needs outside the preset, so Baseline matches GB200/GB300. B200 DEP's Baseline is the shared Blackwell DEP8.
- **B200 DEP default point.** It is DEP2 c32, the engine settings B200 DEP already rendered. It now runs on two GPUs, as the lane does, instead of spanning all eight.
- **Router flags.** The lanes' `--request-timeout-secs 14400` and `--disable-retries` stay in the DEP runbooks; the router companion's command is fixed per strategy.
- **Point labels.** Points are labelled by the bare concurrency, with what else they change in parentheses (`8 (DEP2)`, `64 (DEP2 + host KV)`), since the builder titles the row Concurrency; vllm-project/recipes#1186 makes that the convention. The last commits relabel MiniMax-M3 (#63534) and Kimi-K3 (#63552) the same way: M3 said "8 clients" (also in its descriptions and GB200 table), K3 said `C8`. For these agentic lanes concurrency counts concurrent sessions.
- **Not in this PR:**
  - The B300/GB300 Dynamo xPyD lanes (#4231, #4266): several engines per node and per PD role aren't builder features.
  - GB300's single-node AgentX lanes: they aren't in the recipe today.
