# [CI][XPU] Retry image pull to survive transient containerd ingest races on XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/56245) · state: closed · merged: False

## Original PR description

## Purpose

Intel XPU CI intermittently fails on image pull (not tests) with
`failed commit on ref ... no such file or directory` — a transient containerd
GC/ingest race triggered by the cleanup right before pull, not a disk issue.
The existing `flock` only serializes CLI steps, not containerd's background GC.

## Changes

- Add `pull_image_with_retry` (default 5 attempts, backoff) and fail fast so
  `docker create` doesn't trigger a second racing pull.
- Add a short GC-settle wait in `cleanup_docker` before releasing the lock.
- Tunables: `DOCKER_PULL_MAX_ATTEMPTS`, `DOCKER_PULL_RETRY_DELAY`, `DOCKER_GC_SETTLE_SECS`.

## Test Plan

- `bash -n` passes; verified retry recovers and failed pull aborts cleanly.
