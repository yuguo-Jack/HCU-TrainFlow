# [Security] Support stream_options.include_obfuscation to mitigate token-length side channels

[Upstream PR](https://github.com/vllm-project/vllm/pull/61275) · state: open · merged: False

## Original PR description



## Overview


vLLM accepts but ignores OpenAI's `stream_options.include_obfuscation`, the mitigation OpenAI, Microsoft, Mistral and xAI deployed for the [Whisper Leak](https://arxiv.org/abs/2511.03675) side channel, so each streamed chunk's encrypted size reveals the length of its token. This PR implements the option for chat completions, completions and Responses, adds an opt-in server default `--enable-stream-obfuscation`, and documents both in the security guide.

## Claims


- `stream_options.include_obfuscation` works as in the OpenAI API, including the `include_obfuscation` query parameter on `GET /v1/responses/{id}?stream=true`.
- When enabled, chunks get an `obfuscation` field of random characters that rounds the JSON payload up to a multiple of 128 bytes. In live tests, unpadded content chunks had 6–11 distinct sizes per stream; padded chunks had one.
- Off by default. Without the flag, streams change only for requests that set `include_obfuscation: true`; with it, requests can opt out.

## Validation


Live server on an RTX 3090 with `Qwen/Qwen2.5-0.5B-Instruct`: a script streamed each endpoint (and the Responses GET replay) with the option unset, true and false, against a default server, a server with `--enable-stream-obfuscation`, and the base commit. All 48 cases passed: padding appeared exactly when expected, every padded payload was a multiple of 128 bytes, and `openai` 3.29.0 parsed every stream. On the base commit, `include_obfuscation: true` had no effect.

```
pytest -k "not GPTOSS" tests/entrypoints/serve/utils/test_sse_obfuscation.py \
  tests/entrypoints/openai/test_stream_obfuscation.py \
  tests/entrypoints/launchers/test_cli_args.py \
  tests/entrypoints/openai/chat_completion/test_serving_chat.py \
  tests/entrypoints/openai/test_render_parity.py \
  tests/entrypoints/openai/responses/test_{protocol,streaming_events,serving_responses}.py
# 376 passed, 10 deselected, 1 xfailed
```

The deselected GPT-OSS cases need a `gpt-oss-20b` server; they stream with obfuscation off, where the wrapper returns the stream unchanged, and are covered by CI. Rust: `cargo fmt`, `clippy -D warnings` and `cargo test -p vllm-cmd` pass, and `vllm-rs` rejects the new flag as unsupported.

To reproduce:

```bash
curl -sN localhost:8000/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "model": "Qwen/Qwen2.5-0.5B-Instruct", "stream": true, "max_tokens": 16,
  "messages": [{"role": "user", "content": "Hi"}],
  "stream_options": {"include_obfuscation": true}}' \
| grep '^data: {' | while read -r l; do echo $(( ${#l} - 6 )); done   # all multiples of 128
```

## Details


**Motivation.** [Whisper Leak](https://arxiv.org/abs/2511.03675) showed that a network observer can classify the topic of streamed LLM conversations from TLS record sizes and timing (often above 98% AUPRC across 28 models). The provider mitigations followed its disclosure ([Microsoft](https://microsoft.com/en-us/security/blog/2025/11/07/whisper-leak-a-novel-side-channel-cyberattack-on-remote-language-models/)). Clients send `include_obfuscation` to whatever serves the endpoint, so a vLLM server facing clients directly needs to honor it.

**Design.** A router-level wrapper modeled on `with_sse_keep_alive` pads `data: {...}` events and leaves serving code untouched. Padding is random so compression can't remove it. For Responses only `*.delta` events are padded, as in the OpenAI API. Off by default because it adds 17–144 bytes per chunk. OpenAI pads by default; switching vLLM's default is a one-line change if maintainers prefer it. The flag is registered as unsupported in the Rust frontend, following #58830.

**Limitations.** A chunk's size still reveals whether its payload crosses a 128-byte boundary. Timing is not hidden; the paper found padding alone gives partial protection, so the docs also recommend `--stream-interval`. `/inference/v1/generate` and the Rust frontend are not covered (noted in the docs).  **I can follow up with Rust support once the design here is settled.**

**Duplicates and AI use.** No issue or PR mentions `include_obfuscation`, stream obfuscation or Whisper Leak (searched 2026-10-12). Claude Code assisted with research, implementation, tests and the validation scripts. I made the scope and design decisions, reviewed every changed line and the validation results.
