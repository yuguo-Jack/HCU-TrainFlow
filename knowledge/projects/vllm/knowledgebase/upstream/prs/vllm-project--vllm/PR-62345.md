# [Bugfix][Security] muse: fix quadratic attribute scans in tool-call extraction

[Upstream PR](https://github.com/vllm-project/vllm/pull/62345) · state: open · merged: False

## Original PR description

## Overview

Bound Muse's ATEM attribute scans to a single tag and avoid reparsing tool calls on streaming deltas that cannot complete an invocation. This updates the existing fix after review; it does not add a separate parser or change the shared parser interface.

## Claims

- Attribute searches stop at the next `<` instead of scanning across repeated unterminated tags.
- Tool-call parsing runs when a delta completes `</atem:invoke>`, including split delimiters and the initial handoff. The emitted-call cursor never moves backwards between invocations.
- The rebase preserves #64518's `_parameter_types(request)` handling, including union, enum and `$ref` schemas.

## Details

The attribute classes previously allowed `<`, so a failed attribute search could restart at each open tag and rescan the remaining suffix. Restricting those classes to `[^<>]` preserves ordinary ATEM attributes while stopping that cross-tag search.

An invocation cannot be returned before its closing tag. The streaming gate checks a window extending `len(close) - 1` characters before the new delta, so delimiters split across deltas still trigger parsing. `max(previous_count, len(calls))` preserves the emission cursor on deltas that do not parse.

The merge conflict was caused by #64518 replacing `_string_parameters()` with schema-aware `_parameter_types()`. The rebased gate calls the new helper; none of that upstream schema logic is reverted.

This does **not** make total streaming work linear: `_visible_channels(current_text)` still runs on every delta, and `_INVOKE_RE` is unchanged. No engine, scheduler, model-runner or GPU synchronization code changes.

A call can only complete on a delta that finishes `</atem:invoke>`, so I tried parsing only on those deltas:

```python
close = "</atem:invoke>"
tail = current_text[max(0, len(previous_text) - len(close) + 1) :]
calls = self._parse_tool_calls(...) if close in tail else []
...
self._emitted_tool_calls = max(self._emitted_tool_calls, len(calls))
```

That brings streaming down to 0.13 s with the same tool calls as this PR at every split size I tried, and the Muse tests pass. Could you add it here?

Added as you wrote it. The reasoning holds: a call can only become visible on
