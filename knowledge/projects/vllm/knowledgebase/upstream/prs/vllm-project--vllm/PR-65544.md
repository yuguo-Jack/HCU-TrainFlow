# [Core] Scheduler-owned persistent state for streaming models

[Upstream PR](https://github.com/vllm-project/vllm/pull/65544) · state: open · merged: False

## Original PR description



## Overview

Adds a scheduler-owned persistent-state primitive for streaming models whose per-session state has a fixed size, is not recomputable from the prompt and must outlive individual requests, such as cache-aware streaming RNN-T ASR. Linked from RFC #65543. The first consumer, Nemotron 3.5 streaming ASR (#47455), is planned as an out-of-tree plugin extending the one #59827 registered; no model is added here.

## Claims

- **State spec and slots.** `PersistentStateSpec` describes a fixed-size, mixed-dtype state bundle held in the KV block pool, one slot per session. `PersistentStateLayerBase` layers are discovered alongside attention layers and bound to their slot views; Mamba's specs and managers are unchanged.
- **Admission at connect.** `EngineCore.admit_stream(request)` reserves a slot or refuses at once, so a live caller is refused rather than queued. The request ID is the session identity; a retry with the same payload is idempotent. Later inputs update the parked request; invalid updates are refused with a correlated rejection.
- **Release fence.** On finish, abort, preemption or deadline expiry, a slot that was never scheduled is released at once; a slot that ran in any step is retired, not freed, and is freed only after the worker acknowledges, through `ModelRunnerOutput.state_completion`, that its last step and its cleanup have completed on the device.
- **Engine-owned deadlines** bound never-fed, parked-idle and draining sessions (`additional_config["stream_admission"]`).
- **Planner bound.** `KVCacheSpec.max_num_blocks` is an opt-in bound, `None` for every existing spec. Without `num_gpu_blocks_override`, the state pool is capped at `max_num_seqs + 1` blocks, including the null block; an override may exceed this cap within the profiled budget and is refused above it.
- **Small common-path footprint.** State scheduling lives in a `StateScheduler` subclass selected only for state layouts; base `scheduler.py` changes by +49/−9. Non-state models take the existing paths.
- **Refused combinations** at startup: DP/TP/PP/CP > 1, async scheduling, speculative decoding, prefix caching, KV transfer, DBO, sleep mode, CuMem and HiSparse. The extensible KV cache, on by default with MRv2, is turned off for persistent-state models, so the cache is sized from profiling estimates.

## Details

- 35 files, +4,894/−80. `vllm/` source +2,036/−78, mostly in new modules (`state_scheduler.py` 360, `state_slots.py` 305, `stream_admission.py` 296, `state_slot_manager.py` 297, spec types in `kv_cache_interface.py` +277/−2). Common-path edits: `scheduler.py` +49/−9, `engine/core.py` +124/−45, `model_runner.py` +58/−5, `kv_cache_planning.py` +56, `cudagraph_utils.py` +30/−9, `attn_utils.py` +20/−2, `executor/abstract.py` +11/−1. Tests +2,507/−2. Design doc `docs/design/persistent_state.md` and a CPU example under `examples/features/persistent_state/`.
- Wire: the new optional request and output fields add one nil byte to ordinary outputs. `EngineCoreRequest.stream_admission` is last, so the Rust client's field prefix is unchanged (checked in `test_serial_utils.py`). `EngineCoreOutput.stream_output` follows upstream's `watermarking`; both are appended last for `array_like` compatibility.
- Why not Mamba state: Mamba state is a function of the token prefix (preemption recomputes it, prefix caching checkpoints it). Transducer state is not recomputable, so it needs a reservation at admission and an acknowledged release. A separate spec leaves Mamba's lifetime policy unchanged.
- Host wait: the worker waits on the state-step event when the step's output is collected, once per state step; with synchronous scheduling that wait runs on the worker's main thread at the output boundary, outside the methods `VLLM_GPU_SYNC_CHECK` wraps. It has not been profiled in an engine with a model.
- Extensible KV cache: its warmup commits only the null block while persistent-state warmup uses real slot indices, and state-slot views are bound once at initialization. Until that combination is designed and tested on GPU, the executor reports persistent state as a reason the extensible cache cannot be used, through upstream's existing fallback.
- Open for review: typed config fields instead of `additional_config["stream_admission"]`; whether to export the three `SchedulerStats` fields as metrics. If maintainers prefer, the PR can split into the spec, planner and fence, then `StateScheduler` and admission.
- Draft follow-ups (from `/pr-checklist`): trim `test_scheduler.py` (+1,619) and replace its constructor bypasses with real constructors where practical; replace the fixed CUDA sleep in the delayed-auxiliary-write fence test with an explicit writer-release handshake; rerun the GPU tests at the tip; profile the output-boundary wait and run engine-level `VLLM_GPU_SYNC_CHECK=error` once the plugin provides a model.
- Not a duplicate: open PRs searched for persistent per-session state, state slots, `admit_stream` and admission at connect; none implement scheduler-owned per-session state.
