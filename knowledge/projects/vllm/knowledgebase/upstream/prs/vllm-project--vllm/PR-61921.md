# [Bugfix][Model] Honor quantization config in Inkling MTP

[Upstream PR](https://github.com/vllm-project/vllm/pull/61921) · state: closed · merged: True

## Original PR description

## Overview

Allow Inkling MTP to use the saved quantization config for its input projections and decoder blocks, including per-layer exclusions. This enables serving quantized MTP layers.

## Claims

Honor quantization targets/exclusions and load projection scales on NVIDIA and AMD, without scheme-specific branches.

## Validation

- 15 tests and pre-commit pass; six new regression cases fail on baseline.
- Full-size MTP meta check loads all 136 required parameters with corrected metadata; original metadata fails.
- Tiny H100 BF16/FP8/mixed runs succeed. FP8/mixed match target-only on 8/8 prompts; BF16 behavior is unchanged from baseline.

Limitations: the tiny draft is untrained (zero FP8/mixed acceptance), and GPU tests reused compiled artifacts. Full-model inference/quality, ROCm and multi-GPU remain untested. Meta checks cover MTP construction and shape loading only.

## Details

**Metadata required:** released Inkling-NVFP4 has BF16 MTP weights. Append `model.mtp.*` to `quantization.exclude_modules` in `hf_quant_config.json` before using this change. That metadata correction is not yet published.

Distinct from #60666 (checkpoint renaming) and #48506 (other MTP architectures).
