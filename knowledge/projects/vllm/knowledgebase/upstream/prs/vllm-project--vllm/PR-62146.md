# [Bugfix][Offload] Preserve CPU residency for renamed NVFP4 expert weights

[Upstream PR](https://github.com/vllm-project/vllm/pull/62146) · state: open · merged: False

## Original PR description

## Overview

Preserve CPU/UVA residency when compressed-tensors NVFP4 MoE post-processing renames and repacks expert weights. Restoration currently matches the serialized names and silently leaves the main weights on the GPU despite the offloader's log.

Related to the [NVFP4 rename report by Hivenet-Igor in #58178](https://github.com/vllm-project/vllm/issues/58178#issuecomment-5830101485); this targets that variant rather than every allocation problem in the thread.

## Claims

- Add an identity-by-default quantizer name-resolution hook and the two NVFP4 mappings; retain original/final names when restoring CPU residency. Already-resident parameters remain resident.
- On real Qwen3-30B-A3B NVFP4, expert-only `cpu_offload_gb=1` restores **1,107,296,256 additional expert bytes (1.03125 GiB)**. All **1299 parameter hashes** match baseline/candidate.
- The change runs during weight processing and adds no steady-state host read or synchronization. Capacity is traded for host-transfer latency; no speedup or general accuracy gain is claimed.

## Validation

RTX 5090, 400W, TP=1, MRV2 in-process engine, BF16 output, Triton attention, Marlin MoE and explicit CUTLASS dense. Model `RedHatAI/Qwen3-30B-A3B-NVFP4` at `a4df9f017835830cbb588cfe72bc4e50294183c0`.

Final runs use the **official wheel for exact base `ce49c47cbb241b59a32ef110079a5261dbd08e49`**, `vllm 0.32.0rc1.dev323+gce49c47cb`, PyTorch 2.14.0+cu130, FlashInfer 0.7.2 and Triton 3.8.0. Complete versions of the three Python files are copied from the corresponding Git tree into a separate environment; **no function-definition injection** is used in these runs. Compiled artifacts match the base; this PR changes no CUDA code.

### Numerical differences

Repeated identical stock requests vary even in the unmodified engine (selected raw-logit probe maximum difference 7.625). Earlier layer tracing locates the first observed divergence in Marlin MoE, with equal inputs; routed-token packing order changes between invocations. Freezing only that order makes both GEMMs and the real expert output bit-exact across CPU/UVA → GPU → restored CPU/UVA.

In the **exact-base complete model**, a canonical packing-order diagnostic also gives **20/20 bit-exact next-token raw-logit comparisons**, plus identical tokens and top-5 logprobs for all **12 generated requests** across those residency switches. This control adds synchronization and is confined to the reproduction harness; it is not part of the production fix or performance measurements. Stock inference remains non-deterministic, and the 128-question sample does not establish statistical accuracy equivalence.

[Complete-model control](https://github.com/yibol9768-alt/sglang/blob/fd948aa99130c601e1f35b50b260edf15d79c11e/validation/rtx5090-20261017/round2/evidence/nvfp4-investigate-exact-canonical.json), [paired evaluation](https://github.com/yibol9768-alt/sglang/blob/fd948aa99130c601e1f35b50b260edf15d79c11e/validation/rtx5090-20261017/round2/evidence/vllm-exact-heldout128-comparison.json), [native regression](https://github.com/yibol9768-alt/sglang/blob/fd948aa99130c601e1f35b50b260edf15d79c11e/validation/rtx5090-20261017/round2/evidence/native-offload-exact-patched.xml), [frozen versions, scripts, raw stock runs and limitations](https://github.com/yibol9768-alt/sglang/blob/fd948aa99130c601e1f35b50b260edf15d79c11e/validation/rtx5090-20261017/round2/README.md).

The Graph result exposes a substantial host-transfer cost on this PCIe machine. It is measured after one warmup with identical prompts/output-token counts; cooling occurs outside timings. The earlier eager-only 11–15% overhead must not be generalized to Graph execution. Offload remains an explicit capacity/latency tradeoff; the production change adds no per-token work when offload is disabled.

Full non-UVA pretrained inference fails in **both baseline and candidate** with `b_scales is not on GPU`, matching the externally cached scale issue already handled by open #43453. The unit cases validate tensor residency/restoration with UVA disabled; they do not establish full non-UVA NVFP4/Marlin support. ROCm, other MoE backends, multi-GPU execution and default multiprocessing/HTTP serving were not locally validated. The existing test file is part of the H200/AMD CPU-offload suite; local results do not replace upstream CI.

## Details

`w13_weight_packed` / `w2_weight_packed` become `w13_weight` / `w2_weight` before repacking. Matching only the original names misses those final parameters; unchanged scale names explain the partial offload. The quantizer owns the mapping, avoiding NVFP4-specific suffix guesses in the generic loader; other methods retain identity behavior.

Duplicate check: #56413/#58185/#60909 address allocation/pinning, #54972 allocator release, #57215 XPU transposes, #43453 externally held non-UVA scale references, and #56177/#37190 expert pools. Their inspected diffs do not restore these renamed weights. [Pinned diff audit and search limits](https://github.com/yibol9768-alt/sglang/blob/ca72d5212b33ab079f838144467a870de749e859/validation/rtx5090-20261017/evidence/final-diff-audit.json).

AI assistance was used for diagnosis, implementation, validation and this write-up. The human contributor reviewed the production change and authorized the additional validation and PR updates.
