# [Bugfix][Frontend] Constrain Kimi K3 arguments declared through $ref

[Upstream PR](https://github.com/vllm-project/vllm/pull/62404) · state: open · merged: False

## Original PR description

## Overview

Constrain Kimi K3 strict tool arguments whose types are declared only through `$ref`. An argument referencing an object schema currently accepts an array such as `root=[]`.

## Claims

- Strict Chat Completions and Responses requests reject arrays for an object-valued argument referenced through root `$defs` or `definitions`.
- Server-enforced parameter strictness uses the same fix; non-strict tools keep their existing behavior.
- The original request schema remains unchanged, including recursive references.

The previously failing recursive `$ref` case (`TestNestedDefsDepth:2`) generated `root=[]`, violating the referenced object schema. After the fix it generated `root={}` and passed.

## Details

The K3 builder reads the argument's own `type`, so `$ref`-only arguments can miss type constraints. The parser now resolves supported root `$defs`/`definitions` references and adds the type to a temporary schema, preserving `$ref` and the original request. Unsupported references keep the existing fallback; string constraints retain their existing limitations.

No open PR was found addressing this Kimi K3 `$ref`-only structural-tag validation bug.
