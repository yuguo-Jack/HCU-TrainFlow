# [Docs] Add modular vs. monolithic MoE kernel note to quantization plugin guide

[Upstream PR](https://github.com/vllm-project/vllm/pull/63987) · state: open · merged: False

## Original PR description

## Purpose

The out-of-tree quantization plugin guide documents only the modular
`apply` path of `FusedMoEMethodBase`. It doesn't mention that a method
which performs routing internally should override the `is_monolithic`
property to return `True` and implement `apply_monolithic` instead. This
adds a short note after the MoE example pointing out the two paths and
their signatures.

Docs only, no behavior change.

## Test Plan

- `pre-commit run markdownlint-cli2 --files docs/features/quantization/README.md`
- Signatures copied from
  `vllm/model_executor/layers/fused_moe/fused_moe_method_base.py` on main.

Follow-up to #62187. The import / signature fixes for the stale
`FusedMoE` references are tracked in #50598; this note covers the
`is_monolithic` / `apply_monolithic` gap that #50598 doesn't.
