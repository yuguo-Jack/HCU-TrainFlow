# fix: Only use Triton MoE naive block assignment for batch size 1

[Upstream PR](https://github.com/vllm-project/vllm/pull/64912) · state: closed · merged: False

## Original PR description

## Summary

This PR addresses issue #63943 by fixing the Triton MoE naive block assignment to only be used for batch size 1.

## Problem

The naive block assignment path in `_prepare_expert_assignment()` is taken when:
```python
num_tokens * top_k_num * 4 <= global_num_experts
```

On this path, every (token, expert) pair gets its own block, so an expert chosen by several tokens in the batch has its weights read once per pair. On bandwidth-limited GPUs (NVIDIA GB10 / DGX Spark with LPDDR5x), this causes 8% to 2x slower decode for device-resident weights.

## Solution

Only use the naive block assignment when `num_tokens == 1`, where no two tokens can share an expert. This keeps the batch-1 optimization from #29354/#39016 while removing the repeated reads at 2-4 tokens.

## Changes

- Modified `vllm/model_executor/layers/fused_moe/fused_moe.py`: Changed the naive block assignment condition from `num_tokens * top_k_num * 4 <= global_num_experts` to `num_tokens == 1`

## Testing

- The fix is a minimal one-line condition change
- Existing MoE tests should cover the functionality
- The issue author has offered to test patches on GB10 hardware
