# [CI] Retry image-build steps once on exit code 1

[Upstream PR](https://github.com/vllm-project/vllm/pull/61266) · state: open · merged: False

## Original PR description



## Overview

Retry the four image-build steps once when they exit with code 1, matching the rule the AMD and CPU image builds in `.buildkite/hardware_tests/` already use.

## Claims

- `image-build`, `arm64-image-build`, `image-build-cpu` and `cpu-arm64-image-build` retry once on exit code 1, as well as on the existing agent-lost exit codes (`-1`, `-10`).
- A transient failure while fetching from an upstream source no longer fails the whole build and skips every downstream test step. Examples: a package index, a GitHub release download, or an apt mirror mid-sync.

## Validation

- The YAML parses, and each of the four steps lists the rules `-1`, `-10` and `1`.
- Retry rules only take effect in a real build, so the effect will be measured from CI history after merge: how many retries fire on exit 1, how many pass on retry, and how many fail twice.

## Details

Image-build steps run no tests, so one retry on exit 1 can't hide a test failure. A real build breakage fails again on the retry and the build fails as before, at the cost of one extra image build. A step-level rule covers every fetch site in the Dockerfile and the build scripts, including ones added later, without a retry loop at each site. The rule and its comment are copied from `.buildkite/hardware_tests/amd.yaml`.

These steps also build the `TORCH_NIGHTLY=1` images, so those get the retry too. The non-root smoke-test step runs the built image, so it is left unchanged, and so is the HPU image step.
