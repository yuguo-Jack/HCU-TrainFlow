# [HiSparse][Core] Keep HiSparse out of the general scheduler and KV planning paths

[Upstream PR](https://github.com/vllm-project/vllm/pull/64562) · state: open · merged: False

## Original PR description

## Purpose

Remove HiSparse-specific overrides and special cases from general KV-cache paths, and dedupe the scheduler's load-start code. No intended behavior change for HiSparse; one small zeroing change for copy-on-write blocks, described below.

| Change | Before | After |
|---|---|---|
| Deferred-load start | `_drain_deferred_loads` repeats `update_state_after_alloc` and the prefix-stats recording from `schedule()` | both call `_update_connector_after_alloc` |
| Host block ids in GPU zeroing | `HiSparseSourceManager` overrides `records_new_block_ids` and `take_new_block_ids` to discard host ids after they are recorded | `bind_host_pool` clears `_record_new_block_ids`; the base copy-on-write path now honors that flag (it appended unconditionally) |
| Hot-page stride alignment | `_get_kv_cache_bytes_per_block` special-cases `isinstance(spec, HiSparseHotSpec)` | `HiSparseHotSpec.get_block_stride_alignment()` includes its page size |

Why each is equivalent:
- **Deferred-load start:** the deferral condition, the fence stamp and the drain loop are unchanged, and each load still starts before its stats are recorded.
- **Copy-on-write guard:** CoW blocks now follow the same per-manager `_record_new_block_ids` rule as every other allocation path. For HiSparse host this is what the removed overrides did. **Behavior change:** with zeroing on, a base-path CoW block in a manager that doesn't record new blocks (circular buffer, non-`AttentionSpec` specs) is no longer zeroed. Its regular blocks already weren't. Mamba has its own CoW path and is unaffected.
- **Alignment:** hot groups always carry per-layer names that share the spec, so the hot page size still enters the LCM. On the layer-outermost path, rounding a page up to itself is a no-op.
