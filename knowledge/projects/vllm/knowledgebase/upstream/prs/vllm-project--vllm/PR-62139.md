# [Bugfix][Multimodal] Auto derive max_num_batched_tokens from max_model_len and max_num_seqs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62139) · state: open · merged: False

## Original PR description

## Summary
Fix memory profiling overestimation issue.

When `max_model_len` is set small by user, SchedulerConfig uses the default 'max_num_batched_tokens'. This creates oversized dummy batch during memory profiling, leading to much higher peak activation memory estimation than real runtime.
In encoder-decoder ASR scenarios (Qwen3-ASR in our test), the profiling calculation reports insufficient KV cache memory, and the engine fails to start, even though the real runtime memory requirement is much lower.

This PR:
1. In `SchedulerConfig.__post_init__`, when `max_num_batched_tokens` is not specified, auto set `max_num_batched_tokens = max_model_len`.
2. Add validation to prevent manually set `max_num_batched_tokens` from exceeding manually set upper bound 'max_model_len`.
3. Normal operation is supported under limited VRAM and a smaller max_model_len.
4. Works for multi-model scenarios.
