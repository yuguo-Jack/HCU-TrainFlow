# [Bugfix] Parse JSON tool calls in Llama 4 pythonic parser

[Upstream PR](https://github.com/vllm-project/vllm/pull/46890) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #46863.

Some Llama-4 checkpoints can emit tool calls as JSON, for example `{"type": "function", "name": "Bash", "parameters": {...}}`, instead of the pythonic form that `llama4_pythonic` expects. Those responses were left in `content`, so clients did not receive `tool_calls`.

This adds a conservative non-streaming JSON fallback in `vllm/tool_parsers/llama4_pythonic_tool_parser.py`. It accepts clean JSON tool-call payloads as a single object, comma-separated objects, or a single array, and reads arguments from either `arguments` or `parameters`. Malformed JSON, trailing prose, dangling commas, arrays that do not close, or ordinary JSON objects still pass through unchanged as content.

Streaming JSON parsing is intentionally left for a follow-up because correct streaming support needs partial-JSON lookahead. This PR only changes the non-streaming `extract_tool_calls()` path described in the issue.

AI assistance disclosure: AI tools assisted in preparing this change.

## Test Plan

- Add non-streaming Llama 4 parser tests for the reported JSON `parameters` form, the `arguments` key, comma-separated JSON objects, and a JSON array of objects.
- Add pass-through tests for malformed JSON and non-tool JSON content to keep the fallback conservative.
