# [Benchmark] Add skewed (zipf) expert-load coverage to benchmark_moe.py

[Upstream PR](https://github.com/vllm-project/vllm/pull/57100) · state: open · merged: False

## Original PR description

## Summary

Neither this script's `--tune` search nor SGLang's equivalent tuning script
currently models skewed expert load: gating logits are drawn i.i.d.
(`torch.randn`), so every tuned Triton config is chosen under near-uniform
routing even though production MoE traffic is not uniform.

This adds an opt-in `--expert-load-distribution {uniform,zipf}` flag
(default `uniform`, matching current behavior exactly when omitted).
`zipf` biases gating logits by `-log(rank)` per expert, so lower-index
experts receive disproportionately more routed tokens -- modeling skewed
load without changing anything about how tokens are dispatched once
routed.

Commit 1 is a separate, small prerequisite fix folded into this PR rather
than opened standalone: `get_model_params()` didn't recognize
`DeepseekForCausalLM` (e.g. `deepseek-ai/deepseek-moe-16b-base`), so this
script couldn't run against that model at all before it. Bundled here per
AGENTS.md's guidance on one-off mechanical fixes.

## Measured data

`--tune`, `deepseek-ai/deepseek-moe-16b-base` (E=64, topk=6, `--tp-size 1`),
batch sizes 1/2/4/8/16, single rented NVIDIA GeForce RTX 3090 (community
cloud), triton 3.7.1. Uniform sweep: 8838.73s. Zipf sweep: 1985.18s
(warm Triton kernel cache from the first run). Full cost and run record:
this PR's companion project keeps a public account of it, available on
request.

Winning config per batch size, uniform vs. zipf (`BLOCK_SIZE_M /
BLOCK_SIZE_N / BLOCK_SIZE_K / GROUP_SIZE_M / num_warps / num_stages`):

| batch size | uniform | zipf | same? |
|---|---|---|---|
| 1  | 16/32/128/64/4/2 | 16/32/128/64/4/2 | yes |
| 2  | 16/32/64/16/4/3  | 16/32/64/32/4/3  | no (GROUP_SIZE_M) |
| 4  | 16/64/64/32/8/4  | 16/32/64/64/8/4  | no (BLOCK_SIZE_N, GROUP_SIZE_M) |
| 8  | 32/64/128/1/4/2  | 16/32/256/1/4/3  | no (BLOCK_SIZE_M, BLOCK_SIZE_K, num_stages) |
| 16 | 16/32/64/1/4/3   | 16/32/64/16/4/3  | no (GROUP_SIZE_M) |

4 of 5 batch sizes land on a different winning config once routing is
skewed instead of uniform -- tuning against this script's current
uniform-only default can select a config that isn't actually best for
skewed production traffic.
