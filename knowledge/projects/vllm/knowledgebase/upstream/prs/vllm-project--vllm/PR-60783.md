# [Bugfix][KV Connector][ROCm] MoRIIO: accept kernel-block-split MLA/indexer KV views

[Upstream PR](https://github.com/vllm-project/vllm/pull/60783) · state: open · merged: False

## Original PR description

## Summary

If a backend's kernel block sizes exclude the manager block size, `create_kv_cache_views` gives connectors a **kernel-block-split** 4-D view (leading dim in kernel blocks, `r = num_states / N`). MoRIIO's 4-D branch only accepts `r == 1`, so registration fails with `Unsupported MoRIIO MLA cache shape`.

Affected on `main`: DeepSeek-V3.2-style models on ROCm (e.g. GLM-5.2). `ROCM_AITER_MLA_SPARSE` and `DEEPSEEK_V32_INDEXER` support kernel blocks `[1, MultipleOf(16)]`, so a `--block-size` that isn't 1 or a multiple of 16 (e.g. 8) is split to kernel block 1.

**Change** (`moriio_layout.py`, `get_layer_transfer_geometry`):
- Accept split views for single-head caches (MLA latent, indexer); group them with `group_kernel_blocks` so the geometry is in manager blocks. A dense single-head block is the same bytes for any kernel block size, so P and D may differ.
- Multi-head splits stay rejected (byte order depends on the layout).

Bit-identical for `r == 1`; no wire or metadata change. +17/−5 in one source file.

GLM-5.3-Flash no longer needs this since #57169 (packed layout, never split group-wide).
