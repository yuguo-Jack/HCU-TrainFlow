# [Bugfix][KV Connector][ROCm] MoRIIO: support kernel-block-split 4-D K…

[Upstream PR](https://github.com/vllm-project/vllm/pull/60783) · state: open · merged: False

## Original PR description

## Summary

For an `MLAAttentionSpec` with a `storage_block_size` smaller than `block_size`, `create_kv_cache_views` hands connectors a **kernel-block-split** 4-D view. Its leading dim counts kernel blocks, not manager blocks (`r = block_size / storage_block_size`). MoRIIO's standardized 4-D branch only accepts `r == 1`, so registration fails with `Unsupported MoRIIO MLA cache shape`. Block ids on the wire are always manager ids, so the geometry must be expressed in manager blocks.

**This PR teaches `get_layer_transfer_geometry` (`moriio_layout.py`) to read kernel-split views in manager blocks:**
- Accept `spec.num_states % N == 0`, derive `r = num_states // N`, and report:
  - `num_blocks = B/r`
  - `block_stride = stride[0]*r`
  - `block_len = num_states*slot_size`
- Reject any view that isn't `r` dense, contiguous kernel pages per block, so a malformed layout errors instead of silently transferring wrong bytes.

Bit-identical for `r == 1`, with no wire-format or metadata change. About 20 lines in one file.

## Relevance to GLM-5.3-Flash

- **Before #57169:** this was required for GLM-5.3-Flash 1P/1D READ. Without it, both engines aborted in `register_kv_caches` on the kpool indexer view.
- **On current `main`:** after #57169 moved GLM-5.3-Flash to the generic packed KV layout, every MoRIIO view in our 1P/1D EP8 run registers with `r == 1`. A run with only this PR removed registered both legs and served prefill; it was preempted before the recall check.
- **So this PR is not required for GLM-5.3-Flash on `main` today.** It fixes the general case: any spec whose views arrive kernel-split is still rejected by `main`, and the new kernel-split unit tests fail on `main` with that error.
