# [Perf][LoRA][MoE] Use the shrink/expand kernels for MoE-LoRA batches of up to 64 tokens

[Upstream PR](https://github.com/vllm-project/vllm/pull/64653) · state: closed · merged: True

## Original PR description

Diff: 3 files, +262 / -17.

This PR was split into a stack. Its earlier revisions (problem-sized configs, threshold 256, fp32 intermediate, removal of the small-batch kernel) moved to:

1. this PR: shrink/expand for batches of up to 64 tokens
2. #64746: problem-sized shrink/expand configs, threshold 256
3. #64747: fp32 intermediate, single output rounding
4. #64748: remove the small-batch kernel

## Purpose

For `max_lora_rank <= 128` and `fully_sharded=False`, `_fused_moe_lora` on main always uses the single-launch one-shot or small-batch kernel. Each program in them runs the whole K loop serially, so at decode the grid is a few dozen programs and the kernels run far below memory bandwidth. The existing `_fused_moe_lora_shrink` + `_fused_moe_lora_expand` path spreads the work over more programs.

## Changes

- Batches of up to `FUSED_MOE_LORA_TWO_KERNEL_MAX_TOKENS = 64` tokens use shrink/expand. Larger batches keep the one-shot / small-batch kernels. With the current default configs (from the base-MoE `get_default_config`), shrink/expand wins at every size up to 64 tokens and is mixed above, so the threshold is 64. #64746 raises it to 256 together with configs sized for the LoRA problem.
- TMA descriptors need 16-byte aligned strides. Shrink/expand now also runs small ranks, so TMA is used only when `max_lora_rank * element_size % 16 == 0` (rank 4 in bf16 would otherwise fail with `strides must be 16-byte aligned`).
- The TMA descriptor calls import `TensorDescriptor` where they use it. `import triton` does not load `triton.tools.tensor_descriptor`; on main it is only loaded as a side effect of other imports (in a server, `fused_moe/config.py` through `triton_kernels`). Once small batches reach these calls, `tests/lora/test_fused_moe_lora_kernel.py` fails 18 cases with `AttributeError: module 'triton.tools' has no attribute 'tensor_descriptor'` after #64748.
