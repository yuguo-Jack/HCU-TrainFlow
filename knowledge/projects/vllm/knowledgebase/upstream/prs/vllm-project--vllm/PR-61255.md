# [Bugfix][Kimi-K3] Keep speculative scratch out of checkpoint history

[Upstream PR](https://github.com/vllm-project/vllm/pull/61255) · state: open · merged: False

## Original PR description

## Overview

Use the logical convolution history length when Kimi-K3 exports FlashKDA prefill checkpoints with speculative decoding. This addresses the KDA path of the same class of issue as #60797, which changes Mamba2 only.

## Claims

- A width-4 convolution saves the last 3 tokens before the checkpoint, even when its cache row also holds speculative scratch. For K4 at boundary 16, restore tokens 13/14/15 instead of 9/10/11.
- Require callers to supply the logical history length; the existing GLM callers already do so.

## Validation

| Check | Unmodified main | This change |
| --- | --- | --- |
| CUDA checkpoint tests: K0/K1/K4, both layouts, actual K3 layer construction and convolution resume | 4 failed, 4 passed | 8 passed |
| Tiny K3-path engine: K4, align16, prefix hits 0/64/80 on 67/83/99-token prompts | 12/12 exported histories incorrect | 0/12 incorrect |

The tiny engine used 2 full-rank KDA layers, BF16 dummy weights, hidden size 256, 12 KDA heads of dimension 128, seed 42 and greedy generation. Cached and recomputed tokens/logprobs matched in both arms: dummy weights are insufficient to demonstrate a model-quality improvement. Full Kimi-K3 weight evaluation remains pending, so this PR is a draft.

CUDA validation used one B200 on prod-0030 (physical GPU0), Python sources at `e0317b28c` and existing native extensions from `94f4170df`. No native code changes. The remote environment lacks `tblib`, so the actual pytest invocation used the unchanged upstream distributed/config fixtures in an external plugin:

```bash
.venv/bin/python -m pytest -p upstream_kda_fixtures \
  --confcutdir=tests/models/kimi_k3 \
  tests/models/kimi_k3/test_kda.py -k checkpoint -v --tb=short
```

In the normal test environment, run `.venv/bin/python -m pytest tests/models/kimi_k3/test_kda.py -k checkpoint -v`. The existing B200 Kimi-K3 unit step runs this file. Changed-file pre-commit and DCO hooks passed.

## Details

The exporter inferred history from the cache row's physical capacity, which grows by the speculative-token count. Passing `conv_size - 1` separates logical history from scratch storage. Scratch and unrelated state rows remain untouched; recurrent checkpoint copying is unchanged.

Duplicate checks found no open PR for this KDA fix. #60797 covers Mamba2; #60888 concerns checkpoint publication and initial-state columns. AI assistance was used to prepare and validate this change.
