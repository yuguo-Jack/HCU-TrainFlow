# [Kernel] Fuse native BF16 ReLU2 with NVFP4 quantization

[Upstream PR](https://github.com/vllm-project/vllm/pull/59384) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fuse native BF16 ReLU2 with NVFP4 quantization for Nemotron shared experts on SM10x/FlashInfer CuTe-DSL. Removes one launch and the BF16 intermediate; reuses the consumer from [#59612](https://github.com/vllm-project/vllm/pull/59612), with no GEMM changes.

## Claims

- **24–31% lower activation/quantization latency at 2K–4K tokens; 13–20% lower including the down-projection GEMM.**
- Bit-exact packed values and live scales, with existing activation/LoRA fallbacks preserved.

## Validation

**Revision `462744b0`, GB200, Nemotron shared-expert dimensions** (K=5376, N=4096). Ordinary native compiler settings, warm CUDA graphs; eight paired samples per shape:

| Tokens | ReLU2 + quantization (µs) | Including down GEMM (µs) | Component speedup |
|---:|---:|---:|---:|
| 1 | 2.56 → 1.54 | 6.53 → 6.28 | 1.04× |
| 128 | 3.33 → 2.31 | 8.16 → 7.77 | 1.05× |
| 2,048 | 17.17 → 12.98 | 35.94 → 31.24 | **1.15×** |
| 4,096 | 35.60 → 24.46 | 74.63 → 59.85 | **1.25×** |

All pairs improve; paired component speedups are 1.147–1.151× at 2K and 1.246–1.258× at 4K. Nsight confirms **3 → 2 kernels** with identical GEMM kernel and grid.

**Correctness:** 325 GPU checks and pre-commit/mypy pass. Full-model oracle: 707,680 fused calls, zero value/scale/padding errors, no post-startup compilation. GSM8K: 90.75% in the current instrumented run; prior controlled A/B: 91.66% in all four runs, identical tokens (not a new-stack paired comparison).

**Serving:** prior-stack C50, 2K-input/1K-output median throughput is 2,359 → 2,375 output tokens/s (+0.66%, six trials/arm), with overlapping ranges—not a robust serving-speedup claim.

**Prefill-heavy serving (same revision):** AGG TP1, C50, 8K-input/128-output; fresh-cache B–C–C–B, six 100-request trials per implementation/budget. Both full retries completed: 24/24 trials, 2,400/2,400 requests passed.

| Token budget | Baseline output tokens/s, median [range] | Fused output tokens/s, median [range] | Median change |
|---:|---:|---:|---:|
| 2,048 | 202.87 [198.90–204.09] | 204.56 [201.90–208.36] | +0.83% |
| 4,096 | 386.05 [379.85–394.53] | 392.02 [389.71–397.70] | +1.55% |

## Details

Reuses QuantizedActivation; opaque dispatch preserves dynamic rows under guard-free Dynamo. Warmup registration is metadata-only: the shared `kernel_warmup()` compiles padding/alignment variants after consumer selection is resolved post-load, before CUDA graph capture, following the [startup warmup contract](https://github.com/vllm-project/vllm/blob/462744b08e03b35c44a5d46c8465cf430949e2e6/docs/contributing/jit_kernel_warmup.md#review-checklist). Only the validated native-ReLU2/SM10x/CuTe path is enabled. No scheduler, runner, communication or dependency changes.

Distinct from routed-MoE [#56740](https://github.com/vllm-project/vllm/pull/56740), GELU [#59467](https://github.com/vllm-project/vllm/pull/59467) and normalization [#61073](https://github.com/vllm-project/vllm/pull/61073). No DISAGG, TP>1 or default-stack serving claim.
