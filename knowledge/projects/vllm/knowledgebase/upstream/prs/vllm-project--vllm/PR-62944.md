# [Rust Frontend] Return 400 from /tokenize for invalid requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/62944) · state: open · merged: False

## Original PR description

## Summary
`/tokenize` wrapped every error as a 500 `server_error`, so an invalid chat request (for example an unsupported role) got a 500 there while `/v1/chat/completions` correctly returned a 400 `invalid_request_error`.

## Changes
- Route the three tokenize error sites through the existing `chat_submit_error` / `text_submit_error` helpers, so request-validation errors return 400 and internal failures stay 500.
- Tests for an unsupported role on the chat form (400) and an internal failure (500).

## Testing
- `cargo test` for the server crate
- `cargo clippy`, `cargo fmt --check`

Closes #62321
