# [Bugfix][Frontend] Honor default penalties in transcription and translation requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/61133) · state: open · merged: False

## Original PR description

## Overview

`/v1/audio/transcriptions` and `/v1/audio/translations` ignore server-default `presence_penalty` / `frequency_penalty` (from `generation_config.json` or `--override-generation-config`). Both request models still default the two fields to `0.0` and pass them straight to `SamplingParams`, while `repetition_penalty` right next to them is resolved from `default_sampling_params`. It's the same gap #50769 closed for chat and completions and #60307 for batch chat. I gave the two fields a `None` default and resolve them like the other sampling params.

## Claims

- An omitted penalty on the two audio endpoints resolves to the server default; an explicit client value, including `0.0`, still wins.
- With no server default both stay `0.0`, so nothing changes without a generation config.

## Validation

Noticed while diffing the speech-to-text request models against the completion one.

```python
defaults = {"presence_penalty": 1.5, "frequency_penalty": 0.5, "repetition_penalty": 1.2}
audio = UploadFile(file=BytesIO(b""), filename="a.wav")
reqs = {
    "completions": CompletionRequest(prompt="hi"),
    "transcriptions": TranscriptionRequest(file=audio),
    "translations": TranslationRequest(file=audio),
}
for name, req in reqs.items():
    sp = req.to_sampling_params(16, defaults)
    print(name, sp.presence_penalty, sp.frequency_penalty, sp.repetition_penalty)
```

```text
# main (cc9b0f097)              # this PR
completions 1.5 0.5 1.2         completions 1.5 0.5 1.2
transcriptions 0.0 0.0 1.2      transcriptions 1.5 0.5 1.2
translations 0.0 0.0 1.2        translations 1.5 0.5 1.2
```

I added `TestSpeechToTextPenaltyDefaults` to `tests/entrypoints/openai/test_penalty_default_resolution.py`, parametrized over both request classes; the server-default case fails on main for both.

```
pytest tests/entrypoints/openai/test_penalty_default_resolution.py
ruff check && ruff format --check   # on the three touched files
```

Both pass locally, along with the model-free speech-to-text unit tests. No GPU here, so the Whisper server tests and a live `vllm serve` were not run.

## Details

`temperature` on these two requests also has a hard `0.0` field default (OpenAI's documented default for audio), so I left it alone; this only covers the two penalties.

Not a duplicate as far as I can tell: #50769 and #60307 only touch the chat, completion and batch chat requests, and I didn't find an issue or PR for the audio endpoints.

AI assistance was used to find and prepare this change; I reviewed every line and ran the tests above.
