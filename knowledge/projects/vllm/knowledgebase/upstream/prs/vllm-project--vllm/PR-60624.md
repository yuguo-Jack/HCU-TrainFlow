# Report usage.prompt_tokens_details.multimodal_tokens in the Rust frontend

[Upstream PR](https://github.com/vllm-project/vllm/pull/60624) · state: open · merged: False

## Original PR description

## Overview

Report `usage.prompt_tokens_details.multimodal_tokens` from the Rust frontend for `/v1/chat/completions`, matching what the Python frontend already returns. Implements the unchecked `multimodal_tokens` item from the roadmap in #44280.

## Claims

- `/v1/chat/completions` — streaming and non-streaming — now returns per-modality placeholder token counts under `usage.prompt_tokens_details.multimodal_tokens`, keyed `image` / `audio` / `video`.
- Each count is the sum of that modality's placeholder spans, so the entries add up to the multimodal tokens already included in `usage.prompt_tokens` (upstream documents exactly this contract).
- The object stays gated on `--enable-prompt-tokens-details` and is still omitted when there is nothing to report.
- `created_cache_tokens` is **not** implemented — it needs engine-provided cache-creation counts. A `TODO` in the code records this.

## Validation

Commands from `.buildkite/scripts/run-rust-frontend-cargo-ci.sh` (the Buildkite `Rust Frontend Cargo` group, which this PR triggers because it lists `rust/` in its `source_file_dependencies`), run on main `b49c921` with the patch applied:

cargo nextest run --all-features --locked --no-fail-fast             # 2046 run: 2022 passed, 24 failed, 13 skipped

All 24 failures are environmental on my machine (no HuggingFace reachability, no `uv`): 21 × `vllm-chat::roundtrip` (tokenizer fetch timeouts), `vllm-chat::grammar_replay` (spawns `uv`), `vllm-text` `lower_text_request_uses_real_qwen_generation_defaults` (HF fetch), and `vllm-engine-core-client` `python_msgpack_fixtures_match_rust_encoding` (spawns `uv`). The identical command set on an unmodified checkout of the same `b49c921` gives **2039 run: 2015 passed, the same 24 failed, 13 skipped** — the failure set is unchanged by this patch, and every one of the 7 tests this patch adds passes.

The 7 new tests:

- 2 cover the counting helper (per-modality sums; empty input reports nothing);
- 3 pin the placement rule (appears when the flag is enabled and media is present; hidden by default; still absent when there is neither media nor cached tokens);
- 1 drives the streaming chunk builder;
- 1 is end-to-end (`non_stream_chat_reports_multimodal_prompt_token_details`): it posts a real `/v1/chat/completions` request carrying a base64 PNG through the real handler, renderer, multimodal preprocessing and mock engine, reads back the placeholder span the engine actually received, and asserts the response reports exactly that number under `multimodal_tokens.image`.

Per-crate test counts, measured by `cargo nextest list` on `b49c921` with and without the patch: `vllm-chat` 391 → 393, `vllm-server` 452 → 457.

## Details

**Why this is not duplicating an open PR.** Re-checked today, all zero: open PRs with `prompt_tokens_details` in the title — 0; open PRs with `multimodal_tokens` in the title or body — 0; PRs in any state with `multimodal_tokens` in the title — 0; the 45 comments on #44280 — none claim this field. The roadmap item is still unchecked and unmarked.

**Implementation.** The counts can only be computed after rendering, because that is where the renderer expands placeholders. So `vllm-chat` grows `count_multimodal_tokens()` plus a `ChatLlm::chat_with_metadata()` that returns the counts alongside the event stream. `ChatLlm::chat()` is unchanged behaviourally — it delegates and drops the extra value — so all 20 existing call sites are untouched. The server then threads the counts into both usage paths. `PromptTokenUsageInfo` gains the field, and construction moves into `PromptTokenUsageInfo::from_counts()` so the "omit when empty" rule lives in one place. The rule is only *widened*: a request with no cached tokens and no media serializes exactly as before. `completions.rs` and `inference/generate.rs` pass `None` — neither builds multimodal features.

**Tradeoffs and limitations.**

- `cached_tokens` is unchanged by this patch.
- The `/v1/completions` route has no multimodal input path in the Rust frontend at all.
- `/inference/v1/generate` already returns `mm_placeholders` directly, but its `usage` object does not carry `prompt_tokens_details`; wiring the same counts there is a smaller, separate change.
- No docs page documents this field (`prompt_tokens_details` appears in `docs/` only as incidental example output), so there is nothing to update there.
