# [Bugfix][KV Offload] Prevent incompatible cross-TP cache reuse

[Upstream PR](https://github.com/vllm-project/vllm/pull/55191) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Direct KV pages store rank-local layers at different byte offsets when tensor-parallel size changes. Prevent a cross-topology cache hit from restoring incompatible KV values by keeping affected direct layouts in separate namespaces.

Fixes #62283.

## Claims

- Use topology-specific filesystem/object-store identities and P2P compatibility fields for affected direct layouts.
- Preserve same-topology reuse and certified canonical or replicated sharing.
- Keep existing files and objects intact; entries in formerly topology-independent namespaces become cold.

## Validation

A new `LLM` regression with real TP=1 and TP=2 engines fails without the fix and passes with it. GPU results used NVIDIA B200 GPUs with driver 580.95.05 and a precompiled build of main `b8c04dd3b4`, which this branch includes. The comparison tree is this branch with only the production files restored to main.

```sh
.venv/bin/python -m pytest tests/v1/distributed/test_kv_offload_topology.py -v -s
.venv/bin/python -m pytest tests/v1/kv_connector/unit/offloading_connector/test_config.py -q
```

```text
Without the fix: assert 992 == 0   (the TP=2 engine restored 992 tokens that TP=1 wrote)
                 test_head_sharded_attention_requires_canonical_layout_for_portability[False-1] and [False-2]
                 AssertionError: assert True is False
With the fix:    both files pass, in repeated runs
```

After a cold run, the regression waits for the stored files, because engine shutdown cancels queued stores.

`tests/v1/kv_connector/unit/offloading_connector` and `tests/v1/kv_offload` also pass, except `test_partial_tail_store_uses_attention_and_recurrent_cow_sources` and `test_eagle_partial_tail_round_trip_serves_mamba_checkpoint` in `test_scheduler.py`, which fail the same way on main on this host.

The regression and these unit test directories also give the same results with this branch merged onto main `410ab341a8`, with the same build, because no native code changed between the two commits.

The tables below ran on the same hardware against main `3a90cc6fd0`, before the latest commits on this branch. The later commits change only tests and a docs note.

A longer run with `Qwen/Qwen3-0.6B`, MRV1, and the filesystem tier used a 3581-token prompt. Each result compares greedy output with an uncached engine at the same TP size.

| Writer, then reader | Layout | Cached tokens without the fix | Output without the fix | Cached tokens with the fix | Output with the fix |
| --- | --- | --- | --- | --- | --- |
| TP=1, then TP=2 | Direct | 3568 | Incorrect: `.RFINITE一日.......` | 0 | Correct |
| TP=2, then TP=1 | Direct | 3568 | Incorrect: `abloatuovo affirm written` | 0 | Correct |
| TP=2, then TP=2 | Direct | Not separately measured | Not separately measured | 3568 | Correct |
| TP=1, then TP=1 | Direct | 3568 | Correct | 3568 | Correct |
| TP=1, then TP=2 | Canonical | 3568 | Correct | 3568 | Correct |

The other tiers show the same defect and the same fix, with `Qwen/Qwen3-0.6B` on MRV1:

| Tier and check | Without the fix | With the fix |
| --- | --- | --- |
| Object store through NIXL OBJ against a local S3 endpoint, TP=1 then TP=2 | 2000 cached tokens, incorrect output: `asuring.meologiescery` | 0 cached tokens, output matches an uncached TP=2 engine |
| Object store, a later TP=2 read | Not separately measured | 2000 cached tokens, output matches |
| P2P, `run_accuracy_test.sh`, prefill TP=1 and decode TP=2, `CPU_BYTES=16000000000` | GSM8K accuracy 0.0, and cross-TP loads reach the decoder | GSM8K accuracy 0.4215, with `rejecting peer connect: config fingerprint mismatch` |

The P2P harness default CPU tier of 200 MB hides this defect, because allocation failures leave only a few loads.

**Why MRV1:** Only MRV1 reaches this path. Direct layouts on MRV2 behave the same with and without this change: a TP=1 to TP=2 read is cold, and a later TP=2 read is a hit. MRV1 is still available with `VLLM_USE_V2_MODEL_RUNNER=0`, and #62283 reports this silent output corruption independently. The production change removes more code than it adds, so it does not increase the MRV1 surface.

**CI coverage:** The topology regression has a new two-GPU Buildkite step, because the existing offload step uses one GPU and the existing two-GPU step excludes `kv_transfer`. The regressions of this PR also pass with this branch merged onto main `b2a9480dc7`, with its own precompiled build and `VLLM_WORKER_MULTIPROC_METHOD=spawn` as in CI. Upstream checks are stopped at contributor authorization, so Buildkite has not run this branch.

## Details

Direct storage concatenates each worker's local layers. Changing TP changes the byte layout even when total read sizes match. Only certified canonical mappings are topology-independent; the supported replicated-MLA case has a separate shared identity.

The KV offloading guide now documents filesystem, object-store, and P2P scope. Previously topology-independent head-sharded MRV1 direct caches become cold, even at the same TP size. Already topology-specific direct caches and certified canonical/replicated layouts keep their namespaces. No stored files or objects are deleted.

This does not duplicate an open PR. #55907 and closed #58196 concern physical-layout identity, and #56331 concerns model-configuration identity. Open #62566 adds a warning for topology-bound secondary tiers on the tiering path and does not change which caches are shared. None of them address these rank-local byte offsets.
