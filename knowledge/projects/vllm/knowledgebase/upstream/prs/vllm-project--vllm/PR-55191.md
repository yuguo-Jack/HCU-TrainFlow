# [Bugfix][KV Offload] Keep direct caches topology-specific

[Upstream PR](https://github.com/vllm-project/vllm/pull/55191) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Avoid reusing direct filesystem KV cache entries across tensor-parallel topologies.

## Claims

- Give direct-layout caches topology-specific filenames.
- Preserve same-topology reuse, certified canonical reuse, and replicated-layout handling.

## Validation

The config, mapping, canonical-layout, and filesystem suites pass, along with scoped pre-commit hooks. Restoring the original predicate fails the direct-layout controls while canonical controls pass.

To run the related suites in a configured development environment:

```sh
.venv/bin/python -m pytest tests/v1/kv_connector/unit/offloading_connector tests/v1/kv_offload
```

A fresh reproduction uses real GPU buffers, worker registration, shared mmap views, production DMA handlers, and filesystem I/O. The original predicate loads incorrect FP16 values across TP1/TP2 in both directions. With this change, cross-topology lookups miss and same-topology reloads match. The reproduction also passes on current main with this patch applied.

TP ranks were simulated sequentially on one RTX 5070 Ti. Multi-GPU TP1-to-TP2 model inference remains unverified. Filesystem validation used an extension compiled from this branch's `csrc/fs_io.cpp`; other native extensions were precompiled.

Upstream checks are stopped at contributor authorization; local validation does not establish a CI pass.

## Details

Direct storage concatenates each worker's local layers. Changing TP changes their byte offsets, so equal read sizes do not guarantee compatible data. Only certified canonical layouts are topology-independent; replicated-layout handling stays separate.

Existing direct caches become cold because their namespace changes; no files are deleted. Separate filesystem roots per topology are a workaround. #55907 and closed #58196 concern physical-layout identity; #56331 concerns model-configuration identity. Neither addresses these topology-dependent byte offsets.

AI assistance was used for this change.
