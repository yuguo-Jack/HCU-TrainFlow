# [Bugfix][Perf][DSv4.1] Write prefill index sentinels in combine kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/63264) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fixes stale DeepSeek-V4.1 sparse-index rows in reused prefill workspaces
(#63250), while removing the separate full-workspace memset introduced by
#60613.

The combine kernel now initializes its own `-1` sentinels, so the correctness
fix no longer requires an extra CUDA launch or a write over the full aligned
row.

## Claims

- **Bug fix:** every combine output row is fully initialized. Positions in
  `[combined_len, width)` are `-1`, preventing FlashMLA prefill from consuming
  stale indices left by an earlier request or layer.
- **Performance:** for one combine invocation, the 8K ratio-1 path falls from
  `60.93 us` to `26.21 us` (`2.32x`) in eager execution and from `30.62 us` to
  `26.34 us` (`1.16x`) under CUDA graph replay on H100.
- The regression test covers the 12-token #63250 reproducer, bounded replay,
  and rows whose valid prefix fills the entire aligned width.

## Workload mapping

DeepSeek-V4.1-Flash has 40 language-model attention layers and 3 MTP layers.
Its public config contains:

| V4.1 layer type | Count | Meaning |
| --- | ---: | --- |
| `compress_ratio=0` | 5 | sliding-window attention only |
| `compress_ratio=1` | 20 | full compressed cache, up to 512 indexed entries |
| `compress_ratio=2` | 18 | ratio-2 compressed cache, up to 512 indexed entries |

`compress_ratio=4` and `128` belong to the earlier V4 topology and are not
valid V4.1 layer types. They are therefore excluded from the V4.1 benchmark
results below.

Each benchmark number measures one `combine_topk_swa_indices()` call for one
layer in one batch. It is not a complete model step or TTFT measurement.

| benchmark case | serving scenario |
| --- | --- |
| 12-token SWA | Short new chat prompt; exactly the #63250 corruption case |
| 8K SWA | One fresh 8K prompt without prefix cache, at a pure SWA layer |
| 8K C2 | One fresh 8K prompt, at a ratio-2 compressed layer |
| 8K C2, 8 requests | Eight concurrent ~1K prompts, 8K prefill tokens total |
| 8K C1 | One fresh 8K prompt, at a full-compressed-cache layer |
| 16K C1 | One fresh 16K long-context prompt at a full-cache layer |

## Details

### Root cause

FlashMLA requires each combined index row to be padded to a multiple of 128.
The combine kernel writes the valid top-k and sliding-window prefix, while
`combined_lens` records its logical length.

The prefill call sites reuse a workspace through `out=`. Before the fix, the
suffix outside `combined_lens` retained indices from an earlier invocation.
FlashMLA prefill processes whole index tiles and can load entries beyond
`combined_lens`; a stale in-range index can therefore address a KV row that
the current call did not write. That stale data can corrupt attention for short
prompts even though the final attention mask is supposed to exclude the entry.

#60613 fixed the stale data by clearing the full workspace with
`combined_indices.fill_(-1)`. This PR keeps that correctness guarantee but
performs the initialization inside the existing combine kernel.

### Implementation

After writing the valid indices, the kernel writes `-1` from `combined_len`
through the aligned row width. A `tl.range` loop skips full rows and processes
only the unused suffix of partially filled rows. The 512-element block size was
selected from a coarse 64/128/256/512 sweep.

Because the kernel now writes every output element, the `out=None` allocation
uses `torch.empty` instead of `torch.full`. Output contents are identical to
the `fill_(-1)` implementation.

### Relationship to #60613

This branch includes #60613's correctness commit and replaces its
`fill_(-1)` implementation with the in-kernel equivalent. If #60613 lands
first, this PR can be rebased and reduced to the performance change.

### Limitations

- The public V4.1 config was used to validate layer types and counts, but the
  checkpoint is not available locally. The H20 end-to-end reproducer and model
  accuracy evaluation were not rerun here.
- The committed benchmark's default case list still contains inherited
  `C4/C128` stress cases. Those should be replaced by the ratio-1 cases above
  before marking the PR ready.
- The reported values are per-layer kernel timings. End-to-end TTFT should be
  collected on V4.1 serving hardware with the target TP/EP and speculative
  decoding configuration.
