# [Bugfix][Multimodal] Handle media cache eviction during reads

[Upstream PR](https://github.com/vllm-project/vllm/pull/65363) · state: open · merged: False

## Original PR description

## Overview

A media cache entry evicted between its metadata check and read can be recreated as an empty file, causing image decoding to fail. Treat this race as a cache miss so the media is downloaded again.

## Claims

- Refresh cache entry timestamps without recreating files removed by concurrent LRU eviction.
- Add deterministic regression coverage for synchronous, asynchronous, and model-entrypoint requests.

## Validation

- The new sync and async regression tests fail on the original implementation with an image-decoding error and pass with the fix.
- `VLLM_TARGET_DEVICE=cpu VLLM_PLUGINS='' PYTHONPATH=. ../vllm-reviewer-audit/.venv/bin/python -m pytest tests/multimodal/media/test_connector.py --deselect tests/multimodal/media/test_connector.py::test_chat_cache_evicted_after_stat -q --tb=short`: 84 passed, 1 deselected. The deselected test uses SmolVLM with `LLM.chat` and was not run on the local CPU host.
- On a DGX Spark, a Qwen3.8-27B `LLM.chat` request reproduced the failure with the original cache method and succeeded with the patched method. Normal requests had identical prompt and generated token IDs. This test used installed vLLM 0.31.0 with the patched `_get_cached_bytes` method from this checkout injected into the runtime.
- `pre-commit run --files vllm/multimodal/media/connector.py tests/multimodal/media/test_connector.py docs/features/multimodal_inputs.md`: passed.
- The added media tests are selected by the existing Buildkite multimodal test step.

## Details

`Path.touch()` recreates a cache file if eviction occurs after `stat()`. The resulting empty file is returned as a cache hit, so image decoding fails instead of fetching the media again. `os.utime()` updates the timestamp only when the file exists; if eviction wins the race, the existing `OSError` handler returns a cache miss.

This change addresses the read/eviction race. It does not repair already-corrupt cache files or measure production incidence. It is separate from [#56062](https://github.com/vllm-project/vllm/pull/56062), which bounds cache entries and handles failed downloads, and [#55616](https://github.com/vllm-project/vllm/pull/55616), which changes cache lookup identity.
