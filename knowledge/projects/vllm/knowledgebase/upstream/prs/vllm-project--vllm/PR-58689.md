# [ROCm][DSv4.1] Disambiguate ROCm attention class names

[Upstream PR](https://github.com/vllm-project/vllm/pull/58689) · state: closed · merged: True

## Original PR description

## Purpose

This is a small, focused naming cleanup of DeepSeek V4.1 ROCm attention classes and their selector. It preserves runtime behavior and compatibility with existing configurations.

DeepSeek V4.1 ROCm attention defined its own SWA metadata, SWA metadata builder, and sparse-MLA backend under the same class names as the DeepSeek V4 ROCm implementations. The ROCm SWA metadata builder is a distinct type. It subclasses `DeepseekV41SparseSWAMetadataBuilder`, which handles V4.1's 0/1/2 compression topology.

Rename those V4.1-local classes so they cannot be confused with `vllm.models.deepseek_v4.amd.rocm`:

- `DeepseekV41ROCMAiterSparseSWAMetadata`
- `DeepseekV41ROCMAiterSparseSWAMetadataBuilder`
- `DeepseekV41ROCMAiterMLASparseBackend`

`DeepseekV41ROCMAiterMLAAttention` now uses the renamed sparse-MLA backend, while its SWA backend returns the renamed metadata builder. The canonical V4.1 selector is `ROCM_FLASHMLA_SPARSE_DSV41`; V4.1 continues to accept `ROCM_FLASHMLA_SPARSE_DSV4` as a legacy alias for backward compatibility. DeepSeek V4 behavior is unchanged.

## Test Plan

- `git diff --check`
- Changed-file pre-commit
- Focused registry and backend-selection tests
- Start `deepseek-ai/DeepSeek-V4.1-Flash` with TP=4 using both `ROCM_FLASHMLA_SPARSE_DSV4` and `ROCM_FLASHMLA_SPARSE_DSV41`, and send a completion request to each server.

## Test Result

- Changed-file pre-commit passed (ruff, mypy 3.10–3.13, SPDX, test tethering).
- Focused tests passed for the distinct V4/V4.1 registry paths and for selecting the V4.1 implementation through both the legacy and canonical selectors.
- TP=4 serve smokes passed on four MI355X GPUs with both selectors. Each server returned HTTP 200 and generated `42` for the completion request.
