# [Perf][DSv4.1] Overlap mHC coefficients behind the fused all-reduce on SM90

[Upstream PR](https://github.com/vllm-project/vllm/pull/64892) · state: open · merged: False

## Original PR description



## Overview

Turn on DeepSeek-V4.1's mHC coefficient overlap (#57603) on Hopper wherever the fused CuTe DSL Lamport all-reduce + mHC kernel applies (TP4 with NVLink multicast, e.g. H200). Raise the overlap token cap from 16 to 144 on SM90.

Depends on #59129 (the SM90 DeepGEMM mHC prenorm register-lifetime fix): this PR runs that prenorm kernel on SM90 in the overlap path.

## Claims

- On H200 TP4 (DSV4.1-Flash, DSpark k=5), median ITL drops 4–5% at concurrency 1–16 and stays flat at 32. Batches above 144 rows keep the stock path.
- No change on SM100: `mhc_overlap_max_tokens()` still returns 16 there, and the SM100 gating is unchanged.
- Hopper without the fused all-reduce (no multicast, or TP ≠ 4) keeps the current non-overlap path.

## Validation

**Performance.** H200 TP4, `--max-model-len 200000 --max-num-seqs 64`, DSpark k=5, Humming MoE with humming#177. Real prompts, output length 1024, temperature 0.7. Median ITL in ms:

| conc | main (b2f46e785f) | this PR | Δ |
|---|---|---|---|
| 1 | 9.32, 9.32 | 8.86, 8.87 | −4.9% |
| 8 | 17.34, 17.36 | 16.57, 16.63 | −4.3% |
| 32 | 29.90, 29.98 | 29.92, 29.91 | ±0 |

Two runs each in ABBA order on the same base. Acceptance lengths match (2.95–3.13). An earlier sweep on a development tree also measured c16 −4.0% and c24 −1.9%.

**Cap choice.** Measured per boundary in CUDA graphs: stock FlashInfer AR + mHC vs fused AR + mHC with side-stream coefficients. Values are µs.

| rows | 6 | 24 | 48 | 96 | 144 | 192 |
|---|---|---|---|---|---|---|
| stock | 16.1 | 20.1 | 28.5 | 32.2 | 35.2 | 39.3 |
| fused + overlap | 8.3 | 10.1 | 13.5 | 20.5 | 28.6 | 45.4 |

At 192 rows the one-shot Lamport kernel falls behind FlashInfer's two-shot all-reduce, so the cap stays below 192.

**Correctness.**
- `pytest tests/kernels/mhc/test_mhc_kernels.py` on H200: the newly enabled overlap and decoder-mix tests pass bit-exact.
  - One failure, `test_mhc_fused_post_pre[4-7168-128]` (1 of 917,504 elements off by 1 BF16 ulp), is pre-existing on main. It runs no code this PR touches, and #59129 reports the same case.
- Fused `AllReduceMHC` on 4× H200 at 1–192 rows, eagerly and after 20 graph replays:
  - streams are bitwise equal to the unfused path;
  - layer input is within 1 ulp.
- GPQA-Diamond, three single-repeat runs each (temperature 0.7, 12,288 max tokens): main 74.7 / 73.7 / 75.3 (mean 74.6), this PR 79.3 / 78.3 / 75.3 (mean 77.6). There is no regression; the difference is within run-to-run spread.

Reproduce: `vllm serve deepseek-ai/DeepSeek-V4.1-Flash --tensor-parallel-size 4 --max-model-len 200000 --max-num-seqs 64 --tokenizer-mode deepseek_v41 --speculative-config '{"method":"dspark","num_speculative_tokens":5}'`, then `vllm bench serve --backend vllm --endpoint /v1/completions --dataset-name custom --dataset-path real_prompts.jsonl --skip-chat-template --custom-output-len 1024 --temperature 0.7 --max-concurrency {1,8,32}`.

CI note: CI has no SM90 TP4 DSV4.1 job. The SM90 kernel tests are enabled by this PR (`HAS_MHC_OVERLAP_ARCH`); the end-to-end numbers above were run locally.

## Details

- `MHC_OVERLAP_MAX_TOKENS` becomes the cached `mhc_overlap_max_tokens()`, which returns 144 on SM90 and 16 elsewhere. It sizes the `AllReduceMHC` mailbox (≈17.7 MB at 144), the deferred MoE finalize, and the overlap batch gate.
- On SM90, `supports_mhc_overlap` also requires `supports_mhc_all_reduce`. Without the fused kernel, the coefficients are fully exposed and the overlap loses below ~40 rows (15.7 vs 11.3 µs at 6 rows).
- Differs from #60768, which adds an explicit opt-in that keeps the ordinary TP collective on SM90 and makes no performance claim. This PR enables Hopper only behind the fused all-reduce, where it is measured faster, and needs no new config flag.
- The end-to-end setup (pure TP4 Humming MoE on H200) needs humming#177, which #64802 picks up. The change itself does not depend on it.
- Duplicate check: no other open PR enables the SM90 overlap behind the fused all-reduce. #60768 is the closest (see above).
