# [Kernel][Perf] Triton unified attention: window-align the SWA/chunked KV-tile loop start

[Upstream PR](https://github.com/vllm-project/vllm/pull/54718) · state: open · merged: False

## Original PR description

## Summary

- fix: https://github.com/vllm-project/vllm/issues/44575

The SWA/chunked-attention KV-tile loop floor-rounds its start to a tile boundary, so a misaligned window can span one extra `TILE_SIZE` tile. Adds an opt-in `SHIFT_TILE_BASE` that starts the loop exactly at the window's first allowed key instead — 2D decode/prefill only; `USE_TD` and 3D decode keep the old bounds, and the two other callers of `compute_tile_loop_bounds` are unaffected by default.

This idea was initially proposed by #44584 (@almogtavor), but it was closed — because H100 numbers were near the noise floor for realistic windows. This PR carries the fix forward (adapted for `USE_TD`/Gemma4 additions since) with new B200 evidence below.


## Test Plan
### A. Performance Test

- setup: B200, CUDA-graph-isolated decode latency, averaged over all 16 tile-alignment residues:

| window | before | after | improvement |
|---|---|---|---|
| 128 | 0.0148ms | 0.0128ms | +13.5% |
| 256 | 0.0244ms | 0.0223ms | +8.6% |
| 512 | 0.0449ms | 0.0426ms | +5.1% |
| 1024 | 0.0830ms | 0.0809ms | +2.5% |
| 4096 | 0.3082ms | 0.3055ms | +0.9% |

Per-residue variance collapses from up to 16% pre-fix to <1% post-fix at every window size. (RTX 5090 showed no measurable difference with the same method — fixed per-call overhead likely dominates more there.)

### B. Unit Test

```bash
pytest tests/kernels/attention/test_triton_unified_attention.py
```
1590 passed, including a new bit-exact regression test (`test_triton_unified_attn_sw_tile_base_bit_exact`)
