# [Perf][GLM-5.3-Flash] Batch paired KDA gate projections (f_b_proj/g_b_proj) into one bmm

[Upstream PR](https://github.com/vllm-project/vllm/pull/57617) · state: open · merged: False

## Original PR description

## Purpose and source

Pair the BF16 `f_b_proj` / `g_b_proj` projections into one cached batched matmul. LoRA-configured models retain the original Linear path, including adapters installed after postload; non-BF16 weights also retain the fallback. Compatible postload weight refreshes update the cache in place to preserve CUDA-graph addresses. First load or incompatible shape/dtype/device allocates new storage and requires graph recapture.

Published head: `47895f99d0b9e52a850285e223f597327691e6a8` on fixed main `32551991b9aff4d8af837d640e3adcd9609f7d75`. The final source has a substantial small-M paired-operation microbenchmark benefit, but the latest standalone standard serving run **does not establish a stable C32 end-to-end gain**.

## Controlled follow-up, 2026-10-26 (local candidate; code not pushed)

A new A0 -> P0 -> P1 -> A1 cycle tests the paired projection with a local compile-compatible view (`narrow -> unflatten -> transpose`, source SHA256 `c4b9ade1bfc00e33ecdd7dafdd43c0fb36cc482258a65babfd8bcf5c28118550`). The published code head above remains unchanged. The view change fixes this PR's padded/nonzero-offset M=1 fullgraph regression: the old source gives 1 failure / 1 pass for the two added tests; the local full suite gives 9 passes. This is not evidence of a baseline upstream serving defect.

All four arms used the same fixed MAIN79 image and [DeepGEMM #448](https://github.com/deepseek-ai/DeepGEMM/pull/448) correctness extension, #60567 mHC warmup and the local NVIDIA KPool warmup. Each had a separate container and compile-cache copy, with the same initial seed and the relevant mHC/KPool entries removed before startup. All 16 mHC and 8 KPool keys existed at readiness, with **zero new keys during requests**. These common changes are not attributed to paired projection. The startup mnnvl all-reduce probe fell back to the same single-node trtllm backend in all arms; this is a condition of this measurement, not a complete communication optimization certification.

The same stock protocol described below was kept: 1952 formal requests per arm, C1 reference, three 512-request 2K/128 C32 blocks, and three 128-request mixed 2K/32K blocks. All **7808 formal requests**, 48 natural-stop gold questions, and 384 candidate real-weight finite/bitwise output comparisons passed. The 520 workload warmup requests and 32 first/repeat probes are checked separately and excluded from formal aggregates. All formal durations and tails are retained.

## Microbenchmark and earlier serving limits

Final-source H20 paired-operation measurement used real BF16 ColumnParallelLinear modules, strict CUPTI graph replay/cold L2, three ABBA blocks and untimed warmup. It measures the full `call_fn` GPU activity span, not CPU dispatch or whole-layer/model latency. Both outputs were bitwise equal before and after timing.

| M | Two Linear GPU span (us) | Paired GPU span (us) | Time reduction |
|---:|---:|---:|---:|
| 1 | 5.872 | 2.720 | +53.678% |
| 4 | 5.848 | 2.752 | +52.941% |
| 32 | 5.880 | 2.816 | +52.111% |
| 2048 | 17.424 | 17.720 | -1.699% |
| 8192 | 48.800 | 40.624 | +16.755% |

M2048 regressed in two blocks; M8192 improved in all three. These results do not predict compiled serving performance. Original micro result SHA256: `e1106c548e0497dd430acc29f7a96fe71816bf94fc442b621318901050e8a2f1`.

Historical custom-client MTP-off A0/P/A1 serving is retained separately: the P C32 block rates were **649.138 / 758.354 / 759.621** output tok/s. Pooling every block's output and full wall time gave P 718.460 versus baselines 754.070/757.330, **-4.72%/-5.13%**. Its predeclared block-median results were much closer (+0.61%/+0.06%), while p95 first-output and median TPOT worsened. These older custom-client definitions differ from the new stock benchmark; they are not replaced, pooled with it or used to discard its slow block. Neither episode establishes stable comprehensive serving acceleration.
