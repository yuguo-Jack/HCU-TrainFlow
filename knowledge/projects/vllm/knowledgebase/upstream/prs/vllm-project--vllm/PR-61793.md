# [UMBP][5/10] Add MORI embedded DRAM runtime and transfer handling

[Upstream PR](https://github.com/vllm-project/vllm/pull/61793) · state: closed · merged: True

## Original PR description

This PR is split from the original full PR: https://github.com/vllm-project/vllm/pull/58568

Register `UMBPStoreConnector` and add the worker-private MORI embedded DRAM runtime.
Register GPU KV buffers and move them with bulk and ranged MORI I/O, without a connector-owned host staging copy.
Handle timeouts, cancellation, eviction retry, lookup sockets, and DRAM configuration.

Implementation only. Pipeline parallelism is rejected. Usage and limits are in `docs/features/umbp_embedded_dram.md`. CPU contract tests and MORI integration coverage are in the next PR.

Commit: `063282ba40`. Review slice of [vllm-project/vllm#58568](https://github.com/vllm-project/vllm/pull/58568) for [RFC #57187](https://github.com/vllm-project/vllm/issues/57187). The earlier combined embedded draft is [vllm-project/vllm#58568](https://github.com/vllm-project/vllm/pull/58568).

- tjtanaa · comment · 2026-10-27T07:52:05Z · [source](https://github.com/vllm-project/vllm/pull/61793#discussion_r4386210911)

File: `vllm/distributed/kv_transfer/kv_connector/v1/umbp/runtime/embedded.py` · line 694

Async loads do not populate `_store_deadlines`, so this polling timeout cannot fire for them. The default async worker path drains loads through `poll()`, not `wait()`. If `batch_get_ranges_into_ptr()` stops making progress, this returns None indefinitely and the request never receives load completion.

Please enforce a deadline for running loads as well, starting when the operation begins rather than while it is queued. Preserve buffer ownership on timeout: do not report completion/failure that permits block reuse while native code may still write the destination.

Please add a regression that starts and blocks a native load, advances past its deadline, and exercises only `poll()` —without calling `wait()` or `cancel()` first.

- tjtanaa · comment · 2026-10-27T07:53:31Z · [source](https://github.com/vllm-project/vllm/pull/61793#discussion_r4386219561)

File: `vllm/distributed/kv_transfer/kv_connector/v1/umbp/runtime/embedded.py` · line None

`close()` unconditionally unlinks `self.path`, including when `start()` rejected this instance because another live engine already serves that path.

A reproducible sequence is: start server A, attempt server B on the same path and catch the expected error, then clean up B with `close()`. B removes A’s socket pathname, so A remains alive but its scheduler can no longer connect.

Please only unlink a socket successfully bound/owned by this instance, and add a regression that closes the rejected second server before verifying that the first server still answers lookups.
