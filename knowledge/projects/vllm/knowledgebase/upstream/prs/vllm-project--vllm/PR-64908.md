# [Misc] Remove dead torch < 2.11 version checks and workarounds

[Upstream PR](https://github.com/vllm-project/vllm/pull/64908) · state: open · merged: False

## Original PR description

## Overview

All supported builds now ship torch >= 2.11 (ROCm gfx1250 is the oldest), so checks against 2.6-2.11 always take the same branch. Drop the unreachable branches, backports that only ran on older torch (including the unused patched_fused_scaled_matmul_reduce_scatter op), and the matching test skips. No behavior change on supported torch.

Assisted-By: Claude

## Claims

- Removes 540 lines of dead code (71 added, 611 removed, across 34 files) by deleting version checks for torch 2.6–2.11. 
- Every supported build now ships torch 2.11 or newer, so those checks always give the same answer.
- Removes 5 workarounds for old torch versions that no longer run on any supported build:
     - an unused custom op, patched_fused_scaled_matmul_reduce_scatter (fixed upstream in torch 2.10);
     - a copied PyTorch fix for atomic writes to the compile cache;
     - a torch 2.10-only patch to FxGraphCachePickler (the compile-cache serializer) + its test file and CI entries;
     - a workaround for FP8 weights on CPU when loading llama4;
     - a .clone() workaround in voxtral_realtime.
- Resolves stale TODOs, including the one in parallel_state.py behind [vllm-project/vllm#31470](https://github.com/vllm-project/vllm/issues/31470), which a maintainer had held until all platforms moved past torch 2.9.
- Removes about 25 test skips that could never trigger in the compile, attention and helion tests. It also fixes one test that faked torch 2.8 to exercise a path that no longer exists.
- Corrects a stale CI assumption: a test comment said ROCm CI still ran torch 2.10, but ROCm CI builds from an image with torch 2.13.

No behavior change on any supported build: each removed branch is one that couldn’t run. All pre-commit hooks, including mypy, pass.
