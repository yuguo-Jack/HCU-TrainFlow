# [Bugfix] Surface initial Cohere streaming errors

[Upstream PR](https://github.com/vllm-project/vllm/pull/61963) · state: closed · merged: False

## Original PR description



## Overview

Fix initial generation errors being silently dropped by `POST /cohere/v2/chat` with `stream=true`. Return a Cohere HTTP error response instead of HTTP 200 with only `[DONE]`.

## Claims

- Preserve the status code and message of errors in the first upstream frame.
- Preserve the first successful chunk and existing SSE behavior.
- Close the prefetched upstream generator when the response closes before body iteration or response-header delivery fails.

## Validation

Added regression tests for initial 400/503 errors, first-chunk preservation, malformed JSON, cancellation, and stream cleanup.

- Error-handling and cleanup regression cases fail without their corresponding fixes and pass afterward.
- Cohere tests excluding model integration: **234 passed**.
- HTTP and Cohere SDK integration tests with `HuggingFaceTB/SmolLM2-135M-Instruct` on an NVIDIA H800 NVL: **9 passed** (before the final malformed-JSON adjustment and rebase).
- All applicable pre-commit checks passed, including Ruff and mypy.

PATH="$PWD/.venv/bin:$PATH" .venv/bin/python -m pytest \

  tests/entrypoints/cohere/test_api_router.py

The error cases use controlled upstream frames. The model integration tests cover normal HTTP and Cohere SDK serving.

## Details

The Cohere stream converter expects `ChatCompletionStreamResponse` frames. An initial `{"error": ...}` frame fails validation before `message-start`. Since the exception handler emits an error event only after the stream starts, the client receives HTTP 200 with only `[DONE]`.

Read the first upstream frame before creating the streaming response. Return initial errors through the existing Cohere HTTP error conversion, or forward the frame to the normal converter otherwise. Malformed JSON remains on the existing conversion path.

Since prefetching starts the upstream generator before response-body iteration, ensure it is closed even if body iteration never begins or sending response headers fails.

Response headers now wait for the first upstream frame.
