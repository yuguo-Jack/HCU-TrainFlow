# [CI] Enroll 6 jobs in automatic sharding

[Upstream PR](https://github.com/vllm-project/vllm/pull/65211) · state: closed · merged: True

## Original PR description

## Overview

Enrolls 6 more jobs in `automatic_shard`. Three come from #64606 (draft until its steps pass on main): V1 KV Offload with its AMD mirror and the standalone MI300 DeepSeek-V4.1 gfx942 Mono Decode Kernels step now pass on recent main runs, so they move here and #64606 keeps only the steps still failing. The other three were not enrolled yet: B200 Qwen3.5, the MI355 Step5 mirror (its base step is already enrolled) and the standalone MI250 Batch Invariance step. No commands change.

## Claims

| Job | Plan |
|---|---|
| `v1-kv-offload` + AMD mirror | 1 shard each |
| `dsv41-mono-decode-gfx942-amd` | 1 shard |
| `qwen3-5-unit-tests-b200` | 1 shard |
| `step5-unit-tests` AMD mirror | 1 shard |
| `amd-batch-invariance-a100` | 1 shard |

- One-shard plans run the same tests as on main, as one job, and split by themselves once their tests grow.

## Validation

- Planned each job with ci-infra main's planner against main's timings.
- Every job plans one shard today, so each runs as one job with the same tests as main.
- `split_check.py` finds no step whose jobs each run the whole suite.
- Every job passed its recent main runs.
- `/ci run`, plus a scoped build for the optional and AMD jobs it leaves out, on this head.

## Details

- **Multimodal Models (Extended Generation 1) left out.** Its first build here failed one of four shards: that shard started `test_pixtral.py`'s engine right after tests that initialize CUDA in the pytest process, so the forked engine core could not initialize CUDA. On one job an earlier engine start has already switched vLLM to spawn. It needs spawn set on the command before it can shard.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job. Fallback-aware timeouts belong in a central timeout setting.
