# [Bugfix][Frontend] Reject chat turns the template silently drops

[Upstream PR](https://github.com/vllm-project/vllm/pull/59108) · state: open · merged: False

## Original PR description

## Purpose

Fixes #59090.

`/v1/chat/completions` accepts any string as a message `role`, so custom roles (`CustomChatCompletionMessageParam`) keep working. When the chat template does not emit a non-empty message, that turn used to vanish from the prompt and the request still returned 200. A typo such as `usr`, `assistan`, or `USER` silently deleted a conversation turn.

After the template renders, non-empty messages whose roles the template does not name are checked. If their content is absent from the prompt, the request fails with HTTP 400 and the error names the role. This matches `/v1/messages`, which already returns 400 for a role it does not accept. Empty and whitespace-only messages are left alone, because there is no content to drop. Roles the template actually renders, including custom roles on a catch-all template such as ChatML, still succeed.

Role allow-lists come from a Jinja2 AST walk over `.role` compares and `selectattr`/`rejectattr` filters on `role`. Structural suspects (custom-role multimodal or tool-call turns, including mixed text + tool/image) are checked in batched extra renders: text is probe-token checked, and tool/image parts are stripped in place so echoed text cannot hide a dropped payload and later turns do not shift indexes. Probe tokens use a fixed-width index so they cannot collide as substrings. Variable role compares are probed the same way as `role in allowed_roles`.

Valid requests whose roles the template already renders are unchanged, so model evaluation was not run.

This change was AI-assisted.

- Shr3yash · comment · 2026-09-29T09:15:55Z · [source](https://github.com/vllm-project/vllm/pull/59108#discussion_r4131687963)

File: `vllm/entrypoints/chat_utils.py` · line None

Structural suspects are no longer rendered one at a time.

`_roles_dropped_by_omission` removes every suspect in one extra render. If the prompt is unchanged, each of those messages was omitted and the request is a 400 naming those roles. That is the case in this finding (many custom-role image or tool-call turns the template does not emit), so the cost stays one extra render no matter how long the conversation is.

If that diff changes, existing tool-call names are stamped and checked in one more render, which clears every message the template actually prints. A new text part is not used as proof, because a template can echo it while still dropping the image or tool call. Only a mixed remainder is split, and a fully omitted subgroup is still one render rather than one per message.

24 omitted image turns take 2 renders (baseline + one diff). 24 printed tool calls take 3. Twelve omitted images plus one printed tool call take 4, and only the omitted roles are named.
