# feat(kernel): vectorize output store in AWQ dequantize_weights kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/63955) · state: closed · merged: False

## Original PR description

## Summary

This PR optimizes the CUDA  kernel () by vectorizing the output store operation.

## Problem

The kernel previously wrote each thread's 8 dequantized half-precision values as 8 separate scalar 2-byte stores, despite already holding them in a  register.

## Solution

Replace 8 scalar stores with a single 16-byte  store. The math is unchanged and output is bitwise identical.

## Changes

- Removed the unused  shared memory array and  pointer
- Replaced the loop of 8 scalar stores with a single  store

## Performance Results (H100)

| Layer (K × N) | Before | After | Speedup |
|---------------|--------|-------|---------|
| qkv_proj (4096 × 6144) | 112.7 µs | 31.7 µs | 3.56× |
| o_proj (4096 × 4096) | 52.8 µs | 21.7 µs | 2.44× |
| gate_up_proj (4096 × 28672) | 518.3 µs | 141.6 µs | 3.66× |
| down_proj (14336 × 4096) | 175.7 µs | 71.6 µs | 2.45× |

## End-to-End Impact (VLLM_BATCH_INVARIANT=1)

- TPOT at concurrency 1: **34.9 → 16.0 ms** (2.19× faster)
- Output throughput at concurrency 32: **762 → 1407 tok/s** (1.85× higher)
- GSM8K accuracy, greedy outputs, logprobs: **identical**

## Validation

- 377 tests pass (`test_awq.py`, `test_awq_triton.py`)
- New `test_awq_dequantize` validates CUDA op against PyTorch reference with exact equality (`atol=0, rtol=0`)
- Bitwise equality verified with `torch.equal` on all four layer shapes
- Default Machete path unchanged (control test)
