# [Multimodal][Docs] State that retried media downloads count toward the request budget

[Upstream PR](https://github.com/vllm-project/vllm/pull/62204) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Make it visible that `VLLM_MAX_MEDIA_REQUEST_DOWNLOAD_SIZE_MB` counts retried download attempts. As discussed above with @jperezdealgaba and @DarkLight1337, counting them is intentional: it stops a media URL that keeps disconnecting from transferring several times the limit through retries. This PR keeps that behavior and says so in the error message and in `docs/usage/security.md`.

## Claims

- The budget error now reads `Request media downloads exceed VLLM_MAX_MEDIA_REQUEST_DOWNLOAD_SIZE_MB=… (N bytes received, including retried attempts).`, so an operator seeing it for media under the limit knows why.
- The `security.md` row now says the budget includes "concurrent downloads and retried attempts".
- New sync and async tests pin the restrictive behavior: a fetch that fails mid-body and is retried is charged for both attempts and raises with that message.
- No behavior change.

## Details

This PR originally refunded a failed attempt's bytes before the retry. That was rejected for the security reason above (see @jperezdealgaba's comment and the earlier thread on #61226), and the scope was changed to documenting the behavior, per @DarkLight1337. The branch history shows both commits; the final diff is one line in `vllm/connections.py`, one line in `docs/usage/security.md`, and tests.

The test helpers in `tests/test_connections.py` now accept an exception in the chunk list, to simulate a connection dropping mid-body.

- jperezdealgaba · comment · 2026-10-18T09:10:13Z · [source](https://github.com/vllm-project/vllm/pull/62204#issuecomment-6248067627)

@DarkLight1337 We discussed this in the original MR: https://github.com/vllm-project/vllm/pull/61226#discussion_r4255672641 . If we allow this, it weaknes the security restriction we added in the original MR.
An attacker who can supply a media URL that repeatedly disconnects could make one request transfer more than VLLM_MAX_MEDIA_REQUEST_DOWNLOAD_SIZE_MB permits. With the defaults of three attempts and a 256 MiB per-response limit, a single URL could transfer roughly 768 MiB while the request budget records at most 256 MiB. Which could trigger the security advisory again.

This is mainly a design decision and we went for the most restrictive one. If needed, we can change it, but that was the decision we took
