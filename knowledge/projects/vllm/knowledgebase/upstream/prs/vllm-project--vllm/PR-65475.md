# [Bugfix][ROCm][Qwen4Exp] Bind the opaque SP wrapper in the MTP draft

[Upstream PR](https://github.com/vllm-project/vllm/pull/65475) · state: open · merged: False

## Original PR description

## Overview

Bind the opaque sequence-parallel wrapper `sp_shard` (from #61471) in the AMD MTP draft (`amd/mtp.py`), which still imports the plain helper, so that the draft compiles with `--enable-hc-sp` for Qwen4Exp on ROCm. #65407 makes the same change in `amd/ple_layer.py`.

Stacked on #65407: the first commit here is that PR's change, so review the last commit only; the branch is rebased once #65407 merges.

## Claims

- `test_compiled_sp_ops_handle_untraced_token_counts` also covers `amd/mtp.py`; with the PLE change from #65407 applied, it fails on the plain `sp_shard` import and passes with this change.
- With #61770's hunks applied, the stock draft does not start under `--enable-hc-sp`; with this change it serves. GSM8K is 0.45 / 0.53 points (strict / flexible) below the same server without hc-sp (paired SE 0.43 / 0.39; n = 1 per arm); draft acceptance is 83.8 % against 84.0 %.

## Validation

Nightly `vllm/vllm-openai-rocm:nightly-40941f2c4ba96fba0a7e282a5355e89cd74d9ac5` (0.33.0rc1.dev573+g40941f2c4; `amd/mtp.py` is blob-identical to main `cf31617992`), 2x MI355X, `amd/Qwen3.8-Flash-Next-Quark-MXFP4`.

**Unit test** (`pytest -v -s tests/models/qwen4_exp/test_tpsp.py -k compiled_sp_ops`, 2 GPUs; the AMD CI step `:amd: (MI355) Qwen4 Exp SP` selects it), with the #65407 change to `amd/ple_layer.py` in both runs: the plain `amd/mtp.py` fails (`shape` mismatch, `torch.Size([6, 16]) != torch.Size([7, 16])`); this change passes.

**Server.** Without #61770 the MTP draft does not load with this checkpoint, with or without `--enable-hc-sp`: the draft layers are built as `mtp.layers.48.*` while the Quark `exclude` names `mtp.layers.0.*`, so the draft MoE is built as MXFP4 against BF16 weights (`RuntimeError: The size of tensor a (1280) must match the size of tensor b (2560)`, `routed_experts.py:601`). Every row below applies #61770's `amd/mtp.py` hunks (head `7789493229`):

## Details

`Qwen4ExpMultiTokenPredictor` (`@support_torch_compile`) calls `sp_shard` in `forward`. The plain helper's padding branch is specialized by Dynamo on the traced token count while vLLM drops the guards (comment in `amd/ops/sequence_parallel.py`); the opaque wrapper avoids that. `sp_all_gather` stays plain (no padding branch). Under compile the wrapper clones the unpadded `sp_shard` result: one extra copy per call, not measured. The test helper adds `mtp` to its module loop; its `collectives` function includes the reduce-scatter branch only for modules that bind one (MTP binds `sp_shard` only).

ruff 0.14.0 and typos 1.51.1 pass on the changed files; mypy not run.

Limits: gfx950 only. The CUDA tree (`qwen4_exp/nvidia/*`) imports the plain helper too and is not touched. The server runs depend on #61770. The failing shape of the stock draft (2525 rows over a storage of 2524 rows) is observed; the slicing path that produces it is not traced.

Duplicates: no open PR or issue addresses this (searched on 2026-11-03: PRs touching `amd/mtp.py` and the SP helpers; issues for the failure strings). #61770 (Quark layer-name remap), #64022 and #60650 / #60657 edit other lines of `amd/mtp.py`.
