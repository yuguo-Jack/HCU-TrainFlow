# [DSv4.1][PCP] Support image input

[Upstream PR](https://github.com/vllm-project/vllm/pull/64435) · state: open · merged: False

## Original PR description

## Overview

Enable DeepSeek-V4.1 image inputs with Model Runner V2 PCP on NVIDIA GPUs, including fixed-length DSpark.

## Claims

- Use the existing encoder cache and PCP segment mapping for image inputs.
- Skip empty PCP windows so idle ranks do not request invalid image slices.

## Validation

H20 integration checks with TP1 × PCP4 and DSpark 5:

| Configuration | Image/text cases | C32/C64 cold/warm stress |
|---|---:|---|
| TP1 × PCP4, NONE | 33/33 | Not run |
| TP1 × PCP4, FULL_DECODE_ONLY | 33/33 | Not run |
| TP1 × PCP4, FULL_AND_PIECEWISE | 33/33 | Passed |

Full GSM8K on TP1 × PCP4: **1229/1319 (93.18%)**. Both extraction filters were independently rescored from all saved responses, with no preemptions. The 33 image/text cases are bounded diagnostics, not a broad visual evaluation.

<details>
<summary>Tests and validation limits</summary>

Pure-source unit suites passed **28 encoder + 9 PCP checks**; integration suites passed **12 Engram + 9 PCP + 33 indexer checks**. Ruff, mypy, and applicable local checks pass. Full pre-commit bootstrap remains incomplete because of GitHub fetch timeouts.

The existing four-B200 nightly adds one TP2 × PCP2 test for image chunking, cached image/text batches, and DSpark 5, requiring nonzero draft acceptance on image-only and mixed requests. **This exact nightly has not run.**

```bash
.venv/bin/python -m pytest -q tests/v1/worker/test_encoder_runner.py
.venv/bin/python -m pytest -q tests/v1/worker/test_gpu_pcp_manager.py -k test_validate_config
.venv/bin/python -m pytest -v -s tests/distributed/test_deepseek_v41_multimodal_pcp.py
```

GPU runs reuse a pinned precompiled native runtime. Strict `VLLM_GPU_SYNC_CHECK=error` encounters synchronization in the unchanged vision span helper; a CUDA reproducer without PCP confirms the same issue.

</details>

## Details

ViT remains replicated. PCP partitions the language-model sequence; DSpark consumes the target's image-conditioned auxiliary hidden states. Existing model restrictions still apply.

CUDA graph integration uses [#61555](https://github.com/vllm-project/vllm/pull/61555); the TP1 × PCP4 validation also uses shared Engram from [#61554](https://github.com/vllm-project/vllm/pull/61554). Those changes are separate from this PR.

Scoped open-PR searches found no duplicate: [#62802](https://github.com/vllm-project/vllm/pull/62802) concerns encoder disaggregation and [#43580](https://github.com/vllm-project/vllm/pull/43580) Qwen ViT parallelism.
