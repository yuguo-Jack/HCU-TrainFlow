# [CI][XPU] Temp increase shutdown test timeout for XPU

[Upstream PR](https://github.com/vllm-project/vllm/pull/61745) · state: closed · merged: False

## Original PR description

## Purpose

`tests/v1/shutdown` intermittently fails on Intel CI (XPU) with `Failed: Timeout (>120.0s) from pytest-timeout`, e.g. in various `tensor_parallel_size=2` cases of `test_forward_error.py`/`test_startup_error.py` (see https://buildkite.com/vllm/intel-ci/builds/14158, 14130, 14120).

XPU forces the `spawn` multiprocessing start method instead of `fork` (see `vllm/platforms/xpu.py`), which means every EngineCore/Worker subprocess re-imports the whole package and re-initializes the device runtime, instead of inheriting it via `fork`'s copy-on-write memory. That is noticeably slower and more variable than CUDA's fork-based startup, so the fixed 120s `SHUTDOWN_TEST_TIMEOUT_SEC` budget intermittently trips before the subprocesses finish starting, especially with `tensor_parallel_size=2`.

## Changes

Raise `SHUTDOWN_TEST_TIMEOUT_SEC` to 240s on XPU, keep the 120s budget unchanged for other platforms.

## Test Plan

Ran the affected suite on XPU hardware:

```
python -m pytest tests/v1/shutdown/test_startup_error.py -k "forward-2" -v
```

## Test Result

```
tests/v1/shutdown/test_startup_error.py::test_async_llm_startup_error[forward-2-hmellor/tiny-random-LlamaForCausalLM] PASSED
1 passed, 7 deselected in 47.53s
```

Confirmed via `pytestmark` introspection that the effective timeout marker is now 240s on XPU. `ruff`/`pre-commit` pass.
