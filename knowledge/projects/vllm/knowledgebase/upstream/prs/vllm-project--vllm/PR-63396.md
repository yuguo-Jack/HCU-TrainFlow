# [ROCm][Perf][DSv4] gfx1250 W4A4 MoE: fused silu + fused quant + preshuffled weights 

[Upstream PR](https://github.com/vllm-project/vllm/pull/63396) · state: open · merged: False

## Original PR description

## Purpose

On gfx1250, the AITER W4A4 MoE path (`--moe-backend aiter_triton_mxfp4_mxfp4`, `AiterW4A4ExpertsMonolithic`) runs SILU models such as DeepSeek-V4 through four kernels per MoE layer: GEMM1 with a bf16 output, `fused_clamp_act_mul`, a separate `mxfp4_quant` of the intermediate, then GEMM2. It also forces routing off TDM and gathers the input rows before GEMM1.

This PR runs SILU through the fused path AITER already provides for SWIGLUOAI, and always uses preshuffled weights:

- **Fused epilogue:** GEMM1 applies SiLU (with the clamp) in its epilogue and writes MXFP4 directly (`apply_swiglu=True, out_mx_quant=True`). Nothing runs between the two MoE GEMMs.
- **Routing and gather:** routing keeps TDM on, and GEMM1 gathers rows itself (`gather_indx`) instead of a separate pre-gather.
- **Preshuffled weights:** SILU weights are always preshuffled into the WMMA 16x16 tile order (`preshuffle_weights=True`). This is faster, and it also fixes correctness: with non-preshuffled weights, the gluon `moe_gemm_a4w4` kernel returns intermittent garbage on identical inputs at some tile configs (details below). The preshuffled kernel never did in our tests. On DeepSeek-V4 this restores gsm8k accuracy on gfx1250.

Code changes:

- `oracle/mxfp4.py`: in the `AITER_TRITON_MXFP4_MXFP4` weight prep, SILU joins SWIGLUOAI in the gate/up row interleave, which the fused epilogue reads. This is the only change to `convert_gpt_oss_weight_to_mxfp4_moe_kernel_format`.
- `experts/aiter_mxfp4_w4a4_moe.py`:
  - `AiterW4A4ExpertsMonolithic.__init__` sets `preshuffle_weights` for SILU.
  - The new `process_weights_after_loading(layer)` tile-shuffles `w13_weight` / `w2_weight` in place. The scales already have the right layout and are untouched. Preshuffled weights carry no bias, so SILU with a bias raises `NotImplementedError` on this backend.
  - `aiter_triton_kernel_w4a4_moe_forward` takes `preshuffle_weights`. It fuses the activation and output quant for SILU, drops the gfx1250 TDM-off override and the pre-gather, and computes N from the preshuffled view (`N * 16`).

**gfx1250 only: `AiterW4A4ExpertsMonolithic` is gated to gfx1250, and the oracle branch is only reached through that backend. gfx950 is unchanged.**

Tuned gluon A4W4 configs are added in the AITER PR https://github.com/ROCm/aiter/pull/6890

## Test Plan

All numbers below are on gfx1250, with the identical commit applied to ROCm's gfx1250 development branch (same patch-id).

1. Kernel accuracy: the old and new forward at DeepSeek-V4-Pro TP4 (E=384, H=7168, I=768) and Flash TP2 (E=256, H=4096, I=1024) shapes, top-k and hash routing, 1 to 16384 tokens, against fp32 references.
2. Routing: TDM on vs off, bitwise, and against a torch reference.
3. Determinism: the same forward called 100 times on identical inputs, counting outputs that differ from the first call.
4. gsm8k on DeepSeek-V4-Pro (TP4) and DeepSeek-V4-Flash (TP2): 5-shot, temperature 0, full test set (1319 questions).
5. `vllm bench serve`, random dataset, 8k/1k and 1k/1k at concurrency 16 and 64, temperature 0, `--ignore-eos`.
6. `tests/kernels/moe/test_ocp_mx_moe.py` and `tests/kernels/moe/test_rocm_aiter_moe.py`.
