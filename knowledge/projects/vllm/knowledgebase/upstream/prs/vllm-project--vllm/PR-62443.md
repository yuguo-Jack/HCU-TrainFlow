# [Bugfix][Parser] Hold partial parameter openers in streaming args

[Upstream PR](https://github.com/vllm-project/vllm/pull/62443) · state: open · merged: False

## Original PR description

  ## Overview

  Fixes a streaming/non-streaming mismatch in the Qwen3/MiMo engine tool parser.
  When an open `<parameter` opener is split across chunks, the partial opener was
  streamed into `arguments`; the non-partial converter drops it. Streamed tool
  calls could therefore carry an extra key or a truncated value.

  No existing issue: found by differential testing of the streaming and
  non-streaming parser paths.

  ## Claims

  - Streaming arguments now equal non-streaming arguments for split
    next-parameter openers: `<parameter=`, `<parameter =`, `<parameter\t=`.
  - Partial parameter names that swallowed `</parameter` are dropped consistently
    with `partial=False`.
  - The incremental (O(N)) arg-extender path is preserved.

  ## Validation

  Before (master, server-facing `parse_delta(..., finished=True)`):

  | value | non-stream | streamed |
  |---|---|---|
  | `a<parameter=b` | `{"k": "a"}` | `{"k": "a", "b</parameter": ""` |
  | `a<parameter =b` | `{"k": "a"}` | `{"k": "a<parameter "` |
  | `a<parameter\t=b` | `{"k": "a"}` | `{"k": "a<parameter\t` |

  After: all three are `{"k": "a"}`.

  Commands run:

  ```bash
  pytest tests/parser/engine -q
  # 6101 passed in 38.93s (Python 3.12, torch 2.14.0+cpu, 5a822a3c7e on 16d66734)

  pytest tests/parser/engine/test_qwen3.py -q
  # 94 passed in 1.44s

  Additional differential fuzzing: 20,000 random values/chunk sizes plus
  schema-aware coercion fuzzing, 0 streaming/non-streaming mismatches.

  The new regression test test_streaming_holds_partial_next_parameter
  exercises the server-facing parse_delta(finished=True) path for both qwen3
  and MiMo, with 4 malformed values and 5 chunk sizes. It fails 8/8 on master
  before the fix and passes after.

  Local pre-commit: ruff-check and ruff-format pass. The full pre-commit run
  could not install the actionlint Go environment because this machine cannot
  reach proxy.golang.org; this is unrelated to the changed Python files.

  No model evaluation is included: this change only affects how already-generated
  text is parsed in streaming mode, not model weights, logits, or sampling. The
  parser output-equivalence tests above cover the behavior change.

  Details

  _param_value_extender assumed the trailing potential-tag window had already
  been emitted, so it either leaked that window (when it completed as a tag) or
  dropped it (when it did not). _split_open_value() now separates the stable
  prefix from the pending suffix; the pending suffix is held until it is known
  not to be a tag. The partial converter uses the same split, and malformed
  partial names containing </ are skipped so they match the non-partial
  converter.

  Related: #55497 tightens the parameter-name regex and fixes the <parameter=b
  name-swallow variant. I applied its regex-only change locally and confirmed it
  still leaves <parameter =b and <parameter\t=b leaking the opener into the
  streamed value; this change covers both. If #55497 lands first, I will rebase
  and keep the holdback logic.
