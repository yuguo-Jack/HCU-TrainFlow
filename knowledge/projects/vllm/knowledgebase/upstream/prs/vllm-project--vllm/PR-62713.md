# [DeepSeek][ROCm] V4.1-Flash: enable --monokernel on MI325X

[Upstream PR](https://github.com/vllm-project/vllm/pull/62713) · state: closed · merged: True

## Original PR description

## Summary

Turn `--monokernel` on for the MI325X tensor-parallel recipe. gfx942 mono decode landed in #60731 and uses the same flag as MI355X. MI300X is left unchanged.

From #60731: the kernels run at TP4 only, on decode steps of up to 42 rows (7 requests with five DSpark drafts). With their weight copies included, that PR measured 170.11 GiB of weights a rank, up from 98.88 GiB. On MI325X at `--gpu-memory-utilization 0.9` the KV pool still held 11.18 million tokens. The same 0.9 cap on a 192 GiB MI300X leaves about 2.7 GiB beside those weights, so the flag stays off there.

`0.31.0` rejects `--monokernel`, so the MI325X pip tab is hidden, as on MI355X. The first ROCm 10.0 nightly with #60731 is `nightly-rocm100-df3bd094aeea829f27baa0a5282830464f601d9f`.

## Test plan

- [x] Parsed the YAML. MI325X `single_node_tp` passes `--monokernel` and sets `install.pip: false`. MI300X does neither. MI355X is unchanged.
- [ ] The Recipes workflow passes. It runs `scripts/validate-source.mjs` on `recipes/`.
