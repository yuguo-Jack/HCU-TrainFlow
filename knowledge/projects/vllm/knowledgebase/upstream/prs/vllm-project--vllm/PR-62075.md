# [Bugfix][Spec Decode] Load excluded EAGLE3 NVFP4 embeddings as BF16

[Upstream PR](https://github.com/vllm-project/vllm/pull/62075) · state: open · merged: False

## Original PR description

## Overview

Related to #62028. Serving `nvidia/Gemma-4-31B-IT-NVFP4` with `AEON-7/gemma-4-31B-it-speculator.eagle3-NVFP4` crashed while copying a BF16 `lm_head` row of width 5376 into a packed NVFP4 parameter of width 2688.

## Claims

- Speculators extraction copies the outer `quantization_config` onto the draft config and leaves the caller's `transformer_layer_config` unchanged.
- Flat ModelOpt configs honor `exclude_modules`, and fall back to compressed-tensors `ignore` only when `exclude_modules` is absent. Excluded `embed_tokens` and `lm_head` stay unquantized. `kv_cache_quant_algo` is normalized to uppercase.
- Draft loaders pin `quant_config` after `VllmConfig` construction. `replace()` reruns `__post_init__`, which would otherwise refill a missing quant config from the target model.
- When a draft has both `d2t` and a bool `t2d`, load fails unless every draft id lands on a distinct `t2d` target. Extra `t2d` marks warn. A non-bool `t2d`, or a missing tensor, skips the check.

SM120 results are from @waynehacking8 on main `153a17166e` plus the load fix, and were not re-run here:

- The 2688 vs 5376 mismatch is gone, and greedy target completions match.
- The published draft accepts about 7% (mean length 1.29 at 4 speculative tokens). Its `d2t` is a BF16 round trip of `RedHatAI/gemma-4-31B-it-speculator.eagle3`: 30,732 of 32,000 draft ids are wrong, while `t2d` is intact. Restoring only `d2t` raises acceptance to 62% (mean length 3.50, against 3.58 for the BF16 source).
- Single-stream chat throughput is 93.7 tok/s against 40.9 without a draft, at the same chat GSM8K (0.984).

The vocab-map check then refuses that published NVFP4 checkpoint until `d2t` is restored. There is no env-var override.

```bash
vllm serve nvidia/Gemma-4-31B-IT-NVFP4 \
  --quantization modelopt \
  --kv-cache-dtype fp8 \
  --speculative-config '{"method":"eagle3","model":"AEON-7/gemma-4-31B-it-speculator.eagle3-NVFP4","num_speculative_tokens":4,"draft_tensor_parallel_size":1}'
```

## Details

The crash is the excluded `lm_head`. ModelOpt NVFP4 applies a packed linear method to `LinearBase` and `ParallelLMHead`. `VocabParallelEmbedding` does not get that method. The draft stores ModelOpt metadata on the outer speculators `config.json`, with `exclude_modules: ["lm_head", "embed_tokens"]`. `embed_tokens.weight` is BF16 `[262144, 5376]` and `lm_head.weight` is BF16 `[32000, 5376]`. Linear weights are packed NVFP4.

Extraction kept only `transformer_layer_config`, so the draft lost that quant block. The flat parser read compressed-tensors `ignore` and dropped `exclude_modules`. The weight loader then copied a BF16 row into a packed parameter.

The draft already resolved its own quant config through `get_draft_quant_config()`. It did not inherit the target scheme. Pinning after construction keeps an explicit `None` from being replaced by the target config still attached during draft setup.

`d2t[i]` is the offset from draft id `i` to target id `i + d2t[i]`. Sampling uses only `d2t`. `t2d` is a bool mask, so `d2t` cannot be rebuilt from it. A BF16-rounded `d2t` still loads on main and proposes the wrong tokens. This check rejects that case. It does not fix the #62028 shape mismatch, and the published AEON-7 checkpoint still does not load until `d2t` matches `t2d`.

This is not #49900 (compressed-tensors `draft_model` prefix) and not #59040 (MTP fc quantization). No other open PR covers this exclude path.
