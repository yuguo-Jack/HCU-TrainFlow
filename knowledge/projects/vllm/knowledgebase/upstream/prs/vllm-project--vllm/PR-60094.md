# [Spec Decode] Expose placeholder text for synthetic acceptance

[Upstream PR](https://github.com/vllm-project/vllm/pull/60094) · state: open · merged: False

## Original PR description

## Overview

Render explicit placeholder text for synthetic speculative acceptance in offline generation and OpenAI Chat Completions/Completions. Addresses https://github.com/vllm-project/vllm/issues/59750 (Option 2).

## Claims

- Return `"synthetic "` once per delivered output token ID while retaining real token IDs, detokenization, and stop checks.
- Bypass chat output parsers for synthetic responses and mark successful HTTP responses with `x-vllm-synthetic-output: true`.
- Reject structured output, required/named tool calls, generated-output API logprobs, prompt echo, and beam search where placeholder text would violate the request contract.
- Reject transcription, translation, and realtime speech-to-text before generation because these adapters consume generated text as semantic output.

## Details

Synthetic acceptance can generate IDs that decode or parse to no visible content, causing benchmark clients to reject an otherwise completed request. The replacement occurs after the existing delta/cumulative ID selection in `RequestState._new_completion_output()`. Real decoding and stop detection remain active. Beam search reconstructs text after that substitution, so synthetic-mode beam requests are rejected at both OpenAI generation endpoints and in offline `LLM.beam_search()`. Generative scoring rejects synthetic mode before generation while allowing existing mock-based normal-mode tests without a `vllm_config` attribute. Speech-to-text adapters require semantic generated text and are rejected before engine generation, including realtime transcription. The placeholder is benchmark text, not model content; use server-reported token counts rather than retokenizing it.

This differs from open PR https://github.com/vllm-project/vllm/pull/59650, which selects synthetic acceptance length per request but does not define an output-presentation policy. An open-PR search for `59750 in:body` found no match.

The placeholder changes response size and visible-content timing. Clients that append it to later prompts change prompt lengths and cache behavior. No speedup or output-quality claim is made.
