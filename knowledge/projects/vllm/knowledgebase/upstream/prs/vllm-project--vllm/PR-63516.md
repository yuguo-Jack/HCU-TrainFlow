# [Perf][Kernel] Use a 32-wide swapAB tile for SM100 block FP8 at M 33-64

[Upstream PR](https://github.com/vllm-project/vllm/pull/63516) · state: open · merged: False

## Original PR description



## Overview

On SM100, block-FP8 GEMMs with 33-64 tokens use the swapAB kernel with a 16-wide token tile, which re-reads the weights every 16 tokens. This uses a 32-wide tile for that range. M <= 32 and M > 64 are unchanged.

## Claims

- Decode on `Qwen/Qwen3.8-27B-FP8`, 1xB200: 1.36x faster step at batch 64, 1.11x at batch 48.
- `cutlass_scaled_mm` 1.05-1.83x faster at M 33-64 on the model's GEMM shapes, with identical output.

## Validation

```text
pytest tests/kernels/quantization/test_block_fp8.py -k cutlass -> 7 passed (adds M=33, 64)
```

`LLM.generate`, 128 input tokens, step = (T(out=128) - T(out=1)) / 127. main / PR / PR / main runs, spread < 0.05 ms. Kernel times: CUPTI, CUDA graph, cold L2, 2 rounds per tree.

| Qwen3.8-27B-FP8, 1xB200 | main | PR |
|---|---|---|
| decode step bs1 / 32 | 9.36 / 11.75 ms | 9.35 / 11.74 ms |
| decode step bs48 / 64 | 13.91 / 18.47 ms | **12.52 / 13.56 ms** |
| gemm M=64: qkv / o / gate_up / down (us) | 37.1 / 24.4 / 68.4 / 58.3 | 24.0 / 14.7 / 43.3 / 31.9 |

## Details

SM103 shares this dispatch but was not measured.
