# [Bugfix] Restrict large batch defaults to CUDA GPUs

[Upstream PR](https://github.com/vllm-project/vllm/pull/54043) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Restrict the >=160 GiB batch-default tier to CUDA GPUs, preserving the existing non-CUDA tier. Refreshed against main `c5f8adc0`; related to #53961.

## Claims

- Retain 16384 server tokens for CUDA B200-class devices while using the existing 8192 tier for the mocked MI300X.
- Update the existing platform fixture for main's GB10 capability detection instead of treating an unconfigured MagicMock result as true.

## Validation

- `.venv/bin/python -m pytest tests/engine/test_arg_utils.py -k large_memory_defaults_are_cuda_only -q` — **2 passed**.
- The MI300X regression fails against unmodified main production code (`16384` instead of `8192`); the CUDA control passes.
- Pre-commit on both changed files and `git diff --check origin/main...HEAD` — **passed**.
- An additional prefix-cache CLI test could not infer a device on this host. No real MI300X/B200 startup, memory or throughput evaluation ran here.

## Details

The >=160 GiB branch is described as targeting B200/B300 but currently selects devices by capacity alone. The patch adds a CUDA predicate and retains main's separate GB10 detection and all other tiers.

#53961 is closed after deployment/EP guidance, so this PR does not claim that issue remains open or that it resolves the full reported 1M-context startup failure. The narrower default-policy mismatch remains observable in the CPU regression; reviewer confirmation of the intended policy is requested.

Duplicate check: re-read the issue and searched open PRs by issue number and CUDA batch defaults; no competing open fix for this predicate was found. Open since 2026-08-27. AI assistance was used, with signed-off, signed commits and Codex attribution. Human review and hardware validation remain required.
