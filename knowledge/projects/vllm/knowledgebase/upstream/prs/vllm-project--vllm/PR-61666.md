# [Quantization] Support compressed-tensors MXFP6 (mxfp6-pack-quantized)

[Upstream PR](https://github.com/vllm-project/vllm/pull/61666) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Load compressed-tensors `mxfp6-pack-quantized` checkpoints: MXFP6 (E2M3) weights with dynamic MXFP8 or 16-bit activations, routed to the existing MXFP6 linear kernels (Humming on CUDA). This follows @gau-nernst's [Qwen3.8-27B-MXFP6](https://huggingface.co/gaunernst/Qwen3.8-27B-MXFP6) Quark checkpoint, which showed MXFP6 MLPs + MXFP8 elsewhere fit a 27B model on a 32 GB GPU.

**Draft:** depends on MXFP6 support in compressed-tensors, vllm-project/compressed-tensors#941 (`num_bits=6` float = E2M3, `mxfp6-pack-quantized` format, `MXFP6A8`/`MXFP6A16` presets). LLM Compressor examples are in vllm-project/llm-compressor#3286. The pinned `compressed-tensors==0.17.0` rejects a 6-bit float config while parsing, so this needs a compressed-tensors release and a pin bump before it can merge.

## Claims

- New `CompressedTensorsW6A8Mxfp6` scheme for MXFP6 weights (4 values packed in 3 bytes, uint8 E8M0 scales, group 32). It takes its activation precision from the checkpoint: dynamic MXFP8 or none; anything else raises.
- Mixed MXFP6/MXFP8/FP8 compressed-tensors checkpoints (e.g. Qwen3.8-27B) load and run with torch.compile and CUDA graphs at TP=1 and TP=2.
- The packed layout is byte-identical to the Quark MXFP6 export that the Humming path already serves.

## Validation

[nm-testing/Qwen3.8-27B-MXFP6A8](https://huggingface.co/nm-testing/Qwen3.8-27B-MXFP6A8): MXFP6A8 MLP + MXFP8 attention/GDN/MTP + FP8 per-channel `lm_head`, made with LLM Compressor's `model_free_ptq` (RTN, no calibration). GSM8K on one B300, `tests/evals/gsm8k/gsm8k_eval.py`, 5-shot, greedy, 1319 questions, `vllm serve <model> --max-model-len 8192 --language-model-only`:

| Model | GSM8K |
|---|---|
| Qwen/Qwen3.8-27B (BF16) | 0.782 |
| nm-testing/Qwen3.8-27B-MXFP6A8 | 0.770 |

- Kernel selection: 128 MXFP6 linears use `HummingMxFp6LinearKernel`, 128 MXFP8 linears use `FlashInferCutedslMxfp8LinearKernel`, and `lm_head` uses `CompressedTensorsW8A8Fp8`. Generation is coherent with torch.compile + full CUDA graphs at TP=1 and TP=2.
- Layout check: given the same scales, the compressed-tensors packed weights are byte-identical to `gaunernst/Qwen3.8-27B-MXFP6`, and `humming.ops.weight.unpack_weight(..., 6)` decodes the same codes.
- `pytest tests/quantization/test_compressed_tensors.py::test_compressed_tensors_mxfp6` ([nm-testing/Qwen3-0.6B-MXFP6A8](https://huggingface.co/nm-testing/Qwen3-0.6B-MXFP6A8)) and `::test_compressed_tensors_mxfp4`: pass.

## Details

- Mirrors `CompressedTensorsW4A4Mxfp4` (packed `weight_packed` renamed to `weight` after loading) and reuses `init_mxfp6_linear_kernel`, so CUDA gets Humming and other platforms get the existing emulation fallback. The packed dim shards cleanly under TP because K per partition stays a multiple of 32.
- The scheme is named `W6A8` like the other MX schemes, and also serves weight-only (`MXFP6A16`) checkpoints.
- Not a duplicate: no open vLLM PRs cover compressed-tensors MXFP6. Existing MXFP6 support is Quark-only.
- Humming 0.1.16 works under torch.compile for this path on B300 without the custom-op wrapper in gau-nernst/vllm@sm120-mxfp6. That change may still be needed on SM120 and is independent of this PR.
- AI assistance (Claude Code) was used. I reviewed the diff and ran the validation above.
