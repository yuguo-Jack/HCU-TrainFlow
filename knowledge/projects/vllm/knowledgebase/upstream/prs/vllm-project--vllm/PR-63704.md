# [Spec Decode] Add DSpine adjacent-causal-injection drafts

[Upstream PR](https://github.com/vllm-project/vllm/pull/63704) · state: open · merged: False

## Original PR description



## Overview

Adds DSpine speculative decoding: a DFlash-family drafter that injects each
layer's predecessor features into the next row and re-scores the final write
per candidate pair. Reference implementation:
[tencent/dspine](https://github.com/tencent/dspine) (Apache-2.0);
paper: [arXiv 2609.36173](https://arxiv.org/abs/2609.36173); checkpoint:
[tencent/Qwen3-8B-DSpine-b16](https://huggingface.co/tencent/Qwen3-8B-DSpine-b16).

Searching `vllm-project/vllm` for `dspine` returns no open issue or PR, and no
code in `main` mentions it, so this does not duplicate existing work. DFlash
support itself is already in `main`; this change only adds the DSpine draft
model, its transition scoring, and the dispatch points.

## Claims

- Supports `Qwen/Qwen3-8B` + `tencent/Qwen3-8B-DSpine-b16` on Model Runner V2
  with `--speculative-config '{"method":"dspine","model":...,"num_speculative_tokens":15}'`.
- Greedy output matches non-speculative decoding token for token.
- Higher acceptance length and throughput than the DFlash drafter on the same
  target and hardware (L20D, BF16, single GPU).

The CPU tests compare the bridge and the transition table against independent

validation, checkpoint loading, causality resolution, and speculator routing.

### GPU validation (outside CI: no L20D runner and no checkpoint in CI)

On one NVIDIA L20D (32 GB, sm_120), vLLM 0.31.0 / torch 2.13:

| Check | Result |
| --- | --- |
| Fused Triton bridge vs eager path, BF16, anchor rows preserved | pass (raw bit-identical, mean abs error < 1e-3) |
| `score_transitions` vs float64 reference, BF16 weights | max abs error 4.3e-07 |
| Greedy equivalence, 20 prompts x 128 tokens, `temperature=0` | 20/20 identical with `VLLM_BATCH_INVARIANT=1`; 13/20 with default numerics |
| Acceptance length, 20 short prompts | tau = 4.49 |
| Acceptance length, 16 technical prompts x 256 tokens | tau = 3.38 (DFlash 2.44) |

Greedy divergence without `VLLM_BATCH_INVARIANT=1` is BF16 batch-shape
sensitivity between 16-token verification and single-token decode, not an
acceptance error: repeated runs are deterministic and the batch-invariant run
matches exactly. The per-position acceptance rates also favour DSpine at every
position (`0.774, 0.589, 0.359, 0.234, ...` vs DFlash `0.640, 0.372, 0.192,
0.100, ...`).

### Throughput

Qwen3-8B BF16, 256 output tokens, single L20D, greedy:

| Configuration | Concurrency 1 | Concurrency 8 | tau |
| --- | --- | --- | --- |
| No speculation | 97.7 tok/s | 722.9 tok/s | - |
| **DSpine** | **257.8 tok/s** | **1296.2 tok/s** | 3.38 |
| DFlash | 167.8 tok/s | 1062.8 tok/s | 2.44 |

DSpine is 2.64x / 1.79x over no speculation and 1.54x / 1.22x over DFlash at
concurrency 1 / 8. Gains narrow at high concurrency because 16-token
verification costs more on a consumer-class card and acceptance decays with
position.

## Details

**Model.** `DSpineQwen3ForCausalLM` subclasses `DFlashQwen3ForCausalLM`. The
code bridge stores `codebook`, per-layer read weights, the packed
`[gate; predecessor_gate; prev]` projection, and per-layer write weights under
`selected_prefix_bridge.*`, matching the reference checkpoint layout. After each
active layer it forms `raw = hidden + residual`, reads `sqrt(C) * normalize(R_l
* raw)`, uses `sqrt(C) * codebook[anchor]` on anchor rows, computes
`sigmoid(q + s_prev + b) * v_prev`, writes `raw + rms * W_l * message`, and
fuses the next layer's input RMSNorm (the final norm on the last layer). An
eager path and four Triton kernels share rounding points; the fused path runs
for BF16 CUDA activations.

**Scoring.** `score_transitions` rebuilds the last write in fp32 for every
sender/candidate pair and returns `[batch, steps, K, K]` logits. It keeps the
`[batch, steps, K, hidden]` refined states implicit by working in the bridge
rank space, and skips the final-norm denominator for greedy proposals because a
positive per-sender scale cannot change the argmax. `DSpineSpeculator` inherits
`DFlash2Speculator` and only overrides the model run and candidate scoring, so
the candidate walk, draft-logit cache, and rejection sampling are shared.

**Dispatch.** `method="dspine"` is normalized to `dflash`; a draft whose
`dflash_config` carries `selected_prefix_code_bridge`, or whose architecture is
`DSpineDraftModel`, is rewritten to `DSpineDraftModel` and dispatched to
`DSpineSpeculator`. Checkpoints carrying a bridge are rejected under any other
method rather than silently served without the bridge.

**Limitations.** Tensor parallel size 1 only, unquantized row-contiguous BF16
or FP32 target LM head, no FP4 KV cache, and `num_speculative_tokens` must equal
the trained `block_size - 1` (15 for the released checkpoint). Model Runner V1
is rejected, matching the other candidate-head drafters.

**Tradeoffs.** The `[batch, steps, K, K]` table is computed in fp32 per draft
step, which costs more than DFlash2's single edge projection; the measured
acceptance gain pays for it at low-to-moderate concurrency, but the benefit
narrows under heavy batching. A fused transition kernel is a follow-up.

human reviewed every changed line and ran the tests and GPU validation above.
