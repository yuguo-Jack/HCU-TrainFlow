# [Bugfix][PCP] Align MoE routing padding with gathered tokens

[Upstream PR](https://github.com/vllm-project/vllm/pull/60946) · state: closed · merged: True

## Original PR description

## Purpose

The non-all-to-all PCP path gathers hidden states and router logits across PCP ranks, but the router still reads the rank-local padding mask. With N local rows and P PCP ranks, routing processes P*N rows while the mask still has N entries. CUDA top-k checks that the mask length matches the token count and can raise an `is_padding` size mismatch.

This PR aligns the MoE padding mask with the PCP-gathered token rows and restores the original rank-local mask in a `finally` block. The dispatch/combine interfaces and PCP1/all-to-all paths remain unchanged. Regression tests cover PCP1/2/4, the all-to-all bypass, per-forward caching, and exception cleanup.

A search of open PRs covering PCP padding, PCP MoE, and the relevant padding-cache key found no equivalent fix. Nearby PRs #53639, #60049, and #56258 address different paths.

## Implementation

- Non-all-to-all PCP routing receives a padding mask with the same rank-major layout and row count as the gathered hidden states.
- The original local padding mask is restored on normal and exceptional exits.
- The gathered mask is cached per forward context and reused across MoE calls.

### Result

**Without this fix** (baseline): 
With the unmodified image and model, all seven native weight shards loaded (29.34 GiB per rank). The unpatched run then failed during vLLM's standard startup memory profiling, before the API server became ready:

```text
RuntimeError: .../topk_softmax_kernels.cu:785, is_padding size mismatch, expected: 4096
```

**With this PR**:
Applying the `_sequence_parallel_context` change from this PR at startup allowed the TP2/PCP2 deployment to start and generate successfully. It passed all five chat smoke requests, including a 2,235-token input and concurrent requests of different lengths.

Using the official `tests/evals/gsm8k/gsm8k_eval.py` scoring logic, we evaluated all 1,319 test examples with 5-shot prompts, temperature=0, seed=42, `max_tokens=256`, and concurrency=4. Results:

| Baseline + TP4/PCP1 | 1191/1319 (90.2957%) | 0 | Full evaluation completed; 0 API errors and 0 Pod restarts |
| Baseline + TP2/PCP2 | Could not run | — | Failed during startup profiling with the padding-size mismatch above |
| This PR applied + TP2/PCP2 | 1197/1319 (90.7506%) | 0 | Full evaluation completed; 0 API errors and 0 Pod restarts |
