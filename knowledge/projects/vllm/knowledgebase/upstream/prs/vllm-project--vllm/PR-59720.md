# [Test] Skip FP8 Triton kernel tests on pre-SM89 CUDA GPUs

[Upstream PR](https://github.com/vllm-project/vllm/pull/59720) · state: open · merged: False

## Original PR description

## Purpose

On pre-SM89 CUDA GPUs (Ampere/Turing, e.g. A10, RTX 3090, A100), several FP8 kernel tests fail because Triton's native `fp8e4nv` type requires compute capability 8.9+. These are test-side failures, not product bugs: vLLM already rejects or falls back for these configurations at runtime (for example, the Triton attention backend raises a clear error for an FP8 KV cache below SM89 in `vllm/v1/attention/backends/triton_attn.py`).

This PR makes these tests skip the unsupported FP8 Triton paths on pre-SM89 CUDA GPUs, or assert the intended fallback behavior. It changes tests only. Behavior on SM89+ is unchanged: every new condition is gated on `not current_platform.has_device_capability(89)`, following the existing idiom (e.g. `tests/kernels/attention/test_prefix_prefill.py`).

## Changes

- `tests/kernels/attention/test_cache.py`: skip the Triton implementation with an FP8 KV cache below SM89.
- `tests/kernels/attention/test_merge_attn_states.py`: skip the FP8-output cases below SM89.
- `tests/kernels/moe/test_fp8_tp_loading.py`: for `backend="triton"` below SM89, assert the padded TP layout (`tp_shard_with_padding`, `[128, 128]` blocks) that the runtime intentionally uses there, instead of the refined layout.
- `tests/kernels/quantization/test_per_token_group_quant.py`: add one `requires_fp8_triton` skip marker and apply it to the six FP8 tests that use Triton FP8 (the int8 tests are unaffected).
- `tests/v1/attention/test_mla_backends.py`: drop `TRITON_MLA` from the FP8 KV cache backend candidates below SM89.
