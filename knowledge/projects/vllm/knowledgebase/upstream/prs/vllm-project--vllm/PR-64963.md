# [Bugfix] Preserve cross-encoder pair boundaries during explicit truncation

[Upstream PR](https://github.com/vllm-project/vllm/pull/64963) · state: open · merged: False

## Original PR description

## Overview

Preserve tokenizer-added delimiters and aligned segment IDs when cross-encoder scoring explicitly truncates a query/document pair from the left or right. Related to #61359.

#61363 explicitly excludes cross-encoder pairs. The actual diffs of #61363, #61524, #62783, #63146, #63625 and #62691 were checked; none covers this pair-tokenization fix. Their head/base revisions and issue feedback were refreshed on 2026-11-01, together with open-PR searches.

## Claims

- Keep pair delimiters when the budget can fit them, with aligned token-type IDs.
- Preserve the tail/head of the combined content for explicit left/right truncation; this is not HF `longest_first`.
- Retain unspecified-side behavior and legacy zero/insufficient-budget slicing. No ranking-quality or performance improvement is claimed.

## Details

The previous post-tokenization slice could remove `[CLS]`/`[SEP]` from an already composed pair. The fix obtains the special-token mask during the existing tokenizer call, applies the content budget, and uses the same retained indices for input IDs and token-type IDs. It adds 38 production lines, with no extra tokenizer call, global tokenizer mutation, model-runner change or dependency.

Query/document limits still apply before the combined limit. Empty documents retain the tokenizer's single-input behavior. Score templates and `add_special_tokens=False` receive no new delimiter guarantee. Too-small budgets retain the old fallback. These boundaries are documented in the scoring guide.
