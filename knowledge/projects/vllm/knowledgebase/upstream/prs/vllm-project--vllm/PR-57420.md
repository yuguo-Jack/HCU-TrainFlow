# [Kernel][MiniMax-M3] Add Triton query-tiled sparse prefill tuned on Hopper

[Upstream PR](https://github.com/vllm-project/vllm/pull/57420) · state: open · merged: False

## Original PR description

## Purpose

MiniMax-M3 sparse prefill currently launches one Triton program per query token. Adjacent queries often select overlapping sparse KV blocks, so this PR adds an opt-in query-tiled kernel that:

- groups adjacent queries into one program,
- enumerates the distinct union of their selected blocks,
- loads each union K/V block once, and
- gates each block by per-query membership and causality.

Hopper selects the tiled prefill kernel automatically; other CUDA architectures continue to use the generic scalar kernel. The decode kernel now validates persistent top-k block IDs before dereferencing the block table, which makes mixed chunked-prefill/prefix-reuse batches safe.

This is not a duplicate of the open MiniMax-M3 sparse-attention work:

- #52963 targets ROCm/gfx950.
- #55372 targets query-tiled verify-decode attention, while this PR targets prefill.

AI assistance was used to implement, test, benchmark, and prepare this change. The human submitter reviewed the complete diff and approved submission.

## Test Plan

Correctness (H100 Buildkite):

```bash
pytest -v -s tests/kernels/attention/test_minimax_m3.py
```

This existing H100 kernel shard tracks changes under `vllm/models/minimax_m3/nvidia/` and runs the CUDA parity test directly. It covers partial query tiles, mixed request lengths and prefixes, selected-block membership, non-identity paging, and both NHD and HND KV layouts.

Lint:

```bash
pre-commit run --files \
  vllm/models/minimax_m3/nvidia/ops/sparse_prefill.py \

```

The one-off microbenchmark harness is not included in the tree. The H200 matrix covers the original scalar, standalone tiled, and PR implementations; tile sizes 1/2/4/8/16/32; six prefill geometries; BF16 and FP8 KV; and 16/8/0 shared selections out of top-k 16.

## Test Result

### Correctness

- CUDA parity coverage is in `tests/kernels/attention/test_minimax_m3.py` and runs in the H100 Buildkite kernel shard.
- Coverage includes partial query tiles, mixed request lengths and prefixes, selected-block membership, non-identity paging, and NHD/HND KV layouts.
- H200 maximum absolute error across the benchmark matrix: `0.0009765625`.
- Pre-commit passed.

### H200 kernel microbenchmarks

Median speedup over the original single tile kernel across six shapes:

| KV dtype / shared top-k | Best representative tile | Median speedup |
| --- | ---: | ---: |
| BF16 / 16 of 16 | 8 | 4.49x |
| FP8 / 16 of 16 | 16 | 5.37x |
| BF16 / 8 of 16 | 8 | 1.16x |
| FP8 / 8 of 16 | 2 | 1.20x |

Representative high-overlap results:

- batch 32, q256, BF16: `1.0259 ms -> 0.2252 ms` with tile 8, or 4.56x.
- long-context FP8: approximately 5.37-5.39x with tile 16.

### E2E Prefill-focused SPEED-Bench

A matched scalar/tiled A/B used the full `speed_bench_throughput_8k_low_entropy` split on TP8 H200. Each independent trial ran 512 conversations with fixed OSL 256, temperature 0, seed 42, `min_tokens=256`, and `ignore_eos=true`. Scalar and tiled runs processed identical totals of 2,870,600 input tokens and 131,072 output tokens with zero request errors. Median ISL was 8,223 tokens (mean 5,606.6).

| Concurrency | Scalar input tok/s | Tiled input tok/s | Gain | Request latency | ITL |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 14,458 | 15,108 | **+4.50%** | -4.29% | -6.35% |
| 16 | 17,365 | 18,248 | **+5.09%** | -4.87% | -5.84% |

### E2E Fixed ISL/OSL

One scalar sweep and one tile-16 sweep were run with MiniMax-M3-MXFP8, TP8 on one 8xH200 node per sweep. The AIPerf workload used fixed synthetic ISL 8102 (8278 server-counted tokens after chat templating), fixed OSL 1024, no shared prefix, temperature 0, seed 42, `min_tokens=1024`, and `ignore_eos=true`. Every request produced exactly 1024 tokens, and scalar/tiled total output-token counts matched at every concurrency.

| Concurrency | Requests | Scalar output tok/s/GPU | Tiled output tok/s/GPU | Gain |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 12 | 36.48 | 36.81 | +0.9% |
| 2 | 12 | 57.16 | 57.63 | +0.8% |
| 4 | 12 | 84.79 | 86.75 | +2.3% |
| 8 | 24 | 118.83 | 123.46 | +3.9% |
| 16 | 48 | 153.29 | 159.76 | +4.2% |
| 32 | 96 | 216.00 | 227.58 | +5.4% |
| 64 | 192 | 264.05 | 281.50 | +6.6% |

Tile 16 improves output throughput at every measured concurrency. At concurrency 64-256, it improves output throughput by 6.6-6.8%, average TTFT by 6.6-8.2%, and average ITL by 5.9-6.2%.
