# [Docs] Fix outdated model forward/execute time section in metrics design doc

[Upstream PR](https://github.com/vllm-project/vllm/pull/60150) · state: open · merged: False

## Original PR description



## Overview

The "OpenTelemetry Model Forward vs Execute Time" section of `docs/design/metrics.md` says the current implementation exposes `vllm:model_forward_time_milliseconds` and `vllm:model_execute_time_milliseconds`. Neither exists in V1. This updates the section to match the code.

cc @markmc

## Claims

- The two metric names no longer appear anywhere outside `docs/`.
- The three span attributes in the section's sample trace (`gen_ai.latency.time_in_scheduler`, `time_in_model_forward`, `time_in_model_execute`) are still defined in `vllm/tracing/utils.py` but never set.
- `--collect-detailed-traces` only feeds `ObservabilityConfig.collect_model_forward_time` and `collect_model_execute_time`, which have no readers, so the flag no longer changes what is traced.
- The section now says what the V1 request span records instead (`time_in_model_prefill`, `time_in_model_decode`, `time_in_model_inference`).

Docs only, no code changes.

## Details

I kept the section rather than deleting it, because its closing paragraph is still an open question (whether finer-grained timings are worth the overhead). The diff only changes tense and adds what V1 records today. The quoted help text is unchanged since it still matches the current docstring.

Checked for overlap with open PRs: #54830 also edits this file but only the LoRA section, and #32573 adds new tracing attributes but does not set the forward/execute ones. Neither covers this section.

If it would help, I can follow up with a PR that either deprecates `--collect-detailed-traces` or wires the timings back up, whichever maintainers prefer.
