# [Bugfix][MoE] Handle empty routing in moe_permute

[Upstream PR](https://github.com/vllm-project/vllm/pull/61606) · state: closed · merged: False

## Original PR description

## Overview

Fixes #58789. `moe_permute` crashes the process with SIGFPE when it is called with zero tokens and an `expert_map`.

Supersedes the stale #58790, whose patch targets `csrc/libtorch_stable/moe/...`, a path that moved to `csrc/moe/...` in #60721. cc @arcusbuilds

## Claims

- `moe_permute` no longer divides by zero / crashes for an empty batch (0 tokens), with or without the reusable scratch buffers.
- Adds `test_moe_permute_empty_routing` regression coverage for both code paths.

## Validation

Reproduced on HEAD `d5e62627a3` (RTX 4090, CUDA 13.2): with 0 tokens and a non-trivial `expert_map`, the process dies with SIGFPE (exit 136).

```python
import torch
import vllm._moe_C_stable_libtorch  # noqa: F401
from vllm.model_executor.layers.fused_moe.moe_permute_unpermute import moe_permute

n_expert, n_hidden, topk = 16, 2048, 2
hidden_states = torch.empty((0, n_hidden), dtype=torch.bfloat16, device="cuda")
topk_ids = torch.empty((0, topk), dtype=torch.int32, device="cuda")
expert_map = torch.arange(n_expert, dtype=torch.int32, device="cuda")
moe_permute(hidden_states, None, topk_ids, n_expert, expert_map=expert_map)
```

- With this patch the call returns cleanly: `permuted_hidden_states.shape == (0, n_hidden)`, `expert_first_token_offset == 0`, and `inv_permuted_idx` / `permuted_idx` are empty.
- `test_moe_permute_empty_routing` passes with the patch and kills the pytest process with SIGFPE without it.
- Existing correctness tests in `tests/kernels/moe/test_moe_permute_unpermute.py` pass. (Full-file run on my single 24 GB card: 321 passed; the remaining 136 failures are CUDA-graph OOM caused by another tenant holding ~20.5 GB, unrelated to this change.)

## Details

Root cause: `moe_sort_routing` forwards `expanded_rows = n_token * topk = 0` to `preprocessTopkIdLauncher`, which computes `block = std::min(size, 1024)` -> `0` and then `grid = (size + block - 1) / block` -> integer division by zero.

Fix, in `csrc/moe/moe_permute_unpermute_op.cu`:

- `moe_sort_routing` returns early for an empty batch: zero `expert_first_token_offset` and return an empty row mapping.
- `moe_permute_impl` skips the expand launch when there are no tokens.

This mirrors the existing empty-routing guard in `moe_prepare_scatter` and keeps the expert offsets zeroed, matching the non-empty path where `computeExpertOffsetsAndInverse` zeroes them. `moe_unpermute` already handles 0 tokens, so it is untouched.
