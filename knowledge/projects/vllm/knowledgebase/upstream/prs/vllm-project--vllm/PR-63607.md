# [Bugfix][Frontend] Exclude hidden stop-token logprobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/63607) · state: open · merged: False

## Original PR description



## Overview

Exclude hidden terminal EOS/stop-token logprobs from sampled Chat Completions and Completions responses, in both Python and Rust frontends. Fixes #63591.

AI assistance: OpenAI Codex assisted in preparing this PR.

## Claims

- Streaming and non-streaming logprobs omit a terminal token hidden from the response text; explicitly visible stop tokens retain their logprobs.
- Raw generated token IDs and completion-token usage remain unchanged. Echo-only prompt logprobs and length-limited output retain their final token.

## Details

Detokenization can suppress a terminating EOS/stop-token ID while preserving the sampled IDs and logprobs internally. Response formatting previously emitted every logprob position. This change filters only the hidden terminal position at the OpenAI response boundary. Rust chat events carry the terminal reason alongside the matching token delta so streaming conversion can apply the same rule without buffering another chunk.

String-stop truncation and beam-search behavior are unchanged. Existing synthetic tests that label visible ordinary tokens as EOS now terminate by length; their logprob assertions remain intact. The Rust echo test now omits its genuinely hidden final stop-token logprob. No model weights, sampling decisions, or engine accounting change.

Duplicate check repeated through GitHub CLI before publication: issue #63591 is open with no comments or linked closing PR; open and all-state PR searches for `63591 in:body` returned no matches. Related #61693 concerns prompt logprobs, #60542 and #57442 change raw/sample-only logprob handling, and #62719 trims derender text while explicitly retaining logprobs. None implements this response-layer terminal-token fix.
