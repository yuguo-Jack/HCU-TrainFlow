# [Perf][Gemma4] Fuse MTP speculative decoding layers and sparse gather-GEMV LM head

[Upstream PR](https://github.com/vllm-project/vllm/pull/60689) · state: open · merged: False

## Original PR description

## Overview

This pull request optimizes Gemma 4 Multi-Token Prediction (MTP) speculative decoding across all 5 Gemma 4 model architectures (`google/gemma-4-E2B-it`, `google/gemma-4-E4B-it`, `google/gemma-4-12B-it`, `google/gemma-4-26B-A4B-it`, and `google/gemma-4-31B-it`), eliminating intermediate tensor allocations in the MTP head, unifying multi-step draft execution into a single 1-token decode CUDA graph, and adding opt-in relaxed MTP verification for MoE and reasoning workloads.

Duplicate-work check: verified via `gh pr list --repo vllm-project/vllm --search "gemma4 mtp"` and `gh issue list` that no open pull request or issue implements fused sparse gather-GEMV, unified 1-token Q-only MTP decode, or relaxed MTP verification for Gemma 4 speculative decoding.

### Key architecture enhancements

1. **Sparse gather-GEMV kernel (`fused_mtp_sparse_gather_gemv`)**:
   - Replaces the multi-step `lm_head_weight[selected.reshape(-1)].view(T, S, H)` gather and `torch.einsum("td,tsd->ts", ...)` in `Gemma4MTPMaskedEmbedder._select_and_score` with a 2D-grid Triton kernel (`_sparse_gather_gemv_kernel`).
   - Grid: 2D `(T, cdiv(S, BLOCK_S))`. Each program streams candidate rows directly from `lm_head_weight` and accumulates dot products in FP32 registers without materializing `(T, S, H)` tensors in HBM.
   - Reduces intermediate HBM allocation by **99.61%** (from 2.0 MB down to 8.0 KB at M=1, and from 138.6 MB peak down to 10.6 MB at M=64 on `Assistant-E2B` / `Assistant-E4B`) and achieves up to **2.84x** CUDA Graph speedup (**100.0% bit-exact** top-1 token parity).
   - Includes empty input guards (`T == 0 or S == 0`), contiguous layout handling, and `bfloat16`/`float16` support.

2. **Unified 1-token multi-step decode and query-only hidden states (`TargetDependentARSpeculator`)**:
   - In `vllm/v1/worker/gpu/spec_decode/target_dependent_ar/speculator.py`, eliminates redundant prefill CUDA graph capture and multi-token verification-step prefill execution when `advance_draft_positions=False` (`Gemma4Speculator`).
   - Adds `_prepare_q_only_decode_inputs_kernel` to compact and extract only the last accepted token and hidden state per request (`[num_reqs, H]`) before step 0, running all `K` speculative draft steps through a single 1-token decode CUDA graph.
   - Cuts peak activation memory by **49.4% to 65.4%** across `12B`, `26B-A4B`, and `31B` (expanding available KV cache by **+1.17 GiB to +1.65 GiB**).

3. **Dual-path top-token drafting and monotonic softcap bypass (`Gemma4MTP.get_top_tokens`)**:
   - Updates `Gemma4MTP.get_top_tokens` to support both centroid-masked embeddings (`use_ordered_embeddings=True` on `Assistant-E2B` and `Assistant-E4B`) and dense unmasked embeddings (`use_ordered_embeddings=False` on `Assistant-12B`, `Assistant-26B-A4B`, and `Assistant-31B`).
   - For single-rank (`tp_size == 1`) greedy drafting on unmasked checkpoints, exploits the strict monotonicity of `tanh(x / c) * c` (`c > 0`) to take `argmax` directly on raw LM head logits (with `_suppress_idx` masking preserved), skipping full-vocabulary (`V = 262,144`) FP32 softcapping and temporary buffer materialization on every draft step.
   - Enables `use_local_argmax_reduction` when draft probabilities are not required.

4. **Opt-in relaxed MTP verification (`enable_relaxed_mtp`, `moe_expert_cap`, `cot_lenience_margin`)**:
   - Adds opt-in fields to `SpeculativeConfig` (`enable_relaxed_mtp: bool = False`, `moe_expert_cap: int = 0`, `cot_lenience_margin: float = 0.0`), disabled by default so standard speculative decoding remains 100% lossless.
   - **MoE active expert capping (`moe_expert_cap=14`)**: In `_gemma4_routing_kernel` (`vllm/model_executor/models/gemma4.py`), applies a two-stage bitonic sort per request verification chunk (`1 + gamma` tokens) that preserves all `K=8` experts of token 0 (the guaranteed token) and selects the top `CAP_S - K = 6` experts across the remaining draft tokens (`|S| <= 14` out of 128 experts). Uses `tl.constexpr` specialization so default mode (`CAP_S=0`) compiles to the exact baseline kernel with zero overhead.
   - **CoT-gated lenient acceptance (`cot_lenience_margin=1.8`)**: In `_rejection_kernel` (`vllm/v1/worker/gpu/spec_decode/rejection_sampler_utils.py`), tracks per-request thinking spans (`<|channel>` token 100 to `<channel|>` token 101) across steps and accepts greedy draft tokens inside thinking spans when `target_max_logit - draft_logit <= cot_lenience_margin`, immediately reverting to strict greedy verification upon `<channel|>` (token 101). Guarded by `COT_LENIENT: tl.constexpr` so non-Gemma4 models and default lossless mode incur zero extra buffers, branches, or registers.

## Claims

- **End-to-end V1 speculative decoding speedup (`enforce_eager=False`, `torch.compile` + CUDAGraphs)**:
  - **Lossless mode (`enable_relaxed_mtp=False`, default)**:
    - `gemma-4-E2B-it` (`gamma=4, BS=1`): **651.1 tok/s** (**3.33x speedup vs AR**, **1.08x over `main`**, **100.0% token match**).
    - `gemma-4-E4B-it` (`gamma=4, BS=1`): **193.4 tok/s** (**1.66x speedup vs AR**, **1.03x over `main`**, **100.0% token match**).
    - `gemma-4-12B-it` (`gamma=4, BS=1`): **189.7 tok/s** (**3.32x speedup vs AR**, **1.01x over `main`**, **100.0% token match**; peak activation memory reduced from **2.37 GiB to 1.12 GiB**).
    - `gemma-4-26B-A4B-it` (`gamma=4..7, BS=1..64`): up to **1.07x speedup over `main`** (**100.0% token match**; peak activation memory reduced from **1.79 GiB to 0.62 GiB**).
    - `gemma-4-31B-it` (`gamma=8, BS=1..4`): **111.7 tok/s** at BS=1 (**4.56x speedup vs AR**) and **253.7 tok/s** at BS=4 (**2.60x speedup vs AR**, **1.11x over `main`**, **100.0% token match**; peak activation memory reduced from **3.24 GiB to 1.60 GiB**).
  - **Relaxed MTP mode (`enable_relaxed_mtp=True`) on `gemma-4-26B-A4B-it` (`gamma=4..7, BS=1..64`)**:
    - `BS=1 (gamma=6)`: **338.1 tok/s** vs `238.4 tok/s` on `main` (**1.42x speedup over `main`**, **2.80x speedup vs AR**; block efficiency rises from `4.03` to `4.86`, acceptance rate from `50.5%` to `64.3%`).
    - `BS=8 (gamma=6)`: **1,179.5 tok/s** vs `830.4 tok/s` on `main` (**1.42x speedup over `main`**, **2.43x speedup vs AR**).
    - `BS=16 (gamma=6)`: **1,687.2 tok/s** vs `1,218.7 tok/s` on `main` (**1.38x speedup over `main`**, **2.36x speedup vs AR**).
    - `BS=32 (gamma=5)`: **2,538.8 tok/s** vs `1,923.0 tok/s` on `main` (**1.32x speedup over `main`**, **2.33x speedup vs AR**).
    - `BS=64 (gamma=5)`: **3,758.2 tok/s** vs `3,070.9 tok/s` on `main` (**1.22x speedup over `main`**, **2.14x speedup vs AR**).
- **End-to-end MTP speculative proposer impact (Suite 1 measured)**:
  - Multi-step draft loop with CUDA Graph replay achieves **1.07x to 1.17x speedup** on centroid-masked models (`Assistant-E2B`, `Assistant-E4B`) with **97.6% to 99.2% HBM reduction**, and **49.0% to 100.0% transient HBM reduction** on `Assistant-12B`, `Assistant-26B-A4B`, and `Assistant-31B`.
- **Component microbenchmark timings and parity (`bench_pr8_mtp.py`)**:
  - `Gemma4MTPMaskedEmbedder._select_and_score` (`H=256, S=4096`): **1.09x to 2.84x CUDA Graph speedup** and **1.10x to 1.33x eager speedup** across `M=1..64`, with **100.0% bit-exact** and **100.0% within 1-ULP** parity.
  - `Gemma4MTPMaskedEmbedder.get_top_tokens` (`H=256, S=4096`): up to **2.39x CUDA Graph speedup** and **92.4% peak HBM reduction** at `M=64`, with **100.0% bit-exact** parity.
- **Zero overhead for non-Gemma4 models**:
  - `advance_draft_positions` remains `True` for all other speculators (Eagle, Eagle3, DeepSeek MTP, etc.), and `CAP_S: tl.constexpr = 0` and `COT_LENIENT: tl.constexpr = False` compile out at build time when disabled.
