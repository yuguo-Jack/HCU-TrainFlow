# [Bugfix] Fix out-of-bounds read in kernel_unified_attention block_tab…

[Upstream PR](https://github.com/vllm-project/vllm/pull/61810) · state: open · merged: False

## Original PR description

## Problem

Fixes #61803

`kernel_unified_attention` in `vllm/v1/attention/ops/triton_unified_attention.py` performs an out-of-bounds read when loading `physical_block_idx` from `block_table`.

At line 431, the vectorized `tl.load` reads `block_tables_ptr + block_table_offset + seq_offset // BLOCK_SIZE` without a mask. `seq_offset` is a vector of length `TILE_SIZE` (via `offs_t = tl.arange(0, TILE_SIZE)`). When `max_seq_prefix_len` is not a multiple of `TILE_SIZE`, the last KV tile contains trailing elements where `seq_offset >= max_seq_prefix_len`, causing `seq_offset // BLOCK_SIZE` to index beyond the valid range of `block_table`.

`tile_mask` is computed on line 429 (`seq_offset < max_seq_prefix_len`) but is not applied to this load. All other vectorized loads in the same loop (K/V loads at lines 488-498, per-token-head scales at lines 509-519) correctly use `mask=tile_mask` — this is the only exception.

`compute-sanitizer --tool memcheck` confirms:
```
Invalid __global__ read of size 4 bytes
    at kernel_unified_attention ...
    ... bytes after the nearest allocation ... of size 12 bytes
```

## Fix

Add `mask=tile_mask, other=0` to the `tl.load` call, consistent with all other vectorized loads in the same kernel:

```python
# Before
physical_block_idx = tl.load(
    block_tables_ptr + block_table_offset + seq_offset // BLOCK_SIZE
).to(tl.int64)

# After
physical_block_idx = tl.load(
    block_tables_ptr + block_table_offset + seq_offset // BLOCK_SIZE,
    mask=tile_mask,
    other=0,
).to(tl.int64)
```

### Why `other=0` is safe

Masked positions return `physical_block_idx = 0` (block 0 is always a valid allocated KV block). Downstream K/V loads and per-token-head scale loads already apply `tile_mask` and return `0.0` / `1.0` for out-of-bounds positions, so the `physical_block_idx` value at those positions is never used in any computation that affects output.

### USE_TD scalar load (not modified)

The scalar `physical_block_scalar` load at line 441 (`block_tables_ptr + block_table_offset + (j * TILE_SIZE) // BLOCK_SIZE`) is not affected. Under the `USE_TD` path, the static assertion `BLOCK_SIZE % TILE_SIZE == 0` guarantees that `j * TILE_SIZE < max_seq_prefix_len` for all `j` in `[loop_lo, loop_hi)` (since `loop_hi <= ceil(max_seq_prefix_len / TILE_SIZE)`), so the scalar index always stays in bounds.

This change does not affect model output, accuracy, or serving behavior. The fix only prevents an out-of-bounds read whose results were already masked out by `tile_mask` in all downstream computation. No numerical results change.
