# [Bugfix][Responses] Default image detail in function tool outputs

[Upstream PR](https://github.com/vllm-project/vllm/pull/61340) · state: open · merged: False

## Original PR description

## Overview

Following #57241, apply the existing input_image detail default to list-form function_call_output.output. Currently a tool-returned image without detail fails with ResponseInputImageParam.detail missing, although message images receive the default.

## Claims

- Missing detail becomes auto; explicit detail, accompanying text and string outputs are preserved.
- Reuses the existing copy-on-write normalization; caller dictionaries are not mutated.
- Limited to function outputs; custom-tool support is not added.

## Details

The helper selects output for function_call_output and content for other items. The existing missing-only normalization and list guard remain unchanged. Custom-tool output is deferred rather than claimed as end-to-end supported.

A matching downstream report exists in https://github.com/maximhq/bifrost/issues/5649; https://github.com/maximhq/bifrost/pull/5659 fixes provider-side conversion, while this candidate fixes vLLM backend normalization.

Related work inspected includes #57241 (message image defaults), #54786 (Harmony text-list handling), and #56285 (other Responses compatibility). This candidate targets function-output image defaults. A focused pre-publication search found no same-scope vLLM fix; related #50782 handles Kimi tool-call IDs rather than image-detail normalization.
