# [Build] Remove unused `tools/install_deepgemm.sh`

[Upstream PR](https://github.com/vllm-project/vllm/pull/61265) · state: closed · merged: True

## Original PR description



## Overview

Remove the unused standalone DeepGEMM installer now that vLLM builds and bundles DeepGEMM through CMake.

## Claims

- Delete `tools/install_deepgemm.sh`, which has no callers in the tracked repository.
- Remove its stale Buildkite source-file dependency and CMake pin-synchronization comment, eliminating a second installation path and duplicate pin maintenance.

## Validation

- `pre-commit run --files .buildkite/test_areas/kernels.yaml cmake/external_projects/deepgemm.cmake`: all applicable hooks passed.
- `git diff --check`: passed.
- Local structural assertions using `.venv/bin/python` and PyYAML: the parsed Buildkite configuration changes only by removing the installer dependency; CMake changes only by removing the synchronization comment; the script and all tracked references are gone.
- Model evaluations and GPU tests are not applicable: no build commands, dependency revisions, runtime code, or kernels change. A full wheel build was not run.

## Details

The H100 DeepGEMM CI entry lists the script under `source_file_dependencies`, not `commands`. The active CMake integration invokes `tools/build_deepgemm_C.py` and packages DeepGEMM under `vllm/third_party/deep_gemm`. Removing the standalone installer also removes its manual entry point; users building vLLM continue through the existing CMake integration.

Open-PR searches for `install_deepgemm`, `DeepGEMM install`, `DeepGEMM remove installer`, and `DeepGEMM vestigial` found no duplicate removal. No issue is associated with this cleanup. Related PR #59129 patches the standalone installer as well as CMake for an SM90 kernel fix; it does not remove this obsolete installation path and may need to drop its installer hunk if this lands first.

AI assistance was used for investigation, changes, validation, and this description. This PR is a draft pending human review of every changed line and human execution of the relevant checks required by AGENTS.md.
