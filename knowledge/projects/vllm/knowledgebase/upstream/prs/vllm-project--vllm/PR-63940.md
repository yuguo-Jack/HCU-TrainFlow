# [Core][KV Connector] Use connector hits and cached costs in residual SJF

[Upstream PR](https://github.com/vllm-project/vllm/pull/63940) · state: open · merged: False

## Original PR description

## Overview
Stacked on #63938 (`e0e5656ad`) and immengzi's #51375 port (`2b656dd2f`). Add nonblocking connector hit estimates and cache local residual-cost calculations for waiting-queue SJF ordering.

## Claims
Ranking uses available Mooncake/NIXL estimates without starting or consuming lookups. MultiConnector preserves first-hit order; unknown estimates fall back to local remaining work. Admission revalidates real hits. This PR does not add resident-prefill preemption or token-budget planning.

## Validation
Head `2937285de`, based on `main@d929755b7`:

- **375 CPU tests passed** across residual SJF, scheduler, async scheduler and Mooncake connector suites.
- OPT-125M model comparison on one GPU passed: FCFS/SJF outputs match exactly, and SJF completes the cached longer prompt first. Greedy, batch-invariant, eager; this is correctness evidence, not a performance comparison.
- Removing the bounded-read check in a local fault injection makes its regression fail (**cost 1 instead of 2**).
- Whole-diff pre-commit including mypy passed. Source hashes match the tested snapshot. Read-only estimates now extend the lookup lifecycle tests rather than duplicate their setup.

## Details
Local estimates expire at admission, finish and reset; content/preemption changes refresh them. They may lag unrelated cache population/eviction, so they only affect order. Reset-invalidated external handles stay unknown, and bounded prompt-scoring requests respect main's cache-read limit. Default FCFS retains an empty estimate map and cleanup lookups. End-to-end external-cache performance, long-request tails and broader GPU configurations remain unmeasured; keep draft pending dependencies and upstream CI. Dao Le's and immengzi's attribution is preserved. AI assistance was used.
