# [CI] Remove filters from and shard (H200 MIG 18GB) E2E Core

[Upstream PR](https://github.com/vllm-project/vllm/pull/58741) · state: closed · merged: False

## Original PR description

## What
`(H200 MIG 18GB) E2E Core` selected its tests with two `--ignore` flags and a `-k` filter. This PR moves the excluded files out of `tests/v1/e2e/general/` so every job runs whole files. It then splits E2E Core into a `Mamba Prefix Cache` job and three hash shards over the rest of `general/`, which keeps each job under the 20-minute target.

## Old
```
tests/v1/e2e/general/
├── test_async_scheduling.py        # E2E Scheduling
├── test_kv_sharing_fast_prefill.py # E2E Core Large Memory
├── test_mamba_prefix_cache.py      # mrv1 -> E2E Core, mrv2 -> Large Memory (via -k / node IDs)
└── ... (9 more)                    # E2E Core
e2e-core-1-gpu         E2E Core            pytest v1/e2e/general --ignore .../test_async_scheduling.py --ignore .../test_kv_sharing_fast_prefill.py -k "not test_mamba_prefix_cache_mrv2"
e2e-core-large-memory  Large Memory        pytest .../test_kv_sharing_fast_prefill.py
                                           pytest .../test_mamba_prefix_cache.py::test_mamba_prefix_cache_mrv2 .../test_mamba_prefix_cache.py::test_mamba_prefix_cache_mrv2_async
```

## New
```
tests/v1/e2e/
├── _mamba_prefix_cache.py            # shared body (not collected), was general/test_mamba_prefix_cache.py
├── test_async_scheduling.py          # E2E Scheduling
├── test_kv_sharing_fast_prefill.py   # E2E Core Large Memory
├── test_mamba_prefix_cache_mrv1.py   # E2E Core Mamba Prefix Cache (mrv1, mrv1_async)
├── test_mamba_prefix_cache_mrv2.py   # E2E Core Large Memory (mrv2, mrv2_async)
└── general/                          # E2E Core Shard %N (9 files, unchanged)
e2e-core-1-gpu               E2E Core Shard %N (x3)       pytest v1/e2e/general --num-shards=3 --shard-id=N
e2e-core-mamba-prefix-cache  E2E Core Mamba Prefix Cache  pytest v1/e2e/test_mamba_prefix_cache_mrv1.py
e2e-core-large-memory        Large Memory                 pytest v1/e2e/test_kv_sharing_fast_prefill.py
                                                          pytest v1/e2e/test_mamba_prefix_cache_mrv2.py
```
- **Mirrors:** each NVIDIA job keeps an MI250 mirror, and the new job gets its own (`amd-e2e-core-mamba-prefix-cache`). The E2E Core mirror stays unsharded, with an explicit `parallelism: 1` so the base count can't multiply it.
- **Legacy `test-amd.yaml`:** the MI250 E2E Core step adds the moved MRV1 wrapper as a second command. The other legacy steps only get path updates.

## Notes
- This combines filter removal and sharding in one PR. That is a deliberate exception to the usual two-PR split, because the file moves are small. The same test functions are claimed per lane, and a static check confirms it (39 E2E Core, 4 Large Memory, 3 Scheduling, none duplicated).
- `test_mamba_prefix_cache.py` → the `_mamba_prefix_cache.py` helper plus MRV1/MRV2 wrappers. The `_run_*` bodies stay in the helper because they mutate module globals that the shared fakes read.
- Why this count: MRV1 mamba is the largest single unit, and it's a distinct feature, so it gets its own job. Replaying pytest-shard's hash on recent `main` logs, 2 shards of the remainder would push the slowest shard over 20 minutes on a slow run; 3 keeps it under.
- `source_file_dependencies` now name the files each job runs, with the helper triggering both mamba jobs. Timeouts are lowered to fit the smaller jobs.

Pytest time varies a lot between `main` runs (21–49m for the same job), so this run's wall total isn't a matched comparison. The setup delta is the stable number.
