# [Bugfix][CUDA] Use CUDA memory accounting for integrated GPUs on WSL

[Upstream PR](https://github.com/vllm-project/vllm/pull/64782) · state: open · merged: False

## Original PR description



## Overview

Use CUDA-reported free memory for NVIDIA devices reported as integrated (UMA) under WSL, instead of replacing it with WSL guest RAM availability. This fixes startup failures on RTX Spark systems with a GPU memory carveout.

## Claims

- Keep CUDA's free-memory value on CUDA + WSL, so startup profiling uses the GPU allocation budget rather than the WSL guest's available RAM.
- Preserve host-memory accounting for native Linux UMA devices and existing accounting for discrete GPUs and non-CUDA platforms.
- Extend the existing memory-snapshot regression tests and document the automatic WSL behavior in the GPU installation guide.

## Validation

## Details

`MemorySnapshot.measure()` currently replaces accelerator-reported free memory with `psutil.virtual_memory().available` whenever a GPU is reported as integrated. This is useful on native Linux UMA systems, where reclaimable OS memory is available to the GPU. Under WSL, guest RAM availability does not describe CUDA's allocation budget, particularly with a GPU memory carveout, so the replacement can reject a model that fits the GPU budget.

Reuse the existing cached WSL detection and retain the accelerator-reported value only when the platform is CUDA and runs under WSL. The change adds no options or dependencies and does not add synchronization or transfers to model execution.

Duplicate-work checks found no open upstream PR for `WSL UMA` or `WSL psutil`, and no WSL memory PR by title. Related PRs [#54776](https://github.com/vllm-project/vllm/pull/54776) (ROCm APU pools), [#49760](https://github.com/vllm-project/vllm/pull/49760) (native UMA host reserves), and [#46932](https://github.com/vllm-project/vllm/pull/46932) (CUDA graph estimates) address different behavior and do not contain this CUDA-on-WSL exception. No existing issue is claimed as fixed; this PR addresses the submitter's hardware reproducer.
