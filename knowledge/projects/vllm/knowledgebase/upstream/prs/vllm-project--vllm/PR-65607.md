# [Perf][HiSparse] Batch the coordinator's per-page residency bookkeeping

[Upstream PR](https://github.com/vllm-project/vllm/pull/65607) · state: open · merged: False

## Original PR description

## Purpose

The HiSparse coordinator updated residency one page and one resident group at a time, with a block-pool call per block. When a request's whole context is GPU-resident (~1.3k pages × 20 groups), one `schedule()` spends tens of ms in Python and stalls every running request. Direct GPU landing for P/D (#55398) makes that the common case, so this should merge first.

This PR batches each operation (adopt, unpin, writeback planning and completion, copy recording, free) into one pass per request and one block-pool call. `HiSparseResidentManager` gains `get_residency_pages`, `adopt_resident_pages` and `drop_resident_pages`, which touch only the requested pages, so per-step cost does not grow with context length. Behavior is unchanged, including the order blocks return to the free queue; two new tests pin that order.

Not a duplicate: no open PR touches these loops.
