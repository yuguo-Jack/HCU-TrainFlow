# [Core][Metrics] Collect iteration details during scheduling

[Upstream PR](https://github.com/vllm-project/vllm/pull/61424) · state: open · merged: False

## Original PR description

Relates to #61423 - the idea here is to re-work the per-iteration collection (for console logging) of prefill/decode request and token counters to prepare for exposing these as enabled-by-default, phase-aware Prometheus histograms

Accumulate scheduled prefill/decode request and token counts in the existing request metadata pass, and encoder counts during scheduling. Preserve scheduling-time counts and classify recomputation as prefill.

Remove the legacy collector and redundant encoder-stats payload. Retain existing logging and profiler field names through temporary aliases, with collection controlled by the existing options.

> can you help me understand what happened to `ScheduledEncoderInputStats`?

This was only a count of schedule encoder inputs and encoder output tokens, computed in the scheduler and then assigned to the iteration details. It only existed because the encoder output token count can't be computed from `SchedulerOutput`. We store that count in `IterationDetails` now
