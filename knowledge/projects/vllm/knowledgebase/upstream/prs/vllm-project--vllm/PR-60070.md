# perf: persist FlashInfer multi-CTA-KV counter buffer in sparse MLA

[Upstream PR](https://github.com/vllm-project/vllm/pull/60070) · state: open · merged: False

## Original PR description

## Summary

FlashInfer's `trtllm_batch_decode_with_kv_cache_mla` (sparse MLA decode) builds a
fresh runner on every call, so the trtllm-gen multi-CTA-KV kernel's semaphore
counter region is re-allocated and re-zeroed each decode step. That shows up as a
`FillFunctor<uint8>` launch before every FMHA kernel — one per layer per step —
sitting on the serial attention critical path at small batch sizes and
contributing nothing but latency.

This PR ports the persistent-counter pattern already used by SGLang and by vLLM's
dense MLA path (`flashinfer_mla.py`) into the sparse path
(`FlashInferMLASparseImpl.forward_mqa`): vLLM now owns a persistent, lazily-grown,
zero-initialized uint8 counter buffer passed via `multi_ctas_kv_counter_buffer`.
The kernel self-resets its semaphores at the end of each launch, so the buffer is
zeroed once and safely reused across CUDA-graph decode iterations.

Key details:
- Optional-API probe (`_FI_HAS_MULTI_CTAS_COUNTER_API`) preserves behavior on
  FlashInfer < 0.6.16.
- The buffer is handed over only when the Q head count is tileable per
  trtllm-gen's CTA tiling rules and the KV page size is 32/64.
- Sized at `__init__` for the scheduler worst-case batch and max head count
  (including DCP gather): allocated once during warmup, never after graph capture.
- `VLLM_DISABLE_PERSISTENT_MLA_COUNTER=1` restores the original per-step
  behavior for A/B comparison.

## Performance

GLM-5.2-NVFP4, 4x B200 (TP=4), BS=1, ISL=4, OSL=2048, fp8_e4m3 KV cache. Both
arms measured on the same binary/image and FlashInfer build; baseline = feature
disabled via the env toggle.

| Metric | Baseline | Patched | Delta |
|---|---|---|---|
| Output throughput (tok/s) | 130.8 | 132.5 | **+1.35%** |
| Mean ITL (ms) | 7.591 | 7.490 | **-1.33%** |

Verified reproducible across two independent runs (+1.05% / +1.35% throughput).
Nsight Systems confirms the mechanism: the `FillFunctor<uint8>` launch fires
3,900x in the baseline trace (78 layers x 50 steps) and 0x in the patched trace;
decode step wall time drops by the corresponding ~124 us.

## Correctness

GSM8K (lm_eval, 200 samples, identical harness for both arms):
flexible-extract 0.930 -> 0.955, strict-match 0.930 -> 0.955. No quality loss.

## Tests

New `tests/v1/attention/test_sparse_mla_counter_buffer.py`: 26 CPU-runnable
tests covering head-tileability and counter-bytes formulas, buffer lifecycle
(allocate-zeroed / reuse / grow / device change), dispatch behavior with a fake
FlashInfer kernel (eligibility, fallback paths, env disable), nope-MLA
`sparse_mla_top_k_lens` coexistence, and startup logs. Local run: 24 passed,
2 skipped (intentional: FlashInfer/CUDA not installed). Pure Python change —
one source module + one test file, no recompilation needed.

AI-based Amalgamator was used to prepare this PR. Human reviewed changes.
