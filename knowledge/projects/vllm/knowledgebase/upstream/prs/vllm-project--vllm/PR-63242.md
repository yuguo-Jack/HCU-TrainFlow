# [CI][ROCm] Fail the AITER nightly overlay on wheels ci_base cannot load

[Upstream PR](https://github.com/vllm-project/vllm/pull/63242) · state: closed · merged: True

## Original PR description

- `aiter-nightly-overlay.sh`: after installing the nightly wheel, run `ldd` on every AITER shared object and fail the overlay build (exit 11) if any required glibc or libstdc++ symbol version is missing from ci_base

Since ROCm 10 became the default image in #58761, the AITER nightly overlay picks `+rocm10.0.0` wheels. Those are built on Ubuntu 24.04 (`GCC 13.3.0-6ubuntu2~24.04.1`, UFB manifest `glibc: 2.39`) and need `GLIBC_2.38` and `GLIBCXX_3.4.31`, while ci_base is Ubuntu 22.04 (glibc 2.35, `GLIBCXX_3.4.30`). They install cleanly, then every test that loads an AITER module fails. In AITER nightly 15218, 135 of 137 failed jobs died with `version 'GLIBCXX_3.4.31' not found (required by .../aiter/jit/module_aiter_core.so)`, including LM Eval KV-Offload Medium and MoE Kernels Shard 3, and the 10-19, 10-20 and 10-21 nightlies look the same. With this check the AITER nightly fails at the overlay step, naming the exact missing versions, instead of failing about 137 tests in ways that look like vLLM bugs. Making it green needs ROCm 10 AITER nightlies built for glibc ≤ 2.35, as the `+rocm7.2.3` ones already are (GCC 11.4 on Ubuntu 22.04). That is a fix for the AITER nightly builds, not for vLLM. A newer libstdc++ alone is not enough, because 13 modules (MHA varlen forward, FMHA v3, hipbsolgemm, f4gemm) need glibc 2.38. #61939 moves this install into `Dockerfile.rocm`, and the same check belongs there once it lands.

Validation: I ran the generated `RUN` line under `/bin/sh` (dash) against three AITER builds. The `0.1.27+rocm10.0.0` nightly from 10-22 fails with 96 missing versions (82 `GLIBCXX_3.4.31`, 13 `GLIBC_2.38`, 1 `CXXABI_1.3.14`). The `0.1.27+rocm7.2.3` nightly from 10-21 and the AITER built into the current ROCm 10 image pass with none. I didn't run the overlay end to end. A first attempt that loaded each module with `ctypes` also rejected the working in-image AITER, because modules depend on symbols from other AITER modules, so this checks symbol versions only. No open PR covers this; #61939 rewrites the step but keeps the same selector. `bash -n`, shellcheck and pre-commit pass.
