# [Bugfix][Frontend] Abort streaming input before the first chunk

[Upstream PR](https://github.com/vllm-project/vllm/pull/63952) · state: open · merged: False

## Original PR description




## Overview

Make `AsyncLLM.abort()` terminate streaming-input sessions that are still waiting for their first input chunk. The input task is cancelled and the output iterator finishes without yielding an output.

Addresses the explicit-abort case in [this comment on #57061](https://github.com/vllm-project/vllm/issues/57061#issuecomment-6310672263), rather than the original issue's cancellation-during-registration case.

## Claims

- An external or internal abort before the first chunk stops the input producer and wakes the output consumer, including when the producer task has not started.
- Repeated aborts do not prevent a subsequent request from using the same external request ID.
- Existing processing takes over after the first request is registered; model execution and sampling are unchanged.

## Details

Before the first chunk, `_add_streaming_input_request()` has returned a collector and started an input task, but there is no `RequestState` or external-to-internal request mapping yet. `abort_requests()` therefore finds nothing; a later chunk is submitted normally.

Pending collectors now remain discoverable by abort. Abort removes the entry, cancels the input task and sends `STREAM_FINISHED` directly, including when the task has not started and cannot run its `finally`. The first request registration or task completion removes the pending entry.

State and abort's scan are proportional to streams awaiting their first input. There is no GPU synchronization or per-token work; scheduler, KV-cache and model-runner behavior are unchanged.

Issue comments and open-PR searches found no duplicate of this pre-first-chunk explicit-abort fix. Related work has distinct scope:

- #57062: cancellation while `add_request()` is in progress.
- #58942: terminal handling and preventing later chunks from reviving a registered session.
- #62871: suppressing the final request after input-processing failure.
- #53321 / #59339: scheduler handling of already admitted streaming requests.
