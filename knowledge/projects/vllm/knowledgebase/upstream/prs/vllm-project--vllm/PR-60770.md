# [Bugfix][Frontend] Accept newline-separated parallel Hermes tool calls under tool_choice="required"

[Upstream PR](https://github.com/vllm-project/vllm/pull/60770) · state: open · merged: False

## Original PR description

## Purpose

FIX #60769

Fixes newline-separated parallel tool calls when using the generic Hermes parser with `tool_choice="required"`.

Hermes chat templates can produce a newline between consecutive tool calls:

```text
</tool_call>
<tool_call>
```

The `required` grammar currently expects an empty separator, so it can reject this otherwise valid output.

### Scope

This primarily affects models and configurations using the generic Hermes parser, including:
- NousResearch Hermes 2 Pro, Theta, and Hermes 3
- Models explicitly configured with `--tool-call-parser hermes`
- The Python frontend, where `qwen3_json` currently aliases the Hermes parser

Since #60136, the Rust frontend routes Qwen2.5, QwQ, and Qwen3 to its dedicated `qwen3_json` parser. Those automatically routed models are no longer the motivation for this change.

### Implementation

Override `build_call_format`, the extension point provided by the updated parser trait, so the Hermes `required` grammar accepts the newline used by the shipped template.

The change is scoped to the generic Hermes grammar. A separate Rust builder-side improvement or dedicated Python `qwen3_json` implementation would be complementary.
