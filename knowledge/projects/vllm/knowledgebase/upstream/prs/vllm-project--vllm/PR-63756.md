# [Rust] Bump fastokens to 0.3.4 (split-cache fix, clear truncation)

[Upstream PR](https://github.com/vllm-project/vllm/pull/63756) · state: closed · merged: False

## Original PR description

## Summary
Fixes [vllm-project/vllm#63467](https://github.com/vllm-project/vllm/issues/63467): Rust tokenizer split-cache wrong token ids by bumping `fastokens` to **0.3.4** and adapting the Decoder API.

Claimed on the issue (cc @waynehacking8 @BugenZhao).

## Changes
- `rust/Cargo.toml` / `Cargo.lock`: pin `fastokens` to **0.3.4**
- `hf.rs` `is_byte_level_only`: handle 0.3 `Fuse` + other new Decoder variants (`_` → non-byte-level)
- `new_fastokens`: `set_truncation(None)` + `set_padding(None)` so we keep main’s prior non-truncating behavior (variant 2 under “Fixing it”)
- Tests: `new_fastokens_clears_configured_truncation`, `fastokens_split_cache_append_matches_fresh_encode`

## Verification
```
cargo test -p vllm-tokenizer --lib
# 99 passed
```

## Not in this patch
- Python `fastokens>=` floor (blocked on crusoecloud/fastokens#85)
- Folding into #51027 (coordinated with @waynehacking8 / @BugenZhao on the issue)

Signed-off-by: bantianyue <bantianyue@gmail.com>
