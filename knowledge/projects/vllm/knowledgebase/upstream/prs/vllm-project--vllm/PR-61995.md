# [CPU][MRv2] Enable MRv2 for non-triton CPU backends

[Upstream PR](https://github.com/vllm-project/vllm/pull/61995) · state: open · merged: False

## Original PR description



## Overview

- enables MRv2 (by default) for CPUs where triton isn't avaliable - Arm CPUs, IBM CPUs, RISCV CPUs
- We do not yet remove MRv1 - you can still select it with: `VLLM_USE_V2_MODEL_RUNNER=0 `
- This only applies to CPU backend when triton support is not available, e.g. doesn't apply to x86
- Changes to GPU code are just cosmetic - e.g. to turn a function into an instance method we can override.

## Design

### CPU Hooks

`CPUModelRunner` subclasses `GPUModelRunner` and inherits the main MRv2 flow. 
We select CPU implementations in place of triton code (mostly) through 

- directly overriding methods in CPUModelRunner - for example `CPUModelRunner.prepare_inputs()`
- class selection for `ModelRunner` components through properties, for example: `CPUModelRunner.sampler_clas -> CPUSampler -> CPUSampler._sample_random()` - we use this pattern for:

| `CPUModelRunner` property | Selected implementation for non-triton CPU|
| --- | --- |
| `block_tables_cls` | `CPUBlockTables` |
| `sampler_cls` | `CPUSampler` |
| `prompt_logprobs_worker_cls` | `CPUPromptLogprobsWorker` |
| `watermark_sampler_cls` | `CPUWatermarkSampler` |
| `model_state_cls` | The matching supported CPU model state |
| `structured_outputs_worker_cls` | `CPUStructuredOutputsWorker` |
| `kv_block_zeroer_cls` | `CPUKVBlockZeroer` |

- patching in `cpu/shm.py` - this is for shared code that was not suitable for the patterns above


### CPU implementations

We have 3 flavours:
- pytorch (with torch.compile) for tensor transformations like output and prompt logprobs, token ranks, min-p
- C++ Ops for cases where pytorch impl is not fast enough: gumbel argmax, block-table writes, slot mapping, staged writes, M-RoPE, KV clearing (NOTE: I quite like the approach using numba from https://github.com/vllm-project/vllm/pull/60924 - I'm happy to adopt it here if numba support is mature of non-Arm CPUs)
- Python / numpy for some metadata and request state: thinking budgets, trace replay, state book-keeping 

## Support

### Model

We support the following model families:

| Family | Scope |
| --- | --- |
| Default decoder state | Dense decoder-only and supported multimodal models |
| Mamba-hybrid state | Non-speculative hybrid attention/SSM models; GDN was validated |
| Encoder-only state | Pooling, classification, token-level, and scoring workflows |
| Encoder-decoder state | Ordinary generation and beam search |

We do not support:
- models previously unsupported by CPU on MRv1.
- Diffusion Models
- Models with custom `ModelStates` that are not part of the supported families above

### Features

#### Supported:

| Area | Supported behavior |
| --- | --- |
| Execution | Compiled MRV2 serving, ordinary batching, mixed prefill/decode, TP=1 and TP=2 |
| Caching | Chunked prefill, prefix caching, KV-sharing fast prefill |
| Model state | M-RoPE, non-speculative Mamba/GDN state migration, encoder cache lifecycle |
| Sampling | Greedy, categorical/Gumbel, temperature, top-k, top-p, and min-p |
| Logits processing | Logit bias, allowed tokens, minimum-token rules, repetition/frequency/presence penalties, bad words |
| Sampling metadata | Thinking budgets, trace replay, watermarking, NaN counts, sampling-mask output |
| Logprobs | Output and prompt logprobs, requested token IDs, chunked prompt-logprob accumulation, prefix-cache interaction, and preemption |
| Guided output | Structured-output grammar masking |
| Inputs | Text and image input on the validated Qwen3.5 path |
| Encoder workflows | Embed, classify, token-embed, token-classify, combined dense/sparse output, bi-encoder, cross-encoder, and late interaction |
| Encoder-decoder | Ordinary generation and beam search |

#### Unsupported / TODO

- Speculative decoding
- Prompt embeddings
- Decode context parallelism
- Prefill context parallelism
- Batch-sharded sampling

## Validation

| Model | What was validated |
| --- | --- |
| `Qwen/Qwen3-0.6B` | Compiled text serving; greedy and random sampling |
| `Qwen/Qwen3.5-0.8B` | GDN full and chunked prefill, prefix-cache cold/hit paths, text and image input, output logprobs, TP=1 and TP=2 |
| `google/gemma-4-E4B-it` | KV-sharing fast prefill, chunked serving, and prefix reuse |
| `BAAI/bge-base-en-v1.5` | Embedding and bi-encoder workflows |
| `bert-base-uncased` | Classification and token-level pooling workflows |
| `textdetox/xlmr-large-toxicity-classifier` | Sequence classification |
| `cross-encoder/ms-marco-TinyBERT-L-2-v2` | Cross-encoder scoring |
| `BAAI/bge-m3` | Dense/sparse and late-interaction workflows, including its plugin path |
| `openai/whisper-tiny` | Encoder-decoder generation, beam widths 2 and 4, mixed request lifecycles, logprobs, TP=1 and TP=2 |
