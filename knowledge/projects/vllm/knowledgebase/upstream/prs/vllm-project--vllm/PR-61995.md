# [CPU][MRv2] Enable MRv2 for non-triton CPU backends

[Upstream PR](https://github.com/vllm-project/vllm/pull/61995) · state: closed · merged: True

## Original PR description



## Overview

Context: MRv1 is getting removed https://github.com/vllm-project/vllm/pull/63373, and the MRv2 code uses triton, which does not yet have mature enough support on a lot of platforms. 

This PR:
- enables MRv2 (by default) for CPUs where triton isn't available - Arm CPUs, IBM Z, IBM PowerPC, RISCV CPUs
- only applies to CPU backend when triton support is not available, i.e. doesn't apply to x86
- completely disentangles GPU MRv2 code from CPU, as we all agreed in the cpu-sig meeting - so GPU maintainers updating the GPU code path for MRv2 won't be blocked on CPU failures from changes in the shared path.

## Design

As per our design meeting last week, the approach taken for supported configs is:
- everything has to be under `vllm/v1/worker/cpu` and no changes / dependencies on `vllm/v1/worker/gpu` for MRv2. My approach here is a bit too conservative, I think there are parts of GPU MRv2 that are stable enough for us to share/reuse, but I thought it's better to be on the safe side for now. We can always revisit this later.
- copy MRv2 GPU code verbatim as much as possible - this is the code that the CPU MRv2 in the previous approach (see older commits) used to inherit from subclassing the GPU MRv2
- where copying is not possible, tweak with only the changes necessary to make it work on CPU (e.g. copy the orchestration / wrapper code, but replace a triton kernel call with a C++ kernel call)
- Do not support everything under the sun yet (I avoided spec decode support for now as PR is already huge, we can either add later or hopefully we won't need to if we pull-off triton-cpu fast enough :crossed_fingers:)
- non-triton MRv2 kernels use:
    - pytorch (with torch.compile where useful) for tensor transformations like output and prompt logprobs, token ranks, min-p
    - C++ Ops for cases where pytorch impl is not fast enough: gumbel argmax, block-table writes, slot mapping, M-RoPE
    - Python / numpy for some metadata and request state: thinking budgets, trace replay, state book-keeping 

## Support

We support the following model families:
- Default decoder state: Dense decoder-only and supported multimodal models
- Mamba-hybrid state: Non-speculative hybrid attention/SSM models; GDN was validated 
- Encoder-only state : Pooling, classification, token-level, and scoring workflows
- Encoder-decoder state : Ordinary generation and beam search 

The CPU Sampler supports:
- Greedy and per-request-seeded random sampling using the CPU Gumbel-max/argmax kernel.
- Temperature, top-k, top-p, min-p, repetition/frequency/presence penalties, logit bias, allowed-token
    IDs, bad words, and minimum-token stop suppression.
- Structured-output masks, thinking budgets, trace replay, watermarking, and sampling masks.
- Prompt/output logprobs, requested-token logprobs, sampled-token ranks, and chunked prompt-logprob
    accumulation.
- Top-k/top-p currently use the PyTorch implementation - A fused C++ is available in https://github.com/vllm-project/vllm/pull/62440

We do not yet support:
- models previously unsupported by CPU on MRv1.
- Diffusion Models
- Models with custom `ModelStates` that are not part of the supported families above
- Speculative decoding
- Prompt embeddings
- Decode context parallelism
- Prefill context parallelism
- Batch-sharded sampling
- mm encoder-only

## Performance (on Arm Neoverse-V2 cores)

The best perf indicator here is a small model (< 1b) where the new MRv2 flow and kernels would be a bottleneck and take a consequential percentage of runtime (as apposed to a big model that spends 99.9% of its time in GEMMs)

Here are some perf results with Qwen3.5-0.8B, 256 prompts, 256 input / output tokens

Perf with greedy decoding:

| Concurrency | Throughput | Mean TTFT | Mean TPOT |
| ---: | ---: | ---: | ---: |
| 8 | +9.6% | -2.5% | -9.5% |
| 32 | +7.0% | -0.8% | -7.8% |

| Concurrency | Throughput | Mean TTFT | Mean TPOT |
| ---: | ---: | ---: | ---: |
