# [Security] Bound FunAudioChat runtime audio to the profiled duration

[Upstream PR](https://github.com/vllm-project/vllm/pull/57411) · state: closed · merged: True

## Original PR description

## Summary
FunAudioChat profiles each audio item as 300 seconds (1,500 replacement tokens) for dummy inputs and encoder-cache sizing, but the runtime processor did not enforce that budget. Waveform length drove an unbounded speech-token string, and Whisper features were always padded to `max_length` (a full 300-second tensor per item). Long clips could exceed the profiled token count; many short clips allocated hundreds of MiB to multiple GiB of features before generation. This change rejects audio longer than the profiled sample count and pads Whisper features to the longest item in the request.

## Changes
- `vllm/model_executor/models/funaudiochat.py`: share the profiled sample/frame budget between dummy inputs and runtime admission; reject over-budget waveforms; call the feature extractor with `padding=True`.
- `tests/models/multimodal/processing/test_funaudiochat.py`: unit coverage for the 300s budget, over-budget rejection, in-budget acceptance, and short-clip feature sizing.

## Codepath coverage
- Chat / completions / messages / responses / invocations / gRPC generate / offline `LLM.generate` / batch all run FunAudioChat audio through `FunAudioChatMultiModalProcessor._apply_hf_processor_main`, which is the guarded sink.
- Precomputed embedding passthrough does not use this Whisper/speech-token path.

## Duplicate-work check
Searched open and merged PRs for `funaudiochat.py`, FunAudioChat audio admission, Whisper `padding="max_length"`, and audio token budget. No open or merged PR rejects FunAudioChat runtime duration or stops per-item 300s feature padding. Related #56979 only resizes Whisper dummy waveforms on other models.

## Tests
- `test_max_audio_samples_match_profiled_300s_budget` — default config is 7,500 speech frames / 4,800,000 samples (300s).
- `test_over_budget_audio_is_rejected` — one extra sample is rejected before the feature extractor runs.
- `test_profiled_max_audio_is_accepted` — a full-budget clip is processed; padding is not `max_length`.
- `test_short_audio_does_not_pad_features_to_max_length` — two 1s clips keep ~100-frame features and 25 speech frames each.
