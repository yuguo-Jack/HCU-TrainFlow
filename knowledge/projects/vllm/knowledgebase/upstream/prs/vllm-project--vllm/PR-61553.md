# [DSv4.1][PCP] Enable fixed DSpark and shared Engram storage

[Upstream PR](https://github.com/vllm-project/vllm/pull/61553) · state: open · merged: False

## Original PR description

## Overview

Enable fixed-verification DSpark on the DeepSeek-V4.1 PCP path from #59857, and add opt-in shared host Engram storage so colocated PCP replicas do not duplicate the same TP head shard. This draft now contains an implementation and four-H20 model validation; broader compatibility and accuracy validation remain pending.

## Claims

- Preserve compressor ring tails across PCP ranks after speculative rejection. Publishing only the newest open row loses states needed when the next step resumes at an earlier accepted position.
- Synchronize replicated draft proposals across PCP ranks. A model trace reproduced different draft tokens despite matching target inputs; the corrected path passed cross-rank checks and the model canary.
- Add `pcp_shared_memory` for CPU-offloaded Engram tables. **Hash heads remain TP-sharded; PCP replicas with the same TP rank share the same weight/scale pages.** This changes storage ownership, not precision, lookup arithmetic or token ownership. It reuses the existing `DPSharedEngramStorage` from #57651.

## Validation

Real DeepSeek-V4.1-Flash on four H20 GPUs: TP1/PCP4/DP1/EP4, DSpark5, Humming MoE, `fp8_ds_mla`, chunk8192, max-seqs64, eager/synchronous execution, `VLLM_GPU_SYNC_CHECK=error`, APC and SWA bounded replay **off**.

| Validation | Result |
| --- | --- |
| Distributed Engram suite, original DP plus PCP2/4 and TP1/2 | 31 passed |
| DSpark configuration suite | 13 passed |
| Focused compressor regression, PCP2/4 with 0/5/9 speculative tokens | 12 passed |
| Fixed GSM8K canary, shared TP1/PCP4 | 32/32, zero HTTP errors/truncations |
| Actual DSpark acceptance | 3900/5695 drafted tokens across 1139 draft rounds; mean 4.424 tokens including bonus |
| Engram physical memory | Two shared backing files, eight rank mappings, total PSS 188.83 GiB |

Private TP1/PCP4 requires approximately 755.33 GiB for four copies of these tables and failed at the container's 650 GiB limit. Shared storage used 188.83 GiB for the tables, with total container peak 218.25 GiB and no OOM. `/dev/shm` was 256 GiB **within** the 650 GiB container limit. The failed private and initial shared-startup runs were retained.

The tests exercise exact private/shared lookup parity, uneven head partitions, different/empty PCP inputs, single-writer visibility, changed/restored graph inputs, failure cleanup and storage lifetime. The draft configuration test confirms that disabling PCP sharing for the PCP1 draft does not modify the target. Storage graph tests do not establish model CUDA Graph support; 32 canary questions are not a comprehensive accuracy evaluation.

## Details

Stacked on #59857 at `7908ee8906475842ba0ecd1c09eed6d878718f05`; its MoE prerequisite #60946 remains relevant. Review this implementation incrementally against that SHA. The GitHub diff against main includes the parent's commits.

The new option defaults off:

```bash
--engram-config '{"cpu_offload":true,"pcp_shared_memory":true}'
```

For TP2/PCP2, each of two TP head partitions is stored once and mapped by its two PCP replicas. For TP1/PCP4, one full table is mapped by four replicas. Placement/shm checks fail closed. The initial scope requires V4.1, CPU offload, PCP>1, DP=PP=1 and same-host/shared-namespace replicas; it excludes DP sharing and THP combinations. The PCP1 draft receives a copied config with PCP sharing disabled.

No duplicate implementation was found in the refreshed checks. #56107 supplies generic replicated DSpark; #54036's sharded draft context-KV precompute is complementary and is not implemented here. #57195 concerns SP token-owner Engram lookup, whereas this change preserves TP head partitioning and PCP ownership. #61554 (bounded replay) and #61555 (model graphs) remain separate work. See `docs/design/deepseek_v41_pcp_dspark.md` for storage diagrams, constraints and validation details.

AI assistance was used to investigate, implement and validate this change. This remains a Draft; it does not assert that human line review or complete release qualification has occurred.
