# [Docker] Rename build stages for clarity (base->build-base, build->wheel-build, vllm-base->runtime-base)

[Upstream PR](https://github.com/vllm-project/vllm/pull/46599) · state: closed · merged: False

## Original PR description

## Summary

The CUDA multi-stage `docker/Dockerfile` had two stages that both read as "base" — `base` (the build-side base: devel CUDA + torch, parent of the compile stages) and `vllm-base` (the slim runtime base) — which is genuinely confusing. And `build`, the stage that *assembles* the final wheel, sat ambiguously next to `rust-build` / `csrc-build` / `extensions-build`.

This renames the **internal** stages so they say what they do:

| before | after |
|---|---|
| `base` | `build-base` |
| `vllm-base` | `runtime-base` |
| `build` | `wheel-build` |

`wheel-build` also happens to match the `#### WHEEL BUILD IMAGE ####` section header that already wrapped that stage.

## What is intentionally unchanged

- **`extensions-build`** stays as-is.
- **User-facing build targets** — `test`, `vllm-openai`, `vllm-openai-nonroot`, `vllm-sagemaker` — are unchanged, so `docker build --target ...`, the bake file, docs, and CI image builds are unaffected.

The only external reference that needed updating is the release pipeline, which builds `--target build` to extract wheels: the four CUDA entries in `.buildkite/release-pipeline.yaml` now use `--target wheel-build`. The CPU `--target vllm-build` entries (a different stage in `Dockerfile.cpu`) are untouched.

## Not a refactor of anything else

This is purely a rename for readability — the stage DAG, layer ordering, and build logic are byte-for-byte identical aside from the stage identifiers. All in-file `FROM` / `COPY --from` / `--mount=from` references and the comments that named these stages were updated in lockstep.

`docker/Dockerfile.nightly_torch` has its own similarly-named stages; it's a separate, structurally-different file and is left for a possible follow-up rather than bundled here.

## Testing

Verified by exhaustive grep that no stale `base` / `build` / `vllm-base` stage references remain and that `rust-build` / `csrc-build` / `extensions-build` / `vllm-openai*` were not touched. No build logic changed, so behavior is identical; CI builds the renamed `test` target and the release pipeline builds `wheel-build`.
