# [Bugfix] Support strided weights in sharded state saving

[Upstream PR](https://github.com/vllm-project/vllm/pull/61432) · state: open · merged: False

## Original PR description

## Purpose

`save_sharded_state` serializes each worker's in-memory `state_dict()`, i.e. the
weights *after* `process_weights_after_loading`. Some post-processing leaves a
weight as a non-contiguous view with a widened row stride. On ROCm,
`VLLM_ROCM_FP8_PADDING` (on by default) does exactly that with `F.pad(w, (0, n))[..., :-n]`.

Saving such a model fails twice over:

1. `ShardedStateLoader._filter_subtensors` computes a tensor's end address with
   `tensor.view(-1)[-1]`, which raises on a strided view:
   `RuntimeError: view size is not compatible with input tensor's size and stride`.
2. Even past that, `safetensors.save_file` refuses non-contiguous tensors:
   `ValueError: You are trying to save a non contiguous tensor`.

## Test plan

**1. FP8 model** `Qwen/Qwen3-0.6B-FP8`

```bash
python examples/features/sharded_state/save_sharded_state_offline.py \
    --model Qwen3-0.6B-FP8 --output /tmp/q3-fp8-sharded
```
- fails on main, passes here

Loading that FP8 checkpoint back is a separate, pre-existing problem: it fails
with `Missing keys (...attn.q_scale, ...k_scale, ...v_scale, ...prob_scale)`
on main too, even with `VLLM_ROCM_FP8_PADDING=0`, because those attention
scales are deleted in `process_weights_after_loading` and so never saved. It
is out of scope here.

**2. w4a16 model ** `Qwen/Qwen3-0.6B`:

```bash
python examples/features/sharded_state/save_sharded_state_offline.py \
    --model Qwen3-0.6B --output /tmp/q3-sharded
python examples/features/sharded_state/load_sharded_state_offline.py \
    --model /tmp/q3-sharded --load-format sharded_state \
    --prompt "The capital of France is" --max-tokens 32 --temperature 0
```
- fails on main, passes here
