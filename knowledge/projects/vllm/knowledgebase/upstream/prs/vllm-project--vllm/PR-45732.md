# docs: multi-server vLLM deployment issues and solutions

[Upstream PR](https://github.com/vllm-project/vllm/pull/45732) · state: closed · merged: False

## Original PR description

## Summary

Document 8 deployment issues encountered across 4 GPU servers (RTX 4090/5090) running vLLM v0.22.1-v0.23.0, with code fixes for CUDA 13+ compatibility.

## Problem

Deploying vLLM across multiple GPU servers revealed several compatibility issues:

1. **FlashInfer JIT compilation failures** on CUDA 13+ (missing curand.h)
2. **Hardcoded lib64 paths** break CUDA 13+ installations (which use lib/)
3. **Source compilation OOM** with high MAX_JOBS on systems with limited RAM
4. **Attention backend validation errors** when combining TRITON_ATTN with TurboQuant KV cache
5. **Marlin shape mismatches** with Gemma4 QAT models (fixed in v0.23)
6. **CUDA graph OOM** ignoring gpu_memory_utilization settings
7. **bitsandbytes 4bit incompatibility** with v1 engine
8. **Missing LD_LIBRARY_PATH** configuration for CUDA 13 pip packages

## Solution

### Documentation
Added comprehensive deployment guide covering all 8 issues with:
- Detailed root cause analysis
- Tested workarounds for each issue
- Backend compatibility matrix
- Deployment recommendations
- Related GitHub issues and PRs

### Code Fix
**tools/build_deepgemm_C.py**: Changed hardcoded `-L{cuda_home}/lib64` to check both `lib64/` and `lib/` directories, supporting:
- CUDA 12.x (lib64/ layout)
- CUDA 13+ (lib/ layout)

This fix enables DeepGEMM compilation on both old and new CUDA toolkit versions.

## Testing

Verified on 4 production servers:
- hn01:30823 (RTX 4090, CUDA 13.0, vLLM 0.22.1)
- js02:30107 (RTX 4090, CUDA 12.8, vLLM 0.23.0 source build)
- ah01:30145 (RTX 5090, CUDA 12.9, vLLM 0.22.1)
- sh01:30438 (RTX 4090, CUDA 12.8, vLLM 0.22.1)

All workarounds tested with real workloads.
