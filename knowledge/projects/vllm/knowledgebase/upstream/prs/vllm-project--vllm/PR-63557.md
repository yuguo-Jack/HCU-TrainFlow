# [CI][ROCm] Take NIXL PD accuracy side-channel ports from below the ephemeral range

[Upstream PR](https://github.com/vllm-project/vllm/pull/63557) · state: closed · merged: True

## Original PR description

- `rocm_pd_accuracy_utils.py`: take each server's `VLLM_NIXL_SIDE_CHANNEL_PORT` from below the kernel's ephemeral range instead of from `get_open_port()`

`test_rocm_pd_accuracy[nixl-aiter-deepseek-p1-d1]` failed in [amd-ci 15356](https://buildkite.com/vllm/amd-ci/builds/15356/list?sid=01a1707d-94ec-44ea-af1c-5245434b7339&tab=output): the decode server's `nixl_handshake_listener` hit `ZMQError: Address already in use (tcp://localhost:55235)`, and the server then waited out its startup timeout. The test has picked the side-channel port with `get_open_port()` since #58095, and NIXL only binds `side_channel_port + data_parallel_index` after the model loads, so for ~30 s the released port sits in the ephemeral range where any other `bind(0)` can be given it. This group otherwise passed 6/6 params in every nightly and weekly build from 14934 to 15350, so it is a rare race (about 1 in ~300 param runs) rather than a regression. Ports below `/proc/sys/net/ipv4/ip_local_port_range` are never handed out by `bind(0)` or `connect()`, the same approach as #63453 for MoRIIO. Separately, a dead handshake listener leaves the server neither failing nor healthy; that is a product issue for a follow-up.

The full CI file passes with this change on MI350X (6 passed; GSM8K 0.412-0.424 for Qwen, 0.195-0.202 for DeepSeek, in line with 15356's passing params).

AI assistance (Claude Code) was used to draft this change. Every line was reviewed by the submitter.
