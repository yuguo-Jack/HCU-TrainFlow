# [Model] Drop the 4x M-RoPE cache headroom for Qwen3-VL, Qwen3.5 and Qwen3.8

[Upstream PR](https://github.com/vllm-project/vllm/pull/59853) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Qwen3-VL, Qwen3.5 and Qwen3.8 build their M-RoPE cos/sin cache at 4x `max_position_embeddings`. That headroom exists for Qwen2.5-VL video positions, which these models do not produce, so this sizes the cache like plain RoPE unless video pruning is on.

## Claims

- 4x smaller cos/sin cache per GPU at the default 262k context: 256 → 64 MiB for Qwen3-VL (rotary dim 128), 128 → 32 MiB for Qwen3.5 and Qwen3.8 (rotary dim 64), and 512 → 128 MiB for Qwen3.5 with YaRN at 1M.
- Lower peak while building it, by the same 4x (table below).
- No output change without YaRN, since the new cache is a bit-exact prefix of the old one.
- With YaRN, Qwen3.5's correction range now uses the original context length, matching Transformers (#58870).

## Validation

Measured on SM80 with each model's rope parameters:

| model, rope | cache rows | cache | build peak |
| --- | --- | --- | --- |
| Qwen3.5, default 262k | 1,048,576 → 262,144 | 128 → 32 MiB | 644 → 161 MiB |
| Qwen3.5, YaRN x4 1M | 4,194,304 → 1,048,576 | 512 → 128 MiB | 2,576 → 644 MiB |
| Qwen3-VL, default 262k | 1,048,576 → 262,144 | 256 → 64 MiB | 1,284 → 321 MiB |

The 262k cache equals the first 262,144 rows of the old one in bf16 and fp32 (`torch.equal`). Against `ROPE_INIT_FUNCTIONS["yarn"]` on a `Qwen3_5TextConfig`, 9 of 32 YaRN inverse frequencies differed before and none differ after.

End to end against main, Qwen3.5-0.8B (`max_model_len=8192`) gives identical prompt logprobs on a 266-token text and identical greedy outputs for text and image prompts without YaRN, and the KV cache gains 15 blocks (60 with YaRN). With YaRN the outputs change, and on that prompt both main and this branch stay at the bf16 noise level against Transformers (mean |Δ logprob| 0.028 and 0.029; 0.025 without YaRN). Qwen3-VL-4B and Qwen3-VL-30B-A3B cut to two layers, on dummy weights in language-model-only mode, give identical greedy tokens and logprobs with the cache at 262,144 rows. With `video_pruning_rate=0.5` the cache keeps 1,048,576 rows. Qwen3.8 Flash-Next was not run end to end; its QSA indexer reads the cache at token positions and at the first position of each compressed group, so both stay in range. `tests/kernels/core/test_mrope.py` and `tests/kernels/core/test_rotary_embedding.py` pass.

## Details

The 4x came in with Qwen2.5-VL, where temporal positions scale with video duration and can pass the token count. These models use Qwen3-VL's positions instead: a frame is a `(1, h, w)` grid spanning `max(h, w)` positions over `h * w` tokens, and text advances by one, so the largest position stays below the token count. Qwen3.8-27B runs as `Qwen3_5ForConditionalGeneration`; Qwen3.8 Flash-Next inherits the same positions.

`MRotaryEmbedding` takes the headroom as `positions_factor`, which defaults to 4. A factor of 1 is passed where each model builds its attention: `Qwen3_5DecoderLayer`, Qwen3-VL's text model (`Qwen3LLMModel` and `Qwen3VLMoeDecoderLayer`), and Qwen3.8's QSA attention. Other users of the shared Qwen3, Qwen3-MoE and Qwen3-Next attention keep the 4x, including Qwen3-Omni, whose positions scale with video seconds.

Video pruning keeps the positions of the tokens it drops, so with pruning on the cache stays at 4x. Drafters follow the target's pruning setting, because some MTP drafters are built from a draft model config that does not carry it. Since pruning now changes the cache shape, `ModelConfig.compute_hash` includes whether it is enabled.

#58879 fixes the YaRN correction range for every M-RoPE model and leaves the cache size alone. The two overlap only on Qwen3.5 with YaRN and video pruning disabled, where they give the same frequencies.
