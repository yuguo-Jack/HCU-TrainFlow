# fix(kv-cache): allow TurboQuant on hybrid models

[Upstream PR](https://github.com/vllm-project/vllm/pull/41123) · state: open · merged: False

## Original PR description

## TL;DR
This lets Qwen3.5/Qwen3.6-style hybrid attention/Mamba models run with TurboQuant KV cache by avoiding unsupported native/TurboQuant page mixing, aligning hybrid block sizing to TurboQuant's packed slot size, preserving single-token decode CUDA graph support, and keeping long continuation prefill memory-bounded.

AI assistance was used for this PR. The benchmark and review-feedback updates are documented below so maintainers can evaluate the change end-to-end.

## Duplicate-work check
Related PR: https://github.com/vllm-project/vllm/pull/39931 also works on broader TurboQuant hybrid support and ROCm/uniform-quantization behavior. This PR is narrower: it focuses on Qwen3.6/Qwen3-Next style hybrid models with TurboQuant k8v4, MTP enabled, and the long cached-prefix continuation prefill OOM seen when serving `Qwen/Qwen3.6-27B-FP8` on a single L40S. If maintainers prefer the broader PR, this patch can be folded into or reconciled with that work.

## Summary
- Disable automatic TurboQuant boundary skip layers for hybrid models, while still rejecting explicit skip layers that would mix native and TurboQuant attention pages.
- Use TurboQuant packed slot sizing when aligning hybrid attention and Mamba cache pages.
- Preserve single-token decode CUDA graph support with `UNIFORM_SINGLE_TOKEN_DECODE`, while avoiding unsafe graph claims for the current host-syncing prefill path.
- Route long cached-prefix continuation prefill through sliced TurboQuant decode chunks to avoid materializing large fp16 cached K/V buffers.
- Pass `output_buf`, `buf_holder`, and `max_num_kv_splits` through the sliced continuation decode path and use 64-token slices to keep decode scratch memory bounded on the validated Qwen3.6 run.

## Review focus
- Hybrid KV cache page-size alignment for non-MLA TurboQuant attention.
- TurboQuant continuation prefill behavior after the cached prefix exceeds 32K tokens.
- Whether the 64-token long-prefix decode slice and 32K threshold should be tuned or exposed later.
- Interaction with broader TurboQuant hybrid support in https://github.com/vllm-project/vllm/pull/39931.

# Hybrid model TQ failure root cause — `slot_size_aligned` was changed from power-of-2 to even

Tested this PR's approach on Nemotron-3-Super-120B-AWQ-4bit (hybrid Mamba+MoE+Attention) and Nemotron-Cascade-2-30B-A3B (same architecture family). Removing the `is_hybrid` rejection in `arg_utils.py:1676` is necessary but not sufficient — the underlying failure is in page-size unification.

## What we found

After patching out the upfront rejection, model load fails downstream in `kv_cache_utils.py:1023`:

```
NotImplementedError: The page size of the layer is not divisible by the maximum page size.
Cannot unify by adjusting block_size.
```

The TQ attention layer's slot size and the Mamba layer's page size are not divisible into each other under v0.20's `slot_size_aligned` definition.

## Root cause

Between v0.18-era and v0.20, `slot_size_aligned` in `model_executor/layers/quantization/turboquant/config.py` was changed from "round up to next power of 2" to "round up to next even number":

```python
# v0.20 current:
@property
def slot_size_aligned(self) -> int:
    s = self.slot_size
    return s + (s % 2)  # round up to even

# v0.18-era / our fork (works on hybrid):
@property
def padded_slot_size(self) -> int:
    """Power-of-2 is required for hybrid attention+mamba models where
    page sizes must align across attention and mamba layers."""
    s = self.slot_size
    if s <= 1: return s
    p = 1
    while p < s: p *= 2
    return p
```

For tq-t3nc (head_dim=128): `key_packed=52` + `value_packed=52` = `slot=104`. Even-aligned: 104. Power-of-2-aligned: 128. Mamba page sizes are powers of 2 by construction, so 104 (= 8×13) is not divisible into the Mamba page size, breaking unification.

## Patch that works

Revert `slot_size_aligned` to power-of-2 padding. Costs 23% per-slot waste at head_dim=128 (104 → 128 bytes) but restores hybrid model compatibility.

After this change + this PR's removal of the `is_hybrid` rejection, both Cascade-2 and Super-120B load and serve correctly with `--kv-cache-dtype turboquant_3bit_nc`. KV cache sizes:
- Cascade-2 (BF16, 60GB model): **1.7M tokens** at 0.92 mem util
- Super-120B (AWQ-4bit, 75GB model): 587K tokens at 0.92 mem util
- Both: standard 22-check practical bench at 100% quality

## Suggestion

Either:
1. Restore power-of-2 alignment in `slot_size_aligned` (simple, costs ~23% slot memory)
2. Pad Mamba page size to match TQ slot size (complex, no waste)
3. Make alignment strategy configurable based on model type (auto-detect hybrid)

Option 1 is the change we applied locally — minimal diff, immediately unblocks production hybrid model serving with TQ.

Tested on 8× RTX A4000, vLLM 0.20.0 + this PR + the slot_size_aligned revert. Happy to provide the diff or test other approaches.

— MidasMining, Nemotron-H hybrid models on Ampere

The call to `triton_turboquant_decode_attention` in the continuation prefill loop is missing several important arguments that are present in the standard `_decode_attention` path. Specifically, `buf_holder=layer` is required for the kernel to reuse its internal scratch buffers; without it, the kernel will perform expensive allocations and deallocations on every iteration of the loop. Additionally, `max_num_kv_splits` should be passed to ensure consistent split-K behavior, and `output_buf` can be used to avoid an extra copy.

```suggestion
                        out[q_offset:q_next] = triton_turboquant_decode_attention(
                            query=q_part,
                            kv_cache=kv_cache,
                            block_table=synth_bt,
                            seq_lens=synth_seq_lens,
                            Pi=Pi,
                            centroids=centroids,
                            scale=self.scale,
                            mse_bits=self.tq_config.key_mse_bits,
                            key_packed_size=self.tq_config.key_packed_size,
                            value_quant_bits=(
                                self.tq_config.effective_value_quant_bits
                            ),
                            key_fp8=self.tq_config.key_fp8,
                            norm_correction=self.tq_config.norm_correction,
                            PiT=PiT,
                            output_buf=out[q_offset:q_next],
                            buf_holder=layer,
                            max_num_kv_splits=self.max_num_kv_splits,
                        )
```
