# [Bugfix] Require hybrid KV cache manager for hybrid models

[Upstream PR](https://github.com/vllm-project/vllm/pull/61360) · state: open · merged: False

## Original PR description

## Overview

Fail configuration early when a hybrid attention-recurrent model resolves to a disabled hybrid KV cache manager, instead of failing later during KV-cache planning. Fixes #61313.

## Claims

- Raise an actionable configuration error when the hybrid KV cache manager is disabled for a hybrid model.
- Preserve existing behavior when the manager is enabled or the model is not hybrid.
- Add focused CPU-only regression coverage for all three cases.

## Details

The hybrid KV cache manager can currently resolve to disabled even when `ModelConfig.is_hybrid` is true. Mixed attention and recurrent cache specifications cannot be promoted to the uniform cache type required by the non-hybrid planning path, so startup later fails with a generic `ValueError`.

This change validates the effective setting after automatic and explicit hybrid KV cache manager resolution. It reports the incompatible configuration immediately and suggests either removing `--disable-hybrid-kv-cache-manager` or using a platform and KV connector configuration that supports the manager.

- frank-suwen · comment · 2026-10-14T07:17:43Z · [source](https://github.com/vllm-project/vllm/pull/61360#discussion_r4267846475)

File: `vllm/config/vllm.py` · line 1203

Thanks for raising this. `ModelConfig.is_hybrid` is narrower here than a model with multiple attention types: it derives from the `IsHybrid` interface, whose contract is models containing both attention and Mamba/recurrent blocks. An SWA plus full-attention model is therefore not rejected by this check and can still use the existing promotion fallback when HMA is disabled.

For attention plus Mamba, I could not find a supported fallback. `unify_hybrid_kv_cache_specs()` can promote local attention specs, but it cannot promote `MambaSpec` and `AttentionSpec` to one uniform type; the existing `test_unify_hybrid_kv_cache_specs()` regression test explicitly expects that combination to raise. This check therefore moves the inevitable failure to configuration time with an actionable error rather than removing a working debugging path.

If there is a supported recurrent fallback that I missed, I would be happy to adjust the change. Thanks!
