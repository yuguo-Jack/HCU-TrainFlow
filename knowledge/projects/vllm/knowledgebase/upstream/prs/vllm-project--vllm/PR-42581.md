# [Attention] Add no-output path for custom backends

[Upstream PR](https://github.com/vllm-project/vllm/pull/42581) · state: open · merged: False

## Original PR description

## Purpose
Re-introduce accept_output_buffer as an opt-in flag on AttentionBackend for custom/plugin backends that cannot accept a pre-allocated output tensor.

All built-in vLLM attention backends continue to work unchanged; the new flag only affects custom backends or vLLM plugins that set it explicitly.

This pull request introduces support for attention backends that do not accept pre-allocated output buffers by adding a `unified_attention_without_output` path. The reviewer identified several critical issues with the current implementation: the early return in the `forward` method skips essential KV cache updates, input/output tensor reshaping, and data dependency handling for `torch.compile`. ![critical](https://www.gstatic.com/codereviewagent/critical.svg)

The current implementation of the `no-output` path has several critical issues:

1.  **KV Cache Update**: It returns early before calling `unified_kv_cache_update`. If the custom backend does not handle KV cache updates internally (`forward_includes_kv_cache_update=False`), the KV cache will never be updated, leading to incorrect model output.
2.  **Input Reshaping**: It skips the reshaping of `query`, `key`, and `value` tensors to the 3D format `[num_tokens, num_heads, head_size]`. Most attention implementations (including custom ones) expect this standard vLLM input format.
3.  **Output Reshaping**: It returns the backend's output directly. If the backend returns a 3D tensor, it will cause a shape mismatch in the model, which typically expects a 2D tensor `[num_tokens, hidden_size]`.
4.  **Data Dependency**: It doesn't handle `kv_cache_dummy_dep`, which is required to ensure `torch.compile` preserves the correct ordering between KV cache updates and the attention forward pass.

I suggest moving this logic to after the reshaping and KV cache update blocks, or duplicating that logic within the conditional block.

```python
        if (
            self.is_custom_backend
            and self.use_direct_call
            and output_shape is None
            and not self.attn_backend.accept_output_buffer
        ):
            # Reshape inputs to standard 3D format
            query = query.view(-1, self.num_heads, self.head_size)
            if key is not None:
                key = key.view(-1, self.num_kv_heads, self.head_size)
            if value is not None:
                value = value.view(-1, self.num_kv_heads, self.head_size_v)

            kv_cache_dummy_dep = None
            # Update KV cache if not handled by the backend
            if (not self.attn_backend.forward_includes_kv_cache_update
                    and self.kv_sharing_target_layer_name is None
                    and key is not None and value is not None):
                kv_cache_dummy_dep = unified_kv_cache_update(
                    key, value, self.layer_name)

            output = unified_attention_without_output(
                query, key, value, self.layer_name,
                kv_cache_dummy_dep=kv_cache_dummy_dep)
            
            # Ensure output is returned in 2D format [num_tokens, hidden_size]
            return output.view(-1, self.num_heads * self.head_size_v)
```

The default value for `accept_output_buffer` should be `True` to maintain backward compatibility with existing backends and plugins. Most attention backends in vLLM support (and prefer) pre-allocated output buffers for performance reasons, especially during CUDA graph capture. Setting this to `False` by default forces all custom backends into the `no-output` path unless they explicitly override it, which might lead to unexpected behavior or performance regressions for existing plugins.

```suggestion
    accept_output_buffer: bool = True
```

) -> torch.Tensor:

    return self.impl.forward(
        self,
        query,
        key,
        value,
        kv_cache,
        attn_metadata,
        output_scale=output_scale,
        output_block_scale=output_block_scale,
    )
