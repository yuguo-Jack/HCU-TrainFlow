# [Kernel] Dynamic NVFP4 W4A4/W4A16 selection with shared weights

[Upstream PR](https://github.com/vllm-project/vllm/pull/54614) · state: open · merged: False

## Original PR description

## Purpose

Add opt-in dynamic NVFP4 W4A4/W4A16 selection on SM120/SM121. Both paths share canonical packed weights and scales, without additional weight preparation or a second weight copy. Selection happens before activation quantization, so small decode calls can use W4A16 while larger batches and prefill use W4A4.

The default pair is **FlashInfer CUTLASS W4A4 and native CuTe W4A16**, removing the dependency on the open W4A4 PR #5100. Compatible CUTLASS, b12x, cuDNN and CuTe W4A4 providers use explicit adapters; providers requiring a different weight layout are rejected. The ordinary-linear and fused-SiLU cutoffs are independently configurable from 0 to 16.

```bash
vllm serve nvidia/Qwen3.8-27B-NVFP4 --dtype bfloat16 \
  --kernel-config '{"linear_backend":"nvfp4_dynamic","nvfp4_dynamic_max_tokens":16,"enable_flashinfer_autotune":true}'
```

`nvfp4_dynamic_w4a4_backend` and `nvfp4_dynamic_w4a16_backend` select providers. `nvfp4_dynamic_silu_max_tokens` optionally overrides the fused-down cutoff. Automatic backend selection is unchanged.

Native W4A16 was merged in [FlashInfer #5242](https://github.com/flashinfer-ai/flashinfer/pull/5242). The Spark CI lane pins its merged commit `2f3bc5ac` because FlashInfer 0.7.0 predates it. This updates the existing precision-switching proposal; fixed-precision backend selection does not provide this behavior.

## Performance

On RTX PRO 6000 Max-Q (300 W), NVIDIA Qwen3.8-27B-NVFP4, the measured CuTe W4A4/native-W4A16 pair reduced time per output token by **6.6% to 7.2%** and request latency by **6.1% to 6.8%** at concurrency 1, selecting W4A16 for single-token down projections. MTP was disabled.

| Input | W4A4 TPOT (ms) | Dynamic TPOT (ms) | W4A4 request (ms) | Dynamic request (ms) |
|---|---:|---:|---:|---:|
| 2K | 16.064 | 14.904 | 4298.090 | 4004.911 |
| 3K | 16.626 | 15.532 | 4556.129 | 4276.395 |

These measurements used 256 output tokens and the qualified CuTe W4A4 overlay. They do not measure the new CUTLASS default. The matched CUTLASS-versus-dynamic SPEED-Bench sweep uses 2K/32K inputs, 1024 output tokens and concurrency 1/4/8; results are pending.

## Validation

The focused GPU checks passed for dispatch, shared weights, live-scale CUDA graph replay and native W4A16 at M=1..16. Both compilation startup canaries, pre-commit and full-repository Python 3.10/3.12 mypy passed.

```bash

.venv/bin/python -m pytest tests/kernels/quantization/test_nvfp4_kernel_selection.py tests/model_executor/test_flashinfer_autotune_warmup.py -v
```
