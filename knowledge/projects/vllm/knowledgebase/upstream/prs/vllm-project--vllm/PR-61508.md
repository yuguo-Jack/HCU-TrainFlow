# [Model] Plumb swiglu_limit through Cohere2Moe

[Upstream PR](https://github.com/vllm-project/vllm/pull/61508) · state: open · merged: False

## Original PR description

## Purpose

`Cohere2MoeForCausalLM` never constructed a clamped activation. A checkpoint that sets `config.swiglu_limit` still built a bare `SiluAndMul()` and passed no limit into `FusedMoEFactory`, so the clamp never left the model definition.

This is model-definition plumbing only. No kernel change. It mirrors `Glm5NextMLP` / `Glm5NextMoE`:

- dense and shared `Cohere2MoeMLP` take `swiglu_limit` and use `SiluAndMulWithClamp` when the field is set
- the MoE block forwards the same value to `FusedMoEFactory`

This is **clamped SiLU** (`alpha=1.0`, `beta=0.0` defaults), not SwiGLU-OAI.

When `swiglu_limit` is absent, behavior is unchanged: `SiluAndMul()`, and `FusedMoEFactory` receives `None`. No public Cohere checkpoint sets this field today; the PR enables a config field the architecture already documents, the same way GLM-5.Next does.

## Merge ordering

This PR waits on [ROCm/aiter#6552](https://github.com/ROCm/aiter/pull/6552), not on [ROCm/aiter#6335](https://github.com/ROCm/aiter/pull/6335).

#6552 is the kernel change for the gfx942 bf16 path Cohere hits. It routes bf16 `QuantType.No` SiLU/SwiGLU with an active limit from CK two-stage to the FlyDSL a16wmix port, which applies the clamp. `None`, `0.0`, and `+inf` stay on the current kernel. Until the ROCm image pins an aiter release that contains #6552 (`AITER_BRANCH` in `docker/Dockerfile.rocm_base`), a limit set by this PR still reaches CK on that shape and is dropped. **Intended order: ROCm/aiter#6552 first, then this PR.**

#6335 raises when an active limit reaches an aiter kernel that still ignores it. It does not apply the Cohere clamp, and it does not block review or merge of this PR.

## Test plan

- [x] Construction tests in `tests/models/test_cohere2_moe.py` (no GPU):
  - config without `swiglu_limit` → `SiluAndMul`, factory receives `None`
  - config with a finite limit → `SiluAndMulWithClamp` (alpha=1, beta=0) on dense/shared MLP, and the limit reaches `FusedMoEFactory`
- [x] Wired into the CPU Basic Models Other job in `.buildkite/test_areas/models_basic.yaml`
