# [KVOffload][P2P][CI] Add e2e PD test matrix for the P2P KV-offload tier

[Upstream PR](https://github.com/vllm-project/vllm/pull/61846) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Adds an end-to-end PD test matrix for the P2P KV-offload tier (`OffloadingConnector` + `TieringOffloadingSpec` + `p2p` secondary tier) and wires it into Buildkite, mirroring `nixl_integration/config_sweep_accuracy_test.sh`. Today the tier has only unit tests. The existing `tests/v1/kv_offload/tiering/p2p/run_accuracy_test.sh` isn't run by any CI step, and as written it can pass while proving nothing.

## Claims

- **Asserts KV actually moves.** New `test_p2p_transfer.py` sends fully unique prompts through the proxy and requires the decoders' `vllm:external_prefix_cache_hits` to grow by at least half the prompts' full-block tokens. gsm8k alone passes when the decoder silently recomputes.
- **Fixes multi-prefiller routing in `p2p_connector_proxy.py`.** Every decode was pointed at the first prefiller's P2P port, so `NUM_PREFILL_INSTANCES>1` fetched from the wrong peer. `--p2p-connector-host/--p2p-connector-port` now take one value per prefiller, and the proxy uses the coordinates of the instance that ran the prefill.
- **Makes the driver usable for a matrix.** New knobs: prefiller DP (`PREFILLER_DP_SIZE`), handshake mode (`P2P_MODE=pd|p2p`), `CANONICAL_LAYOUT`, `EXPECT_TRANSFER`, `ENFORCE_EAGER`, `--attention-backend`. Robustness fixes:
  - P2P control ports are strided per instance, so the per-DP-rank ports (base + dp index) can't collide.
  - Each instance pins `VLLM_PORT` / `VLLM_DP_MASTER_PORT`.
  - Cleanup escalates TERM→KILL, also reaps orphaned `VLLM::` DP processes and stale `/dev/shm/vllm_offload_*.mmap`, and waits for ports to free.
  - Every DP rank is warmed before the accuracy run.
  - `MAX_MODEL_LEN` 512 → 2048, because gsm8k 5-shot prompts are longer.
  - `CPU_BYTES` 200 MB → 2 GiB, so the source tier doesn't evict KV before the decoder pulls it at 100 concurrent requests.
- **Adds a 16-config sweep in 4 slices with 4 Buildkite steps.**
  - Attention: dense, MoE and MLA models.
  - Cache types beyond plain attention: hybrid GDN/SSM state, sliding window, fp8 KV.
  - Deployments: both handshake modes, mixed TP, 2×2 instances, decoder-first, DP prefiller, DP-EP decoder.
- **Accuracy check for the new models.** Adds gsm8k expected values for Llama-3.2-1B-Instruct and gemma-3-1b-it. Without them the accuracy check was skipped.

## Details

**Mixed TP needs `canonical_layout: true`.** While building the matrix we found that the default ("direct") host layout isn't byte-identical across TP sizes. A CPU chunk stores each worker's page back to back (`|W0|W1|`, `vllm/v1/kv_offload/cpu/spec.py`), so a TP1 chunk and a TP2 chunk hold the same KV in a different byte order.

- **Default model runner (MRV2):** the parallelism-agnostic exemption is disabled (`offloading/config.py`, `not use_v2_model_runner`). TP-mismatched peers fail the config-fingerprint check and the decoder recomputes, which is safe.
- **`VLLM_USE_V2_MODEL_RUNNER=0`:** the exemption applies, TP1 and TP2 share a namespace, every block transfers, and the decoder decodes garbage (gsm8k 0.0 to 0.005). The FS tier reproduces it too: a TP1 engine writes on MRV1 and a TP2 engine reads back gibberish. So it's the shared layout claim, not the P2P data plane.
- **This PR doesn't change that code.** The mixed-TP configs run with `CANONICAL_LAYOUT=1`, which is correct on both runners. One direct-layout config pins the current safe fallback (`EXPECT_TRANSFER=0`); it should flip to a transfer check once the direct layout is portable. The direct-layout claim will be reported separately. Related: #61822 documents `canonical_layout`.
- **MLA:** `deepseek-vl2-tiny` (used by the NIXL DP_EP configs) has `use_mla: false`, so it covers MoE/EP only. The MLA slice uses DeepSeek-V2-Lite-Chat. Without canonical layout, MLA mixed TP is refused on both runners: `replicated_layout` is only set for TP > 1, so TP1 and TP2 hash differently.

**Which cache types are covered, and why.** The `FEATURES` step covers the cache types whose offload path differs from plain attention:
- Hybrid: several KV groups, Mamba state pages, align-mode hit rounding.
- Sliding window: window-limited lookup and dropping out-of-window blocks; the 512-token window is shorter than the prompts.
- fp8 KV: different page bytes and dtype in the fingerprint.

Two cache types are deliberately left out:
- **MLA + DSA indexer:** the indexer is a plain `MLAAttentionSpec`, so it follows the MLA path already covered. There's no small checkpoint, and the sparse-MLA kernels need SM90+.
- **DeepSeek-V4 compressed attention:** it needs ≥4 large GPUs and is already covered by `kv-offload-large` and the optional DSv4 PD step.

The new step runs in parallel with the others, so wall-clock CI time doesn't grow: three configs, about 7 minutes in total on H200.

**CI resources.**
- The default, DP_EP and FEATURES steps target `l4` × 4 and the MLA step `h100` × 4. MLA is marked `optional` because V2-Lite (16B, ~31 GB bf16) doesn't fit an L4 at TP1.
- Validation ran on H200 only. L4 runtime is unmeasured. The default, DP_EP and MLA steps use the NIXL steps' 55-minute timeout with up to 7 configs; the FEATURES step uses 40 minutes for 3 configs.
- No AMD mirror in this PR.

**Not duplicating existing work.** Searching open PRs for the P2P accuracy driver, `p2p_connector_proxy`, tiering P2P CI and canonical-layout mixed TP finds nothing overlapping. Open P2P PRs (#61667, #60374, #60257) touch the tier's runtime, not its e2e tests.

- nilig · comment · 2026-10-26T07:03:59Z · [source](https://github.com/vllm-project/vllm/pull/61846#issuecomment-6410237963)

The matrix only exercises healthy peers, so the tier's fault handling has no end-to-end coverage, and that is where the recent P2P bugs were: #63207 (control-plane freeze after a peer is removed), #63498 (RDMA reconnect after a fault) and the fail-fast gaps in #63602. Wonder if we could add a fault slice on the same driver, since it already runs each instance as a local process:

- **Stalled prefiller:** SIGSTOP its processes for 60 s mid-run, then SIGCONT. Decode requests that name it should still complete within the tier's 30 s timeout and prefill locally, and the `test_p2p_transfer.py` hit check should pass again after SIGCONT.
- **Killed prefiller:** SIGKILL it and restart it on the same port. Pulls should resume from the restarted instance.
- **One prefiller removed in the 2x2 config:** pulls from the other prefiller should keep their normal latency. In our runs on the nightly without #63207, every removal or restart froze the consumer's control plane, including pulls from the healthy peer, so this case depends on #63207.

Each case asserts a time bound and recovery rather than an accuracy number, so it needs little or no gsm8k. Given the point about L4 queueing, it could be an optional step. Our runs were over RDMA; on a host without RDMA, #63498 does not apply, and with #63207 the TCP path recovered in all 5 runs.
