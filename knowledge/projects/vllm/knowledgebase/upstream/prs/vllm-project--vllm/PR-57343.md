# [Perf][KV Offload] Select the canonical load path by fragment size

[Upstream PR](https://github.com/vllm-project/vllm/pull/57343) · state: open · merged: False

## Original PR description

## Purpose

Fixes #57342. Choose the CPU→GPU load path from the copy sizes actually submitted, not the page size.

### User case

1. Canonical offload layout (`TieringOffloadingSpec`, `canonical_layout: true`)
   with an LBNHC KV layout at TP > 1: `FLEX_ATTENTION` (its only layout) or
   `VLLM_KV_CACHE_LAYOUT=NHD`.
2. Llama-3.1-8B at TP=2 has a 32 KiB page per rank, so `_select_swap_blocks_fn`
   picks `cuMemcpyBatchAsync`.
3. But the canonical mapping splits each page into 16 per-token 2 KiB fragments,
   and `_fill_canonical_ops` submits one copy per fragment, which is the
   small-copy regime #42212 moved to Triton.
4. Each CPU prefix hit copies about 4x slower than it needs to: TTFT p50 88 ms
   instead of 46 ms for a 2K-token prefix on 2×A30.

The fix passes the fragment sizes to the selector and applies the existing
28 KiB threshold and 8-byte alignment check to them.

Unchanged: the direct layout, the connector's default LBHNC layout without DCP
(one run per page), stores (always DMA), and the Triton chunk size (still
page-derived).

The split K/V example in #57342 turned out not to reach the connector at
runtime, since the connector always gets the packed 4-D view.

Not a duplicate: no open PR touches the selector. Neighbours are #48936, #53971,
#53544. The threshold itself being device-dependent is tracked separately in
#57555.

Could we inline this in the selector and remove `_copy_sizes`? This seems concise and directly expresses the distinction. Please keep the chunk-size calculation based on page sizes.

```suggestion
    copy_sizes = [
        size
        for group in layer_refs_per_group
        for ref in group
        for size in (
            [run.fragment_size for run in ref.mapping.runs]
            if canonical_layout and ref.mapping is not None
            else [ref.page_size_bytes]
        )
    ]
    # Triton wins only on small, 8-byte-aligned payloads.
    if (
        not copy_sizes
        or max(copy_sizes) >= THRESHOLD_BYTES
        or any(size % 8 for size in copy_sizes)
    ):
        return ops.swap_blocks_batch
```
