# [Bugfix][Frontend] Don't let the gRPC server share a port that's already in use

[Upstream PR](https://github.com/vllm-project/vllm/pull/65142) · state: open · merged: False

## Original PR description

## Overview

Fixes #65141. gRPC Core enables `SO_REUSEPORT` by default, so a second `vllm serve --grpc` on a busy port starts up and takes part of the first server's traffic. This sets `grpc.so_reuseport` to 0, like #47529 did for the HTTP server and the Rust frontend.

## Claims

- Starting a second gRPC server on a port that's in use now fails with "Address already in use".
- A single server behaves the same as before.

## Validation

I ran two servers on port 50051 with different `--served-model-name`s (main's `grpc_server.py` on the `vllm/vllm-openai-cpu:latest` image, `facebook/opt-125m`), then opened 40 new connections and called `GetModelInfo` on each.

| | Second server | 40 new connections |
|---|---|---|
| Before | starts: `vLLM gRPC server started on 0.0.0.0:50051` | A: 18, B: 22 |
| After | exits: `RuntimeError: Failed to bind to address 0.0.0.0:50051` (`Address already in use`) | A: 40 |

## Details

I didn't add a test. The gRPC launcher tests are skipped in CI since `smg-grpc-servicer` isn't installed there, so a new one would be skipped too.

I couldn't find another PR for this. #65126 touches the same file, but it's about rejecting security flags the gRPC server ignores.
