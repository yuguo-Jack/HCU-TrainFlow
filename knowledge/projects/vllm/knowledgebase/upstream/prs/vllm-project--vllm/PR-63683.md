# [Benchmark][ROCm] Fix attention benchmark specs for split backends; add ROCM_AITER_FA perf configs

[Upstream PR](https://github.com/vllm-project/vllm/pull/63683) · state: open · merged: False

## Original PR description


_Requested by **Tun Jian**_



## Overview

Stacked on #63675 (the ROCM_AITER_FA test suite). Only the last commit is new; please review it after #63675 lands. Part of the attention backend test standard RFC (https://github.com/vllm-project/vllm/issues/63640).

**Before:** The attention benchmark runner did not set `seq_lens_cpu_upper_bound`, which split-based backends such as ROCM_AITER_FA read for prefill and extend specs, so those specs could not run. ROCM_AITER_FA also had no benchmark configs or perf CI step.

**After:** The runner sets it. ROCM_AITER_FA has configs for Qwen3, Qwen3.8-27B and Muse Spark shapes, and an optional MI355 Buildkite step uploads the JSON results per commit for comparison with the merge base.

## Validation

MI350X, `benchmarks/attention_benchmarks/benchmark.py --config benchmarks/attention_benchmarks/configs/rocm_aiter_fa_qwen3_235b.yaml --output-json ...`: all 17 batch specs ran and the JSON was written. Those specs cover prefill 2k/4k/8k, decode at 1/16/128 requests × 2k/4k/8k, extend, spec decode and mixed batches. For example, `q8k` prefill takes 190 µs and `128q1s8k` decode takes 104 µs.

## Details

One-line runner fix, three YAML configs, and the perf step in `.buildkite/test-amd.yaml` and `.buildkite/test_areas/attention.yaml`.
