# [Bugfix][ROCm] Fix DSA MoE skip_final_all_reduce assert with MoRI/DeepEP at TP=1

[Upstream PR](https://github.com/vllm-project/vllm/pull/61653) · state: open · merged: False

## Original PR description

## Overview

On ROCm, the DeepSeek-V3.2 / GLM DSA decoder (`vllm/models/deepseek_v32/amd/model.py`) forces `skip_final_all_reduce = True` on every MoE layer, deferring the TP all-reduce to the next `fused_allreduce_rms_norm`. With DP/PCP + EP at TP=1 and a combine that already reduces (MoRI, DeepEP HT/LL), the MoE runner rejects that and asserts:

```
AssertionError: skip_final_all_reduce requires an un-reduced fused output
```

This PR leaves the final all-reduce on (`skip_final_all_reduce = False`) in exactly that case: a reducing all2all combine and TP=1. Every other layout keeps the existing behaviour.

## Claims

- DP/PCP + EP at TP=1 with MoRI or DeepEP no longer asserts, and the MoE output is reduced exactly once.
- Every other layout is unchanged vs main: TP only, TP+EP, DP without EP, every allgather_reducescatter layout, and MoRI/DeepEP at TP>1 (which still hit the existing assert).
- Out of scope: DP+EP+TP>1 runs sequence-parallel MoE, which the ROCm DSA decoder doesn't support (it all-reduces the all-gathered MoE output again). That limitation predates this PR and is unchanged.

## Validation

- New CPU test `tests/models/deepseek_v32/test_amd_moe_final_all_reduce.py` (40 tests). It covers 19 TP/DP/PCP/EP/backend layouts, using the real decoder-layer init/forward, `MoERunner.forward` and `fused_allreduce_rms_norm` with a simulated TP group. It compares each layout with main's behaviour and asserts that only the TP=1 MoRI/DeepEP layouts change.
  - With this PR: 40/40 pass.
  - On main: 10 fail, which are exactly the 5 TP=1 MoRI/DeepEP layouts (the assert).
- GPU: GLM-5.3 FP8 (`zai-org/GLM-5.3`) on MI355X, llm-d disaggregated prefill/decode, MoRI-EP and MoRI-IO KV transfer.
  - 1P1D: DP8/EP8/TP1 per role. 2P2D: DP16/EP16/TP1, internode MoRI-EP.
  - Before: asserts at startup on every DP rank. After: serves.
  - NIAH: 238/240 (99.2%) on 1P1D, 239/240 (99.6%) on 2P2D.
  - Built from main @ 189bbfb with the first form of this fix plus other in-flight ROCm patches. The narrowed fix behaves identically for these TP=1 MoRI layouts (both turn the skip off).

## Details

The fix is in `vllm/models/deepseek_v32/amd/model.py`. The skip is kept unless `use_mori_kernels`, `use_deepep_ht_kernels` or `use_deepep_ll_kernels` is set and `tensor_parallel_size == 1`. Those combines return a reduced output (`output_is_reduced() == True`). At TP=1 the next RMSNorm's all-reduce is a no-op, so letting the runner own the reduction is both correct and assert-free. The allgather_reducescatter combine leaves the output TP-partial, so it keeps deferring to the RMSNorm as before.

- Fix lives in vllm/models/deepseek_v32/amd/model.py — one AMD model file
  - The contract that's broken (output_is_reduced() == True + skip_final_all_reduce = True) is owned by the kernel, not the model
  - MoriPrepareAndFinalize.output_is_reduced() and DeepEPHTPrepareAndFinalize.output_is_reduced() both unconditionally return True — but at TP>1 they don't reduce across TP ranks, so True is already wrong
    there
  - Correct fix: output_is_reduced() should return tp_size == 1, or MoERunner should resolve the conflict automatically
  - Current fix: every future ROCm model that uses MoRI/DeepEP will hit the same assert and need its own copy of this patch

  Tests (40 tests, 318 lines for a 5-line fix):
  - test_amd_dsa_skip_final_all_reduce (19 parametrized) — asserts a bool on a mock object's internal state, not behavior; passes on main too; not catching the bug
  - test_amd_dsa_moe_output_vs_main for the 14 unchanged layouts — fake TP group (sum + expand) doesn't reflect real tensor_model_parallel_all_reduce; circular
  - test_sequence_parallel_moe_implies_expert_parallel — tests ParallelConfig property untouched by this PR; belongs elsewhere
  - Worth keeping: test_only_the_asserting_tp1_layouts_change + the 5 outcome tests for the fixed layouts

  Other:
  - _runner built via object.__new__ + 10 object.__setattr__ calls to bypass __init__ — sign that MoERunner isn't unit-testable and the test is doing too much
  - The fix should live in MoRI/DeepEP; the tests should live there too
