# [CI/Build][Rust Frontend] Publish vllm-proto on crates.io

[Upstream PR](https://github.com/vllm-project/vllm/pull/56365) · state: closed · merged: True

## Original PR description

## Purpose

Allow crates.io consumers such as Dynamo to use vLLM's protobuf and gRPC bindings without a dependency on Buf's Cargo registry.

- Extract the existing generator into `vllm-proto`; the frontend consumes the same crate.
- Validate packaging on PRs and forks. Publish independently versioned `proto-v*` tags from upstream using Trusted Publishing.
- Document consumption, release steps, and initial publisher setup.

Extends vllm-project/vllm#51276. Searches for `51276 in:body`, `crates.io`, and `proto rust` found no open PR implementing this publication path.

## Test Plan

- `cargo publish --manifest-path rust/proto/Cargo.toml --locked --dry-run`
- `cargo nextest run --manifest-path rust/Cargo.toml -p vllm-server --lib -E 'test(grpc::)' --locked --test-threads 8`
- `cargo clippy --manifest-path rust/Cargo.toml -p vllm-proto -p vllm-server --all-targets --locked -- -D warnings`
- Repository pre-commit hooks, external packaged-crate consumer, and matching/mismatched release-tag checks.

## Test Result

All local checks passed, including 47 existing gRPC tests. An offline consumer outside the checkout imported both clients and passed a protobuf encode/decode round trip; its external dependencies all resolved to crates.io. No test files were added.

No live crates.io upload or Trusted Publishing authentication was performed. Model evaluation was not run: the schemas and generator options are unchanged, with no model or generation-logic changes.
