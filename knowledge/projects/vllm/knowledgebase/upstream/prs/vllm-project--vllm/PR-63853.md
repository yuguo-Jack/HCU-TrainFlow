# [Bugfix][Spec Decode] Apply the draft max_model_len limit before model config hooks

[Upstream PR](https://github.com/vllm-project/vllm/pull/63853) · state: closed · merged: True

## Original PR description

## Overview

Fixes #63844. On Model Runner V2, a hybrid Mamba/attention target with prefix caching disabled and a draft whose `max_model_len` is below the target's fails config validation with `--mamba-block-size can only be set with --enable-prefix-caching`, although the flag was never set. Regression from #63251.

## Claims

- `VllmConfig` now lowers `max_model_len` to the draft's before running the model `verify_and_update_config` hooks, so values they derive from it (here the default `mamba_block_size`) use the final length.
- The reported command starts on V2; V1 and non-hybrid models are unchanged.

## Validation

New test `test_draft_limit_applies_before_hybrid_mamba_block_size` goes through `EngineArgs.create_engine_config()`, the path shared by `LLM` and `vllm serve` (CPU, only config files are fetched).

Before (fix reverted):

```text
$ pytest tests/config/test_speculative_draft_limits_max_model_len.py -k hybrid
E       pydantic_core._pydantic_core.ValidationError: 1 validation error for VllmConfig
E         Value error, --mamba-block-size can only be set with --enable-prefix-caching
1 failed, 4 deselected
```

After:

```text
$ pytest tests/config/test_speculative_draft_limits_max_model_len.py tests/config/test_speculative_draft_max_position_embeddings.py
20 passed
```

Wider suite `pytest tests/config tests/test_config.py` (macOS, CPU-only, `test_ray_runtime_env` deselected since Ray isn't installed): 771 passed, 29 failed. All 29 fail identically on `main` without this change (gated `meta-llama` repos, model inspection failing for multimodal architectures on this platform, CPU-specific compilation defaults, and V1-runner async-scheduling checks), so none are introduced here.

End to end, the reproducer from #63844 (`--load-format dummy`, CPU) now passes config validation; before the fix it raised the error above from `create_engine_config`:

```bash
VLLM_USE_V2_MODEL_RUNNER=1 vllm serve ai21labs/Jamba-tiny-random --max-model-len 4096 \
  --no-enable-prefix-caching --load-format dummy \
  --speculative-config '{"method":"draft_model","model":"ai21labs/Jamba-tiny-random","num_speculative_tokens":3,"max_model_len":1024}'
```

The test runs in the CPU "Multimodal + Config" Buildkite step (`pytest -v -s config`, depends on `vllm/config/`). `pre-commit run` passes on the changed files.

## Details

Root cause: #63251 added `_limit_max_model_len_to_draft()` after `try_verify_and_update_config()`. For hybrid models with prefix caching off, `MambaModelConfig.verify_and_update_config` sets `mamba_block_size = max_model_len` (4096). The limit then lowers `max_model_len` to 1024, and the after-validator `validate_mamba_block_size` reads `mamba_block_size != max_model_len` as a user-set flag.

Moving the limit ahead of the hooks is safe: it only reads the speculative config and `use_v2_model_runner`, which depends on `speculative_config`, `lora_config`, and `parallel_config` fields (executor backend, PP/DCP/PCP sizes, ubatching) that the hooks do not write. Hooks that also lower `max_model_len` (e.g. the 8192 cap for EmbeddingGemma2) still apply, now on top of the draft limit, so the result is the same minimum. Other values the hooks derive from `max_model_len`, such as `rotary_kwargs["max_position"]`, also see the final length now.

Not a duplicate: no open PR references #63844 or `_limit_max_model_len_to_draft`. #52045 works around the same validator for a different trigger (CPU MLA disabling prefix caching) and does not touch this ordering.
