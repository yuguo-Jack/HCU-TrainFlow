## Original PR description

## Overview

Add opt-in MI355X AgentX profiles for [InferenceX #4526](https://github.com/SemiAnalysisAI/InferenceX/pull/4526), replacing the stale MI355X agentic guide with two generated presets covering all twelve operating points. Generic defaults, other GPUs/variants, PD configuration and the separate #2792 fixed-sequence recipe remain intact.

**Source qualification caveat:** shared INT4 QuickReduce can lower DSpark draft-activation communication precision relative to the pinned-image default. Both preset runbooks expose this limitation. These opt-in presets document the source configuration; they do not certify InferenceX draft-precision compliance or production qualification. [Current grandfathering policy](https://github.com/SemiAnalysisAI/InferenceX/blob/f58175bd45c343f1bab7bed35f052a7e429935fc/inferencex-e2e/docs/MODELS.md#all-reduce-policy) explicitly preserves draft-precision requirements; no waiver is claimed.

## Claims

- Nine TP8 points use DSpark K6 with opt-in monokernel; three TP1/DP8 points use tensor-sharded experts and session-affine routing, with monokernel disabled.
- Pins the actual source image `vllm/vllm-openai-rocm:nightly-e4a5b5537344b103ed10de7764378ef09604ef3d` and target/tokenizer revision `72e1d3230f6c080a530b0a1d46f8eb4602340597` of `deepseek-ai/DeepSeek-V4-Pro-0813`. No digest was recorded by the source.
- Generated serving/eval commands keep real target verification. Throughput-only synthetic AL **3.77** is a separate runbook overlay from the committed thinking-on K6 golden curve, and does not enter the production commands.

- Merged runtime prerequisite: [vLLM #61482](https://github.com/vllm-project/vllm/pull/61482), merge `139feb45348d3eb303107a896e21303db3a0344e`; supports DSpark with TP8 monokernel, rather than STP-only.
- Published [recipe](https://recipes.vllm.ai/deepseek-ai/DeepSeek-V4-Pro) / [JSON](https://recipes.vllm.ai/deepseek-ai/DeepSeek-V4-Pro.json) lack these profiles (observed 2026-10-29 at source `vllm-project/vllm@9a0f9b45df86b91664923ad076f27a50f69c4766`; only B200 presets are published). Canonical ownership is vLLM `recipes/`; no renderer copy or generated output is changed.

Before: no MI355X preset JSON; stale guide used `eed1f3...`, synthetic MTP K3 / AL2.49 and fixed max-seqs8. After: two opt-in preset JSON exports with twelve explicit scheduler limits, real DSpark K6, image e4a5 and TP-only monokernel; synthetic reproduction remains separate. Existing baseline output remains byte-equivalent in the inspected matrix.

**Source precision limitation:** [Current InferenceX CONTRIBUTING](https://github.com/SemiAnalysisAI/InferenceX/blob/f58175bd45c343f1bab7bed35f052a7e429935fc/CONTRIBUTING.md#draft-model-precision) prohibits submission-side lowering of draft activation/computation precision below the pinned image's defaults. Source sets `VLLM_ROCM_QUICK_REDUCE_QUANTIZATION=INT4` versus the image default `NONE`, shared by draft collectives. At TP8, 32 active K6 requests yield at least 192 draft rows; a contiguous BF16 attention-output reduction is 2,752,512 bytes, above the 2 MiB INT4 threshold. Draft layers bypass monokernel, not QuickReduce. The recipe explicitly records this unresolved source-qualification issue; a source correction and qualifying evidence are still needed to establish InferenceX compliance. Passing target evals/synthetic AL is not an exception. No InferenceX edit or compliance sign-off is made here.

Other effective-runtime details:

- Native target and DSpark weights are mixed FP8/MXFP4, KV is FP8. No draft dtype/weight-quantization override or model-architecture override is added. Target/tokenizer revisions are pinned, but source supplies **no separate draft revision**; do not infer one from the target flag.
- The obsolete source env `VLLM_PREFIX_CACHE_RETENTION_INTERVAL=32768` is a no-op in e4a5. It is omitted without adding a CLI override, retaining effective default `0`; converting it to CLI32768 would change behavior.
- `image.pip` records dependencies rather than installing them: runbooks require Pillow/FastAPI/Uvicorn in the same container before the generated engine command. The generic Docker wrapper alone is not a completed setup.
- Existing DPA strategy emits TP1/DP8 and a generic router. Its companion cannot express the source pin/timeout/retry settings, so the runbook provides the exact replacement `vllm-router==0.1.14`, consistent hashing, 14400-second timeout, retries disabled and stable `X-Session-ID`. Serve port8100 and Verify/Bench router port8000 remain consistent.

Duplicate checks found no #4526 equivalent. Same-file [vLLM #64316](https://github.com/vllm-project/vllm/pull/64316) is separate **B200 / InferenceX #4554** work. Historical [recipes #824](https://github.com/vllm-project/recipes/pull/824) concerns an older FP8 Preview/MTP lane; merged #928/#972/#1053 do not cover these profiles. This does not import the later InferenceX #4578 candidate.
