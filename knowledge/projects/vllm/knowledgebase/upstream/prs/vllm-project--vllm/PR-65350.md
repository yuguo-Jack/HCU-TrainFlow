# [Bugfix][Spec Decode] Use vllm.config.replace for the MRV1 DFlash draft config

[Upstream PR](https://github.com/vllm-project/vllm/pull/65350) · state: closed · merged: True

## Original PR description

## Overview

After #64096, MRV1 DFlash fails at engine startup. `DFlashProposer._create_draft_vllm_config` uses stdlib `dataclasses.replace` on `VllmConfig`. That passes the new `init=False` field `num_hash_lookahead_tokens` to the constructor, and Pydantic rejects it:

```
ValidationError: 1 validation error for VllmConfig
num_hash_lookahead_tokens
  Unexpected keyword argument [type=unexpected_keyword_argument, input_value=0, input_type=int]
```

This PR uses `vllm.config.replace` instead. It skips `init=False` fields and is already used by the base proposer and the MRV2 DFlash loader. MRV2 is not affected.

## Validation

Fixes the nightly DFlash failures in [ci#99485](https://buildkite.com/vllm/ci/builds/99485): AMD MI355 DPX shards [1/2](https://buildkite.com/vllm/ci/builds/99485#01a1a04d-f648-41e8-9372-6ae84057341b) and [2/2](https://buildkite.com/vllm/ci/builds/99485#01a1a053-720e-4b1d-8b8e-aee2981b06cf).

With this fix, both tests pass locally on MI355X:

| Test | Result |
|---|---|
| `test_dflash_correctness[qwen3-mrv1]` | passed: GSM8K accuracy 0.884, acceptance length 4.12 |
| `test_dflash_reference_acceptance_lengths[False]` | passed: acceptance length mt-bench 4.12, humaneval 6.54, gsm8k 6.42 |
