# [Benchmark] Add synthetic audio support to random-mm

[Upstream PR](https://github.com/vllm-project/vllm/pull/65499) · state: open · merged: False

## Original PR description

## Summary
`RandomMultiModalDataset` only generated synthetic images and video; audio was explicitly unsupported (`"Audio: not yet supported"`).

Adds `generate_synthetic_audio` (random WAV at 48kHz) and wires it through a `(0, duration_seconds, num_channels)` bucket convention — a leading `0` marks a bucket as audio, checked before the existing image/video `num_frames` branches. Content items reuse the `input_audio` format `CustomAudioDataset` already produces for chat-based audio models, so no downstream `serve.py` changes are needed.

## Test plan
- [x] Syntax/diff reviewed
- [x] End-to-end test against a running server: `Qwen/Qwen2-Audio-7B-Instruct`, vLLM, TP1, ROCm. Ran `vllm bench serve --dataset-name random-mm --random-mm-bucket-config '{(0,3,1): 1.0}' --random-mm-limit-mm-per-prompt '{"audio":1}'` against a live server — **4/4 successful requests**, real generated output (108.8 tok/s throughput).
- Also traced against `XiaomiMiMo/MiMo-V2.6-Flash-MOPD` (TP2): the request correctly reached the model's real audio-processing pipeline (not rejected/malformed), confirming the content format is recognized generically — that run hit an unrelated missing model artifact (`audio_tokenizer/` not present in that snapshot), not a client-side issue.
