# [Model Loader] Keep norm layers neutral under dummy weight init

[Upstream PR](https://github.com/vllm-project/vllm/pull/61323) · state: closed · merged: True

## Original PR description



## Overview

Keep normalization layers neutral under `--load-format dummy`: `RMSNorm`, `LayerNorm`, `RMSNormGated` and `GemmaRMSNorm` tag their parameters with `dummy_weight_value` (their identity value), so dummy init no longer fills them with ±1e-3. Follow-up to #61134 (dtype-aware dummy init).

## Claims

- Dummy-loaded norms are identity-like (weight 1, bias 0; Gemma's `1 + w` weight 0) instead of random ±1e-3.
- Activations then keep a realistic scale, so data-dependent kernels time like they do with real weights. On DeepSeek-V4.1-Flash prefill, the sparse indexer's `topKPerRowPrefill` takes 27.8 ms per forward with dummy weights on `main`, 10.7 ms with this PR, and 10.6 ms with real weights.
- Only dummy initialization changes; checkpoint loading is unaffected.

## Validation

DeepSeek-V4.1-Flash (40 layers), TP4 + EP on 4x GB200, MegaMoE, FlashInfer sparse MLA, MXFP4 indexer cache. One prefill step: 8 requests x 1024 new tokens at ~100K context each. GPU kernel time per forward from a profiled CUDA-graph replay of the model forward (3 replays):

| Weights | `topKPerRowPrefill` (ms/forward) | Forward (ms, median of 100 replays) |
| --- | --- | --- |
| dummy, `main` (norms ±1e-3) | 27.84 | 136.0 |
| dummy, this PR | 10.68 | 120.3 |
| real checkpoint | 10.64 | 124.1 |

The remaining forward gap to real weights is MoE routing (real routing from random token IDs vs. a balanced fixture), not this change. All other kernels differ by under 1 ms between this PR and real weights.

These numbers come from an exact-shape forward benchmark that isn't upstream yet; the per-kernel effect can also be seen in an `nsys` profile of any long-context DeepSeek-V4.1 prefill with `--load-format dummy`.

Unit test (in `.buildkite/test_areas/model_executor.yaml`):

```
pytest tests/model_executor/test_weight_utils.py -q
43 passed
```

`test_dummy_norm_weights_are_neutral` fails on `main` (`RMSNorm` weight stays random) and passes with this PR.

No model evaluation: only `--load-format dummy` values change.

## Details

- **Root cause.** With norm weights in ±1e-3, every normalized sublayer input shrinks by ~1000x and loses structure. DeepSeek-V4.1's indexer query ends up near zero, and after FP8/MXFP4 quantization its logits collapse onto a few values with many exact ties. `topKPerRowPrefill` is a data-dependent radix select, so these degenerate logits are its slow case; real models never produce them.
- **Mechanism.** Reuses the existing `dummy_weight_value` hook in `initialize_single_dummy_weight`, as DeepSeek-V4.1's engram already does for its own weights. Each norm declares the value its constructor already uses.
- **Limitation.** Model-local norm classes that don't build on these four layers keep random dummy values.
- **Behavior change.** Dummy-weight benchmarks of models with data-dependent kernels (sparse top-k, etc.) shift toward their real-weight timings.
