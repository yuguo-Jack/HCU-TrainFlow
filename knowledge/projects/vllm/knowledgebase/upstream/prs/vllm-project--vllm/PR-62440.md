# [CPU] Add AArch64 top-k and top-p sampling kernels

[Upstream PR](https://github.com/vllm-project/vllm/pull/62440) · state: open · merged: False

## Original PR description

## Purpose

This PR brings the CPU top-k/top-p sampling implementation from #43452 and #55874 to the current vLLM main branch while preserving the original authorship:

- Tianmu Li implemented the base C++ kernels and integration for top-k, top-p, and combined top-k/top-p sampling.
- Fadi Arafeh added the AArch64 implementation.

The cleanup commit:

- removes the AVX512 and AVX2 sampling paths;
- removes the added AVX2 fast-exp macro and `-mfma` build flag;
- retains the AArch64 and scalar implementations;
- applies repository formatting; and
- adds `TestCpuTopkTopp` to the Arm CPU hardware CI kernel shard.

## Performance

Benchmarks were run on an AWS Neoverse-V2 system with 96 physical CPU cores and no SMT. Operator benchmarks used either 1 or 16 threads. For the end-to-end benchmark, the server was pinned to cores `0-15`, and the client was pinned to cores `16-31`.

### Operator Benchmark

The AArch64 C++ kernels were compared with the PyTorch CPU implementation using:

- FP32 Zipf-like logits (`rank^-1.1`);
- vocabulary size: `131,072`;
- batch sizes: `1`, `8`, and `64`;
- top-k: `k=50`;
- top-p: `p=0.9`;
- combined top-k/top-p: `k=100`, `p=0.9`;
- `5` warm-up iterations and `20` measured iterations;
- `3` repeated A/B runs with alternating execution order.

Input cloning was excluded from the measured region. All 18 configurations produced output masks identical to the PyTorch baseline.

### End-to-End Benchmark

The end-to-end benchmark used:

- model: `Qwen/Qwen3-0.6B`;
- dtype: BF16;
- exact input/output lengths: `128/128` tokens;
- `32` requests per concurrency level and `5` warm-up requests;
- `temperature=0.6`, `top_k=50`, `top_p=0.9`, and `min_p=0`;
- prefix caching disabled;
- EOS ignored;
- unlimited request rate.

The baseline and optimized runs used the same PR source and compiled binary. The only difference was whether top-k/top-p filtering used the PyTorch implementation or the AArch64 C++ kernels.
