# [DeepSeek-V4-P2] Extract deterministic sparse attention

[Upstream PR](https://github.com/vllm-project/vllm/pull/59883) · state: closed · merged: False

## Original PR description

## Motivation

DeepSeek-V4 sparse attention can change a request's result when candidate ordering, the sparse index list, workspace offsets, or the FlashMLA launch depend on neighboring requests. This PR makes the supported sparse-selection and attention path request-local in batch-invariant mode, without changing normal execution.

## Changes

- Add a stable-extension CUDA top-k selector that orders by score and then request-local source index. Use the same tie-break for supported prefill and batch-invariant decode instead of inheriting packed-batch offsets.
- Assemble C4/C128 sparse and sliding-window indices with stable ordering, padding, lengths, and graph-safe metadata. This matters because FlashMLA consumes the index list in order, not merely as a set.
- Launch batch-invariant prefill one request per chunk so the shared workspace dimensions and FlashMLA launch geometry are request-local. In supported decode, use model-capacity-based KV workspace offsets and stable C128 index widths rather than batch-local maxima.
- Add `VLLM_DS4_DECODE_KERNEL=sparse` to opt into the prefill-style sparse FlashMLA decode path. The default is `paged`; this choice is separate from `VLLM_BATCH_INVARIANT`.
- Reject unsupported DCP/PCP batch-invariant sparse top-k and text-with-image aligned sparse attention, instead of silently changing the numeric contract.

## Scope and dependencies

Builds on #59863 for the stable CUDA operator infrastructure; until that PR lands and this branch is rebased, this diff includes its kernel. The guarantee is limited to supported sparse selection, index assembly, and attention under the same request/input contract. It does not establish prefill/decode equivalence, full-model train/rollout alignment, or support for DCP/PCP and image tokens. MoE, mHC, reload, and split-K are outside this PR. Request-local prefill can trade batching efficiency for determinism.

## Validation

- Previously reported local H100 80GB run (Python 3.12, PyTorch 2.13.0+cu130): **109 passed, 9 skipped** across targeted top-k, DeepGEMM, FlashMLA, kernel-contract, and environment suites. Native stable-ABI build and CUDA Graph replay checks also passed in that run.
- Tests cover score ties, packed-offset independence, C4/C128 index assembly, sparse FlashMLA behavior, and unsupported-path rejection. Applicable local pre-commit hooks passed.
- Upstream pre-commit CI was gated by the repository pre-run eligibility check; this is not a passing test result. Full-model alignment, Blackwell, multi-rank NCCL, and serving performance were not validated. No benchmark table is included because serving latency and throughput were not measured.
