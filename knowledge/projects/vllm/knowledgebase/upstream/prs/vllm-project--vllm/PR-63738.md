# [Bugfix][CPU] Run encoder-only attention bidirectionally in CPU_ATTN

[Upstream PR](https://github.com/vllm-project/vllm/pull/63738) · state: closed · merged: True

## Original PR description



## Overview

`CPU_ATTN` runs causal attention for layers built as a plain `Attention(attn_type=ENCODER_ONLY)`, so EmbeddingGemma 2 and ColQwen3.5 silently return wrong embeddings on CPU. The CPU metadata builder now treats encoder-only groups as non-causal.

## Claims

- Fixes CPU output for EmbeddingGemma 2, ColQwen3.5 with the bidirectional contract, and `openpangu` with `is_causal=False`.
- EmbeddingGemma 2 now uses `EncoderOnlyAttention`, like BERT and ModernBERT.
- No GPU change. The GPU backends already run `ENCODER_ONLY` attention bidirectionally.

## Validation

```
pytest tests/kernels/attention/test_cpu_attn.py -k test_encoder_only_attention_ignores_default_causal
```

- main: 2 failed. 99% of elements mismatched, max abs diff 3.05, and the output matches a causal reference within 4.8e-7.
- This PR: 2 passed. `test_cpu_attn.py -k "encoder or dynamic_causal"` (74 passed), `test_embedding_gemma2.py` and pre-commit also pass.

Model checks, outside CI because CPU CI does not run these model tests:

| Model | Without fix | With fix |
|---|---|---|
| EmbeddingGemma 2, real weights, x86 CPU (v0.32.0), cosine vs sentence-transformers (text, image, video) | 0.75–0.98 | ≥ 0.99996 |
| ColQwen3.5, real weights, x86 CPU (v0.32.0), max change in earlier tokens when only the last token differs | 0.0 (causal) | 0.161 (bidirectional) |
| `openpangu` with `is_causal=False`, tiny dummy weights, same check | 0.0 (causal) | 1.4e-3 (bidirectional) |

The ColQwen3.5 and `openpangu` rows check future-token dependence and do not compare outputs against a reference implementation. With bidirectional attention, changing the last token changes the outputs of the earlier tokens, while with causal attention it does not.

## Details

Both model runners build encoder-only `CommonAttentionMetadata` with the default `causal=True`. `EncoderOnlyAttention` clears it, but a plain `Attention(ENCODER_ONLY)` does not. The GPU backends ignore the flag for encoder attention, while `CPU_ATTN` passes it to the scheduler metadata and the kernel, so the fix is in the builder where both are derived.

**Why the EmbeddingGemma 2 change.** The HF reference runs every layer bidirectionally without a KV cache, which is what `EncoderOnlyAttention` encodes. BERT, ModernBERT and the `is_causal=False` paths of Llama, Qwen3 and Gemma 3 already use it, and the encoder-only runner's comment that the encoder builder forces `causal=False` assumes it. This change alone already fixes EmbeddingGemma 2 on CPU: the EmbeddingGemma 2 row above was measured with only this change applied.

This is not a duplicate of the open EmbeddingGemma 2 PRs. They fix the Triton prefill kernel on GPUs, while this PR fixes how the CPU backend applies the causal flag, a path those PRs do not touch.

**To reviewers.**

- The EmbeddingGemma 2 commit does not change output once the builder is fixed. Keep it for consistency with the other encoder models, or drop it?
- The new test covers the CPU builder and kernel directly. Would you also like an end-to-end test through `LLM`? The real checkpoints are too heavy for CPU CI, but a tiny dummy-weight `openpangu` model with `is_causal=False` reproduces the bug in a few seconds.
