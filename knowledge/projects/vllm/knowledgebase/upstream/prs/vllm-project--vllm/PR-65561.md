# [Bugfix][KV Offload] SimpleCPUOffload: requeue a finished request's CPU prefix, free CPU blocks tail first

[Upstream PR](https://github.com/vllm-project/vllm/pull/65561) · state: open · merged: False

## Original PR description

## Overview

Follow-up to #62444, which moves the CPU copy of a GPU prefix hit to the MRU end at admission. Two more places still leave eager `SimpleCPUOffloadConnector`'s CPU tier in store order, so eviction takes the head of a prefix first, and a CPU lookup, which stops at the first missing block, loses the whole chain:

- Eager stores land chunk by chunk, head first: a prompt prefilled in several chunks has its first blocks at the LRU end of the CPU free queue.
- Loaded blocks (`_cleanup_load_request`) and released lookup pins (`_free_pending_cpu_hit`) are freed in prefix order.

This PR:
- Once a finished request's stores have landed, requeues its CPU-cached prefix at the MRU end, tail first (`_refresh_cpu_prefix`, the helper #62444's admission refresh now uses too). The request stays registered until its finish-time flush lands, so the refresh covers the blocks that flush stores.
- Frees loaded blocks and released lookup pins tail first, as the GPU KV cache manager does.

Lazy mode keeps its behavior apart from the tail-first frees. The refresh costs one CPU prefix lookup per finished request, as #62444 does per admitted GPU hit.

## Claims

- `test_chunked_prompt_cpu_copy_evicts_tail_first`: a 4-block prompt stored in two chunks, then half evicted, keeps blocks 0-1 here; main keeps blocks 2-3, so its CPU hit is 0 tokens.
- `test_cpu_prefix_refresh_waits_for_finish_flush`: the request stays registered until its finish-time flush lands, and the block that flush stores is evicted first; main releases the request at finish, before the flush.
- Both fail on main and pass here; the rest of the SimpleCPUOffload tests pass unchanged (numbers below).
