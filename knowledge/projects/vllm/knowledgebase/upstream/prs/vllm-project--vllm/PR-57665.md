# [Bugfix] Copy unaligned packed slices before dtype view

[Upstream PR](https://github.com/vllm-project/vllm/pull/57665) · state: open · merged: False

## Original PR description

## Overview

Fix `unpack_tensor()` when a preceding packed tensor leaves a byte offset that is unaligned for the next tensor's dtype. Only unaligned slices are copied; aligned tensors retain shared storage.

The current head is `784b5f890f8382a872632e40cbf0ef68e355f1ce`, including the scalar support from #52235. Scalar support alone does not fix mixed dtype alignment.

## Claims

* Mixed dtype tensors round trip on CPU and CUDA without the dtype view `storage_offset()` error.
* Aligned transfers retain the existing shared storage behavior.
* The current transfer source works with real Qwen3 weights and an independent vLLM model worker over CUDA IPC on DGX Spark GB10.

## Validation

The current source passed all 40 tests from the pinned `tests/distributed/test_packed_tensor.py`, including CUDA cases. The test file and complete transfer module were loaded into an existing vLLM environment. This was a focused source overlay validation, rather than a full source build. Ten warnings include existing oversized buffer cases and CUDA IPC teardown warnings.

The real model experiment used baseline transfer source `61f084b5f3e58aa3d3eb5c86aeaf4686c460c478` and current head `784b5f890f8382a872632e40cbf0ef68e355f1ce`. Source hashes, executable reproducer and raw trial results are in the [reproduction gist](https://gist.github.com/bojiang-li/692f34e57456290dd900471fac4c06d0). Use `CURRENT-GPU-REPRODUCTION.txt` and files prefixed `current-`; the older files refer to earlier commits.

Runtime: vLLM `0.28.1rc1.dev87+g6d4562c59`, Torch 2.13.0, CUDA 13.0, safetensors 0.8.0, NVIDIA GB10. The model runtime revision and pinned transfer source revisions are recorded separately. Qwen3 0.6B checkpoint revision: `c1899de289a04d12100db370d81485cdf75e47ca`.

The input contains 311 BF16 checkpoint tensors totaling 1,503,264,768 bytes. An independent worker imports the CUDA IPC data, calls `model.load_weights`, and acknowledges CUDA completion before the wall timer stops. Each successful update matches all 226 fused parameters and the same 16 greedy output tokens. Parameter and generation checks are outside the timer. There were 74 successful updates and two expected baseline alignment failures.

| Aligned complete update, 31 alternating pairs | Result |
| :--- | :--- |
| Before median | 56.9902 ms |
| After median | 57.1314 ms |
| Median paired change | +0.2708 ms, +0.4679% |
| Paired bootstrap 95% interval | negative 0.2289% to positive 1.1928% |

The interval includes zero. This experiment did not resolve an overhead difference and does not establish zero overhead or equivalence. The results apply to this integrated GB10 system. An unaligned BF16 prefix fails before the fix and passes afterward, so there is no valid speedup percentage for that case.

Reproduce using the compatible runtime and local checkpoint, after saving the four `current-` source files from the gist under their original names:

```sh
VLLM_WORKER_MULTIPROC_METHOD=spawn VLLM_USE_FLASHINFER_SAMPLER=0 OMP_NUM_THREADS=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 python ipc_update_benchmark.py --model /path/to/Qwen3-0.6B --trials 31 --warmup 3 --unaligned-trials 3 --auxiliary-trials 3 --buffer-mib 2048 --output reproduced-current-ipc.json
```

## Details

A three element fp16 tensor occupies six bytes. Viewing the next slice as fp32 fails because its storage offset is not divisible by four. Calling `.contiguous()` on an already contiguous slice does not reset this offset. The fix clones only such unaligned slices before dtype reinterpretation. It changes no packing format or public signature and adds no dependency or explicit CPU/GPU synchronization to steady state inference.

This real model fixture uses one 2 GiB capacity chunk for the complete checkpoint. An earlier 512 MiB partial checkpoint fixture failed tied weight finalization. Separate multichunk IPC tests do not establish arbitrary model loader chunk correctness. Cross node NCCL, datacenter performance and leak freedom remain unvalidated. CUDA IPC teardown warnings remain in separate controls.
