# [Bugfix][CPU][RISC-V] Round software BF16 conversions to nearest even

[Upstream PR](https://github.com/vllm-project/vllm/pull/64079) · state: open · merged: False

## Original PR description

## Overview

Make software FP32-to-BF16 stores use round-to-nearest-even and preserve NaNs as canonical quiet NaNs. This corrects the RISC-V scalar and RVV software fallback when native BF16 narrowing is unavailable.

## Claims

- Match PyTorch's software BF16 conversion contract instead of truncating the low 16 bits.
- Keep low-payload FP32 NaNs from becoming BF16 infinities.
- Add a public BF16 SiLU-and-multiply regression using a value that distinguishes truncation from rounding.
- Cover 18 software-conversion boundary cases in a compiled-header test selected by CPU hardware CI.

## Details

The helper previously shifted away the lower bits. Adding the tie-to-even rounding bias corrects finite values, including subnormal and overflow boundaries; explicit NaN handling follows PyTorch and does not promise NaN sign/payload preservation. All helper users, including the scalar backend, receive the corrected contract.

Duplicate-work searches for `float_to_bf16`, `float_convert.hpp`, and RISC-V BF16 rounding found no matching open PR. #52934 concerns FP16 narrowing rather than this BF16 helper.
