[Upstream PR](https://github.com/vllm-project/vllm/pull/57182) · state: open · merged: False

## Original PR description

## Purpose

Fixes #57059.

The ROCm custom all-reduce kernels could enter their start barrier without ordering earlier input writes before peer reads. Use the release/acquire start barrier on ROCm and system-scope loads for cross-device flag visibility. The CUDA path is unchanged.

I checked the issue and searched open PRs by issue number and relevant keywords. No existing PR addresses this memory-ordering fix. #57042 touches the same kernel but changes accumulation order, which is unrelated.

AI assistance was used to inspect the code and prepare the patch. The final change was reviewed and tested by the submitter.
