# [NIXL] Share in-flight prefix loads across requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/59343) · state: open · merged: False

## Original PR description

## Overview

Add opt-in sharing of unfinished NIXL prefix loads across requests with separate producer leases, following [RFC #59141](https://github.com/vllm-project/vllm/issues/59141) and dependent on [#57418](https://github.com/vllm-project/vllm/pull/57418).

Current source **`a6236f0`**, tree **`433f55a`**, merges main **`642c18d`** while retaining parent #57418 at **`367746f`**. The full PR against main includes that unmerged parent. This remains a **draft** pending final-source hardware acceptance, human line-by-line review and personal execution of relevant tests.

## Claims

- Concurrent consumers of the same leased physical producer prefix can share immutable complete destination blocks while retaining private writable tails. Each sibling has its own producer lease; matching tokens alone is insufficient.
- Followers release unused leases without another READ. Cancellation retains owner destinations and heartbeat until terminal transfer status; failures follow the parent's recompute/fail policy without rereading released follower leases.
- The parent supplies the pending-load index, transfer-owned block pins and failure propagation. NIXL adds producer/endpoint/geometry/physical-block compatibility and lease coordination.

## Details

Initial scope is direct GPU pull, TP1/PP1/CP1, one full-attention cache group and prefix caching, enabled with `enable_shared_prefix_loads=true` and disabled by default. Unsupported layouts or missing producer block geometry retain independent loads. The owner keeps its full READ; followers share only complete prefix blocks before the last request token.

NIXL registers only the truncated immutable blocks in the parent's `PendingPrefixLoad` index; the writable last block stays private. Completion/failure removes the pending entry and releases transfer pins. An incompatible longest pending prefix conservatively falls back to an independent load. The parent's single KV-holding queue transition and KV-fetch tracking remain intact.

HTTP rejection cleanup tracks successful admission across child tasks. Unknown polling exceptions retain native handles; typed remote disconnect enters release, and a failed release retains the handle and blocks. Persistent unobservable native status does not promise bounded recovery.

The October 16 main merge had one import conflict in `async_llm.py`. The resolution retains both `kv_transfer_admission` and all three upstream Elastic EP middleware imports. Across the PR's 21 files, the feature's added/deleted lines against new main are identical to those against the previous main snapshot. Existing parent history, DCO trailers and coauthor attribution are preserved; no history rewrite was needed.

Before initial submission, open-PR searches found no competing #59141 implementation. [#55374](https://github.com/vllm-project/vllm/pull/55374) composes Store/NIXL ranges within one request; [#43509](https://github.com/vllm-project/vllm/pull/43509) handles best-of fan-out/early notifications. This follow-up shares an unfinished READ across distinct producer leases.
