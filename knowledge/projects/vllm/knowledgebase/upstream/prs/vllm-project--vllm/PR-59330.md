# [Bugfix][KV Connector] Stop P/D transfers short of the last prompt token

[Upstream PR](https://github.com/vllm-project/vllm/pull/59330) · state: open · merged: False

## Original PR description

## Purpose

P/D decode recomputes the last prompt token. NIXL and Mooncake load all N prompt tokens and the scheduler then rewinds one token, but by then every group was laid out for position N. For a sliding window, prefill and decode both drop the block holding position N - W whenever N % block_size == block_size - 1, so the recomputed token N - 1 attends to the null block. With a zeroed null block this silently perturbs one window position for 1/block_size of requests; on DeepSeek-V4.1, whose null block is not zero, it corrupts the output (NaN logits at 1023/4095/8191 tokens, reported in #59197).

The local prefix cache never has this problem: it caps a hit at N - 1 before allocation. Mamba P/D already avoided it with a Mamba-only backoff. This PR makes the backoff unconditional, so P/D follows the same rule as the local cache for every model.

## Changes

- NIXL `_prefill_backoff()` and Mooncake P2P: the prefiller always stops at N - 1, and the decoder loads N - 1 tokens and computes the last one (multi-module MTP still backs off its lookahead). Both sides then lay out every group for the position decode resumes at.
- NIXL bidirectional transfer: the prefiller pulls the decoder's KV from an earlier turn only if that KV ends before its last prompt token. The workers pair blocks from the end of the sequence, so a shorter pull (a prompt shorter than the decoder's context, e.g. a regenerated turn, or one the decoder's KV fully covers now that the prefiller stops one token short) shifted every block.
- The cut never splits a multimodal item: if the prompt ends inside one, both sides back off to the item's start, the prefiller drops the item and the decoder computes it. Models parse an item from its whole placeholder (Qwen3-VL looks up each video frame's end marker), and with `disable_chunked_mm_input` and a lookahead (EAGLE) the scheduler could never schedule an item running past the cut prompt. Shared helpers `get_prefill_stop` / `truncate_prompt_for_prefill` in `kv_connector/utils.py` hold this rule for NIXL and Mooncake, and also cut mixed token-id / embeddings prompts consistently (they used to keep the embeddings and mask at full length, which the worker rejects).
- The cut stays off other prompt-indexed request features: a request with prompt logprobs (e.g. completions with echo and logprobs) transfers nothing, since it skips reading the prefix cache and the decoder never loads its KV (the prefiller returned prompt logprobs for one token fewer than the prompt and the frontend failed); the routed-experts (R3) start is clamped to the prompt length (a start equal to the original length made the scheduler assert); and the cut rebinds the prompt and kv_transfer_params, which in-process parallel samples share.
- NIXL push: a decode-side prefix hit of N - 1 tokens leaves nothing to receive; stop heartbeating the prefiller so it reclaims its blocks when the lease lapses, instead of holding them until the decode request ends.
- `get_num_new_matched_tokens` documents the contract: the count should leave the last prompt token to compute, and a connector transferring from a peer must have the peer stop at the same position, since P2P connectors pair blocks from the end of the sequence.

Behavior changes for full-attention-only models, which previously loaded all N tokens:

- Decode computes the same single token as before; prefill computes one token less and transfers one block less when N % block_size == 1.
- A request sent to the prefiller with `do_remote_decode` always generates one token, which routers already discard (as for Mamba today); P/D prompt logprobs omit the last prompt token.
- The prefiller no longer caches the block holding the last prompt token when N % block_size == 0. A resend of the same prompt is unaffected, since local hits stop at N - 1 anyway.
- Known pre-existing limitation, fixed by #59746: with different P/D block sizes and a decode-side prefix hit, NIXL pairs the transferred blocks one prefill block off whenever the decoder pads past the last token (about half of prompt lengths, on main and with this PR alike); this PR changes which lengths are affected, since decode now loads N - 1 tokens.
- Prefill and decode must run this change together: a decode with it and a prefill without it pair blocks one position apart when N % block_size == 1. NIXL's compatibility version is bumped to 14, so the handshake rejects such a pair.

## Not a duplicate

No open PR addresses the sliding-window rewind. #58556 aligns Mooncake with NIXL's multi-module MTP backoff in the same Mooncake functions; the two compose (the larger backoff wins).
