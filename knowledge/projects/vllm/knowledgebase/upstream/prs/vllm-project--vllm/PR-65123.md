# [Bugfix][EC] Republish runner cache hits after CPU-tier eviction

[Upstream PR](https://github.com/vllm-project/vllm/pull/65123) · state: open · merged: False

## Original PR description



## Overview

Republish producer runner-cache hits after eviction from ECCPU's CPU tier. Previously, repeated requests skipped encoding and saving, so the producer could retain the tensor but return no transfer address to a fresh consumer.

Related: #65079 fixes consumer admission; this PR addresses producer publication independently. Open-PR searches found no duplicate; #63294 concerns filesystem tiering.

## Claims

- Reserve a CPU save on runner-cache hits through a new optional connector callback.
- Save existing tensors through `start_save_caches()`, reusing the normal completion/ready path without rerunning the encoder.
- Preserve consumer-only behavior and avoid redundant loads on `ec_both` cache hits.

Base output: `AssertionError: assert 'cached-image' in {}`; `2 failed, 280 deselected`. The fix produces save metadata without scheduling encoder computation and marks the entry ready after the completion report. Pre-commit passed on all changed files.

The real-server regression repeats an image after producer CPU eviction and checks that a fresh consumer can fetch it. All 3 tests in `test_nixl_failure.py` were skipped without CUDA GPUs; GPU serving/model evaluation is deferred as requested by the author. No GPU correctness or performance result is claimed. The server suite has no dedicated CI step; existing core/connector suites cover CPU checks.

## Details

Runner cache hits previously bypassed `update_state_after_alloc()`, leaving no CPU blocks or save metadata after independent CPU eviction. A default no-op `update_state_after_cache_hit()` callback lets ECCPU reserve a producer save separately from consumer loads. Existing connector implementations inherit the no-op without requiring changes.

At step entry, ECCPU saves only metadata-listed tensors already in the runner cache. Freshly encoded outputs use the existing save hook. Missing CPU capacity retains the existing behavior of not publishing an unavailable entry.
