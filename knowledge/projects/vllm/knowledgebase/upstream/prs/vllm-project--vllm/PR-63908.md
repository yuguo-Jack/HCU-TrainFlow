# [Bugfix][Qwen4Exp] Return float8_e4m3fn from decode_nvfp4_csf in Qwen4Exp NVIDIA model

[Upstream PR](https://github.com/vllm-project/vllm/pull/63908) · state: closed · merged: False

## Original PR description

## Overview
Fixes an issue in Qwen4Exp where NVFP4 Compressed Scale Factor (CSF) decoding returned raw uint8 tensors instead of float8_e4m3fn, causing activation explosion and garbled output.

## Claims
- Correctly casts decoded NVFP4 CSF scale tensors to torch.float8_e4m3fn.
- Resolves 56x scaling error on ModelOpt NVFP4 checkpoints (e.g. nvidia/Qwen3.8-Flash-Next-FP4-Local).
- Adds unit tests for CSF fixed and exception decoding.

## Validation
- Verified with greedy completion and chat completion tests on Qwen3.8 Flash Next FP4 on Blackwell.
- Added tests in tests/models/qwen4_exp/test_nvfp4_csf_decode.py.

## Details
In decode_nvfp4_csf, raw scales were returned as uint8. Downstream multiplications converted scales via scales.to(bfloat16), casting byte 0x38 (representing 1.0 in FP8 E4M3FN) to integer 56.0 in bfloat16.
