# Perf: Optimize CPU detokinzation for long decodes

[Upstream PR](https://github.com/vllm-project/vllm/pull/36023) · state: open · merged: False

## Original PR description

## Purpose
Currently detokinzation will keep track of a string and update it one token at a time. When looking at long decodes it will cause copy and update for the string as strings are immutable. This changes the output_text to be a list of strings and materializes the real string only when needed, and only the required slice.

## Code Review

This pull request optimizes the detokenization process for long sequences by changing the `output_text` from a single string to a list of string chunks. This avoids inefficient string concatenations, which can be a performance bottleneck. The implementation introduces helper methods to handle suffix retrieval and truncation on the list of chunks. The logic appears correct and robust, and the changes are well-contained within the `BaseIncrementalDetokenizer`. This should provide a significant performance improvement for long decodes as intended.
