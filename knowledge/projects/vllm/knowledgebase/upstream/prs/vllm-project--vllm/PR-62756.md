# [Bugfix][ROCm] Muse Spark: apply output multiplier and softcap in compute_logits_local

[Upstream PR](https://github.com/vllm-project/vllm/pull/62756) · state: closed · merged: True

## Original PR description


## Overview

With `--enable-batch-sharded-sampling`, the ROCm Muse Spark model samples from logits that skip its output multiplier and final-logit softcap. This PR gives the model its own `compute_logits_local`, which applies the same transform as `compute_logits`. Follow-up to #62622.

## Claims

- With batch-sharded sampling, ROCm Muse Spark samples from the same fp32 logits as the default path: multiplier 32^-0.5 and softcap 20 are applied.
- With batch-sharded sampling off, which is the default, behavior is unchanged. `compute_logits` only moves its existing post-processing into a helper that both methods call.

## Validation

The new test calls `compute_logits_local` and `compute_logits` on the same hidden states and requires identical output. It fails on the base commit and passes with this PR:

```
$ pytest tests/models/test_muse_spark_logits_local.py -q      # base 2de0531d81
E   AssertionError: The values for attribute 'dtype' do not match: torch.bfloat16 != torch.float32.
FAILED tests/models/test_muse_spark_logits_local.py::test_compute_logits_local_applies_output_transform
1 failed

$ pytest tests/models/test_muse_spark_logits_local.py -q      # this PR
1 passed
```

On the base commit the inherited method returns the raw bf16 lm_head output, so the comparison fails on dtype before it reaches the values. The existing Muse tests also pass with this PR:

```
$ pytest tests/models/test_muse_spark_rocm_loading.py tests/transformers_utils/test_muse_spark_config.py -q
21 passed
```

These runs were CPU-only, in the ROCm image with no GPU attached. Because of that, the ROCm architecture query and device detection were stubbed locally. The new test is wired into the "Basic Models (Other)" Buildkite step and its MI355 mirror. The MI355 mirror now also lists `vllm/models/muse_spark/` as a dependency.

**Not yet done:** an end-to-end GPU run with `--enable-batch-sharded-sampling`, and a model evaluation such as GSM8K comparing the flag on and off. Both are needed before this PR leaves draft.

## Details

**Root cause.**
- The GPU model runner enables batch-sharded sampling for any model that has a `compute_logits_local` attribute (`vllm/v1/worker/gpu/model_runner.py:447-448`).
- In the sampling step it then calls that method and runs an all-to-all instead of calling `compute_logits` (`model_runner.py:1633`).
- The ROCm `MuseSpark1xForCausalLM` inherits `LlamaForCausalLM.compute_logits_local` (`vllm/model_executor/models/llama.py:553`), which returns raw lm_head logits.
- Muse's `compute_logits` (`vllm/models/muse_spark/amd/model.py:1096`) casts to fp32 and applies the multiplier and softcap. The batch-sharded path skipped all of that.
- Greedy decoding is unaffected, because both transforms preserve order. Sampled decoding and speculative-decoding rejection sampling used the wrong distribution.

**Fix.** The transform is elementwise, so applying it to each rank's vocab shard before the all-to-all gives exactly the logits `compute_logits` produces. The runner trims vocab padding after the all-to-all. A generic guard in the model runner was considered and rejected, to keep core code untouched.

**Not a duplicate.** No other open PR changes `compute_logits_local` for Muse Spark. #63078 touches Muse RoPE, not logits.

**Test limitation.** The test builds the model with `__new__` and sets the attributes `compute_logits` reads, instead of using the real constructor. Building a real Muse Spark model needs TP state and the full checkpoint config. This conflicts with `tests/AGENTS.md`'s preference for real constructors, and is noted for reviewers.

## GSM8K: batch-sharded sampling with and without this PR

**Setup.** 8x MI355X, TP8, `amd/Muse-Spark-Open-816B-A42B-Quark-MXFP4`, no speculative decoding. Image `vllm/vllm-openai-rocm:nightly-rocm100-df6603f05` (aiter 0.1.26, torch 2.13.0+rocm10.0.0), with each tree's Python overlaid; base is main 2de0531d81. Server flags are the AMD MXFP4 recipe's:

```bash
VLLM_ROCM_USE_AITER=1 VLLM_ROCM_MUSE_MOE_REDUCE_DTYPE=bf16 VLLM_USE_BREAKABLE_CUDAGRAPH=1 \
vllm serve amd/Muse-Spark-Open-816B-A42B-Quark-MXFP4 \
  --tensor-parallel-size 8 --dtype bfloat16 --distributed-executor-backend mp \
  --language-model-only --compilation-config '{"cudagraph_mode":"FULL_AND_PIECEWISE"}' \
  --no-enable-prefix-caching --enable-chunked-prefill --attention-backend ROCM_AITER_FA \
  --max-model-len 32768 --max-num-seqs 128 --max-num-batched-tokens 8192 \
  --gpu-memory-utilization 0.90 [--enable-batch-sharded-sampling]

# 5-shot, all 1,319 questions, max 256 tokens, 64 concurrent requests
python tests/evals/gsm8k/gsm8k_eval.py --port 8000 --num-shots 5 --max-tokens 256 --max-concurrency 64 --temperature 0
python tests/evals/gsm8k/gsm8k_eval.py --port 8000 --num-shots 5 --max-tokens 256 --max-concurrency 64 --temperature 1.0 --seed 42
```

Accuracy is shown ± one binomial standard error (n = 1,319). Sampled runs also use the model's default `top_k` 64 from its generation config.

| Code | `--enable-batch-sharded-sampling` | Greedy accuracy | Sampled accuracy, T=1.0 | Sampled output tokens |
|---|---|---|---|---|
| main 2de0531d81 | off | 0.9507 ± 0.0060 | 0.8196 ± 0.0106 | 142,640 |
| main 2de0531d81 | on | 0.9462 ± 0.0062 | **0.9469 ± 0.0062** | 123,631 |
| this PR | on | 0.9500 ± 0.0060 | **0.8067 ± 0.0109** | 143,352 |

All three servers start with the same KV cache (167.67 GiB, 8,173,209 tokens). Both flag-on servers log `Batch-sharded sampling enabled.` on all 8 ranks.

- **Greedy is unaffected.** All three greedy scores agree within one standard error, as expected: the multiplier and softcap preserve the order of the logits.
- **On main, the flag silently breaks sampling.** The temperature-1.0 run scores 0.9469 with 123,631 output tokens. That matches the greedy run (0.9462, 123,688 tokens) and is 12.7 points above main with the flag off. Without the 32^-0.5 multiplier the logits are about 5.7x too large, which acts like a temperature of about 0.18, so requested sampling becomes nearly greedy.
- **This PR restores the expected distribution.** With the flag on, the sampled score (0.8067) and output length (143,352 tokens) match main with the flag off (0.8196, 142,640 tokens). The 1.3-point gap is within 1 combined standard error.
