# [Spec Decode] Add draft_context_window for EAGLE-3 drafters

[Upstream PR](https://github.com/vllm-project/vllm/pull/63245) · state: open · merged: False

## Original PR description

## Overview

Adds `draft_context_window` for EAGLE-3: the drafter attends to its last N tokens, with no checkpoint edit. Same field name as #61261 (DFlash, DSpark). Supersedes #53827.

## Claims

- A shipped EAGLE-3 drafter keeps its acceptance length at 32k: 2.14 against 1.06.
- Decode at 32k goes from 16 to 34 tok/s.
- Off by default.

## Validation

Llama-3.1-8B-Instruct with nebius/EAGLE3-Llama-3.1-8B-Instruct, K=3, greedy, batch 1, one A40, 6 prompts per length.

| acceptance length | 8k | 16k | 32k |
|---|---|---|---|
| draft_context_window unset | 1.68 | 1.05 | 1.06 |
| draft_context_window=2048 | 2.12 | 2.18 | 2.14 |

```
pytest tests/v1/spec_decode/test_draft_context_window.py tests/test_config.py::test_draft_context_window_config
pytest tests/v1/spec_decode/test_acceptance_length.py -k draft_context_window  # GPU, slow
```

The first passes on CPU and fails on main. The second passed on the A40 at 1.81 against a 1.5 floor. With FlashInfer on the A40, a windowed drafter raised "Window left is not the same for all layers" before the attention group split and generates after it.

## Details

Draft layers keep a full KV spec and stay in the target's KV group. SlidingWindowSpec would save 3 percent of KV but make 33 groups. Other drafters raise at load. Both runners' attention groups now split on sliding window, as FlashInfer outside TRTLLM rejects mixed windows. Other models see it only with --disable-hybrid-kv-cache-manager and a windowed target.
