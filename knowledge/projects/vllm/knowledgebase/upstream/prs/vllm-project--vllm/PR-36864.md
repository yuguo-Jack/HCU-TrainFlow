# [Model] Add OmniASR (Meta Omnilingual ASR) model support

[Upstream PR](https://github.com/vllm-project/vllm/pull/36864) · state: open · merged: False

## Original PR description

## Purpose

Add initial model support for Meta's OmniASR (Omnilingual ASR) model family.
Addresses #28509 and #36784.

OmniASR is an encoder-decoder ASR model supporting 1600+ languages, built on fairseq2:
```
Audio (16kHz) -> Wav2Vec2 CNN Frontend (7 conv layers, dim=512)
             -> Proj (512→1024)
             -> Wav2Vec2 Transformer Encoder (24 layers, dim=1024)
             -> Linear Projection (1024 -> 4096)
             -> LLaMA Decoder (12 layers, dim=4096)
             -> Text Output (vocab=9812)
```

No cross-attention. Encoder outputs are projected and used as input embeddings (same pattern as Ultravox).

Current status:
- Wav2Vec2 CNN frontend and 24-layer Transformer encoder implemented
- Encoder attention uses MMEncoderAttention / QKVParallelLinear / RowParallelLinear
- Weight loading verified against omniASR-LLM-300M checkpoint (535/535 keys matched)
- Encoder forward pass tested (16kHz audio -> 49 frames x 4096-dim output
- Encoder → LLaMA projection (1024 → 4096)
- 12-layer LLaMA decoder integrated with vLLM's `LlamaForCausalLM` pattern
- Model registration + processor (`OmniASRProcessingInfo`, `OmniASRDummyInputsBuilder`)
- Pytest run passed

**Model checkpoint**: 
- Verified against: [`ziywang50/omniASR-LLM-300M`](https://huggingface.co/ziywang50/omniASR-LLM-300M)
- Original (upstream): [`facebook/omniASR-LLM-300M`](https://huggingface.co/facebook/omniASR-LLM-300M)

The fork (`ziywang50/...`) adds metadata missing from the official repo:
- Full `config.json` (Facebook's only ships partial config): `rms_norm_eps: 1e-5` (matches fairseq2 reference; HF default `1e-6` is incorrect)
- language lookup table
- model.safetensors
- tokenizer.model
- tokenizer_config.json

The forked path now includes [`ziywang50/omniASR-LLM-300M`](https://huggingface.co/ziywang50/omniASR-LLM-300M), [`ziywang50/omniASR-LLM-1B`](https://huggingface.co/ziywang50/omniASR-LLM-1B), [`ziywang50/omniASR-LLM-3B`](https://huggingface.co/ziywang50/omniASR-LLM-3B), and [`ziywang50/omniASR-LLM-7B`](https://huggingface.co/ziywang50/omniASR-LLM-7B)
We've reached out to Meta to upstream these fixes; once their repo is complete,
the PR can switch to the official path.

Finished:
- **Dual embedding architecture**: OmniASR uses two embedding tables — `text_frontend (9813, 4096)` for main vocab and `lang_embeddings (1694, 4096)` for `lid_marker` + 1693 language tokens. vLLM's default single-embedding assumption doesn't apply. ### Note: FlashInfer compatibility

OmniASR's LLaMA decoder has `head_dim=512` (4096 hidden / 8 heads), which is 
larger than FLASH_ATTN's supported range. The decoder requires one of: 
FLASHINFER, TRITON_ATTN, or FLEX_ATTENTION.

On the current upstream main, FLASHINFER hits a kernel-level regression for 
head_dim=512 (`Unsupported max_mma_kv: 0` during kernel warmup). To run this 
model on current main, use:

```bash
python -m vllm.entrypoints.openai.api_server \
  --model ziywang50/omniASR-LLM-300M \
  --attention-backend TRITON_ATTN \
  --enforce-eager --dtype bfloat16
```

## Code Review

This pull request introduces initial support for the OmniASR model, focusing on the encoder architecture. The implementation is a good starting point, but there are critical issues in the attention and feed-forward network modules related to tensor parallelism. These modules currently use standard `nn.Linear` layers or incorrect head count calculations, which will not work correctly in a distributed environment with `tensor_parallel_size > 1`. I have provided specific suggestions to refactor these components using vLLM's parallel layers to ensure they are compatible with tensor parallelism.

- gemini-code-assist[bot] · comment · 2026-03-12T08:48:44Z · [source](https://github.com/vllm-project/vllm/pull/36864#discussion_r2923128883)

File: `vllm/model_executor/models/omniasr.py` · line 355

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

The `Wav2Vec2Attention` module does not correctly handle tensor parallelism. The number of heads for Q, K, V and for the attention mechanism are calculated using the total number of heads, not the per-partition number of heads. This will cause incorrect shapes and errors when `tensor_parallel_size > 1`.

The implementation should be updated to be tensor-parallelism-aware, calculating per-partition head counts and using them to split the QKV tensor and initialize `MMEncoderAttention`.

You will also need to add `from vllm.distributed import get_tensor_model_parallel_world_size`.

```python
class Wav2Vec2Attention(nn.Module):
    """Self-attention with separate q/k/v/output projections (matching checkpoint)"""
    def __init__(self, embed_dim=1024, num_heads=16):
        super().__init__()
        tp_size = get_tensor_model_parallel_world_size()
        self.total_num_heads = num_heads
        self.total_num_kv_heads = num_heads
        self.num_heads = self.total_num_heads // tp_size
        self.num_kv_heads = self.total_num_kv_heads // tp_size
        self.head_dim = embed_dim // self.total_num_heads
        self.scaling = self.head_dim**-0.5

        self.qkv_proj = QKVParallelLinear(
            hidden_size=embed_dim,
            head_size=self.head_dim,
            total_num_heads=self.total_num_heads,
            total_num_kv_heads=self.total_num_kv_heads,
            bias=True,
        )
        self.output_proj = RowParallelLinear(
            input_size=embed_dim,
            output_size=embed_dim,
            bias=True,
        )
        self.attn = MMEncoderAttention(
            self.num_heads,
            self.head_dim,
            self.scaling,
            num_kv_heads=self.num_kv_heads,
        )
        self.q_size = self.num_heads * self.head_dim
        self.kv_size = self.num_kv_heads * self.head_dim

    def forward(self, x):
        qkv, _ = self.qkv_proj(x)
        q, k, v = qkv.split([self.q_size, self.kv_size, self.kv_size], dim=-1)
        attn_output = self.attn(q, k, v)
        output, _ = self.output_proj(attn_output)
        return output
```

![critical](https://www.gstatic.com/codereviewagent/critical.svg)

The `Wav2Vec2FFN` module uses `nn.Linear`, which does not support tensor parallelism. This will lead to incorrect behavior when `tensor_parallel_size > 1`. You should use vLLM's parallel linear layers instead.

Specifically, `inner_proj` should be a `ColumnParallelLinear` layer, and `output_proj` should be a `RowParallelLinear` layer. You'll also need to update the `forward` method to handle the tuple outputs from these layers.

Make sure to import `ColumnParallelLinear` from `vllm.model_executor.layers.linear`.

```suggestion
class Wav2Vec2FFN(nn.Module):
    def __init__(self, embed_dim=1024, ffn_dim=4096):
        super().__init__()
        self.inner_proj = ColumnParallelLinear(
            input_size=embed_dim, output_size=ffn_dim, bias=True
        )
        self.output_proj = RowParallelLinear(
            input_size=ffn_dim, output_size=embed_dim, bias=True
        )

    def forward(self, x):
        x, _ = self.inner_proj(x)
        x = nn.functional.gelu(x)
        x, _ = self.output_proj(x)
        return x
```
