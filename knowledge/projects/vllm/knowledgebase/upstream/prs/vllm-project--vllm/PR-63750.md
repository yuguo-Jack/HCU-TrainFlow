# [Perf][LoRA] Preserve contiguous rank offsets in the MoE one-shot kernel

[Upstream PR](https://github.com/vllm-project/vllm/pull/63750) · state: open · merged: False

## Original PR description

## Overview

Use contiguous rank offsets in the fused MoE-LoRA one-shot kernel's A/B pointer arithmetic, retaining the existing rank masks. This implements the first optimization described in #61665.

## Claims

- Removes the rank-offset `tl.where` that obscures contiguity from Triton's axis analysis.
- Preserves load masks, zero fill, arithmetic, launch parameters, and dispatch.
- No new speedup or bitwise-equivalence result is claimed for this revision. GPU validation is pending.

## Validation

This is a draft prepared without new GPU runs. Correctness tests, baseline-versus-patch bitwise comparisons, CUDA-graph replay, kernel profiling, end-to-end benchmarks, and model evaluations have **not** been run for this revision.

CPU-only checks passed:
- `git diff --check`
- `uv run --no-project .venv/bin/pre-commit run --files vllm/lora/ops/triton_ops/fused_moe_lora_op.py`

Existing `tests/lora/test_fused_moe_lora_kernel.py` includes ranks 4/8 padded to `BLOCK_R=16`, normal ranks, early exits, and additional one-shot cases. It is selected by the LoRA Buildkite job and its AMD mirror. These correctness tests do not establish the performance improvement or bitwise equivalence to the old kernel.

Pending GPU command: `uv run --no-project .venv/bin/python -m pytest tests/lora/test_fused_moe_lora_kernel.py -v`. Before marking ready, also compare identical seeded inputs against the base revision, including mixed/base/disabled adapters, padded ranks, and CUDA-graph replay, then measure the one-shot provider on both revisions and end-to-end serving.

The historical measurements in #61665 motivated this patch; they are not measurements of this PR's current upstream base.

## Details

`safe_offs_r = tl.where(rank_mask, offs_r, 0)` obscures the contiguous rank axis, which is the contiguous dimension of B. Direct `offs_r` avoids that clamp. All A loads (both EVEN_K branches) and the B load retain `rank_mask` and `other=0.0`; [Triton's masked-load contract](https://triton-lang.org/main/python-api/generated/triton.language.load.html) specifies that masked-out addresses are not loaded.

Pointer-alignment assertions, N-split annotations, launch tuning, and base-MoE alignment reuse are outside this PR. No public API or configuration changes.
