# [Fast Start] Preload the FlashInfer autotune table on the weight cache daemon

[Upstream PR](https://github.com/vllm-project/vllm/pull/60085) · state: closed · merged: True

## Original PR description



Extend the preload framework from weights-only to host-side artifacts and make the FlashInfer autotune table the first one.

The daemon gains a bounded, exactly-keyed artifact store served over its existing Unix socket, so any local process can fetch the table, not only the engine that owns the GPU. An engine that finds a table loads it and skips the autotune pass outright; an engine that has to tune hands its table back, so the pass runs once per GPU rather than once per restart. A hit still raises the Kimi K3 KDA projection-overlap limit that the pass sets on the model, since the table does not carry it.

`vllm preload --preload-autotune` runs one throwaway engine against the ready daemons so the pass and the JIT compilation happen at preload time, leaving the table on the daemons for every engine that follows. That engine resolves its defaults under the same usage context as `vllm serve`, since they feed the config hash the table is keyed by, and drops preload's disk-loader config, which its IPC loader would reject.
