# [CI] Shard Quantization Kernels automatically instead of by hand

[Upstream PR](https://github.com/vllm-project/vllm/pull/65484) · state: open · merged: False

## Original PR description

## Overview

Replaces the fixed 6-way split of Quantization Kernels (`parallelism: 6` with `--shard-id`/`--num-shards`) with `automatic_shard`, for the step and its AMD mirror. The planner then sizes the step from main's per-file timings on every build, so it no longer needs a hand-tuned shard count as its tests change.

## Claims

| Job | Before | Plan |
|---|---|---|
| `kernels-quantization-test` | 6 fixed shards | 3 shards |
| its AMD mirror | 6 fixed shards | 3 shards |

- `test_cutlass_scaled_mm.py` and `test_fp8_quant.py` each run in their own pytest command. In one shared process, `test_fp8_quant.py` ran 2.4 times slower after `test_cutlass_scaled_mm.py`, which pushed one shard past 28 minutes.
- Half the jobs, each a few minutes longer than a fixed shard, and less machine time.
- Files that skip themselves at module level on a platform (FP8 block, NVFP4, ROCm- or CPU-only kernels) have no timings there; the planner counts a small guess for each, so the plan is conservative.

## Validation

- The sharding harness (each shard's commands run against a mock test tree, as a PR build and as main with the OTel wrapper) shows every test runs exactly once, for both the step and its mirror.
- `split_check.py` finds no step whose jobs each run the whole suite.
- Both jobs pass on recent main builds.
- Build 99747 (scoped, both jobs): every shard passed; slowest about 19.5 minutes on NVIDIA and 12.5 on AMD. Passed counts match main exactly (NVIDIA 3585 across the three commands, AMD 2909); machine time about 23% lower on NVIDIA and 26% lower on AMD. Skipped counts are lower only because a file that skips at module level counts once per pytest process, and the fixed split ran six processes.
- `/ci run` on this head for the required status.

## Details

- **Labels** drop the `Shard %N` suffix; the generator adds `shard N/M` to sharded jobs.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job.
