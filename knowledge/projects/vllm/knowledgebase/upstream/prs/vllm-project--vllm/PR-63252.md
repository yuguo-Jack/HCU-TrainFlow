# [Perf][MoE] Reuse expert mappings across fragmented weight loads

[Upstream PR](https://github.com/vllm-project/vllm/pull/63252) · state: open · merged: False

## Original PR description

## Overview

Reuse each default `RoutedExperts` layer's expert mapping and index across fragmented `load_weights` calls. Related to #62768, where interleaved weight delivery repeatedly revisits the same layer.

## Claims

- Reuse one mapping/index while its inputs are unchanged; rebuild when projection names, the LoRA prefix, expert counts or gated activation change.
- Preserve actual weight copies, public mapping results and subclass mapping hooks. Retain one Python metadata entry per default expert layer.

## Validation

Current regression validation: source `e38af8bd`, A800 80GB, Python 3.12, PyTorch 2.14.0+cu130 and Transformers 5.20.2. Both arms use the official `432b1003` native wheel; its production source, build inputs and dependencies match `e38af8bd` (the three intervening commits only change CI, a recipe and an unrelated test).

```bash
# Unmodified implementation, with the same new layer tests:
"$validation_python" -m pytest tests/kernels/moe/test_moe_weight_loading_padded.py -k 'interleaved_loads_reuse_mapping or public_mapping_mutation' -q
# Patched implementation, complete related file:
"$validation_python" -m pytest tests/kernels/moe/test_moe_weight_loading_padded.py -q
# Both implementations, real LLM regression:
"$validation_python" -m pytest tests/model_executor/model_loader/test_reload.py::test_interleaved_expert_reload_reuses_mapping -q -s
```

Here `validation_python` is the shared isolated environment's `.venv/bin/python`; `PYTHONPATH` selects each source arm and the same pinned native/dependency assets.

| Regression | Unmodified implementation + new tests | Patched |
| --- | --- | --- |
| Interleaved real-layer reload | Fails at `assert 48 == 2`; all weight comparisons pass | Passes; full related suite **87 passed, 0 skipped** |
| Real `LLM` loading/reloading | Fails at `{build: 48, index: 48} != {build: 0, index: 0}` after weight and output checks | **1 passed, 0 skipped** |

The LLM test saves a constructed two-layer Qwen3MoE checkpoint with real tensors, loads it through `LLM`, then sends interleaved expert weights through `apply_model` to the real `model.load_weights`. It checks every projection after changed-value and restoring reloads, and compares the complete four generated tokens under `VLLM_BATCH_INVARIANT=1`. The two arms' saved checkpoint SHA256 matches. Constructors and loading methods are not mocked; `cProfile` observes actual mapping construction without replacing methods. This is a synthetic regression fixture, not a pretrained accuracy evaluation or a RunAI throughput benchmark.

CPU validation: **83 passed, 4 existing GPU-dependent skips**. Applicable changed-file pre-commit checks passed, including mypy and Buildkite test tethering. Actionlint was excluded; no workflow file changes.

The earlier [full-model measurements](https://github.com/vllm-project/vllm/issues/62768#issuecomment-6305957328) remain separate evidence for the unchanged production patch, measured on `b1ab16c5` with the `612e92801` wheel: official Qwen3-30B-A3B BF16, one A800 80GB, TP1/eager, OMP=1, local shards and ordinary page cache. With RunAI 0.15.7, four predeclared AB/BA/BA/AB pairs gave:

| Measurement | Base | Patch |
| --- | ---: | ---: |
| Weight-loading median | 26.078 s | 18.199 s |
| Weight-loading mean ± sample SD | 26.566 ± 2.318 s | 19.039 ± 3.330 s |
| Complete LLM initialization median | 35.389 s | 27.608 s |

All four pairs improved by 6.058–9.978 s; the loading median decreased **30.21% for this configuration**. Eight fixed prompts, capped at 32 greedy tokens each, matched across runs. **RunAI 0.17 showed no repeatable improvement**; its three runs per arm gave loading means 16.935 ± 0.684 s and 16.871 ± 0.822 s. No cold-cache, inference-throughput or general accuracy improvement is claimed. The reporter's exact Qwen3.5 checkpoint was not reproduced. These latency measurements were not rerun for the test-only revision.

## Details

`AutoWeightsLoader` groups consecutive prefixes, while a streamed iterator may revisit layers. The cache key covers the inputs of the default mapping; subclasses remain uncached because their hooks may depend on additional state. Public `get_expert_mapping()` still returns independent lists. Tensor data and current local expert destinations are not cached.

RunAI 0.15.7 remains supported and CI-pinned. Version 0.17 still permits interleaved chunk completion, so upgrading is not a general ordering guarantee, although it substantially reduced repeated construction in the measured checkpoint. Whether the bounded loading benefit warrants the retained metadata is a tradeoff for review.

Duplicate checks covered the issue timeline, the full open-PR title inventory, newly opened PRs and overlapping patches. #58720 indexes within a call; #58791/#58820 concern bulk loading/staging; #60779 concerns local expert lookup; #61715/#61303 concern RunAI loading/staging. None of the inspected patches implements this cross-call mapping/index cache. The other interested contributor [confirmed no implementation and invited me to lead](https://github.com/vllm-project/vllm/issues/62768#issuecomment-6309278278). No competing PR was linked at the latest check; this is not maintainer approval.

The problem came from a public report and controlled independent reproductions, not the submitter's production workload. OpenAI Codex assisted with investigation, implementation and validation.
