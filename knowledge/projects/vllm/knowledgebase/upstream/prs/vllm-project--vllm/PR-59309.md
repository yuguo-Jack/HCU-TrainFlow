# [Bugfix][HiSparse] Fix MTP acceptance collapse under FULL graphs with a saturated GPU pool

[Upstream PR](https://github.com/vllm-project/vllm/pull/59309) · state: closed · merged: True

## Original PR description

## Purpose

Fixes MTP acceptance collapsing with HiSparse + speculative decoding under FULL CUDA graphs once the HiSparse GPU pool saturates. Two independent causes; both are needed on current main.

**1. Draft rows mirrored before the drafter writes them.** The MTP layers are HiSparse layers too, and HiSparse marks a page clean and releases it for all of its layers, target and draft, at once. Each step does:

```
start_step → target forward → finish_forward → propose (drafter writes its rows)
```

`finish_forward` mirrored *all* layers to host, including draft layers whose rows `propose` had not written yet, and then reported the step's pages clean. The drafter's own per-layer mirror is skipped under FULL graphs, so the fresh draft rows never reached host. When the page's GPU block was reused, the drafter read stale host rows.

**2. The residency resolver can read stale request ids** (regression from #59235). The resolver runs on the HiSparse copy stream, which outside PIECEWISE graphs waits only on `logical_topk_ready`, recorded right after the indexer. #59235 writes the masked request ids later, on the compute stream, so the resolver can read the previous call's ids. The MTP layer alternates four rows per request (draft prefill) with one (draft decode), so stale ids resolve draft rows against other requests' KV.

## Changes

- The speculator tags its draft attention layers (`AttentionLayerBase.is_draft_layer`); HiSparse binding marks their cache handles as draft layers.
- `finish_forward` mirrors only target layers.
- The next step's `start_step` first mirrors the previous step's draft-layer rows (the drafter has run by then), then submits that step's page transfers behind them on the same DMA stream, so a page is only reported clean after its draft rows are queued. They are queued before the step swaps host write events, so the new step's forward and host copies wait for them: by then the scheduler may have handed a finished request's GPU and host blocks to another request. No connector API changes (`wait_for_save` stays a no-op).
- Build the resolver's masked request ids on the copy stream after its wait, into buffers owned by the HiSparse index group (moved from the generic `SparseMLAIndexGroup`); `swap_in` now requires the valid-row count.

**Why not just move `finish_forward` after `propose`?** Outside FULL graphs the drafter re-prepares the draft handles with its own (decode-shaped) metadata, so a combined end-of-step mirror hits HiSparse's metadata consistency checks (`RuntimeError`) for every target/drafter graph-mode mix except FULL/FULL. Target and draft layers need to be mirrored at different points, which requires knowing which layers are draft layers.

**Known limitation (follow-up).** A host block freed after step N (finished or preempted request) can be reallocated to a P/D import before step N's deferred copies land; NIXL writes are not ordered against the copy stream, so an imported request could, rarely, receive stale draft-layer rows (or, with the non-default lazy mirror mode, stale rows for all layers of a preempted request's spilled page). GPU writes and host copy-on-write are ordered: the next step waits for the deferred copies before its forward and host copies. The follow-up holds freed host blocks until the step's deferred writes are reported done.

## Test Plan / Results

**Unit:**
- `test_draft_layer_rows_mirrored_after_drafter[FULL|NONE]` drives the real worker and checks that host draft rows equal the drafter's writes, with exactly one draft-layer copy and the page reported only after it. On main the FULL case fails.
- `test_hisparse_resolver_reads_current_request_ids` (GPU) stalls the compute stream between `logical_topk_ready` and attention, then resolves four rows per request followed by one row per request plus a padding row. It fails on main and passes here.
- H100: `test_sparse_mla_backends.py -k "hisparse or index_group"` 40 passed; HiSparse connector/worker tests pass.
- `tests/v1/e2e/general/test_hisparse.py`: the FULL-graph host-mirror check now verifies MTP rows when the next step's start mirrors them (it compared them right after `finish_forward`, before the drafter writes them) and requires the MTP layer to be detected as a draft layer. 4 passed (H100); fails if the speculator stops tagging its layers.
