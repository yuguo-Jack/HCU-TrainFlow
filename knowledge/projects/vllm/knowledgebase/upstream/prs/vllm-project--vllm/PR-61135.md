# [Perf][C++] Cache VLLM_CUSTOM_ALLREDUCE_ALGO env read in custom all-reduce

[Upstream PR](https://github.com/vllm-project/vllm/pull/61135) · state: closed · merged: False

## Original PR description

## Overview

Cache the `VLLM_CUSTOM_ALLREDUCE_ALGO` environment variable read in the custom all-reduce kernel, eliminating per-call `std::getenv` + `strcmp` chain overhead in the all-reduce hot path.

## Claims

- Eliminates per-call `std::getenv("VLLM_CUSTOM_ALLREDUCE_ALGO")` in custom all-reduce
- Eliminates per-call `strcmp` chain for algo parsing
- Environment variable is read and parsed once per process via static local variables

## Validation

- Code review: the static local initialization is thread-safe in C++11+ (guaranteed by the standard). The all-reduce kernel is called from a single CUDA stream per process, so there is no race concern.
- The behavior is identical: `getenv` returns the same value throughout the process lifetime, and the parsed `force_1stage`/`force_2stage` flags are deterministic from the env value.

## Details

The custom all-reduce kernel in `csrc/custom_all_reduce.cuh` had a comment saying "Check environment variable once" but actually called `std::getenv` and ran the full `strcmp` chain on every `all_reduce` invocation. This is on the TP all-reduce hot path (2N calls per forward pass for an N-layer model).

Use C++ static local variables to cache the `getenv` result and parsed flags. Static locals are initialized exactly once (thread-safe per C++11 standard), so subsequent calls skip the `getenv` + `strcmp` chain entirely.
