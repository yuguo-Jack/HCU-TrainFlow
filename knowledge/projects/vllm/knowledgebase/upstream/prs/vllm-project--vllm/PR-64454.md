# [Benchmark] Separate native and custom activation paths

[Upstream PR](https://github.com/vllm-project/vllm/pull/64454) · state: open · merged: False

## Original PR description



## Overview

Add an eager `forward_native` baseline to the activation kernel benchmark and call the CUDA implementation explicitly for the Custom OP series. This makes it possible to separate PyTorch eager, the vLLM custom operator, and `torch.compile` performance. This addresses the activation benchmark request in #19817.

## Claims

- `benchmark_activation.py` now reports `PyTorch (eager)`, `Custom OP`, and `Compiled` providers.
- The Custom OP series directly measures `forward_cuda` instead of depending on the active CustomOp dispatch configuration.
- The benchmark documentation describes the three providers and the timing scope.

## Validation

- On an NVIDIA H200 NVL with PyTorch `2.14.0+cu130`, the old path recorded 0 `_C::silu_and_mul` calls and compiled native/Triton events; the changed path recorded 289 `_C::silu_and_mul` calls.
- The changed benchmark completed 486 real CUDA invocations across 9 activations, 3 dtypes, 2 representative shapes, 3 providers, and 3 repeats. All results were finite and positive.
- Native and CUDA outputs matched for all 27 activation/dtype cases within dtype-appropriate tolerances.
- The CLI completed successfully:
  `python benchmarks/kernels/benchmark_activation.py --func-name silu_and_mul --dtype bfloat16`
  and printed all 45 shape rows with all three provider columns.
- `pytest tests/kernels/core/test_activation.py::test_act_and_mul tests/kernels/core/test_activation.py::test_activation -q` — 198 passed.
- `SKIP=actionlint pre-commit run --files benchmarks/kernels/benchmark_activation.py docs/benchmarking/README.md` — passed. Actionlint was not run because its local Go module environment could not be initialized; this change does not modify workflow files.

## Details

The previous benchmark labeled `layer(x)` as `Custom OP`. With the benchmark's default `custom_ops=['none']`, that call could dispatch to the compiled native implementation, so the reported Custom OP line did not reliably represent the CUDA custom operator. The provider mapping now calls `forward_native`, `forward_cuda`, and `torch.compile(forward_native)` explicitly. The existing shape grid, seed, and CUDA graph timing are unchanged. This is limited to benchmark tooling and documentation; no serving or model behavior changes, so model evaluation is not applicable.

I searched the issue comments and the open/all PR lists for this benchmark change. The earlier #23908 PR added the original two-series benchmark; no PR currently implements this native baseline. #44962 is closed and concerns a different layernorm test.
