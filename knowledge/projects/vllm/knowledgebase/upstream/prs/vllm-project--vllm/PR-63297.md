# [ROCm][Kimi-K3] Keep KDA prefill checkpoints with the gluon backend

[Upstream PR](https://github.com/vllm-project/vllm/pull/63297) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Since #59552, the gluon KDA prefill backend (AITER `chunk_kda`) is the default on CDNA4. It switches Kimi-K3's KDA prefill checkpoints off, because AITER `chunk_kda` cannot export the mid-prefill state. This PR keeps the checkpoints on with gluon: only prefill steps that carry checkpoint metadata go to the fused HIP kernel, and every other step stays on gluon.

## Claims

- With `kda_prefill_backend="gluon"` and the fused kernel built, `get_kv_cache_spec` reserves the prefill checkpoint block (alignment `KDA_CHECKPOINT_ALIGNMENT`), as the `fused` backend does. Previously it reported 0 blocks.
- A step whose `checkpoint` metadata is set runs `chunk_kda_prefill(backend="fused")`. Steps without checkpoint metadata keep the configured backend.
- If the fused kernel is missing (`is_fused_kda_chunk_supported()` is False), gluon still opts out of checkpoints, so behavior is unchanged.

```python
"""Prefix-cache check for Kimi-K3 KDA prefill checkpoints.

Per prompt length: a cold request A (facts + question about fact i), then B
(same facts + question about fact j) which should hit the prefix cache, then
B again after a prefix-cache reset (cold). B's answer must be right both ways.
"""
import json, random, sys, time, urllib.request

URL = "http://localhost:8000"
TOK = sys.argv[1] if len(sys.argv) > 1 else "/model"
from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained(TOK, trust_remote_code=True)

def post(path, body=None):
    req = urllib.request.Request(URL + path, data=json.dumps(body or {}).encode(),
                                 headers={"Content-Type": "application/json"}, method="POST")
    t = time.time()
    with urllib.request.urlopen(req, timeout=3600) as r:
        raw = r.read()
    return (json.loads(raw) if raw.strip().startswith(b"{") else raw.decode()), time.time() - t

def metrics():
    with urllib.request.urlopen(URL + "/metrics") as r:
        txt = r.read().decode()
    out = {}
    for ln in txt.splitlines():
        for k in ("vllm:prefix_cache_hits_total", "vllm:prefix_cache_queries_total"):
            if ln.startswith(k):
                out[k] = out.get(k, 0) + float(ln.split()[-1])
    return out

def build(n_tokens, seed):
    rnd = random.Random(seed)
    lines, facts = [], []
    while True:
        name = "".join(rnd.choice("BCDFGHJKLMNPRSTVZ") + rnd.choice("aeiou") for _ in range(3)).capitalize()
        code = rnd.randint(1000, 9999)
        facts.append((name, code))
        lines.append(f"Record {len(facts)}: the access code for the city of {name} is {code}.")
        if len(lines) % 50 == 0 and len(tok.encode("\n".join(lines))) >= n_tokens:
            break
    return "\n".join(lines), facts

def ask(doc, name):
    p = (f"Below is a list of records.\n\n{doc}\n\nQuestion: What is the access code for "
         f"the city of {name}? Answer with the four-digit number only.\nAnswer: The access code for the city of {name} is")
    r, dt = post("/v1/completions", {"model": "moonshotai/Kimi-K3", "prompt": p, "max_tokens": 8,
                                      "temperature": 0, "seed": 0})
    c = r["choices"][0]["text"]
    cached = (r.get("usage", {}).get("prompt_tokens_details") or {}).get("cached_tokens")
    return c, r["usage"]["prompt_tokens"], cached, dt

res = []
ok_all = True
for n, seed in ((3000, 1), (9000, 2), (20000, 3), (45000, 4)):
    doc, facts = build(n, seed)
    rnd = random.Random(seed + 100)
    (na, ca), (nb, cb) = facts[rnd.randrange(len(facts))], facts[rnd.randrange(len(facts) // 4)]
    post("/reset_prefix_cache")
    a = ask(doc, na)
    m0 = metrics()
    b_warm = ask(doc, nb)
    m1 = metrics()
    post("/reset_prefix_cache")
    b_cold = ask(doc, nb)
    row = dict(target_tokens=n, prompt_tokens=a[1],
               A=dict(expect=ca, text=a[0], ok=str(ca) in a[0], cached=a[2], s=round(a[3], 2)),
               B_warm=dict(expect=cb, text=b_warm[0], ok=str(cb) in b_warm[0], cached=b_warm[2], s=round(b_warm[3], 2),
                           hit_tokens=m1.get("vllm:prefix_cache_hits_total", 0) - m0.get("vllm:prefix_cache_hits_total", 0)),
               B_cold=dict(text=b_cold[0], ok=str(cb) in b_cold[0], cached=b_cold[2], s=round(b_cold[3], 2)),
               warm_eq_cold=b_warm[0] == b_cold[0])
    ok_all &= row["A"]["ok"] and row["B_warm"]["ok"] and row["B_cold"]["ok"]
    res.append(row)
    print(json.dumps(row), flush=True)
print("PREFIX_CHECK", "PASS" if ok_all else "FAIL")
```

## Details

- **Root cause:** `can_checkpoint` required `kda_prefill_backend == "fused"`. When `auto` resolved to gluon, the spec reserved no checkpoint block. The scheduler then fell back to splitting the final prefill chunk at the block boundary (`scheduler.py`), which costs an extra step per prompt and drops the interior checkpoints.
- **Why route to fused, not export from gluon:** AITER `chunk_kda` (amd-aiter 0.1.25 / 0.1.26 and AITER main) has no checkpoint output. The proper fix is to export the state from the chunk walk inside the kernel; that needs an AITER change first. This PR is the vLLM-only bridge. When AITER grows that output, the routing can be replaced by a signature check.
- **Trade-off:** checkpoint metadata is per step, so a batched prefill step in which any request crosses a snapshot position runs entirely on the fused kernel. Steps without a checkpoint keep gluon's speed. Decode throughput was not part of this measurement.
- **Related PRs (not duplicates):**
  - #56036 adds a separate `flashkda` prefill backend and does not touch checkpoint gating.
  - #61951 adds Triton prefill checkpoints for GLM-5.3-Flash KDA through a host-side split.
  - #61466 moves the prefill checkpoint alignment into `MambaBase.get_prefill_checkpoint_alignment()` and edits the same `get_kv_cache_spec`. Whichever lands second needs a small rebase; the gating condition here carries over unchanged.
