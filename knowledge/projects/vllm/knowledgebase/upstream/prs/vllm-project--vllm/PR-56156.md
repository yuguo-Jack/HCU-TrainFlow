# [Core] Pack heterogeneous KV-cache pages for hybrid models

[Upstream PR](https://github.com/vllm-project/vllm/pull/56156) · state: open · merged: False

## Original PR description

## Overview

Reuse packed `UniformTypeKVCacheSpecs` allocation for heterogeneous attention
and state-cache pages. Second prerequisite: #56155 -> this PR -> #56116.

## Claims

- Keep exact per-layer FP8, NVFP4, and recurrent-state page sizes in compatible
  packed layouts instead of padding every layer to one common page.
- Add a default-disabled `has_layerwise_kv_cache()` capability and prefer a
  compatible block-outer layout; retain existing aligned-layout fallbacks.
- Preserve backend-supported kernel pages and initialize Mamba SSU for wrapped
  state-cache groups. No quantization config activates the capability here.

## Validation

- Scoped pre-commit checks pass, including mypy (Python 3.11), Ruff, formatting,
  test tethering and applicable Buildkite checks:
  `pre-commit run --hook-stage manual --files <incremental changed files>`.
- CPU source isolation passes eight prerequisite test-body cases, 36 resolver
  combinations, four constructor-hook cases with unrelated runtime isolated,
  and 11 platform/layout cases. This is not full-vLLM pytest.
- Earlier-stack Nano/Qwen TP4 serving smokes exercised mixed formats and
  CUDA graphs. Those are historical; fresh GPU/E2E validation and PR1's new
  GPU-backed constructor pytest remain pending.

## Details

Logical encodings remain attention-runtime metadata per #56155; this PR changes
physical allocation only. Existing non-layerwise configurations keep the
existing path. Manager/kernel block sizes remain backend-supported; this does
not add automatic larger-manager-block optimization or new attention kernels.

Restacked onto #56155's test-only alignment; this allocator patch is unchanged.
