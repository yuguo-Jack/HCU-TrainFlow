# [Bugfix][Tool Parser] Fix DotsToolParser self.tools fallback and add FunctionTool compatibility (#60865)

[Upstream PR](https://github.com/vllm-project/vllm/pull/60868) · state: open · merged: False

## Original PR description

### Description
Fixes #60865

This PR addresses two bugs in `DotsToolParser`:
1. **Fallback to `self.tools`**: When `request.tools` is `None`, `DotsToolParser` previously ignored tools passed at initialization (`self.tools`), causing tool calls to be silently discarded. It now resolves `getattr(request, "tools", None) or self.tools or []`.
2. **Support `FunctionTool` (Responses API)**: `DotsToolParser` previously assumed all tools had `.function.name`. It now utilizes `_extract_tool_info` from `vllm.tool_parsers.utils` to support both `ChatCompletionToolsParam` and `FunctionTool`, preventing `AttributeError`.

### Duplicate-Work Checks
- Checked open PRs for `dots`: Only PR #54678 exists, which solely touches regex backtracking.
- No existing PR or issue covers `self.tools` fallback or `FunctionTool` support in `DotsToolParser`.

### Testing

- `test_non_stream_extract_with_parser_tools_and_none_request_tools`
- `test_non_stream_with_function_tool`
- `test_streaming_with_function_tool_and_parser_tools`
