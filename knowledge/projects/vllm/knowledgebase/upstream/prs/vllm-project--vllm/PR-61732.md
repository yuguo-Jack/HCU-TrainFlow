# [CI] Use an ungated model as the attention test config default

[Upstream PR](https://github.com/vllm-project/vllm/pull/61732) · state: closed · merged: True

## Original PR description

## Overview

`create_vllm_config()` in `tests/v1/attention/utils.py` defaults to the gated `meta-llama/Meta-Llama-3-8B`, so every test that relies on the default fails on agents and machines without access to that repo. As suggested in #61416, this defaults it to `Qwen/Qwen3-0.6B`, the default model of `vllm serve`, and switches the explicit Llama-3-8B uses in `tests/v1/attention/` to it as well.

## Claims

- Tests that build their config through the default, and the attention tests that named Llama-3-8B, no longer need access to the meta-llama repo.
- Results do not change for the CUDA tests that use the default or the replaced model.

## Validation

On SM80 with FlashInfer 0.7.1 and an offline HF cache, `main` against `main` + this PR, for every CUDA test file that uses the default or the replaced model:

| Test file | `main` and this PR |
| --- | --- |
| `tests/v1/attention/test_attention_backends.py` | 88 passed, 60 failed, 10 skipped |
| `tests/v1/attention/test_deepseek_v4_swa_visible.py` | 30 passed, 1 failed |
| `tests/v1/attention/test_flashinfer_dcp_spec_reorder.py` | 1 passed |
| `tests/v1/attention/test_mm_prefix.py` | 13 passed, 22 skipped |
| `tests/v1/attention/test_indexer_deepseek_v4_slot_mapping.py` | 32 passed, 1 skipped |
| `tests/v1/attention/test_linear_attention_metadata_builder.py` | 4 passed |
| `tests/kernels/attention/test_minimax_m3.py` | 111 passed, 60 skipped |

The failing tests are the same on both sides and fail for reasons unrelated to the model: FP8 KV caches the Triton backend rejects below SM89, and FlashMLA not being built for SM80. The ROCm test files that use the default were not run.

## Details

Llama-3-8B stays where a test is about that model itself (`tests/test_config.py`, `tests/models/registry.py`) and in the spec decode test that uses the Instruct variant.
