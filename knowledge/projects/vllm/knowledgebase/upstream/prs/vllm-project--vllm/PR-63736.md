# [Bugfix][Spec Decode] Fence deferred block frees after draft KV writes

[Upstream PR](https://github.com/vllm-project/vllm/pull/63736) · state: open · merged: False

## Original PR description

## Overview

Refs #63519. This change proposes delaying deferred block reclamation by one processed step when speculative decoding is enabled, so the completion fence covers draft KV writes issued after the output-copy event.

**Open for review. Runtime correctness and performance validation evidence remain outstanding.**

## Claims

- Adds an extra-step fence for speculative decoding while retaining the existing non-speculative fence.
- Adds a device-synchronized drain for deferred blocks on idle and stalled engine paths.
- Adds scheduler and drain contract tests. Their presence is not a claim that the tests have passed.

## Details

The problematic sequence is: a request's output-copy event completes; its draft forward can still be writing KV; the scheduler releases its blocks; an unordered receive path may write a new request's KV into the reused blocks. The proposal holds those blocks until a later step's completion, with an explicit synchronized drain when progress would otherwise stop.

The design still needs scrutiny: `model_executed=False` does not establish that the batch queue is empty, and the extra fence currently applies to every speculative method rather than only V2 KV-writing speculators. Additional block retention and synchronous drains may affect memory pressure and latency.

Issue-number and area-keyword searches found no confirmed equivalent open implementation during the submission review; this is not an exhaustive equivalence proof. This PR presents the proposal for review while completing the checks above.
