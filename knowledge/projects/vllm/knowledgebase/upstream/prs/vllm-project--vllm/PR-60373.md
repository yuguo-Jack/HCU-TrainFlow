#   [Bugfix][DCP] Support strided LSE in direct A2A reduction

[Upstream PR](https://github.com/vllm-project/vllm/pull/60373) · state: open · merged: False

## Original PR description

## Overview

Fix the `partial LSE must have packed heads` error when using `VLLM_USE_DIRECT_DCP_A2A=1` with transposed FlashAttention MLA LSE tensors, as encountered with **DeepSeek-V2-Lite**. The direct P2P kernel now reads both tensor strides, without a contiguous copy.

Unlike the NCCL fallback proposed in [#54472](https://github.com/vllm-project/vllm/pull/54472), this enables the direct path for these LSE layouts.

## Claims

- Enable direct P2P for strided LSE without changing reduction arithmetic or backend defaults.
- Improve DeepSeek-V2-Lite throughput at concurrency 32/128 on the measured long-context workload; c512 is inconclusive.

## Validation

### Serving performance

DeepSeek-V2-Lite, **8 x H100 80 GB**, TP=DCP=8, expert parallelism enabled, Q/KV gather through NCCL. Both arms use the same image and Mooncake agentic workload; only `VLLM_USE_DIRECT_DCP_A2A` changes between 0 and 1.

Metric: **generated output tokens/second/GPU**; higher is better. Three nodes, two order-balanced repetitions per node: six paired measurements per concurrency.

| 128 | 617.97 | 638.68 | +3.35% | +2.29% to +4.41% |

### Correctness

- **Four GPU tests passed, zero skips:** packed/padded/transposed LSE, singleton tokens, empty shards, and graph replay; packed/strided kernel outputs are bitwise-identical for identical inputs.
- Latest DeepSeek rerun passed eager TP=2 and graph TP=2/8 numerical/path checks. Traces confirm direct kernels. Packed-copy/strided-P2P model controls produced identical saved outputs.
- Additional models are being tested; current model-level evidence covers DeepSeek-V2-Lite only.

## Details

FlashAttention MLA's `[heads, tokens]` LSE becomes a strided `[tokens, heads]` view after transpose. Reading both strides fixes addressing without adding copies, allocations, or synchronization. The receive buffer and combine kernel are unchanged.

Output-layout/capacity restrictions and oversized-prefill fallback remain. This does **not** fix the separate GLM attention-output layout issue [#54305](https://github.com/vllm-project/vllm/issues/54305). If [#54472](https://github.com/vllm-project/vllm/pull/54472) lands first, relax only its LSE guard for this newly supported layout.

Related test-fixture/CI work: [#55492](https://github.com/vllm-project/vllm/pull/55492); consolidate overlapping support changes if it lands first.
