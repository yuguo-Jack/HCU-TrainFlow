# [Bugfix][Multimodal] Return 400 for corrupt AVIF and BLP images

[Upstream PR](https://github.com/vllm-project/vllm/pull/63433) · state: closed · merged: True

## Original PR description

## Overview

Inspired by #62703. A chat request with a corrupt AVIF image gets HTTP 500, and one with bad BLP data gets HTTP 501, instead of 400. `ImageMediaIO.load_bytes` turns only `OSError`, `UnidentifiedImageError` and `SyntaxError` into the `ValueError("Failed to load image: ...")` that becomes a 400. Pillow's AVIF decoder raises `RuntimeError`, and the BLP plugin raises `BLPFormatError`, a `NotImplementedError`, so both get past that `except`. This PR adds `RuntimeError` to it, which covers both.

#62704 fixed the case from #62703, a PNG with a broken chunk (`SyntaxError`), by adding one class to the same tuple. This PR follows the same approach for the decoder errors that it does not cover. An image over Pillow's pixel limit (`DecompressionBombError`) has the same cause, but #60308 fixes it, so this PR does not touch it.

## Claims

- A corrupt AVIF (`RuntimeError: Failed to decode image: Missing or empty image item`) now gives HTTP 400 `Failed to load image: ...`, not 500.
- A BLP file with an unknown compression (`BLPFormatError: Unknown BLP compression 0`) now gives HTTP 400, not 501.
- Any `NotImplementedError` or `RecursionError` raised while decoding (both subclass `RuntimeError`) now also gives 400 instead of 501/500. These come from the input image, so 400 is intended.
- Valid PNG, JPEG, WEBP and AVIF images load as before. vLLM's own `ValueError`s in this block (pixel limit, decoded-size budget) are not affected.
- A new parametrized test in `tests/multimodal/media/test_image.py` covers both cases and checks the wrapped cause.

## Validation

Setup: CPU only. vLLM at upstream `main` `debcf2284`, Pillow 13.0.0, Python 3.12.

Unit tests:

```bash
pytest tests/multimodal/media/test_image.py
```

With the patch, 22 passed. With the old `image.py`, the two new cases fail with `RuntimeError: Failed to decode image: Missing or empty image item` and `BLPFormatError: Unknown BLP compression 0`, and the 20 other tests pass.

HTTP status: I passed each input to `ImageMediaIO.load_bytes` and gave the escaping exception to the real `create_error_response`:

| Input | Before | After |
|---|---|---|
| AVIF with no primary item | `RuntimeError` -> 500 | 400 `Failed to load image: Failed to decode image: Missing or empty image item` |
| BLP2 with compression 0 | `BLPFormatError` -> 501 | 400 `Failed to load image: Unknown BLP compression 0` |
| PNG with a broken chunk (#62703) | 400 | 400 |
| PNG with a 20000x10000 header | `DecompressionBombError` -> 500 | 500, fixed by #60308 |
| Valid PNG, JPEG, WEBP, AVIF | loads | loads |
| Garbage bytes, truncated PNG | 400 | 400 |

`pre-commit run --files vllm/multimodal/media/image.py tests/multimodal/media/test_image.py`: all hooks passed or were skipped.

No model evaluation was run. The change only affects images that fail to decode.

## Details

Pillow has no single base class for bad image data, so `load_bytes` lists the classes. The one added here covers what a fuzz run over the allowed formats found escaping that list, apart from `DecompressionBombError`:

- `RuntimeError` comes from the C AVIF decoder (`_avif.AvifDecoder`) in `Image.open()`.
- It also covers `NotImplementedError`, which Pillow plugins raise for format features they do not support (`BLPFormatError` is one), and `RecursionError` from deeply nested input.
- Every call in this block only decodes client-supplied bytes, so all of these are client errors and map to 400. A 501 in vLLM means the model does not support the API, which does not fit a bad image.

`MemoryError` is still not caught and still gives 500.

This PR and #60308 both extend the same tuple, so whichever merges second needs a one-line rebase.

🟡 (optional) After this merges, every NotImplementedError and RecursionError in the decode block becomes a 400 "Failed to load image". The comment and PR say a NotImplementedError still maps to 501, but it does not. In Python, NotImplementedError and RecursionError both subclass RuntimeError. So the bare `RuntimeError` entry at image.py:105 already catches them, and `BLPFormatError` at image.py:106 is redundant. Fix: narrow the catch so only the AVIF decoder's failure becomes a 400. For example, handle `NotImplementedError` (other than `BLPFormatError`) and `RecursionError` before `RuntimeError` and re-raise them. Or catch RuntimeError only around `open_image`.

<details>
<summary>Why this was flagged</summary>

The except tuple at vllm/multimodal/media/image.py:101-107 now lists `RuntimeError`. Python's built-in hierarchy makes `NotImplementedError` and `RecursionError` subclasses of `RuntimeError`, so the separate `BLPFormatError` entry does nothing. Any NotImplementedError raised inside the try block (lines 84-97) is wrapped as `ValueError("Failed to load image: ...")` and returned as HTTP 400. That includes a Pillow plugin's NotImplementedError, an override of `_convert_image_mode` (the PR names this case) and a RecursionError from deep parsing. On the base branch these escape the except and map to 501 or 500. That contradicts the new comment at lines 98-100 and the PR's claim that a NotImplementedError from `_convert_image_mode` "still maps to 501". Server-side faults would then show up as client errors. No guard reorders or re-raises these subclasses before the tuple.

**Verification:** In Python's built-in hierarchy, NotImplementedError and RecursionError are both subclasses of RuntimeError. So the new bare `RuntimeError` entry at image.py:105 catches every NotImplementedError and RecursionError and re-raises it as `ValueError(f"Failed to load image: {e}")` (line 108), which becomes a 400. This also makes the `BLPFormatError` entry at line 106 redundant.

</details>

🟡 nit (optional): The new avif-no-primary-item case fails, rather than skips, on any Pillow build without AVIF support. Without the `_avif` extension, Pillow's AVIF plugin does not identify the payload. `Image.open` then raises `UnidentifiedImageError`, which is not a `RuntimeError`, so the `__cause__` assertion fails. Fix: skip that case unless `PIL.features.check("avif")` is true, e.g. via `pytest.param(..., marks=pytest.mark.skipif(not features.check("avif"), reason=...))`, and keep the BLP case running everywhere.

<details>
<summary>Why this was flagged</summary>

This needs a Pillow build without libavif, such as a source build where libavif headers are missing or some distro packages. The pinned wheels for x86_64 (pillow==12.3.0 in requirements/test/cpu.txt:719) include AVIF, so the main CI is not affected. On such a build, open_image (vllm/multimodal/image.py:61) passes formats=ALLOWED_IMAGE_FORMATS, which lists "AVIF". Pillow's AvifImagePlugin `_accept` then returns an 'AVIF support not installed' string instead of opening the file, and `Image.open` raises `UnidentifiedImageError`. load_bytes (vllm/multimodal/media/image.py:101-107) wraps that as ValueError, so `pytest.raises` passes. But `isinstance(exc_info.value.__cause__, RuntimeError)` at test_image.py:347 is false, and the test fails. Without this new test, nothing in tests/ needs AVIF (no `features.check` or `_avif` reference exists), so the suite does not fail on these builds on the base branch.

**Verification:** Triggering condition: the test suite runs against a Pillow build without libavif. `open_image` calls `Image.open(fp, formats=ALLOWED_IMAGE_FORMATS)` (vllm/multimodal/image.py:61). `assert isinstance(exc_info.value.__cause__, cause)` with `cause=RuntimeError` fails, because `UnidentifiedImageError` subclasses OSError, not RuntimeError. The test applies no `features.check("avif")` skip.

</details>
