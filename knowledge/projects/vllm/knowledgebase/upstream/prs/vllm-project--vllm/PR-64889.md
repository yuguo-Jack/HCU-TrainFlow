# [Bugfix][Compile] Support distinct attention geometries in RopeKVCacheFusionPass (#64679)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64889) · state: open · merged: False

## Original PR description



## Overview

Register RopeKVCacheFusionPass patterns per distinct attention geometry under _USE_LAYERNAME and convert qkv.split ValueError mismatches into RuntimeError during pattern re-tracing so speculative-decoding drafter graphs with different attention dimensions do not crash torch.compile.

Fixes #64679

## Claims

- Fixes torch._inductor.exc.InductorError (ValueError on qkv.split) when fuse_rope_kvcache runs on a draft_model or EAGLE speculative-decoding drafter whose per-rank QKV width differs from the target model's.
- Registers fusion patterns for every distinct (num_heads, num_kv_heads, head_size, head_size_v) attention geometry present in static_forward_context.

## Validation

```bash
pytest tests/compile/passes/test_rope_kvcache_fusion.py -k test_rope_kvcache_fusion_multi_geometry_and_mismatched_qkv_width -v
```

## Details

When _USE_LAYERNAME is enabled, RopeKVCacheFusionPass.__init__ previously registered patterns from only the first attention layer and broke out of the loop. When a drafter or hybrid layer had a different (num_heads, num_kv_heads, head_size, head_size_v) tuple, the structural matcher still matched the drafter's subgraph and Inductor's check_fn re-traced pattern(qkv, ...) with the drafter's qkv tensor. Because qkv.split([q_size, k_size, v_size], dim=-1) raises ValueError on a width mismatch whereas Inductor's check_fn only catches RuntimeError, compilation failed instead of rejecting the candidate match. Deduplicating by attention geometry and translating ValueError to RuntimeError in fwd_and_view_to_reshape allows non-matching patterns to return False cleanly while still fusing all registered geometries.
