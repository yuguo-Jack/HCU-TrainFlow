# [Bugfix][Gemma4] Preserve activation dtype for quantized vision projections

[Upstream PR](https://github.com/vllm-project/vllm/pull/63911) · state: open · merged: False

## Original PR description



## Overview

Fix Gemma 4 online-FP8 image failures caused by casting activations to quantized projection weight storage dtypes. Fixes #63732 while keeping the vision projections quantized.

## Claims

- Normalize pixels in the unquantized position table's working dtype, reusing HF construction and position embeddings.
- Match the eager model activation dtype in the encoder-graph connector, including int32-packed Marlin weights.
- Add dense parity and real-weight image regressions, plus rendered model documentation.

## Details

HF derives the pixel activation dtype from `input_proj.weight.dtype`. Online FP8 makes that a storage dtype, so the native CUDA input quantizer receives already-FP8 activations and fails. The model-local subclass selects the unquantized position table dtype and preserves checkpoint keys/shapes. The connector matches the eager model activation dtype. No quantization exclusion or shared-kernel change is introduced.

AI assistance was used for investigation, implementation, testing and review. Issue-comment and open-PR checks on 2026-10-27 found no overlapping PR referencing #63732 or the Gemma/FP8 patch embedder fix; existing comments describe reproduction and a quantization-exclusion workaround.
