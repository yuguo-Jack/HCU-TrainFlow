# [Bugfix][Frontend] Preserve DP rank in Responses requests

[Upstream PR](https://github.com/vllm-project/vllm/pull/62450) · state: closed · merged: True

## Original PR description



## Overview

Forward `X-data-parallel-rank` from the Responses API to the engine, matching Chat Completions. This prevents the frontend from silently discarding a gateway's selected DP replica.

## Claims

- Preserve the selected rank for streaming and non-streaming Responses requests, including subsequent built-in tool turns.
- Keep existing default routing when the header is absent or cannot be parsed; rank zero is preserved.

## Validation

On upstream base `fb61ac07bd1d5b8b9722c80085b99ef770efb265`, Python 3.12.13, CPU platform with accelerator visibility disabled:

```bash
VLLM_TARGET_DEVICE=cpu VLLM_PLUGINS='' ASCEND_RT_VISIBLE_DEVICES='' CUDA_VISIBLE_DEVICES='' \
  .venv/bin/python -m pytest tests/entrypoints/openai/responses/test_serving_responses.py \
  -k 'responses_data_parallel_rank or harmony_tool_followup_preserves_render_params' -v -ra --tb=short
```

Result: **11 passed, 66 deselected**, no skips. Tests exercise header parsing through the Responses serving entrypoint to `engine.generate`, and reuse the existing tool-follow-up test. They are included in the existing Buildkite Responses test area.

Serving reproduction on an Ascend-native downstream deployment with a DeepSeek V4.1 Flash model, Mooncake PD, prefill TP4/DP4 and decode TP8/DP2:

| Request | Before forwarding | After forwarding |
| --- | --- | --- |
| Same reconstructed streaming Responses request, reasoning effort `max`, approximately 7.1k prompt tokens | No generated output within 45 seconds; decode waiting for KV fetch | Completed in approximately 3 seconds, including text and `response.completed` |

The serving comparison used a runtime implementation of the same rank-forwarding change on prefill API processes, without restarting the model. It validates the routing correction on that deployment; it is not a deployment of this exact upstream commit. The original client tool schemas were unavailable, so this was a reconstructed reproducer, not a byte-identical replay. No accuracy benchmark or general performance improvement is claimed.

## Details

The gateway can select prefill replica R and direct decode to fetch KV from R. Responses previously omitted `data_parallel_rank` from its engine call, allowing internal load balancing to choose another replica. Decode can then wait for KV at the wrong producer. The fix uses the existing header parser and passes the rank explicitly through `_generate_with_builtin_tools` to every `engine.generate` call. No connector-specific behavior or hardware branch is added.

Duplicate-work checks found no existing PR for this fix. Related #40285 changes internal DP coordinator notifications, and #49246 adds PCP/DP support; neither changes Responses rank forwarding.

AI assistance was used to investigate, implement, and test this change.
