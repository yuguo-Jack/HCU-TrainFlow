# [Core] Don't let a second SIGTERM interrupt EngineCore and worker teardown

[Upstream PR](https://github.com/vllm-project/vllm/pull/64623) · state: open · merged: False

## Original PR description



## Overview

Two signal-handling fixes in the shutdown path. AI assistance (Claude Code) was used to prepare this PR; I reviewed every changed line.

## Claims

- EngineCore ignores SIGTERM while tearing down. It restored `SIG_DFL` first, so after a process-group SIGTERM (Ctrl-C, `docker stop`) the process manager's follow-up SIGTERM killed it mid-way through its workers' teardown.
- A worker acts on the first SIGTERM even when the death-pipe monitor already requested shutdown (one blocked on a remote MQ read ignored SIGTERM entirely), and ignores later ones once teardown has started.

## Validation

`tests/v1/shutdown/test_sigterm.py` (CPU): the worker handler acts on the first SIGTERM after a shutdown request and ignores signals during teardown; EngineCore's `run_engine_core`, with an engine stub whose teardown receives a SIGTERM, finishes its teardown.

```
$ pytest tests/v1/shutdown/test_sigterm.py
3 passed                                    # this PR
$ pytest tests/v1/shutdown/test_sigterm.py -k engine_core
1 failed                                    # main
E       AssertionError: teardown interrupted, exitcode=-15
```

GB300, `vllm serve` TP2 with `VLLM_WORKER_SHUTDOWN_TIMEOUT_SECONDS=30`, SIGTERM to the process group: on `main` EngineCore is killed by the follow-up SIGTERM while waiting for its workers; with this PR `Executor: all workers exited gracefully` follows 4 s later and shutdown completes.

## Details

#62166 scales the worker grace with the HiSparse host-pool size. A longer grace fixes neither problem here, and this PR adds no timeouts: it only stops signals from interrupting a teardown that is already running, within whatever window #63260 or #62166 provide.
