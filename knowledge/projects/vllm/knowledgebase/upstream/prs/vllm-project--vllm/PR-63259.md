# [CI] Trigger recipe previews and the recipes.vllm.ai sync on push

[Upstream PR](https://github.com/vllm-project/vllm/pull/63259) · state: closed · merged: True

## Original PR description

<!-- markdownlint-disable -->

## Overview

Tells vllm-project/recipes as soon as `recipes/` changes, instead of relying on its scheduled polling, which GitHub runs hours late. Recipe PR previews then update a few minutes after each push, and recipes.vllm.ai syncs right after merge. Receiving side: vllm-project/recipes#1169. Labels and the preview link: #63248.

The admin setup below is done, so this can merge.

## Claims

New `.github/workflows/recipes-preview.yml` with a single `dispatch` job:
- **Recipe PR events** (`pull_request_target` on `opened`, `synchronize`, `reopened` and `closed`, limited to `recipes/**`): sends `repository_dispatch: preview-pr` with the PR number. vllm-project/recipes waits two minutes (a newer push cancels the wait), then rebuilds the PR's preview branch, or deletes it when the PR is closed.
- **Push to `main` touching `recipes/**`**: sends `recipes-updated`, which runs `bump-sources` in vllm-project/recipes right away.
- The job's `recipes-preview` environment URL is the PR's preview, so the PR shows a "View deployment" button. The preview page's banner says which commit it renders.

Every recipe PR gets a preview, like Read the Docs previews of docs PRs. An author trust check would only limit Vercel usage, which the debounce and "rebuild only when `recipes/` changed" already bound.

## Security

- The workflow never checks out or runs PR code. The only thing that leaves it is the PR number, validated as `^[0-9]+$`. No PR-controlled string (title, branch name) is interpolated into shell. Same model as vllm-project.github.io's `vercel-preview.yml`.
- PR recipes are rendered on the preview as data: js-yaml's safe `load`, guides via react-markdown without raw HTML, and JSON-LD escaped.
- The token is a short-lived installation token from a GitHub App installed only on vllm-project/recipes with `contents: write`, minted by `actions/create-github-app-token` pinned to v3.2.0. Its key lives in the `recipes-preview` environment, restricted to `main`, so workflows on other branches can't read it. `pull_request_target` jobs run in `main`'s context.
- Rulesets in vllm-project/recipes (below) limit what a leaked key could do to pushing `preview/**` branches, which deploy only to preview URLs, and sending dispatches.
- Cross-repo `repository_dispatch` with a GitHub App token is an established pattern, e.g. `grafana/mimir` → `grafana/backend-enterprise` and `google/xrblocks` → `xrblocks.github.io`.

## Admin setup (done)

Done by a vllm-project admin (full checklist: vllm-project/recipes#1169, "Rollout"):
- **Dispatch App:** Contents read/write only, installed only on `vllm-project/recipes`. Its ID and key are in this repo's `recipes-preview` environment, restricted to `main`.
- **Publisher App:** a separate App with the same scope. Its key is in recipes' `recipes-publisher` environment, also restricted to `main`. `bump-sources` mints its token; GitHub rejects the built-in GitHub Actions App as a bypass actor.
- **Rulesets in vllm-project/recipes:** all branches except `preview/**`, and all tags, each restricting creations, updates and deletions. The dispatch App bypasses neither; the publisher App bypasses the branch rule only. Human Admin, Maintain and Write access is unchanged.
- **Vercel Preview environment:** no environment variables or privileged integrations.

`bump-sources` ran before and after the rulesets were enabled and minted the publisher token both times. Neither run had a source change to push, so the first publisher push to `main` happens when a recipe change merges after this PR.

Not a duplicate: no other open PR triggers recipes builds from this repo.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Keep cleanup events outside the recipe path filter**

If a PR first creates a recipe preview and is then force-pushed or reverted so its current three-dot diff no longer contains any `recipes/**` file, this path filter suppresses the `synchronize` event; it also suppresses `closed` after the PR is closed in that state. Consequently neither an update nor the promised `preview/vllm-pr-N` deletion is dispatched, leaving the old branch and preview stale until some external cleanup. Let cleanup run for previously previewed PRs rather than gating every PR activity on the final diff.
