# [Bugfix][Pooling] Release cached queries when Flash scoring is cancelled

[Upstream PR](https://github.com/vllm-project/vllm/pull/56617) · state: open · merged: False

## Original PR description

## Purpose

Flash late-interaction scoring must stop all query/document producers before releasing their cached query embeddings. During client disconnection, cancelling a producer without joining it can leave request submission or abort unfinished. A second cancellation can also interrupt cleanup, and an already submitted model batch can populate the cache after a cleanup RPC has run.

This PR joins the encoding tasks before aborting remaining requests, shields cleanup from repeated cancellation, and adds an opt-in `wait_for_inflight_batches` argument to the existing collective RPC API. Waiting preserves each pending batch's result for the scheduler, including futures that can only be consumed once.

The branch is rebased onto main `4274ae956c7`. #58975 has since added basic cache release and private document request IDs, so this PR now reuses its `release_late_interaction_query_cache` worker API and removes the duplicate worker/runner changes. The remaining changes address producer completion, repeated cancellation, and ordering against in-flight batches. The collector preserves the newer retryable/non-retryable request error handling.

- **60 passed, 2 skipped, 2 deselected** on macOS/CPU. The two GPU kernel tests were skipped; two unchanged upstream Triton configuration tests were excluded because this environment has no Triton and uses a placeholder instead of `triton.Config`.
- Regressions cover cancellation before query output or collector delivery, partial document completion, child errors, repeated cancellation, request isolation, and RPC batch ordering. Added two cases to preserve upstream request-error handling while a sibling is still pending, and updated the DP fixture for the current utility broadcast API.
- An isolated comparison restored main's `_prepare_generators` + `_collect_batch` collection path while retaining the fixed cleanup path: both normal controls passed, but three cancellation cases failed with unfinished producers or requests. This was a collector-only comparison, not a full-main GPU failure claim.
- All changed files passed pre-commit, including the current mypy check.
- **Fresh A10 HTTP smoke passed for main and the rebased fix, with both MRV1 and MRV2**, using `answerdotai/answerai-colbert-small-v1`. Each run exercised three client disconnections plus cancellation alongside a normal request. Query caches returned to zero, allocated memory stayed stable after cancellation, and normal/concurrent scores matched exactly across all four runs.

The GPU test used each complete target Python package with the same existing image's native artifacts, on one A10 with TP=DP=PP=1. It is a functional cancellation/scoring smoke test, not a full model-quality evaluation or distributed/Ray concurrency validation. The remaining concurrency boundaries are covered by the CPU regressions above. Main already cleans up ordinary stage-boundary cancellations after #58975; the earlier baseline leak result is not a claim about current main.
