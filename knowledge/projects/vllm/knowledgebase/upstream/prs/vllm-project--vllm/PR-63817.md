# [NIXL] Bump NIXL version to 1.5.1

[Upstream PR](https://github.com/vllm-project/vllm/pull/63817) · state: closed · merged: True

## Original PR description



## Overview

Bump the NIXL pin from 1.5.0 to [1.5.1](https://github.com/ai-dynamo/nixl/releases/tag/v1.5.1) for both CUDA 13 (`requirements/kv_connectors.txt`) and CUDA 12 (`requirements/kv_connectors_cu12.txt`) images.

## Claims

- CUDA 12 and CUDA 13 images both install NIXL 1.5.1. The two pins move together; last time they drifted (#56907, then #60428 a week later).
- Picks up the LIBFABRIC fix for context-independent CUDA allocations such as mapped VMM memory (ai-dynamo/nixl#2425).
- The UCX path and NIXL EP do not change. `release/1.5.0...v1.5.1` touches only version strings, attributions, `src/plugins/libfabric/libfabric_backend.cpp` and `contrib/Dockerfile.manylinux` (libfabric 1.21.0 → 2.7.0). UCX stays at the same pinned commit (`65e342a8`).

## Validation

- Dependency resolution, x86_64 and aarch64, both files: `nixl`, `nixl-cu12` and `nixl-cu13` all resolve to 1.5.1.
  ```bash
  uv pip compile --python-version 3.12 --python-platform x86_64-manylinux_2_28 --torch-backend cu129 requirements/kv_connectors.txt
  # repeated for aarch64-manylinux_2_28 and requirements/kv_connectors_cu12.txt
  ```
- `pre-commit run --files requirements/kv_connectors.txt requirements/kv_connectors_cu12.txt`: passed.
- ELF check of `libplugin_LIBFABRIC.so` in `nixl_cu13` cp312 x86_64: 1.5.0 needs libfabric `FABRIC_1.0`, `1.1`, `1.7`; 1.5.1 needs `FABRIC_1.0`, `1.1`, `1.10`. Both list `libfabric.so.1` as a dependency and do not bundle it.
- **Not yet run:** GPU P/D serving with `NixlConnector` on CUDA 12 and CUDA 13, and LIBFABRIC over EFA. This PR stays a draft until those pass. `requirements/kv_connectors.txt` is in the run-all patterns (`.buildkite/ci_config.yaml`), so CI runs the NIXL integration and P/D accuracy tests.
