# [Feature][MRV2] Add typed pipeline side-input transport

[Upstream PR](https://github.com/vllm-project/vllm/pull/53102) · state: open · merged: False

## Original PR description

## Overview

Introduce a registry-driven PP tensor transport interface for Model Runner V2.
Models select their fields once at initialization and reuse common allocation,
buffer restoration and output packaging over the existing tensor-dict channel.

## Claims

- Define wire types and TP policies centrally in `vllm/distributed/pp_transport.py`.
  Register hidden states, residuals, shared top-k indices, and multimodal draft
  embeddings with their CPU mask.
- Let models bind only the tensors they need through `PPTransportTensor`, with
  independent receive/send conditions. `PPTransport` owns
  `make_empty_intermediate_tensors()`, `restore_buffers()` and
  `make_intermediate_tensors()`; DeepSeek V3.2 no longer implements a custom empty
  tensor factory or top-k copy/packing branches in its forward.
- The shared empty-tensor factory delegates to `PPTransport`, preserving the
  existing model import path. Model-specific DeepStack implementations are
  unchanged and outside this PR's scope.
- Keep persistent top-k buffers at stable addresses and restore received values
  before the first layer that reuses them. Preserve matching TP lanes for side
  inputs used by top-k and multimodal drafters.
- Relay graph-external multimodal embeddings to a compatible MRV2 drafter, with
  one-token lookahead, CPU mask and modality labels preserved.

## Validation

Local CPU validation (macOS arm64, Python 3.12):

```text
.venv/bin/python -m pytest --noconftest -q -p no:cacheprovider tests/distributed/test_pp_transport.py tests/models/multimodal/processing/test_moss_audio.py
33 passed
```

Tests cover real three-process Gloo transport of top-k and multimodal draft
embeddings across media/text batches; BF16 inputs alongside INT32 buffers;
persistent buffer addresses; invalid tensor layouts; registered field selection;
the shared empty-tensor factory; and full-graph tracing with the eager compiler
backend. The transport suite is in the CPU speculative-decoding CI job. The
unchanged MOSS tests also passed as a regression check after reverting its
DeepStack migration.

All applicable pre-commit checks passed on the nine PR files, including Ruff,
markdownlint, mypy, SPDX and test-to-CI wiring. The checks were run with the
repository virtual environment first on `PATH`.

GPU end-to-end inference, model accuracy, CUDA graph replay,
`VLLM_GPU_SYNC_CHECK=error` and performance validation remain pending. CPU tracing
is not evidence of CUDA graph replay correctness. Keep this PR as a draft; no
GPU accuracy or performance result is claimed.

## Details

- `PP_TRANSPORT_REGISTRY` separates compiled model inputs from graph-external
  payloads. Adding a new type requires an explicit registry entry. Models select
  fields at initialization; multimodal selection also includes its companion
  mask. See `docs/design/pp_transport.md` for integration examples.
- The model still owns layer-dependent decisions such as whether the next stage
  reuses top-k. The transport module owns
  tensor layout, buffer restoration, allocation and packing. It does not create
  additional collectives or change the sampled/draft-token broadcast queue.
- Variable-length draft embedding payloads remain outside the target CUDA graph's
  input schema. Top-k fields remain in that schema because the target model
  consumes them.
  Runtime operations do not add host reads of device tensor values.
- Preserve upstream embedding weight loading and sharing. Draft tokens still use
  local text embedding lookup on the last PP rank. Text embedding activations
  and embedding weights are not transported; there are no remote embedding
  queries.
- Reuse upstream aux-hidden-state relay and speculative-token synchronization.
  Multimodal capability is broadcast once during initialization, then the existing
  PP tensor-dict channel carries the selected payloads.
- Related work: #59961 addresses the DeepSeek V3.2 shared top-k boundary bug. Its
  model wiring overlaps this PR and should be consolidated during review. This
  PR additionally provides the reusable registry, stage schemas, TP policies and
  MRV2 multimodal-draft relay; it is not a second top-k-only fix. The old stacked
  dependency on #52295 is no longer required.

AI assistance was used for implementation and local checks. Human review and GPU
validation remain required before marking ready.
