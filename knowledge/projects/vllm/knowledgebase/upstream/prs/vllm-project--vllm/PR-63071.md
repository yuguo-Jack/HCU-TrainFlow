# [Perf][ROCm][GLM-5.3-Flash] Defer KDA spec decode state writes

[Upstream PR](https://github.com/vllm-project/vllm/pull/63071) · state: open · merged: False

## Overview

This PR ports the deferred spec decode state of #61434 (Qwen3.8 GDN) to the GLM-5.3-Flash KDA recurrent kernel on ROCm.

Today a spec decode step stores the full fp32 state after every draft token, but the next step reads only the state at the last accepted token. With this PR the kernel:
- stores the full state only after token 0;
- records each later token's inputs in its own slot;
- replays the accepted records at the start of the next step.

Related:
- #61434: the GDN version.
- #61761: DFlash2 performance on ROCm.
- #63073: a faster Gluon kernel for this mode on gfx950. It builds on this PR.

## Claims

- GLM-5.3-Flash + DFlash2, MI355X TP2: step time is 4.7% lower at c=64 and 4.5% lower at c=16, but 1.2% higher at c=1 (details below).
- Non-deferred launches are bit-identical to main.
- A deferred chain of steps matches per-token stores: slot-0 state within 1e-5, outputs within bf16 tolerance.
- The mode is enabled only on ROCm, with spec decode, an fp32 state and no prefix caching. All other configurations are unchanged.

## Details

**Contract** (same as #61434). Each sequence has a row of `ssm_state_indices`:
- Slot 0 holds the state after the first token of the step.
- Slot t > 0 holds token t's record: k, g, v and beta.
- The next step replays `num_accepted_tokens - 1` records onto slot 0, then decodes.
- Replay reproduces the per-token states because the fp32 state is never rounded between tokens.

**When it is on.** `Glm5NextLinearAttention` enables the mode when all of these hold:
- the platform is ROCm;
- `num_spec > 0`;
- `mamba_cache_mode == "none"`, because prefix caching reads the per-token states;
- the SSM state dtype is fp32.

The choice is fixed for the process, so every spec step of a request uses the same mode. The NVIDIA kernel takes the flag only to keep the signatures equal, and asserts that it is off.

**Kernel changes** (`fused_recurrent.py`).
- `DEFER_SPEC_STATE` is a constexpr, so the non-deferred path compiles as before.
- In deferred mode a program records k and g once, so it uses fewer, larger programs: BV 32 and 2 warps, instead of BV 8 and 1 warp. These were the best of BV ∈ {8, 16, 32, 64} × warps ∈ {1, 2, 4} at 16 or more sequences.
- An assert checks that one slot can hold one record per program.

**Tradeoff.**
- At 1 sequence the replay and the larger programs cost more than the saved stores: +2 to +9 µs per layer, which is +1.2% step time at c=1.
- The mode cannot be switched per batch, because the records must match from one step to the next.
- On gfx950, #63073 removes this cost.
