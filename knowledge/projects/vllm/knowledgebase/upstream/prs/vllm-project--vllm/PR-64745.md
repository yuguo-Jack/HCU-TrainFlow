# [Bugfix][LoRA][MoE] Import TensorDescriptor where the MoE-LoRA shrink/expand kernels use it

[Upstream PR](https://github.com/vllm-project/vllm/pull/64745) · state: closed · merged: False

## Original PR description

## Purpose

`_fused_moe_lora_shrink` and `_fused_moe_lora_expand` build TMA descriptors with `triton.tools.tensor_descriptor.TensorDescriptor`, but nothing in vLLM imports `triton.tools.tensor_descriptor`. `import triton` does not load that submodule, so in a fresh process the first call that takes the TMA path fails:

```
AttributeError: module 'triton.tools' has no attribute 'tensor_descriptor'
```

On main this path runs whenever `max_lora_rank > 128` (above the one-shot kernel's limit) on a GPU with TMA support. It usually goes unnoticed in tests because some earlier test in the same process has already imported the submodule.

This PR imports `TensorDescriptor` from `triton.tools.tensor_descriptor` where it is used.

This is the first of a stack that splits #64653:

1. this PR: import fix
2. #64653: use the shrink/expand kernels for batches of up to 64 tokens
3. #64746: problem-sized default configs, threshold 256
4. #64747: fp32 intermediate, single output rounding
5. #64748: remove the small-batch kernel

## Test Plan
