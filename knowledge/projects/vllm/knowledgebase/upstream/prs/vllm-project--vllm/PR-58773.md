# [Bugfix][Spec Decode] Keep MLA-only KV cache dtypes away from non-MLA drafters

[Upstream PR](https://github.com/vllm-project/vllm/pull/58773) · state: open · merged: False

## Original PR description

## Purpose

Fixes the first failure mode of #58733.

A target with sparse MLA layers canonicalizes its KV cache dtype to an MLA-only format while it is built: `_canonicalize_sparse_mla_kv_cache_dtype` turns `fp8` into `fp8_ds_mla` (or keeps `nvfp4_ds_mla`) and writes that back into the shared `cache_config.cache_dtype` (`mla_attention.py`). When the DFlash-family drafter is loaded afterwards, `load_dflash_model` passes that same cache_config through untouched whenever the speculative config doesn't pin a `kv_cache_dtype`, so the drafter's non-MLA sliding-window layers go into backend selection with `kv_cache_dtype=fp8_ds_mla`, which no non-MLA backend serves. Startup dies with "No valid attention backend found".

With this change a non-MLA drafter no longer inherits the ds_mla family: it falls back to `auto`, resolving to the draft model's own dtype. An explicit `kv_cache_dtype` in the speculative config still wins, and an MLA drafter keeps inheriting the canonical format. This covers every speculator built on `load_dflash_model` (DFlash, DFlash2, DSpark, LiLiCorr).

The second failure mode in #58733 (DeepSeek-V4 hyper-connection hidden states being 4x the drafter's expected width, needing aux hidden-state capture) is a separate model-side change that needs acceptance validation on real hardware; I left it out of this PR and said so on the issue.

Not a duplicate: no open PR touches the drafter cache dtype inheritance (checked #58733 links and `dflash`/`kv_cache_dtype` searches, 2026-09-26).

## Test Plan

New regression coverage: `tests/v1/spec_decode/test_dflash_draft_cache_config.py`

- explicit speculative `kv_cache_dtype` always wins
- non-MLA drafter drops inherited `fp8_ds_mla` / `nvfp4_ds_mla` to `auto`
- MLA drafter keeps the inherited ds_mla dtype
- shareable dtypes (`auto`, `fp8`, `bfloat16`) pass through unchanged

Red/green: the test errors on collection against current `main` (the guard doesn't exist) and passes on this branch.

Also run: `tests/v1/spec_decode/` (full dir), plus ruff check/format on all touched files. One existing mock in `test_lilicorr.py` had to grow the `cache_dtype` field the loader now reads.
