# [Feature][MRV2] Add dynamic PP for DSV4 with prefix-cache and Mooncake handoff

[Upstream PR](https://github.com/vllm-project/vllm/pull/63745) · state: open · merged: False

## Original PR description

## Overview

Add opt-in MRv2 buffered dynamic PP for DeepSeek-V4 with local prefix reuse and a Mooncake cache-handoff backend. Movable layers keep independent cache pages; both stages agree on ownership after the previous owner finishes transferring their state.

This remains a **draft prototype**, pending human line-by-line review and NVIDIA model/native RDMA validation. Only vLLM is updated; [vllm-ascend#19868](https://github.com/vllm-project/vllm-ascend/pull/19868) is unchanged. GitHub still reports base merge conflicts, already reported by a bot on October 27; this feature update does not rebase the PR.

## Claims

- Bounded activation snapshots, immutable boundary headers, and completed-device feedback support bounded movement of a PP2 boundary. Defaults retain fixed PP.
- Explicit local prefix support preserves central scheduler block IDs, hashes, sharing, eviction, reset and copy-on-write. Dedicated SWA, compressed KV, indexer and FP32 compressor pages include physical padding; both stages validate layout/group metadata.
- `dynamic_pp_config.kv_transfer_backend="mooncake"` reuses the **same engine initialization, registration/unregistration and batch synchronous WRITE implementation as MooncakeConnector**. PP owns its boundary epoch and cache lifetime; PD retains its existing request protocol. PP exchanges endpoints/addresses through its CPU group, without a PD router/bootstrap service or external `kv_transfer_config`.
- Both backends transfer complete state only when a layer changes owner, including cached prefixes of completed requests. Unchanged cuts copy no KV. Mooncake failures never commit ownership or silently fall back; failed writes retain buffers until worker exit. Normal shutdown unregisters before memory release.
- Separate eager DSV4 MTP1/OUT1 and MTP3 decode opt-ins remain guarded. Prefix/MTP3 shape windows accumulate cooldown across alternating batch shapes. Positive initial offsets account for the last stage's draft work.

**The current policy is full-state handoff.** Selecting Mooncake does not reduce copied bytes or provide asynchronous dirty-block replication. The user's proposed two-stage replicas with asynchronous initial/incremental updates are recorded as the next design direction, not implemented functionality.

## Details

Use eager MRv2 PP2, TP, chunked prefill disabled, `pp_send_buffer_size=2`, and `dynamic_pp_config.enabled=true`. For local prefix reuse also enable prefix caching plus `allow_prefix_caching=true`. `allow_mtp_prefill` permits eager MTP1/OUT1; `allow_mtp_decode` permits eager MTP3. Mooncake is selected with `kv_transfer_backend="mooncake"`, `mooncake_protocol` (default `"rdma"`; `"tcp"` for functional checks), and optional `mooncake_device_name`. The default cache transport remains `"collective"`. Missing native libraries fail setup instead of changing transports.

The engine registers movable allocations once and shares descriptors with the corresponding TP peer. Changed boundaries quiesce previous device work, execute the old-owner write, and propagate completion/error to both stages before advancing the epoch. This adds synchronization at an ownership change. Dedicated pages consume memory beyond the ordinary KV budget, with a full-size plus 1 GiB headroom check; automatic capacity accounting is pending. Large caches or frequent moves can be expensive. Resumed requests, external KV pooling/connectors, HiSparse, graphs, DP/EP/CP/SP, LoRA and cross-layer index reuse remain unsupported.

Shared transfer helpers live under the existing Mooncake connector package; PP epoch/replica logic stays under `vllm/v1/worker/pp/`. Rendered docs describe configuration, memory cost, transport lifetime and the distinction from continuous incremental replication.

Original duplicate-work checks found no equivalent runtime-boundary feedback design. Related #63106 supplies static DSV4.1 partitions and #41247 adjusts chunk sizes; Ascend #14945/#16618 use fold-back stages and MRv1 scheduling. The independent attention correctness fix remains [vllm-ascend#19864](https://github.com/vllm-project/vllm-ascend/pull/19864).

AI assistance was used for implementation and validation. The human owner proposed and directed the design; human review and missing hardware evaluation are required before merge.
