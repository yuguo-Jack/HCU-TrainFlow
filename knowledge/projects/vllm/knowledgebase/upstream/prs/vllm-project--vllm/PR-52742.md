# [Bugfix][Model] Guard DeepSeek V4 compressor CuTe DSL dispatch

[Upstream PR](https://github.com/vllm-project/vllm/pull/52742) · state: open · merged: False

## Original PR description

## Purpose

Fixes #52710.

The DeepSeek V4 compressor imported the optional CUDA CuTe DSL implementation
unconditionally for `head_dim == 512`. Builds without CuTe DSL therefore failed
at dispatch.

The fallback must also respect the cache layout. The Triton compressor writes
the packed `fp8_ds_mla` representation (`torch.uint8`); it is not compatible
with FlashInfer's plain BF16 or per-tensor FP8 cache rows. This change therefore:

- uses CuTe DSL when it is available on CUDA;
- permits the Triton fallback only for packed `torch.uint8` cache rows; and
- raises a clear error for plain BF16/per-tensor FP8 rows without CuTe DSL.

## Duplicate-work check

No open PR addresses this issue.

## Test Plan

- Execute `DeepseekCompressor.forward` with CuTe DSL unavailable for packed
  `uint8`, plain BF16, and plain FP8 E4M3 cache rows.
- Assert the plain layouts fail before the Triton callable can launch.
- Assert the packed layout dispatches to Triton.
- On SM89+, execute the real packed Triton writer against a 584-byte cache row
  followed by a sentinel guard region and verify the guard is unchanged.
- Run the Python-specific pre-commit lint and formatting hooks.

## Test Result

- RTX 3050 (SM86), driver 610.88, PyTorch 2.13.0+cu130:
  - plain BF16 forward rejection: **passed**
  - plain FP8 E4M3 forward rejection: **passed**
  - packed `uint8` forward dispatch: **passed**
  - real packed FP8 write with overrun sentinel: **skipped**, because native
    FP8 E4M3 conversion requires SM89+
- Focused pytest result: **3 passed, 1 skipped**
- Kaggle probe: Tesla P100 (SM60), also below the SM89 requirement
- `pre-commit run ruff-check --files ...`: **passed**
- `pre-commit run ruff-format --files ...`: **passed**
- `git diff origin/main...HEAD --check`: **passed**

The SM89+-gated sentinel test is included for Ada/Hopper/Blackwell CI.

## Model evaluation

Not run. This change does not modify model math, kernels, output values, or model
loading. It restricts dispatch according to the existing cache representation
and prevents an incompatible writer from receiving plain cache rows.

No documentation update is needed because this fixes internal optional-kernel
dispatch without changing the public interface.

AI assistance was used for the implementation. I reviewed every change.
