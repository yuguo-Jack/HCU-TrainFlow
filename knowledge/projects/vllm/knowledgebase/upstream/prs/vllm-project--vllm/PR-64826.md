# [CI] Run Distributed Features examples first and shard it automatically

[Upstream PR](https://github.com/vllm-project/vllm/pull/64826) · state: open · merged: False

## Original PR description

## Overview

Moves the Python example commands of Distributed Features to the start of the step, before its pytest commands, and enrolls the step and its AMD mirror in `automatic_shard`. The planner treats commands before the first pytest as setup that runs in every shard, and allows only pytest after it, so with the examples between pytest commands an enrollment flag would be ignored.

## Claims

| Job | Plan |
|---|---|
| `distributed-tests-2xh100-2xmi300` | 2 shards |
| its AMD mirror | 2 shards |

- Every command stays the same; only the examples move ahead of the pytest commands, and the pytest commands keep their order.
- The slowest job drops to about 17.5 minutes on NVIDIA and about 20 on AMD. Each shard runs the examples, but the pytest commands split evenly enough that machine time stays within a few percent of main.

## Validation

- The generator's enrollment gate accepts the step and its mirror; `split_check.py` finds no step whose jobs each run the whole suite.
- A scoped build of this reorder on an earlier base passed: the NVIDIA step as one job in about 20 minutes, the AMD mirror as 2 shards of about 19 and 20 minutes.
- `/ci run` build 99731 (NVIDIA) and scoped build 99735 (AMD mirror) on this head: every command's passed and skipped counts match main's latest passing nightly, including the `test_dbo.py` cases that failed in the newest nightly. Slowest shard about 17.5 minutes on NVIDIA and 19.4 on AMD; machine time about 2% over main on both.

## Details

- **Known main failure.** The latest nightly failed two `test_dbo.py` cases on the NVIDIA step ("Server exited unexpectedly") after passing in the nightlies before it. Any failure here is compared against main's.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job.
