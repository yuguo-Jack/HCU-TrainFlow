# [Bugfix][Tool Parser] Preserve quoted markers in Apertus arguments

[Upstream PR](https://github.com/vllm-project/vllm/pull/61940) · state: open · merged: False

## Original PR description

## Overview

Fix Apertus tool-call parsing when JSON argument strings contain literal `<|tools_prefix|>` or `<|tools_suffix|>` text, in both streaming and non-streaming responses.

## Claims

- Preserve marker text in string values and keys, including nested arguments, escaped quotes, and backslashes.
- Prevent buffered partial markers from leaking into streamed content and emit valid content-only deltas.
- Retain implicit JSON completion, recovery of missing container brackets, and the scientific-notation fix from #61812.

## Details

The non-streaming regex stopped at the first suffix even inside a JSON string; streaming `rfind` could likewise mistake quoted markers for block boundaries. A shared quote/escape-aware scan finds the suffix outside strings, and streaming content offsets follow the text actually released by the marker buffer. The change stays inside the Apertus parser and its existing tests, without changing the public parser interface or adding dependencies.

If a JSON string itself is unclosed, subsequent suffix text remains string data: the text-only interface cannot reliably distinguish that text from a control token. Recovery of missing container brackets is covered, but this does not promise identical behavior for every malformed output. Multiple calls within one block are supported; separate tool blocks are outside this change's scope.

Duplicate-work check: no open PR addresses this Python boundary fix. #46813 implements the Rust parser, and #50496 adds Apertus 1.5 support in other files. #61812 is already merged into this baseline and its regression tests still pass.
