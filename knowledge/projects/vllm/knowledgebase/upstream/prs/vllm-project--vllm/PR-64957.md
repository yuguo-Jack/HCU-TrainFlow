# feat(compilation): add MoE FlashInfer fusion pass for kMoEFinalizeARResidualRMSNorm (#40544)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64957) · state: open · merged: False

## Original PR description

## Summary

Implements FlashInfer fused MoE finalize + residual add + all-reduce + RMSNorm (pattern code 7) as a compiler pass.

## Changes

1. **vllm/compilation/passes/fusion/moe_flashinfer_fusion.py** (new)
   - MoEFlashInferFusionPass — pattern matcher for UnfinalizedMoEOutput → finalize → add → all-reduce → RMSNorm
   - Custom op flashinfer_trtllm_fused_moe_finalize_ar_rmsnorm calling flashinfer.comm.allreduce_fusion with kMoEFinalizeARResidualRMSNorm

2. **vllm/compilation/passes/pass_manager.py**
   - Import and register pass under fuse_allreduce_rms config flag

3. **vllm/model_executor/layers/fused_moe/runner/moe_runner.py**
   - Decomposition for moe_forward_shared returning UnfinalizedMoEOutput when defer_moe_finalize enabled
   - Forward method handles UnfinalizedMoEOutput to produce matchable FX graph

## Activation

Triggers for models with deferred MoE finalize (DeepSeek-V3, Kimi-K3, MiniMax-M3.1) when:
- torch.compile enabled
- CompilationConfig.pass_config.fuse_allreduce_rms = True
- tensor_parallel_size > 1
- FlashInfer installed with comm module

## Testing

Requires H100x2 (or A100x2 with FlashInfer) — not available locally. CI validation requested.

Closes #40544
