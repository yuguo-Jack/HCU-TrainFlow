# [CI][Test] Seed each MLA backend correctness case (fix B200 V1 Attention shard 1/6)

[Upstream PR](https://github.com/vllm-project/vllm/pull/62047) · state: closed · merged: False

## Original PR description



## Overview

Seed the random inputs of each MLA backend correctness case, so that a case gives the same result in every CI shard. Fixes #62002 (B200 V1 Attention shard 1/6 fails on `main` since 16 Oct).

## Claims

- `test_backend_correctness` and `test_chunked_context_backend_correctness` no longer depend on which tests ran before them in the same pytest process.
- Expected: the failing case `test_backend_correctness[glm-MLAPrefillBackendEnum.TRTLLM_RAGGED-1.0-1.0-fp8-4-deepseek-ai/DeepSeek-R1-mixed_small]` (CUTLASS_MLA and TOKENSPEED_MLA, max diff 0.154297 against `atol=0.15`) gets the inputs it has when it runs first in a process. It passed that way on GB300 ([#62002 comment](https://github.com/vllm-project/vllm/issues/62002#issuecomment-6219889830)). The B200 V1 Attention step of this PR's CI checks it on SM100.

## Validation

- The fix is test-only. Lint, format and test collection pass (`pytest --collect-only tests/v1/attention/test_mla_backends.py`: 349 tests). I have no SM100 GPU; the B200 V1 Attention shards of this PR's CI run every case of the file.
- Root-cause evidence, from the CI logs (details in [#62002](https://github.com/vllm-project/vllm/issues/62002#issuecomment-6220068776)):
  - 126 B200 V1 Attention logs of `main` and PR builds from 8 to 16 Oct run this case. Grouped by the exact ordered list of tests that ran before it in the same process, there are 40 orders, and every order is all-PASSED or all-FAILED. All 16 failing logs (builds 95318–95411) share one order (549 tests before the case); the order before it (614 tests, builds 95282–95298) passed 9 of 9.
  - No code change explains the boundary: the only `main` commits between the last passing base (`dd9e07a25f`, #95296) and the first failing one (`642c18d64c`, #95323, a ROCm-only PR) are #58872 (DeepSeek-V4.1, SM90 only), #60356 (XPU Dockerfile) and #61867 (Kimi K3 model files). The failing `main` build #95334 reuses the dependency layer that #95296 built.

## Details

- Root cause: `_run_backend_correctness` creates its queries, KV and weights with `torch.randn` and never seeds; the file seeds only once at import (`torch.manual_seed(42)`), and `tests/conftest.py` has no per-test seed fixture. The runtime-shard plugin splits `test_mla_backends.py` by test ("812 of 2379 tests, split by test"), so each layout change gives the cases different inputs. In the current layout the failing case lands on an input where one element of the CUTLASS_MLA and TOKENSPEED_MLA output is 0.154297 from a reference of about 0, just over the fp8 `atol` of 0.15.
- The seed is 42, the module's existing seed, applied with `vllm.utils.torch_utils.set_random_seed` at the start of the shared helper, so both correctness tests are covered.
- Limitation: this makes the result stable, but it does not show whether these two backends have an accuracy edge for GLM dims with an fp8 KV cache on some inputs, or whether `atol=0.15` is only tight. Running the case with a few seeds on B200 would answer that; I cannot run SM100.
