# [ROCm][Step5] Exercise the real CSA decode and engine paths in tests

[Upstream PR](https://github.com/vllm-project/vllm/pull/64836) · state: closed · merged: True

## Original PR description

- test_amd_csa_paged.py: decode summary scores, region selection and gated sparse decode attention against FP32 references, on the TP1 (4x16) and TP8 (1x8) head layouts, for single-token decode and 4-row MTP verify, with BF16 and FP8 KV.
- test_amd_model.py: engine test on the reduced registry checkpoint (top-k 16, FP8 KV, block size 32, 300-token chunked prefill) that runs scored prefill and sparse decode end to end, checks that the scored-prefill warmup runs, and compares decode logprobs against a teacher-forced re-prefill.
- test_amd_fp8_kv_init.py: removed, the engine test covers the same FP8 KV and block-size check.

Follow-up to #61837. Most of the ROCm Step5 tests that came with it mock out the code they cover or only check dispatch, so nothing ran the CSA decode chain against a reference or drove the model through the engine. The kernel test is the numerical check: scores, scale, masks, paging and the gate against FP32. The engine test makes sure the real path runs through vLLM. With dummy weights its logits are nearly flat, so a decode wiring bug and a harmless rounding difference across GPUs both move a logprob by one bf16 step. Its logprob tolerance (1e-2) is therefore only a guard against gross breakage, which the docstring says.

On MI355X the Step5 CI step (`pytest -v -s models/step5` plus the Step5 `test_initialization` case), on this branch merged with main, passed 12/12 runs. Both files run in the existing Step5 CI step.
