# [Perf][MoE] Fold routed_scaling_factor into output transform weights

[Upstream PR](https://github.com/vllm-project/vllm/pull/59761) · state: open · merged: False

## Original PR description



## Overview

On ROCm/AITER, `MoERunner` applies `routed_scaling_factor` as a standalone runtime multiply between the routed-output all-reduce and the output-transform GEMM. This PR folds that scale into `fc2_latent_proj`'s weights once at load time (NemotronH latent-MoE only), eliminating the runtime multiply kernel entirely for the common (non-FP16) case.

## Claims

- Eliminates the `triton_poi_fused_mul_2`-style runtime-multiply kernel (`torch.compile`-generated) that sits on the critical path between the routed-output all-reduce and the output-transform GEMM.
- ~1.17x speedup / ~22.3us saved per call on the isolated op sequence, measured on real MI350X hardware (mean and median agree, consistent across p10/p90 -- not a single outlier measurement).


## Validation

**Unit tests** (`tests/model_executor/test_moe_runner_routed_scale_prefold.py`, added in this PR, 12 tests, all passing against this branch).

Reproduce: `pytest tests/model_executor/test_moe_runner_routed_scale_prefold.py -v`

**Wall-clock latency benchmark** (same standalone repro, extended with `torch.cuda.Event`-based GPU timing -- HIP implements the CUDA event API, so this works unmodified under ROCm -- 200 timed iterations after 20 warmup
iterations):

| | mean | median | p10 | p90 | min | max |
|---|---:|---:|---:|---:|---:|---:|
| Before (runtime multiply) | 153.78us | 151.64us | 147.64us | 161.84us | 144.48us | 247.32us |
| After (prefolded, fix) | 131.47us | 129.20us | 126.64us | 139.76us | 122.84us | 170.40us |

## Details

For a bias-free, unquantized linear transform `T(x) = x @ W`, the identity `(x * c) @ W == x @ (c * W)` holds for any scalar `c`. Since `routed_scaling_factor` is applied immediately before the output transform, and NemotronH's `fc2_latent_proj` already computes exactly this safety condition (for an unrelated optimization, `reduce_commutative`), this PR reuses that same condition to fold `routed_scaling_factor` into `fc2_latent_proj`'s weights once at load time.
