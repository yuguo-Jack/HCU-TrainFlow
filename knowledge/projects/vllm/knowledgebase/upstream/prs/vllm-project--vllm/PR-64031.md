# [ROCm][Perf][Kimi-K3] DSpark Markov sampling sharded over the vocabulary, one launch

[Upstream PR](https://github.com/vllm-project/vllm/pull/64031) · state: open · merged: False

## Original PR description

Kimi-K3 DSpark Markov sampling on ROCm (TP > 1): sharded over the vocabulary across TP ranks, all draft positions in one launch.

- Rank k uses its draft lm_head shard of the logits (no base-logits all-gather) and its rows of markov_w2.
- Ranks exchange one tagged record per position through peer memory.
- The draft logits cache stays full-vocabulary on every rank.
- Same noise, rounding and tie break as vLLM's loop. Only the bias's fp32 sum order differs, so it can be off by the last bf16 bit.
- Every other configuration keeps vLLM's loop: greedy drafts, top-k drafting, watermarker, reduced vocabulary, acceptance estimator, fp64 noise, quantized head, batch-sharded cache, TP1, more than 4 rows.
- Core change: `DSparkSpeculator.load_model` calls an optional `model.setup_sample_sequential(speculator)`.

ROWS is a constexpr, so each row count 1-4 compiles separately on each rank at first use. Warmup only runs batches of max_num_seqs, 2 and 1 requests (warmup.py:451-467), and the draft runs eagerly with the unpadded count whenever decode graphs are not FULL (dflash/speculator.py:155-158, 629). So under -cc.cudagraph_mode=PIECEWISE (all four under --enforce-eager) the first 3- or 4-request step compiles mid-serving while peer ranks already spin on this rank's records, and gives up at MAX_SPIN if the compiles finish far enough apart, which is what the test's warm-up comment guards against. Compile the variants in ShardedMarkovSampler.init with _sharded_markov_kernel.warmup(..., grid=(1,)) before the barrier, as deepseek_v41/nvidia/model_state.py:443-449 does.
