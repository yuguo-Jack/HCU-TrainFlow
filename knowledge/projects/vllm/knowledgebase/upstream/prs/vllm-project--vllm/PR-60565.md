# [Bugfix][Reasoning] Fix Kimi K3 response-only transitions

[Upstream PR](https://github.com/vllm-project/vllm/pull/60565) · state: open · merged: False

## Original PR description

## Overview

When Kimi K3 starts directly with a response, streaming can leave `content` empty and fail to signal when JSON constraints should start. This fix recognizes the response control tokens while preserving ordinary text that quotes the same markers.

We encountered JSON response-format failures during endpoint validation with Moonshot AI's official [Kimi Vendor Verifier (KVV)](https://github.com/MoonshotAI/Kimi-Vendor-Verifier). Those failures prompted this investigation; the CPU reproduction below isolates the vLLM parser defect addressed here.

## Claims

- Route response-only output to `content` and identify the constraint start, including when the response opener spans decode steps.
- Keep quoted marker text in reasoning until the explicit think close, and preserve response-marker text inside JSON strings.
- Preserve explicit unfinished thinking, prompt-level reasoning detection and final reasoning-token counting.

<summary>Minimal CPU reproduction and regression controls</summary>

Run in a dependency-prepared vLLM source checkout with `.venv/bin/python`; use `PYTHONPATH=.` if running a saved snippet. This loads the pinned official tokenizer, without model weights. The first assertion reproduces missing streamed content. The remaining assertions check quoted text and the engine's constraint-start boundary.

```python
from transformers import AutoTokenizer
from vllm.entrypoints.openai.chat_completion.protocol import ChatCompletionRequest
from vllm.parser.kimi_k3 import KimiK3Parser
from vllm.reasoning.kimi_k3_reasoning_parser import KimiK3ReasoningParser

class ReasoningOnlyK3(KimiK3Parser):
    reasoning_parser_cls = KimiK3ReasoningParser

tokenizer = AutoTokenizer.from_pretrained(
    "moonshotai/Kimi-K3",
    revision="f831ab66814297da540d832a5235f8e904f29d06",
    trust_remote_code=True,
)
parser = ReasoningOnlyK3(tokenizer)
request = ChatCompletionRequest(model="kimi-k3", messages=[])

# Main baseline fails this response-only streaming assertion.
body = '{"ok":true}'
ids = tokenizer.encode("<|open|>response<|sep|>" + body)
content = ""
for index, token_id in enumerate(ids):
    delta = parser.parse_delta(
        tokenizer.decode([token_id]), [token_id], request,
        finished=index == len(ids) - 1,
    )
    if delta:
        content += delta.content or ""
assert content == body

# Control: quoted ordinary text must remain reasoning.
parser = ReasoningOnlyK3(tokenizer)
quoted = "<|open|>response<|sep|> is only a quoted example."
first = parser.parse_delta(
    quoted, tokenizer.encode(quoted, allow_special_tokens=False),
    request, finished=False,
)
assert first.reasoning == quoted and first.content is None

suffix = '<|close|>think<|sep|><|open|>response<|sep|>{"ok":true}'
second = parser.parse_delta(
    suffix, tokenizer.encode(suffix), request, finished=True,
)
assert second.content == '{"ok":true}'

# Ordinary response-marker text inside JSON must survive token-by-token delivery.
parser = ReasoningOnlyK3(tokenizer)
body = '{"marker":"<|open|>response<|sep|>"}'
ids = (tokenizer.encode("<|open|>response<|sep|>")
       + tokenizer.encode(body, allow_special_tokens=False)
       + tokenizer.encode("<|close|>response<|sep|>"))
content = ""
for index, token_id in enumerate(ids):
    delta = parser.parse_delta(
        tokenizer.decode([token_id]), [token_id], request,
        finished=index == len(ids) - 1,
    )
    if delta:
        content += delta.content or ""
assert content == body

# The real engine caller includes the prompt, unlike frontend parse_delta.
from types import SimpleNamespace
from vllm.sampling_params import SamplingParams, StructuredOutputsParams
from vllm.v1.request import Request
from vllm.v1.structured_output import StructuredOutputManager

prompt = tokenizer.apply_chat_template(
    [{"role": "user", "content": "Return JSON."}],
    thinking=True, add_generation_prompt=True, tokenize=True,
)
engine_request = Request(
    request_id="repro", prompt_token_ids=prompt,
    sampling_params=SamplingParams(
        max_tokens=32, structured_outputs=StructuredOutputsParams(json_object=True),
    ), pooling_params=None,
)
reasoner = KimiK3ReasoningParser(tokenizer)
manager = SimpleNamespace(enable_in_reasoning=False, _get_reasoner=lambda _: reasoner)
opener = tokenizer.encode("<|open|>response<|sep|>")
delta_ids = opener + tokenizer.encode("{}", allow_special_tokens=False)
assert StructuredOutputManager._get_constraint_bounds(
    manager, engine_request, delta_ids,
).constraint_start == len(opener)

# Invalid speculative suffixes must not hide the first genuine transition.
proposal = opener + opener + tokenizer.encode("{}", allow_special_tokens=False)
assert StructuredOutputManager._get_constraint_bounds(
    manager, engine_request, proposal,
).constraint_start == len(opener)
```

Main fails the response-only content and constraint-start assertions. This change passes all assertions, including the quotation controls. The tokenizer encodes structural markers differently from the same characters in ordinary text. These are constructed token sequences, not captured model outputs.

</details>

## Details

The streaming extractor and constraint-start check rely on think markers. A completion that starts with a response has no generated think close, so they miss the initial response transition.

Moonshot's [tokenizer](https://huggingface.co/moonshotai/Kimi-K3/blob/f831ab66814297da540d832a5235f8e904f29d06/tokenization_kimi.py#L154) distinguishes response control tokens from ordinary text containing the same characters. Checking token IDs for this transition prevents quoted reasoning from leaking into `content`; the check stays local to K3 and does not scan the full prompt on each decoding step.

The repair stays in the existing Python K3 reasoning parser and test file: 39 production additions / 2 deletions. It reuses existing marker helpers and token handoff, without changing shared interfaces. It recognizes the official [generation prefix](https://huggingface.co/moonshotai/Kimi-K3/blob/f831ab66814297da540d832a5235f8e904f29d06/encoding_k3.py#L745) while retaining the [encoder's explicit think-close rule](https://huggingface.co/moonshotai/Kimi-K3/blob/f831ab66814297da540d832a5235f8e904f29d06/encoding_k3.py#L505).

Limits: the unchanged non-streaming text extractor still misparses ordinary think-marker characters inside JSON strings. That is a separate pre-existing issue. Custom generation templates and active tool calling are outside the checked coverage. The tested endpoint's backend/version was unavailable, so this fix does not establish the cause of all observed KVV failures.

Related reports: [#57688](https://github.com/vllm-project/vllm/issues/57688) and [#57714](https://github.com/vllm-project/vllm/issues/57714).

Related PRs: [#57689](https://github.com/vllm-project/vllm/pull/57689) and [#57718](https://github.com/vllm-project/vllm/pull/57718) address response-only streaming and the constraint start. In a CPU replay of their compared revisions together, ordinary response-marker text quoted at the start of reasoning entered `content`, making the final JSON invalid. This change checks control-token IDs, keeping that quotation in reasoning and the JSON intact.
