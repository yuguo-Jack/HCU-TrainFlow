# [Bugfix] Fix RustToolParser streaming final flush

[Upstream PR](https://github.com/vllm-project/vllm/pull/51550) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #51549.

Rust-backed tool parsers may retain an ambiguous partial tool-call marker in their incremental buffer. The non-streaming `RustToolParser` path calls `finish()`, but the streaming path previously had no finalization hook. As a result, buffered text could be silently omitted when generation ended.

For example, MiniMax M3 streaming output for:

```text
plain ]<]minimax[>[<tool_ca
```

previously emitted only `plain `, while non-streaming parsing returned the complete text.

This change:

- adds a `finish_streaming()` hook to `RustToolParser`;
- calls it from `DelegatingParser` when generation finishes;
- uses the Rust parser's `reset()` result to recover uncommitted text after parse/finalization errors;
- degrades later deltas in a failed stream to normal content instead of silently dropping them; and
- reuses one delta-message merge helper for engine and non-engine parser finalization.

Streaming recovery preserves events that were already committed. It does not attempt to retract a structured tool call that may already have been sent; only the parser's uncommitted suffix is recovered as content.

AI assistance was used to investigate the lifecycle mismatch, construct regression cases, draft the implementation, and review counterexamples. I reviewed the final diff and the test results below.

## Test Plan

- Cover a partial MiniMax M3 tool-start marker at end of stream.
- Cover a completed first invocation followed by a truncated second invocation, ensuring the first remains structured and is not leaked into content.
- Cover `parse_into()` error recovery, later-delta pass-through, parser reuse, and the real `DelegatingParser(finished=True)` path.
- Run the MiniMax M3 and generic Rust tool-parser unit-test files.
