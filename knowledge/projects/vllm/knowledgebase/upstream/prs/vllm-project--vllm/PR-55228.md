# [Bugfix][EPLB] Reject reloads and transfers for managed models

[Upstream PR](https://github.com/vllm-project/vllm/pull/55228) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

After EPLB changes expert placement, checkpoint reloads can route weights to the wrong experts, and an in-flight rebalance can overwrite new weights. Reject reloads and transfer sessions for EPLB-managed targets before mutation.

## Claims

- Reject checkpoint reloads and weight-transfer sessions for the selected EPLB-managed model.
- Preserve updates to a dense main or draft model when only the other model uses EPLB.
- Require users who need these updates to start the engine with EPLB disabled.

## Validation

A new `LLM` regression with real weights fails without the guard and passes with it. GPU results used NVIDIA B200 GPUs with driver 580.95.05. This branch includes main `410ab341a8`, and the runs used a precompiled build of main `b8c04dd3b4`, because no native code changed between the two commits. The comparison tree is this branch with only the production files restored to main.

```sh
.venv/bin/python -m pytest tests/v1/distributed/test_eplb_weight_update.py -v
```

```text
Without the guard: test_eplb_rejects_weight_updates fails with
                   Failed: DID NOT RAISE Exception
With the guard:    both tests pass on MRV2, and on MRV1 with VLLM_USE_V2_MODEL_RUNNER=0
```

The tests use `deepseek-ai/DeepSeek-V2-Lite-Chat` with TP=2. One checks that an EPLB-managed model rejects `reload_weights` and `start_weight_update`. The other checks that expert parallelism without EPLB still accepts both, with unchanged greedy tokens under `VLLM_BATCH_INVARIANT=1`. `tests/v1/worker/test_gpu_worker_weight_transfer.py` passes unchanged, and it covers runners that have no `eplb_state`.

Related tests also pass at this head: `test_gpu_worker_weight_transfer.py`, `test_gpu_model_runner.py`, `test_extensible_kv_cache.py`, `test_sleep_mode.py`, and `tests/distributed/test_weight_transfer.py`. That last file needs `NCCL_NET_PLUGIN=none` on this host, and without it the batch-invariant and IPC cases hang on main too. Before the last merge from main, `test_gpu_draft_lm_head.py`, `test_sleep_mode_tensor_ownership.py`, and the RL weight checker, weight metrics, and offline transfer tests also passed.

A separate run with `Qwen/Qwen3-30B-A3B`, TP=2, and forced rebalances shows the effect on output. It ran on the same hardware against main `3a90cc6fd0`, before the latest commits on this branch, including the merge that moved the guard ahead of the KV cache loan. Each row compares greedy tokens with the output from before the update.

| Tree and configuration | `reload_weights` | Matching greedy tokens per prompt, out of 32 | Example output afterward |
| --- | --- | --- | --- |
| Without the guard, EPLB, MRV1 | Succeeds | 0, 0, 0, 0 | `\r\n \r\n \r\n` |
| Without the guard, EPLB, MRV2 | Succeeds | 0, 0, 0, 0 | ` is is is is` |
| With the guard, EPLB, MRV1 | Rejected | 32, 32, 32, 32 | ` Paris. The capital of the United Kingdom is London.` |
| With the guard, EP without EPLB, MRV2 | Succeeds | 32, 32, 32, 32 | ` Paris. The capital of the United Kingdom is London.` |

`start_weight_update` is rejected in the same way with EPLB, and it still works without EPLB. On MRV2 with EPLB and the guard, the text stayed correct but greedy tokens matched only in part, because EPLB rebalances continued between generations and vLLM is not batch invariant by default. The same kind of near-tie change occurred across a rebalance without any reload. A real engine with an EPLB main model and an MTP draft model also confirms the draft path. `start_draft_weight_update` is rejected with the guard and succeeds without it, and greedy output is unchanged after the rejected calls.

**Not validated:** No real engine ran with a dense model next to an EPLB-managed model. That exception was checked by reading the code. The regression also passes with `gpu_memory_utilization=0.111` on B200, which is about 20.4 GiB and matches the budget of the L4 CI step, but it has not run on an L4 GPU.

**CI coverage:** `(L4) Distributed DP Basic` and its `(MI355)` mirror select the regression, but ROCm was not run. The regressions of this PR also pass with this branch merged onto main `b2a9480dc7`, with its own precompiled build and `VLLM_WORKER_MULTIPROC_METHOD=spawn` as in CI. Upstream checks are stopped at contributor authorization, so Buildkite has not run this branch.

## Details

Checkpoint loading builds expert mappings from initial placement, while inference can use a newer EPLB map. Draining pending transfers does not fix the completed-rebalance mismatch. The guard runs before reload delegation or update-session mutation and checks the main and draft targets separately.

This is a conservative restriction, not an implementation of safe live-layout reloading. `vllm snapshot` rehearsal also calls `reload_weights`, but snapshots do not support distributed deployments (`docs/features/initialized_snapshots.md`) and EPLB needs TP, PCP, or DP above 1, so no supported snapshot flow reaches this guard. This comes from reading the code and was not run. It also blocks the model-specific path proposed by #59063 for DeepSeek V4.1 on NVIDIA. Generic loaders still need safe live-layout reload support, so that proposal does not replace this guard. Runners without `eplb_state`, such as the standalone CPU runner, skip the check. The guard runs before the KV cache loan that #56492 added to `reload_weights`, so a rejected call does not release KV memory.

The weight-transfer guide documents the target-specific restriction and dense-model exception. The sleep mode, layerwise, and expert-parallel guides and the `enable_eplb` description also state the restriction. Level 2 sleep itself is not rejected: the guard applies to `reload_weights` after wake, so the sleep mode guide warns against that combination. This does not duplicate an open PR. #59063 is the closest open PR, and it is described above.
