# [Bugfix][EPLB] Reject unsafe dynamic weight updates

[Upstream PR](https://github.com/vllm-project/vllm/pull/55228) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Reject reloads and weight-update sessions for EPLB-managed models before they can change weights or session state.

## Claims

- Prevent checkpoint reloads from using stale expert placement after a rebalance.
- Prevent pending rebalance transfers from overwriting updated weights.
- Allow updates to a dense main or draft model when only the other model uses EPLB.

## Validation

The worker weight-transfer suite and scoped pre-commit hooks passed on this branch. Disabling the guard reproduces unsafe reload and update-session starts; dense-target controls still pass.

To run the related suites in a configured development environment:

```sh
.venv/bin/python -m pytest tests/v1/worker
```

Earlier CPU loader/lifecycle reproductions showed incorrectly routed weights after a completed rebalance and old weights restored by a pending transfer. Those reproductions were not repeated after the rebase. Multi-GPU model validation is still needed; local tests used the pinned Humming dependency.

Upstream checks are stopped at contributor authorization; these local results do not establish a CI pass.

## Details

Checkpoint loading builds expert mappings from initial placement, while inference can use a newer EPLB map. Draining pending transfers leaves the completed-rebalance mismatch unresolved. The guard rejects updates before reload delegation or update-session mutation; callers needing updates must disable EPLB.

#59063 proposes synchronization and live expert mapping for DeepSeek V4.1 on NVIDIA. Generic loaders still need a safe live-layout reload, so it does not replace this guard. This conservative restriction also blocks that model-specific update path.
