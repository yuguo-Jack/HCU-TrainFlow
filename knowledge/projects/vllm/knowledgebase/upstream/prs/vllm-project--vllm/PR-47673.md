# [Quantization] Marlin FP4: report missing CUDA custom ops in is_supported

[Upstream PR](https://github.com/vllm-project/vllm/pull/47673) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Report missing Marlin FP4 CUDA custom ops during kernel selection, before weight processing fails. This is the prerequisite for [#47674](https://github.com/vllm-project/vllm/pull/47674).

## Claims

- CUDA capability alone no longer selects Marlin when `_C::gptq_marlin_repack` or `_C::marlin_gemm` lacks a registered CUDA kernel.
- The support result names missing ops; builds registering both retain their existing selection behavior.

## Validation

Tested base `18c19eaf23`; refreshed guard head `a969c9b549`. On ThinkStation PGX (GB10/SM121), Python 3.12.3, PyTorch 2.13.0+cu130, pytest 9.1.1, real current-source modules were imported with prebuilt vLLM extensions.

`.venv/bin/python -m pytest tests/quantization/test_marlin_fp4_registration_guard.py -v`: **5 passed**, covering missing one/multiple ops, registered-op pass-through, absent dispatcher schema and unexpected TypeError propagation. These same five tests passed again in the October 10 oversight run of the stacked suite: **19 passed plus 1 separate native selection case = 20 unique tests**, not 25. The guard files are identical between the standalone and stacked branches, with committed-source hashes verified.

Configured scoped `pre-commit run --files` passed on the three changed files, including Ruff, typos, mypy 3.11, CI test tethering, SPDX and applicable policy checks. Nonmatching hooks skipped as configured. `git diff --check` passed. No full-model or performance claim.

## Details

Source builds can omit Marlin CUDA objects while still passing the existing platform/capability check. The dispatcher guard returns an actionable unsupported reason through the existing support API without adding steady-state inference work.

Open-PR overlap review: [#52974](https://github.com/vllm-project/vllm/pull/52974) adds ROCm gfx90a W4A16 and selector CUDA gating; [#59460](https://github.com/vllm-project/vllm/pull/59460) declares/enforces executed activation schemes. Neither supplies this dispatcher registration check. #47674 is the stacked correctness fallback.

AI assistance was used (Codex). The submitting user reported reviewing every changed line, then requested the October 10 tests under their oversight; Codex executed them with that oversight. Test logs and source-hash provenance are retained. Historical July results are not presented as new validation.
