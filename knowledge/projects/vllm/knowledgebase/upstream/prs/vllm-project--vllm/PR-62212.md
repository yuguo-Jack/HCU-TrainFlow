# [Feature][Whisper] Support srt and vtt response formats for speech-to-text APIs

[Upstream PR](https://github.com/vllm-project/vllm/pull/62212) · state: open · merged: False

## Original PR description

## Overview

Adds support for `response_format="srt"` and `response_format="vtt"` on the `/v1/audio/transcriptions` and `/v1/audio/translations` endpoints, matching the OpenAI audio API surface. Part of the Whisper feature tracker #25750 (the `response_formats` sub-item: `verbose_json` landed in #24209; this covers the remaining subtitle formats).

## Claims

- `srt` and `vtt` were already part of the documented `AudioResponseFormat` type alias and the `response_format` docstrings, but the serving layer rejected them at validation time. They are now accepted and served.
- Subtitle tracks are rendered from the same timestamped segments used by `verbose_json`: same `supports_segment_timestamp` requirement, same non-streamable constraint.
- The API routers now return a `PlainTextResponse` for `text`, `srt` and `vtt` (previously even `text` was wrapped in a JSON body). This also covers the fix proposed in #49102.

## Validation

- New unit tests in `tests/entrypoints/speech_to_text/test_subtitle_formats.py`: exact SRT/VTT cue rendering, timestamp hour rollover and millisecond formatting, blank-segment skipping and SRT renumbering, empty input, zero-length segments.
- Existing speech-to-text unit tests pass locally with the change (`test_speech_to_text_cancellation.py`, `test_chunk_timestamp_offset.py`, `test_transcription_inter_chunk_spacing.py`): 30 passed total including the new tests.
- `ruff check` and `ruff format` clean on all touched files.
- E2E endpoint tests that need a running server are left to CI.

## Details

- `base/utils.py`: new `format_segments_as_srt` / `format_segments_as_vtt` render a sequence of timestamped segments (structural `SubtitleSegment` protocol, so both `TranscriptionSegment` and `TranslationSegment` fit) into standard subtitle tracks: numbered cues with `HH:MM:SS,mmm` timestamps for SRT; a `WEBVTT` header with `HH:MM:SS.mmm` cues for VTT. Segments whose text is empty after stripping are skipped and SRT cues renumbered accordingly.
- `base/serving.py`: new `TIMESTAMPED_FORMATS = {"verbose_json", "srt", "vtt"}` constant routes srt/vtt through the existing verbose_json prompt preprocessing, logprobs and token-to-segment extraction; the rendered subtitle track is carried in the `text` field of the existing non-verbose response models (with `usage` for transcription, matching the plain `json` path).
- Both API routers return `PlainTextResponse` for `text`/`srt`/`vtt`, as the OpenAI API returns these formats as plain text rather than JSON.
- Docs updated in `docs/serving/online_serving/speech_to_text.md`.
