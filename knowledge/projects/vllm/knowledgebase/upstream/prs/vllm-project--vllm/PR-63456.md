# [Feature][Responses] Support GPT-OSS output logprobs

[Upstream PR](https://github.com/vllm-project/vllm/pull/63456) · state: open · merged: False

## Original PR description



## Overview

Support output `logprobs` and `top_logprobs` for GPT-OSS models in `/v1/responses`, for streaming and non-streaming requests. Fixes #61629.

## Claims

- Replace the current Harmony/logprobs HTTP 400 with probabilities for visible final/commentary text, excluding generated headers, reasoning, and tool arguments.
- Keep sampled and top-token scores aligned with the original content tokens across message/channel transitions and UTF-8 boundaries.
- Preserve matching probability entries in streamed deltas, done events, and the completed response, including an unfinished UTF-8 sequence at message end.

## Details

The Harmony parser optionally records content-token positions. `HarmonyContext` associates engine probabilities with visible message content, and the existing Responses formatter and streaming event builders carry those scores to the API. Raw token bytes come from the Harmony encoding so multi-token UTF-8 characters retain their original bytes.

Boundary validation also found that Harmony can finalize an unfinished UTF-8 sequence with a replacement character without emitting `last_content_delta`. The parser now emits the remaining completed-message tail before the completion segment, preserving both streamed text and buffered scores. Truncated raw bytes reconstruct the returned text when decoded with replacement.

Duplicate checks covered the issue/comments and open PR searches for `61629 in:body`, `gpt-oss Responses logprobs`, and `Harmony Responses logprob`; no matching implementation was found. Related #58018 addresses item status/zero-delta lifecycle and #59387 repairs malformed tool headers.
