# [Kernel] Fix vllm_c fused_add_rms_norm to match native IR rounding semantics

## Overview

Fixes #52104: align the `vllm_c` fused-add RMSNorm kernels with the native IR's FP32 residual-sum and weight-multiplication rounding semantics.

## Claims

- Both vectorized and generic CUDA paths compute variance and normalization from the unrounded FP32 sum, then publish the rounded residual.
- The weighted output rounds the normalized value to the weight dtype before multiplying, as the native IR does.
- The BF16/FP16 regression checks exact residual write-back and fewer than 1% output mismatches against the native arithmetic reference, allowing FP32 reduction-order noise.

## Details

The old CUDA paths round `input + residual` to BF16/FP16 before computing variance and then normalize that rounded value. Native IR retains the FP32 sum for both operations. Each CUDA path now recomputes the FP32 sum in the second pass, writes the residual once, and preserves native rounding before the weight multiplication. Recomputing the sum adds input reads and arithmetic; performance has not been benchmarked.

Upstream #60721 moved the CUDA sources from `csrc/libtorch_stable/` into `csrc/`. This revision rebases the original fix onto the current paths.
