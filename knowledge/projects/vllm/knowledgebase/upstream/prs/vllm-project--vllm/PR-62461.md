# [Bugfix][Test] Stop requesting capfd in the subprocess weight cache test

[Upstream PR](https://github.com/vllm-project/vllm/pull/62461) · state: closed · merged: True

## Original PR description

## The failure

`(MI300) Model Executor` in [AMD CI 14934](https://buildkite.com/vllm/amd-ci/builds/14934), the only failure among 1238 passing tests:

```
FAILED model_executor/model_loader/test_weight_cache.py::test_ipc_cache_cold_start_and_warm_restart_tp2_ep - TypeError: cannot pickle '_Local' object
```

## The cause

[#55490](https://github.com/vllm-project/vllm/pull/55490) added `test_ipc_cache_cold_start_and_warm_restart_tp2_ep`, which combines `@create_new_process_for_each_test()` with the `capfd` fixture. The wrapper cloudpickles its arguments into the child process and `CaptureFixture` holds a thread-local, so the test raises before it runs. It is the only test in the file with that combination, and the failure is deterministic: the pickle happens before any GPU work.

## The change

The test no longer requests `capfd`. `DSV2_EP_CASE` leaves `check_flashinfer_cache` off and every use of `capfd` in `run_cold_start_and_warm_restart` sits behind that flag, so the fixture was requested but never read. It could not have worked in the child either, which inherits the parent's descriptors. The helper keeps it as an optional parameter, so the in-process cases retain their autotune-cache assertions.

A wider fix, dropping unpicklable fixtures inside the wrapper in `tests/utils.py`, would silently change behaviour for other tests, so this stays local to the one test that is wrong.

## Tests

`test_ipc_cache_cold_start_and_warm_restart_tp2_ep` fails on `main` with the error above and passes with this change: 1 passed in 216.64s on MI300 (gfx942, ROCm 10.0) with 2 GPUs, through baseline, cold start, daemon, warm and restart.
