# [Bugfix] Disable FlashInfer on sm_120 when the CUDA toolkit is older than 12.9

[Upstream PR](https://github.com/vllm-project/vllm/pull/54267) · state: open · merged: False

## Original PR description

## Purpose

On sm_120 (RTX 50xx / RTX PRO 6000) with a CUDA toolkit < 12.9, FlashInfer's JIT
drops the arch and fails at runtime with "FlashInfer requires GPUs with sm75 or
higher" (#50705). vLLM still selected FLASHINFER, so `--kv-cache-dtype fp8`
crashed at startup.

One check in `has_flashinfer()`, the structure from @pavanimajety's branch, but it
reads the CUDA version the way FlashInfer does: nvcc first, torch only as a
fallback (flashinfer/jit/cpp_ext.py L47-87, 12.9 rule in compilation_context.py
L74-83). Checking `torch.version.cuda` alone is not enough: torch 2.13 ships only
cu129/cu130 wheels, so on my box torch says 13.0, nvcc says 12.8, and FlashInfer
still crashes.

The two helpers copy FlashInfer's code instead of importing it, because importing
flashinfer creates a CUDA context on import (jit/core.py L150) and
`has_flashinfer()` runs in the main process before the workers start.

Replaces the per-path check from the first version of this PR and Pavani's
`flashinfer-cuda-compat-check` branch, as agreed in #pr-reviews. Relax the pin
once flashinfer-ai/flashinfer#3633 lands.

## Test Plan

Manual, RTX 5090, driver 580, nvcc 12.8, torch 2.13.0+cu130, Qwen/Qwen3-1.7B,
main @ dff76bc3e: four `vllm serve` configs before and after.

Unit: `pytest tests/kernels/attention/test_attention_selector.py -k cuda_toolkit`

## Test Result

| run | before | after |
|---|---|---|
| `--kv-cache-dtype fp8` | FLASHINFER selected, `RuntimeError: FlashInfer requires GPUs with sm75 or higher` | TRITON_ATTN, serves |
| default (bf16) | FLASHINFER in candidates | FLASHINFER absent, FLASH_ATTN serves |
| `--attention-backend FLASHINFER`, bf16 and fp8 | same RuntimeError | `ValueError: Selected backend FLASHINFER is not valid for this configuration` |

Unit tests: 3 passed.
