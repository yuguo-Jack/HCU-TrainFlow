# [Bugfix] Don't enable MM embedding inputs on KV consumers in language-model-only mode

[Upstream PR](https://github.com/vllm-project/vllm/pull/62880) · state: closed · merged: True

## Original PR description

## Overview

Since #56379, `_resolve_mm_embedding_inputs()` turns on `allow_missing_mm_embeddings` and `enable_mm_embeds` on every EC/KV consumer, including ones started with `--language-model-only`. This PR leaves both flags off on a KV-only consumer that sets `language_model_only` without `--enable-mm-embeds`, so a text-only KV consumer of a multimodal checkpoint runs in text-only mode again.

## Claims

- A language-model-only KV consumer (for example the decode instance of a text-only P/D deployment of a multimodal checkpoint) reports `supports_multimodal_inputs == False` again and no longer builds a `MultiModalBudget` or an HF processor in its scheduler, frontend and workers.
- This drops the host memory those processes have carried since #56379: about 3.4 GB per decode node in the deployment measured below.
- EPD consumers, the case #56379 targets, keep working: EC consumers always enable both flags, and a KV consumer still enables them unless it sets `language_model_only`. An EPD decode instance that uses `--language-model-only` to skip the encoder can opt back in with `--enable-mm-embeds`.

## Validation

**Unit.** New test `test_consumer_resolves_mm_embedding_inputs` in `tests/config/test_multimodal_config.py` (covered by the `tests/config` step in `.buildkite/test_areas/misc.yaml`). It covers a KV consumer, a language-model-only KV consumer with and without `--enable-mm-embeds`, and a language-model-only EC consumer. Without the change, the language-model-only KV consumer case fails because `allow_missing_mm_embeddings` is `True`. All tests in the file and `pre-commit` pass (CPU-only container).

**Reproducer.** Start any multimodal checkpoint as a KV consumer in language-model-only mode, for example `--language-model-only --limit-mm-per-prompt '{"image":0,"video":0}' --kv-transfer-config '{..., "kv_role": "kv_consumer"}'`.
- Before: the frontend and workers log `enable_mm_embeds is True; modalities handled as embedding-only: ('image', 'video')`, and each EngineCore loads the HF processor.
- After: they log `All limits of multimodal modalities supported by the model are set to 0, running in text-only mode.`

**End to end.** Qwen3.5-397B-A17B-FP8, 1P1D on TPU (prefill PCP8, decode DP8 on one host each), served through vLLM 0.31.0 with the vllm-torchtpu platform plugin. Same image for both runs. Measured with an earlier revision that behaves identically for this decode configuration.

| decode node | without | with | Δ |
|---|---|---|---|
| Pod anonymous memory at serving start | 147.0 GB | 143.6 GB | **−3.4 GB** |
| EngineCore RSS (×8) | 1210 MiB | 802 MiB | −408 MiB each |
| API server RSS | 1743 MiB | 1325 MiB | −418 MiB |
| Worker RSS (×8, total) | 135.3 GiB | 135.5 GiB | unchanged |

The prefill node (KV producer) is unaffected. Serving with the change: 1003/1003 requests, 1503 tok/s, median TPOT 24.0 ms (4096-in / 512-out, concurrency 64, 5 min). I did not validate on GPU.

## Details

Path on the decode (KV consumer) instance of a text-only P/D deployment:

1. Decode starts with `kv_role=kv_consumer` and `--language-model-only`, so every modality limit is 0.
2. `VllmConfig._resolve_mm_embedding_inputs()` sets `allow_missing_mm_embeddings = True` (KV consumer) and then `enable_mm_embeds = True`.
3. `ModelConfig._supports_multimodal_inputs()` returns `True` despite the zero limits, because `enable_mm_embeds` is set.
4. `Scheduler.__init__` (and the frontend's `InputProcessor` and the workers) build a `MultiModalBudget`. `get_mm_max_toks_per_item()` calls e.g. `Qwen2VLProcessingInfo.get_max_image_tokens()` -> `get_image_processor()` -> `ctx.get_hf_processor()`, which instantiates the full HF processor (`Qwen3VLProcessor.from_pretrained`). That processor loads a second copy of the tokenizer and deep-copies it.

A KV role alone does not tell a text-only P/D decode instance from an EPD one, so the change uses `language_model_only` as the text-only signal.

File: `vllm/config/vllm.py` · line None

Could we keep automatic embedding support for EC consumers and honor explicit `enable_mm_embeds` on KV consumers? `language_model_only` zeros modality limits but still permits embedding-only inputs when enabled. This early return also skips `allow_missing_mm_embeddings`, which can reject metadata-only EPD requests.

Suggested rule: enable both flags for EC consumers; for KV-only consumers, enable them when `not language_model_only or enable_mm_embeds`. This preserves the text-only memory saving, while an independent EPD decode instance can opt in with `--enable-mm-embeds`.
