# [Tests][MoE] Test bias and router weight are applied before the cast

[Upstream PR](https://github.com/vllm-project/vllm/pull/64741) · state: open · merged: False

## Original PR description



## Overview

Adds a test for the last steps of `fused_moe_kernel`: add the bias, multiply by the router weight, then cast once. This order broke twice in January (#31676, then #31931; fixed in #31962), and both times the MoE kernel tests stayed green. No open PR covers it.

## Claims

- The test fails on both broken builds and passes on main.
- None of the existing MoE kernel tests catch either break.
- It checks for an exact match (`atol=0, rtol=0`). The inputs are small integers, so the matmul and bias are exact in fp32 and the only rounding is the final cast.

## Validation

`pytest tests/kernels/moe/test_moe.py -k applies_bias_and_router_weight` on an RTX 3050 Ti Laptop GPU:

| Build | Order | Result |
|---|---|---|
| main (4b47db92) | bias, weight, cast | passed |
| a79079fe (before #31931) | cast, bias, weight | failed, 2700 / 8448 elements differ |
| c4041f37 (#31931) | weight, cast, bias | failed, 5568 / 8448 elements differ |

On the old builds I ran the test from a standalone file, since `test_moe.py` is different there.

I also put each bug back into main's kernel on an L4 and ran the existing Triton MoE tests (`test_moe.py`, `test_triton_moe_no_act_mul.py`, `test_block_fp8.py`, `test_block_int8.py`, `test_triton_moe_ptpc_fp8.py`). All 1238 that pass on main still passed with either bug.

The test runs in the existing `:nvidia: (L4) MoE Kernels` step and its `:amd: (MI300)` mirror. I haven't been able to run it on ROCm. I expect it to pass, since Triton and torch both round to nearest even, but the MI300 job will tell.

## Details

- The existing MoE tests use `atol=2e-2` or looser, which can't see where the rounding happens. The #31931 order left the bias unscaled by the router weight, and #31962 measured gsm8k_platinum 0.00 on `amd/gpt-oss-20b-WFP8-AFP8-KVFP8` with it. The only test that caught either break was `test_olmoe_lora_mixed`, and its L4 step now runs nightly only.
- The test calls `invoke_fused_moe_triton_kernel` the same way `TritonExperts` runs its second GEMM: one row of A per (token, expert) pair, `top_k=1`, router weights and `B_bias`.
