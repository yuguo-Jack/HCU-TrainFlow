# [Bugfix][KV Offload][OBJ] Never let a failed NIXL submission escape the tier

[Upstream PR](https://github.com/vllm-project/vllm/pull/62650) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Fix the OBJ secondary tier so a failed NIXL submission is reported as a failed
KV offload job instead of escaping into the EngineCore step. OBJ counterpart of
#60374 (P2P tier).

## Claims

- A NIXL exception from `register_memory`, `prep_xfer_dlist`,
  `make_prepped_xfer`, or `transfer` no longer escapes `submit_store()` /
  `submit_load()`.
- Handles created before the failure are released in reverse order; a failed
  xfer-handle release keeps the job pending until the next poll can retry it.
- The failure is reported as `JobResult(success=False)`, so the parent releases
  the primary pin, invalidates a failed promotion's cached verdict, and
  finalizes the request.
- `transfer()`'s documented `"ERR"` return is still handled. Successful
  transfers and the NIXL dependency version are unchanged.

## Details

**Root cause.** vLLM pins `nixl == 1.5.0` for the KV connectors. In this
version `register_memory`, `prep_xfer_dlist`, and `make_prepped_xfer` return a
handle or raise — there is no sentinel return — and `transfer()` normally
returns `"DONE"`/`"PROC"`/`"ERR"` but can also raise. The same contract holds
back to NIXL 1.1.0, so the tier's old `None` / falsy-handle checks were dead
code and are removed.

Before the fix, the exception propagated out of
`TieringOffloadingManager.complete_store()` into `build_connector_meta()`.
Because no `JobResult` was reported, the parent kept the job, `ref_cnt` was
never decremented, and the request never finalized.

**Design.** One exception handler covers the four submission calls. Both that
path and the `"ERR"` branch call `_fail_submission()`. If
`release_xfer_handle()` fails, the entry remains in `_transfers` with a failed
submission marker, so the poll loop retries the release before publishing a
failed `JobResult`. Once the transfer handle is released, dlist and memory
cleanup remains best effort. The parent therefore handles submission and
in-flight failures through one path without reusing primary memory too early.

**Limitation.** If `register_memory` itself raises, NIXL returns no handle, so
a partial registration on its side cannot be deregistered here.

**Duplicate work.** No open PR addresses this. Related but distinct: #49947
(post-completion cleanup), #56192 (RDMA-capable OBJ configuration), #60374
(merged, P2P equivalent).
