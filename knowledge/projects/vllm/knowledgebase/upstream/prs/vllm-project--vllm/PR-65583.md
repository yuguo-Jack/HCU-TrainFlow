# [Bugfix][Benchmark] Fix bench throughput crash with BlazeEdit HF datasets

[Upstream PR](https://github.com/vllm-project/vllm/pull/65583) · state: open · merged: False

## Original PR description

<!-- markdownlint-disable -->

## Overview

Since #50981, `vllm bench throughput` builds its requests with `bench serve`'s `get_samples`, through `_to_serve_args`. For the BlazeEdit datasets (`vdaita/edit_5k_char`, `vdaita/edit_10k_char`), `get_samples` reads `args.blazedit_min_distance` and `args.blazedit_max_distance`. `bench throughput` defines neither flag and `_to_serve_args` does not fill them in, so the run fails with `AttributeError` before the dataset is loaded. `docs/benchmarking/cli.md` lists BlazeEdit as supported offline.

## Claims

- `bench throughput` runs on both BlazeEdit datasets, over the full distance range (`bench serve`'s defaults, 0.0 and 1.0).
- Other datasets and `bench serve` are unaffected.

## Validation

New regression test `test_get_requests_hf_blazedit` (CPU, HF download stubbed) runs the real `get_requests` and `BlazeditDataset` and checks that every prompt carries the change request.

Before the fix:

```text
$ pytest tests/benchmarks/test_throughput_cli.py -k hf_blazedit
E   AttributeError: 'Namespace' object has no attribute 'blazedit_min_distance'
1 failed, 18 deselected
```

With the fix:

```text
$ pytest tests/benchmarks/test_throughput_cli.py -k hf_blazedit
1 passed, 18 deselected
```

End to end on an A10G, in one container: the main nightly wheel, with current main's `datasets.py` and the compared `throughput.py` (main's, then this PR's) copied over the installed package.

```text
$ vllm bench throughput --model Qwen/Qwen2.5-0.5B-Instruct --dataset-name hf \
    --dataset-path vdaita/edit_5k_char --num-prompts 5 --max-model-len 8192

# main: exit 1
AttributeError: 'Namespace' object has no attribute 'blazedit_min_distance'

# this PR: exit 0
Throughput: 0.31 requests/s, 1758.09 total tokens/s, 1258.70 output tokens/s
Total num prompt tokens:  7935
Total num output tokens:  20000
```

`pytest tests/benchmarks` on CPU: 188 passed with this PR and 187 on main; the new test is the only difference. The remaining 27 failures and 5 errors also occur on main and come from my environment: the `vllm` executable is not on PATH, `pandas` and `soundfile` are not installed, and `test_bench_serve*` needs the gated `meta-llama/Llama-3.2-1B-Instruct`. `pre-commit` passes.

## Details

Root cause: `_to_serve_args` backfills the `bench serve` attributes that `bench throughput` never exposes, but not the BlazeEdit ones. The fix adds them with `bench serve`'s defaults, next to the other backfilled attributes.

`get_samples` reads six more attributes that `bench throughput` lacks, but it cannot reach them: BFCL rejects backends other than `openai-chat` before reading `bfcl_categories`, and SpecBench and SpeedBench are `--dataset-name` values that `bench throughput` does not offer.

`docs/benchmarking/cli.md` now notes, below the BlazeEdit example, that `bench throughput` has no `--blazedit-*` flags and uses the full range.

Not a duplicate: no open PR or issue covers this. #64537 fixes duplicate request IDs after BlazeEdit filtering in `bench serve`, and the open PRs that touch `throughput.py` (#59881, #56354, #59301, #53082) do not change `_to_serve_args`. This changes a different line of `_to_serve_args` than #64831, and the two merge cleanly in either order.
