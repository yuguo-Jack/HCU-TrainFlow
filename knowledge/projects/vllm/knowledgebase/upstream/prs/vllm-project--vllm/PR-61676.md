# [Benchmark] Remove the temporary bench forward dummy loader

[Upstream PR](https://github.com/vllm-project/vllm/pull/61676) · state: closed · merged: True

## Original PR description



## Overview

Follow-up to #61339 (`vllm bench forward`): remove its temporary dummy loader, now that #60096 has landed, and add ROCm TODOs.

## Claims

- The bench's `forward_bench_dummy` loader is gone; `--load-format dummy` uses the stock `DummyModelLoader`. It ran an early `process_weights_after_loading()` so dummy-loaded DeepSeek-V4.1 could fuse its MegaMoE shared experts. #60096 loads MegaMoE experts directly into the DeepGEMM layout, so the CUDA models no longer have `finalize_mega_moe_weights` and the workaround was already a no-op.
- No timing change on DeepSeek-V4.1 (below).
- The model-microbenchmark skill drops its caveat about degenerate dummy norm weights, fixed by #61323.
- TODOs mark where ROCm support is missing (the bench is CUDA-only for now; its end-to-end test is skipped on ROCm because it hangs there, likely on the in-graph timing events).

## Validation

```
pytest tests/benchmarks/test_forward_cli.py   # 3 passed (GB200)
```

DeepSeek-V4.1-Flash, DEP4 on one GB200 node, MegaMoE, FlashInfer sparse MLA, fp8 KV, ~100K KV, balanced routing; same environment and node, main's loader vs this PR:

| case | main | this PR | diff |
| --- | --- | --- | --- |
| decode, 32 reqs | 15565 us | 15635 us | +0.45% |
| decode, 128 reqs | 19986 us | 20011 us | +0.12% |
| prefill 16K | 205.1 ms | 201.9 ms | -1.57% |
| prefill 8 x 1K | 131.5 ms | 129.7 ms | -1.32% |

Diffs are within run-to-run noise (sample spread up to ~1% on V4.1 DEP). Graph-vs-eager and replay checks match between the two.

## Details

- Unrelated observation, same on main: DeepSeek-V4.1 prefill graph replays are no longer bit-identical after main's DeepGEMM bump (#61149); decode replays still are. To be looked into separately.
