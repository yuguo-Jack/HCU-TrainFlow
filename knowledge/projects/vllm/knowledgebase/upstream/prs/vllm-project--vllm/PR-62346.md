# [MRV2][BugFix] Don't expose P/D step output before drafter KV writes complete

[Upstream PR](https://github.com/vllm-project/vllm/pull/62346) · state: open · merged: False

## Original PR description

In MRV2, the async output copy is started before the speculator's propose() so that the D2H copy can overlap with drafting. Its copy event therefore only covers the target model's work, and the scheduler can see a step's output while the drafter is still writing its KV for those blocks.

On a P/D producer this lets a finished request's blocks be sent before its draft KV is complete: the scheduler finishes the request and the KV connector transfers its blocks (e.g. NIXL READ/WRITE, Mooncake, MoRI-IO) without any further GPU sync. Outputs are unaffected since draft tokens are verified, but D's drafter attends over stale draft KV for the prompt for the rest of the request, and via D's prefix cache for later requests sharing that prefix, lowering acceptance.

When the KV connector requires_kv_delivery and spec decoding is enabled, re-record the output copy event after the drafter so that output readiness implies the drafter's KV writes are done. The D2H copies are still issued early. Best-effort caches (offloading connectors) opt out of requires_kv_delivery and their copies are already stream-ordered after compute, so they are unaffected.
