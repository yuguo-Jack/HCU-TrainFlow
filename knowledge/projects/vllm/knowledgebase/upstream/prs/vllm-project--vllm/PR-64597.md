# [CI] Enroll the remaining Engine and Basic Correctness jobs in automatic sharding (17 jobs)

[Upstream PR](https://github.com/vllm-project/vllm/pull/64597) · state: closed · merged: True

## Original PR description



## Overview

Enrolls the remaining Engine and Basic Correctness jobs in `automatic_shard`: 17 jobs (7 steps and 10 AMD mirrors). Part of a series that enrolls every remaining test step, split by test area for review. No commands change.

## Claims

| Step | Plan | AMD mirror |
|---|---|---|
| `e2e-core-large-memory` | 1 shard | 1 shard |
| `v1-e2e-hybrid-chunked-prefill-b200` | 1 shard | 1 shard |
| `v1-e2e-2-gpus` | 1 shard | 1 shard |
| `basic-correctness-sleep-mode` | 2 shards | 2 shards |
| `basic-correctness-cpu-offload` | 1 shard | 1 shard |
| `basic-correctness-cumem` | 1 shard | 1 shard |
| `basic-correctness-prefetch-offload` | 1 shard | 1 shard |
| `engine-1-gpu` | already enrolled | 1 shard |
| `e2e-core-1-gpu` | already enrolled | 1 shard |
| `replayssm-e2e` | already enrolled | 1 shard |

- One-shard and one-job plans run the same tests as on main, as one job, and split by themselves once their tests grow.
- Plans of 2 or more shards cost one extra job setup per shard and bring each shard under the 20-minute target.

## Validation

- Planned each step and mirror with ci-infra main's planner against main's timings; every plan is within 10% of the same plan run as one job.
- The sharding harness (each shard's commands run against a mock test tree, as a PR build and as main with the OTel wrapper) shows every test runs exactly once wherever a plan has 2 or more shards.
- Every step and mirror passes on recent main runs, nightly included.
- `/ci run` (98462) plus a scoped build (98473) for the optional steps and AMD mirrors on this head: every enrolled job passed, and every shard finished under 22 minutes. Basic Correctness Sleep Mode split into 2 shards and used 14% less machine time than main.

## Details

- **Not plain pytest** steps (shell scripts, `torchrun`, examples) and standalone AMD steps are enrolled too; the generator keeps them as one job.
- **caplog.** Files that assert on logs sit in one-shard plans here, so their order in the process doesn't change.
- **Timeouts unchanged.** `timeout_in_minutes` stays per job. Fallback-aware timeouts belong in a central timeout setting.
