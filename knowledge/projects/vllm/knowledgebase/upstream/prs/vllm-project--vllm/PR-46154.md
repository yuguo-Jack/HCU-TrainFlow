# [CPU] Fix mixed-batch GQA decode detection

[Upstream PR](https://github.com/vllm-project/vllm/pull/46154) · state: closed · merged: False

## Original PR description

## Purpose

Fixes #46131.

#43032 enabled per-workitem GQA for decode workitems in mixed batches. However, the executor used scheduler workitem token counts (`q_token_num == 1`) to decide whether a workitem was decode. With split-KV enabled, prefill requests can be partitioned into single-token workitems, so those prefill tiles could incorrectly take the mixed-batch GQA path.

This PR makes mixed-batch GQA decisions use the original request query length from `query_start_loc` instead of the partitioned workitem length, in both the attention and reduction paths. It also keeps the GQA tile size within `MaxQTileIterNum` after applying the current q-per-kv grouping so the static `first_iter_flag` array invariant holds for non-divisible GQA ratios.

Duplicate-work check: I checked the issue comments and open PRs for `46131`, `mixed batch GQA CPU attention`, and `cpu attn gqa decode workitem`; no open PR currently addresses this issue.

AI assistance was used to investigate and prepare this change.
