# [Model] Support EAGLE3/DFlash aux hidden states for GraniteMoe and GraniteMoeShared

[Upstream PR](https://github.com/vllm-project/vllm/pull/61110) · state: closed · merged: True

## Original PR description



## Overview

Implement `SupportsEagle3` for `GraniteMoeForCausalLM` and `GraniteMoeSharedForCausalLM` (which also serves `GraniteMoeSWAForCausalLM`), so Granite MoE models can serve as targets for aux-hidden-state speculative decoding (EAGLE3, DFlash, DSpark) and for `extract_hidden_states`. Follow-up to #60855, which did the same for dense `GraniteForCausalLM`.

## Claims

- Granite MoE targets (`GraniteMoeForCausalLM`, `GraniteMoeSharedForCausalLM`, `GraniteMoeSWAForCausalLM`) can now attach aux-hidden-state drafters and run `extract_hidden_states`. Previously, engine init rejected them because `supports_eagle3` was absent.
- The captured hidden states match HF `output_hidden_states` at the requested layers.
- No behavior change when no aux layers are requested: the models return `hidden_states` exactly as before.

## Details

Same pattern as #60855. The inner models inherit `EagleModelMixin` and record hidden states with `_maybe_add_hidden_state` in the layer loop. The outer `*ForCausalLM` classes declare `SupportsEagle3`. `granitemoeshared.py` has its own model class and layer loop (it does not reuse `GraniteMoeModel.forward`), so both files need the change. Aux hidden states over pipeline parallelism stay unsupported for these models (`supports_aux_hidden_states_over_pp` is left `False`), as in #60855.
