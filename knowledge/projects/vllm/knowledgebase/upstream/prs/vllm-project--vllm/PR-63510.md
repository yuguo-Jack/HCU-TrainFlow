# Rocm/beam common consolidation

[Upstream PR](https://github.com/vllm-project/vllm/pull/63510) · state: open · merged: False

## Original PR description



## Overview

This PR consolidates vendor-neutral Beam and DFlash2 functionality under `vllm/models/beam/common`. I wanted to keep this consolidation in its own PR since it would require reviews from both AMD and NVIDIA. My hope is that limiting the scope makes it easier to review rather than trying to do this as part of [#62057](https://github.com/vllm-project/vllm/pull/62057).

Until [#62057](https://github.com/vllm-project/vllm/pull/62057) lands on `main`, reviewers can view [the effective diff against that PR here](https://github.com/jamesETsmith/vllm/compare/rocm/beam-1.0-day0...rocm/beam-common-consolidation).

## Claims

- Removes duplicated AMD and NVIDIA implementations of the DFlash2 model, normalization kernels, convolution helpers, and candidate-selection helpers.
- Preserves platform-specific attention and KV-cache behavior through small AMD and NVIDIA backend adapters.
- Keeps NVIDIA PDL support while allowing the shared normalization kernel to run on ROCm.
- Reduces the Beam implementation by 742 net lines without changing its public model entry points.

## Validation

- Beam construction, weight-mapping, and configuration tests: **29 passed**.
- DFlash2 kernel and checkpoint-loading tests: **57 passed**.
- GSM8K at concurrency 64: **1,319/1,319 samples**, **93.56% flexible exact match**, and **93.63% strict exact match**.
- `ruff format --check`, `ruff check`, and `git diff --check` pass.

```bash
python -m pytest -q \

python -m pytest -q tests/v1/spec_decode/test_dflash2.py \
  -k "beam_conv_residual_norm or beam_fused_candidate_edges or beam_dflash2_loads_every_checkpoint_tensor"
```

## Details



This change moves the shared DFlash2 model into `common/dflash2.py` and introduces a backend protocol for attention execution and context KV-cache storage. The vendor modules now provide compact adapters for their respective attention backends and cache layouts. Shared convolution, candidate-selection, and layer-normalization kernels are exported directly from `vllm.models.beam.common`.

The common normalization kernel retains CUDA PDL support for NVIDIA all-reduce. Its Triton `launch_pdl` runtime option is supplied only when PDL is enabled because the HIP backend does not recognize that CUDA-specific launch option.

This is a code-organization change; it does not attempt to unify vendor-specific attention kernels or KV-cache update paths.
