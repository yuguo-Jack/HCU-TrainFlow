# WIP: Reassess FlashAttention unsupported-feature validation

[Upstream PR](https://github.com/vllm-project/vllm/pull/61408) · state: closed · merged: False

## Original PR description

## Overview

This draft reassesses unsupported-feature validation in `flash_attn_varlen_func`. The current patch standardizes error messages, but it also changes FA2 argument acceptance and FA3/FA4 exception types; it is **not behavior-preserving**.

The contribution scope is being reassessed following the refactor-only feedback on #61400. No merge-ready upstream bug fix is claimed.

## Claims

- The current diff introduces `_raise_unsupported_feature` and standardizes selected FA2/FA3/FA4 errors.
- The FA2 guard changes from rejecting when all four scheduling/descaling arguments are supplied to rejecting when any one is supplied.
- FA3/FA4 ALiBi rejection changes from `AssertionError` to `NotImplementedError`.
- These are observable behavior changes, not solely diagnostic formatting changes.

## Validation

**Known compatibility blocker:** the existing attention backend supplies `k_descale` and `v_descale` even for non-FP8 calls. With `fa_version=2`, `scheduler_metadata=None`, `q_descale=None`, and K/V descales supplied, upstream reaches FA2 dispatch, while this PR raises `NotImplementedError` before dispatch.

Sources:
- [Backend scale setup and dispatch at the PR base](https://github.com/vllm-project/vllm/blob/61d9c777bfdef66efbf017c7c363d2bdca5db8ee/vllm/v1/attention/backends/flash_attn.py#L1283-L1291)
- [Current PR guard](https://github.com/sivianil/vllm/blob/0001af994f0949e8a7d79a84b828b394828eef46/vllm/vllm_flash_attn/flash_attn_interface.py#L343-L366)

A local control-flow diagnostic executed the upstream and PR wrapper functions with lightweight stand-ins for tensors and the compiled FA2 operator. It reproduced the dispatch/rejection difference above. Calls with all four optional arguments absent reached dispatch in both versions; calls with all four present were rejected in both versions. This checks Python control flow only: **it is not a real PyTorch, CUDA kernel, numerical-correctness, or end-to-end serving test.**

The tests currently in this PR cover selected error strings and invalid version values. They do not cover the normal FA2 descale argument combination above and do not demonstrate an upstream functional bug.

Repository pytest, CUDA serving validation, and model evaluations have not been run in this reassessment environment because PyTorch/CUDA are unavailable. No new passing pytest or lint result is claimed.

## Details
