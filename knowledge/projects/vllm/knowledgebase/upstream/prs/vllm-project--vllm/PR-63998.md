# [Bugfix][KV Connector][Mooncake] Send KV when the prefill token is a stop token

[Upstream PR](https://github.com/vllm-project/vllm/pull/63998) · state: open · merged: False

## Original PR description

## Purpose

`MooncakeConnector.request_finished()` only sends KV for a prefill request that ends as `FINISHED_LENGTH_CAPPED`. If the single token the producer samples is a stop token (EOS), the request ends as `FINISHED_STOPPED`, goes to `reqs_not_processed`, and the KV is never sent. The router discards the producer's token, so the decoder still needs that KV: its pull waits on `send_meta.ready` for the full `VLLM_MOONCAKE_ABORT_REQUEST_TIMEOUT` (480 s default) and then fails with `Timeout waiting for P side ready`.

This is easy to hit on DeepSeek-V4.1: with SWA bounded replay the producer drops the last prompt token (`_truncate_mamba_request_for_prefill`) and samples from the truncated prompt, which makes EOS likely for some prompts. It is not specific to that model; any model can sample a stop token as its first token.

This accepts `FINISHED_STOPPED` alongside `FINISHED_LENGTH_CAPPED`. Aborted/interrupted prefills are still dropped. Accuracy is unaffected: the decoder recomputes the last token and never uses the producer's sampled token.

Not a duplicate: #46008 made the same change but was closed as stale without merging, and no open PR touches this. #62020 is the same fix for MoRIIO. #55870 (no terminal error propagation on transfer failures) is related but separate; this PR does not address it.

## Test Plan

```bash
.venv/bin/python -m pytest tests/v1/kv_connector/unit/test_mooncake_connector.py -k scheduler_request_finished -v
```

Extended `test_scheduler_request_finished` with a `FINISHED_STOPPED` case.

End to end on 2 nodes (DeepSeek-V4.1-Flash, v0.32.0, P DP8 + D DP8, Mooncake `tcp`, llm-d routing sidecar), replaying 300 prompts:

- Before: with `max_tokens=1` on the producer, 41/300 requests (about 14%) finished as `stop` with first token `<｜end▁of▁sentence｜>`. For such a request the decoder timed out after 480 s. Under 45-way concurrent replay 89 requests returned 500 in about 3 minutes and no request completed in the measurement window.
- Same prompt, producer with `ignore_eos: true` (finishes as `length`): decoder pull succeeds in 0.2 s.
- After (this change applied to the producer): the prompt whose producer finish is `stop` now pulls in 0.2 s, and the 45-way replay ran 180 s with 0 errors and 0 timeouts in producer/decoder logs.
