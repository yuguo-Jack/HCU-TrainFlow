# [Bugfix][Mistral] Carry token ids in stream state for byte-fallback tokens

[Upstream PR](https://github.com/vllm-project/vllm/pull/64743) · state: closed · merged: True

## Original PR description



## Overview

Fix streaming derender for Tekken-based Mistral tokenizers, where a byte-fallback token in the decode window breaks the client-carried `stream_state`.

The `/v1/responses` corruption originally reported here was fixed by #65118; this PR only covers the derender endpoints.

## Claims

- Streaming `/v1/completions/derender` and `/v1/chat/completions/derender` keep working when the decode window contains a byte-fallback token instead of rejecting the request.
- With a parser configured, chat derender for `MistralTokenizer` now uses the request's `skip_special_tokens`, matching serving after #65118.

## Details

- Root cause: `MistralTokenizer.convert_ids_to_tokens` returns raw `bytes` for byte-fallback tokens. This happens with `skip_special_tokens=True` too, so it already affects `main`. Streaming derender stored those pieces in `DerenderStreamState.prev_tokens: list[str]`, which goes through JSON between chunks. An incomplete UTF-8 piece can't be carried there.
