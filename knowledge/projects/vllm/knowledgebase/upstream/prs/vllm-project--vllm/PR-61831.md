# [CI] Shard FP8 MoE kernels and L4 Humming eval automatically

[Upstream PR](https://github.com/vllm-project/vllm/pull/61831) · state: open · merged: False

## Original PR description

## Purpose

Takes over #61473 (Kevin's batch 1), rebased onto main. This PR only enables `automatic_shard`; it changes no tests.

| Step | Command | Shards in #61473's build |
|---|---|---:|
| `kernels-fp8-moe-test-2xh100` | two plain `pytest` commands over `kernels/moe` DeepEP tests | 3 |
| `lm-eval-humming-l4` | one `pytest` over `evals/gsm8k` | 2 |

**AMD mirror.** `kernels-fp8-moe-test-2xh100`'s AMD mirror runs past the 20-minute target as one job, so it is enrolled too (`automatic_shard: true` in `mirror.amd`; it already has `dind: false` and no fixed `parallelism`). It plans to 2 shards, splitting `test_deepep_moe.py` by test. `lm-eval-humming-l4` has no AMD mirror.

Left out, with notes in the enrollment tracker:
- `lm-eval-spec-decode-4xb200` and `lm-eval-humming-b200-default`: their failing tests fail the same way on main, so a PR build can't validate the shards.
- `multi-modal-models-extended-pooling`: shard 1 hung twice at `test_colpali.py::test_colpali_v2_multimodal_text_query_image_docs`, which main doesn't do.
- #61473's `multi_gpu_test(..., method="spawn")` change for the DeepEP tests: it worked around a DeepGEMM build that set up CUDA on import, and main has since reverted that (#61510, #61703).

## Test Plan

- Build [94969](https://buildkite.com/vllm/ci/builds/94969) of #61473: both steps passed in every shard, with per-command passed/skipped counts equal to main's single job. No test ran twice.
- Both steps are `optional`, so `/ci run` leaves them behind a block step without sharding them. A build scoped to them with `VLLM_CI_ONLY_STEP_KEYS` re-checks the shards on this head, with the DeepEP tests forking again.
- The AMD mirror: rendered with the pipeline generator and ran every shard's commands against a mock test tree, as a PR build and in main's OTel mode; every test ran in exactly one shard. It is optional like its step, so it needs the same scoped build.
