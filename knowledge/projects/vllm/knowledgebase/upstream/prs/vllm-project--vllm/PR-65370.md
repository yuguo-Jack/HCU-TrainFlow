# [Rust Frontend] Accept Python underscore and dotted flag forms under vllm-rs serve

[Upstream PR](https://github.com/vllm-project/vllm/pull/65370) · state: closed · merged: True

## Original PR description

## Overview

Make `vllm-rs serve` accept the two argv spellings Python's `FlexibleArgumentParser` rewrites: underscores in long flag names (`--served_model_name`) and dotted forms of JSON flags (`--hf-overrides.rope_scaling.factor 4`). Today both reach only the managed Python engine, and the Rust frontend silently keeps its default for flags it declares itself.

## Claims

- Long flag names are normalized like Python: `_` becomes `-` up to the first `.` or `=`, so `--served_model_name qwen` and `--max_model_len=1024` configure the Rust frontend. Keys after the first `.` keep their underscores.
- Dotted forms of every flag `vllm-rs serve` declares (for example `--hf-overrides.*`, `--structured-outputs-config.*`, `--default-chat-template-kwargs.*`) are merged into one `--<flag> <JSON>` with Python's rules, so the Rust tokenizer, model config, structured-output backend and chat template kwargs see the override. Shared flags still reach the engine, unknown keys included.
- Dotted forms of engine-only flags (for example `--compilation-config.mode 3`) go to Python unchanged, as before.
- The Python-supervised path (`vllm serve` with `VLLM_USE_RUST_FRONTEND=1`) is unaffected: it already hands Rust the merged values through `--args-json`.

## Details

Python's `FlexibleArgumentParser` rewrites argv before argparse runs:

- underscores in a long flag name become dashes, up to the first `.` or `=`;
- every dotted form `--<flag>.<key>[.<key>...] <value>` is merged into one `--<flag> <JSON object>` per flag, appended after the other arguments.

Under `vllm-rs serve`, the argv repartitioner (`repartition_managed_engine_args`, `rust/src/managed-engine/src/cli.rs`) keeps a flag on the Rust side only when its head matches a clap name exactly; everything else goes to the managed Python engine. So an underscore spelling or a dotted form of a flag Rust declares reached only the engine. Examples: `--served_model_name`, `--structured-outputs-config.backend guidance` (Rust keeps compiling with xgrammar), `--default-chat-template-kwargs.enable_thinking false`, `--hf-overrides.*`.

One commit per part:

1. **Underscore spellings.** The repartitioner normalizes long flag names like Python, next to the existing `-tp`-style alias normalization. Forwarded flags are normalized too, which Python would do anyway.
2. **Dotted forms of Rust-declared flags.** Before routing, `merge_dotted_frontend_args` merges `--<flag>.<path>` for every flag `vllm-rs serve` declares, with Python's rules: the value is parsed as JSON, then as a human-readable integer (`32k`, `4K`, ported from `human_readable_int`), and otherwise kept as a string; `<key>+ a,b` appends list elements; objects merge key by key and lists concatenate (`recursive_dict_update`). The merged `--<flag> <JSON>` is appended and goes to clap. Shared flags (`--hf-overrides`, `--structured-outputs-config`, `--profiler-config`, `--limit-mm-per-prompt`) reach the engine through the existing re-serialization, which keeps unknown keys (`#[serde(flatten)]` extras; `HfOverrides` is a map).

**Layering.** The consumer is clap's parse of `vllm-rs serve` argv, and the repartitioner is the one place that turns Python-style argv into it (it already absorbs Python's multi-character aliases), so both rewrites live there. `vllm-rs frontend` and `vllm-rs render` parse with clap directly and keep rejecting these spellings with a clap error.

**Differences from Python.**

- A dotted form combined with the full JSON flag (`--hf-overrides '{...}' --hf-overrides.x 1`) is a clap error ("cannot be used multiple times"), like any repeated Rust flag; Python keeps the last occurrence, which silently drops the full JSON.
- A dotted flag with no value is a clap error; Python fails with an `IndexError` traceback.
- Python logs a warning for duplicate dotted keys; Rust overwrites silently with the same result.
- `int()` corner cases that are not JSON (`1_000`) stay strings.

Not a duplicate: no open PR changes how `vllm-rs serve` handles underscore or dotted flag spellings (searched open Rust frontend PRs for argument parsing, dotted flags and `FlexibleArgumentParser`).
